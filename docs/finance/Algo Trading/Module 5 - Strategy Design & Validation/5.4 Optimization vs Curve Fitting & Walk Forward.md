# 5.4 Optimization vs Curve Fitting & Walk Forward Testing

## Idea Has a Limit

Every idea has realistic earning capacity — maybe your idea can give 15% or 35% annual return. Forcing it to 75% = entering curve fitting. Test too many combinations on data and **spurious correlations** will definitely appear — showing 75% but won't come in future.

Three questions this file answers:
1. How much optimization is too much?
2. How to optimize safely?
3. Will strategy survive in future — how to check?

## What is Optimization?

> **Optimization = finding parameter values that improve strategy performance.**

Example: Nifty options system giving 1000 points → can we take it to 2000? Yes → optimization successful.

What parameters can you tune:

| Parameter | Example |
|---|---|
| Moving average length | EMA 10 vs EMA 20 |
| RSI threshold | Buy level change |
| Stop loss distance | ATR multiplier 1.5 vs 2.0 |
| Target multiple | Risk-reward ratio |
| Time filters | Entry window / session avoid |

Why optimize: improve expectancy, reduce drawdown, adapt to market behavior, and **identify stable parameter zones.**

Types: **parameter optimization** (indicator values), **risk optimization** (SL/target ratios, sizing), **time-based optimization** (entry/exit windows).

## Right Way vs Danger Signs

✅ **Right way:**
- **Optimize ranges, not exact numbers**
- 🔑 **Find plateau, not peak** — where BIG area gives stable performance
- Choose robust zone, not maximum-profit points

⚠️ Dangerous when:
- Too many parameters
- Test very narrow ranges
- Focus only on best equity curve

### Over-Optimization Symptoms

| Symptom | Meaning |
|---|---|
| Extremely high Sharpe ratio | Impossible in reality |
| Very smooth equity curve | Fitted on data |
| Works only in specific year | Dies on regime change |
| Fails immediately in live trading | Classic curve-fit sign |

Between optimization and curve fitting **very thin line** — that fine difference decides future survival.

## Practical Example — System 1 (Nifty Expiry Straddle)

Instructor wrote Python code in ~15–30 min and backtested one system (data from Module 3 APIs, saved CSV). See rules — and note **"9:20" means time, not strike!**

```text
System 1 Rules:
1. Trade ONLY on Nifty expiry dates
2. 9:20 AM — check spot price → round to nearest 50-point strike
   → SELL ATM Call + ATM Put (entry = first 1-min candle's open after 9:20)
3. SL: 2× entry premium on each leg
   (sold ₹100 option → square off at ₹200;
    trigger = when any 1-min candle's HIGH crosses that level)
4. Exit: 3:15 PM same day (time-based)
5. Early exit: any leg hits SL
6. No overnight; 1 lot each CE + PE
```

(ATM = strike closest to current price — 4.2/2.2 concept. Selling both Call+Put = straddle.)

Workflow also production-like: wrote entry/exit functions in Python → ran → got **CSV output** with trade date, both legs' entry/SL/exit, PnL per leg, cumulative PnL. Tip: in code's analysis, write only columns you need in CSV.

Results:

| Metric | Result |
|---|---|
| Period | Jan 2025 – Jul 2025 |
| Win rate | **70%** |
| Total points | **2,458** |
| PnL (50 multiplier) | **~₹1,29,900** |

Now question: how to increase profit **without curve-fitting**? 👇

## REAL Optimization = Rule Change (Not Parameter!)

Fundamental: **Don't change system's core strength** (9:20 ATM CE+PE sell stays) — only **add/improve rules that have economic reason.**

What was done — **Adjustment Rule:**

```text
If any leg hits SL
→ immediately sell fresh option of OPPOSITE side at that time's ATM strike
```

See example:

```text
9:20 AM  → 26000 ATM: sold Call ₹80, Put ₹70
12:30 PM → Put SL hit (₹70 → ₹140)
Adjust   → 12:30's new ATM (say 25600) — sell fresh CALL
```

Economic reason solid: Put SL hit means market falling — selling new premium in that direction goes WITH trend, not against.

Result comparison:

| | System 1 | System 1 + Adjustment |
|---|---|---|
| Total points | 2,458 | **4,208** |
| PnL (×50) | ₹1,29,900 | **~₹2,10,400** |

🎉 Just **ONE rule change** almost **DOUBLED** PnL! This is called **real optimization** — optimization of rules, not parameters.

⚠️ And understand its opposite — this is curve fitting: running ML algorithm to test every minute *"is 9:45 entry better? 11:15?"* Nothing will come, because **no economic reason**. That's just backtest fairy tale — in real market that pattern won't exist. If profit found at some time/parameter, must explain **WHY** it came — only then will repeat in future.

## What is Curve Fitting?

> **Definition:** Adjusting parameters so precisely that strategy fits historical NOISE instead of real market behavior.

> 🔑 **"Curve fit strategies trade the PAST, not the FUTURE."**

### Nifty Example

Look at 25-year monthly data — chart only going up. If you saw data after April-2024 and made **long-only system** → ❌ curve fit! Because you "read" past trend and built logic on it. (Making only-short after 2020 crash is same mistake.)

But interesting twist: long-term uptrend has **economic reason** — India's demographics, democracy, business growth fundamentals. Strategy based on fundamentally-strong phenomenon survives in future; based only on data-flaw doesn't. Momentum is similarly a truth/phenomenon (market reacts slowly for 2–3 months, then fast) — that's why momentum strategies survive decades.

### Why Dangerous?

Markets change. Volatility regimes shift (VIX's character), liquidity evolves, participants' behavior changes. What was in past won't repeat exactly.

### Common Causes

- Stacking too many indicators
- Excessive optimization loops
- Data mining — finding something in same data repeatedly
- Selecting only highest-return parameters
- Ignoring out-of-sample testing

Classic horror story: 12 indicators + optimized params = perfect backtest → live blow up 💥.

## Walk Forward Testing

> **Definition:** Optimize on past, test on future unseen data — and keep rolling process forward in time. This simulates real-world trading.

Method:

```text
1. Split data into SEGMENTS
2. OPTIMIZE on first segment   (in-sample)
3. TEST on next segment        (out-of-sample)
4. Roll forward → REPEAT
```

Unseen data proof needed at every step — curve-fit trap doesn't fit here.

Walk forward reveals: parameter stability, strategy adaptability, regime sensitivity, realistic drawdowns, and **WFE**.

### Walk Forward Efficiency (WFE)

Remember simple formula:

```text
WFE ≈ out-of-sample return ÷ in-sample return

Example: optimized in-sample got 40%,
         out-sample test got 28% → WFE = 28/40 = 70%
```

Benchmark:

| WFE | Verdict |
|---|---|
| **70%+** | Very good ✅ — performance transferring to real-world |
| Below that | Strategy unstable ⚠️ — in-sample result not surviving out-of-sample |

## Three Compared

| | Optimization | Walk Forward | Curve Fitting |
|---|---|---|---|
| Purpose | Improved performance | Validated robustness | Accidental |
| Data used | In-sample only | In + out sample | Same data repeatedly |
| Risk | Medium | **Low** | Very high ❌ |
| Live performance | Uncertain | Predictable | Poor |
| Professional use? | Yes | **Mandatory** | Never |

## Rules to Avoid

1. **Limit parameters** — test only 3–5 parameters
2. **Broad ranges** — ❌ run EMA 1–100 and pick best; ✅ holistic range like **EMA 20–50** (if something works, it'll work across whole zone)
3. 🔑 **Always prefer simplest rules** — simple logic survives regime changes
4. **Keep out-of-sample data** — at least 20–30% data never used in optimization; keep for testing
5. **Stability > profit** — slightly less profit with stability beats max profit with fragility
6. **Monte Carlo simulation** — another validation tool (learn later)
7. 🔑 **Multi-asset test:** strategy should work on multiple assets — if only works on one stock/one year, probably curve-fit

## Nutshell

Most algos die from over-optimization, not lack of idea. Optimization = parameter improvement (ranges, plateaus, robust zones); danger symptoms: extreme Sharpe, too-smooth equity, single-year success. Real optimization = rule changes WITH economic reason (adjustment example: 2458 → 4208 points); parameter-mining without reason = backtest fairy tale. Curve fitting = noise-fitting; trades past, not future. Walk forward = in-sample optimize → out-sample test → roll; WFE ≥ 70% = healthy. Protection: 3–5 params, broad ranges, simplest rules, 20–30% data untouched, stability first, multi-asset proof. Backtest profit ≠ future profit — walk forward decides survival.

## What It Is NOT

- ❌ **Optimization ≠ curve fitting.** Difference in intent and method: ranges + plateaus + economic reasoning = optimization; exact-number mining on same data = curve fitting. Thin line but clear.
- ❌ **High WFE ≠ guarantee.** 70%+ only says performance transfer reasonably consistent. Regime shocks can still come — sizing discipline separately needed.
- ❌ **Out-of-sample pass ≠ done forever.** Market keeps evolving; validated system also needs periodic re-validation. Walk-forward once then forget not allowed.

3. Plateau vs peak — difference in parameter selection?

<details>
<summary>Sample Answer</summary>

**Answer:** Peak = exact parameter value where backtest maximum (e.g., EMA 23 best). Plateau = broad zone where entire range performs stably (EMA 20–50 all decent). Peak fragile — live at EMA 24 gives different result because that value captured noise. Plateau robust — exact value slightly here-there, edge stays alive. Hence instruction: optimize ranges, not exact numbers.

</details>

4. Walk forward testing steps and WFE calculation?

<details>
<summary>Sample Answer</summary>

**Answer:** Steps: (1) split data into segments, (2) optimize on first segment (in-sample), (3) test on next segment (out-of-sample), (4) roll forward and repeat. WFE ≈ out-of-sample return ÷ in-sample return. Example: in-sample 40%, out-sample 28% → WFE = 70%. Benchmark: 70%+ very good, below that unstable. Every segment demands unseen data, structurally eliminating curve-fitting chance.

</details>
