# 1.4 Overview of Exchanges, APIs and Data Providers

Pichli file mein dekha ki automated system khud orders place karta hai. Lekin ek minute — tera code order kise bhejta hai? Seedha exchange ko? Kisi aur ko? Yeh flow samajh lo toh algo trading ke 90% confusion khatam ho jaate hain, kyunki beginners ki zyadatar problems isi flow ko na samajhne se aati hain. Isliye is file mein teen cheezein detail mein dekhenge — **Exchange, API, aur Data Provider** — aur yeh bhi ki yeh teeno aapas mein kaise jude hain.

## Thoda History — 2000s Ka Scene

Aaj ka system samajhne ke liye peeche jana padega. 2000s ki baat hai:

Us time trading sirf institutions kar sakte the — retail traders nahi. Exchanges toh the (jaise aaj NSE aur BSE hain), lekin aaj jaise brokers exist hi nahi karte the. Aaj ke discount brokers — Angel One, Upstox, Dhan — us time the hi nahi.

Retail trader ke paas hota tha ek normal broker person (insaan). Usko apna order batate the, wo order exchange tak pahunchata tha. Order change karna ho toh bhi wahi karta tha.

Aur APIs? Exchanges technically APIs provide karte the, lekin strict rules the — "aapke paas enough money honi chahiye, tab access milega." Isliye yeh facility sirf big institutions ke paas thi. Retail traders ko na API milti thi na data. Matlab retail algo trading possible hi nahi thi.

Phir early 2000s mein turnaround aaya:

1. Exchange ne co-location servers launch kiye
2. Wahan se exchanges se brokers bane
3. Brokers ne apni APIs launch ki
4. Tab jaakar retail traders broker ke through algo trading kar paye

## Aaj Ka Order Flow

Ab aaj ka system dekhte hain. Normal retail flow aisa hai:

```
Tu (Retail Trader) → Broker → Exchange → Broker → Tu
```

Example se samajh — Angel One tera broker hai:

1. Tune bola: *"mujhe Reliance buy karna hai"*
2. Tu broker ko bolta hai
3. Broker tere behalf pe exchange mein buy karta hai
4. Exchange output return karta hai broker ko
5. Broker wapas tujhe return karta hai

API wala flow bilkul same hai — bas bolne ka tareeka badal jaata hai:

1. Tu API ka use karke broker ko batata hai (code se)
2. Broker wahi same cheez exchange ko batayega
3. Exchange output return karega
4. API tujhe output return karegi

Bas yahi hota hai. Itni si baat hai.

Aur institutions ka flow? Pehle direct exchange ↔ institutions baat karte the — aaj bhi karte hain. Institutions broker se link nahi hote — wo direct apne orders place karte hain, coding ke through. Vijay Kedia jaise bade logon ki khud ki prop desk hoti hai jo direct exchange se baat karti hai — ye kisi broker ko brokerage nahi dete.

## Ye Flow Samajhna Kyu Zaroori Hai

Kyunki jo banda yeh flow samajh leta hai — data + order kaise move hota hai — wo manual trader ki soch se nikal ke quant ki soch mein aa jaata hai.

**Quant = jo cheezon ko mathematically samajhta hai, jo flows aur executions ko samajhta hai.**

Flow clear hai toh algorithm banana bahut easy ho jaata hai, kyunki tujhe pata hai tera code kisse baat karega aur order kahan jaayega.

## Market System Ki Hierarchy

Ab teeno layers ek-ek karke dekhte hain.

### Level 1 — Exchange

Examples: NSE, BSE — crypto mein Binance.

Exchange = market place where all buyers and sellers meet. Jahan sab buyers-sellers milte hain. Aur exchange hi market structure decide karta hai — tick size kya hoga, margin rules kya honge, etc.

Yahan ek rule yaad rakhna: algo trading direct exchange se tabhi possible jab tere paas direct connection ho — wo institutions ke liye hai. Retail trader ka algo exchange se DIRECT connect nahi hota. Tu Zerodha use karta hai toh seedha NSE pe nahi bech sakta. Pehle broker se connect hoga, phir exchange se. Broker hi tujhe aur tere algo ko exchange se connect karta hai — kyunki tu unhi ki APIs use karta hai.

### Level 2 — Broker

Examples: Zerodha, Angel One, Upstox.

Broker = exchange aur tere beech ki middle layer. Tera saara order broker ke through hi exchange tak jaata hai.

Ek exception: Binance exchange BHI hai aur broker BHI — dono roles ek saath nibhata hai.

### Level 3 — API

**API = digital bridge between your CODE and your BROKER (not exchange).** Tera algo isi ke through orders send karta hai, data receive karta hai, aur rules execute karta hai.

## API Kya Hoti Hai — Ghar-Chabi Analogy

Ab API ko ek example se pakka karte hain.

Soch ek ghar hai, aur uska darwaza. Ghar tere dost Rahul ka hai. Tu andar jaana chahta hai. Andar jaane ke liye kya chahiye? Chabi! Chabi se darwaza kholunga tabhi andar ja paunga. Aur agar wo mujhe apni chabi hi na de, toh main uske ghar mein jaun kaise?

Ab mapping dekh:

- **Ghar** = Broker
- **Tu (andar jaane wala)** = Tera Code
- **Darwaze ki chabi** = API Key

Tera code broker se direct baat karne ke liye API key chahiye — wahi chabi hai. (Full form: API = Application Programming Interface.)

Aur chabi sirf tujhe kyun milti hai? Kyunki dost chahta hai ki uske ghar pe sirf main aaun, koi teesra banda na aaye. Exactly waise hi tera broker chahta hai ki tera account sirf tu hi use kar pao, teri API koi aur use na kar paye. Isliye usne specifically TUJHE chabi di hai — ek API key di hai.

Broker app mein (jaise Angel One) login karo → Trading APIs section → Generate API key. Do cheezein milti hain: **API Key** aur **API Secret**. Inhe copy karke apne code mein use kar sakte ho.

⚠️ **Security warning:** Agar yeh API key/secret galati se kisi aur ko de di, toh wo tere account ko code ke through access kar sakta hai — tere naam se orders bhi place kar sakta hai. Isliye kabhi kisi se share mat karna.

### API Se Kya-Kya Kar Sakte Ho

Sab kuch jo trading mein chahiye, programmatically:

- Real-time price fetch
- Historical data fetch
- Place order
- Modify stop loss
- Exit orders
- Check position
- Check PnL
- Manage portfolio

Isliye kehte hain — **API is the backbone of automation.** Signal generate kar loge, but API/broker connection nahi hoga toh trade place nahi kar paoge.

## Types of APIs

Har broker ki apni API documentation hoti hai (jaise Angel One ki). Mukhya 3 types hote hain:

**1. Historical API:** Sirf historical data fetch — kisi bhi stock/index ka past data.

**2. Market Data API:** Current live LTP (Latest Trading Price) — abhi market mein jo price chal raha hai. Isse OHLCV data milta hai (Open, High, Low, Close, Volume), live ticks milte hain (jaise NIFTY mein price change hota hai uski values), aur historical data bhi.

**3. Trading API:** Order execute — buy/sell kar sakte ho, order place kar sakte ho, order status check kar sakte ho (order chal raha hai ya nahi).

Brokers kaise dete hain? Kuch brokers ek hi API pe teeno kaam karwa dete hain. Kuch alag-alag APIs dete hain har kaam ke liye. Most brokers dono (data + trading) dete hain, par kuch sirf ek dete hain — sirf trading API ya sirf data API. Jo milega use karna padega.

## Data Providers — Backtesting Ka Real Engine

Ab chain ka last piece. API se orders jaate hain, lekin strategy banane se pehle kya chahiye? **Data.**

Data provider wo hota hai jo tujhe kisi bhi stock/index ka historical data provide karta hai — jisse tu apni strategy ko test kar sake.

Data kyun chahiye, teen reasons:

1. **Backtest** — purane data pe strategy test karna
2. **Strategy validation** — verify karna ki strategy kaam karti hai
3. **ML training** — machine learning models train karne ke liye data chahiye

Aur yahan ek line hai jo kabhi mat bhoolna:

> **Good data = Good backtesting. Bad data = Fake profit.**

Bad data ka matlab — data ki values galat hain. Result? Backtest mein profit sahi dikhta hai, but actual live market mein wo strategy kaam nahi karegi. Poora mehnat ka result fake.

## Historical Data vs Live Data

Data do type ka aata hai, aur dono ka behaviour alag hai:

**Historical data:** Clean, already processed. Closed candles (final ban chuke). No gaps. Filtering ki zaroorat nahi. Backtesting ke liye use hota hai.

**Live data:** Raw — tick by tick aata hai. Har price movement ke saath badalta hai. Lag ho sakta hai, spikes aa sakte hain. Filtering zaroori hai. Live trading ke liye use hota hai.

Ek algo trader ko dono handle karna aana chahiye — kyunki backtest historical pe hota hai aur paisa live data pe banta hai.

## Full Algo Trading Flow — End to End

Ab sab jodke poora picture dekhte hain:

```
1. Python se Strategy Logic create karo
        ↓
2. Data Provider se Historical Data lao
        ↓
3. BACKTEST karo (strategy verify karo)
        ↓
4. Broker pe LIVE run karo (live algo trading engine)
        ↓
5. Code connect karo Broker API se
        ↓
6. Broker connect karega Exchange se
        ↓
7. LOGS / Dashboard / Monitoring
```

Last step important hai — jab tera algo kaam karna shuru karega, toh wo logs dega (batayega kaisa kaam kar raha hai) aur dashboard provide karega jahan tu dekh sakta hai strategy kaise perform kar rahi hai. Poore results aayenge jinhe monitor kar sakte ho.

Real example: Zerodha ki API ka naam **Kite API** hai. Flow dekho — tera bot Kite API se live price fetch karta hai → logic decide karta hai buy/sell → bot order send karta hai API pe → order jaata hai exchange (NSE) ko → exchange wapas Kite ko return karta hai → Kite tujhe return karta hai. Crypto mein bhi same flow hota hai.

## Nutshell

Order ka safar hai: **tera code → API → broker → exchange** — aur wapas isi raste se response aata hai. Exchange market place hai, broker middle layer hai, API tera code aur broker ke beech ka digital bridge hai. Data providers backtesting ka engine hain — good data = good backtesting, bad data = fake profit.

## What It Is NOT

- ❌ **Tera code exchange se seedha baat nahi karta.** Retail trader ka algo hamesha broker ke through jaata hai. Direct exchange connection sirf institutions ke paas hai.
- ❌ **API = exchange ka door nahi.** API tere code aur BROKER ke beech ka bridge hai. Broker hi exchange se baat karta hai.
- ❌ **Backtest profit = real profit nahi.** Agar data kharab tha, toh backtest ka profit fake hai. Live market mein wahi strategy fail ho sakti hai.
