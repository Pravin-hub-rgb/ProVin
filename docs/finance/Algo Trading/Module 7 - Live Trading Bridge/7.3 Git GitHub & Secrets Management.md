# 7.3 Git, GitHub & Secrets Management

## Git — Mental Model First

**Git = system of SNAPSHOTS of your code.**

At every important change take a "photo" (**commit**),

and can return to old photo anytime!

### Life Without Git:

```text
final.py
final_v2.py
final_v2_REAL.py
final_v2_REAL_bhai_ab_toh_final.py    😩💀
```

You've done this too, right? Everyone has!

### Git's World:

```text
project/
└── server.py     ← ONE file... history SAFE with Git!
```

What Git gives:

```text
BACKUP   → laptop gone? Everything on GitHub!
HISTORY  → which line changed WHEN
UNDO     → new change broke? return to previous commit!
```

## Core Commands — Only Five!

```bash
git init                       # make this folder git-project (once)
git status                     # what changed? (most used!)
git add .                      # stage all changes for next snapshot
git commit -m "webhook added"  # take SNAPSHOT + message
git log --oneline              # see history
```

Workflow ALWAYS this:

```text
EDIT → status → add → commit
```

Tips:

```text
Take small commits        → one feature = one commit
Meaningful messages       → not "fix", but "fix webhook duplicate alerts"
```

Future-you will thank current-you! 🙏

## GitHub — Code's Home on Internet

Git is LOCAL (on your machine).

**GitHub = CLOUD-HOSTING of git-repositories!**

Code uploaded here so:

```text
✅ Remote-backup available
✅ Deployment-platforms (Render!) can connect DIRECTLY
✅ Can show world (portfolio!)
```

("GitHub = Instagram for coders" — instead of photos, post CODE!)

### Setup

```bash
# Create account + NEW REPOSITORY on github.com
# (keep PRIVATE for algo projects!)

git remote add origin https://github.com/you/algo-project.git
git push -u origin main        # local commits → GitHub!
```

After that just `git push` to sync!

Work on another machine? `git pull` to get latest.

## ⚠️ .gitignore — MOST Important File!

**This is the thing promised in 3.9!**

> `.gitignore` = list of FILES that should NOT go into Git!

In your algo-project these MUST be ignored:

```text
# .gitignore
tokens.py          # API KEYS!! Account-hack risk 💀
.env               # environment-secrets
__pycache__/       # Python-cache (useless noise)
venv/              # virtual-environment (thousands files, zero-value)
*.csv              # big data (heavy repo)
```

How it works:

```bash
git add .
git status      # "tokens.py"... NOT SEEN ANYWHERE! ✅ auto-skipped
```

⚠️ **Once COMMITTED, removing from .gitignore is NOT ENOUGH!**

Still remains in history!

Cleaning history is complex...

real fix: **ROTATE KEYS** (delete old, generate new).

## Horror Story That Happens DAILY 😱

Developer did `git push`...

**30 SECONDS later** bots scanned keys!

(GitHub has automated scrapers running 24x7!)

Crypto-mining/trading started from their account!

```text
LESSON: Minutes matter!
```

So rule:

> **Keys should NEVER be written in code —
> so question of push doesn't arise!**

## Environment Variables — Keys' Right Home

So where to keep keys?

**Environment variables (env-vars)** —
values stored in operating-system/cloud that code gets via
`os.getenv()`:

```python
import os

API_KEY    = os.getenv("DHAN_API_KEY")     # only NAME in code!
API_SECRET = os.getenv("DHAN_SECRET")
```

Code now takes **REFERENCE**, not VALUE!

### Locally — .env File (+ python-dotenv)

```text
# .env file (GITIGNORED!)
DHAN_API_KEY=xyz123...
DHAN_SECRET=abc789...
```

```bash
pip install python-dotenv
```

```python
from dotenv import load_dotenv
load_dotenv()                        # loads .env file

api_key = os.getenv("DHAN_API_KEY")  # now value available
```

`.env` in gitignore → NEVER pushed. Perfect local-setup!

### On Cloud — In Dashboard

On platforms like Render, env-vars set via **DASHBOARD-UI** —

no need to write in code at all!

```text
LOCAL:  .env file        → os.getenv()
CLOUD:  Render dashboard → os.getenv()

SAME CODE! Both places! ✅✨
```

This is professional pattern.

## Leaked? Emergency Steps 🚨

```text
1. ROTATE IMMEDIATELY!
   Broker-dashboard → revoke old key → generate new
   (bots already copied it — this is REAL fix!)

2. Clean history (secondary — useless without rotation)

3. CHECK broker-activity
   Suspicious trades? Tell support!
```

## requirements.txt — Dependencies List

Deployment-platform needs to know which libraries to install.

Hand-written list gets TYPOS

(real cohort-notes had WRONG library name!) —

so auto-generate:

```bash

```

Output:

```text

pandas==2.1.4
requests==2.31.0
python-dotenv==1.0.0
```

Exact versions included —

"worked on my machine, why not cloud?" problem SOLVED!

## Nutshell

Git = snapshots (init/status/add/commit/log); GitHub = remote-home (remote-add + push). ⚠️ **.gitignore NON-NEGOTIABLE:** tokens.py/.env/__pycache__/venv never commit. Keys' home = env-vars: local `.env`+dotenv, cloud dashboard — code only does `os.getenv()`. Leak = INSTANT rotation! Dependencies: `pip freeze > requirements.txt` (hand-written = typo-risk!). This setup is LICENSE for M8-deployment!

## What It Is NOT

- ❌ **GitHub ≠ backup-only tool.** Backup is side-benefit; real power: history + undo + collaboration + deployment-integration. Git's ROI across entire career!
- ❌ **Private repo ≠ secrets safe.** Committing keys even in private repo is wrong practice — team-members, future-leaks, integrated-apps all risk-surface. Rule SAME: keys in env-vars, never in code.
- ❌ **requirements.txt not hand-edit file!** Generated from `pip freeze`; manual-list outdated/typo-prone (REAL incident: course-notes had wrong package-name!). New package added → re-run freeze.
