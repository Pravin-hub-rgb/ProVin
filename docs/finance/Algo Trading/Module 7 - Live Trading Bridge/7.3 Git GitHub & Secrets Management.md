# 7.3 Git, GitHub & Secrets Management

## Git Kya Hai — Mental Model Pehle

**Git = tere code ke snapshots ka system.** Har important change pe "photo" lete ho (commit), aur kabhi bhi purani photo pe wapas ja sakte ho.

Bina git ki zindagi:

```text
final.py
final_v2.py
final_v2_REAL.py
final_v2_REAL_bhai_ab_toh_final.py    😩
```

Git ki duniya:

```text
project/
└── server.py        ← ek hi file, history git ke paas safe
```

Git kya deta hai:
- **Backup** — laptop kho gaya? GitHub pe sab hai
- **History** — kaunsi line kab badli, kisne kiya
- **Undo** — naya change ne kuch toda? pichle commit pe rollback
- **Collaboration** — multiple machines/log pe same project

Aur ek fun fact jo ab meaningful hai: Git = "Instagram for coders" jaisa analogy original cohort mein use hua tha — photos post karte ho (commits), followers dekh sakte hain (public repo).

## Core Commands — Sirf 6

```bash
git init                      # is folder ko git project banao (ek baar)
git status                    # kya badla hai? (sabse zyada use hone wala!)
git add server.py             # yeh file agle snapshot mein daalo
git add .                     # saare changes daalo
git commit -m "webhook added" # snapshot lo message ke saath
git log --oneline             # history dekho
```

Workflow hamesha: **edit → status → add → commit.** Chhote-chhote commits lo ("ek feature = ek commit"), messages meaningful likho — future-tu current-tu ko dhanyawad dega.

## GitHub — Code Ka Ghar Internet Pe

Git local hai (tere machine pe). **GitHub = git repositories ka cloud hosting.** Yahan code upload hota hai taaki:
- Remote backup mile
- Deployment platforms (Render!) directly connect ho sakein
- Duniya ko dikha sakein (portfolio!)

Setup:

```bash
# github.com pe account + new repository banao (private rakhna algo ke liye!)

git remote add origin https://github.com/tu/algo-project.git
git push -u origin main       # local commits → GitHub
```

Aage se bas `git push` karne se sync. Doosri machine pe kaam karna ho: `git pull` se latest lo.

## ⚠️ .gitignore — Sabse Important File

Yahi wo cheez hai jo 3.9 mein promise ki thi. **`.gitignore` ek list hai un files ki jo git MEIN NAHI jaani chahiye.**

Tere algo project mein yeh MUST ignore hon:

```text
# .gitignore
tokens.py          # API KEYS! Account hack risk
.env               # environment secrets
__pycache__/       # Python cache — useless noise
venv/              # virtual environment — hazaron files, zero value
*.csv              # bada data — repo heavy (optional)
ngrok.exe          # binaries
```

Kaise kaam karta hai:

```bash
git add .                # tokens.py SKIP ho gaya automatically
git status               # "Untracked: nothing" — tokens git ke radar pe hi nahi
```

⚠️ **Ek baar commit ho gayi toh .gitignore se nikalna KAafi nahi** — history mein phir bhi pada hai! History se hatana complex hai; asli fix: **keys rotate kar do** (purani delete, nayi generate).

### Horror Story Jo Roz Hota Hai

Developer ne `git push` diya → 30 second baad bots ne keys scan kar li (GitHub pe automated scrapers 24x7 chalte hain!) → crypto mining/trading unke account se shuru. **Minutes matter karte hain.** Isliye rule: keys code mein likhi HI nahi jaani chahiye — toh push mein jaane ka sawaal hi nahi.

## Environment Variables — Keys Ka Sahi Ghar

Toh keys rakhein kahan? **Environment variables (env vars)** — operating system/cloud ke paas stored values jo code mein `os.getenv()` se milti hain:

```python
import os

API_KEY    = os.getenv("DHAN_API_KEY")     # code mein sirf NAAM
API_SECRET = os.getenv("DHAN_SECRET")
```

Code ab key ka **reference** leta hai, value nahi. Value kahan hai?

### Locally — .env File (+ python-dotenv)

```text
# .env   (GITIGNORED!)
DHAN_API_KEY=xyz123...
DHAN_SECRET=abc789...
```

```bash
pip install python-dotenv
```

```python
from dotenv import load_dotenv
load_dotenv()                    # .env file load kar deta hai

api_key = os.getenv("DHAN_API_KEY")
```

`.env` gitignore mein hai → kabhi push nahi hogi. Perfect local setup.

### Cloud Pe — Dashboard Mein

Jab Render jaise platform pe deploy karenge (Module 8), wahan env vars **dashboard UI** se set hoti hain — code mein kahin nahi likhna padta. Same `os.getenv()` code dono jagah chalta hai:

```text
Local:  .env file      → os.getenv()
Cloud:  dashboard vars → os.getenv()
```

Ek hi code, do environments. Yehi professional pattern hai.

### Leak Ho Gayi Toh — Emergency Steps

1. **Turant rotate karo** — broker dashboard pe purani key revoke, nayi generate
2. Commit delete/history-clean karo (par rotation hi asli fix hai — bots ne copy kar li hogi)
3. Broker support ko batao agar suspicious activity dikhe

## requirements.txt — Dependencies Ki List

Deployment platform ko batana padta hai kaunsi libraries install karni hain. Hand-written list mein typo ho jaata hai (original cohort notes mein ek library ka naam hi galat likha tha!) — isliye auto-generate karo:

```bash
pip freeze > requirements.txt
```

Output aisa hoga:

```text
flask==3.0.0
pandas==2.1.4
requests==2.31.0
python-dotenv==1.0.0
kiteconnect==5.0.1
```

Exact versions included — "mere laptop pe chal raha tha, cloud pe kyun nahi" problem solved.

## Nutshell

Git = snapshots (init/add/commit/log); GitHub = remote ghar (remote add + push). ⚠️ `.gitignore` non-negotiable: tokens.py/.env/__pycache__/venv kabhi commit nahi. Keys ka ghar = environment variables: local mein `.env` + python-dotenv, cloud pe dashboard — code sirf `os.getenv()` karta hai. Leak = instant rotation. Dependencies: `pip freeze > requirements.txt` (hand-written list mein typos hoti hain!). Yeh setup Module 8 deployment ka license hai — bina iske Render pe deploy karna account-hack invitation hai.

## What It Is NOT

- ❌ **GitHub = backup-only tool nahi.** Backup toh side-benefit hai; asli power history + undo + collaboration + deployment-integration ki hai. Git seekhne ka ROI poore career mein milta hai.
- ❌ **Private repo = secrets safe nahi.** Private repo mein bhi keys commit karna galat practice hai — team members, future leaks, integrated apps sab risk surface hain. Rule same hai: keys env-vars mein, code mein kabhi nahi.
- ❌ **requirements.txt hand-edit karne ki file nahi.** `pip freeze` se generate hota hai; manually likha list outdated/typo-prone hoti hai (asli case: original notes mein galat package naam tha). Regenerate karo jab bhi naya package add ho.
