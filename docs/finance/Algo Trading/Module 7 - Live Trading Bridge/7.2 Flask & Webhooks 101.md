# 7.2 Flask & Webhooks 101

## Web Server Kya Hota Hai?

Restaurant analogy chalao:

```text
Tu (customer)      → order deta hai     → Waiter    → Kitchen banata hai
Browser/App        → request bhejta hai → Server    → response wapas
```

**Web server = ek program jo continuously chalta rehta hai aur requests ka wait karta hai.** Request aayi → process ki → response bheja. Tera Python code agar server ban jaaye, toh TradingView usse message bhej sakegi.

## HTTP Ke Basics — Sirf Jitna Chahiye

HTTP = browsers/servers ke beech ki bhasha. Do cheezein yaad rakho:

**1. Method — request ka intent:**

| Method | Matlab | Example |
|---|---|---|
| `GET` | "Mujhe data do" | Page kholna, price poochna |
| `POST` | "Main tumhe data de raha hun" | Form submit, **alert bhejna** |

Humara use-case POST hai — TradingView humein signal DATA bhejegi.

**2. Body/JSON — request ke andar ka data:**

```json
{
  "symbol": "RELIANCE",
  "action": "BUY",
  "price": 2456.5
}
```

JSON = key-value format jo har system samajhta hai. Python dict jaisa hi.

## Flask — 10 Line Ka Server

Flask Python ka sabse popular micro web-framework hai. Install:

```bash
pip install flask
```

Poora working server:

```python
from flask import Flask, request

app = Flask(__name__)

@app.route("/hello", methods=["GET"])
def hello():
    return {"message": "server zinda hai!"}

@app.route("/signal", methods=["POST"])
def signal():
    data = request.get_json()          # JSON body → Python dict
    print(f"SIGNAL AAYA: {data}")
    return {"status": "received"}

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)
```

Chalao:

```bash
python server.py
```

Output: `Running on http://127.0.0.1:5000`. Server ab live hai — requests ka wait kar raha hai.

Line by line:
- `@app.route("/signal", methods=["POST"])` — decorator jo kehta hai "jab koi `/signal` address pe POST bheje, yeh function chalao"
- `request.get_json()` — incoming JSON body ko Python dict mein convert
- Return value = response jo wapas jaata hai

Test karne ke liye browser mein `http://127.0.0.1:5000/hello` kholo (GET) — JSON dikhega.

## Localhost Concept — Aur Uski Problem

Woh address `127.0.0.1` = **localhost** = *"yehi machine."* Tera sirf apna computer hi isse access kar sakta hai.

⚠️ Yahi problem hai! TradingView ke servers internet pe hain — woh tere laptop ke andar ke localhost ko **pahunch hi nahi sakte**. Tera laptop home WiFi ke NAT/router ke peeche chhupa hai, upar se firewall bhi hai.

```text
TradingView ──✗──> tera-router ──> tera-laptop:5000   (bahar se blocked)
Tera browser ──✓──> 127.0.0.1:5000                    (andar se fine)
```

Solution chahiye: ek **public URL** jo bahar se reachable ho aur requests ko tere local server tak forward kare. Enter: **ngrok**.

## Ngrok — Tunnel Ka Jaadu

Ngrok ek **tunnel** banata hai: public HTTPS URL ↔ tere laptop ka port 5000.

```text
TradingView → https://abc123.ngrok-free.app → ngrok-cloud → tunnel → laptop:5000
```

Setup:

```bash
# 1. Download & install (ngrok.com) — OS ke hisaab se
# 2. Free account banao, auth token connect karo:
ngrok config add-authtoken <tera_token>

# 3. Tunnel start karo (server.py parallel chal raha hona chahiye):
ngrok http 5000
```

Output mein milega:

```text
Forwarding  https://abc123.ngrok-free.app -> http://localhost:5000
```

Bas! Ab yeh public HTTPS URL duniya se accessible hai — TradingView isko webhook target bana sakti hai. HTTPS already included (webhooks ke liye zaroori).

⚠️ **Free-tier catch:** ngrok restart hone pe **URL badal jaata hai** (`abc123` → naya random). Har restart pe TradingView webhook settings update karni padegi. Paid tier static URL deta hai.

## Webhook — Event-Driven HTTP POST

Ab poora concept ek line mein:

> **Webhook = "jab kuch hota hai, toh main tumhe khud POST bhej dunga"** — event-triggered, server-to-server HTTP call.

Regular API vs webhook ka farq:

```text
Polling (regular API):   tu baar-baar poochta hai "kuch hua? ...ab? ...ab?"
Webhook:                 hone pe woh KHUD tere paas aata hai
```

TradingView alert system webhook support karta hai: jab tera alert fire ho, TradingView tere diye URL pe **POST request** bhej deta hai jismein message body hota hai.

## End-to-End Flow — Ab Poora Picture

```text
1. Tera strategy (Pine Script) signal deti hai
2. TradingView ALERT fire hota hai
3. Alert payload POST hota hai → ngrok public URL
4. Ngrok tunnel → tere laptop ke Flask server (port 5000)
5. Flask route parse karta hai JSON
6. orders.py ka function call → BROKER API → ORDER!
```

Flask side ka complete receiver:

```python
from flask import Flask, request
from orders import place_buy, place_sell   # 7.1 wali file!

app = Flask(__name__)

@app.route("/webhook", methods=["POST"])
def webhook():
    data = request.get_json()
    action = data.get("action", "").upper()
    symbol = data.get("symbol", "")
    qty = int(data.get("qty", 1))

    if action == "BUY":
        place_buy(symbol, qty)
    elif action == "SELL":
        place_sell(symbol, qty)

    return {"status": f"{action} processed"}

app.run(host="0.0.0.0", port=5000)
```

Aur TradingView alert message box mein (JSON format):

```json
{"symbol": "RELIANCE", "action": "BUY", "qty": 10}
```

Test bina TradingView ke bhi kar sakte ho — `requests` se khud POST maaro:

```python
import requests
requests.post("https://abc123.ngrok-free.app/webhook",
              json={"symbol": "RELIANCE", "action": "BUY", "qty": 10})
```

Server terminal mein `SIGNAL AAYA` dikha? Pipeline zinda hai.

## Security Notes — Zaroori

Public URL = duniya ke liye public. Do basic protections:

1. **Secret path ya token check** — URL ko guessable mat hone do:
```python
@app.route("/webhook/<secret_key>", methods=["POST"])   # long random key
def webhook(secret_key):
    if secret_key != MY_SECRET:
        return {"status": "unauthorized"}, 401
    ...
```
2. **Server publicly 24x7 exposed mat chhodo** — testing ke baad ngrok band karo. Production deployment (Render) alag discipline lega.

Aur duplicate-alert problem yaad rakho (fast candles pe TradingView multiple alerts fire karta hai) — 7.1 ki idempotency guard yahan practical hoti hai: same-candle second BUY ignore karo.

## Nutshell

Web server = requests sunne wala program; Flask se 10 lines mein ban jaata hai (`@app.route` + `request.get_json()`). Localhost bahar se unreachable — isliye ngrok tunnel: public HTTPS URL → laptop port. Webhook = event-triggered POST (polling ka ulta). Full pipeline: Pine signal → TV alert → ngrok → Flask → orders.py → broker API. Security: secret path + endpoint hygiene + idempotency guard. Yeh plumbing Module 8 ke har project ka backbone hai. Par pipeline mein abhi ek kamzori hai — keys kahan stored hain? Agli file: Git, GitHub & Secrets.

## What It Is NOT

- ❌ **Webhook = API nahi.** API general-purpose request-response interface hai; webhook uska specific pattern hai — event pe server KHUD tumhare URL pe POST karta hai. Direction reversed hai.
- ❌ **Ngrok = hosting nahi.** Tunnel hai — tere laptop band = service dead. 24x7 chalane ke liye cloud deployment chahiye (Module 8: Render).
- ❌ **GET se data bhejna webhooks ka tareeka nahi.** GET URLs logs/browser-history mein dikhte hain — order instructions leak risk. Sensitive payloads POST body (JSON) mein hi jaate hain.

**In Your Own Words**

1. Localhost aur public URL mein farq? Ngrok bridge kaise banata hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** localhost (127.0.0.1) sirf usi machine se accessible hai jo server chala rahi hai — NAT router + firewall bahar ki requests block karte hain, toh TradingView pahunch hi nahi sakti. Public URL internet se reachable hota hai. Ngrok tunnel banata hai: public HTTPS URL pe aayi request ngrok-cloud se hote hue tere local port tak forward hoti hai. Matlab external service ko lagta hai woh proper server se baat kar rahi hai, asli processing tere laptop pe hoti hai.

</details>

2. Polling vs webhook — automation mein webhook kyun better?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Polling = tu repeatedly poochta hai "signal aaya?" — wasteful (empty checks), delayed (poll interval jitna), rate-limited. Webhook = source khud event pe POST bhejta hai — instant (seconds), efficient (sirf actual events), simple (koi polling loop nahi). Trading alerts time-sensitive hain — seconds matter — isliye webhook natural fit hai. Cost: tera server reachable hona chahiye (ngrok/deployment).

</details>

3. Flask route decorator kya karta hai? `methods=["POST"]` kyun specify?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `@app.route("/webhook")` URL-path ko Python function se bind karta hai — us path pe request aaye toh function chalega. methods parameter batata hai kaunse HTTP methods accept karne hain: POST matlab incoming DATA expect kar rahe hain (alert payload), GET sirf page-fetch hota. Specify na karo toh default GET-only — TradingView ka POST 405 error deta. Explicit = safe.

</details>

4. Free ngrok ka URL-restart problem kya hai, production fix kya hoga?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Free tier har restart pe random subdomain deta hai (abc123.ngrok.app → xyz789...) — purana URL dead. TradingView webhook settings mein stored URL ab galat hai → alerts fail silently. Har restart pe manual update = fragile. Fixes: paid static domain; ya production-grade deployment jahan platform stable URL deta hai (Module 8: Render ka *.onrender.com URL permanent rehta hai).

</details>

5. Webhook endpoint pe kaunse 2 security measures minimum chahiye?

<details>
<summary>Sample Jawab</summary>

**Jawab:** (1) Secret path/token — URL mein random unguessable segment ya header-token check; unauthorized requests 401 return karein (warna koi bhi tera URL dhundh ke fake BUY/SELL trigger kar sakta hai!). (2) Idempotency/dedup guard — same candle ke multiple alerts pe duplicate orders block (open-position check ya last-signal-timestamp compare). Bonus: endpoint ko test ke baad band karna, logs monitor karna.

</details>
