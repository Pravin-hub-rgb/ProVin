# 7.2 Flask & Webhooks 101

## What is Web Server?

Restaurant analogy:

```text
YOU (customer)   → place order → WAITER → KITCHEN makes
BROWSER/APP      → send request → SERVER → response back
```

> **Web server = program that runs ALWAYS
> and WAITS for requests.**

Request came → processed → response sent. That's it!

If your Python code becomes SERVER...

TradingView can MESSAGE it!

## HTTP Basics — Only As Much As Needed

HTTP = common language of browsers/servers.

Remember two things:

### 1. Method — Request's Intent

| Method | Meaning | Example |
|---|---|---|
| `GET` | "GIVE me DATA" | Opening page |
| `POST` | "I'm GIVING you data!" | Form submit, sending ALERT |

Our case is POST — TradingView will SEND us signal-data!

### 2. Body — Data Inside Request

```json
{
  "symbol": "RELIANCE",
  "action": "BUY",
  "qty": 10
}
```

This is **JSON** — key-value format every system understands.

Looks like Python dict, right? Basically same!

## Flask — 10-Line Server!

**Flask** = Python's most popular mini web-framework.

Install:

```bash
pip install flask
```

Complete WORKING server:

```python
from flask import Flask, request

app = Flask(__name__)

@app.route("/hello", methods=["GET"])
def hello():
    return {"message": "server is alive!"}

@app.route("/signal", methods=["POST"])
def signal():
    data = request.get_json()          # JSON came → Python dict!
    print(f"SIGNAL CAME: {data}")
    return {"status": "received"}

app.run(host="0.0.0.0", port=5000)
```

Run:

```bash
python server.py
```

```text
Running on http://127.0.0.1:5000
```

Server LIVE — waiting for requests! 🟢

### Line-by-Line Understand

```python
app = Flask(__name__)
```

Made an app-object — this is your server.

```python

```

**Route decorator** = address-board:

*"when someone POSTs to /signal, run `signal()` function!"*

```text
/signal   → website's address (like home address)
POST      → data coming (GET alone won't work!)
```

```python
data = request.get_json()
```

Incoming JSON-body converted to **Python dict.**

Now `data["action"]` like normal dict-operations possible!

## Localhost Problem — Most Interesting Part!

Look at address: `127.0.0.1` = **localhost** =

*"ONLY THIS MACHINE."*

Meaning only YOUR computer can open this server!

```text
Your browser ──✅──> localhost:5000        (from inside fine!)
TradingView ──❌──> your-router ──> laptop:5000
               (blocked from outside! NAT + firewall)
```

**Problem:** TradingView's servers are on INTERNET —

they can't REACH your laptop's INSIDE localhost at all!

Solution needed: a **PUBLIC URL** visible from outside...

that FORWARDS requests to your local server.

Enter the hero: **NGROK** 🦸

## Ngrok — Tunnel's Magic

Ngrok creates a **TUNNEL:**

```text
PUBLIC URL (ngrok's) ↔ YOUR laptop port 5000
```

```text
TradingView → https://abc123.ngrok-free.app   (public, visible to all)
                     ↓ ngrok cloud
               through tunnel...
                     ↓
            your-laptop:5000    (Flask receives!)
```

### Setup — Three Steps

```bash
# 1. Download + install from ngrok.com

# 2. Create free account, connect auth-token:
ngrok config add-authtoken <your_token>

# 3. Start tunnel (server.py running in parallel!):
ngrok http 5000
```

Output:

```text
Forwarding  https://abc123.ngrok-free.app -> http://localhost:5000
            ↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑
            THIS PUBLIC URL YOU'LL GET!
```

Done! Now this URL accessible to world —

TradingView can make it webhook-target!

HTTPS included (needed for webhooks!).

⚠️ **Free-tier catch:** ngrok URL CHANGES on restart!

(`abc123` → new random name)

Every restart TradingView settings need update.

(Paid tier gives static URL.)

## Webhook — Event-Driven POST

Now whole concept in ONE line:

> **Webhook = "when something HAPPENS, I'll POST to you myself!"**

Event-triggered, server-to-server HTTP call.

### Polling vs Webhook

```text
POLLING (regular API):
You ask repeatedly: "signal came? ...now? ...now? ...now?"
(waste of time, delayed, rate-limits!)

WEBHOOK:
When it happens, IT COMES to you itself!
(instant ✅ efficient ✅ simple ✅)
```

Trading alerts are TIME-SENSITIVE —

hence webhook is natural choice!

## Complete Flow — At a Glance

```text
1. Pine strategy gives signal
2. TradingView ALERT fires
3. Alert POSTs → ngrok public URL
4. Tunnel → your laptop's Flask (:5000)
5. Flask route parses JSON
6. orders.py function call → BROKER API → ORDER! 🚀
```

Complete receiver code:

```python
from flask import Flask, request
from orders import place_buy, place_sell     # from 7.1!

app = Flask(__name__)

@app.route("/webhook", methods=["POST"])
def webhook():
    data = request.get_json()
    action = data.get("action", "").upper()
    symbol = data.get("symbol", "")
    qty = int(data.get("qty", 1))

    if action == "BUY":
        place_buy(symbol, qty)
    elif action == "SELL":
        place_sell(symbol, qty)

    return {"status": f"{action} processed"}

app.run(host="0.0.0.0", port=5000)
```

TradingView alert-box (JSON format):

```json
{"symbol": "RELIANCE", "action": "BUY", "qty": 10}
```

## Security Notes — Necessary Things

Public URL = public to WORLD!

Two basic protections:

### 1. Secret Path / Token Check

Don't make URL GUESSABLE:

```python
@app.route("/webhook/<secret_key>", methods=["POST"])
def webhook(secret_key):
    if secret_key != MY_SECRET:            # long random string!
        return {"status": "unauthorized"}, 401
    # ...real logic here...
```

Otherwise anyone can find your URL and trigger FAKE BUY/SELL!! 😱

### 2. Endpoint Hygiene

After testing, turn ngrok OFF —

don't leave server publicly exposed 24x7.

Production deployment (Module 8) takes different discipline.

And remember duplicate-alert problem?

(Fast candles make TradingView fire MULTIPLE alerts!)

7.1's **idempotency guard** becomes practical here:

ignore second BUY on same candle!

## Nutshell

Web server = request-listening program; Flask in 10 lines (`@app.route` + `request.get_json()`). Localhost unreachable from outside (NAT/firewall) → ngrok tunnel: public HTTPS URL ↔ laptop-port. Webhook = event-triggered POST (opposite of polling!). Full pipeline: Pine-signal → TV-alert → ngrok → Flask → orders.py → broker-API. Security: secret-path + idempotency-guard + endpoint-hygiene. This plumbing is backbone of every M8 project!

## What It Is NOT

- ❌ **Webhook ≠ API!** API is general request-response interface. Webhook is specific PATTERN — on event, server itself POSTs to your URL. Direction is REVERSED!
- ❌ **Ngrok ≠ hosting.** Just tunnel — laptop off = service DEAD! For 24x7 need real cloud-deployment (M8: Render).
- ❌ **Don't send data with GET in webhooks.** GET-URLs appear in logs/browser-history — order-instructions LEAK risk! Sensitive payloads always in POST-body (JSON).

**In Your Own Words**

1. Localhost vs public URL? How does ngrok bridge?

<details>
<summary>Sample Answer</summary>

**Answer:** Localhost (127.0.0.1) accessible only from SAME machine running server — NAT-router+firewall block outside requests, so TradingView can't reach. Public URL internet-reachable. Ngrok creates TUNNEL: request on public-HTTPS-URL → ngrok-cloud → forwarded to your local-port. External service sees proper server, actual processing on your laptop!

</details>

2. Polling vs webhook — why webhook better in automation?

<details>
<summary>Sample Answer</summary>

**Answer:** Polling = you repeatedly ask "signal came?" — wasteful (empty-checks), DELAYED (wait poll-interval), rate-limited. Webhook = source itself POSTs on event — instant (seconds), efficient (only actual events), simple (no polling-loop). Trading alerts TIME-SENSITIVE — seconds matter — hence webhook natural-fit. Cost: your server must be REACHABLE (ngrok/deployment).

</details>

3. What do Flask route decorator + methods=["POST"] do?

<details>
<summary>Sample Answer</summary>

**Answer:** @app.route("/webhook") BINDS URL-path to Python-function — when request comes on that address, that function runs. methods=["POST"] says which HTTP-method to accept: POST = incoming-DATA expected (alert-payload). Default is GET-only — POST would give 405-error! Explicit = safe. request.get_json() then turns body into dict.

</details>

4. Free-ngrok URL-restart problem? Production fix?

<details>
<summary>Sample Answer</summary>

**Answer:** Free-tier gives RANDOM subdomain every restart (abc123.ngrok.app → xyz789...) — old URL DEAD! Stored URL in TradingView-webhook-settings now WRONG → alerts SILENTLY FAIL! Manual update every restart = fragile system. Fixes: paid static-domain, OR production-platform with stable-URL (M8: Render's *.onrender.com stays permanent!).

</details>

5. Two minimum security measures on webhook endpoint?

<details>
<summary>Sample Answer</summary>

**Answer:** (1) SECRET-PATH/TOKEN — random unguessable segment in URL or header-token check; unauthorized → 401 (otherwise ANYONE can find your URL and trigger fake-BUY/SELL!!). (2) IDEMPOTENCY/DEDUP-GUARD — block duplicate-orders on same-candle multiple-alerts (open-position check or last-signal-timestamp compare). Bonus: turn off endpoint after testing + monitor logs!

</details>
