# 7.2 Flask & Webhooks 101

## Web Server Kya Hota Hai?

Restaurant analogy chalao:

```text
TU (customer)   → order deta hai → WAITER → KITCHEN banata hai

BROWSER/APP     → request bhejta hai → SERVER → response wapas
```

> **Web server = ek program jo HAMESHA chalta rehta hai
> aur requests ka WAIT karta hai.**

Request aayi → process ki → response bheja. Bas!

Tera Python code agar SERVER ban jaye...

toh TradingView usse message BHEJ sakegi!

## HTTP Ke Basics — Sirf Utna Jitna Chahiye

HTTP = browsers/servers ki common language.

Do cheezein yaad rakho:

### 1. Method — Request Ka Intent

| Method | Matlab | Example |
|---|---|---|
| `GET` | "Mujhe DATA DO" | Page kholna |
| `POST` | "Main tumhe data DE RAHA hun!" | Form submit, ALERT bhejna |

Humara case POST hai — TradingView humein signal-data BHEJEGI!

### 2. Body — Request Ke Andar Ka Data

```json
{
  "symbol": "RELIANCE",
  "action": "BUY",
  "qty": 10
}
```

Yeh **JSON** hai — key-value format jo HAR system samajhta hai.

Python dict jaisa hi dikhta hai na? Wahi hai basically!

## Flask — 10 Line Ka Server!

**Flask** = Python ka sabse popular mini web-framework.

Install:

```bash
pip install flask
```

Poora WORKING server:

```python
from flask import Flask, request

app = Flask(__name__)

@app.route("/hello", methods=["GET"])
def hello():
    return {"message": "server zinda hai!"}

@app.route("/signal", methods=["POST"])
def signal():
    data = request.get_json()          # JSON aaya → Python dict!
    print(f"SIGNAL AAYA: {data}")
    return {"status": "received"}

app.run(host="0.0.0.0", port=5000)
```

Chalao:

```bash
python server.py
```

```text
Running on http://127.0.0.1:5000
```

Server LIVE hai — requests ka wait kar raha! 🟢

### Line-by-Line Samajh

```python
app = Flask(__name__)
```

Ek app-object bana — yehi tera server hai.

```python
@app.route("/signal", methods=["POST"])

```

**Route decorator** = address-board:

*"jab koi /signal pe POST bheje, `signal()` function chalana!"*

```text
/signal   → website ka address (jaise ghar ka pata)
POST      → data aane wala hai (sirf GET nahi chalega!)
```

```python
data = request.get_json()
```

Aaye hue JSON-body ko **Python dict mein convert** kiya.

Ab `data["action"]` jaise normal dict-operations kar sakte ho!

## Localhost Problem — Sabse Interesting Hissa!

Woh address dekho: `127.0.0.1` = **localhost** =

*"SIRF YEHI MACHINE."*

Matlab sirf TERA computer hi is server ko khol sakta hai!

```text
Tera browser ──✅──> localhost:5000        (andar se fine!)

TradingView ──❌──> tera-router ──> laptop:5000
              (bahar se BLOCKED! NAT + firewall)
```

**Problem:** TradingView ke servers INTERNET pe hain —

woh tere laptop ke ANDAR ke localhost ko PAHUNCH hi nahi sakte!

Solution chahiye: ek **PUBLIC URL** jo bahar se dikhe...

aur requests ko tere local server tak FORWARD kare.

Enter the hero: **NGROK** 🦸

## Ngrok — Tunnel Ka Jaadu

Ngrok ek **TUNNEL** banata hai:

```text
PUBLIC URL (ngrok ka) ↔ TERA laptop port 5000
```

```text
TradingView → https://abc123.ngrok-free.app   (public, sabko dikhta)
                    ↓ ngrok cloud
              tunnel se through...
                    ↓
           tera-laptop:5000    (Flask receive karta hai!)
```

### Setup — Teen Steps

```bash
# 1. ngrok.com se download + install

# 2. Free account banao, auth-token connect:
ngrok config add-authtoken <tera_token>

# 3. Tunnel start (server.py parallel chalu ho!):
ngrok http 5000
```

Output:

```text
Forwarding  https://abc123.ngrok-free.app -> http://localhost:5000
            ↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑↑
            YEH PUBLIC URL MILEGA!
```

Bas! Ab yeh URL duniya se accessible —

TradingView isse webhook-target bana sakti hai!

HTTPS bhi included (webhooks ke liye zaroori!).

⚠️ **Free-tier catch:** ngrok RESTART pe URL BADAL jaata hai!

(`abc123` → naya random name)

(Paid tier static URL deta hai.)

## Webhook — Event-Driven POST

Ab poora concept EK line mein:

> **Webhook = "jab kuch HOTA hai, main khud tumhe POST bhej dunga!"**

Event-triggered, server-to-server HTTP call.

### Polling vs Webhook

```text
POLLING (regular API):
Tu baar-baar poochta hai: "signal aaya? ...ab? ...ab? ...ab?"
(waste of time, delayed, rate-limits!)

WEBHOOK:
Hone pe WOH KHUD tere paas aata hai!
(instant ✅ efficient ✅ simple ✅)
```

Trading alerts TIME-SENSITIVE hain —

isliye webhook hi natural choice hai!

## Poora Flow — Ek Nazar Mein

```text
1. Pine strategy signal deti hai
2. TradingView ALERT fire hota hai
3. Alert POST hota hai → ngrok public URL
4. Tunnel → tere laptop ka Flask (:5000)
5. Flask route JSON parse karta hai
6. orders.py function call → BROKER API → ORDER! 🚀
```

Complete receiver code:

```python
from flask import Flask, request
from orders import place_buy, place_sell     # 7.1 wali file!

app = Flask(__name__)

@app.route("/webhook", methods=["POST"])
def webhook():
    data = request.get_json()
    action = data.get("action", "").upper()
    symbol = data.get("symbol", "")
    qty = int(data.get("qty", 1))

    if action == "BUY":
        place_buy(symbol, qty)
    elif action == "SELL":
        place_sell(symbol, qty)

    return {"status": f"{action} processed"}

app.run(host="0.0.0.0", port=5000)
```

TradingView alert-box mein (JSON format):

```json
{"symbol": "RELIANCE", "action": "BUY", "qty": 10}
```

## Security Notes — Zaroori Baatein

Public URL = DUNIYA ke liye public!

Do basic protections:

### 1. Secret Path / Token Check

URL ko GUESSABLE mat hone do:

```python
@app.route("/webhook/<secret_key>", methods=["POST"])
def webhook(secret_key):
    if secret_key != MY_SECRET:            # long random string!
        return {"status": "unauthorized"}, 401
    # ...asli logic yahan...
```

Warna koi bhi tera URL dhundh ke FAKE BUY/SELL trigger kar sakta hai!! 😱

### 2. Endpoint Hygiene

Testing ke baad ngrok BAND karo —

server publicly 24x7 exposed mat chhodo.

Production deployment (Module 8) alag discipline lega.

Aur duplicate-alert problem yaad rakho?

(Fast candles pe TradingView MULTIPLE alerts fire karta hai!)

7.1 ki **idempotency guard** yahan practical hoti hai:

same-candle second BUY ignore karo!

## Nutshell

Web server = requests sunne-wala program; Flask se 10 lines (`@app.route` + `request.get_json()`). Localhost bahar se UNREACHABLE (NAT/firewall) → ngrok tunnel: public HTTPS URL ↔ laptop-port. Webhook = event-triggered POST (polling ka ulta!). Full pipeline: Pine-signal → TV-alert → ngrok → Flask → orders.py → broker-API. Security: secret-path + idempotency-guard + endpoint-hygiene. Yeh plumbing M8 ke har project ka backbone hai!

## What It Is NOT

- ❌ **Webhook = API nahi!** API general request-response interface hai. Webhook uska specific PATTERN hai — event pe server KHUD tumhare URL pe POST karta hai. Direction REVERSED hoti hai!
- ❌ **Ngrok = hosting NAHI hai.** Sirf tunnel hai — tera laptop band = service DEAD! 24x7 ke liye real cloud-deployment chahiye (M8: Render).
- ❌ **GET se data nahi bhejte webhooks me.** GET-URLs logs/browser-history me dikhte hain — order-instructions LEAK risk! Sensitive payloads hamesha POST-body (JSON) me.

**In Your Own Words**

1. Localhost vs public URL? Ngrok bridge kaise banata hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Localhost (127.0.0.1) sirf USI machine se accessible hai jo server chala rahi hai — NAT-router+firewall bahar ki requests block karte hain, toh TradingView pahunch HI nahi sakti. Public URL internet-se-reachable hota hai. Ngrok TUNNEL banata hai: public-HTTPS-URL pe aayi request → ngrok-cloud → tere local-port tak forward. Matlab external-service ko proper-server lagta hai, asli-processing tere laptop pe hoti hai!

</details>

2. Polling vs webhook — automation mein webhook kyun better?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Polling = tu repeatedly poochta hai "signal aaya?" — wasteful (empty-checks), DELAYED (poll-interval jitna wait), rate-limited. Webhook = source KHUD event-pe POST bhejta hai — instant (seconds), efficient (sirf actual-events), simple (no-polling-loop). Trading alerts TIME-SENSITIVE hain — seconds matter — isliye webhook natural-fit. Cost: tera server REACHABLE hona chahiye (ngrok/deployment).

</details>

3. Flask route decorator + methods=["POST"] kya karte hain?

<details>
<summary>Sample Jawab</summary>

**Jawab:** @app.route("/webhook") URL-path ko Python-function se BIND karta hai — us address pe request aaye toh woh function chalega. methods=["POST"] batata hai kaunsa HTTP-method accept karna hai: POST = incoming-DATA expected (alert-payload). Default GET-only hota hai — POST aayegi toh 405-error! Explicit = safe. request.get_json() phir body-ko-dict banata hai.

</details>

4. Free-ngrok ka URL-restart problem? Production fix?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Free-tier har restart pe RANDOM subdomain deta hai (abc123.ngrok.app → xyz789...) — purana URL DEAD! TradingView-webhook-settings me stored purana URL ab GALAT hai → alerts SILENTLY FAIL! Har restart pe manual-update = fragile system. Fixes: paid static-domain, YA production-platform jahan stable-URL milta hai (M8: Render ka *.onrender.com permanent rehta hai!).

</details>

5. Webhook endpoint pe minimum 2 security measures?

<details>
<summary>Sample Jawab</summary>

**Jawab:** (1) SECRET-PATH/TOKEN — URL me random unguessable segment ya header-token check; unauthorized pe 401 (warna KOI BHI tera URL dhundh ke fake-BUY/SELL trigger kar sakta hai!!). (2) IDEMPOTENCY/DEDUP-GUARD — same-candle ke multiple-alerts pe duplicate-orders block (open-position check ya last-signal-timestamp compare). Bonus: testing ke baad endpoint band karna + logs monitor karna!

</details>
