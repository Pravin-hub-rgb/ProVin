## Indicator vs Strategy — Two Tabs!

Library has TWO types of scripts:

| | **Indicator** | **Strategy** |
|---|---|---|
| Work | Shows signals/alerts | SIMULATES backtest |
| Buy/Sell simulate? | ❌ No | ✅ signal → simulated buy! |
| Use | Visuals, alerts | Results, metrics |

Remember this difference —

we'll start with indicators, `strategy()` version for backtests (used in 8.2)!

## First Script — Hello World!

Pine Editor → Create new → Indicator. Now write:

```pinescript
//@version=6
indicator("My First Indicator")
plot(close)
```

Save → Run ▶️ → ONE LINE appeared on chart (close's line)!

**Congratulations — you're now Pine-coder!** 🎉

### Line-by-Line:

```text
//@version=6              → "this script is version 6"
indicator("My First...")  → making indicator, gave name
plot(close)               → PLOT close-price as line
```

⚠️ **NEVER delete `//@version=6` line!**

It tells which version script is —
remove and compiler CONFUSED!

## Built-in Variables — FREE DATA!

These five variables come ALREADY declared,

fresh data filled per candle:

```text

```

No need to do Python-style `df["close"][i]` —

(This is Pine's most convenient thing!)

⚠️ Don't REUSE these names — they're reserved!

## Variables & Types — Python's Cousin!

Assignment like Python:

```pinescript
a = 10        // int (whole number)
b = 10.0      // float (decimal)
c = true      // bool (True/False)
d = "hello"   // string (quotes!)
```

| Type | Example |
|---|---|
| int | `10` |
| float | `10.0` |
| bool | `true` / `false` |
| string | `"hello"` |
| color | `color.red` |

⚠️ Only NUMBERS plot in plot — not string!

**Named arguments** like Python too:

```pinescript
plot(close, title="My Line", color=color.red)
```

Naming-rules same: case-sensitive (`Data` ≠ `data`),

can't start with number ❌, underscore ✅, space ❌.

Your Python-knowledge DIRECTLY transfers!

## Overlay — On Chart or Below?

```pinescript
indicator("My Indicator", overlay=true)
```

| Setting | Result |
|---|---|
| `overlay=false` (default) | Plot in SEPARATE pane below |
| `overlay=true` | Plot ON PRICE-CHART! |

⚠️ Volume + overlay=true → scale-mismatch error

(volume in crores, price in hundreds!)

Fix: add `force_overlay=true` on that plot separately.

## Inputs — Make User Settings!

How do real indicators' SETTINGS-PANEL get made?

With `input.*` functions!

```pinescript
length = input.int(14, title="RSI Length", group="RSI Settings")
mult   = input.float(1.5, title="Multiplier", group="RSI Settings")
mode   = input.string("Buy", title="Mode",
                      options=["Buy", "Sell", "No Sell"])
useIt  = input.bool(true, title="Enable Filter")
```

Understand:

```text
input.int(14, ...)   → makes number-box, DEFAULT 14
title=...            → this name shows in settings-panel
group=...            → same-group inputs organized in ONE section
options=[...]        → DROPDOWN menu!
```

Input-types menu:

| Type | What UI Becomes |
|---|---|
| `input.int` | Number-box |
| `input.float` | Decimal-box |
| `input.string(options=)` | **DROPDOWN!** |
| `input.bool` | Checkbox ☑️ |

These inputs make strategy FLEXIBLE —
user changes settings, no code edit needed!

## Operators — All Like Python!

| Category | Operators | Note |
|---|---|---|
| Arithmetic | `+ − * / %` | Modulus too! |
| Comparison | `== != > < >= <=` | Result **boolean** |
| Ternary | `condition ? this : that` | if-else one-liner! |
| Compound | `+=`, `-=` | Useful in loops |

**Ternary** only new in SYNTAX:

```pinescript
label = a > b ? "UP" : "DOWN"
```

Read: *"if a>b THEN 'UP', else 'DOWN'"*

## ta.* Namespace — Ready-Made Indicators!

Most important namespace: **`ta.*`** —
all technical-analysis built-ins:

```pinescript
myEma = ta.ema(close, 9)     // same EMA we made in pandas!
myRsi = ta.rsi(close, 14)
```

Loops exist in Pine but **not needed now** —
Pine runs on EVERY candle itself
(think engine is already giant-loop!).

Conditionals (`if/else`) like Python.

## What It Is NOT

- ❌ **Pine ≠ general programming language.** Specialized for trading-charts — can't write files, can't open databases. Job: compute + draw + alert on charts. Heavy-lifting (orders/servers) Python's!
- ❌ **Indicator script ≠ tradable system.** Indicators only SHOW; don't send orders, don't track positions. Strategy() + alert() combo takes to automation.
- ❌ **LuxAlgo copy-paste ≠ understanding.** Pasting others' code safe only when you can READ it. Otherwise live-market-debugging impossible!

**In Your Own Words**

1. Difference between Indicator and Strategy script? When which in automation?

<details>
<summary>Sample Answer</summary>

**Answer:** Indicator only COMPUTES+DRAWS — shows signals visually, can give alerts, but doesn't SIMULATE trades. Strategy() executes simulated buy/sell on signals — hence Strategy-Tester gives metrics (win-rate, profit-curve). Flow: first VERIFY logic with indicator → then strategy() version for BACKTEST → automation uses indicator+alert for LIVE-signals.

</details>

2. What does `{}` curly-bracket click give?

<details>
<summary>Sample Answer</summary>

**Answer:** That indicator's SOURCE-CODE (if public)! Useful: (1) mystery-gone — EMA/VWAP/MACD all PURE-MATH you already understand (4.2!), (2) real-world patterns to learn — inputs organize, plot-styling, (3) debug-reference for your scripts. Exception: protected-scripts (Neural-Momentum type) locked by creator!

</details>

3. Why is `//@version=6` line critical?

<details>
<summary>Sample Answer</summary>

**Answer:** Tells compiler which Pine-version's syntax script uses. Versions have BREAKING-changes (v4→v5→v6 functions/behavior changed). Delete/wrong-version = compiler applies WRONG rules → errors or silently-wrong-behavior! Copy-pasting old scripts (written v4/v5) version-mismatch is common-error.

</details>

4. What do input.* functions enable in real-indicators? Dropdown example?

<details>
<summary>Sample Answer</summary>

**Answer:** User-configurable SETTINGS — tune behavior without code-edit! Each input becomes settings-panel widget: int→number-box, float→decimal, bool→checkbox, string+options→DROPDOWN. Example: mode = input.string("Buy", options=["Buy","Sell","No Sell"]) — user gets 3-option menu, script gets selected-string in variable `mode`. Group parameter organizes inputs into sections.

</details>

5. Pine vs Python — division-of-labor in projects?

<details>
<summary>Sample Answer</summary>

**Answer:** PINE = signal-layer — runs logic on chart (detects crossovers), gives visuals, fires ALERTS (with webhook-payload). PYTHON = execution-layer — receives webhook (7.2 Flask), parses, sends orders to broker-API (7.1!). Both connect via webhooks. Why divide: Pine near chart/data-feed (best signal-detection); Python near systems/orders/servers (best execution). This combo built in upcoming files!

</details>
