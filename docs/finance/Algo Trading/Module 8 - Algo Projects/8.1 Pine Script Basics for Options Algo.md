## Setup — 5 Minute Mein Pehla Editor

Agar TradingView account nahi hai:

2. Koi chart kholo (Bitcoin/Reliance kuch bhi)
3. Neeche **Pine Editor** tab pe click — yahin code likhenge

## Sabse Pehla Jhatka — Har Indicator Ka Code Chhupa Hai

TradingView pe koi bhi indicator lagao (maan lo EMA) → uski settings kholo → wahan ek **`{}` (curly bracket)** icon hota hai → click karo.

**EMA ka poora source code khul jaayega!**

Aur yahi course ka pehla aha-moment hai:

> *EMA ho, VWAP ho, MACD ho — trading world ka HAR indicator Pine Script pe bana hai. Sab pure math hai.*

4.2 mein jo math seekha tha (α = 2/(N+1)...) wohi yahan code mein pada dikhega. LuxAlgo jaise famous publishers ke indicators bhi kholke dekh sakte ho — bahut bada code milega, par structure samajh aane lagega.

⚠️ Exception: kuch strategies (**Neural Momentum** type) ka code **protected** hota hai — creator ne permission nahi di, woh unka asset hai. Curly bracket unpe kaam nahi karega.

💡 Pro tip jo poore module ki philosophy hai: **blind copy mat karo.** Syntax samajh lene do — phir code teri power hai, warna bas paste.

## Indicator vs Strategy — Do Tabs

Library mein do type ke scripts hote hain:

| | **Indicator** | **Strategy** |
|---|---|---|
| Kaam | Signals/alerts dikhata hai | **Backtest simulate** karta hai |
| Buy/Sell simulate? | ❌ | ✅ buy signal → simulated buy, sell signal → simulated sell |
| Use | Visuals, alerts | Results, metrics |

Yeh farq yaad rakhna — hum indicators se start karenge, backtests ke liye strategy() version banega (8.2 mein practical use hoga).

## Pehli Script — Hello World

Pine Editor → Create new → Indicator. Template milega. Apna pehla script:

```pinescript
//@version=6
indicator("My First Indicator")
plot(close)
```

Save → Run ▶️ → chart pe ek line aa gayi (close price ki line). Congratulations — tu ab coder-of-Pine hai.

⚠️ **`//@version=6` line kabhi delete mat karna** — yeh batata hai script kaunse version ki hai. Delete/hataya toh compiler confuse.

`plot(close)` kya kar raha hai? Current candle ki closing value ko line se plot kar raha hai. Yeh EMA nahi — bas raw close. Chart ke upar chahiye (alag pane mein neeche nahi)? `force_overlay=true` add karo plot mein.

## Built-in Variables — OHLCV Ready-Made

Yeh paanch variables already declared aate hain, current candle ka data bhara rehta hai:

```text
open, high, low, close, volume
```

Har nayi candle aate hi inme fresh values aa jaati hain — tujhe fetch nahi karna padta (Python wala df["close"][i] yahan automatic hai!). ⚠️ In naamko reuse mat karo — reserved hain.

Multiple plots ek saath? `plot(close)` + `plot(high)` — dono lines aa jayengi.

## Variables & Data Types — Python Ka Cousin

Assignment Python jaisa hi:

```pinescript
a = 10        // int
b = 10.0      // float
c = true      // bool
d = "hello"   // string (quotes zaroori)
```

| Type | Example |
|---|---|
| int | `10` |
| float | `10.0` |
| bool | `true` / `false` |
| string | `"hello"` |
| color | `color.red`, `color.blue` |

⚠️ Plot mein sirf numbers plot hote hain — string plot nahi hota.

**Named arguments** (Python wale hi): jab argument ka order skip karna ho toh naam dena padta hai:

```pinescript
plot(close, title="My Line", color=color.red)
```

Naming rules bhi Python-identifiers wale hi: case-sensitive (`Data` ≠ `data`), number se start ❌, underscore ✅, space ❌. Matlab tera 3.x ka knowledge directly transfer ho raha hai!

## Overlay — Chart Ke Upar Ya Neeche?

```pinescript
indicator("My Indicator", overlay=true)
```

| Setting | Result |
|---|---|
| `overlay=false` (default) | Plot neeche **alag pane** mein |
| `overlay=true` | Plot **price chart ke upar** |

⚠️ Volume + overlay=true karne pe scale mismatch se error aa sakta hai (volume crores mein, price hundreds) — us plot pe alag se `force_overlay=true` lagao.

## Inputs — User-Configurable Settings

Real indicators ki settings panel kaise banti hai? `input.*` functions se:

```pinescript
length = input.int(14, title="RSI Length", group="RSI Settings")
mult   = input.float(1.5, title="Multiplier", group="RSI Settings")
mode   = input.string("Buy", title="Mode", options=["Buy", "Sell", "No Sell"])
useIt  = input.bool(true, title="Enable Filter")
```

Parameters:

- Pehla value = **default** (settings khole toh pehle se bhari dikhegi)
- `title=` = settings panel mein naam
- `group=` = same group wale inputs ek section mein organize

Input types ka menu:

| Type | UI Kya Banta Hai |
|---|---|
| `input.int` | Number box |
| `input.float` | Decimal box |
| `input.string(options=[...])` | **Dropdown!** |
| `input.bool` | Checkbox |
| `input.source` | Data-source selector |

Yehi inputs baad mein strategy ko flexible banayenge — "EMA length user change kar sake" bina code edit kiye.

## Operators — Sab Python Jaisa

| Category | Operators | Note |
|---|---|---|
| Arithmetic | `+ − * / %` | Modulus bhi hai |
| Comparison | `== != > < >= <=` | Result **boolean** |
| Ternary | `condition ? this : that` | if-else ka one-liner |
| Compound | `+=`, `-=` | Loops mein kaam aayega |

Ternary naya hai sirf syntax mein:

```pinescript
label = a > b ? "UP" : "DOWN"    // agar a>b then "UP" else "DOWN"
```

## Functions, ta.* Namespace, Aur Aage

Functions: `plot()` ek function hai. Sabse important namespace: **`ta.*`** — technical analysis ke saare built-ins:

```pinescript
myEma = ta.ema(close, 9)       // wohi EMA jo humne pandas mein banayi!
myRsi = ta.rsi(close, 14)
```

Loops Pine mein hote hain par **abhi seekhne ki zaroorat nahi** — indicator-level kaam loop-free hota hai (Pine har candle pe khud chalta hai — samajh lo engine already ek giant loop hai!). Conditionals (`if/else`) Python jaisi hi.

AI tip production-grade hai: **Pine ke liye DeepSeek/Grok better hai** — ChatGPT v5 tak ki knowledge solid rakhta hai, naye v6 syntax pe confuse ho sakta hai. (Python ke liye ChatGPT theek hai.)

## Nutshell

Pine Script = TradingView ki language; har indicator isi pe built hai ({ } se source dekho; protected scripts exception). Indicator = signals, Strategy = simulated backtest. First script: `//@version=6` + `indicator()` + `plot()` — version line sacred hai. OHLCV built-ins free data dete hain per candle. Syntax overall Python-jaisa (types, naming, operators, ternary extra). Inputs se settings panels banti hain (int/float/bool/dropdown). `ta.*` namespace = ready-made indicators. Ab agle file mein yeh sab ek REAL strategy pe lagayenge — AI ke saath.

## What It Is NOT

- ❌ **Pine ≠ general programming language.** Woh trading-charts ke liye specialized hai — files nahi likh sakta, databases nahi kholta, arbitrary apps nahi banata. Uska job: chart pe compute + draw + alert. Heavy lifting (orders, servers) Python ki.
- ❌ **Indicator script = tradable system nahi.** Indicators sirf dikhate hain; orders nahi bhejte, positions track nahi karte. Strategy() + alert() combo hi automation tak le jaata hai (agli files).
- ❌ **Copy-paste from LuxAlgo = understanding nahi.** Protected ya open, doosre ka code paste karna tabhi safe hai jab tu padh sake. Warna tune nahi pata hoga ki tera signal asal mein kya kar raha hai — aur debug live market mein hot death hai.

3. `//@version=6` line kyun critical hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Yeh compiler ko batati hai script kis Pine version ki syntax use karti hai. Versions mein breaking changes hote hain (v4→v5→v6 functions/behaviors badle). Line delete/galat version = compiler galat rules apply karega → errors ya silently wrong behavior. Copy-paste purane scripts (jo v4/v5 mein likhe) karte waqt bhi version mismatch hi common error hai.

</details>

4. `input.*` functions real indicators mein kya enable karte hain? Ek dropdown example?

<details>
<summary>Sample Jawab</summary>

**Jawab:** User-configurable settings — code edit kiye bina behavior tune ho jaata hai. Har input settings-panel widget banta hai: int→number box, float→decimal, bool→checkbox, string+options→dropdown. Dropdown example: mode = input.string("Buy", options=["Buy","Sell","No Sell"]) — user ko 3-option menu milta hai, script variable `mode` mein selected string milti hai. Group parameter inputs ko sections mein organize karta hai.

</details>

5. Pine aur Python ka division of labor projects mein kya hoga?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Pine = signal layer — chart pe logic chalata hai (crossovers detect), visuals deta hai, alerts fire karta hai (webhook payload ke saath). Python = execution layer — webhook receive karta hai (7.2 Flask), parse karta hai, broker API pe orders bhejta hai (7.1). Dono webhooks se judte hain. Kyun divide: Pine charts/data-feed ke paas hai (best signal detection), Python systems/orders/servers ke paas (best execution). Agli files mein yehi combo build hoga.

</details>
