## Code Walkthrough — Reversal's Core!

```python
action = request.form.get("action").lower()     # "BUY" came → "buy"
real_action = "sell" if action == "buy" else "buy"   # ← FLIP!!
```

See how SIMPLE the reversal is:

```text
User sent "buy"   → real_action = "SELL"
User sent "sell"  → real_action = "BUY"

ONLY ONE VARIABLE flipped — rest (symbol, qty) untouched!
```

And the order-request dict (that AI gave):

```python
request_order = {
    "action":  mt5.TRADE_ACTION_DEAL,
    "symbol":  symbol,           # e.g., "BTCUSD"
    "volume":  float(lot),       # lot size
    "type":    mt5.ORDER_TYPE_BUY if real_action == "buy"
               else mt5.ORDER_TYPE_SELL,
    "price":   current_price     ← live price needed!
}
```

## ⚠️ Step the Original Material SKIPPED — We ADD!

After the dict, you must SEND it too!

The original notes elided this decisive step —

we add:

```python
# Get LIVE PRICE (where does "price" in dict come from?):
tick = mt5.symbol_info_tick(symbol)
request_order["price"] = tick.ask if real_action == "buy" else tick.bid

# SEND ORDER:
result = mt5.order_send(request_order)

# RETCODE CHECK — placement ≠ success (7.1's lesson!):
if result.retcode != mt5.TRADE_RETCODE_DONE:
    print(f"ORDER FAILED: retcode={result.retcode}")
else:
    print(f"Order FILLED @ {result.price}")
```

```text
symbol_info_tick()   → gets live buy/sell price
order_send()         → ACTUALLY sends order!
retcode              → result's STATUS code
TRADE_RETCODE_DONE   → "successfully filled!" code
```

**Without the retcode check you won't know**

whether the order happened or SILENTLY failed — remember 7.1's placement ≠ fill?!

## MT5 Practical Gotchas

MT5 is desktop-IPC (not cloud-API!) — its quirks:

```text
1. ALGO-TRADING must be ENABLED!
   MT5 toolbar button + Tools → Options → Expert-Advisors
   If off → order_send SILENTLY FAILS!!

2. TERMINAL LOGIN required
   Broker account (demo) logged in in MT5 app!

3. SYMBOL NAMING
   Brokers add suffixes: BTCUSD.a, BTCUSD.raw...
   Check EXACT symbol (from symbol list!)

4. FILLING MODES
   Some brokers want FOK/IOC;
   wrong mode = REJECTION (retcode tells!)

5. TWO-PROCESS REALITY:
   MT5 closed = everything DEAD! App must keep running!!
```

## Now The TWIST — Will This Strategy Really Work?

Pause and think with **4.6 goggles:**

Friend's 10-of-7-trades loss.

But how BIG are the losses? If:

```text
7 losers  × −₹1,000 = −₹7,000
3 winners × +₹5,000 = +₹15,000

NET PROFIT = ₹8,000!! 😱
```

Meaning that trader **could be PROFITABLE despite 70% losing trades!**

(asymmetry — avg WIN big, avg LOSS small!)

Reversing would be a DISASTER!

Reverse logic is valid ONLY when:

```text
Losses BIG and frequent + wins SMALL and rare
(asymmetric OPPOSITE direction!)
```

Lesson:

> **Can BUILD ≠ should BUILD!**
>
> A coder's advantage is this — can TEST the hypothesis!
> Backtest the reverse version! Not orders on assumptions!

## What It Is NOT

- ❌ **Frontend/backend split ≠ two separate apps.** Same system's two LAYERS — HTML form POSTs to backend's routes; backend responds. Flask JOINS both (serving templates)!
- ❌ **mt5.initialize() ≠ connection GUARANTEE.** It's only an ATTACH attempt — terminal running, account logged in, algo trading enabled, THEN orders go! Check status of every step (mt5.last_error()).
- ❌ **70% losing trades ≠ losing trader.** Win rate without PAYOFF RATIO is meaningless (4.6!!). Reverse strategy demand came from this MISUNDERSTANDING — client never looked at MAGNITUDE!
