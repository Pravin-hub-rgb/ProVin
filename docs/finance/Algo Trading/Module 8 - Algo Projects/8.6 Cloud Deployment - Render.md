# 8.6 Cloud Deployment: Render

## Cloud Kyun Zaroori Hai

Problem simple hai:

```text
Local automation:
    Laptop ON + terminal open + ngrok running = bot alive
    Laptop closed / slept / internet gone    = bot DEAD ❌
```

| Market | Timing | Local Setup Ka Status |
|---|---|---|
| Indian market | 9:15–3:30 | Chal jaata hai (din mein laptop on rakh lo) |
| Crypto/Forex | **24x7** | Impossible — sote kaise ho? |

**Cloud = company ke servers** jo hamesha chalte rehte hain. Tera code wahan rehta hai, wahan se execute hota hai. Conceptually: tu computer **rent** pe leta hai (512MB RAM, kuch storage) aur **pay-per-use** hota hai — professional setups mein clients ₹2–3k/month tak dete hain. Par humein free chahiye, toh...

## Solution: Render

AWS, Google Cloud, VPS, Oracle — sab heavy setups hain. Hum use karenge **Render**: free tier account banao, **credit card bhi nahi lagta**, app deploy karo.

Requirements sirf 2 accounts:

```text
1. GitHub account     ← code ka ghar (7.3 mein setup kiya!)
2. Render account     ← render.com, free signup
```

(GitHub = "Instagram for coders" — repo = folder jismein teri files post hoti hain.)

## Step 0 — Pehle Security Fix! ⚠️

⚠️ Ruk. Seedha upload NAHI karenge. **Tera abhi ka code project-ready nahi hai** — agar keys code mein hardcoded hain (`API_KEY = "abc123..."`) toh GitHub pe upload karte hi PUBLIC ho gayi. Bots seconds mein scan kar lete hain (7.3 ki horror story yaad?).

Pehle 7.3 wala env-var pattern apply karo:

```python
# ❌ PEHLE (hardcoded):
API_KEY = "abc123secret..."

# ✅ AB (reference only):
import os
api_key = os.getenv("DELTA_KEY")
```

Keys Notepad/local `.env` mein safe rakho — asli values Render dashboard pe jayengi, GitHub pe KABHI nahi.

## Teen Fixes — Cloud-Ready Code

### Fix 1 — requirements.txt

Server tere laptop pe nahi — use batana padega kaunsi libraries chahiye. Yeh file **shopping list** hai jo Render build-time pe automatically install karta hai:

```text
# requirements.txt
flask
delta-rest-client
requests
```

⚠️ **Typo alert:** original notes mein is list mein `tracker-rest-client` likha tha (galat naam!) aur `uvicorn` bhi tha bina explanation ke. Do lessons: (1) library names EXACT hone chahiye — ek spelling galat = build fail; (2) `uvicorn` ek ASGI server hai FastAPI-type apps ke liye — plain Flask app ke liye zaroori nahi, blind copy mat karo.

Aur best practice 7.3 se: hand-write mat karo —

```bash
pip freeze > requirements.txt
```

### Fix 2 — Environment Variables (upar ho gaya!)

Local pe `.env` file thi; cloud pe values **Render dashboard** mein jaayengi (agli section). Code same rahega — `os.getenv()` dono jagah kaam karta hai. Yehi beauty hai 7.3 wale design ki.

### Fix 3 — Procfile (Optional)

Procfile = "kaise start karna hai" batane wali file. Render pe optional hai kyunki dashboard mein hi start command field hota hai. Skip kar sakte ho.

## GitHub Upload

```text
1. github.com → New repository (e.g., "delta-bot")
2. "uploading an existing file" → files DRAG-DROP:
   server.py + requirements.txt (+ updated login/orders)
3. Commit changes
4. ✅ VERIFY: code kholo — keys NAHI dikhni chahiye,
   sirf os.getenv("DELTA_KEY") reference dikhna chahiye
```

Woh verify step skip mat karna — 10 second lagta hai, account bachata hai.

## Render Deploy — Step by Step

```text
1. render.com → New → Web Service
2. GitHub connect karo → apna repo select karo
3. Settings bharo:
   | Setting       | Value                              |
   |---------------|------------------------------------|
   | Name          | delta-bot                          |
   | Language      | Python 3                           |
   | Build command | pip install -r requirements.txt    |
   | Instance      | Free (512 MB)                      |
4. Environment section → Add:
   Name: DELTA_KEY    Value: <asli key>    Type: Secret 🔒
5. Deploy button!
6. Logs dekho: "Build successful..." → "Deployment live"
```

🎉 **URL mil gaya:** `https://delta-bot.onrender.com`

Yehi tera cloud bot hai — ab 24x7 zinda.

## TradingView Update + IP Whitelist Fix

Do wiring changes:

**1. Webhook URL swap:** TradingView alert settings mein purana ngrok URL hatao, Render URL daalo. Ngrok ab kabhi nahi chahiye — local setup retire.

**2. IP Whitelist update (important!):** Delta API settings mein tune APNE computer ka IP daala tha (8.3). Ab orders **Render ke server se** jaa rahe hain — alag IP! Error aayega jab tak Delta settings mein **server ka IP** add nahi karte. Fix ke baad: *"IP updated — ab error nahi aayega."*

## Testing & Pro Tips

- ⚠️ **Free tier cold start ~50 seconds:** Render free instances idle hone pe spin down hote hain — agla request aane pe wapas start hota hai (isi liye delay). Expect perfection nahi; paid tier instant hota hai.
- 🏆 **Overnight test:** bot ko 5-min TF pe **raat bhar chhod do** — laptop band karo, tension-free. Render chalega.
- 💰 Golden line jiske saath original session khatam hota hai: ***"Paisa long timeframe pe banta hai — 1 second mein nahi."*** HFT nahi ban rahe hum; patience + automation = combo.
- Ek gap jo main add karta hun: **monitoring.** 24x7 bot ko andha na chalao — Render logs check karna daily habit banao, aur broker app mein positions/notifications on rakho. Silent failures sabse mehngi hoti hain.

## Nutshell

Deployment = course arc ka last phase. Cloud kyun: 24x7 markets + laptop dependency khatam. Render: free, no credit card, GitHub-connected. Sequence: security fix PEHLE (env vars) → prompt with current-scenario rule → 3 fixes (requirements.txt via pip freeze — typos fatal!, env vars, Procfile optional) → GitHub upload + keys-verify → Render settings (build command, free instance, secret env vars) → deploy → logs → URL. ## What It Is NOT

- ❌ **Free deployment = zero-cost trading nahi.** Compute free hai par slippage/brokerage/data costs waise hi hain. Aur free tier limits (RAM, cold starts, bandwidth) production-grade strategies ke liye paid tier maang sakti hain.
- ❌ **Deployed bot = self-managing system nahi.** Token expiry, API changes, regime shifts, silent bugs — sab abhi bhi tere monitoring ka hissa hai. Deployment ek milestone hai, maintenance life-long hai.
- ❌ **onrender.com URL = permanent guarantee nahi.** Platform terms change hote hain, free tiers restrict hote hain, services shut down bhi hoti hain (Heroku ka free tier band ho chuka hai!). Backup plan + exportable code (git!) ready rakho.

<details>
<summary>Sample Jawab</summary>

3. IP whitelist error deployment ke baad kyun aata hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Broker security model: "sirf in IPs se requests accept karunga." Tune 8.3 mein apne computer ka public IP whitelist kiya tha — tab orders laptop se jate the. Ab Render ke server se jaate hain jo ka ALAG IP hai → broker reject (unknown source). Fix: Render ke egress IP nikalo (docs/logs se) aur broker dashboard whitelist mein add karo. Lesson: infrastructure badla = auth surfaces bhi badle — systematically review karo.

</details>

4. Free-tier cold start kya hai? Trading pe impact?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Render free instances idle pe spin-down hote hain (resources save karne ke liye). Neeche request aaye toh container wapas start hota hai — ~50 sec. Impact: agar signal aaya aur bot so raha tha, order 50s late lagega — fast markets mein price move ho chuka hoga (slippage/missed entry). Mitigation: paid always-on tier; ya keep-alive pings (workaround); ya high-frequency strategies avoid karo — 5-min+ TF pe 50s occasionally acceptable hai.

</details>
