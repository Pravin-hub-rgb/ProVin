|---|---|

| **Entry** | 9 EMA crosses ABOVE 21 → BUY 🟢 |
| **Exit** | 9 EMA crosses BELOW 21 → SELL 🔴 |
| **Short-selling** | ❌ No — only buy side |

Rules in one line:

```text
BUY when 9 EMA crosses ABOVE 21 EMA
SELL when 9 EMA crosses BELOW 21 EMA
```

Two things notice:

```text
1. NO target, NO stop-loss — deliberately!
   (this is learning-strategy; SL/target come in Module 5)

2. Five things MANDATORY to define strategy:
   indicator + timeframe + instrument + entry + exit
   Any one missing = strategy INCOMPLETE = test impossible!
```

## ⚠️ One Necessary Correction — EMA Mistake

Original cohort notes had:

> *"EMA = average of last N candles' close"* ← WRONG!

And example: `(18+17+16+18+17) ÷ 5 = 17.2`

**This is actually SMA!** True EMA is recursive (remember 4.2):

```text
SMA = all equal                    ← that example above
EMA = α×Close + (1−α)×EMA_yesterday        ← REAL EMA
```

Why matters?

Manual-average signals and library-EMA signals

will come on DIFFERENT days → different trades → different results → CONFUSION!

So throughout course we'll use TRUE EMA only

(`talib.EMA` or `ewm(adjust=False)`).

## NaN Values — Empty Boxes at Start

When indicators calculated, NaN comes at start:

```text
NaN = "Not a Number" = EMPTY box
```

| Indicator | How many rows NaN |
|---|---|
| 9 EMA | ~first 9 rows |
| 21 EMA | ~first 21 rows |
| 200 EMA | ~first 200 rows |

**Why?** 21-EMA needs 21 candles history —

row 1 has NO history! 😅

Fix simple:

```python
df = df.dropna().reset_index(drop=True)
```

```text
dropna()                → remove NaN rows
reset_index(drop=True)  → renumber 0,1,2...
```

No data loss — only rows where indicator didn't EXIST anyway.

## Full Setup Script — All Combined

Now one complete script that makes backtest-ready data:

```python
import pandas as pd
import talib

# STEP 1: Load data
df = pd.read_csv("reliance_5min.csv")
df.columns = [c.lower() for c in df.columns]

# STEP 2: Make indicators
df["ema_9"] = talib.EMA(df["close"], timeperiod=9)
df["ema_21"] = talib.EMA(df["close"], timeperiod=21)

# STEP 3: Clean warm-up rows
df = df.dropna().reset_index(drop=True)

print(df[["close", "ema_9", "ema_21"]].head())
print(f"Candles ready: {len(df)}")
```

Output:

```text

0  2456.3  2455.1  2452.8
1  2458.0  2456.1  2453.9
...
Candles ready: 1471
```

Data clean. Indicators ready. Now just check RULES on each candle!

## Iteration — Backtest's Engine

Backtest core = one loop going to EACH candle:

```python
for i in range(len(df)):
    fast_now = df["ema_9"][i]      # this candle's fast EMA
    slow_now = df["ema_21"][i]     # this candle's slow EMA
    close_now = df["close"][i]     # this candle's close
    # ...conditions checked here (next file!)
```

Each round `i` jumps to next candle:

```text
i = 0 → first candle
i = 1 → second candle
...
i = 1470 → last candle
```

### Why Loop Necessary? Pandas Exists Right?

Good question! Filtering exists in pandas...

But backtest has ORDER that matters:

```text
First BUY happened → then EXIT → then SECOND buy → ...
```

This sequence must be tracked — which trade started when, ended when.

That's sequential story, so loop is natural fit.

(Loop types recap: `range(len(df))` is used —

`for x in list` gives values, not positions!)

4. Why loop in backtesting when pandas filtering available?

<details>
<summary>Sample Answer</summary>

**Answer:** Because backtest = SEQUENTIAL STORY: first trade opened, then closed, then next opened... each step depends on previous (position open or not?). This is state-machine — loop naturally maintains sequence and variables (entry flag, buy_price) update candle-by-candle. Filtering is good for independent rows; loop for order-dependent logic.

</details>

<details>

**Answer:** Risk is UNDEFINED! Exit only on opposite-crossover — choppy market causes constant whipsaws, strong move against theoretically unlimited loss (stock can go to zero in long!). Without target, profits don't systematically book. This is only crossover-mechanics learning vehicle; real trading needs SL/target/position-sizing (Module 5) MANDATORY layer.

</details>
