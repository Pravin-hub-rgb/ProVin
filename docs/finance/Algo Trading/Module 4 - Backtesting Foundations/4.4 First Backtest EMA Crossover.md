## EMA Ka Math — Ek Zaroori Correction

⚠️ **Dhyan do — yahan source material mein classic galti hoti hai jise hum fix kar rahe hain.**

Kai jagah (including original cohort notes) EMA ko aise explain kiya gaya tha:

> *"EMA = Last N candles ke closing price ka average"*

Aur example diya gaya: closes `[18, 17, 16, 18, 17]` → `(18+17+16+18+17) ÷ 5 = 17.2`.

**Yeh actually SMA hai, EMA nahi!** Humne 4.2 mein detail se dekha tha:

```text
SMA  = (18+17+16+18+17) ÷ 5              ← equal weights
EMA  = α × Close + (1−α) × EMA_prev      ← recursive, recent-heavy
jahan α = 2/(N+1)
```

Farq practical kyun matter karta hai? Kyunki agar tu manual "average" method se signals nikalega aur library (`talib.EMA`) se compare karega, toh **numbers match nahi karenge** — cross alag din pe aayenge, trades alag honge, results alag. Aur agar tera backtest manual-SMA pe chala aur live trading TA-Lib-EMA pe — disaster ready hai.

Toh is module mein jab bhi "EMA" likha hai, woh **true recursive EMA** hi hai — jo 4.3 mein `ewm(span=9, adjust=False)` ya `talib.EMA` se banate hain.

Ek aur convention fix karte hain jo agli file mein important hai: columns ke naam **`ema_9` aur `ema_21`** use karenge (fast/slow order clear rehta hai).

## NaN Values — Starting Ke Rows

Jab TA-Lib/pandas se EMA calculate karte ho, starting rows mein `NaN` (Not a Number) aata hai:

| Indicator | Shuruat Mein NaN Rows |
|---|---|
| 9 EMA | ~First 9 rows |
| 21 EMA | ~First 21 rows |
| 200 EMA | ~First 200 rows |

Reason obvious hai — 21 EMA ko 21 candles chahiye history; row 1 pe history hi nahi hai. Jitni badi period, utne zyada warm-up rows.

Handle kaise karein:

```python
df = df.dropna().reset_index(drop=True)
```

- `dropna()` — NaN wali rows hatao
- `reset_index(drop=True)` — index 0 se phir se number karo (warna gaps reh jayenge)

⚠️ Ek subtle point: dono EMAs ke liye dropna karte waqt **sabse lambi period** (21) hi effective boundary banegi — kyunki wahan tak dono columns mein value hai hi nahi.

## Iteration Pattern — Backtest Ka Engine

Backtesting ka core ek loop hai jo **har candle pe jaata hai aur condition check karta hai**:

```python
for i in range(len(df)):
    fast_now = df["ema_9"][i]
    slow_now = df["ema_21"][i]
    close_now = df["close"][i]
    # ... conditions check karo
```

Loop types ka quick recap (3.2 yaad kar):

| Loop Type | Deta Hai | Backtesting? |
|---|---|---|
| `for i in range(len(df))` | Har row ka index | ✅ Haan — yehi use hota hai |
| `for x in list` | List ki values directly | ❌ Index-based access nahi milta |
| `for col in df` | Column names | ❌ Galat direction |

Row access ke liye `df.iloc[i]` bhi kaam karta hai — poori row dict-jaisi milti hai. Aur ek baat jo 3.7 mein seekhi thi ab samajh aayegi: `iloc` mein **stop excluded** hota hai, isliye ranges slice karte waqt dhyan.

Life trading mein loops kam aate hain (pandas vectorized kaam karti hai), par **backtesting mein loop hi sab kuch hai** — kyunki trade sequence matters: pehle buy hua, phir exit hua, phir doosra buy... state machine hai, aur state machine ke liye sequential loop natural hai. Poora state machine (entry flag, buy_price tracking, PnL calculation) agli file ka topic hai.
