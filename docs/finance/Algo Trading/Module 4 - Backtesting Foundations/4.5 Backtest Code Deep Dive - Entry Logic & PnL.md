# 4.5 Backtest Code Deep Dive: Entry Logic & PnL

## Pehle Trial vs Full Backtest Samjho

Abhi tak jo kiya woh **simple trial** tha. Ab full backtesting ki taraf badh rahe hain:

| Simple Trial | Full Backtesting |
|---|---|
| Kuch candles dekh ke haath se calculate | 1500+ candles programmatically loop |
| Manual entry/exit decisions | Automated conditions |
| Sirf 1–2 trades | Multiple trades + statistics |

Is file ka focus: loop logic + entry flag + crossover conditions + PnL. Yeh chhota sa trial-code hai — poori framework (metrics, reports) agli files mein.

## Entry Flag — Dobara Entry Rokna

Problem samajh pehle: agar 9 EMA kai candles tak 21 EMA se upar rehti hai (strong trend), toh simple condition `fast > slow → BUY` **har candle pe naya entry** le legi! 100 positions open ho jayengi.

Solution: boolean flag.

```python
entry = False   # default: abhi koi position nahi

for i in range(len(df)):
    if fast_now > slow_now and not entry:
        # Buy entry le lo
        entry = True
        buy_price = df["close"][i]
```

| Variable Value | Matlab |
|---|---|
| `entry = False` | Flat hain — naya entry allowed |
| `entry = True` | Position already hai — dobara entry NAHI |

`not entry` ka matlab: "jab entry False ho" — matlab jab hum already invested nahin hain. `not` operator ka quick reference:

| Expression | Result |
|---|---|
| `not True` | `False` |
| `not False` | `True` |
| `not entry` (jab entry=False) | `True` → code andar jaayega |

Yahi flag pattern har backtest engine ka dil hai. Aur dhyan do — yahi wohi "event vs state" baat hai jo 4.2/4.3 mein discuss hui thi: state (`fast > slow`) check kar rahe hain, par flag ki wajah se entry sirf **pehli bullish candle** pe hoti hai jab hum flat hain — effectively crossover event hi pakad leta hai.

## PnL Calculation — ⚠️ Critical Correction

⚠️ **Dhyan do — yahan source material mein bada bug tha.** Original cohort notes mein PnL formula aise pada tha:

> `pnl = buy_price - sell_price`
>
> Buy at 100, Sell at 110 → PnL = −10 (**Loss**) ❌
> Buy at 100, Sell at 90 → PnL = +10 (**Profit**) ❌

**Dono rows ulta hain!** Soch ke dekho — long trade matlab pehle khareeda, phir becha. Profit kab hota hai? Jab **bechne ka price khareedne se ZYADA ho**:

```text
PnL = sell_price − buy_price     ← CORRECT

Buy at 100, Sell at 110 → 110 − 100 = +10 (Profit) ✅
Buy at 100, Sell at 90  → 90 − 100  = −10 (Loss)   ✅
```

Sanity check hamesha yehi karo: *"maine 100 mein kharida, 110 mein becha → jeb mein 10 zyada."* Agar tera backtest har winner ko loss dikha raha hai aur net result weirdly negative aa raha hai — sabse pehle PnL line check kar. Yeh **silent bug** strategy ko galat reject karwa deta hai — code chal jaata hai, error nahi aata, bas answer ulta hota hai.

## Complete Working Code

Ab sab kuch jodke poora runnable script:

```python
qty = 10            # har trade mein kitne shares
entry = False       # position flag
buy_price = 0.0     # entry price yaad rakhne ke liye
net_pnl = 0.0       # total profit/loss
trades = []         # har trade ka PnL log

for i in range(len(df)):
    fast_now = df["ema_9"][i]
    slow_now = df["ema_21"][i]

    # ENTRY: bullish state + abhi flat
    if fast_now > slow_now and not entry:
        entry = True
        buy_price = df["close"][i]

    # EXIT: bearish state + position open hai
    elif fast_now < slow_now and entry:
        sell_price = df["close"][i]
        pnl = (sell_price - buy_price) * qty    # CORRECTED formula
        net_pnl += pnl
        trades.append(pnl)
        entry = False                            # ab naya entry possible

print(f"Total trades:   {len(trades)}")
print(f"Winning trades: {sum(1 for t in trades if t > 0)}")
print(f"Net PnL:        {net_pnl:.2f}")
```

Line by line walkthrough:

1. **Setup variables** — flag, prices, totals. `trades` list har trade ka PnL store karti hai (agli file ke metrics isi se banenge!)
2. **Entry block:** bullish state + not entry → position lo, entry price save karo
3. **Exit block (`elif`):** bearish state + position open → becho, PnL nikalo, log karo, flag reset. (`elif` isliye kyunki ek candle pe dono conditions true ho hi nahi sakti — fast EMA ek saath upar bhi aur neeche bhi nahi.)
4. `(sell_price - buy_price) * qty` — corrected formula + quantity multiplier (10 shares × ₹10 move = ₹100 actual PnL; bina qty ke sirf per-share difference aata)
5. `net_pnl += pnl` — accumulation; final value = strategy ka total result

Ek cleanup notice: original notes mein ek dead branch tha (`if fast < slow and not entry: pass`) — "yeh condition kabhi nahi aayegi" wala. Sahi observation thi, toh humne usse hata diya — dead code reader ko confuse karta hai.

## Real World Reminder

Yeh basic calculation hai — actual trading mein **slippage, commission, charges** bhi include karne padte hain. 4.1 wala transaction-cost disaster yaad hai? (500 trades × cost = 150%!) Cost modeling hum baad mein add karenge; abhi logic clean rakhna zaroori tha.

Output interpret karna bhi seekho: `Net PnL` negative aaya toh strategy (is data pe) losing hai. Par ek number se verdict mat de — win rate, drawdown, consistency bhi toh dekhna hai. Woh sab agli file mein: **Performance Metrics**.

## Nutshell

Backtest engine = loop + state machine. Entry flag (`not entry`) repeat entries rokta hai; exit pe flag reset hota hai taaki next crossover pe phir enter ho sakein. ⚠️ Critical fix: **PnL = sell − buy** (source mein ulta pada tha — sanity check: "100 mein khareeda, 110 becha = +10"). Quantity multiplier se real rupee PnL aata hai, aur trades list agli file ke metrics ka raw material hai. Column convention: `ema_9`/`ema_21` — kahin bhi mix na karo.

## What It Is NOT

- ❌ **Yeh production backtester nahi hai.** No SL, no target, no costs, no slippage, no partial exits — minimal engine hai core mechanics sikhane ke liye. Layers baad mein judengi.
- ❌ **Negative net_pnl ≠ strategy useless.** Ek dataset, ek timeframe, no costs — verdict se pehle multiple regimes aur proper metrics chahiye.
- ❌ **State-based entry ≠ event-based entry generally.** Yahan flag ki wajah se dono practically same result dete hain (long-only, single position). Multi-position ya pyramiding strategies mein farq critical ho jaata hai.
