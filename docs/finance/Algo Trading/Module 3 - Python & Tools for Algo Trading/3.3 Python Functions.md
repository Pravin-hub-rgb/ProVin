Imagine a scene.

Chai is made at your home every day. And every day you have to tell the whole recipe:

```text
"Boil water, add leaves, add sugar, add milk, strain and serve..."
```

Every day. Got bored, right?

Now imagine: write the recipe once, **stick it on the fridge**, and just say *"make chai"*?

**That's exactly what a FUNCTION is.**

> Function = packed code. Write once. Give a name. Then call by name, as many times as you want.

# 3.3 Python Functions

## Let's Make the First Function

```python
def make_chai():
    print("Water boiled")
    print("Leaves added")
    print("Milk added")
    print("Chai ready! ☕")
```

What was this? Line by line:

```text
def           → keyword "defining a function"
make_chai     → function's name (you gave it)
()            → input's place (empty for now — will understand shortly)
:             → "code inside starts now"
    print...  → lines inside (indented = part of it)
```

⚠️ Not run yet! Just PACKED.

Tiffin packed — haven't eaten yet.

## Calling — The Real Game

Using a function is called **calling**. Name + brackets:

```python
make_chai()
```

Output:

```text
Water boiled
Leaves added
Milk added
Chai ready! ☕
```

All inner lines ran!

And the magic — as many times as you want:

```python
make_chai()
make_chai()
```

```text
(Chai made 2 times!)
```

Two calls, double output. Code was written only ONCE.

## Wait — What Happened So Far?

```text
✅ def name(): → PACKING a function
✅ name()      → OPENING the pack (calling)
✅ Write once, use unlimited times
```

This concept is the backbone of all programming. The backtest engine in Module 4 will also be one big function.

## Giving Input — Parameters

Now problem: chai got made, but everyone asks differently.

```text
Brother: "less sugar one"
You:     "strong one"
```

One recipe won't work for everyone — **input needed.**

Giving input to function = **parameter**:

```python
def make_chai(sugar):
    print(f"Chai being made with {sugar} spoon sugar")
```

See what happened:

```text
sugar    → parameter = name of input (like a box)
()       → not empty now, name written inside
```

Now send value when calling:

```python
make_chai(1)     # for brother
make_chai(3)     # for you
```

Output:

```text
Chai being made with 1 spoon sugar
Chai being made with 3 spoon sugar
```

Same function. Different results — because input was different!

### Two Inputs Also Possible

Just put comma, done:

```python
def make_chai(sugar, milk_amount):
    print(f"{milk_amount} ml milk, {sugar} spoon sugar")

make_chai(2, 50)
```

```text
50 ml milk, 2 spoon sugar
```

Order matters: first input goes into first parameter.

## Getting Output Back — return

So far function only PRINTED.

But there's another job: **giving result back.**

Understand with example — shop's billing machine:

- You give items (input)
- It calculates (process inside)
- It GIVES bill (output) ← this is `return`!

```python
def calculate_total(price, qty):
    total = price * qty
    return total
```

Line by line:

```text
price * qty     → math happened inside
return total    → result THROWN OUT, into caller's hands
```

Now call — and CATCH the result:

```python
my_bill = calculate_total(100, 5)
print(my_bill)
```

```text
500
```

What happened:

```text
calculate_total(100, 5)  → function ran → returned 500
my_bill = ...            → that 500 came into my_bill box
```

### Print vs Return — Most Confusing Point (Now Clear)

| | `print` | `return` |
|---|---|---|
| What it does | Shows on SCREEN | Gives result BACK |
| Can use later? | ❌ gone, just shown | ✅ lying in box |
| Analogy | Showing a swing | Giving tiffin |

```python
print(total)      # just shows, can't use ahead
return total      # given — save, send ahead, add...
```

In trading code, **return is used more** — because results need processing ahead (calculate PnL, make report, etc.).

## Wait — Whole Flow at a Glance

```python
def calculate_total(price, qty):   # PACKED (2 inputs)
    total = price * qty            # work inside
    return total                   # gave result back

bill = calculate_total(100, 5)     # CALLED, caught result
```

```text
Inputs → function → return → saved in box
```

This pattern will repeat everywhere. Remember like your phone number.

## Small Advanced Point — Inside Stays Inside

One thing that will confuse later, clear now:

```python
def my_function():
    secret = 42          ← made inside
    print(secret)

my_function()            ✅ 42 will show (access from inside)
print(secret)            ❌ ERROR! Can't see from outside
```

Variables made inside function **stay inside.**

Like stuff kept in kitchen — won't be visible in outside room.

This is called scope — for now this much is enough, detail comes later.

## Why Are Functions So Important?

Three solid reasons:

1. **Write once** — bug fixed in one place, fixed everywhere
2. **Name tells meaning** — seeing `calculate_total()` meaning is clear, no need to read inner code
3. **Big programs in small chunks** — backtest engine = union of functions: fetch data function, find signals function, send orders function...

Every file in Module 4 has functions. This file is their ticket.

## Nutshell

Function = packed code with name. Make with `def`, call with name — as many times as you want. Parameters = inputs (`def chai(sugar)`), send values when calling. `return` = giving result back — caller can catch and save it (print only shows, return GIVES). Variables inside function stay inside (scope). Big programs = union of small functions.

## What It Is NOT

- ❌ **Made function ≠ ran it.** Making (def) is separate, calling is separate. Packed tiffin — haven't eaten! Forget to call (`name()`), output will never come.
- ❌ **return and print are not same.** Print = show on screen (result gone). Return = give in hand (use ahead). Confuse them and bugs like "function didn't give value" will come.
- ❌ **Not every code needs a function.** Small one-time code, write directly. Make function when code must be REUSED OR naming improves readability.
