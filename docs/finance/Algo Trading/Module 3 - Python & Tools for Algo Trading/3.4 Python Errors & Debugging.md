# 3.4 Python Errors & Debugging

## Error Ke 3 Main Types

Python mein mainly teen tarah ke errors aate hain:

- **Syntax Error** — code ki "grammar" galat (colon/indent bhool gaye)
- **Runtime Error** — code chalte waqt aata hai (jaise divide by zero)
- **Logical Error** — Python error deta nahi, par answer galat aata hai

Har type ka behaviour alag hai — ek-ek karke dekhte hain.

## Syntax Error — Grammar Galat

Syntax matlab code likhne ka form — jaise language ki grammar. `if` statement likha toh colon (`:`) aur indentation zaroori hai:

```python
# galat — colon nahi
if a > 20
    print("yes")      # ❌ SyntaxError

# sahi
if a > 20:
    print("yes")      # ✅
```

Colon bhool gaye, bracket mismatch kar diya — **SyntaxError** aayega.

Iska fayda yeh hai: syntax wala error code ko **run hi nahi hone deta.** Python sabse pehle grammar check karta hai — pehli hi line pe pakad leta hai. Matlab jab tak syntax theek nahi, program shuru bhi nahi hoga.

## Runtime Error — Chalte Waqt Blast

Runtime error run hone ke **baad** aata hai — sirf specific condition par:

```python
x = int(input("Enter number: "))
print(10 / x)     # x = 0 daala toh ZeroDivisionError
```

Code likhte waqt sab sahi tha, x = 10 diya toh chal bhi gaya. Lekin kisi ne x = 0 daal diya → blast.

Yeh errors tricky hote hain kyunki **sirf kuch cases mein aate hain.** Testing mein nahi mile, production mein aa jaate hain. Aur ek baat — jahan error aaya wahan code ruk jaata hai, uske aage ka kuch nahi chalta.

## NameError — Variable Exist Hi Nahi Karta

```python
print(y)     # ❌ y define hi nahi kiya
```

Aisa variable use kar rahe ho jo banaya hi nahi gaya. Spelling check karo — `name` banaya aur `nmae` use kiya toh bhi NameError hi aayega. Rule simple: pehle define karo, phir use karo.

## IndexError — List Ki Range Se Bahar

```python
L = [1, 2, 3, 4, 5]
print(L[5])     # ❌ IndexError
```

List mein 5 items hain toh indexes `0` se `4` tak hain (yaad kar — indexing 0 se shuru). Index `5` maang liya jo exist hi nahi karta → **IndexError.**

Yeh bhi beginners ka favourite mistake hai — "list mein 5 items hain toh L[5] last item dega" — nahi! Last item `L[4]` hai.

## Logical Error — Sabse Khatarnak

Ab sabse chupa hua error. Ismein Python ko koi problem nahi hoti — code chalega, output bhi aayega... **par answer galat hoga:**

```python
num1 = input("Enter: ")   # string mila!
num2 = input("Enter: ")
print(num1 + num2)        # "10" + "20" = "1020" ❌ 30 nahi aaya
```

Koi red text nahi, koi crash nahi — bas `"1020"` aaya instead of `30`. Kyunki input() ne strings diye aur `+` ne unhe join kar diya (3.1 mein type casting yaad kar?).

Logical error isliye sabse dangerous hai — **tumhe pata hi nahi chalega ki galat hai** jab tak output manually verify na karo. Backtesting mein yeh sabse bada dushman hai — backtest profit dikha raha hai par logic galat hai, aur tujhe pata hi nahi. Isliye results hamesha manually spot-check karo.

## Debugging Ka Basic Process

Jab bhi error aaye, yeh 3 steps:

1. **Error message padho** — Python batata hai kaunsi line pe kya hua. Red text dushman nahi, dost hai.
2. **Us line pe jao, fix karo**
3. **Re-run karo**

Aur logical errors ke liye: print statements daalo beech mein — variables ki values check karo ki expected hain ya nahi. Yehi basic debugging hai.

## Nutshell

Teen main error types: **SyntaxError** (grammar galat — colon/indent/bracket — code run hi nahi hota), **RuntimeError** (chalte waqt specific condition pe — divide by zero), **LogicalError** (koi error nahi, answer galat — sabse chupa hua). Side characters: **NameError** (undefined variable), **IndexError** (list range bahar — max index n-1). Har error normal hai — message padho, fix karo, re-run.

## What It Is NOT

- ❌ **Error = tum coder nahi ho, aisa kuch nahi.** 20 saal ke experienced developers roz errors dekhte hain. Farak sirf itna hai ki unki debugging speed tez hai.
- ❌ **Error message ignore karke guess mat karo.** Message mein answer likha hota hai — line number, error type, reason. Pehle padho.
- ❌ **"Code chal gaya" = "code sahi hai" nahi.** Logical error mein code chalta hai par result galat hota hai — isliye outputs manually verify karna habit banao.
