# 3.4 Python Errors & Debugging

## First One Thing — Error = Message

Don't panic seeing an error.

Error is actually Python's **message**:

> *"Brother wait! Something went wrong here. I'm saying this..."*

Like a car's warning light — whether engine is bad or petrol is low, the light turns on to HELP.

Debugging = reading that message and finding the problem.

**Debug** itself means "removing bugs" — finding hidden mistakes in code.

## Two Big Types of Errors

```text
1. Syntax Error    → wrong grammar while writing
                      (Python catches it while reading code)

2. Logical Error   → code ran, but ANSWER is wrong
                      (most dangerous — Python can't catch it!)
```

Let's look one by one, with examples.

## Syntax Error — Wrong Grammar

Bad grammar in Hindi = can't understand the sentence.

Bad grammar in Python = **code won't run at all.**

```python
for i in range(5)
    print(i)
```

Run... ERROR:

```text
SyntaxError: expected ':'
```

Read the message: *"expected ':'"* — colon (`:`) was expected!

Look at line 1 — colon was forgotten after `range(5)`.

Fix:

```python
for i in range(5):     ← colon added ✅
    print(i)
```

### Message Reading Method (Formula)

```text
1. Read Error TYPE      (SyntaxError? NameError?)
2. Look at LINE NUMBER  (which line did it happen?)
3. Read MESSAGE         ("expected what?")
```

These three steps for every error. Just that.

## Runtime Errors — Blast While Running

Syntax was fine, code RAN... then blew up midway.

### Example 1: NameError

```python
print(profit)
```

```text
NameError: name 'profit' is not defined
```

Read: *"profit named thing doesn't exist at all."*

Meaning — you never created `profit` box!

Maybe spelling is wrong:

```python
profitt = 100     ← double-t written here
print(profit)     ← single here! Names don't match ❌
```

**Fix:** check names — both places must be EXACTLY same (spelling and capital-small both).

`Profit` and `profit` are TWO DIFFERENT names for Python!

### Example 2: ZeroDivisionError

```python
total = 100
trades = 0
average = total / trades
```

```text
ZeroDivisionError: division by zero
```

Read: *"can't divide by zero."*

In math too 100 ÷ 0 = impossible, right? Python says the same.

In real trading this comes when trades = 0 and you calculate average. That's why code first checks: *"trades isn't zero, right?"*

## Most Dangerous — Logical Error

Now read carefully. This one is most dangerous.

**In logical error:**

```text
✅ Code runs
✅ No error comes
❌ But answer is WRONG
```

Python says nothing — it thinks everything ran fine.

Remember the 3.1 trap?

```python
a = "10"       ← quotes = it was TEXT!
b = "20"
result = a + b
print(result)
```

Output: `1020`

No error came. Code ran.

But if this were your backtest and you were adding profit/loss... **entire result WRONG**, and you wouldn't even know. 😱

So remember the rule:

> **Error coming is good — it SHOWS the problem.
> Silent wrong answer — it HIDES the problem.**

And one famous example (from notes): `"10" + "20"` type logical error was sitting in note 29's PnL formula — entire cohort learned wrong PnL because code "was running." We fixed it in Module 4.

## Basic Debugging Process

Now learn to fix. 4-step process — same for every error:

```text
STEP 1: Read error message (type + line number)
STEP 2: Go to that line, look around
STEP 3: Do print debugging
STEP 4: Fix → run again → repeat
```

### Understand Step 3 — What is Print Debugging

Simplest debugging tool: **put print and peek inside.**

Think: chai didn't come right. What would you do?

Taste every step — water okay? leaves okay? milk?

Same in code:

```python
def calculate_average(trades):
    print(f"DEBUG: trades came = {trades}")     ← peek!
    total = sum(trades)
    print(f"DEBUG: total came out = {total}")   ← peek again!
    avg = total / len(trades)
    return avg
```

Run and see — are values what they SHOULD be?

Where first wrong value shows — **that's where the bug is.**

This handles 90% of cases.

### A Real Debug Story

```python
prices = [100, 200, 300]
print(prices[5])     ← asked for 6th element (only 0-4 exist!)
```

```text
IndexError: list index out of range
```

Read: *"index is out of range."*

List has 3 items (positions 0,1,2). I asked for 5.

Fix: `print(prices[2])` — last valid position.

(Index starts from 0 — detail in later files.)

## Remember Error Names (Cheat Sheet)

| Error | Meaning | Common Reason |
|---|---|---|
| `SyntaxError` | Grammar wrong | Colon/bracket miss |
| `NameError` | This name doesn't exist | Spelling wrong / didn't create |
| `ZeroDivisionError` | Divide by 0? No! | trades = 0 |
| `IndexError` | Position out of range | Asked wrong index |
| **Logical** *(silent)* | Ran but answer wrong | "10"+"20" type traps |

First four show up immediately. Fifth is silent — most scary.

## Nutshell

Error = Python's help message, like car's warning light. Process: read message (type + line) → go to line → print-debugging to peek values → fix → repeat. Syntax = grammar (code won't run). Runtime (NameError/ZeroDivision/Index) = blast while running. Logical = SILENT killer — code runs, answer wrong ("10"+"20" trap). Error showing is good; silent wrong answer is worst.

## What It Is NOT

- ❌ **Error coming = you're a bad programmer.** No — errors are daily life of every expert. Skill isn't avoiding errors, it's reading them FAST. Learned to read message = half developer.
- ❌ **Debugging ≠ guess-and-check.** Don't randomly change things and see — systematic process: read, peek (print), compare (expected vs actual), fix. Guessing wastes time.
- ❌ **"No error" ≠ correct code.** Most dangerous illusion. Logical errors are silent. So make it habit to compare outputs with EXPECTED result — "should've been 100+20=120, did it come?"

**Answer:** (1) TYPE — read error's name (SyntaxError/NameError...) — name itself tells half the problem. (2) LINE NUMBER — which line broke, go there (sometimes actual mistake is above). 2. Why is logical error most dangerous — even though it's not visible?

<details>
<summary>Sample Answer</summary>

**Answer:** Because it's INVISIBLE. Syntax/runtime errors loudly fail — caught, fixed. In logical error code runs smoothly, output also comes... but WRONG. In trading: backtest results wrong, and you put real money on that basis! Defense: compare outputs with expected, keep sanity checks ("buy low sell high = should be positive PnL"), verify formulas when results look odd.

</details>

3. How does print debugging work?

<details>
<summary>Sample Answer</summary>

**Answer:** Put print() in between code and see variable's CURRENT value: print(f"DEBUG: {value}"). Then ask yourself: "what should this value be here?" Where actual vs expected first differ — bug is there. Just like making chai: taste every step, where taste changed that's the problem step. Simplest debugger — and surprisingly most effective.

</details>

4. NameError came "name 'proft' is not defined". Think and tell real problem?

<details>
<summary>Sample Answer</summary>

**Answer:** Names don't match. Possibilities: (1) Spelling — 'profit' written somewhere, 'proft' somewhere (one t missing). (2) Capital-small mismatch — 'Profit' vs 'profit' (Python case-sensitive!). (3) Variable never created — assignment missing before use. Fix: write both names side-by-side and compare letter-by-letter. 90% NameErrors are spelling issues.

</details>
