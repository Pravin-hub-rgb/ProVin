## First Understand — What is TOTP

**TOTP = Time-based OTP** = password that **changes every 30 seconds.**

Used bank apps or Google Authenticator?

Those 6-digit codes that expire in few seconds — exactly that.

### So What's the Problem?

If you type OTP **by hand:**

```text
Type... "4-8-2-9-1-0"
Saw code... 30 seconds passed! ❌ EXPIRED
Type again...
Expires again...
INFINITE STRUGGLE 💀
```

So never by hand!

### Solution — pyotp

`pyotp` library GENERATES OTP for you, fresh every time:

```python
import pyotp

totp = pyotp.TOTP("YOUR_TOTP_SECRET")   ← secret set
code = totp.now()                        ← CURRENT valid code!
```

```text
totp.now()   → "give the 6-digit that's valid this second"
```

Fresh code every call. Zero typing. Zero expiry tension. ✅

**Where to get TOTP Secret?**

Angel One app → Settings → API section → copy TOTP secret.

Save that long string in `tokens.py`.

## Login — Four Things

```python
# login.py

from smartapi import SmartConnect
import pyotp
from tokens import api_key, username, mpin, totp_secret

# STEP 1: Waiter ready
smart_api = SmartConnect(api_key=api_key)

# STEP 2: Generate fresh OTP
totp_code = pyotp.TOTP(totp_secret).now()

# STEP 3: Login with everything
session = smart_api.generateSession(
    username=username,       ← your client ID / mobile
    password=mpin,           ← your MPIN (4-digit)
    totp=totp_code           ← just now's fresh OTP
)

# STEP 4: Catch token
access_token = session["data"]["access_token"]
print("LOGIN DONE! ✅")
```

Line by line:

```python
SmartConnect(api_key=...)      → waiter ready (like Dhan/Zerodha)
pyotp.TOTP(secret).now()       → made current valid 6-digit code
generateSession(...)           → gave all documents — entry received
session["data"]["access_token"]→ took out badge and saved
```

Difference from Dhan: one EXTRA document needed here (OTP).

Rest pattern same!

## Two Tokens Come Here

Session response has TWO tokens:

```python
access_token   → today's badge — data/orders with this
refresh_token  → backup pass — expired badge gets
                 NEW badge without full-login
```

| Token | Life | Work |
|---|---|---|
| access_token | short | all requests |
| refresh_token | longer | renew expired badge |

Refresh token means: not full dance every day — sometimes just refresh.

(For now keep simple: expired → run login.py again.)

## Response Format — One Twist Here

Angel One gives candles like this — **lists inside lists:**

```python
{
  "data": {
    "candles": [
      ["2024-01-01 09:15", 2450.0, 2460.0, 2448.0, 2452.0, 125000],
      ["2024-01-01 09:20", 2452.0, 2458.0, 2451.0, 2457.0, 110000]
    ]
  }
}
```

Each candle is a LIST. Position tells what it is:

```text
Position 0 → time
Position 1 → open
Position 2 → high
Position 3 → low
Position 4 → close
Position 5 → volume
```

(Dhan/Zerodha gave named columns — this gives positions!)

## Nutshell

Angel One = TOTP twist. TOTP is 30-sec changing OTP — impossible by hand, automatic with `pyotp.TOTP(secret).now()`. Login: key + username + MPIN + fresh OTP → generateSession → access_token (+ refresh_token backup). Fetch: `get_candle_data()` — here SYMBOL name works (Dhan wanted number!). Response has candles as LISTS — so must give `columns=` yourself when making DataFrame. Each broker's style different, pattern same.

## What It Is NOT

- ❌ **TOTP is not SMS/Email OTP.** It's authenticator-app style time-based code that works without network (only secret + time needed). SMS OTP automation unsafe/inappropriate; TOTP automation perfectly fine — that's why pyotp exists.
- ❌ **refresh_token is not second access token.** Its ONE job: renew expired badge. Data fetch or orders don't go with it. Don't confuse.
- ❌ **Candle-list format is not universal.** Angel One gives lists, Zerodha gives dicts. Response SHAPE differs per broker — so first time `print(response)` to see, then write convert logic.
