## Pehle Samjho — TOTP Kya Hai

**TOTP = Time-based OTP** = aisi password jo **har 30 second mein badal jaati hai.**

Bank apps ya Google Authenticator use kiye hain?

Woh 6-digit codes jo kuch second mein expire ho jaate hain — bilkul waisa.

### Toh Problem Kya Hai?

Agar tu OTP **haath se type** karega:

```text
Type kiya... "4-8-2-9-1-0"
Dekha code ne... 30 second nikal gaye! ❌ EXPIRED
Phir se type...
Phir expire...
INFINITE STRUGGLE 💀
```

Isliye haath se kabhi nahi!

### Solution — pyotp

`pyotp` library tere liye OTP GENERATE karti hai, har baar fresh:

```python
import pyotp

totp = pyotp.TOTP("TERI_TOTP_SECRET")   ← secret set ho gayi
code = totp.now()                        ← CURRENT valid code!
```

```text
totp.now()   → "abhi is second mein jo valid 6-digit hai, woh de do"
```

Har call pe fresh code. Zero typing. Zero expiry tension. ✅

**TOTP Secret kahan milti hai?**

Angel One app → Settings → API section → TOTP secret copy karo.

Woh lambi si string `tokens.py` mein save kar lo.

## Ruk — Abhi Tak Kya Hua?

```text
✅ TOTP = 30-second wali OTP (authenticator app jaisi)
✅ Haath se type = expire ho jayegi = pagalpan
✅ pyotp.TOTP(secret).now() = Python khud fresh OTP banayega ✅
```

## Login — Chaar Cheezein

```python
# login.py

from smartapi import SmartConnect
import pyotp
from tokens import api_key, username, mpin, totp_secret

# STEP 1: Waiter taiyaar
smart_api = SmartConnect(api_key=api_key)

# STEP 2: Fresh OTP generate karo
totp_code = pyotp.TOTP(totp_secret).now()

# STEP 3: Sab kuch de ke login karo
session = smart_api.generateSession(
    username=username,       ← tera client ID / mobile
    password=mpin,           ← tera MPIN (4-digit)
    totp=totp_code           ← abhi ki fresh OTP
)

# STEP 4: Token pakdo
access_token = session["data"]["access_token"]
print("LOGIN DONE! ✅")
```

Line-by-line:

```python
SmartConnect(api_key=...)      → waiter ready (jaise Dhan/Zerodha mein)
pyotp.TOTP(secret).now()       → current valid 6-digit code bana
generateSession(...)           → sab documents de diye — entry mil gayi
session["data"]["access_token"]→ badge nikal ke save kiya
```

Dhan se farq: yahan **ek extra document chahiye tha** (OTP).

Baaki bilkul same pattern!

## Do Tokens Milte Hain Yahan

Session response mein DO tokens hote hain:

```python
access_token   → roz ka badge — data/orders isse
refresh_token  → backup pass — badge expire ho toh NAYA badge
                  bina full-login ke mil jaata hai
```

| Token | Life | Kaam |
|---|---|---|
| access_token | short | saare requests |
| refresh_token | longer | expired badge renew karna |

Refresh token ka matlab: roz poora dance nahi — kabhi-kabhi sirf refresh.

(Abhi hum simple rakhenge: expire hua toh login.py dobara chalao.)

## Nutshell

Angel One = TOTP twist. TOTP har 30 sec badalti OTP hai — haath se impossible, `pyotp.TOTP(secret).now()` se automatic. Login: key + username + MPIN + fresh OTP → generateSession → access_token (+ refresh_token backup). Fetch: `get_candle_data()` — yahan SYMBOL naam chalta hai (Dhan number mangta tha!). Response mein candles LISTS hoti hain — isliye DataFrame banate waqt `columns=` khud dena padta hai. Har broker ka style alag, pattern same.

## What It Is NOT

- ❌ **TOTP = SMS/Email OTP nahi.** Woh authenticator-app wala time-based code hai jo bina network ke bhi banta hai (sirf secret + time chahiye). SMS OTP automation safe/appropriate nahi; TOTP automation perfectly fine — isi liye pyotp exist karta hai.
- ❌ **refresh_token = doosra access token nahi.** Uska EK hi kaam: expire hue badge ko renew karna. Usse data fetch ya orders nahi jaate. Confuse mat hona.
- ❌ **Candle-list format universal nahi.** Angel One lists deta hai, Zerodha dicts. Har broker pe response SHAPE alag — isliye pehli baar `print(response)` karke dekho, phir convert logic likho.
