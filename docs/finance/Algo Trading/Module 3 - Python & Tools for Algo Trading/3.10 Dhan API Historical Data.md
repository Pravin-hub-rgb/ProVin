# 3.10 Dhan API Historical Data

## Setup — Two Things First

**1. Install library (3.5's delivery boy):**

```bash
pip install dhanhq
```

`dhanhq` = Dhan's official Python library. All ready-made functions inside.

**2. Get credentials (3.9's keys):**

```text
Dhan app/web → Settings/API section →
CLIENT ID     (ID card)
ACCESS TOKEN  (visitor badge)
```

Copy both into `tokens.py` (3.9's method):

```python
# tokens.py
client_id = "1101234567"
access_token = "eyJhbGciOi..."     # long random string
```

Now write code.

## Login — Make Client

```python
from dhanhq import dhanhq
from tokens import client_id, access_token

dhan = dhanhq(client_id, access_token)
```

Line by line:

```python
from dhanhq import dhanhq      ← took main class from library
from tokens import ...          ← 3.9's method: keys from separate file
dhan = dhanhq(client_id, ...)   ← "waiter" ready! Now can give orders
```

`dhan` is now our connection object — all requests will go through it.

Login in one line. Dhan is easy, right? 😎

## Historical Data Fetch — Real Candles!

Now that moment. We want Reliance's 5-min candles:

```python
response = dhan.historydailydata(
    security_id="2885",        # Reliance's ID number
    exchange_segment="NSE_EQ",
    instrument="EQUITY",
    interval="5",              # 5-minute candles
    from_date="2024-01-01",
    to_date="2024-02-01"
)

print(response["status"])      # what happened?
print(response["data"][:2])    # see first 2 candles
```

Parameters one by one:

```text
security_id       → stock's NUMBER (not name!) — explained below
exchange_segment  → which exchange (NSE_EQ = NSE equities)
instrument        → type (EQUITY = normal shares)
interval          → candle size ("5" = 5-minute, "60" = 1-hour...)
from/to_date      → from how old to till when
```

Candles will come in response — in JSON format (like dictionary).

### ⚠️ What is Security ID? (Common Confusion!)

Broker doesn't understand "RELIANCE" name — every stock has a **number**:

```text
RELIANCE → 2885
TCS      → 11536
INFY     → 1594
```

These numbers are found in broker's docs/instruments list.

Write name and you'll get error — and this is the first error of next section! 😄

## Two Real Errors (I Made Them Too)

Errors are normal — these two are most common. See them, never surprised again.

### Error 1: Import trouble

```text
ImportError: cannot import name 'dhan_context'
```

**Meaning:** library version is old/new, import name changed.

**Fix:** Google `dhanhq import error` or check current import line on library's GitHub/docs. Libraries keep updating — import lines can change. Lesson: **when error comes, official docs = best friend.**

### Error 2: Symbol won't work

```python
# ❌ WRONG:
dhan.historydailydata(symbol="RELIANCE", ...)
```

```text
TypeError: unexpected keyword argument 'symbol'
```

Python says: *"I don't accept any input named symbol!"*

**Fix:** Dhan doesn't want symbol — wants **security_id** (number above):

```python
# ✅ CORRECT:
dhan.historydailydata(security_id="2885", ...)
```

Lesson: **each broker's function input NAMES are different.** Check docs, don't guess.

```text
✅ STEP 1 CONNECT:     dhanhq(client_id, access_token)
✅ STEP 2 AUTHENTICATE: logged in with token
✅ STEP 3 FETCH:       called historydailydata(...)
✅ STEP 4 CONVERT:     pd.DataFrame(response["data"])
```

See? 3.8's pattern was EXACTLY this. Now this pattern will repeat on every broker.

## Nutshell

Dhan = easiest starter broker. Setup: `pip install dhanhq` + credentials in tokens.py. Login: `dhanhq(client_id, access_token)` — one line. Fetch: `historydailydata(security_id, interval, dates)` — **stock's NUMBER (security_id) needed, not name!** Errors: import issues = check docs; wrong parameter names = TypeError comes, correct name from docs. Last step: response → `pd.DataFrame()` → backtest-ready table.

## What It Is NOT

- ❌ **`response` is not directly DataFrame.** It's JSON/dict (with status + data keys). Pandas tools like `.head()` come only after converting with `pd.DataFrame(response["data"])`. Don't skip convert step.
- ❌ **security_id is not same across brokers.** 2885 is Dhan's Reliance number only. Zerodha/Angel have different numbering systems (instrument_token etc.). Each broker gives instruments list — mapping from there.
- ❌ **Access token is not permanent.** Expires in a day or few hours (depends on broker). Ran code tomorrow and got "unauthorized"? Token refresh/re-generate — code isn't broken!
