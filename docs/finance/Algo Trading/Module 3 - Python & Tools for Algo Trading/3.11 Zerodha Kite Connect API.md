# 3.11 Zerodha Kite Connect API


`kiteconnect` library mein built-in functions already hain: `kite.historical_data`, `kite.place_order`, wagera.

## Login Flow — Teen Tokens Ka Dance

Yahan tak sab brokers same the. Ab Zerodha ka unique hissa. Teen tokens chahiye:

| Token | Kya Hai | Kab Milta Hai |
|---|---|---|
| **API Key** | App ki unique ID | App create hone ke baad |
| **Request Token** | Temporary token | Login URL pe login karne ke baad |
| **Access Token** | Asli permission | Request token + API secret se generate |

### Step-by-Step Code

```python
from kiteconnect import KiteConnect

# Step 1: API key se session object banao
kite = KiteConnect(api_key="YOUR_API_KEY")

# Step 2: Login URL generate karo
login_url = kite.login_url()
print(login_url)
```

Ab manual step aata hai:

3. Ye URL browser mein kholo → Zerodha account se login karo
4. Login ke baad browser redirect hoga aur URL mein `?request_token=xxxxx` dikhega — **usko copy karo**

```python
# Step 3: Request token + secret se access token banao
session = kite.generate_session(
    request_token="PASTE_REQUEST_TOKEN",
    api_secret="YOUR_API_SECRET"
)
kite.set_access_token(session["access_token"])

# DONE! Login complete
```

Poora flow ek nazar mein:

```
[API Key] → login URL open + login → [Request Token] 
→ generate_session() → [Access Token] → Data fetch / Trade
```

Pehli baar ajeeb lagega — "itna lamba kyun?" Par dobara dekho: pattern wahi hai jo 3.9 mein seekha — credentials do, verification hoti hai, access token milta hai. Bas beech mein ek browser login extra hai.

## Access Token Expiry — 24 Ghante Ka Sach

Yeh Zerodha ki sabse annoying cheez hai: **access token 24 ghante mein expire ho jaata hai.**

Matlab roz subah naya token banana padega. Har din woh poora browser-login dance? Nahi — professional solution hai:

**Alag `login.py` file banao** jismein sirf login ka kaam ho:

```text
login.py  → sirf login logic (token generate + save)
app.py    → main trading code → from login import kite
```

```python
# app.py
from login import kite      # access token already set

data = kite.historical_data(...)
```

Best practice: har din subah ek baar `login.py` run karo, phir din bhar main code chalao. Agar kabhi *"Invalid token"* ya *"Authentication failed"* error aaye — samajh lo token expire ho gaya, `login.py` dobara chalao.

## Historical Data Fetch Karna

Login ho gaya? Ab candle data:

```python
data = kite.historical_data(
    instrument_token=259656775,     # NIFTY 50 ka numeric token
    interval="5minute",             # timeframe
    from_date="2022-08-19",
    to_date="2022-09-19",
    continuous=False
)
```

| Parameter | Kya Hai | Examples |
|---|---|---|
| `instrument_token` | Stock/index ka **numeric** token | NIFTY 50 = 259656775 |
| `interval` | Timeframe | `"1minute"`, `"5minute"`, `"15minute"`, `"1day"` |
| `from_date` / `to_date` | Date range | `"2022-08-19 09:15:00"` |

### Instrument Token Kya Hai?

Yeh Dhan wale `security_id` jaisa hi concept hai — bas yahan **numeric ID** hoti hai, naam nahi. Har stock/index ka apna number hai. Kaise mile:

- Zerodha ke docs se instrument list download karo → name se search karo
- Ya ChatGPT se poocho: *"NIFTY 50 ka Zerodha instrument token kya hai?"*

## Common Errors Aur Fixes

**Error 1: `Token is invalid / expired`**
Request/access token expire ho gaya (24 hours). Fix: `login.py` dobara run karo, naya token generate karo.

**Error 2: Data fetch hi nahi ho raha**
Instrument token galat ho sakta hai. Pehle verify karo sahi numeric token diya hai ya nahi.

**Error 3: ChatGPT ka code nahi chala**
Same lesson jo Dhan mein seekha — ChatGPT purana code de deta hai. Google karo: `kiteconnect historical_data` — official docs khulenge, wahi sahi parameters batayenge.

## Nutshell

Kite Connect = Zerodha ka API. Login 3-token dance hai: API key → browser login se request token → `generate_session()` se access token. Token 24 ghante expire — isliye alag `login.py` file banao, roz subah ek baar chalao, main code se import karo. Data: `kite.historical_data()` with numeric `instrument_token`, `interval`, dates. DataFrame convert karo — OHLCV columns ready. Zerodha sabse complex hai — iske baad koi API dar nahi lagegi.

## What It Is NOT

- ❌ **Request token = access token nahi.** Request token temporary hai (ek login ke liye); usko `generate_session()` mein daal ke asli access token banana padta hai. Dono ko mix karna beginners ki common galti hai.
- ❌ **Roz browser login avoid nahi ho sakta (free tier mein).** 24-hour expiry Zerodha ki policy hai — `login.py` automation se bas process fast ho jaata hai.
- ❌ **Instrument token guess nahi kar sakte.** Symbol se number ka mapping docs/list se hi milega — "RELIANCE ka token hoga 738561" type guessing se galat data ya empty response aayega.
