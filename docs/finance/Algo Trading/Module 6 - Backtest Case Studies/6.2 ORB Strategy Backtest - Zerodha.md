# 6.2 Opening Range Breakout (ORB) Backtest — Zerodha

## Strategy Rules

Pehle rules ekdum clear kar lo (yehi rules code mein convert honge):

```text
ORB Rules:
- Instrument: stock (Reliance example) / Nifty / BankNifty
- Market open: 9:15 AM
- First 15-min candle (9:15–9:30) ka HIGH & LOW mark karo
  = "Opening Range"
- Execution: 5-min chart pe
- Price breaks ABOVE high  → LONG entry
- Price breaks BELOW low   → SHORT entry
- Stop Loss = opposite bound (long mein low, short mein high)
- Target = 1:2 risk-reward (1:3 bhi test kar sakte ho)
```

Logic samajh: opening 15 minutes mein institutional money apni position banati hai — jo range banti hai woh din ka "battlefield" hai. Range ke upar break = buyers jeet rahe, neeche break = sellers. Simple, logical, aur 5.3 ke criteria pe perfect fit: objective, repeatable, codable.

Risk-reward math bhi neat hai: long @ range-high 2500, SL @ range-low 2480 (risk 20), target @ 2540 (reward 40) = 1:2. Ek trade jeeta toh do haarne wali cover.

## Code Architecture — Building Blocks

### Helper Functions

Chhote reusable functions (3.3 ka concept kaam pe aa gaya):

```python
def is_green(candle):
    return candle["close"] > candle["open"]

def is_red(candle):
    return candle["close"] < candle["open"]
```

Yeh trivial lagte hain par do fayde hain: (1) intent readable hota hai — `if is_green(c):` khud bolta hai, (2) baar-baar same comparison likhne ka bug chance zero.

### State Machine — Wohi Flag Pattern

4.5 wala `order_in_progress` flag yahan bhi hero hai:

```python
in_trade = False      # abhi position open hai?
direction = None      # "LONG" ya "SHORT"
entry_price = sl = target = 0.0
trades = []
```

### Main Loop — Day-wise ORB Logic

Single-day demo se samjho, phir loop saare days pe:

```python
import pandas as pd

df["date_only"] = df["date"].dt.date          # har candle ka din
df["time"] = df["date"].dt.time

for day, day_df in df.groupby("date_only"):
    day_df = day_df.reset_index(drop=True)

    # --- Opening Range: 9:15–9:30 ke candles (pehli teen 5-min candles)
    or_high = day_df.iloc[0:3]["high"].max()
    or_low  = day_df.iloc[0:3]["low"].min()
    risk = or_high - or_low

    in_trade = False
    entry_price = sl = target = None

    for i in range(3, len(day_df)):            # range ke BAAD ki candles
        c = day_df.iloc[i]
        price = c["close"]

        if not in_trade:
            # LONG: close breaks above range high
            if price > or_high:
                in_trade, direction = True, "LONG"
                entry_price = price
                sl = or_low                     # opposite bound
                target = entry_price + 2 * (entry_price - sl)   # 1:2
            # SHORT: close breaks below range low
            elif price < or_low:
                in_trade, direction = True, "SHORT"
                entry_price = price
                sl = or_high
                target = entry_price - 2 * (sl - entry_price)

        else:
            hit_sl = price <= sl if direction == "LONG" else price >= sl
            hit_tg = price >= target if direction == "LONG" else price <= target

            if hit_sl:
                pnl = (sl - entry_price) * qty if direction == "LONG" \
                      else (entry_price - sl) * qty
                trades.append({"day": day, "dir": direction, "pnl": pnl})
                in_trade = False
            elif hit_tg:
                pnl = (target - entry_price) * qty if direction == "LONG" \
                      else (entry_price - target) * qty
                trades.append({"day": day, "dir": direction, "pnl": pnl})
                in_trade = False

report = pd.DataFrame(trades)
print(f"Trades: {len(report)}, Net PnL: {report['pnl'].sum():.0f}")
```

Dekho kitne purane dost yahan hain:
- **State machine + flag** — 4.5 wala pattern
- **PnL sign** — long mein `(exit − entry)` ⚠️ (neeche correction dekho)
- **iloc slicing** — `iloc[0:3]` = first three candles, stop excluded (3.7!)
- **groupby** — pandas skill (3.7), din-wise processing

⚠️ **Ek aur formula correction source material se:** original notes mein likha tha *"PnL = entry price − exit price (long)"* — **yeh bhi ulta hai!** Long trade mein PnL = **exit − entry** (4.5 mein jo fix kiya tha wahi rule). Short trade mein ulta: entry − exit. Sign errors backtests ko silently poison karte hain — apne code mein ek baar `sanity_check()` comment daal do: *"long jeet = exit > entry?"*

### Time Filter — Late Breakouts Se Bachav

Real ORB traders ek restriction add karte hain: **entries sirf range banne ke turant baad ki window mein.** Din ke 2 baje ka "breakout" wohi signal nahi hota — stale move hota hai. Original class mein bhi time-restriction add ki gayi thi. Code mein ek line:

```python
ENTRY_CUTOFF = dt.time(10, 15)   # example window
...
if not in_trade and c["time"] <= ENTRY_CUTOFF:
    # entry logic
```

Yeh parameter hai — tune kar sakte ho (5.4 yaad hai na: ranges, plateaus!).

## Nutshell

ORB = zero-indicator price-action strategy: first 15-min (9:15–9:30) high-low range → breakout above = LONG (SL = low, target 1:2), below = SHORT (mirror). Workflow: rules comments mein → Kite data (3.11 flow, instruments() se token) → helper functions (`is_green/is_red`) → state-machine loop with flag → day-wise groupby processing. Corrections: PnL = exit − entry for longs (source mein phir ulta tha!). Time filter late breakouts rokta hai. Debugging normal hai. Aur assignment: apna vs AI code diff karna hi asli quant skill hai.

## What It Is NOT

- ❌ **Zero-indicator ≠ zero-logic.** Indicator nahi hai par rules poore hain — range definition, breakout definition, SL/target math. "Price action" bhi precisely defined hona padta hai.
- ❌ **ORB har din trade nahi leta.** Range ke andar price rahi (no breakout) → no trade. No-trade bhi decision hai — forced entries account killers hain.
- ❌ **1:2 target universal law nahi.** Parameter hai — 1:1, 1:3 test karo (broad ranges, 5.4 style). Fixed RR + tight SL combo volatile stocks pe different behave karega.

**In Your Own Words**

1. ORB ka opening range kaise banta hai aur execution 5-min chart pe kyun?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Range = market open ke baad pehli 15 minutes (9:15–9:30) ki combined high-low. 5-min chart pe yeh teen candles hoti hain (9:15, 9:20, 9:25 wali) — unka max high = range top, min low = range bottom. Execution 5-min pe isliye kyunki (a) breakout confirmation finer milti hai — 15-min candle wait karni padti toh move miss, (b) SL/target placement precise hota hai. Definition (range) aur execution (timeframe) alag cheezein hain.

</details>

2. Long trade mein entry, SL, target kahan lagte hain? Math dikhao.

<details>
<summary>Sample Jawab</summary>

**Jawab:** Entry: close crosses above range high (maan lo high=2500, entry=2502). SL: opposite bound = range low (2480) → risk = 22 points. Target: 1:2 RR → reward = 44 → target = 2502+44 = 2546. Code: `sl = or_low; target = entry + 2*(entry − sl)`. Short mirror hai: entry below low, SL = high, target neeche 2× distance. Ek winner (44) do losers (22×2) cover karta hai.

</details>

3. Time filter (entry cutoff) kyun zaroori hai ORB mein?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Kyunki opening range ka significance time-bound hai — subah ka breakout institutional momentum signal hai; dopahar ka same-level cross stale drift hota hai (news, profit booking). Bina cutoff ke strategy random afternoon breakouts bhi legi jo historical edge nahi rakhte. Filter = strategy ka context preserve karna. Yeh parameter hai, tune broad-range style mein hota hai (9:45? 10:15? 10:45?) — plateau dhundo.

</details>

4. Apna vs ChatGPT backtest results alag kyun aa sakte hain (3 reasons)?

<details>
<summary>Sample Jawab</summary>

**Jawab:** (1) Breakout trigger difference — ek close-based, doosra wick/high-based; intraday noise mein ye dozens of trades change karta hai. (2) Same-candle conflict resolution — agar ek candle mein SL bhi touch ho aur target bhi, konsa pehle maana — assumption matters. (3) Entry timing — breakout candle ke close pe ya next open pe; plus costs included ya nahi. Lesson: results differ = assumptions differ. Code diff karke exact line dhundo — yehi professional debugging hai.

</details>
