# 6.2 Opening Range Breakout (ORB) Backtest — Zerodha

## Strategy Rules — First Absolutely Clear

```text
ORB RULES:
Instrument : Stock (Reliance example)
Open Time  : 9:15 AM
RANGE      : First 15-min candle (9:15-9:30) HIGH & LOW
             = "opening range"
Execution  : 5-minute chart
BREAK UP   → LONG entry 🟢
BREAK DOWN → SHORT entry 🔴
STOP LOSS  = opposite side of range
TARGET     = 1:2 risk-reward
```

### Logic Understand — Why Does This Work?

In first 15 minutes after market open

**big players build their positions.**

Range formed is day's "battlefield."

```text
Break ABOVE range → buyers winning → day bullish?
Break BELOW range → sellers winning → day bearish?
```

### Risk-Reward Math (What 1:2 Means)

Example numbers:

```text
Range high: 2500 | Range low: 2480
BUY @ 2500 (on breakout)
SL @ 2480 (range low)        → RISK = ₹20
Target @ 2540                → REWARD = ₹40

1 risk for 2 reward! One win = two losses covered!
```

## Code Architecture — Building Blocks

### Helper Functions (3.3's use!)

```python
def is_green(candle):

def is_red(candle):

```

### State Machine — Same Flag Pattern!

4.5's `entry` flag hero here too:

```python
in_trade = False       # is position open?
direction = None       # "LONG" or "SHORT"
entry_price = sl = target = None
trades = []
```

## Main Loop — Day-wise ORB Logic

Understand one day's demo, then loop over all days:

```python
df["date_only"] = df["date"].dt.date     # which DAY each candle
df["time"] = df["date"].dt.time          # and TIME within that day

for day, day_df in df.groupby("date_only"):      # separate each DAY
    day_df = day_df.reset_index(drop=True)

    # --- OPENING RANGE: first THREE 5-min candles (9:15-9:30)
    or_high = day_df.iloc[0:3]["high"].max()     # biggest high of three
    or_low  = day_df.iloc[0:3]["low"].min()      # smallest low of three
    risk = or_high - or_low                       # range width

    in_trade = False

    for i in range(3, len(day_df)):              # candles AFTER range
        c = day_df.iloc[i]
        price = c["close"]

        if not in_trade:
            # LONG: close went ABOVE range-high?
            if price > or_high:
                in_trade = True
                direction = "LONG"
                entry_price = price
                sl = or_low                      # opposite bound
                target = entry_price + 2 * (entry_price - sl)   # 1:2!

            # SHORT: close went BELOW range-low?
            elif price < or_low:
                in_trade = True
                direction = "SHORT"
                entry_price = price
                sl = or_high                     # mirror!
                target = entry_price - 2 * (sl - entry_price)

        else:
            # Position open — check SL or TARGET
            hit_sl = price <= sl if direction == "LONG" else price >= sl
            hit_tg = price >= target if direction == "LONG" else price <= target

            if hit_sl:
                pnl = (sl - entry_price) if direction == "LONG" else (entry_price - sl)
                trades.append({"day": day, "dir": direction, "pnl": pnl * qty})
                in_trade = False
            elif hit_tg:
                pnl = (target - entry_price) if direction == "LONG" else (entry_price - target)
                trades.append({"day": day, "dir": direction, "pnl": pnl * qty})
                in_trade = False
```

Looks long? Read inside —

**only 3 concepts repeating!**

### Concept 1 — Getting Opening Range

```python
or_high = day_df.iloc[0:3]["high"].max()
```

```text
iloc[0:3]        → positions 0,1,2 (THIRD NOT! stop excluded — 3.7 rule!)
["high"]         → their high column
.max()           → BIGGEST high among three
```

First 3 candles (9:15, 9:20, 9:25) = 15-minute window.

Their max high = range top. Mirror: min low = range bottom.

### Concept 2 — Entry Conditions

```python
if price > or_high:
    ...LONG setup...
elif price < or_low:
    ...SHORT setup...
```

Went above range → LONG. Below range → SHORT.

SL at opposite bound, target 2x distance (1:2!).

```python
target = entry_price + 2 * (entry_price - sl)
```

Read: `(entry − sl)` = RISK.

`2 × risk` = reward. `entry + reward` = target!

### Concept 3 — Exit Checks (SL/Target)

```python
hit_sl = price <= sl if direction == "LONG" else price >= sl
```

This is **ternary** (3.8-style one-line if):

```text
LONG?  → SL hit when price BELOW SL
SHORT? → SL hit when price ABOVE SL
(mirror logic!)
```

## ⚠️ One More Formula Correction!

Original material wrote again:

> *"PnL = entry price − exit price (long)"* ← **REVERSED!**

4.5's same rule again:

```text
✅ Long trade PnL = EXIT − ENTRY
   (bought 100, sold 110 = +10 PROFIT!)
```

Short is reverse: `entry − exit`.

Sign errors silently poison backtests —

**put comment in your code:** `# long win = exit > entry?`

## Time Filter — Avoid Late Breakouts

One improvement real traders add:

**entries only in morning window!**

Afternoon "breakout" isn't same signal — stale move.

```python
ENTRY_CUTOFF = dt.time(10, 15)     # example: entries only till 10:15
...
if not in_trade and c["time"] <= ENTRY_CUTOFF:
    # now entry logic runs
```

This is parameter — tune (9:45? 10:15? 10:45?)

— broad ranges style (remember 5.4?).

## Nutshell

ORB = zero-indicator: first 15-min range (first 3 candles' max-high/min-low) → breakout above = LONG (SL=low, target 1:2), below = SHORT mirror. Workflow: rules in comments → Kite data → helper functions (`is_green/is_red`) → state-machine + flag → day-wise `groupby`. ⚠️ PnL correction again: long = exit − entry! Time-filter avoids late breakouts. Assignment = diff your vs AI code — real quant skill.

## What It Is NOT

- ❌ **Zero-indicator ≠ zero-logic.** No indicator but rules COMPLETE — range definition, breakout definition, SL/target math. Price-action must also be precisely defined.
- ❌ **ORB doesn't trade every day.** Price stays in range (no breakout) → NO TRADE. No-trade is also decision — forced entries are account killers!
- ❌ **1:2 target is not universal law.** It's parameter — test 1:1, 1:3 (broad ranges!). Same RR behaves differently on volatile stock.

1. How does opening range form? Why execute on 5-min chart?

<details>
<summary>Sample Answer</summary>

**Answer:** Range = combined high-low of first 15 minutes (9:15–9:30) after open. On 5-min chart = first THREE candles; their max high = top, min low = bottom. Execute on 5-min because: (a) breakout confirmation finer — waiting for 15-min candle misses move; (b) SL/target placement more precise. Definition (range) and execution-timeframe (candles) are different things.

</details>

2. Show long trade entry/SL/target math.

<details>
<summary>Sample Answer</summary>

**Answer:** Say range high 2500, low 2480. Entry on breakout close 2502. SL = opposite bound = 2480 → risk ₹22. Target 1:2 = 44 points up = 2546. Code: target = entry + 2*(entry − sl). Short is MIRROR: entry below low, SL = high, target 2x down. Math simple: one winner (44) covers two losers (22×2).

</details>

3. Why is time filter necessary?

<details>
<summary>Sample Answer</summary>

**Answer:** Opening range's significance is TIME-bound! Morning breakout = institutional momentum = signal. Afternoon same-level cross = stale drift (profit booking, news) = noise. Without cutoff strategy takes random afternoon "breakouts" with no edge. Cutoff is parameter — tune broad-range style (9:45/10:15/10:45), find plateau.

</details>

4. Why do two codes' results differ? (3 reasons)

<details>
<summary>Sample Answer</summary>

**Answer:** (1) Breakout TRIGGER difference — one close-based, other wick/high-based; in intraday noise this changes dozens of trades. (2) Same-candle CONFLICT — if one candle touches both SL and target, which counted first? Assumption matters. (3) ENTRY timing — breakout candle's close or next open? Plus costs included or not. Lesson: results differ = assumptions differ. Diff code to find exact line — that's professional debugging.

</details>
