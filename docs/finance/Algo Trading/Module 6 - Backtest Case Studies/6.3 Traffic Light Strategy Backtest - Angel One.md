# 6.3 Traffic Light Strategy Backtest — Angel One

## Strategy Rules

```text
Traffic Light Rules:
- Price-action based (koi indicator nahi)
- Alternating GREEN/RED candle PAIRS dhundo
  (double-green ya double-red allowed NAHI)
- Pair ka highest-high aur lowest-low mark karo = range
- Range break hote hi LINEAR ENTRY (seedha entry, koi confirmation nahi)
- Target = 1:2 (ORB jaisa hi)
- Risk management:
  * Max 3 trades per day
  * Saare open orders 3:25 PM pe force-close (naya din, fresh start)
```

Naam kyun "Traffic Light"? Kyunki candles red-green alternate hoti hain jaise signal ke lights — pattern dikhta hai toh "go" milta hai.

Logic samajh: alternating pairs = **indecision/tug-of-war zone** (buyers-sellers baar-baar exchange kar rahe). Us tug-of-war ki poori range mark karo — jo side bhi finally break karegi, woh winner side hogi. ORB se difference: yahan range sirf opening se nahi, **din mein kahin bhi** ban sakti hai.

"Linear entry" ka matlab: breakout dikha → seedha entry, koi extra confirmation nahi (koi indicator check, koi retest wait nahi). Simple = good (5.3 ka principle).

Aur dono risk rules note karo — yeh ORB mein nahi the:

- **Max 3 trades/day:** choppy day mein strategy ko baar-baar fake breakout khane se rokta hai
- **3:25 PM square-off:** overnight position risk zero; har din clean slate

## Data Fetch — Angel One SmartAPI + Chunking

Login flow wahi 3.12 wala — `login.py` file mein `generateSession()` with pyotp TOTP, access token ready. Ab data:

**Token:** Nifty ka instrument token `3045` hai ("normal market" segment). BankNifty chahiye toh uska token dhundo — data alag hoga par **code same rahega**.

⚠️ **Chunking zaroori hai!** Angel One (aur Zerodha bhi) ek request mein poora saal ka minute-data nahi dete — API limit hoti hai. Isliye date-range ko **chunks mein todna padta hai**:

```python
import pandas as pd
from datetime import date, timedelta
from login import smart_api   # 3.12 wala session

def fetch_chunked(token, start, end, interval="FIVE_MINUTE"):
    all_candles = []
    current = start
    while current < end:
        chunk_end = min(current + timedelta(days=30), end)
        raw = smart_api.get_candle_data(
            exchange="NSE",
            tradingsymbol="NIFTY",
            interval=interval,
            fromdate=current.isoformat() + " 09:00",
            todate=chunk_end.isoformat() + " 15:30",
        )
        all_candles.extend(raw["data"]["candles"])
        current = chunk_end
    df = pd.DataFrame(all_candles,
                      columns=["time", "open", "high", "low", "close", "volume"])
    return df

df = fetch_chunked(3045, date(2024, 1, 1), date(2024, 12, 31))
```

## Code Architecture — Pair Detector

### Helpers + Naya Function

```python
def is_green(c):
    return c["close"] > c["open"]

def is_red(c):
    return c["close"] < c["open"]

def is_alternating_pair(prev_c, curr_c):
    """Do consecutive candles jinke colors alag hon"""
    return (is_green(prev_c) and is_red(curr_c)) or \
           (is_red(prev_c) and is_green(curr_c))
```

🔑 **Look-ahead prevention in action:** pair check karne ke liye sirf **current + previous** candle pass karte hain — future candles NAHI dekh sakte. Yehi 4.1 wala look-ahead bias hai jo code level pe avoid hota hai. Har naye candle pe poochte hain: *"kya tum aur tumse pichli wali alternating pair banate hain?"* Agar haan → range mark karo, break ka wait karo.

### State Machine — Ab Extra States Ke Saath

```python
MAX_TRADES = 3
trades_today = 0
in_trade = False
direction = None
range_high = range_low = None
entry_price = sl = target = None

report = {"entry_time": [], "entry_price": [],
          "exit_time": [], "exit_price": [], "pnl": []}
```

Loop skeleton (day-wise groupby — 6.2 jaisa hi):

```python
for i in range(1, len(df)):
    prev_c, curr_c = df.iloc[i-1], df.iloc[i]
    t = curr_c["time"]

    # --- Rule: 3:25 PM forced square-off
    if in_trade and t >= time(15, 25):
        exit_price = curr_c["close"]
        pnl = (exit_price - entry_price) if direction == "LONG" \
              else (entry_price - exit_price)
        log_trade(report, curr_c["time"], entry_price,
                  curr_c["time"], exit_price, pnl)
        in_trade = False
        continue

    # --- Exit checks (SL/target) jab trade open ho
    if in_trade:
        hit_sl = curr_c["close"] <= sl if direction == "LONG" else curr_c["close"] >= sl
        hit_tg = curr_c["close"] >= target if direction == "LONG" else curr_c["close"] <= target
        if hit_sl or hit_tg:
            exit_price = sl if hit_sl else target
            pnl = (exit_price - entry_price) if direction == "LONG" \
                  else (entry_price - exit_price)
            log_trade(report, prev_c["time"], entry_price,
                      curr_c["time"], exit_price, pnl)
            in_trade = False
        continue

    # --- Entry: naya pair bana? trades bachchi hain?
    if not in_trade and trades_today < MAX_TRADES:
        if is_alternating_pair(prev_c, curr_c):
            # pair ki RANGE set karo (pair ke dono candles ka high/low)
            pair = df.iloc[i-1:i+1]
            range_high = pair["high"].max()
            range_low = pair["low"].min()
            pending_breakout = True     # ab breakout ka wait
```

(Breakout-check logic pending state mein — price `range_high` cross kare → LONG with SL=`range_low`, target 1:2; neeche cross → SHORT mirror. Structure ORB jaisa hi hai, bas trigger alag.)

## Nutshell

Traffic Light = alternating green/red candle PAIR ka range-break strategy: pair detect karo (sirf current+prev candle — no look-ahead!), pair high/low mark karo, break pe linear entry, 1:2 target. Do naye risk layers: max 3 trades/day counter aur 3:25 PM forced square-off. Data: SmartAPI chunked fetching (30-day pieces, extend karo), token 3045 Nifty. Report dict-of-lists → DataFrame → 4.6 metrics + ChatGPT analysis. Framework wahi tha jo ORB mein — proof ki tumne ek reusable backtest engine seekha hai, ek-off script nahi.

## What It Is NOT

- ❌ **Alternating pairs = reversal signal nahi.** Pair sirf INDECISION zone define karta hai; trade breakout pe hota hai (momentum direction mein), reversal pe nahi.
- ❌ **Max-3-trades rule profit-limiter nahi hai.** Woh loss-limiter hai — choppy din mein fake breakouts ka damage cap karta hai. Achhe din mein bhi 3 pe rukna discipline hai, greed-control.
- ❌ **Linear entry = careless entry nahi.** Confirmation skip karna speed ke liye conscious choice hai; SL distance (pair range) usko compensate karta hai. Bina SL ke linear entry gambling hai.

1. Pair detector future candles kyun nahi dekhta? Code mein kaise ensure hota hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Kyunki future dekhna look-ahead bias hai — live trading mein future exist hi nahi karta, toh jo backtest future use kare woh lie karta hai. Ensure: function signature hi restriction hai — `is_alternating_pair(prev_c, curr_c)` mein sirf do candles pass hote hain, teesri (future) candle accessible hi nahi. Design principle: data access ko function boundaries se limit karo, toh bias structurally impossible ho jaata hai.

</details>

2. Max 3 trades/day rule ka purpose kya hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Choppy/sideways days mein traffic-light ranges baar-baar banti aur break hoti hain — fake breakouts. Bina cap ke strategy ek hi bure din mein 8-10 SL kha sakti hai. Cap se worst-day damage bounded hai (3 × SL). Yeh position-sizing family ka rule hai (2.4): per-day loss limit. Bonus psychological benefit: revenge trading ka scope khatam — 3 losses ke baad system khud ruk jaata hai.

</details>

3. 3:25 PM square-off kyun (market 3:30 close hota hai)?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Close se theek pehle exit = overnight gap risk zero (5.2 ka intraday principle). Buffer minutes isliye taaki execution complete ho sake close auction/sebi timings se pehle — 3:30 pe exact order bhejna risky hai (liquidity thin, order reject ho sakta). "Naya din fresh start" bhi clean accounting deta hai: har day ka PnL isolated, overnight margin tension nahi.

</details>

4. Chunked fetching kyun zaroori thi Angel One pe jabki Groww pe nahi?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Broker APIs ki per-request data limits alag hote hain. Angel One (aur Zerodha) minute-level historical data limited window mein dete hain — 1 saal lene ke liye ~30-din chunks mein loop karna padta hai (get_candle_data repeatedly, results extend). Groww ka endpoint bada range ek request mein de deta tha. Lesson: broker limits docs se padho, fetcher utility generic likho jo chunk-size parameter le.

</details>

5. ORB vs Traffic Light — framework same, kya-kya badla?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Same: state machine, flag pattern, PnL math, SL/target logic (1:2), day-wise processing, report building, metrics pipeline. Different: signal generation (opening range vs candle-pair range), range timing (fixed morning vs anywhere-in-day), data broker (Kite vs SmartAPI+chunking), risk extras (time cutoff vs trade-cap+EOD square-off). Conclusion: backtest engine reusable hota hai; strategies plug-and-play modules hain.

</details>
