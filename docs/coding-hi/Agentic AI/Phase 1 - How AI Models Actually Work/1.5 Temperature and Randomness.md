Back in the API request we looked at, there was a parameter called `temperature`. You might have seen it in your AI tool's settings and wondered what it does. Let's demystify it.

**Temperature controls how "creative" the model's predictions are.**

# 1.5 Temperature: The Creativity Dial

Remember: a language model works by picking the next most likely token, one at a time. But "most likely" isn't the only option. Behind the scenes, the model assigns a probability score to every possible next token — a ranked list of candidates. At temperature 0, the model always picks the single highest-probability token. Every time. Same input, same output. Deterministic.

As you turn up the temperature, the model starts rolling dice. It still prefers high-probability tokens, but it occasionally reaches a bit lower down the list and picks something less obvious. The higher the temperature, the more often it takes those less-likely paths.

Think of it like this:

- **Temperature 0** — The model plays it safe. "The cat sat on the..." → "mat." Every single time.
- **Temperature 0.7** — The model might pick "rug," "floor," or "windowsill" instead. Same sentence, different flavors.
- **Temperature 1.0+** — The model might pick something surprising like "spaceship" or "stock market." Still grammatically correct, but less predictable.

**Low temperature (0–0.3): You want consistency.** This is what you use for coding, data extraction, following precise instructions, or anything where correctness matters. You want the model to do the obvious right thing every time. Most coding agents default to a low temperature — usually around 0.3 — because you don't want your AI to get *creative* with your production database schema.

**Medium temperature (0.4–0.7): Balanced.** Good for general conversation, explaining concepts, writing documentation. The model has room to vary its phrasing without going off the rails.

**High temperature (0.7–1.0): Creative mode.** Useful for brainstorming, creative writing, generating multiple options, or coming up with alternative approaches. The trade-off: the model is more likely to hallucinate, make mistakes, or go off-topic.

Some models let you go above 1.0, but that's usually a bad idea. At that point, the model is actively avoiding obvious choices and the output quality degrades quickly.

Here's the key insight: **temperature doesn't add randomness like chaos. It adds controlled variation.** The model still only picks from tokens that make grammatical sense. Temperature just shifts whether it picks the safest choice or something more adventurous from the probability distribution.

## What It Is NOT

Temperature is NOT the model's "mood" or "emotion." A high temperature doesn't mean the model is feeling creative — it's just a mathematical parameter that flattens the probability curve, making less-likely tokens slightly more probable. It's also NOT a toggle between "smart" and "dumb." A low-temperature model that always picks the safest token can still give wrong answers — it's just consistently wrong the same way every time. And high temperature doesn't add new knowledge; the model can only pick from tokens it already knows, not invent new ones.

For your coding workflows, keep temperature low when you want the right answer. Dial it up when you want the model to suggest multiple approaches or think outside the box. But remember: if you ask the same question twice at high temperature, you'll get two different answers — neither of which may be correct. Temperature is a creative tool, not a fact-finding one.

**Sample Answer:** For unit tests, keep temperature low (0–0.3) because you want deterministic, correct output — the same assertion should be generated the same way every time. For marketing taglines, dial it up to 0.7–1.0 to get variety and creative alternatives. Think of temperature like a photographer's settings: low temperature is a tripod shot — steady and predictable; high temperature is handheld with motion blur — you might catch something interesting, but you'll also get some duds.

<details>
<summary>2. At temperature 0, a model gives the same output for the same input every time. Is that a good thing or a bad thing? When might it work against you?</summary>

**Sample Answer:** It's good when you need consistency — like generating production code or extracting structured data — but it works against you in creative tasks. If you ask for a poem at temperature 0, you'll get the most statistically common poem every time, which means boring and repetitive. It's like a chef who makes the exact same dish identically every time — great for a Big Mac, terrible if you want a tasting menu.

</details>

<details>
<summary>3. Have you ever asked an AI to do something creative (write a poem, suggest a project name, brainstorm features) and gotten a boring, predictable result? What might have been going on with the temperature?</summary>

**Sample Answer:** The tool was likely running at a low default temperature (many coding-focused tools default to 0.3–0.5). The model played it safe and picked the most obvious next token every time, resulting in the most cliché poem or the most generic project name. It's like asking a painter to "be creative" but only letting them use gray paint — they can technically make something, but it won't be vibrant.

</details>

<details>
<summary>4. Why do you think coding agents default to low temperature? What would happen if Cline or opencode ran at temperature 1.0 all the time?</summary>

**Sample Answer:** Coding requires precision, not creativity. At temperature 1.0, the model would occasionally pick unexpected tokens — using an obscure library instead of the standard one, adding unnecessary "creative" comments, or introducing bugs by choosing less-likely code paths. Your production database schema doesn't need artistic flair. It's like an architect deciding to "spice things up" with the building's load-bearing walls — some things are better left predictable.
