Now you know about tokens — the individual units the model reads and writes in. But those tokens don't float around in infinite space. They live inside something called the **context window**.

The context window is the total amount of text the model can "see" at any given moment. Think of it as the model's working memory — like a desk where it can spread out papers. Everything on that desk is visible. Everything off it might as well not exist.

# 1.3 Context Window: The Model's Desk

When you're using a coding agent like Cline or opencode, here's everything that competes for space on that desk:

- The **system prompt** — the hidden instructions that tell the model how to behave (like "you are a senior software engineer")
- Your **current message**
- The **entire conversation history** — every message you've sent and every response you've gotten
- Any **files or code** you've asked it to read
- Its **own responses** as it generates them

![Context Window Diagram — System Prompt, Attached Files, Conversation History, and Current Message on a Desk](/diagrams/agenticai/context-window.svg)

All of this has to fit inside the context window. If it doesn't fit, something gets pushed off.

Different models have different context sizes:
- Claude Sonnet 4: 200K tokens (that's roughly a 150,000-word novel)
- GPT-4: 128K tokens (about 96,000 words)
- Older models: 4K, 8K, 32K — much tighter

200K tokens sounds like a lot. And it is. But when you're working on a large codebase, uploading multiple files, and having a long back-and-forth conversation, you'd be surprised how fast it fills up.

Let's make this concrete with the dark/light theme example again. Here's what your context window might look like when you tell Cline or opencode to create both themes:

```
System prompt (~500 tokens)
Your message: "Create a dark theme and a light theme for this website" (~15 tokens)
styles.css file you attached (~900 tokens)
Cline's first response: Here's the dark theme CSS... (~400 tokens)
Your follow-up: "Make the dark theme darker" (~10 tokens)
Cline's second response: Here's the updated CSS... (~300 tokens)
Your next question: "Now apply the same to the light theme" (~15 tokens)
Cline's third response: Here's the light theme CSS... (~400 tokens)
--- NOW YOU'RE AT ~2,540 TOKENS ---
```

That's just a few exchanges and you're already at 2,500 tokens. Now imagine you keep going — testing colors, adjusting spacing, fixing responsive breakpoints, asking about accessibility. Ten more exchanges and you could easily be at 20,000+ tokens. The context window starts filling up, and the oldest content — like your original `styles.css` file — gets pushed out.

Here's where the practical pain shows up. Ever been in a long session with Cline or opencode where the agent suddenly seems to "forget" something you discussed earlier? Like you asked it to use a specific naming convention, and twenty messages later it's back to the old style? That's the context window in action. Imagine writing on a sticky note — every new sentence means erasing an older one, and eventually the very first thing you wrote is gone. The early part of the conversation got pushed out to make room for newer content. The model literally cannot see that instruction anymore. In the dark/light theme example, if the agent suddenly forgets that you wanted `--primary-dark: #0f0f23` instead of `#000000`, it's not being careless — the part of the conversation where you specified that color just got evicted from the desk.

This is also why you sometimes need to "refresh" the model's memory — by restating key constraints in your current message, or by using a feature like Cline's or opencode's "checkpoint" to reset the conversation. The model isn't being forgetful in a human sense. Its working memory has a physical limit, and older tokens get evicted.

One more thing: the model's response itself takes up space inside the context window while it's being generated. So a model with a 200K window can't receive a 200K-token prompt and still respond — it needs room to write. Providers usually reserve some of that space for the output.

So when you're working with an AI agent, think about the context window like a resource you're managing. Every file you attach, every long conversation turn, every system prompt directive — they're all competing for real estate. Being concise isn't just polite. It's practical.

## What It Is NOT

The context window is NOT like human memory. It doesn't consolidate important information, form long-term memories, or prioritize one fact over another. When tokens get pushed out, the model doesn't know they're gone — it can't feel "forgetful" the way a person does. It's more like a whiteboard: once something is erased, it's just gone. There's no "oh wait, I think there was something there" feeling. The model's experience is always just what's currently written on the board, nothing more.

Now that you know how the model's memory works, let's zoom out. How does your text actually get from your computer to the model and back? That's the request flow, and it's simpler than you think.

### In Your Own Words

<details>
<summary>1. Have you ever had an AI "forget" something mid-conversation? What do you think got pushed out of the context window to make room?</summary>

**Sample Answer:** The early part of the conversation — like the initial instructions or constraints you set — is the first thing to go as new messages fill the window. Your later messages and the model's longer responses push out the oldest content. It's like a line at a busy deli: the person who ordered first eventually gets pushed out the door as new customers keep arriving, even if their order was the most important one.

</details>

<details>
<summary>2. If you're working on a large project and your AI agent needs to reference multiple files, what strategies could you use to stay within the context window?</summary>

**Sample Answer:** You can summarize files instead of pasting them whole, break the project into smaller focused conversations, or use the model's ability to ask clarifying questions rather than dumping everything upfront. Think of it like telling a friend about a movie — you don't recite the script, you give a summary and only quote the key scenes when needed.

</details>

<details>
<summary>3. Why do you think different models have different context window sizes? What trade-offs might a larger window involve (speed, cost, accuracy)?</summary>

**Sample Answer:** A larger context window requires more memory and computation — the model has to process more tokens for every single prediction. It's like asking someone to read a whole book before answering a question about one sentence: the more they have to keep in mind, the slower and more expensive it gets. Providers choose different window sizes based on the use case — 4K for simple chatbots, 200K for code analysis — and users pay the price in latency and cost.

</details>

<details>
<summary>4. When you start a new conversation with an AI, the context window is empty. How does that change the way you should write your first message compared to your twentieth?</summary>

**Sample Answer:** Your first message needs to include all the context upfront — what you're working on, what tools you're using, what constraints apply — because the model has no prior context. By your twentieth message, a lot of that early context may have been pushed out, so you should restate key constraints or questions directly. It's like joining a meeting late: you need to summarize what you missed because no one else has the full picture anymore.

</details>
