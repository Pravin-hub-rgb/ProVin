# 6.3 Project 3: Research Agent

Two projects in. You've built an agent that fetches weather data, and an agent that reads and summarizes local files. Now let's combine the pattern with a new capability: web search.

The Research Agent takes a topic from the user, searches the web multiple times (the agent decides how many), and produces a structured report. This is the most autonomous agent yet — it plans its own research strategy.

---

## What you're building

User types "Research the current state of AI agents" → agent searches the web, reads results, searches again for follow-up angles, then writes a 5-point summary report.

The agent decides:
- What search queries to run
- How many searches to perform
- When it has enough information to stop
- How to structure the final answer

You don't tell it "search twice." It decides.

---

## Stack

- **Next.js** (App Router)
- **Anthropic SDK** (`@anthropic-ai/sdk`)
- **Tavily API** — a search API designed specifically for AI agents. Returns clean, parsed results instead of raw HTML

---

## Why Tavily instead of Google Search API?

Google's Custom Search API returns 10 blue links with snippets. Tavily is built for agents:
- Returns clean content (not just snippets — actual paragraphs)
- Supports `max_results` to control how many sources to fetch
- Has a simple, single-endpoint API
- Free tier gives 1000 searches/month — plenty for testing

Tavily was literally designed for this use case. Google's API was designed for embedding search results into a website.

## Step 3: The web search tool

Tavily's SDK makes this trivial:

```typescript
// app/api/agent/search.ts

import { tavily } from "@tavily/core";

const tvly = tavily({ apiKey: process.env.TAVILY_API_KEY! });

export async function webSearch(query: string): Promise<string> {
  const response = await tvly.search(query, {
    maxResults: 5,
    searchDepth: "advanced",
  });

  if (!response.results || response.results.length === 0) {
    return `No results found for "${query}". Try a different search term.`;
  }

  return response.results
    .map(
      (result, i) =>
        `[Source ${i + 1}: ${result.title}](${result.url})\n${result.content}`
    )
    .join("\n\n");
}
```

**Walkthrough:**

- `tavily({ apiKey: ... })` initializes the client. The `@tavily/core` package handles authentication and rate limiting
- `tvly.search(query, { maxResults: 5, searchDepth: "advanced" })` — sends a search request. `maxResults: 5` limits to 5 sources. `searchDepth: "advanced"` gets full content rather than just snippets
- The response has a `results` array. Each result has `title`, `url`, and `content` (the full extracted text)
- We format each result as a markdown-like string with source number, title, and content
- If no results, we return a friendly message instead of crashing

**What Tavily returns vs what Google returns:**

Google snippet: "AI agents are autonomous systems that..."

Tavily content: "AI agents are autonomous systems that use large language models to plan and execute complex tasks. They can break down goals into sub-tasks, use tools, and adapt to new information. Unlike traditional chatbots, agents take action — they write code, search the web, call APIs, and control applications."

See the difference? Tavily gives you paragraphs, not sentences. That's what you want when feeding content to an LLM.

## Step 4: The agent loop — `route.ts`

This agent is different from the previous two. It doesn't follow a fixed plan. It decides for itself:

- "I need to understand AI agents, let me search broadly first"
- "Now let me search for specific aspects — frameworks, challenges, use cases"
- "I have enough information, here's the report"

```typescript
// app/api/agent/route.ts

import { NextRequest, NextResponse } from "next/server";
import Anthropic from "@anthropic-ai/sdk";
import { webSearch } from "./search";

const anthropic = new Anthropic({
  apiKey: process.env.ANTHROPIC_API_KEY!,
});

const searchTool = {
  name: "web_search",
  description: "Search the web for information on a topic. Returns up to 5 sources with their content. Use this to research any topic.",
  input_schema: {
    type: "object",
    properties: {
      query: {
        type: "string",
        description: "The search query. Be specific — narrower queries give better results.",
      },
    },
    required: ["query"],
  },
};

const SYSTEM_PROMPT = `You are a research agent. Your job is to research a topic thoroughly and produce a well-structured report.

Guidelines:
- Start with a broad search to get an overview
- Follow up with specific searches for details, statistics, opposing views, or recent developments
- Search at least 2-3 times to get comprehensive coverage
- Do NOT search for the exact same query twice
- When you have enough information, write a final report

The report should include:
1. A summary of the topic
2. Key findings organized by theme
3. Sources referenced`;

export async function POST(req: NextRequest) {
  const { topic } = await req.json();
  const MAX_ITERATIONS = 8;
  let iterationCount = 0;

  let response = await anthropic.messages.create({
    model: "claude-sonnet-4-20250514",
    max_tokens: 4096,
    system: SYSTEM_PROMPT,
    messages: [
      {
        role: "user",
        content: `Research this topic and give me a detailed report: ${topic}`,
      },
    ],
    tools: [searchTool],
  });

  while (iterationCount < MAX_ITERATIONS) {
    const toolUse = response.content.find((block) => block.type === "tool_use");
    if (!toolUse) break;

    let result: string;
    if (toolUse.name === "web_search") {
      result = await webSearch(toolUse.input.query as string);
    } else {
      result = `Unknown tool: ${toolUse.name}`;
    }

    iterationCount++;

    response = await anthropic.messages.create({
      model: "claude-sonnet-4-20250514",
      max_tokens: 4096,
      system: SYSTEM_PROMPT,
      messages: [
        { role: "user", content: `Research this topic and give me a detailed report: ${topic}` },
        { role: "assistant", content: response.content },
        {
          role: "user",
          content: [
            {
              type: "tool_result",
              tool_use_id: toolUse.id,
              content: result,
            },
          ],
        },
      ],
      tools: [searchTool],
    });
  }

  if (iterationCount >= MAX_ITERATIONS) {
    // Force Claude to wrap up — it exhausted its budget
    response = await anthropic.messages.create({
      model: "claude-sonnet-4-20250514",
      max_tokens: 4096,
      system: SYSTEM_PROMPT + "\n\nYou have reached the maximum number of searches. Write your final report now with the information you have.",
      messages: [
        { role: "user", content: `Research this topic and give me a detailed report: ${topic}` },
        { role: "assistant", content: response.content },
        { role: "user", content: "Write your final report now. You have enough information." },
      ],
    });
  }

  const report = response.content[0].text;
  return NextResponse.json({ report });
}
```

**Walkthrough of what makes this different:**

**The system prompt is strategic, not procedural.** In Project 2 we said "list first, then read." Here we say "start broad, then follow up" — we guide the strategy without dictating the exact steps.

**`MAX_ITERATIONS = 8` guard rail.** Without this, Claude could theoretically search forever. Eight searches is generous — most research agents will finish in 3-5. If it hits the limit, we force it to write the report with what it has.

**The forced wrap-up.** When the agent hits the iteration limit, we append "Write your final report now. You have enough information." This prevents the agent from saying "I need more data" — it has to work with what it collected.

**The report structure is in the system prompt, not the code.** We tell Claude what a good report looks like. This is better than hardcoding format logic in TypeScript because Claude is better at writing than we are at formatting.

## Step 5: The frontend — `page.tsx`

A topic input + report display. Like the weather agent's UI but with a textarea for the report.

```tsx
// app/page.tsx

"use client";

import { useState } from "react";

export default function Home() {
  const [topic, setTopic] = useState("");
  const [report, setReport] = useState("");
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState("");

  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault();
    if (!topic.trim()) return;

    setLoading(true);
    setReport("");
    setError("");

    try {
      const res = await fetch("/api/agent", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ topic }),
      });

      if (!res.ok) {
        throw new Error(`HTTP ${res.status}`);
      }

      const data = await res.json();
      setReport(data.report);
    } catch (err) {
      setError(`Research failed: ${err}`);
    } finally {
      setLoading(false);
    }
  }

  return (
    <main style={{ maxWidth: 700, margin: "50px auto", fontFamily: "sans-serif" }}>
      <h1>Research Agent</h1>
      <form onSubmit={handleSubmit}>
        <input
          type="text"
          value={topic}
          onChange={(e) => setTopic(e.target.value)}
          placeholder="e.g. Current state of AI agents"
          style={{ width: "100%", padding: 10, fontSize: 16 }}
        />
        <button type="submit" disabled={loading} style={{ marginTop: 10, padding: "10px 20px" }}>
          {loading ? "Researching..." : "Research"}
        </button>
      </form>

      {error && (
        <div style={{ marginTop: 20, padding: 15, background: "#ffe0e0", borderRadius: 8 }}>
          {error}
        </div>
      )}

      {loading && (
        <div style={{ marginTop: 20, padding: 15, background: "#fff8e0", borderRadius: 8 }}>
          Searching the web and synthesizing results. This may take 30-60 seconds...
        </div>
      )}

      {report && (
        <div style={{ marginTop: 20, padding: 15, background: "#f5f5f5", borderRadius: 8, whiteSpace: "pre-wrap", lineHeight: 1.6 }}>
          <h2>Research Report: {topic}</h2>
          {report}
        </div>
      )}
    </main>
  );
}
```

**Key points:**

- Loading state now says "30-60 seconds" because the agent might do 3-5 searches, each requiring a round trip to both Tavily and Claude
- The report renders with `whiteSpace: "pre-wrap"` and `lineHeight: 1.6` for readability
- We show the topic in the report header so the user can see what was researched

The Research Agent is the most autonomous. The user gives a goal, and the agent decides the strategy, the depth, and the output format. You're moving from "agent as function caller" to "agent as autonomous worker."

## What It Is NOT

This project is **not** a reliable fact-checking system. The agent searches the web and summarizes what it finds, but it can't distinguish between authoritative sources and random blog posts. It will happily cite incorrect information if that's what shows up in search results. It's also not real-time research — the agent works with whatever Tavily returns at that moment, which may not reflect the very latest developments. Always verify important facts independently.

## In Your Own Words

<details>
<summary>1. The Research Agent uses a `MAX_ITERATIONS` guard rail. What happens if you set it to 1? What happens if you remove it entirely? Try both.</summary>

**Sample Answer:** If you set `MAX_ITERATIONS` to 1, the agent can only do one search before being forced to write the report — it'll produce a shallow, single-source document. If you remove the guard rail entirely, the agent could theoretically search forever, racking up API costs. In practice, Claude usually stops after 3-5 searches, but there's no guarantee. The guard rail is cheap insurance against runaway behavior.

</details>

<details>
<summary>2. The system prompt says "Do NOT search for the exact same query twice." Did Claude respect this in your tests? If not, how would you enforce it in code (hint: track past queries)?</summary>

**Sample Answer:** Claude often ignores this instruction and searches the same query twice, especially when results are ambiguous. To enforce it in code, maintain a Set of past queries. Before calling `webSearch`, check if the query already exists. If it does, return a message like "You already searched for that query. Try a different angle." This is an example of why you can't rely solely on prompting — sometimes you need hard enforcement in code.

</details>

<details>
<summary>3. Tavily returns `content` (full paragraphs) vs Google's snippets. How does the quality of the final report change if you switch to a search API that only returns snippets?</summary>

**Sample Answer:** With snippets only, Claude has to fill in gaps with its own knowledge, which increases hallucination risk. A snippet might say "AI agents are..." while Tavily's full content gives specific examples, numbers, and context. The report would be shorter, less detailed, and more likely to contain made-up facts. Tools that return richer data directly improve the quality of the agent's output.

</details>

<details>
<summary>4. The forced wrap-up message appends a command to the conversation. Why do we use a separate `anthropic.messages.create` call instead of just appending to the messages array in the loop?</summary>

**Sample Answer:** The forced wrap-up is a separate API call because the loop's condition (`iterationCount < MAX_ITERATIONS`) has already failed. The loop is designed for the normal case where Claude decides to call a tool. The wrap-up is an intervention — we're overriding Claude's autonomy and telling it to stop searching and write the report. It's also simpler to read as a separate block rather than adding a special case inside the loop.

</details>

<details>
<summary>5. You've now built agents that call APIs, read files, and search the web. What's one new tool you'd add to combine all three — e.g., "summarize the latest news about AI" (search → read → store → report)?</summary>

**Sample Answer:** I'd add a `save_report` tool that stores the final report to a file. The agent would search the web for latest AI news, call `save_report` with the filename and content, then confirm to the user. This combines all three patterns: searching (Tavily), reading (it already has the search results in context), and writing files (`fs.writeFile`). The agent would decide the filename, format, and content — you'd just provide the tool.

</details>
