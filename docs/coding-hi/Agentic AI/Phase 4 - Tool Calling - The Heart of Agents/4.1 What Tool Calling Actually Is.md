In Phase 3, you learned to talk to a model. You send a message, it replies. That's a chatbot. But an agent needs to *do* things, not just talk. It needs to read files, run commands, search the web. That's where tool calling comes in.

Here's the fundamental truth you need to internalize: **a language model cannot do anything on its own.** It can only generate text. It can't open a file, make an HTTP request, or calculate a square root. All it can do is produce tokens.

So how does Cline or opencode read your files? How does it run terminal commands? Magic? No. It's a structured conversation loop, and the key is *tool calling*.

### What Tool Calling Is

Tool calling (also called "function calling") is when the model outputs a **structured instruction** instead of regular text. You define what tools exist, and the model says "I want to use this tool with these parameters." Then *your code* — not the model — actually executes the tool.

Here's what the model actually returns when it wants to read a file:

```json
{
  "tool_calls": [
    {
      "id": "call_abc123",
      "type": "function",
      "function": {
        "name": "read_file",
        "arguments": "{\"path\": \"index.js\"}"
      }
    }
  ]
}
```

That's not the model reading the file. It's the model saying: *"Hey, I'd like to use the read_file tool with path = index.js. You handle the actual reading."*

The `arguments` field is a JSON string — your code has to parse it with `JSON.parse()` before you can use the parameters.

### The Tool Calling Loop

This is the pattern that powers every agentic AI tool you've used:

1. **You**: Send the user's question + the list of available tools
2. **Model**: Responds with either text or a tool call instruction
3. **You**: If it's a tool call, execute the corresponding function
4. **You**: Send the result back to the model
5. **Model**: Continues with the new information (or calls another tool)
6. Repeat until the model responds with plain text

That's it. That's the entire loop. Cline, opencode, every AI coding tool works exactly like this.

### When the Model Calls a Tool, It Doesn't *Do* Anything

This is the most important mental model shift. Say you ask an agent: "Read my package.json and tell me what dependencies I have."

- The model outputs: `{ "tool_calls": [{ "function": { "name": "read_file", "arguments": "{\"path\": \"package.json\"}" } }] }`
- *Your code* opens `package.json` and reads the contents
- *Your code* sends the file contents back to the model
- The model reads those contents and says: "You have express, lodash, and axios."

The model never touched your filesystem. It just told you exactly what it needed, and you acted as its hands. *You are the model's operating system.*

### Why This Matters

Once you understand this, you understand how every AI agent works under the hood. Whether it's Cline or opencode editing files, a customer support bot querying a database, or a coding agent running tests — it's all the same loop:

**Model says what it wants → You execute it → Model gets the result → Model decides what to do next**

In Phase 2, we talked about the agent loop conceptually. Now you're going to build it.

But for the model to know what tools exist, you need to define them first. That's exactly what 4.2 covers.

## What It Is NOT

Tool calling does **not** mean the model runs code on your machine. The model never touches your filesystem, never executes a function, never makes an HTTP request. It only outputs structured JSON — a description of what it *wants* done. Your application reads that JSON and does the actual work. Think of it like a recipe: the model writes down the ingredients and steps (JSON), but you're the chef who actually cooks (executes).

<summary>5. How is this different from a regular chatbot conversation?</summary>

**Sample Answer:** A regular chatbot is a one-and-done: you ask, it answers. Tool calling is a multi-round loop where the model can request information, act on it, and refine its answer. A chatbot reads its training data and guesses. An agent with tools can look up live data, run calculations, and do real work. It's the difference between asking a friend what they *remember* about a topic versus asking them to go to the library, look it up, and come back with the answer.
