# 3.2 Hello World — Your First API Call

You've got your project set up, your API key in a `.env` file, and the SDK installed. Now let's make the model talk.

Replace the contents of `index.js` with this:

```javascript
import Groq from "groq-sdk";
import dotenv from "dotenv";
dotenv.config();

const client = new Groq({ apiKey: process.env.GROQ_API_KEY });

const completion = await client.chat.completions.create({
  model: "llama-3.3-70b-versatile",
  messages: [
    { role: "user", content: "Say hello in 10 words." }
  ],
});

console.log(completion.choices[0].message.content);
```

Run it:

```bash
node index.js
```

You should see something like:

```
Hello! I'm Llama, ready to help you learn.
```

You just made your first AI API call. Let's break down every single line.

## Line by Line

```javascript
import Groq from "groq-sdk";
import dotenv from "dotenv";
```

These import the SDK and the dotenv package. The `from` paths match the package names you installed with npm. Node.js knows to look in `node_modules` for them.

```javascript
dotenv.config();
```

This reads your `.env` file and populates `process.env` with its contents. After this line runs, `process.env.GROQ_API_KEY` is available.

```javascript
const client = new Groq({ apiKey: process.env.GROQ_API_KEY });
```

This creates a **client** object — an authenticated handle to the Groq API. The `apiKey` option is your secret key pulled from the environment. The client will attach this key to every request it makes. You create the client once and reuse it for all your calls.

```javascript
const completion = await client.chat.completions.create({ ... });
```

This is the actual API call. `client.chat.completions.create()` is an async function — it sends a POST request to Groq's servers and waits for the response. The `await` keyword pauses execution until the server responds. Inside the object we pass the parameters:

- **`model`**: The model identifier. `"llama-3.3-70b-versatile"` is a Llama 3 model running on Groq's fast inference hardware. Different models have different capabilities, speeds, and costs. You can find the full list in the Groq docs.
- **`messages`**: An array of conversation turns. Each turn has a `role` (who said it) and `content` (what they said). Right now there's just one message from the user.

```javascript
console.log(completion.choices[0].message.content);
```

The response comes back as an object. `completion.choices` is an array of choices (usually one). Each choice has a `message` with a `content` property containing the model's text. We access it and print it.

## The Full Response Object

When you log `completion` instead of just `completion.choices[0].message.content`, you'll see something like this:

```javascript
{
  id: "chatcmpl-abc123def456",
  object: "chat.completion",
  model: "llama-3.3-70b-versatile",
  choices: [
    {
      index: 0,
      message: {
        role: "assistant",
        content: "Hello! I'm Llama, ready to help you learn."
      },
      finish_reason: "stop"
    }
  ],
  usage: {
    prompt_tokens: 14,
    completion_tokens: 10,
    total_tokens: 24
  }
}
```

This is the raw response. Let's look at each field:

- **`id`**: A unique identifier for this completion. Useful for debugging and tracking.
- **`object`**: Always `"chat.completion"` for this endpoint.
- **`model`**: Which model generated the response. Confirms your request used the right model.
- **`choices`**: An array of response choices (usually one). Each choice has:
  - **`index`**: The position of this choice (0 for the first/only one).
  - **`message`**: The response message, with `role` (`"assistant"`) and `content` (the text).
  - **`finish_reason`**: Why the model stopped generating. `"stop"` means it finished naturally. Other values are `"length"` (hit the max token limit) or `"tool_calls"` (wants to call a tool, coming in Phase 4).
- **`usage`**: Token counts. `prompt_tokens` is how many tokens your prompt consumed. `completion_tokens` is what the model generated. This is how you get billed — by the token.

## Why This Matters

Every AI coding tool — Cline, Kodu, opencode, cursor — makes calls like this under the hood. The difference is they do it over and over, in loops, with tool results fed back in. But the fundamental building block is always the same: you send messages, you get a response.

The magic is gone. You're just passing JSON back and forth.

Now let's zoom in on one important part of that call — the messages array.

---

## What It Is NOT

Your API key is NOT a user account password, even though it looks like one (long random string). A password proves you're a specific human. An API key proves a specific application is authorized to use a service. There's no "forgot your key?" flow — if you lose it, you revoke it in the console and generate a new one. Treat it with the same care as a password, but understand it's a machine credential, not a human one.

### In Your Own Words

<details>
<summary>1. What would happen if you removed the `await` keyword? Try it.</summary>

**Sample Answer:** Without `await`, `client.chat.completions.create()` returns a Promise object immediately instead of waiting for the API response. Your `console.log(completion.choices[0].message.content)` would try to access `.choices` on a Promise, which doesn't exist yet — you'd get `undefined` or a crash. It's like trying to eat a meal while the chef is still cooking it.

</details>

<details>
<summary>2. Why is `completion.choices` an array instead of just a single message object?</summary>

**Sample Answer:** The `choices` array allows multiple response candidates in a single API call (useful for advanced use cases like n-shot sampling). In most agent applications you'll only use `choices[0]`. For tool calling, the model can also include a `tool_calls` field inside the message object — we'll cover that in Phase 4.

</details>

<details>
<summary>3. If you set `max_tokens: 5` and asked the model to write a paragraph, what would `finish_reason` be?</summary>

**Sample Answer:** It would be `"length"` because the model hit your artificial limit before it finished its thought. The response would be cut off mid-sentence — maybe just 5 tokens (roughly 4 words). You'd need to either increase `max_tokens` or make your prompt more specific to get a complete answer.

</details>

<details>
<summary>4. The `usage` object shows 14 prompt tokens for "Say hello in 10 words." How many tokens does your own name use? (You can estimate by counting characters and dividing by ~4, or check an online tokenizer.)</summary>

**Sample Answer:** A name like "Alexander" (9 characters) would be roughly 2-4 tokens, since roughly 3/4 of a character maps to one token on average. Common names are often single tokens because the model's tokenizer recognizes them as common words. Shorter names like "Joe" might be 1 token, while longer ones like "Christopher" could be 2-3.

</details>

<details>
<summary>5. In the response object, the message role is inside `choices[0].message.role`. Why is the role nested there instead of at the top level?</summary>

**Sample Answer:** The `choices` array can hold multiple response candidates, so each one has its own `message` with its own `role`. The `role` inside each message identifies who generated that content (always `"assistant"`). Top-level fields like `id` and `model` apply to the whole response, while everything specific to a particular completion lives inside its `choices` entry.

</details>
