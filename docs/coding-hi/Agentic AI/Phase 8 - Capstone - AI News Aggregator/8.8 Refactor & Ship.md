## Error Handling — Asli System Ki Pehchan

Ek system tabhi production-grade hai jab wo **fail hona** handle karta hai. Kya ho sakta hai? Source down, Groq rate-limit, DB timeout.

### Scrapers Mein — Per-Source try/catch

Agar ek source down hai, poora pipeline nahi rukna chahiye — baaki sources kaam karein:

```javascript
// scrapers/index.js
async function scrapeAll() {
  const sources = [
    youtube.fetchNewItems,
    anthropic.fetchNewItems,
    openai.fetchNewItems,
  ];

  const results = [];
  for (const fetchFn of sources) {
    try {
      const items = await fetchFn();
      results.push(...items);
    } catch (err) {
      // source fail hua, log karo, aage badho
      console.error(`Source failed: ${err.message}`);
    }
  }
  return results;
}
```

> **Key:** Ek source fail = log + continue. Poora pipeline ek source ke wajah se fail nahi hona chahiye.

### LLM Rate-Limit Handling

Groq rate-limit karega toh error aayega. Retry logic add karo:

```javascript
// agents/aggregator.js
async function scoreArticle(article, retries = 3) {
  for (let attempt = 1; attempt <= retries; attempt++) {
    try {
      const response = await client.chat.completions.create({...});
      return JSON.parse(response.choices[0].message.tool_calls[0].function.arguments);
    } catch (err) {
      console.error(`Attempt ${attempt} failed: ${err.message}`);
      if (attempt === retries) throw err;   // last attempt — rethrow
      await new Promise((r) => setTimeout(r, 5000 * attempt));  // backoff
    }
  }
}
```

- `retries = 3` — 3 baar try
- `setTimeout(r, 5000 * attempt)` — exponential backoff (5s, 10s, 15s)
- Last attempt pe rethrow — sab fail hua toh caller handle kare

### Retry Wrapper (Reusable)

```javascript
// lib/retry.js
async function withRetry(fn, retries = 3, delayMs = 5000) {
  for (let attempt = 1; attempt <= retries; attempt++) {
    try {
      return await fn();
    } catch (err) {
      if (attempt === retries) throw err;
      console.error(`Retry ${attempt}/${retries}: ${err.message}`);
      await new Promise((r) => setTimeout(r, delayMs * attempt));
    }
  }
}

module.exports = { withRetry };
```

Agar tumhe chaho toh ise har jagah use kar sakte ho.

## Common Mistakes

- ❌ Refactor ke baad test na karna — structure badla, koi import toota toh sab fail. Har change ke baad `node index.js`.
- ❌ Har file mein naya Pool banana — connection leak. Ek `db/index.js` mein Pool, sab import karo.
- ❌ Error handling sirf main file mein — har layer (scrapers, agents) mein fail handling chahiye.
- ❌ README nahi banana — tumhara code khud nahi bolta ki kya hai. README hi pehla impression hai.
- ❌ `digests/` folder ko `.gitignore` mein daalna (agar chaho toh) — local output files ko commit karne ki zaroorat nahi.

## What It Is NOT

⚠️ **Refactor = "code rewrite" nahi.** Sirf structure/quality improve — functionality same. Requirements badalne par naya code likhna refactor nahi, feature hai.

⚠️ **Error handling = "har jagah try/catch daalna" nahi.** Intentional — kahan log karna, kahan retry, kahan rethrow. Over-catching bhi problem hai (errors chup jate hain).

⚠️ **README = "koi bhi likh do" nahi.** Acha README bataata hai: kya, kaise, tech stack, setup, deployment. Yeh document hai, filler nahi.

⚠️ **Ship = "push kar diya" nahi.** Ship = tested, documented, deployed, monitored. Manual run green + workflow green dono confirm karo.
