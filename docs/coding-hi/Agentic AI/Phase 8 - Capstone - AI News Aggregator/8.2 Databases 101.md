## Database Kya Hai — Ghar Wali Example

Ek **database** ek structured storage hai jahan data tables mein rehta hai. Socho ek **excel spreadsheet** jisme alag-alag sheets hain — ek sheet "Articles", ek "Digests". Har sheet ke columns hain (title, url, date) aur rows (actual articles). Postgres wahi hai, par **production-grade** — internet pe, hazaron users, secure, fast.

**Supabase** = Postgres ka free hosted version, **visual table editor** ke saath. Browser mein khol ke tables bana sakte ho, rows dekh sakte ho — literally watch kar sakte ho ki scrape hone pe rows aati hain. Naye backend seekhne wale ke liye yeh god-send hai.

- **Rows** = har article ek row

## Hamari Schema — `articles` Table

Supabase dashboard mein SQL editor kholo (ya PostgreSQL client se) aur yeh run karo:

```sql
CREATE TABLE articles (
  id SERIAL PRIMARY KEY,
  source TEXT NOT NULL,
  title TEXT NOT NULL,
  url TEXT UNIQUE NOT NULL,
  published_at TIMESTAMP,
  raw_content TEXT,
  score INT,
  reason TEXT,
  ranked BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE digests (
  id SERIAL PRIMARY KEY,
  content TEXT NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);
```

## Har Column Samjho

```sql
id SERIAL PRIMARY KEY
```
- `SERIAL` = auto-incrementing number — har nayi row ko 1, 2, 3... milta hai. Tum nahi bhejte, database khud deta hai
- `PRIMARY KEY` = unique identifier — har row ki pehchan

```sql
source TEXT NOT NULL
```
- `TEXT` = string type
- `NOT NULL` = ye column khali nahi ho sakta (har article ka koi source toh hoga)

```sql
url TEXT UNIQUE NOT NULL
```
- `UNIQUE` = **ye humara dedup mechanism hai** — do articles ka url same nahi ho sakta
- Iska matlab jab insert karte time duplicate url aayega, database mana kar dega (ya silently ignore — `ON CONFLICT` se)

```sql
score INT, reason TEXT
```
- `score` = Aggregator Agent ka 1-10 rating (int)
- `reason` = ek line mein kyun (text)

```sql
ranked BOOLEAN DEFAULT FALSE
```
- `BOOLEAN` = true/false
- `DEFAULT FALSE` = jab nayi row aaye, by default `ranked = false` — matlab "abhi rank nahi hua"
- Aggregator Agent jis row ko process karega, use `ranked = true` karega — taaki agli baar pata rahe kaunse new hain

```sql
created_at TIMESTAMP DEFAULT NOW()
```
- `TIMESTAMP` = date + time
- `DEFAULT NOW()` = insert karte waqt khud current time daal do

## INSERT — Data Daalna

```sql
INSERT INTO articles (source, title, url, published_at, raw_content)
VALUES (
  'youtube',
  'MCP Explained',
  'https://www.youtube.com/watch?v=abc123',
  NOW(),
  'Transcript snippet here...'
);
```

Notice kiya — `id`, `ranked`, `created_at` bheje hi nahi — database khud bharta hai (SERIAL, DEFAULT FALSE, DEFAULT NOW()).

## Dedup — `ON CONFLICT DO NOTHING`

Yahi capstone ka asli magic hai. Agar wo youtube video **kal bhi scrape** hui thi, toh aaj dobara insert mat karo:

```sql
INSERT INTO articles (source, title, url, published_at, raw_content)
VALUES ('youtube', 'MCP Explained', 'https://.../abc123', NOW(), '...')
ON CONFLICT (url) DO NOTHING;
```

- `ON CONFLICT (url)` = jab url unique constraint pe conflict ho (pehle se same url hai)
- `DO NOTHING` = silently skip karo, error mat do

Isliye `url TEXT UNIQUE NOT NULL` rakha tha — **yahi dedup ka mechanism hai.** Har scrape se pehle pura database check karna nahi padta — database khud conflict handle karta hai.

## SELECT — Data Padhna

```sql
-- Saare articles
SELECT * FROM articles;

-- Sirf naye (rank nahi hue) articles
SELECT * FROM articles WHERE ranked = false;

-- Top 5 highest score waale
SELECT * FROM articles WHERE ranked = true ORDER BY score DESC LIMIT 5;
```

Ye queries Aggregator aur Digest agents mein use hongi.

## ORM vs Raw SQL — Manual → Better

Ab jab tak raw SQL samajh aa gaya, ek **better** option hai — **ORM** (Object-Relational Mapping). Prisma/Drizzle jaise tools se tum SQL likhne ki jagah JavaScript object se kaam karte ho:

```javascript
// Raw SQL (pg)
await client.query('INSERT INTO articles (source, title, url) VALUES ($1, $2, $3)');

// Drizzle ORM
await db.insert(articlesTable).values({ source, title, url });
```

- **Manual (`pg` + raw SQL):** Seedha SQL, poora control, concepts clear
- **Better (Drizzle):** TypeScript types, less boilerplate, safer

Hum is capstone mein **`pg` + raw SQL** use karenge — kyunki pehle concepts seedha samajh aayein. Baad mein ORM pe switch karna aasaan hai.

## Common Mistakes

- ❌ `UNIQUE` constraint bhoolna — dedup kabhi kaam nahi karega, duplicate articles insert honge
- ❌ `ON CONFLICT (url)` mein galat column likhna — conflict sirf unique columns pe hote hain
- ❌ `NOT NULL` fields bheje bina insert karna — error aayega
- ❌ `ranked` ko manually track karna — schema mein `BOOLEAN DEFAULT FALSE` hi sahi mechanism hai
- ❌ Database credentials code mein daalna — `.env` se `DATABASE_URL` hi use karo

2. `ranked BOOLEAN DEFAULT FALSE` kya karta hai?

<summary>Sample Jawab</summary>

**Jawab:** Har nayi article by default `ranked = false` hoti hai — matlab "abhi Aggregator ne rank nahi kiya." Aggregator process karne ke baad `ranked = true` karta hai. Isi se "kaunsi nayi hain" pata chalta hai (`WHERE ranked = false`).

</details>

3. `SERIAL PRIMARY KEY` aur `DEFAULT NOW()` ka kya matlab hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `SERIAL` auto-incrementing number hai (har row ko 1, 2, 3...) aur `PRIMARY KEY` unique identifier. `DEFAULT NOW()` created_at mein insert karte waqt khud current timestamp daal deta hai. Dono insert mein bhejne ki zaroorat nahi.

</details>

4. Raw SQL aur ORM mein kya fark hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Raw SQL (`pg`) mein seedha SQL queries likhte ho — poora control, concepts clear. ORM (Drizzle/Prisma) mein JS objects se kaam hota hai — `db.insert(...).values({...})`, TypeScript types, less boilerplate. Hum pehle raw se samjhenge, phir better pe switch.

</details>

## What It Is NOT

⚠️ **Database = "sirf storage" nahi, wo ek model hai.** Schema design (kaunse columns, kya constraints) hi system ko sahi banata hai. `UNIQUE` ya `ranked` jaisi cheezein logic hain, sirf storage nahi.

⚠️ **Postgres = SQLite nahi.** SQLite ek file-based chhota DB hai, Postgres ek full server-based production DB hai. Hum Postgres (Supabase) use karte hain.

⚠️ **`ON CONFLICT DO NOTHING` = silent failure nahi.** Ye intentional dedup hai. Error nahi deta kyunki tumne explicitly bola "agar conflict ho, ignore karo."

⚠️ **ORM = SQL seekhne ki zaroorat nahi = NAHI.** ORM ke andar bhi SQL concepts hain (tables, relations). Raw SQL pehle samjho, phir ORM use karo.
