8.3 mein scraping pipeline ban gayi — RSS feeds se normalized items aate hain. Par ab problem — **scraped items abhi memory mein hain, kahin save nahi hue.** Kal jab system dobara chalega, ye items firse aayenge — kyunki system ko yaad hi nahi ki ye pehle dekh chuka hai. Database integration isi problem ko solve karta hai: items ko `articles` table mein store karo, taaki system ko yaad rahe.

## Kya Karna Hai

1. Supabase (`DATABASE_URL`) se connect karo
2. Scraped items ko `articles` table mein insert karo
3. Dedup — jo url pehle se hai, skip (8.2 ka `ON CONFLICT DO NOTHING`)
4. Future ke liye — "unranked" articles ko query karo (Aggregator ke liye)

## Connect to Supabase

Ek `db.js` file banate hain — database connection yahan ek jagah rehta hai:

```javascript
// db.js
require('dotenv').config();
const { Pool } = require('pg');

const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
});

module.exports = pool;
```

**`pg` Pool kya hai?** Postgres connections ka group. Har query pe naya connection banane ki jagah pool se lete ho — fast aur reliable. `connectionString` `.env` se aati hai — code mein kabhi hardcode nahi.

## Insert Scraped Items — Dedup Ke Saath

Ab scraping + DB ko jodte hain. Ek function jo items ko insert karta hai:

```javascript
// db/insertArticles.js
const pool = require('../db');

async function insertArticles(items) {
  for (const item of items) {
    await pool.query(
      `INSERT INTO articles (source, title, url, published_at, raw_content)
       VALUES ($1, $2, $3, $4, $5)
       ON CONFLICT (url) DO NOTHING`,
      [item.source, item.title, item.url, item.published_at, item.raw_content]
    );
  }
  console.log(`Inserted/checked ${items.length} items`);
}

module.exports = { insertArticles };
```

**Samjho:**
- `$1, $2...` — **parameterized queries** — value ko seedha string mein concatenate nahi karte. Ye SQL injection se bachata hai (security!)
- `ON CONFLICT (url) DO NOTHING` — agar url pehle se exist karta hai, silently skip
- `pool.query()` — async, Promise return karta hai

> **Security note:** `INSERT ... VALUES ('$' + item.title)` jaisa kuch kabhi mat likhna — parameterized queries (`$1`) hi use karo. Ye SQL injection ka standard fix hai.

## Count Check — Kitne Naye Aaye?

Insert ke baad pata hona chahiye ki kitne naye insert hue (conflict wale skip). Ek better version:

```javascript
// db/insertArticles.js
async function insertArticles(items) {
  let inserted = 0;
  for (const item of items) {
    const result = await pool.query(
      `INSERT INTO articles (source, title, url, published_at, raw_content)
       VALUES ($1, $2, $3, $4, $5)
       ON CONFLICT (url) DO NOTHING
       RETURNING id`,
      [item.source, item.title, item.url, item.published_at, item.raw_content]
    );
    if (result.rowCount > 0) inserted++;
  }
  console.log(`New: ${inserted}, duplicate/skipped: ${items.length - inserted}`);
  return inserted;
}
```

`RETURNING id` — insert hone pe row ka id return karta hai. `rowCount > 0` matlab insert hua (conflict nahi hua). Isse pata chalta hai kitne naye aaye.

## Main Pipeline — Sab Jodna

Ab scrape + insert ko ek `index.js` mein jodte hain:

```javascript
// index.js
require('dotenv').config();
const { scrapeAll } = require('./scrapers');
const { insertArticles } = require('./db/insertArticles');

async function main() {
  console.log('Step 1: Scraping...');
  const items = await scrapeAll();

  console.log('Step 2: Inserting into database...');
  const inserted = await insertArticles(items);

  console.log(`Done. ${inserted} new articles saved.`);
  process.exit(0);
}

main().catch((err) => {
  console.error('Pipeline failed:', err);
  process.exit(1);
});
```

Run karo:

```bash
node index.js
```

Output:

```
Step 1: Scraping...
Step 2: Inserting into database...
New: 17, duplicate/skipped: 10
Done. 17 new articles saved.
```

Ab **Supabase dashboard** kholo → Table Editor → `articles` — 17 naye rows dikhengi. Literally watch kar sakte ho ki data store ho raha hai. **Dobara chalao** — ab 0 naye insert honge (sab duplicate), kyunki urls pehle se hain. Yeh dedup live mein kaam kar raha hai.

## Query Unranked Articles — Aggregator Ke Liye

Aggregator Agent (8.5) ke liye sirf naye, unranked articles chahiye:

```javascript
// db/getUnranked.js
const pool = require('../db');

async function getUnranked() {
  const result = await pool.query(
    `SELECT * FROM articles WHERE ranked = false`
  );
  return result.rows;
}

module.exports = { getUnranked };
```

Ye queries Aage Agents mein use hongi. Abhi bas concept pakdo — `WHERE ranked = false` se sirf naye milte hain.

## Common Mistakes

- ❌ Values ko `$1` parameterize ki jagah string concatenate karna — **SQL injection risk**. Hamesha parameterized.
- ❌ Har query ke liye naya `Pool` banana — ek Pool banao, har jagah import karo. `pool.end()` process exit pe.
- ❌ `process.exit(0)` bhoolna — Node app pool connection ke saath hang ho sakta hai. Script khatam hone pe exit karo.
- ❌ `ON CONFLICT` bhoolna — dedup kabhi kaam nahi karega, duplicate rows bharte rahenge.
- ❌ `rowCount` check na karna — pata nahi chalega kitne actually naye the.

## What It Is NOT

⚠️ **Dedup = "har baar poora DB check" nahi.** `UNIQUE` constraint + `ON CONFLICT` se database khud handle karta hai — tumhe pehle SELECT karke check nahi karna.

⚠️ **`pg` = "database ki tarah lagta hai but sirf client" nahi.** `pg` ek client library hai — database khud Supabase pe rehta hai. Tumhare code mein `pg` se usse connect karte ho.

⚠️ **SQL injection = "sirf tutorials ki cheez" nahi.** Real attack hai. Parameterized queries hamesha use karo — 8.4 se habit banao.

⚠️ **`process.exit(1)` error pe = crash nahi, correct hai.** Script failure ko non-zero exit code se signal karti hai — isse scheduling (8.7) ko pata chalta hai ki kuch galat hua.
