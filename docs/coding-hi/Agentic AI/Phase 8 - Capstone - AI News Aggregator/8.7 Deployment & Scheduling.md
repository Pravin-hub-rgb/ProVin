## Deployment Kya Hai — Code Ko Internet Pe Live Karna

**Deployment** = apna code apne laptop se nikaal kar ek **cloud server** pe daalna jahan 24/7 chalta hai. Socho tumhara laptop band hua toh system ruk jata hai. Cloud pe wo hamesha available rahega.

## Scheduling — Sabse Important Decision

System ko **roz 7am pe** chalna hai. Options:

| Option | Kaise | Pros | Cons |
|---|---|---|---|
| Render ka own cron | Render dashboard se schedule | Ek jagah sab | **Free tier sleeps** — reliable nahi |
| **GitHub Actions cron** (hum yeh) | `.github/workflows/` mein YAML workflow | 100% free, reliable, secrets built-in | Code Render pe bhi hona chahiye? |

**Hum GitHub Actions choose karte hain** kyunki:
- Render ka free tier machine ko **sleep** karta hai — schedule miss ho sakta hai
- GitHub Actions ki scheduled workflows (cron) **hamesha reliable** chalti hain
- Secrets (`GROQ_API_KEY`, `DATABASE_URL`) GitHub Actions mein built-in hai

## Step 1 — Code Ko GitHub Push Karna

Agar pehle se GitHub repo nahi hai:

```bash
git init
git add .
git commit -m "AI News Aggregator capstone"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/ai-news-aggregator.git
git push -u origin main
```

**Critical:** `.gitignore` mein `.env` aur `node_modules` hona chahiye (8.1 mein banaya tha) — verify karo ki `.env` push nahi hua:

```bash
git ls-files | grep ".env"   # kuch nahi dikhna chahiye
```

## Step 2 — GitHub Actions Workflow Banao

`.github/workflows/daily-digest.yml` file banao:

```yaml
# .github/workflows/daily-digest.yml
name: Daily AI Digest

on:
  schedule:
    - cron: "0 7 * * *"   # roz 7:00 AM UTC
  workflow_dispatch: {}   # manual trigger bhi allowed

jobs:
  run-pipeline:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install dependencies
        run: npm install

      - name: Run pipeline
        env:
          GROQ_API_KEY: ${{ secrets.GROQ_API_KEY }}
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
        run: node index.js
```

**Samjho workflow:**
- `on: schedule: cron: "0 7 * * *"` — roz 7:00 AM UTC pe trigger
- `cron: "0 7 * * *"` format: `minute hour day month weekday` → 0 minute, 7 hour, * = har din
- `workflow_dispatch` — GitHub UI se manually bhi chala sakte ho (testing ke liye)
- `runs-on: ubuntu-latest` — GitHub ki free Linux machine
- Steps: code lao → Node setup → deps install → `node index.js` (poore pipeline)
- `env:` — secrets ko environment variables mein map kiya

## Step 3 — Secrets Set Karna (GitHub)

Ab `GROQ_API_KEY` aur `DATABASE_URL` ko GitHub Actions secrets mein daalo:

1. GitHub repo kholo
2. **Settings → Secrets and variables → Actions**
3. **New repository secret** banao:
   - Name: `GROQ_API_KEY`, Value: tumhari key
   - Name: `DATABASE_URL`, Value: tumhari connection string

Ye secrets ab code mein nahi, **GitHub ke secure vault** mein hain — workflow mein `${{ secrets.GROQ_API_KEY }}` se milte hain.

> **Why secrets here:** `.env` local machine ke liye hai. Cloud (GitHub Actions) pe secrets GitHub ke encrypted storage mein rakhe jaate hain. Kabhi YAML mein hardcode mat karo.

## Step 4 — Test Karo (Manually Pehle)

Cron ke trigger hone se pehle, workflow ko **manually** chalao:

1. GitHub repo → **Actions** tab
2. "Daily AI Digest" workflow → **Run workflow** button
3. Run hone do — logs dekhoge: "Step 1: Scraping...", "Step 2: Aggregating...", "Step 3: Digesting...", "Done!"

Agar green tick aaya — system kaam kar raha hai cloud pe.

## Step 5 — Verify Scheduling

Cron test karna impossible hai (7am pe aana hoga). Par confirm kar sakte ho:

- Workflow file correct syntax hai
- Manual run green hai
- **GitHub Actions tab mein** schedule ka plan visible hai (Actions → workflow → schedule tab)

Aur ek smart move — **pehle 2-3 manual runs** karo alag-alag din, taaki system consistency check ho jaye.

## Bonus — Render Pe Web Service (Optional)

Agar digest ko **web pe share** karna hai (URL se access), Render pe deploy karo:

1. Render dashboard → **New → Web Service**
2. GitHub repo connect karo
3. Environment variables (`GROQ_API_KEY`, `DATABASE_URL`) Render dashboard mein set karo
4. Build: `npm install`, Start: `node index.js`
5. Render har deploy pe pipeline chalayega

**Note:** Render web service requests pe chalta hai — hume cron ke liye GitHub Actions chahiye. Web service optional hai (agar tumhe HTTP endpoint chahiye).

## Common Mistakes

- ❌ `.env` push karna — GitHub Actions logs mein secrets **encrypted** rehte hain, par `.env` file seedha repo mein hui toh public. `.gitignore` verify karo.
- ❌ Cron syntax galat — `"0 7 * * *"` is `minute hour day month weekday`. Test `crontab.guru` pe kar sakte ho.
- ❌ Secrets ko YAML mein hardcode karna — `${{ secrets.NAME }}` hi use karo, kabhi literal value nahi.
- ❌ Workflow test kiye bina schedule pe rely karna — pehle `workflow_dispatch` se manual run karke verify karo.
- ❌ Node version mismatch — local aur GitHub dono pe same Node (20) setup karo.

## What It Is NOT

⚠️ **Deployment = "code upload" nahi, ek lifecycle hai.** Code GitHub → workflow build → secrets inject → cloud run → schedule. Har piece important hai.

⚠️ **Cron = "exact second pe chalega" guarantee nahi.** GitHub Actions cron ~minute-level accuracy deta hai. Daily digest ke liye perfect, real-time ke liye nahi.

⚠️ **Render = GitHub Actions ka replacement nahi.** Hum dono use karte hain — GitHub Actions scheduling ke liye, Render (optional) web exposure ke liye. Alag jobs.

⚠️ **Secrets = "code mein hidden" nahi.** Wo encrypted storage mein hain — runtime pe environment variables ke roop mein inject hote hain. Kabhi logs mein print nahi karne chahiye.
