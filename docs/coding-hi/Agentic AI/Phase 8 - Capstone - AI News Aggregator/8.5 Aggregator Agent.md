8.4 mein data database mein store hone laga. Ab asli AI ka kaam shuru — jo articles scrape hui hain, unme se kaunsi **tumhare liye relevant** hain? 100 articles mein se 5-6 aisi hogi jo tumhare interests se match karti hain (agentic AI, tool calling, MCP). Inko dhundhna hai — manually nahi, **ek agent se**.

## Aggregator Agent Kya Karta Hai

Har unranked article ko dekhta hai, aur tumhare profile ke hisaab se **1-10 ka score** deta hai + ek line mein reason.

```
Input:  unranked articles (WHERE ranked = false)
Agent:  "yeh article mere profile se kitna match karta hai?"
Output: score (1-10) + reason, aur ranked = true
```

**Profile example:** "interested in agentic AI, tool calling, MCP, multi-agent systems"

## Phase 4 Ka Pattern — Tool Calling

8.1 mein kaha tha — ye capstone Phase 4 ke tool-calling pattern ko **directly reuse** karta hai. Yaad karo Phase 4.2 (Defining Tools) aur 4.5 (Tool Calling Loop):

- Agent ko ek **tool** dete hain — `score_article`
- Agent free-text mein score nahi likhta — **tool call** karta hai
- Isse output structured hota hai → database mein store karna easy

Tool ka concept:

```
Tool: score_article
Arguments: { score: number (1-10), reason: string }
```

Free-text output ki jagah structured tool call — matlab score aur reason guaranteed structured format mein aayenge. Isi ko bolte hain "tool-calling pattern".

## Score Single Article — The Agent Loop

Yahan Phase 4 ka loop ka actual hai:

```javascript
const tools = [
  {
    type: 'function',
    function: {
      name: 'score_article',
      description: 'Score an article by relevance to my profile',
      parameters: {
        type: 'object',
        properties: {
          score: { type: 'integer', description: '1-10 relevance score' },
          reason: { type: 'string', description: 'One line why' },
        },
        required: ['score', 'reason'],
      },
    },
  },
];

async function scoreArticle(article) {
  const response = await client.chat.completions.create({
    model: 'llama-3.3-70b-versatile',
    messages: [
      { role: 'system', content: SYSTEM_PROMPT },
      {
        role: 'user',
        content: `Article title: ${article.title}\nContent: ${article.raw_content}`,
      },
    ],
    tools,
    tool_choice: 'required',  // agent KO tool call karna hi hai
  });

  const toolCall = response.choices[0].message.tool_calls[0];
  const args = JSON.parse(toolCall.function.arguments);
  return args;  // { score: 8, reason: "MCP directly relevant" }
}
```

**Samjho tool loop:**
1. User message mein article bheja (title + content)
2. `tools` — agent ko score_article tool diya
3. `tool_choice: 'required'` — agent ko **compel** kiya tool call kare (free-text nahi)
4. Response mein `tool_calls[0]` — agent ka structured tool call
5. `JSON.parse(function.arguments)` — `{ score, reason }` nikala

Phase 4 ka loop remember karo — Think (agent sochta hai) → Act (tool call) → Observe (hum result lete hain). Yahan simplified — sirf ek tool call (no multi-step loop) kyunki har article independent.

## DB Update — Ranked True Karo

```javascript
const pool = require('../db');

async function updateScore(articleId, score, reason) {
  await pool.query(
    `UPDATE articles
     SET score = $1, reason = $2, ranked = true
     WHERE id = $3`,
    [score, reason, articleId]
  );
}
```

Ab `processArticles` mein jodte hain:

```javascript
const { updateScore } = require('../db/updateScore');

async function processArticles() {
  const articles = await getUnranked();
  for (const article of articles) {
    try {
      const result = await scoreArticle(article);
      await updateScore(article.id, result.score, result.reason);
      console.log(`[${result.score}] ${article.title}`);
    } catch (err) {
      console.error(`Failed for ${article.title}:`, err.message);
    }
  }
}

if (require.main === module) {
  processArticles().then(() => process.exit(0)).catch((e) => {
    console.error(e);
    process.exit(1);
  });
}
```

## Common Mistakes

- ❌ `tool_choice: 'required'` bhoolna — agent free-text return karega, structured nahi milega
- ❌ `JSON.parse(function.arguments)` bina try/catch — malformed JSON pe crash. Error handling zaroori.
- ❌ Saare articles ko bina rate limit sochke bhejna — Groq free tier ~30 req/min. Loop mein bhi fine hai (12 articles), par bade scale pe delay add karo.
- ❌ `ranked = true` update bhoolna — agli baar wahi articles dobara rank honge
- ❌ DB update aur score same try/catch mein — agar update fail hua, score kaam karega par DB mein nahi jaayega. Log karo.

## In Your Own Words

1. Aggregator Agent ka kya kaam hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Har unranked article ko tumhare profile ke hisaab se 1-10 score karta hai + ek line reason deta hai. Phir score/reason DB mein save karke `ranked = true` karta hai — taaki agli baar dobara process na ho.

</details>

2. `score_article` tool kya hai aur `tool_choice: 'required'` kyun?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Ek tool definition jo agent ko structured output (score 1-10 + reason) ke liye compel karta hai. `tool_choice: 'required'` se agent free-text ke bajaye tool call hi karta hai — output guaranteed structured, store karna easy.

</details>

3. `JSON.parse(toolCall.function.arguments)` kya karta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Agent ka tool call response mein arguments ek JSON string mein aate hain (`'{"score": 8, "reason": "..."}'`). `JSON.parse` use ek JavaScript object mein convert karta hai — `result.score`, `result.reason` access karne ke liye.

</details>

4. `ranked = true` update kyun zaroori hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Taaki agli baar `WHERE ranked = false` se sirf naye articles hi aayein. Agar update bhool gaye, har run pe wahi articles dobara score honge — duplicate kaam + waste LLM calls.

</details>

## What It Is NOT

⚠️ **Aggregator = "poore internet ka summary" nahi.** Yeh sirf scrape hue items ko rank karta hai (jo 8.3 mein aaye). Khud search nahi karta.

⚠️ **Score = "model ki ground truth" nahi.** Score agent ki profile-matching judgment hai — ek educated guess. Profile customize karke score behavior badal sakte ho.

⚠️ **Tool calling = "agent ko code likhna" nahi.** Agent tool CALL karta hai, tool ka code tumne likha hai. Yahan `score_article` ka koi backend function nahi — bas structured output ka mechanism. (Phase 4 mein tools ke paas real functions the — yahan score validation hi kaafi hai.)

⚠️ **Ek article = ek LLM call = expensive nahi.** Groq free tier 1 run/day (~12 calls) ke liye far more than enough. Koi paisa nahi.
