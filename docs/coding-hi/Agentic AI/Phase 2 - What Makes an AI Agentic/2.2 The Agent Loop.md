So an agent doesn't just answer — it *acts*. But how does it decide what to do next? It follows a loop. A simple, repeatable pattern that runs until the job is done.

It's called the **ReAct pattern** (short for Reason + Act, though you'll also hear "Think-Act-Observe"). Here's what it looks like:

**Think → Act → Observe → Think → Act → Observe → ... → Done**

![The ReAct Loop — Think → Act → Observe Cycle with Dark/Light Theme Example](/diagrams/agenticai/react-loop.svg)

Let's break down each step:

**Think:** The model looks at where it is and where it needs to go. It asks itself: "What's the next thing I should do to make progress on this goal?" This isn't magic — it's the same prediction engine you learned about in Phase 1, but now pointed at a different kind of question: "What action should I take next?"

**Act:** The model doesn't just output text to you. It calls a *tool* — a function that does something in the real world. Read a file. Write a file. Run a command. Search the web. This is the key difference from a chatbot. The model's output gets *executed*, not just displayed.

**Observe:** The tool returns a result. The model reads it. Maybe the file was created successfully. Maybe there was an error. Maybe the search returned ten links. This new information becomes part of the model's context.

Then the loop repeats. The model thinks again, armed with new information. Act again. Observe again. Over and over until the original goal is met.

Let's trace this with the dark/light theme example you've been following since 1.1. Here's what actually happens inside Cline or opencode when you say "Create a dark theme and a light theme for this website":

- **Think:** The model reads your request and the files in the context. It decides: "First I need to read the current CSS file to understand the existing styles."
- **Act:** The agent calls `read_file` on `styles.css` and gets the contents.
- **Observe:** The model now has all the CSS in its context — class names, color variables, layout rules.

- **Think:** "Now I understand the structure. I'll add CSS variables for theming first, then write the dark theme overrides, then the light theme."
- **Act:** It writes to `styles.css` — adds `:root` variables, `.dark-theme` class, `.light-theme` class.
- **Observe:** The file was saved successfully. No errors.

- **Think:** "The CSS is ready. Now I need to add the JavaScript toggle that switches between themes."
- **Act:** It creates `ThemeToggle.js` and updates `index.js` to include it.
- **Observe:** Files created and imported correctly.

- **Think:** "Let me verify everything works by running the dev server."
- **Act:** It runs `npm run dev`.
- **Observe:** The server starts without errors.

- **Think:** "The task is complete. I'll summarize what was done."
- **Act:** It responds with a summary of the changes.

Each cycle is one pass through Think → Act → Observe. The model never plans more than a step or two ahead — it figures out what to do next based on what just happened. This is why agents like Cline or opencode can adapt when something goes wrong. If the CSS file doesn't exist, the Observe step catches the error, and the Think step adjusts: "OK, I need to create the file first."

You're watching the ReAct loop in real time. Every time your agent shows you its reasoning before running a command, that's the "Think" step. Every command it runs is an "Act." Every result it reads back is an "Observe."

This loop is the engine that makes an agent an agent. Without it, you just have a very smart text generator.

But what kinds of actions can an agent actually take? Let's look at the toolkit.

## What It Is NOT

The ReAct loop is **not** a special mode that only works with expensive, high-end models. Any LLM — even a small one — can follow the Think→Act→Observe pattern. The loop is a wrapping structure, not a model feature. You could take the same GPT-4 that runs a chatbot, wrap it in a ReAct loop, give it tools, and suddenly it's an agent. The model hasn't changed — the architecture around it has. It's like putting the same driver in a regular car vs. a race car with telemetry and a pit crew. The driver is the same; the system changes everything.

### In Your Own Words

<details>
<summary>1. In your own words, what happens during the "Think" step? How is it different from what a chatbot does?</summary>

**Sample Answer:** During the Think step, the model looks at its current state — what it's done so far, what the result was, and what the original goal is — and decides what action to take next. A chatbot thinks only once: "what should I say?" An agent thinks repeatedly: "what should I do next?" It's the difference between giving someone directions and giving them a mission.

</details>

<details>
<summary>2. Why is the "Observe" step so important? What happens if an agent skips it?</summary>

**Sample Answer:** The Observe step closes the feedback loop. Without it, the agent is flying blind — it doesn't know if its action succeeded, failed, or produced unexpected results. If you skipped Observe, the agent would keep acting on old assumptions. Imagine cooking by following a recipe but never tasting the food or looking at the pan. You'd burn everything and never realize it.

</details>

<details>
<summary>3. Can you map the last task you did with Cline or opencode to the Think → Act → Observe loop? Write out at least two full cycles.</summary>

**Sample Answer:** If I asked Cline or opencode to add a dark mode toggle to my React app: Cycle 1 → Think: "I need to create a theme context and a toggle button." Act: Created `ThemeContext.js` with provider logic. Observe: File saved, no errors. Cycle 2 → Think: "Now I need the toggle button component." Act: Wrote `ThemeToggle.jsx`. Observe: File saved, import works. Each cycle builds on the previous observation.

</details>

<details>
<summary>4. What would happen if an agent got stuck in a loop — Think → Act → Observe → Think → Act → Observe → Think → Act → Observe — forever? How would you stop it?</summary>

**Sample Answer:** The agent would waste tokens and time, running the same or similar actions without making progress. Most real agents have safeguards: a maximum number of steps, a token budget, or a timeout. Others detect repetition — if the same observation keeps appearing, the agent stops and asks for help. It's like a Roomba that keeps bumping into the same chair. Eventually it should give up and say "I'm stuck."

</details>

<details>
<summary>5. If an agent never "Thought" and just acted blindly based on your first instruction, would it still be an agent? What could go wrong?</summary>

**Sample Answer:** No — that's just a script, not an agent. Without the Think step, the agent can't adapt when something goes wrong. If the first action fails, it has no way to choose a different approach — it just keeps trying the same thing or crashes. It's like a vending machine that takes your money and drops your snack, but if the snack gets stuck, it just sits there forever. The Think step is what makes an agent flexible instead of fragile.

</details>
