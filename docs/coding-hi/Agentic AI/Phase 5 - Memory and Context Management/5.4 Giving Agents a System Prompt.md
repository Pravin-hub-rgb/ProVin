Besides conversation history, there's another powerful tool — the **system prompt**. This is a message at the very beginning of the context that sets the agent's personality, instructions, and constraints. It's always there, every single turn, sitting at the top of the messages array.

Think of the system prompt as the agent's job description. It tells the model: who you are, what tools you have, how you should behave, and what format to use for responses.

![System Prompt Anatomy — Role, Tools, Format, Constraints, and Guidelines](/diagrams/agenticai/system-prompt-anatomy.svg)

A good system prompt for an agent includes:

- **Role definition.** "You are an expert software engineer. You help users understand and modify codebases."
- **Available tools.** "You have access to the following tools: search_files, read_file, edit_file. Explain your plan before using a destructive tool."
- **Output format.** "When you suggest code changes, show the diff using markdown code blocks."
- **Constraints.** "Never run commands without user confirmation. Never delete files without asking."
- **Behavior guidelines.** "If you're unsure about something, ask clarifying questions. Think step by step."

Why does this matter so much? Because the system prompt is the first thing in context. Everything the model generates is influenced by it. It sets the frame for the entire conversation. Change the system prompt, and the same user messages can produce completely different behavior.

You might have already used this without knowing it. Cline and opencode both have a "Custom Instructions" setting where you can paste instructions that get prepended to every conversation. That's your system prompt. If you've ever told your agent "always ask before running npm install" or "prefer existing libraries over writing from scratch," you were writing a system prompt.

The system prompt is also where you'd put things like the current date, the user's name, or project-specific context that doesn't change between turns. It's efficient because it's sent with every request anyway, so putting stable instructions there saves tokens compared to repeating them in every user message.

One gotcha: models vary in how strongly they follow system prompts. Some models treat them as hard rules. Others treat them as suggestions. Experiment and see how your chosen model responds. If it's ignoring your system prompt, try rewording it more explicitly.

Now, the system prompt handles the instructions. Conversation history handles the recent turns. But what if your agent needs to reference a thousand-page technical manual? That's too much for any context window. You need a different approach entirely.

---

## What It Is NOT

A system prompt is **not** a command that the model follows perfectly. Think of it more like onboarding a new contractor — you give them a handbook (the system prompt), but they might still interpret things differently or make judgment calls you didn't anticipate. Different models have different levels of adherence: some treat the system prompt as a hard rule, others as a suggestion. The same prompt that works perfectly on Claude might be ignored by a smaller model. Always test and iterate.

### In Your Own Words

<details>
<summary>1. What's the difference between a system prompt and a user message?</summary>

**Sample Answer:** The system prompt sets the agent's role, behavior, and constraints — it's always present in every turn. User messages are the ongoing conversation. Think of it as the system prompt being the employee handbook and user messages being the daily tasks you hand that employee. The handbook stays the same; the tasks change.

</details>

<details>
<summary>2. How would you structure a system prompt for a code review assistant?</summary>

**Sample Answer:** I'd start with a clear role ("You are a senior code reviewer"), then add guidelines ("Be constructive, check for security issues, suggest improvements"), output format ("Use file:line notation, explain why"), and constraints ("Don't rewrite code — only suggest changes"). Keep it concise so the model focuses on the key points.

</details>

<details>
<summary>3. Why is the position of the system prompt (first in context) important?</summary>

**Sample Answer:** The model processes context left to right, and the first content sets the frame for everything that follows. It's like meeting someone for the first time — that initial impression shapes how you interpret everything they say afterward. Put the most important instructions at the very beginning of the system prompt.

</details>

<details>
<summary>4. What happens if your system prompt is too long? Too short?</summary>

**Sample Answer:** Too long: you waste tokens and the model may ignore later instructions buried in the middle. Too short: the model lacks guidance and may behave unpredictably, like giving a new employee a one-sentence job description and expecting them to know what to do. Aim for enough direction without over-specifying every edge case.

</details>

<details>
<summary>5. Have you used custom instructions with Cline or another tool? What did you put in them?</summary>

**Sample Answer:** Yes. Common things to include: "Always ask before installing packages or running destructive commands," "Prefer using existing utilities in the codebase over writing from scratch," "Explain your reasoning before writing code," and "Use the project's existing conventions for imports and naming." These shape the agent's behavior without repeating them in every message.

</details>
