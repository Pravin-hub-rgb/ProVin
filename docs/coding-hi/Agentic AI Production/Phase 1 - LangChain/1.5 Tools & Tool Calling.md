# 1.5 Tools & Tool Calling

Ek **tool** matlab — ek normal Python function jise model call kar sakta hai. Model khud function ki logic nahi jaanta. Use sirf batana hota hai ki *kaunsa* kaam available hai aur *kaise* call karna hai. Tool se model ko teen cheezein milti hain: naam, description, aur arguments ka shape. Model inhi se samajhta hai ki kab aur kaise use kare.

## A Normal Function — Then Turn It Into a Tool

Pehle ek saada Python function likho, tumhari apni logic:

```python
def get_weather(city):
    """Get the current weather for a city."""
    return f"The weather in {city} is sunny, 30 degrees."
```

Bas ek normal function. Ab usse **tool** banao:

```python
from langchain_core.tools import tool

@tool
def add(a: int, b: int) -> int:
    """Add two numbers and return the sum."""
    return a + b
```

Yahan fark `@tool` decorator ne diya:

* `@tool` — `def` se pehle wali line. Yeh Python ko bolta hai "is function ko tool bana do, taaki model ise call kar sake."
* Function ka **naam** (`add`) — tool ka naam ban jaata hai. Model isi naam se call karega.
* Function ki **docstring** (`"""Add two numbers..."""`) — tool ka description ban jaati hai. Model isi ko padhke samajhta hai ki is tool ko kab use kare.
* Type hints (`a: int, b: int`) — tool ke arguments ka shape batate hain. Model ko pata chalta hai kaunsa type bhejna hai.

Isliye docstring aur types itne important hain — wahi model ki guide hai ki tool kya karta hai aur kis format mein call karna hai.

## Tell the Model About the Tool — `bind_tools`

Model tool call kare, isse pehle use tool ke existence ka pata hona chahiye. Yeh `bind_tools()` karta hai:

```python
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

load_dotenv()

model = init_chat_model("llama-3.3-70b-versatile")

@tool
def add(a: int, b: int) -> int:
    """Add two numbers and return the sum."""
    return a + b

model_with_tools = model.bind_tools([add])

response = model_with_tools.invoke("What is 5 plus 3?")
print(response)
```

`model.bind_tools([add])` — model ki ek nayi copy banata hai jo tools ke baare mein jaanti hai (yahan bas `add`). Jab tum invoke karte ho to do cheezein ho sakti hain:

* **Model seedha jawab de** — `response.content` mein answer hoga. (Agar model ko lagta hai ki tool ki zaroorat nahi.)
* **Model tool call ke** — `response.content` khali hoga, aur `response.tool_calls` mein add ke arguments bhar ke aayenge, jaise `[{"name": "add", "args": {"a": 5, "b": 3}}]`.

## The Tool Loop — The Hero

Yeh wahi loop hai jo Intro mein tumne khud banaya tha. Model bolta hai kaunsa tool, tum chalao, result wapas bhejo, phir model ko bolo final jawab do.

```python
@tool
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

model_with_tools = model.bind_tools([add])

messages = [{"role": "user", "content": "What is 5 plus 3?"}]

response = model_with_tools.invoke(messages)
messages.append(response)

# kya model ne tool call kehta hua bola? Check karo.
if response.tool_calls:
    tool_call = response.tool_calls[0]
    tool_name = tool_call["name"]
    tool_args = tool_call["args"]

    # Tool khud chalao:
    if tool_name == "add":
        result = add(**tool_args)

    # Result ko ToolMessage ke roop mein wapas bhejo
    messages.append(
        {"role": "tool", "tool_call_id": tool_call["id"], "content": str(result)}
    )

    # Ab final jawab lo — model result dekh ke jawab dega
    final = model_with_tools.invoke(messages)
    print(final.content)
```

Line by line:

1. `response = model_with_tools.invoke(messages)` — model se poocha "5 plus 3?" Model ne seedha jawab nahi diya; use `tool_calls` mein keh diya "`add(5, 3)` call karo."
2. `messages.append(response)` — model ke is message ko (jisme tool_calls hain) history mein jodo. Taaki agli call pe model ko pata rahe ki usne pehle kya socha.
3. `if response.tool_calls:` — check karo ki kya model ne tool call maanga. Agar seedha jawab hota toh yeh block skip ho jaata.
4. `tool_call = response.tool_calls[0]` — pehla tool call nikaalo.
5. `tool_name = tool_call["name"]` aur `tool_args = tool_call["args"]` — pata karo kaunsa tool aur kaunse arguments.
6. `result = add(**tool_args)` — asli tool ko run karo. `**tool_args` dictionary ke key-value pairs ko function ke named arguments mein bana deta hai — matlab `add(a=5, b=3)`.
7. `messages.append({"role": "tool", ...})` — ToolMessage banate ho: us tool call ki id, aur uska result. Ye model ko batata hai ki tool ka jawab kya tha.
8. `final = model_with_tools.invoke(messages)` — ab model ke paas tool ka result hai. Toh wo final jawab deta hai: "5 plus 3 is 8."

## A Shortcut — `create_agent`

Tool loop tumne khud likha. Par dhyan de — ye loop (invoke → check tool → run → wapas bhejo) har jagah same hai. LangChain ne ise ek ready-made agent mein rakh diya hai. Ise `create_agent` kehte hain:

```python
from langchain.agents import create_agent

@tool
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

agent = create_agent(
    model="llama-3.3-70b-versatile",
    tools=[add],
)

response = agent.invoke("What is 5 plus 3?")
print(response.content)
```

Kya hua? Pura tool loop — invoke karna, tool_calls check karna, tool run karna, result wapas bhejna — sab `create_agent` ne andar se kar liya. Tum sirf batate ho: kaunsa model `model=`, kaunse tools `tools=[add]`. Baaki loop agent khud chala leta hai.

Yehi wo "kit" hai jisme tumne Intro mein loop scratch se banaya tha. Ab wahi loop ek ready-made cheez hai. `bind_tools` tumhe raw control deta hai; `create_agent` tumhe simplicity deta hai. Dono useful hain — bind jab tum loop khud handle karna chahte ho, agent jab tumhe loop ready chahiye.

## What It Is NOT

⚠️ **Tool = LLM khud ka code nahi chalata.** Model tumhare function ki lines execute nahi karta. Woh sirf bolta hai "call `add(5, 3)` karo" — asli execution tumhara Python code karta hai `result = add(**tool_args)`. Model ek request bhejta hai, aam execution tumhara code karta hai.

⚠️ **`@tool` sirf metadata add karta hai.** Function ki logic change nahi hoti. Woh wahi Python function hai — bas `@tool` ne usse model ko callable banaya, iski docstring aur types ko model ki guide banaya.

⚠️ **Tool loop agents ka pura core hai, sirf LangChain ki cheez nahi.** Ye wahi pattern hai jo Intro course mein tumne JS mein banaya tha. LangChain ne usse ready-made bana diya — isliye framework ka fayda yahi hai ki common loop dobara nahi likhna padta.
