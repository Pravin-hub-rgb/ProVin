# 1.1 Why Frameworks?

**Framework** matlab — readymade code ka ek pura kit jo common problems ko pehle se solve karke rakhta hai. Tum sirf wahi likhte ho jo tumhare kaam ke liye unique hai, baaki sab kachha kaam kit ne pehle se kar rakha hai.

Samajh aisa lo — ek ghar banao. Tum chaahe toh ek-ek eent kharid ke, gila kar ke, deewar khadi karo. Chhappar, bijli, paani — sab khud jodna padega. Yeh hai scratch se banana. Framework matlab ek **fully-furnished flat** — bijli laggi hai, furniture hai, plumbing ready hai. Tum bas apna saman leke aao aur rehna shuru karo.

Is course mein tum wahi concepts jo Introduction mein zero se banaye — models, tool calling, memory, RAG — inhe real, industry-standard tools se rebuild karoge. **Concepts wahi hain. Bas likhne ka shorthand badalta hai.**

## Getting Python Ready

LangChain ek **Python** library hai. Tumko JavaScript aati hai, par Python tumhare liye nayi hai — koi baat nahi. Isko aise samjho jaise doosri bhasha seekh rahe ho. Sochna wahi, bas bolne ke tareeke alag.

Code likhne se pehle teen cheezein install karni hain:

1. **Python khud** (version 3.9 ya usse nayi)
2. **Packages install karne ka tareeka** — `pip` ya `uv`
3. **Code likhne ki jagah** — koi bhi text editor kaam karega

Chal step by step karte hain.

### Install Python

python.org pe jao, apne system ka installer download karo aur chalao. Ek zaroori cheez — **install karte waqt "Add Python to PATH" wala box tick karna mat bhoolna.** Ye chhota sa tick hi fark banata hai: uske bina `python` likhne pe "command not found" ki confusing error aati hai.

Install ho jaaye toh terminal khologe aur type karoge:

```powershell
python --version
```

Agar kuch aisa dikhe `Python 3.11.x`, toh done — tum taiyaar ho.

### `pip` vs `uv` — Two Ways to Install Packages

**Package** matlab kisi aur ka likha hua code ka collection jo tum apne project me ghusa sakte ho. LangChain bhi ek package hai. Use karne ke liye usko install karna padta hai.

`pip` — classic installer jo Python ke saath aata hai. Har jagah dikhega. `uv` — naya, aur bahut tez, jo same kaam karta hai (aur jis course pe tum chal rahe ho woh bhi yehi use karta hai). Aise samjho — `pip` normal bus, `uv` express train. Dono same stop pe le jaate hain, bas `uv` zyada fast. Hum `uv` use karenge, par `pip` wala tareeka bhi bata dunga.

### Create a Project Folder and a Virtual Environment

**Virtual environment** — tumhare project ke packages ki ek private, alag jagah. Aise socho — is project ke liye ek alag tool box, jisme uske apne screwdrivers hain, uski apni glue. Packages ek project se doosre project mein spill nahi hote.

```powershell
mkdir mysite
cd mysite
uv init
uv add langchain
uv add langchain-groq
```

* `mkdir mysite` — `mysite` naam ka folder banao. "mkdir" = "make directory".
* `cd mysite` — us folder ke andar chale jao. "cd" = "change directory".
* `uv init` — andar ek naya Python project bana deta hai, saath mein `pyproject.toml` file jo project ki settings rakhti hai.
* `uv add langchain` — LangChain package download karke us file mein note kar deta hai.
* `uv add langchain-groq` — Groq ka free model LangChain se jodne wala package. (Hum free mein practice karenge — isi baare mein 1.2 mein.)

Agar `pip` pasand ho toh same cheez aisi dikhegi:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install langchain langchain-groq
```

* `python -m venv .venv` — `.venv` naam ka ek virtual environment banao. ("venv" = "virtual environment").
* `.venv\Scripts\activate` — us environment ko ON karo.
* `pip install langchain` — LangChain ko environment mein download karo.

### The `requirements.txt` (or `pyproject.toml`) File

Dono `uv` aur `pip` tumhare project ko kya chahiye, uski list ek file mein rakhte hain — `requirements.txt` (`pip` ke liye), `pyproject.toml` (`uv` ke liye). Yeh tumhare project ki shopping list hai. Jab tum ya tumhari team kisi nayi computer pe project kholte ho, toh ek hi command se sab install ho jaata hai:

```powershell
pip install -r requirements.txt
```

Ye chhota sa aadat hi project ko "kisi bhi machine pe turant chalu" banata hai. Day one se production mindset.

## What It Is NOT

⚠️ **Framework = magic button nahi.** Yeh tumhara app khud nahi likhta. Yeh koi code generator nahi. Yeh blocks ka ek kit hai jo *tumhe* assemble karna hai. Logic tum design karte ho; LangChain bas readymade parts deta hai taaki tumhe har cheez zero se na banana pade.

⚠️ **Ye wahi "theek 7.1" vala theory nahi hai.** Introduction course 7.1 mein sirf baat hui thi ki *kaunse* frameworks exist karte hain. Ab tum actually ek framework use karoge — haath se, real calls ke saath.

⚠️ **Framework sirf Python ke liye nahi.** JS mein bhi frameworks hain (jaise LangGraph.js). Par iss course mein hum Python wale use kar rahe hain kyunki companies ka jo asli kaam hai woh Python-native hai.

Ab tumhara computer Python bolta hai, tumhe pata hai kit (bricks) kyun behtar hai raw se, aur sab install ho chuka hai. Ab satisfaction wala moment hai — LangChain se apni pehli real AI call karte hain.
