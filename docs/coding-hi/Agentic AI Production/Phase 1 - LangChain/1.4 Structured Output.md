1.3 mein tumne messages aur prompts se conversation banayi. Jab tumne `model.invoke()` kiya aur `response.content` print kiya, wo jawab **free-form text** tha — kuch bhi ho sakta hai. Ek baar maine bhi yahi problem ki thi: humne model se user ka naam aur umar nikalwaana tha, toh usne ek lamba paragraph de diya jisme naam pitch me tha. Main usko code mein directly use nahi kar sakta tha.

Aise hi ek function ko chahiye fixed data — na ke "essay". Wahi is topic ka kaam hai: **structured output**.

# 1.4 Structured Output

**Structured output** matlab — model ko bolna ki jawab ek **fixed format** mein de, jaise ek shape pehle se decide hai. Code ke andar isko **schema** kehte hain — ek aisa template jisme fields fixed hain: naam kya hoga, kis type ka hoga, aur kya bhar sakta hai.

Aise socho — hotel ka check-in form. Usme "Name" ka box hai, "Age" ka box hai, "City" ka box. Tum poora paragraph nahi likhte, tum boxes bharo. Structured output wahi karwaya hai — model ko ek form de do, woh boxes bharta hai, code ko pata rehta hai ki kaun sa data kaunsi field mein.

## Define the Schema with Pydantic

LangChain mein simple tareeka hai `Pydantic` class se form define karna. Pydantic ek Python library hai jo structured data ke validation ke liye banti hai. Ek class likho jo fields batao, aur form taiyaar.

```python
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from pydantic import BaseModel, Field

load_dotenv()

model = init_chat_model("llama-3.3-70b-versatile")

class MovieReview(BaseModel):
    title: str = Field(description="Movie ka naam")
    rating: int = Field(description="5 mein se rating, sirf number")
    favorite_scene: str = Field(description="Ek favorite scene ka description")

structured_model = model.with_structured_output(MovieReview)

review = structured_model.invoke("Tell me about the movie Inception.")
print(review)
print(review.title)
print(review.rating)
```

Line by line:

1. `from pydantic import BaseModel, Field` — Pydantic se do cheezein laye: `BaseModel` (class ka base) aur `Field` (fields describe karne ke liye).
2. `class MovieReview(BaseModel):` — ek nayi Python class banao jiska base `BaseModel` hai. Yeh class hi service form ka template hai.
3. `title: str = Field(...)` — ek field. `title` naam, `str` type (string). `Field(description="...")` — is field ke baare mein model ko batao. Ye description model ko guide karta hai ki yahan kya likhna hai.
4. `model.with_structured_output(MovieReview)` — model ko bolt `MovieReview` ke shape mein jawab do. Yeh ek naya version of model returns ek `structured_model` object jo hamesha `MovieReview` shape return karega.
5. `structured_model.invoke("Tell me about the movie Inception.")` — same invoke, par ab jawab ek `MovieReview` object hai, sirf text nahi.
6. `print(review)` — pura object; `review.title`, `review.rating` — fields individually access. Kar sakta hai data.

Iska kya fayda? Code mein tum seedha kaam karte ho — `review.rating` ek real integer hai, `review.title` ek real string. Model ka jawab predictable hai, isliye code bharosemand aur crash-free. Fixed shape = code janta hai kya milega.

## Two More Approaches — TypedDict and dataclass

Pydantic ke alawa LangChain do aur tareeke bhi deta hai. Dono learn karne layak hain kyunki real code teeno dikhenge.

### Approach 2 — TypedDict

**TypedDict** ek Python ka built-in cheez hai jo ek dictionary ka shape batata hai. Pydantic class ke bajaye tum sirf fields ke types batao, koi `Field(description=...)` nahi:

```python
from typing import TypedDict

class MovieReview(TypedDict):
    title: str
    rating: int
    favorite_scene: str

structured_model = model.with_structured_output(MovieReview)

review = structured_model.invoke("Tell me about the movie Interstellar.")
print(review["title"])   # dictionary ki tarah access
print(review["rating"])
```

Isme fark: `review` ab ek **dictionary** hai, isliye tum `review["title"]` se access karte ho, `.` se nahi. Ye halka hai — isme `Field(description=...)` nahi milta, par syntax simpler aur zehni load kaam.

### Approach 3 — dataclass

**dataclass** Python ka built-in tareeka hai simple data classes banane ka. Isme bhi tum sirf fields define karte ho, aur access `.` se hota hai:

```python
from dataclasses import dataclass

@dataclass
class MovieReview:
    title: str
    rating: int
    favorite_scene: str

structured_model = model.with_structured_output(MovieReview)

review = structured_model.invoke("Tell me about the movie Dune.")
print(review.title)
print(review.rating)
```

### Which One When?

| Tareeka | Access | Field descriptions | Extra features |
|---|---|---|---|
| Pydantic `BaseModel` | `review.title` | ✅ `Field(description=...)` | Validation, defaults, complexity |
| `TypedDict` | `review["title"]` | ❌ | Halka, dict hai |
| `dataclass` | `review.title` | ❌ | Simple, built-in |

Rule of thumb: jab tumhe model ko field ke baare mein bahut context dena hai ya validation chahiye, **Pydantic** jao. Jab bas seedha shape chahiye aur kuch zyada nahi, `TypedDict`/`dataclass` kaafi hain.

## Why This Matters for Agents

Har agent ke core mein ek loop hai: model ko bolo kya karna hai, model ka jawab lo, code seedha use karo. Agar jawab essay hota toh code use parse karta (TEDIOUS aur error-prone). Structured output se jawab apne aap `review.rating` ya `plan["tasks"]` jaisa object hota hai — **code ko exact pata hota hai ki model ne kya kaha.** Function call ke liye bhi yehi chahiye — function ko named arguments chahiye, essay nahi. Agli topic mein yehi dekhenge: tools.

## What It Is NOT

⚠️ **Structured output = model ko "JSON bhejo" bolna nahi.** Seedha bolne se kabhi kabhi raw JSON string milta hai jisse phir parse karna padta hai — easy galat hone wala. `with_structured_output` actual model-function calling ke andar se sahi shape laata hai, apne aap.

⚠️ **Ye sirf validation library nahi.** Pydantic ka kaam validate karna hai, par `with_structured_output` usse aage hai — wo model se hi fixed shape mein jawab mangwata hai. Pydantic sirf tools hai; structured output seekh ka hasil hai.
