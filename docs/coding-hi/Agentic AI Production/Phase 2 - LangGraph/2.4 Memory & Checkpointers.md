# 2.4 Memory & Checkpointers

2.3 ka agent ek baar chalega, jawab dega, aur phir... sab kuch bhool jata hai. Agla `invoke` call ke liye purana conversation chala jata hai. Jaise har baat ke baad tumhe yaad nahi rahe. Isliye jab ek agent multi-turn baat cheet kare, toh zaroorat padti hai ki **state ka koi record ho**.

LangGraph iske liye `checkpointer` ke naam par ek concept de rakha hai — "graph ka save-game".

## Checkpointer = graph ka "save game"

Jaise ek video game mein aap level pura karo toh progress save karo deta hain — agle restart par wahi se shuru karo. Checkpointer bilkul waise hi hota hai: graph ke state ko ek **thread_id** ke niche save karta hai, jisse agle call mein wahi state mile.

## MemorySaver — sabse aasani

`MemorySaver` LangGraph ka in-memory checkpointer hai — program chalti raham tak state yad rakhega.

```python
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.checkpoint.memory import MemorySaver

llm = ChatGroq(model_name="llama-3.3-70b-versatile")

def chatbot(state: MessagesState):
    messages = [SystemMessage(content="Tum ek helpful dost ho.")] + state["messages"]
    return {"messages": [llm.invoke(messages)]}

# 1. ek checkpointer bana ke graph ke saath jod do
memory = MemorySaver()

graph = StateGraph(MessagesState)
graph.add_node("chatbot", chatbot)
graph.add_edge(START, "chatbot")
graph.add_edge("chatbot", END)
graph = graph.compile(checkpointer=memory)   # <-- yahan jod ke diya

# 2. ek thread_id — isi id mein baat bachhegi
config = {"configurable": {"thread_id": "vin-chat-1"}}

# call 1
graph.invoke(
    {"messages": [HumanMessage(content="Main Vin hoon. Tumhe pata hai main kaun hoon?")]]},
    config=config,
)

# call 2 — graph yad rakhega purani baat (kyunki checkpointer = same thread_id)
result = graph.invoke(
    {"messages": [HumanMessage(content="Main kaun tha? Tumhe yaad hai?")]},
    config=config,
)
print(result["messages"][-1].content)
```

Line-by-line:

1. `MemorySaver()` — ek in-memory save-game. Har run ke andar state store rakhega. (Production me jaake `PostgresSaver` / `RedisSaver` use karo — persistence milegi.)
2. `graph.compile(checkpointer=memory)` — graph ko batata hai ki har state koshan `thread_id` ke nicha save kare. Bina iske invoke stateless hota hai.
3. `config = {"configurable": {"thread_id": "..."}}` — batat ahai ki "ye sab itni thread_id ke andar chalega".
4. `graph.invoke(..., config=config)` — har invoke ke saath config bhejna zaroori hai, tabhi checkpointer pata kare ki kis thread ka state retrieve kare.

Agar aap dobara **same thread_id** se invoke karenge toh purana conversation milega — agent neend se jagna jaise laga.

## Yeh Phase 1 ke `InMemoryChatMessageHistory` se kahink alag

Phase 1 me `InMemoryChatMessageHistory` ek **RAM ka list** tha — program restart hote hi sab kuch delete ho jata. LangGraph ka checkpointer **thread_id ke neeche structured state** store karta hai — messages *sath hi other state* bhi. Aur in production mein ye easily `PostgresSaver` jaise durable store mein badal sakte hain — bina code change kiye.

## What It Is NOT

⚠️ **Checkpointer = ek chat history object nahi.** Yeh sirf messages nahi, **poori graph state** (har key/jo tum state mein rakhte ho) save karta hai.

⚠️ **thread_id koi session nahi.** Ek hi checkpointer ke andar alag thread_id = alag conversation. Seedhi ID se poora isolation.

⚠️ **MemorySaver permanent storage nahi.** RAM pe basata hai. Restart par sab kuch reset. Production ke liye toh external saver (Redis/Postgres) chahiye.

## In Your Own Words

<details>
<summary>1. Bina checkpointer ke graph kyun "bhool jata" hai?</summary>

**Jawab:** Har `invoke` ek fresh start hoti hai — graph apni state ke andar se nahi, bilkul seedhi function jaisa. Checkpointer nahi lagao toh purana conversation state mein nahi aata; har call independent lagti hai.

</details>

<details>
<summary>2. thread_id aur checkpointer — dono kis baat karte hain?</summary>

**Jawab:** `thread_id` ek conversation ka naam/identity hota hai. Checkpointer uss thread_id ke under state save karta hai. Same ID = same conversation history; alag ID = alag fresh start.

</details>

<details>
<summary>3. InMemoryChatMessageHistory (Phase 1) se MemorySaver ka mukhya farq?</summary>

**Jawab:** History toh bas messages ka list tha aur RAM pe nikali. Checkpointer seedhi state dict (sab keys) save karta, structured thread_id ke under, aur easily durable store (Postgres/Redis) mein bdal sakta.

</details>
