# 2.11 Deployment & LLMOps

2.10 tak agent perfect bangaya — trace, debug, streaming. Lekin ab tak toh **local dev** tha. Ek baat bhi aayegi jab aap client/product ya end-users ke saamne laa deenge — "production mein kaise daalenge?". **LLMOps** = LLM apps ke ops side: tracking, monitoring, evaluating, deploying. Ye sirf concepts nahi — runnable setup tak le jayenge.

## 1. MLflow — metrics, params, aur traces track karo

MLflow ek experiment tracker hai. Isse aap log karte hain ki: kitna tokens laga, konsa model, konsi prompt, kitna fast, koi error toh nahi.

```bash
uv pip install mlflow[extras]
mlflow ui   # starts at http://localhost:5000
```

```python
import mlflow
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import StateGraph, START, END, MessagesState

llm = ChatGroq(model_name="llama-3.3-70b-versatile")

def chatbot(state: MessagesState):
    messages = [SystemMessage(content="Tum ek helpful dost ho.")] + state["messages"]
    return {"messages": [llm.invoke(messages)]}

g = StateGraph(MessagesState)
g.add_node("chatbot", chatbot)
g.add_edge(START, "chatbot")
g.add_edge("chatbot", END)
app = g.compile()

# --- track karo ---
mlflow.set_experiment("vin-langgraph")
with mlflow.start_run():
    mlflow.log_param("model", "llama-3.3-70b-versatile")
    user_q = "LangGraph mein streaming kyun use karte hain?"
    result = app.invoke({"messages": [HumanMessage(content=user_q)]})
    answer = result["messages"][-1].content
    mlflow.log_metric("answer_chars", len(answer))
    mlflow.log_text(answer, "reply.txt")
    mlflow.log_artifact("app.py")
    print(answer)
```

- `mlflow.set_experiment` — runs kis group mein jayenge.
- `log_param` / `log_metric` / `log_text` / `log_artifact` — sab kuch run ke saath log hota hai.
- `mlflow ui` se dekho.

## 3. Grafana — metrics visualize karo

MLflow se data aaya to dashboard banana hai. Grafana uss data ko visualize karta hai. Local setup (docker-compose):

```yaml
# docker-compose.yml
services:
  grafana:
    image: grafana/grafana-enterprise
    ports: ["3000:3000"]
  prometheus:
    image: prom/prometheus
    ports: ["9090:9090"]
```

LangGraph app se ek simple metrics endpoint rakho (FastAPI) jo Prometheus scrape karega:

```python
from fastapi import FastAPI
import time

api = FastAPI()
_calls = 0
_latency = []

@api.get("/metrics")
def metrics():
    return {"calls": _calls, "avg_latency": sum(_latency)/len(_latency) if _latency else 0}

@api.get("/chat/{q}")
def chat(q: str):
    global _calls, _latency
    t = time.time(); _calls += 1
    r = app.invoke({"messages": [HumanMessage(content=q)]})
    _latency.append(time.time() - t)
    return {"reply": r["messages"][-1].content}
```

Grafana `http://localhost:3000` (user/pass `admin/admin`), `Prometheus` data source add karo `http://prometheus:9090`, phir `calls` and `avg_latency` ka panel banao. Ab aapka real-time dashboard hai.

## 4. Hugging Face Spaces — deploy karo cloud pe

Sabse aasan deploy: **Gradio + HuggingFace Spaces**. Gradio UI banao, HF pe push karo — do minute mein live.

`app.py`:

```python
import gradio as gr
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import StateGraph, START, END, MessagesState

llm = ChatGroq(model_name="llama-3.3-70b-versatile")

def chatbot(state: MessagesState):
    msgs = [SystemMessage(content="Tum ek helpful dost ho.")] + state["messages"]
    return {"messages": [llm.invoke(msgs)]}

g = StateGraph(MessagesState)
g.add_node("chatbot", chatbot)
g.add_edge(START, "chatbot")
g.add_edge("chatbot", END)
app_graph = g.compile()

def reply(message, chat_history):
    result = app_graph.invoke({"messages": [HumanMessage(content=message)]})
    return result["messages"][-1].content

gr.ChatInterface(reply, title="Phase 2 Agent").launch()
```

`requirements.txt`:

```
langchain-groq
langgraph
langchain-core
gradio
```

`.env` (HF Spaces ke **Secrets** mein daalo — kabhi commit mat karo):

```
GROQ_API_KEY=<your-groq-key>
```

Deploy ke steps:

```bash
git init
git remote add origin https://huggingface.co/spaces/<username>/vin-agent
git add app.py requirements.txt .env
git commit -m "phase 2 agent"
git push origin main
```

HF build karega, aur agent `https://<username>.hf.space` pe live ho jayega.

## LLMOps lifecycle — ek nazar mein

1. **Track** — MLflow ya LangSmith → har run ka data.
2. **Monitor** — Grafana dashboard → live metrics.
3. **Evaluate** (2.10) — LangSmith evaluators / datasets.
4. **Deploy** — HF Spaces / Docker / cloud.
5. **Iterate** — naye metrics → improve.

## What It Is NOT

⚠️ **LLMOps = DevOps ki copy nahi.** LLM ke extra dimensions hain — prompt drift, token cost, hallucination, retriever accuracy. Standard DevOps tools hi nahi pakad sakta.

⚠️ **Grafana sirf dashboard tool nahi.** Backend pe ek metrics source hona chahiye — warna koi data hi nahi.

⚠️ **HF Spaces permanent prod hosting nahi.** Free tier thik hai, lekin high-traffic/rate-limit par shaky rehta hai. Bare-metal/cloud par shift karo.

**Jawab:** `log_param` config value (model name) — set hota hai run ke start mein. `log_metric` ek number (answer length, latency) — time-series. `log_artifact` ek file (reply.txt, code) — save karta hai.
