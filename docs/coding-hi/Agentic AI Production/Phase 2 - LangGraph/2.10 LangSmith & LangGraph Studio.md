# 2.10 LangSmith & LangGraph Studio

Agent complex ho gaya — sochna, tool call, branches, multi-agent. Jab koi galat jagah pe ruke ya galt tool call kare, toh dekhna mushkil ho jaye ga ki "kahaan galti hui". Isliye **observability** = "dekhna ke agent kya kar raha hai" zaroori hai.

LangGraph ke do tools iske liye hain: **LangSmith** (trace/cloud) aur **LangGraph Studio** (visual editor).

## LangSmith — cloud trace + debug

LangSmith ek cloud tool hai jo har langchain/langgraph run ka **trace** capture karta hai — step-by-step, token cost, tool calls, errors.

Setup (env):
```bash
uv pip install langsmith
# .env
LANGCHAIN_API_KEY=<your-langsmith-key>   # api.langsmith.ai se
LANGCHAIN_TRACING_V2=true                # tracing on karo
LANGCHAIN_PROJECT=vin-phase2             # runs is project me group karo
```

Run hone par sab kuch automatically trace ho jata hai — koi code change nahi. Dashboard pe jake dekho:

- Har node kab chala — `chatbot`, `writer`, `reviewer`.
- Kitna token laga — cost tracking.
- Tool call kab/kahan hua — argument kya tha, result kya tha.
- Koi error/timeout/rate-limit? Seedha vahin dikhega.

```python
# koi extra code nahi — tracing env vars se on hoti hai.
# Manually log bhi kar sakte:
from langsmith import traceable

@traceable(name="my_calculation")
def expensive_step(x):
    return x * 2
```

## LangGraph Studio — visual editor

LangGraph Studio ek **local desktop UI** hai jisme aap apne graph ko **visualize + run + debug** kar sakte hain — node-by-node click kar ke dekh sakte hain.

Setup:
```bash
# install the langgraph CLI
uv pip install langgraph-cli
# (or) uvx langgraph-cli

cd my_langgraph_project
langgraph dev    # starts a local server
# opens LangGraph Studio desktop app at localhost
```

Studio mein aap dekhenge:
- Graph ka diagram (nodes + edges phool ke jod te hue).
- Har run ka state evolution — state har step pe kaisi thi.
- Breakpoints laga sakte hain (pause karo kisi node se pehle).

## Kahan use karo

- **Debugging** — agent galat answer de raha? Trace mejhe dekho ki kis node ne kya socha, konsa tool galat call hua.
- **Evaluation** — LangSmith datasets + evaluators se aap agent ke runs judge kar sakte hain (accuracy, groundedness).
- **Team handoff** — Studio diagram se aap product team ko graph samjha sakte hain bina code dekhe.

## What It Is NOT

⚠️ **LangSmith ek logging library nahi.** Yo LLM-specific tracing system hai — token cost, prompt/data drift, chain-of-thought capture. Seedhi `print` se kabhi nahi milta.

⚠️ **LangGraph Studio browser wala tool nahi.** Desktop app (macOS/Windows) hai jo local dev server se jura hota hai. Browser pe sirf dashboard, nahi editor.

⚠️ **Observability optional nahi.** Jab graph simple ho toh theek hai, lekin jab agent 5-10 tool calls + branches kare — bina tracing ke kabhi pata nahi chale ga ki kahaan galti hui.

## In Your Own Words

<details>
<summary>1. Env vars lagane se pehle tracing automatically start hoti hai kyun?</summary>

**Jawab:** LangChain/LangGraph telemetry on env var par chalti hai — `LANGCHAIN_TRACING_V2=true` hone se sab SDK calls LangSmith ke paas bhej deti. Koi extra code nahi, bas env + API key se.

</details>

<details>
<summary>2. Studio mein breakpoint laga kar kya dekha ja sakta hai?</summary>

**Jawab:** Graph ek specific node se pehle pause hota hai — aap dekh sakte hain ki uss point par state kaisi thi, phir manually agla node trigger karo. Debugging flow control ke liye bohot madadgar.

</details>

<details>
<summary>3. LangSmith mein project ka kya used hai?</summary>

**Jawab:** Project ek namespace/tag hai — sabhi runs ek saath dikhayenge. Jaise aap `vin-phase2` banaenge toh sirf Phase 2 waale runs milenge, Phase 1 ke alag. Organize rakho.

</details>
