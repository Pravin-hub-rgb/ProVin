# 2.9 Functional API

2.8 mein humne pura `StateGraph` class, `add_node`, `add_edge`, `route()` — sab likha. Par ek chhota sa chatbot banane ke liye itna boilerplate bahut lagega. LangGraph ek **simpler tarika** de rakha hai: **Functional API** — bas plain functions likho, LangGraph flow manage karega.

## StateGraph API vs Functional API

| StateGraph API (2.1–2.8) | Functional API |
|---|---|
| `StateGraph` class, `add_node`, `add_edge` — seedha | `@entrypoint` decorator se ek function — seedha |
| Reducer/typing khud handle karna padta | Inputs/outputs simple — manage karo |
| Complex flows (conditional, multi-agent) ke liye | Simple linear/parallel flows ke liye |

Dono same engine pe chalte hain — Functional API bas ek thin wrapper hai jo StateGraph ko background mein banata hai.

## Ek chatbot — Functional API mein

```python
from langgraph.func import entrypoint
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage

llm = ChatGroq(model_name="llama-3.3-70b-versatile")

# ek function = poora graph
@entrypoint
def chatbot(inputs: dict):
    messages = [SystemMessage(content="Tum ek helpful dost ho. Hinglish mein reply karo.")] + inputs["messages"]
    response = llm.invoke(messages)
    return {"messages": [response]}

# run — seedha function call jaisa lagta hai
result = chatbot.invoke({"messages": [HumanMessage(content="LangGraph aur LangChain mein kya farq?")]}))
print(result["messages"][-1].content)
```

Line-by-line:

1. `from langgraph.func import entrypoint` — Functional API ka decorator.
2. `@entrypoint` — ye function ek graph banata hone wala hai. Inputs ek dict, return ek dict (state update).
3. `def chatbot(inputs)` — state lega (`inputs["messages"]`), model se response lekar `{"messages": [response]}` return karega.
4. `chatbot.invoke(...)` — seedha function call jaisa — lekin yeh graph ke andar chalta hai (checkpointer/streaming sab lag bhi sakta hai).

## Parallel subtasks

Functional API ka asli maza — subtasks ko **concurrent** run karna. `@task` se functions parallel chala sakte hain:

```python
from langgraph.func import entrypoint, task

@task
def fetch_a():
    ...

@task
def fetch_b():
    ...

@entrypoint
def workflow(inputs):
    a = fetch_a()          # dono ek saath chalega
    b = fetch_b()
    done_a = a.result()    # jab tak dono complete hon
    done_b = b.result()
    return done_a + done_b
```

## Memory bhi lag sakta hai

```python
from langgraph.checkpoint.memory import MemorySaver
from langgraph.func import entrypoint

@entrypoint(checkpointer=MemorySaver())   # <-- yaad rakhne ke liye
def chatbot(inputs: dict):
    ...
```

## When to use

- **Functional API** — jab flow simple/parallel ho, ya aapko seedha functions chahiye (prototype, small agent).
- **StateGraph API** —jab conditional routing, multi-agent, complex state shapes chahiye.

## What It Is NOT

⚠️ **Functional API "dumb" nahi — yeh ek aur API hai.** Dono ek hi LangGraph engine pe chalte hain. Functional sirf syntax simple karta hai.

⚠️ **Functions global state nahi bana deti.** Inputs/outputs hi state hote hain — agar aapse koi value chahiye toh inputs se nikal ke do, warna return karo.

⚠️ **@task hamesha parallel hota hai.** Tasks concurrent run karo te hain — agar ek phir se fail kare toh dusra bhi ruka sakta. Jab dependency ho toh seedhi order mein `.result()` lo.

## In Your Own Words

<details>
<summary>1. @entrypoint decorator kya karta hai?</summary>

**Jawab:** Us function ko LangGraph graph mein badalta hai — inputs state ban jaati, return value graph ka next state. Seedhi function, lekin LangGraph usse workflow ke hisse maan karta hai.

</details>

<details>
<summary>2. @task karo parallel kyo run karta hai?</summary>

**Jawab:** @task ek hi graph mein ek async sub-task banata hai. Jab aap dono task ko ek saath trigger karteh (a = fetch_a(); b = fetch_b()) toh dono concurrent chalte hain, .result() se dono complete hone ka intezaar karte hain.

</details>

<details>
<summary>3. Functional API vs StateGraph — kis scenario mein konsa?</summary>

**Jawab:** Simple/parallel flow ya jaldi prototype = Functional API. Jab complex routing/multi-agent/conditional logic chahiye = StateGraph API. Dono same cheez karega, style alag.

</details>
