# 3.4 Vector Stores & Retrieval

3.3 mein chunks vectors mein badal gaye — ab in vectors ko ek jagah daal ke rakhte hain, jahan se **jab bhi ek sawaal aaye, uske against sabse kareeb ke 3-5 vectors nikal saken.** Yeh jagah hai **vector store** (FAISS/Chroma). FAISS = Facebook AI Similarity Search — CPU pe chalti, in-memory, demo-friendly.

## Vector store kya hoti hai

Ek aisi database jo text ke bajaye **vectors** store karti hai — aur internally ek **similarity index** banaati hai (jaise ek sorted map) taake `log(n)` mein nearest neighbor mil sake — seedha linear scan se bhi tez.

## Code: build index + retrieve

```python
# 3.4_vector_rag.py
from langchain_community.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_huggingface import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS

docs   = TextLoader("rag_example.txt").load()                 # (1) load
sp     = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = sp.split_documents(docs)                              # (2) chunk
emb    = HuggingFaceEmbeddings(model_name="BAAI/bge-small-en-v1.5")  # (3) embed model
db     = FAISS.from_documents(chunks, emb)                     # (4) store + index
retriever = db.as_retriever(search_kwargs={"k": 2})            # (5) retrieve wrapper
hits = retriever.get_relevant_documents("Student discount kya hai?")
print("top chunk:", hits[0].page_content)

db.save_local("faiss_index")                                   # (6) persist to disk
db2 = FAISS.load_local("faiss_index", emb, allow_dangerous_deserialization=True)  # (7) reload
```

Line-by-line: `TextLoader(...).load()` — text → `Document` list. `RecursiveCharacterTextSplitter(500, 50)` — 500-char chunks, 50-char overlap. `HuggingFaceEmbeddings` — 384-dim local model. `FAISS.from_documents(chunks, emb)` — har chunk embed kare + ek similarity index banaaye (first call ~10s). `db.as_retriever(search_kwargs={"k": 2})` — ek Runnable wrapper — jisse koi bhi prompt pipeline mein use ho sakta hai; `k=2` matlab top-2 chunks. `get_relevant_documents(q)` — q ko embed kare, FAISS se nearest-2 lao. `save_local("faiss_index")` — folder ke andar `index.faiss` + `index.pkl` banata hai. `FAISS.load_local(..., allow_dangerous_deserialization=True)` — reload — same `emb` object chahiye (taki dims match rahein).

## similarity_search vs as_retriever — kyun dono hain?

- `db.similarity_search(query, k=3)` — directly top-k chunks, jab tumhe ek-off cheez chahiye.
- `db.as_retriever()` — ek `Runnable` — LangChain ke **prompt pipeline** (LCEL) mein jod sakte hain — jaise `retriever | prompt | llm` (3.5 mein).

(query "student discount" — usi chunk ko retrieve karega)

**Troubleshooting:**
- `k=2` par error — chunks se kam — `k` ko chunk count se kam rakho
- `save_local` warning — FAISS pickle load karta hai — `allow_dangerous_deserialization=True` zaroori
- `load_local` par dimension error — reload wale model (emb) mismatch — same `HuggingFaceEmbeddings` pass karo
- `faiss_index` folder ban gaya — agle run mein `from_documents` se bana, persist se mat dobara — load_local karo

## Nutshell

Vector store = vectors + similarity index; FAISS in-mem demo, Chroma persistent. `as_retriever` = Runnable form (pipelines ke liye), `similarity_search` = direct top-k.

## Common Mistakes
- ❌ Rebuild index every run (slow) → fix: `save_local`/`load_local` — save karo, baar-baar rebuild mat karo
- ❌ `allow_dangerous_deserialization` nahi diya reload pe → load_local crash → fix: laga ke do (local trusted file hai)
- ❌ Retrieve wrapper banaya lekin `k` nahi diya → default k=4 — chunks se zyada ho sakta → fix: search_kwargs={"k": 3} set karo

## What It Is NOT
- ⚠️ Exact keyword DB nahi — "discount" likhkar "scholarship" nahi aayega — semantic similarity, fuzzy hoti hai
- ⚠️ Persistent by default nahi — FAISS in-memory hoti hai — restart par data chala jayega — save_local zaroori
- ⚠️ Chroma → faiss drop-in replacement nahi — dono alag APIs hain — ek project mein ek hi jodke rakho

<details>
<summary>1. as_retriever() vs similarity_search — kab use karein?</summary>
**Jawab:** similarity_search — jab seedha top-k chahiye (standalone). as_retriever — jab LangChain LCEL pipeline mein jodna ho — `retriever | prompt | llm` — jodne ke liye Runnable hona chahiye.
</details>

<details>
<summary>2. k kaun karta hai — retrieval mein?</summary>
**Jawab:** Top-k — number of chunks jo LLM ko context mein bhejenge. k bahut bada — context bharega (tokens waste). k bahut chhota — sahi answer miss ho sakta hai. 3-5 sabse common.
</details>

<details>
<summary>3. FAISS ko har run rebuild kyun nahi karte?</summary>
**Jawab:** Embedding model load + index build ~10s/GB data — slow. Ek baar build + save_local karke rakho — agle run load_local se mast.
</details>
