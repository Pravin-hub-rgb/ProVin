# 3.6 Modular RAG for Production

3.5 ka pipeline ek hi file (`3.5_full_rag.py`) tha — sab kuch ek saath. Par capstone (9.x) mein jab 5 documents, 3 query types, monitoring aayenge — ek file bahut messy. Production code samajhne laayak tab banti hai jab har badi **ek class / ek responsibility** le.

## Production code kyun modular hota hai?

Socho restaurant — paani bhi order de sakta? Nahin — ek paani laane wala, ek order lene wala, ek pakane wala. Waise hi RAG mein — **EmbeddingManager, TextProcessor, VectorStore, RAG** — har class apni ek zimmedari rakhegi. (Transcript ne yehi architecture dikhaya tha.)

## Code: 4 classes + 1 orchestrator

```python
# 3.6_modular_rag.py
import os
from dotenv import load_dotenv; load_dotenv()          # GROQ_API_KEY env mein
from langchain_community.document_loaders import DirectoryLoader
from langchain_text_splitter import RecursiveCharacterTextSplitter
from langchain_huggingface import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS
from langchain_groq import ChatGroq
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

class EmbeddingManager:                        # (1) only embeddings
    def __init__(self, model="BAAI/bge-small-en-v1.5"):
        self.emb = HuggingFaceEmbeddings(model_name=model)
    def embed_query(self, t): return self.emb.embed_query(t)

class TextProcessor:                           # (2) load + chunk
    def __init__(self, size=500, overlap=50):
        self.sp = RecursiveCharacterTextSplitter(size, overlap)

class VectorStore:                             # (3) embed + store + persist
    def __init__(self, emb_mgr, path="faiss_index"):
        self.emb = emb_mgr.emb; self.path = path
    def build(self, chunks):
        db = FAISS.from_documents(chunks, self.emb); db.save_local(self.path); return db
    def load(self):
        return FAISS.load_local(self.path, self.emb, allow_dangerous_deserialization=True)

class RAG:                                     # (4) retriever + generator
    def __init__(self, vs, k=3):
        self.db = vs.load(); self.k = k
        self.retriever = self.db.as_retriever(search_kwargs={"k": k})
        self.llm = ChatGroq(model="llama-3.3-70b-versatile", temperature=0.3)
        self.prompt = ChatPromptTemplate.from_template("Answer ONLY:\n{ctx}\n\nQ: {q}")
    def _fmt(self, d): return "\n\n".join(x.page_content for x in d)
    def query(self, q):
        chain = {"ctx": self.retriever | self._fmt, "q": RunnablePassthrough()} | self.prompt | self.llm | StrOutputParser()
        return chain.invoke(q)

# === use — capstone (9.x) mein bhi yehi classes
emb_mgr = EmbeddingManager(); tp = TextProcessor()
db = VectorStore(emb_mgr)                     # build once, then load_local
docs = DirectoryLoader("docs", glob="**/*.txt").load()
print(RAG(db, k=3).query("Student discount kya hai?"))
```

Line-by-line: `EmbeddingManager` — embedding model ek jagah; `.emb` reuse — index+query par dim match. `TextProcessor` — split config ek jagah. `VectorStore.build` — embed+index+**save_local**; `.load` — disk se reload (rebuild mat). `RAG` — retriever+LLM+prompt ek unit; `_fmt` — Documents→string. `chain` LCEL — 3.5 waala, lekin reusable; `RAG(db).query(q)` — ek clean call. `DirectoryLoader(glob="**/*.txt")` — poora folder load kare.

## TEST

**Run:** `python 3.6_modular_rag.py` (docs/ folder mein 1+ .txt file + GROQ_API_KEY)

**Expected:**

```
Student discount 10th standard ko 50% off milta hai.
```

**Troubleshooting:**
- `DirectoryLoader` → 0 docs → folder `docs/` khaali ya glob wrong → `**/*.md` try
- rebuild vs load error → pehle `build` chala ke `faiss_index/` banao, phir `load` — don't call build twice
- `self` attribute miss → Python beginners common → constructors double-check
- ChatGroq 401 → `GROQ_API_KEY` env mein nahi → `.env` ya export check

## Nutshell

Modular RAG = 4 classes (Embedding / TextProcessor / VectorStore / RAG); har class ek responsibility — capstone inhe reuse karega.

## Common Mistakes
- ❌ Rebuild index har run → slow + overwrite → fix: build save_local, phir load_local
- ❌ Retriever + index alag models → dim mismatch → fix: ek `EmbeddingManager` inject karo
- ❌ `langchain.text_splitter` import → langchain>=0.3 mein deprecated → fix: `langchain_text_splitter`

## What It Is NOT
- ⚠️ Over-engineering — small experiment mein 3.5 wala ek file chalega
- ⚠️ Framework magic — yeh bas code organize karna — pipeline koi naya nahi
- ⚠️ 7 classes banane se accha — SRP (single responsibility) matter karta hai, count nahi

## In Your Own Words

<details>
<summary>1. Ek hi file vs 4 classes — kab switch karein?</summary>
**Jawab:** Prototype → ek file (3.5). Jab 2+ query types / bulk docs / retry chahiye — class banao. Rule: jab second baar copy-paste karne lagho — usko class karo.
</details>

<details>
<summary>2. self.emb reuse karne se kya hota?</summary>
**Jawab:** Ek hi embedding object — index build + query — dono mein — taaki dims same rahein. Alag model lagane se FAISS load pe crash padega.
</details>

<details>
<summary>3. load_local pe allow_dangerous_deserialization kyun?</summary>
**Jawab:** FAISS pickle save karta — Python deserialize karta — security warning — local trusted file — safe — par flag lagana padta.
</details>
