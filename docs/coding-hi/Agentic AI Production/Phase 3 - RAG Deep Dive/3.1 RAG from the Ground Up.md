# 3.1 RAG from the Ground Up

Tumne 2.11 mein LangGraph agent ko MLflow + HuggingFace Spaces pe deploy kar diya — logs bhi ja rahi hain, sab theek. Par ab ek aisa scene aayega jisme agent haar jayega: ek user puchhe *"hamari latest pricing docs mein student discount ka policy kya hai?"* — agent uska jawab sirf apni 2019-tak ki training se dega (kyunki tumhari docs tabhi banayi gayi). Yehi hai RAG ka time hai.

## RAG — jab model sirf apni yaad se nahi, balki sahi page se likhe

Socho ek exam — sirf 80% syllabus aata hai, 20% sirf classroom notes mein. Jo student sirf apni notebook yaad karega — uska "extra" answer galat ho jayega (hallucinate). RAG wala: examiner usse pehle kehte hain *"chehra khol ke woh extra page dikhao"*, phir likho*. Matlab: **tum LLM ko document ka sahi hissa (context) dedo, phir LLM uss context se hi jawab banaye** — bina model ko retrain/fine-tune kiye.

## The 5-step pipeline — ek nazar

1. **Load** — documents (PDF/TXT/site) lao → *3.2*
2. **Chunk** — bade doc ko chhote pieces mein tod → *3.2*
3. **Embed** — har chunk → 384-number vector → *3.3*
4. **Store** — vectors → FAISS vector DB → *3.4*
5. **Retrieve + Generate** — sawaal se top chunks nikal, LLM ko context+sawaal bhej → *3.5*

## Code: skeleton — har step ek function

```python
# rag_overview.py — RAG ka minimum skeleton (har line samjho)
# Setup: pip install langchain-community langchain-huggingface faiss-cpu
# rag_example.txt banao — andar daalo:
#   "Student discount 10th standard ko 50% off milta hai."

from langchain_community.document_loaders import TextLoader          # (1) loader
from langchain.text_splitter import RecursiveCharacterTextSplitter  # (2) chunker
from langchain_huggingface import HuggingFaceEmbeddings             # (3) embed
from langchain_community.vectorstores import FAISS                  # (4) vector DB

def load_documents(path):                                  # step-1
    return TextLoader(path).load()

def split_chunks(docs, size=1000, overlap=200):            # step-2
    sp = RecursiveCharacterTextSplitter(chunk_size=size, chunk_overlap=overlap)
    return sp.split_documents(docs)

def make_embeddings():                                     # step-3
    return HuggingFaceEmbeddings(model_name="BAAI/bge-small-en-v1.5")

def build_vector_store(chunks, emb):                       # step-4
    return FAISS.from_documents(chunks, emb)

def retrieve(db, question, k=3):                           # step-5
    ret = db.as_retriever(search_kwargs={"k": k})
    return ret.get_relevant_documents(question)

docs   = load_documents("rag_example.txt")   # 1. load
chunks = split_chunks(docs)                  # 2. chunk
emb    = make_embeddings()                   # 3. embed model
db     = build_vector_store(chunks, emb)     # 4. store
hits   = retrieve(db, "Student discount kya hai?")
print("Retrieved", len(hits), "chunks")
```

Line-by-line: `TextLoader(path).load()` — text file → `Document` list (har ek `page_content` + `metadata`). `RecursiveCharacterTextSplitter` — 1000 chars/chunk, last 200 chars agla chunk mein repeat. `HuggingFaceEmbeddings("bge-small-en-v1.5")` — local 384-dim model (free, ~84MB). `FAISS.from_documents` — vectors + similarity index (first run 10-20s lagta hai). `as_retriever(k=3)` — top-3 chunks dega. `get_relevant_documents(q)` — q ko bhi embed karo, FAISS se nearest-3 lao.

## TEST

**Run:** `python rag_overview.py` (rag_example.txt ke saath, usi folder mein).
**Expected:**
```
Retrieved 3 chunks
```
**Troubleshooting:**
- `No module named 'langchain_community'` → `pip install langchain-community`
- `FileNotFoundError: rag_example.txt` → script wahi folder mein chalao jahan file hai
- chunks < 3 → example.txt chhota hai → text ko `".... " * 5` ya karo, ya file badi likho
- pehle FAISS/emb run par 10-30s → ek baar cache ho gaya toh fast — normal hai

## Nutshell

RAG = document ka sahi hissa lo, phir likhao — bina retrain kiye. 5 steps: load → chunk → embed → store → retrieve + generate.

## Common Mistakes
- ❌ Prompt mein *"use docs se answer karo"* likhne se model apni yaad se likhta → fix: hard `Answer using ONLY this context`
- ❌ Poora doc ek chunk mein → context overflow + dilated retrieval → fix: chunk_size 500-1000
- ❌ Embedding dim mismatch (384 vs 768) → FAISS crash → fix: index + query dono same model se

## What It Is NOT
- ⚠️ Fine-tuning nahi — model kabhi update nahi hota, bas uss context ko prompt mein daal kar dete hain
- ⚠️ Hallucination-proof nahi — agar chunk bhi galat ho, LLM phir bhi galat bana sakta — garbage in, garbage out
- ⚠️ *"Docs jod do, answer mille"* nahi — chunks ache hon chahiye — 3.2/3.4 pe dhyan do

## In Your Own Words

<details>
<summary>1. RAG ke 5 steps ko ek line mein likho.</summary>
**Jawab:** Load → Chunk → Embed → Store → Retrieve+Generate. Document lao, chhote tukdo mein todo, numbers mein badlo, vector DB mein daalo, sawaal se nearest nikal, LLM se likwa.
</details>

<details>
<summary>2. Prompt mein "use docs" likhne se RAG chal uta hai kya?</summary>
**Jawab:** Nahin — model sirf apni training yaad karega. RAG mein do zaroori hain: (a) ek retriever jo sahi chunk nikale, (b) uss chunk ko prompt ke andar daalna. Prompt alone ≠ RAG.
</details>

<details>
<summary>3. Embedding zaroori kyun — nahi to seedha text compare kar sakte?</summary>
**Jawab:** Kyunki similarity vectors par chalti hai, text direct compare kam accurate hota hai. Embedding se text → meaning-wala vector milta hai — jisme "discount" ≈ "50% off" ek do ke paas aate hain.
</details>
