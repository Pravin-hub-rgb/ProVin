Jab tum Zomato pe order karte ho, tumhe ek "delivery time" dikhata hai — 20 min, 35 min, 1 hour. Tumhe nahi pata exact kitne minutes mein khana aayega, but tumhe ek **andaaza** mil jaata hai ki zyada der lagegi ya kam. Based on that, tum decide karte ho — "ye order karna chahiye ya nahi."

DSA me bhi same cheez hoti hai. Tumhe nahi pata exact code kitne milliseconds chalega. But tumhe ek **estimate** chahiye ki 10 elements pe chalega ya 10 lakh elements pe. Wahi hai Time Complexity — code ka "delivery time" estimate.

---

## ✅ Time Complexity kya hai?

> **Time Complexity batata hai ki tumhara code kitne steps lega input ke size ke saath.**

Jaise Zomato ka delivery time depends karta hai order complexity pe (sirf chai = fast, biryani + 5 sides = slow), waise hi code ka time depends karta hai hai input kitna bada hai.

**Important:** Hum exact time nahi nikalte (seconds/ms me). Hum kehte hain — "input 2x bada ho to steps kitne guna badhenge?" That's what Big O tells you.

### Proper Definition

> **Time Complexity of an algorithm is a function, T(n), that measures how the running time grows as the size of the input, n, increases. It's expressed in terms of the number of operations (or steps) the algorithm performs — not in seconds — so it stays meaningful no matter which machine runs it.**

That's the textbook version. Let me unwrap it so it actually lands:

- **"Function T(n)"** is just fancy talk for: *tie the input size `n` to the amount of work done.* Kaam kitna hai, input ke hisaab se — bas yahi hai.
- **"Number of operations, not seconds"** means we count steps (like each loop iteration), not milliseconds. Kyun? Kyunki seconds depend on the hardware — a fast laptop runs the same code way faster than a slow phone. But the *count of steps stays the same* on both. So counting steps is the honest measure; counting seconds is noisy.
- **Back to Zomato:** delivery time depends on the *order* (chai fast, 5 sides slow), not on which delivery guy happens to be fastest today. Same idea — time depends on *input size (n)*, not on the machine.

---

## ✅ Big O Kya Hai?

Big O notation ek **upper bound** hai — worst case me kitna time lagega.

Sochlo tumhe 100 names ka phone book me ek naam dhundna hai. Agar tum **ek ek karke** sab check karo — ye O(n) hai. Agar tum **seedha page khol lo** jahan naam hota hai — ye O(1) hai.

Big O tumhe batata hai ki approach **kitni efficient hai** compared to other approaches.

---

## ✅ Common Time Complexities (ye yaad karo)

### O(1) — Constant Time

Ek kaam, chahe input 1 ho ya 1 crore — same time.

```js
function getFirst(arr) {
  return arr[0]; // bas pehla element nikaalo
}

// 10 elements ho ya 10 crore — ek hi step
```

**Real life:** Tumhe apna phone number yaad karna — ek step, hamesha same time.

---

### O(n) — Linear Time

Input jitna bada, utne zyada steps. Har element pe ek kaam.

```js
function findMax(arr) {
  let max = arr[0];
  for (let i = 1; i < arr.length; i++) {  // n times chalega
    if (arr[i] > max) {
      max = arr[i];
    }
  }
  return max;
}

// 10 elements = 10 steps
// 1000 elements = 1000 steps
```

**Real life:** Tum apne purane messages scroll kar rahe ho — jitne messages, utna time.

---

### O(n²) — Quadratic Time

Ek loop ke andar doosra loop — nested loops. Har element ke liye pura loop chalta hai.

```js
function hasDuplicate(arr) {
  for (let i = 0; i < arr.length; i++) {        // n times
    for (let j = i + 1; j < arr.length; j++) {  // n times har i ke liye
      if (arr[i] === arr[j]) return true;
    }
  }
  return false;
}

// 10 elements = 100 steps (10 x 10)
// 100 elements = 10,000 steps
```

**Real life:** Class me sabse har student ka har doosre student se pair banana — n(n-1)/2 pairs. Students badho to pairs exponentially badhte hain.

---

### O(log n) — Logarithmic Time

Har step me aadha kaam khatam ho jaata hai. Binary search ka pattern.

```js
function binarySearch(arr, target) {
  let left = 0;
  let right = arr.length - 1;

  while (left <= right) {
    let mid = Math.floor((left + right) / 2);
    if (arr[mid] === target) return mid;
    if (arr[mid] < target) left = mid + 1;
    else right = mid - 1;
  }
  return -1;
}

// 1000 elements = max ~10 steps
// 1,000,000 elements = max ~20 steps
```

**Real life:** Dictionary me word dhundhte ho — "M" ke paas jao, phir "Ma" ke paas, phir "Mar" — har baar aadha eliminate. 1000 page ki dictionary me max 10 steps.

---

### O(n log n) — Linearithmic Time

Most efficient sorting algorithms (Merge Sort, Quick Sort average case).

```js
// Merge Sort — har level pe n kaam hota hai, log n levels hoti hain
// Total = n x log n

// 10 elements ≈ 33 steps
// 100 elements ≈ 664 steps
// 1000 elements ≈ 9966 steps
```

**Real life:** Tumhe 50 students ko groups me baatna hai pehle pairs me, phir groups of 4 me, phir groups of 8 me — har level pe sabse baat karo (n), aur levels log n hain.

## ✅ The Cheat Sheet

| Big O | Name | Kab hota hai | Example |
|-------|------|-------------|---------|
| O(1) | Constant | Ek step me kaam ho jaaye | Array ka first element access karna |
| O(log n) | Logarithmic | Har step me aadha eliminate ho | Binary Search |
| O(n) | Linear | Ek loop, har element pe kaam | Find max in array |
| O(n log n) | Linearithmic | Sort karna efficiently | Merge Sort |
| O(n²) | Quadratic | Nested loops | Compare every pair |
| O(2^n) | Exponential | Har element pe 2 choices | Subsets generate karna (recursion) |

**Yaad rakhna:** O(1) > O(log n) > O(n) > O(n log n) > O(n²) — pehla best hai, last worst.

## ✅ Code ko analyze kaise karein?

**Rule 1: Single loop = O(n)**
```js
for (let i = 0; i < n; i++) {
  // O(n)
}
```

**Rule 2: Nested loop = O(n²)**
```js
for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) {
    // O(n²)
  }
}
```

**Rule 3: Loop jo aadha cut kare = O(log n)**
```js
while (left <= right) {
  let mid = Math.floor((left + right) / 2);
  // ...
  left = mid + 1; // ya right = mid - 1
  // Har step me aadha eliminate — O(log n)
}
```

**Rule 4: Constants ignore karo**
```js
// Ye bhi O(n) hai, O(2n) nahi
for (let i = 0; i < n; i++) {
  console.log(i);
}
for (let j = 0; j < n; j++) {
  console.log(j);
}

// Dono alag alag O(n) hain, but Big O me constants nahi rakhte
```

**Rule 5: Different variables = different scales**
```js
// O(n + m) — n aur m alag sizes hain
for (let i = 0; i < n; i++) { }
for (let j = 0; j < m; j++) { }

// O(n × m) — nested, different sizes
for (let i = 0; i < n; i++) {
  for (let j = 0; j < m; j++) { }
}
```

## ✅ Worst case vs Best case

Ek simple example:
```js
function linearSearch(arr, target) {
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === target) return i;
  }
  return -1;
}
```

- **Best case:** Target pehle element pe hai — O(1)
- **Worst case:** Target last me hai ya hai hi nahi — O(n)
- **Average case:**大概 O(n/2) which simplifies to O(n)

Interview me zyadatar **worst case** pucha jaata hai. That's the standard.

---

## ✅ What It Is NOT

- **Big O exact time nahi batata.** Ye batata hai trend — input badhe to time kaise badhega. 2 second ya 20 second nahi, but "linear badhega" ya "square badhega" batata hai.

- **O(n²) hamesha bura nahi hai.** Agar n bahut chhota hai (10 ya 20 elements), to O(n²) bhi thik hai. Big O matters when n is large.

- **Constants matter nahi karte.** O(2n) = O(n), O(100n) = O(n). Reason: jab n 1 crore ho, to 2 ya 100 ka farq nahi padta — dono "linear" hain.

- **Space aur Time alag cheezein hain.** Time complexity batata hai kitne steps, space complexity batata hai kitni memory. Dono ka alag analysis hota hai (next topic me cover karenge).

**In Your Own Words**

1. Tumhe ek array me sabse bada number dhundna hai. Tumne ek loop lagaya jo har element check karta hai. Iska time complexity kya hai, aur kyun?

<details>
<summary>Show Answer</summary>

**Sample Answer:** O(n) hai kyunki tum ek baar array ke har element pe ja rahe ho. Input jitna bada (n), utne steps. Koi shortcut nahi hai — tumhe sab check karna padega kyunki kisi ko bhi bada ho sakta hai.

</details>

2. Agar tumhe do arrays hain — ek size n ka aur ek size m ka — aur tum har element ko har doosre element se compare karo, to time complexity kya hogi?

<details>
<summary>Show Answer</summary>

**Sample Answer:** O(n × m) hogi. Kyunki tum nested loop use kar rahe ho — pehla loop n baar chalega, har baar doosra loop m baar chalega. Total steps = n × m. Agar dono arrays same size ke hain (n = m), to O(n²) bol sakte ho.

</details>

3. Binary Search itna fast kyun hai compared to Linear Search?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Binary Search har step me aadha data eliminate kar deta hai. Linear Search ek ek karke check karta hai. 1 million elements me Linear Search ko max 1 million steps lagenge, Binary Search ko max ~20 steps. Ye exponential difference hai — jaise phone book me seedha page kholna vs ek ek page padhna.

</details>

4. Agar kisi code me 3 alag loops hain jo sab n elements pe chalte hain (nested nahi, sequential), to overall time complexity kya hogi?

<details>
<summary>Show Answer</summary>

**Sample Answer:** O(n) hogi. Kyunki constants ignore hote hain Big O me. 3 separate loops = O(3n) = O(n). Input badhe to har loop linear badhega, total bhi linear badhega.

</details>

5. Tumhara ek function hai jo pehle array sort karta hai (O(n log n)), phir usme ek loop lagata hai (O(n)). Total time complexity kya hogi?

<details>
<summary>Show Answer</summary>

**Sample Answer:** O(n log n) hogi. Kyunki sort (n log n) > loop (n), to sort wala part dominant hai. Big O me sirf sabse bada term rakhte hain — chhote terms ko drop kar dete hain. Same logic: agar tumhare paas O(n²) + O(n) hai, to O(n²) likhoge.

</details>
