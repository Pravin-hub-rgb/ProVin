These are three methods that exist on every single function. All three do exactly the same thing, just slightly differently.

---

## What do they do?

All three let you **manually force** what the value of `this` will be inside the function.

Remember: normally `this` is decided automatically by how you call the function. These three methods let you override that completely. No exceptions.

---

## ✅ First let's set up our example:

```js
function introduce(city, country) {
  console.log(`I am ${this.name} from ${city}, ${country}`);
}

const person = { name: "Arjun" };
```

✅ `person` object has name. `introduce` function expects `this.name` to exist.

If I call normally:
```js
introduce(); // I am undefined from undefined, undefined
```

❌ `this = window`, there is no name.

---

## 🟢 `call()`

`call` runs the function immediately. You pass arguments one by one.

```js
introduce.call(person, "Delhi", "India");
```

Now wait. Look at this carefully.

Our function `introduce(city, country)` expects `city` as the first parameter. But the first thing we passed here is `person`, not `"Delhi"`. That looks wrong, right?

Here is why:

**`call` reserves its first argument for `this`.** The very first slot is always "which object should play the role of `this` inside the function?" It is not for the function's parameters. It is for the context object.

So the actual mapping looks like this:

```
introduce.call(  person,     "Delhi",     "India"    )
                    ↑           ↑            ↑
              this value      city         country
              (the object)    (1st param)  (2nd param)
```

See the shift? `person` is not `city`. It is `this`. The function's real parameters (`city`, `country`) start from the **second argument** of `call`. The first argument is always reserved — it tells the function "hey, use this object as `this` inside you."

If you accidentally passed it like this:
```js
introduce.call("Delhi", "India");
// ❌ Now this = "Delhi" (a string), and "India" becomes city
// Function does: console.log(`I am ${"Delhi".name} from India, undefined`)
// Output: I am undefined from India, undefined
```

That is why you always pass the object first, then the real arguments.

✅ What happens:
- `this` is forced to be `person`
- The function runs immediately
- Arguments are passed normally after first parameter

✅ Output: `I am Arjun from Delhi, India`

---

## 🟢 `apply()`

`apply` also runs the function immediately. But you pass arguments as an array.

```js
introduce.apply(person, ["Delhi", "India"]);
```

Same rule as `call`. First argument is reserved for `this`, second argument is an array of the function's parameters.

```
introduce.apply(  person,     ["Delhi", "India"]  )
                     ↑                ↑
               this value      array of params
               (the object)    [city, country]
```

The only difference from `call`: instead of passing `city` and `country` as separate arguments, you wrap them in an array.

✅ Exactly same result. Only difference is you pass an array instead of separate arguments.

This is very useful when you already have arguments in an array.

---

## 🟢 `bind()`

`bind` does NOT run the function immediately.

It returns a brand new function with `this` permanently fixed forever.

```js
const boundFn = introduce.bind(person, "Delhi");
```

Same rule again. First argument = `this`. And then the function's parameters follow.

But notice something interesting here: we only passed `"Delhi"` (city), not `"India"` (country). That is allowed. `bind` lets you **partially apply** arguments. You can set some arguments now and pass the rest later when you actually call the function.

```
introduce.bind(  person,     "Delhi"    )
                    ↑           ↑
              this value      city
              (the object)    (1st param — set now)

boundFn("India");
//            ↑
//         country (2nd param — passed later)
```

So the mapping works like this:
- `bind` gets the first argument as `this` → `person`
- `bind` gets the next arguments as the function's params → `"Delhi"` is `city`
- When you later call `boundFn("India")`, `"India"` fills in the remaining param → `country`

✅ What happens:
- `this` is permanently set to `person`
- It does NOT run the function
- It returns a new function that you can call later

✅ Now you can call it any time:
```js
boundFn("India");
```

✅ Output: `I am Arjun from Delhi, India`

⚠️ Once you `bind` a function, it can never be changed. You cannot re-bind it again. It is permanently fixed.

## 📋 Side by side comparison

| Method | Runs immediately? | Arguments passed as |
|---|---|---|
| `call` | ✅ Yes | Individual values |
| `apply` | ✅ Yes | Array |
| `bind` | ❌ No | Partial / later |

## 🎯 Real world use case

This is exactly what you used to do in React class components:

```js
class MyComponent {
  constructor() {
    this.handleClick = this.handleClick.bind(this);
  }

  handleClick() {
    // now `this` always refers to the component instance
  }
}
```

This is why everyone had `bind` calls in every constructor.
