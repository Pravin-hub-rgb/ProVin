
This is how inheritance works in JavaScript. No classes. No magic. Just simple objects pointing to other objects.

---

## ✅ Ok first: what is an object?

An object is just a box. You put keys and values inside it.

```js
const dog = {
  name: "Bruno",
  bark: function() { console.log("woof"); }
}
```

✅ That's it. Just a box with things inside.

---

## ✅ Now the most important fact about JavaScript objects:

✅ Every single object in JavaScript has one extra secret hidden key inside it.

This key is called `__proto__`.

And this key always points to another object. Always.

✅ Which object?
By default, when you create any normal object, it points to the base `Object.prototype`. This is why all objects get methods like `toString()` automatically.

✅ Example:
```js
const car = {
  name: "Tesla"
};

// I never added toString() to car. But this works perfectly:
console.log(car.toString()); // "[object Object]"
```

✅ Why does this work?
Because `car.__proto__ = Object.prototype` automatically. And `toString()` exists on `Object.prototype`. So when you call it, it travels up the chain.

But you can change `__proto__` to point to any other object you want. That is how you do inheritance.

That is all. That is prototype. Nothing more.

---

## ✅ What is the prototype chain?

When you try to get something from an object:

```js
console.log(dog.bark);
```

JavaScript does this:
1.  First it looks **inside the dog box itself**
2.  If it finds it, it gives it to you.
3.  If not found, it goes to whatever `dog.__proto__` is pointing to.
4.  It looks inside that box.
5.  If not found, it goes to `that object.__proto__`
6.  It keeps going up until it reaches `null`.
7.  If not found anywhere, returns `undefined`.

✅ This is called the prototype chain.

✅ **Formal definition:**
Prototype chaining is the mechanism by which JavaScript objects inherit properties and methods from one another. When a property is not found on an object, JavaScript automatically looks for it on the object's prototype, continuing up the chain until the property is found or the end of the chain is reached.

That is all it is.

---

## ✅ Simple example:

```js
const animal = {
  breathe: function() { console.log("breathing"); }
};

const dog = {
  bark: function() { console.log("woof"); }
};

// Tell dog: your secret __proto__ key now points to animal
// Object is a built-in global object that comes with JavaScript — always available, like console.
Object.setPrototypeOf(dog, animal);
```

Now:
```js
dog.bark();    // ✅ found directly inside dog box → works
dog.breathe(); // ❌ not inside dog → go to dog.__proto__ → found inside animal → works
```

That's it. That is inheritance in JavaScript.

## ✅ Constructor functions and `new` keyword

Setting `__proto__` manually on every single object is tedious:

```js
const dog = { bark: function() { console.log("woof"); } };
// Object.setPrototypeOf is a helper that JavaScript provides — it does the same thing as setting __proto__ directly.
const puppy = Object.setPrototypeOf({}, dog);  // so much work for one object
```

If you need 1000 objects that all share the same prototype, doing this manually for each one is not practical. There has to be a way to automate it.

That is what constructor functions do. A constructor function is just a regular function, but when you call it with `new`, JavaScript automatically does the prototype wiring for you.

Here is what happens when you put `new` in front of a function call:

```js
new Person("Arjun");
```

✅ JavaScript automatically does 4 things:
1.  Creates a brand new empty object `{}`
2.  Sets `this = that new empty object` inside the function
3.  Runs the function
4.  Returns that new object automatically (even if you don't write return)

And one extra thing — the thing that makes inheritance work:
✅ It also sets `newObject.__proto__ = Person.prototype` automatically.

So `new` saves you from having to write `Object.setPrototypeOf(...)` every single time.

## ✅ What is `.prototype` ?

Now here is the second problem.

If you create 1000 person objects, and each one needs a `greet` method, where do you put it? You could add it inside the constructor:

```js
function Person(name) {
  this.name = name;
  this.greet = function() { console.log(`Hi I'm ${this.name}`); };
}

const p1 = new Person("Arjun");
const p2 = new Person("Priya");
```

But now every single person object has its **own copy** of the `greet` function. 1000 objects = 1000 copies of `greet` in memory. Same function, same behavior, duplicated 1000 times. That is a waste of memory.

What if instead, all 1000 objects could **share** the same single `greet` function? They would all point to the same place in memory.

That is exactly what `.prototype` is for.

✅ **Every single function in JavaScript automatically gets a property called `.prototype` created for it.**

It is just an empty object `{}` that comes free with every function. And anything you put on this `.prototype` object gets shared by every object created with that constructor.

---

## ✅ Constructor function prototype

This is the way everyone actually uses it:

```js
function Person(name) {
  this.name = name;  // ← unique to each instance
}

// Person.prototype is just an empty object that already exists. Let's add something to it.
Person.prototype.greet = function() {  // ← shared by ALL instances
  console.log(`Hi I'm ${this.name}`);
};
```

✅ What happens:
- Every function automatically gets `.prototype` empty object
- We add `greet` function to this object **once**
- Every object created with `new Person()` will automatically have its `__proto__` point to `Person.prototype`
- When you call `p1.greet()`, JavaScript does not find `greet` on `p1` itself, so it looks up `p1.__proto__` (which is `Person.prototype`) and finds it there

```js
const p1 = new Person("Arjun");
const p2 = new Person("Priya");

p1.greet(); // Hi I'm Arjun
p2.greet(); // Hi I'm Priya
```

✅ `greet` is only written **once** in memory.
✅ All 1000 person instances share the exact same single function.
✅ No wasted memory. This is the entire point of `.prototype`.

---

## ✅ `hasOwnProperty`

This is how you check if a property exists directly inside the box, not somewhere up the chain:

```js
p1.hasOwnProperty("name");  // ✅ true → directly inside p1
p1.hasOwnProperty("greet"); // ❌ false → up the chain on Person.prototype
```

That is the full correct answer.
