In the last topic, you saw `await fetch('/api/users')` used as an example over and over. But what actually is `fetch`? Where does it come from? And why does it work the way it does?

Let's step back and think about what's actually happening when you write `fetch('/api/users')`.

Your JavaScript code is running in a browser. That browser is on your computer. The API server is on a different computer somewhere else — maybe in a data center on the other side of the world. Your code needs to send a message across the internet to that server, wait for it to process the request, and bring back a response.

That's what `fetch` does. It's the bridge between your JavaScript code and the rest of the internet.

---

## The Restaurant Phone Analogy

Imagine you're at a restaurant and you want to order food from a different restaurant across the street. You can't just shout across the street — that won't work. You need a phone.

You pick up the phone, dial the number (that's the URL), and place your order. The person on the other end takes your order and says "we'll have it ready in 20 minutes." Then you hang up and go back to your conversation.

When the food is ready, the phone rings. You pick it up, and they say "your order is ready." You walk across the street and pick it up.

The phone is `fetch`. The phone number is the URL. The order you place is the request. The call back when it's ready is the Promise resolving. Walking across the street to pick up the food is like calling `.json()` on the response to extract the data.

---

## ✅ What is Fetch?

> **Fetch is a built-in browser API for making HTTP requests. It returns a Promise that resolves with the server's response.**

Let's unpack that.

**"Built-in browser API"** — you don't need to install anything. No `npm install`. No import statement. It's just there, available globally, in every modern browser. Like `console.log` or `Math.random`. Open any browser console and type `fetch` — you'll see the function.

**"Making HTTP requests"** — your browser communicates with servers using a protocol called HTTP. A request is your browser saying "give me this data" (GET) or "here's some data, save it" (POST). Fetch is the function that lets your JavaScript code make these requests directly, without reloading the page.

**"Returns a Promise"** — this is why you use `fetch` with `await` or `.then()`. The server might be on the other side of the world. The request takes time. Fetch returns a Promise so your code doesn't freeze while waiting.

**"Resolves with the server's response"** — when the server responds, the Promise resolves with a Response object. That object contains the status code (200, 404, 500), headers, and the body. You then parse the body using methods like `.json()` or `.text()`.

All it does: it makes a request to another computer over the internet, and gives you back the response.

---

## ✅ Basic GET Request

GET is the default. When you visit a website, your browser is making GET requests to load the page, images, CSS, and JavaScript. When you type a URL and hit Enter, that's a GET request.

```js
async function getUser() {
  const res = await fetch('https://api.example.com/user/1');

  if (!res.ok) {
    throw new Error(`HTTP error: ${res.status}`);
  }

  const data = await res.json();
  return data;
}
```

Let's break this down:

1. `fetch('https://api.example.com/user/1')` — Send a GET request to this URL. GET is the default method, so we don't need to specify it.

2. `const res = await fetch(...)` — Wait for the server to respond. The response object (`res`) contains the status code, headers, and the body.

3. `if (!res.ok)` — `res.ok` is `true` for status codes 200-299 (success). It's `false` for 404, 500, and any other error status. **This is important:** fetch does NOT throw an error for 404 or 500. It only rejects on network failures (like the server being unreachable or the internet being down). You must check `res.ok` manually.

4. `throw new Error(...)` — If the status is not ok, we throw an error. This will be caught by the nearest `.catch()` or `try/catch` block.

5. `const data = await res.json()` — The response body comes back as a raw stream of bytes. `.json()` reads that stream, parses it from JSON string into a JavaScript object, and returns it. This also returns a Promise, so we `await` it.

6. `return data` — Return the parsed JavaScript object.

## ✅ POST Request — Sending Data

GET requests only retrieve data. To send data to the server (like creating a new user, submitting a form, or posting a comment), you need a POST request.

```js
async function createUser(userData) {
  const res = await fetch('/api/users', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json'
    },
    body: JSON.stringify(userData)
  });

  return await res.json();
}
```

Fetch takes two arguments:

1. **URL** — Where you're sending the request
2. **Options object** — All the settings for this request

Let's break down each property in the options object:

| Property | What it does |
|---|---|
| `method: 'POST'` | The HTTP method. POST means "create a new resource." |
| `headers` | Metadata about the request. Tells the server what you're sending and how to interpret it. |
| `Content-Type: 'application/json'` | The most important header. It tells the server: "I am sending you JSON data. Parse my body as JSON." |
| `body` | The actual data you want to send to the server. |
| `JSON.stringify(userData)` | The internet only understands strings. You cannot send JavaScript objects directly. You must convert them to a JSON string first. |

---

## ✅ The two most common mistakes

**Mistake #1: Forgetting `Content-Type` header**

```js
// ❌ WRONG
fetch('/api/users', {
  method: 'POST',
  body: JSON.stringify(userData)
});
```

Without the `Content-Type: application/json` header, most servers will look at the body and not know what format it's in. They'll just ignore it. Your request goes through, but the server receives an empty body. This is the #1 mistake everyone makes when learning fetch.

**Mistake #2: Forgetting `JSON.stringify()`**

```js
// ❌ WRONG
fetch('/api/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: userData  // userData is a JavaScript object, not a string!
});
```

If you pass a JavaScript object directly as the body, JavaScript will convert it to the string `[object Object]`. The server receives `[object Object]` as the body. All your data is garbage.

Always use `JSON.stringify()` to convert your object to a JSON string before sending.

---

## ✅ Other HTTP Methods

```js
method: 'PUT'     // Replace an entire existing resource
method: 'PATCH'   // Update only part of a resource
method: 'DELETE'  // Remove a resource
```

- **PUT** — "Replace this entire thing with what I'm sending." If the resource has 10 fields and you only send 2, the other 8 get cleared.
- **PATCH** — "Update only these specific fields." If you send 2 fields, only those 2 change. The rest stay as they were.
- **DELETE** — "Remove this resource."

In practice, many APIs just use POST for everything and decide what to do based on the URL. But using the correct method is good practice and follows REST conventions.

---

## ✅ What It Is NOT

- **Fetch is NOT a library.** You don't `npm install fetch`. It's built into the browser. However, Node.js (server-side JavaScript) did not have fetch built in until version 18. In older Node versions, you needed a library like `node-fetch` or `axios`. As of Node 18+, fetch is available globally there too.

- **Fetch is NOT the same as axios.** Axios is a third-party library that does the same thing as fetch but with some differences: axios automatically parses JSON, automatically rejects on HTTP errors (404, 500), and has a cleaner API for things like request cancellation and progress tracking. Fetch is the browser-native standard; axios is an alternative with more features.

- **Fetch does NOT reject on HTTP errors.** This is the most important gotcha. A 404 or 500 response is still a valid HTTP response. Fetch only rejects if the network itself fails — no internet connection, DNS lookup failed, server unreachable. You must always check `res.ok` or `res.status` manually.

- **`res.json()` is NOT the same as `res.text()`.** The response body can be parsed in different formats. `.json()` parses it as JSON. `.text()` gives you the raw string. `.blob()` gives you binary data (for images, files). You can only call one of these methods — once the body is read, it's consumed. Calling `.json()` and then `.text()` on the same response will throw an error.

## 🧠 Interview Questions

> ❓ Does fetch throw an error on 404?
> No. Fetch only rejects on network failure. You must always check `response.ok` or `response.status` to handle HTTP errors. This is a common gotcha that catches beginners off guard.

> ❓ What is the difference between fetch and axios?
> Axios automatically transforms JSON responses, automatically rejects on HTTP error status codes, supports request cancellation, and has a more concise API for setting default headers. Fetch is built into the browser and is the standard, but requires manual handling of JSON parsing and error checking.

> ❓ What does response.json() do?
> It reads the response body stream, parses it from JSON string format into a JavaScript object, and returns a Promise that resolves with that object. It's asynchronous because reading the body stream takes time.

> ❓ Why do you need to await response.json()?
> Because the response body arrives as a stream over the network. It might not all be there yet when the response headers arrive. `.json()` reads that stream as it arrives and only resolves when the entire body is parsed. That's why it returns a Promise.

> ❓ What happens if you call response.json() on a non-JSON response?
> It throws a SyntaxError because it tries to parse something that isn't valid JSON. Always check `res.ok` first, and consider using `res.text()` if you're not sure the response is JSON.

> "The Fetch API is a modern browser standard for making HTTP requests. It returns Promises, which work naturally with async/await. A critical gotcha is that fetch does not reject on HTTP error status codes like 404 or 500 — it only rejects on network failures. You must always check the `ok` property on the response object. For sending data, you need to set the `Content-Type` header and stringify the body with `JSON.stringify()`. The response body is parsed using methods like `.json()` or `.text()`, which also return Promises."

async function signupUser(name, email, password) {

2. You write `fetch('/api/data')` and the server returns a 500 error. Does your `.catch()` block run? Why or why not?

<details>
<summary>Show Answer</summary>

**Sample Answer:** No, the `.catch()` block does NOT run. Fetch only rejects on network failures (no internet, DNS failure, server unreachable). A 500 error is still a valid HTTP response — the server received the request, processed it, and sent back a response. The response just happens to indicate an error. You must check `res.ok` or `res.status` inside the `.then()` block to handle HTTP errors.

</details>

3. What's the difference between `fetch` and `axios`? When would you choose one over the other?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Fetch is built into the browser — no installation needed. Axios is a third-party library you need to install. Axios automatically parses JSON responses, automatically rejects on HTTP errors (404, 500), supports request cancellation natively, and has a cleaner API for setting default headers across all requests. Fetch is lighter (no dependency) and is the web standard, but requires more manual work. For a small project or learning, fetch is fine. For a large production app with many API calls, axios saves time and reduces boilerplate.

</details>

4. You call `res.json()` and then try to call `res.text()` on the same response. What happens? Why?

<details>
<summary>Show Answer</summary>

**Sample Answer:** It throws an error. The response body is a stream that can only be read once. Once `.json()` reads and parses it, the stream is consumed. Calling `.text()` on the same response tries to read an already-consumed stream, which fails. If you need the data in multiple formats, read it once with `.text()` and then parse it manually with `JSON.parse()` if needed.

</details>

5. Imagine you're building a weather app. You need to fetch data from `https://api.weather.com/current?city=Mumbai`. Write the function. What could go wrong? How would you handle errors?

<details>
<summary>Show Answer</summary>

**Sample Answer:**

```js
async function getWeather(city) {
  try {
    const res = await fetch(`https://api.weather.com/current?city=${city}`);

    if (!res.ok) {
      throw new Error(`Weather API returned ${res.status}`);
    }

    const data = await res.json();
    return data;
  } catch (err) {
    console.error("Failed to get weather:", err.message);
    return null; // Return null so the UI can show a fallback
  }
}
```

Things that could go wrong: the API server is down (network error), the city name is invalid (404), the API key is missing (401), the response is not valid JSON (parse error), or the user has no internet connection. The `try/catch` catches network errors and parse errors. The `res.ok` check catches HTTP errors. Returning `null` on failure lets the UI gracefully show "Weather unavailable" instead of crashing.

</details>
