This is one of the most asked interview questions. And also the most useful optimization pattern.

---

## ✅ What is Memoization?

✅ **The simplest explanation in the world:**

> When you call a function with some inputs, you get an output.
> 
> You write down: **"For these exact inputs → this is the answer"**
> 
> Next time you call that same function again with exactly the same inputs, you don't run the whole function again. You just look it up and return the answer you already wrote down.

That is all memoization is. Nothing more.

✅ This is exactly what happens:
```js
// Without memoization
square(5); // calculates → 25
square(5); // calculates again → 25
square(5); // calculates again → 25

// With memoization
square(5); // calculates → 25
square(5); // ✅ FROM CACHE → 25
square(5); // ✅ FROM CACHE → 25
```

---

## ✅ Why do we need it?

Some functions are very expensive. They take a long time to run.

✅ If you call the function **again with exactly the same inputs** - why would you calculate the same answer again?

✅ You can just return the old answer you already calculated.

This will make your code 10x, 100x, 1000x faster.

---

## ✅ How it works:

1.  We create an empty object called `cache`
2.  Every time the function runs:
3.  Check: is this input already in the cache?
4.  ✅ If YES: return the cached value. Done.
5.  ❌ If NO: run the function, store the result in cache, return it.

---

## ✅ Working implementation:

We are going to build this function step by step exactly how you would write it.

---

✅ **Step 1:** First create the outer function. It accepts the function we want to make faster.

```js
function memoize(fn) {

}
```

---

✅ **Step 2:** Create our cache storage. This will live forever.

```js
function memoize(fn) {
  const cache = {};
}
```

---

✅ **Step 3:** Return a new function. This is the function that you will actually call.

```js
function memoize(fn) {
  const cache = {};

  return function(...args) {

  };
}
```
✅ `...args` = rest operator. It collects ALL arguments that are passed, no matter how many.

---

✅ **Step 4:** Convert arguments into a key we can store.

```js
function memoize(fn) {
  const cache = {};

  return function(...args) {
    const key = JSON.stringify(args);
  };
}
```
✅ This turns whatever arguments you pass into a string we can use as an object key.

---

✅ **Step 5:** Check if we already have this key in cache.

```js
function memoize(fn) {
  const cache = {};

  return function(...args) {
    const key = JSON.stringify(args);

    if (cache[key]) {
      console.log("✅ Returning from cache");
      return cache[key];
    }
  };
}
```
✅ If we already have it, return it immediately. We are done.

---

✅ **Step 6:** If we don't have it, run the original function.

```js
function memoize(fn) {
  const cache = {};

  return function(...args) {
    const key = JSON.stringify(args);

    if (cache[key]) {
      console.log("✅ Returning from cache");
      return cache[key];
    }

    console.log("⛏️ Calculating new result");
    const result = fn(...args);
  };
}
```

---

✅ **Step 7:** Store the new result in cache for next time, then return it.

```js
function memoize(fn) {
  const cache = {};

  return function(...args) {
    const key = JSON.stringify(args);

    if (cache[key]) {
      console.log("✅ Returning from cache");
      return cache[key];
    }

    console.log("⛏️ Calculating new result");
    const result = fn(...args);
    
    cache[key] = result;
    return result;
  };
}
```

✅ ✅ ✅ That's it. Done. That is the full complete working memoize function. We built it one step at a time.

---

## ✅ Usage:

```js
function slowSquare(n) {
  // imagine this takes 5 seconds to run
  return n * n;
}

const fastSquare = memoize(slowSquare);
```

✅ First call:
```js
fastSquare(5); // ⛏️ Calculating new result → 25
```

✅ Second call with same input:
```js
fastSquare(5); // ✅ Returning from cache → 25
```

✅ Second call is **instant**. Zero time.

## 🧠 Interview Questions

> ❓ What is memoization?
> An optimization technique that caches the result of expensive function calls, so that subsequent calls with the same arguments return the cached result instead of recomputing.

> ❓ What JavaScript concepts are required to implement memoization?
> Higher order functions, closures, rest operator.

> ❓ What is the downside of memoization?
> It uses extra memory to store the cache. You trade memory for speed.
