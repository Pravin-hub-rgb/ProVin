This is the trick that every JavaScript developer uses 100 times every day.

---

## ✅ What is it?

✅ JavaScript logical operators do **NOT** return `true` or `false`.

✅ They return one of the actual values you passed to them.

✅ And they stop evaluating immediately as soon as they know the answer.

---

## ✅ `&&` Operator

✅ Stops at the first falsy value and returns it.
✅ If all are truthy returns the last value.

```js
0 && 100;      // 0
true && 5;     // 5
null && "hi";  // null
1 && 2 && 3;   // 3
```

✅ This is exactly why this works:
```js
const name = user && user.name;
```
✅ If `user` is null, it returns null. It never even tries to access `user.name`. No crash.

---

## ✅ `||` Operator

✅ Stops at the first truthy value and returns it.
✅ If all are falsy returns the last value.

```js
0 || 100;      // 100
"" || "Guest"; // "Guest"
true || 5;     // true
0 || false || null; // null
```

✅ This is how you provide default values:
```js
const displayName = username || "Guest";
```

---

## ✅ Where you see this the most: React JSX

✅ This is the most common pattern in all of React:
```jsx
{isLoggedIn && <Dashboard />}
```

✅ If `isLoggedIn` is truthy → returns and renders `<Dashboard />`
✅ If `isLoggedIn` is falsy → returns that falsy value and renders nothing.

✅ This is exactly how conditional rendering works.

## 🧠 Interview Questions

> ❓ Do logical operators in JavaScript return booleans?
> No. They return one of the operands.

> ❓ What does `&&` return?
> First falsy value, otherwise last value.

> ❓ What does `||` return?
> First truthy value, otherwise last value.

> ❓ Why does `{condition && <Component />}` work in React?
> Because if condition is falsy it returns that falsy value, and React ignores falsy values when rendering.
