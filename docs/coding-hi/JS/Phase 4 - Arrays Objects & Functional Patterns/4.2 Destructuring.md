## ✅ What is Destructuring?

✅ Destructuring is just a syntax shortcut to extract values from objects and arrays directly into variables.

You don't have to write `user.name`, `user.age`, `user.city` 100 times.

---

## ✅ Object Destructuring

✅ Before:
```js
const name = user.name;
const age = user.age;
const city = user.city;
```

✅ After:
```js
const { name, age, city } = user;
```

✅ Exactly same result.

---

## ✅ Default values

If the property does not exist you can set a default:
```js
const { name, age, city = "Delhi" } = user;
```

✅ If user.city is undefined, it will use "Delhi".

---

## ✅ Rename while destructuring

```js
const { name: userName } = user;
```

✅ Now you have variable `userName` instead of `name`.

---

## ✅ Nested Destructuring

```js
const { address: { street, zip } } = user;
```

---

## ✅ Array Destructuring

✅ Before:
```js
const first = arr[0];
const second = arr[1];
```

✅ After:
```js
const [first, second] = arr;
```

✅ Skip elements:
```js
const [, , third] = arr;
```

✅ Rest operator:
```js
const [first, second, ...rest] = arr;
```

---

## ✅ In function parameters

✅ This is the most common pattern in React.

```jsx
function UserCard({ name, age, isAdmin = false }) {
  return (
    <div>
      <h3>{name}</h3>
      <p>{age} years old</p>
    </div>
  );
}
```

✅ 90% of React components are written exactly like this.

---

## ✅ Common mistakes:

❌ Don't forget the curly braces
❌ Defaults only apply to `undefined`, not `null` or `0`
❌ You cannot destructure something that is `null` / `undefined`

## 🧠 Interview Questions

> ❓ What is the difference between destructuring and property access?
> It is just syntax sugar. It does exactly the same thing under the hood.

> ❓ What happens if you destructure a property that doesn't exist?
> It will be `undefined`, unless you provide a default value.

> ❓ Can you destructure while importing modules?
> Yes. `import { useState, useEffect } from 'react'` is destructuring.
