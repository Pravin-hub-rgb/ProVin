✅ Forget all the fancy words.

Imagine you have a calculator that needs 3 numbers to add them up.

✅ **Normal function:** You have to give it **all 3 numbers RIGHT NOW**
```js
add(1, 2, 3);
```
You have no choice. You have to pass all three at the same time.

✅ **Curried function:** You can give it numbers **one at a time**

First you make the curried version:
```js
const curriedAdd = curry(add);
```

✅ **Important:**
✅ `add` is your original normal function. It is the exact same function from the example above.
✅ You pass this normal function into `curry()`
✅ `curry()` gives you back a NEW magic function. That is `curriedAdd`.
✅ Your original `add` function is not changed at all. It still works exactly like before.

Now you can use it step by step:
```js
const addWith1 = curriedAdd(1);
// ✅ At this point it remembers the 1. It is waiting for more numbers.

const addWith1And2 = addWith1(2);
// ✅ Now it remembers BOTH 1 and 2. Still waiting for the last number.

const total = addWith1And2(3);
// ✅ Now it has all 3 numbers. Finally it adds them all up: 1 + 2 + 3 = 6
```

✅ Every step returns a new function that remembers all the numbers you have given it so far.

✅ It will keep returning functions **FOREVER** until it gets exactly 3 numbers.

```js
const addWith1 = curriedAdd(1);
addWith1(3); // ❌ Only 2 numbers total. Still returns another function. Not a number.

addWith1(2)(3); // ✅ Exactly 3 numbers. Now returns 6.
```

✅ If you give it 4 numbers it will ignore the extra ones.
✅ If you give it less than 3 it will keep waiting.
✅ It will only run the actual calculation **exactly when it has all 3**.

✅ You don't have to give them all at once. You can take breaks. You can store these intermediate functions anywhere you want.

✅ When you finally give it the last number, only then does it actually run the calculation.

---

## ✅ What is the point?

✅ Partial application. You can pre-fill some arguments now, and provide the rest LATER.

```js
const addFive = add(5);
```

✅ Now you have a brand new function that always adds 5 to whatever number you give it:
```js
addFive(3); // 8
addFive(10); // 15
addFive(100); // 105
```

✅ This is how you create reusable specialized functions. This is an extremely powerful pattern.

## ✅ Working implementation:

We will build this function step by step.

---

✅ **Step 1:** Create outer curry function. It accepts the original function.

```js
function curry(fn) {

}
```

---

✅ **Step 2:** Return inner function that collects arguments.

```js
function curry(fn) {
  return function curried(...args) {

  };
}
```

---

✅ **Step 3:** Check: do we have all the arguments already?

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn(...args);
    }
  };
}
```
✅ If YES: just run the original function and return result. We are done.

---

✅ **Step 4:** If NO: return another function that will collect more arguments later.

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn(...args);
    }

    return function(...moreArgs) {
      return curried(...args, ...moreArgs);
    };
  };
}
```

✅ That is it. Full complete curry function.

## ✅ Usage:

```js
const add = (a, b, c) => a + b + c;
const curriedAdd = curry(add);
```

✅ All of these work:
```js
curriedAdd(1)(2)(3);    // 6
curriedAdd(1, 2)(3);    // 6
curriedAdd(1, 2, 3);    // 6
```

✅ Partial application:
```js
const addFive = curriedAdd(5);
addFive(3)(2); // 10
```

## 🧠 Interview Questions

> ❓ What is currying?
> Transforming a function that takes multiple arguments into a sequence of functions each taking a single argument.

> ❓ What is the advantage of currying?
> Partial application. You can create reusable specialized functions by pre-filling some arguments.

> ❓ What is the difference between currying and partial application?
> Currying always produces nested functions. Partial application is the act of pre-filling arguments.
