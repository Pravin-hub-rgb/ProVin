## ✅ What is Event Bubbling?

What happens when you click a button that is inside a div that is inside another div?

```html
<div id="outer">
  <div id="inner">
    <button id="btn">Click Me</button>
  </div>
</div>
```

If all three have click handlers — does only the button's handler run? Or does the button's handler run, then the inner div's, then the outer div's?

You might expect the button's handler to be the only one that fires. After all, you clicked the button, not the div. But JavaScript events do not work that way.

✅ When you click an element, the event does not stop at that element. **It travels UP through every single parent element all the way to the top of the document.** This is called **bubbling** — like a bubble rising through water, the event rises through the DOM tree.

```html
<div id="grandparent">
  <div id="parent">
    <button id="child">Click Me</button>
  </div>
</div>
```

```js
child.addEventListener("click", () => console.log("child"));
parent.addEventListener("click", () => console.log("parent"));
grandparent.addEventListener("click", () => console.log("grandparent"));
document.addEventListener("click", () => console.log("document"));
```

✅ If you click the button this will log:
```
child
parent
grandparent
document
```

✅ Every single one fires. In that order.

## ✅ Stopping Bubbling

Bubbling is usually useful (it enables event delegation), but sometimes you want to stop it.

What if clicking a "delete" button inside a card should NOT trigger the card's click handler (which might navigate to a detail page)?

```html
<div id="card" onclick="openDetail()">
  <button id="deleteBtn">Delete</button>
</div>
```

Without stopping bubbling, clicking the delete button would fire both the button's handler and then the card's handler — deleting the item AND navigating to the detail page. That is not what you want.

✅ Use `event.stopPropagation()` to stop the event from traveling further up:
```js
child.addEventListener("click", function(event) {
  event.stopPropagation();
});
```

✅ Now only the child event will fire. None of the parents will receive the event.

## ✅ Capturing Phase

What if you need to intercept an event **before** it reaches the target? For example, you want to log all clicks on a page, but you want the log to happen before any element's click handler runs.

The event model has three phases, not just one:

```
CAPTURING PHASE → TARGET PHASE → BUBBLING PHASE
```

1. **Capturing** — Event travels **DOWN** from `document` to the target element
2. **Target** — Event reaches the actual element that was clicked
3. **Bubbling** — Event travels **UP** from the target back to `document` (this is what we have been talking about so far)

By default, `addEventListener` listens during the bubbling phase. But you can listen during the capturing phase by passing `{ capture: true }`:

```js
parent.addEventListener("click", handler, { capture: true });
```

Now this handler fires before the target's handler and before any bubbling handlers. The event is intercepted on its way down, before anything else handles it.

✅ 99% of the time you will never need this. Bubbling is default. But now you know capturing exists and why.

## 🧠 Interview Questions

> ❓ Explain event bubbling
> When an event fires on an element it propagates upwards through all ancestor elements.

> ❓ What is the order of event phases?
> Capturing → Target → Bubbling

> ❓ How do you stop event bubbling?
> event.stopPropagation()

> ❓ What is the difference between stopPropagation and stopImmediatePropagation?
> stopPropagation stops bubbling. stopImmediatePropagation also stops other listeners on the same element.

## 🎯 Interview Ready Answer

> "Event bubbling is the mechanism by which events propagate upwards from the target element through all ancestor elements to the top of the document. This is the default behaviour and enables event delegation patterns. Bubbling can be stopped with event.stopPropagation()."

That is the full correct answer.
