## Cheat Sheet (Quick Recall)

```tsx
import { BrowserRouter, Routes, Route, Link } from "react-router-dom";

// BrowserRouter wraps the entire app
<BrowserRouter>
  <Routes>
    <Route path="/" element={<Home />} />
    <Route path="/about" element={<About />} />
  </Routes>
</BrowserRouter>

// Use Link instead of <a> — no page reload
<Link to="/about">About</Link>

// Programmatic navigation
const navigate = useNavigate();
navigate("/about");       // push
navigate("/about", { replace: true });  // replace history
navigate(-1);             // back (history stack)

// NavLink — styling for active route
<NavLink to="/" className={({ isActive }) => isActive ? "active" : ""}>
  Home
</NavLink>
```

## What Happened So Far

In 2.7, we built the To-Do App v2 — Context API for theme toggle, useEffect for categories, useRef for auto-focus. But that was all on **one page**. The user clicked from one component to another — no, actually, everything rendered on the same screen.

Now we'll learn **navigation** — using React Router to create multiple pages, render components based on the URL, and navigate from one "page" to another without a browser reload.

## Broader Goal

React Router gives a multi-page feel even though the real app is a single page (SPA — Single Page Application). On traditional websites, every link click loads a new HTML page from the server — a full page reload. In an SPA, only the component changes, no page reload. This makes the app feel fast and the user experience is seamless.

In Batch 3, we'll learn: building routes, dynamic URLs (like `movies/tt123456`), nested layouts, and protected routes (pages only accessible after login). First, let's understand the React Router setup.

## Step 2 — BrowserRouter: The Router Provider

Before any routing, it's mandatory to wrap your app in `<BrowserRouter>`. BrowserRouter tells React "I'll track URL changes and render accordingly." It's a provider component — just like Context's provider.

```tsx
// main.tsx or App.tsx — wherever your entry point is
import { BrowserRouter } from "react-router-dom";

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </React.StrictMode>,
);
```

**Why BrowserRouter?** Other routers exist — `HashRouter` (uses `#` in the URL, for older browsers), `MemoryRouter` (for testing). `BrowserRouter` is the standard for production — it uses the HTML5 History API and gives clean URLs (`/about`, `/contact`).

> **What It Is NOT:** BrowserRouter doesn't tell the server anything. When you visit `/about`, the browser makes no request to the server — React decides which component to show. That's why in production, you must configure the server to serve `index.html` for all routes. For now, just remember — Vite handles this in development.

## Step 3 — Routes and Route: URL → Component Mapping

`<Routes>` is a container for `<Route>` components. Each Route maps a path to a component:

```tsx
import { Routes, Route } from "react-router-dom";

function App() {
  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/about" element={<About />} />
      <Route path="/contact" element={<Contact />} />
    </Routes>
  );
}
```

**How it works:**
1. User types `/about` in the browser
2. React Router searches each Route's path for a match
3. Where it matches (`path="/about"`), that `element` renders
4. `<Home />` and `<Contact />` don't render — only the matching component

**Important:** Only one Route's element renders at a time. Inside `<Routes>`, only the first match wins. If nothing matches, nothing renders — that's why you use `path="*"` for a 404 page.

```tsx
<Route path="*" element={<NotFound />} />
```

`*` means "any remaining paths." Place it last — specific routes first, then `*`.

## Step 4 — Link: Instead of `<a>`

If you use `<a href="/about">` in an SPA, the browser does a full page reload — the entire app reloads, state is lost. So React Router provides the `<Link>` component:

```tsx
import { Link } from "react-router-dom";

function Navbar() {
  return (
    <nav>
      <Link to="/">Home</Link>
      <Link to="/about">About</Link>
      <Link to="/contact">Contact</Link>
    </nav>
  );
}
```

`<Link>` renders an `<a>` tag in the browser, but calls `event.preventDefault()` on click and uses React Router's internal history to change the URL. No reload — just a component swap.

**Think about it:** If this were a restaurant menu — `<a>` sends the waiter to the kitchen to bring a whole new meal (reload). `<Link>` tells the waiter "keep the table, just swap the plate." This small thing dramatically affects app speed and user experience.

## Step 5 — useNavigate: Navigation from Code

Sometimes you need to navigate after a button click, form submission, or async operation. `<Link>` can't do this — it only handles click events. That's where the `useNavigate` hook comes in:

```tsx
import { useNavigate } from "react-router-dom";

function LoginPage() {
  const navigate = useNavigate();

  function handleLogin() {
    // ...login logic...
    navigate("/dashboard"); // go to dashboard after login
  }

  return (
    <div>
      <button onClick={handleLogin}>Login</button>
    </div>
  );
}
```

**Common patterns with `useNavigate`:**

```tsx
navigate("/about");                    // push a new history entry
navigate("/about", { replace: true }); // replace instead of push
navigate(-1);                          // go back one step (history stack)
navigate(2);                           // go forward two steps
```

Use `replace: true` when you don't want the user to return to the current page via back — like after login, so back doesn't send them back to the login page.

## Step 6 — NavLink: Active Route Styling

`NavLink` is an advanced `<Link>`. When its `to` matches the current URL, it gets an active class — so you can highlight the current page in navigation:

```tsx
import { NavLink } from "react-router-dom";

function Navbar() {
  return (
    <nav>
      <NavLink to="/" className={({ isActive }) => isActive ? "nav-link active" : "nav-link"}>
        Home
      </NavLink>
      <NavLink to="/movies" className={({ isActive }) => isActive ? "nav-link active" : "nav-link"}>
        Movies
      </NavLink>
    </nav>
  );
}
```

Here `isActive` is a boolean that NavLink passes automatically. When the current URL is `/movies`, the second NavLink gets `"nav-link active"`. Style `.active` in CSS:

```css
.nav-link { color: gray; text-decoration: none; }
.nav-link.active { color: blue; font-weight: bold; }
```

## Mini-Project: Movie Browser (Part 1 — Home Page)

We'll build this mini-project in two parts. Part 1 (here) — home page with a movie list and links. Part 2 (3.2) — movie detail page with dynamic routes.

### Step 1 — Movie Data + Home Page Component

First, a simple movie list component:

```tsx
// components/MovieList.tsx
import { Link } from "react-router-dom";

const movies = [
  { id: "tt1375666", title: "Inception", year: 2010 },
  { id: "tt0816692", title: "Interstellar", year: 2014 },
  { id: "tt0133093", title: "The Matrix", year: 1999 },
  { id: "tt0167260", title: "The Lord of the Rings: The Return of the King", year: 2003 },
  { id: "tt0111161", title: "The Shawshank Redemption", year: 1994 },
];

export default function MovieList() {
  return (
    <div>
      <h1>🍿 Movie Browser</h1>
      <div className="movie-grid">
        {movies.map((movie) => (
          <div key={movie.id} className="movie-card">
            <h3>{movie.title}</h3>
            <p>{movie.year}</p>
            <Link to={`/movies/${movie.id}`}>View Details →</Link>
          </div>
        ))}
      </div>
    </div>
  );
}
```

Notice the dynamic path in `<Link to={\`/movies/${movie.id}\`}>`. Each movie gets its own detail page, and this path will be captured by `useParams` in 3.2.

### Step 2 — App.tsx with Router Setup

```tsx
// App.tsx
import { BrowserRouter, Routes, Route } from "react-router-dom";
import MovieList from "./components/MovieList";

function HomePage() {
  return (
    <div>
      <h2>Welcome to Movie Browser</h2>
      <p>Browse our collection of classic movies.</p>
    </div>
  );
}

export default function App() {
  return (
    <BrowserRouter>
      <div className="app">
        <nav>
          <Link to="/">Home</Link>
          <Link to="/movies">Movies</Link>
        </nav>
        <Routes>
          <Route path="/" element={<HomePage />} />
          <Route path="/movies" element={<MovieList />} />
          <Route path="*" element={<h2>404 — Page not found</h2>} />
        </Routes>
      </div>
    </BrowserRouter>
  );
}
```

**Why `<BrowserRouter>` inside App?** Some developers wrap it in `main.tsx`, others in App.tsx. Both work — the difference is scope. If you wrap it in App, all router-related code stays together. It depends on your project structure.

### Step 3 — Test It

1. `/` → shows "Welcome to Movie Browser"
2. `/movies` → shows 5 movies, each with a "View Details" link
3. `/movies/tt1375666` → blank page for now (no matching route — we fix this in 3.2)
4. `/xyz` → shows "404 — Page not found"

## What It Is NOT

- **React Router is not server-side routing** — it's client-side. The URL changes but no server request is made.
- **`<Link>` still renders an `<a>` tag** — it just overrides the default behavior. CSS styling works the same as a normal `<a>`.
- **React Router doesn't make the app multi-page** — it's still a single page (SPA) that *feels* multi-page. That's what "Single Page Application" means.
- **The router must be at the top level of the component tree** — BrowserRouter needs to be above all Routes, Links, and useNavigate calls, or they won't work.

## In Your Own Words

<details>
<summary>Why use React Router instead of plain `<a>` tags?</summary>

A plain `<a>` tag triggers a full page reload — the browser fetches a new HTML page from the server, the React app's entire state resets, and there's a flash (blank screen) during load. React Router's `<Link>` component does a client-side component swap — state is preserved, no reload, and transitions are smooth.
</details>

<details>
<summary>What does `<BrowserRouter>` do, and why must it wrap the app?</summary>

BrowserRouter is a provider component that gives React Router information about browser URL changes. It listens to `window.location` and the HTML5 History API — when the URL changes, it triggers a re-render of the matching `Routes`. Without a router at the top, `Routes`, `Link`, and `useNavigate` can't work because the routing context wouldn't exist.
</details>

<details>
<summary>What does `path="*"` match, and where should it go?</summary>

`*` matches any URL that didn't match any other Route. It's used for 404 pages. It must be placed last in `<Routes>` — specific paths first, then `*`. This is because Routes matches sequentially and renders the first match.
</details>

<details>
<summary>What's the difference between `useNavigate` and `<Link>`? When use which?</summary>

`<Link>` is a component — it handles click events on visible links. `useNavigate` is a hook — it returns a function you call from code (event handlers, async callbacks, timers). Use `<Link>` when the navigation is a visible link in your UI. Use `useNavigate()` when the navigation happens after an action — form submit, API response, timeout.
</details>

<details>
<summary>What does `<NavLink>` provide that `<Link>` doesn't? What is `isActive`?</summary>

`<NavLink>` is `<Link>`'s enhanced version — it automatically detects whether its `to` matches the current URL. `isActive` is a boolean that gets passed to the `className` or `style` function — `true` means this NavLink's route is the current route. You use it to apply an "active" style, like bold or a different color, so the navigation highlights the current page.
</details>
