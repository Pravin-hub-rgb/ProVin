## Where We Left Off

In 1.5.1 we learned interfaces, in 1.5.2 we learned the props concept — passing data into a component with `interface ComponentProps`. Now we'll cover **optional props**, **destructuring**, and **default values** — these three patterns are used in every React component.

## Broader Goal

Some properties are always required, others sometimes omitted. In interfaces, `?` marks a property as optional. Destructuring cleans up our code — instead of `props.name`, just use `name` directly. Default values handle the case where a prop wasn't provided. We'll build a simple GreetingCard that demonstrates optional sender handling.

## Step 1 — Optional Props (The Question Mark)

Think: "Maybe not everyone has a role — a junior developer might not have one assigned yet. Can I make that optional?"

**Concept:** Add `?` after a property name in the interface to make it optional. If it's not passed, it's `undefined`.

```tsx
interface ProfileCardProps {
  name: string;
  role?: string;  // optional
}

function ProfileCard(props: ProfileCardProps): JSX.Element {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>{props.role || "No role specified"}</p>
    </div>
  );
}

<ProfileCard name="Vin" role="React Developer" />  // ✅
<ProfileCard name="Priya" />                         // ✅ role is optional
```

`role?` means "this property may or may not exist." `{props.role || "No role specified"}` uses the `||` operator — if `role` is undefined, fall back to a default string.

### Common Mistake — Forgetting the `?`

```tsx
interface ProfileCardProps {
  name: string;
  role: string;  // ❌ required — must always be provided
}

<ProfileCard name="Priya" />  // ❌ Error: property 'role' is missing
```

TypeScript gives a compile-time error. This is one of TypeScript + React's superpowers — bugs are caught during development, before reaching the browser.

## Step 2 — Destructuring Props

Think: "Writing `props.name`, `props.role` repeatedly is tedious. Is there a shortcut?"

**Concept:** JavaScript **destructuring** pulls object properties directly into variables.

```tsx
interface ProfileCardProps {
  name: string;
  role?: string;
}

// Destructuring in the function parameter
function ProfileCard({ name, role }: ProfileCardProps): JSX.Element {
  return (
    <div>
      <h2>{name}</h2>
      <p>{role || "No role specified"}</p>
    </div>
  );
}

function ProfileCard({ name, role }: ProfileCardProps): JSX.Element { ... }
```

The `{ name, role }` destructures the props object. Now you use `name` and `role` directly — no need to write `props.` every time.

Destructuring is standard practice in React. Look at any professional React code and every component uses destructuring.

### Without vs With Destructuring

```tsx
// Without destructuring
function ProfileCard(props: ProfileCardProps) {
  return <h2>{props.name}</h2>;
}

// With destructuring
function ProfileCard({ name }: ProfileCardProps) {
  return <h2>{name}</h2>;
}
```

Both do the same thing. Destructuring is just syntactic sugar — it makes the code shorter and more readable.

## Step 3 — Default Values in Destructuring

Think: "The `||` operator for defaults works, but can I set a default right inside destructuring?"

**Concept:** You can assign default values during destructuring: `{ role = "No role specified" }`.

```tsx
function ProfileCard({ name, role = "No role specified" }: ProfileCardProps) {
  return (
    <div>
      <h2>{name}</h2>
      <p>{role}</p>
    </div>
  );
}

interface ButtonProps {
  label: string;
  variant?: "primary" | "secondary";
  disabled?: boolean;
}

function Button({ label, variant = "primary", disabled = false }: ButtonProps) {
  // variant is optional, defaults to "primary"
  // disabled is optional, defaults to false
}
```

`role = "No role specified"` — if `role` is undefined, this default value is used. The interface has `role?`, but in the destructuring you assign a default value.

This pattern appears everywhere in professional React code:

```tsx
interface ButtonProps {
  label: string;
  variant?: "primary" | "secondary";
  disabled?: boolean;
}

function Button({ label, variant = "primary", disabled = false }: ButtonProps) {
  // variant is optional, defaults to "primary"
  // disabled is optional, defaults to false
}
```

## Step 4 — Mini-Project: Simple GreetingCard

A simple GreetingCard that handles an optional sender — with destructuring:

```tsx
interface GreetingCardProps {
  recipient: string;
  message: string;
  sender?: string;
}

function GreetingCard({ recipient, message, sender }: GreetingCardProps) {
  return (
    <div style={{ border: "1px solid #ddd", padding: "16px", borderRadius: "8px", marginBottom: "8px" }}>
      <h2>Hello, {recipient}!</h2>
      <p>{message}</p>
      {sender && <p style={{ color: "#666" }}>— {sender}</p>}
    </div>
  );
}

export default GreetingCard;
```

`{sender && <p>...` — this is conditional rendering. If `sender` exists, render the paragraph; otherwise, render nothing. The `&&` operator is used for this — when `sender` is undefined or null, React renders nothing.

```tsx
<GreetingCard recipient="Vin" message="Happy Birthday!" sender="Priya" />
<GreetingCard recipient="Team" message="Great work this week!" />
```

The first card shows the sender; the second doesn't.

## Summary

- **Optional props:** `role?: string` — add `?` after the property name
- **`||` fallback:** `props.role || "default"` — alternative value when undefined
- **Destructuring:** `function Card({ name, role }: Props)` — no need to write `props.`
- **Default values:** `role = "No role specified"` — defaults right inside destructuring
- **Conditional rendering:** `{sender && <p>{sender}</p>}` — only renders if `sender` exists
