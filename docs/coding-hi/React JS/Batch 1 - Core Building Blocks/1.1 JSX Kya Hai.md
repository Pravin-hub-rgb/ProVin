## Broader Goal

We're about to start actual coding. But one thing needs to be clear first — the code inside `App.tsx` is not HTML. It's **JSX**. And without understanding JSX, we can't write any components.

This document's goal: understand what JSX is, how it works, and how it differs from HTML.

## Step 1 — Open `App.tsx` and See What's There

Think: "I ran `npm run dev`, the browser shows something. Where's the code that creates this page?"

Why: You need to understand how the React entry point works. Until you see the source code, you won't know where the page comes from.

Open `src/App.tsx`:

```tsx
function App() {
  return (
    <div>
      <h1>Hello, World!</h1>
      <p>This is my first React app.</p>
    </div>
  );
}

export default App;
```

> **Note:** Your code might look slightly different if you experimented with the Greeting component from 0.8. That's fine — the concepts are the same. We'll write fresh code in the next step.

Look at what's after `return` — code that looks like HTML, but it's inside a JavaScript file. How does the browser know to render this?

The browser doesn't. And this isn't valid JavaScript syntax either.

## Step 2 — What is JSX?

Think: "This `<div>` `<h1>` code — how is it running inside JavaScript? The browser understands HTML, CSS, and JavaScript. What is this hybrid?"

Why: If you use JSX without understanding it, it'll feel like magic. When an error occurs, you won't know why. So you need to understand it first.

**Concept:** JSX stands for **JavaScript XML** — it's a syntax extension for JavaScript that looks like HTML. But the browser can't execute JSX directly. When you run `npm run dev`, Vite runs a compiler (esbuild) in the background that converts JSX into `React.createElement` calls.

This conversion works like this:

```
// What you write (JSX):
<div>Hello, World!</div>

// Vite converts it to (React.createElement):
React.createElement("div", null, "Hello, World!")
```

`React.createElement` is a plain JavaScript function that returns an object — the very object that tells React what to render on screen.

## Step 3 — Prove It to Yourself

Think: "You say JSX converts to `React.createElement`. Show me the proof."

Add a line to `src/App.tsx`:

```tsx
function App() {
  console.log(typeof <h1>Hello</h1>);

  return (
    <div>
      <h1>Hello, World!</h1>
    </div>
  );
}
```

Open the browser console (F12). What does it print?

```
object
```

The `typeof <h1>Hello</h1>` is `object` — not a string, not HTML, but a JavaScript object. And if you `console.log(<h1>Hello</h1>)`, you'll see something like:

```
{ type: 'h1', props: { children: 'Hello' } }
```

That's a React Virtual DOM node. JSX is just a more readable way to create these objects.

**That's why JSX is called "syntactic sugar"** — it's something that's pleasant to write, but underneath, something else is happening.

## Step 4 — Differences Between HTML and JSX

Think: "JSX looks like HTML. Can I just write HTML the same way?"

Why: No. JSX has its own rules. Copy-paste HTML directly and you'll get errors.

**Difference 1 — `class` becomes `className`:**

```html
<!-- HTML -->
<h1 class="heading">Hello</h1>
```

```tsx
// JSX
<h1 className="heading">Hello</h1>
```

Why? Because `class` is a reserved keyword in JavaScript. So JSX uses `className` instead. React internally converts this back to the `class` attribute.

**Difference 2 — `for` becomes `htmlFor`:**

```tsx
<label htmlFor="email">Email</label>
```

Same reason — `for` is also a reserved keyword in JavaScript.

**Difference 3 — Self-closing tags:**

In HTML, `<br>` and `<input>` can go without being closed. In JSX, every tag must be closed:

```tsx
<br />
<input type="text" />
<img src="photo.jpg" alt="Photo" />
```

An error occurs if you don't close with `>`.

**Difference 4 — CamelCase attributes:**

```tsx
<button onClick={handleClick}>Click</button>
<input onKeyDown={handleKey} />
<div tabIndex={0}>Focusable div</div>
```

In HTML it's `onclick`, `onkeydown`, `tabindex` (lowercase). In JSX it's camelCase — `onClick`, `onKeyDown`, `tabIndex`.

Try it — write HTML-style by mistake:

```tsx
<button onclick={() => {}}>Click</button>
```

TypeScript will throw an error like: `Type '(event: MouseEvent) => void' is not assignable to type 'never'` — because React's type system only expects JSX-style props.

## Step 5 — JavaScript Expressions in JSX

Think: "JSX returns objects. How do I use JavaScript values inside JSX?"

Why: Static data has no use. Every component needs dynamic data — values stored in variables, returned from functions, typed by the user.

**Concept:** Inside JSX, use `{ }` curly braces to embed any JavaScript expression.

Try this in `App.tsx`:

```tsx
function App() {
  const name = "Vin";
  const currentYear = new Date().getFullYear();

  return (
    <div>
      <h1>Hello, {name}!</h1>
      <p>Year: {currentYear}</p>
      <p>Sum: {2 + 3}</p>
      <p>Uppercase: {name.toUpperCase()}</p>
    </div>
  );
}
```

What shows up in the browser:
- `{name}` → "Vin"
- `{currentYear}` → "2026"
- `{2 + 3}` → "5"
- `{name.toUpperCase()}` → "VIN"

**Important:** You can only embed **expressions**, not **statements**. That means:

✅ Correct: `{name}`, `{2 + 3}`, `{name.toUpperCase()}`, `{isLoggedIn ? "Hi" : "Hello"}`

❌ Wrong: `{if (true) { return "Hi" }}`, `{for (let i = 0; i < 5; i++) { }}`

If you try the wrong ones, you'll get: `Uncaught SyntaxError: Unexpected token 'if'`

## Step 6 — The Single Root Element Rule

Think: "Can I return two `<div>` elements at once?"

Try this in `App.tsx`:

```tsx
function App() {
  return (
    <h1>Heading</h1>
    <p>Paragraph</p>
  );
}
```

**Concept:** JSX has a strict rule — **a function can only return one root element**. You can't return two siblings at the same time.

The error you'll get: `Adjacent JSX elements must be wrapped in an enclosing tag` — because a JavaScript function can only return one value.

**Solutions:**

1. **Wrap in a `<div>`:**

```tsx
function App() {
  return (
    <div>
      <h1>Heading</h1>
      <p>Paragraph</p>
    </div>
  );
}
```

2. **Use a Fragment (`<>...</>`)** — when you don't need an extra DOM node:

```tsx
function App() {
  return (
    <>
      <h1>Heading</h1>
      <p>Paragraph</p>
    </>
  );
}
```

`<>` is a **Fragment** — it doesn't create an extra element in the DOM, it just groups JSX elements together.

Try it — inspect with developer tools. In the Fragment case, no extra `<div>` shows up. When you don't need an extra wrapper for styling, use Fragment.

## Summary

- JSX = JavaScript XML — looks like HTML, but it's actually `React.createElement` calls
- The browser doesn't understand JSX directly — Vite's compiler converts it
- Use `className` (not `class`), `htmlFor` (not `for`), camelCase attributes
- Every tag must be closed (self-closing tags too)
- Embed JavaScript expressions with `{ }`
- Return only one root element (wrap with `<div>` or `<>` Fragment)
