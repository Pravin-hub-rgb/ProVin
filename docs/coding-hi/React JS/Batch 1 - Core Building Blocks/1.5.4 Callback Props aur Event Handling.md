## Where We Left Off

In 1.5.1 we learned interfaces, 1.5.2 taught us the props concept, and 1.5.3 covered optional props, destructuring, and default values. Now we'll cover an important pattern — **callback props**. When a component needs to tell its parent something (like a button click, form submit), that's where callback props come in.

## Broader Goal

Props aren't just for data — they can also be **functions**. These are called **callback props**. Think of a button component — it just renders a button; it doesn't know what to do on click. The parent decides. The component just tells the parent "a click happened" — and the parent decides what to do next.

## Step 1 — Feel the Problem

Think: "I need an `AlertButton` — it just shows a button. When the user clicks, the parent should know. But the component doesn't know what should happen on click — the parent decides."

If props only carry data (strings, numbers, booleans) — how does this work? Because whatever the click action is, it might change: one place shows an alert, another does a `console.log`, another makes an API call.

**Solution:** Pass a function as a prop — the parent provides the function, the child calls it when the event happens.

## Step 2 — First, Understand: A Function That Takes a Function

Before callback props, let's grasp a simple JavaScript concept — **a function that takes another function as a parameter**.

```javascript
// This function takes a function as parameter
function execute(callback) {
  callback();  // call that function
}

// Create a function
const sayHello = () => console.log("Hello!");

// Pass it to execute — "please run this function"
execute(sayHello);
// Console: "Hello!"
```

Here's what happened: `sayHello` is a function. We passed it to `execute`. Inside `execute`, `callback` becomes `sayHello`, and calling `callback()` is the same as calling `sayHello()`.

```
execute(sayHello)
  → inside execute, callback = sayHello
  → callback() = sayHello()
  → prints "Hello!"
```

In this pattern:
- `execute` → acts like the **child** (receives a function, calls it)
- the caller (who writes `execute(sayHello)`) → acts like the **parent** (provides the function)

**Same idea in React:** The parent component (`App`) passes a function as a prop to the child component (`AlertButton`). The child calls it when an event happens (like a click).

## Step 2.5 — First, Understand: Props Are Always Wrapped in an Object

Before the callback case, let's clarify one thing — **in React, props always arrive wrapped in an object**. Whether it's a value or a function, they're all properties of the same props object.

Consider a simple `AlertButton` that takes two **regular value props**:

```tsx
// Child component
function AlertButton(props: { label: string; count: number }) {
  return (
    <div>
      <button>{props.label}</button>
      <p>Count: {props.count}</p>
    </div>
  );
}
```

```tsx
// Parent component
function App() {
  return <AlertButton label="Click" count={5} />;
}
```

When React renders `App`, what does `props` look like inside `AlertButton`?

```
<AlertButton label="Click" count={5} />
                            ↓
React internally creates something like:
React.createElement(AlertButton, { label: "Click", count: 5 })
                                     ↓
Inside AlertButton, props = { label: "Click", count: 5 }
                                     ↓
props.label → "Click"
props.count → 5
```

React took the JSX attributes (`label="Click"`, `count={5}`), put them into an **object** — `{ label: "Click", count: 5 }` — and passed that object to `AlertButton` as the first argument. That's why you write `props.label` — you're pulling a property out of that object.

**Now the callback case works the same way:**

```tsx
<AlertButton action={handleClick} />
                             ↓
React internally:
React.createElement(AlertButton, { action: handleClick })
                                     ↓
Inside AlertButton, props = { action: handleClick }
                                     ↓
props.action → the handleClick function
```

Exactly the same pattern. The only difference is the value is no longer a string or number — it's a **function**. But it's still wrapped in the same props object.

**Analogy:** Think of it like sending a package. The package (object) can contain a note (string), a number, or a remote control (function). But you can't send anything outside the package — everything goes inside the object. React's props is that package.

### Regular Prop vs Callback Prop — Same Pattern

| | Regular Prop | Callback Prop |
|---|---|---|
| Example | `label="Click"` | `action={handleClick}` |
| Props object | `{ label: "Click" }` | `{ action: handleClick }` |
| Access | `props.label` → "Click" | `props.action` → function |
| Usage | Display it | Call it: `props.action()` |
| Value type | string, number, boolean | **function** |

Both live in the same object. The difference is just that one value is data, the other is a function.

### Compare: Pure JavaScript vs React

```
Pure JS:          execute(sayHello)
                           ↓
                   callback = sayHello (direct parameter)

React JSX:        <AlertButton action={handleClick} />
                           ↓
                   props = { action: handleClick } (wrapped in object)
                   props.action = handleClick (extracted from object)
```

In pure JS, the function is passed directly as a parameter. In React, it's wrapped inside the props object. That's just how React's API is designed — **all props are collected into one object**. There's no deep reason — React was built that way.

Got it? Great, now let's see the full callback prop example in Step 3.

## Step 3 — Callback Props in React (No Destructuring)

Now let's build `AlertButton`. **No destructuring, no `onClick` confusion** — just `props.action`:

```tsx
// Child component
function AlertButton(props: { action: () => void }) {
  return <button onClick={props.action}>Show Alert</button>;
}
```

Line by line:

1. `props: { action: () => void }` — props is an object with a property `action`. `action` has the type `() => void` — a function that takes no arguments and returns nothing. `void` means "this function does its job without returning a value" — like `alert()`, `console.log()`
2. `onClick={props.action}` — when the button is clicked, React calls `props.action()`
3. "Show Alert" — hardcoded text for now, no label prop yet

```tsx
// Parent component
function App() {
  // Parent defines the function
  const handleClick = () => {
    alert("Button was clicked!");
  };

  return (
    <div>
      {/* Parent passes the function as a prop */}
      <AlertButton action={handleClick} />
    </div>
  );
}
```

**Flow — Parent vs Child:**

```
╔══════════════════════════════════════╗
║         PARENT (App)                 ║
║                                      ║
║  1. handleClick function defined      ║
║     (will show an alert)             ║
║                                      ║
║  2. Passed to child:                 ║
║     <AlertButton action={handleClick} ║
╚════════════════════╤═════════════════╝
                     │ prop passed
                     ▼
╔════════════════════╤═════════════════╗
║         CHILD (AlertButton)          ║
║                                      ║
║  3. props.action = handleClick       ║
║     (received)                       ║
║                                      ║
║  4. User clicks the button           ║
║                                      ║
║  5. props.action() is called         ║
║     → handleClick() runs             ║
╚════════════════════╤═════════════════╝
                     │ callback returns
                     ▼
╔══════════════════════════════════════╗
║      PARENT's code executes           ║
║                                      ║
║  6. alert("Button was clicked!")     ║
╚══════════════════════════════════════╝
```

### Parent vs Child — Who Does What

```
PARENT (App):
  → Defines the handleClick function
  → Passes it to child: action={handleClick}
  → Executes when called by child

CHILD (AlertButton):
  → Receives props.action = handleClick
  → User clicks the button
  → Calls props.action()
  → Notifies parent: "click happened"

Direction:
  props → Parent → Child (data flows down)
  callback → Child → Parent (signal flows up)
```

**What happened?** The child didn't decide anything. It just told the parent "click happened." The parent decides what to do next.

### Inline Arrow Functions

You don't need a separate function — you can pass one inline:

```tsx
// Parent passes a function as prop
<AlertButton action={() => alert("Clicked!")} />
```

`() => alert("Clicked!")` is a function. It runs when the click happens.

### Props vs Callbacks — Remember This

| | Regular Prop | Callback Prop |
|---|---|---|
| Data type | string, number, boolean | **function** |
| Example | `label="Click me"` | `action={() => alert()}` |
| What it does | Component displays data | Component notifies parent |
| Direction | Parent → Child | **Child → Parent** |

## Step 4 — Destructuring + Adding a Label

Think: "Writing `props.action` every time is repetitive. And the parent should decide the button's text too."

With destructuring, `props.action` shortens to just `action`:

```tsx
// Child component
interface AlertButtonProps {
  label: string;
  action: () => void;
}

function AlertButton({ label, action }: AlertButtonProps) {
  return <button onClick={action}>{label}</button>;
}
```

Now:
- `label` — the button text, the parent decides
- `action` — what happens on click, the parent decides

```tsx
// Parent component
function App() {
  return (
    <div>
      <h1>Callback Props Demo</h1>
      {/* Parent decides both label and action */}
      <AlertButton label="Click me" action={() => alert("Clicked!")} />
    </div>
  );
}
```

## Step 5 — The `on` Prefix Convention

Callback props usually start with `on` — `action` becomes `onAlert`, `onClick`, `onSubmit`.

| Callback | Meaning |
|----------|---------|
| `onClick` | Called when a button is clicked |
| `onSubmit` | Called when a form is submitted |
| `onDelete` | Called when a delete action happens |
| `onAdd` | Called when an add action happens |

This matches React's built-in event names (`onClick`, `onChange`, etc.). Just by looking at the code, you know it's a callback prop — a child → parent signal.

Let's rename `action` to `onAlert` in `AlertButton`:

```tsx
// Child component
interface AlertButtonProps {
  label: string;
  onAlert: () => void;
}

function AlertButton({ label, onAlert }: AlertButtonProps) {
  return <button onClick={onAlert}>{label}</button>;
}
```

```tsx
// Parent with three different callbacks
<AlertButton label="Save" onAlert={() => alert("Saved!")} />
<AlertButton label="Delete" onAlert={() => alert("Deleted!")} />
```

## Step 6 — Callbacks with Parameters

Think: "Can the callback take parameters? What if the child needs to send data back to the parent?"

```tsx
// Child component
interface MessageButtonProps {
  onSend: (message: string) => void;   // callback with a parameter
}

function MessageButton({ onSend }: MessageButtonProps) {
  return <button onClick={() => onSend("Hello from child!")}>Send</button>;
}
```

Here, `onSend: (message: string) => void` means the callback takes a string parameter and returns nothing. When the button is clicked, the component calls `onSend("Hello from child!")` — passing a message back to the parent.

```tsx
// Parent component
function App() {
  const handleMessage = (msg: string) => {
    console.log("Child said:", msg);
  };

  return (
    <div>
      <MessageButton onSend={handleMessage} />
    </div>
  );
}
```

**Flow:**

```
Parent (App):
  → handleMessage: takes msg parameter, logs it
  → Passed to child: onSend={handleMessage}

Child (MessageButton):
  → onSend = handleMessage received
  → User clicks
  → onSend("Hello from child!") called
  → handleMessage("Hello from child!") runs
  → Console: "Child said: Hello from child!"
```

The child can send data to the parent this way.

### Common Function Type Syntax

```tsx
onAlert: () => void                 // no params, returns nothing
onSend: (message: string) => void   // takes a string, returns nothing
onChange: (id: number) => boolean   // takes a number, returns a boolean
```

## Step 7 — Real Example: Multiple AlertButtons

`components/AlertButton.tsx`:

```tsx
// Child component
interface AlertButtonProps {
  label: string;
  onAlert: (message: string) => void;
}

function AlertButton({ label, onAlert }: AlertButtonProps) {
  return (
    <button onClick={() => onAlert(`Button "${label}" was clicked!`)}>
      {label}
    </button>
  );
}

export default AlertButton;
```

`App.tsx`:

```tsx
// Parent component
import AlertButton from "./components/AlertButton";

function App() {
  const handleAlert = (msg: string) => {
    console.log(msg);
    alert(msg);
  };

  return (
    <div>
      <h1>Callback Props Demo</h1>
      <AlertButton label="Save" onAlert={handleAlert} />
      <AlertButton label="Delete" onAlert={handleAlert} />
      <AlertButton label="Submit" onAlert={handleAlert} />
    </div>
  );
}
```

Three buttons, all from the same `AlertButton` component. When any button is clicked, the parent receives a message — "Button 'Save' was clicked!", "Button 'Delete' was clicked!", etc.

### Recap: Data Flow

```
Parent (App)
  → passes onAlert function to
  → AlertButton (child)
  → User clicks
  → AlertButton calls onAlert()
  → Parent's function executes
```

That's the pattern for callback props — **child → parent communication**. Regular props carry data from parent → child. Callback props carry signals from child → parent.

## Summary

- **Callback props** = functions passed as props
- **Syntax:** `onClick: () => void` — a function type in the interface
- **Convention:** start with `on` — `onClick`, `onAdd`, `onDelete`
- **With parameters:** `onAdd: (text: string) => void` — passing data back to parent
- **Direction:** Callbacks enable **child → parent** communication
- **Inline arrow:** `onAlert={() => alert("Clicked")}` — inline callback
