## Step 1 – Think: App Architecture

No code yet. Think this through first.

**Features:** User types a task, clicks Add, it appears in the list. Each task has a checkbox (complete/incomplete) and a delete button. Three filter buttons: All, Active, Completed. A summary at the bottom: "3 / 5 items left" and a "Clear Completed" button.

**Component tree – visualize it:**

```
App
```

**What state do we need?**

## Step 2 – Foundation: Types + State

First, define the types. What does a task object look like? An id, text, and a completed status. And a union type for the filter.

**Why types first?** TypeScript needs to know the shape of the data. Everything else depends on it.

Create a `src/types.ts` file:

```ts
export interface Task {
  id: number;
  text: string;
  completed: boolean;
}

export type FilterStatus = "all" | "active" | "completed";
```

**Now add state in App.tsx – one piece at a time:**

```tsx
import { useState } from "react";
import type { Task } from "./types";

function App() {
  const [tasks, setTasks] = useState<Task[]>([]);

  console.log("📋 App mounted. Tasks count:", tasks.length);
  console.log("📋 Tasks array:", tasks);

  return <div>To-Do App</div>;
}

export default App;
```

**Console check** – you'll see `[]` and `length: 0`. No tasks yet. The state type is `Task[]` — TypeScript enforces that the array only holds `Task` objects.

## Step 3 – Add Task: Inline Build

Now we add the logic to add a task – first directly in App.tsx, extract later.

**Think:** User types in the input, clicks Add. Need to track what the user types, and create a new task when Add is clicked.

**`handleAdd` function:**

```tsx
const handleAdd = (text: string) => {
  const newTask: Task = {
    id: Date.now(),
    text,
    completed: false,
  };
  setTasks([...tasks, newTask]);
  console.log("✅ Task added:", newTask);
  console.log("📋 New tasks:", [...tasks, newTask]);
};
```

`Date.now()` – a simple way to generate a unique ID. Milliseconds since 1970 — almost guaranteed unique.

**Add the input + button JSX – controlled component pattern with `useState<string>`:**

```tsx
const [inputText, setInputText] = useState("");

const handleInputChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  setInputText(e.target.value);
};

const handleAddClick = () => {
  if (inputText.trim() === "") {
    console.log("⚠️ Empty input — ignoring");
    return;
  }
  handleAdd(inputText.trim());
  setInputText("");
  console.log("🧹 Input cleared");
};
```

**Put the JSX in:**

```tsx
return (

    <div>
      <input
        type="text"
        value={inputText}
        onChange={handleInputChange}
        placeholder="Enter a task..."
      />
      <button onClick={handleAddClick}>Add</button>
    </div>
  </div>
);
```

## Step 4 – TaskInput Component: Extraction

**Think:** The input code is in App.tsx now. But it's an independent UI piece — it deserves its own component.

**Why extract?** Readability – App.tsx should orchestrate, not handle input logic.

`src/components/TaskInput.tsx`:

```tsx
import { useState } from "react";

interface TaskInputProps {
  onAdd: (text: string) => void;
}

function TaskInput({ onAdd }: TaskInputProps): JSX.Element {
  const [text, setText] = useState("");

  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    setText(e.target.value);
  };

  const handleClick = () => {
    if (text.trim() !== "") {
      onAdd(text.trim());
      setText("");
      console.log("🧹 TaskInput: cleared after add");
    } else {
      console.log("⚠️ TaskInput: empty submission blocked");
    }
  };

  return (
    <div>
      <input
        type="text"
        value={text}
        onChange={handleChange}
        placeholder="Enter a task..."
      />
      <button onClick={handleClick}>Add</button>
    </div>
  );
}

export default TaskInput;
```

**Import in App.tsx and remove the inline code:**

```tsx
import TaskInput from "./components/TaskInput";

// ... existing code

return (
  <div>
    <h1>To-Do App</h1>
    <TaskInput onAdd={handleAdd} />
  </div>
);
```

**Test it** – should work the same, but now TaskInput is in its own file. The console should show "TaskInput: cleared after add" on add.

## Step 5 – Render Tasks

Tasks are added but not shown on screen. Let's render them.

**Think:** `tasks` is an array. Use `.map()` to render JSX for each task.

**Why `.map()`?** You can't use `for` loops inside JSX expressions. `.map()` is an expression that returns an array of JSX.

**First, a simple inline render in App.tsx:**

```tsx
return (
  <div>
    <h1>To-Do App</h1>
    <TaskInput onAdd={handleAdd} />
    <div>
      {tasks.map((task) => (
        <div key={task.id}>
          <span>{task.text}</span>
        </div>
      ))}
    </div>
    {tasks.length === 0 && <p>No tasks yet. Add one above!</p>}
  </div>
);
```

`key={task.id}` – React needs a unique identity for each element. Each task has an id, so we use that.

`tasks.length === 0 && <p>...</p>` – conditional rendering with `&&`. Show the message only when the list is empty.

**Test it:** Add "Learn React". Check the console and the UI – the task should appear on screen.

## Step 6 – Toggle Complete (Checkbox)

**Think:** Each task needs a checkbox. Checking it crosses out the text. Unchecking restores it.

**Why toggle state?** Each task has a `completed` property – `false` flips to `true` and back. This is the **array update** pattern – use `.map()` to update just one item, leave the rest untouched.

**First, the standalone concept – array update with `.map()`:**

```js
const items = [
  { id: 1, name: "Milk", bought: false },
  { id: 2, name: "Eggs", bought: false },
];

const updated = items.map((item) =>
  item.id === 1 ? { ...item, bought: true } : item
);
console.log(updated);
// → [{ id: 1, name: "Milk", bought: true }, { id: 2, name: "Eggs", bought: false }]
```

Only the matching item changed. The rest kept the same reference.

**Add `handleToggle` in App.tsx:**

```tsx
const handleToggle = (id: number) => {
  const updated = tasks.map((task) =>
    task.id === id ? { ...task, completed: !task.completed } : task
  );
  console.log("🔄 Toggling task id:", id);
  console.log("📋 Before:", [...tasks]);
  console.log("📋 After:", updated);
  setTasks(updated);
};
```

**Add the checkbox to the render:**

```tsx
{tasks.map((task) => (
  <div key={task.id}>
    <input
      type="checkbox"
      checked={task.completed}
      onChange={() => {
        console.log("☑️ Checkbox clicked for task:", task.id);
        handleToggle(task.id);
      }}
    />
    <span
      style={{
        textDecoration: task.completed ? "line-through" : "none",
        opacity: task.completed ? 0.6 : 1,
        marginLeft: "8px",
      }}
    >
      {task.text}
    </span>
  </div>
))}
```

`checked={task.completed}` – the checkbox is controlled by the task's completed state.

`textDecoration: task.completed ? "line-through" : "none"` – conditional style using a ternary.

**Test it:**
1. Add "Learn React"
2. Click the checkbox – console shows the toggle logs
3. Text gets a strikethrough, becomes dimmer
4. Click again – goes back to normal

## Step 7 – Delete Task

**Think:** Each task needs a Delete button that removes it.

**Why `.filter()`?** Deletion means filtering out the matching item. `.filter()` returns a new array excluding items that match the condition.

**First, the standalone concept – `.filter()` for removal:**

```js
const items = [
  { id: 1, name: "Milk" },
  { id: 2, name: "Eggs" },
];

const afterDelete = items.filter((item) => item.id !== 1);
console.log(afterDelete);
// → [{ id: 2, name: "Eggs" }]
```

`item.id !== 1` – keep everything except id 1.

**Add `handleDelete` in App.tsx:**

```tsx
const handleDelete = (id: number) => {
  const remaining = tasks.filter((task) => task.id !== id);
  console.log("🗑️ Deleting task id:", id);
  console.log("📋 Before:", [...tasks]);
  console.log("📋 After:", remaining);
  setTasks(remaining);
};
```

**Add the Delete button to the render:**

```tsx
{tasks.map((task) => (
  <div key={task.id}>
    <input
      type="checkbox"
      checked={task.completed}
      onChange={() => handleToggle(task.id)}
    />
    <span
      style={{
        textDecoration: task.completed ? "line-through" : "none",
        opacity: task.completed ? 0.6 : 1,
        marginLeft: "8px",
      }}
    >
      {task.text}
    </span>
    <button
      onClick={() => {
        console.log("🗑️ Delete clicked for task:", task.id);
        handleDelete(task.id);
      }}
      style={{ marginLeft: "12px" }}
    >
      Delete
    </button>
  </div>
))}
```

**Test it:** Add a task, click Delete – the task disappears on screen, and the console logs verify what happened.

## Step 9 – Filter (All / Active / Completed)

**Think:** All tasks show up. The user wants to see only active (incomplete) tasks, or only completed.

**Why the `FilterStatus` union type?** The filter can only be one of three values: `"all"`, `"active"`, `"completed"`. TypeScript uses a union type to enforce this – no other values allowed.

**First, the standalone concept – `.filter()` with a boolean property:**

```js
const tasks = [
  { id: 1, text: "Milk", completed: false },
  { id: 2, text: "Eggs", completed: true },
];

const active = tasks.filter((t) => !t.completed);
console.log(active); // → [{ id: 1, text: "Milk", completed: false }]

const completed = tasks.filter((t) => t.completed);
console.log(completed); // → [{ id: 2, text: "Eggs", completed: true }]
```

**Add filter state in App.tsx:**

```tsx
const [filter, setFilter] = useState<FilterStatus>("all");
console.log("🔍 Current filter:", filter);
```

**Filter logic – before the return:**

```tsx
const filteredTasks = tasks.filter((task) => {
  if (filter === "active") return !task.completed;
  if (filter === "completed") return task.completed;
  return true; // "all" – keep every task
});

console.log("🔍 Filtered tasks:", filteredTasks);
```

**Replace `tasks.map` with `filteredTasks.map`:**

```tsx
{filteredTasks.map((task) => (
  <TaskItem key={task.id} task={task} onToggle={handleToggle} onDelete={handleDelete} />
))}
```

**Now create the FilterBar component:**

`src/components/FilterBar.tsx`:

```tsx
import type { FilterStatus } from "../types";

interface FilterBarProps {
  currentFilter: FilterStatus;
  onFilterChange: (filter: FilterStatus) => void;
}

function FilterBar({ currentFilter, onFilterChange }: FilterBarProps): JSX.Element {
  const filters: FilterStatus[] = ["all", "active", "completed"];

  console.log("🔘 FilterBar rendering, current:", currentFilter);

  return (
    <div>
      {filters.map((filter) => (
        <button
          key={filter}
          onClick={() => {
            console.log("🔘 Filter changed to:", filter);
            onFilterChange(filter);
          }}
          style={{
            fontWeight: currentFilter === filter ? "bold" : "normal",
            marginRight: "8px",
          }}
        >
          {filter.charAt(0).toUpperCase() + filter.slice(1)}
        </button>
      ))}
    </div>
  );
}

export default FilterBar;
```

Notice the pattern here – button labels are generated via `.map()` instead of being hardcoded. `filter.charAt(0).toUpperCase() + filter.slice(1)` capitalizes the first letter: "all" → "All", "active" → "Active", "completed" → "Completed".

**Import FilterBar in App.tsx:**

```tsx
import FilterBar from "./components/FilterBar";
import type { Task, FilterStatus } from "./types";
```

**Render it between TaskInput and the list:**

```tsx
<FilterBar currentFilter={filter} onFilterChange={setFilter} />
```

**Test it:**
1. Add "Milk". Add "Eggs"
2. Check "Eggs"
3. Click **Active** → only "Milk" shows
4. Click **Completed** → only "Eggs" shows
5. Click **All** → both show
6. Console shows "🔘 Filter changed to: active" etc.

## Step 10 – TaskList Component + Empty State

The list rendering code is still in App.tsx. Extract it.

**Think:** The list deserves its own component – handle empty state, render TaskItems. Less noise in App.tsx.

`src/components/TaskList.tsx`:

```tsx
import type { Task } from "../types";
import TaskItem from "./TaskItem";

interface TaskListProps {
  tasks: Task[];
  onDelete: (id: number) => void;
  onToggle: (id: number) => void;
}

function TaskList({ tasks, onDelete, onToggle }: TaskListProps): JSX.Element {
  console.log("📋 TaskList rendering, items:", tasks.length);

  if (tasks.length === 0) {
    console.log("📋 TaskList: empty state");
    return <p>No tasks to show.</p>;
  }

  return (
    <div>
      {tasks.map((task) => (
        <TaskItem
          key={task.id}
          task={task}
          onDelete={onDelete}
          onToggle={onToggle}
        />
      ))}
    </div>
  );
}

export default TaskList;
```

New pattern here: **early return** – if the list is empty, return the empty message immediately. This keeps the main `.map()` code cleaner.


## Complete App.tsx – Assembled View

Here's App.tsx in its final assembled form. You've built it piece by piece; here it is all together:

```tsx
import { useState } from "react";
import TaskInput from "./components/TaskInput";
import FilterBar from "./components/FilterBar";
import TaskList from "./components/TaskList";
import type { Task, FilterStatus } from "./types";

function App() {
  const [tasks, setTasks] = useState<Task[]>([]);
  const [filter, setFilter] = useState<FilterStatus>("all");

  console.log("🏠 App re-render. Tasks:", tasks.length, "Filter:", filter);

  const handleAdd = (text: string) => {
    const newTask: Task = { id: Date.now(), text, completed: false };
    setTasks([...tasks, newTask]);
  };

  const handleDelete = (id: number) => {
    setTasks(tasks.filter((task) => task.id !== id));
  };

  const handleToggle = (id: number) => {
    setTasks(
      tasks.map((task) =>
        task.id === id ? { ...task, completed: !task.completed } : task
      )
    );
  };

  const handleClearCompleted = () => {
    setTasks(tasks.filter((task) => !task.completed));
  };

  const filteredTasks = tasks.filter((task) => {
    if (filter === "active") return !task.completed;
    if (filter === "completed") return task.completed;
    return true;
  });

  return (
    <div>
      <h1>To-Do App</h1>
      <TaskInput onAdd={handleAdd} />
      <FilterBar currentFilter={filter} onFilterChange={setFilter} />
      <TaskList
        tasks={filteredTasks}
        onDelete={handleDelete}
        onToggle={handleToggle}
      />
      <div>
        <span>
          {tasks.filter((task) => !task.completed).length} / {tasks.length} items left
        </span>
        <button onClick={handleClearCompleted} style={{ marginLeft: "16px" }}>
          Clear Completed
        </button>
      </div>
    </div>
  );
}

export default App;
```

You've written every line step by step. This assembled view is production-quality code.
