## What We've Covered So Far

In 4.2.1 we learned accessibility fundamentals — `aria-label`, `aria-expanded`, `focus:ring`. Now we'll build something concrete: a **focus-trap**. When a modal is open, the user's Tab key stays trapped inside the modal — it never escapes to the page behind it.

## Broader Goal

We'll build a "Book a Free Trial" modal on the Gym site. When the modal opens → focus lands inside. Tabbing cycles through modal elements. Escape or clicking the backdrop closes it, and focus returns to the trigger button. This is the focus-trap pattern.

## Step 1 — Problem: Focus Escapes the Modal

Open the Gym site in the browser. The Hero section has a "Get Started" button — we'll treat it as the modal trigger for now.

Tab over to the "Get Started" button. Press Enter. But there's no modal yet — let's imagine there was one. Now press Tab. Where does focus go? To the page behind it — the Features section links, the footer, anything in the DOM order after the modal.

The browser doesn't know "the modal is open right now." It just follows the DOM order. If the modal is rendered later in the DOM (like after the footer), Tab will fly straight past it and into the background. **That's the problem we're solving.**

Let's build the modal step by step.

### A New Concept — `fixed`, `inset-0`, and Opacity Modifier

The modal overlay needs three new Tailwind concepts:

| Class | CSS equivalent | What it does |
|-------|---------------|--------------|
| `fixed` | `position: fixed` | Element is positioned relative to the viewport — stays in place when the page scrolls |
| `inset-0` | `top: 0; right: 0; bottom: 0; left: 0` | Zero distance on all sides — covers the entire screen. `inset-4` = 16px gap on all sides, `inset-x-0` = left + right only, `inset-y-0` = top + bottom only |
| `bg-black/50` | `background-color: rgba(0, 0, 0, 0.5)` | The `/50` means 50% opacity. `bg-black/25` = 25%, `bg-black/80` = 80%. Works with any color: `bg-red-500/50`, `text-white/80` |

## Step 4 — Focus-Trap Roadmap + Auto-Focus

### The Full Flow We're Building

Steps 4-7 build the focus-trap. Here's the end goal:

1. **Tab** to the "Book a Free Trial" button → focus ring visible
2. **Enter** → modal opens → focus **automatically** jumps to the Name input
3. **Tab** → focus cycles through modal elements (X → Name → Email → Submit → X...)
4. **Tab** → never escapes to the background — stays inside the modal
5. **Escape** / clicking X or backdrop → modal closes → focus **returns** to the trigger button

```
[Tab] → Button focus → [Enter] → Modal opens → Focus on Name input
  → [Tab] → Email → [Tab] → Submit → [Tab] → ✕ → [Tab] → Name...
  → [Escape / ✕ / backdrop click] → Modal closes → Focus back on button
```

In Step 3, clicking X closes the modal but focus just disappears into the void (goes to `document.body`). Steps 4-7 fix this.

| Step | What gets added |
|------|----------------|
| 4 (this one) | Auto-focus — when modal opens, focus lands on the first input |
| 5 | Escape handler — Escape key closes modal, returns focus to trigger |
| 6 | Tab cycle — Tab loops through modal elements, never escapes |
| 7 | Click-outside + ARIA — click backdrop to close, screen reader announces "dialog" |

### Auto-Focus: When Modal Opens, Focus the First Input

**Problem:** Modal opens but focus is nowhere — the user has to manually Tab or click into the first field. We want focus to land on the Name input automatically.

**Solution:** `useEffect` + `useRef`.

First, understand the two hooks:

---

**`useRef` refresher:**
```
const modalRef = useRef<HTMLDivElement>(null)
```
- `useRef` creates a **mutable object** with a `.current` property
- `modalRef.current` = the actual DOM element with `ref={modalRef}` attached
- Initially `null` — the element doesn't exist yet
- When the component renders, React replaces `.current` with the real DOM element
- **Benefit:** updating `.current` does NOT trigger a re-render (unlike `useState`). It's just a reference.

**`useEffect` refresher:**
```
useEffect(() => { ... }, [isOpen])
```
- The callback runs **after** render
- The dependency array `[isOpen]` — the callback re-runs whenever `isOpen` changes
- This means — once the modal is rendered to the DOM, the effect fires, and you can access the DOM elements

---

**The combination:**

Step 1: Create a `useRef` for the modal's container div
Step 2: Attach it with `ref={modalRef}`
Step 3: In `useEffect`, do `modalRef.current.querySelector("input")?.focus()`

**Verify with console.log first — does the effect fire?**

```tsx

  const modalRef = useRef<HTMLDivElement>(null)

  useEffect(() => {

  }, [isOpen])

  return (
    <>
      <button onClick={() => setIsOpen(!isOpen)} className="...">
        Book a Free Trial
      </button>

      {isOpen && (
        <div
          ref={modalRef}

```

Now the real logic:

```tsx
useEffect(() => {
  if (isOpen && modalRef.current) {
    const input = modalRef.current.querySelector("input")
    console.log("focusing input:", input)
    input?.focus()
  }
}, [isOpen])
```

**TEST:** Console prints "focusing input: <input ...>" ✅. Browser shows modal opening and cursor jumping to the Name input ✅.

---

**Why put the `ref` on the container div, not directly on the input?**

Two reasons:

**1. Reusability for future steps.** Right now we're just focusing the input. But in Step 5 we need to detect Escape key — `onKeyDown` goes on the same div. In Step 6 we need to find all focusable elements — `querySelectorAll` runs on the same div. One ref, all the functionality.

**2. One ref can access multiple elements.** If you put the ref on the input directly, you only get that one input. But with `modalRef.current.querySelector(...)`, you can grab any element inside — Name input, Email input, Submit button, X button. The ref is a **container** — everything inside is accessible through it.

---

**`input?.focus()` — why the `?`?**

`querySelector("input")` returns `null` if there's no input element. The `?` (optional chaining) means — if it's `null`, skip the call. No error.

**`useEffect` dependency `[isOpen]` — why?**

It says "only re-run when `isOpen` changes":
- `false → true`: Modal renders to DOM → effect fires → focus the input
- `true → false`: Modal is removed → effect fires → but `if (isOpen)` is false, so nothing happens

---

## Step 6 — Tab Cycle: Keep Focus Inside the Modal

**Problem:** Tab through the modal. At the last element, Tab again — focus escapes to the page behind. The browser follows DOM order and moves on to whatever comes after the modal in the HTML.

**Solution:** Intercept the Tab key, manually manage the focus cycle within the modal. But first, some concepts.

---

### Concept 1: `querySelectorAll` — Finding Multiple Elements at Once

So far you've seen `querySelector` — finds one element. `querySelectorAll` finds multiple:

```ts
document.querySelectorAll("button")   // all buttons
document.querySelectorAll("input")    // all inputs
```

Need both buttons AND inputs? Use commas in the selector string — like a CSS selector:

```ts
document.querySelectorAll("button, input")   // buttons OR inputs
document.querySelectorAll("button, input, textarea")  // all three
```

The comma means "OR" — buttons OR inputs OR textareas. All matching elements returned in DOM order.

> **Important:** This is a string, not JS concatenation. `querySelectorAll` always takes a string. The commas let you pass multiple selectors at once.

---

### Concept 2: NodeList vs. Array

The result of `querySelectorAll` isn't a plain Array — it's a **NodeList**. It has a `length` property (like an array), but not all array methods work on it in every browser:

```ts
const buttons = document.querySelectorAll("button")
buttons.length        // ✅ works
buttons.map(...)      // ❌ might fail — NodeList doesn't always have map
```

So we convert NodeList to a real Array:

```ts
const arr = Array.from(buttons)   // NodeList → Array
arr.map(btn => ...)               // ✅ now it works
```

`Array.from()` is a built-in JavaScript method that converts any iterable — NodeList, Set, even a string — into a real Array.

---

### Concept 3: The tabindex Attribute

By default, some elements are focusable via Tab (buttons, inputs, links with `href`). Others are not (`<div>`, `<span>`, `<p>`). The `tabindex` attribute controls this:

```html
tabindex="0"  → Focusable in natural Tab order (default for buttons, inputs)
tabindex="-1" → Can be focused programmatically with `.focus()`, but NOT via Tab
tabindex="1"  → Custom Tab order (avoid — only use 0 or -1)
```

**`tabindex="-1"` is the important one** — it means "this element can receive focus via JavaScript, but Tab shouldn't land on it." This is typically used with `.focus()` when you want to control focus programmatically.

When we collect focusable elements for the Tab cycle, we need to **exclude** `tabindex="-1"` elements — because they're not meant to be in the Tab order.

---

### The Full Function

Start simple — just buttons, inputs, textareas:

```ts
function getFocusableElements() {
  // modalRef.current = the modal's overlay div
  // find all button + input + textarea inside it
  const elements = modalRef.current.querySelectorAll("button, input, textarea")
  console.log("focusable:", elements)
  return elements
}
```

But that's incomplete. What if the modal has anchor links (`<a href="...">`)? They're focusable too. What about a `<div tabindex="0">`? Also focusable. We need a complete selector:

```
"button, input, textarea, a[href], [tabindex]:not([tabindex='-1'])"
```

| Part | Meaning |
|------|---------|
| `button, input, textarea` | Elements that are focusable by default |
| `a[href]` | Anchor links with an href — focusable. (Without href, they're not.) |
| `[tabindex]` | Any element with a tabindex attribute |
| `:not([tabindex="-1"])` | But exclude tabindex="-1" — those should NOT be in the Tab cycle |

Full function:

```tsx
const getFocusableElements = (): HTMLElement[] => {
  if (!modalRef.current) return []
  const selectors = 'a[href], button, input, textarea, [tabindex]:not([tabindex="-1"])'
  const nodeList = modalRef.current.querySelectorAll(selectors)
  const elements = Array.from(nodeList)  // NodeList → Array
  console.log("focusable elements:", elements)
  return elements
}
```

---

### The Real Tab Cycle Logic

**The rule:**
- **Tab** on the last element → jump to the first
- **Shift+Tab** on the first element → jump to the last
- **All other cases** → let the browser do its default thing

```tsx
if (e.key === "Tab") {
  const focusable = getFocusableElements()
  const first = focusable[0]
  const last = focusable[focusable.length - 1]

  if (e.shiftKey && document.activeElement === first) {
    console.log("Shift+Tab on first → going to last")
    e.preventDefault()
    last?.focus()
  } else if (!e.shiftKey && document.activeElement === last) {
    console.log("Tab on last → going to first")
    e.preventDefault()
    first?.focus()
  }
}
```

**Breakdown:**
- `document.activeElement` — which element currently has focus? The browser tracks this for you.
- `e.shiftKey` — was Shift held down? If true, it's Shift+Tab.
- **Case 1:** Shift+Tab AND focus is on the first element → move to the last
- **Case 2:** Tab AND focus is on the last element → move to the first
- `e.preventDefault()` — "browser, don't do your default Tab action. We've got this."

## Step 7 — ARIA Attributes: For Screen Readers

The focus logic works. Now add semantics so screen reader users know "this is a dialog, stay inside."

```tsx
<div
  ref={modalRef}
  role="dialog"
  aria-modal="true"
  aria-labelledby="modal-title"
  onKeyDown={handleKeyDown}
  className="fixed inset-0 bg-black/50 flex items-center justify-center z-50"
>
  <div className="relative bg-white rounded-xl p-8 max-w-md w-full mx-4">
    <h2 id="modal-title" className="text-2xl font-bold mb-4">
      Book a Free Trial
    </h2>
```

| Attribute | What it does |
|-----------|--------------|
| `role="dialog"` | Tells the screen reader this is a dialog — it'll announce "Book a Free Trial dialog" |
| `aria-modal="true"` | Tells the screen reader to **ignore** everything outside this dialog. Without it, the reader will still announce background content. |
| `aria-labelledby="modal-title"` | Associates the dialog with its heading. The `<h2>` with `id="modal-title"` becomes the dialog's accessible name. |

> **`aria-modal` is critical.** Without it, the screen reader reads the entire page — background, modal, everything. The user hears "Features section... Book a Free Trial... Features section..." and gets confused. `aria-modal="true"` says "only read what's inside this dialog."

> **`aria-labelledby` vs `aria-label`:** `aria-labelledby` references an existing element's text. `aria-label` provides a string directly. Here, `aria-labelledby="modal-title"` pulls the text from the `<h2>`. If you provided both, `aria-labelledby` wins.

### Click-Outside to Close

Add an `onClick` to the overlay — clicking the dark backdrop closes the modal:

```tsx
<div
  onClick={() => {
    setIsOpen(false)
    openButtonRef.current?.focus()
  }}
>
  <div
    onClick={(e) => e.stopPropagation()}  // don't close when clicking inside
    className="relative bg-white rounded-xl p-8 max-w-md w-full mx-4"
  >
    {/* modal content */}
  </div>
</div>
```

The inner `div`'s `onClick` calls `stopPropagation()` — clicks inside the modal don't bubble up to the overlay. Only clicks on the backdrop (outside the modal) trigger the close.

### The Complete Component

```tsx
import { useState, useRef, useEffect } from "react"
import { X } from "lucide-react"

export default function TrialModal() {
  const [isOpen, setIsOpen] = useState(false)
  const modalRef = useRef<HTMLDivElement>(null)
  const openButtonRef = useRef<HTMLButtonElement>(null)

  const getFocusableElements = (): HTMLElement[] => {
    if (!modalRef.current) return []
    const selectors = 'a[href], button, input, textarea, [tabindex]:not([tabindex="-1"])'
    return Array.from(modalRef.current.querySelectorAll<HTMLElement>(selectors))
  }

  useEffect(() => {
    if (isOpen && modalRef.current) {
      const input = modalRef.current.querySelector("input")
      input?.focus()
    }
  }, [isOpen])

  const handleKeyDown = (e: React.KeyboardEvent) => {
    if (e.key === "Escape") {
      setIsOpen(false)
      openButtonRef.current?.focus()
      return
    }
    if (e.key === "Tab") {
      const focusable = getFocusableElements()
      const first = focusable[0]
      const last = focusable[focusable.length - 1]
      if (e.shiftKey && document.activeElement === first) {
        e.preventDefault()
        last?.focus()
      } else if (!e.shiftKey && document.activeElement === last) {
        e.preventDefault()
        first?.focus()
      }
    }
  }

  return (
    <>
      <button
        ref={openButtonRef}
        onClick={() => setIsOpen(!isOpen)}
        className="bg-blue-600 hover:bg-blue-700 text-white px-8 py-3 rounded-lg font-semibold focus:outline-none focus:ring-2 focus:ring-blue-500 transition-colors"
      >
        Book a Free Trial
      </button>

      {isOpen && (
        <div
          className="fixed inset-0 bg-black/50 flex items-center justify-center z-50"
          onClick={() => {
            setIsOpen(false)
            openButtonRef.current?.focus()
          }}
        >
          <div
            ref={modalRef}
            role="dialog"
            aria-modal="true"
            aria-labelledby="modal-title"
            onKeyDown={handleKeyDown}
            onClick={(e) => e.stopPropagation()}
            className="relative bg-white rounded-xl p-8 max-w-md w-full mx-4"
          >
            <button
              onClick={() => { setIsOpen(false); openButtonRef.current?.focus() }}
              className="absolute top-3 right-3 text-gray-400 hover:text-gray-700 focus:outline-none focus:ring-2 focus:ring-blue-500 rounded transition-colors"
            >
              <X className="w-5 h-5" />
            </button>
            <h2 id="modal-title" className="text-2xl font-bold mb-4">
              Book a Free Trial
            </h2>
            <p className="text-gray-600 mb-6">Fill in your details and we'll get back to you.</p>
            <form onSubmit={(e) => e.preventDefault()}>
              <input type="text" placeholder="Name"
                className="w-full border border-gray-300 rounded-lg px-3 py-2 mb-4 focus:ring-2 focus:ring-blue-500 focus:outline-none" />
              <input type="email" placeholder="Email"
                className="w-full border border-gray-300 rounded-lg px-3 py-2 mb-4 focus:ring-2 focus:ring-blue-500 focus:outline-none" />
              <button type="submit"
                className="bg-blue-600 hover:bg-blue-700 text-white px-6 py-2 rounded-lg focus:outline-none focus:ring-2 focus:ring-blue-500 transition-colors">
                Submit
              </button>
            </form>
          </div>
        </div>
      )}
    </>
  )
}
```

## Common Mistakes

- **Forgetting `aria-modal`:** Screen reader reads background elements — user gets confused.
- **Forgetting `e.stopPropagation()`:** Clicking inside the dialog bubbles to the overlay → modal closes immediately.
- **Not returning focus on close:** After backdrop click, focus is lost — user doesn't know where they are.
- **Using `===` vs `==` in activeElement comparison:** Use strict equality (`===`). Types need to match.
