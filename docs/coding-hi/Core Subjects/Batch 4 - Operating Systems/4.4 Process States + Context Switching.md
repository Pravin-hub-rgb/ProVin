Processes bhi apni lifetime mein **states** se guzarte hain — New, Ready, Running, Waiting, Terminated. Ye states process ke lifecycle ko describe karti hain.

---

# Process States + Context Switching

## Process States — 5 States

Ek process apni lifetime mein in 5 states se guzarta hai:

```
New → Ready → Running → Waiting → Terminated
         ↑         │         │
         └─────────┘         │
         ↑                   │
         └───────────────────┘
```

### New

Process **create** ho raha hai. Abhi RAM mein load nahi hua.

```javascript
// Node.js mein: `node app.js` likha — process new state mein hai
// OS process create kar raha hai
```

### Ready

Process **execute hone ke liye taiyar** hai, CPU ka wait kar raha hai.

```javascript
// Process RAM mein load ho gaya, ready hai
// But CPU abhi doosra process run kar raha hai
// Ready queue mein wait kar raha hai
```

### Running

Abhi **CPU execute** kar raha hai isko.

```javascript
// Process ka code chal raha hai
// JavaScript code execute ho raha hai
```

### Waiting

Kisi **I/O operation** ya event ka wait kar raha hai.

```javascript
// fs.readFile() call kiya — ab disk I/O ka wait
// fetch() call kiya — ab network response ka wait
// Process waiting state mein hai — CPU doosra process chal raha hai
```

### Terminated

Execution **complete** ho gaya.

```javascript
// Process ne kaam khatam kiya
// Memory free ho rahi hai
// process.exit(0) — normal termination
```

---

## State Transitions

```
New → Ready: Process create ho gaya, RAM mein load
Ready → Running: CPU mila, execution shuru
Running → Waiting: I/O operation shuru
Waiting → Ready: I/O complete, wapas ready queue
Running → Terminated: Kaam khatam
Running → Ready: Time slice khatam (preemption)
```

Har state ka ek transition hai — ek state se doosre mein jaana. Ye lifecycle hai process ka.

---

## Context Switching

**Context Switching** = jab CPU ek process/thread se dusre pe **switch** karta hai — current process ka state save karta hai, aur naye process ka state load karta hai.

```javascript
// Node.js event loop — context switching
// Main thread: JavaScript code chal raha hai
// File read complete → callback ready hai
// Main thread: current kaam roko, callback chalao
// = Context switch (conceptual)
```

**Steps:**
1. Current process ka state save karo (registers, memory pointers, program counter)
2. Naye process ka state load karo
3. Naya process execute karo

**Overhead:** Context switching **time-consuming** hai — save + load + overhead. Zyada context switching performance slow kar sakta hai.

```
Process A running → Context switch → Process B running
                 ↑
         Save A's state
         Load B's state
         Overhead: ~1-10 microseconds
```

---

## Node.js — Context Switching Angle

Node.js single-threaded hai but context switching hota hai:

```javascript
// Event loop phases — implicit context switching
setTimeout(() => {
  // Phase 1: Timer
}, 1000);

fs.readFile('file.txt', () => {
  // Phase 2: I/O callback
});

setImmediate(() => {
  // Phase 3: Check phase
});

// Event loop in phases pe switch hota hai
// Har phase = different type of callback
```

**Worker Threads — explicit context switching:**
```javascript
// Main thread → Worker thread = explicit context switch
const worker = new Worker('./heavy-task.js');
// CPU: main thread roko, worker thread chalao
// Worker complete → main thread wapas
```

## Interview Answer

Interviewer poochhe: "Process states batao?"

**Answer:** "5 states: New (create ho raha hai), Ready (execute ke liye taiyar hai, CPU ka wait), Running (CPU execute kar raha hai), Waiting (I/O ka wait), Terminated (complete ho gaya). Transitions: New→Ready→Running→Waiting→Ready→Running→Terminated."

---

## What It Is NOT

⚠️ **Process state = thread state nahi.** Thread ka apna state hota hai but thread process ke andar hota hai. Process ka state overall program ka hai.

⚠️ **Context switching = instant nahi.** Overhead hai — save + load. Isliye zyada threads/contexts se performance slow ho sakti hai.

⚠️ **Waiting state = dead nahi.** Process abhi bhi alive hai — bas kisi I/O ka wait kar raha hai. I/O complete hone pe wapas ready state mein aayega.

## In Your Own Words

1. Process ki 5 states naam se batao aur har ek ka one-liner do.

<details>
<summary>Sample Jawab</summary>

**Jawab:** New — process create ho raha hai. Ready — execute ke liye taiyar, CPU ka wait. Running — CPU execute kar raha hai. Waiting — I/O operation ka wait. Terminated — execution complete ho gaya.

</details>

2. Context Switching kya hai? Overhead kyun hoti hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** CPU jab ek process se dusre pe switch karta hai — current process ka state save karta hai, naye ka load karta hai. Overhead hai kyunki save + load mein time lagta hai (~1-10 microseconds). Zyada context switching se performance slow ho sakti hai.

</details>

3. Node.js single-threaded hai but context switching kyun hoti hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Event loop phases mein implicit context switching hoti hai — timer callbacks, I/O callbacks, check phase. Har phase mein different type ke callbacks chalte hain. Worker Threads mein explicit context switching hoti hai — main thread rok ke worker thread chalata hai.

</details>

4. React component lifecycle aur process states mein kya similarity hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Dono lifecycle states se guzarte hain. React: Mounting → Mounted → Updating → Updated → Unmounting. Process: New → Ready → Running → Waiting → Terminated. Dono mein transitions hain — ek state se doosre mein jaana.

</details>
