OS ko decide karna padta hai kaunsa program kitni memory use kare, kab allocate kare, kab free kare. Ye sab **memory management** ke under aata hai.

---

# Memory Management Basics

## Stack vs Heap

```javascript
// Stack memory — primitive types, fixed size
let x = 10; // Stack pe
let name = "Vin"; // Stack pe
let isActive = true; // Stack pe

// Heap memory — objects, arrays, dynamic size
const product = { name: "Rice", price: 120 }; // Heap pe
const numbers = [1, 2, 3]; // Heap pe
```

| | Stack | Heap |
|---|---|---|
| Data | Primitive types | Objects, arrays |
| Size | Fixed (chhota) | Dynamic (bada) |
| Speed | Fast (direct access) | Slow (reference through pointer) |
| Management | Automatic (LIFO) | Garbage collector |

---

## Virtual Memory

OS har process ko lagta hai jaise use **poori memory** mili hai (isolated), but asal mein OS background mein manage karta hai.

```javascript
// Node.js process ko lagta hai uske paas bahut memory hai
// But asal mein OS memory ko manage karta hai
process.memoryUsage();
// { rss: 30000000, heapTotal: 10000000, heapUsed: 5000000 }
// RSS = actual memory used by process
```

**Virtual Memory concept:**
- Har process ko ek "virtual address space" milta hai
- OS virtual addresses ko physical RAM se map karta hai
- Agar RAM kam pade toh disk (swap space) use hoti hai
- Process ko pata nahi ki actual memory kahan hai — OS handle karta hai

Virtual memory = indirection. OS pehle virtual address map karta hai, phir physical address milta hai.

## Paging

Memory ko **fixed-size blocks** (pages) mein divide karna — taaki management aasan ho aur fragmentation kam ho.

```
Virtual Memory:
Page 0: [0-4KB]
Page 1: [4-8KB]
Page 2: [8-12KB]
...

Physical Memory:
Frame 0: [actual RAM slot 0]
Frame 1: [actual RAM slot 1]
Frame 2: [actual RAM slot 2]
...

OS mapping: Page 0 → Frame 2, Page 1 → Frame 0, Page 2 → Frame 1
```

Paging = memory ko chunks mein divide karna — taaki management aasan ho aur fragmentation kam ho.

---

## Fragmentation

Memory mein **chhote-chhote unused gaps** ban jaana jo use nahi ho paate.

### Internal Fragmentation

Allocated block ke andar **waste space**.

```
Block size: 8KB
Actual data: 5KB
Waste: 3KB (internal fragmentation)
```

### External Fragmentation

Blocks ke beech **gaps** — total space enough hai but contiguous nahi hai.

```
[Used 4KB] [Free 2KB] [Used 4KB] [Free 3KB]
Total free: 5KB — but contiguous nahi hai
Large allocation nahi ho paayega
```

**Paging se fragmentation kam hota hai** — fixed-size pages hain, gaps chhote hote hain.

## Garbage Collection — Node.js

JavaScript engine (V8) automatically memory free karta hai — **garbage collection**.

```javascript
// Memory allocated
let obj = { name: "Rice" };

// Memory freed — jab obj ka reference ho jaaye
obj = null; // Ab garbage collector isko free kar sakta hai
```

**How GC works:**
1. **Mark phase:** Sab reachable objects mark karo (jo currently use ho rahe hain)
2. **Sweep phase:** Unmarked objects (garbage) ko free karo

```javascript
function processData() {
  const largeData = fetchHugeData(); // Heap pe allocate
  // Process karo...
  return result;
} // largeData ka reference jaata hai — GC free kar dega
```

**Memory leak = garbage collection nahi ho pa raha:**
```javascript
// ❌ Memory leak
const cache = {};
setInterval(() => {
  cache[Date.now()] = fetchData(); // Har second naya data add
  // cache kabhi free nahi hota — grow karta rahega
}, 1000);

// ✅ Fix
const cache = new Map();
// Ya cache size limit karo
```

---

## What It Is NOT

⚠️ **Virtual Memory = unlimited memory nahi.** Virtual memory disk se memory borrow karta hai — slow hoti hai. RAM zyada hai toh better hai.

⚠️ **Garbage Collection = memory leak nahi rokta.** GC unreachable objects free karta hai. But agar tum intentionally references hold karo (global variables, event listeners), toh GC kuch nahi kar sakta.

⚠️ **Paging = performance guarantee nahi.** Paging fragmentation kam karti hai but overhead bhi hai (page tables). Bas management aasan hoti hai.

## In Your Own Words

1. Stack aur Heap memory mein kya fark hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Stack pe primitive types hote hain (number, string) — fixed size, fast access, automatic management (LIFO). Heap pe objects/arrays hote hain — dynamic size, slow access (reference through pointer), garbage collector manage karta hai.

</details>

2. Virtual memory kya hai? OS kyun use karta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** OS har process ko lagta hai jaise poori memory mili hai — but asal mein virtual addresses ko physical RAM se map karta hai. Benefits: process isolation (ek process doosre ki memory access nahi kar sakta), RAM kam pade toh disk (swap) use hoti hai.

</details>

3. Memory leak kya hai? Node.js mein kaise hota hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Memory leak tab hota hai jab objects use nahi ho rahe but memory free nahi ho rahi — garbage collection nahi ho pa raha. Node.js mein: global variables, uncleared intervals/timeouts, event listeners jo remove nahi hue, growing caches — ye sab memory leak kar sakte hain.

</details>

4. Garbage collection kaise kaam karta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Mark and sweep algorithm: (1) Mark phase — sab reachable objects mark karo (jo currently use ho rahe hain). (2) Sweep phase — unmarked objects (garbage) free karo. V8 JavaScript engine ye automatically karta hai. Tumhe manually memory free nahi karni padti — but references handle karo.

</details>
