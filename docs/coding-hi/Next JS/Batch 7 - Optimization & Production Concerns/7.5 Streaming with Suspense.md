Now the third problem: **the loading experience.** Imagine a page with two sections — a header (fast, no DB) and a gallery grid (slow — say a 3-second query). Normally the **entire page waits** on that 3-second query — the user sees a blank screen. But the header doesn't depend on that query — why should it wait?

This is what **Streaming with Suspense** fixes — each section loads independently, whatever is ready shows first. We saw `loading.tsx` in 1.4 (route-level Suspense boundary). Now we take it granular — at the section level.

# Streaming with Suspense

## THINK — Why the Whole Page Blocks

A Server Component does `await db.select()` — the page doesn't render until the query completes. If that query takes 3 seconds, the user sees a **blank screen for 3 seconds.** The whole page renders server-side as one block — it needs all the data before it sends any HTML.

Why? Because the page's render **depends on the data** — the server needs the full result before it can send HTML. And there's no reason the **header** also has to wait — its data takes 50ms.

**Streaming** fixes this — the server sends HTML in **chunks**. Whatever section is ready, that chunk comes first. The slow section comes later. The user sees the page **immediately.**

## CONCEPT — What Is Suspense

**Suspense** is React's built-in feature — *"while this isn't ready, show a placeholder."* As soon as the inner data is ready, the placeholder is replaced with the real content.

```tsx
<Suspense fallback={<GallerySkeleton />}>
  <SlowGallery />
</Suspense>
```

**`<Suspense fallback={...}>`** is a boundary. **`<SlowGallery />`** is the inner component (slow async). While `SlowGallery` isn't ready, `fallback` (a skeleton) is shown. Once data is ready, the real content replaces it.

In Next.js Server Components — `SlowGallery` is an **async component** that `await`s. During that await, the Suspense boundary shows the fallback. Everything **outside** the Suspense (the rest of the page) renders and streams immediately.

### `loading.tsx` vs `<Suspense>`

You saw `loading.tsx` in 1.4 — it's a **route-level Suspense boundary** (the whole page). If the entire page is slow, `loading.tsx` shows a skeleton. But when **only one section** is slow — use a granular `<Suspense>` around just that section.

## Step 0 — Where `fetchPhotos` Comes From

The page above imports `fetchPhotos` from `@/lib/photos` — but that file doesn't exist yet. Create it first. **File:** `lib/photos.ts` — a new `lib/` folder at the project root:

```ts
// lib/photos.ts
export type Photo = {
  id: number;
  title: string;
  src: string;
  alt: string;
  width: number;
  height: number;
};

export async function fetchPhotos(): Promise<Photo[]> {
  await new Promise((r) => setTimeout(r, 3000));

  return [
    { id: 1, title: "Cat sleeping", src: "/photos/cat.jpg", alt: "A cat", width: 800, height: 600 },
    { id: 2, title: "Dog running", src: "/photos/dog.jpg", alt: "A dog", width: 800, height: 600 },
    { id: 3, title: "Bird flying", src: "/photos/bird.jpg", alt: "A bird", width: 800, height: 600 },
  ];
}
```

**`export type Photo`** — the data shape. **`export async function fetchPhotos`** — async (the `await` below simulates a slow DB call). `setTimeout(r, 3000)` is an intentional 3-second delay — to demonstrate streaming (see TEST). In a real app, this is where the DB query goes.

## CODE — Streaming One Section

A page where the gallery is slow:

**File:** `app/gallery/page.tsx` — without Suspense (entire page waits)

```tsx
// app/gallery/page.tsx
import { fetchPhotos } from "@/lib/photos";

export default async function GalleryPage() {
  const photos = await fetchPhotos();          // 3 seconds — slow

  return (
    <main>
      <h1>Photo Gallery</h1>
      <div className="grid grid-cols-3 gap-4">
        {photos.map((photo) => (
          <div key={photo.id}>{photo.title}</div>
        ))}
      </div>
    </main>
  );
}
```

Here `await fetchPhotos()` — 3 seconds — the whole page blocks, the `h1` doesn't even show. Now, the same page with Suspense:

**File:** `app/gallery/page.tsx` — Suspense boundary (h1 shows immediately, grid streams)

```tsx
// app/gallery/page.tsx
import { Suspense } from "react";
import { fetchPhotos } from "@/lib/photos";

async function PhotoGrid() {
  const photos = await fetchPhotos();          // 3 seconds — slow

  return (
    <div className="grid grid-cols-3 gap-4">
      {photos.map((photo) => (
        <div key={photo.id}>{photo.title}</div>
      ))}
    </div>
  );
}

export default function GalleryPage() {
  return (
    <main>
      <h1>Photo Gallery</h1>
      <Suspense fallback={<GallerySkeleton />}>
        <PhotoGrid />
      </Suspense>
    </main>
  );
}

function GallerySkeleton() {
  return (
    <div className="grid grid-cols-3 gap-4">
      {Array.from({ length: 9 }).map((_, i) => (
        <div key={i} className="h-40 animate-pulse bg-zinc-200" />
      ))}
    </div>
  );
}
```

**What changed:**

1. **`async function PhotoGrid()`** — the slow logic is in its own async component.
2. **`export default function GalleryPage()`** — the page is no longer `async` — it's synchronous. No `await` at the top level — so the page can render **immediately.**
3. **`<Suspense fallback={<GallerySkeleton />>}`** — a boundary around `PhotoGrid`. While `await fetchPhotos()` runs, `GallerySkeleton` (gray pulsing boxes) shows. When the query completes, the skeleton is replaced with the real grid.

**Result:** `h1` + page structure renders **immediately.** The grid shows a skeleton, then 3 seconds later, the real photos. The user never sees a blank screen — **progressive loading.**

2. Open DevTools → **Network** tab → you'll see the HTML arriving in **chunks** (streaming) — not a single big response.

## Nutshell

Streaming with Suspense: load page **sections independently** — whatever is ready shows first. `<Suspense fallback={...}>` is a boundary — while the inner async component is awaiting, the fallback (a skeleton) shows; when ready, the real content replaces it. Pull the slow logic into its own `async` component, wrap in `<Suspense>`, and the rest of the page renders immediately. `loading.tsx` = route-level (whole page), `<Suspense>` = section-level (granular).

## What It Is NOT

- **Suspense is not "just a spinner."** Suspense is the **mechanism** — show a fallback while something loads. The fallback can be anything (skeleton, spinner, blank). It's not tied to any one UI.
- **Streaming is not "the server got faster."** The query still takes 3 seconds. Streaming improves the **user experience** — instead of a blank screen, the user sees the page structure + skeleton immediately, then the slow section fills in. Perceived performance, not raw speed.
- **`loading.tsx` is not the same as `<Suspense>`.** `loading.tsx` is a route-level automatic boundary — for when the whole page is slow. `<Suspense>` is granular — for when only one section is slow. One is file-based and automatic, the other is component-based and explicit.
- **Suspense needs a genuinely slow async operation inside.** Wrapping fast content in Suspense is pointless — it's just overhead. Use it only around slow sections (DB queries, slow APIs).
