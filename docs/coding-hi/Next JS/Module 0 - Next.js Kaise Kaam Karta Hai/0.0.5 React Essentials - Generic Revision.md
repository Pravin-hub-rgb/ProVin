## 1. JSX — HTML + JavaScript, Together

JSX looks like HTML, but under the hood it is JavaScript. Whatever you `return` inside a component is what gets rendered to the screen.

```tsx
function Greeting() {
  return <h1>Hello, {name}!</h1>;  // {} embeds a JavaScript variable
}
```

> **Remember:** inside `{}`, you can write any JavaScript expression — variables, function calls, ternary conditions. The attribute `class` in HTML becomes `className` in JSX (because `class` is a reserved keyword in JavaScript).

## 2. Components + Props

A component is a function that returns a piece of UI. Props are the inputs passed into a component.

```tsx
interface CardProps {
  title: string;
  count: number;
}

function Card({ title, count }: CardProps) {
  return <div>The {title} has {count} items</div>;
}

<Card title="To-Do" count={3} />  // use it as many times as you want
```

## 3. `useState` — Remembering Data That Changes

React needs to know when a value has changed so the UI can update — a plain variable does not tell React anything. That is why `useState` exists.

```tsx
const [count, setCount] = useState(0);
// count = current value, setCount = the function that updates it

<button onClick={() => setCount(count + 1)}>+</button>
```

> **Remember:** always update state using the setter (`setCount`), never by reassigning the variable directly. React only re-renders when the setter is called.

## 4. Lists + Keys

When rendering an array of items, React uses `.map()`. Each item must have a unique `key` so React can track it during re-renders (this was covered in the React module on reconciliation):

```tsx
<ul>
  {items.map((item) => (
    <li key={item.id}>{item.name}</li>
  ))}
</ul>
```

## 5. Conditional Rendering

Inside JSX, you cannot use an `if` statement directly. Instead, use ternary operators (`? :`) and `&&` (which renders the element only when the condition is true):

```tsx
{isLoading ? <p>Loading...</p> : <p>{data}</p>}
{isAdmin && <button>Delete</button>}  // button renders only if isAdmin is true
```

## 6. `useEffect` — Side Effects (API, Timers, Storage)

`useEffect` handles work that happens outside React's render cycle — fetching data, setting timers, accessing browser APIs. The dependency array (`[]`) controls when the effect re-runs.

```tsx
useEffect(() => {
  fetch("/api/users").then((r) => r.json()).then(setUsers);
}, []);  // [] — runs only once on mount
```

> **Important:** in Next.js Server Components, you will not need `useEffect` for data fetching — that is what 0.3 is about. But for client-side interactivity, it is still used.

## 7. React Router — A Generic Refresher

In the React course, client-side routing was handled by React Router. Here are the core patterns:

| Tool | What it does |
|---|---|
| `<BrowserRouter>` / `<Routes>` / `<Route>` | Set up routing and define routes |
| `<Route path="/about" element={<About/>} />` | Render `<About/>` at URL `/about` |
| `<Link to="/about">` | Navigate without a full page reload |
| `path="/movies/:id"` + `useParams()` | Dynamic route — extract a variable from the URL (`:id`) |
| `useNavigate()` | Navigate programmatically from code (`navigate("/login")`) |
| Nested routes `/parent/child` | Build nested route structure |
| Protected routes | Show a route only to logged-in users (auth-check wrapper) |

> **Remember:** this is a *generic* concept. Next.js uses **file-based routing** (create a folder + `page.tsx`) instead of `<Route>` configs. The concepts are the same — dynamic segments, navigation, nested routes — just implemented differently. We will see the details in 0.7.

## 8. Forms — Controlled Inputs (Generic)

In React, a "controlled input" means the input's value comes from state and is updated via an `onChange` handler:

```tsx
const [email, setEmail] = useState("");
<input value={email} onChange={(e) => setEmail(e.target.value)} />
```

When you are ready to take forms further, **React Hook Form (RHF)** reduces re-renders, and **Zod** provides schema-based validation (with automatic type inference):

```tsx
// RHF + Zod shape (you will use this exact pattern in Next.js)
const schema = z.object({ email: z.string().email() });
const { register, handleSubmit } = useForm({ resolver: zodResolver(schema) });

<form onSubmit={handleSubmit(onSubmit)}>
  <input {...register("email")} />
  <button type="submit">Submit</button>
</form>
```

## 9. State Management — Context API and Zustand (Generic)

- **Context API:** Share global state across components without prop drilling (`createContext` + `useContext`).
- **Zustand:** A lightweight alternative — create a store, read and update it from any component, with minimal boilerplate compared to Context.

Both are used in Next.js for **client-side reactive state**. Server-side data (fetching from DB/API) is managed differently — we will cover that in 0.3.

## Common Mistakes (Review-Specific)

- ❌ Do not come here to re-learn React — this is a quick refresh, not a replacement.
- ❌ Do not import React Router — Next.js has file-based routing built in.
- ❌ Do not sprinkle `useEffect` everywhere — in Server Components, data fetching happens on the server (0.3).
- ❌ Do not use Context or Zustand for server-side data — those are for client-side reactive state.

## Summary

- JSX, components, props, `useState`, lists + keys, conditional rendering, `useEffect` — all from React, used unchanged in Next.js
- Router / forms / state management — the *concepts* carry over; Next.js implements them its own way (file-based routing, built-in actions)

## In Your Own Words

1. Why does React need `useState` — why is a plain variable not enough?

<details>
<summary>Sample Answer</summary>

**Answer:** A plain variable does not notify React that a value has changed. React only knows to re-render when you call the state setter function (`setCount`). If you reassign a plain variable, React has no idea the value changed and the UI does not update.

</details>

2. How did React Router handle a dynamic route like `/movies/:id`, and how did you extract the value?

<details>
<summary>Sample Answer</summary>

**Answer:** You defined a route with `path="/movies/:id"` — the `:id` was a placeholder. Then you called `const { id } = useParams()` inside the component to extract the value from the URL. Next.js's equivalent is a dynamic folder `[slug]` and the `params` prop.

</details>

3. What is a "controlled input"?

<details>
<summary>Sample Answer</summary>

**Answer:** The input's value comes from React state (`value={email}`) and is updated via `onChange` (`onChange={(e) => setEmail(e.target.value)}`). React controls the input's value — user types, state updates, value re-renders. The component is "controlled" by React.

</details>

4. In one line, what do Context API and Zustand each do?

<details>
<summary>Sample Answer</summary>

**Answer:** Both share global state across components without prop drilling — Context is built-in (more boilerplate), Zustand is a lightweight library (less boilerplate).

</details>
