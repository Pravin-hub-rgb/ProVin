## React + Next.js — Versions Come as a Pair

From React 0.0 — Next.js is a framework that wraps React. There is a deeper coupling here: **Next.js is designed to work with specific React versions.** You cannot arbitrarily drop React 19 into a Next.js 13 project — version mismatch causes subtle (and not-so-subtle) bugs.

| Next.js Version | React Version | Notes |
|---|---|---|
| **Next.js 15** | **React 19** | Current latest pair — Actions, Server Components stable |
| **Next.js 14** | **React 18** | Widely used in production — React 19 compat patch available |
| **Next.js 13** | **React 18** | App Router introduced — React 18 concurrent features required |
| **Next.js 12** | **React 17 / 18** | Older — Pages Router was dominant |
| **Next.js 11 -** | **React 16 / 17** | Very old — no longer recommended |

> **Course context:** This course uses **Next.js 15 + React 19** — the current latest stable pair. When you create a Next.js 15 project, React 19 features (Actions, `use()`, `useOptimistic`, stable Server Components) are available directly.

### Who Decides the React Version?

```
package.json (Next.js 15 project)
┌─────────────────────────────────────┐
│  "next": "15.x.x"                    │
│  "react": "19.x.x"  ← NEXT.js pins   │
│  "react-dom": "19.x.x" ← it for you │
└─────────────────────────────────────┘
```

**Next.js pins the React version in its own `package.json`.** When you run `npx create-next-app@latest`, Next.js picks the React version for you — you do not manually run `npm install react@19`. This means Next.js controls React compatibility, not you.

## React Version Highlights

These are the major React versions and what they added. You covered most of this in the React module, but the version numbers matter for the features we will use:

### React 19 (Dec 2024) — Actions + Server Components

```jsx
// React 19 features that come built-in with Next.js 15
const [state, formAction] = useFormState(serverFn, null);

function MyForm() {
  return <form action={formAction}>...</form>;
}

async function serverFn(prev, formData) {
  "use server"; // server-side function — no API route needed
  // save to DB directly
}
```

### React 18 (Mar 2022) — Concurrent Foundation

- Automatic Batching (everywhere)
- `createRoot` (concurrent root)
- `useId`, `startTransition` (covered in React 0.5)

### React 17 (Oct 2020) — Bridge Version

- No major new features — smoother upgrade path
- Event delegation moved from `document` to `root`

### React 16 (Sep 2017) — Fiber + Hooks (16.8)

- **Fiber** (covered in React 0.4)
- **Hooks** (16.8 — the biggest change)

### React 15 and earlier — Legacy

- `ReactDOM.render`, string refs, legacy context — obsolete

## What Happens If You Mismatch?

| Mismatch | What happens |
|---|---|
| Next.js 15 + React 18 | React 19 features (Actions, `use()`) are unavailable — errors or silent failures |
| Next.js 14 + React 19 | Compatibility issues — Next.js 14 was only partially tested with React 19 |
| Two React copies (duplicate) | Hook errors, context breaks, runtime crashes |
| Manual React version bump | Next.js internal patches may be missed |

> **Remember:** Next.js *wraps* React — the version inside Next.js matters deeply. Never fight the version Next.js picks for you.

## What It Is NOT

- ❌ **"React version does not matter in Next.js"** — it absolutely does. Next.js internals (SSR, hydration, rendering engine) depend on the React version.
- ❌ **"Update React manually in Next.js"** — Next.js pins its own React version. Manual updates can break internal patches.
- ❌ **"React 18 works with Next.js 15 without issues"** — partially true, but you lose React 19 features (Actions, `use()`) that Next.js 15 is designed for.
- ❌ **"All Next.js versions work with all React versions"** — no. Each major Next.js release is tested against specific React versions.

## Compatibility Cheat Sheet

**"Next.js 15 = React 19"** — that is the pairing to remember. Unless explicitly told otherwise, never manually change the React version.

```bash
# ✅ Correct — let Next.js pick the React version
npx create-next-app@latest

# ❌ Wrong — manually dropping React 19 into Next.js 14
npx create-next-app@latest
npm install react@19 react-dom@19
```

## Summary

- **Next.js 15 pairs with React 19** — Next.js pins the React version in its `package.json`
- React 19 brings Actions, `use()`, `useOptimistic`, stable Server Components
- Version mismatch → broken features, errors, or silent failures
- Always let Next.js control the React version — do not override it

## In Your Own Words

1. Which React version pairs with Next.js 15, and why does Next.js decide the React version for you?

<details>
<summary>Sample Answer</summary>

**Answer:** Next.js 15 pairs with **React 19**. Next.js decides the React version because Next.js builds on top of React's internals (SSR, hydration, the rendering engine) — a version mismatch can silently break things. When you run `create-next-app`, Next.js pins the matching React version in `package.json`, so you should not manually install a different React version.

</details>

2. What goes wrong if you use Next.js 15 with React 18?

<details>
<summary>Sample Answer</summary>

**Answer:** React 19-specific features — Server Actions, the `use()` hook, `useOptimistic`, and the stable Server Components API — are not available in React 18. The code may fail to compile or silently break at runtime. Next.js 15 is designed around React 19.

</details>

3. Why is installing a second copy of React dangerous?

<details>
<summary>Sample Answer</summary>

**Answer:** If you run `npm install react@19` on top of what Next.js already provides, you can end up with two copies of React in the bundle. This causes hook errors (React's `useState`/`useEffect` keys get confused between the two copies), context stops working across component boundaries, and runtime crashes become unpredictable.

</details>

4. What is the single compatibility rule you should memorize?

<details>
<summary>Sample Answer</summary>

**Answer:** "Next.js 15 = React 19." Let Next.js pick the React version — do not override it manually. This pairing ensures all Server Component, Action, and hydration features work as designed.

</details>
