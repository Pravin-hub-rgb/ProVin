In 3.4.4 we created a client component — `axios.get("/api/reviews")` is being called. But the route does not exist yet — an error is thrown. Now we **create the GET route** so the client can actually receive the data.

---

## THINK — Why Do We Need a Route?

The client component (`ReviewList`) cannot call the data layer directly — `fs` is a Node.js module and does not run in the browser. So we need a **middleman in between** — something that runs on the server, fetches from the data layer, and gives the data to the client. That middleman is the **Route Handler** (learned in 3.1):

```
Client (ReviewList) → axios.get("/api/reviews") → GET Route (server) → getAllReviews() → reviews.json
                                                                           ↑
                                                                     Data layer called here
```

---

## Step 1: Create the GET Route

```tsx
// app/api/reviews/route.ts
import { NextResponse } from "next/server";
import { getAllReviews, getReviewsByProduct } from "@/lib/reviews";

export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const productId = searchParams.get("productId");

  if (productId) {
    const reviews = getReviewsByProduct(Number(productId));
    return NextResponse.json(reviews);
  }

  const reviews = getAllReviews();
  return NextResponse.json(reviews);
}
```

**Line by line:**

1. **`import { NextResponse }`** — for sending the response. `NextResponse.json()` produces a JSON response.

2. **`import { getAllReviews, getReviewsByProduct }`** — functions from the data layer.

3. **`export async function GET()`** — this function handles GET requests. As learned in 3.1, the function name must match the HTTP method: `GET`, `POST`, `PUT`, `DELETE`.

4. **`new URL(request.url)`** — parse the request URL. Used to extract query parameters like `?productId=1`.

5. **`searchParams.get("productId")`** — pull `productId` from the URL. If present, convert it to a number; if absent, it is `null`.

6. **If `productId` is present** — fetch only that product's reviews with `getReviewsByProduct()`. If not — fetch all reviews with `getAllReviews()`.

7. **`NextResponse.json(reviews)`** — send the response as JSON.

## Comparison: Client Fetch vs. Server Component

In 3.4.4 the `ReviewList` we built was a **Client Component** (`"use client"`). Now a second version — a **Server Component** — that calls the data layer directly, no axios needed.

### Server Component Version:

```tsx
// app/components/ReviewListServer.tsx
import { getReviewsByProduct } from "@/lib/reviews";

export function ReviewListServer({ productId }: { productId: number }) {
  const reviews = getReviewsByProduct(productId);

  if (reviews.length === 0) {
    return <p className="text-gray-500">No reviews yet.</p>;
  }

  return (
    <div className="space-y-2">
      <h3 className="font-bold">Reviews ({reviews.length})</h3>
      {reviews.map((review) => (
        <div key={review.id} className="border p-2 rounded bg-white">
          <div className="flex justify-between items-center mb-1">
            <span>{"⭐".repeat(review.rating)}</span>
            <span className="text-sm text-gray-500">{review.createdAt}</span>
          </div>
          <p className="text-gray-700">{review.text}</p>
        </div>
      ))}
    </div>
  );
}
```

**What do you notice?** No `"use client"`, no `useState`, no `useEffect`, no `axios`. Just a direct call to `getReviewsByProduct()`. This is a **Server Component** — which means `fs` works directly here.

### Client vs. Server — Comparison:

| | Client Component (3.4.4) | Server Component (this one) |
|---|---|---|
| **`"use client"`** | Yes | No |
| **Data fetching** | `useEffect` + `axios.get()` | Direct function call |
| **`useState`** | Yes (reviews, loading) | No |
| **Loading state** | Yes ("Loading...") | Not needed (data is ready on the server) |
| **Lines of code** | More (~40) | Fewer (~25) |
| **When to use?** | When you need interactivity (click, form) | When you only need to display data |

---

## Which One to Use?

Use a **Server Component** when:
- You only need to display data (read-only)
- There is no interactivity (no clicks, forms, or inputs)
- You want less code
- Performance matters (the data is ready before the page reaches the browser)

Use a **Client Component** when:
- You need a form (inputs, submit)
- You need click handlers
- You need to manage state (loading, pending, messages)
- You need real-time updates

**For now:** reviews are only displayed — so the Server Component is better. But the next steps bring forms (add a review), edits, and deletes — those need Client Components. So we keep both versions: Server Component for the list, Client Components for forms and buttons.

## Common Mistakes

1. **Adding `"use client"` where it shouldn't be** — don't put it in a Server Component; `fs` will stop working.
2. **Skipping validation in the GET route** — `Number(productId)` can produce `NaN` if the parameter is not a valid number; handle that case.
3. **Forgetting `NextResponse.json()`** — the Route Handler must return `NextResponse.json(data)`; returning nothing means the client gets an empty response.
4. **Trying to read `request.body` on a GET** — query parameters come from `new URL(request.url).searchParams.get("productId")`, not the body.

## Problem That Remains

Right now there is only a **list page** — all reviews are shown. But there is **no detail page** — when a user clicks a review, the full review should appear. And there is **no form** — a new review cannot be added.

The next step builds the **detail page** — `/reviews/[id]`. When a user clicks a review in the list, `/reviews/1` or `/reviews/2` opens, showing the full review text. For that we need a **dynamic route `[id]`** and a **GET single route** — a route that returns one review's data.
