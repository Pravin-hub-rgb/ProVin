# Edit with Server Action + Server Component (3.3.4)

## Where We Left Off

In 3.3.3, we converted delete to a Server Action. Now add and delete both work with Server Actions — consistent patterns, no route handlers for those operations. Only **edit (PUT)** and the **detail page (GET for a single comment)** still use Route Handlers. Today we convert those.

This is the biggest boilerplate reduction — the detail page currently has `useState` × 3, `useEffect` with async fetch, manual loading states, and controlled form inputs. All of that gets replaced by a few lines.

## Current Code — The Detail Page Problem

Let's see the current state of the detail page — it's the most complex component:

```tsx
// app/comments/[id]/page.tsx — 3.2/3.3.3 version (lots of boilerplate)
"use client";

import { useEffect, useState } from "react";

export default function CommentPage({ params }: { params: Promise<{ id: string }> }) {
  const [comment, setComment] = useState<{ id: number; text: string } | null>(null);
  const [editing, setEditing] = useState(false);   // edit mode toggle
  const [editText, setEditText] = useState("");    // form input value

  useEffect(() => {
    params.then(({ id }) => {
      const load = async () => {
        const res = await fetch(`/api/comments/${id}`);
        const data = await res.json();
        setComment(data);
        setEditText(data.text);
      };
      load();
    });
  }, [params]);

  if (!comment) return <p>Loading...</p>;

  return (
    <div className="p-4 border rounded max-w-md mx-auto">
      {editing ? (
        <form onSubmit={handleUpdate} className="flex flex-col gap-2">
          <input value={editText} onChange={(e) => setEditText(e.target.value)} className="border p-2 rounded" />
          <div className="flex gap-2">
            <button type="submit" className="bg-green-500 text-white px-4 py-2 rounded">Save</button>
            <button type="button" onClick={() => setEditing(false)} className="text-gray-500 text-sm">Cancel</button>
          </div>
        </form>
      ) : (
        <>
          <p className="text-lg">{comment.text}</p>
          <button onClick={() => setEditing(true)} className="mt-3 bg-blue-500 text-white px-4 py-2 rounded">Edit</button>
        </>
      )}
    </div>
  );
}
```

All this for showing one comment and letting the user edit it. **Can we reduce it?** Yes — by making the page a Server Component.

## Step 1: Create updateCommentAction — app/actions.ts

First, the server action. This one needs both `id` and `text` from the form data:

**File:** `app/actions.ts`

```tsx
// app/actions.ts — UPDATED (add deleteCommentAction + updateCommentAction)
"use server";

import { revalidatePath } from "next/cache";
import { addComment, deleteComment, updateComment } from "@/lib/comments";

export type FormState = {
  success: boolean;
  message: string;
};

export async function addCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const text = formData.get("comment") as string;
  if (!text || !text.trim()) {
    return { success: false, message: "Comment cannot be empty!" };
  }
  addComment(text);
  revalidatePath("/");
  return { success: true, message: "Comment added!" };
}

export async function deleteCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const id = Number(formData.get("id"));
  const deleted = deleteComment(id);
  if (!deleted) {
    return { success: false, message: "Comment not found!" };
  }
  revalidatePath("/");
  return { success: true, message: "Comment deleted!" };
}

// NEW: update — needs id + text both from form data
export async function updateCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const id = Number(formData.get("id"));
  const text = formData.get("text") as string;

  if (!text || !text.trim()) {
    return { success: false, message: "Comment cannot be empty!" };
  }

  const updated = updateComment(id, text);

  if (!updated) {
    return { success: false, message: "Comment not found!" };
  }

  // Edit changes data in TWO places — list page AND detail page
  revalidatePath("/");
  revalidatePath(`/comments/${id}`);

  return { success: true, message: "Comment updated!" };
}
```

**Why two `revalidatePath` calls?** Edit changes data visible on **two pages** — the list page (`/`) shows the comment text, and the detail page (`/comments/${id}`) shows it too. One `revalidatePath` only handles one path, so we invalidate both.

## Step 2: Create EditCommentForm Component

The edit form needs to be a Client Component (for the editing toggle state). But the page itself becomes a Server Component that reads data directly.

**File:** `app/components/EditCommentForm.tsx` — NEW FILE

```tsx
// app/components/EditCommentForm.tsx
"use client";

import { useState, useEffect, useActionState } from "react";
import { toast } from "sonner";
import { updateCommentAction, FormState } from "../actions";

const initialState: FormState = {
  success: false,
  message: "",
};

export default function EditCommentForm({
  comment,
}: {
  comment: { id: number; text: string };
}) {
  const [editing, setEditing] = useState(false);
  const [state, formAction, isPending] = useActionState(
    updateCommentAction,
    initialState
  );

  // Close the form when the update succeeds
  useEffect(() => {
    if (state.success) {
      setEditing(false);
    }
  }, [state]);

  return (
    <div className="mt-3">
      {editing ? (
        <form action={formAction} className="flex flex-col gap-2">
          <input type="hidden" name="id" value={comment.id} />

          <input
            name="text"
            defaultValue={comment.text}
            className="border p-2 rounded"
          />

          <div className="flex gap-2">
            <button
              type="submit"
              disabled={isPending}
              className="bg-green-500 text-white px-4 py-2 rounded disabled:opacity-50"
            >
              {isPending ? "Saving..." : "Save"}
            </button>
            <button
              type="button"
              onClick={() => setEditing(false)}
              className="text-gray-500 text-sm"
            >
              Cancel
            </button>
          </div>
        </form>
      ) : (
        <button
          onClick={() => setEditing(true)}
          className="mt-3 bg-blue-500 text-white px-4 py-2 rounded hover:bg-blue-600"
        >
          Edit
        </button>
      )}
    </div>
  );
}
```

**Key changes from the 3.2 version:**

1. **`defaultValue={comment.text}`** instead of `value={editText}` — **uncontrolled** instead of controlled. The form doesn't need React state tracking the input because the Server Action reads directly from FormData. No `onChange`, no `editText` state.

2. **`<input type="hidden" name="id" />`** — same pattern as delete (3.3.3). The comment ID is passed via hidden input.

3. **`useEffect` to close form on success** — when `state.success` becomes true, we automatically close the edit form. No manual "Cancel" needed after saving.

4. **Only one piece of state:** `editing` (boolean). The old `comment` and `editText` states are gone — data comes from props.

5. **Cancel button** — `type="button"` so it doesn't submit the form, just calls `setEditing(false)`.

## Step 3: Convert Detail Page to Server Component

Now rewrite the detail page. It becomes a Server Component that reads data directly:

**File:** `app/comments/[id]/page.tsx`

```tsx
// app/comments/[id]/page.tsx — UPDATED (Server Component)
import { getCommentById } from "@/lib/comments";
import { notFound } from "next/navigation";
import Link from "next/link";
import EditCommentForm from "../../components/EditCommentForm";

export default async function CommentPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const comment = getCommentById(Number(id));

  if (!comment) {
    notFound();
  }

  return (
    <div className="p-4 border rounded max-w-md mx-auto">
      <p className="text-lg mb-4">{comment.text}</p>
      <EditCommentForm comment={comment} />
      <Link href="/" className="text-blue-600 hover:underline mt-4 block">
        ← Back to comments
      </Link>
    </div>
  );
}
```

**What disappeared:**
1. `"use client"` — Server Component, no hooks needed
2. `useState` × 3 — data from props, editing state in EditCommentForm
3. `useEffect` + `params.then` + async `fetch` — direct `getCommentById()` call
4. Loading state — Server Component has data at render time

**New things:**
- `await params` — Server Components can be async
- `getCommentById()` — direct data layer call
- `notFound()` — built-in 404 if comment doesn't exist

## Step 4: Clean Up — Delete Route Handlers

Now that delete and edit both use Server Actions, and the detail page reads directly from `getCommentById()`, both route handlers are unused. Delete the entire `app/api/` folder:

```
app/api/comments/route.ts → DELETE
app/api/comments/[id]/route.ts → DELETE
app/api/ → DELETE ENTIRE FOLDER
```

## How It All Works Together

```
Detail Page (Server Component)
  ├─ await params → get id
  ├─ getCommentById(id) → get comment
  ├─ notFound() if not exists
  └─ Render:
       ├─ comment.text (display)
       ├─ EditCommentForm (Client Component)
       │    ├─ editing state → show Edit button or form
       │    └─ form action={formAction} (calls updateCommentAction)
       │         ├─ hidden input name="id" = comment.id
       │         └─ input name="text" defaultValue=comment.text
       └─ Link back to home
```

## Summary of Changes

| Aspect | Before (3.2) | Now (3.3.4) |
|---|---|---|
| **Page type** | Client Component | Server Component |
| **Data loading** | `useEffect` + `params.then` + `fetch` + loading state | `await params` + `getCommentById()` direct |
| **Edit form state** | 3 `useState` (comment, editing, editText) | 1 `useState` (editing only) |
| **Form inputs** | Controlled (`value` + `onChange`) | Uncontrolled (`defaultValue`) |
| **404 handling** | Manual `{ status: 404 }` | `notFound()` built-in |
| **Edit submission** | `handleUpdate` + `fetch` PUT + headers + body | `action={formAction}` + `useActionState` |

## What It Is NOT

- **`defaultValue` is not "less capable"** — it's simpler. Controlled inputs let you validate on every keystroke; uncontrolled just reads the value when needed. For Server Actions, uncontrolled is the right choice.
- **`"use client"` on EditCommentForm is not a mistake** — only the interactive part (edit button toggle) needs to be a Client Component. The page and data reading stay Server Components.
- **`notFound()` is not a custom 404 page** — it triggers Next.js's built-in 404. You can customize it later with `app/not-found.tsx`.

## In Your Own Words

<details>
<summary>Question 1: What boilerplate was eliminated by converting the detail page to a Server Component?</summary>
<p><strong>Answer:</strong> All three `useState` calls (comment, editing, editText), the `useEffect` with `params.then` and inner async `fetch`, the loading state, and manual response handling after save. The Server Component directly calls `getCommentById()` — no network request needed.</p>
</details>

<details>
<summary>Question 2: Why use `defaultValue` instead of `value` for the edit input?</summary>
<p><strong>Answer:</strong> `defaultValue` makes the input **uncontrolled** — the browser manages the input value after initial render. `value` makes it **controlled** — React must track every change via state and `onChange`. Server Actions read from FormData directly, so React doesn't need to track the input. Uncontrolled is simpler and sufficient for Server Actions.</p>
</details>

<details>
<summary>Question 3: Why split the edit functionality between a Server Component (page) and a Client Component (EditCommentForm)?</summary>
<p><strong>Answer:</strong> The page reads data — Server Component. But the edit button toggle and form submission need `useState` and `useActionState` — those hooks only work in Client Components. The page passes data via props, the Client Component handles interaction. This split is the Next.js best practice: data on server, interactivity on client.</p>
</details>

<details>
<summary>Question 4: Why does `updateCommentAction` have two `revalidatePath` calls?</summary>
<p><strong>Answer:</strong> Editing a comment changes data visible on two pages: the list page (`/`) and the detail page (`/comments/{id}`). Each `revalidatePath` call clears the cache for one path. Both need to be invalidated so both show the updated text.</p>
</details>
