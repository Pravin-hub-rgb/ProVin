# addReviewAction + Form Connection (3.4.11)

## Where We Left Off

In 3.4.10, we built the static form UI for the Server Actions version — using uncontrolled inputs with `name` attributes and no `useState`. Now we connect it to a real Server Action.

## Step 1: Create the Server Action

Create `app/actions.ts` with the `addReviewAction`:

```tsx
// app/actions.ts
"use server";

import { addReview } from "@/lib/reviews";
import { revalidatePath } from "next/cache";

export type FormState = {
  success: boolean;
  message: string;
};

export async function addReviewAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const text = formData.get("text") as string;
  const rating = Number(formData.get("rating"));
  const productId = Number(formData.get("productId"));

  // Validation
  if (!text || !text.trim()) {
    return { success: false, message: "Review text is required" };
  }
  if (!rating || rating < 1 || rating > 5) {
    return { success: false, message: "Rating must be between 1 and 5" };
  }

  // Call the data layer
  const review = addReview({ productId, text, rating });

  if (!review) {
    return { success: false, message: "Failed to add review" };
  }

  // Refresh the reviews page to show the new review
  revalidatePath("/reviews");

  return { success: true, message: "Review added successfully" };
}
```

### What's Happening

1. **`"use server"`** — tells Next.js this file contains Server Actions. All exported functions become callable from the client.

2. **`formData.get("text")`** — extracts form field values by `name` attribute. This matches the `<input name="text">` and `<textarea name="text">` from the form.

3. **`Number()`** — form values are always strings, but `rating` and `productId` need to be numbers for the data layer.

4. **Validation** — same checks as the Route Handler version, but instead of returning `NextResponse.json({ error })`, we return `{ success: false, message: "..." }`.

5. **`addReview()`** — calls the data layer function. Same as the Route Handler version — the data layer hasn't changed.

6. **`revalidatePath("/reviews")`** — tells Next.js to re-render the `/reviews` page. This triggers a fresh call to `getReviewsByProduct()`, showing the new review.

## Step 2: Connect to the Form

Update `ReviewFormServer` to use the Server Action:

```tsx
// app/components/ReviewFormServer.tsx
import { addReviewAction } from "../actions";

export function ReviewFormServer({ productId }: { productId: number }) {
  const initialState = { success: false, message: "" };

  return (
    // action={addReviewAction} replaces onSubmit={handleSubmit}
    <form action={addReviewAction} className="space-y-3 border p-4 rounded bg-white mt-4">
      <h3 className="font-bold">New Review</h3>

      <input type="hidden" name="productId" value={productId} />

      <div>
        <label className="block text-sm font-medium mb-1">Rating:</label>
        <select
          name="rating"
          defaultValue={5}
          className="border p-2 rounded w-full"
        >
          {[1, 2, 3, 4, 5].map((n) => (
            <option key={n} value={n}>{"⭐".repeat(n)}</option>
          ))}
        </select>
      </div>

      <div>
        <label className="block text-sm font-medium mb-1">Review:</label>
        <textarea
          name="text"
          placeholder="Write your review..."
          className="w-full border p-2 rounded"
          rows={3}
        />
      </div>

      <button
        type="submit"
        className="bg-blue-500 text-white px-4 py-2 rounded hover:bg-blue-600"
      >
        Submit Review
      </button>
    </form>
  );
}
```

### What Changed?

| Route Handler Version | Server Actions Version |
|---|---|
| `onSubmit={handleSubmit}` | `action={addReviewAction}` |
| `handleSubmit` calls `axios.post()` | No handleSubmit — form directly calls the action |
| `useState` for `text`, `rating`, `pending` | No useState — uncontrolled inputs |
| `e.preventDefault()` | Not needed — `action` handles submission |
| Manual `setText("")`, `setRating(5)` | Not needed — form resets based on `revalidatePath` |

### Why It Works

When you write `<form action={addReviewAction}>`, Next.js:
1. Intercepts the form submission (no page reload)
2. Sends a request to the server with the form data as `FormData`
3. Calls `addReviewAction(formData)` on the server
4. The action runs, modifies data, calls `revalidatePath`
5. The page re-renders with fresh data

All without any axios, fetch, or manual state management from you.

## Behind the Scenes

```
[Browser]
  Form submits
    ↓
[Next.js Client]
  Intercepts submission (no page reload)
  Packages form data as FormData
    ↓
[Next.js Server]
  Calls addReviewAction(prevState, formData)
  → formData.get("text") → review text
  → formData.get("rating") → rating
  → addReview() → saves to reviews.json
  → revalidatePath("/reviews") → marks page as stale
  → returns { success: true, message: "Review added" }
    ↓
[Browser]
  Page re-renders (fresh data from Server Component)
  New review appears
```

Compare this to the Route Handler version:

```
[Browser]
  axios.post("/api/reviews", ...)
    ↓
[Next.js Server — API Route]
  await request.json()
  → addReview() → saves
  → NextResponse.json(review, { status: 201 })
    ↓
[Browser]
  res.data → setReview
  window.location.reload()
```

The Server Action version is simpler: **no axios call, no API route file, no manual refresh.**

## Common Mistakes

- **Forgetting `"use server"`** — without this directive, the function can't be called as a Server Action
- **Using `action={addReviewAction}` with parentheses** — it should be `action={addReviewAction}`, not `action={addReviewAction()}`
- **Missing `name` attributes on inputs** — `FormData.get()` matches by name
- **Using `value` instead of `name`** — controlled vs uncontrolled; Server Actions need `name`
- **Converting values too late** — `Number(formData.get("id"))` — convert in the action, not expecting strings

## What It Is NOT

- **This form doesn't have pending states** — yet. We'll add `useActionState` in 3.4.12 for loading states and feedback messages.
- **Server Actions don't replace the API entirely** — if external clients need the data, the GET routes in 3.4.5 still work alongside.
- **Server Actions aren't "always simpler"** — they're simpler for forms in Next.js-only apps. For external clients or complex logic, Route Handlers are still needed.

## In Your Own Words

<details>
<summary>Question 1: How does `<form action={serverAction}>` differ from `<form onSubmit={clientHandler}>`?</summary>
<p><strong>Answer:</strong> `action` triggers a Server Action — the form data is sent to a server function that Next.js manages. `onSubmit` triggers a client-side handler — you manually call `fetch` or `axios`, manage the response, and handle state. Server Actions handle the network communication, `useActionState` handles state.</p>
</details>

<details>
<summary>Question 2: How does `formData.get()` know which input value to retrieve?</summary>
<p><strong>Answer:</strong> Each form field needs a `name` attribute (like `<input name="text" />`). `FormData.get("text")` finds the field with `name="text"` and returns its value. The names must match exactly.</p>
</details>

<details>
<summary>Question 3: What does `revalidatePath("/reviews")` do?</summary>
<p><strong>Answer:</strong> It tells Next.js that the `/reviews` page's cached render is now stale. On the next request to that page, it re-renders fresh — calling `getReviewsByProduct()` again. The new review appears without a hard refresh.</p>
</details>

<details>
<summary>Question 4: Why don't we need `e.preventDefault()` with `action={addReviewAction}`?</summary>
<p><strong>Answer:</strong> When using `action`, the form submission is handled by the browser's native form mechanism — it sends the data to the Server Action without a traditional page reload. Next.js intercepts this and routes it through the Server Action infrastructure. No `preventDefault` needed.</p>
</details>
