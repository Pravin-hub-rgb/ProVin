# useActionState + Success/Error Messages (3.4.12)

## Where We Left Off

In 3.4.11, we connected the form to a Server Action using `action={addReviewAction}`. The form works — submitting adds a review, and `revalidatePath("/reviews")` makes it appear on the list. But there's no user feedback: no loading spinner, no success message, no error display.

Now we'll add `useActionState` and toast notifications for proper user feedback.

## Step 1: Wrap with useActionState

The key change: we replace `action={addReviewAction}` with `action={formAction}`, where `formAction` comes from `useActionState`. This gives us `state` (the action's return value) and `isPending` (loading state):

```tsx
// app/components/ReviewFormServer.tsx
"use client";

import { useActionState } from "react";
import { addReviewAction, FormState } from "../actions";

const initialState: FormState = {
  success: false,
  message: "",
};

export function ReviewFormServer({
  productId,
}: {
  productId: number;
}) {
  const [state, formAction, isPending] = useActionState(
    addReviewAction,
    initialState
  );

  return (
    <form
      action={formAction}
      className="space-y-3 border p-4 rounded bg-white mt-4"
    >
      <h3 className="font-bold">New Review</h3>

      <input type="hidden" name="productId" value={productId} />

      <div>
        <label className="block text-sm font-medium mb-1">Rating:</label>
        <select
          name="rating"
          defaultValue={5}
          className="border p-2 rounded w-full"
          disabled={isPending}
        >
          {[1, 2, 3, 4, 5].map((n) => (
            <option key={n} value={n}>{"⭐".repeat(n)}</option>
          ))}
        </select>
      </div>

      <div>
        <label className="block text-sm font-medium mb-1">Review:</label>
        <textarea
          name="text"
          placeholder="Write your review..."
          className="w-full border p-2 rounded"
          rows={3}
          disabled={isPending}
        />
      </div>

      <button
        type="submit"
        disabled={isPending}
        className="bg-blue-500 text-white px-4 py-2 rounded hover:bg-blue-600 disabled:bg-gray-400"
      >
        {isPending ? "Adding..." : "Submit Review"}
      </button>

      {state.message && (
        <p
          className={
            state.success ? "text-green-500" : "text-red-500"
          }
        >
          {state.message}
        </p>
      )}
    </form>
  );
}
```

### What useActionState Returns

| Return Value | Purpose |
|---|---|
| `state` | The action's return value (`{ success, message }`) |
| `formAction` | The wrapped action to put on `<form action={...}>` |
| `isPending` | `true` while the action is running, `false` when done |

### What Changed

1. **`useActionState(addReviewAction, initialState)`** — wraps the action
2. **`action={formAction}`** instead of `action={addReviewAction}` — the wrapped version
3. **`disabled={isPending}`** on inputs and button — prevents double submits
4. **`{isPending ? "Adding..." : "Submit Review"}`** — button text changes during loading
5. **`{state.message && <p>...}`** — shows success or error message

### Why `formAction` Instead of `addReviewAction` Directly?

The HTML `<form action={fn}>` convention calls `fn(formData)` — one argument. But Server Actions called via `useActionState` expect **two arguments**: `(prevState, formData)`. The `formAction` adapter bridges this gap — it automatically provides `prevState` (or `initialState`) as the first argument.

If you use `action={addReviewAction}` directly, TypeScript will complain about the argument count mismatch.

## Step 2: Add Toast Notifications

Inline messages are good, but toasts are better for user experience. They appear in a corner of the screen and auto-dismiss. Let's add `sonner`:

```bash
npm install sonner
```

Add `<Toaster />` to the layout:

```tsx
// app/layout.tsx (updated)
import { Toaster } from "sonner";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <body className="bg-gray-50 min-h-screen">
        <nav className="bg-white shadow p-4">
          <h1 className="text-xl font-bold">Reviews & Ratings</h1>
        </nav>
        <main className="max-w-2xl mx-auto p-4">{children}</main>
        <Toaster position="bottom-right" />
      </body>
    </html>
  );
}
```

Then use toasts in the component:

```tsx
// app/components/ReviewFormServer.tsx (with toast)
"use client";

import { useEffect, useActionState } from "react";
import { toast } from "sonner";
import { addReviewAction, FormState } from "../actions";

const initialState: FormState = { success: false, message: "" };

export function ReviewFormServer({
  productId,
}: {
  productId: number;
}) {
  const [state, formAction, isPending] = useActionState(
    addReviewAction,
    initialState
  );

  // Show toast when state changes
  useEffect(() => {
    if (state.message) {
      if (state.success) {
        toast.success(state.message);
      } else {
        toast.error(state.message);
      }
    }
  }, [state]);

  return (
    <form
      action={formAction}
      className="space-y-3 border p-4 rounded bg-white mt-4"
    >
      <h3 className="font-bold">New Review</h3>

      <input type="hidden" name="productId" value={productId} />

      <div>
        <label className="block text-sm font-medium mb-1">Rating:</label>
        <select
          name="rating"
          defaultValue={5}
          className="border p-2 rounded w-full"
          disabled={isPending}
        >
          {[1, 2, 3, 4, 5].map((n) => (
            <option key={n} value={n}>{"⭐".repeat(n)}</option>
          ))}
        </select>
      </div>

      <div>
        <label className="block text-sm font-medium mb-1">Review:</label>
        <textarea
          name="text"
          placeholder="Write your review..."
          className="w-full border p-2 rounded"
          rows={3}
          disabled={isPending}
        />
      </div>

      <button
        type="submit"
        disabled={isPending}
        className="bg-blue-500 text-white px-4 py-2 rounded hover:bg-blue-600 disabled:bg-gray-400"
      >
        {isPending ? "Adding..." : "Submit Review"}
      </button>
    </form>
  );
}
```

**Note:** We removed the inline `{state.message && <p>}` — toast notifications handle feedback instead.

## Test It

```bash
npm run dev
```

1. **Valid submission:** Fill form → Submit → "Adding..." → Toast: "Review added successfully" (green)
2. **Invalid submission:** Empty text → Submit → Toast: "Review text is required" (red)
3. **Invalid rating:** Rating 0 or 6 → Submit → Toast: "Rating must be between 1 and 5"
4. **Form disabled during:** Try clicking Submit twice — second click is ignored
5. **Page refresh:** New review appears in the list automatically

## Route Handler vs Server Action — State Management

| Route Handler | Server Actions |
|---|---|
| `useState` for `text` | No `useState` needed — uncontrolled inputs |
| `useState` for `rating` | No `useState` needed — uncontrolled inputs |
| `useState` for `pending` | `isPending` from `useActionState` |
| `useState` for `message` | `state.message` from `useActionState` |
| `try/catch` for errors | Return `{ success: false, message: "..." }` |
| Inline `<p>` for messages | `toast.success()` / `toast.error()` |

**5 `useState` hooks in Route Handler → 0 `useState` hooks in Server Actions version.** All state management is handled by `useActionState`.

## What It Is NOT

- **Toasts replace inline messages** — they're complementary. Use toasts for transient feedback; use inline messages for persistent error context within the form.
- **`isPending` doesn't prevent all double submits** — it prevents clicks, but the form could still be submitted by pressing Enter. Server-side deduplication (checking for existing data) handles the rest.
- **`useActionState` is not "just a hook"** — it fundamentally changes how form state works. The action's return value becomes the state, and `revalidatePath` ensures fresh data without manual refresh.

## In Your Own Words

<details>
<summary>Question 1: What does `useActionState` return, and how do you use each part?</summary>
<p><strong>Answer:</strong> It returns `[state, formAction, isPending]`: `state` holds the action's return value (starts as `initialState`, becomes the action's return after submission), `formAction` is the wrapped action that goes on `<form action={formAction}>`, and `isPending` is a boolean that's `true` while the server action is executing. Use `isPending` to disable buttons and show "Loading..." text; use `state` to show success/error messages via toast.</p>
</details>

<details>
<summary>Question 2: Why must you use `formAction` instead of passing `addReviewAction` directly to the form?</summary>
<p><strong>Answer:</strong> The native `<form action={fn}>` calls `fn(formData)` with one argument. But `useActionState` actions expect `(prevState, formData)` with two arguments. `formAction` is the adapter that provides `prevState` automatically. Without it, the action would receive `undefined` for `prevState`.</p>
</details>

<details>
<summary>Question 3: How does `useEffect` watching `[state]` trigger toasts?</summary>
<p><strong>Answer:</strong> When the action returns, `useActionState` updates `state` with the action's return value. This causes a re-render, which triggers the `useEffect` that watches `[state]`. Inside the effect, we check `state.message` and call `toast.success()` or `toast.error()` based on `state.success`.</p>
</details>

<details>
<summary>Question 4: Why is the number of `useState` hooks lower with Server Actions?</summary>
<p><strong>answer:</p>
<p>With Route Handlers, you manually manage everything with `useState`: text input state, rating state, loading state, and message state. With Server Actions, `useActionState` provides loading state (`isPending`) and return value (`state`) automatically, and uncontrolled inputs (`name` + `defaultValue`) don't need React state. The form data is collected by the browser and passed to the action.</p>
</details>
