## Broader Goal

With file-based routing, you handled fixed paths (`/about`, `/blog`). But a blog has **many posts** — `/blog/my-first-post`, `/blog/second-post`, `/blog/hello-world`. You cannot create a folder for every post. **Dynamic routes** solve this: a single `page.tsx` handles any number of slugs via `[slug]`.

This file covers:

**A — Dynamic Routes in Practice.** Create `[slug]/page.tsx` so one page catches `/blog/anything`.

**B — `params` — The URL Data.** How Next.js passes the slug value to your page function.

**C — `async` Server Components.** Why the page can be `async`, how `await params` works, and the Next.js 15 Promise change.

**D — Conditional `notFound()` Call.** Trigger a 404 when the slug does not match any post.

## Manual → Better

In React Router, dynamic routes used `:id` and `useParams()`. In Next.js, the `[slug]` folder convention is simpler and the `params` prop is automatic.

## A — Dynamic Routes in Practice

### The Problem — One Post Per Route

Without dynamic routes, each blog post needs its own folder and page:

```
app/blog/
├── first-post/
│   └── page.tsx   →  /blog/first-post
├── second-post/
│   └── page.tsx   →  /blog/second-post
└── hello-world/
    └── page.tsx   →  /blog/hello-world
```

Ten posts → ten folders. A hundred posts → a hundred folders. Impossible to scale.

### Better — One Dynamic Route

Create a single folder named `[slug]` — it catches **any** value after `/blog/`:

```
app/blog/
├── page.tsx              →  /blog  (list of posts — static)
└── [slug]/
    └── page.tsx          →  /blog/:slug (dynamic — ONE file for all posts!)
```

```tsx
// app/blog/[slug]/page.tsx
export default async function BlogPost({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  return <h1>Blog Post: {slug}</h1>;
}
```

Now:
- `/blog/my-first-post` → `params.slug = "my-first-post"`
- `/blog/second-post` → `params.slug = "second-post"`
- `/blog/anything-here` → `params.slug = "anything-here"`

**One file. Infinite routes.**

### The Rule — Square Brackets = Dynamic

- Folder name with `[slug]` → the URL segment is captured into `params.slug`.
- The name inside brackets = the key you get in `params`. Use `[id]` → `params.id`.
- Use `[...slug]` for catch-all segments (advanced, we cover that later).

## B — `params` — The URL Data

### The Convention — `params` Prop

When you visit `/blog/my-first-post`, Next.js routes the request to `[slug]/page.tsx` and calls your function with the captured value:

```tsx
// Next.js internally does:
BlogPost({ params: { slug: "my-first-post" } })
```

This is the **props pattern** you know from React:

```tsx
// React — parent passes props to child
<BlogPost params={{ slug: "my-first-post" }} />
```

**Think of it this way:** Next.js is the parent. You just write the component that receives `params`. Next.js calls it for you with the right values.

### Naming the Dynamic Segment

The folder name determines the `params` key:

| Folder | URL | Access |
|---|---|---|
| `[slug]` | `/blog/my-post` | `params.slug` |
| `[id]` | `/blog/123` | `params.id` |
| `[productId]` | `/products/42` | `params.productId` |

Whatever you put inside `[...]` is the property name you access. Be descriptive — `[slug]` or `[productId]` is clearer than `[s]`.

### TypeScript — Typing `params`

```tsx
export default async function BlogPost({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  // slug is typed as string
}
```

The type `{ slug: string }` declares what `params` will contain. Since you `await` it, TypeScript knows `slug` is a string by the time you destructure it.

### `export default` Is Still Required

Same rule as before — the page function must be a default export. Next.js imports it: `import BlogPost from './[slug]/page'`. The name in `export default function BlogPost()` can be anything, but the default export is non-negotiable.

## C — `async` Server Components

### Why `async` Works on Server Components

A Server Component can use `async` because Next.js renders it on the server before sending HTML to the client:

```tsx
export default async function BlogPost({ params }) {
  const { slug } = await params;        // await — Next.js resolves before HTML
  const post = await fetchPost(slug);    // await — fetch data before HTML
  return <h1>{post.title}</h1>;
}
```

The entire `async` function runs to completion on the server. By the time the function returns JSX, everything (params, fetch) is resolved. The client receives ready-to-render HTML.

### Next.js 15 — `params` Is a Promise

In Next.js 15+, `params` is a **Promise** — you must `await` it:

```tsx
// Next.js 15+
export default async function BlogPost({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;  // must await!
  return <h1>{slug}</h1>;
}
```

If you forget `await`:

```tsx
const { slug } = params;  // ❌ ERROR: slug is undefined
```

Because `params` is a Promise object — `params.slug` is `undefined` (Promises do not have `.slug`). You must `await params` before accessing its keys.

**Rule:** if the type says `Promise<{ slug: string }>`, always `await` before destructuring.

### Client Components Cannot Be `async`

If a component is a **Client Component** (`"use client"` at the top), it **cannot** use `async`:

```tsx
"useuse client";
export default async function BlogPost({ params }) {
  // ❌ SyntaxError: 'await' is only allowed within async function
}
```

Client Components use hooks and must stay synchronous. To use `params` in a Client Component, you must use `.then()` instead:

```tsx
"use use client";
import { useEffect, useState } from 'react';

export default function BlogPost({ params }) {
  const [slug, setSlug] = useState("");

  useEffect(() => {
    params.then(({ slug }) => setSlug(slug));
  }, []);

  return <h1>{slug}</h1>;
}
```

But for Server Components, `async` + `await` is the clean, natural pattern.

## D — Conditional `notFound()` Call

### The Data Match Pattern

With dynamic routes, the slug from the URL must match real data:

```tsx
const posts = [
  { slug: "my-first-post", title: "My First Post" },
  { slug: "hello-world", title: "Hello World" },
];

export default async function BlogPost({ params }) {
  const { slug } = await params;
  const post = posts.find((p) => p.slug === slug);

  // What if the slug does not match? → 404
  if (!post) {
    notFound();
  }

  return <h1>{post.title}</h1>;
}
```

- `posts.find(...)` returns the matching post, or `undefined` if no match.
- If no match, call `notFound()` — Next.js renders the 404 page.

### Importing `notFound`

```tsx
import { notFound } from 'next/navigation';
```

`next/navigation` is Next.js's navigation toolbox — it also provides `redirect()`, `useRouter()`, `useParams()`, `usePathname()`. Import what you need from this module.

### `notFound()` Behavior

`notFound()` does **not return** — calling it immediately interrupts rendering and shows the 404 page. Any code after `notFound()` does not execute:

```tsx
if (!post) {
  notFound();   // ← renders 404, code below is unreachable
  console.log("This never runs");
}
```

This makes the `notFound()` call like an early return — but instead of returning `null`, it hands control to Next.js to render the 404 page.

## In Practice — Full Blog Post Page

```tsx
// app/blog/[slug]/page.tsx
import { notFound } from 'next/navigation';
import { posts } from '@/lib/posts';

export default async function BlogPost({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;

  // Find the post that matches the slug from the URL
  const post = posts.find((p) => p.slug === slug);

  // If no match → trigger 404
  if (!post) {
    notFound();
  }

  // Render the matched post
  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </article>
  );
}
```

**The flow:**
1. Visit `/blog/my-first-post`
2. Next.js routes to `/app/blog/[slug]/page.tsx`
3. Calls `BlogPost({ params: { slug: "my-first-post" } })`
4. You `await params` → `slug = "my-first-post"`
5. Look up the post → found or not
6. If not found → `notFound()` shows the 404 page
7. If found → render the post content

## In Your Own Words

1. How does `[slug]` work as a dynamic route, and what appears in `params`?

<details>
<summary>Sample Answer</summary>

**Answer:** Creating a folder `[slug]` inside `app/blog/` makes the route `/blog/:slug` — one page catches any slug. When visiting `/blog/my-post`, Next.js calls my function with `params = { slug: "my-post" }`. The name inside brackets determines the params key — `[slug]` gives `params.slug`, `[id]` gives `params.id`.

</details>

2. Why can `BlogPost` be `async`, and what must you do before accessing `params.slug`?

<details>
<summary>Sample Answer</summary>

**Answer:** `BlogPost` is a Server Component — Next.js renders it on the server, so `async`/`await` is allowed. I must `await params` before destructuring `slug` because in Next.js 15, `params` is a Promise. Writing `const { slug } = params` gives `undefined` — I have to do `const { slug } = await params;` to get the actual string value.

</details>

3. When does `notFound()` run, and what page does it show?

<details>
<summary>Sample Answer</summary>

**Answer:** `notFound()` runs when the slug from the URL does not match any post in my data — i.e., `posts.find(...)` returns `undefined`. It tells Next.js to render the 404 page (which I will customize in `not-found.tsx` later). `notFound()` does not return — it interrupts rendering and shows the 404 immediately.

</details>

4. Why is this pattern ("you write the function, Next.js calls it") consistent with what we saw in 1.0 and 1.1?

<details>
<summary>Sample Answer</summary>

**Answer:** It is the same contract across all special files — Next.js is the caller. In `page.tsx` (1.0) Next.js calls my page function with `params`. In `layout.tsx` (1.1) Next.js passes `children`. Here in `[slug]/page.tsx`, Next.js passes `params` from the URL. I write the function signature; Next.js fills in the props. It is always the props pattern — Next.js is the parent, I am the child component receiving data.

</details>
