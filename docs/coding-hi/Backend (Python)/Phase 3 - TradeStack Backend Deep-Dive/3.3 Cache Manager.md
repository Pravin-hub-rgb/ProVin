# 3.3 Cache Manager — Pickle Cache, .pkl Files, Invalidation

## Soch (Sochne Wala Scene)

Library with 2000 books socho. Har baar jab koi puche "kya RELIANCE hai?" shelves walk karna slow hai. Librarian ek card catalog rakhta hai (SQLite `cache_index`): ek card per book title, page count, last checked date ke saath. Actual book shelf pe hai (`.pkl` file). Pehle card dekho (instant), phir book fetch karo only if needed.

`cache_manager.py` woh librarian hai. `save()` book write karta hai AND card update. `load()` book fetch karta hai. `stats()` card catalog read. `list_symbols()` card catalog read. Filesystem shelf hai; SQLite catalog hai.

## Concept — Cache Kyun Exist Karta Hai

TradeStack 2000 stocks × 13 indicators scan karta hai. Agar har scan Upstox API se read kare, rate limits hit honge, bandwidth cost, aur scan minutes lagega. Instead:

- Historical OHLCV ek baar download hota hai (bhavcopy / Upstox historical) aur `.pkl` files mein store.
- Scans, charts, stock list sab in files se read.
- Sirf **new** data (aaj ka bhavcopy) append hota hai.

Toh cache app ki speed ka whole point hai. Iske bina TradeStack sirf slow API proxy hai.

## Concept — Pickle Serialization

Python ka `pickle` module Python objects ko bytes mein serialize karta hai aur back. Pandas DataFrame (DatetimeIndex + typed columns) pickle ho kar ek single file banta hai aur unpickle ho kar identical DataFrame:

```python
import pickle
import pandas as pd

# SAVE
with open("RELIANCE.pkl", "wb") as f:
    pickle.dump(df, f)        # df -> bytes on disk

# LOAD
with open("RELIANCE.pkl", "rb") as f:
    data = pickle.load(f)     # bytes -> DataFrame
```

`cache_manager` isko wrap karta hai:

```python
class CacheManager:
    def __init__(self, cache_dir=None):
        ...
        self.cache_dir = Path(cache_dir)
        self.cache_dir.mkdir(parents=True, exist_ok=True)

    def get_cache_path(self, symbol):
        return self.cache_dir / f"{symbol.upper()}.pkl"

    def load(self, symbol):
        path = self.get_cache_path(symbol)
        if not path.exists():
            return None
        try:
            with open(path, "rb") as f:
                data = pickle.load(f)
            if isinstance(data, pd.DataFrame) and not data.empty:
                return data
            return None
        except Exception as e:
            logger.warning(f"Failed to load cache for {symbol}: {e}")
            return None

    def save(self, symbol, data, commit=True):
        path = self.get_cache_path(symbol)
        try:
            with open(path, "wb") as f:
                pickle.dump(data, f)
            self._update_index(symbol, data, path, commit=commit)
            logger.debug(f"Saved cache for {symbol}: {len(data)} rows")
        except Exception as e:
            logger.error(f"Failed to save cache for {symbol}: {e}")
            raise
```

`save()` pe do cheezein hoti hain: (1) `.pkl` file write, (2) `cache_index` mein row upsert. Agar step 1 succeed but step 2 fail, file exist karta hai par index nahi jaanta — `rebuild_index()` fix karta hai.

## Concept — Dual Source of Truth

Do stores hain:

1. **Filesystem** (`data/cache/*.pkl`) — price data ka source of truth.
2. **SQLite `cache_index`** — fast metadata queries ke liye derived index.

Har read SQLite prefer karta hai aur filesystem pe fallback:

```python
def stats(self):
    result = db.get_cache_stats()
    if result["stock_count"] > 0:
        return result
    files = list(self.cache_dir.glob("*.pkl"))
    total_size = sum(f.stat().st_size for f in files)
    latest_date = self.get_latest_cache_date()
    return {"stock_count": len(files), "total_size_mb": total_size / (1024*1024), "latest_date": ...}

def list_symbols(self):
    symbols = db.list_symbols_from_index()
    if symbols:
        return symbols
    return sorted(f.stem for f in self.cache_dir.glob("*.pkl"))
```

Iska matlab app kaam karta hai even if index stale ya empty — bas slow ho jaata hai. Aur `rebuild_index()` index repopulate karta hai all `.pkl` files scan karke (first boot aur recovery pe use).

## Concept — Updating / Merging Data

Jab new bhavcopy data aata hai, poori file replace nahi karte — merge karte hain:

```python
def update(self, symbol, new_data, commit=True):
    self.update_with_data(symbol, new_data, commit=commit)

def update_with_data(self, symbol, new_data, existing=None, commit=True):
    if existing is None:
        existing = self.load(symbol)
    if existing is not None and not existing.empty:
        combined = pd.concat([existing, new_data])
        combined = combined[~combined.index.duplicated(keep="last")]   # dedup, keep newer
        combined = combined.sort_index()
    else:
        combined = new_data
    combined["last_updated"] = pd.Timestamp.now()
    self.save(symbol, combined, commit=commit)
```

`pd.concat` old + new rows stack karta hai. Dedup line (`~index.duplicated(keep="last")`) duplicate dates drop karta hai keeping newer value. `sort_index()` dates order mein rakhta hai. Phir `save()` merged DataFrame `.pkl` mein write aur index update.

## Concept — Invalidation (Kab Cache Throw Karna Hai)

Cache invalidation hard part hai. TradeStack ke strategies:

1. **Age-based** — `needs_update(symbol, max_age_days=3)`: agar last cached date 3 days se purana hai, re-fetch.
2. **Manual delete** — `fix-stock` endpoint `.pkl` file unlink karta hai aur Upstox se re-download.
3. **Gap detection** — `detect_gaps()` stocks find karta hai jinke cached series mein holes (missing trading days); `fix-gap-stocks` re-download karta hai.
4. **Full rebuild** — `rebuild_index()` all `.pkl` files rescan karta hai agar index empty/corrupt.
5. **`last_updated` column** — har merged row ko `last_updated` timestamp milta hai, taaki dekh sako kab data last touched hua.

No TTL ya auto-expiry. Invalidation explicit hai: age check, manual fix, ya gap scan. Deliberate hai — financial data silently disappear nahi hona chahiye; re-download kab ho raha hai pata hona chahiye.

## Concept — Reading from Cache (Helpers)

```python
def get_last_date(self, symbol):
    data = self.load(symbol)
    if data is None or data.empty: return None
    last_idx = data.index[-1]
    return last_idx.date() if hasattr(last_idx, "date") else last_idx

def get_last_close(self, symbol):
    data = self.load(symbol)
    if data is None or data.empty or "close" not in data.columns: return None
    val = data["close"].iloc[-1]
    if pd.isna(val): return None
    return float(val)

def get_date_range(self, symbol, start=None, end=None):
    data = self.load(symbol)
    if data is None or data.empty: return pd.DataFrame()
    if not isinstance(data.index, pd.DatetimeIndex):
        data.index = pd.to_datetime(data.index)
    if start: data = data[data.index >= pd.Timestamp(start)]
    if end:   data = data[data.index <= pd.Timestamp(end)]
    return data
```

`get_last_close` stock-list "resolved" endpoint use karta hai live cached closes dikhane ke liye. `get_date_range` charts power karta hai (last N days fetch).

## Concept — Phase 1 Se Compare

| Phase 1 (mini) | TradeStack (production) |
|---|---|
| No cache — DB/API se read har time | `.pkl` files on disk, SQLite se indexed |
| No serialization format | Pickle (DataFrame ↔ bytes) |
| No invalidation strategy | Age check, manual fix, gap detection, full rebuild |
| Ek store | Do stores: filesystem (data) + SQLite (metadata) |
| `load()` list return | `load()` DataFrame ya None return |

## What It Is NOT

- ❌ **Distributed cache nahi** — local files ek machine pe. No Redis, no Memcached.
- ❌ **Automatic expiry nahi** — kuch auto-delete nahi karta stale files. Invalidation explicit hai.
- ❌ **Database nahi** — `.pkl` files queryable nahi. Ya toh whole DataFrame load karo ya nothing.
- ❌ **Multi-process safe nahi** — pickle files without file locks read/write hote hain; ek writer at a time per symbol assumed.

## Nutshell

**cache_manager = pickle-based per-stock `.pkl` files in `data/cache/`, SQLite `cache_index` se indexed. save() file + index write. load() file read. update() new rows merge (dedup + sort). Invalidation: age check, manual delete, gap detection, full rebuild. Do stores (filesystem data + SQLite metadata) with fallbacks.**

## Common Mistakes

- ❌ **"pickle human-readable hai"** — no, binary hai. Text editor mein open karo garbage milega. `pickle.load` ya `pd.read_pickle` use karo.
- ❌ **"Index source of truth hai"** — no, `.pkl` files hain. Index derived cache hai; `rebuild_index()` se kisi bhi time rebuild.
- ❌ **"save() sirf file write karta hai"** — no, `cache_index` bhi upsert. Agar save() bypass karke file directly write karo, index stale ho jaata hai.
- ❌ **"update() data replace karta hai"** — no, merge karta hai (concat + dedup keep-last + sort). Replace karna history lose karega.
- ❌ **"Cache auto-expires"** — no. Kuch auto-delete nahi. `needs_update()` ya manual fix endpoints use karo.
