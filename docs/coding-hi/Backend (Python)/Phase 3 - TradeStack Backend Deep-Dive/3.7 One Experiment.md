# 3.7 One Experiment — System Samajhne Ke Liye Ek Isolated Change

## Soch (Sochne Wala Scene)

Recipe 10 baar padh sakte ho, par dish tab jaante ho jab ek baar cook karo aur taste karo. Goal feature add karna nahi — system ko poke karo aur dekho react kaise karta hai. Ek change, ek observation, ek lesson.

## Concept — Kyun Ek Small Experiment

Bade changes kuch nahi sikhate (too many variables). Zero changes kuch nahi sikhate (system move hi nahi dekha). Ek small, isolated, reversible change bahut sikhata hai:

- Kaunse files actually run hote hain (vs dead code).
- Data flow kaisa hai (request → route → db/cache → response).
- Logging kya print hota hai, kab.
- Error paths kya hote hain (break karo toh kya hota hai).

Goal **observation se understanding**, not shipping a feature.

## Concept — Experiment Pick Karo (Ek CHUNO)

Jo layer samajhni ho, usse touch karna smallest experiment choose karo. Suggestions, easiest first:

1. **Route mein log line add karo** (e.g., `/health` ya `/api/data/cache-info`). Request flow dekho.
2. **Ek tiny endpoint add karo** (e.g., `GET /api/debug/echo/{msg}`) jo msg + server time return kare. Route registration + path params dekho.
3. **Scanner param default modify karo** (e.g., `price_min` 100 se 500) aur scan run karo. Params flow settings → scanner → results dekho.
4. **Migration se table mein column add karo** aur read back. Migration pattern dekho.
5. **Cache invalidation threshold change karo** (`max_age_days=3` → `1`) aur re-fetches observe karo.
6. **Live trader mein state transition log add karo** (frontend) aur simulated tick watch karo.

Ek CHUNO. All six mat karo — kam seekhoge, zyada nahi.

## Concept — Experiment Loop (5 Steps)

Har experiment same loop follow karta hai:

```
1. Hypothesis  — "Agar main X add karoon, toh Y hona chahiye."
2. Change      — Ek file, ek spot, minimal diff.
3. Run         — server start / scan run / endpoint trigger.
4. Observe     — logs, response, DB state.
5. Revert or keep — git diff, phir revert (yeh learning hai, shipping nahi).
```

Hamesha `git diff` before aur after run karo taaki exactly pata ho kya change hua. Hamesha revert karo unless ship karna intent ho.

## Concept — Experiment 1: Log Line Add (Backend)

**Hypothesis:** `/health` mein log add karne se har health check pe print hoga, proving route har request pe run hota hai.

**Change** `backend/server.py` mein:

```python
@app.get("/health")
def health():
    logger.info("health check hit")
    return {"status": "healthy"}
```

**Run:**
```bash
cd TradeStack/backend
python server.py
# doosre terminal mein:
curl http://127.0.0.1:8001/health
curl http://127.0.0.1:8001/health
```

**Observe:** `data/logs/backend.log` (ya console) mein `health check hit` do baar. `X-Process-Time` header bhi present (middleware runs). Tumne dekha: route har request pe run, middleware wrap karta, logging works.

**Revert:** `git checkout backend/server.py` (ya edit undo).

## Concept — Experiment 2: Tiny Endpoint Add (Backend)

**Hypothesis:** Path param + query param wala new endpoint end-to-end kaam karega aur `/docs` mein dikhega.

**Change** `backend/server.py` mein (Health section ke paas add):

```python
@app.get("/api/debug/echo/{msg}")
def debug_echo(msg: str, times: int = 1):
    logger.info(f"echo msg={msg} times={times}")
    return {"echo": msg, "times": times, "server_time": datetime.now().isoformat()}
```

**Run:** server + `curl "http://127.0.0.1:8001/api/debug/echo/hello?times=3"`. Open `http://127.0.0.1:8001/docs` — endpoint listed aur testable (FastAPI auto-generates Swagger).

**Observe:** response mein echo, times, server_time. `/docs` page prove karta hai FastAPI ne function signature introspect kiya (path param `msg`, query param `times` with default).

**Revert.**

## Concept — Experiment 3: Scanner Param Change (Backend)

**Hypothesis:** `price_min` 100 se 10 karne se cheaper stocks include honge aur result count badhega.

**Change:** settings default edit karo (ya request body se pass):

```bash
# via curl with filters
curl -X POST http://127.0.0.1:8001/api/scanner/continuation \
  -H "Content-Type: application/json" \
  -d '{"filters": {"min_price": 10}}'
```

Phir poll:
```bash
curl http://127.0.0.1:8001/api/scanner/status/<operation_id>
```

**Observe:** `result.count` change; `logs` "Scanned 2000/2000 stocks, found N candidates". Tumne dekha params flow request → `ScanFilters` → `params` dict → `_run_chunk` → `_passes_filters`.

**Revert:** nahi chahiye (request body, not code).

## Concept — Experiment 4: Migration Add (Backend)

**Hypothesis:** `_run_migrations` pattern se column add idempotently kaam karega.

**Change** `backend/src/db.py` mein, `_run_migrations` ke andar:

```python
for col, dtype in [..., ("experiment_note", "TEXT")]:
    try:
        conn.execute(f"ALTER TABLE trade_log ADD COLUMN {col} {dtype}")
    except Exception:
        pass
```

**Run:** server restart (import triggers migration). Check:
```bash
cd TradeStack/backend
python -c "import src.db as d; c=d.get_connection(); print([r[1] for r in c.execute('PRAGMA table_info(trade_log)').fetchall()])"
```

**Observe:** `experiment_note` column list mein. Restart again — no error (idempotent, exception swallowed). Tumne dekha lazy migrations.

**Revert.**

## Concept — Experiment 5: Cache Invalidation (Backend)

**Hypothesis:** `needs_update(max_age_days=3)` ko `max_age_days=1` karne se zyada stocks "needs update" report karenge.

**Change** `TradeStack/backend/` mein quick script:

```python
# experiment.py
from src.cache_manager import cache_manager
symbols = cache_manager.list_symbols()[:20]
for s in symbols:
    print(s, cache_manager.needs_update(s, max_age_days=1), cache_manager.needs_update(s, max_age_days=3))
```

**Run:** `python experiment.py`. Counts compare. Tumne dekha age-based invalidation.

**Revert:** delete `experiment.py`.

## Concept — Experiment 6: State Transition Log (Frontend)

**Hypothesis:** `transitionTo` mein `console.log` add karne se live session ke dauraan har stock ka har state change dikhega.

**Change** `frontend/src/lib/live-trader/reversal/state-machine.ts` mein:

```typescript
transitionTo(newState, reason = ""): void {
    const old = this.state;
    this.state = newState;
    console.log(`[${this.symbol}] ${old} -> ${newState} (${reason})`);
    // existing log already there; add a timestamp:
    console.log(new Date().toISOString(), this.symbol, old, "->", newState);
}
```

**Run:** frontend dev server start, live trader open, browser console watch during market hours (ya recorded tick file replay).

**Observe:** har transition timestamp ke saath printed. Tumne dekha state machine action mein.

**Revert.**

## Concept — Kya Observe Karna Hai (Checklist)

Kisi bhi experiment ke liye capture karo:

- **Logs** — `data/logs/backend.log` ya console. Tumhara line print hua? Kab?
- **Response** — status code, body, `X-Process-Time` header.
- **DB state** — table query before/after.
- **File state** — `.pkl` create/modify hua? (`ls -la data/cache/`)
- **Errors** — agar break hua, traceback read. Error hi lesson hai.

## Concept — Safety Rules

- **Ek time pe ek change.** Do changes = do variables = no conclusion.
- **Kabhi production data edit mat karo.** DB experiments ke liye `TRADESTACK_DB_PATH` env var se scratch DB point karo.
- **Experiments kabhi commit mat karo.** Revert before commit. `git diff` se clean tree verify.
- **Market hours mein live trader real money ke saath mat chhedo.** Paper-trade only.
- **Destructive experiments se pehle backup** (`.pkl` files delete, tables drop).

## Concept — Payoff

Ek experiment ke baad tum 10 hours reading se zyada jaanoge:

- Kaunsa file actually execute hota hai given feature ke liye (vs dead code).
- Exact data flow aur kahan logging add karni hai.
- Errors kaise propagate hote hain (route → exception handler → JSON 500).
- Slow parts kahan hain (timing via `X-Process-Time`).

Yehi real skill: codebase memorize nahi, interrogate karna jaanna.

## What It Is NOT

- ❌ **Feature request nahi** — tum ship nahi kar rahe. Tum learn kar rahe ho.
- ❌ **Refactor nahi** — "while in there clean up" mat karo. Ek change, ek observation.
- ❌ **Test suite nahi** — experiments throwaway hain. Real tests separately (`tests/` dekho).
- ❌ **Reading skip karne ka permission nahi** — experiments work *because* tumne pehle padha. Yeh understanding confirm karte hain, replace nahi.

## Nutshell

**Ek experiment = hypothesis → ek minimal change → run → observe (logs/response/DB/files) → revert. List se ek CHUNO. Isolated, reversible, safe rakho (scratch DB, paper trading). Goal understanding hai, shipping nahi.**

## Common Mistakes

- ❌ **"Time save karne ke liye 5 cheezein ek saath change"** — kuch nahi seekhoge; result attribute nahi kar sakte.
- ❌ **"Revert bhool jaana"** — experiment half-baked feature ban jaata. `git diff` se clean tree verify.
- ❌ **"Hypothesis skip karna"** — prediction ke bina, koi bhi result learning lagta hai. Pehle likho.
- ❌ **"Prod DB edit karna"** — `TRADESTACK_DB_PATH` env var use karo scratch DBs ke liye.
- ❌ **"Live money ke saath market hours mein experiments"** — paper-trade only; observe, trade mat.
