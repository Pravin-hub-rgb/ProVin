2.2 me tumne ConnectionManager banaya tha jo ek flat dictionary me har connected WebSocket track karta hai aur sabko broadcast karta hai. Ek global chat ke liye kaam chal gaya. Par real chat app me **rooms** hote hain — #general, #trading, #random. #trading me bheja message #general me nahi jaana chahiye.

Ye file exactly wahi add karti hai: **rooms**. Har room apna connections group aur apna message history rakhta hai.

# 2.3 Chat Rooms — Multiple Rooms, Join/Leave, Message History

## Soch (Sochne Wala Scene)

Ek hotel socho. Lobby me front desk hai (server). Guests (clients) aate hain aur room maangte hain. Front desk unhe ek key (room_id) deta hai aur room ki taraf point karta hai. Room ke andar sirf us room ke guests ek doosre ko sunte hain. Koi leave kare to baaki notice karte hain. Aur agar koi late aaye, to front desk unhe **recent messages ka notebook** de sakta hai taaki wo catch up kar sake.

Ye hi chat room system hai: room management (kaun kis room me hai), join/leave announcements, message history (last N messages), aur sirf same room ke logon ko broadcast.

## Concept: Room Management

Core idea: ek flat `dict[connection_id -> WebSocket]` ke bajaye **two-level structure**:

```
rooms: dict[room_id -> list[WebSocket]]
history: dict[room_id -> deque of last N messages]
```

- `rooms` jawab deta hai "room X me kaun hai?"
- `history` jawab deta hai "room X me recently kya bola gaya?"

Jab client connect karta hai, wo URL path se room pick karta hai (`/ws/{room_id}`). Tum uska WebSocket us room ki list me add karte ho. Disconnect pe remove. Message aaye to sirf us room ki list ko broadcast.

## Code: RoomManager

```python
# room_manager.py
from fastapi import WebSocket
from collections import deque
from typing import Dict, List

class RoomManager:
    def __init__(self, history_size: int = 20):
        # room_id -> list of connected WebSockets
        self.rooms: Dict[str, List[WebSocket]] = {}
        # room_id -> last N messages (deque auto-drops oldest)
        self.history: Dict[str, deque] = {}
        self.history_size = history_size

    async def connect(self, websocket: WebSocket, room_id: str):
        # Handshake complete karo
        await websocket.accept()

        # Room nahi hai to banao
        if room_id not in self.rooms:
            self.rooms[room_id] = []
            self.history[room_id] = deque(maxlen=self.history_size)

        # Is connection ko room me add karo
        self.rooms[room_id].append(websocket)

        # Catch-up: naye arrival ko last N messages bhejo
        for old_msg in self.history[room_id]:
            await websocket.send_text(old_msg)

        # Room ke sabko join announce karo
        await self.broadcast(room_id, f"[system] a user joined {room_id}")

    def disconnect(self, websocket: WebSocket, room_id: str):
        # Room list se remove; room + history empty hone pe bhi rakho
        if room_id in self.rooms and websocket in self.rooms[room_id]:
            self.rooms[room_id].remove(websocket)

    async def broadcast(self, room_id: str, message: str):
        # Pehle history me store karo (late joiners dekh sake)
        if room_id in self.history:
            self.history[room_id].append(message)

        # Sirf IS room ke connections ko bhejo
        dead: List[WebSocket] = []
        for ws in list(self.rooms.get(room_id, [])):
            try:
                await ws.send_text(message)
            except Exception:
                dead.append(ws)

        # Dead connections clean karo
        for ws in dead:
            if ws in self.rooms.get(room_id, []):
                self.rooms[room_id].remove(ws)
```

Har part:
- `__init__` — do dictionaries: `rooms` (kaun connected hai) aur `history` (kya bola gaya). `deque(maxlen=N)` automatically oldest message drop kar deta hai jab N exceed ho.
- `connect()` — handshake accept, pehli baar room create, connection append, history replay, join announce.
- `disconnect()` — WebSocket ko room list se remove. Room aur uski history rakhte hain taaki future joiner past messages dekh sake.
- `broadcast()` — message history me store, phir sirf us room ke connections ko send. Dead connections collect karke remove (dropped clients handle).

## Concept: Join/Leave Messages

Chat tab "alive" lagta hai jab "X joined" aur "X left" dikhe. RoomManager `connect()` me joins announce karta hai. Leaves ke liye endpoint ka `except` block announce karta hai:

```python
# Endpoint me:
except WebSocketDisconnect:
    manager.disconnect(websocket, room_id)
    await manager.broadcast(room_id, f"[system] a user left {room_id}")
```

Ye system messages bhi history me jaate hain, to late joiner join/leave trail bhi dekhta hai. Agar system messages history me nahi chahiye to `history.append` sirf user messages ke liye move kar do — par simple chat ke liye sab store karna theek hai.

## Concept: Message History (Last N per Room)

History kyun? Do reasons:
1. Late joiner blank screen nahi dekhna chahiye — last few messages dikhne chahiye.
2. Reconnect (network blip) pe client rejoin karke history le sakta hai.

`collections.deque(maxlen=history_size)` use karte hain. Jab `maxlen` exceed hota hai, oldest item automatically remove. No manual slicing, no memory leak. Har room ka apna deque, to #general aur #trading ki history alag-alag.

`history_size` tuning: chat ke liye 20 fine hai. Trading feed ke liye zyada (ya DB persist). Notification bell ke liye 5-10 kaafi.

## Concept: Sirf Specific Room ko Broadcast

2.2 se key difference: `broadcast(room_id, message)` sirf `self.rooms[room_id]` iterate karta hai. #trading me bheja message #general ke connections ko touch nahi karta. Yahi rooms ko useful banata hai.

Agar accidentally `self.rooms` (poora dict) broadcast kar diya `self.rooms[room_id]` ke bajaye, to 2.2 ka global chat recreate ho gaya. Hamesha loop single room tak scope karo.

## FastAPI Endpoint

```python
# main.py
import json
from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from room_manager import RoomManager

app = FastAPI()
manager = RoomManager(history_size=20)

@app.websocket("/ws/{room_id}")
async def room_endpoint(websocket: WebSocket, room_id: str):
    # room_id URL path se aata hai: /ws/general, /ws/trading, etc.
    await manager.connect(websocket, room_id)
    try:
        while True:
            raw = await websocket.receive_text()

            # Plain text ya JSON {"user": "Vin", "text": "hi"} dono accept
            try:
                payload = json.loads(raw)
                user = payload.get("user", "anon")
                text = payload.get("text", raw)
            except json.JSONDecodeError:
                user = "anon"
                text = raw

            message = f"{user}: {text}"
            await manager.broadcast(room_id, message)
    except WebSocketDisconnect:
        manager.disconnect(websocket, room_id)
        await manager.broadcast(room_id, f"[system] a user left {room_id}")
```

Har line:
- `@app.websocket("/ws/{room_id}")` — `{room_id}` path param room ka naam ban jaata hai. `/ws/general` aur `/ws/trading` alag rooms.
- `manager.connect(...)` — handshake + join + history replay + join announce.
- `while True` — listening continue.
- `json.loads(raw)` — structured messages ke liye JSON try; plain text pe fall back.
- `manager.broadcast(room_id, message)` — sirf us room ko bhejo.
- `except WebSocketDisconnect` — client close; cleanup + leave announce.

      const div = document.createElement("div");
      div.textContent = e.data;
      document.getElementById("log").appendChild(div);
    };
    function send() {
      const u = document.getElementById("user").value || "anon";
      const t = document.getElementById("msg").value;

## What It Is NOT

- ❌ **Persistent nahi hai** — history memory (deque) me hai. Server restart = sab history gone. Real persistence ke liye messages SQLite/Postgres me write karo aur join pe load karo.
- ❌ **Authenticated nahi hai** — koi bhi URL se koi bhi room join kar sakta hai. No identity check, no permission. Real apps me auth (JWT query param ya first message) add karo.
- ❌ **Scaled nahi hai** — sab rooms ek process me. Multiple server instances ke liye Redis pub/sub chahiye cross-machine broadcast ke liye.
- ❌ **Reconnects across lost messages** — client reconnect kare to rejoin + history milta hai, par disconnected hone ke beech ke messages lost (unless persisted).

## Nutshell

**Chat rooms = do dicts: room_id -> list[WebSocket] (kaun andar hai) aur room_id -> deque (last N messages). connect() join + history replay + announce. broadcast(room_id) sirf us room ko bhejta hai. disconnect() cleanup.**

## Common Mistakes

- ❌ **"Broadcast to all rooms"** — `self.rooms` loop karne se har message sabko jaata hai. Loop single room tak scope karo.
- ❌ **"History stored globally"** — ek shared deque sab rooms ke liye messages mix kar dega. Har room ka apna deque.
- ❌ **"Forgetting to replay history on join"** — new joiner blank screen dekhega. `connect()` me `self.history[room_id]` replay karo.
- ❌ **"Not handling dead connections in broadcast"** — dropped client list me rehta hai aur har broadcast pe `send_text` throw karta hai. Dead sockets collect karke remove karo.
- ❌ **"Removing the room when empty"** — `del self.rooms[room_id]` se history bhi lost. Room (aur uska deque) empty hone pe bhi rakho, unless explicitly history reset chahiye.

## In Your Own Words

1. RoomManager 2.2 ke ConnectionManager se kaise alag hai?

<details>
<summary>Sample Answer</summary>

**Answer:** ConnectionManager me ek flat dict (connection_id -> WebSocket) tha aur broadcast sabko. RoomManager me room_id keyed do dicts hain: room_id -> list[WebSocket] (members) aur room_id -> deque (history). broadcast() ek room tak scoped hai, aur connect() us room ki history new joiner ko replay karta hai.

</details>

2. Message history ke liye plain list ke bajaye `deque(maxlen=N)` kyun?

<details>
<summary>Sample Answer</summary>

**Answer:** `deque(maxlen=N)` automatically oldest message drop kar deta hai jab N exceed ho, to memory bounded rehti hai bina manual slicing. Plain list forever grow karegi (memory leak) unless manually trim karo `del history[:len-N]`.

</details>

3. Ek user #trading me 5 minute late join karta hai. Wo pehle ke messages kaise dekhega?

<details>
<summary>Sample Answer</summary>

**Answer:** `connect()` me WebSocket ko room me add karne ke baad `self.history[room_id]` loop karke har stored message sirf us WebSocket ko `send_text` karte hain. Deque last N messages hold karta hai, to late joiner catch up kar leta hai.

</details>

4. Agar `self.rooms[room_id]` ke bajaye `self.rooms` broadcast kar do to kya hoga?

<details>
<summary>Sample Answer</summary>

**Answer:** Har message har room ke har connection ko jaayega — 2.2 ka global chat recreate ho gaya aur room isolation toot gaya. Hamesha send loop single target room tak scope karo.

</details>

5. Last user leave karne pe empty room (aur uski history) delete kyun nahi karte?

<details>
<summary>Sample Answer</summary>

**Answer:** Taaki future joiner room ki message history dekh sake. Room aur deque delete karne se history lost. Sirf tab delete karo jab fresh start chahiye (jaise daily reset). Otherwise rakho.

</details>
