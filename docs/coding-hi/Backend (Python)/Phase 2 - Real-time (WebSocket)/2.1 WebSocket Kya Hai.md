Phase 1 mein har interaction request-response tha: client puchta hai, server jawab deta hai, phir connection close ho jata hai. Client ko naya data ke liye phir se puchna padta hai. Page load karna ya form submit karna ke liye yeh theek hai. Lekin chat app ka kya? Har second page refresh nahi karna chahte new messages check karne ke liye.

Yahan **WebSockets** aate hain. WebSocket ek persistent connection hai — client aur server ek baar handshake karte hain, phir dono side bina permission liye kabhi bhi data bhej sakte hain.

# 2.1 WebSocket Kya Hai — Persistent Connection vs HTTP

## Think — Phone Call vs Letter

Socho tumhe friend se baat karni hai. Do options:

**Option 1: Letters (HTTP).** Letter likho, bhejo, reply ka wait karo. Har letter ek alag trip. Reply aane tak next letter nahi bhej sakte. Yeh request-response hai.

**Option 2: Phone call (WebSocket).** Ek baar dial karo, call connect ho, phir dono jab chahe bol sakte hain. Dobara dial karne ki zaroorat nahi. Koi bhi pehle bol sakta hai. Yeh persistent connection hai.

HTTP letters hai. WebSocket phone call hai.

## Concept — What Is a WebSocket

**WebSocket** ek communication protocol hai jo client aur server ke beech full-duplex (two-way), persistent connection provide karta hai single TCP connection pe.

HTTP se key differences:

| Thing | HTTP (request-response) | WebSocket (persistent) |
|-------|----------------------|----------------------|
| Connection | Har request pe open/close | Ek baar open, open rehta hai |
| Who speaks first | Client hamesha initiate karta hai | Dono side kabhi bhi bhej sakte hain |
| Overhead | Headers har request pe | Headers sirf handshake ke time |
| Use case | Pages load, form submit | Chat, live prices, notifications |

## The Handshake — How WebSocket Starts

WebSocket HTTP ko replace nahi karta. Yeh HTTP se **start** hota hai. Client ek HTTP request bhejta hai special header ke saath: `Upgrade: websocket`. Server respond karta hai `101 Switching Protocols`. Uske baad connection HTTP nahi raha — WebSocket hai.

```
Client: "Hey server, can we upgrade to WebSocket?"
Server: "Sure, switching now."
[Connection is now WebSocket — both sides can send freely]
```

Isliye WebSocket firewalls aur proxies ke through kaam karta hai — yeh regular HTTP se start hota hai.

## Code — First WebSocket in FastAPI

FastAPI mein built-in WebSocket support hai. Sabse simple example:

```python
from fastapi import FastAPI, WebSocket

app = FastAPI()

# WebSocket endpoint — note: no HTTP method, just @app.websocket
@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    # Accept the connection (completes the handshake)
    await websocket.accept()
    
    # Loop: receive and echo
    while True:
        # Wait for a message from the client
        data = await websocket.receive_text()
        # Send it back
        await websocket.send_text(f"Echo: {data}")
```

Har line:
- `@app.websocket("/ws")` — `/ws` pe WebSocket endpoint register karta hai (no GET/POST method)
- `await websocket.accept()` — handshake complete karta hai, connection ab open hai
- `await websocket.receive_text()` — client ka message wait karta hai (block hota hai jab tak receive nahi hota)
- `await websocket.send_text(...)` — client ko message bhejta hai
- `while True` — connection alive rakhta hai, messages listen karta hai

## What WebSocket Is NOT

- ❌ **Not HTTP** — handshake ke baad yeh alag protocol hai
- ❌ **Not for everything** — pages load ya simple CRUD ke liye WebSocket mat use karo. HTTP simpler hai aur better cache hota hai.
- ❌ **Not automatically scalable** — har connection server memory hold karta hai. 10,000 connections = 10,000 open sockets.

## Nutshell

**WebSocket = persistent two-way connection. Handshake HTTP se start hota hai, phir switch. Dono side kabhi bhi bhej sakte hain. Real-time ke liye use karo (chat, live prices, notifications).**

## Common Mistakes

- ❌ **"WebSocket replaces HTTP"** — nahi. WebSocket real-time ke liye. Baaki sab HTTP ke liye.
- ❌ **"You don't need accept()"** — zaroori hai `await websocket.accept()` call karna, warna connection kabhi open nahi hoga.
- ❌ **"receive_text() returns immediately"** — nahi, yeh block hota hai jab tak message nahi aata. Yahi point hai.
