Ab imagine karo tum chat app bana rahe ho. Koi message bhejta hai. Dusra person ko instantly kaise dikhega? Wo page refresh nahi kar sakta har second. Unhe **live connection** chahiye — server client ko push kare bina client ke puchhe.

# 2.0 Phase 2 — Real-time (WebSocket) — Kya Seekhenge

## Who Is This Phase For

Tumne request-response APIs banayi hain. HTTP, CRUD, SQLite sab aata hai. But real-time alag world hai — server pehle bolta hai, client nahi. Yeh phase us gap se start hota hai aur working chat app tak build hota hai.

## What You'll Build

A **Chat Room App** — WhatsApp jaisa, but simple. Multiple browser tabs ek room se connect hote hain. Koi message bhejta hai, us room ke sab log instantly dekhte hain. No refresh needed.

Yahi concept hai TradeStack's live trader (Upstox live prices) — server price updates push karta hai client ko real-time.

## What This Phase Is NOT

- ❌ **Production chat app** — no auth, no persistence, no scaling
- ❌ **WebSocket deep dive** — just the basics needed for real-time
- ❌ **TradeStack code changes** — we only read and understand, don't modify production code

## Prerequisites

- Phase 1 complete (1.0 → 1.5.5)
- FastAPI basics understood (routes, Pydantic, SQLite)
- Python basics (variables, functions, loops, dicts)

## What Happened So Far

Phase 1 mein tumne request-response API banaya. Har interaction tha: client asks → server answers. Client always initiates.

Phase 2 mein server bhi initiates. Client ek baar connection open karta hai, aur server push karta hai data jab chahe. Yahi foundation hai har real-time feature ka — chat, live prices, notifications, collaborative editing.
