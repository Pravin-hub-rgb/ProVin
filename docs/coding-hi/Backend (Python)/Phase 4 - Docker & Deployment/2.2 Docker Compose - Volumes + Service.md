Dockerfile se image ban gaya. Ab usse **docker-compose.yml** se run karna easy ho jaye ga — ek command mein up, ek command mein down. Aur **volume mount** se SQLite data container ke bahar bhi persist hoga.

---

## Step 1: `docker-compose.yml` likho

Project folder root me `docker-compose.yml` create karo:

```yaml
version: "3.8"

services:
  backend:
    build: .
    container_name: trading-backend-basic
    ports:
      - "8000:8000"
    volumes:
      - ./data:/app/data
    environment:
      - PYTHONUNBUFFERED=1
    restart: unless-stopped
```

---

## Har line samjho

```yaml
version: "3.8"
```
- Compose file ka version. `3.8` = Docker ka stable version hai. Most setup pe kaam karta.

```yaml
services:
  backend:
```
- Ek hi service: `backend`. TradeStack mein toh 2 services honge (backend + frontend), lekin yahan sirf backend.

```yaml
    build: .
```
- `.` = current folder ka `Dockerfile` use karo build ke liye.
- Alternativ `build: { context: ., dockerfile: Dockerfile }` bhi likh sakta hai, lekin `.` shortcut kaam karta.

```yaml
    container_name: trading-backend-basic
```
- Container ka naam fix karo. Agar na de to Docker random naam deg a ("focused_hodgkin" wagah ka). Debugging easy hota naam se.

```yaml
    ports:
      - "8000:8000"
```
- **Port mapping**: `host:container`.
  - Host (tumhara laptop) = `8000`
  - Container (image ke andar) = `8000`
  - Matlab: browser `http://localhost:8000` → container tak pahunch jayega.

```yaml
    volumes:
      - ./data:/app/data
```
- **Volume mount**: `./data` (host) → `/app/data` (container).
  - Jo bhi host ke `./data` folder me hoga, container ke `/app/data` me dikhega.
  - SQLite DB — agar tumhara code DB ko `./data/settings.db` me likhega (Phase 1 me dekha tha), to woh container ke andar bhi `/app/data/settings.db` me jayega.
  - Container delete ho jaye, DB host pe bacha rahega.

```yaml
    environment:
      - PYTHONUNBUFFERED=1
```
- Log immediately dikhaye (buffering kam karo). Debugging me madad karta.
- `PYTHONUNBUFFERED=1` Python ke stdout/stderr ko turant flush karta hai.

```yaml
    restart: unless-stopped
```
- Container crash hone pe automatically restart hoga. `docker stop` ya system shutdown to rukega.

DB_PATH = os.path.join(os.path.dirname(__file__), "..", "data", "settings.db")

## Step 3: Run karke test karo

### Start:
```bash
docker compose up --build
```
- `--build` = pehle image rebuild karo (Dockerfile change hone pe).
- Pehle baar toh build hoga, dusri baar se cache use hoga.

### Test endpoints:
```bash
# Health check
curl http://localhost:8000/health

# API docs (Swagger)
open http://localhost:8000/docs

# Scan endpoint
curl "http://localhost:8000/api/scan?min_rsi=0&max_rsi=30"
```

### Verify data persistence:
```bash
# Seed some data through API
curl -X POST http://localhost:8000/api/stocks -H "Content-Type: application/json" -d '{"symbol":"TEST","name":"Test Stock","sector":"IT"}'

# Check host machine: data/ folder me DB ban gaya hoga kya?
ls -la data/

# Container stop karo
docker compose down

# Phir se up karo — data kahan gaya?
docker compose up

# DB wapas mil jayega kyunki volume mount
curl http://localhost:8000/api/stocks
```

Expected: `TEST` stock dikh raha hai even after `docker compose down`.

## Common Mistakes

1. **Volume mount path galat** — `./data:/app/data` mein `./data` host path, `/app/data` container path. Phase 1 project structure se match hona chahiye.
2. **`build: .` instead of `build:`** — ye dono kaam karta. Compose auto-detect karta `Dockerfile` ko.
3. **Port conflict** — agar host pe 8000 koi aur process use kar raha hai to error aayega. `8001:8000` likh sakta hai.
4. **DB file permissions** — Linux pe Docker user kahin alag ho sakta hai. Permission denied aaye to `chmod -R 777 data/` karo.
5. **`restart: always` vs `unless-stopped`** — `always` = system reboot pe bhi start hota. `unless-stopped` = manually stop hone tak rehta.
6. **Environment var missing** — agar app `DATABASE_URL` env var chahiye (Phase 1 mein nahi chahiye), to add karo.

## Multi-service extension (preview — TradeStack)

TradeStack ke saath compose aisa lagta:

```yaml
services:
  backend:
    build: ./backend
    ports:
      - "5000:8000"
    volumes:
      - ./backend/data:/app/data
    depends_on:
      - redis

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
```

- `depends_on` = order specify karta. Redis pehle start, phir backend.
- TradeStack ke `docker-compose.yml` aise hi laga (minus frontend for now).

---

## What It Is NOT

- ❌ **Production deployment config** — no nginx, no SSL, no healthcheck
- ❌ **Secrets management** — `.env` files ke through hi manage karo
- ❌ **Database as separate service** — SQLite = file-based. Postgres/MySQL toh alag service banegai

---

## Nutshell

- `docker-compose.yml` = ek hi file mein build config, ports, volumes, env.
- `./data:/app/data` volume mount = SQLite data persists across container restart.
- `docker compose up --build` → `curl localhost:8000/health` verify → seed → `docker compose down` → `up` again → data persists.
- TradeStack bridge = same YAML, just `./backend` context, `depends_on`, and different port.
