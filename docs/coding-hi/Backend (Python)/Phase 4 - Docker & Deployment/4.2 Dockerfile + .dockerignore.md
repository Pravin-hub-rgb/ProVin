# 4.2 Dockerfile + .dockerignore â€” Apna FastAPI App Package Karo

## Soch â€” Recipe Card

Socho tum ek recipe card likh rahe ho "kaise ye app kisi bhi machine pe run kare." Recipe me likhna padega: Python 3.12 se start karo, folder banao, packages install karo, mera code copy karo, port 8000 expose karo, aur uvicorn start karo. Ye recipe card hi `Dockerfile` hai. Docker ise top-to-bottom padhta hai aur har line execute karta hai, har step pe ek naya **layer** create karta hai. Final stack of layers = tumhara image.

## Step 1 â€” `.dockerignore` Likhna

Project root me `.dockerignore` create karo. Ye `.gitignore` ki tarah kaam karta hai â€” Docker matching files ko image me copy karne se skip karta hai.

```text
# Python bytecode

*$py.class
*.so

# Virtual environment
venv/

# Git

# IDE / editor

```

Har group kyu important hai:
- **`venv/`** â€” iske bina tumhara 500MB virtual environment copy hota. Image huge aur slow ho jaati.
- **`__pycache__/`** â€” tumhare machine ka bytecode; useless (aur possibly wrong version) container ke andar.
- **`.env`** â€” secrets kabhi image me bake nahi hone chahiye. Runtime pe pass karo.
- **`data/`** â€” SQLite DB runtime pe create hota hai aur volume mount se persist (4.3). Stale DB image me bake mat karo.
- **`*.md`** â€” docs ship karne ki zarurat nahi. `!README.md` README ko exception rakhta hai.

## Step 2 â€” `Dockerfile` Likhna

Project root me `Dockerfile` (no extension) create karo:

```dockerfile
# Base image: Python 3.12 slim (small, security-patched Debian)
FROM python:3.12-slim

# Image ke andar working directory set karo
WORKDIR /app

# Pehle requirements.txt copy karo (cache optimization â€” niche dekho)
COPY requirements.txt .

# Dependencies install karo
RUN pip install --no-cache-dir -r requirements.txt

# Ab baaki app copy karo
COPY . .

# Environment variables
ENV PYTHONUNBUFFERED=1
ENV PYTHONDONTWRITEBYTECODE=1

# Port document karo jo app listen karega
EXPOSE 8000

# Container start hone pe run hone wala command
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## Step 3 â€” Har Line Samjho

### `FROM python:3.12-slim`

- **Base image** pick karta hai â€” starting layer. `python:3.12-slim` Python 3.12 on minimal Debian. ~150 MB instead of ~900 MB full image.
- **Version match matters:** Phase 1 code Python 3.12 ke liye likha tha. Same use karo ya dependency surprises milenge.
- `slim` docs, tests, optional packages drop karta hai. Chhoti image = faster pulls, smaller attack surface.

### `WORKDIR /app`

- Image ke andar `/app` create karta hai aur subsequent instructions ke liye working directory set karta hai.
- Bina iske, `COPY` `/` (root) me land karta aur paths messy ho jaate.
- `CMD` aur `RUN` is directory ke relative execute hote hain.

### `COPY requirements.txt .`

- Sirf `requirements.txt` copy karta hai `/app` me.
- Ye single line **cache-optimization trick** hai (layer caching niche). Dot `.` means "current WORKDIR" = `/app`.

### `RUN pip install --no-cache-dir -r requirements.txt`

- `RUN` **build time** pe command execute karta hai (runtime nahi). Yahan FastAPI, uvicorn, pandas install hote hain.
- `--no-cache-dir` pip ko downloaded wheels image me save karne se rokta hai. ~100MB+ save.
- Ye layer cached rehti jab tak `requirements.txt` nahi change hota.

### `COPY . .`

- Baaki sab (app/, README, etc.) `/app` me copy karta hai. `.dockerignore` filter karta hai `venv/`, `__pycache__/`, `data/`, etc.
- `pip install` ke **baad** aata hai taaki code changes reinstall trigger na karein.

### `ENV PYTHONUNBUFFERED=1`

- Python ko stdout/stderr immediately flush karne pe majboor karta hai. Bina iske, `print()` aur logs `docker logs` me late ya kabhi nahi dikhte.
- `PYTHONDONTWRITEBYTECODE=1` Python ko `.pyc` files write karne se rokta hai (already ignored, but belt-and-braces).

### `EXPOSE 8000`

- **Sirf documentation.** Readers (aur tooling) ko batata hai ye app port 8000 pe listen karta hai.
- Ye port **publish nahi** karta. Actual publishing `-p` flag ya compose me `ports:` se hota hai (4.3).

### `CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]`

- Command jo container **start** hone pe run hota hai. JSON array form (exec form) â€” shell ke bina directly run hota hai.
- `app.main:app` = `app/main.py` ka `app` object (tumhara FastAPI instance).
- `--host 0.0.0.0` = **all interfaces** pe listen. Critical: `127.0.0.1` container-local only bind karta aur bahar se unreachable.
- `--port 8000` = container ke andar ka port.

## Layer Caching â€” Order Kyu Matter Karta Hai

Docker har instruction ka result **layer** ke as cache karta hai. Rebuild pe, agar instruction aur inputs unchanged hain, Docker cached layer reuse karta hai instead of re-run.

```
Layer 1: FROM python:3.12-slim      (cached forever unless base changes)
Layer 2: WORKDIR /app               (cached)
Layer 3: COPY requirements.txt .    (cached IF requirements.txt unchanged)
Layer 4: RUN pip install ...        (cached IF layer 3 cached)
Layer 5: COPY . .                   (re-runs if ANY file changed)
Layer 6: ENV ...                    (cached)
Layer 7: EXPOSE 8000                (cached)
Layer 8: CMD ...                    (cached)
```

**Bad order** (pehle sab copy):

```dockerfile
COPY . .                  # any code change invalidates this layer
RUN pip install -r requirements.txt   # har code change pe re-run â€” slow!
```

**Good order** (humara): pehle requirements copy, install, phir code. Ab `scanner.py` edit karne pe sirf `COPY . .` re-run (fast) â€” pip install cached rehta. Code change rebuild seconds me, minutes nahi.

Cache invalidation **cascading** hai: agar layer N change hua, layers N+1, N+2... sab rebuild. Isliye slow, stable steps (pip install) early rakho aur fast, volatile steps (code copy) late.

## Step 4 â€” Image Build Karo

Project root se (jahan `Dockerfile` hai):

```bash
docker build -t trading-backend-basic .
```

- `build` = Dockerfile se image build karo.
- `-t trading-backend-basic` = image ko tag (name) do. Run karne ke liye ye naam use hoga.
- `.` = build context (current directory). Docker is folder ke files (respecting `.dockerignore`) daemon ko bhejta hai.

Output (abbreviated):

## Step 5 â€” Container Run Karo

```bash
docker run -p 8000:8000 trading-backend-basic
```

- `run` = image se container create + start.
- `-p 8000:8000` = port publish: host 8000 â†’ container 8000 (host:container).
- `trading-backend-basic` = image name.

Ab test karo:

```bash
curl http://localhost:8000/health
# {"status": "ok", "db": "connected"}

# Swagger UI browser me
# http://localhost:8000/docs
```

Stop karo `Ctrl+C` se. Container stop hota hai; image rehti hai. Same command se phir se run karo kabhi bhi.

Background (detached) me run:

```bash
docker run -d -p 8000:8000 --name trading-backend trading-backend-basic
docker logs trading-backend        # logs dekho
docker stop trading-backend        # stop
docker rm trading-backend          # container remove (image rehti)
```

## Common Mistakes

1. **`CMD` string instead of JSON array** â€” `CMD uvicorn app.main:app ...` shell se run hota hai aur signal handling / graceful shutdown break. `CMD ["uvicorn", ...]` use karo.
2. **`--host 127.0.0.1`** â€” container-local only bind; external requests fail. `0.0.0.0` hona chahiye.
3. **`venv/` copy karna** â€” `.dockerignore` bhool gaye; image GBs me bloat. Always ignore `venv/`.
4. **`data/` bake karna image me** â€” stale DB image ke saath ship; volume mount shadow hota. Ignore `data/`.
5. **CMD me wrong app path** â€” `app.main:app` assume karta hai `app/main.py` with `app = FastAPI()`. Module alag ho to path fix karo.
6. **No `--no-cache-dir`** â€” pip cache ~100MB dead weight add karta.
7. **Dockerfile edit kiya par rebuild nahi** â€” `docker run` purani image use karta. `docker build` ya `docker compose up --build` se rebuild.

## What It Is NOT

- âŒ **Multi-stage build** â€” single `FROM`. Production images build stage + slim runtime stage use karte hain tiny images ke liye.
- âŒ **Non-root user** â€” container root ke as run hota hai. Production `USER appuser` add karta.
- âŒ **Healthcheck** â€” no `HEALTHCHECK` instruction; orchestrators unhealthy containers auto-detect nahi kar sakte.
- âŒ **Secrets in image** â€” real values ke saath `ENV API_KEY=...` kabhi nahi.

## Nutshell

- `.dockerignore` skips `venv/`, `data/`, `__pycache__/`, docs, secrets.
- `Dockerfile`: `FROM python:3.12-slim` â†’ `WORKDIR /app` â†’ copy requirements â†’ `RUN pip install` â†’ copy code â†’ `ENV` â†’ `EXPOSE` â†’ `CMD uvicorn ... 0.0.0.0:8000`.
- **Requirements pehle code se copy karo** cache speed ke liye.
- Build: `docker build -t name .` ; Run: `docker run -p 8000:8000 name`.

## In Your Own Words

1. Kyu `requirements.txt` pehle copy karte hain, baaki code se pehle?

<details>
<summary>Sample Answer</summary>

**Answer:** Layer caching ke liye. Docker har instruction ka result cache karta hai. Agar `requirements.txt` nahi change hua, pip install layer reuse hota hai aur code changes reinstall trigger nahi karte. Code pehle copy karna cache invalidate karta aur har edit pe pip install force karta, builds slow.

</details>

2. `RUN` aur `CMD` me kya fark hai?

<details>
<summary>Sample Answer</summary>

**Answer:** `RUN` build time pe execute hota hai (image me layer create karta, e.g., packages install). `CMD` container start hone pe run hone wala command specify karta hai. RUN = build-time; CMD = runtime.

</details>

3. `--host` `0.0.0.0` kyu hona chahiye, `127.0.0.1` nahi?

<details>
<summary>Sample Answer</summary>

**Answer:** `127.0.0.1` sirf container ke own loopback pe bind karta, to container ke bahar se (browser, host machine) requests nahi pahunch sakti. `0.0.0.0` all interfaces pe bind karta, published port ke through app reachable.

</details>

4. `.dockerignore` kya karta hai aur kyu important hai?

<details>
<summary>Sample Answer</summary>

**Answer:** Ye Docker ko batata hai build context bhejte time kaunse files skip karne hain. Bina iske, `venv/` (500MB+), `__pycache__/`, `.env` me secrets, aur stale DB files image me copy hote hain, image bloat aur secrets leak. Ye `.gitignore` ki tarah kaam karta hai.

</details>

5. Agar `scanner.py` me ek line change karke rebuild karo, to kya hota hai?

<details>
<summary>Sample Answer</summary>

**Answer:** Docker cached layers reuse karta hai up to `COPY requirements.txt .` aur `RUN pip install` (kyunki requirements.txt unchanged), phir `COPY . .` aur baad ke sab re-run. Build fast hota hai kyunki pip install skip. Sirf final layers rebuild.

</details>
