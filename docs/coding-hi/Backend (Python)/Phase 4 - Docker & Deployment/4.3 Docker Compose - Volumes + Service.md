4.2 me tumne `Dockerfile` se image build kiya aur `docker run -p 8000:8000` se run kiya. Kaam karta hai, par har baar ye type karna annoying hai, aur worse â€” container remove hone pe uske andar likha data (tumhara SQLite DB) **hamesha ke liye gayab** ho jaata hai. Docker Compose dono fix karta hai: ek YAML file declare karti hai service kaise run kare, aur **volume mounts** SQLite data ko tumhare host machine pe rakhte hain taaki container restarts ke across survive kare.

# 4.3 Docker Compose â€” Volumes + Service

## Soch â€” Launch Button

Socho tumhare app ko start karne ke liye teen cheezein chahiye: image build karo, ports map karo, data folder mount karo. Inhe manually (`docker build`, `docker run -p ... -v ...`) karna har subah car ko hot-wire karke start karne jaisa hai. Docker Compose **ignition key** hai â€” ek turn (`docker compose up`) sab kuch karta hai, har baar, identically. `docker-compose.yml` file key ka blueprint hai.

## Step 1 â€” `docker-compose.yml` Likho

Project root me (Dockerfile ke next to) `docker-compose.yml` create karo:

```yaml
version: "3.8"

services:
  backend:
    build: .
    container_name: trading-backend-basic
    ports:
      - "8000:8000"
    volumes:
      - ./data:/app/data
    environment:
      - PYTHONUNBUFFERED=1
    restart: unless-stopped
```

## Step 2 â€” Har Line Samjho

### `version: "3.8"`

- Compose file format version declare karta hai. `3.8` stable hai aur modern Docker support karta hai. Naya Compose (v2) ise ignore bhi kar deta hai, par rakhna harmless hai aur intent document karta hai.

### `services:`

- Top-level key jo run hone wale containers (services) list karti hai. Humare paas ek hai: `backend`.
- TradeStack me do honge: `backend` + `redis` (preview niche).

### `backend:`

- Service name. Services jab ek doosre se baat karte hain to DNS hostname ke as use hota hai (e.g., backend `redis` ko name se reach kar sakta hai).

### `build: .`

- Compose ko batata hai current directory (`.`) ka `Dockerfile` use karke image build karo.
- `docker build -t ... .` ke equivalent. Compose automatically tag karta hai.
- Alternative: `build: { context: ., dockerfile: Dockerfile }` â€” same, zyada verbose.

### `container_name: trading-backend-basic`

- Container ka naam fix karta hai. Bina iske Docker random name generate karta hai like `trading-backend-basic-backend-1` ya `focused_hodgkin`.
- Fixed naam `docker logs trading-backend-basic` aur `docker stop trading-backend-basic` predictable banata hai.

### `ports:` / `- "8000:8000"`

- **Port mapping**: `"HOST:CONTAINER"`.
- Host (tumhara laptop) port `8000` â†’ container port `8000`.
- To `http://localhost:8000` tumhare laptop pe container ke andar ka app reach karta hai.
- Agar host 8000 busy hai, `"8001:8000"` use karo (host 8001 â†’ container 8000). App andar still 8000 pe sochta hai.

### `volumes:` / `- ./data:/app/data`

- **Persistence line.** Host folder `./data` ko container folder `/app/data` pe mount karta hai.
- Bidirectional: container ke `/app/data` me likhi files host ke `./data` me dikhti hain, aur vice versa.
- Tumhara Phase 1 code SQLite `./data/settings.db` pe write karta hai. Container ke andar ye path `/app/data/settings.db` ban jaata hai â€” jo mounted folder hai. To DB actually tumhare **host disk** pe write hota hai.
- Container delete karo, DB survive karta hai. Bas yahi point hai.

### `environment:` / `- PYTHONUNBUFFERED=1`

- Container ke andar environment variables set karta hai. Yahan unbuffered Python output taaki logs immediately dikhein.
- Secrets ke liye `.env` file use karo: `env_file: .env` (kabhi `.env` commit mat karo).

### `restart: unless-stopped`

- Restart policy: container crash ho (ya Docker daemon restart ho) to Compose usse wapas up karta hai.
- `unless-stopped` = crash pe restart, par explicit `docker compose stop`/`down` pe down rehta.
- Alternative `always` = manual stop ke baad bhi restart (daemons ke liye). `no` = kabhi restart nahi (default).

## Step 3 â€” DB Path Connection Check Karo

Phase 1 project me (1.5.2 se 1.5.5) DB path kya hai? Check karo:

```python
# Phase 1 ke app/db.py ya app/models.py me dekho
DB_PATH = os.path.join(os.path.dirname(__file__), "..", "data", "settings.db")
```

Agar DB path `./data/settings.db` hai, to volume mount `./data:/app/data` kaam karega. DB host ke `./data/` folder pe bhi write hota hai.

# Expected: settings.db

## Step 5 â€” Multi-service Extension (TradeStack Preview)

TradeStack ka compose aisa dikhega:

```yaml
services:
  backend:
    build: ./backend
    ports:
      - "5000:8000"
    volumes:
      - ./backend/data:/app/data
    depends_on:
      - redis

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
```

- `depends_on` = order specify karta hai. Redis pehle start, phir backend.
- TradeStack ka `docker-compose.yml` aisa dikhega (frontend abhi nahi).

## Common Mistakes

1. **Wrong volume mount path** â€” `./data:/app/data` means `./data` host path, `/app/data` container path. Match karna padta hai tumhare Phase 1 structure se.
2. **`build: .` vs `build:`** â€” dono kaam karte. Compose Dockerfile auto-detect karta hai.
3. **Port conflict** â€” host port 8000 kisi aur process ne use kiya to error. `8001:8000` use kar sakte ho.
4. **DB file permissions** â€” Linux pe Docker user different ho sakta hai. Permission denied to `chmod -R 777 data/`.
5. **`restart: always` vs `unless-stopped`** â€” `always` = system reboot pe bhi start. `unless-stopped` = manually stop tak chalta.
6. **Missing environment variable** â€” agar app ko `DATABASE_URL` env var chahiye (Phase 1 me nahi), add karo.
7. **`depends_on` ko "ready" samajhna** â€” ye sirf start order control karta hai, readiness nahi. Real readiness ke liye healthchecks add karo.

## What It Is NOT

- âŒ **Production deployment config** â€” no nginx, no SSL, no healthcheck
- âŒ **Secrets management** â€” `.env` files only
- âŒ **Database as separate service** â€” SQLite = file-based. Postgres/MySQL separate services honge

## Nutshell

- `docker-compose.yml` = build config, ports, volumes, env sab ek file me.
- `./data:/app/data` volume mount = SQLite data container restarts ke across persist.
- `docker compose up --build` â†’ `curl localhost:8000/health` verify â†’ seed â†’ `docker compose down` â†’ up again â†’ data persist.
- TradeStack bridge = same YAML, bas `./backend` context, `depends_on`, aur different port.

## In Your Own Words

1. Volume mount kya karta hai, aur SQLite ke liye kyu chahiye?

<details>
<summary>Sample Answer</summary>

**Answer:** Volume mount host folder ko container me map karta hai (`./data:/app/data`). App DB us folder me write karta hai, par file actually host pe hoti hai. Container delete hone pe bhi DB survive karta hai aur next run pe wapas aata hai. Bina iske DB container ke writable layer me hota aur `docker compose down` pe lost.

</details>

2. `docker compose up` aur `docker compose up --build` me kya fark hai?

<details>
<summary>Sample Answer</summary>

**Answer:** `up` existing (cached) image se containers start karta hai. `up --build` pehle Dockerfile se image rebuild karta, phir start. `--build` use karo jab Dockerfile ya dependencies change ho; plain `up` code-only changes ke liye kaafi hai (agar source volume-mounted ho, jo yahan nahi hai kyunki hum COPY karte hain image me).

</details>

3. `restart: unless-stopped` ka kya matlab hai?

<details>
<summary>Sample Answer</summary>

**Answer:** Container crash ho ya Docker restart ho to automatically restart hota hai, par explicit `docker compose stop`/`down` karne pe stopped rehta. Daemons ke liye `always` (manual stop ke baad bhi restart); dev ke liye `no` (default) jahan auto-restart nahi chahiye.

</details>

4. `depends_on` alone service readiness ke liye kyu nahi kaafi?

<details>
<summary>Sample Answer</summary>

**Answer:** `depends_on` sirf start order control karta hai â€” Redis backend se pehle start hota hai. Ye wait nahi karta Redis connections accept karne ke liye ready ho. Backend start hoke connect fail kar sakta hai. Real readiness ke liye Redis pe `healthcheck` add karo aur depends_on me `condition: service_healthy`.

</details>

5. Agar host pe 8000 already use me ho to port kaise change karein?

<details>
<summary>Sample Answer</summary>

**Answer:** Mapping ka left side change karo: `"8001:8000"`. Host (tumhara browser) 8001 use karega; container (app) still 8000 pe. App ko change ka pata nahi. Access `http://localhost:8001` se.

</details>
