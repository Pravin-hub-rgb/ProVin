## Part 3 â€” Container Ke Andar Kya Break Hota Hai?

Common failures aur fixes, real containerization mistakes se:

| Symptom | Likely Cause | Fix |
|---------|-------------|-----|
| POST pe `500 Internal Server Error` | DB path relative issue / folder missing | Verify `DB_PATH` `/app/data` me land karta hai; `os.makedirs(DATA_DIR, exist_ok=True)` |
| `localhost:8000` pe Connection refused | Port publish nahi hua | Check `ports: "8000:8000"` aur container running hai (`docker compose ps`) |
| Port 8000 already in use | Host conflict | Pehle `docker compose down`, ya `"8001:8000"` use karo |
| `data/` pe Permission denied | Linux file ownership mismatch | Host pe `chmod -R 777 data/`, ya matching user se container run karo |
| `/health` works but `/api/scan` fails | Container me package missing | `requirements.txt` me add karo, `--build` se rebuild |
| DB file container ke andar nahi dikhta | Volume mount path wrong | Double-check `./data:/app/data` app ke write path se match |
| Image huge (500MB+) | `venv/` ya `__pycache__/` copy hua | `.dockerignore` me add karo, rebuild |
| Code changes reflect nahi hote | `--build` bhool gaye | `docker compose up --build` |
| Container immediately exit | CMD error / import error | `docker compose logs backend` traceback dekho |

Debugging toolkit:

```bash
docker compose logs backend          # app ka stdout/stderr
docker compose exec backend bash     # running container me shell
docker compose exec backend python -c "import app.main; print('import ok')"
docker inspect trading-backend-basic # full container config
```

### TradeStack `docker-compose.yml` (root level)

```yaml
version: "3.8"

services:
  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    container_name: tradestack-backend
    ports:
      - "5000:8000"            # TradeStack convention: host 5000
    volumes:
      - ./data:/app/data        # TradeStack ka data/ folder
    environment:
      - PYTHONUNBUFFERED=1
    restart: unless-stopped
```

### TradeStack-specific notes

- **WAL mode SQLite** (`trades.db`): WAL SQLite same directory me `trades.db-wal` aur `trades.db-shm` sidecar files create karta hai. Kyunki poora `data/` folder mounted hai, sab sidecar files capture hote hain, persistence kaam karta hai. Individual sidecar files delete mat karo.
- **Larger dependency set**: TradeStack ka `requirements.txt` zyada include karta hai (pandas, numpy, possibly TA-lib). Build slower hoga; layer caching (4.2) rebuilds fast rakhta hai.
- **Port 5000 vs 8000**: TradeStack convention 5000 hai. Host 5000 â†’ container 8000 map karo (app andar still 8000 pe listen karta hai).
- **Frontend not included**: Ye phase sirf backend containerize karta hai. Frontend (Next.js) ka apna Dockerfile later â€” scope se bahar yahan.

## In Your Own Words

1. Data persistence actually kaam karta hai kaise verify karoge?

<details>
<summary>Sample Answer</summary>

**Answer:** API se data seed karo, `docker compose down` run karo, host pe `./data/` me DB file still present confirm karo, `docker compose up -d` run karo, phir API query karo. Agar seeded data return ho, volume mount kaam kar raha hai. Extra proof: container entirely `docker rm` se delete karo aur restart â€” data still survive hona chahiye.

</details>

2. Kyu ek endpoint host pe kaam karta hai par container ke andar fail hota hai?

<details>
<summary>Sample Answer</summary>

**Answer:** Usually: `requirements.txt` me package missing (host pe globally installed hai), wrong DB path jo volume mount ke bahar land karta hai, port `127.0.0.1` pe bind instead of `0.0.0.0`, ya Linux pe file-permission issues. `docker compose logs` me traceback check karo.

</details>

3. Dockerfile ko Phase 1 project se TradeStack me move karte time kya change hota hai?

<details>
<summary>Sample Answer</summary>

**Answer:** Teen cheezein: CMD entry point `app.main:app` se `server:app` change hota hai; build context `.` se `./backend` change (kyunki Dockerfile `backend/` me hai); host port 8000 se 5000 change. Dockerfile instructions same rehte hain.

</details>

4. SQLite WAL mode volume mount ko kyu nahi todta?

<details>
<summary>Sample Answer</summary>

**Answer:** WAL mode main DB ke same directory me sidecar files (`trades.db-wal`, `trades.db-shm`) create karta hai. Kyunki poora `data/` folder mounted hai, sab sidecar files together capture hote hain. Jab tak folder mount karo (single file nahi), persistence kaam karta hai.

</details>

5. `docker compose down` aur `docker compose down -v` me kya fark hai?

<details>
<summary>Sample Answer</summary>

**Answer:** `down` containers stop aur remove karta hai par bind-mounted host folders (`./data`) aur named volumes rehte hain. `down -v` named volumes bhi remove karta hai. Bind mounts (humara `./data:/app/data`) kabhi remove nahi hote â€” host pe rehte hain. To hamara SQLite data dono se survive karta hai.

</details>
