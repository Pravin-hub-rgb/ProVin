## Step 1: Project Folder Banao

Sab kuch ek folder me rahega, taaki organized ho. Terminal me jao (jahan tumhara project banega hai — ye tumhare khud ke project folder me banao, `Desktop/main` me kahin bhi):

```bash
mkdir trading-backend-basic
cd trading-backend-basic
mkdir app

```

Ab structure ye hai:
```
trading-backend-basic/
  app/
  data/
```

**`app/` me code rahega, `data/` me database file.** Ye separation real projects ka standard hai — code aur data mix nahi karte.

## Step 2: Virtual Environment Banao (venv)

Ye shuru me confuse karta hai — *"venv kya hai, kyun?"* — par seekh lo, har Python project me ye hota hai.

Socho tumhare **phone ka charger** — ek project me jo libraries chahiye (FastAPI, pandas), wo **dusre project me nahi chahiye**. Har project ko apna alag charger chahiye.

**venv = Python project ka personal "charger bag."** Isme sirf woh libraries install hongi jo is project ko chahiye. Dusre project me woh libraries nahi hongi — clean, isolated.

```bash
python -m venv venv
```

Ye ek `venv/` folder banayega jisme Python ka ek **private copy** hoga. Ab activate karo:

```bash
# Windows:
venv\Scripts\activate

# Mac/Linux:
source venv/bin/activate
```

Ab terminal me dikhega `(venv)` at the start — matlab **ab tum us venv ke andar ho.** Ab har `pip install` sirf is project me jayega.

**Ye har baar karna padega** naya terminal kholne pe. Bhool gaye? Koi nahi — bas activate kar do.

## Step 3: Libraries Install Karo

Ab woh libraries install karo jo chahiye:

```bash
pip install fastapi uvicorn
```

- **`fastapi`** — ye framework hai (routing, validation, docs)
- **`uvicorn`** — ye **server** hai jo FastAPI app ko chalata hai. FastAPI sirf blueprint hai, uvicorn usse actually **run** karta hai. (Jaise blueprint vs building — uvicorn wo building hai jo blueprint ko real banata hai.)

Abhi pandas SQLite nahi chahiye — wo aage (1.5.4) lagega. Abhi sirf ye do kaafi hain.

## Step 4: Pehla File Banao — `app/main.py`

Ab apna pehla FastAPI app likho. Ye 3 cheezein hai — app banana, ek route, aur ek health check:

```python
from fastapi import FastAPI

# App banao — ye tumhara "server ka blueprint"
app = FastAPI(title="Trading Backend Basic", version="0.1.0")


# Pehla endpoint — health check
@app.get("/health")
def health():
    """
    Server zinda hai ya nahi.
    Ye koi data nahi lagata — bas confirm karta hai app chal raha hai.
    """
    return {"status": "ok", "service": "Trading Backend Basic", "version": "0.1.0"}
```

**Line by line samjho:**

- `from fastapi import FastAPI` — FastAPI class import
- `app = FastAPI(...)` — ek app instance banao. `title` se Swagger me naam dikhega, `version` se
- `@app.get("/health")` — **decorator**. Bolo *"`/health` URL pe GET request aaye to neeche wali function chalao."* Ye wahi decorator hai jo 1.1-1.3 me padha tha
- `def health():` — ye function request pe chalega. Naam kuch bhi rakh sakte ho
- `return {...}` — jo dict return karoge, wo **automatically JSON** ban ke client ko jayega

**Yehi FastAPI ka magic hai** — `return {"status": "ok"}` likha, aur FastAPI ne apne aap usse JSON me convert karke bhej diya. Tumne kuch convert nahi kiya.

## Step 5: Server Chalao

Ye **sabse important moment** hai. Terminal me (venv activated) ye chalao:

```bash
uvicorn app.main:app --reload
```

**Ye command ka matlab:**
- `uvicorn` — server chalayega
- `app.main:app` — `app` folder → `main.py` file → `app` variable ko dhoondo. **Ye teen colon se linked hain**
- `--reload` — **code change karo to server khud restart ho jayega.** Ye development ke liye hai. Production me `--reload` nahi hota (security + performance)

**Terminal me kuch aisa dikhega:**
```
INFO:     Started reloader process
INFO:     Uvicorn running on http://127.0.0.1:8000
INFO:     Application startup complete.
```

`http://127.0.0.1:8000` — ye tumhara server chal raha hai. `127.0.0.1` ka matlab **"is computer pe khud"** (localhost). Browser me ye URL kholo.

## Step 6: Test Karo — `/docs` (Ye Sabse Mazedar Part Hai)

Browser me jao: **`http://127.0.0.1:8000/docs`**

**Ruk ja. Jo dikhega wo dekho.** Ye **Swagger UI** hai — FastAPI ka apna automatic documentation. Tumne **manually kuch nahi likha**, bas ek function likha, aur FastAPI ne:

- Sabhi endpoints ki **list** bana di
- Har endpoint ka **kya karta hai** likh di (docstring se)
- Har ek pe **"Try it out"** button de diya
- Har ek ka **example response** dikha diya

**Yehi FastAPI ka sabse bada killer feature hai** — free, automatic documentation.

Ab test karo:
1. `GET /health` expand karo → **"Try it out"** → **"Execute"** dabao
2. Neeche **Response** dikhega: `200` aur `{"status":"ok","service":"Trading Backend Basic","version":"0.1.0"}`
3. Status code **200** = sab theek (1.3 me padha tha)

**Ye moment celebrate karo.** Tumne ek **API server** khada kar liya. Ye woh base hai jisme 1.5.3 me tables aur endpoints aayenge.

## Common Mistakes

1. **`uvicorn app.main:app` galat likhna.** Format exact hai: `module.path:variable`. `app.main:app` sahi. `app/app.py:app` galat. Ya `main:app` bhi galat (kyunki file `app/` folder me hai, to module path `app.main` hoga).

2. **venv activate na karna.** `pip install` global ho jayega aur `uvicorn: command not found` milega. Terminal me `(venv)` dikhna chahiye start me.

3. **`--reload` bhoolna.** Code change karoge aur server purana rahega — confuse hoge ki " mera change kyu nahi dikh raha?" Hamesha development me `--reload` rakho.

4. **Port busy hona.** Agar `8000` pe koi aur chal raha hai to error aayega. Solution: `uvicorn app.main:app --reload --port 8001`.

5. **Browser me `localhost:8000/docs` na khule.** Server band hai ya `/docs` ka path galat. Check karo terminal me error to nahi aaya. Aur `/docs` yaad rakho — `/` pe kuch nahi aayega abhi (root route humne nahi banaya).

6. **`return` me string vs dict.** `return "ok"` bhi chalta hai (JSON string ban jayega), par `return {"status": "ok"}` behtar hai kyunki structured data hai. Health check me dict rakhna standard hai.

## Nutshell

- **venv** = project ka isolated environment. `python -m venv venv` se banao, activate karo, phir har baar naya terminal pe activate karna mat bhoolna.
- **`pip install fastapi uvicorn`** — FastAPI (framework) + uvicorn (server jo chalata hai).
- **`app = FastAPI()`** — app banao. `@app.get("/health")` — route define karo. `return {}` — FastAPI khud JSON banayega.
- **`uvicorn app.main:app --reload`** — server chalao. `--reload` = code change pe auto-restart.
- **`/docs`** = free, automatic Swagger documentation. **"Try it out" se bina frontend ke test karo.**

## In Your Own Words

<details>
<summary>1. venv kyun zaroori hai? Iske bina kya problem aati hai?</summary>

Har Python project ko alag libraries chahiye. Ek project me pandas chahiye, doosre me koi aur version. venv har project ko ek **isolated Python environment** deta hai — jo bhi `pip install` karoge, sirf us project me jayega, system-wide ya doosre projects me nahi. Iske bina libraries mix ho jati hain, version conflicts aate hain, aur ek project doosre ko toot sakta hai. venv = har project ka apna alag "toolbox".

</details>

<details>
<summary>2. `uvicorn app.main:app --reload` me har part ka kya matlab hai?</summary>

`uvicorn` = wo server jo FastAPI app ko actually **run** karta hai (FastAPI sirf blueprint hai). `app.main:app` = module path (`app` folder → `main.py`) aur us file ka variable (`app`) — teen colon se linked. `--reload` = development mode, code change karte hi server auto-restart ho jata hai. Production me `--reload` nahi hota kyunki wo performance hit karta hai aur security risk hai.

</details>

<details>
<summary>3. `/docs` kya hai aur ye kaise aata hai bina likhe?</summary>

`/docs` = **Swagger UI** — FastAPI ka automatic interactive documentation. Ye FastAPI ke andar built-in hai. Jab tum route define karte ho `@app.get("/health")`, FastAPI automatically usse document kar deta hai — function ka naam, docstring (jo `"""..."""` me likha), aur example response. Tumhe manually docs likhne ki zaroorat nahi. Har endpoint pe "Try it out" button milta hai jisse bina koi frontend likhe browser se test kar sakte ho.

</details>

<details>
<summary>4. Function se `return {"status": "ok"}` karte hi JSON kaise ban jaata hai?</summary>

FastAPI har route function ke **return value ko automatically JSON me convert** kar deta hai aur `Content-Type: application/json` header ke saath bhej deta hai. Tumhe `json.dumps()` ya kuch bhi manually call nahi karna. Bas Python ka normal dict/list return karo — FastAPI baaki sambhal leta hai. Yehi FastAPI aur Flask me sabse bada farak hai (Flask me manually `jsonify()` karna padta hai).

</details>

<details>
<summary>5. Health endpoint real me kaun use karta hai? Interview me kaise explain karoon?</summary>

Real me health endpoint use hota hai **deployment ke baad server check karne ke liye**. Hosting platforms (Vercel, Railway, AWS, Docker) aur load balancers har kuch der pe `/health` hit karte hain — agar 200 return hota hai to server healthy maana jaata hai, nahi to wo traffic bhejna chhod deta hai ya server ko restart karta hai. Interview me bolo: *"Maine har service me ek `/health` endpoint add kiya hai jo server ki zindagi check karta hai — isse deployment platform ko pata chalta hai server ready hai ya nahi, aur monitoring tools bhi isko use karte hain."*

</details>

## What It Is NOT

- ❌ **Ye final app nahi hai** — sirf server khada hai. Abhi sirf `/health` hai.
- ❌ **Isme database nahi hai** — tables 1.5.3 me aayengi. Abhi koi data store nahi hota.
- ❌ **Ye production setup nahi hai** — `--reload` development mode hai. Production me workers, gunicorn, proper config chahiye.
- ❌ **Ye frontend nahi hai** — browser me `/docs` se test karoge, koi proper UI nahi banaya ja raha (wo Phase 2/Next.js side hoga).
- ❌ **Ye auth nahi hai** — koi bhi `/health` hit kar sakta hai. Real me security chahiye.
