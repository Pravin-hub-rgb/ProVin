## MCQ

Q: `int umar = 25;` mein `int` ka kya kaam hai?
A. Ye variable ko print karta hai
B. Ye compiler ko batata hai ki is dabbe mein sirf pura number rakhna hai
C. Ye value ko string mein convert karta hai
D. Ye loop chalata hai
> B. C# mein type (yahan `int`) dabba ka label hai — compiler pehle se jaan leta hai ki andar int hi aayega, aur galat value (string) likhi toh chalne se pehle rok deta hai.

---

Q: C# ka `var naam = "Vin";` JS ke `var naam = "Vin";` se kaise alag hai?
A. C# mein `var` kaam nahi karta
B. C# wala dynamic hai — baad mein number bhi daal sakte hain
C. C# wala sirf type chhupata hai — compiler value se type infer karta hai, aur wo type fix rehta hai
D. JS wala type chhupata tha, C# wala nahi chhupta
> C. C# `var` = type tum mat likho, main value dekh kar nikaal leta hoon (`var x = 5` → int). Andar ka type ek baar fix, baad mein galat type nahi daal sakte. JS `var` dynamic tha (kuch bhi chala jaata tha).

---

Q: `10 / 3` C# mein kya deta hai jab dono `int` hain?
A. 3.3333
B. 3
C. 4
D. Compile error
> B. int/int ka result int hota hai — decimal hissa kaat ke fek deta hai (floor). Decimal chahiye toh `(double)10 / 3` jaisa conversion karna padta hai. JS mein sab number the isliye 3.33 milta tha.

---

Q: `Console.ReadLine()` se input lete waqt kya milta hai?
A. Jaisi cheez input ki gayi — number toh number
B. Hamesha string, chahe user ne kya likha ho
C. Number hi, par galat input pe crash
D. Boolean
> B. `Console.ReadLine()` hamesha string lauta hai (JS ke `prompt()` jaisa). Number chahiye toh `int.Parse()` ya `int.TryParse()` se convert karna padta hai.

---

Q: C# mein `List<int>` aur `int[]` array — default kaunsa use karna chahiye aur kyun?
A. Array hamesha — faster hai
B. List — kyunki size badh-sakta hai aur `Add()` se items jod sakte hain
C. Dono same hain, naam farak hai
D. List sirf strings ke liye
> B. Array ka size banate waqt fix hai — `arr[3]` pe exception. List `Add()`/`Remove()` se badhti hai, isliye size pata na ho toh List default choice hai. `int[]` tab jab size constant ho.

Q: C# method ka naam kis convention mein likha jaata hai?
A. camelCase (`getTotal`) — JS jaisa
B. PascalCase (`GetTotal`)
C. snake_case (`get_total`)
D. Koi bhi, farak nahi padta
> B. C# mein methods aur classes PascalCase (`GetTotal`, `Customer`), parameters/variables camelCase (`firstNum`). Ye convention compiler nahi todti par puri community/IDE isse follow karti hai.

---

Q: `void Calculate(int a)` ka matlab kya hai?
A. Method hamesha 0 lautaega
B. Method kuch return nahi karta — bas kaam kar deta hai
C. Method sirf void mein store hota hai
D. Method ka naam void hai
> B. `void` ka matlab return-type khaali — jaise JS function bina `return` ke `undefined` deta tha. Aise methods kaam karte hain (print, file likhna) par value nahi laate.

## TrueFalse

Q: C# mein `if (umar)` chal jaata hai kyunki 0 ko false maana jaata hai (JS jaisi truthy-falsy).
- True
- False
> False. C# condition mein strictly boolean chahiye — `umar` int hai toh seedha nahi chalega. `if (umar > 0)` jaisa explicit comparison likhna padta hai. JS wali truthy-falsy convention C# mein nahi hai.

---

Q: C# `switch` mein kisi `case` ke baad `break` na likho toh agla case fall-through hoga (JS jaisa).
- True
- False
> False. C# mein `break` (ya `return`/`throw`) mandatory hai — compiler error de deta hai. JS ki silent fall-through bug possibility yahan compile-time pe hi khatam ho jaati hai.

---

Q: `marks[10]` jab list mein sirf 3 items hain — C# mein program chalta rehta hai aur `undefined` deta hai.
- True
- False
> False. C# mein IndexOutOfRangeException fekta hai aur program crash karta hai. JS chup-chaap `undefined` deta tha — isliye C# mein access se pehle `idx < Count` check karna zaroori hai.

---

Q: `foreach` loop ke andar us item ki value ko change karna (`n = "x"`) C# mein allowed hai.
- True
- False
> False. `foreach` jo deta hai wo uska apna copy hai (mostly) — badalne pe error aata hai. Value badalni ho toh index wala `for` loop use karo.

---

Q: Method ka `Sum` logic ek jagah likh kar `Average` mein reuse karna duplicate code se behtar hai — kyunki badlaav ek hi jagah karna padta hai.
- True
- False
> True. Yahi DRY (Don't Repeat Yourself) principle hai. `Average` ne `Sum` ko call kiya — total ka logic single jagah. Badalna ho toh ek hi file/line change karni padegi, dobara-dohrana nahi hoga.
