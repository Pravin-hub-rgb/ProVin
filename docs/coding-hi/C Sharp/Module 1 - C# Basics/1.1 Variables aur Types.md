Tumne apna pehla C# program chala liya — `Console.WriteLine`, string, int, sab thoda-thoda dekha. Ab wahi kaam jo JS seekhte waqt sabse pehle kiya tha: data ko variable mein rakhna. JS mein `const naam = "Vin"` theek tha, par C# mein thoda zyada sochna padta hai — kyunki yahan har cheez ka **type** batana padta hai.

# Variables aur Types

**Variable** ka matlab JS wala hi hai — naam wala dabba jisme value rakhte ho. Fark yeh ki C# mein dabba banate waqt ye bhi bolna padta hai dabba kis cheez ka hai:

```csharp
string naam = "Vin";    // text wala dabba
int umar = 25;          // pura number wala dabba
bool active = true;     // sirf true/false wala dabba
```

Syntax ka pattern hamesha same hai: `type naam = value;`. JS mein `const`/`let` likhte the, yahan type likhte hain — kyunki C# compiler ko pehle hi bata do ki dabba kis cheez ka hai, wo baad mein dhyaan rakh lega.

## Kyun type likhna padta hai — JS ka thoda dard yaad karo

JS mein yeh sab ho jaata tha aur kabhi kabhi chup-chaap ulta-seedha karta tha:

```javascript
let x = 5;
x = "paanch";     // JS: koi problem nahi... par galat ho gaya conceptually
x + 1             // "paanch1" — string join! koi error nahi
```

TypeScript ne isko roka tha na — wahi tension C# ko already built-in hai. C# mein:

```csharp
int x = 5;
x = "paanch";     // error CS0029 — compiler ne pehle hi rok diya
x + 1             // hamesha number addition — string/number ki confusion hi nahi
```

**TypeScript wala feel, bas compiler-level pe.** Yahi "strictness" hai jo tumhe daily kaam mein mehsoos hogi — galti likhte hi red line, run karne ki zaroorat nahi.

## C# ke main types (roz kaam ki list)

JS mein `number`, `string`, `boolean`, `object`, `array` — bas. C# mein thoda zyada hain kyunki number alag-alag size ke dabbon mein aata hai:

```csharp
// Numbers
int umar = 25;                 // pura number (integer) — JS ka number ka ek hissa
double salary = 45000.50;      // decimal wala number — JS ka number jaisa
long badaNumber = 1234567890L; // bohot bada integer

// Text
string naam = "Vin";           // "" ya "" dono chalega
char ekAkshar = 'V';           // sirf EK character — single quotes!

// True/False
bool active = true;            // JS jaisa, bas 'bool' naam hai

// Special
int? kuchNahi = null;          // "maybe int" — null allow karne ke liye ? lagao
```

Dhyan do do cheezon pe:

- **`char`** ek akshar ke liye single quotes (`'V'`), `string` ke liye double quotes. JS mein single/double same the, yahan type alag ho jaata hai.
- **`null`** seedhe `int x = null;` nahi chalega — kyunki `int` ek *value type* hai, usme null ki jagah nahi. Isliye `int?` likhna padta hai ("maybe int"). `string s = null;` chalega kyunki string *reference type* hai. Abhi itna hi yaad rakho — "type ke saath `?` = andar null bhi reh sakta hai".

## var — type chhupana (tumhari JS aadat ke liye)

Type har jagah likhna bhaari lage toh C# ek chhota jugaad deta hai:

```csharp
var naam = "Vin";      // compiler khud pakad lega — string
var umar = 25;         // — int
var active = true;     // — bool
```

**`var` ≠ JS ka `var`.** JS wala garbage-can jaisa tha (function scope, baad mein redeclare). C# ka `var` sirf "type tum mat likho, main dekh leta hoon" hai — andar ka type fixed hai, baad mein `var naam = 5;` nahi kar sakte. Matlab **infer** hota hai, **dynamic** nahi hota.

> Practice mein: literal values ke saath `var` (jaise `var list = new List<string>();`), obvious cheezon mein type likho. Zyadatar teams type likhna prefer karti hain — code padhne wale ko turant pata chalta hai.

## const — waise ka waise

```csharp
const int MaxSeats = 100;   // ek baar assign, phir badal nahi sakte
```

JS wala `const` jaisa hi — value fix. Fark: C# mein `const` sirf compile-time constant ke liye chalta hai (jo line likh ke turant pata ho, jaise `100`, `"abc"`). Object ke liye `readonly` use hota hai (module 2 mein). Abhi ke liye `const` = fix value, bas.

## Type conversion — JS se sabse bada behavior shift

JS mein `"5" + 1` string join ban jaata tha na? C# mein aisa kuch nahi hota — type mix hui toh ya toh compiler error de deta hai, ya tumhe **explicitly** bolna padta hai:

```csharp
// String → Number (parseInt/Number jaisa, par typed)
int n = int.Parse("42");          // "42" → 42, galat text ho toh exception
int n2 = Convert.ToInt32("42");   // thoda forgiving version

// Number → String
string s = 42.ToString();         // 42 → "42"

// int → double (safe widening — ye chup-chaap ho jaata hai)
int pura = 45;
double decimalWala = pura;        // 45 → 45.0, koi error nahi
```

**Rule of thumb:** safe wali taraf badalne pe chup-chaap chalta hai (int → double), risky taraf (string → int, double → int) tumhe bolna padta hai. `int.Parse("hello")` likha toh program chalne pe exception fekega — "parsing" mein galti ho sakti hai, isliye user input pe `TryParse` jaisa safer version hota hai (aage ke files mein).

Yeh kya NAHI hai:

- **`var` dynamic nahi hai** — JS `var`/`let` ki tarah kuch bhi daal sakte aise nahi. Ek baar type fix, hamesha wahi.
- **Type naam small nahi hote** — `string`, `int`, `bool` sab lowercase hain, par `.ToString()`, `.Length` jaise members capital hote hain. C# mein convention strict hai.
- **JS ka `number` nahi hai** — JS mein sab number ek type the; C# mein `int`, `double`, `long`, `float` alag hain. Galat dabba chuna toh compiler bolega.

Ek chhota complete example sab jodta hua:

```csharp
// Program.cs
var naam = "Vin";              // string (infer)
int umar = 25;                 // int
double salary = 45000.50;      // double
bool courseReady = true;        // bool

// type conversion + jodna
string message = naam + " ki salary " + salary + " hai";  // + auto-string banata hai
int doublesUmar = umar * 2;    // number maths

Console.WriteLine(message);    // Vin ki salary 45000.5 hai
Console.WriteLine(doublesUmar); // 50
Console.WriteLine(naam.Length); // 3 — string ki property (JS jaisa)
```

`dotnet run` karke dekh lo — output sahi aana chahiye.

## In Your Own Words

1. C# mein variable banate waqt type likhna zaroori hai — JS ke mukable iska faayda ek example ke saath batao.

<details>
<summary>Sample Jawab</summary>

**Jawab:** JS mein `let x = 5; x = "paanch";` chal jaata tha aur baad mein `"paanch" + 1` jaisi galti milti thi. C# mein `int x = 5; x = "paanch";` pe compiler turant error deta hai — galti chalne se pehle pakdi jaati hai, production mein kam jhol.

</details>

2. C# ka `var` aur JS ka `var` — kya same hain? Dono ka farq samjhao.

<details>
<summary>Sample Jawab</summary>

**Jawab:** Nahi. JS `var` function-scoped tha, dobara assign ho sakta tha, aur usme kuch bhi daal sakte the (dynamic). C# `var` sirf type chhupata hai — compiler value se type khud infer karta hai, ek baar fix hone ke baad usme galat type nahi daal sakte. Matlab infer static, dynamic nahi.

</details>

3. `int?` kyun likhna padta hai — `int x = null;` kyun nahi chalta?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `int` value type hai — memory mein direct value rehti hai, null ki jagah nahi hoti. `int?` compiler ko bolta hai ki ye "maybe int" hai (nullable), andar null bhi reh sakta hai. Isliye nullable value types ke liye `?` lagana zaroori hai.

</details>

4. `"42"` ko int mein badalne ke 2 tarike likho, aur `int.Parse("hello")` pe kya hoga.

<details>
<summary>Sample Jawab</summary>

**Jawab:** `int.Parse("42")` ya `Convert.ToInt32("42")`. `int.Parse("hello")` pe parse ho nahi payega aur chalne waqt exception (FormatException) fekega — isliye uncertain input pe safer `int.TryParse` use karte hain.

</details>
