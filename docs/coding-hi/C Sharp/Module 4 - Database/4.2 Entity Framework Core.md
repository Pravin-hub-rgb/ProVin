# Entity Framework Core (EF Core)

## EF Core kya hai — ek analogy

**EF Core = translator.** Ek taraf tumhari C# duniya (classes, objects, LINQ), doosri taraf database ki duniya (tables, rows, SQL). Tum C# mein bolte ho, ye SQL mein DB ko samjha deta hai, aur result wapas C# objects mein laata hai.

```
Tum (C# + LINQ)  ←→  EF Core (translator)  ←→  DB (SQL tables)
db.Students.Where(...)   →   SELECT * FROM Students WHERE ...
```

**ORM = Object-Relational Mapper** — yahi shabd hai, naam yaad rakhna.

## 4 kaam (CRUD) — ek file mein

```csharp
// Model — ye class DB table banegi
class Student
{
    public int Id { get; set; }          // PK (naming convention: Id)
    public string Name { get; set; }
    public int Marks { get; set; }
}

// Context — "DB se jodne wala door"
class SchoolDb : DbContext
{
    public SchoolDb(DbContextOptions<SchoolDb> options) : base(options) { }
    public DbSet<Student> Students { get; set; }    // ← table handle
}

// --- CRUD ---
// CREATE
db.Students.Add(new Student { Name = "Vin", Marks = 90 });
await db.SaveChangesAsync();       // ❗ yahan tak DB mein gaya

// READ
List<Student> all = await db.Students.ToListAsync();
Student one = await db.Students.FindAsync(1);          // Id se
var top = await db.Students.Where(s => s.Marks >= 80)
                           .OrderByDescending(s => s.Marks)
                           .ToListAsync();

// UPDATE
Student s = await db.Students.FindAsync(1);
s.Marks = 95;                       // property badli
await db.SaveChangesAsync();        // UPDATE DB mein chala

// DELETE
db.Students.Remove(s);
await db.SaveChangesAsync();        // DELETE chala
```

**Golden rule: `SaveChangesAsync()` ke bina kuch bhi DB mein nahi jaata.** `Add`/`Remove`/property-change sab sirf memory mein track hote hain — save karne pe EF ek saath SQL bhejta hai (transaction ke saath).

## Program.cs — pehla working setup (SQLite practice)

```csharp
// Program.cs
using Microsoft.EntityFrameworkCore;

class Student
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public int Marks { get; set; }
}

class SchoolDb : DbContext
{
    // connection kahan — Program.cs se aayega
    public DbSet<Student> Students => Set<Student>();
}

class Program
{
    static void Main()
    {
        // SQLite file-based DB — practice ke liye sabse aasan
        var options = new DbContextOptionsBuilder<SchoolDb>()
            .UseSqlite("Data Source=school.db")
            .Options;

        using var db = new SchoolDb(options);
        db.Database.EnsureCreated();     // table nahi hai toh bana do

        // CREATE
        db.Students.Add(new Student { Name = "Vin", Marks = 90 });
        db.Students.Add(new Student { Name = "Rahul", Marks = 85 });
        db.SaveChanges();                // sync version — simple program mein chalega

        // READ (LINQ)
        var top = db.Students.Where(s => s.Marks >= 88)
                             .OrderByDescending(s => s.Marks)
                             .ToList();

        foreach (var s in top)
            Console.WriteLine($"{s.Name}: {s.Marks}");

        // UPDATE
        var vin = db.Students.First(s => s.Name == "Vin");
        vin.Marks = 95;
        db.SaveChanges();

        Console.WriteLine("Total: " + db.Students.Count());
    }
}
```

`dotnet run` → file `school.db` ban jayegi — andar table + data. **C# class → DB table, LINQ → SQL — bina SQL likhe.**

## Migrations — table badalne ka tareeka

`EnsureCreated()` chhoti practice ke liye theek hai, par asli project mein schema **badalta** rehta hai (baad mein `Email` column add karna). Wahi hai **migrations** — version-controlled schema changes:

```bash
dotnet tool install --global dotnet-ef     # ek baar
dotnet ef migrations add InitialCreate     # migration banao (code diff jaisa)
dotnet ef database update                  # DB pe apply karo
```

Flow: model class badlo → `migrations add Naam` (EF ne khud diff nikaal liya) → `database update` (DB mein column add ho gaya). **Git jaisa hai bas database ke liye** — pura history rehta hai. Team projects mein yahi chalta hai.

`appsettings.json` mein connection string rakhna (agle file) toh commands:

```bash
dotnet ef migrations add InitialCreate --startup-project .
```

## Relationships — ek table doosri se (jaise real DB)

```csharp
class Student
{
    public int Id { get; set; }
    public string Name { get; set; }
    public int ClassId { get; set; }          // FK
    public SchoolClass Class { get; set; }    // navigation — jis class mein hai
}

class SchoolClass
{
    public int Id { get; set; }
    public string Title { get; set; }
    public List<Student> Students { get; set; } = new();   // us class ke students
}
```

- `ClassId` = **Foreign Key** (SQL wala wahi)
- `Class` / `Students` = **navigation property** — object graph mein aage-piche ghoomne ke liye

Aur magic — **eager loading** (jo JS `include` jaisa):

```csharp
var s = await db.Students
    .Include(x => x.Class)      // ⭐ class bhi saath laao (JOIN)
    .FirstOrDefaultAsync(x => x.Id == 1);

Console.WriteLine(s.Class.Title);   // bina query kiye data ready
```

Bina `Include` ke `s.Class` null hota (EF jaanta nahi tha). `Include = JOIN` — asli SQL mein.

## Yeh kya NAHI hai

- **`Add()` turant DB mein nahi** — sirf track hua. `SaveChangesAsync()` hi commit hai (jinno DB mein nahi — unke liye `SaveChanges` sync bhi chalta hai async ke bina).
- **EF har query pe sab rows nahi lata** — `.Where()` pe SQL `WHERE` ban ke DB pe hi filter hota hai; memory mein poora table kabhi nahi aata (lazy = soch-samajh ke SQL jaata hai).
- **`EnsureCreated` = migration nahi** — migration aam kaam hai; EnsureCreated baad mein changes handle nahi karta. Practice chhota ho toh chalega.
- **Naviglation property DB column nahi** — `public SchoolClass Class` koi column nahi banata, sirf EF ka link hai; column `ClassId` banata hai.

## In Your Own Words

1. ORM kya hai — EF Core kis duniya ke beech translator ka kaam karta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** ORM (Object-Relational Mapper) C# objects aur database tables ke beech mapping ka kaam karta hai. EF Core tumhare C# + LINQ ko SQL mein badal ke DB ko deta hai, aur rows ko wapas C# objects banata hai — tum SQL likhte hi nahi ho.

</details>

2. `db.Students.Add(x)` ke turant baad DB mein kya hoga — commit kab hota hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Add se kuch nahi hota — EF sirf change memory mein track karta hai. `SaveChangesAsync()` call pe saare pending changes ek saath SQL (INSERT/UPDATE/DELETE) ke roop mein DB ko bheje jaate hain, transaction ke andar.

</details

3. `.Include(x => x.Class)` kyun zaroori hai — bina iske kya hota?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Include related data load karta hai (SQL JOIN). Bina iske `student.Class` null hota hai — EF related table se data laana tabhi karta hai jab tum explicitly bolo. Isse achanak bahut zyada data load hone se bhi bachte ho.

</details>

4. Migrations aur `EnsureCreated()` — real project mein kaunsa aur kyun?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Migrations — kyunki project mein schema badhta rehta hai. Migration = ek version-controlled schema change (`migrations add` se diff banao, `database update` se apply). `EnsureCreated` sirf pehli baar tables banata hai, baad ke changes handle nahi — practice ke liye theek, production ke liye nahi.

</details>

EF Core se CRUD ready hai — par abhi connection string `UseSqlite("...")` code mein likha tha, aur `.csproj` bhi. Asli project mein **secrets/config** alag jagah hote hain, aur project ka structure alag. Wahi agla file: `appsettings.json`, connection strings, aur .NET project ka anatomy.
