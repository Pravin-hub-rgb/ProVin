Ab tak tumne C# language seekhi — variables, classes, loops. Par language toh sirf grammar hai. JavaScript ke saath tumne jo kaam kiya (date nikalna, array filter karna), usme tumhara asli haath-thaa **Node.js ka built-in toolbox** tha — `Date`, `Math`, `Array.map`, `JSON.parse`. C# ke liye wahi toolbox deta hai **.NET ki Base Class Library (BCL)** — aur uska sabse powerful hissa hai **LINQ**.

# BCL aur LINQ

## BCL — .NET ka built-in toolbox

Jab tum `using System;` likhte ho toh tum BCL ke darwaze khol rahe ho. Har chhoti-moti cheez wahan ready milti hai:

```csharp
using System;

Console.WriteLine(DateTime.Now.ToString("yyyy-MM-dd"));   // date — JS: new Date()
Console.WriteLine(Math.Max(5, 10));                        // JS: Math.max
Console.WriteLine(Math.Round(3.14159, 2));                 // 3.14
Console.WriteLine(Guid.NewGuid());                         // unique ID — DB wali
Console.WriteLine("Hello".ToUpper());                      // string helpers
Console.WriteLine(Math.Abs(-50));                          // 50
```

**Kuch install nahi karna** — ye sab `dotnet new console` ke saath hi aata hai. JS mein `Math`, `Date` kahan se aata tha? Browser/Node ke built-ins se. Wahi cheez, par C# mein sab kuch **ek hi library (BCL)** mein organized hai — chahe date ho, file ho, regex ho, collection ho.

NuGet packages tab aate hain jab BCL mein na ho (jaise SQL driver, email client) — woh module 4 mein.

## LINQ — C# ka sabse bada secret weapon

**LINQ = Language Integrated Query** — list/array pe sawaal poochhne ki ek language. Pehle JS wala code dekho:

```javascript
// JS — data filter, sort, transform
const adults = users.filter(u => u.age >= 18);
const names = adults.map(u => u.name.toUpperCase());
const sorted = users.sort((a, b) => a.age - b.age);
```

C# mein wahi kaam do tarike se — pehle **classic** (tumhe ye samajh aana chahiye):

```csharp
List<string> names = new List<string>();
foreach (var u in users)
{
    if (u.Age >= 18)
        names.Add(u.Name.ToUpper());
}
```

Phir **LINQ** (jo roz use hoga):

```csharp
var names = users
    .Where(u => u.Age >= 18)        // filter — JS: filter
    .Select(u => u.Name.ToUpper())  // transform — JS: map
    .OrderBy(u => u.Age)            // sort
    .ToList();
```

Ek nazar mein mapping:

| JS | LINQ |
|---|---|
| `.filter()` | `.Where()` |
| `.map()` | `.Select()` |
| `.find()` | `.FirstOrDefault()` |
| `.some()` | `.Any()` |
| `.every()` | `.All()` |
| `.reduce()` | `.Sum()` / `.Aggregate()` |
| `.sort()` | `.OrderBy()` / `.OrderByDescending()` |
| length check | `.Count()` |

**Lambda** (`u => u.Age >= 18`) JS arrow function jaisa hi hai — ek chhota expression jo bolta hai "har `u` ke saath ye check karo".

## LINQ ke roz wale methods

```csharp
List<int> nums = new List<int> { 5, 3, 8, 1, 9, 2 };

int max = nums.Max();                    // 9
int min = nums.Min();                    // 1
int sum = nums.Sum();                    // 28
double avg = nums.Average();             // 4.66

bool koiBada = nums.Any(n => n > 8);     // true — koi ek mila?
bool SabChhote = nums.All(n => n < 10);  // true — sab mil gaye
int pehla = nums.First();                // 5 — na mile toh exception
int? pehlaYa = nums.FirstOrDefault(n => n > 100);   // null — safe version ⭐
int kitne = nums.Count(n => n % 2 == 0); // even count
```

**`FirstOrDefault` pattern** yaad rakho — C# mein data dhoondhna sabse aam kaam hai, aur ye null lauta sakta hai isliye check karna padta hai:

```csharp
var student = students.FirstOrDefault(s => s.Name == "Vin");
if (student == null)
{
    Console.WriteLine("Nahi mila");
}
else
{
    Console.WriteLine(student.Marks);
}
```

JS mein `arr.find()` `undefined` deta tha — wahi pattern, bas null ke saath.

## Query syntax (purana style)

Codebase mein kabhi-kabhi ye bhi milega:

```csharp
var result = from u in users
             where u.Age >= 18
             select u.Name;
```

SQL jaisa dikhta hai. **Dono same kaam karte hain** — modern code method syntax (`.Where()`) prefer karta hai par dono samajhne chahiye (purane .NET code mein milta hai).

## Anonymous types — bina class ke object

```csharp
var report = new { Naam = "Vin", Marks = 90 };   // chhota data bag
Console.WriteLine(report.Naam);
```

`new { ... }` — ek baar ke liye chhota object bana liya bina class likhe. LINQ ke saath bahut aata hai:

```csharp
var top = students
    .OrderByDescending(s => s.Marks)
    .Select(s => new { s.Naam, s.Marks })   // sirf 2 cheezein chahiye
    .Take(3);
```

**Kab:** jahan data sirf print/report ke liye ho. **Kab nahi:** jahan store/return karna ho (woh proper class/DTO — module 5 mein).

## Yeh kya NAHI hai

- **LINQ = SQL query nahi hai** — database query LINQ-to-SQL hoti hai (module 4), par yahan jo hai wo **in-memory** list pe chalta hai. `List`, array — data already memory mein.
- **`.ToList()` se pehle kuch nahi hota** — LINQ methods **lazy** hain: `.Where()` turant nahi chalta, `foreach`/`ToList`/`Count` karne pe chalta hai. (JS ke `filter` turant naye array banate the — fark hai.)
- **BCL = NuGet package nahi** — BCL built-in hai, NuGet se download karte hain.

## Ek complete program — employee report LINQ se

```csharp
// Program.cs
using System;
using System.Collections.Generic;
using System.Linq;          // ❗ LINQ ke liye

class Employee
{
    public string Name;
    public string Dept;
    public double Salary;
    public Employee(string n, string d, double s) { Name = n; Dept = d; Salary = s; }
}

class Program
{
    static void Main()
    {
        var team = new List<Employee>
        {
            new Employee("Vin", "IT", 50000),
            new Employee("Rahul", "HR", 40000),
            new Employee("Sara", "IT", 60000),
            new Employee("Amit", "HR", 45000),
        };

        // IT wale, salary ke hisaab se, naam le kar
        var itSorted = team
            .Where(e => e.Dept == "IT")
            .OrderByDescending(e => e.Salary)
            .Select(e => $"{e.Name} ({e.Salary:C0})");

        foreach (var line in itSorted)
            Console.WriteLine(line);

        // Ek sawaal: HR mein koi 42000 se zyada?
        bool highPaid = team.Any(e => e.Dept == "HR" && e.Salary > 42000);
        Console.WriteLine("HR ka high earner? " + highPaid);   // True

        // Report: department-wise total
        var totals = team
            .GroupBy(e => e.Dept)                       // group — SQL GROUP BY jaisa
            .Select(g => new { Dept = g.Key, Total = g.Sum(e => e.Salary) });

        foreach (var t in totals)
            Console.WriteLine($"{t.Dept}: {t.Total}");
    }
}
```

`GroupBy` dekha? Department ke hisaab se toorna aur `Sum` — SQL jaisa kaam bina database ke. Yahi power hai.

## In Your Own Words

1. BCL kya hai aur `Math.Round`, `DateTime.Now`, `Guid.NewGuid()` jaise cheezein kahan se aati hain?

<details>
<summary>Sample Jawab</summary>

**Jawab:** BCL (.NET Base Class Library) .NET ke saath built-in aane wali sabse badi class library hai — date, math, file, string, collection sab isme hain. `using System;` se access milti hai. Kuch install nahi karna padta, jaise JS mein `Math`/`Date` built-in the.

</details>

2. JS `filter/map/find` ka LINQ mein equivalent kya hai — ek example ke saath.

<details>
<summary>Sample Jawab</summary>

**Jawab:** `filter → Where`, `map → Select`, `find → FirstOrDefault`. Jaise `users.filter(u => u.age >= 18)` banta hai `users.Where(u => u.Age >= 18)`. Lambda (`u => ...`) arrow function jaisa hai — har item pe condition chalati hai.

</details>

3. `First()` aur `FirstOrDefault()` mein kya fark hai — kab kaunsa use karoge?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `First()` match na mile toh exception fekta hai; `FirstOrDefault()` null/`default` deta hai. User-input/dhoondhne wale code mein `FirstOrDefault` + null-check safe hai — `First()` tab jab pakka pata hai ki milega hi.

</details>

4. `nums.Where(...)` likhte hi kya hota hai — abhi bhi kuch nahi? Kab chalta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Kuch nahi — LINQ lazy hai, sirf query ka plan banta hai. Tab chalta hai jab result consume karo: `ToList()`, `foreach`, `Count()`, `First()` waghera call karo. JS ke `filter` (jo turant array banate the) se ye fark hai.

</details>

Data in-memory mein LINQ se ho gaya — par asli apps mein data **database** mein rehta hai aur **disk/file** pe save hota hai. Aur bahut bade kaam (**API call, database query**) turant nahi hote — inke liye chahiye **async/await** — jo JavaScript mein tumne Promises se kiya tha.
