Your PR is merged. The feature is in main. Now what about that branch you created? It's still sitting there in **two places** — on your local machine AND on GitHub. If you don't clean up both, you'll end up with 200 stale branches and no idea which ones are safe to delete.

**Remember: branches live in two places.**

When you pushed your feature branch earlier, Git created a copy on GitHub (the remote). Your local copy stayed on your machine. Deleting the local branch does NOT delete the remote one, and vice versa. You need to delete from both.

**How to tell which branches are local vs remote:**

```bash
# All branches (local + remote)
$ git branch -a
  UI-side-navbar-modification           ← local (no prefix)
* main                                  ← local
  taraju-loading                        ← local
  remotes/origin/UI-side-navbar-modification  ← remote (origin/ prefix)
  remotes/origin/main                   ← remote

# Remote branches only
$ git branch -r
  origin/UI-side-navbar-modification
  origin/main
```

Local branches show up with **no prefix** — they're on your machine. Remote branches show as `remotes/origin/<name>` (or `origin/<name>` in `-r`) — they're copies on GitHub. If you see a branch in `git branch -a` with `origin/` in the name, that's the remote copy.

**Clean up the remote branch first.**

GitHub offers to delete the remote branch right after merge. See that "Delete branch" button on the PR page? Click it. That deletes the branch on GitHub so nobody else has to look at it.

If you missed the button, or you want to do it from the terminal:

```bash
git push origin --delete feature/add-footer
# Shortcut: git push origin -d feature/add-footer  (same thing)
```

The `--delete` flag also works as `-d` — `git push origin -d feature/add-footer` is the same command. `-d` is just the shorthand, like `-m` for `--message`.

You'll see:

```
$ git push origin --delete feature/add-footer
To https://github.com/dev-A/team-practice.git
 - [deleted]         feature/add-footer
```

That's it. The branch is gone from GitHub.

**See the pattern? Same flag, different command.**

The *verb* changes based on WHERE the branch lives:

| Delete from... | Command | Flag meaning |
|---|---|---|
| **Local** (your machine) | `git branch -d <name>` | `-d` = `--delete` on the branch command |
| **Remote** (GitHub) | `git push origin --delete <name>` | `--delete` = push flag telling GitHub to delete a ref |

Both use `--delete` (or the shorthand `-d`). But the command around it changes: `git branch` for local, `git push` for remote. That's because deleting a local branch is telling your Git to remove a pointer. Deleting a remote branch is telling GitHub "here's a push that removes a ref" — you're pushing a deletion.

**Now clean up your local machine.**

You have two things to delete locally: the branch itself and the tracking reference.

```bash
git switch main
git pull origin main
git branch -d feature/add-footer
```

The `-d` (lowercase) is the safe delete. It only works if the branch has been fully merged. If you try to delete an unmerged branch, Git refuses:

```
$ git branch -d feature/add-footer
error: The branch 'feature/add-footer' is not fully merged.
If you are sure you want to delete it, run 'git branch -D feature/add-footer'.
```

That's Git protecting you from losing work. If you're sure you want to force it anyway, use uppercase `-D`:

```bash
git branch -D feature/add-footer
```

The `-d` and `-D` are short for `--delete` and `--delete --force` respectively. Same flags, different safety level. Use `-d` by default. Only use `-D` when you're absolutely certain the branch's work is safe (or you don't care about it anymore).

Same idea applies to remote branches — if you need to force-delete a remote branch that hasn't been fully synced, add `--force`:

```bash
git push origin --delete --force feature/old-experiment
# or: git push origin -d --force feature/old-experiment
```

**Check which branches are safe to delete before cleaning up:**

Same `--merged` flag works for both local and remote:

```bash
# Local branches merged into main (safe to delete locally)
$ git branch --merged main
  feature/add-footer
  feature/navbar
* main

# Remote branches merged into main (safe to delete on GitHub)
$ git branch -r --merged main
  origin/feature/add-footer
  origin/feature/navbar
  origin/main

# Local branches NOT merged (keep these)
$ git branch --no-merged main
  feature/experimental-thing

# Remote branches NOT merged (keep these too)
$ git branch -r --no-merged main
  origin/feature/experimental-thing
```

Same `--merged` / `--no-merged` logic, just add `-r` to check remote branches instead of local ones.

**How to batch clean up:**

If you have 15 merged branches to delete, doing them one by one is tedious. Here's a trick:

```bash
git branch --merged main | grep -v "main" | xargs git branch -d
```

This lists all merged branches except main, then deletes each one. Only run this when you're sure.

**Clean stale remote-tracking references with `git fetch --prune`:**

When you delete a remote branch on GitHub, your local Git still remembers it showed up in `git branch -r`. That stale `origin/feature/done` entry lingers until you clean it:

```bash
git fetch --prune
```

This tells Git: "fetch all remote changes, and remove any local references to remote branches that no longer exist." Run it after cleanup and your `git branch -a` output stays tidy.

**Why cleanup matters:**

A repo with 200 stale branches is confusing. New team members can't tell which branches are active. Old branches clutter the branch listing in your IDE. And if someone tries to use an old branch thinking it's safe, they might build on top of outdated code.

Delete branches after they're merged. It takes 5 seconds. It keeps the repo tidy.

**One more thing — what about the branch on your teammate's machine?**

When dev-B deletes a branch on GitHub, dev-A's local copy still exists. That's fine. Dev-A will see the stale branch in their local `git branch` listing until they delete it themselves. No harm done, just clean it when you notice it.

Immediately after it's merged into main. Both the remote branch (on GitHub) and the local branch (on your machine).
