You did a `git reset --hard` and lost your changes. Or you deleted a branch and realized it had work you needed. Your heart sinks. But here's the secret: Git almost never truly deletes anything.

**`git reflog` is your safety net.**

Reflog stands for "reference log." It records every single place your HEAD pointer has been. Every commit you made. Every reset. Every branch switch. Every checkout. For about 90 days by default, nothing is truly gone.

**What it looks like:**

```bash
$ git reflog
a1b2c3d (HEAD -> main) HEAD@{0}: reset: moving to HEAD~1
e5f6g7h HEAD@{1}: commit: Add awesome feature
a1b2c3d HEAD@{2}: commit: Fix login bug
4d3e2f1 HEAD@{3}: commit: Initial commit
```

This tells you:
- `HEAD@{0}` is your current position
- `HEAD@{1}` is where you were before — the commit you just reset away
- `HEAD@{2}` is where you were before that

To go back to the "deleted" commit, just check it out:

```bash
git checkout e5f6g7h
```

Now you're in a detached HEAD state (not on any branch), but you can see your files. To rescue it permanently:

```bash
git switch -c recovered-feature
```

This creates a new branch called `recovered-feature` at that commit. Your work is back.

**Full rescue sequence:**

```bash
# Uh oh, I just did git reset --hard HEAD~1 and lost my commit
git reflog
# find the commit hash you want to recover
git checkout <lost-commit-hash>
# verify the files are there
git switch -c rescued-branch
# Your work is now on a new branch. Push it if you want.
```

**What about deleted branches?**

Deleting a branch with `git branch -D` doesn't delete the commits. They're still in the reflog. The branch label is gone, but the commits are recoverable.

```bash
git branch -D feature/navbar    # oh no, I didn't mean that!
git reflog                      # find the last commit on that branch
git switch -c feature/navbar <hash>  # recreate the branch at that commit
```

**What reflog does NOT cover:**

Commits that are older than ~90 days (configurable, but default is 90). Also, commits that Git has garbage-collected (which happens when you run `git gc` or it runs automatically). For most day-to-day "oops" moments, though, reflog has your back.

**When to use reflog vs revert vs reset:**

| Scenario | Tool |
|----------|------|
| Undo last commit, keep changes (local only) | `git reset --soft HEAD~1` |
| Undo last commit, keep changes unstaged (local only) | `git reset --mixed HEAD~1` |
| Delete last commit entirely (local only) | `git reset --hard HEAD~1` |
| Undo something already pushed | `git revert <hash>` |
| I accidentally reset/deleted and need it back | `git reflog` |

Reflog is the emergency backup. Most people learn about it only after they've panicked once. Now you know it exists before the panic hits.

---

**In Your Own Words:**

<details>
<summary>1. What does `git reflog` show you?</summary>

Every place HEAD has pointed to recently — commits, resets, branch switches, checkouts. It's a log of your movements.
</details>

<details>
<summary>2. How do you recover a commit you accidentally deleted with `git reset --hard`?</summary>

Run `git reflog` to find the lost commit hash, then `git checkout <hash>` to inspect it, then `git switch -c <new-branch> <hash>` to rescue it onto a branch.
</details>

<details>
<summary>3. For how long are commits normally kept in reflog?</summary>

About 90 days by default, after which Git may garbage-collect them.
</details>

<details>
<summary>4. Does deleting a branch permanently delete its commits?</summary>

No. The commits still exist and can be found in reflog. Only the branch label pointing to them is removed.
</details>
