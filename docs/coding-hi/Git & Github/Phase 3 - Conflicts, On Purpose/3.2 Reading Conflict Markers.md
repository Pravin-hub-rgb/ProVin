So a conflict happened. You open the file and see this:

```
<<<<<<< HEAD
<h1>Welcome to the best site ever</h1>
=======
<h1>Welcome, friends!</h1>
>>>>>>> feature/teammate-branch
```

It looks broken. It's not. It's Git showing you the two versions and asking you to pick.

**Reading the markers:**

- `<<<<<<< HEAD` — start of the conflict. Everything below this is YOUR version (the branch you're currently on).
- `=======` — the divider. Above is your version, below is the incoming version.
- `>>>>>>> feature/teammate-branch` — end of the conflict. After this, it's back to normal file content. The branch name tells you where the other version came from.

So in the example above:
- Your version: `<h1>Welcome to the best site ever</h1>`
- Their version: `<h1>Welcome, friends!</h1>`

Git has no opinion on which is better. It shows you both and says "you decide."

**What happens if there are multiple conflicts in one file?**

Each conflict gets its own set of markers. You might see 3, 5, or 15 conflict blocks in one file. Each one is independent. Fix them one at a time. Git won't consider the conflict resolved until every marker is gone.

**How to fix it:**

1. Open the file in your editor
2. Decide which version to keep (or write something new combining both)
3. Delete the markers (`<<<<<<<`, `=======`, `>>>>>>>`)
4. Delete the version you don't want
5. Save

After fixing, the file should look like one of these:

Keep your version:
```html
<h1>Welcome to the best site ever</h1>
```

Keep their version:
```html
<h1>Welcome, friends!</h1>
```

Combine both:
```html
<h1>Welcome, friends! This is the best site ever.</h1>
```

All are valid. The decision is yours.

**One critical rule:**

After you fix all conflicts and before you commit, re-read the entire file. People accidentally leave `<<<<<<<` markers in the file all the time. Those won't break Git, but they'll break your HTML (or JavaScript, or whatever the file is). Always double-check.

**What if you want to see the conflict from the terminal?**

```bash
$ git diff
diff --cc index.html
index a1b2c3d..e5f6g7h 100644
--- a/index.html
+++ b/index.html
@@@ -1,4 -1,4 +1,8 @@@
+<<<<<<< HEAD
 +<h1>Welcome to the best site ever</h1>
+=======
+ <h1>Welcome, friends!</h1>
+>>>>>>> feature/teammate-branch
```

This shows the conflict in diff format. Some people prefer this view. I find opening the file directly easier.

**In Your Own Words:**

<details>
<summary>1. What does `<<<<<<< HEAD` mean in a conflict marker?</summary>

It marks the start of the conflict. Everything below it until `=======` is your version (the branch you're currently on).
</details>

<details>
<summary>2. What does `>>>>>>> feature/teammate-branch` tell you?</summary>

That's the end of the conflict marker. The branch name tells you whose changes are in the bottom section.
</details>

<details>
<summary>3. What are the three things you must do to resolve a conflict marker block?</summary>

Delete the markers (`<<<<<<<`, `=======`, `>>>>>>>`), delete the version you don't want, and save.
</details>

<details>
<summary>4. Why should you re-read the whole file before committing a conflict resolution?</summary>

To make sure you didn't accidentally leave any `<<<<<<<` or `=======` markers in the file.
</details>
