You've probably heard people say "push it to GitHub" or "commit your code" — and maybe you've even typed some of those commands yourself. But if someone asked you right now "what actually IS Git?" — could you answer?

Most people can't. And that's fine. But understanding the difference between Git and GitHub is like understanding the difference between your local game save and cloud save. They're connected, but they're not the same thing. And mixing them up makes everything else confusing.

So let's start from zero.

**Git is a tool on your computer that saves versions of your project.**

Imagine you're writing an essay. You write a paragraph. You save it as `essay-v1.docx`. Then you rewrite some parts and save it as `essay-v2.docx`. Then your friend tells you "actually the v1 version was better" — so you dig through your files looking for it.

Git does that, but automatically and way better. Every time you decide "okay, this is a good point to save," you tell Git to take a snapshot of everything. Git remembers that snapshot forever. Later you can look at any old snapshot, compare two snapshots, or go back to an old one.

These snapshots are called **commits**. A commit is just a saved version of your project at a specific moment.

All of this — the saving, the history, the going back to old versions — happens on your computer. No internet needed. Git doesn't need to talk to anyone. It quietly does its job inside a hidden folder called `.git` in your project.

**GitHub is a website where you can upload a copy of your project so other people can see it and work with you.**

Git handles the version saving on your machine. GitHub takes that history and hosts a copy online. Now your teammate can download that copy, make their own changes, and upload their version back. You all sync through GitHub.

It's like a video game save system. Git is your local save file — you save your progress at checkpoints right on your own computer. GitHub is the cloud save — you upload that save file so you can continue on another computer, or so a friend can pick up where you left off. The cloud save isn't where the game runs. It's just a copy you shared.

![Git vs GitHub — Your computer with .git folder on the left, GitHub on the right, connected by push/pull](/diagrams/gitgithub/git-vs-github.svg)

Look at the diagram above. On the left is your computer — Git saves all your commits locally in the `.git` folder, completely offline. On the right is GitHub — it holds a copy of your repo and adds team features like Pull Requests and Issues. The arrow between them shows how they sync (push sends your work up, pull brings changes down).

On top of that, GitHub adds things that Git alone can't do — things that matter when multiple people work together:

- **Pull Requests** — a way to say "I finished my part, can you check it before it goes into the main project?"
- **Code Review** — leaving comments on specific lines of someone's code
- **Issues** — a to-do list for tracking bugs and tasks
- **Actions** — automatically run tests when new code comes in

Git doesn't know how to do any of that. GitHub adds those features on top.

There are other websites that do what GitHub does — **GitLab** and **Bitbucket** are the biggest ones. They all use the same Git tool underneath. The commands are the same. Only the extra team features are different.

**Here's a simple test to check if you understand:**

If you deleted your GitHub account right now, would you lose your saved versions?

No. Your commits are still on your computer, inside that `.git` folder. GitHub was just a copy. You could create a new GitHub account tomorrow, connect it, and push (upload) your work there. Nothing is lost.

**One thing people often get wrong:**

Sometimes people think their code doesn't really "exist" until they push it to GitHub — like GitHub is the real storage and their computer is just a temporary workspace. That's backwards. Your code is real the moment you commit it on your machine. GitHub is just the shared space where you publish it for others.

**In Your Own Words:**

<details>
<summary>1. What is Git? What does it do for you?</summary>

Git is a tool on your computer that saves versions (snapshots) of your project. You can go back to any saved version anytime you want.
</details>

<details>
<summary>2. What is GitHub? What does it add that Git doesn't have?</summary>

GitHub is a website that hosts a copy of your Git history online. It adds team features: Pull Requests, code reviews, Issues, and Actions.
</details>

<details>
<summary>3. What is a commit in simple words?</summary>

A commit is a snapshot of your project at a specific moment. It's like hitting "save" but for your whole project, with a note about what changed.
</details>

<details>
<summary>4. If you lose internet, can you still save versions of your project using Git?</summary>

Yes. Git works completely offline. Saving versions only happens on your computer. You only need internet to share those versions with others through GitHub.
</details>

<details>
<summary>5. Name two websites similar to GitHub.</summary>

GitLab and Bitbucket. They all work with the same Git tool but have their own team features.
</details>
