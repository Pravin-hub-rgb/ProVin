The skeleton is in main. Now we plan the actual work. Create Issues for each piece of functionality. This is how real teams break down work.

**Create these Issues on GitHub:**

1. **Build hero section** — profile photo, name, tagline
2. **Build links section** — list of clickable links (socials, projects)
3. **Build footer** — copyright, attribution
4. **Add dark/light toggle** — JS toggle with CSS variable swap
5. **Style responsive layout** — mobile-friendly, max-width container

Go to the Issues tab → New Issue for each one. Give each a clear description.

Your Issues will look like this:

```
#1 Build hero section
A hero area with a profile image, name, and short tagline. Keep it simple — just HTML and CSS.

#2 Build links section
A list of links (Twitter, GitHub, portfolio) styled as cards/buttons.

#3 Build footer
Simple footer with copyright text and "built with" attribution.

#4 Add dark/light toggle
A button that switches between dark and light themes using CSS custom properties.

#5 Style responsive layout
Ensure everything looks good on mobile. Max-width container, media queries.
```

**Assign issues to developers:**

Conceptually, assign #1, #3, #5 to "dev-A" and #2, #4 to "dev-B". In practice, you're both people, but this simulates how work gets split on a real team.

Note: you don't actually have to assign GitHub Issues to the right account if you're the only person — just remember which dev owns which issue.

**Why this step matters:**

Issues create a roadmap. You know exactly what needs to happen and in what order. No ambiguity about "what should I work on next?" The board tells you.
