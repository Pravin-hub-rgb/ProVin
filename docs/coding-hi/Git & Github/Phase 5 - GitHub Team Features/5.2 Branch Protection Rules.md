You've learned the rules: always branch off main, always use PRs, always get a review. But rules only work if people follow them. What if someone pushes directly to main anyway? What if a PR merges without review?

Branch protection rules enforce the rules automatically. GitHub won't let you break them.

**What is a branch protection rule?**

It's a setting on your GitHub repo that says: "for this branch (usually `main`), enforce these rules."

Common rules:
- **Require a pull request before merging** — blocks direct pushes
- **Require approvals** (1, 2, or more) — PR can't merge without reviews
- **Dismiss stale reviews** — if new commits are pushed, old approvals are reset
- **Require status checks** — tests must pass (we'll cover this in 5.3)
- **Require up-to-date branches** — the branch must be synced with main before merging

**How to set it up:**

1. Go to your repo on GitHub
2. Settings → Branches → "Add branch protection rule"
3. In "Branch name pattern", type `main`
4. Check "Require a pull request before merging"
5. Check "Require approvals" → set to 1
6. Click "Create"

That's it. Now try pushing directly to main:

```bash
$ git switch main
$ echo "bad" >> index.html
$ git add index.html
$ git commit -m "Direct push attempt"
$ git push origin main
 ! [remote rejected] main -> main (protected branch hook declined)
error: failed to push some refs
```

GitHub refused. No warning. No "please don't." It just blocks it. That's the whole point.

**Try merging a PR without review:**

Create a branch, push it, open a PR. You'll see the merge button is greyed out with a message:

```
At least 1 approving review is required by reviewers with write access.
```

You literally cannot merge until someone approves. The rule is enforced by GitHub, not by trust.

**Why this matters:**

- Prevents accidents — no one can push a half-finished feature directly to main
- Enforces process — reviews become mandatory, not optional
- Onboards new teammates — they can't accidentally break things because the rules won't let them
- Audit trail — every commit to main went through a PR with review

**What else you can protect:**

You can protect any branch, not just main. Some teams protect `develop` or `release` branches too. But protecting `main` is the minimum standard at virtually every company.

**A note of caution:**

Branch protection can be bypassed by repo admins. If you're an admin, you might still be able to force-push even with protection on. The rules apply to everyone else. On professional teams, admins have their own rule: "even I follow the process."
