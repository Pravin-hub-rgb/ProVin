This is the lightest topic in the course. You don't need to become a project management expert. But knowing what Project Boards are will help you understand how teams organize work.

**What is a GitHub Project Board?**

It's a Kanban-style board — columns like "To Do", "In Progress", "Done" — where you can drag and drop Issues. Think of it as a visual version of your task list.

Here's what it looks like conceptually:

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│   To Do      │  │ In Progress  │  │    Done      │
│              │  │              │  │              │
│ ▪ Add footer │  │ ▪ Add navbar │  │ ▪ Setup repo  │
│ ▪ Dark mode  │  │              │  │ ▪ Add footer  │
│ ▪ Fix mobile │  │              │  │              │
└──────────────┘  └──────────────┘  └──────────────┘
```

**How to create one:**

1. Go to your repo on GitHub
2. Click the "Projects" tab → "Create project"
3. Choose "Board" layout
4. Name it (e.g., "Team Practice Sprint")
5. Click "Create"

You'll get three default columns: To Do, In Progress, Done. You can rename or add columns.

**How to use it:**

- Create Issues for your tasks (or use existing ones)
- Open an issue → click "Projects" in the sidebar → select your project → assign a column
- Or drag the issue card between columns on the board

When you start working on something, move it to "In Progress." When the PR merges, move it to "Done."

**Why it matters (lightly):**

Many teams plan work in "sprints" — 1-2 week cycles where they pick a set of tasks and move them across a board. Even if your team doesn't use sprints, a board gives everyone a single place to see "what are we working on right now."

For you, just knowing that Project Boards exist is enough. If you join a team that uses them, you'll recognize the format. If you're running a personal project, you can use one to stay organized.

**A quick drill:**

1. On your practice repo, create a Project Board called "Learning Phase 5"
2. Create 3 issues: "Add footer", "Fix navbar spacing", "Add dark mode toggle"
3. Add all three to the board in "To Do"
4. Move one to "In Progress"
5. Do the work, open a PR, merge it
6. Move the issue to "Done"

That's the full cycle. You've now used Issues, PRs, and Project Boards together.
