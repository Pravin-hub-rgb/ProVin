## What This Topic Is Asking (Simple Terms)

Operators are symbols that perform operations on values. You've already seen some (`+`, `-`, `=`, `===`) — now let's see all of them and how they behave, including the ones that surprise beginners.

---

## Operators Overview

| Category | Examples | What they do |
|----------|----------|--------------|
| Arithmetic | `+ - * / % **` | Math operations |
| Comparison | `=== !== > < >= <=` | Compare values, return boolean |
| Logical | `&& \|\| !` | Combine booleans, short-circuit |
| Assignment | `= += -= *= /=` | Assign / update values |
| Ternary | `? :` | Inline if/else |
| Nullish | `??` | Default value when null/undefined |
| Optional chaining | `?.` | Safe property access |

---

## Arithmetic Operators

```js
let a = 10, b = 3;

a + b;   // 13  (addition)
a - b;   // 7   (subtraction)
a * b;   // 30  (multiplication)
a / b;   // 3.333... (division)
a % b;   // 1   (remainder / modulo)
a ** b;  // 1000 (exponentiation: 10^3)
```

**The `+` operator is special** — it does both addition and string concatenation:

```js
5 + 3;        // 8 (number + number = addition)
"5" + 3;      // "53" (string + number = concatenation)
5 + "3";      // "53"
"Hello" + " " + "World"; // "Hello World"
```

**Unary `+`** converts a value to a number:

```js
+"5";       // 5
+"hello";   // NaN
+true;      // 1
+null;      // 0
```

## Comparison Operators

Always use `===` (strict equality) and `!==` (strict inequality). Never use `==` or `!=` (they coerce types).

```js
5 === 5;     // true
5 === "5";   // false (different types)
5 !== "5";   // true
5 > 3;       // true
5 < 3;       // false
5 >= 5;      // true
5 <= 4;      // false
```

**String comparison** is lexicographic (dictionary order, based on Unicode):

```js
"apple" < "banana";  // true (a < b)
"Apple" < "apple";   // true (uppercase A has lower Unicode value than lowercase a)
"10" < "2";          // true (string comparison: "1" < "2")
```

## Logical Operators

### `&&` (AND) — returns first falsy value, or the last value if all are truthy

```js
true && true;     // true
true && false;    // false
5 && 10;          // 10 (both truthy, returns last)
0 && 10;          // 0 (first falsy, returns it)
"" && "hello";    // "" (first falsy)
null && "hello";  // null
```

### `||` (OR) — returns first truthy value, or the last value if all are falsy

```js
true || false;    // true
false || true;    // true
0 || 10;          // 10 (first is falsy, returns second)
"" || "hello";    // "hello"
null || "default"; // "default"
```

### `!` (NOT) — flips the boolean value

```js
!true;     // false
!false;    // true
!0;        // true
!"";       // true
!"hello";  // false
!!"hello"; // true (double NOT converts to boolean)
```

### Short-Circuit Evaluation

`&&` and `||` stop evaluating as soon as the result is determined:

```js
// && short-circuits on first falsy value
const user = null;
user && user.name;  // null — doesn't even try to access .name (no error!)

// || short-circuits on first truthy value
const name = "";
const displayName = name || "Guest";  // "Guest" — name is falsy, so returns "Guest"
```

**Common use case — conditional execution:**

```js
isLoggedIn && showDashboard();  // only calls showDashboard if isLoggedIn is true
const value = input || "default";  // use input if truthy, else "default"
```

## Ternary Operator (`? :`)

The only operator that takes three operands. Inline if/else:

```js
const age = 18;
const status = age >= 18 ? "adult" : "minor";
// status = "adult"

// Equivalent to:
let status;
if (age >= 18) {
  status = "adult";
} else {
  status = "minor";
}
```

**Nested ternary (use sparingly — can be hard to read):**

```js
const score = 85;
const grade = score >= 90 ? "A" : score >= 80 ? "B" : score >= 70 ? "C" : "F";
// grade = "B"
```

---

## Nullish Coalescing (`??`)

Returns the right operand when the left is `null` or `undefined` (not other falsy values like `0`, `""`, `false`):

```js
const value = null ?? "default";     // "default"
const value2 = undefined ?? "default"; // "default"
const value3 = 0 ?? "default";       // 0 (0 is not null/undefined)
const value4 = "" ?? "default";      // "" (empty string is not null/undefined)
const value5 = false ?? "default";   // false
```

**`??` vs `||`:**

```js
const count = 0;
const result1 = count || 10;  // 10 (0 is falsy, so || returns 10)
const result2 = count ?? 10;  // 0 (0 is not null/undefined, so ?? returns 0)

// Use ?? when 0, "", false are valid values
// Use || when you want to treat all falsy values as "missing"
```

---

## Optional Chaining (`?.`)

Safely access nested properties. If any part is `null` or `undefined`, the whole expression returns `undefined` (no error):

```js
const user = {
  name: "Vin",
  address: {
    city: "Delhi",
  },
};

user?.name;              // "Vin"
user?.address?.city;     // "Delhi"
user?.phone?.number;     // undefined (no error, even though phone doesn't exist)
user?.getAge?.();       // undefined (safe method call)

// Without optional chaining:
// user.phone.number  →  TypeError: Cannot read properties of undefined
```

**Combine with nullish coalescing:**

```js
const city = user?.address?.city ?? "Unknown";
// city = "Delhi" (or "Unknown" if any part is null/undefined)
```

---

## Assignment Operators

```js
let x = 10;

x += 5;   // x = x + 5  → 15
x -= 3;   // x = x - 3  → 12
x *= 2;   // x = x * 2  → 24
x /= 4;   // x = x / 4  → 6
x %= 3;   // x = x % 3  → 0
x **= 2;  // x = x ** 2 → 0
```

## Common Mistakes

- **Using `==` instead of `===`** — `0 == false` is `true`, `0 === false` is `false`. Always use `===`.
- **`+` for both addition and concatenation** — `"5" + 3` gives `"53"`, not `8`. Convert first: `Number("5") + 3` or `+"5" + 3`.
- **Short-circuit gotchas** — `0 || "default"` returns `"default"` (0 is falsy). Use `??` if 0 is a valid value.
- **Ternary nesting** — nested ternaries are hard to read. Use if/else for complex logic.
- **Optional chaining on non-null values** — `user?.name` works but is unnecessary if `user` is guaranteed to exist. It's fine to use, but know it returns `undefined` if `user` is null.

---

## What This Topic Is NOT

- ❌ Operators are not the same as **methods** — `+` is an operator, `.toUpperCase()` is a method.
- ❌ `==` and `===` are not the same — `==` coerces, `===` doesn't.
- ❌ `??` and `||` are not the same — `??` only checks `null`/`undefined`, `||` checks all falsy values.
- ❌ `?.` (optional chaining) is not the same as `??` (nullish coalescing) — `?.` safely accesses properties, `??` provides default values.

1. What's the difference between `==` and `===`? Give an example where `==` gives a surprising result.

<details>
<summary>Show Answer</summary>

**Sample Answer:** `==` coerces types before comparing, `===` checks both value and type. Example: `0 == false` is `true` because `false` is coerced to `0`. `0 === false` is `false` because `number !== boolean`. Always use `===` to avoid surprises.

</details>

2. When would you use `??` instead of `||`? Give an example where they differ.

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use `??` when `0`, `""`, or `false` are valid values. Example: `const count = 0; count || 10` returns `10` (0 is falsy), but `count ?? 10` returns `0` (0 is not null/undefined). Use `||` when you want to treat all falsy values as "missing."

</details>

3. What does optional chaining (`?.`) do, and when is it useful?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `?.` safely accesses nested properties. If any part is `null` or `undefined`, the whole expression returns `undefined` instead of throwing an error. Useful when accessing properties on objects that might not exist: `user?.address?.city` returns `undefined` if `user` or `address` is missing, instead of crashing.

</details>

## Cheat Sheet (Quick Recall)

**Arithmetic:** `+ - * / % **` — `%` is remainder, `**` is exponentiation.

**Comparison:** Always `===` and `!==`. `>` `<` `>=` `<=` for ordering.

**Logical:** `&&` (AND, returns first falsy or last), `||` (OR, returns first truthy or last), `!` (NOT, flips).

**Ternary:** `condition ? valueIfTrue : valueIfFalse` — inline if/else.

**Nullish coalescing:** `a ?? b` — returns `b` only if `a` is `null` or `undefined`.

**Optional chaining:** `a?.b?.c` — returns `undefined` if any part is null/undefined.

**Assignment:** `+= -= *= /= %= **=` — shorthand for update.

**Key rule:** `===` always. `??` for null/undefined defaults. `?.` for safe property access. `&&`/`||` for short-circuiting.
