Let's talk about functions first — not the syntax, just what they are.

A function is like a **burger joint**. You walk up to the counter, you give them ingredients (bun, patty, cheese), they do their thing in the kitchen, and they hand you back a burger. In programming terms:

- **Ingredients you give →** parameters
- **The kitchen work →** the code inside the function
- **The burger you get back →** the return value

```js
function makeBurger(bun, patty, cheese) {
  // kitchen work happens here
  return "Here is your " + bun + " " + patty + " " + cheese + " burger";
}
```

Now here is where it gets interesting. In JavaScript, there are **5 different ways** to write that burger joint. They all make burgers, but they behave differently in subtle ways. Let's look at each one.

---

## 1️⃣ Function Declaration

✅ This is the normal standard way.

```js
function add(a, b) {
  return a + b;
}
```

✅ **Properties:**
- Fully hoisted. You can call this function before it is declared.
- Has it's own `this` value
- Has `arguments` object

---

## 2️⃣ Function Expression

When you assign a function to a variable.

```js
const add = function(a, b) {
  return a + b;
};
```

✅ **Properties:**
- NOT hoisted. Behaves exactly like a normal variable.
- Has it's own `this` value
- Has `arguments` object

---

## 3️⃣ Arrow Function

Before arrow functions existed, every function created its own `this`. That might sound fine, but it caused a massive problem with callbacks.

Imagine you had an object with a method that used a callback:

```js
const timer = {
  seconds: 0,
  start: function() {
    setInterval(function() {
      // ❌ this.seconds is undefined here!
      // Because this function has its OWN this (window/undefined)
      this.seconds++;
    }, 1000);
  }
};
```

Developers had to use ugly workarounds like `var self = this` or `.bind(this)` just to keep a reference to the original `this`. It was the #1 source of bugs in JavaScript codebases.

Arrow functions were added to solve exactly this problem. **Arrow functions do NOT have their own `this`.** They inherit `this` from the surrounding scope — wherever they were written, not wherever they were called.

```js
const timer = {
  seconds: 0,
  start: function() {
    setInterval(() => {
      // ✅ this.seconds works! Arrow function uses the outer `this`
      this.seconds++;
    }, 1000);
  }
};
```

Syntax:

```js
const add = (a, b) => {
  return a + b;
};

// Even shorter for single return line
const add = (a, b) => a + b;
```

✅ **Properties:**
- NOT hoisted
- ❌ **DOES NOT HAVE ITS OWN `this`**
- ❌ **DOES NOT HAVE `arguments` object**
- Inherits `this` from surrounding scope

⚠️ This is the single most important difference. 90% of JavaScript bugs come from people not understanding this.

---

## 4️⃣ Default Parameters

What happens if you call a function without passing all its arguments?

```js
function greet(name) {
  return `Hello ${name}`;
}

greet(); // "Hello undefined"
```

`undefined` shows up. That is usually not what you want. Before default parameters, you had to write manual checks inside the function:

```js
function greet(name) {
  name = name || "stranger";  // old workaround
  return `Hello ${name}`;
}
```

Default parameters let you set fallback values directly in the function signature — cleaner, more readable, no manual checks:

```js
function greet(name = "stranger") {
  return `Hello ${name}`;
}

greet(); // ✅ "Hello stranger"
greet("Arjun"); // ✅ "Hello Arjun"
```

---

## 5️⃣ Rest Parameters

What if your function needs to accept any number of arguments — like `Math.max(1, 5, 3, 9, 2)` or `sum(1, 2, 3, 4, 5)`? You cannot know ahead of time how many will be passed.

Before rest parameters, you had to use the special `arguments` object:

```js
function sum() {
  // arguments is NOT a real array. It is array-like.
  // You cannot use .map() or .reduce() directly.
  let total = 0;
  for (let i = 0; i < arguments.length; i++) {
    total += arguments[i];
  }
  return total;
}
```

But `arguments` is not a real array. No `.map()`, `.filter()`, `.reduce()`. No array methods. You had to manually convert it first.

Rest parameters solve this. The `...` syntax collects all remaining arguments into a **real** array:

```js
function sum(...nums) {
  return nums.reduce((a, b) => a + b, 0);
}

sum(1); // 1
sum(1, 2); // 3
sum(1, 2, 3, 4); // 10
```

✅ This is an actual array. You can use `map`, `filter`, `reduce`, everything on it.

## 📋 Side by side comparison

| Type | Hoisted? | Own `this`? | `arguments`? |
|---|---|---|---|
| Function Declaration | ✅ Yes | ✅ Yes | ✅ Yes |
| Function Expression | ❌ No | ✅ Yes | ✅ Yes |
| Arrow Function | ❌ No | ❌ No | ❌ No |

## 🎯 Interview Ready Answer

> "There are multiple ways to create functions in JavaScript. Function declarations are fully hoisted and can be called before definition. Function expressions are not hoisted. Arrow functions, introduced in ES6, do not have their own `this` binding and inherit it from the surrounding lexical scope. Default parameters allow setting fallback values for arguments, while rest parameters allow a function to accept any number of arguments as an array."

That is the full correct answer.
