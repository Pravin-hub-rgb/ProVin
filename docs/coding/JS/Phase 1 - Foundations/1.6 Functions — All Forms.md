In the last topic, you learned about type coercion — how JavaScript automatically converts values between types. But the real building blocks of any JavaScript program are functions. Almost everything you do in JavaScript involves calling a function or creating one.

So what exactly is a function? And why are there so many different ways to write one?

---

## The Burger Joint Analogy

Imagine a burger joint. You walk up to the counter, you give them ingredients (bun, patty, cheese), they do their thing in the kitchen, and they hand you back a burger.

- **Ingredients you give** → parameters (inputs)
- **The kitchen work** → the code inside the function
- **The burger you get back** → the return value (output)

```js
function makeBurger(bun, patty, cheese) {
  // kitchen work happens here
  return "Here is your " + bun + " " + patty + " " + cheese + " burger";
}
```

Now here's where it gets interesting. In JavaScript, there are **5 different ways** to write that burger joint. They all make burgers, but they behave differently in subtle ways.

---

## ✅ What is a function?

> **A function is a reusable block of code that takes inputs, performs an action, and returns an output.**

Let's unpack that.

**"Reusable block of code"** — you write it once, use it many times. Instead of writing the same logic over and over, you put it in a function and call it whenever you need it.

**"Takes inputs"** — functions accept parameters (also called arguments). These are the ingredients you pass in. A function can take zero, one, or many parameters.

**"Performs an action"** — the function body contains the code that runs when the function is called. This is the kitchen work.

**"Returns an output"** — functions can return a value using the `return` keyword. If there's no `return`, the function returns `undefined` by default.

---

## 1️⃣ Function Declaration

This is the normal standard way.

```js
function add(a, b) {
  return a + b;
}
```

**Properties:**
- ✅ Fully hoisted — you can call this function before it's declared
- ✅ Has its own `this` value
- ✅ Has `arguments` object

Because function declarations are fully hoisted, this works:

```js
const result = add(5, 3); // ✅ Works even before the declaration

function add(a, b) {
  return a + b;
}
```

---

## 2️⃣ Function Expression

When you assign a function to a variable.

```js
const add = function(a, b) {
  return a + b;
};
```

**Properties:**
- ❌ NOT hoisted — behaves like a normal variable
- ✅ Has its own `this` value
- ✅ Has `arguments` object

```js
const result = add(5, 3); // ❌ Error if called before declaration

const add = function(a, b) {
  return a + b;
};
```

The function itself has no name — it's "anonymous." The variable name `add` is how you refer to it.

---

## 3️⃣ Arrow Function

Arrow functions were introduced in ES6 (2015) to solve a specific problem: the `this` keyword.

Before arrow functions, every function created its own `this` value. This caused bugs when you had a function inside another function:

```js
const timer = {
  seconds: 0,
  start: function() {
    setInterval(function() {
      // ❌ this.seconds is undefined here!
      // Because this function has its OWN this (window/undefined)
      this.seconds++;
    }, 1000);
  }
};
```

Developers had to use ugly workarounds like `var self = this` or `.bind(this)` just to keep a reference to the original `this`. It was the #1 source of bugs in JavaScript codebases.

Arrow functions were added to solve exactly this problem. **Arrow functions do NOT have their own `this`.** They inherit `this` from the surrounding scope — wherever they were written, not wherever they were called.

```js
const timer = {
  seconds: 0,
  start: function() {
    setInterval(() => {
      // ✅ this.seconds works! Arrow function uses the outer `this`
      this.seconds++;
    }, 1000);
  }
};
```

Syntax:

```js
const add = (a, b) => {
  return a + b;
};

// Even shorter for single return line
const add = (a, b) => a + b;
```

**Properties:**
- ❌ NOT hoisted
- ❌ Does NOT have its own `this`
- ❌ Does NOT have `arguments` object
- ✅ Inherits `this` from surrounding scope

This is the single most important difference. 90% of JavaScript bugs come from people not understanding this.

---

## 4️⃣ Default Parameters

What happens if you call a function without passing all its arguments?

```js
function greet(name) {
  return `Hello ${name}`;
}

greet(); // "Hello undefined"
```

`undefined` shows up. That's usually not what you want. Before default parameters, you had to write manual checks inside the function:

```js
function greet(name) {
  name = name || "stranger";  // old workaround
  return `Hello ${name}`;
}
```

Default parameters let you set fallback values directly in the function signature — cleaner, more readable, no manual checks:

```js
function greet(name = "stranger") {
  return `Hello ${name}`;
}

greet(); // ✅ "Hello stranger"
greet("Arjun"); // ✅ "Hello Arjun"
```

---

## 5️⃣ Rest Parameters

What if your function needs to accept any number of arguments — like `Math.max(1, 5, 3, 9, 2)` or `sum(1, 2, 3, 4, 5)`? You can't know ahead of time how many will be passed.

Before rest parameters, you had to use the special `arguments` object:

```js
function sum() {
  // arguments is NOT a real array. It is array-like.
  // You cannot use .map() or .reduce() directly.
  let total = 0;
  for (let i = 0; i < arguments.length; i++) {
    total += arguments[i];
  }
  return total;
}
```

But `arguments` is not a real array. No `.map()`, `.filter()`, `.reduce()`. No array methods. You had to manually convert it first.

Rest parameters solve this. The `...` syntax collects all remaining arguments into a **real** array:

```js
function sum(...nums) {
  return nums.reduce((a, b) => a + b, 0);
}

sum(1); // 1
sum(1, 2); // 3
sum(1, 2, 3, 4); // 10
```

This is an actual array. You can use `map`, `filter`, `reduce`, everything on it.

## ✅ Side by side comparison

| Type | Hoisted? | Own `this`? | `arguments`? |
|---|---|---|---|
| Function Declaration | ✅ Yes | ✅ Yes | ✅ Yes |
| Function Expression | ❌ No | ✅ Yes | ✅ Yes |
| Arrow Function | ❌ No | ❌ No | ❌ No |

---

## ✅ What It Is NOT

- **A function is NOT the same as a function call.** `add` is the function. `add()` is calling the function. Without the parentheses, you're just referring to the function itself, not executing it.

- **Arrow functions are NOT just shorter syntax.** They also differ in `this` binding and lack of `arguments`. You can't blindly replace all function expressions with arrow functions — especially in object methods or event handlers where you need the function's own `this`.

- **Default parameters are NOT the same as checking inside the function.** Default parameters only apply when the argument is `undefined`. They don't apply for `null` or other falsy values. `greet(null)` would still pass `null`, not the default.

- **Rest parameters are NOT the same as the `arguments` object.** Rest parameters are a real array. `arguments` is array-like but not a real array. Rest parameters also only collect arguments that weren't already captured by named parameters.

## 🧠 Interview Questions

> ❓ What is the difference between a function declaration and a function expression?
> Function declarations are hoisted — you can call them before they appear in code. Function expressions are not hoisted — they follow the rules of the variable keyword used.

> ❓ What is an arrow function? How is it different from a regular function?
> Arrow functions are a shorter syntax for writing functions. They do not have their own `this` — they inherit it from the surrounding scope. They also don't have the `arguments` object.

> ❓ What are default parameters?
> Default parameters allow you to set fallback values for function parameters that are `undefined`. They're specified in the function signature: `function greet(name = "stranger")`.

> ❓ What are rest parameters?
> Rest parameters use `...` syntax to collect all remaining arguments into a real array. They allow functions to accept any number of arguments.

> ❓ Can you use arrow functions for all functions?
> No. Arrow functions don't have their own `this`, so they can't be used as object methods that need to access the object via `this`. They also can't be used as constructors with `new`.
