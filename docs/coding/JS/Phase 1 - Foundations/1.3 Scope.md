In the last topic, you learned about variables — the boxes where you store values. You know how to create them with `const`, `let`, and `var`. But here's a question: once you create a variable, where can you actually use it? Can you access it from anywhere in your code?

The answer is: it depends on **where** you created it. And that's what scope is all about.

---

## The House Analogy

Imagine a house with multiple rooms. There's the living room (global), a bedroom (function), and a closet inside the bedroom (block).

- If something is in the living room, everyone in the house can use it.
- If something is in the bedroom, only people in that bedroom can use it.
- If something is in the closet, only people inside that closet can use it.

And the most important rule: people inside the closet can see the bedroom. But people in the bedroom cannot see inside the closet.

That's exactly how scope works in JavaScript.

---

## ✅ What is scope?

> **Scope defines where a variable can be accessed in your code.**

Let's unpack that.

**"Where a variable can be accessed"** — some variables are available everywhere (global). Some are only available inside a specific function. Some are only available inside a specific block. The scope determines the boundaries.

**"In your code"** — scope is about location. It's determined by where you write the variable declaration, not by when or how you use it.

---

## ✅ The 3 types of scope you actually need

1. **Global Scope** — everywhere
2. **Function Scope** — inside a specific function
3. **Block Scope** — inside a specific `{ }` block

That is everything. There are no other scopes you need to worry about.

---

### 🌍 Global Scope

If you declare a variable outside everything — outside any function, outside any block — it becomes global.

```js
let name = "Pravin";

function show() {
  console.log(name); // ✅ Works
}

show(); // Pravin
```

Since `name` is global, everyone can access it from anywhere. Functions, blocks, nested code — all of it can see and use `name`.

**The catch:** global variables are convenient, but they're also dangerous. Any part of your code can change a global variable. That makes bugs hard to track down. In real projects, you should almost never create global variables.

---

### 🏠 Function Scope

A variable declared inside a function belongs only to that function.

```js
function test() {
  let age = 20;
  console.log(age); // ✅ Works
}

test();

console.log(age); // ❌ ERROR. Does not exist.
```

`age` only exists inside `test()`. Once `test()` finishes running, `age` is gone. No code outside `test()` can access it.

This is called **function scope**. Variables declared with `var` are function-scoped. Variables declared with `let` and `const` are block-scoped (more on that next).

---

### 🧱 Block Scope

A block is anything inside curly braces `{ }`. This includes `if`, `for`, `while`, or just plain `{ }`.

```js
if (true) {
  let city = "Mumbai";
}

console.log(city); // ❌ ERROR. Does not exist.
```

`city` only exists inside that specific block. Step outside the curly braces, and `city` disappears.

Variables declared with `let` and `const` are block-scoped. `var` is **not** block-scoped — it ignores block boundaries.

---

## ✅ The difference between var, let, and const

This is where 90% of confusion comes from.

### `var` → Function Scoped

```js
function demo() {
  if (true) {
    var x = 10;
  }

  console.log(x); // ✅ Works!
}
```

Even though `x` was declared inside `if`, it's available outside the block. Why? Because `var` completely ignores block scope. It only respects function scope. So as long as it's inside the same function, it works.

### `let` and `const` → Block Scoped

```js
function demo() {
  if (true) {
    let y = 20;
  }

  console.log(y); // ❌ ERROR. Does not exist.
}
```

`let` stays inside the block. `const` behaves exactly the same way for scope.

---

## 🚨 The Golden Rule of Scope

This rule will never break. Ever.

> **Inner scope can always access outer scope.**
> **Outer scope can never access inner scope.**

### Example 1: Inner can see Outer

```js
if (true) {
  let a = 5;

  if (true) {
    console.log(a); // ✅ Works — inner can see outer
  }
}
```

The inner block can access variables from the outer block.

### Example 2: Outer cannot see Inner

```js
if (true) {
  let b = 10;
}

console.log(b); // ❌ ERROR — outer cannot see inner
```

The outer scope cannot access variables declared inside the inner scope.

---

## ✅ What It Is NOT

- **Scope is NOT the same as hoisting.** Scope determines where a variable can be accessed. Hoisting determines when a variable is created. They're related but different concepts. We'll cover hoisting in the next topic.

- **`var` is NOT block-scoped.** This is the most common misconception. `var` is function-scoped. It ignores `if`, `for`, and `while` blocks. Only `let` and `const` respect block boundaries.

- **Global scope is NOT always bad.** For small scripts and learning, global variables are fine. For real applications, they create problems because any code can accidentally change them. But understanding global scope is still essential.

- **Scope is NOT determined at runtime.** Scope is determined when your code is written — at compile time, not when it runs. This is called lexical scoping. Where you write the variable determines where it can be accessed.

---

## 🧠 Interview Questions

> ❓ What is scope?
> Scope defines where a variable can be accessed in your code. JavaScript has global, function, and block scope.

> ❓ What is the difference between var, let, and const in terms of scope?
> var is function-scoped — it ignores block boundaries. let and const are block-scoped — they respect `{ }` boundaries.

> ❓ Can inner scope access outer variables?
> Yes. Inner scopes can always access variables from outer scopes.

> ❓ Can outer scope access inner variables?
> No. Outer scopes cannot access variables declared inside inner scopes.

> ❓ What is lexical scoping?
> Scope is determined by where variables are declared in the source code, not by where functions are called. The location of the declaration determines the scope.

**In Your Own Words**

1. You have a house with a living room, a bedroom, and a closet inside the bedroom. Someone in the closet can see the bedroom, but someone in the bedroom cannot see inside the closet. How is this like JavaScript scope?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The living room is global scope — everyone can access it. The bedroom is function scope — only code inside that function can access it. The closet is block scope — only code inside that block can access it. The rule "inner can see outer, but outer cannot see inner" works exactly the same: a variable declared in the block (closet) can be seen by the function (bedroom), but a variable declared in the function cannot be seen by the block. `var` is like a box that leaks out of the closet into the bedroom.

</details>

2. What will this code print? Why?

```js
let a = 10;

function example() {
  let b = 20;
  if (true) {
    let c = 30;
    console.log(a);
    console.log(b);
    console.log(c);
  }
  console.log(c);
}
```

<details>
<summary>Show Answer</summary>

**Sample Answer:** Inside the `if` block: `a` prints `10` (global), `b` prints `20` (function scope, inner can see outer), `c` prints `30` (block scope). Outside the `if` block but still inside `example()`: `console.log(c)` throws a ReferenceError because `c` is block-scoped and doesn't exist outside the `if` block. But `a` and `b` would work if logged there.

</details>

3. Why is `var` considered problematic for scope? Give a code example.

<details>
<summary>Show Answer</summary>

**Sample Answer:** `var` ignores block boundaries. This means a variable declared inside an `if` block leaks outside it:

```js
if (true) {
  var x = 10;
}
console.log(x); // 10 — works, but shouldn't!
```

With `let` or `const`, this would throw an error. `var` makes it easy to accidentally use a variable that should have been contained. This leads to bugs where a variable from one block overwrites something in another.

</details>

4. You declare a variable with `let` inside a `for` loop. Can you access it after the loop finishes? What if you used `var`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** With `let`: no, the variable is block-scoped to the `for` loop and doesn't exist outside it. With `var`: yes, because `var` is function-scoped and ignores the block. The `var` variable "leaks" out of the loop and is accessible after it. This is one reason `let` is preferred — it keeps loop variables contained.

</details>

5. In your own words, explain what "inner scope can access outer scope, but outer cannot access inner" means.

<details>
<summary>Show Answer</summary>

**Sample Answer:** It means scope works like a one-way street. A nested function or block can read and use variables from its parent scope. But the parent scope cannot reach into the nested scope and access its variables. A global variable can be used anywhere. A function variable can be used inside that function and any nested blocks. But a block variable is trapped inside that block. This creates a hierarchy of access where children inherit from parents, not the other way around.

</details>
