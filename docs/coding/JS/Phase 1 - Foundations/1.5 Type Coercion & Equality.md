This is the thing that makes everyone hate JavaScript. But it's actually very simple.

## What is Type Coercion?

Type Coercion is when JavaScript **automatically converts one type to another** before doing something with it.

This happens with `==` loose equality. It does NOT happen with `===` strict equality.

---

## ✅ The two equality operators

| Operator | What it does |
|---|---|
| `==` | Loose Equality. First converts both sides to the same type. Then compares. |
| `===` | Strict Equality. No conversion. Compares exactly as they are. |

---

### Example 1: String and Number

```js
"5" == 5   // ✅ true
"5" === 5  // ❌ false
```

✅ `==` converts the string "5" to actual number 5. Then they are equal.
❌ `===` does no conversion. String is not equal to number.

---

### Example 2: 0 and false

```js
0 == false   // ✅ true
0 === false  // ❌ false
```

✅ `==` converts both to number. Both become 0. So equal.
❌ `===` number is not equal to boolean.

---

### Example 3: The special case

```js
null == undefined  // ✅ true
null === undefined // ❌ false
```

This is the only special rule in the entire language.

Here's why it's special: In Examples 1 and 2, `==` works by **coercing** one side to match the other's type — `"5"` becomes `5`, `false` becomes `0`. That's the normal coercion pattern.

But `null` and `undefined` break that pattern. They don't coerce to anything:

```js
null == 0       // ❌ false  (null does NOT become 0)
null == ""      // ❌ false
null == false   // ❌ false
null == null    // ✅ true
undefined == 0  // ❌ false
```

The spec has a hardcoded rule: `null` and `undefined` are only equal to each other and to themselves. Nothing else. That's what makes this "special" — it's the one case where `==` doesn't follow the normal coercion algorithm.

## 🚨 The Golden Rule

✅ **Always use `===`**. Always. No exceptions.

Never use `==` in real code. Ever.

You will only ever need to know about `==` for interviews.

## 📋 Summary

| Code | Result |
|---|---|
| `"5" == 5` | true |
| `"5" === 5` | false |
| `0 == false` | true |
| `0 === false` | false |
| `null == undefined` | true |
| `null === undefined` | false |
| `true == 1` | true |
| `true === 1` | false |

## 🎯 Interview Ready Answer

> "`==` is loose equality operator which performs type coercion before comparing values. `===` is strict equality operator which compares both value and type without any conversion. It is best practice to always use `===` to avoid unexpected behaviour from coercion. The only exception is that `null == undefined` evaluates to true."

That is the full correct answer.
