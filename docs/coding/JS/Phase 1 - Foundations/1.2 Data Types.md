In the last topic, you learned about variables — the boxes where you store data. You know how to make a box with `const` or `let` and put a value inside. But what kinds of values can you actually put in those boxes?

A number? Text? A list of things? A yes/no value? All of the above. JavaScript understands different kinds of values, and they're called **data types**.

---

## The Label Maker Analogy

Imagine you have a label maker. You can print different kinds of labels:
- A number label: "42", "99", "3.14"
- A text label: "Hello", "Mumbai", "John Doe"
- A yes/no sticker: "ACTIVE", "INACTIVE"
- An empty label with nothing on it

Each label is a different *type* of thing. You can't stick a number and expect it to behave like text. JavaScript is the same — each value has a type, and that type determines what you can do with it.

---

## ✅ What is a data type?

> **A data type defines what kind of value a variable holds and what operations can be performed on it.**

Let's unpack that.

**"What kind of value"** — is it a number? Text? True/false? A list? The type tells JavaScript what the value is.

**"What operations can be performed"** — you can add numbers together with `+`, but you can't "add" a true/false value. You can uppercase text with `.toUpperCase()`, but you can't uppercase a number. The type determines what's possible.

---

## ✅ The 7 primitive types

There are only 7 primitive types in JavaScript. That's it. Everything else is just an object.

| Type | What it is | Example |
|---|---|---|
| `string` | Text. Any words, characters, or symbols. | `"hello"`, `'Mumbai'` |
| `number` | Any number — whole, decimal, negative. | `22`, `3.14`, `-5` |
| `boolean` | Only two possible values. True or false. | `true`, `false` |
| `undefined` | A variable that exists but has no value yet. | `undefined` |
| `null` | Intentionally empty. "Nothing here." | `null` |
| `symbol` | Unique identifiers that can never collide. Rarely used. | `Symbol()` |
| `bigint` | For numbers larger than 9 quadrillion. Rarely used. | `123n` |

That is everything.

99% of the time you will only ever use the first 5. And 90% of the time you will only use the first 3: `string`, `number`, `boolean`.

---

## ✅ The first 5 you'll actually use

### string — Text

A string is any text wrapped in quotes. Single quotes, double quotes, or backticks — all work.

```js
const name = "Arjun";
const city = 'Mumbai';
const message = `Hello, ${name}!`; // Template literal with backtick
```

You use strings for names, messages, descriptions, URLs, everything that's text.

### number — Numbers

Any number, whole or decimal, positive or negative.

```js
const age = 22;
const price = 99.99;
const temperature = -5;
```

You use numbers for ages, prices, counts, distances, everything that's numeric.

### boolean — True or False

Only two possible values: `true` or `false`.

```js
const isLoggedIn = true;
const isAdmin = false;
```

You use booleans for flags, conditions, toggles, anything that represents a yes/no decision.

### undefined — Nothing Assigned Yet

When you create a variable but don't put a value in it, JavaScript automatically gives it `undefined`.

```js
let something;
console.log(something); // undefined
```

Think of `undefined` as JavaScript saying: "This box exists, but nobody put anything in it yet."

### null — Intentionally Empty

When you want to say "this variable exists, but it has nothing useful right now," you set it to `null`.

```js
const user = null; // No user logged in yet
```

Think of `null` as JavaScript saying: "This box exists, and someone deliberately put 'nothing' inside it."

---

## 🚨 The most important rule in JavaScript

> **Variables do not have types. Values have types.**

The box does not care what you put inside it. You can put a string in there, then take it out and put a number in there later. JavaScript does not care at all.

```js
let something = "Hello"; // something holds a string
something = 42;          // now it holds a number — perfectly fine
something = true;        // now it holds a boolean — also fine
```

This is called **dynamic typing**. JavaScript figures out the type from the value, not from the variable. Some languages (like Java or C++) force you to declare the type upfront and never change it. JavaScript is more flexible — but you need to keep track of what type your values are, or you'll get surprises.

---

## ✅ What about objects and arrays?

> **Anything that is not one of those 7 primitive types is an object.**

Objects (`{}`) and arrays (`[]`) are not primitive types. They're more complex structures that can hold multiple values. We'll cover them properly in later topics.

For now, just remember: if it's not one of the 7 primitives from the table above, it's an object.

---

## ✅ What It Is NOT

- **Data types are NOT the same as variables.** Variables are the boxes. Data types are the kinds of things you put inside them. The box doesn't have a type — the thing inside does.

- **`undefined` is NOT the same as `null`.** `undefined` means "never had a value." `null` means "intentionally set to nothing." They're different concepts. `undefined` is JavaScript's default. `null` is your choice.

- **`number` is NOT the same as `bigint`.** Regular numbers can safely represent values up to 9 quadrillion. Beyond that, you lose precision. `bigint` handles arbitrarily large numbers but can't have decimals. Unless you're doing cryptography or dealing with huge financial numbers, you'll never need `bigint`.

- **`symbol` is NOT a string.** Symbols look like strings but they're unique. Every time you create a Symbol, it's different from every other Symbol, even if they have the same description. They're used for special internal purposes in libraries, not for everyday code.

## 🧠 Interview Questions

> ❓ How many primitive types are there in JavaScript?
> 7: string, number, boolean, undefined, null, symbol, bigint.

> ❓ What is the difference between null and undefined?
> undefined means a variable has been declared but not assigned a value. null is an intentional assignment that represents "no value."

> ❓ What does it mean that JavaScript is "dynamically typed"?
> Variables don't have fixed types. The type is determined by the value currently stored in the variable. A variable can hold a string, then a number, then an object without any errors.

> ❓ What is typeof used for?
> It's an operator that returns a string indicating the type of a value. Example: `typeof 42` returns `"number"`, `typeof "hello"` returns `"string"`.

> ❓ Is an array a primitive type?
> No. Arrays are objects. `typeof []` returns `"object"`. Arrays are a special kind of object designed for ordered lists.

**In Your Own Words**

1. You're packing boxes for a move. You have a box labeled "Kitchen" that currently holds plates. Later you change your mind and put books in it instead. Is this like JavaScript or a statically typed language?

<details>
<summary>Show Answer</summary>

**Sample Answer:** This is like JavaScript because the box (variable) doesn't care what you put inside it. In a statically typed language, a "Kitchen" box would only accept kitchen items forever. In JavaScript, you can put plates, then books, then clothes — the box doesn't care. The type belongs to the items (values), not the box (variable).

</details>

2. What's the difference between a box that was never opened (never had anything put in it) and a box that was intentionally left empty? Map each to a JavaScript primitive.

<details>
<summary>Show Answer</summary>

**Sample Answer:** A box that was never opened is `undefined` — the box exists, but nobody ever put anything in it. JavaScript does this automatically. A box that was intentionally left empty is `null` — someone deliberately decided the box should hold nothing. The difference is intent: `undefined` is the default, `null` is a choice.

</details>

3. What will `typeof` return for each of these: `"hello"`, `42`, `true`, `undefined`, `null`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `typeof "hello"` returns `"string"`. `typeof 42` returns `"number"`. `typeof true` returns `"boolean"`. `typeof undefined` returns `"undefined"`. `typeof null` returns `"object"` — this is a famous bug from 1996 that can never be fixed because too much existing code depends on it. It should return `"null"` but it doesn't.

</details>

4. You have a variable that starts as a number, then becomes a string, then becomes a boolean. Is this allowed in JavaScript? Why or why not?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Yes, this is allowed because JavaScript is dynamically typed. Variables don't have fixed types — values do. You can reassign a variable to any type at any time. This flexibility is useful but can also lead to bugs if you're not careful. It's why `const` is recommended — if you never reassign, you never accidentally change types.

</details>

5. How would you check the type of a value at runtime? Why would you need to do this?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use `typeof`. Example: `typeof userInput === "number"`. You'd need this when handling user input, API responses, or any situation where you're not sure what type of data you're dealing with. For example, a function that accepts either a string or an array might check the type to decide how to process the data.

</details>
