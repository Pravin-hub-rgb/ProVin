## What This Topic Is Asking (Simple Terms)

Conditionals let your code make decisions ("if this, do that"). Loops let your code repeat ("do this N times"). Together, they're the control flow — the brain of your program.

---

## Conditionals

### `if` / `else if` / `else`

```js
const age = 18;

if (age >= 18) {
  console.log("Adult");
} else if (age >= 13) {
  console.log("Teenager");
} else {
  console.log("Child");
}
```

### `switch` — when you're comparing one value against many options

```js
const day = "Monday";

switch (day) {
  case "Monday":
    console.log("Start of the week");
    break; // without break, it "falls through" to the next case
  case "Friday":
    console.log("Almost weekend");
    break;
  case "Saturday":
  case "Sunday":
    console.log("Weekend!"); // multiple cases, same result
    break;
  default:
    console.log("Midweek");
}
```

**When to use `switch` vs `if/else`:** Use `switch` when you're comparing one variable against many discrete values. Use `if/else` when you have complex conditions (ranges, multiple variables).

## Loops

### `for` loop — when you know how many times to repeat

```js
for (let i = 0; i < 5; i++) {
  console.log(i); // 0, 1, 2, 3, 4
}

// Counting down
for (let i = 5; i > 0; i--) {
  console.log(i); // 5, 4, 3, 2, 1
}

// Step by 2
for (let i = 0; i < 10; i += 2) {
  console.log(i); // 0, 2, 4, 6, 8
}
```

### `while` loop — when you don't know how many times, just "keep going while condition is true"

```js
let count = 0;
while (count < 3) {
  console.log(count); // 0, 1, 2
  count++;
}

// Danger: infinite loop if condition never becomes false
// while (true) { /* never stops */ }
```

### `do...while` — runs at least once, then checks

```js
let i = 0;
do {
  console.log(i); // 0 (runs once even though condition is false)
  i++;
} while (i < 0);
```

### `for...of` — iterate over values of an iterable (arrays, strings, Sets, Maps)

```js
const fruits = ["apple", "banana", "cherry"];
for (const fruit of fruits) {
  console.log(fruit); // "apple", "banana", "cherry"
}

// Works on strings too
for (const char of "hello") {
  console.log(char); // "h", "e", "l", "l", "o"
}
```

### `for...in` — iterate over keys of an object

```js
const user = { name: "Vin", age: 25, city: "Delhi" };
for (const key in user) {
  console.log(key, user[key]); // "name Vin", "age 25", "city Delhi"
}
```

**Warning:** `for...in` iterates over *all enumerable properties*, including inherited ones. Use `for...of` for arrays, `for...in` for objects. Or better, use `Object.keys()`, `Object.values()`, `Object.entries()`.

---

## Loop Control

### `break` — exit the loop immediately

```js
for (let i = 0; i < 10; i++) {
  if (i === 5) break;
  console.log(i); // 0, 1, 2, 3, 4
}
```

### `continue` — skip the current iteration, move to next

```js
for (let i = 0; i < 5; i++) {
  if (i === 2) continue;
  console.log(i); // 0, 1, 3, 4
}
```

## Common Mistakes

- **Infinite loops** — `while (true)` without a break, or `for` loop where the condition never becomes false. Your browser tab freezes.
- **Off-by-one errors** — `for (let i = 0; i <= 5; i++)` runs 6 times (0 through 5), not 5. Use `<` when you want "up to but not including."
- **Modifying the array while iterating** — `for (let i = 0; i < arr.length; i++) { arr.splice(i, 1); }` skips elements. Iterate backwards or use `filter`.
- **Using `for...in` on arrays** — it iterates over indices as strings (`"0"`, `"1"`, ...), and includes any enumerable properties. Use `for...of` or `forEach` for arrays.
- **Forgetting `break` in `switch`** — without `break`, cases "fall through" to the next one. Always add `break` (or `return`).

---

## What This Topic Is NOT

- ❌ Loops are not the same as **recursion** — recursion is a function calling itself, loops are iterative.
- ❌ `for...of` is not the same as `for...in` — `of` gives values, `in` gives keys.
- ❌ `break` is not the same as `return` — `break` exits the loop, `return` exits the function.
- ❌ `switch` is not the same as `if/else` — `switch` compares one value against many cases, `if/else` handles complex conditions.

## In Your Own Words

1. When would you use `for...of` vs `for...in`? Give an example of each.

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use `for...of` to iterate over values of an iterable (arrays, strings, Sets, Maps): `for (const fruit of fruits) console.log(fruit)`. Use `for...in` to iterate over keys of an object: `for (const key in user) console.log(key, user[key])`. Don't use `for...in` on arrays — it iterates indices as strings and includes inherited properties. Use `for...of` or `forEach` for arrays.

</details>

2. What's the difference between `break` and `continue`? When would you use each?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `break` exits the loop entirely — use it when you found what you were looking for (e.g., found the target in a search). `continue` skips the current iteration and moves to the next — use it to skip invalid items (e.g., skip empty strings while processing a list). `break` = "stop the whole loop." `continue` = "skip this one, keep going."

</details>

3. Why does `switch` need `break` after each case? What happens without it?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Without `break`, JavaScript "falls through" to the next case — it executes the next case's code even if the value doesn't match. Example: `case "Monday": console.log("Monday"); case "Tuesday": console.log("Tuesday");` — if day is "Monday", it prints both "Monday" and "Tuesday". `break` stops the fall-through. (Sometimes fall-through is intentional for grouping cases, like `case "Saturday": case "Sunday": console.log("Weekend");`.)

</details>

## Cheat Sheet (Quick Recall)

**if/else:** `if (cond) { } else if (cond2) { } else { }`

**switch:** `switch (x) { case 1: ...; break; default: ... }` — needs `break` after each case.

**for:** `for (let i = 0; i < n; i++) { }` — when you know the count.

**while:** `while (cond) { }` — when you don't know the count, just "keep going while true."

**for...of:** `for (const v of arr) { }` — values of an iterable.

**for...in:** `for (const k in obj) { }` — keys of an object.

**break:** exit loop. **continue:** skip iteration.

**Key rule:** `for...of` for arrays, `for...in` for objects. Always `break` in switch. Watch for infinite loops.
