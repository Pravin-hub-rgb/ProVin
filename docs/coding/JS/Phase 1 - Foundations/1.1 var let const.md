# 1.1 var / let / const

Okay let's start with the absolute basics. This is the first thing you need to get right. 

Every single interview will ask this. And 90% of people still answer it wrong.

---

## The 3 ways to declare variables in JS

Before 2015 there was only `var`. Then ES6 came and gave us `let` and `const`. Now you will almost never use `var` in modern code. But you still need to understand it, because everyone will ask you the difference.

---

### ✅ const

This should be your **DEFAULT**. Always use `const` first, unless you know for sure you are going to reassign the variable later.

`const` means:
- You CANNOT reassign it
- It is block scoped
- It does NOT get hoisted (well technically it does, but you can't access it before declaration)

```js
const name = "Arjun";

name = "Rahul"; // ❌ ERROR: Assignment to constant variable.
```

> Important note: `const` does NOT make objects or arrays immutable. It only stops reassignment. You can still mutate values inside.

```js
const user = { age: 22 };

user.age = 23; // ✅ This is totally allowed. This is mutation, not reassignment.

user = {}; // ❌ This is reassignment, this will throw error.
```

---

### ✅ let

Use `let` only when you know you will need to reassign the variable later. Most common example: counters.

`let` means:
- You CAN reassign it
- It is block scoped
- Cannot be re-declared in same scope

```js
let count = 0;

count = count + 1; // ✅ Perfectly fine, this is what let is for
```

---

### ❌ var

This is old school. Don't use this in new code. But memorise this for interviews:

`var` means:
- You CAN reassign it
- It is FUNCTION scoped (NOT block scoped)
- Gets hoisted and initialized as undefined
- Can be re-declared multiple times

```js
var x = 1;
var x = 2; // ✅ No error. This is terrible.
```

---

## The most important difference: SCOPE

This is what everyone actually wants to hear in the interview.

| Declaration | Scope |
|---|---|
| `const` | Block scoped |
| `let` | Block scoped |
| `var` | Function scoped |

### What is block scope?

Anything inside curly braces `{ }` is a block. `let` and `const` only exist inside that block. `var` leaks out.

```js
if (true) {
  const a = 10;
  let b = 20;
  var c = 30;
}

console.log(a); // ❌ ReferenceError: a is not defined
console.log(b); // ❌ ReferenceError: b is not defined
console.log(c); // ✅ 30 — var leaked out of the if block!
```

This is the single biggest reason `var` is broken.

---

## The classic interview example

This loop question is asked in literally every junior interview.

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
```

What does this print?

It prints `3, 3, 3`. Not `0, 1, 2`.

Why? Because `var i` is the same single variable for all 3 loop iterations. By the time the timeout runs after 100ms, the loop has already finished and `i` is already 3.

If you change it to `let i`:

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
```

Now it prints `0, 1, 2`. Correctly.

Because `let` creates a new separate `i` variable for every single iteration of the loop. Each timeout gets its own copy.

---

## Summary Rule

1.  **Always use `const` by default**
2.  Only use `let` if you definitely need to reassign
3.  **Never use `var` in 2025+**

That's it. That's all you actually need to write good code. For interview you need all the details above.

---

> 📝 Interview Answer Cheat Sheet:
> 
> What's the difference between var let and const?
> 
> var is function scoped, gets hoisted to undefined, can be re-declared and reassigned.
> 
> let is block scoped, can be reassigned but not re-declared.
> 
> const is block scoped, can neither be re-declared nor reassigned.
