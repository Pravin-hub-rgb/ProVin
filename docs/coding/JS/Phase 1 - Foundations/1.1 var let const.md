In the last topic, you learned that JavaScript is the delivery truck that carries data around. But where do you actually put that data while your code is running? You need somewhere to store it — a place to keep a user's name, their age, the items in their cart, the number of likes on a post.

That's what variables are for. And this is the first thing every interview will ask you about. 90% of people still get it wrong.

---

## The Box Analogy

Imagine you're moving to a new apartment. You have a bunch of items — books, clothes, kitchen stuff. You need boxes to put them in. You label each box so you know what's inside: "Books", "Winter Clothes", "Kitchen".

A variable is exactly that: a box. You put a value inside the box. You give the box a name. Later you can come back, open the box, see what value is inside. You can also take the old value out and put a new value inside.

```js
// I make a box called age. I put 22 inside it.
const age = 22;
```

The box is `age`. The value inside is `22`. The `const` keyword is the type of box we're using.

---

## ✅ What is a variable?

> **A variable is a named container that stores a value in memory.**

Let's unpack that.

**"Named container"** — it's a box with a label. You give it a name like `age`, `name`, `user`, `count`. That name is how you refer to the value later.

**"Stores a value"** — the value is the actual data. A number, a string of text, an object, an array. The box holds whatever you put inside it.

**"In memory"** — when your program runs, the computer sets aside a small piece of memory for each variable. The variable name points to that memory location. When you use the name, JavaScript looks up that memory location and gives you the value.

---

## ✅ The 3 different types of boxes

There are 3 different keywords you can use to make a variable:
1. `const`
2. `let`
3. `var`

These are not 3 different flavours. They are 3 completely different types of boxes, with completely different rules.

---

## ✅ const — The Default

This should be your DEFAULT. Always use `const` first, unless you know for sure you are going to change the value later.

> **`const` creates a variable that cannot be reassigned. It is block-scoped.**

**"Cannot be reassigned"** — once you put a value inside, you cannot put a completely different value in its place. The box is sealed.

**"Block-scoped"** — the box only exists inside the block `{ }` where it was created. Step outside those curly braces, and the box disappears.

```js
const name = "Arjun";

name = "Rahul"; // ❌ ERROR. You cannot put a new value inside this box.
```

> **Important note:**
>
> If the thing inside the box is an object or array, you can still change things INSIDE it. You just can't throw the whole thing away and put a completely different thing there.
>
> ```js
> const user = { age: 22 };
>
> user.age = 23; // ✅ This is fine. We are not changing the box. We are just changing something inside the box.
>
> user = {}; // ❌ ERROR. This would throw away the whole box and put a new one there.
> ```

Think of `const` like a glass display case at a museum. You can rearrange the items inside the case, but you can't replace the entire case with something else.

---

## ✅ let — When You Need to Change

Use `let` only when you know you will need to change the value later. Most common example: counters, accumulators, loop variables.

> **`let` creates a variable that can be reassigned. It is block-scoped.**

**"Can be reassigned"** — you can put a new value inside as many times as you want. The box is not sealed.

**"Block-scoped"** — same as `const`. The box only exists inside the block where it was created.

```js
let count = 0;

count = count + 1; // ✅ Perfectly fine. This is exactly what let is for.
```

Think of `let` like a regular cardboard box. You can take things out, put new things in, reuse it as many times as you want.

---

## ❌ var — The Old Way

This is old school. This is how everyone made variables before 2015. **You will never use this in new code.** But you still need to understand it because every interview will ask you the difference.

> **`var` creates a variable that can be reassigned. It is function-scoped, not block-scoped.**

**"Can be reassigned"** — same as `let`. You can change the value.

**"Function-scoped, not block-scoped"** — this is the key difference. `var` ignores block boundaries like `if`, `for`, `while`. It only respects function boundaries. This causes all kinds of bugs.

```js
var x = 1;
var x = 2; // ✅ No error. You can even make the exact same box twice. This is terrible.
```

Think of `var` like a box that leaks. You put it in one room, but it somehow shows up in every room of the house.

---

## 🧱 What is a block / wall?

I keep saying "inside the walls" and "block-scoped". What does that actually mean?

Any code that is inside curly braces `{ }` is inside a block. It has walls.

`if`, `for`, `while`, functions — everything that uses `{ }` creates walls.

`let` and `const` respect these walls. `var` does not care about walls at all.

```js
if (true) {
  // ✅ These are inside the walls
  const a = 10;
  let b = 20;
  var c = 30;
}

// Outside the walls now

console.log(a); // ❌ ERROR: This box does not exist out here.
console.log(b); // ❌ ERROR: This box does not exist out here.
console.log(c); // ✅ 30. var broke through the wall. It is everywhere.
```

This is the single biggest reason `var` is broken. It does not respect boundaries.

---

## ✅ What It Is NOT

- **`const` does NOT make a value immutable.** It only prevents reassignment. If the value is an object, you can still change its properties. `const` means "the box cannot be replaced," not "the contents cannot be changed."

- **`let` is NOT the same as `var`.** They both allow reassignment, but `let` is block-scoped and `var` is function-scoped. This difference causes the famous interview question bug with loops and `setTimeout`.

- **Variables do NOT have types. Values have types.** The box doesn't care what you put inside it. You can put a string, then take it out and put a number. JavaScript doesn't care. The type belongs to the value, not the variable.

---

## 🧠 Interview Questions

> ❓ What's the difference between var, let, and const?
> var is function-scoped, can be re-declared and reassigned. let is block-scoped, can be reassigned but not re-declared. const is block-scoped, can neither be re-declared nor reassigned.

> ❓ Why should you use const by default?
> Because it prevents accidental reassignment. If a variable never needs to change, making it const communicates that intent and prevents bugs. Only use let when you know the value will change.

> ❓ What happens if you try to reassign a const variable?
> JavaScript throws a TypeError. The assignment fails and your program stops (unless you catch the error).

> ❓ Can you change properties of a const object?
> Yes. const only prevents reassignment of the variable itself. The object's properties can still be modified, added, or deleted.

> ❓ What is the famous interview question about var in a loop?
> Using var in a for loop with setTimeout causes all callbacks to log the final value of i instead of each iteration's value, because var is function-scoped and creates only one variable for the entire loop.

## 🎯 Interview Ready Answer

> "Variables are named containers that store values in memory. `const` creates a block-scoped variable that cannot be reassigned — use it by default. `let` creates a block-scoped variable that can be reassigned — use it when you need to change the value. `var` creates a function-scoped variable that ignores block boundaries — avoid it in modern code."

**In Your Own Words**

1. You have a locker at the gym. You put your bag inside, close the door, and take the key. Later you come back, open the locker, and take your bag out. How is this like a variable?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The locker is the variable. The bag is the value. The locker number is the variable name. You "declare" the locker when you choose one, "assign" a value when you put your bag in, and "access" the value when you open it later. If it's a `const` locker, you can only use it once — you can't put a different bag in later. If it's a `let` locker, you can swap bags as many times as you want.

</details>

2. What's the difference between `const` and `let`? When would you use each one?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `const` creates a variable that cannot be reassigned — once you put a value in, you can't put a different value in its place. `let` creates a variable that can be reassigned as many times as you want. Use `const` by default for everything. Only use `let` when you know the value needs to change, like a counter in a loop or an accumulator.

</details>

3. Why is `var` considered bad practice in modern JavaScript?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `var` ignores block scope (if, for, while blocks). It "leaks" out of blocks and can be accessed outside them, which causes unexpected bugs. It also allows redeclaring the same variable multiple times, which can accidentally overwrite values. `let` and `const` fix both of these problems by respecting block scope and preventing redeclaration.

</details>

4. You write `const user = { name: "Arjun" }` and then `user.name = "Rahul"`. Does this work? Why or why not?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Yes, this works. `const` only prevents reassigning the variable itself — you can't do `user = { name: "Rahul" }`. But you can modify the properties of the object that `user` points to. The variable still points to the same object; only the contents of that object changed. Think of it like a house address — `const` means you can't move to a different house, but you can still rearrange the furniture inside.

</details>

5. What will this code print? Why?

```js
if (true) {
  var a = 10;
  let b = 20;
}
console.log(a);
console.log(b);
```

<details>
<summary>Show Answer</summary>

**Sample Answer:** It prints `10` and then throws a ReferenceError for `b`. `var a` is function-scoped, so it ignores the `if` block and is accessible outside it. `let b` is block-scoped, so it only exists inside the `if` block. This is the key difference between `var` and `let`/`const`.

</details>
