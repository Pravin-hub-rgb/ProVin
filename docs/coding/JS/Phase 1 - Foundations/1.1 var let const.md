## First: What even is a variable?

Before we talk about the 3 types. Let's make sure you understand what a variable actually is.

A variable is just a box.

You put a value inside the box. You give the box a name. Later you can come back, open the box, see what value is inside. You can also take the old value out and put a new value inside.

That's it. That is all a variable ever is.

```js
// I make a box called age. I put 22 inside it.
const age = 22;
```

---

## The 3 different types of boxes

There are 3 different keywords you can use to make a variable:
1.  `const`
2.  `let`
3.  `var`

These are not 3 different flavours. They are 3 completely different types of boxes, with completely different rules.

---

## ✅ const

This should be your DEFAULT. Always use `const` first, unless you know for sure you are going to change the value later.

Rules for const boxes:
✅ Once you put something inside, you cannot put a completely different thing inside
✅ The box only exists inside the walls it was created

```js
const name = "Arjun";

name = "Rahul"; // ❌ ERROR. You cannot put a new value inside this box.
```

> Important note:
>
> If the thing inside the box is an object or array, you can still change things INSIDE it. You just can't throw the whole thing away and put a completely different thing there.
>
> ```js
> const user = { age: 22 };
>
> user.age = 23; // ✅ This is fine. We are not changing the box. We are just changing something inside the box.
>
> user = {}; // ❌ ERROR. This would throw away the whole box and put a new one there.
> ```

---

## ✅ let

Use `let` only when you know you will need to change the value later. Most common example: counters.

Rules for let boxes:
✅ You CAN put a new value inside as many times as you want
✅ The box only exists inside the walls it was created

```js
let count = 0;

count = count + 1; // ✅ Perfectly fine. This is exactly what let is for.
```

---

## ❌ var

This is old school. This is how everyone made variables before 2015. **You will never use this in new code.** But you still need to understand it because everyone will ask you the difference.

Rules for var boxes:
✅ You CAN put a new value inside
❌ The box ignores walls. It leaks out everywhere

```js
var x = 1;
var x = 2; // ✅ No error. You can even make the exact same box twice. This is terrible.
```

---

## 🧱 What is a block / wall?

Okay I keep saying "inside the walls". What does that actually mean?

Any code that is inside curly braces `{ }` is inside a block. It has walls.

`if`, `for`, `while`, functions, everything that uses `{ }` creates walls.

`let` and `const` respect these walls. `var` does not care about walls at all.

```js
if (true) {
  // ✅ These are inside the walls
  const a = 10;
  let b = 20;
  var c = 30;
}

// Outside the walls now

console.log(a); // ❌ ERROR: This box does not exist out here.
console.log(b); // ❌ ERROR: This box does not exist out here.
console.log(c); // ✅ 30. var broke through the wall. It is everywhere.
```

This is the single biggest reason `var` is broken. It does not respect boundaries.

## 🚨 INTERVIEW EXAMPLE - YOU CAN SKIP THIS FOR NOW

This exact question is asked in literally every junior developer interview. You do not need to understand this right now. Come back and read this after you learn about loops and setTimeout.

This is the most famous JavaScript interview question ever asked:

> What will this code print?

Okay this is the trick. This is the part that 99% of people miss.

✅ **YOU ARE NOT LOGGING INSIDE THE LOOP.**

You are not running `console.log(i)` right now. You are **giving setTimeout a piece of paper that says "run this function later".**

The loop finishes. And then much later, all those pieces of paper get run.

```js
for (var i = 0; i < 3; i++) {
  // ❌ This does NOT run now
  // ✅ This just says: "remember to run this after 100ms"
  setTimeout(() => console.log(i), 100);
}
```

✅ This prints:
```
3
3
3
```

❌ It does NOT print `0, 1, 2`.

---

### ✅ Step by step exactly what happens:

1.  `var i` creates ONE SINGLE BOX.
2.  Loop runs first time: `i = 0`. You hand setTimeout a note.
3.  Loop runs second time: `i = 1`. You hand setTimeout another note.
4.  Loop runs third time: `i = 2`. You hand setTimeout a third note.
5.  Loop runs fourth time: `i = 3`. Now `i < 3` is false. Loop stops.
6.  All the code is done now. JavaScript has nothing left to do.
7.  **NOW** after 100ms, setTimeout takes all those notes out and runs them.
8.  Every single note says: "log whatever is inside box i right now".
9.  The value inside that box is now 3.
10. So all three print 3.

✅ This is not a bug. This is exactly how it is supposed to work.

> ⏱️ **How does the timing actually work?**
>
> When `setTimeout(fn, 100)` runs, it starts a timer: 100ms, 99ms, 98ms... counting down in the background.
>
> But JavaScript is insanely fast. A 3-iteration loop finishes in **microseconds**. So by the time the first timer has ticked down to 99.9ms, the loop is already done and `var i` has already been overwritten to 3. All three setTimeout callbacks run after the loop is finished, and they all see the final value: `3`.
>
> With `let`, each loop iteration creates a separate box. So even though the timers fire after the loop, each callback has its own private copy of `i` (0, 1, and 2) that never got overwritten.

---

If you change it to `let i`:

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
```

Now it prints:
```
0
1
2
```

Perfectly correctly.

Why? Because `let` creates a completely NEW SEPARATE BOX for every single loop iteration. Each timeout gets its own private box that no one else changes.

---

And yes, if you used `await` inside the loop it would also print correctly. But that is for much later.

## Summary Rule

1.  **Always use `const` by default**
2.  Only use `let` if you definitely need to change the value
3.  **Never use `var` in 2025+**

That's it. That is all you actually need to write good code.

---

> 📝 Interview Answer Cheat Sheet:
>
> What's the difference between var let and const?
>
> var is function scoped, gets hoisted to undefined, can be re-declared and reassigned.
>
> let is block scoped, can be reassigned but not re-declared.
>
> const is block scoped, can neither be re-declared nor reassigned.
