In the last topic, you learned about functions — the reusable blocks of code that power your programs. And you probably noticed something in the code examples: strings with `${}` inside them, wrapped in backticks instead of quotes. That's not a special syntax for functions — it's a feature called template literals. And it's one of the best things added to JavaScript in the last 10 years.

Think about how we used to build strings. You'd have to do this:

```js
"Hello " + name + ", you are " + age + " years old"
```

All those `+` signs. All those quotes opening and closing. If you forget one `+` or one quote, the whole thing breaks. It's messy, hard to read, and easy to mess up.

Template literals fix all of that.

---

## The Mad Libs Analogy

Remember Mad Libs? You'd have a story with blanks, and you'd fill in words to complete it:

"Hello \_\_\_\_\_\_\_, you are \_\_\_\_\_\_\_ years old and you live in \_\_\_\_\_\_\_\_."

Template literals are exactly that. You write a string with `${}` placeholders, and JavaScript fills in the blanks with your variables.

---

## ✅ What are template literals?

> **Template literals are strings that allow embedded expressions and multi-line content using backtick syntax.**

Let's unpack that.

**"Strings"** — they're still strings. Just text. But they have superpowers.

**"Embedded expressions"** — you can put any JavaScript expression (variables, calculations, function calls) directly inside the string using `${}`. No more concatenation.

**"Multi-line content"** — you can write strings that span multiple lines without using `\n` or `+` to join them.

**"Backtick syntax"** — instead of quotes (`"` or `'`), you use backticks (`` ` ``). That's the key that unlocks the superpowers.

---

## ✅ Two super powers

### 1. String Interpolation — `${}`

You can put any JavaScript expression inside `${}`. Anything that returns a value works:

```js
const name = "Arjun";
const age = 22;

// ❌ Old way — messy concatenation
console.log("Hello " + name + ", you are " + age + " years old");

// ✅ New way — clean and readable
console.log(`Hello ${name}, you are ${age} years old`);
```

You're not limited to just variables. You can put any expression:

```js
const age = 22;

console.log(`You are ${age > 18 ? "adult" : "minor"}`);

const price = 100;
const discount = 20;
console.log(`Total: $${price - discount}`); // Total: $80

const user = { name: "Arjun", city: "Mumbai" };
console.log(`${user.name} lives in ${user.city}`);
```

Functions, calculations, ternary operators, object properties — anything that produces a value works inside `${}`.

### 2. Multi-line Strings

Before template literals, multi-line strings required messy concatenation or escaping:

```js
// ❌ Old way
const html = "<div>" +
  "<p>" + name + "</p>" +
  "</div>";

// Or with escaped newlines
const html = "<div>\n  <p>" + name + "</p>\n</div>";
```

Now you just write normally:

```js
// ✅ New way
const html = `
  <div>
    <p>${name}</p>
  </div>
`;
```

All new lines and spaces are preserved exactly as you write them. This is especially useful for HTML templates, SQL queries, or any text that needs formatting.

---

## ✅ What It Is NOT

- **Template literals are NOT the same as regular strings with backticks.** A backtick string without `${}` is just a regular string. The power comes from the interpolation ability.

- **Template literals are NOT a template engine.** They don't have loops, conditionals (beyond ternary), or other logic. They're just string interpolation. For complex templates, you'd use a library like JSX or Handlebars.

- **Backticks are NOT the same as quotes.** `"hello"` and `` `hello` `` both create strings, but backticks enable interpolation. You can't use `${}` inside regular quotes — it would be treated as literal text.

- **Template literals do NOT prevent XSS or security issues.** If you put user input inside `${}`, it's inserted as-is. No automatic escaping or sanitization. If you're building HTML with user input, you still need to sanitize it.

## 🧠 Interview Questions

> ❓ What are template literals?
> Template literals are strings that support embedded expressions and multi-line content using backtick syntax. They were introduced in ES6.

> ❓ What syntax do template literals use?
> They use backticks (`) instead of quotes. Expressions are embedded using ${expression}.

> ❓ What kind of expressions can you put inside ${}?
> Any JavaScript expression that returns a value: variables, calculations, function calls, ternary operators, object properties, array indexing, etc.

> ❓ Do template literals support multi-line strings?
> Yes. Any newlines inside the backticks are preserved in the string without any special escaping.

> ❓ Can you use template literals in all browsers?
> Yes, all modern browsers support them. Internet Explorer does not support them, but tools like Babel can convert them to regular strings for older browsers.

**In Your Own Words**

1. You have a user object with `name`, `age`, and `city` properties. Write a sentence using both the old concatenation way and the template literal way. Which is easier to read?

<details>
<summary>Show Answer</summary>

**Sample Answer:**

```js
const user = { name: "Priya", age: 25, city: "Delhi" };

// Old way
console.log(user.name + " is " + user.age + " years old and lives in " + user.city);

// Template literal
console.log(`${user.name} is ${user.age} years old and lives in ${user.city}`);
```

The template literal is much easier to read. The structure of the sentence is clear — the variables are just placeholders within the text. The old way requires tracking opening/closing quotes and `+` signs, making it easy to make mistakes.

</details>

2. How would you create a multi-line string that represents an HTML card with a title and description? Write it with template literals.

<details>
<summary>Show Answer</summary>

**Sample Answer:**

```js
const title = "My Article";
const description = "This is about template literals.";

const card = `
  <div class="card">
    <h2>${title}</h2>
    <p>${description}</p>
  </div>
`;
```

No `+` signs, no `\n` escapes. The HTML structure is visible exactly as it will appear. This is much easier to read and maintain than the old concatenation approach.

</details>

3. What is the difference between template literals and regular strings with concatenation? Give a pros/cons comparison.

<details>
<summary>Show Answer</summary>

**Sample Answer:** Template literals are cleaner for mixed content — you don't need to open/close quotes or add `+` signs. They support multi-line without escaping. They can embed any expression. But they're slightly slower than regular strings in very performance-critical code (though the difference is negligible). Regular strings with concatenation are more compatible with older browsers (IE) and don't require a build step. In practice, template literals are preferred in all modern code.

</details>

4. Can you put a function call inside `${}`? Give an example.

<details>
<summary>Show Answer</summary>

**Sample Answer:** Yes, absolutely.

```js
function getGreeting(time) {
  return time < 12 ? "Good morning" : "Good afternoon";
}

const time = 14;
console.log(`${getGreeting(time)}, ${username}!`);
// "Good afternoon, Arjun!"
```

Any expression that returns a value works, including function calls. Just remember that the function runs when the template literal is evaluated.

</details>

5. What happens if you use `${}` inside regular quotes instead of backticks?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The `${}` is treated as literal text — no interpolation happens. `"Hello ${name}"` would output the string "Hello ${name}" literally, not "Hello Arjun". The backtick is what triggers the special behavior. Without it, `${}` is just characters in the string.

</details>
