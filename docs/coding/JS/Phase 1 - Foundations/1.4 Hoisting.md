## What is Hoisting?

When JavaScript runs your code, it does two passes:

✅ **First Pass:** It looks through your entire code and **finds all declarations**.
✅ **Second Pass:** It actually runs the code line by line.

Hoisting is just this:
> **All declarations are moved to the top of their scope, before any code runs.**

That is it. That is all hoisting ever is.

---

## ✅ Different types get hoisted differently

| Type | Behaviour |
|---|---|
| `var` | ✅ Fully hoisted + initialized as `undefined` |
| `let` / `const` | ✅ Hoisted ❌ **NOT initialized** |
| Function Declarations | ✅ Fully hoisted + completely usable |
| Function Expressions | ❌ Not hoisted at all |

---

---

## 1️⃣ `var` Hoisting

```js
console.log(name); // ✅ undefined. No error.
var name = "Pravin";
```

What actually happens:

1.  First pass: JS sees `var name`. It creates the variable at the top and sets it to `undefined`.
2.  Second pass: Runs `console.log(name)` → prints `undefined`
3.  Then finally assigns `"Pravin"` to name.

✅ `var` will never give you an error if you access it before declaration. It will just be `undefined`.

---

## 2️⃣ `let` and `const` Hoisting

This is the lie everyone tells you:
> ❌ "let and const are not hoisted"

✅ **THIS IS 100% WRONG.**

`let` and `const` ARE hoisted. But they are not initialized.

---

### 📝 Important definitions:
✅ **Declaration** = JavaScript knows this variable exists. It reserved a spot for it in memory.
❌ **Initialization** = JavaScript actually put a value inside that spot.

---

### 🚧 The Fence analogy

When JavaScript sees `let` or `const` during first pass:
1.  It declares the variable. The spot is reserved.
2.  It puts a FENCE around this variable from the very top of the scope all the way down to the line where it is declared.
3.  It says: "No one can touch this until you cross this line."

```js
// 🔴 THIS WHOLE AREA IS INSIDE THE FENCE. YOU CANNOT TOUCH CAR HERE.

console.log(car); // ❌ ReferenceError. Cannot access 'car' before initialization.

// ✅ This is the line where the fence opens.
let car = "Tesla";

// 🟢 Now you can touch it.
console.log(car); // ✅ "Tesla"
```

This fence is called the **Temporal Dead Zone (TDZ)**.

✅ The variable exists. It has been hoisted.
❌ But you are not allowed to access it until you reach the line where it is declared.

This is not a bug. This is a safety feature. This is exactly why `let` and `const` were created. To fix the silent undefined bugs that `var` caused.

---

## 3️⃣ Function Declarations

Function declarations are **completely and fully hoisted**.

You can call them **before** they are written in your code.

```js
greet(); // ✅ Works perfectly. "Hello"

function greet() {
  console.log("Hello");
}
```

This works because during first pass, JS finds the entire function and puts it at the top.

---

## 4️⃣ Function Expressions

Function expressions are **NOT hoisted**. They behave exactly like normal variables.

```js
sayHi(); // ❌ TypeError: sayHi is not a function
var sayHi = function() {
  console.log("Hi");
};
```

Because `var sayHi` gets hoisted as `undefined`. So you are trying to call `undefined()` which throws error.

---

## 🚨 Side by side comparison

| Code | Output | Reason |
|---|---|---|
| `console.log(a); var a = 5;` | `undefined` | var is hoisted as undefined |
| `console.log(b); let b = 5;` | `ReferenceError` | let is hoisted but in TDZ |
| `console.log(c); const c = 5;` | `ReferenceError` | same as let |
| `fn(); function fn() {}` | ✅ Works | function declaration fully hoisted |
| `fn(); var fn = function() {}` | `TypeError` | fn is undefined |

---

---

## 📋 Summary

1.  JS always scans all code first before running anything
2.  All declarations are moved to the top of their scope
3.  `var` gets initialized to `undefined`
4.  `let` / `const` get put into Temporal Dead Zone
5.  Function declarations are fully usable immediately
6.  Function expressions behave like normal variables

---

## 🎯 Interview Ready Answer

> "Hoisting is JavaScript's behaviour of moving declarations to the top of their scope before execution. `var` declarations are hoisted and initialized as undefined. `let` and `const` are also hoisted but remain uninitialized in the Temporal Dead Zone until their declaration line is reached. Function declarations are fully hoisted and can be called before they appear in code, while function expressions are not hoisted."

That is the complete correct answer. 90% of developers cannot explain this properly.
