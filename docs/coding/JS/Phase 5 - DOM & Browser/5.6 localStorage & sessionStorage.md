## ✅ What is Web Storage?

✅ Key value storage built into the browser.
✅ Data survives page reloads.
✅ No server required. Everything stays on the client.

✅ There are two types:
| | localStorage | sessionStorage |
|---|---|---|
| ✅ Survives browser close | ✅ YES | ❌ NO |
| ✅ Survives tab close | ✅ YES | ❌ NO |
| ✅ Survives page reload | ✅ YES | ✅ YES |
| ✅ Shared between tabs | ✅ YES | ❌ NO |

---

## ✅ Saving data

✅ You can only store **strings**.

```js
localStorage.setItem("username", "Arjun");
```

✅ To store objects you must convert to JSON first:
```js
const user = { name: "Arjun", age: 25 };

localStorage.setItem("user", JSON.stringify(user));
```

✅ This is the #1 mistake everyone makes. Everyone forgets JSON.stringify.

---

## ✅ Reading data

```js
const username = localStorage.getItem("username");
```

✅ To get back objects you must parse JSON:
```js
const user = JSON.parse(localStorage.getItem("user"));
```

✅ If the key does not exist you get `null`.

---

## ✅ Removing data

✅ Remove single item:
```js
localStorage.removeItem("username");
```

✅ Clear everything:
```js
localStorage.clear();
```

---

## ✅ Same API for sessionStorage

```js
sessionStorage.setItem("token", "abc123");
sessionStorage.getItem("token");
sessionStorage.removeItem("token");
sessionStorage.clear();
```

✅ Exact same methods. Exactly the same API. Only difference is persistence.

## How to Explain

Web Storage provides synchronous key-value storage in the browser that persists across reloads. localStorage survives browser restarts and is shared across tabs; sessionStorage is cleared when the tab closes. Both only store strings, so objects must be serialized with JSON.stringify and parsed with JSON.parse on read.

**The basic flow:**
```js
const user = { name: "Arjun", age: 25 }
localStorage.setItem("user", JSON.stringify(user))
const stored = JSON.parse(localStorage.getItem("user"))
```

setItem stores the stringified object. getItem returns the string or null if the key doesn't exist. JSON.parse converts it back. Forgetting either serialization step is the most common mistake.

**The part that trips everyone up:**

Storage is synchronous and blocks the main thread. Writing large amounts of data stalls the UI. It also has a ~5MB per-domain limit, and quota-exceeded errors must be caught. For anything beyond small settings or tokens, use IndexedDB.

**The mistakes to remember:**
- Storing objects without JSON.stringify, resulting in "[object Object]"
- Reading a missing key and calling JSON.parse on null, which throws
- Storing sensitive data like passwords or tokens in plain localStorage

## 🧠 Interview Questions

> ❓ What is the maximum size of localStorage?
> Approximately 5MB per domain.

> ❓ Can you store objects directly in localStorage?
> No. You must stringify to JSON first.

> ❓ What is the difference between localStorage and sessionStorage?
> localStorage persists permanently. sessionStorage is cleared when tab is closed.

> ❓ Is localStorage async or sync?
> Synchronous. Blocks the main thread.
