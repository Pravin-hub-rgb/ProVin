## ✅ What is the problem?

✅ Some events fire **hundreds of times per second**:
- Typing in an input
- Scrolling the window
- Resizing the window
- Moving the mouse

✅ If you run expensive code every single time your browser will freeze.

✅ We need a way to limit how often functions run.

---

## ✅ Debounce

✅ We will build this function step by step. Line by line.

---

✅ **Step 1:** Debounce is a Higher Order Function.
✅ It takes a normal function and gives you back a new magic function.

```js
function debounce(fn, delay) {

}
```

---

✅ **Step 2:** We need a variable to remember our timer.
✅ This variable lives in closure.

```js
function debounce(fn, delay) {
  let timer;
}
```

---

✅ **Step 3:** Return the new magic function:

```js
function debounce(fn, delay) {
  let timer;

  return function(...args) {

  };
}
```

---

✅ **Step 4:** Every time this function gets called:
✅ First we cancel any existing timer that was already running:

```js
function debounce(fn, delay) {
  let timer;

  return function(...args) {
    clearTimeout(timer);
  };
}
```

---

✅ **Step 5:** Then we set a new timer:

```js
function debounce(fn, delay) {
  let timer;

  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}
```

✅ That is it. Full complete debounce function.

---

✅ **How this works:**
✅ Every single keystroke cancels the previous timer.
✅ Only if you stop typing for 500ms, the last timer will actually run.
✅ That is exactly what you want for search boxes.

---

✅ Best for: search boxes, window resize, autocomplete.

✅ Usage:
```js
const handleSearch = debounce(function(e) {
  console.log("Searching for:", e.target.value);
}, 500);

input.addEventListener("input", handleSearch);
```

✅ This will fire **only once** 500ms after you finish typing.

---

## ✅ Throttle

✅ Debounce waits until you stop.
✅ Throttle keeps running at regular intervals WHILE you are still doing it.

✅ It will fire at most **once every X milliseconds**. No matter how many times it gets triggered.

✅ We will build this function step by step. Line by line.

---

✅ **Step 1:** Throttle is also a Higher Order Function.
✅ It takes a normal function and gives you back a new rate limited function.

```js
function throttle(fn, limit) {

}
```

---

✅ **Step 2:** We need to remember the last time this function actually ran.
✅ This variable lives in closure.

```js
function throttle(fn, limit) {
  let lastCall = 0;
}
```

---

✅ **Step 3:** Return the new rate limited function:

```js
function throttle(fn, limit) {
  let lastCall = 0;

  return function(...args) {

  };
}
```

---

✅ **Step 4:** Every time this function gets called:
✅ First check what time it is right now:

```js
function throttle(fn, limit) {
  let lastCall = 0;

  return function(...args) {
    const now = Date.now();
  };
}
```

---

✅ **Step 5:** Check if enough time has passed since last run:

```js
function throttle(fn, limit) {
  let lastCall = 0;

  return function(...args) {
    const now = Date.now();

    if (now - lastCall >= limit) {
      lastCall = now;
      fn(...args);
    }
  };
}
```

✅ That is it. Full complete throttle function.

---

✅ **How this works:**
✅ It will ignore all calls until enough time has passed.
✅ No matter how many times you call it, it will run at most once every X ms.
✅ That is exactly what you want for scroll events.

---

✅ Best for: scroll events, button clicks, mouse movement, infinite scroll.

✅ Usage:
```js
const handleScroll = throttle(function() {
  console.log("Scroll position updated");
}, 200);

window.addEventListener("scroll", handleScroll);
```

✅ This will fire at most once every 200ms.

## 🧠 Interview Questions

> ❓ What is the difference between debounce and throttle?
> Debounce runs after the user stops. Throttle runs at regular intervals while the event is happening.

> ❓ When would you use debounce?
> Search inputs, window resize, autocomplete.

> ❓ When would you use throttle?
> Scroll events, button clicks, mouse movement, infinite scroll.

Throttle ensures a function runs at most once every given interval. These are essential for handling frequent events like typing, scrolling and resizing without performance issues."
