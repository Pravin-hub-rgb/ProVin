Second most asked DOM interview question. Every frontend developer needs to know this.

## ✅ The Problem

✅ Imagine you have 1000 items in a list:

```js
// ❌ BAD WAY
document.querySelectorAll(".item").forEach(item => {
  item.addEventListener("click", handleClick);
});
```

❌ This creates 1000 separate event listeners. That is slow.
❌ If you add new items later, they will **NOT** have the listener attached.

---

## ✅ The Solution

✅ Instead attach **ONE** single listener to the parent:

```js
// ✅ GOOD WAY
document.querySelector(".list").addEventListener("click", function(event) {
  if (event.target.classList.contains("item")) {
    console.log("Item clicked:", event.target);
  }
});
```

✅ Only 1 listener. Always.
✅ Works for items that are added **after** the page loads.
✅ Works for items that are removed and recreated.

---

## ✅ Why does this work?

✅ Because of event bubbling.

✅ Every click on an item bubbles up to the parent.
✅ The parent listener catches it.
✅ We just check what was actually clicked.

✅ This is one of the most powerful and useful patterns in all of frontend development.

## How to Explain

Event delegation attaches a single listener to a parent element instead of one per child. It works because of bubbling — any child click propagates up to the parent, which checks event.target to identify which child was clicked. One listener handles all current and future children, improving performance and memory.

**The basic flow:**
```js
document.querySelector(".list").addEventListener("click", function(event) {
  if (event.target.matches(".item")) {
    console.log("Item clicked:", event.target)
  }
})
```

The parent listens once. Whether items exist now or are added later via JavaScript, the single handler catches all of them through bubbling.

**The part that trips everyone up:**

event.target may be a nested element inside the item, not the item itself. If your item contains a span or icon, clicking that returns the span as target. Use event.target.closest(".item") to find the nearest matching ancestor instead of checking target directly.

**The mistakes to remember:**
- Checking event.target.classList directly when the clicked element is a child of the target
- Attaching one listener per item in large lists, wasting memory and missing dynamic items
- Forgetting delegation relies on bubbling — it breaks if a child calls stopPropagation

## 🧠 Interview Questions

> ❓ What is event delegation?
> Attaching a single event listener to a parent element instead of multiple listeners on individual child elements.

> ❓ What are the advantages of event delegation?
> Better performance, less memory usage, and automatically works for dynamically added elements.

> ❓ What makes event delegation possible?
> Event bubbling.
