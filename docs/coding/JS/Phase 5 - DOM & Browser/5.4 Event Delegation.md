Second most asked DOM interview question. Every frontend developer needs to know this.

---

## ✅ The Problem

✅ Imagine you have 1000 items in a list:

```js
// ❌ BAD WAY
document.querySelectorAll(".item").forEach(item => {
  item.addEventListener("click", handleClick);
});
```

❌ This creates 1000 separate event listeners. That is slow.
❌ If you add new items later, they will **NOT** have the listener attached.

---

## ✅ The Solution

✅ Instead attach **ONE** single listener to the parent:

```js
// ✅ GOOD WAY
document.querySelector(".list").addEventListener("click", function(event) {
  if (event.target.classList.contains("item")) {
    console.log("Item clicked:", event.target);
  }
});
```

✅ Only 1 listener. Always.
✅ Works for items that are added **after** the page loads.
✅ Works for items that are removed and recreated.

---

## ✅ Why does this work?

✅ Because of event bubbling.

✅ Every click on an item bubbles up to the parent.
✅ The parent listener catches it.
✅ We just check what was actually clicked.

✅ This is one of the most powerful and useful patterns in all of frontend development.

## 🧠 Interview Questions

> ❓ What is event delegation?
> Attaching a single event listener to a parent element instead of multiple listeners on individual child elements.

> ❓ What are the advantages of event delegation?
> Better performance, less memory usage, and automatically works for dynamically added elements.

> ❓ What makes event delegation possible?
> Event bubbling.

---

---

## 🎯 Interview Ready Answer

> "Event delegation is a pattern where a single event listener is attached to a parent element instead of attaching listeners to individual child elements. This works because of event bubbling, and provides better performance and automatic support for dynamically created elements. This is the standard pattern for handling events on lists and dynamic content."

That is the full correct answer.
