## What This Topic Is Asking (Simple Terms)

Cookies are small pieces of data stored in the browser that get sent to the server with every HTTP request. They're used for sessions, authentication tokens, and tracking. Unlike `localStorage`, cookies have an expiry and are accessible by the server.

---

## Setting Cookies

```js
// Basic cookie
document.cookie = "theme=dark";

// With expiry (seconds)
document.cookie = "theme=dark; max-age=86400"; // 1 day

// With expiry date
document.cookie = "theme=dark; expires=Fri, 31 Dec 2025 23:59:59 GMT";

// With path (available on all pages)
document.cookie = "theme=dark; path=/";

// With domain (available on subdomains)
document.cookie = "theme=dark; domain=.example.com; path=/";

// Secure (HTTPS only) + HttpOnly (not accessible via JS)
document.cookie = "token=abc123; Secure; HttpOnly; SameSite=Strict";
```

### Cookie Attributes

| Attribute | What it does |
|-----------|-------------|
| `max-age` | Lifetime in seconds (e.g., `86400` = 1 day) |
| `expires` | Expiry date (GMT format) |
| `path` | URL path where cookie is valid (`/` = entire site) |
| `domain` | Domain where cookie is valid (`.example.com` = subdomains too) |
| `Secure` | Only sent over HTTPS |
| `HttpOnly` | Not accessible via JavaScript (XSS protection) |
| `SameSite` | `Strict` (same-site only), `Lax` (top-level navigation), `None` (cross-site, requires Secure) |

## Reading Cookies

```js
// document.cookie returns ALL cookies as one string
document.cookie; // "theme=dark; username=vin; token=abc123"

// Parse cookies into an object
function getCookies() {
  const cookies = {};
  document.cookie.split(";").forEach((cookie) => {
    const [name, value] = cookie.trim().split("=");
    cookies[name] = decodeURIComponent(value);
  });
  return cookies;
}

const cookies = getCookies();
console.log(cookies.theme);    // "dark"
console.log(cookies.username); // "vin"
```

---

## Deleting Cookies

```js
// Set expiry to the past
document.cookie = "theme=; expires=Thu, 01 Jan 1970 00:00:00 GMT; path=/";

// Or set max-age to 0
document.cookie = "theme=; max-age=0; path=/";
```

**Important:** The `path` must match the original cookie's path, or the deletion won't work.

## Cookie vs localStorage vs sessionStorage

| Feature | Cookie | localStorage | sessionStorage |
|---------|--------|-------------|----------------|
| Capacity | ~4KB | ~5-10MB | ~5-10MB |
| Sent to server | ✅ Yes (with every request) | ❌ No | ❌ No |
| Expiry | Configurable (max-age/expires) | Never (manual clear) | On tab close |
| Accessible via JS | ✅ (unless HttpOnly) | ✅ | ✅ |
| Scope | Domain + path | Origin (protocol + host + port) | Tab + origin |
| Use case | Sessions, auth tokens, tracking | User prefs, cached data | Temporary per-tab state |

## Common Mistakes

- **Forgetting `path=/`** — cookie defaults to the current page's path. If you set it on `/login`, it won't be available on `/dashboard`. Always use `path=/` for site-wide cookies.
- **Not encoding values** — cookie values can't contain spaces, semicolons, or commas. Use `encodeURIComponent()` when setting, `decodeURIComponent()` when reading.
- **Storing secrets in cookies** — cookies are readable by JavaScript (unless `HttpOnly`). Never store passwords or sensitive data. Use `HttpOnly` + `Secure` + `SameSite` for auth tokens.
- **Forgetting to delete with matching path** — `document.cookie = "name=; max-age=0"` won't delete a cookie set with `path=/`. You must include `path=/` in the deletion too.

---

## What This Topic Is NOT

- ❌ Cookies are not the same as **localStorage** — cookies are sent to the server with every request, localStorage stays in the browser.
- ❌ `HttpOnly` cookies are not accessible via **JavaScript** — `document.cookie` won't show them. They're only sent to the server.
- ❌ `SameSite=Strict` is not the same as **`Secure`** — `Secure` means HTTPS only, `SameSite` controls cross-site sending.

## In Your Own Words

1. What's the difference between a cookie and localStorage? When would you use each?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Cookies are small (~4KB), sent to the server with every HTTP request, and have configurable expiry. localStorage is larger (~5-10MB), stays in the browser, and never expires. Use cookies for session/auth tokens (server needs them) and tracking. Use localStorage for user preferences, cached data, and offline state (server doesn't need them). Never store secrets in either — use HttpOnly cookies for auth tokens.

</details>

2. Why is `HttpOnly` important for security?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `HttpOnly` prevents JavaScript from accessing the cookie via `document.cookie`. This protects against XSS attacks — even if an attacker injects a script, they can't steal the auth token. The cookie is only sent to the server with HTTP requests. Always use `HttpOnly` + `Secure` + `SameSite` for authentication cookies.

</details>

3. What happens if you set a cookie without `path=/`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The cookie defaults to the current page's path. If you set it on `/login`, it's only available on `/login` and its subpaths — not on `/dashboard` or `/`. To make a cookie available site-wide, always include `path=/`.

</details>

## Cheat Sheet (Quick Recall)

**Set:** `document.cookie = "name=value; max-age=86400; path=/"`

**Read:** `document.cookie` → parse with split(";") and trim()

**Delete:** `document.cookie = "name=; max-age=0; path=/"` (path must match)

**Attributes:** `max-age` (seconds), `expires` (date), `path`, `domain`, `Secure`, `HttpOnly`, `SameSite`

**Encode:** `encodeURIComponent(value)` when setting, `decodeURIComponent(value)` when reading
