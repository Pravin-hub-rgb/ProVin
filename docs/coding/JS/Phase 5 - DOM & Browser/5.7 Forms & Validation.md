## What This Topic Is Asking (Simple Terms)

Forms are how users send data to your app. Validation is how you check that data is correct before processing it. JavaScript gives you both browser-built validation (HTML5 attributes) and manual validation (JS checks).

---

## HTML5 Built-in Validation

The browser can validate inputs without any JavaScript:

```html
<form>
  <!-- Required field -->
  <input type="text" required>

  <!-- Email format -->
  <input type="email" required>

  <!-- Minimum length -->
  <input type="text" minlength="3" required>

  <!-- Pattern (regex) -->
  <input type="text" pattern="[A-Za-z]+" title="Letters only">

  <!-- Number range -->
  <input type="number" min="1" max="100">

  <!-- URL format -->
  <input type="url">

  <button type="submit">Submit</button>
</form>
```

**How it works:** When the user clicks submit, the browser checks all fields. If any fail, it shows a native error message and blocks submission. No JavaScript needed.

## JavaScript Form Handling

### Reading Form Data with `FormData`

```js
const form = document.querySelector("#myForm");

form.addEventListener("submit", (e) => {
  e.preventDefault(); // stop page reload

  const data = new FormData(form);

  // Get individual values
  const name = data.get("name");      // string or null
  const email = data.get("email");

  // Get all values for a field (checkboxes, multi-select)
  const hobbies = data.getAll("hobby"); // ["reading", "coding"]

  // Convert to object
  const obj = Object.fromEntries(data);
  // { name: "Vin", email: "vin@dev.com", hobby: "reading" }
  // Note: getAll values are lost in fromEntries — only last value kept

  // Iterate
  for (const [key, value] of data) {
    console.log(key, value);
  }
});
```

### HTML5 Validation API (JS)

```js
const input = document.querySelector("#email");

// Check if valid
input.checkValidity();  // true/false

// Show native error message
input.reportValidity();  // shows browser's error tooltip

// Custom error message
input.setCustomValidity("Please enter a valid email");

// Clear custom error
input.setCustomValidity("");

// Validation properties
input.validity.valid;        // true/false
input.validity.valueMissing; // true if required and empty
input.validity.typeMismatch; // true if type="email" and not an email
input.validity.patternMismatch; // true if pattern doesn't match
input.validity.tooShort;     // true if minlength not met
input.validity.rangeUnderflow; // true if below min
input.validity.rangeOverflow;  // true if above max
```

### Form Reset

```js
form.reset();  // clears all fields to their initial values
```

## Manual Validation (Custom Logic)

```js
form.addEventListener("submit", (e) => {
  e.preventDefault();

  const data = new FormData(form);
  const errors = {};

  // Custom checks
  const name = data.get("name");
  if (!name || name.trim().length < 2) {
    errors.name = "Name must be at least 2 characters";
  }

  const email = data.get("email");
  if (!email || !email.includes("@")) {
    errors.email = "Please enter a valid email";
  }

  const age = Number(data.get("age"));
  if (isNaN(age) || age < 18) {
    errors.age = "Must be 18 or older";
  }

  // If errors, show them
  if (Object.keys(errors).length > 0) {
    showErrors(errors);
    return;
  }

  // All good — process the data
  submitForm(Object.fromEntries(data));
});
```

## Common Mistakes

- **Forgetting `e.preventDefault()`** — form submits and page reloads. Always prevent default in form handlers.
- **Not clearing custom validity** — `setCustomValidity("error")` stays until you call `setCustomValidity("")`. If you set it once, the field stays invalid forever.
- **Using `innerHTML` for error messages** — XSS risk. Use `textContent` for error messages.
- **Not validating on the server** — client-side validation is for UX, not security. Always validate on the server too.
- **Forgetting to handle the `submit` event** — if you only listen for `click` on the button, pressing Enter won't trigger it. Listen for `submit` on the form.

## What This Topic Is NOT

- ❌ Forms are not the same as **AJAX/fetch** — forms collect data, fetch sends it to a server. You can use both together (form → fetch).
- ❌ HTML5 validation is not the same as **JS validation** — HTML5 is declarative (attributes), JS is imperative (code). HTML5 runs first, then JS.
- ❌ `FormData` is not the same as a **plain object** — `FormData` is a special object with methods like `get()`, `getAll()`, `append()`. Convert with `Object.fromEntries()` if you need a plain object.

## In Your Own Words

1. What's the difference between HTML5 validation and JavaScript validation? When would you use each?

<details>
<summary>Show Answer</summary>

**Sample Answer:** HTML5 validation uses attributes (`required`, `type="email"`, `minlength`, `pattern`) — the browser checks them automatically on submit and shows native error messages. No JavaScript needed. JS validation is custom code you write (`checkValidity()`, manual checks, `setCustomValidity()`). Use HTML5 for simple checks (required, email format, number range). Use JS for complex logic (cross-field validation, async checks like "is this username taken?", custom error messages). Most real apps use both — HTML5 for quick feedback, JS for complex rules.

</details>

2. What does `e.preventDefault()` do in a form submit handler, and why is it needed?

<details>
<summary>Show Answer</summary>

**Sample Answer:** It stops the browser's default form submission behavior, which is to send the form data to the server and reload the page. Without it, your JavaScript handler runs but the page immediately reloads, losing any state. With `preventDefault()`, you handle the submission in JavaScript (validate, then fetch to API, then update UI) without a page reload.

</details>

3. Why should you always validate on the server, even if you validate on the client?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Client-side validation is for UX (fast feedback, no round-trip). But it can be bypassed — a user can disable JavaScript, modify the HTML, or send a direct HTTP request. Server-side validation is the real security check. Never trust client data. Client validation = convenience. Server validation = security.

</details>

## Cheat Sheet (Quick Recall)

**HTML5 validation:** `required`, `type="email"`, `minlength`, `pattern`, `min`, `max`.

**Read form data:** `new FormData(form)` → `data.get("name")`, `data.getAll("hobby")`, `Object.fromEntries(data)`.

**JS validation:** `input.checkValidity()`, `input.reportValidity()`, `input.setCustomValidity("msg")`, `input.validity.valid`.

**Reset:** `form.reset()`.

**Prevent reload:** `e.preventDefault()` in submit handler.

**Key rule:** Always `preventDefault()` on form submit. Validate on client for UX, on server for security. Use `FormData` to read values.
