Everything that happens in the browser is an event. This is how you make things interactive.

But how do you *listen* for something happening?

Think about your phone. You do not stand there staring at it 24 hours a day waiting for a notification. You go about your life — cooking, working, sleeping — and when a notification arrives, your phone buzzes and you check it. You are not *polling* your phone every millisecond. You are *reacting* to events.

The browser works the same way. Instead of constantly checking "did the user click yet? how about now? now?" (which would freeze your page completely), you tell the browser:

> "Hey, when this button gets clicked, tap me on the shoulder and I will handle it."

That is what `addEventListener` does. It is you saying "tap me when this happens." The browser does the hard work of watching for the event, and your function just sits there waiting to be called.

---

## ✅ Adding Event Listeners

✅ Basic click event:
```js
const button = document.querySelector("#submit");

button.addEventListener("click", function() {
  console.log("Button was clicked!");
});
```

✅ Most common events:
- `click`
- `submit`
- `input`
- `change`
- `keydown`
- `load`
- `scroll`

---

## ✅ Event Object

✅ Every handler receives an event object:
```js
button.addEventListener("click", function(event) {
  console.log(event);
});
```

✅ Most useful properties and methods:
```js
event.preventDefault();      // Stop default browser behaviour
event.stopPropagation();     // Stop event bubbling up
event.target;                // The actual element that was clicked
event.currentTarget;         // The element that the listener is attached to
```

## ✅ Removing Event Listeners

If you add a listener and never remove it, that callback function stays in memory forever. Even if the element is removed from the page, the listener is still there, holding onto references. This is the #1 cause of memory leaks in JavaScript.

However, removing a listener is trickier than it looks.

❌ This does **NOT** work:
```js
button.addEventListener("click", function() {});
button.removeEventListener("click", function() {});
```
✅ These are two different functions. Even though they look identical, each `function() {}` creates a new function in memory. You cannot remove one if you do not have a reference to it.

✅ This works:
```js
function handleClick() {
  console.log("clicked");
}

button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);
```
✅ You must pass the **exact same function reference** — the same variable, the same function object. Only then can JavaScript find and remove it.

## ✅ Event Delegation

Imagine you have a list of 1000 items, and each one needs a click handler:

```js
document.querySelectorAll("li").forEach(li => {
  li.addEventListener("click", () => handleClick(li));
});
```

That is 1000 separate event listeners. 1000 functions in memory. And if you add new list items later (dynamically loaded from the server), they will not have listeners at all.

Event delegation solves both problems. Instead of adding a listener to every single element, you add **one** listener to a parent ancestor and let bubbling do the work. When any child is clicked, the event bubbles up to the parent, and you check which element actually triggered it.

✅ Best practice for dynamic elements:
```js
document.addEventListener("click", function(event) {
  if (event.target.matches(".delete-button")) {
    console.log("Delete button clicked");
  }
});
```

One listener. Works for all current elements. Works for any elements added in the future. Less memory. Less code. No need to re-attach listeners.

## 🧠 Interview Questions

> ❓ What is the difference between target and currentTarget?
> target is the actual element clicked. currentTarget is the element that has the listener attached.

> ❓ Why won't my removeEventListener work?
> You must pass the exact same function reference that you used to add it.

> ❓ What is event delegation?
> Attaching a single listener to a parent element instead of multiple listeners on child elements.
