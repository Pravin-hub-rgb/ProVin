This is what frontend developers actually do. This is the real job.

But first — what is the DOM?

The DOM stands for **Document Object Model**. Let's break down each word:

- **Document** — the HTML file you wrote. When the browser loads your HTML page, that's the "document." The DOM is the browser's representation of that document.
- **Object** — every HTML tag becomes a JavaScript object in memory. A `<div>` becomes a `HTMLDivElement` object, a `<button>` becomes a `HTMLButtonElement` object, a `<p>` becomes a `HTMLParagraphElement` object. These objects have properties (like `textContent`, `className`, `style`) and methods (like `addEventListener`, `querySelector`).
- **Model** — it's a model/representation of the document. Not the actual HTML text, but a structured model of it — a tree of objects that JavaScript can read and modify.

The DOM is a tree-structured representation of your HTML document. When the browser loads an HTML file, it parses the HTML tags and builds a tree of JavaScript objects in memory. Each HTML tag becomes a node in that tree.

The `document` object is the root of that tree. It is the entry point. Without `document`, you cannot access anything on the page. Every DOM operation starts with `document.something(...)`.

DOM manipulation is reading and modifying that tree of objects using JavaScript — changing text, adding elements, removing elements, attaching event listeners.

## ✅ Selecting Elements

✅ Get single element:
```js
const button = document.querySelector("#submit-button");
const card = document.querySelector(".card");
```

✅ Get multiple elements:
```js
const allButtons = document.querySelectorAll("button");
const inputs = document.querySelectorAll("input.required");
```
✅ Returns a NodeList. You can loop over it with `forEach()`.

✅ Older methods that still work:
```js
document.getElementById("id");
document.getElementsByClassName("class");
document.getElementsByTagName("div");
```

---

## ✅ Creating Elements

Once you can find existing elements on the page, the next thing you need is to create **new** ones — adding a new item to a list, displaying new data from the server, showing a notification.

```js
const div = document.createElement("div");
```

This creates an element in memory. It is not on the page yet — just floating in JS memory, invisible. You need to set its content and insert it into the document (which we will cover next).

✅ Set content safely:
```js
div.textContent = "Hello World";
```

❌ Never use this unless you are 100% sure:
```js
div.innerHTML = "<strong>Hello</strong>";
```
✅ This parses HTML. This is how XSS attacks happen.

---

## ✅ Adding Classes & Attributes

Now that you have an element, you need to style it or attach extra data to it. That is what classes and attributes are for.

Classes control how elements look. Attributes store extra data (like IDs, disabled state, or custom data for JavaScript logic).

```js
div.classList.add("card");
div.classList.remove("hidden");
div.classList.toggle("active");
div.classList.contains("loading");
```

✅ Attributes:
```js
div.setAttribute("data-id", "123");
div.getAttribute("data-id");
div.removeAttribute("disabled");
```

---

## ✅ Inserting into page

Creating an element only makes it in memory. It is floating in JavaScript land, invisible. To actually see it on the screen, you need to insert it into the document tree — attach it to a parent that already exists on the page.

```js
document.body.appendChild(div);
parent.appendChild(child);
```

✅ Modern methods:
```js
parent.append(div);
parent.prepend(div);
element.before(otherElement);
element.after(otherElement);
```

---

## ✅ Removing elements

What if you need to delete something from the page — like dismissing a notification, removing a deleted todo item, or closing a modal?

```js
element.remove();
```

✅ Old way:
```js
parent.removeChild(child);
```

## How to Explain

The DOM is the browser's live object representation of your HTML. DOM manipulation means selecting, creating, modifying, and removing elements in that tree. All operations start from the document object. Modern code prefers textContent over innerHTML for safety and querySelector over older getElementById calls.

**The basic flow:**
```js
const button = document.querySelector("#submit")
const div = document.createElement("div")
div.textContent = "Hello"
document.body.append(div)
```

querySelector finds the element. createElement makes a new one in memory. textContent sets safe plain text. append inserts it into the visible page.

**The part that trips everyone up:**

innerHTML parses HTML and executes embedded scripts, making it the primary vector for XSS attacks. Even when the data seems safe, use textContent for plain text and build elements programmatically when structure is needed.

**The mistakes to remember:**
- Using innerHTML with untrusted data, opening the door to XSS
- Forgetting createElement only creates an in-memory node — it's invisible until appended
- Treating a NodeList from querySelectorAll as an array — it has forEach but not map or filter

---

## 🧠 Interview Questions

> ❓ What is the difference between textContent and innerHTML?
> textContent is plain text only. innerHTML parses HTML and is a security risk.

> ❓ What is the difference between querySelector and getElementById?
> querySelector uses CSS selectors. getElementById is slightly faster.

> ❓ What does querySelectorAll return?
> A NodeList. Not an array. You can call forEach() on it.
