## ✅ Basic try / catch

✅ When code throws an error it will crash your entire program unless you catch it.

```js
try {
  // code that might fail
  const data = JSON.parse("this is not json");
} catch (error) {
  // only runs if there was an error
  console.log("Something went wrong");
}
```

✅ If there is an error inside try, execution jumps immediately to catch.
✅ If there is no error catch is completely skipped.

---

## ✅ Error object

✅ Every error has 3 standard properties:

```js
try {
  JSON.parse("bad json");
} catch (err) {
  console.log(err.name);      // SyntaxError
  console.log(err.message);   // Unexpected token 'b'
  console.log(err.stack);     // full stack trace
}
```

✅ Always log these. Never just log `err` by itself.

---

## ✅ finally

✅ `finally` always runs. No matter what.

```js
try {
  // try something
} catch (err) {
  // only on error
} finally {
  // always runs. Always.
  // put cleanup code here: close connections, remove loaders
}
```

✅ Even if you return from inside try or catch, finally will still run.

---

## ✅ Throwing errors

✅ You can throw your own errors:

```js
if (age < 18) {
  throw new Error("You must be 18 or older");
}
```

✅ Always throw actual Error objects. Never throw strings.

---

## ✅ Custom errors

✅ Extend Error class for custom error types:

```js
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}
```

✅ Usage:
```js
throw new ValidationError("Email is invalid", "email");
```

✅ This is how professional codebases handle errors.

---

## ✅ Async / Await error handling

✅ Exactly the same pattern:

```js
async function fetchUser() {
  try {
    const res = await fetch('/api/user');

    if (!res.ok) {
      throw new Error(`HTTP Error: ${res.status}`);
    }

    return await res.json();
  } catch (err) {
    console.error("Failed to fetch user:", err);
  }
}
```

## 🧠 Interview Questions

> ❓ When does finally run?
> Always. No matter if there was an error or not. Even if you return.

> ❓ Should you throw strings or Error objects?
> Always throw Error objects. They have proper stack traces.

> ❓ Can you have try without catch?
> Yes. But you must have finally.

## 🎯 Interview Ready Answer

> "Error handling in JavaScript uses the try/catch/finally pattern. Code inside try is executed, any thrown errors will be caught and handled in the catch block. Finally always runs regardless of outcome for cleanup operations. Custom errors can be created by extending the built in Error class."

That is the full correct answer.
