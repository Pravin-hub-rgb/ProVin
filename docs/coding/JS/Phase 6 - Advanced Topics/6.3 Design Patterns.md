## ✅ Module Pattern ⭐

✅ The most used pattern in all JavaScript.
✅ Uses closures to create private state.

```js
const counter = (function() {
  // ✅ This variable is completely private
  // No one can access it from outside
  let count = 0;

  // ✅ Only what we return is public
  return {
    increment: function() {
      count++;
    },
    decrement: function() {
      count--;
    },
    getCount: function() {
      return count;
    }
  };
})();
```

✅ Usage:
```js
counter.increment();
counter.increment();

console.log(counter.getCount()); // 2

console.log(counter.count); // undefined ❌ You cannot access it
```

✅ This is how you encapsulate logic. This is how every library is written.

## ✅ Observer Pattern ⭐⭐

✅ This pattern is everywhere.
✅ React, Redux, Vue, Angular, Node.js events all use this.

✅ Idea: One object notifies many other objects when something changes.

```js
class EventEmitter {
  constructor() {
    this.events = {};
  }

  // Subscribe to an event
  on(eventName, callback) {
    if (!this.events[eventName]) {
      this.events[eventName] = [];
    }
    this.events[eventName].push(callback);
  }

  // Trigger an event
  emit(eventName, data) {
    if (this.events[eventName]) {
      this.events[eventName].forEach(callback => callback(data));
    }
  }

  // Unsubscribe
  off(eventName, callback) {
    if (this.events[eventName]) {
      this.events[eventName] = this.events[eventName].filter(cb => cb !== callback);
    }
  }
}
```

✅ Usage:
```js
const events = new EventEmitter();

events.on('userLoggedIn', (user) => {
  console.log(`Welcome ${user.name}`);
});

events.emit('userLoggedIn', { name: 'John' });
```

## ✅ Singleton Pattern

✅ Ensure only one instance of a class ever exists.
✅ Perfect for configuration, database connections, loggers.

```js
class AppConfig {
  constructor() {
    // If instance already exists return it
    if (AppConfig.instance) {
      return AppConfig.instance;
    }

    // Otherwise create it
    this.apiUrl = "https://api.example.com";
    this.debug = true;

    // Save the instance
    AppConfig.instance = this;
  }
}
```

✅ Usage:
```js
const config1 = new AppConfig();
const config2 = new AppConfig();

console.log(config1 === config2); // true
```

✅ No matter how many times you call `new` you always get exactly the same object.

## ✅ When to use each

| Pattern | Use case |
|---------|----------|
| Module | When you need private state |
| Observer | When multiple things need to react to changes |
| Singleton | When you must have only one instance |

## 🧠 Interview Questions

> ❓ What is the module pattern?
> It uses closures to create private internal state and only expose a public API.

> ❓ Where is observer pattern used?
> In every event system. All state management libraries use this pattern.

> ❓ What problem does singleton solve?
> Ensures only one instance of an object exists in the entire application.
