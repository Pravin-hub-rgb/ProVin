
A normal function is like a **vending machine**. You put money in, it drops your snack, and that is it. Done. One transaction, one result, goodbye.

A generator is like a vending machine that gives you one snack, then waits for you to press the button again for the next one. You can walk away in between. Come back an hour later, press the button again, and it continues right where it left off.

Generators are functions that can **pause in the middle** and **resume later**. They can return multiple values over time, instead of all at once. You will almost never write them yourself, but they power a lot of modern JavaScript features that you use every day.

---

## ✅ What are generators?

✅ Normal functions run once and return once.
✅ Generator functions can pause and resume.
✅ They can return multiple values over time.

✅ Use `function*` syntax:

```js
function* counter() {
  let i = 0;

  while (true) {
    yield i++;
  }
}
```

✅ `yield` pauses the function and returns the value.

---

## ✅ Using generators

```js
const gen = counter();

console.log(gen.next().value); // 0
console.log(gen.next().value); // 1
console.log(gen.next().value); // 2
console.log(gen.next().value); // 3
```

✅ Every time you call `.next()` the function resumes running until it hits the next `yield`.

---

## ✅ Real world

✅ You will almost never need to write a generator.
✅ They are used internally in libraries.
✅ `async/await` was originally built on top of generators.
✅ All modern iteration features use generators under the hood.

---

## ✅ Important thing

✅ You do not need to master this.
✅ You just need to know that this is a thing that exists.
✅ No junior interview will ever ask you to write a generator.

## 🧠 Interview Questions

> ❓ What is a generator function?
> A special function that can be paused and resumed multiple times.

> ❓ What keyword do you use to pause a generator?
> `yield`

> ❓ When would you use a generator?
> Almost never in application code. Mostly used internally by libraries.
