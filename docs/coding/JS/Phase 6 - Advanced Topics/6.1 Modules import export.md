This is how all modern JavaScript code is organized. This is what you use every single day.

## ✅ What are modules?

✅ Before modules all JavaScript ran in one global scope. Everything was available everywhere.
✅ Modules let you split your code into separate files.
✅ Nothing is shared by default. You have to explicitly export and import things.

✅ There are only two types of exports:
1. Named exports
2. Default exports

---

## ✅ Named Exports

✅ You can export as many things as you want per file.

```js
// utils.js
export const PI = 3.14159;
export function add(a, b) { return a + b; }
export function multiply(a, b) { return a * b; }
export class User {}
```

✅ Importing named exports:
```js
import { add, PI, User } from './utils.js';
```

✅ Rename when importing:
```js
import { add as addNumbers } from './utils.js';
```

✅ Import everything as one object:
```js
import * as utils from './utils.js';

utils.add(1, 2);
utils.multiply(5, 10);
```

---

## ✅ Default Exports

✅ Only **one** default export per file.
✅ This is what you use for components.

```js
// App.js
export default function App() {
  return <div>Hello</div>;
}
```

✅ Importing default exports:
```js
import App from './App.js';
```

✅ No curly braces. You can name it anything you want.

---

## ✅ Both together

✅ You can absolutely have both default and named exports in the same file. This is extremely common.

```js
// Button.js
export default function Button() {} // default
export const buttonSizes = ['sm', 'md', 'lg']; // named
```

✅ This is how you import both at the same time:
```js
import Button, { buttonSizes } from './Button.js';
```

✅ Default comes first outside the braces. Named exports go inside the braces.

---

## ✅ Common Mistakes

❌ This does **NOT** work:
```js
// ❌ Wrong
import add from './utils.js';
```
✅ `add` is a named export, you need curly braces.

❌ This does **NOT** work:
```js
// ❌ Wrong
import { App } from './App.js';
```
✅ `App` is default export, you do NOT use curly braces.

✅ This is the #1 mistake every new developer makes.

## 🧠 Interview Questions

> ❓ What is the difference between named and default exports?
> You can have multiple named exports per file but only one default export. Named exports are imported with curly braces.

> ❓ Can you have both named and default exports in the same file?
> Yes. This is allowed and very common.

> ❓ Do modules run in global scope?
> No. Every module has its own scope.
