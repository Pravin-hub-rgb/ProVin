# (Immediately Invoked Function Expression)

This is one of the oldest patterns in JavaScript.

---

## ✅ What is it?

Let's break it down. Normally you do:
```js
// 1. Define function
function hello() {
  console.log("hello");
}

// 2. Call it
hello();
```

✅ IIFE is just doing both steps at the same time.

```js
// Define + Call immediately
(function() {
  console.log("This runs immediately!");
})();
```

✅ You are still calling it. You are just calling it right after you define it, without giving it a name.

It is not magic. It doesn't run itself. You are calling it. You just do it in the same line.

---

## ✅ What problem does it solve?

Before `let` and `const` were invented, all variables were global.

If you wrote:
```js
var name = "Arjun";
```

✅ This variable would exist everywhere. Every script, every function. This is called **global scope pollution**.

---

## ✅ IIFE was the solution:

```js
(function() {
  var name = "Arjun";
  console.log(name); // works
})();

console.log(name); // ❌ Reference Error! Not accessible.
```

✅ All variables inside the IIFE are completely private. They never leak to the global scope.

This is how everyone wrote JavaScript for 15 years.

---

## ✅ Syntax variations:

You will also see people write it like this:
```js
!function() {
  // same thing
}();
```

Or:
```js
(() => {
  // also works with arrow functions
})();
```

All do exactly the same thing.

---

## ✅ Modern day use:

Now that we have `let`, `const` and block scope, you almost never need IIFE anymore.

But you will still see it in:
✅ Old code
✅ Libraries
✅ Stackoverflow answers from 2010

It is very important to recognize it and know what it does.

## How to Explain

An IIFE is a function that is defined and invoked in the same expression, creating a private scope immediately. Before let and const existed, it was the only way to keep variables out of the global scope. The parentheses around the function make it an expression, and the trailing () calls it right away.

**The basic flow:**
```js
(function() {
  const secret = "private"
  console.log(secret)
})()
console.log(typeof secret) // "undefined"
```

The function runs once immediately. secret exists only inside it and is gone afterward, never leaking to the global scope.

**The part that trips everyone up:**

Writing (function() {})() without the wrapping parentheses is a syntax error — JavaScript parses it as a function declaration, which cannot be invoked inline. The outer parentheses are what turn it into an expression.

**The mistakes to remember:**
- Omitting the wrapping parentheses, causing a syntax error
- Thinking IIFEs run automatically without the trailing call — you must invoke them with ()
- Using IIFEs in modern code where a block with let/const achieves the same thing more cleanly
