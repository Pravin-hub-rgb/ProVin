Classes are a nice friendly way to create objects.

---

## ✅ Ok first: What are classes for?

Classes are just a blueprint for creating objects.

This is how you write a class:
```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    console.log(`${this.name} makes a sound`);
  }
}
```

✅ `constructor` runs automatically when you create a new object
✅ All methods you write inside the class are available on every object you create

---

## ✅ Creating objects from classes

```js
const cat = new Animal("Miaow");
cat.speak(); // Miaow makes a sound
```

✅ That's it. This is how everyone uses classes.

---

## ✅ Inheritance with `extends`

This is the nice part. Classes make inheritance extremely simple.

```js
class Dog extends Animal {
  constructor(name, breed) {
    super(name); // must call this first! This runs parent constructor
    this.breed = breed;
  }

  speak() {
    console.log(`${this.name} barks`);
  }
}
```

✅ `super()` = call parent constructor. You must call this before you can use `this` inside child constructor.

✅ If you write a method with same name, it overrides the parent one.

---

## ✅ Using it:

```js
const d = new Dog("Bruno", "Labrador");

d.speak(); // Bruno barks
```

---

## ✅ Static methods

Static methods are methods that live on the class itself, not on instances.

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  static create(name) {
    return new Animal(name);
  }
}
```

✅ You call them on the class directly, not on instances:

```js
const cat = Animal.create("Miaow");
```

---

## ✅ `instanceof` operator

Checks if something was created from this class:

```js
const d = new Dog("Bruno", "Lab");

d instanceof Dog;     // ✅ true
d instanceof Animal;  // ✅ true
```

## ✅ Now the big secret:

Ok now that you know how to use classes, I will tell you what they actually are.

✅ **ES6 Classes do not add anything new to JavaScript.**

They are just nicer looking syntax. Under the hood, everything works exactly the same as it always has.

✅ **When they say "syntax sugar" - this is exactly what they mean:**

Nothing changed inside JavaScript engine. No new features were added. They just invented a new way to write the exact same code you already were writing.

It is 100% cosmetic. Like painting your old car a different colour. The engine is exactly the same.

---

## ✅ Proof:

This is what everyone was writing before 2015:

```js
function Animal(name) {
  this.name = name;
}

Animal.prototype.speak = function() {
  console.log(`${this.name} makes a sound`);
};
```

✅ This does 100% exactly the same thing as the class we wrote earlier.

✅ You can prove this:
```js
console.log(typeof Animal); // "function"
```

`class Animal` did not create some new magic thing. It created a normal function. Exactly like `function Animal()` did.

And:
```js
console.log(typeof Animal.prototype.speak); // "function"
```

The `speak` method was added to `Animal.prototype` exactly like we were doing manually.

✅ There is zero difference.

The class syntax is just cleaner. That's all.

## 🎯 Interview Ready Answer

> "ES6 Classes are syntactic sugar over JavaScript's existing prototype-based inheritance. They provide a cleaner, more familiar syntax for creating objects and handling inheritance, but do not introduce any new object-oriented model to the language. Under the hood, classes still work with prototypes exactly as they did before."

That is the full correct answer.
