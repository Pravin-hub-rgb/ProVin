In the last topic, you learned about closures — how inner functions can remember outer variables. But there's another keyword that appears inside functions that confuses almost everyone: `this`.

You've probably seen `this` in code and wondered what it refers to. The answer is frustrating: it depends. But once you learn the rules, it's actually very predictable.

---

## The "Me" Analogy

Imagine you hear someone say: "Give this to me."

Who is "me"? It depends entirely on who is saying the sentence.

- If Rahul says it: "me" = Rahul
- If Priya says it: "me" = Priya
- If your mom says it: "me" = your mom

The word "me" has no meaning on its own. It only means something depending on who is speaking.

That's exactly how `this` works in JavaScript. `this` is like the word "me" — it refers to whoever is "speaking" (calling the function).

---

## ✅ What is `this`?

> **`this` is a special keyword inside functions that refers to the object that the function is a property of — determined by how the function is called.**

Let's unpack that.

**"Special keyword"** — `this` is not a variable, not a function, not an object. It's a keyword with special behavior that only exists inside functions.

**"Inside functions"** — `this` only has meaning inside a function. Outside any function, `this` is just the global object (`window` in browsers). All the interesting stuff happens inside functions.

**"Determined by how the function is called"** — this is the key. `this` is not determined by where the function is written. It's determined by how the function is called. The same function can have different `this` values depending on how you call it.

---

## ✅ The 4 rules of `this`

There are only 4 rules. Learn these, and you'll never be confused by `this` again.

### Rule 1: Default Binding (Global)

When you call a function without any context, `this` refers to the global object (`window` in browsers, `global` in Node.js).

```js
function showThis() {
  console.log(this);
}

showThis(); // window (in browser)
```

In strict mode, `this` is `undefined` instead of the global object:

```js
"use strict";
function showThis() {
  console.log(this);
}

showThis(); // undefined
```

### Rule 2: Implicit Binding (Object Method)

When you call a function as a method of an object, `this` refers to that object.

```js
const user = {
  name: "Arjun",
  greet: function() {
    console.log(`Hello, I'm ${this.name}`);
  }
};

user.greet(); // "Hello, I'm Arjun"
```

The object "owns" the function. When you call `user.greet()`, `this` inside `greet` is `user`.

```js
const user2 = {
  name: "Priya",
  greet: user.greet
};

user2.greet(); // "Hello, I'm Priya"
```

Same function, different `this`. Because `this` depends on how the function is called, not where it's defined.

### Rule 3: Explicit Binding (call, apply, bind)

You can force `this` to be whatever you want using `call`, `apply`, or `bind`.

```js
function greet() {
  console.log(`Hello, I'm ${this.name}`);
}

const user1 = { name: "Arjun" };
const user2 = { name: "Priya" };

greet.call(user1); // "Hello, I'm Arjun"
greet.call(user2); // "Hello, I'm Priya"
```

- `call(thisArg, arg1, arg2)` — calls the function with `this` set to `thisArg`
- `apply(thisArg, [args])` — same as call but arguments are in an array
- `bind(thisArg)` — returns a new function with `this` permanently bound

```js
const greetArjun = greet.bind(user1);
greetArjun(); // "Hello, I'm Arjun" — this is permanently user1
```

`bind` is especially useful for creating functions with a fixed `this`.

### Rule 4: `new` Binding (Constructor)

When you use a function with the `new` keyword, `this` refers to a newly created empty object.

```js
function User(name) {
  // this = {} (new empty object created by new)
  this.name = name;
  // this = { name: "Arjun" }
}

const arjun = new User("Arjun");
console.log(arjun.name); // "Arjun"
```

The `new` keyword:
1. Creates a new empty object
2. Sets `this` to that object
3. Runs the function
4. Returns the object (unless the function returns something else)

## ✅ Arrow functions and `this`

Arrow functions are the exception. They don't follow the 4 rules above.

**Arrow functions do NOT have their own `this`.** They inherit `this` from the surrounding lexical scope — wherever they were written, not wherever they were called.

```js
const user = {
  name: "Arjun",
  greet: () => {
    console.log(`Hello, I'm ${this.name}`);
  }
};

user.greet(); // "Hello, I'm undefined" — or window.name
```

This doesn't work because the arrow function doesn't have its own `this`. It uses `this` from the surrounding scope (the global scope), not from `user`.

This is why arrow functions are great for callbacks inside methods:

```js
const timer = {
  seconds: 0,
  start: function() {
    setInterval(() => {
      this.seconds++; // ✅ Arrow function inherits this from start()
    }, 1000);
  }
};
```

The arrow function inside `setInterval` doesn't create its own `this`. It uses `this` from `start()`, which is `timer`.

---

## ✅ What It Is NOT

- **`this` is NOT the function itself.** A common misconception is that `this` inside a function refers to the function. It doesn't. `this` refers to the object that owns the function at call time.

- **`this` is NOT determined by where the function is written.** It's determined by how the function is called. The same function can have different `this` values depending on the caller.

- **Arrow functions do NOT have their own `this`.** They inherit `this` from the surrounding scope. You cannot use `call`, `apply`, or `bind` to change `this` in an arrow function — it ignores them.

- **`this` is NOT the same in strict mode and non-strict mode.** In strict mode, default binding gives `undefined` instead of the global object. This is a safety feature to prevent accidental global pollution.

## 🧠 Interview Questions

> ❓ What is `this` in JavaScript?
> `this` is a special keyword inside functions that refers to the object that the function is a property of. Its value is determined by how the function is called, not where it's defined.

> ❓ What are the 4 rules that determine `this`?
> 1. Default binding — `this` is the global object (or undefined in strict mode)
> 2. Implicit binding — `this` is the object the method is called on
> 3. Explicit binding — `this` is set by call, apply, or bind
> 4. New binding — `this` is a new empty object created by `new`

> ❓ How does `this` work in arrow functions?
> Arrow functions don't have their own `this`. They inherit `this` from the surrounding lexical scope. You can't change `this` in an arrow function with call, apply, or bind.

> ❓ What is the difference between call, apply, and bind?
> call and apply immediately invoke the function with a specified `this`. call takes arguments individually, apply takes them as an array. bind returns a new function with `this` permanently bound, without invoking it.

> ❓ What is `this` in an event handler?
> In a regular function event handler, `this` refers to the element that triggered the event. In an arrow function event handler, `this` comes from the surrounding scope.

**Sample Answer:** No, you can't tell what "this" refers to without knowing who said it. "This" depends on the speaker. In JavaScript, `this` depends on how the function is called — the "speaker" is the object that calls the function. Without knowing the caller, you can't know what `this` is.

2. What will this code print? Why?

```js
const obj = {
  name: "My Object",
  log: function() {
    console.log(this.name);
  }
};

const fn = obj.log;
fn();
```

<details>
<summary>Show Answer</summary>

**Sample Answer:** It prints `undefined` (or `window.name` in browser). Even though `log` was defined as a method of `obj`, `this` is determined by how the function is called, not where it's defined. When you call `fn()`, there's no object context — it's a plain function call. So `this` falls back to the default binding (global object). To get "My Object", you'd need to call `obj.log()` or use `fn.call(obj)`.

</details>

3. What's the difference between `call`, `apply`, and `bind`? Give an example of when you'd use each.

<details>
<summary>Show Answer</summary>

**Sample Answer:** `call` and `apply` invoke the function immediately with a specified `this`. `call` takes arguments individually (`fn.call(obj, 1, 2)`), `apply` takes them as an array (`fn.apply(obj, [1, 2])`). `bind` returns a new function with `this` permanently set, without invoking it. Use `call` when you know the arguments. Use `apply` when arguments are in an array. Use `bind` when you need to create a callback with a fixed `this`.

</details>

4. Why can't you use `bind` to change `this` in an arrow function?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Arrow functions don't have their own `this`. They inherit `this` from the surrounding lexical scope at the time they're created. Since they don't have their own `this`, methods like `bind`, `call`, and `apply` that try to set `this` have no effect. The arrow function will always use the `this` from where it was written, regardless of how it's called.

</details>

5. What will this code print? Walk through each step.

```js
function identify() {
  return this.name;
}

const person = { name: "Arjun", identify };
const pet = { name: "Max", identify };

console.log(identify());
console.log(person.identify());
console.log(pet.identify());
console.log(identify.call({ name: "Stranger" }));
```

<details>
<summary>Show Answer</summary>

**Sample Answer:** `identify()` prints `undefined` (or `window.name`) — default binding, no context. `person.identify()` prints "Arjun" — implicit binding, `this` is `person`. `pet.identify()` prints "Max" — implicit binding, `this` is `pet`. `identify.call({ name: "Stranger" })` prints "Stranger" — explicit binding, `this` is the passed object. Same function, four different `this` values, because `this` depends on how the function is called.

</details>
