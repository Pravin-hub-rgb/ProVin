## What This Topic Is Asking (Simple Terms)

The `new` keyword creates an object from a constructor function. Understanding `new` means understanding what happens under the hood: object creation, prototype linking, `this` binding, and return. OOP (Object-Oriented Programming) in JavaScript is built on prototypes, not classes (classes are just sugar).

---

## The `new` Keyword — Step by Step

When you write `const p = new Person("Vin")`, JavaScript does 4 things:

1. **Creates a new empty object** `{}`.
2. **Links its prototype** to `Person.prototype` (so it inherits methods).
3. **Binds `this`** to the new object inside the constructor.
4. **Returns the new object** (implicitly, unless you return a different object).

```js
function Person(name, age) {
  this.name = name;   // step 3: this = new object
  this.age = age;
}

const p = new Person("Vin", 25);
// p = { name: "Vin", age: 25 }
// p.__proto__ === Person.prototype
```

### Without `new` — the bug

```js
const p = Person("Vin", 25);
// this = window (or undefined in strict mode)
// window.name = "Vin", window.age = 25 — BUG!
// p = undefined (no return statement)
```

**The fix:** Always use `new` with constructor functions. Or use classes (which enforce `new`).

---

## Prototype Chain

Every object has a `__proto__` (prototype) link. When you access a property, JavaScript walks up the chain until it finds it or reaches `null`.

```js
function Animal(name) {
  this.name = name;
}

Animal.prototype.speak = function() {
  return `${this.name} makes a sound`;
};

const dog = new Animal("Rex");
dog.speak(); // "Rex makes a sound"

// Prototype chain:
// dog → Animal.prototype → Object.prototype → null
```

### How property lookup works

```js
dog.speak();
// 1. Look on dog itself — not found
// 2. Look on dog.__proto__ (Animal.prototype) — found! Call it with this = dog
```

### Inheritance via prototype chain

```js
function Dog(name, breed) {
  Animal.call(this, name);  // call parent constructor
  this.breed = breed;
}

// Link Dog.prototype to Animal.prototype
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;

Dog.prototype.bark = function() {
  return `${this.name} barks!`;
};

const rex = new Dog("Rex", "Labrador");
rex.speak(); // "Rex makes a sound" (inherited from Animal)
rex.bark();  // "Rex barks!" (own method)
```

## Classes (ES6 Sugar)

Classes are syntactic sugar over prototypes — they do the same thing, just cleaner:

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    return `${this.name} makes a sound`;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);  // calls Animal constructor
    this.breed = breed;
  }

  bark() {
    return `${this.name} barks!`;
  }
}

const rex = new Dog("Rex", "Labrador");
rex.speak(); // "Rex makes a sound"
rex.bark();  // "Rex barks!"
```

**Under the hood, classes are prototypes.** `class` doesn't create a new OOP model — it's the same prototype chain with nicer syntax.

## `instanceof` and `hasOwnProperty`

```js
const rex = new Dog("Rex", "Labrador");

rex instanceof Dog;        // true
rex instanceof Animal;    // true
rex instanceof Object;    // true

// hasOwnProperty — check if property is on the object itself (not prototype)
rex.hasOwnProperty("name");   // true
rex.hasOwnProperty("speak");  // false (it's on Animal.prototype)
```

## Common Mistakes

- **Forgetting `new`** — `this` becomes `window` (or `undefined` in strict mode). The constructor's properties leak onto the global object. Always use `new`, or use classes (which throw if called without `new`).
- **Mutating prototype affecting all instances** — if you add a method to `Person.prototype` after creating instances, all instances get the method. This can be surprising. Use classes to keep things organized.
- **`__proto__` vs `prototype`** — `__proto__` is the instance's link to the prototype. `prototype` is the object that instances link to. `dog.__proto__ === Dog.prototype`.
- **Not setting `constructor` after `Object.create`** — if you do `Dog.prototype = Object.create(Animal.prototype)` without resetting `constructor`, `rex.constructor` will be `Animal` instead of `Dog`.

---

## What This Topic Is NOT

- ❌ Classes are not a new OOP model — they're syntactic sugar over prototypes. Under the hood, it's the same prototype chain.
- ❌ `new` is not the same as **Object.create** — `new` calls the constructor, `Object.create` just links the prototype. `Object.create(Animal.prototype)` creates an object without calling `Animal`.
- ❌ Prototype chain is not the same as **classical inheritance** — JS uses prototypal inheritance (objects link to objects), not classical (classes inherit from classes).
- ❌ `instanceof` is not the same as **`typeof`** — `typeof` returns a string ("object", "function"), `instanceof` checks the prototype chain.

2. What's the difference between `__proto__` and `prototype`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `__proto__` is a property on *instances* — it points to the prototype object the instance was created from. `prototype` is a property on *constructor functions* — it's the object that instances link to. Example: `const dog = new Dog();` → `dog.__proto__ === Dog.prototype`. `__proto__` is the link, `prototype` is the target.

</details>

3. Why are classes called "syntactic sugar" over prototypes?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Because classes don't create a new OOP model — they compile down to the same prototype chain. `class Dog extends Animal` does the same thing as `Dog.prototype = Object.create(Animal.prototype)` + `Dog.prototype.constructor = Dog`. The `class` syntax is cleaner and enforces `new`, but under the hood it's prototypes all the way down.

</details>

## Cheat Sheet (Quick Recall)

**`new` does 4 things:** create object → link prototype → bind `this` → return object.

**Prototype chain:** instance → constructor.prototype → Object.prototype → null.

**Property lookup:** check instance → check prototype → check parent prototype → ... → null.

**Inheritance:** `Child.prototype = Object.create(Parent.prototype)` + reset `constructor`.

**Classes:** syntactic sugar over prototypes. `class` / `extends` / `super()`.

**`instanceof`:** checks if an object is in a constructor's prototype chain.

**`hasOwnProperty`:** checks if property is on the object itself (not prototype).

**Key rule:** Always use `new` with constructors. Use classes for cleaner syntax. Remember: `__proto__` (instance link) vs `prototype` (constructor's object).
