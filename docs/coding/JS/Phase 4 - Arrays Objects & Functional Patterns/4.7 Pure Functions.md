## ✅ What is a Pure Function?

✅ There are only 2 rules. That is all.

✅ **Rule 1:** Same input → always same output
✅ **Rule 2:** No side effects. It does not change anything outside of itself.

If a function follows both rules → it is pure.

---

## ✅ Pure Function Example:

```js
function add(a, b) {
  return a + b;
}
```

✅ Always returns 5 when you call `add(2, 3)`. Always. Every single time.
✅ It does not change anything else in your program.
✅ It does not read anything from outside.

---

## ✅ Impure Function Examples:

❌ **Depends on external state:**
```js
let tax = 0.18;

function calculateTotal(price) {
  return price * tax;
}
```
✅ Same input can give different output if someone changes the tax variable.

❌ **Modifies external state:**
```js
let total = 0;

function addToTotal(n) {
  total += n;
}
```
✅ This changes something outside the function. This is a side effect.

❌ **Non deterministic:**
```js
function getTime() {
  return Date.now();
}
```
✅ Always returns different output even though you call it the exact same way.

---

## ✅ Why is this important?

✅ Pure functions are 100% predictable.
✅ You can test them without any setup.
✅ You can memoize them safely.
✅ They never cause bugs outside of themselves.

✅ This is the entire foundation that React is built on.
✅ This is the reason React works.

## How to Explain

A pure function always returns the same output for the same input and produces no side effects. It doesn't read or modify anything outside itself. Predictability makes pure functions trivially testable and safely memoizable, and they are the foundation React is built on.

**The basic flow:**
```js
function add(a, b) { return a + b }
```

add(2, 3) is always 5. It reads nothing external and changes nothing external. Compare to Date.now() or a function that mutates a global — those are impure.

**The part that trips everyone up:**

A function that only reads external state is still impure even if it never modifies anything. If the external value changes between calls, the same input produces different output. Purity requires both no side effects and deterministic output.

**The mistakes to remember:**
- Calling Math.random or Date.now inside a function and calling it pure
- Mutating an argument object and returning it — mutation is a side effect
- Assuming const parameters guarantee purity — const prevents reassignment, not mutation

## 🧠 Interview Questions

> ❓ What are the two rules of pure functions?
> Same input always gives same output. No side effects.

> ❓ What is a side effect?
> Any change to state outside the function itself.

> ❓ Why does React care about pure functions?
> Because pure functions are predictable and enable all React optimizations.
