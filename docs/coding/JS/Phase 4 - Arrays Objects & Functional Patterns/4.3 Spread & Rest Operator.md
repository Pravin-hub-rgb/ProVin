The single most useful syntax feature in modern JavaScript.

---

## ✅ There are two operators:

✅ They look exactly the same: `...`

✅ They do exact opposite things. Which one it is depends on where you use it.

---

## ✅ Spread Operator

Before spread, simple operations on arrays and objects were surprisingly painful.

Want to copy an array? You had to use `.slice()`:

```js
const copy = arr.slice();  // read this and think "slice... what slice?"
```

Want to merge two objects? `Object.assign()`:

```js
const merged = Object.assign({}, defaults, userSettings);
// reads backwards. easy to forget the empty {} first arg.
```

Want to update an object property without mutating it? You had to create a new object and manually copy every field:

```js
const updated = { name: user.name, age: 32, email: user.email };
// and if user has 10 more fields? you forget one and it's gone.
```

Spread does all of this in one clean, readable syntax. It expands an array or object into individual values wherever you need them.

✅ **Spread = EXPAND**

✅ Copy array:
```js
const arr1 = [1, 2, 3];
const newArr = [...arr1]; // ✅ New array, no mutation
```

✅ Combine arrays:
```js
const arr2 = [...arr1, 4, 5, 6]; // [1, 2, 3, 4, 5, 6]
```

✅ Copy object:
```js
const newUser = { ...user };
```

✅ Update object without mutation:
```js
const updatedUser = { ...user, age: 32 };
```

✅ Merge objects:
```js
const merged = { ...defaults, ...userSettings };
```

✅ **Important:** Later values always override earlier ones.

## ✅ Rest Operator

What if a function needs to accept any number of arguments — like `sum(1, 5)` or `sum(1, 5, 3, 9, 2)`? You cannot know ahead of time how many will be passed.

Before rest, you had to use the `arguments` object, which is not a real array:

```js
function sum() {
  let total = 0;
  for (let i = 0; i < arguments.length; i++) {
    total += arguments[i];
  }
  return total;
}
// No .reduce() available on arguments
```

Rest solves this. It collects remaining values into a **real** array.

✅ **Rest = COLLECT**

✅ In function parameters:
```js
function sum(first, ...rest) {
  return first + rest.reduce((a, b) => a + b, 0);
}

sum(1, 2, 3, 4, 5); // 15
```

✅ In destructuring:
```js
const [first, second, ...others] = arr;
```

✅ Rest must always be the last parameter.

## ✅ Immutability & Pure Updates

In other docs we saw `.map()`, `.filter()` — these are all **pure functions**. They don't mutate the original array; they return a new array. But the real question is: **why not mutate? What's the problem with mutation?**

### ❌ Problem: Mutation

Mutation means changing existing data:

```js
const arr = [1, 2, 3];
arr.push(4);     // ❌ arr is now [1, 2, 3, 4] — mutated
arr[0] = 99;     // ❌ arr is now [99, 2, 3, 4] — also mutated

const obj = { name: "Rahul", age: 25 };
obj.age = 26;    // ❌ obj is now { name: "Rahul", age: 26 } — mutate
```

Mutation itself isn't wrong. The problem happens when **another piece of code shares the same reference**:

```js
const arr = [1, 2, 3];
const fn1 = (data) => { data.push(4); return data; };
const fn2 = (data) => data.reduce((a, b) => a + b, 0);

const result1 = fn1(arr); // arr is now [1, 2, 3, 4]
const result2 = fn2(arr); // 10 — but this is wrong!
// fn2 should have run on [1, 2, 3], but fn1 mutated arr
```

This is called a **side effect**. One function changed data, and another function got corrupted. These bugs are **hard to track** because mutation can happen anywhere.

### ❌ `const` doesn't prevent mutation

```js
const arr = [1, 2, 3];
arr = [4, 5, 6]; // ❌ Error — const doesn't allow reassignment
arr.push(4);     // ✅ Works! — const doesn't prevent mutation
arr[0] = 99;     // ✅ Works! — same
```

`const` only **prevents reassignment** — you can't write `arr = something`. But `.push()`, `.pop()`, `arr[i] = x`, `obj.k = v` — all of these are allowed mutations.

### ✅ The Immutability Principle

> **Don't mutate. Create new.**

Leave old data as-is. Creating new data means a new reference. Code using the old reference stays safe.

### ✅ Immutable Array Patterns

| Mutation | Immutable |
|----------|-----------|
| `arr.push(x)` | `[...arr, x]` |
| `arr[i] = x` | `arr.map((item, idx) => idx === i ? x : item)` |
| `arr.pop()` | `arr.slice(0, -1)` |
| `arr.splice(i, 1)` | `arr.filter((_, idx) => idx !== i)` |
| `arr.unshift(x)` | `[x, ...arr]` |

```js
const arr = [1, 2, 3];

// ❌ Mutation
arr.push(4);

// ✅ Immutable
const newArr = [...arr, 4]; // [1, 2, 3, 4]
console.log(arr);           // [1, 2, 3] — original safe!
```

### ✅ Immutable Object Patterns

| Mutation | Immutable |
|----------|-----------|
| `obj.k = v` | `{ ...obj, k: v }` |
| `delete obj.k` | `Object.fromEntries(Object.entries(obj).filter(([key]) => key !== "k"))` or `const { k, ...rest } = obj; rest` |

```js
const user = { name: "Rahul", age: 25, city: "Delhi" };

// ❌ Mutation
user.age = 26;

// ✅ Immutable
const updated = { ...user, age: 26 };
console.log(user);    // { name: "Rahul", age: 25, city: "Delhi" } — original safe!
console.log(updated); // { name: "Rahul", age: 26, city: "Delhi" }

// ✅ Delete property immutably
const { city, ...rest } = user;
console.log(rest);    // { name: "Rahul", age: 25 } — city removed
```

### ⚠️ Deep vs Shallow Copy

Spread copies one level deep — **shallow copy**:

```js
const obj = {
  name: "Rahul",
  address: { city: "Delhi", pincode: 110001 }
};

const copy = { ...obj };
copy.name = "Raj";           // ✅ Original safe — name is a string, copy was made
copy.address.city = "Mumbai"; // ❌ Original also changed!
// address is a nested object — spread copied the reference, not the value
```

**How to fix?** Spread each nested level separately:

```js
const deepCopy = {
  ...obj,
  address: { ...obj.address, city: "Mumbai" }
};
// ✅ Original.address safe — { city: "Delhi", pincode: 110001 }
```

### ✅ Deep Copy Methods

#### JSON.parse / JSON.stringify — the simple way

The quickest way to deep-copy a JSON-compatible object:

```js
const original = {
  name: "Arjun",
  address: { city: "Delhi", pincode: 110001 }
};

const deepCopy = JSON.parse(JSON.stringify(original));
deepCopy.address.city = "Mumbai";

console.log(original.address.city); // "Delhi" — original is safe!
console.log(deepCopy.address.city); // "Mumbai"
```

`JSON.stringify` converts the object to a JSON string. `JSON.parse` parses it back into a completely new object. Since strings are immutable and passed by value, every nested level gets its own new reference.

**Limitations:** `JSON.stringify` silently drops values that JSON does not support:
- `undefined` becomes omitted
- Functions are removed entirely
- `Date` objects become strings
- `NaN` and `Infinity` become `null`
- Symbol keys are dropped

```js
const data = {
  name: "Arjun",
  birthday: new Date(),
  handler: () => {},
  missing: undefined,
  notANumber: NaN
};

const broken = JSON.parse(JSON.stringify(data));
// Result: { name: "Arjun", birthday: "2025-01-15T...", notANumber: null }
// handler and missing are gone. birthday is a string, not a Date.
```

#### structuredClone — the modern way

`structuredClone` is a built-in function (available in modern browsers and Node.js 17+) that handles deep copy properly:

```js
const original = {
  name: "Arjun",
  birthday: new Date("2000-01-01"),
  handler: () => {},
  nested: { deep: { value: 42 } }
};

const deepCopy = structuredClone(original);
deepCopy.nested.deep.value = 99;
console.log(original.nested.deep.value); // 42 — original is safe!
console.log(deepCopy.nested.deep.value);  // 99
```

`structuredClone` handles Dates, RegExps, Maps, Sets, nested arrays, and more — everything `JSON.stringify` breaks on.

**One limitation:** `structuredClone` throws on functions and symbols:

```js
const data = { fn: () => "hello" };
structuredClone(data); // ❌ DataCloneError: The object could not be cloned
```

#### Custom recursive deep copy — when you need full control

For edge cases that `structuredClone` does not cover (like copying functions), you can write your own:

```js
function deepClone(obj, hash = new WeakMap()) {
  if (obj === null || typeof obj !== "object") return obj;
  if (hash.has(obj)) return hash.get(obj);

  if (obj instanceof Date) return new Date(obj);
  if (obj instanceof RegExp) return new RegExp(obj);

  const clone = Array.isArray(obj) ? [] : {};
  hash.set(obj, clone); // Handle circular references

  for (const key of Object.keys(obj)) {
    clone[key] = deepClone(obj[key], hash);
  }

  return clone;
}
```

The `WeakMap` here prevents infinite loops on circular references:

```js
const a = { name: "Arjun" };
a.self = a; // circular reference
const copy = deepClone(a); // Works! No stack overflow.
```

## ✅ What It Is NOT (Deep Copy Edition)

- **Shallow copy (spread `{...obj}`) is NOT the same as deep copy.** Spread only copies one level. Nested objects are still shared references. If you modify a nested property in the copy, the original changes too.

- **`JSON.parse(JSON.stringify())` is NOT perfect.** It silently loses `undefined`, functions, Symbols, and converts `Date` objects to strings. Don't use it if your data has any of these.

- **`structuredClone` is NOT available everywhere.** It requires modern environments (Node.js 17+, all modern browsers). If you need to support older browsers, use a polyfill or JSON methods.

- **`Object.assign({}, obj)` is NOT a deep copy.** It is also a shallow copy — exactly the same as spread. Nested objects are shared references.

### 🔗 Why This Matters in React

React compares state by **reference**. When you call `setItems(items)`, React sees: "This is the same reference — nothing changed. Don't re-render."

```js
// ❌ React won't re-render
items.push(newItem);
setItems(items);  // same reference → React ignores

// ✅ React will re-render
setItems([...items, newItem]); // new reference → React updates
```

That's why in React you always use spread / `.map()` / `.filter()`. Never mutate.

### ✅ Summary

- Mutation = changing existing data
- `const` doesn't prevent mutation — only reassignment
- Side effects = a mutation that breaks other code
- Immutable = create new, don't touch the old
- Spread = the most common tool for immutable updates of arrays and objects
- Shallow copy = one level deep — nested objects need nested spread
- React = needs a new reference for re-render — that's why spread is mandatory

## 🧠 Interview Questions

> ❓ What is the difference between spread and rest?
> Spread expands values. Rest collects values. They use the same syntax but do exact opposite operations.

> ❓ Does spread operator do deep copy?
> No. It only copies one level. Nested objects are still shared references.

> ❓ Why is spread operator used so much in React?
> To update state immutably without mutating the original array/object.

> ❓ Does spread produce a deep copy? What are the alternatives?
> No — spread produces a shallow copy (one level only). Nested objects are still shared references. For deep copies: use `JSON.parse(JSON.stringify(obj))` for simple data (loses `undefined`, functions, Dates), `structuredClone(obj)` for modern environments (handles Dates, Maps, Sets, but throws on functions), or a custom recursive function for full control (needed if you must clone functions or handle circular references).
