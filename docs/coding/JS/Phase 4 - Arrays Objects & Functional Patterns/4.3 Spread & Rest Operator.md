The single most useful syntax feature in modern JavaScript.

---

## ✅ There are two operators:

✅ They look exactly the same: `...`

✅ They do exact opposite things. Which one it is depends on where you use it.

---

## ✅ Spread Operator

Before spread, simple operations on arrays and objects were surprisingly painful.

Want to copy an array? You had to use `.slice()`:
```js
const copy = arr.slice();  // read this and think "slice... what slice?"
```

Want to merge two objects? `Object.assign()`:
```js
const merged = Object.assign({}, defaults, userSettings);
// reads backwards. easy to forget the empty {} first arg.
```

Want to update an object property without mutating it? You had to create a new object and manually copy every field:
```js
const updated = { name: user.name, age: 32, email: user.email };
// and if user has 10 more fields? you forget one and it's gone.
```

Spread does all of this in one clean, readable syntax. It expands an array or object into individual values wherever you need them.

✅ **Spread = EXPAND**

✅ Copy array:
```js
const arr1 = [1, 2, 3];
const newArr = [...arr1]; // ✅ New array, no mutation
```

✅ Combine arrays:
```js
const arr2 = [...arr1, 4, 5, 6]; // [1, 2, 3, 4, 5, 6]
```

✅ Copy object:
```js
const newUser = { ...user };
```

✅ Update object without mutation:
```js
const updatedUser = { ...user, age: 32 };
```

✅ Merge objects:
```js
const merged = { ...defaults, ...userSettings };
```

✅ **Important:** Later values always override earlier ones.

## ✅ Rest Operator

What if a function needs to accept any number of arguments — like `sum(1, 5)` or `sum(1, 5, 3, 9, 2)`? You cannot know ahead of time how many will be passed.

Before rest, you had to use the `arguments` object, which is not a real array:

```js
function sum() {
  let total = 0;
  for (let i = 0; i < arguments.length; i++) {
    total += arguments[i];
  }
  return total;
}
// No .reduce() available on arguments
```

Rest solves this. It collects remaining values into a **real** array.

✅ **Rest = COLLECT**

✅ In function parameters:
```js
function sum(first, ...rest) {
  return first + rest.reduce((a, b) => a + b, 0);
}

sum(1, 2, 3, 4, 5); // 15
```

✅ In destructuring:
```js
const [first, second, ...others] = arr;
```

✅ Rest must always be the last parameter.

## ✅ Immutability & Pure Updates

Baaki docs mein humne `.map()`, `.filter()` dekha — yeh sab **pure functions** hain. Yeh original array nahi badalte, naya array return karte hain. Lekin asli sawaal yeh hai: **kyun nahi badalte? Mutation mein kya problem hai?**

### ❌ Problem: Mutation

Mutation ka matlab — existing data ko change karna:

```js
const arr = [1, 2, 3];
arr.push(4);     // ❌ arr ab [1, 2, 3, 4] — mutate ho gaya
arr[0] = 99;     // ❌ arr ab [99, 2, 3, 4] — aur mutate

const obj = { name: "Rahul", age: 25 };
obj.age = 26;    // ❌ obj ab { name: "Rahul", age: 26 } — mutate
```

Mutation apne aap mein galat nahi hai. Problem tab hoti hai jab **doosra code bhi same reference share kare**:

```js
const arr = [1, 2, 3];
const fn1 = (data) => { data.push(4); return data; };
const fn2 = (data) => data.reduce((a, b) => a + b, 0);

const result1 = fn1(arr); // arr ab [1, 2, 3, 4]
const result2 = fn2(arr); // 10 — but yeh galat hai!
// fn2 sirf [1, 2, 3] pe chalna chahiye tha, lekin fn1 ne arr mutate kar diya
```

Isse **side effect** kehte hain. Ek function ne data change kar diya, doosra function corrupt ho gaya. Yeh bugs **track karna mushkil** hote hain kyunki mutation kahin bhi ho sakta hai.

### ❌ `const` doesn't prevent mutation

```js
const arr = [1, 2, 3];
arr = [4, 5, 6]; // ❌ Error — const reassignment nahi kar sakta
arr.push(4);     // ✅ Works! — const mutation nahi rokta
arr[0] = 99;     // ✅ Works! — same
```

`const` sirf **reassignment rokta hai** — `arr = something` nahi likh sakte. Lekin `.push()`, `.pop()`, `arr[i] = x`, `obj.k = v` — yeh sab mutation allowed hain.

### ✅ The Immutability Principle

> **Mutate mat karo. Naya banao.**

Purana data waisa ka waisa rahne do. Naya data banana = new reference. Jo code purana reference use kar raha hai, woh safe hai.

### ✅ Immutable Array Patterns

| Mutation | Immutable |
|----------|-----------|
| `arr.push(x)` | `[...arr, x]` |
| `arr[i] = x` | `arr.map((item, idx) => idx === i ? x : item)` |
| `arr.pop()` | `arr.slice(0, -1)` |
| `arr.splice(i, 1)` | `arr.filter((_, idx) => idx !== i)` |
| `arr.unshift(x)` | `[x, ...arr]` |

```js
const arr = [1, 2, 3];

// ❌ Mutation
arr.push(4);

// ✅ Immutable
const newArr = [...arr, 4]; // [1, 2, 3, 4]
console.log(arr);           // [1, 2, 3] — original safe!
```

### ✅ Immutable Object Patterns

| Mutation | Immutable |
|----------|-----------|
| `obj.k = v` | `{ ...obj, k: v }` |
| `delete obj.k` | `Object.fromEntries(Object.entries(obj).filter(([key]) => key !== "k"))` ya `const { k, ...rest } = obj; rest` |

```js
const user = { name: "Rahul", age: 25, city: "Delhi" };

// ❌ Mutation
user.age = 26;

// ✅ Immutable
const updated = { ...user, age: 26 };
console.log(user);    // { name: "Rahul", age: 25, city: "Delhi" } — original safe!
console.log(updated); // { name: "Rahul", age: 26, city: "Delhi" }

// ✅ Delete property immutably
const { city, ...rest } = user;
console.log(rest);    // { name: "Rahul", age: 25 } — city removed
```

### ⚠️ Deep vs Shallow Copy

Spread ek level deep copy karta hai — **shallow copy**:

```js
const obj = {
  name: "Rahul",
  address: { city: "Delhi", pincode: 110001 }
};

const copy = { ...obj };
copy.name = "Raj";           // ✅ Original safe — name string hai, copy ho gaya
copy.address.city = "Mumbai"; // ❌ Original bhi change ho gaya!
// address ek nested object hai — spread ne reference copy kiya, value nahi
```

**Kaise fix karein?** Har nested level ke liye alag spread karna padta hai:

```js
const deepCopy = {
  ...obj,
  address: { ...obj.address, city: "Mumbai" }
};
// ✅ Original.address safe — { city: "Delhi", pincode: 110001 }
```

### 🔗 Why This Matters in React

React state ko **reference se compare** karta hai. Jab tum `setItems(items)` karte ho, React dekhta hai: "Yeh toh wahi reference hai — kuch nahi badla. Re-render nahi karna."

```js
// ❌ React won't re-render
items.push(newItem);
setItems(items);  // same reference → React ignores

// ✅ React will re-render
setItems([...items, newItem]); // new reference → React updates
```

Isliye React mein hamesha spread / `.map()` / `.filter()` use karte hain. Mutation kabhi nahi.

### ✅ Summary

- Mutation = existing data change karna
- `const` mutation nahi rokta — sirf reassignment rokta hai
- Side effects = ek mutation jo doosre code ko tod de
- Immutable = naya banao, purana mat chhedo
- Spread = arrays aur objects ke liye immutable update ka sabse common tool
- Shallow copy = ek level deep — nested objects ke liye nested spread chahiye
- React = new reference chahiye re-render ke liye — isliye spread mandatory hai

## ✅ React use cases

✅ Pass all props down:
```jsx
function Button(props) {
  return <button {...props} className="btn" />;
}
```

✅ Update state immutably:
```js
setUsers([...users, newUser]);
```

This is the most common pattern in React. You will write this every day.

## ✅ Common mistakes:

❌ Spread only does **shallow copy**. Nested objects are still references.
❌ You cannot spread objects into arrays.
❌ Rest operator must be last.

## 🧠 Interview Questions

> ❓ What is the difference between spread and rest?
> Spread expands values. Rest collects values. They use the same syntax but do exact opposite operations.

> ❓ Does spread operator do deep copy?
> No. It only copies one level. Nested objects are still shared references.

> ❓ Why is spread operator used so much in React?
> To update state immutably without mutating the original array/object.
