# 7.5 — Symbol

## Cheat Sheet (Quick Recall)

- `Symbol` is a unique, immutable primitive.
- Every Symbol is different, even with the same description.
- Use as object property keys (won't collide with string keys).
- `Object.getOwnPropertySymbols(obj)` to retrieve.

## `Symbol` — unique primitive

```js
const sym1 = Symbol("id");
const sym2 = Symbol("id");
sym1 === sym2; // false — each Symbol is unique

// Use as object property keys
const ID = Symbol("id");
const user = {
  name: "Vin",
  [ID]: 42,  // computed property with Symbol key
};

user[ID];      // 42
user.name;     // "Vin"

// Symbols don't show up in for...in or Object.keys()
Object.keys(user);           // ["name"]
Object.getOwnPropertySymbols(user); // [Symbol(id)]
```

**Well-known Symbols:** `Symbol.iterator`, `Symbol.toStringTag`, `Symbol.hasInstance` — used to customize built-in behavior.

## Common Mistakes

- Using `new Symbol()` (throws — use `Symbol()`).
- Forgetting Symbol keys are hidden from `Object.keys`.
- Assuming two Symbols with same description are equal.

## Try It Yourself

1. Create two Symbols with same description and compare.
2. Use a Symbol as an object key.
3. Retrieve Symbol keys with `getOwnPropertySymbols`.

## Summary

- `Symbol` is unique, immutable primitive.
- Use as object property keys.
- Hidden from `Object.keys`/`for...in`.

## What It Is NOT

- `Symbol` is **not** a string.
- `new Symbol()` is **not** valid — use `Symbol()`.
- Two Symbols with same description are **not** equal.
