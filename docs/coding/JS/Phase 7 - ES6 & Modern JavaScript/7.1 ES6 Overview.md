## 1. Default Parameters

Function parameters can have default values:

```js
function greet(name = "stranger") {
  return `Hello, ${name}!`;
}

greet("Vin");      // "Hello, Vin!"
greet();           // "Hello, stranger!"
greet(undefined);  // "Hello, stranger!" (undefined triggers default)
greet(null);       // "Hello, null!" (null does NOT trigger default)
```

**Arrow functions with defaults:**

```js
const multiply = (a = 1, b = 1) => a * b;
multiply();       // 1
multiply(5);      // 5
multiply(5, 3);   // 15
```

## 2. for...of and for...in

### `for...of` — iterate over values of an iterable

```js
const arr = [10, 20, 30];
for (const val of arr) {
  console.log(val); // 10, 20, 30
}

// Works on strings, Sets, Maps
for (const char of "hello") console.log(char); // h, e, l, l, o
```

### `for...in` — iterate over keys of an object

```js
const user = { name: "Vin", age: 25 };
for (const key in user) {
  console.log(key, user[key]); // "name Vin", "age 25"
}
```

**Warning:** `for...in` iterates over *all enumerable properties*, including inherited ones. Use `for...of` for arrays, `for...in` for objects. Or better, use `Object.keys()`, `Object.values()`, `Object.entries()`.

## 3. Map & Set

### `Set` — collection of unique values

```js
const set = new Set([1, 2, 2, 3]);
// Set {1, 2, 3} — duplicates removed

set.add(4);       // Set {1, 2, 3, 4}
set.has(2);       // true
set.delete(2);    // Set {1, 3, 4}
set.size;         // 3

// Remove duplicates from array
const unique = [...new Set([1, 2, 2, 3])]; // [1, 2, 3]
```

### `Map` — key-value pairs, any type as key

```js
const map = new Map();
map.set("name", "Vin");
map.set(42, "answer");
map.set({ id: 1 }, "object key");

map.get("name");   // "Vin"
map.has(42);       // true
map.size;          // 3
map.delete("name");

// Iterate
for (const [key, value] of map) {
  console.log(key, value);
}

// Convert
const obj = Object.fromEntries(map);  // Map → Object
const m = new Map(Object.entries(obj)); // Object → Map
```

**Map vs Object:**

| Feature | Object | Map |
|---------|--------|-----|
| Key types | string, symbol | any type |
| Key order | insertion order (mostly) | insertion order (guaranteed) |
| Size | `Object.keys(obj).length` | `map.size` |
| Iteration | `for...in`, `Object.keys()` | `for...of`, `.forEach()` |
| Performance | slower for frequent add/remove | faster for frequent add/remove |

## 4. Symbol

A `Symbol` is a unique, immutable primitive. Every Symbol is different, even with the same description.

```js
const sym1 = Symbol("id");
const sym2 = Symbol("id");
sym1 === sym2; // false — each Symbol is unique

// Use as object property keys (won't collide with string keys)
const ID = Symbol("id");
const user = {
  name: "Vin",
  [ID]: 42,  // computed property with Symbol key
};

user[ID];      // 42
user.name;     // "Vin"

// Symbols don't show up in for...in or Object.keys()
Object.keys(user);           // ["name"]
Object.getOwnPropertySymbols(user); // [Symbol(id)]
```

**Well-known Symbols:** `Symbol.iterator`, `Symbol.toStringTag`, `Symbol.hasInstance` — used to customize built-in behavior.

## 5. Object Shorthand

ES6 allows shorthand property names and method definitions:

```js
const name = "Vin";
const age = 25;

// Before ES6
const user = { name: name, age: age, greet: function() { return "hi"; } };

// ES6 shorthand
const user2 = { name, age, greet() { return "hi"; } };

// Method shorthand
const calculator = {
  add(a, b) { return a + b; },
  subtract(a, b) { return a - b; },
};
```

## Common Mistakes

- **Using `for...in` on arrays** — iterates indices as strings, includes inherited properties. Use `for...of` or `forEach` for arrays.
- **Assuming `Set` preserves insertion order** — it does (in modern JS), but don't rely on it for logic.
- **Using `Map` when `Object` is fine** — for string keys, objects are simpler. Use Map when keys are non-strings or when you need guaranteed insertion order.
- **Creating Symbols without `Symbol()`** — `Symbol` without `new` throws. Always call `Symbol()`, don't use `new Symbol()`.
- **Forgetting that `Map` keys are compared by reference** — `{ a: 1 } !== { a: 1 }` as Map keys. Use primitives or interned strings.

## What This Topic Is NOT

- ❌ ES6 is not a **separate language** — it's JavaScript. ES6 = ECMAScript 2015 = a version of JavaScript.
- ❌ ES6 features are not **optional** — they're now standard. All modern browsers and Node.js support them.
- ❌ `let`/`const` are not the same as **`var`** — `var` is function-scoped and hoisted, `let`/`const` are block-scoped.
- ❌ `Map` is not the same as **`Object`** — Map allows any key type, preserves insertion order, has `.size`. Object has string/symbol keys, no guaranteed order (mostly), no `.size`.
- ❌ `Set` is not the same as **`Array`** — Set removes duplicates, has `.has()` (O(1)), and is optimized for membership checks.

## In Your Own Words

1. What is a generic in TypeScript? (Wait, this is JS — skip.) What is a `Set`, and how is it different from an array?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A `Set` is a collection of unique values — duplicates are automatically removed. Unlike an array, a Set is optimized for membership checks (`set.has(value)` is O(1) vs `arr.includes(value)` is O(n)). Use a Set when you need to track unique items or check membership frequently. Convert to array with `[...set]`.

</details>

2. What's the difference between `for...of` and `for...in`? Give an example of each.

<details>
<summary>Show Answer</summary>

**Sample Answer:** `for...of` iterates over values of an iterable (arrays, strings, Sets, Maps): `for (const v of [1,2,3]) console.log(v)` → 1, 2, 3. `for...in` iterates over keys of an object: `for (const k in {a:1, b:2}) console.log(k)` → "a", "b". Don't use `for...in` on arrays — it iterates indices as strings and includes inherited properties.

</details>

3. Why would you use a `Map` instead of a plain object?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use a `Map` when: (1) keys are not strings (numbers, objects, functions), (2) you need guaranteed insertion order, (3) you need frequent add/remove (Map is optimized for this), (4) you need `.size` (objects need `Object.keys().length`). Use a plain object for simple string-keyed data where you don't need those features.

</details>

## Cheat Sheet (Quick Recall)

**Default params:** `function fn(x = 0) {}` — default triggers on `undefined`, not `null`.

**for...of:** `for (const v of arr) {}` — values of iterable.

**for...in:** `for (const k in obj) {}` — keys of object.

**Set:** `new Set([1, 2, 2, 3])` → `{1, 2, 3}`. `.add()`, `.has()`, `.delete()`, `.size`. Convert: `[...set]`.

**Map:** `new Map()`. `.set(key, val)`, `.get(key)`, `.has(key)`, `.delete(key)`, `.size`. Iterate: `for (const [k, v] of map)`.

**Symbol:** `Symbol("id")` — unique primitive. Use as object keys. `Object.getOwnPropertySymbols(obj)`.

**Object shorthand:** `{ name, age, greet() {} }` — shorthand for `{ name: name, age: age, greet: function() {} }`.

**Key rule:** ES6 features are now standard. Use them everywhere. `let`/`const` over `var`. Arrow functions for callbacks. Template literals for strings. Destructuring for clean code. Spread/rest for copying/collecting. Classes for OOP. Modules for organization.<|end|>
