## ✅ What is async / await?

✅ It is 100% syntax sugar over Promises.

It does not add any new features. It just makes Promises look like normal synchronous code. No more `.then()` chains.

---

## ✅ How it works:

```js
async function getUserData(id) {
  try {
    const response = await fetch(`/api/users/${id}`);
    const data = await response.json();
    return data;
  } catch (err) {
    console.error("Error:", err);
  }
}
```

✅ 2 simple rules:
1.  Add `async` keyword before function
2.  Use `await` keyword before any Promise

✅ `await` pauses the function execution until the Promise resolves.

---

## ✅ The most common mistake:

❌ **WRONG — sequential, slow**
```js
const a = await fetch('/api/a');
const b = await fetch('/api/b');
const c = await fetch('/api/c');
```

✅ This takes 3 seconds. It waits for each one to finish before starting the next.

✅ **RIGHT — parallel, fast**
```js
const [a, b, c] = await Promise.all([
  fetch('/api/a'),
  fetch('/api/b'),
  fetch('/api/c')
]);
```

✅ This takes 1 second. All run at the same time.

---

## ✅ When to use what:

| Method | Use case |
|---|---|
| `await` one by one | When operations depend on previous results |
| `Promise.all()` | When all operations are independent |

## 🧠 Interview Questions

> ❓ Does async/await replace Promises?
> No. It is just syntax sugar. Under the hood it is still exactly Promises.

> ❓ Can you use await outside an async function?
> No. Not at the top level, unless you are in ES Modules.

> ❓ What is the advantage of async/await?
> Code is much easier to read, debug, and it uses normal try/catch for error handling.
