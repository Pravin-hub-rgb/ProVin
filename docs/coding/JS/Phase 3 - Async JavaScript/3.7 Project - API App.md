## What This Topic Is Asking (Simple Terms)

An API app fetches data from a server and displays it. The pattern: show "Loading...", fetch the data, show it (or show an error). This is the culmination of everything — async/await, fetch, DOM manipulation, error handling.

---

## The Pattern

```js
async function loadPosts() {
  const container = document.querySelector("#posts");
  container.innerHTML = "<p>Loading...</p>";

  try {
    const res = await fetch("https://jsonplaceholder.typicode.com/posts?_limit=5");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const posts = await res.json();
    container.innerHTML = posts
      .map((p) => `<article><h3>${p.title}</h3><p>${p.body}</p></article>`)
      .join("");
  } catch (e) {
    container.innerHTML = `<p>Failed: ${e.message}</p>`;
  }
}

loadPosts();
```

---

## Step by Step

### Step 1: Show loading state

```js
const container = document.querySelector("#posts");
container.innerHTML = "<p>Loading...</p>";
```

Always show something immediately so the user knows the app is working.

### Step 2: Fetch the data

```js
const res = await fetch("https://jsonplaceholder.typicode.com/posts?_limit=5");
```

`fetch` returns a Promise. `await` pauses until the response arrives. The URL includes `?_limit=5` to get only 5 posts.

### Step 3: Check if the response is OK

```js
if (!res.ok) throw new Error(`HTTP ${res.status}`);
```

`fetch` resolves even on 404/500 errors — it only rejects on network failure. Always check `res.ok` (status 200-299). If not OK, throw so the catch block handles it.

### Step 4: Parse JSON

```js
const posts = await res.json();
```

`res.json()` also returns a Promise (parsing takes time). `await` it to get the actual data.

### Step 5: Render the data

```js
container.innerHTML = posts
  .map((p) => `<article><h3>${p.title}</h3><p>${p.body}</p></article>`)
  .join("");
```

Transform the array of posts into HTML strings, join them, and set as `innerHTML`.

### Step 6: Handle errors

```js
} catch (e) {
  container.innerHTML = `<p>Failed: ${e.message}</p>`;
}
```

If anything fails (network error, bad response, parse error), show a friendly error message.

## Why Check `res.ok`?

```js
// fetch resolves even on 404/500 — it only rejects on network failure
const res = await fetch("/api/nonexistent");
console.log(res.ok);       // false
console.log(res.status);    // 404
// Without the check, res.json() would try to parse an error page
```

**Status codes:**
- 2xx (200-299): Success — `res.ok` is `true`
- 4xx (400-499): Client error (bad request, not found, unauthorized)
- 5xx (500-599): Server error

## HTTP Methods

```js
// GET (default)
fetch(url);

// POST (create)
fetch(url, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "New Post", body: "Content" }),
});

// PUT (replace)
fetch(url, { method: "PUT", body: JSON.stringify(data) });

// PATCH (partial update)
fetch(url, { method: "PATCH", body: JSON.stringify({ title: "Updated" }) });

// DELETE
fetch(url, { method: "DELETE" });
```

## Common Mistakes

- **Not checking `res.ok`** — `fetch` resolves on 404/500. Without the check, you try to parse an error page as JSON.
- **Forgetting `await` on `res.json()`** — `res.json()` returns a Promise. Without `await`, you get a Promise, not data.
- **Not handling loading state** — if the fetch takes 3 seconds, the user sees nothing. Always show "Loading..." first.
- **Not handling errors** — network can fail, API can be down. Always wrap in try/catch.
- **Sequential awaits where `Promise.all` fits** — if you need multiple independent fetches, use `Promise.all` instead of awaiting one by one.

---

## What This Topic Is NOT

- ❌ Fetch API is not the same as **Axios** — Axios is a library that wraps fetch with extra features (interceptors, automatic JSON parsing, timeout). Fetch is built into the browser.
- ❌ `fetch` is not the same as **XMLHttpRequest** — XHR is the older API. Fetch is modern and uses Promises.
- ❌ `res.json()` is not the same as **`JSON.parse()`** — `res.json()` reads the response body and parses it. `JSON.parse()` parses a string you already have.

## In Your Own Words

1. Why do you need to check `res.ok` after a `fetch` call? What happens if you don't?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `fetch` resolves even on HTTP errors (404, 500) — it only rejects on network failure. Without `res.ok` check, you'd try to parse an error page as JSON, which might fail or produce garbage data. `res.ok` is `true` for 2xx status codes. Always check it before parsing.

</details>

2. What's the difference between `fetch` rejecting and `res.ok` being false?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `fetch` rejects (throws) only on network failure — no internet, DNS failure, CORS block. `res.ok` is `false` when the server responds with an error status (404, 500, 401) — the request reached the server, but the server said "error." So `fetch` = "did the request reach the server?" `res.ok` = "did the server say success?"

</details>

3. When would you use `Promise.all` instead of sequential `await`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use `Promise.all` when you have multiple independent fetches that don't depend on each other. Sequential: `const a = await fetchA(); const b = await fetchB();` — takes 2 seconds (1s + 1s). Parallel: `const [a, b] = await Promise.all([fetchA(), fetchB()])` — takes 1 second (both at once). Use sequential only when the second fetch needs data from the first.

</details>

## Cheat Sheet (Quick Recall)

**Fetch + check + parse:**
```js
const res = await fetch(url);
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const data = await res.json();
```

**Methods:** GET (default), POST, PUT, PATCH, DELETE.

**POST body:** `body: JSON.stringify(obj)` + `headers: { "Content-Type": "application/json" }`.

**Status:** 2xx = ok, 4xx = client error, 5xx = server error.

**Pattern:** Loading → Fetch → Check → Parse → Render → Catch errors.

**Key rule:** Always check `res.ok`. Always wrap in try/catch. Always show loading state. Use `Promise.all` for independent fetches.
