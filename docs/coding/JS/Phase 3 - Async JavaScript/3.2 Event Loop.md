This is the most asked interview question in all of JavaScript. 90% of developers don't actually understand this.

---

## ✅ Start with the most important fact:

✅ **JavaScript is single threaded.**

It can only do one thing at a time. It has only one call stack.

But it can handle thousands of concurrent operations. How? Because of the Event Loop.

---

## ✅ How this connects to async / sync code:

✅ **All synchronous code runs directly on the Call Stack.** It blocks everything.

✅ **All asynchronous code goes to Web APIs first.**

- `setTimeout` → goes to Web API timer
- `fetch` → goes to Web API network
- `addEventListener` → goes to Web API DOM events

JavaScript doesn't wait. It hands them off to the browser immediately and continues. When the operation is finished, the browser sends the callback to the appropriate queue.

✅ This is why async code doesn't block. The browser is doing the waiting, not JavaScript.

---

## ✅ The 5 parts:

There are only 5 parts you need to know:

| Part | What it does |
|---|---|
| 1. Call Stack | Where your code actually runs. One thing at a time. Last In First Out. |
| 2. Web APIs | The browser handles async stuff here. setTimeout, fetch, clicks, timers all live here. |
| 3. Microtask Queue | Promise callbacks go here. Highest priority. |
| 4. Callback Queue | All other callbacks go here. Lower priority. |
| 5. Event Loop | The boss. Decides what runs next. |

---

## ✅ What does the Event Loop actually do?

✅ It is an infinite loop that does only one check:

> **Is the Call Stack empty?**

- ✅ If NO: do nothing. Wait.
- ✅ If YES:
  1.  First run **everything** in the Microtask Queue
  2.  Then run **one single thing** from the Callback Queue
  3.  Repeat

---

## ✅ The famous interview question:

What is the output?
```js
console.log("1");

setTimeout(() => console.log("2"), 0); // macrotask

Promise.resolve().then(() => console.log("3")); // microtask

console.log("4");
```

✅ **Output:**
```
1
4
3
2
```

✅ **Order of execution:**
1.  ✅ Run all synchronous code first: `1`, `4`
2.  ✅ Call Stack is empty
3.  ✅ Drain entire Microtask Queue: print `3`
4.  ✅ Call Stack is empty again
5.  ✅ Take one from Callback Queue: print `2`

---

## ✅ This is the exact rule:

1.  Run all synchronous code
2.  Run **all** microtasks
3.  Run **one** macrotask
4.  Repeat

That is it. That is the entire event loop.

## 🎯 Interview Ready Answer

> "JavaScript is single threaded with one call stack. The event loop enables non-blocking behaviour by offloading async operations to the browser Web APIs. When the call stack is empty, the event loop will first process all microtasks such as promise callbacks, before processing a single macrotask from the callback queue."

That is the full correct answer.
