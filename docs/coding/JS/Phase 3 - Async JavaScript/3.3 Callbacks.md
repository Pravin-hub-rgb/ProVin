This is the original way JavaScript handled async operations.

## ✅ First: Higher Order Function

Before you understand callbacks you need to understand this:

✅ **Higher Order Function** = any function that accepts another function as an argument.

That is it. That is the full definition.

Examples:
```js
setTimeout(() => {}, 1000);
[1,2,3].map(x => x * 2);
button.addEventListener("click", () => {});
```

All of these are higher order functions. And that is all callbacks are.

---

## ✅ What is a Callback?

A callback is just the function that you pass into a higher order function.

```js
function fetchData(callback) {
  setTimeout(() => {
    callback("data received");
  }, 1000);
}

fetchData(function(data) {
  console.log(data);
});
```

✅ Let's break this down line by line:

1.  `fetchData` is a normal function
2.  We pass another function as the **first argument** when we call `fetchData`
3.  Inside `fetchData` that argument is named `callback`
4.  `callback` is not a magic keyword. It is just a parameter name. We could call it anything.
5.  After 1 second, `fetchData` calls that function for us.

✅ You do not call it. The function you gave it to will call it back later.

This is how all async code was written for 20 years.

## ✅ Callback Hell

This is what actual callback hell looks like in real code:

```js
getUser(userId, function(user) {
  getPosts(user.id, function(posts) {
    getComments(posts[0].id, function(comments) {
      getLikes(comments[0].id, function(likes) {
        // You cannot escape this nesting
      });
    });
  });
});
```

✅ First you need a user
✅ Then you need their posts
✅ Then you need comments for that post
✅ Then you need likes for that comment

Every step depends on the previous result. So you have to keep nesting deeper and deeper.

✅ This is unreadable.
✅ Impossible to debug.
✅ Impossible to handle errors properly.

This is the exact problem that Promises were invented to solve.

## 🧠 Interview Questions

> ❓ What is callback hell?
> When you have multiple async operations that depend on each other, resulting in deeply nested callbacks that move rightwards across the screen. They are extremely hard to read, debug and handle errors.
>
> Example:
> ```js
> getUser(id, () => {
>   getPosts(() => {
>     getComments(() => {
>       // keeps going right
>     })
>   })
> })
> ```

> ❓ Why were Promises introduced?
> To solve callback hell. Promises allow you to chain async operations vertically instead of nesting them horizontally, and also provide a standardised way to handle errors.

> ❓ What is higher order function?
> Any function that can either accept another function as an argument, or return a function as a result.
>
> Example: `setTimeout`, `array.map`, `array.forEach` all accept callbacks and are higher order functions.

## 🎯 Interview Ready Answer

> "A callback is a function passed as an argument to be executed at a later time. They were the primary method for handling asynchronous operations in JavaScript before Promises were introduced. Deeply nested callbacks create what is known as callback hell, which led to the adoption of Promises and async/await."

That is the full correct answer.
