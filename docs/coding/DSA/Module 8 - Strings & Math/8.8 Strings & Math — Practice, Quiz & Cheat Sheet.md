## Mini Quiz

1. How do you handle subtractive pairs (IV, IX) in Roman to Integer?
2. Why use `mid <= x / mid` instead of `mid * mid <= x` in Sqrt(x) / Pow?
3. In the Sieve of Eratosthenes, why start the inner loop at p² instead of 2p?
4. What is the time complexity of binary exponentiation (fast power)?
5. Why reverse the StringBuilder at the end of Add Binary?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. Check if `value(current) < value(next)`. If so, subtract current (subtractive pair like IV=4). Otherwise, add current. The last character is always added (no next to compare).
2. `mid * mid` can overflow for large values of mid. `mid <= x / mid` checks the same condition (`mid² ≤ x`) using division, which doesn't overflow. This is the safe way to compare squares.
3. Multiples smaller than p² (like 2p, 3p, ..., (p-1)p) have already been marked as composite by smaller primes. Starting at p² avoids redundant work. It's an optimization, not a correctness requirement (starting at 2p still works but is slower).
4. O(log n) — each step halves n (n → n/2 → n/4 → ... → 1). log₂(n) steps. Compare to O(n) for naive multiplication.
5. We build the result right-to-left (appending the least significant bit first). The actual binary string is most-significant-bit first, so we reverse at the end. Using StringBuilder with reverse is O(n); using String concatenation would be O(n²).

</details>

## One-Page Cheat Sheet

**Roman to Integer:**
```java
for (int i = 0; i < s.length() - 1; i++) {
    int cur = val.get(s.charAt(i)), next = val.get(s.charAt(i + 1));
    total += (cur < next) ? -cur : cur;
}
total += val.get(s.charAt(s.length() - 1));
```

**Fast Power (binary exponentiation):**
```java
double result = 1, base = x;
long N = (n < 0) ? -(long) n : n;
if (n < 0) base = 1 / x;
while (N > 0) {
    if ((N & 1) == 1) result *= base;
    base *= base;
    N >>= 1;
}
```

**Sieve of Eratosthenes:**
```java
boolean[] isPrime = new boolean[n];
Arrays.fill(isPrime, true);
isPrime[0] = isPrime[1] = false;
for (int p = 2; (long) p * p < n; p++) {
    if (isPrime[p])
        for (int m = p * p; m < n; m += p) isPrime[m] = false;
}
```

**Add Binary:**
```java
StringBuilder sb = new StringBuilder();
int i = a.length()-1, j = b.length()-1, carry = 0;
while (i >= 0 || j >= 0 || carry > 0) {
    int sum = carry;
    if (i >= 0) sum += a.charAt(i--) - '0';
    if (j >= 0) sum += b.charAt(j--) - '0';
    sb.append(sum % 2);
    carry = sum / 2;
}
return sb.reverse().toString();
```

**Longest Common Prefix (vertical scan):**
```java
for (int i = 0; i < strs[0].length(); i++) {
    char c = strs[0].charAt(i);
    for (int j = 1; j < strs.length; j++) {
        if (i >= strs[j].length() || strs[j].charAt(i) != c)
            return strs[0].substring(0, i);
    }
}
return strs[0];
```

## In Your Own Words

1. How do you handle subtractive pairs in Roman to Integer?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Walk the string comparing each value with the next. If current < next, subtract current (subtractive pair like IV=4, IX=9). Otherwise add current. Add the last character separately (it's never subtracted). This handles all subtractive pairs (IV, IX, XL, XC, CD, CM) in one pass.

</details>

2. Why is the Sieve of Eratosthenes faster than checking each number for primality?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Checking each number individually is O(n × √n) (trial division up to √n per number). The Sieve marks all multiples of each prime in one pass — O(n log log n). It avoids redundant checks: once a number is marked composite by a smaller prime, it's never checked again. The inner loop starts at p² because smaller multiples are already marked.

</details>

3. What is binary exponentiation, and why is it O(log n)?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Binary exponentiation computes x^n by squaring: x^n = (x²)^(n/2) if n even, x × (x²)^((n-1)/2) if n odd. Each step halves n, so there are log₂(n) steps. Compare to naive multiplication (n steps). The iterative version processes the binary digits of n: for each bit, square the base; if the bit is 1, multiply into the result.

</details>
