**Problem:** Convert a Roman numeral string to an integer. (LeetCode #13)

**Link:** https://leetcode.com/problems/roman-to-integer/

---

## Which Technique, and Why?

Roman numerals: I=1, V=5, X=10, L=50, C=100, D=500, M=1000. Subtractive pairs: IV=4, IX=9, XL=40, XC=90, CD=400, CM=900. 

The rule: if a numeral's value is less than the next numeral's value, subtract it; otherwise add it. This is a single pass with a lookup map. O(n) time, O(1) space.

**Signal in the problem:** "Roman to integer" → map char → value, single pass, subtract when current < next.

## Approach

Build a map of Roman char → value. Walk the string: if `value(s[i]) < value(s[i+1])`, subtract `value(s[i])`; else add. Add the last character's value.

## Pseudocode

```
map = {I:1, V:5, X:10, L:50, C:100, D:500, M:1000}
total = 0
for i from 0 to n-2:
    if value(s[i]) < value(s[i+1]): total -= value(s[i])
    else: total += value(s[i])
total += value(s[n-1])
return total
```

## Java Code

```java
class Solution {
    public int romanToInt(String s) {
        Map<Character, Integer> val = new HashMap<>();
        val.put('I', 1); val.put('V', 5); val.put('X', 10);
        val.put('L', 50); val.put('C', 100); val.put('D', 500);
        val.put('M', 1000);

        int total = 0;
        for (int i = 0; i < s.length() - 1; i++) {
            int cur = val.get(s.charAt(i));
            int next = val.get(s.charAt(i + 1));
            if (cur < next) total -= cur;
            else total += cur;
        }
        total += val.get(s.charAt(s.length() - 1));
        return total;
    }
}
```

## Line-by-line

- `val` maps Roman chars to integers.
- Loop from 0 to n-2: compare current with next.
- `cur < next` → subtractive pair (IV, IX, etc.) → subtract current.
- Otherwise → additive → add current.
- After the loop, add the last character's value (it's always added — never subtracted because there's nothing after it).

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — fixed map of 7 entries.

## Common Mistakes

- **Subtractive pairs missed.** IV = 4 (not 6). Check `cur < next` before adding.
- **Adding the last character inside the loop.** The loop goes to n-2; the last char is added separately. Don't double-count.
- **Invalid input.** Problem guarantees valid Roman numerals. Don't over-validate.
- **Using a switch instead of a map.** Both work; a map is cleaner. A switch might be faster (no hashing).

## How to Explain (interview)

**Opening:** Roman to Integer converts a Roman numeral to an integer. Map each char to its value. Walk the string: if the current value is less than the next, subtract it (subtractive pair like IV=4); otherwise add it. Add the last character at the end. O(n) time, O(1) space.

**The basic flow:**
```java
for (int i = 0; i < s.length() - 1; i++) {
    int cur = val.get(s.charAt(i)), next = val.get(s.charAt(i + 1));
    total += (cur < next) ? -cur : cur;
}
total += val.get(s.charAt(s.length() - 1));
```

**The part that trips everyone up:** the subtractive rule — IV is 4, not 6. Check `current < next` to decide subtract vs add. Also, the last character is always added (handled separately).

**The mistakes to remember:**
- Forgetting subtractive pairs (IV, IX, XL, XC, CD, CM)
- Double-counting the last character
- Not handling single-character input (loop doesn't execute, returns that char's value)
