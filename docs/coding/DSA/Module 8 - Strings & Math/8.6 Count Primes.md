**Problem:** Given an integer n, return the number of prime numbers strictly less than n. (LeetCode #204)

**Link:** https://leetcode.com/problems/count-primes/

---

## Which Technique, and Why?

"Count primes less than n" → **Sieve of Eratosthenes**. Mark all multiples of each prime starting from p². O(n log log n) time, O(n) space. Far faster than checking each number individually (O(n × √n)).

**Signal in the problem:** "count primes" / "primes less than n" → Sieve of Eratosthenes.

## Approach

1. Create a boolean array `isPrime` of size n, initialized to true.
2. Set `isPrime[0] = isPrime[1] = false` (0 and 1 are not prime).
3. For p from 2 to √n: if `isPrime[p]` is true, mark all multiples of p starting from p² as composite (false).
4. Count the true values.

**Why start at p²?** Multiples smaller than p² (like 2p, 3p, ...) have already been marked by smaller primes. Starting at p² avoids redundant work.

## Pseudocode

```
if n <= 2: return 0
isPrime = array of true (size n)
isPrime[0] = isPrime[1] = false
for p from 2 to sqrt(n):
    if isPrime[p]:
        for multiple from p*p to n-1 step p:
            isPrime[multiple] = false
return count of true in isPrime
```

## Java Code

```java
class Solution {
    public int countPrimes(int n) {
        if (n <= 2) return 0;

        boolean[] isPrime = new boolean[n];
        Arrays.fill(isPrime, true);
        isPrime[0] = isPrime[1] = false;

        for (int p = 2; (long) p * p < n; p++) {
            if (isPrime[p]) {
                for (int multiple = p * p; multiple < n; multiple += p) {
                    isPrime[multiple] = false;
                }
            }
        }

        int count = 0;
        for (boolean prime : isPrime) {
            if (prime) count++;
        }
        return count;
    }
}
```

## Line-by-line

- `if (n <= 2) return 0` — no primes below 2.
- `Arrays.fill(isPrime, true)` — assume all prime initially.
- `isPrime[0] = isPrime[1] = false` — 0 and 1 are not prime.
- Outer loop: `p` from 2 to √n. `(long) p * p < n` avoids overflow.
- Inner loop: mark multiples of p starting from p². Step by p.
- Count remaining true values.

## Complexity

- Time: O(n log log n) — the sieve. Much faster than O(n × √n) (checking each number).
- Space: O(n) — the boolean array.

## Common Mistakes

- **Starting inner loop at 2p instead of p².** 2p, 3p, ..., (p-1)p have already been marked by smaller primes. Start at p² to avoid redundant work (and for correctness with the optimization).
- **Overflow in `p * p`.** For large n, `p * p` can overflow int. Use `(long) p * p < n` in the condition and cast in the inner loop.
- **Off-by-one in the bound.** Primes are strictly less than n. The array size is n, indices 0 to n-1. Correct.
- **Not handling n ≤ 2.** Returns 0. Also n = 0 or 1 → 0.

## How to Explain (interview)

**Opening:** Count Primes counts primes less than n using the Sieve of Eratosthenes. Create a boolean array (all true), mark 0 and 1 as non-prime, then for each p from 2 to √n, mark all multiples of p (starting from p²) as composite. Count the remaining true values. O(n log log n) time, O(n) space.

**The basic flow:**
```java
boolean[] isPrime = new boolean[n];
Arrays.fill(isPrime, true);
isPrime[0] = isPrime[1] = false;
for (int p = 2; (long) p * p < n; p++) {
    if (isPrime[p])
        for (int m = p * p; m < n; m += p) isPrime[m] = false;
}
```

**The part that trips everyone up:** start the inner loop at `p * p`, not `2 * p` (smaller multiples already marked). Also use `(long) p * p` to avoid overflow.

**The mistakes to remember:**
- Starting inner loop at 2p instead of p² (redundant work, but still correct — just slow)
- Overflow in `p * p` (use long)
- Off-by-one: primes are strictly less than n (array size n)
- Not handling n ≤ 2 (return 0)
