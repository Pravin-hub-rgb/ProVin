**Problem:** Implement `pow(x, n)` — compute x raised to the power n. (LeetCode #50)

**Link:** https://leetcode.com/problems/powx-n/

---

## Which Technique, and Why?

Computing x^n by multiplying x n times is O(n) — too slow for large n. **Binary exponentiation (fast power)** computes it in O(log n) by squaring: x^n = (x²)^(n/2) if n is even, x × (x²)^((n-1)/2) if n is odd.

**Signal in the problem:** "pow" / "x^n" / "exponentiation" → binary exponentiation (fast power).

## Approach

Recursive or iterative. If n is even: `pow(x, n) = pow(x*x, n/2)`. If n is odd: `pow(x, n) = x * pow(x*x, (n-1)/2)`. Handle negative n by computing `1 / pow(x, -n)`.

## Pseudocode (recursive)

```
if n == 0: return 1
if n < 0: return 1 / pow(x, -n)
if n % 2 == 1: return x * pow(x * x, (n - 1) / 2)
else: return pow(x * x, n / 2)
```

## Java Code (recursive, with overflow safety)

```java
class Solution {
    public double myPow(double x, int n) {
        if (n == 0) return 1;
        if (n < 0) {
            x = 1 / x;
            n = -n;  // careful: -Integer.MIN_VALUE overflows
        }
        // use long to avoid overflow when n = Integer.MIN_VALUE
        return fastPow(x, (long) n);
    }

    private double fastPow(double x, long n) {
        if (n == 0) return 1;
        double half = fastPow(x, n / 2);
        if (n % 2 == 0) return half * half;
        else return half * half * x;
    }
}
```

## Java Code (iterative)

```java
class Solution {
    public double myPow(double x, int n) {
        long N = n;
        if (N < 0) {
            x = 1 / x;
            N = -N;
        }
        double result = 1;
        double base = x;
        while (N > 0) {
            if ((N & 1) == 1) result *= base;  // if odd, multiply
            base *= base;                       // square
            N >>= 1;                            // divide by 2
        }
        return result;
    }
}
```

## Line-by-line (iterative)

- `N = n` as long to handle `Integer.MIN_VALUE` (negating int overflows).
- If n < 0: x = 1/x, N = -N.
- `result` accumulates the answer; `base` is the current power of x.
- Loop: if N is odd, multiply result by base. Square base. Halve N (bit shift).
- This processes the binary representation of n — O(log n) iterations.

## Complexity

- Time: O(log n) — halves n each step.
- Space: O(1) iterative, O(log n) recursive (stack).

## Common Mistakes

- **Overflow when n = Integer.MIN_VALUE.** `-Integer.MIN_VALUE` overflows int. Use `long` for n.
- **Floating point precision.** For very large n, results may have precision issues. The problem accepts a small epsilon.
- **Not handling n = 0.** x^0 = 1 for any x (including 0^0, which Java defines as 1).
- **Recursive stack overflow.** For n up to 10⁹, recursion depth is ~30 — fine. But iterative is safer.

## How to Explain (interview)

**Opening:** Pow(x, n) computes x^n. The naive approach multiplies x n times — O(n). Binary exponentiation (fast power) does it in O(log n) by squaring: if n is even, x^n = (x²)^(n/2); if odd, x^n = x × (x²)^((n-1)/2). Handle negative n by computing 1/pow(x, -n). Use `long` for n to avoid overflow on Integer.MIN_VALUE.

**The basic flow (iterative):**
```java
double result = 1, base = x;
long N = (n < 0) ? -(long) n : n;
if (n < 0) x = 1 / x; base = x;
while (N > 0) {
    if ((N & 1) == 1) result *= base;
    base *= base;
    N >>= 1;
}
```

**The part that trips everyone up:** `Integer.MIN_VALUE` negation overflows. Use `long`. Also, `mid * mid` isn't relevant here, but the principle of avoiding overflow applies.

**The mistakes to remember:**
- Overflow on `n = Integer.MIN_VALUE` (use long)
- Not handling n = 0 (return 1)
- Floating point precision for very large results
- Recursion depth (fine for log n, but iterative is safer)
