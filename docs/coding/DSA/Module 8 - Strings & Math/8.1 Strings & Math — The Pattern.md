## The Core Idea

**Strings** are sequences of characters. Most string problems are array problems in disguise: two pointers (palindrome, reverse), sliding window (longest substring), hashing (anagrams, frequency). A few are string-specific: prefix matching, base conversion, Roman numerals.

**Math** problems involve number theory: primes (sieve), exponentiation (fast power), base conversion (binary ↔ decimal), GCD/LCM. The key skill is recognizing when a problem is really a math problem disguised as a string problem (e.g., "Add Binary" = base-2 addition).

## How to Recognize It

Think "Strings & Math" when:
- The problem involves **string manipulation**: reversing, splitting, comparing, finding substrings, converting between cases.
- The problem involves **prefixes/suffixes** of strings → compare char by char (Longest Common Prefix).
- The problem involves **number systems**: binary, decimal, Roman, hexadecimal → base conversion.
- The problem involves **primes** → Sieve of Eratosthenes.
- The problem involves **exponentiation** → fast power (binary exponentiation, O(log n)).
- Keywords: "longest common prefix," "Roman to integer," "find substring," "pow," "count primes," "add binary."

## Worked Example: Longest Common Prefix

**Problem:** Find the longest common prefix among an array of strings.

### Brute force (O(n × m))

Compare every pair of strings char by char. Works but redundant.

### Optimized (O(n × m)) — vertical scanning

```java
class Solution {
    public String longestCommonPrefix(String[] strs) {
        if (strs == null || strs.length == 0) return "";

        for (int i = 0; i < strs[0].length(); i++) {
            char c = strs[0].charAt(i);
            for (int j = 1; j < strs.length; j++) {
                if (i >= strs[j].length() || strs[j].charAt(i) != c) {
                    return strs[0].substring(0, i);
                }
            }
        }
        return strs[0]; // first string is the common prefix
    }
}
```

**Line-by-line:**
- Outer loop: index `i` into the first string (the candidate prefix length).
- Inner loop: check if all other strings have the same char at index `i`.
- If any string is too short (`i >= strs[j].length()`) or has a different char → return the prefix so far.
- If all match, the whole first string is the common prefix.

**Key insight:** vertical scanning (compare column by column) is simpler than horizontal (compare string by string). Both are O(n × m) where n = number of strings, m = min length.

Alternative: sort the array and compare first and last strings (O(n log n + m)).

## Common Mistakes

- **Not handling empty array or empty strings.** `strs = []` or `strs = [""]` → return `""`.
- **Index out of bounds.** When `i >= strs[j].length()`, that string is shorter — stop.
- **Roman numeral parsing:** IV = 4 (subtractive), VI = 6 (additive). Check if current value < next value → subtract.
- **Base conversion errors.** Binary addition: carry propagates left. Use `StringBuilder` for efficiency.
- **Sieve of Eratosthenes:** mark multiples starting from p², not 2p (2p is already marked by 2). Start inner loop at `p * p`.
- **Fast power overflow:** `mid * mid` in sqrt; use `mid <= x / mid`. For `pow`, use `long` for intermediate to avoid overflow.

## How to Explain (interview)

**Opening:** Strings & Math covers string manipulation (prefix matching, substring search, base conversion) and number theory (primes, exponentiation). String problems usually reduce to array techniques (two pointers, sliding window, hashing). Math problems reduce to number theory (sieve, fast power, base conversion). The key skill is recognizing when a "string problem" is really a math problem (like "Add Binary").

**The basic flow (string prefix):**
```java
for (int i = 0; i < strs[0].length(); i++) {
    char c = strs[0].charAt(i);
    for (int j = 1; j < strs.length; j++) {
        if (i >= strs[j].length() || strs[j].charAt(i) != c)
            return strs[0].substring(0, i);
    }
}
return strs[0];
```

**The part that trips everyone up:** vertical vs horizontal scanning — both work, vertical is simpler. For Roman numerals, check subtractive pairs (IV, IX, XL, XC, CD, CM). For base conversion, use `StringBuilder` and handle carry.

**The mistakes to remember:**
- Not handling empty strings/arrays
- Index out of bounds when strings have different lengths
- Roman numeral: subtractive pairs (current < next → subtract)
- Sieve: start inner loop at p², not 2p
- Fast power: use long to avoid overflow
