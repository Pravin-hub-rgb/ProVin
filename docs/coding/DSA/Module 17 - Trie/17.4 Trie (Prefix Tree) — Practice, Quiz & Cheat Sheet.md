## Mini Quiz

1. What is the difference between `search` and `startsWith` in a Trie?
2. Why is a Trie's insert/search O(L) where L is the word length?
3. When would you use a HashMap for children instead of an array of 26?
4. How would you find all words in a Trie with a given prefix?
5. What is the space complexity of a Trie with n words of average length L?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. `search(word)` returns true only if the complete word was inserted (checks `isEnd`). `startsWith(prefix)` returns true if any word starts with that prefix (only checks the path exists). "app" inserted → search("app") = true, startsWith("ap") = true, search("ap") = false.
2. Insert/search walks one node per character. Each step is O(1) (array index or map lookup). Total O(L) where L = word/prefix length. Independent of how many words are in the Trie.
3. Use a HashMap when the alphabet is large or unknown (uppercase, unicode, digits). An array of 26 assumes lowercase a–z. HashMap is more memory-efficient for sparse tries (few children per node) but slower (hashing overhead).
4. Walk to the node representing the prefix (O(L)). Then DFS from that node, collecting all words (following paths where isEnd = true). This gives all words with that prefix.
5. O(n × L) in the worst case (no shared prefixes). With shared prefixes, less. Each node has up to 26 children pointers (208 bytes per node for array-based). HashMap-based is more compact for sparse tries.

</details>

## One-Page Cheat Sheet

**Trie node:**
```java
class TrieNode {
    TrieNode[] children = new TrieNode[26]; // or Map<Character, TrieNode>
    boolean isEnd = false;
}
```

**Core operations:**
```java
void insert(String word) {
    TrieNode node = root;
    for (char c : word.toCharArray()) {
        int idx = c - 'a';
        if (node.children[idx] == null) node.children[idx] = new TrieNode();
        node = node.children[idx];
    }
    node.isEnd = true;
}

boolean search(String word) {
    TrieNode node = findNode(word);
    return node != null && node.isEnd;
}

boolean startsWith(String prefix) {
    return findNode(prefix) != null;
}
```

**Complexities:** Insert O(L), Search O(L), StartsWith O(L). Space O(n × L) worst case.

## In Your Own Words

1. What is a Trie, and when would you use one over a HashSet?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A Trie is a tree where each node represents a character, and paths from root to marked nodes spell words. Use a Trie over a HashSet when you need prefix search ("all words starting with X"), autocomplete, or when you need to find all words matching a pattern. HashSet gives O(1) exact-match lookup but can't do prefix search efficiently. Trie gives O(L) prefix search where L = prefix length.

</details>

2. What is the difference between `search` and `startsWith`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `search(word)` returns true only if the complete word was inserted (checks `isEnd`). `startsWith(prefix)` returns true if any word has that prefix (only checks the path exists, regardless of `isEnd`). E.g., insert "apple": search("app") = false, startsWith("app") = true, search("apple") = true.

</details>

3. Why is a Trie's insert O(L) where L is the word length?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Insert walks one node per character. Each step is O(1) (array index or map lookup). Total steps = L = word length. This is independent of how many words are already in the Trie — the path for a new word may share nodes with existing words (shared prefix), but the walk is still O(L).

</details>
