# 21.15 Unique Paths II

**Tier 2 problem.** (LeetCode #63)

**Problem:** Same as Unique Paths (#62), but some cells are obstacles (0 = free, 1 = obstacle). Return 0 if start or end is an obstacle. (LeetCode #63)

**Link:** https://leetcode.com/problems/unique-paths-ii/

---

## Which Technique, and Why?

"Unique paths with obstacles" → **DP (2D)** with obstacle handling. `dp[i][j] = 0` if obstacle. Otherwise `dp[i][j] = dp[i-1][j] + dp[i][j-1]`. O(m × n) time, O(n) space (optimized).

**Signal in the problem:** "unique paths" + "obstacles" → DP with obstacle check.

## Approach

Same as Unique Paths, but if `grid[i][j] == 1` (obstacle), `dp[i][j] = 0`. Also, if start or end is an obstacle → return 0.

## Pseudocode

```
if grid[0][0] == 1 or grid[m-1][n-1] == 1: return 0
dp = new int[n], all 0
dp[0] = 1  // first column (if no obstacle)
for i from 0 to m-1:
    for j from 0 to n-1:
        if grid[i][j] == 1: dp[j] = 0
        else if j > 0: dp[j] = dp[j] + dp[j-1]
return dp[n-1]
```

## Java Code

```java
class Solution {
    public int uniquePathsWithObstacles(int[][] obstacleGrid) {
        int m = obstacleGrid.length, n = obstacleGrid[0].length;
        if (obstacleGrid[0][0] == 1 || obstacleGrid[m - 1][n - 1] == 1) return 0;

        int[] dp = new int[n];
        dp[0] = 1;  // start cell (guaranteed free)

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (obstacleGrid[i][j] == 1) {
                    dp[j] = 0;
                } else if (j > 0) {
                    dp[j] = dp[j] + dp[j - 1];
                }
                // if j == 0 and not obstacle, dp[j] stays (from above, previous row)
            }
        }
        return dp[n - 1];
    }
}
```

## Line-by-line

- Check start/end are free.
- `dp[0] = 1` — start cell.
- For each cell: if obstacle → `dp[j] = 0` (no paths through). Else if `j > 0` → `dp[j] = dp[j] + dp[j-1]` (from above + from left). If `j == 0` and not obstacle → `dp[j]` stays (from above only, previous row's value).
- Return `dp[n-1]`.

## Complexity

- Time: O(m × n).
- Space: O(n) — optimized from O(m × n).

## Common Mistakes

- **Not checking start/end obstacles.** If start or end is an obstacle → 0.
- **Not handling the first column.** `j == 0`: only from above (`dp[0]` stays). Don't add `dp[-1]`.
- **Using `dp[j] = dp[j] + dp[j-1]` when obstacle.** Set to 0 first, then the `else if` skips. The code handles this with the if/else.
- **Confusing with Unique Paths (#62).** Same recurrence, just with obstacle check.

## How to Explain (interview)

**Opening:** Unique Paths II is Unique Paths with obstacles. Same DP, but if a cell is an obstacle, `dp = 0` (no paths through). Also, if start or end is an obstacle → return 0. O(m×n) time, O(n) space.

**The basic flow:**
```java
if (start or end is obstacle) return 0;
dp[0] = 1;
for (int i = 0; i < m; i++) {
    for (int j = 0; j < n; j++) {
        if (obstacle) dp[j] = 0;
        else if (j > 0) dp[j] = dp[j] + dp[j - 1];
    }
}
```

**The part that trips everyone up:** first column (`j == 0`) only gets paths from above (not from left). And if start/end is an obstacle, return 0 immediately.

**The mistakes to remember:**
- Not checking start/end obstacles
- Adding dp[j-1] when j == 0 (index out of bounds)
- Not setting dp[j] = 0 for obstacles
- Confusing with Unique Paths (#62) (no obstacles)
