# 21.2 Climbing Stairs

**Problem:** You are climbing a staircase of n steps. Each time you can climb 1 or 2 steps. How many distinct ways to reach the top? (LeetCode #70)

**Link:** https://leetcode.com/problems/climbing-stairs/

---

## Which Technique, and Why?

"Number of ways to reach step n" with choices (1 or 2 steps) → **Dynamic Programming**. The number of ways to reach step i = ways to reach i-1 + ways to reach i-2 (since you can come from either). This is Fibonacci. O(n) time, O(1) space (optimized).

**Signal in the problem:** "number of ways" / "distinct ways" / "how many ways to reach" → DP with counting.

## Approach

Bottom-up DP. `dp[i] = dp[i-1] + dp[i-2]`. Base: `dp[1] = 1`, `dp[2] = 2`. Optimize space to O(1) using two variables.

## Pseudocode

```
if n <= 2: return n
prev2 = 1, prev1 = 2
for i from 3 to n:
    curr = prev1 + prev2
    prev2 = prev1
    prev1 = curr
return prev1
```

## Java Code

```java
class Solution {
    public int climbStairs(int n) {
        if (n <= 2) return n;
        int prev2 = 1, prev1 = 2;  // dp[1], dp[2]
        for (int i = 3; i <= n; i++) {
            int curr = prev1 + prev2;
            prev2 = prev1;
            prev1 = curr;
        }
        return prev1;
    }
}
```

## Line-by-line

- `n <= 2` → return n (1 way for 1 step, 2 ways for 2 steps: 1+1 or 2).
- `prev2 = dp[i-2]`, `prev1 = dp[i-1]`.
- `curr = prev1 + prev2` — ways to reach i = ways to reach i-1 (then take 1 step) + ways to reach i-2 (then take 2 steps).
- Shift: `prev2 = prev1`, `prev1 = curr`.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — two variables (optimized from O(n) array).

## Common Mistakes

- **Using recursion without memoization.** O(2^n) — too slow for n = 45. Always memoize or use bottom-up.
- **Wrong base cases.** `dp[0] = 1` (one way to stay at ground: do nothing), `dp[1] = 1`. Or `dp[1] = 1, dp[2] = 2`. Be consistent.
- **Not optimizing space.** O(n) array works but O(1) is trivial here since only last 2 values matter.
- **Integer overflow.** For large n (e.g., n = 45), the answer exceeds int range? Actually 45th Fibonacci-ish is ~1.8e9, fits in int. n = 46 → ~3e9, overflows. Use `long` if needed.

## How to Explain (interview)

**Opening:** Climbing Stairs asks how many ways to reach step n taking 1 or 2 steps. DP: ways to reach step i = ways to reach i-1 + ways to reach i-2 (Fibonacci). Bottom-up with O(1) space (only last 2 values needed). O(n) time.

**The basic flow:**
```java
int prev2 = 1, prev1 = 2;
for (int i = 3; i <= n; i++) {
    int curr = prev1 + prev2;
    prev2 = prev1;
    prev1 = curr;
}
return prev1;
```

**The part that trips everyone up:** base cases. `dp[1] = 1`, `dp[2] = 2`. Also, this is just Fibonacci — recognizing that saves time.

**The mistakes to remember:**
- Recursion without memoization (O(2^n))
- Wrong base cases
- Not optimizing space (O(n) array when O(1) suffices)
- Overflow for large n (use long)
