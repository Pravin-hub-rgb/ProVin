# 21.4 Coin Change

**Problem:** Given coins of different denominations and a total amount, find the minimum number of coins to make up that amount. Return -1 if impossible. (LeetCode #322)

**Link:** https://leetcode.com/problems/coin-change/

---

## Which Technique, and Why?

"Minimum number of coins to make amount" → **DP (unbounded knapsack)**. `dp[i]` = min coins to make amount i. For each amount i, try every coin: `dp[i] = min(dp[i], dp[i - coin] + 1)`. O(amount × coins) time, O(amount) space.

**Signal in the problem:** "minimum number of coins" / "fewest coins" / "can you make amount X" → DP with coins.

## Approach

Bottom-up. `dp[0] = 0` (0 coins for amount 0). `dp[i] = min(dp[i], dp[i - coin] + 1)` for each coin ≤ i. Initialize `dp[i] = amount + 1` (infinity sentinel). If `dp[amount] > amount`, return -1.

## Pseudocode

```
dp = array of size (amount + 1), filled with amount + 1
dp[0] = 0
for i from 1 to amount:
    for each coin in coins:
        if coin <= i:
            dp[i] = min(dp[i], dp[i - coin] + 1)
return dp[amount] > amount ? -1 : dp[amount]
```

## Java Code

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, amount + 1);  // infinity sentinel
        dp[0] = 0;

        for (int i = 1; i <= amount; i++) {
            for (int coin : coins) {
                if (coin <= i) {
                    dp[i] = Math.min(dp[i], dp[i - coin] + 1);
                }
            }
        }
        return dp[amount] > amount ? -1 : dp[amount];
    }
}
```

## Line-by-line

- `dp[i]` = min coins to make amount i.
- `dp[0] = 0` — 0 coins for amount 0.
- `dp[i] = amount + 1` — sentinel for "impossible" (any valid answer is ≤ amount, since the smallest coin is 1).
- For each amount i, try each coin. If `coin <= i`, we can use it: `dp[i - coin] + 1` coins.
- `dp[amount] > amount` → impossible → return -1.

## Complexity

- Time: O(amount × coins) — for each amount, try each coin.
- Space: O(amount) — the dp array.

## Common Mistakes

- **Wrong sentinel.** Using `Integer.MAX_VALUE` causes overflow when adding 1. Use `amount + 1` (any valid answer is ≤ amount).
- **Wrong loop order.** Outer loop over amounts, inner over coins. (For "number of combinations," swap: outer over coins, inner over amounts. Different problem.)
- **Not checking `coin <= i`.** Without this, `dp[i - coin]` has negative index → crash.
- **Confusing with "Coin Change II"** (number of combinations, not minimum). Different recurrence and loop order.

## How to Explain (interview)

**Opening:** Coin Change finds the minimum coins to make an amount. DP: `dp[i]` = min coins for amount i. For each amount, try every coin: `dp[i] = min(dp[i], dp[i - coin] + 1)`. O(amount × coins) time, O(amount) space. Initialize with `amount + 1` (sentinel for "impossible").

**The basic flow:**
```java
int[] dp = new int[amount + 1];
Arrays.fill(dp, amount + 1);
dp[0] = 0;
for (int i = 1; i <= amount; i++)
    for (int coin : coins)
        if (coin <= i) dp[i] = Math.min(dp[i], dp[i - coin] + 1);
return dp[amount] > amount ? -1 : dp[amount];
```

**The part that trips everyone up:** the sentinel must be `amount + 1`, not `Integer.MAX_VALUE` (overflow). Also, the loop order matters: outer over amounts, inner over coins = minimum coins. Swapped = number of combinations (different problem).

**The mistakes to remember:**
- Using `Integer.MAX_VALUE` as sentinel (overflow on +1)
- Wrong loop order (combinations vs minimum)
- Not checking `coin <= i` (negative index)
- Confusing with Coin Change II (combinations)
