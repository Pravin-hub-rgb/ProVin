## Mini Quiz

1. What is the difference between top-down (memoization) and bottom-up (tabulation)?
2. What is the DP recipe (4 steps)?
3. Why use `amount + 1` instead of `Integer.MAX_VALUE` as the sentinel in Coin Change?
4. What's the difference between Coin Change (minimum coins) and Coin Change II (number of combinations)?
5. How do you optimize space in DP when `dp[i]` only depends on the last k values?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. Top-down (memoization): write the recursive solution, add a cache. Check cache before computing; store result before returning. Bottom-up (tabulation): start from the smallest subproblem, fill a table iteratively. No recursion. Top-down is easier to derive from recursion; bottom-up avoids stack overflow and is often faster.
2. (1) Define the state: what does dp[i] represent? (2) Find the recurrence: dp[i] = f(dp[i-1], dp[i-2], ...). (3) Set base cases: smallest inputs. (4) (Optional) Optimize space: if dp[i] depends only on last k values, use variables.
3. `Integer.MAX_VALUE + 1` overflows to negative. `amount + 1` is safe because any valid answer is ≤ amount (worst case: amount coins of denomination 1). If dp[amount] > amount, it's impossible.
4. Minimum coins: outer loop over amounts, inner over coins → dp[i] = min(dp[i], dp[i-coin] + 1). Combinations: outer loop over coins, inner over amounts → dp[i] += dp[i-coin]. Different loop order, different problem.
5. Replace the array with k variables. E.g., Climbing Stairs: dp[i] depends on dp[i-1] and dp[i-2], so use `prev1` and `prev2` instead of an array. House Robber: same. This reduces space from O(n) to O(1).

</details>

## One-Page Cheat Sheet

**DP recipe:**
1. Define state: `dp[i] = ?`
2. Find recurrence: `dp[i] = f(dp[i-1], ...)`
3. Base cases
4. (Optional) Optimize space

**Climbing Stairs (Fibonacci):**
```java
int prev2 = 1, prev1 = 2;
for (int i = 3; i <= n; i++) {
    int curr = prev1 + prev2;
    prev2 = prev1;
    prev1 = curr;
}
return n <= 2 ? n : prev1;
```

**House Robber (skip or take):**
```java
int prev2 = nums[0], prev1 = Math.max(nums[0], nums[1]);
for (int i = 2; i < nums.length; i++) {
    int curr = Math.max(prev1, prev2 + nums[i]);
    prev2 = prev1;
    prev1 = curr;
}
return nums.length == 1 ? nums[0] : prev1;
```

**Coin Change (unbounded knapsack):**
```java
int[] dp = new int[amount + 1];
Arrays.fill(dp, amount + 1);
dp[0] = 0;
for (int i = 1; i <= amount; i++)
    for (int coin : coins)
        if (coin <= i) dp[i] = Math.min(dp[i], dp[i - coin] + 1);
return dp[amount] > amount ? -1 : dp[amount];
```

**Complexities:** O(n) for 1D DP, O(n × m) for 2D DP. Space: O(n) or O(1) with optimization.

## In Your Own Words

1. What is the difference between top-down and bottom-up DP?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Top-down (memoization): write the recursive solution, add a cache. Check cache before computing; store result before returning. Easier to derive from recursion. Bottom-up (tabulation): start from the smallest subproblem, fill a table iteratively. No recursion (avoids stack overflow). Often faster (no function call overhead). Both are DP; choose based on which is easier to derive.

</details>

2. What is the DP recipe?

<details>
<summary>Show Answer</summary>

**Sample Answer:** (1) Define the state: what does dp[i] represent? (2) Find the recurrence: dp[i] = f(dp[i-1], dp[i-2], ...). (3) Set base cases: smallest inputs. (4) (Optional) Optimize space: if dp[i] depends only on the last k values, use variables instead of an array. The state definition is the most important step — get it wrong and the recurrence is wrong.

</details>

3. Why is the sentinel `amount + 1` instead of `Integer.MAX_VALUE` in Coin Change?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `Integer.MAX_VALUE + 1` overflows to a negative number, corrupting the min computation. `amount + 1` is safe because any valid answer is at most `amount` (worst case: amount coins of denomination 1). If `dp[amount] > amount`, it's impossible → return -1. This is a common overflow trap.

</details>

4. How do you know if a problem needs DP vs Greedy?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Greedy: the problem has "optimal substructure" AND "greedy choice property" (the best local choice leads to the global optimum). If greedy works, it's simpler and faster (often O(n)). DP: the problem has overlapping subproblems and optimal substructure, but the greedy choice property doesn't hold (you need to consider all choices). Test: if you can prove that the best local choice is always optimal, use greedy. Otherwise, use DP. Many problems look like greedy but aren't (e.g., Coin Change with arbitrary denominations).

</details>
