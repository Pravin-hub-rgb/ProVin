## Mini Quiz

1. What is the difference between top-down (memoization) and bottom-up (tabulation)?
2. What is the DP recipe (4 steps)?
3. Why use `amount + 1` instead of `Integer.MAX_VALUE` as the sentinel in Coin Change?
4. What's the difference between Coin Change (minimum coins) and Coin Change II (number of combinations)?
5. How do you optimize space in DP when `dp[i]` only depends on the last k values?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. Top-down (memoization): write the recursive solution, add a cache. Check cache before computing; store result before returning. Easier to derive from recursion. Bottom-up (tabulation): start from the smallest subproblem, fill a table iteratively. No recursion (avoids stack overflow). Often faster (no function call overhead). Both are DP; choose based on which is easier to derive.
2. (1) Define the state: what does dp[i] represent? (2) Find the recurrence: dp[i] = f(dp[i-1], dp[i-2], ...). (3) Set base cases: smallest inputs. (4) (Optional) Optimize space: if dp[i] depends only on the last k values, use variables instead of an array. The state definition is the most important step.
3. `Integer.MAX_VALUE + 1` overflows to negative. `amount + 1` is safe because any valid answer is at most `amount`. If dp[amount] > amount, it's impossible.
4. Minimum coins: outer loop over amounts, inner over coins → dp[i] = min(dp[i], dp[i-coin] + 1). Combinations: outer over coins, inner over amounts (ascending) → dp[a] += dp[a-coin]. Different loop order, different problem.
5. Replace the array with k variables. E.g., Climbing Stairs: dp[i] depends on dp[i-1] and dp[i-2], so use `prev1` and `prev2`. House Robber: same. This reduces space from O(n) to O(1).

</details>

## One-Page Cheat Sheet

**DP recipe:**
1. Define state: `dp[i] = ?`
2. Find recurrence: `dp[i] = f(dp[i-1], ...)`
3. Base cases
4. (Optional) Optimize space

**Coin Change II (combinations):**
```java
int[] dp = new int[amount + 1]; dp[0] = 1;
for (int coin : coins) for (int a = coin; a <= amount; a++) dp[a] += dp[a - coin];
```

**Unique Paths:**
```java
int[] dp = new int[n]; Arrays.fill(dp, 1);
for (int i = 1; i < m; i++) for (int j = 1; j < n; j++) dp[j] = dp[j] + dp[j - 1];
```

**Edit Distance:**
```java
// dp[j] = 1 + min(dp[j], dp[j-1], prev) on mismatch; dp[j] = prev on match
```

**LCS:**
```java
// match: dp[j] = prev + 1; mismatch: dp[j] = max(dp[j], dp[j-1])
```

**Complexities:** O(n) for 1D DP, O(n × m) for 2D DP. Space: O(n) or O(1) with optimization.

3. Why is loop order critical in Coin Change II?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Outer loop over coins, inner over amounts (ascending) = counts combinations (each combination counted once). Swapped (outer amounts, inner coins) = counts permutations (different problem). Descending inner loop = 0/1 knapsack (each coin used at most once). The loop order completely changes the problem.

</details>

4. How do you know if a problem needs DP vs Greedy?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Test: can you prove that the best local choice always leads to the global optimum? If yes → greedy (simpler, faster). If you can find a counterexample where the greedy choice leads to a suboptimal solution → DP. Many problems look like greedy but aren't (e.g., Coin Change with arbitrary denominations — greedy fails, DP needed). When in doubt, start with DP (correct) and optimize to greedy if possible.

</details>
