## The Core Idea

Many recursive solutions recompute the same subproblem exponentially many times. DP fixes this by **storing** (memoizing) sub-answers.

**Example:** Fibonacci. `fib(5) = fib(4) + fib(3)`. Without memoization, `fib(3)` is computed twice, `fib(2)` three times, etc. → O(2^n). With memoization → O(n).

**Two approaches:**
1. **Top-down (memoization):** write the recursive solution, add a cache (HashMap or array). Check cache before computing; store result before returning.
2. **Bottom-up (tabulation):** start from the smallest subproblem, fill a table iteratively. No recursion, no stack overflow.

**The DP recipe:**
1. Define the state: what does `dp[i]` represent?
2. Find the recurrence: `dp[i] = f(dp[i-1], dp[i-2], ...)`.
3. Base cases: smallest inputs.
4. (Optional) Optimize space: if `dp[i]` only depends on the last few values, use variables instead of an array.

## How to Recognize It

Think "Dynamic Programming" when:
- The problem asks for an **optimal value** (max/min/count) over choices.
- The problem has **overlapping subproblems** (same subproblem solved many times).
- The problem has **optimal substructure** (optimal solution = combination of optimal sub-solutions).
- Keywords: "maximum/minimum," "number of ways," "can you," "longest/shortest," "partition."

**Signal words:** "maximum," "minimum," "count the number of ways," "can you achieve," "longest," "shortest," "partition," "subset sum."

**DP vs Greedy:** Greedy makes the best local choice and never revisits. DP considers all choices and picks the best. If greedy works, it's simpler and faster. If not, use DP.

**DP vs Recursion:** Recursion without memoization is exponential. DP (memoization/tabulation) makes it polynomial. If you can write the recursive solution, you can write the DP.

## Worked Example: Climbing Stairs

**Problem:** You can climb 1 or 2 steps at a time. How many ways to reach step n?

### Brute force (recursion, O(2^n))

```java
static int climb(int n) {
    if (n <= 2) return n;
    return climb(n - 1) + climb(n - 2);  // two choices
}
```

`climb(3)` calls `climb(2)` and `climb(1)`. `climb(2)` calls `climb(1)` and `climb(0)`. `climb(1)` is computed twice. Exponential.

### Top-down with memoization (O(n))

```java
static int climb(int n, int[] memo) {
    if (n <= 2) return n;
    if (memo[n] != 0) return memo[n];
    memo[n] = climb(n - 1, memo) + climb(n - 2, memo);
    return memo[n];
}
```

### Bottom-up (tabulation, O(n) time, O(n) space)

```java
static int climb(int n) {
    if (n <= 2) return n;
    int[] dp = new int[n + 1];
    dp[1] = 1; dp[2] = 2;
    for (int i = 3; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    return dp[n];
}
```

### Space-optimized (O(1) space)

```java
static int climb(int n) {
    if (n <= 2) return n;
    int prev2 = 1, prev1 = 2;  // dp[i-2], dp[i-1]
    for (int i = 3; i <= n; i++) {
        int curr = prev1 + prev2;
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}
```

**Key insight:** `dp[i]` only depends on `dp[i-1]` and `dp[i-2]`, so you only need two variables. This space optimization is common in DP (e.g., House Robber, Fibonacci).

## Common Mistakes

- **Not defining the state clearly.** "What does dp[i] represent?" must be answered before writing the recurrence. Vague states lead to wrong recurrences.
- **Wrong base cases.** Off-by-one in base cases propagates through the whole table. Test small inputs (n=0, n=1, n=2).
- **Forgetting to initialize the memo array.** `new int[n+1]` defaults to 0. If 0 is a valid answer, use -1 as "uncomputed" sentinel.
- **Not optimizing space when possible.** If `dp[i]` depends only on the last k values, use variables instead of an array.
- **Confusing top-down and bottom-up.** Top-down: recursive, memoize. Bottom-up: iterative, fill table. Both are DP; choose based on which is easier to derive.

## How to Explain (interview)

**Opening:** Dynamic Programming solves problems with overlapping subproblems by storing (memoizing) sub-answers. If a recursive solution recomputes the same subproblem, DP makes it polynomial. Two forms: top-down (memoization — recursive with cache) and bottom-up (tabulation — iterative table filling). The recipe: define state (dp[i] = ?), find recurrence, set base cases, optimize space if possible.

**The basic flow (bottom-up):**
```java
int[] dp = new int[n + 1];
dp[0] = base0; dp[1] = base1;
for (int i = 2; i <= n; i++) {
    dp[i] = dp[i-1] + dp[i-2];  // recurrence
}
return dp[n];
```

**The part that trips everyone up:** define what `dp[i]` means **before** writing the recurrence. Also, `dp[i]` might depend on `dp[i-1]` and `dp[i-2]` — but it could depend on `dp[i-1]` and `dp[i+1]` (less common) or a 2D state. Always clarify the state.

**The mistakes to remember:**
- Vague state definition (leads to wrong recurrence)
- Wrong base cases (off-by-one propagates)
- Forgetting memo initialization (0 vs -1 sentinel)
- Not optimizing space when only last k values are needed
- Confusing top-down (memo) with bottom-up (tabulation)
