**Tier 2 problem.** (LeetCode #494)

**Problem:** Given an array and a target, assign + or - to each element such that the sum equals target. Return the number of ways. (LeetCode #494)

**Link:** https://leetcode.com/problems/target-sum/

---

## Which Technique, and Why?

"Assign +/- to reach target" → **DP (subset sum transformation)**. Let P = sum of positive elements, N = sum of negative elements. P + N = total, P - N = target. So P = (total + target) / 2. The problem reduces to: count subsets summing to P. If (total + target) is odd or target > total → 0. O(n × P) time, O(P) space.

**Signal in the problem:** "assign + or -" / "target sum" → transform to subset sum: P = (total + target) / 2.

## Approach

1. Compute total sum. If `total < |target|` or `(total + target) % 2 != 0` → return 0.
2. Target sum for the subset: `P = (total + target) / 2`.
3. DP: `dp[i]` = number of ways to make sum i. `dp[0] = 1`. For each num: for sum from P down to num: `dp[sum] += dp[sum - num]`.
4. Return `dp[P]`.

## Pseudocode

```
total = sum(nums)
if total < abs(target) or (total + target) % 2 != 0: return 0
P = (total + target) / 2
dp = new int[P + 1]
dp[0] = 1
for num in nums:
    for sum from P down to num:
        dp[sum] += dp[sum - num]
return dp[P]
```

## Java Code

```java
class Solution {
    public int findTargetSumWays(int[] nums, int target) {
        int total = 0;
        for (int x : nums) total += x;
        if (total < Math.abs(target) || (total + target) % 2 != 0) return 0;

        int P = (total + target) / 2;
        int[] dp = new int[P + 1];
        dp[0] = 1;

        for (int num : nums) {
            for (int sum = P; sum >= num; sum--) {
                dp[sum] += dp[sum - num];
            }
        }
        return dp[P];
    }
}
```

## Line-by-line

- `total` = sum of all elements.
- `total < |target|` → impossible (target exceeds total sum).
- `(total + target) % 2 != 0` → P isn't an integer → impossible.
- `P = (total + target) / 2` — target subset sum.
- `dp[0] = 1` — one way to make 0 (empty subset).
- For each num: for sum from P down to num: `dp[sum] += dp[sum - num]` — 0/1 knapsack (each number used at most once, assigned + or -).
- Return `dp[P]`.

## Complexity

- Time: O(n × P) where P = (total + target) / 2.
- Space: O(P) — dp array.

## Common Mistakes

- **Not checking `(total + target) % 2 != 0`.** If this is odd, P isn't an integer → no solution.
- **Not checking `total < |target|`.** If target exceeds total sum, impossible.
- **Ascending inner loop.** That allows reuse (unbounded). For "each number used once," use descending.
- **Confusing with Partition Equal Subset Sum (#416).** That's a special case where target = 0 (P = total/2). This generalizes to any target.

## How to Explain (interview)

**Opening:** Target Sum assigns + or - to each element to reach a target. Transform: P + N = total, P - N = target → P = (total + target) / 2. Now it's "count subsets summing to P" — a 0/1 knapsack. O(n × P) time, O(P) space.

**The basic flow:**
```java
int total = sum(nums);
if (total < Math.abs(target) || (total + target) % 2 != 0) return 0;
int P = (total + target) / 2;
int[] dp = new int[P + 1]; dp[0] = 1;
for (int num : nums) {
    for (int sum = P; sum >= num; sum--) dp[sum] += dp[sum - num];
}
return dp[P];
```

**The part that trips everyone up:** the transformation to subset sum. P = (total + target) / 2. Also, the divisibility check `(total + target) % 2 != 0` and the range check `total < |target|`.

**The mistakes to remember:**
- Not checking divisibility (P must be an integer)
- Not checking range (target can't exceed total)
- Ascending inner loop (allows reuse — wrong)
- Confusing with Partition Equal Subset Sum (#416) (special case: target = 0)
