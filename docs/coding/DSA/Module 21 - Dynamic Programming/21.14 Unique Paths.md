**Tier 2 problem.** (LeetCode #62)

**Problem:** A robot is at the top-left of an m×n grid. It can only move right or down. Find the number of unique paths to the bottom-right. (LeetCode #62)

**Link:** https://leetcode.com/problems/unique-paths/

---

## Which Technique, and Why?

"Unique paths in a grid (right/down only)" → **DP (2D)**. `dp[i][j]` = number of paths to cell (i,j). `dp[i][j] = dp[i-1][j] + dp[i][j-1]` (from above + from left). O(m × n) time, O(n) space (optimized).

**Signal in the problem:** "unique paths" / "grid" / "right and down" → 2D DP.

## Approach

Bottom-up. `dp[i][j]` = paths to (i,j). Base: first row and first column = 1 (only one way: straight). Recurrence: `dp[i][j] = dp[i-1][j] + dp[i][j-1]`. Optimize space to O(n).

## Pseudocode

```
dp = new int[n] (all 1)
for i from 1 to m-1:
    for j from 1 to n-1:
        dp[j] = dp[j] + dp[j-1]  // dp[j] is from above (prev row), dp[j-1] is from left (current row)
return dp[n-1]
```

## Java Code

```java
class Solution {
    public int uniquePaths(int m, int n) {
        int[] dp = new int[n];
        Arrays.fill(dp, 1);

        for (int i = 1; i < m; i++) {
            for (int j = 1; j < n; j++) {
                dp[j] = dp[j] + dp[j - 1];
            }
        }
        return dp[n - 1];
    }
}
```

## Line-by-line

- `dp[j]` initially 1 for all j (first row: one path each).
- For each row i: `dp[j] = dp[j] + dp[j-1]`. `dp[j]` (before update) = paths from above (previous row). `dp[j-1]` (already updated) = paths from left (current row).
- After processing all rows, `dp[n-1]` = paths to bottom-right.

## Complexity

- Time: O(m × n).
- Space: O(n) — optimized from O(m × n).

## Common Mistakes

- **Not optimizing space.** O(m × n) array works but O(n) is simpler. The recurrence only needs the previous row.
- **Wrong recurrence.** `dp[i][j] = dp[i-1][j] + dp[i][j-1]` (from above + from left), not `dp[i-1][j-1] + ...`.
- **Off-by-one.** Loop `i from 1 to m-1`, `j from 1 to n-1`. First row/column are base cases (1).
- **Confusing with "Unique Paths II" (#63).** That one has obstacles (some cells are 0). Different handling.

## How to Explain (interview)

**Opening:** Unique Paths counts paths from top-left to bottom-right (right/down only). DP: `dp[i][j] = dp[i-1][j] + dp[i][j-1]` (from above + from left). O(m×n) time, O(n) space (optimized).

**The basic flow:**
```java
int[] dp = new int[n]; Arrays.fill(dp, 1);
for (int i = 1; i < m; i++) {
    for (int j = 1; j < n; j++) {
        dp[j] = dp[j] + dp[j - 1];
    }
}
return dp[n - 1];
```

**The part that trips everyone up:** space optimization. `dp[j]` before update = previous row (above). `dp[j-1]` after update = current row (left). This in-place update works because we process left to right.

**The mistakes to remember:**
- Not optimizing space (O(mn) instead of O(n))
- Wrong recurrence (using dp[i-1][j-1])
- Off-by-one in loops (first row/col are 1)
- Confusing with Unique Paths II (#63, has obstacles)
