# 21.12 Perfect Squares

**Tier 2 problem.** (LeetCode #279)

**Problem:** Given an integer n, return the least number of perfect square numbers that sum to n. (LeetCode #279)

**Link:** https://leetcode.com/problems/perfect-squares/

---

## Which Technique, and Why?

"Least number of perfect squares summing to n" → **DP (unbounded knapsack)**. `dp[i]` = min squares to make i. For each i, try all squares ≤ i: `dp[i] = min(dp[i], dp[i - j*j] + 1)`. O(n × √n) time, O(n) space.

**Signal in the problem:** "least number of" / "perfect squares" / "sum to n" → DP (unbounded knapsack with squares as items).

## Approach

Bottom-up. `dp[0] = 0`. For i from 1 to n: `dp[i] = i` (worst case: 1²+1²+...). For each square j² ≤ i: `dp[i] = min(dp[i], dp[i - j*j] + 1)`.

## Pseudocode

```
dp = new int[n + 1]
dp[0] = 0
for i from 1 to n:
    dp[i] = i  // worst case: all 1s
    for j from 1; j*j <= i; j++:
        dp[i] = min(dp[i], dp[i - j*j] + 1)
return dp[n]
```

## Java Code

```java
class Solution {
    public int numSquares(int n) {
        int[] dp = new int[n + 1];
        dp[0] = 0;
        for (int i = 1; i <= n; i++) {
            dp[i] = i;  // worst case: 1^2 + 1^2 + ... (i times)
            for (int j = 1; j * j <= i; j++) {
                dp[i] = Math.min(dp[i], dp[i - j * j] + 1);
            }
        }
        return dp[n];
    }
}
```

## Line-by-line

- `dp[i]` = min perfect squares summing to i.
- `dp[0] = 0` — 0 squares for 0.
- `dp[i] = i` — worst case (all 1²).
- For each square `j² ≤ i`: try using it → `dp[i - j²] + 1`.
- Return `dp[n]`.

## Complexity

- Time: O(n × √n) — for each i, try up to √i squares.
- Space: O(n) — dp array.

## Common Mistakes

- **Not initializing dp[i] = i.** The worst case is i ones (1²). Without this, dp[i] stays 0 (default), giving wrong (too small) answers.
- **Square overflow.** `j * j` can overflow for large j. Use `j * j <= i` with int (safe for n ≤ 10⁴) or `j <= (int) Math.sqrt(i)`.
- **Confusing with "Coin Change" (#322).** Same DP pattern but items are perfect squares (1, 4, 9, 16, ...) instead of arbitrary coins.
- **Not considering 0.** `dp[0] = 0` is the base case. Without it, `dp[j*j] = dp[0] + 1 = 1` (correct for perfect squares).

## How to Explain (interview)

**Opening:** Perfect Squares finds the min number of perfect squares summing to n. DP: `dp[i]` = min squares for i. For each i, try every square ≤ i: `dp[i] = min(dp[i], dp[i - j²] + 1)`. O(n√n) time, O(n) space. Same pattern as Coin Change, but items are squares.

**The basic flow:**
```java
int[] dp = new int[n + 1];
dp[0] = 0;
for (int i = 1; i <= n; i++) {
    dp[i] = i;
    for (int j = 1; j * j <= i; j++) {
        dp[i] = Math.min(dp[i], dp[i - j * j] + 1);
    }
}
return dp[n];
```

**The part that trips everyone up:** initialize `dp[i] = i` (worst case: all 1s). Without this, dp[i] stays 0 (default), giving wrong answers. Also, the inner loop tries all squares ≤ i, not just one.

**The mistakes to remember:**
- Not initializing dp[i] = i (wrong answers)
- Overflow in `j * j` (use long or sqrt for large n)
- Confusing with Coin Change (#322) (same pattern, different items)
- Not handling n = 0 (returns 0, correct)
