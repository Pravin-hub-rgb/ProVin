**Tier 2 problem.** (LeetCode #518)

**Problem:** Given coins of different denominations and an amount, return the number of combinations that make up that amount. (LeetCode #518)

**Link:** https://leetcode.com/problems/coin-change-ii/

---

## Which Technique, and Why?

"Number of combinations to make amount" → **DP (unbounded knapsack)**. `dp[i]` = number of ways to make amount i. For each coin, for each amount ≥ coin: `dp[amount] += dp[amount - coin]`. **Loop order matters:** outer over coins, inner over amounts → counts combinations (not permutations). O(amount × coins) time, O(amount) space.

**Signal in the problem:** "number of combinations" / "how many ways" + coins → DP. Outer over coins, inner over amounts.

## Approach

Bottom-up. `dp[0] = 1` (one way to make 0: use no coins). For each coin, for amount from coin to target: `dp[amount] += dp[amount - coin]`. The outer-over-coins order ensures each combination is counted once (not permutations).

## Pseudocode

```
dp = new int[amount + 1]
dp[0] = 1
for each coin in coins:
    for amount from coin to target:
        dp[amount] += dp[amount - coin]
return dp[target]
```

## Java Code

```java
class Solution {
    public int change(int amount, int[] coins) {
        int[] dp = new int[amount + 1];
        dp[0] = 1;

        for (int coin : coins) {
            for (int a = coin; a <= amount; a++) {
                dp[a] += dp[a - coin];
            }
        }
        return dp[amount];
    }
}
```

## Line-by-line

- `dp[0] = 1` — one way to make 0 (use no coins).
- Outer loop over coins — ensures each combination counted once.
- Inner loop over amounts (ascending) — unbounded (same coin can be reused).
- `dp[a] += dp[a - coin]` — add ways using this coin.

## Complexity

- Time: O(amount × coins).
- Space: O(amount) — dp array.

## Common Mistakes

- **Wrong loop order.** Outer over amounts, inner over coins → counts permutations (different problem). For combinations, outer over coins, inner over amounts.
- **Descending inner loop.** That's for 0/1 knapsack (each coin used at most once). For unbounded (unlimited coins), inner loop is ascending.
- **Not initializing `dp[0] = 1`.** Without this, all dp values stay 0.
- **Confusing with Coin Change (#322).** That's minimum coins (min, not count). Different recurrence and loop order.

## How to Explain (interview)

**Opening:** Coin Change II counts the number of combinations to make an amount. DP: `dp[a] += dp[a - coin]`. Outer loop over coins, inner over amounts (ascending) → counts combinations, not permutations. O(amount × coins) time, O(amount) space.

**The basic flow:**
```java
int[] dp = new int[amount + 1];
dp[0] = 1;
for (int coin : coins) {
    for (int a = coin; a <= amount; a++) {
        dp[a] += dp[a - coin];
    }
}
return dp[amount];
```

**The part that trips everyone up:** **loop order**. Outer over coins, inner over amounts (ascending) = combinations. Swapped (outer amounts, inner coins) = permutations. Descending inner = 0/1 knapsack (each coin once). The order completely changes the problem.

**The mistakes to remember:**
- Wrong loop order (combinations vs permutations)
- Descending inner loop (0/1 knapsack instead of unbounded)
- Not initializing dp[0] = 1
- Confusing with Coin Change (#322, minimum coins)
