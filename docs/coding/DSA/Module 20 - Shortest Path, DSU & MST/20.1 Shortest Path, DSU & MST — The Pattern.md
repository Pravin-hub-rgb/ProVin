## The Core Idea

**Dijkstra's algorithm:** finds the shortest path from a source to all nodes in a weighted graph with non-negative weights. Uses a min-heap (priority queue) to always expand the closest unvisited node. O((V + E) log V) time.

**Bellman-Ford:** handles negative weights (but no negative cycles). O(V × E) time. Slower but more general.

**Union-Find (DSU):** groups nodes into sets. Supports `find` (which set?) and `union` (merge sets). Used for connectivity, cycle detection, and MST. Nearly O(1) per operation (with path compression + union by rank).

**Minimum Spanning Tree (MST):** connects all nodes with minimum total edge weight. Kruskal's: sort edges, add if they connect different components (DSU). Prim's: grow from a starting node, always add the cheapest edge to the tree.

## Data Structure Primer: Union-Find (DSU)

```java
class DSU {
    int[] parent;
    int[] rank;

    DSU(int n) {
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]); // path compression
        return parent[x];
    }

    boolean union(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return false; // already connected (cycle!)
        if (rank[px] < rank[py]) { int t = px; px = py; py = t; }
        parent[py] = px;
        if (rank[px] == rank[py]) rank[px]++;
        return true;
    }
}
```

- `find(x)`: which set is x in? Path compression flattens the tree.
- `union(x, y)`: merge sets. Returns false if already in the same set (cycle detected).
- Nearly O(1) per operation (inverse Ackermann).

## Worked Example: Network Delay Time (Dijkstra)

**Problem:** Given a network (edges with travel time), find the time for a signal to reach all nodes from source K. Return -1 if not all reachable.

### Brute force (O(V × E))

Bellman-Ford: relax all edges V-1 times. Works but slow.

### Optimized (O((V + E) log V)) — Dijkstra

```java
class Solution {
    public int networkDelayTime(int[][] times, int n, int k) {
        List<List<int[]>> adj = new ArrayList<>();
        for (int i = 0; i <= n; i++) adj.add(new ArrayList<>());
        for (int[] t : times) adj.get(t[0]).add(new int[]{t[1], t[2]});

        int[] dist = new int[n + 1];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[k] = 0;

        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]);
        pq.offer(new int[]{k, 0});

        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int node = cur[0], d = cur[1];
            if (d > dist[node]) continue;  // stale entry
            for (int[] edge : adj.get(node)) {
                int next = edge[0], weight = edge[1];
                if (dist[node] + weight < dist[next]) {
                    dist[next] = dist[node] + weight;
                    pq.offer(new int[]{next, dist[next]});
                }
            }
        }

        int max = 0;
        for (int i = 1; i <= n; i++) {
            if (dist[i] == Integer.MAX_VALUE) return -1;
            max = Math.max(max, dist[i]);
        }
        return max;
    }
}
```

**Line-by-line:**
- Build adjacency list: `node → list of {neighbor, weight}`.
- `dist` array: shortest distance from source. Initialize to infinity, source = 0.
- Min-heap (priority queue) of `{node, distance}`. Start with source.
- Pop the closest node. If stale (distance > recorded), skip.
- For each neighbor: if `dist[node] + weight < dist[neighbor]`, update and push to heap.
- After processing, find the max distance. If any node is unreachable (infinity), return -1.

**Key insight:** the min-heap always expands the closest unvisited node. This greedy choice works because weights are non-negative — once a node is popped, its shortest distance is finalized.

## Common Mistakes

- **Using Dijkstra with negative weights.** Dijkstra requires non-negative weights. For negative weights, use Bellman-Ford.
- **Not skipping stale heap entries.** The same node can be pushed multiple times. Check `if (d > dist[node]) continue;` to skip stale entries.
- **Comparator overflow.** `(a, b) -> a[1] - b[1]` can overflow. Use `Integer.compare(a[1], b[1])`.
- **DSU: not using path compression / union by rank.** Without these, operations are O(n) instead of nearly O(1). Always include both.
- **DSU: confusing find and union.** `find(x)` returns the root. `union(x, y)` merges sets. `union` returns false if already connected (cycle).
- **MST: Kruskal vs Prim.** Kruskal (sort edges + DSU) is simpler for sparse graphs. Prim (min-heap of edges) is better for dense graphs.

## How to Explain (interview)

**Opening:** For weighted graphs: Dijkstra finds shortest path (non-negative weights) using a min-heap — O((V+E) log V). DSU groups nodes into sets with near-O(1) find/union — used for connectivity, cycle detection, and MST. MST (Kruskal) sorts edges and adds them if they connect different components (DSU). Each serves a different purpose: shortest path, connectivity, minimum connection cost.

**The basic flow (Dijkstra):**
```java
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));
pq.offer(new int[]{source, 0});
while (!pq.isEmpty()) {
    int[] cur = pq.poll();
    if (cur[1] > dist[cur[0]]) continue;  // stale
    for (int[] edge : adj.get(cur[0])) {
        if (dist[cur[0]] + edge[1] < dist[edge[0]]) {
            dist[edge[0]] = dist[cur[0]] + edge[1];
            pq.offer(new int[]{edge[0], dist[edge[0]]});
        }
    }
}
```

**The part that trips everyone up:** Dijkstra requires **non-negative weights**. With negatives, use Bellman-Ford. Also, skip stale heap entries (`if (d > dist[node]) continue`). For DSU, always use path compression + union by rank.

**The mistakes to remember:**
- Dijkstra with negative weights (wrong answer)
- Not skipping stale heap entries (wrong distances)
- DSU without path compression / union by rank (O(n) instead of O(1))
- Confusing Kruskal (sort edges) with Prim (grow from a node)
- Comparator overflow in the priority queue
