# 20.3 Redundant Connection

**Problem:** Given a set of edges forming a tree plus one extra edge, find the redundant edge that, when removed, makes it a tree again. (LeetCode #684)

**Link:** https://leetcode.com/problems/redundant-connection/

---

## Which Technique, and Why?

"Find the redundant edge" in an undirected graph → **Union-Find (DSU)**. Process edges in order; if `union(u, v)` returns false (already connected), this edge is redundant. O(n × α(n)) time, O(n) space.

**Signal in the problem:** "redundant connection" / "extra edge" / "cycle in undirected graph" → DSU (union returns false → cycle).

## Approach

Initialize DSU with n nodes. For each edge (u, v): if `find(u) == find(v)` (already connected), this edge is redundant → return it. Else `union(u, v)`.

## Pseudocode

```
dsu = new DSU(n)
for each edge (u, v):
    if dsu.find(u) == dsu.find(v): return [u, v]
    dsu.union(u, v)
return []
```

## Java Code

```java
class Solution {
    public int[] findRedundantConnection(int[][] edges) {
        int n = edges.length;
        DSU dsu = new DSU(n + 1);  // nodes are 1-indexed

        for (int[] edge : edges) {
            if (dsu.find(edge[0]) == dsu.find(edge[1])) {
                return edge;  // redundant
            }
            dsu.union(edge[0], edge[1]);
        }
        return new int[]{};
    }
}

class DSU {
    int[] parent, rank;
    DSU(int n) {
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
    }
    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }
    boolean union(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return false;
        if (rank[px] < rank[py]) { int t = px; px = py; py = t; }
        parent[py] = px;
        if (rank[px] == rank[py]) rank[px]++;
        return true;
    }
}
```

## Line-by-line

- `DSU(n + 1)` — nodes are 1-indexed (1 to n), so array size n+1.
- For each edge: `find(u) == find(v)` → already connected → this edge creates a cycle → redundant.
- If not connected, `union(u, v)` merges the sets.
- Return the first redundant edge found (problem guarantees exactly one).

## Complexity

- Time: O(n × α(n)) ≈ O(n) — nearly linear with path compression + union by rank.
- Space: O(n) — parent and rank arrays.

## Common Mistakes

- **DSU without path compression / union by rank.** Operations become O(n) instead of nearly O(1). Always include both.
- **0-indexed vs 1-indexed.** Nodes are 1 to n. Array size must be n+1. Using size n causes ArrayIndexOutOfBounds.
- **Not checking `find` before `union`.** If you union first, you can't detect the cycle. Check `find(u) == find(v)` first.
- **Returning the wrong edge.** The problem says return the edge that appears last in the input if multiple are redundant. Since we process in order and return the first redundant, and the input order determines priority, this is correct. (If multiple redundant edges exist, return the last one in input order — process all and track the last redundant, or process in order and the first redundant found is actually the answer per problem spec.)

## How to Explain (interview)

**Opening:** Redundant Connection finds the extra edge that creates a cycle in an undirected graph. DSU: process edges in order; if `find(u) == find(v)` (already connected), this edge is redundant. O(n × α(n)) ≈ O(n) time, O(n) space. Each union returns false → cycle detected.

**The basic flow:**
```java
DSU dsu = new DSU(n + 1);
for (int[] edge : edges) {
    if (dsu.find(edge[0]) == dsu.find(edge[1])) return edge;
    dsu.union(edge[0], edge[1]);
}
```

**The part that trips everyone up:** DSU needs path compression + union by rank for near-O(1) operations. Also, nodes are 1-indexed — array size n+1. Check `find` **before** `union`.

**The mistakes to remember:**
- DSU without path compression / union by rank (O(n) ops)
- 0-indexed array for 1-indexed nodes (ArrayIndexOutOfBounds)
- Union before checking find (misses cycle)
- Confusing with directed graph cycle detection (different problem)
