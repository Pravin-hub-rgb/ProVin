# 12.2 Bit Manipulation — Common Bit Tricks

## What This Problem Is Asking (Simple Terms)

Bit manipulation involves using bitwise operators to manipulate individual bits of integers. Common bit tricks include checking if a number is a power of two, counting set bits, swapping bits, and more.

---

## Example 1

**Problem:** Check if a number is a power of two.

**Input:** `n = 8`

**Output:** `true`

**Explanation:** 8 = 2^3, so it's a power of two.

---

## Example 2

**Input:** `n = 3`**

**Output:** `false`

**Explanation:** 3 is not a power of two.

---

## Constraints

- `-2^31 <= n <= 10^4`

---

## Which Technique, and Why?

Bit manipulation uses bitwise operators to manipulate individual bits of integers. Common tricks include `n & (n-1)` to clear the rightmost set bit.

**Signal in the problem:** "count number of 1 bits," "power of two," "single number" → Bit manipulation.

---

## Approach

**Key bit manipulation tricks:**

1. **`n & (n - 1)`** — clears the rightmost set bit (turns the rightmost 1 into 0)
2. **`n & -n`** — isolates the rightmost set bit
3. **`n ^ (n - 1)`** — flips all bits from the rightmost set bit to the right (inclusive)

### Pseudocode (Count number of 1 bits / Hamming Weight)

```
count = 0
while n != 0:
    n = n & (n - 1)  // clears rightmost set bit
    count++
return count
```

### Java Code

```java
class Solution {
    public int hammingWeight(int n) {
        int count = 0;
        while (n != 0) {
            n &= (n - 1);  // clears rightmost set bit
            count++;
        }
        return count;
    }
}
```

### Line-by-line

- `n & (n - 1)` — clears the rightmost set bit (turns the rightmost 1 into 0)
- `count++` — counts each cleared bit
- Loop continues until `n == 0` (all bits cleared)

## Complexity

- Time: O(k) where k = number of set bits (at most 32 for 32-bit int)
- Space: O(1) — just a counter variable

## Common Mistakes

- **Using `>>` instead of `>>>`** — Java `>>` is arithmetic right shift (fills with sign bit), `>>>` is logical right shift (fills with 0s)
- **Forgetting that `n & (n - 1)` clears the rightmost set bit** — this is the core trick
- **Assuming unsigned integers** — Java uses signed integers, so `>>` fills with sign bit
