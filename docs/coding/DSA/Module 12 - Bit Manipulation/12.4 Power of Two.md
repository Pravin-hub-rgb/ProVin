# 12.4 Power of Two

**Problem:** Given an integer n, return true if it is a power of 2. (LeetCode #231)

**Link:** https://leetcode.com/problems/power-of-two/

---

## Which Technique, and Why?

A power of 2 has exactly one set bit in binary: 1, 2, 4, 8, 16, ... (1, 10, 100, 1000, ...). So `n > 0 && (n & (n - 1)) == 0` checks: n is positive AND clearing the lowest set bit gives 0 (meaning there was only one set bit).

**Signal in the problem:** "power of 2" / "is n a power of two" → `n > 0 && (n & (n-1)) == 0`.

## Approach

Check `n > 0` and `(n & (n - 1)) == 0`. If n is a power of 2, it has exactly one set bit; clearing it gives 0.

## Pseudocode

```
return n > 0 and (n & (n - 1)) == 0
```

## Java Code

```java
class Solution {
    public boolean isPowerOfTwo(int n) {
        return n > 0 && (n & (n - 1)) == 0;
    }
}
```

## Line-by-line

- `n > 0` — 0 and negatives are not powers of 2. (0: `0 & -1 = 0` would falsely pass without this check.)
- `n & (n - 1)` — clears the lowest set bit. If n has exactly one set bit (power of 2), this gives 0.
- `== 0` — confirms only one set bit existed.

## Complexity

- Time: O(1) — single bitwise operation.
- Space: O(1).

## Common Mistakes

- **Forgetting `n > 0`.** `n = 0`: `0 & -1 = 0` → falsely returns true. `n < 0`: negative numbers are never powers of 2. The guard is essential.
- **Using a loop.** `while (n % 2 == 0) n /= 2; return n == 1;` works but is O(log n). The bitwise trick is O(1).
- **Using `Math.log`.** Floating point precision issues. `Math.log(n) / Math.log(2)` may not be exactly an integer. Avoid.
- **Confusing with `n & (n + 1)`.** That's a different trick (clears lowest unset bit). For power of 2, use `n & (n - 1)`.

## How to Explain (interview)

**Opening:** A power of 2 has exactly one set bit in binary (1, 10, 100, 1000...). `n & (n-1)` clears the lowest set bit. If the result is 0, there was only one set bit → power of 2. Must also check `n > 0` (0 would falsely pass). O(1) time and space.

**The basic flow:**
```java
return n > 0 && (n & (n - 1)) == 0;
```

**The part that trips everyone up:** `n > 0` is **essential**. Without it, 0 returns true (0 & -1 = 0). Also, this only works for powers of 2, not powers of 3 or other bases.

**The mistakes to remember:**
- Forgetting `n > 0` (0 falsely passes)
- Using a loop (O(log n)) instead of O(1) bitwise
- Using `Math.log` (floating point precision)
- Confusing `n & (n-1)` with `n & (n+1)`
