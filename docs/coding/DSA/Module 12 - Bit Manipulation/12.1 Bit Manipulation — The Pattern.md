## The Core Idea

Every integer is a sequence of bits (0s and 1s). Bitwise operators work on these bits directly:

| Operator | Name | What it does | Example (5=101, 3=011) |
|---|---|---|---|
| `&` | AND | 1 only if both bits are 1 | 101 & 011 = 001 (1) |
| `\|` | OR | 1 if either bit is 1 | 101 \| 011 = 111 (7) |
| `^` | XOR | 1 if bits differ | 101 ^ 011 = 110 (6) |
| `~` | NOT | flips all bits | ~101 = ...010 (in two's complement) |
| `<<` | Left shift | shift bits left (×2) | 101 << 1 = 1010 (10) |
| `>>` | Right shift | shift bits right (÷2) | 101 >> 1 = 10 (2) |
| `>>>` | Unsigned right shift | shift right, fill with 0 | (for negative numbers) |

**Key tricks:**
- `x & (x - 1)` clears the lowest set bit (Brian Kernighan's trick).
- `x & 1` checks if x is odd (lowest bit is 1).
- `x ^ x = 0` and `x ^ 0 = x` — XOR cancels pairs.
- `1 << k` creates a mask with only bit k set.

## How to Recognize It

Think "Bit Manipulation" when:
- The problem involves **parity** (odd/even) → `x & 1`.
- The problem asks to **count set bits** → Brian Kernighan's or bit shifting.
- The problem asks if a number is a **power of 2** → `n > 0 && (n & (n-1)) == 0`.
- The problem involves **XOR** to find a unique element (all others appear twice) → XOR all elements.
- The problem involves **swapping** without a temp variable → `a ^= b; b ^= a; a ^= b`.
- Keywords: "binary representation," "bits," "XOR," "power of 2," "count 1s," "single number."

## Worked Example: Single Number

**Problem:** Given an array where every element appears twice except one, find the single one. O(n) time, O(1) space.

### Brute force (O(n²) or O(n) space)

Check each element against all others (O(n²)), or use a hash set (O(n) space).

### Optimized (O(n) time, O(1) space) — XOR

```java
class Solution {
    public int singleNumber(int[] nums) {
        int result = 0;
        for (int x : nums) {
            result ^= x;   // pairs cancel: a ^ a = 0, 0 ^ single = single
        }
        return result;
    }
}
```

**Line-by-line:**
- `result` starts at 0.
- XOR all elements: pairs cancel (a ^ a = 0), leaving only the single element (0 ^ single = single).
- O(n) time, O(1) space — no hash map needed.

**Key insight:** XOR is commutative and associative. `a ^ a = 0` and `a ^ 0 = a`. So all pairs cancel, leaving the unique element.

## Common Mistakes

- **Using `==` for bit comparison.** Bits are integers; use `&`, `|`, `^`, `~`, `<<`, `>>`.
- **Sign extension with `>>`.** Right shift on negative numbers fills with 1s. Use `>>>` (unsigned) when you need 0-fill.
- **Overflow in shifts.** `1 << 31` overflows int. Use `1L << 31` for long.
- **Brian Kernighan's: `n & (n-1)` clears the lowest set bit.** Don't confuse with `n & (n+1)` or other variants.
- **Power of 2 check:** must also check `n > 0`. `0 & (0-1) = 0`, so 0 would falsely pass without the `n > 0` guard.

## How to Explain (interview)

**Opening:** Bit Manipulation uses bitwise operators (AND, OR, XOR, NOT, shifts) to work directly on the binary representation of numbers. Key tricks: XOR cancels pairs (`a ^ a = 0`), `n & (n-1)` clears the lowest set bit (counting bits, power-of-2 check), `x & 1` checks parity. O(1) per operation. Used for "single number," "count bits," "power of 2," and low-level optimizations.

**The basic flow (single number):**
```java
int result = 0;
for (int x : nums) result ^= x;
return result;
```

**The part that trips everyone up:** XOR cancels pairs — `a ^ a = 0`. Also, `n & (n-1)` clears the lowest set bit, which is the basis for counting bits and checking powers of 2. Don't forget `n > 0` in the power-of-2 check.

**The mistakes to remember:**
- Using `>>` on negatives (sign extension) — use `>>>` for 0-fill
- Overflow in shifts: `1 << 31` overflows int
- Power of 2: must check `n > 0` (0 falsely passes)
- Confusing `n & (n-1)` with other bit tricks
