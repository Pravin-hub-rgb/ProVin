# 13.1 Design Problems — The Pattern

## What This Problem Is Asking (Simple Terms)

Design problems ask you to **design a class or data structure** that supports specific operations with given constraints. Unlike algorithm problems that focus on solving a well-defined problem efficiently, design problems require you to **choose data structures, define APIs, and reason about time/space tradeoffs** based on usage patterns.

---

## Example 1

**Problem:** Design a stack that supports push, pop, top, and retrieving the minimum element in constant time.

**Input:** `["MinStack","push","push","push","getMin","pop","top","getMin"]`, `[[],[-2],[0],[-3],[],[],[],[]]`

**Output:** `[null,null,null,-1,0,3,-2]`

**Explanation:** 
- `MinStack minStack = new MinStack();`
- `minStack.push(-2);`
- `minStack.push(0);`
- `minStack.push(-3);`
- `minStack.getMin();` → return -3
- `minStack.pop();`
- `minStack.top();` → return 0
- `minStack.getMin();` → return -2

---

## Constraints

- `-10^5 <= val <= 10^4`
- `1 <= push, pop, top, getMin calls <= 3 * 10^4`

---

## Which Technique, and Why?

Design problems require choosing appropriate data structures based on **access patterns** and **operation frequencies**. The key is to match data structures to operations:

| Operation | Best Data Structure |
|-----------|-------------------|
| Push/pop at both ends | Deque / Linked List |
| Fast lookup by key | HashMap |
| Maintain order | Linked List / TreeMap |
| Track min/max | Heap / Monotonic Stack |
| String manipulation | Trie / HashMap |

**Signal in the problem:** "Design a data structure that supports..." → Design problem. Look at operations and their frequencies to choose data structures.

---

## Approach

**Design approach:**
1. Identify all operations needed
2. Determine frequency of each operation
3. Choose data structures that optimize frequent operations
4. Combine multiple data structures if needed
5. Implement methods using chosen data structures

## Pseudocode (Example: Min Stack)

```
class MinStack:
    stack = []          // stores all elements
    minStack = []       // stores minimums at each level
    
    push(x):
        stack.push(x)
        if minStack empty or x <= minStack[-1]:
            minStack.push(x)
    
    pop():
        if stack.pop() == minStack[-1]:
            minStack.pop()
    
    top():
        return stack[-1]
    
    getMin():
        return minStack[-1]  // O(1) access to minimum!
```

### Java Code (Min Stack)

```java
class MinStack {
    private Deque<Integer> stack;
    private Deque<Integer> minStack;

    public MinStack() {
        stack = new ArrayDeque<>();
        minStack = new ArrayDeque<>();
    }

    public void push(int val) {
        stack.push(val);
        if (minStack.isEmpty() || val <= minStack.peek()) {
            minStack.push(val);
        }
    }

    public void pop() {
        if (stack.pop().equals(minStack.peek())) {
            minStack.pop();
        }
    }

    public int top() {
        return stack.peek();
    }

    public int getMin() {
        return minStack.peek();
    }
}
```

### Line-by-line

- `Deque<Integer> stack` — stores all elements
- `Deque<Integer> minStack` — stores minimums at each level (top = current minimum)
- `minStack.push(val)` only if `val <= minStack.peek()` — tracks minimums
- `stack.pop()` removes top; if it equals minStack top, pop minStack too
- `minStack.peek()` returns current minimum in O(1)

## Complexity

- Time: O(1) for all operations — push, pop, top, getMin
- Space: O(n) — stores all elements in stack, plus minStack

## Common Mistakes

- **Not using a separate minStack** — would require O(n) to find min
- **Not handling duplicate minimums** — use `<=` when pushing to minStack to handle duplicates correctly
- **Not handling empty stack** — check for empty before pop/top/getMin

## How to Explain (interview)

**Opening:** Design problems require choosing data structures based on operations and access patterns. For Min Stack, use two stacks: one for all elements, one for minimums.

**The basic flow:**
```java
class MinStack {
    Deque<Integer> stack;
    Deque<Integer> minStack;
    
    public void push(int val) {
        stack.push(val);
        if (minStack.isEmpty() || val <= minStack.peek()) {
            minStack.push(val);
        }
    }
    
    public void pop() {

            minStack.pop();

    public int getMin() {
        return minStack.peek();
    }

```

**The part that trips everyone up:**
- **Duplicate minimums** — use `<=` when pushing to minStack to handle duplicates correctly
- **Empty stack checks** — always check if stacks are empty before peek/pop

**The mistakes to remember:**
- Not using a separate minStack — would require O(n) to find min
- Not handling duplicates correctly in minStack
- Not handling empty stack cases
