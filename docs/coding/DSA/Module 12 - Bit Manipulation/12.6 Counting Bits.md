**Tier 2 problem.** (LeetCode #338)

**Problem:** Given an integer n, return an array where the ith element is the number of 1 bits in i (for i from 0 to n). (LeetCode #338)

**Link:** https://leetcode.com/problems/counting-bits/

---

## Which Technique, and Why?

"Count set bits for all numbers 0 to n" → **DP on bits** or **Brian Kernighan's per number**. The DP approach: `bits[i] = bits[i >> 1] + (i & 1)` — the number of 1 bits in i is the number of 1 bits in i/2 plus the last bit. O(n) time, O(n) space. Brian Kernighan's per number is O(n × k) — slower.

**Signal in the problem:** "count bits for all numbers 0 to n" → DP: `bits[i] = bits[i >> 1] + (i & 1)`.

## Approach

DP. `bits[0] = 0`. For i from 1 to n: `bits[i] = bits[i >> 1] + (i & 1)`. Because `i >> 1` is `i / 2` (dropping the last bit), and `i & 1` is the last bit.

## Pseudocode

```
bits = new int[n + 1]
bits[0] = 0
for i from 1 to n:
    bits[i] = bits[i >> 1] + (i & 1)
return bits
```

## Java Code

```java
class Solution {
    public int[] countBits(int n) {
        int[] bits = new int[n + 1];
        bits[0] = 0;
        for (int i = 1; i <= n; i++) {
            bits[i] = bits[i >> 1] + (i & 1);
        }
        return bits;
    }
}
```

## Line-by-line

- `bits[0] = 0` — 0 has zero set bits.
- `i >> 1` — i divided by 2 (drop the last bit). `bits[i >> 1]` = number of 1 bits in i without the last bit.
- `i & 1` — the last bit of i (0 or 1).
- Sum = total set bits in i.

## Complexity

- Time: O(n) — single pass.
- Space: O(n) — the result array.

## Common Mistakes

- **Using Brian Kernighan's per number.** O(n × k) where k = number of set bits. Slower than O(n) DP. Use DP for "all numbers 0 to n."
- **Off-by-one in array size.** Array size is `n + 1` (indices 0 to n).
- **Not handling n = 0.** Returns `[0]`. Correct.
- **Using `i / 2` instead of `i >> 1`.** Same result, but `>>` is the bit-manipulation way and avoids division.

## How to Explain (interview)

**Opening:** Counting Bits returns the number of 1 bits for all numbers 0 to n. DP: `bits[i] = bits[i >> 1] + (i & 1)`. The number of 1 bits in i is the number of 1 bits in i/2 plus the last bit. O(n) time, O(n) space. Better than Brian Kernighan's per number (O(n × k)).

**The basic flow:**
```java
int[] bits = new int[n + 1];
for (int i = 1; i <= n; i++) {
    bits[i] = bits[i >> 1] + (i & 1);
}
return bits;
```

**The part that trips everyone up:** `i >> 1` is `i / 2` (drop the last bit). `i & 1` is the last bit. The sum gives the total set bits. This is DP because `bits[i]` depends on `bits[i >> 1]` (a smaller subproblem).

**The mistakes to remember:**
- Using Brian Kernighan's per number (O(n × k) instead of O(n))
- Array size: n + 1 (indices 0 to n)
- Not handling n = 0 (returns [0])
- Using `i / 2` instead of `i >> 1` (works but less idiomatic)
