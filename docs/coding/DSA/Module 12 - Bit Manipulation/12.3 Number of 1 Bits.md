**Problem:** Given an unsigned integer, return the number of '1' bits (Hamming weight). (LeetCode #191)

**Link:** https://leetcode.com/problems/number-of-1-bits/

---

## Which Technique, and Why?

Count set bits in an integer → **Brian Kernighan's algorithm**: `n & (n - 1)` clears the lowest set bit. Repeat until n is 0. O(k) where k = number of set bits (faster than O(32) bit-by-bit).

**Signal in the problem:** "number of 1 bits" / "Hamming weight" / "count set bits" → Brian Kernighan's (`n & (n-1)`).

## Approach

Brian Kernighan's: `n & (n - 1)` clears the lowest set bit. Count how many times you can do this before n becomes 0.

Alternative: bit-by-bit (check each of 32 bits). O(32) = O(1) but slower in practice.

## Pseudocode (Brian Kernighan's)

```
count = 0
while n != 0:
    n = n & (n - 1)   // clear lowest set bit
    count++
return count
```

## Java Code (Brian Kernighan's)

```java
class Solution {
    public int hammingWeight(int n) {
        int count = 0;
        while (n != 0) {
            n &= (n - 1);  // clear lowest set bit
            count++;
        }
        return count;
    }
}
```

## Java Code (bit-by-bit)

```java
class Solution {
    public int hammingWeight(int n) {
        int count = 0;
        for (int i = 0; i < 32; i++) {
            if ((n & 1) == 1) count++;
            n >>>= 1;  // unsigned right shift
        }
        return count;
    }
}
```

## Line-by-line (Brian Kernighan's)

- `n & (n - 1)` clears the lowest set bit. E.g., `n = 12 (1100)`, `n-1 = 11 (1011)`, `n & (n-1) = 1000 (8)`. The lowest 1 (bit 2) is cleared.
- Each iteration clears one set bit. After k iterations (k = number of 1 bits), n becomes 0.
- O(k) time where k = number of set bits. Best case O(1) (one set bit), worst O(32).

## Complexity

- Brian Kernighan's: O(k) where k = number of set bits. Space O(1).
- Bit-by-bit: O(32) = O(1). Space O(1).

## Common Mistakes

- **Using `n >> 1` (signed) instead of `n >>> 1` (unsigned).** For negative numbers (two's complement), signed right shift fills with 1s, causing an infinite loop. Use `>>>` (unsigned) for bit-by-bit on potentially negative inputs. (LeetCode #191 uses unsigned int, so n ≥ 0 — but good habit.)
- **Confusing `n & (n-1)` with `n & (n+1)`.** `n & (n-1)` clears the lowest set bit. `n & (n+1)` clears the lowest unset bit (different trick).
- **Not handling n = 0.** Returns 0 (loop doesn't execute). Correct.

**The mistakes to remember:**
- Using `>>` instead of `>>>` on negatives (infinite loop)
