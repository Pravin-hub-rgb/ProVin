## Mini Quiz

1. Why does XOR find the single number when all others appear twice?
2. What does `n & (n - 1)` do, and why is it useful?
3. Why must you check `n > 0` in the power-of-2 check?
4. What's the difference between `>>` and `>>>` in Java?
5. What is the time complexity of Brian Kernighan's algorithm?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. XOR is commutative and associative. `a ^ a = 0` (pairs cancel), and `0 ^ single = single` (identity). So XORing all elements cancels all pairs, leaving only the single element. O(n) time, O(1) space.
2. `n & (n - 1)` clears the lowest set bit. E.g., 12 (1100) & 11 (1011) = 8 (1000). This is the basis for counting set bits (Brian Kernighan's), checking powers of 2, and detecting if a number has exactly one set bit.
3. Without `n > 0`: n = 0 gives `0 & -1 = 0` → falsely returns true. Negative numbers are never powers of 2. The guard prevents both false positives.
4. `>>` (signed right shift) fills the left with the sign bit (1 for negatives). `>>>` (unsigned right shift) fills with 0. For bit manipulation on potentially negative numbers, use `>>>` to avoid infinite loops and sign extension.
5. O(k) where k = number of set bits. Each iteration clears one set bit. Best case O(1) (one set bit), worst O(32) (all bits set). Compare to O(32) for bit-by-bit.

</details>

## One-Page Cheat Sheet

**Key operators:**
- `&` AND, `|` OR, `^` XOR, `~` NOT, `<<` left shift, `>>` right shift (signed), `>>>` unsigned right shift.

**Key tricks:**
- Parity: `x & 1` (1 = odd, 0 = even).
- Clear lowest set bit: `x & (x - 1)`.
- Check power of 2: `x > 0 && (x & (x - 1)) == 0`.
- Count set bits: Brian Kernighan's (`x &= (x - 1)` in a loop).
- Find single number (others appear twice): XOR all elements.
- Swap without temp: `a ^= b; b ^= a; a ^= b`.

**Complexities:** all bitwise operations O(1). Brian Kernighan's O(k) where k = set bits.

## In Your Own Words

1. Why does XOR find the single element when all others appear twice?

<details>
<summary>Show Answer</summary>

**Sample Answer:** XOR is commutative and associative. `a ^ a = 0` (any value XORed with itself is 0), and `0 ^ a = a` (XOR with 0 is identity). So XORing all elements: pairs cancel to 0, and `0 ^ single = single`. The result is the single element. Order doesn't matter (commutative), and grouping doesn't matter (associative).

</details>

2. What does `n & (n - 1)` do, and what are its applications?

<details>
<summary>Show Answer</summary>

**Sample Answer:** It clears the lowest set bit. E.g., 12 (1100) & 11 (1011) = 8 (1000). Applications: (1) Count set bits (Brian Kernighan's — repeat until 0). (2) Check power of 2 (`n > 0 && (n & (n-1)) == 0` — exactly one set bit). (3) Check if a number has exactly one set bit.

</details>

3. Why is `>>>` preferred over `>>` for bit manipulation on potentially negative numbers?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `>>` (signed) fills the left with the sign bit (1 for negatives), so negative numbers never become 0 — causing infinite loops in bit-counting. `>>>` (unsigned) fills with 0, so the number eventually becomes 0. For non-negative inputs (like LeetCode's unsigned int), both work, but `>>>` is the safe habit.

</details>
