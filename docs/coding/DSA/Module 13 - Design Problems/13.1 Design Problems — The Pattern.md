## The Core Idea

Design problems ask you to implement a data structure (cache, queue, stack, etc.) with specific operations, each meeting a time complexity target. The key skill is **combining** basic structures so each operation is fast.

**The canonical example: LRU Cache (Least Recently Used).**
- Operations: `get(key)` and `put(key, value)` — both must be O(1).
- When capacity is exceeded, evict the least recently used item.

**How to get O(1) for both:**
- `HashMap` for O(1) lookup by key.
- `Doubly linked list` for O(1) insert/remove and ordering (most recent at front, least recent at back).
- Combine: HashMap maps key → node in the linked list. get/put: move node to front (O(1) with doubly linked list). Evict: remove from back (O(1)).

## How to Recognize It

Think "Design" when:
- The problem says "Design a data structure that supports..." or "Implement X."
- Operations have time complexity requirements (O(1), O(log n)).
- Keywords: "LRU Cache," "LFU Cache," "design," "implement," "O(1) operations."

**Signal words:** "design," "implement," "support operations in O(1)," "least recently used," "most frequently used."

## Worked Example: LRU Cache

```java
class LRUCache {
    private final int capacity;
    private final Map<Integer, Node> map;
    private final Node head;  // dummy head (most recent side)
    private final Node tail;  // dummy tail (least recent side)

    static class Node {
        int key, val;
        Node prev, next;
        Node(int k, int v) { key = k; val = v; }
    }

    public LRUCache(int capacity) {
        this.capacity = capacity;
        this.map = new HashMap<>();
        head = new Node(0, 0);
        tail = new Node(0, 0);
        head.next = tail;
        tail.prev = head;
    }

    public int get(int key) {
        Node node = map.get(key);
        if (node == null) return -1;
        moveToHead(node);  // mark as most recently used
        return node.val;
    }

    public void put(int key, int value) {
        Node node = map.get(key);
        if (node != null) {
            node.val = value;
            moveToHead(node);
        } else {
            if (map.size() == capacity) {
                // evict least recently used (node before tail)
                Node lru = tail.prev;
                remove(lru);
                map.remove(lru.key);
            }
            Node newNode = new Node(key, value);
            map.put(key, newNode);
            addToHead(newNode);
        }
    }

    private void addToHead(Node node) {
        node.prev = head;
        node.next = head.next;
        head.next.prev = node;
        head.next = node;
    }

    private void remove(Node node) {
        node.prev.next = node.next;
        node.next.prev = node.prev;
    }

    private void moveToHead(Node node) {
        remove(node);
        addToHead(node);
    }
}
```

**Line-by-line:**
- `head` and `tail` are dummy sentinels — the real list is between them. Most recent near head, least recent near tail.
- `map` gives O(1) lookup by key.
- `get`: if found, move node to head (mark as recently used). Return value.
- `put`: if key exists, update value and move to head. If new and at capacity, evict the LRU (node before tail), remove from map. Then add new node at head.
- `addToHead`/`remove`/`moveToHead`: O(1) doubly linked list operations.

**Key insight:** the combination of HashMap (O(1) lookup) + doubly linked list (O(1) reorder) gives O(1) for all operations. This is the "design" pattern: combine structures to meet complexity targets.

## Common Mistakes

- **Using a single structure.** HashMap alone gives O(1) lookup but O(n) eviction (must scan for LRU). Linked list alone gives O(1) reorder but O(n) lookup. You need both.
- **Forgetting to update the map on eviction.** When evicting the LRU node, remove it from the map too (`map.remove(lru.key)`).
- **Forgetting to move to head on `get`.** A `get` is a "use" — it must mark the item as recently used.
- **Not handling capacity = 0 or capacity = 1.** Edge cases. The code above handles capacity = 0 (map never has entries, evicts immediately) but verify.
- **Using `LinkedHashMap` instead.** Java's `LinkedHashMap` with `accessOrder = true` gives LRU behavior in ~5 lines. But interviews want to see you build it from scratch.

## LinkedHashMap shortcut (for reference)

```java
class LRUCache extends LinkedHashMap<Integer, Integer> {
    private final int capacity;
    public LRUCache(int capacity) {
        super(capacity, 0.75f, true); // accessOrder = true
        this.capacity = capacity;
    }
    protected boolean removeEldestEntry(Map.Entry<Integer, Integer> eldest) {
        return size() > capacity;
    }
    public int get(int key) { return super.getOrDefault(key, -1); }
    public void put(int key, int value) { super.put(key, value); }
}
```

**Note:** This is the "cheat" version. Know it exists, but be able to build the manual version in an interview.

## How to Explain (interview)

**Opening:** LRU Cache supports `get` and `put` in O(1). Combine a HashMap (O(1) lookup by key) with a doubly linked list (O(1) insert/remove/reorder). Most recent items near the head, least recent near the tail. On get/put, move the node to head. On capacity exceeded, evict the node before tail. O(1) all operations, O(capacity) space.

**The basic flow:**
```java
// get: lookup in map, move to head, return value
// put: if exists, update + move to head; else if at capacity, evict LRU, add new at head
```

**The part that trips everyone up:** `get` must move the node to head (it's a "use"). On eviction, remove from **both** the linked list AND the map. Also, use `LinkedHashMap` with `accessOrder = true` for the shortcut, but know the manual version.

**The mistakes to remember:**
- Forgetting to move to head on `get` (not marking as recently used)
- Evicting from the list but not the map (or vice versa)
- Using a single structure (O(n) eviction or O(n) lookup)
- Not handling capacity = 0 or capacity = 1
