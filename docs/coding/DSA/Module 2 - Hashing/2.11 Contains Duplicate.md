**Problem:** Given an integer array `nums`, return `true` if any value appears **at least twice** in the array, and return `false` if every element is distinct.

**Link:** https://leetcode.com/problems/contains-duplicate/

---

## What This Problem Is Asking (Simple Terms)

You have an array of integers. You need to check whether **any number appears more than once** in the array. If even one value is repeated, return `true`. If every value is unique, return `false`.

You are not asked to find *which* value is duplicated or *where* — just whether a duplicate exists.

---

## Example 1

**Input:** `nums = [1,2,3,1]`

**Output:** `true`

**Explanation:** The element `1` appears at indices `0` and `3`. So a duplicate exists.

---

## Example 2

**Input:** `nums = [1,2,3,4]`

**Output:** `false`

**Explanation:** All elements are distinct. No duplicate exists.

---

## Example 3

**Input:** `nums = [1,1,1,3,3,4,3,2,4,2]`

**Output:** `true`

**Explanation:** Multiple elements appear more than once (`1`, `3`, `4`, `2`).

---

## Constraints

- `1 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`

**Follow-up:** Can you solve it in O(n) time and O(n) space? Can you do it with O(1) extra space (sorting)?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You stand at index `0` (value `1` in Example 1). You scan the rest of the array looking for another `1`. You find it at index `3`. Done — duplicate exists.

If not found at index `0`, you move to index `1` and scan from index `2` onward. And so on.

This is a **loop inside a loop**:
- Outer loop: pick each element
- Inner loop: scan all elements after it looking for the same value

### Brute Force Pseudocode

```
for i from 0 to n-1:
    for j from i+1 to n-1:
        if nums[i] == nums[j]:
            return true
return false
```

### Why Brute Force Is Slow

With `n` elements, the outer loop runs `n` times and the inner loop runs up to `n` times for each outer iteration. That's about `n × n = n²` operations. For `n = 10^5`, that's `10^10` operations — too slow.

---

## Which Data Structure, and Why?

You learned in 2.8 that a **HashSet** answers: "Have I seen this value before?" → yes/no.

For Contains Duplicate, that's **exactly** what you need:
- For each element, ask: "Have I seen this value before?"
- If yes → duplicate found → return `true`
- If no → store it and move on

HashSet is perfect here because you only need **membership** (seen/not seen), not any associated value.

**Why not HashMap?** A HashMap stores `key → value`. Here you don't need a value — you just need to know whether the key exists. Using HashMap would work but wastes memory storing values you never use.

**Signal in the problem:** "any value appears at least twice" / "all distinct" → membership test → HashSet.

---

## Optimized Approach (One Pass with HashSet)

Instead of a second traversal, store each value in a HashSet as you go:

1. Start with an empty HashSet
2. For each element:
   - Try to add it to the set using `add()`
   - `add()` returns `true` if the value was new, `false` if it was already there
   - If `false` → duplicate found → return `true`
   - If `true` → value was new, continue
3. If loop finishes, all elements are distinct → return `false`

### Why This Is O(n)

You traverse the array **once**. Each HashSet operation (`add`, `contains`) is O(1) average. So total time is O(n), space is O(n) for the set.

### Pseudocode

```
seen = empty set
for each x in nums:
    if x in seen: return true
    seen.add(x)
return false
```

### Java Code

```java
class Solution {
    public boolean containsDuplicate(int[] nums) {
        Set<Integer> seen = new HashSet<>();
        for (int x : nums) {
            if (!seen.add(x)) {   // add returns false if already present
                return true;
            }
        }
        return false;
    }
}
```

### Line-by-line

- `seen` holds values we've already encountered.
- `seen.add(x)` returns `true` if `x` was new (added successfully), `false` if `x` was already in the set.
- `!seen.add(x)` is true exactly when `x` is a duplicate — detection in one line, no separate `contains` call.
- If loop finishes without finding a duplicate, return `false`.

## Complexity

- Time: O(n) — single pass, O(1) set ops.
- Space: O(n) — set stores up to n elements (worst case, all distinct).

## Common Mistakes

- **Using a nested loop** (O(n²)) when a set gives O(n). Always reach for a set for "have I seen this?"
- **Forgetting to short-circuit.** Return `true` on the first duplicate found; don't keep scanning.
- **Sorting approach trap:** sorting is O(n log n) and mutates the input. Use only if O(1) extra space is required.

## How to Explain (interview)

**Opening:** Contains Duplicate asks if any value appears more than once. The brute force compares every pair — O(n²). The optimized version walks the array once with a HashSet: for each element, try to add it; if `add` returns false, it was already there, so return true. If the loop finishes, all elements are distinct. O(n) time, O(n) space.

**The basic flow:**
```java
Set<Integer> seen = new HashSet<>();
for (int x : nums) {
    if (!seen.add(x)) return true;
}
return false;
```

**The part that trips everyone up:** `add` returns a boolean — `true` if new, `false` if duplicate. Use that return value instead of a separate `contains` check.

**The mistakes to remember:**
- Using nested loops (O(n²)) instead of a set (O(n))
- Not short-circuiting on the first duplicate
- Sorting when you don't need to (slower, mutates input)
