**Problem:** Given an integer array of size `n`, find all elements that appear more than `⌊n / 3⌋` times.

**Link:** https://leetcode.com/problems/majority-element-ii/

---

## What This Problem Is Asking (Simple Terms)

You have an array of integers. You need to find all elements that appear **more than `n/3` times**.

Since more than `n/3` occurrences means an element takes up more than one-third of the array, there can be **at most 2** such elements.

For example, if `nums = [3,2,3]` (n=3), threshold > `3/3` = >1. `3` appears 2 times (>1), so it qualifies.

---

## Example 1

**Input:** `nums = [3,2,3]`

**Output:** `[3]`

**Explanation:** `n = 3`, threshold > `3/3` = >1. `3` appears 2 times (>1), so it qualifies.

---

## Example 2

**Input:** `nums = [1]`

**Output:** `[1]`

**Explanation:** `n = 1`, threshold > `1/3` = >0. `1` appears 1 time (>0), so it qualifies.

---

## Example 3

**Input:** `nums = [1,2]`

**Output:** `[1,2]`

**Explanation:** `n = 2`, threshold > `2/3` = >0. Both `1` and `2` appear 1 time each (>0), so both qualify.

---

## Constraints

- `1 <= nums.length <= 5 * 10^4`
- `-10^9 <= nums[i] <= 10^9`

**Follow-up:** Could you solve it in linear time and in O(1) space?

---

## Which Data Structure, and Why?

You need elements appearing more than `n/3` times → at most 2 such elements. Two approaches:

1. **HashMap** (value → count): count frequencies, return keys exceeding n/3. O(n) time, O(n) space. Simple.
2. **Boyer-Moore Voting (extended)**: track two candidates and counts. O(n) time, O(1) space.

**Signal in the problem:** "more than n/3" / "majority element II" → at most 2 candidates → Boyer-Moore with two counters, or HashMap.

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could count how many times each element appears, then check which counts exceed `n/3`.

### Brute Force Pseudocode

```
for each element x in nums:
    count = 0
    for each element y in nums:
        if y == x: count++
    if count > n / 3: add x to result
return result (with duplicates removed)
```

### Why Brute Force Is Slow

The outer loop runs `n` times, and the inner loop runs `n` times for each outer iteration. That's O(n²) — too slow for `n = 5 * 10^4`.

---

## Why HashMap or Boyer-Moore?

You need to find elements with frequency > n/3. Two approaches:

1. **HashMap** (value → count): count frequencies, return keys with count > n/3. O(n) time, O(n) space. Simple and general.
2. **Boyer-Moore Voting (extended)**: O(n) time, O(1) space. Track two candidates and two counts — at most 2 elements can appear more than n/3 times.

**Signal in the problem:** "more than n/3" / "majority element II" → at most 2 candidates → Boyer-Moore with two counters, or HashMap.

---

## Optimized Approach (Boyer-Moore Extended — O(1) space)

Track two candidates and two counts. For each element:
- If it matches a candidate, increment that count.
- If a count is 0, set that candidate.
- Otherwise decrement both.

After the pass, verify each candidate's actual count > n/3 (Boyer-Moore only guarantees candidates, not majority).

### Pseudocode (Boyer-Moore)

```
cand1 = null, cand2 = null, count1 = 0, count2 = 0
for x in nums:
    if x == cand1: count1++
    else if x == cand2: count2++
    else if count1 == 0: cand1 = x; count1 = 1
    else if count2 == 0: cand2 = x; count2 = 1
    else: count1--; count2--
// verify
result = []
for c in {cand1, cand2}:
    if count of c in nums > n/3: result.add(c)
return result
```

### Java Code (HashMap)

```java
class Solution {
    public List<Integer> majorityElement(int[] nums) {
        Map<Integer, Integer> freq = new HashMap<>();
        for (int x : nums) freq.put(x, freq.getOrDefault(x, 0) + 1);
        List<Integer> result = new ArrayList<>();
        int n = nums.length;
        for (Map.Entry<Integer, Integer> e : freq.entrySet()) {
            if (e.getValue() > n / 3) result.add(e.getKey());
        }
        return result;
    }
}
```

### Java Code (Boyer-Moore)

```java
class Solution {
    public List<Integer> majorityElement(int[] nums) {
        Integer cand1 = null, cand2 = null;
        int count1 = 0, count2 = 0;

        for (int x : nums) {
            if (cand1 != null && x == cand1) count1++;
            else if (cand2 != null && x == cand2) count2++;
            else if (count1 == 0) { cand1 = x; count1 = 1; }
            else if (count2 == 0) { cand2 = x; count2 = 1; }
            else { count1--; count2--; }
        }

        // Verify
        List<Integer> result = new ArrayList<>();
        int n = nums.length;
        if (cand1 != null && count(nums, cand1) > n / 3) result.add(cand1);
        if (cand2 != null && cand2 != cand1 && count(nums, cand2) > n / 3) result.add(cand2);
        return result;
    }

    private int count(int[] nums, int target) {
        int c = 0;
        for (int x : nums) if (x == target) c++;
        return c;
    }
}
```

### Line-by-line (Boyer-Moore)

- Track two candidates and counts.
- For each element: if it matches a candidate, increment; if a count is 0, set candidate; otherwise decrement both.
- After the pass, verify each candidate's actual count > n/3 (Boyer-Moore only guarantees candidates, not majority).

## Complexity

- HashMap: O(n) time, O(n) space.
- Boyer-Moore: O(n) time, O(1) space.

## Common Mistakes

- **Not verifying candidates.** Boyer-Moore only gives candidates; you must verify their counts.
- **Duplicate candidate.** If cand1 == cand2, don't add twice. Check `cand2 != cand1`.
- **Threshold.** "More than n/3" means `> n/3`, not `>= n/3`. For n=3, threshold is >1, so 2+ occurrences.
- **Using HashMap when O(1) space is required.** HashMap is simpler; Boyer-Moore is for O(1) space.

## How to Explain (interview)

**Opening:** Majority Element II finds elements appearing more than n/3 times (at most 2 such elements). HashMap approach: count frequencies, return keys with count > n/3 — O(n) time, O(n) space. Boyer-Moore (extended): track two candidates and counts; verify each candidate's actual count. O(n) time, O(1) space.

**The basic flow (Boyer-Moore):**
```java
Integer cand1 = null, cand2 = null;
int count1 = 0, count2 = 0;
for (int x : nums) {
    if (x == cand1) count1++;
    else if (x == cand2) count2++;
    else if (count1 == 0) { cand1 = x; count1 = 1; }
    else if (count2 == 0) { cand2 = x; count2 = 1; }
    else { count1--; count2--; }
}
// verify both candidates
```

**The part that trips everyone up:** Boyer-Moore only gives **candidates**, not guaranteed majority elements. You must verify each candidate's actual count > n/3. Also, handle the case where cand1 == cand2 (don't add twice).

**The mistakes to remember:**
- Not verifying candidates (wrong answer on non-majority inputs)
- Duplicate candidate (cand1 == cand2)
- Threshold: "more than n/3" means strictly greater
- Using HashMap when O(1) space is required
