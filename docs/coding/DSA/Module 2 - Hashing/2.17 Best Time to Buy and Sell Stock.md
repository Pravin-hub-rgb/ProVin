**Problem:** You are given an array `prices` where `prices[i]` is the price of a given stock on the `i`th day.

You want to maximize your profit by choosing a **single day** to buy one stock and choosing a **different day in the future** to sell that stock.

Return the **maximum profit** you can achieve from this transaction. If you cannot achieve any profit, return `0`.

**Link:** https://leetcode.com/problems/best-time-to-buy-and-sell-stock/

---

## What This Problem Is Asking (Simple Terms)

You have a list of stock prices, one per day. You can buy on one day and sell on a **later** day. You want to maximize profit (sell price − buy price).

Two rules to hold onto: you can only sell **after** you buy, and you make **one** trade only.

If prices only go down, you can't make a profit — return `0`.

---

## Example 1

**Input:** `prices = [7,1,5,3,6,4]`

**Output:** `5`

**Explanation:** Buy on day 2 (price = 1) and sell on day 5 (price = 6), profit = 6-1 = 5.

Note that buying on day 2 and selling on day 1 is not allowed because you must buy before you sell.

---

## Example 2

**Input:** `prices = [7,6,4,3,1]`

**Output:** `0`

**Explanation:** In this case, no transactions are done and the max profit = 0 — prices only fall, so no trade is taken.

---

## Constraints

- `1 <= prices.length <= 10^5`
- `0 <= prices[i] <= 10^4`

**Follow-up:** What if you could complete as many transactions as you like (i.e., buy one and sell one share of the stock multiple times)? — that's a *different* problem (LeetCode 122, "Stock II"), saved for later; this file is the one-buy-one-sell version.

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand? For each day `i` (buy day), look at every later day `j` (sell day) and compute `prices[j] - prices[i]`. Track the maximum profit.

### Brute Force Pseudocode

```
maxProfit = 0
for i from 0 to n-1:
    for j from i+1 to n-1:
        profit = prices[j] - prices[i]
        if profit > maxProfit: maxProfit = profit
return maxProfit
```

### Why Brute Force Is Slow

The outer loop runs `n` times, and the inner loop runs up to `n` times for each outer iteration. That's about `n × n = n²` operations. For `n = 10^5`, that's `10^10` operations — too slow.

---

## First Try: Find the Global Min First (The Two-Pass Trap)

The natural first idea — and the one tried live before it broke: **first pass, find the smallest price in the whole array. Second pass, walk ahead from there and measure the gap to the end, keeping the biggest gap.** Every time a bigger gap shows up, it replaces the previous smallest-based one.

The problem shows up the moment you pick your example: **the lowest price in the array might be on the last day.** In `[5,4,3,1]`, the min is `1` — and there's nothing after it to sell to. Worse, in `[2,5,1]` the global min `1` again sits at the end, so the two-pass approach reports `0` — but the real answer is `3` (buy at `2`, sell at `5`).

The deep reason: **the buy day must come before the sell day, and the min that matters is the min *before your sell day* — not the global min of the whole array.** A low that appears *after* a great spread is useless to you.

So instead of finding the lowest first and hoping, **track it as you walk.**

---

## The Insight: Sell Today — What From the Past?

Stand on any one day and imagine selling today. To get the best profit, what number from the earlier days would you want to have bought at? **The lowest price seen so far.**

That gives the plan: walk through the days once, keep track of the lowest price you've seen, and at each day ask — *if I sold today, what would my profit be?* Keep the best of those.

**Variables you need: exactly two.** `minPrice` (lowest price seen so far) and `maxProfit` (best profit seen so far). No HashMap, no HashSet — one walk through the array with two variables is enough. Linear time, constant space.

---

## Hand Trace: [7, 1, 5, 3, 6, 4]

Do it by hand first — the code is only this table in Java clothes:

| Day | Price | What happens | minPrice | Profit if sold today | maxProfit |
|-----|-------|--------------|----------|----------------------|-----------|
| 1 | 7 | first price → min becomes 7 | 7 | 7−7 = 0 | 0 |
| 2 | 1 | 1 < 7 → **new low, update min** | 1 | 1−1 = 0 | 0 |
| 3 | 5 | not a new low → check profit | 1 | 5−1 = 4 | **4** |
| 4 | 3 | not a new low → check profit | 1 | 3−1 = 2 | 4 |
| 5 | 6 | not a new low → check profit | 1 | 6−1 = 5 | **5** |
| 6 | 4 | not a new low → check profit | 1 | 4−1 = 3 | 5 |

Return `5` — buy day 2 (price 1), sell day 5 (price 6). Note day 2: updating the min *and* computing profit gives 0, which can't beat the running max — harmless.

## Approach 1: The Branching Version (Built Live — This Is What Got Submitted)

The trace runs in two branches: **today is a new low → update `minPrice`; otherwise → check today's profit.**

### Java Code

```java
class Solution {
    public int maxProfit(int[] prices) {
        int minPrice = Integer.MAX_VALUE;
        int maxProfit = 0;
        for (int i = 0; i < prices.length; i++) {
            if (prices[i] < minPrice) {
                minPrice = prices[i];
            } else if ((prices[i] - minPrice) > maxProfit) {
                maxProfit = prices[i] - minPrice;
            }
        }
        return maxProfit;
    }
}
```

### Line-by-line

- `int minPrice = Integer.MAX_VALUE;` — start the min at the biggest possible int, so the **first price always replaces it**. (Starting at `prices[0]` works too — then the loop can start at index 0 or 1, since the first price compared against itself changes nothing. Both choices were discussed; `MAX_VALUE` is the common textbook form.)
- `int maxProfit = 0;` — the running best. `0` (not `Integer.MIN_VALUE`) because "no profit" is a legal answer: if prices only fall, we return `0`, never a negative.
- `for (int i = 0; i < prices.length; i++)` — one pass over the days, left to right.
- `if (prices[i] < minPrice)` — **today is a new low**: update the min. The comparison reads *"is today's price smaller than the min so far"* — the variable on the left of `<` is the one being tested against.
- `minPrice = prices[i];` — the new low becomes the buy reference.
- `else if ((prices[i] - minPrice) > maxProfit)` — not a new low, so this day is a *candidate sell day*: profit = today − min so far; keep it only if it beats the best so far. (On a new-low day the profit would be 0 — it can never beat a positive `maxProfit`, which is why the `else` costs nothing.)
- `maxProfit = prices[i] - minPrice;` — store the new best.
- `return maxProfit;` — the winner.

**How this code was built (three live rounds):** the first draft had the comparison backwards (`if (minPrice < prices[i])` — updating the min when the price was *higher*) plus two typos (`minPrices`, `manProfit`); the second round lost the `if` after `else`; the third had an extra `)` in the condition. Each fix came from reading the error and the logic — not guessing. Then: **submitted — 1 ms, beating 99.94%.**

**Branches or one-liners?** A plain `if` (no `else`) also works — you'd just recompute profit on new-low days, which is 0 and harmless. The `else if` matches the hand trace exactly: one branch per kind of day.

## Approach 2: The Compact Math.min/Math.max Version (The Notes' Version)

The same algorithm, written shorter — the `if`/`else if` branches replaced by two built-ins doing the choosing:

### Java Code

```java
class Solution {
    public int maxProfit(int[] prices) {
        int minPrice = Integer.MAX_VALUE;
        int maxProfit = 0;
        for (int price : prices) {
            minPrice = Math.min(minPrice, price);
            maxProfit = Math.max(maxProfit, price - minPrice);
        }
        return maxProfit;
    }
}
```

### Line-by-line

- `for (int price : prices)` — a **for-each** loop: no index, just each price in turn.
- `Math.min(minPrice, price)` — picks the smaller of the two, so `minPrice` only ever drops.
- `Math.max(maxProfit, price - minPrice)` — picks the bigger, so `maxProfit` only ever grows.

**The one difference:** it updates `minPrice` first and computes profit on the *same* day. On a new-low day that profit is `0`, which can't beat `maxProfit` — harmless, same result.

**Same logic, same speed (both 1 ms).** One branches on each day, the other lets `min`/`max` do the choosing. The branching version shows the *thinking* — that's the part worth knowing; the compact one is just shorter to write. `Math.min`/`Math.max` are worth keeping in your toolkit either way.

## Complexity

- **Time:** O(n) — single pass, both versions.
- **Space:** O(1) — two variables. No map or set needed.

## Common Mistakes

- **The two-pass global-min trap:** finding the lowest price in the *whole array* first, then looking after it — the min may be last (`[5,4,3,1]`), or a great spread may sit entirely before it (`[2,5,1]` → reports 0, answer is 3). The min must be tracked **as you walk**, always *before* the sell day.
- **Backwards comparison:** `if (minPrice < prices[i])` updates the min when today's price is *higher*. It must be `prices[i] < minPrice` — today's price is the candidate being tested.
- **`else` with no `if`:** `else { (cond) maxProfit = ... }` is a syntax error — a condition needs `if`. It's `else if (cond) { ... }`, and the condition gets **one** pair of brackets: `if ((prices[i] - minPrice) > maxProfit)` — count the closing brackets; the subtraction needs its own pair, and that's it (an extra `)` was a real compile error here).
- **Variable-name typos:** `minPrices` / `manProfit` won't compile — Java doesn't know them. One `n` in the wrong place is still an error; read the compiler message, it points at the exact name.
- **Returning a negative profit:** initialize `maxProfit = 0`, not `Integer.MIN_VALUE` — if prices only decrease, the answer is `0` (no trade), not a negative number.
- **Selling before buying:** the "min so far" approach guarantees buy-before-sell for free — the min is always from an earlier day. A naive "pick any two days" doesn't.
- **Confusing with "Best Time to Buy and Sell Stock II"** (the follow-up: unlimited transactions) — that's a different problem (greedy: sum all positive climbs).
- **Off-by-one / tiny arrays:** one price → loop runs, profit stays 0. Handled by the same code.

## How to Explain (interview)

**Opening:** Best Time to Buy and Sell Stock asks for the max profit from one buy and one sell, buy before sell. The brute force checks all pairs — O(n²). The fix for the naive "find the global min first" idea: the min must come *before* your sell day, so you track the minimum price **seen so far** while walking the array once. At each day, profit = today's price − min so far; keep the best. O(n) time, O(1) space — two variables, no map.

**The basic flow (branching version):**
```java
int minPrice = Integer.MAX_VALUE, maxProfit = 0;
for (int i = 0; i < prices.length; i++) {
    if (prices[i] < minPrice) {
        minPrice = prices[i];
    } else if ((prices[i] - minPrice) > maxProfit) {
        maxProfit = prices[i] - minPrice;
    }
}
return maxProfit;
```

(Compact form: `minPrice = Math.min(minPrice, price); maxProfit = Math.max(maxProfit, price - minPrice);` in a for-each — same algorithm, two lines.)

**The part that trips everyone up:** "find the lowest price first" feels right but breaks — the global min may be at the end, or the best spread may be entirely before it. The low you need is the lowest **before your sell day**, which is exactly what a running `minPrice` gives you.

**The mistakes to remember:**
- Backwards comparison (`minPrice < prices[i]`)
- `else` without `if`, or an extra `)` in the condition
- `maxProfit` initialized to `Integer.MIN_VALUE` instead of `0`
- The two-pass global-min trap (min after the sell day is useless)
