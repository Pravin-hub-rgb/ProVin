# 7.9 My Calendar I

**Tier 2 problem.** (LeetCode #729)

**Problem:** Implement a calendar that can book events. An event can be booked if it doesn't overlap with existing events. (LeetCode #729)

**Link:** https://leetcode.com/problems/my-calendar-i/

---

## Which Technique, and Why?

"Book event if no overlap" → **TreeMap (sorted intervals) or sorted list + binary search**. Store booked intervals sorted by start. For a new event [start, end], check if it overlaps with any existing interval. O(log n) per booking with TreeMap, O(n) with a list.

**Signal in the problem:** "book event" / "no overlap" / "calendar" → sorted intervals + overlap check.

## Approach (sorted list + linear scan — simplest)

Store booked intervals in a list (sorted by start). For a new event, check overlap with all existing intervals. If no overlap, add and sort (or maintain sorted order). O(n) per booking.

Alternative: TreeMap keyed by start, use `floorEntry`/`ceilingEntry` for O(log n) overlap check.

## Pseudocode

```
booked = empty list
book(start, end):
    for each [s, e] in booked:
        if start < e and end > s:  // overlap
            return false
    booked.add([start, end])
    return true
```

## Java Code (sorted list)

```java
class MyCalendar {
    private final List<int[]> booked;

    public MyCalendar() {
        booked = new ArrayList<>();
    }

    public boolean book(int start, int end) {
        for (int[] interval : booked) {
            if (start < interval[1] && end > interval[0]) {
                return false;  // overlap
            }
        }
        booked.add(new int[]{start, end});
        return true;
    }
}
```

## Java Code (TreeMap — O(log n))

```java
class MyCalendar {
    private final TreeMap<Integer, Integer> bookings; // start -> end

    public MyCalendar() {
        bookings = new TreeMap<>();
    }

    public boolean book(int start, int end) {
        Map.Entry<Integer, Integer> floor = bookings.floorEntry(start);
        if (floor != null && floor.getValue() > start) return false; // overlaps with previous

        Map.Entry<Integer, Integer> ceil = bookings.ceilingEntry(start);
        if (ceil != null && ceil.getKey() < end) return false; // overlaps with next

        bookings.put(start, end);
        return true;
    }
}
```

## Line-by-line (TreeMap version)

- `floorEntry(start)` — the interval with the largest start ≤ `start`. If its end > start → overlap.
- `ceilingEntry(start)` — the interval with the smallest start ≥ `start`. If its start < end → overlap.
- Only need to check these two (sorted order guarantees all others are further away).
- If no overlap → add to map.

## Complexity

- Sorted list: O(n) per booking (scan all), O(n) space.
- TreeMap: O(log n) per booking, O(n) space.

## Common Mistakes

- **Overlap condition.** Two intervals [s1, e1) and [s2, e2) overlap if `s1 < e2 && s2 < e1`. Using `<=` is wrong (touching intervals don't overlap).
- **Not checking both neighbors.** With a sorted structure, only the floor and ceiling entries can overlap. Checking all is O(n) but correct; checking only neighbors is O(log n).
- **Using `put` before checking.** Check first, then add. Adding before checking can create false overlaps.
- **Modifying the map during iteration.** Use `floorEntry`/`ceilingEntry` (read-only) before `put`.

## How to Explain (interview)

**Opening:** My Calendar I books events if they don't overlap. Store intervals in a TreeMap (sorted by start). For a new event [start, end], check the floor entry (largest start ≤ start) and ceiling entry (smallest start ≥ start). If either overlaps, reject. O(log n) per booking.

**The basic flow:**
```java
TreeMap<Integer, Integer> bookings = new TreeMap<>();
boolean book(int start, int end) {
    Map.Entry<Integer, Integer> floor = bookings.floorEntry(start);
    if (floor != null && floor.getValue() > start) return false;
    Map.Entry<Integer, Integer> ceil = bookings.ceilingEntry(start);
    if (ceil != null && ceil.getKey() < end) return false;
    bookings.put(start, end);
    return true;
}
```

**The part that trips everyone up:** overlap is `start < otherEnd && otherStart < end` (strictly). Touching intervals (end == otherStart) don't overlap. Also, only check floor and ceiling — sorted order guarantees others can't overlap.

**The mistakes to remember:**
- Using `<=` in overlap check (touching intervals overlap — wrong)
- Not checking both floor and ceiling
- Adding before checking (false overlaps)
- Using a list (O(n)) when TreeMap gives O(log n)
