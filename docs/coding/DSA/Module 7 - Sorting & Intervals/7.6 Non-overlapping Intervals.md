**Tier 2 problem.** (LeetCode #435)

**Problem:** Given an array of intervals, find the minimum number of intervals to remove so that the rest are non-overlapping. (LeetCode #435)

**Link:** https://leetcode.com/problems/non-overlapping-intervals/

---

## Which Technique, and Why?

"Minimum intervals to remove for non-overlapping" → **Greedy: sort by end time, keep the earliest-ending interval.** Sort by end. Walk through; if current interval overlaps with the last kept one (start < lastEnd), remove it (increment count). Else, keep it (update lastEnd). O(n log n) time, O(1) space.

**Signal in the problem:** "minimum to remove" + "non-overlapping intervals" → sort by end time, greedy keep.

## Approach

Sort intervals by end time. Keep the first. For each next: if it doesn't overlap with the last kept (start ≥ lastEnd), keep it (update lastEnd). Else, remove it (count++). The greedy choice: keeping the earliest-ending interval leaves the most room for future intervals.

## Pseudocode

```
sort intervals by end
count = 0
lastEnd = intervals[0][1]
for i from 1 to n-1:
    if intervals[i][0] >= lastEnd:  // no overlap
        lastEnd = intervals[i][1]
    else:
        count++  // remove this interval
return count
```

## Java Code

```java
class Solution {
    public int eraseOverlapIntervals(int[][] intervals) {
        if (intervals.length == 0) return 0;
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1])); // sort by end

        int count = 0;
        int lastEnd = intervals[0][1];

        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] >= lastEnd) {
                lastEnd = intervals[i][1];  // keep
            } else {
                count++;  // remove
            }
        }
        return count;
    }
}
```

## Line-by-line

- Sort by end time — the greedy choice: keep the earliest-ending interval.
- `lastEnd` tracks the end of the last kept interval.
- `intervals[i][0] >= lastEnd` — no overlap → keep, update lastEnd.
- Else → overlap → remove (count++).
- Return count.

## Complexity

- Time: O(n log n) — sorting dominates.
- Space: O(1) extra (or O(log n) for sort stack).

## Common Mistakes

- **Sorting by start instead of end.** Sorting by start doesn't give the greedy optimal. Sort by end.
- **Using `>` instead of `>=`.** Touching intervals (start == lastEnd) don't overlap → keep. Use `>=`.
- **Not handling empty input.** Return 0.
- **Confusing with "Merge Intervals" (#56).** Merge merges overlapping; this one removes to make non-overlapping.

## How to Explain (interview)

**Opening:** Non-overlapping Intervals finds the minimum intervals to remove so the rest don't overlap. Greedy: sort by end time, keep the earliest-ending interval (leaves most room). If the next interval overlaps (start < lastEnd), remove it. O(n log n) time, O(1) space.

**The basic flow:**
```java
Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1]));
int lastEnd = intervals[0][1], count = 0;
for (int i = 1; i < intervals.length; i++) {
    if (intervals[i][0] >= lastEnd) lastEnd = intervals[i][1];
    else count++;
}
```

**The part that trips everyone up:** sort by **end time**, not start time. The greedy choice is "keep the interval that ends earliest" — this leaves maximum room for future intervals. Also, touching intervals (`start == lastEnd`) don't overlap.

**The mistakes to remember:**
- Sorting by start instead of end (wrong greedy)
- Using `>` instead of `>=` (touching intervals)
- Not handling empty input
- Confusing with Merge Intervals (#56)
