**Problem:** Given an array of integers, sort it in ascending order. (LeetCode #912)

**Link:** https://leetcode.com/problems/sort-an-array/

---

## Which Technique, and Why?

"Sort an array" → you can just use `Arrays.sort` (O(n log n)). But the problem likely tests whether you can implement a sort yourself. Common implementations: Merge Sort (stable, O(n log n), O(n) space) or Quick Sort (in-place, O(n log n) average, O(n²) worst).

**Signal in the problem:** "sort an array" without using built-in sort → implement Merge Sort or Quick Sort. If built-in is allowed, `Arrays.sort` is the answer.

## Approach (Merge Sort — stable, guaranteed O(n log n))

Divide the array in half recursively until single elements, then merge two sorted halves back together. Merge is O(n); depth is log n → O(n log n).

## Pseudocode

```
mergeSort(arr, left, right):
    if left >= right: return
    mid = left + (right - left) / 2
    mergeSort(arr, left, mid)
    mergeSort(arr, mid+1, right)
    merge(arr, left, mid, right)

merge(arr, left, mid, right):
    temp = new array of size (right - left + 1)
    i = left, j = mid + 1, k = 0
    while i <= mid and j <= right:
        if arr[i] <= arr[j]: temp[k++] = arr[i++]
        else: temp[k++] = arr[j++]
    copy remaining from left half
    copy remaining from right half
    copy temp back to arr
```

## Java Code (Merge Sort)

```java
class Solution {
    public int[] sortArray(int[] nums) {
        mergeSort(nums, 0, nums.length - 1);
        return nums;
    }

    private void mergeSort(int[] arr, int left, int right) {
        if (left >= right) return;
        int mid = left + (right - left) / 2;
        mergeSort(arr, left, mid);
        mergeSort(arr, mid + 1, right);
        merge(arr, left, mid, right);
    }

    private void merge(int[] arr, int left, int mid, int right) {
        int[] temp = new int[right - left + 1];
        int i = left, j = mid + 1, k = 0;

        while (i <= mid && j <= right) {
            if (arr[i] <= arr[j]) temp[k++] = arr[i++];
            else temp[k++] = arr[j++];
        }
        while (i <= mid) temp[k++] = arr[i++];
        while (j <= right) temp[k++] = arr[j++];

        System.arraycopy(temp, 0, arr, left, temp.length);
    }
}
```

## Line-by-line

- `mergeSort` recursively splits the array in half until single elements (base case `left >= right`).
- `merge` combines two sorted halves into one sorted array using a temp array.
- `i` walks the left half, `j` walks the right half, `k` writes to temp. Always pick the smaller.
- Copy remaining elements from whichever half isn't exhausted.
- `System.arraycopy` copies temp back into the original array.

## Complexity

- Time: O(n log n) — log n levels, each level does O(n) work in merge.
- Space: O(n) — temp array for merging (plus O(log n) recursion stack).

## Common Mistakes

- **Not handling the base case.** `if (left >= right) return;` prevents infinite recursion.
- **Off-by-one in mid.** `mid = left + (right - left) / 2`. Using `(left + right) / 2` can overflow.
- **Forgetting to copy remaining elements.** After the main while loop, one half may have leftover elements — copy them.
- **Using `arr[i] < arr[j]` instead of `<=`.** Using `<` breaks stability (equal elements swap order). Use `<=` for stable sort.
- **Quick Sort worst case.** Quick sort is O(n²) on already-sorted input with a bad pivot. Merge sort guarantees O(n log n).

## How to Explain (interview)

**Opening:** Sort an Array asks you to sort integers. The simplest answer is `Arrays.sort(nums)` (O(n log n)). If implementing manually, Merge Sort is the safe choice: divide in half recursively, merge two sorted halves. O(n log n) guaranteed, stable, O(n) space. Quick Sort is in-place but O(n²) worst case.

**The basic flow:**
```java
void mergeSort(int[] arr, int l, int r) {
    if (l >= r) return;
    int mid = l + (r - l) / 2;
    mergeSort(arr, l, mid);
    mergeSort(arr, mid + 1, r);
    merge(arr, l, mid, r);  // merge two sorted halves
}
```

**The part that trips everyone up:** the merge step must copy **remaining elements** from whichever half isn't exhausted. Also use `<=` (not `<`) in the comparison to maintain stability.

**The mistakes to remember:**
- Forgetting the base case (infinite recursion)
- Not copying remaining elements after the main merge loop
- Using `<` instead of `<=` (breaks stability)
- Quick Sort on sorted input → O(n²) (use Merge Sort or randomized pivot)
