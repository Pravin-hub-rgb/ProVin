## Tool Primer: Sorting in Java

### Arrays.sort (primitives)

```java
int[] arr = {30, 10, 50, 20, 40};
Arrays.sort(arr);                    // in place, ascending: [10,20,30,40,50]
Arrays.sort(arr, 1, 4);              // sort indices [1,4): [30,20,40,50] → [30,20,40,50] sorted in range
```

- Primitives: tuned quicksort, O(n log n), not stable.
- Objects: TimSort, O(n log n), stable.

### Arrays.sort with Comparator (objects/arrays)

```java
// Sort integers descending
Integer[] arr = {3, 1, 4, 1, 5};
Arrays.sort(arr, (a, b) -> b - a);   // descending: [5,4,3,1,1]

// Sort a 2D array by first column
int[][] intervals = {{1,3},{2,6},{8,10}};
Arrays.sort(intervals, (a, b) -> a[0] - b[0]);  // sort by start

// Sort by multiple keys
Arrays.sort(intervals, (a, b) -> {
    if (a[0] != b[0]) return a[0] - b[0];   // primary: start
    return a[1] - b[1];                       // secondary: end
});
```

**Comparator rules:** return negative if a < b, zero if equal, positive if a > b. Use `Integer.compare(a, b)` instead of `a - b` to avoid overflow.

### Collections.sort (lists)

```java
List<Integer> list = new ArrayList<>(Arrays.asList(3, 1, 4));
Collections.sort(list);                      // ascending
Collections.sort(list, Collections.reverseOrder()); // descending
```

### TreeMap / TreeSet (sorted map/set)

```java
TreeMap<Integer, String> tm = new TreeMap<>();
tm.put(3, "c"); tm.put(1, "a"); tm.put(2, "b");
System.out.println(tm);   // {1=a, 2=b, 3=c} — sorted by key

TreeSet<Integer> ts = new TreeSet<>();
ts.add(30); ts.add(10); ts.add(20);
System.out.println(ts);   // [10, 20, 30] — sorted
System.out.println(ts.ceiling(15)); // 20 (smallest >= 15)
System.out.println(ts.floor(15));   // 10 (largest <= 15)
```

- O(log n) per operation. Use when you need ordering, range queries (`floor`, `ceiling`, `lower`, `higher`), or sorted iteration.
- `HashMap`/`HashSet` are faster (O(1)) when order doesn't matter.

## The Intervals Pattern

**The core idea:** an interval is a range [start, end]. Many problems ask you to merge overlapping ranges, count overlaps, or find gaps. Sort intervals by start time, then process left to right with a running "current" interval.

**Merge Intervals algorithm:**
1. Sort intervals by start.
2. Initialize `current = intervals[0]`.
3. For each next interval: if it overlaps with `current` (next.start ≤ current.end), merge (current.end = max(current.end, next.end)). Else, add `current` to result and set `current = next`.
4. Add the last `current`.

**Recognition checklist — think "Sorting & Intervals" when:**
- The problem gives ranges [start, end] and asks to merge/count/find gaps.
- "Merge overlapping intervals" / "insert interval" / "meeting rooms" / "minimum number of rooms."
- "Find the number of overlapping intervals at any point."
- "Sort then process" — any problem where sorting unlocks a greedy one-pass solution.

## Worked Example: Merge Intervals

**Problem:** Given a list of intervals, merge all overlapping ones.

### Brute force (O(n²))

For each interval, check all others for overlap, merge, repeat until no changes.

### Optimized (O(n log n)) — sort + merge

```java
class Solution {
    public int[][] merge(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> a[0] - b[0]); // sort by start

        List<int[]> result = new ArrayList<>();
        int[] current = intervals[0];

        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] <= current[1]) {
                // overlap → merge
                current[1] = Math.max(current[1], intervals[i][1]);
            } else {
                // no overlap → save current, start new
                result.add(current);
                current = intervals[i];
            }
        }
        result.add(current); // don't forget the last one

        return result.toArray(new int[result.size()][]);
    }
}
```

**Line-by-line:**
- Sort by start time — this is what makes a single pass possible.
- `current` tracks the interval being built.
- `intervals[i][0] <= current[1]` — overlap check (next start ≤ current end).
- On overlap: extend `current.end` to the max.
- On no overlap: save `current`, start a new one.
- Add the last `current` after the loop (easy to forget).

## Common Mistakes

- **Forgetting to sort.** Without sorting by start, the merge logic breaks.
- **Not adding the last interval.** The loop saves intervals on "no overlap," but the last `current` is never saved inside the loop.
- **Comparator overflow.** `a[0] - b[0]` can overflow for large values. Use `Integer.compare(a[0], b[0])`.
- **Modifying the input** — if the problem says "don't modify," copy first.
- **Merge condition:** overlap is `next.start <= current.end` (inclusive). If intervals are [1,2] and [3,4], they don't overlap (2 < 3). If [1,3] and [3,5], they overlap (3 <= 3).

## How to Explain (interview)

**Opening:** Sorting & Intervals covers two things: sorting techniques (Arrays.sort, Comparator, TreeMap/TreeSet) and the intervals pattern (merge overlapping ranges). The intervals pattern: sort intervals by start, then walk left to right merging any that overlap (next.start ≤ current.end). O(n log n) time due to sorting, O(n) space for the result. TreeMap/TreeSet give sorted order with O(log n) operations when you need range queries.

**The basic flow (merge intervals):**
```java
Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
List<int[]> result = new ArrayList<>();
int[] current = intervals[0];
for (int i = 1; i < intervals.length; i++) {
    if (intervals[i][0] <= current[1]) current[1] = Math.max(current[1], intervals[i][1]);
    else { result.add(current); current = intervals[i]; }
}
result.add(current);
```

**The part that trips everyone up:** forgetting to add the last `current` interval after the loop. Also, the overlap condition is `<=` (touching intervals merge), and sorting by start is essential.

**The mistakes to remember:**
- Forgetting to sort by start
- Not adding the last interval
- Comparator overflow (use `Integer.compare`)
- Overlap condition: `next.start <= current.end` (inclusive)
