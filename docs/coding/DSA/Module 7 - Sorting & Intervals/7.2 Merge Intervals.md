**Problem:** Given a collection of intervals, merge all overlapping intervals. (LeetCode #56)

**Link:** https://leetcode.com/problems/merge-intervals/

---

## Which Technique, and Why?

Intervals given as [start, end] + "merge overlapping" → **Sort by start + linear merge**. Sort by start time, then walk left to right merging any interval that overlaps with the current one. O(n log n) due to sorting.

**Signal in the problem:** "merge overlapping intervals" / "intervals" + "overlap" → sort by start, then merge.

## Approach

Sort intervals by start. Initialize `current = intervals[0]`. For each next interval: if it overlaps (`next.start <= current.end`), merge (extend `current.end` to max). Else, save `current` and start a new one. Don't forget the last `current`.

## Pseudocode

```
sort intervals by start
result = []
current = intervals[0]
for i from 1 to n-1:
    if intervals[i][0] <= current[1]:
        current[1] = max(current[1], intervals[i][1])
    else:
        result.add(current)
        current = intervals[i]
result.add(current)
return result
```

## Java Code

```java
class Solution {
    public int[][] merge(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));

        List<int[]> result = new ArrayList<>();
        int[] current = intervals[0];

        for (int i = 1; i < intervals.length; i++) {
            if (intervals[i][0] <= current[1]) {
                current[1] = Math.max(current[1], intervals[i][1]);
            } else {
                result.add(current);
                current = intervals[i];
            }
        }
        result.add(current);

        return result.toArray(new int[result.size()][]);
    }
}
```

## Line-by-line

- `Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]))` — sort by start time (overflow-safe comparator).
- `current` tracks the interval being built.
- `intervals[i][0] <= current[1]` — overlap check (next start ≤ current end). Inclusive: touching intervals merge.
- On overlap: extend `current[1]` to the max of both ends.
- On no overlap: save `current`, start a new one.
- `result.add(current)` after the loop — the last interval is never saved inside the loop.

## Complexity

- Time: O(n log n) — sorting dominates; merge is O(n).
- Space: O(n) — result list (O(1) extra if you don't count output).

## Common Mistakes

- **Forgetting to sort.** Without sorting by start, the merge logic breaks.
- **Not adding the last interval.** The loop saves on "no overlap," but the final `current` is never saved inside the loop.
- **Comparator overflow.** `a[0] - b[0]` can overflow. Use `Integer.compare(a[0], b[0])`.
- **Overlap condition:** `next.start <= current.end` (inclusive). [1,2] and [3,4] don't overlap (2 < 3). [1,3] and [3,5] overlap (3 ≤ 3).
- **Empty input.** If `intervals` is empty, `intervals[0]` throws. Check `intervals.length == 0` first.
