**Tier 2 problem.** (LeetCode #179)

**Problem:** Given a list of non-negative integers, arrange them to form the largest number (as a string). (LeetCode #179)

**Link:** https://leetcode.com/problems/largest-number/

---

## Which Technique, and Why?

"Arrange numbers to form the largest number" → **Custom Comparator sorting**. Sort the numbers as strings, but compare them by concatenation order: `a + b` vs `b + a`. If `a + b > b + a` (as strings), `a` comes first. O(n log n) time, O(n) space.

**Signal in the problem:** "largest number" / "arrange to form largest" → sort with custom comparator (compare by concatenation).

## Approach

Convert each number to a string. Sort with a custom comparator: `a + b` vs `b + a`. If `a + b` is greater (lexicographically as strings, since same length comparison works for numeric strings of different lengths... actually string comparison works because "9" > "89" lexicographically? No — "9" vs "89": '9' > '8', so "9" > "89". Correct. "90" vs "9": '9' == '9', then '0' vs (end) — shorter string is smaller, so "9" > "90". Correct. So string comparison works.)

After sorting, concatenate. Edge case: if the result starts with "0" (all zeros), return "0".

## Pseudocode

```
strs = convert nums to strings
sort strs with comparator: (a, b) -> (b + a).compareTo(a + b)
result = join(strs)
if result starts with "0": return "0"
return result
```

## Java Code

```java
class Solution {
    public String largestNumber(int[] nums) {
        String[] strs = new String[nums.length];
        for (int i = 0; i < nums.length; i++) strs[i] = String.valueOf(nums[i]);

        Arrays.sort(strs, (a, b) -> (b + a).compareTo(a + b));

        if (strs[0].equals("0")) return "0";  // all zeros

        StringBuilder sb = new StringBuilder();
        for (String s : strs) sb.append(s);
        return sb.toString();
    }
}
```

## Line-by-line

- Convert each int to String.
- Sort with comparator `(a, b) -> (b + a).compareTo(a + b)`: if `b + a` > `a + b`, then `b` comes first (descending order of concatenation).
- If the largest (first) is "0", all are zero → return "0".
- Join all strings.

## Complexity

- Time: O(n log n × k) where k = max string length (comparison is O(k)).
- Space: O(n × k) — for the string array.

## Common Mistakes

- **Sorting numerically.** `9` < `10` numerically, but `9` should come before `10` in the result ("910" > "109"). Sort by concatenation, not value.
- **Comparator overflow.** Using `a - b` or `Integer.compare` on the original numbers doesn't work. Must compare concatenated strings.
- **Not handling all zeros.** If all inputs are 0, the result would be "000..." → return "0".
- **Using `compareTo` on the original numbers.** `Integer.compareTo` compares numerically, not by concatenation.

**Opening:** Largest Number arranges integers to form the largest number. Sort as strings with a custom comparator: compare `a+b` vs `b+a` (concatenation). If `b+a` is larger, `b` comes first. O(n log n) time. Handle the all-zeros edge case (return "0").

**The basic flow:**
```java
String[] strs = convert(nums);
Arrays.sort(strs, (a, b) -> (b + a).compareTo(a + b));

return String.join("", strs);
```

**The part that trips everyone up:** the comparator compares **concatenated strings** (`a+b` vs `b+a`), not the numbers themselves. "9" should come before "10" because "910" > "109". String comparison works because same-length concatenations compare correctly.

**The mistakes to remember:**
- Sorting numerically instead of by concatenation
- Not handling all-zeros (returns "000...")
- Using Integer.compare instead of string comparison
- Comparator: `(b + a).compareTo(a + b)` for descending
