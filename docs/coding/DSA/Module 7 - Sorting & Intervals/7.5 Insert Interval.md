# 7.5 Insert Interval

**Tier 2 problem.** (LeetCode #57)

**Problem:** Given a set of non-overlapping intervals sorted by start, insert a new interval and merge if necessary. (LeetCode #57)

**Link:** https://leetcode.com/problems/insert-interval/

---

## Which Technique, and Why?

"Insert an interval into sorted non-overlapping intervals" → **Sort + Merge (three phases)**. Three parts: (1) intervals before the new one (end < new.start), (2) overlapping intervals (merge into one), (3) intervals after (start > new.end). O(n) time, O(n) space.

**Signal in the problem:** "insert interval" / "merge after insertion" → three-phase: before, merge, after.

## Approach

Three phases:
1. Add all intervals that end before newInterval starts.
2. Merge all overlapping intervals (new.start ≤ current.end) into one interval.
3. Add all remaining intervals.

## Pseudocode

```
result = []
i = 0
// Phase 1: before
while i < n and intervals[i][1] < newInterval[0]: result.add(intervals[i]); i++
// Phase 2: merge overlapping
while i < n and intervals[i][0] <= newInterval[1]:
    newInterval[0] = min(newInterval[0], intervals[i][0])
    newInterval[1] = max(newInterval[1], intervals[i][1])
    i++
result.add(newInterval)
// Phase 3: after
while i < n: result.add(intervals[i]); i++
return result
```

## Java Code

```java
class Solution {
    public int[][] insert(int[][] intervals, int[] newInterval) {
        List<int[]> result = new ArrayList<>();
        int i = 0, n = intervals.length;

        // Phase 1: intervals before newInterval
        while (i < n && intervals[i][1] < newInterval[0]) {
            result.add(intervals[i]);
            i++;
        }

        // Phase 2: merge overlapping
        while (i < n && intervals[i][0] <= newInterval[1]) {
            newInterval[0] = Math.min(newInterval[0], intervals[i][0]);
            newInterval[1] = Math.max(newInterval[1], intervals[i][1]);
            i++;
        }
        result.add(newInterval);

        // Phase 3: intervals after
        while (i < n) {
            result.add(intervals[i]);
            i++;
        }

        return result.toArray(new int[result.size()][]);
    }
}
```

## Line-by-line

- Phase 1: `intervals[i][1] < newInterval[0]` — interval ends before new one starts → add, move on.
- Phase 2: `intervals[i][0] <= newInterval[1]` — overlap (next start ≤ current end). Merge by extending newInterval's bounds.
- `result.add(newInterval)` — add the merged interval.
- Phase 3: add remaining intervals.

## Complexity

- Time: O(n) — single pass.
- Space: O(n) — result list.

## Common Mistakes

- **Modifying newInterval in place.** The problem usually allows it. If not, copy first.
- **Overlap condition.** `intervals[i][0] <= newInterval[1]` (inclusive). Touching intervals merge.
- **Not handling empty intervals.** If `intervals` is empty, Phase 1 and 2 skip, Phase 3 adds nothing, then `result.add(newInterval)` → correct.
- **Forgetting Phase 3.** After merging, remaining intervals must be added.

## How to Explain (interview)

**Opening:** Insert Interval inserts a new interval into sorted non-overlapping intervals. Three phases: (1) add intervals before, (2) merge overlapping into one, (3) add remaining. O(n) time, O(n) space.

**The basic flow:**
```java
// Phase 1: before
while (i < n && intervals[i][1] < newInterval[0]) result.add(intervals[i++]);
// Phase 2: merge
while (i < n && intervals[i][0] <= newInterval[1]) { merge; i++; }
result.add(newInterval);
// Phase 3: after
while (i < n) result.add(intervals[i++]);
```

**The part that trips everyone up:** the merge condition is `intervals[i][0] <= newInterval[1]` (inclusive — touching intervals merge). Also, don't forget to add the last merged interval and the remaining intervals.

**The mistakes to remember:**
- Overlap condition: `<=` (inclusive), not `<`
- Forgetting Phase 3 (remaining intervals)
- Not adding the merged interval after Phase 2
- Modifying newInterval when the problem says don't
