## Mini Quiz

1. What is the overlap condition for two intervals [a, b] and [c, d]?
2. Why must you sort intervals by start time before merging?
3. What is the time complexity of Merge Sort, and what is its space complexity?
4. Why use `Integer.compare(a, b)` instead of `a - b` in a Comparator?
5. What is the difference between stable and unstable sorting?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. Two intervals overlap if `c <= b` (next start ≤ current end). They don't overlap if `c > b`. Touching intervals (c == b) are considered overlapping (merge them).
2. Sorting by start time ensures that when you process intervals left to right, any overlapping interval will be adjacent or already merged into the current one. Without sorting, an interval could overlap with a later one that hasn't been processed yet, breaking the single-pass merge logic.
3. Time: O(n log n) — log n levels of recursion, each level does O(n) work in merge. Space: O(n) — the temp array for merging (plus O(log n) recursion stack).
4. `a - b` can overflow for large integers (e.g., a = Integer.MAX_VALUE, b = -1 → overflow). `Integer.compare(a, b)` returns -1, 0, or 1 without arithmetic, avoiding overflow.
5. Stable sort preserves the relative order of equal elements. Unstable sort may reorder them. Merge Sort is stable (use `<=` in comparison). Quick Sort is typically unstable. Stability matters when sorting objects by a secondary key.

</details>

## One-Page Cheat Sheet

**Merge Intervals:**
```java
Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
int[] current = intervals[0];
for (int i = 1; i < intervals.length; i++) {
    if (intervals[i][0] <= current[1]) current[1] = Math.max(current[1], intervals[i][1]);
    else { result.add(current); current = intervals[i]; }
}
result.add(current);  // don't forget!
```

**Merge Sort:**
```java
void mergeSort(int[] arr, int l, int r) {
    if (l >= r) return;
    int mid = l + (r - l) / 2;
    mergeSort(arr, l, mid);
    mergeSort(arr, mid + 1, r);
    merge(arr, l, mid, r);
}
```

**Comparator patterns:**
- Ascending: `(a, b) -> Integer.compare(a, b)` or `a - b` (risky)
- Descending: `(a, b) -> Integer.compare(b, a)` or `b - a`
- By field: `(a, b) -> Integer.compare(a[0], b[0])`
- Multi-key: compare primary first, then secondary

**TreeMap/TreeSet:** O(log n) insert/search/delete, sorted order, range queries (`floor`, `ceiling`, `lower`, `higher`).

**Complexities:** Sort O(n log n), Merge O(n). Intervals: O(n log n) time, O(n) space.

## In Your Own Words

1. Why does sorting by start time make interval merging a single pass?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Sorting by start time ensures that when you process intervals left to right, any interval that could overlap with the current one has already been seen or is the next one. If the next interval's start ≤ current's end, they overlap (merge). If next.start > current.end, no overlap (save current, start new). Without sorting, an interval could overlap with one that appears later, breaking this logic. Sorting makes the problem greedy: process in order, merge as you go.

</details>

2. What is the difference between `a - b` and `Integer.compare(a, b)` in a Comparator?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `a - b` computes the difference, which can overflow for large integers (e.g., Integer.MAX_VALUE - (-1) overflows to negative). `Integer.compare(a, b)` returns -1, 0, or 1 without arithmetic, avoiding overflow. Always use `Integer.compare` for safety. The same applies to `Long.compare`, `Double.compare`, etc.

</details>

3. When should you use TreeMap instead of HashMap?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use TreeMap when you need sorted keys or range queries (floor, ceiling, lower, higher). TreeMap is O(log n) per operation (red-black tree). Use HashMap when you only need O(1) lookup and don't care about order — it's faster (O(1) average). In DSA, HashMap is the default; TreeMap is for when ordering matters (e.g., "find the largest key ≤ X").

</details>
