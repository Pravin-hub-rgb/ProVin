Socho tumhare paas ek line me 10 books rakhi hain. Tumhe ek particular book dhundo hai — kaunsi? "Jo book dono taraf se barabar hai" wali. Ab tum kya karoge?

Do tareeke hain. Tareeka 1: book 1 lo, compare karo book 10 se, phir book 2 lo, compare karo book 9 se... matlab har book ko baari-baari dono end wali se compare karo. Tareeka 2: pehle book 1 aur book 10 ko compare karo, phir book 2 aur book 9 ko... ek hi baar me dono taraf se chalo.

Dekha kya hua? Tareeka 1 me ek loop me 10 kaam hue, tareeka 2 me **do jagah se ek saath** chal kar aadhe kaam me hi kaam ho gaya. Yeh doosra tareeka hi hai **Two Pointers** ka concept.

Pichle topic me humne Arrays ki Template 2 me yeh chhupke se use kiya tha — `left` aur `right` — aur maine bola tha "yeh interview me bahut aata hai". Ab uska poora lecture hai. Aaj hum samjhenge ki yeh `left`/`right` wala chakkar actually hai kya, kahan kaam karta hai, kahan nahi, aur yeh brute force se fast kyun hota hai.

## Pehle: "Pointer" hota kya hai? (Bilkul basics)

Jab main "pointer" bolta hoon, ghabrao mat. Yeh C/C++ wala pointer nahi hai jo memory address pakadta hai. Yahan pointer ka matlab sirf ek **number variable** hai jisme ek **index** rakha hai.

```js
let left = 0;      // pointer — shuru me index 0 pe
let right = 5;     // pointer — index 5 pe
```

Bas. Itna hi. `left` ek variable hai jisme `0` hai, `right` me `5` hai. Tumhe array me ghumna hai, to tum in numbers ko badalte ho:

```js
left++;    // left ab 1 ho gaya — matlab ab index 1 pe ho
right--;   // right ab 4 ho gaya — matlab ab index 4 pe ho
```

Pointer ko aise socho: **tumhari ungli**. Ungli kisi index pe rakho, dekho wahan kya value hai, phir ungli aage/peeche karo. Two Pointers ka matlab — **do ungliyan ek saath**, dono taraf se (ya dono ek hi taraf, alag speed se — yeh baad me).

Array me value dekhna toh index se hota hai:

```js
let arr = [10, 20, 30, 40, 50];
let left = 0;
let right = arr.length - 1;   // 4

console.log(arr[left]);   // 10 — left wali ungli index 0 pe
console.log(arr[right]);  // 50 — right wali ungli index 4 pe
```

Koi magic nahi, koi naya syntax nahi. Bas **do variables jo indices rakhte hain**. Yeh baat dil pe lagao — baaki sab toh inhi do variables se nikalta hai.

## Two Pointers Kya Hain?

> **Two Pointers ek pattern hai jisme do indices (left aur right) ek saath array pe chalti hain, taaki ek hi loop me do jagah ka kaam ho jaye — bina do nested loops ke.**

Jab tum bina pointers ke solve karte ho, tum aksar **nested loop** likhte ho — har element ke liye baaki saare elements check karte ho. Woh O(n²) hota hai. Two pointers usko O(n) bana deta hai, kyunki har element ko zyada se zyada ek baar hi touch hota hai.

Isse aise samjho — ek restaurant me 10 customers hain aur 1 waiter. Waiter har table ke paas jaa kar puchta hai "kya chahiye?" — 10 baar jaana padega (brute force). Ab maan lo **2 waiters** hain — ek table 1 se, ek table 10 se shuru kare, dono beech me milenge — 5 baar me kaam ho gaya. Two pointers = do waiters, aadha time, aadha kaam.

> **Asli fayda:** 2 nested loops (O(n²)) → 1 loop (O(n)). Yeh bada difference hai — 1.1 me dekha tha na ki n = 10000 pe O(n²) ka matlab 100 million kaam? Exactly wahi bachta hai.

## Kaise kaam karta hai — Pehla Example: Reverse an Array

Sabse simple example se shuru karte hain — **array ko ulta karna**.

Input: `[1, 2, 3, 4, 5]`
Output: `[5, 4, 3, 2, 1]`

### Brute Force Tareeka (Extra Array Ke Saath)

Pehle woh tareeka jo dimaag me sabse pehle aata hai — naya array banao, pichhe se bharo:

```js
function reverseBrute(arr) {
  let result = [];                // nayi khali array

  for (let i = arr.length - 1; i >= 0; i--) {
    result.push(arr[i]);          // pichhe se value utha kar daalo
  }

  return result;
}

console.log(reverseBrute([1, 2, 3, 4, 5]));  // [5, 4, 3, 2, 1]
```

Yeh kaam kar leta hai, lekin ek problem hai — **nayi array banayi** matlab extra memory (1.2 yaad hai? Space Complexity O(n) lagi). Aur jab interview me bolenge "in-place karo" (matlab original array ko hi ulta karo, nayi mat banao), toh yeh fail ho jayega.

### Two Pointers Tareeka (In-Place)

Ab wahi kaam do ungliyon se:

```js
function reverseTwoPointers(arr) {
  let left = 0;                    // ungli 1 — shuru me
  let right = arr.length - 1;      // ungli 2 — aakhri me

  while (left < right) {           // jab tak ungliyan mil nahi jaati
    // Swap — dono ungliyon wali values badal do
    let temp = arr[left];
    arr[left] = arr[right];
    arr[right] = temp;

    left++;                        // left ungli aage badhao
    right--;                       // right ungli peeche laao
  }

  return arr;
}

console.log(reverseTwoPointers([1, 2, 3, 4, 5]));  // [5, 4, 3, 2, 1]
```

**Har line samjho:**

1. `left = 0` aur `right = arr.length - 1` — dono ungliyan array ke dono end pe.
2. `while (left < right)` — jab tak ungliyan cross nahi ho jaati, loop chalta rahega. `left < right` isliye, kyunki `left === right` pe wohi element hai — swap karke koi fayda nahi.
3. Swap — teen line ka classic pattern: ek temporary variable me value rakho, doosri daalo, phir pehli me. (Yaad ho toh 1.3 me Template 3 tha — `[a, b] = [b, a]` bhi use kar sakte ho.)
4. `left++`, `right--` — dono ungliyan ek-ek kadam aage/peeche.

**Chalta hua dekho:**

```
[1, 2, 3, 4, 5]   left=0, right=4 → swap 1 aur 5
[5, 2, 3, 4, 1]   left=1, right=3 → swap 2 aur 4
[5, 4, 3, 2, 1]   left=2, right=2 → left < right FALSE → ruk jao ✅
```

Sirf **3 swap** me ho gaya — aadhe array ke iterations me.

**Complexity:** Time O(n) — har element ek baar touch hua. Space O(1) — sirf `temp` variable, koi nayi array nahi. In-place = best case scenario.

## Doosra Example: Valid Palindrome

Ab ek string wala problem — **check karo ki string aage se aur pichhe se same padhi jaaye**.

Input: `"racecar"` → output `true`
Input: `"hello"` → output `false` (ulta = `"olleh"`, same nahi)

### Socho — bina code ke, dimaag me

Palindrome check karne ka tareeka: pehla character compare karo aakhri se, doosra doosre-aakhri se... jahan bhi mismatch → false. Kya yaad dila raha hai? **Dono taraf se chalo** — exactly wahi Two Pointers ka scene.

### Code

```js
function isPalindrome(s) {
  let left = 0;
  let right = s.length - 1;

  while (left < right) {
    if (s[left] !== s[right]) {
      return false;               // ek bhi mismatch = palindrome nahi
    }
    left++;
    right--;
  }

  return true;                    // saare match = palindrome hai
}

console.log(isPalindrome("racecar"));  // true
console.log(isPalindrome("hello"));    // false
console.log(isPalindrome("a"));        // true — single char hamesha palindrome
```

**Kyun `left < right` loop me?** Socho `"aa"` — left=0, right=1, compare kiya, dono barabar, left=1, right=0 ho jayega, loop khatam. Saaf. Aur agar `left <= right` use karte, toh middle element khud se compare hota (faltu kaam) — `a` se `a` match karega hi, isliye `left < right` kaafi hai.

**Complexity:** Time O(n), Space O(1). Koi extra array nahi, koi `.reverse()` nahi.

> **Note:** Asli LeetCode wale "Valid Palindrome" me spaces aur punctuation ignore karni hoti hai (`"A man, a plan, a canal: Panama"`). Wahan tum char ko pehle clean karte ho ya check karte ho. Abhi ke liye simple version theek hai — concept wahi hai.

## Teesra Example: Two Sum (Sorted Array)

Yeh sabse famous interview problem hai. Dhyan se suno.

**Problem:** Ek **sorted** array do, aur ek target number. Do aise elements dhundo jinka sum target ke barabar ho. Unke indices return karo.

```
Input:  arr = [2, 7, 11, 15], target = 9
Output: [0, 1]   (kyunki 2 + 7 = 9)
```

Sorted matlab array chhote se bade me sorted hai — `[2, 7, 11, 15]`. Yeh wala clue bahut important hai, ek minute me dikh jaayega kyun.

### Brute Force — Nested Loop (O(n²))

Har element ke liye, baaki sab check karo:

```js
function twoSumBrute(arr, target) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[i] + arr[j] === target) {
        return [i, j];
      }
    }
  }
  return [-1, -1];   // mila nahi
}
```

Kya galat hai? Nested loop = O(n²). `[2, 7, 11, 15]` jaisi chhoti array pe koi fark nahi dikhta, but 10000 elements pe 100 million checks. Interviewer yahi catch karta hai — "kya tum isse fast kar sakte ho?"

### Two Pointers Tareeka — O(n)

Sorted array ka fayda uthao. Do ungliyan — ek shuru me, ek end me. Sum dekho:

- Sum **kam** hai target se → left ungli aage badhao (kyunki aage jaane pe value badhti hai)
- Sum **zyada** hai target se → right ungli peeche laao (kyunki peeche jaane pe value ghatti hai)
- Sum **barabar** hai → mil gaya!

```js
function twoSumSorted(arr, target) {
  let left = 0;
  let right = arr.length - 1;

  while (left < right) {
    let sum = arr[left] + arr[right];

    if (sum === target) {
      return [left, right];       // mil gaya
    } else if (sum < target) {
      left++;                     // sum badhane ke liye bade element ki taraf jaao
    } else {
      right--;                    // sum ghatane ke liye chhote element ki taraf jaao
    }
  }

  return [-1, -1];                // mila nahi
}

console.log(twoSumSorted([2, 7, 11, 15], 9));   // [0, 1]
console.log(twoSumSorted([2, 7, 11, 15], 26));  // [2, 3]
```

**Chalta hua dekho — kyun kam karta hai yeh logic:**

```
arr = [2, 7, 11, 15], target = 9

left=0, right=3 → sum = 2 + 15 = 17 → 17 > 9 → right--  (ab right=2)
left=0, right=2 → sum = 2 + 11 = 13 → 13 > 9 → right--  (ab right=1)
left=0, right=1 → sum = 2 + 7 = 9  → MATCH! ✅
```

Sirf 3 steps me mil gaya. Kyun safe hai yeh? Kyunki **array sorted hai** — left aage badhane se sum hamesha badhega, right peeche laane se hamesha ghatega. Isliye hum confidently decide kar sakte hain ki kaunsa pointer move karna hai. Ek baar left=1 pe aaye, toh 2 wala pair kabhi nahi check karenge — par woh pair already check ho chuka hai (2 ke saath jitna bhi pair possible tha, sab 17 se chhota tha... nahi, ruko, aise mat socho).

Zara detail se: jab left=0 tha, humne right ko 3 se 1 tak laaya — matlab `2+15`, `2+11`, `2+7` sab check kar liye. `2+15` 17 hai (zyada), toh `2` ko `15` se bade kisi element se pair karna impossible hai (sum aur badhega). Isliye `15` ko safely discard kiya. Yahi "ek baar check kiya, hamesha ke liye discard" wala logic O(n²) ko O(n) banata hai — har element zyada se zyada ek baar pair banata hai.

**Complexity:** Time O(n), Space O(1).

> **Important Note:** Yeh sorted wala version hai. Agar array **unsorted** hai toh Two Pointers kaam nahi karega — wahan HashMap chahiye hota hai. Woh aage `1.8 Hashing` me karenge. Abhi itna yaad rakho: **Two Pointers sorted array ka hai, unsorted ka hashing ka.**

## Chautha Example: Container With Most Water

Ab thoda real-world wala — interview me aata hai, aur Two Pointers ka asli dimaag yahan dikhta hai.

**Problem:** Ek array do, har value ek "dune" (wall) ki height hai. Do walls chuno, unke beech ka area (pani bharne ki jagah) maximum karo. Area = height (chhoti wall ki) × distance (beech ki doori).

```
Input:  height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
Output: 49   (index 1 aur 8: height 8 aur 7, distance 7 → 7 × 7 = 49)
```

**Area ka formula:** dono walls me jo **chhoti** hai, woh decide karti hai kitna pani aayega (pani chhoti wall ke upar nahi bah sakta, isliye). Aur distance = `right - left`.

### Brute Force

Har pair check karo — `(0,1), (0,2), ... (1,2), ...` — O(n²). Kaam kar jayega, par 100000 elements pe freeze.

### Two Pointers Logic — Yahan Dimag Lagana Hai

Dono end se shuru karo. Area nikaalo. Ab sawaal: **kaunsa pointer move kare?**

Socho — area = chhoti height × distance. Agar hum **chhoti wall** wale pointer ko andar le jayen, toh height badh sakti hai (nayi wall lambi ho sakti hai), aur area improve ho sakta hai. Agar hum **lambi wall** wale pointer ko andar le jayen, toh height toh kabhi nahi badhegi (chhoti wall hi height decide karti hai) — aur distance ghat jayega. Matlab area hamesha ghatega ya barabar rahega, kabhi nahi badhega.

Isliye rule: **jab bhi move karna ho, chhoti wall wala pointer move karo.**

```js
function maxArea(height) {
  let left = 0;
  let right = height.length - 1;
  let max = 0;

  while (left < right) {
    let width = right - left;                    // beech ki doori
    let currentHeight = Math.min(height[left], height[right]);  // chhoti wall
    let area = width * currentHeight;            // area nikaalo

    max = Math.max(max, area);                   // ab tak ka sabse bada area?

    if (height[left] < height[right]) {
      left++;      // chhoti wall left pe hai → left ko andar laao
    } else {
      right--;     // chhoti wall right pe hai (ya barabar) → right ko andar laao
    }
  }

  return max;
}

console.log(maxArea([1, 8, 6, 2, 5, 4, 8, 3, 7]));  // 49
```

**Har line samjho:**

- `width = right - left` — ungliyon ke beech ka fark hi doori hai.
- `Math.min(...)` — chhoti wall height pakdo. Yehi "bottleneck" hai — bottle ka pani uski sabse chhoti taraf se nikalta hai, wahi decide karta hai.
- `max = Math.max(max, area)` — ab tak ka best record update karo.
- Move rule — chhoti wali taraf se andar jaao.

**Complexity:** Time O(n), Space O(1).

> Isko "greedy" bhi kehte hain — har step pe locally best move chunte ho (chhoti wall ko discard karna), aur end me global best mil jata hai. Greedy ka full concept aage aayega, abhi bas yeh samjho ki "chhoti wall ko hamesha discard karna safe hai" kyunki uske saath koi aur pair area kabhi improve nahi kar sakta (height wahi rahegi, distance ghat jayega).

## Same-Side Pointers (Fast/Slow) — Ek Jhapak

Ab tak humne **dono taraf se** wale pointers dekhe. Ek aur variant hai — **dono pointers ek hi side se**, lekin alag speed se. Ek ko `slow` bolo, doosre ko `fast`.

Kahan use hota hai? Arrays me nahi, mostly **Linked List** me (cycle detect karna, middle nikaalna). Woh Phase 2 ka topic hai. Lekin arrays me bhi ek simple use case hai — **Remove Duplicates from Sorted Array**:

```js
function removeDuplicates(arr) {
  let slow = 0;   // nayi unique values ka position

  for (let fast = 1; fast < arr.length; fast++) {
    if (arr[fast] !== arr[slow]) {
      slow++;
      arr[slow] = arr[fast];   // unique value ko aage laao
    }
  }

  return slow + 1;   // kitne unique elements hain
}

console.log(removeDuplicates([1, 1, 2, 3, 3, 4]));  // 4
```

Iska idea: `fast` har element pe jaata hai, `slow` sirf tab aage badhta hai jab koi nayi (unique) value milti hai. Yeh bhi O(n) me ho jata hai bina extra array ke.

Abhi ke liye itna jaanna kaafi hai — **"do pointers, ek hi direction, alag speed"**. Poore detail me Phase 2 me karenge jab Linked List aayegi.

## Two Pointers Kab Use Karein? (Pattern Recognition)

Yeh sabse important section hai. Problem dekh ke kaise pehchanein ki yahan Two Pointers lagega?

**Signals (inme se koi ek ya zyada mile toh try karo):**

1. **Array sorted hai** — sabse bada signal. Sorted + "do elements dhundo" = Two Pointers.
2. **"Pair" ki baat ho rahi hai** — two sum, two numbers, two walls... jab do cheezein choose karni ho.
3. **Symmetric comparison** — palindrome, reverse, "aage se aur pichhe se same hai kya".
4. **In-place chahiye** — "nayi array nahi bana sakte" bola jaye toh Two Pointers ka time hai.
5. **Ek hi pass me dono end ka kaam** — shuru aur end dono se kaam ho raha hai.

**Jahan NAHI lagega:**

1. **Unsorted array + pair dhundo** — Two Sum unsorted pe Two Pointers fail (sorted hone pe hi logic chalta hai).
2. **Subarray/Substring ki baat** (continuous segment) — woh Sliding Window ka scene hai, agla topic.
3. **Triplets se zyada combinations** — 3Sum me bhi chal jata hai (ek fix karo, baaki Two Pointers), lekin 4+ se complex ho jata hai.

**Ek general rule yaad rakho:** Jab bhi nested loop me lag rahe ho `for (let i...) { for (let j...) }` aur dono loops same array pe hain — ruko, socho, kya yeh Two Pointers se ho sakta hai? Har baar nahi hoga, par 10 me 6 baar hoga.

## Code Template — Yaad Rakhne Wala

Yeh base template hai — isko blank bharo jaisi problem hai:

```js
function twoPointersTemplate(arr) {
  let left = 0;                    // shuru
  let right = arr.length - 1;      // end

  while (left < right) {
    // Yahan kaam karo — compare, swap, ya condition check

    if (/* kuch condition */) {
      left++;
    } else {
      right--;
    }
  }

  return result;
}
```

Teeno examples isi template ki variations hain:
- **Reverse:** swap karo, dono move karo (`left++` aur `right--` dono).
- **Palindrome:** compare karo, mismatch pe return false.
- **Two Sum sorted:** sum compare karo, condition pe ek side move karo.
- **Container:** area nikaalo, chhoti wall wali side move karo.

Pattern same hai — bas har problem me "move kis side karna hai" ka decision alag hota hai. **Yahi decision Two Pointers ka asli dimaag hai.**

## What It Is NOT

- ❌ **Two Pointers = nested loop ki replacement har jagah.** Nahin. Sirf tab jab sorted/symmetric ho ya pointers move karne ka logic ho. Kabhi kabhi nested loop hi sahi solution hota hai (brute force se compare karne ke liye).
- ❌ **Pointer = koi naya data type.** Nahin — bas ek normal number variable jisme index hai.
- ❌ **Hamesha O(n) guarantee.** Two pointers se bhi O(n) hi milta hai — O(log n) nahi, O(1) nahi. Fayda yeh hai ki O(n²) se O(n) hota hai.
- ❌ **Unsorted pe bhi chalega.** Sorted wala logic (sum decide karke move karna) unsorted pe kaam nahi karta — wahan HashMap chahiye (1.8 me).
- ❌ **Sirf arrays ke liye hai.** Strings pe bhi chalta hai (Palindrome dekha), Linked Lists pe bhi (Phase 2), aur kuch advanced jagah.

## Agla Topic — Solved Problems, Phir Sliding Window

Yahan ek cheez notice kari? Two Pointers me dono ungliyan **different ends** se aati hain. Lekin kuch problems me dono ungliyan **ek hi side se** shuru hoti hain aur saath-saath chalti hain — ek fixed "window" banate hue. Jaise "array me 3 consecutive elements ka max sum dhundo" — yahan `left` aur `right` dono 0 se shuru honge, saath-saath aage badhenge, hamesha 3 ka gap rakhte hue. Yeh hai **Sliding Window** — Two Pointers ka hi bhai, agle topic me isko kholenge.

Par pehle — 1.4.1 aur 1.4.2 me yeh patterns **asli problems pe** lagayenge: Move Zeroes (fast/slow wala variant jo removeDuplicates me dekha tha) aur Reverse an Array (left/right swap wala). Pattern library tabhi banti hai jab pattern ko problems pe khud lagao — isliye solved problems ka series Two Pointers ke turant baad rakha hai. Wahan milte hain.

<details>
<summary>Show Answer</summary>

**Sample Answer:** Area = chhoti height × distance. Agar hum lambi wall wale pointer ko andar le jayen, toh chhoti height wahi rahegi (kyunki pani chhoti wall se upar nahi ja sakta) — matlab height badal nahi sakti, aur distance toh ghatega hi. Toh area hamesha ghat jayega, improve hone ka koi chance nahi. Isliye woh lambi wall wale pointer ko move karna pointless hai. Chhoti wall wale pointer ko andar le jao toh nayi wall lambi ho sakti hai — height badhne ka chance hai, isliye sirf wahi move improve kar sakta hai. Har step pe chhoti wall ko discard karna safe hai kyunki uske saath koi bhi pair area improve nahi kar sakta.
