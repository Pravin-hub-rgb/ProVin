Think of a dinner table with 8 friends — everyone has to shift one seat forward: the person at seat 7 moves to seat 0, the person at seat 0 moves to seat 1... the whole table rotates, no one leaves the order, everyone just changes position. That's **rotation**.

In 1.3 Arrays you saw the swap pattern — two fingers from both ends, `[a, b] = [b, a]` (Template 3). Reverse is built from that: swap first-last, then move inward. Today we use that same reverse **three times** to rotate an array. And the discipline from 1.3.1 (empty check first, `arr[0]` as base) will help with today's edge cases.

## Problem 2: Rotate Array by k Steps

> **Statement:** Given an array and a number `k`. **Right rotate** the array by `k` steps — meaning bring the last `k` elements to the front, push the rest back.

**Input:**
```
arr = [1, 2, 3, 4, 5, 6, 7], k = 3
```

**Output:**
```
[5, 6, 7, 1, 2, 3, 4]
```

**Constraints to remember:**
- **Right rotation** (LeetCode 189 default) — right-side elements come to the front
- **In-place** — creating a new array is not allowed
- `k` can be **larger** than the array length — `k = 8`, length `7` is a valid input
- `k = 0` or `k = arr.length` → array stays **as is**
- Empty array (`[]`) and single element (`[7]`) — nothing to do

## Approach 1: Brute Force's Worst — Without Remainder (The Worst Code)

Some people write this directly in interviews — and it's **wrong in two ways**:

```js
var rotate = function(nums, k) {
    if (k > nums.length) return;          // BUG!
    for (let i = 0; i < k; i++) {
        let last = nums.pop();            // take last element
        nums.unshift(last);               // put at front
    }
};
```

**Wrong 1: `if (k > nums.length) return;` — this is a bug.** This means "if `k` is greater than length, do nothing." So if you send `k = 8` on `[1, 2, 3, 4, 5, 6, 7]`, the function returns immediately — the array **stays as is**, never rotated! And `k = 8` isn't an invalid input — it's perfectly valid. The line's logic is just wrong.

**Wrong 2: `unshift` is O(n).** As seen in 1.3 — to insert at the front of an array, every other element has to shift one seat back. `k` times `unshift` = total **O(n·k)**. `n = 10,000`, `k = 5,000` → 50 million steps.

**Watch what happens with k = 8 (if there were no bug):**

```
[1, 2, 3, 4, 5, 6, 7]   original
1 step:   [7, 1, 2, 3, 4, 5, 6]
2 steps:  [6, 7, 1, 2, 3, 4, 5]
3 steps:  [5, 6, 7, 1, 2, 3, 4]
...
7 steps:  [1, 2, 3, 4, 5, 6, 7]   ← back to original!
8 steps:  [7, 1, 2, 3, 4, 5, 6]   ← same as k = 1 result
```

Look closely — **after 7 steps the array is back to original.** So rotating 8 times = rotating once. The remaining 7 steps are wasted work. This small thing is what modulo exploits — now understand it.

---

## Modulo (%) — How to Find the Real Steps

`a % b` means: divide `a` by `b`, and **take the remainder (leftover)**.

```
7 % 3 = 1     (3 goes into 7 two times = 6, leftover 1)
8 % 7 = 1     (7 goes into 8 one time = 7, leftover 1)
5 % 3 = 2     (3 goes into 5 one time = 3, leftover 2)
3 % 3 = 0     (divides perfectly, nothing left)
6 % 3 = 0     (divides perfectly)
```

Now connect it to rotation. As seen above — **rotate an array by its length (n) and it's back to original.** So the real work of `k` is only whatever's left after removing full cycles:

| k | Real steps (`k % 7`) | Result |
|---|---------------------|--------|
| 0 | 0 | `[1, 2, 3, 4, 5, 6, 7]` |
| 1 | 1 | `[7, 1, 2, 3, 4, 5, 6]` |
| 3 | 3 | `[5, 6, 7, 1, 2, 3, 4]` |
| 7 | 0 | `[1, 2, 3, 4, 5, 6, 7]` |
| **8** | **1** | `[7, 1, 2, 3, 4, 5, 6]` |
| 10 | 3 | `[5, 6, 7, 1, 2, 3, 4]` |

`k = 8` doesn't mean "rotate 8 times" — it means "complete one full cycle of 7 (back to original), then 1 extra step." **`8 % 7 = 1`.** `k = 10` = one cycle of 7 + 3 extra = `10 % 7 = 3` → same result as `k = 3`.

This logic in code: **first compute `k = k % arr.length` to get the real steps** — then work with that. Rotating `k` times without remainder is wasteful because your code rotates even for steps that have no effect.

## Approach 2: Brute Force + Remainder (Logic Now Correct, Still Slow)

The direct fix for Approach 1 — first find the remainder, then rotate:

```js
function rotateBrute(arr, k) {
  if (arr.length === 0) return arr;      // empty check first — 1.3.1 discipline
  k = k % arr.length;                    // real steps — 8 % 7 = 1, 10 % 7 = 3

  for (let i = 0; i < k; i++) {
    arr.unshift(arr.pop());              // take last, put at front
  }

  return arr;
}

console.log(rotateBrute([1, 2, 3, 4, 5, 6, 7], 3));  // [5, 6, 7, 1, 2, 3, 4]
console.log(rotateBrute([1, 2, 3, 4, 5, 6, 7], 8));  // [7, 1, 2, 3, 4, 5, 6] — 8 % 7 = 1 step
```

Now the answer is correct — for `k = 8`, only 1 step runs instead of 8. **But performance is still slow:** `unshift` is O(n), so with large `k` and `n` it's still **O(n·k)**. In interviews, call this "brute force + edge case fix" — then move to optimal.

## Approach 3: Three Reverses — The Real Solution (O(n) Time, O(1) Space)

First understand a small tool, then the whole trick. The tool is `reverseRange`.

### Step 1: What reverseRange Does

This function reverses **any part** of an array. `reverseRange(arr, start, end)` means: reverse the elements from index `start` to index `end`.

How? **Two fingers.** One finger at `start`, one at `end`. Swap, move both fingers inward, swap again, move inward... until they meet. Small example:

```js
let arr = [1, 2, 3, 4, 5];
reverseRange(arr, 1, 3);
console.log(arr);   // [1, 4, 3, 2, 5]
```

```
Start:    [1, 2, 3, 4, 5]     fingers: start=1 (on 2), end=3 (on 4)
Swap:     [1, 4, 3, 2, 5]     now start=2, end=2 — met, stop
```

Only indices 1 to 3 (`2, 3, 4`) got reversed → `4, 3, 2`. The rest (`1` and `5`) stayed. This is the `while (start < end)` loop — same as 1.3 Arrays Template 3 (swap pattern), except now you decide the `start`/`end`.

And to reverse the **entire array**, just call `reverseRange(arr, 0, arr.length - 1)` — 0 to last. This single function handles all three steps.

### Step 2: Remember One Rule — Reverse Twice = Original

`[1, 2, 3, 4, 5]` reversed → `[5, 4, 3, 2, 1]`. Reversed again → `[1, 2, 3, 4, 5]`.

**Reverse any part twice and it returns to original order.** This simple fact unlocks the whole trick.

### Step 3: Why Reverse Rotates

Example: `[1, 2, 3, 4, 5, 6, 7]`, `k = 3`. We want the last 3 (`5, 6, 7`) at the front: `[5, 6, 7, 1, 2, 3, 4]`.

**Step 3a — Reverse the entire array:**

```
[1, 2, 3, 4, 5, 6, 7]
→ [7, 6, 5, 4, 3, 2, 1]
```

Look what happened — the 3 elements we wanted at the front (`5, 6, 7`) are now **at the front**! Just in reverse order (`7, 6, 5`). And the remaining 4 (`1, 2, 3, 4`) are at the back, also reversed (`4, 3, 2, 1`).

**Step 3b — Reverse the first 3 elements:**

```
[7, 6, 5, 4, 3, 2, 1]
→ [5, 6, 7, 4, 3, 2, 1]
```

`7, 6, 5` reversed → `5, 6, 7`. Now the front 3 are in correct order. (Reverse twice = original — that rule.)

**Step 3c — Reverse the remaining 4 elements:**

```
[5, 6, 7, 4, 3, 2, 1]
→ [5, 6, 7, 1, 2, 3, 4]  ✅
```

Done.

**The whole logic in one line:** *First reverse everything — the last elements come to the front (in reverse order). Then reverse both parts to fix the order.* The three steps just call `reverseRange` on different ranges.

### Code

```js
function reverseRange(arr, start, end) {
  while (start < end) {
    [arr[start], arr[end]] = [arr[end], arr[start]];
    start++;
    end--;
  }
}

function rotate(arr, k) {
  if (arr.length === 0) return arr;
  k = k % arr.length;                    // real steps — 8 % 7 = 1, 10 % 7 = 3
  if (k === 0) return arr;               // k = 0 or multiple of n — nothing to do

  reverseRange(arr, 0, arr.length - 1);  // 1. reverse all — last elements come to front
  reverseRange(arr, 0, k - 1);           // 2. reverse first k — fix their order
  reverseRange(arr, k, arr.length - 1);  // 3. reverse rest — fix their order

  return arr;
}

console.log(rotate([1, 2, 3, 4, 5, 6, 7], 3));   // [5, 6, 7, 1, 2, 3, 4]
console.log(rotate([1, 2, 3, 4, 5, 6, 7], 8));   // [7, 1, 2, 3, 4, 5, 6] — 8 % 7 = 1
console.log(rotate([1, 2, 3], 10));              // [3, 1, 2] — 10 % 3 = 1
console.log(rotate([1, 2, 3], 0));               // [1, 2, 3]
console.log(rotate([1, 2, 3], 3));               // [1, 2, 3]
console.log(rotate([], 2));                      // []
```

Each call decides which part gets reversed via `start`/`end`:

- `reverseRange(arr, 0, arr.length - 1)` → entire array (0 to last)
- `reverseRange(arr, 0, k - 1)` → first `k` elements (0 to `k - 1`)
- `reverseRange(arr, k, arr.length - 1)` → remaining elements (`k` to last)

**Understand every line:**

- `if (arr.length === 0) return arr;` — empty check first, same 1.3.1 discipline.
- `k = k % arr.length;` — real steps = remainder. `8 % 7 = 1`, `10 % 7 = 3`. Without this, 8 reverses would run.
- `if (k === 0) return arr;` — when `k = 0` or `k` is a multiple of the full length (`k = 6`, `n = 3` → `6 % 3 = 0`), nothing to do. Early return saves three wasted reverses.

**Complexity:** Time **O(n)** — three passes, but each element is touched once per pass (constant 3), so O(3n) = **O(n)**. Space **O(1)** — no new array, just two pointers `start`/`end`.

Difference from brute force? Pop + unshift was O(n·k), and the new-array version was O(n) space. This fixes both — O(n) time **and** O(1) space. That's why this is the interview answer.

> **This is the power of the pattern** — the "reverse twice = original" insight isn't only for rotation. The "Reverse Words in a String" problem is built on it too: reverse the whole string, then reverse each word. One insight, many problems. That's why I say — pattern library is the real skill.

## Variations — The Interviewer Will Twist This

### Variation 1: Left Rotation

The mirror of right rotation — front elements go to the back. Just change the reverse order:

```js
function rotateLeft(arr, k) {
  if (arr.length === 0) return arr;
  k = k % arr.length;
  if (k === 0) return arr;

  reverseRange(arr, 0, k - 1);            // 1. reverse first k
  reverseRange(arr, k, arr.length - 1);   // 2. reverse the rest
  reverseRange(arr, 0, arr.length - 1);   // 3. reverse all

  return arr;
}

console.log(rotateLeft([1, 2, 3, 4, 5, 6, 7], 2));  // [3, 4, 5, 6, 7, 1, 2]
```

Right: reverse all first, then both parts. Left: reverse both parts first, then all. Or remember the shortcut — **left rotate by k = right rotate by (n - k)**. Same function, just call `rotate(arr, n - k)`.

### Variation 2: Negative k

Some interviews include negative `k` (`k = -2` = left rotate by 2). Fix with a double-wrap in modulo:

```js
function rotateAny(arr, k) {
  if (arr.length === 0) return arr;
  k = ((k % arr.length) + arr.length) % arr.length;  // turn negative into positive
  if (k === 0) return arr;
  // ...three reverses
}
```

Why double-wrap? `-2 % 3` in JavaScript gives `-2` (negative remainder). Add 3 to get 1, then `% 3` again gives 1. Worth memorizing this formula.

### Variation 3: Built-in Shortcut (Don't Use in Interviews)

JavaScript does it with `slice` + `concat`:

```js
function rotateBuiltin(arr, k) {
  if (arr.length === 0) return arr;
  k = k % arr.length;
  return arr.slice(-k).concat(arr.slice(0, arr.length - k));
}

console.log(rotateBuiltin([1, 2, 3, 4, 5, 6, 7], 3));  // [5, 6, 7, 1, 2, 3, 4]
```

Fast, but **returns a new array** — not in-place, space O(n). Works in production code; in interviews show the reverse trick.

### Variation 4: String Rotation

The question bank has "Check if String is Rotation of Another" ahead. Strings are **immutable** (covered in 1.3) — so pull characters into an array, rotate, join:

```js
function rotateString(s, k) {
  let chars = s.split("");
  rotate(chars, k);            // the same array rotation from above
  return chars.join("");
}

console.log(rotateString("hello", 2));  // "lohel"
```

`split` takes O(n) space — with immutable strings there's no option, mention this in interviews.

## What It Is NOT

- ❌ **`if (k > nums.length) return;` is not a solution — it's a bug.** When `k` is larger than length, you still have to rotate (`k = 8`, length 7 → rotate with `8 % 7 = 1` step). Returning does nothing.
- ❌ **`k` times pop + unshift is not "O(k)".** `unshift` is O(n) — every time all elements shift. Total is **O(n·k)**. Can't handle large inputs.
- ❌ **`slice` + `concat` is not in-place.** Creates a new array, space O(n). Fails if the constraint is "in-place."
- ❌ **Rotation is not sorting.** Rotation preserves order (values move around), sorting arranges by value. Totally different.
- ❌ **"Rotate k times" doesn't mean real k steps.** After modulo, only the remainder matters — `k = 8`, `n = 7` → 1 step. The other 7 are wasted.

---

## Interview Tips

1. **Show the flow:** "First the worst — pop + unshift without remainder, O(n·k) and wrong when `k > n`. Then fix with remainder — `k %= n`. Then new array — O(n) time, O(n) space. Now optimal — three reverses, O(n) time, O(1) space." This progression itself earns marks.
2. **Mention modulo early** — "Since `k` can be large, first `k %= n`" — that alone is half the work. Give an example: "8 steps = one full cycle of 7 + 1 extra."
3. **Show a dry run** — run the three reverses by hand on `[1,2,3,4,5,6,7]` with `k=3`. Confidence comes from this.
4. **Show reverseRange reuse** — "This is the generalized version of 1.3's swap pattern, just called on three ranges" — this proves you're building a pattern library.
5. **Keep left rotation ready** — interviewers ask for left right after right. Cover it with "left rotate = `rotate(arr, n - k)`."
