## Problem 1: Move Zeroes to End

> **Statement:** Given an array with some zeros. Move all **zeros to the end**, and **preserve the order of non-zero elements** (relative order). And do all this **in-place** — you can't create a new array.

**Input:**
```
arr = [0, 1, 0, 3, 12]
```

**Output:**
```
[1, 3, 12, 0, 0]
```

Notice — the order of `1, 3, 12` is the same, zeros just moved to the back. The key point: **order must be preserved.** If you sorted it, you'd get `[0, 0, 1, 3, 12]` — that's wrong, because non-zeros lost their original order.

**Constraints:**
- In-place — creating a new array to fill is not allowed
- Relative order of non-zeros must be preserved
- Think about edge cases: empty array and all-zeros (`[0, 0, 0]` → `[0, 0, 0]`, no change)

## Approach 1: Brute Force — New Array (This is Wrong)

The easiest approach — put non-zeros into a new list, then fill zeros:

```js
function moveZeroesBrute(arr) {
  let result = [];               // new array
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] !== 0) {
      result.push(arr[i]);       // first all non-zeros
    }
  }
  while (result.length < arr.length) {
    result.push(0);              // then fill remaining with zeros
  }
  return result;
}

console.log(moveZeroesBrute([0, 1, 0, 3, 12]));  // [1, 3, 12, 0, 0]
```

Time is O(n) and order is correct — so what's wrong? **Space O(n)** — a new array was created. When the interview says "do it in-place" and you bring a new array, that fails. So the in-place optimization is needed.

---

## Approach 2: Two Pointers (Same Direction) — The Real Solution

This is the fast/slow pattern from the end of 1.4. Two pointers, both starting at `0`, both moving forward — one `slow` always sits at the **next seat where a non-zero should be written**, and `fast` scans every element.

```js
function moveZeroes(arr) {
  let slow = 0;   // next non-zero value will be written here

  for (let fast = 0; fast < arr.length; fast++) {
    if (arr[fast] !== 0) {
      // non-zero found — bring it to the slow position
      [arr[slow], arr[fast]] = [arr[fast], arr[slow]];
      slow++;
    }
  }

  return arr;
}

console.log(moveZeroes([0, 1, 0, 3, 12]));  // [1, 3, 12, 0, 0]
console.log(moveZeroes([0, 0, 0]));         // [0, 0, 0]
console.log(moveZeroes([1, 2, 3]));         // [1, 2, 3] — no zeros at all
console.log(moveZeroes([]));                // []
```

**Understand every line:**

1. `let slow = 0;` — this pointer says **at which index the next non-zero value should be written in the array**. Starts at 0.
2. `for (let fast = 0; ...)` — `fast` scans the entire array, element by element.
3. `if (arr[fast] !== 0)` — only act when a non-zero is found. On finding a zero, do nothing — `slow` stays in place, `fast` moves forward.
4. Swap — exchange `arr[slow]` and `arr[fast]`. If both are at the same index (at the start), the swap has no effect — the value stays where it is, just `slow++` happens. This is safe.
5. `slow++` — advance the seat for the next non-zero.

**Watch it run — `[0, 1, 0, 3, 12]`:**

```
slow=0, fast=0 → arr[0]=0 → zero, nothing.        → [0, 1, 0, 3, 12]
slow=0, fast=1 → arr[1]=1 → non-zero! swap(0,1) → slow=1 → [1, 0, 0, 3, 12]
slow=1, fast=2 → arr[2]=0 → zero, nothing.        → [1, 0, 0, 3, 12]
slow=1, fast=3 → arr[3]=3 → non-zero! swap(1,3) → slow=2 → [1, 3, 0, 0, 12]
slow=2, fast=4 → arr[4]=12 → non-zero! swap(2,4) → slow=3 → [1, 3, 12, 0, 0] ✅
```

See what happened — `slow` always **paused at the first zero position** (or the next empty seat), and when `fast` found a non-zero, it placed it there. Zeros automatically went to the back, because they were never swapped.

**Why is order preserved?** Because `fast` scans the array left-to-right, so whichever non-zero comes first gets swapped first. `slow` also advances left-to-right. So `1` can never end up after `3` — swaps always happen left-to-right.

**Complexity:** Time O(n) — single loop. Space O(1) — no extra variable for the swap either (destructuring used), just two pointers.

> **This is the same pattern from removeDuplicates in 1.4** — `slow` as the seat for the next unique value, `fast` as scanner. Same idea, slightly different condition. That's why I say — patterns repeat, only the condition changes.

## Another Way to Swap (What You Saw in 1.3)

In 1.3 Template 3 you saw `[a, b] = [b, a]`. That's what's used above. If you want the old way (some interviewers say "show me with temp"):

```js
let temp = arr[slow];
arr[slow] = arr[fast];
arr[fast] = temp;
```

Both do the same thing. In interviews, write whichever comes to mind first — just be able to explain that a swap is happening.

## Another Approach — Overwrite + Fill (Without Swap)

Some people instead of swapping do this — first write all non-zeros **forward** (overwrite), then fill the remaining spots with zeros:

```js
function moveZeroesOverwrite(arr) {
  let writeIndex = 0;              // where to write

  for (let i = 0; i < arr.length; i++) {
    if (arr[i] !== 0) {
      arr[writeIndex] = arr[i];    // bring non-zero forward (overwrite)
      writeIndex++;
    }
  }

  while (writeIndex < arr.length) {
    arr[writeIndex] = 0;           // fill rest with zeros
    writeIndex++;
  }

  return arr;
}

console.log(moveZeroesOverwrite([0, 1, 0, 3, 12]));  // [1, 3, 12, 0, 0]
```

This is also O(n) time, O(1) space, and arguably easier to understand. The swap version looks more "elegant" in interviews, but both are correct. **Use whichever you understand** — the interviewer looks at the pattern, there's no single perfect way.

## Variations — The Interviewer Will Twist This

### Variation 1: Replace Zero with Any Element

"Move all **2s** to the end" or "move all **negatives** to the end" — just change the condition, pattern stays the same:

```js
function moveElementToEnd(arr, target) {
  let slow = 0;

  for (let fast = 0; fast < arr.length; fast++) {
    if (arr[fast] !== target) {
      [arr[slow], arr[fast]] = [arr[fast], arr[slow]];
      slow++;
    }
  }

  return arr;
}

console.log(moveElementToEnd([1, 2, 3, 2, 4, 2], 2));  // [1, 3, 4, 2, 2, 2]
```

Zero isn't special — this pattern works for **moving any element to the end**.

### Variation 2: Count the Zeros

If you know how many zeros there are, you can verify the array is correct after moving:

```js
function countZeroes(arr) {
  return arr.filter(x => x === 0).length;
}

console.log(countZeroes([0, 1, 0, 3, 12]));  // 2
```

Simple, but it shows you thought about the problem from two angles — "how many zeros" and "where to send them."

### Variation 3: Stable Partition

The advanced name for Move Zeroes is **stable partition** — splitting elements into two groups based on a condition, while preserving order. Very common in compiler design and sorting algorithms (e.g., QuickSort's partition). Saying "stable partition" in an interview shows your knowledge level:

> "This problem is basically a stable partition where the predicate is `x !== 0` — non-zeros on the left, zeros on the right, order stable."

Sounds very solid.

---

## What It Is NOT

- ❌ **Sorting is not a solution.** Sorting changes the order — `[0, 1, 0, 3, 12]` sorted gives `[0, 0, 1, 3, 12]`, but expected is `[1, 3, 12, 0, 0]`. As in 1.3.1 — sorting is a last resort when order doesn't matter.
- ❌ **`.filter()` is not in-place.** `arr.filter(x => x !== 0)` returns a new array — fails the in-place constraint. Filter's space is also O(n).
- ❌ **`splice` + push loop is wrong.** For each zero, `splice` is O(n) (elements shift), so it becomes O(n²) total. Two pointers' O(n) is much better.
- ❌ **Order preservation is not optional.** Sometimes interviews say "order doesn't matter" — then sorting works. But unless they say that, the default is that order must be preserved.

## Interview Tips

1. **When you hear "in-place," think: swap, shift, or pointers.** These are the three in-place tools. If you feel like creating a new array, stop — the interviewer blocked exactly that.
2. **Show a dry-run.** Running `[0, 1, 0, 3, 12]` through by hand with pointers shows the interviewer you understand it, not just memorized it.
3. **State edge cases:** empty array, all-zeros, no-zeros, single element. Three lines of answer, confidence doubles.
4. **Say "stable partition"** — one sentence naming the pattern shows you're building a pattern library.

1. What does the `slow` pointer actually track in Move Zeroes? Explain in your own words.

2. Why is order preservation necessary in this problem? What goes wrong if we sort?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Because the problem explicitly says "maintain relative order of non-zero elements." Sorting would turn `[0, 1, 0, 3, 12]` into `[0, 0, 1, 3, 12]` — zeros in the middle, but expected is `[1, 3, 12, 0, 0]`. Bigger case: sorting `[0, 3, 1, 0, 2]` gives `[0, 0, 1, 2, 3]` — the order of 3 and 1 flips! Sorting changes order too. That's why the pattern-based solution (swap + pointers) is used — it guarantees order.

</details>

3. Compare brute force (new array) vs two pointers on time and space. Why does brute force fail?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Brute force: time O(n) (single loop), space O(n) (new array). Two pointers: time O(n), space O(1). Time is the same for both — the difference is space. Brute force fails because the interview constraint is "in-place" — modify the original array, don't allocate new memory. O(n) extra space on large arrays costs memory. Two pointers uses only two integer variables — whether the array has 10 elements or 10 million, space is fixed. That's why in-place is always more valuable when the constraint is given.

</details>

4. Swap pattern vs overwrite + fill pattern — what's the difference? When to use which?

<details>
<summary>Show Answer</summary>

**Sample Answer:** In the swap pattern (approach 2), every non-zero found gets swapped with `arr[slow]` — preserving the original value. In overwrite, the non-zero is copied directly to `arr[writeIndex]` — the old value is lost, then zeros fill the remaining spots. Both are O(n) time, O(1) space. Swap is more "pure" because zeros also shift to their place; overwrite needs a separate fill step. In interviews, use whichever you understand — the interviewer accepts both. Swap is slightly more general because it moves any element to the end without extra fill.

</details>

5. What does "stable partition" mean, and how does Move Zeroes connect to it?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Stable partition means: split elements into two groups based on a condition — those matching go to one side, the rest to the other — while preserving the original order within each group. Move Zeroes has the condition "non-zeros go to the front, zeros to the back" and preserves order — so it's exactly a stable partition with predicate `x !== 0`. Knowing this terminology helps: when an interviewer gives a new problem that's "partition" type (like move all evens to start, odds to end), you'll immediately recognize the same two-pointer pattern applies. That's what building a pattern library means — different problem, same pattern.
