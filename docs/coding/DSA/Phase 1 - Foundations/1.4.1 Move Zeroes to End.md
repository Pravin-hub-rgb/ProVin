## Problem 1: Move Zeroes to End

> **Statement:** Ek array do jisme kuch zeros hain. Saare **zeros ko end** me le jao, aur **non-zero elements ka order waisa hi rakho** (relative order preserve). Aur yeh sab **in-place** karna hai — nayi array nahi bana sakte.

**Input:**
```
arr = [0, 1, 0, 3, 12]
```

**Output:**
```
[1, 3, 12, 0, 0]
```

Dhyan do — `1, 3, 12` ka order same hai, bas zeros peeche daal diye. Yahan dhyan dene wali baat: **order preserve** zaroori hai. Agar tum sort kar dete toh `[0, 0, 1, 3, 12]` aata — woh galat hai, kyunki non-zeros ka original order nahi rahi.

**Constraints:**
- In-place — nayi array bana ke fill karna allowed nahi
- Non-zeros ka relative order preserve karna hai
- Empty array aur all-zeros wale cases socho (`[0, 0, 0]` → `[0, 0, 0]`, kuch change nahi)

---

## Pehle Khud Socho (Code Mat Likho)

1. Agar nayi array banani allowed hoti, toh kya karte? (Yeh brute force hai — pehle isko socho, phir optimize)
2. Bina nayi array ke — tum kaise shift karoge? Loop me `splice` use karoge? Koi better?
3. "Order preserve" constraint kyun important hai? Agar sort kar dete toh kya galat hota?

Jawab sochne ke baad hi code likho — `test.js` me apna attempt, phir neeche compare.

## Approach 1: Brute Force — Nayi Array (Yehi Galat Hai)

Sabse easy tareeka — non-zeros ek nayi list me daal do, phir zeros daal do:

```js
function moveZeroesBrute(arr) {
  let result = [];               // nayi array

  for (let i = 0; i < arr.length; i++) {
    if (arr[i] !== 0) {
      result.push(arr[i]);       // pehle saare non-zeros
    }
  }

  while (result.length < arr.length) {
    result.push(0);              // phir baaki jagah zero se bharo
  }

  return result;
}

console.log(moveZeroesBrute([0, 1, 0, 3, 12]));  // [1, 3, 12, 0, 0]
```

Time O(n) hai, aur order bhi sahi hai — toh galat kya hai? **Space O(n)** — nayi array banayi. Interview me jab bola jaye "in-place karo" aur tum nayi array bana ke lao, woh fail hai. Isliye in-place wala optimize karna padta hai.

## Approach 2: Two Pointers (Same Direction) — The Real Solution

Yahi 1.4 ke end wala fast/slow pattern hai. Do pointers, dono `0` se shuru, dono aage badhte hain — bas ek `slow` hamesha **non-zero value likhne ki agli seat** pe hota hai, aur `fast` har element ko scan karta hai.

```js
function moveZeroes(arr) {
  let slow = 0;   // agli non-zero value yahan aayegi

  for (let fast = 0; fast < arr.length; fast++) {
    if (arr[fast] !== 0) {
      // non-zero mila — usse slow wali jagah pe le aao
      [arr[slow], arr[fast]] = [arr[fast], arr[slow]];
      slow++;
    }
  }

  return arr;
}

console.log(moveZeroes([0, 1, 0, 3, 12]));  // [1, 3, 12, 0, 0]
console.log(moveZeroes([0, 0, 0]));         // [0, 0, 0]
console.log(moveZeroes([1, 2, 3]));         // [1, 2, 3] — koi zero hi nahi
console.log(moveZeroes([]));                // []
```

**Har line samjho:**

1. `let slow = 0;` — yeh pointer batata hai ki **agli non-zero value array me kis index pe likhni hai**. Abhi shuru me 0.
2. `for (let fast = 0; ...)` — `fast` pura array scan karta hai, ek-ek element.
3. `if (arr[fast] !== 0)` — sirf tab kaam karo jab non-zero mile. Zero milne pe kuch mat karo — `slow` apni jagah pe rukta hai, `fast` aage badh jaata hai.
4. Swap — `arr[slow]` aur `arr[fast]` ki values badal do. Agar dono same index pe hain (shuru me), toh swap koi effect nahi karta — value apni hi jagah rahegi, bas `slow++` hoga. Yeh safe hai.
5. `slow++` — ab agli non-zero ki seat aage badha do.

**Chalta hua dekho — `[0, 1, 0, 3, 12]`:**

```
slow=0, fast=0 → arr[0]=0 → zero hai, kuch nahi.        → [0, 1, 0, 3, 12]
slow=0, fast=1 → arr[1]=1 → non-zero! swap(0,1) → slow=1 → [1, 0, 0, 3, 12]
slow=1, fast=2 → arr[2]=0 → zero hai, kuch nahi.        → [1, 0, 0, 3, 12]
slow=1, fast=3 → arr[3]=3 → non-zero! swap(1,3) → slow=2 → [1, 3, 0, 0, 12]
slow=2, fast=4 → arr[4]=12 → non-zero! swap(2,4) → slow=3 → [1, 3, 12, 0, 0] ✅
```

Dekho kya hua — `slow` hamesha **pehle zero wali jagah** pe ruka hua tha (ya agli khali seat pe), aur `fast` non-zero dhunda toh wahan daal diya. Zeros automatically peeche chale gaye, kyunki unhe kabhi swap nahi kiya gaya.

**Order kyun preserve hota hai?** Kyunki `fast` array ko left-to-right scan karta hai, toh jo non-zero pehle aata hai, woh pehle swap hota hai. `slow` bhi left-to-right badhta hai. Isliye `1` kabhi `3` se aage nahi jaa sakta — swap hamesha left-to-right hota hai.

**Complexity:** Time O(n) — ek loop. Space O(1) — swap ke liye koi extra variable bhi nahi (destructuring use kiya), bas do pointers.

> **Yehi pattern 1.4 ke removeDuplicates me tha** — `slow` nayi unique value ki seat, `fast` scanner. Wahi idea, thodi si alag condition. Isliye bolta hoon — patterns repeat hote hain, bas condition badalti hai.

## Swap Ka Naya Tareeka (Jo Tumne 1.3 Me Dekha Tha)

1.3 me Template 3 me `[a, b] = [b, a]` dekha tha na? Wahi use kiya hai upar. Agar purane tareeke se karna ho (interview me kuch log bolte hain "temp use karke dikhao"):

```js
let temp = arr[slow];
arr[slow] = arr[fast];
arr[fast] = temp;
```

Dono kaam wahi karte hain. Interview me jo pehle dimaag me aaye woh likho — bas explain kar pao ki swap ho raha hai.

## Ek Aur Tareeka — Overwrite + Fill (Bina Swap Ke)

Kuch log swap ke bajaye yeh karte hain — pehle saare non-zeros **aage likho** (overwrite), phir baaki jagah zeros **fill** karo:

```js
function moveZeroesOverwrite(arr) {
  let writeIndex = 0;              // kahan likhna hai

  for (let i = 0; i < arr.length; i++) {
    if (arr[i] !== 0) {
      arr[writeIndex] = arr[i];    // non-zero ko aage lao (overwrite)
      writeIndex++;
    }
  }

  while (writeIndex < arr.length) {
    arr[writeIndex] = 0;           // baaki jagah zero bharo
    writeIndex++;
  }

  return arr;
}

console.log(moveZeroesOverwrite([0, 1, 0, 3, 12]));  // [1, 3, 12, 0, 0]
```

Yeh bhi O(n) time, O(1) space hai, aur samajhne me shayad asaan bhi hai. Swap wala interview me zyada "elegant" dikhta hai, par dono sahi hain. **Jo samajh aaye woh do** — interviewer solution ka pattern dekhta hai, ek hi perfect way nahi hota.

## Variations — Interviewer Isko Twist Karega

### Variation 1: Zero Ki Jagah Koi Aur Element

"Move all **2s** to end" ya "move all **negatives** to end" — bas condition badlo, pattern wahi:

```js
function moveElementToEnd(arr, target) {
  let slow = 0;

  for (let fast = 0; fast < arr.length; fast++) {
    if (arr[fast] !== target) {
      [arr[slow], arr[fast]] = [arr[fast], arr[slow]];
      slow++;
    }
  }

  return arr;
}

console.log(moveElementToEnd([1, 2, 3, 2, 4, 2], 2));  // [1, 3, 4, 2, 2, 2]
```

Zero special nahi hai — yeh pattern **kisi bhi element ko end me bhejne** ke kaam aata hai.

### Variation 2: Zeroes Count Karte Jao

Agar tumhe pata ho kitne zeros hain, toh check kar sakte ho ki move ke baad array sahi hai ya nahi:

```js
function countZeroes(arr) {
  return arr.filter(x => x === 0).length;
}

console.log(countZeroes([0, 1, 0, 3, 12]));  // 2
```

Simple hai, par yeh dikhata hai ki tumne problem ko do angles se socha — "kitne zeros hain" aur "unhe kahan bhejna hai".

### Variation 3: Stable Partition

Move Zeroes ka advanced naam hai **stable partition** — ek condition ke hisaab se elements ko do groups me baatna, order preserve karte hue. Compiler design aur sorting algorithms me bahut use hota hai (e.g., QuickSort ka partition). Interview me "stable partition" bolna tumhara knowledge level dikhata hai:

> "Yeh problem basically stable partition hai jahan predicate `x !== 0` hai — non-zeros left, zeros right, order stable."

Bada solid lagta hai yeh bolna.

---

## What It Is NOT

- ❌ **Sort karna solution nahi hai.** Sort karne se order bigad jaata hai — `[0, 1, 0, 3, 12]` sort karo toh `[0, 0, 1, 3, 12]` milta hai, par expected `[1, 3, 12, 0, 0]` hai. 1.3.1 me bhi bola tha — sort last resort hai jab order matter na kare.
- ❌ **`.filter()` bhi in-place nahi hai.** `arr.filter(x => x !== 0)` nayi array return karta hai — in-place constraint fail. Filter ka space bhi O(n) hi hai.
- ❌ **`splice` + push wala loop galat hai.** Har zero ke liye `splice` O(n) khinchta hai (elements shift hote hain), isliye pura O(n²) ban jaata hai. Two pointers ka O(n) kaafi better hai.
- ❌ **Order preserve optional nahi hai.** Interview me kabhi-kabhi "order koi matter nahi karta" bhi bolte hain — tab sort chalta. Par jab tak na bole, default yeh hai ki order preserve karna hai.

## Interview Tips

1. **"In-place karo" sunte hi socho: swap, shift, ya pointers.** Yeh teen hi in-place tools hain. Nayi array banane ka mann kare toh ruko — interviewer ne wahi block kiya hai.
2. **Example dry-run dikhao.** `[0, 1, 0, 3, 12]` ko haath se pointers ke saath chala ke dikhana — isse interviewer ko confidence aata hai ki tum samajh ke likh rahe ho, ratta nahi.
3. **Edge cases bolo:** empty array, all-zeros, no-zeros, single element. Teen lines ka answer, confidence double.
4. **"Stable partition" bolo** — ek sentence me pattern ka naam bata do, interviewer ko pata chal jata hai ki tum pattern library build kar rahe ho.

2. Is problem me order preserve kyun zaroori hai? Agar hum sort kar dete toh kya galat hota?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Kyunki problem explicitly bolti hai "maintain relative order of non-zero elements". 3. Brute force (nayi array) vs two pointers — time aur space dono compare karo. Brute force fail kyun hota hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Brute force: time O(n) (ek loop), space O(n) (nayi array). Two pointers: time O(n), space O(1). Time dono ka same hai — lekin space me fark hai. Brute force fail isliye hota hai kyunki interview ka constraint "in-place" hai — matlab original array me hi modify karo, nayi memory mat lo. Bade arrays pe O(n) extra space memory kharch kar sakti hai. Two pointers sirf do integer variables use karta hai — chahe array 10 elements ka ho ya 10 million ka, space fixed hai. Isliye in-place solution hamesha zyada valuable hota hai jab constraint diya gaya ho.

</details>

4. Swap pattern vs overwrite + fill pattern — dono me kya fark hai? Kaunsa kab use karein?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Swap pattern (approach 2) me har non-zero milne pe usse `arr[slow]` ke saath swap karte hain — original value ko preserve karte hue. Overwrite pattern me non-zero ko directly `arr[writeIndex]` pe copy karte hain — purani value gayab ho jaati hai, phir end me zeros se baaki jagah bhar dete hain. Dono O(n) time, O(1) space hain. Swap zyada "pure" hai kyunki zero bhi apni jagah shift ho jaata hai, overwrite me zero ko baad me fill karna padta hai. Interview me jo samjha aaye woh karo — interviewer dono accept karta hai. Swap pattern thoda zyada general hai kyunki wo kisi bhi element ko end me bhejne ke kaam aata hai bina extra fill kiye.

</details>

5. "Stable partition" ka matlab kya hai, aur Move Zeroes usse kaise judta hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Stable partition ka matlab hai: ek condition ke hisaab se elements ko do groups me baatna — jinka condition match hota hai woh aage, baaki peeche — lekin har group ke andar original order preserve rahe.
