Pichle topic me humne dekha ki code kitna **time** leta hai. But ek aur cheez hoti hai jo utni hi important hai — **memory**.

Sochlo tum ek project bana rahe ho aur tumhara code 10GB data load kar raha hai browser me. Time kitna bhi fast ho, agar memory full ho jaaye to crash ho jaayega. Space complexity tumhe batata hai ki tumhara code kitni **memory** lega.

---

## ✅ Space Complexity kya hai?

> **Space Complexity batata hai ki tumhara code kitni extra memory leta hai input ke size ke saath.**

"Extra" word important hai. Tumhara input (array, string, etc.) to hamesha memory lega — wo count nahi hota. Space complexity me hum **extra** memory dekhte hain jo code create karta hai.

---

## ✅ Kya kya memory leta hai?

### 1. Variables — sabse basic

```js
let count = 0;           // 1 unit space
let name = "Vin";        // 1 unit space
let total = count + 10;  // 1 unit space
```

Har variable = ek unit space. Simple.

---

### 2. Arrays / Objects — size ke proportional

```js
let arr = [1, 2, 3, 4, 5];  // n units (jahan n = 5)
let obj = { a: 1, b: 2 };   // k units (jahan k = keys ki sankhya)
```

Array ka space = usme elements kitne hain. Object ka space = usme key-value pairs kitne hain.

---

### 3. Loops — usually O(1)

```js
function sum(arr) {
  let total = 0;              // 1 unit
  for (let i = 0; i < arr.length; i++) {  // i = 1 unit (reused)
    total += arr[i];          // total already exist karta hai
  }
  return total;
}
// Total extra space = O(1) — sirf 'total' aur 'i' variables
// Loop me naya array create nahi ho raha
```

**Key insight:** Loop me koi extra array create nahi hota, to space O(1) hoti hai. Space complexity sirf tab badhta hai jab tum **naya data structure** banate ho.

---

### 4. New Array banana = O(n)

```js
function doubleElements(arr) {
  let doubled = [];                    // naya array
  for (let i = 0; i < arr.length; i++) {
    doubled.push(arr[i] * 2);          // n elements store
  }
  return doubled;
}
// Space = O(n) — naya array jo size n ka hai
```

Jab tum kisi function me naya array/object banate ho jo input ke proportional bada ho, to space O(n) hai.

---

## ✅ Auxiliary Space vs Total Space

- **Total Space** = input + extra sab mila ke
- **Auxiliary Space** = sirf extra memory (code ne jo create kiya)

Interview me zyadatar **auxiliary space** pucha jaata hai. Reason: input toh hamesha lagega, tumhara code usme kya add kar raha hai — wahi matter karta hai.

**Example:**
```js
function findMax(arr) {    // arr = input, already exists
  let max = arr[0];        // auxiliary: 1 variable = O(1)
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] > max) max = arr[i];
  }
  return max;
}
// Auxiliary Space: O(1)
// Total Space: O(n) — kyunki input array bhi memory me hai
```

---

## ✅ Recursion = Hidden Space Cost

Yeh sabse important concept hai space complexity me.

```js
function factorial(n) {
  if (n === 0) return 1;
  return n * factorial(n - 1);
}
```

Jab tum `factorial(5)` call karte ho:
- `factorial(5)` call hota hai — stack pe push
- `factorial(4)` call hota hai — stack pe push
- `factorial(3)` call hota hai — stack pe push
- `factorial(2)` call hota hai — stack pe push
- `factorial(1)` call hota hai — stack pe push

Ek ke baad ek nahi chal raha — sab **ek saath** memory me hain jab tak base case na mile. Isliye recursion ki space complexity O(n) hoti hai.

```
Stack pe:
┌─────────────┐
│ factorial(5) │
│ factorial(4) │
│ factorial(3) │
│ factorial(2) │
│ factorial(1) │
└─────────────┘
```

**Har recursive call = ek stack frame = ek unit space**

## ✅ Space Complexity Patterns

| Pattern | Space | Example |
|---------|-------|---------|
| Sirf variables | O(1) | `let max = arr[0]` |
| Naya array/object | O(n) | `let doubled = []` |
| Recursion (depth n) | O(n) | `factorial(n)` |
| Recursion (depth log n) | O(log n) | Binary Search recursive |
| 2D array / matrix | O(n²) | `let grid = Array(n).fill().map(() => Array(n))` |

---

## ✅ Time vs Space — Kab kya prefer karein?

Kabhi kabhi tumhe **trade-off** karna padta hai — ya to time bachao ya space bachao.

**Space optimize karne ka example:**
```js
// Naive approach — O(n) space
function hasPairWithSum(arr, target) {
  let seen = [];                    // naya array
  for (let num of arr) {
    if (seen.includes(target - num)) return true;
    seen.push(num);
  }
  return false;
}

// Optimized — O(1) space (two pointer, sorted array assume karo)
function hasPairWithSumSorted(arr, target) {
  let left = 0, right = arr.length - 1;
  while (left < right) {
    let sum = arr[left] + arr[right];
    if (sum === target) return true;
    if (sum < target) left++;
    else right--;
  }
  return false;
}
```

Pehla approach O(n) space leta hai (seen array). Doosra approach O(1) space — sirf 2 variables. Doosra better hai space me.

**But** — agar array sorted nahi hai, to doosra approach kaam nahi karega. Kabhi kabhi space lena padta hai.

**Interview rule of thumb:** Pehle time optimize karo (O(n) se O(log n) ya O(1)), phir agar interviewer bole tab space optimize karo.

## ✅ Common Interview Traps

**Trap 1: String concatenation in loop**
```js
function buildString(n) {
  let result = "";
  for (let i = 0; i < n; i++) {
    result += "a";  // Har baar naya string create hota hai
  }
  return result;
}
// Space: O(n²) technically — kyunki har concatenation naya string banata hai
// But JS engine optimize karta hai, practically O(n)
```

**Trap 2: Spread operator / slice**
```js
let arr = [1, 2, 3, 4, 5];
let copy = [...arr];    // O(n) space — naya array create hua
let slice = arr.slice(); // O(n) space — same
```

**Trap 3: Objects as function params**
```js
function process(obj) {
  // obj reference hai, naya copy nahi
  // Space = O(1) extra
}

function process(obj) {
  let newObj = { ...obj };  // O(n) — spread se copy bana
  // Space = O(n)
}
```

---

## ✅ What It Is NOT

- **Space complexity sirf arrays ki baat nahi hai.** Variables, recursion stack, temporary objects — sab memory leta hai. Har cheez jo function ke andar create hoti hai count hoti hai.

- **O(1) space ka matlab zero memory nahi.** O(1) ka matlab hai constant — input kitna bhi bada ho, extra memory same rahegi. 1 variable ho ya 10 — O(1) hai kyunki input pe depend nahi karta.

- **Recursion hamesha space leti hai.** Har recursive call ek stack frame banata hai. Agar recursion depth n hai to O(n) space. Isliye kabhi kabhi iterative approach better hoti hai space me.

- **Space aur Time alag cheezein hain.** Ek code O(n) time aur O(1) space ho sakta hai (single loop, no extra array). Ek code O(n) time aur O(n) space bhi ho sakta hai (loop + naya array). Dono ka alag analysis hota hai.

**In Your Own Words**

1. Tum ek function likhte ho jo ek array leta hai aur uska har element double karke naya array return karta hai. Space complexity kya hai, aur kyun?

<details>
<summary>Show Answer</summary>

**Sample Answer:** O(n) hai kyunki tum naya array create kar rahe ho jo input array ke proportional hai. Input array ka space input hai (count nahi hota), but jo naya `doubled` array hai wo tumhara extra space hai — n elements store kar raha hai. Isliye auxiliary space O(n).

</details>

2. Tumhara function 100 baar recursion call karta hai (depth 100). Har call me sirf ek variable create hota hai. Space complexity kya hogi?

<details>
<summary>Show Answer</summary>

**Sample Answer:** O(100) = O(100) constant hai — input pe depend nahi kar raha. But agar recursion depth input (n) ke proportional hai (jaise factorial(n)), to space O(n) hogi. Yahan 100 fixed hai, isliye technically O(1). But in general, recursion space = recursion depth.

</details>

3. Do functions hain — Function A ek naya array banata hai jo input ke same size ka hai. Function B sirf 2 variables use karta hai. Dono ka time complexity O(n) hai. Kaunsa function better hai aur kyun?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Function B better hai space me. Dono ka time O(n) hai (same), but Function A ki space O(n) hai (naya array) aur Function B ki space O(1) hai (sirf 2 variables). Agar interviewer bole "optimize for space" to Function B choose karo. But agar Function A ka naya array result return karna zaroori hai, to space lena padega.

</details>

4. Binary Search recursive approach me space complexity kya hai? Aur iterative approach me?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Recursive Binary Search ki space O(log n) hai — kyunki recursion depth log n hoti hai (har call aadha data eliminate karta hai). Iterative Binary Search ki space O(1) hai — sirf `left`, `right`, `mid` variables hain, koi recursion nahi. Isliye iterative approach space me better hai.

</details>

5. Tumhe ek function me object spread (`{...obj}`) use karna hai ya nahi — ye kaise decide karoge?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Agar tumhe original object modify nahi karna hai (immutability chahiye), to spread use karo — O(n) space lagega but safe hai. Agar original object se kaam chal jaata hai (ya tumhe reference chahiye), to mat karo — O(1) space bachegi. React me props ko mutate nahi karte, isliye spread common hai. DSA me usually space bachana hota hai, to avoid karo jab tak zaroori na ho.

</details>
