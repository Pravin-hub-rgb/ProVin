## Problem 1: Find Maximum/Minimum in Array

> **Statement:** Ek array do. Usme se **sabse badi** value aur **sabse chhoti** value dhundo. Dono return karo.

**Input:**
```
arr = [3, 7, 2, 9, 4, 1, 8]
```

**Output:**
```
Max = 9, Min = 1
```

**Constraints yaad rakho:**
- Array me **positive** hi nahi, **negative** numbers bhi ho sakte hain: `[-5, -2, -9]`
- Array me **ek hi element** ho sakta hai: `[42]` — tab max aur min dono 42
- Array **empty** ho sakti hai — yeh edge case poocha jayega!

---

## Pehle Khud Socho (Code Mat Likho)

Ruko — turant code mat likho. Pehle in sawaalo ka jawab dimaag me do:

1. Agar list me 100 numbers hain, aur tumhe max dhundo — kitni baar poori list ghumni padegi? (Hint: ek baar enough hai?)
2. Sabse pehla number kya hai — seedha use karke shuru karoge, ya `0` se compare karna shuru karoge? (Negative numbers ka case socho!)
3. Empty array pe kya hoga agar tum `arr[0]` read karne ki koshish karo?

Jawab soch liye? Ab hi code likho — apne `test.js` me pehle tumhara attempt, phir neeche wala compare karna.

## Approach — Linear Scan (Brute Force Hi Best Hai)

Is problem ka asli naam hai **linear scan** — matlab array ko ek baar, shuru se end tak ghumo, aur har element ko apne "current best" se compare karte jao. Jo bada hai usse current max bana do.

**Yahan koi "trick" nahi hai** — kyunki array **unsorted** hai, koi shortcut nahi ho sakta. Har element ko dekhna hi padega. Agar koi bole "sort kar ke last element le lo" — woh O(n log n) lagega (1.1 me padha tha), jabki linear scan O(n) me hi kaam ho jata hai. Interview me yahi pehchana jata hai — **unsorted array me sabse bada/chhota dhundhne ka best tarika ek hi pass hai.**

### Code

```js
function findMaxMin(arr) {
  if (arr.length === 0) {
    return null;                    // empty array — koi max/min nahi hai
  }

  let max = arr[0];                 // pehla element dono ka shuruaat value
  let min = arr[0];

  for (let i = 1; i < arr.length; i++) {  // i=1 se shuru, kyunki arr[0] pehle hi le liya
    if (arr[i] > max) {
      max = arr[i];                 // naya bada mila, max update
    }
    if (arr[i] < min) {
      min = arr[i];                 // naya chhota mila, min update
    }
  }

  return { max, min };
}

console.log(findMaxMin([3, 7, 2, 9, 4, 1, 8]));  // { max: 9, min: 1 }
console.log(findMaxMin([-5, -2, -9]));           // { max: -2, min: -9 }
console.log(findMaxMin([42]));                   // { max: 42, min: 42 }
console.log(findMaxMin([]));                     // null
```

**Har line samjho:**

1. `if (arr.length === 0) return null;` — **empty array check sabse pehle.** Yeh edge case ka issue hai: agar array khali hai, toh `arr[0]` koi value nahi deta, `undefined` deta hai. Aur `undefined > max` compare karne se koi matlab nahi banta. Interview me pehla sawaal yahi hota hai — "empty array pe kya hoga?"

2. `let max = arr[0]; let min = arr[0];` — **seedha pehle element se shuru karo.** Isse negative numbers wala trap bach jaata hai. Agar tum `let max = 0` se shuru karte, toh `[-5, -2, -9]` me max 0 hi reh jaata — galat! Pehle element ko base banana hamesha safe hai.

3. `for (let i = 1; ...)` — `i = 0` se kyun nahi? Kyunki `arr[0]` ko hum pehle hi max aur min maan chuke hain — usse dobara compare karna bekaar kaam hai. Chhota optimization, par interview me "tumne i=1 se kyun shuru kiya" yeh pooch kar dimaag test karte hain.

4. Do `if` — alag-alag, `else if` nahi. Kyun? Kyunki **ek hi element dono ho sakta hai** (single element case). `else if` use karte toh agar `arr[i] > max` true hua, toh min check hi nahi hota. Par jab tak array me 1 element hai, dono checks zaroori hain. (Note: technically agar `arr[i] > max` hai toh `arr[i] < min` kabhi true nahi hoga, isliye `else if` bhi chalta. Par `if` rakhna readability ke liye safe hai — koi confusion nahi.)

5. `return { max, min };` — object me dono values. Caller ko alag-alag function banane se better hai — ek pass me dono mil gaye.

### Complexity

- **Time: O(n)** — ek loop, har element ek baar visit.
- **Space: O(1)** — sirf do variables `max` aur `min`. No extra array.

**Yeh problem ka perfect answer hai.** 1.1 me padha tha na — O(n) linear time. Yahi best possible hai, kyunki unsorted array ka har element dekhna hi padega. Koi bhi "faster" solution possible hi nahi — isko **lower bound** kehte hain (samajh aaye toh badi baat hai).

## Variations — Interviewer Isko Twist Karega

Asli interview me seedha max/min nahi poocha jaata. Yeh variations poochte hain:

### Variation 1: Sirf Max Chahiye

Agar sirf max chahiye toh `Math.max(...arr)` ek line me:

```js
function findMax(arr) {
  return Math.max(...arr);
}

console.log(findMax([3, 7, 2, 9, 4, 1, 8]));  // 9
```

`...` spread operator 1.3 me padha tha — array ke elements ko alag-alag arguments me convert karta hai. **Lekin dhyan:** badi array pe yeh slow ho sakta hai kyunki spread pura array khinch leta hai. Interview me manually loop likhna better dikhta hai — interviewer ko logic dikhna chahiye, trick nahi.

### Variation 2: Second Largest Dhundo

Yeh direct hota hai — ek loop me max dhundho, phir dusre loop me max se chhota sabse bada:

```js
function secondLargest(arr) {
  let max = -Infinity;
  let second = -Infinity;

  for (let i = 0; i < arr.length; i++) {
    if (arr[i] > max) {
      second = max;          // purana max ab second ban gaya
      max = arr[i];          // naya max
    } else if (arr[i] > second && arr[i] !== max) {
      second = arr[i];
    }
  }

  return second === -Infinity ? null : second;
}

console.log(secondLargest([3, 7, 2, 9, 4, 1, 8]));  // 8
console.log(secondLargest([5, 5, 5]));              // null — sab same hai
```

Iska idea: jab naya max milta hai, **purana max second largest ban jaata hai** — kyunki purana max toh abhi tak ka sabse bada tha (sirf naye se chhota). Yahi "shift down" pattern 1.4 series wale Reverse (1.4.2) aur Move Zeroes (1.4.1) me kaam aayega.

### Variation 3: Index Bhi Do

Max value ke saath uska index bhi chahiye — bas ek `maxIndex` variable rakho:

```js
function findMaxWithIndex(arr) {
  let max = arr[0];
  let maxIndex = 0;

  for (let i = 1; i < arr.length; i++) {
    if (arr[i] > max) {
      max = arr[i];
      maxIndex = i;          // index bhi track karo
    }
  }

  return { max, maxIndex };
}

console.log(findMaxWithIndex([3, 7, 2, 9, 4, 1, 8]));  // { max: 9, maxIndex: 3 }
```

Interview me "value nahi, index chahiye" bolne se yeh pattern yaad rakhna — 90% array problems me value ke saath index bhi track karna hota hai.

## What It Is NOT

- ❌ **Is problem me "optimization" nahi hai.** Linear scan O(n) hi best hai — unsorted array me max/min ka lower bound. Koi hashmap, two pointers, sliding window — kuch nahi lagega. Bade problems ke liye bachaye rakhna, yahan simple hi sahi answer hai.
- ❌ **`Math.max(...arr)` hamesha best nahi.** Badi arrays pe spread memory-heavy ho sakti hai (stack overflow tak). Interview me loop dikhana zyada solid lagta hai.
- ❌ **`0` se shuru karna sahi nahi.** Negative numbers wale cases me `0` base galat jawab deta hai. Base hamesha `arr[0]` rakho.
- ❌ **Sort karna solution nahi hai.** `arr.sort()` + last element = O(n log n). Linear scan ka O(n) usse better hai — sort ko interview me max/min ke liye use karte dekh ke interviewer bhaukhata hai.

## Interview Tips

1. **Pehla sawaal hamesha: "empty array pe kya hoga?"** — Pehle se check karke dikhana confidence deta hai.
2. **Apna example banao** — negative numbers, single element, duplicates. Interview me input bhi tum apne choice ka de sakte ho — weak point dikhana mat.
3. **Brute force ka naam bolo** — "Mai linear scan karunga, O(n)" bolna hi aadha kaam hai. Interviewer ko dikhta hai ki tum complexity soch rahe ho.
4. **Edge cases se shuru karo** — empty check pehle, phir loop. Code ke baad apne examples chalao aur output batao.
