## Problem 1: Find Maximum/Minimum in Array

> **Statement:** Given an array, find the **largest** value and the **smallest** value. Return both.

**Input:**
```
arr = [3, 7, 2, 9, 4, 1, 8]
```

**Output:**
```
Max = 9, Min = 1
```

**Constraints to remember:**
- The array may have not just **positive** but also **negative** numbers: `[-5, -2, -9]`
- The array may have **only one element**: `[42]` — then max and min are both 42
- The array may be **empty** — this edge case will be asked!

## Approach — Linear Scan (Brute Force is Best Here)

The real name of this problem is **linear scan** — traverse the array once from start to end, comparing each element with your "current best." Make the bigger one the new current max.

**There's no "trick" here** — because the array is **unsorted**, no shortcut is possible. You have to look at every element. If someone says "sort it first, then take the last element" — that's O(n log n) (covered in 1.1), while linear scan does it in O(n). Interviews test whether you recognize this — **in an unsorted array, the best way to find the largest/smallest is a single pass.**

### Code

```js
function findMaxMin(arr) {
  if (arr.length === 0) {
    return null;                    // empty array — no max/min
  }

  let max = arr[0];                 // first element is the starting value for both
  let min = arr[0];

  for (let i = 1; i < arr.length; i++) {  // start from 1, since arr[0] already taken
    if (arr[i] > max) {
      max = arr[i];                 // new bigger found, update max
    }
    if (arr[i] < min) {
      min = arr[i];                 // new smaller found, update min
    }
  }

  return { max, min };
}

console.log(findMaxMin([3, 7, 2, 9, 4, 1, 8]));  // { max: 9, min: 1 }
console.log(findMaxMin([-5, -2, -9]));           // { max: -2, min: -9 }
console.log(findMaxMin([42]));                   // { max: 42, min: 42 }
console.log(findMaxMin([]));                     // null
```

**Understand every line:**

1. `if (arr.length === 0) return null;` — **empty array check first.** This is the edge case issue: if the array is empty, `arr[0]` doesn't give any value, it gives `undefined`. Comparing `undefined > max` makes no sense. In interviews, the first question is usually "what happens with an empty array?"
2. `let max = arr[0]; let min = arr[0];` — **start directly with the first element.** This avoids the negative numbers trap. If you started with `let max = 0`, then in `[-5, -2, -9]` the max would remain 0 — wrong! Making the first element the base is always safe.
3. `for (let i = 1; ...)` — why not start from `i = 0`? Because `arr[0]` is already taken as max and min — comparing it again is wasted work. A small optimization, but interviews test your brain with "why did you start at i=1?"
4. Two `if`s — separate, not `else if`. Why? Because **one element could be both** (single element case). If you used `else if`, when `arr[i] > max` is true, the min check wouldn't happen. But as long as the array has 1 element, both checks are needed. (Note: technically if `arr[i] > max` is true, `arr[i] < min` can never be true, so `else if` also works. But keeping `if` is safe for readability — no confusion.)
5. `return { max, min };` — both values in an object. Better than making separate functions — both found in one pass.

### Complexity

- **Time: O(n)** — one loop, each element visited once.
- **Space: O(1)** — only two variables `max` and `min`. No extra array.

**This is the perfect answer for this problem.** As covered in 1.1 — O(n) linear time. This is the best possible, since every element of an unsorted array must be seen. There's no "faster" solution possible — this is called the **lower bound** (understanding this is a big deal).

## Variations — The Interviewer Will Twist This

In real interviews, they don't ask directly for max/min. They ask these variations:

### Variation 1: Only Max Needed

If only max is needed, `Math.max(...arr)` does it in one line:

```js
function findMax(arr) {
  return Math.max(...arr);
}

console.log(findMax([3, 7, 2, 9, 4, 1, 8]));  // 9
```

The `...` spread operator (from 1.3) converts array elements into separate arguments. **But note:** on large arrays this can be slow because spread pulls the entire array at once. In interviews, writing the manual loop looks better — the interviewer wants to see logic, not a trick.

### Variation 2: Find the Second Largest

This comes directly — one loop to find max, then a second loop for the largest smaller than max:

```js
function secondLargest(arr) {
  let max = -Infinity;
  let second = -Infinity;

  for (let i = 0; i < arr.length; i++) {
    if (arr[i] > max) {
      second = max;          // old max becomes second
      max = arr[i];          // new max
    } else if (arr[i] > second && arr[i] !== max) {
      second = arr[i];
    }
  }

  return second === -Infinity ? null : second;
}

console.log(secondLargest([3, 7, 2, 9, 4, 1, 8]));  // 8
console.log(secondLargest([5, 5, 5]));              // null — all same
```

The idea: when a new max is found, the **old max becomes the second largest** — because the old max was the largest until now (just smaller than the new one). This "shift down" pattern will come in handy in the 1.4 series (Reverse (1.4.2) and Move Zeroes (1.4.1)).

### Variation 3: Index Too

Sometimes they want the index along with the max value — just keep a `maxIndex` variable:

```js
function findMaxWithIndex(arr) {
  let max = arr[0];
  let maxIndex = 0;

  for (let i = 1; i < arr.length; i++) {
    if (arr[i] > max) {
      max = arr[i];
      maxIndex = i;          // track index too
    }
  }

  return { max, maxIndex };
}

console.log(findMaxWithIndex([3, 7, 2, 9, 4, 1, 8]));  // { max: 9, maxIndex: 3 }
```

In interviews, "value not needed, index is needed" — remember this pattern. In 90% of array problems, you have to track the value along with its index.

## What It Is NOT

- ❌ **There's no "optimization" in this problem.** Linear scan O(n) is the best — the lower bound for max/min in an unsorted array. No hashmap, two pointers, or sliding window applies here. Keep it simple — that's the right answer.
- ❌ **`Math.max(...arr)` isn't always best.** On large arrays, spread can be memory-heavy (even stack overflow). In interviews, writing the loop looks more solid.
- ❌ **Starting from `0` isn't right.** In cases with negative numbers, a `0` base gives the wrong answer. Always keep the base as `arr[0]`.
- ❌ **Sorting isn't a solution.** `arr.sort()` + last element = O(n log n). Linear scan's O(n) is better — interviewers frown when they see sorting used for max/min.

---

## Interview Tips

1. **First question is always: "what happens with an empty array?"** Checking this first shows confidence.
2. **Make your own example** — negative numbers, single element, duplicates. In interviews, you can even choose your own input — don't show a weak point.
3. **Say the brute force name** — "I'll do a linear scan, O(n)" — that alone is half the work. The interviewer sees you're thinking about complexity.
4. **Start with edge cases** — empty check first, then the loop. After code, run your examples and state the output.

**In Your Own Words**

1. Why is it necessary to start with `let max = arr[0]` in this problem? What problem would arise if we started with `let max = 0`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Starting with `arr[0]` means the base is always a real value from inside the array. If you start with `0`, an array of negatives gives the wrong answer — like `[-5, -2, -9]` would keep max as 0, when the real answer is -2. The `0` base assumes the largest value is always bigger than 0 — which isn't guaranteed. The `arr[0]` base is always safe, whether numbers are positive, negative, or mixed. So remember the rule — "make the first element the base."

</details>

2. Why is the time complexity of this problem O(n), and is a faster solution possible?

<details>
<summary>Show Answer</summary>

**Sample Answer:** It's O(n) because to find the max in an unsorted array, you have to look at every element at least once — how can you know the last element isn't the largest without seeing it? This is the "lower bound" — no solution can be faster, because skipping any element risks missing the max. Sorting would be O(n log n), which is slower. So linear scan is the optimal solution.

</details>

3. Why is the empty array check placed first? What happens without it?

<details>
<summary>Show Answer</summary>

**Sample Answer:** On an empty array, `arr[0]` is `undefined`. The loop doesn't run either (arr.length = 0), so the function returns `{ max: undefined, min: undefined }` — useless and dangerous for the caller (comparisons with undefined give wrong results). Placing the check first makes the function clearly say "no data, null." Checking edge cases first in interviews shows a professional approach.

</details>

4. In the Second Largest variation, what does the `second = max` line do? Explain the logic.

<details>
<summary>Show Answer</summary>

**Sample Answer:** When an element bigger than the current `max` is found, the new element becomes max. The old max was the largest until now (only smaller than the new element) — so the old max is now the second largest. This is the "shift down" pattern: `second = max` makes the old champion the runner-up, then `max = arr[i]` sets the new champion. For duplicates (like `[5, 5, 5]`) there's only one max, no distinct second — so we return null when `second === -Infinity`.

</details>

5. `Math.max(...arr)` vs manual loop — which is better in an interview, and why?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Manual loop is better. Two reasons: first, the spread operator pulls all elements into arguments at once for large arrays, which can be memory-heavy and even error out (maximum call stack). Second — and more important — the interviewer wants to see your logic, not a library function. Writing the loop shows you understand linear scan, can state complexity, and handle edge cases. Use `Math.max` only when the interviewer asks "can we use a library?"

</details>
