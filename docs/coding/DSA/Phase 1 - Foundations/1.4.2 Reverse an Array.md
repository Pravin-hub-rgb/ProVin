## Problem 2: Reverse an Array

> **Statement:** Given an array. Return its **reverse** — last element first, first element last.

**Input:**
```
arr = [1, 2, 3, 4, 5]
```

**Output:**
```
[5, 4, 3, 2, 1]
```

**Constraints to remember:**
- **In-place** — can't create a new array, reverse in the original itself (interviews often say exactly this)
- Empty array (`[]` → `[]`) and single element (`[7]` → `[7]`) — both stay the same, nothing to do
- Strings are like arrays too — the same pattern works on reverse string

## Approach 1: Brute Force — New Array (Easy, But Not In-Place)

The most direct approach — walk from the back, fill a new array:

```js
function reverseBrute(arr) {
  let result = [];                    // new empty array

  for (let i = arr.length - 1; i >= 0; i--) {
    result.push(arr[i]);              // take from back, put in result
  }

  return result;
}

console.log(reverseBrute([1, 2, 3, 4, 5]));  // [5, 4, 3, 2, 1]
```

This works, time is O(n). But two problems: (1) **Space O(n)** — a new array was created, (2) **the original array doesn't change** — some interviews say "reverse in-place, in the original itself." So we need to go further.

---

## Approach 2: Two Pointers (In-Place) — The Real Solution

This is the same code from 1.4. Now understand **why** it works, more deeply:

```js
function reverseInPlace(arr) {
  let left = 0;                       // from the start
  let right = arr.length - 1;         // from the end

  while (left < right) {
    // Swap — exchange the two fingered values
    [arr[left], arr[right]] = [arr[right], arr[left]];

    left++;                           // left finger forward
    right--;                          // right finger backward
  }

  return arr;                         // original is now reversed
}

console.log(reverseInPlace([1, 2, 3, 4, 5]));  // [5, 4, 3, 2, 1]
console.log(reverseInPlace([]));               // []
console.log(reverseInPlace([7]));              // [7]
```

**Understand every line:**

1. `left = 0`, `right = arr.length - 1` — two fingers, at both ends.
2. `while (left < right)` — until the fingers cross. When `left === right`, it's the same element — no point swapping. Hence `<`, not `<=`.
3. Swap — destructuring (Template 3 from 1.3). The old way works too (with temp variable) — in interviews, write whichever comes to mind.
4. `left++`, `right--` — both fingers move one step inward. One pair gets swapped per step.

**Watch it run — `[1, 2, 3, 4, 5]`:**

```
left=0, right=4 → swap(0,4) → [5, 2, 3, 4, 1]
left=1, right=3 → swap(1,3) → [5, 4, 3, 2, 1]
left=2, right=2 → left < right FALSE → stop ✅
```

The whole array reversed in just 2 swaps. The middle element (`3`) was never touched because it's already in its correct position — in a reversed sequence, the middle stays the same.

**Complexity:** Time O(n/2) ≈ O(n) — half the iterations. Space O(1) — just two variables, no new array.

> **This is the same pattern as Container With Most Water in 1.4** — left/right fingers. One pattern gives reverse, palindrome, two-sum, container — all solved. That's why I say, pattern library is the real skill.

## Another Way — JavaScript Built-ins (When it Works, When it Doesn't)

JavaScript has a built-in `reverse()` method:

```js
let arr = [1, 2, 3, 4, 5];
arr.reverse();
console.log(arr);  // [5, 4, 3, 2, 1]
```

This is also **in-place** and O(n). So why not just use it?

**Because in interviews, when you use a built-in, the interviewer asks "do it without the built-in"** — and that's the real test. Using a built-in is fine (do it in production code), but in interviews **showing the logic** is more valuable. The point of DSA practice is to be able to build what's inside `reverse()` yourself.

One more thing — built-in `reverse()` modifies the original array (it's in-place), but some people use it on a copy:

```js
let reversed = [...arr].reverse();   // make copy, then reverse
```

Benefit: original stays safe. But this is O(n) extra space. In interviews, mention all of this — "I know the built-in too, but I'm showing the manual in-place version for the logic" — that impression is best.

## Variations — The Interviewer Will Twist This

### Variation 1: Reverse a Subarray (Reverse a Part)

Not the whole array — reverse only from `start` to `end`:

```js
function reverseRange(arr, start, end) {
  let left = start;
  let right = end;

  while (left < right) {
    [arr[left], arr[right]] = [arr[right], arr[left]];
    left++;
    right--;
  }

  return arr;
}

console.log(reverseRange([1, 2, 3, 4, 5], 1, 3));  // [1, 4, 3, 2, 5]
```

Just `left = 0` becomes `left = start`, and `right = arr.length - 1` becomes `right = end`. This small change is the solution to 1.3.2 (Rotate Array) — hint dropped!

### Variation 2: Reverse a String

Strings aren't arrays, but their characters can be accessed by index — same pattern:

```js
function reverseString(s) {
  let chars = s.split("");          // string → character array
  let left = 0;
  let right = chars.length - 1;

  while (left < right) {
    [chars[left], chars[right]] = [chars[right], chars[left]];
    left++;
    right--;
  }

  return chars.join("");            // back to string
}

console.log(reverseString("hello"));  // "olleh"
```

Note: `s.split("")` takes O(n) space — but strings are immutable, so you can't do it without an array copy. Mention in interviews: "extra space is needed because of string immutability."

### Variation 3: Reverse + Palindrome — Two Sides of the Same Coin

To check a palindrome, **reverse and compare**:

```js
function isPalindrome(s) {
  return s === s.split("").reverse().join("");
}

console.log(isPalindrome("racecar"));  // true
console.log(isPalindrome("hello"));    // false
```

But this takes O(n) space (copy + reverse). The two-pointer version from 1.4 does it in O(1) space. When the interview says "optimize space," give the two-pointer version — that's the difference that shows.

---

## What It Is NOT

- ❌ **Reverse is not sort.** Flipped order = reverse. Sorted order = smallest to largest. Totally different. `[3, 1, 2]` reversed = `[2, 1, 3]`, sorted = `[1, 2, 3]`!
- ❌ **Using built-in `reverse()` is not the solution.** Use it in production, show logic in interviews. "Without built-in" follow-up always comes.
- ❌ **`left <= right` loop is wrong.** When equal, that same element swaps with itself — wasted work. `left < right` is correct (skip the middle in odd lengths).
- ❌ **O(n) space is not "fine" for reverse.** The extra-array solution works, but fails the "in-place" constraint. Two pointers' O(1) space is the interview answer.

---

## Interview Tips

1. **First brute force, then optimize.** "First I'd do it with a new array — O(n) space. Now in-place — two pointers, O(1) space." Showing this flow tells the interviewer you know the process.
2. **The middle element question will come** — "what happens in odd length?" Answer: the middle element is already in its correct place, not swapped, so the loop stops at `left < right`.
3. **Mention the built-in method** — "JavaScript's `reverse()` is also in-place, but I'm showing manually for the logic" — this shows knowledge.
4. **Keep the string version ready** — the interviewer may say "reverse a string too." Both `split` → `reverse` → `join` and two pointers should be ready.

**In Your Own Words**

1. In Reverse Array, why `while (left < right)`? With `left <= right`, what happens, especially in odd-length arrays?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `left < right` because when both pointers land on the same index, that element is already in its correct place (the middle) — swapping is pointless. With `left <= right`, in an odd-length array the middle element swaps with itself (wasted work), and in an even-length array the loop runs one extra iteration after the pointers have crossed — old elements swap back and the array reverts to original! `[1,2,3,4]` with `left=2, right=1` running the loop would swap 3 and 2 back, giving wrong result. So the condition is always `left < right`.

</details>

2. Brute force (new array) vs two pointers (in-place) — time and space difference? Why is in-place preferred in interviews?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Brute force: time O(n), space O(n) — creates a new array. Two pointers: time O(n), space O(1) — just two variables, work in the original array. In interviews in-place is preferred because (1) it's memory efficient — O(n) extra space costs on large data, (2) some problems have the constraint "do not allocate extra space for another array," (3) in production too, avoiding mutation to save memory is best practice. Time is the same in both — the difference is only in space, and interviews ask about the space difference.

</details>

3. We know `arr.reverse()` built-in, so why write it manually?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Two reasons. First: the interviewer's real goal is to test whether you know what happens inside `reverse()` — the logic. Using a built-in prompts "do it without the built-in" and you get stuck. Second: DSA patterns are general — reverse's two-pointer pattern applies to subarray reverse, string reverse, rotate array, palindrome — all of them. Built-in only reverses a full array; the pattern can't generalize. So built-in for production, pattern for interviews — know both, use each in its context.

</details>

4. In the reverse string variation, why must you use `split("")`? Why can't you loop directly on the string?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Because strings in JavaScript are **immutable** — you can't directly change string characters (`s[0] = "x"` has no effect). So you must pull characters into an array with `split("")` (arrays are mutable), swap there, then `join("")` back to string. This takes O(n) extra space — but with immutable strings there's no option, so in interviews it's important to mention why extra space is needed. Same story with palindromes — the two-pointer version does it in O(1), which is why that's better.

</details>

5. What's the difference between reverse and sort? Can their results ever be the same for any array?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Reverse means flipping the sequence — first becomes last, last becomes first. Sort means arranging by value — smallest to largest (or largest to smallest). Difference example: `[3, 1, 2]` reversed = `[2, 1, 3]`, sorted = `[1, 2, 3]` — totally different. Results can be the same only when the array is already in descending order and we sort ascending: `[3, 2, 1]` reversed = `[1, 2, 3]` = sorted. Edge case, but worth knowing.

</details>
