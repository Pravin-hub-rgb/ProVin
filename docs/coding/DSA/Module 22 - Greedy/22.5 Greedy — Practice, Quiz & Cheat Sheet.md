## Mini Quiz

1. What is the greedy choice property?
2. Why must you sort both arrays in Assign Cookies?
3. In Lemonade Change, why prefer $10 + $5 over three $5s for $20 change?
4. What is the time complexity of the greedy approach to Maximum Units on a Truck?
5. How do you know if a problem needs Greedy vs DP?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. The greedy choice property means the best local choice is always part of the global optimal solution. If you can prove this (or can't find a counterexample), greedy works. Without it, you need DP (consider all choices).
2. Sorting enables the greedy assignment: assign the smallest sufficient cookie to the least greedy child. Without sorting, you can't guarantee that a cookie you skip for one child would work for another. Sorting ensures you never waste a large cookie on an easy child.
3. $10 + $5 uses one $10 and one $5 (saves $5s for future $10 customers). Three $5s uses three $5s (wastes them). Since $5s are needed for $10 change, saving them is the greedy (optimal) choice. Using three $5s when a $10 is available can cause failure later.
4. O(n log n) — sorting dominates. The greedy pass is O(n). Space: O(1) extra (sorting may use O(log n) stack).
5. Test: can you prove that the best local choice always leads to the global optimum? If yes → greedy (simpler, faster). If you can find a counterexample where the greedy choice leads to a suboptimal solution → DP. Many problems look like greedy but aren't (e.g., Coin Change with arbitrary denominations).

</details>

## One-Page Cheat Sheet

**Greedy pattern (sort + assign):**
```java
Arrays.sort(g); Arrays.sort(s);
int i = 0, j = 0;
while (i < g.length && j < s.length) {
    if (s[j] >= g[i]) i++;  // satisfied
    j++;  // try next
}
return i;
```

**Lemonade Change:**
```java
int five = 0, ten = 0;
for (int bill : bills) {
    if (bill == 5) five++;
    else if (bill == 10) { if (five == 0) return false; five--; ten++; }
    else { if (ten > 0 && five > 0) { ten--; five--; } else if (five >= 3) five -= 3; else return false; }
}
return true;
```

**Maximum Units on a Truck:**
```java
Arrays.sort(boxTypes, (a, b) -> b[1] - a[1]); // descending by units
int total = 0, remaining = truckSize;
for (int[] box : boxTypes) {
    int take = Math.min(box[0], remaining);
    total += take * box[1];
    remaining -= take;
    if (remaining == 0) break;
}
return total;
```

**Complexities:** Sort O(n log n), greedy pass O(n). Space O(1) extra.

## In Your Own Words

1. What is the greedy choice property?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The greedy choice property means the best local choice is always part of the global optimal solution. If this holds, you can make the best choice at each step and never revisit — greedy works. If it doesn't hold (a locally optimal choice leads to a suboptimal global solution), you need DP. Test by trying to find a counterexample: if greedy fails on some input, it doesn't have the property.

</details>

2. Why does sorting enable the greedy approach in Assign Cookies?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Sorting both arrays lets you greedily assign the smallest sufficient cookie to the least greedy child. Since both are sorted, you can use two pointers: if the current cookie satisfies the current child, satisfy and move to the next child; otherwise, try a larger cookie. This maximizes count because you never "waste" a large cookie on an easy child. Without sorting, you can't guarantee optimal pairing.

</details>

3. How do you know if a problem needs Greedy vs DP?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Try to find a counterexample where the greedy (best local) choice leads to a suboptimal solution. If you can't find one (and can prove it), use greedy (simpler, faster). If you find one, use DP (consider all choices). Many problems look like greedy but aren't (e.g., Coin Change with arbitrary denominations — greedy fails, DP needed). When in doubt, start with DP (correct) and optimize to greedy if possible.

</details>
