## The Core Idea

**Greedy** algorithms make the best local choice at each step and never look back. No backtracking, no memoization. If the problem has the greedy choice property, greedy is simpler and faster than DP.

**Greedy vs DP:**
- **Greedy:** make the best local choice, move forward. O(n) or O(n log n). Works when local optimum = global optimum.
- **DP:** consider all choices, pick the best. O(n²) or O(n × m). Works when greedy doesn't apply.

**How to know if greedy works:** Try to find a counterexample where the greedy choice leads to a suboptimal solution. If you can't find one (and can prove it), greedy works. If you find one, use DP.

**Common greedy patterns:**
1. **Sort then greedy:** sort by one criterion, then make choices (assign cookies, maximum units).
2. **Two pointers (greedy):** move the pointer that gives the best improvement.
3. **Interval scheduling:** sort by end time, pick the earliest-finishing interval.

## How to Recognize It

Think "Greedy" when:
- The problem asks for **maximum/minimum** with a **constraint** (capacity, budget).
- The problem involves **assigning/matching** (cookies to children, items to trucks).
- The problem involves **scheduling** (earliest finish time first).
- The problem has an obvious "best choice" at each step (largest first, smallest first).
- Keywords: "maximum," "minimum," "assign," "schedule," "greedy."

**Signal words:** "maximum number of," "minimum cost," "assign," "schedule," "greedy," "optimal."

## Worked Example: Assign Cookies

**Problem:** Each child has a greed factor; each cookie has a size. A child is satisfied if the cookie size ≥ greed. Maximize the number of satisfied children (each child gets at most one cookie, each cookie to at most one child).

### Brute force (O(n × m))

For each child, try every cookie. Slow.

### Optimized (O(n log n + m log m)) — sort + greedy

```java
class Solution {
    public int findContentChildren(int[] g, int[] s) {
        Arrays.sort(g);  // sort greed factors
        Arrays.sort(s);  // sort cookie sizes

        int child = 0, cookie = 0;
        while (child < g.length && cookie < s.length) {
            if (s[cookie] >= g[child]) {
                child++;  // satisfied
            }
            cookie++;  // try next cookie
        }
        return child;
    }
}
```

**Line-by-line:**
- Sort both arrays (greed and cookie sizes).
- `child` points to the current child; `cookie` to the current cookie.
- If the current cookie satisfies the current child (`s[cookie] >= g[child]`), satisfy the child (child++).
- Always advance cookie (try next cookie).
- Return the number of satisfied children.

**Key insight:** sort both, then greedily assign the smallest sufficient cookie to each child. This maximizes the count because you use the smallest cookie that works, leaving larger cookies for greedier children.

## Common Mistakes

- **Not sorting.** Without sorting, the greedy assignment doesn't work — you can't guarantee optimal pairing.
- **Advancing the wrong pointer.** Always advance `cookie` (try next cookie). Only advance `child` when satisfied. If you advance both on failure, you skip children.
- **Confusing with DP.** If the problem has overlapping subproblems and no greedy choice property, use DP. Test: can you find a counterexample where greedy fails?
- **Not handling edge cases.** Empty arrays, all cookies too small, all children easily satisfied.

## How to Explain (interview)

**Opening:** Greedy makes the best local choice at each step and never revisits. Works when the problem has the greedy choice property (best local = global optimum) and optimal substructure. Common pattern: sort by one criterion, then greedily assign. O(n log n) due to sorting. If greedy doesn't apply, use DP.

**The basic flow (assign cookies):**
```java
Arrays.sort(g); Arrays.sort(s);
int child = 0, cookie = 0;
while (child < g.length && cookie < s.length) {
    if (s[cookie] >= g[child]) child++;  // satisfied
    cookie++;  // try next cookie
}
return child;
```

**The part that trips everyone up:** sort both arrays first. Then greedily assign the smallest sufficient cookie to each child. This maximizes count by not "wasting" large cookies on easy children.

**The mistakes to remember:**
- Not sorting (greedy assignment fails)
- Advancing both pointers on failure (skips children)
- Using greedy when DP is needed (find a counterexample first)
- Not handling edge cases (empty arrays)
