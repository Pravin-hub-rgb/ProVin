# 22.1 Greedy — The Pattern

## What This Problem Is Asking (Simple Terms)

Greedy algorithms make the **locally optimal choice** at each step with the hope of finding the global optimum. Unlike DP which explores all possibilities, greedy makes one choice at a time and never looks back.

**Key insight:** Greedy works when the problem has:
- **Greedy choice property:** locally optimal choice leads to global optimum
- **Optimal substructure:** optimal solution contains optimal solutions to subproblems

---

## Example 1

**Problem:** Given coins [1, 5, 10, 25] and target amount 63, find minimum coins.

**Greedy approach:** Take as many quarters (25¢) as possible, then dimes (10¢), then nickels (5¢), then pennies (1¢).
- 63 ÷ 25 = 2 quarters (50¢), remainder 13¢
- 13 ÷ 10 = 1 dime (10¢), remainder 3¢
- 3 ÷ 5 = 0 nickels, remainder 3¢
- 3 ÷ 1 = 3 pennies
- Total: 2 + 1 + 0 + 3 = **6 coins** ✅

---

## Example 2

**Input:** `coins = [1, 3, 4]`, `target = 6`

**Output:** `2`

**Explanation:**
- Greedy: 4 + 1 + 1 = **3 coins**
- Optimal: 3 + 3 = **2 coins**

**Greedy fails here!** Greedy doesn't work for arbitrary coin denominations.

## Constraints

- `1 <= coins.length <= 12`
- `1 <= coins[i] <= 2^31 - 1`
- `0 <= amount <= 10^4`

## Which Technique, and Why?

Greedy makes **locally optimal choices** at each step with the hope of finding the global optimum. Unlike DP which explores all possibilities, Greedy makes **one choice at a time** and never looks back.

**Signal in the problem:** "minimum number of coins," "maximum number of events," "as many items as possible" → Greedy!

---

## Approach

**Greedy approach:**
1. Sort coins in descending order (largest denomination first).
2. For each coin, take as many as possible without exceeding target.
3. Move to next smaller coin.

### Pseudocode (Coin Change - Greedy)

```
sort coins in descending order
count = 0
for each coin in coins:
    while target >= coin:
        target -= coin
        count++
return count if target == 0 else -1
```

### Java Code (Coin Change - Greedy)

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        Arrays.sort(coins);
        int count = 0;
        
        for (int i = coins.length - 1; i >= 0; i--) {
            while (amount >= coins[i]) {
                amount -= coins[i];
                count++;
            }
        }
        return amount == 0 ? count : -1;
    }
}
```

### Line-by-line

- `Arrays.sort(coins)` — sort coins in ascending order.
- `for (int i = coins.length - 1; i >= 0; i--)` — loop from largest coin to smallest.
- `while (amount >= coins[i])` — take as many of this coin as possible.
- `amount -= coins[i]; count++;` — subtract coin value, increment count.
- `return amount == 0 ? count : -1;` — if amount is 0, return count; else -1.

## Complexity

- Time: O(n log n) — sorting + O(n) greedy pass.
- Space: O(1) — just counters.

## Common Mistakes

- **Assuming greedy works for all coin systems** — greedy fails for arbitrary coin denominations like [1, 3, 4] with target 6 (greedy: 4+1+1=3 coins, optimal: 3+3=2 coins).
- **Not sorting coins** — must sort in descending order.
- **Not handling impossible case** — return -1 if amount cannot be formed.
