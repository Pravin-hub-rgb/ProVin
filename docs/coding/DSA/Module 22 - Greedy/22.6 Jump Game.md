# 22.6 Jump Game

**Tier 2 problem.** (LeetCode #55)

**Problem:** Given an array where each element is the max jump length from that position, determine if you can reach the last index. (LeetCode #55)

**Link:** https://leetcode.com/problems/jump-game/

---

## Which Technique, and Why?

"Can you reach the end?" → **Greedy**. Track the farthest reachable index. At each position, if you can reach it (i ≤ farthest), update farthest = max(farthest, i + nums[i]). If farthest ≥ n-1 → true. O(n) time, O(1) space.

**Signal in the problem:** "jump game" / "can you reach the last index" → greedy (track farthest reachable).

## Approach

Greedy: `farthest = 0`. For i from 0 to n-1: if `i > farthest` → can't reach i → return false. Update `farthest = max(farthest, i + nums[i])`. If `farthest >= n-1` → return true.

## Pseudocode

```
farthest = 0
for i from 0 to n-1:
    if i > farthest: return false
    farthest = max(farthest, i + nums[i])
    if farthest >= n - 1: return true
return farthest >= n - 1
```

## Java Code

```java
class Solution {
    public boolean canJump(int[] nums) {
        int farthest = 0;
        for (int i = 0; i < nums.length; i++) {
            if (i > farthest) return false;
            farthest = Math.max(farthest, i + nums[i]);
            if (farthest >= nums.length - 1) return true;
        }
        return farthest >= nums.length - 1;
    }
}
```

## Line-by-line

- `farthest` = the furthest index reachable so far.
- `if (i > farthest) return false` — if you can't reach position i, you can't proceed.
- `farthest = max(farthest, i + nums[i])` — update the farthest reachable.
- Early exit: if `farthest >= n-1` → can reach the end → true.

## Complexity

- Time: O(n) — single pass.
- Space: O(1).

## Common Mistakes

- **Using DP.** DP works (O(n²) or O(n)) but greedy is simpler and faster. The greedy choice (max reach) is optimal here.
- **Not checking `i > farthest`.** If you can't reach position i, you can't use nums[i]. This check is essential.
- **Off-by-one in the early exit.** `farthest >= n - 1` (not `== n - 1`). If farthest exceeds n-1, you can still reach.
- **Confusing with Jump Game II (#45).** That one asks for the minimum number of jumps. Different problem (greedy with jump counting).

## How to Explain (interview)

**Opening:** Jump Game checks if you can reach the last index. Greedy: track the farthest reachable index. If you can't reach position i (`i > farthest`), return false. Update farthest = max(farthest, i + nums[i]). If farthest ≥ n-1 → true. O(n) time, O(1) space.

**The basic flow:**
```java
int farthest = 0;
for (int i = 0; i < nums.length; i++) {
    if (i > farthest) return false;
    farthest = Math.max(farthest, i + nums[i]);
    if (farthest >= nums.length - 1) return true;
}
return false;
```

**The part that trips everyone up:** the check `i > farthest` must come **before** using `nums[i]`. If you can't reach position i, you can't use its jump. Also, early exit when `farthest >= n-1`.

**The mistakes to remember:**
- Using DP (O(n²)) when greedy is O(n)
- Not checking `i > farthest` (uses unreachable positions)
- Off-by-one in early exit (`==` instead of `>=`)
- Confusing with Jump Game II (#45, min jumps)
