**Tier 2 problem.** (LeetCode #45)

**Problem:** Given an array where each element is the max jump length, find the minimum number of jumps to reach the last index. (LeetCode #45)

**Link:** https://leetcode.com/problems/jump-game-ii/

---

## Which Technique, and Why?

"Minimum jumps to reach the end" → **Greedy (BFS-like levels)**. Track the current jump's range [start, end]. For all positions in this range, find the farthest reachable. When you exhaust the range, increment jumps and set the new range. O(n) time, O(1) space.

**Signal in the problem:** "minimum number of jumps" → greedy with level-by-level expansion (like BFS).

## Approach

Greedy: `jumps = 0`, `currentEnd = 0`, `farthest = 0`. For i from 0 to n-2: `farthest = max(farthest, i + nums[i])`. If `i == currentEnd`: `jumps++`, `currentEnd = farthest`. Return `jumps`.

## Pseudocode

```
jumps = 0, currentEnd = 0, farthest = 0
for i from 0 to n-2:
    farthest = max(farthest, i + nums[i])
    if i == currentEnd:
        jumps++
        currentEnd = farthest
return jumps
```

## Java Code

```java
class Solution {
    public int jump(int[] nums) {
        int jumps = 0, currentEnd = 0, farthest = 0;

        for (int i = 0; i < nums.length - 1; i++) {
            farthest = Math.max(farthest, i + nums[i]);
            if (i == currentEnd) {
                jumps++;
                currentEnd = farthest;
            }
        }
        return jumps;
    }
}
```

## Line-by-line

- `currentEnd` — the farthest index reachable with the current number of jumps.
- `farthest` — the farthest index reachable by extending one more jump from any position in the current range.
- When `i == currentEnd`, we've exhausted the current jump range → increment jumps, set `currentEnd = farthest`.
- Loop to `n-2` (not `n-1`) because you don't need to jump from the last position.

## Complexity

- Time: O(n) — single pass.
- Space: O(1).

## Common Mistakes

- **Using DP.** DP works (O(n²) or O(n)) but greedy is simpler. The greedy "level expansion" is the intended solution.
- **Looping to n-1.** You don't need to jump from the last position. Loop to `n-2`.
- **Not updating `currentEnd` correctly.** `currentEnd = farthest` (not `farthest + 1` or `i + 1`).
- **Confusing with Jump Game (#55).** That one asks "can you reach?" (boolean). This one asks "minimum jumps" (int).

## How to Explain (interview)

**Opening:** Jump Game II finds the minimum jumps to reach the end. Greedy with level expansion: track the current jump's range [start, currentEnd]. For all positions in this range, find the farthest reachable. When the range is exhausted, increment jumps and set the new range. O(n) time, O(1) space.

**The basic flow:**
```java
int jumps = 0, currentEnd = 0, farthest = 0;
for (int i = 0; i < nums.length - 1; i++) {
    farthest = Math.max(farthest, i + nums[i]);
    if (i == currentEnd) { jumps++; currentEnd = farthest; }
}
return jumps;
```

**The part that trips everyone up:** loop to `n - 2` (not `n - 1`) — you don't jump from the last position. Also, `currentEnd = farthest` (not `farthest + 1`).

**The mistakes to remember:**
- Using DP (O(n²)) when greedy is O(n)
- Looping to n-1 (unnecessary, can cause issues)
- Wrong currentEnd update
- Confusing with Jump Game (#55, boolean)
