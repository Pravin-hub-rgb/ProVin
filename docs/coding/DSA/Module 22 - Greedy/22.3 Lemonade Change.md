# 22.3 Lemonade Change

**Problem:** You sell lemonade for $5. Customers pay with $5, $10, or $20 bills. Return true if you can provide correct change to every customer. (LeetCode #860)

**Link:** https://leetcode.com/problems/lemonade-change/

---

## Which Technique, and Why?

Lemonade costs $5; customers pay $5/$10/$20. You need to give change ($5 for $10, $15 for $20). The greedy choice: **always give the largest bills as change first** (save $5s for when you need them). Track counts of $5 and $10 bills. O(n) time, O(1) space.

**Signal in the problem:** "provide change" / "can you serve all customers" → greedy (give largest bills first, track $5/$10 counts).

## Approach

Track `five` and `ten` counts. For each customer:
- $5: `five++`.
- $10: need one $5 → `five--`, `ten++`. If no $5 → false.
- $20: prefer $10 + $5 (give $15 as 10+5). If no $10, give three $5s. If neither → false.

## Pseudocode

```
five = 0, ten = 0
for bill in bills:
    if bill == 5: five++
    elif bill == 10:
        if five == 0: return false
        five--; ten++
    else:  // bill == 20
        if ten > 0 and five > 0:
            ten--; five--
        elif five >= 3:
            five -= 3
        else: return false
return true
```

## Java Code

```java
class Solution {
    public boolean lemonadeChange(int[] bills) {
        int five = 0, ten = 0;
        for (int bill : bills) {
            if (bill == 5) {
                five++;
            } else if (bill == 10) {
                if (five == 0) return false;
                five--;
                ten++;
            } else { // bill == 20
                if (ten > 0 && five > 0) {
                    ten--;
                    five--;
                } else if (five >= 3) {
                    five -= 3;
                } else {
                    return false;
                }
            }
        }
        return true;
    }
}
```

## Line-by-line

- `five`, `ten` track bill counts (no need to track $20s — they're never used as change).
- $5: increment five.
- $10: need one $5 for change. If none → false. Decrement five, increment ten.
- $20: need $15 change. Prefer $10 + $5 (saves $5s). If no $10, use three $5s. If neither → false.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — two counters.

## Common Mistakes

- **Giving three $5s for $20 when a $10 is available.** This wastes $5s. Always prefer $10 + $5 (greedy: use the largest bills for change).
- **Not tracking $5 and $10 separately.** You only need these two ( $20s are never given as change).
- **Returning false too early.** Only return false when you can't make change for the current customer.
- **Assuming $20 bills can be used as change.** Lemonade costs $5; max change needed is $15. $20 is never given as change.

## How to Explain (interview)

**Opening:** Lemonade Change checks if you can give correct change to all customers. Greedy: for $20, prefer giving $10 + $5 (saves $5s) over three $5s. Track $5 and $10 counts (no need to track $20s). O(n) time, O(1) space.

**The basic flow:**
```java
int five = 0, ten = 0;
for (int bill : bills) {
    if (bill == 5) five++;
    else if (bill == 10) { if (five == 0) return false; five--; ten++; }
    else { if (ten > 0 && five > 0) { ten--; five--; } else if (five >= 3) five -= 3; else return false; }
}
return true;
```

**The part that trips everyone up:** for $20 change, prefer $10 + $5 over three $5s. This greedy choice saves $5s for future $10 customers. Using three $5s when a $10 is available can cause failure later.

**The mistakes to remember:**
- Giving three $5s when $10 + $5 is available (wastes $5s)
- Tracking $20 bills (never needed as change)
- Returning false too early (only when can't make change)
- Not preferring largest bills first (greedy choice)
