# 22.8 Gas Station

**Tier 2 problem.** (LeetCode #134)

**Problem:** Given gas and cost arrays for circular stations, find the starting station index to complete the circuit (or -1). (LeetCode #134)

**Link:** https://leetcode.com/problems/gas-station/

---

## Which Technique, and Why?

"Gas station circuit" → **Greedy**. If total gas ≥ total cost, a solution exists. Track running balance; when it goes negative, reset the start to the next station. O(n) time, O(1) space.

**Signal in the problem:** "gas station" / "circular circuit" / "can complete the circuit" → greedy (track balance, reset start).

## Approach

1. If total gas < total cost → return -1.
2. Track `tank` (running balance) and `start`. For each station: `tank += gas[i] - cost[i]`. If `tank < 0`, reset `start = i + 1`, `tank = 0`.
3. Return `start` (if total gas ≥ total cost).

## Pseudocode

```
total = 0, tank = 0, start = 0
for i from 0 to n-1:
    total += gas[i] - cost[i]
    tank += gas[i] - cost[i]
    if tank < 0:
        start = i + 1
        tank = 0
if total < 0: return -1
return start
```

## Java Code

```java
class Solution {
    public int canCompleteCircuit(int[] gas, int[] cost) {
        int total = 0, tank = 0, start = 0;

        for (int i = 0; i < gas.length; i++) {
            total += gas[i] - cost[i];
            tank += gas[i] - cost[i];
            if (tank < 0) {
                start = i + 1;
                tank = 0;
            }
        }

        return total >= 0 ? start : -1;
    }
}
```

## Line-by-line

- `total` — cumulative balance. If < 0, impossible → return -1.
- `tank` — running balance from `start`. If it goes negative, reset `start` to `i + 1` and `tank` to 0.
- `start` — candidate starting station. When `tank < 0`, the current start can't be the answer (and neither can any station before i, because they'd have an even worse balance). So reset to `i + 1`.

## Complexity

- Time: O(n) — single pass.
- Space: O(1).

## Common Mistakes

- **Not checking `total < 0`.** If total gas < total cost, no solution exists → return -1.
- **Resetting start to 0 instead of i+1.** When `tank < 0`, the start must move past the failure point. Stations before i are all invalid.
- **Not resetting tank to 0.** After resetting start, tank must be 0 (fresh start).
- **O(n²) approach.** Trying each start and simulating is O(n²). The greedy O(n) approach is the intended solution.

## How to Explain (interview)

**Opening:** Gas Station finds the starting station for a circular circuit. Greedy: track running balance; when it goes negative, reset start to next station. If total gas ≥ total cost, a solution exists. O(n) time, O(1) space.

**The basic flow:**
```java
int total = 0, tank = 0, start = 0;
for (int i = 0; i < n; i++) {
    total += gas[i] - cost[i];
    tank += gas[i] - cost[i];
    if (tank < 0) { start = i + 1; tank = 0; }
}
return total >= 0 ? start : -1;
```

**The part that trips everyone up:** when `tank < 0`, reset `start = i + 1` (not 0) and `tank = 0`. Stations before i are all invalid (they'd have an even worse balance). Also, check `total >= 0` for existence.

**The mistakes to remember:**
- Not checking total < 0 (returns a start when impossible)
- Resetting start to 0 instead of i+1
- Not resetting tank to 0
- O(n²) simulation instead of O(n) greedy
