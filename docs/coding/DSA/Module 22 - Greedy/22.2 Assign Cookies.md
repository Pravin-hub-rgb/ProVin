**Problem:** Each child has a greed factor g[i]; each cookie has size s[j]. A child is satisfied if s[j] >= g[i]. Maximize the number of satisfied children. Each child gets at most one cookie, each cookie to at most one child. (LeetCode #455)

**Link:** https://leetcode.com/problems/assign-cookies/

---

## Which Technique, and Why?

Maximize satisfied children with cookie sizes → **Greedy (sort + two pointers)**. Sort both arrays, then greedily assign the smallest sufficient cookie to each child. O(n log n + m log m) time, O(1) space.

**Signal in the problem:** "maximize the number" + "assign" + two arrays (children greed, cookie sizes) → sort + greedy two pointers.

## Approach

Sort greed factors and cookie sizes. Use two pointers: child and cookie. If current cookie satisfies current child, satisfy (child++). Always advance cookie. Return child count.

## Pseudocode

```
sort g, sort s
child = 0, cookie = 0
while child < g.length and cookie < s.length:
    if s[cookie] >= g[child]: child++
    cookie++
return child
```

## Java Code

```java
class Solution {
    public int findContentChildren(int[] g, int[] s) {
        Arrays.sort(g);
        Arrays.sort(s);

        int child = 0, cookie = 0;
        while (child < g.length && cookie < s.length) {
            if (s[cookie] >= g[child]) {
                child++;  // satisfied
            }
            cookie++;  // try next cookie
        }
        return child;
    }
}
```

## Line-by-line

- Sort both arrays — enables greedy assignment.
- `child` points to current (least greedy unsatisfied) child.
- `cookie` points to current cookie.
- If `s[cookie] >= g[child]`, this cookie satisfies the child → `child++`.
- Always `cookie++` — try the next cookie.
- Return `child` — number of satisfied children.

## Complexity

- Time: O(n log n + m log m) — sorting dominates.
- Space: O(1) extra (sorting may use O(log n) stack).

## Common Mistakes

- **Not sorting.** Without sorting, greedy assignment doesn't maximize — you might waste a large cookie on an easy child.
- **Advancing both pointers on failure.** If `s[cookie] < g[child]`, only advance `cookie` (the cookie is too small for this child but might work for a... no, since sorted, if it's too small for the least greedy child, it's too small for all). Actually, since g is sorted ascending, if `s[cookie] < g[child]`, this cookie is too small for the current (least greedy) child → too small for all → discard it (cookie++). If `s[cookie] >= g[child]`, satisfy child (child++) and advance cookie. The code handles both correctly.
- **Using nested loops** (O(n × m)) — unnecessary.
- **Not handling empty arrays.** Returns 0. Correct.

## How to Explain (interview)

**Opening:** Assign Cookies maximizes satisfied children. Sort both greed factors and cookie sizes. Greedily assign the smallest cookie that satisfies each child. O(n log n) time, O(1) space.

**The basic flow:**
```java
Arrays.sort(g); Arrays.sort(s);
int child = 0, cookie = 0;
while (child < g.length && cookie < s.length) {
    if (s[cookie] >= g[child]) child++;
    cookie++;
}
return child;
```

**The part that trips everyone up:** sort both arrays. The greedy choice is "assign the smallest sufficient cookie to the least greedy child" — this maximizes count by not wasting large cookies.

**The mistakes to remember:**
- Not sorting (greedy fails)
- Advancing child on failure (skips children)
- Using nested loops (O(n×m)) instead of two pointers (O(n+m))
