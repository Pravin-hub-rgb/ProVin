# 7.1 Greedy — The Pattern

## What This Problem Is Asking (Simple Terms)

Greedy algorithms make the **locally optimal choice** at each step with the hope of finding the global optimum. Think of it as "take the best option right now and worry about the consequences later."

Unlike Dynamic Programming, which explores many possibilities and remembers results, Greedy makes **one choice at a time** and never looks back.

---

## Example 1

**Problem:** You have coins of denominations [1, 5, 10, 25] and want to make 63 cents using the fewest coins.

**Greedy approach:** Take as many quarters (25¢) as possible, then dimes (10¢), then nickels (5¢), then pennies (1¢).

- 63 ÷ 25 = 2 quarters (50¢), remainder 13¢
- 13 ÷ 10 = 1 dime (10¢), remainder 3¢
- 3 ÷ 5 = 0 nickels, remainder 3¢
- 3 ÷ 1 = 3 pennies

Total: 2 + 1 + 0 + 3 = **6 coins**

Is this optimal? Yes! For US coin denominations, greedy always gives the minimum.

---

## Example 2

**Input:** `coins = [1, 3, 4]`, `target = 6`

**Output:** `3`

**Explanation:**
- Greedy: 4 + 1 + 1 = 3 coins
- Optimal: 3 + 3 = **2 coins**

**Greedy fails here!** Greedy doesn't always give the optimal answer for arbitrary coin denominations.

---

## Constraints

- `1 <= coins.length <= 12`
- `1 <= coins[i] <= 2^31 - 1`
- `1 <= amount <= 10^4`

---

## Which Technique, and Why?

Greedy makes **locally optimal choices** hoping they lead to a globally optimal solution. The key insight: **some problems have the "greedy choice property"** — making the locally optimal choice at each step leads to a globally optimal solution.

**Signal in the problem:** "minimum number of coins," "maximum number of events," "as many items as possible" → Greedy!

---

## Approach

Greedy approach:
1. Sort coins in descending order (largest denomination first).
2. For each coin, take as many as possible without exceeding the target.
3. Move to the next smaller coin.

### Pseudocode

```
sort coins in descending order
count = 0
for each coin in coins:
    while target >= coin:
        target -= coin
        count += 1
return count if target == 0 else -1
```

### Java Code

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        Arrays.sort(coins);
        int count = 0;
        
        for (int i = coins.length - 1; i >= 0; i--) {
            while (amount >= coins[i]) {
                amount -= coins[i];
                count++;
            }
        }
        
        return amount == 0 ? count : -1;
    }
}
```

### Line-by-line

- `Arrays.sort(coins)` — sort coins in ascending order.
- Loop from largest coin to smallest.
- `while (amount >= coins[i])` — take as many of this coin as possible.
- `amount -= coins[i]; count++;` — subtract coin value, increment count.
- `return amount == 0 ? count : -1;` — if exact change possible, return count; else -1.

## Complexity

- Time: O(n log n) — sorting + O(n) greedy pass.
- Space: O(1) — just counters.

## Common Mistakes

- **Assuming greedy works for all coin systems** — it fails for arbitrary denominations like [1, 3, 4] with target 6.
- **Not sorting coins** — must process largest to smallest.
- **Infinite loop** — ensure `amount >= coins[i]` condition prevents infinite loop.

**Opening:** Greedy Coin Change picks the largest coin possible at each step. It works for canonical coin systems (like US coins) but fails for arbitrary denominations. O(n log n) time due to sorting, O(1) space.

**The basic flow:**
```java

```

**The part that trips everyone up:** Greedy works for canonical coin systems (like US coins: 1, 5, 10, 25) but fails for arbitrary denominations like [1, 3, 4] with target 6 (greedy: 4+1+1=3 coins, optimal: 3+3=2 coins).

**The mistakes to remember:**
- Assuming greedy works for all coin systems
- Not sorting coins in descending order
- Not handling the case where amount cannot be formed
