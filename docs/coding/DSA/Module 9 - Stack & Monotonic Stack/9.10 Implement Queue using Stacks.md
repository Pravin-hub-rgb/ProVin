**Problem:** Implement a FIFO queue using only two stacks. Support push, pop, peek, and empty. (LeetCode #232)

**Link:** https://leetcode.com/problems/implement-queue-using-stacks/

---

## Which Technique, and Why?

You need FIFO behavior (queue) but only have LIFO containers (stacks). The trick: use **two stacks** — one for input (push), one for output (pop/peek). When the output stack is empty, transfer all elements from input to output (reversing the order, which gives FIFO). Amortized O(1) per operation.

**Signal in the problem:** "implement queue using stacks" → two-stack approach with lazy transfer.

## Approach

- `push(x)`: push to input stack. O(1).
- `pop()`: if output stack is empty, transfer all from input to output (reversing order). Then pop from output. Amortized O(1).
- `peek()`: same as pop but don't remove.
- `empty()`: both stacks empty.

The transfer reverses the order: input stack (bottom→top: 1,2,3) → output stack (bottom→top: 3,2,1) → popping gives 1,2,3 (FIFO). Each element is transferred at most once → amortized O(1).

## Pseudocode

```
push(x): input.push(x)
pop():
    if output empty: while input not empty: output.push(input.pop())
    return output.pop()
peek():
    if output empty: while input not empty: output.push(input.pop())
    return output.peek()
empty(): return input.isEmpty() and output.isEmpty()
```

## Java Code

```java
class MyQueue {
    private Deque<Integer> input = new ArrayDeque<>();
    private Deque<Integer> output = new ArrayDeque<>();

    public void push(int x) {
        input.push(x);
    }

    public int pop() {
        if (output.isEmpty()) {
            while (!input.isEmpty()) {
                output.push(input.pop());
            }
        }
        return output.pop();
    }

    public int peek() {
        if (output.isEmpty()) {
            while (!input.isEmpty()) {
                output.push(input.pop());
            }
        }
        return output.peek();
    }

    public boolean empty() {
        return input.isEmpty() && output.isEmpty();
    }
}
```

## Line-by-line

- `input` stack receives all pushes.
- `pop`/`peek`: if `output` is empty, transfer all from `input` to `output` (reversing order). Then operate on `output`.
- The transfer happens lazily (only when output is empty) — this is what gives amortized O(1).
- `empty`: both stacks must be empty.

## Complexity

- `push`: O(1).
- `pop`/`peek`: amortized O(1) (transfer is O(n) but happens at most once per element).
- `empty`: O(1).
- Space: O(n) — two stacks.

## Common Mistakes

- **Transferring on every operation.** Only transfer when `output` is empty. Transferring every time makes pop O(n) each time.
- **Forgetting to check `output.isEmpty()` before transferring.** If output still has elements, don't transfer — they're already in FIFO order.
- **Using a single stack.** A single stack can't implement a queue efficiently (pop would be O(n)). Two stacks are needed.
- **Using `java.util.Stack`.** Use `ArrayDeque` with `push`/`pop`/`peek`.

## How to Explain (interview)

**Opening:** Implement Queue using Stacks uses two stacks: input (for push) and output (for pop/peek). When output is empty, transfer all elements from input to output — this reverses the order, giving FIFO. Amortized O(1) per operation because each element is transferred at most once.

**The basic flow:**
```java
void push(int x) { input.push(x); }
int pop() {
    if (output.isEmpty()) while (!input.isEmpty()) output.push(input.pop());
    return output.pop();
}
```

**The part that trips everyone up:** transfer is **lazy** — only when output is empty. Also, the transfer reverses the order: input (1,2,3 bottom→top) → output (3,2,1 bottom→top) → pop gives 1, 2, 3 (FIFO).

**The mistakes to remember:**
- Transferring on every pop (O(n) per op instead of amortized O(1))
- Using a single stack (can't do FIFO efficiently)
- Forgetting to check `output.isEmpty()` before transferring
- Using `java.util.Stack` instead of `ArrayDeque`
