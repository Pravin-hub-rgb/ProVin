## Mini Quiz

1. Why is the monotonic stack O(n) even though there's a while loop inside?
2. In Min Stack, why use `<=` on push and `==` on pop?
3. In Evaluate RPN, why does operand order matter for `-` and `/`?
4. In Daily Temperatures, why store indices instead of values?
5. In "Implement Queue using Stacks," why transfer lazily (only when output is empty)?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. Each element is pushed once and popped at most once. The while loop's total work across all iterations is O(n) (amortized), not O(n²). Even though a single iteration might pop multiple elements, each element is popped at most once in its lifetime.
2. `<=` on push ensures duplicates are tracked in minStack. `==` on pop ensures that when a duplicate minimum is popped, minStack is also popped. Using `<` on push would cause desync: the second copy of the minimum wouldn't be in minStack, so popping it wouldn't pop minStack.
3. The first popped value is the **right** operand. For `a - b`, you pop `b` first, then `a`. So `a - b`, not `b - a`. Same for division: `a / b`. Getting this backwards gives wrong answers.
4. You need indices to compute the distance (`i - idx` = number of days). Values alone don't give you the position. Store indices, look up values via the array.
5. Transferring on every pop would make each pop O(n). Transferring lazily (only when output is empty) means each element is transferred at most once in its lifetime — amortized O(1) per operation. Elements already in output are in FIFO order and don't need re-transfer.

</details>

## One-Page Cheat Sheet

**Stack (LIFO):** `push`, `pop`, `peek` — all O(1). Use `ArrayDeque`, not `java.util.Stack`.

**Monotonic Stack (next greater):**
```java
Deque<Integer> stack = new ArrayDeque<>();
for (int i = 0; i < n; i++) {
    while (!stack.isEmpty() && arr[stack.peek()] < arr[i]) {
        int idx = stack.pop();
        result[idx] = i - idx;  // or arr[i] as next greater
    }
    stack.push(i);
}
```

**Min Stack (auxiliary min stack):**
```java
void push(int val) { main.push(val); if (min.isEmpty() || val <= min.peek()) min.push(val); }
void pop() { int v = main.pop(); if (v == min.peek()) min.pop(); }
int getMin() { return min.peek(); }
```

**Evaluate RPN:**
```java
for (String token : tokens) {
    if (isOp(token)) { int b = stack.pop(), a = stack.pop(); stack.push(apply(token, a, b)); }
    else stack.push(Integer.parseInt(token));
}
return stack.pop();
```

**Implement Queue using Stacks:**
```java
void push(int x) { input.push(x); }
int pop() { if (output.isEmpty()) while (!input.isEmpty()) output.push(input.pop()); return output.pop(); }
```

**Complexities:** all stack operations O(1) (amortized for queue-via-stacks). Monotonic stack is O(n) total (each element pushed/popped once).

## In Your Own Words

1. What is a monotonic stack, and when do you use it?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A monotonic stack maintains elements in increasing or decreasing order. When a new element arrives, pop all elements that violate the order. Used for "next greater/smaller element" problems. Each element is pushed and popped at most once → O(n) total. For "next greater," the stack is decreasing (so a new larger element resolves the top). For "next smaller," it's increasing.

</details>

2. Why does the monotonic stack achieve O(n) even with a while loop?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Each element is pushed once and popped at most once. The while loop's total work across all iterations is O(n) (amortized), not O(n²). Even though a single iteration might pop multiple elements, each element is popped at most once in its lifetime. The total number of push + pop operations is at most 2n = O(n).

</details>

3. How does the two-stack queue achieve amortized O(1) pop?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The output stack holds elements in FIFO order. When it's empty, transfer all elements from input to output (reversing order). This transfer is O(n) but happens at most once per element (amortized). Subsequent pops are O(1). Each element is transferred at most once in its lifetime, so total transfer cost is O(n) across all operations → amortized O(1) per pop.

</details>
