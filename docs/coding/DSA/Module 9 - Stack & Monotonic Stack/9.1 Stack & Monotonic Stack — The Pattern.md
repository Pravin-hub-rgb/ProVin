# 9.1 Stack & Monotonic Stack — The Pattern

## What This Problem Is Asking (Simple Terms)

A **Stack** is a Last-In-First-Out (LIFO) data structure — like a stack of plates, the last one placed on top is the first one removed. Operations: `push` (add to top), `pop` (remove from top), `peek` (view top without removing).

A **Monotonic Stack** is a stack where elements are maintained in monotonically increasing or decreasing order. It's used to efficiently find the "next greater/smaller element" for each element in an array.

---

## Example 1

**Input:** `nums = [2, 1, 2, 4, 3]`

**Output:** `[3, 3, 4, -1, -1]`

**Explanation:** 
- For 2 (index 0): next greater is 3 at index 1
- For 1 (index 1): next greater is 2 at index 2
- For 2 (index 2): next greater is 3 at index 3
- For 3 (index 3): no greater element to the right → -1
- For 4 (index 4): no greater element → -1

---

## Example 2

**Input:** `nums = [1,2,3,4,5]`

**Output:** `[2,3,4,5,-1]`

**Explanation:** Each element's next greater is the next element; last element has no greater element.

---

## Constraints

- `1 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`

---

## Which Data Structure/Technique, and Why?

**Monotonic Stack** is the key technique for "next greater/smaller element" problems.

**Signal in the problem:** "next greater element", "next smaller element", "next greater element II" → Monotonic Stack.

---

## Approach

**Monotonic Decreasing Stack:**
- Iterate through array from left to right.
- While stack is not empty AND `nums[stack.peek()] < nums[i]`, pop from stack and set result for popped index to `nums[i]`.
- Push current index onto stack.
- Elements remaining in stack have no greater element → -1.

### Pseudocode

```
result = array of -1, size n
stack = empty stack
for i from 0 to n-1:
    while stack not empty and nums[stack.top()] < nums[i]:
        result[stack.pop()] = nums[i]
    stack.push(i)
return result
```

### Java Code

```java
class Solution {
    public int[] nextGreaterElement(int[] nums) {
        int n = nums.length;
        int[] res = new int[n];
        Arrays.fill(res, -1);
        Deque<Integer> stack = new ArrayDeque<>();
        
        for (int i = 0; i < n; i++) {
            while (!stack.isEmpty() && nums[stack.peek()] < nums[i]) {
                res[stack.pop()] = nums[i];
            }
            stack.push(i);
        }
        return res;
    }
}
```

### Line-by-line

- `int[] res = new int[n]; Arrays.fill(res, -1);` — initialize result with -1 (default for no greater element).
- `Deque<Integer> stack = new ArrayDeque<>()` — stack stores indices, not values.
- `while (!stack.isEmpty() && nums[stack.peek()] < nums[i])` — while current element is greater than element at top of stack, it's the "next greater" for the element at top.
- `res[stack.pop()] = nums[i]` — assign current element as next greater for popped index.
- `stack.push(i)` — push current index onto stack.

## Complexity

- Time: O(n) — each element pushed and popped at most once.
- Space: O(n) — stack can hold up to n elements.

## Common Mistakes

- **Storing values instead of indices** — need indices to update result array correctly.
- **Not initializing result array with -1** — elements without next greater should remain -1.
- **Using wrong comparison** — for next greater, use `nums[stack.peek()] < nums[i]`; for next smaller, use `nums[stack.peek()] > nums[i]`.

---

## How to Explain (interview)

**Opening:** Monotonic Stack finds the next greater/smaller element for each position efficiently. Maintain a monotonic stack of indices; when current element breaks monotonicity, it's the answer for elements popped from stack.

**The basic flow:**
```java
int[] res = new int[n];
Arrays.fill(res, -1);
Deque<Integer> stack = new ArrayDeque<>();
for (int i = 0; i < n; i++) {
    while (!stack.isEmpty() && nums[stack.peek()] < nums[i]) {
        res[stack.pop()] = nums[i];
    }
    stack.push(i);
}
return res;
```

**The part that trips everyone up:**
- Stack stores **indices**, not values — needed to update result array.
- While loop condition uses `<` for next greater, `>` for next smaller.
- Elements remaining in stack have no greater element → remain -1.

**The mistakes to remember:**
- Storing values instead of indices in stack
- Wrong comparison operator (< vs >)
- Not initializing result with -1
