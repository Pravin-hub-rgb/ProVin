## The Core Idea

**Stack (LIFO):** elements are added and removed from the same end (the top). Push adds, pop removes, peek looks. Used for: bracket matching, undo/redo, DFS, expression evaluation.

**Monotonic Stack:** a stack that maintains elements in increasing (or decreasing) order. When a new element arrives, pop all elements that violate the order. This is the key to O(n) "next greater element" problems: each element is pushed and popped at most once.

**The mental model for monotonic stack:** you're scanning left to right. For each element, you ask "which previous elements does this new element 'resolve'?" Pop them and record the answer. The stack holds "unresolved" elements waiting for a larger (or smaller) value.

## How to Recognize It

Think "Stack" when:
- The problem involves **matching/nesting** (brackets, tags, parentheses) → stack.
- The problem involves **undo/redo** or **backtracking** → stack.
- The problem involves **expression evaluation** (postfix, infix) → stack.

Think "Monotonic Stack" when:
- The problem asks for the **next greater/smaller element** for each element.
- The problem asks for the **number of days until a warmer temperature** (next greater).
- Keywords: "next greater element," "next smaller," "daily temperatures," "largest rectangle in histogram."

**Signal words:** "matching brackets," "next greater," "next smaller," "daily temperatures," "monotonic," "nearest."

## Worked Example: Daily Temperatures

**Problem:** Given daily temperatures, return an array where each element is the number of days until a warmer temperature. If none, 0.

### Brute force (O(n²))

For each day, scan forward until a warmer day is found.

### Optimized (O(n)) — monotonic stack

```java
class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int n = temperatures.length;
        int[] result = new int[n];
        Deque<Integer> stack = new ArrayDeque<>(); // indices, decreasing temps

        for (int i = 0; i < n; i++) {
            while (!stack.isEmpty() && temperatures[stack.peek()] < temperatures[i]) {
                int idx = stack.pop();
                result[idx] = i - idx;  // days until warmer
            }
            stack.push(i);
        }
        return result;
    }
}
```

**Line-by-line:**
- `stack` holds indices of days whose "next warmer day" hasn't been found yet. Temperatures at these indices are in decreasing order (monotonic decreasing stack).
- For each day `i`: while the stack is non-empty and `temperatures[i]` is warmer than the temperature at the top index, pop it — `i` is its "next warmer day." Record `i - idx` days.
- Push `i` onto the stack (it's now waiting for a warmer day).
- Unresolved indices remain in the stack with result 0 (default).

**Key insight:** each index is pushed once and popped at most once → O(n) total. The stack is monotonic (decreasing temperatures) — this is what makes the "while" loop amortized O(1).

## Common Mistakes

- **Storing values instead of indices.** You need indices to compute the distance (days). Store indices; look up values via the array.
- **Wrong monotonic order.** For "next greater," the stack should be **decreasing** (so a new larger element resolves the top). For "next smaller," it should be **increasing**.
- **Not popping in a while loop.** A single `if` only resolves one element. Use `while` to resolve all elements that the new value resolves.
- **Using `java.util.Stack`.** It's legacy and slow. Use `ArrayDeque` with `push`/`pop`/`peek`.
- **Forgetting that unresolved elements stay 0.** Initialize result to 0 (default for int arrays) — unresolved days keep 0.

## How to Explain (interview)

**Opening:** Stack is LIFO (last in, first out) — push, pop, peek. Monotonic Stack maintains elements in increasing/decreasing order; when a new element arrives, pop all that violate the order. This turns O(n²) "next greater element" into O(n) because each element is pushed and popped at most once. Used for bracket matching, expression evaluation, and next-greater/smaller problems.

**The basic flow (monotonic, next greater):**
```java
Deque<Integer> stack = new ArrayDeque<>();
for (int i = 0; i < n; i++) {
    while (!stack.isEmpty() && arr[stack.peek()] < arr[i]) {
        int idx = stack.pop();
        result[idx] = i - idx;  // or arr[i] as the "next greater"
    }
    stack.push(i);
}
```

**The part that trips everyone up:** store **indices**, not values (you need the distance). Use `while`, not `if` (resolve all). The stack must be monotonic — if you push without popping, it's just a regular stack, not monotonic.

**The mistakes to remember:**
- Storing values instead of indices
- Using `if` instead of `while` (misses elements)
- Wrong monotonic order (decreasing for next-greater, increasing for next-smaller)
- Using legacy `java.util.Stack` instead of `ArrayDeque`
