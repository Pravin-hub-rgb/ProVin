A queue is a FIFO (First In, First Out) container — elements are added at the back and removed from the front. Like a line at a ticket counter: first come, first served.

---

## Declaration and Creation

```java
import java.util.ArrayDeque;
import java.util.Queue;

Queue<Integer> queue = new ArrayDeque<>();
```

**Note:** Use `Queue` (interface) on the left, `ArrayDeque` (implementation) on the right. Do NOT use `java.util.LinkedList` as a queue unless you need `List` features — `ArrayDeque` is faster.

## Core Operations

```java
Queue<Integer> q = new ArrayDeque<>();

q.offer(10);              // add to back (returns boolean)
q.offer(20);
q.offer(30);

System.out.println(q.peek());   // 10 (look at front, don't remove; null if empty)
System.out.println(q.poll());   // 10 (remove and return front; null if empty)
System.out.println(q.size());    // 2
System.out.println(q.isEmpty()); // false
```

- `offer(x)` — add to back: O(1) amortized. Returns false if capacity exceeded (ArrayDeque never exceeds, so always true).
- `poll()` — remove and return front: O(1). Returns null if empty (vs `remove()` which throws).
- `peek()` — look at front without removing: O(1). Returns null if empty (vs `element()` which throws).
- `isEmpty()`, `size()`: O(1).

**Prefer `offer`/`poll`/`peek`** over `add`/`remove`/`element` — the former return null on empty, the latter throw exceptions.

## When to Use

- **BFS (breadth-first search)** — process nodes level by level.
- **Task scheduling** — process tasks in arrival order.
- **Sliding window maximum** — monotonic deque (uses queue operations).
- **Producer-consumer** — one thread produces, another consumes in order.

## Common Pitfalls

- **Using `java.util.LinkedList` as a queue.** `ArrayDeque` is faster (array-backed, no node allocation). Use `LinkedList` only if you need `List` features.
- **Using `add`/`remove`/`element` instead of `offer`/`poll`/`peek`.** The former throw exceptions on empty; the latter return null. In DSA, you usually want null (safe).
- **Confusing stack and queue.** Stack = LIFO (push/pop same end). Queue = FIFO (offer back, poll front). Don't mix them.
- **Thread safety.** `ArrayDeque` is not thread-safe. Use `ConcurrentLinkedQueue` for concurrent access (rare in DSA).

## A Small Program: BFS Level Order

```java
import java.util.*;

public class BFSExample {
    static void levelOrder(int[][] adj, int start) {
        Queue<Integer> q = new ArrayDeque<>();
        boolean[] visited = new boolean[adj.length];
        q.offer(start);
        visited[start] = true;

        while (!q.isEmpty()) {
            int node = q.poll();
            System.out.print(node + " ");
            for (int neighbor : adj[node]) {
                if (!visited[neighbor]) {
                    visited[neighbor] = true;
                    q.offer(neighbor);
                }
            }
        }
    }

    public static void main(String[] args) {
        int[][] adj = {{1, 2}, {0, 3}, {0, 3}, {1, 2}};
        levelOrder(adj, 0);  // 0 1 2 3
    }
}
```

## In Your Own Words

1. What is FIFO, and how does a queue implement it?

<details>
<summary>Show Answer</summary>

**Sample Answer:** FIFO = First In, First Out. The first element added is the first one removed. A queue implements this by adding at the back (offer) and removing from the front (poll). Like a line at a counter — first person in line is served first. Used for BFS, task scheduling, and any "process in arrival order" scenario.

</details>

2. Why prefer `offer`/`poll`/`peek` over `add`/`remove`/`element`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `offer`/`poll`/`peek` return null on empty (safe). `add`/`remove`/`element` throw `NoSuchElementException` on empty. In DSA, you often check "is the queue empty?" before operating, so null-returning methods are safer and avoid try-catch. `ArrayDeque` never rejects `offer` (unbounded), so `offer` always returns true.

</details>

3. When should you use ArrayDeque as a queue vs as a stack?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Same class, different methods. As a queue (FIFO): `offer` (back), `poll` (front), `peek` (front). As a stack (LIFO): `push` (top), `pop` (top), `peek` (top). `push`/`pop` operate on one end; `offer`/`poll` operate on opposite ends. Don't mix the two sets of methods on the same instance — pick one usage.

</details>
