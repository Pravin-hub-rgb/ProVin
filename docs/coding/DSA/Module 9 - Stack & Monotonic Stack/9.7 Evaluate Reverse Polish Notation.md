**Problem:** Evaluate an arithmetic expression in Reverse Polish Notation (postfix). Valid operators: +, -, *, /. (LeetCode #150)

**Link:** https://leetcode.com/problems/evaluate-reverse-polish-notation/

---

## Which Technique, and Why?

Postfix notation (RPN) has the operator after its operands: "3 4 +" means 3 + 4. No parentheses needed. Evaluation → **Stack**. Push numbers; on an operator, pop two operands, apply, push result. O(n) time, O(n) space.

**Signal in the problem:** "Reverse Polish Notation" / "postfix expression" / "evaluate expression with +,-,*,/" → stack-based evaluation.

## Approach

Walk the tokens. If token is a number, push. If token is an operator, pop two operands (second popped is the left operand), apply, push result. At the end, the stack has one element — the answer.

## Pseudocode

```
stack = empty
for each token:
    if token is number: stack.push(parseInt(token))
    else:
        b = stack.pop()   // right operand
        a = stack.pop()   // left operand
        result = apply(token, a, b)
        stack.push(result)
return stack.pop()
```

## Java Code

```java
class Solution {
    public int evalRPN(String[] tokens) {
        Deque<Integer> stack = new ArrayDeque<>();

        for (String token : tokens) {
            switch (token) {
                case "+": {
                    int b = stack.pop(), a = stack.pop();
                    stack.push(a + b);
                    break;
                }
                case "-": {
                    int b = stack.pop(), a = stack.pop();
                    stack.push(a - b);
                    break;
                }
                case "*": {
                    int b = stack.pop(), a = stack.pop();
                    stack.push(a * b);
                    break;
                }
                case "/": {
                    int b = stack.pop(), a = stack.pop();
                    stack.push(a / b);  // integer division, truncates toward zero
                    break;
                }
                default:
                    stack.push(Integer.parseInt(token));
            }
        }
        return stack.pop();
    }
}
```

## Line-by-line

- `stack` holds operands.
- Number token → push (parsed to int).
- Operator token → pop `b` (right operand) first, then `a` (left operand). Order matters for `-` and `/`.
- Apply operator, push result.
- Final pop returns the answer.

**Operand order:** for `-` and `/`, the first popped is the **right** operand. So `a - b` means `a` is popped second. Getting this backwards is the #1 bug.

## Complexity

- Time: O(n) — single pass, each token processed once.
- Space: O(n) — stack holds up to n operands.

## Common Mistakes

- **Operand order for `-` and `/`.** Pop `b` first (right operand), then `a` (left). `a - b`, not `b - a`. `a / b`, not `b / a`.
- **Integer division truncation.** Java's `/` truncates toward zero. The problem specifies truncation toward zero (not floor). Match the spec.
- **Using `java.util.Stack`** — slow. Use `ArrayDeque`.
- **Not handling negative numbers in tokens.** `Integer.parseInt("-3")` works fine. The split token is the whole number string.

## How to Explain (interview)

**Opening:** Evaluate RPN evaluates a postfix expression. Stack-based: push numbers; on an operator, pop two operands (second popped is left operand), apply, push result. At the end, one element remains — the answer. O(n) time, O(n) space. Division truncates toward zero.

**The basic flow:**
```java
Deque<Integer> stack = new ArrayDeque<>();
for (String token : tokens) {
    if (isOperator(token)) {
        int b = stack.pop(), a = stack.pop();
        stack.push(apply(token, a, b));

}
return stack.pop();
```

**The part that trips everyone up:** **operand order** for `-` and `/`. Pop `b` first (right operand), then `a` (left). `a - b`, not `b - a`. Also, division truncates toward zero (Java default).

**The mistakes to remember:**
- Swapping operand order for `-` and `/`
- Using `java.util.Stack` instead of `ArrayDeque`
- Not handling negative number tokens (they parse fine)
