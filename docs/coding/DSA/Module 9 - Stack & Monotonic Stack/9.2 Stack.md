A stack is a LIFO (Last In, First Out) container — elements are added and removed from the same end (the top). Like a pile of plates: you can only take from the top.

---

## Declaration and Creation

```java
import java.util.ArrayDeque;
import java.util.Deque;

Deque<Integer> stack = new ArrayDeque<>();
```

**Note:** Use `Deque` (interface) on the left, `ArrayDeque` (implementation) on the right. Do NOT use `java.util.Stack` — it's legacy, synchronized, and slow.

## Core Operations

```java
Deque<Integer> stack = new ArrayDeque<>();

stack.push(10);              // add to top
stack.push(20);
stack.push(30);

System.out.println(stack.peek());   // 30 (look at top, don't remove)
System.out.println(stack.pop());    // 30 (remove and return top)
System.out.println(stack.size());   // 2
System.out.println(stack.isEmpty()); // false
```

- `push(x)` — add to top: O(1).
- `pop()` — remove and return top: O(1). Throws `NoSuchElementException` if empty.
- `peek()` — look at top without removing: O(1). Returns null if empty (for ArrayDeque; throws for Stack).
- `isEmpty()`, `size()`: O(1).

## When to Use

- **Bracket/parenthesis matching** — push opening, pop on closing, check match.
- **Undo/redo** — push actions, pop to undo.
- **DFS (depth-first search)** — explicit stack instead of recursion.
- **Expression evaluation** — postfix (RPN) evaluation, infix to postfix conversion.
- **Backtracking** — push state, pop on failure.

## Common Pitfalls

- **Using `java.util.Stack`.** Legacy, slow (synchronized). Use `ArrayDeque` with `push`/`pop`/`peek`.
- **Calling `pop()` on an empty stack** — throws `NoSuchElementException`. Check `isEmpty()` first, or use `poll()` (returns null).
- **Storing values instead of indices.** In "next greater element," you need indices to compute distance. Store indices, look up values via the array.
- **Forgetting LIFO order.** The last element pushed is the first popped. If you need FIFO, use a queue.

## A Small Program: Check Balanced Parentheses

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class BalancedParens {
    static boolean isBalanced(String s) {
        Deque<Character> stack = new ArrayDeque<>();
        for (char c : s.toCharArray()) {
            if (c == '(' || c == '[' || c == '{') {
                stack.push(c);
            } else if (c == ')' || c == ']' || c == '}') {
                if (stack.isEmpty()) return false;
                char top = stack.pop();
                if (!matches(top, c)) return false;
            }
        }
        return stack.isEmpty();
    }

    static boolean matches(char open, char close) {
        return (open == '(' && close == ')') ||
               (open == '[' && close == ']') ||
               (open == '{' && close == '}');
    }

    public static void main(String[] args) {
        System.out.println(isBalanced("([])"));   // true
        System.out.println(isBalanced("([)]"));   // false
    }
}
```

## In Your Own Words

1. What is LIFO, and how does a stack implement it?

<details>
<summary>Show Answer</summary>

**Sample Answer:** LIFO = Last In, First Out. The last element pushed is the first one popped. A stack implements this by adding and removing from the same end (the top). Push adds to top, pop removes from top. This makes it ideal for nested/matching problems (brackets, tags) and backtracking.

</details>

2. Why use ArrayDeque instead of java.util.Stack?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `java.util.Stack` extends `Vector` (synchronized, thread-safe), which adds locking overhead even in single-threaded code. `ArrayDeque` is unsynchronized, faster, and has a cleaner API (push/pop/peek). Use `ArrayDeque` as a stack with `push`/`pop`/`peek`; use `java.util.Stack` only if you need its legacy methods (rarely).

</details>

3. When should you store indices instead of values in a stack?

<details>
<summary>Show Answer</summary>

**Sample Answer:** When you need to compute a distance or position (e.g., "how many days until a warmer temperature" = index difference). Store the index; look up the value via the array. If you only need the value (e.g., "next greater element value"), storing values is fine. When in doubt, store indices — they're more flexible.

</details>
