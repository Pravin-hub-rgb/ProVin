**Tier 2 problem.** (LeetCode #901)

**Problem:** Design a class that, given a daily price, returns the span (number of consecutive days with price ≤ today's price, including today). (LeetCode #901)

**Link:** https://leetcode.com/problems/online-stock-span/

---

## Which Technique, and Why?

"Online stock span" → **Monotonic Stack (decreasing)**. For each new price, pop all previous prices ≤ current, accumulating their spans. The span = 1 + sum of popped spans. O(1) amortized per call.

**Signal in the problem:** "stock span" / "consecutive days with price ≤ today" → monotonic stack (decreasing), accumulate spans.

## Approach

Maintain a stack of (price, span) pairs in decreasing price order. For a new price: while stack top's price ≤ current price, pop and add its span. Push (price, 1 + accumulated span). Return the span.

## Pseudocode

```
stack = empty (of (price, span))
next(price):
    span = 1
    while stack not empty and stack.peek().price <= price:
        span += stack.pop().span
    stack.push((price, span))
    return span
```

## Java Code

```java
class StockSpanner {
    private final Deque<int[]> stack; // {price, span}

    public StockSpanner() {
        stack = new ArrayDeque<>();
    }

    public int next(int price) {
        int span = 1;
        while (!stack.isEmpty() && stack.peek()[0] <= price) {
            span += stack.pop()[1];
        }
        stack.push(new int[]{price, span});
        return span;
    }
}
```

## Line-by-line

- `stack` holds `{price, span}` pairs in decreasing price order.
- For a new price: start span = 1. Pop all entries with price ≤ current, accumulating their spans.
- Push `{price, span}`. Return span.
- Each entry pushed and popped at most once → amortized O(1) per call.

## Complexity

- Time: O(1) amortized per call (O(n) worst case for a single call, but O(1) amortized over all calls).
- Space: O(n) — stack holds up to n entries.

## Common Mistakes

- **Using `>` instead of `<=` in the while condition.** Pop when `stack.peek().price <= price` (equal prices count as part of the span). Using `<` would miss equal prices.
- **Not accumulating spans.** Just popping gives the count of popped elements, not the total span. You need `span += popped.span`.
- **Storing only prices, not spans.** You need both to compute the span efficiently.

## How to Explain (interview)

**Opening:** Online Stock Span returns the number of consecutive days with price ≤ today's. Monotonic stack (decreasing) of (price, span) pairs. For a new price, pop all entries with price ≤ current, accumulating spans. Push (price, 1 + accumulated). Amortized O(1) per call.

**The basic flow:**
```java
int span = 1;
while (!stack.isEmpty() && stack.peek()[0] <= price) {
    span += stack.pop()[1];
}
stack.push(new int[]{price, span});
return span;
```

**The part that trips everyone up:** the while condition is `<=` (equal prices count). And you must accumulate spans (`span += popped.span`), not just count popped entries.

**The mistakes to remember:**
- Using `<` instead of `<=` (misses equal prices)
- Not accumulating spans (returns count, not span)
- Storing only prices (can't compute span efficiently)
