# 9.14 Car Fleet

**Tier 2 problem.** (LeetCode #853)

**Problem:** Cars on a one-lane road. Each car has a position and speed. A faster car behind a slower one forms a fleet (they travel together at the slower speed). Return the number of fleets that arrive at the target. (LeetCode #853)

**Link:** https://leetcode.com/problems/car-fleet/

---

## Which Technique, and Why?

"Car fleet" → **Sort by position (descending) + monotonic stack**. Process cars from closest to target to farthest. Track arrival times. If a car's arrival time ≤ the car in front's, it joins that fleet (pop). Otherwise, it forms a new fleet. O(n log n) time (sorting), O(n) space.

**Signal in the problem:** "car fleet" / "faster car behind slower" / "travel together" → sort by position descending + monotonic stack on arrival times.

## Approach

Sort cars by position (descending — closest to target first). For each car, compute arrival time = (target - position) / speed. Maintain a stack of arrival times (decreasing). If current car's time ≤ stack top's time, it joins the fleet (pop). Else, push (new fleet). The stack size = number of fleets.

## Pseudocode

```
cars = sort by position (descending)
stack = empty
for each car:
    time = (target - position) / speed
    while stack not empty and time <= stack.peek():
        stack.pop()  // joins the fleet
    stack.push(time)
return stack.size()
```

## Java Code

```java
class Solution {
    public int carFleet(int target, int[][] position, int[] speed) {
        int n = position.length;
        // sort by position descending
        Integer[] indices = new Integer[n];
        for (int i = 0; i < n; i++) indices[i] = i;
        Arrays.sort(indices, (a, b) -> Integer.compare(position[b][0], position[a][0]));

        Deque<Double> stack = new ArrayDeque<>();
        for (int idx : indices) {
            double time = (double) (target - position[idx][0]) / speed[idx];
            while (!stack.isEmpty() && time <= stack.peek()) {
                stack.pop();  // joins the fleet ahead
            }
            stack.push(time);
        }
        return stack.size();
    }
}
```

## Line-by-line

- `indices` — sort car indices by position (descending). We sort indices to avoid modifying the input.
- `time = (target - position) / speed` — arrival time at target.
- `while (!stack.isEmpty() && time <= stack.peek())` — if current car arrives no later than the car in front, it joins that fleet (pop). It can't overtake.
- `stack.push(time)` — new fleet (or the merged fleet's time, which is the front car's time).
- `stack.size()` = number of fleets.

## Complexity

- Time: O(n log n) — sorting dominates.
- Space: O(n) — stack.

## Common Mistakes

- **Sorting ascending instead of descending.** Process from closest to target to farthest. Ascending would process farthest first, breaking the logic.
- **Using integer division.** `(target - position) / speed` can lose precision. Use `double` or compare cross-multiplied. For this problem, double is fine (constraints are small).
- **Not popping when time <= stack top.** If current arrives no later than the front car, it joins. Using `<` instead of `<=` would create separate fleets for equal arrival times.
- **Modifying the input arrays.** Sort indices instead to avoid mutating input.

## How to Explain (interview)

**Opening:** Car Fleet counts fleets arriving at a target. Sort cars by position (descending — closest first). Compute arrival time for each. Use a monotonic stack of arrival times: if current car's time ≤ stack top's time, it joins that fleet (pop). Otherwise, push (new fleet). Stack size = number of fleets. O(n log n) time, O(n) space.

**The basic flow:**
```java
// sort by position descending
for each car (closest to farthest):
    time = (target - pos) / speed
    while (!stack.isEmpty() && time <= stack.peek()) stack.pop();
    stack.push(time);
return stack.size();
```

**The part that trips everyone up:** process **closest to target first** (descending position). Also, `time <= stack.peek()` (not `<`) — equal arrival times mean joining the fleet.

**The mistakes to remember:**
- Sorting ascending (wrong order)
- Using `<` instead of `<=` (equal times should join)
- Integer division (precision loss)
- Modifying input arrays (sort indices instead)
