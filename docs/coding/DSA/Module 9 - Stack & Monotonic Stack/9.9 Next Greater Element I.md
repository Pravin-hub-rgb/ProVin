**Problem:** Given two arrays `nums1` and `nums2` (nums1 is a subset of nums2), for each element in nums1 find the next greater element in nums2 (the first element to its right that is greater). Return -1 if none. (LeetCode #496)

**Link:** https://leetcode.com/problems/next-greater-element-i/

---

## Which Technique, and Why?

"Next greater element" for each element → **Monotonic Stack (decreasing)**. Process nums2 left to right; maintain a stack of indices (or values) whose next greater hasn't been found. When a larger element arrives, it's the "next greater" for all smaller elements on the stack.

Why process nums2 and not nums1? Because the "next greater" is defined relative to nums2's order. Then map results to nums1.

**Signal in the problem:** "next greater element" → monotonic stack (decreasing). "For each element in nums1" → build a map from nums2, then look up.

## Approach

1. Walk through nums2 with a monotonic decreasing stack.
2. When nums2[i] is greater than the stack top, it's the next greater for that element → record in a map (value → next greater).
3. For each element in nums1, look up the map (default -1).

## Pseudocode

```
map = empty (value -> next greater)
stack = empty
for x in nums2:
    while stack not empty and stack.peek() < x:
        map[stack.pop()] = x
    stack.push(x)
// elements left in stack have no next greater (default -1)
for each x in nums1:
    result.add(map.getOrDefault(x, -1))
```

## Java Code

```java
class Solution {
    public int[] nextGreaterElement(int[] nums1, int[] nums2) {
        Map<Integer, Integer> nextGreater = new HashMap<>();
        Deque<Integer> stack = new ArrayDeque<>();

        for (int x : nums2) {
            while (!stack.isEmpty() && stack.peek() < x) {
                nextGreater.put(stack.pop(), x);
            }
            stack.push(x);
        }

        int[] result = new int[nums1.length];
        for (int i = 0; i < nums1.length; i++) {
            result[i] = nextGreater.getOrDefault(nums1[i], -1);
        }
        return result;
    }
}
```

## Line-by-line

- `stack` holds values (not indices this time — we only need the value, not the position). It's monotonic decreasing.
- For each `x` in nums2: while stack top < x, pop it and map it to x (x is its next greater). Then push x.
- Elements remaining in the stack have no next greater → map doesn't contain them → `getOrDefault` returns -1.
- For nums1, look up each value in the map.

## Complexity

- Time: O(n + m) where n = nums1.length, m = nums2.length. Each element pushed/popped at most once.
- Space: O(m) — stack and map.

## Common Mistakes

- **Storing indices instead of values.** Here we only need the value (next greater), not the distance. Storing values is simpler. (For Daily Temperatures, we needed indices for distance.)
- **Using `>` instead of `<` in the while condition.** We pop when stack top < current (current is greater). Using `>` would find next *smaller*.
- **Not handling "no next greater."** Elements left in the stack have no next greater → return -1. `getOrDefault(x, -1)` handles this.
- **Assuming nums1 is sorted.** nums1 is a subset of nums2 but not necessarily sorted. Process nums2 in its given order.

## How to Explain (interview)

**Opening:** Next Greater Element I finds, for each element in nums1, the first greater element to its right in nums2. Monotonic stack (decreasing) on nums2: when a larger element arrives, it's the "next greater" for all smaller elements on the stack. Store results in a map, then look up nums1. O(n + m) time, O(m) space. Elements with no greater value return -1.

**The basic flow:**
```java
Deque<Integer> stack = new ArrayDeque<>();
Map<Integer, Integer> nextGreater = new HashMap<>();
for (int x : nums2) {
    while (!stack.isEmpty() && stack.peek() < x) nextGreater.put(stack.pop(), x);
    stack.push(x);
}
```

**The part that trips everyone up:** store **values** (not indices) here — we only need the next greater value, not the distance. Also, the while condition is `stack.peek() < x` (current is greater), not `>`.

**The mistakes to remember:**
- Storing indices when values suffice (or vice versa)
- Wrong comparison direction (`<` vs `>`)
- Forgetting elements with no next greater (return -1)
- Assuming nums1 is sorted (it's a subset, not necessarily sorted)
