**Problem:** Design a stack that supports push, pop, top, and retrieving the minimum element — all in O(1) time. (LeetCode #155)

**Link:** https://leetcode.com/problems/min-stack/

---

## Which Technique, and Why?

You need O(1) min retrieval alongside normal stack operations. The trick: maintain a **second stack** (or a single stack of pairs) that tracks the running minimum. Every push also pushes the current min; every pop also pops the min. O(1) for all operations, O(n) space.

Why not scan for min on each query? That's O(n) per query — too slow. The running-min stack gives O(1).

**Signal in the problem:** "stack with O(1) min" / "retrieve minimum in constant time" → auxiliary min stack.

## Approach

Maintain two stacks: `main` (values) and `minStack` (running minimums). On push: push to main, and push `min(val, minStack.peek())` to minStack (or val if empty). On pop: pop both. `getMin()` returns `minStack.peek()`.

Alternative: single stack storing pairs `{value, currentMin}`.

## Pseudocode

```
push(val):
    main.push(val)
    if minStack empty or val <= minStack.peek(): minStack.push(val)
    // (or always push min(val, minStack.peek()))

pop():
    main.pop()
    minStack.pop()

top(): return main.peek()
getMin(): return minStack.peek()
```

## Java Code

```java
class MinStack {
    private Deque<Integer> main = new ArrayDeque<>();
    private Deque<Integer> minStack = new ArrayDeque<>();

    public void push(int val) {
        main.push(val);
        if (minStack.isEmpty() || val <= minStack.peek()) {
            minStack.push(val);
        }
    }

    public void pop() {
        int val = main.pop();
        if (val == minStack.peek()) {
            minStack.pop();
        }
    }

    public int top() {
        return main.peek();
    }

    public int getMin() {
        return minStack.peek();
    }
}
```

## Line-by-line

- `main` holds all values (normal stack behavior).
- `minStack` holds the running minimum. We only push to it when `val <= current min` (so it stays monotonic non-increasing).
- `pop`: pop from main; if the popped value equals the current min, pop from minStack too. (Using `<=` on push and `==` on pop keeps them in sync even with duplicates.)
- `getMin`: peek minStack — O(1).

## Complexity

- Time: O(1) for push, pop, top, getMin.
- Space: O(n) — two stacks (minStack can be up to n in worst case, e.g., decreasing input).

## Common Mistakes

- **Pushing to minStack on every push.** Works but uses more space. Push only when `val <= min` to keep minStack smaller. (Either is O(n) worst case.)
- **Using `==` comparison with duplicates.** If you push `5, 5, 3`, minStack = [5, 5, 3] (with `<=`). On pop of 5, `val == minStack.peek()` (5 == 5) → pop minStack → [5, 3]. Correct. If you used `<` on push, minStack = [5, 3], and popping the second 5 wouldn't pop minStack → desync. Use `<=` on push and `==` on pop.
- **Not handling empty stack.** `top()` and `getMin()` assume non-empty. The problem guarantees they're called on non-empty stacks.
- **Single stack with pairs.** Alternative: store `{value, min}` pairs in one stack. Simpler but slightly more memory per node.

## How to Explain (interview)

**Opening:** Min Stack supports push, pop, top, and getMin all in O(1). Use an auxiliary min stack that tracks the running minimum: on push, push to main and (if val ≤ current min) push to minStack. On pop, pop both if the popped value equals the current min. getMin peeks minStack. O(1) all operations, O(n) space.

**The basic flow:**
```java
Deque<Integer> main = new ArrayDeque<>(), min = new ArrayDeque<>();
void push(int val) { main.push(val); if (min.isEmpty() || val <= min.peek()) min.push(val); }
void pop() { int v = main.pop(); if (v == min.peek()) min.pop(); }
int getMin() { return min.peek(); }
```

**The part that trips everyone up:** the `<=` on push and `==` on pop. With duplicates, using `<` on push causes desync. Also, minStack can be up to n in size (worst case: decreasing input) — that's expected O(n) space.

**The mistakes to remember:**
- Using `<` instead of `<=` on push (desyncs with duplicates)
- Not handling empty stack in getMin/top
- Confusing single-stack-pairs vs two-stack approach (both work)
