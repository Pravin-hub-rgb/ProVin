# 9.4 Deque (ArrayDeque)

A Deque (Double-Ended Queue) allows insertion and removal at both ends. It can act as a stack (LIFO) or a queue (FIFO) — or both. In Java, `ArrayDeque` is the standard implementation.

---

## Declaration and Creation

```java
import java.util.ArrayDeque;
import java.util.Deque;

Deque<Integer> deque = new ArrayDeque<>();
```

## Core Operations

```java
Deque<Integer> d = new ArrayDeque<>();

// As a stack (LIFO) — operate on one end
d.push(10);              // add to front (top)
d.push(20);
System.out.println(d.peek());   // 20 (front)
System.out.println(d.pop());    // 20 (remove front)

// As a queue (FIFO) — operate on opposite ends
d.offer(10);             // add to back
d.offer(20);
System.out.println(d.peek());   // 10 (front)
System.out.println(d.poll());   // 10 (remove front)

// Deque-specific: operate on both ends
d.addFirst(5);           // add to front
d.addLast(15);           // add to back
System.out.println(d.removeFirst()); // 5
System.out.println(d.removeLast());  // 15
System.out.println(d.getFirst());    // look at front
System.out.println(d.getLast());    // look at back
```

**Method pairs (same operation, different names):**
| Operation | Stack-style | Queue-style | Deque-style |
|---|---|---|---|
| Add to front | `push` | — | `addFirst` / `offerFirst` |
| Add to back | — | `offer` | `addLast` / `offerLast` |
| Remove from front | `pop` | `poll` | `removeFirst` / `pollFirst` |
| Remove from back | — | — | `removeLast` / `pollLast` |
| Peek front | `peek` | `peek` | `getFirst` / `peekFirst` |
| Peek back | — | — | `getLast` / `peekLast` |

All operations are O(1) amortized.

## When to Use

- **Sliding window maximum** — monotonic deque (keep indices, maintain decreasing values).
- **When you need both stack and queue operations** — e.g., a deque can be used as a stack with `push`/`pop` or as a queue with `offer`/`poll`.
- **Palindromic checks** — compare from both ends.
- **BFS with priority** — sometimes a deque is used as a 0-1 BFS queue.

## Common Pitfalls

- **Mixing stack and queue methods on the same instance.** If you `push` (front) and then `poll` (front), you're removing what you just pushed — LIFO, not FIFO. Pick one usage per instance. Mixing causes bugs.
- **Null returns.** `poll`/`peek` return null on empty; `remove`/`getFirst` throw. Use the null-returning versions in DSA.
- **Not thread-safe.** `ArrayDeque` is not synchronized. Use `ConcurrentLinkedDeque` for concurrent access (rare in DSA).
- **Capacity.** `ArrayDeque` grows dynamically; no fixed capacity. `offer` always succeeds.

## A Small Program: Sliding Window Maximum

```java
import java.util.*;

public class SlidingWindowMax {
    static int[] maxSlidingWindow(int[] nums, int k) {
        Deque<Integer> deque = new ArrayDeque<>(); // indices, decreasing values
        int[] result = new int[nums.length - k + 1];
        int idx = 0;

        for (int i = 0; i < nums.length; i++) {
            // Remove indices outside the window
            while (!deque.isEmpty() && deque.peekFirst() < i - k + 1) {
                deque.pollFirst();
            }
            // Remove indices whose values are <= current (maintain decreasing)
            while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[i]) {
                deque.pollLast();
            }
            deque.offerLast(i);

            if (i >= k - 1) {
                result[idx++] = nums[deque.peekFirst()];
            }
        }
        return result;
    }

    public static void main(String[] args) {
        int[] nums = {1, 3, -1, -3, 5, 3, 6, 7};
        System.out.println(Arrays.toString(maxSlidingWindow(nums, 3)));
        // [3, 3, 5, 5, 6, 7]
    }
}
```

## In Your Own Words

1. What is a deque, and how can it act as both a stack and a queue?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A deque (double-ended queue) allows insertion and removal at both ends. As a stack (LIFO): use one end — `push`/`pop`/`peek` on the front. As a queue (FIFO): use opposite ends — `offer` (back) and `poll` (front). The same `ArrayDeque` class serves both; just use different method sets. Pick one usage per instance to avoid confusion.

</details>

2. How does a monotonic deque solve the sliding window maximum problem?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Maintain a deque of indices with decreasing values. For each new element: remove indices outside the window (front), remove indices whose values are ≤ current (back, to maintain decreasing order), then add current index. The front always holds the maximum for the current window. Each element is added and removed at most once → O(n) total.

</details>

3. Why prefer ArrayDeque over LinkedList for a deque?

<details>
<summary>Show Answer</summary>

**Sample Answer:** ArrayDeque is array-backed — no node allocation, better cache locality, faster. LinkedList allocates a node per element and has worse cache performance. Use ArrayDeque for all stack/queue/deque needs in DSA. Use LinkedList only if you need List features (indexing, etc.).

</details>
