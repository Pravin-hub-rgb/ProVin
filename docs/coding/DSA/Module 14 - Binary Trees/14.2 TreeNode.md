# 14.2 TreeNode

A TreeNode is the node of a binary tree. Each node holds a value and pointers to its left and right children (or null if absent). This is the building block for all tree problems.

---

## The Node

```java
class TreeNode {
    int val;
    TreeNode left;
    TreeNode right;

    TreeNode(int val) {
        this.val = val;
        this.left = null;
        this.right = null;
    }
}
```

- `val` holds the data.
- `left` points to the left child (or `null`).
- `right` points to the right child (or `null`).

## Building a Tree

```java
// Manual construction
TreeNode root = new TreeNode(1);
root.left = new TreeNode(2);
root.right = new TreeNode(3);
root.left.left = new TreeNode(4);
root.left.right = new TreeNode(5);
// Tree:
//       1
//      / \
//     2   3
//    / \
//   4   5
```

In LeetCode, trees are given as `TreeNode root` (pre-built). You rarely construct them yourself. But knowing the shape helps you debug.

## Traversals

### Preorder (root → left → right)

```java
void preorder(TreeNode node) {
    if (node == null) return;
    System.out.print(node.val + " ");  // process root
    preorder(node.left);               // left
    preorder(node.right);              // right
}
// Output for above tree: 1 2 4 5 3
```

### Inorder (left → root → right)

```java
void inorder(TreeNode node) {
    if (node == null) return;
    inorder(node.left);                // left
    System.out.print(node.val + " ");  // process root
    inorder(node.right);               // right
}
// Output: 4 2 5 1 3  (sorted for BST)
```

### Postorder (left → right → root)

```java
void postorder(TreeNode node) {
    if (node == null) return;
    postorder(node.left);              // left
    postorder(node.right);             // right
    System.out.print(node.val + " ");  // process root
}
// Output: 4 5 2 3 1
```

### Level Order (BFS)

```java
void levelOrder(TreeNode root) {
    if (root == null) return;
    Queue<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        TreeNode node = q.poll();
        System.out.print(node.val + " ");
        if (node.left != null) q.offer(node.left);
        if (node.right != null) q.offer(node.right);
    }
}
// Output: 1 2 3 4 5
```

## Cost (Big-O)

| Operation | Time | Space |
|---|---|---|
| Access any node | O(n) (must traverse) | — |
| DFS traversal | O(n) | O(h) (recursion stack) |
| BFS traversal | O(n) | O(n) (queue, worst case) |
| Insert (as child) | O(1) (if parent known) | — |

h = height of tree. For a balanced tree, h = O(log n). For a skewed tree, h = O(n).

## Common Pitfalls

- **Null checks.** Always check `node == null` before accessing `node.left`/`node.right`/`node.val`.
- **Stack overflow on skewed trees.** A tree of depth 10⁵ (essentially a linked list) causes `StackOverflowError` with recursion. Use iterative DFS/BFS.
- **Confusing DFS and BFS.** DFS goes deep first (recursion/stack). BFS goes level by level (queue). The problem statement usually hints which one.
- **Modifying the tree.** Some problems (e.g., invert tree) expect in-place modification. Others expect a new tree. Read the problem.
- **Off-by-one in depth/height.** Depth of root = 1 (or 0, depending on convention). Height of leaf = 0 (or 1). Be consistent with the problem's expected answer.

## In Your Own Words

1. What are the three DFS traversal orders, and what distinguishes them?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Preorder: root → left → right (process node first). Inorder: left → root → right (process node in the middle — gives sorted order for BST). Postorder: left → right → root (process node last — used for height, diameter, deletion). The difference is when you process the current node relative to its children.

</details>

2. When should you use BFS (level-order) instead of DFS?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use BFS when the problem involves levels (e.g., "level order traversal," "zigzag," "right side view," "minimum depth"). BFS processes level by level using a queue. DFS is simpler for "is there a path," "max depth," "path sum." Both are O(n) time; BFS uses O(n) space (queue), DFS uses O(h) space (recursion stack).

</details>

3. Why can deep recursion on a skewed tree cause StackOverflowError?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Each recursive call pushes a frame onto the call stack. A skewed tree of depth 10⁵ means 10⁵ recursive calls → stack overflow. The JVM's default stack size is limited (~512KB–1MB). For deep trees, use iterative DFS (explicit stack) or BFS (queue). Balanced trees (depth ~log n) are fine with recursion.

</details>
