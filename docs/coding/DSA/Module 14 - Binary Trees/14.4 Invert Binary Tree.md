# 14.4 Invert Binary Tree

**Problem:** Given the root of a binary tree, invert it (mirror it) and return the root. (LeetCode #226)

**Link:** https://leetcode.com/problems/invert-binary-tree/

---

## Which Technique, and Why?

Invert (mirror) a binary tree → **DFS (post-order or pre-order)**. Swap left and right children recursively. O(n) time, O(h) space.

**Signal in the problem:** "invert" / "mirror" / "flip" a binary tree → swap left and right recursively.

## Approach

Base case: `root == null` → return null. Recursively invert left and right subtrees. Swap `root.left` and `root.right`. Return root.

## Pseudocode

```
if root == null: return null
left = invert(root.left)
right = invert(root.right)
root.left = right
root.right = left
return root
```

## Java Code

```java
class Solution {
    public TreeNode invertTree(TreeNode root) {
        if (root == null) return null;
        TreeNode left = invertTree(root.left);
        TreeNode right = invertTree(root.right);
        root.left = right;
        root.right = left;
        return root;
    }
}
```

## Line-by-line

- `root == null` → return null (base case).
- Recursively invert left and right subtrees.
- Swap: `root.left = right`, `root.right = left`.
- Return root (modified in place).

## Complexity

- Time: O(n) — visit every node once.
- Space: O(h) — recursion stack.

## Common Mistakes

- **Not handling null.** `root == null` → return null.
- **Swapping before recursing.** If you swap first, then recurse on `root.left` (which is now the old right), you'd double-invert. Recurse first, then swap (or swap then recurse on the new children — but be careful). The code above recurses first, then swaps — safe.
- **Returning the wrong node.** Return `root`, not `left` or `right`.
- **Modifying when not allowed.** This problem expects in-place modification. If a problem says "don't modify," build a new tree instead.
