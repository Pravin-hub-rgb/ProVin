# 14.8 Balanced Binary Tree

**Problem:** Given a binary tree, determine if it is height-balanced (for every node, the height difference between left and right subtrees is at most 1). (LeetCode #110)

**Link:** https://leetcode.com/problems/balanced-binary-tree/

---

## Which Technique, and Why?

Check if a tree is height-balanced → **DFS with early termination**. Compute height of left and right subtrees; if the difference > 1, unbalanced. O(n) time, O(h) space. Naive approach (compute height for each node separately) is O(n²).

**Signal in the problem:** "balanced binary tree" / "height difference ≤ 1" → DFS, check height difference at every node.

## Approach

DFS that returns height. At each node: compute left height and right height. If either is -1 (unbalanced) or `|left - right| > 1`, return -1 (unbalanced). Otherwise return `max(left, right) + 1`.

## Pseudocode

```
check(node):
    if node == null: return 0
    left = check(node.left)
    if left == -1: return -1
    right = check(node.right)
    if right == -1: return -1
    if abs(left - right) > 1: return -1
    return max(left, right) + 1
```

## Java Code

```java
class Solution {
    public boolean isBalanced(TreeNode root) {
        return checkHeight(root) != -1;
    }

    private int checkHeight(TreeNode node) {
        if (node == null) return 0;
        int left = checkHeight(node.left);
        if (left == -1) return -1;
        int right = checkHeight(node.right);
        if (right == -1) return -1;
        if (Math.abs(left - right) > 1) return -1;
        return Math.max(left, right) + 1;
    }
}
```

## Line-by-line

- `checkHeight` returns the height, or -1 if unbalanced (early termination).
- Base case: `null → 0`.
- Compute left height; if -1, propagate unbalanced up.
- Compute right height; if -1, propagate.
- If `|left - right| > 1`, unbalanced → return -1.
- Otherwise return `max(left, right) + 1`.

## Complexity

- Time: O(n) — single pass, early termination on first unbalanced node.
- Space: O(h) — recursion stack.

## Common Mistakes

- **Naive O(n²) approach.** Computing height separately for each node is O(n²). The single-pass approach (returning -1 on unbalanced) is O(n).
- **Not early-terminating.** Once a subtree is unbalanced, stop — don't compute the rest. The `-1` propagation handles this.
- **Off-by-one in height.** A single node has height 1 (or 0, depending on convention). This solution uses 1 (leaf = 1). Consistent with maxDepth.
- **Confusing balanced with complete.** Balanced = height difference ≤ 1 at every node. Complete = all levels full except possibly the last, filled left to right. Different properties.

## How to Explain (interview)

**Opening:** Balanced Binary Tree checks if every node has left/right height difference ≤ 1. Single-pass DFS: compute height, return -1 if unbalanced (early termination). O(n) time, O(h) space. The -1 propagation stops computation as soon as an imbalance is found.

**The basic flow:**
```java
int checkHeight(TreeNode node) {
    if (node == null) return 0;
    int left = checkHeight(node.left);
    if (left == -1) return -1;
    int right = checkHeight(node.right);
    if (right == -1) return -1;
    if (Math.abs(left - right) > 1) return -1;
    return Math.max(left, right) + 1;
}
```

**The part that trips everyone up:** use -1 as a sentinel for "unbalanced" and propagate it up. This gives O(n) (early termination) instead of O(n²) (computing height separately for each node).

**The mistakes to remember:**
- O(n²) naive approach (compute height per node)
- Not early-terminating (wasted work)
- Height convention (single node = 1 or 0?)
- Confusing balanced with complete/full tree
