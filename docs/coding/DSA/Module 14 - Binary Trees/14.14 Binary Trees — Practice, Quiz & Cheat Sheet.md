## Mini Quiz

1. What is the recursive template for most binary tree problems?
2. What is the difference between preorder, inorder, and postorder?
3. Why does the diameter problem need to check every node, not just the root?
4. How does the balanced tree check achieve O(n) instead of O(n²)?
5. What's the difference between DFS and BFS in terms of space complexity?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. Base case (null → return base value), recurse on left, recurse on right, combine. E.g., depth = max(left, right) + 1. This template applies to height, diameter, path sum, and most tree problems.
2. Preorder: root → left → right (process node first). Inorder: left → root → right (process in middle — sorted for BST). Postorder: left → right → root (process node last — used for height, diameter, deletion). The difference is when you process the current node relative to children.
3. The diameter is the longest path between any two nodes, which may not pass through the root. At each node, the longest path through it = height(left) + height(right). You must check every node and track the max. Only checking the root misses paths in subtrees.
4. Naive: compute height separately for each node → O(n²) (each height computation is O(n), done for n nodes). Optimized: single pass that returns height and -1 (unbalanced) — early termination stops as soon as an imbalance is found. O(n) worst case.
5. DFS: O(h) space (recursion stack, h = height). For balanced trees, O(log n); for skewed, O(n). BFS: O(n) space (queue holds up to one level, worst case n/2 for a complete tree's last level). DFS is more space-efficient for balanced trees.

</details>

## One-Page Cheat Sheet

**Recursive template:**
```java
int solve(TreeNode root) {
    if (root == null) return 0;       // base case
    int left = solve(root.left);       // recurse
    int right = solve(root.right);
    return combine(root.val, left, right); // combine
}
```

**DFS traversals:**
```java
// Preorder: root, left, right
void preorder(TreeNode node) {
    if (node == null) return;
    visit(node); preorder(node.left); preorder(node.right);
}
// Inorder: left, root, right
void inorder(TreeNode node) {
    if (node == null) return;
    inorder(node.left); visit(node); inorder(node.right);
}
// Postorder: left, right, root
void postorder(TreeNode node) {
    if (node == null) return;
    postorder(node.left); postorder(node.right); visit(node);
}
```

**BFS (level order):**
```java
Queue<TreeNode> q = new ArrayDeque<>();
q.offer(root);
while (!q.isEmpty()) {
    int size = q.size();
    for (int i = 0; i < size; i++) {
        TreeNode node = q.poll();
        // process node
        if (node.left != null) q.offer(node.left);
        if (node.right != null) q.offer(node.right);
    }
}
```

**Key patterns:**
- Height/depth: `max(left, right) + 1`
- Diameter: `max(diameter, left + right)` at each node
- Balanced: return -1 if `|left - right| > 1`, propagate
- Symmetric: cross-compare `left.left` with `right.right`
- Invert: swap left and right after recursing

## In Your Own Words

1. Why is the recursive template (base case → recurse → combine) so common in tree problems?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Because a binary tree is a recursive structure — each node has left and right subtrees that are themselves trees. The problem on a tree decomposes into the same problem on the left subtree + the same problem on the right subtree + combining results at the current node. The base case (null) handles empty subtrees. This divide-and-conquer pattern covers depth, diameter, path sum, inversion, and most tree problems.

</details>

2. What's the difference between height and depth?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Depth is the distance from the root to a node (root has depth 0 or 1). Height is the distance from a node to its deepest leaf (leaf has height 0 or 1). For the whole tree, "height of the tree" = height of the root = maximum depth of any leaf. Conventions vary (some use 0-based, some 1-based). LeetCode typically uses 1-based for both. Be consistent with the problem's expected answer.

</details>

3. When should you use BFS instead of DFS for a tree problem?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use BFS (level-order) when the problem involves levels: "level order traversal," "zigzag," "right side view," "minimum depth" (shortest path to a leaf). BFS processes level by level. Use DFS for "is there a path," "max depth," "path sum," "diameter" — anything that doesn't need level-by-level processing. DFS is more space-efficient (O(h) vs O(n)).

</details>
