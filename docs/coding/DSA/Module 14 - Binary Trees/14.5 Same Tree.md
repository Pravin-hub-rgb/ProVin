**Problem:** Given two binary trees, check if they are structurally identical and have the same values. (LeetCode #100)

**Link:** https://leetcode.com/problems/same-tree/

---

## Which Technique, and Why?

Compare two trees for equality → **DFS (simultaneous recursion)**. Check: both null → true; one null → false; values differ → false; then recurse on left and right. O(n) time, O(h) space.

**Signal in the problem:** "same tree" / "identical trees" → simultaneous DFS on both.

## Approach

Base cases: both null → true; one null → false; values differ → false. Recurse: `isSameTree(p.left, q.left) && isSameTree(p.right, q.right)`.

## Pseudocode

```
if p == null and q == null: return true
if p == null or q == null: return false
if p.val != q.val: return false
return isSameTree(p.left, q.left) && isSameTree(p.right, q.right)
```

## Java Code

```java
class Solution {
    public boolean isSameTree(TreeNode p, TreeNode q) {
        if (p == null && q == null) return true;
        if (p == null || q == null) return false;
        if (p.val != q.val) return false;
        return isSameTree(p.left, q.left) && isSameTree(p.right, q.right);
    }
}
```

## Line-by-line

- Both null → true (empty trees are identical).
- One null, other not → false (different structure).
- Values differ → false.
- Recurse on both left and right; both must be identical.

## Complexity

- Time: O(n) — visit every node (early exit on mismatch).
- Space: O(h) — recursion stack.

## Common Mistakes

- **Not checking both-null first.** If both are null, `p.val` would NPE. Check null cases first.
- **Using `==` for TreeNode comparison.** Compare values (`p.val == q.val`), not references.
- **Not short-circuiting.** `&&` short-circuits: if left is false, right isn't evaluated. Good.

## How to Explain (interview)

**Opening:** Same Tree checks if two trees are structurally identical with the same values. Simultaneous DFS: both null → true; one null → false; values differ → false; then recurse on left and right (both must match). O(n) time, O(h) space.

**The basic flow:**
```java
if (p == null && q == null) return true;
if (p == null || q == null) return false;
if (p.val != q.val) return false;
return isSameTree(p.left, q.left) && isSameTree(p.right, q.right);
```

**The part that trips everyone up:** check null cases **before** accessing `.val`. Both-null → true (empty trees identical). One-null → false.

**The mistakes to remember:**
- Accessing `.val` before null check (NPE)
- Comparing references instead of values
- Not short-circuiting (wasted work)
