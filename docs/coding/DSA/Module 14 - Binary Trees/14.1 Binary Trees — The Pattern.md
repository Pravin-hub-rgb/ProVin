## The Core Idea

A **binary tree** is a recursive structure: each node has at most two children (left and right). The empty tree (null) is the base case. Most tree problems follow this template:

```
solve(node):
    if node == null: return base value
    leftResult = solve(node.left)
    rightResult = solve(node.right)
    return combine(node.val, leftResult, rightResult)
```

**DFS traversals** (depth-first, recursive or iterative):
- **Preorder:** root → left → right (process node before children).
- **Inorder:** left → root → right (gives sorted order for BST).
- **Postorder:** left → right → root (process children before node — used for height, diameter, etc.).

**BFS (level-order):** process level by level using a queue. Used for "level order traversal," "zigzag," "right side view."

## Worked Example: Maximum Depth of Binary Tree

**Problem:** Find the maximum depth (height) of a binary tree.

### Brute force

BFS level by level, count levels. O(n) time, O(n) space.

### Optimized (DFS, O(n) time, O(h) space)

```java
class Solution {
    public int maxDepth(TreeNode root) {
        if (root == null) return 0;          // base case
        int left = maxDepth(root.left);       // solve left subtree
        int right = maxDepth(root.right);     // solve right subtree
        return Math.max(left, right) + 1;    // combine
    }
}
```

**Line-by-line:**
- `root == null` → depth 0 (base case).
- Recursively compute depth of left and right subtrees.
- Return `max(left, right) + 1` — the deeper subtree plus this node.

**Key insight:** the recursive template: base case (null) → recurse on children → combine. This is the foundation of all tree problems.

## Common Mistakes

- **Not handling null.** `root == null` is the base case for almost every tree problem. Forgetting it → NPE.
- **Confusing depth and height.** Depth = distance from root. Height = distance to deepest leaf. For a single node, depth = 1, height = 0 (or 1, depending on convention). Be consistent.
- **Modifying the tree.** Some problems allow in-place modification (e.g., invert tree). If not allowed, don't mutate.
- **Stack overflow on skewed trees.** A skewed tree of depth 10⁵ causes StackOverflowError with recursion. Use iterative DFS/BFS for deep trees.
- **Off-by-one in path sum.** `sum - root.val` vs `sum == root.val` at leaf. Check the problem's definition of "path" (root to leaf).

## How to Explain (interview)

**Opening:** Binary trees are recursive structures — each node has left and right children. Most tree problems follow: base case (null) → recurse on left → recurse on right → combine. DFS (pre/in/post-order) and BFS (level-order) are the two traversal strategies. O(n) time for most problems, O(h) space for DFS (h = height), O(n) for BFS.

**The basic flow (DFS):**
```java
int solve(TreeNode root) {
    if (root == null) return 0;        // base case
    int left = solve(root.left);       // recurse
    int right = solve(root.right);
    return combine(root.val, left, right); // combine
}
```

**The part that trips everyone up:** always handle `root == null` first. Also, distinguish depth (from root) vs height (to leaf) — conventions vary. For deep/skewed trees, recursion can stack-overflow; use iterative.

**The mistakes to remember:**
- Forgetting the null base case (NPE)
- Confusing depth and height
- Stack overflow on skewed trees (use iterative)
- Modifying the tree when not allowed
- Off-by-one in path sum (leaf check)
