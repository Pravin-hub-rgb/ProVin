## The Core Idea

A **topological sort** of a DAG is a linear ordering of vertices such that for every edge u?v, u comes before v. If the graph has a cycle, no topological sort exists.

**Two approaches:**
1. **Kahn's Algorithm (BFS):** compute in-degrees. Start with nodes of in-degree 0 (no prerequisites). Process them, decrement neighbors' in-degrees. When a neighbor's in-degree hits 0, add it to the queue. If you process all nodes, it's a DAG; otherwise, there's a cycle.
2. **DFS-based:** do a DFS; after exploring all neighbors of a node, push it to a stack (or add to result in reverse). The result is a topological order. Detect cycles with a "visiting" state (gray/white/black).

**Kahn's is usually simpler and also detects cycles naturally (count processed nodes).**

## Worked Example: Course Schedule (cycle detection)

**Problem:** Given numCourses and prerequisites [a, b] (b before a), can you finish all courses?

### Brute force

Try all orderings — exponential.

### Optimized (O(V + E)) — Kahn's algorithm

```java
class Solution {
    public boolean canFinish(int numCourses, int[][] prerequisites) {
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
        int[] inDegree = new int[numCourses];

        for (int[] pre : prerequisites) {
            adj.get(pre[1]).add(pre[0]);  // pre[1] -> pre[0]
            inDegree[pre[0]]++;
        }

        Queue<Integer> q = new ArrayDeque<>();
        for (int i = 0; i < numCourses; i++) {
            if (inDegree[i] == 0) q.offer(i);
        }

        int processed = 0;
        while (!q.isEmpty()) {
            int course = q.poll();
            processed++;
            for (int next : adj.get(course)) {
                if (--inDegree[next] == 0) q.offer(next);
            }
        }
        return processed == numCourses;  // if not all processed, there's a cycle
    }
}
```

**Line-by-line:**
- Build adjacency list: `pre[1] ? pre[0]` (prerequisite points to dependent).
- `inDegree[i]` = number of prerequisites for course i.
- Queue starts with courses having no prerequisites (in-degree 0).
- Process each course: decrement neighbors' in-degrees; if 0, they're ready.
- `processed == numCourses` ? no cycle ? can finish.

**Key insight:** if there's a cycle, some nodes never reach in-degree 0 ? they're never processed ? `processed < numCourses`.

## Common Mistakes

- **Wrong edge direction.** `[a, b]` means "b before a" (b is prerequisite). Edge: b ? a. Getting this backwards gives wrong in-degrees.
- **Not detecting cycles.** If `processed < numCourses`, there's a cycle. Don't forget to check.
- **Using DFS without cycle detection.** DFS-based topo sort needs a "visiting" state to detect back edges (cycles). Kahn's handles this naturally.
- **Modifying the in-degree array.** If you need the original later, copy it. Usually fine to modify.

## How to Explain (interview)

**Opening:** Topological Sort orders nodes in a DAG so prerequisites come first. Kahn's algorithm (BFS): compute in-degrees, start with in-degree-0 nodes, process and decrement neighbors. If all nodes processed ? valid order (DAG); else ? cycle. O(V + E) time, O(V + E) space. Also detects cycles.

**The basic flow (Kahn's):**
```java
Queue<Integer> q = new ArrayDeque<>();
for (int i = 0; i < n; i++) if (inDegree[i] == 0) q.offer(i);
int processed = 0;
while (!q.isEmpty()) {
    int node = q.poll();
    processed++;
    for (int next : adj.get(node))
        if (--inDegree[next] == 0) q.offer(next);
}
return processed == n;  // false ? cycle
```

**The part that trips everyone up:** edge direction. `[a, b]` means "b before a" ? edge b ? a. Also, `processed == n` is the cycle check — don't skip it.

**The mistakes to remember:**
- Wrong edge direction (b ? a, not a ? b)
- Not checking `processed == n` (misses cycle detection)
- Using DFS without cycle detection (back edges)
- Modifying in-degree array when you need the original
