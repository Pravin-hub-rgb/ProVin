# 19.2 Course Schedule

**Problem:** Given numCourses and prerequisites [a, b] (b before a), determine if you can finish all courses. (LeetCode #207)

**Link:** https://leetcode.com/problems/course-schedule/

---

## Which Technique, and Why?

"Can you finish all courses given prerequisites?" → **Topological Sort (Kahn's)**. Build a graph (prerequisite → dependent), compute in-degrees, process in-degree-0 nodes. If all processed → no cycle → can finish. O(V + E) time, O(V + E) space.

**Signal in the problem:** "prerequisites" / "can you finish" / "course schedule" → topological sort + cycle detection.

## Approach

Kahn's algorithm. Build adjacency list, compute in-degrees, BFS from in-degree-0 nodes. If processed count == numCourses → true (no cycle).

## Pseudocode

```
build adj: prereq -> course
inDegree[course]++ for each prerequisite
queue = all courses with inDegree == 0
processed = 0
while queue not empty:
    course = queue.poll()
    processed++
    for each next in adj[course]:
        if --inDegree[next] == 0: queue.offer(next)
return processed == numCourses
```

## Java Code

```java
class Solution {
    public boolean canFinish(int numCourses, int[][] prerequisites) {
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
        int[] inDegree = new int[numCourses];

        for (int[] pre : prerequisites) {
            adj.get(pre[1]).add(pre[0]);
            inDegree[pre[0]]++;
        }

        Queue<Integer> q = new ArrayDeque<>();
        for (int i = 0; i < numCourses; i++) {
            if (inDegree[i] == 0) q.offer(i);
        }

        int processed = 0;
        while (!q.isEmpty()) {
            int course = q.poll();
            processed++;
            for (int next : adj.get(course)) {
                if (--inDegree[next] == 0) q.offer(next);
            }
        }
        return processed == numCourses;
    }
}
```

## Line-by-line

- `adj.get(pre[1]).add(pre[0])` — prerequisite points to dependent (edge: pre[1] → pre[0]).
- `inDegree[pre[0]]++` — the dependent has one more prerequisite.
- Queue starts with courses that have no prerequisites.
- Process each course: for each dependent, decrement in-degree; if 0, it's ready.
- `processed == numCourses` → no cycle → can finish all.

## Complexity

- Time: O(V + E) where V = numCourses, E = prerequisites.length.
- Space: O(V + E) — adjacency list + in-degree array + queue.

## Common Mistakes

- **Wrong edge direction.** `[a, b]` means "b before a" → edge b → a. `adj.get(b).add(a)`, `inDegree[a]++`. Getting this backwards gives wrong in-degrees.
- **Not checking `processed == numCourses`.** This is the cycle detection. Without it, you'd return true even with a cycle.
- **Empty prerequisites.** `prerequisites = []` → all courses have in-degree 0 → all processed → true. Correct.
- **Duplicate prerequisites.** If the input has duplicates, in-degree is inflated. Problem usually guarantees no duplicates, but be careful.
