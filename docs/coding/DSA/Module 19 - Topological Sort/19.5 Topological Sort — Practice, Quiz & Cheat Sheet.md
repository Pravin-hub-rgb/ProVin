## Mini Quiz

1. What is a topological sort, and when does it not exist?
2. In Kahn's algorithm, what does `processed == n` check?
3. Why must you reverse the graph for Find Eventual Safe States?
4. What is the time complexity of Kahn's algorithm?
5. What is the difference between Kahn's (BFS) and DFS-based topological sort?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. A topological sort is a linear ordering of vertices in a DAG such that for every edge u→v, u comes before v. It doesn't exist if the graph has a cycle (no valid ordering).
2. `processed == n` checks whether all nodes were processed. If fewer than n were processed, some nodes never reached in-degree 0 → they're part of a cycle → no valid topological sort (can't finish all courses).
3. Kahn's algorithm needs in-degree-0 nodes to start. In the original graph, safe nodes aren't in-degree-0. In the reversed graph, terminal nodes (out-degree 0 in original) become in-degree-0. So you reverse the graph and run Kahn's from terminal nodes.
4. O(V + E) — each node and edge is processed once.
5. Kahn's (BFS): uses in-degrees, processes nodes in topological order, naturally detects cycles (processed < n). DFS-based: do DFS, push nodes to a stack after exploring all neighbors; reverse the stack for the order. Cycle detection requires a "visiting" state (gray/white/black). Kahn's is usually simpler.

</details>

## One-Page Cheat Sheet

**Kahn's algorithm (BFS topological sort):**
```java
List<List<Integer>> adj = new ArrayList<>();
int[] inDegree = new int[n];
// build adj + inDegree
Queue<Integer> q = new ArrayDeque<>();
for (int i = 0; i < n; i++) if (inDegree[i] == 0) q.offer(i);
int processed = 0;
List<Integer> order = new ArrayList<>();
while (!q.isEmpty()) {
    int node = q.poll();
    order.add(node);
    processed++;
    for (int next : adj.get(node))
        if (--inDegree[next] == 0) q.offer(next);
}
return processed == n;  // false → cycle
```

## In Your Own Words

1. What is a topological sort, and when does it not exist?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A topological sort is a linear ordering of vertices in a DAG such that for every edge u→v, u comes before v. It doesn't exist if the graph has a cycle — no valid ordering can satisfy all dependencies. Cycle detection is built into Kahn's algorithm: if `processed < n`, there's a cycle.

</details>

2. How does Kahn's algorithm detect cycles?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Kahn's processes nodes with in-degree 0. If there's a cycle, nodes in the cycle never reach in-degree 0 (they always have at least one incoming edge from within the cycle). So they're never processed → `processed < n`. This is the cycle check — no separate cycle detection needed.

</details>

3. Why reverse the graph for Find Eventual Safe States?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Kahn's needs in-degree-0 nodes to start. In the original graph, safe (terminal) nodes have out-degree 0, not in-degree 0. In the reversed graph, terminal nodes become in-degree 0 (their outgoing edges become incoming). So you reverse the graph and run Kahn's from terminal nodes. Nodes that are processed are safe; nodes in cycles are never processed.

</details>
