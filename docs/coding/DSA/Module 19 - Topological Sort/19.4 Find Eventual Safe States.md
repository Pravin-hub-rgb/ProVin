**Problem:** Given a directed graph, return all nodes that are "eventually safe" — nodes from which all paths eventually reach a terminal node (no outgoing edges). (LeetCode #802)

**Link:** https://leetcode.com/problems/find-eventual-safe-states/

---

## Which Technique, and Why?

"Eventual safe states" = nodes not in or leading to a cycle. A node is safe if all its paths reach a terminal node. This is equivalent to: in the reversed graph, find nodes reachable from terminal nodes. Or use topological sort (Kahn's) on the reversed graph: terminal nodes have out-degree 0 → in the reversed graph, they have in-degree 0 → start from them.

**Signal in the problem:** "eventual safe states" / "terminal nodes" / "all paths reach a terminal" → reverse graph + topological sort (Kahn's) OR DFS with 3-coloring.

## Approach (Reverse graph + Kahn's)

1. Build the reverse adjacency list (for each edge u→v, add v→u in reversed).
2. Compute out-degrees of original graph (= in-degrees of reversed graph).
3. Start Kahn's from nodes with out-degree 0 (terminal nodes) in the original graph.
4. Process: decrement out-degree of predecessors; when 0, they're safe → add to result.
5. Sort the result.

## Pseudocode

```
// Build reverse adj and out-degrees
for each node u:
    for each v in adj[u]:
        revAdj[v].add(u)
        outDegree[u]++

// Kahn's on reversed graph, starting from terminal nodes
queue = all nodes with outDegree == 0
safe = []
while queue not empty:
    node = queue.poll()
    safe.add(node)
    for each prev in revAdj[node]:
        if --outDegree[prev] == 0: queue.offer(prev)

sort safe
return safe
```

## Java Code

```java
class Solution {
    public List<Integer> eventualSafeNodes(int[][] graph) {
        int n = graph.length;
        List<List<Integer>> revAdj = new ArrayList<>();
        for (int i = 0; i < n; i++) revAdj.add(new ArrayList<>());
        int[] outDegree = new int[n];

        for (int u = 0; u < n; u++) {
            for (int v : graph[u]) {
                revAdj.get(v).add(u);  // reverse edge
                outDegree[u]++;
            }
        }

        Queue<Integer> q = new ArrayDeque<>();
        for (int i = 0; i < n; i++) {
            if (outDegree[i] == 0) q.offer(i);  // terminal nodes
        }

        List<Integer> safe = new ArrayList<>();
        while (!q.isEmpty()) {
            int node = q.poll();
            safe.add(node);
            for (int prev : revAdj.get(node)) {
                if (--outDegree[prev] == 0) q.offer(prev);
            }
        }

        Collections.sort(safe);
        return safe;
    }
}
```

## Line-by-line

- `revAdj` — reversed adjacency list. For edge u→v, we add v→u.
- `outDegree[u]` = number of outgoing edges from u in the original graph.
- Terminal nodes (out-degree 0) are safe — they go into the queue first.
- Process: for each safe node, look at its predecessors in the reversed graph. Decrement their out-degree. When it hits 0, all their paths lead to safe nodes → they're safe.
- Sort the result (problem asks for sorted order).

## Complexity

- Time: O(V + E) — building graph + Kahn's. Plus O(V log V) for sorting (can be avoided with a boolean array if needed).
- Space: O(V + E) — reversed adjacency list + out-degree array + queue.

## Common Mistakes

- **Using the original graph instead of the reversed graph.** Kahn's needs in-degree-0 nodes in the reversed graph (= out-degree-0 in original). Using the original graph gives wrong results.
- **Forgetting to sort the result.** The problem asks for nodes in ascending order.
- **Confusing with cycle detection.** Safe nodes are those NOT in or leading to a cycle. The Kahn's approach naturally excludes cycle nodes (they never reach out-degree 0).
- **DFS approach (3-coloring):** also works — mark nodes as 0 (unvisited), 1 (visiting), 2 (safe). A node is safe if all its neighbors are safe. More intuitive but recursive (stack overflow risk on deep graphs).
