**Problem:** Given numCourses and prerequisites, return a valid ordering of courses to finish all. If impossible (cycle), return empty array. (LeetCode #210)

**Link:** https://leetcode.com/problems/course-schedule-ii/

---

## Which Technique, and Why?

"Return a valid ordering" → **Topological Sort (Kahn's)**. Same as Course Schedule, but instead of just counting, record the order in which nodes are processed. O(V + E) time, O(V + E) space.

**Signal in the problem:** "return the order" / "find ordering" / "topological sort" → Kahn's, recording the order.

## Approach

Same as Course Schedule, but append each processed course to a result list. If the result has fewer than numCourses elements, there's a cycle → return empty array.

## Pseudocode

```
build adj + inDegree (same as #207)
queue = in-degree-0 nodes
order = []
while queue not empty:
    course = queue.poll()
    order.add(course)
    for each next in adj[course]:
        if --inDegree[next] == 0: queue.offer(next)
if order.size != numCourses: return []
return order
```

## Java Code

```java
class Solution {
    public int[] findOrder(int numCourses, int[][] prerequisites) {
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
        int[] inDegree = new int[numCourses];

        for (int[] pre : prerequisites) {
            adj.get(pre[1]).add(pre[0]);
            inDegree[pre[0]]++;
        }

        Queue<Integer> q = new ArrayDeque<>();
        for (int i = 0; i < numCourses; i++) {
            if (inDegree[i] == 0) q.offer(i);
        }

        int[] order = new int[numCourses];
        int idx = 0;
        while (!q.isEmpty()) {
            int course = q.poll();
            order[idx++] = course;
            for (int next : adj.get(course)) {
                if (--inDegree[next] == 0) q.offer(next);
            }
        }
        return idx == numCourses ? order : new int[]{};
    }
}
```

## Line-by-line

- Same setup as Course Schedule.
- `order[idx++] = course` — record the processing order.
- `idx == numCourses` — all courses processed → return order. Otherwise, cycle → return empty array.

## Complexity

- Time: O(V + E).
- Space: O(V + E).

## Common Mistakes

- **Same as Course Schedule:** wrong edge direction, not checking for cycle.
- **Returning partial order.** If `idx < numCourses`, there's a cycle — return empty array, not the partial order.
- **Using DFS-based topo sort.** Works but requires cycle detection (back edges). Kahn's is simpler and naturally detects cycles.
- **Not handling empty prerequisites.** All courses have in-degree 0 → all enqueued → returns 0, 1, 2, ..., n-1. Correct.
