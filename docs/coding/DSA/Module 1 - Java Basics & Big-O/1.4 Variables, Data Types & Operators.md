Before diving into variables and types, make sure you understand how bits and bytes work — see **1.3 Primitive Types — Bits, Bytes & Overflow**. It explains why `byte` is -128 to 127, not 0 to 255.

A variable is a named storage location that holds a value. In Java, every variable has a **type**, and the type decides what the location can hold and how much memory it takes. Java is **statically typed** — you must declare the type, and it can't change later.

---

## Primitive Types (the built-in boxes)

Java has 8 primitive types. Memorize the sizes; they matter for overflow.

| Type | Size | Range | Use for |
|---|---|---|---|
| `byte` | 1 byte | -128 to 127 | tiny numbers, raw bytes |
| `short` | 2 bytes | -32768 to 32767 | rarely used |
| `int` | 4 bytes | ~-2.1 billion to 2.1 billion | **default for whole numbers** |
| `long` | 8 bytes | ~-9.2 quintillion to 9.2 quintillion | big counts, timestamps |
| `float` | 4 bytes | ~6-7 decimal digits | rarely used (precision issues) |
| `double` | 8 bytes | ~15-16 decimal digits | **default for decimals** |
| `char` | 2 bytes | single Unicode character | one character |
| `boolean` | 1 bit (conceptually) | true / false | yes/no flags |

**Rule of thumb:** use `int` for whole numbers and `double` for decimals unless you have a reason not to. Use `long` when numbers exceed ~2 billion (e.g., counting pairs in an array of 10⁵ elements can exceed int range).

### Declaration and assignment

```java
int age = 25;              // declare + assign
double price = 99.5;
char grade = 'A';          // single quotes for char
boolean passed = true;
long big = 9_000_000_000L; // L suffix for long literals; underscores for readability

int x;                     // declare only
x = 10;                    // assign later
```

**Note:** `9_000_000_000` without `L` is treated as `int` and overflows. The `L` (or `l`, but use capital `L` — lowercase `l` looks like `1`) makes it a `long`.

## Reference Types (objects)

Anything that's not a primitive is an object — `String`, arrays, `Integer`, your own classes. Variables of reference type hold a **reference** (address) to the object, not the object itself.

```java
String name = "Vin";        // String is a reference type
int[] arr = {1, 2, 3};      // array is an object
```

**Primitive vs reference — the key difference:**
- Primitives hold the **value** directly. `int a = 5; int b = a;` → `b` is an independent copy; changing `b` doesn't affect `a`.
- References hold an **address**. `int[] a = {1,2}; int[] b = a;` → `a` and `b` point to the *same* array; changing via `b` changes `a`.

This is the source of many bugs. (See "Reference vs Value" in the Arrays module.)

## Operators

### Arithmetic
```java
int a = 10, b = 3;
System.out.println(a + b);   // 13  addition
System.out.println(a - b);   // 7   subtraction
System.out.println(a * b);   // 30  multiplication
System.out.println(a / b);   // 3   division — INTEGER division! (see pitfall)
System.out.println(a % b);   // 1   remainder (modulo)
```

### Increment / Decrement
```java
int x = 5;
x++;        // x = 6  (post-increment)
++x;        // x = 7  (pre-increment)
x--;        // x = 6
--x;        // x = 5
```
In a standalone statement, `x++` and `++x` are the same. They differ only when used inside an expression: `y = x++` uses x's old value then increments; `y = ++x` increments first then uses. Prefer standalone statements — clearer.

### Comparison (returns boolean)
```java
a == b   // equal
a != b   // not equal
a > b    a < b    a >= b    a <= b
```

### Logical
```java
a && b   // AND — true if both true
a || b   // OR  — true if either true
!a       // NOT — flips true/false
```

### Assignment shortcuts
```java
x += 5;   // x = x + 5
x -= 2;   // x = x - 2
x *= 3;
x /= 2;
x %= 2;
```

## The Big Pitfall: Integer Overflow

An `int` holds up to ~2.1 billion. Add two large ints and you **silently wrap around** to a negative number — no error, no warning.

```java
int a = 2_000_000_000;
int b = 2_000_000_000;
System.out.println(a + b);   // -294967296  ← WRONG, overflowed!
```

**Fix:** use `long` when values can exceed ~2 billion, or when multiplying two ints (e.g., `n * (n-1)` for n = 10⁵ gives 10¹⁰, which overflows int).

```java
long a = 2_000_000_000L;
long b = 2_000_000_000L;
System.out.println(a + b);   // 4000000000  ← correct
```

**Rule for DSA:** if a problem involves counts, sums, or products of array elements and n can be ~10⁵ or more, default to `long`. When in doubt, use `long` — the cost is negligible.

### Integer division trap
```java
int a = 5, b = 2;
System.out.println(a / b);       // 2  (truncated, not 2.5!)
System.out.println((double) a / b); // 2.5  (cast one operand to double)
```

`5 / 2` in Java is `2`, not `2.5`. To get decimals, cast at least one operand to `double` (or `float`).

## Type Casting

```java
// Widening (automatic, safe): small → large
int i = 10;
long l = i;          // int → long, automatic
double d = i;        // int → double, automatic

// Narrowing (manual, may lose data): large → small
double x = 9.8;
int y = (int) x;     // y = 9  (truncated, not rounded)
```

Casting a `double` to `int` **truncates** (cuts the decimal). To round, use `Math.round()`.

## String Basics (just enough for now)

```java
String s = "Hello";
System.out.println(s.length());        // 5
System.out.println(s.charAt(0));       // 'H'
System.out.println(s.substring(1, 3)); // "el"
System.out.println(s.toUpperCase());   // "HELLO"
```

**Critical pitfall — comparing Strings:**
```java
String a = "Vin";
String b = "Vin";
System.out.println(a == b);        // true (string pool, same literal)
String c = new String("Vin");
System.out.println(a == c);        // false! (different objects)
System.out.println(a.equals(c));   // true  (same content)
```

Always compare String **content** with `.equals()`, never `==`. `==` compares references (memory addresses), not text. This bug bites everyone once.

## A Small Program: Sum of Two Numbers

Put it together — read two numbers, print their sum.

```java
import java.util.Scanner;

public class SumOfTwo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("Enter first number: ");
        int a = sc.nextInt();

        System.out.print("Enter second number: ");
        int b = sc.nextInt();

        int sum = a + b;
        System.out.println("Sum = " + sum);

        sc.close();
    }
}
```

**Line-by-line:**
- `import java.util.Scanner;` — brings in the Scanner class for reading input. Imports go at the top.
- `Scanner sc = new Scanner(System.in);` — creates a Scanner reading from standard input (keyboard).
- `sc.nextInt()` — reads an integer from the user.
- `System.out.print(...)` — prints without newline; `println` prints with newline.
- `"Sum = " + sum` — `+` concatenates a string with a number (number auto-converted to string).
- `sc.close();` — closes the scanner (good practice, frees the resource).

## In Your Own Words

1. What is integer overflow, and how do you prevent it?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Integer overflow happens when a calculation exceeds an `int`'s max (~2.1 billion) — the value silently wraps around to a negative number with no error. Prevent it by using `long` (8 bytes) when values can exceed ~2 billion, especially for counts, sums, or products of array elements with n ~ 10⁵+. Also add the `L` suffix to large literals and cast before multiplying.

</details>

2. Why does `5 / 2` give `2` in Java, and how do you get `2.5`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Because both operands are `int`, Java does integer division, which truncates the decimal (5/2 = 2). To get 2.5, cast at least one operand to `double`: `(double) 5 / 2` or `5.0 / 2`. Casting after division (`(double)(5/2)`) is too late — the truncation already happened.

</details>

3. Why must you use `.equals()` instead of `==` to compare Strings?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `==` compares references (memory addresses), not content. Two String objects with identical text can be different objects, so `==` returns false. `.equals()` compares the actual character content. Exception: string literals are pooled, so `"Vin" == "Vin"` happens to be true — but relying on that is a bug. Always use `.equals()` for content comparison.

</details>

4. What's the difference between primitive and reference types?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Primitives (`int`, `double`, `char`, `boolean`, etc.) hold the value directly in the variable — copying gives an independent copy. Reference types (String, arrays, objects) hold a memory address pointing to the object — copying the reference makes two variables point to the *same* object, so changes through one are visible through the other. This distinction is the source of many bugs.

</details>
