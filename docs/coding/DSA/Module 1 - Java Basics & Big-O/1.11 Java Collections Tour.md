Java's Collections Framework gives you ready-made data structures. This module is a **tour, not depth** — name, purpose, and one example each. Each is taught in depth where it's first used in a pattern module (e.g., HashMap in Module 2, PriorityQueue in Module 16). For now, just know what exists and when to reach for it.

---

## The Big Picture

```
Collection (interface)
├── List   → ordered, allows duplicates       → ArrayList, LinkedList
├── Set    → no duplicates                    → HashSet, TreeSet, LinkedHashSet
├── Queue  → FIFO processing                  → ArrayDeque, PriorityQueue
└── Map    → key → value pairs                → HashMap, TreeMap, LinkedHashMap
```

`Map` is not a `Collection` (it's a separate interface), but it's part of the framework.

## ArrayList — dynamic array

```java
import java.util.ArrayList;
import java.util.List;

List<Integer> nums = new ArrayList<>();
nums.add(10);              // append
nums.add(20);
nums.add(1, 15);           // insert at index 1
System.out.println(nums);  // [10, 15, 20]
System.out.println(nums.get(0));   // 10
nums.set(1, 99);           // replace index 1
nums.remove(2);            // remove by index
System.out.println(nums.size());   // 2
System.out.println(nums.contains(10)); // true
```

- Use when you need a growable array. Most DSA problems that need a "list" use `ArrayList`.
- `get(i)` is O(1), `add` at end is O(1) amortized, `add`/`remove` in middle is O(n).
- For LeetCode, you often return `List<Integer>` or `int[]` — `ArrayList` is for the list case.

## LinkedList — doubly linked list

```java
import java.util.LinkedList;

LinkedList<Integer> ll = new LinkedList<>();
ll.add(10);
ll.addFirst(5);
ll.addLast(20);
ll.removeFirst();
System.out.println(ll);   // [10, 20]
```

- Implements `List` and `Deque`. Good for frequent insert/remove at ends.
- In DSA interviews you usually **build your own** `ListNode` (Module 10) rather than use `java.util.LinkedList` — interviews want to see you handle pointers. But know this exists.

## HashSet — unique values, fast lookup

```java
import java.util.HashSet;
import java.util.Set;

Set<Integer> seen = new HashSet<>();
seen.add(1);
seen.add(2);
seen.add(1);               // duplicate, ignored
System.out.println(seen);  // [1, 2] (order not guaranteed)
System.out.println(seen.contains(2)); // true — O(1)
```

- Use for "have I seen this before?" checks. O(1) add/contains/remove.
- No duplicates, no order guarantee. Use `LinkedHashSet` if you need insertion order; `TreeSet` if you need sorted order.

## HashMap — key → value, fast lookup

```java
import java.util.HashMap;
import java.util.Map;

Map<String, Integer> freq = new HashMap<>();
freq.put("apple", 2);
freq.put("banana", 1);
freq.put("apple", 3);          // overwrites → apple: 3

System.out.println(freq.get("apple"));        // 3
System.out.println(freq.get("grape"));        // null (not present)
System.out.println(freq.getOrDefault("grape", 0)); // 0
System.out.println(freq.containsKey("banana"));  // true
System.out.println(freq.size());              // 2

for (Map.Entry<String, Integer> e : freq.entrySet()) {
    System.out.println(e.getKey() + " = " + e.getValue());
}
```

- The single most-used tool in interviews. Frequency counts, two-sum lookups, grouping anagrams — all HashMap.
- `get`/`put`/`containsKey` are O(1) average.
- `getOrDefault(key, default)` avoids null checks — use it often.

## ArrayDeque — stack or queue (fast)

```java
import java.util.ArrayDeque;
import java.util.Deque;

Deque<Integer> stack = new ArrayDeque<>();
stack.push(10);
stack.push(20);
System.out.println(stack.pop());   // 20 (LIFO)

Deque<Integer> queue = new ArrayDeque<>();
queue.offer(10);
queue.offer(20);
System.out.println(queue.poll());  // 10 (FIFO)
```

- `ArrayDeque` is the modern replacement for `Stack` and `LinkedList` as a queue. Faster, no legacy baggage.
- Use `push`/`pop`/`peek` for stack behavior; `offer`/`poll`/`peek` for queue behavior.
- **Don't use `java.util.Stack`** — it's legacy and slow. Use `ArrayDeque`.

## PriorityQueue — min-heap by default

```java
import java.util.PriorityQueue;

PriorityQueue<Integer> minHeap = new PriorityQueue<>();
minHeap.add(30);
minHeap.add(10);
minHeap.add(20);
System.out.println(minHeap.peek());  // 10 (smallest, not removed)
System.out.println(minHeap.poll());  // 10 (removes smallest)

// Max-heap: pass a comparator
PriorityQueue<Integer> maxHeap = new PriorityQueue<>((a, b) -> b - a);
maxHeap.add(30); maxHeap.add(10); maxHeap.add(20);
System.out.println(maxHeap.poll());  // 30 (largest)
```

- Default is **min-heap** (smallest on top). For max-heap, pass `(a, b) -> b - a` (or `Collections.reverseOrder()`).
- `peek()` looks, `poll()` removes + returns. `add()` inserts.
- All operations O(log n). We'll use this heavily in Module 16.

## TreeMap / TreeSet — sorted map/set

```java
import java.util.TreeMap;
import java.util.TreeSet;

TreeMap<Integer, String> tm = new TreeMap<>();
tm.put(3, "c");
tm.put(1, "a");
tm.put(2, "b");
System.out.println(tm);        // {1=a, 2=b, 3=c} (sorted by key)

TreeSet<Integer> ts = new TreeSet<>();
ts.add(30); ts.add(10); ts.add(20);
System.out.println(ts);        // [10, 20, 30] (sorted)
System.out.println(ts.ceiling(15)); // 20 (smallest >= 15)
```

- Sorted by key (TreeMap) or by element (TreeSet). Backed by a red-black tree.
- O(log n) operations. Use when you need ordering, range queries (`floor`, `ceiling`, `lower`, `higher`), or sorted iteration.
- `HashMap`/`HashSet` are faster (O(1)) when you don't need order — prefer them unless you need sorting.

## Quick Decision Guide

| Need | Use |
|---|---|
| Dynamic array | `ArrayList` |
| Unique values, fast lookup | `HashSet` |
| Key → value lookup | `HashMap` |
| Stack (LIFO) | `ArrayDeque` (push/pop) |
| Queue (FIFO) | `ArrayDeque` (offer/poll) |
| Min/max always on top | `PriorityQueue` |
| Sorted keys / range queries | `TreeMap` / `TreeSet` |
| Linked list (interviews) | Your own `ListNode` |

---

## Common Pitfalls

- **Using `java.util.Stack`** — legacy, slow. Use `ArrayDeque`.
- **Using `LinkedList` as a queue/stack** — `ArrayDeque` is faster. Reserve `LinkedList` for when you need `List` features with frequent middle edits.
- **Forgetting `getOrDefault`** — `map.get(key)` returns null for missing keys; calling `.intValue()` on null throws NPE. Use `getOrDefault`.
- **Modifying a collection while iterating** — throws `ConcurrentModificationException`. Use an iterator with `remove()`, or collect changes first.
- **`TreeMap`/`TreeSet` with null keys** — throws NullPointerException (can't compare null).
- **`PriorityQueue` is min-heap by default** — don't assume max-heap; pass a comparator.

## In Your Own Words

1. Which collection do you use for "have I seen this value before?"

<details>
<summary>Show Answer</summary>

**Sample Answer:** `HashSet` — O(1) add and contains, no duplicates. For key→value lookups (e.g., value → index), use `HashMap`. Choose `HashSet` when you only care about membership, `HashMap` when you need to associate data with each key.

</details>

2. Why is `ArrayDeque` preferred over `Stack` and `LinkedList` for stack/queue?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `ArrayDeque` is faster (array-backed, no node allocation) and has a cleaner API. `java.util.Stack` is a legacy class that extends `Vector` (synchronized, slow) and shouldn't be used. `LinkedList` works but allocates a node per element and is slower. `ArrayDeque` provides both stack (push/pop/peek) and queue (offer/poll/peek) operations efficiently.

</details>

3. How do you make a max-heap with PriorityQueue?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Pass a comparator that reverses the natural order: `new PriorityQueue<>((a, b) -> b - a)` or `new PriorityQueue<>(Collections.reverseOrder())`. The default PriorityQueue is a min-heap (smallest on top). Note: `(a, b) -> b - a` can overflow for large ints; for safety use `Integer.compare(b, a)`.

</details>

4. When do you need TreeMap/TreeSet instead of HashMap/HashSet?

<details>
<summary>Show Answer</summary>

**Sample Answer:** When you need sorted order or range queries — e.g., "smallest key ≥ X" (`ceiling`), "largest key ≤ X" (`floor`), or iterating keys in sorted order. TreeMap/TreeSet are O(log n); HashMap/HashSet are O(1) but unordered. Prefer HashMap/HashSet unless ordering/range matters.

</details>
