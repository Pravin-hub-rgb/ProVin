Programs are useless if they can't talk to the user. Java has a few ways to read input and write output. Learn the common ones and their gotchas.

---

## Output: System.out

```java
System.out.print("Hello");        // prints without newline
System.out.println("Hello");     // prints WITH newline
System.out.printf("Age: %d, Score: %.2f%n", 25, 95.5);  // formatted
```

- `print` — no newline at the end; next output continues on the same line.
- `println` — adds a newline after.
- `printf` — formatted output. `%d` = integer, `%f` = float/double, `%.2f` = 2 decimal places, `%s` = string, `%n` = newline (platform-independent; prefer over `\n`).

```java
System.out.printf("Name: %s, Marks: %d, GPA: %.2f%n", "Vin", 95, 8.7);
// Output: Name: Vin, Marks: 95, GPA: 8.70
```

## Input: Scanner (the easy way)

`Scanner` (from `java.util`) reads from standard input (keyboard). It's the most common in beginner code and LeetCode-style `main` methods.

```java
import java.util.Scanner;

public class InputDemo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("Enter your name: ");
        String name = sc.nextLine();          // reads a full line (with spaces)

        System.out.print("Enter your age: ");
        int age = sc.nextInt();               // reads an int

        System.out.print("Enter your GPA: ");
        double gpa = sc.nextDouble();         // reads a double

        System.out.println("Hello " + name + ", age " + age + ", GPA " + gpa);
        sc.close();
    }
}
```

**Scanner methods you'll use:**
- `nextInt()` — integer
- `nextDouble()` / `nextFloat()` — decimal
- `next()` — one word (stops at whitespace)
- `nextLine()` — entire line (including spaces)
- `nextBoolean()` — true/false
- `hasNextInt()` — checks if next token is an int (useful in loops)

### The gotcha: nextLine() after nextInt()

This bites everyone once.

```java
Scanner sc = new Scanner(System.in);
int n = sc.nextInt();        // reads 5, leaves the '\n' in the buffer
String s = sc.nextLine();     // reads the leftover '\n' → empty string! BUG
```

**Fix:** consume the leftover newline before reading the line.

```java
int n = sc.nextInt();
sc.nextLine();                // consume the newline
String s = sc.nextLine();     // now reads the actual line
```

Or just use `nextLine()` everywhere and parse with `Integer.parseInt(...)`.

### The gotcha: Scanner is slow

For large input (10⁵+ numbers), `Scanner` is too slow and may TLE (time limit exceeded) in competitive programming. Use `BufferedReader` instead (below). For LeetCode you don't read input at all — the platform passes arguments to your method. For practice problems with `main`, Scanner is fine.

## Input: BufferedReader (the fast way)

`BufferedReader` + `StringTokenizer` is the standard fast I/O for competitive programming.

```java
import java.io.*;
import java.util.StringTokenizer;

public class FastInput {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer(br.readLine());

        int a = Integer.parseInt(st.nextToken());
        int b = Integer.parseInt(st.nextToken());

        System.out.println(a + b);
        br.close();
    }
}
```

**Line-by-line:**
- `BufferedReader` wraps `InputStreamReader` which wraps `System.in`. It buffers input for speed.
- `StringTokenizer` splits a line into tokens by whitespace.
- `Integer.parseInt(...)` converts a string token to int. (Use `Long.parseLong` for long.)
- `throws IOException` — BufferedReader methods can throw I/O errors; declaring it is the simple way to handle that in `main`.

You don't need this for LeetCode, but you'll see it in competitive programming templates. Know it exists.

## A Small Program: Simple Calculator

Read two numbers and an operator, print the result.

```java
import java.util.Scanner;

public class Calculator {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("Enter first number: ");
        double a = sc.nextDouble();

        System.out.print("Enter operator (+, -, *, /): ");
        char op = sc.next().charAt(0);   // read one char

        System.out.print("Enter second number: ");
        double b = sc.nextDouble();

        double result;
        switch (op) {
            case '+': result = a + b; break;
            case '-': result = a - b; break;
            case '*': result = a * b; break;
            case '/':
                if (b == 0) {
                    System.out.println("Cannot divide by zero");
                    sc.close();
                    return;
                }
                result = a / b;
                break;
            default:
                System.out.println("Invalid operator");
                sc.close();
                return;
        }

        System.out.println("Result = " + result);
        sc.close();
    }
}
```

**Notes:**
- `sc.next().charAt(0)` — read a token as String, take its first character. Handy for reading a single char.
- `switch` on a `char` works; each case ends with `break` (otherwise it falls through to the next case).
- `return;` in `void main` exits early — used here to abort on bad input.

## A Small Program: Read a Line, Count Words

```java
import java.util.Scanner;

public class WordCount {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter a sentence: ");
        String line = sc.nextLine();

        String[] words = line.trim().split("\\s+");
        System.out.println("Word count: " + words.length);

        sc.close();
    }
}
```

- `trim()` removes leading/trailing spaces.
- `split("\\s+")` splits on one-or-more whitespace (regex). `\\s+` = "whitespace, one or more."
- Edge case: empty input → `trim()` gives `""`, `split` gives `[""]` (length 1). Handle empty input separately if needed.

## Common Pitfalls

- **`nextLine()` after `nextInt()`** — reads the leftover newline. Consume it with an extra `sc.nextLine()`.
- **Forgetting to close Scanner** — not fatal for small programs, but good practice. Don't close `System.in`'s scanner in a long-running program if you'll need input again.
- **Reading with `next()` when you need `nextLine()`** — `next()` stops at the first space; use `nextLine()` for full lines.
- **`sc.next().charAt(0)` on empty input** — throws; check `sc.hasNext()` first.
- **Mixing `print` and `println`** — output formatting bugs; decide line-by-line.

## In Your Own Words

1. What's the difference between `print` and `println`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `print` outputs text without a trailing newline — the next output continues on the same line. `println` outputs text followed by a newline, so the next output starts on a new line. Use `print` when building a line piece by piece; `println` when ending a line. `printf` with `%n` is the platform-safe way to add a newline.

</details>

2. Why does `nextLine()` return an empty string right after `nextInt()`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `nextInt()` reads the number but leaves the trailing newline (`\n`) in the input buffer. The following `nextLine()` immediately consumes that leftover newline and returns an empty string. Fix by calling `sc.nextLine()` once to consume the newline before reading the real line, or read everything with `nextLine()` and parse with `Integer.parseInt`.

</details>

3. When should you use BufferedReader instead of Scanner?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use BufferedReader for large input (10⁵+ values) in competitive programming — Scanner is too slow and may TLE. BufferedReader buffers input and reads faster. For LeetCode you don't read input at all (the platform passes arguments to your method). For small programs and practice, Scanner is fine and easier to use.

</details>

4. How do you read a single character from the user?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `sc.next().charAt(0)` — read a token as a String, then take its first character. Or read a full line and take `charAt(0)`. Always guard against empty input to avoid `StringIndexOutOfBoundsException`.

</details>
