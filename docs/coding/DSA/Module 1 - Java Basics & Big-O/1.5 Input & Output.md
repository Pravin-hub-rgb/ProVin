Before we read input or print output, let's look closely at `System.out`. You've seen it used in earlier files — here we break down exactly what each piece means.

## What is `System`?

`System` is a **built-in Java class** that comes with Java. It lives in the `java.lang` package — a package that's automatically available in every Java file, so you never need to `import` it.

Think of `System` as a **toolbox** that Java gives you for talking to the outside world: printing to the console, reading keyboard input, accessing environment variables, and more.

## Why is `System` capitalized?

Because it's a **class name**, and Java class names follow PascalCase — they start with a capital letter (`System`, `Scanner`, `String`, `Integer`). Variables and methods start with lowercase (`out`, `print`, `nextInt`).

## What is `out`?

`out` is not a method. It's a **static field** (a variable) inside the `System` class. It holds an object of type `PrintStream` — an object whose job is to print text somewhere (by default, your console/terminal).

So `System` is the class, and `out` is an object living inside that class.

## The dot chain: `System.out.println(...)`

When you write `System.out.println("Hello")`, here is what happens, piece by piece:

| Piece | What it is | What it does |
|-------|-----------|--------------|
| `System` | A built-in Java class | The toolbox |
| `.` | Dot operator | "reach inside" the thing on the left |
| `out` | A static field (object) inside `System` | A `PrintStream` object that prints to console |
| `.` | Dot operator | "reach inside" the `out` object |
| `println(...)` | A method inside the `PrintStream` object | Prints text followed by a newline |

So the chain reads left to right: **reach inside `System`, grab the `out` object, then call its `println` method.**

It's like: `Toolbox → screwdriver → tightenScrew()`.

`System.out` itself is the object; `println` is something you *do* with that object.

## Output methods on `System.out`

Once you have the `out` object, you can call these methods on it:

- **`print("text")`** — prints text with no newline. The next output continues on the same line.
- **`println("text")`** — prints text followed by a newline. Next output starts on a new line.
- **`printf("format", values)`** — formatted output. `%d` = integer, `%f` = float/double, `%.2f` = 2 decimal places, `%s` = string, `%n` = newline (platform-safe; prefer over `\n`).

```java
System.out.print("Hello");        // Hello (no newline, cursor stays here)
System.out.println("Hello");     // Hello then newline
System.out.printf("Age: %d, Score: %.2f%n", 25, 95.5);
// Output: Age: 25, Score: 95.50
```

## `printf` format specifiers — the full table

`printf` uses **format specifiers** — placeholders that start with `%` and tell Java what kind of value to print and how. The specifier must match the type of the argument you pass. If it doesn't, Java throws an error at runtime.

| Specifier | For | Example | Output |
|-----------|-----|---------|--------|
| `%s` | String | `printf("Hi %s", "Vin")` | `Hi Vin` |
| `%d` | int (whole number) | `printf("Age: %d", 25)` | `Age: 25` |
| `%f` | double / float (decimal) | `printf("Pi: %f", 3.14159)` | `Pi: 3.141590` |
| `%.2f` | decimal, 2 places | `printf("Score: %.2f", 8.7)` | `Score: 8.70` |
| `%n` | newline (platform-safe) | `printf("Line one%nLine two")` | Line one<br>Line two |

### Common mistake — mismatched specifier

```java
int age = 5;
String name = "h3llo";
System.out.printf("Name: %name, marks: %a", name, age);
```

**What's wrong:**

- `%name` is not a real specifier. For a `String`, use **`%s`**.
- `%a` is for floating-point hexadecimal, not `int`. For a whole number, use **`%d`**.

Java does **not** auto-convert types in `printf`. The specifier must match the argument exactly, or you get `IllegalFormatConversionException`.

**Fixed:**

```java
int age = 5;
String name = "h3llo";
System.out.printf("Name: %s, marks: %d", name, age);
// Output: Name: h3llo, marks: 5
```

### Rule

| If the argument is... | Use this specifier |
|-----------------------|-------------------|
| `String` | `%s` |
| `int`, `byte`, `short`, `long` | `%d` |
| `float`, `double` | `%f` (or `%.2f` for 2 decimals) |
| newline | `%n` |

## What is `System.in`? — the raw source of input

Just as `System.out` is an object for **output** (sending text to the console), `System.in` is an object for **input** (reading text from the keyboard). It's another static field inside the `System` class — an `InputStream` object that represents the standard input stream.

But here is the key problem: **`System.in` is crude.**

It reads input one raw **byte** at a time. If you type the number `255`, `System.in` does not hand you the number `255`. It hands you three separate bytes: `'2'`, `'5'`, `'5'` — and you'd have to convert those bytes into a number yourself. It's like being handed individual LEGO bricks instead of a built toy.

Java gives you `System.in` as the raw source, but it doesn't give you an easy way to read whole words, whole numbers, or whole lines directly from it.

## Why we need `Scanner` — the friendly wrapper

`Scanner` is a class (in `java.util`) whose whole job is to **wrap** a crude input source and make it friendly. It reads from `System.in`, but instead of giving you raw bytes, it gives you whole chunks:

- `nextInt()` — reads a whole number
- `nextLine()` — reads a whole line of text
- `nextDouble()` — reads a decimal number

Without `Scanner`, you'd have to manually read bytes from `System.in`, detect where numbers end, convert text to numbers, handle spaces, and more. `Scanner` does all that boring work for you.

## The template for creating a Scanner

Here is the template:

```java
Scanner variableName = new Scanner(source);
```

- **`Scanner`** — the type (class) of object you're creating
- **`variableName`** — the name you give this Scanner object (you choose it, like `sc` or `input`)
- **`new Scanner(...)`** — creates a new Scanner object
- **`source`** — where the Scanner should read from

## Why we pass `System.in` to `Scanner`

`Scanner` needs to know **where to read from**. It doesn't automatically know you want keyboard input. You could theoretically tell it to read from a file or a string instead. So you pass the source as an argument:

```java
Scanner sc = new Scanner(System.in);
```

This reads as: "Create a new Scanner object named `sc`, and connect it to `System.in` so it reads bytes from the keyboard."

`System.in` is the **source** (the keyboard stream), and `Scanner` wraps it so you can call friendly methods like `sc.nextInt()` and `sc.nextLine()`.

## Putting the two dots together

Here is the full flow, step by step:

1. **`System.in`** — the raw keyboard stream (crude, byte-by-byte)
2. **`new Scanner(System.in)`** — wraps `System.in` into a friendly Scanner object
3. **`sc.nextLine()`** — asks the Scanner to read a whole line from that stream
4. **`sc.close()`** — closes the Scanner when you're done (frees the resource)

```java
import java.util.Scanner;

public class InputOutputDemo {
    public static void main(String[] args) {
        // OUTPUT: System (class) → out (object) → print (method)
        System.out.print("Enter your name: ");

        // INPUT: connect Scanner to System.in, then read
        Scanner sc = new Scanner(System.in);
        String name = sc.nextLine();

        // OUTPUT again
        System.out.println("Hello, " + name + "!");

        sc.close();
    }
}
```

- `System.out.print(...)` — reach inside `System`, grab `out`, call `print`
- `new Scanner(System.in)` — create Scanner connected to keyboard stream
- `sc.nextLine()` — call `nextLine` method on the `sc` Scanner object
- `sc.close()` — close the Scanner when done

## Why `Scanner` needs `import`

`System` is in `java.lang`, which Java automatically imports in every file. But `Scanner` is in `java.util`, which is **not** auto-imported. So you must write:

```java
import java.util.Scanner;
```

at the top of your file before using `Scanner`.


## `Scanner` methods you'll use

| Method | Reads |
|--------|-------|
| `nextInt()` | a whole number |
| `nextDouble()` / `nextFloat()` | a decimal number |
| `next()` | one word (stops at whitespace/space) |
| `nextLine()` | the entire line, including spaces |
| `nextBoolean()` | true or false |
| `hasNextInt()` | checks if the next thing typed is an int |

### Reading a single character with `charAt()`

`Scanner` has no `nextChar()` method. To read a single character, read a whole word with `next()`, then grab the first character with `charAt(0)`:

```java
Scanner sc = new Scanner(System.in);
System.out.print("Enter a grade (A/B/C): ");
char grade = sc.next().charAt(0);   // read a word, take its first char
System.out.println("Your grade: " + grade);
```

`charAt(0)` means "give me the character at index 0" — the very first character of the string.

## Why we call `sc.close()`

When you create a `Scanner` with `new Scanner(System.in)`, Java opens a connection to the keyboard input stream. That connection uses a system resource — an open file handle to `System.in`.

Calling `sc.close()` **closes that connection** and frees the resource. It tells Java: "I'm done reading from the keyboard; you can release the input stream."

### Why it matters

If you don't close the Scanner:

1. **Resource leak** — the input stream stays open for the life of your program. In a short program that runs and exits, this doesn't matter much — Java cleans up when the program ends. But in a long-running program (a server, a game loop, a GUI app), leaving streams open wastes resources and can eventually cause problems.

2. **Good habit** — closing resources you open is a core Java practice. Files, network connections, database connections, and input streams all need to be closed. Learning to close `Scanner` now builds the habit for bigger resources later.

### What happens if you forget

For a small program that runs once and exits, nothing bad happens — Java shuts down everything when the program ends. The common pitfalls section lists it as "not fatal for small programs, but good practice."

### Can you read again after closing?

No. Once you call `sc.close()`, the underlying `System.in` stream is closed too. You cannot read more input from that Scanner (or from `System.in` directly) after closing. So close only when you're truly done reading.

```java
Scanner sc = new Scanner(System.in);
String name = sc.nextLine();   // read input
sc.close();                    // done — close the connection
// sc.nextLine();             // ERROR: scanner is closed
```

### Where to put it

Close the Scanner at the end of your `main` method, after all input reading is complete. Don't close it in the middle if you still need to read more.


This bites everyone once. `nextInt()` reads the number but leaves the trailing Enter key (`\n`) in the input buffer. The next `nextLine()` immediately grabs that leftover newline and returns an empty string.

```java
Scanner sc = new Scanner(System.in);
int n = sc.nextInt();        // reads 5, leaves '\n' behind
String s = sc.nextLine();    // reads the leftover '\n' → empty string! BUG
```

**Fix:** consume the leftover newline before reading the real line:

```java
int n = sc.nextInt();
sc.nextLine();                // consume the leftover newline
String s = sc.nextLine();     // now reads the actual line
```

Or just use `nextLine()` everywhere and parse with `Integer.parseInt(...)`.

## Scanner vs BufferedReader

`Scanner` is easy but slow. For large input (10⁵+ numbers) in competitive programming, use `BufferedReader` instead — it buffers input and reads faster. For LeetCode you don't read input at all (the platform passes arguments to your method). For small practice programs, `Scanner` is fine.

## A Small Program: Simple Calculator

Read two numbers and an operator, print the result.

```java
import java.util.Scanner;

public class Calculator {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("Enter first number: ");
        double a = sc.nextDouble();

        System.out.print("Enter operator (+, -, *, /): ");
        char op = sc.next().charAt(0);

        System.out.print("Enter second number: ");
        double b = sc.nextDouble();

        double result;
        switch (op) {
            case '+': result = a + b; break;
            case '-': result = a - b; break;
            case '*': result = a * b; break;
            case '/':
                if (b == 0) {
                    System.out.println("Cannot divide by zero");
                    sc.close();
                    return;
                }
                result = a / b;
                break;
            default:
                System.out.println("Invalid operator");
                sc.close();
                return;
        }

        System.out.println("Result = " + result);
        sc.close();
    }
}
```

- `sc.next().charAt(0)` — read a token as String, take its first character. Handy for reading a single char.
- `switch` on a `char` works; each case ends with `break`.
- `return;` in `void main` exits early — used here to abort on bad input.

## A Small Program: Read a Line, Count Words

```java
import java.util.Scanner;

public class WordCount {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter a sentence: ");
        String line = sc.nextLine();

        String[] words = line.trim().split("\\s+");
        System.out.println("Word count: " + words.length);

        sc.close();
    }
}
```

- `trim()` removes leading/trailing spaces.
- `split("\\s+")` splits on one-or-more whitespace (regex).
- Edge case: empty input → `trim()` gives `""`, `split` gives `[""]` (length 1). Handle empty input separately if needed.

## Common Pitfalls

- **`nextLine()` after `nextInt()`** — reads the leftover newline. Consume it with an extra `sc.nextLine()`.
- **Forgetting to close Scanner** — not fatal for small programs, but good practice.
- **Reading with `next()` when you need `nextLine()`** — `next()` stops at the first space; use `nextLine()` for full lines.
- **`sc.next().charAt(0)` on empty input** — throws; check `sc.hasNext()` first.
- **Mixing `print` and `println`** — output formatting bugs; decide line-by-line.
