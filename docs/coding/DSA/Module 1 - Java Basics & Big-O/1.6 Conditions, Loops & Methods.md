Control flow is how you make decisions and repeat work. Methods are how you reuse code. These three together are enough to write any basic program.

## Conditions: if / else if / else

```java
int marks = 75;

if (marks >= 90) {
    System.out.println("Grade A");
} else if (marks >= 75) {
    System.out.println("Grade B");
} else if (marks >= 60) {
    System.out.println("Grade C");
} else {
    System.out.println("Fail");
}
```

- Conditions are evaluated top to bottom; the **first** true branch runs, the rest are skipped.
- Braces `{ }` are optional for a single statement, but always use them — prevents bugs when you add a line later.
- Comparison uses `==`, `!=`, `<`, `>`, `<=`, `>=`. Note: `=` is assignment, `==` is comparison. Mixing them is a classic bug.

### Ternary (short if-else)

```java
int max = (a > b) ? a : b;   // if a>b then a else b
String status = (age >= 18) ? "Adult" : "Minor";
```

Use for simple either/or. Don't nest ternaries — unreadable.

### switch

```java
int day = 3;
switch (day) {
    case 1: System.out.println("Monday"); break;
    case 2: System.out.println("Tuesday"); break;
    case 3: System.out.println("Wednesday"); break;
    default: System.out.println("Other day");
}
```

- Each case ends with `break`, or execution **falls through** to the next case (sometimes useful, usually a bug).
- `default` runs if no case matches.
- Java 14+ supports switch expressions (arrow form): `String name = switch(day) { case 1 -> "Mon"; ... };` — cleaner for assigning values.

## Loops

### for — when you know the count

```java
for (int i = 0; i < 5; i++) {
    System.out.println(i);   // 0 1 2 3 4
}
```

Structure: `for (init; condition; update)`. Init runs once; condition checked before each iteration; update runs after each.

### while — when you don't know the count

```java
int i = 0;
while (i < 5) {
    System.out.println(i);
    i++;
}
```

Condition checked before each iteration. If it's false from the start, the body never runs.

### do-while — runs at least once

```java
int i = 0;
do {
    System.out.println(i);
    i++;
} while (i < 5);
```

Condition checked after the body. Use when you need the body to run at least once (e.g., menu loops).

### Enhanced for (for-each) — for arrays/collections

```java
int[] arr = {10, 20, 30};
for (int x : arr) {
    System.out.println(x);   // 10 20 30
}
```

Cleanest when you only need values, not indices. Use the classic `for` when you need the index.

### Infinite loops and break/continue

```java
while (true) {               // infinite loop
    int x = sc.nextInt();
    if (x == 0) break;       // exit the loop
    if (x < 0) continue;     // skip to next iteration
    System.out.println(x);
}
```

- `break` exits the loop immediately.
- `continue` skips the rest of the current iteration and moves to the next.
- `break` also exits `switch`.

### Nested loops — the DSA bread and butter

```java
for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        System.out.print(i + "," + j + "  ");
    }
    System.out.println();
}
```

Nested loops are usually O(n²) — a common complexity in DSA. We'll analyze this in the Big-O module.

## Methods (Functions)

A method is a named, reusable block of code. It takes inputs (parameters), does work, and optionally returns a value.

```java
public class MethodsDemo {
    // A method that returns a value
    static int add(int a, int b) {
        return a + b;
    }

    // A method that returns nothing (void)
    static void greet(String name) {
        System.out.println("Hello, " + name);
    }

    public static void main(String[] args) {
        int sum = add(3, 5);        // call → 8
        System.out.println(sum);
        greet("Vin");               // prints "Hello, Vin"
    }
}
```

**Method order doesn't matter:** Unlike local variables, methods can be called before they are defined in the same class. Java looks at the whole class before running, so `add` and `greet` work here even though they're defined above `main`. You could also define them below `main` — it would still compile and run.

### `static` method vs non-static method — premise first

Before looking at `static`, remember the class/object idea from 1.2: **a class is a blueprint (a house plan); an object is a house built from that blueprint.**

- A **`static` method** belongs to the **class** — the blueprint. You call it directly on the class name. No object needed.
- A **non-static method** belongs to an **object** — the house. You must build an object first (`new ClassName()`), then call the method on that object.

### Concrete side-by-side

```java
public class Calculator {
    // STATIC method — belongs to the class
    static int add(int a, int b) {
        return a + b;
    }

    // NON-STATIC method — belongs to an object
    void greet(String name) {
        System.out.println("Hello, " + name);
    }
}
```

Calling them:

```java
// STATIC — call directly on the class, no object:
int sum = Calculator.add(3, 5);   // works, no new Calculator()

// NON-STATIC — MUST create an object first:
Calculator calc = new Calculator();   // build the house
calc.greet("Vin");                    // use the house
```

### Why `main` is `static`

`public static void main(String[] args)` — the JVM needs to start your program. It looks for `main` and calls it directly. The JVM does **not** create a `Hello` object first — it doesn't know how yet, it's just starting the program. So `main` must be `static`, meaning "call me on the class, don't make me build an object first."

This connects back to 1.2: `static` = "the JVM can run it without creating an object of the class."

### Why helper methods called from `main` must be `static`

`main` is static. A static method belongs to the class — it has no object of its own. It can only directly call other static methods (which also belong to the class). It cannot directly call a non-static method, because a non-static method needs an object, and `main` has no object.

So in a `main`-based program:

```java
public class MethodsDemo {
    static int add(int a, int b) {   // static — can be called from main
        return a + b;
    }

    void greet(String name) {        // non-static — CANNOT be called directly from main
        System.out.println("Hello, " + name);
    }

    public static void main(String[] args) {
        int sum = add(3, 5);           // OK — both static
        // greet("Vin");              // ERROR — non-static, no object
        
        // To call greet, you must build an object:
        MethodsDemo m = new MethodsDemo();
        m.greet("Vin");               // OK now
    }
}
```

### The LeetCode contrast

In LeetCode's `class Solution`, the platform creates the `Solution` object for you behind the scenes. So your methods are usually **non-static** instance methods — the platform's object calls them. That's why LeetCode solutions don't have `static` on their solve methods, but your `main`-based local programs do.

### Summary table

| | `static` method | Non-static method |
|---|---|---|
| Belongs to | The class (blueprint) | An object (house) |
| Need `new`? | No | Yes — `ClassName obj = new ClassName()` |
| How to call | `ClassName.methodName()` | `obj.methodName()` |
| Can `main` call it directly? | Yes | No — must create object first |
| `public static void main` | ✅ static | — |

- **Parameters** — inputs. `int a, int b` are parameters; `3, 5` are arguments.
- **Return type** — `int`, `double`, `String`, etc., or `void` (no return).
- **`return`** exits the method immediately and sends the value back.

### Method overloading

Same method name, different parameter lists. Java picks the right one by argument types.

```java
static int add(int a, int b) { return a + b; }
static double add(double a, double b) { return a + b; }
static int add(int a, int b, int c) { return a + b + c; }
```

Overloading is resolved at compile time by signature (name + parameter types). Return type alone doesn't distinguish methods.

### Common pitfalls

- **Forgetting `return` in a non-void method** — compile error.
- **Returning the wrong type** — `int` method returning `double` without cast.
- **Modifying a parameter** — parameters are local copies (for primitives); changing them doesn't affect the caller. For objects, the reference is copied, so you can modify the object's contents but not reassign the reference.
- **Infinite recursion** — a method calling itself without a base case. (We'll meet recursion in Module 11.)

## A Small Program: Check Prime

Combine conditions, loops, and a method.

```java
public class PrimeCheck {
    static boolean isPrime(int n) {
        if (n <= 1) return false;          // 0, 1, negatives are not prime
        if (n == 2) return true;           // 2 is the only even prime
        if (n % 2 == 0) return false;      // even numbers > 2 are not prime

        // check odd divisors up to sqrt(n)
        for (int i = 3; i * i <= n; i += 2) {
            if (n % i == 0) return false;  // found a divisor → not prime
        }
        return true;
    }

    public static void main(String[] args) {
        for (int i = 1; i <= 20; i++) {
            System.out.println(i + " is " + (isPrime(i) ? "prime" : "not prime"));
        }
    }
}
```

**Line-by-line highlights:**
- `i * i <= n` — loop while i ≤ √n. We only need to check up to the square root (a number's factors come in pairs; if no factor ≤ √n, none exist).
- `i += 2` — check only odd numbers after 2.
- Early `return false` — as soon as a divisor is found, we know it's not prime; no need to keep checking. This is a common optimization.
- Ternary inside `println` to print "prime"/"not prime".

## In Your Own Words

1. When should you use `for` vs `while`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use `for` when you know how many iterations you need (counting from 0 to n-1). Use `while` when the number of iterations depends on a condition you can't predict in advance (reading input until 0, searching until found). Use `do-while` when the body must run at least once (menus, retry loops). Use enhanced `for` when you only need values from an array/collection, not indices.

</details>

2. What is method overloading, and how does Java pick which version to call?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Overloading means multiple methods with the same name but different parameter lists (different number or types of parameters). Java picks the version whose parameter types match the arguments at compile time — this is compile-time (static) polymorphism. Return type alone doesn't distinguish methods; two methods with identical parameters but different return types cause a compile error.

</details>

3. What happens if you forget `break` in a switch case?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Execution "falls through" to the next case and runs its code too, until a `break` or the end of the switch. This is sometimes intentional (grouping cases) but usually a bug. Always add `break` unless you specifically want fall-through, and consider Java 14+ arrow-form switch expressions which don't fall through.

</details>

4. Why must helper methods be `static` in a `main`-based program?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `main` is static — it belongs to the class, not an object. A static method can only call other static methods directly (or create an object first). Non-static methods need an instance; since `main` has no instance, calling a non-static helper directly won't compile. In LeetCode's `class Solution`, methods are instance methods because the platform creates the `Solution` object for you.

</details>
