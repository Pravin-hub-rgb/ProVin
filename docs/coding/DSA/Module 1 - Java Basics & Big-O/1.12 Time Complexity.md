# Time Complexity — how much time grows as input grows

## What you already know

You can write code that works. Now you need to know: **as the input gets bigger, does the time stay the same, grow a little, or grow a lot?**

That's what time complexity measures.

## What is `n`?

`n` is the **size of the input**. If you have an array:

```java
int[] arr = {10, 20, 30, 40, 50};
```

The array has 5 elements, so `n = 5`.

If you have an array of 1000 numbers, `n = 1000`. If you have 100000 numbers, `n = 100000`.

`n` is just the count of items you're processing.

## What is `O(...)`?

`O(...)` is **notation**. It describes how time grows as `n` gets bigger.

Think of it like this:

- **`O(n)`** means: time grows in direct proportion to `n`. If `n` doubles, time doubles. If `n` is 10x bigger, time is 10x bigger.
- **`O(n²)`** means: time grows as `n` squared. If `n` doubles, time becomes 4x bigger. If `n` is 10x bigger, time is 100x bigger.
- **`O(1)`** means: time stays the same, no matter how big `n` is.

The letter `O` doesn't stand for anything you need to memorize. It's just the symbol computer scientists use for this.

## Example 1: Reading one element — O(1)

```java
int[] arr = {10, 20, 30, 40, 50};
int first = arr[0];   // gets element at index 0
```

Getting `arr[0]` takes the same amount of time whether the array has 5 elements or 5 million elements. The computer jumps directly to that position.

This is **O(1)** — constant time. The "1" means time doesn't grow with `n`. It stays constant.

## Example 2: Looking at every element — O(n)

```java
int[] arr = {10, 20, 30, 40, 50};

for (int i = 0; i < arr.length; i++) {
    System.out.println(arr[i]);
}
```

Here `arr.length` is `n`. The loop runs `n` times. Each iteration does one print.

- If `n = 5`, the loop runs 5 times.
- If `n = 1000`, the loop runs 1000 times.
- If `n = 100000`, the loop runs 100000 times.

Time grows in direct proportion to `n`. This is **O(n)** — linear time. The "n" means time grows linearly with input size.

## Example 3: Looking at every pair — O(n²)

```java
int[] arr = {10, 20, 30, 40, 50};

for (int i = 0; i < arr.length; i++) {
    for (int j = 0; j < arr.length; j++) {
        System.out.println(arr[i] + " and " + arr[j]);
    }
}
```

The outer loop runs `n` times. For each iteration of the outer loop, the inner loop also runs `n` times.

Total times the inner body runs: `n × n = n²`.

- If `n = 5`, inner body runs 25 times.
- If `n = 100`, inner body runs 10000 times.
- If `n = 10000`, inner body runs 100000000 times (100 million).

Time grows as `n` squared. This is **O(n²)** — quadratic time.

## Comparing O(n) vs O(n²)

| n | O(n) operations | O(n²) operations |
|---|-----------------|------------------|
| 10 | 10 | 100 |
| 100 | 100 | 10,000 |
| 1,000 | 1,000 | 1,000,000 |
| 10,000 | 10,000 | 100,000,000 |
| 100,000 | 100,000 | 10,000,000,000 |

At `n = 100,000`, O(n) is 100,000 operations (fast). O(n²) is 10 billion operations (very slow).

This is why O(n²) code can pass for small inputs but fail for large inputs.

## Reading complexity from code

| Code shape | Complexity | Why |
|------------|-----------|-----|
| `int x = arr[0];` | O(1) | One access, doesn't depend on `n` |
| Single loop `for (i = 0; i < n; i++)` | O(n) | Loop runs `n` times |
| Nested loop `for i, for j` both to `n` | O(n²) | Inner body runs `n × n` times |
| Loop that halves `i = i / 2` | O(log n) | Each step cuts remaining work in half |

## The bracket notation

You asked about the brackets in `O(n)`. There's nothing special inside them — `n` is just the input size variable. `O(n)` reads as "order of n" or "big-O of n". The brackets hold the expression that describes how time grows: `n`, `n²`, `1`, `log n`, etc.
