# 1.6 Classes, Objects & Generics

Java is object-oriented. In DSA you won't build big class hierarchies, but you *will* write small classes: `ListNode`, `TreeNode`, `Node`. You also need to read `List<Integer>`, `Map<String, Integer>`. This module covers exactly that much.

---

## Class and Object

A **class** is a type definition; an **object** is an instance of that type.

```java
public class Dog {
    // Fields (state)
    String name;
    int age;

    // Constructor (how to build one)
    public Dog(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Method (behavior)
    public void bark() {
        System.out.println(name + " says woof!");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog d1 = new Dog("Rex", 3);   // create object
        Dog d2 = new Dog("Max", 5);

        d1.bark();   // "Rex says woof!"
        d2.bark();   // "Max says woof!"
    }
}
```

**Line-by-line:**
- `class Dog { ... }` — the type definition. Holds fields (data) and methods (behavior).
- `String name; int age;` — instance fields; each object gets its own copy.
- Constructor `Dog(String name, int age)` — runs when you write `new Dog(...)`. `this.name = name` assigns the parameter to the field (`this` = "this object").
- `new Dog("Rex", 3)` — creates an object in memory and returns a reference to it.
- `d1.bark()` — calls the method on object `d1`.

### this keyword

`this` refers to the current object. Use it to disambiguate field vs parameter when they share a name (as above). In DSA code you'll see `this.val`, `this.next` in node classes.

## The Node Classes You'll Write in DSA

These are the two most common classes in interview code. Memorize their shape.

### ListNode (linked list)

```java
class ListNode {
    int val;
    ListNode next;

    ListNode(int val) {
        this.val = val;
        this.next = null;
    }
}
```

- `val` holds the data, `next` points to the next node (or `null` if last).
- Constructor takes the value; `next` defaults to null.

### TreeNode (binary tree)

```java
class TreeNode {
    int val;
    TreeNode left;
    TreeNode right;

    TreeNode(int val) {
        this.val = val;
        this.left = null;
        this.right = null;
    }
}
```

- `left` and `right` point to child nodes (or `null`).

### Building a list manually

```java
ListNode head = new ListNode(1);
head.next = new ListNode(2);
head.next.next = new ListNode(3);
// list: 1 -> 2 -> 3 -> null
```

In practice you'll write helper methods to build/print lists, but the shape above is what matters.

## static vs instance

- **Instance (non-static):** belongs to an object. Needs `new`. Fields/methods that describe one object's state. `d1.bark()` is instance.
- **Static:** belongs to the class itself. No object needed. `Math.max(a, b)`, `System.out`. Shared across all instances.

```java
public class Counter {
    static int total = 0;     // shared by all instances
    int id;                  // per-object

    Counter() {
        total++;
        id = total;
    }
}
```

**In DSA:** utility methods like `reverseList(ListNode head)` are often `static` (no object state). LeetCode's `Solution` methods are instance (non-static) because the platform instantiates `Solution`.

## Generics: List<Integer>, Map<String, Integer>

Generics let you write "a list of X" where X is a type parameter. You've seen `ArrayList<Integer>`. Here's what it means.

```java
import java.util.ArrayList;
import java.util.List;

List<Integer> nums = new ArrayList<>();   // list of Integers
nums.add(10);
nums.add(20);
int first = nums.get(0);                   // 10 (auto-unboxed to int)

List<String> names = new ArrayList<>();
names.add("Vin");
```

- `List<Integer>` — "a List of Integer." The `<Integer>` is the type parameter.
- `new ArrayList<>()` — diamond operator; Java infers the type from the left side.
- **Why `Integer` not `int`?** Generics work only with reference types, not primitives. `int` → `Integer` (wrapper class). Java auto-boxes: `nums.add(10)` converts int 10 to Integer 10 automatically. And auto-unboxes on retrieval: `int first = nums.get(0)`.

### The 8 wrapper classes (memorize the mapping)

| Primitive | Wrapper |
|---|---|
| `int` | `Integer` |
| `long` | `Long` |
| `double` | `Double` |
| `char` | `Character` |
| `boolean` | `Boolean` |
| `byte` | `Byte` |
| `short` | `Short` |
| `float` | `Float` |

You'll see these in `List<Integer>`, `Map<String, Integer>`, `Set<Character>`, etc.

### Generics in your own classes

```java
class Box<T> {
    T value;
    Box(T value) { this.value = value; }
    T get() { return value; }
}

Box<Integer> intBox = new Box<>(42);
Box<String> strBox = new Box<>("hi");
```

`T` is a placeholder type. You rarely write generic classes in DSA, but you must read `List<Integer>` fluently.

### Raw types (avoid)

```java
List nums = new ArrayList();   // raw type — no type parameter
nums.add(10);
nums.add("hello");             // compiles! (no type checking) — bug at runtime
```

Always specify the type parameter: `List<Integer>`, not raw `List`. Raw types disable type safety.

## A Small Program: A Simple Node-Based List

Build a tiny linked list and print it — ties classes + generics together.

```java
class Node {
    int val;
    Node next;
    Node(int val) { this.val = val; this.next = null; }
}

public class SimpleList {
    static void print(Node head) {
        Node cur = head;
        while (cur != null) {
            System.out.print(cur.val + " -> ");
            cur = cur.next;
        }
        System.out.println("null");
    }

    public static void main(String[] args) {
        Node head = new Node(1);
        head.next = new Node(2);
        head.next.next = new Node(3);

        print(head);   // 1 -> 2 -> 3 -> null
    }
}
```

**Line-by-line:**
- `Node` class with `val` and `next` — the standard linked list node shape.
- `print` walks the list: start at `head`, follow `next` until `null`. This traversal pattern (cur = cur.next) is the foundation of all linked list problems.
- `while (cur != null)` — stop when we run past the last node.

## In Your Own Words

1. What is the difference between a class and an object?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A class is a type definition defining fields and methods. An object is an instance created from that type using `new`. The class exists once in code; you can create many objects from it, each with its own field values. E.g., `class Dog` is the type; `new Dog("Rex", 3)` creates one object.

</details>

2. Why does `List<Integer>` use `Integer` instead of `int`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Generics work only with reference types, not primitives. `int` is a primitive, so Java uses the wrapper class `Integer`. Java auto-boxes: `nums.add(10)` converts int→Integer automatically, and auto-unboxes on retrieval: `int x = nums.get(0)` converts Integer→int. The 8 wrappers are Integer, Long, Double, Character, Boolean, Byte, Short, Float.

</details>

3. What is the shape of a linked list node, and why `next = null`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A node has a value field (`val`) and a pointer to the next node (`next`). `next` is `null` for the last node, marking the end of the list. Traversal stops when `cur == null`. The shape is: `class ListNode { int val; ListNode next; ListNode(int val){ this.val=val; this.next=null; } }`. This is the foundation of all linked list problems.

</details>

4. What's the difference between static and instance members?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Instance (non-static) members belong to an object — need `new`, each object has its own copy. Static members belong to the class itself — no object needed, shared across all instances (e.g., `Math.max`, `Counter.total`). In `main`-based programs, helper methods must be `static`. In LeetCode's `Solution`, methods are instance because the platform creates the object.

</details>
