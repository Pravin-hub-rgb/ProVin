# ArrayList & List — growable lists

## Arrays cannot grow

You've worked with arrays:

```java
int[] marks = new int[5];
marks[0] = 85;
marks[1] = 92;
int first = marks[0];   // 85
```

An array has a **fixed size**. When you write `new int[5]`, it holds exactly 5 elements. You cannot add a 6th:

```java
marks[5] = 78;   // ERROR — array index out of bounds
```

If you don't know how many elements you need ahead of time, an array doesn't work.

## ArrayList — a list that grows

Java provides a class called **`ArrayList`** (in `java.util`) that works like an array but **can grow**. You keep adding elements, and it expands automatically.

```java
import java.util.ArrayList;

ArrayList list = new ArrayList();
list.add(10);
list.add(20);
list.add(30);
```

You read elements back with `.get()` and check how many are inside with `.size()`:

```java
int first = list.get(0);   // 10
int count = list.size();   // 3
```

Notice: you use `.add()` and `.get()` instead of `[ ]` brackets.

## Plain ArrayList is unsafe

When you write `ArrayList list` without a type inside `< >`, Java does not track what kind of elements are inside. It treats everything as `Object`.

```java
ArrayList list = new ArrayList();
list.add(10);
list.add("Vin");
list.add(true);
```

This compiles, but it is unsafe. When you take an element out, Java gives you `Object`, not the original type:

```java
Object x = list.get(0);   // Object, not int
```

You have to manually cast it back:

```java
int y = (int) list.get(0);   // works if it really is an int
int z = (int) list.get(1);   // CRASH at runtime — "Vin" is a String, not an int
```

If you guess the wrong type, the program crashes while running.

## List is an interface, ArrayList is a class

`List` and `ArrayList` are two different things:

- **`List`** is an **interface**. It declares methods like `add()`, `get()`, `size()`, but with no code inside them. You cannot create an object from it:

  ```java
  List x = new List();   // ERROR — List is an interface, you can't new it
  ```

- **`ArrayList`** is a **class**. It has actual code for `add()`, `get()`, `size()`, etc. It says it implements `List` — meaning it provides the code for everything `List` requires.

Because `ArrayList` implements `List`, an `ArrayList` object **is also a `List`**. Java lets you store it in a variable declared as `List`:

```java
List list2 = new ArrayList();
```

This line does two things:

| Part | What it means |
|------|-------------|
| `List list2` | Declare variable `list2` with type `List` (the interface) |
| `=` | Connects the name to the object |
| `new ArrayList()` | Creates the actual object using the `ArrayList` class |

The variable is typed as `List`, but the actual object created is an `ArrayList`. Both have `add`, `get`, `size` — because `ArrayList` implements `List` and must provide those methods.

## Why declare as `List` instead of `ArrayList`?

You might wonder: if `ArrayList` already has all the methods (`add`, `get`, `size`), why not just write `ArrayList list2 = new ArrayList()`?

You *can* — and it works fine. But Java has more than one class that implements `List`. `ArrayList` is one. `LinkedList` is another. Both have `add`, `get`, `size`.

The point of declaring `List list2 = new ArrayList()` is **flexibility**. It means: "I don't care which specific list class this is — I only care that it behaves like a `List`."

This matters most when writing methods. Consider a method that prints the first element:

```java
import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;

// Version A: locked to ArrayList only
void printFirst(ArrayList list) {
    System.out.println(list.get(0));
}

// Version B: works with ANY List — ArrayList OR LinkedList
void printFirst(List list) {
    System.out.println(list.get(0));
}
```

With Version A, you can only pass an `ArrayList`:

```java
ArrayList al = new ArrayList();
al.add(10);

LinkedList ll = new LinkedList();
ll.add(10);

printFirst(al);   // OK
printFirst(ll);   // ERROR — LinkedList is not an ArrayList
```

With Version B, you can pass either:

```java
printFirst(al);   // OK
printFirst(ll);   // OK — both are List
```

If you later decide to switch from `ArrayList` to `LinkedList`, you change **one line**:

```java
List list2 = new LinkedList();   // was ArrayList
```

Every method that takes `List` keeps working, because `LinkedList` also has `add`, `get`, `size`.

If you'd written `ArrayList` everywhere, you'd have to find and change every single declaration.

**Bottom line:** `ArrayList list = new ArrayList()` works fine. `List list = new ArrayList()` lets you write methods that accept any list type — `ArrayList` or `LinkedList` — without rewriting your code when you switch.

## Array vs ArrayList

| Operation | Array | ArrayList |
|-----------|-------|-----------|
| Create | `int[] a = new int[5];` | `ArrayList list = new ArrayList();` |
| Add value | `a[0] = 10;` | `list.add(10);` |
| Get value | `int x = a[0];` | `int x = list.get(0);` |
| Size | `a.length` (fixed) | `list.size()` (grows) |

## A complete example

```java
import java.util.ArrayList;
import java.util.List;

public class ScoreTracker {
    public static void main(String[] args) {
        List scores = new ArrayList();
        scores.add(85);
        scores.add(92);
        scores.add(78);

        System.out.println("First score: " + scores.get(0));   // 85
        System.out.println("Number of scores: " + scores.size()); // 3

        int total = 0;
        for (Object s : scores) {
            total += (int) s;
        }
        System.out.println("Average: " + (total / scores.size()));
    }
}
```
