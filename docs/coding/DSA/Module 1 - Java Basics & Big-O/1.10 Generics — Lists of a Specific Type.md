# Generics — type strictness for lists

In 1.9 you learned about `ArrayList` and `List`. A plain `ArrayList` holds anything — numbers, text, true/false — all mixed together as `Object`. That's unsafe: when you take something out, Java doesn't remember what type it was, and you can crash at runtime.

**Generics** is Java's solution. It lets you put a type inside `< >` to restrict what a list holds.

## From plain to typed

Plain `ArrayList` — anything goes:

```java
ArrayList list = new ArrayList();
list.add(10);
list.add("Vin");
list.add(true);   // compiles, but unsafe
```

When you take something out, Java gives you `Object`:

```java
Object x = list.get(0);   // Object, not int
```

You must cast manually, and casting wrong crashes at runtime:

```java
int y = (int) list.get(0);   // works if element 0 is really an int
int z = (int) list.get(1);   // CRASH — element 1 is "Vin", not an int
```

## Typed list with generics

```java
List<Integer> nums = new ArrayList<>();
```

This means: `nums` is a `List` that holds **only Integer values**. Nothing else.

```java
nums.add(10);      // OK — Integer
nums.add(20);      // OK — Integer
// nums.add("Vin");  // ERROR — String is not Integer. Compile error, stops before running.
```

Because Java knows the list holds only Integers, taking something out needs no cast:

```java
int first = nums.get(0);   // 10 — already an Integer, auto-unboxed to int
```

## Breaking down the line

```java
List<Integer> nums = new ArrayList<>();
```

| Part | What it means |
|------|-------------|
| `List<Integer>` | Declare variable `nums` as a `List` holding only `Integer` values |
| `<Integer>` | The type parameter — goes inside angle brackets `< >`, names the type this list holds |
| `nums` | The variable name |
| `new ArrayList<>()` | Creates the actual `ArrayList` object |
| `<>` | Diamond operator — empty on the right side; Java copies `Integer` from the left side so you don't write it twice |

## Why `Integer` not `int`?

`List` and `ArrayList` work with objects (reference types), not primitives. You cannot write `List<int>` or `ArrayList<int>`.

`Integer` is the object version of `int` (called a wrapper class). Java converts automatically:

```java
List<Integer> nums = new ArrayList<>();
nums.add(10);      // auto-boxing: int 10 becomes Integer object
int first = nums.get(0);   // auto-unboxing: Integer becomes int
```

So you write `int` in your code, and Java handles the conversion behind the scenes.

## What generics gives you

| Without generics | With generics (`List<Integer>`) |
|------------------|----------------------------------|
| Holds anything — `Object` | Holds only `Integer` |
| Take out → `Object`, must cast | Take out → already `Integer`, no cast |
| Cast wrong → crash at runtime | Add wrong type → compile error, doesn't run |
| You track types manually | Java enforces types automatically |

## A complete example

```java
import java.util.ArrayList;
import java.util.List;

public class ScoreTracker {
    public static void main(String[] args) {
        List<Integer> scores = new ArrayList<>();
        scores.add(85);
        scores.add(92);
        scores.add(78);

        System.out.println("First score: " + scores.get(0));   // 85
        System.out.println("Number of scores: " + scores.size()); // 3

        int total = 0;
        for (int s : scores) {
            total += s;
        }
        System.out.println("Average: " + (total / scores.size()));
    }
}
```

## In Your Own Words

1. What is the problem with a plain `ArrayList` that has no type inside `< >`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A plain `ArrayList` holds anything as `Object`. When you take an element out with `.get()`, Java returns `Object` and does not remember the original type. You must cast manually, and casting to the wrong type crashes the program at runtime.
</details>

2. What does `<Integer>` do in `List<Integer>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `<Integer>` is a type parameter that restricts the list to hold only Integer values. If you try to add a String, Java gives a compile error and stops the program before it runs.
</details>

3. What does `<>` mean in `new ArrayList<>()`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `<>` is the diamond operator. It is empty on the right side; Java copies the type from the left side (`List<Integer>` becomes `ArrayList<Integer>`) so you do not write the type twice.
</details>

4. Why is it `List<Integer>` and not `List<int>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Generics work only with objects (reference types), not primitives. `int` is a primitive, so you use its object wrapper `Integer`. Java converts `int` to `Integer` automatically (auto-boxing) and back (auto-unboxing).
</details>
