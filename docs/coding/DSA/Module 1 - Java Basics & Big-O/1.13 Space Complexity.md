Time complexity asks "how much time." Space complexity asks "how much extra memory" your algorithm uses beyond the input. Same Big-O notation, different thing being measured.

---

## What Counts as Space?

Two kinds:

1. **Auxiliary space** — extra memory your algorithm allocates (arrays, hash maps, recursion stack). This is what we usually mean by "space complexity."
2. **Input space** — memory the input itself takes. Usually we don't count this (it's given), but sometimes a problem says "O(1) extra space," which means auxiliary space only.

**Rule of thumb:** when someone says "space complexity," they mean auxiliary space unless stated otherwise.

### What It Is NOT

- Space complexity is **not** the total memory of the program (JVM, OS, etc.) — just the algorithm's extra memory.
- O(1) space doesn't mean "zero bytes." It means the extra memory doesn't grow with n (a few variables). A fixed-size array of 26 (for alphabet) is O(1), not O(n).
- Recursion uses space — the call stack counts. A recursive function with depth n uses O(n) space even if it allocates nothing else.

---

## Common Space Complexities

| Code shape | Space |
|---|---|
| A few variables | O(1) |
| One array of size n | O(n) |
| 2D array n × n | O(n²) |
| HashMap with up to n entries | O(n) |
| Recursion depth d | O(d) |
| Sorting in place (quicksort) | O(log n) (recursion stack) |
| Merge sort (needs temp array) | O(n) |
| Creating a copy of the input | O(n) |

---

## In-Place vs Extra Space

- **In-place:** the algorithm works within the input array, using O(1) extra space. E.g., reversing an array by swapping (two pointers). Preferred when the problem asks for O(1) space.
- **Extra space:** allocates new structures. E.g., creating a new array of size n.

**Trade-off:** in-place saves memory but can be harder to reason about and may destroy the input. Many problems explicitly allow or forbid extra space — read the constraints ("do not allocate extra space" means O(1) auxiliary).

---

## Recursion and the Call Stack

Every recursive call pushes a frame onto the call stack. Stack depth = space.

```java
static int factorial(int n) {
    if (n <= 1) return 1;        // base case
    return n * factorial(n - 1); // recursive call
}
```

- Depth: n calls on the stack at once (n, n-1, ..., 1). Space = **O(n)**.
- Even though no arrays are allocated, the recursion itself costs O(n) space.

```java
static int binarySearch(int[] arr, int lo, int hi, int target) {
    if (lo > hi) return -1;
    int mid = lo + (hi - lo) / 2;
    if (arr[mid] == target) return mid;
    if (arr[mid] < target) return binarySearch(arr, mid + 1, hi, target);
    return binarySearch(arr, lo, mid - 1, target);
}
```

- Each call halves the range: depth = log₂(n). Space = **O(log n)**.

**Pitfall:** deep recursion (n = 10⁵) can cause `StackOverflowError`. Iterative versions avoid this. Some problems require iterative solutions for this reason.

---

## Worked Example: Reverse an Array (Two Versions)

**Version A — in-place, O(1) space:**

```java
static void reverseInPlace(int[] arr) {
    int left = 0, right = arr.length - 1;
    while (left < right) {
        int temp = arr[left];
        arr[left] = arr[right];
        arr[right] = temp;
        left++;
        right--;
    }
}
```
Auxiliary space: O(1) (just `temp`, `left`, `right`). Modifies the original array.

**Version B — new array, O(n) space:**

```java
static int[] reverseNew(int[] arr) {
    int[] res = new int[arr.length];
    for (int i = 0; i < arr.length; i++) {
        res[i] = arr[arr.length - 1 - i];
    }
    return res;
}
```
Auxiliary space: O(n) (the new array). Original array untouched.

**Choose based on constraints:** if the problem says "O(1) space" or "in place," use Version A. Otherwise Version B is often clearer.

---

## Time vs Space Trade-off

Many problems have a time-space trade-off: you can use more memory to go faster, or less memory to go slower.

- **Two Sum:** O(n) time with a HashMap (O(n) space) vs O(n²) time with nested loops (O(1) space).
- **Memoization in DP:** store sub-answers in a map/array (O(n) space) to avoid recomputing (saves exponential time).

The "right" answer depends on the constraints. If memory is tight, prefer O(1) space even if slower. If time is tight, spend memory for speed.

## In Your Own Words

1. What is the difference between time complexity and space complexity?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Time complexity measures how running time grows with input size n. Space complexity measures how extra memory (auxiliary space) grows with n. Both use Big-O. They're independent — an algorithm can be O(n) time and O(1) space (in-place reverse), or O(n) time and O(n) space (reverse into new array). Space usually means auxiliary space, not input size.

</details>

2. Why does recursion use O(n) space even if it allocates no arrays?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Because each recursive call pushes a stack frame (parameters, local variables, return address) onto the call stack. A recursion of depth n has n frames on the stack at once → O(n) space. Deep recursion (n = 10⁵) can cause StackOverflowError. This is why iterative versions are sometimes required.

</details>

3. What does "O(1) extra space" mean, and is a fixed array of size 26 O(1)?

<details>
<summary>Show Answer</summary>

**Sample Answer:** "O(1) extra space" means auxiliary memory that doesn't grow with n — a constant number of variables or a fixed-size structure. A fixed array of size 26 (e.g., for 26 lowercase letters) is O(1) because 26 doesn't change regardless of input size. It's still "constant" even though it's 26 bytes, not 1 byte.

</details>

4. In a problem that says "do not use extra space," what should you do?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use an in-place algorithm with O(1) auxiliary space — work within the input array using swaps/pointers, don't allocate new arrays or hash maps. E.g., reverse an array by swapping from both ends. If you genuinely need a hash map, the problem probably allows it; "no extra space" is a hard constraint you must respect.

</details>
