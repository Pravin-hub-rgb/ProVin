Before we write any Java code, we need to understand the shape of a Java program. If you open the next file, you'll see a full program with `import java.util.Scanner`, `public class`, `public static void main`, and more — but none of it is explained there. This file sets the premise first. We'll look at the template, fill in each piece one by one, and only then write a complete program.

Think of it like learning to drive: we look at where the steering wheel, pedals, and gears are before we start the engine.

## What is a class?

Everything in Java lives inside a **class**. You cannot write a loose function floating by itself like you can in JavaScript or Python. Every variable, every method, every line of logic must belong to a class.

Think of a class as a **blueprint**. A house blueprint is not a house you can live in — it's the plan for making houses. From one blueprint, you can build many identical houses. Each house built from that blueprint is called an **object** (or an instance).

In Java:

```java
public class Calculator {
}
```

`Calculator` is the class name. By convention, class names start with a capital letter — `Calculator`, `Student`, `BankAccount`. The file must be saved as `Calculator.java` if the class is `public class Calculator`.

## How to define a class — the template

Here is the template for defining a class:

```
access_modifier class ClassName {
    // everything goes inside here
}
```

- **`access_modifier`** — controls who can see and use this class. Most commonly `public`.
- **`class`** — the keyword that tells Java "this is a class."
- **`ClassName`** — the name you give the class.

For example:

```java
public class Calculator {
}
```

This defines a `public` class named `Calculator`. Because it's `public`, other classes and even the JVM itself can see and use it.

## Why the filename must match the class name

Here is a rule Java enforces strictly: **if your class is declared `public class Calculator`, the file must be named `Calculator.java`.** The class name and the filename must match exactly, including capitalization.

Why? When you compile with `javac`, the Java compiler looks at the filename to find the `public` class inside it. If they don't match — say, `public class Calculator` is in a file named `calc.java` — the code won't compile.

## Objects — creating something from the blueprint

A class is just a blueprint. To actually *use* it, you create an **object** from it. This is like building a house from the blueprint.

Here is the template for creating an object:

```java
ClassName objectName = new ClassName();
```

- **`ClassName`** (first one) — the type of object you're creating.
- **`objectName`** — the variable name you give this specific object.
- **`new ClassName()`** — creates a fresh object from the `ClassName` blueprint.

Example:

```java
Calculator calc = new Calculator();
```

This creates a `Calculator` object named `calc`. Once you have an object, you can access what's inside it using the dot operator (`.`):

```java
calc.someMethod();
```

## Why we don't create an object of the outer class

You might wonder: if everything in Java lives inside a class, and we create objects from classes, why doesn't the `Hello` class in `public class Hello` get turned into an object automatically?

Here is the answer: the outer class (`public class Hello`) is a **container**, not something you need to build. It holds the program's entry point — the `main` method. The JVM calls `main` directly, without needing you to create a `Hello` object first.

We'll cover creating objects and calling methods on them properly in **1.8 Classes & Objects**. For now, just remember: the outer class is a container; `main` is where execution begins.

## Access modifiers — controlling who can see what

Before we look at `main`, let's understand access modifiers properly, because they appear everywhere in Java.

An **access modifier** is a keyword placed before a class, method, or variable to control who can access it.

| Modifier | Who can access it |
|----------|-------------------|
| `public` | Anyone — other classes, other files, the JVM |
| `private` | Only code inside the same class |
| `protected` | This class and its subclasses (we'll cover subclasses later) |
| (none) | Only classes in the same package |

Java uses these for **safety**. Imagine a `BankAccount` class. You'd want the `balance` to be `private` so no other code can change it directly. You'd provide a `public` method like `deposit()` that checks the amount is positive before adding it. This is called **encapsulation** — hiding internal details and exposing only what's needed.

## The `main` method — the program's entry point

Every Java program needs a starting point. The JVM looks for exactly this:

```java
public static void main(String[] args)
```

Let's look at the **template** first. A method in Java looks like this:

```
access_modifier static return_type method_name(parameters)
```

- **`access_modifier`** — who can call this method (`public`, `private`, etc.)
- **`static`** — whether the method can run without creating an object first
- **`return_type`** — what kind of value the method gives back (`void` means nothing, `int` means a whole number, `String` means text, etc.)
- **`method_name`** — the name you give the method
- **`parameters`** — inputs the method accepts, inside parentheses

Now let's fill in each piece of `public static void main(String[] args)`:

### `public` — access modifier

`public` means the JVM can call this method from outside the class. The JVM is not inside your `Hello` class, so `main` must be `public` for the JVM to reach it.

### `static` — runs without an object

`static` means the JVM can run this method **without creating an object** of the class first.

Which class? **The outer class** — the class inside which `main` is declared. In `public class Welcome { ... }`, the outer class is `Welcome`.

Normally, if you want to call a method that lives inside a class, you have to build an object from that class first:

```java
Welcome w = new Welcome();   // build an object from the Welcome blueprint
w.someMethod();              // call a method on that object
```

But `main` is `static`, so the JVM skips the object-building step. It calls `main` directly on the `Welcome` class itself:

```
Welcome.main(...)   // JVM calls this directly — no `new Welcome()` needed
```

The JVM calls `main` before any objects exist, so `main` must be `static`. If it weren't `static`, the JVM would have to create a `Welcome` object first, but it doesn't know how to do that yet — it's just starting the program.

### `void` — return type

`void` is the **return type** — it tells Java what kind of value the method gives back when it finishes. `void` means "nothing." The `main` method doesn't return a value to the JVM; it just runs and ends.

If a method returned a whole number, its return type would be `int`. If it returned text, it would be `String`. `main` returns nothing, so it's `void`.

### `main` — the method name

`main` is simply the **name** of the method. The JVM is hardcoded to search for a method named exactly `main`. It must be spelled `main` — not `Main`, not `run`, not `start`.

### `(String[] args)` — parameters

The parentheses hold the method's **parameters** — inputs it accepts. `String[] args` means "an array of text values named `args`." These are values you can pass when running the program from the terminal. For now, you can leave it as is and not worry about it.

## Putting it all together — a complete program

Now that we know every piece, here is a complete, minimal Java program:

```java
public class Welcome {
    public static void main(String[] args) {
        System.out.println("Welcome to Java DSA!");
    }
}
```

Let's map each line to what we just learned:

- `public class Welcome` — a `public` class named `Welcome`. The file must be `Welcome.java`.
- `public static void main(String[] args)` — the entry point. `public` lets the JVM call it, `static` lets it run without an object, `void` returns nothing, `main` is the name the JVM looks for, and `(String[] args)` holds terminal inputs.
- `System.out.println("Welcome to Java DSA!");` — prints text to the console. `System` is a built-in Java class, `out` is the output stream, and `println` prints a line of text.

Save this as `Welcome.java`, then compile and run:

```bash
javac Welcome.java
java Welcome
```

You should see `Welcome to Java DSA!` printed in the terminal.
