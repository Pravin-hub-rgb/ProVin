# 1.1 Java Setup & How It Runs

Before writing any Java, you need to understand what you're actually running. Java has three layers, and beginners confuse them constantly. Get this right once and it never confuses you again.

---

## The Three Layers: JDK, JRE, JVM

Three components, nested:

- **JVM (Java Virtual Machine)** — the engine that actually runs your Java code. It reads bytecode and translates it into machine instructions for your specific OS (Windows, Mac, Linux). You never install the JVM alone.
- **JRE (Java Runtime Environment)** — JVM plus the standard libraries (String, Math, System, etc.) your code needs to run. Enough to *run* Java programs, not to write them.
- **JDK (Java Development Kit)** — JRE plus the compiler (`javac`) and other developer tools. To *write and compile* Java, you need the JDK.

**In one line:** JDK contains JRE, JRE contains JVM. As a developer you always install the **JDK**.

### Why Java has this split (the big idea)

Java code is **compiled once, run anywhere**. You write `.java` → compile to `.class` (bytecode) → the JVM on any machine runs that bytecode. That's why the same `.class` file runs on Windows, Mac, and Linux without recompiling. The JVM is the translator that makes this possible.

```
You write:     Hello.java   (human-readable source)
Compiler:      javac Hello.java   →   Hello.class  (bytecode, platform-independent)
Run:           java Hello   →   JVM reads Hello.class → runs on your OS
```

### What It Is NOT

- JVM is **not** a compiler. It runs bytecode; `javac` compiles source to bytecode.
- JRE is **not** enough to develop. Without `javac` (in the JDK) you can't compile your own code.
- "Java is interpreted" is a half-truth. It's compiled to bytecode first, then the JVM interprets/JIT-compiles that bytecode.

## Installing Java

1. Download the JDK from [adoptium.net](https://adoptium.net) (Temurin) or Oracle. Pick the latest LTS (Java 17 or 21).
2. Install it. Note the install path (e.g., `C:\Program Files\Eclipse Adoptium\jdk-21...`).
3. Set `JAVA_HOME` to that path, and add `%JAVA_HOME%\bin` (or `$JAVA_HOME/bin`) to your `PATH`.
4. Verify in a terminal:

```bash
java -version      # should print the Java version
javac -version     # should print the compiler version
```

If both print a version, you're ready. If `javac` is "not recognized", your PATH is wrong — fix that before anything else.

### IDE

You can write Java in Notepad, but use an IDE: **IntelliJ IDEA Community** (free, best for Java) or **VS Code + Extension Pack for Java**. The IDE handles compile/run with one click and shows errors inline.

## Your First Program

Create a file named `Hello.java` (the file name must match the public class name):

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, DSA!");
    }
}
```

Run it two ways:

```bash
# Terminal way
javac Hello.java     # compiles → Hello.class
java Hello           # runs → prints "Hello, DSA!"

# IDE way: click "Run" — it does both steps for you
```

### Line-by-line

- `public class Hello` — declares a class named `Hello`. The file must be named `Hello.java`.
- `public static void main(String[] args)` — the **entry point**. Every Java program starts here. The JVM looks for exactly this signature. `String[] args` holds command-line arguments.
- `System.out.println(...)` — prints a line to the console. `System` is a class, `out` is a static field (a PrintStream), `println` prints + newline.

### Things that go wrong here

- **File name mismatch:** class `Hello` must be in `Hello.java`. `hello.java` (lowercase) fails on case-sensitive systems.
- **`main` signature typo:** `public static void main(String args[])` works, but `public void main(...)` or `static void main(...)` (missing `public`) won't be found by the JVM.
- **Running `java Hello.java`** compiles-and-runs in one step (Java 11+), but the classic way is `javac` then `java`. In interviews/LeetCode you just write the class.
- **Forgetting the semicolon** — Java requires `;` at the end of every statement.

## How LeetCode / interview platforms expect your code

On LeetCode you don't write `main`. You write a class (usually `Solution`) with a method:

```java
class Solution {
    public int add(int a, int b) {
        return a + b;
    }
}
```

The platform calls your method with test inputs and checks the output. So learn the `class Solution { public ... method(...) }` shape — that's what you'll write 90% of the time.

## In Your Own Words

1. What is the difference between JDK, JRE, and JVM?

**Sample Answer:** JVM is the engine that runs bytecode. JRE is JVM + standard libraries (enough to run programs). JDK is JRE + compiler and dev tools (needed to write/compile code). JDK contains JRE, JRE contains JVM. As a developer you install the JDK. "Compiled once, run anywhere" works because bytecode is platform-independent and the JVM on each OS translates it.

2. Why must the file name match the public class name?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Java's compiler and JVM use the file name to locate the class. A `public class Hello` must live in `Hello.java`. Mismatch causes a compile error ("class Hello is public, should be declared in a file named Hello.java"). On case-sensitive systems, `hello.java` ≠ `Hello.java`.

</details>

3. What does `public static void main(String[] args)` do, and why that exact signature?

<details>
<summary>Show Answer</summary>

**Sample Answer:** It's the entry point — the JVM starts execution here. `public` so the JVM can access it from outside, `static` so it runs without creating an object, `void` because it returns nothing, `String[] args` for command-line arguments. The JVM specifically looks for this signature; change it and the program won't run.

</details>

4. What's the difference between `javac` and `java`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `javac` is the compiler — turns `.java` source into `.class` bytecode. `java` is the launcher — starts the JVM to run the bytecode. Compile first (`javac`), then run (`java`). Java 11+ also lets you run a single file directly with `java Hello.java`, which compiles in memory.

</details>
