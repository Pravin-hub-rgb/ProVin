# 1.10 LeetCode Format & Common Pitfalls

You know Java basics now. This module covers the **shape of interview code** (how LeetCode/platforms expect your solution) and the **pitfalls that cause silent bugs**. Read it once; come back when something breaks.

---

## How LeetCode Expects Your Code

You do **not** write `main`. You write a class (usually `Solution`) with a method. The platform instantiates your class, calls your method with test inputs, and checks the return value.

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        // your code
        return new int[]{i, j};
    }
}
```

**Rules of the shape:**
- Class is usually `Solution` (or `Main` on some platforms). Don't add `public` to the class on LeetCode — it can cause issues; `class Solution` is fine.
- Method signature must match exactly (name, parameter types, return type). The platform calls it by name.
- Return the result; don't print it. `System.out.println` in a solution is wrong (and slows you down).
- Don't read input with `Scanner` — inputs arrive as method parameters.
- Helper methods can be `private` or package-private; make them `static` if they don't use instance state.

### Common method signatures you'll write

```java
// Array problems
public int findMax(int[] nums)
public int[] twoSum(int[] nums, int target)
public void sortColors(int[] nums)          // in-place, void return

// String problems
public boolean isPalindrome(String s)
public String reverseWords(String s)

// Linked list
public ListNode reverseList(ListNode head)

// Tree
public TreeNode invertTree(TreeNode root)
public int maxDepth(TreeNode root)

// Graph
public boolean canFinish(int numCourses, int[][] prerequisites)
```

**Return type matters:** if the problem says "return the modified array," return `int[]`. If it says "modify in place," return `void`. Match the platform's expected signature exactly — check the problem's "Java" tab.

## The 10 Most Common Pitfalls

### 1. Comparing Strings with `==`

```java
String a = "Vin";
String c = new String("Vin");
System.out.println(a == c);       // false (different objects!)
System.out.println(a.equals(c));   // true  (same content)
```

**Fix:** always `.equals()` (or `.equalsIgnoreCase()`) for content. `==` compares references.

### 2. Integer overflow

```java
int a = 2_000_000_000;
int b = 2_000_000_000;
System.out.println(a + b);   // -294967296 — silently wrong!
```

**Fix:** use `long` for sums/products/counts when n ≥ 10⁵. Add `L` suffix to literals. Cast before multiplying: `(long) a * b`.

### 3. Integer division

```java
int x = 5 / 2;              // 2, not 2.5
double y = (double) 5 / 2;  // 2.5
```

**Fix:** cast one operand to `double` *before* dividing. Casting after (`(double)(5/2)`) is too late.

### 4. `arr.length` vs `s.length()`

```java
int[] arr = {1,2,3};
System.out.println(arr.length);    // field, no parens
String s = "abc";
System.out.println(s.length());    // method, with parens
```

Arrays use a field; Strings use a method. The compiler catches the wrong one — but know which is which.

### 5. Off-by-one in loops

```java
for (int i = 0; i <= arr.length; i++)  // WRONG: arr.length is out of bounds
for (int i = 0; i < arr.length; i++)   // RIGHT
```

Last valid index is `length - 1`. Condition is `< length`, never `<=`.

### 6. Null pointer (NullPointerException)

```java
String s = null;
System.out.println(s.length());   // NPE! program crashes
```

**Fix:** check `if (s == null)` before using. In DSA, check for null nodes in linked lists/trees: `if (node == null) return ...;`.

### 7. Mutating while iterating

```java
List<Integer> list = new ArrayList<>(Arrays.asList(1,2,3,4,5));
for (int i = 0; i < list.size(); i++) {
    if (list.get(i) == 3) list.remove(i);   // indices shift → skips elements / ConcurrentModification
}
```

**Fix:** iterate backwards, or collect indices to remove, or use `Iterator.remove()`, or build a new list.

### 8. Reference vs value (aliasing)

```java
int[] a = {1,2,3};
int[] b = a;            // NOT a copy — same array
b[0] = 99;
System.out.println(a[0]); // 99 — a changed too!
```

**Fix:** `int[] b = Arrays.copyOf(a, a.length);` or `a.clone()`.

### 9. Forgetting `break` in switch

Falls through to the next case. Always add `break` unless you intend fall-through.

### 10. Recursion without a base case

```java
static int bad(int n) {
    return n + bad(n - 1);   // no base case → StackOverflowError
}
```

**Fix:** always define the base case first, and ensure the recursive call moves *toward* it (n decreases, or range halves).

## A Worked End-to-End Example

Problem: "Given an array of integers, return indices of two numbers that add up to target."

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        // HashMap: value → index
        java.util.Map<Integer, Integer> seen = new java.util.HashMap<>();

        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];
            if (seen.containsKey(complement)) {
                return new int[]{ seen.get(complement), i };
            }
            seen.put(nums[i], i);
        }
        return new int[]{};   // no solution (problem guarantees one exists)
    }
}
```

**Line-by-line:**
- `seen` maps a value to its index — O(1) lookup.
- For each element, compute `complement = target - nums[i]`. If complement was seen before, we found the pair.
- Store current value → index for future complements.
- Return `new int[]{a, b}` — array literal syntax.
- Time: O(n) (one pass). Space: O(n) (hash map).

This is the classic "brute force O(n²) → hashmap O(n)" optimization. Brute force: nested loops checking all pairs. Optimized: one pass with a hash map. This pattern (lookup table) appears in dozens of problems.

## Quick Pre-Submission Checklist

Before submitting on LeetCode, verify:
- [ ] Method signature matches the problem's expected (name, params, return type).
- [ ] Return type is correct (int vs int[], void for in-place).
- [ ] No `System.out.println` in the solution.
- [ ] Edge cases handled: empty array, single element, all same, negatives, zero.
- [ ] No overflow (use `long` where needed).
- [ ] String comparisons use `.equals()`.
- [ ] Array bounds: `< length`, last index `length - 1`.
- [ ] Null checks for linked list/tree nodes.
- [ ] Recursion has a base case.

3. How do you handle the "modify in place, O(1) space" constraint?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Work within the input array using swaps/pointers without allocating new arrays or hash maps. E.g., reverse by swapping from both ends. Don't allocate a copy. If the problem genuinely needs a hash map, the constraint usually allows it — but "O(1) extra space" is a hard limit you must respect.

</details>

Also verify the method returns correctly for the "not found" case (e.g., returning `-1` or an empty array per problem spec).
