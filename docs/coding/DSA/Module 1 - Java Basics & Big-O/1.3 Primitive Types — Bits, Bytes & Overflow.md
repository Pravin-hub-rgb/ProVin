Before we look at Java's primitive types, we need to answer one question: **what is a "byte," really?**

If you open your phone's predictive text, it suggests the next word based on what you typed. It doesn't understand English — it just remembers patterns of letters. A computer's memory works the same way: it doesn't "understand" numbers. It only stores patterns of switches that are either on or off.

## What is a bit?

A **bit** (short for "binary digit") is the smallest unit of data a computer can store. Think of it as a single light switch:

- **Off = 0**
- **On = 1**

That's all a bit can do. One switch. Two states.

## What is a byte?

Eight bits together make a **byte**. If one bit is one switch, a byte is eight switches side by side:

```
[0] [0] [0] [0] [0] [0] [0] [0]
```

Each switch can be 0 or 1, so eight switches give us 2⁸ = **256 different patterns**:

```
00000000, 00000001, 00000010, ... , 11111110, 11111111
```

**Important:** 256 is the count of combinations, not the biggest number. Because we start counting at 0, the biggest number we can store is **255** (0 through 255 is exactly 256 combinations).

Here is how the math works for all 8 bits set to 1:

```
2⁰ + 2¹ + 2² + 2³ + 2⁴ + 2⁵ + 2⁶ + 2⁷
= 1 + 2 + 4 + 8 + 16 + 32 + 64 + 128
= 255
```

So `11111111` = **255** if we treat it as an unsigned number.

## Splitting 256 into positive and negative

If we used all 256 patterns for unsigned counting, the range would be 0 to 255. But Java needs negative numbers too. So it splits the 256 patterns evenly:

**256 ÷ 2 = 128**

That gives 128 patterns for non-negative numbers (0 to 127) and 128 patterns for negative numbers (-1 to -128).

To make this split, Java reserves the **leftmost bit** as the sign bit:
- Leftmost bit `0` → positive (or zero)
- Leftmost bit `1` → negative

So 8 bits = 1 sign bit + 7 value bits, giving us:
- Non-negative: 0 to 127 (128 values)
- Negative: -1 to -128 (128 values)
- Total: 256 patterns, range **-128 to 127**

## The byte range: -128 to 127

Here is how the 256 patterns line up in Java's `byte`:

| Binary | Value |
|--------|-------|
| `00000000` | 0 |
| `00000001` | 1 |
| ... | ... |
| `01111110` | 126 |
| `01111111` | 127 ← biggest positive |
| `10000000` | -128 ← wraps HERE |
| `10000001` | -127 |
| ... | ... |
| `11111110` | -2 |
| `11111111` | -1 |

Notice something important: **after 127 comes -128, not 0.** The patterns wrap around like an odometer.

## Why `11111111` is -1, not 255

All-ones looks like it should be 255, but the leftmost bit is `1`, so Java reads it as negative. To decode a negative two's complement number:

1. Flip all bits
2. Add 1
3. Negate the result

Let's decode `11111111`:
- Flip: `00000000`
- Add 1: `00000001` = 1
- Negate: **-1**

So `11111111` = **-1**, not 255.

## Example: storing -5 in a byte

1. Start with positive 5: `00000101`
2. Flip all bits: `11111010`
3. Add 1: `11111011`

So **-5 = `11111011`**. Leftmost bit is `1` → negative. Decode: flip → `00000100` = 4, +1 = 5, negate → **-5**.

## What happens with `byte b = 132`?

132 in binary is `10000100`. The leftmost bit is `1`, so Java treats it as negative.

To find the value: count 4 steps from -128:
- `10000000` = -128
- `10000001` = -127
- `10000010` = -126
- `10000011` = -125
- `10000100` = **-124**

So `byte b = 132` wraps around to **-124**.

```java
byte b = (byte) 132;  // b is -124, not 132! Silent wraparound.
```

Without the cast, `byte b = 132;` is a **compile error** because 132 doesn't fit in a signed byte.

## The full primitive type table

| Type | Size | Bits | Range | Use for |
|------|------|------|-------|---------|
| `byte` | 1 byte | 8 bits | -128 to 127 | tiny numbers, raw bytes |
| `short` | 2 bytes | 16 bits | -32,768 to 32,767 | rarely used |
| `int` | 4 bytes | 32 bits | ~-2.1 billion to 2.1 billion | default whole numbers |
| `long` | 8 bytes | 64 bits | ~-9.2 quintillion to 9.2 quintillion | big counts, timestamps |
| `float` | 4 bytes | 32 bits | ~6-7 decimal digits | rarely used (precision issues) |
| `double` | 8 bytes | 64 bits | ~15-16 decimal digits | default decimals |
| `char` | 2 bytes | 16 bits | one Unicode character | one character |
| `boolean` | 1 bit (conceptually) | — | true / false | yes/no flags |

**Rule of thumb:** use `int` for whole numbers and `double` for decimals unless you have a reason not to. Use `long` when numbers exceed ~2 billion.

## Why sizes matter: integer overflow

An `int` holds up to ~2.1 billion. Add two large ints and you **silently wrap around** to a negative number — no error, no warning.

```java
int a = 2_000_000_000;
int b = 2_000_000_000;
System.out.println(a + b);   // -294967296  ← WRONG, overflowed!
```

**Fix:** use `long` when values can exceed ~2 billion.

```java
long a = 2_000_000_000L;
long b = 2_000_000_000L;
System.out.println(a + b);   // 4000000000  ← correct
```

## What it is NOT

A `byte` is **not** 4 bits. It is 8 bits. Four bits is sometimes called a "nibble" (half a byte), but Java has no primitive type that small.

`byte` is **not** unsigned 0 to 255. Java's `byte` is always signed (-128 to 127). If you need 0 to 255, you must use `int` and manage the range yourself.

## A Small Program: Check Byte Limits

```java
public class ByteLimits {
    public static void main(String[] args) {
        byte max = 127;
        byte min = -128;

        System.out.println("Max byte: " + max);   // 127
        System.out.println("Min byte: " + min);   // -128

        // What happens if we go one past max?
        byte overflow = (byte) (max + 1);
        System.out.println("127 + 1 = " + overflow); // -128 (wraps around!)

        // What happens with 132?
        byte weird = (byte) 132;
        System.out.println("(byte) 132 = " + weird); // -124
    }
}
```

**Line-by-line:**
- `byte max = 127;` — largest positive value a byte can hold.
- `byte min = -128;` — most negative value a byte can hold.
- `byte overflow = (byte) (max + 1);` — `max + 1` is 128, which doesn't fit in a byte, so we cast it and Java wraps it to -128.
- `byte weird = (byte) 132;` — 132 doesn't fit, so Java decodes the bit pattern `10000100` as -124.
