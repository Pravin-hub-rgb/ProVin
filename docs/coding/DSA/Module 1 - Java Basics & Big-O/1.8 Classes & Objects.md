Java is object-oriented. In DSA you won't build big class hierarchies, but you *will* write small classes. This module covers exactly the class-and-object part, plus interfaces.

---

## Class and Object

A **class** is a type definition; an **object** is an instance of that type.

```java
public class Dog {
    // Fields (state)
    String name;
    int age;

    // Constructor (how to build one)
    public Dog(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Method (behavior)
    public void bark() {
        System.out.println(name + " says woof!");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog d1 = new Dog("Rex", 3);   // create object
        Dog d2 = new Dog("Max", 5);

        d1.bark();   // "Rex says woof!"
        d2.bark();   // "Max says woof!"
    }
}
```

**Line-by-line:**
- `class Dog { ... }` — the type definition. Holds fields (data) and methods (behavior).
- `String name; int age;` — instance fields; each object gets its own copy.
- Constructor `Dog(String name, int age)` — runs when you write `new Dog(...)`. `this.name = name` assigns the parameter to the field (`this` = "this object").
- `new Dog("Rex", 3)` — creates an object in memory and returns a reference to it.
- `d1.bark()` — calls the method on object `d1`.

### this keyword

`this` refers to the current object. Use it to disambiguate field vs parameter when they share a name (as above).

---

## static vs instance

- **Instance (non-static):** belongs to an object. Needs `new`. Fields/methods that describe one object's state. `d1.bark()` is instance.
- **Static:** belongs to the class itself. No object needed. `Math.max(a, b)`, `System.out`. Shared across all instances.

```java
public class Counter {
    static int total = 0;     // shared by all instances
    int id;                  // per-object

    Counter() {
        total++;
        id = total;
    }
}
```

**In DSA:** utility methods are often `static` (no object state). LeetCode's `Solution` methods are instance (non-static) because the platform instantiates `Solution`.

## Interface

A **class** is a blueprint with actual code inside — fields and methods that do things.

An **interface** is different. It only lists **what methods must exist**, but it does **not** provide the code inside them. It's a contract: "any class that says it is this interface must provide these methods."

You cannot create an object from an interface:

```java
Drawable d = new Drawable();   // ERROR — interface can't be instantiated
```

Here is how you define an interface:

```java
interface Drawable {
    void draw();   // no method body — just the signature
}
```

`draw()` has no `{ }` block. The interface just says: "any class that is `Drawable` must have a `draw` method."

A class says it follows the interface using `implements`:

```java
class Circle implements Drawable {
    public void draw() {
        System.out.println("Drawing a circle");
    }
}

class Square implements Drawable {
    public void draw() {
        System.out.println("Drawing a square");
    }
}
```

Both `Circle` and `Square` provide their own code for `draw`. Because they implement `Drawable`, you can store them in a variable typed as `Drawable`:

```java
Drawable d1 = new Circle();   // OK — Circle is a Drawable
Drawable d2 = new Square();   // OK — Square is a Drawable
d1.draw();   // "Drawing a circle"
d2.draw();   // "Drawing a square"
```

You cannot do the reverse:

```java
Drawable d = new Drawable();   // ERROR — interface can't be instantiated
```

### Interface vs class

| | Class | Interface |
|---|-------|-----------|
| Can you `new` it? | Yes | No |
| Has method bodies? | Yes | No (only signatures) |
| Keyword | `class` | `interface` |
| How a class joins it | — | `implements` |
### Why interfaces matter

An interface lets you treat different objects the same way, as long as they implement the same interface. You can write one method that accepts `Drawable` and it will work with `Circle`, `Square`, or any other class that implements `Drawable`.

## A Small Program: Bank Account

A small, non-DSA example that ties class, object, constructor, `this`, fields, and methods together:

```java
public class BankAccount {
    String owner;
    double balance;

    BankAccount(String owner, double initialBalance) {
        this.owner = owner;
        this.balance = initialBalance;
    }

    void deposit(double amount) {
        if (amount > 0) {
            balance = balance + amount;
            System.out.println(owner + " deposited " + amount + ". New balance: " + balance);
        }
    }

    void withdraw(double amount) {
        if (amount > 0 && amount <= balance) {
            balance = balance - amount;
            System.out.println(owner + " withdrew " + amount + ". New balance: " + balance);
        } else {
            System.out.println("Cannot withdraw " + amount + ". Insufficient funds.");
        }
    }

    void showBalance() {
        System.out.println(owner + "'s balance: " + balance);
    }

    public static void main(String[] args) {
        BankAccount a = new BankAccount("Vin", 1000);
        BankAccount b = new BankAccount("Ana", 500);

        a.showBalance();   // Vin's balance: 1000.0
        b.showBalance();   // Ana's balance: 500.0

        a.deposit(200);    // Vin deposited 200.0. New balance: 1200.0
        b.withdraw(700);   // Cannot withdraw 700.0. Insufficient funds.
        b.withdraw(200);   // Ana withdrew 200.0. New balance: 300.0

        a.showBalance();   // Vin's balance: 1200.0
        b.showBalance();   // Ana's balance: 300.0
    }
}
```

**Line-by-line:**

- `BankAccount(String owner, double initialBalance)` — constructor. Runs when you write `new BankAccount(...)`. Sets the owner and starting balance.
- `this.owner = owner` — `this.owner` is the field inside the object; `owner` (no `this.`) is the parameter passed in. `this` distinguishes them.
- `void deposit(double amount)` — a method that belongs to the object. Each account has its own balance, so depositing into `a` doesn't affect `b`.
- `BankAccount a = new BankAccount("Vin", 1000)` — creates one account object named `a`.
- `BankAccount b = new BankAccount("Ana", 500)` — creates a second, independent account object named `b`.
- `a.deposit(200)` — calls `deposit` on object `a` only; object `b` is untouched.

This shows why objects matter: each `BankAccount` is independent, with its own `owner` and `balance`. A class is the blueprint; each `new` call builds a separate object from it.

## In Your Own Words

1. What is the difference between a class and an object?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A class is a type definition defining fields and methods. An object is an instance created from that type using `new`. The class exists once in code; you can create many objects from it, each with its own field values. E.g., `class Dog` is the type; `new Dog("Rex", 3)` creates one object.

</details>

2. What is an interface, and how is it different from a class?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A class is a blueprint with actual code — fields and methods with bodies that do things. An interface only lists method signatures (no bodies); it's a contract saying "any class that implements me must provide these methods." You can `new` a class but not an interface. A class joins an interface with `implements`.

</details>

3. What's the difference between static and instance members?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Instance (non-static) members belong to an object — need `new`, each object has its own copy. Static members belong to the class itself — no object needed, shared across all instances (e.g., `Math.max`, `Counter.total`). In `main`-based programs, helper methods must be `static`. In LeetCode's `Solution`, methods are instance because the platform creates the object.

</details>
