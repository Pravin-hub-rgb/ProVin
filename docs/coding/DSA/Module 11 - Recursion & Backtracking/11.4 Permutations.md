# 11.4 Permutations

**Problem:** Given an array of distinct integers, return all possible permutations. (LeetCode #46)

**Link:** https://leetcode.com/problems/permutations/

---

## Which Technique, and Why?

"Generate all permutations" → **Backtracking with a used array**. Track which elements are used; at each position, try each unused element. O(n × n!) time, O(n) space.

**Signal in the problem:** "permutations" / "all arrangements" / "rearrangements" → backtracking with a `used` boolean array.

## Approach

Backtrack with `used[]`. Base: `current.size() == n` → record copy. For each element: if not used, mark used, add, recurse, undo (remove + unmark).

## Pseudocode

```
result = []
used = boolean array (size n)
backtrack(nums, used, [], result)
return result

backtrack(nums, used, current, result):
    if current.size == nums.length: result.add(copy); return
    for i from 0 to nums.length-1:
        if used[i]: continue
        used[i] = true
        current.add(nums[i])
        backtrack(nums, used, current, result)
        current.remove(last)
        used[i] = false
```

## Java Code

```java
class Solution {
    public List<List<Integer>> permute(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        boolean[] used = new boolean[nums.length];
        backtrack(nums, used, new ArrayList<>(), result);
        return result;
    }

    private void backtrack(int[] nums, boolean[] used, List<Integer> current, List<List<Integer>> result) {
        if (current.size() == nums.length) {
            result.add(new ArrayList<>(current));
            return;
        }
        for (int i = 0; i < nums.length; i++) {
            if (used[i]) continue;
            used[i] = true;
            current.add(nums[i]);
            backtrack(nums, used, current, result);
            current.remove(current.size() - 1);
            used[i] = false;
        }
    }
}
```

## Line-by-line

- `used[i]` — tracks which elements are in the current permutation.
- `if (used[i]) continue` — skip already-used elements.
- `used[i] = true` / `current.add(nums[i])` — choose.
- `backtrack(...)` — explore (next position).
- `current.remove(...)` / `used[i] = false` — undo.

## Complexity

- Time: O(n × n!) — n! permutations, each takes O(n) to build.
- Space: O(n) — recursion stack + used array (+ output).

## Common Mistakes

- **Not undoing `used[i]`.** Must set `used[i] = false` after recursion, or the element stays "used" for sibling branches.
- **Storing references.** Use `new ArrayList<>(current)` when recording.
- **Using a set instead of a boolean array.** Works but slower. Boolean array is O(1) per check.
- **Not handling duplicates.** This problem assumes distinct elements. For duplicates, see Permutations II (11.6).

## How to Explain (interview)

**Opening:** Permutations generates all arrangements of an array. Backtracking with a `used` boolean array: at each position, try each unused element, mark used, recurse, undo. O(n × n!) time. Each element used exactly once per permutation.

**The basic flow:**
```java
boolean[] used = new boolean[n];
void backtrack(List<Integer> cur) {
    if (cur.size() == n) { result.add(new ArrayList<>(cur)); return; }
    for (int i = 0; i < n; i++) {
        if (used[i]) continue;
        used[i] = true; cur.add(nums[i]);
        backtrack(cur);
        cur.remove(cur.size() - 1); used[i] = false;
    }
}
```

**The part that trips everyone up:** you must undo **both** `current.remove(...)` and `used[i] = false`. Forgetting either corrupts sibling branches. Also, for arrays with duplicates, see Permutations II (skip condition).

**The mistakes to remember:**
- Forgetting to undo `used[i]`
- Storing references instead of copies
- Not handling duplicates (different problem)
- Using a Set instead of boolean array (slower)
