## The Core Idea

**Backtracking** is recursion + undo: try a choice, recurse, then undo the choice so the next iteration starts clean.

**The three steps (repeated for every choice):**
1. **Choose** — make a decision (add an element).
2. **Explore** — recurse with the new state.
3. **Undo** — remove the choice so the next iteration tries a different one.

Used for: subsets, permutations, combinations, N-Queens, Sudoku, word search.

## How to Recognize It

Think "Backtracking" when:
- The problem asks for **all** combinations/permutations/subsets.
- You need to **try choices and undo** (N-Queens, Sudoku, word search).
- Keywords: "all possible," "generate," "combinations," "permutations," "subsets."

**Signal words:** "generate all," "all possible," "combinations," "permutations," "subsets," "backtrack."

## Worked Example: Subsets (backtracking)

**Problem:** Given an array, return all subsets.

```java
class Solution {
    public List<List<Integer>> subsets(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        backtrack(nums, 0, new ArrayList<>(), result);
        return result;
    }

    private void backtrack(int[] nums, int start, List<Integer> current, List<List<Integer>> result) {
        result.add(new ArrayList<>(current));  // record current subset (copy!)

        for (int i = start; i < nums.length; i++) {
            current.add(nums[i]);               // 1. choose
            backtrack(nums, i + 1, current, result); // 2. explore
            current.remove(current.size() - 1);  // 3. undo
        }
    }
}
```

**Line-by-line:**
- `result.add(new ArrayList<>(current))` — record a copy at every node (including the empty set).
- `for (int i = start; ...)` — try each remaining element as the next choice.
- `current.add(nums[i])` — choose.
- `backtrack(nums, i + 1, ...)` — recurse with the next starting index (avoid reusing the same element).
- `current.remove(...)` — undo the choice so the next iteration starts clean.

**Key insight:** the "choose → explore → undo" pattern. The recursion explores all combinations; the undo ensures each branch starts from a clean state.

## Common Mistakes

- **Forgetting to undo.** After the recursive call, remove the choice (`current.remove(...)`) or state leaks into sibling branches.
- **Storing references instead of copies.** `result.add(current)` stores a reference — later modifications corrupt stored results. Use `new ArrayList<>(current)`.
- **Not shrinking the problem.** If the recursive call doesn't reduce the input, infinite recursion.
- **Deep recursion → StackOverflow.** For large inputs, recursion depth can overflow. Use iterative or increase stack size.

## How to Explain (interview)

**Opening:** Backtracking is recursion + undo: choose, explore, undo. Used for generating all subsets, permutations, combinations. The "choose → explore → undo" pattern ensures each branch starts clean. Time depends on branching (O(2^n) for subsets); space is O(depth) for the call stack.

**The basic flow:**
```java
void backtrack(int[] nums, int start, List<Integer> current, List<List<Integer>> result) {
    result.add(new ArrayList<>(current));  // record
    for (int i = start; i < nums.length; i++) {
        current.add(nums[i]);               // choose
        backtrack(nums, i + 1, current, result); // explore
        current.remove(current.size() - 1);  // undo
    }
}
```

**The part that trips everyone up:** **undo** the choice after the recursive call (`current.remove(...)`) and **copy** the list when storing (`new ArrayList<>(current)`). Forgetting either corrupts results.

**The mistakes to remember:**
- Forgetting to undo (state leaks into sibling branches)
- Storing references instead of copies (mutated results)
- Not shrinking the problem (infinite recursion)
- Deep recursion on large inputs (stack overflow)
