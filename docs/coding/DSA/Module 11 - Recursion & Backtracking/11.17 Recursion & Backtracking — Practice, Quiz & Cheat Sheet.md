## Mini Quiz

1. What are the two essential parts of every recursive function?
2. What happens if a recursive function has no base case?
3. In backtracking, what are the three steps in the loop?
4. Why must you copy the list (`new ArrayList<>(current)`) when storing a subset?
5. What is the time complexity of generating all subsets of an array of size n?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. Base case (when to stop) and recursive case (how to shrink the problem and call yourself). Without the base case, infinite recursion ? StackOverflowError. Without shrinking, the recursive call never reaches the base case.
2. Infinite recursion ? `StackOverflowError`. The call stack grows until it exceeds the JVM's stack size limit. Always define a base case that is reachable.
3. Choose (add the element), Explore (recurse with the next starting index), Undo (remove the element to try a different choice). This "choose ? explore ? undo" pattern is the backbone of all backtracking.
4. Because `result.add(current)` stores a reference. Later modifications to `current` (in other branches) would change the stored subset. Copying with `new ArrayList<>(current)` creates an independent snapshot.
5. O(2^n) — there are 2^n subsets, and generating each takes O(n) (copying). Total O(n × 2^n). Space: O(n) for the recursion stack (depth) plus O(n × 2^n) for storing all subsets.

</details>

## One-Page Cheat Sheet

**Recursion template:**
```java
ReturnType solve(Input input) {
    if (base case) return base result;    // stop condition
    // shrink the problem
    ReturnType sub = solve(smaller input);
    return combine(input, sub);            // combine results
}
```

**Backtracking template (subsets):**
```java
void backtrack(int[] nums, int start, List<Integer> current, List<List<Integer>> result) {
    result.add(new ArrayList<>(current));   // record (copy!)
    for (int i = start; i < nums.length; i++) {
        current.add(nums[i]);               // choose
        backtrack(nums, i + 1, current, result); // explore
        current.remove(current.size() - 1);  // undo
    }
}
```

**Backtracking template (permutations, swap-based):**
```java
void backtrack(int[] nums, int start, List<List<Integer>> result) {
    if (start == nums.length) {
        result.add(new ArrayList<>(Arrays.asList(nums))); // or convert
        return;
    }
    for (int i = start; i < nums.length; i++) {
        swap(nums, start, i);          // choose
        backtrack(nums, start + 1, result); // explore
        swap(nums, start, i);          // undo
    }
}
```

**Complexities:** Subsets O(n × 2^n), Permutations O(n × n!), Combinations O(n × C(n,k)). Space: O(n) call stack (plus output storage).

## In Your Own Words

1. What is the difference between recursion and backtracking?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Recursion is a function calling itself to solve a smaller problem (divide and conquer, tree traversal). Backtracking is recursion + undo: you make a choice, recurse, then undo the choice if it doesn't lead to a solution. All backtracking is recursion, but not all recursion is backtracking. Recursion solves one problem; backtracking explores all possibilities.

</details>

2. Why must you copy the list when storing a subset in backtracking?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Because `result.add(current)` stores a reference to the same list object. Later modifications to `current` (in other branches) would change the stored subset. Using `new ArrayList<>(current)` creates an independent copy (snapshot) at that moment, preserving the correct state.

</details>

3. What happens if a recursive function has no base case?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Infinite recursion ? `StackOverflowError`. Each call pushes a frame onto the call stack; without a base case, the stack grows until it exceeds the JVM's limit. Always define a base case that is reachable (the recursive call must shrink the problem toward it).

</details>
