# 11.12 Generate Parentheses

**Problem:** Given n pairs of parentheses, generate all combinations of well-formed parentheses. (LeetCode #22)

**Link:** https://leetcode.com/problems/generate-parentheses/

---

## Which Technique, and Why?

"Generate all well-formed parentheses" → **Backtracking with constraints**. Track open and close counts. You can add '(' if open < n. You can add ')' if close < open. This pruning ensures well-formedness. O(4^n / √n) time (Catalan number).

**Signal in the problem:** "generate all valid/well-formed parentheses" → backtracking with open/close count constraints.

## Approach

Backtrack with `open` and `close` counts. At each step:
- If `open < n`: add '(', recurse with open+1, then undo.
- If `close < open`: add ')', recurse with close+1, then undo.
- Base: `open == n && close == n` → record.

## Pseudocode

```
result = []
backtrack("", 0, 0, n, result)
return result

backtrack(current, open, close, n, result):
    if open == n and close == n: result.add(current); return
    if open < n:
        backtrack(current + "(", open + 1, close, n, result)
    if close < open:
        backtrack(current + ")", open, close + 1, n, result)
```

## Java Code

```java
class Solution {
    public List<String> generateParenthesis(int n) {
        List<String> result = new ArrayList<>();
        backtrack("", 0, 0, n, result);
        return result;
    }

    private void backtrack(String current, int open, int close, int n, List<String> result) {
        if (open == n && close == n) {
            result.add(current);
            return;
        }
        if (open < n) {
            backtrack(current + "(", open + 1, close, n, result);
        }
        if (close < open) {
            backtrack(current + ")", open, close + 1, n, result);
        }
    }
}
```

## Line-by-line

- `open` = number of '(' used so far. `close` = number of ')' used.
- `open < n` → we can still add '('. Recurse with open+1.
- `close < open` → we can add ')' (more opens than closes). Recurse with close+1.
- Base: `open == n && close == n` → all pairs used → record.
- The constraints ensure well-formedness: never more closes than opens, never more opens than n.

## Complexity

- Time: O(4^n / √n) — Catalan number C_n. Each valid combination has 2n characters.
- Space: O(n) — recursion depth (at most 2n).

## Common Mistakes

- **Adding ')' when `close >= open`.** This creates invalid sequences like ")(" or "())". The `close < open` guard prevents this.
- **Adding '(' when `open >= n`.** Would exceed n pairs. The `open < n` guard prevents this.
- **Using String concatenation in recursion.** `current + "("` creates a new String each time — O(n) per call. For n ≤ 8, this is fine. For larger n, use StringBuilder with append/delete.
- **Not pruning.** Without the guards, you'd generate all 2^(2n) combinations and filter — much slower.

## How to Explain (interview)

**Opening:** Generate Parentheses generates all well-formed combinations of n pairs. Backtracking with constraints: track open and close counts. Add '(' if open < n; add ')' if close < open. These guards ensure well-formedness (never more closes than opens, never exceed n pairs). O(4^n/√n) time.

**The basic flow:**
```java
void backtrack(String cur, int open, int close, int n) {
    if (open == n && close == n) { result.add(cur); return; }
    if (open < n) backtrack(cur + "(", open + 1, close, n);
    if (close < open) backtrack(cur + ")", open, close + 1, n);
}
```

**The part that trips everyone up:** the two guards — `open < n` (can add '(') and `close < open` (can add ')'). Without them, you generate invalid sequences. The `close < open` guard is the key to well-formedness.

**The mistakes to remember:**
- Adding ')' when close >= open (invalid)
- Adding '(' when open >= n (exceeds n pairs)
- Using String concatenation (O(n) per call — fine for small n)
- Not pruning (generates all 2^(2n) combinations)
