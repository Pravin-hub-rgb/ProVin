**Problem:** Given a string, partition it such that every substring is a palindrome. Return all possible partitionings. (LeetCode #131)

**Link:** https://leetcode.com/problems/palindrome-partitioning/

---

## Which Technique, and Why?

"Partition string into palindromic substrings, return all partitionings" ? **Backtracking**. At each position, try every possible substring starting there; if it's a palindrome, add it and recurse on the rest. O(2^n × n) time (n possible cut points, each palindrome check O(n)).

**Signal in the problem:** "partition" + "palindrome" + "all possible" ? backtracking with palindrome check.

## Approach

Backtrack: parameters `start` (current position), `current` (list of palindromic substrings so far). For each end from start to n-1: if `s[start..end]` is palindrome, add it, recurse with `end+1`, undo.

## Pseudocode

```
result = []
backtrack(s, 0, [], result)
return result

backtrack(s, start, current, result):
    if start == s.length(): result.add(copy of current); return
    for end from start to s.length()-1:
        if isPalindrome(s, start, end):
            current.add(s.substring(start, end+1))
            backtrack(s, end + 1, current, result)
            current.remove(last)
```

## Java Code

```java
class Solution {
    public List<List<String>> partition(String s) {
        List<List<String>> result = new ArrayList<>();
        backtrack(s, 0, new ArrayList<>(), result);
        return result;
    }

    private void backtrack(String s, int start, List<String> current, List<List<String>> result) {
        if (start == s.length()) {
            result.add(new ArrayList<>(current));
            return;
        }
        for (int end = start; end < s.length(); end++) {
            if (isPalindrome(s, start, end)) {
                current.add(s.substring(start, end + 1));
                backtrack(s, end + 1, current, result);
                current.remove(current.size() - 1);
            }
        }
    }

    private boolean isPalindrome(String s, int l, int r) {
        while (l < r) {
            if (s.charAt(l) != s.charAt(r)) return false;
            l++;
            r--;
        }
        return true;
    }
}
```

## Line-by-line

- `start == s.length()` ? all characters partitioned ? record copy.
- `for (end = start; ...)` — try every substring starting at `start`.
- `isPalindrome(s, start, end)` — check if `s[start..end]` is a palindrome.
- If yes: add substring, recurse from `end + 1`, undo.
- `isPalindrome` uses two pointers from both ends.

## Complexity

- Time: O(2^n × n) — 2^n possible partitions, each palindrome check O(n).
- Space: O(n) — recursion depth + current list.

## Common Mistakes

- **Not checking palindrome before adding.** Only add substrings that are palindromes.
- **Wrong substring bounds.** `s.substring(start, end + 1)` — end is inclusive, so `end + 1`.
- **Not undoing.** `current.remove(...)` after recursion.
- **Inefficient palindrome check.** Precompute a palindrome table (DP) for O(1) checks ? O(n²) total instead of O(2^n × n). Good optimization for interviews.

## How to Explain (interview)

**Opening:** Palindrome Partitioning finds all ways to partition a string into palindromic substrings. Backtracking: at each position, try every substring starting there; if it's a palindrome, add it and recurse on the rest. O(2^n × n) time (n palindrome checks per partition).

**The basic flow:**
```java
void backtrack(String s, int start, List<String> cur) {
    if (start == s.length()) { result.add(new ArrayList<>(cur)); return; }
    for (int end = start; end < s.length(); end++) {
        if (isPalindrome(s, start, end)) {
            cur.add(s.substring(start, end + 1));
            backtrack(s, end + 1, cur);
            cur.remove(cur.size() - 1);
        }
    }
}
```

**The part that trips everyone up:** `s.substring(start, end + 1)` — the end index is exclusive, so add 1. Also, `isPalindrome` uses two pointers (O(n) per check). Precompute a palindrome table for O(1) checks (optimization).

**The mistakes to remember:**
- Wrong substring bounds (off by one)
- Not checking palindrome before adding
- Not undoing (state leaks)
- Inefficient palindrome check (use DP table for O(1))
