# 11.10 Combinations

**Problem:** Given n and k, return all possible combinations of k numbers from 1 to n. (LeetCode #77)

**Link:** https://leetcode.com/problems/combinations/

---

## Which Technique, and Why?

"Generate all combinations of k numbers from 1..n" → **Backtracking**. Try each number from `start` to n, add, recurse with `i + 1` and `k - 1`, undo. Prune when remaining numbers can't fill k. O(C(n, k) × k) time.

**Signal in the problem:** "combinations of k numbers from 1 to n" → backtracking with count constraint, no sum.

## Approach

Backtrack: parameters `start` (current number to try), `k` (remaining count). Base: `k == 0` → record copy. For each `i` from `start` to `n`: add i, recurse with `i + 1, k - 1`, undo. Prune: if `n - i + 1 < k` → not enough numbers left → break.

## Pseudocode

```
result = []
backtrack(1, k, [], result, n)
return result

backtrack(start, k, current, result, n):
    if k == 0: result.add(copy); return
    for i from start to n:
        if n - i + 1 < k: break  // not enough numbers left
        current.add(i)
        backtrack(i + 1, k - 1, current, result, n)
        current.remove(last)
```

## Java Code

```java
class Solution {
    public List<List<Integer>> combine(int n, int k) {
        List<List<Integer>> result = new ArrayList<>();
        backtrack(1, k, n, new ArrayList<>(), result);
        return result;
    }

    private void backtrack(int start, int k, int n, List<Integer> current, List<List<Integer>> result) {
        if (k == 0) {
            result.add(new ArrayList<>(current));
            return;
        }
        for (int i = start; i <= n; i++) {
            if (n - i + 1 < k) break;  // not enough numbers remaining
            current.add(i);
            backtrack(i + 1, k - 1, n, current, result);
            current.remove(current.size() - 1);
        }
    }
}
```

## Line-by-line

- `start` — the smallest number we can try next (ensures ascending order, no duplicate combinations).
- `k` — how many more numbers we need.
- `k == 0` → found a valid combination → record copy.
- `if (n - i + 1 < k) break` — if there aren't enough numbers left (from i to n) to fill k slots, stop. This is the pruning.
- `backtrack(i + 1, k - 1, ...)` — next number must be bigger, one fewer slot.

## Complexity

- Time: O(C(n, k) × k) — C(n,k) combinations, each takes O(k) to copy.
- Space: O(k) — recursion depth.

## Common Mistakes

- **Not pruning.** Without `n - i + 1 < k`, you explore branches that can't possibly fill k slots. Wastes time.
- **Allowing reuse.** Pass `i + 1`, not `i` — each number used at most once.
- **Starting from 0.** Numbers are 1 to n. Start at 1.
- **Not copying when recording.** Use `new ArrayList<>(current)`.

## How to Explain (interview)

**Opening:** Combinations generates all ways to choose k numbers from 1 to n. Backtracking: try each number from start to n, add it, recurse with i+1 (no reuse) and k-1 (one fewer slot), undo. Prune when not enough numbers remain. O(C(n,k) × k) time.

**The basic flow:**
```java
void backtrack(int start, int k, List<Integer> cur) {
    if (k == 0) { result.add(new ArrayList<>(cur)); return; }
    for (int i = start; i <= n; i++) {
        if (n - i + 1 < k) break;
        cur.add(i);
        backtrack(i + 1, k - 1, cur);
        cur.remove(cur.size() - 1);
    }
}
```

**The part that trips everyone up:** the pruning `n - i + 1 < k` — if fewer than k numbers remain from i to n, stop. Also, `start` ensures ascending order (no duplicate combinations).

**The mistakes to remember:**
- Not pruning (explores dead branches)
- Passing `i` instead of `i + 1` (allows reuse)
- Starting from 0 instead of 1
- Not copying when recording
