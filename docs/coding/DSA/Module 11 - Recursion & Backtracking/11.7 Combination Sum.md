# 11.7 Combination Sum

**Problem:** Given an array of distinct integers and a target, find all unique combinations that sum to target. The same number may be chosen unlimited times. (LeetCode #39)

**Link:** https://leetcode.com/problems/combination-sum/

---

## Which Technique, and Why?

"Find all combinations summing to target, unlimited reuse" → **Backtracking**. At each step, try each candidate from `start` onward (reuse allowed by passing `i`, not `i+1`). Sort first to enable pruning (if `sum + nums[i] > target`, break). O(n^(target/min)) time.

**Signal in the problem:** "combinations that sum to target" + "same number can be used unlimited" → backtracking with reuse (pass `i`, not `i+1`).

## Approach

Sort the array. Backtrack: for each candidate from `start`, if adding it doesn't exceed target, add it, recurse with `i` (reuse allowed), then undo. Prune: if `sum + nums[i] > target`, break (sorted, so later ones are even bigger).

## Pseudocode

```
sort candidates
result = []
backtrack(candidates, target, 0, [], result, 0)
return result

backtrack(candidates, target, start, current, result, sum):
    if sum == target: result.add(copy of current); return
    if sum > target: return
    for i from start to candidates.length-1:
        if sum + candidates[i] > target: break  // prune
        current.add(candidates[i])
        backtrack(candidates, target, i, current, result, sum + candidates[i])  // i, not i+1 (reuse)
        current.remove(last)
```

## Java Code

```java
class Solution {
    public List<List<Integer>> combinationSum(int[] candidates, int target) {
        Arrays.sort(candidates);
        List<List<Integer>> result = new ArrayList<>();
        backtrack(candidates, target, 0, new ArrayList<>(), result, 0);
        return result;
    }

    private void backtrack(int[] candidates, int target, int start, List<Integer> current, List<List<Integer>> result, int sum) {
        if (sum == target) {
            result.add(new ArrayList<>(current));
            return;
        }
        if (sum > target) return;

        for (int i = start; i < candidates.length; i++) {
            if (sum + candidates[i] > target) break;  // prune (sorted)
            current.add(candidates[i]);
            backtrack(candidates, target, i, current, result, sum + candidates[i]); // reuse: i, not i+1
            current.remove(current.size() - 1);
        }
    }
}
```

## Line-by-line

- `Arrays.sort` — enables pruning (break when sum exceeds target).
- `sum == target` → record a copy, return.
- `sum > target` → prune (shouldn't happen with the break, but safety).
- `backtrack(..., i, ...)` — pass `i` (not `i+1`) to allow reusing the same element.
- `if (sum + candidates[i] > target) break` — since sorted, later elements are ≥ current, so they'll also exceed.

## Complexity

- Time: O(n^(target/min)) — branching factor up to n, depth up to target/min.
- Space: O(target/min) — recursion depth.

## Common Mistakes

- **Passing `i + 1` instead of `i`.** That prevents reuse (that's Combination Sum II). For unlimited reuse, pass `i`.
- **Not pruning.** Without the `break`, you explore many dead branches. Sort + break makes it much faster.
- **Not copying when recording.** `result.add(new ArrayList<>(current))`.
- **Forgetting to undo.** `current.remove(...)` after recursion.

## How to Explain (interview)

**Opening:** Combination Sum finds all combinations of numbers (unlimited reuse) that sum to target. Backtracking: try each candidate from `start`, add it, recurse with the same index (reuse), undo. Sort first and prune when sum exceeds target. O(n^(target/min)) time.

**The basic flow:**
```java
void backtrack(int[] nums, int target, int start, List<Integer> cur, int sum) {
    if (sum == target) { result.add(new ArrayList<>(cur)); return; }
    if (sum > target) return;
    for (int i = start; i < nums.length; i++) {
        if (sum + nums[i] > target) break;
        cur.add(nums[i]);
        backtrack(nums, target, i, cur, sum + nums[i]); // i, not i+1
        cur.remove(cur.size() - 1);
    }
}
```

**The part that trips everyone up:** pass `i` (not `i + 1`) to allow reuse. Also, the `break` (not `continue`) for pruning — since sorted, all later elements also exceed.

**The mistakes to remember:**
- Passing `i + 1` (prevents reuse — that's a different problem)
- Using `continue` instead of `break` for pruning (slower)
- Not copying when recording
- Forgetting to undo
