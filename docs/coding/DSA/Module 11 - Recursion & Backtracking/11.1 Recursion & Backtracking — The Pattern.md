## The Core Idea

**Recursion** is when a function calls itself to solve a smaller version of the same problem. Every recursive function has:
1. **Base case** — the simplest input, solved directly (stops the recursion).
2. **Recursive case** — shrink the problem and call yourself.

**The call stack** is how the JVM remembers where to return. Each call pushes a frame; when the base case is hit, frames pop back up, returning values.

**Backtracking** is recursion + undo: try a choice, recurse, then undo the choice if it doesn't lead to a solution. Used for: subsets, permutations, combinations, N-Queens, Sudoku.

## How to Recognize It

Think "Recursion" when:
- The problem has **self-similar structure** (tree, divide-and-conquer, subproblems).
- You can define the answer in terms of a **smaller input** (f(n) = f(n-1) + ...).
- Keywords: "recursive," "tree," "divide and conquer," "subproblems."

Think "Backtracking" when:
- The problem asks for **all combinations/permutations/subsets**.
- You need to **try choices and undo** (N-Queens, Sudoku, word search).
- Keywords: "all possible," "generate," "combinations," "permutations," "subsets."

**Signal words:** "recursive," "base case," "tree traversal," "subsets," "permutations," "combinations," "backtrack."

## Worked Example 1: Factorial (simple recursion)

```java
static int factorial(int n) {
    if (n <= 1) return 1;          // base case
    return n * factorial(n - 1);    // recursive case
}
```

- Base case: `n <= 1` → return 1 (0! = 1, 1! = 1).
- Recursive case: `n! = n × (n-1)!`.
- Call stack for `factorial(4)`: factorial(4) → factorial(3) → factorial(2) → factorial(1) [base, returns 1] → 2 → 6 → 24.

## Worked Example 2: Subsets (backtracking)

**Problem:** Given an array, return all subsets.

```java
class Solution {
    public List<List<Integer>> subsets(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        backtrack(nums, 0, new ArrayList<>(), result);
        return result;
    }

    private void backtrack(int[] nums, int start, List<Integer> current, List<List<Integer>> result) {
        result.add(new ArrayList<>(current));  // record current subset (including empty)

        for (int i = start; i < nums.length; i++) {
            current.add(nums[i]);               // choose
            backtrack(nums, i + 1, current, result); // explore
            current.remove(current.size() - 1);  // undo (backtrack)
        }
    }
}
```

**Line-by-line:**
- `result.add(new ArrayList<>(current))` — record a copy of the current subset at every node (including the empty set).
- `for (int i = start; ...)` — try each remaining element as the next choice.
- `current.add(nums[i])` — choose.
- `backtrack(nums, i + 1, ...)` — recurse with the next starting index (avoid reusing the same element).
- `current.remove(...)` — undo the choice (backtrack) so the next iteration tries a different element.

**Key insight:** the "choose → explore → undo" pattern. The recursion explores all combinations; the undo ensures each branch starts from a clean state.

## Common Mistakes

- **Missing base case.** Infinite recursion → `StackOverflowError`. Always define when to stop.
- **Not shrinking the problem.** If the recursive call doesn't reduce the input (e.g., `f(n)` calls `f(n)`), infinite recursion.
- **Forgetting to undo in backtracking.** After the recursive call, undo the choice (`current.remove(...)`) or the state leaks into sibling branches.
- **Modifying shared state without copying.** `result.add(current)` adds a reference — later modifications to `current` change the stored subset. Use `new ArrayList<>(current)` to copy.
- **Deep recursion → StackOverflow.** For n = 10⁵, recursion depth 10⁵ can overflow. Use iterative or increase stack size.

## How to Explain (interview)

**Opening:** Recursion is a function calling itself to solve a smaller version of the same problem. Every recursive function needs a base case (when to stop) and a recursive case (how to shrink). The call stack remembers return addresses. Backtracking is recursion + undo: choose, explore, undo — used for subsets, permutations, combinations. O(n) or worse depending on branching; space is O(depth) for the call stack.

**The basic flow (factorial):**
```java
int factorial(int n) {
    if (n <= 1) return 1;        // base case
    return n * factorial(n - 1); // recursive case
}
```

**The part that trips everyone up:** the base case must be reachable and correct. Also, in backtracking, **undo** the choice after the recursive call (`current.remove(...)`) and **copy** the list when storing (`new ArrayList<>(current)`).

**The mistakes to remember:**
- Missing base case → StackOverflowError
- Not shrinking the problem → infinite recursion
- Forgetting to undo in backtracking (state leaks)
- Storing references instead of copies (mutated results)
- Deep recursion on large inputs (stack overflow)
