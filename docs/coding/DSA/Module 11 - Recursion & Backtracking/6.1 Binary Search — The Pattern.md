# 11.1 Recursion Basics — The Pattern

## What This Problem Is Asking (Simple Terms)

Recursion is when a function calls itself to solve a smaller instance of the same problem. Each recursive call works on a smaller piece until reaching a base case — a simple case that can be answered directly without more recursion.

Think of it like Russian nesting dolls: open one doll to find a smaller one inside, until you reach the tiniest doll that can't be opened further.

---

## Example 1

**Problem:** Compute factorial of n: n! = n × (n-1) × ... × 1

**Input:** `n = 5`

**Output:** `120`

**Explanation:** 5! = 5 × 4 × 3 × 2 × 1 = 120

---

## Example 2

**Input:** `n = 0`

**Output:** `1`

**Explanation:** 0! = 1 (by definition)

---

## Constraints

- `0 <= n <= 12` (to avoid integer overflow)

---

## Which Technique, and Why?

Recursion breaks a problem into smaller instances of the same problem. Each recursive call works on a smaller piece until reaching a base case — a simple case that can be answered directly without more recursion.

**Signal in the problem:** Problems that can be defined in terms of themselves (factorial, Fibonacci, tree traversal, etc.)

---

## Approach

**Recursive approach:**
1. **Base case:** if n == 0 or n == 1, return 1.
2. **Recursive case:** return n × factorial(n - 1).

### Pseudocode

```
function factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)
```

### Java Code

```java
class Solution {
    public int factorial(int n) {
        if (n <= 1) return 1;
        return n * factorial(n - 1);
    }
}
```

### Line-by-line

- `if (n <= 1) return 1;` — base case: factorial of 0 or 1 is 1.
- `return n * factorial(n - 1);` — recursive case: n! = n × (n-1)!

## Complexity

- Time: O(n) — n recursive calls.
- Space: O(n) — recursion stack depth.

## Common Mistakes

- **Missing base case** — causes infinite recursion and StackOverflowError.
- **Wrong base case** — factorial of 0 is 1, not 0.

---

## How to Explain (interview)

**Opening:** Recursion solves problems by breaking them into smaller subproblems of the same type. Each recursive call handles a smaller piece until reaching a base case that can be answered directly.

**The basic flow:**
```java
int factorial(int n) {
    if (n <= 1) return 1;  // base case
    return n * factorial(n - 1);  // recursive case
}
```

**The part that trips everyone up:**
- **Base case** — without it, recursion never stops and causes StackOverflowError.
- **Each recursive call must make progress** toward the base case (e.g., n decreases by 1).

**The mistakes to remember:**
- Missing base case → infinite recursion → StackOverflowError
- Not making progress toward base case → infinite recursion
