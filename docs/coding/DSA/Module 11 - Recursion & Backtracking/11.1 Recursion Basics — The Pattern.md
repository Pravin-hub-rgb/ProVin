## What Is Recursion?

A function that **calls itself**. Instead of solving a big problem all at once, you solve a tiny piece and hand the rest back to yourself.

### The two things every recursive function needs

1. **Base case** — the simplest input, solved directly. This is where recursion **stops**. Without it, the function calls itself forever.
2. **Recursive case** — shrink the problem by one step, then call yourself again.

If either is missing, the program crashes with `StackOverflowError`.

### Example 1: Factorial

`5! = 5 × 4 × 3 × 2 × 1 = 120`

How do you compute this recursively? Notice: `5! = 5 × 4!`. And `4! = 4 × 3!`. The problem shrinks by one each time.

```java
static int factorial(int n) {
    if (n <= 1) return 1;          // base case: 0! = 1, 1! = 1
    return n * factorial(n - 1);    // recursive case: n! = n × (n-1)!
}
```

**How the call stack works (factorial(4)):**

```
factorial(4) calls factorial(3)
  factorial(3) calls factorial(2)
    factorial(2) calls factorial(1)
      factorial(1) → base case, returns 1
    factorial(2) → 2 × 1 = 2, returns 2
  factorial(3) → 3 × 2 = 6, returns 6
factorial(4) → 4 × 6 = 24, returns 24
```

Each call pushes a frame onto the **call stack**. When the base case returns, frames pop back up, passing results upward. The call stack is just the JVM's way of remembering "where to return after this call finishes."

### Example 2: Sum of an array

```java
static int sum(int[] arr, int index) {
    if (index >= arr.length) return 0;   // base case: nothing left to add
    return arr[index] + sum(arr, index + 1);  // recursive case: current + rest
}
```

- Base case: `index >= arr.length` → return 0 (empty sum).
- Recursive case: `arr[index] + sum(arr, index + 1)` — add current element, then solve for the rest.

Call for `sum({1, 2, 3}, 0)`:
```
sum(arr, 0) = 1 + sum(arr, 1)
  sum(arr, 1) = 2 + sum(arr, 2)
    sum(arr, 2) = 3 + sum(arr, 3)
      sum(arr, 3) = 0  (base case)
    = 3 + 0 = 3
  = 2 + 3 = 5
= 1 + 5 = 6
```

### What goes wrong (and how to spot it)

| Mistake | What happens | Fix |
|---|---|---|
| No base case | Infinite recursion → `StackOverflowError` | Always define when to stop |
| Problem doesn't shrink | `f(n)` calls `f(n)` → infinite recursion | Make sure the recursive call uses a smaller input |
| Base case never reached | Same as above | Check that each step moves toward the base case |

### Recursion vs iteration

Anything recursive can be written iteratively (with a loop and a stack). Recursion is often clearer for tree/graph problems. Iteration avoids stack overflow on deep inputs.

## How to Recognize It

Think "Recursion" when:
- The problem has **self-similar structure** (tree, divide-and-conquer, subproblems).
- You can define the answer in terms of a **smaller input** (f(n) = f(n-1) + ...).
- Keywords: "recursive," "tree traversal," "divide and conquer," "subproblems."

**Signal words:** "recursive," "base case," "tree traversal," "divide and conquer," "subproblems."

## Common Mistakes

- **Missing base case.** Infinite recursion → `StackOverflowError`. Always define when to stop.
- **Not shrinking the problem.** If the recursive call doesn't reduce the input, infinite recursion.
- **Deep recursion → StackOverflow.** For n = 10⁵, recursion depth 10⁵ can overflow. Use iterative or increase stack size.

## How to Explain (interview)

**Opening:** Recursion is a function calling itself to solve a smaller version of the same problem. Every recursive function needs a base case (when to stop) and a recursive case (how to shrink). The call stack remembers return addresses. Time depends on branching; space is O(depth) for the call stack.

**The basic flow (factorial):**
```java
int factorial(int n) {
    if (n <= 1) return 1;        // base case
    return n * factorial(n - 1); // recursive case
}
```

**The part that trips everyone up:** the base case must be reachable and correct. Also, recursion can be rewritten iteratively to avoid stack overflow on deep inputs.

**The mistakes to remember:**
- Missing base case → StackOverflowError
- Not shrinking the problem → infinite recursion
- Deep recursion on large inputs (stack overflow)
