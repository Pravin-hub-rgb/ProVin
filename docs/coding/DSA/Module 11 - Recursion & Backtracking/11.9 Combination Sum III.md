**Problem:** Find all valid combinations of k numbers (1–9) that sum to n. Each number used at most once. (LeetCode #216)

**Link:** https://leetcode.com/problems/combination-sum-iii/

---

## Which Technique, and Why?

"Find all combinations of k numbers (1–9) summing to n" ? **Backtracking with a fixed range (1–9) and count constraint**. Try each number from `start` to 9; add, recurse with `i + 1` and `k - 1`; undo. Prune when remaining numbers can't reach k or sum exceeds n. O(C(9, k)) time.

**Signal in the problem:** "combinations of k numbers" + "1 to 9" + "sum to n" ? backtracking with count constraint.

## Approach

Backtrack over numbers 1–9. Parameters: `start` (current number to try), `k` (remaining count), `sum` (remaining sum). Base: `k == 0 && sum == 0` ? record. Prune: if `k <= 0` or `sum <= 0` or `start > 9` or `sum < start` ? return. For each `i` from `start` to 9: if `i > sum` break (prune); add i, recurse with `i+1, k-1, sum-i`, undo.

## Pseudocode

```
result = []
backtrack(start, k, sum, current, result)
return result

backtrack(start, k, sum, current, result):
    if k == 0 and sum == 0: result.add(copy); return
    if k <= 0 or sum <= 0 or start > 9: return
    for i from start to 9:
        if i > sum: break
        current.add(i)
        backtrack(i + 1, k - 1, sum - i, current, result)
        current.remove(last)
```

## Java Code

```java
class Solution {
    public List<List<Integer>> combinationSum3(int k, int n) {
        List<List<Integer>> result = new ArrayList<>();
        backtrack(1, k, n, new ArrayList<>(), result);
        return result;
    }

    private void backtrack(int start, int k, int sum, List<Integer> current, List<List<Integer>> result) {
        if (k == 0 && sum == 0) {
            result.add(new ArrayList<>(current));
            return;
        }
        if (k <= 0 || sum <= 0 || start > 9) return;

        for (int i = start; i <= 9; i++) {
            if (i > sum) break;  // prune: can't use a number bigger than remaining sum
            current.add(i);
            backtrack(i + 1, k - 1, sum - i, current, result);
            current.remove(current.size() - 1);
        }
    }
}
```

## Line-by-line

- `start` — the smallest number we can try next (avoids duplicates and ensures ascending order).
- `k` — how many more numbers we need.
- `sum` — remaining target sum.
- Base case: `k == 0 && sum == 0` ? found a valid combination ? record copy.
- Prune: `k <= 0` (no more slots), `sum <= 0` (no more sum needed, but k > 0 ? invalid), `start > 9` (out of range).
- `if (i > sum) break` — since i is increasing, if i > sum, all later i also exceed ? break.
- `backtrack(i + 1, k - 1, sum - i, ...)` — next number must be bigger (i+1), one fewer slot, reduced sum.

## Complexity

- Time: O(C(9, k)) — combinations of 9 choose k. At most C(9,4) = 126 for k=4.
- Space: O(k) — recursion depth (at most k).

## Common Mistakes

- **Not pruning.** Without `if (i > sum) break`, you explore dead branches. With only 9 numbers it's small, but pruning is good practice.
- **Allowing reuse.** Pass `i + 1`, not `i` — each number used at most once.
- **Not checking both `k == 0` and `sum == 0`.** If k == 0 but sum > 0, the combination doesn't sum to n. If sum == 0 but k > 0, you need more numbers.
- **Starting from 0 instead of 1.** Numbers are 1–9, so start at 1.

## How to Explain (interview)

**Opening:** Combination Sum III finds all combinations of k numbers (1–9) summing to n. Backtracking with a count constraint: try each number from start to 9, add it, recurse with i+1 (no reuse), k-1 (one fewer slot), sum-i (reduced target). Undo after. Prune when i > sum. O(C(9,k)) time.

**The basic flow:**
```java
void backtrack(int start, int k, int sum, List<Integer> cur) {
    if (k == 0 && sum == 0) { result.add(new ArrayList<>(cur)); return; }
    if (k <= 0 || sum <= 0 || start > 9) return;
    for (int i = start; i <= 9; i++) {
        if (i > sum) break;
        cur.add(i);
        backtrack(i + 1, k - 1, sum - i, cur);
        cur.remove(cur.size() - 1);
    }
}
```

**The part that trips everyone up:** the base case checks **both** `k == 0` and `sum == 0`. Also, `start` ensures ascending order (no duplicate combinations like [1,2] and [2,1]).

**The mistakes to remember:**
- Base case only checks k == 0 (misses sum check)
- Passing `i` instead of `i + 1` (allows reuse)
- Starting from 0 instead of 1
- Not pruning (`i > sum` break)
