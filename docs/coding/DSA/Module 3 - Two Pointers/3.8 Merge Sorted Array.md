**Problem:** You are given two integer arrays `nums1` and `nums2`, sorted in non-decreasing order, and two integers `m` and `n`, representing the number of elements in `nums1` and `nums2` respectively.

Merge `nums1` and `nums2` into a single array sorted in non-decreasing order.

The final sorted array should not be returned by the function, but instead be stored inside the array `nums1`. To accommodate this, `nums1` has a length of `m + n`, where the first `m` elements denote the elements that should be merged, and the last `n` elements are set to `0` and should be ignored. `nums2` has a length of `n`. (LeetCode #88)

**Link:** https://leetcode.com/problems/merge-sorted-array/

---

## What This Problem Is Asking (Simple Terms)

You have two sorted arrays. `nums1` has enough space at the end (filled with zeros) to hold all elements from both arrays. You need to merge them into `nums1` in sorted order, modifying `nums1` in place.

For example, `nums1 = [1,2,3,0,0,0]`, `m = 3`, `nums2 = [2,5,6]`, `n = 3` → merged: `[1,2,2,3,5,6]`.

You modify `nums1` in place and don't return anything (void).

**Output:** `[1,2,2,3,5,6]`

**Explanation:** The arrays we are merging are `[1,2,3]` and `[2,5,6]`. The result is `[1,2,2,3,5,6]`.

## Constraints

- `nums1.length == m + n`
- `nums2.length == n`
- `0 <= m, n <= 200`
- `1 <= m + n <= 200`
- `-10^9 <= nums1[i], nums2[j] <= 10^9`

**Follow-up:** Can you solve it in O(m + n) time and O(1) extra space?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could copy `nums2` into `nums1`'s placeholder slots, then sort the whole `nums1` array.

### Brute Force Pseudocode

```
for j from 0 to n-1:
    nums1[m + j] = nums2[j]
sort nums1
```

### Why Brute Force Is Not Ideal

Sorting takes O((m+n) log (m+n)). Since both arrays are already sorted, you can merge in O(m+n) without sorting.

---

## Which Data Structure/Technique, and Why?

You're merging two sorted arrays → **Two Pointers** (one per array). The trick: merge **from the end** (right to left) so you don't overwrite `nums1`'s elements before reading them. Three pointers: `i` (end of nums1's real data), `j` (end of nums2), `k` (end of merged result).

Why from the end? If you merge from the front, you'd overwrite `nums1`'s elements that haven't been read yet. Merging from the back writes into the empty placeholder slots.

**Signal in the problem:** "merge two sorted arrays in place" → two pointers, merge from the end.

---

## Optimized Approach (Three Pointers from the End)

Three pointers from the end: `i = m-1` (last real element of nums1), `j = n-1` (last of nums2), `k = m+n-1` (last slot of nums1). Compare `nums1[i]` and `nums2[j]`, put the larger at `nums1[k]`, decrement the chosen pointer and `k`. Continue until `nums2` is exhausted.

### Pseudocode

```
i = m - 1, j = n - 1, k = m + n - 1
while j >= 0:
    if i >= 0 and nums1[i] > nums2[j]:
        nums1[k] = nums1[i]
        i--
    else:
        nums1[k] = nums2[j]
        j--
    k--
```

### Java Code

```java
class Solution {
    public void merge(int[] nums1, int m, int[] nums2, int n) {
        int i = m - 1, j = n - 1, k = m + n - 1;

        while (j >= 0) {
            if (i >= 0 && nums1[i] > nums2[j]) {
                nums1[k] = nums1[i];
                i--;
            } else {
                nums1[k] = nums2[j];
                j--;
            }
            k--;
        }
    }
}
```

### Line-by-line

- `i = m - 1` — last real element of nums1 (before placeholders).
- `j = n - 1` — last element of nums2.
- `k = m + n - 1` — last slot of nums1 (where we write).
- `while j >= 0` — continue until all of nums2 is merged.
- `if i >= 0 && nums1[i] > nums2[j]` — nums1's element is bigger, put it at `k`.
- `else` — nums2's element is bigger (or nums1 exhausted), put it at `k`.
- `k--` — move write position left.

## Complexity

- Time: O(m + n) — each element visited once.
- Space: O(1) — only three pointers.

## Common Mistakes

- **Merging from the front** — overwrites `nums1`'s unread elements before they're compared.
- **Loop condition `i >= 0` instead of `j >= 0`** — you must process all of nums2; if nums1 is exhausted first, just copy remaining nums2.
- **Forgetting `i >= 0` check** — accessing `nums1[i]` when `i < 0` causes ArrayIndexOutOfBoundsException.
- **Not handling `m = 0`** — `i = -1`, loop should just copy all of nums2.

## How to Explain (interview)

**Opening:** Merge Sorted Array merges two sorted arrays into `nums1` in place. Since `nums1` has extra space at the end, merge from right to left using three pointers: `i` (end of nums1's data), `j` (end of nums2), `k` (end of merged result). Compare and place the larger element at `k`, moving backwards. O(m+n) time, O(1) space.

**The basic flow:**
```java
int i = m - 1, j = n - 1, k = m + n - 1;
while (j >= 0) {
    if (i >= 0 && nums1[i] > nums2[j]) {
        nums1[k] = nums1[i];
        i--;
    } else {
        nums1[k] = nums2[j];
        j--;
    }
    k--;
}
```

**The part that trips everyone up:** merging from the end, not the front. And the loop condition is `j >= 0` (process all of nums2), not `i >= 0` (if nums1 runs out first, just copy remaining nums2).

**The mistakes to remember:**
- Merging from the front (overwrites unread elements)
- Wrong loop condition
- Forgetting `i >= 0` bounds check
- Not handling `m = 0` edge case
