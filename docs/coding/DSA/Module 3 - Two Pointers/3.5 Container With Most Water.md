**Problem:** You are given an integer array `height` of length `n`. There are `n` vertical lines drawn such that the two endpoints of the `i`th line are `(i, 0)` and `(i, height[i])`.

Find two lines that together with the x-axis form a container, such that the container contains the most water.

Return the maximum amount of water a container can store. (LeetCode #11)

**Link:** https://leetcode.com/problems/container-with-most-water/

---

## What This Problem Is Asking (Simple Terms)

You have an array of heights representing vertical lines. You need to pick two lines that, together with the x-axis, form a container that holds the maximum amount of water.

The amount of water a container can hold is: `min(height[i], height[j]) * (j - i)` — the shorter line limits the height, and the distance between lines is the width.

You return just the maximum area value, not the indices.

---

## Example 1

**Input:** `height = [1,8,6,2,5,4,8,3,7]`

**Output:** `49`

**Explanation:** The two lines at indices 1 and 8 (heights 8 and 7) form a container with width 7 and height 7, area = 49.

---

## Example 2

**Input:** `height = [1,1]`

**Output:** `1`

**Explanation:** Width 1, height 1, area = 1.

---

## Constraints

- `n == height.length`
- `2 <= n <= 10^5`
- `0 <= height[i] <= 10^4`

**Follow-up:** Could you solve it in O(n) time?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could check every pair of lines `(i, j)`, compute `min(height[i], height[j]) * (j - i)`, and track the maximum.

### Brute Force Pseudocode

```
maxArea = 0
for i from 0 to n-1:
    for j from i+1 to n-1:
        area = min(height[i], height[j]) * (j - i)
        if area > maxArea: maxArea = area
return maxArea
```

### Why Brute Force Is Slow

Outer loop runs `n` times, inner loop runs up to `n` times. O(n²) — too slow for `n = 10^5`.

---

## Which Data Structure/Technique, and Why?

You need max area = `min(height[i], height[j]) * (j - i)`. Naive: check all pairs → O(n²). Optimized: **Two Pointers (converging)**. Start at both ends (widest container). Move the **shorter** side inward — the shorter side is the bottleneck, so moving it is the only way to possibly find a bigger area.

**Signal in the problem:** "max area" / "container" / "two lines" + array → two pointers from both ends, move the shorter side.

---

## Optimized Approach (Two Pointers, Converging)

`left = 0`, `right = n-1`. Compute area. Move the pointer with the smaller height. Track max area.

### Pseudocode

```
left = 0, right = n - 1
maxArea = 0
while left < right:
    width = right - left
    h = min(height[left], height[right])
    maxArea = max(maxArea, width * h)
    if height[left] < height[right]: left++
    else: right--
return maxArea
```

### Java Code

```java
class Solution {
    public int maxArea(int[] height) {
        int left = 0, right = height.length - 1;
        int maxArea = 0;

        while (left < right) {
            int width = right - left;
            int h = Math.min(height[left], height[right]);
            maxArea = Math.max(maxArea, width * h);

            if (height[left] < height[right]) left++;
            else right--;
        }
        return maxArea;
    }
}
```

### Line-by-line

- `left` and `right` start at opposite ends — widest container first.
- Area = width × height of shorter line.
- Move the **shorter** pointer inward. Why? The taller line could still form a bigger area with a new partner; the shorter one can't (any new container with it would be narrower AND no taller).
- Each step reduces the search space by 1 → O(n) total, no nested loop.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — two pointers.

## Common Mistakes

- **Moving the wrong pointer.** In "container with most water," move the **shorter** side. Moving the taller side loses potential area.
- **Off-by-one in the while condition.** Use `left < right` (not `<=`) — when they meet, there's no container.
- **Forgetting the array must be sorted** for two-sum style problems. Unsorted → use a hash map (Module 2). (Not applicable here — no sorting needed.)

## How to Explain (interview)

**Opening:** Container With Most Water asks for two lines that form a container with the most water. The brute force checks every pair — O(n²). The optimized version uses two pointers from both ends, always moving the shorter side inward because it's the bottleneck. O(n) time, O(1) space.

**The basic flow:**
```java
int left = 0, right = height.length - 1;
int maxArea = 0;
while (left < right) {
    int width = right - left;
    int h = Math.min(height[left], height[right]);
    maxArea = Math.max(maxArea, width * h);
    if (height[left] < height[right]) left++;
    else right--;
}
return maxArea;
```

**The part that trips everyone up:** moving the **shorter** side — not the taller one. Moving the shorter side is the only way to possibly find a taller line and increase area.

**The mistakes to remember:**
- Moving the wrong pointer (shorter vs taller)
- Off-by-one: `left < right`, not `left <= right`
