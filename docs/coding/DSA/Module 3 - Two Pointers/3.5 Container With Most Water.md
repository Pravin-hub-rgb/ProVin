**Problem:** Given an array of heights, find two lines that form a container holding the most water. (LeetCode #11)

**Link:** https://leetcode.com/problems/container-with-most-water/

---

## Which Technique, and Why?

You need max area = min(height[i], height[j]) × (j - i). Naive: check all pairs → O(n²). Optimized: **Two Pointers (converging)**. Start at both ends (widest container). Move the **shorter** side inward — the shorter side is the bottleneck, so moving it is the only way to possibly find a bigger area.

**Signal in the problem:** "max area" / "container" / "two lines" + array → two pointers from both ends, move the shorter side.

## Approach

`left = 0`, `right = n-1`. Compute area. Move the pointer with the smaller height. Track max area.

## Pseudocode

```
left = 0, right = n - 1
maxArea = 0
while left < right:
    width = right - left
    h = min(height[left], height[right])
    maxArea = max(maxArea, width * h)
    if height[left] < height[right]: left++
    else: right--
return maxArea
```

## Java Code

```java
class Solution {
    public int maxArea(int[] height) {
        int left = 0, right = height.length - 1;
        int maxArea = 0;

        while (left < right) {
            int width = right - left;
            int h = Math.min(height[left], height[right]);
            maxArea = Math.max(maxArea, width * h);

            if (height[left] < height[right]) left++;
            else right--;
        }
        return maxArea;
    }
}
```

## Line-by-line

- Start at widest (left=0, right=n-1) — max possible width.
- Area = width × height of shorter line (water can't exceed the shorter line).
- Move the **shorter** pointer. Why? The taller line could still form a bigger area with a new partner; the shorter one can't (any new container with it would be narrower AND no taller).
- Each step shrinks width by 1 → O(n) total.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — two pointers.

## Common Mistakes

- **Moving the taller pointer.** This skips potential better areas. Always move the shorter side.
- **Off-by-one:** `left < right` (not `<=`).
- **Assuming sorted input.** The array is NOT sorted here — two pointers still work because of the "move shorter" logic, not because of sorting.
- **Integer overflow:** width × height can exceed int range for large inputs. Use `long` if needed.

## How to Explain (interview)

**Opening:** Container With Most Water asks for the max area between two lines. Two pointers from both ends (widest first). At each step, compute area = width × min(height[left], height[right]), then move the **shorter** pointer inward — the shorter side is the bottleneck. O(n) time, O(1) space.

**The basic flow:**
```java
int left = 0, right = height.length - 1, maxArea = 0;
while (left < right) {
    maxArea = Math.max(maxArea, (right - left) * Math.min(height[left], height[right]));
    if (height[left] < height[right]) left++; else right--;
}
```

**The part that trips everyone up:** move the **shorter** side, not the taller. Moving the taller side can skip the optimal answer. Also the array is unsorted — two pointers work here due to the "shorter side" logic, not sorting.

**The mistakes to remember:**
- Moving the taller pointer instead of the shorter
- Off-by-one: `left < right`
- Assuming the array must be sorted (it doesn't need to be here)
