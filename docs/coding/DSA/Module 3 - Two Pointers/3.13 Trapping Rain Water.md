# 3.13 Trapping Rain Water

**Tier 2 problem.** (LeetCode #42)

**Problem:** Given n non-negative integers representing an elevation map, compute how much water it can trap after raining. (LeetCode #42)

**Link:** https://leetcode.com/problems/trapping-rain-water/

---

## Which Technique, and Why?

"Trapping rain water" → **Two Pointers (converging)**. Water at position i = min(maxLeft, maxRight) - height[i]. Instead of precomputing maxLeft and maxRight arrays (O(n) space), use two pointers from both ends, tracking the running max from each side. Move the pointer with the smaller max. O(n) time, O(1) space.

**Signal in the problem:** "trapping rain water" / "water trapped between bars" → two pointers with running max from both sides.

## Approach

Two pointers: `left = 0`, `right = n-1`. Track `leftMax` and `rightMax`. If `height[left] < height[right]`: water at left = `leftMax - height[left]` (leftMax is the bottleneck), update leftMax, left++. Else: water at right = `rightMax - height[right]`, update rightMax, right--.

**Why move the smaller side?** The water level at a position is determined by the smaller of the two maxes. If `height[left] < height[right]`, then `leftMax <= rightMax` (since leftMax ≤ height[left] < height[right] ≤ rightMax... actually leftMax is the max seen from left, which is ≤ height[left] only if... let me think). The key invariant: when `height[left] <= height[right]`, we know `leftMax <= rightMax` is not guaranteed, but we know that `leftMax` (the max from the left up to `left`) is the binding constraint for the left pointer, and since `height[left] <= height[right]`, the water at `left` is determined by `leftMax` (which is ≤ `height[right]` ≤ `rightMax`). So we can safely compute water at `left` using `leftMax`.

## Pseudocode

```
left = 0, right = n - 1
leftMax = 0, rightMax = 0, water = 0
while left < right:
    if height[left] <= height[right]:
        leftMax = max(leftMax, height[left])
        water += leftMax - height[left]
        left++
    else:
        rightMax = max(rightMax, height[right])
        water += rightMax - height[right]
        right--
return water
```

## Java Code

```java
class Solution {
    public int trap(int[] height) {
        int left = 0, right = height.length - 1;
        int leftMax = 0, rightMax = 0, water = 0;

        while (left < right) {
            if (height[left] <= height[right]) {
                leftMax = Math.max(leftMax, height[left]);
                water += leftMax - height[left];
                left++;
            } else {
                rightMax = Math.max(rightMax, height[right]);
                water += rightMax - height[right];
                right--;
            }
        }
        return water;
    }
}
```

## Line-by-line

- `leftMax` / `rightMax` — running max from each side.
- `height[left] <= height[right]` — process the smaller side. The smaller side's max is the binding constraint.
- `water += leftMax - height[left]` — water trapped at `left` = leftMax - height[left].
- Advance the pointer that was processed.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — two pointers + two maxes.

## Common Mistakes

- **Moving the wrong pointer.** Move the side with the smaller height. Moving the taller side loses water.
- **Computing water as `min(leftMax, rightMax) - height[i]` for all i.** This works but needs O(n) space for the max arrays. The two-pointer approach avoids this.
- **Off-by-one:** `left < right` (not `<=`). When they meet, no water to compute.
- **Not updating max before computing water.** Update `leftMax = max(leftMax, height[left])` first, then `water += leftMax - height[left]`. If you compute water first, leftMax might be stale.

## How to Explain (interview)

**Opening:** Trapping Rain Water computes water trapped between bars. Water at position i = min(maxLeft, maxRight) - height[i]. Two pointers from both ends: process the smaller side (its max is the binding constraint). O(n) time, O(1) space — no precomputed arrays needed.

**The basic flow:**
```java
int left = 0, right = n - 1, leftMax = 0, rightMax = 0, water = 0;
while (left < right) {
    if (height[left] <= height[right]) {
        leftMax = Math.max(leftMax, height[left]);
        water += leftMax - height[left++];
    } else {
        rightMax = Math.max(rightMax, height[right]);
        water += rightMax - height[right--];
    }
}
```

**The part that trips everyone up:** process the **smaller** side. The water at the smaller side is determined by its own max (which is ≤ the other side's max). Also, update max **before** computing water.

**The mistakes to remember:**
- Moving the taller pointer (loses water)
- Computing water before updating max
- Using O(n) space (precomputed arrays) when O(1) is possible
- Off-by-one: `left < right`, not `left <= right`
