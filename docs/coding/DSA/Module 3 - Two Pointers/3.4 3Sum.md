**Problem:** Given an integer array, find all unique triplets that sum to zero. (LeetCode #15)

**Link:** https://leetcode.com/problems/3sum/

---

## Which Technique, and Why?

3Sum = find i < j < k with nums[i] + nums[j] + nums[k] == 0. 

Naive: three nested loops → O(n³). Better: fix one element, then solve Two Sum on the rest → O(n²). Since the rest needs to be searched for a pair summing to `-nums[i]`, and we want O(1) space, sort the array first, then use **Two Pointers** for the inner pair search.

**Signal in the problem:** "three numbers that sum to target" + "unique triplets" + "no duplicate results" → sort + fix one + two pointers. The "unique" requirement is the tricky part (skip duplicates).

## Approach

1. Sort the array.
2. For each index `i` (the first element of the triplet):
   - Skip if `nums[i] == nums[i-1]` (avoid duplicate triplets).
   - If `nums[i] > 0`, break (sorted, so no more zero-sum triplets possible).
   - Use two pointers (`left = i+1`, `right = n-1`) to find pairs summing to `-nums[i]`.
   - Skip duplicates for `left` and `right` after finding a valid triplet.

## Pseudocode

```
sort nums
result = []
for i from 0 to n-3:
    if i > 0 and nums[i] == nums[i-1]: continue   // skip duplicate
    if nums[i] > 0: break                        // no more zero sums
    left = i + 1, right = n - 1
    while left < right:
        sum = nums[i] + nums[left] + nums[right]
        if sum == 0:
            result.add([nums[i], nums[left], nums[right]])
            left++; right--
            while left < right and nums[left] == nums[left-1]: left++
            while left < right and nums[right] == nums[right+1]: right--
        else if sum < 0: left++
        else: right--
return result
```

## Java Code

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        Arrays.sort(nums);

        for (int i = 0; i < nums.length - 2; i++) {
            if (i > 0 && nums[i] == nums[i - 1]) continue;  // skip duplicate
            if (nums[i] > 0) break;                          // sorted, no more

            int left = i + 1, right = nums.length - 1;
            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                if (sum == 0) {
                    result.add(Arrays.asList(nums[i], nums[left], nums[right]));
                    left++;
                    right--;
                    while (left < right && nums[left] == nums[left - 1]) left++;
                    while (left < right && nums[right] == nums[right + 1]) right--;
                } else if (sum < 0) {
                    left++;
                } else {
                    right--;
                }
            }
        }
        return result;
    }
}
```

## Line-by-line

- `Arrays.sort(nums)` — enables two pointers and duplicate skipping.
- Outer loop fixes `nums[i]` as the first element. Skip if same as previous (avoids duplicate triplets).
- `if (nums[i] > 0) break` — sorted array, if the smallest of the three is positive, sum can't be 0.
- Inner two-pointer search for pair summing to `-nums[i]`.
- On a hit: record triplet, then skip duplicates for both pointers.

## Complexity

- Time: O(n²) — outer loop O(n) × inner two-pointer O(n). Sorting is O(n log n), dominated.
- Space: O(1) extra (excluding output list). O(n log n) for sort's recursion stack (TimSort).

## Common Mistakes

- **Duplicate triplets.** Without the `nums[i] == nums[i-1]` skip (and the left/right skips), you get duplicate results. This is the #1 bug.
- **Forgetting to sort.** Two pointers only work on sorted arrays.
- **Using a set to dedupe results** — works but adds O(n) space and is slower. Skip duplicates in-place instead.
- **Breaking too early or too late.** `if (nums[i] > 0) break` is correct because the array is sorted. If you break on `>= 0`, you miss triplets with a zero (but 0, 0, 0 is handled since 0 > 0 is false).

## How to Explain (interview)

**Opening:** 3Sum finds all unique triplets summing to zero. Sort the array first. Then fix one element (i), and use two pointers on the rest to find pairs summing to -nums[i]. Skip duplicates at all three positions to avoid duplicate triplets. O(n²) time (O(n) per fixed element), O(1) extra space.

**The basic flow:**
```java
Arrays.sort(nums);
for (int i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] == nums[i-1]) continue;
    if (nums[i] > 0) break;
    int left = i + 1, right = nums.length - 1;
    while (left < right) {
        int sum = nums[i] + nums[left] + nums[right];
        if (sum == 0) { /* record, skip dups */ }
        else if (sum < 0) left++; else right--;
    }
}
```

**The part that trips everyone up:** **duplicate skipping** at all three positions (i, left, right). Without it, you get duplicate triplets. Also, break when `nums[i] > 0` (sorted).

**The mistakes to remember:**
- Forgetting to skip duplicates → duplicate results
- Not sorting first → two pointers won't work
- Using a HashSet to dedupe (works but slower and uses extra space)
- Breaking on `>= 0` instead of `> 0` (misses 0,0,0)
