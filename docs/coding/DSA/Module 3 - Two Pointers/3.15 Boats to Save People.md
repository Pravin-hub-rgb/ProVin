# 3.15 Boats to Save People

**Tier 2 problem.** (LeetCode #881)

**Problem:** Given people's weights and a boat limit (max weight per boat, at most 2 people per boat), find the minimum number of boats needed. (LeetCode #881)

**Link:** https://leetcode.com/problems/boats-to-save-people/

---

## Which Technique, and Why?

"Minimum boats, at most 2 people, weight limit" → **Greedy + Two Pointers**. Sort weights. Pair the heaviest with the lightest if they fit; otherwise the heaviest goes alone. O(n log n) time, O(1) space.

**Signal in the problem:** "minimum boats" + "at most 2 people" + "weight limit" → sort + two pointers (pair heaviest with lightest).

## Approach

Sort weights. Two pointers: left (lightest), right (heaviest). If `weights[left] + weights[right] <= limit`, pair them (left++, right--). Else, heaviest goes alone (right--). Count boats.

## Pseudocode

```
sort weights
left = 0, right = n - 1, boats = 0
while left <= right:
    if weights[left] + weights[right] <= limit:
        left++
    right--
    boats++
return boats
```

## Java Code

```java
class Solution {
    public int numRescueBoats(int[] people, int limit) {
        Arrays.sort(people);
        int left = 0, right = people.length - 1, boats = 0;

        while (left <= right) {
            if (people[left] + people[right] <= limit) {
                left++;
            }
            right--;
            boats++;
        }
        return boats;
    }
}
```

## Line-by-line

- Sort weights ascending.
- `left` points to lightest, `right` to heaviest.
- If lightest + heaviest ≤ limit → pair them (left++, right--).
- Else → heaviest goes alone (right--).
- `boats++` each iteration (one boat per iteration).
- Loop until `left > right`.

## Complexity

- Time: O(n log n) — sorting dominates.
- Space: O(1) extra (or O(log n) for sort stack).

## Common Mistakes

- **Not sorting.** Without sorting, the greedy pairing doesn't work.
- **Pairing heaviest with heaviest.** That's wrong — pair heaviest with lightest (greedy: use the lightest person to "fill" the boat with the heaviest).
- **Off-by-one.** `left <= right` (not `<`). When `left == right`, one person remains → one boat.
- **Counting boats wrong.** `boats++` happens every iteration, whether paired or alone. Don't increment twice.

## How to Explain (interview)

**Opening:** Boats to Save People minimizes boats (max 2 people, weight limit). Greedy + two pointers: sort weights, pair heaviest with lightest if they fit; otherwise heaviest goes alone. O(n log n) time, O(1) space.

**The basic flow:**
```java
Arrays.sort(people);
int left = 0, right = people.length - 1, boats = 0;
while (left <= right) {
    if (people[left] + people[right] <= limit) left++;
    right--;
    boats++;
}
return boats;
```

**The part that trips everyone up:** pair the **heaviest with the lightest** (not heaviest with heaviest). The greedy choice: use the lightest person to fill the boat with the heaviest — if they don't fit, the heaviest goes alone (no one can pair with them).

**The mistakes to remember:**
- Not sorting (greedy fails)
- Pairing heaviest with heaviest (wrong)
- Off-by-one: `left <= right` (not `<`)
- Counting boats twice (increment once per iteration)
