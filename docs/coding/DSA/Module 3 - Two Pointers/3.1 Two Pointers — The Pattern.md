## The Core Idea

Many problems on arrays/strings require checking pairs of elements. The naive approach: nested loops over all pairs → O(n²). 

**Two Pointers** uses two indices that move based on a condition, eliminating the inner loop → O(n). The key insight: if the array is sorted (or you're checking symmetry/palindrome), you can decide which pointer to move without checking every pair.

**Two variants:**

1. **Opposite ends (converging):** `left = 0`, `right = n-1`, move them toward each other. Used for: reverse, palindrome, container with most water, two-sum on sorted array.
2. **Same direction (fast & slow):** both start at 0, one moves faster. Used for: remove duplicates, move zeroes, merge.

## How to Recognize It

Think "Two Pointers" when:
- The array/string is **sorted** and you need to find a pair → converge from both ends.
- The problem asks about a **palindrome** or **symmetry** → compare from both ends.
- The problem asks to **reverse** or **rearrange in place** → swap from both ends.
- You need to **filter/remove** elements in place (duplicates, zeroes) → fast & slow pointers.
- You need to **merge** two sorted arrays → two pointers, one per array.
- The problem asks for **container with most water / max area** → converge, moving the shorter side.

**Signal words:** "sorted array," "in-place," "palindrome," "two numbers that sum," "remove duplicates," "merge."

## Worked Example: Container With Most Water

**Problem:** Given heights, find two lines that form a container with the most water.

### Brute force (O(n²))

Check every pair (i, j), compute area = min(height[i], height[j]) × (j - i). Track max.

### Optimized (O(n)) — two pointers

```java
class Solution {
    public int maxArea(int[] height) {
        int left = 0, right = height.length - 1;
        int maxArea = 0;

        while (left < right) {
            int width = right - left;
            int h = Math.min(height[left], height[right]);
            maxArea = Math.max(maxArea, width * h);

            // move the shorter side — it's the bottleneck
            if (height[left] < height[right]) left++;
            else right--;
        }
        return maxArea;
    }
}
```

**Line-by-line:**
- `left` and `right` start at opposite ends — widest container first.
- Area = width × height of shorter line.
- Move the **shorter** pointer inward. Why? The taller line could still form a bigger area with a new partner; the shorter one can't (any new container with it would be narrower AND no taller).
- Each step reduces the search space by 1 → O(n) total, no nested loop.

**Key insight:** you don't need to check every pair. The decision "move the shorter side" is safe because the shorter side can never be part of a better container with the current setup.

## Common Mistakes

- **Moving the wrong pointer.** In "container with most water," move the **shorter** side. Moving the taller side loses potential area.
- **Off-by-one in the while condition.** Use `left < right` (not `<=`) — when they meet, there's no container.
- **Forgetting the array must be sorted** for two-sum style problems. Unsorted → use a hash map (Module 2).
- **Fast & slow pointer confusion:** in "remove duplicates," the slow pointer marks the write position, fast scans ahead. Don't swap their roles.
- **Modifying while iterating** — same pitfall as Module 2; handle carefully.

## How to Explain (interview)

**Opening:** Two Pointers is a pattern where you use two indices instead of nested loops. On a sorted array or palindrome, you start one pointer at each end and move them toward each other based on a condition — O(n) instead of O(n²). There's also a "fast and slow" variant where both move in the same direction for in-place filtering. The key is that you can decide which pointer to move without checking every pair.

**The basic flow (converging):**
```java
int left = 0, right = arr.length - 1;
while (left < right) {
    // compare / compute
    if (condition) left++;
    else right--;
}
```

**The part that trips everyone up:** you must move the **correct** pointer. In "container with most water," move the shorter side — moving the taller side can skip the optimal answer. Also ensure the array is sorted when using two pointers for sum/search problems.

**The mistakes to remember:**
- Moving the wrong pointer (shorter vs taller)
- Using two pointers on an unsorted array (use hash map instead)
- Off-by-one: `left < right`, not `left <= right`
- Confusing fast/slow roles in in-place filtering
