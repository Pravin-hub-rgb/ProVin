## Mini Quiz

1. In "Container With Most Water," which pointer do you move and why?
2. Why does 3Sum require sorting the array first?
3. What is the difference between the converging and fast & slow variants of two pointers?
4. In "Merge Sorted Array," why do you merge from the end?
5. What is the time complexity of the two-pointer approach to a sorted two-sum?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. Move the **shorter** side. The shorter line is the bottleneck — any container with it is limited by its height. Moving the taller side can't improve the area (width shrinks and height stays capped by the shorter). Moving the shorter side is the only way to possibly find a taller line.
2. Two pointers only work on sorted arrays — you need the sorted order to decide which pointer to move (if sum is too small, move left up for a bigger value; too big, move right down). Also, sorting enables duplicate skipping (skip if `nums[i] == nums[i-1]`).
3. Converging: pointers start at opposite ends and move toward each other (palindrome, container, two-sum sorted). Fast & slow: both start at the beginning, one moves faster (remove duplicates, move zeroes, in-place filtering). Converging is for pair-finding; fast & slow is for in-place compaction.
4. Merging from the front overwrites nums1's unread elements (nums1 has placeholders at the end). Merging from the back writes into the empty slots, preserving unread elements.
5. O(n) — single pass, each step eliminates one element. O(1) space.

</details>

## One-Page Cheat Sheet

**Core pattern:** two indices instead of nested loops. Converging (both ends → middle) for pair-finding/palindrome; fast & slow (same direction) for in-place filtering.

**Converging template:**
```java
int left = 0, right = arr.length - 1;
while (left < right) {
    // compare / compute
    if (condition) left++;
    else right--;
}
```

**Fast & slow template:**
```java
int slow = 0;
for (int fast = 0; fast < arr.length; fast++) {
    if (arr[fast] != 0) {   // or "is new value"
        arr[slow] = arr[fast]; // or swap
        slow++;
    }
}
```

**Complexities:** O(n) time, O(1) space for both variants.

**When to use Two Pointers:** sorted array + pair search, palindrome/symmetry, in-place removal/filtering, merging two sorted arrays, container/max area problems.

## In Your Own Words

1. Why does sorting enable the two-pointer approach for 3Sum?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Sorting lets you decide which pointer to move without checking every pair. If `nums[i] + nums[left] + nums[right] < 0`, you need a bigger sum → move `left` up (sorted, so nums[left+1] ≥ nums[left]). If > 0, move `right` down. This eliminates the inner loop. Sorting also enables duplicate skipping: skip `nums[i]` if it equals `nums[i-1]`. Without sorting, two pointers don't work — you'd need a hash map.

</details>

2. In "Container With Most Water," why move the shorter side?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The shorter side is the bottleneck — area = width × min(heights). Moving the taller side keeps the height capped by the shorter side (no improvement possible) while shrinking width. Moving the shorter side is the only way to potentially find a taller line. This is safe: the current container with the shorter side is the best possible with that shorter side at this width.

</details>

3. What's the difference between converging and fast & slow two pointers?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Converging: pointers start at opposite ends and move toward each other (palindrome, container, sorted two-sum). Used for pair-finding and symmetry checks. Fast & slow: both start at the beginning, one moves faster (remove duplicates, move zeroes, in-place compaction). Used for filtering/rearranging in place. Converging needs sorted or symmetric input; fast & slow works on any array.

</details>

4. Why merge from the end in "Merge Sorted Array"?

<details>
<summary>Show Answer</summary>

**Sample Answer:** nums1 has m real elements followed by n placeholder slots. Merging from the front would overwrite nums1's unread elements before they're read. Merging from the end writes into the empty placeholder slots, preserving unread elements. Loop while `j >= 0` (nums2 exhausted) — remaining nums1 elements are already in place.

</details>
