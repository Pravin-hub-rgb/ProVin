**Problem:** Given an array, move all 0s to the end while maintaining the relative order of non-zero elements. Do it in place. (LeetCode #283)

**Link:** https://leetcode.com/problems/move-zeroes/

---

## Which Technique, and Why?

You need to move all zeros to the end, preserving order of non-zeros, in place (O(1) space) → **Two Pointers (fast & slow)**. Slow marks the write position for the next non-zero; fast scans ahead. When fast finds a non-zero, swap/write it to slow's position.

Why not count zeros and overwrite? That works (O(n) time, O(1) space) but requires two passes. Two pointers does it in one pass.

**Signal in the problem:** "move all X to the end" + "maintain relative order" + "in place" → fast & slow pointers.

## Approach

`slow = 0`. For `fast` from 0 to n-1: if `nums[fast] != 0`, swap `nums[slow]` and `nums[fast]`, then `slow++`. Non-zeros get written to the front in order; zeros bubble to the back.

## Pseudocode

```
slow = 0
for fast from 0 to n-1:
    if nums[fast] != 0:
        swap(nums[slow], nums[fast])
        slow++
```

## Java Code

```java
class Solution {
    public void moveZeroes(int[] nums) {
        int slow = 0;
        for (int fast = 0; fast < nums.length; fast++) {
            if (nums[fast] != 0) {
                int temp = nums[slow];
                nums[slow] = nums[fast];
                nums[fast] = temp;
                slow++;
            }
        }
    }
}
```

## Line-by-line

- `slow` is the write position for the next non-zero.
- `fast` scans every element.
- When `nums[fast] != 0`, swap it with `nums[slow]` (puts the non-zero in its final position) and advance `slow`.
- Zeros naturally end up at the back because they're never swapped forward (slow only advances on non-zeros).
- Void return — modifies in place.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — two pointers (the swap uses a temp variable).

## Common Mistakes

- **Using extra array** — works but O(n) space, violates the in-place requirement.
- **Not preserving order.** Swapping (as above) preserves order. If you just "move zeros to end" by counting, you also preserve order — but a naive swap of zeros with the end loses order.
- **Counting approach pitfall:** counting zeros then overwriting works, but you must write non-zeros first, then zeros. Don't overwrite non-zeros with zeros.
- **Empty array / all zeros / no zeros** — the loop handles all (slow stays 0 or advances correctly).

## How to Explain (interview)

**Opening:** Move Zeroes moves all 0s to the end while keeping non-zero order, in place. Fast & slow pointers: slow marks the write position, fast scans. When fast finds a non-zero, swap it to slow's position and advance slow. Zeros naturally bubble to the back. O(n) time, O(1) space.

**The basic flow:**
```java
int slow = 0;
for (int fast = 0; fast < nums.length; fast++) {
    if (nums[fast] != 0) {
        int t = nums[slow]; nums[slow] = nums[fast]; nums[fast] = t;
        slow++;
    }
}
```

**The part that trips everyone up:** the swap preserves relative order of non-zeros. Also, don't advance `slow` on zeros — only on non-zeros.

**The mistakes to remember:**
- Using extra space (violates in-place requirement)
- Swapping zeros to the front (loses order)
- Forgetting that the method returns void (modifies in place)
