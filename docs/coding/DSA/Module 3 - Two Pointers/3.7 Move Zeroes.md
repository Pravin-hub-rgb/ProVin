**Problem:** Given an integer array `nums`, move all `0`s to the end of it while maintaining the relative order of the non-zero elements. (LeetCode #283)

**Note:** You must do this **in-place** without making a copy of the array.

**Link:** https://leetcode.com/problems/move-zeroes/

---

## What This Problem Is Asking (Simple Terms)

You have an array of integers. You need to move all zeros to the end while keeping the non-zero elements in their original relative order. You must do this **in place** — no creating a new array.

For example, `nums = [0,1,0,3,12]` → after moving zeros to the end: `[1,3,12,0,0]`.

You modify the array in place and don't return anything (void).

---

## Example 1

**Input:** `nums = [0,1,0,3,12]`

**Output:** `[1,3,12,0,0]`

**Explanation:** Non-zeros `[1,3,12]` keep their order at the front; zeros `[0,0]` move to the back.

---

## Example 2

**Input:** `nums = [0]`

**Output:** `[0]`

**Explanation:** Single zero, nothing to move.

---

## Constraints

- `1 <= nums.length <= 10^4`
- `-2^31 <= nums[i] <= 2^31 - 1`

**Follow-up:** Could you minimize the total number of operations?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could count all non-zero elements, then overwrite the array: first all non-zeros in order, then all zeros.

### Brute Force Pseudocode

```
count = 0
for each x in nums:
    if x != 0: count++
// overwrite: first copy non-zeros, then fill rest with zeros
i = 0
for each x in nums:
    if x != 0: nums[i++] = x
while i < n: nums[i++] = 0
```

### Why Brute Force Is Not Ideal

Two passes over the array. The follow-up asks to minimize total operations — one pass is better.

---

## Which Data Structure/Technique, and Why?

You need to move all zeros to the end, preserving order of non-zeros, in place (O(1) space) → **Two Pointers (fast & slow)**. Slow marks the write position for the next non-zero; fast scans ahead. When fast finds a non-zero, swap/write it to slow's position.

Why not count zeros and overwrite? That works (O(n) time, O(1) space) but requires two passes. Two pointers does it in one pass.

**Signal in the problem:** "move all X to the end" + "maintain relative order" + "in place" → fast & slow pointers.

---

## Optimized Approach (Fast & Slow Pointers)

`slow = 0`. For `fast` from 0 to n-1: if `nums[fast] != 0`, swap `nums[slow]` and `nums[fast]`, then `slow++`. Non-zeros get written to the front in order; zeros bubble to the back.

### Pseudocode

```
slow = 0
for fast from 0 to n-1:
    if nums[fast] != 0:
        swap(nums[slow], nums[fast])
        slow++
```

### Java Code

```java
class Solution {
    public void moveZeroes(int[] nums) {
        int slow = 0;
        for (int fast = 0; fast < nums.length; fast++) {
            if (nums[fast] != 0) {
                int temp = nums[slow];
                nums[slow] = nums[fast];
                nums[fast] = temp;
                slow++;
            }
        }
    }
}
```

### Line-by-line

- `slow = 0` — write position starts at 0.
- `for fast from 0 to n-1` — scan every element.
- `if nums[fast] != 0` — found a non-zero to keep.
- `swap(nums[slow], nums[fast])` — move non-zero to write position; whatever was at slow goes to fast's old position (could be zero or another non-zero).
- `slow++` — advance write position.

## Complexity

- Time: O(n) — single pass with fast pointer.
- Space: O(1) — only two pointers and a temp variable.

## Common Mistakes

- **Not handling all-zeros array** — `slow` never advances, returns correctly (array unchanged).
- **Not handling no-zeros array** — every element swaps with itself (slow == fast), array unchanged.
- **Comparing `nums[fast] != nums[slow]` instead of `nums[fast] != 0`** — you're looking for non-zero values, not differences between positions.
- **Forgetting to increment `slow`** — all non-zeros would write to position 0, overwriting each other.

## How to Explain (interview)

**Opening:** Move Zeroes moves all zeros to the end while preserving non-zero order, in place. Use two pointers: slow marks the write position, fast scans ahead. When fast finds a non-zero, swap it to slow's position and advance slow. O(n) time, O(1) space.

**The basic flow:**
```java
int slow = 0;
for (int fast = 0; fast < nums.length; fast++) {
    if (nums[fast] != 0) {
        swap(nums[slow], nums[fast]);
        slow++;
    }
}
```

**The part that trips everyone up:** the swap moves whatever was at `slow` to `fast`'s old position. If `slow == fast`, it's a self-swap (harmless). If `slow < fast`, the value at `slow` (could be zero or non-zero) moves to `fast`'s position, and `fast`'s non-zero moves to `slow`.

**The mistakes to remember:**
- Comparing against wrong value (`nums[slow]` instead of `0`)
- Forgetting to increment `slow`
- Not handling edge cases (all zeros, no zeros)
