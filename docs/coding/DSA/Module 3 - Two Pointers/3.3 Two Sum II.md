# 3.3 Two Sum II — Input Array Is Sorted

**Problem:** Given a 1-indexed sorted array, find two numbers that add up to target. Return their indices (1-based). (LeetCode #167)

**Link:** https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/

---

## Which Technique, and Why?

The array is **sorted**. Two Sum on a sorted array → **Two Pointers (converging)**. Start one pointer at each end; if the sum is too small, move left up (increase sum); if too big, move right down (decrease sum). O(n) time, O(1) space.

Why not a hash map (Module 2)? A hash map works too (O(n) time, O(n) space), but since the array is sorted, two pointers gives O(1) space and is the intended solution. The sorted property is the signal.

**Signal in the problem:** "sorted array" + "two numbers that sum to target" → two pointers from both ends. (Unsorted → hash map.)

## Approach

`left = 0`, `right = n-1`. While `left < right`: compute `sum = nums[left] + nums[right]`. If sum == target → return (1-based indices). If sum < target → left++ (need bigger). If sum > target → right-- (need smaller).

## Pseudocode

```
left = 0, right = n - 1
while left < right:
    sum = nums[left] + nums[right]
    if sum == target: return [left+1, right+1]
    if sum < target: left++
    else: right--
```

## Java Code

```java
class Solution {
    public int[] twoSum(int[] numbers, int target) {
        int left = 0, right = numbers.length - 1;

        while (left < right) {
            int sum = numbers[left] + numbers[right];
            if (sum == target) {
                return new int[]{left + 1, right + 1}; // 1-based
            } else if (sum < target) {
                left++;
            } else {
                right--;
            }
        }
        return new int[]{}; // shouldn't reach here
    }
}
```

## Line-by-line

- Pointers start at opposite ends — smallest + largest sum.
- `sum < target` → need a bigger sum → move `left` up (array is sorted, so nums[left+1] ≥ nums[left]).
- `sum > target` → need a smaller sum → move `right` down.
- Return 1-based indices (`left + 1`, `right + 1`) per problem spec.
- Each step eliminates one element → O(n) total.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — two pointers.

## Common Mistakes

- **Returning 0-based indices.** This problem wants 1-based. (Two Sum (Module 2) wants 0-based.) Read the spec.
- **Using a hash map** — works but uses O(n) space; two pointers is cleaner for sorted input.
- **Infinite loop:** if you forget to move a pointer when `sum == target` is handled by return, fine. But ensure `left++`/`right--` happen in the else branches.
- **Assuming duplicates are fine** — they are; the logic still works with duplicates.

## How to Explain (interview)

**Opening:** Two Sum II is Two Sum on a sorted array. Instead of a hash map (O(n) space), use two pointers: one at each end. If the sum is too small, move the left pointer up (bigger value); if too big, move the right pointer down (smaller value). O(n) time, O(1) space. Returns 1-based indices.

**The basic flow:**
```java
int left = 0, right = nums.length - 1;
while (left < right) {
    int sum = nums[left] + nums[right];
    if (sum == target) return new int[]{left + 1, right + 1};
    if (sum < target) left++; else right--;
}
```

**The part that trips everyone up:** the array is **sorted** (that's the whole point). And indices are **1-based** here, unlike Two Sum's 0-based.

**The mistakes to remember:**
- Returning 0-based instead of 1-based indices
- Using a hash map (works but wastes space when sorted)
- Forgetting to move a pointer (infinite loop)
