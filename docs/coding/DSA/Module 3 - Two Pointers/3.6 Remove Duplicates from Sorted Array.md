**Problem:** Given an integer array `nums` sorted in **non-decreasing order**, remove the duplicates **in-place** such that each unique element appears only **once**. The **relative order** of the elements should be kept the **same**. Then return the number of unique elements in `nums`.

Consider the number of unique elements of `nums` be `k`. To get accepted, you need to do the following things:

- Change the array `nums` such that the first `k` elements of `nums` contain the unique elements in the order they were present in `nums` initially. The remaining elements of `nums` are not important, as well as the size of `nums`.
- Return `k`.

**Link:** https://leetcode.com/problems/remove-duplicates-from-sorted-array/

---

## What This Problem Is Asking (Simple Terms)

You have a **sorted** array of numbers, and some numbers appear more than once. You need to remove the duplicates **in place** — meaning you rearrange the same array, not create a new one — so that each unique number appears exactly once, in the same order as before.

After you're done, the first part of the array should contain all the unique numbers in order, and you return **how many** unique numbers there were. What happens to the rest of the array doesn't matter.

For example, `nums = [1,1,2]` → after removing duplicates, `nums` becomes `[1,2,...]` and you return `2`.

---

## Example 1

**Input:** `nums = [1,1,2]`

**Output:** `2`, `nums = [1,2,_]`

**Explanation:** Your function should return `k = 2`, with the first two elements of `nums` being `1` and `2`. It doesn't matter what you leave beyond the returned `k` (hence underscores).

---

## Example 2

**Input:** `nums = [0,0,1,1,1,2,2,3,3,4]`

**Output:** `5`, `nums = [0,1,2,3,4,_,_,_,_,_]`

**Explanation:** Your function should return `k = 5`, with the first five elements of `nums` being `0`, `1`, `2`, `3`, and `4`. It does not matter what you leave beyond the returned `k`.

---

## Constraints

- `1 <= nums.length <= 3 * 10^4`
- `-100 <= nums[i] <= 100`
- `nums` is sorted in **non-decreasing order** (ascending order).

**Follow-up:** Can you solve it in O(n) time and O(1) extra space?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could check every element against every other element to find duplicates, then remove them. Or you could build a new list with only unique numbers and copy it back. But that uses extra memory, and the problem requires doing this **in place**.

### Brute Force Pseudocode

```
result = empty list
for each x in nums:
    if x is not in result:
        add x to result
copy result back to nums[0..result.size-1]
return result.size
```

### Why Brute Force Is Not Ideal

Checking whether `x` is already in `result` takes time proportional to the current size of `result`. Over the whole array, that's O(n²). And building a separate list uses extra memory, but the problem demands O(1) extra space.

---

## Which Data Structure/Technique, and Why?

The array is **sorted**, so duplicates are always **next to each other**. This means you don't need to scan the whole array for each element — you just need to compare each element with the one you last kept.

You need **two pointers** moving in the **same direction**:
- A **slow** pointer marks where the next unique number should be written.
- A **fast** pointer scans ahead, looking for the next new number.

**Signal in the problem:** "remove duplicates **in place**" + "sorted array" + "**O(1) extra space**" → two pointers, same direction.

---

## Optimized Approach (Same-Side Two Pointers)

Use two pointers:
- `slow` — points to the last unique number we've kept.
- `fast` — scans ahead, looking for the next new number.

When `fast` finds a number different from the one at `slow`, copy it to `slow + 1`, then move `slow` forward by one. `fast` always moves forward, one step at a time.

### Pseudocode

```
slow = 0
for fast from 1 to n-1:
    if nums[fast] != nums[slow]:
        slow++
        nums[slow] = nums[fast]
return slow + 1
```

### Java Code

```java
class Solution {
    public int removeDuplicates(int[] nums) {
        if (nums.length == 0) return 0;

        int slow = 0;
        for (int fast = 1; fast < nums.length; fast++) {
            if (nums[fast] != nums[slow]) {
                slow++;
                nums[slow] = nums[fast];
            }
        }
        return slow + 1;
    }
}
```

### Line-by-line

- `slow = 0` — the first element is always unique, so `slow` starts at index 0.
- `for fast from 1 to n-1` — `fast` scans every element after the first.
- `if nums[fast] != nums[slow]` — found a new unique number.
- `slow++` → `nums[slow] = nums[fast]` — write it to the next position after the last unique number.
- Return `slow + 1` — `slow` is an index (0-based), so the count of unique numbers is `slow + 1`.

## Complexity

- Time: O(n) — `fast` makes a single pass over the array.
- Space: O(1) — only two pointers, no extra data structures.

## Common Mistakes

- **Not handling an empty array** — check `nums.length == 0` first (or handle it implicitly).
- **Returning `slow` instead of `slow + 1`** — `slow` is a zero-based index, so the count of elements is `slow + 1`.
- **Comparing `nums[fast]` with `nums[fast-1]` instead of `nums[slow]`** — you must compare against the last **kept** number, not the last **seen** number. Otherwise you might keep duplicates.
- **Using a separate list** — the problem requires O(1) extra space, so you must overwrite `nums` in place.

## How to Explain (interview)

**Opening:** Remove Duplicates from Sorted Array removes duplicates from a sorted array **in place**, keeping each unique element once and returning how many there are. Since the array is sorted, duplicates are next to each other, so you only need to compare the current number with the last one you kept.

**The basic flow:**
```java
int slow = 0;
for (int fast = 1; fast < nums.length; fast++) {
    if (nums[fast] != nums[slow]) {
        slow++;
        nums[slow] = nums[fast];
    }
}
return slow + 1;
```

**The part that trips everyone up:** comparing `nums[fast]` with `nums[slow]` (the last **kept** number), not `nums[fast-1]` (the last **seen** number). If you compare with `fast-1`, you'd copy `1` again when you see `[1,1,2]` because `nums[2]` equals `nums[1]` even though `1` is already kept.

**The mistakes to remember:**
- Returning `slow` instead of `slow + 1`
- Comparing `nums[fast]` with `nums[fast-1]` instead of `nums[slow]`
- Using extra space (a new array) instead of overwriting in place
