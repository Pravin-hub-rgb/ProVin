# 3.6 Remove Duplicates from Sorted Array

**Problem:** Given a sorted array, remove duplicates in-place so each element appears once. Return the new length. (LeetCode #26)

**Link:** https://leetcode.com/problems/remove-duplicates-from-sorted-array/

---

## Which Technique, and Why?

The array is **sorted**, so duplicates are adjacent. You need to remove duplicates **in place** (O(1) extra space) → **Two Pointers (fast & slow)**. Slow pointer marks the write position; fast scans ahead. When fast finds a new value, write it at slow and advance both.

Why not a set? A set works but uses O(n) space. The problem wants O(1) space, so two pointers is the intended solution.

**Signal in the problem:** "sorted array" + "remove duplicates in place" + "O(1) extra space" → fast & slow pointers.

## Approach

`slow = 0`. For `fast` from 1 to n-1: if `nums[fast] != nums[slow]`, increment slow and copy `nums[fast]` to `nums[slow]`. Return `slow + 1` (new length).

## Pseudocode

```
if nums is empty: return 0
slow = 0
for fast from 1 to n-1:
    if nums[fast] != nums[slow]:
        slow++
        nums[slow] = nums[fast]
return slow + 1
```

## Java Code

```java
class Solution {
    public int removeDuplicates(int[] nums) {
        if (nums.length == 0) return 0;

        int slow = 0;
        for (int fast = 1; fast < nums.length; fast++) {
            if (nums[fast] != nums[slow]) {
                slow++;
                nums[slow] = nums[fast];
            }
        }
        return slow + 1;
    }
}
```

## Line-by-line

- `slow` points to the last unique element written.
- `fast` scans ahead looking for the next unique value.
- When `nums[fast] != nums[slow]`, we found a new unique value → advance `slow` and write it there.
- Return `slow + 1` because slow is 0-based (length = index + 1).
- Elements beyond `slow + 1` are leftover garbage — the problem only cares about the first `slow+1` elements.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — two pointers.

## Common Mistakes

- **Returning `slow` instead of `slow + 1`.** slow is 0-based; length is index + 1.
- **Not handling empty array.** `nums.length == 0` → return 0 (avoid index out of bounds).
- **Using a set** — works but O(n) space, violates the O(1) constraint.
- **Confusing with "Remove Duplicates from Sorted Array II"** (allow up to 2 duplicates) — different problem, needs a different counter.

## How to Explain (interview)

**Opening:** Remove Duplicates from a Sorted Array removes duplicates in place with O(1) extra space. Fast & slow pointers: slow marks the write position, fast scans ahead. When fast finds a value different from slow's, write it at slow and advance slow. Return slow + 1. O(n) time, O(1) space.

**The basic flow:**
```java
int slow = 0;
for (int fast = 1; fast < nums.length; fast++) {
    if (nums[fast] != nums[slow]) {
        nums[++slow] = nums[fast];
    }
}
return slow + 1;
```

**The part that trips everyone up:** the array is **sorted** (duplicates are adjacent). Also return `slow + 1`, not `slow`. Elements beyond the new length are garbage — the problem only checks the first `slow+1`.

**The mistakes to remember:**
- Returning `slow` instead of `slow + 1`
- Not handling empty array
- Using a HashSet (works but O(n) space, violates constraint)
