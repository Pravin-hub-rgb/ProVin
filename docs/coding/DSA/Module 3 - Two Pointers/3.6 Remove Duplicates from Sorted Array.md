**Problem:** Given an integer array `nums` sorted in non-decreasing order, remove the duplicates **in-place** such that each unique element appears only **once**. The relative order of the elements should be kept the same. Then return the number of unique elements in `nums`.

**Link:** https://leetcode.com/problems/remove-duplicates-from-sorted-array/

---

## What This Problem Is Asking (Simple Terms)

You have a **sorted** array with duplicates. You need to remove duplicates **in place** (without creating a new array) so each element appears only once. Return the count of unique elements.

The first `k` elements of the array should contain the unique values in their original order. What happens beyond index `k-1` doesn't matter.

For example, `nums = [1,1,2]` → after removal, `nums = [1,2,...]` and return `2`.

---

## Example 1

**Input:** `nums = [1,1,2]`

**Output:** `2`, `nums = [1,2,_]`

**Explanation:** Your function should return `k = 2`, with the first two elements of `nums` being `1` and `2`. It doesn't matter what you leave beyond the returned `k`.

---

## Example 2

**Input:** `nums = [0,0,1,1,1,2,2,3,3,4]`

**Output:** `5`, `nums = [0,1,2,3,4,_,_,_,_,_]`

**Explanation:** Your function should return `k = 5`, with the first five elements of `nums` being `0`, `1`, `2`, `3`, and `4`.

---

## Constraints

- `1 <= nums.length <= 3 * 10^4`
- `-100 <= nums[i] <= 100`
- `nums` is sorted in non-decreasing order.

**Follow-up:** Can you solve it in O(n) time and O(1) extra space?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could create a new array, copy only the unique elements into it, then copy back. But that uses O(n) extra space.

### Brute Force Pseudocode

```
unique = []
for each x in nums:
    if x not in unique: unique.add(x)
copy unique back to nums[0..unique.size-1]
return unique.size
```

### Why Brute Force Is Not Ideal

Uses O(n) extra space for the `unique` array. The follow-up asks for O(1) extra space.

---

## Which Data Structure/Technique, and Why?

The array is **sorted**, so duplicates are adjacent. You need to remove duplicates **in place** (O(1) extra space) → **Two Pointers (fast & slow)**. Slow pointer marks the write position; fast scans ahead. When fast finds a new value, write it at slow and advance both.

Why not a set? A set works but uses O(n) space. The problem wants O(1) space, so two pointers is the intended solution.

**Signal in the problem:** "sorted array" + "remove duplicates in place" + "O(1) extra space" → fast & slow pointers.

---

## Optimized Approach (Fast & Slow Pointers)

`slow = 0`. For `fast` from 1 to n-1: if `nums[fast] != nums[slow]`, increment `slow` and copy `nums[fast]` to `nums[slow]`. Return `slow + 1` (new length).

### Pseudocode

```
slow = 0
for fast from 1 to n-1:
    if nums[fast] != nums[slow]:
        slow++
        nums[slow] = nums[fast]
return slow + 1
```

### Java Code

```java
class Solution {
    public int removeDuplicates(int[] nums) {
        if (nums.length == 0) return 0;
        int slow = 0;
        for (int fast = 1; fast < nums.length; fast++) {
            if (nums[fast] != nums[slow]) {
                slow++;
                nums[slow] = nums[fast];
            }
        }
        return slow + 1;
    }
}
```

### Line-by-line

- `slow = 0` — first element is always kept (write position starts at 0).
- `for fast from 1 to n-1` — scan every element after the first.
- `if nums[fast] != nums[slow]` — found a new unique value.
- `slow++` → `nums[slow] = nums[fast]` — write it at the next write position.
- Return `slow + 1` — count of unique elements (slow is 0-indexed, count is 1-indexed).

## Complexity

- Time: O(n) — single pass with fast pointer.
- Space: O(1) — only two pointers.

## Common Mistakes

- **Not handling empty array** — check `nums.length == 0` first.
- **Returning `slow` instead of `slow + 1`** — slow is 0-indexed, count is 1-indexed.
- **Comparing `nums[fast] != nums[fast-1]` instead of `nums[fast] != nums[slow]`** — must compare against the last *kept* element, not the last *seen* element.
- **Modifying elements beyond `slow+1`** — only the first `slow+1` elements matter; the rest can be anything.

## How to Explain (interview)

**Opening:** Remove Duplicates from Sorted Array removes duplicates in-place from a sorted array. Since the array is sorted, duplicates are adjacent. Use two pointers: slow marks the write position, fast scans ahead. When fast finds a new value, write it at slow and advance both. O(n) time, O(1) space.

**The basic flow:**
```java
int slow = 0;
for (int fast = 1; fast < nums.length; fast++) {
    if (nums[fast] != nums[slow]) {
        slow++;
        nums[slow] = nums[fast];
    }
}
return slow + 1;
```

**The part that trips everyone up:** comparing `nums[fast] != nums[slow]` (against the last *kept* element), not `nums[fast] != nums[fast-1]` (against the last *seen* element). If you have `[0,0,1]`, when fast reaches `1` at index 2, `slow` is still at index 0 (`0`), so `nums[2] != nums[0]` is true → write `1` at `nums[1]`.

**The mistakes to remember:**
- Not handling empty array
- Returning `slow` instead of `slow + 1`
- Comparing against `nums[fast-1]` instead of `nums[slow]`
