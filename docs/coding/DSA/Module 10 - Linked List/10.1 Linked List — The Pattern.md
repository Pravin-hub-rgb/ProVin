## The Core Idea

A linked list is a sequence of **nodes**, where each node holds a value and a pointer to the next node. Unlike arrays, there's no contiguous memory — nodes can be scattered. You traverse by following pointers.

**Why linked lists?** O(1) insert/delete at a known position (no shifting). But O(n) access (no index). They're the foundation for stacks, queues, graphs, and many advanced structures.

**The mental model:** draw the list as boxes (nodes) with arrows (pointers). To modify the list, you're rewiring arrows. Always handle null (end of list) and edge cases (empty list, single node).

## Worked Example: Reverse a Linked List

**Problem:** Reverse a singly linked list.

### Brute force (O(n) space)

Traverse, store all nodes in an array, reverse the array, rebuild. Works but uses O(n) space.

### Optimized (O(n) time, O(1) space) — three pointers

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        ListNode prev = null;
        ListNode curr = head;

        while (curr != null) {
            ListNode next = curr.next;  // save next before overwriting
            curr.next = prev;           // reverse the link
            prev = curr;                // advance prev
            curr = next;                // advance curr
        }
        return prev;  // new head
    }
}
```

**Line-by-line:**
- `prev = null` — the new tail's next will be null.
- `curr = head` — start at the first node.
- `next = curr.next` — save the next node before we overwrite `curr.next`.
- `curr.next = prev` — reverse the link (point backward).
- `prev = curr` — advance prev to current.
- `curr = next` — advance curr to the saved next.
- Return `prev` — when `curr` is null, `prev` is the new head.

**Key insight:** you must save `next` before overwriting `curr.next`, otherwise you lose the rest of the list. Draw it: three arrows (prev, curr, next) moving one step at a time.

## Common Mistakes

- **Losing the rest of the list.** Always save `next` before overwriting `curr.next`.
- **Not handling null/empty list.** Check `head == null` or `head.next == null` early.
- **Forgetting to return the new head.** After reversal, `prev` is the new head, not `head`.
- **Off-by-one in "remove nth from end."** Use fast & slow pointers with a gap of n.
- **Cycle detection infinite loop.** If there's a cycle, a simple traversal never ends. Use Floyd's (slow/fast) or a visited set.

## How to Explain (interview)

**Opening:** A linked list is a chain of nodes where each node points to the next. No random access (O(n) to reach element i), but O(1) insert/delete at a known position. The key skill is pointer manipulation — draw the nodes and arrows, then rewire carefully. Always handle null (end of list) and edge cases (empty, single node).

**The basic flow (reverse):**
```java
ListNode prev = null, curr = head;
while (curr != null) {
    ListNode next = curr.next;  // save
    curr.next = prev;            // reverse
    prev = curr;                 // advance
    curr = next;
}
return prev;  // new head
```

**The part that trips everyone up:** save `next` before overwriting `curr.next` — otherwise you lose the rest of the list. Also, return `prev` (the new head), not `head`.

**The mistakes to remember:**
- Losing the rest of the list (not saving next)
- Not handling null/empty list
- Returning the old head instead of the new head
- Off-by-one in "remove nth from end" (gap of n, not n-1)
- Infinite loop on cyclic lists (use Floyd's or visited set)
