**Problem:** Given the head of a linked list, determine if it is a palindrome. (LeetCode #234)

**Link:** https://leetcode.com/problems/palindrome-linked-list/

---

## Which Technique, and Why?

Check if a linked list is a palindrome → **Find middle + reverse second half + compare**. O(n) time, O(1) space. (A stack or array approach works but uses O(n) space.)

Why this approach? You can't index a linked list, so you can't compare symmetric positions directly. Solution: find the middle, reverse the second half, then compare first half with reversed second half.

**Signal in the problem:** "palindrome linked list" → find middle + reverse second half + compare (O(1) space). Or stack/array (O(n) space, simpler).

## Approach

1. Find the middle (slow & fast pointers).
2. Reverse the second half (starting from middle).
3. Compare first half with reversed second half.
4. (Optional) Restore the list.

## Pseudocode

```
// Step 1: find middle
slow = head, fast = head
while fast != null and fast.next != null:
    slow = slow.next
    fast = fast.next.next

// Step 2: reverse second half
prev = null, curr = slow
while curr != null:
    next = curr.next
    curr.next = prev
    prev = curr
    curr = next

// Step 3: compare
first = head, second = prev
while second != null:
    if first.val != second.val: return false
    first = first.next
    second = second.next
return true
```

## Java Code

```java
class Solution {
    public boolean isPalindrome(ListNode head) {
        if (head == null || head.next == null) return true;

        // Step 1: find middle
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }

        // Step 2: reverse second half
        ListNode prev = null, curr = slow;
        while (curr != null) {
            ListNode next = curr.next;
            curr.next = prev;
            prev = curr;
            curr = next;
        }

        // Step 3: compare
        ListNode first = head, second = prev;
        while (second != null) {
            if (first.val != second.val) return false;
            first = first.next;
            second = second.next;
        }
        return true;
    }
}
```

## Line-by-line

- **Find middle:** slow/fast pointers. For even length, slow ends at the second middle (start of second half).
- **Reverse second half:** standard three-pointer reversal starting from `slow`.
- **Compare:** walk both halves simultaneously. If any mismatch → not palindrome. `second` (reversed half) is shorter or equal, so loop on `second != null`.
- Returns true if all match.

## Complexity

- Time: O(n) — three passes (find middle, reverse, compare), each O(n).
- Space: O(1) — only pointers.

## Common Mistakes

- **Not handling single node / empty list.** Return true (trivially a palindrome).
- **Comparing the wrong halves.** Compare first half with reversed second half. The reversed half starts at `prev` (new head of reversed second half).
- **Off-by-one in middle for even length.** Slow/fast with `fast != null && fast.next != null` puts slow at the second middle for even length — this is correct (second half starts at the second middle).
- **Forgetting to restore the list.** Some problems expect the list unchanged. If so, reverse the second half back after comparison. (This problem doesn't require it, but good practice.)

## How to Explain (interview)

**Opening:** Palindrome Linked List checks if the list reads the same forwards and backwards. Since you can't index a linked list, find the middle (slow & fast), reverse the second half, then compare first half with reversed second half. O(n) time, O(1) space. Three passes: find middle, reverse, compare.

**The basic flow:**
```java
// 1. Find middle
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; }
// 2. Reverse second half
ListNode prev = null, curr = slow;
while (curr != null) { ListNode next = curr.next; curr.next = prev; prev = curr; curr = next; }
// 3. Compare
ListNode a = head, b = prev;
while (b != null) { if (a.val != b.val) return false; a = a.next; b = b.next; }
return true;
```

**The part that trips everyone up:** slow ends at the **second middle** for even length (correct start of second half). Also, compare until `second != null` (the reversed half is shorter or equal). Don't forget to restore the list if the problem requires it.

**The mistakes to remember:**
- Not handling single node / empty (return true)
- Comparing the wrong halves
- Off-by-one in middle (first vs second middle)
- Forgetting to restore the list if required
