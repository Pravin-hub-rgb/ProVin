**Problem:** Merge two sorted linked lists into one sorted list. (LeetCode #21)

**Link:** https://leetcode.com/problems/merge-two-sorted-lists/

---

## Which Technique, and Why?

Merge two sorted lists → **Two pointers (one per list) + dummy node**. Compare heads, attach the smaller one, advance. O(n + m) time, O(1) space (reusing existing nodes).

**Signal in the problem:** "merge two sorted lists" → two pointers + dummy node. Similar to merge in merge sort, but on linked lists.

## Approach

Use a dummy head node. Compare `l1.val` and `l2.val`; attach the smaller to `current.next`; advance that list's pointer. At the end, attach the remaining list. Return `dummy.next`.

## Pseudocode

```
dummy = new ListNode(0)
current = dummy
while l1 != null and l2 != null:
    if l1.val <= l2.val:
        current.next = l1; l1 = l1.next
    else:
        current.next = l2; l2 = l2.next
    current = current.next
current.next = (l1 != null) ? l1 : l2
return dummy.next
```

## Java Code

```java
class Solution {
    public ListNode mergeTwoLists(ListNode l1, ListNode l2) {
        ListNode dummy = new ListNode(0);
        ListNode current = dummy;

        while (l1 != null && l2 != null) {
            if (l1.val <= l2.val) {
                current.next = l1;
                l1 = l1.next;
            } else {
                current.next = l2;
                l2 = l2.next;
            }
            current = current.next;
        }

        current.next = (l1 != null) ? l1 : l2;
        return dummy.next;
    }
}
```

## Line-by-line

- `dummy` — sentinel node before the head. Simplifies logic (no special-casing empty lists).
- `current` — tracks the last node in the merged list.
- Compare `l1.val` and `l2.val`; attach the smaller, advance that pointer.
- `current = current.next` — advance the merged list pointer.
- After the loop, one list may have remaining nodes — attach them all at once (`current.next = l1 or l2`).
- Return `dummy.next` — the actual head.

## Complexity

- Time: O(n + m) — each node visited once.
- Space: O(1) — reuses existing nodes (no new nodes created).

## Common Mistakes

- **Forgetting the dummy node.** Without it, you need special cases for empty lists and the first node. The dummy eliminates these.
- **Not attaching the remaining list.** After the loop, one list may still have nodes — `current.next = (l1 != null) ? l1 : l2`.
- **Using `l1.val < l2.val` instead of `<=`.** Either works for correctness, but `<=` ensures stability (equal elements from l1 come first).
- **Creating new nodes instead of reusing.** Works but uses O(n+m) space. The problem usually expects O(1) extra space.
