# 10.4 Reverse Linked List

**Problem:** Given the head of a singly linked list, reverse it and return the new head. (LeetCode #206)

**Link:** https://leetcode.com/problems/reverse-linked-list/

---

## Which Technique, and Why?

Reversing a linked list → **Three pointers (prev, curr, next)**. Walk the list, reversing each link as you go. O(n) time, O(1) space. No data structure needed — just pointer manipulation.

**Signal in the problem:** "reverse a linked list" → three-pointer iterative reversal. (Recursive version is O(n) space due to call stack.)

## Approach

Iterative: `prev = null`, `curr = head`. While `curr != null`: save `next = curr.next`, set `curr.next = prev`, advance `prev = curr`, `curr = next`. Return `prev`.

Recursive: reverse the rest, then point the next node's next back to current.

## Pseudocode (iterative)

```
prev = null, curr = head
while curr != null:
    next = curr.next
    curr.next = prev
    prev = curr
    curr = next
return prev
```

## Java Code (iterative)

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        ListNode prev = null;
        ListNode curr = head;

        while (curr != null) {
            ListNode next = curr.next;  // save before overwriting
            curr.next = prev;           // reverse link
            prev = curr;                // advance prev
            curr = next;                // advance curr
        }
        return prev;  // new head
    }
}
```

## Java Code (recursive)

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        if (head == null || head.next == null) return head;
        ListNode newHead = reverseList(head.next);
        head.next.next = head;   // reverse the link
        head.next = null;        // old head becomes tail
        return newHead;
    }
}
```

## Line-by-line (iterative)

- `prev = null` — the new tail's next will be null.
- `curr = head` — start at first node.
- `next = curr.next` — **save** next before overwriting `curr.next`.
- `curr.next = prev` — reverse the link (point backward).
- `prev = curr` — advance prev.
- `curr = next` — advance curr to saved next.
- Return `prev` — when `curr` is null, `prev` is the new head.

## Complexity

- Iterative: O(n) time, O(1) space.
- Recursive: O(n) time, O(n) space (call stack).

## Common Mistakes

- **Losing the rest of the list.** If you do `curr.next = prev` before saving `next`, you lose everything after. Always save first.
- **Returning `head` instead of `prev`.** After reversal, `head` is the tail (points to null). `prev` is the new head.
- **Not handling null/empty.** `head == null` → return null (loop doesn't execute, returns prev = null). Correct.
- **Single node.** `head.next == null` → loop runs once, returns head. Correct.

## How to Explain (interview)

**Opening:** Reverse Linked List reverses a singly linked list in O(n) time, O(1) space. Three pointers: prev, curr, next. Save next before overwriting curr.next, reverse the link, advance both pointers. Return prev (the new head). The recursive version is O(n) space due to the call stack.

**The basic flow:**
```java
ListNode prev = null, curr = head;
while (curr != null) {
    ListNode next = curr.next;  // save
    curr.next = prev;            // reverse
    prev = curr;                 // advance
    curr = next;
}
return prev;
```

**The part that trips everyone up:** save `next` **before** overwriting `curr.next`. Otherwise you lose the rest of the list. Also return `prev`, not `head`.

**The mistakes to remember:**
- Not saving next before overwriting (loses the list)
- Returning the old head instead of prev
- Not handling null/empty list
- Recursive version uses O(n) stack space
