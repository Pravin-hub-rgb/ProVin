**Tier 2 problem.** (LeetCode #328)

**Problem:** Given a linked list, group all odd-indexed nodes together followed by even-indexed nodes. (LeetCode #328)

**Link:** https://leetcode.com/problems/odd-even-linked-list/

---

## Which Technique, and Why?

"Group odd/even indexed nodes" → **Two pointers (odd and even)**. Maintain two separate lists (odd and even), then concatenate. O(n) time, O(1) space.

**Signal in the problem:** "odd even linked list" / "group by index parity" → two pointers splitting into odd/even lists.

## Approach

Two pointers: `odd` starts at head, `even` at head.next. Save `evenHead`. Walk: `odd.next = even.next; odd = odd.next;` then `even.next = odd.next; even = even.next;`. At the end, connect `odd.next = evenHead`.

## Pseudocode

```
if head == null: return null
odd = head, even = head.next, evenHead = even
while even != null and even.next != null:
    odd.next = even.next
    odd = odd.next
    even.next = odd.next
    even = even.next
odd.next = evenHead
return head
```

## Java Code

```java
class Solution {
    public ListNode oddEvenList(ListNode head) {
        if (head == null) return null;

        ListNode odd = head;
        ListNode even = head.next;
        ListNode evenHead = even;

        while (even != null && even.next != null) {
            odd.next = even.next;
            odd = odd.next;
            even.next = odd.next;
            even = even.next;
        }

        odd.next = evenHead;
        return head;
    }
}
```

## Line-by-line

- `odd = head` — odd-indexed nodes (0, 2, 4, ...).
- `even = head.next` — even-indexed nodes (1, 3, 5, ...).
- `evenHead = even` — save the start of the even list for reconnection.
- Loop: `odd.next = even.next` (skip the even node), advance odd. Then `even.next = odd.next` (skip the next odd), advance even.
- `odd.next = evenHead` — connect the two lists.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — only pointers.

## Common Mistakes

- **Not saving `evenHead`.** You need it to reconnect the lists at the end.
- **Wrong loop condition.** `even != null && even.next != null` — stop when even runs out. Using `odd != null` can cause NPE.
- **Modifying head.** The head stays the same (odd list starts at head). Return `head`.
- **Not handling empty/single node.** `head == null` → null. Single node → returns head (loop doesn't execute).

## How to Explain (interview)

**Opening:** Odd Even Linked List groups odd-indexed and even-indexed nodes. Two pointers (odd and even) split the list into two chains, then reconnect. O(n) time, O(1) space.

**The basic flow:**
```java
ListNode odd = head, even = head.next, evenHead = even;
while (even != null && even.next != null) {
    odd.next = even.next; odd = odd.next;
    even.next = odd.next; even = even.next;
}
odd.next = evenHead;
return head;
```

**The part that trips everyone up:** save `evenHead` before modifying. The loop condition is `even != null && even.next != null` (not `odd`). Reconnect with `odd.next = evenHead`.

**The mistakes to remember:**
- Not saving evenHead (can't reconnect)
- Wrong loop condition (NPE)
- Returning wrong node (return head, which is odd's start)
- Not handling empty/single node
