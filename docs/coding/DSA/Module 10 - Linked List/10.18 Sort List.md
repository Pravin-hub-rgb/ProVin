# 10.18 Sort List

**Tier 2 problem.** (LeetCode #148)

**Problem:** Sort a linked list in O(n log n) time and O(1) space (or O(log n) stack space). (LeetCode #148)

**Link:** https://leetcode.com/problems/sort-list/

---

## Which Technique, and Why?

"Sort a linked list in O(n log n)" → **Merge Sort** (bottom-up or top-down). Arrays use quicksort, but linked lists are better suited for merge sort (no random access needed for merging). O(n log n) time, O(log n) space (recursion stack) for top-down, O(1) for bottom-up.

**Signal in the problem:** "sort linked list" + "O(n log n)" → merge sort (top-down recursive or bottom-up iterative).

## Approach (Top-down merge sort)

Find middle (slow/fast), split, recursively sort both halves, merge.

## Pseudocode

```
sortList(head):
    if head == null or head.next == null: return head
    mid = findMiddle(head)
    left = sortList(head)
    right = sortList(mid)
    return merge(left, right)

findMiddle(head):
    slow = head, fast = head.next
    while fast != null and fast.next != null:
        slow = slow.next
        fast = fast.next.next
    mid = slow.next
    slow.next = null  // split
    return mid

merge(l1, l2):
    dummy = new ListNode(0)
    cur = dummy
    while l1 != null and l2 != null:
        if l1.val <= l2.val: cur.next = l1; l1 = l1.next
        else: cur.next = l2; l2 = l2.next
        cur = cur.next
    cur.next = (l1 != null) ? l1 : l2
    return dummy.next
```

## Java Code

```java
class Solution {
    public ListNode sortList(ListNode head) {
        if (head == null || head.next == null) return head;

        // Find middle
        ListNode slow = head, fast = head.next;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        ListNode mid = slow.next;
        slow.next = null;  // split

        ListNode left = sortList(head);
        ListNode right = sortList(mid);
        return merge(left, right);
    }

    private ListNode merge(ListNode l1, ListNode l2) {
        ListNode dummy = new ListNode(0);
        ListNode cur = dummy;
        while (l1 != null && l2 != null) {
            if (l1.val <= l2.val) {
                cur.next = l1;
                l1 = l1.next;
            } else {
                cur.next = l2;
                l2 = l2.next;
            }
            cur = cur.next;
        }
        cur.next = (l1 != null) ? l1 : l2;
        return dummy.next;
    }
}
```

## Line-by-line

- Base case: `head == null || head.next == null` → already sorted.
- Find middle: slow/fast with `fast = head.next` (so slow ends at the node before mid). Split with `slow.next = null`.
- Recursively sort both halves.
- Merge: standard two-pointer merge with dummy node.

## Complexity

- Time: O(n log n) — log n levels, each level O(n) merge.
- Space: O(log n) — recursion stack. (Bottom-up merge sort achieves O(1).)

## Common Mistakes

- **Using quicksort.** Quick sort on linked lists is O(n²) worst case and requires random access (which linked lists don't have efficiently). Use merge sort.
- **Wrong middle finding.** `fast = head.next` (not `head`) so slow ends at the node before mid. Then `mid = slow.next; slow.next = null` splits cleanly.
- **Not splitting.** If you don't set `slow.next = null`, the two halves are still connected → infinite recursion.
- **Modifying the list.** Merge sort modifies pointers but reuses nodes (O(1) extra space besides recursion stack).

## How to Explain (interview)

**Opening:** Sort List sorts a linked list in O(n log n). Merge sort: find middle, split, recursively sort both halves, merge. Linked lists are ideal for merge sort (no random access needed). O(n log n) time, O(log n) space (recursion stack).

**The basic flow:**
```java
if (head == null || head.next == null) return head;
ListNode slow = head, fast = head.next;
while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; }
ListNode mid = slow.next; slow.next = null;
return merge(sortList(head), sortList(mid));
```

**The part that trips everyone up:** find middle with `fast = head.next` (not `head`), so slow ends at the node before mid. Then split with `slow.next = null`. Without the split, infinite recursion.

**The mistakes to remember:**
- Using quicksort (O(n²) worst case, needs random access)
- Wrong middle (fast = head instead of head.next)
- Not splitting (infinite recursion)
- Not using a dummy node in merge (messy edge cases)
