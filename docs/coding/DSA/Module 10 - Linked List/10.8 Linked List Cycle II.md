# 10.8 Linked List Cycle II

**Problem:** Given a linked list, return the node where the cycle begins. If no cycle, return null. (LeetCode #142)

**Link:** https://leetcode.com/problems/linked-list-cycle-ii/

---

## Which Technique, and Why?

Find the cycle's entry node → **Floyd's Cycle Detection (two phases)**. Phase 1: detect the cycle (slow & fast meet). Phase 2: find the entry — reset one pointer to head, move both one step at a time; they meet at the entry. O(n) time, O(1) space.

**Signal in the problem:** "return the node where the cycle begins" → Floyd's two-phase algorithm.

## Approach

Phase 1: slow & fast meet inside the cycle. Phase 2: reset slow (or fast) to head; advance both by 1; they meet at the cycle entry.

**Why this works:** Let the distance from head to cycle entry be `a`, and the cycle length be `c`. When slow and fast meet, slow has traveled `a + b` (b = distance into the cycle), fast has traveled `a + b + k*c`. Since fast = 2×slow: `a + b + k*c = 2(a + b)` → `k*c = a + b`. So `a = k*c - b`. If you reset one pointer to head and advance both by 1, after `a` steps, the head-pointer reaches the entry, and the cycle-pointer (which was `b` into the cycle) advances `a = k*c - b` steps → lands at `b + (k*c - b) = k*c` → the entry. They meet at the entry.

## Pseudocode

```
// Phase 1: detect cycle
slow = head, fast = head
while fast != null and fast.next != null:
    slow = slow.next
    fast = fast.next.next
    if slow == fast: break
if fast == null or fast.next == null: return null  // no cycle

// Phase 2: find entry
slow = head
while slow != fast:
    slow = slow.next
    fast = fast.next
return slow  // or fast — they're equal
```

## Java Code

```java
class Solution {
    public ListNode detectCycle(ListNode head) {
        if (head == null || head.next == null) return null;

        ListNode slow = head;
        ListNode fast = head;

        // Phase 1: detect cycle
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) break;
        }
        if (fast == null || fast.next == null) return null;  // no cycle

        // Phase 2: find entry
        slow = head;
        while (slow != fast) {
            slow = slow.next;
            fast = fast.next;
        }
        return slow;
    }
}
```

## Line-by-line

- Phase 1: same as cycle detection. If no cycle, return null.
- Phase 2: reset `slow` to head. Advance both `slow` and `fast` by 1. They meet at the cycle entry.
- Return `slow` (== `fast` at the entry).

## Complexity

- Time: O(n) — both phases are O(n).
- Space: O(1) — two pointers.

## Common Mistakes

- **Skipping Phase 2.** Phase 1 only detects the cycle; Phase 2 finds the entry. You need both.
- **Not checking for no-cycle.** If Phase 1 exits because `fast` reached null, there's no cycle → return null.
- **Resetting the wrong pointer.** Reset `slow` to head (or fast — either works). Advance both by 1 (not 2).
- **Off-by-one in Phase 2.** The meeting point is the entry, not one before or after. The math guarantees this.

## How to Explain (interview)

**Opening:** Linked List Cycle II finds the cycle's entry node. Phase 1: Floyd's slow & fast meet inside the cycle. Phase 2: reset one pointer to head, advance both by 1 — they meet at the entry. The math: when they meet, slow has traveled a+b, fast a+b+k*c; since fast=2×slow, a = k*c - b, so advancing both by 1 from head and meeting point lands them at the entry. O(n) time, O(1) space.

**The basic flow:**
```java
// Phase 1: detect
while (fast != null && fast.next != null) {
    slow = slow.next; fast = fast.next.next;
    if (slow == fast) break;
}
if (fast == null || fast.next == null) return null;
// Phase 2: find entry
slow = head;
while (slow != fast) { slow = slow.next; fast = fast.next; }
return slow;
```

**The part that trips everyone up:** Phase 2 advances **both** pointers by **1** (not 2). And you must check for no-cycle after Phase 1.

**The mistakes to remember:**
- Skipping Phase 2 (only detects, doesn't find entry)
- Not checking for no-cycle (NPE or wrong answer)
- Resetting both pointers or advancing by 2 in Phase 2 (wrong meeting point)
- Confusing with cycle detection (#141) — this one returns the node
