## Mini Quiz

1. Why must you save `next` before overwriting `curr.next` when reversing a linked list?
2. In Floyd's cycle detection, why do slow and fast meet if there's a cycle?
3. How does Phase 2 of Floyd's algorithm find the cycle entry?
4. Why use a dummy node in "Remove Nth From End"?
5. How do you delete a node in O(1) without access to the head?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. Because `curr.next = prev` overwrites the forward link. If you don't save `next = curr.next` first, you lose the reference to the rest of the list — you can't continue traversing. Save first, then overwrite.
2. In a cycle, fast (2 steps) is faster than slow (1 step). Each step, fast gains 1 on slow. Since the cycle is finite, fast will eventually catch up to slow. If no cycle, fast reaches null.
3. When slow and fast meet, slow has traveled a+b, fast a+b+k*c. Since fast=2×slow, a = k*c - b. Reset slow to head; advance both by 1. After a steps, slow reaches the entry, and fast (at b + a = k*c) also reaches the entry. They meet at the entry.
4. The dummy node is a sentinel before the head. It handles the edge case of removing the head (when n = length) without special-casing. It also ensures `slow` always has a predecessor. Return `dummy.next` (the new head).
5. Copy the next node's value into the current node, then skip the next node (`node.next = node.next.next`). This removes the current node's value in O(1) without needing the predecessor. Only works if the node is not the tail.

</details>

## One-Page Cheat Sheet

**Reverse (iterative):**
```java
ListNode prev = null, curr = head;
while (curr != null) {
    ListNode next = curr.next;
    curr.next = prev;
    prev = curr;
    curr = next;
}
return prev;
```

**Middle (slow & fast):**
```java
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}
return slow;
```

**Merge two sorted lists (dummy):**
```java
ListNode dummy = new ListNode(0), cur = dummy;
while (l1 != null && l2 != null) {
    if (l1.val <= l2.val) { cur.next = l1; l1 = l1.next; }
    else { cur.next = l2; l2 = l2.next; }
    cur = cur.next;
}
cur.next = (l1 != null) ? l1 : l2;
return dummy.next;
```

**Cycle detection (Floyd's):**
```java
// Phase 1: detect
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next; fast = fast.next.next;
    if (slow == fast) break;
}
if (fast == null || fast.next == null) return null; // no cycle
// Phase 2: find entry
slow = head;
while (slow != fast) { slow = slow.next; fast = fast.next; }
return slow;
```

**Remove nth from end (dummy + gap n+1):**
```java
ListNode dummy = new ListNode(0); dummy.next = head;
ListNode fast = dummy, slow = dummy;
for (int i = 0; i <= n; i++) fast = fast.next;
while (fast != null) { fast = fast.next; slow = slow.next; }
slow.next = slow.next.next;
return dummy.next;
```

**Delete node in O(1) (no head):**
```java
node.val = node.next.val;
node.next = node.next.next;
```

## In Your Own Words

1. Why is the dummy node technique useful in linked list problems?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A dummy (sentinel) node is a placeholder placed before the head. It eliminates special-casing: the head is always `dummy.next`, so insertions/deletions at the head use the same code as middle operations. After building, return `dummy.next`. This is especially useful for "remove nth from end" (removing head when n = length) and "merge two lists" (handling empty lists).

</details>

2. How does Floyd's cycle detection find the cycle entry (Phase 2)?

<details>
<summary>Show Answer</summary>

**Sample Answer:** In Phase 1, slow and fast meet inside the cycle. Let head-to-entry = a, entry-to-meeting = b, cycle length = c. Slow traveled a+b, fast a+b+k*c. Since fast = 2×slow: a = k*c - b. Phase 2: reset slow to head, advance both by 1. After a steps, slow reaches entry, fast (at b + a = k*c) also reaches entry. They meet at the entry.

</details>

3. Why does Add Two Numbers not need to reverse the lists?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The digits are stored in reverse order (least significant digit first). When you add two numbers, you start from the least significant digit — which is the head of the list. So you can add digit by digit from head to tail, tracking carry, without reversing. The result is also in reverse order (least significant first), which matches the expected output format.

</details>
