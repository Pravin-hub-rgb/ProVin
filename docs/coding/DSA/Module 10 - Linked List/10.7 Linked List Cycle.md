# 10.7 Linked List Cycle

**Problem:** Given a linked list, determine if it has a cycle. (LeetCode #141)

**Link:** https://leetcode.com/problems/linked-list-cycle/

---

## Which Technique, and Why?

Detect a cycle in a linked list → **Floyd's Cycle Detection (slow & fast pointers)**. Slow moves 1 step, fast moves 2. If there's a cycle, fast will eventually catch up to slow. If fast reaches null, no cycle. O(n) time, O(1) space.

Why not a visited set? A set works (O(n) time, O(n) space) but uses extra memory. Floyd's is O(1) space.

**Signal in the problem:** "linked list cycle" / "detect cycle" → Floyd's slow & fast pointers.

## Approach

`slow = head`, `fast = head`. While `fast != null && fast.next != null`: advance slow by 1, fast by 2. If `slow == fast`, cycle exists. If fast reaches null, no cycle.

## Pseudocode

```
slow = head, fast = head
while fast != null and fast.next != null:
    slow = slow.next
    fast = fast.next.next
    if slow == fast: return true
return false
```

## Java Code

```java
class Solution {
    public boolean hasCycle(ListNode head) {
        if (head == null || head.next == null) return false;

        ListNode slow = head;
        ListNode fast = head;

        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) return true;
        }
        return false;
    }
}
```

## Line-by-line

- `slow` moves 1 step, `fast` moves 2.
- If there's a cycle, fast will eventually catch up to slow (they'll be at the same node).
- If there's no cycle, fast reaches null → return false.
- The `slow == fast` check happens after advancing (not before) to avoid false positive at the start (both start at head).

## Complexity

- Time: O(n) — if cycle exists, fast catches slow within n steps. If no cycle, fast reaches null in n/2 steps.
- Space: O(1) — two pointers.

## Common Mistakes

- **Checking `slow == fast` before advancing.** Both start at head, so they'd be "equal" immediately. Check after advancing.
- **Not handling null/empty.** `head == null` or `head.next == null` → no cycle. Check early.
- **Using a visited set.** Works (O(n) space) but wastes memory. Floyd's is O(1) space.
- **Infinite loop.** If you don't advance fast by 2 (or advance slow), the loop never terminates on a cyclic list.
