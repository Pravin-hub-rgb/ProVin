## Mini Quiz

1. What is the time and space complexity of the hashmap approach to Two Sum?
2. Why is `getOrDefault(key, 0)` safer than `get(key)` when counting frequencies?
3. How do you check if two strings are anagrams using a hash map?
4. What is Kadane's algorithm, and what problem does it solve?
5. How do you compute the product of all elements except the current one in O(n) time and O(1) extra space?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. O(n) time (single pass), O(n) space (hash map storing up to n entries).
2. `get(key)` returns null for missing keys; calling `.intValue()` on null throws NPE. `getOrDefault(key, 0)` returns 0 instead, avoiding the null check.
3. Count character frequencies in both strings using two HashMaps (or one with +1 for first string and -1 for second). If all counts are zero, they're anagrams. Alternatively, sort both strings and compare.
4. Kadane's algorithm finds the maximum subarray sum. Track a running sum; if it goes negative, reset to 0 (start fresh). Track the maximum running sum seen. O(n) time, O(1) space.
5. Compute prefix products (left to right) and suffix products (right to left). The product except self at index i is `prefix[i-1] * suffix[i+1]`. To do it in O(1) extra space, reuse the output array: first pass stores prefix products in it, second pass multiplies by suffix products running from the right.

</details>

## One-Page Cheat Sheet

**Core pattern:** walk the array once, maintain a "memory" (HashMap/HashSet). For each element, check if memory has what you need; if yes, answer found; if no, record and continue.

**Key operations:**
- Frequency count: `map.put(x, map.getOrDefault(x, 0) + 1)`
- Membership: `set.contains(x)`, `map.containsKey(x)`
- Group by key: `map.computeIfAbsent(key, k -> new ArrayList<>()).add(item)`
- Two Sum: store `value → index`; check complement.

**Complexities:** single pass with hash map = O(n) time, O(n) space.

**When to use Arrays & Hashing:** counting, grouping, "have I seen this?", pairs that sum to target, anagrams, frequency-based problems.

## In Your Own Words

1. Why does a hash map turn an O(n²) two-sum into O(n)?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Brute force checks every pair (i, j) — O(n²). With a hash map, as you walk the array you store each value → index. For element i, instead of scanning forward for its complement (O(n)), you check the map in O(1). One pass, O(n) total. The cost is O(n) extra space for the map. This "lookup table" pattern applies to many problems: replace a nested search with a constant-time map lookup.

</details>

2. What is the difference between HashMap and HashSet, and when do you use each?

<details>
<summary>Show Answer</summary>

**Sample Answer:** HashMap stores key → value pairs; HashSet stores only unique keys (no values). Use HashMap when you need to associate data with each key (frequency counts, value → index). Use HashSet for pure membership testing ("have I seen this?") and deduplication. HashSet is essentially a HashMap with dummy values.

</details>

3. How does Kadane's algorithm find the maximum subarray sum?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Maintain a running sum. For each element, either extend the current subarray (add the element) or start fresh (if the running sum is negative, reset to 0 then add). Track the maximum running sum seen. The reset works because a negative running sum can only reduce any future subarray — better to start over. O(n) time, O(1) space.

</details>

4. How do you compute "product of all elements except self" in O(n) time?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use prefix and suffix products. First pass (left to right): output[i] = product of all elements before i. Second pass (right to left): multiply output[i] by the running product of elements after i. O(n) time. For O(1) extra space, reuse the output array: store prefix products in it during pass 1, then multiply by suffix products in pass 2 without allocating another array.

</details>
