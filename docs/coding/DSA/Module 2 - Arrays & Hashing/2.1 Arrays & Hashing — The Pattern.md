## The Core Idea

This module's pattern: **use a hash map or set as "memory" while walking the array once.**

Many array problems ask you to find, count, or group elements. A naive approach checks every pair → O(n²). A hash map lets you look up "have I seen X before?" in O(1), turning the problem into a single pass → O(n).

**The mental model:** as you walk through the array, maintain a "memory" (hash map/set) of what you've seen. For each element, ask: "does my memory already contain what I need?" If yes, you have an answer. If no, record this element and move on.

## The Pattern Explained

**Step 1 — Identify the lookup.** What value would make the current element a valid answer? (e.g., in Two Sum, the complement `target - nums[i]`.)

**Step 2 — Check memory.** Is that value already in your hash map/set? If yes, you're done.

**Step 3 — Record.** Store the current element (and its index/value) in memory for future elements.

**Step 4 — Move on.** Advance to the next element.

This is the "remember what you've seen" pattern. It appears in dozens of problems.

## How to Recognize It

Think "Arrays & Hashing" when:
- The problem asks whether two elements sum to a target → store seen values in a set/map. (Two Sum)
- The problem asks if all elements are distinct → set size vs array length. (Contains Duplicate)
- The problem asks if two strings are anagrams → compare character frequency maps. (Valid Anagram)
- The problem asks to group items by a property → map from "key" to list of items. (Group Anagrams)
- The problem asks for the k most/least frequent elements → frequency map + heap or bucket sort. (Top K Frequent)
- The problem asks for a product/sum excluding the current element → prefix and suffix products. (Product Except Self)
- The problem asks for the majority element → frequency map or Boyer-Moore. (Majority Element)
- The problem asks for max profit from one buy-sell → track min so far. (Best Time to Buy/Sell Stock)
- The problem asks for the maximum subarray sum → Kadane's: track running sum, reset when negative. (Maximum Subarray)
- The problem asks to sort 0s, 1s, 2s in place → counting sort or Dutch National Flag. (Sort Colors)

## Worked Example: Two Sum

**Problem:** Given an array of integers and a target, return indices of two numbers that add up to target. (Assume exactly one solution exists.)

### Step 1: Brute force (O(n²) time, O(1) space)

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        for (int i = 0; i < nums.length; i++) {
            for (int j = i + 1; j < nums.length; j++) {
                if (nums[i] + nums[j] == target) {
                    return new int[]{i, j};
                }
            }
        }
        return new int[]{};
    }
}
```

Check every pair. Correct but slow: n² pairs.

### Step 2: Optimized with HashMap (O(n) time, O(n) space)

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();  // value → index

        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];
            if (seen.containsKey(complement)) {
                return new int[]{seen.get(complement), i};
            }
            seen.put(nums[i], i);
        }
        return new int[]{};
    }
}
```

**Line-by-line:**
- `seen` maps a value to the index where it appeared.
- For each element, compute `complement = target - nums[i]` — the value we need to find.
- If complement is already in `seen`, we found the pair: return its index and current index.
- Otherwise, record current value → index and move on.
- One pass, O(n) time. O(n) space for the map.

**Key insight:** instead of searching forward for the complement (O(n) per element), we check our memory (O(1)). The trade-off: we spend O(n) memory to save O(n) time per element.

## Common Mistakes

- **Returning values instead of indices.** Two Sum asks for indices. Read the problem statement carefully.
- **Assuming the array is sorted.** Two Sum's array is *not* sorted. (Two Sum II is the sorted variant.)
- **Using `==` for String comparison** in anagram problems. Use `.equals()` or compare char arrays.
- **Forgetting that HashMap allows null keys/values** — `get` returns null for missing keys; calling `.intValue()` on null throws NPE. Use `getOrDefault` or `containsKey`.
- **Modifying the input when not allowed.** Some problems say "do not modify the input array." Product Except Self can be done in O(1) extra space by reusing the output array, but not by mutating input.
- **Counting sort assumption:** Sort Colors can be solved with counting, but if the range is large, counting sort is O(range) space — check constraints.

## How to Explain (interview)

**Opening:** Arrays & Hashing is a pattern where you walk through an array once and use a hash map or set as "memory" of what you've seen. For each element you ask: does my memory already contain the value I need to complete the answer? If yes, you're done; if no, record the current element and move on. It turns O(n²) "check every pair" into O(n) "check memory."

**The basic flow:**
```java
Map<Integer, Integer> seen = new HashMap<>();
for (int i = 0; i < nums.length; i++) {
    int complement = target - nums[i];
    if (seen.containsKey(complement)) return new int[]{seen.get(complement), i};
    seen.put(nums[i], i);
}
```
One pass. For each element, compute what you need, check memory in O(1), record if not found.

**The part that trips everyone up:**
- Two Sum asks for **indices**, not values — read the problem statement.
- The array is **not** sorted (that's Two Sum II). Don't assume sorting.
- `get` returns null for missing keys — use `containsKey` or `getOrDefault` to avoid NPE.

**The mistakes to remember:**
- Returning values instead of indices
- Assuming the array is sorted
- Using `==` for String comparison in anagram problems
- Modifying the input when the problem forbids it
