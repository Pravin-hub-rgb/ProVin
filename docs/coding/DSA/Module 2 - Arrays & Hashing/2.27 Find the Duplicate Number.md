# 2.27 Find the Duplicate Number

**Tier 2 problem.** (LeetCode #287)

**Problem:** Given an array of n+1 integers where each is in [1, n], find the duplicate number. Must not modify the array, use O(1) space. (LeetCode #287)

**Link:** https://leetcode.com/problems/find-the-duplicate-number/

---

## Which Technique, and Why?

"Find duplicate in array with constraints (no modify, O(1) space)" → **Floyd's Cycle Detection** (treat the array as a linked list). Or binary search on the answer (count numbers ≤ mid). The Floyd's approach is the most elegant: `nums[i]` points to index `nums[i]`, forming a linked list. A duplicate means a cycle. Find the cycle entry.

**Signal in the problem:** "find duplicate" + "no modify" + "O(1) space" → Floyd's cycle detection or binary search on answer.

## Approach (Floyd's — O(n) time, O(1) space)

Treat the array as a linked list: node i points to node nums[i]. A duplicate value means two nodes point to the same node → cycle. Find the cycle entry using Floyd's two-phase algorithm (same as Linked List Cycle II).

## Pseudocode

```
// Phase 1: find meeting point
slow = nums[0], fast = nums[0]
do:
    slow = nums[slow]
    fast = nums[nums[fast]]
while slow != fast

// Phase 2: find entry
slow = nums[0]
while slow != fast:
    slow = nums[slow]
    fast = nums[fast]
return slow
```

## Java Code

```java
class Solution {
    public int findDuplicate(int[] nums) {
        // Phase 1: find meeting point
        int slow = nums[0];
        int fast = nums[0];
        do {
            slow = nums[slow];
            fast = nums[nums[fast]];
        } while (slow != fast);

        // Phase 2: find entry
        slow = nums[0];
        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }
        return slow;
    }
}
```

## Line-by-line

- `slow = nums[0]`, `fast = nums[0]` — start at index 0 (value nums[0]).
- Phase 1: `slow = nums[slow]` (one step), `fast = nums[nums[fast]]` (two steps). They meet inside the cycle.
- Phase 2: reset `slow = nums[0]`. Advance both by 1 (`nums[slow]`, `nums[fast]`). They meet at the duplicate (cycle entry).
- Return `slow`.

## Complexity

- Time: O(n) — both phases are O(n).
- Space: O(1) — two pointers.

## Common Mistakes

- **Not handling the case where nums[0] is part of the cycle.** The algorithm handles this correctly because we start both at `nums[0]` and use a `do-while` (at least one iteration).
- **Using a HashSet.** Works (O(n) space) but violates the O(1) space constraint.
- **Modifying the array.** Sorting or negating values works but violates the "don't modify" constraint.
- **Confusing with "Find All Duplicates" (#442).** That problem allows O(n) space and modifying. This one doesn't.

## How to Explain (interview)

**Opening:** Find the Duplicate Number finds a duplicate in an array of n+1 integers in [1,n] with O(1) space and no modification. Treat the array as a linked list: index i → index nums[i]. A duplicate means a cycle. Floyd's cycle detection: Phase 1 finds the meeting point, Phase 2 finds the entry (the duplicate). O(n) time, O(1) space.

**The basic flow:**
```java
int slow = nums[0], fast = nums[0];
do { slow = nums[slow]; fast = nums[nums[fast]]; } while (slow != fast);
slow = nums[0];
while (slow != fast) { slow = nums[slow]; fast = nums[fast]; }
return slow;
```

**The part that trips everyone up:** the array is treated as a **linked list** (index → value → index). The duplicate creates a cycle. Phase 2 finds the cycle entry = the duplicate. Also, use `do-while` (not `while`) for Phase 1 because slow and fast start at the same point.

**The mistakes to remember:**
- Using HashSet (violates O(1) space)
- Modifying the array (violates constraint)
- Using `while` instead of `do-while` (infinite loop when they start equal)
- Confusing with "Find All Duplicates" (#442) (different constraints)
