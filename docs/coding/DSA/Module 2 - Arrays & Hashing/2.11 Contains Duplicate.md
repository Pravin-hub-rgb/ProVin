# 2.11 Contains Duplicate

**Problem:** Given an integer array, return `true` if any value appears at least twice, `false` if all elements are distinct. (LeetCode #217)

**Link:** https://leetcode.com/problems/contains-duplicate/

---

## Which Data Structure, and Why?

You need to check, for each element, whether you've seen it before. That's membership testing: "have I seen value X?" → O(1) lookup → **HashSet**.

Why not HashMap? You only need membership (seen/not seen), no associated value. A set is the minimal tool. (A HashMap with dummy values would also work but is overkill.)

**Signal in the problem:** "any value appears at least twice" / "all distinct" → membership test → HashSet. Also: "return true if duplicate exists" → you can short-circuit on first duplicate.

## Approach

**Brute force (O(n²)):** check every pair for equality.

**Optimized (O(n)):** one pass. For each element, if it's already in the set, return true. Otherwise add it. If loop finishes, return false.

Alternative: sort the array (O(n log n)) and check adjacent elements. Slower than the hash set but O(1) extra space.

## Pseudocode

```
seen = empty set
for each x in nums:
    if x in seen: return true
    seen.add(x)
return false
```

## Java Code

```java
class Solution {
    public boolean containsDuplicate(int[] nums) {
        Set<Integer> seen = new HashSet<>();
        for (int x : nums) {
            if (!seen.add(x)) {   // add returns false if already present
                return true;
            }
        }
        return false;
    }
}
```

**Note:** `seen.add(x)` returns `true` if x was new, `false` if it was already there. So `!seen.add(x)` is true exactly when x is a duplicate — detection in one line, no separate `contains` call.

## Complexity

- Time: O(n) — single pass, O(1) set ops.
- Space: O(n) — set stores up to n elements (worst case, all distinct).

## Common Mistakes

- **Using a nested loop** (O(n²)) when a set gives O(n). Always reach for a set for "have I seen this?"
- **Forgetting to short-circuit.** Return `true` on the first duplicate found; don't keep scanning.
- **Sorting approach trap:** sorting is O(n log n) and mutates the input. Use only if O(1) extra space is required.

## How to Explain (interview)

**Opening:** Contains Duplicate asks if any value appears more than once. The brute force compares every pair — O(n²). The optimized version walks the array once with a HashSet: for each element, try to add it; if `add` returns false, it was already there, so return true. If the loop finishes, all elements are distinct. O(n) time, O(n) space.

**The basic flow:**
```java
Set<Integer> seen = new HashSet<>();
for (int x : nums) {
    if (!seen.add(x)) return true;
}
return false;
```

**The part that trips everyone up:** `add` returns a boolean — `true` if new, `false` if duplicate. Use that return value instead of a separate `contains` check.

**The mistakes to remember:**
- Using nested loops (O(n²)) instead of a set (O(n))
- Not short-circuiting on the first duplicate
- Sorting when you don't need to (slower, mutates input)
