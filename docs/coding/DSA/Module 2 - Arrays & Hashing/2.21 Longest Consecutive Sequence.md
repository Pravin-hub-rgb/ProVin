**Tier 2 problem.** (LeetCode #128)

**Problem:** Given an unsorted array of integers, find the length of the longest consecutive elements sequence. Must run in O(n) time. (LeetCode #128)

**Link:** https://leetcode.com/problems/longest-consecutive-sequence/

---

## Which Technique, and Why?

"Longest consecutive sequence" in O(n) → **HashSet**. Put all elements in a set. For each element, if it's the start of a sequence (i.e., `x - 1` is NOT in the set), count consecutive elements (`x, x+1, x+2, ...`) by checking the set. Each element is visited at most twice → O(n) total.

**Signal in the problem:** "consecutive sequence" / "longest consecutive" + "O(n) time" → HashSet + "start of sequence" check.

## Approach

1. Put all elements in a HashSet.
2. For each element x: if `x - 1` is NOT in the set, x is a sequence start. Count consecutive elements (x+1, x+2, ...) by checking the set. Track max.
3. Only start counting from sequence starts → each element visited O(1) times → O(n) total.

## Pseudocode

```
set = set of all nums
maxLen = 0
for each x in nums:
    if (x - 1) not in set:  // x is a sequence start
        len = 1
        while (x + len) in set: len++
        maxLen = max(maxLen, len)
return maxLen
```

## Java Code

```java
class Solution {
    public int longestConsecutive(int[] nums) {
        Set<Integer> set = new HashSet<>();
        for (int x : nums) set.add(x);

        int maxLen = 0;
        for (int x : nums) {
            if (!set.contains(x - 1)) {  // x is a sequence start
                int len = 1;
                while (set.contains(x + len)) len++;
                maxLen = Math.max(maxLen, len);
            }
        }
        return maxLen;
    }
}
```

## Line-by-line

- `set` holds all elements for O(1) lookup.
- `if (!set.contains(x - 1))` — x is a sequence start (nothing before it). This is the key optimization: only count from starts, so each element is counted at most once.
- `while (set.contains(x + len)) len++` — count consecutive elements.
- `maxLen` tracks the best.

## Complexity

- Time: O(n) — each element is visited at most twice (once in the outer loop, once in the inner while, but only for sequence starts).
- Space: O(n) — the set.

## Common Mistakes

- **Sorting.** O(n log n) — works but doesn't meet the O(n) requirement. The HashSet approach is O(n).
- **Counting from every element.** Without the `x - 1` check, you'd count from every element → O(n²). The start check ensures O(n).
- **Not handling duplicates.** HashSet handles duplicates automatically (size doesn't change).
- **Empty array.** Returns 0 (maxLen stays 0). Correct.

## How to Explain (interview)

**Opening:** Longest Consecutive Sequence finds the longest run of consecutive integers in O(n). Put all elements in a HashSet. For each element, if it's a sequence start (x-1 not in set), count consecutive elements (x+1, x+2, ...) by checking the set. Only count from starts → O(n) total (each element visited at most twice).

**The basic flow:**
```java
Set<Integer> set = new HashSet<>(Arrays.asList(nums));
int maxLen = 0;
for (int x : nums) {
    if (!set.contains(x - 1)) {
        int len = 1;
        while (set.contains(x + len)) len++;
        maxLen = Math.max(maxLen, len);
    }
}
```

**The part that trips everyone up:** the `x - 1` check. Without it, you count from every element → O(n²). With it, you only count from sequence starts → O(n). Also, the inner while loop's total work is O(n) across all starts (each element counted once).

**The mistakes to remember:**
- Sorting (O(n log n) — works but not O(n))
- Counting from every element (O(n²))
- Not handling empty array
- Using a list instead of a set (O(n) lookup)
