A StringBuilder is a mutable sequence of characters. Unlike String (immutable), you can append, insert, delete, and reverse in place without creating new objects. Use it whenever you build a string in a loop or with many appends.

---

## Declaration and Creation

```java
StringBuilder sb = new StringBuilder();          // empty, default capacity 16
StringBuilder sb2 = new StringBuilder("Hello"); // starts with "Hello"
StringBuilder sb3 = new StringBuilder(100);     // empty, capacity 100 (pre-allocate)
```

**Capacity vs length:** capacity is the internal buffer size; length is the actual string length. When length exceeds capacity, the buffer doubles. Pre-allocating capacity (third form) avoids resizing in tight loops.

## Common Operations

```java
StringBuilder sb = new StringBuilder("Hello");

sb.append(" World");          // "Hello World"
sb.append(42);                // appends "42" → "Hello World42"
sb.append('!');               // appends char → "Hello World42!"

sb.insert(5, ",");            // "Hello, World42!"  (insert at index 5)
sb.delete(5, 6);              // "Hello World42!"    (delete index 5)
sb.deleteCharAt(10);          // delete one char
sb.replace(6, 11, "Java");     // "Hello Java42!"

sb.reverse();                 // reverses in place
sb.setCharAt(0, 'h');         // "hello Java42!" (set char at index)

String result = sb.toString(); // convert to String
System.out.println(sb.length()); // current length
System.out.println(sb.charAt(0)); // 'h'
```

## Why StringBuilder Instead of String

```java
// BAD: O(n²) — each += creates a new String
String s = "";
for (int i = 0; i < n; i++) {
    s += "a";   // copies entire string each time
}

// GOOD: O(n) — appends in place
StringBuilder sb = new StringBuilder();
for (int i = 0; i < n; i++) {
    sb.append("a");
}
String s = sb.toString();
```

**Rule:** if you're building a string in a loop or with more than ~3 concatenations, use StringBuilder. Single concatenation (`"a" + "b"`) is fine with String — the compiler optimizes it.

## StringBuilder vs StringBuffer

- `StringBuilder` — not thread-safe, faster. Use in single-threaded code (99% of DSA).
- `StringBuffer` — thread-safe (synchronized), slower. Use only when multiple threads modify the same buffer.

In DSA, always use `StringBuilder`.

## Cost (Big-O)

| Operation | Time |
|---|---|
| `append`, `insert` (amortized) | O(1) |
| `delete`, `replace` | O(n) (shifts chars) |
| `reverse` | O(n) |
| `toString` | O(n) |
| `charAt`, `setCharAt` | O(1) |

## Common Pitfalls

- **Using `+` in a loop instead of StringBuilder** — O(n²). The most common performance mistake.
- **Forgetting `toString()`** — StringBuilder is not a String. Pass `sb.toString()` where a String is expected. (Some APIs accept CharSequence, which StringBuilder implements.)
- **Capacity surprises:** if you append beyond capacity, the buffer doubles. Pre-allocate with `new StringBuilder(expectedSize)` to avoid.
- **`insert`/`delete` in the middle** — O(n) due to shifting. Avoid in hot loops.

## A Small Program: Build a Reversed String

```java
public class BuildReversed {
    static String buildReversed(String s) {
        StringBuilder sb = new StringBuilder();
        for (int i = s.length() - 1; i >= 0; i--) {
            sb.append(s.charAt(i));
        }
        return sb.toString();
    }

    public static void main(String[] args) {
        System.out.println(buildReversed("hello"));  // "olleh"
    }
}
```

## In Your Own Words

1. Why is StringBuilder faster than String concatenation in a loop?

<details>
<summary>Show Answer</summary>

**Sample Answer:** String is immutable, so `s += "a"` creates a new String and copies all previous characters each iteration — O(n) per append, O(n²) total. StringBuilder is mutable with an internal buffer that grows amortized O(1) per append — O(n) total. The cost difference is dramatic for large n.

</details>

2. When should you use StringBuilder vs StringBuffer?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use StringBuilder in single-threaded code (almost all DSA). It's faster because it's not synchronized. Use StringBuffer only when multiple threads modify the same buffer concurrently — its methods are synchronized (thread-safe) but slower. In DSA, always StringBuilder.

</details>

3. What is the difference between capacity and length in StringBuilder?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Length is the number of characters currently in the buffer. Capacity is the size of the internal buffer (how many chars it can hold before resizing). When length exceeds capacity, the buffer doubles. You can pre-allocate with `new StringBuilder(expectedSize)` to avoid resizing in tight loops.

</details>
