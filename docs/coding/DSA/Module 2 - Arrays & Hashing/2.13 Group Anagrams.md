**Problem:** Given an array of strings `strs`, group the anagrams together. You can return the answer in **any order**.

An **Anagram** is a word or phrase formed by rearranging the letters of a different word or phrase, typically using all the original letters exactly once.

**Link:** https://leetcode.com/problems/group-anagrams/

---

## What This Problem Is Asking (Simple Terms)

You have an array of strings. You need to group together all strings that are anagrams of each other — strings that contain the same characters with the same frequencies.

For example, `"eat"`, `"tea"`, and `"ate"` are all anagrams (they all contain e×1, a×1, t×1), so they belong in the same group. `"bat"` is alone — it's not an anagram of any other string.

You are not asked to find *which* strings are anagrams of a specific one — just to group all anagrams together into separate lists.

---

## Example 1

**Input:** `strs = ["eat","tea","tan","ate","nat","bat"]`

**Output:** `[["bat"],["nat","tan"],["ate","eat","tea"]]`

**Explanation:**

- `"bat"` is alone → its own group.
- `"nat"` and `"tan"` are anagrams → same group.
- `"ate"`, `"eat"`, `"tea"` are anagrams → same group.

---

## Example 2

**Input:** `strs = [""]`

**Output:** `[[""]]`

---

## Example 3

**Input:** `strs = ["a"]`

**Output:** `[["a"]]`

---

## Constraints

- `1 <= strs.length <= 10^4`
- `0 <= strs[i].length <= 100`
- `strs[i]` consists of lowercase English letters.

**Follow-up:** How would you handle Unicode characters or very long strings efficiently?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could compare every pair of strings to check if they're anagrams (sort each, compare). If two strings are anagrams, put them in the same group. This requires comparing every pair — O(n²) comparisons, each taking O(k log k) to sort.

### Brute Force Pseudocode

```
groups = empty list of lists
used = array of false, size n
for i from 0 to n-1:
    if used[i]: continue
    group = [strs[i]]
    used[i] = true
    for j from i+1 to n-1:
        if used[j]: continue
        if sorted(strs[i]) == sorted(strs[j]):
            group.add(strs[j])
            used[j] = true
    groups.add(group)
return groups
```

### Why Brute Force Is Slow

Comparing every pair takes O(n²) string comparisons. Each comparison sorts both strings (O(k log k)). Total: O(n² × k log k) — too slow for large inputs.

## Which Data Structure/Technique, and Why?

You need to group strings that share the same "anagram signature." Two strings are anagrams if they contain **the same characters with the same frequencies**.

So the label for each word comes from counting its letters:

- `"eat"` → a×1, e×1, t×1 → label `"a1e1t1"`
- `"tea"` → a×1, e×1, t×1 → same label `"a1e1t1"` → same group
- `"tan"` → a×1, n×1, t×1 → label `"a1n1t1"` → different group

A HashMap maps this label to the list of words that share it:

- **Key** = the label (built from letter counts)
- **Value** = list of all strings with that key

**Signal in the problem:** "group" + "anagrams" → group by a computed label → HashMap<String, List<String>>.

Since the constraints say **lowercase English letters only**, there are exactly 26 possible letters. You can store counts in a fixed array of 26 — one box per letter.

---

## Optimized Approach 1: Counting Array of 26 (Recommended)

Since `strs[i]` contains only lowercase English letters, you can build the label from a 26-box array:

1. For each word, create an array of 26 zeros (one box per letter).
2. For each letter in the word, increment its box (`box = letter - 'a'`).
3. Build the label by writing each letter and its count for non-zero boxes: e.g., `"eat"` → `"a1e1t1"`, `"tea"` → `"a1e1t1"` → same key.
4. Map this label → list of words.
5. Return all lists from the map.

### Pseudocode

```
groups = empty map (String -> List<String>)
for each word in words:
    count = array of 26 zeros
    for each letter c in word:
        count[c - 'a']++
    key = ""
    for i from 0 to 25:
        if count[i] > 0:
            key += ('a' + i) + count[i]   // e.g., "a1e1t1"
    groups[key].add(word)
return all values of groups
```

### Java Code

```java
class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {
        Map<String, List<String>> groups = new HashMap<>();

        for (String word : strs) {
            int[] count = new int[26];
            for (int i = 0; i < word.length(); i++) {
                int loc = word.charAt(i) - 'a';
                count[loc]++;
            }

            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < 26; i++) {
                if (count[i] > 0) {
                    sb.append((char) ('a' + i));
                    sb.append(count[i]);
                }
            }
            String key = sb.toString();

            groups.computeIfAbsent(key, k -> new ArrayList<>()).add(word);
        }

        return new ArrayList<>(groups.values());
    }
}
```

### Line-by-line

- `int[] count = new int[26]` — one box per lowercase letter `a`–`z`.
- `int loc = word.charAt(i) - 'a'` — maps each letter to its box number (`'a'` → 0, `'b'` → 1, ..., `'z'` → 25).
- `count[loc]++` — deposits one count for this letter.
- `StringBuilder sb` — builds the label string.
- `if (count[i] > 0)` — only append boxes that actually appeared.
- `sb.append((char) ('a' + i))` — appends the letter for box `i`.
- `sb.append(count[i])` — appends how many times it appeared.
- `groups.computeIfAbsent(key, k -> new ArrayList<>()).add(word)` — creates a new list if the key is new, then adds the word.
- `new ArrayList<>(groups.values())` — wraps all lists into the result.

### Why increment for `s` and decrement for `t`? (Counting logic)

Think of the map as a "bank account" for each letter:

1. First pass over `s`: deposit each letter into the account (count goes up).
2. Second pass over `t`: withdraw each letter from the account (count goes down).

If `t` has exactly the same letters as `s`, every box ends at exactly zero — nothing left over, nothing missing. If `t` has more of a letter than `s`, some box goes negative. If `t` is missing a letter, some box stays positive.

## Complexity (Counting Array Approach)

- Time: O(n × k) where n = number of strings, k = max string length (count each letter once per word).
- Space: O(n × k) — storing all strings in the map.

## Alternative Approach: Sorting Key

If you prefer not to count, you can sort each string's characters to build the label:

```
groups = empty map (String -> List<String>)
for each word in words:
    key = sorted(word)   // sort characters
    groups[key].add(word)
return all values of groups
```

This is O(n × k log k) because you sort each word. It works fine for short words but does more work than the counting array when words are long.

### Java Code (Sorting Key)

```java
class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {
        Map<String, List<String>> groups = new HashMap<>();
        for (String s : strs) {
            char[] chars = s.toCharArray();
            Arrays.sort(chars);
            String key = new String(chars);
            groups.computeIfAbsent(key, k -> new ArrayList<>()).add(s);
        }
        return new ArrayList<>(groups.values());
    }
}
```

## Complexity (Sorting Key Approach)

- Time: O(n × k log k) where k = max string length (sorting each string).
- Space: O(n × k) — storing all strings in the map.

## Common Mistakes

- **Using the original string as the key.** `"eat"` and `"tea"` are different strings but anagrams — key must be the sorted form or frequency signature.
- **Forgetting `computeIfAbsent` / creating duplicate lists.** Use `computeIfAbsent` or check `containsKey` before `put`.
- **Returning `groups.values()` directly.** It's a `Collection`, not a `List`. Wrap with `new ArrayList<>(...)`.
- **Empty string / single char edge cases.** `""` sorts to `""` — works fine, but make sure your code handles it.
- **Building the label as numbers only** — `"a1e1t1"` includes letters so `"a1e1t1"` and `"a1n1t1"` stay distinct. Writing only numbers would collide.

## How to Explain (interview)

**Opening:** Group Anagrams groups strings that are anagrams of each other. Two strings are anagrams iff they have the same characters with the same frequencies. So count each letter (a→z), build a label from the counts, group all strings sharing the same label using a HashMap<String, List<String>>. O(n × k) time where k is string length.

**The basic flow:**
```java
Map<String, List<String>> groups = new HashMap<>();
for (String word : strs) {
    int[] count = new int[26];
    for (int i = 0; i < word.length(); i++) {
        count[word.charAt(i) - 'a']++;
    }
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < 26; i++) {
        if (count[i] > 0) {
            sb.append((char) ('a' + i));
            sb.append(count[i]);
        }
    }
    String key = sb.toString();
    groups.computeIfAbsent(key, k -> new ArrayList<>()).add(word);
}
return new ArrayList<>(groups.values());
```

**The part that trips everyone up:** building the label correctly — only include boxes that are non-zero, and append both the letter and its count. Without the letter, `"a1b1"` and `"b1a1"` would collide; without the count, `"a1b2"` and `"a2b1"` would collide.

**The mistakes to remember:**
- Using the original string as the key (won't group anagrams)
- Forgetting `computeIfAbsent` / creating duplicate lists
- Returning `groups.values()` directly (it's a `Collection`, not a `List`)
- Not handling empty strings (empty key `""` — works fine)
