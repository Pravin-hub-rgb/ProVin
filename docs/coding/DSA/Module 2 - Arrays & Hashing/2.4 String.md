A String is an immutable sequence of characters. Once created, it cannot be changed — every "modification" creates a new String. Strings are the most common input in DSA problems (anagrams, palindromes, substring search).

---

## Declaration and Creation

```java
String s = "Hello";                    // string literal
String t = new String("Hello");        // new object (avoid unless needed)
String empty = "";                     // empty string
String fromChars = new String(new char[]{'H','i'}); // from char array
```

**String pool:** literals like `"Hello"` are interned — two variables with the same literal point to the same object. `new String("Hello")` forces a new object. For DSA you rarely need `new String`.

## Accessing Characters

```java
String s = "Hello";
System.out.println(s.length());          // 5 (method, with parens)
System.out.println(s.charAt(0));         // 'H'
System.out.println(s.charAt(s.length()-1)); // 'o' (last char)
```

- `length()` is a method (with parens) — unlike array's `length` field.
- `charAt(i)` returns a `char` (primitive), not a String.

## Common Methods

```java
String s = "Hello World";

s.substring(0, 5);        // "Hello" (from 0 to 4)
s.substring(6);           // "World" (from 6 to end)
s.toUpperCase();          // "HELLO WORLD"
s.toLowerCase();          // "hello world"
s.indexOf('o');           // 4 (first occurrence)
s.lastIndexOf('o');       // 7
s.contains("World");      // true
s.startsWith("He");       // true
s.endsWith("ld");         // true
s.replace('l', 'x');      // "Hexxo Worxd" (new string)
s.trim();                 // removes leading/trailing spaces
s.split(" ");             // ["Hello", "World"]
```

**Remember:** none of these modify `s` — they return new strings. `s` stays "Hello World".

## Immutability in Action

```java
String s = "Hello";
s.toUpperCase();              // does NOT change s
System.out.println(s);        // "Hello" — unchanged

String t = s.toUpperCase();   // t = "HELLO", s still "Hello"
```

Because strings are immutable, repeated concatenation in a loop creates many intermediate strings — O(n) per concatenation, O(n²) total. Use StringBuilder for that (see 2.4).

## Comparison

```java
String a = "Vin";
String b = "Vin";
String c = new String("Vin");

System.out.println(a == b);        // true (string pool, same literal)
System.out.println(a == c);        // false (different objects)
System.out.println(a.equals(c));   // true (same content)
System.out.println(a.equalsIgnoreCase("vin")); // true
```

**Always compare content with `.equals()` (or `.equalsIgnoreCase()`), never `==`.** `==` compares references (memory addresses). This bug bites everyone once.

## Converting: String ↔ char[]

```java
String s = "hello";
char[] chars = s.toCharArray();     // ['h','e','l','l','o']

String back = new String(chars);    // "hello"
String fromChar = String.valueOf('A'); // "A"
```

In DSA, converting a string to a char array (`s.toCharArray()`) lets you manipulate characters in place — essential for in-place string problems (reverse, palindrome, anagram).

## Splitting and Joining

```java
String s = "apple,banana,cherry";
String[] parts = s.split(",");              // ["apple", "banana", "cherry"]

String joined = String.join("-", parts);    // "apple-banana-cherry"
```

- `split(regex)` takes a regex. `split(",")` splits on comma. `split("\\s+")` splits on whitespace.
- `String.join(delimiter, array)` joins with a delimiter.

## Cost (Big-O)

| Operation | Time |
|---|---|
| `length()`, `charAt(i)` | O(1) |
| `substring` (Java 7+) | O(n) (copies) |
| `equals`, `compareTo` | O(n) |
| `indexOf`, `contains` | O(n × m) (naive) |
| `concatenation` (s + t) | O(n + m) |
| `toCharArray()` | O(n) |

## Common Pitfalls

- **`==` instead of `.equals()`** — compares references, not content. Silent wrong answers.
- **Concatenation in a loop** — O(n²). Use StringBuilder.
- **`substring` indexing** — `substring(begin, end)` is [begin, end) — end is exclusive. `s.substring(1, 3)` gives chars at indices 1 and 2.
- **Empty string edge cases** — `s.charAt(0)` on `""` throws `StringIndexOutOfBoundsException`. Check `s.isEmpty()` first.
- **Null strings** — `null.length()` throws NPE. Check for null.
- **`split` on trailing empty strings** — `"a,b,".split(",")` gives `["a", "b"]` (trailing empty dropped). Use `split(",", -1)` to keep them.

## A Small Program: Check Palindrome

```java
public class Palindrome {
    static boolean isPalindrome(String s) {
        int left = 0, right = s.length() - 1;
        while (left < right) {
            if (s.charAt(left) != s.charAt(right)) return false;
            left++;
            right--;
        }
        return true;
    }

    public static void main(String[] args) {
        System.out.println(isPalindrome("racecar"));  // true
        System.out.println(isPalindrome("hello"));    // false
    }
}
```

Two pointers from both ends, comparing characters. O(n) time, O(1) space.

## In Your Own Words

1. Why are Strings immutable in Java, and what is the consequence for concatenation?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Strings are immutable for thread-safety and security (string pool sharing). The consequence: every "modification" (concatenation, toUpperCase, etc.) creates a new String object, copying all characters. In a loop, `s += x` is O(n) per iteration → O(n²) total. Use StringBuilder (mutable) for repeated appends — O(1) amortized per append.

</details>

2. Why must you use `.equals()` instead of `==` to compare Strings?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `==` compares references (memory addresses), not content. String literals are pooled so `"Vin" == "Vin"` is true, but `new String("Vin")` creates a different object, so `==` returns false even for identical text. `.equals()` compares character content. Always use `.equals()` (or `.equalsIgnoreCase()`) for content comparison.

</details>

3. How do you convert a String to a char array, and why is it useful?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `s.toCharArray()` returns a `char[]`. It's useful because char arrays are mutable — you can modify characters in place (swap, reverse, sort) without creating new objects. Essential for in-place string problems like reversing a string or checking anagrams by sorting characters.

</details>
