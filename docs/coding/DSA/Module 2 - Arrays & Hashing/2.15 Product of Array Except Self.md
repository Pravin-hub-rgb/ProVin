**Problem:** Given an integer array `nums`, return an array `answer` such that `answer[i]` is equal to the product of all the elements of `nums` except `nums[i]`.

The product of any prefix or suffix of `nums` is **guaranteed** to fit in a 32-bit integer.

You must write an algorithm that runs in O(n) time and **without using the division operation**.

**Link:** https://leetcode.com/problems/product-of-array-except-self/

---

## What This Problem Is Asking (Simple Terms)

You have an array of numbers. For each position `i`, you need to compute the product of **all other elements** — everything except the one at position `i`.

For example, if `nums = [1,2,3,4]`:
- `answer[0]` = product of everything except index 0 = 2×3×4 = 24
- `answer[1]` = product of everything except index 1 = 1×3×4 = 12
- `answer[2]` = product of everything except index 2 = 1×2×4 = 8
- `answer[3]` = product of everything except index 3 = 1×2×3 = 6

You cannot use division (the problem forbids it, and division by zero is a problem anyway).

**What about "prefix or suffix"?** A **prefix** is everything from the start up to some point — for `[1,2,3,4]`, the prefix `[1,2]` is the first two numbers. A **suffix** is everything from some point to the end — the suffix `[3,4]` is the last two. The sentence in the problem does two jobs:

1. **It's a promise:** every product of a start-section or an end-section fits in a 32-bit int, so no overflow — you don't need to do anything about it.
2. **It's a hint:** for any index, the answer is two parts multiplied together — everything to its **left** (a prefix) times everything to its **right** (a suffix). The problem is quietly telling you how it wants to be solved.

## Constraints

- `2 <= nums.length <= 10^5`
- `-30 <= nums[i] <= 30`
- The product of any prefix or suffix of `nums` is **guaranteed** to fit in a 32-bit integer.

**Follow-up:** Can you solve it in O(1) extra space complexity? (The output array does not count as extra space for the purpose of space complexity analysis.)

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand? A genuine first attempt: keep a `product = 1`, loop through the array for each index, skip the current index, multiply everything else, store it. Skip index `i` means the inner loop just checks `j != i`.

For each position `i`, multiply all other elements together:
- For index 0: multiply nums[1] × nums[2] × ... × nums[n-1]
- For index 1: multiply nums[0] × nums[2] × ... × nums[n-1]
- And so on...

### Brute Force Pseudocode

```
n = nums.length
answer = new array of size n
for i from 0 to n-1:
    product = 1
    for j from 0 to n-1:
        if j != i:
            product = product * nums[j]
    answer[i] = product
return answer
```

(One correction people make here: the first and last elements are **not** skipped as positions — index 0 has nothing on its left, so its "left product" is just 1; the last index has nothing on its right, so its "right product" is just 1. They still need answers.)

### Why Brute Force Is Slow

The outer loop runs `n` times, and the inner loop runs `n` times for each outer iteration. That's about `n × n = n²` operations. For `n = 10^5`, that's `10^10` operations — too slow.

### The Question That Unlocks the Optimization

In the nested approach, the left product for index 3 **includes** the left product for index 2. What are you recomputing? Every product of "everything to the left" is the previous one, times one more number. That's a **running product** — reuse it instead of rebuilding it. This is a general habit: when your brute force repeats the same multiplication, look for a value you can carry forward.

---

## Which Data Structure, and Why?

The problem explicitly forbids using division. Also, division by zero is a problem if any element is `0`.

So decompose the answer instead:

`result[i] = (product of elements left of i) × (product of elements right of i)`

Check it on `nums = [1,2,3,4]`, index 2: left part = 1×2 = 2, right part = 4 → 2×4 = 8. ✅ Index 1: left = 1, right = 3×4 = 12 → 12. ✅

You compute left products (prefixes) in one pass, right products (suffixes) in another. This is exactly what the prefix/suffix sentence was hinting at.

**Signal in the problem:** "product of all elements except self" + "no division" → prefix/suffix products.

---

## Optimized Approach 1: Running Variables (Walk and Carry)

Two passes, each carrying one running variable:

1. **Left to right:** at each index, **first** write the running product so far into the slot, **then** multiply the running product by the current number so it's ready for the next index.
2. **Right to left:** same two moves from the other end — **first** multiply the slot by the running right product, **then** update the running product.

The order inside each loop matters: *use the variable first, update it second.*

### Walk-through on `[2,3,4,5]`

Left pass (`left = 1`, write then update):

| i | write `ans[i] = left` | then `left *= nums[i]` |
|---|----------------------|------------------------|
| 0 | ans[0] = 1 | left = 1×2 = 2 |
| 1 | ans[1] = 2 | left = 2×3 = 6 |
| 2 | ans[2] = 6 | left = 6×4 = 24 |
| 3 | ans[3] = 24 | left = 24×5 = 120 |

Slots now hold `1, 2, 6, 24` — each one is the product of everything to its **left**. (Index 3's slot is 24 = 2×3×4 — correct, 5 itself doesn't belong in its own left product.)

Right pass (`right = 1`, multiply slot then update), walking `i = 3 → 0`:

| i | `ans[i] *= right` | then `right *= nums[i]` |
|---|-------------------|-------------------------|
| 3 | ans[3] = 24×1 = 24 | right = 1×5 = 5 |
| 2 | ans[2] = 6×5 = 30 | right = 5×4 = 20 |
| 1 | ans[1] = 2×20 = 40 | right = 20×3 = 60 |
| 0 | ans[0] = 1×60 = 60 | right = 60×2 = 120 |

Final: `[60, 40, 30, 24]` — index 0: 3×4×5=60, index 1: 2×4×5=40, index 2: 2×3×5=30, index 3: 2×3×4=24. ✅

Note what this did for the **follow-up**: no prefix array, no suffix array, no third combining array — just the answer array plus **one variable per pass**. That's O(1) extra space.

### Java Code

```java
class Solution {
    public int[] productExceptSelf(int[] nums) {
        int[] ans = new int[nums.length];

        // Pass 1: left products (prefix), running variable
        int left = 1;
        for (int i = 0; i < nums.length; i++) {
            ans[i] = left;        // write what's to the left of i
            left *= nums[i];      // extend the running product
        }

        // Pass 2: multiply by right products (suffix), running variable
        int right = 1;
        for (int i = nums.length - 1; i >= 0; i--) {
            ans[i] *= right;      // slot already holds the left product
            right *= nums[i];     // extend the running product leftward
        }

        return ans;
    }
}
```

### Line-by-line

- `int left = 1` — nothing to the left of index 0, so the running left product starts at 1.
- `ans[i] = left` — **before** touching `nums[i]`, the slot gets "everything strictly before i".
- `left *= nums[i]` — now grow it for the next index. (Multiply by `nums[i]`, the **number** — not `i`, the position.)
- Pass 2's loop **starts** at `nums.length - 1` because that's the last valid index — here the `- 1` is correct.
- Pass 1's loop must go to `i < nums.length` — **no `- 1`**. `i < length - 1` stops one short, never fills the last slot, it stays `0`, and pass 2 then multiplies that 0 — the whole tail comes out wrong. "Less than length" already means "up to length minus one".
- `ans[i] *= right` — **multiply**, don't replace: the slot already holds the left product from pass 1.

## Optimized Approach 2: The Array Remembers (from the notes)

Same two-pass idea, but pass 1 doesn't keep a separate variable — **the array itself remembers the running product**, reading back its own previous slot:

```java
class Solution {
    public int[] productExceptSelf(int[] nums) {
        int n = nums.length;
        int[] output = new int[n];

        // Pass 1: prefix products
        output[0] = 1;
        for (int i = 1; i < n; i++) {
            output[i] = output[i - 1] * nums[i - 1];
        }

        // Pass 2: multiply by suffix products
        int suffix = 1;
        for (int i = n - 1; i >= 0; i--) {
            output[i] *= suffix;
            suffix *= nums[i];
        }

        return output;
    }
}
```

### Line-by-line

- `output[0] = 1` — no elements to the left of index 0, so prefix product is 1.
- Pass 1: `output[i] = output[i-1] * nums[i-1]` — prefix product up to i: the previous slot's product, times the previous number.
- Pass 2: `suffix` tracks the running product of elements to the right. `output[i] *= suffix` multiplies prefix by suffix. Then `suffix *= nums[i]` extends suffix leftward.
- After both passes, `output[i] = prefix[i] × suffix[i]` = product of all except self.

### The Two Approaches Side by Side

| | Approach 1 (running variable) | Approach 2 (array remembers) |
|---|------------------------------|------------------------------|
| Pass 1 | `left` variable: write, then `left *= nums[i]` | no variable: `output[i] = output[i-1] * nums[i-1]` |
| Pass 2 | identical — running variable, multiply slot, update | identical — running variable, multiply slot, update |
| Extra state | one `int` variable per pass | zero extra variables (array is the memory) |
| Reading it | the running product is visible in a named variable | you must follow `output[i-1]` back a slot |

Both are O(n) time and O(1) extra space, both pass interviews. The running-variable version keeps the product in a named thing you can picture ("walk and carry"); the notes version is compact because the array does double duty. Pick whichever you can explain without pausing — and be ready to say *why* pass 2 is a multiply and not an assignment.

---

## Complexity

- Time: O(n) — two passes, each touching every element once (both approaches).
- Space: O(1) extra — only the return array plus a couple of `int` variables (the output array is the return value, not counted as extra).

---

## Common Mistakes

- **Using division** — problem forbids it; also division by zero if any element is 0.
- **`i < nums.length - 1` in pass 1** — the off-by-one trap. The loop stops one short, the last slot never gets written (stays `0`), and pass 2 multiplies that 0 — wrong tail. Pass 1 condition is `i < nums.length`. (The `- 1` *is* correct in pass 2, where you're **starting** at the last index — starting position vs stopping condition are different jobs.)
- **`left = left * i`** — `i` is the position, `nums[i]` is the number sitting there. Multiply by the number.
- **Replacing instead of multiplying in pass 2** — `ans[i] = right` throws away the left product that pass 1 stored. It must be `ans[i] *= right`.
- **O(n) extra space** — allocating separate prefix and suffix arrays (then a third to combine). The follow-up wants one answer array plus variables; fold pass 2 into the answer.
- **Off-by-one in the notes version:** `output[i] = output[i-1] * nums[i-1]`, not `nums[i]`.
- **Overflow:** products can exceed int range. If the problem has large values, use `long` and cast. (LeetCode #238 guarantees the fits-in-32-bits property and expects int output, so int is fine here.)

## How to Explain (interview)

**Opening:** Product Except Self asks for the product of all elements except the current one, without division. The key idea: `result[i] = (product of elements to the left) × (product of elements to the right)`. Two passes: first pass fills the output array with prefix products; second pass multiplies each by the running suffix product. O(n) time, O(1) extra space.

**The basic flow (running-variable style):**
```java
int[] ans = new int[n];
int left = 1;
for (int i = 0; i < n; i++) { ans[i] = left; left *= nums[i]; }
int right = 1;
for (int i = n - 1; i >= 0; i--) { ans[i] *= right; right *= nums[i]; }
```

**The part that trips everyone up:** no division allowed (and division by zero). In pass 2, multiply into the slot — it already holds the prefix. And pass 1 runs to `i < n`, not `n - 1`.

**The mistakes to remember:**
- Using division (forbidden, and breaks on zeros)
- `i < nums.length - 1` in pass 1 — last slot stays 0, tail comes out wrong
- `ans[i] = right` instead of `ans[i] *= right` — wipes the left product
- Allocating O(n) extra space instead of reusing the output array

**If they ask for the alternative:** pass 1 can also read the array's own previous slot — `output[i] = output[i-1] * nums[i-1]` — no running variable needed; the array remembers the prefix for you. Pass 2 is the same either way.
