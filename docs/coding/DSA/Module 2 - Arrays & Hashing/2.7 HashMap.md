A HashMap maps keys to values with O(1) average lookup, insert, and delete. It is the single most-used data structure in DSA interviews — frequency counts, two-sum lookups, grouping, caching.

---

## Declaration and Creation

```java
import java.util.HashMap;
import java.util.Map;

Map<String, Integer> freq = new HashMap<>();        // empty
Map<String, Integer> copy = new HashMap<>(freq);    // copy of another map
Map<String, Integer> sized = new HashMap<>(100);    // initial capacity 100
```

**Note:** Use the interface type `Map` on the left, `HashMap` on the right. This lets you swap to `TreeMap` (sorted) without changing code.

## Core Operations

```java
Map<String, Integer> map = new HashMap<>();

map.put("apple", 2);                    // insert
map.put("apple", 3);                    // overwrite → apple: 3
System.out.println(map.get("apple"));    // 3
System.out.println(map.get("grape"));    // null (not present)
System.out.println(map.getOrDefault("grape", 0)); // 0 (safe default)

System.out.println(map.containsKey("apple"));  // true
System.out.println(map.containsValue(3));     // true (O(n)!)

map.remove("apple");                    // remove key
System.out.println(map.size());         // 0
map.clear();                            // remove all
```

- `put`, `get`, `containsKey`, `remove`: O(1) average.
- `containsValue`: O(n) — scans all values. Avoid in hot code.
- `getOrDefault(key, default)`: returns the value or default if key absent. Use this to avoid null checks.

## Frequency Counting Pattern

The most common HashMap pattern in DSA.

```java
String s = "aabbc";
Map<Character, Integer> freq = new HashMap<>();
for (char c : s.toCharArray()) {
    freq.put(c, freq.getOrDefault(c, 0) + 1);
}
// freq = {a:2, b:2, c:1}
```

**Shorthand (Java 8+):**
```java
freq.merge(c, 1, Integer::sum);   // same as above, cleaner
```

## Grouping Pattern

Map a computed key to a list of items.

```java
String[] words = {"eat", "tea", "tan", "ate", "nat", "bat"};
Map<String, List<String>> groups = new HashMap<>();

for (String w : words) {
    char[] chars = w.toCharArray();
    Arrays.sort(chars);
    String key = new String(chars);   // sorted string as key
    groups.computeIfAbsent(key, k -> new ArrayList<>()).add(w);
}
// groups: {"aet": ["eat","tea","ate"], "ant": ["tan","nat"], "abt": ["bat"]}
```

- `computeIfAbsent(key, k -> new ArrayList<>())` — creates the list if absent, returns it. Cleaner than `if (!map.containsKey(key)) map.put(key, new ArrayList<>())`.

## Iterating

```java
Map<String, Integer> map = new HashMap<>();
map.put("a", 1); map.put("b", 2);

// Iterate over entries (most common)
for (Map.Entry<String, Integer> e : map.entrySet()) {
    System.out.println(e.getKey() + " = " + e.getValue());
}

// Iterate over keys
for (String key : map.keySet()) {
    System.out.println(key + " = " + map.get(key));
}

// Java 8+ forEach
map.forEach((k, v) -> System.out.println(k + " = " + v));
```

**Note:** iteration order is NOT guaranteed (HashMap is unordered). Use `LinkedHashMap` for insertion order, `TreeMap` for sorted order.

## Cost (Big-O)

| Operation | Average | Worst (hash collisions) |
|---|---|---|
| `put`, `get`, `containsKey`, `remove` | O(1) | O(n) |
| `size` | O(1) | O(1) |
| Iteration | O(n) | O(n) |

Worst case O(n) occurs with hash collisions. Java 8+ converts long collision chains to balanced trees (O(log n)) for String/Integer keys, so worst case is rarely hit in practice.

## When to Use

- Frequency counting (count occurrences of each element).
- "Have I seen this value?" lookups (Two Sum complement).
- Grouping items by a computed property (anagrams).
- Caching / memoization (store computed results).
- Mapping an entity to its data (id → object).

## Common Pitfalls

- **`get` returns null for missing keys.** Calling `.intValue()` on null → NPE. Use `getOrDefault`.
- **Modifying while iterating** → `ConcurrentModificationException`. Use `Iterator.remove()` or collect keys first.
- **Using mutable objects as keys.** If a key's `hashCode` changes after insertion (e.g., a list you modified), the map can't find it. Use immutable keys (String, Integer, or your own with stable hashCode/equals).
- **Forgetting to override `hashCode` and `equals`** in custom key classes. Default `Object.hashCode()` uses memory address — two "equal" objects hash differently and won't match.
- **`containsValue` is O(n).** If you need value lookups, consider a reverse map or a different structure.

## A Small Program: Two Sum with HashMap

```java
import java.util.*;

public class TwoSum {
    static int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>(); // value → index
        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];
            if (seen.containsKey(complement)) {
                return new int[]{seen.get(complement), i};
            }
            seen.put(nums[i], i);
        }
        return new int[]{};
    }

    public static void main(String[] args) {
        int[] nums = {2, 7, 11, 15};
        System.out.println(Arrays.toString(twoSum(nums, 9))); // [0, 1]
    }
}
```

## In Your Own Words

1. What is the average time complexity of HashMap get/put, and what's the worst case?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Average O(1) — hash the key, jump to the bucket. Worst case O(n) if all keys hash to the same bucket (collisions). Java 8+ converts long collision chains to balanced trees (O(log n)) for comparable keys, so worst case is rarely hit in practice. Good hash functions distribute keys evenly.

</details>

2. Why should you use `getOrDefault` instead of `get` when counting frequencies?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `get(key)` returns null for missing keys. Doing `freq.get(c) + 1` on null throws NullPointerException. `getOrDefault(c, 0)` returns 0 for missing keys, so `freq.getOrDefault(c, 0) + 1` works safely without an explicit null check.

</details>

3. What happens if you use a mutable object as a HashMap key and then modify it?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The object's hashCode may change after modification, so the map can no longer find it in the original bucket — the entry becomes "lost" (still in the map but unreachable by key). Always use immutable keys (String, Integer, or custom classes with stable hashCode/equals). If you must use a mutable key, don't modify it after insertion.

</details>
