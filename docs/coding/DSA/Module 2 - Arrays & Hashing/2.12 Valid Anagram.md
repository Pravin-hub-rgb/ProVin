**Problem:** Given two strings `s` and `t`, return `true` if `t` is an anagram of `s`, and `false` otherwise.

An **Anagram** is a word or phrase formed by rearranging the letters of a different word or phrase, typically using all the original letters exactly once.

**Link:** https://leetcode.com/problems/valid-anagram/

---

## What This Problem Is Asking (Simple Terms)

You have two strings. You need to check whether they contain **the same characters with the same frequencies**, just possibly in a different order.

If `s = "anagram"` and `t = "nagaram"`, both have `a`×3, `n`×1, `g`×1, `r`×1, `m`×1 → anagram.
If `s = "rat"` and `t = "car"`, `s` has `t` but `t` has `c` → not an anagram.

You are not asked to find *which* characters differ — just whether the two strings are anagrams or not.

---

## Example 1

**Input:** `s = "anagram"`, `t = "nagaram"`

**Output:** `true`

**Explanation:** Both strings contain the same characters with the same frequencies: `a`×3, `n`×1, `g`×1, `r`×1, `m`×1.

---

## Example 2

**Input:** `s = "rat"`, `t = "car"`

**Output:** `false`

**Explanation:** `s` has `r`×1, `a`×1, `t`×1. `t` has `c`×1, `a`×1, `r`×1. The character `t` is in `s` but not in `t`, and `c` is in `t` but not in `s`. Not anagrams.

---

## Constraints

- `1 <= s.length, t.length <= 5 * 10^4`
- `s` and `t` consist of lowercase English letters.

**Follow-up:** What if the inputs contain Unicode characters? How would you adapt your solution?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could sort both strings and compare them character by character. If they match after sorting, they're anagrams.

### Brute Force Pseudocode

```
sort s
sort t
if s == t: return true
else: return false
```

### Why Brute Force Is Slower

Sorting both strings takes O(n log n) time where n is the string length. While simple, it's slower than counting characters directly.

---

## Which Data Structure, and Why?

You learned in 2.8 that a **HashSet** answers: "Have I seen this character before?" → yes/no.

For Valid Anagram, that's **not enough**. A set only tracks presence, not count. Consider:
- `s = "aab"` → counts: a×2, b×1
- `t = "abb"` → counts: a×1, b×2

Both have the same set of characters `{a, b}` → a HashSet would say "yes" for both. But they're **not** anagrams because the frequencies differ.

So you need to **count** characters:
- **HashMap** (char → count): tracks frequency of each character
- **int[26]** array: one slot per lowercase letter (a→0, b→1, ..., z→25), O(1) space since 26 is constant

**Signal in the problem:** "same characters, same frequency" / "anagram" → frequency counting → HashMap or int[26].

---

## Optimized Approach (Counting)

Instead of sorting, count characters:

1. If lengths differ → not an anagram (return false immediately)
2. Create a count array of size 26 (one slot per letter)
3. Walk through `s`: increment count for each character
4. Walk through `t`: decrement count for each character
5. If any count is non-zero at the end → frequencies differ → not an anagram
6. If all counts are zero → an anagram

### Why This Is O(n)

You walk through both strings once each. Each character operation is O(1). Total time is O(n), space is O(1) (fixed array of 26).

### Pseudocode

```
if s.length != t.length: return false
count = array of 26 zeros
for each c in s: count[c - 'a']++
for each c in t: count[c - 'a']--
for each c in count:
    if c != 0: return false
return true
```

### Java Code

```java
class Solution {
    public boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) return false;

        int[] count = new int[26];   // for lowercase letters
        for (int i = 0; i < s.length(); i++) {
            count[s.charAt(i) - 'a']++;
            count[t.charAt(i) - 'a']--;
        }
        for (int c : count) {
            if (c != 0) return false;
        }
        return true;
    }
}
```

### Line-by-line

- Length check first — different lengths can't be anagrams.
- `count[26]` — one slot per letter. `'a'` → index 0, `'b'` → 1, ..., `'z'` → 25. The trick `c - 'a'` maps a char to 0–25.
- First loop: increment for `s`, decrement for `t` in one pass.
- Second loop: if any count is non-zero, frequencies differ → not anagram.

## Complexity

- Time: O(n) — two passes over the strings.
- Space: O(1) — fixed array of 26 (constant, regardless of input size). O(k) where k = alphabet size.

## Common Mistakes

- **Not checking lengths first** — wastes time; different lengths = not anagram.
- **Using `==` on Strings** — compare with `.equals()` or compare counts, never `==`.
- **Assuming only lowercase letters.** If uppercase or unicode is possible, use a HashMap instead of `int[26]`.
- **Off-by-one in char arithmetic:** `c - 'a'` assumes lowercase. `'A' - 'a'` is negative — out of bounds.

## How to Explain (interview)

**Opening:** Valid Anagram checks if two strings have the same characters with the same frequencies. The brute force sorts both and compares — O(n log n). The optimized version counts characters: increment for `s`, decrement for `t`, and check all counts are zero. Since there are only 26 lowercase letters, a fixed `int[26]` array gives O(n) time and O(1) space.

**The basic flow:**
```java
int[] count = new int[26];
for (int i = 0; i < s.length(); i++) {
    count[s.charAt(i) - 'a']++;
    count[t.charAt(i) - 'a']--;
}
for (int c : count) if (c != 0) return false;
return true;
```

**The part that trips everyone up:** the input might include uppercase or unicode characters. `int[26]` only works for lowercase a–z. Use a HashMap for general cases.

**The mistakes to remember:**
- Forgetting the length check first
- Using `int[26]` for non-lowercase input (out of bounds / wrong answer)
- Comparing Strings with `==` instead of checking counts
