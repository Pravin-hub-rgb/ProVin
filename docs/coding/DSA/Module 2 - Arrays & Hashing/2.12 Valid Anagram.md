**Problem:** Given two strings `s` and `t`, return `true` if `t` is an anagram of `s`, and `false` otherwise.

An **Anagram** is a word or phrase formed by rearranging the letters of a different word or phrase, typically using all the original letters exactly once.

**Link:** https://leetcode.com/problems/valid-anagram/

---

## What This Problem Is Asking (Simple Terms)

You have two strings. You need to check whether they contain **the same characters with the same frequencies**, just possibly in a different order.

If `s = "anagram"` and `t = "nagaram"`, both have `a`×3, `n`×1, `g`×1, `r`×1, `m`×1 → anagram.
If `s = "rat"` and `t = "car"`, `s` has `r`×1, `a`×1, `t`×1. `t` has `c`×1, `a`×1, `r`×1. The character `t` is in `s` but not in `t`, and `c` is in `t` but not in `s`. Not anagrams.

You are not asked to find *which* characters differ — just whether the two strings are anagrams or not.

---

## Example 1

**Input:** `s = "anagram"`, `t = "nagaram"`

**Output:** `true`

**Explanation:** Both strings contain the same characters with the same frequencies: `a`×3, `n`×1, `g`×1, `r`×1, `m`×1.

---

## Example 2

**Input:** `s = "rat"`, `t = "car"`

**Output:** `false`

**Explanation:** `s` has `r`×1, `a`×1, `t`×1. `t` has `c`×1, `a`×1, `r`×1. The character `t` is in `s` but not in `t`, and `c` is in `t` but not in `s`. Not anagrams.

---

## Constraints

- `1 <= s.length, t.length <= 5 * 10^4`
- `s` and `t` consist of lowercase English letters.

**Follow-up:** What if the inputs contain Unicode characters? How would you adapt your solution?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could sort both strings and compare them character by character. If they match after sorting, they're anagrams.

### Brute Force Pseudocode

```
sort s
sort t
if s == t: return true
else: return false
```

### Why Brute Force Is Slower

Sorting both strings takes O(n log n) time where n is the string length. While simple, it's slower than counting characters directly.

---

## Which Data Structure/Technique, and Why?

You need to **count** how many times each character appears — not just whether it appears. A HashSet only tracks presence (yes/no), not count:

- `s = "aab"` → counts: a×2, b×1
- `t = "abb"` → counts: a×1, b×2

Both have the same set `{a, b}` → a HashSet would say "yes" for both. But they're **not** anagrams because the frequencies differ.

So you need to **count** characters:

- **HashMap** (char → count): tracks frequency of each character. Key = character, value = how many times it appears.

**Why `value → count` (not `count → value`)?** Because you look up by **character** and retrieve its **count**. The key in a map is what you search with; the value is what you get back. You search: *"have I seen this character?"* → key = character. You want to know *"how many times?"* → value = count. If you stored `count → character` instead, you'd be looking up by count, which tells you nothing about whether a specific character exists.

**Why increment for `s` and decrement for `t`?**

Think of the map as a "bank account" for each letter:

1. First pass over `s`: deposit each letter into the account (count goes up).
2. Second pass over `t`: withdraw each letter from the account (count goes down).

If `t` has exactly the same letters as `s`, every box ends at exactly zero — nothing left over, nothing missing. If `t` has more of a letter than `s`, some box goes negative. If `t` is missing a letter, some box stays positive.

**Signal in the problem:** "same characters, same frequency" / "anagram" → frequency counting → HashMap.

---

## Optimized Approach 1: HashMap (Java `HashMap`)

Count characters of `s` into a HashMap (increment), then walk `t` and decrement. If any count goes negative or a character isn't in the map at all → not an anagram.

### Pseudocode

```
count = empty HashMap (char -> int)
for each c in s:
    count[c] = count.getOrDefault(c, 0) + 1
for each c in t:
    if count.get(c) == null or count.get(c) == 0:
        return false
    count.put(c, count.get(c) - 1)
return true
```

### Java Code

```java
class Solution {
    public boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) return false;

        Map<Character, Integer> freq = new HashMap<>();
        for (int i = 0; i < s.length(); i++) {
            char ch = s.charAt(i);
            freq.put(ch, freq.getOrDefault(ch, 0) + 1);
        }
        for (int i = 0; i < t.length(); i++) {
            char ch = t.charAt(i);
            if (!freq.containsKey(ch) || freq.get(ch) == 0) {
                return false;
            }
            freq.put(ch, freq.get(ch) - 1);
        }
        return true;
    }
}
```

### Line-by-line

- `freq.put(ch, freq.getOrDefault(ch, 0) + 1)` — if `ch` is new, `getOrDefault` returns 0, so we store 1. If it exists, we add 1.
- `if (!freq.containsKey(ch) || freq.get(ch) == 0)` — if `ch` was never in `s`, or all its copies were used up → not an anagram.
- `freq.put(ch, freq.get(ch) - 1)` — withdraw one occurrence of `ch`.

### Why This Is O(n)

You walk through `s` once to count up, then walk through `t` once to count down. Each character operation is O(1) average with HashMap. Total time O(n), space O(k) where k = number of distinct characters (at most 26 for lowercase).

## Optimized Approach 2: Array of 26 (Better for This Problem)

The constraints say `s` and `t` consist of **lowercase English letters** only. That means there are only 26 possible characters. Instead of a HashMap, you can use a plain `int` array of size 26 — one slot per letter.

### Why this is better here

- **Direct index access:** `'a' - 'a' = 0`, `'b' - 'a' = 1`, ..., `'z' - 'a' = 25`. The character itself tells you which box to read/write — no hashing needed.
- **Less overhead:** A HashMap wraps every character in a `Character` object and every count in an `Integer` object, then runs a hash function. An array is a direct jump to the box number.
- **Constraints allow it:** Since input is guaranteed lowercase `a-z`, 26 slots cover everything. If the input had uppercase or other characters, you'd need the HashMap instead.

### Pseudocode

```
count = array of 26 zeros
for each c in s: count[c - 'a']++
for each c in t: count[c - 'a']--
for each c in count:
    if c != 0: return false
return true
```

### Java Code

```java
class Solution {
    public boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) return false;

        int[] count = new int[26];
        for (int i = 0; i < s.length(); i++) {
            count[s.charAt(i) - 'a']++;
            count[t.charAt(i) - 'a']--;
        }
        for (int c : count) {
            if (c != 0) return false;
        }
        return true;
    }
}
```

### Line-by-line

- `count[26]` — one slot per lowercase letter. `'a'` → index 0, `'b'` → 1, ..., `'z'` → 25.
- `count[s.charAt(i) - 'a']++` — deposit one count for this letter (deposit for `s`).
- `count[t.charAt(i) - 'a']--` — withdraw one count for this letter (withdraw for `t`).
- If any box is non-zero at the end → frequencies differ → not an anagram.

## Complexity (Array Version)

- Time: O(n) — two passes over the strings.
- Space: O(1) — fixed array of 26, regardless of input size.

## Common Mistakes

- **Not checking lengths first** — wastes time; different lengths = not anagram.
- **Using `==` on Strings** — compare with `.equals()` or compare counts, never `==`.
- **Assuming only lowercase letters.** If uppercase or unicode is possible, use a HashMap instead of `int[26]`.
- **Off-by-one in char arithmetic:** `c - 'a'` assumes lowercase. `'A' - 'a'` is negative — out of bounds.

## How to Explain (interview)

**Opening:** Valid Anagram checks if two strings have the same characters with the same frequencies. I'd count characters with a HashMap first — increment for `s`, decrement for `t`, check all counts are zero. O(n) time, O(k) space where k = distinct characters.

**But here, since the input is guaranteed lowercase English letters only, I'd use an int array of size 26 instead** — direct index access with `c - 'a'`, no HashMap overhead. Still O(n) time, O(1) space.

**The basic flow (array version):**
```java
int[] count = new int[26];
for (int i = 0; i < s.length(); i++) {
    count[s.charAt(i) - 'a']++;
    count[t.charAt(i) - 'a']--;
}
for (int c : count) if (c != 0) return false;
return true;
```

**The part that trips everyone up:** `c - 'a'` maps each letter to its own box (0–25). `a` is 0, `b` is 1, ..., `z` is 25. `z - 'a'` is 25, which fits in 26 slots.

**The mistakes to remember:**
- Forgetting the length check first
- Using `int[26]` for non-lowercase input (out of bounds / wrong answer)
- Comparing Strings with `==` instead of checking counts
