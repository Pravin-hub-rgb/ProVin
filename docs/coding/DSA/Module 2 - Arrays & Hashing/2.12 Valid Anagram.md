**Problem:** Given two strings `s` and `t`, return `true` if `t` is an anagram of `s` (same characters, same frequencies, different order). (LeetCode #242)

**Link:** https://leetcode.com/problems/valid-anagram/

---

## Which Data Structure, and Why?

An anagram means both strings have the **same character frequencies**. You need to count characters in one string and check against the other. That's a frequency count → **HashMap** (char → count). Or, since there are only 26 lowercase letters, a fixed `int[26]` array (counting sort) — O(1) space.

Why a map and not a set? A set only tracks presence, not count. "aabc" and "abbc" both have a, b, c — but different counts. You need counts, so a frequency map.

**Signal in the problem:** "same characters, same frequency" / "anagram" → frequency counting → HashMap or int[26].

## Approach

**Brute force (O(n log n)):** sort both strings and compare. Simple, but sorting is slower than counting.

**Optimized (O(n)):** count characters of `s` (+1), then decrement for `t` (-1). If any count goes negative or lengths differ, not an anagram. Or use two frequency maps and compare.

## Pseudocode

```
if s.length != t.length: return false
freq = empty map (char -> count)
for each c in s: freq[c]++
for each c in t:
    if freq[c] == 0: return false
    freq[c]--
return true
```

## Java Code

```java
class Solution {
    public boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) return false;

        int[] count = new int[26];   // for lowercase letters
        for (int i = 0; i < s.length(); i++) {
            count[s.charAt(i) - 'a']++;
            count[t.charAt(i) - 'a']--;
        }
        for (int c : count) {
            if (c != 0) return false;
        }
        return true;
    }
}
```

**Line-by-line:**
- Length check first — different lengths can't be anagrams.
- `count[26]` — one slot per letter. `'a'` → index 0, `'b'` → 1, ..., `'z'` → 25. The trick `c - 'a'` maps a char to 0–25.
- First loop: increment for s, decrement for t in one pass.
- Second loop: if any count is non-zero, frequencies differ → not anagram.

## Complexity

- Time: O(n) — two passes over the strings.
- Space: O(1) — fixed array of 26 (constant, regardless of input size). O(k) where k = alphabet size.

## Common Mistakes

- **Not checking lengths first** — wastes time; different lengths = not anagram.
- **Using `==` on Strings** — compare with `.equals()` or compare counts, never `==`.
- **Assuming only lowercase letters.** If uppercase or unicode is possible, use a HashMap instead of `int[26]`.
- **Off-by-one in char arithmetic:** `c - 'a'` assumes lowercase. `'A' - 'a'` is negative — out of bounds.

## How to Explain (interview)

**Opening:** Valid Anagram checks if two strings have the same characters with the same frequencies. The brute force sorts both and compares — O(n log n). The optimized version counts characters: increment for s, decrement for t, and check all counts are zero. Since there are only 26 lowercase letters, a fixed `int[26]` array gives O(n) time and O(1) space.

**The basic flow:**
```java
int[] count = new int[26];
for (int i = 0; i < s.length(); i++) {
    count[s.charAt(i) - 'a']++;
    count[t.charAt(i) - 'a']--;
}
for (int c : count) if (c != 0) return false;
return true;
```

**The part that trips everyone up:** the input might include uppercase or unicode characters. `int[26]` only works for lowercase a–z. Use a HashMap for general cases.

**The mistakes to remember:**
- Forgetting the length check first
- Using `int[26]` for non-lowercase input (out of bounds / wrong answer)
- Comparing Strings with `==` instead of checking counts
