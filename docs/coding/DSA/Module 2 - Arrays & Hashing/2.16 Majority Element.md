**Problem:** Given an array `nums` of size `n`, return the majority element.

The **majority element** is the element that appears more than `⌊n / 2⌋` times. You may assume that the majority element always exists in the array.

**Link:** https://leetcode.com/problems/majority-element/

---

## Example 1

**Input:** `nums = [3,2,3]`

**Output:** `3`

**Explanation:** `3` appears 2 times, which is more than ⌊3/2⌋ = 1.

---

## Example 2

**Input:** `nums = [2,2,1,1,1,2,2]`

**Output:** `2`

**Explanation:** `2` appears 4 times, which is more than ⌊7/2⌋ = 3.

---

## Constraints

- `n == nums.length`
- `1 <= n <= 10^5`
- `-10^9 <= nums[i] <= 10^9`

**Follow-up:** Could you solve the problem in linear time and in O(1) space?

---

## Which Data Structure, and Why?

You need the element with frequency > n/2. Two approaches:
1. **HashMap** (value → count) — count frequencies, return the one exceeding n/2. O(n) time, O(n) space. Simple and general.
2. **Boyer-Moore Voting Algorithm** — O(n) time, O(1) space. Exploits the fact that a majority element (> n/2) can "cancel out" non-majority elements.

**Signal in the problem:** "appears more than n/2 times" / "majority element" → frequency count (HashMap) or Boyer-Moore (if O(1) space required).

## Approach (HashMap — simplest)

Count frequencies with a HashMap. Return the key whose count > n/2.

## Approach (Boyer-Moore — O(1) space)

Maintain a `candidate` and a `count`. For each element:
- If count == 0, set candidate = current element.
- If current == candidate, count++.
- Else count--.

The majority element survives the cancellation because it appears more than all others combined.

## Java Code (HashMap)

```java
class Solution {
    public int majorityElement(int[] nums) {
        Map<Integer, Integer> freq = new HashMap<>();
        int n = nums.length;
        for (int x : nums) {
            freq.put(x, freq.getOrDefault(x, 0) + 1);
            if (freq.get(x) > n / 2) return x;  // early exit
        }
        return -1; // shouldn't reach here (problem guarantees a majority)
    }
}
```

## Java Code (Boyer-Moore)

```java
class Solution {
    public int majorityElement(int[] nums) {
        int candidate = 0, count = 0;
        for (int x : nums) {
            if (count == 0) candidate = x;
            count += (x == candidate) ? 1 : -1;
        }
        return candidate;
    }
}
```

## Line-by-line (Boyer-Moore)

- `candidate` holds the current majority candidate; `count` is its "lead."
- If `count == 0`, pick the current element as the new candidate.
- If current equals candidate, increment lead; otherwise decrement (cancellation).
- Because the majority appears > n/2 times, it can never be fully cancelled — it survives.

## Complexity

- HashMap: O(n) time, O(n) space.
- Boyer-Moore: O(n) time, O(1) space.

## Common Mistakes

- **Assuming the array is sorted** — majority element problems don't guarantee sorted input (that's a different problem).
- **Boyer-Moore without verifying** — Boyer-Moore finds a candidate; if the problem didn't guarantee a majority, you'd need a second pass to verify the candidate's count > n/2.
- **Off-by-one in the threshold** — "more than n/2" means `> n/2`, not `>= n/2`. For n=4, threshold is >2, so 3+ occurrences.

## How to Explain (interview)

**Opening:** Majority Element asks for the value appearing more than n/2 times. The simple approach: count frequencies with a HashMap and return the one exceeding n/2 — O(n) time, O(n) space. The optimal approach is Boyer-Moore voting: maintain a candidate and a count; increment when you see the candidate, decrement otherwise; when count hits 0, pick a new candidate. The majority survives because it outnumbers all others combined. O(n) time, O(1) space.

**The basic flow (Boyer-Moore):**
```java
int candidate = 0, count = 0;
for (int x : nums) {
    if (count == 0) candidate = x;
    count += (x == candidate) ? 1 : -1;
}
return candidate;
```

**The part that trips everyone up:** Boyer-Moore only works when a majority (> n/2) is **guaranteed**. If not guaranteed, verify the candidate with a second pass counting its occurrences.

**The mistakes to remember:**
- Using Boyer-Moore when no majority is guaranteed (wrong answer)
- "More than n/2" means strictly greater — for n=4, need 3+ occurrences
- Forgetting the O(1)-space requirement makes you over-engineer with a HashMap
