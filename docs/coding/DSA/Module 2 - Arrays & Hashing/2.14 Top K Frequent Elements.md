**Problem:** Given an integer array, return the k most frequent elements. (LeetCode #347)

**Link:** https://leetcode.com/problems/top-k-frequent-elements/

---

## Which Data Structure, and Why?

Two sub-problems: (1) count frequencies → **HashMap** (value → count). (2) find the top k by frequency → **PriorityQueue (min-heap)** of size k, or **bucket sort** by frequency.

Why a min-heap of size k? Keep the k largest frequencies; the smallest of those k sits on top and gets evicted when a larger one comes. O(n log k) instead of sorting all n (O(n log n)).

**Signal in the problem:** "top k most frequent" → frequency map + heap (or bucket sort). "k most/least" → heap.

## Approach

1. Count frequencies with a HashMap.
2. Use a min-heap of size k keyed by frequency. For each entry, push it; if heap size > k, pop the smallest.
3. Extract elements from the heap.

Alternative (bucket sort): create buckets by frequency (index = frequency), then collect from highest frequency down. O(n) time.

## Pseudocode (heap approach)

```
freq = count frequencies (HashMap)
minHeap = empty min-heap (by frequency)
for each (value, count) in freq:
    push (value, count) to minHeap
    if minHeap.size > k: pop
result = elements in minHeap
```

## Java Code (heap approach)

```java
class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        // Step 1: frequency map
        Map<Integer, Integer> freq = new HashMap<>();
        for (int x : nums) freq.put(x, freq.getOrDefault(x, 0) + 1);

        // Step 2: min-heap of size k, keyed by frequency
        PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> a[1] - b[1]);
        for (Map.Entry<Integer, Integer> e : freq.entrySet()) {
            heap.offer(new int[]{e.getKey(), e.getValue()});
            if (heap.size() > k) heap.poll();
        }

        // Step 3: extract
        int[] result = new int[k];
        for (int i = 0; i < k; i++) result[i] = heap.poll()[0];
        return result;
    }
}
```

## Line-by-line

- `freq` maps value → count.
- `PriorityQueue<int[]>` with comparator `a[1] - b[1]` → min-heap by frequency (index 1). Smallest frequency on top.
- For each entry, push `{value, count}`. If heap exceeds k, pop the smallest-frequency entry. After processing all, heap holds the top k.
- Extract the values (index 0) into the result array.

## Complexity

- Time: O(n log k) — n entries, each heap op O(log k).
- Space: O(n) — frequency map + heap.

Bucket sort alternative: O(n) time, O(n) space.

## Common Mistakes

- **Using a max-heap of all elements** — O(n log n). Works but slower than min-heap of size k.
- **Comparator overflow:** `a[1] - b[1]` can overflow for large counts. Use `Integer.compare(a[1], b[1])` for safety.
- **Forgetting that the heap stores `{value, count}` pairs** — extract `heap.poll()[0]` (the value), not the count.
- **k larger than distinct count** — problem guarantees k ≤ distinct count, but handle gracefully.

## How to Explain (interview)

**Opening:** Top K Frequent Elements asks for the k most common values. First count frequencies with a HashMap. Then use a min-heap of size k keyed by frequency: push each entry, and if the heap exceeds k, evict the smallest frequency. The heap ends up holding the top k. O(n log k) time. Alternatively, bucket sort by frequency gives O(n).

**The basic flow:**
```java
Map<Integer, Integer> freq = new HashMap<>();
for (int x : nums) freq.put(x, freq.getOrDefault(x, 0) + 1);
PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> a[1] - b[1]);
for (var e : freq.entrySet()) {
    heap.offer(new int[]{e.getKey(), e.getValue()});
    if (heap.size() > k) heap.poll();
}
```

**The part that trips everyone up:** the heap is a **min-heap by frequency** (smallest on top), so the smallest of the top-k gets evicted. Also extract `poll()[0]` (value), not `[1]` (count).

**The mistakes to remember:**
- Using max-heap of all elements (O(n log n)) instead of min-heap of size k (O(n log k))
- Comparator overflow with subtraction — use `Integer.compare`
- Extracting the count instead of the value
