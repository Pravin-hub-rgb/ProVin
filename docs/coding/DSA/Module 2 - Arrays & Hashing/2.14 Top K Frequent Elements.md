**Problem:** Given an integer array `nums` and an integer `k`, return the `k` most frequent elements. You may return the answer in **any order**.

**Link:** https://leetcode.com/problems/top-k-frequent-elements/

---

## What This Problem Is Asking (Simple Terms)

You have an array of numbers. You need to find the `k` numbers that appear most frequently in the array.

For example, if `nums = [1,1,1,2,2,3]` and `k = 2`, then `1` appears 3 times and `2` appears 2 times — these are the top 2 most frequent.

You are not asked to sort by frequency — just to return the `k` most frequent elements in any order.

---

## Example 1

**Input:** `nums = [1,1,1,2,2,3]`, `k = 2`

**Output:** `[1,2]`

**Explanation:** `1` appears 3 times, `2` appears 2 times, `3` appears 1 time. The top 2 most frequent are `1` and `2`.

---

## Example 2

**Input:** `nums = [1]`, `k = 1`

**Output:** `[1]`

---

## Constraints

- `1 <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`
- `k` is in the range `[1, the number of unique elements in the array]`.
- It is **guaranteed** that the answer is unique.

**Follow-up:** Your algorithm's time complexity must be better than O(n log n), where n is the array's size.

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could count how many times each number appears, then sort all numbers by frequency, and take the top `k`.

### Brute Force Pseudocode

```
freq = count frequencies of each number
sort all numbers by frequency (descending)
return first k numbers
```

### Why Brute Force Is Slower

Sorting all unique numbers takes O(u log u) where u is the number of unique elements. In the worst case u = n, so O(n log n). The follow-up asks for better than O(n log n).

---

## Which Data Structure/Technique, and Why?

You need two things:
1. **Count frequencies** → **HashMap** (value → count)
2. **Find the top k by frequency** → **Bucket sort** (array of lists)

Since all numbers in the array appear between 1 and `n` times, the count itself can be used as an index into a fixed-size array. This avoids sorting entirely.

**Signal in the problem:** "top k most frequent" → frequency map + bucket sort. **"k most/least"** → bucket sort or heap. Since we only have HashMap/ArrayList/array in this module, bucket sort is the right fit.

---

## Optimized Approach (Bucket Sort — Counting by Frequency)

1. Count frequencies with a HashMap (`number` → `count`)
2. Create an array of lists where index = frequency (box `i` holds all numbers that appear exactly `i` times)
3. Walk the boxes from the back (highest frequency) down to 1, collecting numbers until you have `k`

### Pseudocode

```
freq = count frequencies (HashMap)
buckets = array of empty lists, size n+1
for each (value, count) in freq:
    buckets[count].add(value)
result = []
for i from n down to 1:
    for each value in buckets[i]:
        result.add(value)
        if result.size == k: return result
return result
```

### Java Code

```java
class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        // Step 1: frequency map
        Map<Integer, Integer> freq = new HashMap<>();
        for (int x : nums) {
            freq.put(x, freq.getOrDefault(x, 0) + 1);
        }

        // Step 2: bucket sort — array of lists, index = frequency
        List<Integer>[] buckets = new List[nums.length + 1];
        for (int i = 0; i <= nums.length; i++) {
            buckets[i] = new ArrayList<>();
        }
        for (Map.Entry<Integer, Integer> e : freq.entrySet()) {
            buckets[e.getValue()].add(e.getKey());
        }

        // Step 3: walk buckets from back, collect top k
        int[] result = new int[k];
        int idx = 0;
        for (int i = nums.length; i > 0; i--) {
            for (int val : buckets[i]) {
                result[idx++] = val;
                if (idx == k) return result;
            }
        }
        return result;
    }
}
```

### Line-by-line

- `freq.put(x, freq.getOrDefault(x, 0) + 1)` — if `x` is new, `getOrDefault` returns 0, so we store 1. If it exists, we add 1.
- `buckets = new List[nums.length + 1]` — box `i` will hold numbers appearing `i` times. Box 0 stays unused.
- `buckets[e.getValue()].add(e.getKey())` — put the number into its frequency bucket.
- Walk `i` from `nums.length` down to 1: highest frequency first.
- For each value in the bucket, add to result. Stop when `idx == k`.

## Complexity

- Time: O(n) — count frequencies (O(n)), fill buckets (O(n)), collect top k (O(n)).
- Space: O(n) — frequency map + buckets.

## Common Mistakes

- **Forgetting to initialize each bucket** — `buckets[i] = new ArrayList<>()` for every `i`, otherwise `buckets[i].add(...)` throws NullPointerException.
- **Assuming `k` equals number of unique elements** — problem guarantees it, but the early return `if (idx == k) return result` handles it safely.
- **Using a HashMap for the bucket counts** — you don't need it; the frequency itself is the array index.

## How to Explain (interview)

**Opening:** Top K Frequent Elements asks for the `k` most common values. First count frequencies with a HashMap. Then use bucket sort: create an array where index `i` holds all numbers appearing `i` times. Walk the buckets from back to front, collecting numbers until you have `k`. O(n) time, O(n) space.

**The basic flow:**
```java
Map<Integer, Integer> freq = new HashMap<>();
for (int x : nums) freq.put(x, freq.getOrDefault(x, 0) + 1);

List<Integer>[] buckets = new List[nums.length + 1];
for (int i = 0; i <= nums.length; i++) buckets[i] = new ArrayList<>();
for (Map.Entry<Integer, Integer> e : freq.entrySet()) {
    buckets[e.getValue()].add(e.getKey());
}

int[] result = new int[k];
int idx = 0;
for (int i = nums.length; i > 0; i--) {
    for (int val : buckets[i]) {
        result[idx++] = val;
        if (idx == k) return result;
    }
}
return result;
```

**The part that trips everyone up:** `buckets` is an array of lists, not a map. Initialize each bucket before using it (`buckets[i] = new ArrayList<>()`). Also remember to walk backward from `n` to `1`, not forward.

**The mistakes to remember:**
- Using a PriorityQueue (not taught yet in this module) — bucket sort works instead.
- Forgetting to initialize each bucket before adding to it.
- Walking forward instead of backward (would give least frequent, not most).
