A HashSet stores unique values with O(1) average add, remove, and contains. It's essentially a HashMap with dummy values — use it for membership testing and deduplication.

## What Is a Set

Think of a Set as a collection of **unique items** — no duplicates allowed. Like your `products` table where `product_id` must be unique, or a Set of user emails where each email appears once. A Set answers one question fast: **"have I seen this value before?"**

This is different from a List or Array, where duplicates are allowed and order matters. A Set cares only about membership: is X in here or not?

## Why `Set` on Left, `HashSet` on Right

Look at this line:

```java
Set<Integer> seen = new HashSet<>();
```

There are two parts:

- **`Set` (left side)** — the **interface**. It defines what operations a Set must support: `add`, `remove`, `contains`, `size`, `isEmpty`. It's the contract.
- **`HashSet` (right side)** — the **implementation**. It's the actual class that stores data using hash-based buckets for O(1) average operations.

You declare as `Set` (interface) but instantiate as `HashSet` (concrete class). Good practice — if you later need a sorted set, change only the right side to `TreeSet`; the left side (`Set`) stays the same and all your code using `add`/`contains` keeps working.

## Declaration and Creation

```java
import java.util.HashSet;
import java.util.Set;

Set<Integer> seen = new HashSet<>();           // empty
Set<String> words = new HashSet<>(100);       // initial capacity
Set<Integer> copy = new HashSet<>(seen);       // copy
```

**Note:** Use the interface type `Set` on the left, `HashSet` on the right. Swap to `TreeSet` (sorted) or `LinkedHashSet` (insertion order) without changing code.

## Core Operations

```java
Set<Integer> set = new HashSet<>();

set.add(1);                    // true (added)
set.add(1);                    // false (duplicate, ignored)
System.out.println(set.contains(1)); // true — O(1)
System.out.println(set.size());      // 1

set.remove(1);                 // true (removed)
set.remove(99);                // false (not present)

set.clear();                   // remove all
System.out.println(set.isEmpty()); // true
```

- `add` returns `true` if the element was new, `false` if it was already present. Use this to detect duplicates in one line.
- `contains` is O(1) average — the main reason to use a set.

## Iteration

```java
Set<String> set = new HashSet<>(Arrays.asList("a", "b", "c"));
for (String s : set) {
    System.out.println(s);     // order NOT guaranteed
}

set.forEach(s -> System.out.println(s));
```

**Note:** iteration order is not guaranteed. Use `LinkedHashSet` for insertion order, `TreeSet` for sorted order.

## Set Operations

```java
Set<Integer> a = new HashSet<>(Arrays.asList(1, 2, 3));
Set<Integer> b = new HashSet<>(Arrays.asList(2, 3, 4));

// Union
Set<Integer> union = new HashSet<>(a);
union.addAll(b);               // {1, 2, 3, 4}

// Intersection
Set<Integer> inter = new HashSet<>(a);
inter.retainAll(b);            // {2, 3}

// Difference (a - b)
Set<Integer> diff = new HashSet<>(a);
diff.removeAll(b);             // {1}
```

## Cost (Big-O)

| Operation | Average | Worst |
|---|---|---|
| `add`, `remove`, `contains` | O(1) | O(n) |
| `size`, `isEmpty` | O(1) | O(1) |
| Iteration | O(n) | O(n) |

Same as HashMap — HashSet is backed by a HashMap internally.

## When to Use

- Membership testing: "have I seen this value before?"
- Deduplication: remove duplicates from a collection.
- Finding unique elements.
- Tracking visited nodes in graph traversal.

## Common Pitfalls

- **Assuming order.** HashSet has no order. If you need sorted, use TreeSet; insertion order, use LinkedHashSet.
- **Using mutable objects as elements.** Same issue as HashMap keys — if `hashCode` changes after insertion, the element is lost. Use immutable elements.
- **`add` return value ignored.** `set.add(x)` returns true only if x was new — useful for detecting duplicates: `if (!set.add(x)) { /* duplicate */ }`.
- **Null elements:** HashSet allows one null. `TreeSet` does not (can't compare null).

## A Small Program: Remove Duplicates

```java
import java.util.*;

public class RemoveDuplicates {
    static int[] removeDups(int[] arr) {
        Set<Integer> seen = new HashSet<>();
        List<Integer> result = new ArrayList<>();
        for (int x : arr) {
            if (seen.add(x)) {          // true only if new
                result.add(x);
            }
        }
        return result.stream().mapToInt(i -> i).toArray();
    }

    public static void main(String[] args) {
        int[] arr = {1, 2, 2, 3, 3, 3, 4};
        System.out.println(Arrays.toString(removeDups(arr))); // [1, 2, 3, 4]
    }
}
```

## In Your Own Words

1. What is the relationship between HashSet and HashMap?

<details>
<summary>Show Answer</summary>

**Sample Answer:** HashSet is backed by a HashMap internally — it stores elements as keys with a dummy constant value. So HashSet has the same O(1) average operations and the same hashing behavior as HashMap. The difference is API: HashSet has no values, only membership. Use HashSet for "have I seen this?" and deduplication; HashMap when you need key → value mapping.

</details>

2. How do you detect duplicates in one pass using a HashSet?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `set.add(x)` returns `true` if x was new, `false` if already present. So: `if (!set.add(x)) { /* x is a duplicate */ }`. This detects duplicates in O(n) time and O(n) space in a single pass — no nested loops.

</details>

3. Why does HashSet not guarantee iteration order?

<details>
<summary>Show Answer</summary>

**Sample Answer:** HashSet is backed by a hash table — elements are placed in buckets by hashCode, and iteration follows bucket order, which appears random. Use `LinkedHashSet` to preserve insertion order, or `TreeSet` for sorted order. Both have slightly higher overhead but predictable iteration.

</details>
