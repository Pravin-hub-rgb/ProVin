An ArrayList is a resizable array. It gives you the same O(1) index access as an array, but grows automatically when you add elements. Use it when you don't know the size upfront.

---

## Declaration and Creation

```java
import java.util.ArrayList;
import java.util.List;

List<Integer> nums = new ArrayList<>();     // empty, type inferred
List<String> names = new ArrayList<>(10);   // initial capacity 10 (still size 0)
List<Integer> copy = new ArrayList<>(nums); // copy of another list
```

**Note:** Use the interface type `List` on the left and `ArrayList` on the right. This lets you swap implementations later without changing code.

## Adding Elements

```java
List<Integer> list = new ArrayList<>();
list.add(10);              // append → [10]
list.add(20);              // append → [10, 20]
list.add(1, 15);           // insert at index 1 → [10, 15, 20]
list.addAll(Arrays.asList(30, 40)); // append multiple
```

- `add(value)` appends at the end: O(1) amortized.
- `add(index, value)` inserts at a position: O(n) (shifts elements).

## Accessing and Modifying

```java
List<Integer> list = new ArrayList<>(Arrays.asList(10, 20, 30));

System.out.println(list.get(0));       // 10
System.out.println(list.size());       // 3 (method, with parens)
list.set(1, 99);                      // replace index 1 → [10, 99, 30]
System.out.println(list.contains(99)); // true
System.out.println(list.indexOf(30));  // 2
```

- `get(i)` is O(1). `set(i, val)` is O(1).
- `size()` is a method (with parens) — unlike array's `length` field.

## Removing Elements

```java
List<Integer> list = new ArrayList<>(Arrays.asList(10, 20, 30, 40));

list.remove(1);            // remove by index → [10, 30, 40]  (O(n))
list.remove(Integer.valueOf(30)); // remove by value → [10, 40]  (O(n))

list.clear();              // remove all → []
```

**Pitfall:** `remove(int index)` vs `remove(Object)`. Passing an `int` removes by index; passing an `Integer` object removes by value. `list.remove(1)` removes index 1, not the value 1. To remove value 1, use `list.remove(Integer.valueOf(1))`.

## Traversing

```java
List<Integer> list = new ArrayList<>(Arrays.asList(10, 20, 30));

for (int i = 0; i < list.size(); i++) {
    System.out.println(list.get(i));
}

for (int x : list) {
    System.out.println(x);
}

// Java 8+ lambda
list.forEach(x -> System.out.println(x));
```

## Cost (Big-O)

| Operation | Time |
|---|---|
| `get(i)`, `set(i, val)` | O(1) |
| `add` (append) | O(1) amortized |
| `add(i, val)` (insert) | O(n) |
| `remove(i)` or `remove(value)` | O(n) |
| `contains`, `indexOf` | O(n) |
| `size()` | O(1) |

## When to Use

- Size unknown at creation time.
- Frequent appends.
- Need `List` interface for APIs (LeetCode returning `List<Integer>`).

Use a plain `int[]` when size is known and you want maximum speed / minimal memory.

## Common Pitfalls

- **`remove(int)` vs `remove(Object)`:** `list.remove(2)` removes index 2; `list.remove(Integer.valueOf(2))` removes the value 2. Silent bugs.
- **Modifying while iterating:** throws `ConcurrentModificationException`. Iterate backwards or use an iterator with `remove()`.
- **`size()` vs `length`:** ArrayList uses `size()` (method); arrays use `length` (field).
- **Autoboxing cost:** `List<Integer>` boxes each int into an Integer object. For huge lists, `int[]` is faster and uses less memory.

## A Small Program: Filter Even Numbers

```java
import java.util.*;

public class FilterEvens {
    static List<Integer> getEvens(int[] arr) {
        List<Integer> result = new ArrayList<>();
        for (int x : arr) {
            if (x % 2 == 0) result.add(x);
        }
        return result;
    }

    public static void main(String[] args) {
        int[] arr = {1, 2, 3, 4, 5, 6};
        System.out.println(getEvens(arr));  // [2, 4, 6]
    }
}
```

## In Your Own Words

1. When should you use ArrayList instead of a plain array?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use ArrayList when the number of elements is unknown at creation time or changes dynamically (appends/removals). Use a plain array when size is fixed and you want maximum speed and minimal memory (no boxing, no capacity overhead). LeetCode often requires returning `List<Integer>` — use ArrayList for that.

</details>

2. What's the gotcha with `list.remove(2)`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `remove(int index)` removes by index, not by value. `list.remove(2)` removes the element at index 2. To remove the value 2, use `list.remove(Integer.valueOf(2))` so Java picks the `remove(Object)` overload. This ambiguity causes silent bugs.

</details>

3. Why is `get(i)` O(1) but `remove(i)` O(n) in ArrayList?

<details>
<summary>Show Answer</summary>

**Sample Answer:** ArrayList is backed by an array. `get(i)` is direct index access — O(1). `remove(i)` deletes an element and shifts all elements after it one position left — O(n) in the worst case. Appending is O(1) amortized (occasional resize copies, but averaged out).

</details>
