**Problem:** A **permutation** of an array of integers is an arrangement of its members into a sequence or linear order.

For example, for `arr = [1,2,3]`, the following are considered permutations of `arr`: `[1,2,3]`, `[1,3,2]`, `[3,1,2]`, `[2,3,1]`.

The **next permutation** of an array of integers is the next lexicographically greater permutation of its integer. More formally, if all the permutations of the array are sorted in one container according to their lexicographical order, then the next permutation of that array is the permutation that follows it in the sorted container. If such an arrangement is not possible, the array must be rearranged as the lowest possible order (i.e., sorted in ascending order).

For example, the next permutation of `arr = [1,2,3]` is `[1,3,2]`.
Similarly, the next permutation of `arr = [2,3,1]` is `[3,1,2]`.
While the next permutation of `arr = [3,2,1]` is `[1,2,3]` because `[3,2,1]` does not have a lexicographically larger rearrangement.

Given an array of integers `nums`, find the next permutation of `nums`.

The replacement must be **in place** and use only constant extra memory.

**Link:** https://leetcode.com/problems/next-permutation/

---

## Example 1

**Input:** `nums = [1,2,3]`

**Output:** `[1,3,2]`

**Explanation:** `[1,3,2]` is the next lexicographically greater permutation after `[1,2,3]`.

---

## Example 2

**Input:** `nums = [3,2,1]`

**Output:** `[1,2,3]`

**Explanation:** `[3,2,1]` is the last permutation. The next permutation wraps around to the smallest (`[1,2,3]`).

---

## Example 3

**Input:** `nums = [1,1,5]`

**Output:** `[1,5,1]`

---

## Constraints

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 100`

**Follow-up:** Could you implement it in O(n) time and O(1) extra space?

---

## Which Technique, and Why?

"Next permutation in place" → **Find pivot + swap + reverse**. Three steps: (1) find the first index `i` from the right where `nums[i] < nums[i+1]` (the pivot). (2) Find the smallest element to the right of `i` that is greater than `nums[i]`, swap. (3) Reverse the suffix after `i`. O(n) time, O(1) space.

**Signal in the problem:** "next permutation" / "next lexicographically greater" / "in place" → find pivot → swap → reverse suffix.

## Approach

1. Find `i` from the right where `nums[i] < nums[i+1]`. If none, the array is the last permutation → reverse the whole array.
2. Find `j` from the right where `nums[j] > nums[i]` (smallest such).
3. Swap `nums[i]` and `nums[j]`.
4. Reverse `nums[i+1..n-1]`.

## Pseudocode

```
// Step 1: find pivot
i = n - 2
while i >= 0 and nums[i] >= nums[i+1]: i--
if i >= 0:
    // Step 2: find successor
    j = n - 1
    while nums[j] <= nums[i]: j--
    // Step 3: swap
    swap(nums[i], nums[j])
// Step 4: reverse suffix
reverse(nums, i + 1, n - 1)
```

## Java Code

```java
class Solution {
    public void nextPermutation(int[] nums) {
        int n = nums.length;

        // Step 1: find pivot (first decrease from right)
        int i = n - 2;
        while (i >= 0 && nums[i] >= nums[i + 1]) i--;

        if (i >= 0) {
            // Step 2: find smallest element to the right that's > nums[i]
            int j = n - 1;
            while (nums[j] <= nums[i]) j--;
            // Step 3: swap
            int temp = nums[i];
            nums[i] = nums[j];
            nums[j] = temp;
        }

        // Step 4: reverse suffix (or whole array if no pivot)
        int left = i + 1, right = n - 1;
        while (left < right) {
            int temp = nums[left];
            nums[left] = nums[right];
            nums[right] = temp;
            left++;
            right--;
        }
    }
}
```

## Line-by-line

- Step 1: scan from right to find the first "descent" (`nums[i] < nums[i+1]`). If none, the array is in descending order (last permutation).
- Step 2: find the smallest element to the right of `i` that's greater than `nums[i]` (scan from right).
- Step 3: swap them.
- Step 4: reverse the suffix after `i` — this turns the descending suffix into ascending (smallest next permutation).

## Complexity

- Time: O(n) — three linear scans.
- Space: O(1) — in place.

## Common Mistakes

- **Using `>` instead of `>=` in Step 1.** Use `>=` to skip equal elements (handles duplicates). `nums[i] >= nums[i+1]` skips equal and descending.
- **Using `<=` instead of `<` in Step 2.** `nums[j] <= nums[i]` skips elements ≤ nums[i]. You want the first (from right) that's strictly greater.
- **Not reversing the suffix.** After the swap, the suffix is still in descending order. Reverse it to get the smallest suffix (next permutation).
- **Not handling the last permutation.** If no pivot found (i < 0), reverse the whole array (i+1 = 0, so the reverse covers everything).

## How to Explain (interview)

**Opening:** Next Permutation finds the next lexicographically greater arrangement in O(n) time, O(1) space. Three steps: (1) find the pivot (first decrease from right), (2) find and swap with the smallest larger element to the right, (3) reverse the suffix. If no pivot exists, reverse the whole array (wrap to smallest).

**The basic flow:**
```java
int i = n - 2;
while (i >= 0 && nums[i] >= nums[i + 1]) i--;  // find pivot
if (i >= 0) {
    int j = n - 1;
    while (nums[j] <= nums[i]) j--;  // find successor
    swap(nums, i, j);
}
reverse(nums, i + 1, n - 1);  // reverse suffix
```

**The part that trips everyone up:** the comparison operators. Step 1 uses `>=` (skip equal and descending). Step 2 uses `<=` (skip ≤ pivot). Step 4 reverses the suffix (not the whole array, unless no pivot).

**The mistakes to remember:**
- Using `>` instead of `>=` in Step 1 (wrong pivot with duplicates)
- Using `<` instead of `<=` in Step 2 (wrong successor)
- Forgetting to reverse the suffix
- Not handling the last permutation (no pivot → reverse whole array)
