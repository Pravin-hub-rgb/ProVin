**Problem:** Given an array `nums` with `n` objects colored red, white, or blue, sort them **in-place** so that objects of the same color are adjacent, with the colors in the order red, white, and blue.

We will use the integers `0`, `1`, and `2` to represent the color red, white, and blue, respectively.

You must solve this problem without using the library's sort function.

**Link:** https://leetcode.com/problems/sort-colors/

---

## What This Problem Is Asking (Simple Terms)

You have an array containing only `0`s, `1`s, and `2`s. You need to sort it in-place so that all `0`s come first, then all `1`s, then all `2`s.

For example, if `nums = [2,0,2,1,1,0]`, after sorting it becomes `[0,0,1,1,2,2]`.

You cannot use `Arrays.sort()` — you need an O(n) solution.

---

## Example 1

**Input:** `nums = [2,0,2,1,1,0]`

**Output:** `[0,0,1,1,2,2]`

**Explanation:** All 0s come first, then 1s, then 2s.

---

## Example 2

**Input:** `nums = [2,0,1]`

**Output:** `[0,1,2]`

---

## Constraints

- `n == nums.length`
- `1 <= n <= 300`
- `nums[i]` is either `0`, `1`, or `2`.

**Follow-up:** Could you come up with a one-pass algorithm using only constant extra space?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could count how many `0`s, `1`s, and `2`s there are, then overwrite the array: first all `0`s, then all `1`s, then all `2`s.

### Brute Force Pseudocode

```
count0 = 0, count1 = 0, count2 = 0
for each x in nums:
    if x == 0: count0++
    else if x == 1: count1++
    else: count2++
i = 0
while count0 > 0: nums[i++] = 0; count0--
while count1 > 0: nums[i++] = 1; count1--
while count2 > 0: nums[i++] = 2; count2--
```

### Why Brute Force Is Not Optimal

Counting sort is O(n) time and O(1) space (fixed 3 counters), which is already good. But it makes **two passes** over the array (one to count, one to overwrite). The Dutch National Flag algorithm does it in **one pass**.

---

## Which Data Structure, and Why?

`Arrays.sort()` is O(n log n) — works but slower. Since we only have 3 distinct values, we can do O(n).

**Signal in the problem:** "sort 0s, 1s, 2s in place" / "only 3 distinct values" → counting sort or Dutch National Flag.

---

## Optimized Approach (Dutch National Flag — One Pass)

Three pointers: `low` (boundary of 0s), `mid` (current), `high` (boundary of 2s). Invariant: everything before `low` is `0`, between `low` and `mid` is `1`, after `high` is `2`.

- `nums[mid] == 0` → swap with `low`, advance both `low` and `mid`.
- `nums[mid] == 1` → just advance `mid`.
- `nums[mid] == 2` → swap with `high`, decrement `high` (don't advance `mid` — the swapped-in value is unexamined).

### Pseudocode (Dutch National Flag)

```
low = 0, mid = 0, high = n - 1
while mid <= high:
    if nums[mid] == 0:
        swap(nums[low], nums[mid])
        low++; mid++
    else if nums[mid] == 1:
        mid++
    else: // nums[mid] == 2
        swap(nums[mid], nums[high])
        high--
```

### Java Code (Counting Sort)

```java
class Solution {
    public void sortColors(int[] nums) {
        int count0 = 0, count1 = 0, count2 = 0;
        for (int x : nums) {
            if (x == 0) count0++;
            else if (x == 1) count1++;
            else count2++;
        }
        int i = 0;
        while (count0-- > 0) nums[i++] = 0;
        while (count1-- > 0) nums[i++] = 1;
        while (count2-- > 0) nums[i++] = 2;
    }
}
```

### Java Code (Dutch National Flag)

```java
class Solution {
    public void sortColors(int[] nums) {
        int low = 0, mid = 0, high = nums.length - 1;
        while (mid <= high) {
            if (nums[mid] == 0) {
                swap(nums, low, mid);
                low++; mid++;
            } else if (nums[mid] == 1) {
                mid++;
            } else {
                swap(nums, mid, high);
                high--;
            }
        }
    }

    private void swap(int[] a, int i, int j) {
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }
}
```

## Complexity

- Counting sort: O(n) time, O(1) space (two passes).
- Dutch National Flag: O(n) time, O(1) space (single pass, fewer writes).

## Common Mistakes

- **Using `Arrays.sort`** — O(n log n), slower than O(n). Works but not optimal.
- **Dutch National Flag: advancing `mid` after swapping with `high`.** Don't — the swapped-in value (from `high`) is unexamined. Only advance `mid` on `0` or `1`.
- **Off-by-one in the while condition:** `mid <= high` (not `<`). When `mid == high`, that element still needs processing.
- **Assuming the array has only 0/1/2.** If other values exist, counting sort with 3 buckets breaks. Check constraints.

## How to Explain (interview)

**Opening:** Sort Colors sorts an array of 0s, 1s, and 2s in place. Counting sort is simplest: count 0s, 1s, 2s, then overwrite. O(n) time, O(1) space. The Dutch National Flag algorithm does it in one pass with three pointers (low, mid, high) maintaining the invariant: 0s before `low`, 1s between `low` and `mid`, 2s after `high`.

**The basic flow (Dutch National Flag):**
```java
int low = 0, mid = 0, high = nums.length - 1;
while (mid <= high) {
    if (nums[mid] == 0) { swap(nums, low, mid); low++; mid++; }
    else if (nums[mid] == 1) { mid++; }
    else { swap(nums, mid, high); high--; }
}
```

**The part that trips everyone up:** when swapping `mid` with `high`, do **not** advance `mid` — the value swapped in from `high` is unexamined. Also the while condition is `mid <= high`, not `mid < high`.

**The mistakes to remember:**
- Advancing `mid` after swapping with `high` (skips elements)
- Using `Arrays.sort` (O(n log n)) when O(n) is expected
- Forgetting the array is modified in place (void return)
