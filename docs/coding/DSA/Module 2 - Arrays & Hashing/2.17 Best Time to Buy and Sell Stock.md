**Problem:** Given daily prices, find the maximum profit from one buy and one sell (buy before sell). Return 0 if no profit possible. (LeetCode #121)

**Link:** https://leetcode.com/problems/best-time-to-buy-and-sell-stock/

---

## Which Data Structure, and Why?

You need the maximum of `prices[j] - prices[i]` with `i < j`. The naive approach checks all pairs → O(n²). The optimized approach: track the **minimum price seen so far** as you walk left to right; at each day, compute profit = current price − min so far, and track the max profit.

No complex data structure needed — just two variables (`minPrice`, `maxProfit`). But the *pattern* is "track a running minimum" (a form of prefix tracking). If the problem allowed multiple transactions, you'd need a different approach (DP).

**Signal in the problem:** "max profit, one buy one sell, buy before sell" → track min so far, compute profit at each step. "Multiple transactions" → different problem (greedy/DP).

## Approach

**Brute force (O(n²)):** for each buy day i, for each sell day j > i, compute profit, track max.

**Optimized (O(n)):** one pass. Maintain `minPrice` (lowest price seen so far) and `maxProfit`. For each price: update `minPrice = min(minPrice, price)`; then `maxProfit = max(maxProfit, price - minPrice)`.

## Pseudocode

```
minPrice = infinity
maxProfit = 0
for each price in prices:
    minPrice = min(minPrice, price)
    maxProfit = max(maxProfit, price - minPrice)
return maxProfit
```

## Java Code

```java
class Solution {
    public int maxProfit(int[] prices) {
        int minPrice = Integer.MAX_VALUE;
        int maxProfit = 0;

        for (int price : prices) {
            minPrice = Math.min(minPrice, price);
            maxProfit = Math.max(maxProfit, price - minPrice);
        }
        return maxProfit;
    }
}
```

## Line-by-line

- `minPrice` starts at infinity — the first price becomes the min.
- For each price: first update `minPrice` (so buying "today" is allowed only if it's the new min — but since we compute profit after, buying and selling on the same day gives 0 profit, which is fine).
- `price - minPrice` is the profit if we sell today (having bought at the lowest so far).
- `maxProfit` tracks the best profit seen. If all prices decrease, `maxProfit` stays 0 (no profitable trade).

**Order matters:** update `minPrice` before computing profit, so you can "buy" at today's price and sell at today's price (0 profit, harmless) rather than using yesterday's min against today's price incorrectly. Actually both orders work here because selling on the same day you buy gives 0, which never beats a positive profit. But updating min first is the standard form.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — two variables.

## Common Mistakes

- **Selling before buying** — must ensure buy index < sell index. The "min so far" approach guarantees this because min is always from an earlier day.
- **Returning negative profit** — if prices only decrease, return 0 (no trade). Initialize `maxProfit = 0`, not `Integer.MIN_VALUE`.
- **Confusing with "Best Time to Buy and Sell Stock II"** (multiple transactions) — that's a different problem (greedy: sum all positive differences).
- **Off-by-one / empty array:** if `prices` is empty or has one element, the loop handles it (maxProfit stays 0).

## How to Explain (interview)

**Opening:** Best Time to Buy and Sell Stock asks for max profit from one buy and one sell, buy before sell. The brute force checks all pairs — O(n²). The optimized version walks the array once, tracking the minimum price seen so far. At each day, profit = today's price − min so far; track the max. O(n) time, O(1) space. If prices only decrease, return 0.

**The basic flow:**
```java
int minPrice = Integer.MAX_VALUE, maxProfit = 0;
for (int price : prices) {
    minPrice = Math.min(minPrice, price);
    maxProfit = Math.max(maxProfit, price - minPrice);
}
return maxProfit;
```

**The part that trips everyone up:** buy must come before sell — the "min so far" guarantees this. Also return 0 (not negative) when no profitable trade exists.

**The mistakes to remember:**
- Selling before buying (violates constraint)
- Returning negative profit instead of 0
- Confusing with Stock II (multiple transactions) — different problem
