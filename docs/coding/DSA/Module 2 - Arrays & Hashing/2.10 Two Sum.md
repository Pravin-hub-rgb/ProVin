**Problem:** Given an array of integers `nums` and a target, return indices of two numbers that add up to target. Exactly one solution exists. (LeetCode #1)

**Link:** https://leetcode.com/problems/two-sum/

---

## Which Data Structure, and Why?

You need to find, for each element, whether its **complement** (`target - nums[i]`) has appeared before. That's a lookup: "have I seen value X?" → O(1) lookup → **HashMap** (value → index).

Why not a set? A set only stores membership. Here we need the **index** of the complement, so we map value → index. Hence HashMap, not HashSet.

**Signal in the problem:** "find two numbers that sum to target" + "return indices" → you need to remember where each value was → HashMap.

## Approach

**Brute force (O(n²)):** check every pair (i, j). Correct but slow.

**Optimized (O(n)):** one pass. For each element, compute complement. If complement is in the map, return indices. Otherwise, store current value → index.

## Pseudocode

```
seen = empty map (value -> index)
for i from 0 to n-1:
    complement = target - nums[i]
    if seen contains complement:
        return [seen[complement], i]
    seen[nums[i]] = i
return []
```

## Java Code

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>(); // value → index

        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];
            if (seen.containsKey(complement)) {
                return new int[]{seen.get(complement), i};
            }
            seen.put(nums[i], i);
        }
        return new int[]{};
    }
}
```

## Line-by-line

- `seen` maps a value to the index where it appeared.
- For each element, `complement = target - nums[i]` is the value we need.
- `seen.containsKey(complement)` — O(1) check. If true, we found the pair.
- `seen.get(complement)` gives the earlier index; `i` is the current index.
- `seen.put(nums[i], i)` records current value for future complements.
- Return `new int[]{a, b}` — array literal. If no solution (shouldn't happen per problem), return empty.

## Complexity

- Time: O(n) — single pass, O(1) map ops.
- Space: O(n) — map stores up to n entries.

## Common Mistakes

- Returning **values** instead of **indices**.
- Assuming the array is sorted (that's Two Sum II).
- Using `==` for comparison (not relevant here, but habit).
- Forgetting that `get` returns null — use `containsKey` first.

## How to Explain (interview)

**Opening:** Two Sum asks for two indices whose values sum to a target. The brute force checks every pair in O(n²). The optimized version walks the array once, using a HashMap to remember each value's index. For each element, compute the complement (target minus current value) and check if it's already in the map — if yes, return both indices; if no, record the current value and move on. O(n) time, O(n) space.

**The basic flow:**
```java
Map<Integer, Integer> seen = new HashMap<>();
for (int i = 0; i < nums.length; i++) {
    int complement = target - nums[i];
    if (seen.containsKey(complement)) return new int[]{seen.get(complement), i};
    seen.put(nums[i], i);
}
```

**The part that trips everyone up:** the problem wants **indices**, not the values themselves. Also the input is **not sorted** — don't try binary search.

**The mistakes to remember:**
- Returning values instead of indices
- Assuming the array is sorted
- Forgetting the null check on `get` (use `containsKey`)
