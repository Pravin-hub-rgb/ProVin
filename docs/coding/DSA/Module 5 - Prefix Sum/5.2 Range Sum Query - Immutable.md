**Problem:** Given an integer array `nums`, handle multiple queries of the following type: calculate the sum of the elements of `nums` between indices `left` and `right` **inclusive** where `left <= right`.

Implement the `NumArray` class:
- `NumArray(int[] nums)` Initializes the object with the integer array `nums`.
- `int sumRange(int left, int right)` Returns the sum of the elements of `nums` between indices `left` and `right` inclusive (i.e. `nums[left] + nums[left + 1] + ... + nums[right]`).

**Link:** https://leetcode.com/problems/range-sum-query-immutable/

---

## What This Problem Is Asking (Simple Terms)

You are given an array **once**. Then someone asks you many times: **"What is the sum from index `left` to index `right`?**" 

For example, `nums = [-2, 0, 3, -5, 2, -1]`:

- `sumRange(0, 2)` → `(-2) + 0 + 3 = 1`
- `sumRange(2, 5)` → `3 + (-5) + 2 + (-1) = -1`
- `sumRange(0, 5)` → `(-2) + 0 + 3 + (-5) + 2 + (-1) = -3`

You get the array **once** in the constructor, then answer many queries on it.

## Example 1

**Input:**
```
["NumArray", "sumRange", "sumRange", "sumRange"]
[[[-2,0,3,-5,2,-1]], [0,2], [2,5], [0,5]]
```

**Output:**
```
[null, 1, -1, -3]
```

**Explanation:**
- `NumArray([-2, 0, 3, -5, 2, -1])` → constructor, returns `null`
- `sumRange(0, 2)` → `(-2) + 0 + 3 = 1`
- `sumRange(2, 5)` → `3 + (-5) + 2 + (-1) = -1`
- `sumRange(0, 5)` → `(-2) + 0 + 3 + (-5) + 2 + (-1) = -3`

---

## Constraints

- `1 <= nums.length <= 10^4`
- `-10^5 <= nums[i] <= 10^5`
- `0 <= left <= right < nums.length`
- At most `10^4` calls will be made to `sumRange`.

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

For each query, loop from `left` to `right` and add up the elements.

### Brute Force Pseudocode

```
sumRange(left, right):
    sum = 0
    for i from left to right:
        sum += nums[i]
    return sum
```

### Why Brute Force Is Slow

Each query takes O(k) time where `k = right - left + 1` (the length of the range). In the worst case, that's O(n) per query. With up to `10^4` queries and `10^4` elements, that's up to `10^8` operations — too slow.

---

## Which Data Structure/Technique, and Why?

The constructor gets called **once** with the array. Then `sumRange` gets called **many times** with different `left` and `right` values.

**Prefix Sum** precomputes a running total array once in the constructor. Each query then becomes **one subtraction**:

```
sum(i..j) = prefix[j+1] - prefix[i]
```

**Signal in the problem:** "multiple queries" + "range sum" + "immutable array" → **Prefix Sum**.

**Why Prefix Sum?** Because you pay O(n) once in the constructor to build prefix sums, then every query is O(1) — just one subtraction. With up to `10^4` queries, O(1) per query is essential.

**Prefix Sum vs Sliding Window:** Sliding window works when all numbers are positive (you grow/shrink one window). Prefix Sum works with **negative** numbers too, and handles **many queries** on the same array.

---

## Optimized Approach (Prefix Sum Array)

Build a `prefix` array where `prefix[i]` = sum of the first `i` elements (indices `0` to `i-1`). `prefix[0] = 0` (sum of zero elements).

Then:
- `sumRange(left, right)` = `prefix[right + 1] - prefix[left]`

**Why `right + 1`?** Because `prefix[right + 1]` = sum of first `right + 1` elements (indices `0` to `right`), and `prefix[left]` = sum of first `left` elements (indices `0` to `left - 1`). Subtracting gives sum from index `left` to `right` inclusive.

### Pseudocode

```
constructor(nums):
    n = nums.length
    prefix = new int[n + 1]
    prefix[0] = 0
    for i from 0 to n-1:
        prefix[i + 1] = prefix[i] + nums[i]

sumRange(left, right):
    return prefix[right + 1] - prefix[left]
```

### Java Code

```java
class NumArray {
    private int[] prefix;

    public NumArray(int[] nums) {
        int n = nums.length;
        prefix = new int[n + 1];
        prefix[0] = 0;
        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + nums[i];
        }
    }

    public int sumRange(int left, int right) {
        return prefix[right + 1] - prefix[left];
    }
}
```

### Line-by-line

- `int[] prefix` — declares the prefix array at class level so both constructor and `sumRange` can see it.
- `prefix = new int[n + 1]` — one extra slot because `prefix[0] = 0` (sum of zero elements), and we need space for `prefix[n]`.
- `prefix[0] = 0` — sum of zero elements is 0.
- `prefix[i + 1] = prefix[i] + nums[i]` — running total: sum of first `i+1` elements = sum of first `i` elements + `nums[i]`.
- `prefix[right + 1] - prefix[left]`:
  - `prefix[right + 1]` = sum of first `right + 1` elements (indices `0` to `right`)
  - `prefix[left]` = sum of first `left` elements (indices `0` to `left - 1`)
  - Difference = sum of elements from index `left` to `right` inclusive.

## Complexity

- **Constructor:** O(n) time — single pass to build prefix array. O(n) space.
- **sumRange:** O(1) time — one subtraction. O(1) space.

## Common Mistakes

- **Off-by-one:** using `prefix[right] - prefix[left]` instead of `prefix[right + 1] - prefix[left]`. The `+1` accounts for `prefix[0] = 0` being the sum of zero elements.
- **Modifying `nums` after construction** — the prefix array was built from the original values. If `nums` changes, `prefix` becomes stale.

## How to Explain (interview)

**Opening:** Range Sum Query - Immutable asks for the sum of elements between `left` and `right`, queried many times on the same array. Precompute a prefix array: `prefix[i]` = sum of first `i` elements. Then `sumRange(left, right)` = `prefix[right + 1] - prefix[left]` — one subtraction, O(1) per query after O(n) preprocessing.

**The basic flow:**
```java
prefix[0] = 0;
for (int i = 0; i < n; i++) {
    prefix[i + 1] = prefix[i] + nums[i];
}
// query:
return prefix[right + 1] - prefix[left];
```

**The part that trips everyone up:** `prefix[i]` = sum of the **first `i` elements** (indices `0` to `i-1`), **not** sum up to index `i`. So `prefix[right + 1] - prefix[left]` gives sum from index `left` to `right` inclusive.

**The mistakes to remember:**
- Using `prefix[right]` instead of `prefix[right + 1]`
- Forgetting `prefix[0] = 0`
- Thinking you need a HashMap — you don't; an array is perfect because the keys (indices) are just `0, 1, 2, ...`
