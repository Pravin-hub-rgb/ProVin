**Problem:** Given an integer array `nums`, find the **pivot index** — the index where the sum of all numbers **strictly to the left** equals the sum of all numbers **strictly to the right**. Return the **leftmost** such index, or `-1` if none exists.

**Link:** https://leetcode.com/problems/find-pivot-index/

---

## What This Problem Is Asking (Simple Terms)

You have an array of integers. You need to find a position where everything to its left adds up to exactly the same sum as everything to its right — **not counting the pivot element itself**.

For example, `nums = [1, 7, 3, 6, 5, 6]`. At index `3`, the number is `6`. To its left: `1 + 7 + 3 = 11`. To its right: `5 + 6 = 11`. They match! So index `3` is the pivot index.

You return the **first** index where this happens, or `-1` if none exists.

---

## Example 1

**Input:** `nums = [1, 7, 3, 6, 5, 6]`

**Output:** `3`

**Explanation:** Index `3` holds `6`. Left side: `1 + 7 + 3 = 11`. Right side: `5 + 6 = 11`. They match, so index `3` is the pivot index.

---

## Example 2

**Input:** `nums = [1, 2, 3]`

**Output:** `-1`

**Explanation:** No index satisfies the condition.

---

## Example 3

**Input:** `nums = [2, 1, -1]`

**Output:** `0`

**Explanation:** Index `0` holds `2`. Nothing is to its left, so left sum is `0`. To its right: `1 + (-1) = 0`. They match, so index `0` is the pivot index.

---

## Constraints

- `1 <= nums.length <= 10^4`
- `-10^5 <= nums[i] <= 10^5`

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

For each index `i`, walk left and sum everything before it. Then walk right and sum everything after it. Compare. If they match, return `i`. Otherwise, move to the next index and try again.

### Brute Force Pseudocode

```
for i from 0 to n-1:
    leftSum = 0
    for j from 0 to i-1:
        leftSum += nums[j]
    rightSum = 0
    for j from i+1 to n-1:
        rightSum += nums[j]
    if leftSum == rightSum:
        return i
return -1
```

### Why Brute Force Is Slow

Outer loop runs `n` times. Each iteration scans up to `n` elements on both sides. O(n²) — too slow for `n = 10^4`.

---

## Which Data Structure/Technique, and Why?

We repeatedly need two things at each index `i`:
1. Sum of everything to the **left** of `i`
2. Sum of everything to the **right** of `i`

Computing these fresh each time wastes work. But notice: if we know the **total sum** of the whole array, then:

```
rightSum = total - leftSum - nums[i]
```

So we only need to track one running value: the **left sum** as we walk from left to right. Everything else falls out of subtraction.

This is the **prefix sum** idea in disguise — but even simpler: we only need one running total, not a whole array of them.

**Signal in the problem:** "sum to the left" / "sum to the right" / "pivot index" → Prefix Sum.

---

## Optimized Approach (Prefix Sum — Single Pass)

1. Compute `total` = sum of the entire array.
2. Walk left to right with `leftSum` starting at `0`.
3. At each index `i`:
   - `rightSum = total - leftSum - nums[i]` (everything except left part and current element)
   - If `leftSum == rightSum`, return `i` immediately (first match = leftmost).
   - Otherwise, `leftSum += nums[i]` and continue.
4. If loop finishes without a match, return `-1`.

### Pseudocode

```
total = sum of all elements
leftSum = 0
for i from 0 to n-1:
    rightSum = total - leftSum - nums[i]
    if leftSum == rightSum: return i
    leftSum += nums[i]
return -1
```

### Java Code

```java
class Solution {
    public int pivotIndex(int[] nums) {
        int total = 0;
        for (int x : nums) total += x;

        int leftSum = 0;
        for (int i = 0; i < nums.length; i++) {
            int rightSum = total - leftSum - nums[i];
            if (leftSum == rightSum) return i;
            leftSum += nums[i];
        }
        return -1;
    }
}
```

### Line-by-line

- `total = sum of all elements` — compute once before the loop.
- `leftSum = 0` — sum of elements strictly to the **left** of current index.
- `rightSum = total - leftSum - nums[i]` — total minus everything to the left minus the current element itself = everything to the **right**.
- `if (leftSum == rightSum) return i` — found the pivot! Return immediately (leftmost match).
- `leftSum += nums[i]` — move the boundary forward: current element now belongs to the "left side" for the next index.
- `return -1` — no index matched.

## Complexity

- Time: **O(n)** — one pass to compute total, one pass to find pivot.
- Space: **O(1)** — two integer variables (`total`, `leftSum`).

## Common Mistakes

- **Order matters:** `rightSum = total - leftSum - nums[i]` must use `leftSum` **before** adding `nums[i]`. Update `leftSum` only after checking.
- **`leftSum` excludes `nums[i]`** — it tracks elements strictly to the left, which is what "strictly to the left" means.
- **`total` includes everything** — subtract both `leftSum` and `nums[i]` to isolate the right side.
- **Edge cases:** Single element array → left sum `0`, right sum `0` → returns `0` (correct). Empty array → returns `-1` (loop never runs).

## How to Explain (interview)

**Opening:** Find Pivot Index asks for an index where sum of elements to the left equals sum of elements to the right, excluding the pivot itself.

**The core idea:** Track running `leftSum`. Since `leftSum + nums[i] + rightSum = total`, we can compute `rightSum = total - leftSum - nums[i]` instead of scanning right side every time. O(n) time, O(1) space.

**The basic flow:**
```java
int total = 0;
for (int x : nums) total += x;

int leftSum = 0;
for (int i = 0; i < nums.length; i++) {
    int rightSum = total - leftSum - nums[i];
    if (leftSum == rightSum) return i;
    leftSum += nums[i];
}
return -1;
```

**The part that trips everyone up:** `leftSum` is the sum of elements **strictly before** index `i`. At index `0`, it's `0`. We update it **after** checking, not before.

**The mistakes to remember:**
- Updating `leftSum` before computing `rightSum` — then you'd include `nums[i]` on both sides.
- Forgetting that `total` includes `nums[i]`, so you must subtract it when computing `rightSum`.
- Returning the last match instead of the first (leftmost).
