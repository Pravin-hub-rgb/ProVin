# 16.9 Top K Frequent Words

**Tier 2 problem.** (LeetCode #692)

**Problem:** Given an array of strings, return the k most frequent words. Sort by frequency (descending), then by lexicographical order (ascending) for ties. (LeetCode #692)

**Link:** https://leetcode.com/problems/top-k-frequent-words/

---

## Which Technique, and Why?

"Top K frequent words" with tie-breaking by lexicographical order → **HashMap (frequency) + min-heap of size K** (keyed by frequency, then lexicographical). The heap keeps the K most frequent; on tie, the lexicographically smallest is kept (so the largest lexicographically is evicted). O(n log k) time, O(n) space.

**Signal in the problem:** "top K frequent" + "lexicographical order for ties" → min-heap of size K with custom comparator.

## Approach

1. Count frequencies with a HashMap.
2. Use a min-heap of size k. Comparator: lower frequency first; on tie, lexicographically larger first (so it gets evicted, keeping the smaller one).
3. Extract from heap and reverse (heap gives ascending, we want descending frequency).

## Pseudocode

```
freq = count frequencies
minHeap = min-heap of size k (by freq asc, then lex desc)
for each (word, count) in freq:
    push {word, count}
    if size > k: pop
// extract and reverse
result = []
while heap not empty: result.add(0, heap.poll().word)  // prepend (or collect and reverse)
return result
```

## Java Code

```java
class Solution {
    public List<String> topKFrequent(String[] words, int k) {
        Map<String, Integer> freq = new HashMap<>();
        for (String w : words) freq.put(w, freq.getOrDefault(w, 0) + 1);

        PriorityQueue<String> heap = new PriorityQueue<>((a, b) -> {
            if (freq.get(a) != freq.get(b)) return freq.get(a) - freq.get(b);  // min by freq
            return b.compareTo(a);  // max lex (so it's evicted, keeping smaller)
        });

        for (String w : freq.keySet()) {
            heap.offer(w);
            if (heap.size() > k) heap.poll();
        }

        List<String> result = new ArrayList<>();
        while (!heap.isEmpty()) result.add(0, heap.poll());  // prepend for descending freq
        return result;
    }
}
```

## Line-by-line

- `freq` maps word → count.
- Comparator: if frequencies differ, smaller frequency first (min-heap by freq). On tie, larger string first (so it's evicted, keeping the lexicographically smaller one).
- Push each word; if heap exceeds k, pop the "worst" (lowest freq, or highest lex on tie).
- Extract: prepend to result (heap gives ascending freq, we want descending).

## Complexity

- Time: O(n log k) — n words, each heap op O(log k).
- Space: O(n) — frequency map + heap.

## Common Mistakes

- **Comparator direction.** Min-heap by frequency (smallest freq on top, evicted). On tie, max lex on top (evicted, keeping smallest lex). Getting either wrong gives wrong ordering.
- **Extract order.** Heap gives ascending frequency. Prepend to result (or collect and reverse) to get descending.
- **Comparator overflow.** `freq.get(a) - freq.get(b)` can overflow (rare for counts, but use `Integer.compare` for safety).
- **Confusing with "Top K Frequent Elements" (#347).** That one is integers without tie-breaking. This one has lexicographical tie-breaking.

## How to Explain (interview)

**Opening:** Top K Frequent Words returns the k most frequent words, sorted by frequency (desc) then lexicographically (asc). Min-heap of size k: comparator puts lowest frequency on top (evicted), and on tie, lexicographically largest on top (evicted, keeping smallest). O(n log k) time, O(n) space.

**The basic flow:**
```java
PriorityQueue<String> heap = new PriorityQueue<>((a, b) -> {
    if (freq.get(a) != freq.get(b)) return freq.get(a) - freq.get(b);
    return b.compareTo(a);  // larger string first → evicted
});
// push all, evict if size > k
// extract by prepending (ascending → descending)
```

**The part that trips everyone up:** the comparator's tie-breaking. On equal frequency, you want the lexicographically **smallest** to survive. So the heap evicts the **largest** lexicographically (put it on top). Also, extract by prepending (heap gives ascending freq).

**The mistakes to remember:**
- Wrong comparator direction (min vs max for freq and lex)
- Extracting in wrong order (ascending instead of descending)
- Comparator overflow (use Integer.compare)
- Confusing with #347 (integers, no tie-breaking)
