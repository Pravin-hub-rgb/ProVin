## Mini Quiz

1. Why use a min-heap of size K to find the K largest elements?
2. What is Java's default PriorityQueue heap type?
3. How do you create a max-heap in Java?
4. What is the time complexity of heap insert and extract?
5. What's the difference between `peek()` and `poll()`?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. A min-heap of size K keeps the K largest elements, with the smallest of those K on top. When a new element arrives, if it's larger than the top, push it and evict the top. This keeps only K elements. O(n log K) time (better than sorting's O(n log n) when K is small). Using a max-heap of all n elements would be O(n log n).
2. Min-heap. The smallest element is always on top. `peek()` returns the smallest, `poll()` removes and returns the smallest.
3. `new PriorityQueue<>(Collections.reverseOrder())` or `new PriorityQueue<>((a, b) -> Integer.compare(b, a))`. Both make the largest element the top.
4. Both O(log n). Insert (offer): add at end, bubble up. Extract (poll): remove root, replace with last, bubble down. Peek is O(1).
5. `peek()` looks at the top element without removing it. `poll()` removes and returns the top element. Use `peek()` when you only need to look; `poll()` when you want to remove.

</details>

## One-Page Cheat Sheet

**Min-heap (default):** `PriorityQueue<Integer> pq = new PriorityQueue<>();`
**Max-heap:** `new PriorityQueue<>(Collections.reverseOrder())`

**Top K largest (min-heap of size K):**
```java
PriorityQueue<Integer> heap = new PriorityQueue<>();
for (int x : nums) {
    heap.offer(x);
    if (heap.size() > K) heap.poll();
}
// heap holds the K largest
```

**Last Stone Weight:**
```java
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
for (int s : stones) maxHeap.offer(s);
while (maxHeap.size() > 1) {
    int a = maxHeap.poll(), b = maxHeap.poll();
    if (a != b) maxHeap.offer(a - b);
}
return maxHeap.isEmpty() ? 0 : maxHeap.peek();
```

**Complexities:** Insert O(log n), Extract O(log n), Peek O(1). Top K: O(n log K).

## In Your Own Words

1. Why is Java's PriorityQueue a min-heap by default, and how do you make it a max-heap?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Java's PriorityQueue uses natural ordering (Comparable) by default, which for integers means ascending — smallest on top = min-heap. To make a max-heap, pass a comparator that reverses the order: `Collections.reverseOrder()` or `(a, b) -> Integer.compare(b, a)`. This makes the largest element the top.

</details>

2. Why does a min-heap of size K find the K largest elements (not a max-heap)?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A min-heap of size K keeps the K largest elements seen so far, with the smallest of those K on top. When a new element arrives, if it's larger than the top, push it and evict the top (the smallest of the K). The heap always holds the K largest. Using a max-heap of all n elements would also work but is O(n log n) instead of O(n log K). When K is small, min-heap of size K is much faster.

</details>

3. What is the difference between `peek()` and `poll()`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `peek()` looks at the top element without removing it (O(1)). `poll()` removes and returns the top element (O(log n)). Use `peek()` when you only need to look; `poll()` when you want to remove. Both return null if the heap is empty (vs `element()`/`remove()` which throw).

</details>
