**Tier 2 problem.** (LeetCode #215)

**Problem:** Given an array, find the kth largest element (not necessarily distinct). (LeetCode #215)

**Link:** https://leetcode.com/problems/kth-largest-element-in-an-array/

---

## Which Technique, and Why?

"Kth largest element" → **Min-heap of size k** (O(n log k)) or **Quickselect** (O(n) average). Min-heap: keep the k largest; the top is the kth largest. Quickselect: partition like quicksort, recurse on the side containing k.

**Signal in the problem:** "kth largest" → min-heap of size k (O(n log k)) or quickselect (O(n) avg).

## Approach (Min-heap of size k)

Maintain a min-heap of size k. For each element: push, if size > k, pop. The top is the kth largest.

## Pseudocode

```
heap = min-heap
for x in nums:
    heap.offer(x)
    if heap.size > k: heap.poll()
return heap.peek()
```

## Java Code

```java
class Solution {
    public int findKthLargest(int[] nums, int k) {
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();
        for (int x : nums) {
            minHeap.offer(x);
            if (minHeap.size() > k) minHeap.poll();
        }
        return minHeap.peek();
    }
}
```

## Complexity

- Time: O(n log k) — n insertions, each O(log k).
- Space: O(k) — heap holds k elements.

## Common Mistakes

- **Using a max-heap of all elements.** O(n log n) — works but slower.
- **Confusing "kth largest" with "kth smallest."** Kth largest → min-heap of size k (evict smallest). Kth smallest → max-heap of size k (evict largest).
- **Not handling duplicates.** The problem allows duplicates. The heap approach handles them naturally.

## How to Explain (interview)

**Opening:** Kth Largest Element finds the kth largest in O(n log k) using a min-heap of size k. Keep the k largest; the smallest of those k (on top) is the kth largest. Evict the top when size exceeds k.

**The basic flow:**
```java
PriorityQueue<Integer> heap = new PriorityQueue<>(); // min-heap
for (int x : nums) {
    heap.offer(x);
    if (heap.size() > k) heap.poll();
}
return heap.peek();
```

**The part that trips everyone up:** use a **min-heap** of size k (not max-heap of all n). The min-heap evicts the smallest of the top k, keeping only the k largest.

**The mistakes to remember:**
- Using max-heap of all elements (O(n log n) instead of O(n log k))
- Confusing "kth largest" with "kth smallest" (which heap to use)
- Not handling duplicates (heap handles them naturally)
