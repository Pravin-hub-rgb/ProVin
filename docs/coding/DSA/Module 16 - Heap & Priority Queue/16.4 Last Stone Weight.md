**Problem:** You have stones with given weights. Each turn, smash the two heaviest; if they differ, the remainder goes back. Return the weight of the last stone (or 0 if none). (LeetCode #1046)

**Link:** https://leetcode.com/problems/last-stone-weight/

---

## Which Technique, and Why?

"Repeatedly take the two heaviest" → **Max-heap**. Java's `PriorityQueue` is min-heap by default, so use `Collections.reverseOrder()` for max-heap. Pop two, push remainder if they differ. O(n log n) time, O(n) space.

**Signal in the problem:** "two largest" / "heaviest" / "repeatedly take max" → max-heap.

## Approach

Push all stones into a max-heap. While size > 1: pop two largest, if they differ, push the difference. Return the last stone (or 0).

## Pseudocode

```
maxHeap = max-heap with all stones
while maxHeap.size > 1:
    a = maxHeap.poll()  // heaviest
    b = maxHeap.poll()  // second heaviest
    if a != b: maxHeap.offer(a - b)
return maxHeap.isEmpty() ? 0 : maxHeap.peek()
```

## Java Code

```java
class Solution {
    public int lastStoneWeight(int[] stones) {
        PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
        for (int s : stones) maxHeap.offer(s);

        while (maxHeap.size() > 1) {
            int a = maxHeap.poll();
            int b = maxHeap.poll();
            if (a != b) maxHeap.offer(a - b);
        }
        return maxHeap.isEmpty() ? 0 : maxHeap.peek();
    }
}
```

## Line-by-line

- `maxHeap` — max-heap via `Collections.reverseOrder()`.
- Push all stones.
- While more than one stone: pop the two heaviest, smash. If they differ, push the remainder.
- Return the last stone (or 0 if heap is empty).

## Complexity

- Time: O(n log n) — n insertions + (n-1) pops/pushes, each O(log n).
- Space: O(n) — heap holds up to n stones.

## Common Mistakes

- **Using a min-heap.** Java's default `PriorityQueue` is min-heap — would give the two lightest, not heaviest. Use `Collections.reverseOrder()`.
- **Comparator overflow.** `(a, b) -> b - a` can overflow. Use `Collections.reverseOrder()` or `Integer.compare(b, a)`.
- **Forgetting the final carry.** If the last smash produces a remainder, it goes back. The `if (a != b)` handles this. If all stones cancel, heap is empty → return 0.
- **Sorting instead of heap.** Sorting each time is O(n² log n). Heap is O(n log n).

## How to Explain (interview)

**Opening:** Last Stone Weight repeatedly smashes the two heaviest stones. Max-heap gives O(1) access to the heaviest. Pop two, push the remainder if they differ. O(n log n) time, O(n) space. Java's PriorityQueue is min-heap by default — use `Collections.reverseOrder()` for max-heap.

**The basic flow:**
```java
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
for (int s : stones) maxHeap.offer(s);
while (maxHeap.size() > 1) {
    int a = maxHeap.poll(), b = maxHeap.poll();
    if (a != b) maxHeap.offer(a - b);
}
return maxHeap.isEmpty() ? 0 : maxHeap.peek();
```

**The part that trips everyone up:** Java's `PriorityQueue` is a **min-heap** by default. For max-heap, pass `Collections.reverseOrder()`. Also, return 0 if the heap is empty (all stones cancelled).

**The mistakes to remember:**
- Using min-heap instead of max-heap
- Comparator overflow with subtraction
- Forgetting the final carry (remainder goes back)
- Sorting instead of using a heap (slower)
