**Tier 2 problem.** (LeetCode #846)

**Problem:** Given an array of cards and a group size W, determine if you can rearrange the cards into groups of W consecutive cards. (LeetCode #846)

**Link:** https://leetcode.com/problems/hand-of-straights/

---

## Which Technique, and Why?

"Can cards be arranged into groups of W consecutive?" → **Greedy + TreeMap (or sort + count)**. Sort the cards. For each smallest remaining card, try to form a group (card, card+1, ..., card+W-1). If any card in the group is missing, return false. Use a frequency map (TreeMap for sorted keys) or sort + count. O(n log n) time.

**Signal in the problem:** "hand of straights" / "groups of W consecutive cards" → greedy: always start a group from the smallest remaining card.

## Approach

1. Count frequencies (TreeMap for sorted keys, or sort + count array).
2. For each card in ascending order: if it has count > 0, form a group starting from it. Decrement counts for card, card+1, ..., card+W-1. If any is missing → false.
3. If all groups formed → true.

## Pseudocode

```
freq = count of each card (TreeMap, sorted)
for each card in freq (ascending):
    if freq[card] > 0:
        count = freq[card]
        for i from 0 to W-1:
            if freq[card + i] < count: return false
            freq[card + i] -= count
return true
```

## Java Code

```java
class Solution {
    public boolean isNStraightHand(int[] hand, int groupSize) {
        TreeMap<Integer, Integer> freq = new TreeMap<>();
        for (int c : hand) freq.put(c, freq.getOrDefault(c, 0) + 1);

        for (int card : freq.keySet()) {
            if (freq.get(card) > 0) {
                int count = freq.get(card);
                for (int i = 0; i < groupSize; i++) {
                    int next = card + i;
                    if (freq.getOrDefault(next, 0) < count) return false;
                    freq.put(next, freq.get(next) - count);
                }
            }
        }
        return true;
    }
}
```

## Line-by-line

- `freq` — TreeMap (sorted by card value) with counts.
- For each card (ascending): if count > 0, form `count` groups starting from this card.
- For each group member (card, card+1, ..., card+W-1): check enough cards exist, decrement.
- If any member is missing → return false.

## Complexity

- Time: O(n log n) — TreeMap operations O(log n) per card.
- Space: O(n) — frequency map.

## Common Mistakes

- **Not starting from the smallest.** Always start a group from the smallest remaining card. This is the greedy choice.
- **Using a HashMap instead of TreeMap.** HashMap isn't sorted — you'd need to sort keys separately. TreeMap gives sorted iteration.
- **Not handling the count correctly.** If card appears 3 times, you need 3 groups starting from card (and card+1, ..., card+W-1 must also appear ≥ 3 times).
- **Confusing with "Divide Array in Sets of K Consecutive Numbers" (#1296).** Same problem, different name.

## How to Explain (interview)

**Opening:** Hand of Straights checks if cards can be arranged into groups of W consecutive cards. Greedy: always start a group from the smallest remaining card. Use a TreeMap (sorted) with counts. For each smallest card with count > 0, form groups (decrement counts for card, card+1, ..., card+W-1). If any is missing → false. O(n log n) time, O(n) space.

**The basic flow:**
```java
TreeMap<Integer, Integer> freq = new TreeMap<>();
for (int c : hand) freq.put(c, freq.getOrDefault(c, 0) + 1);
for (int card : freq.keySet()) {
    if (freq.get(card) > 0) {
        int count = freq.get(card);
        for (int i = 0; i < W; i++) {
            if (freq.getOrDefault(card + i, 0) < count) return false;
            freq.put(card + i, freq.get(card + i) - count);
        }
    }
}
return true;
```

**The part that trips everyone up:** always start from the **smallest** remaining card. Also, if a card appears `count` times, you need `count` groups — all members must appear at least `count` times.

**The mistakes to remember:**
- Not starting from the smallest (wrong greedy)
- Using HashMap instead of TreeMap (unsorted)
- Not handling multiple groups (count > 1)
- Confusing with #1296 (same problem)
