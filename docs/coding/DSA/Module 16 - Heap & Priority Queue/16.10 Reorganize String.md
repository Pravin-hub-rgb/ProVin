# 16.10 Reorganize String

**Tier 2 problem.** (LeetCode #767)

**Problem:** Given a string, rearrange it so no two adjacent characters are the same. Return any valid rearrangement, or "" if impossible. (LeetCode #767)

**Link:** https://leetcode.com/problems/reorganize-string/

---

## Which Technique, and Why?

"Rearrange so no two adjacent are the same" → **Greedy + Max-heap**. Always place the most frequent remaining character that isn't the last placed. Use a max-heap of (char, count). Pop the most frequent, append, decrement, push back (if count > 0) after placing a different char. O(n log 26) = O(n) time.

**Signal in the problem:** "reorganize" / "no two adjacent same" → greedy with max-heap (always place most frequent).

## Approach

1. Count character frequencies.
2. Max-heap of (count, char), ordered by count descending.
3. Build result: pop the most frequent (that isn't the last placed), append, decrement, push back if count > 0. If only one type remains and its count > remaining slots → impossible.

## Pseudocode

```
freq = count chars
maxHeap = max-heap by count
prev = null
result = ""
while maxHeap not empty or prev != null:
    if maxHeap empty: return ""  // impossible
    (count, char) = maxHeap.pop()
    result += char
    if prev != null: maxHeap.push(prev); prev = null
    if count - 1 > 0: prev = (count - 1, char)
return result
```

## Java Code

```java
class Solution {
    public String reorganizeString(String s) {
        int[] freq = new int[26];
        for (char c : s.toCharArray()) freq[c - 'a']++;

        PriorityQueue<int[]> maxHeap = new PriorityQueue<>((a, b) -> b[0] - a[0]);
        for (int i = 0; i < 26; i++) {
            if (freq[i] > 0) maxHeap.offer(new int[]{freq[i], i});
        }

        StringBuilder sb = new StringBuilder();
        int[] prev = null;

        while (!maxHeap.isEmpty() || prev != null) {
            if (maxHeap.isEmpty()) return "";  // impossible
            int[] cur = maxHeap.poll();
            sb.append((char) (cur[1] + 'a'));
            if (prev != null) {
                maxHeap.offer(prev);
                prev = null;
            }
            if (cur[0] - 1 > 0) prev = new int[]{cur[0] - 1, cur[1]};
        }
        return sb.toString();
    }
}
```

## Line-by-line

- `freq` counts each character.
- `maxHeap` — max-heap by frequency (most frequent on top).
- For each step: pop the most frequent, append to result. If `prev` exists (a char waiting to be re-added), push it back. Then, if the current char still has count > 0, set it as `prev` (can't place it next — cooldown).
- `if (maxHeap.isEmpty()) return ""` — if the heap is empty but `prev` remains, it's impossible (one char dominates).

## Complexity

- Time: O(n log 26) = O(n) — 26 letters, heap ops O(log 26).
- Space: O(26) = O(1) — heap holds at most 26 entries.

## Common Mistakes

- **Not using a max-heap.** Greedy: always place the most frequent available char. Using a min-heap or queue gives wrong results.
- **Not tracking `prev`.** You must avoid placing the same char consecutively. The `prev` mechanism ensures a cooldown of one.
- **Impossible case.** If any char's frequency > (n + 1) / 2, it's impossible → return "". The heap naturally handles this (heap empties while prev remains).
- **Comparator overflow.** `b[0] - a[0]` can overflow. Use `Integer.compare(b[0], a[0])` for safety.

## How to Explain (interview)

**Opening:** Reorganize String rearranges characters so no two adjacent are the same. Greedy + max-heap: always place the most frequent available character, with a one-step cooldown (can't place the same char twice in a row). O(n log 26) = O(n) time, O(1) space.

**The basic flow:**
```java
PriorityQueue<int[]> maxHeap = new PriorityQueue<>((a, b) -> b[0] - a[0]);
// push all chars with freq > 0
int[] prev = null;
while (!maxHeap.isEmpty() || prev != null) {
    if (maxHeap.isEmpty()) return "";  // impossible
    int[] cur = maxHeap.poll();
    sb.append((char)(cur[1] + 'a'));
    if (prev != null) { maxHeap.offer(prev); prev = null; }
    if (cur[0] - 1 > 0) prev = new int[]{cur[0] - 1, cur[1]};
}
```

**The part that trips everyone up:** the `prev` mechanism — after placing a char, it can't be placed next. Push it back only after placing a different char. If the heap empties while `prev` remains → impossible.

**The mistakes to remember:**
- Not using max-heap (wrong greedy)
- Forgetting the `prev` cooldown (places same char consecutively)
- Not returning "" when impossible
- Comparator overflow (use Integer.compare)
