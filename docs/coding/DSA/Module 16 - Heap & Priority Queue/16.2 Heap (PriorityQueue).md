# 16.2 Heap (PriorityQueue)

A heap is a complete binary tree where the parent is always ≤ children (min-heap) or ≥ children (max-heap). The root is always the minimum (min-heap) or maximum (max-heap). Java's `PriorityQueue` implements a min-heap.

---

## Declaration and Creation

```java
import java.util.PriorityQueue;
import java.util.Collections;

// Min-heap (default) — smallest on top
PriorityQueue<Integer> minHeap = new PriorityQueue<>();

// Max-heap — largest on top
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());

// Max-heap with comparator
PriorityQueue<Integer> maxHeap2 = new PriorityQueue<>((a, b) -> b - a);

// With initial capacity
PriorityQueue<Integer> sized = new PriorityQueue<>(100);

// Custom objects (by a field)
PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> a[1] - b[1]); // min by index 1
```

**Note:** Use `PriorityQueue` (class) directly — there's no `Heap` interface in Java. The class implements `Queue`.

## Core Operations

```java
PriorityQueue<Integer> pq = new PriorityQueue<>();

pq.offer(30);             // insert (returns boolean)
pq.offer(10);
pq.offer(20);

System.out.println(pq.peek());  // 10 (look at min, don't remove; null if empty)
System.out.println(pq.poll());  // 10 (remove and return min; null if empty)
System.out.println(pq.size());  // 2
System.out.println(pq.isEmpty()); // false
```

- `offer(x)` / `add(x)` — insert: O(log n).
- `poll()` — remove and return min: O(log n). Returns null if empty (vs `remove()` which throws).
- `peek()` — look at min without removing: O(1). Returns null if empty.
- `size()`, `isEmpty()`: O(1).

**Prefer `offer`/`poll`/`peek`** over `add`/`remove`/`element` (null-returning, safer).

## Min-Heap vs Max-Heap

```java
// Min-heap (default): smallest on top
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
minHeap.offer(30); minHeap.offer(10); minHeap.offer(20);
System.out.println(minHeap.poll());  // 10

// Max-heap: largest on top
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
maxHeap.offer(30); maxHeap.offer(10); maxHeap.offer(20);
System.out.println(maxHeap.poll());  // 30
```

## Custom Comparators (for objects/arrays)

```java
// Min-heap by frequency (index 1 of int[])
PriorityQueue<int[]> heap = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));

// Max-heap by frequency
PriorityQueue<int[]> maxHeap = new PriorityQueue<>((a, b) -> Integer.compare(b[1], a[1]));

// For strings: sort by length
PriorityQueue<String> pq = new PriorityQueue<>((a, b) -> a.length() - b.length());
```

**Always use `Integer.compare(a, b)` instead of `a - b`** to avoid overflow.

## Cost (Big-O)

| Operation | Time |
|---|---|
| `offer` / `add` | O(log n) |
| `poll` / `remove` | O(log n) |
| `peek` | O(1) |
| `size`, `isEmpty` | O(1) |
| Build heap from array | O(n) (heapify) |

## When to Use

- **Top K largest/smallest** — min/max heap of size K.
- **Kth largest/smallest** — heap of size K.
- **Merge K sorted lists** — min-heap of size K (one element per list).
- **Scheduling with priority** — process highest-priority first.
- **Median of a stream** — two heaps (max-heap for lower half, min-heap for upper half).

## Common Pitfalls

- **Default is min-heap.** If you need max-heap, pass `Collections.reverseOrder()` or a comparator.
- **Comparator overflow.** `a - b` can overflow. Use `Integer.compare(a, b)`.
- **`peek()` vs `poll()`.** `peek()` looks; `poll()` removes. Don't call `poll()` when you only want to look.
- **Confusing "K largest" with "K smallest."** K largest → min-heap of size K (evict smallest). K smallest → max-heap of size K (evict largest).
- **PriorityQueue is not thread-safe.** Use `PriorityBlockingQueue` for concurrent access (rare in DSA).
- **No `get` by index.** PriorityQueue doesn't support O(1) access by index. If you need that, use a different structure.

## A Small Program: Kth Largest Element

```java
import java.util.*;

public class KthLargest {
    static int findKthLargest(int[] nums, int k) {
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();
        for (int x : nums) {
            minHeap.offer(x);
            if (minHeap.size() > k) minHeap.poll();
        }
        return minHeap.peek();
    }

    public static void main(String[] args) {
        int[] nums = {3, 2, 1, 5, 6, 4};
        System.out.println(findKthLargest(nums, 2));  // 5
    }
}
```

## In Your Own Words

1. What is the difference between a min-heap and a max-heap?

<details>
<summary>Show Answer</summary>

**Sample Answer:** In a min-heap, the parent is ≤ children — the root is the minimum. In a max-heap, the parent is ≥ children — the root is the maximum. Java's `PriorityQueue` is a min-heap by default. For a max-heap, pass `Collections.reverseOrder()` or a comparator `(a, b) -> b - a` (or `Integer.compare(b, a)`). Choose based on whether you need the smallest or largest element on top.

</details>

2. Why use a min-heap of size K to find the K largest elements?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A min-heap of size K keeps the K largest elements seen so far, with the smallest of those K on top. When a new element arrives, if it's larger than the top, push it and evict the top. This keeps only K elements. O(n log K) time (better than sorting's O(n log n) when K is small). Using a max-heap of all n elements would be O(n log n) — works but slower.

</details>

3. Why use `Integer.compare(a, b)` instead of `a - b` in a comparator?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `a - b` can overflow for large integers (e.g., `Integer.MIN_VALUE - 1` wraps to positive). `Integer.compare(a, b)` returns -1, 0, or 1 without arithmetic, avoiding overflow. The same applies to `Long.compare`, `Double.compare`, etc. Always use the `compare` method for safety.

</details>
