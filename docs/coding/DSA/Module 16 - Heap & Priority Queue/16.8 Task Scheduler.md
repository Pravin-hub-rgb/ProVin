# 16.8 Task Scheduler

**Tier 2 problem.** (LeetCode #621)

**Problem:** Given tasks (letters) and a cooldown n, find the minimum time to execute all tasks such that the same task is at least n intervals apart. (LeetCode #621)

**Link:** https://leetcode.com/problems/task-scheduler/

---

## Which Technique, and Why?

"Minimum time with cooldown" → **Greedy + Max-heap** (or math formula). The most frequent task determines the minimum time. Use a max-heap of task frequencies. Repeatedly take the most frequent available task, apply cooldown, re-add tasks whose cooldown has expired. O(n log 26) = O(n) since only 26 letters.

**Signal in the problem:** "task scheduler" / "cooldown" / "minimum time with n intervals between same task" → greedy with max-heap (or math formula).

## Approach (Math formula — simplest)

The answer is `max(tasks.length, (maxFreq - 1) * (n + 1) + countOfMaxFreq)`. The most frequent task creates `(maxFreq - 1)` gaps of size `n`, plus the final group of max-frequency tasks.

Alternative: max-heap simulation (more general, handles arbitrary constraints).

## Pseudocode (math formula)

```
freq = count of each task
maxFreq = max(freq)
countMax = number of tasks with freq == maxFreq
return max(tasks.length, (maxFreq - 1) * (n + 1) + countMax)
```

## Java Code (math formula)

```java
class Solution {
    public int leastInterval(char[] tasks, int n) {
        int[] freq = new int[26];
        for (char t : tasks) freq[t - 'A']++;

        int maxFreq = 0, countMax = 0;
        for (int f : freq) {
            if (f > maxFreq) { maxFreq = f; countMax = 1; }
            else if (f == maxFreq) countMax++;
        }

        int formula = (maxFreq - 1) * (n + 1) + countMax;
        return Math.max(tasks.length, formula);
    }
}
```

## Java Code (max-heap simulation)

```java
class Solution {
    public int leastInterval(char[] tasks, int n) {
        int[] freq = new int[26];
        for (char t : tasks) freq[t - 'A']++;

        PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
        for (int f : freq) if (f > 0) maxHeap.offer(f);

        int time = 0;
        Queue<int[]> cooldown = new LinkedList<>(); // {remaining freq, available time}

        while (!maxHeap.isEmpty() || !cooldown.isEmpty()) {
            time++;
            if (!maxHeap.isEmpty()) {
                int f = maxHeap.poll() - 1;
                if (f > 0) cooldown.offer(new int[]{f, time + n});
            }
            if (!cooldown.isEmpty() && cooldown.peek()[1] == time) {
                maxHeap.offer(cooldown.poll()[0]);
            }
        }
        return time;
    }
}
```

## Line-by-line (math formula)

- `freq` counts each task.
- `maxFreq` = highest frequency. `countMax` = how many tasks have that frequency.
- `(maxFreq - 1) * (n + 1) + countMax` — the most frequent task creates `maxFreq - 1` gaps of size `n`, plus the final group of `countMax` tasks.
- `Math.max(tasks.length, formula)` — if there are enough other tasks to fill the gaps, the answer is just `tasks.length`.

## Complexity

- Math formula: O(n) time, O(1) space (26 letters).
- Heap simulation: O(n log 26) = O(n) time, O(26) space.

## Common Mistakes

- **Using the formula without `Math.max(tasks.length, formula)`.** If there are enough other tasks to fill the gaps, the answer is just `tasks.length`. The formula can overcount.
- **Not counting `countMax` correctly.** `countMax` = number of tasks with frequency == `maxFreq`. If two tasks both appear maxFreq times, the final group has 2 tasks.
- **Confusing with "Task Scheduler II" (#2365).** That one has a different cooldown rule (same task type, not same letter). Different problem.
- **Overflow.** `(maxFreq - 1) * (n + 1)` can overflow for large inputs. Use `long` if needed (LeetCode constraints are small).

Alternatively, simulate with a max-heap.
