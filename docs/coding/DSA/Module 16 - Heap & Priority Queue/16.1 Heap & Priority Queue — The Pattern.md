## The Core Idea

A **heap** is a complete binary tree where the parent is always ≤ children (min-heap) or ≥ children (max-heap). The root is the min (or max). You can:
- **Insert:** O(log n) — add at the end, bubble up.
- **Extract min/max:** O(log n) — remove root, replace with last, bubble down.
- **Peek min/max:** O(1) — root.

Java's `PriorityQueue` is a **min-heap** by default. For a max-heap, pass a comparator: `new PriorityQueue<>(Collections.reverseOrder())` or `(a, b) -> b - a`.

**Key insight for "top K":** To find the K largest elements, use a **min-heap of size K**. Keep the K largest; the smallest of those K sits on top and gets evicted when a larger one comes. O(n log K) instead of O(n log n) for sorting.

## How to Recognize It

Think "Heap" when:
- The problem asks for the **K largest/smallest** elements → min/max heap of size K.
- The problem asks for the **Kth largest/smallest** → heap.
- The problem involves **merging K sorted lists** → min-heap of size K (one element from each list).
- The problem involves **scheduling with priority** → priority queue.
- Keywords: "top K," "kth largest," "kth smallest," "merge k sorted," "least/most frequent," "median."

**Signal words:** "kth largest," "top K," "merge k sorted lists," "schedule," "priority," "median."

**Heap vs Sorting:** Sorting is O(n log n) and gives all elements in order. Heap is O(n log k) when you only need the top K. If K is small, heap is faster. If K ≈ n, sorting is simpler.

## Worked Example: Last Stone Weight

**Problem:** Repeatedly smash the two heaviest stones; if they differ, the remainder goes back. Return the last stone's weight (or 0).

### Brute force (O(n² log n))

Sort the array each time, take the two largest, insert the remainder. Slow.

### Optimized (O(n log n)) — max-heap

```java
class Solution {
    public int lastStoneWeight(int[] stones) {
        PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
        for (int s : stones) maxHeap.offer(s);

        while (maxHeap.size() > 1) {
            int a = maxHeap.poll();  // heaviest
            int b = maxHeap.poll();  // second heaviest
            if (a != b) maxHeap.offer(a - b);
        }
        return maxHeap.isEmpty() ? 0 : maxHeap.peek();
    }
}
```

**Line-by-line:**
- `maxHeap` — max-heap (largest on top) via `Collections.reverseOrder()`.
- Push all stones.
- While more than one stone: pop the two heaviest, smash them. If they differ, push the remainder.
- Return the last stone (or 0 if none).

**Key insight:** the heap always gives you the heaviest stone in O(1) (peek) / O(log n) (poll). No need to sort repeatedly.

## Common Mistakes

- **Using a min-heap when you need a max-heap.** Java's `PriorityQueue` is min-heap by default. For max-heap, pass `Collections.reverseOrder()` or a comparator.
- **Comparator overflow.** `(a, b) -> b - a` can overflow. Use `Integer.compare(b, a)` or `Collections.reverseOrder()`.
- **Forgetting that `peek()` doesn't remove.** `peek()` looks; `poll()` removes. Don't call `poll()` when you only want to look.
- **Confusing "K largest" with "K smallest."** K largest → min-heap of size K (evict smallest). K smallest → max-heap of size K (evict largest). Getting this backwards gives wrong answers.

## How to Explain (interview)

**Opening:** A heap is a complete binary tree where the parent is always ≤ (min-heap) or ≥ (max-heap) its children. The root is always the min/max. Insert and extract are O(log n); peek is O(1). Java's `PriorityQueue` is a min-heap by default. Used for "top K," "kth largest/smallest," "merge k sorted lists," and scheduling. For "K largest," use a min-heap of size K.

**The basic flow (min-heap of size K for top K largest):**
```java
PriorityQueue<Integer> heap = new PriorityQueue<>(); // min-heap
for (int x : nums) {
    heap.offer(x);
    if (heap.size() > K) heap.poll(); // evict smallest
}
// heap now holds the K largest
```

**The part that trips everyone up:** for "K largest," use a **min-heap** of size K (evict the smallest of the K). Using a max-heap of all elements is O(n log n) — works but slower. Also, Java's PriorityQueue is min-heap by default — pass `Collections.reverseOrder()` for max-heap.

**The mistakes to remember:**
- Using min-heap when you need max-heap (or vice versa)
- Comparator overflow with subtraction
- `peek()` vs `poll()` confusion
- Confusing "K largest" with "K smallest" (which heap to use)
