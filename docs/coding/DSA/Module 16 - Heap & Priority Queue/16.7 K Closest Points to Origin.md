**Tier 2 problem.** (LeetCode #973)

**Problem:** Given an array of points, return the k closest to the origin (0, 0). (LeetCode #973)

**Link:** https://leetcode.com/problems/k-closest-points-to-origin/

---

## Which Technique, and Why?

"K closest to origin" → **Max-heap of size k** (by distance). Keep the k closest; the farthest of those k sits on top and gets evicted when a closer one comes. O(n log k) time, O(k) space. (Or quickselect for O(n) average.)

**Signal in the problem:** "k closest" / "k nearest" → max-heap of size k (evict farthest).

## Approach

Max-heap of size k, keyed by distance (squared distance to avoid sqrt). For each point: push; if size > k, pop the farthest. Extract remaining.

## Pseudocode

```
maxHeap = max-heap (by distance)
for each point:
    dist = x*x + y*y
    push {dist, point}
    if maxHeap.size > k: pop
return the points in maxHeap
```

## Java Code

```java
class Solution {
    public int[][] kClosest(int[][] points, int k) {
        PriorityQueue<int[]> maxHeap = new PriorityQueue<>((a, b) -> b[0] - a[0]); // max by distance

        for (int[] p : points) {
            int dist = p[0] * p[0] + p[1] * p[1];
            maxHeap.offer(new int[]{dist, p[0], p[1]});
            if (maxHeap.size() > k) maxHeap.poll();
        }

        int[][] result = new int[k][2];
        for (int i = 0; i < k; i++) {
            int[] entry = maxHeap.poll();
            result[i][0] = entry[1];
            result[i][1] = entry[2];
        }
        return result;
    }
}
```

## Line-by-line

- `maxHeap` — max-heap by distance (squared distance to avoid sqrt and floating point).
- For each point: push `{dist, x, y}`. If size > k, pop the farthest.
- After processing, extract the k closest from the heap.

## Complexity

- Time: O(n log k) — n insertions, each O(log k).
- Space: O(k) — heap holds k entries.

## Common Mistakes

- **Using a min-heap of all elements.** O(n log n) — works but slower. Max-heap of size k is O(n log k).
- **Computing actual distance (sqrt).** Use squared distance (x² + y²) — avoids floating point and sqrt. Comparison is the same.
- **Comparator overflow.** `b[0] - a[0]` can overflow for large distances. Use `Integer.compare(b[0], a[0])` for safety.
- **Confusing "K closest" with "K largest distance."** K closest → max-heap of size k (evict farthest). K farthest → min-heap of size k (evict closest).

## How to Explain (interview)

**Opening:** K Closest Points to Origin finds the k nearest points. Max-heap of size k keyed by squared distance: keep the k closest, evict the farthest. O(n log k) time, O(k) space. Use squared distance (x² + y²) to avoid sqrt.

**The basic flow:**
```java
PriorityQueue<int[]> maxHeap = new PriorityQueue<>((a, b) -> b[0] - a[0]);
```

**The part that trips everyone up:** use a **max-heap** of size k (evict the farthest). Using a min-heap of all n elements is O(n log n). Also, use squared distance (no sqrt needed).

**The mistakes to remember:**
- Using min-heap of all elements (O(n log n) instead of O(n log k))
- Computing sqrt (unnecessary, floating point issues)
- Comparator overflow (use Integer.compare)
- Confusing "K closest" with "K farthest" (which heap to use)
