# 16.3 Kth Largest Element in a Stream

**Problem:** Design a class that finds the kth largest element in a stream of numbers. (LeetCode #703)

**Link:** https://leetcode.com/problems/kth-largest-element-in-a-stream/

---

## Which Technique, and Why?

"Kth largest in a stream" → **Min-heap of size k**. Keep the k largest elements seen so far; the smallest of those k (on top of the min-heap) is the kth largest. On each new number, push it and evict the smallest if size > k. O(log k) per insertion, O(k) space.

**Signal in the problem:** "kth largest in a stream" / "running kth largest" → min-heap of size k.

## Approach

Constructor: build a min-heap from the initial array (keep only k largest). `add(val)`: push val, if size > k, poll. Return `peek()`.

## Pseudocode

```
constructor(nums, k):
    this.k = k
    heap = new min-heap
    for x in nums: add(x)

add(val):
    heap.offer(val)
    if heap.size > k: heap.poll()
    return heap.peek()
```

## Java Code

```java
class KthLargest {
    private final PriorityQueue<Integer> heap;
    private final int k;

    public KthLargest(int k, int[] nums) {
        this.k = k;
        this.heap = new PriorityQueue<>();
        for (int x : nums) add(x);
    }

    public int add(int val) {
        heap.offer(val);
        if (heap.size() > k) heap.poll();
        return heap.peek();
    }
}
```

## Line-by-line

- Constructor: build the heap by calling `add` for each initial number. This keeps only the k largest.
- `add(val)`: push val, then if size > k, evict the smallest. The top is now the kth largest.
- Return `heap.peek()` — the kth largest (smallest of the top k).

## Complexity

- Constructor: O(n log k) — n insertions, each O(log k).
- `add`: O(log k) time, O(1) extra space.
- Space: O(k) — heap holds at most k elements.

## Common Mistakes

- **Using a max-heap of all elements.** O(n log n) per query — too slow. Min-heap of size k is O(log k).
- **Not evicting when size > k.** The heap would grow unbounded; `peek()` would return the smallest, not the kth largest.
- **Returning `poll()` instead of `peek()`.** `poll()` removes the element; `peek()` just looks. You want to keep the element.
- **Not handling the initial array.** If `nums.length < k`, the heap has fewer than k elements; `peek()` returns the smallest so far (which is the kth largest once k elements arrive). The problem guarantees enough elements eventually.

## How to Explain (interview)

**Opening:** Kth Largest in a Stream maintains a min-heap of size k. The top of the min-heap is the kth largest (smallest of the top k). On each new number, push it and evict the smallest if size exceeds k. O(log k) per insertion, O(k) space. Constructor processes the initial array.

**The basic flow:**
```java
PriorityQueue<Integer> heap = new PriorityQueue<>(); // min-heap
for (int x : nums) { heap.offer(x); if (heap.size() > k) heap.poll(); }
// add(val): same — push, evict if needed, return peek()
```

**The part that trips everyone up:** use a **min-heap** of size k (not max-heap of all elements). The min-heap evicts the smallest of the top k, keeping only the k largest. Return `peek()`, not `poll()`.

**The mistakes to remember:**
- Using max-heap of all elements (O(n log n) instead of O(log k))
- Not evicting when size > k
- Returning `poll()` instead of `peek()` (removes the element)
- Not processing the initial array in the constructor
