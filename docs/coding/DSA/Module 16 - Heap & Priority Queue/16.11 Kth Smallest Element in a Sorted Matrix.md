# 16.11 Kth Smallest Element in a Sorted Matrix

**Tier 2 problem.** (LeetCode #378)

**Problem:** Given an n×n matrix where rows and columns are sorted in ascending order, find the kth smallest element. (LeetCode #378)

**Link:** https://leetcode.com/problems/kth-smallest-element-in-a-sorted-matrix/

---

## Which Technique, and Why?

"Kth smallest in a sorted matrix" → **Min-heap of size (or BFS from top-left)**. Start at top-left, push to min-heap. Pop the smallest, push its right and down neighbors (if not visited). Do this k times. The kth popped is the answer. O(k log k) time, O(k) space.

Alternative: binary search on value range [min, max] — O(n log(max-min)).

**Signal in the problem:** "kth smallest in sorted matrix" → min-heap BFS (start top-left, expand right/down) or binary search on value.

## Approach (Min-heap)

Min-heap of (value, row, col). Start with (matrix[0][0], 0, 0). Mark visited. Pop k times: each pop, push right and down neighbors (if in bounds and not visited). The kth popped value is the answer.

## Pseudocode

```
minHeap = min-heap of (value, row, col)
visited = boolean[m][n]
minHeap.offer({matrix[0][0], 0, 0})
visited[0][0] = true
for i from 1 to k:
    {val, r, c} = minHeap.poll()
    if i == k: return val
    if r+1 < m and !visited[r+1][c]: visited[r+1][c] = true; offer({matrix[r+1][c], r+1, c})
    if c+1 < n and !visited[r][c+1]: visited[r][c+1] = true; offer({matrix[r][c+1], r, c+1})
```

## Java Code

```java
class Solution {
    public int kthSmallest(int[][] matrix, int k) {
        int n = matrix.length;
        PriorityQueue<int[]> minHeap = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        boolean[][] visited = new boolean[n][n];

        minHeap.offer(new int[]{matrix[0][0], 0, 0});
        visited[0][0] = true;

        int result = 0;
        for (int i = 0; i < k; i++) {
            int[] cur = minHeap.poll();
            result = cur[0];
            int r = cur[1], c = cur[2];
            if (r + 1 < n && !visited[r + 1][c]) {
                visited[r + 1][c] = true;
                minHeap.offer(new int[]{matrix[r + 1][c], r + 1, c});
            }
            if (c + 1 < n && !visited[r][c + 1]) {
                visited[r][c + 1] = true;
                minHeap.offer(new int[]{matrix[r][c + 1], r, c + 1});
            }
        }
        return result;
    }
}
```

## Line-by-line

- Start at top-left (smallest element).
- Pop the smallest, push its right and down neighbors.
- `visited` prevents re-pushing the same cell.
- After k pops, `result` is the kth smallest.

## Complexity

- Time: O(k log k) — k heap operations, each O(log k).
- Space: O(k) — heap + visited (but visited is O(n²); can optimize with a set or by marking in place).

## Common Mistakes

- **Not marking visited.** The same cell can be reached from two directions (from above and from left). Without visited, you'd push duplicates.
- **Pushing both neighbors before popping.** You must pop first, then push neighbors. Pushing before popping can cause duplicates.
- **Confusing with "Search a 2D Matrix" (#74 and #240).** Those are search problems (binary search). This is "kth smallest" (heap or binary search on value).
- **Binary search on value:** also works — O(n log(max-min)). The heap approach is O(k log k), better when k is small.

**The part that trips everyone up:** mark cells as **visited** when pushing (not when popping) to avoid duplicates. Also, push right AND down neighbors.

**The mistakes to remember:**
