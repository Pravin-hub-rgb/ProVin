**Problem:** Given a binary array `nums` and an integer `k`, return the maximum number of consecutive 1's in the array if you can flip at most `k` 0's. (LeetCode #1004)

**Link:** https://leetcode.com/problems/max-consecutive-ones-iii/

## Constraints

- `1 <= nums.length <= 10^5`
- `nums[i]` is either 0 or 1.
- `0 <= k <= nums.length`

**Follow-up:** Could you solve it in O(n) time and O(1) space?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could check every possible subarray, count the number of 0's in it, and if it's ≤ k, track the length.

### Brute Force Pseudocode

```
maxLen = 0
for i from 0 to n-1:
    for j from i to n-1:
        count zeros in nums[i..j]
        if zeros <= k:
            maxLen = max(maxLen, j - i + 1)
return maxLen
```

### Why Brute Force Is Slow

O(n²) — too slow for n = 10^5.

---

## Which Data Structure/Technique, and Why?

"Maximum consecutive 1's after flipping at most k 0's" → **Sliding Window (variable size)**. Maintain a window where the number of 0's ≤ k. Expand right; if 0's > k, shrink left. O(n) time, O(1) space.

**Signal in the problem:** "maximum consecutive 1's" + "flip at most k 0's" → sliding window with at most k zeros in window.

---

## Optimized Approach (Sliding Window)

Variable-size window. Expand `right`; if `nums[right] == 0`, increment `zeros`. While `zeros > k`, shrink `left` (if `nums[left] == 0`, decrement `zeros`, `left++`). Update `maxLen = right - left + 1`.

### Pseudocode

```
left = 0, zeros = 0, maxLen = 0
for right from 0 to n-1:
    if nums[right] == 0: zeros++
    while zeros > k:
        if nums[left] == 0: zeros--
        left++
    maxLen = max(maxLen, right - left + 1)
return maxLen
```

### Java Code

```java
class Solution {
    public int longestOnes(int[] nums, int k) {
        int left = 0, zeros = 0, maxLen = 0;

        for (int right = 0; right < nums.length; right++) {
            if (nums[right] == 0) zeros++;
            while (zeros > k) {
                if (nums[left] == 0) zeros--;
                left++;
            }
            maxLen = Math.max(maxLen, right - left + 1);
        }
        return maxLen;
    }
}
```

### Line-by-line

- `if nums[right] == 0: zeros++` — count zeros in window.
- `while zeros > k` — too many zeros, shrink from left.
- `if nums[left] == 0: zeros--` — removing a zero from window.
- `left++` — shrink window.
- `maxLen = Math.max(maxLen, right - left + 1)` — update best.

## Complexity

- Time: O(n) — each character enters and leaves the window at most once.
- Space: O(1) — three variables.

## Common Mistakes

- **Not using `while` instead of `if`** — after shrinking, zeros might still be > k.
- **Window size off-by-one:** `right - left + 1`.
- **Assuming k=0 works differently** — k=0 means no flips allowed, just longest run of 1's. The algorithm handles this correctly.

## How to Explain (interview)

**Opening:** Max Consecutive Ones III asks for the longest subarray of 1's after flipping at most k zeros. Sliding window: expand right, count zeros; when zeros > k, shrink left. O(n) time, O(1) space.

**The basic flow:**
```java
int left = 0, zeros = 0, maxLen = 0;
for (int right = 0; right < nums.length; right++) {
    if (nums[right] == 0) zeros++;
    while (zeros > k) {
        if (nums[left] == 0) zeros--;
        left++;
    }
    maxLen = Math.max(maxLen, right - left + 1);
}
return maxLen;
```

**The part that trips everyone up:** using `while` instead of `if` for shrinking — after removing one zero, zeros might still be > k.

**The mistakes to remember:**
- Using `if` instead of `while` for shrinking
- Window size is `right - left + 1`
- Not handling k = 0 correctly (algorithm handles it automatically)
