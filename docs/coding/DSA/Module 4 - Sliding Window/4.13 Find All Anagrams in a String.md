**Problem:** Given two strings `s` and `p`, return an array of all the start indices of `p`'s anagrams in `s`. You may return the answer in any order. (LeetCode #438)

**Link:** https://leetcode.com/problems/find-all-anagrams-in-a-string/

---

## What This Problem Is Asking (Simple Terms)

You have two strings `s` and `p`. You need to find all starting indices in `s` where a substring of length `p.length()` is an anagram (permutation) of `p`.

For example, `s = "cbaebabacd"`, `p = "abc"` → substrings of length 3 that are anagrams of "abc": "cba" (index 0), "abc" (index 6) → output `[0, 6]`.

You return a list of starting indices, not the substrings themselves.

---

## Example 1

**Input:** `s = "cbaebabacd"`, `p = "abc"`

**Output:** `[0,6]`

**Explanation:** Substrings starting at index 0 ("cba") and index 6 ("abc") are anagrams of "abc".

---

## Example 2

**Input:** `s = "abab"`, `p = "ab"`

**Output:** `[0,1,2]`

**Explanation:** Substrings of length 2 that are anagrams of "ab": "ab" (index 0), "ba" (index 1), "ab" (index 2).

---

## Constraints

- `1 <= s.length, p.length <= 3 * 10^4`
- `s` and `p` consist of lowercase English letters.

**Follow-up:** Could you solve it in O(n) time and O(1) space?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could extract every substring of `s` with length `p.length()`, check if it's an anagram of `p`, and record the starting index if it is.

### Brute Force Pseudocode

```
result = []
for i from 0 to s.length() - p.length():
    substr = s[i..i+p.length()-1]
    if isAnagram(substr, p): result.add(i)
return result
```

### Why Brute Force Is Slow

O(n × m) where n = s.length(), m = p.length(). For large inputs, too slow.

---

## Which Data Structure/Technique, and Why?

"Find all anagrams of p in s" → **Fixed-Size Sliding Window**. Maintain a frequency map of characters in `p` and a sliding window of size `p.length()` in `s`. Slide the window one character at a time; if frequency maps match, record the starting index. O(n) time, O(26) = O(1) space.

**Signal in the problem:** "anagrams" + "substring" → fixed-size sliding window with frequency map.

---

## Optimized Approach (Fixed-Size Sliding Window)

1. Count character frequencies in `p`.
2. Initialize a sliding window of size `p.length()` in `s` with its frequency map.
3. If maps match, record index 0.
4. Slide window: remove `s[left]`, add `s[right]`, update map, check match.
5. Record all matching start indices.

### Pseudocode

```
countP = frequency map of p
countS = frequency map of s[0..p.length()-1]
result = []
if countP == countS: result.add(0)
for right from p.length() to s.length()-1:
    countS[s[right]]++
    countS[s[right - p.length()]]--
    if countP == countS: result.add(right - p.length() + 1)
return result
```

### Java Code

```java
class Solution {
    public List<Integer> findAnagrams(String s, String p) {
        List<Integer> result = new ArrayList<>();
        if (s.length() < p.length()) return result;

        int[] countP = new int[26];
        int[] countS = new int[26];

        for (int i = 0; i < p.length(); i++) {
            countP[p.charAt(i) - 'a']++;
            countS[s.charAt(i) - 'a']++;
        }

        if (Arrays.equals(countP, countS)) result.add(0);

        for (int i = p.length(); i < s.length(); i++) {
            countS[s.charAt(i) - 'a']++;
            countS[s.charAt(i - p.length()) - 'a']--;
            if (Arrays.equals(countP, countS)) result.add(i - p.length() + 1);
        }
        return result;
    }
}
```

### Line-by-line

- `countP[p.charAt(i) - 'a']++` — build frequency map of p.
- `countS[s.charAt(i) - 'a']++` — build initial window frequency map.
- `Arrays.equals(countP, countS)` — check if frequency maps match.
- Slide window: add new char `s[i]`, remove leftmost char `s[i - p.length()]`.
- Check match after each slide; record start index `i - p.length() + 1`.

## Complexity

- Time: O(n) where n = s.length() — each character processed once.
- Space: O(1) — two arrays of 26.

## Common Mistakes

- **Not handling `s.length() < p.length()`** — return empty list immediately.
- **Using HashMap instead of array** — array of 26 is faster and simpler for lowercase letters.
- **Forgetting to remove the leftmost char when sliding** — window would grow unbounded.
- **Off-by-one in start index** — start index is `i - p.length() + 1`, not `i - p.length()`.
