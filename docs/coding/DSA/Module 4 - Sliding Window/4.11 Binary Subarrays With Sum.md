**Problem:** Given a binary array `nums` and an integer `goal`, return the number of non-empty subarrays that sum to `goal`. (LeetCode #930)

**Link:** https://leetcode.com/problems/binary-subarrays-with-sum/

---

## What This Problem Is Asking (Simple Terms)

You have a binary array (0s and 1s) and a target sum `goal`. You need to count the number of contiguous subarrays whose sum equals exactly `goal`.

Since the array is binary, the sum of a subarray equals the number of 1's in it.

For example, `nums = [1,0,1,0,1]`, `goal = 2` → subarrays with sum 2: `[1,0,1]`, `[1,0,1]` (indices 0-2 and 2-4), `[0,1,0,1]` (indices 1-4)... wait, let me recount. `nums = [1,0,1,0,1]`, target = 2:
- [1,0,1] (indices 0-2) sum = 2 ✓
- [1,0,1] (indices 2-4) sum = 2 ✓
- [0,1,0,1] (indices 1-4) sum = 2 ✓
So output is 3.

You return just the count.

---

## Example 1

**Input:** `nums = [1,0,1,0,1]`, `goal = 2`

**Output:** `3`

**Explanation:** The 3 subarrays are shown above.

---

## Example 2

**Input:** `nums = [0,0,0,0,0]`, `goal = 0`

**Output:** `15`

**Explanation:** All subarrays sum to 0. There are 5+4+3+2+1 = 15 subarrays.

---

## Constraints

- `1 <= nums.length <= 3 * 10^4`
- `nums[i]` is either 0 or 1.
- `0 <= goal <= nums.length`

**Follow-up:** Could you solve it in O(n) time and O(1) space?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could check every possible subarray, compute its sum, and count those equal to `goal`.

### Brute Force Pseudocode

```
count = 0
for i from 0 to n-1:
    sum = 0
    for j from i to n-1:
        sum += nums[j]
        if sum == goal: count++
return count
```

### Why Brute Force Is Slow

O(n²) — too slow for n = 3 * 10^4.

---

## Which Data Structure/Technique, and Why?

"Count subarrays with sum = goal" with binary array → **Prefix Sum + HashMap** OR **Sliding Window (at most trick)**.

Since the array is binary (non-negative), the prefix sum is non-decreasing. We can use the "at most k" trick:
- `count(sum == goal) = count(sum <= goal) - count(sum <= goal - 1)`
- `count(sum <= k)` can be done with sliding window in O(n).

**Signal in the problem:** "number of subarrays with sum = goal" + binary array → prefix sum + hashmap OR sliding window with at-most trick.

---

## Optimized Approach (Prefix Sum + HashMap)

Track cumulative sum. For each position, check if `prefixSum - goal` has been seen before. Count all such occurrences.

### Pseudocode

```
count = {0: 1}
prefixSum = 0, result = 0
for x in nums:
    prefixSum += x
    result += count[prefixSum - goal]
    count[prefixSum]++
return result
```

### Java Code

```java
class Solution {
    public int numSubarraysWithSum(int[] nums, int goal) {
        Map<Integer, Integer> count = new HashMap<>();
        count.put(0, 1);
        int prefixSum = 0, result = 0;

        for (int x : nums) {
            prefixSum += x;
            result += count.getOrDefault(prefixSum - goal, 0);
            count.put(prefixSum, count.getOrDefault(prefixSum, 0) + 1);
        }
        return result;
    }
}
```

### Line-by-line

- `count.put(0, 1)` — empty prefix sum seen once.
- `prefixSum += x` — running sum.
- `result += count.getOrDefault(prefixSum - goal, 0)` — if `prefixSum - goal` was seen before, those subarrays end at current position.
- `count.put(prefixSum, ...)` — record current prefix sum.

## Complexity

- Time: O(n) — single pass.
- Space: O(n) — hash map can have up to n entries.

## Common Mistakes

- **Not initializing `count[0] = 1`** — subarrays starting at index 0 would be missed.
- **Using sliding window incorrectly** — sliding window works for "at most k" but not "exactly k" directly. Use prefix sum + hashmap, or use `atMost(goal) - atMost(goal-1)`.
- **Array index out of bounds** — `prefixSum` can exceed array bounds if using array instead of HashMap.

**The basic flow:**
