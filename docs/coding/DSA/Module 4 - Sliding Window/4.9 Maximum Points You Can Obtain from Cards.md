# 4.9 Maximum Points You Can Obtain from Cards

**Tier 2 problem.** (LeetCode #1423)

**Problem:** Given an array of card points and k, pick exactly k cards from either end (left or right) to maximize the total points. (LeetCode #1423)

**Link:** https://leetcode.com/problems/maximum-points-you-can-obtain-from-cards/

---

## Which Technique, and Why?

"Pick k cards from ends to maximize sum" → **Sliding Window (fixed size, inverted)**. Instead of picking k from the ends, think of it as: total sum - minimum sum of a contiguous subarray of size `n - k`. Find the minimum sum window of size `n - k`, subtract from total. O(n) time, O(1) space.

**Signal in the problem:** "pick from either end" + "maximize" → inverted sliding window (min sum of middle).

## Approach

Total sum of all cards. We pick k from ends, leaving `n - k` in the middle (contiguous). To maximize picked, minimize the middle sum. Find min sum of a contiguous subarray of size `n - k` using a fixed-size sliding window. Answer = total - minMiddle.

## Pseudocode

```
n = cards.length
if k == n: return total sum
windowSize = n - k
windowSum = sum of first windowSize elements
minSum = windowSum
for i from windowSize to n-1:
    windowSum += cards[i] - cards[i - windowSize]
    minSum = min(minSum, windowSum)
return total - minSum
```

## Java Code

```java
class Solution {
    public int maxScore(int[] cardPoints, int k) {
        int n = cardPoints.length;
        int total = 0;
        for (int c : cardPoints) total += c;

        if (k == n) return total;

        int windowSize = n - k;
        int windowSum = 0;
        for (int i = 0; i < windowSize; i++) windowSum += cardPoints[i];

        int minSum = windowSum;
        for (int i = windowSize; i < n; i++) {
            windowSum += cardPoints[i] - cardPoints[i - windowSize];
            minSum = Math.min(minSum, windowSum);
        }

        return total - minSum;
    }
}
```

## Line-by-line

- `total` = sum of all cards.
- If `k == n`, take all → return total.
- `windowSize = n - k` — the middle subarray we leave behind.
- First window: sum of first `windowSize` elements.
- Slide: add new element, remove old. Track min.
- Answer = `total - minSum` (maximize picked = minimize left-behind).

## Complexity

- Time: O(n) — two passes (total + sliding window).
- Space: O(1).

## Common Mistakes

- **Trying to pick from ends directly.** You'd need to consider all splits (k from left, 0 from right; k-1 left, 1 right; ...). The inverted approach (min middle) is simpler.
- **Window size = k instead of n-k.** The window is the middle (left-behind), not the picked cards. Size = n - k.
- **Not handling k == n.** If k == n, windowSize = 0 → division by zero or empty window. Return total directly.
- **Off-by-one in the slide.** `windowSum += cards[i] - cards[i - windowSize]` — the removed element is `i - windowSize`.

## How to Explain (interview)

**Opening:** Maximum Points from Cards picks k cards from either end to maximize sum. Instead of trying all splits, invert: total sum − minimum sum of a contiguous middle subarray of size n-k. Fixed-size sliding window finds the min middle. O(n) time, O(1) space.

**The basic flow:**
```java
int total = sum(cards);
if (k == n) return total;
int wSize = n - k, wSum = sum(first wSize), minSum = wSum;
for (int i = wSize; i < n; i++) {
    wSum += cards[i] - cards[i - wSize];
    minSum = Math.min(minSum, wSum);
}
return total - minSum;
```

**The part that trips everyone up:** the window is the **middle** (left-behind), size `n - k`, not the picked cards. Also handle `k == n` (window size 0).

**The mistakes to remember:**
- Window size = n - k (not k)
- Not handling k == n (empty window)
- Trying all splits (O(k) instead of O(n))
- Off-by-one in the slide: `cards[i - windowSize]`
