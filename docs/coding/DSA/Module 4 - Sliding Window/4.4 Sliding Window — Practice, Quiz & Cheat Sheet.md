## Mini Quiz

1. Why must `left` only move forward (never reset to 0) in the longest substring problem?
2. Why does the minimum subarray sum problem require positive integers?
3. What is the difference between fixed-size and variable-size sliding window?
4. What is the window size formula (inclusive both ends)?
5. What is the time complexity of sliding window, and why?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. Resetting `left` to 0 would re-examine characters already processed, making it O(n²). Since the window [left, right] always contains unique characters, moving `left` past the duplicate's last position is sufficient — everything before that is already "clean."
2. Sliding window relies on monotonicity: shrinking the window (removing elements from the left) must decrease (or at least not increase) the sum. With positive numbers, removing elements always decreases the sum, so `while (sum >= target)` correctly finds the minimum window. With negatives, shrinking could increase the sum, breaking the logic.
3. Fixed-size: window size is given (k). Slide by one — add new element on right, remove old on left. O(n). Variable-size: window grows/shrinks based on a condition (e.g., "no duplicates" or "sum ≥ target"). Both pointers move right; left only moves when the condition is violated.
4. `right - left + 1` (both ends inclusive). Not `right - left`.
5. O(n) — each element enters the window (right++) and leaves the window (left++) at most once. Total operations = 2n = O(n), regardless of the inner while loop (amortized).

</details>

## One-Page Cheat Sheet

**Core pattern:** maintain a window [left, right]. Expand right to include new elements; shrink left when the condition is violated. The window always represents a valid candidate. Each element enters and leaves at most once → O(n).

**Variable-size template:**
```java
int left = 0, maxLen = 0;
for (int right = 0; right < n; right++) {
    // add nums[right] to window
    while (window is invalid) { left++; }  // shrink
    maxLen = Math.max(maxLen, right - left + 1);
}
```

**Minimum window template:**
```java
int left = 0, sum = 0, minLen = INF;
for (int right = 0; right < n; right++) {
    sum += nums[right];
    while (sum >= target) {
        minLen = Math.min(minLen, right - left + 1);
        sum -= nums[left++];
    }
}
```

**Complexities:** O(n) time, O(1) space (plus O(k) for the hash map in the unique-chars variant).

**When to use Sliding Window:** "longest/shortest contiguous subarray/substring satisfying a condition," sum/average/count over a range with a target, "at most K distinct," "no repeating characters."

## In Your Own Words

1. Why does sliding window achieve O(n) time even with an inner while loop?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The inner while loop's total work across all iterations is O(n), not O(n²). Each element is added to the window once (right++) and removed at most once (left++). So across the entire algorithm, left moves at most n times and right moves at most n times — total 2n operations = O(n). The inner loop is amortized, not per-iteration.

</details>

2. When does sliding window NOT work?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Sliding window requires monotonicity — shrinking the window must decrease (or not increase) the metric you're tracking. This holds for positive numbers (sum decreases when you remove elements). With negative numbers, shrinking can increase the sum, breaking the logic. For arrays with negatives, use prefix sum + binary search instead. Also, if the condition isn't "contiguous subarray," sliding window doesn't apply.

</details>

3. What's the difference between sliding window and two pointers?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Sliding window: both pointers move in the same direction (left to right), maintaining a contiguous range. Used for "longest/shortest contiguous subarray satisfying a condition." Two pointers: pointers often start at opposite ends and converge (or move at different speeds). Used for pair-finding on sorted arrays, palindromes, in-place compaction. If both pointers only move forward and maintain a window → sliding window. If they converge from both ends → two pointers.

</details>
