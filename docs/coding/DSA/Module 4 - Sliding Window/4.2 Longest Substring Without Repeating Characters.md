# 4.2 Longest Substring Without Repeating Characters

**Problem:** Given a string, find the length of the longest substring without repeating characters. (LeetCode #3)

**Link:** https://leetcode.com/problems/longest-substring-without-repeating-characters/

---

## Which Technique, and Why?

"Longest substring without repeating characters" → contiguous substring + uniqueness condition → **Sliding Window (variable size)**. Maintain a window of unique characters; expand right, shrink left on duplicate.

Why not brute force? Checking all substrings for uniqueness is O(n³) (or O(n²) with a set). Sliding window is O(n) because each character enters and leaves the window once.

**Signal in the problem:** "longest substring" + "without repeating" → sliding window with a "last seen index" map.

## Approach

Two pointers `left` and `right` (both move right). A HashMap tracks the last index of each character. Expand `right`; if `s[right]` was seen within the current window, move `left` past its last occurrence. Update max length.

## Pseudocode

```
lastSeen = empty map (char -> index)
left = 0, maxLen = 0
for right from 0 to n-1:
    c = s[right]
    if c in lastSeen and lastSeen[c] >= left:
        left = lastSeen[c] + 1
    lastSeen[c] = right
    maxLen = max(maxLen, right - left + 1)
return maxLen
```

## Java Code

```java
class Solution {
    public int lengthOfLongestSubstring(String s) {
        Map<Character, Integer> lastSeen = new HashMap<>();
        int left = 0, maxLen = 0;

        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);
            if (lastSeen.containsKey(c) && lastSeen.get(c) >= left) {
                left = lastSeen.get(c) + 1;
            }
            lastSeen.put(c, right);
            maxLen = Math.max(maxLen, right - left + 1);
        }
        return maxLen;
    }
}
```

## Line-by-line

- `lastSeen` maps char → its most recent index.
- `right` expands the window by including `s[right]`.
- If `c` was seen **within the current window** (`lastSeen.get(c) >= left`), move `left` to `lastSeen.get(c) + 1` — shrink past the duplicate.
- Update `lastSeen[c] = right`.
- `maxLen` tracks the best window size (`right - left + 1`).
- `left` only moves forward → O(n) total.

## Complexity

- Time: O(n) — each character enters and leaves the window at most once.
- Space: O(min(n, 26)) — at most 26 distinct chars for lowercase (or n for general ASCII).

## Common Mistakes

- **Resetting `left = 0` on a duplicate.** Only shrink past the duplicate's last position. Resetting to 0 makes it O(n²).
- **Not checking `lastSeen.get(c) >= left`.** A char seen *before* the current window is irrelevant. Without this check, you'd incorrectly shrink.
- **Window size off-by-one:** size is `right - left + 1` (both inclusive), not `right - left`.
- **Using a Set instead of a map of last indices.** A set works (add on expand, remove on shrink) but is slightly more code. The "last seen index" approach is cleaner.

## How to Explain (interview)

**Opening:** Longest Substring Without Repeating Characters asks for the longest substring with all unique characters. Sliding window: expand right, and when a duplicate enters, shrink left to just past the duplicate's last position. Use a HashMap tracking each char's last index. O(n) time because left and right each move at most n times.

**The basic flow:**
```java
Map<Character, Integer> lastSeen = new HashMap<>();
int left = 0, maxLen = 0;
for (int right = 0; right < s.length(); right++) {
    char c = s.charAt(right);
    if (lastSeen.containsKey(c) && lastSeen.get(c) >= left)
        left = lastSeen.get(c) + 1;
    lastSeen.put(c, right);
    maxLen = Math.max(maxLen, right - left + 1);
}
```

**The part that trips everyone up:** `left` moves to `lastSeen[c] + 1`, not to 0. And you must check `lastSeen.get(c) >= left` — a char seen before the current window doesn't count as a duplicate.

**The mistakes to remember:**
- Resetting left to 0 (O(n²) instead of O(n))
- Not checking `>= left` (incorrect shrinking)
- Window size is `right - left + 1`, not `right - left`
