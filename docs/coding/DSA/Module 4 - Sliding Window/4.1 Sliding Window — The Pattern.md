**Problem:** Given an integer array `nums` and an integer `k`, return the maximum sum of any **contiguous** subarray of size `k`.

**Link:** https://leetcode.com/problems/maximum-average-subarray-i/ (similar pattern)

---

## What This Problem Is Asking (Simple Terms)

You have an array of numbers and a fixed window size `k`. You need to find the **maximum sum** of any contiguous subarray of exactly `k` elements.

For example, `nums = [1, 12, -5, -6, 50, 3]`, `k = 4`:
- `[1, 12, -5, -6]` → sum = 2
- `[12, -5, -6, 50]` → sum = 51 ← maximum
- `[-5, -6, 50, 3]` → sum = 46

Answer: `51`

---

## Example 1

**Input:** `nums = [1,12,-5,-6,50,3]`, `k = 4`

**Output:** `51`

**Explanation:** Maximum sum is `[12, -5, -6, 50] = 51`.

---

## Example 2

**Input:** `nums = [5,-1,-3,8]`, `k = 3`

**Output:** `4`

**Explanation:** Maximum sum is `[5,-1,-3]` = `5`, `[ -1,-3,8]` = `4`. Wait, `[5,-1,-3]` = `3`, `[-1,-3,8]` = `4`. Max is `4`.

---

## Constraints

- `1 <= k <= nums.length <= 10^5`
- `-10^5 <= nums[i] <= 10^4`

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

For every starting position `i`, take the next `k` elements, sum them, and track the maximum.

### Brute Force Pseudocode

```
maxSum = -infinity
for i from 0 to n-k:
    currentSum = 0
    for j from i to i+k-1:
        currentSum += nums[j]
    maxSum = max(maxSum, currentSum)
return maxSum
```

### Why Brute Force Is Slow

Outer loop runs ~n times, inner loop runs k times. O(n×k). For large arrays, this is slow.

---

## Which Data Structure/Technique, and Why?

The window slides one step at a time. When you slide from `[i, i+k-1]` to `[i+1, i+k]`:

- Remove `nums[i]` (leaves the window)
- Add `nums[i+k]` (enters the window)

You don't need to recompute the whole sum. Just **subtract the outgoing** and **add the incoming**. O(1) per step.

**Signal in the problem:** "subarray of size k", "contiguous", "maximum sum" → sliding window with **fixed window size k**.

---

## Optimized Approach (Sliding Window — Fixed Size)

1. Compute sum of first `k` elements (first window).
2. Slide window: remove leftmost, add new right element, update max.
3. Repeat until end.

### Pseudocode

```
windowSum = sum of nums[0..k-1]
maxSum = windowSum
for i from k to n-1:
    windowSum = windowSum - nums[i-k] + nums[i]
    maxSum = max(maxSum, windowSum)
return maxSum
```

### Java Code

```java
class Solution {
    public int maxAverageSum(int[] nums, int k) {
        int windowSum = 0;
        for (int i = 0; i < k; i++) {
            windowSum += nums[i];
        }
        int maxSum = windowSum;
        
        for (int i = k; i < nums.length; i++) {
            windowSum = windowSum - nums[i - k] + nums[i];
            maxSum = Math.max(maxSum, windowSum);
        }
        return maxSum;
    }
}
```

### Line-by-line

- `windowSum` tracks sum of current window of size `k`.
- First loop builds the initial window.
- Second loop slides: subtract element leaving (`nums[i-k]`), add element entering (`nums[i]`).
- Track max seen.

## Complexity

- Time: O(n) — each element added and subtracted once.
- Space: O(1) — just a few variables.

## Common Mistakes

- **Off-by-one in window bounds.** Window covers indices `[i-k+1, i]` after slide.
- **Forgetting to initialize `maxSum` with first window sum.**
- **Using `i < nums.length - k` loop condition** instead of starting loop at `k`.

## How to Explain (interview)

**Opening:** Maximum sum of size-k subarray → sliding window with fixed window size. Compute first window sum, then slide: subtract leftmost, add new rightmost. O(n) time, O(1) space.

**The basic flow:**
```java
int windowSum = sum of first k elements;
int maxSum = windowSum;
for (int i = k; i < nums.length; i++) {
    windowSum = windowSum - nums[i - k] + nums[i];
    maxSum = Math.max(maxSum, windowSum);
}
return maxSum;
```

**The part that trips everyone up:** forgetting that the window slides one step at a time — you don't recompute the whole sum, just subtract the outgoing element and add the incoming one.

**The mistakes to remember:**
- Off-by-one: window covers `k` elements, indices `[i-k+1, i]` after slide.
- Not initializing `maxSum` with the first window sum.
- Using nested loop instead of sliding window.
