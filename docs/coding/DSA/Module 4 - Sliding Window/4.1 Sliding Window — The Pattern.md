## The Core Idea

Many problems ask for the **longest or shortest contiguous part** of an array/string that satisfies some rule. The naive approach checks all subarrays → O(n²) or O(n³).

**Sliding Window** maintains a window [left, right] that always represents a valid candidate. You expand `right` to include new elements; when the window becomes invalid, you shrink `left` until it's valid again. Each element enters and leaves the window at most once → **O(n)**.

**Two variants:**

1. **Fixed-size window:** window size is given (k). Slide by one: add the new element on the right, remove the old one on the left. O(n).
2. **Variable-size window:** window grows/shrinks based on a condition. Expand right; shrink left when invalid. O(n) (each pointer moves at most n times).

## How to Recognize It

Think "Sliding Window" when:
- The problem asks for the **longest/shortest contiguous** subarray or substring satisfying a rule.
- The problem involves a **sum/average/count** over a contiguous range with a target.
- Keywords: "longest substring without repeating," "minimum size subarray sum," "maximum sum subarray of size k."
- The data is a string/array and the condition is about characters/elements within a range.

**Signal words:** "contiguous," "substring," "subarray," "longest," "shortest," "window," "at most K."

**Sliding Window vs Two Pointers:** Two pointers usually converge from both ends (sorted array, palindrome). Sliding window moves in one direction (left and right both move right, never left) over a contiguous range. If both pointers only move forward → sliding window.

## Worked Example: Longest Substring Without Repeating Characters

**Problem:** Find the length of the longest substring without repeating characters.

### Brute force (O(n³) or O(n²))

Check all substrings, verify no repeats. Too slow.

### Optimized (O(n)) — sliding window

```java
class Solution {
    public int lengthOfLongestSubstring(String s) {
        Map<Character, Integer> lastSeen = new HashMap<>(); // char → last index
        int left = 0, maxLen = 0;

        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);
            if (lastSeen.containsKey(c) && lastSeen.get(c) >= left) {
                left = lastSeen.get(c) + 1;  // shrink: move left past the duplicate
            }
            lastSeen.put(c, right);
            maxLen = Math.max(maxLen, right - left + 1);
        }
        return maxLen;
    }
}
```

**Line-by-line:**
- `right` expands the window by including `s[right]`.
- If `c` was seen within the current window (`lastSeen.get(c) >= left`), move `left` to `lastSeen.get(c) + 1` — shrinking past the duplicate.
- Update `lastSeen[c] = right`.
- `maxLen` tracks the best window size.
- `left` only moves forward (never resets to 0) → O(n) total.

**Key insight:** the window [left, right] always contains unique characters. When a duplicate enters, shrink from the left until unique again. Each character enters and leaves at most once.

## Common Mistakes

- **Resetting `left = 0` on a duplicate.** Don't — only shrink past the duplicate's last position. Resetting to 0 makes it O(n²).
- **Not checking `lastSeen.get(c) >= left`.** A character seen *before* the current window doesn't matter. Without this check, you'd incorrectly shrink.
- **Fixed vs variable confusion.** Fixed-size window: size is given, slide by one. Variable-size: grow/shrink by condition. Don't mix them.
- **Off-by-one in window size:** window size = `right - left + 1` (inclusive both ends).

## How to Explain (interview)

**Opening:** Sliding Window maintains a contiguous window [left, right] over an array/string. Expand right to include new elements; shrink left when a condition is violated. The window always represents a valid candidate. Each element enters and leaves at most once → O(n). Used for "longest/shortest contiguous subarray/substring satisfying a condition."

**The basic flow (variable size):**
```java
int left = 0, maxLen = 0;
for (int right = 0; right < n; right++) {
    // add s[right] to window
    while (window is invalid) { left++; }  // shrink
    maxLen = Math.max(maxLen, right - left + 1);
}
```

**The part that trips everyone up:** `left` only moves **forward** (never resets to 0). Resetting to 0 turns O(n) into O(n²). Also check `lastSeen >= left` before shrinking — a char seen before the current window is irrelevant.

**The mistakes to remember:**
- Resetting left to 0 on duplicate (O(n²))
- Not checking `lastSeen >= left` (incorrect shrinking)
- Confusing fixed-size (given k) with variable-size (condition-based)
- Window size is `right - left + 1`, not `right - left`
