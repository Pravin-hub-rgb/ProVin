**Problem:** You are given a string `s` and an integer `k`. You can choose any character of the string and change it to any other uppercase English character. You can perform this operation at most `k` times.

Return the length of the longest substring containing the same letter you can get after performing the above operations. (LeetCode #424)

**Link:** https://leetcode.com/problems/longest-repeating-character-replacement/

---

## What This Problem Is Asking (Simple Terms)

You have a string of uppercase letters and can change up to `k` characters to any other uppercase letter. You need to find the longest substring where all characters are the same after at most `k` changes.

For example, `s = "ABAB"`, `k = 2` → change both A's to B's → `"BBBB"`, length 4.

You return just the length, not the substring itself.

---

## Example 1

**Input:** `s = "ABAB"`, `k = 2`

**Output:** `4`

**Explanation:** Replace the two 'A's with two 'B's or vice versa → `"BBBB"` or `"AAAA"`, length 4.

---

## Example 2

**Input:** `s = "AABABBA"`, `k = 1`

**Output:** `4`

**Explanation:** Replace the one 'A' in the middle with 'B' → `"AABBBBA"`. The substring `"BBBB"` has length 4.

---

## Constraints

- `1 <= s.length <= 10^5`
- `s` consists of only uppercase English letters.
- `0 <= k <= s.length`

**Follow-up:** Could you solve it in O(n) time?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could check every possible substring, count character frequencies, and see if `windowSize - maxFreq <= k`.

### Brute Force Pseudocode

```
maxLen = 0
for i from 0 to n-1:
    for j from i to n-1:
        count = frequency map of s[i..j]
        maxFreq = max(count.values())
        if (j - i + 1) - maxFreq <= k:
            maxLen = max(maxLen, j - i + 1)
return maxLen
```

### Why Brute Force Is Slow

O(n³) — O(n²) substrings, each frequency count O(n). Too slow for n = 10^5.

---

## Which Data Structure/Technique, and Why?

"Longest substring containing the same letter after replacing at most k characters" → **Sliding Window (variable size)**. Maintain a window and a frequency map. The window is valid if `windowSize - maxFreq <= k` (replacements needed ≤ k). Expand right; when invalid, shrink left. O(n) time, O(26) = O(1) space.

**Signal in the problem:** "longest substring" + "replace at most k" → sliding window with frequency count and validity check.

---

## Optimized Approach (Sliding Window)

Variable-size window. Expand `right`, add char to freq map. Track `maxFreq` in the window. While `windowSize - maxFreq > k` (too many replacements needed), shrink `left` (decrement freq, `left++`). Update `maxLen`.

**Key trick:** you don't need to decrement `maxFreq` when shrinking — it's okay to keep a "stale" `maxFreq` because it only makes the window harder to expand (conservative), and the answer is still correct. This keeps it O(n).

### Pseudocode

```
count = array of 26 zeros
left = 0, maxFreq = 0, maxLen = 0
for right from 0 to n-1:
    count[s[right] - 'A']++
    maxFreq = max(maxFreq, count[s[right] - 'A'])
    while (right - left + 1) - maxFreq > k:
        count[s[left] - 'A']--
        left++
    maxLen = max(maxLen, right - left + 1)
return maxLen
```

### Java Code

```java
class Solution {
    public int characterReplacement(String s, int k) {
        int[] count = new int[26];
        int left = 0, maxFreq = 0, maxLen = 0;

        for (int right = 0; right < s.length(); right++) {
            count[s.charAt(right) - 'A']++;
            maxFreq = Math.max(maxFreq, count[s.charAt(right) - 'A']);
            while ((right - left + 1) - maxFreq > k) {
                count[s.charAt(left) - 'A']--;
                left++;
            }
            maxLen = Math.max(maxLen, right - left + 1);
        }
        return maxLen;
    }
}
```

### Line-by-line

- `count[s.charAt(right) - 'A']++` — add current char to frequency map.
- `maxFreq = Math.max(maxFreq, ...)` — track the most frequent char in current window.
- `while (right - left + 1) - maxFreq > k` — window needs more than k replacements, shrink.
- `count[s.charAt(left) - 'A']--` — remove left char from window.
- `left++` — shrink window.
- `maxLen = Math.max(maxLen, right - left + 1)` — update best.

## Complexity

- Time: O(n) — each character enters and leaves the window at most once.
- Space: O(1) — array of 26.

## Common Mistakes

- **Not using `while` instead of `if`** — after shrinking, window might still be invalid.
- **Decrementing `maxFreq` when shrinking** — not needed; stale `maxFreq` is conservative and correct.
- **Window size off-by-one:** `right - left + 1`.
- **Assuming lowercase letters** — problem says uppercase only (A-Z), so array of 26.

## How to Explain (interview)

**Opening:** Longest Repeating Character Replacement asks for the longest substring of identical characters after at most k replacements. Sliding window: expand right, track max frequency; if `windowSize - maxFreq > k`, shrink left. The key insight: `maxFreq` doesn't need to decrease when shrinking — a stale (higher) maxFreq just makes the window harder to expand, which is safe. O(n) time, O(1) space.

**The basic flow:**
```java
int[] count = new int[26];
int left = 0, maxFreq = 0, maxLen = 0;
for (int right = 0; right < s.length(); right++) {
    count[s.charAt(right) - 'A']++;
    maxFreq = Math.max(maxFreq, count[s.charAt(right) - 'A']);
    while ((right - left + 1) - maxFreq > k) {
        count[s.charAt(left) - 'A']--;
        left++;
    }
    maxLen = Math.max(maxLen, right - left + 1);
}
return maxLen;
```

**The part that trips everyone up:** not decrementing `maxFreq` when shrinking — it seems wrong but is actually correct and necessary for O(n).

**The mistakes to remember:**
- Using `if` instead of `while` for shrinking
- Decrementing maxFreq unnecessarily
- Window size is `right - left + 1`
