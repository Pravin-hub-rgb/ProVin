**Tier 2 problem.** (LeetCode #424)

**Problem:** Given a string, find the length of the longest substring containing the same letter after replacing at most k characters. (LeetCode #424)

**Link:** https://leetcode.com/problems/longest-repeating-character-replacement/

---

## Which Technique, and Why?

"Longest substring with at most k replacements" → **Sliding Window (variable size)**. Maintain a window [left, right] and a frequency map of characters in the window. The window is valid if `windowSize - maxFreq <= k` (replacements needed ≤ k). Expand right; when invalid, shrink left. O(n) time, O(26) = O(1) space.

**Signal in the problem:** "longest substring" + "replace at most k" → sliding window with frequency count and a validity check.

## Approach

Variable-size window. Expand right, add char to freq map. Track maxFreq in the window. While `windowSize - maxFreq > k` (too many replacements needed), shrink left (decrement freq, left++). Update maxLen.

**Key trick:** you don't need to decrement maxFreq when shrinking — it's okay to keep a "stale" maxFreq because it only makes the window harder to expand (conservative), and the answer is still correct. This keeps it O(n).

## Pseudocode

```
freq = empty map (char -> count)
left = 0, maxFreq = 0, maxLen = 0
for right from 0 to n-1:
    freq[s[right]]++
    maxFreq = max(maxFreq, freq[s[right]])
    while (right - left + 1) - maxFreq > k:
        freq[s[left]]--
        left++
    maxLen = max(maxLen, right - left + 1)
return maxLen
```

## Java Code

```java
class Solution {
    public int characterReplacement(String s, int k) {
        int[] freq = new int[26];
        int left = 0, maxFreq = 0, maxLen = 0;

        for (int right = 0; right < s.length(); right++) {
            freq[s.charAt(right) - 'a']++;
            maxFreq = Math.max(maxFreq, freq[s.charAt(right) - 'a']);

            while ((right - left + 1) - maxFreq > k) {
                freq[s.charAt(left) - 'a']--;
                left++;
            }
            maxLen = Math.max(maxLen, right - left + 1);
        }
        return maxLen;
    }
}
```

## Line-by-line

- `freq[26]` — frequency of each letter in the current window.
- `maxFreq` — max frequency of any single char in the window (tracked, not recomputed).
- `(windowSize - maxFreq) > k` — replacements needed exceed k → invalid → shrink.
- `maxFreq` is not decremented when shrinking — this is a known optimization (stale maxFreq only makes the window harder to expand, never incorrect).

## Complexity

- Time: O(n) — right and left each move at most n times.
- Space: O(1) — fixed array of 26.

## Common Mistakes

- **Recomputing maxFreq on every shrink.** O(n × 26) — works but slower. The stale-maxFreq trick keeps it O(n).
- **Using `if` instead of `while`.** You may need to shrink multiple times. Use `while`.
- **Window size formula.** `right - left + 1`, not `right - left`.
- **Assuming only lowercase letters.** If uppercase or other chars are possible, use a HashMap.

## How to Explain (interview)

**Opening:** Longest Repeating Character Replacement finds the longest substring with at most k replacements to make all characters the same. Sliding window: expand right, track frequency and maxFreq. Window valid if `size - maxFreq <= k` (replacements needed ≤ k). When invalid, shrink left. O(n) time, O(1) space.

**The basic flow:**
```java
int[] freq = new int[26];
int left = 0, maxFreq = 0, maxLen = 0;
for (int right = 0; right < s.length(); right++) {
    freq[s.charAt(right) - 'a']++;
    maxFreq = Math.max(maxFreq, freq[s.charAt(right) - 'a']);
    while ((right - left + 1) - maxFreq > k) {
        freq[s.charAt(left) - 'a']--;
        left++;
    }
    maxLen = Math.max(maxLen, right - left + 1);
}
```

**The part that trips everyone up:** the stale `maxFreq` trick. You don't decrement maxFreq when shrinking — it only makes the window harder to expand (conservative). The answer is still correct because a larger maxFreq would only allow a larger window, and we track the max window size seen.

**The mistakes to remember:**
- Recomputing maxFreq on every shrink (O(n×26) instead of O(n))
- Using `if` instead of `while` for shrinking
- Window size is `right - left + 1`
- Assuming only lowercase (use HashMap for general chars)
