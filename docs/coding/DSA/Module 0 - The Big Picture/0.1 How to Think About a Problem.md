Tools (arrays, hash maps, loops) are just instruments. The real work is **how to think**. This file is the problem-solving playbook you'll use on every problem, in every module. Read it once, then come back to it when you feel stuck.

## The 5-Step Process

When you get a problem (LeetCode, interview, anywhere), follow this. Don't skip steps.

### Step 1: Understand First

**Never start coding before you understand the problem.**

- Read the problem **2–3 times**.
- What's the input? What's the output?
- Make a **small example** yourself and solve it by hand.
- Think about **edge cases**: empty array? single element? all same elements? negatives? zeros?

Example — "Find Maximum in Array":
```
Input:  [3, 1, 4, 1, 5, 9, 2, 6]   → Output: 9
Input:  [10]                         → Output: 10   (single element is the max)
Input:  [-5, -2, -8]                 → Output: -2   (max among negatives too)
```

This step gives you **clarity** on what actually needs to be done.

### Step 2: Think Before You Code

**What would the brute force be?** Always think this first. Brute force = the most direct approach, with no optimization.

For "Find Maximum," brute force:
1. Take the first element as max.
2. Compare with the rest.
3. If a bigger one is found, update max.

```java
// Brute force — O(n) time, O(1) space
static int findMax(int[] arr) {
    int max = arr[0];
    for (int i = 1; i < arr.length; i++) {
        if (arr[i] > max) {
            max = arr[i];
        }
    }
    return max;
}
```

**Why start with brute force:**
- It works first (even if slow).
- It gives you ideas for optimization.
- In interviews, it shows the interviewer you can solve it — then optimize later.

**The 4-Question Framework — ask these on every problem:**
```
1. "What do I have?"    → input, its size, its type
2. "What do I need?"    → output, its type
3. "What's the gap?"    → the logic / loop / condition needed
4. "How to bridge?"     → the algorithm
```

Example — "Reverse an Array":
```
1. What do I have?   → [1, 2, 3, 4, 5], length = 5
2. What do I need?   → [5, 4, 3, 2, 1]
3. What's the gap?   → order has to be flipped
4. How to bridge?    → two pointers, swap from both ends
```

### Step 3: Draw It (Pen and Paper)

**This is the most underrated trick.**

Draw the array by hand. Write indices on top. Show with arrows what's happening.

```
Original:  [1, 2, 3, 4, 5]
Index:      0  1  2  3  4

Step 1: Swap arr[0] and arr[4]
        [5, 2, 3, 4, 1]

Step 2: Swap arr[1] and arr[3]
        [5, 4, 3, 2, 1]

Done!
```

Once you've drawn it, the pattern **starts showing itself**. Writing code becomes easier after.

### Step 4: Write Pseudocode (3-Line Plan)

Before code, write a 3–4 line plan:

```java
// Reverse Array — Plan:
// 1. Two pointers — left = 0, right = length - 1
// 2. While left < right — swap
// 3. Increment left, decrement right
```

Pseudocode gives you a **blueprint**. Code is just a translation of that blueprint.

### Step 5: Code, Then Refactor

```java
// Step 1: Write brute force (whatever comes to mind)
static int[] reverseArray(int[] arr) {
    int left = 0, right = arr.length - 1;
    while (left < right) {
        int temp = arr[left];
        arr[left] = arr[right];
        arr[right] = temp;
        left++;
        right--;
    }
    return arr;
}

// Step 2: Clean up (remove temp, use destructuring via a helper or just keep it clear)
```

First make it work, then clean it up. Don't chase perfection the first time. In an interview, get a working solution on the board, then optimize.

## Three Reusable Templates

These three templates solve ~80% of array problems. Recognize the pattern, use them.

### Template 1: Linear Scan (most common)

When you need to "traverse the whole array once."

```java
static int linearScan(int[] arr) {
    int result = arr[0];   // or some initial value
    for (int i = 1; i < arr.length; i++) {
        // make a decision on every element
        if (arr[i] > result) {
            result = arr[i];
        }
    }
    return result;
}
```

Use cases: Find Max, Find Min, Find Second Largest, Contains Duplicate.

### Template 2: Two Pointers (from both ends)

When the array is **sorted** or it's a **palindrome/symmetric** problem.

```java
static int twoPointers(int[] arr) {
    int left = 0, right = arr.length - 1;
    while (left < right) {
        // compare arr[left] and arr[right]
        // make a decision — move forward or stop
        left++;
        right--;
    }
    return 0; // placeholder
}
```

Use cases: Reverse Array, Valid Palindrome, Container With Most Water, Two Sum (sorted).

### Template 3: Swap Pattern (in-place transform)

When you need to **reverse** or **rearrange** without extra space.

```java
static int[] swapPattern(int[] arr) {
    int left = 0, right = arr.length - 1;
    while (left < right) {
        int temp = arr[left];
        arr[left] = arr[right];
        arr[right] = temp;
        left++;
        right--;
    }
    return arr;
}
```

Use cases: Reverse Array, Rotate Array, Sort Colors.

## Cheatsheet: Array Operations

| Concept | Syntax | Time |
|---|---|---|
| Access | `arr[i]` | O(1) |
| Search (linear) | loop | O(n) |
| Add at end (array) | not supported (fixed size) | — |
| Sort | `Arrays.sort(arr)` | O(n log n) |
| Reverse (in place) | two pointers | O(n) |
| Copy | `Arrays.copyOf(arr, n)` | O(n) |
| Length | `arr.length` | O(1) |

**Remember:**
- Index starts at 0, last = `length - 1`.
- `arr.length` is a field (no parens); `s.length()` is a method.
- Arrays are mutable; strings are immutable.

## Things That Go Wrong (Pitfalls)

### Off-by-One Error
```java
// WRONG
for (int i = 0; i <= arr.length; i++) { ... }  // arr[length] is out of bounds

// RIGHT
for (int i = 0; i < arr.length; i++) { ... }
```
Rule: `i < arr.length` (less than, not less-or-equal). Last index is `length - 1`.

### Sort Without Comparator (numbers)
```java
int[] nums = {100, 9, 80, 7};
Arrays.sort(nums);   // works for primitives (numeric sort) — fine
```
For objects, provide a comparator: `Arrays.sort(arr, (a, b) -> a - b)`.

### Mutating During Iteration
```java
// WRONG — size changes mid-loop
for (int i = 0; i < arr.length; i++) {
    if (arr[i] == 3) arr[i] = 0;  // if you're removing, indices shift
}
```
Fix: identify elements first, then remove; or build a new array.

### Reference vs Value
```java
int[] a = {1, 2, 3};
int[] b = a;          // NOT a copy — same array
b[0] = 99;
System.out.println(a[0]); // 99 — a changed too
```
Fix: `int[] c = Arrays.copyOf(a, a.length);`
