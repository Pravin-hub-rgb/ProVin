**Problem:** Given a rotated sorted array of unique elements, find the minimum element. (LeetCode #153)

**Link:** https://leetcode.com/problems/find-minimum-in-rotated-sorted-array/

---

## Which Technique, and Why?

Rotated sorted array + find minimum → **Binary Search**. The minimum is at the "pivot" — the point where the rotation happened. At least one half is always sorted; the minimum is in the unsorted half (or is the first element if not rotated).

**Signal in the problem:** "rotated sorted array" + "find minimum" → binary search, compare mid with right.

## Approach

Binary search. At each mid:
- If `nums[mid] > nums[right]`, the minimum is in the right half (`left = mid + 1`).
- Else (`nums[mid] <= nums[right]`), the minimum is in the left half including mid (`right = mid`).

The comparison is with `nums[right]`, not `nums[left]` — because the rightmost element is always in the "second sorted segment" (or is the minimum itself).

## Pseudocode

```
left = 0, right = n - 1
while left < right:
    mid = left + (right - left) / 2
    if nums[mid] > nums[right]:
        left = mid + 1
    else:
        right = mid
return nums[left]
```

## Java Code

```java
class Solution {
    public int findMin(int[] nums) {
        int left = 0, right = nums.length - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] > nums[right]) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }
        return nums[left];
    }
}
```

## Line-by-line

- `left < right` (not `<=`) — we're finding a boundary, not an exact match. When `left == right`, we've found the minimum.
- `nums[mid] > nums[right]` → the min is to the right of mid (mid is in the first sorted segment, right is in the second).
- `nums[mid] <= nums[right]` → mid could be the min or it's to the left → `right = mid` (include mid).
- Return `nums[left]` — when the loop exits, `left == right` points at the minimum.

## Complexity

- Time: O(log n).
- Space: O(1).

## Common Mistakes

- **Using `nums[left]` for comparison instead of `nums[right]`.** Comparing with `nums[right]` is correct because the rightmost element is always in the second sorted segment. Comparing with `nums[left]` gives wrong results.
- **Using `right = mid - 1` instead of `right = mid`.** This excludes mid, which could be the minimum. Use `right = mid`.
- **Loop condition `left <= right`.** This is for "find exact." For "find boundary/minimum," use `left < right`. Mixing them causes issues.
- **Duplicates (LeetCode #154):** if duplicates exist, `nums[mid] == nums[right]` is ambiguous — you can't tell which side. Fall back to `right--` (O(n) worst case). This problem guarantees unique elements.

## How to Explain (interview)

**Opening:** Find Minimum in Rotated Sorted Array finds the smallest element in a rotated sorted array. Binary search: compare mid with the rightmost element. If `nums[mid] > nums[right]`, the minimum is to the right; else it's to the left (including mid). O(log n) time, O(1) space. Loop condition is `left < right` (boundary search, not exact match).

**The basic flow:**
```java
int left = 0, right = nums.length - 1;
while (left < right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] > nums[right]) left = mid + 1;

}
return nums[left];
```

**The part that trips everyone up:** compare with `nums[right]`, not `nums[left]`. And use `right = mid` (not `mid - 1`) because mid could be the minimum. Loop condition is `left < right`, not `left <= right`.

**The mistakes to remember:**
- Comparing with `nums[left]` instead of `nums[right]`
- Using `right = mid - 1` (excludes the minimum)
- Using `left <= right` (wrong loop condition for boundary search)
- Duplicates break the O(log n) — fall back to O(n) (different problem, #154)
