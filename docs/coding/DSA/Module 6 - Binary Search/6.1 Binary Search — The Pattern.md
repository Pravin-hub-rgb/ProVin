**Problem:** Given a sorted array of integers `nums` and an integer `target`, return the index of `target` if it exists in `nums`, otherwise return `-1`. (LeetCode #704)

**Link:** https://leetcode.com/problems/binary-search/

---

## What This Problem Is Asking (Simple Terms)

You have a **sorted** array of numbers. You need to find if a target number exists in it, and if so, return its index.

Because the array is sorted, you don't need to look at every element. You can use the middle element as a clue: if the middle element is bigger than your target, the target must be somewhere to the left; if it's smaller, it must be somewhere to the right. Each step cuts the search space in half.

---

## Example 1

**Input:** `nums = [-1,0,3,5,9,12]`, `target = 9`

**Output:** `4`

**Explanation:** `9` exists at index `4`.

---

## Example 2

**Input:** `nums = [-1,0,3,5,9,12]`, `target = 2`

**Output:** `-1`

**Explanation:** `2` does not exist in `nums`, so return `-1`.

---

## Constraints

- `1 <= nums.length <= 10^4`
- `-10^4 <= nums[i] <= 10^4`
- All integers in `nums` are distinct.
- `nums` is sorted in ascending order.
- `-10^4 <= target <= 10^4`

---

## Linear Search vs Binary Search

Before optimizing, think like a beginner: how would you solve this by hand?

You could check every element one by one from the start until you find the target. That's linear search — O(n) time in the worst case.

**Binary search** works only because the array is sorted. You look at the middle element:
- If it equals the target, you're done.
- If it's smaller than the target, the target must be to the right.
- If it's bigger than the target, the target must be to the left.

Then you repeat on whichever half remains. Each step cuts the search space in half.

---

## Why Sorting Matters

Binary search works because the array is sorted. If the array were unsorted, the middle element wouldn't tell you which side to look in — the target could be anywhere. Sorting gives you order, and order gives you the power to discard half the search space each step.

---

## Why Logarithmic Time?

Each step cuts the remaining search space in half:
- Start with `n` elements
- After 1 step: `n / 2` left
- After 2 steps: `n / 4` left
- After 3 steps: `n / 8` left
- ...
- After `k` steps: `n / 2^k` left

You stop when `n / 2^k = 1`, which means `2^k = n`, or `k = log₂(n)`.

So binary search takes **O(log n)** time — for a million elements, at most about 20 checks instead of a million.

---

## The Two-Pointer Flow

You keep two indices, `left` and `right`, that mark the current search window:
- Initially `left = 0`, `right = nums.length - 1` (the whole array).
- While `left <= right`:
  - Find the middle index: `mid = left + (right - left) / 2`
  - If `nums[mid] == target`: return `mid` — found it.
  - If `nums[mid] < target`: the target is to the right, so `left = mid + 1`.
  - If `nums[mid] > target`: the target is to the left, so `right = mid - 1`.
- If the loop ends without finding it, return `-1`.

### Pseudocode

```
left = 0
right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if nums[mid] == target:
        return mid
    if nums[mid] < target:
        left = mid + 1
    else:
        right = mid - 1
return -1
```

### Java Code

```java
class Solution {
    public int search(int[] nums, int target) {
        int left = 0, right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                return mid;
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }

        return -1;
    }
}
```

### Line-by-line

- `left = 0` — leftmost index we haven't ruled out.
- `right = nums.length - 1` — rightmost index we haven't ruled out.
- `while (left <= right)` — keep going while there's at least one element left to check. The `<=` matters: when `left == right`, there's still one element to check.
- `int mid = left + (right - left) / 2` — the middle index. We write it this way instead of `(left + right) / 2` to avoid integer overflow when `left` and `right` are large.
- `if (nums[mid] == target) return mid` — found it.
- `else if (nums[mid] < target) left = mid + 1` — middle is too small, so target must be to the right. We can throw away `mid` itself because it doesn't match.
- `else right = mid - 1` — middle is too big, so target must be to the left. We discard `mid` too.
- `return -1` — loop ended without finding the target.

## Complexity

- Time: **O(log n)** — each step halves the search space.
- Space: **O(1)** — just two pointers and a mid variable.

## Common Mistakes

- **Writing `mid = (left + right) / 2`** — if `left` and `right` are both large, their sum can overflow an int. Always write `left + (right - left) / 2`.
- **Using `while (left < right)`** — this stops when `left == right`, leaving one element unchecked. Use `left <= right`.
- **Forgetting to move past `mid`** — after checking `nums[mid]`, you must set `left = mid + 1` or `right = mid - 1`, otherwise `mid` stays in the range forever and the loop never ends.
- **Returning `mid` after the loop** — `mid` from the last iteration isn't meaningful. Return `-1` when the loop finishes without finding the target.

## How to Explain (interview)

**Opening:** Binary search finds a target in a sorted array in O(log n) time. Instead of checking every element, you look at the middle element. If it's too small, the target must be to the right; if too big, to the left. Each step throws away half the search space.

**The basic flow:**
```java
int left = 0, right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) return mid;
    if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
return -1;
```

**The part that trips everyone up:**
- **`left <= right`**: you need `<=`, not just `<`, because when `left == right` there's still one element to check.
- **`left + (right - left) / 2`**: prevents integer overflow when `left` and `right` are both large.
- **Moving past `mid`**: after checking `mid`, move to `mid + 1` or `mid - 1`. If you don't, `mid` stays in the range and the loop spins forever.
- **Return `-1` at the end**, not `mid` — `mid` after the loop doesn't mean anything useful.

**The mistakes to remember:**
- Forgetting `left <= right` and writing `left < right`
- Writing `(left + right) / 2` without worrying about overflow
- Forgetting to move `left` or `right` past `mid` after checking it
