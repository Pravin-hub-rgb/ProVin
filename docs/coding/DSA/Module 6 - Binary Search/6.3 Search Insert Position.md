# 6.3 Search Insert Position

## Problem

Given a sorted array of distinct integers and a target value, return the index if the target is found. If not, return the index where it would be if it were inserted in order. (LeetCode #35)

**Link:** https://leetcode.com/problems/search-insert-position/

---

## What This Problem Is Asking (Simple Terms)

You have a **sorted** array of integers and a target value. You need to find the index where the target would be inserted to keep the array sorted. If the target already exists, return its index.

For example, `nums = [1,3,5,6]`, `target = 2` → insert at index 1 (between 1 and 3).

---

## Example 1

**Input:** `nums = [1,3,5,6]`, `target = 5`

**Output:** `2`

**Explanation:** `5` exists at index `2`.

---

## Example 2

**Input:** `nums = [1,3,5,6]`, `target = 2`

**Output:** `1`

**Explanation:** `2` would be inserted at index `1` (between 1 and 3).

---

## Example 3

**Input:** `nums = [1,3,5,6]`, `target = 7`

**Output:** `4`

**Explanation:** `7` would be inserted at index `4` (at the end).

---

## Constraints

- `1 <= nums.length <= 10^4`
- `-10^4 <= nums[i] <= 10^4`
- `nums` is sorted in ascending order.
- `-10^4 <= target <= 10^4`

---

## Which Technique, and Why?

Sorted array + find insertion point → **Binary Search**. The insertion position is the first index where `nums[i] >= target` (lower bound). Standard binary search with a slight modification: when the loop ends, `left` is the insertion point.

**Signal in the problem:** "sorted array" + "insert position" / "where to insert" → binary search for lower bound.

---

## Approach

Standard binary search, but instead of returning -1 when not found, return `left` (the position where the element would be inserted). The loop invariant: everything before `left` is `< target`, everything from `right+1` onward is `>= target`.

### Pseudocode

```
left = 0, right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if nums[mid] == target: return mid
    if nums[mid] < target: left = mid + 1
    else: right = mid - 1
return left   // insertion point
```

### Java Code

```java
class Solution {
    public int searchInsert(int[] nums, int target) {
        int left = 0, right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) return mid;
            if (nums[mid] < target) left = mid + 1;
            else right = mid - 1;
        }
        return left;
    }
}
```

### Line-by-line

- `left = 0` — leftmost index we haven't ruled out.
- `right = nums.length - 1` — rightmost index we haven't ruled out.
- `while (left <= right)` — keep going while there's at least one element left to check.
- `int mid = left + (right - left) / 2` — the middle index.
- `if (nums[mid] == target) return mid;` — found it.
- `else if (nums[mid] < target) left = mid + 1;` — middle is too small, so target must be to the right.
- `else right = mid - 1;` — middle is too big, so target must be to the left.
- `return left;` — when the loop ends, `left` is the first index where `nums[left] >= target` (the insertion point).

### Complexity

- Time: O(log n) — each step halves the search space.
- Space: O(1) — just two pointers and a `mid` variable.

## Common Mistakes

- **Writing `mid = (left + right) / 2`** — if `left` and `right` are both large, their sum can overflow an int. Always write `left + (right - left) / 2`.
- **Using `while (left < right)`** — this stops when `left == right`, leaving one element unchecked. Use `left <= right`.
- **Forgetting to move past `mid`** — after checking `nums[mid]`, you must set `left = mid + 1` or `right = mid - 1`. Otherwise `mid` stays in the range forever and the loop never ends.
- **Returning `mid` after the loop** — `mid` from the last iteration isn't meaningful. Return `left` when the loop finishes without finding the target.

## How to Explain (interview)

**Opening:** Search Insert Position finds the index where a target would be inserted in a sorted array. Greedy with level expansion: track the current jump's range [start, currentEnd]. For all positions in this range, find the farthest reachable. When the range is exhausted, increment jumps and set the new range. O(n) time, O(1) space.

**The basic flow:**
```java
int left = 0, right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) return mid;
    if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
return left;
```

**The part that trips everyone up:**
- **`left <= right`**: you need `<=`, not just `<`, because when `left == right` there's still one element to check.
- **`left + (right - left) / 2`**: prevents integer overflow when `left` and `right` are both large.
- **Moving past `mid`**: after checking `nums[mid]`, you must set `left = mid + 1` or `right = mid - 1`. Otherwise `mid` stays in the range forever and the loop never ends.
- **Returning `left` at the end**, not `mid` — `mid` from the last iteration isn't meaningful. When the loop ends, `left` is the insertion point.

**The mistakes to remember:**
- Forgetting `left <= right` and writing `left < right`
- Writing `(left + right) / 2` without worrying about overflow
- Forgetting to move `left` or `right` past `mid` after checking it
