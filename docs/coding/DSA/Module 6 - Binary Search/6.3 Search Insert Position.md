**Problem:** Given a sorted array and a target, return the index where target should be inserted to keep the array sorted. (LeetCode #35)

**Link:** https://leetcode.com/problems/search-insert-position/

---

## Which Technique, and Why?

Sorted array + find insertion point → **Binary Search**. The insertion position is the first index where `nums[i] >= target` (lower bound). Standard binary search with a slight modification: when the loop ends, `left` is the insertion point.

**Signal in the problem:** "sorted array" + "insert position" / "where to insert" → binary search for lower bound.

## Approach

Standard binary search, but instead of returning -1 when not found, return `left` (the position where the element would be inserted). The loop invariant: everything before `left` is < target, everything from `right+1` onward is ≥ target.

## Pseudocode

```
left = 0, right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if nums[mid] == target: return mid
    if nums[mid] < target: left = mid + 1
    else: right = mid - 1
return left   // insertion point
```

## Java Code

```java
class Solution {
    public int searchInsert(int[] nums, int target) {
        int left = 0, right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) return mid;
            if (nums[mid] < target) left = mid + 1;
            else right = mid - 1;
        }
        return left;
    }
}
```

## Line-by-line

- Same as standard binary search.
- If target exists, return its index.
- If not, the loop exits with `left > right`. At that point, `left` is the first index where `nums[left] >= target` (or `n` if target is larger than all elements) — exactly the insertion point.

## Complexity

- Time: O(log n).
- Space: O(1).

## Common Mistakes

- **Returning -1 when not found.** This problem wants the insertion index, not -1.
- **Returning `right + 1` instead of `left`.** Both work (`right + 1 == left` when the loop exits), but `left` is more intuitive.
- **Off-by-one when target is larger than all elements.** `left` becomes `n` — valid insertion index (append at end). Don't clamp to `n-1`.

## How to Explain (interview)

**Opening:** Search Insert Position finds where a target should be inserted in a sorted array. Standard binary search, but return `left` (not -1) when the target isn't found — `left` ends up at the first position where `nums[i] >= target`. O(log n) time, O(1) space.

**The basic flow:**
```java
int left = 0, right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) return mid;
    if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
return left;  // insertion point
```

**The part that trips everyone up:** return `left`, not -1 or `right`. When the loop exits, `left` is the insertion index. Also handle the case where target is larger than all elements (`left = n`).

**The mistakes to remember:**
- Returning -1 instead of the insertion index
- Returning `right` instead of `left` (off by one)
- Not handling target larger than all elements
