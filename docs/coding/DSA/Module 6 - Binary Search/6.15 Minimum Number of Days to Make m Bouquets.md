# 6.15 Minimum Number of Days to Make m Bouquets

**Tier 2 problem.** (LeetCode #1482)

**Problem:** Given an array of bloom days and integers m (bouquets) and k (flowers per bouquet), find the minimum number of days to make m bouquets (each bouquet needs k adjacent bloomed flowers). (LeetCode #1482)

**Link:** https://leetcode.com/problems/minimum-number-of-days-to-make-m-bouquets/

---

## Which Technique, and Why?

"Minimum days to make m bouquets" → **Binary Search on Answer**. The answer (days) lies in [1, max(bloomDay)]. For candidate mid (days), count how many bouquets can be made: scan the array, count consecutive bloomed flowers (bloomDay[i] <= mid); when count reaches k, make a bouquet and reset. If bouquets >= m → feasible → try fewer days. O(n log(maxDay)) time.

**Signal in the problem:** "minimum days" + "make m bouquets" + "k adjacent" → binary search on answer + greedy counting.

## Approach

Binary search on [1, maxDay]. Feasibility: scan the array, count consecutive bloomed flowers. When count reaches k, make a bouquet (reset count). If total bouquets ≥ m → feasible.

## Pseudocode

```
left = 1, right = max(bloomDay)
while left <= right:
    mid = left + (right - left) / 2
    bouquets = 0, flowers = 0
    for day in bloomDay:
        if day <= mid:
            flowers++
            if flowers == k: bouquets++; flowers = 0
        else:
            flowers = 0
    if bouquets >= m:
        answer = mid; right = mid - 1
    else:
        left = mid + 1
return answer
```

## Java Code

```java
class Solution {
    public int minDays(int[] bloomDay, int m, int k) {
        if ((long) m * k > bloomDay.length) return -1;  // impossible

        int left = 1, right = 0;
        for (int d : bloomDay) right = Math.max(right, d);

        int answer = right;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            int bouquets = 0, flowers = 0;
            for (int day : bloomDay) {
                if (day <= mid) {
                    flowers++;
                    if (flowers == k) {
                        bouquets++;
                        flowers = 0;
                    }
                } else {
                    flowers = 0;
                }
            }
            if (bouquets >= m) {
                answer = mid;
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        }
        return answer;
    }
}
```

## Line-by-line

- `(long) m * k > bloomDay.length` — if there aren't enough flowers for m bouquets, return -1.
- `left = 1, right = max(bloomDay)` — answer is in this range.
- Feasibility: scan bloomDay. If `day <= mid` (bloomed), increment `flowers`. When `flowers == k`, make a bouquet and reset. If `day > mid` (not bloomed), reset `flowers` (breaks adjacency).
- `bouquets >= m` → feasible → try fewer days. Else → need more days.

## Complexity

- Time: O(n log(maxDay)) — n flowers, log(maxDay) binary search steps.
- Space: O(1).

## Common Mistakes

- **Not checking feasibility of m bouquets.** If `m * k > bloomDay.length`, return -1 immediately.
- **Not resetting `flowers` on non-bloomed days.** If `day > mid`, the adjacency breaks — reset `flowers = 0`.
- **Using `flowers >= k` instead of `== k`.** When `flowers == k`, make a bouquet and reset to 0. Using `>=` would make multiple bouquets from one run of flowers (wrong — each flower can only be in one bouquet).
- **Wrong bounds.** `left = 1` (not 0 — days start at 1). `right = max(bloomDay)` (not sum).

## How to Explain (interview)

**Opening:** Minimum Days to Make m Bouquets finds the earliest day when m bouquets (each k adjacent bloomed flowers) can be made. Binary search on answer [1, maxDay]. Feasibility: scan bloomDay, count consecutive bloomed flowers; when count reaches k, make a bouquet and reset. O(n log(maxDay)) time, O(1) space.

**The basic flow:**

**The part that trips everyone up:** reset `flowers = 0` when a non-bloomed day breaks the adjacency. Also, check `flowers == k` (not `>=`) — each flower can only be in one bouquet.

**The mistakes to remember:**
- Not checking `m * k > n` (impossible case)
- Not resetting flowers on non-bloomed days
- Using `>=` instead of `==` for flowers == k
- Wrong bounds (left = 0 or right = sum)
