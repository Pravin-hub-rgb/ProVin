# 6.2 Binary Search

**Problem:** Given a sorted array and a target, return the index of target if it exists, otherwise -1. (LeetCode #704)

**Link:** https://leetcode.com/problems/binary-search/

---

## Which Technique, and Why?

Sorted array + find target → **Binary Search**. O(log n) time, O(1) space. The most basic application of the pattern.

**Signal in the problem:** "sorted array" + "search for target" → binary search.

## Approach

Standard binary search: `left = 0`, `right = n-1`. Compute `mid`. If `nums[mid] == target`, return mid. If `nums[mid] < target`, search right half (`left = mid + 1`). Else search left half (`right = mid - 1`).

## Pseudocode

```
left = 0, right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if nums[mid] == target: return mid
    if nums[mid] < target: left = mid + 1
    else: right = mid - 1
return -1
```

## Java Code

```java
class Solution {
    public int search(int[] nums, int target) {
        int left = 0, right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) return mid;
            if (nums[mid] < target) left = mid + 1;
            else right = mid - 1;
        }
        return -1;
    }
}
```

## Line-by-line

- `left = 0, right = n - 1` — inclusive both ends.
- `mid = left + (right - left) / 2` — avoids overflow.
- `nums[mid] == target` → found, return.
- `nums[mid] < target` → target is in the right half → `left = mid + 1`.
- `nums[mid] > target` → target is in the left half → `right = mid - 1`.
- Loop condition `left <= right` — inclusive. When `left > right`, the element doesn't exist.

## Complexity

- Time: O(log n) — halves the search space each step.
- Space: O(1) — two pointers.

## Common Mistakes

- **Overflow:** `(left + right) / 2` can overflow. Use `left + (right - left) / 2`.
- **Wrong loop condition:** `left < right` (exclusive) with `left = mid + 1`/`right = mid - 1` (exclusive) works for "find exact" too, but you must be consistent. The inclusive form (`left <= right`) with exclusive updates is the most common and least error-prone.
- **Infinite loop:** if you use `left = mid` or `right = mid` instead of `mid ± 1`, the loop can stall. Always exclude `mid` after checking it.
- **Applying to unsorted data** — binary search requires sorted input.

## How to Explain (interview)

**Opening:** Binary Search finds an element in a sorted array in O(log n). Compare the target with the middle element; if smaller, search left; if larger, search right. Halve the search space each step. O(log n) time, O(1) space. Requires sorted input.

**The basic flow:**
```java
int left = 0, right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) return mid;
    if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
return -1;
```

**The part that trips everyone up:** overflow in `mid = (left + right) / 2`. Use `left + (right - left) / 2`. Also, `left <= right` with `left = mid + 1` / `right = mid - 1` — mixing inclusive/exclusive causes infinite loops.

**The mistakes to remember:**
- Overflow in mid calculation
- Wrong loop condition causing infinite loop
- Using binary search on unsorted data
