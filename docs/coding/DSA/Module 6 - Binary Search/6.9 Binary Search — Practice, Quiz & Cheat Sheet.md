## Mini Quiz

1. Why use `left + (right - left) / 2` instead of `(left + right) / 2`?
2. What's the difference between `left <= right` and `left < right` as loop conditions?
3. In a rotated sorted array, how do you determine which half is sorted?
4. For "Find Minimum in Rotated Sorted Array," why compare `nums[mid]` with `nums[right]` instead of `nums[left]`?
5. What is "search on answer," and when do you use it?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. `(left + right)` can overflow for large indices (sum exceeds int max). `left + (right - left) / 2` computes the same midpoint without overflow.
2. `left <= right` (inclusive both ends) with `left = mid + 1` / `right = mid - 1` (exclude mid) → for "find exact" (target exists or not). `left < right` (exclusive right) with `right = mid` (include mid) → for "find boundary" (minimum, first occurrence). Mixing them causes infinite loops or missed elements.
3. Check `nums[left] <= nums[mid]`. If true, the left half is sorted. If false, the right half is sorted. (At least one half is always sorted in a rotated sorted array.)
4. The rightmost element is always in the second sorted segment (or is the minimum itself). Comparing mid with right tells you whether mid is in the first segment (min is to the right) or the second (min is to the left). Comparing with left gives wrong results because left could be in either segment.
5. "Search on answer" means binary searching a value range [lo, hi] (not an array), where you can check if a candidate value is feasible. Use it when the problem asks "minimum X such that condition holds" (e.g., sqrt, Koko Eating Bananas, capacity to ship packages). The feasibility check must be monotonic.

</details>

## One-Page Cheat Sheet

**Standard binary search:**
```java
int left = 0, right = n - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) return mid;
    if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
return -1;
```

**Lower bound (first ≥ target):** when `nums[mid] >= target`, go left (`right = mid - 1`); else go right. Return `left`.

**Upper bound (last ≤ target):** when `nums[mid] <= target`, go right (`left = mid + 1`); else go left. Return `right`.

**Rotated sorted array:** determine which half is sorted, check if target is in that range, narrow accordingly.

**Find minimum in rotated:** compare `nums[mid]` with `nums[right]`. If `nums[mid] > nums[right]`, min is right; else min is left (include mid).

**Search on answer:** binary search on [lo, hi], check feasibility with a helper. Return the boundary.

**Complexities:** O(log n) time, O(1) space for all variants.

## In Your Own Words

1. Why must you use `left + (right - left) / 2` instead of `(left + right) / 2`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `(left + right)` can exceed `Integer.MAX_VALUE` for large indices, causing overflow (wraps to negative). `left + (right - left) / 2` computes the same midpoint but `right - left` is at most `n`, so no overflow. This is a classic bug in binary search implementations.

</details>

2. When do you use `left <= right` vs `left < right`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `left <= right` (inclusive both ends) with `left = mid + 1` / `right = mid - 1` (exclude mid) — for "find exact" (target exists or not). `left < right` (exclusive right) with `right = mid` (include mid) — for "find boundary" (minimum, first occurrence, lower/upper bound). Mixing them (e.g., `left <= right` with `right = mid`) causes infinite loops.

</details>

3. How do you find the first and last occurrence of a target in a sorted array?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Two binary searches. Left boundary: search for first index where `nums[i] >= target` (go left when `>=`, go right otherwise). Right boundary: search for last index where `nums[i] <= target` (go right when `<=`, go left otherwise). After each, verify the found index actually contains the target. O(log n) each, O(log n) total.

</details>

4. What is "search on answer," and give an example?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Instead of searching an array, you binary search a value range [lo, hi] where you can check if a candidate value is feasible. Use it when the problem asks "minimum X such that condition holds" and feasibility is monotonic. Example: Sqrt(x) — search [0, x], candidate mid is feasible if `mid * mid <= x`. Return the largest feasible value. Other examples: Koko Eating Bananas, Capacity to Ship Packages.

</details>
