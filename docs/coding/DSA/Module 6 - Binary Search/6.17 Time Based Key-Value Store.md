**Tier 2 problem.** (LeetCode #981)

**Problem:** Design a time-based key-value store that supports `set(key, value, timestamp)` and `get(key, timestamp)` — return the value with the largest timestamp ≤ the given timestamp. (LeetCode #981)

**Link:** https://leetcode.com/problems/time-based-key-value-store/

---

## Which Technique, and Why?

"Get value at or before a timestamp" → **HashMap + Binary Search**. Map key → list of (timestamp, value) pairs (sorted by timestamp since set is called in increasing order). For get, binary search the list for the largest timestamp ≤ target. O(log n) per get, O(1) per set.

**Signal in the problem:** "time-based" / "get at timestamp" / "largest timestamp ≤ X" → HashMap + binary search on sorted timestamp list.

## Approach

- `set(key, value, timestamp)`: append (timestamp, value) to `map[key]`. Timestamps are given in increasing order, so the list stays sorted.
- `get(key, timestamp)`: if key not in map → "". Binary search the list for the largest timestamp ≤ given. Use `Collections.binarySearch` or manual binary search.

## Pseudocode

```
map = HashMap<String, List<Pair>>

set(key, value, timestamp):
    map.computeIfAbsent(key, k -> new ArrayList<>()).add(new Pair(timestamp, value))

get(key, timestamp):
    if !map.containsKey(key): return ""
    list = map.get(key)
    // binary search for largest timestamp <= given
    lo = 0, hi = list.size() - 1, result = ""
    while lo <= hi:
        mid = lo + (hi - lo) / 2
        if list[mid].timestamp <= timestamp:
            result = list[mid].value
            lo = mid + 1
        else:
            hi = mid - 1
    return result
```

## Java Code

```java
class TimeMap {
    private final Map<String, List<int[]>> map; // key -> list of {timestamp, value-encoded}

    // Actually, store as list of pairs. Use a small record or int[] with value index.
    // Simpler: store List<String[]> or two parallel lists. Here: List of int[] where [0]=timestamp, value stored separately.
    // Cleanest: store List<int[]> for timestamps and List<String> for values, or a Pair class.

    private static class Entry {
        int timestamp;
        String value;
        Entry(int t, String v) { timestamp = t; value = v; }
    }

    private final Map<String, List<Entry>> store;

    public TimeMap() {
        store = new HashMap<>();
    }

    public void set(String key, String value, int timestamp) {
        store.computeIfAbsent(key, k -> new ArrayList<>()).add(new Entry(timestamp, value));
    }

    public String get(String key, int timestamp) {
        List<Entry> list = store.get(key);
        if (list == null) return "";

        int lo = 0, hi = list.size() - 1;
        String result = "";
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (list.get(mid).timestamp <= timestamp) {
                result = list.get(mid).value;
                lo = mid + 1;  // try to find a larger valid timestamp
            } else {
                hi = mid - 1;
            }
        }
        return result;
    }
}
```

## Line-by-line

- `store` maps key → list of `Entry(timestamp, value)`.
- `set`: append to the list. Timestamps are increasing, so the list stays sorted.
- `get`: if key not found → "". Binary search for the largest timestamp ≤ given. `lo = mid + 1` when valid (try to find a larger valid one).
- Return `result` (empty string if no valid timestamp found).

## Complexity

- `set`: O(1) amortized (append to list).
- `get`: O(log n) — binary search on the list.
- Space: O(n) — stores all entries.

## Common Mistakes

- **Not using binary search.** Linear scan is O(n) per get — too slow for many queries.
- **Assuming timestamps are sorted.** The problem guarantees `set` is called with increasing timestamps. If not, you'd need to sort.
- **Off-by-one in binary search.** When `timestamp <= target`, move `lo = mid + 1` (try to find larger). When `>` target, move `hi = mid - 1`.
- **Not handling missing key.** Return "" if key not in store.
- **Confusing with "Time Based Key-Value Store II"** (different constraints).

## How to Explain (interview)

**Opening:** Time Based Key-Value Store supports set (key, value, timestamp) and get (key, timestamp) returning the value with the largest timestamp ≤ the given. HashMap maps key → sorted list of (timestamp, value). Get uses binary search for the largest timestamp ≤ target. O(1) set, O(log n) get.

**The basic flow:**
```java
// set: store.computeIfAbsent(key, k -> new ArrayList<>()).add(new Entry(ts, val));
// get: binary search for largest ts <= target
int lo = 0, hi = list.size() - 1, result = "";
while (lo <= hi) {
    int mid = lo + (hi - lo) / 2;
    if (list.get(mid).timestamp <= timestamp) { result = list.get(mid).value; lo = mid + 1; }
    else hi = mid - 1;
}
return result;
```

**The part that trips everyone up:** the binary search finds the **largest** timestamp ≤ target, not the exact match. Move `lo = mid + 1` when valid (to try larger). Also, timestamps are guaranteed increasing (so no sorting needed).

**The mistakes to remember:**
- Linear scan instead of binary search (O(n) per get)
- Wrong binary search direction (finding exact instead of largest ≤)
- Not handling missing key (return "")
- Assuming timestamps need sorting (they're given in increasing order)
