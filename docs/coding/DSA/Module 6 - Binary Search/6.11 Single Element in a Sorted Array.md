**Tier 2 problem.** (LeetCode #540)

**Problem:** Given a sorted array where every element appears twice except one, find the single element. (LeetCode #540)

**Link:** https://leetcode.com/problems/single-element-in-a-sorted-array/

---

## Which Technique, and Why?

"Single element in a sorted array (all others appear twice)" → **Binary Search**. Pairs are at (even, odd) indices before the single element and (odd, even) after. Binary search on the mid: if `nums[mid] == nums[mid^1]`, the single is to the right; else to the left. O(log n) time, O(1) space.

**Signal in the problem:** "sorted array" + "every element appears twice except one" → binary search with index parity.

## Approach

Binary search. At mid, check if `mid` is even or odd. If `nums[mid] == nums[mid ^ 1]` (pair intact), the single is to the right (`left = mid + 1`). Else, single is to the left (including mid) (`right = mid`).

## Pseudocode

```
left = 0, right = n - 1
while left < right:
    mid = left + (right - left) / 2
    if nums[mid] == nums[mid ^ 1]:
        left = mid + 1
    else:
        right = mid
return nums[left]
```

## Java Code

```java
class Solution {
    public int singleNonDuplicate(int[] nums) {
        int left = 0, right = nums.length - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == nums[mid ^ 1]) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }
        return nums[left];
    }
}
```

## Line-by-line

- `mid ^ 1` — XOR with 1 flips the last bit: even → odd, odd → even. This gives the paired index.
- If `nums[mid] == nums[mid ^ 1]`, the pair is intact → single is to the right → `left = mid + 1`.
- Else, mid is the single or it's to the left → `right = mid`.
- Loop condition `left < right` (boundary search, not exact match). When `left == right`, that's the single element.

## Complexity

- Time: O(log n) — binary search.
- Space: O(1).

## Common Mistakes

- **Using `mid + 1` or `mid - 1` incorrectly.** When `nums[mid] != nums[mid ^ 1]`, the single could be at `mid` itself, so use `right = mid` (not `mid - 1`).
- **Loop condition `left <= right`.** This is for "find exact." For boundary search, use `left < right`.
- **Not handling n = 1.** Single element → loop doesn't execute, returns `nums[0]`. Correct.
- **Using a hash map.** Works (O(n) space) but binary search is O(1) space and O(log n) time.

## How to Explain (interview)

**Opening:** Single Element in a Sorted Array finds the element that appears once (all others twice) in O(log n). Binary search using index parity: pairs are at (even, odd) before the single and (odd, even) after. If `nums[mid] == nums[mid ^ 1]`, the pair is intact → single is right. Else, single is at or left of mid.

**The basic flow:**
```java
int left = 0, right = n - 1;
while (left < right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == nums[mid ^ 1]) left = mid + 1;
    else right = mid;
}
return nums[left];
```

**The part that trips everyone up:** `mid ^ 1` gives the paired index (even↔odd). Also, loop condition is `left < right` (boundary search), and when not matching, use `right = mid` (not `mid - 1`) because mid itself could be the answer.

**The mistakes to remember:**
- Using `left <= right` (wrong loop condition for boundary search)
- Using `right = mid - 1` (excludes the single element)
- Not handling n = 1
- Using hash map (O(n) space) when binary search is O(1)
