# 6.5 Search in Rotated Sorted Array

**Problem:** A sorted array was rotated at some pivot. Given the rotated array and a target, return its index, or -1. (LeetCode #33)

**Link:** https://leetcode.com/problems/search-in-rotated-sorted-array/

---

## Which Technique, and Why?

Rotated sorted array + search target → **Binary Search with a twist**. In a rotated sorted array, at least one half is always sorted. Determine which half is sorted, check if the target lies in that range, and narrow accordingly. O(log n).

**Signal in the problem:** "rotated sorted array" + "search" → binary search, with half-sorted detection.

## Approach

Standard binary search loop. At each mid, determine which half is sorted (`nums[left] <= nums[mid]` → left half sorted, else right half sorted). If the target lies in the sorted half's range, search there; otherwise search the other half.

## Pseudocode

```
left = 0, right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if nums[mid] == target: return mid
    if nums[left] <= nums[mid]:          // left half sorted
        if nums[left] <= target < nums[mid]: right = mid - 1
        else: left = mid + 1
    else:                                 // right half sorted
        if nums[mid] < target <= nums[right]: left = mid + 1
        else: right = mid - 1
return -1
```

## Java Code

```java
class Solution {
    public int search(int[] nums, int target) {
        int left = 0, right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) return mid;

            if (nums[left] <= nums[mid]) {          // left half sorted
                if (nums[left] <= target && target < nums[mid]) {
                    right = mid - 1;
                } else {
                    left = mid + 1;
                }
            } else {                                 // right half sorted
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;
                } else {
                    right = mid - 1;
                }
            }
        }
        return -1;
    }
}
```

## Line-by-line

- `mid = left + (right - left) / 2` — overflow-safe.
- `nums[left] <= nums[mid]` — checks if the left half is sorted (handles duplicates at the boundary).
- If left half is sorted and target is in `[nums[left], nums[mid])`, search left; else search right.
- If right half is sorted and target is in `(nums[mid], nums[right]]`, search right; else search left.

## Complexity

- Time: O(log n) — halves the search space each step.
- Space: O(1).

## Common Mistakes

- **Using `nums[left] < nums[mid]` instead of `<=`.** With duplicates at the boundary, `<` can misclassify. Use `<=`.
- **Wrong range check.** Left half sorted: target must satisfy `nums[left] <= target < nums[mid]` (note: `< nums[mid]` because mid already checked). Right half: `nums[mid] < target <= nums[right]`.
- **Forgetting that at least one half is always sorted.** This is the key property. If left isn't sorted, right must be.
- **Overflow** in mid calculation.

## How to Explain (interview)

**Opening:** Search in Rotated Sorted Array finds a target in a rotated sorted array in O(log n). At each step, determine which half is sorted (at least one always is). If the target lies in the sorted half's range, search there; otherwise search the other half.

**The basic flow:**
```java
int left = 0, right = n - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) return mid;
    if (nums[left] <= nums[mid]) {  // left sorted
        if (nums[left] <= target && target < nums[mid]) right = mid - 1;
        else left = mid + 1;
    } else {  // right sorted
        if (nums[mid] < target && target <= nums[right]) left = mid + 1;
        else right = mid - 1;
    }
}
```

**The part that trips everyone up:** determining which half is sorted and whether the target is in that half's range. Use `<=` for the sorted check (handles duplicates). The target range check must exclude `mid` (already checked).

**The mistakes to remember:**
- Using `<` instead of `<=` for the sorted-half check
- Wrong boundary in the target range check (inclusive/exclusive)
- Forgetting that at least one half is always sorted
