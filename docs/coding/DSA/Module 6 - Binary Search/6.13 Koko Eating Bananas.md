# 6.13 Koko Eating Bananas

**Tier 2 problem.** (LeetCode #875)

**Problem:** Koko has piles of bananas. She can eat k bananas per hour. Find the minimum k such that she can finish all piles within h hours. (LeetCode #875)

**Link:** https://leetcode.com/problems/koko-eating-bananas/

---

## Which Technique, and Why?

"Minimum k such that feasible" → **Binary Search on Answer**. The answer (eating speed) lies in [1, maxPile]. For a candidate k, check if Koko can finish within h hours: `sum(ceil(pile / k)) <= h`. This feasibility is monotonic: if k works, any k' > k also works. Binary search the range. O(n log(maxPile)) time.

**Signal in the problem:** "minimum X such that condition holds" / "minimum speed/capacity" → binary search on answer range + feasibility check.

## Approach

Binary search on [1, maxPile]. For candidate mid (speed), compute hours needed = sum of ceil(pile / mid). If hours ≤ h → feasible → try smaller (right = mid - 1, but track answer). Else → need bigger (left = mid + 1).

## Pseudocode

```
left = 1, right = max(piles)
answer = right
while left <= right:
    mid = left + (right - left) / 2
    hours = sum of ceil(pile / mid) for all piles
    if hours <= h:
        answer = mid
        right = mid - 1   // try smaller
    else:
        left = mid + 1    // need bigger
return answer
```

## Java Code

```java
class Solution {
    public int minEatingSpeed(int[] piles, int h) {
        int left = 1, right = 0;
        for (int p : piles) right = Math.max(right, p);

        int answer = right;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            int hours = 0;
            for (int p : piles) {
                hours += (p + mid - 1) / mid;  // ceil(p / mid)
            }
            if (hours <= h) {
                answer = mid;
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        }
        return answer;
    }
}
```

## Line-by-line

- `right = max(piles)` — the max pile is the upper bound (eating 1 banana/hour would take maxPile hours for the biggest pile, but we can do better).
- `left = 1` — minimum speed (eat 1 banana per hour).
- `hours += (p + mid - 1) / mid` — integer ceil division: ceil(p/mid) = (p + mid - 1) / mid.
- If `hours <= h` → feasible → record answer, try smaller speed (`right = mid - 1`).
- Else → need bigger speed (`left = mid + 1`).

## Complexity

- Time: O(n log(maxPile)) — n piles, log(maxPile) binary search steps.
- Space: O(1).

## Common Mistakes

- **Wrong bounds.** `left = 1` (not 0 — speed can't be 0). `right = maxPile` (not sum — eating faster than the max pile doesn't help).
- **Ceil division.** `(p + mid - 1) / mid`, not `p / mid` (that's floor). Or use `(int) Math.ceil((double) p / mid)`.
- **Tracking answer.** When feasible, record `answer = mid` and search lower. Don't return immediately (you want the minimum).
- **Overflow in `p + mid - 1`.** For large p and mid, this can overflow. Use `(p - 1) / mid + 1` or long. LeetCode constraints are small enough for int.

## How to Explain (interview)

**Opening:** Koko Eating Bananas finds the minimum eating speed. Binary search on answer [1, maxPile]. For candidate speed k, check if Koko can finish within h hours: sum of ceil(pile/k) ≤ h. Feasibility is monotonic (if k works, any k' > k works). O(n log(maxPile)) time, O(1) space.

**The basic flow:**
```java
int left = 1, right = maxPile, answer = right;
while (left <= right) {
    int mid = left + (right - left) / 2;
    int hours = 0;
    for (int p : piles) hours += (p + mid - 1) / mid;
    if (hours <= h) { answer = mid; right = mid - 1; }
    else left = mid + 1;
}
return answer;
```

**The part that trips everyone up:** this is **search on answer** — you're binary searching a value range, not an array. The feasibility check (`hours <= h`) must be monotonic. Also, ceil division: `(p + mid - 1) / mid`.

**The mistakes to remember:**
- Wrong bounds (left = 0 or right = sum)
- Floor division instead of ceil (undercounts hours)
- Not tracking the answer (returning immediately)
- Overflow in ceil division for large values
