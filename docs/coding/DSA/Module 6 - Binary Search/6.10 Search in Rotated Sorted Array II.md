**Problem:** A sorted array (with duplicates) was rotated. Find if target exists. (LeetCode #81)

**Link:** https://leetcode.com/problems/search-in-rotated-sorted-array-ii/

## Which Technique, and Why?

Rotated sorted array with duplicates + search target → **Binary Search with a twist**. Unlike #33 (no duplicates), duplicates break the "which half is sorted" check. When `nums[left] == nums[mid] == nums[right]`, you can't tell which half is sorted → shrink both ends (`left++, right--`). Worst case O(n). O(log n) average.

**Signal in the problem:** "rotated sorted array" + "duplicates" → binary search with duplicate handling.

## Approach

Standard rotated search, but when `nums[left] == nums[mid]`, you can't determine which half is sorted. Shrink both ends (`left++, right--`) and continue. This degrades to O(n) in the worst case (all elements equal).

## Pseudocode

```
left = 0, right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if nums[mid] == target: return true
    if nums[left] == nums[mid] && nums[mid] == nums[right]:
        left++; right--  // can't tell which half is sorted
    else if nums[left] <= nums[mid]:  // left half sorted
        if nums[left] <= target && target < nums[mid]: right = mid - 1
        else: left = mid + 1
    else:  // right half sorted
        if nums[mid] < target && target <= nums[right]: left = mid + 1
        else: right = mid - 1
return false
```

## Java Code

```java
class Solution {
    public boolean search(int[] nums, int target) {
        int left = 0, right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) return true;

            if (nums[left] == nums[mid] && nums[mid] == nums[right]) {
                left++;
                right--;
            } else if (nums[left] <= nums[mid]) {
                if (nums[left] <= target && target < nums[mid]) right = mid - 1;
                else left = mid + 1;
            } else {
                if (nums[mid] < target && target <= nums[right]) left = mid + 1;
                else right = mid - 1;
            }
        }
        return false;
    }
}
```

## Line-by-line

- `nums[mid] == target` → found.
- `nums[left] == nums[mid] && nums[mid] == nums[right]` → can't tell which half is sorted → shrink both ends.
- Otherwise, same as #33 (Search in Rotated Sorted Array): determine sorted half, check if target is in range.

## Complexity

- Time: O(log n) average, O(n) worst case (all elements equal).
- Space: O(1).

## Common Mistakes

- **Not handling the duplicate case.** Without the `nums[left] == nums[mid] == nums[right]` check, the algorithm gives wrong answers on inputs like [1,0,1,1,1] with target 0.
- **Using `nums[left] < nums[mid]` instead of `<=`.** With duplicates, `<` misclassifies. Use `<=`.
- **Assuming O(log n).** With duplicates, worst case is O(n). The problem accepts this.
