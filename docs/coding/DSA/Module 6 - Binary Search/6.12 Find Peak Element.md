**Tier 2 problem.** (LeetCode #162)

**Problem:** Given an array, find a peak element (strictly greater than its neighbors). Return any peak's index. (LeetCode #162)

**Link:** https://leetcode.com/problems/find-peak-element/

---

## Which Technique, and Why?

"Find a peak element" in O(log n) → **Binary Search**. If `nums[mid] < nums[mid+1]`, a peak exists to the right; else, a peak exists to the left (including mid). The array is not sorted, but the "peak exists" property is monotonic — you can binary search on it.

**Signal in the problem:** "peak element" / "local maximum" + "O(log n)" → binary search using the "peak exists to the right" property.

## Approach

Binary search. At mid: if `nums[mid] < nums[mid + 1]`, a peak exists to the right (`left = mid + 1`). Else, a peak exists to the left (including mid) (`right = mid`). Return `left` when `left == right`.

## Pseudocode

```
left = 0, right = n - 1
while left < right:
    mid = left + (right - left) / 2
    if nums[mid] < nums[mid + 1]:
        left = mid + 1
    else:
        right = mid
return left
```

## Java Code

```java
class Solution {
    public int findPeakElement(int[] nums) {
        int left = 0, right = nums.length - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] < nums[mid + 1]) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }
        return left;
    }
}
```

## Line-by-line

- `left = 0, right = n - 1` — inclusive both ends.
- `mid = left + (right - left) / 2`.
- `nums[mid] < nums[mid + 1]` → ascending at mid → peak is to the right → `left = mid + 1`.
- Else (descending or flat) → peak is at or left of mid → `right = mid`.
- Loop condition `left < right` (boundary search). When `left == right`, that's a peak.

## Complexity

- Time: O(log n) — binary search.
- Space: O(1).

## Common Mistakes

- **Checking `nums[mid] < nums[mid - 1]` instead of `nums[mid + 1]`.** You need to look right to decide the direction. Comparing with left gives wrong results.
- **Using `left <= right` with `right = mid - 1`.** This is for "find exact." For boundary search, use `left < right` with `right = mid`.
- **Not handling n = 1.** Single element → loop doesn't execute, returns 0. Correct (the only element is a peak).
- **Assuming the array is sorted.** It's not. Binary search works here because of the "peak exists" property, not sorting.

## How to Explain (interview)

**Opening:** Find Peak Element finds a local maximum in O(log n). Binary search: if `nums[mid] < nums[mid+1]`, a peak exists to the right; else, a peak exists at or left of mid. The array isn't sorted, but the "peak exists" property is monotonic — you can binary search on it.

**The basic flow:**
```java
int left = 0, right = n - 1;
while (left < right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] < nums[mid + 1]) left = mid + 1;
    else right = mid;
}
return left;
```

**The part that trips everyone up:** you compare with `nums[mid + 1]` (the right neighbor), not `nums[mid - 1]`. Also, loop condition is `left < right` with `right = mid` (not `mid - 1`).

**The mistakes to remember:**
- Comparing with left neighbor instead of right
- Wrong loop condition / update (infinite loop)
- Assuming the array is sorted (it's not — but binary search still works)
- Not handling n = 1 (single element is a peak)
