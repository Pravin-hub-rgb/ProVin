# 6.7 Sqrt(x)

**Problem:** Given a non-negative integer x, compute and return the integer square root (floor of the exact square root). (LeetCode #69)

**Link:** https://leetcode.com/problems/sqrtx/

---

## Which Technique, and Why?

"Find sqrt(x)" where x can be up to 2³¹-1 → **Binary Search on Answer**. The answer (integer sqrt) lies in range [0, x]. For a candidate `mid`, check if `mid * mid <= x` (feasible) → search higher; else search lower. O(log x) time.

Why not `Math.sqrt`? That uses floating point and can have precision issues. Binary search on integers is exact.

**Signal in the problem:** "compute sqrt" / "integer square root" / "floor of square root" → binary search on the answer range [0, x].

## Approach

Binary search on range [0, x]. `mid = (left + right) / 2` (or overflow-safe). If `mid * mid <= x`, the answer is at least `mid` → `left = mid + 1` (or `left = mid` for boundary). If `mid * mid > x`, the answer is smaller → `right = mid - 1`. Return `right` (or `left - 1`) as the floor sqrt.

## Pseudocode

```
left = 0, right = x
while left <= right:
    mid = left + (right - left) / 2
    if mid * mid <= x:
        left = mid + 1
    else:
        right = mid - 1
return right   // floor sqrt
```

## Java Code

```java
class Solution {
    public int mySqrt(int x) {
        if (x < 2) return x;  // 0→0, 1→1

        int left = 0, right = x;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (mid <= x / mid) {     // mid*mid <= x, written to avoid overflow
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        return right;  // right is the floor sqrt
    }
}
```

## Line-by-line

- `if (x < 2) return x` — base cases: sqrt(0)=0, sqrt(1)=1.
- `mid <= x / mid` — checks `mid * mid <= x` without overflow. If mid is large, `mid * mid` overflows int. Using division avoids this.
- `mid * mid <= x` → feasible (mid could be the answer or smaller) → search higher: `left = mid + 1`.
- `mid * mid > x` → too big → search lower: `right = mid - 1`.
- Return `right` — when the loop exits, `right` is the largest value with `right * right <= x`.

## Complexity

- Time: O(log x) — binary search on range [0, x].
- Space: O(1).

## Common Mistakes

- **Overflow in `mid * mid`.** For x up to 2³¹-1, mid can be ~46340, and mid² ~2.1 billion — fits in int barely, but `mid * mid` for mid > 46340 overflows. Use `mid <= x / mid` to be safe.
- **Wrong return value.** Return `right` (or `left - 1`), not `mid` or `left`. When the loop exits, `left = right + 1`, and `right` is the floor sqrt.
- **Wrong bounds.** `right = x` is correct (sqrt(x) ≤ x for x ≥ 1). Using `right = x/2` also works for x > 1 but needs a special case for x = 1.
- **Floating point.** `Math.sqrt` returns double — casting to int can give wrong results due to precision. Binary search on integers is exact.

## How to Explain (interview)

**Opening:** Sqrt(x) computes the integer square root (floor). Binary search on the answer range [0, x]: for candidate mid, check if mid² ≤ x (feasible). If yes, search higher; if no, search lower. O(log x) time, O(1) space. Use `mid <= x / mid` to avoid overflow instead of `mid * mid`.

**The basic flow:**
```java
int left = 0, right = x;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (mid <= x / mid) left = mid + 1;  // feasible, try higher
    else right = mid - 1;                  // too high
}
return right;  // floor sqrt
```

**The part that trips everyone up:** return `right`, not `mid` or `left`. Also avoid `mid * mid` overflow — use `mid <= x / mid`. This is "search on answer": you're binary searching a value range, not an array.

**The mistakes to remember:**
- Overflow: `mid * mid` can overflow — use `mid <= x / mid`
- Returning `mid` or `left` instead of `right`
- Using `Math.sqrt` (floating point precision issues)
- Wrong bounds: `right` must be `x` (not `x/2` without handling x=1)
