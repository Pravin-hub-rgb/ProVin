**Problem:** Given a sorted array, find the starting and ending position of a given target value. Return [-1, -1] if not found. (LeetCode #34)

**Link:** https://leetcode.com/problems/find-first-and-last-position-of-element-in-sorted-array/

---

## Which Technique, and Why?

Sorted array + find the **range** (first and last occurrence) of a target → **Binary Search twice**: once for the left boundary (first occurrence), once for the right boundary (last occurrence). Each search is O(log n), total O(log n).

Why two searches? A single binary search finds *an* occurrence, not necessarily the first or last. You need separate lower-bound and upper-bound searches.

**Signal in the problem:** "first and last position" / "starting and ending position" / "range of target" → two binary searches (lower bound + upper bound).

## Approach

- **Left boundary:** binary search for the first index where `nums[i] >= target`. If `nums[mid] >= target`, go left (`right = mid - 1`); else go right (`left = mid + 1`). After the loop, `left` is the first position (if `nums[left] == target`).
- **Right boundary:** binary search for the last index where `nums[i] <= target`. If `nums[mid] <= target`, go right (`left = mid + 1`); else go left (`right = mid - 1`). After the loop, `right` is the last position.

## Pseudocode

```
// left boundary
left = 0, right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if nums[mid] >= target: right = mid - 1
    else: left = mid + 1
first = left  (if left < n and nums[left] == target else -1)

// right boundary
left = 0, right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if nums[mid] <= target: left = mid + 1
    else: right = mid - 1
last = right  (if right >= 0 and nums[right] == target else -1)
```

## Java Code

```java
class Solution {
    public int[] searchRange(int[] nums, int target) {
        int[] result = {-1, -1};
        if (nums.length == 0) return result;

        // Left boundary
        int left = 0, right = nums.length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] >= target) right = mid - 1;
            else left = mid + 1;
        }
        if (left < nums.length && nums[left] == target) result[0] = left;

        // Right boundary
        left = 0; right = nums.length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] <= target) left = mid + 1;
            else right = mid - 1;
        }
        if (right >= 0 && nums[right] == target) result[1] = right;

        return result;
    }
}
```

## Line-by-line

- **Left boundary search:** finds the first index where `nums[i] >= target`. After the loop, `left` points there. If `nums[left] == target`, that's the first occurrence.
- **Right boundary search:** finds the last index where `nums[i] <= target`. After the loop, `right` points there. If `nums[right] == target`, that's the last occurrence.
- Empty array check prevents index-out-of-bounds.
- The two searches are mirror images: left search uses `>=` (go left), right search uses `<=` (go right).

## Complexity

- Time: O(log n) — two binary searches.
- Space: O(1).

## Common Mistakes

- **Single binary search.** A single search finds *an* occurrence, not necessarily the first or last. You need two searches.
- **Not checking if the found index actually has the target.** After the left search, `left` might point past the end or at a different value. Check `nums[left] == target`.
- **Mixing up `>=` and `<=`.** Left boundary: `nums[mid] >= target → go left`. Right boundary: `nums[mid] <= target → go right`. Swap them and you get wrong boundaries.
- **Empty array** — handle before searching to avoid index errors.

## How to Explain (interview)

**Opening:** Find First and Last Position finds the range of a target in a sorted array. Two binary searches: one for the left boundary (first occurrence) using `>=`, one for the right boundary (last occurrence) using `<=`. O(log n) time, O(1) space. Each search narrows to a boundary, not an exact match.

**The basic flow:**
```java
// Left boundary
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] >= target) right = mid - 1;
    else left = mid + 1;
}
// Right boundary
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] <= target) left = mid + 1;
    else right = mid - 1;
}
```

**The part that trips everyone up:** you need **two** searches, not one. A single binary search finds an occurrence, not the first/last. Also, after each search, verify the found index actually contains the target.

**The mistakes to remember:**
- Using a single binary search (finds any occurrence, not boundary)
- Not verifying `nums[left] == target` / `nums[right] == target`
- Swapping `>=` and `<=` between the two searches
- Empty array not handled
