# 6.4 Find First and Last Position of Element in Sorted Array

## What This Problem Is Asking (Simple Terms)

You have a **sorted** array of integers and a target value. You need to find the **starting** and **ending** position of that target value in the array.

For example, `nums = [5,7,7,8,8,10]`, `target = 8`. The number `8` appears at index `3` and index `4`, so you return `[3, 4]`.

If the target doesn't exist at all, you return `[-1, -1]`.

---

## Example 1

**Input:** `nums = [5,7,7,8,8,10]`, `target = 8`

**Output:** `[3,4]`

**Explanation:** The number `8` appears at index `3` and index `4`. So you return `[3, 4]`.

---

## Example 2

**Input:** `nums = [5,7,7,8,8,10]`, `target = 6`

**Output:** `[-1,-1]`

**Explanation:** The value `6` does not exist in `nums`, so return `[-1, -1]`.

---

## Example 3

**Input:** `nums = []`, `target = 0`

**Output:** `[-1,-1]`

**Explanation:** The array is empty, so there is no target.

---

## Constraints

- `0 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`
- `nums` is sorted in non-decreasing order.
- `-10^9 <= target <= 10^4`

---

## Linear Search vs Binary Search

Before optimizing, think like a beginner: how would you solve this by hand?

You could scan from left to right to find the first occurrence, then scan again from right to left to find the last occurrence. That's O(n) time — acceptable, but we can do better.

**Binary search** works only because the array is sorted. You look at the middle element:
- If it equals the target, you found an occurrence — but you need to check if there's another one further left (for first occurrence) or to the right (for last occurrence).
- If it's smaller than the target, the target must be to the right.
- If it's bigger than the target, the target must be to the left.

Then you repeat on whichever half remains. Each step cuts the search space in half.

---

## Why Sorting Matters

Binary search works **because** the array is sorted. If the array were unsorted, the middle element wouldn't tell you which side to look in — the target could be anywhere. Sorting gives you order, and order gives you the power to discard half the search space each step.

---

## Why Logarithmic Time?

Each step cuts the remaining search space in half:

- Start with `n` elements
- After 1 step: `n / 2` left
- After 2 steps: `n / 4` left
- After 3 steps: `n / 8` left
- After `k` steps: `n / 2^k` left

You stop when `n / 2^k = 1`, which means `2^k = n`, or `k = log₂(n)`.

So binary search takes **O(log n)** time — for a million elements, at most about 20 checks instead of a million.

---

## The Two-Pointer Flow

You keep two indices, `left` and `right`, that mark the current search window:

- Initially `left = 0`, `right = nums.length - 1` (the whole array).
- While `left <= right`:
  - Find the middle index: `mid = left + (right - left) / 2`
  - If `nums[mid] == target`:
    - **Left hunter**: record `mid` as candidate, then look left (`right = mid - 1`) to see if there's an earlier one.
    - **Right hunter**: record `mid` as candidate, then look right (`left = mid + 1`) to see if there's a later one.
  - If `nums[mid] < target`, move left up.
  - If `nums[mid] > target`, move right down.
- If the loop ends without finding it, return `[-1, -1]`.

### Pseudocode (Two Searches)

```
// Left hunter: find first occurrence
left = 0, right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if nums[mid] == target:
        result[0] = mid
        right = mid - 1   // keep searching left
    else if nums[mid] < target:
        left = mid + 1
    else:
        right = mid - 1

// Right hunter: find last occurrence
left = 0, right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if nums[mid] == target:
        result[1] = mid
        left = mid + 1   // keep searching right
    else if nums[mid] < target:
        left = mid + 1
    else:
        right = mid - 1
return result
```

### Java Code

```java
class Solution {
    public int[] searchRange(int[] nums, int target) {
        int[] result = {-1, -1};
        if (nums.length == 0) return result;

        // Left hunter: find first occurrence
        int left = 0, right = nums.length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) {
                result[0] = mid;
                right = mid - 1;   // keep searching left for earlier occurrence
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }

        // Right hunter: find last occurrence
        left = 0;
        right = nums.length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) {
                result[1] = mid;
                left = mid + 1;   // keep searching right for later occurrence
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }

        return result;
    }
}
```

### Line-by-line

- `int[] result = {-1, -1};` — initialize result with -1, -1 (in case target is not found).
- `if (nums.length == 0) return result;` — empty array, return immediately.
- **Left hunter:** `left = 0`, `right = nums.length - 1`.
  - `mid = left + (right - left) / 2` — avoids integer overflow.
  - `if (nums[mid] == target)` — found it! Record `result[0] = mid`, then **keep searching left** (`right = mid - 1`) to find an earlier occurrence.
  - `else if (nums[mid] < target)` — middle is too small, so target is to the right.
  - `else` — middle is too big, so target is to the left.
- **Right hunter:** Reset `left = 0`, `right = nums.length - 1`.
  - Same logic, but when `nums[mid] == target`: `result[1] = mid`, then **keep searching right** (`left = mid + 1`).
- `return result;` — if target was never found, both entries remain -1.

### Complexity

- Time: **O(log n)** — two binary searches, each O(log n).
- Space: **O(1)** — just two pointers and a result array.

## Common Mistakes

- **Stopping at first match** — for the left hunter, you must keep searching left to find the **first** occurrence.
- **Not moving past `mid`** — after checking `nums[mid]`, you must set `left = mid + 1` or `right = mid - 1`. Otherwise `mid` stays in the range forever and the loop never ends.
- **Writing `mid = (left + right) / 2`** — if `left` and `right` are both large, their sum can overflow an int. Always write `left + (right - left) / 2`.
- **Using `while (left < right)`** — this stops when `left == right`, leaving one element unchecked. Use `left <= right`.

## How to Explain (interview)

**Opening:** Find First and Last Position finds the starting and ending position of a target value in a sorted array. Since duplicates may exist, a single binary search isn't enough — we need two passes: one to find the leftmost occurrence, another to find the rightmost.

**The basic flow:**
```java
// Left hunter
int left = 0, right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) {
        result[0] = mid;
        right = mid - 1;   // keep searching left for earlier occurrence
    } else if (nums[mid] < target) {
        left = mid + 1;
    } else {
        right = mid - 1;
    }
}
// Right hunter
left = 0;
right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) {
        result[1] = mid;
        left = mid + 1;   // keep searching right for later occurrence
    } else if (nums[mid] < target) {
        left = mid + 1;
    } else {
        right = mid - 1;
    }
}
return result;
```

**The part that trips everyone up:**
- **`left <= right`**: you need `<=`, not just `<`, because when `left == right` there's still one element to check.
- **Moving past `mid`**: after checking `nums[mid]`, you must set `left = mid + 1` or `right = mid - 1`. Otherwise `mid` stays in the range forever and the loop never ends.
- **Returning `mid`**: don't return `mid` directly — store it in `result[0]` or `result[1]` and return `result` at the end.

**The mistakes to remember:**
- Forgetting `left <= right` and writing `left < right`
- Writing `(left + right) / 2` without worrying about overflow
- Forgetting to move `left` or `right` past `mid` after checking it
