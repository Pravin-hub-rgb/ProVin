# 6.4 Find First and Last Position of Element in Sorted Array

## What This Problem Is Asking (Simple Terms)

You have an array of integers sorted in non-decreasing order, and you need to find the **starting** and **ending** position of a given target value.

For example, given `nums = [5,7,7,8,8,10]` and target = 8:
- The number 8 appears at index 3 and index 4
- So you return `[3, 4]`

If the target is not found, return `[-1, -1]`.

---

## Example 1

**Input:** `nums = [5,7,7,8,8,10]`, `target = 8`

**Output:** `[3,4]`

**Explanation:** The 8s appear at index 3 and index 4.

---

## Example 2

**Input:** `nums = [5,7,7,8,8,10]`, `target = 6`

**Output:** `[-1,-1]`

**Explanation:** The value 6 does not exist in the array, so return `[-1, -1]`.

---

## Example 3

**Input:** `nums = []`, `target = 0`

**Output:** `[-1,-1]`

**Explanation:** The array is empty, so there is no target.

---

## Constraints

- `0 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`
- `nums` is sorted in non-decreasing order
- `-10^9 <= target <= 10^4`

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could scan from left to right to find the first occurrence of the target, then scan again from right to left to find the last occurrence. If you never find the target, return `[-1, -1]`.

### Brute Force Pseudocode

```
first = -1, right = -1
for i from 0 to n-1:
    if nums[i] == target:
        if result[0] == -1: result[0] = i
        result[1] = i
return result
```

### Why Brute Force Is Slow

O(n) — you scan the array at most twice. For `n = 10^5` this is fine, but the problem asks for `O(log n)` time.

---

## Which Technique, and Why?

The array is **sorted**, and we need **O(log n)** time. This screams **binary search**.

But standard binary search finds *any* occurrence of the target. We need the **first** and **last** occurrence specifically.

**Signal in the problem:** "sorted array" + "log n runtime" + "first and last position" → binary search, twice.

---

## Why Two Binary Searches?

You might think: "Can I just find one 8 and then expand left and right?" 

No — if there are many 8s, expanding linearly defeats the purpose. You need **two separate binary searches**:

1. **Left hunter:** finds the *leftmost* 8 — when you find 8, keep searching left to see if there's an earlier one.
2. **Right hunter:** finds the **rightmost** 8 — when you find 8, keep searching right to see if there's a later one.

---

## The Left Hunter

You search normally with binary search, but when you find `nums[mid] == target`, you **don't stop**. You record it as a candidate answer and keep searching to the **left** (`right = mid - 1`) to see if there's an earlier occurrence.

### Pseudocode

```
left = 0, right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if nums[mid] == target:
        result[0] = mid        // found one, but keep looking left
        right = mid - 1
    else if nums[mid] < target:
        left = mid + 1
    else:
        right = mid - 1
```

---

## The Right Hunter

Same idea, but mirrored. When you find `nums[mid] == target`, you **keep searching right** (`left = mid + 1`) to find a later occurrence.

### Pseudocode

```
left = 0, right = n - 1
while left <= right:
    mid = left + (right - left) / 2
    if nums[mid] == target:
        result[1] = mid
        left = mid + 1         // keep searching right for a later one
    else if nums[mid] < target:
        left = mid + 1
    else:
        right = mid - 1
```

---

## Java Code

```java
class Solution {
    public int[] searchRange(int[] nums, int target) {
        int[] result = {-1, -1};
        if (nums.length == 0) return result;

        // Left hunter: find first occurrence
        int left = 0, right = nums.length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) {
                result[0] = mid;
                right = mid - 1;   // keep searching left for earlier occurrence
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }

        // Right hunter: find last occurrence
        left = 0;
        right = nums.length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) {
                result[1] = mid;
                left = mid + 1;   // keep searching right for later occurrence
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }

        return result;
    }
}
```

### Line-by-line

- `int[] result = {-1, -1};` — initialize result with -1, -1 (in case target is not found)
- `left = 0, right = nums.length - 1` — the full search range
- `int mid = left + (right - left) / 2` — the middle index (overflow-safe)
- `if (nums[mid] == target)` — found it! Record `mid` as candidate, then search left to see if there's an earlier one
- `right = mid - 1` — shrink the right boundary to search left
- `if (nums[mid] < target) left = mid + 1` — target is bigger, so search right half
- `else right = mid - 1;` — middle is too big, so target must be to the left

## Complexity

- Time: O(log n) — two binary searches, each O(log n)
- Space: O(1) — just two pointers per hunter

## Common Mistakes

- **Stopping at first match** — for the left hunter, you must keep searching left to find the **first** occurrence
- **Not moving past `mid`** — after checking `nums[mid]`, you must set `left = mid + 1` or `right = mid - 1`. Otherwise `mid` stays in range forever and the loop never ends.
- **Writing `(left + right) / 2`** — can overflow for large arrays. Always use `left + (right - left) / 2`.

---

## How to Explain (interview)

**Opening:** Find First and Last Position finds the first and last occurrence of a target in a sorted array. Since the array is sorted, use binary search twice: once to find the leftmost occurrence, once to find the rightmost.

**The basic flow:**
```java
// Left hunter
int left = 0, right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) {
        result[0] = mid;
        right = mid - 1;   // keep searching left
    } else if (nums[mid] < target) {
        left = mid + 1;
    } else {
        right = mid - 1;
    }
}
// Right hunter
left = 0; right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) {
        result[1] = mid;
        left = mid + 1;   // keep searching right
    } else if (nums[mid] < target) {
        left = mid + 1;
    } else {
        right = mid - 1;
    }
}
return result;
```

**The part that trips everyone up:**
- **`left <= right`**: you need `<=`, not just `<`, because when `left == right` there's still one element to check.
- **Moving past `mid`**: after checking `nums[mid]`, you must set `left = mid + 1` or `right = mid - 1`. Otherwise `mid` stays in the range forever and the loop never ends.
- **Returning `result`**: initialized to `{-1, -1}`, so if target is never found, you return `[-1, -1]` automatically.

**The mistakes to remember:**
- Forgetting `left <= right` and writing `left < right`
- Writing `(left + right) / 2` without worrying about overflow
- Stopping at the first match instead of continuing to search left/right
