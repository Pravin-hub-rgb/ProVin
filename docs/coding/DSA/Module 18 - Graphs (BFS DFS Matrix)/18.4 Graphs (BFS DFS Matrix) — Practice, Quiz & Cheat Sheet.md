## Mini Quiz

1. What is the difference between BFS and DFS in terms of space complexity?
2. Why does "sinking" a cell (setting to '0') prevent infinite loops?
3. When should you use BFS instead of DFS?
4. What is the time complexity of flood fill on an m×n grid?
5. How do you handle 8-directional connectivity vs 4-directional?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. BFS uses O(V) space (queue holds up to one level, worst case V/2 for a complete tree). DFS uses O(V) space in the worst case (recursion stack for a skewed graph) but O(depth) typically. For grids, both are O(m×n) worst case. BFS is needed for shortest path; DFS is simpler for component counting.
2. Sinking marks the cell as visited ('0' = water). When DFS revisits the cell, the boundary check `grid[i][j] != '1'` returns immediately, preventing re-processing and infinite loops. Without sinking, the same cell would be visited repeatedly.
3. Use BFS when you need the shortest path in an unweighted graph/grid (BFS explores level by level, so the first time you reach a node is via the shortest path). Use DFS for connected components, flood fill, and path existence (simpler to implement recursively).
4. O(m × n) — each cell is visited at most once. The flood fill marks cells as visited, so no cell is processed twice.
5. 4-directional: check up, down, left, right (i±1, j±1 with one coordinate fixed). 8-directional: also check the 4 diagonals. The problem statement specifies which. Most "island" problems are 4-directional.

</details>

## One-Page Cheat Sheet

**DFS flood fill (sink):**
```java
void dfs(char[][] grid, int i, int j) {
    if (i < 0 || j < 0 || i >= grid.length || j >= grid[0].length || grid[i][j] != '1') return;
    grid[i][j] = '0';  // sink
    dfs(grid, i + 1, j);
    dfs(grid, i - 1, j);
    dfs(grid, i, j + 1);
    dfs(grid, i, j - 1);
}
```

**DFS returning area:**
```java
int dfs(int[][] grid, int i, int j) {
    if (i < 0 || j < 0 || i >= grid.length || j >= grid[0].length || grid[i][j] != 1) return 0;
    grid[i][j] = 0;
    return 1 + dfs(grid, i + 1, j) + dfs(grid, i - 1, j) +
               dfs(grid, i, j + 1) + dfs(grid, i, j - 1);
}
```

**BFS (level order):**
```java
Queue<int[]> q = new ArrayDeque<>();
q.offer(new int[]{startI, startJ});
while (!q.isEmpty()) {
    int[] cell = q.poll();
    for (int[] dir : new int[][]{{1,0},{-1,0},{0,1},{0,-1}}) {
        int ni = cell[0] + dir[0], nj = cell[1] + dir[1];
        if (inBounds && grid[ni][nj] == 1) {
            grid[ni][nj] = 0;  // mark visited
            q.offer(new int[]{ni, nj});
        }
    }
}
```

**Complexities:** O(m × n) time. O(m × n) space for recursion (O(1) if modifying in place). BFS uses O(min(m,n)) space for the queue.

## In Your Own Words

1. Why does "sinking" a cell prevent infinite loops in flood fill?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Sinking marks the cell as visited (changed from '1' to '0'). When DFS revisits the cell, the boundary check `grid[i][j] != '1'` returns immediately (the cell is now '0'). Without sinking, the same cell would be visited repeatedly, causing infinite recursion. The sink is both the "visited" marker and the "don't process again" guard.

</details>

2. When should you use BFS instead of DFS for a grid problem?

<details>
<summary>Show Answer</summary>
**Sample Answer:** Use BFS when you need the shortest path (BFS explores level by level, so the first time you reach a cell is via the shortest path). Use DFS for connected components, flood fill, and "is there a path" (simpler to implement recursively). For counting islands or max area, both work — DFS is simpler. For shortest path, BFS is required.

</details>

3. What is the difference between 4-directional and 8-directional connectivity?

<details>
<summary>Show Answer</summary>

**Sample Answer:** 4-directional: cells are connected if they share an edge (up, down, left, right). 8-directional: also includes diagonal connections. Most "island" problems use 4-directional. The problem statement specifies which. With 8-directional, you check 8 neighbors instead of 4.

</details>
