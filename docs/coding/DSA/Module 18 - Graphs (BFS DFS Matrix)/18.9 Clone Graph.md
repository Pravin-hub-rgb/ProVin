# 18.9 Clone Graph

**Tier 2 problem.** (LeetCode #133)

**Problem:** Given a connected undirected graph, return a deep copy. (LeetCode #133)

**Link:** https://leetcode.com/problems/clone-graph/

---

## Which Technique, and Why?

"Deep copy a graph" → **DFS/BFS + HashMap (original → copy)**. Create a copy of each node, store the mapping, then wire up neighbors using the map. O(V + E) time, O(V) space.

**Signal in the problem:** "clone graph" / "deep copy" → HashMap (original → copy) + DFS/BFS.

## Approach

DFS: if node is null → return null. If node already in map → return map[node]. Create copy, store in map. For each neighbor, recursively clone and add to copy's neighbors. Return copy.

## Pseudocode

```
map = empty (original -> copy)
clone(node):
    if node == null: return null
    if node in map: return map[node]
    copy = new Node(node.val)
    map[node] = copy
    for neighbor in node.neighbors:
        copy.neighbors.add(clone(neighbor))
    return copy
```

## Java Code

```java
class Solution {
    private final Map<Node, Node> map = new HashMap<>();

    public Node cloneGraph(Node node) {
        if (node == null) return null;
        if (map.containsKey(node)) return map.get(node);

        Node clone = new Node(node.val);
        map.put(node, clone);

        for (Node neighbor : node.neighbors) {
            clone.neighbors.add(cloneGraph(neighbor));
        }
        return clone;
    }
}
```

## Line-by-line

- `map` stores original → copy mapping.
- If node already cloned → return the copy (prevents infinite loop on cycles).
- Create copy, store in map **before** recursing (so cycles are handled).
- For each neighbor, recursively clone and add to copy's neighbors.

## Complexity

- Time: O(V + E) — visit every node and edge once.
- Space: O(V) — map + recursion stack.

## Common Mistakes

- **Not storing in map before recursing.** If you recurse first, cycles cause infinite recursion. Store the mapping before exploring neighbors.
- **Using `==` for node comparison.** Use the map (reference equality works for objects, but the map is the clean way).
- **Not handling null.** Empty graph → return null.
- **Modifying the original.** Don't change the original's neighbors.

## How to Explain (interview)

**Opening:** Clone Graph creates a deep copy. HashMap (original → copy): for each node, create a copy and store the mapping, then wire neighbors using the map. Handle cycles by checking the map before recursing. O(V+E) time, O(V) space.

**The basic flow:**
```java
Map<Node, Node> map = new HashMap<>();
Node clone(Node node) {
    if (node == null) return null;
    if (map.containsKey(node)) return map.get(node);
    Node clone = new Node(node.val);
    map.put(node, clone);
    for (Node n : node.neighbors) clone.neighbors.add(clone(n));
    return clone;
}
```

**The part that trips everyone up:** store the mapping **before** recursing (so cycles are handled). If you recurse first, infinite loop.

**The mistakes to remember:**
- Not storing in map before recursing (infinite loop on cycles)
- Not handling null (empty graph)
- Modifying the original graph
- Using BFS instead of DFS (both work; DFS is simpler)
