## The Core Idea

A **graph** is a set of nodes (vertices) connected by edges. In DSA, graphs appear as:
- **Explicit graphs:** given as adjacency list/matrix (nodes and edges).
- **Implicit graphs:** grids/matrices where each cell is a node and neighbors are adjacent cells.

**Representation:**
- **Adjacency list:** `Map<Integer, List<Integer>>` or `List<List<Integer>>`. Space O(V + E). Best for sparse graphs.
- **Adjacency matrix:** `boolean[][]` or `int[][]`. Space O(V²). Best for dense graphs or small V.

**BFS (Breadth-First Search):** explore level by level using a queue. Finds shortest path in unweighted graphs. O(V + E) time, O(V) space.

**DFS (Depth-First Search):** explore as deep as possible, then backtrack. Uses recursion or an explicit stack. O(V + E) time, O(V) space (recursion stack).

**For grid problems:** BFS and DFS both work. DFS is simpler to write recursively. BFS is needed for shortest path. For "count islands" or "max area," either works.

## How to Recognize It

Think "Graphs / BFS / DFS / Matrix" when:
- The input is a **2D grid/matrix** of 0s and 1s (or characters) → each cell is a node, neighbors are adjacent.
- The problem asks to **count connected components** / "number of islands."
- The problem asks for the **largest connected component** / "max area."
- The problem involves **shortest path** in an unweighted graph/grid → BFS.
- Keywords: "islands," "connected components," "flood fill," "shortest path," "matrix," "grid."

**Signal words:** "islands," "connected," "matrix," "grid," "flood fill," "shortest path," "BFS," "DFS."

## Worked Example: Number of Islands

**Problem:** Given a grid of '1's (land) and '0's (water), count the number of islands (connected groups of '1's, 4-directionally).

### Brute force (O(n²) with union-find or flood fill)

Flood fill each island, mark visited, count.

### Optimized (O(m × n)) — DFS flood fill

```java
class Solution {
    public int numIslands(char[][] grid) {
        if (grid == null || grid.length == 0) return 0;
        int count = 0;
        for (int i = 0; i < grid.length; i++) {
            for (int j = 0; j < grid[0].length; j++) {
                if (grid[i][j] == '1') {
                    count++;
                    dfs(grid, i, j);  // sink the island
                }
            }
        }
        return count;
    }

    private void dfs(char[][] grid, int i, int j) {
        if (i < 0 || j < 0 || i >= grid.length || j >= grid[0].length || grid[i][j] != '1') {
            return;
        }
        grid[i][j] = '0';  // mark visited (sink)
        dfs(grid, i + 1, j);
        dfs(grid, i - 1, j);
        dfs(grid, i, j + 1);
        dfs(grid, i, j - 1);
    }
}
```

**Line-by-line:**
- Outer loop scans every cell. When a '1' is found, increment count and sink the entire island.
- `dfs` marks the current cell as '0' (visited) and recurses on 4 neighbors.
- The boundary checks prevent out-of-bounds and re-visiting.
- Each cell is visited at most once → O(m × n) time.

**Key insight:** "sinking" the island (marking visited cells as '0') avoids a separate visited array. This is the standard grid DFS pattern.

## Common Mistakes

- **Not marking visited.** Without marking, you'll infinite-loop or re-count. Mark cells as visited (set to '0' or use a visited array).
- **Wrong neighbor directions.** 4-directional: up/down/left/right. 8-directional: also diagonals. Read the problem — "4-directionally connected" vs "8-directionally."
- **Modifying the input.** Sinking modifies the grid. If the problem says "don't modify," use a visited boolean array.
- **Stack overflow on large grids.** Deep recursion on a 1000×1000 grid can overflow. Use iterative DFS (explicit stack) or BFS (queue).
- **Off-by-one in bounds.** `i >= grid.length` and `j >= grid[0].length`. Check all four boundaries.

## How to Explain (interview)

**Opening:** Graph problems on grids: each cell is a node, neighbors are adjacent cells (4 or 8 directions). Count islands = count connected components. DFS flood fill: when you find a '1', increment count and sink the entire island (mark visited). O(m×n) time, O(m×n) space for recursion stack (or O(1) if modifying in place). BFS also works and is needed for shortest path.

**The basic flow:**
```java
for each cell:
    if cell == '1':
        count++
        dfs(cell)  // sink the island
// dfs: mark current as '0', recurse on 4 neighbors
```

**The part that trips everyone up:** marking visited (sink to '0' or visited array). Without it, infinite loop or re-counting. Also, distinguish 4-directional vs 8-directional connectivity.

**The mistakes to remember:**
- Not marking visited (infinite loop / re-count)
- Wrong neighbor directions (4 vs 8)
- Modifying input when problem forbids it
- Stack overflow on large grids (use iterative)
- Off-by-one in bounds checks
