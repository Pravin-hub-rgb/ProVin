## The Core Idea

A **Binary Search Tree (BST)** is a binary tree where, for every node:
- All values in the **left subtree** are **less than** the node's value.
- All values in the **right subtree** are **greater than** the node's value.

This property makes search, insert, and (conceptually) delete O(height) = O(log n) on a balanced tree.

**Key operations:**
- **Search:** compare target with node.val; go left if smaller, right if larger. O(h).
- **Insert:** search for the position; insert as a leaf. O(h).
- **Delete:** three cases — (1) leaf → remove; (2) one child → replace with child; (3) two children → replace with inorder successor (smallest in right subtree), then delete successor. O(h).
- **Inorder traversal** gives sorted order (left, root, right).

## How to Recognize It

Think "BST" when:
- The tree has an **ordering property** (left < root < right).
- The problem asks to **search, insert, or validate** a BST.
- The problem involves **LCA in a BST** (LCA is the first node where the two values diverge).
- Keywords: "binary search tree," "BST," "validate BST," "LCA of BST," "kth smallest in BST."

**Signal words:** "binary search tree," "BST," "left < root < right," "inorder sorted," "LCA," "kth smallest."

## Worked Example: Search in a BST

**Problem:** Given a BST and a target, return the node if found, else null.

### Brute force (O(n))

Linear scan of all nodes — ignores the BST property.

### Optimized (O(h)) — exploit ordering

```java
class Solution {
    public TreeNode searchBST(TreeNode root, int val) {
        if (root == null || root.val == val) return root;
        if (val < root.val) return searchBST(root.left, val);
        return searchBST(root.right, val);
    }
}
```

**Line-by-line:**
- `root == null` → not found (base case).
- `root.val == val` → found, return node.
- `val < root.val` → target is in the left subtree → recurse left.
- `val > root.val` → target is in the right subtree → recurse right.

**Key insight:** the BST property lets you eliminate half the tree at each step (on a balanced tree). O(h) = O(log n) for balanced, O(n) for skewed.

## Common Mistakes

- **Not using the BST property.** Treating a BST like a general binary tree (DFS all nodes) is O(n) — correct but slow. Use the ordering to search in O(h).
- **Assuming the BST is balanced.** A BST can be skewed (e.g., inserted in sorted order) → O(n) worst case. If balance matters, use an AVL/Red-Black tree (not covered here).
- **LCA in BST:** LCA is the first node where one value is ≤ node.val and the other is ≥ node.val. Don't use the general tree LCA algorithm (which checks both subtrees) — the BST property gives a simpler O(h) solution.
- **Validating a BST:** checking `left.val < root.val < right.val` is not enough — the entire left subtree must be < root.val. Use min/max bounds: `isValid(node, min, max)`.

## How to Explain (interview)

**Opening:** A BST is a binary tree where left subtree values < node value < right subtree values. This enables O(h) search/insert (h = height). Inorder traversal gives sorted order. LCA in a BST is the first node where the two values diverge (one ≤ node, other ≥ node). O(h) time, O(h) space for recursion.

**The basic flow (search):**
```java
if (root == null || root.val == val) return root;
if (val < root.val) return searchBST(root.left, val);
return searchBST(root.right, val);
```

**The part that trips everyone up:** the BST property applies to the **entire** subtree, not just direct children. `left.val < root.val < right.val` is necessary but not sufficient. For validation, pass min/max bounds.

**The mistakes to remember:**
- Treating BST like a general tree (O(n) instead of O(h))
- Assuming balanced (worst case O(n) on skewed tree)
- LCA: use the BST property (divergence point), not general tree LCA
- Validation: need min/max bounds, not just direct children comparison
