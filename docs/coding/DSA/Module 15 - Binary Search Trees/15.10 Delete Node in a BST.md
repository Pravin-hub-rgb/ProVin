**Tier 2 problem.** (LeetCode #450)

**Problem:** Given the root of a BST and a key, delete the node with that key and return the root. (LeetCode #450)

**Link:** https://leetcode.com/problems/delete-node-in-a-bst/

---

## Which Technique, and Why?

"Delete a node from a BST" → **BST search + three cases.** (1) Leaf → remove (return null). (2) One child → replace with child. (3) Two children → replace with inorder successor (smallest in right subtree), then delete successor. O(h) time, O(h) space.

**Signal in the problem:** "delete node in BST" → BST search + three cases (leaf, one child, two children).

## Approach

Search for the node. When found:
- **Leaf (no children):** return null.
- **One child:** return that child.
- **Two children:** find the inorder successor (smallest in right subtree), copy its value, then delete the successor from the right subtree.

## Pseudocode

```
deleteNode(root, key):
    if root == null: return null
    if key < root.val: root.left = deleteNode(root.left, key)
    elif key > root.val: root.right = deleteNode(root.right, key)
    else:  // found
        if root.left == null: return root.right
        if root.right == null: return root.left
        // two children: find inorder successor
        successor = root.right
        while successor.left != null: successor = successor.left
        root.val = successor.val
        root.right = deleteNode(root.right, successor.val)
    return root
```

## Java Code

```java
class Solution {
    public TreeNode deleteNode(TreeNode root, int key) {
        if (root == null) return null;

        if (key < root.val) {
            root.left = deleteNode(root.left, key);
        } else if (key > root.val) {
            root.right = deleteNode(root.right, key);
        } else {
            // Found the node
            if (root.left == null) return root.right;
            if (root.right == null) return root.left;

            // Two children: find inorder successor
            TreeNode successor = root.right;
            while (successor.left != null) successor = successor.left;
            root.val = successor.val;
            root.right = deleteNode(root.right, successor.val);
        }
        return root;
    }
}
```

## Line-by-line

- Search: if key < root.val → left; if key > root.val → right.
- Found: if one child is null → return the other child.
- Two children: find the inorder successor (leftmost in right subtree). Copy its value. Delete the successor from the right subtree (recursively).
- The BST property is maintained: successor is the smallest value > root.val, so replacing root.val with it keeps left < root < right.

## Complexity

- Time: O(h) — search + find successor + delete. O(log n) balanced, O(n) skewed.
- Space: O(h) — recursion stack.

## Common Mistakes

- **Not handling all three cases.** Leaf, one child, two children — each needs different handling.
- **Finding the wrong successor.** The inorder successor is the **smallest** in the right subtree (leftmost node of right subtree). Not the largest in the left subtree (that's the predecessor — also valid, but be consistent).
- **Not deleting the successor after copying.** If you copy the successor's value but don't delete it, you have a duplicate.
- **Modifying the tree when not allowed.** This problem expects in-place modification.

## How to Explain (interview)

**Opening:** Delete Node in a BST removes a node in O(h) time. Three cases: (1) leaf → return null; (2) one child → return that child; (3) two children → replace with inorder successor (smallest in right subtree), then delete successor. O(h) time, O(h) space.

**The basic flow:**
```java
if (key < root.val) root.left = deleteNode(root.left, key);
else if (key > root.val) root.right = deleteNode(root.right, key);
else {
    if (root.left == null) return root.right;
    if (root.right == null) return root.left;
    // two children: find successor, copy, delete
    TreeNode succ = root.right;
    while (succ.left != null) succ = succ.left;
    root.val = succ.val;
    root.right = deleteNode(root.right, succ.val);
}
return root;
```

**The part that trips everyone up:** for two children, you must **delete the successor** after copying its value. Also, the successor is the **leftmost** node in the right subtree (smallest value greater than root).

**The mistakes to remember:**
- Not handling all three cases
- Finding the wrong successor (largest in left instead of smallest in right)
- Not deleting the successor after copying
- Modifying when problem says don't
