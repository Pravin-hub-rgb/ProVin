**Tier 2 problem.** (LeetCode #230)

**Problem:** Given the root of a BST, return the kth smallest value. (LeetCode #230)

**Link:** https://leetcode.com/problems/kth-smallest-element-in-a-bst/

---

## Which Technique, and Why?

"Kth smallest in a BST" → **Inorder traversal** (gives sorted order) + stop at kth. O(k) time best, O(n) worst, O(h) space. Or use a counter during inorder. No need to traverse the whole tree.

**Signal in the problem:** "kth smallest in BST" → inorder traversal (sorted order) + stop at k.

## Approach

Inorder traversal. Maintain a counter. When counter reaches k, record the value. Stop early (don't traverse the whole tree).

## Pseudocode

```
count = 0, result = 0
inorder(node, k):
    if node == null: return
    inorder(node.left, k)
    count++
    if count == k: result = node.val; return
    inorder(node.right, k)
```

## Java Code

```java
class Solution {
    private int count = 0;
    private int result = 0;

    public int kthSmallest(TreeNode root, int k) {
        inorder(root, k);
        return result;
    }

    private void inorder(TreeNode node, int k) {
        if (node == null) return;
        inorder(node.left, k);
        if (++count == k) {
            result = node.val;
            return;
        }
        inorder(node.right, k);
    }
}
```

## Line-by-line

- `count` tracks how many nodes have been visited in inorder.
- `inorder(node.left)` — visit left subtree first.
- `if (++count == k)` — increment and check. If kth, record and return (early exit).
- `inorder(node.right)` — visit right subtree.

## Complexity

- Time: O(k) best (if k is small), O(n) worst (k = n).
- Space: O(h) — recursion stack.

## Common Mistakes

- **Traversing the whole tree.** Stop early when count == k. Don't visit remaining nodes.
- **Using a list.** Storing all elements in a list is O(n) space. The counter approach is O(h) space.
- **Not handling k = 1.** The smallest element is the leftmost node. The algorithm handles this (count reaches 1 at the first inorder node).
- **Confusing with "Kth Largest."** For kth largest, do reverse inorder (right, root, left) or use `k = n - k + 1`.

## How to Explain (interview)

**Opening:** Kth Smallest in a BST uses inorder traversal (which gives sorted order for BST). Walk inorder, count nodes; when count reaches k, record and stop. O(k) time (best), O(h) space. No need to traverse the whole tree.

**The basic flow:**
```java
int count = 0, result = 0;
void inorder(TreeNode node, int k) {
    if (node == null) return;
    inorder(node.left, k);
    if (++count == k) { result = node.val; return; }
    inorder(node.right, k);
}
```

**The part that trips everyone up:** stop early when `count == k` — don't traverse the remaining tree. Also, inorder gives sorted order **only for BST** (not general binary trees).

**The mistakes to remember:**
- Traversing the whole tree (wasted work)
- Using a list (O(n) space instead of O(h))
- Not handling k = 1 (leftmost node)
- Confusing with Kth Largest (reverse inorder)
