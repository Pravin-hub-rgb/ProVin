## Mini Quiz

1. What is the time complexity of search/insert in a BST, and what's the worst case?
2. How do you find the LCA of two nodes in a BST?
3. Why does inorder traversal of a BST give sorted order?
4. How do you validate that a binary tree is a BST?
5. What are the three cases for deleting a node in a BST?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. O(h) where h = height. O(log n) for balanced, O(n) for skewed (e.g., inserted in sorted order). The BST property lets you eliminate half the tree at each step on a balanced tree.
2. The LCA is the first node where p and q diverge: if both < root.val, go left; if both > root.val, go right; otherwise, root is the LCA. O(h) time, no need to search both subtrees.
3. Inorder visits left → root → right. In a BST, left < root < right, so visiting in this order produces ascending order. This is a property of BSTs only.
4. Pass min/max bounds down: `isValid(node, min, max)` checks `min < node.val < max`, then recurses with updated bounds (left: max = node.val, right: min = node.val). O(n) time. Use long for bounds to handle Integer.MAX_VALUE/MIN_VALUE.
5. (1) Leaf: return null. (2) One child: return that child. (3) Two children: replace with inorder successor (smallest in right subtree), then delete the successor.

</details>

## One-Page Cheat Sheet

**BST property:** left subtree < node < right subtree.

**Search:** `if (val < root.val) go left; else go right;`
**Insert:** search for position, insert as leaf.
**LCA:** first node where p and q diverge.
**Validate:** min/max bounds, `min < node.val < max`.
**Convert sorted array to BST:** middle as root, recurse.
**Delete:** leaf → null; one child → child; two children → inorder successor.
**Iterator:** push left spine; pop, push left spine of right child.

**Complexities:** Search/insert/delete: O(h) = O(log n) balanced, O(n) skewed. Inorder: O(n).

## In Your Own Words

1. Why is searching in a BST O(h) instead of O(n)?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The BST property (left < root < right) lets you eliminate half the tree at each step: if target < node.val, go left; if target > node.val, go right. You only follow one path down. For a balanced tree, h = log n → O(log n). For a skewed tree, h = n → O(n). The BST property is what makes it faster than a general tree search (O(n)).

</details>

2. How does the BST property make LCA simpler than in a general tree?

<details>
<summary>Show Answer</summary>

**Sample Answer:** In a general tree, LCA requires checking both subtrees (O(n)). In a BST, the ordering property tells you which direction to go: if both p and q are less than root, go left; if both greater, go right; otherwise, root is the LCA (divergence point). You only follow one path down — O(h) time, O(1) space (iterative).

</details>

3. What is the difference between "Validate BST" (#98) and "is it a BST" as a general check?

<details>
<summary>Show Answer</summary>

**Sample Answer:** #98 (Validate BST) checks if a given binary tree satisfies the BST property. The key insight: checking `left.val < root.val < right.val` for direct children is NOT sufficient — the entire left subtree must be < root.val and the entire right subtree must be > root.val. Use min/max bounds: `isValid(node, min, max)` checks `min < node.val < max`. This is the correct, complete check.

</details>
