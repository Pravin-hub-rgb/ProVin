## Mini Quiz

1. What is the time complexity of search/insert in a BST, and what's the worst case?
2. How do you find the LCA of two nodes in a BST (without the general tree algorithm)?
3. Why does inorder traversal of a BST give sorted order?
4. How do you validate that a binary tree is a BST?
5. What is the delete operation in a BST, and what are its three cases?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. O(h) where h = height. O(log n) for balanced, O(n) for skewed (e.g., inserted in sorted order). The BST property lets you eliminate half the tree at each step (on a balanced tree).
2. The LCA is the first node where p and q diverge: if both < root.val, go left; if both > root.val, go right; otherwise, root is the LCA. O(h) time, no need to search both subtrees.
3. Inorder visits left → root → right. In a BST, left < root < right, so visiting in this order produces ascending order. This is a property of BSTs, not general binary trees.
4. Pass min/max bounds down the tree: `isValid(node, min, max)` checks `min < node.val < max`, then recurses with updated bounds. Left child: max = node.val. Right child: min = node.val. O(n) time.
5. (1) Leaf: remove it. (2) One child: replace node with its child. (3) Two children: replace with inorder successor (smallest in right subtree), then delete the successor. O(h) time.

</details>

## One-Page Cheat Sheet

**BST property:** left subtree < node < right subtree (for all nodes).

**Search:**
```java
if (root == null || root.val == val) return root;
return (val < root.val) ? search(root.left, val) : search(root.right, val);
```

**Insert:**
```java
if (root == null) return new TreeNode(val);
if (val < root.val) root.left = insert(root.left, val);
else root.right = insert(root.right, val);
return root;
```

**LCA (BST):**
```java
if (p.val < root.val && q.val < root.val) return lca(root.left, p, q);
if (p.val > root.val && q.val > root.val) return lca(root.right, p, q);
return root;
```

**Validate BST (with bounds):**
```java
boolean isValid(TreeNode node, long min, long max) {
    if (node == null) return true;
    if (node.val <= min || node.val >= max) return false;
    return isValid(node.left, min, node.val) && isValid(node.right, node.val, max);
}
// call: isValid(root, Long.MIN_VALUE, Long.MAX_VALUE)
```

**Convert sorted array to BST:**
```java
TreeNode build(int[] nums, int l, int r) {
    if (l > r) return null;
    int mid = l + (r - l) / 2;
    TreeNode node = new TreeNode(nums[mid]);
    node.left = build(nums, l, mid - 1);
    node.right = build(nums, mid + 1, r);
    return node;
}
```

**Complexities:** Search/insert/delete: O(h) = O(log n) balanced, O(n) skewed. Inorder: O(n).

## In Your Own Words

1. Why is searching in a BST O(h) instead of O(n)?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The BST property (left < root < right) lets you eliminate half the tree at each step: if target < node.val, go left; if target > node.val, go right. You only follow one path down the tree. For a balanced tree, h = log n → O(log n). For a skewed tree, h = n → O(n). The BST property is what makes it faster than a general tree search (O(n)).

</details>

2. How does the BST property make "Convert Sorted Array to BST" straightforward?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A sorted array is already in inorder order. The middle element becomes the root (so left and right halves have equal size → balanced). Recurse on the left half (smaller elements) and right half (larger elements). The BST property is satisfied automatically because the array is sorted. O(n) time, O(log n) space.

</details>

3. Why is LCA in a BST simpler than LCA in a general binary tree?

<details>
<summary>Show Answer</summary>
**Sample Answer:** In a general tree, LCA requires checking both subtrees (O(n)). In a BST, the ordering property tells you which direction to go: if both p and q are less than root, go left; if both greater, go right; otherwise, root is the LCA (divergence point). You only follow one path down — O(h) time, O(1) space (iterative).

</details>
