# 15.2 Search in a BST

**Problem:** Given the root of a BST and a value, return the node if the value exists, otherwise null. (LeetCode #700)

**Link:** https://leetcode.com/problems/search-in-a-binary-search-tree/

---

## Which Technique, and Why?

BST search → **exploit the ordering property**. Compare target with node.val; go left if smaller, right if larger. O(h) time, O(h) space (recursion) or O(1) (iterative). Much faster than O(n) linear search on a general tree.

**Signal in the problem:** "search in a BST" / "find a value in a BST" → BST search (O(h)).

## Approach

If root is null or root.val == val → return root. If val < root.val → search left. Else → search right.

## Pseudocode

```
if root == null or root.val == val: return root
if val < root.val: return search(root.left, val)
return search(root.right, val)
```

## Java Code

```java
class Solution {
    public TreeNode searchBST(TreeNode root, int val) {
        if (root == null || root.val == val) return root;
        if (val < root.val) return searchBST(root.left, val);
        return searchBST(root.right, val);
    }
}
```

## Iterative version

```java
class Solution {
    public TreeNode searchBST(TreeNode root, int val) {
        while (root != null && root.val != val) {
            root = (val < root.val) ? root.left : root.right;
        }
        return root;
    }
}
```

## Line-by-line

- Base case: `root == null` (not found) or `root.val == val` (found).
- `val < root.val` → target is in the left subtree → go left.
- `val > root.val` → target is in the right subtree → go right.
- Iterative version: same logic in a loop, O(1) space.

## Complexity

- Time: O(h) where h = height. O(log n) for balanced, O(n) for skewed.
- Space: O(h) recursive, O(1) iterative.

## Common Mistakes

- **Treating it as a general tree.** DFS all nodes is O(n) — correct but ignores the BST property. Use the ordering for O(h).
- **Not handling null.** `root == null` → return null.
- **Assuming balanced.** Worst case O(n) on a skewed tree (e.g., inserted in sorted order). If the problem requires O(log n), the tree must be balanced (AVL/Red-Black).
- **Off-by-one in comparison.** `val < root.val` → left, `val > root.val` → right. Use `<` and `>`, not `<=` and `>=` (no duplicates in a BST, or handle duplicates consistently).

## How to Explain (interview)

**Opening:** Search in a BST finds a value in O(h) time (h = height). Compare target with node.val: if smaller, go left; if larger, go right. Base cases: null (not found) or match (found). O(log n) on balanced trees, O(n) worst case on skewed trees.

**The basic flow:**
```java
if (root == null || root.val == val) return root;
return (val < root.val) ? searchBST(root.left, val) : searchBST(root.right, val);
```

**The part that trips everyone up:** use the BST property — don't traverse all nodes. Also, the iterative version uses O(1) space (no recursion stack).

**The mistakes to remember:**
- Treating BST as a general tree (O(n) instead of O(h))
- Not handling null (NPE)
- Assuming balanced (worst case O(n))
- Using `<=`/`>=` instead of `<`/`>` (duplicates)
