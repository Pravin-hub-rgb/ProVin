# 15.11 Binary Search Tree Iterator

**Tier 2 problem.** (LeetCode #173)

**Problem:** Implement an iterator over a BST. `next()` returns the next smallest element. `hasNext()` returns true if there's a next. Both should be O(1) amortized. (LeetCode #173)

**Link:** https://leetcode.com/problems/binary-search-tree-iterator/

---

## Which Technique, and Why?

"BST iterator with O(1) amortized next()" → **Iterative inorder traversal with a stack**. Push all left nodes from root. `next()`: pop top, push all left nodes of its right child. `hasNext()`: stack non-empty. O(1) amortized per call (each node pushed/popped once).

**Signal in the problem:** "BST iterator" / "next smallest" / "O(1) amortized" → iterative inorder with a stack.

## Approach

Constructor: push all left nodes from root. `next()`: pop top, push all left nodes from its right child, return top.val. `hasNext()`: stack non-empty.

## Pseudocode

```
constructor(root):
    stack = empty
    pushLeft(root)

pushLeft(node):
    while node != null:
        stack.push(node)
        node = node.left

next():
    node = stack.pop()
    pushLeft(node.right)
    return node.val

hasNext():
    return !stack.isEmpty()
```

## Java Code

```java
class BSTIterator {
    private final Deque<TreeNode> stack;

    public BSTIterator(TreeNode root) {
        stack = new ArrayDeque<>();
        pushLeft(root);
    }

    private void pushLeft(TreeNode node) {
        while (node != null) {
            stack.push(node);
            node = node.left;
        }
    }

    public int next() {
        TreeNode node = stack.pop();
        pushLeft(node.right);
        return node.val;
    }

    public boolean hasNext() {
        return !stack.isEmpty();
    }
}
```

## Line-by-line

- Constructor: `pushLeft(root)` pushes all left nodes (the inorder sequence starts with the leftmost).
- `pushLeft(node)`: walks left, pushing each node. This ensures the next smallest is always on top.
- `next()`: pop the top (smallest unreturned), then push all left nodes of its right child (they're the next candidates in sorted order).
- `hasNext()`: stack non-empty → more nodes to return.

## Complexity

- `next()`: O(1) amortized (each node pushed/popped once, total O(n) over all calls).
- `hasNext()`: O(1).
- Space: O(h) — stack holds at most h nodes (height of tree).

## Common Mistakes

- **Recursive inorder (store all in a list).** O(n) space and O(n) preprocessing. Works but doesn't meet O(1) amortized / O(h) space.
- **Not pushing left nodes of the right child.** After popping a node, you must push the left spine of its right child (those are the next smallest).
- **Using `peek()` instead of `pop()`.** `next()` must remove the node from the stack.
- **Not handling null root.** Constructor with null → stack empty → `hasNext()` returns false. Correct.

## How to Explain (interview)

**Opening:** BST Iterator returns the next smallest element in O(1) amortized. Iterative inorder with a stack: constructor pushes all left nodes (leftmost first). `next()` pops the top, pushes all left nodes of its right child. `hasNext()` checks if stack is non-empty. O(h) space.

**The basic flow:**
```java
void pushLeft(TreeNode node) {
    while (node != null) { stack.push(node); node = node.left; }
}
int next() {
    TreeNode node = stack.pop();
    pushLeft(node.right);
    return node.val;
}
```

**The part that trips everyone up:** after popping, you must push the left spine of the **right child** (not the right child itself). Those are the next candidates in sorted order. Also, `pushLeft` must walk all the way left.

**The mistakes to remember:**
- Recursive inorder (O(n) space, not O(h))
- Not pushing left nodes of right child
- Using peek instead of pop
- Not handling null root
