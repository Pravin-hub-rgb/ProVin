**Problem:** Given an integer array, handle multiple queries asking for the sum of elements between indices `left` and `right` (inclusive). (LeetCode #303)

**Link:** https://leetcode.com/problems/range-sum-query-immutable/

---

## Which Technique, and Why?

Multiple range-sum queries on a static array → **Prefix Sum**. Precompute the prefix array once in the constructor; each query is O(1). Without prefix sum, each query is O(n) → O(n × q) total for q queries.

**Signal in the problem:** "range sum query" + "immutable" (no updates) + multiple queries → prefix sum. If updates were allowed, you'd need a Fenwick tree / segment tree.

## Approach

Constructor: build `prefix` array where `prefix[i]` = sum of `nums[0..i-1]`. `sumRange(left, right)` returns `prefix[right+1] - prefix[left]`.

## Pseudocode

```
constructor(nums):
    n = nums.length
    prefix = new int[n + 1]
    for i from 0 to n-1:
        prefix[i+1] = prefix[i] + nums[i]

sumRange(left, right):
    return prefix[right+1] - prefix[left]
```

## Java Code

```java
class NumArray {
    private int[] prefix;

    public NumArray(int[] nums) {
        int n = nums.length;
        prefix = new int[n + 1];
        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + nums[i];
        }
    }

    public int sumRange(int left, int right) {
        return prefix[right + 1] - prefix[left];
    }
}
```

## Line-by-line

- `prefix` has size `n + 1`. `prefix[0] = 0` (sum of zero elements).
- `prefix[i+1] = prefix[i] + nums[i]` — cumulative sum.
- `sumRange(left, right)` = `prefix[right+1] - prefix[left]` — sum of elements from `left` to `right` inclusive.

## Complexity

- Constructor: O(n) time, O(n) space.
- `sumRange`: O(1) time, O(1) space.

## Common Mistakes

- **Off-by-one:** `prefix[right + 1] - prefix[left]`, not `prefix[right] - prefix[left]`. The +1 accounts for prefix being 1-indexed.
- **Empty array:** if `nums` is empty, `prefix` has size 1 (`[0]`). `sumRange` won't be called (or returns 0). Handle gracefully.
- **Modifying the array after construction** — the class assumes immutability. If the array changes, rebuild the prefix.

## How to Explain (interview)

**Opening:** Range Sum Query Immutable precomputes prefix sums so each query is O(1). Build `prefix[i]` = sum of first i elements. `sumRange(left, right)` = `prefix[right+1] - prefix[left]`. O(n) preprocessing, O(1) per query.

**The basic flow:**
```java
prefix[0] = 0;
for (int i = 0; i < n; i++) prefix[i + 1] = prefix[i] + nums[i];
// query: prefix[right + 1] - prefix[left]
```

**The part that trips everyone up:** the +1 in `prefix[right + 1]`. The prefix array is 1-indexed (prefix[0] = 0), so the sum of elements 0..right is prefix[right+1].

**The mistakes to remember:**
- Off-by-one: using `prefix[right]` instead of `prefix[right + 1]`
- Forgetting that the array must be immutable (no updates)
- Not handling empty array in constructor
