## The Core Idea

Many problems ask: "what's the sum of elements from index i to j?" The naive approach sums them each time → O(n) per query, O(n²) for n queries.

**Prefix Sum** precomputes an array `prefix` where `prefix[i]` = sum of `nums[0..i-1]` (sum of first i elements). Then the sum of `nums[i..j]` = `prefix[j+1] - prefix[i]` — O(1) per query.

**The mental model:** instead of recomputing a sum every time, store the running total and subtract two stored totals. One subtraction gives you any range sum.

**Two variants:**
1. **Range sum queries (static array):** precompute prefix array once, answer each query in O(1).
2. **Subarray sum equals K:** use a hash map of prefix sums. For each index, check if `prefix[i] - K` was seen before → subarray sum = K. O(n) time.

## How to Recognize It

Think "Prefix Sum" when:
- The problem asks for the **sum of a range** (i to j) multiple times.
- The problem asks for a **subarray with a given sum** (especially sum = 0 or sum = K).
- Keywords: "range sum," "subarray sum," "pivot index," "equilibrium point."
- The array is static (no updates) — if updates are needed, use a Fenwick tree / segment tree (advanced, not in Tier 1).

**Signal words:** "sum of elements between i and j," "contiguous subarray sum equals K," "find pivot/equilibrium index."

**Prefix Sum vs Sliding Window:** Sliding window works when all elements are positive (monotonic sum). Prefix sum works with negatives too, and is better for repeated range queries.

## Worked Example: Subarray Sum Equals K

**Problem (Tier 2):** Count subarrays whose sum equals K.

### Naive (O(n²))

Check all subarrays, compute sum, count matches.

### Optimized (O(n)) — prefix sum + hash map

```java
class Solution {
    public int subarraySum(int[] nums, int k) {
        Map<Integer, Integer> prefixCount = new HashMap<>();
        prefixCount.put(0, 1);   // empty prefix has sum 0
        int prefix = 0, count = 0;

        for (int x : nums) {
            prefix += x;
            // if prefix - k was seen, there's a subarray summing to k
            count += prefixCount.getOrDefault(prefix - k, 0);
            prefixCount.put(prefix, prefixCount.getOrDefault(prefix, 0) + 1);
        }
        return count;
    }
}
```

**Line-by-line:**
- `prefix` accumulates the running sum up to current index.
- If `prefix - k` exists in the map, it means some earlier prefix had sum `prefix - k`, so the subarray between that point and here sums to `k`.
- Store `prefix` in the map for future lookups.
- Initialize with `{0: 1}` to handle subarrays starting from index 0.

**Key insight:** `sum(i..j) = prefix[j+1] - prefix[i]`. If that equals K, then `prefix[i] = prefix[j+1] - K`. So we just check if `prefix - K` was seen.

## Common Mistakes

- **Off-by-one in prefix indices.** `prefix[i]` = sum of first i elements (indices 0..i-1). Range sum `nums[i..j]` = `prefix[j+1] - prefix[i]`. Get this wrong and everything breaks.
- **Forgetting the empty prefix.** Initialize `prefixCount.put(0, 1)` to handle subarrays starting at index 0.
- **Using prefix sum with updates.** Prefix sum is for static arrays. If the array is updated frequently, use a Fenwick tree / segment tree (advanced).
- **Confusing with sliding window.** Sliding window needs positive numbers (monotonic). Prefix sum works with negatives.

## How to Explain (interview)

**Opening:** Prefix Sum precomputes cumulative sums so any range sum is answered in O(1). Build `prefix[i]` = sum of first i elements. Then `sum(i..j) = prefix[j+1] - prefix[i]`. For "subarray sum equals K," use a hash map of prefix sums: at each index, check if `prefix - K` was seen. O(n) time, O(n) space.

**The basic flow (range query):**
```java
int[] prefix = new int[n + 1];
for (int i = 0; i < n; i++) prefix[i + 1] = prefix[i] + nums[i];
// sum(i..j) = prefix[j+1] - prefix[i]
```

**The part that trips everyone up:** the off-by-one in indexing. `prefix[i]` is the sum of the first *i* elements (indices 0 to i-1). Range sum `nums[i..j]` = `prefix[j+1] - prefix[i]`. Also, initialize the map with `{0: 1}` for subarrays starting at index 0.

**The mistakes to remember:**
- Off-by-one in prefix indices
- Forgetting the empty prefix (sum 0 at index -1)
- Applying to arrays with updates (use Fenwick tree instead)
- Confusing with sliding window (prefix sum works with negatives)
