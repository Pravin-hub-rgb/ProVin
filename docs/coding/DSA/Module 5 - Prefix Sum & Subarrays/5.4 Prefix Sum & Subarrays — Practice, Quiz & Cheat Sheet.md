## Mini Quiz

1. What is the formula for the sum of elements from index i to j using a prefix array?
2. Why is `prefix` size `n + 1` instead of `n`?
3. In Find Pivot Index, why do you compute `rightSum` before updating `leftSum`?
4. What is the time complexity of building the prefix array and of each query?
5. When does prefix sum NOT work well?

<details>
<summary>Show Answer</summary>

**Sample Answers:**
1. `prefix[j + 1] - prefix[i]` — sum of elements from index i to j (inclusive). `prefix[k]` = sum of first k elements (indices 0 to k-1).
2. `prefix[0] = 0` represents the sum of zero elements (empty prefix). This handles queries starting at index 0: `sumRange(0, j) = prefix[j+1] - prefix[0] = prefix[j+1]`. Without the +1, you'd need a special case for i = 0.
3. `rightSum = total - leftSum - nums[i]`. `leftSum` is the sum of elements *before* index i. If you update `leftSum += nums[i]` first, you'd include the current element in the left sum, making `rightSum` wrong. Compute rightSum first, then update leftSum.
4. Building: O(n) time, O(n) space. Each query: O(1) time, O(1) space.
5. When the array is frequently updated (prefix sum is for static arrays). For dynamic arrays, use a Fenwick tree or segment tree (advanced). Also, prefix sum works with negative numbers (unlike sliding window).

</details>

## One-Page Cheat Sheet

**Core pattern:** precompute cumulative sums so any range sum is O(1). `prefix[i]` = sum of first i elements. Range sum `nums[i..j]` = `prefix[j+1] - prefix[i]`.

**Subarray sum equals K (with hash map):**
```java
Map<Integer, Integer> prefixCount = new HashMap<>();
prefixCount.put(0, 1);
int prefix = 0, count = 0;
for (int x : nums) {
    prefix += x;
    count += prefixCount.getOrDefault(prefix - k, 0);
    prefixCount.put(prefix, prefixCount.getOrDefault(prefix, 0) + 1);
}
```

**Pivot index:**
```java
int total = sum(nums), leftSum = 0;
for (int i = 0; i < nums.length; i++) {
    if (leftSum == total - leftSum - nums[i]) return i;
    leftSum += nums[i];
}
return -1;
```

**Complexities:** O(n) preprocessing, O(1) per query. O(n) space for prefix array.

**When to use Prefix Sum:** range sum queries on static arrays, subarray sum equals K (with hash map), equilibrium/pivot index, problems where you need to compare sums of two parts.

## In Your Own Words

1. Why is the prefix array size `n + 1` instead of `n`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `prefix[0] = 0` represents the sum of zero elements (empty prefix). This handles range queries starting at index 0 without a special case: `sumRange(0, j) = prefix[j+1] - prefix[0] = prefix[j+1]`. Without the +1, you'd need an if-statement for `left == 0`. The extra slot is a sentinel that simplifies the formula.

</details>

2. How does the hash map approach find subarrays summing to K?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `sum(i..j) = prefix[j+1] - prefix[i]`. If this equals K, then `prefix[i] = prefix[j+1] - K`. So at each index j, compute `prefix - K` and check if it was seen before (stored in the map). If yes, there's a subarray from that earlier index to j summing to K. Initialize the map with `{0: 1}` to handle subarrays starting at index 0.

</details>

3. When should you use prefix sum instead of sliding window?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Use prefix sum when elements can be negative (sliding window needs positive numbers for monotonicity) or when you need to answer many range-sum queries on a static array (O(1) per query after O(n) preprocessing). Use sliding window when you need the longest/shortest contiguous subarray satisfying a condition with positive numbers (O(n) time, O(1) space, no preprocessing).

</details>
