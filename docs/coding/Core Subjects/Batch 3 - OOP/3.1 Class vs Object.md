Class aur Object — dono blueprint hain but alag tareeke se. `interface` sirf shape define karta hai (kya properties hongi, unka type kya hai). `class` shape ke saath **implementation** bhi deta hai (methods, constructor, logic).

Database mein bhi yahi hai — **table schema** (structure) aur **actual data** (rows). Schema define karta hai ki columns kya honge, data mein actual values hoti hain.

---

# Class vs Object

## Class — Blueprint

**Class** = ek blueprint/template — define karta hai ki object mein kya properties aur methods honge.

```typescript
// Class = blueprint (jaise database schema)
class Product {
  name: string;
  price: number;

  constructor(name: string, price: number) {
    this.name = name;
    this.price = price;
  }

  getDiscountedPrice(discount: number): number {
    return this.price - (this.price * discount / 100);
  }
}
```

TypeScript `interface` se comparison:
```typescript
// Interface = sirf shape (no implementation)
interface ProductShape {
  name: string;
  price: number;
}

// Class = shape + implementation
class Product implements ProductShape {
  name: string;
  price: number;

  constructor(name: string, price: number) {
    this.name = name;
    this.price = price;
  }

  getDiscountedPrice(discount: number): number {
    return this.price - (this.price * discount / 100);
  }
}
```

**Fark:** Interface sirf define karta hai ki "kya hona chahiye." Class define karta hai ki "kya hona chahiye" aur "kaise kaam karega."

## Object — Actual Instance

**Object** = class ka ek actual instance — real memory mein exist karta hai.

```typescript
// Object = actual data (jaise database row)
const rice = new Product("Basmati Rice", 120);
const oil = new Product("Mustard Oil", 250);

console.log(rice.name); // "Basmati Rice"
console.log(oil.getDiscountedPrice(10)); // 225
```

```typescript
// Class = blueprint
// Object = actual variable (instance)

interface Product { name: string; price: number; }
const product: Product = { name: "Rice", price: 120 }; // actual object
```

**Database analogy:**
```
Class = Table schema (products table structure)
Object = Actual row (product_id=1, name="Rice", price=120)
```

Ek class se multiple objects ban sakte hain — jaise ek table mein bahut saare rows ho sakte hain.

## Constructor — Object Initialize Karna

**Constructor** = special method jo object banate waqt automatically call hota hai.

```typescript
class Product {
  name: string;
  price: number;

  // Constructor — object banate waqt call hota hai
  constructor(name: string, price: number) {
    this.name = name;  // this = current object
    this.price = price;
  }
}

// new keyword se object banta hai, constructor automatically call hota hai
const rice = new Product("Basmati Rice", 120);
// Constructor called: this.name = "Basmati Rice", this.price = 120
```

TypeScript shorthand:
```typescript
// Shorthand — constructor parameter directly property ban jaata hai
class Product {
  constructor(
    public name: string,
    public price: number
  ) {}
}
// Equivalent to manual constructor
```

## Methods — Object Ka Kaam

**Methods** = class ke andar functions — object apne data pe kaam karta hai.

```typescript
class Product {
  constructor(
    public name: string,
    public price: number
  ) {}

  // Method — object ka kaam
  getDiscountedPrice(discount: number): number {
    return this.price - (this.price * discount / 100);
  }

  isExpensive(): boolean {
    return this.price > 500;
  }
}

const rice = new Product("Basmati Rice", 120);
console.log(rice.getDiscountedPrice(10)); // 108
console.log(rice.isExpensive()); // false
```

**Database analogy:** Methods = stored procedures/functions. Data + logic ek jagah hai.

## static — Class Level Pe

**Static** properties/methods class pe hote hain, object pe nahi. Har object ke liye same value.

```typescript
class Product {
  static totalCount = 0; // Class-level property

  constructor(public name: string, public price: number) {
    Product.totalCount++; // Har new object pe count badhega
  }

  static getTotalCount(): number {
    return Product.totalCount;
  }
}

const rice = new Product("Rice", 120);
const oil = new Product("Oil", 250);

console.log(Product.getTotalCount()); // 2 — class level pe
// rice.totalCount nahi hota — sirf Product.totalCount hota hai
```

## this Keyword — Current Object

`this` = current object ka reference. Method ke andar `this` se current object ke properties access karte ho.

```typescript
class Product {
  constructor(public name: string, public price: number) {}

  toString(): string {
    return `${this.name}: ₹${this.price}`; // this = current product
  }
}

const rice = new Product("Rice", 120);
console.log(rice.toString()); // "Rice: ₹120"
```

**Gotcha:** Arrow functions mein `this` nahi badalta — regular functions mein hota hai.

```typescript
class Timer {
  count = 0;

  // ❌ Arrow function — this Timer ko refer karega (correct)
  start = () => {
    setInterval(() => {
      this.count++; // this = Timer object
    }, 1000);
  };

  // ❌ Regular function — this window/undefined ho sakta hai
  startWrong() {
    setInterval(function() {
      this.count++; // this = window (browser) ya undefined (Node)
    }, 1000);
  }
}
```

## DukaanOS Context

```typescript
class Product {
  constructor(
    public id: string,
    public name: string,
    public price: number,
    private stock: number // private — directly access nahi kar sakte
  ) {}

  isAvailable(): boolean {
    return this.stock > 0;
  }

  reduceStock(quantity: number): void {
    if (quantity > this.stock) {
      throw new Error("Insufficient stock");
    }
    this.stock -= quantity;
  }

  getStock(): number {
    return this.stock;
  }
}

// Objects
const rice = new Product("1", "Basmati Rice", 120, 50);
const oil = new Product("2", "Mustard Oil", 250, 30);

console.log(rice.isAvailable()); // true
rice.reduceStock(5);
console.log(rice.getStock()); // 45
// rice.stock = -100; // Error! stock private hai
```

## What It Is NOT

⚠️ **Class = interface nahi.** Interface sirf shape define karta hai (no implementation). Class shape + implementation dono deta hai.

⚠️ **Object = variable nahi.** Object class ka instance hai — methods bhi hain, properties bhi. Sirf data nahi, behavior bhi hai.

⚠️ **Class = always necessary nahi.** Simple data ke liye `interface` ya `type` kaafi hai. Class tab use karo jab **behavior** bhi chahiye (methods, encapsulation).

## In Your Own Words

1. TypeScript `interface` aur `class` mein kya fark hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Interface sirf shape define karta hai — ki object mein kya properties hongi, unka type kya hai. Class shape + implementation dono deta hai — properties, methods, constructor. Interface = "kya hona chahiye." Class = "kya hona chahiye" aur "kaise kaam karega."

</details>

2. Constructor kya hai? Kab call hota hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Constructor special method hai jo `new` keyword se object banate waqt automatically call hota hai. Object initialize karta hai — properties ko values deta hai. Jaise `new Product("Rice", 120)` — constructor call hota hai aur `this.name = "Rice"`, `this.price = 120` hota hai.

</details>

3. `static` keyword kya karta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `static` property/method class pe hoti hai, object pe nahi. Har object ke liye same value hoti hai. Jaise `Product.totalCount` — har new product banane pe count badhta hai, but ye count sirf class level pe hai, har product ke paas alag count nahi hai.

</details>

4. Class tab use karo jab... (2 situations batao)

<details>
<summary>Sample Jawab</summary>

**Jawab:** (1) Jab **behavior** chahiye — data ke saath methods bhi chahiye (Product class mein `getDiscountedPrice()` method). (2) Jab **encapsulation** chahiye — private properties jo directly access nahi ho sakti (Product mein `private stock`). Simple data ke liye interface kaafi hai.

</details>
