Class and Object — both are blueprints but work differently. `interface` only defines shape (what properties will exist, what their types are). `class` provides **implementation** along with shape (methods, constructor, logic).

Same in databases — **table schema** (structure) and **actual data** (rows). Schema defines what columns will exist, data contains the actual values.

# Class vs Object

## Class — Blueprint

**Class** = a blueprint/template — defines what properties and methods an object will have.

```typescript
// Class = blueprint (like a database schema)
class Product {
  name: string;
  price: number;

  constructor(name: string, price: number) {
    this.name = name;
    this.price = price;
  }

  getDiscountedPrice(discount: number): number {
    return this.price - (this.price * discount / 100);
  }
}
```

Comparison with TypeScript `interface`:
```typescript
// Interface = only shape (no implementation)
interface ProductShape {
  name: string;
  price: number;
}

// Class = shape + implementation
class Product implements ProductShape {
  name: string;
  price: number;

  constructor(name: string, price: number) {
    this.name = name;
    this.price = price;
  }

  getDiscountedPrice(discount: number): number {
    return this.price - (this.price * discount / 100);
  }
}
```

**Difference:** Interface only defines "what should exist." Class defines "what should exist" and "how it will work."

## Object — Actual Instance

**Object** = an actual instance of a class — exists in real memory.

```typescript
// Object = actual data (like a database row)
const rice = new Product("Basmati Rice", 120);
const oil = new Product("Mustard Oil", 250);

console.log(rice.name); // "Basmati Rice"
console.log(oil.getDiscountedPrice(10)); // 225
```

```typescript
// Class = blueprint
// Object = actual variable (instance)

interface Product { name: string; price: number; }
const product: Product = { name: "Rice", price: 120 }; // actual object
```

**Database analogy:**
```
Class = Table schema (products table structure)
Object = Actual row (product_id=1, name="Rice", price=120)
```

Multiple objects can be created from one class — just like one table can have many rows.

## Constructor — Initializing an Object

**Constructor** = a special method that's automatically called when an object is created.

```typescript
class Product {
  name: string;
  price: number;

  // Constructor — called automatically when object is created
  constructor(name: string, price: number) {
    this.name = name;  // this = current object
    this.price = price;
  }
}

// new keyword creates the object, constructor is called automatically
const rice = new Product("Basmati Rice", 120);
// Constructor called: this.name = "Basmati Rice", this.price = 120
```

TypeScript shorthand:
```typescript
// Shorthand — constructor parameter becomes a property directly
class Product {
  constructor(
    public name: string,
    public price: number
  ) {}
}
// Equivalent to manual constructor
```

## Methods — Object's Work

**Methods** = functions inside a class — the object operates on its own data.

```typescript
class Product {
  constructor(
    public name: string,
    public price: number
  ) {}

  // Method — object's work
  getDiscountedPrice(discount: number): number {
    return this.price - (this.price * discount / 100);
  }

  isExpensive(): boolean {
    return this.price > 500;
  }
}

const rice = new Product("Basmati Rice", 120);
console.log(rice.getDiscountedPrice(10)); // 108
console.log(rice.isExpensive()); // false
```

**Database analogy:** Methods = stored procedures/functions. Data + logic in one place.

## static — Class Level

**Static** properties/methods belong to the class, not the object. Same value for every object.

```typescript
class Product {
  static totalCount = 0; // Class-level property

  constructor(public name: string, public price: number) {
    Product.totalCount++; // Count increases with every new object
  }

  static getTotalCount(): number {
    return Product.totalCount;
  }
}

const rice = new Product("Rice", 120);
const oil = new Product("Oil", 250);

console.log(Product.getTotalCount()); // 2 — at class level
// rice.totalCount doesn't exist — only Product.totalCount does
```

## this Keyword — Current Object

`this` = reference to the current object. Inside a method, `this` accesses the current object's properties.

```typescript
class Product {
  constructor(public name: string, public price: number) {}

  toString(): string {
    return `${this.name}: ₹${this.price}`; // this = current product
  }
}

const rice = new Product("Rice", 120);
console.log(rice.toString()); // "Rice: ₹120"
```

**Gotcha:** In arrow functions, `this` doesn't change — in regular functions, it can.

```typescript
class Timer {
  count = 0;

  // ✅ Arrow function — this refers to Timer (correct)
  start = () => {
    setInterval(() => {
      this.count++; // this = Timer object
    }, 1000);
  };

  // ❌ Regular function — this can be window/undefined
  startWrong() {
    setInterval(function() {
      this.count++; // this = window (browser) or undefined (Node)
    }, 1000);
  }
}
```

```typescript
class Product {
  constructor(
    public id: string,
    public name: string,
    public price: number,
    private stock: number // private — can't be accessed directly
  ) {}

  isAvailable(): boolean {
    return this.stock > 0;
  }

  reduceStock(quantity: number): void {

    }

  }

  }
}

rice.reduceStock(5);
```

## What It Is NOT

⚠️ **Class ≠ interface.** Interface only defines shape (no implementation). Class provides both shape + implementation.

⚠️ **Object ≠ variable.** Object is an instance of a class — has methods and properties. Not just data, but behavior too.

⚠️ **Class ≠ always necessary.** For simple data, `interface` or `type` is enough. Use a class when you need **behavior** (methods, encapsulation).

## In Your Own Words

1. What's the difference between TypeScript `interface` and `class`?

<details>
<summary>Sample Answer</summary>

**Answer:** Interface only defines shape — what properties an object will have and their types. Class provides both shape + implementation — properties, methods, constructor. Interface = "what should exist." Class = "what should exist" and "how it will work."

</details>

2. What is a constructor? When is it called?

<details>
<summary>Sample Answer</summary>

**Answer:** Constructor is a special method that's automatically called when an object is created with the `new` keyword. It initializes the object — gives values to properties. Like `new Product("Rice", 120)` — constructor is called and `this.name = "Rice"`, `this.price = 120`.

</details>

3. What does the `static` keyword do?

<details>
<summary>Sample Answer</summary>

**Answer:** `static` property/method belongs to the class, not the object. Same value for every object. Like `Product.totalCount` — count increases with every new product, but the count exists only at class level, not per product.

</details>

4. When should you use a class? (Give 2 situations)

<details>
<summary>Sample Answer</summary>

**Answer:** (1) When you need **behavior** — data with methods (Product class with `getDiscountedPrice()` method). (2) When you need **encapsulation** — private properties that can't be accessed directly (Product with `private stock`). For simple data, an interface is enough.

</details>
