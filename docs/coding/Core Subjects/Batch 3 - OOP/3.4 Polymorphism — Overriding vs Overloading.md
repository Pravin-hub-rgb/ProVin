Same method name, different types — different behavior. This is **Polymorphism**. "Poly" = many, "morph" = forms. The same method can behave differently in different classes.

# Polymorphism

## What is Polymorphism

**Polymorphism** = the same method/function can **behave differently** in different classes.

```typescript
// Same method name, different types — polymorphism
const strings: string[] = ["a", "b", "c"];
const numbers: number[] = [1, 2, 3];

strings.map(s => s.toUpperCase()); // for strings
numbers.map(n => n * 2); // for numbers
// Same .map() method, different behavior
```

---

## 2 Types of Polymorphism

### 1. Method Overriding (Runtime Polymorphism)

The child class **redefines** the parent's method in its own way. Which method gets called is decided at runtime.

```typescript
class Shape {
  area(): number {
    return 0;
  }

  describe(): string {
    return `Area: ${this.area()}`;
  }
}

class Circle extends Shape {
  constructor(public radius: number) {
    super();
  }

  override area(): number {
    return Math.PI * this.radius * this.radius;
  }
}

class Rectangle extends Shape {
  constructor(public width: number, public height: number) {
    super();
  }

  override area(): number {
    return this.width * this.height;
  }
}

// Polymorphism — same method call, different behavior
const shapes: Shape[] = [new Circle(5), new Rectangle(4, 6)];

shapes.forEach(shape => {
  console.log(shape.describe());
  // Circle: "Area: 78.54"
  // Rectangle: "Area: 24"
  // Same describe() call, different area() behavior
});
```

**Decided at runtime:** `shape.describe()` is called → `describe()` calls `this.area()` internally → if `this` is actually a Circle, Circle's `area()`; if Rectangle, Rectangle's `area()`. This is called **late binding** or **dynamic dispatch**.

### 2. Method Overloading (Compile-Time Polymorphism)

Same method name, **different parameters**. Which version to call is decided at compile time.

```typescript
// TypeScript method overloading
function calculateTotal(price: number): number;
function calculateTotal(price: number, tax: number): number;
function calculateTotal(price: number, discount: number, tax: number): number;
function calculateTotal(price: number, tax?: number, discount?: number): number {
  let total = price;
  if (discount) total -= discount;
  if (tax) total += tax;
  return total;
}

// Different parameters — different behavior
calculateTotal(100); // 100
calculateTotal(100, 18); // 118 (with tax)
calculateTotal(100, 18, 10); // 108 (with tax and discount)
```

**TypeScript overloading syntax:** Write type signatures, then a single implementation. Unlike C++/Java (where multiple implementations exist).

## Polymorphism — Why It Matters

```typescript
// ❌ Without polymorphism — separate function for each type
function getAreaCircle(circle: Circle): number {
  return Math.PI * circle.radius * circle.radius;
}

function getAreaRect(rect: Rectangle): number {
  return rect.width * rect.height;
}

// Need a new function for every new shape
```

```typescript
// ✅ With polymorphism — one function, works for every shape
function getArea(shape: Shape): number {
  return shape.area(); // Polymorphism — decided at runtime
}

const circle = new Circle(5);
const rect = new Rectangle(4, 6);

console.log(getArea(circle)); // 78.54
console.log(getArea(rect)); // 24
// Same function, different behavior
```

**Benefit:** Add a new shape (Triangle) — the `getArea()` function doesn't need to change. Open/Closed Principle is followed.

## Abstract Class — Foundation of Polymorphism

Abstract class = incomplete class — some methods are only declared, not defined. Must be completed in the child class.

```typescript
abstract class PaymentMethod {
  abstract processPayment(amount: number): void; // declaration only
  abstract refund(amount: number): void; // declaration only

  logTransaction(amount: number): void {
    console.log(`Transaction of ₹${amount} logged`);
  }
}

class UPIPayment extends PaymentMethod {
  processPayment(amount: number): void {
    console.log(`Processing ₹${amount} via UPI`);
    this.logTransaction(amount);
  }

  refund(amount: number): void {
    console.log(`Refunding ₹${amount} via UPI`);
  }
}

class CashPayment extends PaymentMethod {
  processPayment(amount: number): void {
    console.log(`Processing ₹${amount} in Cash`);
    this.logTransaction(amount);
  }

  refund(amount: number): void {
    console.log(`Refunding ₹${amount} in Cash`);
  }
}

// Polymorphism — same method, different payment methods
const payments: PaymentMethod[] = [new UPIPayment(), new CashPayment()];
payments.forEach(p => p.processPayment(500));
// UPIPayment: "Processing ₹500 via UPI"
// CashPayment: "Processing ₹500 in Cash"
```

## Polymorphism via Interface

```typescript
interface Payable {
  pay(amount: number): void;
}

interface Refundable {
  refund(amount: number): void;
}

class OnlineOrder implements Payable, Refundable {
  pay(amount: number): void {
    console.log(`Paid ₹${amount}`);
  }

  refund(amount: number): void {
    console.log(`Refunded ₹${amount}`);
  }
}

class CashOrder implements Payable {
  pay(amount: number): void {
    console.log(`Paid ₹${amount} in cash`);
  }

  refund(amount: number): void {
    console.log("No refund for cash orders");
  }
}

// Polymorphism — via interface type
const orders: Payable[] = [new OnlineOrder(), new CashOrder()];
orders.forEach(o => o.pay(100)); // Same method, different behavior
```

## DukaanOS Context

```typescript
abstract class DiscountStrategy {
  abstract calculateDiscount(price: number): number;

  applyDiscount(price: number): number {
    const discount = this.calculateDiscount(price);
    return price - discount;
  }
}

class PercentageDiscount extends DiscountStrategy {
  constructor(private percentage: number) {
    super();
  }

  calculateDiscount(price: number): number {
    return price * (this.percentage / 100);
  }
}

class FlatDiscount extends DiscountStrategy {
  constructor(private amount: number) {
    super();
  }

  calculateDiscount(price: number): number {
    return Math.min(this.amount, price); // discount can't exceed price
  }
}

// Polymorphism — same method, different discount strategies
const discounts: DiscountStrategy[] = [
  new PercentageDiscount(10), // 10% off
  new FlatDiscount(50), // ₹50 off
];

const originalPrice = 200;
discounts.forEach(d => {
  console.log(`Discounted price: ₹${d.applyDiscount(originalPrice)}`);
});
// PercentageDiscount: "Discounted price: ₹180"
// FlatDiscount: "Discounted price: ₹150"
```

## What It Is NOT

⚠️ **Polymorphism ≠ only method overriding.** Overriding (runtime) and overloading (compile-time) are both polymorphism.

⚠️ **Polymorphism ≠ complex.** Simple concept — same method, different behavior. You already use `.map()` — that's polymorphism.

⚠️ **Polymorphism ≠ inheritance required.** Interface-based polymorphism exists too — `Payable` interface implemented by different classes.

## In Your Own Words

1. What's the difference between Method Overriding and Method Overloading?

<details>
<summary>Sample Answer</summary>

**Answer:** Overriding = child class redefines the parent's method (same parameters, different implementation). Decided at runtime. Overloading = same method name, different parameters (decided at compile time). In TypeScript, overloading is done by declaring signatures and writing a single implementation.

</details>

2. How does polymorphism follow the Open/Closed Principle?

<details>
<summary>Sample Answer</summary>

**Answer:** With polymorphism, you can add new shapes/payment methods without changing old code. The `getArea()` function accepts a Shape — Circle, Rectangle, Triangle all work. Add a new shape, the function doesn't change. Open for extension, closed for modification.

</details>

3. Why can't you instantiate an abstract class?

<details>
<summary>Sample Answer</summary>

**Answer:** An abstract class is incomplete — some methods are only declared, not defined. If you instantiate it, incomplete methods could be called — runtime error. So first complete it in a child class, then instantiate the child class.

</details>

4. Where can polymorphism be used in your DukaanOS?

<details>
<summary>Sample Answer</summary>

**Answer:** Discount strategies — PercentageDiscount, FlatDiscount, BuyOneGetOne — can all extend the DiscountStrategy abstract class. Payment methods — UPI, Cash, Card — can all implement the PaymentMethod interface. Same method call, different behavior — polymorphism.

</details>
