Same method name, different types ke saath alag kaam — ye **Polymorphism** hai. "Poly" = many, "morph" = forms. Same method different classes mein different tarike se behave kar sakta hai.

# Polymorphism

## Polymorphism Kya Hai

**Polymorphism** = same method/function different classes mein **different tarike se behave** kar sakta hai.

```typescript
// Same method name, different types — polymorphism
const strings: string[] = ["a", "b", "c"];
const numbers: number[] = [1, 2, 3];

strings.map(s => s.toUpperCase()); // String ke liye
numbers.map(n => n * 2); // Number ke liye
// Same .map() method, different behavior
```

---

## 2 Types of Polymorphism

### 1. Method Overriding (Runtime Polymorphism)

Child class parent ke method ko apne tarike se **redefine** karti hai. Run time pe decide hota hai kaunsa method call hoga.

```typescript
class Shape {
  area(): number {
    return 0;
  }

  describe(): string {
    return `Area: ${this.area()}`;
  }
}

class Circle extends Shape {
  constructor(public radius: number) {
    super();
  }

  override area(): number {
    return Math.PI * this.radius * this.radius;
  }
}

class Rectangle extends Shape {
  constructor(public width: number, public height: number) {
    super();
  }

  override area(): number {
    return this.width * this.height;
  }
}

// Polymorphism — same method call, different behavior
const shapes: Shape[] = [new Circle(5), new Rectangle(4, 6)];

shapes.forEach(shape => {
  console.log(shape.describe());
  // Circle: "Area: 78.54"
  // Rectangle: "Area: 24"
  // Same describe() call, different area() behavior
});
```

**Runtime pe decide hota hai:** `shape.describe()` call hota hai → `describe()` andar `this.area()` call karta hai → `this` ka actual type Circle hai toh Circle ka `area()`, Rectangle hai toh Rectangle ka `area()`. Ye **late binding** ya **dynamic dispatch** kehte hain.

### 2. Method Overloading (Compile-Time Polymorphism)

Same method naam, **different parameters**. Compile time pe decide hota hai kaunsa version call hoga.

```typescript
// TypeScript method overloading
function calculateTotal(price: number): number;
function calculateTotal(price: number, tax: number): number;
function calculateTotal(price: number, discount: number, tax: number): number;
function calculateTotal(price: number, tax?: number, discount?: number): number {
  let total = price;
  if (discount) total -= discount;
  if (tax) total += tax;
  return total;
}

// Different parameters — different behavior
calculateTotal(100); // 100
calculateTotal(100, 18); // 118 (with tax)
calculateTotal(100, 18, 10); // 108 (with tax and discount)
```

**TypeScript overloading syntax:** Type signatures likho, ek hi implementation likho. C++/Java jaisa nahi hai (jahan multiple implementations hoti hain).

## Polymorphism — Why It Matters

```typescript
// ❌ Without polymorphism — har type ke liye alag function
function getArea(circle: Circle): number {
  return Math.PI * circle.radius * circle.radius;
}

function getAreaRect(rect: Rectangle): number {
  return rect.width * rect.height;
}

// Har naye shape ke liye naya function likho
```

```typescript
// ✅ With polymorphism — ek hi function, har shape kaam karega
function getArea(shape: Shape): number {
  return shape.area(); // Polymorphism — runtime pe decide
}

const circle = new Circle(5);
const rect = new Rectangle(4, 6);

console.log(getArea(circle)); // 78.54
console.log(getArea(rect)); // 24
// Same function, different behavior
```

**Benefit:** Naya shape add karo (Triangle) — `getArea()` function change nahi karna padega. Open/Closed Principle follow hota hai.

## Abstract Class — Polymorphism Ka Foundation

Abstract class = incomplete class — kuch methods sirf declared hain, defined nahi. Child class mein complete karna padta hai.

```typescript
abstract class PaymentMethod {
  abstract processPayment(amount: number): void; // sirf declaration
  abstract refund(amount: number): void; // sirf declaration

  logTransaction(amount: number): void {
    console.log(`Transaction of ₹${amount} logged`);
  }
}

class UPIPayment extends PaymentMethod {
  processPayment(amount: number): void {
    console.log(`Processing ₹${amount} via UPI`);
    this.logTransaction(amount);
  }

  refund(amount: number): void {
    console.log(`Refunding ₹${amount} via UPI`);
  }
}

class CashPayment extends PaymentMethod {
  processPayment(amount: number): void {
    console.log(`Processing ₹${amount} in Cash`);
    this.logTransaction(amount);
  }

  refund(amount: number): void {
    console.log(`Refunding ₹${amount} in Cash`);
  }
}

// Polymorphism — same method, different payment methods
const payments: PaymentMethod[] = [new UPIPayment(), new CashPayment()];
payments.forEach(p => p.processPayment(500));
// UPIPayment: "Processing ₹500 via UPI"
// CashPayment: "Processing ₹500 in Cash"
```

## Interface Se Polymorphism

```typescript
interface Payable {
  pay(amount: number): void;
}

interface Refundable {
  refund(amount: number): void;
}

class OnlineOrder implements Payable, Refundable {
  pay(amount: number): void {
    console.log(`Paid ₹${amount}`);
  }

  refund(amount: number): void {
    console.log(`Refunded ₹${amount}`);
  }
}

class CashOrder implements Payable {
  pay(amount: number): void {
    console.log(`Paid ₹${amount} in cash`);
  }

  refund(amount: number): void {
    console.log("No refund for cash orders");
  }
}

// Polymorphism — interface type se
const orders: Payable[] = [new OnlineOrder(), new CashOrder()];
orders.forEach(o => o.pay(100)); // Same method, different behavior
```

## DukaanOS Context

```typescript
abstract class DiscountStrategy {
  abstract calculateDiscount(price: number): number;

  applyDiscount(price: number): number {
    const discount = this.calculateDiscount(price);
    return price - discount;
  }
}

class PercentageDiscount extends DiscountStrategy {
  constructor(private percentage: number) {
    super();
  }

  calculateDiscount(price: number): number {
    return price * (this.percentage / 100);
  }
}

class FlatDiscount extends DiscountStrategy {
  constructor(private amount: number) {
    super();
  }

  calculateDiscount(price: number): number {
    return Math.min(this.amount, price); // Discount price se zyada nahi
  }
}

// Polymorphism — same method, different discount strategies
const discounts: DiscountStrategy[] = [
  new PercentageDiscount(10), // 10% off
  new FlatDiscount(50), // ₹50 off
];

const originalPrice = 200;
discounts.forEach(d => {
  console.log(`Discounted price: ₹${d.applyDiscount(originalPrice)}`);
});
// PercentageDiscount: "Discounted price: ₹180"
// FlatDiscount: "Discounted price: ₹150"
```

## What It Is NOT

⚠️ **Polymorphism = sirf method overriding nahi.** Overriding (runtime) aur overloading (compile-time) dono polymorphism hain.

⚠️ **Polymorphism = complex nahi hai.** Simple concept hai — same method, different behavior. Tum already `.map()` use kar rahe ho — ye polymorphism hai.

⚠️ **Polymorphism = always inheritance zaroori nahi.** Interface se bhi polymorphism hota hai — `Payable` interface implement karke.

## In Your Own Words

1. Method Overriding aur Method Overloading mein kya fark hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Overriding = child class parent ka method redefine karti hai (same parameters, different implementation). Run time pe decide hota hai. Overloading = same method naam, different parameters (compile time pe decide). TypeScript mein overloading signatures declare karke ek implementation likhte hain.

</details>

2. Polymorphism se Open/Closed Principle kaise follow hota hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Polymorphism mein tum naye shapes/payment methods add kar sakte ho bina purane code change kiye. `getArea()` function Shape accept karta hai — Circle, Rectangle, Triangle sab kaam karega. Naya shape add karo, function change nahi karna. Open for extension, closed for modification.

</details>

3. Abstract class ka object kyun nahi ban sakta?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Abstract class incomplete hai — kuch methods sirf declared hain, defined nahi. Agar object banaya toh incomplete methods call ho sakte hain — runtime error. Isliye pehle child class mein complete karo, phir child class ka object banao.

</details>

4. Tumhara DukaanOS mein polymorphism kahan use ho sakta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Discount strategies — PercentageDiscount, FlatDiscount, BuyOneGetOne — sab DiscountStrategy abstract class extend kar sakte hain. Payment methods — UPI, Cash, Card — sab PaymentMethod interface implement kar sakte hain. Same method call, different behavior — polymorphism.

</details>
