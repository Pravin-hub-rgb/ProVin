`private`, `public`, `protected` — these are OOP's **access modifiers** — they decide where a property/method can be accessed from. You've probably used these — written `private quantity: number` at some point.

This is part of **encapsulation** — protecting data so it can't be modified incorrectly from outside.

---

# Encapsulation + Access Modifiers

## What is Encapsulation

**Encapsulation** = bundling data (properties) and the methods that operate on it into one unit (class), and preventing internal details from being accessed directly from outside.

```typescript
// ❌ Without encapsulation — everything public
interface Product {
  name: string;
  price: number;
  stock: number; // anyone can set it to -999
}

// ✅ With encapsulation — stock protected
class Product {
  constructor(
    public name: string,
    public price: number,
    private stock: number // only accessible inside the class
  ) {}
}
```

Database analogy: a `private` column = only a stored procedure can access it. Not a direct SQL query.

## 3 Access Modifiers

### public (default)

Accessible from anywhere. If no modifier is specified, it's `public`.

```typescript
class Product {
  public name: string; // public — accessible from anywhere
  price: number;       // also public (default)

  constructor(name: string, price: number) {
    this.name = name;
    this.price = price;
  }
}

const rice = new Product("Rice", 120);
console.log(rice.name); // ✅ accessible
console.log(rice.price); // ✅ accessible
rice.name = "Oil"; // ✅ can change
```

### private

Accessible **only inside the same class**. Can't be accessed directly from outside.

```typescript
class Product {
  public name: string;
  private stock: number; // private — only inside the class

  constructor(name: string, stock: number) {
    this.name = name;
    this.stock = stock;
  }

  // Access through methods
  reduceStock(amount: number): void {
    if (amount > this.stock) {
      throw new Error("Insufficient stock");
    }
    this.stock -= amount; // ✅ accessible inside the class
  }

  getStock(): number {
    return this.stock; // ✅ accessible inside the class
  }
}

const rice = new Product("Rice", 50);
// rice.stock = -100; // ❌ Error! private
rice.reduceStock(10); // ✅ access through method
console.log(rice.getStock()); // ✅ access through method
```

**DukaanOS angle:** If `stock` were public, any code could write `rice.stock = -999` — bypassing validation. Accessing via `private` + method is encapsulation.

### protected

Accessible in the same class **and its child classes**.

```typescript
class Vehicle {
  constructor(protected speed: number) {} // protected

  protected accelerate(): void {
    this.speed += 10; // ✅ accessible inside the class
  }
}

class Car extends Vehicle {
  honk(): void {
    this.speed += 5; // ✅ accessible in child class
    this.accelerate(); // ✅ accessible in child class
    console.log(`Speed: ${this.speed}`);
  }
}

const car = new Car(50);
car.honk(); // ✅
// console.log(car.speed); // ❌ Error! protected
// car.accelerate(); // ❌ Error! protected
```

**Difference:**
- `private` = only in the same class
- `protected` = same class + child classes

## Private vs Protected — Real Example

```typescript
class BankAccount {
  private balance: number; // private — only in this class

  constructor(initialBalance: number) {
    this.balance = initialBalance;
  }

  deposit(amount: number): void {
    this.balance += amount;
  }

  getBalance(): number {
    return this.balance;
  }
}

class SavingsAccount extends BankAccount {
  // ❌ Can't access this.balance — it's private
  // ✅ Can use getBalance() — it's public
}

// If it were protected:
class BankAccountProtected {
  protected balance: number; // protected

  constructor(initialBalance: number) {
    this.balance = initialBalance;
  }
}

class SavingsAccountProtected extends BankAccountProtected {
  applyInterest(rate: number): void {
    this.balance += this.balance * rate; // ✅ protected — allowed in child class
  }
}
```

## Encapsulation — Why It Matters

**Problem without encapsulation:**
```typescript
// ❌ Everything public — chaos
class Product {
  name: string;
  price: number;
  stock: number;
}

const rice = new Product();
rice.name = "Rice";
rice.price = 120;
rice.stock = 50;

// Any code...
rice.stock = -100; // ❌ Validation bypassed!
rice.price = -50; // ❌ Negative price!
// Data becomes inconsistent
```

**Solution with encapsulation:**
```typescript
// ✅ Private data — controlled access
class Product {
  constructor(
    public name: string,
    private _price: number,
    private _stock: number
  ) {}

  get price(): number {
    return this._price;
  }

  set price(value: number) {
    if (value < 0) throw new Error("Price cannot be negative");
    this._price = value;
  }

  get stock(): number {
    return this._stock;
  }

  reduceStock(amount: number): void {
    if (amount > this._stock) throw new Error("Insufficient stock");
    this._stock -= amount;
  }
}

const rice = new Product("Rice", 120, 50);
// rice._price = -50; // ❌ Private
rice.price = 150; // ✅ Validation happens via setter
// rice.price = -50; // ❌ Error! Validation works
```

## Getter/Setter — Controlled Access

**Getter** = read like a property but a method runs underneath.
**Setter** = write like a property but validation happens.

```typescript
class Circle {
  constructor(private _radius: number) {}

  get radius(): number {
    return this._radius;
  }

  set radius(value: number) {
    if (value <= 0) throw new Error("Radius must be positive");
    this._radius = value;
  }

  get area(): number {
    return Math.PI * this._radius * this._radius; // Computed property
  }
}

const circle = new Circle(5);
console.log(circle.radius); // 5 — getter used
console.log(circle.area); // 78.54 — computed
circle.radius = 10; // setter used
// circle.radius = -1; // ❌ Error! Validation
```

## Prisma Connection — private fields

Prisma also has field-level access control (hiding sensitive fields):

```typescript
// Prisma — hiding sensitive fields
model User {
  id    String @id @default(uuid())
  name  String
  email String
  password String @map("password_hash") // hidden in API responses
}
```

The `password` field doesn't appear in API responses — encapsulation concept.

---

## What It Is NOT

⚠️ **Encapsulation ≠ hiding data.** Encapsulation means **controlled access** — data isn't hidden, it's only accessible through authorized methods.

⚠️ **Private ≠ secure.** In TypeScript, `private` is only checked at compile time. At runtime, anyone can access it (in JavaScript, `obj._property`). If you need security, validate server-side.

⚠️ **Encapsulation ≠ unnecessary complexity.** For simple data, an `interface` is enough. Use a class when you need behavior + validation.

## In Your Own Words

1. What's the difference between `private` and `protected`?

<details>
<summary>Sample Answer</summary>

**Answer:** `private` is accessible only inside the same class — even child classes can't access it. `protected` is accessible in the same class + its child classes. Example: `private balance` — only in BankAccount class. `protected balance` — in both BankAccount and its child SavingsAccount.

</details>

2. Why use getter/setter instead of a simple property?

<details>
<summary>Sample Answer</summary>

**Answer:** Getter/setter give you controlled access. Simple property = direct read/write. Getter = read like a property but validation happens. Setter = write like a property but validation happens. Like `set radius(value)` checks that the value is positive.

</details>

3. What problem can occur if the `stock` property in your Product class is public?

<details>
<summary>Sample Answer</summary>

**Answer:** Any code could write `product.stock = -100` — validation gets bypassed. Stock becomes negative, data becomes inconsistent. Fix: make `stock` private and access it through `reduceStock()` method which validates.

</details>

4. What does "controlled access" mean in encapsulation?

<details>
<summary>Sample Answer</summary>

**Answer:** Data isn't hidden — it's only accessible through authorized methods. Like `product.reduceStock(5)` decreases stock (with validation). You can't directly do `product.stock = -5`. The control is over how data is accessed and modified.

</details>
