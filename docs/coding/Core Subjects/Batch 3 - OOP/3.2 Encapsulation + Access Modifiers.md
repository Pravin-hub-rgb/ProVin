TypeScript mein tum `private`, `public`, `protected` keywords use karte ho. Ye OOP ke **access modifiers** hain — decide karte hain ki property/method kahan se access ho sakta hai. Tumne ye kabhi na kabhi use kiya hoga — `private quantity: number` likha hoga.

Ye **encapsulation** ka part hai — data ko protect karna taaki bahar se galat tarike se modify na ho.

---

# Encapsulation + Access Modifiers

## Encapsulation Kya Hai

**Encapsulation** = data (properties) aur uspe kaam karne wale methods ko ek unit (class) mein bandh dena, aur internal details ko bahar se directly access hone se rokna.

TypeScript analogy:
```typescript
// ❌ Without encapsulation — sab public hai
interface Product {
  name: string;
  price: number;
  stock: number; // koi bhi -999 kar sakta hai
}

// ✅ With encapsulation — stock protected hai
class Product {
  constructor(
    public name: string,
    public price: number,
    private stock: number // sirf class ke andar access
  ) {}
}
```

Database analogy: `private` column = sirf stored procedure access kar sakti hai. Direct SQL query se nahi.

## 3 Access Modifiers

### public (default)

Kahin se bhi access ho sakta hai. Agar koi modifier na ho toh `public` hota hai.

```typescript
class Product {
  public name: string; // public — kahin se bhi access
  price: number;       // bhi public hai (default)

  constructor(name: string, price: number) {
    this.name = name;
    this.price = price;
  }
}

const rice = new Product("Rice", 120);
console.log(rice.name); // ✅ accessible
console.log(rice.price); // ✅ accessible
rice.name = "Oil"; // ✅ change kar sakte ho
```

### private

Sirf **usi class ke andar** access ho sakta hai. Bahar se directly access nahi.

```typescript
class Product {
  public name: string;
  private stock: number; // private — sirf class ke andar

  constructor(name: string, stock: number) {
    this.name = name;
    this.stock = stock;
  }

  // Methods through access karo
  reduceStock(amount: number): void {
    if (amount > this.stock) {
      throw new Error("Insufficient stock");
    }
    this.stock -= amount; // ✅ class ke andar access allowed
  }

  getStock(): number {
    return this.stock; // ✅ class ke andar access allowed
  }
}

const rice = new Product("Rice", 50);
// rice.stock = -100; // ❌ Error! private hai
rice.reduceStock(10); // ✅ method through access
console.log(rice.getStock()); // ✅ method through access
```

**DukaanOS angle:** Agar `stock` public hota, toh koi bhi code seedha `rice.stock = -999` likh sakta tha — validation bypass karke. `private` + method se access karna encapsulation hai.

### protected

Usi class **aur uski child classes** mein access ho sakta hai.

```typescript
class Vehicle {
  constructor(protected speed: number) {} // protected

  protected accelerate(): void {
    this.speed += 10; // ✅ class ke andar allowed
  }
}

class Car extends Vehicle {
  honk(): void {
    this.speed += 5; // ✅ child class mein allowed
    this.accelerate(); // ✅ child class mein allowed
    console.log(`Speed: ${this.speed}`);
  }
}

const car = new Car(50);
car.honk(); // ✅
// console.log(car.speed); // ❌ Error! protected hai
// car.accelerate(); // ❌ Error! protected hai
```

**Difference:**
- `private` = sirf usi class mein
- `protected` = usi class + uski child classes mein

## Private vs Protected — Real Example

```typescript
class BankAccount {
  private balance: number; // private — sirf isi class mein

  constructor(initialBalance: number) {
    this.balance = initialBalance;
  }

  deposit(amount: number): void {
    this.balance += amount;
  }

  getBalance(): number {
    return this.balance;
  }
}

class SavingsAccount extends BankAccount {
  // ❌ this.balance access nahi kar sakte — private hai
  // ❌ this.deposit() bhi access nahi kar sakte — private nahi, but parent mein defined hai
  // ✅ getBalance() use kar sakte hain — public hai
}

// Agar protected hota:
class BankAccountProtected {
  protected balance: number; // protected

  constructor(initialBalance: number) {
    this.balance = initialBalance;
  }
}

class SavingsAccountProtected extends BankAccountProtected {
  applyInterest(rate: number): void {
    this.balance += this.balance * rate; // ✅ protected — child class mein allowed
  }
}
```

## Encapsulation — Why It Matters

**Problem without encapsulation:**
```typescript
// ❌ Everything public — chaos
class Product {
  name: string;
  price: number;
  stock: number;
}

const rice = new Product();
rice.name = "Rice";
rice.price = 120;
rice.stock = 50;

// Koi bhi code...
rice.stock = -100; // ❌ Validation bypassed!
rice.price = -50; // ❌ Negative price!
// Data inconsistent ho gaya
```

**Solution with encapsulation:**
```typescript
// ✅ Private data — controlled access
class Product {
  constructor(
    public name: string,
    private _price: number,
    private _stock: number
  ) {}

  get price(): number {
    return this._price;
  }

  set price(value: number) {
    if (value < 0) throw new Error("Price cannot be negative");
    this._price = value;
  }

  get stock(): number {
    return this._stock;
  }

  reduceStock(amount: number): void {
    if (amount > this._stock) throw new Error("Insufficient stock");
    this._stock -= amount;
  }
}

const rice = new Product("Rice", 120, 50);
// rice._price = -50; // ❌ Private hai
rice.price = 150; // ✅ Setter se validation hoti hai
// rice.price = -50; // ❌ Error! Validation kaam karti hai
```

## Getter/Setter — Controlled Access

**Getter** = property ki tarah read karo but andar se method chalta hai.
**Setter** = property ki tarah write karo but validation hoti hai.

```typescript
class Circle {
  constructor(private _radius: number) {}

  get radius(): number {
    return this._radius;
  }

  set radius(value: number) {
    if (value <= 0) throw new Error("Radius must be positive");
    this._radius = value;
  }

  get area(): number {
    return Math.PI * this._radius * this._radius; // Computed property
  }
}

const circle = new Circle(5);
console.log(circle.radius); // 5 — getter use hua
console.log(circle.area); // 78.54 — computed
circle.radius = 10; // setter use hua
// circle.radius = -1; // ❌ Error! Validation
```

## Prisma Connection — private fields

Prisma mein bhi `@private` directive hota hai (field-level access control):
```typescript
// Prisma — sensitive fields hide karna
model User {
  id    String @id @default(uuid())
  name  String
  email String
  password String @map("password_hash") // hide in API responses
}
```

API response mein `password` field nahi aata — encapsulation concept.

## What It Is NOT

⚠️ **Encapsulation = data hide karna nahi.** Encapsulation ka matlab hai **controlled access** — data hidden nahi hai, but sirf authorized methods se access ho sakta hai.

⚠️ **Private = secure nahi.** TypeScript mein `private` sirf compile-time pe check hota hai. Runtime pe koi bhi access kar sakta hai (JavaScript mein `obj._property`). Security chahiye toh server-side validation karo.

⚠️ **Encapsulation = unnecessary complexity nahi.** Simple data ke liye `interface` kaafi hai. Class tab use karo jab behavior + validation chahiye.

## In Your Own Words

1. `private` aur `protected` mein kya fark hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `private` sirf usi class ke andar access hota hai — child class bhi access nahi kar sakti. `protected` usi class + uski child classes mein access hota hai. Example: `private balance` — sirf BankAccount class mein. `protected balance` — BankAccount aur uske child SavingsAccount dono mein.

</details>

2. Getter/Setter kyun use karte ho? Simple property se kya fark hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Getter/Setter se tum controlled access de sakte ho. Simple property = direct read/write. Getter = property ki tarah padho but validation hoti hai. Setter = property ki tarah likho but validation hoti hai. Jaise `set radius(value)` mein check hota hai ki value positive hai.

</details>

3. Agar tumhare Product class mein `stock` property public ho toh kya problem ho sakti hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Koi bhi code `product.stock = -100` likh sakta hai — validation bypass ho jayegi. Stock negative ho jayega, data inconsistent ho jayega. Fix: `private stock` karo aur `reduceStock()` method se access karo jo validation karti hai.

</details>

4. Encapsulation "controlled access" hai — iska matlab kya hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Data hidden nahi hai — sirf authorized methods se access hota hai. Jaise `product.reduceStock(5)` se stock kam hota hai (validation ke saath). Direct `product.stock = -5` nahi kar sakte. Control hai ki data kaise access hoga, kaise modify hoga.

</details>
