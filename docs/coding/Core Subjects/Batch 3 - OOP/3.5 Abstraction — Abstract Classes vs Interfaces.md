# Abstraction

## Abstraction Kya Hai

**Abstraction** = Complex implementation details ko chhupa ke, sirf **zaroori/relevant cheezein** user ko dikhana.

```typescript
// Interface = Abstraction
interface PaymentProcessor {
  processPayment(amount: number): void;
  refund(amount: number): void;
}

// Caller ko pata hai: processPayment() aur refund() honge
// Caller ko nahi pata: andar kya ho raha hai
// Kya Stripe se connect ho raha hai? Kya UPI se? Kya bank transfer se?
// Caller ko pata nahi — ye abstraction hai
```

**Real-world analogy (code version):**
```typescript
// Tum `fetch()` use karte ho — but andar kya hota hai?
fetch('https://api.example.com');
// Tumhe pata hai: request jaayegi, response aayega
// Tumhe nahi pata: DNS resolve, TCP connection, SSL handshake...
// Ye abstraction hai — complex details chhupi hain
```

## Abstract Classes

**Abstract class** = incomplete class — kuch methods sirf **declared** hain (signature hai), **defined** nahi (implementation nahi). Child class mein complete karna padta hai.

```typescript
abstract class PaymentMethod {
  // Abstract methods — sirf declaration, no implementation
  abstract processPayment(amount: number): void;
  abstract refund(amount: number): void;

  // Concrete method — implementation hai
  logTransaction(amount: number): void {
    console.log(`Transaction of ₹${amount} logged at ${new Date()}`);
  }
}

// ❌ Abstract class ka direct object nahi ban sakta
// const p = new PaymentMethod(); // Error!

// ✅ Child class banao, implement karo, phir object banao
class UPIPayment extends PaymentMethod {
  processPayment(amount: number): void {
    console.log(`Processing ₹${amount} via UPI`);
    this.logTransaction(amount); // Parent ka method
  }

  refund(amount: number): void {
    console.log(`Refunding ₹${amount} via UPI`);
  }
}

const upi = new UPIPayment();
upi.processPayment(500); // ✅
```

**Interview question:** "Abstract class ka object kyun nahi ban sakta?"

**Answer:** "Kyunki wo incomplete hai — kuch methods sirf declared hain, defined nahi. Agar object banaya toh incomplete methods call ho sakte hain — runtime error. Isliye pehle child class mein complete karo, phir child ka object banao."

## Interface vs Abstract Class

Ye sabse common comparison question hai interview mein.

| | Interface | Abstract Class |
|---|---|---|
| Implementation | Sirf contract, koi implementation nahi | Kuch methods implement ho sakte hain |
| Multiple inheritance | Ek class multiple interfaces implement kar sakti hai | Ek class sirf ek abstract class extend kar sakti hai |
| Properties | Sirf type define karta hai | Properties with values bhi ho sakti hain |
| Constructor | Nahi hota | Hota hai |
| Access modifiers | Sirf public | Public, private, protected — sab |
| Kab use karo | Jab sirf "ye methods honi chahiye" ka contract chahiye | Jab common logic bhi share karna ho |

### Interface Example
```typescript
// Interface — sirf contract
interface Payable {
  pay(amount: number): void;
}

interface Refundable {
  refund(amount: number): void;
}

// Multiple interfaces — allowed
class OnlineOrder implements Payable, Refundable {
  pay(amount: number): void {
    console.log(`Paid ₹${amount}`);
  }
  refund(amount: number): void {
    console.log(`Refunded ₹${amount}`);
  }
}
```

### Abstract Class Example
```typescript
// Abstract class — common logic + contract
abstract class PaymentMethod {
  // Common logic — har payment method mein same
  logTransaction(amount: number): void {
    console.log(`₹${amount} transaction logged`);
  }

  // Contract — child implement karega
  abstract processPayment(amount: number): void;
  abstract refund(amount: number): void;
}

class UPIPayment extends PaymentMethod {
  processPayment(amount: number): void {
    console.log(`UPI: ₹${amount}`);
    this.logTransaction(amount); // Common logic reuse
  }
  refund(amount: number): void {
    console.log(`UPI refund: ₹${amount}`);
  }
}

// ❌ Multiple abstract classes — not allowed
// class X extends PaymentMethod, AnotherAbstract { }
```

**Simple rule:** Interface tab use karo jab sirf "ye methods honi chahiye" ka contract chahiye, implementation ki freedom child pe chhodni ho. Abstract class tab jab kuch common logic bhi share karna ho child classes ke beech.

## Abstraction — Practical Example

```typescript
// Abstract class — database operations ka abstraction
abstract class DatabaseRepository<T> {
  abstract findById(id: string): Promise<T | null>;
  abstract findAll(): Promise<T[]>;
  abstract create(data: T): Promise<T>;
  abstract update(id: string, data: Partial<T>): Promise<T>;
  abstract delete(id: string): Promise<void>;

  // Common logic — validation
  validate(data: any): boolean {
    return data !== null && data !== undefined;
  }
}

// Concrete implementation — Product repository
class ProductRepository extends DatabaseRepository<Product> {
  async findById(id: string): Promise<Product | null> {
    return prisma.product.findUnique({ where: { id } });
  }

  async findAll(): Promise<Product[]> {
    return prisma.product.findMany();
  }

  async create(data: Product): Promise<Product> {
    return prisma.product.create({ data });
  }

  async update(id: string, data: Partial<Product>): Promise<Product> {
    return prisma.product.update({ where: { id }, data });
  }

  async delete(id: string): Promise<void> {
    await prisma.product.delete({ where: { id } });
  }
}

// Caller ko pata hai: findById, findAll, create, update, delete honge
// Caller ko nahi pata: Prisma use ho raha hai, kaise query ho rahi hai
// Abstraction — implementation hidden, interface visible
```

## What It Is NOT

⚠️ **Abstraction = data hiding nahi.** Data hiding = encapsulation (private/protected). Abstraction = complexity hiding — user ko sirf relevant cheezein dikhana.

⚠️ **Abstract class = interface nahi.** Abstract class mein common logic bhi ho sakti hai, constructor ho sakta hai, access modifiers ho sakte hain. Interface sirf contract hai.

⚠️ **Abstraction = unnecessary nahi.** Jab code complex ho aur multiple implementations hon (UPI, Cash, Card), tab abstraction se clean hota hai.

## In Your Own Words

1. Abstract class ka object kyun nahi ban sakta?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Abstract class incomplete hai — kuch methods sirf declared hain, defined nahi. Agar object banaya toh incomplete methods call ho sakte hain — runtime error. Isliye pehle child class mein complete karo (implement abstract methods), phir child class ka object banao.

</details>

2. Interface aur abstract class mein 3 main differences batao.

<details>
<summary>Sample Jawab</summary>

**Jawab:** (1) Interface sirf contract hai, abstract class mein common logic bhi ho sakti hai. (2) Multiple interfaces implement kar sakte ho, sirf ek abstract class extend kar sakte ho. (3) Interface ka constructor nahi hota, abstract class ka hota hai. (4) Interface mein sirf public methods, abstract class mein public/private/protected sab.

</details>

3. Tumhara DukaanOS mein abstraction kahan useful hoga?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Payment methods — UPI, Cash, Card — sab PaymentMethod abstract class extend kar sakte hain. Same `processPayment()` call, different behavior. Discount strategies — PercentageDiscount, FlatDiscount — sab DiscountStrategy extend kar sakte hain. Naya payment method add karo, purana code change nahi karna.

</details>

4. "Interface tab use karo jab implementation ki freedom child pe chhodni ho" — iska matlab kya hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Interface sirf method signatures define karta hai — `pay(amount: number): void`. Har implementer (UPI, Cash, Card) apne tareeke se implement karega. Interface koi restriction nahi lagata ki "kaise karo" — sirf "kya karo" batata hai. Abstract class mein common logic hota hai jo sab follow karenge.

</details>
