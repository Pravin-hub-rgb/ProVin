One class can give its properties and methods to another class — without rewriting them. Via `extends`, the child class takes the parent's properties/methods. This is **inheritance** — one type takes another type's properties/methods.

Same in databases — **parent table** and **child table**. The child table inherits the parent's properties (via foreign key).

---

# Inheritance

## What is Inheritance

**Inheritance** = a class (child) can **reuse** the properties and methods of another class (parent), without rewriting them.

```typescript
// Parent class
class Vehicle {
  constructor(public brand: string, public speed: number) {}

  displayInfo(): string {
    return `${this.brand} is running at ${this.speed} km/h`;
  }
}

// Child class — inherits from Vehicle
class Car extends Vehicle {
  constructor(brand: string, speed: number, public doors: number) {
    super(brand, speed); // Calling parent constructor is mandatory
  }

  honk(): string {
    return "Pom Pom!";
  }
}

const myCar = new Car("Honda", 120, 4);
console.log(myCar.displayInfo()); // inherited method from Vehicle
console.log(myCar.honk()); // Car's own method
```

**Database analogy:**
```
Vehicle (parent)          Car (child)
─────────────            ──────────────
brand: string     ───►   brand: string (inherited)
speed: number     ───►   speed: number (inherited)
displayInfo()     ───►   displayInfo() (inherited)
                         doors: number (child's own)
                         honk() (child's own)
```

## extends — The Inheritance Keyword

`extends` makes the child class inherit from the parent:

```typescript
class Parent {
  constructor(public name: string) {}

  greet(): string {
    return `Hello, ${this.name}`;
  }
}

class Child extends Parent {
  constructor(name: string, public age: number) {
    super(name); // Call parent's constructor — must be first line
  }

  introduce(): string {
    return `${this.greet()}! I'm ${this.age} years old.`;
    // greet() is inherited from parent
  }
}

const child = new Child("Vin", 25);
console.log(child.introduce()); // "Hello, Vin! I'm 25 years old."
```

## super() — Calling Parent Constructor

`super()` = calling the parent class's constructor. **`super()` must be the first line in the child class's constructor.**

```typescript
class Vehicle {
  constructor(public brand: string) {
    console.log(`Vehicle created: ${brand}`);
  }
}

class Car extends Vehicle {
  constructor(brand: string, public doors: number) {
    super(brand); // ✅ Parent constructor called first
    // Now this.brand is available
    console.log(`Car created with ${doors} doors`);
  }
}

// Without super():
class BadCar extends Vehicle {
  constructor(brand: string) {
    // ❌ Error! Must call super() first
    // console.log(this.brand); // Error! this not initialized yet
  }
}
```

**TypeScript rule:** `super()` must be the **first statement** in the constructor. After that, `this` can be accessed.

## Method Overriding — Child's Own Version

The child class can **redefine** the parent's method in its own way — this is **method overriding**.

```typescript
class Shape {
  area(): number {
    return 0; // Default — 0 area
  }

  describe(): string {
    return `Shape with area ${this.area()}`;
  }
}

class Circle extends Shape {
  constructor(public radius: number) {
    super();
  }

  // Method overriding — overriding parent's method
  override area(): number {
    return Math.PI * this.radius * this.radius;
  }
}

class Rectangle extends Shape {
  constructor(public width: number, public height: number) {
    super();
  }

  override area(): number {
    return this.width * this.height;
  }
}

const shapes: Shape[] = [new Circle(5), new Rectangle(4, 6)];
shapes.forEach(shape => console.log(shape.area()));
// Circle: 78.54, Rectangle: 24
// Same method call, different behavior
```

**`override` keyword:** In TypeScript, using `override` is best practice — it shows that this method overrides the parent's method. If the method doesn't exist in the parent, an error occurs.

## Types of Inheritance

### Single Inheritance
```
Animal → Dog
One parent, one child
```

### Multilevel Inheritance
```
Animal → Mammal → Dog
Chain: A → B → C
```

### Hierarchical Inheritance
```
Vehicle → Car
Vehicle → Truck
Vehicle → Bike
One parent, multiple children
```

### Multiple Inheritance — Not in TypeScript

```typescript
// ❌ Multiple inheritance doesn't exist in TypeScript/JavaScript
class Flyable { fly() {} }
class Swimmable { swim() {} }

// class Duck extends Flyable, Swimmable { } // ❌ Error!
```

**Solution: Use interfaces:**
```typescript
interface Flyable {
  fly(): void;
}

interface Swimmable {
  swim(): void;
}

class Duck implements Flyable, Swimmable {
  fly() { console.log("Flying"); }
  swim() { console.log("Swimming"); }
}
```

**Database analogy:** Single inheritance = one parent table. Multiple inheritance = many-to-many relationship (junction table).

## Interview — Types of Inheritance

Interviewer asks: "What types of inheritance are there?"

**Answer:**
- **Single:** One parent, one child (Vehicle → Car)
- **Multilevel:** Chain form (Animal → Mammal → Dog)
- **Hierarchical:** One parent, multiple children (Vehicle → Car, Truck, Bike)
- **Multiple:** One class from two parents (doesn't exist in TypeScript — use interfaces)

## DukaanOS Context

```typescript
// Base class
class InventoryItem {
  constructor(
    public id: string,
    public name: string,
    protected quantity: number
  ) {}

  isAvailable(): boolean {
    return this.quantity > 0;
  }

  reduceStock(amount: number): void {
    if (amount > this.quantity) throw new Error("Insufficient stock");
    this.quantity -= amount;
  }
}

// Child class — specific item type
class PerishableItem extends InventoryItem {
  constructor(
    id: string,
    name: string,
    quantity: number,
    public expiryDate: Date
  ) {
    super(id, name, quantity);
  }

  isExpired(): boolean {
    return new Date() > this.expiryDate;
  }

  // Override — perishable item has different behavior
  override isAvailable(): boolean {
    return this.quantity > 0 && !this.isExpired();
  }
}

const milk = new PerishableItem("1", "Milk", 10, new Date("2024-01-15"));
console.log(milk.isAvailable()); // false — expired
milk.reduceStock(5); // ✅ inherited method
console.log(milk.isExpired()); // ✅ child's own method
```

## What It Is NOT

⚠️ **Inheritance ≠ copy-paste.** Inheritance **reuses** code — write once, inherit elsewhere. Copy-paste creates duplication.

⚠️ **Inheritance ≠ always right.** Composition (embedding objects) is sometimes better than inheritance. "Has-a" relationship → composition, "is-a" relationship → inheritance.

⚠️ **Multiple inheritance ≠ in TypeScript.** It exists in C++, not in TypeScript. Solution: use Interfaces.

## In Your Own Words

1. What does `extends` do? Why is `super()` necessary?

<details>
<summary>Sample Answer</summary>

**Answer:** `extends` makes the child class inherit from the parent — it reuses the parent's properties/methods. `super()` calls the parent's constructor — it must be the first line in the child's constructor, so the parent gets initialized and `this` becomes available.

</details>

2. What is method overriding? Why use the `override` keyword in TypeScript?

<details>
<summary>Sample Answer</summary>

**Answer:** Method overriding = the child class redefines the parent's method in its own way. Like Circle overriding `area()` to calculate its own area. The `override` keyword makes TypeScript check that the method exists in the parent — if not, an error occurs.

</details>

3. Why doesn't multiple inheritance exist in TypeScript? What's the solution?

<details>
<summary>Sample Answer</summary>

**Answer:** Multiple inheritance means one class extending two parents — this causes the diamond problem (which method to use?). TypeScript/JavaScript doesn't support it. Solution: use Interfaces — `class Duck implements Flyable, Swimmable`. Interfaces only define the contract; implementation is provided by the child class.

</details>

4. What's the difference between `extends` and `implements`?

<details>
<summary>Sample Answer</summary>

**Answer:** `extends` = inheritance — takes parent's properties + methods + implementation. `implements` = contract — only method signatures are defined, implementation provided by child class. `extends` has `super()`, `implements` doesn't.

</details>
