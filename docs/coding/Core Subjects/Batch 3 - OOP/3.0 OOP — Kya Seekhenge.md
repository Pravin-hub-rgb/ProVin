You've written `class`, `extends`, `private`, `public` in your code. When you write `class Product { private price: number }`, you're doing **encapsulation**. When you write `class Car extends Vehicle`, you're doing **inheritance**.

OOP isn't just "create a class, create an object" — these are design principles that make your code maintainable. In interviews, when asked "explain OOP," state the 4 pillars and give a code example for each — that's stronger than "I memorized it."

## What You'll Learn in This Batch

Six concepts, each connected to your TypeScript code:

**A — Class vs Object.** Blueprint vs actual instance. TypeScript `interface` vs `class` — both are blueprints but work differently.

**B — Encapsulation.** Protecting data — `private`, `public`, `protected`. Your `private quantity: number` is encapsulation.

**C — Inheritance.** Code reuse — child class takes parent's properties/methods via `extends`. Your `Car extends Vehicle`.

**D — Polymorphism.** Same method, different behavior — `override area()`. Method overriding vs overloading.

**E — Abstraction.** Hiding complex details — abstract classes and interfaces. Just the contract "these methods must exist."

**F — SOLID Principles.** 5 design principles that make code maintainable. Remember names + one-liners.
