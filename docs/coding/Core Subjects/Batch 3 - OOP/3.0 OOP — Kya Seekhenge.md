Tumne `class`, `extends`, `private`, `public` likha hai apne code mein. Jab tum `class Product { private price: number }` likhte ho toh tum **encapsulation** kar rahe ho. Jab tum `class Car extends Vehicle` likhte ho toh tum **inheritance** kar rahe ho.

OOP sirf "class banao, object banao" nahi hai — ye design principles hain jo tumhare code ko maintainable banate hain. Interview mein jab poochte hain "OOP explain karo," toh 4 pillars bolke ek-ek ka code example do — ye "ratta laga hai" se zyada strong lagta hai.

---

## Kya Seekhenge Is Batch Mein

Che concepts hain, har ek tumhare TypeScript code se connected:

**A — Class vs Object.** Blueprint vs actual instance. TypeScript `interface` vs `class` — dono blueprint hain but alag tareeke se.

**B — Encapsulation.** Data ko protect karna — `private`, `public`, `protected`. Tumhara `private quantity: number` — ye encapsulation hai.

**C — Inheritance.** Code reuse — `extends` se child class parent ki properties/methods leti hai. Tumhara `Car extends Vehicle`.

**D — Polymorphism.** Same method, different behavior — `override area()`. Method overriding vs overloading.

**E — Abstraction.** Complex details chhupana — abstract classes aur interfaces. Sirf "ye methods honi chahiye" ka contract.

**F — SOLID Principles.** 5 design principles jo code ko maintainable banate hain. Naam + one-liner yaad rakho.
