TypeScript mein `EventEmitter` aur `Observable` soche ho? `EventEmitter` — tum event listen karte ho, aur jab event aata hai toh callback chalta hai. `Observable` — stream se data aata rehta hai, tum subscribe karte ho.

REST API mein problem ye hai — client ko **har baar khud request** bhejni padti hai naya data lene ke liye (polling). Jaise tum har 5 second mein `fetch()` karo "koi naya order aaya?" ke liye. Ye inefficient hai.

**WebSocket** iska solution hai — ek baar connection ban jaye, toh server khud data push karta hai bina client ke request ke.

# WebSockets — Real-Time Connection

## REST API Ki Limitation

Socho tumhara trading bot hai — stock prices real-time change hoti hain. Agar REST API use karo:

```typescript
// ❌ REST Polling — inefficient
setInterval(async () => {
  const response = await fetch('/api/prices');
  const prices = await response.json();
  updateUI(prices);
}, 1000); // Har second mein request
```

**Problems:**
1. Har second ek HTTP request — bandwidth waste
2. HTTP headers baar-baar bhejne padte hain — overhead
3. Server pe unnecessary load
4. Latency — request bheji, response aaya, tab tak price change ho chuki

## WebSocket — Better Solution

```typescript
// ✅ WebSocket — efficient, real-time
const ws = new WebSocket('wss://api.upstox.com/feed');

ws.onopen = () => {
  console.log('Connected');
  // Server ko subscribe karo
  ws.send(JSON.stringify({ action: 'subscribe', symbol: 'RELIANCE' }));
};

ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  // Server khud data push karta hai — bina request ke
  updatePrice(data);
};

ws.onclose = () => {
  console.log('Disconnected');
};
```

**Benefits:**
1. **Ek baar connection** — baar-baar request nahi
2. **Server push** — server khud data bhejta hai
3. **Low latency** — real-time updates
4. **Less overhead** — HTTP headers nahi

---

## WebSocket vs REST — Comparison

| | REST API | WebSocket |
|---|---|---|
| Connection | Har request pe naya connection | Ek persistent connection |
| Direction | Client → Server (request) | Bidirectional (client + server) |
| Data flow | Client maangta hai | Server push karta hai |
| Latency | Thoda zyada (request-response cycle) | Kam (persistent connection) |
| Use case | CRUD operations | Real-time data, chat, gaming |

---

## WebSocket Connection Lifecycle

```
1. Client: WebSocket connection maangta hai
2. Server: Connection accept karta hai (upgrade HTTP → WebSocket)
3. Client: Server ko bolta hai "ye data chahiye" (subscribe)
4. Server: Jab naya data aata hai, client ko push karta hai
5. Connection tab tak rehta hai jab tak client close na kare
```

**TypeScript analogy:**
```typescript
// REST = har baar function call
const data = await fetch('/api/data'); // Ek baar call

// WebSocket = EventEmitter — subscribe karo, data aata rahega
ws.on('price-update', (data) => { // Continuously aata rahega });
```

## Tumhara Trading Bot — Real Example

Tumhara options trading bot Upstox WebSocket use karta hai:

```typescript
// Tumhara trading bot
const ws = new WebSocket('wss://api.upstox.com/v2/feed');

ws.onopen = () => {
  // Subscribe to stock prices
  ws.send(JSON.stringify({
    action: 'subscribe',
    instrumentTokens: ['RELIANCE', 'TCS', 'INFY']
  }));
};

ws.onmessage = (event) => {
  const tick = JSON.parse(event.data);
  // Real-time price mil rahi hai — bina request ke
  if (tick.lastPrice > targetPrice) {
    executeTrade(tick);
  }
};
```

**Interview mein bol sakte ho:** "Maine ek options trading bot banaya hai jo Upstox WebSocket se real-time tick data receive karta hai — REST polling ke bajaye WebSocket isliye use kiya kyunki humein sub-second latency chahiye price updates ke liye. Har second poll karna inefficient hota, WebSocket se server directly price push karta hai jaise hi change hoti hai."

## WebSocket Use Cases

**Real-time trading data** — stock prices, crypto prices (tumhara trading bot)
**Chat applications** — WhatsApp, Slack — messages real-time aate hain
**Live dashboards** — analytics, monitoring — data continuously update hota hai
**Multiplayer gaming** — player positions real-time sync hoti hain
**Collaborative editing** — Google Docs — multiple users ek saath edit karte hain

---

## WebSocket kaise kaam karta hai — Under the Hood

1. **HTTP Upgrade:** Client pehle HTTP request bhejta hai, server ko bolta hai "WebSocket connection chahiye"
2. **Handshake:** Server accept karta hai, connection upgrade hota hai HTTP → WebSocket
3. **Persistent Connection:** Ab TCP connection open rehta hai — dono taraf se data bhej sakte ho
4. **Frames:** Data **frames** mein bhejta hai (packets jaisa but application level pe)

```
Client: HTTP GET /feed (Upgrade: websocket)
Server: HTTP 101 Switching Protocols
Ab: TCP connection open, bidirectional data flow
```

---

## What It Is NOT

⚠️ **WebSocket = replacement nahi hai REST ka.** REST CRUD operations ke liye better hai. WebSocket sirf real-time, continuous data ke liye hai.

⚠️ **WebSocket = always on nahi.** Connection band ho sakta hai — server crash, network issue. Reconnection logic likhna padta hai.

⚠️ **WebSocket = sirf chat ke liye nahi.** Trading data, live dashboards, gaming, collaborative editing — bahut use cases hain.
