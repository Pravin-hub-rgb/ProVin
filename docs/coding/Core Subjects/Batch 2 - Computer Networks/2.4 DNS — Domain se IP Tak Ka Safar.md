TypeScript mein `import` statements socho — tum `import { Product } from './types'` likhte ho aur bundler (Webpack/Vite) usko resolve karta hai — actual file path mein convert karta hai. `./types` → `/src/types/index.ts`. tum sirf naam jaante ho, asli address bundler dhundhta hai.

Networks mein bhi yahi hota hai — tum `google.com` type karte ho, but computer ko actually `142.250.190.46` (IP address) chahiye. Ye conversion **DNS** karta hai.

# DNS — Domain se IP Tak Ka Safar

## DNS Kya Hai

**DNS** = Domain Name System. Ye **phonebook of the internet** hai — domain name (jaise `google.com`) ko IP address (jaise `142.250.190.46`) mein convert karta hai.

TypeScript analogy:
```typescript
// DNS = TypeScript module resolution
import { Product } from './types';
// Bundler resolves: './types' → '/src/types/index.ts'

// DNS resolves:
// 'google.com' → '142.250.190.46'
```

Computer domain names nahi samajhta — IP addresses samajhta hai. DNS tumhari madad karta hai ki tum `google.com` type karo aur computer `142.250.190.46` pe connect kare.

---

## DNS Flow — Jab Tum URL Type Karte Ho

```
Step 1: Browser cache check karo — pehle se IP pata hai kya?
Step 2: Nahi? OS cache check karo
Step 3: Nahi? DNS Resolver (ISP ka) query karo
Step 4: Resolver Root DNS Server se poochta hai
Step 5: Root server bataata hai konsa TLD server hai (.in, .com ke liye)
Step 6: TLD server bataata hai konsa Authoritative DNS server hai
Step 7: Authoritative server IP address deta hai
Step 8: Browser us IP pe connect karta hai
```

**TypeScript analogy:** Ye module resolution jaisa hai — bundler pehle node_modules dhundhta hai, phir relative paths, phir aliases. DNS bhi multiple levels pe check karta hai.

---

## DNS Records — Types

Interview poochte hain: "DNS records kya hain?"

### A Record — Domain → IP Address

```dns
trishulinsurance.in.    A    76.76.21.21
```

Domain ko directly ek IP address se point karta hai.

### CNAME Record — Domain → Domain

```dns
www.trishulinsurance.in.    CNAME    trishulinsurance.in.
```

Domain ko dusre domain se point karta hai. Vercel deployment mein generally CNAME use hota hai.

### MX Record — Email ke liye

```dns
trishulinsurance.in.    MX    mail.trishulinsurance.in.
```

Email kahan jaayega — ye define karta hai.

### TXT Record — Text information

```dns
trishulinsurance.in.    TXT    "v=spf1 include:_spf.google.com ~all"
```

SPF records, domain verification — ye sab TXT records hain.

## Tumhara Real Example — Trishul Insurance

Tumne Hostinger se domain khareeda (`trishulinsurance.in`) aur Vercel pe deploy kiya. DNS setup kaise hua?

```
Hostinger: Domain manage karta hai (nameservers)
Vercel: Deployment host karta hai (IP address)

DNS Record:
trishulinsurance.in.    CNAME    cname.vercel-dns.com.
```

**Kya hua:**
1. Tumne Hostinger mein Vercel ke nameservers set kiye
2. Vercel ne automatically DNS record create kiya (CNAME)
3. Jab koi `trishulinsurance.in` type karta hai → DNS resolve hota hai → Vercel ke server pe jaata hai
4. Vercel tumhara Next.js app serve karta hai

**Interview mein bol sakte ho:** "Maine recently ek client project (Trishul Insurance) mein Hostinger domain ko Vercel deployment se DNS records ke through connect kiya hai — CNAME record set kiya."

## DNS Caching — Multiple Levels

DNS har level pe cache karta hai:

```
Browser cache → OS cache → Router cache → ISP cache → DNS Server
```

**Cache TTL** (Time To Live) hota hai — kitni der tak cache rakho. Agar 300 seconds hai toh 5 minutes baad DNS wapas resolve hoga.

**TypeScript analogy:** LRU Cache jaisa — cache mein data hota hai, TTL expiry ke baad hota hai.

---

## DNS vs Direct IP

Kyun domain name use karte ho? Direct IP address kyun nahi?

```typescript
// ❌ Direct IP — mushkil hai
fetch('http://142.250.190.46') // Kaunsa server hai? Pata nahi

// ✅ Domain name — easy hai
fetch('https://api.google.com') // Pata hai kya hai
```

**Benefits:**
- Domain name yaad rakhna easy hai (`google.com` vs `142.250.190.46`)
- IP address change ho sakta hai, domain name nahi
- Multiple servers ke liye same domain use kar sakte ho (load balancing)

---

## What It Is NOT

⚠️ **DNS = sirf domain → IP conversion nahi.** DNS MX records, TXT records, CNAME records bhi handle karta hai — email, verification, etc.

⚠️ **DNS = instant nahi.** DNS resolution mein time lagta hai (milliseconds). Isliye caching hota hai — baar-baar resolve karna padta.

⚠️ **DNS = sirf websites ke liye nahi.** API calls, database connections, email — sab DNS use karte hain jab domain name hota hai.
