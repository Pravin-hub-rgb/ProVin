# DNS — Domain to IP Journey

## What is DNS

**DNS** = Domain Name System. The **phonebook of the internet** — converts a domain name (like `google.com`) into an IP address (like `142.250.190.46`).

```
DNS resolves:
'google.com' → '142.250.190.46'
```

Computers don't understand domain names — they understand IP addresses. DNS helps you so you type `google.com` and the computer connects to `142.250.190.46`.

---

## DNS Flow — When You Type a URL

```
Step 1: Check browser cache — already know the IP?
Step 2: No? Check OS cache
Step 3: No? Query the DNS Resolver (ISP's)
Step 4: Resolver asks the Root DNS Server
Step 5: Root server says which TLD server (.in, .com)
Step 6: TLD server says which Authoritative DNS server
Step 7: Authoritative server returns the IP address
Step 8: Browser connects to that IP
```

Multiple levels are checked — first cache, then resolver, then root server, then TLD, then authoritative. If a cached answer exists at any level, it comes directly.

---

## DNS Records — Types

Interview question: "What are DNS records?"

### A Record — Domain → IP Address

```dns
trishulinsurance.in.    A    76.76.21.21
```

Points a domain directly to an IP address.

### CNAME Record — Domain → Domain

```dns
www.trishulinsurance.in.    CNAME    trishulinsurance.in.
```

Points a domain to another domain. Generally CNAME is used for Vercel deployments.

### MX Record — For Email

```dns
trishulinsurance.in.    MX    mail.trishulinsurance.in.
```

Defines where email goes.

### TXT Record — Text Information

```dns
trishulinsurance.in.    TXT    "v=spf1 include:_spf.google.com ~all"
```

SPF records, domain verification — all these are TXT records.

## Your Real Example — Trishul Insurance

You bought a domain from Hostinger (`trishulinsurance.in`) and deployed on Vercel. How was DNS set up?

```
Hostinger: Manages the domain (nameservers)
Vercel: Hosts the deployment (IP address)

DNS Record:
trishulinsurance.in.    CNAME    cname.vercel-dns.com.
```

**What happened:**
1. You set Vercel's nameservers in Hostinger
2. Vercel automatically created a DNS record (CNAME)
3. When someone types `trishulinsurance.in` → DNS resolves → goes to Vercel's server
4. Vercel serves your Next.js app

**In interviews you can say:** "I recently connected a client project (Trishul Insurance) domain from Hostinger to a Vercel deployment through DNS records — set up a CNAME record."

## DNS Caching — Multiple Levels

DNS caches at every level:

```
Browser cache → OS cache → Router cache → ISP cache → DNS Server
```

**Cache TTL** (Time To Live) — how long to keep the cache. If 300 seconds, DNS re-resolves after 5 minutes.

Caching makes things fast — you don't have to resolve every time. Like a phonebook — once you remember a number, you don't look it up again, you just call directly.

---

## DNS vs Direct IP

Why use a domain name? Why not a direct IP address?

```
// ❌ Direct IP — hard
fetch('http://142.250.190.46') // Which server is this? No idea

// ✅ Domain name — easy
fetch('https://api.google.com') // You know what this is
```

**Benefits:**
- Domain names are easy to remember (`google.com` vs `142.250.190.46`)
- IP address can change, domain name doesn't
- Multiple servers can use the same domain (load balancing)

---

## What It Is NOT

⚠️ **DNS ≠ only domain → IP conversion.** DNS also handles MX records, TXT records, CNAME records — email, verification, etc.

⚠️ **DNS ≠ instant.** DNS resolution takes time (milliseconds). That's why caching exists — so you don't resolve every request.

⚠️ **DNS ≠ only for websites.** API calls, database connections, email — all use DNS when there's a domain name.
