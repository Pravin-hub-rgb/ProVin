Your DukaanOS frontend runs in the browser, the backend is deployed on Vercel, the database is on Supabase. How do all of these communicate? A request goes from the frontend, the server sends a response, data comes back as JSON. What is all of this? These are all **Computer Networks** concepts.

You write `fetch('https://api.example.com/products')` — but how does this request go out? How does it reach the server? How does the response come back? What is HTTP? What is TCP? What is DNS? Understanding all of this is essential — not just writing `fetch()`, but knowing what's happening inside.

## What You'll Learn in This Batch

Six concepts, each connected to your daily work:

**A — OSI Model.** The 7-layer architecture of the internet. You need to know how data travels from one device to another — just remember the order of the layers.

**B — TCP vs UDP.** Two ways to send data — reliable (TCP) or fast (UDP). Your WebSocket is based on TCP — because trading data needs reliability.

**C — HTTP vs HTTPS.** You send HTTP requests every day — but how does HTTPS secure them? What is the SSL/TLS handshake?

**D — DNS.** How does a domain name (like `google.com`) convert to an IP address? This was directly used in your Trishul Insurance deployment.

**E — REST API + HTTP Methods + Status Codes.** You build Next.js API routes — GET, POST, PUT, DELETE. These are REST principles.

**F — WebSockets.** REST's limitation — the client has to send a request every time to get new data. With WebSocket, the server can push data itself. Your trading bot uses WebSocket.
