# HTTP vs HTTPS

## HTTP — Plain Text

**HTTP** = HyperText Transfer Protocol. Data is transferred in **plain text** — anyone in between can intercept and read it.

```javascript
// HTTP request — data goes in plain text
fetch('http://api.example.com/login', {
  method: 'POST',
  body: JSON.stringify({
    username: 'vin',
    password: 'secret123'
    // All of this goes in plain text — anyone can read it!
  })
});
```

**Problem:** If you're on public WiFi (cafe, airport), anyone can intercept your data. Your password, credit card number — all in plain text.

## HTTPS — Encrypted

**HTTPS** = HTTP + **SSL/TLS Encryption**. Data goes in **encrypted form** — even if intercepted, it can't be read.

```javascript
// HTTPS request — data is encrypted
fetch('https://api.example.com/login', {
  method: 'POST',
  body: JSON.stringify({
    username: 'vin',
    password: 'secret123'
    // All of this is encrypted — no one can read it
  })
});
```

**HTTPS = HTTP + SSL/TLS.** That's the only difference — encryption added.

---

## SSL/TLS Handshake — How It Works

Interview question: "How does HTTPS secure things?"

**Step-by-step flow:**

```
1. Client → Server: "I want an HTTPS connection" (Client Hello)
2. Server → Client: Sends SSL Certificate (contains public key)
3. Client: Verifies the certificate (signed by a trusted authority?)
4. Both: Decide on a symmetric session key (for encrypted communication)
5. Now data is sent using the encrypted session key
```

**Key concept:** Starts with asymmetric encryption (public/private key), switches to symmetric encryption (session key) for speed.

```javascript
// Asymmetric = public key (everyone knows it, but only you have the private key)
// Symmetric = session key (both sides have the same key, fast encryption)

// Steps 1-4: Handshake (asymmetric — slow but secure)
// Step 5: Data transfer (symmetric — fast)
```

## Certificate Authority (CA)

Verifies the certificate — "did this certificate come from a trusted authority?"

```
Certificate Authority (CA) = notary public
- DigiCert, Let's Encrypt, GlobalSign
- They verify the certificate is real
- Browsers have a list of trusted CAs
```

If the certificate is invalid, the browser shows a warning: "Your connection is not private."

## HTTP vs HTTPS — Comparison

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | 443 |
| Encryption | No (plain text) | Yes (SSL/TLS) |
| Speed | A bit fast (no encryption overhead) | A bit slow (encryption takes time) |
| Security | Anyone can read | Encrypted — only you and server |
| SEO | Google penalizes | Google prefers |
| Browser | "Not Secure" warning | Padlock icon |

## Mixed Content Warning

If your page is on HTTPS but some resource loads over HTTP:

```html
<!-- ✅ SAFE — both HTTPS -->
<script src="https://cdn.example.com/script.js"></script>

<!-- ⚠️ WARNING — mixed content -->
<script src="http://cdn.example.com/script.js"></script>
<!-- Browser warning: "Mixed Content" -->
```

The browser can block HTTP resources if the page is on HTTPS.

## Interview Answer

Interviewer asks: "What's the difference between HTTP and HTTPS?"

**Answer:** "HTTP sends data in plain text — anyone can intercept and read it. HTTPS is HTTP + SSL/TLS encryption — data is encrypted. In the SSL/TLS handshake, a session key is decided using asymmetric encryption, then data is sent using symmetric encryption — fast and secure. Vercel automatically provides HTTPS with an SSL certificate."

---

## What It Is NOT

⚠️ **HTTPS ≠ only for login pages.** The entire site should be HTTPS. Google prefers it, and browsers don't show warnings.

⚠️ **HTTPS ≠ 100% secure.** Encryption protects data, but phishing attacks and server vulnerabilities are separate issues.

⚠️ **You don't have to buy an SSL certificate.** Vercel, Netlify, Cloudflare provide free SSL certificates (Let's Encrypt).
