There are two kinds of protocols in networks — **TCP** (reliable) and **UDP** (fast). When you need to send data, you have to decide: speed or reliability.

---

# TCP vs UDP

## TCP — Reliable Delivery

**TCP** = Transmission Control Protocol. Data is delivered **reliably** — guaranteed delivery, order maintained, error detection.

**How TCP works:**

1. **Connection is established first** (3-way handshake)
2. Data is broken into **packets**
3. Each packet gets an **acknowledgement** (server says "received")
4. If no acknowledgement, the packet is **resent**
5. Data stays **in order**

```
Client: "I want to connect" (SYN)
Server: "Okay, I'm ready" (SYN-ACK)
Client: "Confirmed, connection established" (ACK)

Now send data — reliable delivery
```

## UDP — Fast but Risky

**UDP** = User Datagram Protocol. Data is sent **fast** — but not guaranteed. Packets can be lost, order can get mixed up.

**How UDP works:**

1. **No connection** — send data directly
2. **No acknowledgement** — server doesn't say "received"
3. **Packet loss possible** — not resent
4. **Order can get mixed up** — a later packet can arrive earlier

---

## Comparison

| | TCP | UDP |
|---|---|---|
| Connection | Connection-oriented (handshake) | Connectionless (send directly) |
| Reliability | Guaranteed delivery, order maintained | No guarantee — packet loss possible |
| Speed | A bit slow (reliability overhead) | Fast |
| Error handling | Error detection + retransmission | Basic error detection, no retransmission |
| Use case | Web browsing, file transfer, email | Video streaming, gaming, live feeds |

---

## 3-Way Handshake — How a TCP Connection Forms

Interview question: "How does a TCP connection form?"

```
Step 1: Client → Server: SYN ("I want to connect")
Step 2: Server → Client: SYN-ACK ("Okay, I'm ready")
Step 3: Client → Server: ACK ("Confirmed, connection established")
```

3 steps — hence **3-way handshake**. After the connection is established, data is sent reliably.

---

## When to Use Which

**Use TCP when:**
- Data must be correct — file transfer, email, web pages
- Order matters — database queries, API calls
- HTTP/HTTPS is TCP-based

**Use UDP when:**
- Speed matters — live video, gaming
- Some data loss is acceptable — next packet will arrive
- Real-time streaming — VoIP calls, live broadcasts

## Interview Answer

Interviewer asks: "Is WebSocket TCP or UDP?"

**Answer:** "TCP-based. WebSocket is a persistent, reliable connection between client and server. Trading data needs reliability — price data must not be missed. TCP guarantees delivery and maintains order. UDP can lose packets — not suitable for trading."

---

## What It Is NOT

⚠️ **TCP ≠ always better.** TCP is slow because of reliability. For video streaming, UDP is better — slight pixelation is okay, but delay is not.

⚠️ **UDP ≠ unreliable.** UDP gives "no guarantee," but practically most packets arrive. It's just not guaranteed.

⚠️ **HTTP = TCP.** HTTP/HTTPS are TCP-based protocols. WebSocket is also TCP. UDP is only for specific use cases (gaming, streaming).
