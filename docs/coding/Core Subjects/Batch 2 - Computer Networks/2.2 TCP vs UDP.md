Networks mein do tarah ke protocols hain — **TCP** (reliable) aur **UDP** (fast). Data bhejna hai toh decide karna padega: speed chahiye ya reliability.

---

# TCP vs UDP

## TCP — Reliable Delivery

**TCP** = Transmission Control Protocol. Data **reliably** deliver hota hai — guaranteed delivery, order maintained, error detection.

**TCP kaise kaam karta hai:**

1. **Connection establish** hota hai pehle (3-way handshake)
2. Data **packets** mein banta hai
3. Har packet ka **acknowledgement** aata hai (server bolta hai "mil gaya")
4. Agar acknowledgement nahi aaya toh packet **wapas bhejta** hai
5. Data **order mein** rehta hai

```
Client: "Connect karna hai" (SYN)
Server: "Theek hai, main ready hoon" (SYN-ACK)
Client: "Confirm, connection ban gaya" (ACK)

Ab data bhejo — reliable delivery
```

## UDP — Fast but Risky

**UDP** = User Datagram Protocol. Data **fast** bhejta hai — but guaranteed nahi. Packet loss ho sakta hai, order bigad sakta hai.

**UDP kaise kaam karta hai:**

1. **Connection nahi** hota — seedha data bhej do
2. **Acknowledgement nahi** aata — server nahi bolta "mil gaya"
3. **Packet loss ho sakta hai** — wapas nahi bhejta
4. **Order bigad sakta hai** — pehle packet baad mein aa sakta hai

---

## Comparison

| | TCP | UDP |
|---|---|---|
| Connection | Connection-oriented (handshake) | Connectionless (seedha bhej do) |
| Reliability | Guaranteed delivery, order maintained | No guarantee — packet loss ho sakta hai |
| Speed | Thoda slow (reliability ke overhead) | Fast |
| Error handling | Error detection + retransmission | Basic error detection, no retransmission |
| Use case | Web browsing, file transfer, email | Video streaming, gaming, live feeds |

---

## 3-Way Handshake — TCP Connection Kaise Banta Hai

Interview mein poochte hain: "TCP connection kaise banta hai?"

```
Step 1: Client → Server: SYN ("connect karna hai")
Step 2: Server → Client: SYN-ACK ("theek hai, main ready hoon")
Step 3: Client → Server: ACK ("confirm, connection ban gaya")
```

3 steps lage — isliye **3-way handshake** kehte hain. Connection establish hone ke baad data reliable tarike se bhejta hai.

---

## Kab Kaunsa Use Karo

**TCP use karo jab:**
- Data sahi chahiye — file transfer, email, web pages
- Order important hai — database queries, API calls
- HTTP/HTTPS TCP pe based hai

**UDP use karo jab:**
- Speed important hai — live video, gaming
- Thoda data loss chalega — next packet aa jayega
- Real-time streaming — VoIP calls, live broadcasts

---

## Tumhare Code Se Connection

**HTTP request — TCP based:**
```javascript
// HTTP/HTTPS TCP pe based hai
const response = await fetch('https://api.example.com/products');
// Reliable — data sahi aayega ya error aayega
```

**WebSocket — TCP based:**
```javascript
// WebSocket bhi TCP pe based hai
const ws = new WebSocket('wss://api.upstox.com/feed');
// Reliable — trading data missed nahi hona chahiye
```

**Video call — UDP based:**
```
// Video streaming UDP use karta hai
// Thoda pixelated ho jaye chalega, but delay nahi hona chahiye
```

---

## Interview Answer

Interviewer poochhe: "WebSocket TCP hai ya UDP?"

**Answer:** "TCP-based hai. WebSocket ek persistent, reliable connection hai client aur server ke beech. Trading data mein reliability chahiye — price data missed nahi hona chahiye. TCP guaranteed delivery deta hai, order maintain karta hai. UDP mein packet loss ho sakta hai — trading ke liye suitable nahi."

---

## What It Is NOT

⚠️ **TCP = hamesha better nahi.** TCP slow hai reliability ki wajah se. Agar tum video streaming kar rahe ho toh UDP better hai — thoda pixelated ho jaye chalega, but delay nahi hona chahiye.

⚠️ **UDP = unreliable nahi.** UDP "no guarantee" deta hai, but practically zyada packets pahunchte hain. Bas guaranteed nahi hai.

⚠️ **HTTP = TCP hai.** HTTP/HTTPS TCP pe based hai. WebSocket bhi TCP pe hai. UDP sirf specific use cases mein hota hai (gaming, streaming).
