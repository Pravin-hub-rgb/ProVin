TypeScript mein CRUD operations socho — `Create`, `Read`, `Update`, `Delete`. Ye tum har application mein karte ho. React mein `useState`, `useEffect`, API calls — sab CRUD hain.

Database mein bhi CRUD hota hai — `INSERT`, `SELECT`, `UPDATE`, `DELETE`. But frontend se database tak kaise jaata hai? **API** ke through. Aur API kaise design karte hain? **REST** principles follow karke.

# REST API + HTTP Methods + Status Codes

## REST Kya Hai

**REST** = Representational State Transfer. Ek **architecture style** hai APIs banane ke liye. Rules hain ki API kaise design honi chahiye:

1. **Resources** hain (data entities) — jaise Products, Orders, Customers
2. Har resource ka **URL** hai — `/products`, `/orders`
3. **HTTP methods** se operations define karte ho — GET, POST, PUT, DELETE

TypeScript analogy:
```typescript
// REST = TypeScript interface + methods
interface ProductAPI {
  getAll(): Product[];           // GET /products
  getById(id: string): Product;  // GET /products/:id
  create(data: Product): Product; // POST /products
  update(id: string, data: Product): Product; // PUT /products/:id
  delete(id: string): void;     // DELETE /products/:id
}
```

---

## HTTP Methods — CRUD Operations

| Method | Kaam | SQL Equivalent | Prisma Equivalent |
|---|---|---|---|
| **GET** | Data fetch karna (read-only) | `SELECT` | `findMany`, `findUnique` |
| **POST** | Naya data create karna | `INSERT` | `create` |
| **PUT** | Poora resource update/replace karna | `UPDATE` (poora row) | `update` (sab fields) |
| **PATCH** | Sirf ek part update karna | `UPDATE` (specific columns) | `update` (specific fields) |
| **DELETE** | Resource delete karna | `DELETE` | `delete` |

### GET — Data Fetch Karna

```typescript
// Next.js API route
// GET /api/products — sab products
export async function GET() {
  const products = await prisma.product.findMany();
  return Response.json(products);
}

// GET /api/products/:id — ek product
export async function GET(request: Request, { params }: { params: { id: string } }) {
  const product = await prisma.product.findUnique({
    where: { id: params.id }
  });
  return Response.json(product);
}
```

### POST — Naya Data Create Karna

```typescript
// POST /api/products — naya product banao
export async function POST(request: Request) {
  const body = await request.json();
  const product = await prisma.product.create({
    data: {
      name: body.name,
      price: body.price,
    }
  });
  return Response.json(product, { status: 201 });
}
```

### PUT vs PATCH — Update

```typescript
// PUT /api/products/:101 — poora product replace
// Body: { name: "New Rice", price: 150, description: "..." }
// Agar koi field miss ho toh null/default ho jayega

// PATCH /api/products/:101 — sirf ek part update
// Body: { price: 150 }
// Sirf price change hoga, baaki sab same rahega
```

**Interview question:** "PUT aur PATCH mein kya fark hai?"

**Answer:** "PUT poora object replace karta hai — agar koi field miss ho toh wo null ho jaayega. PATCH sirf jo fields bheje hain wahi update karta hai — baaki same rehte hain. PUT tab use karo jab poora object dobara likhna ho, PATCH tab jab sirf kuch fields update karne ho."

### DELETE — Resource Delete Karna

```typescript
// DELETE /api/products/:id
export async function DELETE(request: Request, { params }: { params: { id: string } }) {
  await prisma.product.delete({
    where: { id: params.id }
  });
  return Response.json({ success: true });
}
```

## REST URL Design — Conventions

```
GET    /products          — sab products
GET    /products/:id      — ek product
POST   /products          — naya product banao
PUT    /products/:id      — poora product update
PATCH  /products/:id      — sirf kuch fields update
DELETE /products/:id      — product delete karo

GET    /products/:id/reviews  — ek product ke reviews
POST   /products/:id/reviews  — ek product mein naya review
```

**Rules:**
- **Nouns** use karo (`/products`), verbs nahi (`/getProducts`)
- **Plural** use karo (`/products`), singular nahi (`/product`)
- **Nested** resources for relationships (`/products/:id/reviews`)

## Status Codes — Response Kya Hai

Har HTTP response mein ek **status code** hota hai — batata hai ki request successful thi ya nahi.

### 2xx — Success

| Code | Matlab | Kab |
|---|---|---|
| `200 OK` | Successful request | GET, PUT, PATCH |
| `201 Created` | Naya resource create hua | POST |
| `204 No Content` | Successful but koi response body nahi | DELETE |

```typescript
// POST handler — 201 Created
return Response.json(newProduct, { status: 201 });

// DELETE handler — 204 No Content
return new Response(null, { status: 204 });
```

### 3xx — Redirection

| Code | Matlab |
|---|---|
| `301 Moved Permanently` | Resource permanently nayi jagah hai |
| `304 Not Modified` | Cache se le lo, wapas mat bhejo |

### 4xx — Client Error (Tumhari Galti)

| Code | Matlab | Kab |
|---|---|---|
| `400 Bad Request` | Galat data bheja | Invalid JSON, missing fields |
| `401 Unauthorized` | Auth nahi hai | Login nahi kiya / token invalid |
| `403 Forbidden` | Auth hai but permission nahi | Admin page pe non-admin user |
| `404 Not Found` | Resource nahi mila | Wrong ID, wrong URL |
| `422 Unprocessable Entity` | Data valid nahi hai | Validation errors |
| `429 Too Many Requests` | Rate limit hit | Bahut zyada requests |

```typescript
// 401 — Unauthorized
if (!session) {
  return Response.json({ error: "Login required" }, { status: 401 });
}

// 403 — Forbidden
if (user.role !== "admin") {
  return Response.json({ error: "Admin only" }, { status: 403 });
}

// 404 — Not Found
const product = await prisma.product.findUnique({ where: { id } });
if (!product) {
  return Response.json({ error: "Product not found" }, { status: 404 });
}
```

### 5xx — Server Error (Server Ki Galti)

| Code | Matlab |
|---|---|
| `500 Internal Server Error` | Server crash / unhandled error |
| `502 Bad Gateway` | Upstream server se response nahi aaya |
| `503 Service Unavailable` | Server down hai / maintenance |

```typescript
// 500 — Internal Server Error
try {
  const product = await prisma.product.findUnique({ where: { id } });
  return Response.json(product);
} catch (error) {
  return Response.json({ error: "Server error" }, { status: 500 });
}
```

---

## 401 vs 403 — Common Confusion

Interview poochte hain: "401 aur 403 mein kya fark hai?"

- **401 Unauthorized:** Tum **authenticated nahi ho** — login nahi kiya, token invalid hai. "Pehle login karo."
- **403 Forbidden:** Tum **authenticated ho** but is resource ko access karne ki **permission nahi hai**. "Tum login ho but admin page nahi dekh sakte."

```
401 = "Tum kaun ho? Pehle pehchano."
403 = "Tum pehchane gaye ho, but yahan nahi aa sakte."
```

## Tumhara DukaanOS — REST API Example

```typescript
// app/api/products/route.ts
export async function GET() {
  const products = await prisma.product.findMany();
  return Response.json(products); // 200 OK
}

export async function POST(request: Request) {
  const body = await request.json();
  const product = await prisma.product.create({ data: body });
  return Response.json(product, { status: 201 }); // 201 Created
}

// app/api/products/[id]/route.ts
export async function GET(request: Request, { params }) {
  const product = await prisma.product.findUnique({
    where: { id: params.id }
  });
  if (!product) {
    return Response.json({ error: "Not found" }, { status: 404 });
  }
  return Response.json(product);
}
```

---

## What It Is NOT

⚠️ **REST = sirf GET/POST nahi.** PUT, PATCH, DELETE bhi hain. Har HTTP method ka apna kaam hai.

⚠️ **Status codes = sirf 200 aur 404 nahi.** 201 (Created), 401 (Unauthorized), 403 (Forbidden), 500 (Server Error) — ye sab commonly use hote hain.

⚠️ **REST = RPC nahi.** REST resources pe based hai (`/products`), RPC actions pe (`/getProducts`). REST mein verbs HTTP methods hain, URL nouns hain.
