Data travels through **7 steps** to get from one device to another. Each step has its own job. These 7 steps = the **OSI Model**'s 7 layers.

---

# OSI Model — 7 Layers Architecture

## What It Is

**OSI** = Open Systems Interconnection. A **conceptual model** — it describes how data travels from one device to another when you call `fetch()`.

```
Your Data → 7 Layers → Network Cable/WiFi → Server → 7 Layers → Server Data
```

Each layer has its own job, and each layer uses the services of the layer below it.

---

## 7 Layers — Top to Bottom

### Layer 7 — Application Layer

**What it does:** This is the layer you directly see — HTTP, HTTPS, FTP, SMTP, WebSocket. Your `fetch()`, your browser, your API call — all work at this layer.

```
fetch('https://api.example.com/products')
// HTTP request — Layer 7 protocol
```

### Layer 6 — Presentation Layer

**What it does:** Converts data format — encryption/decryption, compression, format translation. JSON → binary, or encrypted → decrypted.

```
// JSON.parse() and JSON.stringify() — this is Layer 6's job
// binary → JSON conversion
```

When you use HTTPS, data is encrypted — that's Layer 6's job. Data gets decoded at the receiver's end.

### Layer 5 — Session Layer

**What it does:** Establishes and maintains connections. Login sessions, WebSocket connections, API sessions — all managed at this layer.

```
// Session management — Layer 5
// Establishing a login session, maintaining it, closing it
```

When you log in and the session is maintained — that's Layer 5. Whether the connection is open or closed — this layer decides.

### Layer 4 — Transport Layer

**What it does:** Reliable delivery (TCP) or fast delivery (UDP). Maintaining data order, error detection, retransmission.

**TCP:** Reliable — if a packet is lost, resend it. Order is maintained.
**UDP:** Fast — send it, if lost it's lost. Used in gaming, video streaming.

### Layer 3 — Network Layer

**What it does:** Routing — decides the data's path. Identifies where data is going via IP addresses.

```
// IP address — Layer 3
// https://142.250.190.46 — this is Google's IP address
```

Routers work at this layer — they decide which path data takes.

### Layer 2 — Data Link Layer

**What it does:** Physical addressing — MAC address. How devices communicate within a local network.

Switches work at this layer — they forward data within the local network based on MAC address.

### Layer 1 — Physical Layer

**What it does:** Actual cables, signals, hardware. WiFi waves, Ethernet cables, fiber optics.

This is the actual physical medium — data travels as electrical signals or radio waves.

## Practical Flow — When You Call `fetch()`

```
You: fetch('https://api.example.com/products')

Layer 7 (Application): Creates the HTTP request
Layer 6 (Presentation): Converts JSON → binary
Layer 5 (Session): Establishes the connection
Layer 4 (Transport): Ensures reliable delivery via TCP
Layer 3 (Network): Decides the route via IP address
Layer 2 (Data Link): Sends data on the local network
Layer 1 (Physical): Sends the actual signal via cable/WiFi

===== Internet =====

Server: Same 7 layers in reverse order
Layer 1 → Layer 7: Data gets formatted back, response comes
```

## How Deep in Interviews

Interviewer asks: "Explain the OSI model?"

**Short answer:** "7 layers that manage data delivery — Application (HTTP), Presentation (encryption), Session (connections), Transport (TCP/UDP), Network (IP routing), Data Link (MAC address), Physical (cables)."

**Medium answer:** "Your `fetch()` call starts at Layer 7 — HTTP request. Then data goes down through each layer — encryption, session management, TCP reliable delivery, IP routing, local network, physical cable. On the server, the same layers process data in reverse order."

**Deep answer not needed** for full-stack roles. Just know the layer order and which protocol is at which layer (HTTP Layer 7, TCP Layer 4, IP Layer 3).

---

## What It Is NOT

⚠️ **OSI ≠ actual implementation.** It's a conceptual model. The real internet uses the TCP/IP model (4 layers), but OSI is more famous for interviews.

⚠️ **Memorizing 7 layers isn't essential.** In interviews, you need to know the 7 names and what happens at each layer — that's it. No deep detail needed.

⚠️ **You don't work at every layer.** You only work at Layer 7 (Application) — `fetch()`, WebSocket, HTTP. The rest of the layers are handled by network infrastructure.

2. Is your WebSocket based on TCP or UDP? Why?

<details>
<summary>Sample Answer</summary>

**Answer:** TCP-based. Because trading data needs reliability — price data must not be missed. TCP guarantees delivery and maintains order. UDP can lose packets — too risky for trading.

</details>

3. When you call `fetch()`, which layer does data start from and which does it reach?

<details>
<summary>Sample Answer</summary>

**Answer:** Starts at Layer 7 (Application) — HTTP request is created. Then goes down: Layer 6 (encryption), Layer 5 (session), Layer 4 (TCP), Layer 3 (IP routing), Layer 2 (local network), Layer 1 (physical cable). On the server, the same layers process data in reverse order.

</details>

4. What's the difference between TCP and UDP? When is each used?

<details>
<summary>Sample Answer</summary>

**Answer:** TCP is reliable — guaranteed delivery, order maintained, error detection + retransmission. UDP is fast — send it, if lost it's lost. TCP: web browsing, file transfer, email (data must be correct). UDP: gaming, video streaming, live data feeds (speed matters).

</details>

5. Does the actual internet use the OSI model, or is it just for interviews?

<details>
<summary>Sample Answer</summary>

**Answer:** The actual internet uses the TCP/IP model (4 layers). But OSI is conceptual — it helps understand how data travels. OSI is more famous in interviews because its 7 layers are clearly defined. Both are similar, just the layer division differs.

</details>
