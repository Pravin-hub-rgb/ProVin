Two tables, and you need data from both. Customer name is in one table, order amount in another. How do you show both together? **With Joins.**

---

# Joins

## The Problem — Two Tables, One Query

Imagine you have two tables:

```sql
-- customers table
| customer_id | name    |
|-------------|---------|
| 1           | Rahul   |
| 2           | Priya   |
| 3           | Amit    |

-- orders table
| order_id | customer_id | amount |
|----------|-------------|--------|
| 101      | 1           | 500    |
| 102      | 1           | 300    |
| 103      | 2           | 700    |
```

Now you want: "Show each customer with their orders." Problem: customer name is in `customers` table, order amount is in `orders` table. They're separate.

The database does this with a **JOIN**.

---

## INNER JOIN — Only Matched Rows

Only rows where a match exists **in both tables**.

```sql
SELECT customers.name, orders.amount
FROM customers
INNER JOIN orders ON customers.customer_id = orders.customer_id;
```

Result:
```
| name  | amount |
|-------|--------|
| Rahul | 500    |
| Rahul | 300    |
| Priya | 700    |
```

Notice: **Amit doesn't appear** — because he has no orders. INNER JOIN shows only matched rows.

---

## LEFT JOIN — All Rows from the Left Table

**All rows** from the left table — data from the right if match found, else NULL.

```sql
SELECT customers.name, orders.amount
FROM customers
LEFT JOIN orders ON customers.customer_id = orders.customer_id;
```

Result:
```
| name  | amount |
|-------|--------|
| Rahul | 500    |
| Rahul | 300    |
| Priya | 700    |
| Amit  | NULL   |  -- Amit has no order, so NULL
```

Amit now appears — his `amount` is NULL because he has no orders, but the customer row is still there.

**DukaanOS angle:** When you want "show all products whether in stock or not" — that's the classic LEFT JOIN use case. Products LEFT JOIN inventory — every product shows up, stock is NULL if none.

```sql
SELECT products.name, inventory.quantity
FROM products
LEFT JOIN inventory ON products.id = inventory.product_id;
```

---

## RIGHT JOIN — All Rows from the Right Table

Opposite of LEFT — all rows from the right table, data from the left if match found, else NULL.

```sql
SELECT customers.name, orders.amount
FROM customers
RIGHT JOIN orders ON customers.customer_id = orders.customer_id;
```

Result:
```
| name  | amount |
|-------|--------|
| Rahul | 500    |
| Rahul | 300    |
| Priya | 700    |
```

Here all orders from the right table (`orders`) show up. If a customer didn't match, `name` would be NULL.

**Tip:** RIGHT JOIN is almost never used. You can achieve the same by reversing the order in a LEFT JOIN. Most developers only use LEFT JOIN.

---

## FULL OUTER JOIN — All Rows from Both Tables

All rows from both tables, whether matched or not.

```sql
SELECT customers.name, orders.amount
FROM customers
FULL OUTER JOIN orders ON customers.customer_id = orders.customer_id;
```

Result:
```
| name  | amount |
|-------|--------|
| Rahul | 500    |
| Rahul | 300    |
| Priya | 700    |
| Amit  | NULL   |  -- customer exists, no order
```

If there's an order with no matching customer (orphan record), that would also show up with `name = NULL`.

---

## SELF JOIN — A Table Joined with Itself

A table joined with itself — when there's a hierarchy within a table.

```sql
-- employees table
| emp_id | name     | manager_id |
|--------|----------|------------|
| 1      | Rajesh   | NULL       |  -- CEO
| 2      | Suresh   | 1          |  -- under Rajesh
| 3      | Priyanka | 1          |  -- under Rajesh
| 4      | Amit     | 2          |  -- under Suresh
```

"Show each employee with their manager":
```sql
SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.emp_id;
```

Result:
```
| employee | manager |
|----------|---------|
| Rajesh   | NULL    |  -- CEO, no manager
| Suresh   | Rajesh  |
| Priyanka | Rajesh  |
| Amit     | Suresh  |
```

The same table used twice — once as `e` (employee), once as `m` (manager). Hence SELF JOIN.

---

## Common Gotcha — NULL in LEFT JOIN

Interview question: *"What happens in a LEFT JOIN if a customer has no orders?"*

`orders.amount` comes as **NULL**, but the customer's row still shows up. Important — the customer doesn't disappear.

---

## Prisma and Joins — Implicit Joins

Prisma doesn't write explicit JOINs. Prisma understands relations itself:

```typescript
// Prisma — works like a LEFT JOIN
const customersWithOrders = await prisma.customer.findMany({
  include: {
    orders: true  // orders come along with each customer
  }
});
```

Result:
```typescript
[
  { name: "Rahul", orders: [{ amount: 500 }, { amount: 300 }] },
  { name: "Priya", orders: [{ amount: 700 }] },
  { name: "Amit", orders: [] }  // empty array, not NULL
]
```

Prisma uses LEFT JOIN internally. If a customer has no orders, you get an empty array (not NULL).

---

## Join Types — When to Use Which

| Type | When to use |
|---|---|
| **INNER JOIN** | You want only matched data — unmatched rows not needed |
| **LEFT JOIN** | You want all rows from the left table; right matches if found, else NULL |
| **RIGHT JOIN** | You want all rows from the right table (almost never used) |
| **FULL OUTER JOIN** | You want all rows from both tables |
| **SELF JOIN** | Hierarchy in a table (employee-manager, category-subcategory) |

**Interview rule:** LEFT JOIN is used the most. INNER JOIN is second. The rest are rarely asked in full-stack roles.

---

## What It Is NOT

⚠️ **JOIN ≠ just merging data.** JOIN is a mathematical operation — cartesian product of two sets with a condition. But in practice, you just need to understand "match and combine."

⚠️ **RIGHT JOIN isn't necessary.** You can achieve the same by reversing the order in a LEFT JOIN. Most developers use only INNER and LEFT.

⚠️ **Prisma has no explicit JOIN.** You use the `include` directive — Prisma JOINs internally. But understanding SQL is essential for interviews.

## In Your Own Words

1. What's the difference between INNER JOIN and LEFT JOIN? When would you use each?

<details>
<summary>Sample Answer</summary>

**Answer:** INNER JOIN shows only matched rows — rows present in both tables. LEFT JOIN shows all rows from the left table; data from the right if matched, else NULL. Use case: "show all customers whether they have orders or not" — LEFT JOIN. "Show only customers who have orders" — INNER JOIN.

</details>

2. If you have `products` and `inventory` tables and want "show all products with stock quantity" — which join?

<details>
<summary>Sample Answer</summary>

**Answer:** LEFT JOIN — `products LEFT JOIN inventory ON products.id = inventory.product_id`. Because "all products" are wanted, whether in stock or not. If you use INNER JOIN, only products with inventory records show up — products without stock disappear.

</details>

3. What comes back in a LEFT JOIN when there's no match in the right table?

<details>
<summary>Sample Answer</summary>

**Answer:** NULL comes back for the right table's columns. Like `orders.amount` is NULL if the customer has no orders. But the customer's row still shows up — it doesn't disappear.

</details>

4. What does the Prisma `include` directive do? What happens in SQL underneath?

<details>
<summary>Sample Answer</summary>

**Answer:** `include: { orders: true }` tells Prisma to fetch orders along with the customer. Underneath, Prisma does a LEFT JOIN between `customers` and `orders` tables. But you don't write explicit SQL — Prisma handles it. If a customer has no orders, an empty array comes back (not NULL).

</details>

5. When is a SELF JOIN used? Give a real example.

<details>
<summary>Sample Answer</summary>

**Answer:** SELF JOIN is used when there's a hierarchy in a table — like an employees table where each employee has a manager (who is also an employee). `employees e LEFT JOIN employees m ON e.manager_id = m.emp_id` — the same table is aliased twice. Another example: categories table with subcategories — parent and child category in the same table.

</details>
