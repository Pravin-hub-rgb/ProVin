TypeScript mein tum `Array.filter()` aur `Array.find()` use karte ho data dhundhne ke liye. Agar tumhare paas do arrays hain aur tumhe dono ka data milake dikhana hai — toh kya karte ho? Ek loop lagake doosre array se match dhundhte ho.

Database mein bhi yahi hota hai — do tables hain, tumhe dono ka data milake chahiye. But wahan tum loop nahi lagate, wahan **Joins** use karte hain.

---

# Joins

## The Problem — Do Tables, Ek Query

Socho tumhare paas do tables hain:

```sql
-- customers table
| customer_id | name    |
|-------------|---------|
| 1           | Rahul   |
| 2           | Priya   |
| 3           | Amit    |

-- orders table
| order_id | customer_id | amount |
|----------|-------------|--------|
| 101      | 1           | 500    |
| 102      | 1           | 300    |
| 103      | 2           | 700    |
```

Ab tumhe chahiye: "Har customer ke saath unke orders dikhao." Problem: customer naam `customers` table mein hai, order amount `orders` table mein hai. Dono alag hain.

TypeScript mein agar ye arrays hote:
```typescript
const customers = [
  { id: 1, name: "Rahul" },
  { id: 2, name: "Priya" },
  { id: 3, name: "Amit" },
];

const orders = [
  { orderId: 101, customerId: 1, amount: 500 },
  { orderId: 102, customerId: 1, amount: 300 },
  { orderId: 103, customerId: 2, amount: 700 },
];
```

Data milake dikhane ke liye tum aisa karte:
```typescript
const result = customers.map(customer => ({
  ...customer,
  orders: orders.filter(o => o.customerId === customer.id)
}));
```

Database mein yahi kaam **JOIN** karta hai — bas syntax alag hai.

---

## INNER JOIN — Sirf Match Hua Wale

Sirf wo rows jinke match **dono tables mein** hain.

```sql
SELECT customers.name, orders.amount
FROM customers
INNER JOIN orders ON customers.customer_id = orders.customer_id;
```

Result:
```
| name  | amount |
|-------|--------|
| Rahul | 500    |
| Rahul | 300    |
| Priya | 700    |
```

Notice kiya? **Amit dikha hi nahi** — kyunki uska koi order nahi hai. INNER JOIN sirf matched rows dikhata hai.

TypeScript analogy:
```typescript
// INNER JOIN = filter + map
const result = customers.filter(c => orders.some(o => o.customerId === c.id))
  .map(c => ({
    name: c.name,
    orders: orders.filter(o => o.customerId === c.id)
  }));
```

---

## LEFT JOIN — Left Table Ke Saare Rows

Left table ke **saare rows** dikhao, right table se match mila toh data, nahi toh NULL.

```sql
SELECT customers.name, orders.amount
FROM customers
LEFT JOIN orders ON customers.customer_id = orders.customer_id;
```

Result:
```
| name  | amount |
|-------|--------|
| Rahul | 500    |
| Rahul | 300    |
| Priya | 700    |
| Amit  | NULL   |  -- Amit ka order nahi hai, isliye NULL
```

Amit ab dikha — uska `amount` NULL hai kyunki uska koi order nahi hai, but customer ki row phir bhi hai.

**DukaanOS angle:** Jab tum "sabhi products dikhao chahe stock mein hon ya na hon" — ye LEFT JOIN ka classic use case hai. Products LEFT JOIN inventory — har product dikhega, stock nahi hai toh NULL.

```sql
SELECT products.name, inventory.quantity
FROM products
LEFT JOIN inventory ON products.id = inventory.product_id;
```

---

## RIGHT JOIN — Right Table Ke Saare Rows

LEFT ka opposite — right table ke saare rows, left se match mila toh data, nahi toh NULL.

```sql
SELECT customers.name, orders.amount
FROM customers
RIGHT JOIN orders ON customers.customer_id = orders.customer_id;
```

Result:
```
| name  | amount |
|-------|--------|
| Rahul | 500    |
| Rahul | 300    |
| Priya | 700    |
```

Yahan right table (`orders`) ke saare orders dikhe. Customer match nahi hua toh `name` NULL hota.

**Tip:** RIGHT JOIN almost kabhi use nahi hota. Tum LEFT JOIN ka order reverse karke wahi kaam kar sakte ho. Most developers sirf LEFT JOIN use karte hain.

---

## FULL OUTER JOIN — Dono Tables Ke Saare Rows

Dono tables ke saare rows, match ho ya na ho.

```sql
SELECT customers.name, orders.amount
FROM customers
FULL OUTER JOIN orders ON customers.customer_id = orders.customer_id;
```

Result:
```
| name  | amount |
|-------|--------|
| Rahul | 500    |
| Rahul | 300    |
| Priya | 700    |
| Amit  | NULL   |  -- customer hai, order nahi
```

Agar koi order aisa bhi ho jiska customer nahi hai (orphan record), wo bhi dikhega with `name = NULL`.

---

## SELF JOIN — Table Apne Aap Se

Ek table ka apne aap se join — jab ek table mein hierarchy ho.

```sql
-- employees table
| emp_id | name    | manager_id |
|--------|---------|------------|
| 1      | Rajesh  | NULL       |  -- CEO
| 2      | Suresh  | 1          |  -- Rajesh ke under
| 3      | Priyanka| 1          |  -- Rajesh ke under
| 4      | Amit    | 2          |  -- Suresh ke under
```

"Har employee ke saath uska manager dikhao":
```sql
SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.emp_id;
```

Result:
```
| employee | manager |
|----------|---------|
| Rajesh   | NULL    |  -- CEO, koi manager nahi
| Suresh   | Rajesh  |
| Priyanka | Rajesh  |
| Amit     | Suresh  |
```

Ek hi table ko do baar use kiya — ek `e` (employee) ke roop mein, ek `m` (manager) ke roop mein. Isliye SELF JOIN.

---

## Common Gotcha — LEFT JOIN Mein NULL

Interview mein poochte hain: *"LEFT JOIN mein agar customer ka koi order nahi hai toh kya hoga?"*

`orders.amount` **NULL** aayega, but customer ki row phir bhi dikhegi. Ye important hai — customer disappear nahi hoga.

TypeScript mein ye `undefined` jaisa hai:
```typescript
const result = customers.map(c => ({
  name: c.name,
  amount: orders.find(o => o.customerId === c.id)?.amount ?? undefined
}));
// Amit ke liye amount undefined hoga
```

## Prisma Mein Joins — Implicit Joins

Prisma mein tum explicit JOIN nahi likhte. Prisma khud samajhta hai relations:

```typescript
// Prisma — ye LEFT JOIN jaisa kaam karta hai
const customersWithOrders = await prisma.customer.findMany({
  include: {
    orders: true  // har customer ke saath orders aayenge
  }
});
```

Result:
```typescript
[
  { name: "Rahul", orders: [{ amount: 500 }, { amount: 300 }] },
  { name: "Priya", orders: [{ amount: 700 }] },
  { name: "Amit", orders: [] }  // empty array, NULL nahi
]
```

Prisma `LEFT JOIN` use karta hai andar se. Agar customer ke orders nahi hain toh empty array aata hai (NULL nahi).

---

## Join Types — Kab Kaunsa

| Type | Kab use karo |
|---|---|
| **INNER JOIN** | Sirf matched data chahiye — unmatched rows nahi chahiye |
| **LEFT JOIN** | Left table ke saare rows chahiye, right se match ho toh theek, nahi toh NULL |
| **RIGHT JOIN** | Right table ke saare rows chahiye (almost kabhi use nahi hota) |
| **FULL OUTER JOIN** | Dono tables ke saare rows chahiye |
| **SELF JOIN** | Table mein hierarchy hai (employee-manager, category-subcategory) |

**Interview rule:** LEFT JOIN sabse zyada use hota hai. INNER JOIN doosra. Baaki rarely poochte hain full-stack roles mein.

---

## What It Is NOT

⚠️ **JOIN = sirf data merge nahi.** JOIN ek mathematical operation hai — two sets ka cartesian product with a condition. But practice mein tumhe bas "match karo aur milao" samajhna hai.

⚠️ **RIGHT JOIN zaroori nahi.** Tum LEFT JOIN ka order reverse karke wahi kaam kar sakte ho. Most developers sirf INNER aur LEFT use karte hain.

⚠️ **Prisma mein explicit JOIN nahi hota.** `include` directive use karte ho — Prisma andar se JOIN karta hai. But SQL samajhna zaroori hai interview ke liye.

## In Your Own Words

1. INNER JOIN aur LEFT JOIN mein kya fark hai? Kab kaunsa use karoge?

<details>
<summary>Sample Jawab</summary>

**Jawab:** INNER JOIN sirf matched rows dikhata hai — dono tables mein jo rows match karti hain. LEFT JOIN left table ke saare rows dikhata hai, right se match mila toh data, nahi toh NULL. Use case: "sabhi customers dikhao chahe order ho ya na ho" — LEFT JOIN. "Sirf wahi customers dikhao jinke orders hain" — INNER JOIN.

</details>

2. Agar tumhare paas `products` aur `inventory` tables hain, aur tumhe "sabhi products dikhao with stock quantity" likhna hai — kaunsa join use karoge?

<details>
<summary>Sample Jawab</summary>

**Jawab:** LEFT JOIN — `products LEFT JOIN inventory ON products.id = inventory.product_id`. Kyunki "sabhi products" chahiye chahe stock mein ho ya na ho. Agar INNER JOIN karoge toh sirf wahi products dikhenge jinke inventory records hain — bina stock wale products gayab ho jayenge.

</details>

3. LEFT JOIN mein agar right table se match nahi mila toh kya aata hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** NULL aata hai right table ke columns mein. Jaise `orders.amount` NULL hoga agar customer ka koi order nahi hai. But customer ki row phir bhi dikhegi — disappear nahi hoga.

</details>

4. Prisma `include` directive kya karta hai? SQL mein kya hota hai andar se?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `include: { orders: true }` Prisma ko bolta hai ki customer ke saath orders bhi fetch karo. Andar se Prisma LEFT JOIN karta hai `customers` aur `orders` tables ke beech. But explicit SQL nahi likhna padta — Prisma handle karta hai. Agar customer ke orders nahi hain toh empty array aata hai (NULL nahi).

</details>

5. SELF JOIN kab use hota hai? Ek real example do.

<details>
<summary>Sample Jawab</summary>

**Jawab:** SELF JOIN tab hota hai jab table mein hierarchy ho — jaise employees table jisme har employee ka ek manager hai (jo khud bhi employee hai). `employees e LEFT JOIN employees m ON e.manager_id = m.emp_id` — ek hi table ko do baar alias karke join karte hain. Aur example: categories table jisme subcategories hain — parent category aur child category ek hi table mein.

</details>
