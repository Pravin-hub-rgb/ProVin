Data kahan store hota hai jab koi app use karte ho? Products, orders, customers — sab kuch database mein hai. Tum Prisma se queries likh rahe ho — `prisma.product.findMany()`, `prisma.order.create()`. But andar kya ho raha hai? Jab tum `findMany()` likhte ho toh database kaise decide karta hai ki kahan se data uthaye? Jab `create()` karte ho toh data disk pe kaise save hota hai?

Ye sab samajhna zaroori hai — sirf "use karna" nahi. Interview mein jab poochhte hain "DBMS explain karo," toh sirf "database management system" bolke kaam nahi chalta. Tumhe pata hona chahiye ki data kyun tables mein hai, normalization kyun zaroori hai, indexes kaise kaam karte hain. Ye sab tumhare daily kaam se directly juda hai — bas vocabulary chahiye apne kaam ko explain karne ke liye.

---

## Kya Seekhenge Is Batch Mein

Chhe concepts hain, har ek important hai:

**A — DBMS vs RDBMS + Keys.** Database kya hai, RDBMS kyun better hai, aur primary key, foreign key, composite key — ye sab database ke identifiers kaise kaam karte hain.

**B — Normalization.** Data duplication kyun khatam karna chahiye. Agar tumhara `orders` table mein customer ka naam baar-baar repeat ho raha hai — ye problem hai. Normalization isse solve karta hai.

**C — Joins.** Do tables ko kaise milaate hain. Jab customer ka naam ek table mein hai aur order ka amount doosre mein — toh dono ko saath mein kaise dikhao?

**D — Indexing.** Database ko fast kaise banate hain. 1 lakh products hain aur barcode se dhundhna hai — bina index ke poora table scan karna padega. Index lagao toh seedha mil jaata hai.

**E — Transactions + ACID.** Jab ek sale hoti hai — inventory kam hona aur sales record create hona — ye dono ek saath honi chahiye. Ya dono ho ya koi nahi. Partial execution data inconsistent kar degi.

**F — SQL vs NoSQL.** Kab SQL (Postgres) use karo, kab NoSQL (MongoDB). Structured data ho toh SQL, flexible data ho toh NoSQL — dono ka apna jagah hai.
