Where is data stored when you use an app? Products, orders, customers — everything is in the database. You're writing queries with Prisma — `prisma.product.findMany()`, `prisma.order.create()`. But what's happening inside? When you write `findMany()`, how does the database decide where to fetch data from? When you do `create()`, how is data saved to disk?

Understanding all of this is essential — not just "using" it. In interviews, when asked "explain DBMS," saying "database management system" isn't enough. You need to know why data is in tables, why normalization is needed, how indexes work. All of this connects directly to your daily work — you just need the vocabulary to explain your work.

---

## What You'll Learn in This Batch

Six concepts, each important:

**A — DBMS vs RDBMS + Keys.** What a database is, why RDBMS is better, and how identifiers like primary key, foreign key, composite key work.

**B — Normalization.** Why eliminate data duplication. If your `orders` table repeats the customer's name — that's a problem. Normalization solves this.

**C — Joins.** How to combine two tables. When the customer's name is in one table and the order amount in another — how do you show both together?

**D — Indexing.** How to make the database fast. 1 lakh products and you need to find by barcode — without an index you scan the whole table. With an index you jump straight to it.

**E — Transactions + ACID.** When a sale happens — inventory decreases and a sales record is created — both must happen together. Either both happen or neither. Partial execution makes data inconsistent.

**F — SQL vs NoSQL.** When to use SQL (Postgres), when NoSQL (MongoDB). Structured data → SQL, flexible data → NoSQL — both have their place.
