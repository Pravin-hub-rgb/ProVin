DukaanOS mein tumhara data kahan store hota hai? Products, orders, customers — sab kuch Postgres mein hai. Tum Prisma se queries likh rahe ho — `prisma.product.findMany()`, `prisma.order.create()`. But andar kya ho raha hai? Jab tum `findMany()` likhte ho toh database kaise decide karta hai ki kahan se data uthaye? Jab `create()` karte ho toh data disk pe kaise save hota hai?

Ye sab samajhna zaroori hai — sirf "use karna" nahi. Interview mein jab poochhte hain "DBMS explain karo," toh sirf "database management system" bolke kaam nahi chalta. Tumhe pata hona chahiye ki data kyun tables mein hai, normalization kyun zaroori hai, indexes kaise kaam karte hain. Ye sab tumhare daily kaam se directly juda hai — bas vocabulary chahiye apne kaam ko explain karne ke liye.

## Kya Seekhenge Is Batch Mein

Chhe concepts hain, har ek tumhare code ke context se connected:

**A — DBMS vs RDBMS + Keys.** Database kya hai, RDBMS kyun better hai, aur primary key, foreign key, composite key — ye sab TypeScript ki `interface` se kaise relate karte hain.

**B — Normalization.** Data duplication kyun khatam karna chahiye. Agar tumhara `orders` table mein customer ka naam baar-baar repeat ho raha hai — ye wahi hai jaise ek object mein same property 5 jagah copy karke rakhna.

**C — Joins.** Do tables ko kaise milaate hain. TypeScript mein `Array.filter()` aur `Array.find()` se kaise data combine karte ho — database mein wahi kaam joins karte hain.

**D — Indexing.** Database ko fast kaise banate hain. TypeScript mein `Map` vs `Array` — Map O(1) deta hai kyunki index hai, Array mein O(n) scan karna padta hai. Database mein bhi wahi concept hai.

**E — Transactions + ACID.** Jab ek sale hoti hai — inventory kam hona aur sales record create hona — ye dono ek saath honi chahiye. Jaise React mein `useEffect` cleanup — ya dono ho ya koi nahi.

**F — SQL vs NoSQL.** Kab SQL (Postgres) use karo, kab NoSQL (MongoDB). TypeScript ka `interface` vs `any` — structured vs flexible.
