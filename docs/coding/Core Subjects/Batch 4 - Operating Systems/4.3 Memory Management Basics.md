The OS has to decide which program uses how much memory, when to allocate, when to free. All of this falls under **memory management**.

---

# Memory Management Basics

## Stack vs Heap

```javascript
// Stack memory — primitive types, fixed size
let x = 10; // On stack
let name = "Vin"; // On stack
let isActive = true; // On stack

// Heap memory — objects, arrays, dynamic size
const product = { name: "Rice", price: 120 }; // On heap
const numbers = [1, 2, 3]; // On heap
```

| | Stack | Heap |
|---|---|---|
| Data | Primitive types | Objects, arrays |
| Size | Fixed (small) | Dynamic (large) |
| Speed | Fast (direct access) | Slow (access via reference/pointer) |
| Management | Automatic (LIFO) | Garbage collector |

---

## Virtual Memory

The OS makes each process feel like it has **all the memory** (isolated), while managing things behind the scenes.

```javascript
// Node.js process feels like it has lots of memory
// But OS manages memory behind the scenes
process.memoryUsage();
// { rss: 30000000, heapTotal: 10000000, heapUsed: 5000000 }
// RSS = actual memory used by process
```

**Virtual Memory concept:**
- Each process gets a "virtual address space"
- OS maps virtual addresses to physical RAM
- If RAM runs short, disk (swap space) is used
- Process doesn't know where actual memory is — OS handles it

Virtual memory = indirection. OS first maps the virtual address, then physical address is found.

---

## Paging

Dividing memory into **fixed-size blocks** (pages) — to make management easier and reduce fragmentation.

```
Virtual Memory:
Page 0: [0-4KB]
Page 1: [4-8KB]
Page 2: [8-12KB]
...

Physical Memory:
Frame 0: [actual RAM slot 0]
Frame 1: [actual RAM slot 1]
Frame 2: [actual RAM slot 2]
...

OS mapping: Page 0 → Frame 2, Page 1 → Frame 0, Page 2 → Frame 1
```

Paging = dividing memory into chunks — makes management easier and reduces fragmentation.

---

## Fragmentation

Small unused gaps forming in memory that can't be used.

### Internal Fragmentation

Waste space **inside** an allocated block.

```
Block size: 8KB
Actual data: 5KB
Waste: 3KB (internal fragmentation)
```

### External Fragmentation

Gaps **between** blocks — total space is enough but not contiguous.

```
[Used 4KB] [Free 2KB] [Used 4KB] [Free 3KB]
Total free: 5KB — but not contiguous
Large allocation not possible
```

**Paging reduces fragmentation** — fixed-size pages mean gaps are small.

## Garbage Collection — Node.js

The JavaScript engine (V8) automatically frees memory — **garbage collection**.

```javascript
// Memory allocated
let obj = { name: "Rice" };

// Memory freed — when obj's reference is lost
obj = null; // Now garbage collector can free this
```

**How GC works:**
1. **Mark phase:** Mark all reachable objects (currently in use)
2. **Sweep phase:** Free unmarked objects (garbage)

```javascript
function processData() {
  const largeData = fetchHugeData(); // allocated on heap
  // Process...
  return result;
} // largeData's reference lost — GC will free it
```

**Memory leak = garbage collection can't happen:**
```javascript
// ❌ Memory leak
const cache = {};
setInterval(() => {
  cache[Date.now()] = fetchData(); // new data every second
  // cache never freed — keeps growing
}, 1000);

// ✅ Fix
const cache = new Map();
// Or limit cache size
```

---

## What It Is NOT

⚠️ **Virtual Memory ≠ unlimited memory.** Virtual memory borrows from disk — it's slow. More RAM is better.

⚠️ **Garbage Collection ≠ prevents memory leaks.** GC frees unreachable objects. But if you intentionally hold references (global variables, event listeners), GC can't do anything.

⚠️ **Paging ≠ performance guarantee.** Paging reduces fragmentation but has overhead (page tables). It just makes management easier.

## In Your Own Words

1. What's the difference between Stack and Heap memory?

<details>
<summary>Sample Answer</summary>

**Answer:** Stack holds primitive types (number, string) — fixed size, fast access, automatic management (LIFO). Heap holds objects/arrays — dynamic size, slow access (via reference/pointer), managed by garbage collector.

</details>

2. What is virtual memory? Why does the OS use it?

<details>
<summary>Sample Answer</summary>

**Answer:** The OS makes each process feel like it has all the memory — but actually maps virtual addresses to physical RAM. Benefits: process isolation (one process can't access another's memory), and if RAM runs short, disk (swap) is used.

</details>

3. What is a memory leak? How does it happen in Node.js?

<details>
<summary>Sample Answer</summary>

**Answer:** Memory leak happens when objects aren't in use but memory isn't freed — garbage collection can't happen. In Node.js: global variables, uncleared intervals/timeouts, event listeners that aren't removed, growing caches — all can cause memory leaks.

</details>

4. How does garbage collection work?

<details>
<summary>Sample Answer</summary>

**Answer:** Mark and sweep algorithm: (1) Mark phase — mark all reachable objects (currently in use). (2) Sweep phase — free unmarked objects (garbage). V8 JavaScript engine does this automatically. You don't manually free memory — but you need to handle references.

</details>
