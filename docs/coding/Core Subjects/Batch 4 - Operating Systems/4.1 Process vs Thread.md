An independently running program — has its **own memory space**. Inside it, separate **threads** can run that share memory. Process and Thread — these are fundamental OS concepts.

---

# Process vs Thread

## What is a Process

**Process** = an independently running program — has its **own memory space**.

```javascript
// When you run `node app.js` — a process is created
// Inside that process:
// - V8 JavaScript engine (main thread)
// - libuv thread pool (background I/O)
// - Event loop
// - Memory heap + stack
```

A process is an independent unit — it can't directly access another process's memory.

## What is a Thread

**Thread** = a **lightweight execution unit** running inside a process — threads of the same process **share** memory.

```javascript
// On the main thread
const data = fetchSomeData();

// On a background thread (libuv)
fs.readFile('large-file.txt', (err, data) => {
  // This runs on a background thread
  // Main thread isn't blocked
});
```

---

## Comparison

| | Process | Thread |
|---|---|---|
| Memory | Own separate memory space | Shares memory with the process |
| Creation cost | Heavy (uses more resources) | Light (created fast) |
| Communication | Slow (IPC — Inter-Process Communication) | Fast (shared memory) |
| Crash impact | One process crashing doesn't affect others | One thread crashing can affect the whole process |
| Use case | Independent applications | Background tasks within an app |

## Node.js — Single Threaded + Background Threads

```javascript
// Node.js architecture
// Main thread: JavaScript execution
// libuv thread pool: File I/O, DNS, Crypto, Compression

const http = require('http');

const server = http.createServer((req, res) => {
  // Runs on main thread — JavaScript execution
  res.end('Hello World');

  // This runs on a background thread — main thread not blocked
  fs.readFile('large-file.txt', (err, data) => {
    // Callback comes back to main thread
  });
});
```

**In interviews you can say:** "Node.js is single-threaded for JavaScript execution, but uses the libuv thread pool for heavy I/O operations — file read, DNS lookup, crypto. The main thread isn't blocked, that's why it's non-blocking I/O."

## IPC — Inter-Process Communication

Two processes can't talk directly — their memory is separate. Communication requires **IPC**:

- **Pipes** — one process's output becomes another's input
- **Sockets** — network communication
- **Shared Memory** — both processes access the same memory
- **Message Passing** — sending messages

**Node.js example:**
```javascript
// Parent process
const { fork } = require('child_process');

const child = fork('./worker.js');
child.send({ task: 'process-data', data: [1, 2, 3] });

child.on('message', (result) => {
  console.log('Result from child:', result);
});

// worker.js
process.on('message', (msg) => {
  const result = msg.data.map(x => x * 2);
  process.send(result);
});
```

## Process — In Node.js

```javascript
// process object — info about the Node.js process
console.log(process.pid); // Process ID
console.log(process.memoryUsage()); // Memory usage
console.log(process.env.NODE_ENV); // Environment variables

// Process exit
process.on('exit', (code) => {
  console.log(`Process exited with code ${code}`);
});

// Uncaught error
process.on('uncaughtException', (err) => {
  console.error('Uncaught Exception:', err);
  process.exit(1);
});
```

## Thread — In Node.js

```javascript
// Worker Threads — explicit threads in Node.js
const { Worker, isMainThread, parentPort, workerData } = require('worker_threads');

if (isMainThread) {
  // Main thread
  const worker = new Worker(__filename, {
    workerData: { numbers: [1, 2, 3, 4, 5] }
  });

  worker.on('message', (result) => {
    console.log('Result:', result);
  });
} else {
  // Worker thread
  const result = workerData.numbers.map(x => x * 2);
  parentPort.postMessage(result);
}
```

**Use Worker Threads when:**
- CPU-intensive tasks (image processing, data crunching)
- Background computation
- Don't want to block the main thread

---

## What It Is NOT

⚠️ **Process ≠ program.** Process is a running instance. Program is the file (`app.js`), process is its execution (`node app.js`).

⚠️ **Thread ≠ always faster.** Thread creation has cost too. For small tasks, threads are overhead. Use threads only for heavy tasks.

⚠️ **Node.js ≠ truly multi-threaded.** JavaScript execution is single-threaded. Background I/O uses threads but JavaScript code doesn't run on them (except Worker Threads).

## In Your Own Words

1. Give 3 main differences between Process and Thread.

<details>
<summary>Sample Answer</summary>

**Answer:** (1) Process has its own memory, thread shares memory. (2) Process is heavy (slow creation), thread is light (fast creation). (3) If a process crashes, others aren't affected; if a thread crashes, it can affect the whole process.

</details>

2. Node.js is single-threaded but what happens in the background?

<details>
<summary>Sample Answer</summary>

**Answer:** JavaScript execution happens on the main thread (single-threaded). But the libuv thread pool uses background threads for heavy I/O operations — file read, DNS lookup, crypto. The main thread isn't blocked, that's why it's non-blocking I/O. `fs.readFile()` runs on a background thread.

</details>

3. When do you use Worker Threads?

<details>
<summary>Sample Answer</summary>

**Answer:** For CPU-intensive tasks — image processing, data crunching, heavy computation. Normal I/O is handled by the libuv thread pool. Use Worker Threads when you explicitly need to run a separate thread and not block the main thread.

</details>

4. Why is IPC (Inter-Process Communication) necessary?

<details>
<summary>Sample Answer</summary>

**Answer:** Two processes have separate memory — they can't access each other directly. IPC enables communication — pipes, sockets, shared memory, message passing. In Node.js, parent-child processes communicate via `child_process.fork()` using `send()` and `on('message')`.

</details>
