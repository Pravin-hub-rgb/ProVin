Node.js single-threaded hai — tum jaante ho. JavaScript engine (V8) ek hi thread pe chalta hai. But `setTimeout`, `fs.readFile`, `fetch()` — ye sab background mein kaam karte hain bina main thread ko block kiye. Kaise?

Answer: Node.js ek **process** hai aur usme **threads** hain. Main JavaScript execution ek thread pe hota hai, but heavy I/O operations (file read, crypto) ke liye **libuv thread pool** use hota hai — background mein alag threads hote hain.

---

# Process vs Thread

## Process Kya Hai

**Process** = ek independently running program — apni khud ki **memory space** hoti hai.

```typescript
// Node.js process
// Jab tum `node app.js` chalate ho — ek process banta hai
// Us process mein:
// - V8 JavaScript engine (main thread)
// - libuv thread pool (background I/O)
// - Event loop
// - Memory heap + stack
```

**TypeScript analogy:** Process = ek independent `worker` — apna data hai, apna execution context hai, doosre worker se directly baat nahi kar sakta (IPC chahiye).

## Thread Kya Hai

**Thread** = ek process ke andar chalne wala **lightweight execution unit** — same process ke threads memory **share** karte hain.

```typescript
// Node.js main thread
const data = fetchSomeData(); // Main thread pe

// Background thread (libuv)
fs.readFile('large-file.txt', (err, data) => {
  // Ye background thread pe chalta hai
  // Main thread block nahi hota
});
```

**TypeScript analogy:** Thread = ek function jo same scope mein share hota hai. Multiple functions ek saath chal sakti hain, same variables access kar sakti hain.

---

## Comparison

| | Process | Thread |
|---|---|---|
| Memory | Apni alag memory space | Same process ke saath memory share |
| Creation cost | Heavy (zyada resources lagte hain) | Light (fast banta hai) |
| Communication | Slow (IPC — Inter-Process Communication) | Fast (shared memory) |
| Crash impact | Ek process crash ho toh dusre pe asar nahi | Ek thread crash ho sakta hai poore process ko affect kare |
| Use case | Independent applications | Background tasks within an app |

---

## Node.js — Single Threaded + Background Threads

```typescript
// Node.js architecture
// Main thread: JavaScript execution
// libuv thread pool: File I/O, DNS, Crypto, Compression

const http = require('http');

const server = http.createServer((req, res) => {
  // Main thread pe chalta hai — JavaScript execution
  res.end('Hello World');

  // Ye background thread pe chalta hai — main thread block nahi hota
  fs.readFile('large-file.txt', (err, data) => {
    // Callback main thread pe aata hai
  });
});
```

**Interview mein bol sakte ho:** "Node.js single-threaded hai JavaScript execution ke liye, but libuv thread pool use karta hai heavy I/O operations ke liye — file read, DNS lookup, crypto. Main thread block nahi hota, isliye non-blocking I/O hai."

---

## IPC — Inter-Process Communication

Do processes seedha baat nahi kar sakte — unki memory alag hai. Communication ke liye **IPC** chahiye:

- **Pipes** — ek process ka output doosre ka input
- **Sockets** — network communication
- **Shared Memory** — dono processes same memory access karein
- **Message Passing** — messages bhejo

**Node.js example:**
```typescript
// Parent process
const { fork } = require('child_process');

const child = fork('./worker.js');
child.send({ task: 'process-data', data: [1, 2, 3] });

child.on('message', (result) => {
  console.log('Result from child:', result);
});

// worker.js
process.on('message', (msg) => {
  const result = msg.data.map(x => x * 2);
  process.send(result);
});
```

## Process — Node.js Mein

```typescript
// process object — Node.js process ki info
console.log(process.pid); // Process ID
console.log(process.memoryUsage()); // Memory usage
console.log(process.env.NODE_ENV); // Environment variables

// Process exit
process.on('exit', (code) => {
  console.log(`Process exited with code ${code}`);
});

// Uncaught error
process.on('uncaughtException', (err) => {
  console.error('Uncaught Exception:', err);
  process.exit(1);
});
```

## Thread — Node.js Mein

```typescript
// Worker Threads — Node.js mein explicit threads
const { Worker, isMainThread, parentPort, workerData } = require('worker_threads');

if (isMainThread) {
  // Main thread
  const worker = new Worker(__filename, {
    workerData: { numbers: [1, 2, 3, 4, 5] }
  });

  worker.on('message', (result) => {
    console.log('Result:', result);
  });
} else {
  // Worker thread
  const result = workerData.numbers.map(x => x * 2);
  parentPort.postMessage(result);
}
```

**Worker Threads tab use karo:**
- CPU-intensive tasks (image processing, data crunching)
- Background computation
- Main thread ko block nahi karna

---

## What It Is NOT

⚠️ **Process = program nahi.** Process ek running instance hai. Program file hai (`app.js`), process uska execution hai (`node app.js`).

⚠️ **Thread = always faster nahi.** Thread creation bhi cost hai. Chhote tasks ke liye threads overhead hain. Bas heavy tasks ke liye threads use karo.

⚠️ **Node.js = truly multi-threaded nahi.** JavaScript execution single-threaded hai. Background I/O ke liye threads hain but JavaScript code nahi chalta unpe (Worker Threads ke alawa).

<details>

<details>
<summary>Sample Jawab</summary>

**Jawab:** CPU-intensive tasks ke liye — image processing, data crunching, heavy computation. Normal I/O ke liye libuv thread pool kaafi hai. Worker Threads tab jab tumhe explicitly alag thread chalana ho aur main thread ko block nahi karna ho.

</details>

<details>

</details>
