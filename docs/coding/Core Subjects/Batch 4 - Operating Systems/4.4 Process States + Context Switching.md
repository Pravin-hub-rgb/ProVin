Processes also go through **states** during their lifetime — New, Ready, Running, Waiting, Terminated. These states describe the process lifecycle.

# Process States + Context Switching

## Process States — 5 States

A process goes through these 5 states during its lifetime:

```
New → Ready → Running → Waiting → Terminated
         ↑         │         │
         └─────────┘         │
         ↑                   │
         └───────────────────┘
```

### New

Process is **being created**. Not yet loaded into RAM.

```javascript
// In Node.js: wrote `node app.js` — process in new state
// OS is creating the process
```

### Ready

Process is **ready to execute**, waiting for CPU.

```javascript
// Process loaded into RAM, ready
// But CPU is running another process right now
// Waiting in ready queue
```

### Running

CPU is currently **executing** it.

```javascript
// Process code is running
// JavaScript code is executing
```

### Waiting

Waiting for some **I/O operation** or event.

```javascript
// Called fs.readFile() — now waiting for disk I/O
// Called fetch() — now waiting for network response
// Process in waiting state — CPU running another process
```

### Terminated

Execution **complete**.

```javascript
// Process finished its work
// Memory being freed
// process.exit(0) — normal termination
```

---

## State Transitions

```
New → Ready: Process created, loaded into RAM
Ready → Running: Got CPU, execution started
Running → Waiting: I/O operation started
Waiting → Ready: I/O complete, back to ready queue
Running → Terminated: Work finished
Running → Ready: Time slice expired (preemption)
```

Every state has a transition — moving from one state to another. This is the process lifecycle.

---

## Context Switching

**Context Switching** = when the CPU **switches** from one process/thread to another — saves the current process's state, loads the new process's state.

```javascript
// Node.js event loop — context switching
// Main thread: JavaScript code running
// File read complete → callback ready
// Main thread: stop current work, run callback
// = Context switch (conceptual)
```

**Steps:**
1. Save current process's state (registers, memory pointers, program counter)
2. Load new process's state
3. Execute new process

**Overhead:** Context switching is **time-consuming** — save + load + overhead. Too much context switching can slow down performance.

```
Process A running → Context switch → Process B running
                 ↑
         Save A's state
         Load B's state
         Overhead: ~1-10 microseconds
```

---

## Node.js — Context Switching Angle

Node.js is single-threaded but context switching happens:

```javascript
// Event loop phases — implicit context switching
setTimeout(() => {
  // Phase 1: Timer
}, 1000);

fs.readFile('file.txt', () => {
  // Phase 2: I/O callback
});

setImmediate(() => {
  // Phase 3: Check phase
});

// Event loop switches between phases
// Each phase = different type of callback
```

**Worker Threads — explicit context switching:**
```javascript
// Main thread → Worker thread = explicit context switch
const worker = new Worker('./heavy-task.js');
// CPU: stop main thread, run worker thread
// Worker complete → back to main thread
```

## Interview Answer

Interviewer asks: "What are process states?"

**Answer:** "5 states: New (being created), Ready (ready to execute, waiting for CPU), Running (CPU executing), Waiting (waiting for I/O), Terminated (complete). Transitions: New→Ready→Running→Waiting→Ready→Running→Terminated."

---

## What It Is NOT

⚠️ **Process state ≠ thread state.** Thread has its own state but thread is inside a process. Process state is about the overall program.

⚠️ **Context switching ≠ instant.** There's overhead — save + load. Too many contexts/threads can slow down performance.

⚠️ **Waiting state ≠ dead.** Process is still alive — just waiting for some I/O. When I/O completes, it returns to ready state.
