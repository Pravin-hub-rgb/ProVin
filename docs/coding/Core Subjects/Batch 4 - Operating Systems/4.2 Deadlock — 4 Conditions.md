# Deadlock

## What is Deadlock

**Deadlock** = two (or more) processes are waiting for each other's resource to be released, and no one releases — everyone gets stuck **forever**.

## Real Example

```javascript
// Process A has Resource 1, needs Resource 2
// Process B has Resource 2, needs Resource 1

// Process A:
lock(resource1);        // ✅ Got it
// now needs resource2... but B has it
// waiting for resource2...  ← STUCK

// Process B:
lock(resource2);        // ✅ Got it
// now needs resource1... but A has it
// waiting for resource1...  ← STUCK

// Both stuck in infinite wait
```

---

## 4 Conditions for Deadlock

These 4 conditions must hold **together** for deadlock to occur:

### 1. Mutual Exclusion

A resource can be used by only **one process** at a time.

```javascript
// Lock — only one process can access at a time
const lock = new Mutex();
await lock.acquire();
// Critical section — only one process here
lock.release();
```

### 2. Hold and Wait

A process **holds** one resource and **waits** for another.

```javascript
// Process A:
const resource1 = await acquire(resource1); // held
// now waiting for resource2... while holding resource1
```

### 3. No Preemption

A resource **cannot be forcefully taken away** — the process releases it itself.

```javascript
// Can't forcefully take resource1
// A will release when done
// But A is waiting for B — never happens
```

### 4. Circular Wait

Processes wait for each other in a **circular chain**.

```
A waits for B's resource
B waits for A's resource
Circular chain = DEADLOCK
```

---

## Prevention — Break One Condition

To prevent deadlock, **break any one condition:**

**Fixed Resource Ordering:**
```javascript
// ✅ Prevention — both processes request resources in same order
// A: first resource1, then resource2
// B: first resource1, then resource2
// No circular wait forms
```

**Timeout:**
```javascript
// ✅ Prevention — time limit on waiting
const resource = await acquire(resource2, { timeout: 5000 });
if (!resource) {
  // Timeout — release current resources, retry
  release(resource1);
  await sleep(1000);
  // Retry with proper order
}
```

## Node.js — Real Deadlock Scenario

```javascript
// ❌ Potential deadlock — nested callbacks
app.get('/order', async (req, res) => {
  const order = await prisma.order.findUnique({ where: { id } });

  // Nested callbacks — if one fails, everything hangs
  await prisma.inventory.update({ /* ... */ });
  await prisma.sales.create({ /* ... */ });
  // If these aren't in a transaction — deadlock possible
});

// ✅ Prevention — use transaction
app.get('/order', async (req, res) => {
  await prisma.$transaction(async (tx) => {
    await tx.inventory.update({ /* ... */ });
    await tx.sales.create({ /* ... */ });
  });
});
```

## Interview Answer

Interviewer asks: "What is deadlock? Give the 4 conditions?"

**Answer:** "Deadlock happens when two processes wait for each other's resource and no one releases — everyone gets stuck. 4 conditions: (1) Mutual Exclusion — resource usable by only one process at a time, (2) Hold and Wait — holding one resource while waiting for another, (3) No Preemption — can't forcefully take away, (4) Circular Wait — waiting in a circular chain."

**Practical answer:** "Deadlock is rare in Node.js because it's single-threaded. But it can happen in database transactions — when two transactions wait for each other's lock. Using Prisma `$transaction` prevents this — it provides proper ordering."

---

## What It Is NOT

⚠️ **Deadlock ≠ hang.** Hang = program is slow or stuck on some operation. Deadlock = specific circular wait situation.

⚠️ **Deadlock ≠ only in databases.** Multi-threaded applications, database transactions, distributed systems — can happen anywhere.

⚠️ **Deadlock ≠ always a crash.** Program doesn't crash — it just hangs. Manual intervention needed (kill the process).
