Do transactions ek-dusre ka resource wait kar rahi hain, koi release nahi kar raha. Sab stuck. Ye **Deadlock** hai.

# Deadlock

## Deadlock Kya Hai

**Deadlock** = do (ya zyada) processes ek-dusre ka resource release hone ka wait kar rahe hain, aur koi bhi release nahi kar raha — sab stuck ho jaate hain **forever**.

## Real Example

```javascript
// Process A ke paas Resource 1 hai, use Resource 2 chahiye
// Process B ke paas Resource 2 hai, use Resource 1 chahiye

// Process A:
lock(resource1);        // ✅ Mil gaya
// ab resource2 chahiye... lekin B ke paas hai
// wait for resource2...  ← STUCK

// Process B:
lock(resource2);        // ✅ Mil gaya
// ab resource1 chahiye... lekin A ke paas hai
// wait for resource1...  ← STUCK

// Dono infinite wait mein fas gaye
```

---

## 4 Conditions for Deadlock

Ye 4 conditions **ek saath** honi chahiye tabhi deadlock hota hai:

### 1. Mutual Exclusion

Resource ek time pe sirf **ek process** use kar sakta hai.

```javascript
// Lock — ek time pe sirf ek process access kar sakta hai
const lock = new Mutex();
await lock.acquire();
// Critical section — sirf ek process yahan
lock.release();
```

### 2. Hold and Wait

Process ek resource **pakde hue** hai aur dusre ka **wait** kar raha hai.

```javascript
// Process A:
const resource1 = await acquire(resource1); // Hold kar liya
// Ab resource2 ka wait kar raha hai... hold karke
```

### 3. No Preemption

Resource **forcefully chheena nahi** ja sakta — process khud release karega.

```javascript
// resource1 forcefully le nahi sakte
// A kabhi release karega jab kaam ho jaayega
// But A wait kar raha hai B ka — kabhi nahi hoga
```

### 4. Circular Wait

Processes ek **circular chain** mein ek-dusre ka wait kar rahe hain.

```
A waits for B's resource
B waits for A's resource
Circular chain = DEADLOCK
```

---

## Prevention — Koi Ek Condition Todo

Deadlock rokne ke liye **koi ek condition break karo:**

**Fixed Resource Ordering:**
```javascript
// ✅ Prevention — dono processes same order mein resource maange
// A: pehle resource1, phir resource2
// B: pehle resource1, phir resource2
// Circular wait nahi banega
```

**Timeout:**
```javascript
// ✅ Prevention — wait ka time limit
const resource = await acquire(resource2, { timeout: 5000 });
if (!resource) {
  // Timeout — release current resources, retry
  release(resource1);
  await sleep(1000);
  // Retry with proper order
}
```

## Node.js — Real Deadlock Scenario

```javascript
// ❌ Potential deadlock — callback hell
app.get('/order', async (req, res) => {
  const order = await prisma.order.findUnique({ where: { id } });

  // Nested callbacks — agar ek fail ho toh sab hang
  await prisma.inventory.update({ /* ... */ });
  await prisma.sales.create({ /* ... */ });
  // Agar ye dono ek transaction mein nahi hain — deadlock possible
});

// ✅ Prevention — transaction use karo
app.get('/order', async (req, res) => {
  await prisma.$transaction(async (tx) => {
    await tx.inventory.update({ /* ... */ });
    await tx.sales.create({ /* ... */ });
  });
});
```

## Interview Answer

Interviewer poochhe: "Deadlock kya hai? 4 conditions batao?"

**Answer:** "Deadlock tab hota hai jab do processes ek-dusre ka resource wait kar rahi hain aur koi release nahi kar raha — sab stuck. 4 conditions: (1) Mutual Exclusion — resource sirf ek process use kar sake, (2) Hold and Wait — ek resource pakadke doosre ka wait, (3) No Preemption — forcefully chheen nahi sakte, (4) Circular Wait — A B ka wait kare, B A ka wait kare."

**Practical answer:** "Node.js mein deadlock zyada nahi hota kyunki single-threaded hai. But database transactions mein ho sakta hai — jab do transactions ek-dusre ka lock wait karein. Prisma `$transaction` use karna isse rokta hai — proper ordering deta hai."

---

## What It Is NOT

⚠️ **Deadlock = hang nahi.** Hang = program slow hai ya stuck hai kisi operation pe. Deadlock = specific circular wait situation.

⚠️ **Deadlock = sirf database mein nahi.** Multi-threaded applications, database transactions, distributed systems — kahin bhi ho sakta hai.

⚠️ **Deadlock = hamesha crash nahi.** Program crash nahi hota — sirf hang hota hai. Manual intervention chahiye (kill process).
