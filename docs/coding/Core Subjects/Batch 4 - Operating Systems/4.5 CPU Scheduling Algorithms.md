In the OS, **CPU scheduling** happens — the OS decides which process runs on the CPU when. Multiple processes are in the ready queue, the OS has to decide which one first.

---

# CPU Scheduling Algorithms

## What is CPU Scheduling

Multiple processes are in the **ready queue**, but the CPU can execute only one process at a time. The OS has to decide which process runs when — this is **CPU scheduling**.

```
Ready Queue: [P1, P2, P3, P4]
CPU: only one process can run at a time
Scheduler: which one first? → P2 → P4 → P1 → P3
```

The event loop works similarly — callbacks are in a queue, it decides which runs when.

---

## FCFS — First Come First Serve

Whoever **arrives first**, runs first. Simplest algorithm.

```
Process  | Burst Time | Arrival Time
P1       | 24         | 0
P2       | 3          | 1
P3       | 3          | 2

Execution order: P1 → P2 → P3
P1 wait time: 0
P2 wait time: 24
P3 wait time: 27
```

**Pros:** Simple, fair (order-based)
**Cons:** Convoy effect — if one long process arrives, everyone else waits

Like a FIFO queue — whoever came first goes first. Whichever request arrived first, gets processed first.

---

## SJF — Shortest Job First

The **shortest job** first. Whichever has the least burst time (how long it'll take) runs first.

```
Process  | Burst Time
P1       | 6
P2       | 2
P3       | 8
P4       | 3

Execution order: P2 (2) → P4 (3) → P1 (6) → P3 (8)
```

**Pros:** Minimum average wait time
**Cons:** Burst time must be known in advance (practically difficult), starvation possible (long jobs wait)

Like a priority queue — shortest task first. Complete small tasks first.

---

## Round Robin — Fixed Time Slice

Each process gets a **fixed time slice** (quantum), then the next process. Fair — everyone gets a chance.

```
Time Quantum = 4

Process  | Burst Time
P1       | 12
P2       | 4
P3       | 8

Execution:
P1 runs 4 units → P2 runs 4 units (complete) → P3 runs 4 units
→ P1 runs 4 units → P3 runs 4 units (complete) → P1 runs 4 units (complete)
```

**Pros:** Fair, responsive — no process waits too long
**Cons:** Context switching overhead (frequent switching), quantum size hard to decide

Like time-sharing — every process gets equal chance.

---

## Comparison

| Algorithm | Strategy | Pros | Cons |
|---|---|---|---|
| FCFS | First arrived runs first | Simple | Convoy effect |
| SJF | Shortest job first | Minimum wait time | Burst time must be known |
| Round Robin | Fixed time slice | Fair, responsive | Context switching overhead |

## Interview Answer

Interviewer asks: "What are CPU scheduling algorithms?"

**Answer:** "3 main ones: FCFS (First Come First Serve — first arrived runs first, simple but convoy effect), SJF (Shortest Job First — shortest job first, minimum wait but burst time must be known), Round Robin (fixed time slice for each process, fair but context switching overhead)."

---

## What It Is NOT

⚠️ **Scheduling ≠ only 3 algorithms.** FCFS, SJF, Round Robin are just the basics. Priority Scheduling, Multilevel Queue also exist — but basics are enough.

⚠️ **SJF ≠ practical.** You don't know in advance how long a process will take. Approximation is used (predicted from past behavior).

⚠️ **Round Robin ≠ always best.** If quantum is too small, context switching overhead becomes huge. Quantum size decision is important.

## In Your Own Words

1. What is the FCFS algorithm? What is the convoy effect?

<details>
<summary>Sample Answer</summary>

**Answer:** FCFS = first come first serve — whichever process arrives first in the ready queue gets the CPU first. Convoy effect = if one long process (P1, burst 24) arrives first, other short processes (P2, P3) wait for it. P2's wait time becomes 24 — even though its burst is only 3.

</details>

2. What is time quantum in Round Robin?

<details>
<summary>Sample Answer</summary>

**Answer:** Time quantum = fixed time slice given to each process. If quantum = 4, each process runs for 4 units, then next process. If a process completes within 4 units, fine; otherwise the next process gets its chance. Fair — everyone gets equal opportunity.

</details>

3. Why does SJF give minimum wait time?

<details>
<summary>Sample Answer</summary>

**Answer:** SJF runs shortest jobs first — like P2 (burst 2) → P4 (burst 3) → P1 (burst 6). If P1 ran first, P2 and P4 would wait longer. With SJF, short jobs complete quickly, reducing average wait time.

</details>

4. Why is the Node.js event loop like a scheduling algorithm?

<details>
<summary>Sample Answer</summary>

**Answer:** The event loop gives priority to callbacks — microtasks (Promises) first, then setImmediate, then setTimeout. Just like a CPU scheduler gives priority to processes. The event loop decides which callback runs when — same as CPU scheduling.

</details>
