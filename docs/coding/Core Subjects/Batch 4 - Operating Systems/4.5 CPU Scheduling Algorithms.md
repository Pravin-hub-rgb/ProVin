TypeScript mein event loop hai — callbacks queue mein hain, event loop decide karta hai kaunsa callback kab chalega. Priority hoti hai — setTimeout vs setImmediate vs Promise.

OS mein bhi **CPU scheduling** hota hai — OS decide karta hai kaunsa process kab CPU pe chalega. Multiple processes ready queue mein hain, OS ko decide karna hai kaunsa pehle.

# CPU Scheduling Algorithms

## CPU Scheduling Kya Hai

Multiple processes **ready queue** mein hain, CPU sirf ek process ko ek time pe execute kar sakta hai. OS ko decide karna hai kaunsa process kab chalega — ye **CPU scheduling** hai.

```
Ready Queue: [P1, P2, P3, P4]
CPU: sirf ek process chal sakta hai
Scheduler: kaunsa pehle? → P2 → P4 → P1 → P3
```

**TypeScript analogy:** Event loop = scheduler. Callbacks queue mein hain, event loop decide karta hai kaunsa callback kab chalega.

---

## FCFS — First Come First Serve

Jo **pehle aaya**, pehle chalega. Sabse simple algorithm.

```
Process  | Burst Time | Arrival Time
P1       | 24         | 0
P2       | 3          | 1
P3       | 3          | 2

Execution order: P1 → P2 → P3
P1 ka wait time: 0
P2 ka wait time: 24
P3 ka wait time: 27
```

**Pros:** Simple, fair (order based)
**Cons:** Convoy effect — agar ek lamba process aaya toh baaki sab wait karte hain

**TypeScript analogy:** FIFO queue — pehle aaya pehle gaya. Jaise request handling — jo request pehle aayi, pehle process ho.

---

## SJF — Shortest Job First

Sabse **chhota job** pehle. Burst time (kitna time lagega) sabse kam wa pehle.

```
Process  | Burst Time
P1       | 6
P2       | 2
P3       | 8
P4       | 3

Execution order: P2 (2) → P4 (3) → P1 (6) → P3 (8)
```

**Pros:** Minimum average wait time
**Cons:** Burst time pehle se pata hona chahiye (practically mushkil), starvation possible (lambe jobs ka wait)

**TypeScript analogy:** Priority queue — shortest task pehle. Jaise task scheduling — chhote tasks pehle complete karo.

---

## Round Robin — Fixed Time Slice

Har process ko ek **fixed time slice** milta hai (quantum), phir next process. Fair hai — sabko chance milta hai.

```
Time Quantum = 4

Process  | Burst Time
P1       | 12
P2       | 4
P3       | 8

Execution:
P1 chala 4 units → P2 chala 4 units (complete) → P3 chala 4 units
→ P1 chala 4 units → P3 chala 4 units (complete) → P1 chala 4 units (complete)
```

**Pros:** Fair, responsive — koi process wait nahi karta zyada
**Cons:** Context switching overhead (baar-baar switch), quantum size decide karna mushkil

**TypeScript analogy:** `setInterval` — har process ko time milta hai. Jaise time-sharing — sabko equal chance.

---

## Comparison

| Algorithm | Strategy | Pros | Cons |
|---|---|---|---|
| FCFS | Pehle aaya pehle chala | Simple | Convoy effect |
| SJF | Chhota job pehle | Minimum wait time | Burst time pata hona chahiye |
| Round Robin | Fixed time slice | Fair, responsive | Context switching overhead |

## Interview Answer

Interviewer poochhe: "CPU scheduling algorithms batao?"

**Answer:** "3 main: FCFS (First Come First Serve — pehle aaya pehle chala, simple but convoy effect), SJF (Shortest Job First — chhota job pehle, minimum wait but burst time pata hona chahiye), Round Robin (har process ko fixed time slice, fair but context switching overhead)."

---

## What It Is NOT

⚠️ **Scheduling = sirf 3 algorithms nahi.** FCFS, SJF, Round Robin bas hain. Priority Scheduling, Multilevel Queue bhi hain — but basics ke liye ye kaafi hain.

⚠️ **SJF = practical mein mushkil hai.** Pata nahi hota ki process kitna time lega. Approximation use hoti hai (past behavior se predict).

⚠️ **Round Robin = hamesha best nahi.** Agar quantum bahut chhota ho toh context switching overhead zyada ho jaayega. Quantum size decide karna important hai.

## In Your Own Words

1. FCFS algorithm kya hai? Convoy effect kya hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** FCFS = pehle aaya pehle chala — jo process pehle ready queue mein aaya, pehle CPU milega. Convoy effect = agar ek lamba process (P1, 24 burst time) pehle aaya toh baaki chhote processes (P2, P3) uska wait karte hain. P2 ka wait time 24 ho jaata hai — even though uska burst sirf 3 hai.

</details>

2. Round Robin mein time quantum kya hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Time quantum = fixed time slice jo har process ko milta hai. Jaise quantum = 4, toh har process 4 units tak chalega, phir next process. Agar process 4 units mein complete ho gaya toh theek, nahi toh next process ko chance milta hai. Fair hai — sabko equal chance milta hai.

</details>

3. SJF minimum wait time deta hai — kyun?

<details>
<summary>Sample Jawab</summary>

**Jawab:** SJF chhote jobs pehle execute karta hai — jaise P2 (2 burst) → P4 (3 burst) → P1 (6 burst). Agar P1 pehle chalta toh P2, P4 sabka wait time badhta. SJF se chhote jobs jaldi complete hote hain, average wait time kam hota hai.

</details>
4. Node.js event loop ek scheduling algorithm jaisa kyun hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Event loop callbacks ko priority deti hai — microtasks (Promises) sabse pehle, phir setImmediate, phir setTimeout. Jaise CPU scheduler processes ko priority deta hai. Event loop decide karta hai kaunsa callback kab chalega — same as CPU scheduling.

</details>
