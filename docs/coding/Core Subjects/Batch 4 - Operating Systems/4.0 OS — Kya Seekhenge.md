Node.js is single-threaded — you know that. But `setTimeout`, `fs.readFile`, `fetch()` — how do all of these work in the background if it's single-threaded? Answer: **Event Loop** and **libuv thread pool**. These are OS concepts — processes, threads, scheduling.

OS isn't just "process vs thread" — memory management, deadlock, context switching — all of these relate to your daily Node.js work. But there's no need to go deep — just get the basics clear.

## What You'll Learn in This Batch

Five concepts, just the basics:

**A — Process vs Thread.** Node.js is single-threaded but has background threads. What's the difference between process and thread.

**B — Deadlock.** Two processes waiting for each other's resource, no one releasing — everyone stuck. This happens in real bugs too.

**C — Memory Management Basics.** Virtual memory, paging — how the OS decides which program uses how much memory.

**D — Process States + Context Switching.** What states a process goes through in its lifetime, and how the CPU switches.

**E — CPU Scheduling Algorithms.** How the OS decides which process runs on the CPU when — FCFS, SJF, Round Robin.
