**Problem:** Given an array of integers `nums` containing `n + 1` integers where each integer is in the range `[1, n]` inclusive.

There is only **one repeated number** in `nums`, return this repeated number.

You must solve the problem **without modifying** the array `nums` and uses only constant extra space.

**Link:** https://leetcode.com/problems/find-the-duplicate-number/

---

## What This Problem Is Asking (Simple Terms)

You have an array of `n + 1` integers, where each integer is between `1` and `n` (inclusive). Since there are `n + 1` elements but only `n` possible values, at least one value must repeat. You need to find that repeated number.

You cannot modify the array and can only use O(1) extra space.

For example, if `nums = [1,3,4,2,2]` (n=4, array has 5 elements), the number `2` appears twice.

---

## Example 1

**Input:** `nums = [1,3,4,2,2]`

**Output:** `2`

**Explanation:** `n = 4`, array has `n + 1 = 5` elements. The number `2` appears twice (indices 3 and 4).

---

## Example 2

**Input:** `nums = [3,1,3,4,2]`

**Output:** `3`

**Explanation:** `n = 4`, array has `n + 1 = 5` elements. The number `3` appears twice (indices 0 and 2).

---

## Example 3

**Input:** `nums = [1,1]`

**Output:** `1`

**Explanation:** `n = 1`, array has `n + 1 = 2` elements. The number `1` appears twice.

---

## Example 4

**Input:** `nums = [1,1,2]`

**Output:** `1`

**Explanation:** `n = 2`, array has `n + 1 = 3` elements. The number `1` appears twice (indices 0 and 1).

## Constraints

- `1 <= n <= 10^5`
- `nums.length == n + 1`
- `1 <= nums[i] <= n`
- All the integers in `nums` appear **only once** except for **precisely one integer** which appears **two or more times**.

**Follow-up:** How can we prove that at least one duplicate number must exist in `nums`? Can you solve the problem in linear time and O(1) space?

---

## Which Data Structure, and Why?

"Find duplicate in array with constraints (no modify, O(1) space)" → **Floyd's Cycle Detection** (treat array as linked list). Or binary search on answer (count numbers ≤ mid). Floyd's is most elegant: `nums[i]` points to index `nums[i]`, forming a linked list. A duplicate means a cycle → find cycle entry.

**Signal in the problem:** "find duplicate" + "no modify" + "O(1) space" → Floyd's cycle detection or binary search on answer.

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could check each element against every other element to find a duplicate.

### Brute Force Pseudocode

```
for i from 0 to n:
    for j from i+1 to n:
        if nums[i] == nums[j]: return nums[i]
return -1
```

### Why Brute Force Is Slow

O(n²) time — too slow for `n = 10^5`. Also O(1) space, which is fine, but the time is the problem.

---

## Why Floyd's Cycle Detection?

You can't use a HashSet (O(n) space violates the constraint). You can't modify the array (sorting or negation violates the constraint).

The key insight: treat the array as a **linked list**. Index `i` points to index `nums[i]`. A duplicate value means two indices point to the same index → a **cycle**.

**Signal in the problem:** "find duplicate" + "no modify" + "O(1) space" → Floyd's cycle detection or binary search on answer.

---

## Optimized Approach (Floyd's Cycle Detection — O(n) time, O(1) space)

Treat the array as a linked list: node `i` points to node `nums[i]`. A duplicate value means two nodes point to the same node → cycle. Find the cycle entry using Floyd's two-phase algorithm.

### Pseudocode

```
// Phase 1: find meeting point
slow = nums[0], fast = nums[0]
do:
    slow = nums[slow]
    fast = nums[nums[fast]]
while slow != fast

// Phase 2: find entry
slow = nums[0]
while slow != fast:
    slow = nums[slow]
    fast = nums[fast]
return slow
```

### Java Code

```java
class Solution {
    public int findDuplicate(int[] nums) {
        // Phase 1: find meeting point
        int slow = nums[0];
        int fast = nums[0];
        do {
            slow = nums[slow];
            fast = nums[nums[fast]];
        } while (slow != fast);

        // Phase 2: find entry
        slow = nums[0];
        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }
        return slow;
    }
}
```

### Line-by-line

- `slow = nums[0]`, `fast = nums[0]` — start at index 0 (value `nums[0]`).
- Phase 1: `slow = nums[slow]` (one step), `fast = nums[nums[fast]]` (two steps). They meet inside the cycle.
- Phase 2: reset `slow = nums[0]`. Advance both by 1 (`nums[slow]`, `nums[fast]`). They meet at the duplicate (cycle entry).
- Return `slow`.

## Complexity

- Time: O(n) — both phases are O(n).
- Space: O(1) — two pointers.

## Common Mistakes

- **Not handling the case where `nums[0]` is part of the cycle.** The algorithm handles this correctly because we start both at `nums[0]` and use a `do-while` (at least one iteration).
- **Using a HashSet.** Works (O(n) space) but violates the O(1) space constraint.
- **Modifying the array.** Sorting or negating values works but violates the "don't modify" constraint.
- **Confusing with "Find All Duplicates" (#442).** That problem allows O(n) space and modifying. This one doesn't.
- **Using `while` instead of `do-while` for Phase 1.** `slow` and `fast` start at the same point, so `while` would exit immediately.

## How to Explain (interview)

**Opening:** Find the Duplicate Number finds a duplicate in an array of n+1 integers in [1,n] with O(1) space and no modification. Treat the array as a linked list: index `i` → index `nums[i]`. A duplicate means a cycle. Floyd's cycle detection: Phase 1 finds the meeting point, Phase 2 finds the entry (the duplicate). O(n) time, O(1) space.

**The basic flow:**
```java
int slow = nums[0], fast = nums[0];
do { slow = nums[slow]; fast = nums[nums[fast]]; } while (slow != fast);
slow = nums[0];
while (slow != fast) { slow = nums[slow]; fast = nums[fast]; }
return slow;
```

**The part that trips everyone up:** the array is treated as a **linked list** (index → value → index). The duplicate creates a cycle. Phase 2 finds the cycle entry = the duplicate. Also, use `do-while` (not `while`) for Phase 1 because `slow` and `fast` start at the same point.

**The mistakes to remember:**
- Using HashSet (violates O(1) space)
- Modifying the array (violates constraint)
- Using `while` instead of `do-while` (infinite loop when they start equal)
- Confusing with "Find All Duplicates" (#442) (different constraints)
