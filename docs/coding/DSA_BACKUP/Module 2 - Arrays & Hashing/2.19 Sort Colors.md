**Problem:** Given an array `nums` with `n` objects colored red, white, or blue, sort them **in-place** so that objects of the same color are adjacent, with the colors in the order red, white, and blue.

We will use the integers `0`, `1`, and `2` to represent the color red, white, and blue, respectively.

You must solve this problem **without using the library's sort function**.

**Link:** https://leetcode.com/problems/sort-colors/

---

## What This Problem Is Asking (Simple Terms)

You have an array containing only `0`s, `1`s, and `2`s. You need to sort it **in-place** so that all `0`s come first, then all `1`s, then all `2`s.

For example, if `nums = [2,0,2,1,1,0]`, after sorting it becomes `[0,0,1,1,2,2]`.

You cannot use `Arrays.sort()` — you need an O(n) solution.

---

## Example 1

**Input:** `nums = [2,0,2,1,1,0]`

**Output:** `[0,0,1,1,2,2]`

**Explanation:** All 0s come first, then 1s, then 2s.

---

## Example 2

**Input:** `nums = [2,0,1]`

**Output:** `[0,1,2]`

---

## Constraints

- `n == nums.length`
- `1 <= n <= 300`
- `nums[i]` is either `0`, `1`, or `2`.

**Follow-up:** Could you come up with a one-pass algorithm using only constant extra space?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could count how many `0`s, `1`s, and `2`s there are, then overwrite the array: first all `0`s, then all `1`s, then all `2`s.

### Brute Force Pseudocode

```
count0 = 0, count1 = 0, count2 = 0
for each x in nums:
    if x == 0: count0++
    else if x == 1: count1++
    else: count2++
i = 0
while count0 > 0: nums[i++] = 0; count0--
while count1 > 0: nums[i++] = 1; count1--
while count2 > 0: nums[i++] = 2; count2--
```

### Why Brute Force Is Not Optimal

Counting sort is O(n) time and O(1) space (fixed 3 counters), which is already good. But it makes **two passes** over the array (one to count, one to overwrite).

---

## Which Data Structure/Technique, and Why?

The array contains only **3 distinct values** (`0`, `1`, `2`). You can count how many of each exist, then rewrite the array in order.

- **Counting sort** (this module): Count each value, then overwrite the array in order. O(n) time, O(1) space (3 counters). Fits "arrays & hashing" because you're counting frequencies into a fixed-size array of 3.

- **Dutch National Flag** (Module 3 - Two Pointers): A three-pointer approach that sorts in one pass by swapping elements in place. Uses `low`, `mid`, `high` pointers instead of counting.

Both are valid. Since this module is about arrays and hashing (counting and remembering what you've seen), **counting sort is the natural fit here**.

**Signal in the problem:** "sort 0s, 1s, 2s in place" / "only 3 distinct values" → count each value, then overwrite in order.

---

## Optimized Approach (Counting Sort — Two Passes)

Count how many `0`s, `1`s, and `2`s exist, then overwrite the array: first all `0`s, then all `1`s, then all `2`s.

### Pseudocode

```
count0 = 0, count1 = 0, count2 = 0
for each x in nums:
    if x == 0: count0++
    else if x == 1: count1++
    else: count2++
i = 0
while count0 > 0: nums[i++] = 0; count0--
while count1 > 0: nums[i++] = 1; count1--
while count2 > 0: nums[i++] = 2; count2--
```

### Java Code

```java
class Solution {
    public void sortColors(int[] nums) {
        int count0 = 0, count1 = 0, count2 = 0;
        for (int x : nums) {
            if (x == 0) count0++;
            else if (x == 1) count1++;
            else count2++;
        }
        int i = 0;
        while (count0-- > 0) nums[i++] = 0;
        while (count1-- > 0) nums[i++] = 1;
        while (count2-- > 0) nums[i++] = 2;
    }
}
```

### Line-by-line

- `count0`, `count1`, `count2` — three counters, one per value.
- First loop counts how many of each value exist.
- Second section writes `count0` zeros, then `count1` ones, then `count2` twos — overwriting the array in sorted order.

## Complexity

- Time: O(n) — two passes (one to count, one to overwrite).
- Space: O(1) — three integer counters.

## Common Mistakes

- **Using `Arrays.sort()`** — O(n log n), slower than O(n). Works but not optimal.
- **Forgetting that `nums` only has 3 values** — counting sort with 3 counters only works because there are exactly 3 possible values.
- **Assuming the array order must be preserved** — this problem sorts in place, so order is intentionally changed.

## How to Explain (interview)

**Opening:** Sort Colors sorts an array of 0s, 1s, and 2s in place. Since there are only 3 distinct values, I count how many of each exist, then overwrite the array: first all 0s, then all 1s, then all 2s. O(n) time, O(1) space (3 counters).

**The basic flow:**
```java
int count0 = 0, count1 = 0, count2 = 0;
for (int x : nums) {
    if (x == 0) count0++;
    else if (x == 1) count1++;
    else count2++;
}
int i = 0;
while (count0-- > 0) nums[i++] = 0;
while (count1-- > 0) nums[i++] = 1;
while (count2-- > 0) nums[i++] = 2;
```

**The part that trips everyone up:** noticing that with only 3 possible values, counting is simpler than comparing. Some people default to `Arrays.sort()` (O(n log n)) without realizing 3 values means O(n) counting is possible.

**The mistakes to remember:**
- Using `Arrays.sort()` (O(n log n)) when O(n) is expected
- Not recognizing that only 3 distinct values exist
- Forgetting that this modifies the array in place (void return)

**Note:** There's also a one-pass **Dutch National Flag** approach using three pointers (`low`, `mid`, `high`), but that belongs to the **Two Pointers** pattern (Module 3), not this one. Both solve the same problem; counting sort fits this module because it's fundamentally about counting values.
