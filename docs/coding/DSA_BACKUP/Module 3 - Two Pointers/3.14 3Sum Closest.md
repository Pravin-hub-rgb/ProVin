**Problem:** Given an integer array `nums` of length `n` and an integer `target`, find three integers in `nums` such that the sum is closest to `target`.

Return the sum of the three integers.

You may assume that each input would have exactly one solution. (LeetCode #16)

**Link:** https://leetcode.com/problems/3sum-closest/

---

## What This Problem Is Asking (Simple Terms)

You have an array of integers and a target number. You need to find **three numbers** whose sum is closest to the target (not necessarily equal). Return the sum of those three numbers.

For example, `nums = [-1,2,1,-4]`, `target = 1`. The sum closest to 1 is `2` (-1 + 2 + 1 = 2).

You return the sum value, not the indices.

---

## Example 1

**Input:** `nums = [-1,2,1,-4]`, `target = 1`

**Output:** `2`

**Explanation:** The sum that is closest to the target is 2. (-1 + 2 + 1 = 2).

---

## Example 2

**Input:** `nums = [0,0,0]`, `target = 1`

**Output:** `0`

**Explanation:** The sum that is closest to the target is 0. (0 + 0 + 0 = 0).

---

## Constraints

- `3 <= nums.length <= 10^3`
- `-1000 <= nums[i] <= 1000`
- `-10^4 <= target <= 10^4`

**Follow-up:** Could you solve it in O(n²) time complexity?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could check every possible triplet, compute its sum, and track which sum is closest to target (smallest absolute difference).

### Brute Force Pseudocode

```
closest = infinity
for i from 0 to n-3:
    for j from i+1 to n-2:
        for k from j+1 to n-1:
            sum = nums[i] + nums[j] + nums[k]
            if abs(sum - target) < abs(closest - target):
                closest = sum
return closest
```

### Why Brute Force Is Slow

Three nested loops → O(n³). For `n = 10^3`, that's `10^9` operations — too slow.

---

## Which Data Structure/Technique, and Why?

"3 numbers closest to target" → **Sort + Two Pointers**. Sort the array. Fix one element, use two pointers on the rest to find the pair closest to `target - nums[i]`. Track the closest sum. O(n²) time, O(1) space (or O(log n) for sort).

**Signal in the problem:** "3Sum closest" / "closest to target" → sort + fix one + two pointers, track closest.

---

## Optimized Approach (Sort + Fix One + Two Pointers)

Sort. For each `i`, two pointers (`left = i+1`, `right = n-1`) on the rest. Compute sum. If sum == target, return immediately (can't get closer). If sum < target, `left++` (need bigger). If sum > target, `right--` (need smaller). Track the closest sum (min absolute difference).

### Pseudocode

```
sort nums
closest = infinity
for i from 0 to n-3:
    left = i + 1, right = n - 1
    while left < right:
        sum = nums[i] + nums[left] + nums[right]
        if sum == target: return sum
        if abs(sum - target) < abs(closest - target): closest = sum
        if sum < target: left++
        else: right--
return closest
```

### Java Code

```java
class Solution {
    public int threeSumClosest(int[] nums, int target) {
        Arrays.sort(nums);
        int n = nums.length;
        int closest = nums[0] + nums[1] + nums[2];

        for (int i = 0; i < n - 2; i++) {
            int left = i + 1, right = n - 1;
            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                if (sum == target) return sum;
                if (Math.abs(sum - target) < Math.abs(closest - target)) {
                    closest = sum;
                }
                if (sum < target) left++;
                else right--;
            }
        }
        return closest;
    }
}
```

### Line-by-line

- `Arrays.sort(nums)` — enables two pointers.
- `closest = nums[0] + nums[1] + nums[2]` — initial closest sum (first triplet).
- `left = i + 1, right = n - 1` — two pointers for the remaining pair.
- `sum == target` → return immediately (can't get closer).
- `Math.abs(sum - target) < Math.abs(closest - target)` → update closest if this sum is closer.
- `sum < target` → need bigger sum → `left++`.
- `sum > target` → need smaller sum → `right--`.

## Complexity

- Time: O(n²) — sort O(n log n), outer loop O(n), inner two-pointer O(n).
- Space: O(1) extra (excluding sort's internal space).

## Common Mistakes

- **Not sorting first** — two pointers requires sorted input.
- **Not initializing `closest` properly** — use the first triplet sum as initial value.
- **Not returning immediately when `sum == target`** — can't get closer than exact match.
- **Using `Math.abs(closest - target)` incorrectly** — compare absolute differences, not raw differences.

## How to Explain (interview)

**Opening:** 3Sum Closest finds three numbers whose sum is closest to a target. Sort the array, fix one element, then use two pointers to find pairs summing closest to `target - nums[i]`. Track the closest sum (min absolute difference). O(n²) time, O(1) extra space.

**The part that trips everyone up:** returning immediately when `sum == target` (can't get closer). Also, tracking closest by absolute difference, not raw difference.

**The mistakes to remember:**
- Not sorting first
- Not returning immediately on exact match
- Comparing raw difference instead of absolute difference
- Not initializing `closest` with a valid triplet sum
