**Problem:** Given `n` non-negative integers representing an elevation map where the width of each bar is 1, compute how much water it can trap after raining. (LeetCode #42)

**Link:** https://leetcode.com/problems/trapping-rain-water/

---

## What This Problem Is Asking (Simple Terms)

You have an array of bar heights. After it rains, water gets trapped between the bars. You need to compute the total amount of water trapped.

Water can be trapped at position `i` if there are taller bars on both left and right sides. The water level at position `i` is `min(maxLeft[i], maxRight[i])` — the shorter of the two tallest bars on either side. The actual water trapped at `i` is `waterLevel[i] - height[i]` (if positive).

For example, `height = [0,1,0,2,1,0,1,3,2,1,2,1]` traps 6 units of water.

---

## Example 1

**Input:** `height = [0,1,0,2,1,0,1,3,2,1,2,1]`

**Output:** `6`

**Explanation:** The elevation map traps 6 units of water: 1 unit at index 2, 1 at index 4, 2 at index 5, 1 at index 7, 1 at index 8.

---

## Example 2

**Input:** `height = [4,2,0,3,2,5]`

**Output:** `9`

**Explanation:** The elevation map traps 9 units of water.

---

## Constraints

- `n == height.length`
- `1 <= n <= 2 * 10^4`
- `0 <= height[i] <= 10^5`

**Follow-up:** Could you solve it in O(n) time and O(1) space?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

For each position `i`, find the tallest bar to its left (`maxLeft`) and tallest bar to its right (`maxRight`). Water at `i` = `min(maxLeft, maxRight) - height[i]` (if positive). Sum all water amounts.

### Brute Force Pseudocode

```
total = 0
for i from 0 to n-1:
    maxLeft = max(height[0..i])
    maxRight = max(height[i..n-1])
    water = min(maxLeft, maxRight) - height[i]
    if water > 0: total += water
return total
```

### Why Brute Force Is Slow

For each position `i`, finding `maxLeft` and `maxRight` takes O(n). Total: O(n²) — too slow for `n = 2 * 10^4`.

---

## Which Data Structure/Technique, and Why?

"Trapping rain water" → **Two Pointers (converging)**. Water at position `i` = `min(maxLeft, maxRight) - height[i]`. Instead of precomputing `maxLeft` and `maxRight` arrays (O(n) space), use two pointers from both ends, tracking the running max from each side. Move the pointer with the smaller max. O(n) time, O(1) space.

**Signal in the problem:** "trapping rain water" / "water trapped between bars" → two pointers with running max from both sides.

---

## Optimized Approach (Two Pointers with Running Max)

Two pointers: `left = 0`, `right = n-1`. Track `leftMax` and `rightMax`. If `height[left] < height[right]`: water at left = `leftMax - height[left]` (leftMax is the bottleneck), update `leftMax`, `left++`. Else: water at right = `rightMax - height[right]`, update `rightMax`, `right--`.

**Why move the smaller side?** The water level at a position is determined by `min(maxLeft, maxRight)`. If `height[left] < height[right]`, we know `leftMax` (the max from left up to `left`) is ≤ `height[right]` (since `leftMax ≤ height[left] < height[right]`), and since `rightMax ≥ height[right]`, we know `leftMax ≤ rightMax`. So the water at `left` is bounded by `leftMax`, which we already know. We can safely compute and move `left`.

### Pseudocode

```
left = 0, right = n - 1
leftMax = 0, rightMax = 0
total = 0
while left < right:
    if height[left] < height[right]:
        if height[left] >= leftMax: leftMax = height[left]
        else: total += leftMax - height[left]
        left++
    else:
        if height[right] >= rightMax: rightMax = height[right]
        else: total += rightMax - height[right]
        right--
return total
```

### Java Code

```java
class Solution {
    public int trap(int[] height) {
        int left = 0, right = height.length - 1;
        int leftMax = 0, rightMax = 0;
        int total = 0;

        while (left < right) {
            if (height[left] < height[right]) {
                if (height[left] >= leftMax) {
                    leftMax = height[left];
                } else {
                    total += leftMax - height[left];
                }
                left++;
            } else {
                if (height[right] >= rightMax) {
                    rightMax = height[right];
                } else {
                    total += rightMax - height[right];
                }
                right--;
            }
        }
        return total;
    }
}
```

### Line-by-line

- `left = 0, right = height.length - 1` — pointers at both ends.
- `leftMax = 0, rightMax = 0` — running max from each side.
- `if height[left] < height[right]` — process the side with the smaller bar (the bottleneck).
- `if height[left] >= leftMax` — new max from left, update it (no water trapped at this bar).
- `else` — water trapped at left = `leftMax - height[left]`.
- `left++` / `right--` — move the processed pointer inward.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — four variables.

## Common Mistakes

- **Precomputing maxLeft/maxRight arrays** — O(n) space, not needed.
- **Moving the wrong pointer** — always move the side with the smaller bar (the bottleneck).
- **Using `>` instead of `>=`** when updating max — if `height[left] == leftMax`, no water trapped, update is fine either way.
- **Off-by-one** — `while left < right`, stop when they meet.

## How to Explain (interview)

**Opening:** Trapping Rain Water computes water trapped between bars after rain. Water at position `i` = `min(maxLeft, maxRight) - height[i]`. Instead of precomputing max arrays (O(n) space), use two pointers from both ends with running maxes. Move the pointer with the smaller bar (the bottleneck). O(n) time, O(1) space.

**The basic flow:**
```java
int left = 0, right = height.length - 1;
int leftMax = 0, rightMax = 0;
int total = 0;
while (left < right) {
    if (height[left] < height[right]) {
        if (height[left] >= leftMax) leftMax = height[left];
        else total += leftMax - height[left];
        left++;
    } else {
        if (height[right] >= rightMax) rightMax = height[right];
        else total += rightMax - height[right];
        right--;
    }
}
return total;
```

**The part that trips everyone up:** understanding why moving the smaller side is correct — because `leftMax ≤ height[left] < height[right] ≤ rightMax`, so `leftMax` is the binding constraint for the left position.

**The mistakes to remember:**
- Precomputing max arrays (O(n) space)
- Moving the wrong pointer
- Off-by-one in while condition
