**Problem:** Given an array `nums` of `n` integers, return an array of all the **unique quadruplets** `[nums[a], nums[b], nums[c], nums[d]]` such that:

- `0 <= a, b, c, d < n`
- `a`, `b`, `c`, and `d` are distinct.
- `nums[a] + nums[b] + nums[c] + nums[d] == target`

You may return the answer in any order. (LeetCode #18)

**Link:** https://leetcode.com/problems/4sum/

---

## What This Problem Is Asking (Simple Terms)

You have an array of integers. You need to find all unique groups of **four numbers** that add up to a target value.

For example, if `nums = [1,0,-1,0,-2,2]` and `target = 0`, the quadruplets are `[-2,-1,1,2]`, `[-2,0,0,2]`, and `[-1,0,0,1]`.

You are not asked to return indices — just the values. And you must not return duplicate quadruplets (same four numbers in different order counts as one).

---

## Example 1

**Input:** `nums = [1,0,-1,0,-2,2]`, `target = 0`

**Output:** `[[-2,-1,1,2],[-2,0,0,2],[-1,0,0,1]]`

**Explanation:** The three unique quadruplets that sum to 0.

---

## Example 2

**Input:** `nums = [2,2,2,2,2]`, `target = 8`

**Output:** `[[2,2,2,2]]`

**Explanation:** The only quadruplet is all four 2s.

---

## Constraints

- `1 <= nums.length <= 200`
- `-10^9 <= nums[i] <= 10^9`
- `-10^9 <= target <= 10^9`

**Follow-up:** Could you solve it in O(n³) time complexity?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could check every possible quadruplet (i, j, k, l), compute their sum, and keep those that equal target. Then remove duplicates.

### Brute Force Pseudocode

```
result = empty set of quadruplets
for a from 0 to n-4:
    for b from a+1 to n-3:
        for c from b+1 to n-2:
            for d from c+1 to n-1:
                if nums[a] + nums[b] + nums[c] + nums[d] == target:
                    add sorted([nums[a], nums[b], nums[c], nums[d]]) to result
return result as list
```

### Why Brute Force Is Slow

Four nested loops → O(n⁴). For `n = 200`, that's `1.6 * 10^9` operations — way too slow.

---

## Which Data Structure/Technique, and Why?

"Find all unique quadruplets summing to target" → **Two Pointers (nested)**. Sort the array. Fix two elements (`i`, `j`), then use two pointers (`left`, `right`) on the rest to find pairs summing to `target - nums[i] - nums[j]`. Skip duplicates at all levels. O(n³) time, O(1) space.

**Signal in the problem:** "4Sum" / "k-sum" / "quadruplets summing to target" → sort + fix k-2 elements + two pointers.

---

## Optimized Approach (Sort + Fix Two + Two Pointers)

Sort the array. Two outer loops fix `nums[i]` and `nums[j]`. Inner two-pointer search for pair summing to `target - nums[i] - nums[j]`. Skip duplicates at `i`, `j`, `left`, `right`. Prune with early exit conditions.

### Pseudocode

```
sort nums
result = []
for i from 0 to n-4:
    if i > 0 and nums[i] == nums[i-1]: continue   // skip duplicate i
    if nums[i] + nums[i+1] + nums[i+2] + nums[i+3] > target: break   // smallest sum too big
    if nums[i] + nums[n-3] + nums[n-2] + nums[n-1] < target: continue  // largest sum too small
    for j from i+1 to n-3:
        if j > i+1 and nums[j] == nums[j-1]: continue   // skip duplicate j
        if nums[i] + nums[j] + nums[j+1] + nums[j+2] > target: break
        if nums[i] + nums[j] + nums[n-2] + nums[n-1] < target: continue
        left = j + 1, right = n - 1
        while left < right:
            sum = nums[i] + nums[j] + nums[left] + nums[right]
            if sum == target:
                result.add([nums[i], nums[j], nums[left], nums[right]])
                left++; right--
                while left < right and nums[left] == nums[left-1]: left++
                while left < right and nums[right] == nums[right+1]: right--
            else if sum < target: left++
            else: right--
return result
```

### Java Code

```java
class Solution {
    public List<List<Integer>> fourSum(int[] nums, int target) {
        List<List<Integer>> result = new ArrayList<>();
        Arrays.sort(nums);
        int n = nums.length;

        for (int i = 0; i < n - 3; i++) {
            if (i > 0 && nums[i] == nums[i - 1]) continue;
            if (nums[i] + nums[i+1] + nums[i+2] + nums[i+3] > target) break;
            if (nums[i] + nums[n-3] + nums[n-2] + nums[n-1] < target) continue;

            for (int j = i + 1; j < n - 2; j++) {
                if (j > i + 1 && nums[j] == nums[j - 1]) continue;
                if (nums[i] + nums[j] + nums[j+1] + nums[j+2] > target) break;
                if (nums[i] + nums[j] + nums[n-2] + nums[n-1] < target) continue;

                int left = j + 1, right = n - 1;
                while (left < right) {
                    long sum = (long)nums[i] + nums[j] + nums[left] + nums[right];
                    if (sum == target) {
                        result.add(Arrays.asList(nums[i], nums[j], nums[left], nums[right]));
                        left++; right--;
                        while (left < right && nums[left] == nums[left-1]) left++;
                        while (left < right && nums[right] == nums[right+1]) right--;
                    } else if (sum < target) {
                        left++;
                    } else {
                        right--;
                    }
                }
            }
        }
        return result;
    }
}
```

### Line-by-line

- `Arrays.sort(nums)` — enables two pointers and duplicate skipping.
- Outer loop `i` fixes the first element; inner loop `j` fixes the second.
- Duplicate skipping at `i` and `j` levels prevents duplicate quadruplets.
- Early pruning breaks/continues when the smallest/largest possible sums can't reach target.
- Inner two pointers (`left`, `right`) find pairs summing to `target - nums[i] - nums[j]`.
- `long sum` prevents integer overflow with large values.

## Complexity

- Time: O(n³) — two outer loops O(n²), inner two-pointer O(n).
- Space: O(1) extra (excluding output list).

## Common Mistakes

- **Not sorting first** — two pointers requires sorted input.
- **Not skipping duplicates** at all four levels (`i`, `j`, `left`, `right`).
- **Integer overflow** — use `long` for sum when values can be up to 10^9.
- **Off-by-one in loop bounds** — `i < n-3`, `j < n-2` ensure room for `left` and `right`.
- **Returning indices instead of values** — this problem wants values.
