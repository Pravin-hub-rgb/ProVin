**Problem:** Given a 1-indexed array of integers `numbers` that is already sorted in non-decreasing order, find two numbers such that they add up to a specific `target` number. Return the indices of the two numbers (1-indexed) as an integer array `[index1, index2]` of length 2. (LeetCode #167)

**Link:** https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/

---

## What This Problem Is Asking (Simple Terms)

You have a **sorted** array of integers and a target number. You need to find **two different positions** (indices) where the numbers at those positions add up to the target.

Because the array is sorted, you can use two pointers: one at the start (smallest value) and one at the end (largest value). If their sum is too small, move the left pointer up to get a bigger value. If their sum is too big, move the right pointer down to get a smaller value.

You return **1-based indices** (not 0-based), as the problem specifies.

---

## Example 1

**Input:** `numbers = [2,7,11,15]`, `target = 9`

**Output:** `[1,2]`

**Explanation:** The sum of `2` and `7` is `9`. Therefore index1 = 1, index2 = 2. Return `[1, 2]`.

**Output:** `[1,3]`

**Explanation:** The sum of `2` and `4` is `6`. Therefore index1 = 1, index2 = 3. Return `[1, 3]`.

## Constraints

- `2 <= numbers.length <= 3 * 10^4`
- `-1000 <= numbers[i] <= 1000`
- `-1000 <= target <= 1000`
- The tests are generated such that there is exactly one solution.
- You may not use the same element twice.

**Follow-up:** Can you solve it in O(n) time and O(1) extra space?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

For each element at index `i`, you scan the rest of the array looking for `target - numbers[i]`. This is a loop inside a loop → O(n²).

### Brute Force Pseudocode

```
for i from 0 to n-1:
    for j from i+1 to n-1:
        if numbers[i] + numbers[j] == target:
            return [i+1, j+1]  // 1-based
return []
```

### Why Brute Force Is Slow

Outer loop runs `n` times, inner loop runs up to `n` times. O(n²) — too slow for `n = 3 * 10^4`.

---

## Which Data Structure/Technique, and Why?

The array is **sorted**. Two Sum on a sorted array → **Two Pointers (converging)**. Start one pointer at each end; if the sum is too small, move left up (increase sum); if too big, move right down (decrease sum). O(n) time, O(1) space.

Why not a hash map (Module 2)? A hash map works too (O(n) time, O(n) space), but since the array is sorted, two pointers gives O(1) space and is the intended solution. The sorted property is the signal.

**Signal in the problem:** "sorted array" + "two numbers that sum to target" → two pointers from both ends. (Unsorted → hash map.)

---

## Optimized Approach (Two Pointers, Converging)

`left = 0`, `right = n-1`. While `left < right`: compute `sum = numbers[left] + numbers[right]`. If sum == target → return (1-based indices). If sum < target → left++ (need bigger). If sum > target → right-- (need smaller).

### Pseudocode

```
left = 0, right = n - 1
while left < right:
    sum = numbers[left] + numbers[right]
    if sum == target: return [left+1, right+1]
    if sum < target: left++
    else: right--
```

### Java Code

```java
class Solution {
    public int[] twoSum(int[] numbers, int target) {
        int left = 0, right = numbers.length - 1;

        while (left < right) {
            int sum = numbers[left] + numbers[right];
            if (sum == target) {
                return new int[]{left + 1, right + 1}; // 1-based
            } else if (sum < target) {
                left++;
            } else {
                right--;
            }
        }
        return new int[]{}; // shouldn't reach here
    }
}
```

### Line-by-line

- Pointers start at opposite ends — smallest + largest sum.
- `sum < target` → need a bigger sum → move `left` up (array is sorted, so `numbers[left+1] >= numbers[left]`).
- `sum > target` → need a smaller sum → move `right` down.
- Return 1-based indices (`left + 1`, `right + 1`) per problem spec.
- Each step eliminates one element → O(n) total.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — two pointers.

## Common Mistakes

- **Returning 0-based indices.** This problem wants 1-based. (Two Sum (Module 2) wants 0-based.) Read the spec.
- **Using a hash map** — works but uses O(n) space; two pointers is cleaner for sorted input.
- **Infinite loop:** if you forget to move a pointer when `sum == target` is handled by return, fine. But ensure `left++`/`right--` happen in the else branches.
- **Assuming duplicates are fine** — they are; the logic still works with duplicates.

## How to Explain (interview)

**Opening:** Two Sum II is Two Sum on a sorted array. Instead of a hash map (O(n) space), use two pointers: one at each end. If the sum is too small, move the left pointer up (bigger value); if too big, move the right pointer down (smaller value). O(n) time, O(1) space. Returns 1-based indices.

**The basic flow:**
```java
int left = 0, right = nums.length - 1;
while (left < right) {
    int sum = nums[left] + nums[right];
    if (sum == target) return new int[]{left + 1, right + 1};
    if (sum < target) left++; else right--;
}
```

**Trace on `[1, 2, 3, 6]`, target 5:** left at 1, right at 6 → sum 7, too big, right--. left at 1, right at 3 → sum 4, too small, left++. left at 2, right at 3 → sum 5, match → return `[3, 4]` (1-based). Each step eliminates one element.

**The part that trips everyone up:** the array is **sorted** (that's the whole point). And indices are **1-based** here, unlike Two Sum's 0-based.

**The mistakes to remember:**
- Returning 0-based instead of 1-based indices
- Using a hash map (works but wastes space when sorted)
- Forgetting to move a pointer (infinite loop)
