**Problem:** Given an integer array `nums`, return all the triplets `[nums[i], nums[j], nums[k]]` such that `i != j`, `i != k`, and `j != k`, and `nums[i] + nums[j] + nums[k] == 0`.

Notice that the solution set must not contain duplicate triplets. (LeetCode #15)

**Link:** https://leetcode.com/problems/3sum/

---

## What This Problem Is Asking (Simple Terms)

You have an array of integers. You need to find all unique groups of **three numbers** that add up to zero.

For example, if `nums = [-1,0,1,2,-1,-4]`, the triplets that sum to zero are `[-1,-1,2]` and `[-1,0,1]`.

You are not asked to return indices — just the values. And you must not return duplicate triplets (same three numbers in different order counts as one).

---

## Example 1

**Input:** `nums = [-1,0,1,2,-1,-4]`

**Output:** `[[-1,-1,2],[-1,0,1]]`

**Explanation:**
- `nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0`.
- `nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0`.
- `nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0`.
The distinct triplets are `[-1,0,1]` and `[-1,-1,2]`.

---

## Example 2

**Input:** `nums = [0,1,1]`

**Output:** `[]`

**Explanation:** The only possible triplet does not sum up to 0.

---

## Example 3

**Input:** `nums = [0,0,0]`

**Output:** `[[0,0,0]]`

**Explanation:** The only possible triplet sums up to 0.

---

## Constraints

- `3 <= nums.length <= 3000`
- `-10^5 <= nums[i] <= 10^5`

**Follow-up:** Could you solve it in O(n²) time complexity?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could check every possible triplet (i, j, k) where i < j < k, compute their sum, and keep those that equal zero. Then remove duplicates.

### Brute Force Pseudocode

```
result = empty set of triplets
for i from 0 to n-3:
    for j from i+1 to n-2:
        for k from j+1 to n-1:
            if nums[i] + nums[j] + nums[k] == 0:
                add sorted([nums[i], nums[j], nums[k]]) to result
return result as list
```

### Why Brute Force Is Slow

Three nested loops → O(n³). For `n = 3000`, that's `2.7 * 10^10` operations — way too slow.

---

## Which Data Structure/Technique, and Why?

3Sum = find i < j < k with `nums[i] + nums[j] + nums[k] == 0`.

Naive: three nested loops → O(n³). Better: **fix one element**, then solve Two Sum on the rest → O(n²). Since the rest needs to be searched for a pair summing to `-nums[i]`, and we want O(1) space, sort the array first, then use **Two Pointers** for the inner pair search.

**Signal in the problem:** "three numbers that sum to target" + "unique triplets" + "no duplicate results" → sort + fix one + two pointers. The "unique" requirement is the tricky part (skip duplicates).

---

## Optimized Approach (Sort + Fix One + Two Pointers)

1. Sort the array.
2. For each index `i` (the first element of the triplet):
   - Skip if `nums[i] == nums[i-1]` (avoid duplicate triplets).
   - If `nums[i] > 0`, break (sorted, so no more zero-sum triplets possible).
   - Use two pointers (`left = i+1`, `right = n-1`) to find pairs summing to `-nums[i]`.
   - Skip duplicates for `left` and `right` after finding a valid triplet.

### Pseudocode

```
sort nums
result = []
for i from 0 to n-3:
    if i > 0 and nums[i] == nums[i-1]: continue   // skip duplicate
    if nums[i] > 0: break                        // no more zero sums
    left = i + 1, right = n - 1
    while left < right:
        sum = nums[i] + nums[left] + nums[right]
        if sum == 0:
            result.add([nums[i], nums[left], nums[right]])
            left++; right--
            while left < right and nums[left] == nums[left-1]: left++
            while left < right and nums[right] == nums[right+1]: right--
        else if sum < 0: left++
        else: right--
return result
```

### Java Code

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        Arrays.sort(nums);

        for (int i = 0; i < nums.length - 2; i++) {
            if (i > 0 && nums[i] == nums[i - 1]) continue;  // skip duplicate
            if (nums[i] > 0) break;                          // sorted, no more

            int left = i + 1, right = nums.length - 1;
            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];
                if (sum == 0) {
                    result.add(Arrays.asList(nums[i], nums[left], nums[right]));
                    left++;
                    right--;
                    while (left < right && nums[left] == nums[left - 1]) left++;
                    while (left < right && nums[right] == nums[right + 1]) right--;
                } else if (sum < 0) {
                    left++;
                } else {
                    right--;
                }
            }
        }
        return result;
    }
}
```

### Line-by-line

- `Arrays.sort(nums)` — enables two pointers and duplicate skipping.
- `if (i > 0 && nums[i] == nums[i-1]) continue` — skip duplicate first elements.
- `if (nums[i] > 0) break` — sorted array, if first element is positive, all remaining sums are positive.
- `left = i + 1, right = nums.length - 1` — two pointers for the remaining pair.
- `sum == 0` → found a triplet; add it, move both pointers, skip duplicates.
- `sum < 0` → need bigger sum → move `left` up.
- `sum > 0` → need smaller sum → move `right` down.

## Complexity

- Time: O(n²) — sort is O(n log n), outer loop O(n), inner two-pointer O(n).
- Space: O(1) extra (excluding output list).

## Common Mistakes

- **Not sorting first** — two pointers requires sorted input.
- **Not skipping duplicates** — produces duplicate triplets in output.
- **Not breaking when `nums[i] > 0`** — wasted iterations on impossible sums.
- **Off-by-one in loop bounds** — `i < nums.length - 2` ensures room for `left` and `right`.
- **Returning indices instead of values** — this problem wants values, not indices (unlike Two Sum).

## How to Explain (interview)

**Opening:** 3Sum asks for all unique triplets that sum to zero. The naive approach checks all triplets — O(n³). The optimized approach sorts the array, fixes one element, then uses two pointers to find pairs summing to `-nums[i]`. O(n²) time, O(1) extra space. The key challenge is skipping duplicates to avoid repeated triplets.

**The basic flow:**
```java
Arrays.sort(nums);
for (int i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] == nums[i - 1]) continue;
    int left = i + 1, right = nums.length - 1;
    while (left < right) {
        int sum = nums[i] + nums[left] + nums[right];
        if (sum == 0) { ... add, move both, skip duplicates ... }
        else if (sum < 0) left++;
        else right--;
    }
}
```

**The part that trips everyone up:** duplicate skipping. You must skip duplicate `i` values AND duplicate `left`/`right` values after finding a valid triplet. Also, `nums[i] > 0` break condition saves time on sorted arrays.

**The mistakes to remember:**
- Not sorting first
- Not skipping duplicate triplets
- Returning indices instead of values
- Off-by-one in loop bounds
