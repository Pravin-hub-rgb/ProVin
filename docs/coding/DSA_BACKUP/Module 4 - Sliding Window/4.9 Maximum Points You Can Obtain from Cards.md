**Problem:** There are several cards arranged in a row, and each card has an associated number of points. The points are given in the integer array `cardPoints`.

In one step, you can take one card from the beginning or from the end of the row. You have to take exactly `k` cards.

Your score is the sum of the points of the cards you have taken.

Given the integer array `cardPoints` and the integer `k`, return the maximum score you can obtain. (LeetCode #1423)

**Link:** https://leetcode.com/problems/maximum-points-you-can-obtain-from-cards/

---

## What This Problem Is Asking (Simple Terms)

You have an array of card points. You can take exactly `k` cards, but each time you can only take from the beginning or the end of the row. You want to maximize the total points.

For example, `cardPoints = [1,2,3,4,5,6,1]`, `k = 3` → take `[1,2,3]` from front (sum 6) or `[4,5,6]` from back (sum 15) or `[1,6,1]` mixed (sum 8) → max is `4+5+6=15`... wait, let me recalculate. Actually taking from back: `[1,6,1]`... no. Let me think again. `cardPoints = [1,2,3,4,5,6,1]`, `k = 3`. Take 3 cards from beginning: `[1,2,3]` = 6. Take 3 from end: `[5,6,1]` = 12. Take 2 from front, 1 from end: `[1,2,1]` = 4. Take 1 from front, 2 from end: `[1,6,1]` = 8. Max is 12.

You return just the max score, not the cards themselves.

---

## Example 1

**Input:** `cardPoints = [1,2,3,4,5,6,1]`, `k = 3`

**Output:** `12`

**Explanation:** Take the last 3 cards: `[5,6,1]` → sum = 12.

## Example 2

**Input:** `cardPoints = [2,2,2]`, `k = 2`

**Output:** `4`

**Explanation:** Any 2 cards sum to 4.

## Example 3

**Input:** `cardPoints = [9,7,7,7,7,7,7]`, `k = 1`

**Output:** `9`

**Explanation:** Take the first card (9) — better than taking the last (7).

## Constraints

- `1 <= cardPoints.length <= 10^5`
- `1 <= cardPoints[i] <= 10^4`
- `1 <= k <= cardPoints.length`

**Follow-up:** Could you solve it in O(n) time and O(1) space?

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could try every possible split: take `i` cards from front and `k-i` from back, for `i` from 0 to k. Compute the sum for each split.

### Brute Force Pseudocode

```
maxScore = 0
for i from 0 to k:
    sum = sum of first i cards + sum of last (k-i) cards
    maxScore = max(maxScore, sum)
return maxScore
```

### Why Brute Force Is Slow

O(k²) if you compute sums naively each time, or O(k) with prefix sums but k can be up to n = 10^5. Actually the brute force is O(k²) without prefix sums. With prefix sums it's O(k) which is fine. But the sliding window approach is cleaner.

---

## Which Data Structure/Technique, and Why?

"Maximum points taking k cards from beginning or end" → **Sliding Window**. Equivalent to: find the minimum sum subarray of length `n - k` (the cards you DON'T take), then subtract from total sum.

Total points - minimum subarray sum of length `n - k` = maximum points you can take.

**Signal in the problem:** "take k cards from beginning or end" → complement: leave `n-k` cards in the middle → sliding window of fixed size `n-k` to find minimum sum.

---

## Optimized Approach (Sliding Window — Fixed Size)

Total sum of all cards. Find minimum sum subarray of length `n - k`. Answer = total - minSum.

### Pseudocode

```
total = sum of all cards
windowSize = n - k
windowSum = sum of first windowSize cards
minSum = windowSum
for right from windowSize to n-1:
    windowSum += nums[right] - nums[right - windowSize]
    minSum = min(minSum, windowSum)
return total - minSum
```

### Java Code

```java
class Solution {
    public int maxScore(int[] cardPoints, int k) {
        int n = cardPoints.length;
        int total = 0;
        for (int x : cardPoints) total += x;

        int windowSize = n - k;
        int windowSum = 0;
        for (int i = 0; i < windowSize; i++) {
            windowSum += cardPoints[i];
        }
        int minSum = windowSum;

        for (int i = windowSize; i < n; i++) {
            windowSum += cardPoints[i] - cardPoints[i - windowSize];
            minSum = Math.min(minSum, windowSum);
        }
        return total - minSum;
    }
}
```

### Line-by-line

- `total = sum of all cards` — total points available.
- `windowSize = n - k` — cards you DON'T take (stay in the middle).
- `windowSum = sum of first windowSize cards` — initial window sum.
- `windowSum += cardPoints[i] - cardPoints[i - windowSize]` — slide window: add new, remove old.
- `minSum = Math.min(minSum, windowSum)` — track minimum window sum.
- `return total - minSum` — total minus cards left in middle = cards you take.

## Complexity

- Time: O(n) — single pass.
- Space: O(1) — few variables.

## Common Mistakes

- **Not handling `k == n`** — windowSize = 0, answer = total. Need to handle this edge case.
- **Confusing the direction** — you want to MINIMIZE the middle subarray, not maximize.
- **Window size off-by-one:** `n - k`, not `k`.

## How to Explain (interview)

**Opening:** Maximum Points You Can Obtain from Cards asks for max points taking k cards from beginning or end. Equivalent to: total sum minus minimum sum subarray of length `n-k` (cards left in middle). Sliding window of fixed size `n-k` finds the minimum sum. O(n) time, O(1) space.

**The basic flow:**
```java
int total = 0;
for (int x : cardPoints) total += x;
int windowSize = n - k;
int windowSum = 0;
for (int i = 0; i < windowSize; i++) windowSum += cardPoints[i];
int minSum = windowSum;
for (int i = windowSize; i < n; i++) {
    windowSum += cardPoints[i] - cardPoints[i - windowSize];
    minSum = Math.min(minSum, windowSum);
}
return total - minSum;
```

**The part that trips everyone up:** thinking about taking cards from the front/back directly. The trick is to think about what you DON'T take (the middle subarray) and minimize that instead.

**The mistakes to remember:**
- Not handling `k == n` (windowSize = 0)
- Maximizing instead of minimizing the middle subarray
- Window size is `n - k`, not `k`
