**Problem:** Given an array of positive integers `nums` and a positive integer `target`, return the minimal length of a subarray whose sum is greater than or equal to `target`. If there is no such subarray, return 0 instead. (LeetCode #209)

**Link:** https://leetcode.com/problems/minimum-size-subarray-sum/

---

## What This Problem Is Asking (Simple Terms)

You have an array of positive integers and a target sum. You need to find the **shortest contiguous subarray** whose sum is at least `target`. Return its length, or 0 if no such subarray exists.

For example, `nums = [2,3,1,2,4,3]`, `target = 7` → `[4,3]` has sum 7, length 2.

---

## Example 1

**Input:** `target = 7`, `nums = [2,3,1,2,4,3]`

**Output:** `2`

**Explanation:** The subarray `[4,3]` has the minimal length under the problem constraint.

---

## Example 2

**Input:** `target = 4`, `nums = [1,4,4]`

**Output:** `1`

**Explanation:** The subarray `[4]` has sum 4, length 1.

---

## Example 3

**Input:** `target = 11`, `nums = [1,1,1,1,1,1,1,1]`

**Output:** `0`

**Explanation:** No subarray sums to 11 or more.

---

## Constraints

- `1 <= target <= 10^9`
- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^5`

**Follow-up:** If you have figured out the O(n) solution, try coding another solution of which the time complexity is O(n log n).

---

## Brute Force Approach (The Simplest Way)

Before optimizing, think like a beginner: how would you solve this by hand?

You could check every possible subarray, compute its sum, and track the shortest one that meets the target.

### Brute Force Pseudocode

```
minLen = infinity
for i from 0 to n-1:
    sum = 0
    for j from i to n-1:
        sum += nums[j]
        if sum >= target:
            minLen = min(minLen, j - i + 1)
            break
return minLen if minLen != infinity else 0
```

### Why Brute Force Is Slow

O(n²) — too slow for n = 10^5.

---

## Which Data Structure/Technique, and Why?

"Minimum size subarray sum ≥ target" → **Sliding Window (variable size)**. Since all numbers are positive, the sum increases as we expand right and decreases as we shrink left. Maintain a window whose sum is ≥ target, then shrink to find the minimum.

**Signal in the problem:** "minimum size subarray" + "sum ≥ target" → sliding window with shrinking when valid.

---

## Optimized Approach (Sliding Window)

`left = 0`, `currentSum = 0`. Expand `right`; add `nums[right]` to sum. While sum ≥ target, update min length and shrink left (subtract `nums[left]`, left++).

### Pseudocode

```
left = 0, sum = 0, minLen = infinity
for right from 0 to n-1:
    sum += nums[right]
    while sum >= target:
        minLen = min(minLen, right - left + 1)
        sum -= nums[left]
        left++
return minLen if minLen != infinity else 0
```

### Java Code

```java
class Solution {
    public int minSubArrayLen(int target, int[] nums) {
        int left = 0, sum = 0, minLen = Integer.MAX_VALUE;

        for (int right = 0; right < nums.length; right++) {
            sum += nums[right];
            while (sum >= target) {
                minLen = Math.min(minLen, right - left + 1);
                sum -= nums[left];
                left++;
            }
        }
        return minLen == Integer.MAX_VALUE ? 0 : minLen;
    }
}
```

### Line-by-line

- `sum += nums[right]` — expand window to include current element.
- `while sum >= target` — window is valid, try to shrink from left to find shorter.
- `minLen = Math.min(minLen, right - left + 1)` — update shortest valid window.
- `sum -= nums[left]; left++` — shrink from left.
- Return 0 if no valid window found (`minLen` still infinity).

## Complexity

- Time: O(n) — each element enters and leaves the window at most once.
- Space: O(1) — three variables.

## Common Mistakes

- **Not using `while` instead of `if`** — after shrinking, sum might still be ≥ target; keep shrinking.
- **Forgetting to check `minLen == Integer.MAX_VALUE`** — return 0 if no valid subarray.
- **Window size off-by-one:** `right - left + 1`.
- **Assuming negative numbers** — sliding window works because all numbers are positive (sum only increases when expanding).

## How to Explain (interview)

**Opening:** Minimum Size Subarray Sum asks for the shortest contiguous subarray with sum ≥ target. Sliding window: expand right, add to sum; when sum ≥ target, shrink from left to find the shortest valid window. O(n) time because left and right each move at most n times.

**The basic flow:**
```java
int left = 0, sum = 0, minLen = Integer.MAX_VALUE;
for (int right = 0; right < nums.length; right++) {
    sum += nums[right];
    while (sum >= target) {
        minLen = Math.min(minLen, right - left + 1);
        sum -= nums[left];
        left++;
    }
}
return minLen == Integer.MAX_VALUE ? 0 : minLen;
```

**The part that trips everyone up:** using `while` instead of `if` for shrinking — after removing `nums[left]`, sum might still be ≥ target, so keep shrinking.

**The mistakes to remember:**
- Not checking `minLen == Integer.MAX_VALUE` (return 0 if none found)
- Window size is `right - left + 1`, not `right - left`
- Assuming array has negative numbers (sliding window only works with positive numbers)
