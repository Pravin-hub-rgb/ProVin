The last two files gave the LLM hands and two doors — RAG for your stored collection, tools for the live world. But one trip through the building answers one question and stops. The agent doesn't stop. It keeps taking trips until the job is done. Time to see the loop itself.

A **chatbot makes one trip.** You send a message, the controller maybe fetches something, the LLM writes a reply, done. One pass: input in, answer out. That's the whole shape.

An **agent makes many trips.** The LLM decides it needs a tool, the controller runs it, the result comes back, and the LLM decides again what to do next — and repeats until the whole job is finished. Same building, same floors, but the middle floor keeps running over and over. **Agentic AI** is just the name for AI systems built that way.

The loop, written as steps so you can see the rhythm: think → pick a tool → tool runs → look at the result → think again → ... → done. The LLM drives itself instead of waiting for you at every step. A chatbot answers once and stops; an agent can search, read what came back, search differently, run code, check the output, and only then reply.

The sharpest part is that the LLM doesn't plan everything upfront and then freeze. After each tool result it looks again and decides the next step, so if something fails it adapts — switch to a different API, try a different file, adjust the plan. That step-by-step looking and adjusting is the loop, and it keeps going until the LLM decides the job is done and gives you the final answer. One tool call isn't enough for a real job, and the agent knows it.

The brain, body, and hands picture from 3.1 is the same picture here, just running in a circle. The brain (LLM) thinks and decides what's needed, speaking its request. The body (controller) hears and moves. The hands (tools) reach into the outside world. The brain never uses a hand directly — it only speaks, and the body moves, and then the brain speaks again.

You've seen this on a tool you actually use: Kilo Code, the VS Code extension. It's an agent — it loops, reading files, editing code, running commands, looking at the results, and deciding what to do next, all through tool calls with the LLM deciding each step. The plan mode and code mode you've used are a smart design on top of that loop: plan mode mostly reads and thinks, then writes the plan as an md file; code mode follows that file while looping with tools. And you've spotted a real difference between agents: some plan first and then execute, and some just loop step by step, deciding as they go. Both are agents, just built differently. The plan file also helps with the context window — the plan survives even if the earlier chat gets cut or summarized.

The nots. An agent is *not* an LLM with tools baked in — the model ships as patterns; the application offers the toolbox and runs the loop; swap the tools, same LLM. An agent is *not* a different kind of AI — same pipeline, same circles, same LLM; just a wrapper with tools and a loop instead of a single reply. And an agent is *not* a chatbot that happens to call one tool — the loop, repeating until the job is done, is the whole difference.
