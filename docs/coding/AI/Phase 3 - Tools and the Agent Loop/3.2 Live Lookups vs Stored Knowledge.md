The last file gave the LLM hands: tools the controller uses on the LLM's request, one tool call at a time. But there's a question that comes up the moment you have both tools and RAG on the same floor: when you need outside information, which door do you use?

Two doors, and the split is about the source. **RAG is for your stored collection** — documents you loaded ahead of time, fingerprinted and waiting in the vector database. **Tools are for the live world** — things that change or that you never stored, like today's news, a GitHub repo's current state, or an API response. RAG searches your library; tools reach out to the world.

The contrast, side by side, so the line stays sharp. RAG fetches by meaning from a collection you prepared earlier: the controller fingerprints your question, matches it against stored fingerprints, and brings back the closest chunks. Tools fetch plain text straight from the source: the controller calls a web search or an API, and the result comes back un-fingerprinted, raw. RAG needs setup time — documents chopped and fingerprinted once. Tools need no setup — they just go get it now.

Your own reasoning settled this one, and it holds. A CRUD app's database is plain data — no fingerprints, no embeddings, nothing to do with RAG. Embeddings enter only when you add an AI search-by-meaning feature on top: keep the normal database, add a vector database beside it holding fingerprints of whatever text you want searchable by meaning. And live data — the internet, GitHub, an API — is never pre-fingerprinted; it arrives as plain text through tools. Two doors, one picture: RAG for your library, tools for the live world.

A few cases to test the split. "What's our company's leave policy?" — your stored documents, so RAG. "What's the latest commit on this repo?" — live, so a tool. "Summarize this PDF I uploaded" — your stored collection once it's loaded, so RAG. "What's the weather right now?" — live, so a tool. The question to ask is always: was this information prepared and stored ahead of time, or does it have to be fetched fresh?

One boundary worth keeping, so the map stays honest. RAG is not a search engine over the whole internet — classically it searches your own stored collection. And tools are not only for fetching: they can also do actions, like running code or saving a file. But for the information question, the split holds: stored collection versus live world.

The nots. RAG is *not* for live data — it searches fingerprints made ahead of time. Tools are *not* for your stored collection — they don't search fingerprints; they fetch plain text. And neither door is the LLM itself — both are jobs the controller performs with different hands, and the LLM only reads what comes back.
