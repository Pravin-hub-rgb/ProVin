The main diagram stopped at generative AI — deep learning's branch that creates new content instead of labeling it. Time for the zoomed-in diagram: what actually lives *inside* that circle.

Because "generative AI" isn't one model. It's a family — siblings that each generate a different *kind* of content. And one of those siblings is the model that everything you've used so far is built on: the LLM.

---

## The Generative AI Circle Up Close

Quick recap of what this circle is (file 1.3): **generative AI is deep learning built to create new content** — a paragraph nobody wrote, an image nobody took, a voice nobody recorded. It can do this because training taught it the patterns of its data so well that it can produce new examples that follow those patterns.

The zoomed-in diagram looks like this:

```
Generative AI
├── LLM            (text)
├── Image models   (images)
├── Audio models   (sound)
├── Music models   (songs)
└── Video models   (video)

[ multimodal ] = a property, not a circle
```

Five siblings, each a deep learning model trained on one kind of data to generate that kind of content. Let's take the structure notes first, then the star.

**Two placement calls on this diagram:**

1. **Coding models don't get their own circle.** Code is text — so a "coding model" is normally just an LLM trained heavily on code. It belongs inside the LLM circle, not beside it. The true siblings are the media generators: image, audio, music, video.
2. **Multimodal is not a container.** A model that handles several kinds at once — text *plus* images, say — is called **multimodal**, but that's a *property* a model can have, not a bigger circle holding the others. On the diagram, draw it as an overlap or a label underneath: "spans more than one."

(Also worth knowing: **audio** is the broad family — speech recognition, text-to-speech voices, sound effects. **Music** is the narrower branch focused on composing songs and melodies. You can draw them as two siblings or nest music inside audio; either way, music is the more specific one.)

---

## The LLM — Breaking Down the Name

Now the sibling chatbots and agents are built around: the **LLM**. Three words, one at a time.

- **Language** — it works with human language: words, sentences, and also code, since code is a kind of language too.
- **Model** — the trained result from file 1.2: the big file of parameters holding learned patterns.
- **Large** — two things are huge: the amount of text it trained on, and the number of parameters, often billions.

So: **an LLM — a large language model — is a very large deep learning model trained on text, that generates language by predicting what comes next.**

---

## What It Actually Does

Here's the whole trick, and it connects to something you already know from your phone: you type "I'm going to the" and the keyboard suggests "store". Predict the next word.

An LLM does exactly that — at scale. You give it a question, it predicts the first word of the answer, then the next, then the next, over and over until a full reply is assembled. That's all the fluent writing you see. Your own instinct from the start was right: **it predicts.** Everything else — summarizing, translating, writing code — is the same next-word prediction applied to different kinds of prompts.

Why is language *the* special one among the siblings? Because language is so flexible. Code, emails, essays, questions, recipes — all text. So one LLM can write code, answer questions, and summarize documents, all with the same single skill: predicting what comes next. That's why the LLM is the sibling that got famous, and the one chatbots and agents are wrapped around.

## Where Chatbots and Agents Sit

One rule for the diagram, because it's the most common drawing mistake: **chatbots and agents are not circles inside the LLM.**

The LLM is the *model*. Chatbots and agents are *applications wrapped around it* — products with screens, chat boxes, tool connections. If you want them on the diagram, draw them **outside as boxes touching the LLM circle**, with a label like "applications built on LLMs", and arrows pointing at the LLM they're built on.

Same for the arrow list you might want on the diagram. Besides chatbot and agent, the common LLM applications are:

- **Assistants** — voice assistants and coding assistants (chatbots tuned for a job)
- **Search and question-answering tools** — ask questions over documents or the web
- **Writing and summarizing tools** — email drafters, meeting summarizers
- **Translation tools**
- **Automation workflows** — the LLM is one step in a bigger process, like sorting incoming support tickets

Chatbot and agent are the two big ones; the rest are mostly flavors of those. Full detail on both — and the agent's *tools* — is the next file. Here we're just placing them: boxes outside, arrows in.

## What This Family Is NOT

- **The LLM is not the whole of generative AI.** It's one sibling — the text one. Image, audio, music, and video models sit beside it.
- **Multimodal is not a model type or a container.** It's a property: handling more than one kind of data. A multimodal model spans siblings; it doesn't hold them.
- **Generative AI does not "understand" or "imagine".** It generates by predicting patterns learned in training — impressive output, but the mechanism is still the next-piece prediction from this file.
- **A coding model is not a separate species.** Code is text — it's an LLM trained heavily on code.
