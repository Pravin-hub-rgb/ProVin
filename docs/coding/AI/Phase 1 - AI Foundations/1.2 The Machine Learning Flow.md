In the last file we settled the core idea: software that learns patterns from examples instead of following hand-written rules. But "the model learns from data" is still a black box. Where does the data go in? What comes out? Who actually uses it?

There's a fixed pipeline behind every AI system you've ever touched — chatbots, voice assistants, image generators, all of them run the same chain. Let's walk it end to end, one step at a time.

---

## The Pipeline — Six Steps

Here's the whole flow, start to finish:

```
data → training → model → testing → inference → application
```

1. **Data** — the raw material: text, images, audio, whatever the system will learn from.
2. **Training** — the process of showing the model that data and letting it adjust itself until it gets good at predicting.
3. **Model** — the finished result of training.
4. **Testing** — checking the model on test data it never saw.
5. **Inference** — using the finished model on brand-new input.
6. **Application** — the product wrapped around the model that real people use.

That's the map. Now each step properly, because two of these words — *training* and *inference* — get mixed up constantly, and one more, *model*, is the single most important word in this whole course.

---

## Data and Training

**Data** is just the raw stuff: the pile of books, websites, and code for a language model; the labeled photos for an image model; the spam emails from the last file. Nothing is smart about it yet — it's the raw material.

**Training** is the factory process. The algorithm goes through the data over and over, adjusting its internal settings a little each time, until its predictions stop being wrong. When people say a model was "trained on the entire internet," that's what they mean — this process ran on an enormous pile of text.

Remember from the last file: training happens on **training data** (the seen, in-sample part).

---

## The Model

**A model is the trained result: a big file full of numbers that captures the patterns learned from data.**

That's the definition. A few consequences of it, because this word carries so much weight:

- **You give it an input, it uses those numbers to predict an output.** A question goes in, an answer comes out.
- **It doesn't look anything up.** There's no database inside, no internet connection at answer time. Only the patterns.
- **It doesn't hold the original data either.** The books it trained on are gone — what remains are the numbers that pattern left behind.

Those numbers have a name: **parameters**. When someone says "this model has 70 billion parameters," that's literally how many numbers are inside the file. More parameters → more capacity to hold complex patterns (and a bigger, hungrier model).

**Quick check:** you ask a chatbot a question — where does its answer come from, the original training data or the parameters?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The parameters. Training processed the original data once and distilled it into patterns stored as numbers; the data itself is not inside the model. At answer time the model only runs those numbers against your input — it never retrieves a book or searches anything. That's also why it can sound confident about things it "knows" without being able to check.

</details>

---

## Testing — Before Anyone Uses It

Once training finishes, **testing** checks the model on test data it never touched — the out-of-sample pile from the last file. High scores on training data plus high scores on test data means it learned patterns. Great on training, bad on testing → overfitting, scrap or retrain.

Testing sits *right after* training and *before* the model goes anywhere near real users. It's a quality gate, not part of daily use.

---

## Inference — Using the Finished Model

Here's the word people confuse with training most often. **Inference is what happens when a finished, trained model is used to make a prediction on new input.**

Every time you type a message into a chatbot and get a reply, the model is doing inference: new input goes in, a prediction comes out. Take a photo and your phone finds the faces? Inference. Spam filter judging an incoming email? Inference.

Two properties worth locking in:

- **Inference is *using* the model; training is *building* it.** Training is heavy, slow, expensive — done rarely, in a factory. Inference is light, fast, repeated constantly — the engine running.
- **Inference is not testing.** Testing is a one-time quality check on held-back data before release. Inference is the model doing its actual job, on live input, forever after.

**Quick check:** in your own words, what's the difference between training and inference?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Training is building the model — the factory pass where it adjusts its parameters on training data until predictions get good. It's slow, expensive, and happens once (or a few times). Inference is using the finished model — feeding it brand-new input and getting a prediction back, like every chatbot reply. Testing sits between them: a one-time check on unseen data before the model ships. Build it → check it → run it.

</details>

## Application — The Product Around the Model

The last step: **application** is the product wrapped around the model — the thing with a screen, a microphone, a chat box.

A raw model is just a file that predicts. Nobody talks to a file. So something gets built around it:

- a **chatbot** — a chat window where your message goes to the model and the reply comes back
- a **voice assistant** — the same idea, with speech converted in and out
- an **agent** — a product that can also *do things*, not just reply (we'll get to this properly in a later file)

Your endpoint question from the learning notes has a clean answer: **the endpoint of AI is a prediction** — an output. What differs between a chatbot, a voice assistant, and an agent is just *what kind* of output and *what wraps around* it.

And one bonus word you'll hear constantly: **production**. Application is the product itself; production is that product running in the real world with real users hitting it. "It works in dev but not in production" — same word, same meaning as anywhere else in software.

---

## Full Chain, One Line

```
data → training → model → testing → inference → application
      (builds)   (result) (check)   (use it)   (product)
```

Data feeds training, training builds the model, testing checks it on unseen data, inference does the predicting on live input, and the application is the product wrapped around it all. Artificial intelligence, end to end: human-made software that mimics human-like thinking by learning patterns from examples.

---

## What This Pipeline Is NOT

- **Training is not something that happens when you chat.** Typing to a chatbot only triggers inference. Your messages are not silently "teaching" the model (at least not in any immediate way).
- **The model is not a program in the usual sense.** No if-else logic inside — a file of parameters plus math that turns input into a prediction.
- **Inference is not searching.** New input in, prediction out — no lookup table, no web fetch (unless an *application* around the model adds one; again, later).
- **The application is not the AI itself.** It's the wrapper. The AI — the learning, the patterns — lives in the model produced by the pipeline.
