Last time settled the idea — learn patterns from examples — but you stopped on a fair complaint: terms one by one with no proper flow, no place for any of them to sit. So here's the whole chain first, then each link: every AI word you'll ever hear has a slot in this pipeline.

```
data → training → model → testing → inference → application
```

**Data** is the raw material: text, images, audio — whatever the system will learn from. Nothing smart about it yet.

**Training** is the factory process: the algorithm goes through the data over and over, adjusting its internal settings a little each time, until its predictions stop being wrong. When people say a model was "trained on the entire internet," that's what they mean — this process ran on an enormous pile of text. It runs on the training data — the seen, in-sample part from last time.

**The model** is the trained result: a big file full of numbers that captures the patterns learned from data. You give it an input, it uses those numbers to predict an output. A few consequences worth holding, because this word carries so much weight. It doesn't look anything up — no database inside, no internet at answer time; only the patterns. It doesn't hold the original data either — the books it trained on are gone; what remains are the numbers those patterns left behind. And those numbers have a name: **parameters**. "This model has 70 billion parameters" literally means 70 billion numbers inside the file. More parameters, more capacity for complex patterns — and a bigger, hungrier model.

So where does a question to a chatbot come from — the original training data or the parameters? The parameters. Training distilled the data into patterns stored as numbers; the data itself isn't inside. The model only runs those numbers against your input. (That's also why it can sound confident about things it "knows" without being able to check.)

**Testing** comes right after training: a quality gate on test data the model never touched. High on training *and* high on testing → it learned patterns. Great on training, bad on testing → overfitting, scrap or retrain. It sits before the model goes anywhere near real users.

**Inference** is the word people confuse with training most often: **using the finished model to make a prediction on new input.** Every message to a chatbot that gets a reply — inference. Face detection on a photo — inference. Spam filter judging an incoming email — inference.

The distinction to lock: training is *building* the model — heavy, slow, expensive, done rarely. Inference is *running* it — light, fast, repeated constantly. And inference is not testing: testing is the one-time check on held-back data before release; inference is the model doing its actual job, on live input, forever after. You once tangled these — training and testing aren't the same thing, and "interference" is really *inference*: a different step again, not about checking, about using.

**Application** is the last step: the product wrapped around the model — the thing with a screen, a microphone, a chat box. A raw model is just a file that predicts, and nobody talks to a file. So something gets built around it: a chatbot (chat window, your message to the model, reply back), a voice assistant (same, with speech in and out), an agent (a product that can also *do things* — we'll get to this properly in a later file). The endpoint of AI is a prediction — an output. What differs between chatbot, voice, and agent is just what kind of output and what wraps around it.

And one bonus word you'll hear constantly: **production**. Application is the product itself; production is that product running in the real world with real users hitting it. "Works in dev but not in production" — same word, same meaning as anywhere else in software.

Full chain, one line:

```
data → training → model → testing → inference → application
      (builds)   (result) (check)   (use it)   (product)
```

Data feeds training, training builds the model, testing checks it on unseen data, inference predicts on live input, the application is the product wrapped around it all. Artificial intelligence, end to end.

The nots: training is *not* something that happens when you chat — typing to a chatbot only triggers inference; your messages aren't silently teaching the model. The model is *not* a program in the usual sense — no if-else inside; a file of parameters plus math. Inference is *not* searching — new input in, prediction out. And the application is *not* the AI itself — it's the wrapper; the learning lives in the model the pipeline produced.
