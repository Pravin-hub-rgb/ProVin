## Chatbot — The Simplest Wrapper

**A chatbot is a chat window where you type a message, and the LLM writes a reply.** That's the entire idea.

Step by step:

1. You type a message into the chat window.
2. The app sends it to the LLM.
3. The LLM predicts a reply, word by word (the next-word machine from file 1.4).
4. The app shows the reply to you.

One detail explains the "memory" illusion: **the app keeps your earlier messages and sends them along with each new one.** The LLM itself isn't recalling anything between turns — every request arrives as one big prompt containing the conversation so far. It *seems* to remember because the wrapper does the remembering.

A **voice assistant** is the same wrapper with two extra stages: speech converted to text on the way in, text converted to speech on the way out. Same LLM, same prediction.

**Quick check:** why does a chatbot "remember" the conversation?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Because the application around the LLM keeps the earlier messages and includes them in every request it sends. The LLM itself is stateless — each reply is just prediction on whatever input it receives. The wrapper stitches the history in, so the model appears to remember.

</details>

## Agent — A Wrapper That Takes Actions

**An agent is also a wrapper around an LLM, with one big difference: it can take actions, not just reply with text.**

The contrast, one line each:

- **A chatbot only talks.** Output = words.
- **An agent can do.** Search the web, run code, open a file, call an API — then use the result to decide what to do next.

Where do these abilities come from? One word: **tools**.

**Tools are the individual abilities you give an agent** — web search, file editing, code execution, API calls. The agent app *offers* the tools to the LLM; the LLM decides which tool to use and when; the tool does the action; the result goes back to the LLM so it can decide the next step.

So counting tools works exactly like you'd expect: one agent might have five tools, another six — the sixth being, say, web surfing, which lets it do one more *kind* of action.

One placement rule, same spirit as the diagram: **the tools are not inside the LLM itself.** The LLM comes with its patterns; the application hands it a toolbox and asks "which one?" The model chooses, the wrapper executes.

---

## The Agent Loop

How does "decide, act, look at the result, decide again" actually run? As a loop around the model — the same model, over and over:

```
think → pick a tool → tool runs → look at result → think again → ...
```

Keep going until the task is done. A chatbot answers once and stops; an agent *loops* — it can search, read what came back, search differently, run code, check the output, and only then reply. The LLM drives itself instead of waiting for you at every step.

We'll build and take apart real agent loops in detail in a later topic of this course — here, the picture you need is just: **an agent is a loop repeating around a model, with tools on tap.**

**Quick check:** a chatbot and an agent both run on an LLM. Name the two things the agent's wrapper adds.

<details>
<summary>Show Answer</summary>

**Sample Answer:** Tools (the abilities it can execute — search, run code, edit files, APIs) and a loop (think → use tool → read result → think again, repeating until the task is done). The chatbot wrapper just sends messages and shows replies; the agent wrapper offers tools and keeps the cycle running.

</details>

## The Rest of the Application Family

The arrow list from the diagram, now with meaning:

- **Assistants** — voice assistants and coding assistants: chatbots tuned for a job (a role, a system prompt, maybe tools).
- **Search and question-answering tools** — ask questions over your documents or the web; the LLM reads what's retrieved and answers.
- **Writing and summarizing tools** — email drafters, meeting summarizers: chatbot-shaped, pointed at one task.
- **Translation tools** — the same next-word prediction, prompted in one language, continuing in another.
- **Automation workflows** — the LLM is one step inside a bigger process, like an inbox where incoming support tickets get classified, summarized, and routed without a chat window at all.

Chatbot and agent are the two big shapes; the rest are flavors — mostly chatbots with a job, or agents with a narrow loop.

Every piece from this phase now connects:

**Data** goes into **training**, which produces a **model** — checked by **testing**, used for **inference**, wrapped in an **application**. ## What Chatbots and Agents Are NOT

- **A chatbot is not a circle inside the LLM.** It's a wrapper — a product built *around* the model, which is why it belongs on the diagram as a box with an arrow, not a nested circle.
- **An agent is not an LLM with tools baked in.** The model ships as patterns; the application offers the toolbox and runs the loop. Swap the tools, same LLM.
- **A chatbot's memory is not the model remembering.** The wrapper resends the history each turn — the model predicts fresh every time.
- **Agents are not a different kind of AI.** Same pipeline, same circles, same LLM — just a wrapper with tools and a loop instead of a single reply.
