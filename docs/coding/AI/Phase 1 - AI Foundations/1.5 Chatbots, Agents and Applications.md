The diagram ended with one unexplored arrow: from the LLM out to its applications — boxes outside the circles, pointing in. We listed the family (assistants, search, translation, automation), but the two big ones deserve the full treatment: **the chatbot** and **the agent**. These are the products you've actually used for months. Time to see what's inside them.

A **chatbot** is the simplest wrapper: a chat window where you type a message, and the LLM writes a reply. That's the entire idea. You type → the app sends it to the LLM → the LLM predicts a reply, word by word (the next-word machine from 1.4) → the app shows it to you. One detail explains the "memory" illusion: the app keeps your earlier messages and sends them along with each new one. The LLM itself isn't recalling anything between turns — every request arrives as one big prompt containing the conversation so far. It *seems* to remember because the wrapper does the remembering. A **voice assistant** is the same wrapper with two extra stages: speech converted to text in, text converted to speech out. Same LLM, same prediction.

An **agent** is also a wrapper around an LLM, with one big difference: it can take actions, not just reply with text. The contrast, one line each — *a chatbot only talks*, output = words. *An agent can do*: search the web, run code, open a file, call an API — then use the result to decide what to do next.

Where do those abilities come from? One word: **tools**. Tools are the individual abilities you give an agent — web search, file editing, code execution, API calls. The agent app *offers* the tools to the LLM; the LLM decides which tool to use and when; the tool does the action; the result goes back to the LLM so it can decide the next step. So counting tools works exactly as you'd expect: one agent might have five, another six — the sixth being, say, web surfing, one more *kind* of action.

One placement rule, same spirit as the diagram: the tools are *not* inside the LLM itself. The LLM comes with its patterns; the application hands it a toolbox and asks "which one?" The model chooses, the wrapper executes.

And how does "decide, act, look at the result, decide again" actually run? As a loop around the model — same model, over and over: think → pick a tool → tool runs → look at the result → think again → ... until the task is done. A chatbot answers once and stops; an agent *loops* — it can search, read what came back, search differently, run code, check the output, and only then reply. The LLM drives itself instead of waiting for you at every step. We'll take real agent loops apart step by step in a later phase — here, the picture you need: **an agent is a loop repeating around a model, with tools on tap.**

Say the difference back in one line: what does the agent's wrapper add over a chatbot's? Two things — tools (the abilities it can execute) and a loop (think → use tool → read result → think again, until done).

The rest of the arrow list, now with meaning. **Assistants** — voice and coding assistants: chatbots tuned for a job (a role, instructions, maybe tools). **Search and question-answering tools** — questions over your documents or the web; the LLM reads what's retrieved and answers. **Writing and summarizing tools** — chatbot-shaped, pointed at one task. **Translation tools** — the same next-word prediction, prompted in one language, continuing in another. **Automation workflows** — the LLM is one step inside a bigger process, like an inbox where support tickets get classified, summarized, and routed without a chat window at all. Chatbot and agent are the two big shapes; the rest are flavors — chatbots with a job, or agents with a narrow loop.

Every piece from this phase now connects. **Data** goes into **training**, which produces a **model** — checked by **testing**, used for **inference**, wrapped in an **application**. The technique nests as **AI ⊃ machine learning ⊃ deep learning ⊃ {discriminative, generative}**. Inside generative AI sit the **LLM** and its media siblings. And out on the arrows: **chatbots** (talk) and **agents** (talk + tools + loop), plus the flavors around them. That's artificial intelligence, end to end: human-made software that mimics human-like thinking — not by copying the brain, but by learning patterns from examples and predicting what comes next.

The nots: a chatbot is *not* a circle inside the LLM — a wrapper, a product built *around* the model, which is why it belongs on the diagram as a box with an arrow. An agent is *not* an LLM with tools baked in — the model ships as patterns; the application offers the toolbox and runs the loop; swap the tools, same LLM. A chatbot's memory is *not* the model remembering — the wrapper resends the history each turn; the model predicts fresh every time. And agents are *not* a different kind of AI — same pipeline, same circles, same LLM; just a wrapper with tools and a loop instead of a single reply.
