## Main Content

A comment is text the browser skips. It exists for you (and your team), not for the user. The first problem beginners create: they forget the closing `-->` and the rest of the page gets swallowed. The second: they put secrets in comments, not realizing anyone can view source.

**Syntax:**

```html
<!-- This is a comment -->
<p>Hello</p>
<!-- TODO: add image here -->
```

Line by line: `<!--` starts the comment, `-->` ends it. Everything between is ignored by the browser and not rendered. The comment can span one line or many.

**Uses:**

- Explaining tricky markup.
- Leaving TODOs or reminders.
- Temporarily disabling a block of HTML (wrap it in a comment).
- Section markers in long files.

**Rules:**

- Start with `<!--` and end with `-->`.
- Cannot be nested — `<!-- outer <!-- inner --> -->` breaks (the first `-->` closes it).
- Cannot contain `--` in some strict parsers (avoid double hyphens inside).
- Comments are sent to the browser and visible via "View Source" — never put passwords or secrets in them.

**Shortcut:** in VS Code, select lines and press Ctrl+/ (Cmd+/ on Mac) to toggle comment marks — one press wraps them, another unwraps. Handy for quickly hiding code while testing.

```html
<!-- <img src="old.jpg" alt="Old"> -->
```

Wrap the line in a comment to hide it without deleting. Useful while testing, but clean up later.

**Debugging scenarios:**

- "Half my page is missing" — a comment is missing its closing `-->`. Find the unclosed comment and close it.
- "My comment shows on the page" — you used `//` or `#` instead of `<!-- -->`. Use HTML comment syntax.
- "I nested comments and the output is broken" — nesting is not allowed. Remove the inner comment or restructure.
- "Someone found my API key in my page" — you put a secret in a comment. Comments are public. Remove it and rotate the key.

## Common Mistakes

- Forgetting the closing `-->` — the rest of the page gets swallowed as a comment.
- Nesting comments — produces broken output.
- Leaving secrets/API keys in comments (visible to anyone via View Source).
- Over-commenting obvious code, creating clutter.
- Using comments instead of removing dead code permanently.

## Try It Yourself

1. Add a comment above a heading and check "View Source."
2. Wrap an image in a comment and confirm it disappears.
3. Try nesting two comments and observe the breakage.
4. Search your file for `<!--` to audit comments.

## Summary

- Syntax: `<!-- ... -->`.
- Browser ignores comments; they show in View Source.
- Uses: notes, TODOs, disabling code, section markers.
- Cannot nest; do not put secrets in them.
- Clean up comments as code stabilizes.
