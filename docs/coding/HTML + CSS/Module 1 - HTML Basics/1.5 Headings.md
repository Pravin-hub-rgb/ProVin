## Main Content

Headings give a page structure, like a table of contents. `<h1>` is the main title, `<h2>` sections, `<h3>` subsections. The problem beginners create: they pick `<h3>` because it "looks smaller" and end up with a page that has no real outline, which confuses screen readers and search engines.

Start from a page with one big title and three sections. Guess: use `<h1>` for the title and `<h1>` again for each section? That gives four "main titles" and no hierarchy. Guess: use `<h1>`, then `<h2>`, then `<h3>`? That builds a real outline. The second guess is right.

```html
<h1>Main Title</h1>
<h2>Section</h2>
<h3>Subsection</h3>
<h4>Sub-subsection</h4>
<h5>Minor</h5>
<h6>Smallest</h6>
```

Line by line: `<h1>` is the most important heading, usually the page's main title. Each following level is a deeper subsection. The browser renders them in decreasing default size, but the size is a side effect, not the point.

**Rules of good heading use:**

- Use headings in order. Do not jump from `<h1>` to `<h3>` without an `<h2>`.
- One `<h1>` per page as the main title.
- Pick the level by meaning (importance/depth), not by how big you want it to look.
- Styling (font-size, color) is done with CSS, not by choosing a lower heading level.

**Why it matters:** screen readers and search engines use the heading outline to understand the page. Skipping levels or using headings for styling breaks that outline. A blind user navigating by headings will miss sections; a search engine will misjudge the page's topics.

```html
<!-- Good: meaningful hierarchy -->
<h1>Blog Title</h1>
<h2>Post 1</h2>
<h3>Introduction</h3>
<h2>Post 2</h2>

<!-- Bad: skipping and styling misuse -->
<h1>Title</h1>
<h3>Looks smaller but means "section"</h3>
```

**Debugging scenarios:**

- "My page has no `<h1>`" — search engines and screen readers lose the main topic. Add one at the top.
- "My outline jumps from h1 to h3" — a section is missing its h2. Insert the missing level.
- "I used h4 to make small text" — that is a styling decision, not a heading. Use a `<p>` with CSS instead.
- "My headings all look the same size" — you used the same level repeatedly. Vary the level to reflect depth, then style with CSS.

## Common Mistakes

- Using `<h1>` multiple times for every section heading.
- Skipping levels (h1 -> h3) for visual reasons.
- Choosing a heading level to get a desired font size instead of using CSS.
- Using headings for non-heading text (e.g., a big bold paragraph).
- No `<h1>` at all on the page.

## Try It Yourself

1. Build a page with h1 -> h2 -> h3 and inspect the outline in DevTools (Accessibility tab).
2. Try skipping a level and note the outline gap.
3. Replace an h2 with an h4 and confirm the page looks different without CSS.
4. Add CSS to make an h3 look like an h1 and observe meaning vs appearance.

## Summary

- Six levels: h1 (most important) to h6.
- One h1 per page as the main title.
- Do not skip levels; keep a clean outline.
- Level = meaning/importance, not size.
- Styling is CSS's job.

## In Your Own Words

1. How many heading levels exist and which is most important?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Six levels: `<h1>` to `<h6>`. `<h1>` is the most important and usually the page's main title. `<h6>` is the least important.

</details>

2. Why should you not skip heading levels?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Headings form the document outline used by screen readers and search engines. Skipping levels (e.g., h1 straight to h3) creates gaps in that outline, making the page harder to navigate for assistive tech and harder to understand for crawlers.

</details>

3. Should you pick a heading level based on how big you want the text?

<details>
<summary>Show Answer</summary>

**Sample Answer:** No. Pick the level by meaning/importance. If you want a different size, use CSS. Using heading levels for styling breaks the semantic outline and harms accessibility and SEO.

</details>
