# Doc 1.11 — Images

## Where We Are So Far

`1.10` covered links. Now images — embedding pictures. Connection: links taught paths; images reuse the same path skills.

## Broader Goal

Embed images correctly with proper `src`, `alt`, dimensions, and paths, and caption them semantically.

---

## Main Content

An image is embedded with the void element `<img>`. It needs at least `src` (where the file is) and `alt` (what it is). The first problem beginners create: a missing or wrong `src` shows a broken icon; a missing `alt` fails accessibility. The second: omitting `width`/`height` makes the page jump as images load.

Start from a page that needs a photo. Guess: write `<img photo.jpg>`? The browser does not know that is an image or where it lives. Guess: write `<img src="photo.jpg" alt="A photo">`? That gives the browser the file location and a description. The second guess is right.

**Basic image:**

```html
<img src="images/photo.jpg" alt="A sunset over the mountains" />
```

Line by line: `<img>` is a void element (no closing tag). `src="images/photo.jpg"` points to the file. `alt="A sunset over the mountains"` describes the image for screen readers and as fallback text if it fails to load.

**Attributes:**

- `src` — path to the image file (relative or absolute URL).
- `alt` — alternative text describing the image. Shown if the image fails to load and read by screen readers. Keep it concise and meaningful; use `alt=""` for decorative images.
- Paths are **case-sensitive** on most servers: `Photo.jpg` and `photo.jpg` are different files. Match the exact filename casing.
- `width` / `height` — dimensions in pixels. Reserve space so the page does not jump when the image loads.
- `title` — tooltip on hover (optional).

```html
<img src="images/photo.jpg" alt="A sunset" width="600" height="400" />
```

Line by line: `width="600"` and `height="400"` reserve a 600x400 box before the image arrives, preventing layout shift. The browser uses the aspect ratio from these two numbers to size the placeholder.

**Relative vs absolute (same as links):**

```html
<img src="images/logo.png" alt="Logo" />        <!-- relative: next to this file's folder -->
<img src="/images/logo.png" alt="Logo" />       <!-- root-absolute -->
<img src="https://example.com/img.png" alt="" /> <!-- remote -->
```

**Common formats:** JPG (photos), PNG (transparency, screenshots), SVG (icons/logos, scalable), WebP (modern, small). Choose by content, not habit.

**Captioning with figure:**

```html
<figure>
  <img src="images/chart.png" alt="Sales chart for 2026" />
  <figcaption>Figure 1: Sales grew 20% in 2026.</figcaption>
</figure>
```

Line by line: `<figure>` wraps self-contained media. `<figcaption>` captions it. This gives the image and its caption a semantic relationship (covered more in `1.19`).

**Debugging scenarios:**

- "My image shows a broken icon" — `src` path is wrong. Check the Network tab for a 404 and fix the path.
- "Screen reader says nothing for my image" — `alt` is missing. Add a meaningful description, or `alt=""` for decorative images.
- "The page jumps when the image loads" — `width`/`height` are missing. Add them.
- "My image is huge and slow" — you served a 4000px photo for a 400px slot. Resize the file.
- "My caption is not linked to the image" — you used `<p>` under `<img>` instead of `<figure>`/`<figcaption>`. Wrap them.

## Common Mistakes

- Missing `alt` — fails accessibility and shows nothing on broken images.
- Wrong relative path — image shows a broken icon (check Network tab for 404).
- Omitting `width`/`height` — causes layout shift as images load.
- Using huge images without resizing — slow pages.
- Using `alt` to stuff keywords (SEO spam) instead of describing the image.

## Try It Yourself

1. Add an image with correct `src` and `alt`; verify it loads.
2. Break the path on purpose and check the Network tab 404.
3. Add `width`/`height` and observe no layout shift.
4. Wrap the image in `<figure>` with a `<figcaption>`.
5. Test a decorative image with `alt=""`.

## Summary

- `<img>` is a void element needing `src` and `alt`.
- `alt` = accessibility + fallback text.
- `width`/`height` reserve space, prevent shift.
- Relative/absolute paths work like links.
- `<figure>` + `<figcaption>` captions images semantically.

## In Your Own Words

1. Why is the `alt` attribute important?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `alt` describes the image for screen readers (accessibility) and is shown if the image fails to load. For decorative images, use `alt=""` so screen readers skip them. Missing `alt` fails accessibility checks.

</details>

2. Why add `width` and `height` to `<img>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** They reserve the image's space in the layout before it loads, preventing the page from jumping (layout shift) when the image arrives. The browser uses the aspect ratio to size the placeholder.

</details>

3. When should you use `<figure>` and `<figcaption>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** When an image (or diagram) is self-contained content with a caption. `<figure>` wraps the media and `<figcaption>` provides its caption, creating a semantic link between them that a loose `<p>` under an `<img>` would not convey.

</details>

## Cheat Sheet (Quick Recall)

**`<img src alt>`** (void). **`alt`** = accessibility/fallback. **`width`/`height`** = reserve space.

**Paths:** relative (`images/x.png`) or absolute (URL).

**Caption:** `<figure>` + `<figcaption>`.
