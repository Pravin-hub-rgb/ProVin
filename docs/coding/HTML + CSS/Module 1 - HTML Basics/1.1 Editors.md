## Main Content

You could write HTML in Notepad right now and it would work, because HTML is plain text. But the feedback loop would be slow: type, save, switch to the browser, refresh, repeat. The problem is not "which editor is best?" — it is "how do I see my changes the moment I save?" That is what a good editor plus a live preview solves.

Start from a blank folder. You create `index.html`, type a heading, save, and want to see it immediately. Guess: maybe the browser auto-refreshes? No — browsers only reload when asked. Guess: maybe a special "HTML editor" is required? No — any text editor can write HTML. The answer is a small extension that watches your file and refreshes the browser for you.

**Recommended editor:** VS Code (free, cross-platform, huge extension ecosystem).

A plain text editor like Notepad can write HTML, but a code editor gives three things that matter from day one: syntax highlighting (different colors for tags and content so mistakes jump out), autocomplete (suggests tag and attribute names as you type), and error hints (flags missing brackets or mismatched tags). Those are the reasons to use VS Code instead of Notepad.

**Why the file is called `index.html`:** `index` is the conventional name for a site's entry page. When a server is asked for a folder, it looks for `index.html` inside it and serves that. Frameworks like React follow the same convention later, so the habit starts here.

**Live Server vs double-clicking:** when you double-click an `.html` file, the browser reads it straight from disk and the address starts with `file://`. Live Server instead runs a tiny local server on your machine (address like `http://localhost:5500`) and the browser asks it for the file over HTTP — the same request/response pattern from Module 0. Live Server also keeps a quiet connection open to the page; when you save, it tells the browser to reload. That is how the auto-refresh works. (Under the hood, Live Server injects a small script into the page it serves; that script opens a persistent connection back to Live Server, and on save Live Server sends a "reload" message down that line. The reload itself is still a fresh request from the browser.)

**Useful extensions:**

- **Live Server** — auto-refreshes the browser on save. This is the one that fixes the slow loop.
- **Prettier** — auto-formats code (indentation, spacing) so your HTML stays consistent.
- **HTML CSS Support** — autocompletes CSS class names while you type.

**Creating your first file:**

1. Open VS Code.
2. Create a new file.
3. Save it as `index.html` (the `.html` extension is what tells the browser to render it).
4. Write some HTML.
5. Open it with Live Server.

```text
File -> New File -> Save As -> index.html
```

Paste this minimal example:

```html
<!DOCTYPE html>
<html>
  <head><title>Test</title></head>
  <body><h1>Hello</h1></body>
</html>
```

Line by line: `<!DOCTYPE html>` declares HTML5. `<html>` wraps everything. `<head>` holds metadata, here just the tab title. `<body>` holds the visible content, here one heading. Then right-click `index.html` and choose "Open with Live Server" (or click "Go Live" in the bottom-right corner of VS Code). The page opens in your browser. Edit the text, press Ctrl+S, and watch the browser update on its own.

**Why Live Server matters:** without it you save, switch windows, and refresh manually. With it, save once and the browser updates. That fast feedback loop is what makes learning HTML fast, because you see the result of every change before you forget what you typed.

**Common debugging scenarios:**

- "My page shows raw text instead of a heading" — you saved as `.txt` instead of `.html`. Rename the file.
- "I edited the file but the browser shows the old version" — you forgot to save. Press Ctrl+S, then refresh.
- "Live Server is not refreshing" — the extension is not installed, or you opened the file by double-clicking instead of via Live Server. Right-click the file and choose "Open with Live Server."
- "I changed something in DevTools and it disappeared" — DevTools edits are temporary (covered in `1.15`). They never save to your file.

## Common Mistakes

- Saving as `.txt` instead of `.html` — the browser then shows the raw text instead of rendering the page.
- Not installing Live Server and refreshing manually every time, which slows the learning loop.
- Editing in DevTools and expecting it to save to your file. It does not.
- Forgetting to save before refreshing — the browser shows the old version.
- Working in the wrong folder and wondering why changes do not appear.

## Try It Yourself

1. Install VS Code and the Live Server extension.
2. Create `index.html` with the snippet above.
3. Open with Live Server and confirm "Hello" appears in the browser.
4. Change the text, save (Ctrl+S), and watch it update without a manual refresh.
5. Install Prettier and format the file (Shift+Alt+F, then pick Prettier if asked).

## Summary

- VS Code is the recommended editor; HTML is plain text.
- Live Server gives instant browser refresh on save — the core of a fast feedback loop.
- Prettier formats; HTML CSS Support autocompletes.
- Always save as `.html`.
- Inspecting and debugging in the browser is covered in `1.15`.
