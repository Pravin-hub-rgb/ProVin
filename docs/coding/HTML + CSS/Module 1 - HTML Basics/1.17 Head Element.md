## Main Content

The `<head>` holds information about the page, not content shown to the user. It is where you tell the browser how to read the file, what the page is called, and which other files to load. The problem beginners create: they put visible content in `<head>` (it never shows), or they forget charset/viewport and get garbled text or zoomed-out mobile pages.

Start from a page that looks fine on desktop but garbled on a phone. Guess: the CSS is wrong? Maybe, but first check the head — a missing viewport meta makes mobile browsers pretend the screen is ~980px wide. A missing charset makes non-English text garble. Fix the head first, then blame CSS.

**The standard head block:**

```html
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>My Page</title>
  <meta name="description" content="A short summary of this page." />
  <meta name="author" content="Your Name" />
  <link rel="icon" href="favicon.ico" />
  <link rel="stylesheet" href="styles.css" />
</head>
```

Line by line: `<meta charset="UTF-8" />` declares the character encoding. `<meta name="viewport" ...>` controls mobile layout. `<title>` sets the tab title. `<meta name="description">` summarizes the page for search engines. `<meta name="author">` names the author. `<link rel="icon">` sets the favicon. `<link rel="stylesheet">` connects CSS.

**Part by part:**

**`<title>`** — the page title shown in the browser tab, bookmarks, and search results. Keep it concise and descriptive. Every page needs one.

**`<meta charset="UTF-8">`** — declares the character encoding. UTF-8 covers almost all characters (English, Hindi, emojis, symbols). Must come early in the head so the browser knows the table before reading text. (Charset deep-dive was in Module 0.)

**`<meta name="viewport" ...>`** — controls layout on mobile. `width=device-width` uses the phone's real width instead of pretending ~980px; `initial-scale=1.0` starts at normal zoom. Without it, mobile pages look zoomed out. Desktop browsers ignore this line. (Covered in depth in Module 0.)

**Other meta labels (name/content pairs):**

- `description` — short summary; search engines often show it under your title.
- `author` — who wrote the page.
- `robots` — tells crawlers to index/follow or not.
- `theme-color` — tints the browser's address bar on some phones.

Each meta says one thing: `name` picks the label, `content` supplies the value.

**Favicon (tab icon):**

```html
<link rel="icon" href="favicon.ico" />
```

Line by line: `rel="icon"` declares the relationship; `href` points to the file. A small image next to the title in the tab, bookmarks, and history. Browsers also auto-look for `favicon.ico` in the site root even without the tag, but the tag lets you choose any name/folder/format (PNG, SVG).

**Connecting CSS:**

```html
<link rel="stylesheet" href="styles.css" />
```

`rel="stylesheet"` tells the browser to fetch and apply this CSS file. (Full CSS connection methods come in Module 5.)

**Order matters (roughly):** charset first, then viewport, then title, then other meta, then links.

**Debugging scenarios:**

- "My tab shows 'Untitled'" — `<title>` is missing or empty. Add it.
- "Non-English text is garbled" — charset is missing or late. Put `<meta charset="UTF-8">` first.
- "My mobile page is zoomed out" — viewport meta is missing. Add it.
- "My favicon does not appear" — path is wrong, or the browser cached the old one. Hard-refresh (Ctrl+Shift+R) or clear cache.
- "My CSS does not apply" — `rel="stylesheet"` is missing or `href` path is wrong. Check the Network tab for a 404.
- "Visible content in `<head>` does not show" — move it to `<body>`.

## Common Mistakes

- Forgetting charset or putting it late — non-English text may garble.
- Missing viewport meta — mobile pages look zoomed out.
- No `<title>` — tab shows "Untitled"; bad SEO.
- Favicon path wrong — icon does not appear (and browsers cache favicons aggressively; hard-refresh to test).
- Putting visible content in `<head>` — it will not show.
- Confusing `<link>` (head, void) with `<a>` (body, clickable).

## Try It Yourself

1. Build the standard head block and verify the tab title.
2. Remove the viewport meta, open the device toolbar (Ctrl+Shift+M), and observe zoomed-out layout.
3. Add a `favicon.ico` to the root and confirm it appears (hard-refresh if needed).
4. Add `name="description"` and inspect in DevTools Elements.
5. Change charset to ISO-8859-1 and paste Hindi text to see garbling.

## Summary

- `<head>` = metadata (charset, viewport, title, meta, link).
- `<title>` = tab title + SEO.
- `<meta charset="UTF-8">` early; `<meta name="viewport">` for mobile.
- Other meta: description, author, robots, theme-color.
- Favicon via `<link rel="icon">`; CSS via `<link rel="stylesheet">`.
- Order: charset -> viewport -> title -> meta -> links.

## In Your Own Words

1. What is the difference between `<title>` and an `<h1>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `<title>` sets the browser tab title, bookmark name, and search-result title (metadata in `<head>`, not visible on the page). `<h1>` is the main visible heading on the page (in `<body>`). They often differ in wording and serve different audiences (browser/SEO vs. reader).

</details>

2. Why must charset come early in the head?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The browser reads bytes top-down. If charset is declared late, it may have already guessed wrong and garbled non-English text. Declaring UTF-8 first ensures the correct table is used from the start.

</details>

3. How does a favicon get set?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Via `<link rel="icon" href="favicon.ico">` in the head, pointing to an image file. Browsers also auto-look for `favicon.ico` in the site root even without the tag. The tag allows custom names, folders, and formats (PNG, SVG).

</details>

4. What is the viewport meta line for?

<details>
<summary>Show Answer</summary>

**Sample Answer:** It tells mobile browsers to use the device's real width instead of pretending ~980px, and to start at normal zoom (`initial-scale=1.0`). Without it, mobile pages look zoomed out. Desktop browsers ignore it.

</details>

## Cheat Sheet (Quick Recall)

**`<title>`** tab/SEO. **`<meta charset>`** encoding (early). **`<meta viewport>`** mobile.

**`<meta name="description">`** summary. **`<link rel="icon">`** favicon.

**`<link rel="stylesheet">`** CSS. **Order:** charset -> viewport -> title -> meta -> links.
