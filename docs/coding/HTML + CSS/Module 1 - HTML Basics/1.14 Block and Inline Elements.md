# Doc 1.14 — Block and Inline Elements

## Where We Are So Far

`1.13` covered tables. Now block vs inline — how elements flow on the page. Connection: many tags met so far; now the rule that governs how they sit next to each other.

## Broader Goal

Understand the block/inline distinction, the neutral containers (`div`, `span`), and how CSS `display` changes the behavior.

---

## Main Content

Every element is either block or inline by default. This determines how it sits among other elements. The problem beginners create: they expect two `<div>`s to sit side by side (they stack), or they expect a `<span>` to take full width (it does not). Understanding the default flow prevents a lot of "why is my layout wrong?" confusion.

Start from two headings written one after the other. Guess: they sit side by side? No — headings are block, so they stack vertically. Guess: wrap them in `<span>`? Then they flow inline. The difference is the default `display` value, not the tag name.

**Block elements:** take the full available width, start on a new line, stack vertically.

```html
<div>Block 1</div>
<p>Block 2</p>
<h1>Block 3</h1>
```

Line by line: each element takes the full width of its container and starts on a new line, so they stack top to bottom.

**Inline elements:** take only as much width as their content, flow within a line of text.

```html
<p>This is <span>inline</span> text with a <a href="#">link</a> and <strong>bold</strong>.</p>
```

Line by line: `<span>`, `<a>`, and `<strong>` sit inside the paragraph's text flow, taking only their content's width.

**Comparison:**

| Property | Block | Inline |
|---|---|---|
| Width | Full available width | Content width only |
| New line | Yes, starts on new line | No, flows in text |
| Can contain | Block or inline | Inline only (usually) |
| Examples | `div`, `p`, `h1`-`h6`, `section`, `article`, `ul`, `table` | `span`, `a`, `strong`, `em`, `img`, `code` |

**Neutral containers:**

- `<div>` — a generic block container. Use when no semantic block tag fits.
- `<span>` — a generic inline container. Use when no semantic inline tag fits.

**CSS can change the behavior:**

```css
span { display: block; }   /* inline becomes block */
div  { display: inline; } /* block becomes inline */
```

`inline-block` gives inline flow but block-like sizing (width/height apply). This is how CSS layouts reflow elements without changing the HTML.

**Debugging scenarios:**

- "My two divs will not sit side by side" — divs are block by default. Use `display: inline-block` or flexbox.
- "My span will not take a width" — spans are inline; width does not apply. Use `display: inline-block` or `block`.
- "My image has a gap below it" — `<img>` is inline by default and sits on the text baseline. Use `display: block` or `vertical-align`.
- "My layout breaks after I added a div" — you put a block inside an inline element, which is invalid. Fix the nesting.

## Common Mistakes

- Putting block elements inside inline elements (invalid HTML).
- Using `<div>` for everything instead of semantic tags.
- Assuming `<img>` is block — it is inline by default (can cause gaps).
- Forgetting that `display` in CSS overrides the default.
- Using `<br>` to fake block spacing instead of CSS.

## Try It Yourself

1. Put two `<span>` and two `<div>` side by side; observe flow.
2. Wrap text in `<span>` and change color via CSS to see inline styling.
3. Inspect an `<img>` and note it is inline (causes baseline gaps).
4. Apply `display: block` to a span and watch it take full width.
5. Build a row of items using `display: inline-block`.

## Summary

- Block = full width, new line; inline = content width, flows in text.
- `div` (block) and `span` (inline) are neutral containers.
- CSS `display` can override the default.
- Choose semantic tags first; use `div`/`span` as fallback.
- Block vs inline is about flow, not importance.

## In Your Own Words

1. What is the difference between a block and an inline element?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A block element takes the full available width and starts on a new line (e.g., `<div>`, `<p>`, `<h1>`). An inline element takes only its content's width and flows within text (e.g., `<span>`, `<a>`, `<strong>`). The difference is flow, not importance.

</details>

2. What are `<div>` and `<span>` for?

<details>
<summary>Show Answer</summary>

**Sample Answer:** They are neutral containers with no semantic meaning: `<div>` is a generic block container, `<span>` is a generic inline container. Use them as fallbacks when no semantic tag fits (e.g., grouping for styling).

</details>

3. Can CSS change whether an element is block or inline?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Yes. The `display` property overrides the default: `display: block`, `display: inline`, or `display: inline-block`. This is how CSS layouts reflow elements without changing the HTML.

</details>

## Cheat Sheet (Quick Recall)

**Block:** full width, new line (`div`, `p`, `h1`, `section`).

**Inline:** content width, flows in text (`span`, `a`, `strong`, `img`).

**Neutral:** `div` (block), `span` (inline). **CSS:** `display` overrides.
