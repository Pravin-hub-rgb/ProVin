# Doc 1.16 — Computer Code Elements

## Where We Are So Far

`1.15` covered DevTools. Now computer code elements — displaying code on a page. Connection: inspecting code done; now how to show code to readers.

## Broader Goal

Display code and terminal-style text semantically using `<code>`, `<pre>`, `<kbd>`, `<samp>`, and `<var>`.

---

## Main Content

When you write about code on a web page, you need tags that say "this is code," not just monospace styling. The problem beginners create: they use `<pre>` alone and lose the "code" semantics, or they use `<code>` alone and lose the formatting because newlines collapse. The fix is pairing them.

Start from a page that shows a two-line function. Guess: put it in `<code>`? The newlines collapse to spaces and it becomes one line. Guess: put it in `<pre>`? Whitespace is preserved but it is not marked as code. Guess: combine `<pre><code>`? Both preserved and semantic. The third guess is right.

**Inline code:**

```html
<p>Use the <code>console.log()</code> function.</p>
```

Line by line: `<code>` is inline and renders in a monospace font. It marks a piece of code within text. Use it for variable names, function names, or short snippets inside a sentence.

**Code block (preserve formatting):**

```html
<pre><code>
function hello() {
  console.log("Hi");
}
</code></pre>
```

Line by line: `<pre>` preserves whitespace and newlines (unlike normal HTML which collapses them). `<code>` marks the content as code. Pairing `<pre>` with `<code>` is the standard for code blocks.

**Other code-related tags:**

```html
<p>Press <kbd>Ctrl</kbd> + <kbd>S</kbd> to save.</p>
<p>The program printed: <samp>Hello, World!</samp></p>
<p>The formula is E = mc<sup>2</sup>, where <var>m</var> is mass.</p>
```

Line by line: `<kbd>` marks keyboard input (keys the user presses). `<samp>` marks sample output from a program. `<var>` marks a variable name in math or code.

**Debugging scenarios:**

- "My code block lost its indentation" — you used `<code>` without `<pre>`. Wrap it in `<pre><code>`.
- "My code block has weird extra indentation" — `<pre>` preserves ALL whitespace, including accidental indentation in your source. Fix the source indentation.
- "My keyboard shortcut does not look like keys" — `<kbd>` is semantic; styling is CSS. Add CSS if you want a keycap look.
- "My variable is not italic" — `<var>` is semantic; default styling varies. Style with CSS.

## Common Mistakes

- Using `<pre>` alone for code without `<code>` — loses the "this is code" semantics.
- Forgetting that `<pre>` preserves ALL whitespace, including accidental indentation.
- Using `<code>` for a whole block without `<pre>` — newlines collapse.
- Styling these tags with CSS to look like normal text — defeats their purpose.
- Using `<code>` for non-code text just to get monospace font.

## Try It Yourself

1. Put a two-line function in `<pre><code>` and verify formatting is preserved.
2. Try the same without `<pre>` and observe collapse.
3. Add `<kbd>` for a shortcut like Ctrl+S.
4. Add `<samp>` for terminal output.
5. Use `<var>` in a math expression.

## Summary

- `<code>` = inline code; `<pre>` = preserve whitespace.
- Combine `<pre><code>` for code blocks.
- `<kbd>` = keys, `<samp>` = output, `<var>` = variable.
- These are semantic, not just styling.

## In Your Own Words

1. Why combine `<pre>` with `<code>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `<pre>` preserves whitespace and newlines (which HTML normally collapses), and `<code>` marks the content as code semantically. Together they create a formatted, meaningful code block. `<pre>` alone loses the "code" semantics; `<code>` alone loses the formatting.

</details>

2. What is the difference between `<kbd>` and `<samp>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `<kbd>` represents keyboard input the user types (e.g., Ctrl+S). `<samp>` represents sample output from a program or terminal. One is input, the other is output.

</details>

3. When would you use `<var>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** To mark a variable name in a mathematical expression or programming context (e.g., `E = mc², where m is mass`). It is semantic, indicating "this is a variable," not just italic styling.

</details>

**Rule:** semantic meaning, not just monospace font.
