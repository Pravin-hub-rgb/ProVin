## Main Content

Every HTML page follows the same skeleton. Without it, browsers may render inconsistently or fall back to quirks mode. First the skeleton, then what each part does, then how to build it up in stages.

**The doctype story:** HTML went through numbered versions — HTML 2 (1995), HTML 3.2 (1997), HTML 4.01 (1999) — each with a long, hard-to-remember doctype that pointed at a DTD (document type definition) and picked a flavor (strict, transitional, frameset). When the line was missing or wrong, browsers fell back to **quirks mode**, imitating sloppy 1990s behavior, and the same page could look different across browsers. HTML5 (the current "living standard," no version number) cut the line down to just `<!DOCTYPE html>` — no version, no URL, nothing to memorize — so the browser always uses today's standard rules. That is the whole declaration; it tells the browser "render this as modern HTML."

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>My Page</title>
  </head>
  <body>
    <h1>Hello</h1>
  </body>
</html>
```

Line by line: `<!DOCTYPE html>` declares HTML5 and must be the very first line. `<html lang="en">` is the root element wrapping everything; the `lang` attribute declares the page language (accessibility and SEO). `<head>` holds metadata about the page: charset, viewport, title, links to CSS — nothing here is directly visible. `<body>` holds all visible content: headings, paragraphs, images, links.

**Stage 1 — Minimal (renders, but bare):**

```html
<!DOCTYPE html>
<html>
  <body>
    <h1>Hello</h1>
  </body>
</html>
```

This renders a heading, but the browser has to guess the encoding and the tab title shows "Untitled." Fine for a quick test, not for a real page.

**Stage 2 — Add a title:**

```html
<head>
  <title>My Page</title>
</head>
```

Now the tab shows "My Page" and search engines have something to display.

**Stage 3 — Full standard skeleton (use this every time):**

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>My Page</title>
  </head>
  <body>
    <h1>Hello</h1>
  </body>
</html>
```

**Emmet shortcut:** in VS Code, type `!` in an empty `.html` file and press Tab — Emmet generates the full Stage 3 skeleton for you, including the `lang`, charset, and viewport lines. You will still learn to type it by hand, but the shortcut saves time in real projects.

**Viewport vs page:** the viewport is the visible window area where the page is drawn; the page itself can be much longer and scroll. On a phone, `width=device-width` makes the browser use the real screen width instead of pretending ~980px. Desktop browsers ignore the viewport meta line and use the window width instead.

**Debugging scenarios:**

- "My heading disappeared" — you put it inside `<head>` instead of `<body>`. Move it down.
- "The tab says 'Untitled'" — `<title>` is missing or empty. Add it inside `<head>`.
- "Non-English text shows as question marks" — charset is missing or wrong. Add `<meta charset="UTF-8">` as the first line inside `<head>`.
- "The page looks zoomed out on my phone" — viewport meta is missing. Add it.
- "The browser renders in quirks mode" — doctype is missing or wrong. Make `<!DOCTYPE html>` the very first line, with nothing above it.

## Common Mistakes

- Forgetting `<!DOCTYPE html>` — the browser may enter quirks mode and render oddly.
- Putting visible content inside `<head>` — it will not show.
- Nesting `<html>` inside `<body>` or vice versa — invalid structure.
- Omitting `<title>` — the tab shows "Untitled" and SEO suffers.
- Using a wrong/old doctype copied from an old tutorial.
- Leaving whitespace or a comment above the doctype — it must be first.

## Try It Yourself

1. Create `index.html` with the Stage 3 skeleton.
2. Change the `<title>` and check the browser tab.
3. Move the `<h1>` into `<head>` and observe it disappears.
4. Remove the doctype, save, refresh — note any rendering change, then put it back.
5. Add `lang="fr"` and inspect the `<html>` tag in DevTools later.

## Summary

- Skeleton: doctype -> html -> head (metadata) -> body (visible content).
- `<!DOCTYPE html>` = HTML5, simplified from the old long doctype.
- `lang` on `<html>` declares the page language.
- `<head>` = metadata; `<body>` = visible content.
- Use the Stage 3 skeleton for every page.

## In Your Own Words

1. What does `<!DOCTYPE html>` do?

<details>
<summary>Show Answer</summary>

**Sample Answer:** It declares that the document is HTML5. It must be the first line. HTML5 simplified the old long doctype (which pointed at a DTD) to just this short line. Without it, the browser may enter quirks mode and render inconsistently.

</details>

2. What is the difference between `<head>` and `<body>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `<head>` holds metadata about the page (charset, viewport, title, CSS links) that is not directly visible. `<body>` holds all the visible content the user sees (headings, paragraphs, images, links). Putting visible content in `<head>` makes it not show.

</details>

3. Why add `lang="en"` to the `<html>` tag?

<details>
<summary>Show Answer</summary>

**Sample Answer:** It declares the language of the page. This helps screen readers pronounce text correctly and helps search engines understand the page. Use the correct code for your language (e.g., `lang="fr"` for French).

</details>

## Cheat Sheet (Quick Recall)

**Skeleton:** `<!DOCTYPE html>` -> `<html lang="en">` -> `<head>` (meta + title) -> `<body>` (content).

**Doctype:** just `<!DOCTYPE html>` — HTML5 simplified it.

**Rule:** metadata in head, visible content in body.
