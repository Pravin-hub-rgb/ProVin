## Main Content

HTML is made of elements. An element is a tag (or pair of tags) plus its content. The first problem beginners hit: a tag that never closes swallows the rest of the page. The second: a tag that should not close gets closed and produces an extra empty box. Understanding the two families — normal and void — prevents both.

**Normal element (has content and a closing tag):**

```html
<p>Hello World</p>
```

Parts: start tag `<p>`, content `Hello World`, end tag `</p>`. The browser shows the content and stops when it sees `</p>`.

**Void element (no content, no closing tag):**

```html
<br>
<hr>
<img src="photo.jpg" alt="Photo">
<input type="text">
```

These represent things that have no inner content — a line break, a divider, an image, an input field. They are self-contained. Writing `</br>` or `</img>` is invalid (harmless in practice, but wrong).

**Nested elements (building a tree):**

```html
<div>
  <h1>Title</h1>
  <p>Paragraph</p>
</div>
```

The `<div>` contains two child elements. This nesting is how the DOM (from Module 0) is built — every page is a tree of parent and child elements.

**Tag vs element:** the tag is the label in angle brackets (`<p>`). The element is the whole package — opening tag, content, and closing tag. People use the words interchangeably, but the distinction matters when you debug: "unclosed tag" means the browser never saw the closing label.

**The slash question:** some people write `<br />` with a trailing slash. That is the older XHTML style; in modern HTML the slash is optional and plain `<br>` is standard. Both work in browsers, but pick one style and stay consistent.

**Debugging scenarios:**

- "The rest of my page vanished" — an unclosed normal element swallowed everything after it. Find the missing `</p>` or `</div>` and close it.
- "I see an extra empty box" — you wrote a closing tag for a void element (`</br>` or `</img>`). Remove the closing tag.
- "My text is bold/italic in the wrong place" — overlapping tags like `<p><b>text</p></b>`. Fix the nesting so tags close in reverse order.
- "DevTools shows a different tree than my source" — the browser auto-fixed your broken nesting. Fix the source to match what you intended.

## Common Mistakes

- Forgetting the closing tag on a normal element — the browser may grab following content as its content.
- Closing a void element that has no closing tag — harmless but unnecessary and invalid.
- Mismatched/overlapping tags: `<p><b>text</p></b>` — invalid nesting.
- Confusing "tag" and "element" when reading error messages.
- Mixing self-closing (`<br />`) and plain (`<br>`) styles in the same file.

## Try It Yourself

1. Write `<p>Hello</p>` and verify it renders.
2. Write an unclosed `<p>Hello` and see how the browser auto-closes it (inspect in DevTools).
3. Nest `<b>` inside `<p>` and inspect the tree in the Elements tab.
4. Try both `<br>` and `<br />` — confirm identical output.
5. Write a `<div>` with three children and view the tree in the Elements tab.

## Summary

- Element = start tag + content + end tag.
- Void elements have no content/closing tag: `br`, `hr`, `img`, `input`, `meta`, `link`.
- Elements nest to form a tree (the DOM).
- Tag ≠ element (tag is the label; element is the whole).
- HTML5 void elements need no trailing slash.

## In Your Own Words

1. What is the difference between a tag and an element?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A tag is the label in angle brackets (e.g., `<p>`). An element is the whole package — opening tag, content, and closing tag (e.g., `<p>Hello</p>`). Void elements like `<br>` are just a single tag with no content.

</details>

2. What is a void element? Give examples.

<details>
<summary>Show Answer</summary>

**Sample Answer:** A void element has no content and no closing tag — it represents something self-contained like a line break or an image. Examples: `<br>`, `<hr>`, `<img>`, `<input>`, `<meta>`, `<link>`. In HTML5 they do not need a trailing slash.

</details>

3. Why does nesting matter?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Nesting builds the document tree (the DOM). Parent/child relationships determine structure, styling inheritance, and how assistive tech reads the page. Invalid nesting (overlapping tags) produces unpredictable rendering.

</details>

## Cheat Sheet (Quick Recall)

**Normal:** `<p>content</p>`. **Void:** `<br>`, `<hr>`, `<img>`, `<input>`, `<meta>`, `<link>`.

**Nesting:** parents contain children; forms a tree.

**Slash:** optional in HTML5; standard is no slash.
