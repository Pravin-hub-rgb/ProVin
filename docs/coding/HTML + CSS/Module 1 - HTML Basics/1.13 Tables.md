# Doc 1.13 — Tables

## Where We Are So Far

`1.12` covered lists. Now tables — tabular data. Connection: lists group items; tables group data in rows and columns.

## Broader Goal

Build accessible, well-structured tables with headers, grouping, captions, and merged cells — and know when not to use tables.

---

## Main Content

Tables display tabular data: rows and columns. They are not for page layout (that is CSS's job). The problem beginners create: they use tables to lay out a page, which breaks accessibility and responsiveness. Another: mismatched column counts across rows, which breaks the grid silently.

Start from a small dataset — names and ages. Guess: write `<table><tr><td>Alice 30</td></tr></table>`? That puts everything in one cell with no structure. Guess: split into rows and cells with headers? That builds a real table. The second guess is right.

**Basic table:**

```html
<table>
  <tr>
    <th>Name</th>
    <th>Age</th>
  </tr>
  <tr>
    <td>Alice</td>
    <td>30</td>
  </tr>
  <tr>
    <td>Bob</td>
    <td>25</td>
  </tr>
</table>
```

Line by line: `<table>` wraps the whole table. `<tr>` is a row. `<th>` is a header cell (bold/centered by default, semantic). `<td>` is a regular data cell. Row by row, the table builds its grid.

**Semantic grouping:**

```html
<table>
  <caption>Student Scores</caption>
  <thead>
    <tr><th>Name</th><th>Score</th></tr>
  </thead>
  <tbody>
    <tr><td>Alice</td><td>90</td></tr>
    <tr><td>Bob</td><td>85</td></tr>
  </tbody>
  <tfoot>
    <tr><td>Average</td><td>87.5</td></tr>
  </tfoot>
</table>
```

Line by line: `<caption>` is the title and should be the first child of `<table>`. `<thead>` wraps header rows. `<tbody>` wraps body rows. `<tfoot>` wraps footer/summary rows. These groups help screen readers and make large tables maintainable.

**Merging cells:**

```html
<td colspan="2">Spans 2 columns</td>
<td rowspan="2">Spans 2 rows</td>
```

`colspan="n"` makes a cell span n columns. `rowspan="n"` makes it span n rows. Keep total counts consistent or the table breaks.

**Accessibility:** use `<th>` (not `<td>`) for headers, and `scope="col"`/`scope="row"` to associate headers with cells.

```html
<th scope="col">Name</th>
<th scope="row">Alice</th>
```

Line by line: `scope="col"` says "this header applies to the column below." `scope="row"` says "this header applies to the row to its right."

**Debugging scenarios:**

- "My table looks like a broken grid" — column counts differ across rows. Count cells in each row and make them match (accounting for colspan).
- "My header is not announced as a header" — you used `<td>` instead of `<th>`. Switch to `<th>`.
- "My caption shows in the wrong place" — `<caption>` must be the first child of `<table>`. Move it up.
- "My merged cell created a gap" — colspan/rowspan counts are off. Recount.
- "My page layout breaks on mobile" — you used a table for layout. Use CSS flexbox/grid instead.

## Common Mistakes

- Using tables for page layout (use CSS flexbox/grid instead).
- Forgetting `<th>` for headers — hurts accessibility.
- Mismatched column counts across rows (breaks the grid).
- Omitting `<caption>` for complex tables.
- Using `colspan`/`rowspan` incorrectly, creating gaps.
- Forgetting `scope` on headers in large tables.

## Try It Yourself

1. Build a 3-column, 4-row table with a header row.
2. Add `<caption>`, `<thead>`, `<tbody>`.
3. Merge two cells with `colspan="2"`.
4. Add `scope` attributes and inspect accessibility.
5. Try a mismatched row and observe the broken layout.

## Summary

- `<table>`/`<tr>`/`<th>`/`<td>` for tabular data.
- Group with `<thead>`/`<tbody>`/`<tfoot>`; title with `<caption>`.
- `colspan`/`rowspan` merge cells.
- Use `<th scope>` for accessibility.
- Tables are for data, not layout.

## In Your Own Words

1. What is the difference between `<th>` and `<td>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `<th>` is a header cell (bold/centered by default, semantic "this is a header") used in `<thead>`; `<td>` is a regular data cell. Use `<th>` for column/row headers to make the table accessible and meaningful.

</details>

2. What do `colspan` and `rowspan` do?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `colspan="n"` makes a cell span n columns; `rowspan="n"` makes it span n rows. They merge adjacent cells into one larger cell. Keep total counts consistent or the table breaks.

</details>

3. Why should tables not be used for page layout?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Tables are semantically for tabular data. Using them for layout harms accessibility, makes responsive design hard, and is hard to maintain. Page layout should use CSS (flexbox/grid), covered in later modules.

</details>

## Cheat Sheet (Quick Recall)

**`<table>`** wraps; **`<tr>`** row; **`<th>`** header; **`<td>`** data.

**Group:** `<thead>`/`<tbody>`/`<tfoot>`; **title:** `<caption>`.

**Merge:** `colspan`, `rowspan`. **A11y:** `scope`.

**Rule:** data only, not layout.
