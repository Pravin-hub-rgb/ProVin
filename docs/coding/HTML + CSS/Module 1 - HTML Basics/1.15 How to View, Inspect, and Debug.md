# Doc 1.15 — How to View, Inspect, and Debug

## Broader Goal

Learn to use DevTools to inspect the DOM, debug missing files, test responsive sizes, and understand that edits there are temporary.

---

## Main Content

DevTools is built into every modern browser. It is your X-ray for HTML/CSS/JS. The problem beginners create: they edit in DevTools and expect it to save, or they ignore the Network tab when an image fails. Knowing the four key tabs and the temporary nature of DevTools edits prevents both.

Press F12 (or Ctrl+Shift+I) to open it.

**Four tabs that matter:**

- **Elements** — view and edit the live DOM and CSS. Right-click any element on the page and choose "Inspect" to jump to it. The Styles pane shows which CSS rules apply; toggle properties, change values, add new ones — the page updates instantly, but changes are **not** saved to your file.
- **Console** — JavaScript errors and logs. (Needs JS knowledge; covered in the JavaScript course.)
- **Network** — every file request the page makes, with status codes. A 404 here means a broken image/link/CSS path.
- **Sources** — view your files, set breakpoints (JS debugging).

**Device toolbar:** Ctrl+Shift+M (or the phone icon) simulates a phone/tablet. The page reflows as if on that device. Great for testing responsive behavior.

**Common debugging scenarios:**

- "My image is not showing" — check Network tab for a 404; fix the `src` path.
- "My CSS is not applying" — check Elements tab for selector mismatches and overridden rules (struck-through).
- "The layout is broken" — check the Computed pane for width, height, margin, padding, border.
- "Nothing happens on click" — check Console for JS errors (later).
- "My edit disappeared after refresh" — DevTools edits are temporary; make the change in your source file.

**Debugging loop:** inspect -> identify -> fix in source -> save -> refresh -> verify.

**Debugging scenarios:**

- "I changed text in Elements and it vanished on refresh" — expected; DevTools edits live only in the browser. Edit the source file.
- "I cannot find the right node in a big page" — right-click the element on the page and choose "Inspect" to jump straight to it.
- "My phone layout looks wrong but desktop is fine" — toggle the device toolbar (Ctrl+Shift+M) and test at 375px.
- "A file loads on desktop but 404s on deploy" — paths are case-sensitive on most servers. Match exact casing.

## Common Mistakes

- Editing in DevTools and expecting it to save (it does not).
- Ignoring the Network tab when images/CSS fail to load.
- Not using "Inspect" to find the right node in a big page.
- Testing only on desktop and never simulating a phone.
- Forgetting to hard-refresh when testing favicons or cached assets.

## Try It Yourself

1. Open any page, press F12, explore the four tabs.
2. Right-click an element -> Inspect; change its text in Elements and watch it update.
3. Refresh the page and confirm the change is gone (temporary).
4. Open Network tab, reload, find a 404 by breaking an image path.
5. Toggle the device toolbar and resize to 375px (phone).

## Summary

- DevTools: F12 / Ctrl+Shift+I.
- Elements = live DOM/CSS (temporary edits).
- Network = requests/404s.
- Sources = files/breakpoints.
- Device toolbar = simulate phones.
- Always verify in DevTools when something looks wrong.

## In Your Own Words

1. Do edits made in the Elements tab save to your files?

<details>
<summary>Show Answer</summary>

**Sample Answer:** No. DevTools edits are temporary and live only in the browser. Refreshing the page reverts them. You must make the same change in your source file to keep it.

</details>

2. Which DevTools tab helps you find a broken image?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The Network tab. It lists every file request with its status code. A 404 means the image path is wrong. Fix the `src` in your HTML accordingly.

</details>

3. How do you simulate a phone screen in DevTools?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Press Ctrl+Shift+M (or click the phone/tablet icon) to toggle the device toolbar, then choose a device or set a custom width. The page reflows as if on that screen size.

</details>
