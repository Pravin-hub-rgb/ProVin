# Doc 1.20 — HTML Entities

## Where We Are So Far

`1.19` covered semantic HTML. Now HTML entities — showing special characters safely. Connection: you have written tags with `<` and `>`; now how to display those same characters as text.

## Broader Goal

Display reserved characters (`<`, `>`, `&`) and special symbols using named or numeric entities.

---

## Main Content

The problem: `<` starts a tag. If you want to show the literal text `<h1>` on a page, the browser thinks a tag is starting and your page breaks. The fix: a special code that stands in for the character. It starts with `&`, then a name, then `;`. The browser shows the character without treating it as markup.

Start from a page that explains HTML and needs to show a tag. Guess: type `<h1>` directly? The browser parses it as a tag and nothing shows (or renders an empty heading). Guess: use `&lt;h1&gt;`? The browser shows `<h1>` as text. The second guess is right.

**Core entities:**

```html
<p>5 &lt; 10</p>        <!-- 5 < 10 -->
<p>10 &gt; 5</p>       <!-- 10 > 5 -->
<p>Tom &amp; Jerry</p>  <!-- Tom & Jerry -->
<p>She said &quot;hi&quot;</p>  <!-- She said "hi" -->
```

Line by line: `&lt;` renders `<`. `&gt;` renders `>`. `&amp;` renders `&` (needed because `&` starts every entity). `&quot;` renders `"`. `&apos;` renders `'`.

**Non-breaking space:**

```html
<p>Price:&nbsp;&nbsp;&nbsp;&nbsp;400</p>
```

`&nbsp;` is a space that survives whitespace collapsing and prevents a line break between the words it joins. Do not use it for layout spacing — use CSS.

**Symbols via named entities:**

```html
<p>&copy; 2026 My Site</p>
<p>&euro;50 &nbsp; &pound;40 &nbsp; &yen;300</p>
<p>&larr; &rarr; &uarr; &darr;</p>
```

**Numeric entities (for anything without a name):**

```html
<p>&#128512; &#127829; &#128640;</p>
```

`&#number;` uses the character's position in the Unicode table. Named entities are easier to read but only common symbols have names; everything else is reachable by number.

**Debugging scenarios:**

- "My entity shows as literal text `&lt;`" — you forgot the trailing `;`. Add it: `&lt;`.
- "My page broke after adding `&`" — an unescaped `&` makes the browser try to parse an entity. Escape it as `&amp;`.
- "My layout uses `&nbsp;` for spacing" — works but is wrong. Use CSS margin/padding.
- "My emoji entity does not render" — the number is wrong or you used `&` without `#`. Use `&#number;` with the correct Unicode code point.

## Common Mistakes

- Forgetting the trailing `;` — entity may not render.
- Writing `&` without escaping in text — browser tries to parse an entity.
- Using `&nbsp;` for layout spacing instead of CSS.
- Confusing entity names (e.g., `&copy` without semicolon).
- Nesting entities or double-escaping.

## Try It Yourself

1. Display the literal text `<h1>` on a page using entities.
2. Write `Tom & Jerry` correctly.
3. Create a gap with four `&nbsp;` and compare to CSS margin.
4. Add `&copy;` and a few arrows.
5. Use a numeric entity for an emoji and confirm it renders.

## Summary

- Entity syntax: `&name;` or `&#number;`.
- Core: `&lt;`, `&gt;`, `&amp;`, `&quot;`, `&nbsp;`.
- Named entities for common symbols (`&copy;`, `&euro;`).
- Numeric entities reach anything in Unicode.
- Always include the trailing semicolon.

## In Your Own Words

1. Why do we need `&lt;` and `&gt;`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Because `<` and `>` start and end HTML tags. To display them as literal text, you use `&lt;` and `&gt;`. Otherwise the browser interprets them as markup and the page breaks.

</details>

2. What does `&nbsp;` do that a normal space does not?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `&nbsp;` is a non-breaking space that survives HTML's whitespace collapsing (multiple normal spaces collapse to one) and prevents a line break between the words it joins. Normal spaces collapse and can break lines.

</details>

3. What is the difference between named and numeric entities?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Named entities (`&copy;`) are readable but only exist for common symbols. Numeric entities (`&#128512;`) use the character's Unicode position and can reach any character, including those without a name.

</details>

## Cheat Sheet (Quick Recall)

**Core:** `&lt;` `<`, `&gt;` `>`, `&amp;` `&`, `&quot;` `"`, `&nbsp;` space.

**Symbols:** `&copy;`, `&euro;`, `&larr;`, etc. **Numeric:** `&#number;`.

**Rule:** escape reserved chars; semicolon required.
