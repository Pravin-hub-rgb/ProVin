## Main Content

The problem: a web address travels as plain text across the internet. Only a limited set of characters is safe in a URL — English letters, digits, and a few symbols. A space is not allowed, and neither are non-English letters. The fix: swap unsafe characters for a percent sign plus two hex digits representing the character's code.

Start from a Google search for "hello world." Look at the address bar: the space becomes `+` (in the query string after `?`) or `%20`. Both forms work. That observation is the whole mechanism — unsafe characters get swapped for safe codes so the address can travel as plain text.

**Observe it yourself:** search Google for "hello world" and look at the address bar.

```text
https://www.google.com/search?q=hello+world
https://www.google.com/search?q=hello%20world
```

Both work. `+` is a shorthand for space in query strings; `%20` is the general form.

**How it works:**

- `%20` = space (hex 20 = decimal 32).
- `%C3%A9` = é (UTF-8 bytes for é).
- Safe chars (letters, digits, `-`, `_`, `.`, `~`) need no encoding.

**Try it:** type `https://www.google.com/search?q=hello%20world` in the address bar and press Enter. The search still works; the box shows "hello world".

**URL encoding vs HTML entities:**

| | URL encoding | HTML entities |
|---|---|---|
| Where | Web addresses (URLs) | HTML content |
| Space becomes | `+` or `%20` | `&nbsp;` or normal space |
| Less-than becomes | `%3C` | `&lt;` |
| Purpose | Make addresses safe to travel as text | Display reserved chars as text |

Do not mix them up: use entities in HTML content, percent-encoding in URLs.

**Debugging scenarios:**

- "My link with a space in the filename 404s" — the browser encodes it, but if you built the URL by hand you may have missed it. Let the browser or your framework encode it.
- "My search shows `%20` in the search box" — you percent-encoded a URL that was already encoded (double-encoding). Encode once, at the point of building the URL.
- "My non-English filename breaks on the server" — the server expects a specific encoding (usually UTF-8). Match it.
- "I used `&nbsp;` in a URL" — wrong domain. Use `%20` in URLs.

## Common Mistakes

- Manually typing `%20` in visible page text instead of a space.
- Forgetting that paths and query strings may encode differently.
- Double-encoding (`%2520`) by encoding an already-encoded URL.
- Assuming all characters are safe in URLs.
- Confusing URL encoding with HTML entities.

## Summary

- URLs carry only a safe character set.
- Unsafe chars (space, non-English) are percent-encoded (`%20`) or `+` for space in queries.
- Encoding makes addresses travel safely as plain text.
- URL encoding ≠ HTML entities — different domains, different rules.
- Avoid double-encoding.

## In Your Own Words

1. Why does a space become `%20` or `+` in a URL?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A URL can only safely carry a limited set of characters; a space is not allowed. So it is encoded: `%20` (percent + hex code for space) in general, or `+` as a shorthand in query strings. This lets the address travel as plain text.

</details>

2. What is the difference between URL encoding and HTML entities?

<details>
<summary>Show Answer</summary>

**Sample Answer:** URL encoding (percent-encoding) makes characters safe inside web addresses (space -> `%20`). HTML entities display reserved characters as text in page content (`<` -> `&lt;`). Different domains, different purposes — do not mix them.

</details>

3. What does "double-encoding" mean and why avoid it?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Encoding an already-encoded URL (e.g., turning `%20` into `%2520`). It happens when you encode a URL that is already encoded. The server then fails to decode it correctly. Encode once, at the point of building the URL.

</details>

## Cheat Sheet (Quick Recall)

**Safe chars:** letters, digits, `-`, `_`, `.`, `~`. **Space:** `+` or `%20`. **Other:** `%` + 2 hex digits.

**URL encoding vs entities:** different domains.

**Avoid double-encoding.**
