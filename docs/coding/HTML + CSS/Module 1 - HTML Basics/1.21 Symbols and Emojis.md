# Doc 1.21 — Symbols and Emojis

## Where We Are So Far

`1.20` covered HTML entities. Now symbols and emojis — characters you cannot easily type. Connection: entities showed how to encode characters; now symbols/emojis as characters in the Unicode table.

## Broader Goal

Use symbols and emojis correctly, understanding the role of UTF-8 and the difference between pasting and encoding.

---

## Main Content

Symbols and emojis are characters in the giant Unicode table. The problem beginners create: they paste an emoji, save the file in the wrong encoding, and it turns into garbage. Or they assume emojis are images. The fix is understanding that they are characters that need UTF-8, and that numeric entities work anywhere.

Start from a page that needs a euro sign. Guess: paste € directly? Works only if the file is UTF-8 and charset is declared. Guess: use `&euro;`? Works in any charset. Both are valid; the second is safer for portability.

**Symbols via entities (always safe):**

```html
<p>Price: &euro;50 &nbsp; &pound;40 &nbsp; &yen;300</p>
<p>Arrows: &larr; &rarr; &uarr; &darr;</p>
<p>Math: &times; &divide; &plusmn; &ne;</p>
<p>&hearts; &spades; &check;</p>
```

Line by line: each `&name;` is a named entity for a symbol. Named entities are readable but only common symbols have names. Everything else can be reached by its Unicode number.

**Emojis — two ways:**

```html
<!-- Version 1: pasted directly (needs UTF-8) -->
<p>I love coding 😄</p>
<p>Pizza time 🍕</p>
<p>Rocket launch 🚀</p>

<!-- Version 2: numeric entities (works in any charset) -->
<p>I love coding &#128512;</p>
<p>Pizza time &#127829;</p>
<p>Rocket launch &#128640;</p>
```

Line by line: pasting works when the file is saved as UTF-8 and `<meta charset="UTF-8">` says so. The numeric version uses the character's position in the Unicode table and is plain ASCII text, so it works regardless of charset.

**Why pasting works:** your file is saved as UTF-8 and `<meta charset="UTF-8">` says so. The browser reads the emoji's bytes using the Unicode table, so no special code is needed. The numeric version works even if the file's charset were something else, because the entity is plain ASCII text converted by the browser.

**The charset test:** if you set charset to ISO-8859-1 and open the file from disk, pasted emojis (and Hindi) garble, while numeric entities still render. That is the same lesson as Module 0: same bytes, wrong table, wrong characters.

**Symbols/emojis vs images:** they are characters, so they inherit font size and color and scale smoothly. Images are separate files. Use characters for simple glyphs; images for complex art.

**Debugging scenarios:**

- "My pasted emoji shows as �" — file is not saved as UTF-8 or charset is wrong. Save as UTF-8 and declare `<meta charset="UTF-8">`.
- "My numeric entity shows as literal text" — you forgot the `#` or the semicolon. Use `&#number;`.
- "My emoji looks different on iPhone vs Windows" — expected; each platform has its own glyph set. Emojis are characters, not images.
- "My symbol does not inherit color" — you used an image instead of a character. Switch to the character.

## Common Mistakes

- Pasting emojis without declaring UTF-8 — they garble.
- Saving the file in a non-UTF-8 encoding while declaring UTF-8.
- Using emoji images when a character would do (or vice versa).
- Assuming all emoji render identically across OS/browsers (they do not — each platform has its own glyph set).
- Overusing emojis in professional content.

## Try It Yourself

1. Paste three emojis into a paragraph with UTF-8 declared; confirm they render.
2. Write the same three as numeric entities; compare.
3. Change charset to ISO-8859-1, save, open from disk — observe garbling.
4. Revert to UTF-8 and hard-refresh.
5. Add a few symbols (`&euro;`, arrows) and style them with CSS color.

## Summary

- Symbols via entities or direct paste (UTF-8).
- Emojis are Unicode characters; paste with UTF-8 or use `&#number;`.
- Numeric entities work in any charset; pasted chars need UTF-8.
- Symbols/emojis inherit font size/color (characters, not images).
- Declare UTF-8 early and save files as UTF-8.

## In Your Own Words

1. Why can you paste an emoji directly into HTML?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Because the file is saved as UTF-8 and `<meta charset="UTF-8">` tells the browser to read bytes using the Unicode table, which includes emojis. No special code is needed. If the charset were different, the bytes would be misread and garble.

</details>

2. What is the advantage of numeric entities (`&#128512;`) over pasting?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Numeric entities are plain ASCII text, so they work regardless of the file's charset. Pasted emojis rely on UTF-8 being declared and the file saved as UTF-8. Numeric entities are safer for portability; pasting is more readable.

</details>

3. Are emojis images or characters?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Characters (Unicode code points). They inherit font size and color and scale like text. They are not image files. Rendering differs by platform/OS since each uses its own glyph set.

</details>

**Symbols:** entities (`&euro;`) or paste (UTF-8).
