# Doc 1.19 — Semantic HTML

## Where We Are So Far

`1.18` covered iframes. Now semantic HTML — tags named for their job. Connection: you have seen `div` and `span` as neutral containers; now tags that describe what each part of the page is.

## Broader Goal

Replace anonymous `div` piles with meaningful tags, understand the semantic family, and adopt clean HTML writing habits.

---

## Main Content

The problem: a page built from nothing but `div`. Four `div`s — top, menu, content, bottom. To you they are different jobs; to the browser, screen reader, and search engine they are identical and meaningless. The fix: give different jobs different tag names. Semantic means "the tag's name describes its meaning," not how it looks.

Start from a page with four `div`s. Guess: keep them and add classes like `class="header"`? That works for CSS but carries no meaning for assistive tech or search engines. Guess: use `<header>`, `<nav>`, `<main>`, `<footer>`? That carries meaning in the tag itself. The second guess is the one to reach for.

**The layout family (block elements, no special look by default):**

```html
<header>
  <h1>My Website</h1>
</header>

<nav>
  <a href="index.html">Home</a>
  <a href="pages/about.html">About</a>
</nav>

<main>
  <article>
    <h2>First Post</h2>
    <p>Self-contained content.</p>
  </article>

  <aside>
    <p>A related note, not the main content.</p>
  </aside>
</main>

<footer>
  <p>Written by me.</p>
</footer>
```

Line by line: `<header>` is the top of a page or section. `<nav>` is a group of navigation links. `<main>` is the central content (one per page). `<article>` is self-contained content that could stand alone (post, news story, product card). `<aside>` is related but not central (sidebar, note, ad). `<footer>` is the bottom of a page or section. `<section>` (not shown) is a themed group within a page, usually with its own heading. `<figure>`/`<figcaption>` wrap media with its caption (see `1.11`).

**article vs section:** ask "could this stand alone on another site?" If yes, `article`. If it is just one part of a bigger whole, `section`.

**When to still use `div`:** when no semantic tag fits — e.g., a wrapper purely for styling or grouping. Semantic first, `div` as fallback. Same for `span` among inline elements.

**HTML-only style habits (keep these from day one):**

- Use lowercase tag and attribute names.
- Indent nested elements consistently (2 spaces).
- Always quote attribute values.
- Put one element per line for readability.
- Close tags in the right order (no overlapping).
- Prefer semantic tags; use `div`/`span` as fallback.

These habits make your HTML readable, diff-friendly, and maintainable — and they carry into every framework later.

**Debugging scenarios:**

- "My page looks the same after switching to semantic tags" — expected; semantic tags have no default styling. Check the DOM in DevTools to confirm the structure changed.
- "My screen reader still cannot find navigation" — you used `<div class="nav">` instead of `<nav>`. Switch to `<nav>`.
- "I have two `<main>` elements" — invalid; only one per page. Merge or remove one.
- "My `<article>` is not standalone" — you used it for a sidebar snippet. Use `<aside>` or `<section>` instead.

## Common Mistakes

- Using `div` for everything instead of semantic tags.
- Confusing `article` and `section`.
- Assuming semantic tags look different — they do not (no default styling).
- Putting `main` more than once or nesting it inside `article`.
- Using semantic tags for styling instead of meaning.

## Try It Yourself

1. Rebuild a page using `header`, `nav`, `main`, `footer` instead of `div`s.
2. Add an `article` and an `aside` inside `main`.
3. Wrap an image in `figure` with `figcaption`.
4. Compare the page's appearance before/after — it should look identical.
5. Audit a page: replace one `div` with the most fitting semantic tag.

## Summary

- Semantic tags describe their job: `header`, `nav`, `main`, `footer`, `article`, `section`, `aside`, `figure`/`figcaption`.
- They look like `div` but carry meaning.
- `div`/`span` are fallbacks when no semantic tag fits.
- `article` = standalone; `section` = themed group.
- Adopt clean HTML habits from day one.

## In Your Own Words

1. What does "semantic" mean in HTML?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The tag's name describes the meaning/purpose of its content, not how it looks. E.g., `<nav>` means "navigation links," `<article>` means "self-contained content." This helps screen readers, search engines, and developers understand the page structure.

</details>

2. When should you use `<div>` instead of a semantic tag?

<details>
<summary>Show Answer</summary>

**Sample Answer:** When no semantic tag fits — e.g., a wrapper purely for styling or grouping. The rule: look for a semantic tag first; use `div` as the fallback.

</details>

3. What is the difference between `<article>` and `<section>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `<article>` is for self-contained content that could stand alone (blog post, news story, product card). `<section>` is a themed group of content within a page, usually with its own heading (a chapter). Ask "could this stand alone?" — yes means article.

</details>
