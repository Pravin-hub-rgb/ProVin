## Main Content

This module is about playing sound and video on a web page. Module 3 was about drawing things on the page; this one is about putting media on it: songs, podcasts, clips, even a YouTube video.

Before `<video>` and `<audio>` existed, browsers could not play much on their own. Sites needed outside add-ons (plug-ins) like Flash. Now the browser does it by itself, the same way it already shows text and images. That is why the plug-ins lecture (4.3) is mostly history.

**Why a tag instead of a link:** if you just link to a video file, the visitor must leave your page or download the file before watching. With the `<video>` tag, the player sits right inside your page next to your text, so people press play without going anywhere. Same idea as using `<img>` instead of a link to a picture: your page stays the star and the media is part of it.

**The two tags:** `<video>` for moving pictures (with optional sound), `<audio>` for sound only. Both are container elements that can hold `<source>` children and fallback text.

**Basic video (with a public sample link):**

```html
<video src="https://www.w3schools.com/html/mov_bbb.mp4" controls style="border: 2px solid red;"></video>
```

Line by line: `src` is the address of the video file. `controls` is the one word that gives you the whole player: play/pause, timeline, volume, fullscreen, and a settings menu (download, speed, picture-in-picture). Without `controls`, the video just shows its first frame (or the poster image) with no way to start it. The red border is the debugging trick. I used a public sample clip so you do not need your own file.

**Basic audio (with a public sample link):**

```html
<audio src="https://www.w3schools.com/html/horse.mp3" controls></audio>
```

Line by line: same idea as video but for sound. With `controls` you get a slim player bar (play, timeline, volume) — there is no picture, so the video-only attributes (`poster`, `width`, `height`) do not apply. Without `controls`, an audio tag shows nothing at all (no visual UI by default), so the player simply vanishes.

**`<source>` + fallback text (more flexible than `src` on the tag):**

```html
<video controls style="border: 2px solid red;">
  <source src="https://www.w3schools.com/html/mov_bbb.mp4" type="video/mp4" />
  Your browser does not support the video tag.
</video>
```

Line by line: the address moves into a `<source>` child, which also carries a `type` telling the browser what kind of file it is (e.g. `video/mp4`, `audio/mpeg`). The plain sentence at the bottom is fallback text: it only shows if a browser is too old to understand the `<video>` tag at all.

**Multiple sources (format fallback):** not every browser plays every format. MP4 works almost everywhere, but some prefer WebM or OGG. List several versions of the same media and the browser goes down your list top to bottom, playing the first one it understands.

```html
<video controls>
  <source src="video.mp4" type="video/mp4" />
  <source src="video.webm" type="video/webm" />
  <source src="video.ogg" type="video/ogg" />
</video>
```

Line by line: three versions of the same clip. The browser tries MP4 first; if it cannot play that, it tries WebM, then OGG. The order you write is the order of priority. For a single browser that understands all of them, it plays the first one and the rest are ignored. Swap the order and, if that browser supports both, nothing changes — the difference only shows on a browser that cannot play the first one.

Same trick for audio:

```html
<audio controls>
  <source src="audio.ogg" type="audio/ogg" />
  <source src="audio.mp3" type="audio/mpeg" />
</audio>
```

Line by line: OGG first, MP3 second. Notice the MP3 type is `audio/mpeg`, not `audio/mp3` (a common trip-up). The browser plays the first format it supports.

**Common formats:** audio — MP3, WAV, OGG. Video — MP4, WebM, OGG. Pick by what your target browsers support, not by habit. MP4 (video) and MP3 (audio) are the safest defaults.

**A note on player appearance:** the controls look a bit different in Chrome, Firefox, and Safari, since each browser draws its own.

**Debugging scenarios:**

- "My video is just a still picture" — `controls` is missing. Add it.
- "My audio player vanished" — audio has no picture; without `controls` there is nothing to draw. Add `controls`.
- "My video shows a broken/empty box" — the `src` path or URL is wrong. Check the Network tab for a 404.
- "Nothing plays even though the file loads" — the `type` on `<source>` does not match the file (e.g. `video/mp4` on a WebM file). Fix the MIME type.
- "My page shows the fallback sentence" — the browser is too old for `<video>`/`<audio>`, or the tag is malformed. Fix the markup.
- "My first source never plays but the second does" — the first format is not supported by that browser; that is expected, the fallback worked. Reorder if you want a different priority.
- "My video is huge and slow" — you served a massive file. Compress and offer multiple formats/sizes.

## Common Mistakes

- Missing `controls` (no UI to start playback).
- Wrong MIME type in `<source>` (file loads but does not play).
- Omitting fallback text (old browsers show nothing useful).
- Linking to a media file instead of embedding it (visitor leaves your page).
- Serving huge media without compression.
- Assuming all browsers support one format.

## Try It Yourself

1. Embed a video with `controls` using a public sample URL; press play.
2. Remove `controls` and confirm you only see the first frame.
3. Add `<source>` with `type` and fallback text; confirm it plays.
4. List two video formats and check which one your browser picks (Network tab).
5. Embed an audio file; remove `controls` and confirm the player vanishes.
6. Test fallback text by deliberately breaking the tag name.

## Summary

- `<video>` and `<audio>` embed media inside your page (vs. linking out).
- `controls` gives the built-in player (play/pause, timeline, volume, fullscreen).
- `<source src type>` allows multiple formats; browser plays the first it supports.
- Fallback text shows only in browsers too old for the tag.
- Common formats: audio MP3/WAV/OGG; video MP4/WebM/OGG.
- Audio has no visual UI by default; video shows its first frame without controls.

## In Your Own Words

1. Why use a `<video>` tag instead of a link to a video file?

<details>
<summary>Show Answer</summary>

**Sample Answer:** A link makes the visitor leave your page or download the file before watching. The `<video>` tag keeps the player inside your page next to your text, so people press play without going anywhere — like using `<img>` instead of a link to a picture.

</details>

2. What does the `controls` attribute do, and what happens without it?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `controls` gives the built-in player (play/pause, timeline, volume, fullscreen, settings). Without it, a video shows only its first frame (or poster) with no way to start; an audio tag shows nothing at all.

</details>

3. Why list more than one `<source>` inside a video/audio tag?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Different browsers support different formats. Listing several versions lets the browser go down the list and play the first one it understands, so your media works across browsers. Order is priority.

</details>

4. Name two common video formats and two common audio formats.

<details>
<summary>Show Answer</summary>

**Sample Answer:** Video: MP4, WebM (also OGG). Audio: MP3, WAV (also OGG). MP4 and MP3 are the safest defaults.

</details>

5. What is fallback text in a `<video>`/`<audio>` tag, and when does it show?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The plain text placed between the opening and closing tags. It shows only in browsers too old to understand the `<video>`/`<audio>` element; modern browsers ignore it and play the media.

</details>

## Cheat Sheet (Quick Recall)

**Tags:** `<video>`, `<audio>`. **`controls`** = built-in player. **`src`** or **`<source src type>`**. **Fallback text** inside tags. **Multiple sources** = browser picks first supported (top to bottom). **Formats:** audio MP3/WAV/OGG; video MP4/WebM/OGG. **Audio has no visual UI** without controls. **Video shows first frame** without controls.
