# Doc 4.1 — Video

## Where We Are So Far

`4.0` introduced media tags, `controls`, `<source>`, and formats. Now the video-specific attributes: `poster`, `autoplay`, `muted`, `loop`, `width`/`height`, plus responsive sizing. Connection: you can embed a video; now you control how it looks and behaves before and during playback.

## Broader Goal

Use `<video>` attributes to set a thumbnail (`poster`), auto-start (with the `muted` catch), loop, and size it correctly — including why a fixed width breaks on small screens and how to fix it later with CSS.

---

## Main Content

A `<video>` tag has extra attributes that control playback and appearance. We'll go one at a time so each effect is visible.

**`poster` — thumbnail shown before play:**

```html
<video controls poster="https://www.w3schools.com/html/pic_trulli.jpg" width="320" src="https://www.w3schools.com/html/mov_bbb.mp4"></video>
```

Line by line: `poster` takes the address of an image and shows it until the user presses play (then the video takes over). Without it, the browser shows the first frame, which you saw in 4.0. `width="320"` shrinks the box to a tidy size; height adjusts on its own to keep the aspect ratio right. In real projects use a proper thumbnail (a striking frame from the video) so viewers know what they are about to watch.

**`autoplay` — start without a click (with a catch):**

```html
<video autoplay src="https://www.w3schools.com/html/mov_bbb.mp4"></video>
```

Line by line: `autoplay` asks the browser to start the video as soon as it loads. The catch: browsers usually block autoplay unless the video is muted. Edge may allow it with sound; Firefox is usually stricter and refuses. Same code, different browsers — which is exactly why the rule is unreliable.

Try the same page in Firefox: with `autoplay` only (no `muted`), playback is blocked. The behavior varies by browser and settings.

**`muted` — no sound, and the fix for autoplay:**

```html
<video autoplay muted src="https://www.w3schools.com/html/mov_bbb.mp4"></video>
```

Line by line: `muted` starts the video silent. Pair it with `autoplay` and browsers will start it on their own, everywhere. The viewer can still turn sound on with the volume button. So `autoplay` and `muted` almost always travel together; that pair is the safe habit (common for silent background videos on landing pages).

**`loop` — restart when it ends:**

```html
<video autoplay muted loop src="https://www.w3schools.com/html/mov_bbb.mp4"></video>
```

Line by line: `loop` is another one-word attribute, like `controls`. When the video ends, it jumps back to the start and plays again, forever. The sample clip is short, so you can watch it reach the end and restart. Usually combined with `autoplay` and `muted` for background videos.

**`width` / `height` — dimensions:**

```html
<video controls width="640" height="360" src="https://www.w3schools.com/html/mov_bbb.mp4"></video>
```

Line by line: `width` and `height` set the box size in pixels. If you set only `width`, height adjusts to keep the aspect ratio. Setting a fixed width like 320 keeps the video 320 px wide even on a tiny phone screen, so it can overflow the viewport.

**Responsive sizing caveat:** a fixed `width` does not shrink on small screens. The fix is CSS (`max-width: 100%; height: auto;` on the video), which we will revisit after learning CSS.

**Debugging scenarios:**

- "My video autoplays in Edge but not Firefox" — browsers block autoplay with sound. Add `muted` alongside `autoplay`.
- "My autoplay video has no sound" — that is the expected safe behavior; the viewer can unmute. If you need sound on load, you cannot reliably autoplay; require a click instead.
- "My thumbnail does not show" — `poster` URL is wrong or the image failed to load. Check the Network tab; without a valid poster the first frame shows.
- "My video is distorted" — you set both `width` and `height` with the wrong aspect ratio. Set only `width` and let height auto-adjust, or match the video's aspect ratio.
- "My video overflows on mobile" — fixed `width` does not shrink. Use the CSS fix in the note above.
- "Loop never restarts" — `loop` is misspelled or on the wrong element. It must be on the `<video>` tag.
- "Fullscreen button does nothing" — for a YouTube iframe this is `allowfullscreen` (see 4.4); for native `<video>`, fullscreen is part of `controls`.

## Common Mistakes

- `autoplay` without `muted` (blocked by most browsers).
- Missing `controls` (no UI).
- Wrong `poster` URL (falls back to first frame).
- Setting fixed `width`/`height` with a mismatched aspect ratio (distortion).
- Fixed width breaking responsiveness on small screens.
- Forgetting that `poster` is an image, not the video.

## Try It Yourself

1. Add a `poster` image; confirm it shows before play and disappears after.
2. Set `width="320"` only; confirm height auto-adjusts.
3. Test `autoplay` alone in Firefox and Edge; note the difference.
4. Add `muted` to `autoplay`; confirm it starts in both browsers.
5. Add `loop`; wait for the clip to end and watch it restart.
6. Shrink the browser window with a fixed width and observe overflow.

## Summary

- `<video>` attributes: `controls`, `autoplay`, `muted`, `loop`, `poster`, `width`/`height`.
- `poster` = thumbnail before play.
- `autoplay` usually needs `muted` (browser policy varies).
- `loop` restarts the video when it ends.
- Fixed `width` can overflow on small screens; fix with CSS later (`max-width: 100%; height: auto;`).
- Multiple `<source>` still applies for format fallback.
