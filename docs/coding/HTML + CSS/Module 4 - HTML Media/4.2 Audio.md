# Doc 4.2 — Audio

## Where We Are So Far

`4.1` covered video attributes (`poster`, `autoplay`, `muted`, `loop`). Now audio: same core idea, no picture, plus `preload` and format fallback. Connection: audio reuses `controls`, `autoplay`, `muted`, `loop`, and `<source>`; it adds `preload` for download behavior.

## Broader Goal

Embed sound with `<audio>`, understand that it has no visual UI by default, use `preload` (`none`/`metadata`/`auto`), and list multiple `<source>` formats with the correct MIME types.

---

## Main Content

Audio works almost exactly like video, but with no picture. Same idea, start simple.

**Basic audio (public sample):**

```html
<audio controls src="https://www.w3schools.com/html/horse.mp3"></audio>
```

Line by line: `src` points to the sound file; `controls` gives the slim player bar (play, timeline, volume). There is no screen, so `poster`, `width`, and `height` do not apply. Remove `controls` and the whole player vanishes — the audio tag is still on the page but, with no controls and no picture, there is nothing to draw, so it is completely invisible. That is the "no visual UI by default" behavior.

**Multiple sources (format fallback):**

```html
<audio controls>
  <source src="https://www.w3schools.com/html/horse.ogg" type="audio/ogg" />
  <source src="https://www.w3schools.com/html/horse.mp3" type="audio/mpeg" />
</audio>
```

Line by line: OGG first, MP3 second. The browser plays the first format it understands. Notice the MP3 type is `audio/mpeg`, not `audio/mp3` — a common trip-up. Both files are public samples, so this should play. Swap the order: if your browser supports both, nothing changes; the order only matters when a browser cannot play the first one, then it skips down the list.

**`preload` — how much to load before play:** it tells the browser how much of the audio to download before anyone presses play. Three values:

- `none` — download nothing until the user hits play. Saves data, but there is a short wait when they do.
- `metadata` — download only the basic info (like total length), so the player can show the full time.
- `auto` — let the browser download as much as it wants, so playback starts quickly.

```html
<audio controls preload="metadata" src="https://www.w3schools.com/html/horse.mp3"></audio>
```

Line by line: `preload="metadata"` fetches just the basic info. With `preload="none"` the player shows `0:00` for both current and total (nothing fetched, so the length is unknown). With `metadata` the player shows the real total (e.g. `0:00 / 0:01` for a short clip). On a page with many audio clips, `none` or `metadata` saves a lot of data; `auto` is good when you are sure the user will play it.

**Other shared attributes** (`autoplay`, `muted`, `loop`) work the same as in 4.1, including the `autoplay` + `muted` rule for browsers.

**Debugging scenarios:**

- "My audio player is gone" — `controls` is missing. Audio has no picture, so without controls there is nothing to draw. Add `controls`.
- "My audio does not play" — the `type` on `<source>` is wrong (e.g. `audio/mp3` instead of `audio/mpeg`). Fix the MIME type.
- "My page with 20 audio clips is slow" — every `preload="auto"` downloads on page load. Use `none` or `metadata` to save data.
- "Player shows 0:00 / 0:00" — `preload="none"` fetched nothing, so the length is unknown. Use `metadata` to show the total time.
- "First source never plays but the second does" — the first format is not supported by that browser; fallback worked. Reorder if you want a different priority.
- "My audio autoplays in Edge but not Firefox" — same as video: browsers block autoplay with sound. Add `muted`.

## Common Mistakes

- Missing `controls` (player invisible).
- Wrong MIME type (`audio/mpeg` for MP3, not `audio/mp3`).
- Using `preload="auto"` on pages with many clips (wastes bandwidth).
- Assuming audio needs `width`/`height`/`poster` (it does not).
- Forgetting that only the clicked/first supported source plays.

## Try It Yourself

1. Embed an audio file with `controls`; play it.
2. Remove `controls` and confirm the player vanishes.
3. Add two `<source>` tags; swap their order and note when (if) anything changes.
4. Test `preload="none"` vs `preload="metadata"` and compare the displayed time.
5. Add `autoplay muted loop` and confirm silent auto-play with repeat.

## Summary

- `<audio>` embeds sound; no picture, so no `poster`/`width`/`height`.
- `controls` shows the player bar; without it the tag is invisible.
- `preload`: `none` (nothing), `metadata` (basic info), `auto` (as much as possible).
- Multiple `<source>` with correct MIME types for format fallback.
- Shared attributes (`autoplay`, `muted`, `loop`) follow the same rules as video.

2. What are the three values of `preload`, and what does each do?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `none` loads nothing until play (saves data, short wait). `metadata` loads only basic info like total length. `auto` lets the browser download as much as it wants so playback starts quickly.

</details>

3. Why must an MP3 file use `type="audio/mpeg"` and not `audio/mp3`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `audio/mpeg` is the correct MIME type for MP3. `audio/mp3` is not standard, so a browser may fail to recognize and play the file. Always match the official MIME type.

</details>

4. When would you pick `preload="none"` over `preload="auto"`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** When a page has many audio clips and you want to save bandwidth — `none` loads nothing until the user presses play. Use `auto` only when you are sure the user will play it.

</details>

5. How does format fallback work for audio?

<details>
<summary>Show Answer</summary>

**Sample Answer:** List multiple `<source>` tags with different formats; the browser goes top to bottom and plays the first one it supports. Order is priority; a single browser that supports all of them plays the first.

</details>

## Cheat Sheet (Quick Recall)

**`<audio controls>`** player bar. **No `controls` = invisible.** **`preload`:** `none` / `metadata` / `auto`. **`<source src type>`** fallback (top to bottom). **MP3 type = `audio/mpeg`.** Shared attrs: `autoplay`, `muted`, `loop` (same rules as video).
