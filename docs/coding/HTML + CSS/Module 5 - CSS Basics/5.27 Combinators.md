# Doc 5.27 — Combinators

## Cheat Sheet (Quick Recall)

- Descendant: `div p` (any p inside div).
- Child: `div > p` (direct child only).
- Adjacent sibling: `h1 + p` (p immediately after h1).
- General sibling: `h1 ~ p` (all p after h1).

## Main Content

### THINK

Selectors can be combined to target specific relationships. First descendant, then child, then siblings.

### CONCEPT

```css
/* Descendant: any p inside div */
div p { color: blue; }

/* Child: direct p child of div */
div > p { color: green; }

/* Adjacent sibling: p immediately after h1 */
h1 + p { color: red; }

/* General sibling: all p after h1 */
h1 ~ p { color: gray; }
```

### CODE (gradual)

Stage 1 — Descendant:

```css
div p { color: blue; }
```

Stage 2 — Child:

```css

```

Stage 3 — Sibling:

```css

h1 ~ p { color: gray; }
```

## Common Mistakes

- Confusing descendant (space) with child (`>`).
- Overusing deep descendant selectors (specificity).
- Wrong sibling order.

**In Your Own Words**

1. What is a descendant combinator?

<details>
<summary>Sample Answer</summary>

**Answer:** Space: selects any descendant (e.g., `div p`).

</details>

2. What is a child combinator?

<details>
<summary>Sample Answer</summary>

**Answer:** `>`: selects direct children only.

</details>

3. What is an adjacent sibling combinator?

<details>
<summary>Sample Answer</summary>

**Answer:** `+`: selects element immediately after.

</details>

4. What is a general sibling combinator?

<details>
<summary>Sample Answer</summary>

**Answer:** `~`: selects all following siblings.

</details>

5. Difference between descendant and child?

<details>
<summary>Sample Answer</summary>

**Answer:** Descendant = any nested level; child = direct only.

</details>

## What It Is NOT

- ❌ Descendant is **not** direct child.
- ❌ Child is **not** all descendants.
- ❌ Sibling combinators are **not** for parent selection.
