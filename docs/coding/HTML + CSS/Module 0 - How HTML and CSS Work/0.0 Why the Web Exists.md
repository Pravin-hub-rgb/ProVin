## The Problem in 1989

Think about the last time you searched for something online. You typed a few words, hit enter, and within a second you had thousands of pages to choose from. That feels normal today. But in 1989, none of that existed. There was no Google, no websites, no clicking links. The web had not been invented yet.

So how did we get from nothing to this? That is the story of this doc. And understanding it matters because every single thing you will build in this course sits on top of those foundations.

Imagine you are a researcher at CERN, the physics lab in Switzerland, back in 1989. Thousands of researchers come from all over the world, work for a few months, and leave. Documents live on different computers, in different formats. Nobody can follow how they connect. Email and FTP already existed, so you could send a file to someone. But finding and linking documents across machines was painful. There was no way to say "this document refers to that one" and have it just work.

Tim Berners-Lee saw this problem and proposed a solution: let documents link to each other, whatever machine they live on. That is the seed of the web.

## The Timeline

- **1989** - Tim Berners-Lee proposes the web at CERN
- **1991** - First website goes live
- **1993** - CERN makes the technology free for everyone; the Mosaic browser makes the web easy to use
- **Browser wars** - Netscape vs Internet Explorer, each adding their own quirks
- **1994** - W3C (World Wide Web Consortium) founded to set standards
- **1994** - Hakon Wium Lie proposes CSS, because people were misusing HTML for styling

The gap was not sending files (email and FTP already existed). The gap was linking and finding - turning all of that into one click, in one program.

## Internet vs Web

```
┌─────────────────────────────────────────┐
│              THE INTERNET                │
│   (the global network of machines)      │
│                                         │
│   ┌─────────┐  ┌─────────┐  ┌───────┐  │
│   │   Web   │  │  Email  │  │ Games │  │
│   │ (pages) │  │ (mail)  │  │(apps) │  │
│   └─────────┘  └─────────┘  └───────┘  │
│                                         │
│   The web is ONE service on the internet │
└─────────────────────────────────────────┘
```

The internet is the global network of connected machines - the roads. The web is one service on top of it - a neighborhood on those roads. Email, file transfer, online games, and video calls all use the internet but are not the web.

Rule of thumb: all web use is internet use, but not all internet use is web use. If you open Gmail in your browser, that is the web. If you use an email app, that is the internet but not the web.

## The Three Inventions

Berners-Lee's solution needed three pieces:

```
URL  ──►  HTTP  ──►  HTML
(address)  (delivery)  (content)
   │          │          │
   │          │          └── "this is a heading, a paragraph, a link"
   │          └── "give me this page" → server sends back content
   └── "https://google.com/maps" → where to go
```

1. **URL (Uniform Resource Locator)** - the standard address of one resource. Not "universal" - "uniform" means every address follows the same format. A URL says what you want: `https://google.com/maps`.

2. **HTTP (HyperText Transfer Protocol)** - how it travels. Your browser sends a request ("give me this page"), the server sends back a response with the content. HTTP carries HTML, CSS, images, JavaScript - everything a page needs.

3. **HTML (HyperText Markup Language)** - what it contains. Labeled content: "this is a heading," "this is a link," "this is a paragraph."

**DNS (Domain Name System)** turns a name like `google.com` into an IP address (like `142.250.80.46`). Humans cannot remember numbers, so DNS does the lookup for you.

One-sentence recap: You type a URL, DNS turns the name into an IP address, the browser sends an HTTP request to that server, and the server sends back HTML that the browser shows as a page.

## W3C vs W3Schools vs MDN

**W3C (World Wide Web Consortium)** is the standards body that defines how HTML and CSS should work. **W3Schools** is a private tutorial site that borrowed the "W3" name - it is not affiliated with W3C. For trusted reference documentation, use **MDN (Mozilla Developer Network)**.

## Common Mistakes

- **Confusing internet and web** - the internet is the network (roads), the web is one service on top (a neighborhood). Email and video calls use the internet but are not the web.
- **"Universal" vs "Uniform"** - URL stands for Uniform Resource Locator, not Universal. Uniform means every address follows the same format.
- **W3C vs W3Schools** - W3C is the standards body. W3Schools is a private tutorial site. For trusted reference, use MDN.

## What It Is NOT

- The internet is **not** the same as the web - internet is the network, web is one service on top.
- URL does **not** stand for "Universal" - it is "Uniform," meaning every address follows the same format.
- W3C is **not** W3Schools - W3C is the standards body, W3Schools is a private tutorial site.
- HTML is **not** a programming language - it is markup (labels content). (Covered in detail in 0.1.)
