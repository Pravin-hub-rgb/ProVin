# Doc 0.2 — How the Browser Turns Files into a Page

## Cheat Sheet (Quick Recall)

- Browser parses HTML into the DOM (a tree of nodes).
- Browser parses CSS into the CSSOM (a second tree of styles).
- DOM + CSSOM combine into the Render Tree (only visible elements included).
- Layout calculates size and position of every element.
- Paint fills in colors, text, and images.
- Composite stacks layers into the final image you see (like Photoshop layers).
- Pipeline in one line: HTML -> DOM, CSS -> CSSOM, combine -> render tree, then layout, paint, composite.

HTML and CSS are just text files. You write them in a code editor, save them, and somehow they become a page with colors, text, and images on your screen. How does that happen?

The answer is a pipeline - a series of steps, each building on the last. The browser does not just "read" the file and show it. It transforms the text into structures, combines them, calculates positions, fills in pixels, and stacks everything together. Understanding this pipeline helps you understand why certain things are slow, why some CSS does not apply, and why the page looks the way it does.

```
  HTML file (text)          CSS file (text)
       │                         │
       ▼                         ▼
  ┌─────────┐              ┌─────────┐
  │   DOM   │              │  CSSOM  │
  │  (tree) │              │ (tree)  │
  └────┬────┘              └────┬────┘
       │                        │
       └────────┬───────────────┘
                ▼
         ┌─────────────┐
         │ Render Tree │  (only visible elements)
         └──────┬──────┘
                ▼
         ┌─────────────┐
         │   Layout    │  (size & position)
         └──────┬──────┘
                ▼
         ┌─────────────┐
         │    Paint    │  (colors, text, images)
         └──────┬──────┘
                ▼
         ┌─────────────┐
         │  Composite  │  (stack layers → final image)
         └─────────────┘
```

The browser reads the HTML file top to bottom and builds a tree called the **DOM** (Document Object Model). Each tag becomes a node in the tree. A tree fits because HTML is nested - elements sit inside other elements. Each node is an object that can be read and changed.

```html
<body>
  <h1>Hello</h1>
  <p>World</p>
</body>
```

Becomes:

```
body
├── h1 ("Hello")
└── p ("World")
```

The DOM is not the HTML file. The file is just text. The DOM is the living structure the browser builds from it. Think of the HTML file as a recipe and the DOM as the meal - the recipe is instructions, the meal is the result.

The browser reads all the CSS and builds a second tree called the **CSSOM** (CSS Object Model). This is where cascade conflicts get settled - when two rules clash (one says the heading is blue, another says it is red), the browser decides which one wins while building this tree.

The two trees combine into the **render tree**. It contains only visible things - elements with `display: none` are left out. Each node now knows both what it is (from the DOM) and how it should look (from the CSSOM). Think of it like this: the DOM is the skeleton, the CSSOM is the skin and clothes, and the render tree is the dressed person ready to be placed on stage.

Layout works out the size and position of every element. The render tree knows what each element looks like, but not where it goes or how big it is. Layout calculates the exact position and dimensions of every box on the page.

Paint fills in the actual pixels - colors, text, images. Where layout said things go, paint fills them in. If layout is the blueprint, paint is the construction - the walls get their color, the text gets its font, the images get drawn.

Composite is the final step where everything is put together into the one image you see. Think of it like Photoshop layers: the browser draws different parts of the page on separate layers, and composite stacks them together in the right order into the final picture.

JavaScript can manipulate the DOM - change text, add elements, respond to clicks. That is a topic for the JavaScript course. Scripts can pause the browser while it reads the page - details are covered in the JS course.

## Common Mistakes

- **Thinking the DOM is the HTML file** - the file is text, the DOM is the living tree the browser builds from it.
- **Confusing layout and paint** - layout decides where and how big, paint fills in colors and images.
- **Overcomplicating composite** - it is just the final stacking step. Photoshop layers is the right analogy.

1. What is the DOM?

<summary>Show Answer</summary>

**Sample Answer:** The DOM (Document Object Model) is the tree the browser builds after reading your HTML file. Each tag becomes a node. It is not the HTML file itself - the file is just text, the DOM is the living structure the browser creates from it. The DOM can be read and changed by JavaScript.

2. What are the six steps of the rendering pipeline, in order?

<details>
<summary>Show Answer</summary>

**Sample Answer:** (1) HTML -> DOM (build the content tree). (2) CSS -> CSSOM (build the style tree). (3) DOM + CSSOM -> Render Tree (combine, only visible elements). (4) Layout (calculate size and position of every element). (5) Paint (fill in colors, text, images). (6) Composite (stack layers into the final image). One line: HTML -> DOM, CSS -> CSSOM, combine -> render tree, then layout, paint, composite.

</details>

3. Why does the render tree only include visible elements?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Elements with `display: none` in their CSS are left out of the render tree. They still exist in the DOM, but they do not take up space and are not painted. This saves the browser from doing unnecessary work.

</details>

4. What is the difference between layout and paint?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Layout decides where each element goes and how big it is (position and dimensions). Paint fills in the colors, text, and images where layout said they go. Layout is geometry; paint is pixels.

</details>

## What It Is NOT

- The DOM is **not** the HTML file - the file is text, the DOM is the living tree.
- Layout is **not** the same as paint - layout is position and size, paint is colors and images.
- Composite is **not** about animation - it is the final stacking step. Animation is a separate topic.
- CSSOM is **not** the same as DOM - DOM is content and structure, CSSOM is styles.

## Cheat Sheet (Quick Recall)

**Pipeline:** HTML -> DOM -> CSS -> CSSOM -> Render Tree -> Layout -> Paint -> Composite.

**DOM:** tree of nodes, built from HTML. Not the file - the living structure.

**CSSOM:** style tree, built from CSS. Cascade conflicts settled here.

**Render tree:** DOM + CSSOM merged. Only visible elements included.

**Layout:** size and position of every element.

**Paint:** colors, text, images filled in.

**Composite:** final stacking (like Photoshop layers).

**JS:** can manipulate the DOM - covered in JS course. One sentence mention only.

**Key rule:** HTML -> DOM, CSS -> CSSOM, combine -> render tree, then layout, paint, composite.
