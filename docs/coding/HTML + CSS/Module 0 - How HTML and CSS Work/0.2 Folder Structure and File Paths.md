# Doc 0.2 — Folder Structure and File Paths

## Cheat Sheet (Quick Recall)

- Keep `index.html` at project root.
- Organize assets in folders: `css/`, `js/`, `images/`.
- Relative paths: `./css/style.css`, `../images/logo.png`.
- Absolute paths start from domain root: `/css/style.css`.
- Consistent naming (lowercase, hyphens) avoids broken links.

## Main Content

### THINK

A web project has multiple files: HTML, CSS, JS, images. They must be organized and linked with correct paths. Broken paths are a common beginner mistake. First folder structure, then relative vs absolute paths, then common mistakes.

### CONCEPT

**Recommended structure:**

```
my-project/
├── index.html
├── css/
│   └── styles.css
├── js/
│   └── app.js
└── images/
    └── logo.png
```

**Linking in HTML:**

```html
<link rel="stylesheet" href="css/styles.css" />
<script src="js/app.js" defer></script>
<img src="images/logo.png" alt="Logo" />
```

**Relative paths:**

- `./css/styles.css` — same folder level.
- `../images/logo.png` — go up one folder.

**Absolute paths:**

- `/css/styles.css` — from domain root (works on servers, not local files).

**Naming conventions:**

- Lowercase, hyphens: `my-page.html`, not `My Page.html`.
- No spaces in file names.

### CODE (gradual)

Stage 1 — Single file (no structure):

```html
<!-- index.html with inline CSS -->
```

Stage 2 — Separate CSS file:

```

```


Stage 3 — Organized folders:

```

```

## Common Mistakes

- Wrong relative path (e.g., `css/style.css` vs `css/styles.css`).
- Absolute paths on local files (`/css/...` does not work with `file://`).
- Spaces in file names.
- Forgetting to link the CSS file.

## Summary

- Keep `index.html` at root; organize assets in folders.
- Relative paths for local files; absolute for server.
- Consistent naming avoids broken links.

## What It Is NOT

- ❌ Absolute paths are **not** for local `file://` browsing.
- ❌ File names with spaces are **not** safe.
- ❌ Folder structure is **not** optional for larger projects.
