# Doc 2.2 — Form Elements

## Where We Are So Far

`2.0` and `2.1` covered the form container and its submission attributes. You know where data goes and how. Now the building blocks that actually collect the data: `input`, `textarea`, `select`, `button`, and `label`. Connection: the envelope is ready; now the fields that go inside it.

## Broader Goal

Learn each form control, how to pair labels with fields for accessibility, the difference between `<button>` and `<input type="submit">`, and the `value`-vs-visible-text rule in dropdowns, so you can build a usable, accessible form.

## Main Content

A form is useless without controls. HTML gives five core ones: `input`, `textarea`, `select`, `button`, and `label`. Each has a specific job.

**`<input>` — the workhorse.** A single-line field whose behavior is set by its `type` attribute (`text`, `email`, `password`, ...). It is a void element: no closing tag and no inner content.

```html
<input type="text" name="author">
```

**`<textarea>` — multi-line text.** Unlike `input`, it has an opening and a closing tag, and anything between them becomes the starting text. Use it for messages, comments, or any long free-form text. `rows` and `cols` set its visible size.

```html
<label for="msg">Message</label>
<textarea id="msg" name="msg" rows="4" cols="30"></textarea>
```

Line by line: the label pairs with the textarea via `for`/`id`; `rows="4"` gives four visible lines; `cols="30"` gives 30 characters of width; the value that gets submitted is whatever the user types (or the starting text if they leave it alone).

**`<select>` + `<option>` — a dropdown.** You use a `select` tag and put an `option` tag inside it for each choice. The `name` goes on the `select`, not on the options.

```html
<label for="city">City</label>
<select id="city" name="city">
  <option value="lko">Lucknow</option>
  <option value="del">Delhi</option>
</select>
```

Line by line: `select` is the dropdown container and carries the `name` that gets submitted; each `option` is one choice; the text between the option tags (`Lucknow`) is what the user sees; the `value` attribute (`lko`) is what actually gets sent.

**The value rule:** the `value` attribute is what travels to the server; the visible text is only for the user. Pick Delhi and submit — the URL shows `city=del`, not `city=Delhi`. If you leave `value` out entirely, the browser sends the visible text instead, so you would get `city=Delhi`. That is usually not what you want, because display text can change (translation, capitalization) while the value should stay stable.

**Empty value + `required`:** to force the user to pick a real option, add a placeholder option with `value=""` and put `required` on the `select`.

```html
<select id="city" name="city" required>
  <option value="">Choose a city</option>
  <option value="lko">Lucknow</option>
  <option value="del">Delhi</option>
</select>
```

The browser treats the select as "not filled in" only when the chosen option's `value` is an empty string. With `value=""`, the placeholder counts as nothing chosen, so `required` blocks submit. Without the empty value, the placeholder text becomes a real value and `required` is satisfied — wrong data. `required` goes on the `select` itself, not on the options.

**`<button>` — the clickable control.** Its `type` decides what it does:

- `submit` sends the form.
- `reset` clears all fields back to their starting values.
- `button` does nothing by itself; it is meant for JavaScript.

```html
<button type="submit">Search</button>
<button type="reset">Reset</button>
```

Catch: inside a form, a `<button>` with no `type` defaults to `submit`. So a button you meant for something else will still send the form unless you write `type="button"`.

There is also an older style, `<input type="submit" value="Search">`. It does the same job, but a `<button>` tag can hold other HTML inside it (like an icon), while `<input>` can only show plain text from `value`. Most modern code prefers `<button>`.

**`<label>` — the accessible name of a field.** You have seen it already; here is the full picture. The label is the text that tells the user what a field is for. Pair it with the field using `for` (on the label) and `id` (on the control), and they must match exactly.

```html
<label for="author">Author</label>
<input type="text" id="author" name="author">
```

That link does two things: clicking the label text puts the cursor in the box, and screen readers announce what the field is for. A form control without a label is unusable for screen-reader users and harder to click on mobile.

Two pairing styles:

```html
<!-- Explicit (preferred) -->
<label for="author">Author</label>
<input type="text" id="author" name="author">

<!-- Wrapped (no for/id needed) -->
<label>
  Author
  <input type="text" name="author">
</label>
```

The explicit form is preferred because the label and control can be separated in the layout, and assistive tech handles it most reliably.

**Putting it together:**

```html
<form action="/search" method="get">
  <label for="author">Author</label>
  <input type="text" id="author" name="author">

  <label for="msg">Message</label>
  <textarea id="msg" name="msg" rows="4" cols="30"></textarea>

  <label for="city">City</label>
  <select id="city" name="city" required>
    <option value="">Choose a city</option>
    <option value="lko">Lucknow</option>
    <option value="del">Delhi</option>
  </select>

  <button type="submit">Search</button>
  <button type="reset">Reset</button>
</form>
```

Line by line: the form sends with `get` to `/search`; `author` is a single-line text input with a label; `msg` is a multi-line textarea; `city` is a required dropdown whose placeholder has an empty value; the submit button sends everything; the reset button clears all fields to their starting values (so the placeholder option reappears).

**Debugging scenarios:**

- "My textarea shows the placeholder text as real content" — you put text between the tags expecting a placeholder. Put hint text in a `<label>` or `placeholder` attribute instead; content between tags is the default value.
- "Dropdown always sends the first item even when I pick nothing" — the first option has no `value`, so its visible text is sent. Add a placeholder option with `value=""` and `required` on the select.
- "My reset button submits the form" — the button has no `type`, so it defaults to `submit`. Write `type="reset"`.
- "My icon button shows no text" — with `<input type="submit">` the label comes from `value`. Switch to `<button>` and put the icon/text between the tags.
- "Screen reader does not announce my field" — the control has no associated `<label>`. Add one with matching `for`/`id`.
- "Clicking the label does nothing" — `for` and `id` do not match exactly. Fix the spelling/case.

## Common Mistakes

- Putting `name` on `option` instead of on `select`.
- Forgetting `value` on `option` and accidentally sending display text.
- Using `<textarea>` for a single line (use `<input type="text">`).
- Leaving `<button>` without `type` inside a form.
- Treating `<input type="submit">` and `<button type="submit">` as identical — they differ in what content they can hold.
- Pairing label and control with mismatched `for`/`id`.

## Try It Yourself

1. Build the form above and submit it; confirm `city=del` (value, not "Delhi") in the URL.
2. Remove `value` from an option and observe that the visible text is now sent.
3. Add a placeholder option with `value=""` and `required`; submit without choosing and watch the browser block.
4. Type into the fields, click Reset, and confirm they return to starting values.
5. Remove the `type` from a button and watch it submit unexpectedly.

## Summary

- `input`: single-line, void element, behavior set by `type`.
- `textarea`: multi-line, has open/close tags; content between tags is the default value.
- `select` + `option`: dropdown; `name` on `select`; `value` is sent, visible text is shown.
- Empty `value=""` + `required` on `select` forces a real choice.
- `button`: `submit`/`reset`/`button`; defaults to `submit` inside a form.
- `<button>` can hold HTML; `<input type="submit">` shows only `value` text.
- `label` paired via `for`/`id` gives accessibility and click-to-focus.

## In Your Own Words

1. What is the difference between `<input>` and `<textarea>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `<input>` is a single-line, void element (no closing tag) whose behavior is set by `type`. `<textarea>` is a multi-line control with opening and closing tags; text between the tags becomes its default value.

</details>

2. In a `<select>`, what gets sent to the server — the visible text or the `value`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The `value` attribute. The text between `<option>` tags is only what the user sees. If `value` is omitted, the visible text is sent instead.

</details>

3. How do you force a user to pick a real option in a dropdown?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Add a first option with `value=""` (empty) and put `required` on the `<select>`. The empty value counts as "nothing chosen", so `required` blocks submit until a real option is selected.

</details>

4. What is the default `type` of a `<button>` inside a form, and why does it matter?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `submit`. It matters because a button without an explicit `type` will send the form even if you intended it for another purpose (like a reset or a JS action).

</details>

5. How do you associate a `<label>` with a form control?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Put `for="x"` on the `<label>` and `id="x"` on the control, with matching values. Alternatively, wrap the control inside the `<label>`. The explicit `for`/`id` form is preferred.

</details>

## Cheat Sheet (Quick Recall)

**Controls:** `input` (single-line, void), `textarea` (multi-line), `select`+`option` (dropdown), `button` (submit/reset/button), `label` (accessible name).

**Dropdown rule:** `value` is sent, visible text is shown. Empty `value=""` + `required` forces a choice.

**Button:** defaults to `submit` in a form. `<button>` can hold HTML; `<input type="submit">` shows only `value`.

**Label:** `for` must match control's `id` exactly.
