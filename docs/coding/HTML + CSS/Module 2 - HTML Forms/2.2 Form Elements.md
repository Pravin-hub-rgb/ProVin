# Doc 2.2 — Form Elements

## Cheat Sheet (Quick Recall)

- `<input>`: text, email, password, etc.
- `<textarea>`: multi-line text.
- `<select>` + `<option>`: dropdown.
- `<button>`: submit/reset/button.
- `<label>`: accessible label.

## Main Content

### THINK

Forms need inputs. HTML provides input, textarea, select, button, label. First each element, then how they work together.

### CONCEPT

```html
<input type="text" />
<textarea></textarea>
<select>
  <option>Option 1</option>
</select>
<button type="submit">Submit</button>
<label for="name">Name</label>
```

- `<input>`: various types (text, email, etc.).
- `<textarea>`: multi-line.
- `<select>`/`<option>`: dropdown.
- `<button>`: submit/reset/button.
- `<label>`: accessible label (use `for` + `id`).

### CODE (gradual)

Stage 1 — Text input:

```html
<input type="text" />
```

Stage 2 — Textarea:

```html
<textarea rows="4" cols="50"></textarea>
```

Stage 3 — Select + button + label:

```html
<label for="country">Country:</label>
<select id="country">
  <option>India</option>
  <option>USA</option>
</select>
<button type="submit">Submit</button>
```

## Common Mistakes

- Missing `name` on inputs.
- Missing `label` (accessibility).
- Wrong `type` on button (submit vs button).

## Summary

- Form elements: input, textarea, select, button, label.
- Always pair label with input via `for`/`id`.

## What It Is NOT

- ❌ `<textarea>` is **not** for single-line (use `<input>`).
- ❌ `<select>` without `<option>` is **empty**.
- ❌ `<button>` without `type` defaults to submit.
