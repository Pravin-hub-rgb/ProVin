# Doc 2.1 — Form Attributes

## Cheat Sheet (Quick Recall)

- `action`: submit URL.
- `method`: `get`/`post`.
- `target`: where to display response (`_self`, `_blank`).
- `autocomplete`: on/off.
- `novalidate`: disable browser validation.

## Main Content

### THINK

The `<form>` tag has attributes controlling submission behavior. First action/method, then target/autocomplete/novalidate.

### CONCEPT

```html
<form action="/submit" method="post" target="_blank" autocomplete="off" novalidate>
```

- `action` — submit URL.
- `method` — `get`/`post`.
- `target` — response display (`_self`, `_blank`).
- `autocomplete` — browser autofill on/off.
- `novalidate` — disables HTML5 validation.

### CODE (gradual)

Stage 1 — action + method:

```html
<form action="/submit" method="post">
```

Stage 2 — target:

```html
<form action="/submit" method="post" target="_blank">
```

Stage 3 — autocomplete + novalidate:

```html
<form action="/submit" method="post" autocomplete="off" novalidate>
```

### TEST

Three questions:

1. What does `action` specify? (submit URL)
2. What does `method="post"` do? (sends data in body)
3. What does `novalidate` do? (disables browser validation)

**Checkpoint:** Create a form with various attributes and test.

## Common Mistakes

- Using `get` for passwords.
- Forgetting `action` (submits to current page).
- Misusing `target`.

## Try It Yourself

## What It Is NOT

- ❌ `get` is **not** for sensitive data.
- ❌ `novalidate` does **not** disable server validation.
- ❌ `target` is **not** for styling.
