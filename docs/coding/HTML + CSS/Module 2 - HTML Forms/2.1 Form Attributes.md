# Doc 2.1 — Form Attributes

## Where We Are So Far

`2.0` introduced the `<form>` container, `action`, `method`, `name`, and `label`. You can already build a working form. Now we configure how the whole form behaves when submitted: where the response opens, whether the browser may autofill, and whether built-in validation runs. Connection: the container exists; now its submission settings.

## Broader Goal

Learn the form-level attributes — `action`, `method`, `target`, `autocomplete`, `novalidate` — and how they control submission behavior, so you can choose `get` vs `post`, control the response destination, and turn browser validation on or off deliberately.

---

## Main Content

A `<form>` tag can carry attributes that apply to the entire submission. You already know `action` and `method`; the new ones are `target`, `autocomplete`, and `novalidate`.

```html
<form action="/submit" method="post" target="_blank" autocomplete="off" novalidate>
```

**`action` — the receiving URL.** Defaults to the current page if omitted. Set it explicitly so the form always goes where you intend, even if the page URL changes.

**`method` — `get` or `post`.** This is the most important choice, so compare them directly:

| | `get` | `post` |
|---|---|---|
| Where data goes | Appended to the URL as query params | In the request body |
| Visible in address bar | Yes | No |
| Bookmarkable/shareable | Yes | No |
| Typical use | Search, filters, reading data | Login, signup, saving, uploads |
| Sensitive data | No — never | Yes — but still needs HTTPS |
| Size limit | URL length (~2000 chars) | Much larger |

Rule of thumb: if the form *reads* or *searches*, use `get`; if it *creates, updates, or authenticates*, use `post`. Default is `get`, so always write `method` explicitly to avoid accidentally sending a password in the URL.

**`target` — where the response page opens.** By default the response replaces the current page (`_self`). Set `target="_blank"` to open the result in a new tab, which is useful for preview or search results you want to keep alongside the form.

```html
<form action="/search" method="get" target="_blank">
```

Other values: `_self` (default, same tab), `_blank` (new tab/window), `_parent` and `_top` (for frames/iframes). In normal pages you will mostly use `_self` or `_blank`.

**`autocomplete` — browser autofill.** Defaults to `on`, which is why your browser offers to fill in email, address, or saved passwords when you click a field. Set `autocomplete="off"` to ask the browser not to offer those suggestions — useful for sensitive one-time codes or fields where past entries would be wrong.

```html
<form action="/search" method="get" autocomplete="off">
```

Browsers may still ignore `off` for saved passwords or username fields for usability reasons, so treat it as a hint, not a guarantee. You can also set `autocomplete` on individual inputs to be more precise (e.g. `autocomplete="email"`).

**`novalidate` — skip built-in validation.** Browsers check some fields on their own before submitting: required fields must not be empty, `email` must look like an email, `number` must be in range, and so on. `novalidate` turns that checking off for the whole form.

```html
<form action="/search" method="get" novalidate>
```

To see the difference, first add `required` to an input:

```html
<input type="text" id="author" name="author" required>
```

Leave the box empty and click Search — the browser stops you with a message. Now add `novalidate` to the form and submit again with an empty box — this time it goes through. `novalidate` is handy for testing, for "save draft" flows, or when you handle validation entirely in JavaScript.

Important distinction: `novalidate` only disables the *browser's* checks. The server must always re-validate; never trust client-side validation alone.

**Debugging scenarios:**

- "My form always opens the result in a new tab" — `target="_blank"` is set on the form. Remove it or set `target="_self"`.
- "Autofill suggestions still appear after `autocomplete="off"`" — browsers can ignore it for passwords/usernames. That is expected; move sensitive handling to the server.
- "Validation messages never show" — `novalidate` is on the form. Remove it, or move it to a specific button via `formnovalidate` (see `2.5`).
- "My form submits but nothing happens / page just reloads" — `action` is missing, so it posts to itself. Set `action` explicitly.
- "Password ends up in the URL" — `method` defaults to `get`. Write `method="post"`.

## Common Mistakes

- Using `get` for passwords or any sensitive data.
- Forgetting `method` and silently getting `get`.
- Using `novalidate` to "fix" a broken form instead of fixing the validation rules.
- Assuming `autocomplete="off"` is a security control — it is a hint only.
- Confusing `target="_blank"` (new tab) with opening a new window (browsers usually tab it).

## Try It Yourself

1. Build a form with `action`, `method="get"`, and `required` on an input; submit empty and observe the browser block.
2. Add `novalidate` and confirm the empty submit now goes through.
3. Set `target="_blank"` and confirm the result opens in a new tab.
4. Toggle `autocomplete="off"` on a field you have typed in before; observe whether suggestions still appear.
5. Switch `method` to `post` and confirm the data leaves the address bar.

## Summary

- `action` sets the destination URL (default: current page).
- `method` is `get` (URL, bookmarkable, for reads) or `post` (body, for writes); default `get`.
- `target` controls where the response opens (`_self`, `_blank`, ...).
- `autocomplete` hints the browser about autofill (`on`/`off`).
- `novalidate` disables the browser's built-in validation for the whole form.
- Client-side validation is convenience only; the server must re-validate.

## Cheat Sheet (Quick Recall)

**Form attrs:** `action` (URL), `method` (`get`/`post`), `target` (`_self`/`_blank`), `autocomplete` (`on`/`off`), `novalidate`.

**get vs post:** URL vs body; bookmarkable vs not; reads vs writes; never passwords in `get`.

**novalidate** = skip browser checks only. **autocomplete** = hint only.
