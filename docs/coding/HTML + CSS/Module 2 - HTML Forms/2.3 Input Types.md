# Doc 2.3 — Input Types

## Where We Are So Far

`2.2` covered the form controls. The `<input>` element is the most flexible of them: one tag, many behaviors, chosen by the `type` attribute. Now we survey the input types and what each one does to validation and the on-screen keyboard. Connection: you know the controls; now the flavors of `<input>`.

## Broader Goal

Learn the input types grouped by purpose (text-like, numeric, date/time, choice, special), how each one validates and which keyboard it triggers on mobile, and the gotchas (radio grouping, file uploads, `tel` not validating), so you pick the right type for each field.

---

## Main Content

The `type` attribute on an `<input>` changes everything about the field: its appearance, the keyboard shown on phones, and the validation the browser applies. Using the right type gives you free validation and a better mobile experience; using `text` for everything throws both away.

**Text-like types** — they all look like a text box, but each behaves slightly differently:

- `text`: plain single-line text, the default.
- `email`: expects an email address; the browser checks for an `@` and a domain before submit, and on phones shows a keyboard with the `@` key.
- `password`: hides the characters as dots; does not validate format.
- `tel`: phone number; brings up a number keypad on phones, but does **not** check the format — that is up to you (use `pattern`).
- `url`: expects a full address starting with a scheme like `https://`; blocks submit otherwise.
- `search`: looks like a text box but browsers may add a small clear (×) button and it tells assistive tech this is a search field.

```html
<input type="text" name="name">
<input type="email" name="email">
<input type="password" name="pass">
<input type="tel" name="phone">
<input type="url" name="site">
<input type="search" name="q">
```

Try the email one: type `hello` and submit — the browser blocks it and asks for a valid email. Try the url one: type `google.com` without `https://` and submit — it blocks you; add `https://` and it goes through. `tel` and `password` never block on format; only `email` and `url` validate shape.

**Numeric types:**

- `number`: a box that only accepts digits, with small up/down arrows; `min`, `max`, and `step` constrain it.
- `range`: a slider the user drags; the value is not shown unless you display it yourself.

```html
<input type="number" name="age" min="1" max="100">
<input type="range" name="volume" min="0" max="10">
```

Type `500` into the number field with `max="100"` and submit — the browser says "please select a value that is not more than 100". The arrows also respect `step` (default 1).

**Date and time types:**

- `date`: calendar picker; submitted value is always `YYYY-MM-DD`.
- `time`: hour/minute picker; submitted as `HH:MM`.
- `datetime-local`: date and time together; submitted as `YYYY-MM-DDTHH:MM`.
- `month`: year and month only.
- `week`: year and week number.

```html
<input type="date" name="dob">
<input type="time" name="meet">
<input type="datetime-local" name="when">
```

The submitted format is fixed no matter how the browser displays it, so the server can parse it reliably. An empty date/time field is still submitted, just with no value (e.g. `meet=`).

**Choice types:**

- `checkbox`: an on/off tick. If unticked, **nothing is sent at all** for that name. Tick it and `name=value` is sent.
- `radio`: a single choice from a group. Radios that share the same `name` form one group where only one can be selected. Radios with different names do not group — you could tick both.
- `color`: a color picker; the submitted value is a hex code like `#400040`.
- `file`: lets the user pick a file from their computer.

```html
<input type="checkbox" id="news" name="news" value="yes">
<label for="news">Subscribe to newsletter</label>

<input type="radio" id="m" name="gender" value="male">
<label for="m">Male</label>

<input type="radio" id="f" name="gender" value="female">
<label for="f">Female</label>

<input type="color" name="fav">
<input type="file" name="photo">
```

Line by line: the checkbox sends `news=yes` only when ticked; the two radios share `name="gender"` so they are mutually exclusive and send `gender=male` or `gender=female`; color sends a hex code (the `#` is URL-encoded as `%23` in the address bar); file sends only the file's name with `get`.

**File upload gotcha:** with `get`, only the file's name is sent, not the file itself. To actually upload a file you need both changes on the form tag:

```html
<form action="/upload" method="post" enctype="multipart/form-data">
```

`post` puts the data in the request body, and `enctype="multipart/form-data"` tells the browser to package the file's contents properly. Without both, the file never reaches the server. You will not see this difference in the address bar because it only affects `post` requests; check the Network tab in DevTools if you want to verify.

**Special types:**

- `hidden`: shows nothing on the page, but its `name` and `value` are still submitted. Use it to pass data the user should not edit, like an ID or where they came from. Users can still see and change it with DevTools, so never trust it for anything secure.
- `submit`: sends the form (input version of the submit button).
- `reset`: clears the form.
- `button`: does nothing on its own; for JavaScript.

```html
<input type="hidden" name="source" value="homepage">
<input type="submit" value="Send">
<input type="reset" value="Clear">
<input type="button" value="Click me">
```

The text on these input-buttons comes from the `value` attribute, whereas with the `<button>` tag the text goes between the tags. They do the same jobs, just written differently. Most modern code prefers `<button>` because it can hold HTML like an icon.

**Debugging scenarios:**

- "I can select two radios at once" — they have different `name` values. Give them the same `name`.
- "My checkbox value is missing from the URL" — it was unticked. That is expected; unticked checkboxes send nothing.
- "File upload sends only the filename" — the form uses `get` or lacks `enctype="multipart/form-data"`. Switch to `post` + `multipart/form-data`.
- "`tel` accepts `abc`" — `tel` does not validate format. Add `pattern` (e.g. `pattern="[0-9]{10}"`).
- "My hidden field is being tampered with" — `hidden` is not secure; validate on the server.
- "The color value shows `%23` in the URL" — that is the URL-encoded `#`; the real value is `#400040`. Normal, not a bug.
- "Date shows in US format in the UI but `YYYY-MM-DD` in the URL" — the display format is locale-dependent; the submitted format is fixed. This is correct behavior.

## Common Mistakes

- Using `type="text"` for email and losing free validation.
- Radio buttons without a shared `name`.
- Missing `value` on radio/checkbox (then nothing meaningful is sent).
- Forgetting `method="post"` + `enctype="multipart/form-data"` for file uploads.
- Assuming `tel` validates phone numbers.
- Trusting `hidden` fields for security.
- Confusing `submit`/`reset`/`button` input types with the `<button>` tag's types.

## Try It Yourself

1. Build a form with `email`, `password`, `tel`, `url`, and `search` inputs; submit `hello` in the email and `google.com` in the url, and observe the blocks.
2. Add two radios with the same `name` and confirm only one can be selected; then give them different names and confirm both can be selected.
3. Add a checkbox, submit ticked and unticked, and compare the URL.
4. Add a color input, pick a color, and read the hex value in the URL.
5. Add a file input and submit with `get`; then switch to `post` + `enctype="multipart/form-data"` and observe the difference in DevTools.

## Summary

- Text-like: `text`, `email`, `password`, `tel`, `url`, `search` — `email` and `url` validate shape; `tel` does not.
- Numeric: `number` (digits, arrows, min/max/step), `range` (slider).
- Date/time: `date`, `time`, `datetime-local`, `month`, `week` — submitted in fixed formats.
- Choice: `checkbox` (on/off, sends nothing when off), `radio` (same `name` = one group), `color` (hex), `file` (needs post + multipart).
- Special: `hidden` (submitted but invisible, not secure), `submit`, `reset`, `button`.
- Pick the type that matches the data; you get free validation and better mobile keyboards.

## In Your Own Words

1. Which input types validate their format automatically, and which do not?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `email` and `url` validate format automatically. `tel` and `password` do not validate format (use `pattern` for `tel`). `text` does not validate either.

</details>

2. How do radio buttons become a single-choice group?

<details>
<summary>Show Answer</summary>

**Sample Answer:** By giving them the same `name` attribute. Radios with the same name are mutually exclusive; different names form independent groups.

</details>

3. What two things must a form have to actually upload a file?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `method="post"` and `enctype="multipart/form-data"` on the `<form>`. With `get`, only the filename is sent.

</details>

4. What does a `hidden` input do, and why is it not secure?

<details>
<summary>Show Answer</summary>

**Sample Answer:** It submits a name/value pair without showing anything on the page. It is not secure because users can view and modify it with browser DevTools, so the server must never trust it for sensitive decisions.

</details>

5. What happens when a checkbox is submitted while unticked?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Nothing is sent for that name. Unticked checkboxes are omitted entirely from the submitted data.

</details>

## Cheat Sheet (Quick Recall)

**Text-like:** `text`, `email` (validates @), `password` (masked), `tel` (keypad, no validation), `url` (needs scheme), `search` (clear button).

**Numeric:** `number` (min/max/step), `range` (slider).

**Date/time:** `date` (YYYY-MM-DD), `time` (HH:MM), `datetime-local`, `month`, `week`.

**Choice:** `checkbox` (sends nothing when off), `radio` (same name = group), `color` (hex), `file` (post + multipart).

**Special:** `hidden` (not secure), `submit`, `reset`, `button`.
