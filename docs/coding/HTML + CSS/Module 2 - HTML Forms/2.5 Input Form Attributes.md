# Doc 2.5 — Input Form Attributes

## Where We Are So Far

`2.4` covered input attributes that constrain a field. Now the attributes that let a single control override or join a form: `form`, `formaction`, `formmethod`, `formenctype`, `formnovalidate`, and `formtarget`. These are the per-control counterparts of the form-level attributes from `2.1`. Connection: you know form settings and field settings; now how one field or button can change the form's settings for itself.

## Broader Goal

Learn how to attach a control to a form by ID even from outside the form, and how a button can override the form's `action`, `method`, `enctype`, validation, and `target` for that one click, so you can build patterns like "Save draft" (skip validation) or "Preview" (open in new tab).

---

## Main Content

Sometimes one control needs different submit settings than the rest of the form. Input form attributes provide that: they attach a control to a form or override the form's own settings for a single button click.

**`form` — associate a control with a form by ID.** The control does not have to be nested inside the `<form>` tags. Set `form="f1"` where `f1` is the form's `id`, and the browser treats that control as part of that form on submit.

```html
<form id="f1" action="/search" method="get">
  <input type="text" name="title">
  <button type="submit">Search</button>
</form>

<input type="text" name="note" form="f1">
```

Line by line: the form has `id="f1"` and contains `title`; the `note` input sits outside the form tags but `form="f1"` links it to that form; on submit both `title` and `note` are sent. Remove `form="f1"` and `note` disappears from the submitted data, because an input outside a form with no association is ignored. The value of `form` must match the form's `id` exactly.

**`formaction` — override the destination for one button.** The form's own `action` applies by default; a button with `formaction` sends the data to a different URL instead, but only when that button is the one clicked.

```html
<form action="/save" method="get">
  <input type="text" name="title">
  <button type="submit">Save</button>
  <button type="submit" formaction="/draft">Save draft</button>
</form>
```

Line by line: both buttons submit the same `title` field; clicking Save goes to `/save`; clicking Save draft goes to `/draft`. All inputs in the form are sent either way — only the destination changes based on which button was clicked. Use `formaction` when the destinations are genuinely different pages.

A related pattern: give each button a `name` and `value` instead (e.g. `name="team" value="a"`), and both buttons go to the same address while the server reads `team=a` or `team=b`. Only the clicked button's name/value is sent. `formaction` is better for different destinations; `name`/`value` is simpler when one endpoint can handle both.

**`formmethod` — override how one button sends.** Same idea as `formaction`, but for the method. If the form says `post`, a button with `formmethod="get"` sends with `get` (data in the URL) when clicked.

```html
<form action="/search" method="post">
  <input type="text" name="author">
  <button type="submit">Save</button>
  <button type="submit" formmethod="get">Search</button>
</form>
```

Line by line: Save uses the form's `post`, so the address bar shows just `/search` with no data; Search uses `get`, so you see `/search?author=...`. A real use case: Save sends data privately with `post`, while a Search button on the same form uses `get` so the result URL can be bookmarked.

**`formenctype` — override the packaging for one button.** `enctype` controls how `post` data is packaged. The default is `application/x-www-form-urlencoded` (plain key=value pairs); `multipart/form-data` is needed for file uploads. `formenctype` lets one button choose its own packaging.

```html
<form action="/upload" method="post">
  <input type="file" name="photo">
  <button type="submit">Upload (default)</button>
  <button type="submit" formenctype="multipart/form-data">Upload (multipart)</button>
</form>
```

The first button uses default packaging, so the file's contents are not sent — just its name. The second packages the data as multipart, so the actual file goes through. You cannot see this in the address bar because it only affects `post` requests; check the Network tab in DevTools (look at the request's `Content-Type`). In practice most people just set `enctype` on the form itself, so this override is rarely needed.

**`formnovalidate` — skip validation for one button.** You already know `novalidate` on the whole form. `formnovalidate` does the same thing but for a single button, which is exactly what a "Save draft" button needs: the user should not have to fill every required field just to save a draft.

```html
<form action="/publish" method="post">
  <input type="text" name="title" required>
  <button type="submit">Publish</button>
  <button type="submit" formaction="/draft" formnovalidate>Save draft</button>
</form>
```

Line by line: Publish enforces `required` and blocks an empty title; Save draft skips all checks and submits anyway, going to `/draft`. Try it with the box empty: click Publish (blocked), then click Save draft (goes through). This is the classic use case for `formnovalidate`.

**`formtarget` — override where the response opens for one button.** Just like `target` on the form, but per button.

```html
<form action="/preview" method="get">
  <input type="text" name="title">
  <button type="submit">Preview here</button>
  <button type="submit" formtarget="_blank">Preview in new tab</button>
</form>
```

The first button opens the result in the same tab; the second opens it in a new tab. Try both and confirm the second opens a new tab.

**All six together:**

```html
<form id="f1" action="/save" method="post">
  <input type="text" name="title" required>
  <button type="submit">Save</button>
  <button type="submit" formaction="/draft" formnovalidate>Save draft</button>
  <button type="submit" formaction="/preview" formmethod="get" formtarget="_blank">Preview</button>
</form>

<!-- outside the form, still part of it -->
<input type="text" name="note" form="f1">
```

Line by line: the form has `id="f1"` and posts to `/save` by default, with `title` required; Save posts normally; Save draft skips validation and goes to `/draft`; Preview uses `get` and opens in a new tab at `/preview`; the `note` input is outside the form tags but `form="f1"` attaches it, so it is submitted with the rest.

**Debugging scenarios:**

- "My external input is not submitted" — the `form` attribute is missing or its value does not match the form's `id` exactly. Fix the spelling/case.
- "Both buttons go to the same URL even though I set `formaction`" — the override is on the wrong element, or the button's `type` is not `submit`. Put `formaction` on a `type="submit"` button.
- "Validation still runs on my Save draft button" — you used `novalidate` on the form instead of `formnovalidate` on the button, or the attribute name is misspelled. Use `formnovalidate` on that button.
- "My Preview button still uses `post`" — `formmethod` is misspelled or not on the button. Check spelling: `formmethod`, not `form-method`.
- "`formtarget` opens nothing new" — value must be `_blank` (with underscore). `_blank` not `blank`.
- "External control is ignored entirely" — an input outside a form with no `form` attribute is not associated with any form. Add `form="id"`.

## Common Mistakes

- `form` attribute referencing a non-existent or misspelled ID.
- Confusing `formnovalidate` (per button) with `novalidate` (whole form).
- Putting override attributes on an `<input>` that is not a submit button and expecting them to do anything.
- Overusing overrides until the form's behavior is hard to follow.
- Forgetting that only the clicked button's overrides apply.

## Try It Yourself

1. Put an input outside a form, associate it with `form="id"`, submit, then remove the attribute and confirm it disappears.
2. Add two buttons with different `formaction` values; click each and compare the path in the address bar.
3. Add a required field and a button with `formnovalidate`; submit empty via each button.
4. Override `method` on one button (`formmethod="get"`) and compare the address bar.
5. Override `target` on one button (`formtarget="_blank"`) and confirm a new tab opens.

## Summary

- `form="id"` attaches a control to a form by ID, even from outside the form.
- `formaction`, `formmethod`, `formenctype`, `formnovalidate`, `formtarget` override the form's own settings for that one button click.
- Only the clicked button's overrides apply.
- Classic uses: "Save draft" with `formnovalidate`, "Preview" with `formmethod="get"` + `formtarget="_blank"`.
- Overrides are per-button; keep the form's defaults sensible.

## In Your Own Words

1. What does the `form` attribute do?

<details>
<summary>Show Answer</summary>

**Sample Answer:** It associates a control (even one outside the `<form>` tags) with a form by matching the form's `id`, so that control is submitted with that form.

</details>

2. What is the difference between `formnovalidate` and `novalidate`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `novalidate` disables validation for the whole form. `formnovalidate` disables validation for a single submit button, so other buttons on the same form can still enforce it (e.g., "Save draft" skips checks while "Publish" keeps them).

</details>

3. When is `formaction` the right tool?

<details>
<summary>Show Answer</summary>

**Sample Answer:** When different submit buttons on the same form should send the data to different URLs. Only the clicked button's `formaction` applies.

</details>

4. Name one use case for `formmethod="get"` on a button in a `post` form.

<details>
<summary>Show Answer</summary>

**Sample Answer:** A "Search" or "Preview" button that should produce a bookmarkable URL while the main "Save" button submits privately with `post`.

</details>

5. Why must the `form` attribute's value match the form's `id` exactly?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The browser links the control to the form by that ID. A mismatch (spelling or case) means no association, and the control is ignored on submit.

</details>

## Cheat Sheet (Quick Recall)

**Associate:** `form="formId"` (control can be outside the form).

**Overrides (per button):** `formaction` (URL), `formmethod` (get/post), `formenctype` (packaging), `formnovalidate` (skip checks), `formtarget` (_self/_blank).

**Rule:** only the clicked button's overrides apply. Keep form defaults sensible.
