# Doc 2.4 — Input Attributes

## Main Content

An input attribute is an extra setting on an `<input>` (or other control) that changes how it behaves: making it mandatory, limiting its length, or showing hint text. Several you have already used (`type`, `name`, `id`, `required`, `min`, `max`); here is the full set.

**`value` vs `placeholder` — the most confused pair.**

- `value` sets the text that is already in the box. It is a real default: it gets submitted if the user does not change it.
- `placeholder` shows grey hint text that disappears as soon as the user starts typing. It is **never** submitted.

```html
<input type="text" name="author" value="Orwell">
<input type="text" name="author" placeholder="Enter author name">
```

Test both and submit without typing: the `value` field sends `author=Orwell`; the placeholder field sends `author=` (empty). Placeholder is a visual hint only.

Two important notes. First, placeholder is **not** a replacement for a `<label>`: it vanishes the moment someone types, and screen readers cannot rely on it, so always keep the label too. Second, placeholder is not a default value — if you need a pre-filled value, use `value`.

**`required` — mandatory field.** The browser blocks submission and shows a message if the field is empty. Works on text inputs, selects (with empty-value placeholder), textareas, and others.

```html
<input type="text" name="author" required>
```

**`readonly` vs `disabled` — both stop editing, but they differ in submission.**

- `readonly`: the user cannot edit the value, but it is still submitted, and the user can click into it and copy the text. Use it when the server still needs the value, like an order ID the user should see but not change.
- `disabled`: the field is greyed out, cannot be focused, and is left out of the submission entirely. Use it when the field is temporarily not relevant.

```html
<input type="text" name="a" value="one" readonly>
<input type="text" name="b" value="two" disabled>
```

Submit this form and the URL shows `a=one` but no `b`. That single test settles the difference: readonly is submitted, disabled is not. Students mix these up constantly, so make it a live demo.

Comparison:

| | `readonly` | `disabled` |
|---|---|---|
| User can edit | No | No |
| User can focus/copy | Yes | No |
| Submitted with form | Yes | No |
| Visually | Normal (sometimes slightly grey) | Greyed out |
| Use when | Value must be seen but not changed | Field not relevant right now |

**`min`, `max`, and `step` — numeric/date constraints.** You have used `min` and `max` on a number field. `step` sets the allowed increments.

```html
<input type="number" name="qty" min="0" max="100" step="5">
```

With `step="5"`, the valid values are 0, 5, 10, 15, ... Type `7` and submit — the browser blocks it and suggests the nearest valid numbers (5 and 10). `step` also controls how far the up/down arrows jump. These attributes also work on `range`, `date`, `time`, and other numeric/date types.

**`pattern` — your own validation rule via a regular expression.** The browser checks the entire value against the pattern and blocks submit on mismatch. Always add a `title` — it becomes the hint text in the error message.

```html
<input type="text" name="zip" pattern="[0-9]{6}" title="Enter a 6-digit zip code">
```

That pattern means exactly six digits, nothing else. Type `abc` and submit — the browser shows an error including your title text. Type `226001` and it goes through. Pattern is great for phone formats, zip codes, and custom codes that the built-in types do not cover.

**`minlength` and `maxlength` — character limits.**

```html
<input type="text" name="username" minlength="3" maxlength="10">
```

`maxlength` physically stops typing after 10 characters — the user cannot exceed it. `minlength` only complains on submit if there are fewer than 3 characters, and only if the user actually typed something, so an empty box still passes unless you also add `required`. Try typing a long word (it stops at 10), then try just two letters and submit (blocked).

**Putting constraints together:**

```html
<form action="/search" method="get">
  <label for="zip">ZIP code</label>
  <input type="text" id="zip" name="zip"
         placeholder="226001"
         required minlength="6" maxlength="6"
         pattern="[0-9]{6}"
         title="Enter a 6-digit ZIP code">

  <label for="qty">Quantity</label>
  <input type="number" id="qty" name="qty"
         min="1" max="10" step="1" value="1">

  <label for="code">Invite code (read-only)</label>
  <input type="text" id="code" name="code" value="ABC123" readonly>

  <button type="submit">Submit</button>
</form>
```

Line by line: `zip` is required, must be exactly 6 digits, cannot exceed 6 characters, and shows a placeholder hint; `qty` is a number between 1 and 10 defaulting to 1; `code` is pre-filled and visible but not editable, yet still submitted; submit sends all three.

**Debugging scenarios:**

- "My field shows hint text that gets submitted" — you used `placeholder` expecting a default. Use `value` for a real default.
- "My readonly field is not in the submitted data" — you actually used `disabled`. Switch to `readonly`.
- "My disabled field is being edited" — you used `readonly`. Switch to `disabled`.
- "Validation never triggers on an empty box" — `minlength` does not apply to empty values. Add `required`.
- "My pattern never matches anything" — the regex is invalid or does not anchor the whole value. Test it; remember the browser matches the entire value, not a substring.
- "The user can type more than maxlength" — `maxlength` is not supported on all types (e.g. `number`); enforce via `pattern` or JS, or use a `text` input.
- "My number field accepts decimals when I want integers" — set `step="1"` (or `step="any"` to allow any). Default step is 1 but browsers may still allow typed decimals; combine with `pattern` if strict.

## Common Mistakes

- Using `placeholder` as a label or as a default value.
- Confusing `readonly` (submitted) with `disabled` (not submitted).
- Thinking `minlength` validates empty fields (it does not; use `required`).
- Invalid or unanchored regex in `pattern`.
- Forgetting `title` on `pattern`, so the error message is unhelpful.
- Assuming client-side constraints are enough — the server must re-validate.

## Try It Yourself

1. Add `value="Orwell"` and `placeholder="Enter author"` to two fields; submit empty and compare the URLs.
2. Add `readonly` to one field and `disabled` to another with values; submit and confirm only the readonly one is sent.
3. Set `min="1" max="10" step="2"` on a number input; type `3` and submit, then type `4`.
4. Add `pattern="[0-9]{6}"` with a `title`; type `abc` then `226001`.
5. Set `minlength="3" maxlength="5"`; type a long word, then type two letters and submit.

## Summary

- `value` = real default, submitted; `placeholder` = hint, never submitted, not a label.
- `required` makes a field mandatory.
- `readonly` = not editable but submitted; `disabled` = not editable and not submitted.
- `min`/`max`/`step` constrain number/range/date/time inputs.
- `pattern` = custom regex validation; pair with `title`.
- `maxlength` stops typing; `minlength` validates on submit (only if non-empty).
- Client-side validation is convenience; the server must re-validate.

## Cheat Sheet (Quick Recall)

**value** = default, submitted. **placeholder** = hint, never submitted, not a label.

**required** = mandatory. **readonly** = not editable, submitted. **disabled** = not editable, not submitted.

**min/max/step** = numeric/date constraints. **pattern** = regex (add `title`). **maxlength** = hard cap; **minlength** = submit-time check (non-empty only).

Client validation = convenience; server must re-validate.
