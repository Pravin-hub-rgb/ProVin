# Doc 3.1 — SVG

## Where We Are So Far

## Broader Goal

## Main Content

SVG (Scalable Vector Graphics) is the other built-in way to draw on a page. The big difference from canvas: you do not need JavaScript. You write shapes as HTML tags, and the browser draws them. Each shape becomes a real node in the page, so you can change it later and it stays sharp at any size.

**Why SVG stays sharp:** canvas stores pixels (a fixed grid of dots), so zooming stretches the dots and looks blurry. SVG stores instructions ("circle, center here, radius 50"), so the browser redraws at the new size and it is always crisp. That is what "scalable" means, and why logos and icons are almost always SVG.

**Empty svg (the blank box):**

```html
<svg width="300" height="150" style="border: 2px solid red;"></svg>
```

Line by line: `<svg>` is the drawing area, like the canvas was. `width`/`height` set its size (default is also 300x150, same as canvas). The border is the same debugging trick. With nothing inside, it is just a blank box.

**Rectangle (`<rect>`):**

```html
<svg width="300" height="150" style="border: 2px solid red;">
  <rect x="20" y="20" width="150" height="75" fill="blue" />
</svg>
```

Line by line: `<rect>` draws a rectangle. `x`/`y` are the top-left corner, then `width`/`height` for size — the same four numbers idea as canvas `fillRect`. `fill="blue"` sets the color. Notice the shape is a normal tag inside the svg, with no JavaScript.

**Circle (`<circle>`):**

```html
<circle cx="250" cy="75" r="40" fill="green" />
```

Line by line: `cx`/`cy` are the center of the circle (not a corner), and `r` is the radius (distance from center to edge). The full width across is twice the radius (the diameter), so `r="40"` gives an 80 px circle. Here the center is at 250, 75, so it spans 210 to 290 across, fitting inside the 300 wide box. Try changing `fill` from blue to orange and refresh: the shape updates by editing the tag.

**Line (`<line>`):**

```html
<line x1="20" y1="120" x2="280" y2="120" stroke="black" stroke-width="3" />
```

Line by line: a line needs two points, `x1`/`y1` (start) and `x2`/`y2` (end). A line has no inside to fill, so instead of `fill` you give it a `stroke` (the line's color) and `stroke-width` (thickness). With both y values at 120, the line runs flat horizontally from left to right; if the two x values matched instead, it would be vertical.

**Polygon (`<polygon>`):**

```html
<polygon points="50,20 80,70 20,70" fill="purple" />
```

Line by line: one tag where you list all the corners as `x,y` pairs in the `points` attribute, and the browser connects them in order and closes the shape back to the first point. Three pairs make a triangle, four make a four-sided shape, six make a hexagon. Order matters: list corners out of order and the lines cross, giving a bow-tie instead of a clean shape. Try four pairs like `50,20 80,50 50,80 20,50` — you get a diamond (rhombus), because each corner is 30 away from the center at 50, 50.

**Path (`<path>`):** the most powerful shape; it can draw curves and any shape, using pen-instruction commands in the `d` attribute.

Straight line (M = move, L = line):

```html
<path d="M 20 140 L 120 140" stroke="red" stroke-width="3" fill="none" />
```

Line by line: `M 20 140` moves the pen to 20 from the left and 140 from the top without drawing. `L 120 140` puts the pen down and draws a line to 120, 140. M stands for "move", L for "line". The result is a flat horizontal line, just like the `<line>` tag. A path has a fill by default (black), and the browser closes the gap between end and start to make a shape, then paints inside it. Add `fill="none"` to turn the fill off and keep only the outline. Chain more commands to turn corners: `M 20 140 L 120 140 L 120 100` draws an L shape.

Curves (C = cubic Bezier):

```html
<svg width="300" height="150" style="border: 2px solid red;">
  <path d="M 220 30 C 100 0, 60 60, 150 75 C 240 90, 200 150, 80 120"
        fill="none" stroke="black" stroke-width="6" />
</svg>
```

Line by line: two curves joined into an S. Each `C` takes three points: the last one is where the curve ends, and the first two are control points that act like invisible magnets pulling the curve toward them (the line never touches them). Change a control point like `100 0` and watch the curve bend.

Blocky S using only M and L:

```html
<svg width="300" height="150" style="border: 2px solid red;">
  <path d="M 220 30 L 80 30 L 80 75 L 220 75 L 220 120 L 80 120"
        fill="none" stroke="black" stroke-width="6" />
</svg>
```

Line by line: read it as pen instructions — move to top right, line across the top, down the left, across the middle, down the right, across the bottom. `fill="none"` is already there, so no black fill appears.

**Sharpness test (canvas vs SVG):** draw the same circle in both, then zoom the browser to 500% (Ctrl/Cmd +). The canvas circle's edges get blurry or jagged because its pixels are stretched. The SVG circle stays crisp because the browser redraws it from instructions. That is why logos and icons are almost always SVG.

**Styling SVG with CSS:** SVG shapes are real tags, so they can be styled with CSS instead of attributes, and they support `:hover`. This only works for inline SVG (shapes written directly in your HTML), not for SVG loaded as an image.

```html
<!-- NOTE: revisit this after learning CSS -->
<style>
  .my-circle {
    fill: orange;
    stroke: black;
    stroke-width: 4;
  }
  .my-circle:hover {
    fill: green;
  }
</style>

<svg width="300" height="150" style="border: 2px solid red;">
  <circle class="my-circle" cx="150" cy="75" r="50" />
</svg>
```

Line by line: the `<style>` block says anything with class `my-circle` gets those colors; the circle tag no longer has `fill` on it, just `class="my-circle"`. The `:hover` part turns the circle green when the mouse is over it — possible only because SVG shapes are real tags on the page. Canvas cannot do this, since a canvas circle is just pixels. The HTML comment is a reminder to revisit after learning CSS.

**SVG vs canvas choice:** SVG for logos, icons, diagrams, charts with a modest number of elements, anything that must stay crisp at any zoom or be screen-reader accessible. Canvas for games, particle effects, image manipulation (pixel-level access), real-time visualizations with huge point counts. SVG is DOM-based (accessible, styleable, per-shape events like `circle.addEventListener("click", ...)`); canvas is immediate-mode (faster for thousands of objects). Ten thousand DOM nodes get sluggish; ten thousand `fillRect` calls do not.

**Debugging scenarios:**

- "My svg is invisible" — missing `width`/`height`, or no border. Add `width`/`height` and a red border to see the box.
- "My shape has a black fill I did not want" — paths and polygons fill by default. Add `fill="none"`.
- "My polygon looks like a bow-tie" — corners listed out of order. List them in clockwise/counter-clockwise order.
- "My line is invisible" — you used `fill` instead of `stroke`. Lines have no inside; use `stroke` and `stroke-width`.
- "My circle is cut off" — `cx`/`cy`/`r` place it outside the svg box. Check the span: center ± radius must fit inside width/height.
- "My SVG blurs when I zoom" — that should not happen for SVG; check you are not using a raster image or canvas instead. Inline SVG stays crisp.
- "CSS hover does nothing on my SVG" — the SVG is loaded as an image (`<img src="...svg">`) or via CSS background, not inline. Only inline SVG gives full DOM/CSS/JS access.
- "My shape does not respond to click" — use inline SVG; external/`<img>` SVG cannot receive per-shape events.

## Common Mistakes

- Missing `width`/`height` on `<svg>`.
- Forgetting `fill`/`stroke` (or using the wrong one for lines).
- Forgetting `fill="none"` on paths/polygons, causing unwanted black fills.
- Listing polygon corners out of order.
- Using CSS background/`<img>` for SVG and expecting DOM/CSS/JS access.
- Expecting SVG to need JavaScript (it does not, unless dynamic).

1. Draw an empty svg with a red border; confirm the 300x150 default.
2. Add a blue rect and a green circle; verify the circle's diameter is 2r.
3. Draw a horizontal line with `stroke` and `stroke-width`.
4. Draw a triangle with `<polygon>`; then try four corners for a diamond.
5. Draw an L shape with a path using M and L; add `fill="none"`.
6. Draw a curvy S with two C commands; change a control point.
7. Zoom to 500% and compare a canvas circle vs an SVG circle.
8. Add a class and `:hover` fill change; hover over the shape.

## Summary

- SVG = Scalable Vector Graphics, XML-based, resolution-independent.
- Inline `<svg>` with shapes: `<rect>`, `<circle>`, `<line>`, `<polygon>`, `<path>`.
- `cx`/`cy`/`r` for circles; `points` for polygons; `d` with M/L/C for paths.
- `fill` for inside, `stroke`/`stroke-width` for outline; `fill="none"` removes fill.
- SVG scales without quality loss; DOM-based and accessible.
- Inline SVG enables CSS styling and per-shape events.
- Choose SVG for objects; canvas for painted surfaces.

## Cheat Sheet (Quick Recall)

**`<svg width height>`** container (default 300x150). **Shapes:** `<rect x y width height>`, `<circle cx cy r>`, `<line x1 y1 x2 y2>`, `<polygon points>`, `<path d>`. **Path commands:** M (move), L (line), C (curve). **Fill vs stroke:** `fill` inside, `stroke`/`stroke-width` outline, `fill="none"` removes fill. **Scales without blur** (vector). **Inline only** for CSS/JS/events. **Canvas vs SVG:** painted surface vs described shapes.
