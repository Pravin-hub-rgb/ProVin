## Main Content

A web page usually shows text and images, but sometimes the picture has to be alive: a chart that updates when data changes, a game, a live visualization. A fixed image file cannot do that, because it is frozen. `<canvas>` is HTML's built-in way to draw with code instead of image files. It is a rectangular bitmap region: a grid of pixels that JavaScript paints on. The tag itself draws nothing; it only reserves the area. JavaScript holds the pen.

**Why code beats a picture sometimes:** a screenshot gets blurry when stretched and never changes. A canvas drawing can resize, animate, and react to clicks. One caveat: canvas is a bitmap, so unlike SVG (next doc) it can get blurry if stretched. Canvas is the "paint a surface every frame" tool.

**Empty canvas:**

```html
<canvas style="border: 2px solid red;"></canvas>
```

Line by line: `<canvas>` creates the drawing area. With no `width`/`height` it defaults to 300 pixels wide and 150 pixels tall. The `border` is a debugging trick: an empty canvas is invisible, so a border makes its outline visible. Without JavaScript, the canvas stays empty and invisible (except for that border). Canvas does not draw anything on its own.

**Confirm the default size:** open a page with just that tag and the red border. The box is 300 wide by 150 tall, roughly a small banner.

**Pick up the pen (the 2D context):**

```html
<canvas id="myCanvas" style="border: 2px solid red;"></canvas>

<script>
  const canvas = document.getElementById("myCanvas");
  const ctx = canvas.getContext("2d");
</script>
```

Line by line: `document.getElementById("myCanvas")` finds the canvas tag by its `id`. `canvas.getContext("2d")` asks that canvas for its 2D drawing tool, which is stored in `ctx` (short for context). Think of `ctx` as the pen. Nothing appears yet, because we picked up the pen but did not touch the paper. The `"2d"` string is required; it selects the 2D drawing API.

**Draw a rectangle:**

```js
ctx.fillStyle = "blue";
ctx.fillRect(20, 20, 150, 75);
```

Line by line: `ctx.fillStyle = "blue"` picks the color (shared state; it stays blue until changed). `ctx.fillRect(20, 20, 150, 75)` paints a filled rectangle. The first two numbers, `x` and `y`, are the position of the rectangle's top-left corner measured from the canvas's top-left (0, 0), with x going right and y going down. The last two are the size: width and height, not a second corner. So this box starts 20 px from the left and 20 px from the top, and is 150 px wide and 75 px tall; its bottom-right corner lands at 170, 95. Change the first two numbers and the box moves; change the last two and it stretches.

**Draw text:**

```js
ctx.font = "30px Arial";
ctx.fillStyle = "black";
ctx.fillText("Hello Canvas", 20, 130);
```

Line by line: `ctx.font = "30px Arial"` sets the size and typeface. `ctx.fillStyle = "black"` switches the color back, because `fillStyle` is shared (otherwise the text would be blue). `ctx.fillText("Hello Canvas", 20, 130)` draws the words. The `20` is how far from the left the text starts; the `130` is how far down from the top, but it marks the baseline, the invisible line the letters sit on (like writing on lined paper where the pen rests on the line). The letters rise upward from that line, which is why the words appear near the bottom of a 150 px tall canvas. Change 130 to 50 and the words jump up near the top.

Full working file:

```html
<canvas id="myCanvas" style="border: 2px solid red;"></canvas>

<script>
  const canvas = document.getElementById("myCanvas");
  const ctx = canvas.getContext("2d");

  // Blue rectangle
  ctx.fillStyle = "blue";
  ctx.fillRect(20, 20, 150, 75);

  // Text
  ctx.font = "30px Arial";
  ctx.fillStyle = "black";
  ctx.fillText("Hello Canvas", 20, 130);
</script>
```

**Sizing the canvas:** default is 300 by 150. Change it with `width` and `height` written as attributes on the canvas tag, not in CSS:

```html
<canvas id="myCanvas" width="500" height="300" style="border: 2px solid red;"></canvas>
```

Line by line: `width="500"` and `height="300"` set the actual pixel resolution of the bitmap. Setting size with CSS instead stretches the existing 300x150 bitmap, which makes it blurry. Always set `width`/`height` as attributes (or in JS via `canvas.width = 500`) when you want a different resolution. Canvas is a bitmap, so it does not get SVG's free resolution independence (next doc).

**Canvas vs SVG (preview):** canvas paints pixels and forgets them (immediate mode); to move a shape you clear and redraw. SVG keeps each shape as a DOM node (retained mode). Pick canvas for games, particle effects, image manipulation (pixel access via `getImageData`), and real-time visualizations with huge point counts. Pick SVG for logos, icons, diagrams, and charts with a modest number of elements that must stay crisp at any zoom and be screen-reader accessible. Rule of thumb: "a picture made of objects" -> SVG; "a surface I paint on every frame" -> canvas.

**Accessibility note:** canvas content is invisible to screen readers and search engines unless you add fallback content inside the tag, e.g. `<canvas>...fallback text...</canvas>`.

**Debugging scenarios:**

- "My canvas is invisible" — empty canvas has no border. Add `style="border: 2px solid red;"` to see its outline.
- "Nothing draws" — you forgot `getContext("2d")`, or the script ran before the canvas was in the DOM. Grab the context first, and put the script after the tag (or use `DOMContentLoaded`).
- "My rectangle is in the wrong spot" — remember x/y is the top-left corner, not the center. Check the first two numbers.
- "My box size is wrong" — the last two numbers are width and height, not the bottom-right corner. Compute bottom-right as x+width, y+height.
- "My text is clipped or missing" — the baseline (second number) is too large/small; text sits on that line. Try a smaller value like 50 to move it up.
- "Canvas looks blurry on my monitor" — you sized it with CSS instead of `width`/`height` attributes, or you are on a high-DPI screen without scaling by `devicePixelRatio`. Set attributes for resolution.
- "My drawing disappeared after I changed data" — canvas does not remember shapes; you must clear and redraw. (Use SVG if you want retained shapes.)

## Common Mistakes

- Missing `width`/`height` attributes (defaults to 300x150).
- Drawing before the canvas is in the DOM.
- Using CSS to size the canvas (stretches the bitmap, blurry).
- Forgetting that `fillStyle` is shared state.
- Expecting canvas to be accessible by default (add fallback content).
- Forgetting that canvas needs JavaScript to draw anything.

## Try It Yourself

1. Create an empty canvas with a red border; confirm it is 300x150.
2. Grab the 2D context and draw a blue rectangle at 20, 20, 150 wide, 75 tall.
3. Change the rectangle's first two numbers and watch it move; change the last two and watch it stretch.
4. Draw "Hello Canvas" at 20, 130; change 130 to 50 and observe the jump.
5. Set `width="500" height="300"` on the tag and confirm no blur.

## Summary

- `<canvas>` is a bitmap drawing area; JS draws via `getContext("2d")`.
- `fillRect(x, y, width, height)`: x/y is top-left corner, last two are size.
- `fillText(text, x, baseline)`: baseline is the line letters sit on.
- Size via `width`/`height` attributes, not CSS (avoids blur).
- Canvas needs JS; content invisible to screen readers without fallback.
- Canvas = paint a surface every frame; SVG = describe shapes (next doc).

## Cheat Sheet (Quick Recall)

**`<canvas>`** (bitmap) + JS. **`getContext("2d")`** = pen. **`fillRect(x, y, w, h)`** x/y = top-left corner. **`fillText(text, x, baseline)`** baseline = line letters sit on. **Size:** `width`/`height` attributes (not CSS). **Default:** 300x150. **Blurry if stretched** (bitmap). **Invisible to screen readers** without fallback. **Canvas vs SVG:** paint surface vs describe shapes.
