# 2.2 Your First LangGraph Chatbot

If 2.1 had a node that just printed "Hello!", this topic builds that into a **real chatbot** — where the model thinks and replies to every user message. Same graph, but now we plug **ChatGroq** (Groq's Llama 3.3 70B) in the middle, so you get a "Dost-to-Dost" style reply.

Setup is the same as Phase 1: keep `GROQ_API_KEY` in `.env`, `uv pip install langchain-groq langgraph langchain-core`. In code, `ChatGroq(model_name="llama-3.3-70b-versatile")` picks the key from the env.

## Graph — start → chatbot → end

```python
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import StateGraph, START, END, MessagesState

# A model — Groq's Llama 3.3 70B (free tier)
llm = ChatGroq(model_name="llama-3.3-70b-versatile")

# A node: send the state's messages to the model, return a new message
def chatbot(state: MessagesState):
    # system message always first — tell the model "you are a helpful friend"
    messages = [SystemMessage(content="Tum ek friendly, helpful dost ho. Hinglish mein reply karo.")] + state["messages"]
    return {"messages": [llm.invoke(messages)]}

# Wire the graph together
graph = StateGraph(MessagesState)
graph.add_node("chatbot", chatbot)
graph.add_edge(START, "chatbot")
graph.add_edge("chatbot", END)
graph = graph.compile()

# Take a user message, run, print the reply
user_query = "Tum kaun ho, or yeh graph kya hota hai?"
result = graph.invoke({"messages": [HumanMessage(content=user_query)]})
print(result["messages"][-1].content)
```

What each line means:

1. `ChatGroq(model_name=...)` — loads Groq's Llama 3.3 70B model; the API key comes from the env `GROQ_API_KEY`.
2. `HumanMessage` / `SystemMessage` — message types. HumanMessage is the user's question, SystemMessage is the model's personality.
3. `MessagesState` — LangGraph's built-in state that holds a `messages` list, working like a "chat history" up and down. Its `messages` is set via a **reducer** (`add_messages`) — meaning new messages get appended to the old ones.
4. `def chatbot(state)` — a node. It sends the old messages + system prompt to the model, and returns the model's response as a new `AIMessage`.
5. `StateGraph(MessagesState)` → `add_node` → `add_edge(START,"chatbot")` → `add_edge("chatbot",END)` → `compile()` — build the graph and make it runnable.
6. `graph.invoke({"messages":[HumanMessage(...)]})` — give direct input; the graph runs and returns the final state.
7. `result["messages"][-1].content` — the content of the last (newest) message in the state, which is the model's reply.

When you use the `add_messages` reducer, the old messages also survive into the next call — so this graph works like a **conversation**.

## What It Is NOT

⚠️ **This is NOT a LangChain `LLM` or `Runnable` chain.** A LangChain chain is a linear pipeline. A LangGraph graph is a **stateful flow** — state passes through every node, and it can branch or loop.

⚠️ **State is NOT a global object.** Every `invoke` call gets its own state. Stored state only comes back with a separate thread/checkpointer (covered in 2.4).

⚠️ **The response is NOT just the model.** The graph returns the updated state dictionary — all the keys and all the messages together.

## In Your Own Words

<details>
<summary>1. What does the state do after the graph runs once?</summary>

**Answer:** The graph updates the state it was given (adds messages) and returns it. If a checkpointer is attached, it saves too. Otherwise it stays within that same run.

</details>

<details>
<summary>2. Why is `add_edge(START, "chatbot")` necessary?</summary>

**Answer:** START is the graph's entry point. If no edge is connected from START, the graph doesn't know where to begin — so every graph must have at least one edge from START to a node.

</details>

<details>
<summary>3. Why should the system prompt always come first in the message list?</summary>

**Answer:** The model reads messages in sequence — what comes first carries more weight. Keep the system prompt first so the model treats it as a "personality," then the user query after it. Order matters.

</details>
