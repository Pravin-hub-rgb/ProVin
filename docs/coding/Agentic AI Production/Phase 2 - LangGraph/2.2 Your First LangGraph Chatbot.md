# 2.2 Your First LangGraph Chatbot

Agar 2.1 mein ek "Hello!" print karne wala node laga, toh yeh topic ussko badha kar ek **real chatbot** banayenge — jahan har user message pe model soch kar jawab de. Matlab: ekhi graph, lekin ab bich mein **ChatGroq** (Groq ka Llama 3.3 70B) chipkaenge, jisse "Dost-to-Dost" style ka jawab milta rahe.

Setup puche — Phase 1 ke samed: `.env` me `GROQ_API_KEY` rakho, `uv pip install langchain-groq langgraph langchain-core`. Code mein `ChatGroq(model_name="llama-3.3-70b-versatile")` env se key utha leta hai.

## Graph — start → chatbot → end

```python
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import StateGraph, START, END, MessagesState

# Ek model — Groq ke Llama 3.3 70B (free tier)
llm = ChatGroq(model_name="llama-3.3-70b-versatile")

# Ek node: state ke messages ko model ko bhej kar naya message return karo
def chatbot(state: MessagesState):
    # system message hamesha pehle — model ko "tum ek helpful dost ho" batao
    messages = [SystemMessage(content="Tum ek friendly, helpful dost ho. Hinglish mein reply karo.")] + state["messages"]
    return {"messages": [llm.invoke(messages)]}

# Graph jod do
graph = StateGraph(MessagesState)
graph.add_node("chatbot", chatbot)
graph.add_edge(START, "chatbot")
graph.add_edge("chatbot", END)
graph = graph.compile()

# Ek user message lo, run karo, jawab print karo
user_query = "Tum kaun ho, or yeh graph kya hota hai?"
result = graph.invoke({"messages": [HumanMessage(content=user_query)]})
print(result["messages"][-1].content)
```

Har line ka matlab:

1. `ChatGroq(model_name=...)` — Groq ke Llama 3.3 70B model ko load karta hai; API key env `GROQ_API_KEY` se milta hai.
2. `HumanMessage` / `SystemMessage` — message types. HumanMessage user ka sawal, SystemMessage model ki personality.
3. `MessagesState` — LangGraph ka built-in state jisme `messages` list hoti hai, upar neeche ek "chat history" ki tarah kaam karti hai. Iske andar `messages` ek **reducer** (`add_messages`) se set hoti hai — matlab nayi messages purane mein judti rehti hain.
4. `def chatbot(state)` — ek node. Use purani messages + system prompt ko model ko bhejta hai, aur model ka response as a new `AIMessage` return karta hai.
5. `StateGraph(MessagesState)` → `add_node` → `add_edge(START,"chatbot")` → `add_edge("chatbot",END)` → `compile()` — graph bana kar execute hone layak.
6. `graph.invoke({"messages":[HumanMessage(...)]})` — seedhi input dijiye; graph run hota hai aur return karta hai final state.
7. `result["messages"][-1].content` — state ke aakhiri (naye) message ka content, jo model ka jawab hota hai.

Jab aap `add_messages` reducer use karte hain, toh agle call mein purane messages bhi rehte hain — isliye yeh graph ek **conversation ke form mein** kaam karta hai.

## What It Is NOT

⚠️ **LangChain ke `LLM` ya `Runnable` chain nahi.** LangChain chain ek linear pipeline hota hai. LangGraph graph ek **stateful flow** — state har node se pass hota hai, branch/loop ho sakta hai.

⚠️ **State koi global object nahi.** Har `invoke` call apni state leta hai. Jo state store raha, usse alag thread/checkpointer ke saath hi milta hai (aagma jaane 2.4).

⚠️ **Response ek model hi return nahi.** Graph return karta hai updated state dictionary — jitne bhi keys, jitne bhi messages ek saath.

## In Your Own Words

<details>
<summary>1. Graph ek baar run hone ke baad state kya karta hai?</summary>

**Jawab:** Graph apne andar jo state leke aaya, usse update karta hai (messages add karta) aur return karta hai. Agar checkpointer laga ho toh save bhi karta. Nahi toh yeh wohi run ke andar reh jaati hai.

</details>

<details>
<summary>2. `add_edge(START, "chatbot")` kyu zaroori hai?</summary>

**Jawab:** START graph entry point hoti hai. Agar koi edge START se nahi lagi, toh graph ko pata nahi chal paata ki kahan se shuru kare — isliye har graph mein START se kami se kami ek node tak ka edge hona chahiye.

</details>

<details>
<summary>3. Message list mein system prompt hamesha pehle kyun rakhte hain?</summary>

**Jawab:** Model messages ko sequence mein padhti hai — jo pahle aata hai, uska weight zyada hota hai. System prompt pehle rakhenge toh model usse as a "personality" samajh karega, phir user query uske baad aayegi. Order ka matlab hota hai.

</details>
