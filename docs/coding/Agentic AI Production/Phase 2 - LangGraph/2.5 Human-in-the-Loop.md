# 2.5 Human-in-the-Loop

The agent from 2.4 now remembers, but it still can't say no to anything — it keeps moving straight ahead. There's no telling whether the agent might take a wrong action. Production agents are better when **a person intervenes** — like an intern who does the work after getting the boss's approval.

LangGraph gives `interrupt()` for this — the graph can stop at a point, the person gives feedback, and then it resumes the same way.

## Analogy — intern + boss

Think of an intern (the agent) who says: "Boss, I've made this tool call, please approve." The boss (the human) says "Yes" or "No." If "Yes" → the intern moves ahead. If "No" → cancel. The graph's `interrupt()` does exactly the "stop the intern" job.

## Code — pause at a critical action, resume with approval

```python
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage, AIMessage
from langgraph.graph import StateGraph, START, END, MessagesState
from langgraph.types import interrupt, Command

llm = ChatGroq(model_name="llama-3.3-70b-versatile")

# A node that first asks the person, then moves ahead
def cautious_assistant(state: MessagesState):
    action = state["messages"][-1].content

    # 🔴 The graph stops here — feedback goes to the person
    human_ok = interrupt(
        f"Agent ne kaha: {action!r}. Kya main isse approve karoonse? (yes/no)"
    )

    if human_ok and human_ok.strip().lower() == "yes":
        answer = llm.invoke([SystemMessage(content="Tum ek helpful dost ho."),
                             HumanMessage(content=action)])
        return {"messages": [AIMessage(content=answer.content)]}
    return {"messages": [AIMessage(content="Action user response cancel kar diya — approved nahi hua.")]}

graph = StateGraph(MessagesState)
graph.add_node("assistant", cautious_assistant)
graph.add_edge(START, "assistant")
graph.add_edge("assistant", END)
graph = graph.compile()

# 1st invoke — the graph stops at the interrupt
result = graph.invoke({"messages": [HumanMessage(content="Send email to CEO")]})
print("__interrupt__" in result)   # True — means the graph paused

# 2nd invoke — give human feedback (resume):
result2 = graph.invoke(Command(resume="yes"))
print(result2["messages"][-1].content)
```

How it runs:

1. `interrupt("...?")` — the graph can **stop** (pause) instantly. Its return value comes from the person's response.
2. When `interrupt()` runs, the `result` gets an `__interrupt__` key — meaning "I'm paused, you tell me what to do."
3. `graph.invoke(Command(resume="yes"))` — a signal to "move ahead." The `resume` value is exactly what `interrupt()` returned — that is, `human_ok`.

> Note: this way you can ask the person through an approval UI, a Slack message, or any tool. In real production there's often a dashboard button that sends `resume`.

## Use case

Whenever the agent takes a **high-impact action** (payment, email to the CEO, deleting an account) — get approval from a person's hand first. Keep the risk under control.

## What It Is NOT

⚠️ **`interrupt()` is NOT an exception/halt.** The graph is NOT "closed" — it's just **paused**. It waits for a resume. Not a crash — an intentional stop.

⚠️ **Human feedback can only be a resume string.** If you want a structured object (JSON), you can put that in `resume` too — `Command(resume={"approved": True, "notes": "OK"})`.

⚠️ **Don't attach it to every node.** Intervene only when needed — overuse makes the agent stop for too long. Use it only for critical actions.

## In Your Own Words

<details>
<summary>1. Are `interrupt()` and `resume()` the same thing?</summary>

**Answer:** No. `interrupt()` **pauses** the graph (it stops at a point). `Command(resume=...)` **moves it ahead**. The first stops, the second starts.

</details>

<details>
<summary>2. What happens if you send `Command(resume="no")` in the 2nd invoke?</summary>

**Answer:** `interrupt()` expected `"yes"` — so `human_ok = "no"`. The `if human_ok... == "yes"` check fails, so the else branch runs and shows the "cancelled" message. Meaning the person said "no," so the action is cancelled.

</details>

<details>
<summary>3. Where is this `interrupt()` useful in production?</summary>

**Answer:** When the agent does risky work — like sending money, deleting something, sending an email. First get approval through a UI button/door from a person, then proceed by sending `resume`.

</details>
