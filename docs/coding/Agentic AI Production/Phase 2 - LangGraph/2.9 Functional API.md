# 2.9 Functional API

In 2.8 we wrote the full `StateGraph` class, `add_node`, `add_edge`, `route()` — everything. But for a small chatbot, all that boilerplate feels like a lot. LangGraph gives a **simpler way**: the **Functional API** — just write plain functions, and LangGraph manages the flow.

## StateGraph API vs Functional API

| StateGraph API (2.1–2.8) | Functional API |
|---|---|
| `StateGraph` class, `add_node`, `add_edge` — direct | `@entrypoint` decorator on a function — direct |
| Reducer/typing has to be handled by you | Inputs/outputs are simple — manage them |
| For complex flows (conditional, multi-agent) | For simple linear/parallel flows |

Both run on the same engine — the Functional API is just a thin wrapper that builds the StateGraph in the background.

## A chatbot — in the Functional API

```python
from langgraph.func import entrypoint
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage

llm = ChatGroq(model_name="llama-3.3-70b-versatile")

# one function = the whole graph
@entrypoint
def chatbot(inputs: dict):
    messages = [SystemMessage(content="Tum ek helpful dost ho. Hinglish mein reply karo.")] + inputs["messages"]
    response = llm.invoke(messages)
    return {"messages": [response]}

# run — feels like a plain function call
result = chatbot.invoke({"messages": [HumanMessage(content="LangGraph aur LangChain mein kya farq?")]})
print(result["messages"][-1].content)
```

Line by line:

1. `from langgraph.func import entrypoint` — the Functional API's decorator.
2. `@entrypoint` — this function becomes a graph. Inputs are a dict, return is a dict (state update).
3. `def chatbot(inputs)` — takes state (`inputs["messages"]`), gets a response from the model, returns `{"messages": [response]}`.
4. `chatbot.invoke(...)` — feels like a plain function call — but it runs inside the graph (checkpointer/streaming can be attached too).

## Parallel subtasks

The real fun of the Functional API — running subtasks **concurrently**. With `@task` you can run functions in parallel:

```python
from langgraph.func import entrypoint, task

@task
def fetch_a():
    ...

@task
def fetch_b():
    ...

@entrypoint
def workflow(inputs):
    a = fetch_a()          # both run at once
    b = fetch_b()
    done_a = a.result()    # wait until both complete
    done_b = b.result()
    return done_a + done_b
```

## Memory can be attached too

```python
from langgraph.checkpoint.memory import MemorySaver
from langgraph.func import entrypoint

@entrypoint(checkpointer=MemorySaver())   # <-- to remember
def chatbot(inputs: dict):
    ...
```

## When to use

- **Functional API** — when the flow is simple/parallel, or you want plain functions (prototype, small agent).
- **StateGraph API** — when you need conditional routing, multi-agent, complex state shapes.

## What It Is NOT

⚠️ **The Functional API is NOT "dumb" — it's just another API.** Both run on the same LangGraph engine. Functional only makes the syntax simpler.

⚠️ **Functions don't create global state.** Inputs/outputs are the state — if you need a value, pull it from the inputs and return it.

⚠️ **`@task` is always parallel.** Tasks run concurrently — if one fails, it can stop the other. When there's a dependency, take `.result()` in plain order.

## In Your Own Words

<details>
<summary>1. What does the `@entrypoint` decorator do?</summary>

**Answer:** It turns that function into a LangGraph graph — inputs become state, the return value becomes the graph's next state. A plain function, but LangGraph treats it as part of the workflow.

</details>

<details>
<summary>2. Why does `@task` run in parallel?</summary>

**Answer:** `@task` creates an async sub-task inside the same graph. When you trigger both tasks at once (`a = fetch_a(); b = fetch_b()`), both run concurrently, and `.result()` waits for both to complete.

</details>

<details>
<summary>3. Functional API vs StateGraph — which in which scenario?</summary>

**Answer:** Simple/parallel flow or a quick prototype = Functional API. When you need complex routing/multi-agent/conditional logic = StateGraph API. Both do the same thing, the style differs.

</details>
