# 2.11 Deployment & LLMOps

Up to 2.10 the agent was perfect — traced, debugged, streaming. But so far it was **local dev**. A moment will come when you put it in front of a client/product or end-users — "how do I put it in production?" **LLMOps** = the ops side of LLM apps: tracking, monitoring, evaluating, deploying. This isn't just concepts — we'll take it to a runnable setup.

## 1. MLflow — track metrics, params, and traces

MLflow is an experiment tracker. With it you log: how many tokens were used, which model, which prompt, how fast, any errors.

```bash
uv pip install mlflow[extras]
mlflow ui   # starts at http://localhost:5000
```

```python
import mlflow
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import StateGraph, START, END, MessagesState

llm = ChatGroq(model_name="llama-3.3-70b-versatile")

def chatbot(state: MessagesState):
    messages = [SystemMessage(content="Tum ek helpful dost ho.")] + state["messages"]
    return {"messages": [llm.invoke(messages)]}

g = StateGraph(MessagesState)
g.add_node("chatbot", chatbot)
g.add_edge(START, "chatbot")
g.add_edge("chatbot", END)
app = g.compile()

# --- track it ---
mlflow.set_experiment("vin-langgraph")
with mlflow.start_run():
    mlflow.log_param("model", "llama-3.3-70b-versatile")
    user_q = "LangGraph mein streaming kyun use karte hain?"
    result = app.invoke({"messages": [HumanMessage(content=user_q)]})
    answer = result["messages"][-1].content
    mlflow.log_metric("answer_chars", len(answer))
    mlflow.log_text(answer, "reply.txt")
    mlflow.log_artifact("app.py")
    print(answer)
```

- `mlflow.set_experiment` — which group the runs go into.
- `log_param` / `log_metric` / `log_text` / `log_artifact` — everything gets logged with the run.
- See it with `mlflow ui`.

## 2. LangSmith → MLflow bridge (pick one)

LangSmith also traces — but explicitly bridging it into MLflow is an enterprise feature. At the beginner level use just **one** — either MLflow or LangSmith. Using both together feels like overkill at the start.

## 3. Grafana — visualize metrics

Once data comes from MLflow, you need a dashboard. Grafana visualizes that data. Local setup (docker-compose):

```yaml
# docker-compose.yml
services:
  grafana:
    image: grafana/grafana-enterprise
    ports: ["3000:3000"]
  prometheus:
    image: prom/prometheus
    ports: ["9090:9090"]
```

Keep a simple metrics endpoint in the LangGraph app (FastAPI) that Prometheus scrapes:

```python
from fastapi import FastAPI
import time

api = FastAPI()
_calls = 0
_latency = []

@api.get("/metrics")
def metrics():
    return {"calls": _calls, "avg_latency": sum(_latency)/len(_latency) if _latency else 0}

@api.get("/chat/{q}")
def chat(q: str):
    global _calls, _latency
    t = time.time(); _calls += 1
    r = app.invoke({"messages": [HumanMessage(content=q)]})
    _latency.append(time.time() - t)
    return {"reply": r["messages"][-1].content}
```

Grafana at `http://localhost:3000` (user/pass `admin/admin`), add the `Prometheus` data source at `http://prometheus:9090`, then build panels for `calls` and `avg_latency`. Now you have a real-time dashboard.

## 4. Hugging Face Spaces — deploy to the cloud

The easiest deploy: **Gradio + HuggingFace Spaces**. Build a Gradio UI, push to HF — live in two minutes.

`app.py`:

```python
import gradio as gr
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import StateGraph, START, END, MessagesState

llm = ChatGroq(model_name="llama-3.3-70b-versatile")

def chatbot(state: MessagesState):
    msgs = [SystemMessage(content="Tum ek helpful dost ho.")] + state["messages"]
    return {"messages": [llm.invoke(msgs)]}

g = StateGraph(MessagesState)
g.add_node("chatbot", chatbot)
g.add_edge(START, "chatbot")
g.add_edge("chatbot", END)
app_graph = g.compile()

def reply(message, chat_history):
    result = app_graph.invoke({"messages": [HumanMessage(content=message)]})
    return result["messages"][-1].content

gr.ChatInterface(reply, title="Phase 2 Agent").launch()
```

`requirements.txt`:

```
langchain-groq
langgraph
langchain-core
gradio
```

`.env` (put it in HF Spaces **Secrets** — never commit it):

```
GROQ_API_KEY=<your-groq-key>
```

Deploy steps:

```bash
git init
git remote add origin https://huggingface.co/spaces/<username>/vin-agent
git add app.py requirements.txt .env
git commit -m "phase 2 agent"
git push origin main
```

HF builds it, and the agent goes live at `https://<username>.hf.space`.

## LLMOps lifecycle — in one glance

1. **Track** — MLflow or LangSmith → data for every run.
2. **Monitor** — Grafana dashboard → live metrics.
3. **Evaluate** (2.10) — LangSmith evaluators / datasets.
4. **Deploy** — HF Spaces / Docker / cloud.
5. **Iterate** — new metrics → improve.

## What It Is NOT

⚠️ **LLMOps is NOT a copy of DevOps.** LLMs have extra dimensions — prompt drift, token cost, hallucination, retriever accuracy. Standard DevOps tools can't catch these.

⚠️ **Grafana is NOT just a dashboard tool.** There has to be a metrics source on the backend — otherwise there's no data at all.

⚠️ **HF Spaces is NOT permanent prod hosting.** The free tier is fine, but it gets shaky under high traffic/rate limits. Shift to bare-metal/cloud.

## In Your Own Words

<details>
<summary>1. `log_param`, `log_metric`, `log_artifact` — which is for what?</summary>

**Answer:** `log_param` is a config value (model name) — set at the start of the run. `log_metric` is a number (answer length, latency) — time-series. `log_artifact` is a file (reply.txt, code) — saved.

</details>

<details>
<summary>2. Where do Grafana's metrics come from?</summary>

**Answer:** Grafana fetches from a data source (Prometheus/Loki/or a FastAPI endpoint). Add the source's URL, then build panels.

</details>

<details>
<summary>3. How do you keep `GROQ_API_KEY` on HF Spaces?</summary>

**Answer:** Put the env var in the HF Space's Settings → Secrets (masked). Code reads it from env via `ChatGroq()`. Never commit it to the repo.

</details>
