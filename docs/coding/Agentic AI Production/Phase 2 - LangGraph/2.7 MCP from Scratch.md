# 2.7 MCP from Scratch

In 2.6 the agent thinks, calls a tool, and replies. But where do those tools come from? Writing a tool by hand every time is a lot of work.

That's why **MCP (Model Context Protocol)** exists — an open standard (built by Anthropic) that makes tools into a *universal plug*. If anyone builds an MCP server, any compatible agent can use it — without any custom integration.

## Recap — MCP = USB for AI tools

In Introduction course 7.2 you learned: MCP is a thing where a tool/function gets exposed in a *standard way*, and any agent can "plug in" and use it. Like USB-C — one slot, all devices fit.

## Build a simple MCP server

```python
# mcp_date_server.py
from mcp import App

app = App("date-tools")

@app.tool()
def current_date(dummy: str = "") -> str:
    """Provides today's date."""
    from datetime import date
    return date.today().isoformat()

# Run:  mcp run mcp_date_server.py
```

1. `App("date-tools")` — create an MCP app/server with a name.
2. `@app.tool()` — the decorator turns this function into a *tool* that any agent can see.
3. `"""Provides today's date."""` — the docstring = the tool's description (the agent listens to this).
4. The return type (`-> str`) is the tool's output.
5. `mcp run mcp_date_server.py` runs the server (on stdio transport).

Install: `uv pip install mcp`.

## Connect a LangGraph agent to it

```python
from langchain_mcp import MultiServerMCPClient
from langgraph.prebuilt import create_react_agent
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage
import asyncio

llm = ChatGroq(model_name="llama-3.3-70b-versatile")

async def main():
    # connect to the MCP server (our date tool)
    client = MultiServerMCPClient({
        "date-tools": {
            "command": "python",
            "args": ["mcp_date_server.py"],
            "transport": "stdio",
        }
    })
    tools = await client.get_tools()    # pull the tools from the server

    agent = create_react_agent(llm, tools)
    result = await agent.ainvoke(
        {"messages": [HumanMessage(content="Aaj ki date kya hai?")]}
    )
    print(result["messages"][-1].content)

asyncio.run(main())
```

- `MultiServerMCPClient` turns an MCP server into langchain-usable tools.
- `client.get_tools()` — brings the tool the server exposes (here `current_date`) as a langchain `Tool`.
- `create_react_agent(llm, tools)` — now the agent can use this tool, without you injecting it by hand.

## The real benefit of MCP

- **One tool, all agents.** One MCP server = GitHub, Slack, Notion, database, file-system — any compatible agent can use it.
- **No vendor lock-in.** No custom code for every framework. One server, same for everyone.
- **Security sandbox.** The server decides for itself which tools are accessible to whom.

## What It Is NOT

⚠️ **MCP is NOT a framework.** A framework gives features — MCP is a **protocol/transport standard** (like a USB cable). Building server/client is framework-independent.

⚠️ **Not every tool is an MCP server.** You can keep many tools in one MCP server (date + weather + calculator). Server = a tool-collection.

⚠️ **MCP isn't only in LangGraph.** Any MCP-compatible agent (Claude Code, Cursor, etc.) can use it — that's exactly why it's a standard.

## In Your Own Words

<details>
<summary>1. What's the difference between an MCP tool and a langchain `@tool` function?</summary>

**Answer:** `@tool` turns a function into a langchain tool — it only reaches LangChain, inside one process. MCP is a protocol — through it, tools get exposed on a separate process/server, and any MCP-client can use them (multi-language, cross-framework).

</details>

<details>
<summary>2. Why "multi-server" in `MultiServerMCPClient`?</summary>

**Answer:** You can attach one client to multiple MCP servers — one for GitHub, one for Notion, one for a database. The client pulls tools from all the servers together.

</details>

<details>
<summary>3. What is a transport in an MCP server?</summary>

**Answer:** Transport = the connection mode between server and client. `stdio` = both inside one process/through stdin-stdout (simple, local). `sse` = HTTP via server-sent events (remote, when the server is on the network).

</details>
