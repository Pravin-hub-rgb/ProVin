# 2.1 Graphs: State, Nodes, Edges

Phase 1 mein tumne LangChain ke building blocks seekhe — ek model call, usme tool, memory, streaming. Wo sab ek line mein the — model ko bhejo, jawab lo. Lekin real production agents itni simple nahi hote. Kuch scenes mein agent ko pehle sochna padta hai, phir ek tool call karna, phir sochna, phir doosra tool. Kuch pooch kar aage badna ho jata hai. Isko ek seedhi line se control karna kabhi clean nahi rehta.

Isi liye LangGraph hai — agents ko ek **graph** ke tarah banana. Vin ne Introduction course 7.3 mein multi-agent ka concept seekha tha. Ab wahi soch code mein aati hai, LangGraph ke through.

## Ek graph kya hota hai — aik board game se samjho

Graph matlab ek aisa **map jisme steps (nodes) hote hain aur unke beech connections (edges)**. Aisa socho ek board game — board ke squares nodes hain, aur unke beech arrows edges hain. Jaise aap ek square par khade ho, aur arrow bata raha hai ki agle turn aap kis square pe chale jao ge.

- **Node** — graph ka ek step. Jaise "sawaal padho", "model socho", "tool call karo", "jawab likho". Har node ek function hota hai jo state lega aur return karega.
- **Koi edge** — dono nodes ke beech ka connection. Bataata hai ki "jab node X ho to node Y pe jao".
- **State** — ek shared **bag** jisme saara data rehta hai. Har node ise padhta hai, nayi cheezein add karta hai. Ye bag poore graph ke through aage badhta hai — jaise ek office ka shared whiteboard jisme har employee apni nayi baat likh deta hai.

Jab aap ke paas aisa graph hai — jaise squares, edges, ek shared board — toh decision lete waqt aapko flexibility milti hai. Aap branch kar sakte hain (agaro option A ho to Y, warna Z), loop karsakte hain (jab tak pakka nahi ho jaye), ya parallel kuch kadam utha sakte hain. Ye linear loop ke comparison mein bahut maza aata hai.

## StateGraph — skeleton banao

LangGraph mein `StateGraph` class se graph banate hain. State ek **TypedDict** se define hota hai — python me dictionary ka blueprint:

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# 1. State define karo — shared "bag" ka blueprint
class State(TypedDict):
    messages: list

# 2. Ek node function — state lega, kaam karega, state return karega
def add_hello(state):
    return {"messages": state["messages"] + ["Hello!"]}

# 3. Builder banao
builder = StateGraph(State)

# 4. Node register karo
builder.add_node("greet", add_hello)

# 5. Edges jodo — flow decide karo
builder.add_edge(START, "greet")
builder.add_edge("greet", END)

# 6. Compile karke graph taiyaar
graph = builder.compile()

# 7. Chalao
result = graph.invoke({"messages": []})
print(result["messages"])
```

Har line ka matlab:

1. `from langgraph.graph import StateGraph, START, END` — LangGraph ke core. `StateGraph` graph banane ki class, `START` entry-point marker, `END` exit marker.
2. `class State(TypedDict): messages: list` — State ka blueprint define karo. Yeh batata hai ki shared bag mein `messages` naam ki list hogi.
3. `def add_hello(state)` — ek node function. `state` milta hai (purana bag). Uska return dict langgraph ise state se **merge** karta (naye keys/append).
4. `builder = StateGraph(State)` — builder supervisor banao, jise pata chal jayega ki state kis form mein hai.
5. `builder.add_node("greet", add_hello)` — graph mein ek step add karo: naam "greet", function `add_hello`.
6. `add_edge(START, "greet")` phir `add_edge("greet", END)` — "START se greet, greet se END."
7. `graph = builder.compile()` — graph ko compute karke ready karo.
8. `result = graph.invoke({"messages": []})` — ek empty state se poora graph chala lo. START → greet → END.
9. `print(result["messages"])` — result hamesha final state. Isme `["Hello!"]` aayega.

## Linear loop se behtar kyun hai

Phase 1 ka loop ek fixed sequence tha — steps ek ke baad ek, phir ek, phir ek. Graph aisa nahi. Graph mein aap karo:
* **Branch** — condition ke hisaab se alag edge lelena.
* **Loop** —jab tak condition naa mile, ek hi node phir se chalana.
* **Parallel** — do nodes ek hi time pe chalana.

Real agent ke liye zaroori hai — sochne, tool call, result dekh kar phir se sochna. Linear loop mein yeh loop manually bandhaana padta hai aur jaldi se bahut messy ho jata hai. Graph ise asaani se handle karta hai.

## What It Is NOT

⚠️ **Graph "machine learning ka graph" nahi.** Woh koi data-points ka chart nahi — yo toh ek **workflow diagram** hai, steps ka flow, jaise architecture ke flowchart.

⚠️ **State koi permanent file ya database nahi.** Yo ek dictionary hoti hai jo node-node ke beech pass hoti hai. Jab graph khatam hota hai, state clear hojati hai.

⚠️ **Node order e list ki tarah fixed honi zaroori nahi.** Aap nodes kabhi bhi add karsakte hain — actual "konsa node kab chalega" usi `edges` decide karte hain.
