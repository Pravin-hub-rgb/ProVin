# 2.6 Streaming in LangGraph

Jab tak aap `graph.invoke()` use karte hain, user ko lagta hai jaise agent kuchh nahi kar raha — ek jagah pe baith kar, phir ek sudden jawab. Agar user ko har ek second dikhalagaye ki "agent soch raha hai, tool call kar raha hai, likh raha hai" — toh bahut zyada satisfying hota hai. Isliye **streaming** ka maza.

LangGraph do tarah stream karta hai — tokens (words aate huye) aur graph ke **steps** (har node ek nazar mein).

## 1. Token streaming — `stream_mode="messages"`

```python
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import StateGraph, START, END, MessagesState

llm = ChatGroq(model_name="llama-3.3-70b-versatile")

def chatbot(state: MessagesState):
    messages = [SystemMessage(content="Tum ek helpful dost ho. Thoda lamba jawaab do.")] + state["messages"]
    return {"messages": [llm.invoke(messages)]}

graph = StateGraph(MessagesState)
graph.add_node("chatbot", chatbot)
graph.add_edge(START, "chatbot")
graph.add_edge("chatbot", END)
graph = graph.compile()

# 💡 token-by-token aayega
for token, metadata in graph.stream(
    {"messages": [HumanMessage(content="LangGraph kya hota hai, batao thoda lamba.")]},
    stream_mode="messages",
):
    if token.content:
        print(token.content, end="", flush=True)
print()
```

- `stream_mode="messages"` — har ek token as a separate message milta hai. Aap `print(token.content, end="")` karo — jaise koi likhta ho.
- `flush=True` zaroori — warna terminal buffer mein jaa sakta hai.
- `metadata` ke andar info hoti hai (konsa node, kaun message type).

## 2. Step streaming — `stream_mode="values"`

```python
# 💡 har graph step ka ek "snapshot" milega
for event in graph.stream(
    {"messages": [HumanMessage(content="LangChain aur LangGraph mein farq?")]}],
    stream_mode="values",
):
    event["messages"][-1].pretty_print()
```

- `stream_mode="values"` — har ek node execute hone ke baad graph ka pura state snapshot milta hai. Aap dekh sakte hain ki chatbot ne kaise socha, phir kaisse jawab diya.
- Debugging ke liye zabardast — aapko pata chalta hai ki agent kis node pe kaun message daala, kya tool call hua, kya nahi.

## Kahan use karo

- **Frontend UI** — jab aap chatbot ke words ek ek karke screen pe type hone chahiye (jaise ChatGPT).
- **Debug** — jaise aap dekhna chahein ki agent tool call kyun kiya, phir response kaise banaya.
- **Agentic loop visibility** — ReAct agent ke `think→act→observe` har step dikha sakte hain.

## What It Is NOT

⚠️ **stream_mode="messages" = token stream nahi, response stream.** Ye just LLM ke tokens nahi — graph ke andar jitne messages hain, usme se ek ek karke token aate hain (jameen tak pura conversation).

⚠️ **Stream ek synchronous loop nahi.** `for` loop thoda async jaisa chalta hai — aap har ek token pe react kar sakte hain, par graph ka logic phir bhi ek saath chalta hai.

⚠️ **Stream hamesha UI ke liye hi nahi.** Kabhi kabhi stream sirf logging/debugging ke liye bhi hoti hai — jab aapko pata chalna ho ki agent kis phase mein hai.

## In Your Own Words

<details>
<summary>1. stream_mode="messages" aur "values" — dono mein kya fark?</summary>

**Jawab:** "messages" har ek token ko ek event ke roop mein bhejta hai — aap usse screen pe type karsakte. "values" har graph step (node execution) ke baad pura state snapshot bhejta hai — aapko dekha jaaye ki agentne kya kiya, kis order mein.

</details>

<details>
<summary>2. Agar aap flush nahi karenge, toh kya hota hai?</summary>

**Jawab:** `print` terminal ko buffer karta hai — poori baat ek saath nahi, ek batch mein print hoti hai. `flush=True` buffer ko turant flush karta hai — isliye user har letter ko turant dekhega. Bina iske lagbhag 1-2 sec baad sab kuch ek saath aayega.

</details>

<details>
<summary>3. Step streaming debugging mein kyun madad karti hai?</summary>

**Jawab:** Aap har step ke state snapshot dekhte hain — ki kis node ne koi message daala, konsa tool call hua, kab response aaya. Agar agent koi galat jagah pe ruka ya galt tool call kiya, toh aap uss specific step pe dekh ke pata laga sakte hain.

</details>
