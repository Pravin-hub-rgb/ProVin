# 2.6 Streaming in LangGraph

As long as you use `graph.invoke()`, the user feels like the agent is doing nothing — sitting in one place, then a sudden reply. If the user could see every second that "the agent is thinking, making a tool call, writing" — that would be much more satisfying. That's the fun of **streaming**.

LangGraph streams in two ways — tokens (words arriving) and the graph's **steps** (every node in view).

## 1. Token streaming — `stream_mode="messages"`

```python
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import StateGraph, START, END, MessagesState

llm = ChatGroq(model_name="llama-3.3-70b-versatile")

def chatbot(state: MessagesState):
    messages = [SystemMessage(content="Tum ek helpful dost ho. Thoda lamba jawaab do.")] + state["messages"]
    return {"messages": [llm.invoke(messages)]}

graph = StateGraph(MessagesState)
graph.add_node("chatbot", chatbot)
graph.add_edge(START, "chatbot")
graph.add_edge("chatbot", END)
graph = graph.compile()

# 💡 token-by-token aayega
for token, metadata in graph.stream(
    {"messages": [HumanMessage(content="LangGraph kya hota hai, batao thoda lamba.")]},
    stream_mode="messages",
):
    if token.content:
        print(token.content, end="", flush=True)
print()
```

- `stream_mode="messages"` — every token arrives as a separate message. Do `print(token.content, end="")` — like someone typing.
- `flush=True` is needed — otherwise the terminal can buffer it.
- `metadata` holds info (which node, which message type).

## 2. Step streaming — `stream_mode="values"`

```python
# 💡 a "snapshot" of every graph step
for event in graph.stream(
    {"messages": [HumanMessage(content="LangChain aur LangGraph mein farq?")]}],
    stream_mode="values",
):
    event["messages"][-1].pretty_print()
```

- `stream_mode="values"` — after every node executes, a snapshot of the whole graph state arrives. You can see how the chatbot thought, then how it replied.
- Great for debugging — you learn which node added which message, which tool got called, which didn't.

## Where to use it

- **Frontend UI** — when the chatbot's words should type out on screen one by one (like ChatGPT).
- **Debug** — when you want to see why the agent made a tool call, then how it built the reply.
- **Agentic loop visibility** — the ReAct agent's `think→act→observe` steps can all be shown.

## What It Is NOT

⚠️ **`stream_mode="messages"` is NOT just a token stream, it's a response stream.** It's not only the LLM's tokens — tokens arrive one by one out of all the messages inside the graph (including the whole conversation).

⚠️ **Stream is NOT a synchronous loop.** The `for` loop runs somewhat like async — you can react to every token, but the graph's logic still runs all at once.

⚠️ **Stream isn't only for the UI.** Sometimes the stream is only for logging/debugging — when you want to know which phase the agent is in.

## In Your Own Words

<details>
<summary>1. What's the difference between `stream_mode="messages"` and `"values"`?</summary>

**Answer:** "messages" sends every token as an event — you can type it on screen. "values" sends a snapshot of the whole state after every graph step — you can see what the agent did, in what order.

</details>

<details>
<summary>2. What happens if you don't flush?</summary>

**Answer:** `print` buffers the terminal — the whole thing doesn't print at once, it prints in a batch. `flush=True` flushes the buffer instantly — so the user sees every letter right away. Without it, everything arrives at once after about 1-2 sec.

</details>

<details>
<summary>3. Why does step streaming help in debugging?</summary>

**Answer:** You see a snapshot of the state at every step — which node added which message, which tool got called, when the response came. If the agent got stuck somewhere or called the wrong tool, you can spot it at that specific step.

</details>
