# 2.10 LangSmith & LangGraph Studio

The agent has gotten complex — thinking, tool calls, branches, multi-agent. When it gets stuck somewhere or makes the wrong tool call, it's hard to see "where did it go wrong." That's why **observability** = "seeing what the agent is doing" becomes necessary.

LangGraph has two tools for this: **LangSmith** (trace/cloud) and **LangGraph Studio** (visual editor).

## LangSmith — cloud trace + debug

LangSmith is a cloud tool that captures a **trace** of every langchain/langgraph run — step by step, token cost, tool calls, errors.

Setup (env):
```bash
uv pip install langsmith
# .env
LANGCHAIN_API_KEY=<your-langsmith-key>   # from api.langsmith.ai
LANGCHAIN_TRACING_V2=true                # turn tracing on
LANGCHAIN_PROJECT=vin-phase2             # group runs into this project
```

As soon as it runs, everything gets traced automatically — no code change. Go to the dashboard and see:
- When each node ran — `chatbot`, `writer`, `reviewer`.
- How many tokens were used — cost tracking.
- When a tool call happened — what the argument was, what the result was.
- Any error/timeout/rate-limit? It shows up right there.

```python
# no extra code — tracing turns on from env vars.
# You can also log manually:
from langsmith import traceable

@traceable(name="my_calculation")
def expensive_step(x):
    return x * 2
```

## LangGraph Studio — visual editor

LangGraph Studio is a **local desktop UI** where you can **visualize + run + debug** your graph — click node by node and see.

Setup:
```bash
# install the langgraph CLI
uv pip install langgraph-cli
# (or) uvx langgraph-cli

cd my_langgraph_project
langgraph dev    # starts a local server
# opens the LangGraph Studio desktop app at localhost
```

In Studio you'll see:
- The graph's diagram (nodes + edges joined like flowers).
- State evolution of every run — what the state was at each step.
- You can set breakpoints (pause before a node).

## Where to use it

- **Debugging** — the agent giving a wrong answer? See in the trace which node thought what, which tool got called wrong.
- **Evaluation** — with LangSmith datasets + evaluators you can judge the agent's runs (accuracy, groundedness).
- **Team handoff** — with the Studio diagram you can explain the graph to the product team without showing code.

## What It Is NOT

⚠️ **LangSmith is NOT a logging library.** It's an LLM-specific tracing system — token cost, prompt/data drift, chain-of-thought capture. A plain `print` can never give this.

⚠️ **LangGraph Studio is NOT a browser tool.** It's a desktop app (macOS/Windows) connected to a local dev server. Only the dashboard is in the browser, not the editor.

⚠️ **Observability is NOT optional.** When the graph is simple it's fine, but when the agent makes 5-10 tool calls + branches — without tracing you'll never know where it went wrong.

## In Your Own Words

<details>
<summary>1. Why does tracing start automatically once the env vars are set?</summary>

**Answer:** LangChain/LangGraph telemetry runs on env vars — with `LANGCHAIN_TRACING_V2=true`, all SDK calls get sent to LangSmith. No extra code, just env + API key.

</details>

<details>
<summary>2. What can you see by setting a breakpoint in Studio?</summary>

**Answer:** The graph pauses before a specific node — you can see what the state was at that point, then manually trigger the next node. Very helpful for controlling the debugging flow.

</details>

<details>
<summary>3. What's the use of a project in LangSmith?</summary>

**Answer:** A project is a namespace/tag — all runs show together. If you make `vin-phase2`, you'll only get Phase 2 runs, Phase 1 separately. Keeps things organized.

</details>
