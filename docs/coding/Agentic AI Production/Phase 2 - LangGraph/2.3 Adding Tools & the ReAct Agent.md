# 2.3 Adding Tools & the ReAct Agent

The chatbot from 2.2 only talked back and forth. A real agent does more than that. Sometimes when a question is asked, the answer can't come from just "thinking" — it has to come from **doing work** (using a tool) — like when a date is asked for or a calculation is requested.

LangGraph gives a ready-made shortcut for this: **`create_react_agent()`**. It gives you an agent that thinks → acts (tool call) → thinks again — until the job is done.

## ReAct loop = think → act → observe → think → ...

The agent thinks: "The user asked for a date. Let me make a tool call." The tool runs, a result comes back. Then it thinks again: "I got the result. Now give the answer." This loop `create_react_agent` runs on its own.

## Make a tool — with `@tool`

```python
from langchain_core.tools import tool
from datetime import date

@tool
def get_current_date(dummy: str = "") -> str:
    """Returns today's date."""
    return str(date.today())
```

The `@tool` decorator turns that Python function into a tool the model can see — the docstring is the description, the return is the tool result.

## Build the agent

```python
from langchain_groq import ChatGroq
from langchain_core.messages import HumanMessage
from langgraph.prebuilt import create_react_agent

llm = ChatGroq(model_name="llama-3.3-70b-versatile")

# an agent with one tool
agent = create_react_agent(llm, [get_current_date])

# run — watch the agent: it thinks, calls the tool, sees the result, replies
user_query = "Aaj ki date kya hai?"
result = agent.invoke({"messages": [HumanMessage(content=user_query)]})
print(result["messages"][-1].content)
```

1. `create_react_agent(llm, [get_current_date])` — builds an agent graph from the model + tool list. Inside it there's automatically a **tool node** that runs the tool when the model calls it.
2. `agent.invoke(...)` — the whole agent loop runs: the model thinks → tool call → tool result → model replies. All in one invoke.
3. `result["messages"][-1]` — the agent's last reply (all messages, up to the tool result, sit in the state together).

## What happens inside the agent loop (step by step)

- Step 1: State = `[HumanMessage("Aaj ki date kya hai?")]`. The model thinks: "I need the date." → makes a tool call `get_current_date`.
- Step 2: LangGraph picks up that tool call, runs the function, adds a `ToolMessage` as the result into the state.
- Step 3: The model looks again — now it knows the date is `2025-...` → gives a direct `AIMessage` reply.
- The loop keeps going until "stop."

## What It Is NOT

⚠️ **An agent is NOT a single LLM call.** An agent is a **loop** — it thinks repeatedly, acts repeatedly. So it's not just one model call, it's a state machine that runs until the whole act is done.

⚠️ **A tool is NOT a bare function call.** A tool is a "schema" to the model (input, description, name). The model decides, and LangGraph handles the execution — so don't feed it bad input.

⚠️ **`create_react_agent` is NOT "smart."** It's a preset graph structure. For custom behaviour (custom stop conditions, custom routing) you may have to build the graph yourself with 2.1's `StateGraph`.

## In Your Own Words

<details>
<summary>1. How does think/act/observe flow in ReAct?</summary>

**Answer:** The model thinks (think), then makes a tool call (act), the tool's result comes back (observe), then the model thinks again. This loop keeps going until a final text answer arrives.

</details>

<details>
<summary>2. Why use the `@tool` decorator?</summary>

**Answer:** `@tool` turns a function into an object the model understands as a "tool" — its name, description (from the docstring), and input schema get extracted automatically. Without it the model doesn't know this function is a tool.

</details>

<details>
<summary>3. `create_react_agent` vs building the graph yourself — when which?</summary>

**Answer:** When you only need the standard "think→act→observe," `create_react_agent` is enough. When you want a custom flow (conditions, parallel, multi-agent handoff), you'll have to build the `StateGraph` yourself.

</details>
