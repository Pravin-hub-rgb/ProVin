# 1.1 Why Frameworks?

A **framework** is a complete kit of ready-made code that solves common problems ahead of time. You only write what's unique to your task; the kit handles all the grunt work.

Think of building a house. You could buy bricks one by one, mix mortar, and raise the walls yourself — electricity, water, everything you'd have to wire and plumb by hand. That's building from scratch. A framework is a **fully-furnished flat** — the wiring is done, the furniture is in, the plumbing is ready. You just bring your stuff and start living.

In this course you'll rebuild the same concepts you created from zero in the Introduction — models, tool calling, memory, RAG — using real, industry-standard tools. **The concepts are the same. Only the way you write them changes.**

## Getting Python Ready

LangChain is a **Python** library. You know JavaScript, but Python is new to you — no problem. Think of it as learning a second language. The thinking is the same; only the way of speaking differs.

Before writing any code, three things need to be installed:

1. **Python itself** (version 3.9 or newer)
2. **A way to install packages** — `pip` or `uv`
3. **A place to write code** — any text editor works

Let's do it step by step.

### Install Python

Go to python.org, download the installer for your system, and run it. One important thing — **while installing, don't forget to tick the "Add Python to PATH" box.** That tiny tick is what makes the difference: without it, typing `python` gives a confusing "command not found" error.

Once installed, open the terminal and type:

```powershell
python --version
```

If you see something like `Python 3.11.x`, you're done — you're ready.

### `pip` vs `uv` — Two Ways to Install Packages

A **package** is a collection of code someone else wrote that you can plug into your project. LangChain itself is a package. To use it, you have to install it.

`pip` — the classic installer that comes with Python. You'll see it everywhere. `uv` — new, and very fast, doing the same job (and the course you're on uses this too). Think of it this way — `pip` is a normal bus, `uv` is an express train. Both reach the same stop; `uv` just gets there faster. We'll use `uv`, but I'll also show the `pip` way.

### Create a Project Folder and a Virtual Environment

A **virtual environment** is a private, separate place for your project's packages. Think of it as a separate toolbox for this project, with its own screwdrivers and its own glue. Packages don't spill from one project into another.

```powershell
mkdir mysite
cd mysite
uv init
uv add langchain
uv add langchain-groq
```

- `mkdir mysite` — creates a folder named `mysite`. "mkdir" = "make directory".
- `cd mysite` — go inside that folder. "cd" = "change directory".
- `uv init` — creates a new Python project inside, along with a `pyproject.toml` file that holds the project's settings.
- `uv add langchain` — downloads LangChain and notes it in that file.
- `uv add langchain-groq` — the package that connects Groq's free model to LangChain. (We'll practice for free — more on this in 1.2.)

If you prefer `pip`, the same thing looks like:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install langchain langchain-groq
```

- `python -m venv .venv` — creates a virtual environment named `.venv`. ("venv" = "virtual environment".)
- `.venv\Scripts\activate` — turns that environment ON.
- `pip install langchain` — downloads LangChain into the environment.

### The `requirements.txt` (or `pyproject.toml`) File

Both `uv` and `pip` keep the list of what your project needs in a file — `requirements.txt` (for `pip`), `pyproject.toml` (for `uv`). This is your project's shopping list. When you or your team opens the project on a new computer, a single command installs everything:

```powershell
pip install -r requirements.txt
```

This tiny habit is what makes a project "runs instantly on any machine." A production mindset from day one.

## What It Is NOT

⚠️ **A framework is NOT a magic button.** It doesn't write your app for you. It's not a code generator. It's a kit of blocks that *you* assemble. You design the logic; LangChain just gives ready-made parts so you don't have to build everything from zero.

⚠️ **This isn't just the "theory" from 7.1.** In Introduction course 7.1 we only talked about *which* frameworks exist. Now you actually use a framework — hands-on, with real calls.

⚠️ **A framework isn't only for Python.** Frameworks exist in JS too (like LangGraph.js). But in this course we use the Python ones because the real work companies do is Python-native.

Now your computer speaks Python, you know why a kit (bricks) beats raw, and everything is installed. Now the satisfying moment — make your first real AI call with LangChain.

**Answer:** Different projects need different packages — and sometimes different versions of the same package. Like a separate kitchen for every project — not everyone eating from one shared pantry.

<details>
<summary>3. What's the difference between `pip` and `uv`?</summary>

**Answer:** Both do the same job — installing packages. `uv` is just newer and faster, doing the same work in less time. Express train vs normal bus. Same destination either way.

</details>
