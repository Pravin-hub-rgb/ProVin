# 1.5 Tools & Tool Calling

A **tool** is a normal Python function that the model can call. The model doesn't know the function's logic itself. You only have to tell it *which* job is available and *how* to call it. A tool gives the model three things: a name, a description, and the shape of the arguments. From these alone the model understands when and how to use it.

## A Normal Function — Then Turn It Into a Tool

First write a plain Python function with your own logic:

```python
def get_weather(city):
    """Get the current weather for a city."""
    return f"The weather in {city} is sunny, 30 degrees."
```

Just a normal function. Now turn it into a **tool**:

```python
from langchain_core.tools import tool

@tool
def add(a: int, b: int) -> int:
    """Add two numbers and return the sum."""
    return a + b
```

Here's what the `@tool` decorator added:

- `@tool` — the line before `def`. This tells Python "turn this function into a tool so the model can call it."
- The function's **name** (`add`) — becomes the tool's name. The model calls it by this name.
- The function's **docstring** (`"""Add two numbers..."""`) — becomes the tool's description. The model reads this to understand when to use the tool.
- Type hints (`a: int, b: int`) — tell the shape of the tool's arguments. The model learns what type to send.

That's why the docstring and types matter so much — they're the model's guide to what the tool does and in what format to call it.

## Tell the Model About the Tool — `bind_tools`

Before the model can call a tool, it has to know the tool exists. `bind_tools()` does that:

```python
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

load_dotenv()

model = init_chat_model("llama-3.3-70b-versatile")

@tool
def add(a: int, b: int) -> int:
    """Add two numbers and return the sum."""
    return a + b

model_with_tools = model.bind_tools([add])

response = model_with_tools.invoke("What is 5 plus 3?")
print(response)
```

`model.bind_tools([add])` — creates a new copy of the model that knows about the tools (here, just `add`). When you invoke it, two things can happen:

- **The model replies directly** — the answer is in `response.content`. (When the model thinks it doesn't need a tool.)
- **The model makes a tool call** — `response.content` is empty, and `response.tool_calls` comes back with `add`'s arguments, like `[{"name": "add", "args": {"a": 5, "b": 3}}]`.

## The Tool Loop — The Hero

This is the same loop you built by hand in the Intro. The model says which tool, you run it, send the result back, then ask the model for the final reply.

```python
@tool
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

model_with_tools = model.bind_tools([add])

messages = [{"role": "user", "content": "What is 5 plus 3?"}]

response = model_with_tools.invoke(messages)
messages.append(response)

# did the model ask to call a tool? Check.
if response.tool_calls:
    tool_call = response.tool_calls[0]
    tool_name = tool_call["name"]
    tool_args = tool_call["args"]

    # run the tool yourself:
    if tool_name == "add":
        result = add(**tool_args)

    # send the result back as a ToolMessage
    messages.append(
        {"role": "tool", "tool_call_id": tool_call["id"], "content": str(result)}
    )

    # now get the final reply — the model replies after seeing the result
    final = model_with_tools.invoke(messages)
    print(final.content)
```

Line by line:

1. `response = model_with_tools.invoke(messages)` — ask the model "5 plus 3?" The model doesn't reply directly; it says in `tool_calls` "call `add(5, 3)`."
2. `messages.append(response)` — add the model's message (which carries the tool_calls) to the history, so the model remembers what it thought on the next call.
3. `if response.tool_calls:` — check whether the model asked for a tool call. If it had replied directly, this block would be skipped.
4. `tool_call = response.tool_calls[0]` — pull out the first tool call.
5. `tool_name = tool_call["name"]` and `tool_args = tool_call["args"]` — find out which tool and which arguments.
6. `result = add(**tool_args)` — run the actual tool. `**tool_args` turns the dictionary's key-value pairs into named arguments — meaning `add(a=5, b=3)`.
7. `messages.append({"role": "tool", ...})` — create a ToolMessage: the tool call's id and its result. This tells the model what the tool's reply was.
8. `final = model_with_tools.invoke(messages)` — now the model has the tool's result. So it gives the final reply: "5 plus 3 is 8."

## A Shortcut — `create_agent`

You wrote the tool loop by hand. But notice — this loop (invoke → check tool → run → send back) is the same everywhere. LangChain has put it into a ready-made agent. It's called `create_agent`:

```python
from langchain.agents import create_agent

@tool
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

agent = create_agent(
    model="llama-3.3-70b-versatile",
    tools=[add],
)

response = agent.invoke("What is 5 plus 3?")
print(response.content)
```

What happened? The entire tool loop — invoking, checking tool_calls, running the tool, sending the result back — all of it `create_agent` did internally. You only say: which model with `model=`, which tools with `tools=[add]`. The loop runs itself.

This is the "kit" where you built the loop from scratch in the Intro. Now that same loop is a ready-made thing. `bind_tools` gives you raw control; `create_agent` gives you simplicity. Both are useful — bind when you want to handle the loop yourself, agent when you want the loop ready-made.

## What It Is NOT

⚠️ **A tool does NOT mean the LLM runs the code itself.** The model doesn't execute your function's lines. It only says "call `add(5, 3)`" — the actual execution is done by your Python code with `result = add(**tool_args)`. The model sends a request; normal execution is done by your code.

⚠️ **`@tool` only adds metadata.** The function's logic doesn't change. It's still the same Python function — `@tool` just made it callable by the model, turning its docstring and types into the model's guide.

⚠️ **The tool loop is the entire core of agents, not just a LangChain thing.** It's the same pattern you built in JavaScript in the Intro course. LangChain turned it into a ready-made thing — that's the whole point of a framework, so you don't rewrite the common loop.
