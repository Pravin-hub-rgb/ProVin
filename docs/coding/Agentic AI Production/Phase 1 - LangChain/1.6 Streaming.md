In 1.5 you gave the model tools. Now think about something you see every day in ChatGPT or Claude — while the model is writing a reply, text appears word by word, like a typing effect. You don't have to wait for the whole reply. This is **streaming**, and a big part of today's agents runs on it.

# 1.6 Streaming

As long as you use `model.invoke()`, you get nothing until the whole reply is ready. This is a **blocking** call — everything comes back ready. But for real users this feels "slow," especially for long answers.

**Streaming** means taking the response in blocks, as soon as the model generates them. The first small chunk arrives instantly, then the next, then the next. Like a water dispenser's drips — catch each drip, don't wait for the whole bottle.

## `invoke` vs `stream` — Feel the Difference

These are two model calls, same question, two different experiences:

**Invoke (all at once):**
```python
response = model.invoke("Tell me a long story about a robot.")
print(response.content)   # the whole story prints at once
```

**Stream (chunk by chunk):**
```python
for chunk in model.stream("Tell me a long story about a robot."):
    print(chunk.content, end="")
```

Understand the difference:

- `model.invoke(...)` — one model call. `response.content` comes back only when the whole reply is ready. Screen stays blank till then.
- `model.stream(...)` — returns an **iterator** — a sequence you iterate over with a `for` loop.
- `for chunk in model.stream(...)` — on each loop round, `chunk` holds a bit of the model's new text (a word or two).
- `chunk.content` — the text part of that chunk.
- `print(chunk.content, end="")` — print it out; `end=""` means "don't put a new line after each print," so all the chunks stay on one line.

The effect? With `invoke` you stare at a blank screen for 5 seconds and then the whole paragraph appears. With `stream` the first word shows up instantly and text keeps growing — like typing.

## Streaming That Still Gathers the Full Answer

Sometimes you want to stream *and* keep the whole reply (joining all the chunks). Simple:

```python
full_text = ""
for chunk in model.stream("Explain recursion simply."):
    print(chunk.content, end="")
    full_text += chunk.content   # join the chunks

print()   # new line
print("FULL:", full_text)   # the whole reply in one string
```

- `full_text = ""` — an empty string to collect all the chunks into.
- `full_text += chunk.content` — add each chunk.
- After the loop, `full_text` — the whole reply, as one string. You get streaming's benefit and the full text too.

## Where Do You Really Use This?

Think of a customer-support agent. The user asks a question, and while the model prepares the whole reply, the user stares at a blank screen — feels "laggy." With streaming, the answer types out immediately. That's why ChatGPT, Claude — all of them use streaming.

## What It Is NOT

⚠️ **Streaming does NOT mean an instant answer.** It doesn't mean "instant answer" arrived. It's the same process — the model generates the whole text — you just get it in small pieces as they're made. Total time stays the same; only the feel is faster.

⚠️ **`model.stream()` is NOT some new thing — it's the same model request.** Only the way the response comes changes: `invoke` gives it all at once, `stream` gives the same text in chunks. Streaming is native to every model in the world.

<summary>1. What's the difference between `model.invoke()` and `model.stream()`?</summary>

**Answer:** `invoke()` returns the whole reply only after it's fully ready — screen stays blank till then. `stream()` returns the reply in chunks — as soon as each piece is generated, it arrives. Both are the same model request; only the way the response comes differs: all at once vs in pieces.

<details>
<summary>2. Why use `end=""` in `print(chunk.content, end="")`?</summary>

**Answer:** `print()` by default adds a new line after every call. `end=""` says "don't add a new line," so all the chunks join on one line — without `end=""`, every chunk would land on its own line and look broken.

</details>

<summary>3. Does streaming make the model generate faster? What actually changes?</summary>

**Answer:** No, the model's generation speed doesn't increase — the whole text is made in the same time. The difference is in delivering the response. `invoke` waits for the whole thing to be ready; `stream` shows each ready piece immediately. So it feels faster to the user even though the time is the same.

</details>
