Now a thing you've probably noticed — as long as you were sending history by hand in the messages list, everything was fine. But the moment the program stopped, everything vanished. Next time, the model remembers nothing. In Introduction course 5.1 we learned this problem as **stateless**.

Think — leave WhatsApp aside, think of this: a friend who forgets what you said earlier every time you talk. Frustrating, right? That's why agents need **memory**.

# 1.7 Short-Term Memory

**Short-term memory** means remembering for a while within the same conversation. Its job is to hold the messages that just happened inside this agent. That's what makes a conversation feel like a real chat — the model remembers what you said earlier.

The simple way in LangChain is `InMemoryChatMessageHistory` — an object that stores your conversation. "In-memory" means it lives in RAM (random access memory); it resets the moment the program stops. For now this is enough — persistent memory we'll see later with more advanced techniques.

## `InMemoryChatMessageHistory` — Setup

```python
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_core.chat_history import InMemoryChatMessageHistory

load_dotenv()

model = init_chat_model("llama-3.3-70b-versatile")

chat_history = InMemoryChatMessageHistory()
```

- `from langchain_core.chat_history import InMemoryChatMessageHistory` — imports the conversation storage class. "Chat history" = the full record of the chat.
- `chat_history = InMemoryChatMessageHistory()` — creates an object that will store your conversation. All messages go inside it.

Now add messages to it:

```python
from langchain_core.messages import HumanMessage

chat_history.add_user_message("Mera naam Vin hai.")
chat_history.add_ai_message("Namaste Vin! Kaise madad karoon?")

print(chat_history.messages)
```

- `chat_history.add_user_message("...")` — adds your message to the history (as a HumanMessage).
- `chat_history.add_ai_message("...")` — adds the model's reply to the history.
- `chat_history.messages` — the full list, so you can see what's remembered.

## Use the History With the Model

Now the real trick — send the earlier chat to the model so it "remembers." Simple: pass the history messages plus the new question to the model:

```python
# the user's new question
new_user_message = HumanMessage("Mera naam kya hai, kya yaad hai?")

# combine the old history messages + the new question
full_context = chat_history.messages + [new_user_message]
response = model.invoke(full_context)

print(response.content)   # "Tumhara naam Vin hai" — remembered! (if it's in history)
```

Line by line:

1. `new_user_message = HumanMessage("...")` — the model's new question: "what's my name?"
2. `chat_history.messages + [new_user_message]` — join the lists. Left side has the full old history, right side has the new question. This combined list goes to the model.
3. `response = model.invoke(full_context)` — the model gets the full context — first "My name is Vin" and now "what's the name?" So the reply remembers that the name is Vin.
4. `print(response.content)` — the reply.

And importantly — add the new reply to the history too, so the next question stays connected. One extra step:

```python
chat_history.add_ai_message(response.content)
```

Now the next question will also arrive with the previous reply in the context. The conversation keeps growing.

### In-memory = reset on restart

One important point — `InMemoryChatMessageHistory` lives in RAM. The moment the program stops or restarts, the whole history resets. That means memory only works while the program is running; if something like a server restart happens, everything is gone. In Phase 2 you'll see a **checkpointer** — like a "save game" that stores state to disk/database.

## What It Is NOT

⚠️ **Short-term memory does NOT mean the LLM "remembers."** The model stores nothing itself. The model is a stateless formula — you keep sending the history back in a list. "Memory" is just a pattern where you resend the history so the model can use it.

⚠️ **In-memory ≠ persistent.** It lives only in RAM. Program stops = history gone. For now this is enough — in later phases we'll see persistent (lasting) memory that remembers even after a program restart.
