# 1.2 Your First LangChain Call

An **LLM** (large language model) is the brain behind ChatGPT. The thing that reads your words and writes a reply. To talk to it from code, you send a message over the internet and it sends back a reply. In LangChain this happens through a **model object** — a Python object that represents the AI model and knows how to call it.

## First, You Need an API Key (a Free One!)

Before any code, one thing is needed: an **API key**. Think of it as a key card that proves you have permission to use the model, and the provider tracks every request against it.

Good news — you can practice with an actual model **completely free** for this course. We'll use **Groq** — a service that gives a free tier (very fast, open models). A paid service like OpenAI isn't needed right now.

**How to get a free Groq key:**
1. Go to `console.groq.com`, create a free account (signing in with Google works too).
2. In the "API Keys" section, create a new key — it starts with `gsk_`.
3. Copy that key and keep it with you for now.

(An OpenAI or Google model also works — the pattern is identical. But for free practice, Groq is perfect.)

### Store the Key Safely in a `.env` File

Never **write the API key directly in your code.** If the code gets shared (say, uploaded to GitHub), the key goes with it. Instead, keep the key in a special `.env` file — which stores secrets — and load it from there.

Create a `.env` file in your project folder:

```
GROQ_API_KEY=gsk_your-free-key-here
```

And add `.env` to your `.gitignore` file (the list Git ignores), so it never gets uploaded. The key stays private and safe on your computer.

### The Full Program

This is the smallest complete LangChain program that calls a model. Read it first, then we'll break every line down — code learned "from a friend explaining it" doesn't get forgotten fast:

```python
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

load_dotenv()

model = init_chat_model("llama-3.3-70b-versatile")

response = model.invoke("What is the capital of France?")
print(response.content)
```

Let's understand each line like a recipe:

1. `from dotenv import load_dotenv` — brings in a helper that can read the `.env` file. "dotenv" is a package that loads your secret keys into the program.
2. `from langchain.chat_models import init_chat_model` — imports `init_chat_model`, the handy LangChain function that sets up the model. "init" = "initialize" = get something ready.
3. `load_dotenv()` — this line actually reads your `.env` file and makes `GROQ_API_KEY` available inside the program. The empty parentheses `()` mean — no extra info needed.
4. `model = init_chat_model("llama-3.3-70b-versatile")` — creates a model object and stores it in the variable `model`. You're telling it *which* model to use by name. "llama-3.3-70b-versatile" is Groq's free, open model. LangChain, seeing this, knows to call Groq (because we installed `langchain-groq` in 1.1).
5. `response = model.invoke("What is the capital of France?")` — the star of the show. `invoke` means "call it." You're sending the question to the model. The model's full reply is stored in the `response` variable.
6. `print(response.content)` — prints the reply on screen. `response` is an object with parts; `.content` is the text part — the actual written reply.

Run it:

```powershell
python main.py
```

You should see `Paris` (or a full sentence) get printed. Congratulations — that's your first AI call from Python.

## Two Ways to Create a Model

You've run the code and got a reply. But there's another, equally important way to create a model object — used when you want more control over a specific provider's (like OpenAI's) settings. The Groq shortcut is the modern way; the direct class is the older, explicit way. Both show up in real code, so let's look at both.

### Way 1 — The Shortcut: `init_chat_model`

What we just used. You just give a **model name string** and LangChain figures out the provider from the name itself, loads the right class, and hands back a ready model object. One line, zero fuss. This is the "Go" of setup — it sniffs out what's needed.

### Way 2 — The Direct Class: `ChatOpenAI(...)`

Every provider has its own class. OpenAI's is `ChatOpenAI`. Where the shortcut guesses the provider for you (like the Groq one), with the direct class you decide the provider yourself — hence the name. This example is for OpenAI; if you use an OpenAI key:

```python
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI

load_dotenv()

model = ChatOpenAI(model="gpt-4o-mini")

response = model.invoke("What is the capital of France?")
print(response.content)
```

Line by line:

1. `from dotenv import load_dotenv` — same as before, to load the key.
2. `from langchain_openai import ChatOpenAI` — imports the OpenAI-specific class. The package name `langchain_openai` tells you it comes from a separate helper library for OpenAI.
3. `load_dotenv()` — loads the key.
4. `model = ChatOpenAI(model="gpt-4o-mini")` — creates the model. The model name comes with a clear label: `model="gpt-4o-mini"`. The class already knows it's "OpenAI", so you only give the specific model name.
5. `response = model.invoke("What is the capital of France?")` — sends the message, stores the reply.
6. `print(response.content)` — prints the text reply.

Both give you the same `model` object that you can `invoke`. `init_model` is fast for switching providers (Google, OpenAI, whatever) because you only change the name string. `ChatOpenAI` is explicit when you want to set OpenAI-specific options. Start with whichever feels clearer.

## Raw Response vs Just the Text

`response` isn't a plain string — it's a neat object called an **AIMessage**, which holds the reply plus some metadata (extra info about the call).

- `response.content` — just the text reply. What you usually want.
- `response.metadata` — a dictionary of extras: token usage, model name, time, etc. Like the receipt that comes with coffee — the coffee itself is `.content`; the printed details are `.metadata`.

Play around:

```python
print(response)                # the full AIMessage object
print(response.content)        # just the written reply
print(response.metadata)       # the "receipt" — tokens, model, timing
```

In a real app you almost always read `.content` to show the user, but sometimes `.metadata` too — to track cost or usage. Same call, two lenses.

## What It Is NOT

⚠️ **This first call is NOT a conversation.** The model remembered nothing before or after this request — every `invoke` is a fresh, forgetful moment, like talking to a stranger you just met. This is called **stateless**, and it's the default for LLMs. Reminding it later is a whole topic (that's memory).

⚠️ **This is NOT a web page.** Nothing rendered in a browser — this is pure Python talking to a server over the internet and printing a string. This is the foundation every AI app is built on.
