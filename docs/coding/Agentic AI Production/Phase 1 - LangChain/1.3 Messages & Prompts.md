1.2 mein tumne ek akela message bheja tha — `model.invoke("What is the capital of France?")`. Jab aisa karte ho, LangChain isko andar se ek **human message** mein wrap karta hai. Par real conversation mein sirf ek message nahi hota — hota hai ek pura list, jisme system ki instructions bhi hoti hain, tumhare sawaal, aur AI ke jawab. Yeh roles hi hai jo conversation ko shape dete hain.

# 1.3 Messages & Prompts

Introduction course mein tumne roles seekhe the — system, user, assistant. Wahi cheez ab Python/LangChain ke andar dekhne waale hain, kyunki **har message ka ek role hota hai**, aur role decide karta hai message kaisa treat hoga.

## The 4 Message Types

LangChain mein 4 tarah ke messages hote hain. Har ek ka apna class aur apna role:

| Message class | Role | Kya hota hai |
|---|---|---|
| `SystemMessage` | System | Model ko "kaise behave karna hai" batata hai — hidden instructions |
| `HumanMessage` | User | Tum jo likhte ho — tumhara sawaal |
| `AIMessage` | Assistant | Model ka jawab (aur tool calls bhi) |
| `ToolMessage` | Tool | Tool ke andar se aaya result |

**SystemMessage** sabse chhota, sabse powerful — ye wahi "you are a senior engineer" type instructions hai. Jab tak tum model ko bol nahi dete ki "tum ek chef ho", woh chef ki tarah behave nahi karega. Instructions de dete ho toh har jawab usi lens se aata hai.

**HumanMessage** — tumhara sawaal. **AIMessage** — usse pehle ka model jawab (history ka hissa). **ToolMessage** — jab model koi tool call karta hai, tool jo result deta hai woh is type ka hota hai — agli topic mein detail dekhoge.

## First Example: A Conversation List

LangChain mein model ko sirf ek string nahi, ek **list of messages** dete ho. Aise:

```python
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_core.messages import SystemMessage, HumanMessage

load_dotenv()

model = init_chat_model("llama-3.3-70b-versatile")

messages = [
    SystemMessage("You are a helpful travel guide for India."),
    HumanMessage("What is a must-try food in Delhi?"),
]

response = model.invoke(messages)
print(response.content)
```

Line by line:

1. `from langchain_core.messages import SystemMessage, HumanMessage` — ek alag package `langchain_core` se message classes import karta hai. LangChain core package mein base cheezein `from langchain import` se, extras `from langchain_core` se aati hain.
2. `model = init_chat_model("llama-3.3-70b-versatile")` — wahi model object, pehle jaisa.
3. `messages = [...]` — messages ka ek list banao. Andar do entries: ek `SystemMessage` — "tum India ka travel guide ho" — aur ek `HumanMessage` — "Delhi mein kya try karna chahiye?"
4. `response = model.invoke(messages)` — note kiya? Ab string nahi bhej rahe, **pura list** bhej rahe hain. Model poora list padta hai — system instruction pehle, phir tumhara sawaal.
5. `print(response.content)` — jawab print.

Iska result? Model Delhi ka food suggest karega **tour guide ki tone mein** — kyunki system message ne usse kah diya ki woh guide hai. Try karke dekho — bina system message kya fark padta hai? (Hint: tone aur details.)

## Add History — Full Back-and-Forth

Ab pichla jawab bhi conversation mein bhejte hain, taaki model "remember" kare pehle kya hua:

```python
messages = [
    SystemMessage("You are a helpful travel guide for India."),
    HumanMessage("What is a must-try food in Delhi?"),
    AIMessage("Try Chole Bhature near Chandni Chowk — it's a classic."),
    HumanMessage("Sounds great. What about the best time to visit?"),
]

response = model.invoke(messages)
print(response.content)
```

Isme ek nayi cheez add hui: an `AIMessage`. Model ka pehla jawab ab wapas bheja gaya hai, taaki agla jawab context ke saath aaye — "Chole Bhature ke baare mein maine bata diya, ab time pooch raha hai" — non-stop conversation feel hoti hai. Agar wo `AIMessage` nahi bhejte toh model ko pata hi nahi hota ki pehle kya baat hui thi.

## Prompt Templates — Make Messages Dynamic

Agar tum har baar poora message string likhoge, code repeat hoga. Prompt template isse solve karta hai — ek template jisme **variables** hote hain, jo har call pe badal sakte hain.

```python
from langchain_core.prompts import ChatPromptTemplate

template = ChatPromptTemplate.from_messages([
    ("system", "You are a travel guide for {country}."),
    ("human", "What should I eat in {city}?"),
])

messages = template.invoke({"country": "India", "city": "Delhi"})

response = model.invoke(messages)
print(response.content)
```

Samjho:

* `ChatPromptTemplate.from_messages([...])` — messages ka template banata hai. `("system", "...")` aur `("human", "...")` chhote tareeke hain same message types likhne ke — wo SystemMessage/HumanMessage ban jaate hain.
* `{country}` aur `{city}` — ye **placeholders** (khaali jagah) hain. `{something}` matlab "yahan kuch bhi aayega."
* `template.invoke({"country": "India", "city": "Delhi"})` — template ko values dete ho. `{country}` ki jagah "India", `{city}` ki "Delhi" aa jaata hai. Ab message list taiyaar.
* `model.invoke(messages)` — wahi, wo taiyaar list bhejo.

Fayda? Tumhe baar baar poora prompt likhna nahi padta — bas template ek baar banao aur har call pe naye values do. `{"country": "Japan", "city": "Tokyo"}` daalo, template khud prompt badal deta hai. Yeh wahi cheez hai jo aage agents mein fret hota hai — dynamic, reusable prompts.

## What It Is NOT

⚠️ **Messages flat list nahi hote — ordered hote hain.** `[SystemMessage, HumanMessage]` ka order matter karta hai. System pehle aana chahiye, phir sawaal — model isi order padhta hai. Ulti list bhejoge toh instructions late aa jayengi.

⚠️ **`AIMessage` sirf jawab ka record nahi — wo context hai.** Jab tum pichla jawab wapas bhejte ho, tum model ko context de rahe ho, taaki wo pehle ki baat se connected jawab de. Best reply ke liye pichla jawab bhejna zaroori.

⚠️ **Prompt template = string concat nahi.** `{city}` isko "sirf text jodo" nahi banata. Ye structured placeholders hain jo turant values se replace hote hain — bina raw user input ko seedha prompt mein ghusa ke. Matlab — "sirf variables badlo", prompt ka structure stable rakho.
