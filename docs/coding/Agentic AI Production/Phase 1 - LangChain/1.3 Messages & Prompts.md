In 1.2 you sent a single message — `model.invoke("What is the capital of France?")`. When you do that, LangChain wraps it internally into a **human message**. But a real conversation isn't a single message — it's a whole list, with system instructions, your questions, and the AI's replies. These roles are what shape the conversation.

# 1.3 Messages & Prompts

In the Introduction course you learned about roles — system, user, assistant. Here we'll see the same thing inside Python/LangChain, because **every message has a role**, and the role decides how the message gets treated.

## The 4 Message Types

LangChain has 4 kinds of messages. Each has its own class and its own role:

| Message class | Role | What it is |
|---|---|---|
| `SystemMessage` | System | Tells the model how to behave — hidden instructions |
| `HumanMessage` | User | What you write — your question |
| `AIMessage` | Assistant | The model's reply (and tool calls too) |
| `ToolMessage` | Tool | The result coming from inside a tool |

**SystemMessage** is the smallest but most powerful — it's the "you are a senior engineer" kind of instruction. Until you tell the model "you are a chef," it won't behave like a chef. Once you give instructions, every reply comes through that lens.

**HumanMessage** — your question. **AIMessage** — the model's previous reply (part of history). **ToolMessage** — when the model calls a tool, the result the tool returns is of this type — more detail in the next topic.

## First Example: A Conversation List

In LangChain you don't give the model just a string — you give it a **list of messages**. Like this:

```python
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_core.messages import SystemMessage, HumanMessage

load_dotenv()

model = init_chat_model("llama-3.3-70b-versatile")

messages = [
    SystemMessage("You are a helpful travel guide for India."),
    HumanMessage("What is a must-try food in Delhi?"),
]

response = model.invoke(messages)
print(response.content)
```

Line by line:

1. `from langchain_core.messages import SystemMessage, HumanMessage` — imports the message classes from a separate package, `langchain_core`. Base things come from `from langchain import`; extras come from `from langchain_core`.
2. `model = init_chat_model("llama-3.3-70b-versatile")` — the same model object as before.
3. `messages = [...]` — create a list of messages. Two entries inside: a `SystemMessage` — "you are a travel guide for India" — and a `HumanMessage` — "what should I try in Delhi?"
4. `response = model.invoke(messages)` — notice? Now you're not sending a string, you're sending the **whole list**. The model reads the whole list — the system instruction first, then your question.
5. `print(response.content)` — print the reply.

The result? The model suggests food in Delhi **in a tour-guide tone** — because the system message told it it's a guide. Try it without the system message and see the difference (hint: tone and details).

## Add History — Full Back-and-Forth

Now send the previous reply back into the conversation too, so the model "remembers" what happened before:

```python
messages = [
    SystemMessage("You are a helpful travel guide for India."),
    HumanMessage("What is a must-try food in Delhi?"),
    AIMessage("Try Chole Bhature near Chandni Chowk — it's a classic."),
    HumanMessage("Sounds great. What about the best time to visit?"),
]

response = model.invoke(messages)
print(response.content)
```

A new thing added here: an `AIMessage`. The model's first reply is now sent back, so the next reply comes with context — "I already told them about Chole Bhature, now they're asking about timing" — and it feels like a non-stop conversation. If you don't send that `AIMessage` back, the model has no idea what was discussed before.

## Prompt Templates — Make Messages Dynamic

If you write out the whole message string every time, code repeats. Prompt templates solve this — a template with **variables** that can change on every call.

```python
from langchain_core.prompts import ChatPromptTemplate

template = ChatPromptTemplate.from_messages([
    ("system", "You are a travel guide for {country}."),
    ("human", "What should I eat in {city}?"),
])

messages = template.invoke({"country": "India", "city": "Delhi"})

response = model.invoke(messages)
print(response.content)
```

Understand:

- `ChatPromptTemplate.from_messages([...])` — creates a template of messages. `("system", "...")` and `("human", "...")` are shortcuts for writing the same message types — they become SystemMessage/HumanMessage.
- `{country}` and `{city}` — these are **placeholders** (empty slots). `{something}` means "something will go here."
- `template.invoke({"country": "India", "city": "Delhi"})` — you give the template the values. "India" fills `{country}`, "Delhi" fills `{city}`. Now the message list is ready.
- `model.invoke(messages)` — same as before, send that ready list.

The benefit? You don't have to write out the full prompt every time — create the template once and just give new values on each call. Feed `{"country": "Japan", "city": "Tokyo"}` and the template changes the prompt itself. This is the same thing that gets reused heavily in agents later — dynamic, reusable prompts.

## What It Is NOT

⚠️ **Messages are NOT a flat list — they are ordered.** The order of `[SystemMessage, HumanMessage]` matters. The system should come first, then the question — that's the order the model reads. Send the list upside down and the instructions arrive late.

⚠️ **`AIMessage` is NOT just a record of the reply — it's context.** When you send the previous reply back, you're giving the model context so it can give a connected answer. Sending the previous reply is essential for the best answer.

⚠️ **A prompt template is NOT just string concatenation.** `{city}` doesn't just "join text." These are structured placeholders that get replaced by values instantly — without shoving raw user input straight into the prompt. In other words — "just swap the variables," keep the prompt's structure stable.
