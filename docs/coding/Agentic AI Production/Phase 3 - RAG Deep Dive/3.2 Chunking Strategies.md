Kya usse ek hi chunk mein daal denge? ## Kyu todna padta hai â€’ ek textbook analogy

Ek chapter bada ho toh usse sections mein todti ho â€” har section ek independent idea rakhta hai. Wahi chunk: ek chunk ek **coherent idea ya paragraph** rakhe, aise ki retrieval ke time woh sahi tukda nikal sake.

- **chunk_size** â€ kitne characters/words ek chunk mein â€‹hain (1000 = ~150-250 words).
- **chunk_overlap** â€ agle chunk ke start mein previous chunk ka last `overlap` chars repeat karo â€-taki jo concept boundary pe toota ho, uski poori jaankari dono mein mile.

## 3 strategies â€’ kaun si chahiye?

**1. Fixed-size** â€ har fixed chars pe todta hai. Simple lekin ek word ko beechâ€‍''Â¬-split kar sakta hai.

**2. Recursive (recommended)** â€ `RecursiveCharacterTextSplitter` pehle `\n\n` (paragraph) se try karta â€– agar nahi hua toh `\n` (line) â€– phir `" "` (space) â€– phir character. Matlab pehle **logical boundaries** par todna, sirf jab zaroorat ho tabhi character-level tak girna.

**3. Token-aware** â€ (3.6 mein detail) â€ LLM ke token limit ke hisaab se todna (ek word kabhi-kabhi 3 tokens bhi ho sakta hai).

## Code: alag alag chunk_size â€ se kya farak padta hai?

```python
# chunk_compare.py
from langchain.text_splitter import RecursiveCharacterTextSplitter

doc = "The student discount gives 50% off for grades 6-10. " * 20  # 20x repeat = badi text

for size in (200, 500, 1000):
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=size,
        chunk_overlap=0,          # pehle overlap nahi â€ size hi dekhte hain
        separators=["\n\n", "\n", " ", ""]
    )
    chunks = splitter.split_text(doc)
    print(f"chunk_size={size} -> {len(chunks)} chunks; first len={len(chunks[0])}")
```

Line-by-line: `"..." * 20` â€ ek hi idea ko 20 baar repeat kara â€ document badi ban gaya. `RecursiveCharacterTextSplitter` â€ separators priority order â€-- pehle paragraph, baad mein space, aakhir mein char. `split_text(doc)` â€ text â†’ chunk list. `len(chunks[0])` â€ pehle chunk ki length â€— size se kuchh kam honi chahiye (kyunki paragraph boundary pe cut karega).

## Goldilocks rule â€’ chunk_size kaise chunhein?

- **100-300 chars** â€ FAQ / short fact â€’ precise retrieval, lekin boundary cut hoga.
- **500-1000 chars** â€ paragraphs / snippets â€’ readable + good retrieval â€’ **most common sweet spot**.
- **1500+ chars** â€ essays â€’ full context, lekin prompt bhar sakta hai, dilution.

**Rule:** chunk_size â‰ apne **typically expected answer length**. Agar answer 2-3 paragraphs hota hai â€ 600-800 chars. Agar 1-line fact â€ 150-300 chars.

## Nutshell

Chunking = document ko aise chhote tukdo mein todna ke har ek ek poora idea rakhe â€ size 500-1000 chars, overlap 100-200.

## Common Mistakes
- ❌ `overlap=0` â€ boundary pe toota concept aadha-baad milega â†’ fix: hamesha 10-20% overlap (chunk_size/5 ya 100-200)
- ❌ `chunk_size` bhi bada rakha (e.g. 8000) â€ ek chunk mein poora doc â†’ dilute retrieval + context overflow â†’ fix: 500-1000 start karo
- ❌ char count hi dekha, token nahi â†’ LLM context se bahar â†’ fix: 3.6 token-aware splitter, ya `chars * 0.25 â‰ˆ tokens` rough estimate

## What It Is NOT
- ⚠️ Ek simple `text.split(" ")` nahi â€’ that random word-break hota hai â€– proper splitter boundaries par todti hai
- ⚠️ Always-perfect â€’ chunk quality still depends on doc structure â€' messy PDFs (scanned) need OCR (next phases)
- ⚠️ One-size-fits-all â€’ legal docs vs code docs vs FAQs â€’ alag alag chunk_size chahiye
