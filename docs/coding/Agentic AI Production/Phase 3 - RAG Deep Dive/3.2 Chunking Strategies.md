# 3.2 Chunking Strategies

3.1 mein humne dekha — pura document FAISS mein nahi daal sakte, pehle todna padta hai. Ek chhota text file toh chhota tha, par socho tumhari ek company policy **200-page ka PDF** ho. Kya usse ek hi chunk mein daal denge? Nahin — dohi mushkil: (1) context window bhar jayega, (2) retrieval quality gir jaati hai (sabse related chunk poora document ho jayega, kuch filter nahi hua).

## Kyu todna padta hai — ek textbook analogy

Ek chapter bada ho toh usse sections mein todti ho — har section ek independent idea rakhta hai. Wahi chunk: ek chunk ek **coherent idea ya paragraph** rakhe, aise ki retrieval ke time woh sahi tukda nikal sake.

- **chunk_size** — kitne characters/words ek chunk mein hain (1000 = ~150-250 words).
- **chunk_overlap** — agle chunk ke start mein previous chunk ka last `overlap` chars repeat karo — taki jo concept boundary pe toota ho, uski poori jaankari dono mein mile.

## 3 strategies — kaun si chahiye?

**1. Fixed-size** — har fixed chars pe todta hai. Simple lekin ek word ko beech mein split kar sakta hai.

**2. Recursive (recommended)** — `RecursiveCharacterTextSplitter` pehle `\n\n` (paragraph) se try karta — agar nahi hua toh `\n` (line) — phir `" "` (space) — phir character. Matlab pehle **logical boundaries** par todna, sirf jab zaroorat ho tabhi character-level tak girna.

**3. Token-aware** — (3.6 mein detail) — LLM ke token limit ke hisaab se todna (ek word kabhi-kabhi 3 tokens bhi ho sakta hai).

## Code: alag alag chunk_size — se kya farak padta hai?

```python
# chunk_compare.py
from langchain.text_splitter import RecursiveCharacterTextSplitter

doc = "The student discount gives 50% off for grades 6-10. " * 20  # 20x repeat = badi text

for size in (200, 500, 1000):
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=size,
        chunk_overlap=0,          # pehle overlap nahi — size hi dekhte hain
        separators=["\n\n", "\n", " ", ""]
    )
    chunks = splitter.split_text(doc)
    print(f"chunk_size={size} -> {len(chunks)} chunks; first len={len(chunks[0])}")
```

Line-by-line: `"..." * 20` — ek hi idea ko 20 baar repeat kara — document badi ban gaya. `RecursiveCharacterTextSplitter` — separators priority order — pehle paragraph, baad mein space, aakhir mein char. `split_text(doc)` — text → chunk list. `len(chunks[0])` — pehle chunk ki length — size se kuchh kam honi chahiye (kyunki paragraph boundary pe cut karega).

## Goldilocks rule — chunk_size kaise chunhein?

- **100-300 chars** — FAQ / short fact — precise retrieval, lekin boundary cut hoga.
- **500-1000 chars** — paragraphs / snippets — readable + good retrieval — **most common sweet spot**.
- **1500+ chars** — essays — full context, lekin prompt bhar sakta hai, dilution.

**Rule:** chunk_size ≈ apne **typically expected answer length**. Agar answer 2-3 paragraphs hota hai — 600-800 chars. Agar 1-line fact — 150-300 chars.

**Troubleshooting:**

- alag counts — text same hona chahiye — (randomness nahi hai) — doc string check karo
- overlap=0 hone par bhi sahi lage — lekin production mein 10-20% overlap daalna na bhoolo

## Nutshell

Chunking = document ko aise chhote tukdo mein todna ke har ek poora idea rakhe — size 500-1000 chars, overlap 100-200.

## Common Mistakes
- ❌ `overlap=0` — boundary pe toota concept aadha-baad milega → fix: hamesha 10-20% overlap (chunk_size/5 ya 100-200)
- ❌ `chunk_size` bhi bada rakha (e.g. 8000) — ek chunk mein poora doc → dilute retrieval + context overflow → fix: 500-1000 start karo
- ❌ char count hi dekha, token nahi → LLM context se bahar → fix: 3.6 token-aware splitter, ya `chars * 0.25 ≈ tokens` rough estimate

## What It Is NOT
- ⚠️ Ek simple `text.split(" ")` nahi — that random word-break hota hai — proper splitter boundaries par todti hai
- ⚠️ Always-perfect — chunk quality still depends on doc structure — messy PDFs (scanned) need OCR (next phases)
- ⚠️ One-size-fits-all — legal docs vs code docs vs FAQs — alag alag chunk_size chahiye

## In Your Own Words

<details>
<summary>1. Overlap kyun zaroori hai?</summary>
**Jawab:** Kyunki agar ek concept do chunks ke beech se jaye — pehle chunk mein aadha, doosre mein aadha — toh dono retrieve hone par partial ho sakta hai. Overlap repeat karke dono mein poori jaankari rakhte hain.
</details>

<details>
<summary>2. RecursiveCharacterTextSplitter — recursion kahan hai?</summary>
**Jawab:** Recursion = separator list pe recursively try karna — pehle `\n\n`, fail → `\n`, fail → `" "`, fail → char. Jab tak chunk target size mein na ho, tab tak chhote separator pe girta raha.
</details>

<details>
<summary>3. Character split vs token split — kaun sahi?</summary>
**Jawab:** Token — kyunki LLM tokens count karta hai. Par token split slow hai — isliye pehle char splitter se experiment karte hain, phir 3.6 modular mein token-aware lagate hain.
</details>
