# 3.7 Agentic RAG

3.6 mein humne dekha — ek `RAG` class jo ek beparaah query lega, ek hi baar search karega (k=3), LLM ko context do, answer dega. Par real mein agent ek baar search se kaafi nahi samajhta — kabhi dobara search karta hai, query reword karke phir try karta, kabhi decide karta hai ki kaafi hai. **Simple RAG = ek fixed search. Agentic RAG = LLM khud decide karta hai ki kitni baar, kya search kare, kab takhein.**

## Simple RAG ka limit

Simple pipeline (3.5) ek hi baar `retriever.get_relevant_documents(q)` call karega — fir LLM generate. Agar pehla chunk galat lage — LLM uss galat context par chhuta fuk jayega. Agent kehenge: *"kya mujhe aur dhoondhna chahiye?"* — phir dubara search karenge — query change karke phir se — tab tak sahi nahi milta.

## Agentic RAG = agent loop + retrieval tool

Bridge (Phase 2, 2.3): ReAct agent — *"soch → action → observe → soch..."*. Waise hi agent — uske "action" ki jagah sirf retrieval nahi, ek ya do retrieval tools honge — LLM decide karega ki kaunse call karein, kitni baar, kab takhein. Structure doc: *"Agentic RAG = the LLM decides how to search (rewrite the query, search multiple times, decide when it has enough)."*

## Code: retrieval ek TOOL → agent

```python
# 3.7_agentic_rag.py — LangChain ReAct agent + retrieval tool
import os
from dotenv import load_dotenv; load_dotenv()
from langchain_community.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_huggingface import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS
from langchain_groq import ChatGroq
from langchain_core.tools import tool
from langchain.agents import create_react_agent, AgentExecutor
from langchain_core.prompts import ChatPromptTemplate

# (1) data side — same as 3.5
docs   = TextLoader("rag_example.txt").load()
chunks = RecursiveCharacterTextSplitter(500, 50).split_documents(docs)
emb    = HuggingFaceEmbeddings(model_name="BAAI/bge-small-en-v1.5")
db     = FAISS.from_documents(chunks, emb)

# (2) retrieval ek TOOL — LLM ise call karega jab dhoondhna ho
@tool
def search(query: str) -> str:
    """Search company documents for discounts/policies."""
    docs = db.as_retriever(search_kwargs={"k": 3}).get_relevant_documents(query)
    return "\n\n".join(d.page_content for d in docs)

# (3) LLM — ChatGroq + llama-3.3-70b-versatile
llm = ChatGroq(model="llama-3.3-70b-versatile", temperature=0.3)

# (4) ReAct prompt — tool call ke baad LLM phir sochne aayega
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful RAG agent. Use the search tool only when needed."),
    ("human", "{input}"),
    ("placeholder", "{agent_scratchpad}"),
])

# (5) agent + executor
agent = create_react_agent(llm, tools=[search], prompt=prompt)
ex    = AgentExecutor(agent=agent, tools=[search], verbose=True, max_iterations=3)

# (6) run — LLM khud decide karega kitni baar search kare
print(ex.invoke({"input": "College students ke liye discount kya milta?"})["output"])
```

Line-by-line: (1) data side — 3.5 waala, ab `db` ready. (2) `@tool` — `search` ko LangChain tool banata — docstring — LLM ko bataati — kabhi call kare; `get_relevant_documents` — chunks → string. (3) `ChatGroq(..., temperature=0.3)` — generation LLM. (4) ReAct prompt — system role + user input + `agent_scratchpad` placeholder — agent ke thought-trace yehin aayega. (5) `create_react_agent` — agent banata; `AgentExecutor` run karta — `verbose=True` tool calls dikhata — `max_iterations=3` anti-loop. (6) `ex.invoke({"input": q})` — LLM pehle sochta — (maybe tool call) — result dekhta — fir generate karta — **yehi agentic behavior: LLM ne khud decide kiya ki search zaroori tha.**

## Nutshell

Agentic RAG = agent loop + retrieval tool; LLM khud decide karta hai kitni baar search kare — simple RAG se zyada flexible + accurate.

## Common Mistakes
- ❌ `max_iterations` bahut bada (10) → agent loop mein phas sakta → fix: 2-3 rakho
- ❌ Retrieval tool mein k bahut bada (10) → context overflow → fix: k=3
- ❌ Agent ko bina tool ke bheja → search hi nahi karega → fix: tools=[search] dena zaroori

## What It Is NOT
- ⚠️ Har query pe search zaroori nahi — simple factual answers mein agent seedha jawab de sakta hai
- ⚠️ Infinite loop safe nahi — `max_iterations` lagana zaroori — warna agent ghoomta rahega
- ⚠️ Smart retrieval nahi — agent decide karta hai *kab* search kare, par *kaise* search kare woh abhi bhi fixed (top-k) hai — 3.6 modular mein aur improve hoga

## In Your Own Words

<details>
<summary>1. Simple RAG aur Agentic RAG mein kya fark hai?</summary>
**Jawab:** Simple RAG ek baar search karta hai aur LLM ko de deta. Agentic RAG mein LLM khud decide karta hai — kabhi ek baar, kabhi dobara, query change karke — jab tak sahi context na mile.
</details>

<details>
<summary>2. `agent_scratchpad` placeholder kya hai?</summary>
**Jawab:** Yeh woh jagah hai jahan agent ke sochne ke steps (thoughts, tool calls, results) store hote hain. LLM ko pata chalta hai ki usne pehle kya socha aur kya result aaya — isliye agla step le sakta hai.
</details>

<details>
<summary>3. `max_iterations=3` kyun rakhte hain?</summary>
**Jawab:** Anti-loop safety. Agar agent ko sahi answer nahi mil raha, woh baar baar search karta rahega. 3 steps mein limit hota hai — ya toh answer mil jaata hai, ya fallback answer aata hai.
</details>
