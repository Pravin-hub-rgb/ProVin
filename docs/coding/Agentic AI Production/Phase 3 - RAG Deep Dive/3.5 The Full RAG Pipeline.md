# 3.5 The Full RAG Pipeline

Up to 3.4, chunk → embed → store → retrieve is done. Now the last — the most exciting step: **generate** — the LLM gets the retrieved chunks + the question, and writes a natural-language answer. This is the full RAG pipeline — data side + LLM side together.

## Full pipeline — 6 boxes, one arrow

```
[Documents] → [Chunk] → [Embed] → [Vector Store] → [Retrieve top-k] → [LLM generate]
    3.1      3.2/3.4   3.3        3.4          3.4              THIS FILE
```

Generate is done only by the LLM — but the LLM gives the right answer only when it gets **direct context, without hallucination.** Hence the hard requirement — the prompt: *"Answer using ONLY this context."*

## LLM — ChatGroq + llama-3.3-70b-versatile

Up to 3.1-3.4 there were only embeddings (bge, local, free). For generation we need a chat LLM — user spec: **ChatGroq** + `llama-3.3-70b-versatile` (Groq free tier), key `GROQ_API_KEY` from env.

## Code: end-to-end RAG

```python
# 3.5_full_rag.py — the whole pipeline at once
import os
from dotenv import load_dotenv
load_dotenv()                                  # (1) GROQ_API_KEY from .env

from langchain_community.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_huggingface import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS
from langchain_groq import ChatGroq
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

# (2) data side — load → chunk → embed → store → retrieve
docs   = TextLoader("rag_example.txt").load()
chunks = RecursiveCharacterTextSplitter(500, 50).split_documents(docs)
emb    = HuggingFaceEmbeddings(model_name="BAAI/bge-small-en-v1.5")
db     = FAISS.from_documents(chunks, emb)
retriever = db.as_retriever(search_kwargs={"k": 3})

# (3) generation side — LLM + "ONLY context" prompt
llm    = ChatGroq(model="llama-3.3-70b-versatile", temperature=0.3)
prompt = ChatPromptTemplate.from_template(
    "Answer using ONLY this context:\n{context}\n\nQuestion: {question}")

# (4) Document list → string joiner
def fmt_docs(d): return "\n\n".join(x.page_content for x in d)

# (5) LCEL chain — context(retriever|fmt) + question(passthrough) → prompt → llm → text
chain = {"context": retriever | fmt_docs,
         "question": RunnablePassthrough()} | prompt | llm | StrOutputParser()

# (6) run
print(chain.invoke("Student discount kya hai?"))
```

Line by line: (1) `load_dotenv()` — `GROQ_API_KEY` from `.env` — never hardcode in code. (2) data side — the 3.1-3.4 pipeline; `as_retriever(k=3)` top-3. (3) `ChatGroq(model="llama-3.3-70b-versatile", temperature=0.3)` — generation; low temp — deterministic. "ONLY this context" — anti-hallucination instruction. (4) `fmt_docs` — Document list → one string — the LLM likes strings. (5) LCEL dict: `context`=`retriever|fmt_docs` (2 runnables chained), `question`=`RunnablePassthrough()` — user input straight; then `|prompt|llm|StrOutputParser()`. (6) `chain.invoke(q)` — retriever → chunks → prompt → llm → final text.

## Wrong vs Right — why RAG works

- **Without RAG (prompt only):** LLM "maybe 10th grade students get some offer too?" — guessed — could be wrong.
- **With RAG:** "Student discount 10th standard ko 50% off milta hai (source: rag_example.txt)" — quoted from the doc — verifiable.

**Troubleshooting:**
- `401 Unauthorized` → `GROQ_API_KEY` not set → export it or put it in `.env`
- model name `not found` → try `llama-3-70b-8192`
- answer still hallucinating → temperature=0.1, make the prompt "ONLY" stronger
- retriever empty → chunks=0 — chunk_size below 500 — check file load

## Nutshell

Full RAG = load → chunk → embed → store → retrieve(top-k) → LLM; a hard "ONLY context" prompt reduces hallucinations.

## Common Mistakes
- ❌ Forgot "use this context" → LLM writes from memory → fix: hard `Answer using ONLY this context`
- ❌ k too big (10) → too much context for the LLM — overflow → fix: k=2-3
- ❌ temperature 0.7 → random answer → fix: 0.1-0.3 (for fact Q&A)

## What It Is NOT
- ⚠️ Not magic — if the doc is wrong — the LLM will be wrong too — RAG amplifies that wrong
- ⚠️ Not an alternative to the vector DB — the whole pipeline needs embed→store→retrieve to run
- ⚠️ Not static — change the retrieval query (rewrite), and the answer improves (3.6/3.7)

## In Your Own Words

<details>
<summary>1. Why use LCEL `a | b | c` — not a simple function?</summary>
**Answer:** LCEL is chainable + streamable + LangSmith-instrumentable. A normal function isn't — middleware/logging/retry don't attach easily.
</details>

<details>
<summary>2. What does temperature=0.3 do — isn't 0.7 better?</summary>
**Answer:** 0.7 can be creative — but it raises hallucination risk — for fact-based Q&A, 0.1-0.3 is better — deterministic + faithful.
</details>

<details>
<summary>3. Why does `format_docs` turn a Document list into a string? Can't we pass Documents directly?</summary>
**Answer:** The LLM prompt template wants a string — not a Document object — so we join the retrieved list into a string.
</details>
