# 3.6 Modular RAG for Production

3.5 ka pipeline ek hi file (`3.5_full_rag.py`) tha â€– sab kuch ek saath. Par capstone (9.x) mein jab 5 documents, 3 query types, monitoring aayenge â€– ek file bahut messy. Production code samajhne laayak tab banti hai jab har badi **ek class / ek responsibility** le.

## Production code kyun modular hota hai?

Socho restaurant â€– paani bhi order de sakta? Nahin â€ ek paani laane wala, ek order lene wala, ek pakane wala. Waise hi RAG mein â€** EmbeddingManager, TextProcessor, VectorStore, RAG â€** â€– har class apni ek zimmedari rakhegi. (Transcript ne yehi architecture dikhaya tha.)

## Code: 4 classes + 1 orchestrator

```python
# 3.6_modular_rag.py
import os
from dotenv import load_dotenv; load_dotenv()          # GROQ_API_KEY env mein
from langchain_community.document_loaders import DirectoryLoader
from langchain_text_splitter import RecursiveCharacterTextSplitter
from langchain_huggingface import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS
from langchain_groq import ChatGroq
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

class EmbeddingManager:                        # (1) only embeddings
    def __init__(self, model="BAAI/bge-small-en-v1.5"):
        self.emb = HuggingFaceEmbeddings(model_name=model)
    def embed_query(self, t): return self.emb.embed_query(t)

class TextProcessor:                           # (2) load + chunk
    def __init__(self, size=500, overlap=50):
        self.sp = RecursiveCharacterTextSplitter(size, overlap)

class VectorStore:                             # (3) embed + store + persist
    def __init__(self, emb_mgr, path="faiss_index"):
        self.emb = emb_mgr.emb; self.path = path
    def build(self, chunks):
        db = FAISS.from_documents(chunks, self.emb); db.save_local(self.path); return db
    def load(self):
        return FAISS.load_local(self.path, self.emb, allow_dangerous_deserialization=True)

class RAG:                                     # (4) retriever + generator
    def __init__(self, vs, k=3):
        self.db = vs.load(); self.k = k
        self.retriever = self.db.as_retriever(search_kwargs={"k": k})
        self.llm = ChatGroq(model="llama-3.3-70b-versatile", temperature=0.3)
        self.prompt = ChatPromptTemplate.from_template("Answer ONLY:\n{ctx}\n\nQ: {q}")
    def _fmt(self, d): return "\n\n".join(x.page_content for x in d)
    def query(self, q):
        chain = {"ctx": self.retriever | self._fmt, "q": RunnablePassthrough()} | self.prompt | self.llm | StrOutputParser()
        return chain.invoke(q)

# â†ªâªâª use â€– capstone (9.x) mein bhi yehi classes
emb_mgr = EmbeddingManager(); tp = TextProcessor()
db = VectorStore(emb_mgr)                     # build once, then load_local
docs = DirectoryLoader("docs", glob="**/*.txt").load()
print(RAG(db, k=3).query("Student discount kya hai?"))
```

Line-by-line: `EmbeddingManager` â€ embedding model ek jagah; `.emb` reuse â€ index+query par dim match. `TextProcessor` â€ split config ek jagah. `VectorStore.build` â€ embed+index+**save_local**; `.load` â€ disk se reload (rebuild mat). `RAG` â€ retriever+LLM+prompt ek unit; `_fmt` â€ Documentsâ†string. `chain` LCEL â€ 3.5 waala, lekin reusable; `RAG(db).query(q)` â€ ek clean call. `DirectoryLoader(glob="**/*.txt")` â€ poora folder load kare.

## Nutshell

Modular RAG = 4 classes (Embedding / TextProcessor / VectorStore / RAG); har class ek responsibility â€ capstone inhe reuse karega.

## Common Mistakes
- ❌ Rebuild index har run â† slow + overwrite â† fix: build save_local, phir load_local
- ❌ Retriever + index alag models â†â dim mismatch â† fix: ek `EmbeddingManager` inject karo
- ❌ `langchain.text_splitter` import â† langchain>=0.3 mein deprecated â† fix: `langchain_text_splitter`

## What It Is NOT
- Ï € Over-engineering â€“ small experiment mein 3.5 wala ek file chalega
- Ï € Framework magic â€– yeh bas code organize karna â€ pipeline koi naya nahi
- Ï € 7 classes banane se accha â€– SRP (single responsibility) matter karta hai, count nahi
