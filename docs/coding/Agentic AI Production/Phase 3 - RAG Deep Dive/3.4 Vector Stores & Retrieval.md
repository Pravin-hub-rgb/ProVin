# 3.4 Vector Stores & Retrieval

In 3.3 chunks became vectors — now we put those vectors somewhere, where **whenever a question arrives, we can pull the 3-5 closest vectors against it.** That place is a **vector store** (FAISS/Chroma). FAISS = Facebook AI Similarity Search — runs on CPU, in-memory, demo-friendly.

## What a vector store is

A database that stores **vectors** instead of text — and internally builds a **similarity index** (like a sorted map) so nearest neighbors come back in `log(n)` — faster than a straight linear scan.

## Code: build index + retrieve

```python
# 3.4_vector_rag.py
from langchain_community.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_huggingface import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS

docs   = TextLoader("rag_example.txt").load()                 # (1) load
sp     = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = sp.split_documents(docs)                              # (2) chunk
emb    = HuggingFaceEmbeddings(model_name="BAAI/bge-small-en-v1.5")  # (3) embed model
db     = FAISS.from_documents(chunks, emb)                     # (4) store + index
retriever = db.as_retriever(search_kwargs={"k": 2})            # (5) retrieve wrapper
hits = retriever.get_relevant_documents("Student discount kya hai?")
print("top chunk:", hits[0].page_content)

db.save_local("faiss_index")                                   # (6) persist to disk
db2 = FAISS.load_local("faiss_index", emb, allow_dangerous_deserialization=True)  # (7) reload
```

Line by line: `TextLoader(...).load()` — text → `Document` list. `RecursiveCharacterTextSplitter(500, 50)` — 500-char chunks, 50-char overlap. `HuggingFaceEmbeddings` — 384-dim local model. `FAISS.from_documents(chunks, emb)` — embeds every chunk + builds a similarity index (first call ~10s). `db.as_retriever(search_kwargs={"k": 2})` — a Runnable wrapper — usable inside any prompt pipeline; `k=2` means top-2 chunks. `get_relevant_documents(q)` — embed q, fetch the nearest-2 from FAISS. `save_local("faiss_index")` — creates `index.faiss` + `index.pkl` inside the folder. `FAISS.load_local(..., allow_dangerous_deserialization=True)` — reload — you need the same `emb` object (so dims match).

## similarity_search vs as_retriever — why both?

- `db.similarity_search(query, k=3)` — directly top-k chunks, when you need a one-off.
- `db.as_retriever()` — a `Runnable` — can be joined into a LangChain **prompt pipeline** (LCEL) — like `retriever | prompt | llm` (in 3.5).

**Troubleshooting:**
- `k=2` error — fewer chunks than k — keep k below the chunk count
- `save_local` warning — FAISS saves a pickle — `allow_dangerous_deserialization=True` is required
- dimension error on `load_local` — the reload model (emb) mismatch — pass the same `HuggingFaceEmbeddings`
- `faiss_index` folder got created — next run, don't rebuild with `from_documents` — use `load_local`

## Nutshell

Vector store = vectors + similarity index; FAISS is in-mem for demos, Chroma is persistent. `as_retriever` = Runnable form (for pipelines), `similarity_search` = direct top-k.

## Common Mistakes
- ❌ Rebuild the index every run (slow) → fix: `save_local`/`load_local` — save once, don't rebuild every time
- ❌ Didn't pass `allow_dangerous_deserialization` on reload → `load_local` crashes → fix: pass it (local trusted file)
- ❌ Made the retrieve wrapper but didn't set `k` → default k=4 — can exceed chunks → fix: set `search_kwargs={"k": 3}`

## What It Is NOT
- ⚠️ Not an exact keyword DB — searching "discount" won't bring "scholarship" — it's semantic similarity, fuzzy
- ⚠️ Not persistent by default — FAISS is in-memory — data is gone on restart — `save_local` is required
- ⚠️ Chroma is NOT a drop-in replacement for FAISS — different APIs — stick to one in a project

## In Your Own Words

<details>
<summary>1. `as_retriever()` vs `similarity_search` — when to use which?</summary>
**Answer:** `similarity_search` — when you want top-k directly (standalone). `as_retriever` — when you want to join it into a LangChain LCEL pipeline — `retriever | prompt | llm` — needs to be a Runnable to join.
</details>

<details>
<summary>2. What does k do in retrieval?</summary>
**Answer:** Top-k — the number of chunks sent to the LLM as context. k too big — context fills (tokens wasted). k too small — the right answer may be missed. 3-5 is most common.
</details>

<details>
<summary>3. Why not rebuild FAISS on every run?</summary>
**Answer:** Embedding model load + index build ~10s/GB of data — slow. Build once + `save_local`, then `load_local` on the next run is great.
</details>
