# 3.4 Vector Stores & Retrieval

3.3 mein chunks vectors mein badal gaye â€‹â€” ab in vectors ko ek jagah daal ke rakhte hain, jahan se **jab bhi ek sawaal aaye, uske against sabse kareeb ke 3-5 vectors nikal saken.** Yeh jagah hai **vector store** (FAISS/Chroma). FAISS = Facebook AI Similarity Search â€– CPU pe chalti, in-memory, demo-friendly.

## Vector store kya hoti hai

Ek aisi database jo text ke bajaye **vectors** store karti hai â€– aur internally ek **similarity index** banaati hai (jaise ek sorted map) taake `log(n)` mein nearest neighbor mil sake â€” seedha linear scan se bhi tez.

## Code: build index + retrieve

```python
# 3.4_vector_rag.py
from langchain_community.document_loaders import TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_huggingface import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS

docs   = TextLoader("rag_example.txt").load()                 # (1) load
sp     = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
chunks = sp.split_documents(docs)                              # (2) chunk
emb    = HuggingFaceEmbeddings(model_name="BAAI/bge-small-en-v1.5")  # (3) embed model
db     = FAISS.from_documents(chunks, emb)                     # (4) store + index
retriever = db.as_retriever(search_kwargs={"k": 2})            # (5) retrieve wrapper
hits = retriever.get_relevant_documents("Student discount kya hai?")
print("top chunk:", hits[0].page_content)

db.save_local("faiss_index")                                   # (6) persist to disk
db2 = FAISS.load_local("faiss_index", emb, allow_dangerous_deserialization=True)  # (7) reload
```

Line-by-line: `TextLoader(...).load()` â€ text â†’ `Document` list. `RecursiveCharacterTextSplitter(500, 50)` â€ 500-char chunks, 50-char overlap. `HuggingFaceEmbeddings` â€ 384-dim local model. `FAISS.from_documents(chunks, emb)` â€ har chunk embed kare + ek similarity index banaaye (first call ~10s). `db.as_retriever(search_kwargs={"k": 2})` â€ ek Runnable wrapper â€– jisse koi bhi prompt pipeline mein use ho sakta hai; `k=2` matlab top-2 chunks. `get_relevant_documents(q)` â€ q ko embed kare, FAISS se nearest-2 laaâ€. `save_local("faiss_index")` â€ folder ke andar `index.faiss` + `index.pkl` banata hai. `FAISS.load_local(..., allow_dangerous_deserialization=True)` â€ reload â€– same `emb` object chahiye (taki dims match rahein).

## similarity_search vs as_retriever â€ kyun dono hain?

- `db.similarity_search(query, k=3)` â€ directly top-k chunks, jab tumhe ek-off cheez chahiye.
- `db.as_retriever()` â€ ek `Runnable` â€– LangChain ke **prompt pipeline** (LCEL) mein jod sakte hain â€– jaise `retriever | prompt | llm` (3.5 mein).

- `save_local` warning â€ FAISS pickle load karta hai â€ `allow_dangerous_deserialization=True` zaroori
- `load_local` par dimension error â€ reload wale model (emb) mismatch â€– same `HuggingFaceEmbeddings` pass karo
- `faiss_index` folder ban gaya â€– agle run mein `from_documents` se bana, persist se mat dobara â€ load_local karo

## Nutshell

Vector store = vectors + similarity index; FAISS in-mem demo, Chroma persistent. `as_retriever` = Runnable form (pipelines ke liye), `similarity_search` = direct top-k.

## Common Mistakes
- ❌ Rebuild index every run (slow) â†’ fix: `save_local`/`load_local` â€ save karo, baar-baar rebuild mat karo
- ❌ `allow_dangerous_deserialization` nahi diya reload pe â†’ load_local crash â†’ fix: laga ke do (local trusted file hai)
- ❌ Retrieve wrapper banaya lekin `k` nahi diya â†’ default k=4 â€â†¡ chunks se zyada ho sakta â†’ fix: search_kwargs={"k": 3} set karo

## What It Is NOT
- ⚠️ Exact keyword DB nahi â€– "discount" likhkar "scholarship" nahi aayega â€– semantic similarity, fuzzy hoti hai
- ⚠️ Persistent by default nahi â€– FAISS in-memory hoti hai â€ restart par data chala jayega â€ save_local zaroori
- ⚠️ Chroma â†’ faiss drop-in replacement nahi â€– dono alag APIs hain â€– ek project mein ek hi jodke rakho
