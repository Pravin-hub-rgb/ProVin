# 3.1 RAG from the Ground Up

In 2.11 you deployed the LangGraph agent to MLflow + HuggingFace Spaces — logs are flowing, everything's fine. But now a scene comes up where the agent will lose: a user asks *"what's the student discount policy in our latest pricing docs?"* — the agent will answer from its training that only goes up to 2019 (because your docs were made around then). This is RAG's time.

## RAG — when the model doesn't write from memory, but from the right page

Think of an exam — you know only 80% of the syllabus, the rest is only in your classroom notes. A student who only memorized their notebook — their "extra" answer will be wrong (hallucinate). The RAG student: the examiner first says *"open the book, show me that extra page," then write.* Meaning: **give the LLM the right part of the document (context), then let the LLM write the answer from that context** — without retraining/fine-tuning the model.

## The 5-step pipeline — at a glance

1. **Load** — bring in documents (PDF/TXT/site) → *3.2*
2. **Chunk** — break the big doc into small pieces → *3.2*
3. **Embed** — each chunk → 384-number vector → *3.3*
4. **Store** — vectors → FAISS vector DB → *3.4*
5. **Retrieve + Generate** — pull top chunks by the question, send context+question to the LLM → *3.5*

## Code: skeleton — each step a function

```python
# rag_overview.py — minimum RAG skeleton (understand every line)
# Setup: pip install langchain-community langchain-huggingface faiss-cpu
# create rag_example.txt — put inside:
#   "Student discount 10th standard ko 50% off milta hai."

from langchain_community.document_loaders import TextLoader          # (1) loader
from langchain.text_splitter import RecursiveCharacterTextSplitter  # (2) chunker
from langchain_huggingface import HuggingFaceEmbeddings             # (3) embed
from langchain_community.vectorstores import FAISS                  # (4) vector DB

def load_documents(path):                                  # step-1
    return TextLoader(path).load()

def split_chunks(docs, size=1000, overlap=200):            # step-2
    sp = RecursiveCharacterTextSplitter(chunk_size=size, chunk_overlap=overlap)
    return sp.split_documents(docs)

def make_embeddings():                                     # step-3
    return HuggingFaceEmbeddings(model_name="BAAI/bge-small-en-v1.5")

def build_vector_store(chunks, emb):                       # step-4
    return FAISS.from_documents(chunks, emb)

def retrieve(db, question, k=3):                           # step-5
    ret = db.as_retriever(search_kwargs={"k": k})
    return ret.get_relevant_documents(question)

docs   = load_documents("rag_example.txt")   # 1. load
chunks = split_chunks(docs)                  # 2. chunk
emb    = make_embeddings()                   # 3. embed model
db     = build_vector_store(chunks, emb)     # 4. store
hits   = retrieve(db, "Student discount kya hai?")
print("Retrieved", len(hits), "chunks")
```

Line by line: `TextLoader(path).load()` — text file → `Document` list (each has `page_content` + `metadata`). `RecursiveCharacterTextSplitter` — 1000 chars/chunk, last 200 chars repeat into the next chunk. `HuggingFaceEmbeddings("bge-small-en-v1.5")` — local 384-dim model (free, ~84MB). `FAISS.from_documents` — vectors + similarity index (first run takes 10-20s). `as_retriever(k=3)` — gives top-3 chunks. `get_relevant_documents(q)` — embed q too, fetch the nearest-3 from FAISS.

## TEST

**Run:** `python rag_overview.py` (with rag_example.txt, in the same folder).
**Expected:**
```
Retrieved 3 chunks
```
**Troubleshooting:**
- `No module named 'langchain_community'` → `pip install langchain-community`
- `FileNotFoundError: rag_example.txt` → run the script in the folder where the file is
- chunks < 3 → rag_example.txt is too small → make the text bigger, or do `".... " * 5`
- first FAISS/emb run takes 10-30s → normal after first cache

## Nutshell

RAG = take the right part of the document, then write — without retraining. 5 steps: load → chunk → embed → store → retrieve + generate.

## Common Mistakes
- ❌ Writing "use the docs to answer" in the prompt and the model writes from memory → fix: hard `Answer using ONLY this context`
- ❌ The whole doc in one chunk → context overflow + diluted retrieval → fix: chunk_size 500-1000
- ❌ Embedding dim mismatch (384 vs 768) → FAISS crash → fix: index + query both from the same model

## What It Is NOT
- ⚠️ Not fine-tuning — the model is never updated, we just put that context into the prompt
- ⚠️ Not hallucination-proof — if the chunk itself is wrong, the LLM can still write wrong — garbage in, garbage out
- ⚠️ Not "just add docs, answers will come" — chunks must be good — pay attention to 3.2/3.4

## In Your Own Words

<details>
<summary>1. Write the 5 steps of RAG in one line.</summary>
**Answer:** Load → Chunk → Embed → Store → Retrieve+Generate. Bring the document, break into small pieces, turn into numbers, put in vector DB, pull nearest by the question, have the LLM write it.
</details>

<details>
<summary>2. Does RAG work just by writing "use the docs" in the prompt?</summary>
**Answer:** No — the model will only rely on its training memory. RAG needs two things: (a) a retriever that pulls the right chunk, and (b) putting that chunk inside the prompt. Prompt alone ≠ RAG.
</details>

<details>
<summary>3. Why are embeddings necessary — can't we just compare text directly?</summary>
**Answer:** Because similarity runs on vectors, direct text comparison is less accurate. Embeddings give text → a meaning-carrying vector — where "discount" ≈ "50% off" land close to each other.
</details>
