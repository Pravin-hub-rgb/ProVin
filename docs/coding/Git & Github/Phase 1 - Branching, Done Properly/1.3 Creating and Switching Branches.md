Alright, enough theory. You know why branches exist and how to name them. Now let's type the actual commands. This is the part you'll do dozens of times a day on a real job.

**First, the commands you need:**

Here's what `git branch` looks like in a real project with three branches:

```
$ git branch
  feature/navbar
* main
  fix/login-button
```

The `*` next to `main` tells you that's your current branch. Without it, you'd have to guess which branch you're on. Run this command often.

To see remote branches too:

```
$ git branch -a
  feature/navbar
* main
  fix/login-button
  remotes/origin/HEAD -> origin/main
  remotes/origin/feature/navbar
  remotes/origin/main
```

The `remotes/origin/*` entries are GitHub's versions that your computer knows about.

To switch between branches:
```bash
git switch <branch-name>      # switch to a branch that already exists
git switch -c <new-name>      # create a NEW branch and switch to it in one step
```

When you switch, Git tells you what happened:

```
$ git switch feature/navbar
Switched to branch 'feature/navbar'

$ git switch main
Switched to branch 'main'
```

If you have uncommitted changes, Git will warn you instead of silently switching:

There's also an older way that still works:
```bash
git checkout <branch-name>    # same as git switch
git checkout -b <new-name>    # same as git switch -c
```

`git switch` was added in 2019 because `git checkout` was doing too many things. `switch` only switches branches. The old `checkout` command also restores files, checks out specific commits, and does other stuff. For branches, use `switch`. It's cleaner.

The diagram above shows the complete workflow visually — 6 steps from start to PR. Steps 1-3 happen in sequence every time you start something new. Steps 4-6 repeat as you work.

**The standard workflow for starting new work:**

```bash
# Step 1: Go to main and make sure it's up to date
git switch main
git pull origin main

# Step 2: Create your new branch
git switch -c feature/navbar

# Step 3: Do your work, save your files
# (edit code here)

# Step 4: Commit your changes
git add -p
git commit -m "Add responsive navbar"

# Step 5: Share your branch on GitHub
git push -u origin feature/navbar
```

The `-u` flag the first time you push sets up a connection. After that, you can just type `git push` and Git knows where to send it.

**What happens when you switch branches?**

When you switch from `feature/navbar` to `main`, Git rewrites your files to match `main`. The files in your editor change. This can be scary at first, but it's fine because:

- Your commits are safe in the `.git` folder
- Your uncommitted changes might carry over (if possible) or Git will block the switch

If Git refuses because you have unsaved changes, you have three choices:

1. **Commit** them if they're ready
2. **Stash** them (put them aside temporarily) with `git stash`, switch, then come back and `git stash pop`
3. **Discard** them with `git checkout -- <filename>` (careful, this is permanent)

**The most important thing to remember:**

Always pull the latest `main` BEFORE creating a new branch. If you branch off an old version of main, your new branch starts behind. That means extra conflicts later.

```
git switch main
git pull origin main            # get the latest
git switch -c feature/navbar    # now you're starting fresh
```

Don't skip the pull. Even if you think main hasn't changed. One `git pull` costs 2 seconds. One conflict bomb costs hours.

**Also watch out for:**

Accidentally creating a branch while you're on another feature branch. If you're on `feature/navbar` and run `git switch -c feature/footer`, the new branch will include ALL the navbar commits too. Always check which branch you're on first. Run `git branch` to see.

**In Your Own Words:**

<details>
<summary>1. What command creates a new branch and switches to it at the same time?</summary>

`git switch -c <branch-name>` (or the older `git checkout -b <branch-name>`).
</details>

<details>
<summary>2. What does the `-u` flag do when you push a branch for the first time?</summary>

It sets up a connection between your local branch and the remote one, so future pushes can be just `git push`.
</details>

<details>
<summary>3. What should you do BEFORE creating a new branch?</summary>

Switch to main and run `git pull origin main` so your new branch starts from the latest version.
</details>

<details>
<summary>4. What happens if you create a new branch while you're on a feature branch?</summary>

The new branch will include all the commits from the feature branch too. Always check which branch you're on first.
</details>

<details>
<summary>5. Git refuses to switch branches because you have unsaved changes. What are your options?</summary>

Commit the changes (if ready), stash them with `git stash` (to come back later), or discard them (permanent — be careful).
</details>
