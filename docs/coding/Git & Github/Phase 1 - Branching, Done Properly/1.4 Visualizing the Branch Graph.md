You remember the `git tree` alias we set up in Phase 0? If you haven't set it up yet, do it now — it's a one-time thing:

```bash
git config --global alias.tree "log --oneline --graph --all --decorate"
```

This alias is about to become your most-used Git command. It shows you the entire history of your repository as an ASCII graph. Once you get comfortable reading this graph, you'll never work blindly again.

**What you're looking at:**

Run `git tree` in any repo with more than one branch. You'll see something like:

```
* 9a8b7c6 (HEAD -> feature/navbar) Add responsive dropdown menu
* 2b3c4d5 Fix z-index on mobile toggle
* 1a2b3c4 (main) Update footer copyright year
* f5e6d7c Add contact form validation
* 8a9b0c1 (origin/main, origin/HEAD) Initial commit with basic layout
* 4d3e2f1 Set up project scaffolding
```

Wait — that's just a straight line. Where's the "graph"? The graph shows branch splits and merges. Here's a more interesting example:

```
*   9a8b7c6 (HEAD -> main) Merge feature/navbar into main
|\
| * 2b3c4d5 (feature/navbar) Add dropdown menu
| * 1a2b3c4 Adjust spacing on mobile
* | f5e6d7c Fix login validation error
* | 8a9b0c1 Add password reset endpoint
|/
* 4d3e2f1 Initial commit
```

Now you can see the branching. The `|\` and `|/` are Git's way of drawing two lines of development that eventually merged. The `| *`  and `* |` lines show commits happening in parallel on different branches. The merge commit at the top (with `*`) has two parents — one from main's work and one from the feature branch.

Let's decode the symbols:
- `*` — a commit
- `|` — a line continuing
- `\` and `/` — lines merging or diverging
- `(HEAD -> main)` — where you are right now (HEAD) and what branch that is
- `(feature/navbar)` — another branch pointing to a specific commit
- `(origin/main)` — the remote's main branch

**Reading the story:**

Once you can read the graph, every repo tells a story. Consider this:

```
*   g8f7e6d (HEAD -> main) Merge deploy/backend
|\
| * d4c3b2a (deploy/backend) Add production DB config
| * c1b2a3d Update server dependencies
* | b9a8c7d Fix homepage meta tags
* | a7b6c5d Update README
|/
* 9f8e7d6 Initial setup
```

Reading from bottom to top: started with initial setup. Then two people worked in parallel — one on `deploy/backend` (adding DB config, updating deps) and one on main directly (fixing meta tags, updating readme). The `deploy/backend` branch was merged into main at the top.

You can answer questions instantly:
- **Where did this branch fork?** Look for the first commit where the lines diverge (where `|\` appears).
- **Has it been merged?** Check if the lines rejoin (where `\|/` or similar appears) and if the branch's commits are part of main's history.
- **Is my branch up to date?** See if main's latest commit appears in your branch's history.

**More visualization commands:**

```bash
# List branches already merged into main
git branch --merged main
# Output:
#   feature/navbar
#   fix/login-handler

# List branches NOT yet merged
git branch --no-merged main
# Output:
#   feature/dark-mode
#   experiment/new-api
```

These are extremely useful for cleanup. Before deleting a branch, always run `--merged` to confirm its work is safely in main:

```bash
git branch -d feature/navbar    # safe: git checks if it's merged
git branch -D feature/navbar    # force delete: even if NOT merged (dangerous!)
```

Lowercase `-d` is safe — Git refuses if the branch isn't fully merged. Uppercase `-D` forces deletion regardless. Get in the habit of using `-d` and only reaching for `-D` when you're absolutely sure.

**Beyond the terminal:**

While `git tree` is powerful, sometimes you want a visual tool. Options include:
- `gitk` — built-in GUI that comes with Git
- `git gui` — another built-in option
- VS Code's Git Graph extension
- GitHub's network graph (Repository → Insights → Network)
- Third-party tools: SourceTree, GitKraken, Tower

The terminal graph is faster for daily use, but GUI tools can be helpful when exploring complex histories with many branches.

**Practical exercise:**

1. Create 2-3 branches off main.
2. Make a different commit on each branch.
3. Run `git tree` after each commit.
4. Merge one branch into main.
5. Run `git tree` again — see the merge commit with two parents.
6. Run `git branch --merged main` — see that the merged branch is listed.

Do this a few times until the graph output is intuitive. You should be able to look at a graph and describe what happened in English.
