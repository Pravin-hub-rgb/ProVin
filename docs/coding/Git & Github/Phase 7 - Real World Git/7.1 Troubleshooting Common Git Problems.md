Things break. Git is great at keeping your data safe, but it's also cryptic when something goes wrong. Here's every common error you'll hit, what it actually means, and how to fix it.

---

## 1. `ORIG_HEAD` Corrupted — `cannot lock ref 'ORIG_HEAD': reference broken`

**What happened:** You tried `git merge` / `git rebase` / `git reset` and Git stores a backup pointer called `ORIG_HEAD` so it remembers where HEAD was before. That pointer file got corrupted.

**Fix:**

```powershell
Remove-Item -LiteralPath ".git\ORIG_HEAD" -Force
```

Linux/Mac:

```bash
rm .git/ORIG_HEAD
```

Then retry your operation. Git recreates `ORIG_HEAD` fresh.

**Why:** `ORIG_HEAD` is a plain text file in `.git/` holding a commit hash. A crash or incomplete operation corrupts it. Safe to delete — it's just a pointer.

---

## 2. Lock Files (`index.lock`, `HEAD.lock`, `ORIG_HEAD.lock`)

**What happened:**

```
fatal: Unable to create '.git/index.lock': File exists.
Another git process seems to be running...
```

**What it is:** Git creates `.lock` files to prevent two operations from running simultaneously. If Git crashes, the lock stays behind.

**Fix:**

```powershell
Remove-Item -LiteralPath ".git\index.lock" -Force
```

Replace `index.lock` with whatever lock file Git complained about. **But** make sure no Git process is actually running first (check Task Manager).

---

## 3. Detached HEAD

**What happened:** You checked out a hash and saw the scary "detached HEAD" message.

**What it is:** `HEAD` normally points to a branch. In detached state, it points directly to a commit. Any commits you make here will be orphaned when you switch away.

**Fix — just get back to a branch:**

```bash
git switch main
```

**Fix — if you made commits and want to keep them:**

```bash
git switch -c rescue-branch
```

This creates a new branch at your current position, rescuing the commits.

**Common causes:** `git checkout <hash>`, `git checkout origin/main`, a failed rebase.

---

## 4. `fatal: refusing to merge unrelated histories`

**What happened:**

```
fatal: refusing to merge unrelated histories
```

**When:** You tried merging branches (or pulling) that don't share a common ancestor.

**Fix:**

```bash
git pull origin main --allow-unrelated-histories
```

or

```bash
git merge other-branch --allow-unrelated-histories
```

**Don't** use this flag casually. If two branches SHOULD share history, figure out why they don't (probably `git init` instead of `git clone`).

---

## 5. `! [rejected]` — Failed to Push

**What happened:**

```
! [rejected] main -> main (non-fast-forward)
error: failed to push some refs
```

**What it is:** Remote has commits you don't have locally. Git refuses to erase them.

**Fix:**

```bash
git pull origin main
# resolve conflicts, then:
git push origin main
```

Or for cleaner history:

```bash
git fetch origin
git rebase origin/main
git push origin main
```

**If you really must force:**

```bash
git push --force-with-lease origin main
```

`--force-with-lease` is safer than `--force` — it checks nobody else pushed first.

---

## 6. `fatal: not a git repository`

**Fix:** Either `cd` to the right directory, or if `.git` was deleted, re-clone the repo. Check with `Get-ChildItem -Force` (Windows) or `ls -la` (Mac/Linux) to see if `.git` exists.

---

## 7. `cannot lock ref 'refs/heads/...'`

**What happened:** You have a branch name that conflicts — e.g., a branch called `feature` AND another called `feature/X`. Git stores refs as files, so `feature` can't be both a file and a directory.

**Fix:**

```bash
git branch -m feature feature-old   # rename the conflicting branch
```

---

## 8. `Your branch and 'origin/main' have diverged`

**What it is:** Both you and the remote have commits the other doesn't.

**Fix — merge:**

```bash
git pull origin main
```

**Fix — rebase (linear history):**

```bash
git fetch origin
git rebase origin/main
git push origin main
```

**Don't** blindly `--force` — you might erase your teammate's commits.

---

## 9. `fatal: bad revision 'HEAD'`

**When:** Fresh repo with no commits yet, or referencing a deleted branch.

**Fix — fresh repo:**

```bash
git commit --allow-empty -m "Initial commit"
```

**Fix — deleted branch:**

```bash
git reflog   # find the actual hash
git show <hash>
```

---

## 10. Ctrl+C During Merge/Rebase

**Fix:**

```bash
git merge --abort
# or
git rebase --abort
```

If `--abort` also fails:

```bash
git reflog
git reset --hard HEAD@{N}   # N = entry before the operation
```

---

## 11. Committed to the Wrong Branch

**Fix — if you haven't pushed yet:**

```bash
# copy the commit hash first
git log --oneline -1

# undo the commit on this branch (keep changes in working dir)
git reset --mixed HEAD~1

# switch to the right branch
git switch -c correct-branch

# commit there instead
git add .
git commit -m "message"
```

**Fix — if you already pushed to the wrong branch:**

```bash
# revert the commit on the wrong branch (safe because it's shared)
git revert <hash>

# cherry-pick that commit to the right branch
git switch correct-branch
git cherry-pick <hash>
```

---

## 12. `bad object refs/remotes/origin/main` — Corrupted Remote Tracking Reference

**What happened:**

```
! [rejected] main -> main (non-fast-forward)
error: failed to push some refs
```

You ran `git pull` and got:

```
fatal: bad object refs/remotes/origin/main
error: did not send all necessary objects
```

**What it is:** Your local remote-tracking reference (`refs/remotes/origin/main`) is corrupted — the commit hash stored there doesn't exist in the remote's object database. This happens when someone force-pushed `main`, the remote history was rewritten, or the local repo's packed-refs file got corrupted.

This is different from #5 (simple push rejection) — there `git pull` works, here `git pull` also fails because the ref itself is corrupted.

**Fix:**

```bash
# Step 1 — Find the actual remote commit hash
git ls-remote origin HEAD

# Step 2 — Directly fix the broken reference
git update-ref refs/remotes/origin/main <hash-from-ls-remote>

# Step 3 — Fetch to verify everything is clean
git fetch origin

# Step 4 — Rebase your local commits on top of remote
git pull --rebase origin main

# Step 5 — Push
git push origin main
```

**Alternative — if `git update-ref` doesn't work:**

```bash
git remote prune origin
git fetch origin
git pull --rebase origin main
git push origin main
```

`git remote prune origin` removes all local remote-tracking refs that no longer exist on the remote. Then `git fetch` rebuilds them fresh.

**In Your Own Words:**

<details>
<summary>1. When there's a simple push rejection (#5), `git pull` works — but why doesn't it work in the corrupted ref case?</summary>

Because in a simple push rejection both the remote and local history are healthy — they've just diverged. But in the corrupted ref case, the commit hash in `refs/remotes/origin/main` doesn't exist in the remote's database, so `git pull` also fails.
</details>

<details>
<summary>2. What does `git remote prune origin` do?</summary>

It cleans up remote-tracking refs. If a branch was deleted on the remote, its local `origin/branch` reference is also removed. In the corrupted refs case, it removes the old broken pointers. Then `git fetch` rebuilds them fresh.
</details>

<details>
<summary>3. Why use `git pull --rebase` in Step 4 instead of `git pull`?</summary>

On a conflict, `--rebase` gives cleaner history — your commits get re-applied on top of the remote's commits, no merge commit is created. History stays linear.
</details>

<details>
<summary>4. When does this error normally occur?</summary>

When the `main` branch was force-pushed on the remote, or remote garbage collection removed old objects, or the local repository's packed-refs file got accidentally corrupted.
</details>

## Quick Reference

| Error | Fix |
|-------|-----|
| `ORIG_HEAD` broken | Delete `.git\ORIG_HEAD` |
| Lock file | Delete `.git\*.lock` |
| Detached HEAD | `git switch main` or `git switch -c rescue-branch` |
| Unrelated histories | `--allow-unrelated-histories` |
| Push rejected | `git pull` first |
| Diverged branches | `git pull` or `git rebase` |
| Wrong branch commit | `git reset HEAD~1` → switch → commit |
| Stuck merge/rebase | `git merge --abort` / `git rebase --abort` |
| Corrupted remote ref (`bad object`) | `git ls-remote origin HEAD` → `git update-ref refs/remotes/origin/main <hash>` → fetch → rebase → push |
