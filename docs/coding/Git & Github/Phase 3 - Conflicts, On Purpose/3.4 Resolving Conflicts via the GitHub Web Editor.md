Sometimes you open a PR and GitHub says "This branch has conflicts that must be resolved." If the conflict is small — a line or two — you don't need to pull locally. You can fix it right on GitHub.com.

**Where to find the web editor:**

On your PR page, if there's a conflict, GitHub shows:

```
⚠️ This branch has conflicts that must be resolved
```

Next to it, a button: **"Resolve conflicts"**. Click it.

GitHub opens a simple web-based editor showing the conflicted file. It looks the same as what you'd see in your local editor:

```
<<<<<<< feature/navbar
<h1>Welcome to the best site ever</h1>
=======
<h1>Welcome, friends!</h1>
>>>>>>> main
```

**How to resolve:**

1. Edit the file in the web editor — delete markers, keep the version you want
2. Scroll down, click **"Mark as resolved"** (only clickable when all markers are gone)
3. If there are multiple conflicted files, repeat for each one
4. Click **"Commit merge"**

That's it. GitHub creates a merge commit, and the PR is no longer blocked.

**When to use the web editor:**

- Small, simple conflicts (1-2 lines)
- Quick typo-level fixes where you're confident about the right version
- When you're on a different machine and don't have the repo cloned

**When NOT to use it:**

- Complex conflicts involving logic — you can't run the code in the web editor, so you can't test your fix
- Multiple files with conflicts — it gets tedious fast
- Conflicts that require understanding the full code context

For anything non-trivial, resolve locally. Pull the branch, fix in your real editor, test the code, then push. The web editor is for the quick stuff.

**What the other person sees:**

When you resolve conflicts through GitHub's web editor, the PR updates automatically. The other dev doesn't need to do anything. They'll see the conflict banner disappear next time they refresh the page.

**A common trap:**

People use the web editor for a "quick fix," accidentally delete the wrong lines, commit, and break the build. Then they have to make another fix PR on top. If you're not 100% sure what the right resolution is, do it locally where you can test.
