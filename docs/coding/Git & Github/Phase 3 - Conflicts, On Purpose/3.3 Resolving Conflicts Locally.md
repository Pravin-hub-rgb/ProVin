You know what a conflict looks like. Now here's the exact workflow to resolve one from start to finish.

**Step 1: See the conflict message**

When you try to merge or pull and hit a conflict, Git tells you:

```
$ git merge origin/main
Auto-merging index.html
CONFLICT (content): Merge conflict in index.html
Automatic merge failed; fix conflicts and then commit the result.
```

Git pauses the merge. Your files are in a conflicted state. Nothing is broken. Nothing is lost.

**Step 2: See which files are conflicted**

```bash
$ git status
On branch feature/navbar
You have unmerged paths.
  (fix conflicts and run "git commit")
  (use "git merge --abort" to abort the merge)

Unmerged paths:
  both modified:   index.html
```

`both modified: index.html` means that file has conflicts. Note the other files that may have auto-merged successfully — those are fine.

**Step 3: Open the file and fix the conflicts**

Open `index.html` in your editor. You'll see conflict markers:

```
<<<<<<< HEAD
<h1>Welcome to the best site ever</h1>
=======
<h1>Welcome, friends!</h1>
>>>>>>> main
```

Edit the file to keep whichever version (or combination) you want. Delete the markers. Save.

**Step 4: Tell Git the conflict is resolved**

After saving the file:

```bash
git add index.html
```

This tells Git "the conflict in this file is resolved." Do this for every conflicted file.

**Step 5: Complete the merge**

```bash
git commit
```

Git opens your editor with a pre-filled merge commit message like:

```
Merge branch 'main' into feature/navbar

# Conflicts:
#	index.html
```

Save and close. The merge is complete.

```
$ git commit
[feature/navbar 9a8b7c6] Merge branch 'main' into feature/navbar
```

**What if things go wrong and you want to start over?**

```bash
git merge --abort
```

This undoes the entire merge. Your branch goes back to exactly how it was before you ran `git merge`. No traces. No damage.

**The full loop (memorize this):**

```
git merge origin/main          # try to merge
# CONFLICT in index.html       # Git tells you what's wrong
# fix the file manually        # edit, delete markers, save
git add index.html             # mark as resolved
git commit                     # complete the merge
```

That's it. 4-5 commands. The actual work is reading the file and deciding what to keep.

**What if there are multiple conflicted files?**

Fix them all, then `git add` each one. Or fix all of them and then `git add .` (safe here because you already know the merge is in progress and `.` will only add resolved files).

```bash
# fix file1, file2, file3
git add .
git commit
```

**One more thing — VS Code handles this visually.**

If you use VS Code, when you open a conflicted file, you'll see buttons above each conflict block:

- **Accept Current** — keep your version (HEAD)
- **Accept Incoming** — keep their version
- **Accept Both** — keep both, one after the other
- **Compare Changes** — see a diff view

Click the button, save, done. But knowing how to do it manually first is important — you won't always have VS Code.

**In Your Own Words:**

<details>
<summary>1. What should you run first when you see "Automatic merge failed"?</summary>

`git status` to see which files have conflicts.
</details>

<details>
<summary>2. After editing a conflicted file, what command tells Git the conflict is resolved?</summary>

`git add <filename>` marks the file as resolved and staged.
</details>

<details>
<summary>3. What command undoes a merge and puts everything back to normal?</summary>

`git merge --abort` — it cancels the merge entirely and restores your branch.
</details>

<details>
<summary>4. After fixing all conflicts and staging them, what command completes the merge?</summary>

`git commit` — it creates the merge commit to finish the merge.
</details>

<details>
<summary>5. In VS Code, what four options do you get for resolving a conflict?</summary>

Accept Current (yours), Accept Incoming (theirs), Accept Both (both versions), Compare Changes (diff view).
</details>
