Reading about conflicts is one thing. Fixing them yourself is different. These three drills will make you genuinely comfortable with conflicts. Do them on your practice repo with the dev-A/dev-B setup.

**Drill 1: Same-line text conflict**

This is the basic one. Two branches, same line, different text.

Setup:

```bash
# On dev-A
git switch main
git pull origin main
git switch -c drill-1-dev-a
# edit index.html line 10 to: <h1>Dev A's version</h1>
git add index.html
git commit -m "Dev A changes heading"
git push -u origin drill-1-dev-a

# On dev-B
git switch main
git pull origin main
git switch -c drill-1-dev-b
# edit index.html line 10 to: <h1>Dev B's version</h1>
git add index.html
git commit -m "Dev B changes heading"
git push -u origin drill-1-dev-b
```

Now on dev-B, try merging dev-A's branch:

```bash
git switch drill-1-dev-b
git merge origin/drill-1-dev-a
```

You'll get a conflict on line 10. Fix it three different ways in three separate runs:
1. Keep dev-A's version
2. Keep dev-B's version
3. Combine both into something new

Each time: edit, `git add`, `git commit`, done.

**Drill 2: One edits, one deletes**

This is a different flavor. Dev-A edits a line. Dev-B deletes the entire block containing that line.

Setup:

```bash
# On dev-A
git switch main
git pull origin main
git switch -c drill-2-dev-a
# edit index.html — change the heading to something new
git add index.html
git commit -m "Dev A updates heading"
git push -u origin drill-2-dev-a

# On dev-B
git switch main
git pull origin main
git switch -c drill-2-dev-b
# delete the entire heading section from index.html
git add index.html
git commit -m "Dev B removes heading section"
git push -u origin drill-2-dev-b
```

On dev-B, merge dev-A:

```bash
git switch drill-2-dev-b
git merge origin/drill-2-dev-a
```

The conflict message will say something like:

```
CONFLICT (modify/delete): index.html deleted in HEAD and modified in drill-2-dev-a.
```

This is a different choice. You need to decide: does the heading stay (keep dev-A's change) or go (keep dev-B's deletion)? Git won't guess. You decide by editing the file to one of the two states.

**Drill 3: Whitespace/formatting conflict**

This one is annoyingly common on real teams. One person reformats (changes indentation, adds spaces) while the other changes logic on the same lines.

Setup:

```bash
# On dev-A
git switch main
git pull origin main
git switch -c drill-3-dev-a
# Reformat index.html — change indentation from 2 spaces to 4 spaces everywhere
# (or use a formatter like Prettier)
git add index.html
git commit -m "Dev A reformats indentation"
git push -u origin drill-3-dev-a

# On dev-B
git switch main
git pull origin main
git switch -c drill-3-dev-b
# Change actual content on line 10 of index.html
git add index.html
git commit -m "Dev B changes heading text"
git push -u origin drill-3-dev-b
```

On dev-B, merge dev-A:

```bash
git switch drill-3-dev-b
git merge origin/drill-3-dev-a
```

Every line that dev-A reformatted and dev-B also touched will conflict. This is why teams agree on a formatter (Prettier, ESLint) and run it on every file before committing. Same formatting for everyone = this conflict type disappears.

**After each drill:**

Run `git tree` to see what happened:

```
*   9a8b7c6 (HEAD -> drill-3-dev-b) Merge branch 'drill-3-dev-a' into drill-3-dev-b
|\
| * 2b3c4d5 (origin/drill-3-dev-a) Dev A reformats indentation
* | 1a2b3c4 Dev B changes heading text
|/
* 4d3e2f1 Initial commit
```

The merge commit has two parents. That's the shape of a resolved conflict.

**Clean up between drills:**

```bash
git switch main
git branch -D drill-1-dev-a drill-1-dev-b drill-2-dev-a drill-2-dev-b drill-3-dev-a drill-3-dev-b
git push origin --delete drill-1-dev-a drill-1-dev-b drill-2-dev-a drill-2-dev-b drill-3-dev-a drill-3-dev-b
```

---

**In Your Own Words:**

<details>
<summary>1. What's the setup for a same-line text conflict?</summary>

Two branches both edit the exact same line of the same file to different values.
</details>

<details>
<summary>2. What message does Git show for a "one edits, one deletes" conflict?</summary>

`CONFLICT (modify/delete): file deleted in HEAD and modified in <branch>`.
</details>

<details>
<summary>3. Why do whitespace/formatting conflicts happen, and how do teams avoid them?</summary>

One person reformats while another edits the same lines. Teams avoid it by using a shared formatter (like Prettier) that everyone runs on every file.
</details>

<details>
<summary>4. What shape does a resolved conflict create in `git tree`?</summary>

A merge commit with two parents — one from each branch that was merged.
</details>
