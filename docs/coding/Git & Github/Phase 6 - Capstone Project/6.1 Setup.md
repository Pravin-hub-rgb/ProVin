This is it. Everything you've learned in Phases 1 through 5 comes together in one real project. By the end, you'll have a repo whose history proves you know team Git workflow — and you can show it to anyone.

**The project:**

A simple "link-in-bio" landing page — like Linktree but your own. Plain HTML/CSS/JS, no frameworks. The focus is on the Git workflow, not the coding.

**Pages/sections:**
- Hero with your name and tagline
- Links section (socials, projects)
- Footer
- Dark/light mode toggle (simple JS)

**Step 1: dev-A creates the repo**

On dev-A's GitHub account, create a new repo called `bio-link-capstone`. Add dev-B as a collaborator (same as 2.2).

```bash
# Clone on dev-A's machine
git clone https://github.com/dev-A/bio-link-capstone.git
cd bio-link-capstone
```

**Step 2: Turn ON branch protection BEFORE anything else**

Go to Settings → Branches → Add rule for `main`. Check:
- Require a pull request before merging
- Require approvals: 1

Without this, you'll be tempted to skip the process. With it, you literally cannot bypass the PR workflow.

**Step 3: Set up per-repo identities**

```bash
git config user.name "Dev A"
git config user.email "dev-a@example.com"
```

On dev-B's machine/folder:

```bash
git clone https://github.com/dev-A/bio-link-capstone.git
cd bio-link-capstone
git config user.name "Dev B"
git config user.email "dev-b@example.com"
```

**Step 4: First commit goes through a PR — no exceptions**

Yes, even the initial skeleton goes through review. This builds the habit.

On dev-A:

```bash
git switch -c repo-setup
```

Create the initial files:

```html
<!-- index.html -->
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>My Bio Link</title>
  <link rel="stylesheet" href="style.css" />
</head>
<body>
  <div id="app">
    <h1>Hello, I'm Dev A</h1>
    <p>Welcome to my little corner of the internet</p>
  </div>
  <script src="script.js"></script>
</body>
</html>
```

```css
/* style.css */
* { margin: 0; padding: 0; box-sizing: border-box; }
body { font-family: system-ui, sans-serif; padding: 2rem; max-width: 600px; margin: 0 auto; }
```

```js
// script.js
console.log("Bio link loaded");
```

Also create a `.gitignore` (from 5.4) and a `README.md`:

```markdown
# Bio Link Capstone

A personal link-in-bio landing page built to practice team Git workflow.

## Setup

Open `index.html` in a browser.
```

Commit, push, open a PR:

```bash
git add .
git commit -m "Add initial project skeleton"
git push -u origin repo-setup
```

Go to GitHub.com → open a PR titled "Initial project skeleton" → assign dev-B as reviewer. Switch to dev-B, approve, merge.

```bash
git switch main
git pull origin main
```

The foundation is set. Every future change goes through this same cycle.

**In Your Own Words:**

<details>
<summary>1. Why do you set up branch protection BEFORE the first commit?</summary>

To force the PR workflow from the very beginning. If you skip it for the first commit, you'll be tempted to skip it later.
</details>

<details>
<summary>2. Even the initial repo setup goes through a PR. Why?</summary>

To build the habit. If every change goes through a PR — no exceptions — it becomes automatic.
</details>

<details>
<summary>3. What files should the initial skeleton include?</summary>

index.html, style.css, script.js, .gitignore, and README.md.
</details>
