You committed something and immediately thought "wait, I messed up." Maybe the commit message is wrong. Maybe you included a file you shouldn't have. Maybe you want to undo the whole thing.

`git reset` is how you go back. It moves your current branch pointer backward to an earlier commit. The key question is: what happens to your changes when you do that?

There are three modes, and they control exactly that.

**`git reset --soft` — "Undo the commit, keep everything staged."**

Your branch pointer goes back one commit. Your changes are still there, still staged, ready to commit again.

```
$ git commit -m "Add contact form"
$ git reset --soft HEAD~1
$ git status
On branch main
Changes to be committed:
  new file:   contact.html
```

Use this when you want to redo the commit — fix the message, add more files, split into multiple commits. Nothing is lost.

**`git reset --mixed` (the default) — "Undo the commit, unstage but keep changes."**

Your branch pointer goes back. Your changes stay in your working directory but are no longer staged. This is the default if you just type `git reset` without a mode.

```
$ git commit -m "Add contact form"
$ git reset --mixed HEAD~1    # or just: git reset HEAD~1
$ git status
On branch main
Changes not staged for commit:
  modified:   contact.html
```

Use this when you want to uncommit but keep working on the changes before staging again.

**`git reset --hard` — "Undo the commit AND delete the changes."**

Your branch pointer goes back. Your changes are gone. Permanently (well, almost — we'll cover reflog in 4.3).

```
$ git commit -m "Add contact form"
$ git reset --hard HEAD~1
HEAD is now at a1b2c3d Initial commit
$ git status
On branch main
nothing to commit, working tree clean
```

The commit is gone. The changes are gone. This is the dangerous one. But it's also useful when you committed something you genuinely don't want and want it erased.

**The `HEAD~1` notation:**

`HEAD` is your current position. `HEAD~1` means "one commit before HEAD." `HEAD~3` means "three commits before HEAD." You can also use a specific commit hash instead.

```
git reset --soft HEAD~1       # undo last commit, keep staged
git reset --soft HEAD~3       # undo last 3 commits, keep staged
git reset --mixed a1b2c3d      # go back to that specific commit, keep changes unstaged
git reset --hard e5f6g7h       # go back to that specific commit, DELETE all later changes
```

**The most important rule about reset:**

Never use `git reset` (of any mode) on a commit that has already been pushed and other people might have pulled. You're rewriting history. Other people's repos will become confused and you'll cause problems.

If you need to undo something that's already been shared, use `git revert` (next lecture). Reset is for your local, unpushed work only.

**When to use each mode:**

- `--soft`: you committed too early, want to add more to the same commit or change the message
- `--mixed`: you committed but want to re-examine your changes before staging again
- `--hard`: you committed something you absolutely don't want and want it erased (local only!)

---

**In Your Own Words:**

<details>
<summary>1. What does `git reset` do at a high level?</summary>

It moves your current branch pointer backward to an earlier commit.
</details>

<details>
<summary>2. What's the difference between `--soft`, `--mixed`, and `--hard`?</summary>

`--soft` keeps changes staged, `--mixed` (default) keeps changes unstaged, `--hard` deletes changes entirely.
</details>

<details>
<summary>3. When is it safe to use `git reset --hard`?</summary>

Only on commits that haven't been pushed or shared with anyone else.
</details>

<details>
<summary>4. What should you use instead of reset when you need to undo something already pushed?</summary>

`git revert` — it creates a new commit that undoes the changes instead of rewriting history.
</details>
