Merges get undone too. Maybe you merged the wrong branch. Maybe the feature wasn't ready. Maybe the merge broke things and you need to roll back.

How you undo it depends on one question: has the merge been pushed yet?

**Scenario 1: Merge happened locally, not pushed yet.**

This is the easy case. The merge is just a commit on your local branch. Use reset:

```bash
git reset --hard HEAD~1
```

This moves your branch pointer back one commit — right before the merge. The merge commit and all its changes are gone. Your branch is back to where it was before you merged.

```bash
$ git log --oneline --graph
*   9a8b7c6 (HEAD -> main) Merge branch 'feature/navbar'  ← gone after reset
|\
| * 2b3c4d5 Add dropdown
* | f5e6d7c Fix login
|/
* 4d3e2f1 Initial commit

$ git reset --hard HEAD~1
HEAD is now at f5e6d7c Fix login

$ git log --oneline
f5e6d7c (HEAD -> main) Fix login
4d3e2f1 Initial commit
```

Merge undone. Clean.

**Scenario 2: Merge already pushed to shared main.**

Now it's not safe to reset because others may have pulled the merge commit. Use revert with the `-m 1` flag:

```bash
git revert -m 1 <merge-commit-hash>
```

The `-m 1` tells Git "revert this merge, keeping the changes from the first parent (main) and discarding the changes from the merged branch."

```bash
$ git revert -m 1 9a8b7c6
```

Git creates a new commit that undoes everything the merge brought in. The history shows:

```
* 7d8e9f0 (HEAD -> main) Revert "Merge branch 'feature/navbar'"
*   9a8b7c6 Merge branch 'feature/navbar'
|\
| * 2b3c4d5 Add dropdown
* | f5e6d7c Fix login
|/
* 4d3e2f1 Initial commit
```

The merge stays in history. The revert commit counteracts it. Everyone can pull safely.

**The problem with reverting a merge:**

If you later want to re-merge that same branch, Git won't let you because it considers those commits already in main (via the first merge). To re-merge after a revert, you'd need to revert the revert. Don't worry about this now — just know that reverting a merge makes future re-merges of that branch tricky.

**The GitHub way:**

On a merged PR's page, there's a "Revert" button. Clicking it creates a new PR that reverts the merge. Same as `git revert -m 1` but through the UI. This is the most common way teams undo a merge on shared main.

**The rule in one sentence:**

```
If it's local, reset it. If it's shared, revert it.
```

Same rule as everything else in this phase. Merge undo is no different.
