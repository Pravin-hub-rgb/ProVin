Before we can practice the full PR workflow, we need the right setup. You need two GitHub accounts and the ability to act as both of them. If you've already got this from Phase 1 exercises, you can skim this. If not, read on.

> **Don't want to create two GitHub accounts?** Use the **[Git Lab](/lab/github?scenario=two-collaborators)** simulator instead. It gives you a split-screen terminal where you play both Senior Dev (left) and Junior Dev (right) right in your browser — no accounts needed. Start with the "Two Collaborators Workflow" scenario.

**You need two GitHub accounts (or the Git Lab above).**

Call them `dev-A` and `dev-B`. They can be your real account and a throwaway. The point is to simulate two different developers working on the same repo.

- **dev-A** acts as the **Senior Dev** (repo owner) — creates the repo, pushes code, has merge permissions.
- **dev-B** acts as the **Junior Dev** (collaborator) — pulls changes, reviews PRs, learns the workflow.

In the lab simulator, the blue terminal is Senior Dev and the purple terminal is Junior Dev. You'll switch between them by logging in and out of GitHub in your browser.

**Step 1: Create a practice repo on dev-A**

Go to GitHub.com, logged in as dev-A. Click the "+" icon in the top right, then "New repository."

- Name it `team-practice`
- Make it public (or private, doesn't matter for practice)
- Check "Add a README file" so it starts with something
- Click "Create repository"

**Step 2: Add dev-B as a collaborator**

In your repo, go to Settings → Collaborators → Add people. Type dev-B's GitHub username and send the invite.

Now switch to dev-B's GitHub account. You'll see a notification. Accept the invitation.

That's it. Both accounts can now push to the same repo.

**Step 3: Clone on both machines**

If you have two machines, clone on both. If you only have one machine, clone into two separate folders — that works just as well.

```bash
# On machine/folder A, logged in as dev-A
git clone https://github.com/dev-A/team-practice.git
cd team-practice

# On machine/folder B, logged in as dev-B
git clone https://github.com/dev-B/team-practice.git
# Notice: same repo, but since dev-B is a collaborator, they can push too
```

**Step 4: Set your Git identity per repo**

This is important. You need your commits to show different authors depending on which "person" you're playing. Don't use `--global` here. Set the identity per repo:

```bash
# In dev-A's folder
git config user.name "Dev A"
git config user.email "dev-a@example.com"

# In dev-B's folder
git config user.name "Dev B"
git config user.email "dev-b@example.com"
```

Now when you check:

```bash
$ git config user.name
Dev A
```

And when you make a commit, the author will be "Dev A" or "Dev B" depending on which folder you're in.

**Step 5: Verify you can push from both**

On dev-A's side (Senior Dev):

```
$ echo "hello from Senior Dev" > hello.txt
$ git add hello.txt
$ git commit -m "Add hello from Senior Dev"
$ git push origin main
```

Now on dev-B's side (Junior Dev), pull and confirm:

```bash
git pull origin main
```

You should see dev-A's commit appear.

**Why not use `--global`?**

If you set `user.name` and `user.email` globally, every commit from your machine would show the same author. By setting them per repo, your practice repo shows "Dev A" and "Dev B" commits while your real projects still show your real name. Clean separation.

**In Your Own Words:**

<details>
<summary>1. Why do you need two GitHub accounts for this course?</summary>

To simulate two developers. You practice the full workflow — one person creates the PR, the other reviews it — instead of reviewing your own work.
</details>

<details>
<summary>2. How do you add a collaborator to a GitHub repo?</summary>

Repo Settings → Collaborators → Add people → type their username → send invite. They accept on their end.
</details>

<details>
<summary>3. Why should you set `git config` without `--global` in your practice repo?</summary>

So commits show the correct simulated author (Dev A vs Dev B) without overriding your global Git identity for real projects.
</details>

<details>
<summary>4. Can two different folders on the same machine both push to the same repo?</summary>

Yes. Each folder has its own Git config and credentials. They act like separate machines.
</details>
