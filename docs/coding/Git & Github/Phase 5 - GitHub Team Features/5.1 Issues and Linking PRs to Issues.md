You know the PR workflow. You know how to resolve conflicts. You know how to undo mistakes. Now we add the layer that real teams use on top of Git: GitHub's project management features.

The first one is Issues.

**What is a GitHub Issue?**

An Issue is a tracked task, bug report, feature request, or question. It's a ticket. Think of it as a post-it note that lives in your repo forever. Anyone on the team can create one.

Issues have:
- A title and description
- Labels (like "bug", "enhancement", "good first issue")
- Assignees (who's working on it)
- Comments (discussion happens here)
- A number (#1, #2, #3... auto-incremented)

**Why Issues matter on a team:**

Without Issues, work happens in people's heads. "Didn't Alice say she was going to add the footer?" "Bob mentioned a bug in the login... or was that Charlie?" Issues make everything visible. Every task has a home.

**Linking PRs to Issues:**

Here's the powerful part. In your PR description, you can write:

```
Closes #12
```

When that PR merges, GitHub automatically closes Issue #12. The issue and PR get linked. Months later, you can look at Issue #12 and see "oh, here's the PR that fixed it, and here's the discussion about the fix."

Other keywords that work:
- `Closes #12` (closes when PR merges)
- `Fixes #12` (same as closes)
- `Resolves #12` (same as closes)
- `Addresses #12` (links without closing)

**Hands-on practice:**

1. Go to your practice repo on GitHub
2. Click the "Issues" tab → "New Issue"
3. Write a title like "Add footer section" and a short description
4. Click "Submit new issue"

You'll see it gets number #1.

Now create a branch, make a simple change, and open a PR. In the PR description, write:

```
Adds a footer with social links.

Closes #1
```

Merge the PR. Go back to Issues. Issue #1 is now closed, with a link to the PR that closed it.

**Labels:**

Labels help organize issues. GitHub gives you default ones like "bug", "enhancement", "question". You can also create custom ones. On a real team, you might have labels like `frontend`, `backend`, `urgent`, `needs-discussion`.

To add a label to an issue: open the issue → click the gear icon next to "Labels" → select labels.

**Assignees:**

Assigning an issue to someone tells the team "this person is working on this." It prevents two people from accidentally doing the same work.
