# 5.1 Syntax — Pause Resume Implementation

> **Let's implement pause/resume in real TypeScript code.**

## Adding Pause/Resume to Feed

```typescript
// 5.1-pause-resume.ts
// (Continued from 3.3 — SimulatedFeed class)

pause(): void {
  if (this.ticker) {
    clearInterval(this.ticker)
    this.ticker = null
    this.emit("pause")
    console.log("[feed] paused (simulating disconnect)")
  }
}

resume(): void {
  if (!this.ticker) {
    this.start()  // restart the interval
    this.emit("resume")
    console.log("[feed] resumed (simulating reconnect)")
  }
}

// The KEY difference from just stop+start:
// - prices Map persists (same class instance)
// - tickCount persists
// - All PositionMachine states persist
```

## Line-by-Line: Why This Works

### `if (this.ticker)` guard
- **What:** Only pause if currently running
- **Why:** Calling `pause()` twice would error on second `clearInterval(null)`

### `this.ticker = null`
- **What:** Flags feed as "not running"
- **Why:** `resume()` checks `!this.ticker` — if null, it's safe to start

### `this.start()` in resume
- **What:** Restarts the interval
- **Why:** Same prices Map — prices **continue** from where they paused

### `this.emit("pause")` / `this.emit("resume")`
- **What:** Notifies subscribers
- **Why:** Machines can log "feed disconnected" → "feed reconnected"

## Full Test with Pause/Resume

```typescript
const feed = new SimulatedFeed(["AAPL", "MSFT"])
const managers = new Map([
  ["AAPL", new PositionMachine("AAPL")],
  ["MSFT", new PositionMachine("MSFT")],
])

// Subscribe machines to feed
feed.on("tick", (tick) => {
  managers.get(tick.symbol)?.onTick(tick.close)
})

feed.on("signal", (signal) => {
  managers.get(signal.symbol)?.onSignal(signal.direction as "long" | "short")
})

feed.on("pause", () => {
  console.log("All machines: feed disconnected, holding state")
})

feed.on("resume", () => {
  console.log("All machines: feed reconnected, receiving ticks again")
})

// Start
for (const mgr of managers.values()) mgr.watch()
feed.start()

// Pause after 3s
setTimeout(() => {
  console.log("\n--- PAUSING (disconnect) ---")
  managers.get("AAPL")?.onSignal("long")  // enter position before disconnect
  feed.pause()
}, 3000)

// Resume after 3s (total 6s)
setTimeout(() => {
  console.log("\n--- RESUMING (reconnect) ---")
  feed.resume()
}, 6000)

// End after 10s
setTimeout(() => {
  console.log("\n=== FINAL STATES ===")
  for (const [symbol, mgr] of managers) {
    console.log(`${symbol}: ${mgr.getStatus()}`)
  }
  process.exit(0)
}, 10000)
```

## Common Mistake

```typescript
// ❌ Re-creating feed on resume — state lost
resume() {
  this.feed = new SimulatedFeed(this.symbols)  // prices reset!
  this.feed.start()
}

// ✅ Same instance — state preserved
resume() {
  this.start()  // restarts interval only, same prices Map
}
```

## What It Is NOT

- **NOT network handling.** No actual WebSocket errors to catch
- **NOT reconnect backoff.** Real code waits longer between retries — here we resume immediately

## Bridge

`streamer.ts` `reconnect()`:
```
this.ws?.close()
this.ws = new WebSocket(url)
this.ws.onopen = this.onOpen.bind(this)
// machines still have their position managers — state never reset
```

Your `feed.resume()` = their `this.ws = new WebSocket(...)`.
