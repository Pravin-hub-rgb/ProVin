## What Is the Event Loop (in one sentence)

JavaScript has **one thread**. The event loop is the mechanism that lets timers, network callbacks, and user events all share that single thread without blocking each other.

Think of it like a restaurant with one waiter serving N tables:
- The waiter takes an order (timer fires), writes it down, moves on
- When food is ready (callback), waiter serves it
- The waiter never stands idle — if 5 tables' timers fire at once, they queue up and get handled one by one

## Timers in Node.js — `setInterval` and `clearInterval`

```typescript
// setInterval runs a function REPEATEDLY at X ms intervals
const intervalId = setInterval(() => {
  console.log("tick:", Date.now())
}, 500) // 500ms = 0.5 seconds = 2x per second
```

```typescript
// clearInterval stops it — cleanup, just like useEffect in React 2.1
clearInterval(intervalId)
console.log("timer stopped")
```

## Building a Simulated Feed

Here's a feed that pushes fake OHLC data for 3 symbols:

```typescript
interface OHLC {
  symbol: string
  open: number
  high: number
  low: number
  close: number
  timestamp: number
}

// Fake price generator — random walk
const prices: Record<string, number> = {
  "AAPL": 150,
  "MSFT": 350,
  "GOOGL": 140,
}

function makeTick(symbol: string): OHLC {
  const currentPrice = prices[symbol]
  const change = (Math.random() - 0.5) * 2  // ±$1 random walk
  const newPrice = Math.max(1, currentPrice + change)
  prices[symbol] = newPrice

  return {
    symbol,
    open: currentPrice,
    high: Math.max(currentPrice, newPrice),
    low: Math.min(currentPrice, newPrice),
    close: newPrice,
    timestamp: Date.now(),
  }
}

// Push ticks every 500ms
const INTERVAL_MS = 500

const feed = setInterval(() => {
  for (const symbol of ["AAPL", "MSFT", "GOOGL"]) {
    const tick = makeTick(symbol)
    console.log(`${tick.symbol}: $${tick.close.toFixed(2)} (at ${new Date(tick.timestamp).toLocaleTimeString()})`)
  }
}, INTERVAL_MS)

// Pause/resume simulation — like disconnect/reconnect
function pauseFeed() {
  clearInterval(feed)
  console.log("FEED PAUSED (simulating disconnect)")
}

function resumeFeed() {
  // Re-create the interval
  setInterval(() => {
    for (const symbol of ["AAPL", "MSFT", "GOOGL"]) {
      const tick = makeTick(symbol)
      console.log(`${tick.symbol}: $${tick.close.toFixed(2)}`)
    }
  }, INTERVAL_MS)
  console.log("FEED RESUMED (simulating reconnect)")
}

// Test: pause after 3 seconds, resume after 2 more
setTimeout(pauseFeed, 3000)
setTimeout(resumeFeed, 5000)
```

Run it:
```bash
npx tsx 2.0.ts
```

You'll see:
```
AAPL: $150.43 (at 10:30:01)
MSFT: $349.12 (at 10:30:01)
GOOGL: $140.87 (at 10:30:01)
... (repeats twice)
FEED PAUSED (simulating disconnect)
... silence for 2 seconds ...
FEED RESUMED (simulating reconnect)
AAPL: $149.88 (at 10:30:05)
...
```

## The Key Sentence You Need to Explain

> "One process, N subscriptions, callbacks per tick — the event loop is doing the concurrency."

What this means:
- **ONE process** (one Node.js thread, not multiple processes)
- **N subscriptions** (3 symbols = 3 data streams)
- **Callbacks per tick** (each timer fire = a callback handling all 3 symbols)
- **The event loop does the concurrency** — no threads, no async/await needed

## What It Is NOT

- **NOT real networking.** No WebSocket, no Upstox, no protobuf. Just a timer calling a function. The point is the *pattern* — one loop, N data streams — not the transport.
- **NOT a performance concern.** Your `setInterval` at 500ms won't scale to 10,000 symbols. Real `streamer.ts` uses protobuf + reconnect-with-backoff because it has to. This lab is about recognizing the shape.
