# 1.0 Concept — Timers and setInterval

> **First, you need to understand — `setInterval` is very different from `setTimeout`.** Let's see what happens when you run a timer...

## Problem Statement

You need a fake price tick every 500ms. Remember `useEffect + setInterval` in React? Same concept here — but no React, just Node.js/TS directly.

## What happens if you do it directly?

```typescript
const intervalId = setInterval(() => {
  console.log("tick")
}, 500)
```

**Notice?** This runs. But what happens when the component unmounts — or, in this case, when the script ends?

```typescript
setInterval(() => {
  console.log("tick")
}, 500)
// no reference, no cleanup — timer keeps running
```

**Problem:** You didn't store `intervalId` → **cleanup is impossible**. The timer keeps running in the background. It gets stuck in memory. I made this mistake myself — in one demo, 2 timers ran at once, and the counter started increasing at double speed.

## What Is setInterval

A JavaScript function that **repeatedly** runs a callback at a fixed interval. The single-threaded event loop handles it — the second tick won't run until the first tick completes.

## What It Is NOT

- **NOT a thread.** One timer = one callback in the event queue, not parallel execution
- **NOT fire-and-forget.** Every timer returns an ID — use it for `clearInterval`

## Key Rule

> **One variable per interval.** Otherwise you'll never know when to stop.

```typescript
// ❌ Bad — no reference
setInterval(() => {}, 500)

// ✅ Good — store the reference
const id = setInterval(() => {}, 500)
clearInterval(id)  // cleanup possible
```

## A senior dev's tip

> "I used to think — `clearInterval` is only for advanced use. No — you'll use it for life. Note down a `clearInterval` with every `setInterval`, or debugging will drive you crazy."

## Bridge

Real `streamer.ts` uses `setInterval` inside WebSocket reconnect logic — same cleanup pattern, just wrapped in connection state.
