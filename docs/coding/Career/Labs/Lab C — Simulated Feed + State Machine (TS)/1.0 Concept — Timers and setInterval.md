# 1.0 Concept — Timers and setInterval

> **Yaar, pehle samajhna padega — setInterval ek dam alag hota hai setTimeout se.** 
> Timer chala ke dekho kya hota hai...

## Problem Statement

Tumhe har 500ms ek fake price tick chahiye. React ke andar toh `useEffect + setInterval` tha yaad? Wahi same concept — par yahan React nahi, seedha Node.js/TS.

## Kya hota hai agar directly karo?

```typescript
const intervalId = setInterval(() => {
  console.log("tick")
}, 500)
```

**Notice kiya?** Yeh chalta hai. Lekin kya hoga jab component unmount ho jaye ya... is case mein script khatam ho jaye?

```typescript
setInterval(() => {
  console.log("tick")
}, 500)
// koi reference nahi, koi cleanup nahi — timer zindabad
```

**Problem:** `intervalId` nahi store kiya → **cleanup impossible**. Timer background mein chalti rahi. Memory mein phas jaati hai. Mainne bhi yahi galti ki thi — ek demo mein 2 timers ek saath chalne laga, counter double speed se badh raha tha.

## What Is setInterval

JavaScript ka ek function jo **repeatedly** ek callback ko fixed interval pe chaltā hai. Single-threaded event loop handle karta hai — tab tak pehla tick complete nahi hota, dusra nahi chalta.

## What It Is NOT

- **NOT a thread.** Ek timer = ek callback in the event queue, not parallel execution
- **NOT fire-and-forget.** Har timer ek ID return karta hai — use `clearInterval` ke liye

## Key Rule

> **Har interval ke liye ek variable.** Agar nahi toh tumhein pata nahi chalega kab stop karein.

```typescript
// ❌ Bad — no reference
setInterval(() => {}, 500)

// ✅ Good — store the reference
const id = setInterval(() => {}, 500)
clearInterval(id)  // cleanup possible
```

## Dost ka tip

> "Maine pehle socha — `clearInterval` sirf advanced feature hai. Beta, yeh zindagi bhar use hoga. Har `setInterval` ke saath `clearInterval` note karo, warna debugging mein paagal aa jayega."

## Bridge

Real `streamer.ts` uses `setInterval` inside WebSocket reconnect logic — same cleanup pattern, just wrapped in connection state.
