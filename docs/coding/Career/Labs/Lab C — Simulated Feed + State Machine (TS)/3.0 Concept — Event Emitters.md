# 3.0 Concept — Event Emitters and Pub/Sub

> **A big idea to grasp now. If the feed calls the machine directly, you get coupling.** Understand the EventEmitter concept — "I did something" is the broadcast, "I'm listening" is the subscription.

## What Is EventEmitter

A pattern where:
1. **Emitter** — when something happens, it emits (broadcasts "tick arrived")
2. **Listeners** — anyone can listen as much as they want
3. **No direct reference** — the emitter doesn't know about the listener

## Real Example — Feed Broadcasting to N Machines

```
Feed starts → every 500ms → emits "tick" for AAPL
  → PositionManager_AAPL.onTick receives it
  → PositionManager_MSFT.onTick receives it (if subscribed)
  → PositionManager_GOOG.onTick receives it (if subscribed)
```

## Code Pattern

```typescript
import { EventEmitter } from "events"

const feed = new EventEmitter()

// Multiple listeners on same event
feed.on("tick", (data) => {
  console.log("Machine 1 got tick:", data.symbol)
})

feed.on("tick", (data) => {
  console.log("Machine 2 got tick:", data.symbol)
})

// Emitter doesn't know who's listening
feed.emit("tick", { symbol: "AAPL", price: 150 })
// Output:
// Machine 1 got tick: AAPL
// Machine 2 got tick: AAPL
```

## Why Not Direct Calls?

```typescript
// ❌ Tight coupling — feed knows about machines
class Feed {
  machines: PositionManager[]
  start() {
    setInterval(() => {
      for (const machine of this.machines) {
        machine.onTick(price)  // feed must know machines exist
      }
    }, 500)
  }
}

// ✅ Loose coupling — feed just emits, listeners decide
class Feed {
  start() {
    setInterval(() => {
      const tick = makeTick()
      this.emit("tick", tick)  // who listens? Not feed's problem
    }, 500)
  }
}
```

## What It Is NOT

- **NOT a state store.** EventEmitter events are fire-and-forget — no replay, no history
- **NOT async/await.** Emitters are synchronous by default unless you make async listeners
- **NOT a framework.** Node built-in `events` module — no dependencies

## Why This Matters for TradeStack

`streamer.ts` is an EventEmitter subclass. It emits:
- `"tick"` → real-time price updates
- `"connected"` → WebSocket opened
- `"disconnected"` → need to reconnect
- `"signal"` → trading signal detected

Each consumer subscribes to what it needs — position manager needs ticks, logger needs signals, reconnect logic needs disconnect events.
