# 2.0 Concept — State Machines

> **Socho: agar ek trade ka state kabhi bhi track nahi karte, toh kya hoga?** 
> Do entries ho sakte hain, ya ek hi position mein 2 baar entry. Chaos.

## What Is a State Machine (Plain English)

Ek aisa system jahan:
1. **Object exactly one state** mein hota hai koi bhi samay
2. **Transitions** defined hote hain (State A → State B)
3. **Invalid transitions** rejected hote hain (table mein nahi hai toh nahi jaane do)

## Real Example — Position States

Trading mein ek stock ka position kabhi ek state mein hota hai:

```
IDLE — not watching this symbol
  ↓ watch
WATCHING — watching for entry signal
  ↓ signal triggers
IN_POSITION — entered the trade
  ↓ exit signal
EXITED — closed the trade
  ↓ reset
IDLE
```

Har state ek **exclusive** mode. WATCHING AND IN_POSITION nahi ho sakta ek sath.

## Code Representation

React ke `useReducer` se sikhaya tha — yahi pattern hai:

```typescript
// React Batch 5.5 concept
type Status = "idle" | "watching" | "in_position" | "exited"
```

## What It Is NOT

- **NOT a database state.** Yeh sirf memory mein track karta hai — restart = reset
- **NOT a persistence layer.** Koi save nahi hota — agar process band ho toh sab IDLE se start hota hai
- **NOT complex business logic.** Yeh bas "allowed moves" define karta hai — kya koi bhi transition legal hai ya nahi

## Key Rule

> **Har transition table has source + destination.** "watching → in_position" allowed, "idle → exited" not allowed.
