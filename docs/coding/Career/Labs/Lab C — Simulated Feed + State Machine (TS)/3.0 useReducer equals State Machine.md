# 3.0 useReducer = State Machine

> **Open with:** React's `useReducer` (Batch 5.5) is actually a state machine. You already learned: "saare possible actions ek jagah defined, har action ek pure function." That exact pattern → real state machine.
>
> **Connect to previous:** In `2.0`, you built a feed that ticks. Now you'll add a **position tracker** — each symbol transitions through trading states.

## State Machine (in plain English)

A state machine is an object that can be in **exactly one of several named states** at any time, and only certain transitions are allowed.

For Trading:
```
IDLE → WATCHING → IN_POSITION → EXITED
```

You can't "exit" if you were never "in position." You can't go "watching" if you're already "watching."

## React's useReducer (Recap from Batch 5.5)

```typescript
// From React 5.5: reducer with discriminated union actions
function reducer(state: State, action: Action): State {
  switch (action.type) {
    case 'start': return { ...state, status: 'watching' }
    case 'enter': return { ...state, status: 'in_position' }
    case 'exit':  return { ...state, status: 'exited' }
    default:      return state
  }
}
```

## Porting to Plain TypeScript (No React)

The **exact same pattern** — but in a plain class/object:

```typescript
type Status = "idle" | "watching" | "in_position" | "exited"

interface Position {
  symbol: string
  status: Status
}

const VALID_TRANSITIONS: Record<Status, Status[]> = {
  idle: ["watching"],
  watching: ["in_position", "idle"],
  in_position: ["exited", "idle"],
  exited: ["idle"],
}

function createPosition(symbol: string): Position {
  return { symbol, status: "idle" }
}

function tryTransition(pos: Position, action: string): Position {
  const allowed = VALID_TRANSITIONS[pos.status]

  // Map action names to target states
  const actionToStatus: Record<string, Status> = {
    watch: "watching",
    enter: "in_position",
    exit: "exited",
    reset: "idle",
  }

  const target = actionToStatus[action]
  if (!target) {
    console.log(`INVALID ACTION: ${action}`)
    return pos
  }

  if (allowed.includes(target)) {
    console.log(`${pos.symbol}: ${pos.status} → ${target}`)
    return { ...pos, status: target }
  }

  console.log(`INVALID TRANSITION: ${pos.symbol} cannot go ${pos.status} → ${target}`)
  return pos
}

// Test it
let position = createPosition("AAPL")

position = tryTransition(position, "watch")    // ✅ idle → watching
position = tryTransition(position, "enter")     // ✅ watching → in_position
position = tryTransition(position, "exit")     // ✅ in_position → exited
position = tryTransition(position, "enter")     // ❌ INVALID TRANSITION: exited cannot go → in_position
position = tryTransition(position, "reset")    // ✅ exited → idle

// Output:
// AAPL: idle → watching
// AAPL: watching → in_position
// AAPL: in_position → exited
// INVALID TRANSITION: AAPL cannot go exited → in_position
// AAPL: exited → idle
```

Run it:
```bash
npx tsx 3.0.ts
```

## The Other Key Sentence

> "The state machine guarantees a stock is in exactly one phase, so double entries can't happen."

What this means:
- **Exactly one phase** — no "is it watching OR in position?" ambiguity
- **Double entries can't happen** — because `enter` from `watching` is the only valid path, and after entering, the state changes, blocking a second `enter`

## What It Is NOT

- **NOT a database.** This machine doesn't persist — restart the script, state resets to `idle`. Real TradeStack persists position state.
- **NOT error handling.** The machine just rejects invalid transitions — it doesn't decide what *should* happen. Real `continuation/state-machine.ts` has 11 states because it handles partial fills, stop-losses, and order types. You're learning the skeleton.

## Bridge — TradeStack's Real State Machines

TradeStack has **two 11-state machines** (not 4 states):
- `continuation/state-machine.ts` — entry → breakout detection → entry → trailing stop → exit
- `reversal/state-machine.ts` — mirror pattern, opposite signals

But the **concept is identical** to your 4-state machine: a transition table, allowed moves only, invalid calls rejected. When you read those 11-state files in M6, the structure will look familiar — just more rows in the same table.
