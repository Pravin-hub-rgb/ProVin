# 5.0 Build machine.ts

> **Open with:** In `3.0`, you built a single position state machine. Now you'll wrap it in a class — one per symbol — that subscribes to the feed and tracks position state.
>
> **Connect to previous:** `4.0` emitted ticks. `3.0` showed the state transition logic. Now you combine them: each machine listens to the feed, updates on ticks, and validates transitions on signals.

## What You Build

A `PositionManager` class that:
1. Holds a 4-state position: `idle → watching → in_position → exited`
2. Subscribes to the feed's tick/signal events
3. Validates transitions (rejects invalid ones)
4. Prints a readable state timeline

```typescript
import { OHLC, FeedEvent, SimulatedFeed } from "./4.0"

export type Status = "idle" | "watching" | "in_position" | "exited"

export class PositionManager {
  private status: Status = "idle"
  private entryPrice: number | null = null

  // Allowed next states from each current state
  private static ALLOWED: Record<Status, Status[]> = {
    idle: ["watching"],
    watching: ["in_position", "idle"],
    in_position: ["exited", "idle"],
    exited: ["idle"],
  }

  constructor(public symbol: string) {}

  getStatus(): Status {
    return this.status
  }

  private tryTransition(action: string): boolean {
    const targetMap: Record<string, Status> = {
      watch: "watching",
      enter: "in_position",
      exit: "exited",
      reset: "idle",
    }

    const target = targetMap[action]
    if (!target) {
      console.log(`  ❌ INVALID ACTION: ${this.symbol} cannot "${action}"`)
      return false
    }

    if (PositionManager.ALLOWED[this.status].includes(target)) {
      // Log the transition
      console.log(`  ${this.symbol}: ${this.status} → ${target}`)
      this.status = target

      if (target === "in_position") this.entryPrice = undefined // set on signal
      if (target === "idle") this.entryPrice = null
      return true
    }

    console.log(`  ❌ INVALID TRANSITION: ${this.symbol} cannot go ${this.status} → ${target}`)
    return false
  }

  // Called by feed on each tick
  onTick(event: { type: "tick"; data: OHLC }): void {
    // In real TradeStack: this is where price tracking, trailing stops, etc. live
    // Here: just log we received the tick
    console.log(`[${this.symbol}] tick: $${event.data.close.toFixed(2)} (state: ${this.status})`)
  }

  // Called by feed on signal events
  onSignal(event: { type: "signal"; symbol: string; direction: "long" | "short" }): void {
    if (event.symbol !== this.symbol) return

    console.log(`[${this.symbol}] SIGNAL: ${event.direction}`)

    // State machine logic for handling a signal
    if (this.status === "watching") {
      this.tryTransition("enter")  // watching → in_position
    } else if (this.status === "in_position") {
      this.tryTransition("exit")   // in_position → exited
    }
    // If idle/exited and we get a signal — ignore
  }

  // Manual transition for testing invalid paths
  watch(): void { this.tryTransition("watch") }
  reset(): void { this.tryTransition("reset") }
}
```

## Testing — Include Invalid Transitions

```typescript
// Quick test — you'll wire this to the feed in 6.0
const manager = new PositionManager("AAPL")

manager.watch()     // ✅ idle → watching
manager.watch()     // ❌ INVALID TRANSITION: cannot go watching → watching (wait, this IS valid per ALLOWED)
// Actually: watching CAN'T go to watching — ALLOWED["watching"] = ["in_position", "idle"]
// So this logs: ❌ INVALID TRANSITION

manager.reset()     // ❌ watching → idle is VALID via "reset"
```

Wait — let's check the allowed transitions:
```
watching: ["in_position", "idle"]
```

So `reset` (→ idle) is valid from watching. But calling `watch` again when already watching — `watch` maps to `watching`, and `watching` is NOT in `["in_position", "idle"]`, so it rejects. ✅ That's the state machine doing its job.

## What It Is NOT

- **NOT a real trading bot.** No order execution, no risk management, no P&L calc. Just state tracking.
- **NOT the full TradeStack machine.** Real `continuation/state-machine.ts` has 11 states: `unwatched → watching → confirming → entered → ...`. You're building the skeleton.
