The last file handled data in memory with LINQ. But what about work like database queries or API calls? They take time — 2 seconds. If that sits on one thread, the whole program stops. In JS you solved this problem with `await fetch(...)` — **promises**. C# has the same concept, name is **Task** — and the syntax `async/await` is almost identical.

# Async / Await (Task)

## Problem — blocking code

```csharp
Console.WriteLine("Pehle...");
System.Threading.Thread.Sleep(3000);   // wait 3 sec (JS: sleep — you never wanted this)
Console.WriteLine("Baad mein");        // runs after 3 sec
```

The program sits **blocked** for 3 seconds. On a server that means — stop everything for all other users too. That's the disaster.

## C#'s solution — Task + await

```csharp
async Task DoSomethingAsync()
{
    Console.WriteLine("Shuru");

    await Task.Delay(3000);          // 3 sec — BUT the program doesn't block!

    Console.WriteLine("3 sec baad");
}
```

Line by line:

- **`Task`** — an object saying "I'm working, not done yet" (JS's **Promise**). `Task<int>` = an `int` will come later.
- **`async`** — before the method name: "this method uses `await`".
- **`await Task.Delay(3000)`** — "pause here, but let other work continue". Until the delay ends, this method hands control back — and other requests get served in that time.

JS comparison, exactly:

```javascript
// JS
async function doSomething() {
  console.log("Shuru");
  await new Promise(r => setTimeout(r, 3000));
  console.log("3 sec baad");
}
```

```csharp
// C#
async Task DoSomethingAsync()
{
    Console.WriteLine("Shuru");
    await Task.Delay(3000);
    Console.WriteLine("3 sec baad");
}
```

**Syntax is almost copy-paste.** Difference: JS had Promise, here it's `Task`. In JS every async function implicitly returned a Promise; here you must write the return type:

| JS | C# |
|---|---|
| `Promise<T>` | `Task<T>` |
| `Promise<void>` | `Task` |
| `async function f()` | `async Task FAsync()` |
| `await fetch()` | `await HttpClient.GetAsync()` |
| `setTimeout` | `Task.Delay` |

## A real example — reading a file

```csharp
async Task<string> ReadFileAsync(string path)
{
    Console.WriteLine("Padhna shuru...");
    string content = await File.ReadAllTextAsync(path);   // disk I/O — await!
    Console.WriteLine("Padh gaya, " + content.Length + " chars");
    return content;
}
```

`File.ReadAllTextAsync` — .NET's async version. **Pattern:** in .NET, almost every blocking method has a `...Async` version — `ReadAllText` vs `ReadAllTextAsync`, `GetAsync`, `SaveChangesAsync`. This is everyday work.

## Return type rule

```csharp
async Task KuchKaam()          // nothing needed back (not void — void async doesn't work)
{
    await Task.Delay(100);
}

async Task<int> CountAsync()   // an int comes back
{
    await Task.Delay(100);
    return 42;
}

// Call:
int result = await CountAsync();
```

**Rule:** an `async` method's return type must be `Task` or `Task<T>` (bare `void async` is invalid). When calling, add `await` to get the inner value.

## Without await — what happens (common mistake)

```csharp
async Task<int> CountAsync() { await Task.Delay(100); return 42; }

int x = CountAsync();      // ❌ no — you get Task<int>, not int
int y = await CountAsync(); // ✅ 42
```

Without `await` you have a **Task** (wrapped gift), not the value. Assigning `Task<int>` to `int` gives a compile error — the C# compiler catches you here.

Another mistake — `async void`:

```csharp
async void Bad() { ... }    // ❌ never do this (except event handlers)
```

`async void` has no return to track — errors don't surface, testing is hard. Always keep `Task`.

## Parallel work — two tasks at once

```csharp
async Task Demo()
{
    Task a = Task.Delay(2000);        // 2 sec work started — DID NOT BLOCK
    Task b = Task.Delay(2000);        // second one also started together

    await Task.WhenAll(a, b);         // wait for both to finish
    Console.WriteLine("Dono ho gaye — total ~2 sec, not 4!");
}
```

`Task.WhenAll` = JS's `Promise.all`. Run two API calls together — time doesn't add up. Write `await` one after another and it's sequential (JS was the same).

## When async is needed — and when not

**Needed:** database query, file read/write, HTTP/API call, sending email — disk/network work.

**Not needed:** `Console.WriteLine`, in-memory math (`nums.Sum()`), in-memory LINQ — these happen instantly; making them async adds pointless overhead.

> **Library rule:** for methods built for others, add an `Async` suffix (`GetUserAsync()`) — callers know an await is needed.

## What It Is NOT

- **`async` doesn't make code fast** — its job is to **work without blocking**. Total time stays the same, but the thread stays free (a server can take many requests at once).
- **`await` ≠ thread block** — in JS there was only one thread, but in C# the point of `await` is that the thread goes to other work, doesn't block.
- **Task ≠ thread** — Task is a handle for "work is running"; a thread pool is used inside. One thread can run a thousand Tasks.

## A complete program — running async

```csharp
// Program.cs
using System;
using System.Threading.Tasks;

class Program
{
    static async Task Main(string[] args)     // Main can be async too!
    {
        Console.WriteLine("Chai banao...");

        Task chai = MakeChaiAsync();           // start — parallel
        Task toast = MakeToastAsync();         // start — parallel

        await Task.WhenAll(chai, toast);       // wait for both
        Console.WriteLine("Nashta ready!");

        string data = await FetchDataAsync();
        Console.WriteLine("Data: " + data);
    }

    static async Task MakeChaiAsync()
    {
        await Task.Delay(2000);                // 2 sec — but thread free
        Console.WriteLine("Chai ready");
    }

    static async Task MakeToastAsync()
    {
        await Task.Delay(1500);
        Console.WriteLine("Toast ready");
    }

    static async Task<string> FetchDataAsync()
    {
        await Task.Delay(1000);
        return "user_42";                      // real code would make an HTTP call
    }
}
```

Output in ~2 seconds (3 tasks parallel). `static async Task Main` — Main can be async too; this is the standard start of .NET apps.

## In Your Own Words

1. What's C#'s equivalent of JS's `Task` — how does `async/await` look in both?

<details>
<summary>Sample Answer</summary>

**Answer:** `Task` = JS's Promise ("work running, result later"). Syntax is the same: `async function` → `async Task`, `await promise` → `await task`, `Promise<T>` → `Task<T>`, `Promise.all` → `Task.WhenAll`.

</details>

2. Why is calling `async Task<int> CountAsync()` with `int x = CountAsync()` wrong?

<details>
<summary>Sample Answer</summary>

**Answer:** Without `await`, the method returns a `Task<int>` (result wrapped), not an int. `int x = ...` is a type mismatch — compile error. Correct: `int x = await CountAsync();` — `await` pulls the real int out.

</details>

3. Does `await` stop the program or not — why is it essential on a server?

<details>
<summary>Sample Answer</summary>

**Answer:** The program doesn't stop — on `await` the thread is freed, other requests get served, and it returns when the result comes. On a server this means the whole system doesn't block for one user — that's how concurrent handling happens.

</details>

4. Two `Task.Delay(2000)` with `WhenAll` — total time?

<details>
<summary>Sample Answer</summary>

**Answer:** ~2 seconds — both start together (`WhenAll` = `Promise.all`), time doesn't add up. Sequential `await` would take 4 seconds.

</details>
