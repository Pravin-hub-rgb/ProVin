Pichhle file mein LINQ se data in-memory mein nipta diya. Par database query ya API call jaise kaam hote kya hain? Waqt lagte hain — 2 second. Agar wahi ek thread pe rakha, toh poora program ruk jayega. JS mein tumne `await fetch(...)` se yeh problem solve ki thi — **promises**. C# mein wahi concept hai, naam hai **Task** — aur syntax `async/await` bilkul same hai.

# Async / Await (Task)

## Problem — rukne wala code

```csharp
Console.WriteLine("Pehle...");
System.Threading.Thread.Sleep(3000);   // 3 sec ruk jao (JS: sleep — bilkul nahi chahiye tha)
Console.WriteLine("Baad mein");        // ye 3 sec baad chalega
```

Program 3 second **band** baith gaya. Server pe aisa matlab — ek user ke liye baaki sab rok do. Wahi disaster hai.

## C# ka solution — Task + await

```csharp
async Task DoSomethingAsync()
{
    Console.WriteLine("Shuru");

    await Task.Delay(3000);          // 3 sec — PAR program rukta nahi!

    Console.WriteLine("3 sec baad");
}
```

Line by line:

- **`Task`** — "main kaam kar raha hoon, abhi khatam nahi hua" wala object (JS ka **Promise**). `Task<int>` = baad mein ek `int` milega.
- **`async`** — method ke naam ke aage: "is method mein `await` use hoga".
- **`await Task.Delay(3000)`** — "yahan ruk ja, par dusre kaam chalte raho". Jab tak delay khatam, ye method control wapas de deta hai — aur us waqt dusre requests serve hote hain.

JS comparison ekdum:

```javascript
// JS
async function doSomething() {
  console.log("Shuru");
  await new Promise(r => setTimeout(r, 3000));
  console.log("3 sec baad");
}
```
```csharp
// C#
async Task DoSomethingAsync()
{
    Console.WriteLine("Shuru");
    await Task.Delay(3000);
    Console.WriteLine("3 sec baad");
}
```

**Syntax lagbhag copy-paste.** Fark: JS mein Promise tha, yahan `Task`. JS mein har async function implicitly Promise deta tha, yahan return type likhna padta hai:

| JS | C# |
|---|---|
| `Promise<T>` | `Task<T>` |
| `Promise<void>` | `Task` |
| `async function f()` | `async Task FAsync()` |
| `await fetch()` | `await HttpClient.GetAsync()` |
| `setTimeout` | `Task.Delay` |

## Ek asli example — file padhna

```csharp
async Task<string> ReadFileAsync(string path)
{
    Console.WriteLine("Padhna shuru...");
    string content = await File.ReadAllTextAsync(path);   // disk I/O — await!
    Console.WriteLine("Padh gaya, " + content.Length + " chars");
    return content;
}
```

`File.ReadAllTextAsync` — .NET ka async version. **Pattern yeh hai:** .NET mein lagbhag har blocking method ka `...Async` version hota hai — `ReadAllText` vs `ReadAllTextAsync`, `GetAsync`, `SaveChangesAsync`. Roz yahi hoga.

## Return type ka niyam (exam/interview wala)

```csharp
async Task KuchKaam()          // kuch nahi chahiye wapas (void nahi — void async nahi chalta)
{
    await Task.Delay(100);
}

async Task<int> CountAsync()   // int milega
{
    await Task.Delay(100);
    return 42;
}

// Call:
int result = await CountAsync();
```

**Rule:** `async` method ka return type `Task` ya `Task<T>` hona chahiye (bina T ke `void async` invalid hai). Call karte waqt `await` lagao toh andar wali value milti hai.

## await ke bina kya hota hai (aam galti)

```csharp
async Task<int> CountAsync() { await Task.Delay(100); return 42; }

int x = CountAsync();      // ❌ nahi — Task<int> mil raha hai, int nahi
int y = await CountAsync(); // ✅ 42
```

Bina `await` ke tumhare paas **Task** hai (wrapped gift), value nahi. `Task<int>` ko `int` mein assign kiya toh compile error — C# compiler yahan tumhe pakadta hai.

Ek aur galti — `async void`:

```csharp
async void Bad() { ... }    // ❌ kabhi mat karo (event handlers ke alawa)
```

`async void` ka koi return track nahi ho sakta — errors ka pata nahi chalta, testing mushkil. Hamesha `Task` rakho.

## Parallel kaam — do tasks ek saath

```csharp
async Task Demo()
{
    Task a = Task.Delay(2000);        // 2 sec ka kaam shuru — RUKA NAHI
    Task b = Task.Delay(2000);        // doosra bhi ek saath shuru

    await Task.WhenAll(a, b);         // dono khatam hone ka intzaar
    Console.WriteLine("Dono ho gaye — total ~2 sec, 4 nahi!");
}
```

`Task.WhenAll` = JS ka `Promise.all`. Do API calls ek saath chala do — waqt add nahi hota. `await` ek ke baad ek likhoge toh sequential (JS mein bhi yahi hota tha).

## Kab async chahiye — aur kab nahi

**Chahiye:** database query, file read/write, HTTP/API call, email bhejna — disk/network wale kaam.

**Nahi chahiye:** `Console.WriteLine`, memory ka maths (`nums.Sum()`), in-memory LINQ — ye sab turant hote hain, async karoge toh faltu overhead.

> **Library ka rule:** jo method doosron ke liye banaye ho, usme `Async` suffix lagao (`GetUserAsync()`) — call karne wale ko pata chale await chahiye.

## Yeh kya NAHI hai

- **`async` se code fast nahi hota** — uska kaam hai **ruknaye bina** kaam karna. Total time same, par thread free rehti hai (server ek saath bahut requests le sakta hai).
- **`await` = thread block nahi** — JS mein toh thread ek hi tha, par C# mein `await` ka point yahi hai ki thread dusre kaam pe chali jaati hai, rukti nahi.
- **Task ≠ thread** — Task ek "kaam chal raha hai" ka handle hai; andar thread pool use hota hai. Ek thread se hazaar Tasks chal sakte hain.

## Ek complete program — async chalao

```csharp
// Program.cs
using System;
using System.Threading.Tasks;

class Program
{
    static async Task Main(string[] args)     // Main bhi async ho sakta hai!
    {
        Console.WriteLine("Chai banao...");

        Task chai = MakeChaiAsync();           // shuru — parallel
        Task toast = MakeToastAsync();         // shuru — parallel

        await Task.WhenAll(chai, toast);       // dono ka intzaar
        Console.WriteLine("Nashta ready!");

        string data = await FetchDataAsync();
        Console.WriteLine("Data: " + data);
    }

    static async Task MakeChaiAsync()
    {
        await Task.Delay(2000);                // 2 sec — par thread free
        Console.WriteLine("Chai ready");
    }

    static async Task MakeToastAsync()
    {
        await Task.Delay(1500);
        Console.WriteLine("Toast ready");
    }

    static async Task<string> FetchDataAsync()
    {
        await Task.Delay(1000);
        return "user_42";                      // asli code mein HTTP call
    }
}
```

Output ~2 second mein (3 kaam parallel). `static async Task Main` — Main bhi async ho sakta hai, yehi .NET apps ka standard shuruaat hai.

## In Your Own Words

1. C# `Task` ka JS duniya ka equivalent kya hai — `async/await` dono mein kaise dikhta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `Task` = JS ka Promise ("kaam chal raha hai, baad mein result"). Syntax same hai: `async function` → `async Task`, `await promise` → `await task`, `Promise<T>` → `Task<T>`, `Promise.all` → `Task.WhenAll`.

</details>

2. `async Task<int> CountAsync()` ko `int x = CountAsync()` se call karna galat kyun hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Bina `await` ke method `Task<int>` deta hai (result wrapped), int nahi. `int x = ...` mein type mismatch — compile error. Sahi: `int x = await CountAsync();` — `await` ke andar se asli int nikalta hai.

</details>

3. `await` lagane se program ruk jaata hai ya nahi — server pe kyun zaroori hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Program rukta nahi — `await` pe thread free ho jaati hai, dusre requests serve hote hain, jab result aaye tab wapas aati hai. Server pe iska matlab ek user ke liye poora system block nahi hota — isi liye concurrent handling hoti hai.

</details>

4. `Task.Delay(2000)` aur `Task.Delay(2000)` do baar `WhenAll` se — total kitna time?

<details>
<summary>Sample Jawab</summary>

**Jawab:** ~2 second — dono ek saath shuru ho jaate hain (`WhenAll` = `Promise.all`), time add nahi hota. Sequential `await` karte toh 4 second lagte.

</details>

Async se waqt wala problem solve hua — par abhi data memory mein hi hai, program band toh gaya. Data ko **file** ya **JSON** mein save karna aur wapas padhna — wahi agla file: JSON, files, aur generics ka toolbox.
