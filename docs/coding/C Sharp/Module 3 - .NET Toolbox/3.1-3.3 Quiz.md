## MCQ

Q: LINQ ka `.Where()` JS duniya mein kya karta hai?
A. `.map()`
B. `.filter()` — condition wale items chhod ke baaki
C. `.find()`
D. `.sort()`
> B. `.Where(u => u.Age >= 18)` = items filter karta hai jahan condition true ho — bilkul `arr.filter(u => u.age >= 18)`. `.Select()` map aur `.FirstOrDefault()` find ke equivalent hain.

Q: `FirstOrDefault()` ko `First()` se prefer kyun kiya jaata hai user-dhoondhne wale code mein?
A. FirstOrDefault fast hai
B. First() kuch return nahi karta
C. First() match na mile toh exception fekta hai, FirstOrDefault null deta hai jise check kar sakte ho
D. Dono same hain
> C. `First()` na milne par program crash (InvalidOperationException). `FirstOrDefault()` null deta hai — `if (x == null)` se handle ho jaata hai. Naya developer ho toh pehle wala hamesha safer hai.

Q: C# mein `async Task<int>` method ka matlab kya hai?
A. Method turant int deta hai
B. Method "abhi int nahi, baad mein Task ke through dega" — `await` se nikalna padta hai
C. Method ka naam int hai
D. Method thread block karta hai
> B. `Task<int>` = pending result jisme int aayega. `int x = await CountAsync()` se value milti hai. Bina `await` ke tumhare paas Task hai (wrapped), int nahi — type error aayega.

---

Q: `await Task.Delay(2000)` ka kya hota hai?
A. Poora program 2 sec band ho jaata hai
B. Thread block hoti hai jab tak delay khatam
C. Ye method ruk jaata hai aur thread free ho kar dusre kaam karti hai, 2 sec baad wapas aati hai
D. Error aata hai
> C. `await` ka point yahi hai — wait karte hue thread release ho jaati hai (dusre requests serve hote hain). JS mein event loop wala tha, C# mein thread-pool continuation wala. Program/program ka dusra hissa nahi rukta.

---

Q: `Promise<T>` ka C# equivalent kya hai?
A. `Future<T>`
B. `Task<T>`
C. `Thread<T>`
D. `async<T>`
> B. JS `Promise<T>` = C# `Task<T>`, `Promise.all` = `Task.WhenAll`, `await` dono mein same. Yehi mapping yaad rehni chahiye — JS wale async concepts seedhe C# mein translate hote hain.

---

Q: `JsonSerializer.Deserialize<Person>(json)` mein `<Person>` kyun likhna padta hai?
A. Syntax hai, koi matlab nahi
B. Kyunki C# ko batana padta hai JSON ko kis type mein todna hai — JS `JSON.parse` jaisa free-for-all nahi
C. Person class ka naam dikhane ke liye
D. Warna JSON print nahi hoga
> B. JS `JSON.parse` bina type ke object bana deta tha (chhod do `any`). C# type-safe hai — `<Person>` se pata chalta hai kaunsi class banani hai aur galat JSON pe error pehle milta hai.

---

Q: Generic class `MyList<T>` ka `T` kya hai?
A. Ek specific class ka naam
B. Placeholder — class banate waqt asli type daalenge (`MyList<int>`)
C. Template file
D. Method ka return type hamesha
> B. `T` type-parameter hai — jaise function mein parameter value leta hai, generic type leta hai. `MyList<int>` se `T=int`, `MyList<string>` se `T=string` — ek hi code, type safety ke saath.

## TrueFalse

Q: `async` likhne se code tez chalta hai — kaam jaldi khatam ho jaata hai.
- True
- False
> False. `async` ka kaam tez karna nahi — **rukne se bachana** hai. Total time same rehta hai (2 sec delay 2 hi hai), par thread free rehti hai aur dusre kaam chalte hain. Server pe isi se concurrency aati hai.

---

Q: `async void` method likhna C# mein aam practice hai aur hamesha theek rehta hai.
- True
- False
> False. `async void` avoid karo — uska Task track nahi hota, andar ka error bahar nahi aata, test karna mushkil. Hamesha `Task`/`Task<T>` rakho (event handlers ke alawa).

---

Q: LINQ ke `.Where()` call karte hi filter turant chal jaata hai — bilkul JS `.filter()` jaisa.
- True
- False
> False. LINQ lazy hai — `.Where()` sirf query ka plan banata hai. Tab chalta hai jab result consume karo (`ToList()`, `foreach`, `Count()` etc.). JS `.filter()` turant naya array banata tha.

---

Q: `File.ReadAllTextAsync` jaisa `...Async` suffix wala version tab use hota hai jab kaam rukne wala ho (disk/network).
- True
- False
> True. Disk I/O, HTTP, DB query — sab rukne wale kaam hain, inke `...Async` versions thread free rakhte hain. `Console.WriteLine` jaise turant wale kaam pe async ki zaroorat nahi.

---

Q: Generics sirf performance ke liye hain — type check ka isse koi lena-dena nahi.
- True
- False
> False. Generics dono karte hain — compile-time type safety (`MyList<int>.Add("hi")` error) aur performance (box/unbox nahi hota, jitna object wale purane tarike mein hota tha).
