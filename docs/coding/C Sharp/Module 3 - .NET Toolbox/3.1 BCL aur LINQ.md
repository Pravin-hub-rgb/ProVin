Until now you learned the C# language — variables, classes, loops. But a language is just grammar. In JS, the real work you did (getting dates, filtering arrays) relied on **Node.js's built-in toolbox** — `Date`, `Math`, `Array.map`, `JSON.parse`. C# gets the same toolbox from **.NET's Base Class Library (BCL)** — and its most powerful part is **LINQ**.

# BCL and LINQ

## BCL — .NET's built-in toolbox

When you write `using System;`, you're opening BCL's door. Every small thing is ready there:

```csharp
using System;

Console.WriteLine(DateTime.Now.ToString("yyyy-MM-dd"));   // date — JS: new Date()
Console.WriteLine(Math.Max(5, 10));                        // JS: Math.max
Console.WriteLine(Math.Round(3.14159, 2));                 // 3.14
Console.WriteLine(Guid.NewGuid());                         // unique ID — DB one
Console.WriteLine("Hello".ToUpper());                      // string helpers
Console.WriteLine(Math.Abs(-50));                          // 50
```

**Nothing to install** — all this comes with `dotnet new console`. In JS, where did `Math`, `Date` come from? Browser/Node built-ins. The same thing, except in C# everything is **organized in one library (BCL)** — date, file, regex, collection, all of it.

NuGet packages come in only when BCL doesn't have it (like SQL driver, email client) — that's module 4.

## LINQ — C#'s biggest secret weapon

**LINQ = Language Integrated Query** — a language for asking questions of a list/array. First look at the JS code:

```javascript
// JS — filter, sort, transform data
const adults = users.filter(u => u.age >= 18);
const names = adults.map(u => u.name.toUpperCase());
const sorted = users.sort((a, b) => a.age - b.age);
```

In C# the same work two ways — first the **classic** (you should understand this):

```csharp
List<string> names = new List<string>();
foreach (var u in users)
{
    if (u.Age >= 18)
        names.Add(u.Name.ToUpper());
}
```

Then **LINQ** (what you'll use daily):

```csharp
var names = users
    .Where(u => u.Age >= 18)        // filter — JS: filter
    .Select(u => u.Name.ToUpper())  // transform — JS: map
    .OrderBy(u => u.Age)            // sort
    .ToList();
```

Mapping at a glance:

| JS | LINQ |
|---|---|
| `.filter()` | `.Where()` |
| `.map()` | `.Select()` |
| `.find()` | `.FirstOrDefault()` |
| `.some()` | `.Any()` |
| `.every()` | `.All()` |
| `.reduce()` | `.Sum()` / `.Aggregate()` |
| `.sort()` | `.OrderBy()` / `.OrderByDescending()` |
| length check | `.Count()` |

**Lambda** (`u => u.Age >= 18`) is just like a JS arrow function — a small expression that says "run this check for every `u`".

## LINQ's everyday methods

```csharp
List<int> nums = new List<int> { 5, 3, 8, 1, 9, 2 };

int max = nums.Max();                    // 9
int min = nums.Min();                    // 1
int sum = nums.Sum();                    // 28
double avg = nums.Average();             // 4.66

bool koiBada = nums.Any(n => n > 8);     // true — found any one?
bool SabChhote = nums.All(n => n < 10);  // true — all matched
int pehla = nums.First();                // 5 — throws if not found
int? pehlaYa = nums.FirstOrDefault(n => n > 100);   // null — safe version ⭐
int kitne = nums.Count(n => n % 2 == 0); // even count
```

Remember the **`FirstOrDefault` pattern** — finding data is the most common task in C#, and since it can return null, you must check:

```csharp
var student = students.FirstOrDefault(s => s.Name == "Vin");
if (student == null)
{
    Console.WriteLine("Nahi mila");
}
else
{
    Console.WriteLine(student.Marks);
}
```

In JS, `arr.find()` returned `undefined` — the same pattern, just with null.

## Query syntax (the old style)

You'll sometimes find this in codebases:

```csharp
var result = from u in users
             where u.Age >= 18
             select u.Name;
```

It looks like SQL. **Both do the same work** — modern code prefers method syntax (`.Where()`), but you should understand both (you'll find them in older .NET code).

## Anonymous types — object without a class

```csharp
var report = new { Naam = "Vin", Marks = 90 };   // small data bag
Console.WriteLine(report.Naam);
```

`new { ... }` — created a small object for one-time use without writing a class. Comes up a lot with LINQ:

```csharp
var top = students
    .OrderByDescending(s => s.Marks)
    .Select(s => new { s.Naam, s.Marks })   // only 2 things needed
    .Take(3);
```

**When:** data is only for print/report. **When not:** when it must be stored/returned (that's a proper class/DTO — module 5).

## What It Is NOT

- **LINQ ≠ SQL query** — database queries are LINQ-to-SQL (module 4), but what's here runs on **in-memory** lists. `List`, array — data already in memory.
- **Nothing happens before `.ToList()`** — LINQ methods are **lazy**: `.Where()` doesn't run immediately, it runs on `foreach`/`ToList`/`Count`. (JS's `filter` made a new array immediately — that's the difference.)
- **BCL ≠ NuGet package** — BCL is built in; NuGet is downloaded.

## A complete program — employee report with LINQ

```csharp
// Program.cs
using System;
using System.Collections.Generic;
using System.Linq;          // ❗ needed for LINQ

class Employee
{
    public string Name;
    public string Dept;
    public double Salary;
    public Employee(string n, string d, double s) { Name = n; Dept = d; Salary = s; }
}

class Program
{
    static void Main()
    {
        var team = new List<Employee>
        {
            new Employee("Vin", "IT", 50000),
            new Employee("Rahul", "HR", 40000),
            new Employee("Sara", "IT", 60000),
            new Employee("Amit", "HR", 45000),
        };

        // IT people, by salary, with names
        var itSorted = team
            .Where(e => e.Dept == "IT")
            .OrderByDescending(e => e.Salary)
            .Select(e => $"{e.Name} ({e.Salary:C0})");

        foreach (var line in itSorted)
            Console.WriteLine(line);

        // One question: anyone in HR above 42000?
        bool highPaid = team.Any(e => e.Dept == "HR" && e.Salary > 42000);
        Console.WriteLine("HR ka high earner? " + highPaid);   // True

        // Report: department-wise total
        var totals = team
            .GroupBy(e => e.Dept)                       // group — like SQL GROUP BY
            .Select(g => new { Dept = g.Key, Total = g.Sum(e => e.Salary) });

        foreach (var t in totals)
            Console.WriteLine($"{t.Dept}: {t.Total}");
    }
}
```

Saw `GroupBy`? Splitting by department and `Sum` — SQL-like work without a database. That's the power.

## In Your Own Words

1. What is BCL, and where do `Math.Round`, `DateTime.Now`, `Guid.NewGuid()` come from?

<details>
<summary>Sample Answer</summary>

**Answer:** BCL (.NET Base Class Library) is the biggest built-in class library that ships with .NET — date, math, file, string, collection, all in it. Accessed via `using System;`. Nothing to install, just like JS's built-in `Math`/`Date`.

</details>

2. What's the LINQ equivalent of JS `filter/map/find` — with an example.

<details>
<summary>Sample Answer</summary>

**Answer:** `filter → Where`, `map → Select`, `find → FirstOrDefault`. Like `users.filter(u => u.age >= 18)` becomes `users.Where(u => u.Age >= 18)`. Lambda (`u => ...`) is like an arrow function — a condition runs for each item.

</details>

3. Difference between `First()` and `FirstOrDefault()` — when which?

<details>
<summary>Sample Answer</summary>

**Answer:** `First()` throws an exception if no match; `FirstOrDefault()` returns null/default. In user-searching code, `FirstOrDefault` + null-check is safe — `First()` only when you're sure it'll be found.

</details>

4. What happens when you write `nums.Where(...)` — is anything happening yet? When does it run?

<details>
<summary>Sample Answer</summary>

**Answer:** Nothing — LINQ is lazy, it only builds the query plan. It runs when the result is consumed: `ToList()`, `foreach`, `Count()`, `First()` etc. That's the difference from JS's `filter` (which made an array immediately).

</details>

Data got handled in memory with LINQ — but real apps keep data in a **database** and save it to **disk/file**. And big tasks (API call, database query) don't finish instantly — for those you need **async/await**, which you did with Promises in JavaScript.
