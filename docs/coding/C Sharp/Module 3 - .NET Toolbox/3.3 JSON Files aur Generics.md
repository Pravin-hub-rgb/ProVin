Async data is running now — but everything's gone when the program closes. In browser JS, data lived in `localStorage` or in API response JSON. C#/.NET has the same two jobs: **files** (save to disk) and **JSON** (data as text) — plus one thing JS didn't have: **generics** (`List<int>`'s `<>`), which you've already used but should now understand.

# JSON, Files and Generics

## JSON — where it lives in C#

In JS, `JSON.stringify`/`JSON.parse` were built in. In C#, there's the **`System.Text.Json`** namespace:

```csharp
using System.Text.Json;

// Object → JSON string
var student = new { Naam = "Vin", Marks = 90 };
string json = JsonSerializer.Serialize(student);
Console.WriteLine(json);     // {"Naam":"Vin","Marks":90}

// JSON string → Object
string data = "{\"Naam\":\"Vin\",\"Marks\":90}";
var obj = JsonSerializer.Deserialize<Person>(data);   // ❗ generic — <Person>
Console.WriteLine(obj.Naam);
```

Pattern, exactly like JS:

```javascript
JSON.stringify(obj)                    →  JsonSerializer.Serialize(obj)
JSON.parse(str)                        →  JsonSerializer.Deserialize<T>(str)
```

**`Deserialize<Person>`** — you must say in `<>` which type to parse the JSON into (JS's `JSON.parse` made anything — here it's typed). The JSON key matches the C# property name — to change it, use an attribute:

```csharp
class User
{
    [JsonPropertyName("user_name")]    // JSON key will be "user_name"
    public string UserName { get; set; }
    public int Age { get; set; }       // this stays "Age"
}
```

## Reading/writing files — the async way

```csharp
// Write (string → file)
string content = "Line 1\nLine 2";
await File.WriteAllTextAsync("notes.txt", content);

// Read (file → string)
string back = await File.ReadAllTextAsync("notes.txt");
Console.WriteLine(back);

// Does the file exist?
bool hai = File.Exists("notes.txt");
```

Everything's inside the `File` class — `WriteAllText`, `ReadAllText`, `AppendAllText`, `Copy`, `Delete`. Module 3.2's rule applies here too: use the **`...Async` version** (disk I/O is blocking work).

Avoid path mistakes:

```csharp
// ❌ relative path — don't know which folder it ran from (working directory issue)
await File.WriteAllTextAsync("notes.txt", content);

// ✅ explicit path (or Path.Combine)
string folder = Path.Combine(Environment.CurrentDirectory, "data");
Directory.CreateDirectory(folder);   // create if missing
string path = Path.Combine(folder, "notes.txt");
await File.WriteAllTextAsync(path, content);
```

**JSON + file = your own small database** (handy in early project days):

```csharp
string json = JsonSerializer.Serialize(students, new JsonSerializerOptions { WriteIndented = true });
await File.WriteAllTextAsync("students.json", json);

string back = await File.ReadAllTextAsync("students.json");
var loaded = JsonSerializer.Deserialize<List<Student>>(back);
```

`WriteIndented = true` — pretty JSON (indented); otherwise it's all one line.

## Generics — the real meaning of `List<int>`'s `<>`

You've written `List<int>`, `Task<string>` — now the secret inside:

```csharp
// Without generics — TIGHT BOX (separate code for each type)
class IntList
{
    int[] items = new int[100];
    void Add(int x) { ... }
    int Get(int i) { ... }
}
class StringList
{
    string[] items = new string[100];    // copy-paste!
    ...
}
```

With generics — **one code, type from outside**:

```csharp
class MyList<T>               // T = placeholder ("any type")
{
    private List<T> items = new List<T>();

    public void Add(T item)    { items.Add(item); }     // T becomes whatever comes in
    public T Get(int i)        { return items[i]; }
}
```

```csharp
MyList<int> a = new MyList<int>();
MyList<string> b = new MyList<string>();
a.Add(5);        // T = int
b.Add("hi");     // T = string — same class!
```

**Benefit:** write once, works for every type — and **type safe** (trying to add a string gives a compile error). JS's alternative was `any` (dangerous); here `T` keeps the safety.

You can write your own generic method too:

```csharp
T FirstOf<T>(List<T> list)
{
    return list[0];         // any T, string or int
}

FirstOf(new List<int> { 5, 6 });     // 5
FirstOf(new List<string> { "a" });   // "a"
```

You can add limits with **constraints**:

```csharp
T MaxOf<T>(List<T> list) where T : IComparable<T>   // only types that can be compared
{
    T best = list[0];
    for (int i = 1; i < list.Count; i++)
        if (list[i].CompareTo(best) > 0) best = list[i];
    return best;
}
```

`where T : IComparable<T>` — "T must be a type that can be compared". Here interface + generic show up together. .NET's `List<T>`, `Dictionary<TKey,TValue>`, `Task<T>` are all built on this pattern — now their `<>` will make sense.

## What It Is NOT

- **`JsonSerializer.Deserialize` is not magic** — you must give the type in `<>`, and JSON keys + property names must match (if not, use `[JsonPropertyName]`).
- **Always check file operations** — `ReadAllText` on a missing file throws. Use `File.Exists` first, or try-catch (exception handling in detail in module 5).
- **Generics ≠ `object`** — old C# kept everything as `object` (had to unbox, slow, type mistakes happened). Generics check the type at compile time, zero performance loss.

## A complete program — save/load students to a file

```csharp
// Program.cs
using System;
using System.Collections.Generic;
using System.IO;
using System.Text.Json;
using System.Threading.Tasks;

class Student
{
    public string Name { get; set; }
    public int Marks { get; set; }
}

class Program
{
    static async Task Main()
    {
        var students = new List<Student>
        {
            new Student { Name = "Vin", Marks = 90 },
            new Student { Name = "Rahul", Marks = 85 },
        };

        string path = Path.Combine(Environment.CurrentDirectory, "students.json");

        // Save
        string json = JsonSerializer.Serialize(students,
            new JsonSerializerOptions { WriteIndented = true });
        await File.WriteAllTextAsync(path, json);
        Console.WriteLine("Save ho gaya: " + path);

        // Load
        string back = await File.ReadAllTextAsync(path);
        var loaded = JsonSerializer.Deserialize<List<Student>>(back);

        // LINQ — question on loaded data
        var top = loaded.Where(s => s.Marks >= 88)
                        .Select(s => s.Name);
        Console.WriteLine("Topper: " + string.Join(", ", top));
    }
}
```

Save → Load → LINQ — three modules' use together. Run it and open `students.json` to see.

## In Your Own Words

1. What's C#'s equivalent of JS's `JSON.stringify/parse` — why `<T>` in `Deserialize<T>`?

<details>
<summary>Sample Answer</summary>

**Answer:** `JsonSerializer.Serialize(obj)` and `JsonSerializer.Deserialize<T>(str)`. `<T>` because C# must be told which type to parse the JSON into (`Deserialize<Person>`) — JS's `JSON.parse` made anything without being told, here it's type-safe.

</details>

2. What are generics — explain with `MyList<T>`, and why was the old `object` way bad?

<details>
<summary>Sample Answer</summary>

**Answer:** Generics = one piece of code that takes its type from outside (`<T>` placeholder). `MyList<int>` and `MyList<string>` use the same class. The `object` way didn't catch type mistakes at compile time and boxed/unboxed values (slow); generics are type-safe and fast.

</details>

3. Give the complete 3-step flow for saving JSON to a file.

<details>
<summary>Sample Answer</summary>

**Answer:** (1) Turn the object into a JSON string with `JsonSerializer.Serialize`, (2) write to disk with `File.WriteAllTextAsync(path, json)`, (3) read back: `ReadAllTextAsync` + `JsonSerializer.Deserialize<List<T>>(back)` to make the object again.

</details>

4. What does the `where T : IComparable<T>` constraint mean?

<details>
<summary>Sample Answer</summary>

**Answer:** A condition in a generic method — only types that implement `IComparable` (i.e. can be compared) are allowed as `T`. So inside, methods like `CompareTo` can be safely called — a random type can't come in and break the code.

</details>
