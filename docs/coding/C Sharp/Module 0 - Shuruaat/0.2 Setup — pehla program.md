In the previous file you saw that C# needs a compiler and that compiler comes with .NET. So the first job — get .NET onto your machine, and then feel that same thing you felt when you ran `node app.js`.

# Setup — .NET SDK and your first program

## Step 1: Install the .NET SDK

SDK means **Software Development Kit** — compiler + runtime + the `dotnet` command, all in one package. You had to install Node.js to run JS, right? Exactly the same thing, just called .NET SDK.

Go to your browser → `dotnet.microsoft.com/download` → pick your OS (Windows) → download and run the latest **SDK** installer. (Pick the LTS version — "LTS" means long-term support, always go with LTS.)

After installing, open a terminal (PowerShell):

```bash
dotnet --version
```

A version number came up (like `8.0.xxx`) — setup done. If nothing came up, close the terminal and open it again (PATH gets refreshed).

> **Remember:** don't install just the "Runtime" — the runtime only runs things; to check/compile code you wrote you need the SDK. The SDK already includes the runtime.

## Step 2: Your first project

In a terminal, inside a folder:

```bash
dotnet new console -n MeraPehlaProgram
cd MeraPehlaProgram
```

- `dotnet new console` — magic like `npx create-next-app`: a ready-made template is created. "Console" means a program that runs in the terminal (no website — for now we're just learning).
- `-n MeraPehlaProgram` — the project's name.
- `cd` — go into that folder.

This gets created in the folder:

```
MeraPehlaProgram/
├── MeraPehlaProgram.csproj   ← project details (like package.json)
├── Program.cs                ← your code goes here (like app.js)
└── obj/ bin/                 ← generated build files (like node_modules — don't touch)
```

Open **`Program.cs`** — you'll find something like:

```csharp
// See https://aka.ms/new-console-template for more information
Console.WriteLine("Hello, World!");
```

This is the entry file — in JS we started with `console.log`, here with `Console.WriteLine`. (In C# `Console` has a capital C — it's the class name, all of this becomes clear in module 2.)

## Step 3: Run it

```bash
dotnet run
```

Output:

```
Hello, World!
```

**Recognize the feel?** `node app.js` → output. Here `dotnet run` → output. The only difference is that compilation also happens in between — the first run is a bit slow (1-2 seconds), then it's fast because a build cache forms.

## Tweak Program.cs and see

Make the content of `Program.cs` this:

```csharp
// Program.cs
Console.WriteLine("Hello, C#!");          // line 1: print
string naam = "Vin";                      // line 2: created a string variable
int umar = 25;                            // line 3: int (whole number)
Console.WriteLine(naam + " ki umar " + umar + " hai");  // line 4: join and print
```

Run `dotnet run`:

```
Hello, C#!
Vin ki umar 25 hai
```

Line by line:

1. `Console.WriteLine("...")` — prints a string literal (JS: `console.log`)
2. `string naam = "Vin"` — a variable, but type first (in JS we wrote `const naam`, here `string`)
3. `int umar = 25` — int means **whole number**. In JS there was one `number` type; here `int` (integer), `double` (decimal) are separate
4. `+` joins the strings — just like JS, but you can only join the same types. `naam + umar` works (string + int), but `umar + 10` would be number addition

## Try writing it wrong (the compiler's real benefit)

Do this — accidentally write a string on line 3:

```csharp
int umar = "pachees";   // wrong! string instead of number
```

Now `dotnet run`:

```
error CS0029: Cannot implicitly convert type 'string' to 'int'
```

**This is the real difference between JS and C#.** In JS this code would have run and things would have gone sideways later. C#'s compiler **stopped it before it even ran** — with the file and line number of the error. The error will feel scary at first, but this is your bodyguard — until the code is correct, it simply won't run.

Try one more common mistake:

```csharp
Console.Writeline("hello");   // 'W' lowercase — wrong
```

```
error CS0117: 'Console' does not contain a definition for 'Writeline'
```

The compiler tells you what's wrong and where. For now, that's debugging.

## Writing in VS Code (recommended)

It works from the terminal too, but VS Code will be more comfortable:

1. Open VS Code → install the **C# extension** (the Microsoft one, search "C#") — for IntelliSense (autocomplete) and error underlining
2. `File → Open Folder` and open your `MeraPehlaProgram` folder
3. Click on `Program.cs` → the **▷ Run** button in the bottom-right corner (appears after the C# extension) or `dotnet run` in the terminal

> **Both VS and VS Code work** — Visual Studio (the big .exe) is .NET's own IDE, used for large projects. But for now VS Code + the extension is enough, and you're already comfortable with it.

## What This Is NOT

- **`dotnet run` ≠ `npm run dev`** — `dotnet run` runs the program once and it ends (console app). `npm run dev` keeps a server running. The server scene comes in Module 5 (`dotnet run` will run a server there — but the structure will be different).
- **`.csproj` is not code** — it's the project's metadata (name, which .NET version, which packages). Like package.json. Open it and have a look, it'll make sense.
- **`obj/ bin/` folders aren't junk** — they're generated build files, ignored in git (the `.gitignore` template handles that).

## In Your Own Words

1. What's the difference between the .NET SDK and the .NET Runtime — which should you install and why?

<details>
<summary>Sample Answer</summary>

**Answer:** The runtime only runs a built program; the SDK gives you the compiler + runtime + the dotnet command. To learn/write code you need the SDK — the runtime is already inside it. Install just the runtime and you won't be able to write and compile code.

</details>

2. What is `dotnet new console`'s equivalent in the Node.js world, and which file is `Program.cs` equivalent to?

<details>
<summary>Sample Answer</summary>

**Answer:** `dotnet new console` ≈ `npx create-next-app` (creates a new project from a template), and `Program.cs` ≈ `app.js` — program execution starts here.

</details>

3. What happened when you wrote `int umar = "pachees";`, and what would have happened in JS?

<details>
<summary>Sample Answer</summary>

**Answer:** C#'s compiler gave an error before running (CS0029) because a string can't be converted to int. In JS the code would have run (JS is loosely typed) and things would have gone sideways later or at runtime.

</details>

4. Name the 2 most common compiler errors you've seen so far.

<details>
<summary>Sample Answer</summary>

**Answer:** CS0029 (type mismatch — can't put a string into an int) and CS0117 (wrong name written — like `Writeline` with a lowercase 'w'). Both get caught before the program runs.

</details>
