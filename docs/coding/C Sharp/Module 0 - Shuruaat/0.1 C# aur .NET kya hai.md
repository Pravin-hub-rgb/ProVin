When you learned JavaScript, you figured out that JS has no home of its own — it runs in the browser or inside Node.js. JavaScript was your language; Node.js was the engine that ran it. Now you have to do the same thing in a new world — and there the language is **C#**, and the engine that runs it is **.NET**.

# What are C# and .NET

**C# (C-Sharp) is a programming language** — just like JavaScript is a language. Microsoft created it in 2000. Your old JS code looked like this:

```javascript
// JavaScript
const naam = "Vin";
console.log("Hello " + naam);
```

The same work in C#:

```csharp
// C#
string naam = "Vin";
Console.WriteLine("Hello " + naam);
```

You can probably guess from the syntax — the story is the same, only you have to write the type first (`string naam` — like JS's `const naam`, but you tell the compiler up front that this is a string).

Now the real difference: JS runs without checks — `console.log(naam.toUpperCase())` will only error at the end, at runtime, if `naam` turns out to be a number. C#'s compiler reads the entire code before it runs — wrong type, wrong method, anything wrong, and the program simply won't run. That's why C# is preferred in large professional projects (banks, large systems) — you get the chance to catch mistakes up front.

## .NET — C#'s engine

A language alone can't do anything. JavaScript needed Node.js to run — reading files, building servers, all of that came from it. Similarly, C# needs .NET to run — Microsoft's own platform that executes C# code and also hands you thousands of ready-made tools.

So the relationship is crystal clear:

| JS world | C# world |
|---|---|
| JavaScript (language) | **C# (language)** |
| Node.js (engine/runtime) | **.NET (engine/runtime)** |
| npm | NuGet |
| Express / Next.js API routes | **ASP.NET Core (Web API)** |
| package.json | .csproj file |
| `node app.js` | `dotnet run` |
| JavaScript (types at runtime) | C# (types at compile time) |

Look closely — this table is your whole map. Everything you learned in JS has an equivalent here. The only new things are the syntax and this strictness.

## What This Is NOT (common misconceptions)

- **Not C++'s little brother** — the names and syntax overlap, but there's none of the manual memory pain of C++. The .NET garbage collector handles that itself (more on that in module 3).
- **.NET is not a language** — .NET is the platform, C# is the language. This mix-up happens a lot — remember it.
- **.NET doesn't only run on Windows** — that used to be true, but the modern .NET (which you'll learn) runs on Linux, Mac, everything — which is why it runs on servers.
- **Not Java** — it feels very similar, but the syntax and ecosystem are different.

## First look — what C# looks like

One small complete program, to take away the fear:

```csharp
// Program.cs — C#'s entry file, like JS's app.js
Console.WriteLine("Hello, C#!");   // equivalent of console.log

string naam = "Vin";               // string type, like a JS variable
int umar = 25;                     // int = whole number (in JS everything was just number; here types differ)

Console.WriteLine(naam + " ki umar " + umar + " hai");
```

Clear, right? `Console.WriteLine` = `console.log`, variable = variable, you just have to write the type. That's all C# is at the start — everything else stands on top of this.

2. How does C#'s compiler work differently compared to JS, and why is this important in large projects?

<details>
<summary>Sample Answer</summary>

**Answer:** In JS, type errors surface while the code runs (at runtime), while C#'s compiler reads the whole code before running and catches type/method errors up front (at compile time). That's why fewer crashes reach production in large projects.

</details>

3. Why is it wrong to say "C# is C++'s little brother"?

<details>
<summary>Sample Answer</summary>

**Answer:** The names and syntax overlap a bit, but C++ forces you to manage memory manually while .NET's garbage collector handles memory on its own. So C# doesn't have the pointer/pain side of C++ — they're separate languages.

</details>
