Pichhle file ke end mein ek dikkat chhodi thi — `public` fields daal kar sabko andar ghusne diya tha. Koi `s1.marks = -500` likh de toh poora data bigad jaayega. Bank ka balance koi bhi bahar se badal de aisa ho toh kaise bank? Yahi problem hai, aur iska C# ka swagat hai — **encapsulation**.

# Properties aur Encapsulation

## Problem — data khula pada hai

```csharp
class Student
{
    public int marks;
}

Student s = new Student();
s.marks = -500;    // ❌ chal gaya! koi rokne wala nahi
```

Encapsulation ka matlab: **data ko andar lock karo, bahar sirf controlled raaste do.** Field ko private karo, aur bahar wale sirf tarike (methods/properties) se chhu sakein — jahan tum validation laga sako.

## Private field + public property — C# ka main pattern

```csharp
class Student
{
    private int _marks;    // bahar se seedha access BANNED

    public int Marks       // yeh hai PUBLIC raasta (property)
    {
        get { return _marks; }             // padhne pe
        set
        {
            if (value < 0 || value > 100)
                Console.WriteLine("Marks 0-100 ke beech hona chahiye!");
            else
                _marks = value;            // likhne pe — validation yahan
        }
    }
}
```

```csharp
Student s = new Student();
s.Marks = 95;       // ✅ set chala → check hua → _marks = 95
s.Marks = -500;     // ⚠️ set chala → reject! _marks mein -500 nahi gaya
Console.WriteLine(s.Marks);   // get chala → 95
```

3 cheezein:

1. **`private int _marks`** — field chhupayi. Bahar `s._marks` likha toh error. (Naam ka `_` prefix sirf convention hai — batata hai "yeh andar wali private cheez hai".)
2. **`public int Marks`** — **property**. Bahar wala `s.Marks` likhta hai, par andar `get`/`set` block chalte hain — jaise ek reception jo tumhari request le kar andar jaata hai.
3. **`value`** — `set` ke andar `value` mein wo aati hai jo kisi ne likhi (`s.Marks = 95` → `value = 95`). Validation yahin lagti hai.

**Ye hi encapsulation hai:** andar data, bahar controlled door. JS mein aisa kuch nahi tha (objects khule the) — Python wala `@property` ho toh wo yaad karo, warna C# hi tumhari pehli proper property language hai.

## Auto-property — roz ka shortcut

Validation nahi chahiye toh lambi form likhne ki zaroorat nahi:

```csharp
class Student
{
    public string Naam { get; set; }      // pura kaam compiler ne khud kar diya
    public int Marks { get; set; }
}
```

`{ get; set; }` — compiler ke andar ek private backing field khud bana leta hai. **Ye 90% jagah use hota hai** — jahan validation chahiye wahan lambi form, baaki jagah auto.

```csharp
Student s = new Student { Naam = "Vin", Marks = 95 };   // object initializer — JS object literal jaisa
```

`new Student { ... }` — constructor ke baad seedhe fields bharne ka C# wala tareeka (JS `{ naam: "Vin" }` wali feeling).

## Read-only property — sirf padho, badlo mat

```csharp
public double Balance
{
    get { return _balance; }     // set hi nahi — bahar se sirf padh sakte ho
}
```

Ya auto wali mein sirf `get`:

```csharp
public string CreatedAt { get; } = DateTime.Now.ToString("yyyy-MM-dd");
```

Jis cheez ko bahar se badalna hi nahi chahiye (ID, banne ki date) — wahi read-only.

## Naming convention — C# team wali

```csharp
class Course
{
    private string _title;              // field: _camelCase (underscore)
    private int _duration;

    public string Title                 // property: PascalCase
    {
        get => _title;
        set => _title = value?.Trim() ?? "Untitled";   // expression form
    }

    public int Duration
    {
        get => _duration;
        set => _duration = value > 0 ? value : 1;      // validation + default
    }
}
```

`get => ...; set => ...;` — expression-bodied form, chhoti property ke liye compact. `value?.Trim()` jaisi cheezein (null-conditional) JS `?.` jaisi hain — C# mein bhi hai.

**Convention:** field `_naam`, property `Naam`, method `GetNaam`. C# interview mein naming poochhi jaati hai — yehi hai.

## Kahan kya use kare — quick decision

- **Bahar se read-only cheez** (ID, timestamp): `{ get; }`
- **Normal data, koi check nahi** (naam, title): `{ get; set; }` (auto)
- **Data jise check karna hai** (marks, balance, age): `_field` + lambi property with validation
- **Bilkul andar wala secret**: `private` field bina property ke

## Ek complete program — Bank account v2 (safe wala)

```csharp
// Program.cs
class Account
{
    private string _owner;
    private double _balance;

    public string Owner
    {
        get => _owner;
        set => _owner = string.IsNullOrWhiteSpace(value) ? "Unknown" : value;
    }

    public double Balance { get; private set; }   // bahar se sirf padho

    public Account(string owner, double opening)
    {
        Owner = owner;                            // property ke through — validation lagega
        _balance = opening >= 0 ? opening : 0;
    }

    public void Deposit(double amt)
    {
        if (amt <= 0) { Console.WriteLine("Galat amount"); return; }
        _balance += amt;
    }

    public void Withdraw(double amt)
    {
        if (amt <= 0 || amt > _balance) { Console.WriteLine("Nahi ho sakta"); return; }
        _balance -= amt;
    }
}

// --- program ---
Account a = new Account("Vin", 1000);
a.Deposit(500);
// a.Balance = 99999;     // ❌ compile error — set private hai! seedha badal nahi sakte
Console.WriteLine(a.Balance);   // 1500 — sirf padh sakte ho
```

Dekho kitna safe ho gaya — balance sirf `Deposit`/`Withdraw` se badalta hai, dono mein check hai. Bahar se koi cheat nahi kar sakta. **Yahi "professional" code dikhta hai company mein** — sab fields muffled hain, bahar sirf soche-samjhe tareeke.

## Yeh kya NAHI hai

- **`public` field = encapsulation nahi** — `public int marks` mein validation ka koi mauka hi nahi. Property ka point yahi hai ki get/set ke beech mein baith sako.
- **Property koi method nahi hai** — bahar se `s.Marks` likhte ho (`()` nahi lagate). Andar get/set chalte hain, bahar se lagta hai jaise seedha field ho.
- **Har private ke saath property zaroori nahi** — agar field sirf class ke andar hi kaam aata hai (helper state), toh seedha private chhod do. Bahar chahiye tabhi property banao.

## In Your Own Words

1. Encapsulation kya hai — Account balance ke example ke saath samjhao.

<details>
<summary>Sample Jawab</summary>

**Jawab:** Data ko private karke bahar sirf controlled raaste dena. Balance private hai, bahar sirf `Deposit`/`Withdraw` methods — jahan check lagta hai. Isliye koi bahar se seedha balance nahi bigad sakta — data guarded hai.

</details>

2. `set` block mein `value` kya hota hai — `s.Marks = 95` likhne pe kya chalta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `value` = wo number jo kisi ne assign kiya (95). `s.Marks = 95` seedha field mein nahi jaata — `set` block chalta hai, jahan `value` ko check (validation) karke phir private field mein daala jaata hai.

</details>

3. Auto-property `{ get; set; }` aur full property (`_field` + get/set) mein kab kaunsi use karni chahiye?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Validation ya logic nahi toh auto-property (short, compiler backing field khud banata hai). Check chahiye (marks 0-100, balance positive) toh `_field` + lambi property with get/set. Read-only ke liye sirf `{ get; }`.

</details>

4. `public double Balance { get; private set; }` ka bahar wale developer ke liye kya matlab hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Bahar se Balance padha ja sakta hai (`a.Balance`), par set nahi — kyunki `private set` hai. Value sirf class ke andar methods se badalti hai. Bahar se `a.Balance = 999` likha toh compile error.

</details>

Ab data safe hai — par har class sab kuch apne aap karti hai. Bade system mein kaam baantna padta hai: ek class doosri se inherit kare, ek interface follow kare. Wahi hai OOP ka doosra half — **inheritance aur polymorphism**.
