Ab tak tum sab cheezein alag-alag variables mein rakh rahe the — `naam`, `umar`, `salary` alag-alag. Par jab ek student ke 10 attributes hain aur students 100 hain, toh aise nahi chalega. JS mein tumne objects banaye the (`{ naam: "Vin", umar: 25 }`) aur React mein `function Student()` components likhe the — wahi idea ab **class** ke roop mein, par zyada structured.

# Class aur Object

## Class kya hai — pehle analogy

Class ek **naksha** hai. "Student" ka naksha socho — usme likha hai har student ke paas naam hoga, umar hoga, roll number hoga, aur `Print()` karne ka tareeka hoga. Naksha akele kuch nahi — koi kaam ka nahi. Par us naksha se jitne chaaho **objects** bana lo — har object (yaani har student) asli cheez hai, apne data ke saath.

Naksha = **Class**. Naksha se bana hua = **Object** (instance bhi kehte hain).

JS mein bhi yahi tha — `function Student()` = blueprint, `new Student()` = object. Bas C# mein syntax zyada explicit hai.

## Pehli class

```csharp
class Student
{
    // data (fields) — JS object ke properties jaisi
    string naam;
    int umar;
    int marks;

    // kaam (methods) — JS object ke methods jaisi
    void Print()
    {
        Console.WriteLine(naam + " | " + umar + " | " + marks);
    }
}
```

Ab use karo:

```csharp
// object banao — JS: const s = new Student()
Student s1 = new Student();
s1.naam = "Vin";      // object ke andar value daalo
s1.umar = 25;
s1.marks = 90;
s1.Print();            // Vin | 25 | 90

Student s2 = new Student();
s2.naam = "Rahul";
s2.umar = 26;
s2.marks = 85;
s2.Print();            // Rahul | 26 | 85
```

**Yehi fayda hai** — ek naksha, do objects, alag-alag data. `s1.naam` aur `s2.naam` ek doosre se independent hain (JS object wali feeling).

> Modern C#: `Student s1 = new Student();` ki jagah `Student s1 = new();` bhi chalta hai (target-typed new) — type left side pe already likha hai. Dono chalega, pehla wala zyada clear hai abhi.

## Constructor — object banate waqt data bhar do

Upar mein har object banake 3-3 line alag se likhni padi. **Constructor** se banate waar sab ho jaata hai:

```csharp
class Student
{
    string naam;
    int umar;
    int marks;

    // constructor — class ka naam, koi return type nahi
    public Student(string naam, int umar, int marks)
    {
        this.naam = naam;    // this = abhi ka object
        this.umar = umar;
        this.marks = marks;
    }

    void Print()
    {
        Console.WriteLine($"{naam} | {umar} | {marks}");
    }
}
```

```csharp
Student s1 = new Student("Vin", 25, 90);
Student s2 = new Student("Rahul", 26, 85);
s1.Print();
```

3 cheezein nayi:

1. **Constructor** — class ke naam wala method (`public Student(...)`), `new` karte hi apne aap chalta hai. Return type nahi hota (object khud ban raha hai).
2. **`this`** — "abhi jis object pe kaam ho raha hai". `this.naam = naam` ka matlab: object ka `naam` field bharo, andar wala `naam` parameter hai. JS ka `this` object ke liye tha — wahi, par zyada predictable (JS wala `this` ka drama yahan nahi).
3. **`public`** — access keyword, agla point:

## public kya hai (thoda module 2.2 ka teaser)

`public` ka matlab — bahar se koi bhi isko use kar sakta hai. Bina `public` likhe toh class ke **andar** hi tak simit rehta hai (default "private"). Abhi itna yaad rakho — **fields `public` kar do jab tak encapsulation nahi seekha**:

```csharp
class Student
{
    public string naam;    // bahar se set kar sakte ho
    public int marks;
}
```

Warna `s1.naam = "Vin"` pe error aayega. Detail agla file — encapsulation se fields ko secure karna.

## Ek complete program — Bank account

```csharp
// Program.cs
class Account
{
    public string owner;
    public double balance;

    public Account(string owner, double opening)
    {
        this.owner = owner;
        this.balance = opening;
    }

    public void Deposit(double amt)
    {
        if (amt <= 0) { Console.WriteLine("Galat amount"); return; }
        balance += amt;
        Console.WriteLine($"+{amt} → {balance}");
    }

    public void Withdraw(double amt)
    {
        if (amt > balance) { Console.WriteLine("Balance kam"); return; }
        balance -= amt;
        Console.WriteLine($"-{amt} → {balance}");
    }
}

// --- asli program ---
Account a1 = new Account("Vin", 1000);
a1.Deposit(500);        // 1500
a1.Withdraw(200);       // 1300
Console.WriteLine(a1.owner + ": " + a1.balance);
```

Dekho kya hua — data (`owner`, `balance`) aur uspe hone wale kaam (`Deposit`, `Withdraw`) **ek jagah** jude hue hain. Har account ka apna alag state. Yahi OOP ka core hai: **data + behaviour ek saath**.

JS comparison:

```javascript
// JS
const a1 = {
  owner: "Vin",
  balance: 1000,
  deposit(amt) { this.balance += amt; }
};
```

Wahi cheez, bas yahan blueprint class hai, type safe hai, aur badi team mein code organize rehta hai.

## Yeh kya NAHI hai

- **Class = object nahi hai** — class naksha hai, object usse bana hua. `Student` (class) ≠ `s1` (object).
- **`this` JS jaisa unpredictable nahi** — JS mein arrow vs normal function mein `this` badal jaata tha. C# mein `this` hamesha current object hai — koi drama nahi.
- **Har cheez class nahi hai** — chhote utilities (jaise `Math.Abs(5)`) classes ke bagair bhi chalte hain. Class tab banao jab **state + kaam** ek saath ho (Account, Student, Product).

</details>

</details>
