## MCQ

Q: Class aur Object ka sahi rishta kya hai?
A. Class hi object hota hai, naam farak hai
B. Class blueprint hai, object usse bana hua instance hai
C. Object blueprint hai, class usse bana instance hai
D. Dono ek doosre ko replace karte hain
> B. Class naksha hai (kya-kya hoga — fields, methods), aur `new` se banaye gaye objects uske asli instances hain jisme apna data hai. `Student` (class) ka ek se zyada `s1`, `s2` objects ho sakte hain.

---

Q: `s1.marks = -500` jaise seedha data badalne se bachne ke liye C# ka main pattern kya hai?
A. Public field sabse theek hai
B. Field ko private karke public property (get/set) dena jahan validation lage
C. Marks ko string bana dena
D. Class ko seal kar dena
> B. Encapsulation: field `private` (bahar ja hi nahi sakta), bahar sirf property ka raasta — jiske `set` mein validation hoti hai (`value` check karke). Isliye -500 kabhi andar nahi pahunchta.

---

Q: `Student : Person` likhne ka kya matlab hai?
A. Student ko Person ka koi faayda nahi
B. Person, Student se inherit karta hai
C. Student, Person se inherit karta hai — uske public/protected members use kar sakta hai
D. Dono class merge ho jaati hain
> C. Colon ke baad wala **parent/base** hai. `Student : Person` = Student child hai — Person ka code (fields, methods) reuse kar sakta hai, aur `base(...)` se parent ka constructor bhi call karta hai.

---

Q: Polymorphism chalne ke liye C# mein kya- kya chahiye?
A. Sirf method ka naam same hona chahiye
B. Parent mein `virtual`, child mein `override`
C. Dono classes `abstract` honi chahiye
D. Interface hona zaroori hai
> B. C# mein chup-chaap override nahi hota (JS jaisa nahi). Parent method `virtual` mark hoti hai, child `override` likhta hai. Tab run-time pe object ka sahi wala method chalta hai.

---

Q: Ek interface ke andar kya hota hai?
A. Poora code jo children ko milega
B. Sirf method/property ke signature (rule) — implementation nahi
C. Data fields aur constructor
D. Database query
> B. Interface contract hai — "jo implement kare usko ye methods hone chahiye". Body mostly nahi hoti, har implementer khud likhta hai. Isliye alag-alag families (Student, Product) ek sath ye rule le sakte hain.

---

Q: C# mein ek class kitni classes se inherit kar sakti hai?
A. Jitni chaaho
B. Do se zyada nahi
C. Sirf ek — par interfaces jitni chaaho
D. Zero — inheritance nahi hai
> C. C# single inheritance hai (ek parent class). Multiple capability ke liye interfaces lagti hain — `class M : Person, ISaveable, IComparable` chalega. Yahi interface ka asli faayda.

---

Q: `using System.Collections.Generic;` ka kya kaam hai?
A. NuGet package install karta hai
B. `List<>` jaise type ko bina poora naam (`System.Collections.Generic.List`) likhe use karne deta hai
C. Code ko compile karta hai
D. File save karta hai
> B. `using` namespace ke items ko short naam deta hai (JS `import` ke direction ke ulta — wahan aata hai, yahan se namespace "use" hota hai). Package install ka kaam NuGet ka hai, module 3 mein.

## TrueFalse

Q: `class Student : Address` inheritance ka sahi example hai kyunki student ke paas address hota hai.
- True
- False
> False. Yeh "has-a" relation hai — Student ke paas address hai, Student address *hai* nahi. Inheritance sirf "IS-A" ke liye (`Student : Person`). Has-a ke liye simple field lo (`Address address` field).

---

Q: Parent ki `private` field child class mein directly accessible hoti hai.
- True
- False
> False. `private` sirf usi class ke andar. Child ko chahiye toh parent `protected` use kare (class + children ke liye) ya public property dein. Encapsulation parent-child pe bhi lagti hai.

---

Q: `abstract class` ka seedha `new` se object banaya ja sakta hai jaise normal class ka.
- True
- False
> False. Abstract class aadhi incomplete hoti hai (abstract methods bina body) — uska object banane se compiler error. Usse sirf child classes ban sakti hain jo sab abstract methods implement kar dein.

---

Q: Interface mein fields (data) rakhe ja sakte hain.
- True
- False
> False. Interface sirf contract hai — method/property signatures. Andar data state rakhni ho toh class chahiye (ya interface ka default method sirf behaviour deta hai, field nahi).

---

Q: Ek file ke saare lamba code ko chhota-chhota methods mein todna encapsulation ka part hai aur production code mein standard practice hai.
- True
- False
> True. Chhote methods ka har ek ek kaam karte hain (single responsibility), padhne/test/fix mein aasan, aur doosre methods reuse kar sakte hain (jaise Average ne Sum ko). Yahi DRY + clean code ki practice hai.
