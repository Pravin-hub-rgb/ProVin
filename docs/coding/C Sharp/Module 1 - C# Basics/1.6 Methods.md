# Methods (Functions)

## Method banana — JS vs C#

JS mein:

```javascript
function namaste(naam) {
  return "Hello " + naam;
}
console.log(namaste("Vin"));
```

C# mein:

```csharp
string Namaste(string naam)
{
    return "Hello " + naam;
}

Console.WriteLine(Namaste("Vin"));
```

Pattern samjho — JS ki jagah ab **4 cheezein** likhni padti hain:

```csharp
ReturnType MethodName(parameters)
{
    // kaam
    return value;
}
```

1. **Return type** — method kya lautaega (`string`, `int`, `void` agar kuch nahi)
2. **Naam** — C# mein method ka naam **PascalCase** hota hai (`Namaste`, `GetTotal`) — JS mein `camelCase` tha. Convention strict hai, IDE auto bhi aisa hi likhega
3. **Parameters** — `(string naam)` — har param ka type likhna padta hai
4. **`return`** — wahi

> C# functions ko **methods** kehte hain (class ke andar rehte hain — module 2 mein). Bolte waqt "method" hi bolo, interview mein bhi yahi shabd chalega.

## void — kuch na lautane wala

```csharp
void Namaste(string naam)      // return type void
{
    Console.WriteLine("Hello " + naam);
    // return nahi chahiye — kuch de hi nahi rahe
}
```

JS mein function implicitly `undefined` deta tha. C# mein **saf-saf `void` likhna padta hai** — "ye method kuch nahi lautaega". Aur agar `void` likha toh `return "kuch";` error de dega.

Ek line wale methods (C# 10+ shorthands):

```csharp
int Add(int a, int b) => a + b;    // expression body — return chup-chaap
void Hi() => Console.WriteLine("Hi");
```

`=>` (fat arrow) — JS arrow function wali feeling, bas return type bahar likhi.

## Parameters vs arguments

```csharp
int Multiply(int a, int b)   // yeh PARAMETERS (naam hain)
{
    return a * b;
}

Multiply(4, 5);              // yeh ARGUMENTS (asli values)
```

Bas itna hi — interview mein dono shabd aate hain, fark jaan lo.

## Default parameters aur named arguments — JS wali sahulat

```csharp
void Greet(string naam, string salutation = "Namaste")   // = "..." = default
{
    Console.WriteLine(salutation + " " + naam);
}

Greet("Vin");                    // Namaste Vin — default use hua
Greet("Vin", "Hello");           // Hello Vin — override
Greet("Vin", salutation: "Hey"); // named — order matter nahi karta
```

`salutation = "Ji"` — JS mein `function greet(naam, sal = "Ji")` waise hi. Default wale **aakhir mein** hone chahiye (pehle required, phir default).

## Out — ek se zyada value wapas bhejna

JS mein kabhi array/object return karke "do values" manage karte the. C# mein **`out`** hai:

```csharp
void Divide(int a, int b, out int result, out int remainder)
{
    result = a / b;
    remainder = a % b;
}

Divide(17, 5, out int quotient, out int rem);   // 3, 2
Console.WriteLine($"{quotient} remainder {rem}");
```

`out` parameter ka matlab — method **andar bhar ke deta hai**. Call karte waqt `out` dobara likhna padta hai (ya `out int x` se seedha declare). Pehli baar weird lagta hai, par kabhi-kabhi 2 related values return karni ho (jaise `int.TryParse` mein tha na — success + number dono).

## Ref — reference pe kaam karna (optional)

```csharp
void Increment(ref int n)
{
    n = n + 1;    // asli variable badal raha hai
}

int count = 5;
Increment(ref count);   // count ab 6 — badla hua dikhega
```

`ref` = value copy nahi, **asli variable** ka reference. `out` se fark: `out` mein method ko value deni hi padti hai; `ref` mein dono taraf chal sakta hai. Basics mein kam aata hai — jaan lo, roz nahi.

## Recursive — khud ko bulana

```csharp
int Factorial(int n)
{
    if (n <= 1) return 1;         // base case — yahan rukna hai
    return n * Factorial(n - 1);  // khud ko call
}

Console.WriteLine(Factorial(5));   // 120
```

`5 * 4 * 3 * 2 * 1 = 120`. JS mein bhi same logic thi. **Base case zaroori** — warna stack overflow (C# mein bhi `StackOverflowException`).

## Early return — nested if ka dard khatam

Module 3 conditions mein nested if chhoda tha — ab function ke saath solution:

```csharp
// ❌ Deep nested if — padhne mein mushkil
void Process(int umar, bool loggedIn)
{
    if (loggedIn)
    {
        if (umar >= 18)
        {
            Console.WriteLine("Chalega");
        }
    }
}

// ✅ Early return — pehle galat case ko bhagao
void Process(int umar, bool loggedIn)
{
    if (!loggedIn) { Console.WriteLine("Login karo"); return; }
    if (umar < 18)  { Console.WriteLine("Bachcha"); return; }

    Console.WriteLine("Chalega");   // saaf-saaf last line
}
```

Har guard clause (`if (...) return;`) ke baad function chhota saaf hota jaata hai. Production code ka sabse aam pattern hai — ise hi "early return" bolte hain.

## Scope — JS wala `{}`

```csharp
int x = 10;
if (true)
{
    int y = 20;
    Console.WriteLine(x + y);   // ✅ bahar wala andar dikh raha hai
}
Console.WriteLine(y);           // ❌ y bahar nahi jaanta — error
```

JS wala block scope (`let`/`const` wala) yahi hai. Andar banaya bahar gayab. Function ke andar ke variables function ke bahar nahi jaate.

## Ek complete program — sab methods mein

```csharp
// Program.cs
int ReadNumber(string prompt)
{
    Console.Write(prompt);
    return int.Parse(Console.ReadLine());
}

int Sum(List<int> numbers)
{
    int total = 0;
    foreach (int n in numbers) total += n;
    return total;
}

double Average(List<int> numbers)
{
    if (numbers.Count == 0) return 0;      // guard — 0 se divide nahi
    return (double)Sum(numbers) / numbers.Count;   // doosra method reuse!
}

void Report(List<int> numbers)
{
    Console.WriteLine($"Count: {numbers.Count}");
    Console.WriteLine($"Sum: {Sum(numbers)}");
    Console.WriteLine($"Avg: {Average(numbers):F2}");
}

// --- ab asli program (3 line) ---
List<int> marks = new List<int>();
int n = ReadNumber("Kitne marks: ");
for (int i = 0; i < n; i++) marks.Add(ReadNumber($"Mark {i + 1}: "));
Report(marks);
```

Dekho kya hua — input ka kaam ek method, maths ka method, report ka method, aur **asli program sirf 3 line** ka. `Average` ne `Sum` ko call kiya (methods ek doosre ko use kar sakte hain). Yahi structure companies mein hota hai — sab lamba code chhota-chhota methods mein tootta hai.

Yeh kya NAHI hai:

- **Method name JS jaisa camelCase nahi** — C# mein method/class PascalCase (`GetTotal`), parameters camelCase (`firstNumber`). Convention follow karo, IDE bhi wahi expect karta hai.
- **`void` wale mein return value nahi** — `return 5;` error. Aur non-void method mein har raaste pe return hona chahiye (compiler check karta hai).
- **Functions "kuch bhi" pass nahi karte** — har parameter ka type fixed. JS ki tarah koi bhi cheez (number bhi, string bhi) ek parameter mein nahi jaayegi.

## In Your Own Words

1. JS function aur C# method likhne mein 4 structural fark batao.

<details>
<summary>Sample Jawab</summary>

**Jawab:** (1) Return type likhna padta hai (`void` agar kuch nahi), (2) naam PascalCase hota hai, (3) har parameter ka type mandatory, (4) implicit undefined nahi — `return`/`void` saf-saf. Arrow functions bhi hain (`=>`) par return type phir bhi bahar likhti hai.

</details>

2. `out` parameter kis scene mein kaam aata hai — `int.TryParse` ke example ke saath samjhao.

<details>
<summary>Sample Jawab</summary>

**Jawab:** Jab ek se zyada related values wapas bhejni hon. `int.TryParse("42", out int n)` mein method do cheezein deta hai — success (bool) seedha return mein, aur parsed number `out n` ke through. Method ke andar value "bhar ke" deta hai.

</details>

3. "Early return" pattern kya hai aur kyun use karte hain?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Galat/early conditions pe turant `return` kar dena, taaki baaki kaam nest na ho. `if (!loggedIn) return;` — aage ka code sirf tab chalta hai jab sab sahi ho. Isse code chhota, padhne mein aasan, aur bug kam hote hain.

</details>

4. `Average` method ne `Sum` ko kyun call kiya — isme kya fayda hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Total ka logic ek jagah likha (`Sum`), use do jagah kaam aaya — average bhi isi se bana. Isse duplicate code nahi hota (DRY) aur agar total ka logic badalna ho toh ek hi jagah change karna padta hai.

</details>
