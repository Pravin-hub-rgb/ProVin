# Arrays and Lists

## Array — the fixed-size box

```csharp
string[] naam = { "Vin", "Rahul", "Sara" };   // 3 names, one array
int[] marks = { 90, 85, 78, 92 };             // 4 marks

Console.WriteLine(naam[0]);      // Vin — starts at ZERO (like JS)
Console.WriteLine(marks[2]);     // 78
Console.WriteLine(naam.Length);  // 3 — total count (JS: length)
```

Syntax breakdown:

- `string[]` = "array of string" — `[]` after the type. `int[]` = array of int.
- `{ ... }` = initial values directly.
- Index starts at **0**, access with `[]`, count with `.Length` — all like JS.

**One big difference — the size is fixed:**

```csharp
int[] marks = new int[3];    // 3 slots, all 0 at start
marks[0] = 90;
marks[1] = 85;
marks[2] = 78;
marks[3] = 95;    // ❌ IndexOutOfRangeException — no room!
```

In JS, `arr.push()` grew the array automatically. A C# array has its **size fixed at creation** — it won't grow later. So when you don't know the size or it keeps growing, use not an array but a **List**.

One more thing: in `new int[3]` all ints are **initialized to 0** (in JS it was `undefined`). Strings become `null`. C# fills in the default value itself.

## List — the growing box (this is what you'll use daily)

```csharp
using System.Collections.Generic;   // top of file — List lives here

List<int> marks = new List<int>();   // empty list, free size

marks.Add(90);                       // add (like push)
marks.Add(85);
marks.Add(78);

Console.WriteLine(marks.Count);      // 3 — Count, not length!
Console.WriteLine(marks[0]);         // 90 — same [] indexing

marks.Remove(85);                    // remove by value
marks.RemoveAt(0);                   // remove at index 0
bool hai = marks.Contains(78);       // true
```

`List<T>` — `T` is your type. `List<string>` = string list, `List<int>` = int list. This is the first glimpse of **generics** (details in module 3; for now just: write the type inside `<>`).

Summary of the difference:

| | Array (`int[]`) | List (`List<int>`) |
|---|---|---|
| Size | fixed at creation | grows and shrinks |
| Growing | ❌ no | `Add()` |
| Count | `.Length` | `.Count` |
| Speed | a bit faster | negligible difference |
| When | size known (always 7 days) | size unknown (how many items will the user enter) |

In day-to-day work **List is the default** — use an array only when the size is constant.

## Looping over a List

```csharp
List<string> city = new List<string> { "Dehradun", "Delhi", "Mumbai" };

foreach (string c in city)
{
    Console.WriteLine(c);
}
```

`foreach` + `List` = the most common pair. When you need the index:

```csharp
for (int i = 0; i < city.Count; i++)
{
    Console.WriteLine($"{i}: {city[i]}");
}
```

## List's useful methods (you'll need them daily)

```csharp
List<int> n = new List<int> { 3, 1, 4, 1, 5 };

n.Sort();              // 1, 1, 3, 4, 5 — in-place sort
n.Reverse();           // 5, 4, 3, 1, 1
int idx = n.IndexOf(4); // 2 — where it was found (-1 = not found)
n.Clear();             // empty everything

int total = n.Count;   // now 0
```

And one powerful thing — **a small box inside a big one** (nested):

```csharp
List<List<int>> table = new List<List<int>>
{
    new List<int> { 1, 2, 3 },
    new List<int> { 4, 5, 6 }
};

Console.WriteLine(table[1][2]);   // 6 — first row, then column
```

A JSON array-of-arrays looks exactly like this — when you fetch data, you'll get it this way.

## Common mistakes (habits carried over from JS)

```csharp
List<int> marks = new List<int> { 90, 85 };

// 1. Writing .length
Console.WriteLine(marks.length);   // ❌ in C# it's .Length/.Count — lowercase doesn't work

// 2. Treating it like an array (List only)
int[] arr = { 1, 2, 3 };
arr.Add(4);                        // ❌ arrays don't have Add

// 3. Type mismatch
List<int> nums = new List<int> { 1, 2, "teen" };  // ❌ string not allowed

// 4. Accessing empty space
Console.WriteLine(marks[10]);       // ❌ exception — in JS it was undefined, here crash
```

Point 4 — remember: in JS `arr[10]` quietly gave `undefined`; in C# it **throws an exception**. So checking `Count` before accessing is a good habit:

```csharp
if (idx < marks.Count)
{
    Console.WriteLine(marks[idx]);
}
```

## One complete program — student report card

```csharp
// Program.cs
List<int> marks = new List<int>();

Console.Write("Kitne subjects: ");
int count = int.Parse(Console.ReadLine());

for (int i = 1; i <= count; i++)
{
    Console.Write($"Subject {i} ka marks: ");
    marks.Add(int.Parse(Console.ReadLine()));   // straight into the list
}

marks.Sort();                     // small to big
int min = marks[0];
int max = marks[marks.Count - 1];  // last = biggest (sorted)

int total = 0;
foreach (int m in marks) total += m;
double avg = (double)total / marks.Count;

Console.WriteLine($"Min: {min}, Max: {max}, Avg: {avg:F2}");
Console.WriteLine($"Sabse kam wale top 3: {string.Join(", ", marks.GetRange(0, Math.Min(3, marks.Count)))}");
```

`marks.Count - 1` — the index of the last element (one less than the count, since it starts at 0). `:F2` is formatting — up to 2 decimals. Loop + list + condition, all together.

What this is NOT:

- **Arrays don't have `Add()`** — an array is fixed; only a List grows. This confusion is the most common mistake.
- **It's `.Count`, not `.length`** (for Lists). For arrays it's `.Length`. Capitalization matters.
- **Out of bounds = exception** — there's no JS-style `undefined` peace. Check the size before accessing.

## In Your Own Words

1. Array vs List — which would you use and why; state three differences.

<details>
<summary>Sample Answer</summary>

**Answer:** Use an array when the size is fixed beforehand (a 7-day calendar) — `int[]`. Use a List when the size is unknown/will grow (how many marks the user enters) — `List<int>` with `Add()`. Differences: size, `.Length` vs `.Count`, and you can't grow an array.

</details>

2. What happens inside `new int[3]`, and what did the same work give in JS?

<details>
<summary>Sample Answer</summary>

**Answer:** C# fills all three slots with 0 (int's default). In JS the array had holes/undefined — `arr[0]` had no value right away. C# always gives a default value so you never get an uninitialized one.

</details>

3. `marks[10]` when the list has only 3 items — what happens in C# vs JS?

<details>
<summary>Sample Answer</summary>

**Answer:** In C# an IndexOutOfRangeException — the program crashes. In JS you quietly got `undefined`. That's why in C# you must check `idx < marks.Count` before accessing.

</details>

4. What does the nested list `table[1][2]` mean?

<details>
<summary>Sample Answer</summary>

**Answer:** `table[1]` = the second inner list (row 2), and its `[2]` = the third element of that row. The two brackets are at different levels — first the outer box, then the inner one.

</details>
