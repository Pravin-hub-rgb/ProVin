In the previous file you made variables — but everything was hardcoded, written as `umar = 25`. A real program is the one that asks the user for something. In JS you had `prompt()` or browser input; in the C# console world the simplest way is `Console.ReadLine` — and then calculations with operators on that input.

# Input and Operators

## Taking input from the user

```csharp
// Program.cs — first interactive program
Console.Write("Apna naam batao: ");       // prints on the same line
string naam = Console.ReadLine();          // user types and presses Enter

Console.Write("Umar batao: ");
string umarText = Console.ReadLine();      // input is always a STRING!

Console.WriteLine("Namaste " + naam + ", tum " + umarText + " saal ke ho.");
```

```bash
dotnet run
```

```
Apna naam batao: Vin
Umar batao: 25
Namaste Vin, tum 25 saal ke ho.
```

Understand the 3-line scheme:

1. `Console.Write` — doesn't add a line break (the cursor stays put), so you can print the prompt right alongside. The `Line` in `Console.WriteLine` = a new line after.
2. `Console.ReadLine()` — takes the user's input **paused** (until Enter is pressed) and **always returns a string**. JS's `prompt()` also returned a string — same habit.
3. String + string = joining — the `+` work from JS.

> **Note:** `Console.ReadLine()` can return null if the input stream closes (Ctrl+Z) — ignore it for now; during normal runs you get a string.

## Is the input a number? (here the difference from JS shows)

In the program above, `umarText` is a **string** — "25". If you want to calculate, you have to pause:

```csharp
Console.Write("Umar batao: ");
int umar = int.Parse(Console.ReadLine());   // "25" → 25 — now it's a number

Console.WriteLine("Saalon mein mahine: " + umar * 12);   // 300
```

`int.Parse` turned the string into a number. Now `umar * 12` is real multiplication.

**Warning:** if the user typed "bees", `int.Parse` will throw an exception and the program will die. For such user input there's a safer version:

```csharp
string text = Console.ReadLine();
if (int.TryParse(text, out int umar))     // did it parse?
{
    Console.WriteLine("Mahine: " + umar * 12);
}
else
{
    Console.WriteLine("Number likho bhai!");
}
```

`TryParse` returns a boolean — if it succeeded, `true` + the value (the value lands in `out int umar`), otherwise `false` + no crash. You know `if`, details in the next file — for now just remember: **user input = string → number via Parse/TryParse.**

## Operators — all the JS ones

The math ones are exactly the same:

```csharp
int a = 10, b = 3;
Console.WriteLine(a + b);   // 13
Console.WriteLine(a - b);   // 7
Console.WriteLine(a * b);   // 30
Console.WriteLine(a / b);   // 3 !!! — not 3.33, 3
Console.WriteLine(a % b);   // 1 — modulus (leftover value)
```

**One place it differs from JS:** `10 / 3` gave `3.33` in JS (everything was number). In C#, `int / int = int` — the decimal part gets cut off. Want decimals? Make one of them a double:

```csharp
Console.WriteLine((double)a / b);   // 3.333333...
```

This is the mistake that happens most often — remember it.

**Comparison ones** are the same too: `==`, `!=`, `<`, `>`, `<=`, `>=` — and their result is a `bool` (`true`/`false`), which plugs straight into a condition.

**Logical:** `&&` (AND), `||` (OR), `!` (NOT) — just like JS:

```csharp
bool eligible = umar >= 18 && umar <= 60;   // both conditions must be true
```

## Compound assignment — small shortcuts

```csharp
int count = 0;
count = count + 1;    // long
count += 1;           // same work — write this
count -= 2;           // count = count - 2
count *= 3;           // count = count * 3
count++;              // +1 shortcut (like JS), count-- too
```

All exactly JS-style. Used every day.

## Small tips for string operators

```csharp
string a = "Hello";
string b = "World";

Console.WriteLine(a + " " + b);     // Hello World — + joins
Console.WriteLine(a.Length);         // 5 — property (like JS .length)
Console.WriteLine(a.ToUpper());      // HELLO — method (JS: toUpperCase())
Console.WriteLine(a.Contains("ell")); // true (JS: includes)
Console.WriteLine($"Aap {a}, kitne? {a.Length}");  // string interpolation ⭐
```

**String interpolation** (`$"..."`) — C#'s prettiest trick. The exact equivalent of JS's template literal (backtick):

```javascript
// JS
console.log(`Hello ${name}, you are ${age}`);
```

```csharp
// C#
Console.WriteLine($"Hello {name}, you are {age}");
```

The only difference is the `$` before the `"`. Use this style in daily work — joining with `+` gets messy fast.

## One complete small program tying it all together

```csharp
// Program.cs — bill calculator
Console.Write("Item ka price batao: ");
int price = int.Parse(Console.ReadLine());

Console.Write("Kitne quantity: ");
int qty = int.Parse(Console.ReadLine());

int total = price * qty;
int discount = total / 10;        // 10% discount (integer maths)
int final = total - discount;

Console.WriteLine($"Price: {price} x {qty} = {total}");
Console.WriteLine($"Discount (10%): -{discount}");
Console.WriteLine($"Final bill: {final}");
```

Input, parse, maths, compound logic, interpolation — all in one. Run it and check.

What this is NOT:

- **`Console.ReadLine()` doesn't give a number** — always a string. If you need a number you must Parse (just like JS's `prompt()`).
- **`/` doesn't always divide the way you think** — int/int gives a floor value. Want decimals? Cast with `(double)`.
- **`=` and `==` are different** — `=` is assignment, `==` is comparison. In C#, writing it wrong gives a compiler error (`=` doesn't work in a condition — no silent mistake like JS).

## In Your Own Words

1. What do `Console.ReadLine()` and `Console.Write` do, line by line, and how do they differ from `WriteLine`?

<details>
<summary>Sample Answer</summary>

**Answer:** `ReadLine()` takes a line of input from the user and always returns a string. `Write` prints without a line break; `WriteLine` prints and then moves the cursor to the next line (print + newline).

</details>

2. What must you do before multiplying the user-entered string "25" by 12 — and what's the safe version?

<details>
<summary>Sample Answer</summary>

**Answer:** First convert the string to an int — `int.Parse("25")`. But on bad input this throws an exception, so the safe version is `int.TryParse(text, out int n)`, which returns `true/false` without crashing.

</details>

3. Why doesn't `10 / 3` give 3.33 in C#, and how do you get the real decimal result?

<details>
<summary>Sample Answer</summary>

**Answer:** Because both are `int` and int/int gives an int (the decimal part is cut off). To get decimals, at least one operand must become a double: `(double)10 / 3` → 3.33.

</details>

4. What's the difference between a JS template literal and C# string interpolation — with syntax?

<details>
<summary>Sample Answer</summary>

**Answer:** JS: backticks with `` `Hello ${name}` ``. C# (modern): `$"Hello {name}"` — `$` before the quotes, no `${}`, just `{}`. Both do the same job — filling a variable into text.

</details>
