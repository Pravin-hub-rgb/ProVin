In the conditions file you saw the program can decide which path to take — but if you have to print 10 students' marks, will you write `Console.WriteLine` 10 times? Absolutely not. For doing the same work over and over there are **loops** — and JS's `for`, `while`, `foreach` all exist in C#.

# Loops — for, foreach, while

## for loop — the counting one

```csharp
for (int i = 1; i <= 5; i++)
{
    Console.WriteLine("Line " + i);
}
```

```
Line 1
Line 2
Line 3
Line 4
Line 5
```

The three parts are exactly the JS ones:

1. `int i = 1` — start (created the counter)
2. `i <= 5` — keep going while this is true
3. `i++` — +1 after every round

One round = one **iteration**. The only difference is that you had to write the counter's type (`int i`); otherwise it's copy-paste from JS.

## foreach — over every item of a list

```csharp
string[] naam = { "Vin", "Rahul", "Sara" };

foreach (string n in naam)
{
    Console.WriteLine(n);
}
```

`for (item in collection)` — this is JS's `for...of`. Every element of the array/list comes into `n` one at a time. In C#, when you only need to traverse, `foreach` is often preferred — use `for` when you need the index.

## while — while the condition is true

```csharp
int i = 1;
while (i <= 5)
{
    Console.WriteLine("Line " + i);
    i++;          // ❗ you have to arrange the way out yourself
}
```

The difference between `for` and `while`: in `for` the counter's whole control is visible in one place (start-check-increment); in `while` there's only the condition — you manage the counter yourself. So **forget `i++` and you get an infinite loop** — the program keeps spinning (you have to stop it with Ctrl+C). This mistake happens less in `for`.

When to use `while`: when you don't know the count in advance, until the user says something:

```csharp
string input = "";
while (input != "exit")
{
    Console.Write("Command (band karne ke liye exit): ");
    input = Console.ReadLine();
    Console.WriteLine("Tumne likha: " + input);
}
```

Here you don't know how many rounds will run — so `while` is the right choice.

## do-while — at least once

```csharp
int ch;
do
{
    Console.Write("1-2-3 chuno: ");
    ch = int.Parse(Console.ReadLine());
} while (ch < 1 || ch > 3);
```

The difference: in `while` the check happens first, in `do-while` **it runs once first, then checks**. Perfect for menu scenes — the user must give input at least once.

## break and continue — controlling the loop

```csharp
// break — end the loop entirely
for (int i = 1; i <= 100; i++)
{
    if (i == 6) break;        // stops at 6
    Console.WriteLine(i);      // prints 1..5
}

// continue — skip this round, take the next
for (int i = 1; i <= 5; i++)
{
    if (i == 3) continue;      // skips the round for 3
    Console.WriteLine(i);      // 1,2,4,5
}
```

`break` = the whole loop ends. `continue` = skip just this iteration, start the next. Exactly like JS.

## Nested loops — one inside another

```csharp
// 5x5 box
for (int i = 0; i < 5; i++)
{
    for (int j = 0; j < 5; j++)
    {
        Console.Write("* ");
    }
    Console.WriteLine();   // new line after each row
}
```

```
* * * * *
* * * * *
* * * * *
* * * * *
* * * * *
```

The outer loop runs the rows, the inner runs the columns of that row. Table/chessboard/pattern programs are built from this. Understand the cost — 5x5 = 25 iterations; if both go to 100, that's 10,000 — nested loop time **multiplies**, it doesn't add.

## Avoiding infinite loops

```csharp
int i = 0;
while (true)          // condition always true
{
    Console.WriteLine(i);
    i++;
    if (i > 10) break;   // ❗ there must be a way out
}
```

`while (true)` is used on purpose too (server loops, etc.) — but there must be a `break` or return inside. Forget it and it's Ctrl+C.

## One complete program — FizzBuzz

```csharp
// 1 to 15: multiple of 3 → Fizz, of 5 → Buzz, of both → FizzBuzz
for (int i = 1; i <= 15; i++)
{
    if (i % 3 == 0 && i % 5 == 0)
        Console.WriteLine("FizzBuzz");
    else if (i % 3 == 0)
        Console.WriteLine("Fizz");
    else if (i % 5 == 0)
        Console.WriteLine("Buzz");
    else
        Console.WriteLine(i);
}
```

`%` + loop + condition — all of module 1's pieces together. Good practice; run it today.

What this is NOT:

- **`for`'s syntax is like JS but the type is mandatory** — you need `for (int i = 0; ...)`, `for (i = 0; ...)` won't run (C# doesn't accept an undeclared variable).
- **You can't change the item inside `foreach`** — `foreach (var n in arr) { n = "x"; }` is an error. It's its own copy. Use `for` if you need to change.
- **Forgetting `i++` in `while` = infinite loop** — the compiler won't stop you, the condition stays true forever. After writing a loop, always think "how do I get out?"

## In Your Own Words

1. When should you use `for` vs `while` — with one example each?

<details>
<summary>Sample Answer</summary>

**Answer:** Use `for` when you know the count (1 to 10) — counter, check, increment all in one place. Use `while` when you don't know (until the user says "exit") — but then you manage the counter/arrangement yourself.

</details>

2. What's the difference between `break` and `continue` — explain with output.

<details>
<summary>Sample Answer</summary>

**Answer:** `break` ends the whole loop (no more iterations). `continue` skips the current iteration and starts the next — the loop keeps running. Like in a 1-5 loop, `continue` on `i==3` skips 3 but 4,5 still come; `break` stops at 3.

</details>

3. How does a nested loop's time grow — how many iterations in a 10x10 loop?

<details>
<summary>Sample Answer</summary>

**Answer:** The outer runs 10 times and the inner runs 10 times each time — total 10x10 = 100 iterations. So iterations multiply; if it became 100x100, that's 10,000.

</details>

4. Why is `do-while` different from `while` — in which scene would you prefer it?

<details>
<summary>Sample Answer</summary>

**Answer:** In `while` the condition is checked first (could run 0 times); in `do-while` the body runs once first, then the check. Like a menu — the user must be shown it at least once, so `do-while`.

</details>

Loops let you do the same thing many times — but always with the same variable (`i`). Now you need a box that holds **many things** at once — arrays and lists.
