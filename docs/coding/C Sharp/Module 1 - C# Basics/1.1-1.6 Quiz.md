## MCQ

Q: What does `int` do in `int umar = 25;`?
A. It prints the variable
B. It tells the compiler this box only holds whole numbers
C. It converts the value to a string
D. It runs a loop
> B. In C#, the type (here `int`) is the box's label — the compiler knows up front that only an int will go in, and if you write a wrong value (string) it stops before running.

---

Q: How is C#'s `var naam = "Vin";` different from JS's `var naam = "Vin";`?
A. `var` doesn't work in C#
B. C#'s is dynamic — you can put a number in later
C. C#'s only hides the type — the compiler infers the type from the value, and that type stays fixed
D. JS hid the type, C# doesn't
> C. C# `var` = don't write the type, I'll figure it out from the value (`var x = 5` → int). Once the type is fixed, you can't put a wrong type in. JS `var` was dynamic (anything went).

---

Q: What does `10 / 3` give in C# when both are `int`?
A. 3.3333
B. 3
C. 4
D. Compile error
> B. int/int gives an int — the decimal part gets cut off (floor). If you want decimals, you have to convert, e.g. `(double)10 / 3`. In JS everything was number so you got 3.33.

---

Q: What does `Console.ReadLine()` return?
A. Whatever was typed — number stays number
B. Always a string, no matter what the user typed
C. A number only, crashes on bad input
D. A boolean
> B. `Console.ReadLine()` always returns a string (like JS's `prompt()`). If you need a number, you convert with `int.Parse()` or `int.TryParse()`.

---

Q: Between C#'s `List<int>` and `int[]` array — which should you default to and why?
A. Always the array — it's faster
B. List — because it can grow and you can add items with `Add()`
C. Both are the same, just different names
D. List is only for strings
> B. An array's size is fixed when created — accessing `arr[3]` throws. A List grows via `Add()`/`Remove()`, so when you don't know the size, List is the default choice. `int[]` is for when the size is constant.

---

Q: What naming convention are C# methods written in?
A. camelCase (`getTotal`) — like JS
B. PascalCase (`GetTotal`)
C. snake_case (`get_total`)
D. Anything goes, it doesn't matter
> B. In C#, methods and classes are PascalCase (`GetTotal`, `Customer`), parameters/variables are camelCase (`firstNum`). The compiler doesn't enforce it but the whole community/IDE follows it.

---

Q: What does `void Calculate(int a)` mean?
A. The method always returns 0
B. The method returns nothing — it just does the work
C. The method is stored only in void
D. The method's name is void
> B. `void` means an empty return type — like a JS function without `return` giving `undefined`. Such methods do work (print, write to file) but bring no value back.

## TrueFalse

Q: In C#, `if (umar)` runs because 0 is treated as false (JS-style truthy-falsy).
- True
- False
> False. C# needs a strictly boolean in the condition — if `umar` is an int it won't run directly. You have to write an explicit comparison like `if (umar > 0)`. JS's truthy-falsy convention doesn't exist in C#.

---

Q: In C# `switch`, if you don't write `break` after a `case`, the next case falls through (like JS).
- True
- False
> False. In C#, `break` (or `return`/`throw`) is mandatory — the compiler gives an error. JS's silent fall-through bug possibility is eliminated at compile time here.

---

Q: `marks[10]` when the list has only 3 items — in C# the program keeps running and gives `undefined`.
- True
- False
> False. C# throws an IndexOutOfRangeException and the program crashes. JS quietly gave `undefined` — which is why in C# you must check `idx < Count` before accessing.

---

Q: You can change an item's value inside a `foreach` loop (`n = "x"`) in C#.
- True
- False
> False. What `foreach` gives you is its own copy (mostly) — changing it gives an error. If you need to change values, use an index-based `for` loop.

---

Q: Writing the `Sum` logic once and reusing it in `Average` is better than duplicate code — because the change only has to be made in one place.
- True
- False
> True. This is the DRY (Don't Repeat Yourself) principle. `Average` calls `Sum` — the total logic lives in a single place. If it needs changing, you change one file/line, no re-duplication.
