You've run your first C# program — `Console.WriteLine`, string, int, you've seen a bit of everything. Now the same work you did first when learning JS: keeping data in variables. `const naam = "Vin"` was fine in JS, but in C# you have to think a bit more — because here every thing's **type** has to be stated.

# Variables and Types

A **variable** means the same as in JS — a named box that holds a value. The difference is that in C#, when you make the box, you also have to say what the box is for:

```csharp
string naam = "Vin";    // text box
int umar = 25;          // whole-number box
bool active = true;     // true/false-only box
```

The pattern is always the same: `type name = value;`. In JS you wrote `const`/`let`; here you write the type — because C#'s compiler wants to know up front what kind of box this is, and it'll keep track afterwards.

## Why you have to write the type — remember JS's little pain

In JS this all happened and sometimes silently went sideways:

```javascript
let x = 5;
x = "paanch";     // JS: no problem... but conceptually wrong
x + 1             // "paanch1" — string join! no error
```

TypeScript stopped this, right — and that same tension is already built into C#. In C#:

```csharp
int x = 5;
x = "paanch";     // error CS0029 — compiler stopped it up front
x + 1             // always number addition — no string/number confusion
```

**The TypeScript feel, but at compiler level.** This "strictness" is what you'll feel in daily work — a red line the moment you write the mistake, no need to run.

## C#'s main types (the everyday list)

In JS you had `number`, `string`, `boolean`, `object`, `array` — that's it. C# has a few more because numbers come in boxes of different sizes:

```csharp
// Numbers
int umar = 25;                 // whole number (integer) — one part of JS's number
double salary = 45000.50;      // decimal number — like JS's number
long badaNumber = 1234567890L; // very large integer

// Text
string naam = "Vin";           // "" or '' both work
char ekAkshar = 'V';           // only ONE character — single quotes!

// True/False
bool active = true;            // like JS, just called 'bool'

// Special
int? kuchNahi = null;          // "maybe int" — add ? to allow null
```

Pay attention to two things:

- **`char`** is for a single character with single quotes (`'V'`), `string` uses double quotes. In JS single/double were the same; here the type differs.
- **`null`** won't work directly as `int x = null;` — because `int` is a *value type*, there's no room for null in it. That's why you write `int?` ("maybe int"). `string s = null;` works because string is a *reference type*. Remember this much for now — "type with `?` = null can live inside too".

## var — hiding the type (for your JS habit)

If writing the type everywhere feels heavy, C# gives a small trick:

```csharp
var naam = "Vin";      // compiler figures it out itself — string
var umar = 25;         // — int
var active = true;     // — bool
```

**`var` ≠ JS's `var`.** The JS one was like a garbage can (function scope, redeclare later). C#'s `var` only means "don't write the type, I'll see for myself" — the type inside is fixed, you can't do `var naam = 5;` later. So it's **inferred**, not **dynamic**.

> In practice: use `var` with literal values (like `var list = new List<string>();`), and write the type for obvious things. Most teams prefer writing the type — the reader immediately knows what's going on.

## const — same as before

```csharp
const int MaxSeats = 100;   // assign once, can't change after
```

Same as JS's `const` — the value is fixed. The difference: in C#, `const` only works for compile-time constants (values known right when you write the line, like `100`, `"abc"`). For objects, `readonly` is used (module 2). For now, `const` = fixed value, that's it.

## Type conversion — the biggest behavior shift from JS

In JS, `"5" + 1` became a string join, right? Nothing like that happens in C# — if types get mixed, either the compiler gives an error, or you have to **explicitly** say so:

```csharp
// String → Number (like parseInt/Number, but typed)
int n = int.Parse("42");          // "42" → 42, throws exception if text is wrong
int n2 = Convert.ToInt32("42");   // a slightly more forgiving version

// Number → String
string s = 42.ToString();         // 42 → "42"

// int → double (safe widening — happens silently)
int pura = 45;
double decimalWala = pura;        // 45 → 45.0, no error
```

**Rule of thumb:** converting to the safe side happens silently (int → double); on the risky side (string → int, double → int) you have to say it. Write `int.Parse("hello")` and the program throws an exception while running — parsing can go wrong, so for user input there's a safer version like `TryParse` (in later files).

What this is NOT:

- **`var` is not dynamic** — you can't put anything in it like JS's `var`/`let`. Once the type is fixed, it stays that way.
- **Type names aren't capitalized** — `string`, `int`, `bool` are all lowercase, but members like `.ToString()`, `.Length` are capitalized. The convention is strict in C#.
- **There's no JS-style `number`** — in JS every number was one type; in C# `int`, `double`, `long`, `float` are separate. Pick the wrong box and the compiler will tell you.

One small complete example tying it all together:

```csharp
// Program.cs
var naam = "Vin";              // string (inferred)
int umar = 25;                 // int
double salary = 45000.50;      // double
bool courseReady = true;        // bool

// type conversion + joining
string message = naam + " ki salary " + salary + " hai";  // + auto-makes string
int doublesUmar = umar * 2;    // number maths

Console.WriteLine(message);    // Vin ki salary 45000.5 hai
Console.WriteLine(doublesUmar); // 50
Console.WriteLine(naam.Length); // 3 — string's property (like JS)
```

Run it with `dotnet run` — the output should be correct.

## In Your Own Words

1. In C# you have to write the type when making a variable — explain the benefit over JS with an example.

<details>
<summary>Sample Answer</summary>

**Answer:** In JS, `let x = 5; x = "paanch";` ran and later `"paanch" + 1`-style mistakes showed up. In C#, `int x = 5; x = "paanch";` gives a compiler error up front — the mistake is caught before running, so fewer bugs reach production.

</details>

2. C#'s `var` and JS's `var` — are they the same? Explain the difference.

<details>
<summary>Sample Answer</summary>

**Answer:** No. JS's `var` was function-scoped, could be reassigned, and could hold anything (dynamic). C#'s `var` only hides the type — the compiler infers the type from the value, and once fixed you can't put a wrong type in. So it's inferred-static, not dynamic.

</details>

3. Why do you have to write `int?` — why doesn't `int x = null;` work?

<details>
<summary>Sample Answer</summary>

**Answer:** `int` is a value type — the value lives directly in memory, there's no room for null. `int?` tells the compiler this is a "maybe int" (nullable), so null can live inside. That's why nullable value types need the `?`.

</details>

4. Write two ways to turn `"42"` into an int, and what happens with `int.Parse("hello")`.

<details>
<summary>Sample Answer</summary>

**Answer:** `int.Parse("42")` or `Convert.ToInt32("42")`. With `int.Parse("hello")`, parsing fails and it throws an exception at runtime (FormatException) — that's why safer `int.TryParse` is used for uncertain input.

</details>
