In the previous file you built a bill calculator — but it had only one path: input → maths → print. A real program thinks: if there's a discount, do this; otherwise do that. You already know `if`/`else`/`switch` from JS — in C# it's all the same, just a bit stricter.

# Conditions — if, else, switch

## if / else — exactly like JS

```csharp
Console.Write("Umar batao: ");
int umar = int.Parse(Console.ReadLine());

if (umar >= 18)
{
    Console.WriteLine("Vote de sakte ho!");
}
else
{
    Console.WriteLine("Abhi nahi.");
}
```

Look at the syntax — the braces `{}` are always mandatory (in JS you could skip them on a single line; here you can't), the condition goes in `( )`, and inside goes any expression that gives a boolean. `umar >= 18` is a boolean, so it runs directly.

Multiple conditions:

```csharp
if (umar < 13)
{
    Console.WriteLine("Bachcha");
}
else if (umar < 60)
{
    Console.WriteLine("Adult");
}
else
{
    Console.WriteLine("Senior");
}
```

`else if` — exactly the JS one, order matters (the first match wins, the rest are skipped).

## How a condition becomes "true" — C# is stricter

In JS, `if (umar)` ran (truthy/falsy — 0, "", null all false). In C#, **the condition needs a boolean, directly**:

```csharp
int umar = 0;
if (umar)           // ❌ ERROR — can't put an int into a bool
{
}

if (umar != 0)      // ✅ — write the boolean explicitly
{
}
```

This is the first shock for JS devs. C# doesn't say "0 is just false" — it says "write a condition whose result is a boolean". Build the boolean with `&&`, `||`, `!` or comparison operators.

> One exception (C# 9+): type patterns like `if (umar is not 0)` — but for basics always write a comparison.

## Ternary — the one-line version

```csharp
string status = (umar >= 18) ? "Adult" : "Minor";
Console.WriteLine(status);
```

`(condition) ? value1 : value2` — exactly like JS's. In C# you can drop the parentheses (`umar >= 18 ? ...` also works), but keeping them keeps it clear.

## switch — same job, new syntax

In JS, `switch` + `break` was painful (forget it and you got fall-through). In C# the structure is the same, but **`break` at the end of a case is mandatory** (or `return`), otherwise the compiler gives an error — there's no chance of forgetting:

```csharp
Console.Write("Option chuno (1/2/3): ");
string ch = Console.ReadLine();

switch (ch)
{
    case "1":
        Console.WriteLine("Naya order");
        break;               // ❗ case ends here
    case "2":
        Console.WriteLine("Order dekho");
        break;
    case "3":
        Console.WriteLine("Bahar");
        break;
    default:                 // default = else
        Console.WriteLine("Galat option");
        break;
}
```

One more thing — `switch` isn't only for string/int; it works on every type (enums use it daily — we'll see in module 2). And modern C# has pattern matching too (when a condition comes along with values):

```csharp
switch (score)
{
    case >= 90:                    // score >= 90?
        Console.WriteLine("A grade");
        break;
    case >= 75:
        Console.WriteLine("B grade");
        break;
    default:
        Console.WriteLine("Aur mehnat");
        break;
}
```

This is a bit advanced — for now the classic `case "1":` is enough, but know that C#'s switch is more powerful than JS's.

## Joining conditions with logical operators

```csharp
if (umar >= 18 && umar <= 60 && active)
{
    Console.WriteLine("Eligible");
}
```

- `&&` both must be true (AND)
- `||` at least one true (OR)
- `!` flip it (NOT)

All in one file — exactly like JS. The only difference is that the operands must always be booleans (`&&` needs a `true/false` value on both sides).

## Nested if — and one small pattern

```csharp
if (loggedIn)
{
    if (isAdmin)
    {
        Console.WriteLine("Admin panel");
    }
    else
    {
        Console.WriteLine("Normal user");
    }
}
else
{
    Console.WriteLine("Pehle login karo");
}
```

It runs (like JS), but deep nested ifs are hard to read. Professionally this gets straightened out with **early return** — I'll show that when functions arrive at the end of module 1.

## One complete program — ATM-style

```csharp
// Program.cs
Console.Write("Balance batao: ");
int balance = int.Parse(Console.ReadLine());

Console.Write("Kitna withdraw karna hai: ");
int amount = int.Parse(Console.ReadLine());

if (amount <= 0)
{
    Console.WriteLine("Amount galat hai.");
}
else if (amount > balance)
{
    Console.WriteLine("Balance kam hai.");
}
else if (amount % 100 != 0)
{
    Console.WriteLine("Sirf 100 ke multiple chalte hain.");
}
else
{
    balance = balance - amount;    // or balance -= amount;
    Console.WriteLine($"Naya balance: {balance}");
}
```

`amount % 100 != 0` — checked with modulus whether it's a multiple of 100. These small conditions together build real logic.

What this is NOT:

- **`if (umar)` doesn't run** — JS's truthy-falsy habit doesn't work in C#. Always write a boolean condition (`umar > 0`).
- **`break` in `switch` is not optional** — in JS, forgetting it made the next case run (a bug was born); in C# the compiler gives an error directly.
- **The condition can't be just any value** — like JS's `if (stringVar)` (empty string = false), that doesn't happen here. You have to write `stringVar != ""`.

## In Your Own Words

1. Why does `if (umar)` run in JS but not in C#?

<details>
<summary>Sample Answer</summary>

**Answer:** C# wants strictly a boolean in the condition. `umar` is an int, which can't be put directly into a bool. JS's truthy/falsy convention doesn't exist — you have to write an explicit boolean comparison like `if (umar > 0)`.

</details>

2. What happens if you don't write `break` in C#'s `switch` — compared to JS?

<details>
<summary>Sample Answer</summary>

**Answer:** In C# you get a compiler error (break/return/throw is mandatory at the end of a case block). In JS the code ran and fell through to the next case — a silent bug. C# eliminated that possibility entirely.

</details>

3. In the ATM program, what is `amount % 100 != 0` checking?

<details>
<summary>Sample Answer</summary>

**Answer:** The modulus `%` gives the leftover value when dividing by 100. If `% 100 != 0`, the amount isn't a full multiple of 100 (like 250) — so the ATM-style logic rejects it because the machine only dispenses 100 notes.

</details>

4. `else if` vs nested `if` — what's the difference between two ways of doing the same job?

<details>
<summary>Sample Answer</summary>

**Answer:** `else if` checks all the alternative conditions at one level — clean to read. Nested if-inside-if is when there's a condition on a condition (first login, then admin) — since both things are required together, they go inside each other.

</details>
