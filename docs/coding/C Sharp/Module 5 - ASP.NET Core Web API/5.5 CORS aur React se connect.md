JWT se tumhari API protected ho gayi — par ek dikkat abhi bhi baaki hai. Tumhara React app `localhost:3000` pe chalta hai, API `localhost:5000` pe — browser dono ko **alag-alag origin** maanta hai aur seedha fetch karne pe rok deta hai. Yahi dikkat hai **CORS**, aur uske baad ka saara flow jo tumhare Next.js projects mein tha (env, API base URL, error handle) — yahan API wali side se.

# CORS aur React se connect

## Problem — browser kyun rok raha hai

Tumne `fetch('http://localhost:5000/api/students')` likha React mein, console mein:

```
Access to fetch at 'http://localhost:5000/...' from origin
'http://localhost:3000' has been blocked by CORS policy
```

**CORS = Cross-Origin Resource Sharing.** Browser ka security rule: ek page doosre "origin" (domain + port + protocol) se data maang sake — **server ko pehle hi permission deni padti hai.** Yeh restriction **sirf browser** ki hai — Postman/curl se wahi API bina kisi issue ke chalti hai (isliye debugging mein alag-alag lagta hai).

Logic samjho: `evil.com` wala page tumhara `bank.com` session cookie/use data na le le — isi liye browser by-default block. API ko bolna padta hai "haan, `localhost:3000` ko allow karo".

## Server side fix — 3 line

```csharp
// Program.cs — builder.Build() se pehle
builder.Services.AddCors(options =>
{
    options.AddPolicy("Frontend", policy =>
        policy.WithOrigins("http://localhost:3000")     // sirf tumhara React dev URL
              .AllowAnyHeader()                          // Authorization header waghera
              .AllowAnyMethod());                        // POST/PUT/DELETE
});

// ...Build() ke baad, endpoints se pehle:
app.UseCors("Frontend");
```

2 jagah: **service** mein policy banao (builder pe), **middleware** lagao (`UseCors`) — endpoint se pehle taki har response mein header lag jaaye.

Server response mein yeh header chala jaata hai:

```
Access-Control-Allow-Origin: http://localhost:3000
```

Ab browser khush — React se fetch chal jaayega.

### Preflight bhi samjho (interview bonus)

Jab request simple GET nahi hoti (custom header, `Content-Type: application/json` wala POST), browser **pehle ek OPTIONS request** bhejta hai — "pehle batao, kya mai bhej sakta hoon?" Server `Allow-Origin`/`Allow-Headers` se jawab deta hai, phir asli request. `.AllowAnyHeader/Method` isi preflight ke liye hain. OPTIONS handler likhne ki zaroorat nahi — middleware khud karta hai.

### Production mein

```csharp
.WithOrigins("https://tumsiwebsite.com")     // dev URL nahi, asli domain
```

Ya multiple:

```csharp
.WithOrigins("https://app.example.com", "https://admin.example.com")
```

**`AllowAnyOrigin()` sabke liye allow** — dev mein chalta hai, production mein security review mein phase jaata hai. Hamesha specific origins.

## React side — poora flow (tumhari duniya)

```javascript
// .env (React side)
VITE_API_URL=http://localhost:5000        // Next.js: NEXT_PUBLIC_API_URL

// api.js — base URL ek jagah
const API = import.meta.env.VITE_API_URL;

export async function getStudents() {
  const token = localStorage.getItem("token");
  const res = await fetch(`${API}/api/students`, {
    headers: { "Authorization": `Bearer ${token}` },
  });
  if (!res.ok) throw new Error("API fail");     // status code handle
  return res.json();
}

export async function login(email, password) {
  const res = await fetch(`${API}/api/login`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ email, password }),
  });
  if (!res.ok) return null;                     // 401
  const { token } = await res.json();
  localStorage.setItem("token", token);
  return token;
}
```

**Dekho kya-kya jod diya:**

1. **Base URL `.env` mein** — `localhost:5000` hardcode nahi (module 4.3 wala rule, doosri taraf)
2. **`Authorization: Bearer`** header — JWT wala flow (5.4)
3. **`res.ok` check** — 400/404/500 pe `throw`, warna UI mein galat data
4. **`res.json()`** — wahi jo backend automatic JSON mein bhej raha tha

Yeh wahi pattern hai jo tumhare Next.js API routes mein tha — bas ab roles ulte hain: **tumhara React wahi client hai, aur backend ASP.NET Core.**

## Debugging checklist (jab na chale)

1. **CORS error console mein?** → API side `UseCors` policy + `UseCors` endpoint se pehle. OPTIONS request Postman se maaro — header aa rahe hain?
2. **401?** → token missing/expired — `Authorization` header check, `UseAuthentication` order check
3. **404?** → route match (`/api/...`), trailing slash, port galat
4. **400?** → JSON body ka shape DTO se match (`Content-Type: application/json` bhoolo toh bind nahi hota)
5. **Network tab mein request dikh nahi?** → URL/port dekho, ya CORS preflight fail

Dev mein CORS policy change ki → **API restart** (`dotnet run` dobara) — policy startup pe banti hai.

## Yeh kya NAHI hai

- **CORS = API security nahi hai** — CORS sirf **browser** ko rokta hai. Postman/curl se sab ho jaata hai. Asli security = JWT + validation (5.3/5.4). `AllowAnyOrigin` "security" nahi deta.
- **CORS error backend ka code nahi** — API bilkul theek hai, browser policy ka issue hai. Isliye "Postman mein chalta hai, browser mein nahi" = 99% CORS.
- **React `.env` mein secret nahi** — `NEXT_PUBLIC_`/`VITE_` wali values browser ko dikhti hain (sab dekh sakte hain). Sirf public config (URL) — secret keys kabhi frontend pe nahi. Secrets API ke paas.
