Pichhle file mein pehla GET endpoint chala diya — par wo static tha. Asli API ko 4 cheezein karni hoti hain: **ID se data dhoondna, naya data lena (POST), badalna (PUT), hatana (DELETE)** — aur beech mein jo object andar aate/bahar jaate hain unhe **DTOs** mein rakhna. Yahi file sab hai.

# Endpoints, Routing aur DTOs

## CRUD ke 4 endpoints — ek jagah

Ek students resource ke liye:

```
GET    /api/students       → saare list karo
GET    /api/students/5     → ek (Id=5)
POST   /api/students       → naya banao
PUT    /api/students/5     → update karo
DELETE /api/students/5     → hatao
```

Yahi **REST** ka pattern hai (WEB-DEV course mein detail tha) — resource ke naam pe URLs, HTTP method se kaam. Ab C# mein:

```csharp
// Program.cs (minimal API style) — EF wala
app.MapGet("/api/students", async (SchoolDb db) =>
    await db.Students.ToListAsync());

app.MapGet("/api/students/{id}", async (int id, SchoolDb db) =>
    await db.Students.FindAsync(id) is Student s
        ? Results.Ok(s)
        : Results.NotFound());          // 404

app.MapPost("/api/students", async (CreateStudentDto dto, SchoolDb db) =>
{
    var student = new Student { Name = dto.Name, Marks = dto.Marks };
    db.Students.Add(student);
    await db.SaveChangesAsync();
    return Results.Created($"/api/students/{student.Id}", student);   // 201
});
```

Dekho **routing syntax**:

- `{id}` — **route parameter**: URL ka wo hissa variable ban gaya (`/api/students/5` → `id = 5`)
- **lambda parameters inject** hote hain: `(int id, SchoolDb db)` — `id` URL se, `db` server se (DI, agla point)

Aur **HTTP status codes** ka khel:

```csharp
Results.Ok(data)           // 200 — sab theek
Results.Created(url, data) // 201 — nayi cheez bani
Results.NotFound()         // 404 — nahi mili
Results.BadRequest(msg)    // 400 — client ki galti
```

JS `res.status(201)` wala kaam — yahan method ke naam se saaf.

## DTO — Data Transfer Object

**Sawaal:** `POST /api/students` mein client kuch bhi bhej sakta hai:

```json
{ "name": "Vin", "marks": 90, "isAdmin": true, "salary": 999999 }
```

Agar tum seedha DB wali `Student` class use kar lo toh `isAdmin`, `salary` kahan jaayenge? **Mass assignment** ki galti — user ne khud ko admin bana liya. **Isliye alag class — sirf jo chahiye:**

```csharp
// Client se aane wala — sirf input
record CreateStudentDto(string Name, int Marks);

// Client ko jaane wala — sirf output (sensitive chhupao)
record StudentDto(int Id, string Name, int Marks);
```

`record` = chhoti data class (C# wala DTO sabse popular form). Ab:

```csharp
app.MapPost("/api/students", async (CreateStudentDto dto, SchoolDb db) =>
{
    var student = new Student { Name = dto.Name, Marks = dto.Marks };  // sirf chahiye wale
    db.Students.Add(student);
    await db.SaveChangesAsync();

    var outDto = new StudentDto(student.Id, student.Name, student.Marks);
    return Results.Created($"/api/students/{outDto.Id}", outDto);
});
```

**Rule:** input ke liye `CreateXxxDto`/`UpdateXxxDto`, output ke liye `XxxDto`, andar ka model DB ke liye. 3 class lagti hain bhari, par security + clear API milti hai — har bade project mein yahi pattern hai.

Fayda ek aur — **DB ki cheezein bahar nahi jaati:** password hash, internal flags sab `StudentDto` mein honge hi nahi.

## Controller style mein wahi sab

```csharp
[ApiController]
[Route("api/students")]
public class StudentsController : ControllerBase
{
    private readonly SchoolDb _db;
    public StudentsController(SchoolDb db) { _db = db; }   // DI — agla hissa

    [HttpGet]
    public async Task<IActionResult> GetAll() =>
        Ok(await _db.Students.ToListAsync());

    [HttpGet("{id:int}")]                       // ⭐ constraint: sirf int
    public async Task<IActionResult> Get(int id)
    {
        var s = await _db.Students.FindAsync(id);
        return s is null ? NotFound() : Ok(s);
    }

    [HttpPost]
    public async Task<IActionResult> Create(CreateStudentDto dto)
    {
        var student = new Student { Name = dto.Name, Marks = dto.Marks };
        _db.Students.Add(student);
        await _db.SaveChangesAsync();
        return CreatedAtAction(nameof(Get), new { id = student.Id }, student);
    }
}
```

Differences: `Ok/NotFound` (ControllerBase methods), `[HttpGet("{id:int}")]` route constraint, aur class ke constructor mein `SchoolDb _db` — yeh hai **Dependency Injection**:

```csharp
builder.Services.AddDbContext<SchoolDb>(o =>
    o.UseSqlServer(builder.Configuration.GetConnectionString("SchoolDb")));
```

**DI ka matlab:** `SchoolDb` tum `new` nahi karte — server startup pe ban chuki hai, constructor mein **inject** ho jaati hai. Har request mein fresh connection aur config se — yahi `.NET ka sabse roz wala pattern` hai (`builder.Services.Add...` + constructor). Next.js mein config/context wala feel.

## Query parameters — filter/sort (URL mein `?`)

```csharp
// GET /api/students?minMarks=80&sort=desc
app.MapGet("/api/students", async (int? minMarks, string? sort, SchoolDb db) =>
{
    var q = db.Students.AsQueryable();
    if (minMarks is not null) q = q.Where(s => s.Marks >= minMarks);
    if (sort == "desc") q = q.OrderByDescending(s => s.Marks);
    return await q.ToListAsync();
});
```

`?minMarks=80` — **query string** parameters. `int?` (nullable) isliye — optional hain. JS mein `new URLSearchParams(location.search)` wala tha, yahan framework khud parse karke parameter de deta hai. Pagination (`page`, `pageSize`), search (`q`), filter — sab yahin aate hain.

## Routing ke rules (aam mistakes)

- Route case-sensitive nahi (`/api/Students` ≈ `/api/students`) par consistency rakho — sab lowercase
- `{id:int}` jaisi **constraint** lagao — `abc` aayi toh 404/400, handler chalega hi nahi
- Route pe **conflict** (do GET same path) → startup pe error
- **HTTP method match** — `[HttpPost]` endpoint pe GET aayi toh 405

## Yeh kya NAHI hai

- **DTO = DB model nahi** — model DB ke liye, DTO client contract ke liye. Dono alag rakhna production rule hai (security + flexibility).
- **Route parameter `{id}` = query parameter `?id=` nahi** — path wala resource identify karta hai (`/students/5`), query wala filter/options deta hai (`?minMarks=80`).
- **`CreatedAt` (201) har jagah nahi** — POST (nayi cheez) pe 201, baaki mein 200. Conventions REST ke hain — swagger bhi isi se generate karta hai.

## In Your Own Words

1. REST CRUD ke 4 HTTP methods aur unke kaam — students resource ke against batao.

2. DTO kyun chahiye — `Student` model directly POST body mein lene se kya khatra hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Mass assignment khatra — client `isAdmin`, `salary`, `id` jaise fields bhej deta hai aur seedhe DB mein chala jaata hai. `CreateStudentDto` mein sirf allowed fields hain — extra fields ignore. Saath mein bahar jaate waqt sensitive fields (password) bhi chhup jaate hain `StudentDto` mein.

</details>

3. `{id}` route parameter aur `?minMarks=80` query parameter — kab kaunsa?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `{id}` = URL path ka part — resource identify karta hai (`/students/5` = kaunsa student), required. Query param `?` ke baad — filter/options deta hai (`minMarks`, `sort`, `page`), optional hote hain aur API ek hi path pe alag-alag views deta hai.

</details>

4. Dependency Injection (`builder.Services.AddDbContext` + constructor) ka kaam kya hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Service (jaise SchoolDb) ko constructor mein **diya** jaata hai — tum `new` nahi karte. Startup pe register hota hai (`AddDbContext`), har request pe framework inject kar deta hai. Isse config ek jagah, test karna aasan, aur dependency ka control server ke paas.

</details>

Endpoints + DTOs se structure ban gaya — par abhi client jo bheje usko hum **blindly** maan rahe hain. Agla file: validation (galat data rokna) aur error handling (galat cheez pe sahi status + message dena).
