# Web API kya hai — pehla API

## Pehle samjho — API kya bhejta hai

Tumne React mein `fetch('/api/products')` kiya tha — uske peeche server pe kuch chal raha tha jo JSON deta tha. Woh "kuch" hota hai ek **Web API** — HTTP requests (GET/POST/PUT/DELETE) sunne wala program, jo database se baat karke **JSON** wapas bhejta hai. UI nahi, sirf data.

```
React app  --fetch("/api/students")-->  ASP.NET Core API  --EF Core-->  DB
        <------ JSON response -----------  (yeh tum banaoge)
```

**Frontend (React) = dikhana. Backend (API) = data + rules.** Tum dono jaante ho — bas ab backend C# mein banega.

## ASP.NET Core kya hai — naam hi confusing hai

- **ASP.NET** — Microsoft ka web framework ka purana naam (ages se hai)
- **Core** — cross-platform wala naya version (Linux pe chalta hai)
- **.NET Core / .NET 8 / .NET 9** — wahi platform jiska setup module 0 mein kiya

Roz bolte hain **"ASP.NET Core"** = ".NET pe bana web framework". Aur **Web API** = uske andar sirf data dene wale endpoints banane wala hissa. HTML render karne wala MVC bhi hai, par aaj zyadatar APIs hi banate hain kyunki frontend alag hai (React).

## Pehla project — `dotnet new webapi`

```bash
dotnet new webapi -n SchoolApi
cd SchoolApi
dotnet run
```

Khol ke dekho — folder mein:

```
SchoolApi/
├── Program.cs           ← startup — yahan sab jodta hai (Next.js ka layout/server entry jaisa)
├── appsettings.json     ← connection strings waghera (module 4.3)
├── Controllers/         ← endpoints (agar controller template chuni)
└── SchoolApi.csproj
```

`dotnet run` → terminal mein URL dikhega (`http://localhost:5000` ya 5231). Browser mein kholo — API chal rahi hai! `swagger` wali page aayi toh aur bhi badhiya — usse test kar sakte ho (agle file mein).

> Template ke hisaab se **minimal API** (Program.cs mein seedhe endpoints) ya **controllers** dono mil sakte hain. Naya .NET minimal API prefer karta hai, par purane/naye dono codebase mein dono milte hain — isliye hum dono dekhenge: shuruaat minimal (simple), phir controllers (classic style).

## Minimal API — 5 line mein pehla endpoint

`Program.cs` mein:

```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/", () => "Hello, API!");              // GET / → simple text
app.MapGet("/api/health", () => new { status = "ok", time = DateTime.Now });

app.Run();
```

`dotnet run` → `http://localhost:5000/api/health` browser mein:

```json
{"status":"ok","time":"2026-09-25T10:30:00"}
```

Line by line:

1. `WebApplication.CreateBuilder(args)` — app ban raha hai (config, logging, sab ready)
2. `builder.Build()` — builder se app bana
3. `MapGet("/route", () => ...)` — "jab GET request aaye is path pe, yeh do" — arrow function JS wala feel
4. `app.Run()` — server chalu (npm run dev wali line — server ab rukega)

**Pehla API chal gaya.** Request-response ka flow:

```
Browser/React:  GET http://localhost:5000/api/health
Server:         MapGet ne pakda → lambda chali → object banaya
Response:       JSON (auto) + HTTP 200
```

`Console.WriteLine` wali duniya ab HTTP wali mein hai.

## JSON auto — magic kahan hai

Tumne lambda mein sirf object diya, JSON kisne banaya? **ASP.NET Core automatically** object → JSON bana deta hai (response ke liye) aur JSON → object (request body ke liye). `JSON.stringify` likhne ki zaroorat nahi — JS mein `res.json()` tha na, woh serialization backend yahi kar deta hai.

## Controller style — classic tareeka

Ab wahi kaam **controllers** se (bade projects mein aksar yahi milega):

```csharp
// Controllers/HealthController.cs
using Microsoft.AspNetCore.Mvc;

[ApiController]                    // "yeh ek API controller hai" — auto validation, JSON etc.
[Route("api/[controller]")]        // /api/health (naam se)
public class HealthController : ControllerBase
{
    [HttpGet]                      // GET request handle kare
    public IActionResult Get()
    {
        return Ok(new { status = "ok", time = DateTime.Now });   // 200 + JSON
    }
}
```

Aur `Program.cs` mein (agar template mein nahi hai):

```csharp
builder.Services.AddControllers();
...
app.MapControllers();
```

Mapping dekho:

| Minimal API | Controller |
|---|---|
| `MapGet("/api/health", ...)` | `[HttpGet]` + class `[Route("api/...")]` |
| Program.cs mein sab route | `Controllers/` folder mein class |
| chhota-simple | bade system mein organized |

**Dono aane chahiye.** Abhi ke learning ke liye minimal se samjho, project (module 6) mein controllers use karke folder-based structure milega.

## Routing kaise match hoti hai (logic)

Request aayi `GET /api/students/5`:

1. Path dekha → `api/students/5` kis route se match?
2. `api/students` + `5` → `/api/students/{id}` wale endpoint ne pakda
3. `5` ko **parameter** mein daala (`int id`)
4. Method check → GET wala action chala
5. Response JSON + status code

Agar match nahi mila → **404**. Galat data type (`abc` jagah `int` 5 chahiye tha) → **400**. Yahi status codes hain: 200 OK, 201 Created, 400 Bad Request, 404 Not Found, 500 Server Error. REST recap tumhare WEB-DEV course mein hai — wahan se utha lo.

## Yeh kya NAHI hai

- **Web API = website nahi** — wo HTML page nahi deta, JSON deta hai. HTML React (tumhara frontend) deta hai.
- **`dotnet run` = production server nahi** — development ke liye. Production mein IIS/Kestrel/Docker alag se (deploy module 6.4).
- **Controller hi zaroori nahi** — minimal API bhi real hain (naya .NET inhe push karta hai). Par dono ka concept same: route → handler → JSON.
- **API key/DB abhi nahi** — pehle route + response ka skeleton clear, agle files mein EF, auth, validation jodenge.
