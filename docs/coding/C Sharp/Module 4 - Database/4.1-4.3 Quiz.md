## MCQ

Q: SQL injection se bachne ka sahi tarika kya hai?
A. User input chhota rakho
B. Query mein input ko string se jodo par quotes lagao
C. Parameterized query (`@name` + parameters) ya EF Core use karo
D. Error messages band kar do
> C. String concatenation (`"...Name = '" + input + "'"`) mein user query tod sakta hai. Parameterized query mein value data treat hoti hai, code nahi — EF Core toh automatically parameters banata hai. Yahi asli protection hai.

---

Q: ORM (Entity Framework) kya karta hai?
A. Database install karta hai
B. C# objects aur database tables ke beech mapping — LINQ ko SQL mein badal ke DB ko bhejta hai
C. HTML render karta hai
D. Code compile karta hai
> B. Object-Relational Mapper — `db.Students.Where(...)` jaisi LINQ query ko SQL mein badal ke DB ko bhejta hai, aur rows ko wapas C# objects banata hai. Tumhe SQL likhne ki zaroorat nahi.

---

Q: `db.Students.Add(student)` ke baad DB mein kya hua?
A. Row insert ho gayi
B. Kuch nahi — `SaveChangesAsync()` call karne pe hi INSERT DB mein jaata hai
C. Table ban gayi
D. Program crash
> B. EF change tracker mein sirf memory mein track karta hai. `SaveChanges()`/`SaveChangesAsync()` pe pending changes ek saath (transaction ke saath) SQL ban ke jaate hain. Add = intent, Save = commit.

---

Q: Paiso (salary/price) ke liye C# mein kaunsa type — aur `double` kyun nahi?
A. `double` hi best hai
B. `float`
C. `decimal` — floating-point rounding galti nahi karta
D. `int`
> C. Double mein 0.1+0.2 = 0.300000000000004 jaisi galti aati hai jo paise mein 1 paise ka farak bana sakti hai. `decimal` exact fixed-point hai — isliye banking/DB ke paise wale columns DECIMAL + C# decimal.

---

Q: `.Include(x => x.Class)` EF Core mein kya karta hai?
A. Class delete karta hai
B. Related data load karta hai (SQL JOIN) — bina iske `student.Class` null hota hai
C. Naya table banata hai
D. Config load karta hai
> B. Navigation property ko eagerly load karta hai — SQL mein JOIN ban ke related table ka data bhi laata hai. Bina Include ke EF related data apne aap nahi laata (null), taki faltu query na chalein.

---

Q: Real project mein connection string kahan honi chahiye?
A. `Program.cs` mein string literal
B. `appsettings.json` mein, aur asli secrets `user-secrets`/env vars mein
C. Hardcoded comment
D. Har file mein copy
> B. Config file mein rakho (badalne wali), secrets ko `dotnet user-secrets` ya environment variable mein — kyunki appsettings.json git mein jaata hai. Password kabhi code/config mein nahi.

---

Q: `dotnet ef migrations add X` aur `dotnet ef database update` ka kya hota hai?
A. Package install
B. Migration file banti hai (schema diff), phir update se DB pe apply hoti hai
C. Server restart
D. Code format
> B. Migrations = DB schema ka version control. `add` pe EF tumhare model changes dekh kar migration file bana deta hai, `database update` se wo DB pe execute hoti hai (CREATE TABLE/ALTER COLUMN). Git jaisa, database ke liye.

## TrueFalse

Q: EF Core `Where()` lagane pe poora table memory mein le aata hai, phir filter karta hai.
- True
- False
> False. `Where()` se SQL mein `WHERE` ban ke DB pe hi filter hota hai — memory mein sirf matching rows aati hain. EF query soch-samajh ke (translated) DB ko bhejta hai.

---

Q: Connection string mein password `appsettings.json` mein likh dena chahiye kyunki woh file git mein safe hai.
- True
- False
> False. `appsettings.json` git mein jaati hai — wahan secret nahi. Secrets `user-secrets` (local) ya environment variable (server) mein rakhte hain, jo git ke bahar rehte hain.

---

Q: `IDENTITY(1,1)` wale column mein nayi row pe DB khud Id badha deta hai, aur EF Core wahi value object ke `Id` property mein laata hai.
- True
- False
> True. DB auto-increment Id deta hai; `SaveChanges` ke baad EF nayi generated Id wapas tumhare object mein set kar deta hai — C# code ko Id khud assign nahi karni padti.

---

Q: `EnsureCreated()` real projects mein migrations ka full replacement hai — schema badalne pe bhi yahi chalana chahiye.
- True
- False
> False. `EnsureCreated` sirf pehli baar tables banata hai, baad ke schema changes (naya column) handle nahi karta. Real project migrations use karta hai — version-controlled changes jo `database update` se apply hote hain.

---

Q: `decimal` type specifically finance/money ke liye recommended hai kyunki wo exact value rakhta hai.
- True
- False
> True. Floating-point (float/double) rounding error karta hai — paiso mein galti. `decimal` fixed-point exact hai — isliye SQL DECIMAL columns ke saath C# decimal aata hai (banking standard).
