Pichhle file mein connection string seedha code mein likh di thi: `UseSqlite("Data Source=school.db")`. Par asli project mein wahan hota hai **passwords aur server addresses** — jo code mein likha toh git mein chala jaayega aur sab dekh lenge. JS world mein iska naam tha `.env` — C#/.NET mein wahi kaam karta hai **`appsettings.json`**.

# Connection String aur appsettings.json

## Problem — config code mein nahi

```csharp
// ❌ Production code aisa nahi hota
.UseSqlServer("Server=prod-db.company.com;Database=App;Password=Secret123")
```

Git push kiya → poori duniya ko password mil gaya. Aur server badla toh code badlo, recompile, redeploy — mushkil. **Isliye config alag file mein, code sirf padhta hai.**

JS comparison:

```javascript
// JS — .env
DB_URL=postgres://...
console.log(process.env.DB_URL)     // code mein sirf read
```
```jsonc
// C# — appsettings.json
{
  "ConnectionStrings": {
    "Default": "Server=...;Database=..."
  }
}
```

Fark: `.env` key=value plain text tha, yahan **JSON** file hai — aur .NET usse strongly-typed settings bhi bana deta hai.

## appsettings.json — project ka config envelope

Har .NET web project mein hota hai (root pe):

```json
{
  "Logging": {
    "LogLevel": { "Default": "Information" }
  },
  "ConnectionStrings": {
    "SchoolDb": "Data Source=school.db"
  },
  "Jwt": {
    "Secret": "yeh-secret-key-hai",
    "ExpiryMinutes": 60
  }
}
```

Har section ek jagah — logging, DB, auth. **Yeh file git mein jaati hai** (secrets alag — aage).

## Code se padhna — Options pattern (company wala tareeka)

**Tareeka 1 (chhota, script/apps ke liye):**

```csharp
using Microsoft.Extensions.Configuration;

var config = new ConfigurationBuilder()
    .SetBasePath(AppContext.BaseDirectory)
    .AddJsonFile("appsettings.json", optional: false)
    .Build();

string conn = config.GetConnectionString("SchoolDb");   // section se value
```

`GetConnectionString("SchoolDb")` — `ConnectionStrings` section se value utha liya.

**Tareeka 2 (ASP.NET Core — module 5 mein yahi chalega):** config automatically milta hai, aur `Program.cs` mein:

```csharp
builder.Services.AddDbContext<SchoolDb>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("SchoolDb")));
```

`builder.Configuration` = wahi `appsettings.json` ka reader, jo request ke saath chalta hai. Abhi itna samjho — **code connection string ko jaanta nahi, config deta hai.**

## Secrets — asli password wali cheez

Connection string mein password ho toh `appsettings.json` git mein **mat** daalo. .NET ka tool:

```bash
dotnet user-secrets init                              // project secret vault on
dotnet user-secrets set "ConnectionStrings:SchoolDb" "Server=...;Password=RealPass"
```

Yeh values `secrets.json` mein rehti hai — **git mein kabhi nahi jaati**. Dev machine pe har developer ka apna. Production mein connection string **environment variable** se aati hai (server pe set hoti hai) — .NET dono (`user-secrets`, env vars) `builder.Configuration` se automatically utha leta hai.

**Layer samjho (interview wala):**

```
Production:  env var (server)     ─┐
Dev:         user-secrets         ─┼→  builder.Configuration  →  code
Default:     appsettings.json     ─┘
```

Jo upar wala ho wo jeet jaata hai. Code change nahi hota — sirf config badalta hai.

## Project anatomy — folder structure samjho

Chhote `dotnet new console` mein sab ek jagah tha. Asli web project mein:

```
MyApp/
├── Program.cs              ← entry point (abhi chhota — startup yahan)
├── appsettings.json        ← config
├── Controllers/ ya Endpoints/  ← API ke routes (module 5)
├── Models/ ya Data/        ← classes (Student, DbContext)
├── MyCompany.MyApp.csproj  ← project file (package.json jaisa)
└── obj/ bin/
```

Naam conventions dekhte hi C# wale lagte hain — `Models/`, `Services/`, `Controllers/`. `.csproj` mein packages:

```xml
<Project Sdk="Microsoft.NET.Sdk.Web">
  <ItemGroup>
    <PackageReference Include="Microsoft.EntityFrameworkCore.SqlServer" Version="8.0.0" />
  </ItemGroup>
</Project>
```

`<PackageReference>` = package.json ka `dependencies` wala hissa. `dotnet add package` khud yahan add kar deta hai. **NuGet = npm, .csproj = package.json.**

## Ek complete example — config + EF

```json
// appsettings.json
{
  "ConnectionStrings": {
    "SchoolDb": "Data Source=school.db"
  }
}
```

```csharp
// Program.cs
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Configuration;

var config = new ConfigurationBuilder()
    .SetBasePath(Directory.GetCurrentDirectory())
    .AddJsonFile("appsettings.json")
    .Build();

var options = new DbContextOptionsBuilder<SchoolDb>()
    .UseSqlite(config.GetConnectionString("SchoolDb"))   // config se!
    .Options;

using var db = new SchoolDb(options);
db.Database.EnsureCreated();
Console.WriteLine("DB jud gaya: " + db.Students.Count());
```

Ab connection string **code ke bahar** hai — badalni ho toh JSON file theek karo, C# recompile nahi.

> Server pe (Linux) path wali galti se bachne ke liye production mein `SetBasePath(AppContext.BaseDirectory)` prefer hota hai — abhi ke liye chal raha hai.

## Yeh kya NAHI hai

- **`appsettings.json` = `.env` jaisi secret file nahi hai** — woh git mein jaati hai. Secrets `user-secrets` ya env vars mein — sirf zaroori config `appsettings.json` mein.
- **Config file bhi hardcode hi hai** — farak ye hai ki woh **badalne wali** hai (code recompile nahi), aur alag-alag jagah (dev/prod) alag values ho sakti hain.
- **NConfig library nahi** — Microsoft.Extensions.Configuration .NET ka built-in hai, kuch alag install nahi karna (web projects mein toh aata hi hai).

## In Your Own Words

1. Connection string code mein rakhne ki jagah `appsettings.json` mein kyun rakhte hain — 2 wajah?

<details>
<summary>Sample Jawab</summary>

**Jawab:** (1) Security — code git mein jaata hai, wahan password nahi hona chahiye; config file se secret alag rakh sakte ho (user-secrets). (2) Flexibility — server badalne pe sirf config badlo, code recompile/redeploy nahi. Dev aur prod ke alag values ho sakti hain.

</details>

2. .NET configuration ki 3 layers kaunsi hain aur kaunsi upar wali jeet jaati hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** appsettings.json (default), user-secrets (dev local), environment variable (production server). Higher layer override karti hai — env var set ho toh wohi value milti hai, warna user-secrets, warna appsettings.json. Code hamesha `builder.Configuration` se padhta hai.

</details>

3. NuGet package aur `.csproj` ka `<PackageReference>` ka rishta kya hai — JS se compare karo.

<details>
<summary>Sample Jawab</summary>

**Jawab:** Nuget = npm registry, `dotnet add package X` = `npm install X`, aur `.csproj` ka `<PackageReference Include="X" Version="...">` = package.json ka dependencies entry. Project kholte hi .NET packages khud restore karta hai (npm install jaisa).

</details>

4. `Controllers/`, `Models/` wala folder structure kyun hota hai — sab Program.cs mein kyun nahi?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Ek file mein sab (routes, data, logic) ho toh badhne pe sambhalna mushkil. C# projects mein har kaam ka alag hissa (models alag, routes alag, services alag) — padhne, team-work (kam conflict) aur test karne mein aasan. Namespace + folders se code organize rehta hai.

</details>
