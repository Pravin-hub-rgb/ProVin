# SQL Crash Recap + C# se SQL

## SQL — 5 minute mein wapas

DBMS course ka quick revision (detail wahi hai):

```sql
-- Table banao
CREATE TABLE Students (
    Id INT PRIMARY KEY IDENTITY(1,1),
    Name NVARCHAR(100),
    Marks INT
);

-- Data dalo
INSERT INTO Students (Name, Marks) VALUES ('Vin', 90);

-- Padho
SELECT Name, Marks FROM Students WHERE Marks >= 80;

-- Badlo
UPDATE Students SET Marks = 95 WHERE Name = 'Vin';

-- Hatado
DELETE FROM Students WHERE Name = 'Old';
```

5 commands — **INSERT, SELECT, UPDATE, DELETE** (CRUD) + `CREATE`. Yehi roz chalte hain. Joins/aggregates detail mein DBMS course mein hai, wahan se utha lo.

Ek cheez DB se judi — **IDENTITY(1,1)** ka matlab: Id khud badhti jaati hai (1, 2, 3...) — C# object ke `Id` mein yahi aayega, khud set nahi karna.

## C# se database — teen tarike (aur kyun EF choose karenge)

**Tareeka 1: ADO.NET (raw SQL)** — sabse purana, seedha:

```csharp
// Pseudo-structure — samajhne ke liye
using (var conn = new SqlConnection(connectionString))
{
    await conn.OpenAsync();
    var cmd = new SqlCommand("SELECT Name FROM Students WHERE Marks >= @min", conn);
    cmd.Parameters.AddWithValue("@min", 80);       // ⭐ parameterized
    var reader = await cmd.ExecuteReaderAsync();
    while (await reader.ReadAsync())
        Console.WriteLine(reader.GetString(0));
}
```

Ye code aaj bhi chalta hai, par har query ke liye itna boilerplate. Aur dhyan do **`@min`** pe:

```csharp
// ❌ Kabhi aisa mat karo — SQL INJECTION
string name = userInput;
var cmd = new SqlCommand("SELECT * FROM Users WHERE Name = '" + name + "'", conn);
```

Agar user ne `' OR '1'='1` likh diya toh query tod gayi — sab records leak. **Isliye hamesha parameterized query** (`@name` + `Parameters.AddWithValue`) — parameters value ko data treat karta hai, code nahi. Yeh security ka fundamental rule hai.

**Tareeka 2: Dapper** — raw SQL ke upar chhota wrapper, chhota kaam ho toh.

**Tareeka 3: Entity Framework Core (EF Core)** — .NET ka apna **ORM** (Object-Relational Mapper): C# class ↔ DB table ka mapping khud. **Aaj ke zyadatar projects isi se bante hain** — isliye detail yahin hai.

```csharp
// EF Core style — SQL tum likhte hi nahi
var toppers = await db.Students
    .Where(s => s.Marks >= 80)     // ← LINQ! module 3 wala
    .OrderBy(s => s.Marks)
    .ToListAsync();
```

Dekha? **LINQ hi SQL ban jaata hai.** `Where → WHERE`, `OrderBy → ORDER BY`, `Select → SELECT`. Module 3 ka LINQ yahin kaam aaya.

## SQL aur C# types ka mapping

DB aur C# dono ke types alag-alag naam rakhte hain:

| SQL | C# |
|---|---|
| INT | `int` |
| NVARCHAR(100) | `string` |
| BIT | `bool` |
| DECIMAL(18,2) | `decimal` (money ke liye — double nahi!) |
| DATETIME2 | `DateTime` |
| NULL-able INT | `int?` |

**Money ke liye `decimal`** — `double` floating-point galti karta hai (0.1 + 0.2 wala dard). Banking/accounting code mein `decimal` hi chalta hai — money ke liye yahi default hai.

## Yeh kya NAHI hai

- **EF Core = database nahi hai** — EF Core driver/mapper hai, database alag (SQL Server/PostgreSQL/SQLite). Jaise React UI hai aur backend alag.
- **String concatenation se query nahi** — SQL injection. Hamesha parameters/EF.
- **Program band = data gayab nahi** — DB disk pe hai (JSON file wala dard nahi). Program band, data rehta hai — yahi DB ka point hai.
- **`double` = money nahi** — `decimal` use karo.

## In Your Own Words

1. SQL injection kya hai aur C# mein usse kaise bachte hain?

<details>
<summary>Sample Jawab</summary>

**Jawab:** User input ko query mein string jodna, jisse wo query ko tod/skill sakta hai (`' OR '1'='1`). Bachne ka: parameterized queries (`@name` + `AddWithValue`) — value data treat hoti hai code nahi. EF Core mein toh parameterization automatically hota hai.

</details>

2. ORM (Entity Framework) raw SQL se alag kyun hai — ek faayda batao.

<details>
<summary>Sample Jawab</summary>

**Jawab:** ORM C# class aur DB table ka mapping khud sambhalta hai — tum SQL likhte nahi ho, LINQ/objects se kaam karta hai (`db.Students.Where(...)`). Faayda: SQL likhna nahi padta, refactoring safe, type-safe — badlaav compile-time pakda jaata hai.

</details>

3. Paise (money) wale column ke liye C# mein kaunsa type aur kyun — `double` kyun nahi?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `decimal` — kyunki double floating-point rounding galti karta hai (0.1+0.2 = 0.30000000000000004), jo paiso mein 1 paise ki galti bana sakta hai. `decimal` exact fixed-point hai — banking/DB (DECIMAL/NUMERIC) ke liye designed.

</details>

4. SQL ke `IDENTITY(1,1)` aur C# object ke `Id` field ka kya rishta?

<details>
<summary>Sample Jawab</summary>

**Jawab:** IDENTITY ka matlab DB Id khud badata hai (1,2,3...) jab nayi row insert ho. EF Core mein object bharke insert karo — DB auto Id de deta hai aur wahi value object ke Id property mein wapas aa jaati hai (khud set nahi karna).

</details>

SQL wapas aa gaya — ab asli kaam: **Entity Framework Core** se C# class ko DB table banana aur CRUD karna, wo bhi bina SQL likhe.
