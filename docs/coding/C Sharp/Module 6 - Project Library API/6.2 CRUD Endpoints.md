# Project Setup — Models and Database

## Think First — What Will the Data Model Be

Think for 2 minutes before writing code — that's the senior habit. What's in a library?

- **Book** — title, author, genre, price, available (how many copies)
- (No need to overcomplicate — keep it small and clean, 1 table is enough)

```
Book:
  Id        int (PK, auto)
  Title     string (required, max 200)
  Author    string (required, max 100)
  Genre     string? (optional)
  Price     decimal (money!)
  Available int (copies)
  CreatedAt DateTime
```

Now create it:

```bash
dotnet new webapi -n LibraryApi
cd LibraryApi
dotnet add package Microsoft.EntityFrameworkCore.Sqlite
```

(SQL Server in production; for practice, SQLite — file-based, nothing to install.)

## Step 1: Model (DB Table)

`Models/Book.cs`:

```csharp
using System.ComponentModel.DataAnnotations;

namespace LibraryApi.Models;

public class Book
{
    public int Id { get; set; }                    // PK — DB auto-increments

    [Required, StringLength(200)]
    public string Title { get; set; } = "";

    [Required, StringLength(100)]
    public string Author { get; set; } = "";

    [StringLength(50)]
    public string? Genre { get; set; }             // optional — can be null

    public decimal Price { get; set; }              // ⭐ money = decimal (see 4.1)

    public int Available { get; set; }

    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
}
```

See what got used:

- **`namespace LibraryApi.Models`** — every file in a namespace (module 2.4)
- **Attributes** — validation that auto-applies on the API (5.3)
- **`decimal`** — for price (4.1)
- **`string?`** — optional genre

## Step 2: DbContext (The Door to the DB)

`Data/LibraryDbContext.cs`:

```csharp
using LibraryApi.Models;
using Microsoft.EntityFrameworkCore;

namespace LibraryApi.Data;

public class LibraryDbContext : DbContext
{
    public LibraryDbContext(DbContextOptions<LibraryDbContext> options) : base(options) { }

    public DbSet<Book> Books => Set<Book>();     // → Books table
}
```

Same as module 4.2 — options (connection string) come through the constructor via DI.

## Step 3: Config + DI (Combining Modules 4.3 + 5.2)

`appsettings.json`:

```json
{
  "ConnectionStrings": {
    "Library": "Data Source=library.db"
  },
  "Logging": { "LogLevel": { "Default": "Information" } }
}
```

`Program.cs`:

```csharp
using LibraryApi.Data;
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);

// Services — wire everything up here
builder.Services.AddControllers();
builder.Services.AddDbContext<LibraryDbContext>(options =>
    options.UseSqlite(builder.Configuration.GetConnectionString("Library")));

// CORS — for React (5.5)
builder.Services.AddCors(options =>
    options.AddPolicy("Frontend", p =>
        p.WithOrigins("http://localhost:3000").AllowAnyHeader().AllowAnyMethod()));

var app = builder.Build();

app.UseCors("Frontend");
app.MapControllers();

app.Run();
```

**`builder.Services` = DI registrations** (the 4.3 config + 5.2 DbContext pattern). `GetConnectionString("Library")` reads from config.

## Step 4: Create the Table via Migration

```bash
dotnet tool install --global dotnet-ef        # first time only
dotnet ef migrations add InitialCreate --startup-project .
dotnet ef database update
```

You'll see logs like `CreateTable "Books"` in the terminal — **the `library.db` file got created.** (If migrations give you trouble, there's a shortcut: `db.Database.EnsureCreated()` — but migrations are the production path.)

For now, add 2 books (or later via the API):

```csharp
// At the end of Program.cs (before app.Run()) — optional seed
using (var scope = app.Services.CreateScope())
{
    var db = scope.ServiceProvider.GetRequiredService<LibraryDbContext>();
    if (!db.Books.Any())
    {
        db.Books.AddRange(
            new Book { Title = "Clean Code", Author = "Robert Martin", Price = 499, Available = 3, Genre = "Programming" },
            new Book { Title = "The Pragmatic Programmer", Author = "Hunt & Thomas", Price = 550, Available = 2, Genre = "Programming" }
        );
        db.SaveChanges();
    }
}
```

A scope gives a new context (DI outside a request) — the `if (!db.Books.Any())` check means re-running won't create duplicates.

## What This Is NOT

- **Model class ≠ DTO** — right now `Book` does both jobs (small project), but the next file will have separate `CreateBookDto`s (the 5.2 rule).
- **Don't hand-write migration files** — EF generates them. Change the model → `migrations add` → `update`.
- **Seed data is optional** — the main thing is the CRUD API; seed is only for testing.

## In Your Own Words

1. What were the first 3 steps when creating the project — in order?

<details>
<summary>Sample Jawab</summary>

**Jawab:** (1) First think through the data model (Book's fields and types — decimal for price), (2) `dotnet new webapi` + EF packages, (3) Model class + DbContext + connection string + DI registration, (4) create the DB table via migration. Think → build → DB → then endpoints.

</details>

2. How do `AddDbContext` and `AddCors` connect in `Program.cs` — and what does `MapControllers` do?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Both register into `builder.Services` (the DI container) — things that get resolved per request. `MapControllers` tells the routing pipeline that `/api/...` requests should match the `[Route]`/`[HttpGet]` attributes in the `Controllers/` folder.

</details>

3. What do `dotnet ef migrations add` + `database update` do — and why are they better than `EnsureCreated`?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `add` has EF inspect model changes and create a migration file (schema diff); `update` applies it to the DB — history is kept, version-controlled, and future changes (a new column) are handled. `EnsureCreated` only creates the DB the first time; it can't apply changes.

</details>

4. Why `decimal` for price — and why `if (!db.Books.Any())` for seed data?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Decimal is exact; double has floating-point rounding errors — unacceptable for money. The `Any()` check means seed runs only the first time — re-running `dotnet run` won't create duplicate books.

</details>
