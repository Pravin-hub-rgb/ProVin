## Test checklist — Postman/Swagger se har case

Yeh checklist copy kar lo — har project ke liye kaam aayegi:

**Happy path (sab sahi):**
```
GET    /api/books             → 200, items array + total
GET    /api/books/1           → 200, book object
POST   /api/books (sahi body) → 201 + Location header
PUT    /api/books/1 (body)    → 200
DELETE /api/books/2           → 204
```

**Edge cases (har test mein yahi dhundho):**
```
GET    /api/books/999          → 404 { "error": "Book not found" }
POST   /api/books {khali body} → 400 (validation — Title required)
POST   /api/books {price: -5}  → 400 (Range validation)
GET    /api/books?page=0&pageSize=999 → page=1, pageSize=50 (clamp kaam kar raha)
GET    /api/books/search?q=clean       → sirf match wali
DELETE /api/books/999          → 404
```

**Galat body (kal ka format):**
```
PUT /api/books/1 { "name": "wrong-field" } → 400 — DTO nahi bana
```

Har case ka response note karo — ye table README mein bhi daal sakte ho.

## React se jodna (5.5 wala flow — ab asli)

`http://localhost:3000` wale React app mein:

```javascript
const API = import.meta.env.VITE_API_URL;   // http://localhost:5231

export async function fetchBooks(page = 1) {
  const res = await fetch(`${API}/api/books?page=${page}&pageSize=10`);
  if (!res.ok) throw new Error("Failed to load books");
  return res.json();       // { page, pageSize, total, items }
}

export async function addBook(book) {
  const res = await fetch(`${API}/api/books`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(book),
  });
  if (!res.ok) {
    const err = await res.json();
    throw new Error(err.error);     // structured error — 6.3 wala
  }
  return res.json();
}
```

**Sabse aam pehli dikkat:** CORS. API restart karo policy change ke baad, aur `WithOrigins` mein React URL (`http://localhost:3000`) sahi hai na — port bhi.

## In Your Own Words

1. POST `/api/books` mein `201` aur GET mein `200` — kyun alag, aur `Location` header kya batata hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** 201 = "nayi cheez bani" (POST ka success), 200 = general OK (GET/PUT). Location header mein nayi resource ka URL (`/api/books/3`) — client ko pata chalta hai ki woh resource ab kahan milti hai. REST conventions hain — tooling isi se kaam karti hai.

</details>

2. Edge-case testing checklist mein 4 cases likho jo CRUD API ke zaroori hain.

<details>
<summary>Sample Jawab</summary>

**Jawab:** (1) Nahi mila → 404 structured error, (2) Galat/missing body → 400 validation, (3) Extreme inputs (`page=0`, `pageSize=99999`) → clamp/sanitize, (4) Galat method/route → 404/405. Happy path (200/201) ke saath yahi 4 har complete API mein zaroori hain.

</details>

3. React ke `addBook` mein `res.ok` check aur `err.error` padhna kyun zaroori hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `fetch` network error nahi deta 400/404 pe — `res.ok` hi batata hai ki fail hua. Backend ka structured `{error}` padh kar user ko sahi message dikhate hain (validation message), warna UI mein generic "failed" aata ya response ignore ho jaata.

</details>
