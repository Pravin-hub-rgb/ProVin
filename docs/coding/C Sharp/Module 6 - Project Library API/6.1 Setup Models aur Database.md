# Project Setup — Models aur Database

## Pehle socho — data model kya hoga

Code se pehle 2 minute sochna — senior wali aadat. Library mein kya hai?

- **Book** — title, author, genre, price, available (kitni copies)
- (Zyada complex banane ki zaroorat nahi — interview ke liye 1 table ka clean project kaafi)

```
Book:
  Id        int (PK, auto)
  Title     string (required, max 200)
  Author    string (required, max 100)
  Genre     string? (optional)
  Price     decimal (money!)
  Available int (copies)
  CreatedAt DateTime
```

Ab banao:

```bash
dotnet new webapi -n LibraryApi
cd LibraryApi
dotnet add package Microsoft.EntityFrameworkCore.Sqlite
```

(SQL Server company mein, practice ke liye SQLite — file-based, kuch install nahi.)

## Step 1: Model (DB table)

`Models/Book.cs`:

```csharp
using System.ComponentModel.DataAnnotations;

namespace LibraryApi.Models;

public class Book
{
    public int Id { get; set; }                    // PK — DB auto badhayegi

    [Required, StringLength(200)]
    public string Title { get; set; } = "";

    [Required, StringLength(100)]
    public string Author { get; set; } = "";

    [StringLength(50)]
    public string? Genre { get; set; }             // optional — null ho sakta hai

    public decimal Price { get; set; }              // ⭐ money = decimal (4.1 wala)

    public int Available { get; set; }

    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
}
```

Dekho kya use hua:

- **`namespace LibraryApi.Models`** — har file namespace mein (module 2.4)
- **Attributes** — validation jo API pe auto lagega (5.3)
- **`decimal`** — price ke liye (4.1)
- **`string?`** — optional genre

## Step 2: DbContext (DB ka door)

`Data/LibraryDbContext.cs`:

```csharp
using LibraryApi.Models;
using Microsoft.EntityFrameworkCore;

namespace LibraryApi.Data;

public class LibraryDbContext : DbContext
{
    public LibraryDbContext(DbContextOptions<LibraryDbContext> options) : base(options) { }

    public DbSet<Book> Books => Set<Book>();     // → Books table
}
```

Module 4.2 jaisa — constructor se options (connection string) aate hain DI ke through.

## Step 3: Config + DI (module 4.3 + 5.2 jod ke)

`appsettings.json`:

```json
{
  "ConnectionStrings": {
    "Library": "Data Source=library.db"
  },
  "Logging": { "LogLevel": { "Default": "Information" } }
}
```

`Program.cs`:

```csharp
using LibraryApi.Data;
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);

// Services — yahan sab jodte hain
builder.Services.AddControllers();
builder.Services.AddDbContext<LibraryDbContext>(options =>
    options.UseSqlite(builder.Configuration.GetConnectionString("Library")));

// CORS — React ke liye (5.5)
builder.Services.AddCors(options =>
    options.AddPolicy("Frontend", p =>
        p.WithOrigins("http://localhost:3000").AllowAnyHeader().AllowAnyMethod()));

var app = builder.Build();

app.UseCors("Frontend");
app.MapControllers();

app.Run();
```

**`builder.Services` = DI registrations** (4.3 config + 5.2 DbContext wala pattern). `GetConnectionString("Library")` config se.

## Step 4: Migration se table banao

```bash
dotnet tool install --global dotnet-ef        # pehli baar
dotnet ef migrations add InitialCreate --startup-project .
dotnet ef database update
```

Terminal mein logs aayenge `CreateTable "Books"` — **`library.db` file ban gayi.** (Migration mein issue aaye toh shortcut: `db.Database.EnsureCreated()` — par production wala raasta migrations hi hai.)

Abhi ke liye 2 books daal do (ya baad mein API se):

```csharp
// Program.cs ke end mein (app.Run() se pehle) — optional seed
using (var scope = app.Services.CreateScope())
{
    var db = scope.ServiceProvider.GetRequiredService<LibraryDbContext>();
    if (!db.Books.Any())
    {
        db.Books.AddRange(
            new Book { Title = "Clean Code", Author = "Robert Martin", Price = 499, Available = 3, Genre = "Programming" },
            new Book { Title = "The Pragmatic Programmer", Author = "Hunt & Thomas", Price = 550, Available = 2, Genre = "Programming" }
        );
        db.SaveChanges();
    }
}
```

Scope se naya context milta hai (request ke bahar DI) — `if (!db.Books.Any())` se dobara run pe duplicate nahi.

## Folder structure ab


## Yeh kya NAHI hai

- **Model class = DTO nahi** — abhi `Book` dono kaam kar raha hai (chhota project), par agle file mein `CreateBookDto` alag honge (5.2 wala rule).
- **Migration file haath se likhna nahi** — EF khud banata hai. Model badlo → `migrations add` → `update`.
- **Seed data optional hai** — main CRUD API hai; seed sirf test karne ke liye.

## In Your Own Words

1. Project banate waqt pehle 3 kadam kaunse the — order ke saath.

<details>
<summary>Sample Jawab</summary>

**Jawab:** (1) Pehle data model socha (Book ke fields, types — decimal for price), (2) `dotnet new webapi` + EF packages, (3) Model class + DbContext + connection string + DI registration, (4) migration se DB table. Sochna → banana → DB → phir endpoints.

</details>

2. `Program.cs` mein `AddDbContext` aur `AddCors` kis tarike se jud rahe hain — aur `MapControllers` ka kya kaam?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Dono `builder.Services` (DI container) mein register hote hain — services/request pe milne wali cheezein. `MapControllers` batata hai ki `/api/...` requests `Controllers/` folder ke `[Route]`/`[HttpGet]` attributes se match karein — routing pipeline mein.

</details>

3. `dotnet ef migrations add` + `database update` kya karta hai — `EnsureCreated` se kyun behtar?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `add` se EF model changes dekh kar migration file (schema diff) banti hai, `update` se wo DB pe apply hoti hai — history rehti hai, version control, aur future changes (naya column) handle ho jaate hain. `EnsureCreated` sirf pehli baar banata hai, changes nahi.

</details>

4. Price ke liye `decimal` kyun — aur seed data `if (!db.Books.Any())` kyun?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Decimal exact hai, double floating-point rounding galti karta hai — paise mein galti. `Any()` check se seed sirf pehli baar chalta hai — dobara `dotnet run` pe duplicate books nahi banti.

</details>
