# Search, Pagination aur Error Handling

## Search — query parameter se (5.2 wala concept)

`BooksController` mein naya endpoint:

```csharp
// GET /api/books/search?q=kurtzweil&genre=Programming&maxPrice=600
[HttpGet("search")]
public async Task<IActionResult> Search(
    [FromQuery] string? q,
    [FromQuery] string? genre,
    [FromQuery] decimal? maxPrice)
{
    var query = _db.Books.AsQueryable();      // "abhi tak kuch nahi bheja"

    if (!string.IsNullOrWhiteSpace(q))
        query = query.Where(b =>
            b.Title.Contains(q) || b.Author.Contains(q));

    if (!string.IsNullOrWhiteSpace(genre))
        query = query.Where(b => b.Genre == genre);

    if (maxPrice is not null)
        query = query.Where(b => b.Price <= maxPrice);

    var books = await query
        .OrderBy(b => b.Title)
        .Select(b => new BookDto(b.Id, b.Title, b.Author, b.Genre, b.Price, b.Available))
        .ToListAsync();

    return Ok(books);
}
```

Dekho kya sika:

- **`[FromQuery]`** — value URL `?q=` se aayegi (bina bhi bind ho jaata hai, par explicit = clear)
- **`IQueryable` = lazy query builder** (LINQ wala lazy — module 3.1!) — `.Where()` sirf SQL mein condition jodta hai, `.ToListAsync()` pe hi DB pe hit hota hai. Ek saath saari conditions judti hain — **SQL `WHERE q AND genre AND price` ban ke ek query jaati hai**
- **`||` (OR)** title ya author dono

`string.Contains` → SQL mein `LIKE '%q%'` — EF khud translate karta hai.

## Pagination — 1000 books load mat karo

```csharp
// GET /api/books?page=2&pageSize=10
[HttpGet]                    // upar wale GetAll ki jagah ye version
public async Task<IActionResult> GetAll(
    [FromQuery] int page = 1,
    [FromQuery] int pageSize = 10)
{
    page = Math.Max(1, page);                 // 0 ya negative aaya toh 1
    pageSize = Math.Clamp(pageSize, 1, 50);   // 1-50 ke beech — ⭐ abuse se bachna

    var total = await _db.Books.CountAsync();   // total kitni

    var books = await _db.Books
        .OrderBy(b => b.Id)
        .Skip((page - 1) * pageSize)         // itni chhod do
        .Take(pageSize)                      // itni lo
        .ToListAsync();

    return Ok(new
    {
        page,
        pageSize,
        total,
        items = books
    });
}
```

**`Skip/Take` = SQL `LIMIT/OFFSET`** — DB pe hi page banta hai, memory mein saari books nahi. Response envelope:

```json
{
  "page": 2, "pageSize": 10, "total": 37,
  "items": [ ...10 books... ]
}
```

**`Math.Clamp(pageSize, 1, 50)`** — client `pageSize=99999` bhej de toh DB load na ho — input pe limit = simple security/performance (5.3 wali validation ka extension).

## Errors — structured aur consistent

Abhi tak alag-alag jagah `new { error = "..." }` likha — ab ek helper se:

`Infrastructure/ApiResult.cs` (ya jo naam pasand ho):

```csharp
namespace LibraryApi.Infrastructure;

public static class Errors
{
    public static IResult NotFound(string what) =>
        Results.NotFound(new { error = $"{what} not found" });

    public static IResult BadRequest(string message) =>
        Results.BadRequest(new { error = message });

    // Validation errors — ek field ke against
    public static IResult Invalid(string field, string message) =>
        Results.BadRequest(new { error = message, field });
}
```

Ab endpoints mein:

```csharp
if (book is null) return Errors.NotFound("Book");
```

**Consistent shape** (5.3): `{ "error": "...", "field": "..." }` — React ek hi jagah handle karega:

```javascript
const data = await res.json();
if (!res.ok) setMessage(data.error);    // hamesha wahi format
```

Aur global middleware ek baar (5.3 wala — Program.cs):

```csharp
app.UseExceptionHandler(err => err.Run(async ctx =>
{
    ctx.Response.StatusCode = 500;
    await ctx.Response.WriteAsJsonAsync(new { error = "Something went wrong" });
}));
```

Ab har jagah errors ek jaise — 400 (client galti), 404 (nahi mila), 500 (server, generic).

## Validation ab bhi double layer

- **DTO/Model attributes** → auto 400 (pehla layer)
- **Business if** → `Errors.BadRequest("Stock kam hai")` jaise rules (doosri layer)

```csharp
// Example business rule — borrow endpoint ke liye
if (book.Available <= 0)
    return Errors.BadRequest("No copies available");
```

Framework validation format ke liye, `if` logic ke liye — dono milte hain (5.3).

## Yeh kya NAHI hai

- **`Skip/Take` ke bina pagination = fake** — agar pehle `.ToListAsync()` karke list ke `[0..10]` le rahe ho, toh poori table load ho rahi hai — DB pe hi Skip/Take karo (`IQueryable` pe hi rakhna).
- **`pageSize` client pe chhodna nahi** — clamp/limit zaroori, warna `pageSize=1000000` wali request server gira sakti hai.
- **Error messages mein internals nahi** — `"SQL syntax error at line 4"` jaisa kabhi nahi; generic + log server pe.

## In Your Own Words

1. `IQueryable` pe `.Where()` baar-baar lagane ka faayda kya hai — ek query kab DB pe jaati hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Har `.Where()` sirf SQL condition **add** karta hai (lazy), DB pe nahi jaata. `.ToListAsync()`/`.Count()` pe saari conditions ek saath SQL `WHERE ... AND ...` ban ke **ek hi query** jaati hai. Isliye 3 filters = 1 round-trip, aur filter DB pe hoti hai (memory mein poori table nahi).

</details>

2. `Math.Clamp(pageSize, 1, 50)` kyun — client `pageSize=999999` bheje toh kya hota?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Warna client ek request mein poori DB (ya bahut badi rows) maang leta hai — server/memory pe load, DoS jaisa misuse. Clamp se limit fix hai (max 50) — pagination ka point hi hai ki chhote pages lo; input pe limit = performance + security.

</details>

3. Search endpoint mein `q`, `genre`, `maxPrice` optional hain — code mein kaise handle, aur SQL kaisa banta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Har parameter `if (!string.IsNullOrWhiteSpace(...))` / `if (x is not null)` se sirf tab add hota hai jab value ho — warna filter rehne deta hai (optional behavior). SQL mein sirf diye gaye filters `AND` se judte hain — sab empty ho toh saari books.

</details>

4. Structured error `{error, field}` ka frontend ko kya faayda hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Client ek hi jagah handle kar sakta hai — `if (!res.ok) show(data.error)`, aur `field` se specific input ke neeche message dikha sakta hai. Random HTML/text messages aate toh har jagah alag parsing karni padti — consistency = maintainable frontend.

</details>
