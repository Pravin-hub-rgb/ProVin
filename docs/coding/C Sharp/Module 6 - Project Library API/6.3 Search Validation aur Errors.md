# CRUD Endpoints — BookController

## DTOs First (the 5.2 Rule — Applied in the Project)

`Models/BookDtos.cs`:

```csharp
namespace LibraryApi.Models;

// Coming from the client (POST/PUT)
public record CreateBookDto(
    string Title,
    string Author,
    string? Genre,
    decimal Price,
    int Available
);

// Going out (response)
public record BookDto(int Id, string Title, string Author, string? Genre, decimal Price, int Available);
```

> Validation attributes live on the Model (`Book`) (6.1) — `[ApiController]` checks them against the DTO as long as the types match. For extra safety you can put them on the DTO too; the Model ones are enough for this project.

## Controller — Full CRUD

`Controllers/BooksController.cs`:

```csharp
using LibraryApi.Data;
using LibraryApi.Models;
using Microsoft.AspNetCore.Mvc;
using Microsoft.EntityFrameworkCore;

namespace LibraryApi.Controllers;

[ApiController]
[Route("api/books")]           // /api/books — the [controller] trick works too
public class BooksController : ControllerBase
{
    private readonly LibraryDbContext _db;

    public BooksController(LibraryDbContext db)   // DI — the 5.2 way
    {
        _db = db;
    }

    // GET /api/books
    [HttpGet]
    public async Task<IActionResult> GetAll()
    {
        var books = await _db.Books
            .OrderBy(b => b.Title)
            .Select(b => new BookDto(b.Id, b.Title, b.Author, b.Genre, b.Price, b.Available))
            .ToListAsync();

        return Ok(books);
    }

    // GET /api/books/5
    [HttpGet("{id:int}")]       // constraint: numbers only
    public async Task<IActionResult> GetById(int id)
    {
        var book = await _db.Books.FindAsync(id);
        if (book is null) return NotFound(new { error = "Book not found" });

        return Ok(new BookDto(book.Id, book.Title, book.Author, book.Genre, book.Price, book.Available));
    }

    // POST /api/books
    [HttpPost]
    public async Task<IActionResult> Create(CreateBookDto dto)
    {
        var book = new Book
        {
            Title = dto.Title,
            Author = dto.Author,
            Genre = dto.Genre,
            Price = dto.Price,
            Available = dto.Available
        };

        _db.Books.Add(book);
        await dbSave();          // helper below — next point

        var outDto = new BookDto(book.Id, book.Title, book.Author, book.Genre, book.Price, book.Available);
        return CreatedAtAction(nameof(GetById), new { id = book.Id }, outDto);   // 201
    }

    // PUT /api/books/5
    [HttpPut("{id:int}")]
    public async Task<IActionResult> Update(int id, CreateBookDto dto)
    {
        var book = await _db.Books.FindAsync(id);
        if (book is null) return NotFound(new { error = "Book not found" });

        book.Title = dto.Title;          // fields updated (EF change tracker catches it)
        book.Author = dto.Author;
        book.Genre = dto.Genre;
        book.Price = dto.Price;
        book.Available = dto.Available;

        await dbSave();
        return Ok(new BookDto(book.Id, book.Title, book.Author, book.Genre, book.Price, book.Available));
    }

    // DELETE /api/books/5
    [HttpDelete("{id:int}")]
    public async Task<IActionResult> Delete(int id)
    {
        var book = await _db.Books.FindAsync(id);
        if (book is null) return NotFound(new { error = "Book not found" });

        _db.Books.Remove(book);
        await dbSave();
        return NoContent();              // 204 — nothing back, job done
    }

    private async Task dbSave()
    {
        try
        {
            await _db.SaveChangesAsync();
        }
        catch (DbUpdateException ex)
        {
            // DB-level error (constraint etc.)
            Console.WriteLine(ex.Message);
            throw;   // middleware returns 500 (see 5.3)
        }
    }
}
```

**Every endpoint follows the same pattern** (the formula to remember):

```
[HttpMethod("{params}")] → find in DbContext → null? NotFound → do the work → SaveChanges → response with status
```

Status code map:

| Situation | Response |
|---|---|
| GET found | `200 Ok` + data |
| GET/PUT/DELETE not found | `404 NotFound` |
| POST created | `201 Created` + Location header |
| PUT/DELETE done | `200 Ok` / `204 NoContent` |
| Validation failed | `400 BadRequest` (auto) |

`CreatedAtAction` — along with 201, it also puts the new resource's URL in the header (`/api/books/3`) — the polite REST way.

## Smell Check — One Mistake You Made

Above I wrote `await dbSave()` in `Create` — actually you should just write **`await _db.SaveChangesAsync()`** (as in 6.1/5.2). The `dbSave()` helper is optional — if you want it simple, write directly:

```csharp
await _db.SaveChangesAsync();
```

No need for try-catch everywhere — the error middleware (5.3) covers all of it. **Keep it simple** — the motto of this crash course.

## What This Is NOT

- **`Select(BookDto...)` in every endpoint is not optional — but strongly recommended** — if you just do `Ok(book)`, the day you add `CreatedById`/internals to `Book`, those leak out too. The DTO boundary = the contract.
- **PUT = full update** (the whole object), PATCH = partial (advanced, skip for now). Remember the difference.
- **Don't catch `DbUpdateException` and swallow** — log/throw (the middleware handles it). Swallowing = hiding bugs.

## In Your Own Words

1. State the 5-step formula for a CRUD endpoint (the pattern from GET through DELETE).

<details>
<summary>Sample Jawab</summary>

**Jawab:** (1) Route + HTTP method attribute, (2) fetch data from DbContext (`FindAsync`/`ToListAsync`), (3) if not found → `NotFound()` — early return, (4) do the work (create/update/remove) + `SaveChangesAsync()`, (5) respond with the right status (Ok/Created/NoContent) + data in a DTO.

</details>

2. Why `CreatedAtAction` in POST — and what does it send?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Along with 201 Created, a `Location` header — the new resource's URL (`/api/books/3`). REST convention: the client learns where the new thing lives (to GET it next) — more informative than a plain 200.

</details>

3. Why return `BookDto` instead of the raw `Book` — what could go wrong right now?

<details>
<summary>Sample Jawab</summary>

**Jawab:** The model keeps changing — tomorrow an `InternalNotes` or `VendorPassword` field gets added and a raw `Ok(book)` would leak it through the API. The DTO is a stable contract — only what you want shown goes out, and the model/DB internals stay hidden.

</details>

4. `200` vs `204` after DELETE — what's the difference and which works?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `204 NoContent` = done, no data back (common for DELETE/PUT); `200 Ok` = data/response body also sent. Both valid — 204 is more precise when you don't need a body.

</details>
