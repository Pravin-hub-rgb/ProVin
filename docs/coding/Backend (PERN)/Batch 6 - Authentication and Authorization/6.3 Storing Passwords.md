# Doc 6.3 — Storing Passwords

## Cheat Sheet (Quick Recall)

- Never store plain text passwords.
- Use slow hashing (Argon2id recommended, bcrypt legacy).
- Salt prevents rainbow table attacks.
- `argon2` package for Argon2id.
- Never log passwords.

Passwords must be hashed, never stored in plain text.

```ts
import argon2 from "argon2";

// Hash
const hash = await argon2.hash("password123");

// Verify
const valid = await argon2.verify(hash, "password123");
```

- **Plain text:** never store (database leak = all passwords exposed).
- **Fast hash (SHA-256):** too fast — brute-forceable.
- **Slow hash (Argon2id):** intentional delay makes brute-force expensive.
- **Salt:** random per-password, prevents rainbow tables.
- **bcrypt:** legacy, still common in codebases.

**Break it on purpose:** hash the same password twice and compare (different salts → different hashes).

## What It Is NOT

- Hashing is **not** encryption — hashing is one-way, encryption is reversible.
- Plain text is **not** acceptable — never store.
- Fast hashing is **not** safe — use slow hashing.

---

## Common Mistakes

- Storing plain text passwords.
- Using fast hashing (SHA-256).
- Logging passwords (even in debug).
- Not salting (rainbow table attacks).

---

## Try It Yourself

1. Hash and verify with Argon2id.
2. Compare timing with a fast hash.
3. Hash the same password twice and compare.

## Summary

- Never store plain text.
- Use Argon2id (slow hash + salt).
- bcrypt is legacy.
- Never log passwords.
