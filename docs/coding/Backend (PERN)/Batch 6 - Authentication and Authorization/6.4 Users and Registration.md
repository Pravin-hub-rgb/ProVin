A `User` model through a migration, a registration endpoint with Zod validation, 409 on duplicate email, and a response that never includes the hash.

```prisma
model User {
  id           String   @id @default(uuid())
  email        String   @unique
  passwordHash String
  role         Role     @default(USER)
  createdAt    DateTime @default(now())
}

enum Role {
  USER
  ADMIN
}
```

```ts
app.post("/auth/register", validate(registerSchema), async (req, res) => {
  const { email, password } = req.body;
  const existing = await prisma.user.findUnique({ where: { email } });
  if (existing) {
    res.status(409).json({ error: { code: "CONFLICT", message: "Email already registered" } });
    return;
  }
  const hash = await argon2.hash(password);
  const user = await prisma.user.create({
    data: { email, passwordHash: hash },
    select: { id: true, email: true, role: true, createdAt: true },
  });
  res.status(201).json({ data: user });
});
```

- `User` model with unique email, hashed password, role.
- Registration validates with Zod.
- 409 on duplicate email.
- Response excludes `passwordHash`.

## What It Is NOT

- Password hash is **not** in the response — never leak it.
- Registration is **not** authentication — it creates the account.
- `role` default is **not** admin — it is `user`.

---

## Common Mistakes

- Returning password hash in response.
- Not checking for duplicate email (409).
- Not hashing password before storing.
