# Doc 6.7 — Refresh Tokens

## Cheat Sheet (Quick Recall)

- Short-lived access token + opaque rotating refresh token.
- Refresh token in httpOnly cookie, stored hashed in DB.
- Rotate on every use.
- Reuse detection: revoke entire family on reuse.
- Logout revokes refresh token.

Short-lived access tokens need a way to renew. The refresh token is an opaque random value (not a JWT), sent only in an httpOnly cookie, stored hashed in Postgres, rotated on every use, and revoked on logout.

```ts
// Refresh endpoint
app.post("/auth/refresh", async (req, res) => {
  const refreshToken = req.cookies.refreshToken;
  if (!refreshToken) {
    res.status(401).json({ error: { code: "UNAUTHORIZED", message: "Missing refresh token" } });
    return;
  }
  // verify hashed token in DB, rotate, issue new access token
  // ...
});
```

- **Access token:** short-lived (15 min), JWT, sent in header.
- **Refresh token:** opaque random value, httpOnly cookie, hashed in DB.
- **Rotation:** new refresh token on every use.
- **Reuse detection:** if an already-used refresh token appears again, revoke the whole family.
- **Logout:** revoke refresh token.

```
Login → access token (15m) + refresh token (httpOnly cookie)
  ↓
Access token expires
  ↓
POST /auth/refresh → new access token + new refresh token (rotation)
  ↓
Logout → revoke refresh token family
```

## What It Is NOT

- Refresh token is **not** a JWT — it is an opaque random value.
- Rotation is **not** optional — it limits damage from theft.
- Reuse detection is **not** optional — it detects token theft.

---

## Common Mistakes

- Storing refresh token in localStorage (XSS theft).
- Not rotating (stolen token valid forever).
- Not detecting reuse (theft goes unnoticed).
