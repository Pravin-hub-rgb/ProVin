# Doc 6.2 — Cookies in Practice

## Cheat Sheet (Quick Recall)

- `Set-Cookie` header sets a cookie.
- Attributes: `httpOnly`, `Secure`, `SameSite`, `Path`, `Max-Age`/`Expires`.
- `httpOnly`: JS cannot read (XSS protection).
- `Secure`: only over HTTPS.
- `SameSite`: CSRF protection (Strict/Lax/None).

Cookies are small data stored by the browser and sent automatically with requests.

```ts
res.set("Set-Cookie", "token=abc123; HttpOnly; Secure; SameSite=Strict; Path=/; Max-Age=3600");
```

- **`httpOnly`:** JavaScript cannot read (XSS protection).
- **`Secure`:** only sent over HTTPS.
- **`SameSite`:** CSRF protection. `Strict` (no cross-site), `Lax` (top-level navigation), `None` (with Secure).
- **`Path`:** which paths the cookie applies to.
- **`Max-Age`/`Expires`:** lifetime.

**Break it on purpose:** read a cookie from JavaScript when `httpOnly` is off, then when it is on.

## What It Is NOT

- `httpOnly` is **not** optional for tokens — it prevents XSS theft.
- `Secure` is **not** for development (localhost is OK without it).
- `SameSite=Strict` is **not** for cross-site requests.

---

## Common Mistakes

- Not setting `httpOnly` (XSS theft).
- Not setting `Secure` in production.
- Wrong `SameSite` (CSRF vulnerability).
