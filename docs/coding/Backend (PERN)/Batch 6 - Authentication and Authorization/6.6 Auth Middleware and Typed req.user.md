# Doc 6.6 — Auth Middleware and Typed req.user

## Cheat Sheet (Quick Recall)

- Read token from `Authorization: Bearer <token>`.
- Verify with `jose` (`jwtVerify`).
- Attach user to `req.user`.
- Reject with 401 if invalid/missing.
- Extend Express's `Request` type via declaration merging.

Read the token, verify it, attach the user to the request, reject with 401 otherwise.

```ts
import { jwtVerify } from "jose";

// Extend Express Request type
declare global {
  namespace Express {
    interface Request {
      user?: { id: string; role: string };
    }
  }
}

async function authMiddleware(req, res, next) {
  const header = req.get("Authorization");
  const token = header?.startsWith("Bearer ") ? header.slice(7) : null;
  if (!token) {
    res.status(401).json({ error: { code: "UNAUTHORIZED", message: "Missing token" } });
    return;
  }
  try {
    const secret = new TextEncoder().encode(process.env.JWT_SECRET);
    const { payload } = await jwtVerify(token, secret);
    req.user = { id: payload.sub as string, role: payload.role as string };
    next();
  } catch {
    res.status(401).json({ error: { code: "UNAUTHORIZED", message: "Invalid token" } });
  }
}

// Usage
app.get("/me", authMiddleware, (req, res) => {
  res.json({ data: req.user });
});
```

- `jwtVerify(token, secret)` verifies the token.
- `req.user` attached for downstream handlers.
- Declaration merging types `req.user` everywhere.
- Reject with 401 on missing/invalid token.

## What It Is NOT

- `req.user` is **not** automatic — you must attach it.
- Middleware is **not** a route — it runs before the handler.
- `jwtVerify` is **not** `decode` — it verifies the signature.

---

## Common Mistakes

- Not attaching `req.user` (downstream handlers fail).
- Not handling missing token (crash).
- Using `decode` instead of `verify` (no signature check).
