Why a message to a user on another server instance needs a shared channel, with Redis as the usual answer. One paragraph, no build.

When you have multiple server instances behind a load balancer, a WebSocket connection on Server A cannot directly send a message to a client connected to Server B. Naive broadcasting (iterating `wss.clients`) only reaches clients on the same instance. The solution: Redis pub/sub — Server A publishes a message to a Redis channel, Server B subscribes and forwards it to its clients. This is the "scaling beyond one server" problem and Redis is the usual answer.

## What It Is NOT

- This is **not** built in this course — preview only.
- Naive broadcasting is **not** sufficient for multi-instance.
- Redis pub/sub is **not** the only solution — but it is the usual one.
