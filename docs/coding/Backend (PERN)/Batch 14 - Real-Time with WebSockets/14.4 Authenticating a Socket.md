Connections cannot send arbitrary headers from a browser. Authenticate during or right after the handshake. Never trust a message just because the socket is open.

```ts
import { WebSocketServer } from "ws";
import { jwtVerify } from "jose";

const wss = new WebSocketServer({ port: 8080 });

wss.on("connection", async (ws, req) => {
  const token = new URL(req.url!, "http://localhost").searchParams.get("token");
  if (!token) { ws.close(4001, "Missing token"); return; }
  try {
    const secret = new TextEncoder().encode(process.env.JWT_SECRET);
    const { payload } = await jwtVerify(token, secret);
    (ws as any).userId = payload.sub;
  } catch {
    ws.close(4001, "Invalid token");
    return;
  }
  ws.on("message", (data) => {
    // trust req.user, not the message
    console.log(`User ${(ws as any).userId}: ${data}`);
  });
});
```

- **Token in query param:** `?token=...` (browser cannot set headers).
- **Verify on connection:** reject invalid/missing.
- **Store userId on ws object:** use it, not message data.
- **Never trust message alone:** socket open ≠ authenticated.

## What It Is NOT

- Socket open is **not** authenticated — verify token.
- Message data is **not** trusted — use `ws.userId`.
- Browser cannot send **arbitrary headers** — use query param.

---

## Common Mistakes

- Trusting any message on open socket.
- Not verifying token on connection.
- Storing token in message (insecure).
