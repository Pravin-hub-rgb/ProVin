# Doc 14.1 — HTTP versus a Persistent Connection

## Cheat Sheet (Quick Recall)

- HTTP: request/response, then connection closes.
- Persistent: open channel, server pushes data.
- Polling: client asks repeatedly (wasteful).
- Server-Sent Events: server pushes (one-way).
- WebSockets: bidirectional persistent connection.

HTTP is request/response. WebSockets are persistent. First polling (wasteful), then SSE (one-way), then WebSockets (bidirectional).

- **HTTP:** request → response → close.
- **Polling:** client asks repeatedly (wasteful).
- **SSE:** server pushes (one-way, text).
- **WebSockets:** bidirectional persistent connection.

## What It Is NOT

- HTTP is **not** persistent — connection closes after response.
- Polling is **not** efficient — wastes bandwidth.
- SSE is **not** bidirectional — server-to-client only.

---

## Common Mistakes

- Using polling when WebSockets are needed.
- Not understanding SSE limitations.
- Ignoring connection lifecycle.
