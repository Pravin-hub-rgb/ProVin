Repeatable jobs run once even with several instances. Replaces `node-cron`.

```ts
// Repeatable job (runs every 60 seconds)
await queue.add("cleanup", {}, { repeat: { every: 60000 } });

// Cron pattern
await queue.add("nightly", {}, { repeat: { pattern: "0 2 * * *" } });
```

- `repeat: { every: ms }` — interval.
- `repeat: { pattern: cron }` — cron schedule.
- Single execution guaranteed (Redis-backed).
- Replaces `node-cron` (no duplicate runs).

## What It Is NOT

- Repeatable jobs are **not** `setInterval` — they run once.
- `node-cron` is **not** needed — BullMQ handles scheduling.
- Duplicate runs are **not** acceptable — BullMQ guarantees single execution.

---

## Common Mistakes

- Using `node-cron` with multiple instances (duplicate runs).
- Not using repeatable jobs.
- Wrong cron pattern.
