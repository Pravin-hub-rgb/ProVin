Retries with backoff, concurrency limits, delayed jobs, failed-job handling, and idempotent jobs.

```ts
const worker = new Worker("tasks", async (job) => {
  await checkUrl(job.data.url);
}, {
  connection,
  concurrency: 5,
});

// Job with retry
await queue.add("check-url", { url }, {
  attempts: 3,
  backoff: { type: "exponential", delay: 1000 },
  delay: 5000, // delayed job
});
```

- **Retries:** `attempts: 3` with backoff.
- **Backoff:** exponential (1s, 2s, 4s...).
- **Concurrency:** `concurrency: 5` (max 5 at a time).
- **Delayed jobs:** `delay: 5000` (run after 5s).
- **Idempotent jobs:** safe to retry (callback to 11.8).

**Break it on purpose:** make a job fail and watch the retries.

## What It Is NOT

- Retries are **not** infinite — set `attempts`.
- Backoff is **not** optional — prevents hammering.
- Jobs are **not** safe to retry unless idempotent.

---

## Common Mistakes

- Retrying forever with no backoff.
- Jobs not safe to run twice.
- No concurrency limit (overwhelms resources).
