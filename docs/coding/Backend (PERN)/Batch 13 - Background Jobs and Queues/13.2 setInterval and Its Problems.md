`setInterval` is the simplest scheduler, but it has many problems.

```ts
setInterval(async () => {
  await cleanupExpiredSessions();
}, 60 * 60 * 1000); // every hour
```

**Problems:**

- **Lost on restart:** if the process restarts, the interval is lost.
- **Overlapping runs:** if the job takes longer than the interval, it overlaps.
- **Runs twice with two instances:** two servers = two runs.
- **No retry:** if the job fails, it is not retried.

**Break it on purpose:** start two instances and watch duplicate work.

## What It Is NOT

- `setInterval` is **not** a job system — it is a timer.
- It is **not** reliable — lost on restart, no retry.
- It is **not** for production — use a queue.

---

## Common Mistakes

- Using `setInterval` for critical work.
- Not handling overlapping runs.
- Not handling failures.
