Jobs that fetch URLs a user provided create a server-side request forgery (SSRF) risk. Block private/local addresses, set timeouts and size limits, limit redirects.

```ts
import { URL } from "node:url";
import dns from "node:dns/promises";
import net from "node:net";

async function isSafeUrl(url: string): Promise<boolean> {
  const parsed = new URL(url);
  if (!["http:", "https:"].includes(parsed.protocol)) return false;

  const { address } = await dns.lookup(parsed.hostname);
  if (net.isIP(address) && isPrivateIP(address)) return false;

  return true;
}

function isPrivateIP(ip: string): boolean {
  return ip.startsWith("127.") || ip.startsWith("10.") || ip.startsWith("192.168.") || ip === "::1";
}
```

- **SSRF:** user-supplied URL targets internal service.
- **Block private ranges:** 127.0.0.0/8, 10.0.0.0/8, 192.168.0.0/16.
- **Timeouts:** prevent hanging.
- **Size limits:** prevent memory blowup.
- **Redirect limits:** prevent redirect to internal.

## What It Is NOT

- SSRF is **not** XSS — it is server-side.
- Blocking is **not** optional — internal services are at risk.
- Timeouts are **not** optional — hanging requests waste resources.

---

## Common Mistakes

- Fetching user-supplied URLs without blocking internal addresses.
- No timeouts or size limits.
- Unlimited redirects.
