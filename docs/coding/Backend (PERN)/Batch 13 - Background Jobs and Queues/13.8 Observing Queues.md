Logging job lifecycle, counting failures, a status endpoint.

```ts
worker.on("completed", (job) => {
  logger.info({ jobId: job.id, duration: job.finishedOn - job.processedOn }, "Job completed");
});

worker.on("failed", (job, err) => {
  logger.error({ jobId: job.id, err }, "Job failed");
});

// Status endpoint
app.get("/jobs/:id", async (req, res) => {
  const job = await queue.getJob(req.params.id);
  if (!job) { res.status(404).json({ error: { code: "NOT_FOUND" } }); return; }
  res.json({ data: { id: job.id, state: await job.getState(), progress: job.progress } });
});
```

- **Job lifecycle:** completed, failed, active.
- **Logging:** with job id and duration.
- **Failure count:** track failures.
- **Status endpoint:** check job state.

## What It Is NOT

- Observing is **not** optional — you need visibility.
- Logging is **not** just console.log — use structured logging (pino).
- Status endpoint is **not** for clients only — also for monitoring.

---

## Common Mistakes

- No logging (blind to failures).
- No status endpoint (can't check job state).
- Logging secrets (passwords, tokens).
