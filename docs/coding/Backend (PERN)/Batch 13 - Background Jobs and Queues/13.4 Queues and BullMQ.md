Queues decouple work from the request. Producer adds jobs, worker processes them.

```ts
import { Queue, Worker } from "bullmq";
import Redis from "ioredis";

const connection = new Redis(process.env.REDIS_URL);

// Producer (in API)
const queue = new Queue("tasks", { connection });
await queue.add("check-url", { url: "https://example.com" });

// Worker (separate process)
const worker = new Worker("tasks", async (job) => {
  await checkUrl(job.data.url);
}, { connection });
```

- **Producer:** API adds jobs to queue.
- **Queue:** Redis stores jobs.
- **Worker:** separate process processes jobs.
- **BullMQ:** built on ioredis (Batch 12).

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│ Producer │ ──► │  Queue   │ ──► │  Worker  │
│  (API)   │     │ (Redis)  │     │ (process)│
└──────────┘     └──────────┘     └──────────┘
```

## What It Is NOT

- Worker is **not** the API process — separate process.
- Queue is **not** in-memory — stored in Redis.
- BullMQ is **not** a scheduler — it is a queue (use repeatable jobs for scheduling).

---

## Common Mistakes

- Running worker inside the web process.
- Not using Redis (in-memory queue).
- Not handling job failures.
