ACID: Atomicity, Consistency, Isolation, Durability. Each with a failure demo.

- **Atomicity:** all operations succeed or all fail (no partial).
- **Consistency:** data stays valid (constraints enforced).
- **Isolation:** concurrent transactions don't interfere (isolation levels).
- **Durability:** committed data survives crashes (written to disk).

**Failure demos:**

- Atomicity: transfer fails halfway → both balances unchanged.
- Consistency: constraint violation → transaction rolls back.
- Isolation: concurrent updates → each sees consistent state.
- Durability: crash after commit → data persists.

## What It Is NOT

- ACID is **not** just a buzzword — it guarantees correctness.
- Atomicity is **not** "no side effects" — it is all-or-nothing.
- Durability is **not** optional — committed data must survive.

---

## Common Mistakes

- Not using transactions for multi-step writes.
- Assuming auto-commit is enough.
- Confusing isolation with locking.
