# Doc 11.8 — Idempotency Keys

## Cheat Sheet (Quick Recall)

- Idempotency key: client sends a unique key per request.
- Server stores key + result.
- Repeated request with same key returns same result.
- Makes payment-style endpoints safe to retry.

Clients retry on network failure. An idempotency key makes a repeated request safe.

```ts
app.post("/transfers", async (req, res) => {
  const key = req.get("Idempotency-Key");
  if (!key) {
    res.status(400).json({ error: { code: "BAD_REQUEST", message: "Missing Idempotency-Key" } });
    return;
  }
  const existing = await prisma.idempotencyKey.findUnique({ where: { key } });
  if (existing) {
    res.status(existing.status).json(existing.response);
    return;
  }
  // process transfer
  const result = await processTransfer(req.body);
  await prisma.idempotencyKey.create({ data: { key, status: 200, response: result } });
  res.status(200).json(result);
});
```

- **Idempotency key:** client sends unique key per request.
- **Server stores:** key + result.
- **Repeated request:** returns same result (no duplicate processing).
- **Safe to retry:** payment-style endpoints.

**Callback to 2B.3:** idempotency in REST.

## What It Is NOT

- Idempotency key is **not** a transaction ID — it is client-provided.
- Repeated request is **not** re-processed — returns stored result.
- Missing key is **not** acceptable — require it.

---

## Common Mistakes

- Not storing the result (key exists but no result).
- Not checking the key first (processes duplicate).
- Storing key without transaction (race condition).
