---

Optimistic concurrency uses a version column instead of locks. No locks held, but retries on conflict.

```sql
-- Add version column
ALTER TABLE accounts ADD COLUMN version integer NOT NULL DEFAULT 1;

-- Conditional update
UPDATE accounts SET balance = balance - 100, version = version + 1
WHERE id = 1 AND version = 5;
-- If 0 rows updated → conflict → retry
```

```ts
// Prisma version-checked update
const updated = await prisma.account.updateMany({
  where: { id: 1, version: expectedVersion },
  data: { balance: newBalance, version: { increment: 1 } },
});
if (updated.count === 0) {
  // conflict → retry
}
```

- **Version column:** `version integer`.
- **Conditional update:** `WHERE version = expected`.
- **Retry on conflict:** if 0 rows updated, retry.
- **Compared with locking:** no locks held, but retries needed.

## What It Is NOT

- Optimistic is **not** pessimistic — no locks, retries instead.
- `updateMany` is **not** `update` — `updateMany` returns count.
- Retry is **not** optional — must retry on conflict.

---

## Common Mistakes

- Not checking `count` (silent failure).
- Not retrying (operation fails).
- Using optimistic when pessimistic is better (high contention).
