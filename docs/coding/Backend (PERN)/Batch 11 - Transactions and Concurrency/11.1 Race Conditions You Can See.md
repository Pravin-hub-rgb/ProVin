## Broader Goal

The goal of Batch 11 is to understand what goes wrong when many requests touch the same data. Current step: race conditions.

---

Fire many concurrent withdrawals at one account and watch the balance go wrong.

```ts
// Naive (buggy) transfer
async function transfer(from: string, to: string, amount: number) {
  const fromBal = await getBalance(from);
  const toBal = await getBalance(to);
  await setBalance(from, fromBal - amount);
  await setBalance(to, toBal + amount);
}
```

- **Lost update:** two requests read same balance, both write → one overwrites the other.
- **Reproduce:** fire 100 concurrent withdrawals of $10 from $1000 → balance goes negative.

**Break it on purpose:** reproduce the bug with a load script.

## What It Is NOT

- Race conditions are **not** theoretical — they cause real data corruption.
- `async` is **not** atomic — each `await` is a yield point.
- In-memory state is **not** safe — concurrent requests interleave.

---

## Common Mistakes

- Read-then-write without transaction.
- Assuming single-threaded = no races (Node is single-threaded but async yields).
- Not testing concurrency.
