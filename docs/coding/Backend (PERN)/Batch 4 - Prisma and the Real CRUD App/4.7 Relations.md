# Doc 4.7 — Relations

## Cheat Sheet (Quick Recall)

- One-to-many and many-to-many in schema.
- Nested writes: `connect`, `connectOrCreate`.
- Reading relations: `include`.
- N+1 trap: looping + calling client inside loop.
- Fix: use `include` or `select`.

Relations connect models. One-to-many and many-to-many.

```prisma
model Bookmark {
  id    String @id @default(uuid())
  tags  Tag[]
}

model Tag {
  id        String     @id @default(uuid())
  name      String     @unique
  bookmarks Bookmark[]
}
```

**Nested writes:**

```ts
// connect existing tag
await prisma.bookmark.create({
  data: { url, title, tags: { connect: [{ id: tagId }] } },
});

// connectOrCreate
await prisma.bookmark.create({
  data: { url, title, tags: { connectOrCreate: { where: { name: "js" }, create: { name: "js" } } } },
});
```

**Reading relations:**

```ts
const bookmark = await prisma.bookmark.findUnique({
  where: { id },
  include: { tags: true },
});
```

**N+1 trap:** looping over bookmarks and calling `prisma.tag.findMany` inside the loop. Fix: use `include` or `select`.

## What It Is NOT

- Relations are **not** automatic — you define them in schema.
- `include` is **not** `select` — `include` adds relations, `select` chooses fields.
- N+1 is **not** harmless — it causes performance issues.

---

## Common Mistakes

- N+1 queries (loop + client call).
- Over-fetching with `include` (use `select`).
- Forgetting `connect`/`connectOrCreate`.

## Summary

- One-to-many and many-to-many in schema.
