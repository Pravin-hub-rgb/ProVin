# Doc 4.4 — Migrations

## Cheat Sheet (Quick Recall)

- `prisma migrate dev` — create + apply migration (dev).
- `prisma migrate deploy` — apply existing migrations (prod).
- Migrations folder: readable SQL files.
- `prisma migrate dev --name add_note` — named migration.
- Edit model → generate migration → read the SQL.

Migrations track schema changes like code.

```bash
npx prisma migrate dev --name init
# Creates: prisma/migrations/2026..._init/migration.sql
```

- `prisma migrate dev` — creates + applies migration (dev).
- `prisma migrate deploy` — applies existing migrations (prod).
- Migrations folder: readable SQL files.
- `--name` gives the migration a name.

**Compare with 3.15 (by hand):** numbered SQL files → Prisma generates them.

**Break it on purpose:** edit a model, generate the migration, read the SQL it wrote.

## What It Is NOT

- `migrate dev` is **not** `migrate deploy` — dev creates, deploy applies.
- Migrations are **not** optional — schema changes must be tracked.
- Editing the DB by hand is **not** recommended — use migrations.

---

## Common Mistakes

- Editing the database by hand instead of through a migration.
- Forgetting to regenerate/reapply after schema change.
- Using `migrate dev` in production.
