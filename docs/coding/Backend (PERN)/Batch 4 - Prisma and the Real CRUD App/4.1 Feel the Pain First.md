## Problem — What Is Painful About Hand-Written Data Access?

Take the Batch 3 `pg` script and the Bookmarks table. Write list, create, and update functions by hand: map rows to objects, build dynamic `WHERE` clauses for filters, handle optional fields. He writes down what was repetitive or fragile.

```ts
// Hand-written data module (the pain)
import { pool } from "./db.js";

type Bookmark = { id: string; url: string; title: string; note?: string };

export async function listBookmarks(tag?: string, q?: string) {
  const conditions: string[] = [];
  const params: unknown[] = [];
  let i = 1;
  if (tag) { conditions.push(`$${i++} = ANY(tags)`); params.push(tag); }
  if (q) { conditions.push(`title ILIKE $${i++}`); params.push(`%${q}%`); }
  const where = conditions.length ? `WHERE ${conditions.join(" AND ")}` : "";
  const { rows } = await pool.query(`SELECT * FROM bookmarks ${where} ORDER BY created_at DESC`, params);
  return rows.map((r) => ({ id: r.id, url: r.url, title: r.title, note: r.note }));
}

export async function createBookmark(url: string, title: string, note?: string) {
  const { rows } = await pool.query(
    "INSERT INTO bookmarks (url, title, note) VALUES ($1, $2, $3) RETURNING *",
    [url, title, note]
  );
  return rows[0];
}
```

- Mapping rows to objects: manual.
- Dynamic `WHERE`: string building (error-prone).
- Optional fields: conditional SQL.
- Repetitive, fragile, hard to maintain.

## What It Is NOT

- Hand-written SQL is **not** wrong — it is just tedious.
- Prisma is **not** magic — it generates the same SQL.
- This pain is **not** permanent — Prisma solves it.

---

## Common Mistakes

- Building SQL with string concatenation (injection risk).
- Not mapping rows to typed objects.
- Forgetting optional fields.
