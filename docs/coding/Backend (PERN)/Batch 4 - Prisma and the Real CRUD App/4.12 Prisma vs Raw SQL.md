# Doc 4.12 — Prisma vs Raw SQL

## Cheat Sheet (Quick Recall)

- Prisma: readable schema, strong typing, excellent migrations.
- Raw SQL: full control, no hidden queries.
- Query builders (Drizzle): SQL-closer alternative.
- Trade-offs: convenience vs control.

---

A written comparison: what Prisma saved, what it hid, when to use raw SQL.

| | Prisma | Raw SQL (pg) |
|---|---|---|
| Schema | Readable schema file | CREATE TABLE SQL |
| Migrations | Auto-generated | Manual numbered files |
| Types | Generated from schema | Manual TypeScript types |
| Queries | Method calls (findMany, create) | SQL strings |
| Control | Limited (escape hatch: $queryRaw) | Full control |
| Performance | Good (may hide N+1) | Full control |

**When to use Prisma:** rapid development, type safety, migrations.

**When to use raw SQL:** complex queries, performance-critical paths, full control.

**Query builders (Drizzle):** SQL-closer alternative (PREVIEW).

## What It Is NOT

- Prisma is **not** always better — raw SQL gives full control.
- Raw SQL is **not** always worse — it is more explicit.
- Drizzle is **not** covered — just a PREVIEW.

## Common Mistakes

- Using Prisma for everything (even when raw SQL is better).
- Using raw SQL for everything (tedious).
- Not understanding the trade-offs.
