Prisma schema defines your database tables as models.

```prisma
model Bookmark {
  id        String   @id @default(uuid())
  url       String   @unique
  title     String
  note      String?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  tags      Tag[]
}

model Tag {
  id        String     @id @default(uuid())
  name      String     @unique
  bookmarks Bookmark[]
}
```

- `model`: defines a table.
- Field types: `String`, `Int`, `Boolean`, `DateTime`, `Json`.
- `@id`: primary key.
- `@default`: default value (`uuid()`, `now()`).
- `@unique`: unique constraint.
- `@updatedAt`: auto-updates on change.
- `@relation`: connects models (many-to-many here).

**Compare with SQL (3.4):**

| Prisma | SQL |
|--------|-----|
| `@id` | `PRIMARY KEY` |
| `@unique` | `UNIQUE` |
| `@default(now())` | `DEFAULT now()` |
| `String?` | nullable column |

## What It Is NOT

- Prisma schema is **not** SQL — it generates SQL.
- `@default` is **not** application-level — it is database-level.
- Relations are **not** automatic — you define them.

---

## Common Mistakes

- Missing `@id` (no primary key).
- Wrong field types (e.g., `String` for numbers).
- Not comparing with SQL (miss the mapping).
