Prisma Client provides typed CRUD operations.

```ts
import { PrismaClient } from "@prisma/client";
const prisma = new PrismaClient();

// Create
const bookmark = await prisma.bookmark.create({
  data: { url: "https://example.com", title: "Example" },
});

// Read one
const found = await prisma.bookmark.findUnique({ where: { id: bookmark.id } });

// Read many
const all = await prisma.bookmark.findMany({ orderBy: { createdAt: "desc" } });

// Update
const updated = await prisma.bookmark.update({
  where: { id: bookmark.id },
  data: { title: "New Title" },
});

// Delete
await prisma.bookmark.delete({ where: { id: bookmark.id } });
```

- `create({ data })`: inserts a row.
- `findUnique({ where })`: finds by unique field.
- `findMany({ where, orderBy, take, skip })`: lists with filters.
- `update({ where, data })`: updates a row.
- `delete({ where })`: deletes a row.

**Generated types follow the schema.** If you add a field, the client updates.

**Show equivalent SQL:** enable query logging to see the SQL Prisma generates.

## What It Is NOT

- Prisma Client is **not** the database — it connects to Postgres.
- `findUnique` is **not** `findFirst` — `findUnique` requires a unique field.
- Generated types are **not** manual — they follow the schema.

---

## Common Mistakes

- Using `findFirst` when `findUnique` is needed (unique field).
- Forgetting to regenerate client after schema change.
- Not enabling query logging (can't see SQL).
