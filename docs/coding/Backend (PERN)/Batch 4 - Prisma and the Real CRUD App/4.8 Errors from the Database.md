Prisma throws known errors with codes. Map them to HTTP statuses through the error handler.

```ts
import { Prisma } from "@prisma/client";

function mapPrismaError(err: unknown) {
  if (err instanceof Prisma.PrismaClientKnownRequestError) {
    if (err.code === "P2002") return { status: 409, code: "CONFLICT", message: "Duplicate value" };
    if (err.code === "P2025") return { status: 404, code: "NOT_FOUND", message: "Record not found" };
  }
  return { status: 500, code: "INTERNAL_ERROR", message: "Something went wrong" };
}
```

- **P2002:** unique constraint violation → 409 Conflict.
- **P2025:** record not found → 404 Not Found.
- Map through the error handler from 2A.8.
- Never leak raw database errors to clients.

**Break it on purpose:** create a duplicate and read the raw error.

## What It Is NOT

- Raw errors are **not** for clients — map them first.
- Prisma errors are **not** HTTP errors — you map them.
- `P2002` is **not** `P2025` — different codes, different statuses.

---

## Common Mistakes

- Leaking raw database errors to clients.
- Not mapping P2002/P2025.
- Catching all errors as 500.
