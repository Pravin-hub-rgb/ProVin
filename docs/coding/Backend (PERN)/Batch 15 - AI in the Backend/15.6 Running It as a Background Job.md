Use the queue from Batch 13 for slow enrichment so the request returns immediately.

```ts
// API: enqueue enrichment job
app.post("/bookmarks/:id/enrich", authMiddleware, async (req, res) => {
  await enrichmentQueue.add("enrich", { bookmarkId: req.params.id, userId: req.user.id });
  res.status(202).json({ data: { status: "queued" } });
});

// Worker: process enrichment
const worker = new Worker("enrichment", async (job) => {
  const { bookmarkId, userId } = job.data;
  const bookmark = await prisma.bookmark.findUnique({ where: { id: bookmarkId } });
  if (!bookmark) return;
  const summary = await callAI(bookmark.url);
  await prisma.bookmark.update({ where: { id: bookmarkId }, data: { summary } });
}, { connection });
```

- **Request returns immediately** (202 Accepted).
- **Worker processes** enrichment in background.
- **Idempotent jobs:** safe to retry (callback to 11.8).

## What It Is NOT

- Enrichment is **not** synchronous — it runs in background.
- Worker is **not** in the API process — separate process.
- Job is **not** safe to retry unless idempotent.

---

## Common Mistakes

- Doing slow enrichment in the request handler (blocks).
- Worker inside the web process.
- Not making jobs idempotent.
