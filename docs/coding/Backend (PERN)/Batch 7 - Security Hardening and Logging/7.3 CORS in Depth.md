CORS in depth: allowlist from config, credentials, preflight caching, common mistakes.

```ts
import cors from "cors";

const allowedOrigins = process.env.ALLOWED_ORIGINS?.split(",") || [];
app.use(cors({
  origin: (origin, cb) => {
    if (!origin || allowedOrigins.includes(origin)) cb(null, true);
    else cb(new Error("Not allowed by CORS"));
  },
  credentials: true,
  maxAge: 86400, // preflight cache 24h
}));
```

- **Allowlist:** origins from config (env var).
- **Credentials:** `credentials: true` allows cookies. Wildcard `*` + credentials = invalid (browser blocks).
- **Preflight caching:** `maxAge` caches preflight response.
- **Common mistake:** reflecting any origin (security hole).

**Break it on purpose:** configure badly and show the risk.

## What It Is NOT

- CORS is **not** a server-side block — it is a browser policy.
- Wildcard + credentials is **not** allowed — browser blocks.
- CORS is **not** authentication — it is origin control.

## Common Mistakes

- Wildcard origin + credentials (invalid).
- Reflecting any origin (security hole).
- Not handling preflight (OPTIONS).
