# Doc 7.2 — Security Headers with helmet

## Cheat Sheet (Quick Recall)

- `helmet` sets security headers automatically.
- Headers: `Content-Security-Policy`, `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`.
- API (JSON) needs fewer headers than a website.
- Inspect before/after with curl.

---

Security headers protect against common attacks. `helmet` sets them automatically.

```ts
import helmet from "helmet";
app.use(helmet());
```

- `Content-Security-Policy`: prevents XSS (restricts script sources).
- `Strict-Transport-Security`: forces HTTPS.
- `X-Content-Type-Options: nosniff`: prevents MIME sniffing.
- `X-Frame-Options`: prevents clickjacking.

**API vs website:** an API returning JSON needs fewer headers than a site serving HTML. helmet defaults are good for both.

**Inspect before/after:**

```bash
curl -I http://localhost:3000/health
```

## What It Is NOT

- helmet is **not** a firewall — it sets headers.
- Headers are **not** optional in production — they protect against attacks.
- API headers are **not** the same as website headers — fewer needed.

---

## Common Mistakes

- Not using helmet at all.
- Over-configuring (breaking the API).
- Not inspecting headers to verify.
