# Doc 7.5 — Limits on Everything

## Cheat Sheet (Quick Recall)

- Body size limits: `express.json({ limit: "1mb" })`.
- Page size caps: `limit` max 50.
- Max string/array lengths in Zod schemas.
- Request timeouts.
- Every input needs an upper bound.

## Where We Are So Far

## Broader Goal

The goal of Batch 7 is to make the API hard to abuse and easy to observe. Current step: limits.

---

Every input needs an upper bound. First body size, then page size, then string/array lengths, then timeouts.

```ts
// Body size limit
app.use(express.json({ limit: "1mb" }));

// Page size cap (in Zod schema)
const querySchema = z.object({
  limit: z.coerce.number().min(1).max(50).default(10),
  page: z.coerce.number().min(1).default(1),
});

// String/array length limits
const bookmarkSchema = z.object({
  title: z.string().min(1).max(200),
  tags: z.array(z.string().max(30)).max(10),
  note: z.string().max(1000).optional(),
});

// Request timeout
app.use((req, res, next) => {
  req.setTimeout(30000); // 30s
  next();
});
```

- Body size: `express.json({ limit: "1mb" })`.
- Page size: cap `limit` at 50.
- String lengths: `.max(200)` on title.
- Array lengths: `.max(10)` on tags.
- Request timeout: `req.setTimeout(30000)`.

**File uploads:** PREVIEW only (OUT OF SCOPE).

## What It Is NOT

- Limits are **not** optional — every input needs an upper bound.
- Body size limit is **not** the same as page size cap.
- File uploads are **not** covered in this course.

---

## Common Mistakes

- No body size limit → memory blowup.
- No page size cap → huge responses.
- No string/array length limits → database bloat.
- No request timeout → hanging requests.
