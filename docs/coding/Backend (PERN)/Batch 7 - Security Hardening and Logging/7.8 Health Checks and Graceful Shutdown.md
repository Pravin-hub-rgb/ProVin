# Doc 7.8 — Health Checks and Graceful Shutdown

## Cheat Sheet (Quick Recall)

- `/health`: am I alive? (liveness).
- `/ready`: can I serve? (readiness, includes DB check).
- Graceful shutdown: stop accepting, finish in-flight, close DB, exit.
- `SIGTERM` handler.

---

`/health` (am I alive) versus `/ready` (can I serve, including a database check). On `SIGTERM`, stop accepting connections, finish in-flight requests, close the Prisma client, then exit.

```ts
app.get("/health", (req, res) => {
  res.json({ status: "ok" });
});

app.get("/ready", async (req, res) => {
  try {
    await prisma.$queryRaw`SELECT 1`;
    res.json({ status: "ready" });
  } catch {
    res.status(503).json({ status: "not ready" });
  }
});

process.on("SIGTERM", async () => {
  server.close(async () => {
    await prisma.$disconnect();
    process.exit(0);
  });
});
```

- `/health`: liveness (am I alive?).
- `/ready`: readiness (can I serve? includes DB check).
- Graceful shutdown: stop accepting → finish in-flight → close DB → exit.
- `SIGTERM`: signal from platform (Docker, Kubernetes).

**Break it on purpose:** kill the server mid-request and see what the client gets.

## What It Is NOT

- `/health` is **not** `/ready` — health = alive, ready = can serve.
- Graceful shutdown is **not** immediate — finish in-flight first.
- `SIGTERM` is **not** `SIGKILL` — SIGTERM allows cleanup, SIGKILL does not.

---

## Common Mistakes

- No health check (platform can't monitor).
- No graceful shutdown (in-flight requests dropped).
- Not closing DB connection (leaks).
