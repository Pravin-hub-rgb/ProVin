Manual first: show what `console.log` logging looks like once there are many requests. Then pino: structured JSON.

```ts
import pino from "pino";

const logger = pino({
  level: process.env.LOG_LEVEL || "info",
  redact: ["req.headers.authorization", "req.headers.cookie", "*.password"],
});

// Child logger with request id
app.use((req, res, next) => {
  req.log = logger.child({ requestId: req.get("X-Request-Id") });
  next();
});

// Usage
req.log.info({ userId: req.user?.id }, "User fetched bookmarks");
```

- `pino`: fast JSON logger.
- **Log levels:** trace, debug, info, warn, error, fatal.
- **Child loggers:** carry request id.
- **Redaction:** remove secrets (passwords, tokens, cookies).
- **Dev:** `pino-pretty` for readable output.
- **Prod:** raw JSON for machine parsing.

**What to log:** method, path, status, duration, request id, user id.

**What never to log:** passwords, tokens, cookies, full request bodies with secrets.

## What It Is NOT

- `console.log` is **not** structured — hard to search.
- Pino is **not** the only logger — Winston also works.
- Redaction is **not** optional — secrets must not appear in logs.

---

## Common Mistakes

- Logging passwords/tokens.
- Using `console.log` in production.
- Not redacting sensitive fields.
