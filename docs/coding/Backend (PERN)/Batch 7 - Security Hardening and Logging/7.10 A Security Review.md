# Doc 7.10 — A Security Review

## Cheat Sheet (Quick Recall)

- Walk your API against a written checklist.
- Fix what fails.
- Commit the checklist to the repository.
- Repeat regularly (not just once).

## Where We Are So Far

In 7.9 we saw secrets and dependency hygiene. Now a security review — walk your own API against a checklist.

## Broader Goal

The goal of Batch 7 is to make the API hard to abuse and easy to observe. Current step: security review.

---

Walk your own API against a written checklist and fix what fails.

**Checklist items:**

- [ ] Auth: protected routes, ownership checks.
- [ ] Input validation: Zod on all routes.
- [ ] Rate limiting: strict on auth, loose elsewhere.
- [ ] CORS: allowlist, no wildcard + credentials.
- [ ] Security headers: helmet.
- [ ] Limits: body size, page size, string/array lengths.
- [ ] Logging: structured, redacted, no secrets.
- [ ] Error handling: no stack traces leaked.
- [ ] Secrets: not in Git, rotated if leaked.
- [ ] Dependencies: audit run, reviewed.

**Mini-project:** the completed checklist, committed to the repository.

## What It Is NOT

- Security review is **not** a one-time task — repeat regularly.
- Checklist is **not** exhaustive — add your own items.
- Passing checklist is **not** 100% secure — it is a baseline.

---

## Common Mistakes

- Treating security review as one-time.
- Not committing the checklist.
- Skipping items that seem "minor."
