## Problem — How Do You Write Middleware for Logging, Timing, and Request IDs?

Express middleware is just a function `(req, res, next) => {}`. Write a request logger, a timing header, and a request ID. First logger, then timing, then request ID.

```ts
import express from "express";
import { randomUUID } from "node:crypto";
const app = express();

// Request logger
app.use((req, res, next) => {
  const start = Date.now();
  res.on("finish", () => {
    const duration = Date.now() - start;
    console.log(`${req.method} ${req.path} ${res.statusCode} ${duration}ms`);
  });
  next();
});

// Request ID
app.use((req, res, next) => {
  const id = randomUUID();
  res.set("X-Request-Id", id);
  next();
});
```

- `res.on("finish")` — fires when response is sent (status known).
- `randomUUID()` — generates unique ID.
- `res.set(name, value)` — sets response header.

**Status is only known after the response finishes.** That is why the logger uses the `finish` event.

## What It Is NOT

- Custom middleware is **not** a route — it runs for all routes.
- `res.on("finish")` is **not** synchronous — it fires after response sent.
- `randomUUID()` is **not** `Math.random()` — it is cryptographically unique.

---

## Common Mistakes

- Logging status before response finishes (always 200).
- Forgetting `next()` → request hangs.
- Not using `finish` event for duration.

## Summary

- Custom middleware: `(req, res, next) => {}`.
- Use `res.on("finish")` for status/duration.
- `randomUUID()` for request IDs.
