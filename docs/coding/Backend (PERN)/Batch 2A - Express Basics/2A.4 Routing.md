## Problem — How Do You Organize Routes in Express?

Express gives you `app.get`, `app.post`, `express.Router`, and `app.use` for mounting. First methods and params, then query strings, then routers, then order.

```ts
import express from "express";
const app = express();
app.use(express.json());

// Method + path
app.get("/items", (req, res) => res.json([]));
app.post("/items", (req, res) => res.status(201).json(req.body));

// Route params
app.get("/items/:id", (req, res) => {
  const { id } = req.params;
  res.json({ id });
});

// Query strings
app.get("/search", (req, res) => {
  const { q, limit } = req.query;
  res.json({ q, limit });
});

// Router
const itemsRouter = express.Router();
itemsRouter.get("/", (req, res) => res.json([]));
itemsRouter.post("/", (req, res) => res.status(201).json(req.body));
app.use("/items", itemsRouter);
```

- `app.get/post/put/patch/delete(path, handler)` — method + path.
- `:id` in path → `req.params.id`.
- `?q=...` in URL → `req.query.q`.
- `express.Router()` — group routes, mount with `app.use(prefix, router)`.
- Route order matters: first match wins.

**Express 5 path rules:** named wildcards, `{/:id}` optional segments (different from Express 4).

**Break it on purpose:** put a catch-all route above a specific one → specific route never matches.

## What It Is NOT

- `req.params` is **not** `req.query` — params are path segments, query is URL query.
- Route order is **not** automatic — first match wins.
- Express 5 paths are **not** Express 4 paths — syntax differs.

---

## Common Mistakes

- Trusting `req.query` values to be single strings (can be arrays/objects).
- Putting catch-all route above specific routes.
- Using Express 4 path syntax in Express 5.

## Summary

- Methods: `app.get/post/put/patch/delete`.
- Params: `:id` → `req.params.id`.
- Query: `?q=` → `req.query.q`.
- Router: `express.Router()` + `app.use(prefix, router)`.
- Order matters: first match wins.
