## Problem — How Do You Handle Errors in Express?

Express needs a 404 handler and an error handler. Express 5 forwards async errors automatically. First 404, then error middleware, then async errors.

```ts
import express from "express";
const app = express();

// Routes
app.get("/items/:id", async (req, res) => {
  const item = await findItem(req.params.id);
  if (!item) throw new NotFoundError("Item not found");
  res.json(item);
});

// 404 handler (after all routes)
app.use((req, res) => {
  res.status(404).json({ error: { code: "NOT_FOUND", message: "Route not found" } });
});

// Error handler (4 args, must be last)
app.use((err, req, res, next) => {
  const status = err instanceof NotFoundError ? 404 : 500;
  res.status(status).json({ error: { code: err.name, message: err.message } });
});
```

- **404 handler:** catches unmatched routes (must be after all routes).
- **Error handler:** 4 arguments `(err, req, res, next)` — must be last.
- **Express 5:** errors thrown in async handlers are forwarded automatically (no try/catch needed).
- **Never leak stack traces** in responses.

**Break it on purpose:**

- Put error handler before routes → it won't catch anything.
- Throw inside async handler → Express 5 forwards it automatically.

## What It Is NOT

- Error handler is **not** a route — it has 4 args, routes have 3.
- Error handler is **not** before routes — it must be last.
- Stack traces are **not** for clients — log them, don't send them.

---

## Common Mistakes

- Putting error handler before routes.
- Forgetting 4 args → treated as regular middleware.
- Leaking stack traces to clients.

## Summary

- 404 handler: after all routes, sends 404.
- Error handler: 4 args, must be last.
- Express 5 forwards async errors automatically.
- Never leak stack traces.
