## Problem — Why Split app.ts and server.ts?

`app.ts` builds and exports the app. `server.ts` starts listening. Why? Tests in Batch 8 will import the app without opening a port. Configuration comes from the loader in Batch 1.8.

```ts
// app.ts
import express from "express";
import { itemsRouter } from "./routes/items.js";

export function createApp() {
  const app = express();
  app.use(express.json());
  app.use("/items", itemsRouter);
  // 404 + error handlers here
  return app;
}
```

```ts
// server.ts
import { createApp } from "./app.js";
import { loadConfig } from "./config.js";

const config = loadConfig();
const app = createApp();
app.listen(config.port, () => {
  console.log(`Server on http://localhost:${config.port}`);
});
```

- `app.ts`: builds the Express app, registers middleware/routes, exports it.
- `server.ts`: loads config, creates app, starts listening.
- Tests import `createApp()` without `listen()` (no port opened).

## What It Is NOT

- `app.ts` is **not** the server — it does not listen.
- `server.ts` is **not** where routes go — it only starts.
- Tests are **not** importing `server.ts` — they import `app.ts`.

---

## Common Mistakes

- Putting `app.listen` in `app.ts` (tests open ports).
- Mixing config loading with route registration.
- Not exporting `createApp`.
