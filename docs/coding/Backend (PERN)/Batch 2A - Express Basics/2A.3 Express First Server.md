## Problem — What Does Express Do for You?

Express gives you `app.get`, `app.post`, `res.json`, and `express.json()` middleware. It removes the repetitive routing and parsing code. First install, then create a server, then compare line counts.

```bash
npm install express
npm install -D @types/express
```

```ts
import express from "express";

const app = express();
app.use(express.json());

app.get("/items", (req, res) => {
  res.json([{ id: 1, name: "Item" }]);
});

app.post("/items", (req, res) => {
  const { name } = req.body;
  res.status(201).json({ id: 2, name });
});

app.listen(3000, () => {
  console.log("Server on http://localhost:3000");
});
```

- `express()` — creates an app.
- `app.use(express.json())` — parses JSON bodies automatically.
- `app.get(path, handler)` — route handler.
- `res.json(data)` — sends JSON response.
- `res.status(code)` — sets status code.
- `app.listen(port)` — starts the server.

**Compare with raw http:** Express removes the manual chunk reading, JSON.parse, and Content-Type headers.

## What It Is NOT

- Express is **not** a different runtime — it runs on Node.
- `express.json()` is **not** automatic — you must `app.use()` it.
- `res.json()` is **not** `res.send()` — `json()` sets Content-Type automatically.

---

## Common Mistakes

- Forgetting `app.use(express.json())` → `req.body` is undefined.
- Using `res.send()` instead of `res.json()` (no Content-Type).
- Not calling `app.listen()`.
