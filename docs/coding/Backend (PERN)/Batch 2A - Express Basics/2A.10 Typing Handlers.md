## Problem — How Do You Type Express Request Handlers?

Express handlers need types. `Request<Params, ResBody, ReqBody, Query>` from `@types/express` gives you typed params, body, query. First the type, then the slots, then the honest limit.

```ts
import { Request, Response } from "express";

type ItemParams = { id: string };
type ItemBody = { name: string };
type ItemQuery = { include?: string };

app.get("/items/:id", (req: Request<ItemParams, unknown, unknown, ItemQuery>, res: Response) => {
  const { id } = req.params;      // typed as string
  const { include } = req.query;  // typed as string | undefined
  res.json({ id, include });
});

app.post("/items", (req: Request<{}, unknown, ItemBody>, res: Response) => {
  const { name } = req.body;      // typed as { name: string }
  res.status(201).json({ name });
});
```

- `Request<Params, ResBody, ReqBody, Query>` — four type slots.
- `Params` — route params (`:id`).
- `ResBody` — response body type.
- `ReqBody` — request body type.
- `Query` — query string type.

**Honest limit:** these types describe what you *expect*, they do not check what actually arrives. That gap is closed by validation (2B.4, Zod in Batch 5).

## What It Is NOT

- Types are **not** runtime validation — they only describe expectations.
- `Request` generics are **not** automatic — you must specify them.
- Types do **not** check actual incoming data — use validation for that.

---

## Common Mistakes

- Trusting `req.body` type (it is untrusted input).
- Not specifying generics (defaults to `any`).
- Thinking types replace validation.
