## Problem — How Does a Request Flow Through Express?

A request passes through functions in order. Each calls `next()` or ends the response. First the pipeline model, then `app.use`, then order, then `express.json()`.

```ts
import express from "express";
const app = express();

// Middleware 1: logger
app.use((req, res, next) => {
  console.log(`${req.method} ${req.path}`);
  next();
});

// Middleware 2: parse JSON
app.use(express.json());

// Route
app.get("/items", (req, res) => {
  res.json(req.body);
});

app.listen(3000);
```

- `app.use(fn)` — registers middleware for all routes.
- `next()` — passes to the next middleware/route.
- Order matters: middleware runs top-to-bottom.
- `express.json()` parses JSON bodies (size limit configurable).

**Break it on purpose:**

- Reorder middleware → behavior changes.
- Remove `express.json()` → `req.body` is undefined.

```
Request → Logger → express.json() → Route → Response
              │
              └── next() passes control
```

## What It Is NOT

- Middleware is **not** a route — it runs for all routes (unless path-scoped).
- `next()` is **not** optional — without it, the request hangs.
- `express.json()` is **not** automatic — you must `app.use()` it.

---

## Common Mistakes

- Forgetting `next()` → request hangs.
- Wrong order → middleware doesn't run when expected.
- Missing `express.json()` → `req.body` undefined.

## Summary

- Middleware: functions that run in order, each calls `next()` or ends response.
- `app.use(fn)` registers for all routes.
- Order matters; `express.json()` parses bodies.
