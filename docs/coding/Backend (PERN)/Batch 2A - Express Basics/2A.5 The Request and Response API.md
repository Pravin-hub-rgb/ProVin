## Problem — What Does Express Give You on req and res?

Express adds helpers on top of raw Node's `req`/`res`. First `req` properties, then `res` methods, then the echo endpoint.

```ts
app.get("/echo/:id", (req, res) => {
  const params = req.params;        // route params
  const query = req.query;          // query strings
  const body = req.body;           // parsed body (needs express.json())
  const header = req.get("Content-Type"); // header value

  res.status(200).json({
    method: req.method,
    path: req.path,
    params,
    query,
    headers: req.headers,
    body,
  });
});
```

- `req.params` — route parameters (`:id`).
- `req.query` — query strings (`?q=...`).
- `req.body` — parsed body (requires `express.json()`).
- `req.get(name)` — read a header.
- `res.status(code)` — set status code.
- `res.json(data)` — send JSON.
- `res.set(name, value)` — set header.
- `res.sendStatus(code)` — send status with no body.

**Trap:** `req.query` values can be strings, arrays, or nested objects. Never trust them to be a single string.

## What It Is NOT

- `req.params` is **not** `req.query` — different sources.
- `req.body` is **not** available without `express.json()`.
- `res.json()` is **not** `res.send()` — `json()` sets Content-Type.

---

## Common Mistakes

- Trusting `req.query` to be a string.
- Forgetting `express.json()` → `req.body` undefined.
- Using `res.send()` instead of `res.json()`.

## Summary

- `req.params`, `req.query`, `req.body`, `req.get()`.
- `res.status()`, `res.json()`, `res.set()`, `res.sendStatus()`.
- `req.query` can be string/array/object — never trust it.
