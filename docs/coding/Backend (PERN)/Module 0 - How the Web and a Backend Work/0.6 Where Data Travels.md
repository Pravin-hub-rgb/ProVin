## Problem — Where Should Each Piece of Data Go?

Data in an HTTP request can travel in five places. Choosing the right place matters. Put a secret in the URL and it leaks. Put a filter in the body and it is awkward. First the five places, then the rules.

```
┌─────────────────────────────────────────────────┐
│  GET /users/123?role=admin HTTP/1.1             │
│  Host: api.example.com                          │
│  Authorization: Bearer <token>                   │
│  Content-Type: application/json                  │
│                                                 │
│  { "name": "Vin" }                              │
│                                                 │
│  path: /users/123                               │
│  query: ?role=admin                             │
│  headers: Host, Authorization, Content-Type      │
│  body: { "name": "Vin" }                        │
│  cookies: sent automatically by browser         │
└─────────────────────────────────────────────────┘
```

- **Path:** the resource ID. `/users/123` → user 123.
- **Query:** filters, search, pagination. `?page=2&limit=10`.
- **Headers:** metadata. Auth token, content type, accept.
- **Body:** the main payload. JSON data for POST/PUT/PATCH.
- **Cookies:** small data stored by browser, sent automatically with requests.

**Rules of thumb:**

- Resource ID → path.
- Filters/search → query.
- Auth token → header (or cookie).
- Data to create/update → body.
- Secrets → never in URL (query/path). URLs are logged, cached, and visible in browser history.

## What It Is NOT

- Secrets are **not** safe in URLs — they leak in logs and history.
- GET requests should **not** have a body — use query params instead.
- Headers are **not** the body — headers are metadata, body is payload.

---

## Common Mistakes

- Putting secrets in the URL (query/path).
- Using body for GET requests.
- Confusing headers and body.

## Summary

- Data travels in: path, query, headers, body, cookies.
- Path = ID, query = filters, headers = metadata, body = payload, cookies = auto-sent.
