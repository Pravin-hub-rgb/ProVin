# Doc 0.6 — Where Data Travels

## Cheat Sheet (Quick Recall)

- Data can travel in: path, query, headers, body, cookies.
- Path: resource ID (`/users/123`).
- Query: filters/pagination (`?page=2&limit=10`).
- Headers: metadata (auth token, content type).
- Body: the main payload (JSON).
- Cookies: small data stored by browser, sent automatically.

Data in an HTTP request can travel in five places. Choosing the right place matters.

```
┌─────────────────────────────────────────────────┐
│  GET /users/123?role=admin HTTP/1.1             │
│  Host: api.example.com                          │
│  Authorization: Bearer <token>                   │
│  Content-Type: application/json                  │
│                                                 │
│  { "name": "Vin" }                              │
│                                                 │
│  path: /users/123                               │
│  query: ?role=admin                             │
│  headers: Host, Authorization, Content-Type      │
│  body: { "name": "Vin" }                        │
│  cookies: sent automatically by browser         │
└─────────────────────────────────────────────────┘
```

- **Path:** the resource ID. `/users/123` → user 123.
- **Query:** filters, search, pagination. `?page=2&limit=10`.
- **Headers:** metadata. Auth token, content type, accept.
- **Body:** the main payload. JSON data for POST/PUT/PATCH.
- **Cookies:** small data stored by browser, sent automatically with requests.

**Rules of thumb:**

- Resource ID → path.
- Filters/search → query.
- Auth token → header (or cookie).
- Data to create/update → body.
- Secrets → never in URL (query/path).

## Common Mistakes

- Putting secrets in the URL (query/path).
- Using body for GET requests.
- Confusing headers and body.

## Questions

1. Where should a resource ID go?

**Answer:** In the path (/users/123).

2. Where should filters go?

**Answer:** In the query string (?role=admin).

3. Where should an auth token go?

**Answer:** In headers (Authorization) or cookies.

4. Where should the main payload go?

**Answer:** In the body (JSON).

5. Why not put secrets in the URL?

**Answer:** URLs are logged, cached, and visible in browser history.
