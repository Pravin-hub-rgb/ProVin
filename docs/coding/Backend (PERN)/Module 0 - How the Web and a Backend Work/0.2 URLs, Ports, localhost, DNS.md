# Doc 0.2 — URLs, Ports, localhost, DNS

## Cheat Sheet (Quick Recall)

- URL = scheme + host + port + path + query.
- `localhost` = your own machine (127.0.0.1).
- Port = a number identifying a service on a machine (e.g., 3000, 5173).
- DNS = turns a name (google.com) into an IP address.
- `localhost:3000` and `localhost:5173` are different origins.

A URL is an address. It tells the browser where to send a request and what to ask for.

```
https://google.com:443/maps?q=paris
  │        │       │    │      │
  │        │       │    │      └── query (data)
  │        │       │    └── path (what you want)
  │        │       └── port (service number)
  │        └── host (server name)
  └── scheme (protocol)
```

- **Scheme:** `http` or `https` (http + TLS).
- **Host:** server name (google.com) or IP.
- **Port:** service number (443 for HTTPS, 80 for HTTP, 3000/5173 for dev).
- **Path:** what you want (`/maps`).
- **Query:** extra data (`?q=paris`).

**localhost:** your own machine. `http://localhost:3000` means "the service on port 3000 on this machine."

**DNS:** turns a name (google.com) into an IP address (142.250.80.46). Humans remember names; computers use numbers.

**Same origin:** `localhost:3000` and `localhost:5173` are different origins (different ports). Browsers treat them as separate sites.

## Common Mistakes

- Mixing up port and path.
- Thinking `localhost` is the internet.
- Treating different ports as the same origin.
