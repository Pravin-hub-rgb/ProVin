## Problem — How Do Client and Server Actually Talk?

You have an address (URL) and a server listening on a port. But what do they say to each other? HTTP is the language. A request asks for something; a response answers.

**Request:**

```
GET /bookmarks HTTP/1.1
Host: localhost:3000
Accept: application/json
```

- **Method** (GET, POST, etc.) — what you want to do.
- **Path** (/bookmarks) — what you want.
- **Headers** (Host, Accept, etc.) — metadata.
- **Body** (for POST/PUT/PATCH) — the data you are sending.

**Response:**

```
HTTP/1.1 200 OK
Content-Type: application/json

[{"id": 1, "title": "Example"}]
```

- **Status code** (200, 404, etc.) — did it work?
- **Headers** (Content-Type, etc.) — metadata about the response.
- **Body** — the data coming back.

**Methods:**

- GET: read
- POST: create
- PUT: replace
- PATCH: partial update
- DELETE: remove

**Status codes:**

- 2xx: success (200 OK, 201 Created, 204 No Content)
- 3xx: redirect
- 4xx: client error (400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict, 422 Unprocessable)
- 5xx: server error (500 Internal Server Error)

**401 vs 403:** 401 = "who are you?" (not authenticated). 403 = "you may not" (authenticated but not allowed).

## What It Is NOT

- HTTP is **not** only for HTML — it carries JSON, images, JS, everything.
- 200 is **not** for everything — use the most specific honest code.
- 401 is **not** 403 — 401 means not authenticated, 403 means not authorized.

---

## Common Mistakes

- Mixing up 401 and 403.
- Using 200 for everything.
- Thinking HTTP is only for web pages.

## Summary

- HTTP request: method, path, headers, body.
- HTTP response: status, headers, body.
- Methods: GET, POST, PUT, PATCH, DELETE.
- Status codes: 2xx, 3xx, 4xx, 5xx.
