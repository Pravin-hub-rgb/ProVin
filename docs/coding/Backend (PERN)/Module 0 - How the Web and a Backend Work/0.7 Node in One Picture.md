Node.js is a JavaScript runtime that runs outside the browser. It lets you write server-side code in JavaScript/TypeScript.

```
┌─────────────────────────────────────────────┐
│              Node.js Process                │
│                                             │
│   ┌─────────────────────────────────────┐   │
│   │         Event Loop (single thread)  │   │
│   │                                     │   │
│   │   ┌─────┐ ┌─────┐ ┌─────┐          │   │
│   │   │Timer│ │ I/O │ │Promise│          │   │
│   │   └─────┘ └─────┘ └─────┘          │   │
│   └─────────────────────────────────────┘   │
│                                             │
│   Non-blocking: file/network ops don't      │
│   block the loop. They use the OS.          │
└─────────────────────────────────────────────┘
```

- **Single thread:** one event loop handles all requests.
- **Non-blocking I/O:** file reads, network calls, timers are async.
- **Event loop:** processes callbacks when they are ready.
- **Blocking the loop:** CPU-heavy work freezes all requests.

**Key idea:** Node does not use one thread per request. It uses one thread with async operations. A slow loop (e.g., a big `for` loop) freezes the server.

## Common Mistakes

- Thinking Node uses one thread per request.
- Blocking the event loop with CPU-heavy work.
- Confusing async with parallel.

## Questions

1. What is Node.js?

**Answer:** A JavaScript runtime that runs outside the browser.

2. Is Node multi-threaded?

**Answer:** No — single-threaded event loop.

3. What is non-blocking I/O?

**Answer:** File/network operations don't block the event loop; they use the OS.

4. What happens if you block the event loop?

**Answer:** All requests freeze until the blocking work completes.

5. How do you run a Node file?

**Answer:** `node file.js`.
