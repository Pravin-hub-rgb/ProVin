REST (Representational State Transfer) is a way of thinking about APIs. Resources are nouns; HTTP methods are verbs.

```
GET    /bookmarks        → list bookmarks
POST   /bookmarks        → create a bookmark
GET    /bookmarks/123    → get one bookmark
PUT    /bookmarks/123    → replace a bookmark
PATCH  /bookmarks/123    → partially update
DELETE /bookmarks/123    → delete a bookmark
```

- **Resource:** a noun (bookmarks, users, posts).
- **Method:** a verb (GET, POST, PUT, PATCH, DELETE).
- **URL:** identifies the resource.
- **Idempotent:** GET, PUT, DELETE are idempotent (same result if repeated). POST is not.

**Design rules:**

- Use plural nouns: `/users`, not `/user`.
- Use IDs in path: `/users/123`.
- Use query params for filtering: `/users?role=admin`.

## Common Mistakes

- Using verbs in URLs (`/getUser`, `/deleteUser`).
- Using POST for everything.
- Not using status codes correctly.

## Questions

1. What is REST?

**Answer:** A way of designing APIs where resources are nouns and HTTP methods are verbs.

2. What is a resource?

**Answer:** A noun representing a thing (users, bookmarks, posts).

3. Which methods are idempotent?

**Answer:** GET, PUT, DELETE.

4. Why use plural nouns in URLs?

**Answer:** Consistency and convention (/users, not /user).

5. Where does filtering go?

**Answer:** Query parameters (/users?role=admin).
