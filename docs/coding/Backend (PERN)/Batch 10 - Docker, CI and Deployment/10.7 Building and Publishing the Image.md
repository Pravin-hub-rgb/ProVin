# Doc 10.7 — Building and Publishing the Image

## Cheat Sheet (Quick Recall)

- CI builds image on every push to main.
- Push to container registry (Docker Hub, GHCR).
- `docker build` and `docker push`.
- Tag with commit SHA or version.

## Where We Are So Far

In 10.6 we saw CI. Now building and publishing the image.

## Broader Goal

The goal of Batch 10 is to package and deploy the stack. Current step: image build/publish.

---

CI builds the image on every push to main and pushes it to a container registry.

```yaml
# In CI workflow
- name: Build image
  run: docker build -t my-api:${{ github.sha }} .
- name: Push to registry
  run: docker push my-api:${{ github.sha }}
```

- **Build:** `docker build -t my-api:latest .`.
- **Push:** `docker push my-api:latest`.
- **Registry:** Docker Hub, GitHub Container Registry (GHCR).
- **Tagging:** commit SHA or version number.

**Mini-project:** the build job in CI.

## What It Is NOT

- Building is **not** deploying — CI builds, CD deploys.
- Registry is **not** optional — needed for deployment.
- Tagging is **not** arbitrary — use SHA or version.

---

## Common Mistakes

- Not tagging with SHA/version.
- Pushing without authentication.
- Building on every branch (use main only).
