Operating the deployed app: reading logs, rolling back, zero-downtime deploys, backups, monitoring.

```bash
# Read logs
docker logs my-api

# Roll back
docker pull my-api:previous-sha
docker compose up -d

# Health check
curl https://api.example.com/ready
```

- **Logs:** pino JSON logs (use log aggregator: Datadog, Grafana, etc.).
- **Rollback:** deploy previous image tag.
- **Zero-downtime:** deploy new, drain old, switch (concept).
- **Backups:** DB backups (concept).
- **Monitor:** uptime, error rate, latency, resource usage.

**Break it on purpose:** cause a deliberate production failure and fix it.

## What It Is NOT

- Zero-downtime is **not** instant — it requires load balancer.
- Backups are **not** automatic — set them up.
- Monitoring is **not** optional — you need observability.

---

## Common Mistakes

- Not reading logs (blind debugging).
- No rollback plan.
- No backups (data loss).
- No monitoring (silent failures).
