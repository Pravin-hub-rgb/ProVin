One file runs API, Postgres, and the web app.

```yaml
services:
  db:
    image: postgres:18
    environment:
      POSTGRES_PASSWORD: secret
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 5s
      retries: 5

  api:
    build: ./apps/api
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://postgres:secret@db:5432/postgres
    depends_on:
      db:
        condition: service_healthy

  web:
    build: ./apps/web
    ports:
      - "5173:5173"

volumes:
  pgdata:
```

- **Services:** db, api, web.
- **Networks:** automatic (services talk by name).
- **Volumes:** `pgdata` persists DB data.
- **Health check:** API waits for ready DB (`depends_on: condition: service_healthy`).
- **Env vars:** `DATABASE_URL` points to `db` service.

## What It Is NOT

- Compose is **not** for production at scale — it is for dev/small deployments.
- `depends_on` is **not** enough without health check — just starts order.
- Volumes are **not** optional for data persistence.

---

## Common Mistakes

- Missing health check → API starts before DB ready.
- Hardcoding secrets in Compose (use env file).
- Not using volumes → data lost on restart.

1. Create a Compose file with db + api + web.

3. Run `docker compose up` and verify.
