## Problem — Why Do Apps Break on Other Machines?

The "works on my machine" problem. Containers solve it. First image vs container, then layers, then VMs vs containers.

```
┌─────────────────────────────────────────────┐
│           Docker Image (template)           │
│  ┌─────────────────────────────────────┐   │
│  │  Layer 3: app code + node_modules   │   │
│  │  Layer 2: Node.js runtime           │   │
│  │  Layer 1: OS base (Alpine/Debian)    │   │
│  └─────────────────────────────────────┘   │
│                                             │
│  Container = running instance of image      │
└─────────────────────────────────────────────┘
```

- **Image:** a read-only template (layers).
- **Container:** a running instance of an image.
- **Layers:** each Dockerfile instruction adds a layer (cached).
- **VMs vs containers:** VMs virtualize hardware (heavy); containers share OS kernel (light).

## What It Is NOT

- Image is **not** container — image is template, container is instance.
- Container is **not** a VM — lighter, shares OS kernel.
- Layers are **not** optional — they enable caching.

---

## Common Mistakes

- Confusing image and container.
- Thinking containers are VMs.
- Not understanding layers (caching).
