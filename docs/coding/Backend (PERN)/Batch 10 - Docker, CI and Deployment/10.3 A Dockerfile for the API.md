A Dockerfile builds an image. Multi-stage build: compile TS, ship only what production needs.

```dockerfile
# Stage 1: Build
FROM node:22-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Production
FROM node:22-alpine
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY package*.json ./
USER node
EXPOSE 3000
CMD ["node", "dist/server.js"]
```

- **Base image:** `node:22-alpine` (small).
- **Layer order:** dependencies first (cached), then code.
- **`.dockerignore`:** exclude `node_modules`, `.git`, `.env`.
- **Multi-stage:** compile in builder, ship only `dist/` + `node_modules`.
- **Non-root:** `USER node` for security.

**Manual first:** naive single-stage image → then improved with before/after size comparison.

## What It Is NOT

- Single-stage is **not** for production — multi-stage is.
- Running as root is **not** safe — use `USER node`.
- `.dockerignore` is **not** optional — it speeds up builds.

---

## Common Mistakes

- Wrong layer order (cache misses).
- Missing `.dockerignore` (huge images).
- Running as root (security risk).
- Shipping dev dependencies.
