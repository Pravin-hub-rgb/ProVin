List with filters and paging, create, update, delete, cache invalidation, loading/error states, optimistic updates.

```ts
const { data, isLoading, isError } = useQuery({
  queryKey: ["bookmarks", { tag, q, page }],
  queryFn: () => apiClient<BookmarkList>(`/bookmarks?tag=${tag}&q=${q}&page=${page}`),
});

const mutation = useMutation({
  mutationFn: (newBookmark) => apiClient("/bookmarks", { method: "POST", body: JSON.stringify(newBookmark) }),
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ["bookmarks"] }),
});
```

- **List:** filters (`tag`, `q`) + paging (`page`, `limit`).
- **Mutations:** create/update/delete.
- **Cache invalidation:** `invalidateQueries` after mutation.
- **Loading/error states:** `isLoading`, `isError`.
- **Optimistic update:** update UI before server confirms.
- **Tie to HTTP statuses:** 401 → redirect, 404 → not found, 422 → show errors.

## What It Is NOT

- TanStack Query is **not** a state manager — server state only.
- Optimistic updates are **not** guaranteed — must rollback on error.
- Cache is **not** permanent — invalidate on mutation.

---

## Common Mistakes

- Not invalidating cache after mutation.
- Not handling loading/error states.
- Not tying to HTTP statuses.
