An npm workspace with a `shared` package holding the Zod schemas used by both the API and the React app.

```json
// package.json (root)
{
  "workspaces": ["apps/*", "packages/*"]
}
```

```
project/
├── apps/
│   ├── api/          # Express backend
│   └── web/          # React frontend
└── packages/
    └── shared/       # Zod schemas
        └── src/
            └── bookmark.schema.ts
```

```ts
// packages/shared/src/bookmark.schema.ts
import { z } from "zod";
export const createBookmarkSchema = z.object({
  url: z.string().url(),
  title: z.string().min(1).max(200),
});
export type CreateBookmark = z.infer<typeof createBookmarkSchema>;
```

- **Shared package:** holds Zod schemas.
- **API:** imports schema for validation.
- **Frontend:** imports schema for form validation.
- **Break it on purpose:** change a rule in shared schema → both sides update.

## What It Is NOT

- Shared schemas are **not** automatic — you must set up workspaces.
- npm workspaces are **not** the only option — monorepo tools exist.
- Schemas are **not** duplicated — single source of truth.

---

## Common Mistakes

- Duplicating schemas (drift).
- Not using workspaces (manual sync).
- Forgetting to rebuild shared package.
