One module wraps `fetch`. Base URL from environment, JSON handling, the shared error shape turned into a typed error.

```ts
// apiClient.ts
const BASE_URL = import.meta.env.VITE_API_URL || "http://localhost:3000";

class ApiError extends Error {
  constructor(public status: number, public code: string, message: string) {
    super(message);
  }
}

export async function apiClient<T>(path: string, options?: RequestInit): Promise<T> {
  const res = await fetch(`${BASE_URL}${path}`, {
    ...options,
    headers: { "Content-Type": "application/json", ...options?.headers },
  });
  if (!res.ok) {
    const body = await res.json();
    throw new ApiError(res.status, body.error.code, body.error.message);
  }
  return res.json();
}
```

- `BASE_URL` from env.
- `ApiError` typed error.
- Components call `apiClient<T>("/bookmarks")`, not `fetch`.

## What It Is NOT

- `fetch` is **not** called directly in components — use `apiClient`.
- `ApiError` is **not** a generic Error — it carries status and code.
- Base URL is **not** hardcoded — use env.

---

## Common Mistakes

- Calling `fetch` directly in components.
- Not typing errors.
- Hardcoding base URL.
