Factories and builders create valid records with overrides, instead of copy-pasted fixtures.

```ts
function makeUser(overrides: Partial<User> = {}): User {
  return {
    id: randomUUID(),
    email: `user-${randomUUID()}@test.com`,
    role: "USER",
    ...overrides,
  };
}

function makeBookmark(userId: string, overrides: Partial<Bookmark> = {}): Bookmark {
  return {
    id: randomUUID(),
    url: "https://example.com",
    title: "Example",
    userId,
    ...overrides,
  };
}
```

- `makeUser()` — creates a valid user with defaults.
- `makeUser({ role: "admin" })` — overrides specific fields.
- Avoid copy-pasted fixtures (hard to maintain).

## What It Is NOT

- Fixtures are **not** recommended — hard to maintain.
- Factories are **not** for production — test only.
- Defaults are **not** arbitrary — they must be valid.

---

## Common Mistakes

- Copy-pasted fixtures (hard to maintain).
- Invalid default values.
- Not using overrides (rigid tests).
