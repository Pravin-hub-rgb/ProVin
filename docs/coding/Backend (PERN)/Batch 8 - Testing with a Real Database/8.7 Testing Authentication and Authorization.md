Helpers that register and log in a test user and return a token or cookie. Test protected routes, expiry, refresh rotation, reuse detection.

```ts
async function registerAndLogin(app, email = "test@test.com", password = "password123") {
  await request(app).post("/auth/register").send({ email, password });
  const res = await request(app).post("/auth/login").send({ email, password });
  return res.body.data.accessToken;
}

describe("auth", () => {
  it("protects routes", async () => {
    const res = await request(app).get("/me");
    expect(res.status).toBe(401);
  });

  it("user A cannot see user B's bookmarks", async () => {
    const tokenA = await registerAndLogin(app, "a@test.com");
    const tokenB = await registerAndLogin(app, "b@test.com");
    const createRes = await request(app).post("/bookmarks").set("Authorization", `Bearer ${tokenA}`).send({ url: "https://a.com", title: "A" });
    const id = createRes.body.data.id;
    const getRes = await request(app).get(`/bookmarks/${id}`).set("Authorization", `Bearer ${tokenB}`);
    expect(getRes.status).toBe(404);
  });
});
```

- **Helper:** register + login → token.
- **Protected routes:** 401 without token.
- **Ownership:** user A cannot see/edit/delete user B's data.
- **Expiry/refresh/reuse:** test token lifecycle.

## What It Is NOT

- Auth tests are **not** optional — they are critical.
- Testing with one user is **not** enough — test cross-user.
- Mocking auth is **not** recommended — test the real flow.

---

## Common Mistakes

- Testing with one user only.
- Not testing ownership (cross-user).
- Not testing token expiry/refresh.
