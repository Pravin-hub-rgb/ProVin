Supertest calls the Express `app` directly — no server needed, no port opened.

```ts
import request from "supertest";
import { createApp } from "../src/app.js";

const app = createApp();

describe("GET /health", () => {
  it("returns 200", async () => {
    const res = await request(app).get("/health");
    expect(res.status).toBe(200);
    expect(res.body).toEqual({ status: "ok" });
  });
});

describe("POST /bookmarks", () => {
  it("returns 422 on bad input", async () => {
    const res = await request(app).post("/bookmarks").send({ url: "bad" });
    expect(res.status).toBe(422);
    expect(res.body.error.code).toBe("VALIDATION_ERROR");
  });
});
```

- `request(app)` — calls the app directly.
- `.get()`, `.post()`, `.send()` — HTTP methods.
- Assert `status`, `headers`, `body`.

**This is where `app.ts` vs `server.ts` pays off** — tests import `createApp()` without opening a port.

## What It Is NOT

- Supertest is **not** a browser — it calls the app directly.
- `app.ts` is **not** `server.ts` — tests import `app.ts`.
- HTTP tests are **not** unit tests — they test the full request/response cycle.

---

## Common Mistakes

- Importing `server.ts` (opens a port).
- Not asserting status/headers/body.
- Testing implementation instead of behavior.
