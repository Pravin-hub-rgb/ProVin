## Broader Goal

The goal of Batch 8 is to write tests that give real confidence. Current step: what and why to test.

---

The test pyramid in plain words: unit tests (fast, isolated), integration tests (real DB), E2E (full flow). What an API test should prove: behavior, not implementation. What is not worth testing.

- **Unit:** pure functions (validators, helpers, paginate).
- **Integration:** routes with real database.
- **E2E:** full flow (optional, OUT OF SCOPE).

**What to test:**

- Happy paths (create, read, update, delete).
- Error paths (400, 401, 403, 404, 409, 429).
- Edge cases (empty list, huge page size).
- Auth/ownership (user A cannot see user B's data).

**What not to test:**

- Framework internals (Express routing).
- Third-party libraries.
- Trivial getters.

## What It Is NOT

- 100% coverage is **not** the goal.
- Testing implementation is **not** valuable.
- Mocking everything is **not** confidence.

---

## Common Mistakes

- Testing implementation details.
- Mocking the database (tests the mock, not the queries).
- Chasing coverage numbers.
