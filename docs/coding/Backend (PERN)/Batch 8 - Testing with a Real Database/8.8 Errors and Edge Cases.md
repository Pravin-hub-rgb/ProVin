Every status code the API can return gets at least one test. Boundary values, empty lists, huge page sizes.

```ts
describe("errors", () => {
  it("400 on bad JSON", async () => {
    const res = await request(app).post("/bookmarks").send("bad");
    expect(res.status).toBe(400);
  });
  it("401 without token", async () => {
    const res = await request(app).get("/me");
    expect(res.status).toBe(401);
  });
  it("404 on missing bookmark", async () => {
    const res = await request(app).get("/bookmarks/999");
    expect(res.status).toBe(404);
  });
  it("409 on duplicate URL", async () => {
    // create twice with same URL
    expect(res.status).toBe(409);
  });
  it("429 on rate limit", async () => {
    // hammer login
    expect(res.status).toBe(429);
  });
});
```

- **Error-coverage table:** each row linked to a test.
- **Boundary values:** min/max, empty, null.
- **Empty list:** `GET /bookmarks` with no data.
- **Huge page size:** `limit=1000000` → capped at 50.

## What It Is NOT

- Error tests are **not** optional — they are critical.
- Boundary values are **not** the same as happy paths.
- One test per status code is **not** enough — test edge cases too.

---

## Common Mistakes

- Missing status codes in tests.
- Not testing boundary values.
- Not testing empty lists.
