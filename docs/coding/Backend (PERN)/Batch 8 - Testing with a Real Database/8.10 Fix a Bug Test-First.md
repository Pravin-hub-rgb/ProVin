# Doc 8.10 — Fix a Bug Test-First

## Cheat Sheet (Quick Recall)

- Reproduce bug with a failing test.
- Fix the bug.
- Watch test pass.
- Light TDD: red → green → refactor.

## Where We Are So Far

In 8.9 we saw coverage. Now fix a bug test-first — light TDD.

## Broader Goal

The goal of Batch 8 is to write tests that give real confidence. Current step: test-first debugging.

---

Reproduce a planted bug with a failing test, fix it, watch it pass. Light form of TDD.

```ts
// 1. Red: write a failing test
it("returns 404 for another user's bookmark", async () => {
  const res = await request(app).get(`/bookmarks/${otherUserBookmarkId}`).set("Authorization", `Bearer ${token}`);
  expect(res.status).toBe(404);
});

// 2. Fix: add ownership check
// 3. Green: test passes
```

- **Red:** write a failing test (reproduces the bug).
- **Green:** fix the bug (test passes).
- **Refactor:** clean up (test still passes).

**Mini-project:** the bug, the test, and the fix in three commits.

## What It Is NOT

- TDD is **not** mandatory — it is a tool.
- Test-first is **not** always practical — use when it helps.
- Red → green → refactor is **not** a religion.

---

## Common Mistakes

- Writing tests after the fix (misses the bug).
- Not reproducing first (guessing).
- Over-engineering TDD.
