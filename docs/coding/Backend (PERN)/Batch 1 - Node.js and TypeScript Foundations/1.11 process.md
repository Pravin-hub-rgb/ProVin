## Problem — How Do You Access the Current Process?

The `process` object gives access to the current Node.js process: args, env, exit codes, standard I/O, signals.

```ts
// Command-line args
console.log(process.argv); // ["node", "script.js", "arg1", "arg2"]

// Environment variables
console.log(process.env.NODE_ENV); // "development"

// Exit codes
process.exit(0); // success
process.exit(1); // error

// Standard I/O
process.stdout.write("Hello\n");
process.stderr.write("Error\n");

// Signals
process.on("SIGINT", () => {
  console.log("Ctrl+C pressed");
  process.exit(0);
});
```

**parseArgs (node:util):**

```ts
import { parseArgs } from "node:util";
const { values } = parseArgs({
  options: {
    since: { type: "string" },
    limit: { type: "string", default: "10" },
  },
});
console.log(values.since, values.limit);
```

- `process.argv`: command-line arguments.
- `process.env`: environment variables.
- `process.exit(code)`: exit with code (0 = success, 1 = error).
- `process.stdin/stdout/stderr`: standard I/O.
- `process.on("SIGINT")`: handle Ctrl+C.
- `parseArgs` from `node:util` for flag parsing.

## What It Is NOT

- `process.argv` is **not** just user args — it includes node and script path.
- `process.exit(0)` is **not** required — Node exits when the loop is empty.
- `process.env` is **not** type-safe — values are `string | undefined`.

---

## Common Mistakes

- Not setting exit codes (always 0).
- Swallowing errors in catch.
- Not handling SIGINT (Ctrl+C).

---

## Try It Yourself

1. Build a CLI with two flags that exits 1 on bad input.
2. Load config from env and fail fast when missing.
3. Handle Ctrl+C gracefully.
