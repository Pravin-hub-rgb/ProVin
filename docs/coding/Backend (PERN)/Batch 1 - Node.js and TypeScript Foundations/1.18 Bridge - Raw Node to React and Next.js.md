# Doc 1.18 — Bridge: Raw Node to React/Next.js

## Cheat Sheet (Quick Recall)

- React/Next.js automation is built on raw Node work.
- File-based routing (Next.js) automates manual `if (req.url)` routing.
- Server Actions/API routes automate `res.end(JSON.stringify(...))`.
- Next.js has built-in `.env` support; raw Node uses `--env-file` or dotenv.
- `npm run dev` hot reload automates nodemon-style restarts.

## Where We Are So Far

Batch 1 is complete — you can set up, run, type-check, and debug a TypeScript Node project. This short note connects that raw Node work to the React/Next.js tools you already know.

## Broader Goal

The goal of this note is to show that framework "magic" is just automated raw Node work. Once you see the manual version, the automated version makes sense.

---

If you have used Next.js, you have already used Node without knowing it. Next.js runs on Node and automates the manual work you just learned.

| Raw Node (what you just did) | Next.js (what you will use next) |
|---|---|
| Routing with `if (req.url === '/')` | File-based routing — folder + `page.tsx` = route |
| Manual `res.end(JSON.stringify(...))` | API routes / Server Actions built in |
| `import`/`export` modules | Same module system |
| Manual async `await fetch()` | Direct `await fetch()` in Server Components |
| Manual `.env` (`dotenv` or `--env-file`) | Next.js has `.env` support built in |
| `nodemon` auto-restart | `npm run dev` hot reload |

**The real point:** The "magic" you see in Next.js (folder = route, server components, API routes) connects directly to this manual work in raw Node. Now when you see routing or data fetching in the Next.js course, you will think — "this is the same thing I did with if/else and JSON.stringify in raw Node, just automated by the framework."

**How they connect:**

- Next.js server components run on Node. They can `await fetch()` directly because Node supports async/await.
- Next.js API routes are just Express-like handlers under the hood.
- Next.js reads `.env` files automatically (same concept as `--env-file`).
- `npm run dev` in Next.js gives hot reload (same as nodemon, but built in).

## Common Mistakes

- Thinking Next.js is "different" from Node — it runs on Node.
- Not understanding that file-based routing is just automated URL routing.
- Thinking `.env` in Next.js is different from `.env` in Node — same concept.
