# Doc 1.13 — Errors

## Cheat Sheet (Quick Recall)

- `Error` class: `new Error("message")`.
- Custom errors: `class MyError extends Error`.
- `cause`: `new Error("msg", { cause: err })`.
- Unhandled rejections: `process.on("unhandledRejection")`.
- `try`/`catch` for sync and async errors.

Errors are inevitable. Handle them well.

```ts
// Basic error
throw new Error("Something went wrong");

// Custom error
class NotFoundError extends Error {
  constructor(message: string) {
    super(message);
    this.name = "NotFoundError";
  }
}

// Error with cause
try {
  // something
} catch (err) {
  throw new Error("Failed to process", { cause: err });
}

// Unhandled rejection handler
process.on("unhandledRejection", (reason) => {
  console.error("Unhandled:", reason);
  process.exit(1);
});
```

- `Error` class: base for all errors.
- Custom errors: extend `Error`.
- `cause`: chain errors (ES2022).
- Unhandled rejections: catch at process level.

## Common Mistakes

- Swallowing errors with empty `catch`.
- Not setting `this.name` in custom errors.
- Ignoring unhandled rejections.

## Questions

1. How to create a custom error?

**Answer:** `class MyError extends Error { ... }`.

2. What is `cause` used for?

**Answer:** Chaining errors (ES2022).

3. How to handle unhandled rejections?

**Answer:** `process.on("unhandledRejection", callback)`.

4. Why not swallow errors?

**Answer:** Silent failures are hard to debug.

5. What should `this.name` be set to?

**Answer:** The error class name.
