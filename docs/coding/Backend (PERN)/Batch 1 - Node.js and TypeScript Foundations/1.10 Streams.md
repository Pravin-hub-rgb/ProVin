## Problem — How Do You Process a 1 GB File Without Crashing?

Streams process data in chunks, keeping memory low. First basic stream, then `readline` for line-by-line, then backpressure.

```ts
import { createReadStream } from "node:fs";
import { createInterface } from "node:readline";

const rl = createInterface({
  input: createReadStream("big-file.log"),
  crlfDelay: Infinity,
});

let count = 0;
for await (const line of rl) {
  count++;
}
console.log(`Lines: ${count}`);
```

- `createReadStream` reads in chunks.
- `readline` processes line by line.
- `for await...of` consumes the stream.
- Memory stays low even for 1 GB files.

**Backpressure:** if the consumer (processing) is slower than the producer (reading), the stream pauses to avoid overwhelming memory.

**Stream types:**

- Readable: source of data (file, network).
- Writable: destination (file, network).
- Duplex: both (TCP socket).
- Transform: modify data in transit (compression).

## What It Is NOT

- Streams are **not** buffers — they process in chunks, not all at once.
- `readFileSync` is **not** memory-efficient — it loads everything.
- Backpressure is **not** automatic in all cases — handle it.

---

## Common Mistakes

- Using `readFileSync` on huge files (blocks + memory).
- Not handling stream errors.
- Ignoring backpressure.
