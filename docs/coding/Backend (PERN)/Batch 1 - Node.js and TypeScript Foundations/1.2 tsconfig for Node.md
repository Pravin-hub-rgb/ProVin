## Problem — How Do You Tell TypeScript How to Behave?

TypeScript needs configuration. `tsconfig.json` tells the compiler how to behave. Wrong config = import errors, missed type errors, or build failures.

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "nodenext",
    "moduleResolution": "nodenext",
    "strict": true,
    "noEmit": true,
    "erasableSyntaxOnly": true,
    "verbatimModuleSyntax": true,
    "skipLibCheck": true
  },
  "include": ["src"]
}
```

- `strict: true` — enables all strict type checks.
- `module: nodenext` — uses Node's native ESM.
- `noEmit: true` — type-checks only, no JS output.
- `erasableSyntaxOnly: true` — disallows enums, namespaces, constructor param properties.
- `verbatimModuleSyntax: true` — requires `import type` for type-only imports.
- `skipLibCheck: true` — skips type checking of declaration files (faster).

## What It Is NOT

- `strict: true` is **not** optional — it catches real bugs.
- `noEmit: true` does **not** emit files — it only checks.
- `erasableSyntaxOnly` is **not** a style preference — it prevents non-erasable syntax.

---

## Common Mistakes

- Forgetting `module: nodenext` → import errors.
- Not using `strict: true` → missed type errors.
- Using enums (not erasable) → compile errors.

## Try It Yourself

1. Toggle each flag and read the error it produces.
2. Add an `enum` and see `erasableSyntaxOnly` catch it.
3. Add a type-only import without `import type` and see `verbatimModuleSyntax` catch it.
