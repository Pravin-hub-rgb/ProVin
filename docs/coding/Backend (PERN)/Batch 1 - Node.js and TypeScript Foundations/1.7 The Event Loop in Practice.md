# Doc 1.7 — The Event Loop in Practice

## Cheat Sheet (Quick Recall)

- Event loop processes callbacks: timers, I/O, microtasks.
- Microtasks (promises, nextTick) run before macrotasks (timers).
- Blocking the loop freezes all requests.
- `setImmediate` runs after I/O; `process.nextTick` runs before I/O.

The event loop is how Node handles async operations on a single thread.

```ts
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// Output: 1, 4, 3, 2
```

- **Microtasks** (promises, `process.nextTick`) run first.
- **Macrotasks** (timers, I/O) run next.
- `setImmediate` runs after I/O callbacks.
- `process.nextTick` runs before I/O (highest priority).

**Blocking the loop:**

```ts
// CPU-heavy loop freezes all requests
for (let i = 0; i < 1e9; i++) {}
```

A slow loop blocks everything — timers, I/O, promises.

## Common Mistakes

- Blocking the event loop with CPU-heavy work.
- Confusing microtasks and macrotasks.
- Using `setTimeout(fn, 0)` expecting immediate execution.

## Questions

1. What runs first: microtasks or macrotasks?

**Answer:** Microtasks (promises, nextTick).

2. What is `process.nextTick`?

**Answer:** Highest-priority microtask, runs before I/O.

3. What happens if you block the event loop?

**Answer:** All requests freeze until blocking work completes.

4. What is `setImmediate`?

**Answer:** Runs after I/O callbacks.

5. How to measure event loop lag?

**Answer:** Compare `Date.now()` before and after a heavy operation.
