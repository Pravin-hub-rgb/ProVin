## Problem — How Does Node Handle Async Operations on a Single Thread?

The event loop is how Node handles async operations on a single thread. Microtasks (promises, `nextTick`) run first; macrotasks (timers, I/O) run next.

```ts
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// Output: 1, 4, 3, 2
```

- **Microtasks** (promises, `process.nextTick`) run first.
- **Macrotasks** (timers, I/O) run next.
- `setImmediate` runs after I/O callbacks.
- `process.nextTick` runs before I/O (highest priority).

**Blocking the loop:**

```ts
// CPU-heavy loop freezes all requests
for (let i = 0; i < 1e9; i++) {}
```

A slow loop blocks everything — timers, I/O, promises.

## What It Is NOT

- The event loop is **not** multi-threaded — single thread.
- `setTimeout(fn, 0)` is **not** immediate — it goes to the macrotask queue.
- Blocking is **not** harmless — it freezes all requests.

---

## Common Mistakes

- Blocking the event loop with CPU-heavy work.
- Confusing microtasks and macrotasks.
- Using `setTimeout(fn, 0)` expecting immediate execution.
