## Problem — How Do You Handle Async Operations in Node?

Node is async by nature. Network calls, file reads, timers — all async. First callbacks (old), then promises, then async/await (preferred).

**Callbacks (old style):**

```ts
import { readFile } from "node:fs";
readFile("file.txt", (err, data) => {
  if (err) throw err;
  console.log(data);
});
```

**Promises:**

```ts
import { readFile } from "node:fs/promises";
readFile("file.txt")
  .then((data) => console.log(data))
  .catch((err) => console.error(err));
```

**async/await (preferred):**

```ts
import { readFile } from "node:fs/promises";
async function main() {
  try {
    const data = await readFile("file.txt");
    console.log(data);
  } catch (err) {
    console.error(err);
  }
}
main();
```

- `async` function returns a `Promise`.
- `await` pauses until the promise resolves.
- `try`/`catch` handles errors.

## What It Is NOT

- `await` is **not** blocking the thread — it pauses the function, not the event loop.
- Promises are **not** callbacks — they are composable and chainable.
- `async` is **not** parallel — it is sequential async.

---

## Common Mistakes

- Forgetting `await` → gets a Promise, not the value.
- Not handling errors → unhandled rejection.
- Mixing callbacks and promises.
