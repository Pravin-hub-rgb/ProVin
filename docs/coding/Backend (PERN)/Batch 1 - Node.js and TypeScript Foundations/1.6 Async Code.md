- `async`/`await`: cleaner syntax for promises.

- `try`/`catch`: error handling with async/await.

Node is async by nature. Network calls, file reads, timers — all async.

**Callbacks (old style):**

```ts
import { readFile } from "node:fs";
readFile("file.txt", (err, data) => {
  if (err) throw err;
  console.log(data);
});
```

**Promises:**

```ts
import { readFile } from "node:fs/promises";
readFile("file.txt")
  .then((data) => console.log(data))
  .catch((err) => console.error(err));
```

**async/await (preferred):**

```ts
import { readFile } from "node:fs/promises";
async function main() {
  try {
    const data = await readFile("file.txt");
    console.log(data);
  } catch (err) {
    console.error(err);
  }
}
main();
```

- `async` function returns a `Promise`.
- `await` pauses until the promise resolves.
- `try`/`catch` handles errors.

## Common Mistakes

- Forgetting `await` → gets a Promise, not the value.
- Not handling errors → unhandled rejection.
- Mixing callbacks and promises.

## Questions

1. What does `async` do to a function?

**Answer:** Makes it return a Promise.

2. What does `await` do?

**Answer:** Pauses until the promise resolves.

3. How to handle errors with async/await?

**Answer:** `try`/`catch`.

4. What is `Promise<T>`?

**Answer:** A typed promise that resolves to type T.

5. Why prefer async/await over callbacks?

**Answer:** Cleaner, easier to read, better error handling.
