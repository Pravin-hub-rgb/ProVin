- `timestamptz` in Postgres (always store UTC).
- `Intl.DateTimeFormat` for formatting.
- Time zones: store UTC, display in user's zone.

Time is tricky. Store it in UTC, display it in the user's time zone.

```ts
const now = new Date();
console.log(now.toISOString()); // "2026-11-25T10:30:00.000Z"
console.log(now.getTime());     // milliseconds since epoch
```

**ISO 8601:** `2026-11-25T10:30:00Z` (UTC). Always use ISO format for APIs.

**Time zones:**

```ts
const fmt = new Intl.DateTimeFormat("en-IN", {
  timeZone: "Asia/Kolkata",
  dateStyle: "medium",
  timeStyle: "short",
});
console.log(fmt.format(now)); // "25 Nov 2026, 4:00 pm"
```

**Rules:**

- Store in UTC (database: `timestamptz`).
- Display in user's time zone.
- Never use `Date` for money or precise calculations.

## Common Mistakes

- Storing local time instead of UTC.
- Using `float` for timestamps.
- Ignoring time zones in APIs.

## Questions

1. What format for API timestamps?

**Answer:** ISO 8601 (e.g., `2026-11-25T10:30:00Z`).

2. What does `timestamptz` store?

**Answer:** Timestamp with time zone (always UTC internally).

3. How to format dates for a locale?

**Answer:** `Intl.DateTimeFormat(locale, options)`.

4. Why store in UTC?

**Answer:** Avoids time zone ambiguity; convert to user's zone on display.

5. What method returns ISO string?

**Answer:** `date.toISOString()`.
