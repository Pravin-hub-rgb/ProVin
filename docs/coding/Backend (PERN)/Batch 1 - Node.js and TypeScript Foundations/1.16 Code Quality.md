## Problem — How Do You Keep Code Consistent and Bug-Free?

Code quality tools catch bugs and enforce style. First ESLint (bugs/style), then Prettier (formatting), then scripts.

```bash
npm install -D eslint prettier @typescript-eslint/parser @typescript-eslint/eslint-plugin
```

**ESLint config (`.eslintrc.json`):**

```json
{
  "parser": "@typescript-eslint/parser",
  "plugins": ["@typescript-eslint"],
  "extends": ["eslint:recommended", "plugin:@typescript-eslint/recommended"],
  "rules": {
    "no-console": "warn"
  }
}
```

**Prettier config (`.prettierrc`):**

```json
{
  "semi": true,
  "singleQuote": true,
  "tabWidth": 2
}
```

**Scripts:**

```json
{
  "scripts": {
    "dev": "node --watch src/server.ts",
    "check": "tsc --noEmit",
    "lint": "eslint src/",
    "format": "prettier --write src/"
  }
}
```

**Editor integration:** format on save, lint on save.

## What It Is NOT

- ESLint is **not** a formatter — Prettier handles formatting.
- Prettier is **not** a linter — ESLint catches bugs.
- `npm run check` is **not** `npm run lint` — check = tsc, lint = ESLint.

---

## Common Mistakes

- Not running lint before commit.
- Ignoring ESLint warnings.
- Inconsistent formatting (use Prettier).
