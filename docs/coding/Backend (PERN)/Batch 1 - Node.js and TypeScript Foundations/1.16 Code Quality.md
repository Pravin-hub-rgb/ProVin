Code quality tools catch bugs and enforce style.

```bash
npm install -D eslint prettier @typescript-eslint/parser @typescript-eslint/eslint-plugin
```

**ESLint config (`.eslintrc.json`):**

```json
{
  "parser": "@typescript-eslint/parser",
  "plugins": ["@typescript-eslint"],
  "extends": ["eslint:recommended", "plugin:@typescript-eslint/recommended"],
  "rules": {
    "no-console": "warn"
  }
}
```

**Prettier config (`.prettierrc`):**

```json
{
  "semi": true,
  "singleQuote": true,
  "tabWidth": 2
}
```

**Scripts:**

```json
{
  "scripts": {
    "dev": "node --watch src/server.ts",
    "check": "tsc --noEmit",
    "lint": "eslint src/",
    "format": "prettier --write src/"
  }
}
```

**Editor integration:** format on save, lint on save.

## Common Mistakes

- Not running lint before commit.
- Ignoring ESLint warnings.
- Inconsistent formatting (use Prettier).

## Questions

1. What is ESLint for?

**Answer:** Linting — catches bugs and enforces code style.

2. What is Prettier for?

**Answer:** Formatting — consistent code style.

3. What command runs ESLint?

**Answer:** `eslint src/` (or `npm run lint`).

4. What command formats code with Prettier?

**Answer:** `prettier --write src/`.

5. Why use both ESLint and Prettier?

**Answer:** ESLint catches bugs/logic; Prettier handles formatting. Separation of concerns.
