- Literal types: `type Status = "ok" | "error"`.

- `satisfies`: checks type without widening.

Backend code deals with untrusted input (JSON from requests). TypeScript helps keep it safe.

```ts
function parseUser(input: unknown): { name: string; age: number } {
  if (typeof input !== "object" || input === null) {
    throw new Error("Invalid input");
  }
  const obj = input as Record<string, unknown>;
  if (typeof obj.name !== "string" || typeof obj.age !== "number") {
    throw new Error("Invalid fields");
  }
  return { name: obj.name, age: obj.age };
}
```

- `unknown`: safe. Must narrow before use.
- `any`: unsafe. Disables type checking. Avoid.
- Narrowing: `typeof`, `instanceof`, `in`.
- Literal types: `type Status = "ok" | "error"`.
- `readonly`: prevents mutation of properties.
- `satisfies`: checks type without widening.
- Type guards: functions returning `input is Type`.

## Common Mistakes

- Using `any` to silence errors.
- Not narrowing `unknown`.
- Forgetting `readonly` for config.

## Questions

1. Why prefer `unknown` over `any`?

**Answer:** `unknown` is safe — you must narrow it before use. `any` disables type checking.

2. How to narrow `unknown`?

**Answer:** Use `typeof`, `instanceof`, or `in` operator.

3. What is a literal type?

**Answer:** A type with exact values: `type Status = "ok" | "error"`.

4. What does `readonly` do?

**Answer:** Prevents mutation of a property.

5. What is `satisfies`?

**Answer:** Checks that a value matches a type without widening it.
