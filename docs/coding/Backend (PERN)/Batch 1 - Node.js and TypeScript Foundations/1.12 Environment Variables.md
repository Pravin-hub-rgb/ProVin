# Doc 1.12 — Environment Variables

## Cheat Sheet (Quick Recall)

- `process.env.VAR_NAME` reads env vars.
- `.env` file for local config (never commit).
- `node --env-file=.env` loads env file.
- `.env.example` documents required vars.
- Fail fast: throw if required var is missing.

## Where We Are So Far

Environment variables configure your app without hardcoding secrets.

```bash
# .env (never commit this)
DATABASE_URL=postgres://user:pass@localhost:5432/db
PORT=3000
NODE_ENV=development
```

```ts
const dbUrl = process.env.DATABASE_URL;
if (!dbUrl) {
  throw new Error("DATABASE_URL is required");
}
const port = Number(process.env.PORT) || 3000;
```

**Loading .env:**

```bash
node --env-file=.env src/server.ts
```

**.env.example (commit this):**

```bash
DATABASE_URL=
PORT=3000
NODE_ENV=development
```

**Rules:**

- Never commit `.env` (add to `.gitignore`).
- Commit `.env.example` with empty values.
- Fail fast if a required var is missing.

## Common Mistakes

- Committing `.env` (secrets leaked).
- Not failing fast on missing vars.
- Using `process.env` without checking.

## Questions

1. How to read an env var in Node?

**Answer:** `process.env.VAR_NAME`.

2. How to load a `.env` file?

**Answer:** `node --env-file=.env`.

3. Should `.env` be committed?

**Answer:** No — add to `.gitignore`.

4. What should `.env.example` contain?

**Answer:** Required var names with empty values.

5. Why fail fast on missing vars?

**Answer:** Catch config errors at startup, not at runtime.
