## Problem — How Do You Configure an App Without Hardcoding Secrets?

Environment variables configure your app without hardcoding secrets. Never commit `.env`.

```bash
# .env (never commit this)
DATABASE_URL=postgres://user:pass@localhost:5432/db
PORT=3000
NODE_ENV=development
```

```ts
const dbUrl = process.env.DATABASE_URL;
if (!dbUrl) {
  throw new Error("DATABASE_URL is required");
}
const port = Number(process.env.PORT) || 3000;
```

**Loading .env:**

```bash
node --env-file=.env src/server.ts
```

**.env.example (commit this):**

```bash
DATABASE_URL=
PORT=3000
NODE_ENV=development
```

**Rules:**

- Never commit `.env` (add to `.gitignore`).
- Commit `.env.example` with empty values.
- Fail fast if a required var is missing.

## What It Is NOT

- `.env` is **not** for production secrets — use env vars or secret managers.
- `process.env` is **not** type-safe — values are `string | undefined`.
- Missing vars are **not** harmless — fail fast.

---

## Common Mistakes

- Committing `.env` (secrets leaked).
- Not failing fast on missing vars.
- Using `process.env` without checking.
