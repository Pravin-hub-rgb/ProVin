## Problem — Can You Build a Real CLI Tool That Uses Everything?

Build a command-line tool that reads a web-server log and prints a report. This proves you can write, run, type-check, and debug TypeScript on Node.

**Input:** a log file path. The course provides a script that generates 10,000 to 100,000 lines of realistic log data.

**Parse:** each line into a typed record: timestamp, method, path, status, duration in ms. Count and skip malformed lines, then report how many there were.

**Report:**

- Total requests.
- Requests per status class (2xx, 3xx, 4xx, 5xx).
- Top 10 paths.
- p50 and p95 duration.
- The 5 slowest requests.
- Requests per minute.

**Flags:**

- `--since`, `--until` (ISO timestamps, time zone aware).
- `--format table` or `--format json`.
- `--top N`.

**Requirements:**

- Reads as a stream. A 1,000,000-line file stays under 100 MB of RAM.
- Exit codes: 0 success, 1 usage error, 2 unreadable file.
- At least five modules.
- Passes `tsc --noEmit` and ESLint.

**Done when:** The report is correct on a file with deliberately malformed lines, the memory limit holds, and you can explain where the event loop is and is not blocked.

## What It Is NOT

- This is **not** a full production CLI — it is a learning project.
- `readFileSync` is **not** acceptable — must stream.
- Wrong exit codes are **not** acceptable — 0/1/2.

---

## Common Mistakes

- Using `readFileSync` on huge files.
- Not handling malformed lines.
- Wrong exit codes.
- Not streaming (memory overflow).

---

## Try It Yourself

1. Start from an empty folder and build the CLI.
2. Test with a 1M-line file (memory under 100 MB).
3. Add malformed lines and verify they are skipped.
