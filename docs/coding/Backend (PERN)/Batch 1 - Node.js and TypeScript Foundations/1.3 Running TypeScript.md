# Doc 1.3 — Running TypeScript

## Cheat Sheet (Quick Recall)

- `node file.ts` runs TypeScript with type stripping (no type checking).
- `node --watch` auto-restarts on file changes.
- `tsc --noEmit` type-checks without emitting.
- `tsc` builds JS for production.
- Type stripping removes types but does not check them.

Node 26 can run TypeScript directly via type stripping. It removes type annotations but does not check them.

```bash
node src/server.ts          # runs (strips types)
node --watch src/server.ts  # runs + auto-restart on save
tsc --noEmit                # type-checks (catches errors)
tsc                         # builds JS to dist/ for production
```

**Type stripping vs type checking:**

- Type stripping: removes types, runs code. Fast. No errors caught.
- Type checking: `tsc --noEmit`. Catches type errors. Slower.

**Workflow:**

1. Write code in `src/`.
2. Run `npm run dev` (node --watch) for instant feedback.
3. Run `npm run check` (tsc --noEmit) to catch type errors.
4. For production: `tsc` builds JS to `dist/`.

**Type stripping limits:**

- Erasable syntax only (no `enum`, `namespace`, constructor param properties).
- `.ts` in import paths.
- `import type` for type-only imports.

## Common Mistakes

- Believing Node type-checks TypeScript (it only strips types).
- Forgetting `tsc --noEmit` before commit.
- Using non-erasable syntax (enums).
