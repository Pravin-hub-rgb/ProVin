# Doc 1.4 — ES Modules in Node

## Cheat Sheet (Quick Recall)

- ES modules: `import` and `export`.
- `.ts` in import paths (Node requirement).
- `import type` for type-only imports.
- `node:` prefix for built-in modules (`node:fs`, `node:path`).

Node uses ES modules (import/export) with `"type": "module"` in package.json.

```ts
// math.ts
export function add(a: number, b: number): number {
  return a + b;
}

// main.ts
import { add } from "./math.ts";
console.log(add(2, 3));
```

**Key rules:**

- Import paths include `.ts` extension: `./math.ts` (not `./math`).
- Type-only imports use `import type`: `import type { User } from "./types.ts"`.
- Built-in modules use `node:` prefix: `import fs from "node:fs"`.

**Splitting code:**

```ts
// utils.ts
export const greet = (name: string) => `Hello, ${name}`;

// main.ts
import { greet } from "./utils.ts";
console.log(greet("Vin"));
```

## Common Mistakes

- Forgetting `.ts` in import paths → "Cannot find module".
- Using `import` for types without `import type` → verbatimModuleSyntax error.
- Missing `node:` prefix for built-ins.

## Questions

1. What must import paths include in Node ESM?

**Answer:** The `.ts` extension.

2. How to import a type-only value?

**Answer:** `import type { ... } from "..."`.

3. What prefix for built-in modules?

**Answer:** `node:` (e.g., `node:fs`).

4. How to export a function?

**Answer:** `export function name() { ... }`.

5. What enables ES modules in package.json?

**Answer:** `"type": "module"`.
