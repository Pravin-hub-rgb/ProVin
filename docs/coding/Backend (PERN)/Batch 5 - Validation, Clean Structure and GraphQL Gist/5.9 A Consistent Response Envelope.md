# Doc 5.9 — A Consistent Response Envelope

## Cheat Sheet (Quick Recall)

- Single resource: `{ data: { ... } }`.
- List: `{ data: [...], pagination: { page, limit, total } }`.
- Error: `{ error: { code, message, details? } }`.
- Consistency is a gift to the frontend.

## Where We Are So Far

In 5.8 we saw generics. Now a consistent response envelope — shape of responses.

## Broader Goal

The goal of Batch 5 is to make the API refuse bad input consistently and clean up structure. Current step: response envelope.

---

The shape of a single resource response, a list response with paging info, and an error response. Consistency is a gift to the frontend.

```ts
// Single resource
res.json({ data: { id: "1", url: "https://example.com", title: "Example" } });

// List
res.json({
  data: [{ id: "1", title: "Example" }],
  pagination: { page: 1, limit: 10, total: 1, totalPages: 1 },
});

// Error
res.status(400).json({
  error: { code: "VALIDATION_ERROR", message: "Invalid input", details: [...] },
});
```

- **Single resource:** `{ data: { ... } }`.
- **List:** `{ data: [...], pagination: { ... } }`.
- **Error:** `{ error: { code, message, details? } }`.

## What It Is NOT

- Inconsistent shapes are **not** acceptable — frontend needs one shape.
- `data` is **not** optional — always wrap in `data`.
- Error shape is **not** different from the validation error shape — same shape.

---

## Common Mistakes

- Different shapes for different routes.
- Not wrapping single resource in `data`.
- Inconsistent error shapes.
