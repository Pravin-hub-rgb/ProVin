Generics on the backend: a generic `validate<T>` middleware, a typed `Result<T, E>` return for services, and utility types (`Pick`, `Omit`, `Partial`) to derive create/update inputs from one model.

```ts
// Generic validate middleware
function validate<T extends z.ZodTypeAny>(schema: T) {
  return (req, res, next) => {
    const result = schema.safeParse(req.body);
    if (!result.success) { /* ... */ }
    req.body = result.data;
    next();
  };
}

// Result type
type Result<T, E = Error> = { ok: true; value: T } | { ok: false; error: E };

// Utility types
type CreateBookmarkInput = Omit<Bookmark, "id" | "createdAt" | "updatedAt">;
type UpdateBookmarkInput = Partial<CreateBookmarkInput>;
```

- `validate<T>`: generic middleware.
- `Result<T, E>`: typed return for services.
- `Pick`/`Omit`/`Partial`: derive input types from model.
- Show where generics make code clearer and where they add noise.

## What It Is NOT

- Generics are **not** always better — use when they add clarity.
- `Result<T, E>` is **not** a replacement for try/catch — it is a pattern.
- Utility types are **not** runtime — they are compile-time only.

---

## Common Mistakes

- Overusing generics (noise).
- Not using `Omit`/`Partial` (duplicate types).
- Generics where simple types suffice.
