One reusable middleware takes a schema and validates `body`, `query`, or `params` before the handler runs. After it, handlers can trust their input.

```ts
import { z } from "zod";
import { Request, Response, NextFunction } from "express";

function validate<T extends z.ZodTypeAny>(schema: T, source: "body" | "query" | "params" = "body") {
  return (req: Request, res: Response, next: NextFunction) => {
    const result = schema.safeParse(req[source]);
    if (!result.success) {
      res.status(400).json({
        error: { code: "VALIDATION_ERROR", message: "Invalid input", details: result.error.issues },
      });
      return;
    }
    req[source] = result.data;
    next();
  };
}

// Usage
app.post("/bookmarks", validate(createBookmarkSchema), (req, res) => {
  // req.body is now typed and validated
  res.status(201).json(req.body);
});
```

- `validate(schema)` — reusable middleware.
- Validates `body`, `query`, `params`.
- Replaces `req[source]` with parsed result.
- Handlers trust input after validation.

## What It Is NOT

- Middleware is **not** a route — it runs before the handler.
- `safeParse` is **not** `parse` — it returns a result, not a throw.
- Validation is **not** optional — always validate at the boundary.

---

## Common Mistakes

- Validating only `body`, forgetting `params` and `query`.
- Not replacing `req[source]` with parsed data.
- Forgetting `next()` → request hangs.
