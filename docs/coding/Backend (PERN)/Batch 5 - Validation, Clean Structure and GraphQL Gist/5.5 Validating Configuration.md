# Doc 5.5 — Validating Configuration

## Cheat Sheet (Quick Recall)

- Zod schema for `process.env`.
- Parse once at startup, fail fast.
- Rest of app imports typed `config` object.
- Never touch `process.env` outside config.

## Where We Are So Far

In 5.4 we saw one error shape. Now validating configuration — replace hand-written env loader with Zod.

## Broader Goal

The goal of Batch 5 is to make the API refuse bad input consistently. Current step: config validation.

---

Replace the hand-written environment loader from Batch 1.8 with a Zod schema that parses `process.env` once at startup and fails fast with a readable list of every problem.

```ts
import { z } from "zod";

const configSchema = z.object({
  DATABASE_URL: z.string().url(),
  PORT: z.coerce.number().default(3000),
  NODE_ENV: z.enum(["development", "production", "test"]).default("development"),
});

export const config = configSchema.parse(process.env);
```

- `configSchema`: Zod schema for env vars.
- `configSchema.parse(process.env)`: parses and validates.
- Fail fast: throws readable error if any var is missing/invalid.
- Rest of app imports `config` and never touches `process.env`.

## What It Is NOT

- `config` is **not** `process.env` — it is typed and validated.
- `parse` is **not** `safeParse` — it throws on failure (fail fast).
- This is **not** optional — always validate config at startup.

---

## Common Mistakes

- Using `process.env` throughout the app (untyped).
- Not failing fast (silent config errors).
- Using `safeParse` instead of `parse` (no fail-fast).
