A single lesson, no project code. What GraphQL is, how it differs from REST, when a team picks it.

**What GraphQL is:**

One endpoint. The client asks for exactly the fields it wants.

```graphql
query {
  bookmark(id: "1") {
    title
    url
    tags { name }
  }
}
```

**REST equivalent:** `GET /bookmarks/1` returns all fields (over-fetching) or requires multiple calls (under-fetching).

**Problems GraphQL solves:**

- Over-fetching: REST returns more than needed.
- Under-fetching: REST requires multiple calls.
- Many clients with different needs (web, mobile).

**Costs GraphQL adds:**

- Complexity (new layer).
- Caching is harder.
- Security/monitoring is more complex.

**When a team picks GraphQL:** many clients, complex data, over/under-fetching pain.

**Goal:** "Do you know GraphQL?" → "I know the idea and the trade-offs, and I have built REST in depth."

**OUT OF SCOPE:** building with GraphQL in this course.

## What It Is NOT

- GraphQL is **not** built in this course — gist level only.
- GraphQL is **not** always better — REST is simpler for most cases.
- GraphQL is **not** a database — it is a query language for APIs.

---

## Common Mistakes

- Thinking GraphQL replaces REST entirely.
- Ignoring the costs (complexity, caching).
- Building with GraphQL without understanding trade-offs.
