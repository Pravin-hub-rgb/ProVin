Zod is a schema validation library. You already know it from React forms. Now use it on the server.

```ts
import { z } from "zod";

const createBookmarkSchema = z.object({
  url: z.string().url(),
  title: z.string().min(1).max(200),
  tags: z.array(z.string()).max(10).optional(),
  note: z.string().optional(),
});

type CreateBookmark = z.infer<typeof createBookmarkSchema>;

// Parse (throws on failure)
const data = createBookmarkSchema.parse(req.body);

// Safe parse (returns result)
const result = createBookmarkSchema.safeParse(req.body);
if (!result.success) {
  // result.error.issues
} else {
  // result.data
}
```

- `z.object({ ... })` defines a schema.
- `z.string()`, `z.number()`, `z.array()`, `.optional()`, `.default()`.
- `parse` throws on failure.
- `safeParse` returns `{ success, data/error }`.
- `z.infer<typeof schema>` derives the TypeScript type.

**Query params arrive as strings** — use coercion:

```ts
const querySchema = z.object({
  limit: z.coerce.number().min(1).max(50).default(10),
  page: z.coerce.number().min(1).default(1),
});
```

**Break it on purpose:** send a body with wrong types and read the structured error Zod produces.

## What It Is NOT

- `parse` is **not** `safeParse` — `parse` throws, `safeParse` returns a result.
- Zod is **not** TypeScript — it validates at runtime.
- `z.infer` is **not** a cast — it derives the type from the schema.

---

## Common Mistakes

- Using Zod 3 snippets with Zod 4 (API changed).
- Not using `z.infer` (type drift).
- Forgetting coercion for query params (they arrive as strings).
