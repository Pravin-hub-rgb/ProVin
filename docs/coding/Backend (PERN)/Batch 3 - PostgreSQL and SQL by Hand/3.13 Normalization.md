---

Normalization organizes tables to reduce redundancy. Up to 3NF in plain words.

- **1NF:** atomic values, no repeating groups (no arrays in columns).
- **2NF:** 1NF + no partial dependencies (all non-key columns depend on full PK).
- **3NF:** 2NF + no transitive dependencies (non-key columns depend only on PK).

**When to denormalize:** read performance matters (e.g., caching computed values).

## What It Is NOT

- Normalization is **not** always perfect — denormalize for performance.
- 1NF is **not** enough — go to 3NF for business data.
- Denormalization is **not** bad — it is a trade-off.

---

## Common Mistakes

- Storing arrays in columns (violates 1NF).
- Not normalizing (data duplication).
- Over-normalizing (too many joins).
