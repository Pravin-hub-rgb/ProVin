A server reuses connections instead of opening one per request. Opening a connection per request is slow and wasteful.

```ts
import { Pool } from "pg";

const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
  max: 20,                    // max connections
  idleTimeoutMillis: 30000,   // close idle after 30s
  connectionTimeoutMillis: 2000, // wait 2s for connection
});

// pool.query acquires and releases automatically
const result = await pool.query("SELECT 1");

// Close on shutdown
process.on("SIGTERM", () => pool.end());
```

- `Pool` manages connections.
- `pool.query()` acquires and releases automatically.
- `max`: maximum connections.
- `idleTimeoutMillis`: close idle connections.
- `connectionTimeoutMillis`: wait time for a connection.
- `pool.end()`: close all connections (on shutdown).

**Compare:** per-request connections vs pool under load — pool is much faster.

## What It Is NOT

- `Pool` is **not** a single connection — it manages many.
- `pool.query()` is **not** `pool.connect()` — query auto-releases.
- Pool is **not** infinite — `max` limits connections.

---

## Common Mistakes

- Opening a connection per request (slow).
- Not closing the pool on shutdown (leaks).
- Setting `max` too high (database overload).
