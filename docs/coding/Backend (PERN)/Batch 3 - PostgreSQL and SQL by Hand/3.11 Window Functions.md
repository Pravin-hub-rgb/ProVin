# Doc 3.11 — Window Functions

## Cheat Sheet (Quick Recall)

- `ROW_NUMBER()`, `RANK()`, `DENSE_RANK()`.
- Running totals: `SUM() OVER (ORDER BY ...)`.
- `OVER (PARTITION BY ... ORDER BY ...)`.
- Window functions compute over a set of rows without collapsing.

---

Window functions compute a value for each row based on a set of related rows, without collapsing them (unlike aggregates).

```sql
-- ROW_NUMBER
SELECT title, ROW_NUMBER() OVER (ORDER BY created_at) AS rn
FROM books;

-- RANK
SELECT title, RANK() OVER (ORDER BY borrow_count DESC) AS rank
FROM books;

-- Running total
SELECT date, amount, SUM(amount) OVER (ORDER BY date) AS running_total
FROM sales;

-- Partition
SELECT genre, title, ROW_NUMBER() OVER (PARTITION BY genre ORDER BY borrow_count DESC) AS rank
FROM books;
```

- `ROW_NUMBER()`: sequential number (1, 2, 3...).
- `RANK()`: rank with gaps (1, 2, 2, 4).
- `DENSE_RANK()`: rank without gaps (1, 2, 2, 3).
- `OVER (...)`: defines the window.
- `PARTITION BY`: groups rows (like GROUP BY but without collapsing).
- Running total: `SUM() OVER (ORDER BY ...)`.

## What It Is NOT

- Window functions are **not** aggregates — they don't collapse rows.
- `RANK()` is **not** `DENSE_RANK()` — RANK has gaps.
- `OVER` is **not** optional — it defines the window.

---

## Common Mistakes

- Confusing `RANK()` and `DENSE_RANK()`.
- Forgetting `OVER` clause.
- Using window functions when aggregates suffice.
