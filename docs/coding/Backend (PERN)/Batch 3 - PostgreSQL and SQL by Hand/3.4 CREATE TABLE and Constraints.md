# Doc 3.4 — CREATE TABLE and Constraints

## Cheat Sheet (Quick Recall)

- `PRIMARY KEY`: uniquely identifies a row.
- `NOT NULL`: cannot be null.
- `UNIQUE`: no duplicates.
- `CHECK`: custom validation.
- `DEFAULT`: default value.
- `FOREIGN KEY`: references another table.

---

Constraints make the database refuse bad data even if the application forgets to.

```sql
CREATE TABLE bookmarks (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  url text NOT NULL UNIQUE,
  title text NOT NULL CHECK (length(title) BETWEEN 1 AND 200),
  note text,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE tags (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL UNIQUE
);

CREATE TABLE bookmark_tags (
  bookmark_id uuid REFERENCES bookmarks(id) ON DELETE CASCADE,
  tag_id uuid REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (bookmark_id, tag_id)
);
```

- `PRIMARY KEY`: uniquely identifies a row.
- `NOT NULL`: cannot be null.
- `UNIQUE`: no duplicates.
- `CHECK`: custom validation (e.g., length between 1 and 200).
- `DEFAULT`: default value (e.g., `now()`).
- `FOREIGN KEY`: references another table's PK.

**Break it on purpose:** violate each constraint and read the error.

## What It Is NOT

- Constraints are **not** optional — they protect data integrity.
- `CHECK` is **not** application-level validation — it is database-level.
- `FOREIGN KEY` is **not** automatic in Postgres — you must define it.

---

## Common Mistakes

- Missing `NOT NULL` on required fields.
- No `CHECK` constraints (app forgets validation).
- No foreign keys (orphaned data).
