# Doc 3.5 — CRUD in SQL

## Cheat Sheet (Quick Recall)

- `INSERT INTO ... VALUES (...)` — create.
- `SELECT * FROM ... WHERE ...` — read.
- `UPDATE ... SET ... WHERE ...` — update.
- `DELETE FROM ... WHERE ...` — delete.
- `RETURNING *` — get the row back.
- Write `WHERE` first (safe habit).

## Where We Are So Far

## Broader Goal

The goal of Batch 3 is to design a schema and answer real questions with SQL. Current step: CRUD.

---

CRUD: Create, Read, Update, Delete. Run the complete cycle on one table entirely in SQL.

```sql
-- Create
INSERT INTO bookmarks (url, title) VALUES ('https://example.com', 'Example') RETURNING *;

-- Read
SELECT * FROM bookmarks WHERE id = '...';

-- Update
UPDATE bookmarks SET title = 'New Title' WHERE id = '...' RETURNING *;

-- Delete
DELETE FROM bookmarks WHERE id = '...' RETURNING *;
```

- `INSERT INTO ... VALUES (...)` — create.
- `SELECT ... FROM ... WHERE ...` — read.
- `UPDATE ... SET ... WHERE ...` — update.
- `DELETE FROM ... WHERE ...` — delete.
- `RETURNING *` — get the affected row back.

**Safe habit:** write the `WHERE` first, then the rest. Prevents accidental full-table updates/deletes.

## What It Is NOT

- `UPDATE` without `WHERE` updates **all rows**.
- `DELETE` without `WHERE` deletes **all rows**.
- `RETURNING` is **not** standard SQL — it is Postgres-specific (but useful).

---

## Common Mistakes

- Forgetting `WHERE` on UPDATE/DELETE (data loss).
- Not using `RETURNING` (lost the row).
- Using string concatenation for values (SQL injection).
