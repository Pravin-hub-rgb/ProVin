# Doc 3.12 — Indexes

## Cheat Sheet (Quick Recall)

- B-tree index: speeds up lookups.
- `CREATE INDEX idx_name ON table(column);`.
- Composite index: multiple columns.
- Unique index: enforces uniqueness.
- `EXPLAIN` / `EXPLAIN ANALYZE`: read query plans.
- Indexes cost on writes (slower INSERT/UPDATE).

## Where We Are So Far

In 3.11 we saw window functions. Now indexes — speeding up queries.

---

Indexes speed up lookups. B-tree is the default. `EXPLAIN ANALYZE` shows the plan.

```sql
-- Create index
CREATE INDEX idx_bookmarks_url ON bookmarks(url);

-- Composite index
CREATE INDEX idx_bookmarks_user_created ON bookmarks(user_id, created_at);

-- Unique index
CREATE UNIQUE INDEX idx_bookmarks_url_unique ON bookmarks(url);

-- Read plan
EXPLAIN ANALYZE SELECT * FROM bookmarks WHERE url = 'https://example.com';
```

- **B-tree:** default index type, good for equality and range.
- **Composite:** multiple columns (order matters).
- **Unique:** enforces uniqueness.
- **Cost on writes:** INSERT/UPDATE slower (index must be updated).
- **Foreign keys:** not indexed automatically in Postgres (add manually).

**Break it on purpose:** make a slow query on a large seeded table, read the plan, add an index, read the plan again.

## What It Is NOT

- Indexes are **not** free — they slow down writes.
- `EXPLAIN` is **not** `EXPLAIN ANALYZE` — ANALYZE actually runs the query.
- Foreign keys are **not** auto-indexed in Postgres.

---

## Common Mistakes

- Missing indexes on foreign keys.
- Over-indexing (slow writes).
- Not reading `EXPLAIN ANALYZE`.

## Try It Yourself

1. Make a slow query on a large table.
2. Read the plan with `EXPLAIN ANALYZE`.
3. Add an index and read the plan again.

## Summary

- `CREATE INDEX` for B-tree.
- Composite and unique indexes.
- `EXPLAIN ANALYZE` for query plans.
- Indexes cost on writes.
