# Doc 3.3 — Data Types

## Cheat Sheet (Quick Recall)

- `text`: variable-length string.
- `integer`, `bigint`: whole numbers.
- `numeric`: exact decimal (for money).
- `boolean`: true/false.
- `timestamptz`: timestamp with time zone (store UTC).
- `uuid`: unique identifier.
- `jsonb`: JSON data.
- Never `float` for money; never `timestamp` without time zone.

Choosing the right type matters. Wrong types cause bugs and data loss.

```sql
CREATE TABLE example (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL,
  age integer,
  price numeric(10,2),        -- exact decimal for money
  active boolean DEFAULT true,
  created_at timestamptz DEFAULT now(),
  metadata jsonb
);
```

- `text`: variable-length string.
- `integer`, `bigint`: whole numbers.
- `numeric`: exact decimal (for money). Never `float`.
- `boolean`: true/false.
- `timestamptz`: timestamp with time zone (store UTC). Never `timestamp` without TZ.
- `uuid`: unique identifier.
- `jsonb`: JSON data (queryable).

**Break it on purpose:** store the same value in `float`, `numeric`, and `text` and compare the arithmetic. `float` loses precision.

## What It Is NOT

- `float` is **not** for money — use `numeric`.
- `timestamp` (without TZ) is **not** safe — use `timestamptz`.
- `text` is **not** `varchar` — `text` is preferred in Postgres.

---

## Common Mistakes

- Using `float` for money (precision loss).
- Using `timestamp` without time zone (ambiguity).
- Using `varchar` instead of `text`.
