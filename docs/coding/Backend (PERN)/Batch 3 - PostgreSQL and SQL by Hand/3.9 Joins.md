# Doc 3.9 — Joins

## Cheat Sheet (Quick Recall)

- `INNER JOIN`: only matching rows.
- `LEFT JOIN`: all left rows + matching right (null if no match).
- `RIGHT JOIN` / `FULL JOIN`: rare.
- Self join: table joined to itself.

Joins combine rows from multiple tables based on a related column.

```sql
-- INNER JOIN: only matching rows
SELECT books.title, authors.name
FROM books
INNER JOIN authors ON books.author_id = authors.id;

-- LEFT JOIN: all books + matching author (null if no author)
SELECT books.title, authors.name
FROM books
LEFT JOIN authors ON books.author_id = authors.id;

-- Self join
SELECT e.name, m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;
```

- `INNER JOIN`: only rows that match in both tables.
- `LEFT JOIN`: all rows from left table + matching right (null if no match).
- `RIGHT JOIN`: all rows from right table + matching left (rare).
- `FULL JOIN`: all rows from both (rare).
- Self join: table joined to itself (e.g., employees and managers).

**Venn diagrams mislead** for some joins — always show real rows.

## What It Is NOT

- `INNER JOIN` is **not** `LEFT JOIN` — INNER excludes non-matching.
- `LEFT JOIN` is **not** `RIGHT JOIN` — LEFT keeps all left rows.
- Self join is **not** a different table — same table aliased.

---

## Common Mistakes

- Using `INNER JOIN` when `LEFT JOIN` is needed (loses rows).
- Forgetting the `ON` condition (cartesian product).
- Not aliasing in self joins.
