---

A transaction is all or nothing. `BEGIN`, then operations, then `COMMIT` or `ROLLBACK`.

```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;  -- or ROLLBACK
```

- **Atomicity:** all or nothing.
- **Consistency:** data stays valid.
- **Isolation:** concurrent transactions don't interfere.
- **Durability:** committed data survives crashes.

**Mini-project:** roll back a half-finished money transfer by hand and show the balances are unchanged.

## What It Is NOT

- `COMMIT` is **not** `ROLLBACK` — commit saves, rollback discards.
- Transaction is **not** optional for multi-step writes.
- ACID is **not** just a buzzword — it guarantees correctness.

---

## Common Mistakes

- Forgetting `COMMIT` (transaction never saves).
- Not using transactions for multi-step writes.
- Confusing isolation levels.
