# Doc 3.10 — Subqueries, CTEs and UNION

## Cheat Sheet (Quick Recall)

- Subquery: query inside a query.
- CTE (`WITH`): named subquery for readability.
- `UNION`: combines results (removes duplicates).
- `UNION ALL`: combines results (keeps duplicates).

---

Complex queries need structure. Subqueries nest queries. CTEs name steps. UNION combines results.

```sql
-- Subquery
SELECT * FROM books
WHERE author_id IN (SELECT id FROM authors WHERE country = 'UK');

-- CTE (WITH)
WITH uk_authors AS (
  SELECT id FROM authors WHERE country = 'UK'
)
SELECT * FROM books WHERE author_id IN (SELECT id FROM uk_authors);

-- UNION (removes duplicates)
SELECT title FROM books WHERE year > 2020
UNION
SELECT title FROM books WHERE author_id = 1;

-- UNION ALL (keeps duplicates)
SELECT title FROM books WHERE year > 2020
UNION ALL
SELECT title FROM books WHERE author_id = 1;
```

- **Subquery:** query inside a query.
- **CTE (`WITH`):** named subquery for readability.
- **`UNION`:** combines results, removes duplicates.
- **`UNION ALL`:** combines results, keeps duplicates.

## What It Is NOT

- CTE is **not** a temporary table — it is a named subquery.
- `UNION` is **not** `UNION ALL` — UNION removes duplicates.
- Subqueries are **not** always slower — the planner optimizes.

---

## Common Mistakes

- Using `UNION` when `UNION ALL` is needed (or vice versa).
- Deeply nested subqueries (use CTEs for readability).
- Forgetting `WITH` for CTEs.
