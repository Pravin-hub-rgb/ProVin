# Doc 3.6 — Filtering and NULL

## Cheat Sheet (Quick Recall)

- `AND`, `OR`, `IN`, `BETWEEN`, `LIKE`, `ILIKE`.
- `NULL` is not equal to anything, not even itself.
- Use `IS NULL` / `IS NOT NULL`, never `= NULL`.
- `LIKE` is case-sensitive; `ILIKE` is case-insensitive (Postgres).

Filtering uses `WHERE` with conditions. NULL behaves specially.

```sql
-- AND, OR
SELECT * FROM bookmarks WHERE title = 'X' AND url LIKE '%example%';

-- IN
SELECT * FROM bookmarks WHERE status IN ('active', 'pending');

-- BETWEEN
SELECT * FROM bookmarks WHERE created_at BETWEEN '2026-01-01' AND '2026-12-31';

-- LIKE (case-sensitive)
SELECT * FROM bookmarks WHERE title LIKE 'A%';

-- ILIKE (case-insensitive, Postgres)
SELECT * FROM bookmarks WHERE title ILIKE 'a%';

-- NULL handling
SELECT * FROM bookmarks WHERE note IS NULL;
SELECT * FROM bookmarks WHERE note IS NOT NULL;
```

**NULL gotcha:** `NULL` is not equal to anything, not even itself. `WHERE note = NULL` returns nothing. Use `IS NULL`.

## What It Is NOT

- `= NULL` is **not** valid — use `IS NULL`.
- `LIKE` is **not** case-insensitive — use `ILIKE` (Postgres).
- `NULL` is **not** `0` or empty string — it is unknown.

---

## Common Mistakes

- Comparing with `= NULL` instead of `IS NULL`.
- Forgetting `ILIKE` is Postgres-specific.
- Confusing `NULL` with empty string.
