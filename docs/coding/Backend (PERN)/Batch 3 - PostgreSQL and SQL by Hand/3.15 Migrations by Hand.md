## Broader Goal

The goal of Batch 3 is to design a schema and answer real questions with SQL. Current step: migrations.

---

Schema changes must be recorded like code. Use numbered SQL files run in order.

```
migrations/
├── 001_create_bookmarks.sql
├── 002_add_note_column.sql
└── 003_create_tags.sql
```

- Each file is a migration (up).
- Run in order (001, 002, 003).
- Never edit a committed migration — create a new one.
- This is the manual version of Prisma Migrate (Batch 4).

**Mini-project:** evolve a schema across three migration files.

## What It Is NOT

- Migrations are **not** optional — schema changes must be tracked.
- Editing a committed migration is **not** safe — create a new one.
- Migrations are **not** just for tables — indexes, constraints, data too.

---

## Common Mistakes

- Editing committed migrations.
- Not running in order.
- Missing rollback (down) migration.
