# Doc 3.7 — Aggregates

## Cheat Sheet (Quick Recall)

- `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`.
- `GROUP BY` groups rows.
- `HAVING` filters groups (after aggregation).
- `WHERE` filters rows (before aggregation).

Aggregates summarize data. `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` compute over rows. `GROUP BY` groups; `HAVING` filters groups.

```sql
-- Count
SELECT COUNT(*) FROM bookmarks;

-- Sum and average
SELECT SUM(duration), AVG(duration) FROM requests;

-- Group by
SELECT status, COUNT(*) FROM requests GROUP BY status;

-- Having (filter groups)
SELECT status, COUNT(*) FROM requests GROUP BY status HAVING COUNT(*) > 10;
```

- `COUNT(*)` counts rows.
- `SUM(col)` sums values.
- `AVG(col)` averages.
- `MIN(col)` / `MAX(col)` min/max.
- `GROUP BY col` groups rows by column.
- `HAVING` filters after aggregation (like `WHERE` for groups).

**WHERE vs HAVING:**

- `WHERE` filters rows before aggregation.
- `HAVING` filters groups after aggregation.

## What It Is NOT

- `HAVING` is **not** `WHERE` — HAVING is for groups.
- `COUNT(*)` is **not** `COUNT(col)` — `COUNT(col)` ignores NULLs.
- Aggregates are **not** for individual rows — use `GROUP BY`.

---

## Common Mistakes

- Using `HAVING` instead of `WHERE` (or vice versa).
- Forgetting `GROUP BY` with aggregates.
- Confusing `COUNT(*)` and `COUNT(col)`.
