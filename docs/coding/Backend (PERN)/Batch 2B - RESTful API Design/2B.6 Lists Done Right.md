## Problem — How Do You Paginate and Filter a List Safely?

Unbounded lists are a production bug. First pagination (`limit`/`page`), then filtering (`tag`, `q`), then sorting, then response shape.

```ts
app.get("/bookmarks", (req, res) => {
  const tag = req.query.tag as string | undefined;
  const q = req.query.q as string | undefined;
  const limit = Math.min(Number(req.query.limit) || 10, 50);
  const page = Math.max(Number(req.query.page) || 1, 1);

  let items = bookmarks;
  if (tag) items = items.filter((b) => b.tags.includes(tag));
  if (q) items = items.filter((b) => b.title.toLowerCase().includes(q.toLowerCase()));

  const total = items.length;
  const start = (page - 1) * limit;
  const paged = items.slice(start, start + limit);

  res.json({
    items: paged,
    pagination: { page, limit, total, totalPages: Math.ceil(total / limit) },
  });
});
```

- `limit`/`page` for pagination (hard cap on page size).
- `tag` for filtering.
- `q` for search.
- Sort by `createdAt` (newest first).
- Response shape: items + pagination.

**Break it on purpose:** request `limit=1000000` → capped at 50.

## What It Is NOT

- Unbounded lists are **not** acceptable — always cap.
- `limit` is **not** unlimited — hard cap (e.g., 50).
- Filtering is **not** in the path — use query params.

---

## Common Mistakes

- No cap on `limit` → memory blowup.
- No pagination → huge responses.
- Inconsistent response shape.

## Try It Yourself

1. Add `tag`, `q`, `limit`, `page` to a list endpoint.
2. Request `limit=1000000` and verify cap.
3. Sort by `createdAt` descending.

## Summary

- Pagination: `limit`/`page` with hard cap.
- Filtering: `tag`, `q` via query params.
- Response shape: items + pagination.
