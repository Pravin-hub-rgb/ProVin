## Problem — What Is the Difference Between PUT and PATCH? What Is Idempotent?

PUT replaces the whole resource. PATCH changes part of it. Idempotent means repeating the request leaves the same result. First PUT vs PATCH, then idempotency, then DELETE twice.

```ts
// PUT: replace entire resource
app.put("/bookmarks/:id", (req, res) => {
  const { id } = req.params;
  const { url, title, note, tags } = req.body;
  // replace entire bookmark
  res.json({ id, url, title, note, tags });
});

// PATCH: partial update
app.patch("/bookmarks/:id", (req, res) => {
  const { id } = req.params;
  // update only provided fields
  res.json({ id, ...req.body });
});

// DELETE: remove
app.delete("/bookmarks/:id", (req, res) => {
  // delete bookmark
  res.status(204).send();
});
```

- **PUT:** replace the whole resource. Send all fields.
- **PATCH:** partial update. Send only changed fields.
- **Idempotent:** repeating leaves the same result. GET, PUT, DELETE are idempotent. POST is not.

**DELETE twice:** first call deletes (204), second call returns 404 (already gone). The end state is the same (resource gone).

**Break it on purpose:**

- Call POST ten times → ten records appear.
- Call DELETE twice → first 204, second 404.

## What It Is NOT

- PUT is **not** PATCH — PUT replaces all, PATCH changes part.
- Idempotent is **not** "no side effects" — it means same result on repeat.
- DELETE twice is **not** an error — second returns 404, end state same.

---

## Common Mistakes

- Using PUT for partial changes.
- Using POST when PUT/PATCH is correct.
- Not handling DELETE twice.
