## Problem — Which Status Code and Headers for Each Situation?

Pick the most specific honest code. Never use 200 for everything. First status codes, then headers (Location, Content-Type), then the table.

```ts
// Create → 201 + Location
res.status(201).set("Location", `/bookmarks/${id}`).json(bookmark);

// Read → 200
res.status(200).json(bookmark);

// Update → 200
res.status(200).json(updated);

// Delete → 204 (no body)
res.status(204).send();

// Bad input → 400 or 422
res.status(400).json({ error: { code: "BAD_REQUEST", message: "..." } });

// Not found → 404
res.status(404).json({ error: { code: "NOT_FOUND", message: "..." } });

// Conflict → 409
res.status(409).json({ error: { code: "CONFLICT", message: "..." } });
```

- 200: OK (read/update).
- 201: Created (with `Location` header).
- 204: No Content (delete).
- 400: Bad Request (malformed).
- 404: Not Found (missing resource).
- 409: Conflict (duplicate).
- 422: Unprocessable (well-formed but invalid).

**Rule of thumb:** pick the most specific honest code. Never use 200 for everything.

## What It Is NOT

- 200 is **not** for everything — be specific.
- 400 is **not** 422 — 400 = malformed, 422 = well-formed but invalid.
- 204 is **not** 200 — 204 has no body.

---

## Common Mistakes

- Using 200 for everything.
- Missing `Location` header on 201.
- Sending body with 204.
