## Problem — How Do You Test and Document Your API?

API clients (Bruno/Postman) help test and document. First collections, then environments, then saved examples, then curl equivalents.

```json
// Bruno collection example
{
  "name": "Bookmarks API",
  "requests": [
    { "name": "List bookmarks", "method": "GET", "url": "{{baseUrl}}/bookmarks" },
    { "name": "Create bookmark", "method": "POST", "url": "{{baseUrl}}/bookmarks", "body": { "url": "https://example.com", "title": "Example" } }
  ]
}
```

- **Collection:** group of requests.
- **Environment:** variables (baseUrl, token).
- **Saved examples:** success and failure responses.
- **curl equivalent:** document the curl command for each request.

## What It Is NOT

- API clients are **not** a replacement for tests — they are for manual testing.
- Collections are **not** committed with secrets — use env vars.
- Bruno is **not** the only option — Postman also works.

---

## Common Mistakes

- Not saving examples (hard to debug).
- Hardcoding secrets in collections.
- Not documenting curl equivalents.

---

## Try It Yourself

1. Create a Bruno collection with all endpoints.
2. Add environments (dev, prod).
3. Save success and failure examples.

## Summary

- Bruno/Postman collections for testing.
- Environments for variables.
- Saved examples for success/failure.
- curl equivalents for documentation.
