## Problem — Why Does the Browser Block Cross-Origin API Calls?

The same-origin policy blocks cross-origin calls. CORS allows them. First the problem (browser error), then the `cors` package, then why wildcard is bad.

```ts
import cors from "cors";
app.use(cors({ origin: "http://localhost:5173" }));
```

- Same-origin: same scheme + host + port.
- Cross-origin: different origin → browser blocks.
- Preflight: OPTIONS request before the actual request.
- `cors` package: configure allowed origin.
- Wildcard `*` allows all — avoid in production.

**Break it on purpose:** call the API from a Vite app on another port and read the browser error; fix it; then show why wildcard is a shortcut to avoid.

## What It Is NOT

- CORS is **not** a server-side block — it is a browser policy.
- `cors` package is **not** automatic — you must configure it.
- Wildcard `*` is **not** safe for production.

---

## Common Mistakes

- Disabling CORS with wildcard and never fixing it.
- Not handling preflight (OPTIONS).
- Forgetting CORS in production.
