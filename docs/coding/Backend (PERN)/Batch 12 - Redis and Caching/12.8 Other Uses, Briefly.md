Redis has many uses beyond caching. Short-lived tokens, simple locks, leaderboards.

```ts
// Short-lived token
await redis.set(`token:${token}`, userId, "EX", 300); // 5 min TTL

// Simple lock
const acquired = await redis.set(`lock:${resource}`, "1", "NX", "EX", 10);
if (acquired) { /* do work */ }

// Leaderboard
await redis.zadd("leaderboard", score, "player1");
const top10 = await redis.zrevrange("leaderboard", 0, 9, "WITHSCORES");
```

- **Short-lived tokens:** session tokens, OTPs.
- **Simple locks:** distributed lock (NX + EX).
- **Leaderboards:** sorted sets (ZADD, ZREVRANGE).

**One paragraph, no build.** These are PREVIEW concepts.

## What It Is NOT

- Redis is **not** a replacement for a database.
- Locks are **not** foolproof — use Redlock for production.
- Leaderboards are **not** the primary use case — caching is.

---

## Common Mistakes

- Using Redis as primary data store.
- Simple locks in production (use Redlock).
- Not setting TTL (memory grows).
