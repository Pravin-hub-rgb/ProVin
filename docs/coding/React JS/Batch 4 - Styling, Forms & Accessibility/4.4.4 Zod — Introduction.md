# 4.4.4 Zod — Introduction

---

## Abhi Tak Kya Hua

4.4.3 mein React Hook Form ka built-in validation seekha — `register` mein `required`, `pattern` likhe.

Kaam karta tha — par email format check ke liye yeh likhna pada:

```tsx
pattern: {
  value: /^[^\s@]+@[^\s@]+\.[^\s@]+$/,
  message: 'Email sahi format mein nahi hai'
}
```

Yeh regex padhna mushkil hai. Complex rules ke liye aur mushkil hoga.

**Kya hoga agar validation rules seedhi padhne wali language mein likh sakein?**

Yahi karta hai **Zod.**

---

## Is Doc Mein Kya Karenge — Broader Goal

Humara kaam hai — Zod ko form ke saath connect karna taaki validation Zod handle kare.

Iske liye do cheezein karni hain:
1. **Zod ka schema banana** — "form mein kaunse fields hain, unki type kya hai" define karna
2. **Schema ko RHF se jodna** — taaki submit pe Zod validate kare

Pehle samjhte hain schema kya hota hai — phir connect karenge.

---

## Schema Kya Hota Hai

Schema matlab — **"mera data kaisa dikhna chahiye" — ek blueprint.**

Zod mein yeh aise likhte hain:

```ts
z.object({
  naam: z.string(),
  email: z.string()
})
```

Abhi email ke liye sirf `z.string()` hai — matlab "ek string hona chahiye." Specific validation rules jaise email format check karna — woh 4.4.5 mein karenge.

## Install Karo

Do packages chahiye:

```bash
npm install zod @hookform/resolvers
```

**`zod`** — schema likhne ki library

**`@hookform/resolvers`** — yeh ek bridge hai. Zod aur RHF do alag libraries hain — yeh package dono ko connect karta hai.

---

## Schema Banana Shuru Karo

`ContactForm.tsx` mein `z` import karo — component ke bahar schema banana shuru karo.

Pehle sirf `z` import karo aur ek simple schema dekho:

```tsx
import { z } from 'zod'

const formSchema = z.object({
  naam: z.string()
})

console.log(formSchema)
```

Browser console mein ek Zod object dikhega. Console.log hata do.

Ab baaki sab fields add karo:

```tsx
const formSchema = z.object({
  naam: z.string(),
  email: z.string()
})
```

Abhi sirf types hain — rules baad mein.

---

## RHF Se Connect Karo — `zodResolver`

Connection se pehle, ek cheez karte hain — `FormFields` type define karna.

Pehle (4.4.1 / 4.4.3) hum RHF ke liye type banate the — `naam: string`, `email: string`. Ab Zod ka bhi schema hai — `naam: z.string()`, `email: z.string()`.

Dono ek hi cheez define kar rahe hain — fields ka structure. Toh dono ko saath rakhte hain:

```tsx
import { useForm } from 'react-hook-form'
import { zodResolver } from '@hookform/resolvers/zod'
import { z } from 'zod'

// Manual Type — RHF ko batata hai kaunse fields hain
type FormFields = {
  naam: string
  email: string
}

// Zod Schema — validation ke liye
const formSchema = z.object({
  naam: z.string(),
  email: z.string()
})

export default function ContactForm() {
  const { register, handleSubmit, formState: { errors } } = useForm<FormFields>({
    resolver: zodResolver(formSchema)
  })
  // ...
}
```

`useForm<FormFields>({ resolver: zodResolver(formSchema) })` — ab `useForm` ko type bhi pata hai (kaunse fields hain) aur resolver bhi pata hai (validation kaise karni hai).

`resolver: zodResolver(formSchema)` — RHF ko bol raha hai — "submit pe validation ka kaam Zod ko de do." Ab RHF apne built-in validators nahi chalayega — **Zod** check karega har field ko. Agar Zod ko koi field galat lagi (jaise number jagah string aayi), toh error automatically RHF ke `formState.errors` mein chala jayega — wahi `errors` object jo 4.4.3 mein seekha tha.

**Ek zaroori baat** — `register` mein se pehle wale rules hatao:

```tsx
// Pehle aisa tha — hatao
{...register('naam', { required: 'Naam zaroori hai' })}

// Ab sirf yeh
{...register('naam')}
```

RHF ke built-in validators aur `zodResolver` ek saath kaam nahi karte. Rules ab Zod sambhalega.

`formState: { errors }` wahi hai jo 4.4.3 mein seekha tha — error messages yahan aate hain.

---

## Problem — Do Jagah Define Karna

Dekho abhi kya ho raha hai:

| Jagah | Kya Likha |
|-------|-----------|
| `type FormFields` | `naam: string`, `email: string` |
| Zod schema | `naam: z.string()`, `email: z.string()` |

Same fields — do jagah. Agar kal humein ek `phone` field add karni hai — dono jagah change karna padega. Ek jagah bhool gaye toh bug.

**Zod ka solution** — `z.infer`. Yeh schema se automatically TypeScript type nikal leta hai. Matlab — schema ek jagah, type usse auto-generate. No duplication.

Woh 4.4.6 mein seekhenge. Abhi ke liye manual type rakhte hain.

---

## Submit Karo — Dekho Kya Hota Hai

Abhi hamare schema mein sirf `z.string()` hai — koi validation rule nahi.

```ts
z.object({
  naam: z.string(),     // → bas itna ki string hona chahiye
  email: z.string()     // → bas itna ki string hona chahiye
})
```

`z.string()` ka matlab hai — "yeh ek string value honi chahiye." Empty string `""` bhi technically ek string hai. `null` ya `undefined` nahi hai toh valid hai.

Toh submit karo:

```tsx
onSubmit={handleSubmit((data) => {
  console.log(data)
})}
```

Dono fields khali chhod ke bhi submit karo — form submit ho jayega, console mein `{ naam: '', email: '' }` print hoga, aur `errors` object khali rahega.

**Error kyun nahi aaya?** — kyunki humne koi rule nahi diya. Schema sirf type check karta hai — "yeh string hai ya nahi." Empty string bhi string hai — isliye error nahi.

Yeh sahi hai — abhi hum sirf connect kar rahe hain. 4.4.5 mein validation rules add karenge — phir errors dikhenge.

---

## Summary

✅ **Zod** — schema likhte hain — "data kaisa hona chahiye"  
✅ `z.object({})` — object schema — fields define karo  
✅ `z.string()` — type check karta hai — "yeh string hona chahiye"  
✅ `@hookform/resolvers` — bridge hai Zod aur RHF ke beech  
✅ `resolver: zodResolver(formSchema)` — `useForm` mein pass kiya  
✅ `useForm<FormFields>({ resolver })` — type bhi, resolver bhi  
✅ `formState: { errors }` — wahi kaam karta hai jo 4.4.3 mein tha  
✅ `register` mein se built-in rules hatao — Zod handle karega  
✅ Sirf `z.string()` se error nahi aata — empty string bhi valid hai — rules nahi hain  
⚠️ **Manual type + Zod schema = duplication** — `z.infer` solve karega (4.4.6 mein)

## Agla Step

Zod connected hai, par validation rules nahi hain. Ab `.min(1)`, `.email()` jaise rules add karenge — taaki empty string aur ghalat format reject ho.

Yahi hoga **4.4.5 mein.**
