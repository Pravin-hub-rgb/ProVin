# 4.2.3 Accessible Contact Form

## Cheat Sheet (Quick Recall)

```tsx
<label htmlFor="email">Email</label>
<input
  id="email" type="email"
  aria-required="true"
  aria-invalid={!!errors.email}
  aria-describedby={errors.email ? "email-error" : undefined}
/>
{errors.email && (
  <span id="email-error" role="alert">{errors.email}</span>
)}
<form noValidate onSubmit={handleSubmit}>...</form>
```

## Abhi Tak Kya Hua

4.2.1 mein ARIA basics seekhe — `aria-label`, `aria-expanded`, `focus:ring`. 4.2.2 mein focus-trap pattern seekha — modal mein focus cycle karna. Ab ek real form banayenge jo accessible ho — labels, ARIA attributes, validation errors sab ke saath.

## Broader Goal

Gym site mein ek Contact section add karna hai jo screen reader users ke liye bhi accessible ho. Har input ka label hoga, required fields announce honge, validation errors input se associate honge, aur error message appear hote hi screen reader turant bolega.

## Step 1 — Problem: Form Bina ARIA Ke

Socho — ek simple contact form:

```tsx
<form>
  <input placeholder="Name" />
  <input placeholder="Email" />
  <button>Send Message</button>
</form>
```

Screen reader user ko kya pata chalega?
- "Name input" — theek hai, lekin required hai ya nahi? Pata nahi.
- Error aaya — input border red ho gaya. Lekin screen reader nahi bolega. User ko pata nahi chalega ki error hai.
- Error message — screen visible hai, lekin screen reader usse input se associate nahi kar pa raha.

**Har problem ka ek ARIA solution hai.** Chal step by step banate hain.

## Step 3 — Validation: Submit Pe Check Karo

Ab validation add karte hain. Submit button pe validate — agar kuch galat hai toh errors state set karo.

### 3.1 Concept — "Data Kahan Jayega?"

HTML form ka default behavior hai — submit karte hi page refresh karo aur data URL/server pe bhejo. React app mein humein page refresh nahi chahiye. Hum chahte hain — form ka data React mein capture karein, state mein store karein, aur UI update karein.

Toh pehla kaam — form mein ek **handler** function lagao jo submit event pakde.

### 3.2 Syntax — "Form Mein onSubmit Lagao"

Form mein `onSubmit` attribute add karo — yeh React ko batata hai "submit event mere function ko de do":

```tsx
<form onSubmit={handleSubmit}>
```

Abhi `handleSubmit` function exist nahi karta — abhi function banayenge.

### 3.3 Function Banao — Event Capture Karo

Pehle ek simple function banate hain jo event object receive kare aur console mein data dikhaye. Abhi type nahi denge — pehle plain JS style mein dekhte hain kya hota hai:

```tsx
function handleSubmit(event) {
  console.log("submitting — name:", name, "email:", email)
}
```

Form mein attribute add karna mat bhoolna:

```tsx
<form onSubmit={handleSubmit}>
```

### 3.4 Test — Observe Problem

**TEST:** Fields bharo, submit karo.

Console mein "submitting — name: Pravin email: pravin@test.com" aaya? ✅

Lekin ek problem — page **refresh** ho gaya (notice kiya ek flash?). Console ka output gayab? Kyunki page reload hone ke baad React dubara mount hua, console clear.

Yahi problem hai — **HTML forms ka default behavior**: submit → page refresh. React app mein yeh nahi chahiye.

### 3.5 Fix — preventDefault()

Ab fix karte hain. Event object ke paas ek method hai — `preventDefault()` — jo browser ko bolta hai "apna default behaviour mat karo":

```tsx
function handleSubmit(event) {
  event.preventDefault()
  console.log("submitting — name:", name, "email:", email)
}
```

**Cause-Effect Chain:**
- `event.preventDefault()` → browser page refresh nahi karta
- React app intact rehti hai — console output dikhta hai
- Hum data process kar sakte hain — validation, API call, state update

### 3.6 TypeScript Type — SyntheticEvent

Ab TypeScript use kar rahe hain toh event ka type bhi dena padega. React mein jo bhi event handler aata hai, woh browser ka native event nahi hota — React use **SyntheticEvent** mein wrap karta hai:

```
Browser fire karta hai:  native submit event
                              ↓
React intercept karta hai:    makes SyntheticEvent
                              ↓
Tumhare handler ko milta hai: SyntheticEvent
```

`SyntheticEvent` base class hai — React ke saare events iske subtypes the:

```
React.SyntheticEvent          ← Base — wrapper around native event
  ├── React.FormEvent         ← Form events (submit) [deprecated]
  ├── React.ChangeEvent       ← Input changes (onChange) [deprecated]
  ├── React.KeyboardEvent     ← Key presses (onKeyDown) [deprecated]
  └── React.MouseEvent        ← Clicks (onClick) [deprecated]
```

Latest `@types/react` mein yeh sab subtypes **deprecated** ho gaye hain. Ab sirf `SyntheticEvent` use hota hai with generic parameter:

```tsx
const handleSubmit = (e: React.SyntheticEvent<HTMLFormElement>) => {
  e.preventDefault()
  console.log("submitting — name:", name, "email:", email)
}
```

`<HTMLFormElement>` batata hai ki event kis HTML element se aaya. Iske saath `e.currentTarget` ka type automatically set ho jata hai.

Test dobara karo — ab page refresh nahi ho raha, console output dikh raha hai ✅.

### 3.7 — Validation: Error State + validate() + handleSubmit

Ab validation ki baat karte hain. Socho — errors ke saath kya hota hai:

- Pehle: errors nahi hain (sab fields valid)
- User submit kare: errors aa sakte hain (some fields invalid)
- User fix kare: errors chale gaye (ab valid)

**React rule:** Jo bhi UI change ho sakta hai, woh **state** hai. Errors change ho rahe hain — toh errors ke liye bhi state chahiye.

Kaise store karein errors? Ek object jisme har field optional ho — agar property nahi hai toh error nahi hai, property hai (string) toh error hai:

```tsx
const [errors, setErrors] = useState<{ name?: string; email?: string }>({})
```

Ab sawaal — **validate karein kahan?** Seedha `handleSubmit` mein bhi check kar sakte ho:

```tsx
// ❌ Mix karna — sab ek jagah
const handleSubmit = (e) => {
  e.preventDefault()
  if (!name.trim()) setErrors({ name: "Name is required" })
  else setErrors({})
  // aur submit bhi yahi...
}
```

Lekin isme **do alag concerns** mix ho rahe hain:
1. **Check karna** — kya galat hai?
2. **Action lena** — submit karna hai ya nahi?

Jab mix karte ho:
- Nayi field ya rule add karo toh `handleSubmit` mein dalna padega — 200 lines ka function ban jayega
- Edit form mein bhi same validation chahiye toh copy-paste karna padega
- Test karna mushkil — function ek saath teen kaam kar raha hai

**Better approach — validate() function alag rakho** jiska kaam sirf ek hai: "batao kya galat hai".

Is function ko **pure function** kehte hain — same input, same output, side effect nahi. Validate React state kuch set nahi karega, sirf errors object return karega. Isse:

- validate() ko test karna easy hai — input do, output check karo
- Naya rule add karna easy hai — validate mein ek line
- Edit form mein wahi validate() reuse kar sakte ho
- handleSubmit sirf decide karta hai — errors hain toh stop, nahi toh proceed

```tsx
const validate = (name: string, email: string) => {
  const newErrors: { name?: string; email?: string } = {}
  if (!name.trim()) newErrors.name = "Name is required"
  if (!email.trim()) newErrors.email = "Email is required"
  else if (!email.includes("@")) newErrors.email = "Enter a valid email"
  return newErrors
}
```

Dhyaan do — `validate` **parameters leta hai**, state ko directly read nahi karta. Agar direct `name` aur `email` variable closure se lete, toh pure function nahi hota — kyunki external state pe depend karta. Parameters se same input = same output guaranteed hai.

Console se verify pehle — validate function kya return kar raha hai:

```tsx
console.log("validation result:", validate("", ""))
```

**TEST — Case 1:** `validate("", "")` → `{name: 'Name is required', email: 'Email is required'}` ✅
**TEST — Case 2:** `validate("Pravin", "abc")` → `{email: 'Enter a valid email'}` ✅
**TEST — Case 3:** `validate("Pravin", "pra@test.com")` → `{}` ✅

Confidence aa gaya. Ab handleSubmit mein validate() call karo, setErrors karo, aur agar errors hain toh return karo — aage mat bado:

```tsx
const handleSubmit = (e: React.SyntheticEvent<HTMLFormElement>) => {
  e.preventDefault()

  const newErrors = validate(name, email)
  console.log("errors after validation:", newErrors)
  setErrors(newErrors)

  if (Object.keys(newErrors).length > 0) {
    console.log("form invalid — errors dikha rahe hain")
    return  // validation fail — aage mat bado
  }

  // yahan pahunche matlab sab valid hai
  console.log("form valid, submitting")
  alert("Form submitted!")
  setName("")
  setEmail("")
}
```

**Cause-Effect Chain:**
- `validate(name, email)` → errors object return kare (sirf check)
- `setErrors(newErrors)` → React state update → re-render (action)
- `Object.keys(newErrors).length > 0` → koi error hai → `return` — aage mat bado
- Errors empty hain → submit karo, form reset karo

**Separation clear hai:**
- **validate()** — sirf check karta hai, kuch set nahi karta
- **handleSubmit()** — decide karta hai ki kya action lena hai

**TEST — Case 1:** Dono fields empty. Console mein "errors after validation: {name: 'Name is required', email: 'Email is required'}" ✅ + "form invalid — errors dikha rahe hain" ✅.
**TEST — Case 2:** Name bharo, email mein "abc". Console mein "errors after validation: {email: 'Enter a valid email'}" ✅.
**TEST — Case 3:** Dono sahi bharo. Console mein "form valid, submitting" ✅. Alert aaya? ✅.

Ab errors state set ho rahi hai. Agle step mein errors ko UI mein dikhayenge — ARIA attributes ke saath.

## Step 4 — Error Display: aria-invalid + aria-describedby

Ab errors object se UI update karo. Input border red karo, error message dikhao, aur ARIA attributes add karo.

**Console.log se verify pehle — errors state render ho rahi hai ya nahi:**

```tsx
// Form mein, input ke neeche:
{console.log("rendering errors:", errors)}
{errors.name && (
  <p style={{ color: "red" }}>{errors.name}</p>
)}
```

**TEST:** Empty submit karo. Console mein "rendering errors: {name: 'Name is required', email: 'Email is required'}" ✅. Red text screen pe dikh raha hai? ✅.

Ab proper UI — label ke saath `htmlFor` + `id`, input mein `aria-invalid` + `aria-describedby`, span mein `role="alert"`:

```tsx
<div className="mb-4">
  <label htmlFor="contact-name" className="block font-medium mb-1">Name</label>
  <input
    id="contact-name"
    type="text"
    value={name}
    onChange={(e) => setName(e.target.value)}
    aria-required="true"
    aria-invalid={!!errors.name}
    aria-describedby={errors.name ? "name-error" : undefined}
    className={`w-full border rounded-lg px-3 py-2 focus:ring-2 focus:ring-blue-500 focus:outline-none ${
      errors.name ? "border-red-500" : "border-gray-300"
    }`}
  />
  {errors.name && (
    <span id="name-error" role="alert" className="text-red-600 text-sm mt-1 block">
      {errors.name}
    </span>
  )}
</div>
```

Har attribute ka kaam:

| Attribute | Kya karta hai |
|-----------|--------------|
| `htmlFor="contact-name"` | Label ko input se associate — click label → input focus. Screen reader "Name" bolega |
| `id="contact-name"` | Input ki unique ID. `htmlFor` isi se match karta hai |
| `aria-required="true"` | Screen reader "Name, required" bolega |
| `aria-invalid={!!errors.name}` | Jab error ho → `true`, screen reader "Name, invalid entry" bolega |
| `aria-describedby="name-error"` | Error message ka ID input se associate. Screen reader input read karte waqt error bhi padhega |
| `role="alert"` | Jaise hi span appear ho, screen reader turant announce kare — bina user ke focus move kiye |

**`aria-describedby` dynamic kyun hai?** `errors.name ? "name-error" : undefined` — jab koi error nahi, attribute exist nahi karta. Screen reader tabhi error read karega jab actually error ho. False positive nahi hoga.

Email field mein bhi wahi pattern:

```tsx
<div className="mb-4">
  <label htmlFor="contact-email" className="block font-medium mb-1">Email</label>
  <input
    id="contact-email"
    type="email"
    value={email}
    onChange={(e) => setEmail(e.target.value)}
    aria-required="true"
    aria-invalid={!!errors.email}
    aria-describedby={errors.email ? "email-error" : undefined}
    className={`w-full border rounded-lg px-3 py-2 focus:ring-2 focus:ring-blue-500 focus:outline-none ${
      errors.email ? "border-red-500" : "border-gray-300"
    }`}
  />
  {errors.email && (
    <span id="email-error" role="alert" className="text-red-600 text-sm mt-1 block">
      {errors.email}
    </span>
  )}
</div>
```

Abhi tak `noValidate` nahi daala. Browser ki default validation bhi chalegi — double validation, confusing. Add karo:

```tsx
<form onSubmit={handleSubmit} noValidate>
```

`noValidate` browser ki built-in HTML5 validation disable karta hai — `required` attribute, type mismatch (email), etc. Hum khud validate kar rahe hain JavaScript se — isliye browser interfere nahi kare.

Poora final component:

```tsx
import { useState } from "react"

export default function ContactSection() {
  const [name, setName] = useState("")
  const [email, setEmail] = useState("")
  const [errors, setErrors] = useState<{ name?: string; email?: string }>({})

  const validate = (name: string, email: string) => {
    const newErrors: { name?: string; email?: string } = {}
    if (!name.trim()) newErrors.name = "Name is required"
    if (!email.trim()) newErrors.email = "Email is required"
    else if (!email.includes("@")) newErrors.email = "Enter a valid email"
    return newErrors
  }

  const handleSubmit = (e: React.SyntheticEvent<HTMLFormElement>) => {
    e.preventDefault()
    const newErrors = validate(name, email)
    if (Object.keys(newErrors).length > 0) {
      setErrors(newErrors)
      return
    }
    setErrors({})
    alert("Form submitted!")
    setName("")
    setEmail("")
  }

  return (
    <section className="py-16 bg-gray-50" aria-labelledby="contact-heading">
      <div className="max-w-xl mx-auto px-4">
        <h2 id="contact-heading" className="text-3xl font-bold text-center mb-8">
          Contact Us
        </h2>

        <form onSubmit={handleSubmit} noValidate>
          <div className="mb-4">
            <label htmlFor="contact-name" className="block font-medium mb-1">Name</label>
            <input
              id="contact-name" type="text" value={name}
              onChange={(e) => setName(e.target.value)}
              aria-required="true"
              aria-invalid={!!errors.name}
              aria-describedby={errors.name ? "name-error" : undefined}
              className={`w-full border rounded-lg px-3 py-2 focus:ring-2 focus:ring-blue-500 focus:outline-none ${
                errors.name ? "border-red-500" : "border-gray-300"
              }`}
            />
            {errors.name && (
              <span id="name-error" role="alert" className="text-red-600 text-sm mt-1 block">
                {errors.name}
              </span>
            )}
          </div>

          <div className="mb-4">
            <label htmlFor="contact-email" className="block font-medium mb-1">Email</label>
            <input
              id="contact-email" type="email" value={email}
              onChange={(e) => setEmail(e.target.value)}
              aria-required="true"
              aria-invalid={!!errors.email}
              aria-describedby={errors.email ? "email-error" : undefined}
              className={`w-full border rounded-lg px-3 py-2 focus:ring-2 focus:ring-blue-500 focus:outline-none ${
                errors.email ? "border-red-500" : "border-gray-300"
              }`}
            />
            {errors.email && (
              <span id="email-error" role="alert" className="text-red-600 text-sm mt-1 block">
                {errors.email}
              </span>
            )}
          </div>

          <button type="submit"
            className="w-full bg-blue-600 hover:bg-blue-700 text-white py-3 rounded-lg font-semibold transition-colors focus:ring-2 focus:ring-blue-500 focus:ring-offset-2">
            Send Message
          </button>
        </form>
      </div>
    </section>
  )
}
```

|-------|--------|---------------------|

| Name (error) | Submit empty | "Name, invalid entry" + "Name is required" alert |
| Name (fix) | Type something | "Name, valid entry" |

## Common Mistakes

- **`placeholder` as label:** Placeholder gayab ho jata hai jab user type karta hai. Screen reader use read kar leta hai lekin visually user bhool sakta hai field ka naam. Hamesha `<label>` use karo.
- **`aria-invalid` bhoolna:** Error show kar diya, input border red kar diya, lekin screen reader ko nahi bataya ki field invalid hai. Blind user ko pata nahi chalega error kahan hai.
- **`role="alert"` nahi daala:** Error message screen pe aa gaya, lekin screen reader ne announce nahi kiya. User tab tak error dekhega jab tak manually na dhundhe.
- **`htmlFor` aur `id` mismatch:** Label ka `htmlFor` input ke `id` se match karna chahiye. Typo ho toh label input se associate nahi hoga.
- **`noValidate` bhoolna:** Browser apni validation bhi chalayega aur tumhari bhi — confusing behavior.

## Khud Try Karo
