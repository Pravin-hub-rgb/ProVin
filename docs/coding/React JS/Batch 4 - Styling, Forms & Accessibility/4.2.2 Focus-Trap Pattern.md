# 4.2.2 Focus-Trap Pattern

## Cheat Sheet (Quick Recall)

```tsx
const modalRef = useRef<HTMLDivElement>(null);
const openButtonRef = useRef<HTMLButtonElement>(null);
const [isOpen, setIsOpen] = useState(false);

// Auto-focus on open
useEffect(() => {
  if (isOpen) modalRef.current?.querySelector("input")?.focus();
}, [isOpen]);

// Escape handler
const handleKeyDown = (e: React.KeyboardEvent) => {
  if (e.key === "Escape") { setIsOpen(false); openButtonRef.current?.focus(); }
};

// Tab cycle
const getFocusableElements = () => Array.from(
  modalRef.current?.querySelectorAll<HTMLElement>(
    'a[href], button, input, textarea, [tabindex]:not([tabindex="-1"])'
  ) ?? []
);
// Tab + Shift+Tab: first↔last cycling (see full code)
```

## Abhi Tak Kya Hua

4.2.1 mein ARIA basics seekhe — `aria-label`, `aria-expanded`, `focus:ring`. Ab ek specific pattern seekhenge — **focus-trap**. Jab modal khule, user ka focus modal ke andar hi rahe.

## Broader Goal

Gym site mein "Book a Free Trial" modal banayenge. Modal khule → focus andar jaye. Tab dabaye → modal ke elements cycle kare, background pe nahi jaye. Escape dabaye → modal band, focus wapas button pe aaye. Yeh focus-trap pattern hai.

## Step 1 — Problem: Modal Ke Bahar Focus Chala Jaata Hai

Browser mein Gym site kholo. Hero section mein "Get Started" button hai — vahi modal ka trigger maan lo abhi ke liye.

Tab dabao jab tak focus "Get Started" button pe na pahunch jaye. Enter dabao — kuch nahi hua kyunki abhi modal hai nahi. Lekin imagine karo modal khul gaya. Ab Tab dabao — focus kahan jayega? Background ke elements pe. Modal ke andar nahi.

Browser ko pata nahi hota "ab modal open hai." Woh natural DOM order follow karta hai. Agar modal DOM mein footer ke baad hai, toh focus wahan jayega. **Is problem ko solve karna hai.**

Chal step by step modal banate hain.

## Step 2 — Static UI: Button + Modal Skeleton

Pehle content daalo. Koi logic nahi. Koi state nahi. Sirf HTML.

### Naya Concept — fixed + inset-0 + Opacity Modifier

Modal ke overlay ke liye teen naye Tailwind concepts chahiye:

| Class | CSS equivalent | Kya karta hai |
|-------|---------------|--------------|
| `fixed` | `position: fixed` | Element viewport ke relative position hota hai — scroll karne par bhi same jagah rahega |
| `inset-0` | `top: 0; right: 0; bottom: 0; left: 0` | Charo taraf 0 distance — pure screen cover karta hai. `inset-4` = charo taraf 16px gap, `inset-x-0` = sirf left+right, `inset-y-0` = sirf top+bottom |
| `bg-black/50` | `background-color: rgba(0, 0, 0, 0.5)` | `/50` = 50% opacity. `bg-black/25` = 25%, `bg-black/80` = 80%. Kisi bhi color ke saath: `bg-red-500/50`, `text-white/80` |

Fark samajh — `absolute` parent ke relative hota hai (parent `relative` hona chahiye), `fixed` hamesha **viewport** (screen) ke relative hota hai. Overlay ke liye `fixed` chahiye kyunki overlay ko screen cover karni hai, parent ke andar nahi.

## Step 4 — Focus-Trap Roadmap + Auto-Focus

### Pehle Poora Flow Samajh Lo

Step 4 se 6 tak hum focus-trap pattern build karenge. Final behavior kya hoga:

1. **Tab repeatedly** → "Book a Free Trial" button pe focus aayega (`focus:ring` dikhega)
2. **Enter** → modal khulega, focus **automatically** Name input pe jayega
3. **Tab** → modal ke **andar cycle** karega (X → Name → Email → Submit → X...)
4. **Tab** → **background pe nahi jayega** — modal ke andar hi cycle karega
5. **Escape / X click** → modal band hoga, focus **wapas** "Book a Free Trial" button pe aayega

```
[Tab] → Button focus → [Enter] → Modal opens → Focus on Name input
  → [Tab] → Email → [Tab] → Submit → [Tab] → ✕ → [Tab] → Name...
  → [Escape / ✕] → Modal closes → Focus back on button
```

Step 3 mein X button se close hota hai, lekin focus abhi bhi background pe nikal jaata hai. Steps 4-6 yeh fix karenge:

| Step | Kya add hoga |
|------|-------------|
| 4 (yeh) | Auto-focus — modal khule toh input pe focus ho |
| 5 | Escape handler — Escape dabao → modal band, focus wapas button pe |
| 6 | Tab cycle — focus modal ke andar cycle kare, background pe na jaye |

### Auto-Focus: Modal Khule Toh Input Pe Focus Jaye

**Problem:** Modal khulta hai, lekin focus kahan hai? Kahi nahi. User ko Tab (ya mouse) se manually input pe jaana padta hai. Isliye auto-focus chahiye — jaise hi modal khule, cursor directly Name input pe ho.

**Solution:** `useEffect` + `useRef`.

Pehle in dono hooks ko samajh lo:

---

**`useRef` refresher:**
```
const modalRef = useRef<HTMLDivElement>(null)
```
- `useRef` ek **mutable object** banata hai jisme `.current` property hoti hai
- `modalRef.current` = woh actual DOM element jispe `ref={modalRef}` attach kiya
- Initially `null` hota hai (element exist nahi karta abhi)
- Jab component render hota hai, React `.current` ko real DOM element se replace kar deta hai
- **Fayda:** `useRef` change hone par component re-render nahi hota (unlike `useState`). Sirf `.current` update hota hai.

**`useEffect` refresher:**
```
useEffect(() => { ... }, [isOpen])
```
- `useEffect` ka callback **render ke baad** chalta hai
- Dependency array `[isOpen]` — jab bhi `isOpen` change, callback phir se chale
- Iska matlab: modal DOM mein aa gaya (render ho gaya) → useEffect chala → ab input access kar sakte hain

---

**Do teeno ka combination:**

Step 1: `useRef` se modal ke div ka reference banao
Step 2: Div pe `ref={modalRef}` lagao
Step 3: `useEffect` mein `modalRef.current.querySelector("input")?.focus()` karo

**Lekin pehle console.log se verify karo ki useEffect trigger ho raha hai ya nahi:**

```tsx
import { useRef, useEffect } from "react"

function TrialModal() {
  const [isOpen, setIsOpen] = useState(false)
  const modalRef = useRef<HTMLDivElement>(null)

  useEffect(() => {
    console.log("useEffect fired, isOpen:", isOpen)
  }, [isOpen])

  return (
    <>
      <button onClick={() => setIsOpen(!isOpen)} className="...">
        Book a Free Trial
      </button>

      {isOpen && (
        <div
          ref={modalRef}
          className="fixed inset-0 bg-black/50 flex items-center justify-center"
        >
          {/* modal content */}
        </div>
      )}
    </>
  )
}
```

**TEST:** Button click → console "useEffect fired, isOpen: true" ✅. Dobara click → "useEffect fired, isOpen: false" ✅.

Ab real logic:

```tsx
useEffect(() => {
  if (isOpen && modalRef.current) {
    const input = modalRef.current.querySelector("input")
    console.log("focusing input:", input)
    input?.focus()
  }
}, [isOpen])
```

**TEST:** Console "focusing input: <input...>" ✅. Browser mein modal khule aur cursor directly Name input pe ✅.

---

**Important question — ref div pe kyun lagaya, direct input pe kyun nahi?**

Do reason hain:

**1. Future steps ke liye reusable hai.** Abhi sirf input focus kar rahe ho. Lekin Step 5 mein Escape key detect karni hai — `onKeyDown` bhi isi div pe lagega. Step 6 mein saare focusable elements dhunndhne hain — `querySelectorAll` bhi isi div ke andar karenge. Ek ref, sab kaam.

**2. Ek ref se multiple elements access kar sakte ho.** Direct input ref hota to sirf woh input milta. `modalRef.current.querySelector("input")` se ANDAR ka koi bhi element mil sakta hai — Name input, Email input, Submit button, X button. Ek ref, saare elements ka parent.

Socho `modalRef` ek **container** hai — iske andar jo bhi elements hain, unhe ref ke through access kar sakte ho. Direct input ref sirf ek element deta.

---

**`input?.focus()` ka `?` kyun?**

`querySelector("input")` `null` return kar sakta hai agar modal mein koi input na ho. `?` (optional chaining) ka matlab — agar `null` hai toh kuch mat karo, error mat daalo.

**`useEffect` ka dependency array `[isOpen]` kyun?**

Yeh batata hai ki "yeh code tabhi chalao jab `isOpen` change ho."
- `false → true`: modal DOM mein aaya → input focus karo
- `true → false`: modal DOM se gaya → kuch mat karo

## Step 5 — Escape: Escape Dabao → Modal Band, Focus Wapas Button Pe

**Problem:** Modal andar hai, Escape dabao toh modal band hona chahiye. Aur band hone ke baad focus wapas "Book a Free Trial" button pe aana chahiye taaki user agla action kar sake.

**Solution:** `onKeyDown` handler + `openButtonRef`.

**Logic:**
1. Modal ke div pe `onKeyDown` lagao — koi bhi key press is div ke through catch hogi
2. Agar `e.key === "Escape"` → `setIsOpen(false)` + `openButtonRef.current?.focus()`
3. `openButtonRef` ek aur `useRef` hai — is baar "Book a Free Trial" button ke liye

**Pehle console.log se verify — kaunsa key press ho raha hai:**

```tsx
const handleKeyDown = (e: React.KeyboardEvent) => {
  console.log("key pressed:", e.key)
}

// Modal ke andar wale div mein:
<div ref={modalRef} onKeyDown={handleKeyDown}>
```

**TEST:** Modal kholo. Escape dabao. Console "key pressed: Escape" ✅. "a" dabao. Console "key pressed: a" ✅.

Ab real logic:

```tsx
const openButtonRef = useRef<HTMLButtonElement>(null)

const handleKeyDown = (e: React.KeyboardEvent) => {
  if (e.key === "Escape") {
    console.log("Escape pressed, closing modal")
    setIsOpen(false)
    openButtonRef.current?.focus()
  }
}
```

Button mein `ref` daalo:

```tsx
<button ref={openButtonRef} onClick={() => setIsOpen(!isOpen)}>
```

**TEST:** Modal kholo. Escape dabao. Modal band. Focus wapas button pe. Console "Escape pressed, closing modal" ✅. Dobara Enter dabao — modal phir khule ✅.

**`openButtonRef.current?.focus()` kyun?**

Modal band hone ke baad focus kahi nahi hota (document.body pe chala jata hai). User ko pata nahi hota ab kya focus hai. Isliye explicitly focus wapas uss button pe daal rahe hain jisne modal khola tha. Yeh accessible hai — keyboard user ko turant pata chal jaata hai ki "ab main wapas button pe hoon."

## Step 6 — Tab Cycle: Focus Modal Ke Andar Cycle Kare

**Problem:** Tab dabao — focus modal ke andar hi rahega ya background pe? Currently, browser DOM order follow karta hai. Modal DOM mein Footer ke baad hai toh Tab footer ke links pe chala jayega. Yeh galat hai — modal ke andar hi cycle hona chahiye.

**Solution:** Tab key intercept karo, manually focus cycle karo. Lekin iske liye pehle kuch concepts samajhne padenge.

---

### Concept 1: QuerySelectorAll — Ek Saath Multiple Elements Dhundhna

Ab tak tumne `querySelector` dekha tha — ek element dhundhta hai. `querySelectorAll` multiple elements dhundhta hai:

```ts
document.querySelectorAll("button")   // saare button de do
document.querySelectorAll("input")    // saare input de do
```

Lekin agar ek saath button AUR input dono chahiye? CSS selector string mein commas lagao:

```ts
document.querySelectorAll("button, input")   // button bhi, input bhi — saath mein
document.querySelectorAll("button, input, textarea")  // teeno
```

Comma ka matlab "YA" — button YA input YA textarea. Jo bhi match hoga, mil jayega.

> Yeh string concatenation nahi hai. `querySelectorAll` ko HAMESHA string chahiye hota hai. Aur comma se tum multiple selectors ek saath de sakte ho.

---

### Concept 2: NodeList vs Array

`querySelectorAll` ka result simple Array nahi hota. Yeh **NodeList** hota hai — ek collection jisme `length` property hoti hai, lekin array methods (map, filter, forEach) nahi hoti sabhi browsers mein.

```ts
const buttons = document.querySelectorAll("button")
buttons.length        // ✅ kaam karta hai
buttons.map(...)      // ❌ error — NodeList pe map nahi hai
```

Isliye NodeList ko Array mein convert karte hain:

```ts
const arr = Array.from(buttons)    // NodeList → Array
arr.map(btn => ...)                // ✅ ab kaam karega
```

`Array.from()` JavaScript ka built-in method hai — kisi bhi "array-like" cheez (NodeList, Set, string) ko real Array mein convert karta hai.

---

### Concept 3: tabindex Attribute

HTML elements ka default Tab behavior hota hai — button, input, textarea Tab se focus ho sakte hain. Lekin kuch elements default mein Tab se focus nahi hote (jaise `<div>`, `<span>`, `<p>`).

`tabindex` attribute se tum kisi bhi element ko Tab-focusable bana sakte ho:

```html
<button>Default focusable</button>        <!-- Tab se focus ho sakta hai -->
<div tabindex="0">Ab yeh bhi focusable</div>  <!-- 0 = natural order mein aayega -->
<div tabindex="5">Custom order</div>      <!-- 5 = specific order mein aayega -->
```

Teen tarah ke values:

| tabindex | Matlab |
|----------|--------|
| `0` | Natural DOM order mein focusable |
| Positive (1, 2, 5...) | Custom order (pehle 1, phir 2, phir 0 wale) — rarely use karte hain |
| **`-1`** | Programmatic focus possible (`.focus()` kaam karega), lekin **Tab se focus nahi ho sakta** |

Yeh `tabindex="-1"` wala important hai — iska matlab hai element focus ho SAKTA hai (JS se) lekin Tab cycle mein NAHI aana chahiye.

Isliye jab hum saare focusable elements dhundhte hain, toh `tabindex="-1"` wale ko exclude karna padta hai.

---

### Ab Full Function Samjho

Pehle easy version — sirf buttons, inputs, textareas:

```ts
function getFocusableElements() {
  // modalRef.current = modal ka div
  // uske andar saare button + input + textarea dhundho
  const elements = modalRef.current.querySelectorAll("button, input, textarea")
  console.log("focusable:", elements)
  return elements
}
```

Lekin yeh incomplete hai. Agar modal mein anchor link (`<a href="...">`) ho? Woh bhi focusable hai. Agar koi `<div tabindex="0">` ho? Woh bhi focusable hai.

Isliye complete selector:
```
"button, input, textarea, a[href], [tabindex]:not([tabindex='-1'])"
```

| Part | Matlab |
|------|--------|
| `button, input, textarea` | Default focusable elements |
| `a[href]` | Sirf wahi anchor links jinme `href` attribute ho (bina href ke anchor focusable nahi hota) |
| `[tabindex]` | Koi bhi element jispe `tabindex` attribute laga ho |
| `:not([tabindex="-1"])` | Lekin `tabindex="-1"` wale MAT do — woh Tab cycle mein nahi aane chahiye |

Ab pura function:

```tsx
const getFocusableElements = (): HTMLElement[] => {
  if (!modalRef.current) return []
  const selectors = 'button, input, textarea, a[href], [tabindex]:not([tabindex="-1"])'
  const nodeList = modalRef.current.querySelectorAll(selectors)
  const elements = Array.from(nodeList)  // NodeList ko Array mein badlo
  console.log("focusable elements:", elements)
  return elements
}
```

### Ab Real Tab Cycle Logic

**Logic:**
- Tab daba → last element pe ho → first pe chale jao
- Shift+Tab daba → first element pe ho → last pe chale jao
- Baaki cases mein browser normal behavior kare

```tsx
if (e.key === "Tab") {
  const focusable = getFocusableElements()
  const first = focusable[0]
  const last = focusable[focusable.length - 1]

  if (e.shiftKey && document.activeElement === first) {
    console.log("Shift+Tab on first → going to last")
    e.preventDefault()
    last?.focus()
  } else if (!e.shiftKey && document.activeElement === last) {
    console.log("Tab on last → going to first")
    e.preventDefault()
    first?.focus()
  }
}
```

**Breakdown:**
- `document.activeElement` = abhi focus kiske paas hai? Browser khud track karta hai.
- `e.shiftKey` = user ne Shift daboya? True hai toh Shift+Tab.
- **Case 1:** Shift+Tab aur first element pe ho → last pe chale jao
- **Case 2:** Tab aur last element pe ho → first pe chale jao
- `e.preventDefault()` = browser ko mat do Tab le jaane do. Hum khud handle kar rahe hain.

## Step 7 — ARIA Attributes: Screen Reader Ke Liye

Focus logic theek hai. Ab screen reader users ke liye semantics add karo — woh dekhte nahi, unhe HTML attributes batate hain ki "yeh ek dialog hai, iske bahar mat jaao."

```tsx
<div
  ref={modalRef}
  role="dialog"
  aria-modal="true"
  aria-labelledby="modal-title"
  onKeyDown={handleKeyDown}
>
  <h2 id="modal-title" className="text-2xl font-bold mb-4">
    Book a Free Trial
  </h2>
```

| Attribute | Kya karta hai |
|-----------|--------------|
| `role="dialog"` | Screen reader ko batata hai yeh ek dialog hai — announce karega "Book a Free Trial dialog" |
| `aria-modal="true"` | Screen reader ko batata hai modal ke bahar ka content ignore karna hai. Baghair iske, woh background elements bhi read karega |
| `aria-labelledby="modal-title"` | Dialog ko heading se associate karta hai — `id="modal-title"` wale element ka text dialog ka accessible name ban jata hai |

> **`aria-modal` kyun zaroori hai?** Screen reader normally poora page read karta hai — top se bottom. Modal ke saath bhi woh background elements read karega agar `aria-modal="true"` nahi hai. User confused ho jayega ki "modal hai ya page hai?" `aria-modal` screen reader ko bataata hai "bas modal ke andar ka content do, background ignore karo."

> **`aria-labelledby` vs `aria-label`:** `aria-labelledby` kisi existing element ke text ko reference karta hai. `aria-label` directly string leta hai. Yahan `aria-labelledby="modal-title"` ka matlab hai — `<h2 id="modal-title">` ka text "Book a Free Trial" dialog ka name hai. Agar dono diye hain toh `aria-labelledby` priority leta hai.

Ab poora final component:

```tsx
import { useState, useRef, useEffect } from "react"
import { X } from "lucide-react"

export default function TrialModal() {
  const [isOpen, setIsOpen] = useState(false)
  const modalRef = useRef<HTMLDivElement>(null)
  const openButtonRef = useRef<HTMLButtonElement>(null)

  const getFocusableElements = (): HTMLElement[] => {
    if (!modalRef.current) return []
    const selectors = 'a[href], button, input, textarea, [tabindex]:not([tabindex="-1"])'
    return Array.from(modalRef.current.querySelectorAll<HTMLElement>(selectors))
  }

  useEffect(() => {
    if (isOpen && modalRef.current) {
      const input = modalRef.current.querySelector("input")
      input?.focus()
    }
  }, [isOpen])

  const handleKeyDown = (e: React.KeyboardEvent) => {
    if (e.key === "Escape") {
      setIsOpen(false)
      openButtonRef.current?.focus()
      return
    }
    if (e.key === "Tab") {
      const focusable = getFocusableElements()
      const first = focusable[0]
      const last = focusable[focusable.length - 1]
      if (e.shiftKey && document.activeElement === first) {
        e.preventDefault()
        last?.focus()
      } else if (!e.shiftKey && document.activeElement === last) {
        e.preventDefault()
        first?.focus()
      }
    }
  }

  return (
    <>
      <button
        ref={openButtonRef}
        onClick={() => setIsOpen(!isOpen)}
        className="bg-blue-600 hover:bg-blue-700 text-white px-8 py-3 rounded-lg font-semibold focus:outline-none focus:ring-2 focus:ring-blue-500 transition-colors"
      >
        Book a Free Trial
      </button>

      {isOpen && (
        <div
          className="fixed inset-0 bg-black/50 flex items-center justify-center z-50"
          onClick={() => {
            setIsOpen(false)
            openButtonRef.current?.focus()
          }}
        >
          <div
            ref={modalRef}
            role="dialog"
            aria-modal="true"
            aria-labelledby="modal-title"
            onKeyDown={handleKeyDown}
            onClick={(e) => e.stopPropagation()}
            className="relative bg-white rounded-xl p-8 max-w-md w-full mx-4"
          >
            <button
              onClick={() => { setIsOpen(false); openButtonRef.current?.focus() }}
              className="absolute top-3 right-3 text-gray-400 hover:text-gray-700 focus:outline-none focus:ring-2 focus:ring-blue-500 rounded transition-colors"
            >
              <X className="w-5 h-5" />
            </button>
            <h2 id="modal-title" className="text-2xl font-bold mb-4">Book a Free Trial</h2>
            <p className="text-gray-600 mb-6">Fill in your details and we'll get back to you.</p>
            <form onSubmit={(e) => e.preventDefault()}>
              <input type="text" placeholder="Name"
                className="w-full border border-gray-300 rounded-lg px-3 py-2 mb-4 focus:ring-2 focus:ring-blue-500 focus:outline-none" />
              <input type="email" placeholder="Email"
                className="w-full border border-gray-300 rounded-lg px-3 py-2 mb-4 focus:ring-2 focus:ring-blue-500 focus:outline-none" />
              <div className="flex gap-3">
                <button type="submit"
                  className="bg-blue-600 hover:bg-blue-700 text-white px-6 py-2 rounded-lg font-medium focus:outline-none focus:ring-2 focus:ring-blue-500 transition-colors">
                  Submit
                </button>
                <button type="button"
                  onClick={() => { setIsOpen(false); openButtonRef.current?.focus() }}
                  className="bg-gray-200 hover:bg-gray-300 text-gray-800 px-6 py-2 rounded-lg font-medium focus:outline-none focus:ring-2 focus:ring-blue-500 transition-colors">
                  Cancel
                </button>
              </div>
            </form>
          </div>
        </div>
      )}
    </>
  )
}
```

## Common Mistakes

- **`aria-modal` bhoolna:** Screen reader background elements bhi read karega — user confused.
- **`e.stopPropagation()` bhoolna:** Dialog ke andar click → backdrop onClick bhi chalega → modal turant band.
- **Backdrop click pe focus wapas na karna:** `openButtonRef.current?.focus()` bhoolna — focus kahi nahi.
- **Tab cycle mein `document.activeElement` galat compare karna:** `===` se compare karo, `==` nahi. Types match hone chahiye.

## Khud Try Karo

1. `role="dialog"` hatao. Screen reader se test karo — kya farak hai?
2. `getFocusableElements` mein `e.preventDefault()` hatao. Tab dabao — kya hota hai?
3. Cancel button ka `onClick` se `openButtonRef.current?.focus()` hatao. Modal band hone ke baad Escape dabao — focus kahan hai?
