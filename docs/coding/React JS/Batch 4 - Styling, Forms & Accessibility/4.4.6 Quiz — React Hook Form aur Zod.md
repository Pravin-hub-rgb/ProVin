# 4.4.6 Quiz — React Hook Form aur Zod

## MCQ

Q: Controlled form inputs mein input ki current value kaun store karta hai aur kaise update hota hai?
A. `useRef` hook se reference store karte hain, submit pe DOM se value read karte hain
B. `useState` hook mein value store karte hain, `onChange` handler se update karte hain
C. `useReducer` hook se form state manage karte hain, `dispatch` se update karte hain
D. Browser ka built-in form state apne aap handle karta hai, React sirf event listen karta hai
> B. Controlled inputs mein React state single source of truth hai. `useState` value store karta hai, `onChange` input event pe state update karta hai. A galat — `useRef` uncontrolled approach hai. C galat — possible hai par standard nahi, `useState` simpler hai. D galat — React state handle karti hai, browser nahi.

Q: Manual form validation mein error dikhane ka standard pattern kya hai?
A. Errors ko array mein store karke submit pe saare errors ek saath dikhana
B. Har field ke liye error state variable, submit pe if-else checks, error set karna
C. Form ko Error Boundary mein wrap karna jo invalid inputs detect kare
D. Browser ki built-in validation pe depend karna (`required`, `type` attributes)
> B. Manual validation mein har field ka error state hota hai, submit pe if-else se check karke error set karte hain, JSX mein `{error && <p>}</p>` dikhate hain. A galat — possible hai par standard nahi. C galat — Error Boundary runtime errors catch karta hai, validation nahi. D galat — browser validation ko control karna mushkil hai.

Q: React Hook Form mein `register('naam')` ko input element mein kaise connect karte hain?
A. `register` ek CSS class return karta hai jisme styling hoti hai, className mein lagao
B. `register` ek object return karta hai — `onChange`, `onBlur`, `ref` — spread se input mein daalo
C. `register` ek string return karta hai, input ke `name` attribute mein set karo
D. `register` input ko directly mutate karta hai, React component ke andar hi
> B. `register` ek object return karta hai jisme RHF ke internal handlers hote hain. `{...register('naam')}` spread karne se RHF input track karta hai. A galat — CSS class nahi return hoti. C galat — sirf string nahi, poora object. D galat — React mutation nahi karta, props ke through connect hota hai.

Q: RHF mein `handleSubmit` ko form ke `onSubmit` mein dene ka kya fayda hai?
A. Form data ko JSON mein convert karta hai, API ko bhejne ke liye ready karta hai
B. Browser ke default form submit behavior ko enable karta hai, form action pe bhejta hai
C. RHF state leta hai, validation trigger karta hai, valid ho toh callback call karta hai
D. Form submissions ko debounce karta hai, baar baar submit se bachata hai
> C. `handleSubmit` bridge hai — form state leta hai, validation trigger karta hai, valid ho toh `onSubmit` callback call karta hai. A galat — JSON conversion khud karni padti hai. B galat — `preventDefault()` internally call hota hai. D galat — debounce RHF feature nahi hai.

Q: RHF built-in validation mein `{...register('naam', { required: 'Naam do' })}` likhne par error message kahan milta hai?
A. `register` function ka return value — ek string hoti hai error message
B. `formState.errors.naam.message` mein automatically populate hota hai
C. Browser ke native validation popup mein dikhta hai
D. `handleSubmit` ke doosre callback mein parameter ke roop mein aata hai
> B. RHF validation errors `formState.errors` mein auto populate hoti hain. `errors.naam.message` mein wahi string hoti jo `required:` mein di thi. A galat — `register` error return nahi karta. C galat — browser validation suppress ho jaata hai. D galat — doosra callback hota hai par standard `formState.errors` hai.

Q: RHF built-in validation mein email format check kaise kiya jaata hai?
A. `register('email', { type: 'email' })` se — browser automatically validate karta hai
B. `register('email', { pattern: { value: /^...$/, message: 'Error' } })` se — regex aur message pass karte hain
C. Alag validation function banakar `register` ke `validate` option mein dete hain
D. RHF email validation support nahi karta — external library zaroori hai
> B. `pattern` rule regex leta hai aur value match na ho toh error deta hai. Email validate karne ke liye complex regex likhna padta hai — yahi Zod ka use case hai. A galat — `type: 'email'` browser validation trigger karta hai, RHF ka nahi. C galat — `validate` custom functions ke liye hai. D galat — pattern rule kaam karta hai par regex mushkil hai.

Q: `zodResolver` ka RHF mein kya kaam hai?
A. Zod schema ko plain JavaScript object mein convert karta hai
B. Zod ke errors ko browser console mein log karta hai debugging ke liye
C. Bridge ka kaam karta hai — submit pe Zod validate kare, errors RHF ke `formState` mein aaye
D. RHF ke built-in validators ko upgrade karta hai taaki Zod syntax samajh sakein
> C. `zodResolver` `@hookform/resolvers` ka function hai. useForm mein resolver ke roop mein pass karte hain. Submit pe Zod validate karta hai, errors RHF ke `formState.errors` mein populate ho jaate hain. A galat — conversion nahi karta. B galat — console log nahi karta. D galat — RHF validators upgrade nahi hote, replace hote hain.

Q: Jab RHF ke saath Zod use karte hain toh manual `FormFields` type aur Zod schema ke beech kya problem hai?
A. Zod schema aur RHF type ek saath use nahi ho sakte — conflict aata hai
B. `FormFields` type sirf RHF ke liye hota hai, usse Zod schema se koi connection nahi
C. Manual type aur Zod schema dono same fields define karte hain — duplication, do jagah maintain karna padta hai
D. `FormFields` type RHF mein nahi, sirf Zod schema mein define karna chahiye
> C. Manual type (`type FormFields = { naam: string }`) aur Zod schema (`z.object({ naam: z.string() })`) same structure define karte hain. Ek field add karni hai toh do jagah change karna padega — error-prone. `z.infer` iska solution hai. A galat — saath use hote hain. B galat — connection nahi hona hi problem hai. D galat — RHF ko type bhi chahiye.

Q: Zod v4 mein email validation ka sahi tareeka kya hai?
A. `z.string().email()` — pehle string banao phir email validation do
B. `z.email()` — top-level method, seedha email validate karo
C. `z.validate('email')` — alag validate method hai email ke liye
D. `z.string({ email: true })` — options object mein email flag do
> B. Zod v4 mein `z.email()` top-level method hai. `z.string().email()` Zod v3 ka tarika tha jo ab deprecated hai. Naye code mein `z.email('message')` use karte hain. A galat — deprecated hai. C galat — `z.validate` exist nahi karta. D galat — options object ka pattern nahi hai.

Q: Zod mein `.min(1, 'message')` ka kya effect hota hai?
A. String ki minimum length 1 character — empty string reject karega
B. Field ki minimum numeric value 1 — numbers ke liye use hota hai
C. Schema minimum 1 bar validate hoga — performance optimization
D. Form minimum 1 field hona chahiye — empty form reject karega
> A. `.min(1)` string ki length check karta hai. Empty string `""` ki length 0 hoti hai, `.min(1)` fail karega. Custom message bhi de sakte hain. B galat — number ke liye bhi `.min()` hota hai par context string ka hai. C galat — validation count ka concept nahi hai. D galat — form level check nahi hai.

---

Q: `z.infer<typeof formSchema>` se kya milta hai?
A. Zod schema ka runtime validation result — sahi hai ya galat
B. Zod schema ki TypeScript type — auto-generated object type jo schema se match karta hai
C. Zod schema ka JavaScript object — schema ko plain object mein convert karta hai
D. Zod schema ka error type — automatically error messages infer karta hai
> B. `z.infer<typeof formSchema>` ek TypeScript utility type hai. Schema ki base type nikalta hai — `naam: z.string()` se `naam: string` banata hai. Runtime mein kuch nahi karta. A galat — validation result nahi. C galat — conversion nahi karta. D galat — error messages nahi nikalta.

Q: RHF + Zod ka complete submit flow kya hai?
A. Schema → z.infer → Type + zodResolver → submit pe Zod validate → errors formState mein
B. RHF validators + Zod schema dono chalte hain — do baar validation hota hai submit pe
C. Zod schema se manually type likho → useForm<Type>() → submit pe RHF hi validate kare
D. Type alag banao → schema alag banao → RHF built-in validation use karo, Zod nahi
> A. Complete flow: Zod schema, `z.infer` se type auto-generate, `useForm` mein type + zodResolver do, submit pe Zod validate, errors RHF ke formState mein. B galat — do baar validation nahi hota, sirf Zod chalega. C galat — manual type duplication hai. D galat — built-in validation ka use case nahi hai.

## TrueFalse

Q: Manual form validation mein har field ke liye alag `useState` variable banane ki jagah ek object state (`{ naam: '', email: '' }`) bana sakte hain — isse states count kam ho jaata hai.
- True
- False

---

Q: RHF ka `register` function uncontrolled input ko controlled input mein convert kar deta hai.
- True
- False
> False. RHF uncontrolled approach follow karta hai — input ki value DOM mein rehti hai, RHF ref ke through read karta hai. Controlled input mein value React state mein hoti hai aur onChange se update hoti hai.

---

Q: RHF built-in validation aur `zodResolver` dono ek saath use kar sakte hain — ek field mein dono ka validation chalega.
- True
- False
> False. Jab `zodResolver` lagate hain toh RHF apne built-in validators disable kar deta hai. Zod saari validation sambhalta hai. Dono ek saath nahi chal sakte.

---

Q: `z.string()` ka matlab hai ki field empty nahi honi chahiye — string type hai toh kuch content toh chahiye.
- True
- False
> False. `z.string()` sirf type check karta hai — value string hai ya nahi. Empty string `""` bhi valid string hai. Empty string reject karne ke liye `.min(1)` chahiye.

---

Q: Zod v4 mein `z.email()` top-level method hai — pehle `z.string()` call karne ki zaroorat nahi.
- True
- False
> True. `z.email()` direct use kar sakte hain. `z.string().email()` Zod v3 ka tarika hai jo ab deprecated hai.

---

Q: `z.infer` sirf development time (compile time) pe kaam karta hai — production bundle mein iska kuch trace nahi hota.
- True
- False
> True. `z.infer` ek TypeScript utility type hai. Compile time pe type check hota hai, runtime JavaScript bundle mein kuch nahi bachta. Zod ka runtime function nahi hai yeh.
