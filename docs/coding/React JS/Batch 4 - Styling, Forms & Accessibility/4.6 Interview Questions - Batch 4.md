### 11. Controlled vs Uncontrolled components?

**Answer:** Controlled: the input's value lives in React state (`value` + `onChange`) — React is the source of truth, enabling real-time validation and conditional UI. Uncontrolled: the DOM holds the value; you read it with a `ref` when needed.

**Likely follow-up:** *When would you use uncontrolled?* — simple forms, file inputs, or integrating with non-React code; everything with live validation stays controlled (or uses React Hook Form, which manages this for you).

### 70. What is the basic pattern for a controlled form input?

**Answer:** `<input value={state} onChange={e => setState(e.target.value)} />` — the value comes from React state, every keystroke updates state, which re-renders the input with the new value.

**Likely follow-up:** *Why doesn't typing lag?* — single-input state updates are cheap; the cost appears when that state change re-renders a huge list next to it (colocate or memoize — Batch 5).

### 74. Difference between `e.preventDefault()` and `e.stopPropagation()`?

**Answer:** `preventDefault()` cancels the browser's default action — like a form submit reloading the page. `stopPropagation()` stops the event bubbling up to parent handlers.

**Likely follow-up:** *Where do you use both?* — a form inside a clickable card: prevent the submit reload, stop the click reaching the card's handler.

### 48. What is the purpose of the `useId` hook?

**Answer:** Generates a unique, stable ID that matches between server and client renders (SSR-safe) — used to connect `<label>` and `aria-*` attributes to inputs without `Math.random()` hydration mismatches.

**Likely follow-up:** *Why not just hardcode an id?* — components can render multiple times on a page; hardcoded ids collide. `useId` gives per-instance uniqueness.

### 109. How do you ensure accessibility in React apps?

**Answer:** Semantic HTML first (`button` not `div`), ARIA attributes where semantics fall short, keyboard navigation (tab order, focus traps in modals), `useId` for label associations, and automated checks with `eslint-plugin-jsx-a11y` or axe-core.

**Likely follow-up:** *Fastest accessibility win?* — real buttons/labels/alt text; most violations disappear before you touch a single ARIA attribute.

### 68. Debouncing vs Throttling — when to use each in React?

**Answer:** Debounce: run once after a pause in rapid-fire events — search-as-you-type waits 300ms after the last keystroke. Throttle: run at most once per fixed interval — window resize/scroll handlers. Both cap expensive API calls and re-renders.

**Likely follow-up:** *Which for a search box?* — debounce (you want the final query); which for scroll analytics? — throttle (you want steady sampling).

---

### 97. What is a Portal in React?

**Answer:** `createPortal(child, domNode)` renders UI into a DOM node outside the parent hierarchy (usually `document.body`) while keeping the React tree and event bubbling logically unchanged — the standard fix for modals, dropdowns and tooltips trapped by parent `overflow`/`z-index`.

**Likely follow-up:** *Why not just append to body manually?* — you'd lose React context and event bubbling; the portal keeps the component in the React tree, so Context and handlers still work.
