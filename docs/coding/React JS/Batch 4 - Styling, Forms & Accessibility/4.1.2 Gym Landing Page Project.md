### 2.5 "Ab browser failao. 768px pe kya broken ho raha hai?"

Mobile design ready hai. Ab dev browser ka viewport stretch karta hai — dheere dheere.

**768px (md breakpoint).** Links ke liye jagah hai. Toh:

*"Mobile pe links chhupe the. Ab 768px se upar links dikhne chahiye. Aur hamburger ab chhupna chahiye — kyunki space hai."*

```
                    Mobile (base: 0-767px)    Desktop (md+: 768px+)
Links               hidden                    flex
Hamburger           block (default)           hidden
```

**Base class = mobile behavior. Breakpoint override = desktop behavior.**

Yahi hai mobile-first ka core pattern.

```tsx
// Links — base: hidden. md breakpoint override: flex
<div className="hidden md:flex gap-8 font-medium">
  <a href="#">Home</a>
  <a href="#">Features</a>
  <a href="#">Pricing</a>
  <a href="#">Contact</a>
</div>

// Hamburger — base: block (mobile dikhe). md override: hidden
<button className="md:hidden text-2xl">☰</button>
```

Notice — links mein abhi koi hover class nahi hai. Sirf layout ka kaam ho raha hai. Hover polish agle step mein daalenge.

**Links ke baare mein:** Static page hai — koi routing nahi. Isliye `<a>` enough. Real app mein (jaise To-Do app) tum `<Link>` (basic navigation) ya `<NavLink>` (active state styling) use karte. Choice depends on: "Kya active state highlight karni hai?"

**TEST:** 375px → sirf logo + hamburger. 768px+ → links dikhein, hamburger chhup ✅

> **Maine pehli baar `md:` dekha toh laga "yeh mobile lagao." But ulta hai. `md:` ka matlab "agar screen md se badi hai tab." Mobile ke liye base classes likho, breakpoints sirf enhance karte hain.**

---

### 2.6 "Ab hover daalo — polish ka time."

Links ab desktop pe dikh rahe hain (`md:flex`). Ab hover add karo visual feedback ke liye.

Hover ek **desktop-only interaction** hai. Mobile user kabhi mouse nahi la sakta. Isliye pehle layout aur responsive kaam kiya, phir polish — yahi sahi order hai.

```tsx
<a href="#" className="hover:text-blue-400 transition-colors">Home</a>
```

- `hover:text-blue-400` — hover state pe text blue ho jayega.
- `transition-colors` — smooth animation. 150ms default. Baghair transition ke color instantly change hota hai — jarring lagta hai.

Ab purane code mein sirf hover classes add karte hain:

```tsx
<div className="hidden md:flex gap-8 font-medium">
  <a href="#" className="hover:text-blue-400 transition-colors">Home</a>
  <a href="#" className="hover:text-blue-400 transition-colors">Features</a>
  <a href="#" className="hover:text-blue-400 transition-colors">Pricing</a>
  <a href="#" className="hover:text-blue-400 transition-colors">Contact</a>
</div>
```

**TEST:** 768px+ karo. Links visible hain. Hover karo — color smoothly blue ho jata hai ✅

> **Ek senior dev ne mujhe sikhaya tha:** "Critical actions kabhi sirf hover pe mat rakho. Mobile user unhe kabhi access nahi kar payega. Hover polish hai, functionality nahi."

### 2.7 "Hamburger clickable karna hai. State ka use karo, CSS hack nahi."

Ab problem: hamburger click pe mobile menu khulna chahiye. Dev sochta hai:

*"Menu ki visibility yaad rakhni hai. CSS display toggle? No — React component ka state hai. `useState` use karo."*

```
Click → setIsOpen(!isOpen) → state flip
State true → mobile menu render
State false → mobile menu hidden
```

```tsx
import { useState } from "react"

function Navbar() {
  const [isOpen, setIsOpen] = useState(false)

  return (
    <nav className="bg-gray-900 text-white">
      <div className="max-w-6xl mx-auto px-4 py-4 flex justify-between items-center">
        <div className="text-2xl font-bold">💪 GymPro</div>
        <div className="hidden md:flex gap-8 font-medium">
          <a href="#" className="hover:text-blue-400 transition-colors">Home</a>
          <a href="#" className="hover:text-blue-400 transition-colors">Features</a>
          <a href="#" className="hover:text-blue-400 transition-colors">Pricing</a>
          <a href="#" className="hover:text-blue-400 transition-colors">Contact</a>
        </div>
        <button
          className="md:hidden text-2xl"
          onClick={() => setIsOpen(!isOpen)}
        >
          {isOpen ? "✕" : "☰"}
        </button>
      </div>

      {/* Mobile menu — sirf tab render jab isOpen true */}
      {isOpen && (
        <div className="md:hidden bg-gray-800 px-4 py-4 flex flex-col gap-4">
          <a href="#" className="hover:text-blue-400">Home</a>
          <a href="#" className="hover:text-blue-400">Features</a>
          <a href="#" className="hover:text-blue-400">Pricing</a>
          <a href="#" className="hover:text-blue-400">Contact</a>
        </div>
      )}
    </nav>
  )
}
```

**CSS `display: block/none` kyun nahi?** Kyunki React ka domain hai state management. CSS ka domain nahi. `useState` ko use karo — woh React ko batata hai "ab re-render kar." CSS direct manipulation React ke virtual DOM ko bypass karta hai.

**TEST:** Mobile pe hamburger click → menu khule. ✕ icon. Dobara click → menu band. Desktop pe hamburger chhupa, links dikhte hain ✅

### 3.2 "Background pattern — gradient dark to dark."

Hero visually impactful hona chahiye. Gradient background:


- `from-gray-900 via-gray-800 to-gray-900` — start: darkest, middle: lighter (gradient effect dikhe), end: darkest.

`text-white` — sab text white.

### 3.3 "Container + centering. Pehle jaisa pattern."

```tsx
<div className="max-w-6xl mx-auto px-4 py-24 md:py-32 text-center">
```

`py-24 md:py-32` — mobile pe 6rem padding, md se 8rem. Mobile pe thoda kam jagah, desktop pe zyada.

### 3.4 "Mobile pe heading chhoti. Desktop pe badi. Responsive typography."

Dev ka decision tree:

*"Heading sabse important cheez hai. Mobile 375px pe 4xl sufficient hai. 768px pe thoda bada. 1024px pe aur bada."*

```tsx
<h1 className="text-4xl md:text-5xl lg:text-6xl font-bold mb-4">
  Transform Your <span className="text-blue-500">Body</span>
</h1>
```

- `text-4xl` (36px) — base = mobile.
- `md:text-5xl` (48px) — tablet override.
- `lg:text-6xl` (60px) — desktop override.

`text-blue-500` — sirf "Body" highlight. Brand color. Blue-500 = middle shade, primary actions ke liye ideal.

Paragraph:
```tsx
<p className="text-lg md:text-xl text-gray-300 max-w-2xl mx-auto mb-8">
  Join the best gym in town...
</p>
```

- `text-gray-300` — light gray. Pure white nahi — thoda subtle, heading se kam emphasis.
- `max-w-2xl mx-auto` — width limit 42rem. Paragraph full width nahi phelta.

### 3.5 "Do buttons — primary filled, secondary outline."

```tsx

  <button className="bg-blue-600 hover:bg-blue-700 text-white px-8 py-3 rounded-lg font-semibold transition-colors">
```

**Primary (filled):** `bg-blue-600 hover:bg-blue-700` — action button. Kitna bhi hover effects daalo, primary action hamesha clear hona chahiye bina hover kiye.

**Secondary (outline):** `border-2 border-white hover:bg-white hover:text-gray-900` — less prominent. Hover pe invert hota hai.

> **Senior dev ka rule:** Kabhi do primary buttons ek saath mat rakho. Ek dominant, ek secondary. Yahan Get Started dominant hai, Learn More secondary.

```tsx
              <div className="text-5xl mb-4">{feature.icon}</div>
              <h3 className="text-xl font-bold mb-2">{feature.title}</h3>
              <p className="text-gray-600 leading-relaxed">{feature.desc}</p>
            </div>
          ))}
        </div>
      </div>
    </section>
  )
}
```

## Common Mistakes (Senior Dev ke Blindspots)

- **`mx-auto` bhoolna:** Tum container daalna bhool jaaoge aur content left-aligned rahega. Har section mein check karo — `max-w-6xl` ke saath `mx-auto` hai?
- **`key` prop map() mein:** React warning ayegi. Devtools mein dekho. Static array hai toh `index` chalta hai. Dynamic ho toh unique `id` do.
- **Mobile-first confusion:** `md:` ka matlab "768px se upar." Base class = mobile behavior. Breakpoint = override. `hidden md:flex` — mobile hidden, md se flex.
- **Hamburger ki visibility bhoolna:** Desktop pe hamburger chhupana. `md:hidden` button pe. Bhoologe toh desktop pe bhi hamburger dikhega.
- **Data vs hardcode decision:** 3 se zyada repetitive elements ho toh data array + map sochna. Manual copy-paste mat karo.
- **Primary vs secondary button:** Do visually equal buttons nahi. Ek dominant, ek subtle. User ko pata hona chahiye "pehle yeh click kar."

## Summary (Dev ka Mental Model)

| Concept | Dev ka Thought |
|---|---|
| Folder structure | `components/` — har component alag file. `App.tsx` compose karta hai. |
| Mobile-first | Base class = mobile. Breakpoint = override. Mobile decide karo pehle. |
| Container pattern | `max-w-6xl mx-auto px-4` — limit + center + padding. Har mein same. |
| Responsive grid | `grid-cols-1 md:grid-cols-2 lg:grid-cols-3` — mobile 1, tablet 2, desktop 3. |
| Responsive hide/show | `hidden md:flex` — mobile chhupao, desktop dikhao. |
| State-based toggle | `useState` for menu. CSS display nahi, React state ka domain hai. |
| Hover effects | Polish hai, functionality nahi. Mobile pe hover exist nahi karta. |
| Data-driven UI | Repetitive elements → array + `.map()`. Scale karta hai. |
