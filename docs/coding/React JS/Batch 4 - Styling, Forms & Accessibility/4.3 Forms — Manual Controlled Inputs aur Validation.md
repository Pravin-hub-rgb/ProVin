## Cheat Sheet (Quick Recall)

```tsx
// Typed form state
interface NoteForm {
  title: string;
  content: string;
}

const [form, setForm] = useState<NoteForm>({ title: "", content: "" });

// Controlled input — multiple fields with single handler
const handleChange = (e: React.ChangeEvent<HTMLInputElement | HTMLTextAreaElement>) => {
  const { name, value } = e.target;
  setForm((prev) => ({ ...prev, [name]: value }));
};

// Handle submit
const handleSubmit = (e: React.FormEvent) => {
  e.preventDefault(); // IMPORTANT — page reload rokta hai
  // ...validation + logic
};

// Manual validation
interface FormErrors {
  title?: string;
  content?: string;
}

function validate(form: NoteForm): FormErrors {
  const errors: FormErrors = {};
  if (!form.title.trim()) errors.title = "Title is required";
  else if (form.title.length < 3) errors.title = "At least 3 characters";
  if (!form.content.trim()) errors.content = "Content is required";
  return errors;
}

// Usage in JSX
<form onSubmit={handleSubmit}>
  <label htmlFor="title">Title</label>
  <input id="title" name="title" value={form.title} onChange={handleChange} />
  {errors.title && <span role="alert">{errors.title}</span>}
</form>
```

## Abhi Tak Kya Hua

4.2 mein accessibility seekhi — ARIA labels, focus management, focus-trap pattern, accessible forms (labels, aria-invalid, aria-describedby, role="alert"). Gym site ke contact form mein proper labels aur error associations daale.

Ab baari hai **forms ki** — lekin is baar poori depth mein. 1.7 mein `useState` seekha tha aur ek simple input form banaya tha (name input → alert). Lekin real forms mein multiple fields hote hain, validation hoti hai, error messages, submit handling — aur bahut kuch.

Maine bhi apne pehle project mein forms ko "bas ek input" samajh ke underestimate kiya tha — baad mein pata chala ki forms poori app ka 50% logic consume kar sakte hain. Har field ke liye state, validation, error handling — sab kuch manually likhna padta hai. Yeh doc usi experience se likh raha hoon.

Yeh doc (4.3) aur agli doc (4.4) — dono forms ke liye hain. Pehle **manual approach** seekhenge (sab kuch khud likhenge — controlled inputs, validation, error handling). Phir 4.4 mein **React Hook Form + Zod** dekhenge — jo boilerplate kam karta hai aur performance better deta hai.

Manual → Better ka pattern yahan bhi hai. Pehle problem feel karo, phir library introduce karo.

## Step 1 — Problem Feel Karo: HTML Forms vs React Forms

HTML forms apne aap kaam karte hain:

```html
<form action="/submit">
  <input name="title" />
  <button type="submit">Submit</button>
</form>
```

Submit karoge toh page refresh hoga, data server pe jayega. Lekin React mein hum **page refresh nahi chahte** — humein data JavaScript mein capture karna hai, state mein store karna hai, aur UI instantly update karni hai. Isliye hum form ke default behavior ko rok te hain (`preventDefault`) aur sab kuch React ke through handle karte hain.

Yeh approach kehlata hai **controlled components** — input ki value React state se control hoti hai, DOM se nahi. 1.7 mein yeh concept briefly touch kiya tha, lekin ab poori depth mein dekhenge.

## Step 2 — Controlled Input Ka Concept (Coder's Perspective Flow)

### Step 2.1 — Concept: Kaun Control Kar Raha Hai?

Vanilla HTML mein input ki value **DOM** control karta hai. Tum type karte ho, DOM update hota hai. React ko pata nahi chalata.

React mein input ki value **React state** control karti hai. Jab user type karta hai, `onChange` event fire hota hai, state update hoti hai, re-render hota hai, nayi value input mein dikhti hai.

```
Vanilla: User types → DOM updates (React unaware)
React:   User types → onChange → setState → re-render → input shows new value
```

### Step 2.2 — Syntax: Value + onChange

```tsx
<input
  value={form.title}        // React state se value aati hai
  onChange={handleChange}    // User type kare toh state update karo
  name="title"              // Kaunsa field update karna hai — identify karta hai
/>
```

Teen attributes mandatory hain: `value` (state), `onChange` (handler), aur `name` (field identifier).

### Step 2.3 — Visual Mapping

```
User types "Hello"
  → onChange fires
  → e.target.name = "title" (kaunsa field)
  → e.target.value = "Hello" (kya type kiya)
  → setForm({ ...form, title: "Hello" })
  → re-render
  → form.title ab "Hello"
  → input value = "Hello"
```

### Step 2.4 — Minimal Code: Single Handler for All Fields

```tsx
import { useState } from "react";

interface NoteForm {
  title: string;
  content: string;
}

function NoteInput() {
  const [form, setForm] = useState<NoteForm>({ title: "", content: "" });

  const handleChange = (
    e: React.ChangeEvent<HTMLInputElement | HTMLTextAreaElement>
  ) => {
    const { name, value } = e.target;
    setForm((prev) => ({ ...prev, [name]: value }));
  };

  return (
    <form>
      <input
        name="title"
        value={form.title}
        onChange={handleChange}
        placeholder="Note title"
      />
      <textarea
        name="content"
        value={form.content}
        onChange={handleChange}
        placeholder="Note content"
      />
    </form>
  );
}
```

**Pattern dhyan do:** Ek hi `handleChange` function teeno fields ke liye kaam kar raha hai. Kaise? `e.target.name` se field identify karta hai, aur `[name]: value` computed property syntax se specific field update karta hai. Spread operator `...prev` se baaki fields preserve rehti hain.

### Step 2.5 — Flow: Jab User Input Type Karta Hai

```
1. User "Buy groceries" type karta hai
2. onChange → handleChange fires
3. e.target.name = "title", e.target.value = "Buy groceries"
4. setForm(prev => ({ ...prev, title: "Buy groceries" }))
5. React state update → component re-render
6. input value = form.title = "Buy groceries" — UI updated
```

## Step 3 — Form Submit Handling

Form submit karne ke liye `onSubmit` event handler use karte hain. Most important cheez — `e.preventDefault()` call karna nahi bhoolna.

```tsx
const handleSubmit = (e: React.FormEvent) => {
  e.preventDefault(); // page reload hone se rokta hai

  // Validation yahan karenge
  // Data submit karenge (API ya local state)
  // Form reset karenge
};
```

`React.FormEvent` — React ka synthetic event type for form events. `preventDefault()` browser ke default form submission behavior ko rokta hai (jo page refresh karta hai).

### Full Submit Handler

```tsx
function NoteInput({ onAddNote }: { onAddNote: (note: NoteForm) => void }) {
  const [form, setForm] = useState<NoteForm>({ title: "", content: "" });

  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    onAddNote(form);         // parent ko data bhejo
    setForm({ title: "", content: "" }); // form reset
  };

  const handleChange = (
    e: React.ChangeEvent<HTMLInputElement | HTMLTextAreaElement>
  ) => {
    const { name, value } = e.target;
    setForm((prev) => ({ ...prev, [name]: value }));
  };

  return (
    <form onSubmit={handleSubmit}>
      {/* inputs */}
      <button type="submit">Add Note</button>
    </form>
  );
}
```

`onAddNote` ek callback prop hai — parent ko data bhejta hai. Submit ke baad form reset karna important hai — nahi toh purana data input mein dikhta rahega.

## Step 4 — Manual Validation Pattern

Ab forms ka sabse tedious part — **validation**. Manual validation means — sab kuch khud likhna. Ek validate function, ek errors state, aur field-level error messages.

### Step 4.1 — Validation Function

```tsx
interface FormErrors {
  title?: string;
  content?: string;
}

function validateNote(form: NoteForm): FormErrors {
  const errors: FormErrors = {};

  // Title validation
  if (!form.title.trim()) {
    errors.title = "Title is required";
  } else if (form.title.trim().length < 3) {
    errors.title = "Title must be at least 3 characters";
  } else if (form.title.trim().length > 50) {
    errors.title = "Title must be under 50 characters";
  }

  // Content validation
  if (!form.content.trim()) {
    errors.content = "Content is required";
  } else if (form.content.trim().length < 10) {
    errors.content = "Content must be at least 10 characters";
  }

  return errors;
}
```

### Step 4.2 — Error State in Form

```tsx
function NoteInput() {
  const [form, setForm] = useState<NoteForm>({ title: "", content: "" });
  const [errors, setErrors] = useState<FormErrors>({});
  const [touched, setTouched] = useState<{ title?: boolean; content?: boolean }>({});

  const handleChange = (
    e: React.ChangeEvent<HTMLInputElement | HTMLTextAreaElement>
  ) => {
    const { name, value } = e.target;
    setForm((prev) => ({ ...prev, [name]: value }));

    // Real-time validation — sirf touched fields ke liye
    if (touched[name as keyof typeof touched]) {
      const newErrors = validateNote({ ...form, [name]: value });
      setErrors((prev) => ({ ...prev, [name]: newErrors[name as keyof FormErrors] }));
    }
  };

  const handleBlur = (
    e: React.FocusEvent<HTMLInputElement | HTMLTextAreaElement>
  ) => {
    const { name } = e.target;
    setTouched((prev) => ({ ...prev, [name]: true }));
    // Field leave karte waqt validate karo
    const newErrors = validateNote(form);
    setErrors((prev) => ({ ...prev, [name]: newErrors[name as keyof FormErrors] }));
  };

  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    const newErrors = validateNote(form);
    setErrors(newErrors);
    setTouched({ title: true, content: true });

    if (Object.keys(newErrors).length > 0) return; // validation fail

    onAddNote(form);
    setForm({ title: "", content: "" });
    setErrors({});
    setTouched({});
  };

  // ...JSX
}
```

**Touched pattern:** Jab tak user ne field ko touch nahi kiya (blur event fire nahi hua), tab tak error nahi dikhana. Kyun? Agar pehle se errors dikhane shuru kar doge, toh user ko form bharte waqt hi red messages dikhenge — annoying. Sirf tab dikhao jab user field chhod ke gaya ho (blur) ya submit kiya ho.

### Step 4.3 — JSX with Errors

```tsx
return (
  <form onSubmit={handleSubmit} noValidate>
    <div className="mb-4">
      <label htmlFor="note-title" className="block font-medium mb-1">
        Title
      </label>
      <input
        id="note-title"
        name="title"
        value={form.title}
        onChange={handleChange}
        onBlur={handleBlur}
        className={`w-full border rounded-lg px-3 py-2 focus:ring-2 focus:ring-blue-500 focus:outline-none ${
          errors.title && touched.title ? "border-red-500" : "border-gray-300"
        }`}
        aria-invalid={!!errors.title && touched.title}
        aria-describedby={errors.title && touched.title ? "title-error" : undefined}
      />
      {errors.title && touched.title && (
        <span id="title-error" role="alert" className="text-red-600 text-sm mt-1 block">
          {errors.title}
        </span>
      )}
    </div>
    {/* similar for content */}
  </form>
);
```

### NoteForm Component

```tsx
import { useState, useEffect } from "react";
import type { NoteFormData } from "./types";

interface NoteFormProps {
  initialData?: NoteFormData;  // Edit mode ke liye
  onSubmit: (data: NoteFormData) => void;
  submitLabel?: string;
}

interface FormErrors {
  title?: string;
  content?: string;
}

function validateNote(data: NoteFormData): FormErrors {
  const errors: FormErrors = {};
  if (!data.title.trim()) errors.title = "Title is required";
  else if (data.title.trim().length < 3) errors.title = "At least 3 characters";
  else if (data.title.trim().length > 50) errors.title = "Under 50 characters";
  if (!data.content.trim()) errors.content = "Content is required";
  else if (data.content.trim().length < 10) errors.content = "At least 10 characters";
  return errors;
}

export default function NoteForm({ initialData, onSubmit, submitLabel = "Add Note" }: NoteFormProps) {
  const [form, setForm] = useState<NoteFormData>({ title: "", content: "" });
  const [errors, setErrors] = useState<FormErrors>({});
  const [touched, setTouched] = useState<{ title?: boolean; content?: boolean }>({});

  // Edit mode — initialData se form fill karo
  useEffect(() => {
    if (initialData) setForm(initialData);
  }, [initialData]);

  const handleChange = (e: React.ChangeEvent<HTMLInputElement | HTMLTextAreaElement>) => {
    const { name, value } = e.target;
    setForm((prev) => ({ ...prev, [name]: value }));
    if (touched[name as keyof typeof touched]) {
      const newErrors = validateNote({ ...form, [name]: value });
      setErrors((prev) => ({ ...prev, [name]: newErrors[name as keyof FormErrors] }));
    }
  };

  const handleBlur = (e: React.FocusEvent<HTMLInputElement | HTMLTextAreaElement>) => {
    const { name } = e.target;
    setTouched((prev) => ({ ...prev, [name]: true }));
    const newErrors = validateNote(form);
    setErrors((prev) => ({ ...prev, [name]: newErrors[name as keyof FormErrors] }));
  };

  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    const newErrors = validateNote(form);
    setErrors(newErrors);
    setTouched({ title: true, content: true });
    if (Object.keys(newErrors).length > 0) return;
    onSubmit(form);
    if (!initialData) setForm({ title: "", content: "" });
    setErrors({});
    setTouched({});
  };

  return (
    <form onSubmit={handleSubmit} noValidate>
      <div className="mb-4">
        <label htmlFor="note-title" className="block font-medium mb-1">
          Title
        </label>
        <input
          id="note-title"
          name="title"
          value={form.title}
          onChange={handleChange}
          onBlur={handleBlur}
          className={`w-full border rounded-lg px-3 py-2 focus:ring-2 focus:ring-blue-500 focus:outline-none ${
            errors.title && touched.title ? "border-red-500" : "border-gray-300"
          }`}
          aria-invalid={!!errors.title && touched.title}
          aria-describedby={errors.title && touched.title ? "title-error" : undefined}
        />
        {errors.title && touched.title && (
          <span id="title-error" role="alert" className="text-red-600 text-sm mt-1 block">
            {errors.title}
          </span>
        )}
      </div>

      <div className="mb-4">
        <label htmlFor="note-content" className="block font-medium mb-1">
          Content
        </label>
        <textarea
          id="note-content"
          name="content"
          value={form.content}
          onChange={handleChange}
          onBlur={handleBlur}
          rows={4}
          className={`w-full border rounded-lg px-3 py-2 focus:ring-2 focus:ring-blue-500 focus:outline-none ${
            errors.content && touched.content ? "border-red-500" : "border-gray-300"
          }`}
          aria-invalid={!!errors.content && touched.content}
          aria-describedby={errors.content && touched.content ? "content-error" : undefined}
        />
        {errors.content && touched.content && (
          <span id="content-error" role="alert" className="text-red-600 text-sm mt-1 block">
            {errors.content}
          </span>
        )}
      </div>

      <button
        type="submit"
        className="bg-blue-600 hover:bg-blue-700 text-white px-6 py-2 rounded-lg font-medium transition-colors"
      >
        {submitLabel}
      </button>
    </form>
  );
}
```

### App Component (Notes App v1)

```tsx
import { useState } from "react";
import type { Note, NoteFormData } from "./types";
import NoteForm from "./NoteForm";
import NoteCard from "./NoteCard";

export default function NotesAppV1() {
  const [notes, setNotes] = useState<Note[]>([]);
  const [editingNote, setEditingNote] = useState<Note | null>(null);

  const addNote = (data: NoteFormData) => {
    const newNote: Note = {
      id: Date.now(),
      title: data.title.trim(),
      content: data.content.trim(),
      createdAt: new Date().toLocaleDateString(),
    };
    setNotes((prev) => [newNote, ...prev]);
  };

  const updateNote = (data: NoteFormData) => {
    if (!editingNote) return;
    setNotes((prev) =>
      prev.map((note) =>
        note.id === editingNote.id
          ? { ...note, title: data.title.trim(), content: data.content.trim() }
          : note
      )
    );
    setEditingNote(null);
  };

  const deleteNote = (id: number) => {
    setNotes((prev) => prev.filter((note) => note.id !== id));
  };

  return (
    <div className="max-w-2xl mx-auto p-4">
      <h1 className="text-3xl font-bold mb-2">📝 Notes App v1</h1>
      <p className="text-gray-500 mb-6">
        Create notes with manual validation — all controlled inputs, no libraries.
      </p>

      <div className="bg-gray-50 rounded-xl p-6 mb-8 border border-gray-200">
        <h2 className="text-xl font-semibold mb-4">
          {editingNote ? "Edit Note" : "Create New Note"}
        </h2>
        <NoteForm
          key={editingNote?.id ?? "new"}
          initialData={editingNote ?? undefined}
          onSubmit={editingNote ? updateNote : addNote}
          submitLabel={editingNote ? "Update Note" : "Add Note"}
        />
      </div>

      {notes.length === 0 ? (
        <p className="text-gray-400 text-center py-8">
          No notes yet. Create one above!
        </p>
      ) : (
        <div className="space-y-4">
          {notes.map((note) => (
            <NoteCard
              key={note.id}
              note={note}
              onEdit={setEditingNote}
              onDelete={deleteNote}
            />
          ))}
        </div>
      )}
    </div>
  );
}
```

**Flow of the app:**

```
1. User form bharta hai (title + content)
2. Validation check hoti hai har field ke liye
3. Submit karta hai → note add hota hai list mein
4. NoteCard dikhta hai — Edit aur Delete buttons ke saath
5. Edit button → form fill hota hai editingNote state se
6. Update → note updated, form reset
```

## What It Is NOT

- **`preventDefault()` optional nahi hai** — bhool gaye toh form submit hone par page refresh ho jayega, saara state reset ho jayega, aur React app dubara load hogi. Har form mein pehli line `e.preventDefault()` likhna rule bana lo.
- **Manual validation scalable nahi hai.** Teen fields ke liye theek hai, lekin 10+ fields ke liye boilerplate bahut ho jati hai — har field ke liye if-else, error state, touched state, blur handler. Yahan React Hook Form aata hai (4.4 mein).
- **`noValidate` attribute bhoolna mat.** Browser ki default HTML validation (required, type="email", etc.) controlled components ke saath conflict kar sakti hai. `noValidate` browser ki validation band kar deta hai — humari custom validation chalegi.
- **Touched pattern zaroori nahi hai** har app mein, lekin user experience ke liye recommended hai. Tum chahe toh submit hone pe saare errors ek saath dikha sakte ho (without touched tracking).
- **Form state ko reset karna mat bhoolna** submit ke baad — `setForm({ title: "", content: "" })`. Nahin toh purana data input mein dikhta rahega.

## In Your Own Words

<details>
<summary>Controlled component kya hota hai aur uncontrolled se kya fark hai?</summary>

Controlled component mein input ki value React state se control hoti hai — `value={form.title}` + `onChange={handleChange}`. Jab user type karta hai, React state update hoti hai, aur input wahi value dikhata hai jo state mein hai. Uncontrolled mein input apni internal DOM state maintain karta hai — React ko pata nahi hota value kya hai jab tak form submit nahi karte. React forms mein controlled approach standard hai kyunki state aur UI hamesha sync rehte hain, validation easy hoti hai, aur conditional rendering possible hai.
</details>

<details>
<summary>Ek `handleChange` function multiple fields ke liye kaise kaam karta hai?</summary>

Har input mein `name` attribute hota hai (jaise `name="title"`). Jab onChange fire hota hai, `e.target.name` se field ka naam milta hai aur `e.target.value` se current value. Phir computed property syntax `[name]: value` ka use karte hain: `setForm(prev => ({ ...prev, [name]: value }))`. Spread operator `...prev` baaki fields ki values preserve karta hai. Is pattern se ek hi function 10 fields ke liye bhi kaam karega — koi alag-alag handler nahi banana padta.
</details>

<details>
<summary>Manual validation mein "touched" pattern kyu use karte hain?</summary>

Touched pattern ensure karta hai ki error messages tab hi dikhein jab user ne field ke saath interact kiya ho (focus → blur). Agar bina touched ke errors dikhane shuru kar do, toh form khulte hi saare fields red ho jayenge — user ne kuch type bhi nahi kiya aur error dikh raha hai. Yeh bad UX hai. Touched pattern se: form khula → sab clean → user field mein type karta hai → field chhodta hai (blur) → error dikhta hai (agar hai toh). Submit button pe touched set ho jata hai saare fields ke liye.
</details>

<details>
<summary>`e.preventDefault()` form submit mein kyun zaroori hai?</summary>

HTML forms ka default behavior hai — submit hone par page refresh karna aur form data ko URL ya server bhejna. React SPA (Single Page Application) mein yeh behavior undesired hai kyunki poora app reload ho jayega, state reset ho jayegi, aur user experience break ho jayega. `e.preventDefault()` browser ke is default behavior ko rokta hai, jisse hum form data ko JavaScript mein capture kar sakte hain, validation laga sakte hain, aur state update kar sakte hain bina page reload kiye.
</details>

<details>
<summary>Edit mode mein form ko existing data se fill karna — `initialData` prop kaise kaam karta hai?</summary>

`initialData` ek optional prop hai jo NoteForm component leta hai. Jab user "Edit" button click karta hai, parent component `setEditingNote(note)` call karta hai, aur NoteForm ko `initialData={editingNote}` pass karta hai. `useEffect` initialData change detect karta hai aur `setForm(initialData)` call karta hai — form automatically fill ho jata hai. Key prop (`key={editingNote?.id ?? "new"}`) ensure karta hai ki jab editingNote change ho, component re-mount ho (internal state reset). Submit button ka label bhi change ho jata hai "Add Note" → "Update Note".
</details>
