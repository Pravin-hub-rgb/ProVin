## Step 1 — The Visualizer Component

First, let's create a helper component that tracks render counts. This will be used inside every component.

**Let's try the intuitive approach first — increment a counter on every render:**

```tsx
// ❌ Won't work
export default function RenderCount({ label }: { label: string }) {
  let count = 0
  count++ // Local variable — resets to 0 on every render
  return <p>{label} rendered: {count} times</p>
}
```

`let count = 0` is inside the component function — it resets to `0` on every render. `count++` is useless. The count will always show 1.

**Try a module-level variable — outside the component:**

```tsx
// ❌ React 19 error
const counts: Record<string, number> = {}

export default function RenderCount({ label }: { label: string }) {
  counts[label] = (counts[label] ?? 0) + 1 // Error!
  return <p>{label} rendered: {counts[label]} times</p>
}
```

React 19 throws an error: *"Modifying a variable defined outside a component is not allowed."* React wants components to stay **pure** during the render phase — only read props and state, don't perform any side effects.

**Try useRef — persistent storage inside the component:**

```tsx
// ❌ React 19 error
import { useRef } from 'react'

export default function RenderCount({ label }: { label: string }) {
  const count = useRef(0)
  count.current++          // Error: Cannot access refs during render
  return <p>{label} rendered: {count.current} times</p>
}
```

React 19: *"Cannot access refs during render."* `ref.current` can only be accessed in event handlers or effects — not during render.

**Try useEffect — increment after render:**

```tsx
// ❌ Infinite loop
import { useEffect, useState } from 'react'

export default function RenderCount({ label }: { label: string }) {
  const [count, setCount] = useState(0)

  useEffect(() => {
    setCount(c => c + 1) // Effect → setState → re-render → effect → ...
  })

  return <p>{label} rendered: {count} times</p>
}
```

`useEffect` runs after every render. `setCount` changes state → the component re-renders → the effect runs again → `setCount` is called again → **infinite loop**. React crashes.

**So how do you track render counts in React 19?**

First, understand this: React's rendering happens in **two phases**.

### Phase 1: Render Phase (Creating the Blueprint)

When your component function is called and JSX is returned — React decides "what needs to change."

This is where **no side effects** (modifying variables, API calls, `console.log`) are allowed. React wants this phase to be **pure** — just read props/state and produce JSX.

If you modify a module-level variable during the render phase, React throws an error: *"Modifying a variable defined outside a component is not allowed."*

### Phase 2: Commit Phase (Actual Construction)

React has decided what needs to change. Now it updates the actual DOM. This is where side effects are allowed — `useEffect` runs here, and `Profiler`'s `onRender` callback runs here too.

### Analogy

Think of yourself as an architect:

| Phase | As an architect | As React |
|-------|-----------------|----------|
| **Render** | Draw the blueprint — decide what to build | Call the component function, get JSX |
| **Commit** | Actual construction — lay bricks, paint | Update the DOM, run effects |

While drawing the blueprint, you can't go breaking down walls (side effect). You can only do that during construction. React works the same way.

### The Solution

React has a built-in `Profiler` component with an `onRender` callback that fires in the **commit phase** — meaning the blueprint has already been drawn and actual construction is underway. You can safely modify module-level variables here:

```tsx
// ✅ React 19 compatible
import { Profiler } from 'react'

const counts: Record<string, number> = {}

export default function RenderCount({ label }: { label: string }) {
  return (
    <Profiler id={label} onRender={() => { counts[label] = (counts[label] ?? 0) + 1 }}>
      <div className="text-xs text-gray-400 mb-1">
        {label} rendered: {counts[label] ?? 0} times
      </div>
    </Profiler>
  )
}
```

Here's why no error is thrown:

| Step | Which Phase | What's happening |
|------|-------------|------------------|
| 1️⃣ | **Render** | Component function is called → `<div>` is evaluated → `{counts[label] ?? 0}` is **read** (not modified) ✅ |
| 2️⃣ | **Commit** | React inserts `<div>` into the DOM → `onRender` fires → `counts[label]++` is **modified** ✅ |

Two different phases — read during render, write during commit. React is happy.

**One small caveat:** The first render will display `0` because the commit phase hasn't happened yet (count hasn't been incremented). But as soon as any button is clicked — a new render is triggered — at which point `counts[label]` will be `1`, and the display will be accurate.

## Step 2 — Showing the Problem (Without Optimization)

Let's build the version without any optimizations first, so the problem is clearly visible:

```tsx
// App.tsx
import { useState } from 'react'
import RenderCount from './RenderCount'

function ExpensiveCard({ value }: { value: number }) {
  return (
    <div className="border p-4 rounded">
      <RenderCount label="ExpensiveCard" />
      <p>Value: {value}</p>
    </div>
  )
}

function Sidebar() {
  return (
    <div className="border p-4 rounded bg-gray-50">
      <RenderCount label="Sidebar" />
      <p>Sidebar — nothing changes here</p>
    </div>
  )
}

export default function App() {
  const [count, setCount] = useState(0)
  const [value, setValue] = useState(42)

  return (
    <div className="p-8 space-y-4">
      <RenderCount label="App" />
      
      <div className="space-x-2">
        <button onClick={() => setCount(c => c + 1)}>
          Re-render App ({count})
        </button>
        <button onClick={() => setValue(v => v + 1)}>
          Change Value ({value})
        </button>
      </div>

      <div className="flex gap-4">
        <ExpensiveCard value={value} />
        <Sidebar />
      </div>
    </div>
  )
}
```

Check the browser now. Click any button — all components are re-rendering:
- `App` — obviously, state changed
- `ExpensiveCard` — value didn't change, yet it's re-rendering
- `Sidebar` — nothing changed, yet it's re-rendering

## Step 3 — Add React.memo

Let's memoize `Sidebar` first — it has no props, so it should never re-render:

```tsx
// App.tsx
import { memo } from 'react'

const Sidebar = memo(function Sidebar() {
  return (
    <div className="border p-4 rounded bg-gray-50">
      <RenderCount label="Sidebar" />
      <p>Sidebar — nothing changes here</p>
    </div>
  )
})
```

Now let's also memoize `ExpensiveCard`:

```tsx
// App.tsx
interface ExpensiveCardProps {
  value: number
}

const ExpensiveCard = memo(function ExpensiveCard({ value }: ExpensiveCardProps) {
  return (
    <div className="border p-4 rounded">
      <RenderCount label="ExpensiveCard" />
      <p>Value: {value}</p>
    </div>
  )
})
```

Test now:

- First render — all render once
- Click "Re-render App" — only `App` renders. `ExpensiveCard` and `Sidebar` are skipped. See it? `value` didn't change, so memo skipped the render.
- Click "Change Value" — `App` re-renders, `ExpensiveCard` re-renders (because `value` changed), `Sidebar` is skipped.

## Step 4 — The Problem — Inline Function Breaks Memo

Now let's add an `onClick` prop to `ExpensiveCard` — like a real app would have event handlers. We see the full component here — along with the problem it creates:

```tsx
// App.tsx
import { memo, useState } from 'react'
import RenderCount from './RenderCount'

const ExpensiveCard = memo(function ExpensiveCard({
  value, onClick
}: {
  value: number
  onClick: () => void
}) {
  return (
    <div className="border p-4 rounded" onClick={onClick}>
      <RenderCount label="ExpensiveCard" />
      <button
        onClick={onClick}
        className="bg-red-500 text-white px-4 py-2 rounded m-2 cursor-pointer"
      >
        Expensive Card Click
      </button>
      <p>Value: {value}</p>
    </div>
  )
})

export default function App() {
  const [count, setCount] = useState(0)
  const [value, setValue] = useState(42)

  const handleClick = () => {                // ❌ New function on every render
    console.log('card clicked')
  }

  return (
    <div className="p-8 space-y-4">
      <RenderCount label="App" />

      <div className="space-x-2">
        <button onClick={() => setCount(c => c + 1)}>
          Re-render App ({count})
        </button>
        <button onClick={() => setValue(v => v + 1)}>
          Change Value ({value})
        </button>
      </div>

      <ExpensiveCard value={value} onClick={handleClick} />
      <Sidebar />
    </div>
  )
}
```

Click "Re-render App" — `ExpensiveCard` is re-rendering again! `Sidebar` is fine (nothing changed about it) but `ExpensiveCard`'s memo broke.

**Why?** `handleClick` is a regular function defined inside `App()`. Every time `App` re-renders, a new `handleClick` function is created in memory. New reference = new `onClick` prop = `Object.is(oldFn, newFn)` → false → memo re-renders.

Memo only skips the render when props have the **same** reference. Inline functions get a new reference on every render — memo is useless.

---

## Step 5 — Fix with useCallback

```tsx
// App.tsx
import { useCallback } from 'react'

const handleClick = useCallback(() => {
  console.log('card clicked')
}, []) // No dependencies — never changes
```

Test now — `ExpensiveCard` stops re-rendering. The function reference is stable.

## Step 6 — useMemo — Caching Derived Data

Now let's add a heavy calculation — a function that takes a lot of time:

```tsx
// App.tsx
function slowCalculation(num: number): number {
  console.log('⚡ slow calculation is running')
  let result = 0
  for (let i = 0; i < 10000000; i++) {
    result += num * i
  }
  return result
}

function App() {
  const [count, setCount] = useState(0)
  const [value, setValue] = useState(42)

  const computed = slowCalculation(value) // ❌ Runs on every render

  return (
    // ...
    <p>Computed: {computed}</p>
    // ...
  )
}
```

Every time "Re-render App" is clicked, `slowCalculation` runs — even though `value` hasn't changed. The browser freezes.

Fix with useMemo:

```tsx
const computed = useMemo(() => slowCalculation(value), [value])
```

Now `slowCalculation` only runs when `value` changes. Count change → cached result is used.

## Step 7 — Final Component Tree with All Optimizations

```tsx
import { useState, useMemo, useCallback, memo } from 'react'

const Sidebar = memo(function Sidebar() {
  return (
    <div className="border p-4 rounded bg-gray-50">
      <RenderCount label="Sidebar" />
      <p>Sidebar — static content</p>
    </div>
  )
})

const ExpensiveCard = memo(function ExpensiveCard({
  value, onClick
}: {
  value: number
  onClick: () => void
}) {
  return (
    <div className="border p-4 rounded" onClick={onClick}>
      <RenderCount label="ExpensiveCard" />
      <p>Value: {value}</p>
    </div>
  )
})

export default function App() {
  const [count, setCount] = useState(0)
  const [value, setValue] = useState(42)

  const handleClick = useCallback(() => {
    console.log('card clicked')
  }, [])

  const computed = useMemo(() => {
    console.log('⚡ heavy calculation')
    let result = 0
    for (let i = 0; i < 10000000; i++) result += value * i
    return result
  }, [value])

  return (
    <div className="p-8 space-y-4">
      <button onClick={() => setCount(c => c + 1)}>
        Re-render App ({count})
      </button>
      <button onClick={() => setValue(v => v + 1)}>
        Change Value ({value})
      </button>
      <p>Computed: {computed}</p>
      <ExpensiveCard value={value} onClick={handleClick} />
      <Sidebar />
    </div>
  )
}
```

Check the render counts:

| Action | App | ExpensiveCard | Sidebar | slowCalculation |
|--------|-----|---------------|---------|-----------------|
| Initial render | 1 | 1 | 1 | ran |
| Re-render App | 2 | 1 (skip) | 1 (skip) | didn't run |
| Change Value | 3 | 2 | 1 (skip) | ran (value changed) |
| Re-render App | 4 | 2 (skip) | 1 (skip) | didn't run |
