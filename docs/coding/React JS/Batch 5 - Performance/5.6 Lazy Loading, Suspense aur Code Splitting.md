## What We've Covered So Far

In 5.5, we learned `useReducer` — managing complex state in one central function.

Now let's talk about **app load time** — when the app grows, the bundle gets big, and the user waits longer for it to load. The solution: code splitting.

---

## The Problem — Everything in One Bundle

When Vite or Webpack builds, all the code gets bundled into one (or a few) JavaScript files. Even if the user only wants to see the login page — the entire app's code gets downloaded.

Think of an app with:
- Dashboard (heavy charts)
- User Profile (large form)
- Analytics (complex tables)
- Settings

The user opens the login page — but the browser downloads code for Dashboard, Profile, and Analytics too. Unnecessary. Longer load time. Bad user experience.

**Why is this a problem?** The bundler packs everything together. There's no concept of "this component isn't needed right now, download it later" — until you use code splitting.

---

## Code Splitting — What It Is

Code splitting means breaking the bundle into smaller chunks. Each chunk loads only when it's actually needed.

Two benefits:
1. **Faster initial load** — only the code for what the user sees right now is downloaded
2. **On-demand loading** — other chunks load later, when the user navigates to that page or feature

---

## React.lazy + Suspense — What They Are

`React.lazy` is a function that makes a component "lazy" — its code only downloads when the component actually renders, not before.

`Suspense` is a component that handles the "loading state" — when a lazy component is loading, its fallback is displayed.

Syntax:

```tsx
const LazyComponent = React.lazy(() => import('./HeavyComponent'))

// Use with Suspense:
<Suspense fallback={<p>Loading...</p>}>
  <LazyComponent />
</Suspense>
```

**What's happening internally?** `React.lazy()` takes a function that returns a dynamic `import()`. When `LazyComponent` is rendered, React internally calls `import()`. Download starts. Since `LazyComponent` is inside `Suspense` — the loading fallback is shown. Download completes → the component renders.

Visual mapping:

```
User clicks "Show Chart"
    │
    ▼
LazyComponent renders
    │
    ├── Chunk already loaded?
    │   ├── Yes → Render immediately
    │   └── No → Show Suspense fallback, start download
    │
    ▼
Chunk downloaded
    │
    ▼
Component renders, Suspense fallback disappears
```

## Minimal Code — A Lazy Component

```tsx
import { lazy, Suspense, useState } from 'react'

// Lazy import — HeavyChart goes into a separate chunk
const HeavyChart = lazy(() => import('./HeavyChart'))

export default function Dashboard() {
  const [showChart, setShowChart] = useState(false)

  return (
    <div>
      <button onClick={() => setShowChart(true)}>
        Show Chart
      </button>

      {showChart && (
        <Suspense fallback={<div className="p-4 text-gray-500">Chart is loading...</div>}>
          <HeavyChart />
        </Suspense>
      )}
    </div>
  )
}
```

```tsx
// HeavyChart.tsx — this becomes its own chunk
export default function HeavyChart() {
  return <div>{/* Heavy chart rendering */}</div>
}
```

Open the browser's Network tab. Click the button — you'll see a new `.js` file download. That's the `HeavyChart` chunk. It wasn't downloaded before — it loads on demand, right when it's needed.

---

## Flow — What Happens When You Click the Button

1. `showChart` state becomes `true`
2. React tries to render `HeavyChart`
3. `React.lazy` triggers — an internal `import()` call starts
4. The browser downloads the `HeavyChart` chunk
5. React shows the Suspense fallback (loading text)
6. Download completes → Suspense fallback is removed → `HeavyChart` renders

## Building Up — Route-Level Splitting

In a real app, you split at the route level — each route gets its own chunk:

```tsx
import { lazy, Suspense } from 'react'
import { BrowserRouter, Routes, Route, Link } from 'react-router-dom'

const Home = lazy(() => import('./routes/Home'))
const Dashboard = lazy(() => import('./routes/Dashboard'))
const Analytics = lazy(() => import('./routes/Analytics'))
const Settings = lazy(() => import('./routes/Settings'))

export default function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/dashboard">Dashboard</Link>
        <Link to="/analytics">Analytics</Link>
        <Link to="/settings">Settings</Link>
      </nav>

      <Suspense fallback={<div className="p-8 text-center">Page is loading...</div>}>
        <Routes>
          <Route path="/" element={<Home />} />
          <Route path="/dashboard" element={<Dashboard />} />
          <Route path="/analytics" element={<Analytics />} />
          <Route path="/settings" element={<Settings />} />
        </Routes>
      </Suspense>
    </BrowserRouter>
  )
}
```

Now each route is in its own chunk. The user opens `/` — only the Home chunk downloads. Navigate to `/dashboard` — only then the Dashboard chunk downloads. Initial load is fast.

---

## When to Use Lazy Loading — And When Not To

**❌ Don't use lazy loading when:**
- The component is small — the overhead of lazy loading outweighs the benefit
- The component is needed on the initial render — lazy just adds unnecessary delay
- In SSR environments — `React.lazy` doesn't work server-side

**✅ Use lazy loading when:**
- Heavy components (charts, rich text editors, image editors)
- Routes the user visits later
- Conditional components (modals, drawers, tab content)
- Third-party libraries that are heavy (like `moment.js`, `lodash`)

---

## Common Mistake — Forgetting Suspense

A lazy component must be used inside `Suspense`, or you get an error:

```tsx
// ❌ Wrong — no Suspense
const HeavyChart = lazy(() => import('./HeavyChart'))
function App() {
  return <HeavyChart /> // Error: A component suspended while rendering
}

// ✅ Correct — wrap in Suspense
function App() {
  return (
    <Suspense fallback={<p>Loading...</p>}>
      <HeavyChart />
    </Suspense>
  )
}
```
