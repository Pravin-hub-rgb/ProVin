## Abhi Tak Kya Hua

5.1 mein React.memo seekha — component ko cache karta hai, props same hain toh render skip. Lekin ek problem thi — inline objects har render pe naya reference banate hain, memo kaam nahi karta.

Ab baat karte hain **values** cache karne ki.

---

## Problem — Unrelated State Change → Unnecessary Calculation

Ek component lo jisme do alag states hain — ek `search` aur ek `count`. Yeh dono ek doosre se unrelated hain:

```tsx
function Dashboard({ items }: { items: number[] }) {
  const [search, setSearch] = useState('')
  const [count, setCount] = useState(0)

  const filteredItems = items.filter(item => {
    console.log('filter chal raha hai')
    return item.toString().includes(search)
  })

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>Increment</button>
      <input value={search} onChange={e => setSearch(e.target.value)} />
      <ul>
        {filteredItems.map(item => <li key={item}>{item}</li>)}
      </ul>
    </div>
  )
}
```

Ab do scenarios hain:

**Scenario 1 — Input type karo:** `search` change hota hai → component re-render → `filter` chalta hai. Yeh sahi hai — search badla, toh filtered list bhi badalni chahiye.

**Scenario 2 — Count button click karo:** Sirf `count` change hota hai → component re-render → lekin `filter` **bhi** chal raha hai! Console mein "filter chal raha hai" print ho raha hai.

Yeh unnecessary hai. Count ka filter se kya lena-dena? `search` aur `items` toh change nahi hue.

**Yeh problem kyun hai?** React ko nahi pata ki `items.filter` ka `count` se koi relation nahi. React har render pe component function top-to-bottom execute karta hai. `filter` line bhi execute hoti hai — chahe zaroorat ho ya nahi.

Agar `items` array 10,000 ka hai, toh har count increment pe 10,000 items dobara filter ho rahe hain. Bilkul waste.

## useMemo — Kya Hai

`useMemo` ek hook hai jo **value** ko cache (memoize) karta hai. Dependency array mein di hui values tab tak same hain, tab tak useMemo pichli cached value return karta hai — calculation dobara nahi hoti.

Syntax:

```tsx
const cachedValue = useMemo(
  () => computeExpensiveValue(input),
  [input] // dependencies
)
```

**Kya hota hai internally?** Pehle render pe useMemo ka callback function call hota hai, result cache hota hai. Agle renders pe — dependencies check hoti hain. Agar same hain (kyun React `Object.is` use karta hai) — toh callback call nahi hota, cached value return hoti hai. Agar koi dependency change hui — callback dobara call hota hai, naya result cache hota hai.

Visual mapping:

```
Render trigger
    │
    ▼
useMemo(() => compute, [items, search])
    │
    ├── items === oldItems && search === oldSearch?
    │   └── Yes → Return cached value (no compute)
    │
    └── No → Call compute(), cache new value, return it
```

## React.memo vs useMemo — Fundamental Difference

Dono mein "memo" hai, isliye confuse hona natural hai. Lekin yeh dono different levels pe kaam karte hain:

| | React.memo (5.1) | useMemo (5.2) |
|---|---|---|
| **Kya target hai?** | Component | Value (calculation result) |
| **Kya hai?** | Higher-Order Component (HOC) | Hook |
| **Kya prevent kare?** | Component ka re-render | Calculation ka re-execution |
| **Kya check kare?** | Props change hue ya nahi | Dependencies change hui ya nahi |
| **Syntax** | `memo(Component)` | `useMemo(() => val, [deps])` |

**React.memo** — component-level optimization. "Props nahi badle → is component ko dubara render mat karo."

**useMemo** — value-level optimization. "Dependencies nahi badli → yeh calculation dubara mat chalao, purani cached value de do."

Toh short answer:
- **Variable / calculation cache karni hai?** → `useMemo`
- **Component ko unnecessary re-render se bachana hai?** → `React.memo`
- **Dono ek saath?** — React.memo component rokta hai, useMemo stable reference deta hai taaki React.memo ka `Object.is` comparison sahi kaam kare.

## Minimal Code — Filter Ko Cache Karo

UseMemo se fix karte hain. UseMemo hook batata hai — "yeh calculation sirf tab chalao jab yeh dependencies change hon":

```tsx
import { useState, useMemo } from 'react'

function Dashboard({ items }: { items: number[] }) {
  const [search, setSearch] = useState('')
  const [count, setCount] = useState(0)

  const filteredItems = useMemo(
    () => {
      console.log('filter chal raha hai')
      return items.filter(item => item.toString().includes(search))
    },
    [items, search]
  )

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>Increment</button>
      <input value={search} onChange={e => setSearch(e.target.value)} />
      <ul>
        {filteredItems.map(item => <li key={item}>{item}</li>)}
      </ul>
    </div>
  )
}
```

**Ab console dekh:**

| Action | Filter Chala? | Kyun? |
|--------|--------------|-------|
| Count button click | ❌ Nahi | `items` same, `search` same → cached value reuse |
| Input mein type karo | ✅ Haan | `search` change → dependency change → filter run |

Pehle **count button** click karo — console mein kuch print nahi hoga. Filter nahi chala. Kyunki useMemo ne check kiya: `[items, search]` dono same hain pichli render se — cached `filteredItems` return kar diya.

Ab **input mein kuch type** karo — console mein "filter chal raha hai" print hoga. Kyunki `search` change hua → dependency list mein change → React ne filter dobara call kiya.

Yeh hai useMemo ka asli fayda: heavy calculation sirf tab chalao jab uski dependencies actually change hui hain. Baaki re-renders pe cached result do.

## Flow — Do Scenarios: Count Click vs Input Type

**Scenario A — Count Button Click (unrelated state change):**
1. `count` state change hota hai
2. `Dashboard` re-render trigger hota hai
3. useMemo line execute hoti hai
4. React dependencies check karta hai: `items` same? haan. `search` same? haan.
5. Koi dependency change nahi hui → callback call nahi hota
6. Cached `filteredItems` return hota hai — koi calculation nahi
7. Component render hota hai — UI mein count update, list waisi ki waisi

**Scenario B — Input Type (relevant dependency change):**
1. `search` state change hota hai
2. `Dashboard` re-render trigger hota hai
3. useMemo line execute hoti hai
4. React dependencies check karta hai: `items` same hai, `search` change hua
5. Dependency change hui → callback call hota hai → naya `filteredItems` calculate hota hai
6. Component naye filteredItems ke saath render hota hai

## useMemo vs Direct Code

Direct code har render pe chalta hai:

```tsx
const result = slowFunction(data)  // har render pe call
```

useMemo sirf tab chalta hai jab dependencies change hon:

```tsx
const result = useMemo(() => slowFunction(data), [data])  // sirf data change pe call
```

## useMemo + React.memo Combo

5.1 mein `React.memo` seekha — component ko cache karta hai. Props same hoon toh render skip. Lekin problem thi — inline objects/arrays har render pe naya reference banate hain, `Object.is` false hota hai, memo re-render karta hai.

Yahan `useMemo` kaam aata hai — object/array reference ko stable banane ke liye.

### ❌ Pehle — Inline Object, Memo Useless

```tsx
import { memo, useState } from 'react'

const Profile = memo(function Profile({ user }: { user: { name: string; age: number } }) {
  console.log('Profile render')
  return <div>{user.name}</div>
})

export default function App() {
  const [count, setCount] = useState(0)
  const user = { name: 'Vin', age: 25 } // ❌ Har render pe naya object

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
      <Profile user={user} />
    </div>
  )
}
```

Ab count click karo — `Profile` bhi render ho raha hai. Kyun? `{ name: 'Vin', age: 25 }` har render pe naya reference. `Object.is(oldUser, newUser)` → false → memo re-render.

### ✅ Baad Mein — useMemo Se Stable Reference

```tsx
import { memo, useState, useMemo } from 'react'

const Profile = memo(function Profile({ user }: { user: { name: string; age: number } }) {
  console.log('Profile render')
  return <div>{user.name}</div>
})

export default function App() {
  const [count, setCount] = useState(0)
  const user = useMemo(() => ({ name: 'Vin', age: 25 }), []) // ✅ Ek baar object bana, cache kar liya

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
      <Profile user={user} />
    </div>
  )
}
```

Ab count click — `App` render, `Profile` render nahi. `useMemo` ne ek baar object banaya, har render pe wahi reference return kiya. `Object.is` → true → memo skip.

Chain:
```
Inline object → naya reference → Object.is false → memo useless ❌
useMemo → stable reference → Object.is true → memo works ✅
```

## Kab useMemo Lagao, Kab Nahi

**❌ Mat lagao jab:**
- Calculation trivial ho (sum, simple map/filter on small array)
- Component rarely re-render hota ho
- Premature optimization — pehle measure karo

**✅ Lagao jab:**
- Heavy calculation ho (large array operations, complex math)
- Referential stability chahiye (objects/arrays pass kar rahe ho memo'd components ko)
- Derived state jo baar baar calculate ho raha ho unnecessarily

---

## Common Mistake — Har Cheez useMemo Mein Daal Dena

```tsx
// ❌ Unnecessary — simple cheez
const doubled = useMemo(() => count * 2, [count])

// ✅ Direct — itna trivial hai, useMemo ka overhead hi zyada hai
const doubled = count * 2
```

useMemo ka bhi ek overhead hai — dependency array create karna, compare karna. Trivial calculations ke liye direct code better hai.

---

## Summary

✅ **useMemo** — value cache karta hai — expensive calculations ke liye  
✅ Dependency array change nahi hua → cached value, koi calculation nahi  
✅ Dependency change hui → dobara calculate, cache update  
✅ React.memo ke saath combo — stable object references pass karne ke liye  
✅ Don't over-use — trivial calculations ke liye zaroori nahi  
✅ Pehle Profiler se measure karo, phir optimize karo
