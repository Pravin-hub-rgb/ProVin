# 5.2 useMemo — Expensive Calculations Cache Karna

---

## Abhi Tak Kya Hua

5.1 mein React.memo seekha — component ko cache karta hai, props same hain toh render skip. Lekin ek problem thi — inline objects har render pe naya reference banate hain, memo kaam nahi karta.

Ab baat karte hain **values** cache karne ki.

---

## Problem — Har Render Pe Expensive Calculation

Ek simple example:

```tsx
function Dashboard({ items }: { items: number[] }) {
  const [search, setSearch] = useState('')

  // Imagine karo — yeh function heavy hai
  const filteredItems = items.filter(item => {
    console.log('filter chal raha hai')
    return item.toString().includes(search)
  })

  return (
    <div>
      <input value={search} onChange={e => setSearch(e.target.value)} />
      <ul>
        {filteredItems.map(item => <li key={item}>{item}</li>)}
      </ul>
    </div>
  )
}
```

Notice kiya? Har baar input change → `search` state change → component re-render → `filter` dobara chal raha hai.

Lekin — agar `items` array change nahi hua aur `search` bhi wahi hai toh filter dobara chalna unnecessary hai. Agar items 10,000 hain toh har keystroke pe 10,000 items filter ho rahe hain.

**Yeh problem kyun hai?** React har render pe component function call karta hai. Andar jo bhi code hai — woh har baar execute hota hai. React automatically nahi jaanta ki "yeh calculation pehle bhi ho chuki hai, same result hai."

---

## useMemo — Kya Hai

`useMemo` ek hook hai jo **value** ko cache (memoize) karta hai. Dependency array mein di hui values tab tak same hain, tab tak useMemo pichli cached value return karta hai — calculation dobara nahi hoti.

Syntax:

```tsx
const cachedValue = useMemo(
  () => computeExpensiveValue(input),
  [input] // dependencies
)
```

**Kya hota hai internally?** Pehle render pe useMemo ka callback function call hota hai, result cache hota hai. Agle renders pe — dependencies check hoti hain. Agar same hain (kyun React `Object.is` use karta hai) — toh callback call nahi hota, cached value return hoti hai. Agar koi dependency change hui — callback dobara call hota hai, naya result cache hota hai.

---

## Minimal Code — Filter Ko Cache Karo

UseMemo se fix karte hain:

```tsx
import { useState, useMemo } from 'react'

function Dashboard({ items }: { items: number[] }) {
  const [search, setSearch] = useState('')

  const filteredItems = useMemo(
    () => {
      console.log('filter chal raha hai')
      return items.filter(item => item.toString().includes(search))
    },
    [items, search]
  )

  // Jab tak items aur search same hain — filter dobara nahi chalega

  return (
    <div>
      <input value={search} onChange={e => setSearch(e.target.value)} />
      <ul>
        {filteredItems.map(item => <li key={item}>{item}</li>)}
      </ul>
    </div>
  )
}
```

Ab console dekh — pehli render pe "filter chal raha hai" print hoga. Agli render pe agar `items` aur `search` dono same hain toh filter nahi chalega.

Agar search change kiya → dependency change hui → filter dobara chalega. Lekin agar koi aur state change hui (jo search ko affect nahi karti) → filter nahi chalega kyunki dependencies same hain.

---

## useMemo vs Direct Code

Direct code har render pe chalta hai:

```tsx
const result = slowFunction(data)  // har render pe call
```

useMemo sirf tab chalta hai jab dependencies change hon:

```tsx
const result = useMemo(() => slowFunction(data), [data])  // sirf data change pe call
```

## useMemo + React.memo Combo

5.1 mein problem thi — inline objects se memo kaam nahi karta. useMemo se fix:

```tsx
const user = useMemo(() => ({ name: 'Vin', age: 25 }), [])
// Ab user ka reference tab tak same rahega jab tak component unmount na ho

return <Profile user={user} />
// Profile memo hai — ab kaam karega kyunki user reference same hai
```

## Coder's Perspective Flow

### 1. Concept
`useMemo` ek function ka result cache karta hai. Dependency array change nahi hua → cached result do. Change hua → dobara calculate karo.

### 2. Syntax
```tsx
const value = useMemo(() => compute(), [dep1, dep2])
```

### 3. Visual Mapping
```
Render trigger
    │
    ▼
useMemo(() => compute, [items, search])
    │
    ├── items === oldItems && search === oldSearch?
    │   └── Yes → Return cached value (no compute)
    │
    └── No → Call compute(), cache new value, return it
```

### 4. Minimal Code
Wahi filter example upar hai — useMemo se filter sirf tab chal raha hai jab zaroori ho.

### 5. Flow — Jab User Input Me Type Karta Hai
1. `search` state change hota hai
2. `Dashboard` re-render trigger hota hai
3. useMemo line execute hoti hai
4. React dependencies compare karta hai: `items` same hai, `search` change hua
5. Dependency change hui → callback call hota hai → naya `filteredItems` calculate hota hai
6. Component naye filteredItems ke saath render hota hai

### 6. Build Up — Sorting + Filtering Combo

```tsx
function ProductList({ products }: { products: Product[] }) {
  const [sortBy, setSortBy] = useState('name')
  const [maxPrice, setMaxPrice] = useState(1000)

  const processed = useMemo(() => {
    const filtered = products.filter(p => p.price <= maxPrice)
    return filtered.sort((a, b) => {
      if (sortBy === 'name') return a.name.localeCompare(b.name)
      return a.price - b.price
    })
  }, [products, sortBy, maxPrice])

  // Sirf tab chalega jab products, sortBy, ya maxPrice change ho
  return <div>{/* render processed items */}</div>
}
```

## Kab useMemo Lagao, Kab Nahi

**❌ Mat lagao jab:**
- Calculation trivial ho (sum, simple map/filter on small array)
- Component rarely re-render hota ho
- Premature optimization — pehle measure karo

**✅ Lagao jab:**
- Heavy calculation ho (large array operations, complex math)
- Referential stability chahiye (objects/arrays pass kar rahe ho memo'd components ko)
- Derived state jo baar baar calculate ho raha ho unnecessarily

---

## Common Mistake — Har Cheez useMemo Mein Daal Dena

```tsx
// ❌ Unnecessary — simple cheez
const doubled = useMemo(() => count * 2, [count])

// ✅ Direct — itna trivial hai, useMemo ka overhead hi zyada hai
const doubled = count * 2
```

useMemo ka bhi ek overhead hai — dependency array create karna, compare karna. Trivial calculations ke liye direct code better hai.

---

## Summary

✅ **useMemo** — value cache karta hai — expensive calculations ke liye  
✅ Dependency array change nahi hua → cached value, koi calculation nahi  
✅ Dependency change hui → dobara calculate, cache update  
✅ React.memo ke saath combo — stable object references pass karne ke liye  
✅ Don't over-use — trivial calculations ke liye zaroori nahi  
✅ Pehle Profiler se measure karo, phir optimize karo

## Agla Step

UseMemo ne values cache karna sikha diya. Lekin functions ka kya? Har render pe naya function reference = memo useless. Iska solution hai **`useCallback`**. Woh 5.3 mein.
