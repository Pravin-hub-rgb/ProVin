
## MCQ

Q: What is React's default behavior when a parent component re-renders?
A. The child also re-renders along with the parent — this is React's default behavior
B. The child's render is skipped if props haven't changed — React tracks this internally
C. Only the parent renders, the child stays untouched — React is smart by default
D. The browser decides whether the child should render or not — React just suggests

> A. React's default behavior is parent renders → child renders. React doesn't know whether the child's props changed or not — it just renders. B is wrong — React doesn't check props by default. C is wrong — the child does re-render. D is wrong — the browser has nothing to do with render decisions.

---

Q: What is a Higher-Order Component (HOC) in React?
A. A function that takes a component and returns a new enhanced component — like gift wrapping
B. A built-in hook that manages a component's lifecycle — it's built-in like useState
C. A component class that renders other components — works like a layout wrapper
D. A function that directly modifies HTML elements — DOM manipulation utility

> A. An HOC is a function that takes a component, adds some extra functionality, and returns a new component. B is wrong — an HOC is not a hook and doesn't manage lifecycle. C is wrong — that's a class component, a different thing than an HOC pattern. D is wrong — HOC doesn't directly modify the DOM.

Q: What does React.memo do?
A. It memoizes a component — skips render if props haven't changed
B. It records a component's state changes — keeps a log of every update
C. It stores a component in the browser cache — preserves data across page reloads
D. It converts a component's JSX to plain HTML — reduces bundle size

> A. Memo "remembers" a component. On parent re-renders, memo checks — did this component's props change since last time? If not, skip the render, return cached output. B is wrong — memo doesn't log anything. C is wrong — it has nothing to do with browser cache. D is wrong — memo doesn't convert JSX to HTML.

---

Q: Which method does React.memo use internally to compare props?
A. `Object.is` — value or reference comparison, JavaScript's built-in method
B. `JSON.stringify` — converts the whole object to a string and compares
C. `deepEqual` — recursively compares nested objects
D. `===` — strict equality operator, JavaScript's default comparison

> A. React.memo internally uses `Object.is` to compare props. For primitives it does value comparison, for objects it does reference comparison. B is wrong — `JSON.stringify` is slow and order-sensitive. C is wrong — React doesn't do deep comparison. D is wrong — it's `Object.is`, not `===`.

---

Q: How does memo work with primitive props (string, number, boolean)?
A. Direct value comparison — if the value is the same, the render is skipped
B. Reference comparison — checks the memory address of both
C. Deep comparison — recursively checks nested values too
D. No comparison at all — always renders regardless of what happens

> A. With primitives, React directly compares values — `"name" === "name"` or `25 === 25`. Same value = render skipped. B is wrong — reference comparison is for objects/arrays. C is wrong — deep comparison isn't done. D is wrong — memo does compare, it doesn't just render blindly.

---

Q: Why does comparing two objects with identical contents return false using `Object.is`?
A. It compares memory addresses, not the values inside — each object gets a unique address
B. The object's content is compared, but a mismatch in key order causes false
C. The object's type is compared — if the type matches, it returns true
D. The object's length is compared — if the length matches, it returns true

> A. JavaScript objects, arrays, and functions each get a unique address in memory. `Object.is` compares those addresses, not the contents. B is wrong — content isn't compared. C is wrong — type isn't what's checked. D is wrong — length has no role here.

---

Q: If an inline arrow function is passed as a prop like `<Child onClick={() => handleClick()} />`, will memo work?
A. No — each render creates a new function reference, making memo useless
B. Yes — memo performs deep comparison on functions, same logic means it will skip
C. No — memo only works with primitive props, not functions
D. Yes — React auto-stabilizes inline functions, so memo works fine

> A. The arrow function creates a new function object on every render — a new reference, a new memory address. `Object.is` sees the new address and thinks "props changed" — it will render. B is wrong — memo doesn't do deep comparison. C is wrong — memo works with functions as long as the reference is stable. D is wrong — React doesn't auto-stabilize inline functions.

---

Q: What is the problem with the children prop and memo?
A. Each render creates a new React element object — a new reference, memo will re-render
B. Memo doesn't check the children prop at all — it always renders regardless
C. The children prop only accepts strings — so memo's comparison doesn't apply
D. Comparing the children prop is impossible — React throws an error

> A. `children` is also a prop. JSX gets converted to `React.createElement` — each render creates a new element, a new reference. Memo's `Object.is` check sees the new reference and thinks "props changed" → it renders. B is wrong — memo doesn't ignore it, the problem is the reference. C is wrong — children can be anything. D is wrong — no error, memo just renders.

Q: When should you apply React.memo?
A. When the component is heavy and receives the same props repeatedly
B. When the component is trivial — a simple span or div
C. When the component always receives different props — something new every render
D. When the component is only a class component — not for functional components

> A. Apply memo when the component is heavy (charts, tables, lists) and receives the same props over and over. First, measure with the Profiler to confirm it actually makes a difference. B is wrong — applying memo to trivial components is a waste. C is wrong — if props always change, memo is useless. D is wrong — memo is for functional components; for class components, there's PureComponent.

---

Q: Which statement about React.memo is correct?
A. Memo only skips render when props are the same — if any prop changes, it will render normally
B. Once you wrap a component in memo, it will never re-render again — it always returns cached output
C. Memo completely prevents a component from re-rendering — one render is enough forever
D. Memo only works in development mode — React ignores it in production

> A. Memo is not a "magic bullet." It only skips the render when props are the same. If any prop changes, memo renders normally. B is wrong — this is the most common misconception. C is wrong — changed props trigger a render. D is wrong — memo works in production too.

## TrueFalse

Q: React.memo is a built-in higher-order component.
- True
- False
> True. React.memo is a built-in HOC — it takes a component and returns a new wrapped component that does props comparison. Other HOCs (like Redux's `connect()`) are patterns that developers create themselves.

---

Q: React.memo internally uses the `Object.is` method to compare props.
- True
- False
> True. React.memo internally uses `Object.is` to compare props. For primitives it does value comparison, for objects it does reference comparison. If they're the same, the render is skipped. If they're different, it renders.

---

Q: Passing inline objects or arrays as props means React.memo will always skip the render because the values remain the same.
- True
- False
> False. Inline objects or arrays create a new reference (memory address) on every render. `Object.is` sees the new reference — it thinks "props changed" — and renders. The fact that values are the same doesn't matter.

---

Q: In React, React.memo is the only built-in higher-order component; all other HOCs are patterns that developers create themselves.
- True
- False
> True. React.memo is the only built-in HOC. `connect()` (Redux), `withRouter()` — these are patterns, not built-in component types. In React, there are only two built-in component types: functional and class.

---

Q: Wrapping a component in memo means it will never re-render.
- True
- False
> False. This is the most common misconception. Memo only skips the render when props are the same. If any prop changes, the component renders normally. Memo is not a "magic bullet" that stops all re-renders.

---

Q: With the children prop, React.memo won't skip the render because each render creates a new React element object.
- True
- False
> True. `children` is also a prop. `React.createElement` creates a new element object on every render. New reference = `Object.is` returns false = memo renders. That's why passing children to a memo'd component generally doesn't help.
