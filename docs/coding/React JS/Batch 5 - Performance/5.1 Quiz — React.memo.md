# 5.1 Quiz — React.memo

## MCQ

Q: React ka default behavior kya hai jab parent component re-render hota hai?
A. Parent ke saath child bhi re-render hota hai — React default behavior hai
B. Child ka render skip hota hai agar props nahi badle — React internally track karta hai
C. Sirf parent render hota hai, child untouched rehta hai — React smart hai default mein
D. Browser decide karta hai child render kare ya nahi — React bas suggestion deta hai
> A. React ka default behavior parent render → child render hai. React ko nahi pata ki child ke props change hue ya nahi, woh bas render kar deta hai. B galat — React default mein props nahi check karta. C galat — child bhi re-render hota hai. D galat — browser ka render decision se koi lena dena nahi.

---

Q: Higher-Order Component (HOC) React mein kya hota hai?
A. Function jo component lekar naya enhanced component return kare — gift wrapping jaisa pattern
B. Built-in hook jo component ki lifecycle manage kare — useState ki tarah built-in hai
C. Component class jo doosre components ko render kare — layout wrapper ki tarah kaam karta hai
D. Function jo HTML elements ko directly modify kare — DOM manipulation utility hai
> A. HOC ek function hai jo component leta hai, extra functionality add karta hai, aur naya component return karta hai. B galat — HOC hook nahi hai, lifecycle manage nahi karta. C galat — class component alag cheez hai, HOC pattern hai. D galat — HOC DOM directly modify nahi karta.

---

Q: React.memo ka kya kaam hai?
A. Component ko memoize karta hai — props na badle to render skip karta hai
B. Component ke state changes ko record karta hai — har update ka log rakhata hai
C. Component ko browser cache mein store karta hai — page reload pe data bachata hai
D. Component ke JSX ko plain HTML mein convert karta hai — bundle size ghatata hai
> A. Memo component ko "yaad" rakhta hai. Parent re-render pe memo check karta hai — kya props pichli baar se change hue? Agar nahi, to render skip, cached output do. B galat — memo state record nahi karta. C galat — browser cache se koi lena dena nahi. D galat — memo JSX-HTML conversion nahi karta.

---

Q: React.memo internally props compare karne ke liye kaunsa method use karta hai?
A. `Object.is` — value ya reference comparison, JavaScript ka built-in method
B. `JSON.stringify` — poora object string mein convert karke compare karta hai
C. `deepEqual` — nested objects ko recursively compare karta hai
D. `===` — strict equality operator, JavaScript ka default comparison
> A. React.memo internally `Object.is` use karta hai. Primitives ke liye value compare, objects ke liye reference compare. B galat — `JSON.stringify` slow hai aur order-sensitive. C galat — React deep comparison nahi karta. D galat — `===` nahi, `Object.is` use hota hai jo edge cases handle karta hai.

---

Q: Primitive props (string, number, boolean) ke saath memo kaise kaam karta hai?
A. Direct value comparison karta hai — same value hai to render skip ho jata hai
B. Reference comparison karta hai — memory address check karta hai dono ka
C. Deep comparison karta hai — nested values bhi recursively check karta hai
D. Koi comparison nahi karta — hamesha render kar deta hai chahe kuch bhi ho
> A. Primitives ke saath React directly value compare karta hai — `"name" === "name"` ya `25 === 25` ki tarah. Same value = render skip. B galat — reference comparison objects/arrays ke saath hota hai. C galat — deep comparison nahi karta. D galat — memo bina comparison ke kaam nahi karta.

---

Q: Do objects jinki values same hain, unka `Object.is` comparison false kyun deta hai?
A. Memory address compare hota hai, values nahi — har object ka alag address hota hai
B. Object ka content compare hota hai, lekin order mismatch ki wajah se false aata hai
C. Object ka type compare hota hai — same type hai to true return karta hai
D. Object ki length compare hoti hai — same length hai to true return hota hai
> A. JavaScript objects/arrays/functions ko memory mein ek unique address milta hai. `Object.is` woh address compare karta hai, andar ki values nahi. B galat — content compare nahi hota. C galat — type sirf compare nahi hota. D galat — length ka koi role nahi.

---

Q: Agar inline arrow function prop mein bheja jaye `<Child onClick={() => handleClick()} />` to memo kaam karega?
A. Nahi — har render pe naya function reference banta hai, memo useless ho jata hai
B. Haan — memo functions ka deep comparison karta hai, same logic hai to skip karega
C. Nahi — memo sirf primitive props ke saath kaam karta hai, functions ke saath nahi
D. Haan — React inline functions ko auto-stabilize karta hai, memo properly kaam karega
> A. Arrow function har render pe naya function object bana raha hai — naya reference, naya memory address. `Object.is` naya address dekhega aur sochega "props change hue" — render karega. B galat — memo deep comparison nahi karta. C galat — memo functions ke saath bhi kaam karta hai agar reference stable ho. D galat — React inline functions ko auto-stabilize nahi karta.

---

Q: Children prop ke saath memo ka problem kya hai?
A. Har render pe naya React element object banta hai — naya reference, memo render karega
B. Children prop ko memo check hi nahi karta — hamesha render hota hai chahe kuch bhi ho
C. Children prop sirf strings leta hai — isliye memo ka comparison kaam nahi karta
D. Children prop ko compare karna impossible hai — React error throw kar deta hai
> A. `children` bhi ek prop hai. JSX `React.createElement` mein convert hota hai — har render pe naya object, naya reference. Memo `Object.is` check karega aur sochega "props change hue" → render. B galat — memo ignore nahi karta, problem reference ka hai. C galat — children kuch bhi ho sakta hai. D galat — error nahi aati, bas memo render karega.

---

Q: React.memo kab lagana chahiye?
A. Jab component heavy ho aur same props baar baar aa rahe ho
B. Jab component trivial ho — ek simple span ya div ho
C. Jab component hamesha different props leta ho — har render pe kuch naya
D. Jab component sirf class component ho — functional components ke liye nahi
> A. Memo tab lagao jab component heavy ho (charts, tables, lists) aur baar baar same props aate hain. Pehle profiler se measure karo ki memo se fark pad raha hai. B galat — trivial component pe memo waste hai. C galat — hamesha different props pe memo useless. D galat — memo functional components ke saath use hota hai, class components ke liye PureComponent hai.

---

Q: React.memo ke baare mein kaunsa statement sahi hai?
A. Memo sirf tab render skip karta hai jab props same hain — change hue to render karega
B. Memo laga diya matlab component kabhi re-render nahi hoga — hamesha cached output use hoga
C. Memo component ko completely render hone se rok deta hai — ek baar render bas kaafi hai
D. Memo sirf development mode mein kaam karta hai — production mein React ignore kar deta hai
> A. Memo "magic bullet" nahi hai. Yeh sirf tab render skip karta hai jab props same hain. Agar koi prop change hota hai, memo bhi normally render karega. B galat — yeh sabse common misconception hai. C galat — props change pe render hoga hi. D galat — memo production mein bhi kaam karta hai.

## TrueFalse

Q: React.memo ek built-in higher-order component hai.
- True
- False
> True. React.memo built-in HOC hai — component lekar ek naya wrapped component return karta hai jo props compare karta hai. Baaki HOCs (jaise Redux ka `connect`) patterns hain jo developers khud banate hain.

---

Q: React.memo internally `Object.is` method use karta hai props compare karne ke liye.
- True
- False
> True. Memo internally `Object.is` se props compare karta hai. Primitives ka value comparison, objects ka reference comparison. Agar same hain to render skip. Agar different hain to render.

---

Q: Inline objects ya arrays props mein bhejne se React.memo hamesha render skip karega kyunki values same rehti hain.
- True
- False
> False. Inline objects ya arrays har render pe naya reference (memory address) banta hai. `Object.is` naya address dekhega — "props change hue" samjhega — render karega. Values same hone se koi fark nahi padta.

---

Q: React mein sirf `React.memo` ek built-in higher-order component hai, baaki saare HOCs patterns hain jo developers khud banate hain.
- True
- False
> True. `React.memo` hi sirf built-in HOC hai. `connect()` (Redux), `withRouter()` — yeh patterns hain, built-in component types nahi. React mein do hi built-in component types hain: functional aur class.

---

Q: React.memo laga dene se component kabhi bhi re-render nahi hoga.
- True
- False
> False. Yeh sabse common misconception hai. Memo sirf tab render skip karta hai jab props same hain. Agar koi bhi prop change hota hai, memo component ko normally render karega. Memo "magic bullet" nahi hai.

---

Q: Children prop ke saath React.memo render skip nahi karega kyunki har render pe naya React element object banta hai.
- True
- False
> True. `children` bhi ek prop hai. `React.createElement` har render pe naya object banata hai. Naya reference = `Object.is` false = memo render karega. Isliye children prop aur memo ka combination generally kaam nahi karta.
