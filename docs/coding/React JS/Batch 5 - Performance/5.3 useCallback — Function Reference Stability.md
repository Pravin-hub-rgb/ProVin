## Abhi Tak Kya Hua

5.1 mein React.memo seekha — component cache karta hai. 5.2 mein useMemo seekha — values cache karta hai.

Lekin ek problem reh gayi — **functions**. Har render pe naya function reference banta hai. Agar memo'd component ko function prop mil raha hai — memo useless ho jata hai kyunki har baar naya function reference = naya prop.

Ab baat karte hain **function references** cache karne ki.

---

## Problem — Filter Change → Saare Items Re-render

Ek TodoList lo jisme `TodoItem` memo wrapped hai, lekin `onToggle` function har render pe naya banta hai:

```tsx
const TodoItem = memo(function TodoItem({ todo, onToggle }: {
  todo: { id: number; text: string; done: boolean }
  onToggle: (id: number) => void
}) {
  console.log('TodoItem render:', todo.id)
  return (
    <li>
      <input type="checkbox" checked={todo.done} onChange={() => onToggle(todo.id)} />
      {todo.text}
    </li>
  )
})

function TodoList() {
  const [todos, setTodos] = useState(initialTodos)
  const [filter, setFilter] = useState('all')

  function handleToggle(id: number) {
    setTodos(prev => prev.map(t =>
      t.id === id ? { ...t, done: !t.done } : t
    ))
  }

  return (
    <div>
      <button onClick={() => setFilter('all')}>All</button>
      <button onClick={() => setFilter('done')}>Done</button>
      {todos.map(todo => (
        <TodoItem key={todo.id} todo={todo} onToggle={handleToggle} />
      ))}
    </div>
  )
}
```

Console mein dekho — filter button click karo (`All` → `Done` → `All`). Har baar saare `TodoItem` ka "TodoItem render" print hota hai.

**Yeh kyun ho raha hai?** Filter change ka `onToggle` se kya relation? Kuch nahi. Problem yeh hai ki har baar `TodoList` render hota hai, `handleToggle` ek naya function object banta hai — naya memory address, naya reference.

`TodoItem` memo hai, lekin `onToggle` prop ka reference badal raha hai → `Object.is(puranaOnToggle, nayaOnToggle)` → false → memo sochta hai "props change hue" → render karta hai.

**Aur toggle karne ka scenario:** Jab actual checkbox click karte ho, sirf woh ek item change hona chahiye. Lekin memo already fail ho chuka hai (filter change se) — saare items render ho rahe hain.

**Yeh React ki galti nahi hai.** JavaScript mein functions objects hain. `function handleToggle() {}` aur `function handleToggle() {}` — dono alag references. React ka memo `Object.is` se compare karta hai. Naya reference = naya prop = re-render.

## useCallback — Kya Hai

`useCallback` ek hook hai jo **function reference** ko cache karta hai. Dependency array change nahi hua — wahi purana function reference return karta hai. Change hua — naya function banata hai.

Syntax:

```tsx
const cachedFn = useCallback(
  () => { /* function body */ },
  [dep1, dep2] // dependencies
)
```

**Kya hota hai internally?** Pehle render pe useCallback diya hua function store kar leta hai. Agle renders pe — dependencies check karta hai. Same hain → purana function reference return. Change hui → naya function banata hai, store karta hai, return karta hai.

Visual mapping:

```
Render trigger
    │
    ▼
useCallback(fn, [a, b])
    │
    ├── a === oldA && b === oldB?
    │   └── Yes → Return old function reference
    │
    └── No → Create new function, cache it, return it
```

## Minimal Code — useCallback Se Fix

```tsx
import { useState, useCallback } from 'react'

function TodoList() {
  const [todos, setTodos] = useState(initialTodos)

  const handleToggle = useCallback((id: number) => {
    setTodos(prev => prev.map(t =>
      t.id === id ? { ...t, done: !t.done } : t
    ))
  }, []) // koi dependency nahi — setTodos ka functional update safe hai

  return (
    <div>
      {todos.map(todo => (
        <TodoItem key={todo.id} todo={todo} onToggle={handleToggle} />
      ))}
    </div>
  )
}
```

Ab `handleToggle` ka reference tab tak same rahega jab tak dependencies `[]` change na hon — aur yeh kabhi change nahi hote. `TodoItem` memo ab kaam karega.

**Console mein check karo:**

| Scenario | useCallback? | TodoItem render? |
|----------|-------------|------------------|
| Filter change (All → Done) | ❌ Bina | Haan — saare items re-render |
| Filter change (All → Done) | ✅ Saath | Nahi — sirf UI update, render skip |
| Checkbox toggle | ❌ Bina | Haan — saare items re-render (unnecessary) |
| Checkbox toggle | ✅ Saath | Sirf woh ek item jiska `todo` actually change hua |

---

## Flow — Do Scenarios

**Scenario A — Filter Button Click (unrelated state change):**
1. `filter` state change hota hai (`all` → `done`)
2. `TodoList` re-render trigger hota hai
3. `handleToggle` useCallback line execute hoti hai — dependencies `[]` check hoti hain
4. Koi dependency change nahi hui → wahi purana `handleToggle` reference return hota hai
5. `todos.map` iterate karta hai, har `TodoItem` ko `onToggle` milta hai — same reference
6. `TodoItem` memo check karta hai — `todo` object same? haan. `onToggle` same? haan. → render skip
7. Sirf UI update hota hai (filter buttons re-render), items nahi

**Scenario B — Checkbox Toggle (actual data change):**
1. Checkbox click → `handleToggle(id)` call → `setTodos` state change
2. `TodoList` re-render trigger hota hai
3. `handleToggle` useCallback — `[]` same → purana reference return
4. Lekin `todos` array change hua → jo `todo` object actually toggle hua, uska naya reference hai
5. `TodoItem` memo check — sirf woh ek item render hoga jiska `todo` change hua, baaki skip

## useCallback vs useMemo

```tsx
// Yeh:
useCallback(fn, deps)

// Bilkul waisa hi hai jaise:
useMemo(() => fn, deps)
```

`useCallback(fn, deps)` = `useMemo(() => fn, deps)`. Dono same kaam karte hain. `useCallback` sirf syntactic sugar hai function references ke liye — padhne mein easy lagta hai.

## Build Up — Callback with Dynamic Dependencies

```tsx
function CommentList({ postId }: { postId: number }) {
  const [comments, setComments] = useState<Comment[]>([])

  const addComment = useCallback((text: string) => {
    const newComment = { id: Date.now(), text, postId }
    setComments(prev => [...prev, newComment])
  }, [postId]) // postId change pe naya function banta hai

  // Agar postId change hua — purana addComment galat postId capture karega
  // Isliye dependency array mein postId daalna zaroori hai
}
```

## useCallback + React.memo = Perfect Combo

Yeh dono saath kyun use hote hain:

```
React.memo → component props same hain toh render skip karta hai
useCallback → function reference stable rakhta hai taaki memo kaam kare
```

Bina useCallback ke, memo ko lagane ka koi fayda nahi agar function props har render pe naye mil rahe hain. Isliye dono hamesha saath aate hain.

---

## Kab useCallback Lagao, Kab Nahi

**❌ Mat lagao jab:**
- Function memo'd component ko prop ke roop mein nahi mil raha
- Component trivial hai — memo laga hi nahi hai
- Premature optimization

**✅ Lagao jab:**
- Function memo'd child component ko prop ja raha hai
- Function useEffect ki dependency hai (5.6 mein dekhenge)
- Function expensive calculation mein use ho raha hai (useMemo ke saath)

## Common Mistake — Har Function useCallback Mein Daal Dena

```tsx
// ❌ Unnecessary — koi child memo nahi hai, koi effect depend nahi karta
const handleClick = useCallback(() => {
  console.log('clicked')
}, [])

// ✅ Direct — useCallback ka koi fayda nahi, overhead hi hai
const handleClick = () => console.log('clicked')
```

Har function ko useCallback mein wrap karna bhi ek anti-pattern hai. Sirf tab lagao jab koi actual problem solve ho rahi ho.

## Summary

✅ **useCallback** — function reference cache karta hai  
✅ Dependencies change nahi hui → purana function reference return  
✅ **React.memo + useCallback** combo — memo kaam karne ke liye zaroori  
✅ Sirf tab lagao jab koi child memo ho ya effect depend kare  
✅ Har function mein mat daalo — unnecessary overhead hai

## React.memo vs useMemo vs useCallback — Ab Ek Saath Dekho

Teeno seekh liye. Ab ek saath compare karte hain:

| Dimension | React.memo | useMemo | useCallback |
|-----------|-----------|---------|-------------|
| **Kya cache karta hai** | Component rendered output | Calculation result | Function reference |
| **Input** | Component | `() => value` | Function |
| **Output** | Memoized component | Cached value | Stable function reference |
| **Syntax** | `memo(Comp)` | `useMemo(() => val, deps)` | `useCallback(fn, deps)` |
| **Kab use karo** | Parent re-render → child same props ho toh render skip | Heavy calculation har render pe chal rahi ho | Function prop memo'd component ko ja raha ho |

**Real flow of all three:**

1. `React.memo` component wrap karta hai — props same hain toh render skip
2. Lekin inline objects har render pe naya reference → `useMemo` se object stabilize karo
3. Lekin inline functions har render pe naya reference → `useCallback` se function stabilize karo
4. Teeno mil ke ek kaam — **unnecessary re-renders rokna**
