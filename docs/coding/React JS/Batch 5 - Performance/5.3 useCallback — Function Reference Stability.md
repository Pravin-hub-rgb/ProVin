## What We've Covered So Far

In 5.1, we learned `React.memo` — it caches a component. In 5.2, we learned `useMemo` — it caches values.

But there's still a problem: **functions**. Every render creates a new function reference, which breaks memo. Let's talk about caching **function references**.

---

## The Problem — Filter Change → All Items Re-render

Imagine a TodoList where `TodoItem` is wrapped in memo, but the `onToggle` function gets recreated on every render:

```tsx
const TodoItem = memo(function TodoItem({ todo, onToggle }: {
  todo: { id: number; text: string; done: boolean }
  onToggle: (id: number) => void
}) {
  console.log('TodoItem render:', todo.id)
  return (
    <li>
      <input type="checkbox" checked={todo.done} onChange={() => onToggle(todo.id)} />
      {todo.text}
    </li>
  )
})

function TodoList() {
  const [todos, setTodos] = useState(initialTodos)
  const [filter, setFilter] = useState('all')

  function handleToggle(id: number) {
    setTodos(prev => prev.map(t =>
      t.id === id ? { ...t, done: !t.done } : t
    ))
  }

  return (
    <div>
      <button onClick={() => setFilter('all')}>All</button>
      <button onClick={() => setFilter('done')}>Done</button>
      {todos.map(todo => (
        <TodoItem key={todo.id} todo={todo} onToggle={handleToggle} />
      ))}
    </div>
  )
}
```

Check the console — click the filter buttons (All → Done → All). Every time, all `TodoItem`s print "TodoItem render".

**Why is this happening?** What does the filter have to do with `onToggle`? Nothing. The issue is that every time `TodoList` re-renders, `handleToggle` becomes a brand new function object — a new memory address, a new reference.

`TodoItem` is memoized, but the `onToggle` prop's reference keeps changing → `Object.is(oldFn, newFn)` → false → memo thinks "props changed" → it re-renders.

**And the toggle scenario:** When you actually click a checkbox, only that one item should change. But memo has already broken (from the filter change) — all items are re-rendering unnecessarily.

**This isn't React's fault.** In JavaScript, functions are objects. `function handleToggle() {}` written twice creates two different references. React's memo uses `Object.is` to compare — a new reference means a new prop, which triggers a re-render.

---

## useCallback — What It Is

`useCallback` is a hook that caches a **function reference**. As long as the dependency array hasn't changed, it keeps returning the same function reference. If a dependency changed, it creates a new function.

Syntax:

```tsx
const cachedFn = useCallback(
  () => { /* function body */ },
  [dep1, dep2] // dependencies
)
```

**What's happening internally?** On the first render, `useCallback` stores the given function. On subsequent renders — it checks the dependencies. Same → returns the old function reference. Changed → creates a new function, stores it, returns it.

Visual mapping:

```
Render triggered
    │
    ▼
useCallback(fn, [a, b])
    │
    ├── a === oldA && b === oldB?
    │   └── Yes → Return old function reference
    │
    └── No → Create new function, cache it, return it
```

---

## Minimal Code — Fix with useCallback

```tsx
import { useState, useCallback } from 'react'

function TodoList() {
  const [todos, setTodos] = useState(initialTodos)

  const handleToggle = useCallback((id: number) => {
    setTodos(prev => prev.map(t =>
      t.id === id ? { ...t, done: !t.done } : t
    ))
  }, []) // No dependencies — setTodos' functional update is safe

  return (
    <div>
      {todos.map(todo => (
        <TodoItem key={todo.id} todo={todo} onToggle={handleToggle} />
      ))}
    </div>
  )
}
```

Now `handleToggle`'s reference stays the same as long as dependencies `[]` don't change — which they never do. `TodoItem`'s memo now works correctly.

**Check the console:**

| Scenario | useCallback? | TodoItem re-renders? |
|----------|-------------|----------------------|
| Filter change (All → Done) | ❌ Without | Yes — all items re-render |
| Filter change (All → Done) | ✅ With | No — just UI update, render skipped |
| Checkbox toggle | ❌ Without | Yes — all items re-render (unnecessary) |
| Checkbox toggle | ✅ With | Only the one item whose `todo` actually changed |

---

## Flow — Two Scenarios

**Scenario A — Filter Button Click (unrelated state change):**
1. `filter` state changes (`all` → `done`)
2. `TodoList` re-renders
3. `handleToggle` useCallback line executes — dependencies `[]` are checked
4. No dependency changed → the old `handleToggle` reference is returned
5. `todos.map` iterates, each `TodoItem` gets `onToggle` — same reference
6. `TodoItem` checks memo — `todo` object same? Yes. `onToggle` same? Yes. → render skipped
7. Just a UI update (the filter buttons), items don't re-render

**Scenario B — Checkbox Toggle (actual data change):**
1. Checkbox click → `handleToggle(id)` called → `setTodos` state changes
2. `TodoList` re-renders
3. `handleToggle` useCallback — `[]` is the same → old reference returned
4. But `todos` array changed → the `todo` object that was actually toggled has a new reference
5. `TodoItem` checks memo — only that one item re-renders whose `todo` changed, rest skip

## useCallback vs useMemo

```tsx
// This:
useCallback(fn, deps)

// Is exactly the same as:
useMemo(() => fn, deps)
```

`useCallback(fn, deps)` = `useMemo(() => fn, deps)`. Both do the same thing. `useCallback` is just syntactic sugar for function references — it reads more naturally.

---

## Building Up — Callback with Dynamic Dependencies

```tsx
function CommentList({ postId }: { postId: number }) {
  const [comments, setComments] = useState<Comment[]>([])

  const addComment = useCallback((text: string) => {
    const newComment = { id: Date.now(), text, postId }
    setComments(prev => [...prev, newComment])
  }, [postId]) // postId changes → new function is created

  // If postId changed — the old addComment would capture the old postId
  // That's why postId must be in the dependency array
}
```

## useCallback + React.memo = Perfect Combo

Why are these used together:

```
React.memo → skips component re-render when props are the same
useCallback → keeps function references stable so memo works
```

Without `useCallback`, there's no point applying `memo` if function props get recreated on every render. That's why they almost always go together.

---

## When to Use useCallback — And When Not To

**❌ Don't use when:**
- The function isn't passed as a prop to a memoized child component
- The component is trivial — not memoized anyway
- Premature optimization

**✅ Use when:**
- A function is passed as a prop to a memoized child component
- The function is a dependency in `useEffect` (we'll look at this in 5.6)
- The function wraps an expensive calculation (used with `useMemo`)

---

## Common Mistake — Wrapping Every Function in useCallback

```tsx
// ❌ Unnecessary — no memoized child, no effect dependency
const handleClick = useCallback(() => {
  console.log('clicked')
}, [])

// ✅ Direct — useCallback brings no benefit here, just overhead
const handleClick = () => console.log('clicked')
```

Wrapping every function in `useCallback` is also an anti-pattern. Only use it when it actually solves a problem.

---

## Summary

✅ **useCallback** — caches a function reference  
✅ Dependencies haven't changed → old function reference is returned  
✅ **React.memo + useCallback** combo — essential for memo to actually work  
✅ Only use when a child is memoized or an effect depends on it  
✅ Don't wrap every function — it's unnecessary overhead

## React.memo vs useMemo vs useCallback — All Together Now

We've learned all three. Let's compare them side by side:

| Dimension | React.memo | useMemo | useCallback |
|-----------|-----------|---------|-------------|
| **What does it cache?** | A component's rendered output | A calculation's result | A function reference |
| **Input** | A Component | `() => value` | A function |
| **Output** | A memoized component | A cached value | A stable function reference |
| **Syntax** | `memo(Comp)` | `useMemo(() => val, deps)` | `useCallback(fn, deps)` |
| **Use when** | Parent re-renders but child's props are the same → skip child render | Heavy calculation runs on every render | A memoized child receives a function prop |

**The complete real-world flow:**

1. `React.memo` wraps a component — skips render when props are the same
2. But inline objects get a new reference each render → use `useMemo` to stabilize the object
3. But inline functions get a new reference each render → use `useCallback` to stabilize the function
4. All three together = **unnecessary re-renders are prevented**
