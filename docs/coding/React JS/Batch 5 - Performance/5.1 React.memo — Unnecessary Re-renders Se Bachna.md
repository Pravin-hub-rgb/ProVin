## Problem — Parent Re-render → Child Bhi Re-render

Ek simple component lete hain:

```tsx
function ExpensiveCard() {
  console.log('ExpensiveCard render')
  return <div className="p-4 border rounded">Main expensive hoon</div>
}

function Dashboard() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
      <ExpensiveCard />
    </div>
  )
}
```

Notice kiya? Har baar `Dashboard` re-render hota hai (count change hone pe) — `ExpensiveCard` bhi re-render hota hai, chahe uska kuch change nahi hua.

Browser console kholo — har click pe "ExpensiveCard render" print ho raha hai.

**Yeh problem kyun hai?** React ka default behavior hai — parent render → child render. React ko nahi pata ki `ExpensiveCard` ke props change hue ya nahi. Woh bas render kar deta hai.

Chhote component ke liye koi fark nahi padta. Lekin agar `ExpensiveCard` mein heavy calculation ho, ya woh ek list ka item ho (100 items), toh har baar unnecessarily render karna waste hai.

## Higher-Order Component (HOC) — Pehle Yeh Samjho

`React.memo` ko "higher-order component" kaha jaata hai. Pehle samajhte hain iska matlab kya hai.

Tumhe pata hai ki JavaScript mein **higher-order functions** hote hain — jaise `map`, `filter`, `setTimeout`. Ye functions ya toh function **lete hain** ya function **return karte hain**:

```tsx
function multiplier(factor) {
  return function (value) {
    return value * factor
  }
}
const double = multiplier(2)
console.log(double(5)) // 10
```

`multiplier` ek higher-order function hai kyunki yeh ek function return kar raha hai.

**Higher-Order Component (HOC)** wohi pattern hai, lekin React components ke saath. Ek HOC ek function hai jo:
1. Ek component leta hai (as argument)
2. Extra functionality add karta hai
3. Ek naya component return karta hai

```tsx
const EnhancedComponent = withExtraFeature(WrappedComponent)
```

Gift wrapping service ki tarah socho. Tum ek gift dete ho (component). Woh use wrap karta hai aur ek wrapped gift return karta hai (enhanced component). Original gift wahi hai, bas usme wrapping add hui.

**What It Is NOT:** HOC koi built-in React API nahi hai. Sirf `React.memo` built-in hai. Baaki HOCs (jaise `connect()` from Redux, `withRouter()`) patterns hain jo developers khud banate hain.

### React Mein Component Types

React mein technically do hi component types hain:

| Type | Kya Hai |
|------|---------|
| **Functional Component** | Function jo JSX return kare. Hooks use ho sakte hain. Modern React. |
| **Class Component** | `class extends React.Component`. Lifecycle methods. Legacy / purana code. |

Inke alawa kuch **patterns** hain jo components ko enhance / modify karte hain:

| Pattern | Kya Karta Hai |
|---------|--------------|
| **HOC** | Component lekar enhanced component return kare |
| **React.memo** | Built-in HOC — props na badle toh render skip |
| **React.PureComponent** | Class component ka built-in shallow comparison |

Ab aate hain React.memo pe — jo ek **built-in HOC** hai...

## React.memo — Kya Hai

Iska kaam simple hai — component ko "yaad" rakhna (memoize). Jab parent re-render hota hai, memo check karta hai — "kya is component (jisko memo wrap kiya hai) ke props pichli baar se change hue?" Agar nahi hue — toh render skip karo, cached result do.

Syntax:

```tsx
const ExpensiveCard = React.memo(function ExpensiveCard() {
  console.log('ExpensiveCard render')
  return <div className="p-4 border rounded">Main expensive hoon</div>
})
```

Ya functional component alag banao phir memo wrap karo:

```tsx
function ExpensiveCard() {
  console.log('ExpensiveCard render')
  return <div className="p-4 border rounded">Main expensive hoon</div>
}

export default React.memo(ExpensiveCard)
```

**Kya hota hai internally?** React.memo component ko wrap karta hai. Jab parent render trigger hota hai, memo internally `Object.is` se props compare karta hai. Agar props same hain — to React purana rendered output reuse karta hai, component function call nahi hota.

## Minimal Code — Memo Lagao, Dekho Fark

```tsx
import { useState, memo } from 'react'

const ExpensiveCard = memo(function ExpensiveCard() {
  console.log('render')
  return <div className="p-4 border rounded">Main expensive hoon</div>
})

export default function Dashboard() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
      <ExpensiveCard />
    </div>
  )
}
```

Ab console dekh — count change karne pe sirf pehli baar "render" print hoga. Baad ki clicks pe sirf `count` change hoga, `ExpensiveCard` render nahi hoga.

Notice kiya? Memo ne render skip kiya kyunki props the hi nahi (aur `Object.is(undefined, undefined)` = true). Simple case.

## Props Ke Saath Memo

Jab component ko props milte hain, memo tab kaam aata hai jab props **same** hain:

```tsx
const Greeting = memo(function Greeting({ name }: { name: string }) {
  console.log('Greeting render:', name)
  return <p>Hello, {name}!</p>
})

function App() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>Clicked: {count}</button>
      <Greeting name="Vin" />
    </div>
  )
}
```

Har click pe `count` change hota hai → `App` re-render → `Greeting` ke props check hote hain. `name` same hai ("Vin") → memp render nahi karega. Sirf pehli baar "Greeting render: Vin" print hoga.

Lekin agar `name` change ho:

```tsx
<Greeting name={count > 5 ? 'Vin' : 'Guest'} />
```

Toh jab count 5 cross karega, `name` change hoga — memo re-render karega kyunki props change hue.

## Coder's Perspective Flow

### 1. Concept
`React.memo` ek wrapper hai jo component ko "cache" karta hai. Jab component re-render ho sakta hai, memo pichle props se naye props compare karta hai. Same hain toh render skip.

### 2. Syntax
```tsx
const MemoComp = memo(Component)
// ya
export default memo(Component)
```

### 3. Visual Mapping
```
Parent re-render
    │
    ▼
React.memo(Child)
    │
    ├── Props same? ──→ Skip render (cached output)
    │
    └── Props different? ──→ Normal render
```

### 4. Minimal Code
Wahi `ExpensiveCard` example upar hai — memo lagao, extra render skip dekho.

### 5. Flow — Kya Hota Hai Jab Button Click Hota Hai
1. `count` state change hota hai
2. `App` re-render trigger hota hai
3. `Greeting` component render hota hai (kyunki woh `App` ke andar hai)
4. Lekin `Greeting` memo wrapped hai — React internally `Object.is` se props compare karta hai
5. `name` ka pichla value ("Vin") === naya value ("Vin") → true
6. React cached output reuse karta hai — `Greeting` function call nahi hota
7. "Greeting render:" console mein nahi print hota

### 6. Build Up — Real Scenario

Socho ek list hai — 100 items. Har item ka component hai. Agar parent list state change karta hai (jaise ek item delete), toh memo ke bina saare 100 re-render hote hain. Memo laga do — sirf wohi re-render hoga jiska actual data change hua.

```tsx
const TodoItem = memo(function TodoItem({ todo, onToggle }: {
  todo: { id: number; text: string; done: boolean }
  onToggle: (id: number) => void
}) {
  console.log('TodoItem render:', todo.id)
  return (
    <li>
      <input type="checkbox" checked={todo.done} onChange={() => onToggle(todo.id)} />
      {todo.text}
    </li>
  )
})
```

## Jab Memo Kaam Nahi Karega

Memo sirf **props compare** karta hai. Lekin agar:

### 1. Inline Objects / Arrays / Functions

Har render pe naya object/reference banta hai — `Object.is` false deta hai.

```tsx
// ❌ Har render pe naya object — memo useless
<Profile user={{ name: 'Vin', age: 25 }} />

// ❌ Har render pe nayi function — memo useless
<TodoItem onToggle={(id) => toggleTodo(id)} />
```

Is problem ka solution hai `useMemo` aur `useCallback` — woh 5.2 aur 5.3 mein.

### 2. Children Prop

`children` bhi ek prop hai. Agar parent har baar naya JSX pass karta hai, memo check fail karega.

```tsx
<Card>
  <p>Har baar naya JSX</p>   {/* ❌ children change ho raha hai */}
</Card>
```

---

## Memo Kab Lagao, Kab Nahi

**❌ Mat lagao jab:**
- Component trivial ho (ek `<span>`, ek `<div>`)
- Component hamesha different props leta ho
- Premature optimization — pehle problem measure karo, phir memo lagao

**✅ Lagao jab:**
- Component heavy ho (charts, tables, lists)
- Component baar baar same props ke saath render ho raha ho
- Profiler mein clearly dikhe ki memo se fark pad raha hai

---

## Common Mistake — "Memo = Kabhi Render Nahi Hoga"

Nahi. Memo sirf tab render skip karta hai jab props **same** hain. Agar koi bhi prop change hota hai — memo render karega. Yeh "magic bullet" nahi hai jo saare re-renders rok de.

---

## Summary

✅ **React.memo** — higher-order component — component ko "yaad" rakhta hai  
✅ Props same hain → render skip, cached output reuse  
✅ `Object.is` se props compare karta hai internally  
✅ Inline objects/functions se memo useless ho jata hai  
✅ Use when component is heavy, baar baar same props aate hain  
✅ Don't over-optimize — pehle Profiler se measure karo

---

## Agla Step

Memo laga diya — lekin inline functions aur objects ki problem hai. Naye props reference = memo useless. Iska solution hai **`useMemo` aur `useCallback`**. Woh 5.2 aur 5.3 mein.
