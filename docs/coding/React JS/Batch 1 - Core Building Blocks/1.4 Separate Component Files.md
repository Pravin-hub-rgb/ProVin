## Abhi Tak Kya Hua

1.3 mein import/export ka system seekha — `export default` vs `export named`, `import type`, aur module system ka basic idea clear ho gaya. Ab is knowledge ko real project mein use karte hain — **component ko alag file mein rakhna, import karna, aur multiple components ko ek App mein combine karna**.

## Broader Goal

Ab tak ProfileCard aur MemberBadge `App.tsx` mein ek saath likhe the — jo chhota example ke liye theek hai. Lekin real project mein aisa nahi hota. Har component ki apni file hoti hai. Is topic mein component-folder structure, import chain, aur multiple components ke saath kaam karna seekhenge.

## Step 1 — Ek File Mein Sab Kuch — Problem

Soch: "1.2 mein ProfileCard aur App dono `App.tsx` mein the. Kya problem hai?"

Chhota example (50 lines) — koi problem nahi. Lekin real component 100-200 lines ka hota hai. Agar 10 components ek file mein daal do:

```
App.tsx — 2000 lines ka monster file
```

Iss file mein ProfileCard, MemberBadge, Header, Footer, Sidebar — sab ek saath. Koi bhi ek component edit karna hai toh 2000 lines scroll karni padegi. Do developers ek saath kaam nahi kar sakte ki ek hi file edit karein.

**Real-world examples:**
- Facebook ka main component file kabhi 10,000+ lines ka tha (React team ne use split karne ka article bhi likha tha)
- Amazon, Flipkart, Zomato — har bade project mein file splitting mandatory hai

Is problem ka solution — **ek component = ek file**.

## Step 2 — Components Folder Structure

Soch: "Alag file to banani hai. Lekin kahan banani hai? Koi convention hai?"

Har React project mein ek `components/` folder hota hai:

```
src/
├── components/
│   ├── ProfileCard.tsx
│   └── MemberBadge.tsx
├── App.tsx
└── main.tsx
```

**Rules:**
1. File ka naam component ke naam ke jaisa — `ProfileCard` → `ProfileCard.tsx`
2. PascalCase file names — React ecosystem standard
3. `.tsx` extension — kyunki file mein JSX hai
4. `components/` folder `src/` ke andar

Yeh convention hai, rule nahi. Kuch teams lowercase file names use karti hai (`profileCard.tsx`), kuch folders ko `components/` nahi `ui/` bolti hai. Lekin React ecosystem mein above structure standard hai.

## Step 3 — ProfileCard Ko Alag File Mein

Soch: "App.tsx mein ProfileCard function likha hai. Use alag file mein kaise nikaalein?"

**Step-by-step:**

1. **Naya folder banayein:** `src/components/`
2. **Nayi file banayein:** `src/components/ProfileCard.tsx`
3. **Component function wahan move karein**
4. **`export default` karein**
5. **App.tsx mein `import` karein**

`src/components/ProfileCard.tsx`:

```tsx
function ProfileCard() {
  const name = "Vin";
  const role = "React Developer";

  return (
    <div>
      <h2>{name}</h2>
      <p>{role}</p>
    </div>
  );
}

export default ProfileCard;
```

`src/App.tsx`:

```tsx
import ProfileCard from "./components/ProfileCard";

function App() {
  return (
    <div>
      <h1>My App</h1>
      <ProfileCard />
      <ProfileCard />
    </div>
  );
}

export default App;
```

Browser mein same output — kuch nahi badla. Bas code organize ho gaya.

**Kya hua actual mein?**
- `ProfileCard.tsx` file mein component define kiya aur export kiya
- `App.tsx` mein relative path `"./components/ProfileCard"` se import kiya
- File extension `.tsx` import path mein nahi likhte — TypeScript handle kar leta hai
- `./` ka matlab "current folder ke andar"

### Import Path Note

```
import ProfileCard from "./components/ProfileCard";
                   //  |_________|__________|
                   //  current      subfolder + file (bina extension)
                   //  folder
```

Path component ki file ke relative hota hai. `App.tsx` `src/` folder mein hai, `ProfileCard.tsx` `src/components/` folder mein. Toh path: `"./components/ProfileCard"`.

## Step 4 — Multiple Components, Multiple Files

Soch: "Ek ProfileCard toh alag file mein aa gaya. Ab MemberBadge bhi alag file mein rakhna hai."

`src/components/MemberBadge.tsx`:

```tsx
function MemberBadge() {
  const name = "Priya";
  const role = "Designer";

  return (
    <div>
      <h3>{name}</h3>
      <p>{role}</p>
    </div>
  );
}

export default MemberBadge;
```

`App.tsx` — dono import karo:

```tsx
import ProfileCard from "./components/ProfileCard";
import MemberBadge from "./components/MemberBadge";

function App() {
  return (
    <div>
      <h1>My Team</h1>
      <ProfileCard />
      <ProfileCard />
      <MemberBadge />
      <MemberBadge />
    </div>
  );
}

export default App;
```

Dekho — `App.tsx` ab sirf import + layout ka kaam kar rahi hai. ProfileCard aur MemberBadge apni-apni files mein alag. Agar kisi ek component mein change karna hai, toh sirf wahi file edit karo.

### Multiple Files Ka Fayda

1. **Readability:** Har file chhoti aur focused
2. **Team Work:** Do developers ek saath kaam kar sakte hain — ek ProfileCard pe, doosra MemberBadge pe
3. **Reusability:** Component doosre projects mein copy-paste karna aasan
4. **Testing:** Component ki alag file hai toh use isolate karke test easy hota hai
5. **Git Conflicts:** Do developers same component pe kaam karein toh conflict sirf usi file mein hogi, App.tsx mein nahi

## Step 5 — TypeScript Return Type — Optional

Soch: "ProfileCard mein `: JSX.Element` return type nahi likha. Chalega?"

`ProfileCard.tsx` dekho — function ke baad `: JSX.Element` nahi likha. Phir bhi TypeScript error nahi de rahi. Kyun?

**Type Inference in action:** TypeScript automatically infer kar leta hai ki component JSX.Element return karega. Explicit return type optional hai.

Professional React codebases mein mostly return type skip karte hain. Lekin learning phase mein explicit likhna achhi aadat hai — pata chalta hai ki component actually kya return kar raha hai.

### Kab Explicit Return Type Likhein

- **Jab component complex ho** — multiple return paths ho sakte hain
- **Jab team convention ho** — kuch teams TypeScript strict mode mein return type force karti hain
- **Learning phase** — samajhne ke liye useful

## Step 6 — Import Export Ka Pattern Tumhari Team Mein

Soch: "Har project mein same pattern hota hai?"

React projects mein generally do standard patterns hain:

**Pattern 1 — Default Export per Component (Most Common):**

```
// ProfileCard.tsx
function ProfileCard() { ... }
export default ProfileCard;

// App.tsx
import ProfileCard from "./components/ProfileCard";
```

**Pattern 2 — Named Export per Component:**

```
// ProfileCard.tsx
export function ProfileCard() { ... }

// App.tsx
import { ProfileCard } from "./components/ProfileCard";
```

Is course mein Pattern 1 follow karenge — default export. Yeh Next.js / Vite / Create React App sab ke saath consistent hai. Pattern 2 bhi kuch teams use karti hai (especially jab ek file se multiple components export karne ho). Dono valid hain, bas consistency chahiye.

## Summary

- Component = ek file — `ProfileCard.tsx`, `MemberBadge.tsx`
- `components/` folder — standard React convention
- File name = PascalCase (`ProfileCard.tsx`)
- Extension `.tsx` for files with JSX
- Import path relative: `"./components/ProfileCard"`
- Multiple files = better team work, readability, reusability
- Return type `JSX.Element` optional (TypeScript infer kar leta hai)
- Default export — standard practice in this course

Components banaye, alag files mein rakhe, import/export kiya. Ab agla logical step — **component ko dynamic banana** taaki ek component har baar alag data ke saath render ho. Iske liye **Props** seekhenge. 1.2 ka static ProfileCard ab dynamic banega.
