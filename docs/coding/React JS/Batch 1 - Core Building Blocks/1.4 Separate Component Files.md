## Where We Left Off

In 1.3, we learned the import/export system — `export default` vs named exports, `import type`, and the basics of JavaScript modules. Now we'll use that knowledge in a real project — putting a **component in its own file**, importing it, and combining multiple components into an App.

## Broader Goal

So far, `ProfileCard` and `MemberBadge` were written together in `App.tsx` — fine for a small example. But that's not how real projects work. Every component has its own file. In this topic, we'll build the component folder structure, the import chain, and work with multiple components.

## Step 1 — The Problem with One File

Think: "In 1.2, both `ProfileCard` and `App` were in `App.tsx`. What's the problem?"

A small example (50 lines) — no problem. But a real component is 100–200 lines. Put 10 components in one file:

```
App.tsx — a 2000-line monster file
```

That one file has ProfileCard, MemberBadge, Header, Footer, Sidebar — all together. Want to edit one component? Scroll through 2000 lines. Two developers can't work on the same file at once.

**Real-world examples:**
- Facebook's main component file used to be 10,000+ lines (the React team wrote an article about splitting it)
- Amazon, Flipkart, Zomato — every large project needs file splitting

The solution: **one component = one file**.

## Step 2 — Components Folder Structure

Think: "I need to create a new file. Where does it go? Is there a convention?"

Every React project has a `components/` folder:

```
src/
├── components/
│   ├── ProfileCard.tsx
│   └── MemberBadge.tsx
├── App.tsx
└── main.tsx
```

**Rules:**
1. File name matches the component name — `ProfileCard` → `ProfileCard.tsx`
2. PascalCase file names — standard in the React ecosystem
3. `.tsx` extension — because the file contains JSX
4. `components/` folder lives inside `src/`

This is a convention, not a hard rule. Some teams use lowercase file names (`profileCard.tsx`), others call the folder `ui/` instead of `components/`. But the structure above is standard in the React ecosystem.

## Step 3 — Move ProfileCard to Its Own File

Think: "ProfileCard is defined in `App.tsx`. How do I move it to a separate file?"

**Step by step:**

1. **Create the folder:** `src/components/`
2. **Create the file:** `src/components/ProfileCard.tsx`
3. **Move the component function** into it
4. **Add `export default`**
5. **Import in `App.tsx`**

`src/components/ProfileCard.tsx`:

```tsx
function ProfileCard() {
  const name = "Vin";
  const role = "React Developer";

  return (
    <div>
      <h2>{name}</h2>
      <p>{role}</p>
    </div>
  );
}

export default ProfileCard;
```

`src/App.tsx`:

```tsx
import ProfileCard from "./components/ProfileCard";

function App() {
  return (
    <div>
      <h1>My App</h1>
      <ProfileCard />
      <ProfileCard />
    </div>
  );
}

export default App;
```

Browser shows the same output — nothing actually changed. The code is just organized now.

**What happened under the hood:**
- `ProfileCard.tsx` defines the component and exports it
- `App.tsx` imports it with the relative path `"./components/ProfileCard"`
- File extension `.tsx` is omitted in the import path — TypeScript resolves it
- `./` means "inside the current folder"

### Import Path Note

```
import ProfileCard from "./components/ProfileCard";
                    //  |_________|__________|
                    //    current    subfolder + file (no extension)
                    //    folder
```

The path is relative to the importing file. `App.tsx` is in `src/`, and `ProfileCard.tsx` is in `src/components/`. So the path is `"./components/ProfileCard"`.

## Step 4 — Multiple Components, Multiple Files

Think: "ProfileCard moved to its own file. Now MemberBadge needs to go to its own file too."

`src/components/MemberBadge.tsx`:

```tsx
function MemberBadge() {
  const name = "Priya";
  const role = "Designer";

  return (
    <div>
      <h3>{name}</h3>
      <p>{role}</p>
    </div>
  );
}

export default MemberBadge;
```

`App.tsx` — import both components:

```tsx
import ProfileCard from "./components/ProfileCard";
import MemberBadge from "./components/MemberBadge";

function App() {
  return (
    <div>
      <h1>My Team</h1>
      <ProfileCard />
      <ProfileCard />
      <MemberBadge />
      <MemberBadge />
    </div>
  );
}

export default App;
```

Now `App.tsx` only handles imports and layout. ProfileCard and MemberBadge live in their own separate files. Want to change one component? Just edit that one file.

### Benefits of Multiple Files

1. **Readability:** Each file is small and focused on one thing
2. **Team work:** Two developers can work simultaneously — one on ProfileCard, another on MemberBadge
3. **Reusability:** Copying a component to another project is just one file — import and use
4. **Testing:** Because the component is in its own file, you can isolate it and test it
5. **Git conflicts:** If two developers work on the same component, the conflict stays in that component's file — not in App.tsx

## Step 5 — TypeScript Return Type: Optional

Think: "I didn't write `: JSX.Element` as the return type for ProfileCard. Will TypeScript complain?"

Looking at `ProfileCard.tsx` — the function doesn't have `: JSX.Element`. TypeScript doesn't error. Why?

**Type Inference in action:** TypeScript automatically infers that the component returns `JSX.Element`. Explicit return type is optional.

In professional React codebases, return types are mostly skipped. But while learning, writing them explicitly is a good habit — you know exactly what the function is returning.

### When to Write Explicit Return Types

- **When the component is complex** — multiple return paths may exist
- **When the team convention requires it** — some teams enforce strict TypeScript and force return types
- **While learning** — helpful for understanding

## Step 6 — The Import/Export Pattern in Your Team

Think: "Does every project follow the same pattern?"

React projects generally use two standard patterns:

**Pattern 1 — Default Export per Component (Most Common):**

```
// ProfileCard.tsx
function ProfileCard() { ... }
export default ProfileCard;

// App.tsx
import ProfileCard from "./components/ProfileCard";
```

**Pattern 2 — Named Export per Component:**

```
// ProfileCard.tsx
export function ProfileCard() { ... }

// App.tsx
import { ProfileCard } from "./components/ProfileCard";
```

This course follows Pattern 1 — default export. It's consistent with Next.js, Vite, and Create React App. Pattern 2 is also used by some teams (especially when exporting multiple components from one file). Both are valid — consistency is what matters.

## Summary

- **One component = one file** — `ProfileCard.tsx`, `MemberBadge.tsx`
- **`components/` folder** — standard React convention
- File names use PascalCase — `ProfileCard.tsx`
- `.tsx` extension for files containing JSX
- Import paths are relative — `"./components/ProfileCard"`
- Multiple files bring better readability, team work, reusability
- Return type `JSX.Element` is optional (TypeScript infers it)
- Default export — the standard practice in this course
