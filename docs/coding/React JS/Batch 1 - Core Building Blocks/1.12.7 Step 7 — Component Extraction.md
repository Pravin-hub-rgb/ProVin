# 1.12.7 — Step 7: Component Extraction

## Where We Left Off

Search + filter work (1.12.6). App.tsx is getting big. Extract into components, one at a time. For each: why extract, what props it needs, how the callback prop flows (child → parent), then the code.

`ContactForm` is already done (1.12.3) — we skip it.

We extract in this order: SearchBar → FilterBar → ContactList (card inlined) → ContactCard (pull out) → Footer → final App.tsx.

### Step 7.1 — Extract `SearchBar` (callback prop: `onChange`)

**Think:** The search input currently lives inline in App.tsx. It's a controlled input whose value comes from App's `search` state. Extract it: the child renders the input, the parent owns the state. The child tells the parent "user typed X" via a callback prop.

**Why a callback prop?** The child (SearchBar) doesn't own `search` state — App does. But the child needs to update it. So the parent passes a function (`onChange`) down; the child calls it when the user types. This is the 1.5.4 callback-prop pattern (same as `onAdd` in 1.12.3).

**Proof of connection (console.log first):** Before passing real state updates, pass a handler that only logs — to confirm the child→parent link works.

```tsx
interface SearchBarProps {
  value: string;
  onChange: (value: string) => void;
}

export default function SearchBar({ value, onChange }: SearchBarProps) {
  return (
    <input
      value={value}
      onChange={(e) => {
        console.log("🔍 SearchBar: user typed", e.target.value);
        onChange(e.target.value);   // tell parent
      }}
      placeholder="Search by name..."
    />
  );
}
```

```tsx
import SearchBar from "./SearchBar";

export default function App() {
  const [search, setSearch] = useState("");

  const handleSearchChange = (value: string) => {
    console.log("✅ App received search:", value);
    setSearch(value);
  };

  return (
    <div>
      <h1>Contact Book</h1>
      <SearchBar value={search} onChange={handleSearchChange} />
    </div>
  );
}
```

**Console check** – type in the search box. You should see "🔍 SearchBar: user typed ..." then "✅ App received search: ...". The child talked to the parent. Connection proven. Then remove the console.logs for the final version (below).

**Final `src/SearchBar.tsx` (clean):**

```tsx
interface SearchBarProps {
  value: string;
  onChange: (value: string) => void;
}

export default function SearchBar({ value, onChange }: SearchBarProps) {
  return (
    <input
      value={value}
      onChange={(e) => onChange(e.target.value)}
      placeholder="Search by name..."
    />
  );
}
```

**Final `src/App.tsx` wiring:**

```tsx
<SearchBar value={search} onChange={setSearch} />
```

`onChange={setSearch}` — passing the setter directly, since its signature `(value: string) => void` matches. Shorthand for `onChange={(v) => setSearch(v)}`.

### Step 7.2 — Extract `FilterBar` (callback prop: `onChange`)

**Think:** Filter buttons currently inline. Extract them. Same pattern as SearchBar: child renders buttons, parent owns `categoryFilter`. Child calls `onChange(cat)` when a button is clicked.

**Props:** `current: CategoryFilter` (what's active) + `onChange: (filter) => void` (tell parent).

```tsx
import type { CategoryFilter } from "./types";

interface FilterBarProps {
  current: CategoryFilter;
  onChange: (filter: CategoryFilter) => void;
}

export default function FilterBar({ current, onChange }: FilterBarProps) {
  const options: CategoryFilter[] = ["all", "family", "work", "friend"];

  return (
    <div>
      {options.map((opt) => (
        <button
          key={opt}
          onClick={() => onChange(opt)}
          style={{ fontWeight: current === opt ? "bold" : "normal" }}
        >
          {opt.charAt(0).toUpperCase() + opt.slice(1)}
        </button>
      ))}
    </div>
  );
}
```

**Wiring in App.tsx:**

```tsx
<FilterBar current={categoryFilter} onChange={setCategoryFilter} />
```

**Callback flow:** button click → `onChange(opt)` → App's `setCategoryFilter(opt)` → re-render → `current` prop updates → active button bolds. The child never owns the filter; it just reports clicks.

### Step 7.3 — Extract `ContactList` (parent first, card inlined for now)

**Think:** The list renders one card per contact. Extract the list first — but the card doesn't exist yet as a component, so inline the card JSX inside the list (like Step 4 did). We'll pull the card out in 7.4.

**Props:** `contacts: Contact[]` + `onToggleFavorite: (id) => void` + `onDelete: (id) => void`.

```tsx
import type { Contact } from "./types";

interface ContactListProps {
  contacts: Contact[];
  onToggleFavorite: (id: number) => void;
  onDelete: (id: number) => void;
}

export default function ContactList({ contacts, onToggleFavorite, onDelete }: ContactListProps) {
  if (contacts.length === 0) {
    return <p>No contacts found.</p>;
  }

  return (
    <div>
      {contacts.map((contact) => (
        <div key={contact.id} style={{ border: "1px solid #ddd", padding: "0.75rem", borderRadius: "8px", marginBottom: "0.5rem" }}>
          <div style={{ display: "flex", justifyContent: "space-between", alignItems: "center" }}>
            <strong>{contact.name}</strong>
            <button onClick={() => onToggleFavorite(contact.id)}>
              {contact.favorite ? "★" : "☆"}
            </button>
          </div>
          <div>📞 {contact.phone}</div>
          {contact.email && <div>✉️ {contact.email}</div>}
          <div>
            <span style={{ fontSize: "0.8rem", color: "#666" }}>[{contact.category}]</span>
            <button onClick={() => onDelete(contact.id)} style={{ marginLeft: "1rem", color: "red" }}>
              Delete
            </button>
          </div>
        </div>
      ))}
    </div>
  );
}
```

**Callback flow:** the list forwards `onToggleFavorite` and `onDelete` down to each inlined card's buttons. The list doesn't transform them — it just calls them with `contact.id`. The parent (App) still owns the logic.

**Wiring in App.tsx:**

```tsx
<ContactList
  contacts={filteredContacts}
  onToggleFavorite={handleToggleFavorite}
  onDelete={handleDelete}
/>
```

App passes the filtered list (data) plus the two handlers (callbacks). `ContactList` doesn't know what `handleToggleFavorite` does — it just calls it when a card's star is clicked.

### Step 7.4 — Extract `ContactCard` (pull the card out of the list)

**Think:** The card JSX is now duplicated inside `ContactList`. Extract it into its own component. Replace the inlined card with `<ContactCard ... />`.

**Props:** `contact: Contact` (data, read-only) + `onToggleFavorite: (id) => void` + `onDelete: (id) => void`.

```tsx
import type { Contact } from "./types";

interface ContactCardProps {
  contact: Contact;
  onToggleFavorite: (id: number) => void;
  onDelete: (id: number) => void;
}

export default function ContactCard({ contact, onToggleFavorite, onDelete }: ContactCardProps) {
  return (
    <div style={{ border: "1px solid #ddd", padding: "0.75rem", borderRadius: "8px", marginBottom: "0.5rem" }}>
      <div style={{ display: "flex", justifyContent: "space-between", alignItems: "center" }}>
        <strong>{contact.name}</strong>
        <button onClick={() => onToggleFavorite(contact.id)}>
          {contact.favorite ? "★" : "☆"}
        </button>
      </div>
      <div>📞 {contact.phone}</div>
      {contact.email && <div>✉️ {contact.email}</div>}
      <div>
        <span style={{ fontSize: "0.8rem", color: "#666" }}>[{contact.category}]</span>
        <button onClick={() => onDelete(contact.id)} style={{ marginLeft: "1rem", color: "red" }}>
          Delete
        </button>
      </div>
    </div>
  );
}
```

**Optional prop in action** – `{contact.email && <div>...</div>}` renders email only if present. The `Contact` interface already marks `email?` as optional.

**Now update `ContactList` to use `ContactCard`:**

```tsx
import type { Contact } from "./types";
import ContactCard from "./ContactCard";

interface ContactListProps {
  contacts: Contact[];
  onToggleFavorite: (id: number) => void;
  onDelete: (id: number) => void;
}

export default function ContactList({ contacts, onToggleFavorite, onDelete }: ContactListProps) {
  if (contacts.length === 0) {
    return <p>No contacts found.</p>;
  }

  return (
    <div>
      {contacts.map((contact) => (
        <ContactCard
          key={contact.id}
          contact={contact}
          onToggleFavorite={onToggleFavorite}
          onDelete={onDelete}
        />
      ))}
    </div>
  );
}
```

**Callback flow:** card's star button → `onToggleFavorite(contact.id)` → forwarded up to `ContactList`'s prop → forwarded up to App's `handleToggleFavorite(id)` → `setContacts(...)` → re-render → card's star updates. The card never mutates the contact; it just reports "user clicked star on id X." Same for delete. That's the whole point of callback props: the child reports, the parent decides.

**Composition** – `ContactList` renders `ContactCard` children. `key={contact.id}` on the mapped component (from 1.11). Callbacks forwarded unchanged.

### Step 7.5 — Extract `Footer` (composition with `children`)

**Think:** The bottom summary (count + Clear All button) is flexible content. Use the `children` pattern (1.6): Footer is a wrapper, App decides what goes inside.

```tsx
interface FooterProps {
  children: React.ReactNode;
}

export default function Footer({ children }: FooterProps) {
  return (
    <footer style={{ marginTop: "1rem", borderTop: "1px solid #ddd", paddingTop: "0.5rem" }}>
      {children}
    </footer>
  );
}
```

**Children pattern** (from 1.6) – `Footer` wraps whatever is passed as children. This keeps the count/clear button flexible — App controls the content, Footer controls the layout.

### Step 7.6 — Final `App.tsx` (slim, all wired)

```tsx
import { useState } from "react";
import type { Contact, Category, CategoryFilter } from "./types";
import ContactForm from "./ContactForm";
import SearchBar from "./SearchBar";
import FilterBar from "./FilterBar";
import ContactList from "./ContactList";
import Footer from "./Footer";

export default function App() {
  const [contacts, setContacts] = useState<Contact[]>([]);
  const [search, setSearch] = useState("");
  const [categoryFilter, setCategoryFilter] = useState<CategoryFilter>("all");

  const handleAdd = (name: string, phone: string, email: string, category: Category, favorite: boolean) => {
    const newContact: Contact = {
      id: Date.now(),
      name,
      phone,
      email: email.trim() === "" ? undefined : email.trim(),
      category,
      favorite,
    };
    setContacts([...contacts, newContact]);
  };

  const handleDelete = (id: number) => {
    setContacts(contacts.filter((c) => c.id !== id));
  };

  const handleToggleFavorite = (id: number) => {
    setContacts(
      contacts.map((c) => (c.id === id ? { ...c, favorite: !c.favorite } : c))
    );
  };

  const handleClearAll = () => {
    setContacts([]);
  };

  const filteredContacts = contacts.filter((contact) => {
    const matchesSearch = contact.name.toLowerCase().includes(search.toLowerCase());
    const matchesCategory = categoryFilter === "all" || contact.category === categoryFilter;
    return matchesSearch && matchesCategory;
  });

  return (
    <div style={{ maxWidth: "600px", margin: "0 auto", padding: "1rem" }}>
      <h1>Contact Book</h1>

      <ContactForm onAdd={handleAdd} />

      <SearchBar value={search} onChange={setSearch} />

      <FilterBar current={categoryFilter} onChange={setCategoryFilter} />

      <ContactList
        contacts={filteredContacts}
        onToggleFavorite={handleToggleFavorite}
        onDelete={handleDelete}
      />

      <Footer>
        <span>{contacts.length} contact{contacts.length !== 1 ? "s" : ""}</span>
        {contacts.length > 0 && (
          <button onClick={handleClearAll} style={{ marginLeft: "1rem" }}>
            Clear All
          </button>
        )}
      </Footer>
    </div>
  );
}
```

**Console check** – add contacts, search, filter by category, toggle favorite, delete. Everything works. App.tsx is now ~40 lines — all logic delegated to components via props. Notice the callback flow: every child reports events up via `onX` props; App owns all state.
