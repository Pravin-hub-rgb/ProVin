## Abhi Tak Kya Hua

1.6 mein children prop aur composition pattern seekha — Card aur Container layout components banaye. Lekin abhi tak koi interactivity nahi hai — sab static hai. Button dabane se kuch nahi hota.

## Broader Goal

React ki sabse important cheez seekhenge — **state**. Jab tak state nahi hogi, app kuch bhi yaad nahi rakh sakti. User ne kitni baar button dabaya? Kaunsa task complete hua? Sab state mein store hota hai.

## Step 1 — Problem Feel Karo

Soch: "Button dabane par count badhe. Lekin jab component re-render hota hai, toh variable reset ho jata hai. Count kaise yaad rakhe?"

`App.tsx` mein try karo:

```tsx
function App() {
  let count = 0;

  const handleClick = () => {
    count = count + 1;
    console.log(count); // console mein 1, 2, 3...
  };

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={handleClick}>Increment</button>
    </div>
  );
}
```

Console mein count badhega, lekin screen par `Count: 0` hi dikhega. Kyun?

**Problem:** `let count = 0` ek local variable hai. Jab component re-render hota hai, yeh dobara `0` set ho jata hai. React ko pata nahi chalta ki count change hua hai kyunki yeh React ke tracking system ke bahar hai.

Isliye **state** chahiye — React ko batana padta hai ki "yeh value track karo, jab change ho toh re-render karo".

### Pehle Samjho: Hook Kya Hota Hai?

`useState` ko samajhne se pehle, ek concept clear karte hain — **hook kya hota hai React mein?**

**Hook** (काँटा) ek special React function hai jo React ki features (jaise state, lifecycle) ko **function components** mein use karne deta hai. "Hook into React" — matlab React ke andar ki power se connect ho jao.

<details>
<summary><strong>Bonus — Function vs Class Component (History)</strong></summary>

React mein components banane ke do tarike hain:

**1. Function Component (jo ab tak bana rahe ho):**
```tsx
function App() {
  return <h1>Hello</h1>;
}
```
Simple JavaScript function. Props receive karta hai, JSX return karta hai.

**2. Class Component (puraana tareeka):**
```tsx
class App extends React.Component {
  render() {
    return <h1>Hello</h1>;
  }
}
```
JavaScript class. `React.Component` ko extend karta hai, `render()` method mein JSX return karta hai.

**React 16.8 (2019) se pehle:**
- Sirf **class components** state rakh sakte the (count, input value, etc. yaad rakhna)
- **Function components** "stateless" the — sirf UI dikha sakte the, kuch yaad nahi rakh sakte the

**React 16.8 mein hooks aaye:**
- `useState` jaisi hooks ne function components mein bhi state possible banayi
- Aaj kal log **function components + hooks** use karte hain
- Class components almost extinct — sirf puraane codebases mein dikhenge

Yeh history jan na zaroori nahi hai daily use ke liye, lekin samajhne mein help karta hai ki hooks kyun aaye.

### Hook ki Body — Rules aur Convention

**"use" prefix:** Har React hook `use` se shuru hota hai. React isi convention se identify karta hai:
- `useState` — state ke liye
- `useEffect` — side effects ke liye (baad mein seekhenge)
- `useContext` — context ke liye (baad mein seekhenge)

Agar tum khud ka hook banao (custom hook), toh naam bhi `use` se shuru karna padta hai. Ye React ka rule hai.

**Rules of Hooks (Reason Ke Saath):**

1. **Top level call karo** — hooks ko `if`, `for`, ya function ke andar mat daalo. Component ke top level par likho.

   **Reason:** React internally hooks ko **call order ke hisaab se** yaad rakhta hai. Har baar component render hota hai, hooks usi order mein call hone chahiye. Agar `if` ke andar daal diya:
   ```tsx
   if (count > 0) {
     useEffect(...);  // ❌ kabhi call hoga kabhi nahi — order change
   }
   ```
   React ka internal system (linked list) order par depend karta hai. Pehli render mein hook order [A, B, C] tha. Doosri render mein [A, C] ho gaya — React samjhega ki B wali state kahan gayi? Isliye hooks hamesha top level — har render mein same order.

2. **Sirf function components / custom hooks mein** — regular JavaScript functions mein hooks call nahi kar sakte.

   **Reason:** React sirf component ke render cycle ke dauran hooks ko track karta hai. Regular function ka React ke render cycle se connection nahi hai:
   ```tsx
   function handleClick() {
     const [count, setCount] = useState(0);  // ❌ yeh kahan render hoga?
   }
   ```
   React ko pata nahi ki yeh function kab call hua, kis component ke liye hai. Hook ka context (kaunsa component, kaunsa render) tabhi available hota hai jab function component directly call ho raha ho.

### Analogy: Electricity Plug Point

Socho tumhare ghar mein electricity ka **plug point** (socket) hai. Tum heater, charger, TV — sab plug point se connect karte ho. Plug point khud power nahi hai, lekin power se connect karta hai.

**Hook wahi plug point hai:**
- `useState` ek plug point hai jo **state power** se connect karta hai
- Tum component mein `useState` call karte ho → React ki state system se connect ho jate ho
- Khud state implement nahi karni padti — React karta hai

```
React [State System]  ←→  useState (plug point)  ←→  Tumhara Component
```

Bina `useState` ke, component React ki state system se connected nahi hai. Isliye local variable (`let count = 0`) React ko trigger nahi karta re-render ke liye.

## Step 2 — useState Hook

**Concept:** `useState` ek React hook hai jo state variable create karta hai. Jab state change hoti hai, component automatically re-render hota hai.

### Step-by-Step Samjho

**Step 1 — useState ko call karo, initial value do:**

```tsx
useState(0)
```

`useState` ek function hai. Isko call karte waqt hum **initial value** dete hain — jo pehli baar render par dikhega. Yahan `0` initial value hai.

**Step 2 — useState kya return karta hai?**

`useState(0)` call karne par yeh ek **array return** karta hai jisme do cheezein hoti hain:

```
useState(0) → [0, setterFunction]
                ↑     ↑
                |     setter — state change karne ka function
                |
                current value — jo bhi initial diya tha
```

Array ka:
- **Pehla element** — current value (abhi `0` hai)
- **Doosra element** — ek function jo value change karta hai (setter function)

**Step 3 — Array destructuring se dono nikaalo:**

```tsx
const [count, setCount] = useState(0);
```

Yeh array destructuring hai. 1.5.3 mein seekha tha — array ke elements ko variables mein nikaalna. Yahan:

- `count` = current value (0)
- `setCount` = function jo `count` ko change karega
- `useState(0)` = 0 se shuru karo

Agar bina destructuring ke likhte:

```tsx
const stateArray = useState(0);
const count = stateArray[0];       // pehla element — current value
const setCount = stateArray[1];    // doosra element — setter function
```

Lekin array destructuring (`[count, setCount]`) ek line mein kar deta hai. React community mein **hamesha `[value, setValue]`** pattern use hota hai — `count` / `setCount`, `name` / `setName`, `items` / `setItems`.

**Step 4 — setCount se value change karo:**

```tsx
setCount(count + 1);  // count 0 tha → 1 ho gaya
```

`setCount` React ko batata hai "ab nayi value 1 hai". React nayi value store karta hai aur component ko **re-render** karta hai. Ab `count` ki value 1 ho jati hai.

### Poora Code Ek Saath

```tsx
import { useState } from "react";   // Step 0 — import

function App() {
  const [count, setCount] = useState(0);   // Step 1-3 — state banao

  const handleClick = () => {
    setCount(count + 1);   // Step 4 — state change karo
  };

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={handleClick}>Increment</button>
    </div>
  );
}
```

**Flow dekho — kya hota hai jab button dabate ho:**

```
Initial render
  → useState(0) → count = 0
  → Screen: "Count: 0"

Button Click
  → setCount(0 + 1) → count ab 1
  → React re-render karta hai
  → useState(0) → React yaad rakhta hai ki ab count 1 hai
  → count = 1
  → Screen: "Count: 1"

Button Click again
  → setCount(1 + 1) → count ab 2
  → React re-render
  → count = 2
  → Screen: "Count: 2"
```

Console mein count badhta tha, lekin screen par nahi dikhta tha (let variable case). Ab `useState` ke saath screen bhi update hota hai kyunki React ko pata hai ki state change hui hai.

### Breakdown Ek Baar Aur

| Code | Matlab |
|------|--------|
| `useState(0)` | State banao, initial value 0 |
| `[count, setCount]` | Array destructuring — count (current), setCount (setter) |
| `count` | Current value — HTML mein use karo |
| `setCount(count + 1)` | Naya value do — React re-render karega |

## Step 3 — TypeScript Type Inference

Soch: "Step 2 mein `useState(0)` likha — TypeScript ne kaise samajh liya ki `count` ka type `number` hai?"

**Answer:** TypeScript **initial value se type infer** kar leta hai. Matlab tumhe explicitly `<number>` type batane ki zaroorat nahi — TypeScript khud dekh leta hai ki `0` ek `number` hai.

```tsx
const [count, setCount] = useState(0);
// TypeScript: "0 ek number hai → count ka type number hai"
// setCount ab sirf number accept karega — string nahi daal sakte
```

Yeh tab bhi kaam karta hai:

| Code | TypeScript infer karega |
|------|------------------------|
| `useState(0)` | `number` |
| `useState("")` (empty string) | `string` |
| `useState("Hello")` (non-empty) | `string` |
| `useState(false)` ya `useState(true)` | `boolean` |
| `useState(0.5)` (decimal) | `number` |

```tsx
const [name, setName] = useState("");     // infer → string
const [isDone, setIsDone] = useState(false); // infer → boolean
const [price, setPrice] = useState(99.99);   // infer → number
```

**Exception — Jab initial value type nahi bata sakta:**

```tsx
const [items, setItems] = useState([]); // infer → never[]
// "never[]" matlab "khali array, kuch daal nahi sakte"
```

Empty array ka type clear nahi hai — kya items `string` hain, `number`, ya objects? Isliye jab arrays/objects use karte hain toh explicit type dena padta hai. Yeh aage dekhenge.

**Rule:** Pehle hamesha `useState(0)` ya `useState("")` likho — TypeScript khud infer kar lega. Sirf tab explicit type do jab initial value sufficient nahi (jaise empty array, nullable). `<number>` jaise explicit generics ka syntax aage seekhenge — abhi ke liye inference hi kaafi hai.

## Step 4 — Counter Mini-Project

Soch: "Ek proper Counter banate hain — increment, decrement, reset, aur negative value rokna."

`src/components/Counter.tsx`:

```tsx
import { useState } from "react";

function Counter(): JSX.Element {
  const [count, setCount] = useState(0);   // infer → number

  const increment = () => {
    setCount(count + 1);
  };

  const decrement = () => {
    if (count > 0) {
      setCount(count - 1);
    }
  };

  const reset = () => {
    setCount(0);
  };

  return (
    <div>
      <h2>Counter: {count}</h2>
      <button onClick={increment}>+1</button>
      <button onClick={decrement}>-1</button>
      <button onClick={reset}>Reset</button>
    </div>
  );
}

export default Counter;
```

`App.tsx` mein import karo:

```tsx
import Counter from "./components/Counter";

function App() {
  return (
    <div>
      <h1>Mini Projects</h1>
      <Counter />
    </div>
  );
}
```

**Event handling breakdown:**

`onClick={increment}` — `onClick` ek prop hai jo function leta hai. Jab button click hota hai, React yeh function call karta hai. 

Agar aise likho:

```tsx
<button onClick={setCount(count + 1)}>+1</button> // ❌ Galat
```

Yeh function call kar dega immediately, click par nahi. Hamesha function reference do, call nahi:

```tsx
<button onClick={() => setCount(count + 1)}>+1</button> // ✅ Sahi
```

## Step 5 — Event TypeScript Typing

Soch: "Counter mein +1, -1 aur Reset buttons hain. Lekin user seedha value type karna chahega — 5, 100, 42 — manual clicks ki jagah directly number daalke set kare."

### Step 5a — Input Add Karo (Sirf UI)

Counter function mein, buttons ke neeche ek input field daalte hain:

```tsx
<input type="number" placeholder="Set count..." />
```

Browser mein check karo — input dikhega. Type karo — kuch nahi hota. Kyun? Koi event handler nahi jo typing capture kare.

### Step 5b — onChange Handler

Soch: "Jab user type kare, tab kuch capture karna padega."

**Concept — `onChange` event:** HTML elements mein `onChange` event hota hai jo har character change par trigger hota hai. React mein yeh user ke har keystroke ko catch karta hai.

Pehle sirf console mein print karte hain — event kaam kar raha hai ya nahi:

```tsx
const handleChange = (event) => {
  console.log(event.target.value);
};
```

`<input>` mein `onChange={handleChange}` add karo. Browser console open karo, input mein type karo — har character console mein aa raha hai.

TypeScript error aayega: **Parameter `event` implicitly has `any` type**. Event ka type specify nahi kiya.

### Step 5c — Event Type Add Karo

React mein har event ka ek specific TypeScript type hota hai. Input `onChange` ke liye:

```tsx
const handleChange = (event: React.ChangeEvent<HTMLInputElement>) => {
  console.log(event.target.value);
};
```

Yeh type bata raha hai:
- `ChangeEvent` — "change" event ke liye React ka generic type
- `<HTMLInputElement>` — specific DOM element: input field

Ab error nahi aayega. `event.target.value` input ki current value hai — jo bhi user type kare.

### Step 5d — Console ki Jagah State Mein Store Karo

Soch: "Console mein value print ho rahi hai. Ab use state mein store karna hai — taki React re-render kare aur screen update ho."

**Pehle kaam:** Naya state variable banao jo input ki value rakhega:

```tsx
const [inputValue, setInputValue] = useState("");  // infer → string
```

**Doosra kaam:** `handleChange` ko update karo — `console.log` ki jagah `setInputValue` call karo:

```tsx
// Pehle: console.log(event.target.value);
// Ab:
const handleChange = (event: React.ChangeEvent<HTMLInputElement>) => {
  setInputValue(event.target.value);
};
```

Har character change par `setInputValue` call hoga → `inputValue` state update → React re-render karega.

**Teesra kaam:** Input ko **controlled** banao — `value={inputValue}` add karo:

```tsx
<input
  type="number"
  value={inputValue}
  onChange={handleChange}
  placeholder="Set count..."
/>
```

Ab input ki value React state se control ho rahi hai. User type karta hai → `handleChange` → `setInputValue` → state update → React re-render → input updated.

Yeh **controlled input** pattern hai — React state source of truth hai, HTML input nahi.

---

**⚠️ Common Galati — `setCount(event.target.value)`**

Aap soch sakte ho: "Count hi toh set karna hai, `inputValue` ki alag state kyun banayein? Directly `setCount` karo na":

```tsx
// ❌ GALI — typing input se directly count set karna
const handleChange = (event: React.ChangeEvent<HTMLInputElement>) => {
  setCount(event.target.value);
};
```

Chalao toh kaam karta dikhega. Lekin bug hai:

- `event.target.value` hamesha **`string`** hota hai — chahe `type="number"` ho
- `useState(0)` ne `count` ka type `number` infer kiya
- Aap `string` pass kar rahe ho → `count` string ban gaya

Ab `count + 1` **string concatenation** ban gaya, numeric addition nahi:

| Action | `count` ki value | Kyun? |
|--------|-----------------|-------|
| Input mein "5" likha | `"5"` (string!) | `event.target.value` string hai |
| Increment click | `"51"` | `"5" + 1` → concatenation |
| Increment phir se | `"511"` | `"51" + 1` → concatenation |

**Sahi approach — do alag state kyun?**

| State | Type | Kis liye? |
|-------|------|-----------|
| `count` | `number` | Final count value — display + calculation |
| `inputValue` | `string` | Input ki raw text — user jo bhi type kar raha hai (invalid bhi ho sakti hai, jaise "abc") |

Alag state ka matlab hai ki input mein kuch bhi type kar sakte ho, aur tabhi count set karo jab validate ho jaye. Step 5e mein yahi karenge.

### Step 5e — Set Button

"Set" button chahiye jo input value ko count mein daal de:

```tsx
const setFromInput = () => {
  const num = parseInt(inputValue, 10);
  if (!isNaN(num)) {
    setCount(num);
    setInputValue("");
  }
};
```

Line by line:
- `parseInt(inputValue, 10)` — string "25" ko number 25 mein convert karo. `10` = decimal system
- `!isNaN(num)` — "is Not a Number". Agar valid number hai toh hi set karo. "abc" → `isNaN` true → set nahi hoga
- `setCount(num)` — count update
- `setInputValue("")` — input clear karo

Button mein `onClick={setFromInput}` add karo.

### Poora Counter Ab Aisa Dikhta Hai

```tsx
import { useState } from "react";

function Counter(): JSX.Element {
  const [count, setCount] = useState(0);
  const [inputValue, setInputValue] = useState("");

  const handleChange = (event: React.ChangeEvent<HTMLInputElement>) => {
    setInputValue(event.target.value);
  };

  const setFromInput = () => {
    const num = parseInt(inputValue, 10);
    if (!isNaN(num)) {
      setCount(num);
      setInputValue("");
    }
  };

  return (
    <div>
      <h2>Counter: {count}</h2>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={() => setCount(count > 0 ? count - 1 : 0)}>-1</button>
      <button onClick={() => setCount(0)}>Reset</button>
      <div>
        <input
          type="number"
          value={inputValue}
          onChange={handleChange}
          placeholder="Set count..."
        />
        <button onClick={setFromInput}>Set</button>
      </div>
    </div>
  );
}
```

Browser mein test karo — "25" type karo, Set dabao → count 25. "abc" type karo → kuch nahi hoga (invalid number).

### Common Event Types — Reference

| Event | TypeScript Type |
|---|---|
| Input change | `React.ChangeEvent<HTMLInputElement>` |
| Button click | `React.MouseEvent<HTMLButtonElement>` |
| Form submit | `React.FormEvent<HTMLFormElement>` |
| Key press | `React.KeyboardEvent<HTMLInputElement>` |

React ke saare event types `React` namespace mein hain. `<HTMLInputElement>` generic part — kaunsa DOM element event trigger kar raha hai. 1.8 Generics chapter mein detail mein samjhenge.

## Step 6 — Controlled Input Form

Soch: "Ab tak ek hi component mein state + events sikh gaye. Lekin real apps mein form data parent component tak bhejna hota hai — controlled input + callback pattern ka practice karte hain."

### Step 6a — Sirf UI Banao (No State, No Props)

Ek form component chahiye. Pehle sirf UI — koi state nahi, koi functionality nahi:

`src/components/GreetingForm.tsx`:

```tsx
function GreetingForm() {
  return (
    <div>
      <input type="text" placeholder="Enter your name..." />
      <button>Submit</button>
    </div>
  );
}

export default GreetingForm;
```

`App.tsx` mein import karo:

```tsx
import Counter from "./components/Counter";
import GreetingForm from "./components/GreetingForm";

function App() {
  return (
    <div>
      <h1>Mini Projects</h1>
      <Counter />
      <GreetingForm />
    </div>
  );
}
```

Browser mein check karo — input + button dikhega. Type bhi kar sakte ho. Lekin Submit dabane se kuch nahi hota — koi handler nahi hai.

### Step 6b — State Add Karo (Controlled Input)

Soch: "Input ki value capture karni hai. Submit dabe tab parent ko bhejni hai."

Pehle input ko controlled banao — state + onChange:

```tsx
import { useState } from "react";

function GreetingForm() {
  const [name, setName] = useState("");  // infer → string

  return (
    <div>
      <input
        type="text"
        value={name}
        onChange={(e) => setName(e.target.value)}
        placeholder="Enter your name..."
      />
      <button>Submit</button>
    </div>
  );
}
```

- `value={name}` — input ki value state se aati hai
- `onChange={(e) => setName(e.target.value)}` — user type kare → setName update → React re-render

### Step 6c — Callback Prop Add Karo

Soch: "Data capture ho raha hai. Lekin Submit dabe to parent ko kaise bhejein?"

1.5.4 mein callback prop seekha tha — parent ek function pass karta hai, child use call karta hai:

```tsx
interface GreetingFormProps {
  onSubmit: (name: string) => void;
}

function GreetingForm({ onSubmit }: GreetingFormProps) {
  // ...
}
```

`onSubmit` ek callback hai jo parent ko name string bhejta hai. Parent decide karega ki data ke saath kya karna hai.

### Step 6d — Submit Handler

Soch: "Button dabe to teen kaam karne hain — validate karo, callback call karo, input clear karo."

```tsx
const handleSubmit = () => {
  if (name.trim() !== "") {
    onSubmit(name);
    setName("");
  }
};
```

- `name.trim()` — whitespace hatao ("  Vin  " → "Vin")
- `!== ""` — agar empty nahi hai toh hi submit karo
- `onSubmit(name)` — parent ko data bhejo
- `setName("")` — input clear karo, agla naam type karne ke liye

Button mein `onClick={handleSubmit}` add karo.

### Final GreetingForm

```tsx
import { useState } from "react";

interface GreetingFormProps {
  onSubmit: (name: string) => void;
}

function GreetingForm({ onSubmit }: GreetingFormProps) {
  const [name, setName] = useState("");

  const handleSubmit = () => {
    if (name.trim() !== "") {
      onSubmit(name);
      setName("");
    }
  };

  return (
    <div>
      <input
        type="text"
        value={name}
        onChange={(e) => setName(e.target.value)}
        placeholder="Enter your name..."
      />
      <button onClick={handleSubmit}>Submit</button>
    </div>
  );
}

export default GreetingForm;
```

### App.tsx Mein Use Karo

```tsx
function App() {

    alert(`Hello, ${name}!`);
  };

  return (
    <div>
      <h1>Mini Projects</h1>

```

Browser mein test karo — "Vin" type karo, Submit dabao → "Hello, Vin!" alert. Input automatically clear ho gaya. Empty submit karo → kuch nahi hota, validation rok raha hai.

### Recap — Controlled Input Form

| Concept | Code | Kaam |
|---------|------|------|
| Controlled input | `value={name}` + `onChange` | Input ki value React state se aati hai |
| Trim validation | `name.trim() !== ""` | Empty submit rokta hai |
| Clear after submit | `setName("")` | Input clean, next value ready |
| Callback | `onSubmit(name)` | Child → parent data bhejta hai |

## Summary

- `useState` — state variable create karta hai, change par re-render trigger karta hai
- Syntax: `const [state, setState] = useState(initialValue)` — Type typeScript infer karta hai
- Array destructuring — `state` (current value), `setState` (update function)
- Event types: `React.ChangeEvent<HTMLInputElement>`, `React.MouseEvent<HTMLButtonElement>`
- Controlled input: `value` + `onChange` — React state se input controlled hota hai
- Type inference: TypeScript initial value se type infer kar leta hai (mostly)
