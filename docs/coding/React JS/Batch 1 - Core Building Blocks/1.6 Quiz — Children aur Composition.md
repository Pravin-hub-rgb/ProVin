
## MCQ

Q: Agar tum `<Card content="<h1>Title</h1>" />` likho to browser mein kya dikhega?
A. Ek bada heading render hoga "Title" — React strings ko HTML mein convert karta hai
B. Kuch nahi dikhega — React error dega kyunki string mein HTML tags allowed nahi hain
C. Literally "<h1>Title</h1>" text dikhega — React strings ko HTML escape karta hai
D. Heading render hoga lekin styling nahi lagegi — kyunki inline HTML reject hota hai
> C. React JSX mein strings ko HTML escape karta hai — XSS attacks se bachne ke liye. `<h1>` aur `</h1>` actual HTML elements nahi, sirf text characters hain. Isliye `<Card>` ke andar direct JSX daalo, string mein nahi.

Q: `children` prop kaise kaam karti hai?
A. `children` ek function hai jo component ke children elements ko delete karta hai
B. `children` ek special prop hai — React automatically beech ka content assign karta hai
C. `children` ek method hai jisme manually har child element pass karna padta hai
D. `children` sirf class components mein kaam karti hai function components mein nahi
> B. Component ke opening aur closing tag ke beech jo bhi content likho, React automatically use `children` prop mein daal deta hai. `<Card><p>Hi</p></Card>` → `props.children` = `<p>Hi</p>`.

Q: `React.ReactNode` type kis cheez ke liye use hota hai?
A. Sirf strings accept karne ke liye — numbers aur boolean reject ho jaate hain
B. Sirf JSX elements accept karne ke liye — strings aur numbers allowed nahi hain
C. Kuch bhi jo React render kar sakta hai — string, number, JSX, null, array sab
D. Sirf arrays accept karne ke liye — multiple children ke liye yeh type use hota hai
> C. `React.ReactNode` ek union type hai — `string | number | boolean | null | undefined | JSX.Element | ReactNode[] | ReactPortal`. Isliye children prop ke liye perfect hai — kuch bhi ho sakta hai jo React render kare.

Q: Agar component ke andar do children hain to React unhe kaise treat karta hai?
A. React error dega — component sirf ek child accept kar sakta hai multiple nahi

C. Sirf pehla child render hota hai baaki ignore ho jaate hain
D. React automatically do naye components bana kar unme divide kar deta hai
> B. Single child = ek element. Multiple children = array. `React.ReactNode` dono cases handle kar leta hai. Isliye children prop flexible hai — ek bhi child ho ya hazaar, kaam karega.

Q: `children` naam change karna possible hai? Kya farak padta hai?
A. Naam change nahi kar sakte — `children` hi likhna mandatory hai React mein
B. Kar sakte ho lekin auto-assign ka feature nahi milega — explicitly pass karna padega
C. Naam change karne se component ki performance improve hoti hai
D. Kar sakte ho aur koi farak nahi padta — auto-assign har naam ke saath kaam karta hai
> B. Agar `children` ki jagah `content` likho to `<Card><p>Hi</p></Card>` se `content` undefined rahega. React sirf `children` naam ko hi auto-assign karta hai. Custom naam ke saath explicitly pass karna padega — `<Card content={<p>Hi</p>} />`.

A. Normal prop sirf strings le sakta hai children sirf JSX elements le sakta hai

Q: Composition pattern do tarike se kaam karta hai — props ke through aur children ke through. Farak kya hai?
A. Props-based composition sirf numbers ke saath kaam karta hai, children-based sirf strings ke saath
B. Props-based mein component explicitly attribute deta hai, children-based mein React auto-assign karta hai beech ka content
C. Dono ek hi cheez hain — sirf syntax alag hai, internally same hota hai

Q: React ka "composition over inheritance" philosophy ka kya matlab hai?

> B. React recommend karta hai ki components ko ek doosre ke andar daalo (composition), na ki "extends" karo (inheritance). Jaise `<Card><Avatar /></Card>` — Card ne Avatar ko extend nahi kiya, andar daal diya. Yeh inheritance se zyada flexible hai.

## TrueFalse

Q: `children` React ka reserved keyword hai — koi aur naam use nahi kar sakte.
- True
- False
> False. `children` reserved keyword nahi hai — sirf ek special prop name hai. Tum koi aur naam bhi use kar sakte ho (jaise `content`), lekin tab auto-assign ka feature nahi milega. React sirf `children` naam ko hi automatically assign karta hai.

Q: React JSX mein strings ko HTML escape karta hai — iska matlab `<h1>` text ki tarah dikhega, rendered heading nahi.
- True
- False
> True. React security ke liye strings ko HTML escape karta hai. `<Card content="<h1>Hi</h1>" />` mein `<h1>` actual heading nahi banega — screen par "<h1>Hi</h1>" text dikhega. XSS attacks se bachne ke liye yeh behavior hai.

Q: Agar component ke andar ek hi child hai to children prop ek single element hota hai, agar multiple hain to array hota hai.
- True
- False
> True. Single child: `children = <p>Hello</p>` (JSX.Element). Multiple children: `children = [<h1>Title</h1>, <p>Content</p>]` (array). `React.ReactNode` dono cases ko handle kar leta hai.

---

Q: `React.ReactNode` sirf JSX elements ke liye use hota hai — strings, numbers, null accept nahi karta.
- True
- False
> False. `React.ReactNode` ek union type hai jo sab kuch accept karta hai jo React render kar sakta hai — string, number, boolean, null, undefined, JSX.Element, array of nodes, portals. Isliye children prop ke liye perfect hai.

---

Q: React mein composition sirf children prop ke through hota hai — props ke through component combine nahi kar sakte.
- True
- False
> False. Composition do tarike se hota hai: (1) props ke through — `<Avatar name="Vin" />` — Avatar ko name prop de kar UserCard mein combine kiya (2) children ke through — `<Card>content</Card>` — card ke andar kuch bhi wrap kiya. Dono composition hain.

---

Q: "Composition over inheritance" ka matlab hai ki components ko ek doosre ke andar daalna chahiye, extend nahi karna chahiye.
- True
- False
> True. React ka philosophy hai ki class-based inheritance (`class Dog extends Animal`) ki jagah composition use karo. `<Card><Avatar /></Card>` — Card ne Avatar ko extend nahi kiya, andar daal diya. Yeh zyada flexible, testable aur maintainable hota hai.

## ShortAnswer

Q: `children` prop kya hai? Normal prop aur children prop mein fark kya hai? Examples ke saath explain karo.

<details>
<summary>Sample Answer</summary>

**`children` prop** ek special prop hai — component ke opening aur closing tag ke beech ka content React automatically `children` mein daal deta hai.

**Normal Prop vs Children Prop:**

| Feature | Normal Prop | Children Prop |
|---------|-------------|---------------|
| Kaise pass karte ho | `<Card title="Hello" />` | `<Card>Hello</Card>` |
| Kaise receive karte ho | `props.title` | `props.children` |
| Auto-assign? | ❌ Explicitly likhna padta hai | ✅ React automatically le leta hai |
| Kab use karo | Specific data (string, callback, ID) | Arbitrary JSX content wrap karna ho |

**Example — Dono ek saath:**
```tsx
interface CardProps {
  children: React.ReactNode;
  title?: string;
}

function Card({ children, title }: CardProps) {
  return (
    <div className="card">
      {title && <h3>{title}</h3>}
      {children}
    </div>
  );
}

// Use:
<Card title="Tasks">
  <p>Review PR</p>
  <p>Write tests</p>
</Card>
```

</details>

Q: Layout component kya hota hai? Composition pattern kaise kaam karta hai? Example do.

<details>
<summary>Sample Answer</summary>

**Layout component** sirf structure provide karta hai — styling, border, padding, width. Content nahi deta, children ke through aata hai.

**Example — Container layout:**
```tsx
interface ContainerProps {
  children: React.ReactNode;
}

function Container({ children }: ContainerProps) {
  return (
    <div style={{ maxWidth: "600px", margin: "0 auto", padding: "20px" }}>
      {children}
    </div>
  );
}
```

**Composition pattern** — chhote components ko combine karke bade components banana:
```tsx
<Container>
  <Card title="Today's Tasks">
    <p>Review PR</p>
  </Card>
  <Card>
    <p>Deploy to staging</p>
  </Card>
</Container>
```

Yahan:
- `Container` — layout deta hai (max-width, center)
- `Card` — layout deta hai (border, padding, title)
- Content — children ke through aata hai

Har component focused hai — ek hi kaam karta hai. Combine karke poora UI banate hain. Yahi composition hai.

</details>

Q: React mein composition ke do tarike kya hain? Har tarike ka ek example do aur explain karo ki "composition over inheritance" ka kya matlab hai.

<details>
<summary>Sample Answer</summary>

**Composition ke do tarike:**

**1. Props ke through (Data-based composition):**
Ek component doosre component ko specific props dekar combine karta hai.
```tsx
function Avatar({ name }: { name: string }) {
  return <img src={`https://api.dicebear.com/7.x/initials/svg?seed=${name}`} alt={name} />;
}

function UserCard({ name, role }: { name: string; role: string }) {
  return (
    <div className="card">
      <Avatar name={name} />
      <h3>{name}</h3>
      <p>{role}</p>
    </div>
  );
}
```
Yahan `UserCard` ne `Avatar` ko props dekar combine kiya. UserCard decide karta hai ki Avatar ko kya data chahiye.

**2. Children ke through (Wrapper composition):**
Component children prop leta hai aur koi bhi content wrap karta hai.
```tsx
function Card({ children }: { children: React.ReactNode }) {
  return <div className="card">{children}</div>;
}

<Card>
  <UserCard name="Vin" role="Developer" />
</Card>
```
Yahan Card sirf wrapper hai — use nahi pata ki andar kya hai. Content children ke through aata hai.

**Composition over inheritance:**
React recommend karta hai ki components ko ANDAR daalo (compose) na ki EXTEND karo (inherit).
- Inheritance: `class Dog extends Animal { /* override methods */ }` — tight coupling
- Composition: `<Card><Avatar /></Card>` — loose coupling, flexible, easy to test

React docs bhi kehti hai: "Use composition instead of inheritance."

</details>
