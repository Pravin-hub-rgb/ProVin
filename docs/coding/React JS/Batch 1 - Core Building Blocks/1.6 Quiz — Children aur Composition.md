
## MCQ

Q: If you write `<Card content="<h1>Title</h1>" />`, what shows up in the browser?
A. A large heading "Title" renders — React converts strings to HTML
B. Nothing renders — React throws an error because HTML tags aren't allowed in strings
C. The literal text "<h1>Title</h1>" appears — React escapes strings to prevent XSS
D. The heading renders but without styling – inline HTML is rejected
> C. React JSX escapes strings to prevent XSS (Cross-Site Scripting) attacks. `<h1>` and `</h1>` are just text characters, not real HTML elements. If you want actual JSX to render, pass it as children: `<Card><h1>Title</h1></Card>`.

Q: How does the `children` prop work?
A. `children` is a function that deletes elements from the component's children
B. `children` is a special prop — React automatically assigns content between tags
C. `children` is a method where you manually pass each child element
D. `children` only works in class components, not in function components
> B. Whatever you write between a component's opening and closing tags is automatically captured by React into the `children` prop. `<Card><p>Hi</p></Card>` → `props.children` = `<p>Hi</p>`.

Q: When is `React.ReactNode` type used?
A. Only for strings — numbers and booleans are rejected
B. Only for JSX elements — strings and numbers aren't allowed
C. For anything React can render — strings, numbers, JSX, null, arrays
D. Only for arrays — multiple children require this type
> C. `React.ReactNode` is a union type: `string | number | boolean | null | undefined | JSX.Element | ReactNode[] | ReactPortal`. It accepts anything React can render — perfect for the `children` prop since it can be anything.

Q: If a component has two children inside it, how does React treat them?
A. React throws an error — a component can only accept one child
B. React wraps both children into an array for `props.children`
C. Only the first child renders; the rest are ignored
D. React creates two new components, splitting the children
> B. Single child = a single element. Multiple children = an array. `React.ReactNode` handles both cases, which is why the children prop is flexible — one child or a thousand, it works.

Q: Can you rename the `children` prop? Does it matter?
A. No — `children` is a mandatory keyword in React
B. Yes, but auto-assignment stops working — you'd pass it explicitly
C. Yes, and it improves component performance
D. Yes, and it still works the same — auto-assignment works with any name
> B. If you rename `children` to `content`, then `<Card><p>Hi</p></Card>` leaves `content` as undefined. React only auto-assigns to `children`. With a custom name, you'd need to pass it explicitly: `<Card content={<p>Hi</p>} />`.

Q: What is the main difference between a normal prop and the children prop?
A. Normal props only accept strings; children only accept JSX elements
B. Normal props are explicit attributes; children are auto-assigned by React
C. Normal props only accept numbers; children only accept functions
D. Normal props and children are identical — just different syntax
> B. Normal props are written as attributes: `<Card title="Hello" />`. Children are React's auto-assigned content between tags: `<Card>Hello</Card>`. Normal props carry specific data; children carry wrapped content.

Q: What is a layout component?

B. A component that provides structure only – not content
C. A component that only renders on mobile devices
D. A component that displays different content on each page
> B. A layout component (like `Container`, `Card`) provides structure — borders, padding, width, styling. The actual content comes through children. `<Container><h1>App</h1></Container>` — Container provides layout, `h1` is the content.

Q: What is the composition pattern in React?
A. Styling a component by wrapping it in CSS classes
B. Building bigger components by combining smaller ones – via children
C. Splitting a component into separate files and importing/exporting
D. Deleting a component and replacing it with a new one
> B. Composition means building bigger components by combining smaller, focused ones. `<Card title="Tasks"><p>Task 1</p></Card>` — Card is a layout component, its content comes through children. This is the composition pattern.

Q: Composition in React works in two ways – via props and via children. What's the difference?
A. Props-based composition only works with numbers; children-based composition only works with strings
B. In props-based composition the parent explicitly passes attributes; in children-based, React auto-assigns content between tags
C. They're identical – just a syntax difference, nothing different internally
D. Props-based composition only works in class components; children-based only in function components
> B. Props-based composition: `<Avatar name="Vin" />` – the parent explicitly passes the `name` attribute. Children-based composition: `<Card>content</Card>` – React auto-assigns the content between tags to `children`. Both are composition, but through different mechanisms.

Q: What does "composition over inheritance" mean in React?
A. Inheritance is not allowed in React – it throws an error
B. Put components inside each other instead of extending them
C. Classes are better than functions in React
D. Composition only works in class components; inheritance only in function components
> B. React recommends nesting components inside each other (composition) instead of extending classes (inheritance). `<Card><Avatar /></Card>` – Card wraps Avatar rather than extending it. This is more flexible, testable, and maintainable.

## TrueFalse

Q: `children` is a reserved React keyword – you cannot use any other name.
- True
- False
> False. `children` is not a reserved keyword – it's just a special prop name. You can use other names (like `content`), but auto-assignment won't work. React only auto-assigns to `children`.

---

Q: React escapes strings in JSX – meaning `<h1>` in a string appears as literal text, not a rendered heading.
- True
- False
> True. React escapes strings to prevent XSS attacks. `<Card content="<h1>Hi</h1>" />` displays the literal text "<h1>Hi</h1>" on screen, not a heading. To render actual JSX, pass it as children.

---

Q: If a component has one child, `children` is a single element; if multiple, it becomes an array.
- True
- False
> True. Single child: `children = <p>Hello</p>` (JSX.Element). Multiple children: `children = [<h1>Title</h1>, <p>Content</p>]` (array). `React.ReactNode` handles both cases.

---

Q: `React.ReactNode` only accepts JSX elements – strings, numbers, and null are rejected.
- True
- False
> False. `React.ReactNode` is a union type that accepts everything React can render – strings, numbers, booleans, null, undefined, JSX elements, arrays of nodes, portals. It's the most flexible type for children.

---

Q: Composition in React only works through the `children` prop – you can't combine components via props.
- True
- False
> False. Composition works two ways: (1) via props – `<Avatar name="Vin" />` – UserCard passes a name to Avatar; (2) via children – `<Card>content</Card>` – Card wraps arbitrary content. Both are composition.

- True
- False
> True. React recommends nesting components inside each other (composition) instead of using class-based inheritance (`class Dog extends Animal`). `<Card><Avatar /></Card>` – Card wraps Avatar rather than extending it. This approach is more flexible, testable, and maintainable.

## ShortAnswer

Q: What is the `children` prop? What is the difference between a normal prop and the children prop? Include examples.

<details>
<summary>Sample Answer</summary>

**`children` prop** is a special prop that captures whatever content is placed between a component's opening and closing tags. React automatically assigns it.

**Normal Prop vs Children Prop:**

| Feature | Normal Prop | Children Prop |
|---------|-------------|---------------|
| How you pass it | `<Card title="Hello" />` | `<Card>Hello</Card>` |
| How you receive it | `props.title` | `props.children` |
| Auto-assigned? | ❌ Must write explicitly | ✅ React grabs content between tags |
| When to use | Specific data (string, callback, ID) | Arbitrary JSX content to wrap |

**Example – both together:**
```tsx
interface CardProps {
  children: React.ReactNode;
  title?: string;
}

function Card({ children, title }: CardProps) {
  return (
    <div className="card">
      {title && <h3>{title}</h3>}
      {children}
    </div>
  );
}

// Use:
<Card title="Tasks">
  <p>Review PR</p>
  <p>Write tests</p>
</Card>
```

</details>

Q: What is a layout component and how does the composition pattern work? Give an example.

<details>
<summary>Sample Answer</summary>

**Layout component** provides structure only – borders, padding, width, styling. It receives content through `children` and doesn't produce content itself.

**Example – Container layout component:**
```tsx
interface ContainerProps {
  children: React.ReactNode;
}

function Container({ children }: ContainerProps) {
  return (
    <div style={{ maxWidth: "600px", margin: "0 auto", padding: "20px" }}>
      {children}
    </div>
  );
}
```

**Composition pattern** – building bigger components by combining smaller ones:
```tsx
<Container>
  <Card title="Today's Tasks">
    <p>Review PR</p>
  </Card>
  <Card>
    <p>Deploy to staging</p>
  </Card>
</Container>
```

Here:
- `Container` provides layout (max-width, centered)
- `Card` provides layout (border, padding, title)
- Content comes through children

Each component is focused on one job. They combine to render the full UI. That's composition.

**Composition has two approaches:**
1. **Via props** – `<Avatar name="Vin" />` – parent passes data to child
2. **Via children** – `<Card>content</Card>` – React auto-assigns wrapped content

</details>

Q: Explain the two ways composition works in React. Give an example of each, and explain what "composition over inheritance" means.

<details>
<summary>Sample Answer</summary>

**Two ways composition works in React:**

**1. Via Props (Data-based composition):**
A parent component passes specific data to a child component through props.
```tsx
function Avatar({ name }: { name: string }) {
  return <img src={`https://api.dicebear.com/7.x/initials/svg?seed=${name}`} alt={name} />;
}

function UserCard({ name, role }: { name: string; role: string }) {
  return (
    <div className="card">
      <Avatar name={name} />
      <h3>{name}</h3>
      <p>{role}</p>
    </div>
  );
}
```
Here `UserCard` composes `Avatar` by passing the `name` prop. UserCard decides what data Avatar needs.

**2. Via Children (Wrapper composition):**
A parent passes arbitrary content to a child component between its tags.
```tsx
function Card({ children }: { children: React.ReactNode }) {
  return <div className="card">{children}</div>;
}

<Card>
  <UserCard name="Vin" role="Developer" />
</Card>
```
Here Card is a wrapper – it doesn't know what's inside, it just provides layout. Content comes through children.

**Composition over inheritance:**
React recommends composing components (putting them inside each other) instead of extending classes. Instead of `class UserCard extends BaseCard`, you write `<Card><UserCard /></Card>`. This creates loose coupling, is easier to test, and is more flexible than rigid inheritance hierarchies.

</details>
