## Abhi Tak Kya Hua

1.2 mein pehla component `ProfileCard` banaya — ek function jo capital letter se shuru hota hai aur JSX return karta hai. `App()` ke andar `<ProfileCard />` likh ke use kiya. Sab kuch ek hi file mein tha — `App.tsx`. Lekin real projects mein code alag-alag files mein split hota hai. Iske liye **import/export** system chahiye.

## Broader Goal

Tumne ab tak ek file mein code likha. Lekin jab project 10, 50, 100 files ka ho jayega, toh ek file doosri file ki cheezein kaise use karegi? Browser by default ek file ke variables ko doosri file mein nahi jaane deta. Isliye JavaScript ka **module system** hai — `export` bhejta hai, `import` laata hai. Pehle simple values/functions se shuru karenge, phir React components tak build up karenge.

## Step 1 — Problem Feel Karo

Soch: "Maine `data.ts` mein ek variable banaya `const name = "Vin"`. Toh `App.tsx` mein `name` kaise use karun?"

Browser mein har file ka apna **scope** hota hai — variables ek file se doosri file mein automatically accessible nahi hote. Agar `App.tsx` mein `console.log(name)` likho toh error aayegi — "name is not defined".

Isliye JavaScript ka module system hai — do simple words:

- **`export`** — "yeh cheez file se bahar jayegi" (bhej rahe ho)
- **`import`** — "yeh cheez doosri file se aayegi" (le rahe ho)

## Step 2 — Sabse Simple: Ek Variable Export/Import

Soch: "Ek string variable ko doosri file mein bhejna hai. Kaise?"

`data.ts`:

```ts
export const name = "Vin";
```

`App.tsx`:

```tsx
import { name } from "./data";

console.log(name); // "Vin"
```

**Export:** `export` keyword variable ke aage laga diya.

**Import:** `import { name } from "./data"` — curly braces `{ }` ke andar wahi naam jo export kiya tha. `"./data"` relative path hai — "current folder ke andar `data.ts`".

Path `.ts` extension nahi likhte — TypeScript automatically figure out kar leta hai.

> **"Restaurant menu" analogy:** `export` = menu mein item daalna. `import` = waiter ko order batana — menu se wahi naam bolna jo menu mein likha hai. (`export const name = "Vin"` → menu mein "name" naam se item hai. Waiter se `{ name }` ka order karo.)

## Step 3 — Multiple Values Export Karna

Soch: "Sirf name nahi, age bhi bhejni hai. Kya alag-alag export kar sakta hoon?"

**Concept — Named Export:** Ek file multiple cheezein export kar sakti hai. Har export ka apna naam hota hai.

`data.ts`:

```ts
export const name = "Vin";
export const age = 25;
export const isStudent = true;
```

`App.tsx`:

```tsx
import { name, age, isStudent } from "./data";

console.log(name);      // "Vin"
console.log(age);       // 25
console.log(isStudent); // true
```

Ya ek saath import nahi karna chahte toh selective bhi kar sakte ho:

```tsx
import { name } from "./data";    // sirf name chahiye
import { age, isStudent } from "./data";  // ya components separately
```

**Key Rules:**
- Import karte waqt naam **exactly match** karna chahiye — `name` export kiya to `{ name }` import karna padega
- Selective import — jitne chahiye utne le sakte ho
- `{ name }` mein curly braces ka matlab "named import" — file mein se specific naam ki cheez khoj rahe ho

## Step 4 — Functions Export Karna

Soch: "Variable toh export ho gaya. Function bhi export kar sakta hoon?"

Bilkul. Function export ka same pattern hai — `export` function ke aage laga do.

`utils.ts`:

```ts
export function greet(name: string) {
  return `Hello, ${name}!`;
}

export function add(a: number, b: number) {
  return a + b;
}
```

`App.tsx`:

```tsx
import { greet, add } from "./utils";

console.log(greet("Vin"));  // "Hello, Vin!"
console.log(add(2, 3));     // 5
```

### Inline Export vs Export at Bottom

Function ko define karte waqt hi export kar sakte ho (inline), ya alag se bottom mein:

```ts
// Style 1 — inline (most common)
export function greet(name: string) {
  return `Hello, ${name}!`;
}

// Style 2 — alag se export
function greet(name: string) {
  return `Hello, ${name}!`;
}
export { greet };  // ya export { greet as hello }
```

Dono same kaam karte hain. Inline style zyada common hai — ek hi jagah define + export ho jata hai.

## Step 5 — Default Export

Soch: "Har file sirf ek hi "main" cheez export kare — jaise `App.tsx` ka `App` component. Toh har baar `{ }` likhne ki zaroorat nahi honi chahiye?"

**Concept — Default Export:** Jab ek file ki **sabse important cheez** ek hi ho. Default export ko bina curly braces ke import karte hain.

`config.ts`:

```ts
const appName = "ProVin";
export default appName;
```

`App.tsx`:

```tsx
import appName from "./config";

console.log(appName); // "ProVin"
```

Dekho — `{ appName }` nahi likhna pada. Sirf `appName`. Aur file mein export default alag naam ka bhi ho sakta hai:

```ts
const xyz = "ProVin";
export default xyz;  // variable ka naam kuch bhi ho
```

```tsx
import appName from "./config";  // import karte waqt tum apna naam de sakte ho
import anything from "./config"; // ✅ allowed — default import ka naam tum choose karte ho
console.log(appName); // "ProVin"
console.log(anything); // "ProVin"
```

**Default vs Named — Foundation Difference:**

| | Named Export | Default Export |
|---|---|---|
| Syntax | `export const name = "Vin"` | `const name = "Vin"; export default name` |
| Import | `{ name }` — naam exactly match | `anything` — naam tum choose karo |
| Per file | Multiple | Sirf ek |
| Use case | Utility functions, constants, types | Main component, main class |

### Common Mistake — Direct Default Export with const

Yeh **galat** hai:

```ts
export default const appTitle = "ProVin"; // ❌ Syntax error
```

Kyun? JavaScript mein `export default` ke baad **expression** aata hai, declaration nahi. `const/let/var` declaration hai, expression nahi.

```ts
// ✅ Sahi — expression
export default "ProVin";
export default 42;
export default { name: "Vin" };

// ✅ Sahi — pehle declare, phir export
const appTitle = "ProVin";
export default appTitle;

// ✅ Sahi — anonymous function (yeh expression hai)
export default function() { return "hello"; }
```

**Exception:** Sirf `export default function greet() {}` kaam karta hai (named function declaration). Yeh JavaScript ka historical exception hai — function declarations ko `export default` ke saath allow kiya gaya hai. Lekin `const`/`let`/`var` ke saath nahi.

**Rule of thumb:** Default export ke liye pehle variable declare karo, phir alag line mein `export default variableName` likho. Ya seedha value/expression daalo.

## Step 6 — Ab React Component Par Apply Karte Hain

Soch: "Variables aur functions toh export ho gaye. React component bhi toh function hi hai — capital letter wala. Toh same pattern se export hoga?"

Haan, exactly same. Component ek function hai jo JSX return karta hai:

`ProfileCard.tsx`:

```tsx
function ProfileCard() {
  return <div>Hello from ProfileCard</div>;
}

export default ProfileCard;  // component ka default export
```

`App.tsx`:

```tsx
import ProfileCard from "./ProfileCard";

function App() {
  return <ProfileCard />;
}

export default App;
```

**Component files ka standard pattern:**
- File sirf ek hi component export karti hai — isliye **`export default`** perfect fit hai
- Component ka naam aur file ka naam same rakho — `ProfileCard.tsx` → export `ProfileCard`
- `App.tsx` bhi `export default App` karti hai — har app ka entry point

### Default Import Naam Flexibility

Default import ka naam tum khud choose kar sakte ho:

```tsx
import Card from "./ProfileCard";       // ✅ allowed
import MyComponent from "./ProfileCard"; // ✅ allowed
```

Lekin convention hai ki wahi naam rakho jo component/file ka hai — code padhne mein aasan rehta hai. Is course mein bhi yahi follow karenge.

## Step 7 — Default + Named Export Ek Saath

Soch: "Component to default export kiya. Lekin us component ke saath kuch helper functions bhi export karne hain — jaise type interface ya constants. Named export se add kar sakte hain?"

Haan — ek file mein **ek `default` + multiple `named`** exports ho sakte hain.

`ProfileCard.tsx`:

```tsx
export default function ProfileCard() {
  return <div>Profile</div>;
}

export function ProfileImage() {
  return <img src="..." alt="profile" />;
}

export const MAX_CARDS = 10;
```

Import:

```tsx
import ProfileCard, { ProfileImage, MAX_CARDS } from "./ProfileCard";
```

Default import bina curly braces ke, named imports curly braces ke saath. Ek line mein dono aa sakte hain.

## Step 8 — Import Rename (as keyword)

Soch: "Agar do alag files mein same naam export ho raha ho — `greet` function `utils.ts` mein bhi aur `helpers.ts` mein bhi — toh conflict kaise solve karein?"

`as` keyword se import ka naam badal sakte ho:

```tsx
import { greet as greetFromUtils } from "./utils";
import { greet as greetFromHelpers } from "./helpers";

greetFromUtils("Vin");   // Hello, Vin!
greetFromHelpers("Vin"); // Hey, Vin!
```

## Step 9 — import type

Soch: "Interface bhi export karna hai. Lekin interface runtime mein exist nahi karta — sirf TypeScript compile time ke liye hota hai."

`types.ts`:

```ts
export interface User {
  name: string;
  age: number;
}
```

`App.tsx`:

```tsx
import type { User } from "./types";

const user: User = { name: "Vin", age: 25 };
```

`import type` ka fayda — bundler (Vite) ko pata chal jaata hai ki yeh sirf type hai, runtime bundle mein include nahi karna. Isse bundle size kam hoti hai.

React components mein jab interface component file mein hi ho:

`ProfileCard.tsx`:

```tsx
export interface ProfileCardProps {
  name: string;
  role: string;
}

export default function ProfileCard({ name, role }: ProfileCardProps) {
  return <div>{name} — {role}</div>;
}
```

Import:

```tsx
import ProfileCard, { type ProfileCardProps } from "./ProfileCard";
```

Yahan `type` keyword named import ke saath laga hai — bata raha hai ki yeh type hai, runtime value nahi.

## Summary

- **Variable export:** `export const name = "Vin"` → import: `{ name }`
- **Function export:** `export function greet() {}` → import: `{ greet }`
- **Default export:** `export default App` → import: `App` (bina curly braces)
- **Default + named:** `import X, { Y, Z } from "./file"`
- **Named import exact match** karna padta hai, default import ka naam tum choose karte ho
- **Multiple named exports** per file, sirf ek default
- **`as` keyword** se import rename: `import { X as Y }`
- **`import type`** — sirf types ke liye, runtime bundle optimize hota hai
- File extension import path mein nahi likhte — TypeScript handle kar leta hai
- `./` ka matlab "current folder" — path relative hota hai

## Agla Step

Import/export samajh aa gaya — pehle simple values, phir functions, phir components. Ab ek component ko uski **apni file** mein rakhna seekhenge — `components/` folder ka structure, kyun ek component = ek file, aur multiple components ko import karke ek App mein kaise combine karte hain.
