## Abhi Tak Kya Hua

1.5.1 mein interface seekha, 1.5.2 mein props ka concept, 1.5.3 mein optional props aur destructuring seekhi. Ab ek important pattern seekhenge — **callback props**. Jab component ko parent ko kuch batana ho (jaise button click, form submit), tab callback props ka use hota hai.

## Broader Goal

Props sirf data nahi, **functions** bhi pass kar sakte ho. Yeh unhe **callback props** kehte hain. Button component socho — woh sirf button render karta hai, click handle nahi karta. Click ka kaam parent ka hai. Component sirf parent ko bata ta hai "click hua", aur parent decide karta hai ki ab kya karna hai.

## Step 1 — Problem Feel Karo

Soch: "Ek `AlertButton` component banana hai jo button dikhata hai. Jab user click kare, toh parent ko pata chalna chahiye. Lekin component ko nahi pata ki click par kya hona chahiye — woh toh parent decide karega."

Agar props sirf data pass karte hain — string, number, boolean — toh yeh kaam nahi hoga. Kyunki click ka behavior parent ke hisaab se change ho sakta hai. Ek jagah alert dikhana hai, doosri jagah console.log karna hai, teesri jagah API call karna hai.

**Solution:** Function as prop — parent ek function pass karega, component use call karega jab event hoga.

## Step 2 — Pehle Samjho: Function Jo Function Leta Hai

Callback prop samajhne se pehle, JavaScript ka ek simple concept clear karte hain — **function jo function leta hai as parameter**.

```javascript
// Ye function ek function leta hai as parameter
function execute(callback) {
  callback();  // us function ko call karo
}

// Ek function banao
const sayHello = () => console.log("Hello!");

// execute ko do — "yeh function call kar do"
execute(sayHello);
// Console: "Hello!"
```

Dekho — `sayHello` ek function hai. `execute` ko `sayHello` pass kiya. `execute` ne `callback()` call kiya. Iska matlab `sayHello()` call ho gaya.

```
execute(sayHello)
  → execute ke andar callback = sayHello
  → callback() = sayHello()
  → "Hello!" print hua
```

Is pattern mein:
- `execute` → **child** ki tarah hai (function receive karta hai, call karta hai)
- caller (`execute(sayHello)` likhne wala) → **parent** ki tarah hai (function provide karta hai)

**Same baat React mein:** Parent component (App) child component (AlertButton) ko ek function pass karta hai. Child use call karega jab koi event hoga (jaise click).

## Step 2.5 — Pehle Normal Variable Props Ka Object Samjho

Callback prop pe jaane se pehle, ek cheez clear karte hain — **React mein props hamesha ek object ke andar aate hain**. Chahe variable ho ya function, sab isi object ki properties hain.

Socho tumhare paas ek simple `AlertButton` hai jo do **normal variable props** leta hai:

```tsx
// Child component
function AlertButton(props: { label: string; count: number }) {
  return (
    <div>
      <button>{props.label}</button>
      <p>Count: {props.count}</p>
    </div>
  );
}
```

```tsx
// Parent component
function App() {
  return <AlertButton label="Click" count={5} />;
}
```

Jab React `App` render karega, toh `AlertButton` ke andar `props` kaise dikhega? Ye dekho:

```
<AlertButton label="Click" count={5} />
                           ⬇
React internally kuch aisa banata hai:
React.createElement(AlertButton, { label: "Click", count: 5 })
                                    ⬇
AlertButton ke andar props = { label: "Click", count: 5 }
                                    ⬇
props.label → "Click"
props.count → 5
```

React ne JSX attributes (`label="Click"`, `count={5}`) ko uthaya aur ek **object** mein daal diya — `{ label: "Click", count: 5 }`. Fir yeh object `AlertButton` ko first argument ke roop mein diya. Isliye function ke andar `props.label` likhna padta hai — object se property nikaal rahe ho.

**Ab callback wala case dekho:**

```tsx
<AlertButton action={handleClick} />
                            ⬇
React internally:
React.createElement(AlertButton, { action: handleClick })
                                    ⬇
AlertButton ke andar props = { action: handleClick }
                                    ⬇
props.action → handleClick function
```

Bilkul same pattern. Sirf farak yeh hai ki value ab string/number nahi, balki **function** hai. Lekin wrapper (props object) wahi hai.

**Analogy:** Socho tum kisi ko parcel bhej rahe ho. Parcel ke andar ek letter (string), ek number, ya ek remote control (function) ho sakta hai. Lekin parcel (object) ke bahar kuch nahi bhej sakte. React ka props wahi parcel hai.

### Regular Prop vs Callback Prop — Ek Hi Pattern

| | Regular Prop | Callback Prop |
|---|---|---|
| Example | `label="Click"` | `action={handleClick}` |
| Props object | `{ label: "Click" }` | `{ action: handleClick }` |
| Access | `props.label` → "Click" | `props.action` → function |
| Use | Display karo | Call karo: `props.action()` |
| Value type | string, number, boolean | **function** |

Dono same object mein rehte hain. Farak sirf itna — ek value hai, doosra function hai.

### Compare: Pure JS vs React

```
Pure JS:          execute(sayHello)
                           ⬇
                  callback = sayHello (direct parameter)

React JSX:        <AlertButton action={handleClick} />
                           ⬇
                  props = { action: handleClick } (object mein wrap)
                  props.action = handleClick (object se nikaal rahe)
```

Pure JS mein seedha parameter milta hai. React mein object ke andar. Yeh React ka design hai — **sab props ek object mein** collect hote hain. Koi special reason nahi, bas React ka API aisa bana hai.

Yeh clear ho gaya? Achha, ab Step 3 mein callback prop ka pura example dekhte hain.

## Step 3 — React Mein Callback Prop (No Destructuring)

Ab AlertButton banate hain. **Koi destructuring nahi, koi `onClick` confusion nahi.** Sirf `props.action`:

```tsx
// Child component
function AlertButton(props: { action: () => void }) {
  return <button onClick={props.action}>Show Alert</button>;
}
```

Line by line:

1. `props: { action: () => void }` — props ek object hai jisme ek property `action` hai. `action` ka type hai `() => void` — ek function jo kuch return nahi karta. `void` ka matlab hai "yeh function sirf kaam karta hai, koi value wapas nahi deta" — jaise `alert()`, `console.log()`
2. `onClick={props.action}` — jab button click hoga, React `props.action()` call karega
3. "Show Alert" — hardcoded text, abhi label prop nahi hai

```tsx
// Parent component
function App() {
  // Parent ne function define kiya
  const handleClick = () => {
    alert("Button was clicked!");
  };

  return (
    <div>
      {/* Parent ne function prop ke through child ko diya */}
      <AlertButton action={handleClick} />
    </div>
  );
}
```

**Flow dekho — Parent vs Child:**

```
╔══════════════════════════════════════╗
║         PARENT (App)                 ║
║                                      ║
║  1. handleClick function banaya      ║
║     (alert karega)                   ║
║                                      ║
║  2. Child ko diya:                   ║
║     <AlertButton action={handleClick} ║
╚════════════════════╤═════════════════╝
                     │ prop pass hui
                     ▼
╔════════════════════╤═════════════════╗
║         CHILD (AlertButton)          ║
║                                      ║
║  3. props.action = handleClick       ║
║     (receive kiya)                   ║
║                                      ║
║  4. User ne button click kiya        ║
║                                      ║
║  5. props.action() call kar diya     ║
║     → handleClick() chal gaya        ║
╚════════════════════╤═════════════════╝
                     │ callback wapas
                     ▼
╔══════════════════════════════════════╗
║      PARENT ka code execute hua      ║
║                                      ║
║  6. alert("Button was clicked!")     ║
╚══════════════════════════════════════╝
```

### Parent vs Child — Kaun Kya Karta Hai

```
PARENT (App):
  → handleClick function DEFINE karta hai
  → Child ko prop mein PASS karta hai: action={handleClick}
  → Jab child call karega, tab execute hoga

CHILD (AlertButton):
  → props.action = handleClick RECEIVE karta hai
  → User click karta hai
  → props.action() CALL karta hai
  → Parent ko signal bhejta hai: "click ho gaya"

Direction:
  props → Parent → Child (data down)
  callback → Child → Parent (signal up)
```

**Kya hua?** Child ne kuch decide nahi kiya. Sirf parent ko bata diya "click hua". Parent decide karta hai ki ab kya karna hai.

### Inline Arrow Function

Alag function banaye bina bhi kar sakte ho:

```tsx
// Parent (App) se child ko function prop pass ho raha hai
<AlertButton action={() => alert("Clicked!")} />
```

`() => alert("Clicked!")` ek function hai. Jab click hoga, tabhi chalega.

### Remember: Props vs Callback

| | Regular Prop | Callback Prop |
|---|---|---|
| Data type | string, number, boolean | **function** |
| Example | `label="Click me"` | `action={() => alert()}` |
| Kaam | Component data dikhata hai | Component parent ko batata hai |
| Direction | Parent → Child | **Child → Parent** |

## Step 4 — Destructuring + Label Add Karo

Soch: "Har baar `props.action` likhna repetitive hai. Aur button ka text bhi parent decide kare."

Destructuring se `props.action` ki jagah seedha `action` likh sakte ho:

```tsx
// Child component
interface AlertButtonProps {
  label: string;
  action: () => void;
}

function AlertButton({ label, action }: AlertButtonProps) {
  return <button onClick={action}>{label}</button>;
}
```

Ab:
- `label` — button ka text, parent decide karega
- `action` — click par kya hoga, parent decide karega

```tsx
// Parent component
function App() {
  return (
    <div>
      <h1>Callback Props Demo</h1>
      {/* Child ko label + function dono parent decide karega */}
      <AlertButton label="Click me" action={() => alert("Clicked!")} />
    </div>
  );
}
```

## Step 5 — `on` Prefix Convention

Callback props ka naam usually `on` se shuru hota hai — `action` ki jagah `onAlert`, `onClick`, `onSubmit`.

| Callback | Meaning |
|----------|---------|
| `onClick` | Button click par call hoga |
| `onSubmit` | Form submit par call hoga |
| `onDelete` | Delete action par call hoga |
| `onAdd` | Add action par call hoga |

Yeh naming React ki built-in events (`onClick`, `onChange`) se match karti hai. Code padhte hi pata chal jata hai ki yeh callback prop hai.

Ab `AlertButton` mein `action` ka naam `onAlert` kar dete hain:

```tsx
// Child component
interface AlertButtonProps {
  label: string;
  onAlert: () => void;
}

function AlertButton({ label, onAlert }: AlertButtonProps) {
  return <button onClick={onAlert}>{label}</button>;
}
```

```tsx
// Parent (App) se teen different callbacks ke saath
<AlertButton label="Save" onAlert={() => alert("Saved!")} />
<AlertButton label="Delete" onAlert={() => alert("Deleted!")} />
```

## Step 6 — Callback with Parameters

Soch: "Kya callback function ko parameter bhi pass kar sakte hain? Jaise child parent ko kuch data bhejna chahe?"

```tsx
// Child component
interface MessageButtonProps {
  onSend: (message: string) => void;   // callback with parameter
}

function MessageButton({ onSend }: MessageButtonProps) {
  return <button onClick={() => onSend("Hello from child!")}>Send</button>;
}
```

Yahan `onSend: (message: string) => void` ka matlab — callback ek string parameter lega aur kuch return nahi karega. Component button click par `onSend("Hello from child!")` call karta hai — parent ko ek message bhej raha hai.

```tsx
// Parent component
function App() {
  const handleMessage = (msg: string) => {
    console.log("Child ne kaha:", msg);
  };

  return (
    <div>
      <MessageButton onSend={handleMessage} />
    </div>
  );
}
```

**Flow:**

```
Parent (App):
  → handleMessage function: msg parameter leta hai, console.log karta hai
  → Child ko diya: onSend={handleMessage}

Child (MessageButton):
  → onSend = handleMessage receive kiya
  → User click karta hai
  → onSend("Hello from child!") call kiya
  → handleMessage("Hello from child!") chal gaya
  → Console: "Child ne kaha: Hello from child!"
```

Callback ke saath parameter pass karne ka yahi pattern hai — child parent ko data bhej sakta hai.

### Common Function Type Syntax

```tsx
onAlert: () => void                 // koi parameter nahi, kuch return nahi
onSend: (message: string) => void   // ek string parameter, kuch return nahi
onChange: (id: number) => boolean   // number leta hai, boolean return karta hai
```

## Step 7 — Real Example: Multiple AlertButtons

`components/AlertButton.tsx`:

```tsx
// Child component
interface AlertButtonProps {
  label: string;
  onAlert: (message: string) => void;
}

function AlertButton({ label, onAlert }: AlertButtonProps) {
  return (
    <button onClick={() => onAlert(`Button "${label}" was clicked!`)}>
      {label}
    </button>
  );
}

export default AlertButton;
```

`App.tsx`:

```tsx
// Parent component
import AlertButton from "./components/AlertButton";

function App() {
  const handleAlert = (msg: string) => {
    console.log(msg);
    alert(msg);
  };

  return (
    <div>
      <h1>Callback Props Demo</h1>
      <AlertButton label="Save" onAlert={handleAlert} />
      <AlertButton label="Delete" onAlert={handleAlert} />
      <AlertButton label="Submit" onAlert={handleAlert} />
    </div>
  );
}
```

Ab teen buttons hain, ek hi `AlertButton` component. Har button par click karte hi parent ko message bhejta hai — "Button 'Save' was clicked!", "Button 'Delete' was clicked!", etc.

### Recap: Data Flow

```
Parent (App) 
  → onAlert function pass karta hai
  → AlertButton (child) ko
  → User click karta hai
  → AlertButton onAlert() call karta hai
  → Parent ka function execute hota hai
```

Callback props ka yahi pattern hai — **child → parent communication**. Props data pass karte hain parent se child tak. Callback props child se parent tak signal bhejte hain.

## Summary

- Callback props = function as prop
- Syntax: `onClick: () => void` — interface mein function type
- Convention: `on` prefix — `onClick`, `onAdd`, `onDelete`
- Parameters: `onAdd: (text: string) => void` — callback ke saath data bhejo
- Direction: Callbacks **child → parent** communicate karte hain
- Arrow function in prop: `onAlert={() => alert("Clicked")}` — inline callback

Callback props clear hain — component parent ko notify kar sakta hai. Agle chapter mein **children** prop aur **composition** pattern dekhenge — ek component ke andar doosra component kaise wrap karte hain, layout components kaise banate hain.
