# 1.4 Quiz — Separate Component Files

## MCQ

Q: Ek file mein multiple components rakhne ki sabse badi problem kya hai?
A. Components ek doosre ke variables ko accidentally overwrite kar sakte hain
B. File bada hota hai — readability kam, team work mushkil, scroll difficult
C. React multiple components ek file mein allow nahi karta — error aati hai
D. Browser multiple components ek file mein load nahi kar paata hai
> B. Real components 100-200 lines ke hote hain. 10 components ek file mein = 2000 lines ka monster. Edit karna mushkil, do developers ek saath kaam nahi kar sakte. Solution — ek component = ek file.

---

Q: React project mein components kis folder mein rakhte hain?
A. `src/` folder ke andar `components/` folder — standard convention hai
B. `public/` folder ke andar `components/` folder — public assets ke saath
C. `node_modules/` ke andar `components/` folder — dependencies ke saath
D. Koi folder nahi — saare components directly `src/` mein rakhte hain
> A. `src/components/` standard React convention hai. File ka naam component ke naam ke jaisa rakho — `ProfileCard` → `ProfileCard.tsx`. PascalCase file names, `.tsx` extension for JSX.

---

Q: Component ko alag file mein rakhne ke baad App mein kaise use karte hain?
A. Component file ko public folder mein rakhna padta hai App auto detect kar leta hai
B. Component ko HTML mein `<script>` tag se include karte hain jaise purane JS mein
C. Component file se `import` karte hain relative path ke saath bina extension ke
D. Component ka naam `window` object mein assign karna padta hai global access ke liye
> C. `import ProfileCard from "./components/ProfileCard"` — relative path, bina `.tsx` extension ke. TypeScript extension handle kar leta hai. `./` ka matlab "current folder ke andar".

---

Q: Import path `"./components/ProfileCard"` mein `./` ka kya matlab hai?
A. Parent folder ke andar components folder mein ProfileCard file
B. Root folder (src/) ke andar components folder mein ProfileCard file
C. Current folder ke andar components folder mein ProfileCard file
D. Nested folder ke andar components folder mein ProfileCard file
> C. `./` ka matlab "current folder" hai. Agar App.tsx `src/` mein hai aur ProfileCard.tsx `src/components/` mein hai, toh path `"./components/ProfileCard"` — current folder se andar jao.

---

Q: Component files ke liye extension `.tsx` kyun use karte hain?
A. Kyunki file mein JSX hai — `.tsx` extension JSX wali TypeScript files ke liye hai
B. Kyunki `.tsx` extension CSS styling automatically apply karta hai har component par
C. Kyunki `.tsx` extension browser ko file ko fast render karne mein help karta hai
D. Kyunki `.tsx` extension ke bina React component import nahi ho sakta
> A. `.tsx` TypeScript files ke liye hai jo JSX contain karti hain. Regular TypeScript (bina JSX ke) `.ts` extension use karta hai. Agar file mein JSX hai to `.tsx` mandatory hai.

---

Q: Multiple files mein components rakhne se kaun sa fayda nahi milta?
A. Team work — do developers ek saath different components par kaam kar sakte hain
B. Reusability — component ko doosre project mein copy-paste karna aasan hota hai
C. File size chhoti hoti hai — readability aur navigation improve hoti hai
D. App ki performance automatically fast ho jaati hai — React fast ho jaata hai
> D. File splitting se performance directly fast nahi hoti. Fayde hain — readability, team work, reusability, Git conflicts kam, testing easy. Ye code organization ke fayde hain, performance ke nahi.

---

Q: Professional React codebases mein component ka return type explicit likhna?
A. Hamesha likhna padta hai — TypeScript strict mode force karta hai har jagah
B. Kabhi nahi likhte — TypeScript type inference par depend karte hain hamesha
C. Mostly skip karte hain lekin complex components mein kabhi kabhi likhte hain
D. Sirf class components mein likhte hain function components mein nahi likhte
> C. Professional codebases mein mostly return type skip karte hain kyunki TypeScript infer kar leta hai. Lekin complex components (multiple return paths) ya team convention ho to explicit likh sakte hain.

Q: Is course mein kaunsa export pattern follow kiya jayega?
A. Pattern 1 — Default Export per Component — consistent with Next.js/Vite
B. Pattern 2 — Named Export per Component — consistent with older React apps
C. Dono patterns ek saath — har component ko default aur named dono export karenge
D. Koi pattern fixed nahi — har file mein alag-alag pattern use karenge
> A. Is course mein Pattern 1 (Default Export per Component) follow hoga. Yeh Next.js, Vite, Create React App sab ke saath consistent hai. Consistency sabse important hai.

## TrueFalse

Q: Component file ka naam lowercase bhi ho sakta hai — `profileCard.tsx` — yeh bhi chalega.
- True
- False
> True. PascalCase file names convention hai, rule nahi. Kuch teams lowercase use karti hai. Lekin React ecosystem mein PascalCase standard hai — `ProfileCard.tsx`. Consistency important hai.

---

Q: Import path mein file extension `.tsx` likhna mandatory hai — bina extension ke error aati hai.
- True
- False
> False. Import path mein file extension nahi likhte — TypeScript automatically handle kar leta hai. `import ProfileCard from "./components/ProfileCard"` — sahi hai. `.tsx` extension nahi lagate.

---

Q: Ek file mein multiple components rakhne se app ki performance improve hoti hai.
- True
- False
> False. File splitting se performance improve nahi hoti. Ye code organization ka concept hai — readability, team work, reusability ke liye. Performance build tool (Vite) aur React ki rendering efficiency par depend karti hai.

---

Q: Agar file mein JSX nahi hai to `.tsx` ki jagah `.ts` extension use karna chahiye.
- True
- False
> True. `.tsx` sirf un files ke liye hai jo JSX contain karti hain. Agar file mein pure TypeScript hai (types, interfaces, utility functions bina JSX ke), to `.ts` extension use karo. Yeh extension ka basic rule hai.

## ShortAnswer

Q: Components ko alag-alag files mein rakhne ke 3 main fayde kya hain? Explain karo.

<details>
<summary>Sample Answer</summary>

**1. Readability:** Har file chhoti aur focused. Ek component ko edit karna hai to sirf wahi file kholo, 2000 lines scroll nahi karni padti.

**2. Team Work:** Do developers ek saath kaam kar sakte hain — ek ProfileCard file pe kaam kar raha hai, doosra MemberBadge file pe. Ek hi file pe conflict nahi.

**3. Reusability:** Component doosre project mein copy-paste karna aasan. Sirf ek file copy karo, App mein import karo, use karo.

**Bonus — Git Conflicts:** Jab do developers same component pe kaam karein, conflict sirf usi component ki file mein hogi. App.tsx aur doosri files safe rehti hain.

**Analogy:** Jaise kitchen mein har cheez (spoons, plates, glasses) apni alag jagah rakhi hoti hai. Ek hi drawer mein sab kuch daal do to kuch nahi milta. File splitting bhi yahi hai — har component ki apni jagah.

</details>

Q: Correct file structure kya honi chahiye agar tumhare paas ProfileCard aur MemberBadge components hain? Folder structure draw karo aur path explain karo.

<details>
<summary>Sample Answer</summary>

**File Structure:**
```
src/
├── components/
│   ├── ProfileCard.tsx
│   └── MemberBadge.tsx
├── App.tsx
└── main.tsx
```

**Path Explanation:**
- `App.tsx` `src/` folder mein hai
- `ProfileCard.tsx` `src/components/` folder mein hai
- App se ProfileCard import karne ka path: `"./components/ProfileCard"`
  - `./` = current folder (src/)
  - `components/` = subfolder
  - `ProfileCard` = file name (bina extension)
- Extension `.tsx` import path mein nahi likhte

**Component File Pattern:**
```tsx
// ProfileCard.tsx
function ProfileCard() {
  return <div>...</div>;
}
export default ProfileCard;
```

**App File Pattern:**
```tsx
// App.tsx
import ProfileCard from "./components/ProfileCard";
import MemberBadge from "./components/MemberBadge";
```

</details>
