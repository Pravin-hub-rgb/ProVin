
## MCQ

Q: What is the biggest problem with keeping multiple components in a single file?
A. Components can accidentally overwrite each other's variables
B. The file gets too large — poor readability, difficult teamwork, painful scrolling
C. React doesn't allow multiple components in one file — it throws an error
D. The browser can't load multiple components from one file
> B. Real components are 100–200 lines each. 10 components in one file = a 2000-line monster. Hard to edit, two developers can't work simultaneously. Solution: one component = one file.

Q: Where do you put components in a React project?
A. Inside `src/` folder, in a `components/` subfolder — standard convention
B. In `public/` folder, in a `components/` subfolder — alongside public assets
C. In `node_modules/`, in a `components/` subfolder — alongside dependencies
D. No specific folder — all components go directly in `src/`
> A. `src/components/` is the standard React convention. File name should match component name — `ProfileCard` → `ProfileCard.tsx`. PascalCase names, `.tsx` extension for JSX files.

---

Q: After moving a component to its own file, how do you use it in App?
A. Put the component file in the public folder and App auto-detects it
B. Include the component file with an HTML `<script>` tag, like traditional JS
C. Import it with a relative path, no file extension
D. Assign the component name to `window` for global access
> C. `import ProfileCard from "./components/ProfileCard"` — relative path with no `.tsx` extension. TypeScript resolves the extension automatically. `./` means "inside the current folder."

---

Q: In the import path `"./components/ProfileCard"`, what does `./` mean?
A. Inside the parent folder, then components folder, then ProfileCard file
B. Inside the root folder (src/), then components folder, then ProfileCard file
C. Inside the current folder, then components folder, then ProfileCard file
D. Inside a nested folder, then components folder, then ProfileCard file
> C. `./` means "current folder." If App.tsx is in `src/` and ProfileCard.tsx is in `src/components/`, the path `"./components/ProfileCard"` means "go into the components subfolder from here."

Q: Why use the `.tsx` extension for component files?
A. Because the file contains JSX — `.tsx` is for TypeScript files with JSX
B. Because `.tsx` automatically applies CSS styling to every component
C. Because `.tsx` helps the browser render files faster
D. Because without `.tsx`, React components can't be imported
> A. `.tsx` is for TypeScript files that contain JSX. Plain TypeScript (no JSX) uses `.ts`. If the file has JSX, `.tsx` is mandatory.

Q: What is NOT a benefit of splitting components into multiple files?
A. Teamwork — two developers can work on different components simultaneously
B. Reusability — copying a component to another project is easy
C. Smaller file size — improves readability and navigation
D. Automatic performance improvement — React runs faster
> D. File splitting doesn't improve performance directly. The benefits are about code organization — readability, teamwork, reusability, fewer Git conflicts, easier testing. Performance depends on the build tool (Vite) and React's rendering, not file count.

A. Always required — TypeScript strict mode forces return types everywhere
B. Never written — always depend on TypeScript inference

D. Only class components need return types, not function components
> C. In professional codebases, return types are mostly skipped because TypeScript infers them. But for complex components (multiple return paths) or when team conventions require it, explicit return types may be written.

## TrueFalse

Q: Component file names must always be lowercase — like `profileCard.tsx`.
- True
- False
> True. PascalCase is a convention, not a requirement. Some teams use lowercase. But PascalCase (`ProfileCard.tsx`) is the React ecosystem standard. Consistency is what matters.

---

Q: The file extension `.tsx` must be included in the import path — otherwise it's an error.
- True
- False
> False. File extensions are not needed in import paths — TypeScript resolves them automatically. `import ProfileCard from "./components/ProfileCard"` is correct without `.tsx`.

---

Q: Splitting components into multiple files automatically makes the app faster.
- True
- False
> False. File splitting is about code organization, not performance. The benefits are readability, teamwork, reusability, fewer Git conflicts, and easier testing. App performance depends on the build tool and React's rendering, not how files are split.

---

Q: If a file has no JSX, it should use `.ts` instead of `.tsx`.
- True
- False
> True. `.tsx` is only for files containing JSX. If a file is pure TypeScript (types, interfaces, utility functions without JSX), use `.ts`. This is a basic rule for file extensions.

## ShortAnswer

Q: What are 3 benefits of putting each component in its own file? Explain.

<details>
<summary>Sample Answer</summary>

**1. Readability:** Each file stays small and focused on one thing. To edit a component, just open that one file — no scrolling through 2000 lines.

**2. Teamwork:** Two developers can work simultaneously — one on ProfileCard, another on MemberBadge. No merge conflicts in the same file.

**3. Reusability:** Copying a component to another project is one file — copy, import, use.

**Bonus — Git Conflicts:** When two developers work on the same component, the conflict stays in that component's file. App.tsx and other files stay safe.

**Analogy:** Like a kitchen where every utensil (spoons, plates, glasses) has its own place. Dump everything in one drawer and you can't find anything. File splitting is the same — every component gets its own home.

</details>

Q: Draw the correct file structure for ProfileCard and MemberBadge components, and explain the import path.

<details>
<summary>Sample Answer</summary>

**File Structure:**
```
src/
├── components/
│   ├── ProfileCard.tsx
│   └── MemberBadge.tsx
├── App.tsx
└── main.tsx
```

**Path Explanation:**
- `App.tsx` sits in the `src/` folder
- `ProfileCard.tsx` sits in `src/components/`
- To import ProfileCard from App, the path is `"./components/ProfileCard"`
  - `./` = current folder (src/)
  - `components/` = subfolder
  - `ProfileCard` = file name (no extension)
- File extensions (`.tsx`) are NOT included in import paths
- TypeScript resolves the extension automatically

**Component File Pattern:**
```tsx
// ProfileCard.tsx
function ProfileCard() {
  return <div>...</div>;
}
export default ProfileCard;
```

**App File Pattern:**
```tsx
// App.tsx
import ProfileCard from "./components/ProfileCard";
import MemberBadge from "./components/MemberBadge";
```

</details>
