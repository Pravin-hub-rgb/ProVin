## Broader Goal

Ab actual coding shuru karni hai. Lekin pehle ek cheez clear karni padegi — jo code `App.tsx` ke andar likha hai, woh HTML nahi hai. Woh **JSX** hai. Aur JSX ko samjhe bina hum koi component nahi likh sakte.

Is doc ka goal: JSX kya hai, yeh kaise kaam karta hai, aur HTML se kya fark hai — yeh sab clear ho jayega.

## Step 1 — App.tsx Kholo Aur Dekho Kya Likha Hai

Soch: "Maine `npm run dev` chalaya, browser mein kuch dikh raha hai. Woh code kahan hai jo yeh page bana raha hai?"

Kyun: Samajhna hai ki React ka entry point kaise kaam karta hai. Jab tak source code nahi dekhenge, tab tak pata nahi chalega ki page kahan se aa raha hai.

VS Code mein `src/App.tsx` kholo:

```tsx
function App() {
  return (
    <div>
      <h1>Hello, World!</h1>
      <p>This is my first React app.</p>
    </div>
  );
}

export default App;
```

> **Note:** Tumhara code thoda alag ho sakta agar 0.8 mein Greeting component experiment kiya tha. Koi baat nahi — concept same hai. Agli step se hum naye code likhenge.

Dekho — `return` ke baad kya likha hai? HTML jaisa code, lekin JavaScript file ke andar. Browser ko yeh kaise pata chal raha hai ki yeh render karna hai?

Browser ko nahi pata. Aur yeh JS ka valid syntax bhi nahi hai.

## Step 2 — JSX Kya Hai

Soch: "Yeh `<div>` `<h1>` wala code JavaScript ke andar kaise chal raha hai? Browser toh HTML, CSS aur JavaScript samajhta hai — yeh teeno ka mixture kya hai?"

Kyun: Agar hum samjhe bina JSX use karte rahenge, toh yeh "magic" lagega. Jab koi error aayegi, pata nahi chalega ki kyun aayi. Isliye pehle samajhna zaroori hai.

**Concept:** JSX ka matlab hai **JavaScript XML** — yeh JavaScript ka syntax extension hai jo HTML jaisa dikhta hai. Lekin browser directly JSX nahi samajhta. Jab tum `npm run dev` chalate ho, Vite background mein ek compiler (esbuild) chala raha hota hai jo JSX ko React code mein convert karta hai.

Yeh conversion kuch aisa hota hai:

```
// Jo tum likhte ho (JSX):
<div>Hello, World!</div>

// Vite usse convert karta hai (React.createElement):
React.createElement("div", null, "Hello, World!")
```

`React.createElement` ek plain JavaScript function call hai jo ek object return karta hai — wahi object jo React ko batata hai ki screen par kya render karna hai.

## Step 3 — Prove Kar Ke Dekho

Soch: "Tu keh raha hai ki JSX convert hota hai `React.createElement` mein. Kaise prove karein?"

`src/App.tsx` mein ek line add karo:

```tsx
function App() {
  console.log(typeof <h1>Hello</h1>);

  return (
    <div>
      <h1>Hello, World!</h1>
    </div>
  );
}
```

Browser console kholo (F12). Kya print hua?

```
object
```

`<h1>Hello</h1>` ka type `object` hai. Koi string nahi, koi HTML nahi — ek JavaScript object. Aur agar `console.log(<h1>Hello</h1>)` karo, toh kuch aisa object dikhega:

```
{ type: 'h1', props: { children: 'Hello' } }
```

Yahi React ka Virtual DOM node hai. JSX sirf yeh object create karne ka ek readable tarika hai.

**Isliye JSX ko "syntactic sugar" kehte hain** — ek cheez jo likhne mein achi lagi, par asal mein kuch aur ho raha hai.

## Step 4 — HTML Aur JSX Mein Fark

Soch: "Agar JSX HTML jaisa dikhta hai, toh kya main sab HTML wahi likh sakta hoon jaisa likhta aaya hoon?"

Kyun: Nahi. JSX ke apne rules hain. Agar direct HTML copy karoge toh error aayegi.

**Fark 1 — `class` nahi, `className` likho:**

```html
<!-- HTML mein aise likhte ho: -->
<h1 class="heading">Hello</h1>
```

```tsx
// JSX mein aise likho:
<h1 className="heading">Hello</h1>
```

Kyun? JavaScript mein `class` ek reserved keyword hai. Isliye JSX ne `className` use kiya. React internally isse `class` attribute mein convert kar deta hai.

**Fark 2 — `for` nahi, `htmlFor` likho:**

```tsx
<label htmlFor="email">Email</label>
```

Same reason — `for` bhi JavaScript ka reserved keyword hai.

**Fark 3 — Self-closing tags:**

HTML mein `<br>` ya `<input>` bina close kiye chal jata hai. JSX mein har tag ko close karna padta hai:

```tsx
<br />
<input type="text" />
<img src="photo.jpg" alt="Photo" />
```

Error aayegi agar `>` ke saath close nahi kiya.

**Fark 4 — Attributes camelCase mein:**

```tsx
<button onClick={handleClick}>Click</button>
<input onKeyDown={handleKey} />
<div tabIndex={0}>Focusable div</div>
```

HTML mein `onclick`, `onkeydown`, `tabindex` (lowercase). JSX mein `onClick`, `onKeyDown`, `tabIndex` (camelCase).

Ek kaam karo — galti se HTML style likh ke dekho:

```tsx
<button onclick={() => {}}>Click</button>
```

TypeScript error aayegi kuch aisi: `Type '(event: MouseEvent) => void' is not assignable to type 'never'` — kyunki React ka typing system sirf JSX-style props expect karta hai.

## Step 5 — JavaScript Expressions in JSX

Soch: "Agar JSX object return karta hai, toh main JavaScript ki values ko JSX ke andar kaise use karoon?"

Kyun: Static data ka koi use nahi. Har component ko dynamic data dikhana hota hai — jo variable mein store hai, jo function se aa raha hai, jo user ne type kiya hai.

**Concept:** JSX ke andar `{ }` curly braces lagake koi bhi JavaScript expression daal sakte ho.

`App.tsx` mein yeh karo:

```tsx
function App() {
  const name = "Vin";
  const currentYear = new Date().getFullYear();

  return (
    <div>
      <h1>Hello, {name}!</h1>
      <p>Year: {currentYear}</p>
      <p>Sum: {2 + 3}</p>
      <p>Uppercase: {name.toUpperCase()}</p>
    </div>
  );
}
```

Browser mein kya dikh raha hai?

- `{name}` → "Vin"
- `{currentYear}` → "2026"
- `{2 + 3}` → "5"
- `{name.toUpperCase()}` → "VIN"

**Important:** Sirf **expressions** daal sakte ho, **statements** nahi. Matlab:

✅ Sahi: `{name}`, `{2 + 3}`, `{name.toUpperCase()}`, `{isLoggedIn ? "Hi" : "Hello"}`

❌ Galat: `{if (true) { return "Hi" }}`, `{for (let i = 0; i < 5; i++) { }}`

Agar yeh error aayi toh tumhe pata chal jayega: `Uncaught SyntaxError: Unexpected token 'if'`

## Step 6 — Single Root Element Ka Rule

Soch: "Kya main do `<div>` ek saath return kar sakta hoon?"

`App.tsx` mein yeh try karo:

```tsx
function App() {
  return (
    <h1>Heading</h1>
    <p>Paragraph</p>
  );
}
```

**Concept:** JSX ka ek strict rule hai — **ek function sirf ek hi root element return kar sakta hai**. Do siblings ek saath nahi return kar sakte.

Error aayegi: `Adjacent JSX elements must be wrapped in an enclosing tag` — kyunki JavaScript function sirf ek hi value return kar sakta hai.

**Solutions:**

1. **`<div>` mein wrap karo:**

```tsx
function App() {
  return (
    <div>
      <h1>Heading</h1>
      <p>Paragraph</p>
    </div>
  );
}
```

2. **Fragment (`<>...</>`) use karo — jab extra DOM node nahi chahiye:**

```tsx
function App() {
  return (
    <>
      <h1>Heading</h1>
      <p>Paragraph</p>
    </>
  );
}
```

`<>` ek **Fragment** hai — yeh DOM mein koi extra element nahi banata, sirf JSX elements ko group karta hai.

Try karo — developer tools mein inspect karo. `<>` case mein `<div>` extra nahi dikhega. Jab styling ke liye extra wrapper nahi chahiye, tab Fragment use karte hain.

## Summary

- JSX = JavaScript XML — HTML jaisa dikhta hai, par asal mein `React.createElement` calls hai
- Browser JSX directly nahi samajhta — Vite ka compiler convert karta hai
- `className` (not `class`), `htmlFor` (not `for`), camelCase attributes
- Har tag close karna padta hai (self-closing included)
- `{ }` curly braces se JavaScript expressions embed karo
- Sirf ek root element return karo (ya `<div>`, ya `<>` Fragment)
