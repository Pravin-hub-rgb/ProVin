# 1.5 Quiz — Interface, Props, Callbacks

## MCQ

Q: TypeScript interface ka kya kaam hai?
A. Interface ek object ka shape define karta hai — kaun si properties hain aur unka type kya hai
B. Interface ek function ka body define karta hai — andar ka code kaise execute hoga
C. Interface ek component ka UI design define karta hai — kaise dikhega
D. Interface ek file ka module system define karta hai — kaunsa export kaunsa import
> A. Interface object ka "shape" define karta hai — `{ name: string; age: number }`. TypeScript enforce karta hai ki object mein exactly wahi properties hon jo interface mein defined hain. Wrong property = compile-time error.

---

Q: Props interface ke naam mein kya convention follow karte hain?
A. `ComponentNameProps` — component ke naam ke saath `Props` suffix — standard hai
B. `PropsComponentName` — `Props` prefix ke saath component ka naam — convention hai
C. `IComponentName` — `I` prefix ke saath PascalCase — C# style convention hai
D. Koi convention nahi — kuch bhi naam de sakte ho bina kisi pattern ke
> A. Convention hai `ComponentNameProps` — `ProfileCardProps`, `AlertButtonProps`. Yeh React ecosystem mein standard hai. Optional hai lekin code padhne mein aasan hota hai.

---

Q: Interface ko doosri file mein use karne ke liye kaunsa import syntax sahi hai?
A. `import interface { User } from "./types"` — interface ke saath special keyword
B. `import User from "./types"` — default import ki tarah bina curly braces ke
C. `import type { User } from "./types"` — type import, runtime bundle mein nahi aata
D. `import { interface User } from "./types"` — interface keyword ke saath import
> C. `import type` bundler ko batata hai ki yeh sirf type hai, runtime value nahi. Types compile time ke baad bundle se hat jaate hain, isliye bundle size chhoti rehti hai.

---

Q: React mein props kya hote hain?
A. Props ek global state management system hai jo saare components share karte hain
B. Props function arguments ki tarah hain jo parent component se data child tak le jaate hain
C. Props ek CSS-in-JS library hai jo component ko style karne ke liye use hoti hai
D. Props ek browser API hai jo React components ko native elements se connect karti hai
> B. Jis tarah function parameters leta hai, usi tarah component props leta hai. `<ProfileCard name="Vin" />` likhne se React ek `{ name: "Vin" }` object banata hai aur component ko props ke through deta hai.

---

Q: Inline type aur interface mein sabse important fark kya hai?
A. Inline type faster hota hai runtime mein, interface slow hota hai
B. Interface reuse ho sakta hai multiple jagah, inline type reuse nahi ho sakta
C. Inline type sirf class components mein kaam karta hai, interface function components mein
D. Interface sirf TypeScript strict mode mein kaam karta hai, inline type nahi
> B. Inline type `(props: { name: string })` — ek hi component mein use kar sakte ho, doosri jagah nahi. Interface `interface Props { name: string }` — `export` karke kahi aur bhi `import` kar sakte ho.

---

Q: Interface mein property ko optional kaise banate hain?
A. Property ke aage `opt_` prefix laga kar — `opt_name: string`
B. Property ko square brackets mein wrap kar ke — `[name]: string`
C. Property ke baad `?` laga kar — `role?: string`
D. Property ke type mein `| undefined` add kar ke — `role: string | undefined`
> C. `role?: string` — `?` property ke baad lagao taake optional ho jaye. Agar pass nahi kiya to `undefined` hogi. `||` operator se default value de sakte ho — `props.role || "No role specified"`.

Q: Destructuring ka kya fayda hai jab props ke saath use karte hain?
A. Destructuring se props automatically immutable ho jaate hain kabhi change nahi ho sakte
B. Destructuring se props ka type check runtime par hota hai compile time par nahi
C. Destructuring se `props.` likhne ki zaroorat nahi — seedha property name use kar sakte ho
D. Destructuring se component ki performance improve hoti hai re-render kam ho jaate hain
> C. `function Card({ name, role }: Props)` — ab seedha `name` aur `role` use kar sakte ho, `props.name` nahi likhna padta. Destructuring syntactical sugar hai — code chhota aur readable banata hai.

Q: Default values destructuring ke saath kaise dete hain?
A. `function Card({ name, role = "Default" }: Props)` — destructuring mein hi default value assign
B. `function Card({ name, role }: Props = { role: "Default" })` — poore props object ko default
C. `function Card(props: Props = { role: "Default" })` — function parameter default value
D. Destructuring ke saath default values dena possible nahi hai — alag se handle karna padta hai
> A. `role = "Default"` — destructuring ke andar hi default value assign kar sakte ho. Agar `role` undefined hai to yeh default use hogi. Yeh professional React code mein standard practice hai.

Q: Callback props kya hote hain?
A. Callback props wo hote hain jo component ko ek baar call karne ke baad automatically destroy ho jaate hain
B. Callback props wo props hain jinka type function hai — child parent ko kuch batane ke liye
C. Callback props wo props hain jo ek specific time interval par automatically call hote hain
D. Callback props wo props hain jo sirf class components mein kaam karte hain function mein nahi
> B. Props sirf data (string, number, boolean) nahi, functions bhi pass kar sakte ho. Callback prop = function as prop. Child jab button click kare to `props.onAlert()` call karega, aur parent ka function execute hoga.

Q: Callback props ke naam mein kaunsa prefix convention use hota hai?
A. `handle` prefix — `handleClick`, `handleSubmit`, `handleDelete` — React standard hai
B. `cb` prefix — `cbClick`, `cbSubmit`, `cbDelete` — callback ka short form hai
C. `on` prefix — `onClick`, `onSubmit`, `onDelete` — React events ke saath consistent
D. `callback` prefix — `callbackClick`, `callbackSubmit` — full word use karna convention hai
> C. `on` prefix — `onClick`, `onAlert`, `onSend`. Yeh React ki built-in events (`onClick`, `onChange`) se match karta hai. Code padhte hi pata chal jata hai ki yeh callback prop hai — parent → child nahi, child → parent signal hai.

Q: Interface ko multiple functions mein reuse karne ka kya fayda hai?
A. Har function apna alag interface define kare to zyada type safety hoti hai
B. Interface reuse se consistency rehti hai — same type har jagah enforce hota hai
C. Interface reuse se runtime performance improve hoti hai kaafi had tak
D. Interface reuse ka koi practical fayda nahi — inline type better option hai
> B. Interface reuse ka fayda consistency hai — ek hi `User` interface 10 functions mein use kar sakte ho. Agar ek jagah property change ki to sab jagah auto-reflect. Inline type se har jagah alag change karna padta.

Q: `props` naam — yeh React keyword hai ya sirf ek convention?
A. `props` React ka reserved keyword hai — kuch aur likhne se error aati hai
B. `props` sirf convention hai — tum `data`, `p`, ya kuch bhi likh sakte ho
C. `props` sirf class components mein zaroori hai function components mein nahi
D. `props` sirf TypeScript mein chalta hai plain JavaScript mein kaam nahi karta
> B. `props` keyword nahi hai — sirf function parameter ka naam hai. Tum kuch bhi likh sakte ho. Lekin industry standard `props` hai — kisi aur ka code padhoge to `props` dekh ke pata chalega ki yeh React component hai.

Q: Conditional rendering ke liye kaunsa operator use karte hain?
A. `{sender && <p>{sender}</p>}` — agar sender exist karta hai to render, nahi to kuch nahi
B. `{if (sender) { <p>{sender}</p> }}` — if statement ke saath conditional render
C. `{sender ?: <p>{sender}</p>}` — ternary operator ka ek short form hai
D. `{sender ?? <p>{sender}</p>}` — nullish coalescing operator se render hota hai
> A. `{sender && <p>{sender}</p>}` — JavaScript `&&` operator. Jab sender undefined/null hai to React kuch render nahi karta. Jab sender ki value hai to `<p>` render hota hai. `if` statement JSX mein use nahi kar sakte.

Q: `() => void` type ka kya matlab hai callback props mein?
A. Ek function jo koi parameter nahi leta aur kuch return nahi karta — sirf kaam karta hai
B. Ek function jo ek parameter leta hai void return type ke saath — data leta hai kuch nahi deta
C. Ek function jo koi parameter nahi leta aur ek number return karta hai default mein
D. Ek function jo multiple parameters leta hai aur ek string return karta hai hamesha
> A. `() => void` — `()` means koi parameter nahi, `void` means koi value return nahi karta. Sirf kaam karta hai — jaise `alert()`, `console.log()`. `(message: string) => void` — ek parameter leta hai, value return nahi karta.

---

Q: Callback prop mein child parent ko data kaise bhejta hai?
A. Callback props parameter nahi le sakte — child sirf signal bhej sakta hai data nahi
B. Parent callback mein parameter type define karta hai aur child call karte waqt value pass karta hai
C. Child parent ko data nahi bhej sakta — data hamesha parent se child ki taraf jaata hai
D. Data bhejne ke liye child ko ek alag API call karni padti hai callback kaam nahi karta
> B. Parent define karta hai — `onSend: (message: string) => void`. Child call karta hai — `onSend("Hello from child!")`. Parent ka function `message` parameter receive karta hai. Child → Parent data pass karne ka yahi standard pattern hai.

- True
- False
> False. Interface sirf TypeScript ka compile-time feature hai. Runtime mein interfaces exist nahi karte. Browser pure JavaScript chalata hai — TypeScript compile karne ke baad saari types hat jaati hain.

- True
- False

Q: Interface mein optional property bhoolne par runtime error aati hai jab browser code execute karta hai.
- True
- False
> False. Error compile-time aati hai, runtime nahi. TypeScript ki superpower yahi hai — jab tum `role` pass karna bhoolte ho, TypeScript development mein hi error de deta hai. Browser tak error nahi pahunchti.

- True
- False
> False. Callback props child → parent communication karte hain (signal up). Parent child ko ek function prop deta hai, child use call karta hai jab kuch hota hai. Regular props (data) parent → child jaate hain (data down).

- True
- False
> True. Destructuring React mein universal practice hai. `function Card({ name, role }: Props)` — `props.name` ki jagah seedha `name`. Code chhota, readable, aur maintainable hota hai.

## ShortAnswer

Q: TypeScript interface kya hai? React props ke saath kaise use hota hai? Example ke saath explain karo.

<details>
<summary>Sample Answer</summary>

**Interface** object ka shape define karta hai — kaun si properties hongi aur unka type kya hoga.

**React Props ke saath use:**

```tsx
// 1. Interface define karo
interface ProfileCardProps {
  name: string;
  role: string;
}

// 2. Interface ko props type ke roop mein use karo
function ProfileCard({ name, role }: ProfileCardProps): JSX.Element {
  return (
    <div>
      <h2>{name}</h2>
      <p>{role}</p>
    </div>
  );
}

// 3. Component use karo
<ProfileCard name="Vin" role="React Developer" />
```

**Key points:**
- `ProfileCardProps` — convention: `ComponentNameProps`
- Interface ko `export` karke doosri files mein reuse kar sakte ho
- `import type { ProfileCardProps }` — runtime bundle mein nahi aata
- Agar wrong property pass ki to compile-time error — browser tak nahi pahunchti

**Interface vs Inline Type:**
- Inline: `(props: { name: string })` — chhote props ke liye
- Interface: `interface Props { name: string }` — complex, reusable components ke liye

</details>

Q: Callback props kya hote hain? Parent aur Child ke beech data flow kaise hota hai? `on` prefix convention ke saath example do.

<details>
<summary>Sample Answer</summary>

**Callback props** = function as prop. Child component parent ko kuch batana chahta hai (jaise button click), to parent ek function prop pass karta hai aur child use call karta hai.

**Parent vs Child Flow:**

```
PARENT (App):
  → handleClick function DEFINE karta hai
  → Child ko prop mein PASS karta hai: onAlert={handleClick}
  → Jab child call karega tab execute hoga

CHILD (AlertButton):
  → onAlert = handleClick RECEIVE karta hai
  → User click karta hai
  → onAlert() CALL karta hai
  → Parent ko signal: "click ho gaya"
```

**Example:**

```tsx
// Child component
interface AlertButtonProps {
  label: string;
  onAlert: (message: string) => void;
}

function AlertButton({ label, onAlert }: AlertButtonProps) {
  return (
    <button onClick={() => onAlert(`Button "${label}" was clicked!`)}>
      {label}
    </button>
  );
}

// Parent component
function App() {
  const handleAlert = (msg: string) => {
    console.log(msg);
    alert(msg);
  };

  return (
    <div>
      <AlertButton label="Save" onAlert={handleAlert} />
      <AlertButton label="Delete" onAlert={handleAlert} />
    </div>
  );
}
```

**Direction:**
- Regular props: Parent → Child (data down)
- Callback props: Child → Parent (signal up)

**`on` prefix convention:** `onClick`, `onAlert`, `onSend` — React ki built-in events se consistent.

</details>
