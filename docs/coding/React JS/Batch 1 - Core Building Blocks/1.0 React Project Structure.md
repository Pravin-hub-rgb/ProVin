Think: "I ran `npm create vite@latest my-app -- --template react-ts`. A folder was created. What's inside?"


Focus on three areas: **top-level files**, the **`src/` folder**, and the **`public/` folder**. Each file has one job, and they form a chain that connects everything.

## Step 2 — Top-Level Files: What Are These?

**`package.json`** — your app's ID card. It contains:
- Project name, version
- Dependencies (which packages are needed)
- Scripts (`"dev"`, `"build"`, `"preview"`)
- This is the file that tells Vite how to run things

**`vite.config.ts`** — Vite's setup file. Enables the React plugin, allows custom configuration. No need to dig into it.

**`tsconfig.json`** — TypeScript's dictator. Strict mode? ESNext target? This file decides. Without it, TypeScript won't work.

**`index.html`** — This is the most important file that many people overlook.

---

## Step 3 — `index.html`: The Real Entry Point

Think: "I open the browser, and a page shows up. Where does that page's HTML come from?"

Why: After learning React, you'll get lost in the `src/` folder and forget that at the end of the day, the browser needs HTML. `index.html` is the file the browser loads directly.

Open `index.html`:

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>My App</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.tsx"></script>
  </body>
</html>
```

Notice: there's an empty `<div id="root"></div>` and a `<script>` tag that loads `main.tsx`.

The browser loads this HTML. It sees — "there's an empty div, and there's a script." The script downloads, TypeScript/JSX has already been compiled into browser-compatible JavaScript (Vite did this), and the script runs.

This `index.html` is the **real entry point** — not `main.tsx`, not `App.tsx`. The browser loads `index.html` first, then the script loads, then React starts its work.

> This is the file that exists in traditional React apps (without a framework). Next.js abstracts this away — you never see `index.html`.

---

## Step 4 — `main.tsx`: Where React's Engine Starts

Think: "The browser loaded the script. Now what?"

Why: `main.tsx` is where React begins building its world. Its only job is to connect React to the DOM.

Open `src/main.tsx`:

```tsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import App from './App.tsx'
import './index.css'

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App />
  </StrictMode>,
)
```

Let's decode each line:

**`import { createRoot } from 'react-dom/client'`** — importing React's DOM connector. `createRoot` is a function that lets React communicate with the browser's DOM.

**`document.getElementById('root')!`** — find the `<div id="root">` from `index.html`. The `!` means "TypeScript, I know this is not null" — because we created that div ourselves.

**`createRoot(...)`** — create a React "root." This means React will now manage the Virtual DOM inside this div. Outside of it, React does nothing.

**`.render(<StrictMode><App /></StrictMode>)`** — render the `<App />` component inside this root. `<StrictMode>` is a wrapper that enables extra development-time checks.

**`import App from './App.tsx'`** — importing the App component. This is our root component.

This file's entire job is completed in four lines: **find the root, connect React, and render App.**

---

## Step 5 — How `createRoot` Works (A Bit Deeper)

Think: "I called `createRoot`, rendered `<App />` — what's actually happening behind the scenes?"

`createRoot` creates a React Root object. This Root is the anchor point for React's Virtual DOM tree. When you call `.render()`, React:

1. Takes your component tree and builds a **Virtual DOM tree**
2. Converts that Virtual DOM into the **Real DOM**
3. Places the real DOM inside `<div id="root">`

This means React only controls what's inside `<div id="root">`. Nothing outside that. That's why `index.html` only has an empty div and a script tag — React takes over from there.

### What It Is NOT

`createRoot` is not a "server" running in the background. It's not a "framework." It's just a function that takes a DOM element and limits React's control to that element.

---

## Step 6 — `App.tsx`: The Root Component

Think: "`main.tsx` rendered `App`. What is `App`?"

Why: `App.tsx` is the component that defines the layout of your entire app. Other components live inside it. This is called the **root component** — the top of the component tree.

Open `src/App.tsx`:

```tsx
import { useState } from 'react'
import './App.css'

function App() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <h1>Hello, World!</h1>
      <button onClick={() => setCount(count + 1)}>
        Count is {count}
      </button>
    </div>
  )
}

export default App
```

This is a **function** that **returns JSX**. React calls this function, takes the returned JSX, builds the Virtual DOM, and finally renders it to the DOM.

`export default App` — this is why `main.tsx` can do `import App from './App.tsx'`. Without this export, the import would fail.

---

## Step 7 — The Component Tree: Who Sits Inside Whom

Think: "Is there just one component — `App`? Or are there more? Who's inside whom?"

Why: React applications are structured as a component tree — components nested inside other components. Visualizing this tree is important.

Right now there's only one component — `App`. But as we go further, the tree will look like this:

```
createRoot
  └── StrictMode
      └── App
          ├── Header
          ├── MainContent
          │   ├── Sidebar
          │   └── ArticleList
          │       ├── ArticleCard
          │       ├── ArticleCard
          │       └── ArticleCard
          └── Footer
```

Each component takes props from its parent, renders children, and React decides when to update which one.

> You can visualize this tree using the React Developer Tools browser extension — the Components tab shows the entire tree.

## Step 9 — The Pipeline: From `npm run dev` to the Browser Screen

Think: "I typed `npm run dev` in the terminal. What happened next that made the page show up in the browser?"

Visualize the full pipeline:

```
npm run dev
    ↓
Vite dev server starts (port 5173)
    ↓
index.html served to the browser
    ↓
Browser parses index.html
    ↓
Finds <script src="/src/main.tsx">
    ↓
Vite transforms main.tsx and all its imports (App.tsx, etc.)
    TypeScript/JSX → browser-compatible JavaScript
    ↓
Transformed code reaches the browser
    ↓
createRoot(document.getElementById('root')!) runs
    ↓
React builds the Virtual DOM
    ↓
React updates the Real DOM
    ↓
Renders on the browser screen
    ↓
HMR is ready — change code, only the changed part updates
```

Every time you change code, Vite recompiles only the changed file and sends the update to the browser. This is called **Hot Module Replacement (HMR)**.

## Step 10 — Traditional React vs Vite/Next.js Abstraction

Think: "You said `index.html` is the entry point. But where is `index.html` in Next.js?"

Why: Different tools abstract different things. Traditional React (with Vite) shows you `index.html`. Next.js doesn't.

| | Traditional React (Vite) | Next.js |
|---|---|---|
| Entry point | `index.html` + `main.tsx` | File-based routing |
| `index.html` | Visible, editable | Abstracted, internally managed |
| Routing | Manual (React Router) | Automatic (from folder structure) |
| Component mount | `createRoot` called in main.tsx | Framework handles it |

In traditional React (Vite), you can open `index.html` and see the `<div id="root">`. In Next.js, all of this is handled internally by the framework — you just create a `page.tsx` file.

This course uses **Traditional React (Vite)**. Next.js gets its own separate course later. But the concepts are the same — both use React components, props, and state. Only the setup approach differs.

## Step 11 — At a Glance: The Complete Connection Map

```
index.html
  │ <div id="root"></div>
  │ <script src="/src/main.tsx">
  ▼
main.tsx
  │ createRoot(document.getElementById('root')!)
  │ .render(<App />)
  ▼
App.tsx
  │ function App() { return ( JSX ) }
  ▼
JSX → Babel/Vite → React.createElement() → Virtual DOM → Real DOM
  ▼
Rendered on browser screen
```

This is the chain. Every file is connected to the next. Break one link, and the app won't run.

## In Your Own Words (Self-Check)

Answer these 5 questions yourself first, then click `details` to compare with the sample answer.

1. **After running `npm run dev`, what happens step by step until the page shows up in the browser?**

<details>
<summary>Sample Answer</summary>

`npm run dev` → Vite dev server starts → `index.html` served to browser → Browser parses `index.html` → `<script src="/src/main.tsx">` is found → Vite transforms `main.tsx` and all its imports (App.tsx, index.css, etc.) from TypeScript/JSX into browser-compatible JavaScript → Transformed code reaches the browser → `createRoot(document.getElementById('root')!)` runs → React renders `<App />` → Virtual DOM is built → Real DOM is updated → Browser renders to screen.
</details>

2. **What does `createRoot` do? What happens if you don't call `createRoot` in `main.tsx`?**

<details>
<summary>Sample Answer</summary>

`createRoot` connects React to a DOM element — React will now manage the Virtual DOM inside that element. Without calling `createRoot`, React never connects to the DOM — no matter what component tree you build, nothing will display on screen because React doesn't know where to render.

</details>

3. **Why is `index.html` the "real entry point" and not `main.tsx`?**

<details>
<summary>Sample Answer</summary>

The browser loads `index.html` first — it's the entry point for HTML, CSS, and JavaScript. `main.tsx` cannot be loaded directly by the browser (it's TypeScript/JSX). So `index.html` includes a `<script>` tag that points to `main.tsx`. `main.tsx` is React's entry point, but not the browser's.

</details>

4. **What is a component tree? Why is `App.tsx` the root component?**

<details>
<summary>Sample Answer</summary>

A component tree is a hierarchy where components are nested inside other components. `App.tsx` is the root component because:
- `createRoot().render(<App />)` renders `App` first
- All other components are rendered inside `App` (directly or indirectly)
- `App` is at the top of the tree

</details>

5. **What's the difference in file structure between Traditional React (Vite) and Next.js?**

<details>
<summary>Sample Answer</summary>

In Traditional React (Vite), `index.html` is visible and editable, you call `createRoot` yourself, and routing is manual (React Router). In Next.js, `index.html` is abstracted away (internally managed), `createRoot` is handled by the framework, and routing is file-based (created automatically from folder structure). The concepts are the same — both use React components — but the setup approach is different.

</details>
