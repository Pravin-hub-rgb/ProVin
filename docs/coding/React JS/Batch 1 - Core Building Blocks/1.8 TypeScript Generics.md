## Abhi Tak Kya Hua

1.7 mein `useState` hook seekha — state store karna aur event handling. `useState(0)` likha toh TypeScript automatically infer kar gaya ki type `number` hai. Lekin kabhi kabhi TypeScript infer nahi kar paata — tab `useState<Item[]>([])` jaise syntax use karte hain. Yeh `<Item[]>` wala angle bracket syntax **generics** hai. Is chapter mein bilkul basics se samjhenge.

## Broader Goal

TypeScript ka ek powerful feature hai — **generics**. Jab tak specific type nahi pata, tab tak generic type variable use kar sakte ho. Socho ek function jo kisi bhi type ka array reverse kar de — `number[]`, `string[]`, `User[]` — ek hi function sabke liye kaam kare. Generics se yeh possible hai.

## Step 1 — Problem Feel Karo

Soch: "Ek function chahiye jo array ka pehla element return kare. Lekin array mein numbers bhi ho sakte hain, strings bhi, objects bhi."

Bina generics ke — alag functions banane padte:

```typescript
// Sirf numbers ke liye
function getFirstNumber(arr: number[]): number | undefined {
  return arr[0];
}

// Sirf strings ke liye
function getFirstString(arr: string[]): string | undefined {
  return arr[0];
}

// Sirf booleans ke liye
function getFirstBoolean(arr: boolean[]): boolean | undefined {
  return arr[0];
}
```

Teeno functions ka kaam ek jaise hai — sirf type alag hai. Dusre types ke liye firse kyun likhein? `any` use kar sakte ho:

```typescript
function getFirstAny(arr: any[]): any {
  return arr[0];
}
```

`any` se TypeScript ka poora fayda khatam ho jata hai — type safety nahi bachti. `string` array daala, `number` return hua, TypeScript kuch nahi bolega.

**Solution — Generics:** Ek aisa pattern jismein type ko variable ki tarah use kar sakte ho. Jaise function parameter value leta hai (`function add(a, b)`), waise generic `<T>` type leta hai. Call karte waqt actual type decide hoti hai.

**Real-world analogy:** Ek container box jo kuch bhi hold kar sakta hai — books, clothes, toys. Box ka shape same rehta hai, andar ka item change hota hai. Generics bhi aisa hi hai — code ka structure same, type change hoti rehti hai.

## Step 2 — Generic Function: Pehla Example

```typescript
function getFirst<T>(arr: T[]): T | undefined {
  return arr[0];
}
```

**Definition — Generics:** TypeScript ka feature jismein `<T>` ek placeholder type hota hai. Actual type tab decide hoti hai jab function call hota hai. Isliye kahte hain "generic" — specific type nahi, general purpose.

Yahan `<T>` ek **type variable** hai — jaise function parameter `arr` value leta hai, waise `<T>` type leta hai. Jab function call karte ho, tab T ki actual type decide hoti hai.

```typescript
const firstNum = getFirst<number>([10, 20, 30]);
// T = number → return type number | undefined
// firstNum = 10

const firstStr = getFirst<string>(["a", "b", "c"]);
// T = string → return type string | undefined
// firstStr = "a"

const firstBool = getFirst<boolean>([true, false]);
// T = boolean → return type boolean | undefined
// firstBool = true
```

**Line by line:**

1. `function getFirst<T>` — `function` keyword, naam `getFirst`, aur `<T>` generic type parameter
2. `(arr: T[])` — function ek parameter leta hai `arr` jiska type hai `T[]` (T type ka array)
3. `: T | undefined` — return type: `T` ya `undefined` (agar array khali hai toh)
4. `<number>([10, 20, 30])` — call karte waqt `<number>` bataya ki T = number hai

Generic ke bina teen functions likhne padte. Generic se ek function, sab types ke liye.

### TypeScript Type Inference with Generics

Accha lagta hai `<number>` explicit likhna. Lekin TypeScript **infer** kar sakta hai:

```typescript
const firstNum = getFirst([10, 20, 30]);
// TypeScript: "[10, 20, 30] → number[] → T = number"
// Explicit <number> likhne ki zaroorat nahi
```

TypeScript argument `[10, 20, 30]` ko dekh kar samajh leta hai ki `T = number`. Isliye `getFirst([10, 20, 30])` kaam karta hai, bina `<number>` likhe.

```typescript
const firstStr = getFirst(["x", "y"]);  // infer → string
const firstBool = getFirst([true]);      // infer → boolean
```

Inference kaam karta hai jab TypeScript actual value se type deduce kar sakta hai. Complex cases mein explicit generic dena padta hai — React mein `useState<User | null>(null)` jaise.

### Breakdown

```
function getFirst<T>(arr: T[]): T | undefined {
      //            ↑     ↑       ↑
      //            |     |       return type: T ya undefined
      //            |     parameter: T ka array
      //            generic type parameter
  return arr[0];
}

getFirst<number>([10, 20, 30])
//       ↑
//       explicit: T = number
```

### Common Variable Names for Generics

| Variable | Meaning |
|----------|---------|
| `T` | Type (default, sabse common) |
| `U` | doosra type |
| `V` | teesra type |
| `TItem` | meaningful name (array item type) |

React events mein dekhte ho: `ChangeEvent<HTMLInputElement>` — yahan `HTMLInputElement` specific type hai jo `<T>` ki jagah aaya hai.

## Step 3 — T Koi Bhi Type Accept Karta Hai

Abhi tak `T` koi bhi type ho sakta hai — number, string, boolean, object, array, kuch bhi. Lekin kya agar T ko restrict karna ho? Jaise "sirf wahi types jo `.length` property rakhte hain"?

Jab aisa karna ho, tab **constraints** use karte hain:

```typescript
function getLength<T extends { length: number }>(item: T): number {
  return item.length;
}
```

`T extends { length: number }` ka matlab — "T sirf wahi type ho sakta hai jisme `length: number` property ho". Strings aur arrays dono mein length hota hai:

```typescript
getLength("Hello");      // 5 — string mein length hota hai
getLength([1, 2, 3]);    // 3 — array mein length hota hai
// getLength(123);       // ❌ Error — number mein length nahi hota
```

**Abhi ke liye itna jaanna kaafi hai.** React mein constraints ka use mainly event handlers mein hota hai — `ChangeEvent<HTMLInputElement>` mein `HTMLInputElement` specific DOM element type hai jo generic parameter mein aata hai.

## Step 4 — Multiple Type Parameters

Ek function do generic parameters bhi le sakta hai:

```typescript
function pair<T, U>(first: T, second: U): [T, U] {
  return [first, second];
}

const result = pair<string, number>("age", 25);
// result = ["age", 25] — type: [string, number]
```

TypeScript inference se kaam ho jata hai:

```typescript
const result = pair("age", 25);  // infer → [string, number]
```

React mein multiple generics rare hain. Zyada tar ek hi generic parameter hota hai — `useState<T>`, `useRef<T>`, `ChangeEvent<T>`.

## Step 5 — Generics in TypeScript Types (Interfaces)

Generics sirf functions ke saath nahi, types/interfaces ke saath bhi kaam karte hain:

```typescript
interface Box<T> {
  value: T;
}

const numberBox: Box<number> = { value: 42 };
const stringBox: Box<string> = { value: "hello" };
```

`Box<T>` ek generic interface hai. `T` ki jagah koi bhi type aa sakta hai. Yeh React mein common hai — jaise `Array<T>` generic interface hai:

```typescript
// Yeh dono same hain:
const nums1: number[] = [1, 2, 3];
const nums2: Array<number> = [1, 2, 3];
```

`number[]` actually `Array<number>` ka shorthand hai. Typescript generics React mein har jagah dikhenge — abhhi React component types mein dekhte hain.

## Step 6 — React Mein Generics

React extensively generics use karta hai. Kuch common examples.

### Pehle Samajh — T Sirf Simple Type Nahi, Koi Bhi Type Hai

Step 2 mein dekha: `getFirst<number>` → T = number, `getFirst<string>` → T = string. Simple types the.

Lekin **T koi bhi type ho sakta hai** — simple bhi, complex bhi:

```typescript
// T = number[] (array of numbers)
getFirst<number[]>([1, 2, 3]);

// T = Item[] (array of Items) — Item ek interface hai
interface Item {
  id: number;
  text: string;
}
getFirst<Item[]>([{ id: 1, text: "Hello" }]);

// T = string | null (union type)
getFirst<string | null>([null, "a", null]);
```

Same `<T>` syntax, bas T ki value complex ho sakti hai — array, object, union, kuch bhi.

### useState

Ab useState mein same pattern:

```typescript
// T = number — same as getFirst<number>
const [count, setCount] = useState(0);

// T = string — same as getFirst<string>
const [name, setName] = useState("");

// T = Item[] — (Item interface upar "Pehle Samajh" mein define hai)
const [items, setItems] = useState<Item[]>([]);
```

Jab initial value se type clear ho (`useState(0)` → number), inference kaam karta hai. Jab complex ho (empty array, nullable), tab explicit generic dena padta hai:

```typescript
interface User {
  id: number;
  name: string;
}

const [user, setUser] = useState<User | null>(null);
// null se TypeScript infer nahi kar sakta ki User type hoga
```

### Event Types

```typescript
const handleChange = (event: React.ChangeEvent<HTMLInputElement>) => {
  // ChangeEvent<HTMLInputElement> — generic type
  // HTMLInputElement specific DOM element type hai
};
```

`React.ChangeEvent<T>` ek generic type hai. `<HTMLInputElement>` specific type hai jo batata hai ki kaunsa element event trigger kar raha hai. `HTMLTextAreaElement`, `HTMLSelectElement`, `HTMLFormElement` — sab specific DOM element types hain.

### Recap — T ka Flow

```
getFirst<number>          → T = number
getFirst<string>          → T = string
getFirst<Item[]>          → T = Item[]
useState<number>(0)       → T = number      (same pattern)
useState<Item[]>([])      → T = Item[]      (same pattern)
ChangeEvent<HTMLInputElement> → T = HTMLInputElement  (same pattern)
```

Bas teen cheezein React mein generics use karti hain Batch 1 level tak — `useState<T>`, `ChangeEvent<T>`, aur `Array<T>` (jo `T[]` ka dusra syntax hai).

## Step 7 — Generic vs Inference: Kab Kya Use Karein

| Situation | Generics Chahiye? | Example |
|-----------|-------------------|---------|
| Initial value se type clear | ❌ Inference kaafi | `useState(0)` |
| Empty array — type unclear | ✅ Explicit generic | `useState<Item[]>([])` |
| Null/undefined initial value | ✅ Explicit generic | `useState<User \| null>(null)` |
| Function — koi bhi type accept | ✅ Generic function | `getFirst<T>(arr: T[])` |
| Event handler — specific element | ✅ Generic type | `ChangeEvent<HTMLInputElement>` |
| Simple prop types | ❌ Regular interface | `interface Props { name: string }` |

## Summary

- **Generics** — type variable jo call/use karte waqt specific type ban jaata hai
- Syntax: `<T>` — angle brackets + type variable
- Convention: `T`, `U`, `V` ya meaningful name like `TItem`
- Functions: `function name<T>(arg: T): T`
- Types/Interfaces: `interface Box<T> { value: T }`
- React: `useState<T>()`, `ChangeEvent<T>`, `Array<T>`
- **Inference** — TypeScript khud type deduce kar leta hai (mostly)
- **Explicit** — jab inference enough nahi (empty array, nullable)
- Constraints: `T extends { length: number }` — type restrict karna

## Mini-Project 1 — Explicit useState Practice

Soch: "`useState(0)` likha toh TypeScript infer kar leta hai ki type `number` hai. Lekin yeh sirf tab kaam karta hai jab initial value se type clear ho. Kya hoga jab initial value se type clear nahi? Jaise `useState(null)` ya `useState([])` — TypeScript confuse ho jata hai."

**Goal:** Ek app banayenge jisme teen state variables hain — ek inference se, do explicit generic ke saath. Dekhenge kab inference kaam karta hai aur kab explicit dena padta hai.

### Kya Banayenge?

App teen sections ka hoga:

| Section | State Type | Initial Value | UI |
|---------|-----------|---------------|-----|
| Name | `string` | `""` | Input + display text |
| Nickname | `string \| null` | `null` | Input + "(not set)" jab empty |
| Tags | `string[]` | `[]` | Input + Add button + comma-separated list |

**Final UI dikhega kuch aisa:**

```
┌─────────────────────────────────┐
│  useState Type Practice          │
│                                   │
│  Inference (state = "")          │
│  [Enter name...]                  │
│  Name: "John"                     │
│                                   │
│  Explicit (state = string | null) │
│  [Enter nickname...]              │
│  Nickname: (not set)              │
│                                   │
│  Explicit (state = string[])      │
│  [Enter tag...] [Add Tag]         │
│  Tags: react, typescript          │
└─────────────────────────────────┘
```

Ab step by step banate hain.

### Step 1 — Inference wala state banao

Sabse simple case: initial value se type clear hai.

```tsx
import { useState } from "react";

function App() {
  const [name, setName] = useState(""); // TypeScript: initial value "" → infer → string

  return (
    <div>
      <input value={name} onChange={(e) => setName(e.target.value)} placeholder="Name" />
      <p>Name: {name}</p>
    </div>
  );
}
```

**Kyun?** `""` ek string hai. TypeScript dekh leta hai ki state hamesha string type ki hogi. Inference kaam kar gaya. Simple case mein explicit `<string>` likhna zaroori nahi.

### Step 2 — Null initial value — explicit generic do

Soch: "Kya hoga agar `null` initial value do?"

```tsx
const [nickname, setNickname] = useState(null); // infer → null
```

`null` se TypeScript infer karega ki type `null` hai — sirf `null`. `string` assign nahi kar sakte. Yeh problem hai.

**Solution:** Explicit generic do — TypeScript ko batao ki "null initial value hai, lekin baad mein string bhi aa sakti hai":

```tsx
const [nickname, setNickname] = useState<string | null>(null);
//      ↑                          ↑
//      state type                  explicit: string ya null dono allowed
```

`<string | null>` ka matlab: "T = string | null". Union type hai — dono allowed. Ab set kar sakte ho:

```tsx
<input
  value={nickname ?? ""}
  onChange={(e) => setNickname(e.target.value || null)}
  placeholder="Nickname"
/>
```

`e.target.value || null` — agar value empty hai toh null set karo, nahi toh string. TypeScript kuch nahi bolega kyunki type `string | null` dono allow karta hai.

**UI behavior:** Input mein type karo → nickname display ho. Input clear karo → "(not set)" dikhe (kyunki null ho gaya).

### Step 3 — Empty array — explicit generic do

Soch: "Aur empty array? `useState([])` likhne se kya hoga?"

```tsx
const [tags, setTags] = useState([]); // infer → never[]
// never[] matlab: "khali array aur hamesha khali rahega"
```

`never[]` ka matlab kuch daal nahi sakte. Galat hai.

**Solution:** Explicit generic batao ki yeh `string[]` array hai:

```tsx
const [tags, setTags] = useState<string[]>([]); // T = string[]
```

**Ab UI banate hain.** Ek input + button chahiye — user type kare, Add dabaye, aur tag list mein add ho jaye. Neeche comma-separated dikhe.

```tsx
const [inputTag, setInputTag] = useState("");

const handleAddTag = () => {
  if (inputTag.trim() === "") return;
  setTags([...tags, inputTag.trim()]);
  setInputTag(""); // input clear karo after add
};

return (
  <div>
    <input
      value={inputTag}
      onChange={(e) => setInputTag(e.target.value)}
      placeholder="Enter tag..."
    />
    <button onClick={handleAddTag}>Add Tag</button>
    <p>Tags: {tags.join(", ") || "(empty)"}</p>
  </div>
);
```

**Kaise kaam karta hai:**

1. User input mein "react" type karta hai → `inputTag` state update hota hai
2. Add Tag button dabata hai → `handleAddTag` call hota hai
3. `inputTag.trim()` check karta hai ki empty toh nahi
4. `setTags([...tags, inputTag.trim()])` — purane array ko spread karo, naya tag add karo
5. `setInputTag("")` — input field clear karo
6. `tags.join(", ")` — array ke saare strings ko comma-separated dikhao

**UI flow:**

```
[Enter tag...] [Add Tag]    ← inputTag="" hai
User types "react"
[react] [Add Tag]           ← inputTag="react"
User clicks Add Tag
[Enter tag...] [Add Tag]    ← inputTag="" ho gaya (clear)
Tags: react                  ← tags=["react"] display ho raha
```

### Final Code — Mini-Project 1

```tsx
import { useState } from "react";

export default function App() {
  // ✅ Inference — initial value "" se type clear hai
  const [name, setName] = useState("");

  // ✅ Explicit — <string | null> kyunki null se inference sirf "null type" karega
  const [nickname, setNickname] = useState<string | null>(null);

  // ✅ Explicit — <string[]> kyunki [] se inference "never[]" karega
  const [tags, setTags] = useState<string[]>([]);

  const [inputTag, setInputTag] = useState("");

  const handleAddTag = () => {
    if (inputTag.trim() === "") return;
    setTags([...tags, inputTag.trim()]);
    setInputTag("");
  };

  return (
    <div>
      <h2>1. useState Type Practice</h2>

      <div>
        <h3>Inference (state = "")</h3>
        <input value={name} onChange={(e) => setName(e.target.value)} placeholder="Name" />
        <p>Name: "{name}"</p>
        <small>TypeScript inferred: string</small>
      </div>

      <div>
        <h3>Explicit (state = string | null)</h3>
        <input
          value={nickname ?? ""}
          onChange={(e) => setNickname(e.target.value || null)}
          placeholder="Nickname"
        />
        <p>Nickname: {nickname ?? "(not set)"}</p>
        <small>TypeScript expects: string | null</small>
      </div>

      <div>
        <h3>Explicit (state = string[])</h3>
        <input
          value={inputTag}
          onChange={(e) => setInputTag(e.target.value)}
          placeholder="Enter tag..."
        />
        <button onClick={handleAddTag}>Add Tag</button>
        <p>Tags: {tags.join(", ") || "(empty)"}</p>
        <small>TypeScript expects: string[]</small>
      </div>
    </div>
  );
}
```

### Test

1. Name input mein type karo → value update hota hai, neeche display ho
2. Nickname input empty karo → "(not set)" dikhe. Type karo → value dikhe
3. Tags wale input mein "react" type karo → Add Tag dabao → "react" list mein add ho. "typescript" add karo → "react, typescript" dikhe
4. Console mein `typeof` check karo — teeno state variables ka type alag hai

## Mini-Project 2 — Typed Event Handlers

Soch: "`handleChange` likhna hai. `(e) => ...` likh diya. Lekin `e` ka type kya hai? `React.ChangeEvent<HTMLInputElement>` — yeh `<HTMLInputElement>` wala part generic hai. Lekin kya hoga agar `<textarea>` ya `<select>` ho? Toh `<HTMLTextAreaElement>` ya `<HTMLSelectElement>` use karna padta hai."

**Goal:** Ek form banayenge jisme `<input>`, `<textarea>`, aur `<select>` — teeno DOM elements hain. Har ek ka `ChangeEvent<T>` type alag hai. Dekhenge ki `<T>` ki value DOM element ke hisaab se kyun badalti hai.

### Step 1 — Input field ka event handler

Input field ke liye `HTMLInputElement` use karte hain:

```tsx
import { useState } from "react";

function App() {
  const [text, setText] = useState("");

  // ChangeEvent<HTMLInputElement> — input field ke liye
  const handleInput = (e: React.ChangeEvent<HTMLInputElement>) => {
    setText(e.target.value);
  };

  return (
    <div>
      <input value={text} onChange={handleInput} placeholder="Type here..." />
      <p>Input: {text}</p>
    </div>
  );
}
```

**Kyun `HTMLInputElement`?** `e.target` ka type React ko pata hona chahiye. Input field ka target `HTMLInputElement` hota hai — jisme `value` property hoti hai. Agar galat type do, toh `e.target.value` accessible nahi hoga.

### Step 2 — Textarea ka event handler

Textarea ka type `HTMLTextAreaElement` hai — same `ChangeEvent<T>` pattern, bas T badla:

```tsx
const [bio, setBio] = useState("");

// ChangeEvent<HTMLTextAreaElement> — textarea ke liye
const handleTextarea = (e: React.ChangeEvent<HTMLTextAreaElement>) => {
  setBio(e.target.value);
};

return (
  <textarea value={bio} onChange={handleTextarea} placeholder="Your bio..." rows={3} />
);
```

`HTMLTextAreaElement` aur `HTMLInputElement` dono mein `.value` hota hai, lekin React type safety ensure karta hai ki sahi DOM element ka type use ho raha hai.

**Coder mindset:** "Dono mein onChange kaam karta hai. Lekin TypeScript ko exact type chahiye — `HTMLInputElement` vs `HTMLTextAreaElement` alag types hain. Agar `<textarea>` ke liye `HTMLInputElement` likh diya, toh TypeScript error dega."

### Step 3 — Select ka event handler

Select dropdown ka type `HTMLSelectElement` hai:

```tsx
const [role, setRole] = useState("user");

// ChangeEvent<HTMLSelectElement> — dropdown ke liye
const handleSelect = (e: React.ChangeEvent<HTMLSelectElement>) => {
  setRole(e.target.value);
};

return (
  <select value={role} onChange={handleSelect}>
    <option value="user">User</option>
    <option value="admin">Admin</option>
    <option value="moderator">Moderator</option>
  </select>
);
```

**Kyun alag types?** React ka `ChangeEvent<T>` generic type hai. `<T>` ki jagah actual DOM element type aati hai:
- `<input>` → `ChangeEvent<HTMLInputElement>`
- `<textarea>` → `ChangeEvent<HTMLTextAreaElement>`
- `<select>` → `ChangeEvent<HTMLSelectElement>`

Teeno ka `e.target.value` same hota hai, lekin TypeScript enforce karta hai ki sahi DOM element ka type use karo — bug prevention ke liye.

### Final Code — Mini-Project 2

```tsx
import { useState } from "react";

export default function App() {
  const [text, setText] = useState("");
  const [bio, setBio] = useState("");
  const [role, setRole] = useState("user");

  // ChangeEvent<HTMLInputElement>
  const handleInput = (e: React.ChangeEvent<HTMLInputElement>) => {
    setText(e.target.value);
  };

  // ChangeEvent<HTMLTextAreaElement>
  const handleTextarea = (e: React.ChangeEvent<HTMLTextAreaElement>) => {
    setBio(e.target.value);
  };

  // ChangeEvent<HTMLSelectElement>
  const handleSelect = (e: React.ChangeEvent<HTMLSelectElement>) => {
    setRole(e.target.value);
  };

  return (
    <div>
      <h2>2. ChangeEvent Type Practice</h2>

      <div>
        <h3>Input (ChangeEvent&lt;HTMLInputElement&gt;)</h3>
        <input value={text} onChange={handleInput} placeholder="Type here..." />
        <p>Text: {text}</p>
      </div>

      <div>
        <h3>Textarea (ChangeEvent&lt;HTMLTextAreaElement&gt;)</h3>
        <textarea value={bio} onChange={handleTextarea} placeholder="Your bio..." rows={3} />
        <p>Bio: {bio}</p>
      </div>

      <div>
        <h3>Select (ChangeEvent&lt;HTMLSelectElement&gt;)</h3>
        <select value={role} onChange={handleSelect}>
          <option value="user">User</option>
          <option value="admin">Admin</option>
          <option value="moderator">Moderator</option>
        </select>
        <p>Role: {role}</p>
      </div>
    </div>
  );
}
```

### Test

1. Input mein type karo — text update ho
2. Textarea mein type karo — bio update ho
3. Select dropdown change karo — role update ho
4. Har event handler ka type alag hai (`HTMLInputElement`, `HTMLTextAreaElement`, `HTMLSelectElement`) — lekin sab same `ChangeEvent<T>` pattern follow karte hain
