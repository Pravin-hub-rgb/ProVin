## Abhi Tak Kya Hua

1.5.1 mein interface seekha, 1.5.2 mein props ka concept seekha — component ko data pass karna, `interface ComponentProps`, aur component reusability. Ab optional props, destructuring aur default values seekhenge — yeh teen patterns har React component mein use hote hain.

## Broader Goal

Kuch properties component ke liye hamesha chahiye (required), kuch kabhi kabhi (optional). Interface mein `?` se optional mark karte hain. Destructuring se code clean hota hai — `props.name` ki jagah seedha `name`. Default values se missing props handle karte hain. Simple GreetingCard banayenge jo optional sender handle karega.

## Step 1 — Optional Props (Question Mark)

Soch: "Sabke paas role nahi bhi ho sakta — koi fresher hai jiska role assign nahi hua. Kya optional bana sakta hoon?"

**Concept:** Interface mein property ke baad `?` lagane se woh optional ho jaati hai. Agar pass nahi ki toh woh `undefined` hogi.

```tsx
interface ProfileCardProps {
  name: string;
  role?: string;  // optional
}

function ProfileCard(props: ProfileCardProps): JSX.Element {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>{props.role || "No role specified"}</p>
    </div>
  );
}
```

```tsx
<ProfileCard name="Vin" role="React Developer" />  // ✅
<ProfileCard name="Priya" />                         // ✅ role optional
```

`role?` ka matlab — "yeh property ho bhi sakti hai aur nahi bhi". `{props.role || "No role specified"}` — `||` operator se default value: agar `role` undefined hai toh fallback do.

### Common Mistake: `?` bhoolna

```tsx
interface ProfileCardProps {
  name: string;
  role: string;  // ❌ required — hamesha dena padega
}

<ProfileCard name="Priya" />  // ❌ Error: property 'role' missing
```

TypeScript compile-time error dega. Yeh React + TypeScript ka superpower hai — bugs development mein hi pakde jaate hain.

## Step 2 — Destructuring Props

Soch: "Har baar `props.name`, `props.role` likhna repetitive hai. Kya shortcut hai?"

**Concept:** JavaScript **destructuring** — object ki properties ko directly variable mein nikaal sakte ho.

```tsx
interface ProfileCardProps {
  name: string;
  role?: string;
}

// Destructuring in function parameter
function ProfileCard({ name, role }: ProfileCardProps): JSX.Element {
  return (
    <div>
      <h2>{name}</h2>
      <p>{role || "No role specified"}</p>
    </div>
  );
}
```

`function ProfileCard({ name, role }: ProfileCardProps)` — yeh props object ko destructure kar raha hai. Ab seedha `name` aur `role` use kar sakte ho, `props.` nahi likhna padta.

Destructuring React mein standard practice hai. Koi bhi professional React code dekho ge, toh har component mein destructuring dikhega.

### Without vs With Destructuring

```tsx
// Without destructuring
function ProfileCard(props: ProfileCardProps) {
  return <h2>{props.name}</h2>;
}

// With destructuring
function ProfileCard({ name }: ProfileCardProps) {
  return <h2>{name}</h2>;
}
```

Dono same kaam karte hain. Destructuring sirf syntactical sugar hai — code chhota aur readable banata hai.

## Step 3 — Default Values in Destructuring

Soch: "`||` operator se default value dena theek hai. Lekin kya destructuring ke saath hi default de sakta hoon?"

**Concept:** Destructuring ke saath hi default value de sakte ho — `{ role = "No role specified" }`.

```tsx
function ProfileCard({ name, role = "No role specified" }: ProfileCardProps) {
  return (
    <div>
      <h2>{name}</h2>
      <p>{role}</p>
    </div>
  );
}
```

`role = "No role specified"` — agar `role` undefined hai toh yeh default value use hogi. Interface mein `role?` laga hoga, destructuring mein default value assign karte ho.

Yehi pattern professional React code mein har jagah dikhega:

```tsx
interface ButtonProps {
  label: string;
  variant?: "primary" | "secondary";
  disabled?: boolean;
}

function Button({ label, variant = "primary", disabled = false }: ButtonProps) {
  // variant optional hai, default "primary"
  // disabled optional hai, default false
}
```

## Step 4 — Mini-Project: Simple GreetingCard

Simple GreetingCard jo optional sender handle karta hai — destructuring ke saath:

```tsx
interface GreetingCardProps {
  recipient: string;
  message: string;
  sender?: string;
}

function GreetingCard({ recipient, message, sender }: GreetingCardProps) {
  return (
    <div style={{ border: "1px solid #ddd", padding: "16px", borderRadius: "8px", marginBottom: "8px" }}>
      <h2>Hello, {recipient}!</h2>
      <p>{message}</p>
      {sender && <p style={{ color: "#666" }}>— {sender}</p>}
    </div>
  );
}

export default GreetingCard;
```

`sender && <p>...` — conditional rendering. Agar `sender` hai toh show karo, nahi toh kuch mat dikhao. Yeh `&&` operator ka use hai — jab `sender` undefined/null hoga toh React kuch render nahi karega.

```tsx
<GreetingCard recipient="Vin" message="Happy Birthday!" sender="Priya" />
<GreetingCard recipient="Team" message="Great work this week!" />
```

Pehla card `sender` ke saath dikhega, doosra bina sender ke.

## Summary

- Optional props: `role?: string` — `?` lagao property ke baad
- `||` fallback: `props.role || "default"` — undefined par alternative value
- Destructuring: `function Card({ name, role }: Props)` — `props.` nahi likhna padta
- Default values: `role = "No role specified"` — destructuring mein hi de sakte ho
- Conditional render: `{sender && <p>{sender}</p>}` — only if sender exists

## Agla Step

Optional props, destructuring aur default values clear hain. Agle chapter mein **callback props** seekhenge — function as prop pass karna, `on` prefix convention, aur component se parent ko kaise notify karte hain. Yeh real-world React ka essential pattern hai.
