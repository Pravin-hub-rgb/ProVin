### 10. How do you return multiple root elements from a component?

**Answer:** With a Fragment — `<React.Fragment>` or the shorthand `<>...</>`. It groups children without adding a wrapper DOM node, which matters for table rows, list items and SVG where an extra div breaks valid HTML.

**Likely follow-up:** *Can a Fragment take a key?* — Yes, `<React.Fragment key={...}>` when you need keyed grouping; the shorthand `<>` can't.

---

### 12. Why are keys necessary in list rendering?

**Answer:** Keys let React identify which items changed, were added or removed — enabling correct reconciliation and preventing state from landing on the wrong component instance. Use a stable unique id, never the array index for dynamic lists.

**Likely follow-up:** *What breaks with index keys?* — reordering misattributes state (item A's checkbox state lands on item B).

---

### 13. What are props?

**Answer:** Properties — values a parent passes down to a child. A `ProductCard` receives `name` and `price` as props. It's one-way data flow: parent → child, configuration/input from outside.

**Likely follow-up:** *Can the child change a prop?* — No; it calls a callback prop instead, the parent updates its state, and new props flow back down.

---

### 14. Props vs State?

**Answer:** Props are read-only inputs owned by the parent; state is mutable data owned by the component. Props re-render when the parent updates; state re-renders when its setter is called.

**Likely follow-up:** *Which is for dynamic interactive data?* — state (form inputs, counters, selections); props carry API data and configuration.

---

### 15. Why should props be treated as read-only?

**Answer:** One-way data flow guarantees predictability — the parent owns the data, the child is just a view of it. Mutating props (or calling the parent's setState during render) creates side effects and bugs.

**Likely follow-up:** *What's the correct pattern instead?* — pass a callback like `onUpdate`, call it from an event handler, let the parent update state.

---

### 16. What is unidirectional data flow?

**Answer:** Data flows only parent → child through props. Children can't modify parent data directly — to change it, you lift state up and pass callback functions so the child triggers a parent update.

**Likely follow-up:** *Why not two-way binding like Angular's ngModel?* — one-way flow is predictable and far easier to debug (you always know where a value came from).

---

### 17. How does a child component communicate with its parent?

**Answer:** Through a callback function passed down as a prop. The child calls `onMessage(data)` when something happens; the parent's handler updates its state. The child triggers, the parent decides.

**Likely follow-up:** *Real example?* — the Contact Book form: `<ContactForm onAdd={addContact} />`, the form only collects, the parent adds to state.

---

### 19. React element vs component?

**Answer:** An element is an immutable plain object describing what should render (`{ type, props }`) — it's what you return from a component. A component is a function/class blueprint that *creates* elements. React renders elements, not components directly.

**Likely follow-up:** *How heavy is an element?* — very; it's a plain object, so re-creating it each render is cheap — the expensive part is the DOM diff.

---

### 21. What's the common mistake with the `key` prop?

**Answer:** Using the array index as key when items can be reorder/added/deleted. React then reuses the wrong instance — stale state, wrong animations, lost input focus. Use stable unique ids (database ids).

**Likely follow-up:** *When IS index key fine?* — static lists that never reorder, insert or remove items.

---

### 23. Functional vs Class components?

**Answer:** Functional: a plain function returning JSX, using hooks for state/lifecycle — the modern standard. Class: an ES6 class with `render()` and lifecycle methods — legacy, written only when maintaining old codebases (and still required for Error Boundaries).

**Likely follow-up:** *Any reason to learn classes?* — reading legacy code and error boundaries; new code is always functional.

---

### 24. Difference between stateless and stateful components?

**Answer:** Stateless (presentational) holds no internal state — it renders UI from props. Stateful (container) owns state via `useState`/`useReducer` and passes data down. Keep logic in containers, display in stateless components.

**Likely follow-up:** *Does stateless mean no functions?* — No; it means no internal state. Stateless components can take callbacks and render anything.

---

### 25. What are the class component lifecycle phases?

**Answer:** Mounting (`constructor` → `render` → `componentDidMount`), Updating (`shouldComponentUpdate` → `render` → `componentDidUpdate`), Unmounting (`componentWillUnmount`), plus `componentDidCatch` for errors.

**Likely follow-up:** *Hook equivalents?* — `useEffect` with `[]` (mount), deps array (update), cleanup return (unmount) — see Q26 in Batch 2.

---

### 28. How does the `children` prop work?

**Answer:** `props.children` automatically holds whatever is written between the component's tags — `<Wrapper><p>Hello</p></Wrapper>` puts `<p>` into children. It's the engine of layout/wrapper components and the composition pattern.

**Likely follow-up:** *Can it be multiple nodes?* — Yes; children is an array when there's more than one.

---

### 29. Purpose of `defaultProps`?

**Answer:** Provides a fallback when a prop isn't passed. In modern React, default parameter values (`function Comp({ name = "Guest" })`) are preferred — `defaultProps` is being deprecated for function components.

**Likely follow-up:** *How is this different from TypeScript's `name?: string`?* — optional type allows `undefined`; the default parameter supplies the actual fallback value.

---

### 30. What does PropTypes do?

**Answer:** A runtime type checker that warns in development when a prop gets the wrong type. TypeScript is the stronger alternative — compile-time checking, generics, refactors — and it's what this course uses.

**Likely follow-up:** *Why did teams drop PropTypes?* — TS catches the same mistakes at build time, before code ever runs.

---

### 34. What are React Hooks, and why were they introduced?

**Answer:** Functions that let functional components use state and lifecycle (React 16.8). They solved three class pains: reusing stateful logic (→ custom hooks), tangled lifecycle methods (→ colocated effects), and confusing `this`/boilerplate (→ plain functions).

**Likely follow-up:** *Give a reuse example.* — `useFetch` shared across components without HOCs or wrapper components.

---

### 35. How does `useState` work?

**Answer:** `useState(initial)` returns `[value, setter]`; calling the setter schedules a re-render. Updates are async and batched; when new state depends on old, use `setState(prev => ...)`. Never mutate — replace the object/array, because React compares references (`Object.is`).

**Likely follow-up:** *Why does `items.push(4)` not re-render?* — same reference = no change detected; `setItems([...items, 4])` creates a new one.

---

### 36. When should you use functional updates (`setState(prev => ...)` )?

**Answer:** When the next state derives from the previous — especially with multiple rapid updates or closures that captured a stale value. The functional form always receives the latest state.

**Likely follow-up:** *Where does this commonly bite?* — counters inside intervals/loops using `count + 1` from a stale closure instead of `prev => prev + 1`.

---

### 96. Composition vs Inheritance — which does React prefer?

**Answer:** Composition, explicitly. You combine behaviors through children and props (`<Card><Header /></Card>`) instead of class hierarchies — flexible, loosely coupled components.

**Likely follow-up:** *When does inheritance feel tempting?* — the "base component" urge; extract a shared component or a custom hook instead.

---

### 99. Why is immutability important in React?

**Answer:** React detects change by reference — if you mutate state in place, it never re-renders and devtools/time-travel history break. Create a new object/array to signal change (Redux Toolkit's Immer gives you safe mutable-looking syntax under the hood).

**Likely follow-up:** *Isn't copying expensive?* — shallow copies are cheap; correctness and debuggability win every time.

---

### 100. What happens when you change a `key` prop?

**Answer:** React treats it as a completely different component — the old one unmounts (state destroyed) and a fresh one mounts. That's intentional when you *want* a reset, e.g. `<Form key={step} />` to clear fields when the step changes.

**Likely follow-up:** *How do you reset a form without key?* — manual state reset, or key the form by its identity (the cleaner way).
