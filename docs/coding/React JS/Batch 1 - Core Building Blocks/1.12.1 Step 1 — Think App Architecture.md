# 1.12.1 — Step 1: Think: App Architecture

No code yet. Think this through first.

**Features:** User fills a form (name required, phone, optional email, category), clicks Add, contact appears in the list. Each contact shows name, phone, email (if provided), category badge, and a favorite star. Search box filters by name. Category filter buttons: All / Family / Work / Friend. Summary at the bottom: "X contacts" and a "Clear All" button. Each contact has a delete button.

**Component tree – visualize it:**

```
App
├── ContactForm     (controlled inputs + Add button, callback prop onAdd)
├── SearchBar       (controlled input, filters list)
├── FilterBar       (category filter buttons)
├── ContactList
│   └── ContactCard[]  (props + conditional render + favorite toggle + delete)
└── Footer          (count + clear button, composition with children)
```

**What state do we need?**
- `contacts: Contact[]` – array of all contacts
- `search: string` – search query
- `categoryFilter: CategoryFilter` – currently selected category filter

**Why separate components?** Keeps `App.tsx` small, improves readability, and each component does one thing (single responsibility). This is where composition (1.6) and props (1.5) pay off.
