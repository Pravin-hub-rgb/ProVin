
## MCQ

Q: What are the two main rules for a React component?
A. Capitalized name and returns JSX — the two essential rules
B. Lowercase name and returns a string — these are the rules
C. Number-prefixed name and returns an array — the standard approach
D. Underscore-prefixed name and returns a number — the convention
> A. A React component has two rules: (1) its name starts with a capital letter — `ProfileCard`, `Button`, `Header`. (2) the function returns JSX. If you break either rule, React won't recognize it as a component.

---

Q: Why must a component's name start with a capital letter?
A. So TypeScript can distinguish the component from an HTML tag
B. So React knows it's a custom component, not an HTML tag
C. Because lowercase function names are deprecated in modern JavaScript
D. So the component can only be defined at the module level, not inside
> B. A capital letter signals to React: "this is my custom component." `div` is treated as a regular HTML tag. `ProfileCard` is treated as a custom component and React renders it accordingly.

---

Q: What does the return type `: JSX.Element` signify for a component?
A. The component will only return HTML elements, nothing else
B. The component returns JSX, and anything else triggers an error
C. The component must always be class-based, not function-based
D. The component can only be written in TypeScript, not in plain JavaScript
> B. `: JSX.Element` tells TypeScript that the function returns JSX. If you accidentally return something like a string (`return "Hello"`), TypeScript will throw an error.

---

Q: Using `<ProfileCard />` — what is this correct syntax called?
A. Component instantiation — using a React component as a JSX tag
B. Component destruction — freeing a component from memory
C. Component inheritance — a component receives props from another
D. Component registration — registering a component in global scope
> A. Using a component with HTML-tag syntax — `<ProfileCard />` — is called **component instantiation**. It's different from a regular function call like `ProfileCard()`.

---

Q: What is the main difference between a component and a regular function?
A. Components can't define variables inside; regular functions can
B. A component can only be used once; regular functions can be called multiple times
C. React treats components specially — JSX tag syntax and automatic re-rendering
D. Components only work in JavaScript projects; regular functions only in TypeScript
> C. A component is technically just a function, but React treats it specially — it's invoked with JSX tag syntax (`<Greet />`) and React automatically re-renders it when state or props change.

---

Q: Regarding TypeScript return type annotations on components:
A. Always required — omitting causes a runtime error at component execution
B. Optional — TypeScript infers the `JSX.Element` type automatically
C. Only required for class components; function components allow omission
D. Only required in production builds; development allows omission
> B. TypeScript automatically infers that a component returns `JSX.Element`. The explicit annotation is optional. But when learning, writing it explicitly is a good habit — it makes you aware of what the function actually returns.

---

Q: What does "component reusability" mean in practice?
A. Component reusability — write a component once and use it multiple times
B. Component modularity — splitting a component into smaller modules
C. Component inheritance — a parent component passing props to a child
D. Component abstraction — hiding the internal complexity of a component
> A. Component reusability means you write a component once and use it multiple times. Using `<ProfileCard />` three times renders three cards without duplicating any code.

---

Q: When is it acceptable to have multiple components in a single file?
A. Never — each component requires its own file
B. Only in production code; development requires separate files
C. It's okay for small projects; large projects benefit from separate files
D. Only in TypeScript projects, not in plain JavaScript
> C. For small projects, having multiple components in one file is fine. In larger projects, separate files keep things organized and make imports/exports clearer. There's no strict rule — it depends on project size and team preference.

## ShortAnswer

Q: What is a React component? Explain the two main rules with examples. How do you use a component?

<details>
<summary>Sample Answer</summary>

**Answer:** A React component is a JavaScript function that returns JSX. There are two strict rules:

**Rule 1 — Capitalized name:** The function name must start with a capital letter.
```tsx
// ❌ Wrong — lowercase start
function profileCard() { return <div>...</div>; }

// ✅ Correct — capital letter
function ProfileCard() { return <div>...</div>; }
```

**Rule 2 — Returns JSX:** The function must return JSX that React renders on screen.

**Using a component:** Use a component like an HTML tag:
```tsx
<ProfileCard />
<ProfileCard></ProfileCard>
```

Why the capital letter? React uses it to distinguish: `div` is an HTML tag, `ProfileCard` is a custom component that React knows how to render.

</details>

Q: What are three main differences between a React component and a regular function? Compare them.

<details>
<summary>Sample Answer</summary>

**Answer:** Three main differences:

**1. How you call it:**
- Regular function: `greet("Vin")` — a standard function call
- Component: `<Greet name="Vin" />` — JSX tag syntax

**2. What it returns:**
- Regular function: can return anything — string, number, object, array
- Component: returns only JSX (what React renders on the screen)

**3. Naming convention:**
- Regular function: `greet` (lowercase)
- Component: `Greet` (capitalized)

**Bonus — re-rendering:**
- Regular function: you have to call it manually if you want to run it again
- Component: React automatically re-renders it whenever state or props change

**Analogy:** A component is a special function that React gives VIP treatment to — special calling syntax, automatic re-rendering, and lifecycle management.

</details>
