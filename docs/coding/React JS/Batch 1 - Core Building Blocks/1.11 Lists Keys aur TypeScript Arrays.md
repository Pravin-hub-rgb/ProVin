
## Abhi Tak Kya Hua

Pichle chapter mein conditional rendering seekha — toggle flag, filter, union types. Ek pattern notice kiya hoga: har baar list render karne ke liye `.map()` use kiya, aur har item mein `key={item.id}` likha. But why? Kya hoga agar key nahi likhen? Aur arrays ke saath aur kaunse operations roz karne padte hain? Yahi is chapter ka focus hai.

## Step 1 — .map() Ka Deep Explanation

Soch: Jab hum likhte hain `items.map(item => <div>{item.text}</div>)`, to React ko kya mil raha hai? Ek number? Ek string? Kuch aur?

**.map() ka actual kaam:**

Kyun hum isko use karte hain? Kyonki JSX mein directly `for` loop nahi likh sakte. JSX expressions ke andar sirf JavaScript expressions kaam karte hain, statements nahi. `.map()` ek expression hai jo return karta hai — naya array.

Kyun naya array? Kyonki React ko ek array of JSX elements chahiye. Har element ke liye ek `<div>`, ek `<li>`, kuch bhi. `.map()` har item ke liye function call karta hai, jo kuch bhi return kare woh collect karta hai, aur naya array de deta hai.

Let's verify:

```js
// standalone — Node.js mein bhi chala sakte ho
const numbers = [1, 2, 3];
const doubled = numbers.map((num) => num * 2);
console.log(doubled); // [2, 4, 6]
console.log(numbers); // [1, 2, 3] — original unchanged

const asStrings = numbers.map((num) => `Number: ${num}`);
console.log(asStrings); // ["Number: 1", "Number: 2", "Number: 3"]
```

Dekha? Original array change nahi hota. `.map()` hamesha naya array return karta hai. Yeh important hai — React mein state immutability ke liye yahi chahiye.

**TypeScript typing — automatic:**

Jab tum `items: Item[]` declare karte ho, to `.map()` ke callback parameter mein `item` ka type automatically `Item` infer ho jata hai. Explicit type likhna zaroori nahi:

```tsx
const items: Item[] = [
  { id: 1, text: "Learn React", flagged: false },
  { id: 2, text: "Build project", flagged: true },
];

return (
  <div>
    {items.map((item) => (
      // TypeScript knows item is Item
      <div key={item.id}>
        <span>{item.text}</span>
      </div>
    ))}
  </div>
);
```

## Step 2 — key Prop — Problem First

**Problem:** Neeche wala code run karo. Filter toggle karo. Dekho kya hota hai.

Soch: "Har baar `.map()` chal raha hai, React sab kuch re-render kar raha hai. Lekin kya woh har element ko DOM mein naya bana raha hai? Ya kuch optimize kar raha hai?"

Bina key ke:

```tsx
// ❌ Bina key — React confused
{items.map((item) => (
  <div>{item.text}</div>
))}
```

Kyun yeh problem hai? React ka Virtual DOM diffing (0.3 mein padha tha) elements ko index se compare karta hai jab key nahi hoti. Matlab:

```
Array: [A, B, C] → filter change → [A, C, D]

React ka diffing (bina key):
1. Position 0: A same hai — kuch mat karo
2. Position 1: B → C — DOM update karo (content change)
3. Position 2: C → D — DOM update karo (content change)
```

Do DOM updates. Lekin sach yeh hai ki sirf ek element change hua (D naya aaya), aur ek delete hua (B gaya). React ne wrong identity assume ki.

**Key se React ko identity milti hai:**

```
Array: [{id:1}, {id:2}, {id:3}] → [{id:1}, {id:3}, {id:4}]

React ka diffing (with key):
1. id:1 — same hai, kuch mat karo
2. id:3 — exist karta hai, move karo (DOM update nahi)
3. id:4 — naya hai, insert karo
4. id:2 — missing hai, delete karo
```

Sirf ek insert aur ek delete. Minimum DOM operations.

**Verify yourself:**

```js
// Yeh conceptual hai — actual DOM updates nahi dekh sakte
// Lekin React DevTools mein "Highlight Updates" feature se dekh sakte ho
// Bina key ke saare items highlight hote hain har baar
// Key ke saath sirf actual change hue items highlight hote hain
```

**Key kaise choose karein:**

```tsx
// ✅ Sahi — unique, stable ID
<div key={item.id}>

// ❌ Galat — array index (reordering par bugs)
<div key={index}>

// ❌ Galat — random number (har render naya, React confused)
<div key={Math.random()}>
```

**Key prop component ko nahi milti:**

```tsx
function ItemComponent({ id, text }: { id: number; text: string }) {
  return <div>{text}</div>;
}

// Key parent ke map mein lagti hai
{items.map((item) => (
  <ItemComponent key={item.id} id={item.id} text={item.text} />
))}
```

`key` React internal use ke liye reserved hai. `props.key` access karoge to `undefined` milega.

## Step 3 — Array State Operations — Problem First

Soch: "Items array mein se koi item delete karna hai. Ya naya add karna hai. Directly `items[2]` set kar sakte hain? Ya push kar sakte hain?"

**Kyun nahi?** React state directly mutate nahi karte. Kyunki React ko pata hona chahiye ki state change hui hai. Direct mutation se React ko pata nahi chalega aur re-render nahi hoga. Naya reference (naya array) dena padta hai.

**Add item:**

```tsx
// End mein add — spread operator se naya array
const handleAdd = (newItem: Item) => {
  setItems([...items, newItem]);
  console.log("Added:", newItem);
  console.log("New length:", items.length + 1);
};

// Start mein add
const handleAddFirst = (newItem: Item) => {
  setItems([newItem, ...items]);
};
```

`.push()` use nahi kar sakte kyunki woh existing array mutate karta hai. `[...items, newItem]` naya array create karta hai with all old items plus the new one.

**Remove item:**

```tsx
const handleDelete = (idToRemove: number) => {
  setItems(items.filter((item) => item.id !== idToRemove));
  console.log("Removed id:", idToRemove);
  console.log("Remaining:", items.filter((item) => item.id !== idToRemove).length);
};
```

`.filter()` naya array return karta hai jisme sirf woh items hain jo condition match karte hain. `id !== idToRemove` ka matlab — jiska id match kare, usko hata do.

**Update specific item:**

```tsx
const handleToggle = (idToUpdate: number) => {
  setItems(
    items.map((item) =>
      item.id === idToUpdate
        ? { ...item, flagged: !item.flagged }  // naya object (sirf updated ka)
        : item                                   // reference same (unchanged)
    )
  );
};
```

Yahan do cheezen ho rahi hain:
1. `.map()` naya array bana raha hai — so React knows state changed
2. `{ ...item, flagged: !item.flagged }` — naya object sirf us item ke liye jise update karna hai
3. Baaki items ka reference `item` hi hai — wahi purana object

**Optimization — naya object sirf updated item ka:**

```tsx
items.map((item) =>
  item.id === id
    ? { ...item, flagged: !item.flagged } // naya object, ek hi item ka
    : item                                 // reference same, 99% items
);
```

React sirf DOM mein wahi update karega jo actually change hua. Baaki items ka reference same hai to React unhe skip kar dega.

**Clear all:**

```tsx
const handleClear = () => {
  setItems([]);
  console.log("Items cleared. Length:", 0);
};
```

**Check if exists:**

```tsx
const exists = items.some((item) => item.text === newText);
console.log("Exists?", exists);
```

## Step 4 — TypeScript Array Typing Patterns

Soch: "Array types sirf `Item[]` nahi hote. Kabhi array ko readonly banana ho, kabhi fixed-length tuple chahiye. Kaise karein?"

**Basic array:**

```ts
const items: Item[] = [];
```

**Generic syntax — same cheez:**

```ts
const items: Array<Item> = [];
```

**Readonly array — modify nahi kar sakte:**

```ts
const readonlyItems: readonly Item[] = [];
// readonlyItems.push(newItem);   // ❌ Error
// readonlyItems[0] = item;      // ❌ Error
```

React mein yeh common pattern hai — array ko readonly mark karte hain to ensure karte hain ki accidentally mutate na ho.

**Tuple — fixed length, different types:**

```ts
const pair: [string, number] = ["React", 2024];
const [name, year] = pair;
console.log(name); // "React"
console.log(year); // 2024
```

Tuple tab use karo jab exact number of elements pata ho aur har position ka type different ho.

**Union array — multiple types:**

```ts
const mixed: (string | number)[] = ["React", 2024, "TypeScript"];
console.log(mixed); // ["React", 2024, "TypeScript"]
```

**React mein most common pattern:** `Item[]`. Baki patterns specific use cases ke liye.

## Step 5 — Union Types — Real Use Case

Soch: "FilterStatus mein humne type banaya `"all" | "flagged" | "unflagged"`. Iska actual benefit kya hai?"

**Concept:** Union type tab use karo jab koi value limited possible values mein se koi ek ho sakti hai. TypeScript ensure karega ki tum galat value assign na karo.

```ts
type FilterStatus = "all" | "flagged" | "unflagged";

function setFilter(status: FilterStatus) {
  console.log("Filter set to:", status);
}

setFilter("all");       // ✅
setFilter("flagged");   // ✅
setFilter("none");      // ❌ Error — "none" type mein nahi hai
```

TypeScript automatically autocomplete dikhayega. VS Code mein `"` type karte hi teen options dikhenge.

**Real use case — item status:**

```ts
export type ItemStatus = "draft" | "published" | "archived";

export interface Item {
  id: number;
  text: string;
  status: ItemStatus;
}
```

Ab `Item.status` sirf teen values mein se koi ek ho sakti hai:

```ts
const item: Item = { id: 1, text: "Hello", status: "draft" };
// item.status = "deleted";     // ❌ Error
// item.status = "published";   // ✅
```

## Summary

| Concept | Kya Hai |
|---------|---------|
| `.map()` | Array ko JSX array mein convert karta hai, original array change nahi hota |
| `key` prop | React ko element identity batata hai — diffing efficient banata hai |
| `key` choice | Unique aur stable ID use karo, index nahi |
| Add item | `setItems([...items, newItem])` — spread operator |
| Remove item | `setItems(items.filter(i => i.id !== id))` — filter |
| Update item | `setItems(items.map(i => i.id === id ? {...i, ...} : i))` — map |
| `readonly Item[]` | Immutable array — accidental mutation se bachata hai |
| Union types | Limited possible values, TypeScript enforce karta hai |
