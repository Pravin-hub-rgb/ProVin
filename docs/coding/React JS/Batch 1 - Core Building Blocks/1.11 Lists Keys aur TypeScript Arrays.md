In the last chapter, we learned conditional rendering — toggling flags, filtering with union types. ## Step 1 – Deep Dive: How `.map()` Actually Works

Think: When you write `items.map(item => <div>{item.text}</div>)`, what does React actually get? A number? A string? Something else?

**What `.map()` actually does:**

Why do we use it? Because JSX expressions can't contain `for` loops — only JavaScript expressions, not statements. `.map()` is an expression that returns a new array.

Why a new array? Because React needs an array of JSX elements. One `<div>`, one `<li>`, whatever. `.map()` calls the function for each item and collects the return values into a new array.

Let's verify:

```js
// You can run this in Node.js
const numbers = [1, 2, 3];
const doubled = numbers.map((num) => num * 2);
console.log(doubled); // [2, 4, 6]
console.log(numbers); // [1, 2, 3] — original unchanged

const asStrings = numbers.map((num) => `Number: ${num}`);
console.log(asStrings); // ["Number: 1", "Number: 2", "Number: 3"]
```

See? The original array isn't modified. `.map()` always returns a new array. This matters for React state immutability.

**TypeScript typing – automatic:**

When you declare `items: Item[]`, the callback parameter `item` automatically gets type `Item`. You don't need to write the type explicitly:

```tsx
const items: Item[] = [
  { id: 1, text: "Learn React", flagged: false },
  { id: 2, text: "Build project", flagged: true },
];

return (
  <div>
    {items.map((item) => (
      // TypeScript knows item is an Item
      <div key={item.id}>
        <span>{item.text}</span>
      </div>
    ))}
  </div>
);
```

## Step 2 – The `key` Prop: See the Problem First

**Problem:** Run this code without a key. Toggle the filter. See what happens.

Think: "Every render, `.map()` runs and React re-renders everything. But is it rebuilding every element in the DOM? Or is it optimizing somehow?"

Without a key:

```tsx
// ❌ Without a key – React is confused
{items.map((item) => (
  <div>{item.text}</div>
))}
```

Why is this a problem? React's Virtual DOM diffing (from 0.3) compares elements by position when there's no key. So:

```
Array: [A, B, C] → after filter change → [A, C, D]

React's diffing (without key):
1. Position 0: A is the same — do nothing
2. Position 1: B → C — update DOM (content changed)
3. Position 2: C → D – update DOM (content changed)
```

Two DOM updates. But the truth is only one element changed (D is new) and one was removed (B is gone). React assumed the wrong identity.

**With a key, React gets true identity:**

```
Array: [{id:1}, {id:2}, {id:3}] → [{id:1}, {id:3}, {id:4}]

React's diffing (with key):
1. id:1 — same, do nothing
2. id:3 — exists, move it (no DOM content update needed)
3. id:4 — new, insert it
4. id:2 — missing, delete it
```

Just one insert and one delete – minimum DOM operations.

**Verify yourself:**

```js
// This is conceptual — you can't see actual DOM updates directly
// But with React DevTools' "Highlight Updates" feature, you can see:
// Without a key — all items flash yellow on every render
// With a key — only the items that actually changed flash yellow
```

**How to choose a key:**

```tsx
// ✅ Correct – unique, stable ID
<div key={item.id}>

// ❌ Wrong – array index (bugs on reorder)
<div key={index}>

// ❌ Wrong – random number (new every render, React is confused)
<div key={Math.random()}>
```

**The key prop is not passed to the component:**

```tsx
function ItemComponent({ id, text }: { id: number; text: string }) {
  return <div>{text}</div>;
}

// The key goes in the parent's .map()
{items.map((item) => (
  <ItemComponent key={item.id} id={item.id} text={item.text} />
))}
```

The `key` is React's internal identity prop. If you try to access `props.key`, you get `undefined`.

## Step 3 – Array State Operations: See the Problem First

Think: "I want to delete an item from the array, or add a new one. Can I just do `items[2] = newItem`? Or use `items.push(...)`?"

**Why not?** React state shouldn't be mutated directly. If you mutate the array, React doesn't know the state changed. You need to pass a new reference (a new array) so React knows to re-render.

**Add an item:**

```tsx
// Add to end – spread creates a new array
const handleAdd = (newItem: Item) => {
  setItems([...items, newItem]);
  console.log("Added:", newItem);
  console.log("New length:", items.length + 1);
};

// Add to beginning
const handleAddFirst = (newItem: Item) => {
  setItems([newItem, ...items]);
};
```

You can't use `.push()` because it mutates the existing array. `[...items, newItem]` creates a brand new array with all the old items plus the new one.

**Remove an item:**

```tsx
const handleDelete = (idToRemove: number) => {
  setItems(items.filter((item) => item.id !== idToRemove));
  console.log("Removed id:", idToRemove);
  console.log("Remaining:", items.filter((item) => item.id !== idToRemove).length);
};
```

`.filter()` returns a new array with only the items that pass the condition. `item.id !== idToRemove` means "keep everything except the one being deleted."

**Update a specific item:**

```tsx
const handleToggle = (idToUpdate: number) => {
  setItems(
    items.map((item) =>
      item.id === idToUpdate
        ? { ...item, flagged: !item.flagged }  // new object (only for updated item)
        : item                                   // same reference (unchanged)
    )
  );
};
```

Two things happening here:
1. `.map()` creates a new array — React knows the state changed
2. `{ ...item, flagged: !item.flagged }` – creates a new object only for the item being updated
3. Unchanged items keep the same reference (`item`)

**Optimization – only the updated item gets a new object:**

```tsx
items.map((item) =>
  item.id === id
    ? { ...item, flagged: !item.flagged } // new object, just one item
    : item                                 // same reference, 99% of items
);
```

React only updates the DOM for the items that actually changed. Since the other items have the same reference, React skips them.

**Clear all:**

```tsx
const handleClear = () => {
  setItems([]);
  console.log("Items cleared. Length:", 0);
};
```

**Check if an item exists:**

```tsx
const exists = items.some((item) => item.text === newText);
console.log("Exists?", exists);
```

## Step 4 – TypeScript Array Typing Patterns

Think: "Arrays aren't just `Item[]`. Sometimes I need a readonly array. Sometimes I need a fixed-length tuple. How do I do that?"

**Basic array:**

```ts
const items: Item[] = [];
```

**Generic syntax – same thing, different way:**

```ts
const items: Array<Item> = [];
```

**Readonly array – can't be modified:**

```ts
const readonlyItems: readonly Item[] = [];
// readonlyItems.push(newItem);   // ❌ Error
// readonlyItems[0] = item;       // ❌ Error
```

This pattern is common in React – marking arrays as readonly prevents accidental mutations.

**Tuple – fixed length with different types:**

```ts
const pair: [string, number] = ["React", 2024];
const [name, year] = pair;
console.log(name); // "React"
console.log(year); // 2024
```

Use tuples when you know the exact number of elements and their types.

**Union array – multiple types in one array:**

```ts
const mixed: (string | number)[] = ["React", 2024, "TypeScript"];
console.log(mixed); // ["React", 2024, "TypeScript"]
```

**Most common pattern in React:** `Item[]`. The other patterns are for specific use cases.

## Step 5 – Union Types: Real Use Case

Think: "We defined `FilterStatus` as `"all" | "flagged" | "unflagged"`. What's the real benefit of that?"

**Concept:** Use a union type when a value can only be one of a limited set of values. TypeScript makes sure you don't accidentally assign something invalid.

```ts
type FilterStatus = "all" | "flagged" | "unflagged";

function setFilter(status: FilterStatus) {
  console.log("Filter set to:", status);
}

setFilter("all");       // ✅
setFilter("flagged");   // ✅
setFilter("none");      // ❌ Error – "none" isn't in the type
```

TypeScript shows autocomplete. In VS Code, when you type `"`, it shows the three valid options.

**Real-world example – item status:**

```ts
export type ItemStatus = "draft" | "published" | "archived";

export interface Item {
  id: number;
  text: string;
  status: ItemStatus;
}
```

Now `item.status` can only be one of `"draft"`, `"published"`, `"archived"`:

```ts
const item: Item = { id: 1, text: "Hello", status: "draft" };
// item.status = "deleted";     // ❌ Error
// item.status = "published";   // ✅
```

## Summary

| Concept | What it is |
|---------|------------|
| `.map()` | Converts an array into a JSX array. The original array is not modified. |
| `key` prop | Tells React an element's identity – makes diffing efficient |
| `key` choice | Use unique, stable IDs – not array indices |
| Add item | `setItems([...items, newItem])` – spread operator |
| Remove item | `setItems(items.filter(i => i.id !== id))` – filter |
| Update item | `setItems(items.map(i => i.id === id ? {...i, ...} : i))` – map |
| `readonly Item[]` | Immutable array – protects against accidental mutations |
| Union types | A limited set of possible values – TypeScript enforces |
