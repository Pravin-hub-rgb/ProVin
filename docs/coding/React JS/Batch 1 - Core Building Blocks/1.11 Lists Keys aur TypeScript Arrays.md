## Step 1 — .map() Ka Deep Explanation

Soch: "`.map()` har baar list render karne ke liye use hota hai. Lekin yeh kaise kaam karta hai?"

**Concept:** `.map()` JavaScript ka array method hai jo:
1. Har element par ek function call karta hai
2. Function ka return value collect karta hai
3. Naya array return karta hai (original array change nahi hota)

```ts
// Simple example — numbers ko strings mein convert karo
const numbers = [1, 2, 3];
const doubled = numbers.map((num) => num * 2);
// doubled = [2, 4, 6]

const asStrings = numbers.map((num) => `Number: ${num}`);
// asStrings = ["Number: 1", "Number: 2", "Number: 3"]
```

React mein `.map()` ka use:

```tsx
const items: Item[] = [
  { id: 1, text: "Learn React", flagged: false },
  { id: 2, text: "Build project", flagged: true },
];

return (
  <div>
    {items.map((item) => (
      <div key={item.id}>
        <span>{item.text}</span>
      </div>
    ))}
  </div>
);
```

Yahan `.map()` har item ke liye ek `<div>` JSX element return karta hai. React ko ek array of JSX elements milta hai, aur woh unhe DOM mein render karta hai.

**TypeScript typing:**

```tsx
{items.map((item: Item) => (
  // item ka type automatically infer hota hai array type se
))
}

TypeScript automatically infer karta hai ki `item` ka type `Item` hai — kyunki `items: Item[]` declare kiya hai. Explicit type likhna optional hai.

## Step 2 — key Prop — Kya Hai Aur Kyun Zaroori Hai

Soch: "Har list item mein `key={item.id}` likhna padta hai. Agar key nahi likhoon toh kya hota hai?"

**Concept — Warning:** Agar key nahi doge, React console mein warning dega:

```
Warning: Each child in a list should have a unique "key" prop.
```

React kaam karega, lekin inefficient tarike se.

**Kyun key zaroori hai?** (0.3 Reconciliation se connect karo)

Yaad karo 0.3 mein padha tha — React jab state change hoti hai, purana Virtual DOM tree aur naya tree compare karta hai (diffing). Jab list render hoti hai, React ko har element ki **identity** pata honi chahiye — kaunsa element change hua, kaunsa delete hua, kaunsa naya add hua.

**Without key:**

```
Array: [A, B, C] → [A, C, D]

React sochta hai:
1. A same hai — kuch mat karo
2. B → C: content change hua, DOM update karo
3. C → D: content change hua, DOM update karo
```

React ne saare elements compare kiye aur do DOM updates kiye — inefficient.

**With key:**

```
Array: [{id:1}, {id:2}, {id:3}] → [{id:1}, {id:3}, {id:4}]

React sochta hai:
1. id:1 same hai — kuch mat karo
2. id:3 exist karta hai — move karo, update nahi
3. id:4 naya hai — insert karo
4. id:2 missing hai — delete karo
```

Key se React ko pata chal gaya ki kaunsa element change nahi hua, kaunsa move hua, kaunsa naya aaya. DOM operations minimum ho gaye.

**Key kaise choose karein:**

```tsx
// ✅ Sahi — unique, stable ID
<div key={item.id}>

// ❌ Galat — array index (reordering par bugs aayenge)
<div key={index}>

// ❌ Galat — random number (har render par naya, React confused)
<div key={Math.random()}>
```

**Important — key prop component ko nahi milti:**

```tsx
function ItemComponent({ id, text }: { id: number; text: string }) {
  return <div>{text}</div>;
}

// Key yahan parent ke map mein lagti hai, component ke andar nahi
{items.map((item) => (
  <ItemComponent key={item.id} id={item.id} text={item.text} />
))}
```

Agar `ItemComponent` ke andar `props.key` access karne ki koshish karoge, toh `undefined` milega. `key` React internal use ke liye reserved hai.

## Step 3 — TypeScript Arrays — Common Patterns

Soch: "Arrays ke saath kaun-kaun se operations roz karne padte hain React mein?"

**Add item:**

```tsx
// End mein add
setItems([...items, newItem]);

// Start mein add
setItems([newItem, ...items]);
```

**Remove item:**

```tsx
// Filter by id
setItems(items.filter((item) => item.id !== idToRemove));
```

**Update item:**

```tsx
// Map with condition — specific item update karo, baaki same rakho
setItems(
  items.map((item) =>
    item.id === idToUpdate
      ? { ...item, flagged: !item.flagged }
      : item
  )
);
```

**Clear all:**

```tsx
setItems([]);
```

**Check if exists:**

```tsx
const exists = items.some((item) => item.text === newText);
```

## Step 4 — TypeScript Arrays — Typing Patterns

Soch: "Array types sirf `Item[]` nahi hote. Aur bhi patterns hain."

```tsx
// Basic array
const items: Item[] = [];

// Generic syntax (same hi hai)
const items: Array<Item> = [];

// Readonly array — modify nahi kar sakte
const readonlyItems: readonly Item[] = [];
// readonlyItems.push(newItem); ❌ Error

// Tuple — fixed length, different types
const pair: [string, number] = ["React", 2024];
const [name, year] = pair; // destructuring works perfectly

// Union array — multiple types allowed
const mixed: (string | number)[] = ["React", 2024, "TypeScript"];
```

**React mein most common pattern:** `Item[]` ya `Array<Item>`. Baaki patterns specific use cases ke liye.

## Step 5 — Array State Optimization

Soch: "Har toggle par poora array map hota hai. Kya yeh inefficient nahi hai?"

**Concept:** React ki diffing efficient hai. `.map()` naya array reference create karta hai, lekin objects ko spread karta hai — purane objects copy nahi hote, reference share hote hain.

```tsx
// Yeh naya array create karta hai
items.map((item) =>
  item.id === id
    ? { ...item, flagged: !item.flagged } // naya object (sirf updated ka)
    : item // reference same (unchanged items)
);
```

Sirf updated item ka naya object bana. Baaki 99% items ka reference wahi purana hai. React sirf DOM mein wahi update karega jo actually change hua.

## Step 6 — TypeScript Union Types Deep Dive

Soch: "FilterStatus union type hai — `"all" | "flagged" | "unflagged"`. Iska actual use kya hai?"

**Concept:** Union type tab use karo jab koi value limited possible values mein se koi ek ho sakti hai.

```tsx
type FilterStatus = "all" | "flagged" | "unflagged";

function setFilter(status: FilterStatus) {
  // sirf teen values allowed
}

setFilter("all");       // ✅
setFilter("flagged");   // ✅
setFilter("none");      // ❌ Error — "none" FilterStatus type mein nahi hai
```

TypeScript automatically autocomplete bhi dikhayega — VS Code mein `"` type karte hi teen options dikhenge.

**Real use case — item status:**

```ts
export type ItemStatus = "draft" | "published" | "archived";

export interface Item {
  id: number;
  text: string;
  status: ItemStatus;
}
```

Ab `Item.status` sirf teen values mein se koi ek ho sakti hai. Koi random string assign nahi kar sakte:

```ts
item.status = "deleted";   // ❌ Error
item.status = "published"; // ✅
```

## Summary

- `.map()` — array ko JSX array mein convert karta hai, har element ke liye ek JSX element
- `key` prop — React ko element identity batata hai, diffing efficient banata hai
- `key` unique aur stable hona chahiye (ID use karo, index nahi)
- Array state updates: spread `[...]` for add, `.filter()` for delete, `.map()` for update
- `readonly Item[]` — immutable array type
- Union types — limited possible values, TypeScript enforce karta hai
- `Array<T>` aur `T[]` — same cheez, different syntax
