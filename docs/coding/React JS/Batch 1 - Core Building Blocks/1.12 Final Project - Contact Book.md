## Step 1 — Think: App Architecture

No code yet. Think this through first.

**Features:** User fills a form (name required, phone, optional email, category), clicks Add, contact appears in the list. Each contact shows name, phone, email (if provided), category badge, and a favorite star. Search box filters by name. Category filter buttons: All / Family / Work / Friend. Summary at the bottom: "X contacts" and a "Clear All" button. Each contact has a delete button.

**Component tree – visualize it:**

```
App
├── ContactForm     (controlled inputs + Add button, callback prop onAdd)
├── SearchBar       (controlled input, filters list)
├── FilterBar       (category filter buttons)
├── ContactList
│   └── ContactCard[]  (props + conditional render + favorite toggle + delete)
└── Footer          (count + clear button, composition with children)
```

**What state do we need?**
- `contacts: Contact[]` – array of all contacts
- `search: string` – search query
- `categoryFilter: CategoryFilter` – currently selected category filter

**Why separate components?** Keeps `App.tsx` small, improves readability, and each component does one thing (single responsibility). This is where composition (1.6) and props (1.5) pay off.

Now let's write code — one piece at a time.

## Step 2 — Foundation: Types + State

First, define the types. What does a contact object look like? An id, name, phone, optional email, category, and a favorite flag. And a union type for the category filter.

**Why types first?** TypeScript needs to know the shape of the data. Everything else depends on it.

Create a `src/types.ts` file:

```ts
// src/types.ts
export type Category = "family" | "work" | "friend";

export interface Contact {
  id: number;
  name: string;
  phone: string;
  email?: string;        // optional — not every contact has an email
  category: Category;
  favorite: boolean;
}

export type CategoryFilter = "all" | Category;
```

Notice `email?: string` — the `?` makes it optional (from 1.5.3). And `CategoryFilter` reuses `Category` via union (`"all" | Category`).

**Now add state in App.tsx – one piece at a time:**

```tsx
// src/App.tsx
import { useState } from "react";
import type { Contact } from "./types";

function App() {
  const [contacts, setContacts] = useState<Contact[]>([]);

  console.log("📋 App mounted. Contacts count:", contacts.length);
  console.log("📋 Contacts array:", contacts);

  return <div>Contact Book</div>;
}

export default App;
```

**Console check** – you'll see `[]` and `length: 0`. No contacts yet. The state type is `Contact[]` — TypeScript enforces that the array only holds `Contact` objects.

## Step 3 — Add Contact: Inline Build

Now we add the logic to add a contact – first directly in App.tsx, extract into a component later.

**Think:** User types name, phone, optional email, picks category, clicks Add. Need to track what the user types (controlled inputs), and create a new contact when Add is clicked.

**`handleAdd` function:**

```tsx
// src/App.tsx
const handleAdd = (name: string, phone: string, email: string, category: Category) => {
  const newContact: Contact = {
    id: Date.now(),
    name,
    phone,
    email: email.trim() === "" ? undefined : email.trim(),
    category,
    favorite: false,
  };
  setContacts([...contacts, newContact]);
  console.log("✅ Contact added:", newContact);
  console.log("📋 New contacts:", [...contacts, newContact]);
};
```

`Date.now()` – a simple way to generate a unique ID. Milliseconds since 1970 — almost guaranteed unique. `email` is set to `undefined` when empty (so the optional field stays absent, not an empty string).

**Add the controlled inputs + button JSX with `useState<string>`:**

```tsx
// src/App.tsx
const [name, setName] = useState("");
const [phone, setPhone] = useState("");
const [email, setEmail] = useState("");
const [category, setCategory] = useState<Category>("friend");

const handleNameChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  setName(e.target.value);
};

const handlePhoneChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  setPhone(e.target.value);
};

const handleEmailChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  setEmail(e.target.value);
};

const handleCategoryChange = (e: React.ChangeEvent<HTMLSelectElement>) => {
  setCategory(e.target.value as Category);
};

const handleAddClick = () => {
  if (name.trim() === "" || phone.trim() === "") {
    console.log("⚠️ Name and phone are required — ignoring");
    return;
  }
  handleAdd(name.trim(), phone.trim(), email, category);
  setName("");
  setPhone("");
  setEmail("");
  setCategory("friend");
};
```

**JSX:**

```tsx
// src/App.tsx
<div>
  <input value={name} onChange={handleNameChange} placeholder="Name (required)" />
  <input value={phone} onChange={handlePhoneChange} placeholder="Phone (required)" />
  <input value={email} onChange={handleEmailChange} placeholder="Email (optional)" />
  <select value={category} onChange={handleCategoryChange}>
    <option value="family">Family</option>
    <option value="work">Work</option>
    <option value="friend">Friend</option>
  </select>
  <button onClick={handleAddClick}>Add Contact</button>
</div>
```

**`as Category`** – the select's value is `string`, but state expects `Category`. We assert it's a `Category` (we know the options are valid). This is a type assertion.

**Console check** – add a contact, see it logged. Type in inputs, watch them update. Empty name/phone → ignored with a warning.

## Step 4 — Render the List

**Think:** Contacts are stored. Now display them. `.map()` converts the array into JSX. Each contact needs a unique `key` (use `id`). Conditional rendering: show email only if present (`email && ...`).

**The `.map()` pattern:**

```tsx
// src/App.tsx
{contacts.map((contact) => (
  <div key={contact.id}>
    <strong>{contact.name}</strong>
    <span> — {contact.phone}</span>
    {contact.email && <span> ({contact.email})</span>}
    <span> [{contact.category}]</span>
    <button>Delete</button>
  </div>
))}
```

`{contact.email && <span>...</span>}` – `&&` conditional rendering (from 1.10). If `email` is `undefined`, nothing renders.

**Empty state:**

```tsx
// src/App.tsx
{contacts.length === 0 ? (
  <p>No contacts yet. Add one above!</p>
) : (
  contacts.map((contact) => (
    <div key={contact.id}>
      <strong>{contact.name}</strong>
      <span> — {contact.phone}</span>
      {contact.email && <span> ({contact.email})</span>}
      <span> [{contact.category}]</span>
      <button onClick={() => handleDelete(contact.id)}>Delete</button>
    </div>
  ))
)}
```

**`handleDelete`:**

```tsx
// src/App.tsx
const handleDelete = (id: number) => {
  setContacts(contacts.filter((contact) => contact.id !== id));
  console.log("🗑️ Deleted contact:", id);
};
```

**Console check** – add 2 contacts, see them render. Delete one, see it disappear. Empty state shows when none left.

## Step 5 — Favorite Toggle (`.map()` with Condition)

**Think:** Each contact should be markable as a favorite (star). Clicking the star flips `favorite: true/false`. Direct mutation won't work (reference issue from 1.9/1.10). Use `.map()` with a condition.

**`handleToggleFavorite`:**

```tsx
// src/App.tsx
const handleToggleFavorite = (id: number) => {
  setContacts(
    contacts.map((contact) => {
      if (contact.id === id) {
        return { ...contact, favorite: !contact.favorite };
      }
      return contact;
    })
  );
};
```

`...contact` copies all properties, then overrides `favorite`. Other contacts keep the same reference (React skips them).

**Render the star:**

```tsx
// src/App.tsx
<button onClick={() => handleToggleFavorite(contact.id)}>
  {contact.favorite ? "★" : "☆"}
</button>
```

Ternary (from 1.10): favorite → filled star, not → outline.

**Console check** – toggle a favorite, see `favorite` flip in the console. Star updates on screen.

## Step 6 — Search + Category Filter

**Think:** User wants to find contacts by name and filter by category. Two filters combine: search (text match) and category (exact match). Both are state.

**State additions:**

```tsx
// src/App.tsx
const [search, setSearch] = useState("");
const [categoryFilter, setCategoryFilter] = useState<CategoryFilter>("all");
```

**Filtered contacts:**

```tsx
// src/App.tsx
const filteredContacts = contacts.filter((contact) => {
  const matchesSearch = contact.name.toLowerCase().includes(search.toLowerCase());
  const matchesCategory = categoryFilter === "all" || contact.category === categoryFilter;
  return matchesSearch && matchesCategory;
});
```

`.includes()` – string method: checks if search text is contained in the name. `.toLowerCase()` makes it case-insensitive.

**Search input (controlled):**

```tsx
// src/App.tsx
<input
  value={search}
  onChange={(e) => setSearch(e.target.value)}
  placeholder="Search by name..."
/>
```

**Category filter buttons:**

```tsx
// src/App.tsx
<div>
  {(["all", "family", "work", "friend"] as CategoryFilter[]).map((cat) => (
    <button
      key={cat}
      onClick={() => setCategoryFilter(cat)}
      style={{ fontWeight: categoryFilter === cat ? "bold" : "normal" }}
    >
      {cat.charAt(0).toUpperCase() + cat.slice(1)}
    </button>

</div>
```

Union type + conditional styling (from 1.10). `cat.charAt(0).toUpperCase() + cat.slice(1)` capitalizes the first letter ("all" → "All").

**Render `filteredContacts` instead of `contacts`:**

```tsx

{filteredContacts.length === 0 ? (
```

**Think:** App.tsx is getting big. Extract into components. This is where 1.4 (separate files), 1.5 (props), 1.6 (composition/children) pay off. Each component gets its own file.

**Component breakdown:**

### `src/types.ts` (already exists)

### `src/ContactForm.tsx`

```tsx
// src/ContactForm.tsx
import { useState } from "react";
import type { Category } from "./types";

interface ContactFormProps {
  onAdd: (name: string, phone: string, email: string, category: Category) => void;
}

export default function ContactForm({ onAdd }: ContactFormProps) {
// src/App.tsx
const [name, setName] = useState("");
  const [phone, setPhone] = useState("");
  const [email, setEmail] = useState("");
  const [category, setCategory] = useState<Category>("friend");

  const handleSubmit = () => {
    if (name.trim() === "" || phone.trim() === "") return;
    onAdd(name.trim(), phone.trim(), email, category);
    setName("");
    setPhone("");
    setEmail("");
    setCategory("friend");
  };

  return (
    <div>
      <input value={name} onChange={(e) => setName(e.target.value)} placeholder="Name (required)" />
      <input value={phone} onChange={(e) => setPhone(e.target.value)} placeholder="Phone (required)" />
      <input value={email} onChange={(e) => setEmail(e.target.value)} placeholder="Email (optional)" />
      <select value={category} onChange={(e) => setCategory(e.target.value as Category)}>
        <option value="family">Family</option>
        <option value="work">Work</option>
        <option value="friend">Friend</option>
      </select>
      <button onClick={handleSubmit}>Add Contact</button>
    </div>
  );
}
```

**Callback prop** (`onAdd`) – the child collects input, the parent owns the state. The child calls `onAdd(...)` and the parent's handler runs. This is the 1.5.4 callback prop pattern.

### `src/ContactList.tsx`

```tsx
// src/ContactList.tsx
import type { Contact } from "./types";
import ContactCard from "./ContactCard";

interface ContactListProps {
  contacts: Contact[];
  onToggleFavorite: (id: number) => void;
  onDelete: (id: number) => void;
}

export default function ContactList({ contacts, onToggleFavorite, onDelete }: ContactListProps) {
  if (contacts.length === 0) {
    return <p>No contacts found.</p>;

          onDelete={onDelete}
```

### `src/App.tsx` (final, slim)

```tsx
// src/App.tsx
import { useState } from "react";
import type { Contact, Category, CategoryFilter } from "./types";
import ContactForm from "./ContactForm";
import SearchBar from "./SearchBar";
import FilterBar from "./FilterBar";
import ContactList from "./ContactList";
import Footer from "./Footer";

export default function App() {
  const [contacts, setContacts] = useState<Contact[]>([]);
// src/App.tsx
const [search, setSearch] = useState("");
  const [categoryFilter, setCategoryFilter] = useState<CategoryFilter>("all");

// src/App.tsx
const handleAdd = (name: string, phone: string, email: string, category: Category) => {
    const newContact: Contact = {
      id: Date.now(),
      name,
      phone,
      email: email.trim() === "" ? undefined : email.trim(),
      category,
      favorite: false,
    };
    setContacts([...contacts, newContact]);
  };

// src/App.tsx
const handleDelete = (id: number) => {
    setContacts(contacts.filter((c) => c.id !== id));
  };

// src/App.tsx
const handleToggleFavorite = (id: number) => {
    setContacts(
      contacts.map((c) => (c.id === id ? { ...c, favorite: !c.favorite } : c))
    );
  };

  const handleClearAll = () => {
    setContacts([]);
  };

// src/App.tsx
const filteredContacts = contacts.filter((contact) => {
    const matchesSearch = contact.name.toLowerCase().includes(search.toLowerCase());
    const matchesCategory = categoryFilter === "all" || contact.category === categoryFilter;
    return matchesSearch && matchesCategory;
  });

  return (
    <div style={{ maxWidth: "600px", margin: "0 auto", padding: "1rem" }}>
      <h1>Contact Book</h1>

      <ContactForm onAdd={handleAdd} />

      <SearchBar value={search} onChange={setSearch} />

      <FilterBar current={categoryFilter} onChange={setCategoryFilter} />

      <ContactList
        contacts={filteredContacts}
        onToggleFavorite={handleToggleFavorite}
        onDelete={handleDelete}
      />

      <Footer>
        <span>{contacts.length} contact{contacts.length !== 1 ? "s" : ""}</span>
        {contacts.length > 0 && (
          <button onClick={handleClearAll} style={{ marginLeft: "1rem" }}>
            Clear All
          </button>
        )}
      </Footer>
    </div>
  );
}
```

**Console check** – add contacts, search, filter by category, toggle favorite, delete. Everything works. App.tsx is now ~40 lines — all logic delegated to components via props.

## Common Mistakes (Project-Specific)

- **Forgetting `key` on mapped components** – React warns and diffing breaks. Always `key={contact.id}`.
- **Mutating state directly** (`contacts.push(...)`) – no re-render. Use spread/`.filter`/`.map`.
- **Passing state setters instead of handlers** – pass `handleDelete` (a function), not `setContacts`. Keeps components decoupled.
- **Optional prop access without guard** – `contact.email.toUpperCase()` crashes if undefined. Use `{contact.email && ...}` or optional chaining.
- **`as Category` abuse** – only assert when you're certain the value is valid (select options). Don't sprinkle `as` everywhere.
- **Filtering without `.toLowerCase()`** – search becomes case-sensitive. Normalize both sides.
- **Empty state check on `filteredContacts` vs `contacts`** – show "No contacts found" when filtered list is empty (could be due to search), but "No contacts yet" when the whole list is empty. Subtle UX difference.

## In Your Own Words

1. Why did we split into multiple components instead of keeping everything in `App.tsx`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Single responsibility — each component does one thing (form collects input, card displays one contact, list renders the array). App.tsx stays small and readable, only owning state. Components become reusable and testable. Props define the contract between them. This is composition (1.6) + props (1.5) in practice.

</details>

2. Why does `ContactForm` keep its own input state instead of lifting it to `App`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The input state is temporary (only needed while typing). Lifting it to App would bloat App with form details that don't matter to the rest of the app. The form collects input, then calls `onAdd(...)` to hand the final data to App. This is the "state closest to where it's used" principle — App owns the contacts, the form owns the typing.

</details>

3. How does search filtering differ from the category filter in implementation?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Search: text match — `contact.name.toLowerCase().includes(search.toLowerCase())`. Partial, case-insensitive, substring. Category: exact match — `contact.category === categoryFilter` (or "all" keeps everything). Search uses `.includes()` on strings; category uses `===` on a union type. Both are `.filter()` predicates combined with `&&`.

</details>

4. Why is `email?: string` (optional) better than `email: string` with empty string default?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Optional means "may not exist" — `undefined` represents absence. An empty string `""` is a value, so you'd need extra checks like `email !== ""`. With `email?`, `{contact.email && <div>...</div>}` cleanly skips rendering when absent. The data model reflects reality: not every contact has an email.

</details>

5. What would break if you removed `key={contact.id}` from the `.map()` in `ContactList`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** React falls back to index-based diffing. On delete/reorder/filter, React reuses the wrong DOM nodes — inputs lose focus, animations glitch, and in worse cases the wrong contact's data shows. With `key={contact.id}`, React tracks identity correctly and does minimal DOM updates (from 1.11).

</details>
