
## MCQ

Q: What problem occurs when you manage state with `let count = 0`?
A. `let` variables aren't accessible inside React components — scope issue
B. The variable resets on re-render and React doesn't know it changed
C. `let` only works in class components; function components require `const`
D. `let` only stores strings; numbers aren't allowed
> B. `let count = 0` is a local variable — it resets to `0` on every re-render. React doesn't know it changed, so the screen doesn't update. That's why `useState` is needed — it tells React to track and re-render on changes.

Q: What is the correct syntax for the `useState` hook?
A. `const state = useState(0)` — state is stored in a single variable
B. `const [count, setCount] = useState(0)` — array destructuring for value and setter
C. `useState(0, count, setCount)` — three arguments to `useState`
D. `this.useState(0)` — class component syntax for hooks
> B. `useState` returns an array: `[currentValue, setterFunction]`. Use array destructuring to pull both out. The convention is `[value, setValue]` — `count`/`setCount`, `name`/`setName`.

Q: What happens when you call `setCount(count + 1)`?
A. The DOM updates immediately without re-rendering — just the text changes
B. The new value is stored and React re-renders the component, updating the screen
C. React creates a brand new component instance and removes the old one from memory
D. React sends a new HTTP request to fetch the updated value
> B. `setCount(count + 1)` stores the new value and triggers a re-render. When `useState` runs again, React remembers the new value. The screen updates to reflect it.

Q: How does TypeScript infer the type of `useState(0)`?
A. TypeScript infers `number` from the initial value `0` — no explicit type needed
B. TypeScript always infers `any` — you must always specify the type explicitly
C. TypeScript infers `string` from `useState(0)` — because 0 can be a string
D. TypeScript doesn't work with hooks — you always need `<Type>` syntax
> A. TypeScript infers from the initial value. `useState(0)` → `number`. `useState("")` → `string`. `useState(false)` → `boolean`. Only specify a type explicitly when the initial value isn't enough (like empty arrays).

Q: What happens if you write `onClick={setCount(count + 1)}`?
A. The count increments on button click — this is the correct way to write onClick
B. The function runs immediately during render, not on click
C. Nothing happens — TypeScript throws a syntax error
D. The button gets disabled because `setCount` returns void
> B. `setCount(count + 1)` runs immediately during render — not on click. You must pass a function reference: `onClick={() => setCount(count + 1)}` or `onClick={increment}`. React needs a function, not a call result.

Q: What is a controlled input?
A. The input value comes from the HTML and React reads it via onChange
B. The input value comes from React state (`value`) and updates state on `onChange`
C. The input is uncontrolled — React only sets the initial value
D. The input value comes from a ref variable, not state
> B. A controlled input uses `value={state}` (React state is the source of truth) and `onChange` updates the state. Flow: React state → HTML input → user types → onChange → state update → React re-renders → input updates.

Q: Why use a separate `inputValue` state instead of setting `count` directly from the input?
A. A component can only have one `useState` call — not multiple
B. `event.target.value` is always a string — count is a number, causing type mismatch and bugs
C. Separate states make React faster because count state is skipped
D. More states always means shorter code — one is better than two
> B. `event.target.value` is always a string — even with `type="number"`. `count` is inferred as `number`. Setting `setCount(event.target.value)` makes count a string, so `count + 1` becomes string concatenation ("5" + 1 = "51"). Two states let you validate before setting.

Q: What does `void` mean in `onSubmit: (name: string) => void`?
A. The function will return some value — void means the return type is number
B. The function just does work — it doesn't return a value back to the parent
C. The function is asynchronous — void means async operation
D. The function will throw an error — void means error handling
> B. `void` means the function doesn't return a value — it just does work. The child calls `onSubmit(name)`, the parent's function runs, but no value is sent back. It's a "fire and forget" callback.

Q: Why call `setName("")` after form submission?
A. The whole component resets to its initial state
B. To clear the input — the next name can be typed without manually clearing
C. To free memory — unused state is removed from React
D. To notify the parent component — empty string is a signal
> B. `setName("")` clears the input. Since it's a controlled input (`value={name}`), setting `name` to an empty string clears the input on re-render. The user can immediately type the next name without clearing manually.

## TrueFalse

Q: `useState` returns two values — the current value and a setter function that updates state and triggers a re-render.
- True
- False
> True. `useState` returns an array `[currentValue, setterFunction]`. The setter stores the new value and re-renders the component so the screen updates.

---

Q: Hooks can be called inside `if` statements and loops — there's no restriction.
- True
- False
> False. Hooks must be called at the top level of a component. React tracks hooks by call order, and conditional calls would change the order between renders — confusing React's internal state management.

---

Q: `event.target.value` always returns a string — even when the input has `type="number"`.
- True
- False
> True. HTML input `value` is always a string. `type="number"` only changes the browser's validation and keyboard — `event.target.value` is still a string. You need `parseInt` or `Number()` to convert it.

---

Q: In a controlled input, the HTML input is the source of truth — React reads from it.
- True
- False
> False. In a controlled input, React state is the source of truth. `value={name}` means the input's value comes from React state, not the other way around. User types → onChange → state updates → React re-renders → input reflects state.

---

Q: Calling `setName("")` after submit is optional — the input still works without it.
- True
- False
> True. Technically the component still works without `setName("")`. But the input won't be cleared — the old value stays visible. The user would have to manually delete it. Clearing is a best practice for good UX.

---

Q: `onClick={setCount(count + 1)}` is correct — React calls the function on click.
- True
- False
> False. `setCount(count + 1)` runs immediately during render — not on click. React needs a function reference, not a call result. Write `onClick={() => setCount(count + 1)}` or `onClick={increment}` instead.

## ShortAnswer

Q: How does the `useState` hook work? Explain the syntax, return value, and the re-render flow using a counter example.

<details>
<summary>Sample Answer</summary>

**`useState`** is a React hook that creates a state variable. When the state changes, the component automatically re-renders.

**Syntax:**
```tsx
const [count, setCount] = useState(0);
//       ^            ^            ^
//       |            |            initial value (TypeScript infers → number)
//       |            setter function — updates the state
//       current value
```

**Return value:** An array `[currentValue, setterFunction]`. Use array destructuring to pull both out.

**Re-render flow — what happens on button click:**
```
Initial render → useState(0) → count = 0 → Screen: "Count: 0"

Button Click → setCount(0 + 1) → React stores new value → re-renders
→ useState() → React remembers count is now 1 → count = 1
→ Screen: "Count: 1"
```

**Example:**
```tsx
import { useState } from "react";

function Counter(): JSX.Element {
  const [count, setCount] = useState(0);
  const [inputValue, setInputValue] = useState("");

  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    setInputValue(e.target.value);
  };

  const setFromInput = () => {
    const num = parseInt(inputValue, 10);
    if (!isNaN(num)) {
      setCount(num);
      setInputValue("");
    }
  };

  return (
    <div>
      <h2>Count: {count}</h2>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={() => setCount(count > 0 ? count - 1 : 0)}>-1</button>
      <input type="number" value={inputValue} onChange={handleChange} />
      <button onClick={setFromInput}>Set</button>
    </div>
  );
}
```

</details>

Q: Explain the controlled input pattern. Include event typing, validation, and how it connects to a callback prop in a form.

<details>
<summary>Sample Answer</summary>

**Controlled input** — the input's value is controlled by React state, not by the HTML element itself.

**The pattern:** `value={state}` + `onChange` handler that updates state.

**Example — GreetingForm:**
```tsx
import { useState } from "react";

interface GreetingFormProps {
  onSubmit: (name: string) => void;
}

function GreetingForm({ onSubmit }: GreetingFormProps) {
  const [name, setName] = useState("");  // infer → string

  const handleSubmit = () => {
    if (name.trim() !== "") {   // validation — prevents empty submit
      onSubmit(name);           // callback — sends data to parent
      setName("");              // clear — resets the input
    }
  };

  return (
    <div>
      <input
        type="text"
        value={name}                           // controlled — value from state
        onChange={(e) => setName(e.target.value)}  // updates state on every keystroke
        placeholder="Enter your name..."
      />
      <button onClick={handleSubmit}>Submit</button>
    </div>
  );
}
```

**Key concepts:**

| Concept | Code | Purpose |
|---------|------|---------|
| Controlled input | `value={name}` + `onChange` | React state is the single source of truth |
| Event typing | `React.ChangeEvent<HTMLInputElement>` | TypeScript type for input change events |
| Validation | `name.trim() !== ""` | Blocks empty submissions |
| Clear after submit | `setName("")` | Cleans input for next entry |
| Callback | `onSubmit(name)` | Child sends data to parent |

**Data flow:**
```
User types → onChange → setName → state update
→ React re-renders → input reflects new value
→ On Submit: validation → onSubmit(name) → parent's callback runs → setName("") clears input
```

</details>
