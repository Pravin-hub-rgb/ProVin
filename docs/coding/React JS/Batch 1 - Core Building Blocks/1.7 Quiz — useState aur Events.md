# 1.7 Quiz — useState aur Events

## MCQ

Q: `let count = 0` se state manage karne par kya problem hoti hai?
A. `let` variable React component ke bahar accessible nahi hota — scope issue hai
B. Component re-render par variable reset ho jata hai aur React ko pata nahi chalta
C. `let` variable sirf class components mein kaam karta hai function mein nahi
D. `let` variable sirf strings store kar sakta hai numbers allow nahi hain
> B. `let count = 0` local variable hai — har re-render par dobara `0` set ho jata hai. React ko pata nahi chalta ki value change hui. Isliye `useState` chahiye jo React ko track karne aur re-render trigger karne ka tarika deta hai.

Q: `useState` hook ka sahi syntax kya hai?
A. `const state = useState(0)` — ek variable mein state store hota hai
B. `const [count, setCount] = useState(0)` — array destructuring se value aur setter
C. `useState(0, count, setCount)` — teen arguments leta hai useState
D. `this.useState(0)` — class component style mein call karte hain
> B. `useState` ek array return karta hai jisme do elements hain — current value aur setter function. Array destructuring se dono nikaalte hain: `[count, setCount]`. Pattern hai `[value, setValue]`.

Q: Jab `setCount(count + 1)` call kiya jaata hai to React kya karta hai?
A. Turant DOM update karta hai bina re-render kiye — sirf text change hota hai
B. Nayi value store karta hai aur component ko re-render karta hai screen update hoti hai
C. Ek naya component create karta hai purane ko memory se remove karta hai
D. Browser ko ek naya HTTP request bhejta hai nayi value fetch karne ke liye
> B. `setCount(count + 1)` — React nayi value store karta hai aur component ko re-render karta hai. `useState` call hota hai to React yaad rakhta hai ki ab count 1 hai. Screen update ho jaati hai.

Q: TypeScript `useState(0)` se `count` ka type kaise infer karta hai?
A. TypeScript initial value `0` se `number` type infer kar leta hai — explicit nahi dena padta
B. TypeScript hamesha `any` type infer karta hai — har baar explicit type dena padta hai
C. TypeScript `useState(0)` se `string` infer karta hai — kyunki 0 string bhi ho sakta hai
D. TypeScript inference kaam nahi karta hooks ke saath — hamesha `<Type>` likhna padta hai
> A. TypeScript initial value se type infer karta hai. `useState(0)` → `number`. `useState("")` → `string`. `useState(false)` → `boolean`. Sirf tab explicit type do jab initial value sufficient nahi (jaise empty array).

Q: `onClick={setCount(count + 1)}` likhne par kya hoga?
A. Button click par count increment hoga — yeh sahi tarika hai onclick likhne ka
B. Component render hote hi immediately count increment ho jayega click par nahi
C. Kuch nahi hoga — TypeScript error aayegi kyunki syntax galat hai
D. Button disable ho jayega — kyunki setCount return value void hai
> B. `setCount(count + 1)` immediately call ho jayega, click par nahi. Hamesha function reference do — `onClick={() => setCount(count + 1)}` ya `onClick={increment}`. React ko function dena hai, call result nahi.

Q: Input `onChange` event ka sahi TypeScript type kya hai?
A. `React.ClickEvent<HTMLInputElement>` — change ke liye ClickEvent use karte hain
B. `React.ChangeEvent<HTMLInputElement>` — yeh generic type input change deta hai
C. `HTMLInputElement.ChangeEvent` — event type HTML element se aata hai React se nahi
D. `React.InputEvent<HTMLChangeElement>` — InputEvent change ke liye standard hai
> B. `React.ChangeEvent<HTMLInputElement>` — `ChangeEvent` React ka generic type hai changes ke liye. `<HTMLInputElement>` batata hai ki kaunsa DOM element event trigger kar raha hai.

Q: Controlled input ka pattern kya hai?
A. Input ki value HTML se aati hai aur React state onChange update hoti hai
B. Input ki value React state se aati hai (`value`) aur onChange state update karta hai
C. Input uncontrolled hota hai — React sirf initially value set karta hai baad mein nahi
D. Input ki value ek ref variable se control hoti hai state se nahi
> B. Controlled input mein `value={inputValue}` se React state source of truth hai. `onChange` user ke typing ko state mein store karta hai. React state → HTML input → user type → onChange → state update → React re-render.

Q: Count ko input se set karne ke liye alag `inputValue` state kyun rakhte hain count state mein nahi daalte?
A. Ek component mein do state variables allowed nahi hain — ek hi useState call kar sakte hain
B. `event.target.value` string hota hai — count number hai, type mismatch se bug aata hai
C. `inputValue` state React ko fast banati hai kyunki count state skip ho jaati hai
D. Alag state se code chhota hota hai — do states ek se better hain hamesha
> B. `event.target.value` hamesha string hota hai — chahe `type="number"` ho. `count` ka type `number` hai. Directly `setCount(event.target.value)` karoge to count string ban jayega aur `count + 1` string concatenation ban jayega ("5" + 1 = "51").

Q: Callback prop `onSubmit: (name: string) => void` mein `void` ka kya matlab hai?
A. Function kuch return karega — void ka matlab return type number hai
B. Function sirf kaam karta hai — koi value wapas nahi deta parent ko
C. Function asynchronous hai — void ka matlab async operation hai
D. Function error throw karega — void ka matlab error handling hai
> B. `void` ka matlab function koi value return nahi karta — sirf kaam karta hai. Child `onSubmit(name)` call karta hai, parent ka function execute hota hai, lekin parent ko koi value wapas nahi jaati.

Q: Submit ke baad `setName("")` kyun karte hain?
A. Component ko reset karne ke liye — poora component initial state mein aa jaata hai
B. Input clear karne ke liye — agla naam type karne ke liye input empty ho jaata hai
C. Memory free karne ke liye — unused state React ke memory se hata di jaati hai
D. Parent component ko notify karne ke liye — setName empty string signal bhejta hai
> B. `setName("")` input clear karta hai. Controlled input mein `value={name}` hai. Jab `setName("")` call kiya to `name` empty string ho gaya → React re-render → input ki value empty. User agla naam type kar sakta hai.

- False
> True. `useState` ek array return karta hai: `[currentValue, setterFunction]`. Setter function nayi value store karta hai aur component ko re-render karta hai taake screen update ho.

- True
- False
> False. Hooks hamesha component ke top level par call karne chahiye. React hooks ko call order ke hisaab se yaad rakhta hai. Agar `if` ke andar daaloge to kabhi call hoga kabhi nahi — order change ho jayega aur React confuse ho jayega.

Q: `event.target.value` hamesha string hota hai — chahe input `type="number"` kyun na ho.
- True
- False
> True. HTML inputs ka `value` property hamesha string return karta hai. `type="number"` sirf browser ko batata hai ki keyboard number dikhao aur validation karo — lekin `event.target.value` ka type string hi rahega.

---

Q: Controlled input mein source of truth HTML input hota hai — React state usse read karti hai.
- True
- False
> False. Controlled input mein React state source of truth hoti hai. `value={name}` se input ki value React state se aati hai. User type karta hai → onChange → state update → React re-render → input updated. React state hi controller hai HTML input nahi.

---

Q: `onSubmit(name)` ke baad `setName("")` call karna optional hai — input waise bhi render hota hai.
- True
- False
> True. Technical roop se optional hai — component bina setName("") ke bhi kaam karega. Lekin input clear nahi hoga aur pichli value dikhti rahegi. User ko manually delete karna padega. Isliye best practice hai ki submit ke baad input clear karo.

- True

> False. Yeh function call immediately hoga component render hote hi, click par nahi. Hamesha function reference do — `onClick={() => setCount(count + 1)}` ya `onClick={increment}`.

## ShortAnswer

Q: `useState` hook kaise kaam karta hai? Syntax, return value, aur re-render flow explain karo. Counter example ke saath samjhao.

<details>
<summary>Sample Answer</summary>

**`useState`** ek React hook hai jo state variable create karta hai. Jab state change hoti hai, component automatically re-render hota hai.

**Syntax:**
```tsx
const [count, setCount] = useState(0);
//       ^            ^            ^
//       |            |            initial value (TypeScript infer → number)
//       |            setter function — state change karta hai
//       current value
```

**Return value:** Ek array — `[currentValue, setterFunction]`. Array destructuring se nikaalte hain.

**Flow — kya hota hai jab button dabate ho:**
```
Initial render → useState(0) → count = 0 → Screen: "Count: 0"

Button Click → setCount(0 + 1) → React nayi value store karta hai → re-render
→ useState() → React yaad rakhta hai ab count 1 hai → count = 1
→ Screen: "Count: 1"
```

**Example:**
```tsx
import { useState } from "react";

function Counter(): JSX.Element {
  const [count, setCount] = useState(0);
  const [inputValue, setInputValue] = useState("");

  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    setInputValue(e.target.value);
  };

  const setFromInput = () => {
    const num = parseInt(inputValue, 10);
    if (!isNaN(num)) {
      setCount(num);
      setInputValue("");
    }
  };

  return (
    <div>
      <h2>Count: {count}</h2>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={() => setCount(count > 0 ? count - 1 : 0)}>-1</button>
      <input type="number" value={inputValue} onChange={handleChange} />
      <button onClick={setFromInput}>Set</button>
    </div>
  );
}
```

</details>

Q: Controlled input pattern kya hai? Event typing, validation, aur callback prop ke saath ek form example do.

<details>
<summary>Sample Answer</summary>

**Controlled input** — input ki value React state se control hoti hai, HTML input khud nahi.

**Pattern:** `value={state}` + `onChange` handler jo state update kare.

**Example — GreetingForm:**
```tsx
import { useState } from "react";

interface GreetingFormProps {
  onSubmit: (name: string) => void;
}

function GreetingForm({ onSubmit }: GreetingFormProps) {
  const [name, setName] = useState("");  // infer → string

  const handleSubmit = () => {
    if (name.trim() !== "") {   // validation — empty check
      onSubmit(name);           // callback — parent ko data
      setName("");              // clear — input empty
    }
  };

  return (
    <div>
      <input
        type="text"
        value={name}                           // controlled
        onChange={(e) => setName(e.target.value)}  // update state
        placeholder="Enter your name..."
      />
      <button onClick={handleSubmit}>Submit</button>
    </div>
  );
}
```

**Key concepts:**
| Concept | Code | Kaam |
|---------|------|------|
| Controlled input | `value={name}` + `onChange` | React state source of truth |
| Event typing | `React.ChangeEvent<HTMLInputElement>` | TypeScript type for input change |
| Validation | `name.trim() !== ""` | Empty submit rokta hai |
| Clear after submit | `setName("")` | Input clean, next value ready |
| Callback | `onSubmit(name)` | Child → parent data bhejta hai |

</details>
