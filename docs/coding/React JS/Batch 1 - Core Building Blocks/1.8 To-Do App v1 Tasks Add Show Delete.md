# 1.8 — To-Do App v1: Tasks Add, Show, Delete

## Abhi Tak Kya Hua

1.7 mein `useState` seekha — Counter banaya, event handling samjhi, controlled inputs dekhe, aur `TaskInput` component ko actual kaam karne layak banaya. Ab state store kar sakte hain aur user input handle kar sakte hain.

## Broader Goal

Ab tak ke saare concepts ek saath use karenge — To-Do app ka **working version 1** banayenge. Tasks add karna, screen par dikhana, aur delete karna — yeh teen features implement honge. TypeScript types bhi define karenge task structure ke liye.

## Step 1 — Task Type Define Karo

Soch: "Task ki kya information store karni chahiye? Sirf text kaafi hai ya aur kuch?"

**Concept:** Ek task mein at least yeh hona chahiye:
- `id` — unique identifier (delete/edit ke time identify karne ke liye)
- `text` — actual task content
- `completed` — status (abhi nahi, 1.9 mein add hoga)

`interface` se task ka shape define karo. `src/App.tsx` ke top par (ya alag file mein) yeh add karo:

```tsx
interface Task {
  id: number;
  text: string;
}
```

Yeh type pure data hai, component nahi — isliye `.ts` file mein bhi rakh sakte ho. Abhi `App.tsx` mein hi rakhte hain, baad mein alag file mein nikaal lenge.

`App.tsx` mein state add karo:

```tsx
import { useState } from "react";
import Container from "./components/Container";
import TaskInput from "./components/TaskInput";

interface Task {
  id: number;
  text: string;
}

function App() {
  const [tasks, setTasks] = useState<Task[]>([]);

  const handleAdd = (text: string) => {
    const newTask: Task = {
      id: Date.now(),
      text: text,
    };
    setTasks([...tasks, newTask]);
  };

  return (
    <Container>
      <h1>To-Do App</h1>
      <TaskInput onAdd={handleAdd} />
    </Container>
  );
}

export default App;
```

**Key concepts:**

1. `useState<Task[]>([])` — state array of tasks hai, initially empty
2. `Date.now()` — unique id generate karta hai (current timestamp in milliseconds). Real apps mein UUID use karte hain, lekin abhi yeh kaafi hai
3. `[...tasks, newTask]` — spread operator. Purane array ko copy karo aur naya task add karo

## Step 2 — State Update Ka Rule

Soch: "Direct push kyun nahi kar sakte? `tasks.push(newTask)` likhne se kya hoga?"

**Concept — Immutability:** React mein state ko **directly modify nahi** kar sakte. `tasks.push(newTask)` se array change ho jayega, lekin React ko pata nahi chalega. React ko naya array reference chahiye.

```tsx
// ❌ Galat — React ko pata nahi chalega
tasks.push(newTask);
setTasks(tasks);

// ✅ Sahi — naya array create karo
setTasks([...tasks, newTask]);
```

Spread operator `...tasks` original array ke saare elements ko naye array mein copy karta hai. Phir `newTask` end mein add hota hai. Yeh naya array React ko batata hai ki "state change hui hai, re-render karo".

Same for delete:

```tsx
// ❌ Galat
delete tasks[id];

// ✅ Sahi — filter se naya array banao
setTasks(tasks.filter((task) => task.id !== id));
```

## Step 3 — Tasks Display Karo

Soch: "Tasks array mein store hain. Screen par kaise dikhayen?"

Abhi `.map()` use karenge — JavaScript ka method jo array ke har element par loop karta hai aur naya array return karta hai. Detail explanation 1.10 mein, abhi basic use:

`App.tsx` mein return ke andar `TaskInput` ke neeche tasks render karo:

```tsx
function App() {
  const [tasks, setTasks] = useState<Task[]>([]);

  const handleAdd = (text: string) => {
    const newTask: Task = { id: Date.now(), text };
    setTasks([...tasks, newTask]);
  };

  const handleDelete = (id: number) => {
    setTasks(tasks.filter((task) => task.id !== id));
  };

  return (
    <Container>
      <h1>To-Do App</h1>
      <TaskInput onAdd={handleAdd} />
      <div>
        {tasks.map((task) => (
          <div key={task.id}>
            <span>{task.text}</span>
            <button onClick={() => handleDelete(task.id)}>Delete</button>
          </div>
        ))}
      </div>
      {tasks.length === 0 && <p>No tasks yet. Add one above!</p>}
    </Container>
  );
}
```

**Breakdown:**

1. `{tasks.map((task) => (...))}` — har task ke liye ek `<div>` render karo
2. `key={task.id}` — React ko har element ki unique identity batata hai (0.3 Reconciliation mein padha tha). Required jab list render karo
3. `onClick={() => handleDelete(task.id)}` — delete button, arrow function immediate call nahi karta, sirf reference pass karta hai
4. `tasks.length === 0 && <p>No tasks yet...</p>` — agar koi task nahi hai toh message dikhao

Browser mein check karo — tasks add ho rahe hain, delete ho rahe hain, aur empty state message dikh raha hai.

## Step 4 — TaskList Component Mein Extract Karo

Soch: "App.tsx bada ho raha hai. Task list ka logic alag component mein rakhna chahiye."

`src/components/TaskList.tsx`:

```tsx
interface Task {
  id: number;
  text: string;
}

interface TaskListProps {
  tasks: Task[];
  onDelete: (id: number) => void;
}

function TaskList({ tasks, onDelete }: TaskListProps): JSX.Element {
  return (
    <div>
      {tasks.map((task) => (
        <div key={task.id}>
          <span>{task.text}</span>
          <button onClick={() => onDelete(task.id)}>Delete</button>
        </div>
      ))}
      {tasks.length === 0 && <p>No tasks yet. Add one above!</p>}
    </div>
  );
}

export default TaskList;
```

Ab `App.tsx` mein `Task` interface export karo aur `TaskList` import karo:

```tsx
import { useState } from "react";
import Container from "./components/Container";
import TaskInput from "./components/TaskInput";
import TaskList from "./components/TaskList";

export interface Task {
  id: number;
  text: string;
}

function App() {
  const [tasks, setTasks] = useState<Task[]>([]);

  const handleAdd = (text: string) => {
    const newTask: Task = { id: Date.now(), text };
    setTasks([...tasks, newTask]);
  };

  const handleDelete = (id: number) => {
    setTasks(tasks.filter((task) => task.id !== id));
  };

  return (
    <Container>
      <h1>To-Do App</h1>
      <TaskInput onAdd={handleAdd} />
      <TaskList tasks={tasks} onDelete={handleDelete} />
    </Container>
  );
}

export default App;
```

**Interface duplication problem:** `Task` interface abhi `TaskList.tsx` aur `App.tsx` dono mein define hai. Agar ek jagah change kiya toh doosri jagah bhi change karna padega. Solution — common types alag file mein. Agle step mein karenge.

## Step 5 — Common Types Alag File Mein

`src/types.ts`:

```ts
export interface Task {
  id: number;
  text: string;
}
```

Ab dono files mein import karo:

`src/App.tsx`:
```tsx
import { useState } from "react";
import Container from "./components/Container";
import TaskInput from "./components/TaskInput";
import TaskList from "./components/TaskList";
import type { Task } from "./types";
```

`src/components/TaskList.tsx`:
```tsx
import type { Task } from "../types";

interface TaskListProps {
  tasks: Task[];
  onDelete: (id: number) => void;
}
```

**`import type` vs `import`:** `import type` sirf types import karta hai, runtime JavaScript mein kuch add nahi karta. TypeScript 4.5+ ka feature hai. Agar sirf types import kar rahe ho, `import type` use karo — isse bundle size pe positive effect hota hai.

## Summary

- `Task` type define kiya: `{ id: number; text: string }`
- `useState<Task[]>([])` — tasks array state
- State immutability rule: naya array reference do (`...spread`, `.filter()`)
- `.map()` — array ke har element ke liye JSX render karo
- `key={task.id}` — list rendering mein zaroori
- Common types alag file mein rakho (`src/types.ts`)
- `import type` — sirf types import karta hai, bundle mein nahi aata
