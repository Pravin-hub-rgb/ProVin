## Where We Left Off

In 1.4, we learned how to organize components in separate files — the `components/` folder, `export default`, and importing from relative paths. The components were still static — hardcoded data. Now we'll make them **dynamic** using **props**. But before that, we need to understand **interfaces** — they define the shape of our props types.

## Broader Goal

An interface defines an object's **shape** — what properties it has and what types they should be. This is a core TypeScript concept. In 1.5.2, we'll use this with props. For now, let's solidify the interface concept at a pure TypeScript level.

## Step 1 — Feel the Problem

Think: "I'm creating an object `{ name: "Vin", age: 25 }`. How do I ensure it always has `name` (a string) and `age` (a number) — and nothing else?"

Without TypeScript — no guarantee. Anyone can add, remove, or change any property. The solution is TypeScript's **interface**.

## Step 2 — Your First Interface

**Concept:** An interface defines the **shape** of an object.

```ts
interface User {
  name: string;
  age: number;
}

const user: User = { name: "Vin", age: 25 };     // ✅
const bad: User = { name: "Vin" };                 // ❌ 'age' missing
const bad2: User = { name: "Vin", age: "25" };     // ❌ age should be number
```

The `interface User { }` block defines — "any object typed as `User` must have `name: string` and `age: number`." TypeScript now enforces this.

### Naming Your Interface

- PascalCase — `User`, `Product`, `ProfileCardProps`
- A noun — `User`, `Task`, `Config`
- Props convention: `ComponentNameProps` — `ProfileCardProps`

## Step 3 — Export and Import an Interface

Interfaces are types — they can be used in other files:

`types.ts`:

```ts
export interface User {
  name: string;
  age: number;
}
```

`App.tsx`:

```tsx
import type { User } from "./types";

const user: User = { name: "Vin", age: 25 };
```

Use `import type` — it's a type-only import that won't end up in the runtime bundle.

## Step 4 — Multiple Properties + Nested Objects

Interfaces can hold simple types, arrays, and nested objects:

```ts
interface Address {
  city: string;
  pincode: number;
}

interface User {
  name: string;
  age: number;
  address: Address;        // nested interface
  skills: string[];        // array of strings
  metadata: Record<string, string>;  // dynamic keys
}
```

## Step 5 — Reusing Interfaces

Interfaces can be reused across multiple places — keeping consistency:

```ts
interface User {
  name: string;
  age: number;
}

function greet(user: User) {
  return `Hello, ${user.name}`;
}

function isAdult(user: User) {
  return user.age >= 18;
}
```

## Summary

- `interface` = defines the shape of an object
- Syntax: `interface Name { prop1: type1; prop2: type2 }`
- Enforces types — wrong property = compile-time error
- Naming convention: PascalCase (`User`, `Product`)
- `export interface` + `import type` — reuse across files
- Supports nested interfaces, arrays, and complex types
- Props convention: `ComponentNameProps`
