## Where We Left Off

In 1.9, we learned array state — storing items with `useState<string[]>([])`, adding items with the spread operator, rendering with `.map()`, deleting with `.filter()`. We also saw a glimpse of conditional rendering: `items.length === 0 && <p>...</p>`. This chapter dives deeper into **conditional rendering**.

## Broader Goal

We'll build a **Flagged Items** app — like the 1.9 todo app, but now items are objects instead of strings. Each item has a **flag** (star) that can be toggled. **Filter buttons** show only flagged, unflagged, or all items. We'll also display an **item count**.

While building this, we'll learn:
- **Ternary operator `? :`** and **`&&`** – conditional rendering in JSX
- **`.map()` with a condition** – updating a specific item in an array
- **Union types** – `"all" | "flagged" | "unflagged"`
- **`.filter()` with a property** – filtering objects by property

## Step 1 – Scaffold: Full App

Let's create a new `App.tsx` – now using `Item` objects instead of strings. Same pattern as 1.9, just the object version.

Create a `src/types.ts` file:

```ts
export interface Item {
  id: number;
  text: string;
  flagged: boolean;
}
```

**App.tsx** – full code. Works like 1.9, but stores `Item` objects instead of strings:

```tsx
import { useState } from "react";
import type { Item } from "./types";

export default function App() {
  const [items, setItems] = useState<Item[]>([]);
  const [input, setInput] = useState("");

  console.log("Items:", items);

  const handleAdd = () => {
    if (input.trim() === "") return;
    const newItem: Item = {
      id: Date.now(),
      text: input.trim(),
      flagged: false,
    };
    setItems([...items, newItem]);
    setInput("");
  };

  const handleDelete = (id: number) => {
    setItems(items.filter((item) => item.id !== id));
  };

  return (
    <div>
      <h1>Flagged Items</h1>
      <div>
        <input
          value={input}
          onChange={(e) => setInput(e.target.value)}
          placeholder="Add item..."
        />
        <button onClick={handleAdd}>Add</button>
      </div>
      <div>
        {items.length === 0 ? (
          <p>No items yet. Add one above!</p>
        ) : (
          items.map((item) => (
            <div key={item.id}>
              <span>{item.text}</span>
              <button onClick={() => handleDelete(item.id)}>Delete</button>
            </div>
          ))
        )}
      </div>
    </div>
  );
}
```

**Test it** – items are added and deleted. Now we add conditional rendering: toggle flag, filter buttons, item count.

## Step 2 – Toggle Flag (`.map()` with Condition)

**Think:** "When the user clicks a star, the flag toggles – `flagged: true` becomes `false` and vice versa."

**Problem:** In 1.9 we deleted items with `.filter()` – removing the whole item. Here we need to **update** the item, not delete it. Can we push directly?

```tsx
// ❌ Think – will this work?
items[0].flagged = true;
setItems(items);
```

No, it won't. Same reference issue – React ignores it. Immutability rule: create a new array.

**Concept – `.map()` with a condition:**

`.map()` iterates through every element and returns something for each. You can add a condition – change only the matching element, leave the rest as-is:

```tsx
const nums = [1, 2, 3, 4, 5];

const result = nums.map((n) => {
  if (n > 2) return n * 10;  // matches condition → change
  return n;                    // otherwise → unchanged
});

console.log(result); // → [1, 2, 30, 40, 50]
```

Only elements matching the condition (`n > 2`) get changed.

**Apply this to the app – `handleToggleFlag`:**

```tsx
const handleToggleFlag = (id: number) => {
  setItems(
    items.map((item) => {
      if (item.id === id) {
        return { ...item, flagged: !item.flagged };
      }
      return item;
    })
  );
};
```

`...item` means "copy all existing properties of item." Then override just `flagged` with the flipped value `!item.flagged`.

**Verify with console.log:**

```tsx
const handleToggleFlag = (id: number) => {
  const updated = items.map((item) => {
    if (item.id === id) return { ...item, flagged: !item.flagged };
    return item;
  });
  console.log("After toggle:", updated);
  setItems(updated);
};
```

Add an item. Copy its `id` from the console. Call `handleToggleFlag(thatId)`. In the console you'll see only that item's `flagged` flip from `false` to `true`.

## Step 3 – Conditional Rendering Concepts (Ternary + &&)

**Think:** "The toggle logic is ready. Now I need the UI to show different things based on conditions – a filled star for flagged items, an outline for unflagged."

**Why:** The same button needs to render different content depending on the item's state. This is the core use case for conditional rendering.

Let's look at standalone examples first.

**Concept – Ternary Operator `? :`:**

```js
const age = 20;
const label = age >= 18 ? "Adult" : "Minor";
console.log(label); // → "Adult"
```

Pattern: `condition ? valueIfTrue : valueIfFalse`

In React JSX:

```tsx
const isMorning = true;
return <p>{isMorning ? "🌅" : "🌙"}</p>;
```

This is an **inline** JSX expression – used directly inside `{ }`.

**Concept – `&&` Operator:**

```js
const isLoggedIn = true;
isLoggedIn && console.log("Welcome!");
// → "Welcome!"
```

`&&` means: if the left side is truthy, evaluate the right. If falsy, short-circuit and skip.

In React: "show this only when the condition is true":

```tsx
const hasNotification = true;
return <div>{hasNotification && <span>🔔</span>}</div>;
```

Both of these show up everywhere in React code. Let's apply them to the app.

## Step 4 – Conditional UI in the App

**Think:** "The concepts are clear. Now I need to add a star toggle button and conditional styling in App.tsx."

The scaffold from Step 1 only shows text + delete. Now add a **star button** that toggles the flag. Apply conditional rendering one step at a time.

First, add the star button to the item rendering, with simple "Toggle" text:

```tsx
{items.map((item) => (
  <div key={item.id}>
    <button onClick={() => handleToggleFlag(item.id)}>Toggle</button>
    <span>{item.text}</span>
    <button onClick={() => handleDelete(item.id)}>Delete</button>
  </div>
))}
```

Note: `key={item.id}` – since each item has a unique id, use that instead of the index.

**Test it** – clicking toggle flips `flagged` between `true` and `false`. Now turn that button into a star icon.

**Star icon – ternary:**

```tsx
<button onClick={() => handleToggleFlag(item.id)}>
  {item.flagged ? "★" : "☆"}
</button>
```

Condition: if `item.flagged` is true → filled star `★`; if false → outline star `☆`.

**Background color – ternary:**

```tsx
<button
  onClick={() => handleToggleFlag(item.id)}
  style={{
    background: item.flagged ? "#ffd700" : "#eee",
    border: "1px solid #ccc",
    borderRadius: "4px",
    cursor: "pointer",
    padding: "2px 8px",
    marginRight: "8px",
  }}
>
  {item.flagged ? "★" : "☆"}
</button>
```

**Text bold – ternary:**

```tsx
<span style={{ fontWeight: item.flagged ? "bold" : "normal" }}>
  {item.text}
</span>
```

Each line is a conditional rendering use case, all using the ternary operator.

**Test it:**
1. Add "Milk" → star is grey (`☆`), text is normal
2. Click star → star turns yellow (`★`), text becomes bold
3. Click again → back to grey, normal

## Step 5 – Filter Buttons (Union Type + `.filter()`)

**Think:** "All items show up. But the user might want to see only flagged items, or only unflagged."

**Problem:** There's no filtering. We need to track which filter is active, and render items accordingly.

We need three possible filter values:
- `"all"` – all items
- `"flagged"` – only flagged items
- `"unflagged"` – only unflagged items

TypeScript uses **union types** to enforce that only these three string values are allowed.

**Concept – Union Type:**

```ts
type TrafficLight = "red" | "yellow" | "green";

let light: TrafficLight = "red";  // ✅
light = "blue";                    // ❌ TypeScript error
```

`|` means "or" – the value can be one of these. Only the specified values are allowed.

**Concept – `.filter()` with a property (review from 1.9, now with objects):**

In 1.9 we filtered strings. Now we check object properties:

```ts
const items: Item[] = [
  { id: 1, text: "Milk", flagged: true },
  { id: 2, text: "Eggs", flagged: false },
];

const flaggedItems = items.filter((item) => item.flagged);
console.log(flaggedItems); // → [Milk]

const unflaggedItems = items.filter((item) => !item.flagged);
console.log(unflaggedItems); // → [Eggs]
```

**Add the filter state to App.tsx:**

```tsx
type FilterStatus = "all" | "flagged" | "unflagged";

function App() {
  const [items, setItems] = useState<Item[]>([]);
  const [filter, setFilter] = useState<FilterStatus>("all");
  const [input, setInput] = useState("");
  // ...
}
```

Note the union type's initial value is `"all"` – at first, all items show.

**Add the filter logic – before the return, inside App:**

```tsx
const filteredItems = items.filter((item) => {
  if (filter === "flagged") return item.flagged;
  if (filter === "unflagged") return !item.flagged;
  return true; // "all" – keep everything
});

console.log("Current filter:", filter, "Filtered:", filteredItems); // verify
```

**Add three filter buttons – between the input and the list:**

```tsx
<div>
  <button
    onClick={() => setFilter("all")}
    style={{ fontWeight: filter === "all" ? "bold" : "normal" }}
  >
    All
  </button>
  <button
    onClick={() => setFilter("flagged")}
    style={{ fontWeight: filter === "flagged" ? "bold" : "normal" }}
  >
    Flagged
  </button>
  <button
    onClick={() => setFilter("unflagged")}
    style={{ fontWeight: filter === "unflagged" ? "bold" : "normal" }}
  >
    Unflagged
  </button>
</div>
```

This is a new use case for conditional styling – whichever filter is active appears bold.

**Replace `items.map` with `filteredItems.map`:**

```tsx
{filteredItems.map((item) => (
  // ... same rendering
))}
```

**Full return of App.tsx:**

```tsx
return (
  <div>
    <h1>Flagged Items</h1>

    <div>
      <input
        value={input}
        onChange={(e) => setInput(e.target.value)}
        placeholder="Enter an item..."
      />
      <button onClick={handleAdd}>Add</button>
    </div>

    <div>
      <button
        onClick={() => setFilter("all")}
        style={{ fontWeight: filter === "all" ? "bold" : "normal" }}
      >
        All
      </button>
      <button
        onClick={() => setFilter("flagged")}
        style={{ fontWeight: filter === "flagged" ? "bold" : "normal" }}
      >
        Flagged
      </button>
      <button
        onClick={() => setFilter("unflagged")}
        style={{ fontWeight: filter === "unflagged" ? "bold" : "normal" }}
      >
        Unflagged
      </button>
    </div>

    <div>
      {filteredItems.map((item) => (
        <div key={item.id}>
          <button
            onClick={() => handleToggleFlag(item.id)}
            style={{
              background: item.flagged ? "#ffd700" : "#eee",
              border: "1px solid #ccc",
              borderRadius: "4px",
              cursor: "pointer",
              padding: "2px 8px",
              marginRight: "8px",
            }}
          >
            {item.flagged ? "★" : "☆"}
          </button>
          <span style={{ fontWeight: item.flagged ? "bold" : "normal" }}>
            {item.text}
          </span>
          <button onClick={() => handleDelete(item.id)}>Delete</button>
        </div>
      ))}
    </div>

    {items.length === 0 && <p>No items yet. Add one above!</p>}
  </div>
);
```

**Test it:**
1. Add "Milk", flag it. Add "Eggs", don't flag it.
2. Click **Flagged** → only "Milk" shows
3. Click **Unflagged** → only "Eggs" shows
4. Click **All** → both reappear
5. Toggle a flag → the filtered list updates instantly

## Step 6 – Put `FilterStatus` in Common Types

**Think:** "The `FilterStatus` type is defined in App.tsx. What if another file needs it later?"

**Why:** Avoid type duplication. Define once, import everywhere.

Put both types in `src/types.ts`:

```ts
export interface Item {
  id: number;
  text: string;
  flagged: boolean;
}

export type FilterStatus = "all" | "flagged" | "unflagged";
```

Update the import in App.tsx:

```tsx
import type { Item, FilterStatus } from "./types";
```

Remove the `type FilterStatus = ...` line from App.tsx.

## Step 7 – Item Count (Extra Conditional Rendering)

**Think:** "Show how many items there are and how many are flagged."

**Why:** Users want a summary.

```tsx
{
  items.length > 0 && (
    <p>
      Flagged: {items.filter((item) => item.flagged).length} / {items.length} items
    </p>
  )
}
```

This `&&` conditional rendering shows the message only when items exist. `items.filter((item) => item.flagged).length` counts how many are flagged.

If there are no items, nothing displays. If there are items, it shows "Flagged: 2 / 3 items."

## Summary

- **Interface** – defines an object's shape (`Item { id, text, flagged }`)
- **`.map()` with a condition** – updates a specific item, leaves the rest unchanged
- **Ternary `? :`** – `condition ? valueIfTrue : valueIfFalse` – inline conditional in JSX
- **`&&` operator** – `condition && <JSX>` – renders only when condition is truthy
- **Union type** – `"all" | "flagged" | "unflagged"` – enforces a specific set of values
- **`.filter()` with a property** – `items.filter(item => item.flagged)` – filters by property
- **Conditional styles** – `style={{ prop: condition ? value1 : value2 }}`
- **Immutability** – `.map()` and `.filter()` create new arrays, never mutate
