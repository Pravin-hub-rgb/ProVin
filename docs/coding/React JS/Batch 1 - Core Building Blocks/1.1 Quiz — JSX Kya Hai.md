# 1.1 Quiz — JSX Kya Hai

## MCQ

Q: JSX ka full form kya hai?
A. JavaScript XML — HTML jaisa syntax jo React.createElement mein compile hota hai
B. JavaScript Extension — browser ko directly samajh aane wala naya markup system
C. Java Syntax Extension — React ko server-side render karne ka specific tool hai
D. JSON XML Format — HTML aur JSON combination jo dynamic data handle karta hai
> A. JSX = JavaScript XML. Ye HTML jaisa syntax hai jo Vite ke compiler (esbuild) dwara React.createElement calls mein convert hota hai. Browser JSX directly nahi samajhta.

---

Q: `<h1>Hello</h1>` ka console mein typeof check karne par kya output aata hai?
A. string — kyunki HTML jaisa dikhta hai isliye string return hona chahiye
B. object — kyunki JSX compile ho kar ek JavaScript object return karta hai
C. function — kyunki har element internally render function ki tarah work karta hai
D. undefined — kyunki JSX bina compiler ke directly execute nahi ho sakta hai
> B. `<h1>Hello</h1>` ka typeof "object" hai — ek plain JavaScript object jisme `type: 'h1'` aur `props: { children: 'Hello' }` hota hai. Yahi React ka Virtual DOM node hai.

---

Q: JSX mein `class` attribute ki jagah `className` kyun use karte hain?
A. JavaScript mein `class` ek reserved keyword hai — isliye className use karte hain
B. React ne className rakha kyunki class CSS ka part hai aur conflict hota hai
C. className sirf React ka ek purana convention hai jo ab deprecated ho chuka hai
D. Sirf TypeScript projects mein className ki zaroorat hai, JS mein class chalega
> A. `class` JavaScript mein ek reserved keyword hai (jaise `if`, `for`, `return`). Isliye JSX ne className use kiya. React internally isse `class` attribute mein convert kar deta hai.

---

Q: JSX mein self-closing tag kaise likhna chahiye?
A. `<input>` — bina close kiye HTML ki tarah, error nahi aati hai
B. `<input />` — `/` ke saath close karna padta hai, warna error aati hai
C. `<input></input>` — opening aur closing tags dono likhne padte hain JSX mein
D. `<input/>` — bina space ke bhi chal sakta hai kabhi kabhi error aati hai
> B. JSX mein har self-closing tag (`<br>`, `<input>`, `<img>`) ko `/` ke saath close karna padta hai — `<br />`. HTML mein bina close kiye chal jata hai, lekin JSX mein error aayegi.

---

Q: JSX mein `{ }` curly braces ka kya kaam hai?
A. HTML comments add karne ke liye use hote hain JSX code ke andar
B. CSS styles inline define karne ke liye use hote hain JSX code ke andar
C. JavaScript expressions embed karne ke liye use hote hain JSX code ke andar
D. Multiple elements group karne ke liye use hote hain JSX code ke andar
> C. `{ }` curly braces ke andar koi bhi JavaScript expression daal sakte ho — variable, calculation, function call, ternary operator. Sirf expressions (jo value return karein), statements nahi.

---

Q: JSX mein kaunsa code sahi hai?
A. `<p>{if (true) { return "Hi" }}</p>` — conditional logic ka sahi tarika hai
B. `<p>{name.toUpperCase()}</p>` — JavaScript function expression ka sahi use hai
C. `<p>{for (let i = 0; i < 5; i++) { }}</p>` — loop ka sahi istemal JSX code mein
D. `<p>{const x = 5; x + 3}</p>` — variable declaration addition ka sahi method hai
> B. Sirf expressions allowed hain jo value return karein. `name.toUpperCase()` ek expression hai jo value return karta hai. `if`, `for`, `const` statements hain — ye expressions nahi hain isliye JSX mein embed nahi ho sakte.

---

Q: JSX mein do siblings ek saath return karne par kaun si error aati hai?
A. Multiple elements must be wrapped in an array format
B. Adjacent JSX elements must be wrapped in an enclosing tag
C. Two siblings cannot be returned from the same component function
D. Each JSX element needs a unique key identifier prop for rendering
> B. JavaScript function sirf ek hi value return kar sakta hai. Do `<h1>` aur `<p>` ko ek saath return karna = do values return karna. Inhe `<div>` ya `<>` Fragment mein wrap karna padta hai.

---

Q: Fragment (`<>...</>`) ka kya fayda hai?
A. DOM mein extra wrapper node banata hai CSS styling aur layout ke liye
B. DOM mein koi extra element nahi banata sirf group karne ka kaam karta hai
C. Sirf TypeScript projects mein Fragment use kar sakte ho JS projects mein nahi
D. Fragment sirf development mode mein kaam karta hai production build mein nahi
> B. `<>...</>` (Fragment) DOM mein koi extra element nahi banata. `<div>` se wrap karne par DOM mein extra `<div>` aata hai. Jab styling ke liye extra wrapper nahi chahiye, tab Fragment use karte hain.

## TrueFalse

Q: JSX browser directly samajh leta hai — ise compile karne ki zaroorat nahi hai.
- True
- False
> False. Browser JSX directly nahi samajhta. Vite background mein esbuild compiler chala kar JSX ko React.createElement calls mein convert karta hai. Browser ko sirf plain JavaScript samajh aata hai.

---

Q: JSX mein `onclick` (lowercase) attribute HTML ki tarah sahi hai.
- True
- False
> False. HTML mein `onclick` (lowercase) hota hai, lekin JSX mein camelCase use hota hai — `onClick`, `onKeyDown`, `tabIndex`. Agar `onclick` likhoge to TypeScript error aayegi kyunki React sirf JSX-style props expect karta hai.

---

Q: JSX ke andar sirf expressions daal sakte hain, statements nahi.
- True
- False
> True. Expressions (jaise `name`, `2 + 3`, `name.toUpperCase()`) value return karte hain aur JSX mein embed ho sakte hain. Statements (jaise `if`, `for`, `const`) kuch return nahi karte isliye embed nahi ho sakte.

---

Q: `<>` Fragment ka use karke multiple elements return kar sakte hain bina extra DOM node banaye.
- True
- False
> True. `<>` DOM mein koi extra element nahi banata. Developer tools mein inspect karoge to sirf actual elements dikhenge, koi wrapper `<div>` nahi. Jab styling ke liye extra wrapper zaroori ho tab `<div>` use karo.

## ShortAnswer

Q: JSX kya hai aur yeh kaise kaam karta hai? Code likhne se lekar browser mein render hone tak ka poora flow explain karo.

<details>
<summary>Sample Answer</summary>

**Answer:** JSX (JavaScript XML) ek syntax extension hai jo HTML jaisa dikhta hai lekin asal mein React.createElement calls ka shorthand hai.

**Step-by-step flow:**

1. **Code likhna:** Tum `App.tsx` mein JSX likhte ho — `<h1>Hello</h1>`.
2. **Compilation:** Vite (esbuild) JSX ko React.createElement mein convert karta hai:
   - `<h1>Hello</h1>` → `React.createElement("h1", null, "Hello")`
3. **Virtual DOM node:** `React.createElement` ek plain JavaScript object return karta hai:
   - `{ type: 'h1', props: { children: 'Hello' } }` — yahi Virtual DOM node hai.
4. **Reconciliation:** React Virtual DOM tree ko purani copy se compare karta hai.
5. **Commit:** Sirf actually badle hue parts real DOM mein apply hote hain.
6. **Browser render:** Real DOM update hota hai aur browser screen pe draw karta hai.

**Key point:** JSX ek syntactic sugar hai — likhne mein achi lagi, par asal mein kuch aur ho raha hai.

</details>

Q: HTML aur JSX mein 4 main fark kya hain? Examples ke saath explain karo.

<details>
<summary>Sample Answer</summary>

**Answer:** Chaar main fark:

**1. `class` vs `className`:**
- HTML: `<h1 class="heading">Hello</h1>`
- JSX: `<h1 className="heading">Hello</h1>`
- Reason: `class` JavaScript ka reserved keyword hai.

**2. `for` vs `htmlFor`:**
- HTML: `<label for="email">Email</label>`
- JSX: `<label htmlFor="email">Email</label>`
- Reason: `for` bhi JavaScript ka reserved keyword hai.

**3. Self-closing tags:**
- HTML: `<br>` `<input>` — bina close kiye chal jata hai.
- JSX: `<br />` `<input />` — har tag ko close karna padta hai (`/` ke saath).

**4. camelCase attributes:**
- HTML: `onclick`, `onkeydown`, `tabindex` (lowercase)
- JSX: `onClick`, `onKeyDown`, `tabIndex` (camelCase)

**Bonus fark — JavaScript expressions:**
- JSX mein `{ }` curly braces use karke JavaScript expressions embed kar sakte ho: `{name}`, `{2 + 3}`, `{name.toUpperCase()}`. HTML mein aisa kuch nahi hai.

</details>
