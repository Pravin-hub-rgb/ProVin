
## MCQ

Q: What does JSX stand for?
A. JavaScript XML — HTML-like syntax that compiles into `React.createElement` calls
B. JavaScript Extension — a new markup system the browser understands directly
C. Java Syntax Extension — a React-specific tool for server-side rendering
D. JSON XML Format — a combination of HTML and JSON that handles dynamic data
> A. JSX = JavaScript XML. It's an HTML-like syntax that gets compiled into `React.createElement` calls by Vite's compiler (esbuild). The browser does not understand JSX directly.

---

Q: When you check `typeof <h1>Hello</h1>` in the console, what output do you get?
A. string — because it looks like HTML, it should return a string
B. object — because JSX compiles into a JavaScript object
C. function — because every element works internally as a render function
D. undefined — because JSX can't execute without a compiler
> B. The `typeof <h1>Hello</h1>` is `object` — a plain JavaScript object with `type: 'h1'` and `props: { children: 'Hello' }`. This is a React Virtual DOM node.

Q: In JSX, why do you use `className` instead of `class`?
A. Because TypeScript can distinguish components from HTML tags more easily
B. Because React sees it as a custom component, not an HTML tag
C. Because `class` is a reserved keyword in JavaScript
D. Because lowercase functions are deprecated in modern JavaScript
> C. `class` is a reserved keyword in JavaScript (like `if`, `for`, `return`). That's why JSX uses `className` instead. React internally converts this back to the `class` attribute.

---

Q: How should self-closing tags be written in JSX?
A. `<input>` — no closing needed, just like in HTML, no error occurs
B. `<input />` — must close with `/`, otherwise an error occurs
C. `<input></input>` — both opening and closing tags must be written in JSX
D. `<input/>` — without a space, sometimes an error occurs
> B. In JSX, every self-closing tag (`<br>`, `<input>`, `<img>`) must be closed with `/` — like `<br />`. HTML lets you omit the closing, but JSX throws an error.

---

Q: What is the purpose of `{ }` curly braces in JSX?
A. To add HTML comments inside JSX code
B. To define CSS styles inline within JSX code
C. To embed JavaScript expressions inside JSX code
D. To group multiple elements within JSX code
> C. You can put any JavaScript expression inside `{ }` — variables, calculations, function calls, ternary operators. Only expressions (that return a value) are allowed, not statements.

---

Q: Which of these is the correct way to write JSX?
A. `<p>{if (true) { return "Hi" }}</p>` — the correct way to write conditional logic
B. `<p>{name.toUpperCase()}</p>` — the correct use of a JavaScript expression
C. `<p>{for (let i = 0; i < 5; i++) { }}</p>` — the correct way to use a loop in JSX
D. `<p>{const x = 5; x + 3}</p>` — the correct way to declare a variable and add to it
> B. Only expressions that return a value are allowed. `name.toUpperCase()` is an expression that returns a value. `if`, `for`, `const` are statements — they don't return values, so they can't be embedded in JSX.

---

Q: What error appears when you try to return two sibling elements at once in JSX?
A. Multiple elements must be wrapped in an array format
B. Adjacent JSX elements must be wrapped in an enclosing tag
C. Two siblings cannot be returned from the same component function
D. Each JSX element needs a unique key identifier prop for rendering
> B. A JavaScript function can only return one value. Returning two `<h1>` and `<p>` elements at the same time = returning two values. You need to wrap them in a `<div>` or `<>` Fragment.

---

Q: What is the benefit of using a Fragment (`<>...</>`)?
A. It creates an extra wrapper node in the DOM for CSS styling and layout
B. It creates no extra element in the DOM — it only groups elements together
C. Fragments can only be used in TypeScript projects, not in plain JavaScript
D. Fragments only work in development mode, not in production builds
> B. `<>...</>` (Fragment) creates no extra element in the DOM. If you wrap elements in a `<div>`, an extra `<div>` appears in the DOM. When you don't need an extra wrapper for styling, use Fragment.

## TrueFalse

Q: JSX is directly understood by the browser — it doesn't need compilation.
- True
- False
> False. The browser does not understand JSX directly. Vite runs an esbuild compiler in the background that converts JSX into `React.createElement` calls. The browser only understands plain JavaScript.

---

Q: In JSX, `onclick` (lowercase) is correct, just like in HTML.
- True
- False
> False. HTML uses lowercase (`onclick`, `onkeydown`, `tabindex`), but JSX uses camelCase — `onClick`, `onKeyDown`, `tabIndex`. If you write `onclick`, TypeScript will throw an error because React's type system only expects JSX-style props.

---

Q: Inside JSX, you can only embed expressions, not statements.
- True
- False
> True. Expressions (like `name`, `2 + 3`, `name.toUpperCase()`) return a value and can be embedded in JSX. Statements (like `if`, `for`, `const`) don't return anything, so they can't be embedded.

---

Q: You can return multiple elements using `<>` Fragment without creating an extra DOM node.
- True
- False
> True. `<>` doesn't create an extra element in the DOM. If you inspect with developer tools, you'll only see the actual elements, no wrapper `<div>`. When you don't need an extra wrapper for styling, use `<>` instead of `<div>`.

## ShortAnswer

Q: What is JSX, and how does it work? Explain the full flow from writing code to rendering in the browser.

<details>
<summary>Sample Answer</summary>

**Answer:** JSX (JavaScript XML) is a syntax extension that looks like HTML, but under the hood it's just shorthand for `React.createElement` calls.

**Step-by-step flow:**

1. **Writing code:** You write JSX in `App.tsx` — like `<h1>Hello</h1>`.
2. **Compilation:** Vite (via esbuild) compiles JSX into `React.createElement`:
   - `<h1>Hello</h1>` → `React.createElement("h1", null, "Hello")`
3. **Virtual DOM node:** `React.createElement` returns a plain JavaScript object:
   - `{ type: 'h1', props: { children: 'Hello' } }` — this is the Virtual DOM node.
4. **Reconciliation:** React compares the Virtual DOM tree against the previous copy.
5. **Commit:** Only the parts that actually changed are applied to the real DOM.
6. **Browser render:** The real DOM updates, and the browser draws it on screen.

**Key point:** JSX is syntactic sugar — pleasant to write, but underneath, `React.createElement` is doing the real work.

</details>

Q: What are 4 differences between HTML and JSX? Explain with examples.

<details>
<summary>Sample Answer</summary>

**Answer:** Four main differences:

**1. `class` vs `className`:**
- HTML: `<h1 class="heading">Hello</h1>`
- JSX: `<h1 className="heading">Hello</h1>`
- Reason: `class` is a reserved keyword in JavaScript.

**2. `for` vs `htmlFor`:**
- HTML: `<label for="email">Email</label>`
- JSX: `<label htmlFor="email">Email</label>`
- Reason: `for` is also a reserved keyword in JavaScript.

**3. Self-closing tags:**
- HTML: `<br>` `<input>` — can go without being closed.
- JSX: `<br />` `<input />` — every tag must be closed with `/`.

**4. CamelCase attributes:**
- HTML: `onclick`, `onkeydown`, `tabindex` (lowercase)
- JSX: `onClick`, `onKeyDown`, `tabIndex` (camelCase)

**Bonus difference — JavaScript expressions:**
- In JSX, you can use `{ }` curly braces to embed JavaScript expressions: `{name}`, `{2 + 3}`, `{name.toUpperCase()}`. HTML has no such feature.

</details>
