# 1.3 — Props aur TypeScript Interface

## Abhi Tak Kya Hua

1.2 mein pehla component `ProfileCard` banaya. Export/import karna seekha, `JSX.Element` return type dekha, aur teen same cards render kiye. Problem: sab cards same data dikha rahe hain — "Vin, React Developer". Agar alag-alag log dikhane hain toh kya karna hai?

## Broader Goal

ProfileCard ko dynamic banana hai — taaki ek hi component har baar alag data ke saath render ho. Iske liye **Props** concept seekhenge. TypeScript mein props ke types kaise define karte hain (`interface`), aur component ko kaise type-safe banate hain — yeh sab clear ho jayega.

Greeting Card mini-project banayenge, phir is concept ko To-Do app mein use karenge.

## Step 1 — Problem Feel Karo

Soch: "Teen ProfileCard render kiye, sab same. Kya har card ke liye alag component banana padega?"

Agar alag data chahiye toh kya karna hoga?

```tsx
// Kya aise karna padega?
function VinCard() { return <div>Vin — React Developer</div>; }
function PriyaCard() { return <div>Priya — Designer</div>; }
function RajCard() { return <div>Raj — Backend Dev</div>; }
```

Yeh chhota example hai toh theek lag raha. Lekin 100 cards ke liye 100 components? Bilkul nahi. Isliye **props** chahiye — component ko data pass karne ka tarika.

## Step 2 — Props Kya Hai

**Concept:** Props = function arguments. Jis tarah ek function parameters leta hai, usi tarah component bhi parameters leta hai. Bas React mein unhe **props** kehte hain.

```tsx
// Normal function
function greet(name: string) {
  return `Hello, ${name}`;
}
greet("Vin");

// React component with props
function ProfileCard(props: { name: string; role: string }) {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>{props.role}</p>
    </div>
  );
}
<ProfileCard name="Vin" role="React Developer" />
```

Dekho — `<ProfileCard name="Vin" role="React Developer" />` likhne se React ek object banata hai `{ name: "Vin", role: "React Developer" }` aur yeh object `props` parameter ke through component mein jaata hai.

Ek component, alag-alag data. Isse kehte hain **component reusability**.

## Step 4 — TypeScript Interface for Props

Soch: "Props ka type abhi inline likha hai — `{ name: string; role: string }`. Yeh type component ke baahar bhi chahiye hoga (jaise App.tsx mein). Toh har jagah inline likhna padega?"

Kyun: Inline type theek hai ek baar ke liye. Lekin jab complex properties hongi ya type multiple jagah reuse karna hoga, toh **interface** use karte hain. 0.7 mein padha tha — interface ek object ka shape define karta hai.

`ProfileCard.tsx` mein `function` se pehle interface define karo:

```tsx
interface ProfileCardProps {
  name: string;
  role: string;
}

function ProfileCard(props: ProfileCardProps): JSX.Element {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>{props.role}</p>
    </div>
  );
}

export default ProfileCard;
```

Interface ka naam `ProfileCardProps` rakha. Yeh convention hai — component ke naam ke saath `Props` suffix. Interface props ka type define karta hai.

**Kya fark hua?** Same hi hai functionally. Lekin:

1. Type alag line mein hai — padhne mein aasan
2. Agar `ProfileCardProps` ko kahi aur import karna ho toh ready hai
3. Interface mein optional properties, default values, complex types — sab aa sakta hai

## Step 5 — Optional Props (Question Mark)

Soch: "Role sabke paas nahi bhi ho sakta. Kya main optional bana sakta hoon?"

**Concept:** Interface mein property ke baad `?` lagane se woh optional ho jaati hai. Agar pass nahi ki toh `undefined` hogi.

```tsx
interface ProfileCardProps {
  name: string;
  role?: string;
}

function ProfileCard(props: ProfileCardProps): JSX.Element {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>{props.role || "No role specified"}</p>
    </div>
  );
}
```

`role?` ka matlab — "yeh property ho bhi sakti hai aur nahi bhi". Agar nahi hai, toh fallback value do `"No role specified"`.

`App.tsx` mein:

```tsx
<ProfileCard name="Vin" role="React Developer" />
<ProfileCard name="Priya" /> {/* role optional hai, error nahi aayegi */}
```

## Step 6 — Destructuring Props

Soch: "Har baar `props.name`, `props.role` likhna repetitive lag raha hai. Kya shortcut hai?"

**Concept:** JavaScript destructuring — object ki properties ko directly variable mein nikaal sakte ho.

```tsx
interface ProfileCardProps {
  name: string;
  role?: string;
}

function ProfileCard({ name, role }: ProfileCardProps): JSX.Element {
  return (
    <div>
      <h2>{name}</h2>
      <p>{role || "No role specified"}</p>
    </div>
  );
}
```

Dekho — `function ProfileCard({ name, role }: ProfileCardProps)` — yeh props object ko destructure kar raha hai. Ab seedha `name` aur `role` use kar sakte ho, `props.` nahi likhna padta.

Destructuring React mein standard practice hai. Har professional component aise hi likhta hai.

## Step 7 — Mini-Project: Greeting Card Generator

Soch: "ProfileCard toh ban gaya. Ab ek **Greeting Card** component banate hain jo props ke through message aur recipient ka naam le."

Isme koi naya concept nahi — bas props ka practice hoga.

`src/components/GreetingCard.tsx`:

```tsx
interface GreetingCardProps {
  recipient: string;
  message: string;
  sender?: string;
}

function GreetingCard({ recipient, message, sender }: GreetingCardProps): JSX.Element {
  return (
    <div>
      <h2>Hello, {recipient}!</h2>
      <p>{message}</p>
      {sender && <p>— {sender}</p>}
    </div>
  );
}

export default GreetingCard;
```

`App.tsx` mein:

```tsx
import ProfileCard from "./components/ProfileCard";
import GreetingCard from "./components/GreetingCard";

function App() {
  return (
    <div>
      <h1>My App</h1>
      <ProfileCard name="Vin" role="React Developer" />
      <ProfileCard name="Priya" />
      <hr />
      <GreetingCard recipient="Vin" message="Happy Birthday!" sender="Priya" />
      <GreetingCard recipient="Team" message="Great work this week!" />
    </div>
  );
}
```

Dekho — component ka interface define karta hai ki kaunsa data required hai aur kaunsa optional. Agar required prop miss kiya:

```tsx
<GreetingCard message="Hello" /> // ❌ Error — 'recipient' is missing
```

TypeScript compile-time error dega. Isliye React + TypeScript powerful hai — bugs development mein hi catch ho jaate hain.

## Step 8 — To-Do App Ki Shuruaat

Soch: "Greeting Card ho gaya. Ab To-Do app ka structure sochte hain."

Abhi sirf ek `TaskInput` component banayenge — jo props leta hai ek `onAdd` function. Function ko props mein pass karna bhi seekhna hai.

`src/components/TaskInput.tsx`:

```tsx
interface TaskInputProps {
  onAdd: (text: string) => void;
}

function TaskInput({ onAdd }: TaskInputProps): JSX.Element {
  return (
    <div>
      <input type="text" placeholder="Add a task..." />
      <button onClick={() => onAdd("Sample task")}>Add</button>
    </div>
  );
}

export default TaskInput;
```

Abhi button sirf "Sample task" hi add karega — 1.5 mein actual input handling seekhenge.

`App.tsx` mein use karo:

```tsx
import TaskInput from "./components/TaskInput";

function App() {
  const handleAdd = (text: string) => {
    console.log("Adding task:", text);
  };

  return (
    <div>
      <h1>To-Do App</h1>
      <TaskInput onAdd={handleAdd} />
    </div>
  );
}
```

**Concept — Callback props:** Components parent se data nahi le sakte (sirf props ke through data aata hai). Lekin woh parent ko bata sakte hain ki "kuch hua" — callback function props ke through. Yahan `onAdd` ek callback hai — `TaskInput` call karega jab user add button dabayega, aur `App` (parent) us callback mein task add karega.

Browser console mein "Adding task: Sample task" print hoga har baar click karne par.

## Summary

- Props = function arguments for components — data pass karne ka tarika
- Inline type `{ name: string }` ya `interface ProfileCardProps` — interface prefer karo
- Optional props: `role?: string` — `?` lagao property ke baad
- Destructuring: `function Card({ name }: { name: string })` — standard practice
- Callback props: component parent ko event notify kar sakta hai (`onAdd`, `onClick`)
- Interface convention: `ComponentNameProps` — component ke naam ke saath Props suffix

Props samajh aa gaye. Agle chapter mein **children** prop aur **Composition** pattern dekhenge — ek component ke andar doosra component kaise wrap karte hain, aur layout components kaise banate hain. Yeh To-Do app ka structure banane ke liye zaroori hai.
