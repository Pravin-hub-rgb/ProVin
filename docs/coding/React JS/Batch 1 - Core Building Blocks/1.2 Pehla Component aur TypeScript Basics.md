# 1.2 — Pehla Component aur TypeScript Basics

## Abhi Tak Kya Hua

1.1 mein JSX samjha — yeh HTML nahi hai, `React.createElement` ka syntactic sugar hai. `className`, `htmlFor`, camelCase attributes, `{ }` expressions, aur single root element ka rule — sab clear hai. Browser abhi bhi `localhost:5173` dikha raha hai.

## Broader Goal

1.1 mein sirf `App.tsx` edit kiya tha. Ab ek naya component banayenge — apna khud ka **ProfileCard**. Samjhenge ki ek React component kaise likhte hain, export/import kaise karte hain, aur TypeScript component typing basics kya hote hain.

## Step 1 — Component Kya Hota Hai

Soch: "App.tsx mein ek function hai jo JSX return kar raha hai. Kya main aise aur functions bana sakta hoon?"

Kyun: Real app mein sab kuch `App.tsx` mein nahi likhte. Code ko chhote-chhote reusable pieces mein todna padta hai. React mein har piece ko **component** kehte hain.

**Concept:** React component sirf ek JavaScript function hai jiske do rules hain:

1. **Function ka naam capital letter se shuru hona chahiye** — `ProfileCard`, `Button`, `Header`
2. **Function JSX return karna chahiye** — jo bhi render karna hai

```
// ❌ Component nahi — lowercase se shuru
function profileCard() { return <div>...</div>; }

// ✅ Component hai — capital letter
function ProfileCard() { return <div>...</div>; }
```

Capital letter kyun? React ko pata hona chahiye ki yeh ek component hai, na ki koi regular HTML tag. `div` React samajhta hai "yeh HTML div tag hai". `ProfileCard` React samajhta hai "yeh mera custom component hai, ise render karo".

## Step 2 — ProfileCard Component Banao

Soch: "App.tsx ke andar ek naya function likh ke component bana sakta hoon ya alag file mein?"

Kyun: Chhote components ek file mein rakh sakte ho, lekin jab project bada hoga toh alag files mein rakhna padta hai. Abhi ek hi file mein banate hain, baad mein alag karenge.

`src/App.tsx` mein `App` function ke upar yeh naya function add karo:

```tsx
function ProfileCard() {
  const name = "Vin";
  const role = "React Developer";

  return (
    <div>
      <h2>{name}</h2>
      <p>{role}</p>
    </div>
  );
}

function App() {
  return (
    <div>
      <h1>My App</h1>
      <ProfileCard />
    </div>
  );
}
```

Dekho — `App` ke andar `<ProfileCard />` likha hai. Yehi tarika hai component ko use karne ka — bilkul HTML tag jaisa.

Browser check karo. Kya dikh raha hai?

```
My App
Vin
React Developer
```

Agar error aaye `'ProfileCard' is defined but never used` — toh ignore karo, yeh TypeScript warning hai. Next step mein fix ho jayega.

## Step 3 — Component Ko Alag File Mein Rakho

Soch: "Ek file mein do components theek hai, lekin professional projects mein ek file mein ek hi component rakhte hain na?"

Kyun: Yes. Har component ki apni file hoti hai. Isse code organize rahta hai, import/export clear hota hai, aur jab component bada hoga toh uski file alag se manage ho sakti hai.

`src/` folder mein ek naya folder banao `components/`. Usme `ProfileCard.tsx` file banao:

```tsx
function ProfileCard() {
  const name = "Vin";
  const role = "React Developer";

  return (
    <div>
      <h2>{name}</h2>
      <p>{role}</p>
    </div>
  );
}

export default ProfileCard;
```

Ab `src/App.tsx` mein import karo:

```tsx
import ProfileCard from "./components/ProfileCard";

function App() {
  return (
    <div>
      <h1>My App</h1>
      <ProfileCard />
    </div>
  );
}

export default App;
```

**Concept — Export/Import do types ke hote hain:**

1. **Default export:** `export default ProfileCard` → import: `import ProfileCard from "./file"`
2. **Named export:** `export { ProfileCard }` → import: `import { ProfileCard } from "./file"`

Abhi default export use karenge. Baad mein named export bhi dekhenge.

Browser refresh karo — same output aana chahiye. Kuch nahi badla, bas code organize ho gaya.

## Step 4 — TypeScript Component Typing

Soch: "Component ek function hai jo JSX return karta hai. TypeScript mein function ka return type kaise likhte hain?"

Kyun: 0.7 TypeScript Warm-up mein seekha tha — functions ka return type explicit likh sakte ho. React component ka return type `JSX.Element` hota hai.

`ProfileCard.tsx` mein return type add karo:

```tsx
function ProfileCard(): JSX.Element {
  const name = "Vin";
  const role = "React Developer";

  return (
    <div>
      <h2>{name}</h2>
      <p>{role}</p>
    </div>
  );
}

export default ProfileCard;
```

`JSX.Element` TypeScript ko batata hai ki yeh function JSX return karega. Agar galti se kuch aur return kiya toh error dega:

```tsx
function ProfileCard(): JSX.Element {
  return "Hello"; // ❌ Error — string JSX.Element nahi hai
}
```

> **Note:** React 19 ke saath `JSX.Element` ab global type hai (React import kiye bina). React 18 mein `React.ReactNode` ya `React.FC` use hota tha. React 19 mein `JSX.Element` standard hai.

## Step 5 — Multiple Components Banake Dekho

Soch: "Ek ProfileCard toh ban gaya. Kya main do ProfileCard ek saath use kar sakta hoon?"

`App.tsx` mein:

```tsx
import ProfileCard from "./components/ProfileCard";

function App() {
  return (
    <div>
      <h1>My Team</h1>
      <ProfileCard />
      <ProfileCard />
      <ProfileCard />
    </div>
  );
}

export default App;
```

Browser mein teen cards dikhenge — sab same "Vin" aur "React Developer" ke saath. Abhi sab static hai, lekin yeh component reusability ka concept hai. Agle chapter mein ise dynamic banayenge.

## Step 6 — Component Naming Convention

Soch: "File ka naam `ProfileCard.tsx` rakha. Kya convention hai?"

**Rules:**
- File name component ke naam ke jaisa — `ProfileCard` → `ProfileCard.tsx`
- Capital letter se file start karo (PascalCase)
- Extension `.tsx` (not `.ts`) — kyunki file mein JSX hai. Agar `.ts` rakhte toh TypeScript error aata

Yeh convention hai, rule nahi. Kuch log lowercase files rakhte hain (`profileCard.tsx`). Lekin React ecosystem mein PascalCase files standard hai.

## Step 7 — TypeScript Ka Type Inference

Soch: "Agar main return type nahi bhi likhoon, toh TypeScript error toh nahi deta?"

Try karo — `: JSX.Element` hatao. TypeScript error nahi dega.  

**Concept — Type Inference:** TypeScript automatically infer kar leta hai ki component `JSX.Element` return karega. Explicit return type optional hai. React developers mostly return type nahi likhte kyunki TypeScript infer kar leta hai.

Lekin jab koi naya concept seekh rahe ho, pehle explicit likhna achhi aadat hai — pata chalta hai ki actually kya return ho raha hai.

## Summary

- Component = function + capital letter + returns JSX
- `export default` + `import` se component reuse karo
- Components ko `components/` folder mein alag file mein rakho
- Return type: `JSX.Element` (TypeScript mostly infer kar leta hai)
- File naming: PascalCase with `.tsx` extension

## Agla Step

ProfileCard abhi static hai — har jagah same "Vin" dikha raha hai. Agle chapter mein **Props** seekhenge — component ko dynamic data pass karna taaki ek hi component alag-alag data ke saath reuse ho.
