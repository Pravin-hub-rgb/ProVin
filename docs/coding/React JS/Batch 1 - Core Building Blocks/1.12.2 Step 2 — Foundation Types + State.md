# 1.12.2 — Step 2: Foundation: Types + State

## Where We Left Off

We've decided the architecture (1.12.1). Now define the types and state.

First, define the types. What does a contact object look like? An id, name, phone, optional email, category, and a favorite flag. And a union type for the category filter.

**Why types first?** TypeScript needs to know the shape of the data. Everything else depends on it.

Create a `src/types.ts` file:

```ts
export type Category = "family" | "work" | "friend";

export interface Contact {
  id: number;
  name: string;
  phone: string;
  email?: string;        // optional — not every contact has an email
  category: Category;
  favorite: boolean;
}

export type CategoryFilter = "all" | Category;
```

Notice `email?: string` — the `?` makes it optional (from 1.5.3). And `CategoryFilter` reuses `Category` via union (`"all" | Category`).

**Now add state in App.tsx – one piece at a time:**

```tsx
import { useState } from "react";
import type { Contact } from "./types";

function App() {
  const [contacts, setContacts] = useState<Contact[]>([]);

  console.log("📋 App mounted. Contacts count:", contacts.length);
  console.log("📋 Contacts array:", contacts);

  return <div>Contact Book</div>;
}

export default App;
```

**Console check** – you'll see `[]` and `length: 0`. No contacts yet. The state type is `Contact[]` — TypeScript enforces that the array only holds `Contact` objects.
