
## MCQ

Q: After running `npm create vite@latest`, which is the most important file the browser loads directly?
A. `main.tsx` — React's entry point where the component tree starts rendering
B. `index.html` — the browser parses this first, then loads the script
C. `App.tsx` — the root component that defines the app layout
D. `package.json` — config for dependencies and scripts, needed for builds
> B. `index.html` is the real entry point. The browser loads it first, finds `<div id="root">`, then loads the `<script src="/src/main.tsx">`. `main.tsx` is React's entry point, not the browser's.

Q: In `main.tsx`, what does the `!` mean in `createRoot(document.getElementById('root')!)`?
A. TypeScript is assured that the element is not null — non-null assertion
B. JavaScript's logical NOT operator — flipping the root element
C. Forces the DOM to create the element if it doesn't exist
D. React ignores the signal — no action on root element
> A. The `!` is TypeScript's non-null assertion operator. `document.getElementById('root')` can return `null`. The `!` tells TypeScript: "I know this won't be null" — because we created the `#root` div in `index.html`.

---

Q: What does `createRoot` return, and what happens next?
A. An HTTP server that serves the app on port 5173
B. A Root object with a `.render()` method that mounts to the DOM
C. A CSS stylesheet that replaces `index.css`
D. A callback function called on every state change
> B. `createRoot` creates a React Root object. Through this Root, React manages the Virtual DOM inside `#root`. Calling `.render(<App />)` makes React convert the component tree to Virtual DOM, then to Real DOM, and mount it.

Q: What connects `main.tsx` to `App.tsx`?
A. `main.tsx` includes `App.tsx` via a `<script>` tag in the HTML
B. `main.tsx` imports the CSS from `App.tsx` for styling
C. `main.tsx` imports `App.tsx` and uses it in `createRoot().render()`
D. `App.tsx` imports `main.tsx` — the connection is reversed
> C. In `main.tsx`, there's `import App from './App.tsx'`. Then `createRoot(...).render(<App />)` — App becomes the root component where all other components render.

Q: Why is `App.tsx` called the root component?
A. It renders first and all other components are inside it
B. It's the smallest file — "root" means smallest
C. It has no imports — it's a self-contained component
D. It only renders on the server side — root server component
> A. `App.tsx` is the root component because `createRoot().render(<App />)` renders `App` first. Inside `App`, components like `Header`, `MainContent`, `Footer` are rendered. The top of the component tree is always `App`.

Q: What does the `<StrictMode>` wrapper do in React?
A. Enables TypeScript strict mode — type checking becomes stricter
B. Runs extra development checks — catching potential bugs
C. Applies CSS strict mode — forcing inline styles
D. Optimizes the production build — reducing bundle size
> B. `<StrictMode>` runs extra side-effect checks and warnings in development — like double-invoking reducers, unmount checks. In production, it does nothing extra. Its job is to make you aware of potential bugs.

Q: What does Vite's Hot Module Replacement (HMR) do?
A. Reloads the entire page on every code change
B. Replaces only the changed component — state is preserved
C. Rebuilds the project every 5 seconds
D. Automatically opens a new browser tab when the project starts
> B. HMR means when you change code, Vite recompiles only the changed file and sends an update to the browser. Only the affected part updates — no full page reload, and state is preserved.

Q: In Vite setup, `index.html` is visible and you call `createRoot` yourself. How is this different from Next.js?
A. Next.js doesn't need `index.html` — React runs in the browser without setup
B. Next.js abstracts `index.html` — `createRoot` is handled by the framework
C. Next.js uses `app.html` instead — `createApp` is the function
D. Next.js doesn't use React — it's an Angular-based framework
> B. Next.js abstracts away what Vite makes visible. `index.html` is internally managed — you never see it. `createRoot` is also handled by the framework. You just create an `app/page.tsx` file and routing is automatic from folder structure.

Q: What happens if you remove `export default App` from `App.tsx`?
A. Nothing — React automatically detects the App component
B. `main.tsx`'s import fails — no default export found
C. App renders but errors stay silent — no warnings
D. Vite automatically adds a default export if you forget
> B. Without a default export, the import fails. `import App from './App.tsx'` expects a default export. You'd get an error — "Module has no default export." This isn't React-specific — it's a JavaScript/TypeScript module rule.

Q: What is the purpose of `vite-env.d.ts`?
A. Defines Vite's environment variables — a replacement for `.env`
B. Tells TypeScript about Vite's specific types — `import.meta.env`, CSS imports, assets
C. Configures the Vite dev server — port and proxy settings
D. Suppresses all TypeScript errors in the project for easier debugging
> B. `vite-env.d.ts` is a TypeScript declaration file. It contains Vite-specific types — like the type of `import.meta.env`, types for `.css` imports, and types for image asset imports. Without it, TypeScript wouldn't understand these Vite-specific imports.

## TrueFalse

Q: `index.html` is called the "real entry point" because the browser loads it first. `main.tsx` is not the browser's entry point because the browser can't parse TypeScript/JSX directly.
- True
- False
> True. The browser loads `index.html` first. `main.tsx` contains TypeScript and JSX that the browser can't execute directly — Vite compiles it into browser-compatible JavaScript. `index.html` includes a `<script>` tag that loads the compiled `main.tsx`.

---

Q: `index.html` is optional in a Vite + React project — Vite generates it automatically.
- True
- False
> False. `index.html` is required. Without it, the browser has nothing to load. `index.html` defines the `<div id="root">` and includes the script that loads the React app. (Next.js abstracts this away — you don't see `index.html` — but in Vite + React, it's visible and editable.)

---

Q: You can call `createRoot` on multiple DOM elements — multiple independent React apps can run on the same page.
- True
- False
> True. `createRoot` can be called on any DOM element. If you have `<div id="root1">` and `<div id="root2">`, you can call `createRoot` on both. They become independent React apps — not connected to each other. This pattern is used in micro-frontend architectures.

---

Q: With HMR, the entire page reloads when code changes so the new code takes effect.
- True
- False
> False. HMR's whole point is that the page does NOT reload. Only the changed module is replaced and the browser updates — the current state (form inputs, scroll position) is preserved. Full reload only happens when HMR can't handle the change (like CSS in some setups).

---

Q: After running `npm run dev`, Vite pre-compiles all `.tsx` files and keeps them ready on the server for instant serving.
- True
- False
> False. Vite's dev server uses on-demand compilation. When the browser requests a file, Vite compiles that file at that moment. Pre-compiling is not needed. This is why Vite is fast regardless of project size — it only compiles what's requested. (Production builds with `npm run build` do pre-compile.)

---

Q: Traditional React (Vite) and Next.js both use the same React concepts — components, props, state, hooks. Only the setup differs.
- True
- False
> True. No matter which framework or build tool you use, React's core concepts remain the same. Components, props, state, hooks — all identical. Only the project setup, routing approach, and build process differ. Vite requires manual configuration; Next.js abstracts it away.

## ShortAnswer

Q: Explain the full pipeline from `npm run dev` to the page showing up in the browser. What happens at each step?

<details>
<summary>Sample Answer</summary>

```
npm run dev
    ↓
Vite dev server starts (port 5173)
    ↓
Browser requests index.html
    ↓
Server serves index.html
    ↓
Browser parses HTML — finds <div id="root">
    ↓
Browser finds <script type="module" src="/src/main.tsx">
    ↓
Browser requests the script
    ↓
Vite compiles main.tsx (TypeScript/JSX → browser JS)
    ↓
Vite also compiles all imports recursively
    (App.tsx, index.css, etc.)
    ↓
Transformed code reaches the browser
    ↓
JavaScript executes:
  1. createRoot(document.getElementById('root')!) — creates React Root
  2. .render(<StrictMode><App /></StrictMode>) — renders App
    ↓
React builds Virtual DOM from the component tree
    ↓
Virtual DOM → Real DOM conversion
    ↓
Real DOM inserted into <div id="root">
    ↓
Browser renders to screen
    ↓
HMR is ready — code changes update only the affected part
```

</details>

Q: How are `index.html`, `main.tsx`, and `App.tsx` connected? Explain each file's role and visualize the connection.

<details>
<summary>Sample Answer</summary>

**Connection chain:**
```
index.html → main.tsx → App.tsx → Browser screen
```

**Each file's role:**

1. **`index.html`** — The browser's entry point.
   - Defines `<div id="root">` — where React injects content
   - Includes `<script type="module" src="/src/main.tsx">` to load the script
   - This is the first file the browser loads

2. **`main.tsx`** — React's entry point.
   - `import App from './App.tsx'` — imports the App component
   - `createRoot(document.getElementById('root')!)` — connects React to the DOM
   - `.render(<App />)` — mounts App as the root component

3. **`App.tsx`** — The root component.
   - `function App() { return ( JSX ) }` — defines the component
   - `export default App` — allows `main.tsx` to import it
   - All other components render inside App

**Visual connection:**
```
index.html
  │ <script src="/src/main.tsx">
  ▼
main.tsx
  │ import App from './App.tsx'
  │ createRoot(...).render(<App />)
  ▼
App.tsx
  │ export default App
  │ function App() { return ( <div>...</div> ) }
  ▼
Virtual DOM → Real DOM → Screen
```

If any link in this chain breaks (e.g., `index.html` has no `<div id="root">`, or `App.tsx` has no default export), the app won't work.

</details>
