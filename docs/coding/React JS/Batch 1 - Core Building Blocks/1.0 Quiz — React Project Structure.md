# 1.0 Quiz — React Project Structure

## MCQ

Q: `npm create vite@latest` ke baad project folder mein sabse important file kaun si hai jo browser directly load karta hai?
A. `main.tsx` — React ka entry point, yahin se component tree render shuru hota hai
B. `index.html` — browser sabse pehle ise parse karta hai, script load hoti hai
C. `App.tsx` — root component jisme poore app ka layout define hota hai
D. `package.json` — dependencies aur scripts ka config, build ke liye zaroori
> B. `index.html` asli entry point hai. Browser pehle `index.html` load karta hai, `<div id="root">` dekhta hai, phir `<script src="/src/main.tsx">` download karta hai. `main.tsx` React ka entry point hai, browser ka nahi.

---

Q: `main.tsx` mein `createRoot(document.getElementById('root')!)` mein `!` ka kya matlab hai?
A. TypeScript ko assurance deta hai ki element null nahi hoga — non-null assertion
B. JavaScript ka logical NOT operator hai — root element ko flip kar raha hai
C. DOM element ko forcefully create karta hai — nahi mila to bana deta hai
D. React ko ignore signal hai — root element par koi action mat lo
> A. `!` TypeScript ka non-null assertion operator hai. `document.getElementById('root')` `null` return kar sakta hai. `!` TypeScript se keh raha hai "mujhe pata hai yeh null nahi hoga" — kyunki humne khud `index.html` mein `div#root` banaya hai.

---

Q: `createRoot` function kya return karta hai aur uske baad kya hota hai?
A. Ek HTTP server return karta hai jo port 5173 par app serve karta hai
B. Ek Root object return karta hai jisme `.render()` method hota hai jo DOM mein mount karta hai
C. Ek CSS stylesheet return karta hai jo `index.css` ko replace kar deti hai
D. Ek callback function return karta hai jo har state change par call hota hai
> B. `createRoot` ek React Root object banata hai. Is Root ke through React `div#root` ke andar Virtual DOM manage karta hai. `.render(<App />)` call karne se React component tree ko Virtual DOM mein convert karta hai, phir real DOM mein render karta hai.

---

Q: `main.tsx` aur `App.tsx` ka kya connection hai?
A. `main.tsx` `App.tsx` ko `<script>` tag se HTML mein include karta hai
B. `main.tsx` `createRoot` se `App.tsx` ka CSS import karta hai styling ke liye
C. `main.tsx` `App.tsx` ko import karta hai aur `createRoot().render()` mein use karta hai
D. `App.tsx` `main.tsx` ko import karta hai — connection ulti taraf hai
> C. `main.tsx` mein `import App from './App.tsx'` hota hai. Phir `createRoot(...).render(<App />)` — App component root ban jaata hai jisme baaki saare components render hote hain.

---

Q: Component tree mein `App.tsx` ko root component kyun kehte hain?
A. Kyunki `App.tsx` sabse pehle render hota hai aur baaki components iske andar hote hain
B. Kyunki `App.tsx` ki file size sabse chhoti hoti hai — root matlab smallest file
C. Kyunki `App.tsx` mein koi imports nahi hote — yeh self-contained component hai
D. Kyunki `App.tsx` sirf server-side render hota hai — root server component hai
> A. `App.tsx` root component hai kyunki `createRoot().render(<App />)` sabse pehle `App` render karta hai. `App` ke andar `Header`, `MainContent`, `Footer` jaise components hote hain. Component tree ka top `App` hi hota hai.

Q: `<StrictMode>` wrapper React mein kya karta hai?
A. TypeScript strict mode enable karta hai — type checking strict ho jaati hai
B. Development mein extra checks chalta hai — potential bugs detect karta hai
C. CSS strict mode apply karta hai — inline styles ko force karta hai
D. Production build optimize karta hai — bundle size reduce ho jaati hai
> B. `<StrictMode>` development mein extra side-effect checks aur warnings provide karta hai — jaise double-invocation of reducers, unmount checks. Production build kuch nahi karta extra. Iska kaam hai tumhe potential bugs se aware karna.

Q: Vite ka Hot Module Replacement (HMR) kya karta hai?
A. Code change par poora page reload karta hai — refresh programmatically hota hai
B. Code change par sirf changed component update hota hai — state preserve rehti hai
C. Har 5 second mein project rebuild karta hai — chahe code change hua ho ya nahi
D. Naya browser tab automatically kholta hai jab project start hota hai
> B. HMR ka matlab hai — jab tum code change karte ho, Vite sirf change hue file ko recompile karta hai aur browser ko update bhejta hai. Poore page ki jagah sirf affected part update hota hai. State bhi preserve rehti hai (component unmount nahi hota).

Q: Vite setup mein `index.html` visible hota hai aur tum `createRoot` khud call karte ho. Next.js mein yeh kaise different hai?
A. Next.js mein kuch nahi hota — React browser mein bina setup ke run hota hai
B. Next.js mein `index.html` abstract hota hai — `createRoot` framework handle karta hai
C. Next.js mein `index.html` ki jagah `app.html` hota hai — `createApp` function use hota hai
D. Next.js bina React ke chalata hai — yeh Angular-based framework hai
> B. Next.js traditional React (Vite) ko abstract kar leta hai. `index.html` internally manage hota hai — tumhe dikhta nahi. `createRoot` bhi framework handle karta hai. Tum bas `app/page.tsx` file banate ho aur routing automatically folder structure se create hoti hai.

---

Q: `export default App` `App.tsx` mein se hata do to kya hoga?
A. Kuch nahi — React automatically App component detect kar leta hai
B. `main.tsx` ka import fail ho jayega — default export missing hai
C. App component render hoga lekin errors silent rahenge — koi warning nahi
D. Vite automatic default export add kar dega agar bhool gaya to
> B. Default export nahi hai to import fail ho jayega. `import App from './App.tsx'` default export expect karta hai. Error aayegi — "Module has no default export." React se koi connection nahi, yeh pure JavaScript/TypeScript module system ka rule hai.

---

Q: `vite-env.d.ts` file ka kya role hai?
A. Vite ki environment variables define karta hai — `.env` file ka replacement hai
B. TypeScript ko Vite ke types batata hai — `import.meta.env`, CSS imports, assets
C. Vite ka dev server configuration hota hai — port aur proxy settings yahin hain
D. Project ke saare TypeScript errors suppress kar deta hai — debugging ke liye
> B. `vite-env.d.ts` ek type declaration file hai. Isme Vite-specific types hote hain — jaise `import.meta.env` ka type, `.css` import ka type, image asset import ka type. Iske bina TypeScript Vite-specific imports ko samajh nahi payega.

## TrueFalse

Q: `index.html` ko "real entry point" kaha jaata hai kyunki browser sabse pehle ise load karta hai. `main.tsx` browser ka entry point nahi hai kyunki browser TypeScript/JSX directly nahi samajhta.
- True
- False
> True. Browser directly `main.tsx` load nahi kar sakta — TypeScript aur JSX ko browser-compatible JavaScript mein compile karna padta hai (Vite yeh karta hai). `index.html` ek `<script>` tag ke through `main.tsx` ko include karta hai. Browser ka entry point `index.html` hai.

---

Q: `index.html` Vite + React project mein optional hai — framework automatically generate kar leta hai.
- True
- False
> False. `index.html` mandatory hai. Iske bina browser ko kuch serve nahi hoga. `index.html` hi woh file hai jo `<div id="root">` define karta hai aur `<script>` tag ke through React app load karta hai. Next.js mein `index.html` abstract hota hai visible nahi — lekin internally exist karta hai. Vite + React mein yeh visible hai aur editable hai.

---

Q: `createRoot` ek se zyada DOM elements mein call kar sakte hain — ek page mein do alag React apps independent chal sakti hain.
- True
- False
> True. `createRoot` kisi bhi DOM element ko React ka anchor point bana sakta hai. Ek page mein `<div id="root1">` aur `<div id="root2">` dono par `createRoot` call kar sakte ho. Dono independent React apps honge — ek doosre se connected nahi. Micro-frontend architecture mein yeh pattern use hota hai.

---

Q: HMR (Hot Module Replacement) mein code change karne ke baad poora page reload hota hai taake naye changes reflect ho.
- True
- False
> False. HMR ka fayda yehi hai ki poora page reload nahi hota. Sirf change hue component ka module replace hota hai aur browser update ho jaata hai. Isse state preserve rehti hai aur developer experience fast hota hai. Full reload sirf tab hota hai jab HMR possible nahi (jaaye CSS change ho).

---

Q: `npm run dev` chalane ke baad Vite sabhi `.tsx` files ko pehle se compile karke server par ready rakhta hai instant serve ke liye.
- True
- False
> False. Vite dev server **on-demand compilation** karta hai. Jab browser koi file request karta hai tab Vite us file ko compile karta hai — pehle se nahi. Isliye Vite itna fast hai — project size matter nahi karta. Production build (`npm run build`) mein pehle se compile hota hai.

---

Q: Traditional React (Vite) aur Next.js dono mein component tree ka concept same hai — dono mein props, state, aur components hote hain.
- True
- False
> True. Framework chahe koi bhi ho — React ka core concept same hai. Components, props, state, hooks — sab same hain. Sirf setup, routing, aur build process ka tareeka different hai. Vite mein manual setup hai, Next.js mein abstracted. Lekin ek baar component likhne ke baad dono mein same tarah kaam karta hai.

## ShortAnswer

Q: `npm run dev` se lekar browser mein page dikhne tak poor pipeline step by step explain karo. Har step mein kya hota hai?

<details>
<summary>Sample Answer</summary>

```
npm run dev
    ↓
Vite dev server start (port 5173)
    ↓
Browser `index.html` request karta hai
    ↓
Server `index.html` serve karta hai
    ↓
Browser HTML parse karta hai — `<div id="root">` dikhta hai
    ↓
`<script type="module" src="/src/main.tsx">` milta hai
    ↓
Browser script request karta hai
    ↓
Vite `main.tsx` compile karta hai (TypeScript/JSX → browser JS)
    ↓
Vite recursively `main.tsx` ke saare imports bhi compile karta hai
    (App.tsx, index.css, etc.)
    ↓
Transformed code browser tak pahunchta hai
    ↓
JavaScript execute hota hai:
    1. `createRoot(document.getElementById('root')!)` — React Root banata hai
    2. `.render(<StrictMode><App /></StrictMode>)` — App component render karta hai
    ↓
React component tree se Virtual DOM banata hai
    ↓
Virtual DOM → Real DOM conversion
    ↓
Real DOM `<div id="root">` ke andar insert hota hai
    ↓
Browser screen pe render karta hai
    ↓
Ab HMR ready hai — code change par sirf changed part update
```

</details>

Q: `index.html`, `main.tsx`, aur `App.tsx` — teeno files kaise connected hain? Har file ka specific role explain karo aur chain ka visualize karo.

<details>
<summary>Sample Answer</summary>

**Chain:**
```
index.html  ──→  main.tsx  ──→  App.tsx  ──→  Browser Screen
```

**Har file ka role:**

1. **`index.html`** — Browser ka entry point.
   - `<div id="root"></div>` define karta hai — yahan React apna content daalega
   - `<script type="module" src="/src/main.tsx">` — script load karta hai
   - Browser ke liye yeh first file hai jo serve hoti hai

2. **`main.tsx`** — React ka entry point.
   - `createRoot(document.getElementById('root')!)` — React ko DOM se jodta hai
   - `.render(<App />)` — App component ko React root mein mount karta hai
   - `import App from './App.tsx'` — App component ko import karta hai
   - Iska poora kaam: React ko start karna aur App ko render karna

3. **`App.tsx`** — Root component.
   - `function App() { return ( JSX ) }` — component define karta hai
   - `export default App` — `main.tsx` import kar sake isliye export
   - Baaki saare components App ke andar render hote hain
   - Component tree ka top level hai

**Visual connection:**
```
index.html
  │ <script src="/src/main.tsx">
  ▼
main.tsx
  │ import App from './App.tsx'
  │ createRoot(...).render(<App />)
  ▼
App.tsx
  │ export default App
  │ function App() { return ( <div>...</div> ) }
  ▼
Virtual DOM → Real DOM → Screen
```

Agar chain ka ek bhi link toota (jaise `index.html` mein `<div id="root">` nahi, ya `App.tsx` export nahi kiya), to app nahi chalega.

</details>
