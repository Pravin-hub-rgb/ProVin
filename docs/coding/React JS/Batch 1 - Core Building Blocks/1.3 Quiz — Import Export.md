
## MCQ

Q: Why is JavaScript's module system needed?
A. Each file has its own scope — variables aren't accessible across files automatically
B. The browser uses the module system to render HTML files alongside React
C. Loops and conditionals only work inside modules in JavaScript
D. The module system automatically links CSS styles with components
> A. Each file has its own scope — a variable defined in `data.ts` isn't accessible in `App.tsx` directly. The module system (`export`/`import`) solves this problem.

Q: Which is the correct syntax for a named export?
A. `export default const name = "Vin"` — the standard way to do a default named export
B. `export { name }` — a separate export block, or inline as `export const name`
C. `module.exports = { name }` — Node.js style, also used in React
D. `exports.name = "Vin"` — CommonJS syntax that's standard in React
> B. Named export can be done two ways: inline (`export const name = "Vin"`) or separately (`export { name }`). Both accomplish the same thing.

Q: When using named imports, how must the name match?
A. The imported name must exactly match the exported name
B. The imported name must be uppercase even if the export was lowercase
C. The imported name can be anything — the file auto-maps
D. The imported name must be the reverse of the exported name
> A. Named imports require exact name matching — to import `export const name = "Vin"`, you write `import { name }`. `import { userName }` won't work.

---

Q: Which is the correct syntax for a default export?
A. `export default const appTitle = "ProVin"` — declare and export in one line
B. `const appTitle = "ProVin"; export default appTitle` — declare, then export
C. `export const default appTitle = "ProVin"` — const with default export
D. `default export const appTitle = "ProVin"` — default keyword comes first
> B. `export default const` is a syntax error because `export default` expects an expression, not a declaration. Declare the variable first, then `export default variableName`.

---

Q: How many default exports can a file have?
A. Only one — one default export per file is allowed
B. Two — one for a variable and one for a function
C. As many as you want — there's no limit on default exports
D. Zero — React doesn't use default exports, only named
> A. Only one default export per file is allowed. But named exports have no limit — a file can have one default + multiple named exports.

---

Q: What is the correct syntax to import both default and named exports together?
A. `import ProfileCard from "./ProfileCard"` on one line and `import { ProfileImage } from "./ProfileCard"` on another
B. `import ProfileCard, { ProfileImage, MAX_CARDS } from "./ProfileCard"`
C. `import { ProfileCard, ProfileImage, MAX_CARDS } from "./ProfileCard"`
D. `import * as ProfileCard from "./ProfileCard"` — import everything at once
> B. Default imports have no curly braces; named imports use curly braces. Both can be on one line: `import X, { Y, Z } from "./file"`.

Q: What does `import type` give you?
A. TypeScript also type-checks at runtime, improving performance
B. The bundler knows it's type-only — it's excluded from the runtime bundle
C. Imported values automatically become immutable with `import type`
D. TypeScript type checking becomes faster at compile time
> B. `import type` signals to the bundler (Vite) that this is a type-only import, not a runtime value. Types are stripped at compile time, so they're excluded from the production bundle — reducing bundle size.

---

Q: What does the `as` keyword do in imports?
A. Automatically makes imported values async
B. Renames an import to resolve naming conflicts
C. Automatically sorts imported files alphabetically
D. Lazy-loads imports only when needed
> B. The `as` keyword renames imports — `import { greet as greetFromUtils } from "./utils"`. Use it when two files both export something with the same name.

## TrueFalse

Q: `export default const appTitle = "ProVin"` — this syntax is valid.
- True
- False
> False. `export default` is followed by an expression, not a declaration. `const` is a declaration, not an expression. Declare the variable first (`const appTitle = "ProVin"`), then export it on a separate line with `export default appTitle`.

Q: When using default imports, the name must match exactly what was exported.
- True
- False
> False. Default import names are your choice. `export default appName` can be imported as `import myName from "./config"` or `import anything from "./config"` — both work. But convention is to keep the same name as the component/file.

## ShortAnswer

Q: What is the difference between named export and default export? Explain with examples.

<details>
<summary>Sample Answer</summary>

**Named Export:**
- Syntax: `export const name = "Vin"` or `export function greet() {}`
- Import: `{ name }` — the name must match exactly
- Per file: Multiple (no limit)
- Use case: Utility functions, constants, types, multiple exports

**Default Export:**
- Syntax: `const app = "ProVin"; export default app` or `export default "ProVin"`
- Import: `app` or `anything` — you choose the name, no curly braces
- Per file: Only one
- Use case: The main component of a file, the main class

**Example:**
```tsx
// ProfileCard.tsx — default + named exports
export default function ProfileCard() {
  return <div>Profile</div>;
}
export const MAX_CARDS = 10;

// App.tsx — import both
import ProfileCard, { MAX_CARDS } from "./ProfileCard";
```

</details>

Q: How do you export and import a React component? Explain the full flow from creating a component file to using it.

<details>
<summary>Sample Answer</summary>

**Flow — from creating a component to using it:**

**Step 1 — Create the component file:** `ProfileCard.tsx`
```tsx
function ProfileCard() {
  return <div>Hello from ProfileCard</div>;
}
export default ProfileCard;
```

**Step 2 — Import it:** in `App.tsx`
```tsx
import ProfileCard from "./ProfileCard";
```

**Step 3 — Use it:** as a JSX tag
```tsx
function App() {
  return (
    <div>
      <h1>My App</h1>
      <ProfileCard />
    </div>
  );
}
export default App;
```

**Key points:**
- Component files export one component → `export default` is perfect
- Match the file name to the component name — `ProfileCard.tsx` → `ProfileCard`
- Default import names are your choice, but convention says keep the same name
- `./` means "current folder" — relative path
- File extensions (`.tsx`, `.ts`) aren't needed in import paths

</details>
