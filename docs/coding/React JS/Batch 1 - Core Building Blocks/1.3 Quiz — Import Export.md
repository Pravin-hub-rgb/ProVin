# 1.3 Quiz — Import Export

## MCQ

Q: JavaScript module system ki zaroorat kyun padti hai?
A. Har file ka apna scope hota hai — variables automatically accessible nahi hote
B. Browser HTML files ko render karne ke liye module system ka use karta hai
C. JavaScript mein loops aur conditions sirf modules mein kaam karte hain
D. Module system CSS styles ko components ke saath automatically link karta hai
> A. Browser mein har file ka apna scope hota hai — `data.ts` mein bana variable `App.tsx` mein directly accessible nahi hota. Module system (`export`/`import`) is problem ko solve karta hai.

---

Q: Named export ka sahi syntax kaunsa hai?
A. `export default const name = "Vin"` — default named export ka standard tarika
B. `export { name }` — alag se export block, ya inline `export const name`
C. `module.exports = { name }` — Node.js style, React mein bhi yahi use hota hai
D. `exports.name = "Vin"` — CommonJS syntax jo React mein standard hai
> B. Named export do tarah se ho sakta hai: inline — `export const name = "Vin"`, ya alag se — `export { name }`. Dono same kaam karte hain.

---

Q: Named import karte waqt naam kaise match karna chahiye?
A. Import ka naam export ke naam se exactly match karna chahiye
B. Import ka naam uppercase mein likhna padta hai chahe export lowercase ho
C. Import ka naam kuch bhi ho sakta hai — file automatically map ho jaati hai
D. Import ka naam export ke naam ka reverse likhna padta hai
> A. Named import mein naam exactly match karna padta hai — `export const name = "Vin"` ko `import { name }` se hi laana hoga. `{ userName }` se nahi chalega.

---

Q: Default export ka sahi syntax kaunsa hai?
A. `export default const appTitle = "ProVin"` — ek line mein declare aur export
B. `const appTitle = "ProVin"; export default appTitle` — alag line mein export
C. `export const default appTitle = "ProVin"` — const ke saath default export
D. `default export const appTitle = "ProVin"` — default keyword pehle aata hai
> B. `export default const` syntax error hai kyunki `export default` ke baad expression aata hai, declaration nahi. Pehle variable declare karo, phir `export default variableName` likho.

---

Q: Ek file mein kitne default exports ho sakte hain?
A. Sirf ek — default export per file sirf ek allowed hai
B. Do — ek variable ke liye aur ek function ke liye
C. Jitne chahe utne — default export ki koi limit nahi hai
D. Zero — React mein default export use nahi karte sirf named use karte hain
> A. Per file sirf ek default export allowed hai. Lekin named exports ki koi limit nahi — ek file mein ek default + multiple named exports ho sakte hain.

---

Q: Default aur named exports ek saath import karne ka sahi syntax kya hai?
A. `import ProfileCard from "./ProfileCard"` aur alag line mein `import { ProfileImage } from "./ProfileCard"`
B. `import ProfileCard, { ProfileImage, MAX_CARDS } from "./ProfileCard"`
C. `import { ProfileCard, ProfileImage, MAX_CARDS } from "./ProfileCard"`
D. `import * as ProfileCard from "./ProfileCard"` — saare imports ek sath
> B. Default import bina curly braces ke, named imports curly braces ke saath. Ek line mein dono combine ho sakte hain — `import X, { Y, Z } from "./file"`.

---

Q: `import type` ka kya fayda hai?
A. TypeScript ko runtime mein bhi types check karne deta hai isse performance better hoti hai
B. Bundler ko pata chal jaata hai ki yeh sirf type hai — runtime bundle mein include nahi hota
C. `import type` se import ki hui values automatically immutable ho jaati hain
D. `import type` se TypeScript ki type checking fast ho jaati hai compile time kam lagta hai
> B. `import type` bundler (Vite) ko batata hai ki yeh sirf type hai, runtime value nahi. Isse production bundle ka size kam hota hai kyunki types bundle mein include nahi hote.

---

Q: `as` keyword import mein kya kaam karta hai?
A. Import ki hui value ko automatically async bana deta hai
B. Import ka naam change karta hai taaki naam conflict resolve ho sake
C. Import ki hui file ko automatically sort karta hai alphabetical order mein
D. Import ko lazy load karta hai jab zaroorat ho tabhi fetch hota hai
> B. `as` keyword import rename karta hai — `import { greet as greetFromUtils } from "./utils"`. Jab do alag files mein same naam export ho, tab name conflict resolve karne ke liye use hota hai.

## TrueFalse

Q: `export default const appTitle = "ProVin"` — yeh syntax valid hai.
- True
- False
> False. `export default` ke baad expression aata hai, declaration nahi. `const` declaration hai, expression nahi. Pehle variable declare karo (`const appTitle = "ProVin"`), phir alag line mein `export default appTitle` likho.

---

Q: Default import karte waqt naam exactly wahi hona chahiye jo export kiya tha.
- True
- False
> False. Default import ka naam tum khud choose kar sakte ho. `export default appName` ko `import myName from "./config"` ya `import anything from "./config"` — dono chalega. Lekin convention hai ki component/file ka wahi naam rakho.

---

Q: Ek file mein multiple default exports ho sakte hain — sirf syntax alag hota hai.
- True
- False
> False. Per file sirf ek default export allowed hai. Lekin nombed exports ki koi limit nahi hai — ek file mein ek default + jitne chahe utne named exports ho sakte hain.

---

Q: `import type` ka use karne se production bundle ka size kam ho sakta hai.
- True
- False
> True. `import type` bundler (Vite) ko batata hai ki yeh sirf TypeScript type hai, runtime value nahi. Types compile time ke baad hat jaate hain, isliye bundle mein include nahi hote. Isse production bundle ka size kam hota hai.

## ShortAnswer

Q: Named export aur Default export mein kya fark hai? Examples ke saath explain karo.

<details>
<summary>Sample Answer</summary>

**Named Export:**
- Syntax: `export const name = "Vin"` ya `export function greet() {}`
- Import: `{ name }` — naam exactly match karna padta hai
- Per file: Multiple (koi limit nahi)
- Use case: Utility functions, constants, types, multiple exports

**Default Export:**
- Syntax: `const app = "ProVin"; export default app` ya `export default "ProVin"`
- Import: `app` ya `anything` — naam tum choose karte ho, curly braces nahi
- Per file: Sirf ek
- Use case: Main component of a file, main class

**Example:**
```tsx
// ProfileCard.tsx — default + named exports
export default function ProfileCard() {
  return <div>Profile</div>;
}
export const MAX_CARDS = 10;

// App.tsx — import both
import ProfileCard, { MAX_CARDS } from "./ProfileCard";
```

</details>

Q: React component ko export/import kaise karte hain? Ek component file se lekar use karne tak ka poora flow explain karo.

<details>
<summary>Sample Answer</summary>

**Flow — component create se lekar use tak:**

**Step 1 — Component file banayein:** `ProfileCard.tsx`
```tsx
function ProfileCard() {
  return <div>Hello from ProfileCard</div>;
}
export default ProfileCard;
```

**Step 2 — Import karein:** `App.tsx` mein
```tsx
import ProfileCard from "./ProfileCard";
```

**Step 3 — Use karein:** JSX mein `<ProfileCard />` ki tarah
```tsx
function App() {
  return (
    <div>
      <h1>My App</h1>
      <ProfileCard />
    </div>
  );
}
export default App;
```

**Key points:**
- Component file sirf ek component export karta hai — `export default` perfect fit
- File ka naam aur component ka naam same rakho — `ProfileCard.tsx` → `ProfileCard`
- Default import ka naam tum choose kar sakte ho, lekin convention wahi rakho
- `./` ka matlab "current folder" — relative path hai
- File extension (`.tsx`, `.ts`) import path mein nahi likhte

</details>
