## Abhi Tak Kya Hua

1.5.1 mein interface seekha, 1.5.2 mein props seekhe, 1.5.3 mein optional props aur destructuring seekhi, 1.5.4 mein callback props seekhe (function as prop, `on` prefix). Greeting Card banaya, aur callback prop `onAdd` ka concept clear hai.

## Broader Goal

Ab tak jo components banaye — `ProfileCard`, `GreetingCard`, `TaskInput` — sab "self-closing" the: `<ProfileCard />`, `<GreetingCard ... />`. Lekin real apps mein components ke andar doosre components hote hain. Jaise:

```tsx
<Card>
  <h1>Title</h1>
  <p>Content</p>
</Card>
```

Yeh **composition** pattern hai — ek component ke andar doosra content pass karna. Iske liye **`children`** prop use hoti hai.

## Step 1 — Problem Feel Karo

Soch: "Ek `Card` component banana hai jo ek border aur shadow ke saath koi bhi content wrap kare. Lekin content toh har jagah alag hoga."

Agar props se content pass karein:

```tsx
function Card({ content }: { content: string }) {
  return <div className="card">{content}</div>;
}

<Card content="<h1>Title</h1><p>Content</p>" />
```

Problem — `content` string hai, toh HTML render nahi hoga. Agar object pass karein toh complex ho jayega. Agar JSX pass karein toh?

function Card({ content }) {

### React Strings Ko Escape Karta Hai

Jab tum `<Card content="<h1>Title</h1>" />` likhte ho, `content` ek string hai — `<h1>` aur `<p>` sirf text characters hain, actual HTML elements nahi.

React JSX mein strings ko **HTML escape** karta hai. Matlab screen par literally `<h1>Title</h1>` text dikhega, rendered heading nahi. Yeh security ke liye hai — **XSS (Cross-Site Scripting)** attacks se bachta hai.

`dangerouslySetInnerHTML` exists but React ne intentionally scary naam rakha hai — "yeh unsafe hai, sure ho toh hi use karo".

**Asli solution:** JSX ko string nahi, actual React elements ke roop mein pass karo:

```tsx
// ❌ String — HTML nahi banega
<Card content="<h1>Title</h1>" />

// ✅ JSX direct — lekin kaise?
<Card>
  <h1>Title</h1>
</Card>
```

Yeh pattern React mein `children` prop se possible hai. Step 2 mein dekhte hain.

## Step 2 — Children Prop

Soch: "HTML mein `<div>` ke andar kuch bhi daal sakte ho — wo automatically render ho jaata hai. React mein kya aisa kuch hai?"

**Concept:** `children` ek special prop hai — jo bhi component ke opening aur closing tag ke beech mein likho, woh `children` mein aa jaata hai.

```tsx
<Card>
  <h1>Hello</h1>    {/* yeh children hai */}
  <p>World</p>       {/* yeh bhi children hai */}
</Card>
```

`Card` component ke andar yeh content receive karta hai props.children ke through.

`src/components/Card.tsx`:

```tsx
function Card({ children }: { children: React.ReactNode }): JSX.Element {
  return (
    <div style={{ border: "1px solid #ccc", padding: "16px", borderRadius: "8px" }}>
      {children}
    </div>
  );
}

export default Card;
```

`React.ReactNode` — TypeScript type jo batata hai ki `children` kuch bhi ho sakta hai: string, number, JSX, array of JSX, `null`, `undefined` — jo bhi React render kar sakta hai.

`App.tsx` mein use karo:

```tsx
import Card from "./components/Card";

function App() {
  return (
    <div>
      <Card>
        <h2>Welcome!</h2>
        <p>This is inside a Card component.</p>
      </Card>
      <Card>
        <p>Another card with different content.</p>
      </Card>
    </div>
  );
}
```

Dekho — content alag hai, lekin Card ki styling (border, padding, borderRadius) same hai. Isse kehte hain **layout component** — jo sirf structure provide karta hai, content nahi.

### "children" Keyword Hai Ya Convention?

`children` koi JavaScript keyword nahi hai, na hi React ka reserved keyword. Yeh ek **special prop name** hai — React internally dekhta hai ki "component ke opening aur closing tag ke beech kuch content hai?" toh use automatically `children` naam ki prop mein daal deta hai.

`children` name change kar sakte ho? Haan. Lekin tab auto-assign ka feature nahi milega:

```tsx
// Agar custom name diya — children ki jagah content
function Card({ content }: { content: React.ReactNode }) {
  return <div className="card">{content}</div>;
}
```

Ab `<Card><h1>Hi</h1></Card>` likhoge toh `content` undefined rahega. Kyunki React sirf `children` naam ko hi automatically assign karta hai. Custom name ke saath tumhe explicitly normal prop ki tarah pass karna padega:

```tsx
<Card content={<h1>Hi</h1>} />  // explicit — normal prop ki tarah
```

Lekin yeh karne ka koi fayda nahi — `children` hi standard hai. Isliye hamesha `children` naam use karo taake auto-assign ka feature mil sake.

### Normal Prop vs Children Prop — Farak Kya Hai?

| Feature | Normal Prop | Children Prop |
|---------|-------------|---------------|
| Kaise pass karte ho | `<Card title="Hello" />` | `<Card>Hello</Card>` |
| Component mein kaise receive karte ho | `props.title` | `props.children` |
| Auto assign hota hai? | ❌ Nahi — explicitly attribute mein likhna padta hai | ✅ Haan — React automatically beech ka content le leta hai |
| Naam convention | Kuch bhi ho sakta hai — `label`, `action`, `onClick`, `count` | Sirf **`children`** — koi aur naam doge toh auto-assign nahi hoga |
| Jab use karte ho | Specific data pass karna ho — string, number, boolean, function | Arbitrary JSX content jo component ke andar wrap karna ho |

### Normal Props + Children — Ek Saath

React component ek saath dono le sakta hai — specific data normal props se, aur wrapped content `children` se:

```tsx
interface CardProps {
  children: React.ReactNode;
  title?: string;
}

function Card({ children, title }: CardProps) {
  return (
    <div className="card">
      {title && <h3>{title}</h3>}
      {children}
    </div>
  );
}
```

```tsx
<Card title="Today's Tasks">   {/* normal prop — specific data */}
  <p>Review PR</p>              {/* children — auto-assign */}
  <p>Write tests</p>            {/* children — part of wrapped content */}
  <p>Deploy to staging</p>      {/* children — more wrapped content */}
</Card>
```

Yahan:
- `title="Today's Tasks"` — **normal prop** hai. Explicitly pass kiya, `props.title` se access karte ho
- `<p>Review PR</p>` etc — **children** hain. React ne automatically assign kiya, `props.children` se access karte ho

Card component dono ko combine karta hai — heading (title) aur wrapped content (children) ko card layout mein render karta hai.

### Normal Prop vs Children — Jab Dono Mein Content Pass Karein

Socho: "Agar main normal prop se bhi JSX pass kar doon aur children se bhi?"

```tsx
// Normal prop se JSX — kaam karega lekin awkward hai
<Card content={<h1>Hi</h1>} />

// Children se JSX — natural hai, React style
<Card>
  <h1>Hi</h1>
</Card>
```

Dono kaam karte hain. Lekin `children` wala pattern zyada readable hai — HTML ki tarah likhte ho (jaise `<div>` ke andar content). Normal prop mein `content={<h1>Hi</h1>}` likhna JSX ke andar JSX daalna hai — chalta hai but messy.

### Recap — Kab Kya Use Karein

| Situation | Use |
|-----------|-----|
| Button ka text | `children` — `<Button>Click</Button>` |
| Card mein wrapped content | `children` — `<Card><p>Content</p></Card>` |
| Specific value (user ID) | Normal prop — `<Profile userId={1} />` |
| Callback function | Normal prop — `<TaskInput onAdd={handleAdd} />` |
| Optional heading ya title | Normal prop — `<Card title="Notes">...</Card>` |

Rule of thumb: Jo component ke **beech** mein aata hai woh `children`, jo **attribute** mein aata hai woh normal prop. HTML ki tarah socho — `<div>` ke beech ka content vs `<img src="..." />` ka attribute.

## Step 3 — Composition Pattern: Lego Blocks Ki Tarah

Soch: "Children prop toh aa gaya. Lekin asli fayda kya hai? Sirf wrap karna hi composition hai?"

Nahi. Composition ek broader pattern hai — **chhote components ko combine karke bade components banana**. Jaise Lego blocks se bade structures bante hain.

### HTML Mein Composition Naturally Hai

HTML mein tum roz composition use karte ho — bas naam nahi pata:

```html
<div>
  <header>
    <h1>Title</h1>
    <nav>Home | About</nav>
  </header>
  <main>
    <p>Content here</p>
  </main>
</div>
```

Chhote elements (`<h1>`, `<p>`, `<nav>`) combine hokar bade structures (`<header>`, `<main>`, `<div>`) banate hain. React mein same pattern — sirf elements ki jagah **components** hain.

### React Mein Composition — Do Tarike

#### 1. Props ke Through (Data Pass)

Ek component doosre component ko specific props dekar compose karta hai:

```tsx
// Chhota component 1 — sirf avatar dikhata hai
function Avatar({ name }: { name: string }) {
  return <img src={`https://api.dicebear.com/7.x/initials/svg?seed=${name}`} alt={name} />;
}

// Chhota component 2 — sirf info dikhata hai
function Info({ name, role }: { name: string; role: string }) {
  return (
    <div>
      <h3>{name}</h3>
      <p>{role}</p>
    </div>
  );
}

// Bada component — Avatar + Info ko combine kiya
function UserCard({ name, role }: { name: string; role: string }) {
  return (
    <div className="card">
      <Avatar name={name} />
      <Info name={name} role={role} />
    </div>
  );
}
```

Yahan `UserCard` ne `Avatar` aur `Info` ko **props dekar** combine kiya. Do alag components, ek saath kaam kar rahe hain. UserCard ko nahi pata ki Avatar internally kya render karta hai — usse sirf itna pata hai ki Avatar ko `name` chahiye.

#### 2. children Ke Through (Wrap)

Doosra tarika — wrapper component banao jo `children` ke through koi bhi content le:

```tsx
// Card sirf layout provide karta hai
function Card({ children }: { children: React.ReactNode }) {
  return <div className="card">{children}</div>;
}

// Card ke andar kuch bhi daal do — composition
<Card>
  <UserCard name="Vin" role="Developer" />
</Card>
```

Yahan `Card` ko nahi pata ki andar kya hai — woh sirf layout deta hai. UserCard ko nahi pata ki woh Card ke andar hai. Dono ek doosre ke baare mein nahi jaante — **loose coupling**. Yeh composition ka fayda hai.

### Dono Tarike Ek Saath

Real apps mein dono tarike ek saath use hote hain:

```tsx
// Do components — ek avatar, ek user info
function Avatar({ name }: { name: string }) {
  return <img src={`https://api.dicebear.com/7.x/initials/svg?seed=${name}`} alt={name} />;
}

interface InfoProps {
  name: string;
  role: string;
  status?: "online" | "offline";
}

function Info({ name, role, status }: InfoProps) {
  return (
    <div>
      <h3>{name}</h3>
      <p>{role} {status === "online" ? "🟢" : "⚪"}</p>
    </div>
  );
}

// UserCard — props ke through Avatar + Info ko compose karta hai
function UserCard({ name, role, status }: InfoProps) {
  return (
    <div className="card">
      <Avatar name={name} />
      <Info name={name} role={role} status={status} />
    </div>
  );
}

// App — UserCard ko Card ke andar compose karta hai (children)
function App() {
  return (
    <Card>
      <UserCard name="Vin" role="React Developer" status="online" />
      <UserCard name="Priya" role="Designer" status="offline" />
    </Card>
  );
}
```

Composition tree dekho:

```
App
└── Card (children-based — wrapper)
    ├── UserCard (props-based — Avatar + Info combine)
    │   ├── Avatar
    │   └── Info
    └── UserCard
        ├── Avatar
        └── Info
```

### Composition Over Inheritance

Agar tum school ya college mein OOP (Object-Oriented Programming) padhe ho, toh wahan **inheritance** hota hai — "class Dog extends Animal". React mein aisa nahi hai. React ka philosophy hai **composition over inheritance**.

| Inheritance (OOP) | Composition (React) |
|---|---|
| Class extends doosri class | Component ANDAR doosra component |
| "Parent se properties inherit" | "Chhote blocks se bana" |
| Tight coupling | Loose coupling |
| Ek hierarchy | Flexible, flat structure |

React docs bhi kehti hai — "Use composition instead of inheritance."

### Recap — Composition in React

| What | How | Example |
|------|-----|---------|
| Specific component banao | Props do | `<Avatar name="Vin" />` |
| Layout banane ke liye | children lo | `<Card>content</Card>` |
| Dono combine karo | Props + children | `<Card title="Users"><Avatar name="Vin" /></Card>` |

## Step 4 — React.ReactNode Deep Explanation

Soch: "`React.ReactNode` kya hai? Kya main `string | JSX.Element | null` likh sakta hoon?"

**Concept:** `React.ReactNode` ek TypeScript type hai jo React ki renderable values ka union type hai:

```tsx
type ReactNode = 
  | string 
  | number 
  | boolean 
  | null 
  | undefined 
  | JSX.Element 
  | ReactNode[] // array of nodes
  | ReactPortal;
```

Agar manually union type likhni hoti toh bahut lambi hoti. Isliye `React.ReactNode` use karo — ek hi type mein sab cover ho jata hai.

Lekin ek limitation hai — `React.ReactNode` sirf tab use karo jab children ka type exactly pata na ho (flexible). Agar children ka specific type chahiye (jaise sirf `string`), toh explicit type do:

```tsx
interface ButtonProps {
  children: string; // sirf string allow
}
```

## Step 5 — Layout Component — Container

Soch: "Ek container component chahiye jo app ko center kare, width limit kare."

`src/components/Container.tsx`:

```tsx
interface ContainerProps {
  children: React.ReactNode;
}

function Container({ children }: ContainerProps): JSX.Element {
  return (
    <div style={{ maxWidth: "600px", margin: "0 auto", padding: "20px" }}>
      {children}
    </div>
  );
}

export default Container;
```

Ab `App.tsx` mein poora content Container ke andar daalo:

```tsx
import Container from "./components/Container";

function App() {
  return (
    <Container>
      <h1>My App</h1>
      <p>This content is centered with max-width 600px.</p>
    </Container>
  );
}
```

Browser mein check karo — content ab center mein hai, max 600px wide, har taraf 20px padding.

## Step 6 — Multiple Children vs Single Children

Soch: "Agar Card ke andar ek child ho toh kya fark hai? Agar do ho toh?"

React automatically handle karta hai:

```tsx
// Single child — children ek hi element hai
<Card>
  <p>Hello</p>
</Card>
// children = <p>Hello</p> (JSX.Element)

// Multiple children — children array ho jayega
<Card>
  <h1>Title</h1>
  <p>Content</p>
</Card>
// children = [<h1>Title</h1>, <p>Content</p>] (JSX.Element[])
```

`React.ReactNode` dono cases ko handle kar leta hai. Isliye flexible hai.

## Step 7 — Card Component ko TypeScript Interface Ke Saath

`src/components/Card.tsx` ko interface ke saath rewrite karo:

```tsx
interface CardProps {
  children: React.ReactNode;
  title?: string;
}

function Card({ children, title }: CardProps): JSX.Element {
  return (
    <div style={{ border: "1px solid #ccc", padding: "16px", borderRadius: "8px" }}>
      {title && <h3>{title}</h3>}
      {children}
    </div>
  );
}

export default Card;
```

Ab Card optional title bhi le sakta hai:

```tsx
<Card title="Tasks">
  <p>Task 1</p>
  <p>Task 2</p>
</Card>
```

`{title && <h3>{title}</h3>}` yeh short-circuit evaluation hai — agar `title` hai toh `<h3>` render karo, nahi toh kuch mat karo. 1.7 mein conditional rendering detail mein dekhenge.

## Summary

- `children` prop — component ke opening/closing tag ke beech ka content
- Type: `React.ReactNode` — sab kuch accept karta hai (JSX, string, array, null)
- Layout components — sirf structure provide karte hain, content nahi (Container, Card)
- Composition pattern — chhote components ko combine karke bade components banate hain
- `{title && <h3>{title}</h3>}` — conditional rendering ka shorthand
