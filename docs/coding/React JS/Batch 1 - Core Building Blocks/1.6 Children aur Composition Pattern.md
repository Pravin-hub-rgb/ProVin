# 1.6 — Children aur Composition Pattern

## Abhi Tak Kya Hua

1.5.1 mein interface seekha, 1.5.2 mein props seekhe, 1.5.3 mein optional props aur destructuring seekhi, 1.5.4 mein callback props seekhe (function as prop, `on` prefix). Greeting Card banaya, aur callback prop `onAdd` ka concept clear hai. Ab To-Do app ka structure sochna shuru kiya hai.

## Broader Goal

Ab tak jo components banaye — `ProfileCard`, `GreetingCard`, `TaskInput` — sab "self-closing" the: `<ProfileCard />`, `<GreetingCard ... />`. Lekin real apps mein components ke andar doosre components hote hain. Jaise:

```tsx
<Card>
  <h1>Title</h1>
  <p>Content</p>
</Card>
```

Yeh **composition** pattern hai — ek component ke andar doosra content pass karna. Iske liye **`children`** prop use hoti hai. Yeh To-Do app ka layout structure banane ke liye zaroori hai.

## Step 1 — Problem Feel Karo

Soch: "Ek `Card` component banana hai jo ek border aur shadow ke saath koi bhi content wrap kare. Lekin content toh har jagah alag hoga."

Agar props se content pass karein:

```tsx
function Card({ content }: { content: string }) {
  return <div className="card">{content}</div>;
}

<Card content="<h1>Title</h1><p>Content</p>" />
```

Problem — `content` string hai, toh HTML render nahi hoga. Agar object pass karein toh complex ho jayega. Agar JSX pass karein toh?

React ka solution: **`children`** prop.

## Step 2 — Children Prop

Soch: "HTML mein `<div>` ke andar kuch bhi daal sakte ho — wo automatically render ho jaata hai. React mein kya aisa kuch hai?"

**Concept:** `children` ek special prop hai — jo bhi component ke opening aur closing tag ke beech mein likho, woh `children` mein aa jaata hai.

```tsx
<Card>
  <h1>Hello</h1>    {/* yeh children hai */}
  <p>World</p>       {/* yeh bhi children hai */}
</Card>
```

`Card` component ke andar yeh content receive karta hai props.children ke through.

`src/components/Card.tsx`:

```tsx
function Card({ children }: { children: React.ReactNode }): JSX.Element {
  return (
    <div style={{ border: "1px solid #ccc", padding: "16px", borderRadius: "8px" }}>
      {children}
    </div>
  );
}

export default Card;
```

`React.ReactNode` — TypeScript type jo batata hai ki `children` kuch bhi ho sakta hai: string, number, JSX, array of JSX, `null`, `undefined` — jo bhi React render kar sakta hai.

`App.tsx` mein use karo:

```tsx
import Card from "./components/Card";

function App() {
  return (
    <div>
      <Card>
        <h2>Welcome!</h2>
        <p>This is inside a Card component.</p>
      </Card>
      <Card>
        <p>Another card with different content.</p>
      </Card>
    </div>
  );
}
```

Dekho — content alag hai, lekin Card ki styling (border, padding, borderRadius) same hai. Isse kehte hain **layout component** — jo sirf structure provide karta hai, content nahi.

## Step 3 — React.ReactNode Deep Explanation

Soch: "`React.ReactNode` kya hai? Kya main `string | JSX.Element | null` likh sakta hoon?"

**Concept:** `React.ReactNode` ek TypeScript type hai jo React ki renderable values ka union type hai:

```tsx
type ReactNode = 
  | string 
  | number 
  | boolean 
  | null 
  | undefined 
  | JSX.Element 
  | ReactNode[] // array of nodes
  | ReactPortal;
```

Agar manually union type likhni hoti toh bahut lambi hoti. Isliye `React.ReactNode` use karo — ek hi type mein sab cover ho jata hai.

Lekin ek limitation hai — `React.ReactNode` sirf tab use karo jab children ka type exactly pata na ho (flexible). Agar children ka specific type chahiye (jaise sirf `string`), toh explicit type do:

```tsx
interface ButtonProps {
  children: string; // sirf string allow
}
```

## Step 4 — Layout Component — Container

Soch: "To-Do app ka ek main layout chahiye — ek container jo app ko center kare, width limit kare."

`src/components/Container.tsx`:

```tsx
interface ContainerProps {
  children: React.ReactNode;
}

function Container({ children }: ContainerProps): JSX.Element {
  return (
    <div style={{ maxWidth: "600px", margin: "0 auto", padding: "20px" }}>
      {children}
    </div>
  );
}

export default Container;
```

Ab `App.tsx` mein poora content Container ke andar daalo:

```tsx
import Container from "./components/Container";
import TaskInput from "./components/TaskInput";

function App() {
  const handleAdd = (text: string) => {
    console.log("Adding task:", text);
  };

  return (
    <Container>
      <h1>To-Do App</h1>
      <TaskInput onAdd={handleAdd} />
    </Container>
  );
}
```

Browser mein check karo — content ab center mein hai, max 600px wide, har taraf 20px padding.

## Step 5 — Multiple Children vs Single Children

Soch: "Agar Card ke andar ek child ho toh kya fark hai? Agar do ho toh?"

React automatically handle karta hai:

```tsx
// Single child — children ek hi element hai
<Card>
  <p>Hello</p>
</Card>
// children = <p>Hello</p> (JSX.Element)

// Multiple children — children array ho jayega
<Card>
  <h1>Title</h1>
  <p>Content</p>
</Card>
// children = [<h1>Title</h1>, <p>Content</p>] (JSX.Element[])
```

`React.ReactNode` dono cases ko handle kar leta hai. Isliye flexible hai.

## Step 6 — Card Component ko TypeScript Interface Ke Saath

`src/components/Card.tsx` ko interface ke saath rewrite karo:

```tsx
interface CardProps {
  children: React.ReactNode;
  title?: string;
}

function Card({ children, title }: CardProps): JSX.Element {
  return (
    <div style={{ border: "1px solid #ccc", padding: "16px", borderRadius: "8px" }}>
      {title && <h3>{title}</h3>}
      {children}
    </div>
  );
}

export default Card;
```

Ab Card optional title bhi le sakta hai:

```tsx
<Card title="Tasks">
  <p>Task 1</p>
  <p>Task 2</p>
</Card>
```

`{title && <h3>{title}</h3>}` yeh short-circuit evaluation hai — agar `title` hai toh `<h3>` render karo, nahi toh kuch mat karo. 1.7 mein conditional rendering detail mein dekhenge.

## Step 7 — To-Do App Ka Structure Abhi Tak

Soch: "Abhi tak To-Do app mein kya kya bana liya?"

- `Container` — layout (max-width, center)
- `Card` — reusable box with optional title
- `TaskInput` — input + add button (abhi sirf "Sample task" add karta hai)

Folder structure:

```
src/
├── components/
│   ├── Card.tsx
│   ├── Container.tsx
│   ├── GreetingCard.tsx
│   ├── ProfileCard.tsx
│   └── TaskInput.tsx
└── App.tsx
```

Agle chapter mein **state** aur **events** seekhenge — tab `TaskInput` actual kaam karega aur tasks add ho payenge.

## Summary

- `children` prop — component ke opening/closing tag ke beech ka content
- Type: `React.ReactNode` — sab kuch accept karta hai (JSX, string, array, null)
- Layout components — sirf structure provide karte hain, content nahi (Container, Card)
- Composition pattern — chhote components ko combine karke bade components banate hain
- `{title && <h3>{title}</h3>}` — conditional rendering ka shorthand
