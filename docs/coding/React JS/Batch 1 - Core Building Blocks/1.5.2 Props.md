## Abhi Tak Kya Hua

1.5.1 mein interface seekha — object ka shape define karna, `export interface`, `import type`. Ab is knowledge ko React mein **props** ke saath use karenge. Component ab dynamic hoga — har baar alag data ke saath render ho sakta hai.

## Broader Goal

Ab tak ProfileCard static tha — har jagah same "Vin — React Developer". Component reusability ka fayda tab hai jab **ek hi component alag-alag data ke saath render ho**. Props React ka mechanism hai data pass karne ka. Inline type se shuru karenge, phir interface mein upgrade karenge.

## Step 1 — Problem Feel Karo

Soch: "Teen ProfileCard render kiye, sab same data — 'Vin', 'React Developer'. Kya har card ke liye alag component banana padega?"

```tsx
// Kya aise karna padega?
function VinCard() { return <div>Vin — React Developer</div>; }
function PriyaCard() { return <div>Priya — Designer</div>; }
function RajCard() { return <div>Raj — Backend Dev</div>; }
```

100 cards ke liye 100 components? Bilkul nahi. Isliye **props** chahiye — component ko data pass karne ka tarika.

## Step 2 — Props = Function Arguments

**Concept:** Jis tarah ek function parameters leta hai, usi tarah component bhi parameters leta hai. React mein unhe **props** kehte hain.

```tsx
// Normal function
function greet(name: string) {
  return `Hello, ${name}`;
}
greet("Vin");

// React component with props
function ProfileCard(props: { name: string; role: string }) {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>{props.role}</p>
    </div>
  );
}
<ProfileCard name="Vin" role="React Developer" />
```

Dekho — `<ProfileCard name="Vin" role="React Developer" />` likhne se React ek object banata hai `{ name: "Vin", role: "React Developer" }` aur yeh object `props` parameter ke through component mein jaata hai. Component ke andar `props.name` aur `props.role` use karte ho.

### Props is Not a Keyword

`props` koi React keyword nahi hai — yeh sirf function parameter ka naam hai. Tum kuch bhi likh sakte ho:

```tsx
function ProfileCard(data: { name: string; role: string }) {
  return <h2>{data.name}</h2>;
}

function ProfileCard(p: { name: string; role: string }) {
  return <h2>{p.name}</h2>;
}

function ProfileCard(customProp: { name: string; role: string }) {
  return <h2>{customProp.name}</h2>;
}
```

Teeno kaam karenge. Lekin **convention** yeh hai ki `props` hi likho — kisi aur ka code padhoge toh `props` dekh ke turant pata chalega ki yeh React component ka parameter hai. Isliye poori industry `props` use karti hai.

## Step 3 — Interface Ke Saath Props

1.5.1 ka interface ab use karte hain. Inline type ki jagah `ProfileCardProps` interface define karo:

```tsx
interface ProfileCardProps {
  name: string;
  role: string;
}

function ProfileCard(props: ProfileCardProps): JSX.Element {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>{props.role}</p>
    </div>
  );
}

export default ProfileCard;
```

`App.tsx`:

```tsx
import ProfileCard from "./components/ProfileCard";

function App() {
  return (
    <div>
      <h1>My Team</h1>
      <ProfileCard name="Vin" role="React Developer" />
      <ProfileCard name="Priya" role="Designer" />
      <ProfileCard name="Raj" role="Backend Dev" />
    </div>
  );
}
```

Browser mein ab teen alag cards dikhenge. Ek component, alag-alag data — **component reusability**.

### Interface Convention

Interface ka naam `ProfileCardProps` rakha. Yeh convention hai: **`ComponentNameProps`** — component ke naam ke saath `Props` suffix. Purely optional hai, lekin React ecosystem mein standard hai.

### Inline Type vs Interface

| | Inline Type | Interface |
|---|---|---|
| Syntax | `props: { name: string }` | `interface Props { name: string }` then `props: Props` |
| Reuse | Nahi kar sakte | Multiple jagah use kar sakte ho |
| Readability | Chhote props ke liye theek | Complex components ke liye better |
| Export | Possible nahi | `export interface` — kahi aur import kar sakte ho |

Chhote components (< 3-4 props) mein inline type bhi chalega. Lekin real projects mein interface prefer karte hain — extensible hai, reuse ho sakta hai, aur type alag line mein hai.

## Summary

- Props = function arguments for components
- `<ProfileCard name="Vin" />` → React ek props object banata hai
- Inline type: `(props: { name: string })` — simple cases mein
- Interface: `interface ProfileCardProps { name: string }` — professional pattern
- Convention: `ComponentNameProps`
- Ek component, alag-alag data = component reusability

## Agla Step

Props ke saath interface use karna aa gaya. Agle chapter mein **optional props** (`?`), **destructuring** (`{ name, role }`), **default values** (`||`), aur **callback props** (functions as props) seekhenge. Yeh real-world components mein har jagah use hote hain.
