# 1.2 — Pehla Component

## Abhi Tak Kya Hua

1.1 mein JSX samjha — yeh HTML nahi hai, `React.createElement` ka syntactic sugar hai. `className`, `htmlFor`, camelCase attributes, `{ }` expressions, aur single root element ka rule — sab clear hai. Browser abhi bhi `localhost:5173` dikha raha hai.

## Broader Goal

1.1 mein sirf `App.tsx` edit kiya tha. Ab ek naya component banayenge — apna khud ka **ProfileCard**. Samjhenge ki React component kaise likhte hain, component reuse kaise karte hain, aur TypeScript typing basics kya hote hain. Interface aur import/export agle topics mein detail mein aayenge.

## Step 1 — Component Kya Hota Hai

Soch: "App.tsx mein ek function hai jo JSX return kar raha hai. Kya main aise aur functions bana sakta hoon?"

Har real app mein code ko chhote-chhote reusable pieces mein todna padta hai. React mein har piece ko **component** kehte hain.

**Concept:** React component sirf ek JavaScript function hai jiske do rules hain:

1. **Function ka naam capital letter se shuru hona chahiye** — `ProfileCard`, `Button`, `Header`
2. **Function JSX return karna chahiye** — jo bhi render karna hai

```
// ❌ Component nahi — lowercase se shuru
function profileCard() { return <div>...</div>; }

// ✅ Component hai — capital letter
function ProfileCard() { return <div>...</div>; }
```

Capital letter kyun? React ko pata hona chahiye ki yeh ek component hai, na ki koi regular HTML tag. `div` React samajhta hai "yeh HTML div tag hai". `ProfileCard` React samajhta hai "yeh mera custom component hai, ise render karo".

## Step 2 — ProfileCard Component Banao

Soch: "Component function to samajh aa gaya. Use kaise banate hain?"

`App.tsx` mein `App` function ke upar yeh naya function add karo:

```tsx
function ProfileCard() {
  const name = "Vin";
  const role = "React Developer";

  return (
    <div>
      <h2>{name}</h2>
      <p>{role}</p>
    </div>
  );
}

function App() {
  return (
    <div>
      <h1>My App</h1>
      <ProfileCard />
    </div>
  );
}
```

Dekho — `App` ke andar `<ProfileCard />` likha hai. Yehi tarika hai component ko use karne ka — bilkul HTML tag jaisa.

Browser check karo:

```
My App
Vin
React Developer
```

Agar error aaye `'ProfileCard' is defined but never used` — toh ignore karo, yeh TypeScript warning hai. Agli files mein import karna seekhenge toh fix ho jayega.

## Step 3 — TypeScript Component Typing

Soch: "Component ek function hai jo JSX return karta hai. TypeScript mein function ka return type kaise likhte hain?"

0.7 TypeScript Warm-up mein seekha tha — functions ka return type explicit likh sakte ho. React component ka return type `JSX.Element` hota hai.

```tsx
function ProfileCard(): JSX.Element {
  const name = "Vin";
  const role = "React Developer";

  return (
    <div>
      <h2>{name}</h2>
      <p>{role}</p>
    </div>
  );
}
```

`JSX.Element` TypeScript ko batata hai ki yeh function JSX return karega. Agar galti se kuch aur return kiya toh error dega:

```tsx
function ProfileCard(): JSX.Element {
  return "Hello"; // ❌ Error — string JSX.Element nahi hai
}
```

> **Note:** React 19 ke saath `JSX.Element` ab global type hai (React import kiye bina). React 18 mein `React.ReactNode` ya `React.FC` use hota tha. React 19 mein `JSX.Element` standard hai.

### Important — return aur JSX ke beech line break mat daalo

Shuruaat mein sabse common mistake yeh hoti hai:

```tsx
function ProfileCard(): JSX.Element {
  return                // ❌ Line break — ASI ka shikaar
  <div>
    <h2>Vin</h2>
  </div>
}
```

Yeh chalega nahi. Kyun? JavaScript ki **Automatic Semicolon Insertion (ASI)** — jab `return` ke baad turant line break aata hai, toh JavaScript samajhti hai "return khatam, undefined return karo" aur `<div>` unreachable code ban jaata hai.

```tsx
// JS engine ise aise padhta hai:
return;
<div>...</div>  // kabhi execute nahi hoga
```

ProfileCard ab kuch return nahi kar raha — `void` return ho raha hai. React ko component se JSX chahiye, `void` nahi.

**Do tarike hain fix karne ke:**

1. **JSX return ke saath same line mein rakho** (chhota JSX ho toh):

   ```tsx
   return <div>...</div>
   ```

2. **Parentheses mein wrap karo** — yeh standard React pattern hai multi-line JSX ke liye:

   ```tsx
   return (
     <div>...</div>
   )
   ```

   Parentheses ASI ko trigger nahi karte kyunki `return (` ke baad line break aata hai lekin expression abhi complete nahi hua (closing `)` ka wait hai). Isliye JavaScript samajhti hai "wait, expression abhi khatam nahi hua, line break ignore karo."

**Rule of thumb:** Multi-line JSX hamesha parentheses mein wrap karo. Single-line JSX same line par rakho.

```tsx
// ✅ Single line — same line
return <h2>Vin</h2>;

// ✅ Multi-line — parentheses
return (
  <div>
    <h2>Vin</h2>
    <p>React Developer</p>
  </div>
);

// ❌ Kabhi nahi — line break ke baad multi-line
return
<div>...</div>;
```

## Step 4 — Multiple Components Ka Use

Soch: "Ek ProfileCard toh ban gaya. Kya main do ProfileCard ek saath use kar sakta hoon?"

`App.tsx` mein:

```tsx
function App() {
  return (
    <div>
      <h1>My Team</h1>
      <ProfileCard />
      <ProfileCard />
      <ProfileCard />
    </div>
  );
}
```

Browser mein teen cards dikhenge — sab same "Vin" aur "React Developer" ke saath. Abhi sab static hai, but yeh **component reusability** ka concept hai. Ek baar component likha, teen jagah use kiya.

### Component vs Regular Function

Component aur regular function mein kya fark hai?

| Feature | Regular Function | React Component |
|---------|-----------------|-----------------|
| Use | Normal call: `greet("Vin")` | JSX tag: `<Greet name="Vin" />` |
| Return | Kuch bhi — string, number, object | JSX (jo React render karta hai) |
| Name | `greet` (lowercase) | `Greet` (capital) |
| Re-render | N/A | React automatically handle karta hai jab state/props change ho |

Component technically ek function hi hai — bas React usse special treat karta hai.

## Step 5 — TypeScript Type Inference

Soch: "Agar main return type nahi bhi likhoon, toh TypeScript error toh nahi deta?"

Try karo — `: JSX.Element` hatao. TypeScript error nahi dega.

**Concept — Type Inference:** TypeScript automatically infer kar leta hai ki component `JSX.Element` return karega. Explicit return type optional hai. React developers mostly return type nahi likhte kyunki TypeScript infer kar leta hai.

Lekin jab koi naya concept seekh rahe ho, pehle explicit likhna achhi aadat hai — pata chalta hai ki actually kya return ho raha hai.

## Summary

- Component = function + capital letter + returns JSX
- `<ProfileCard />` — component ko use karne ka syntax
- Return type: `JSX.Element` (TypeScript mostly infer kar leta hai)
- Component reuse: ek baar likho, multiple jagah use karo
- Component vs regular function — syntax alag, behaviour alag
- Multiple components ek file mein chalta hai — baad mein alag files mein split karenge
