## Before Hooks — Class Components

React Hooks (`useState`, `useEffect`, etc.) arrived in 2019 with React 16.8. Before that, components were written as classes:

```tsx
class Counter extends React.Component<{}, { count: number }> {
  constructor(props: {}) {
    super(props)
    this.state = { count: 0 }
  }

  componentDidMount() {
    console.log('Component mounted')
  }

  componentDidUpdate(prevProps: {}, prevState: { count: number }) {
    console.log('Component updated:', prevState.count, '→', this.state.count)
  }

  componentWillUnmount() {
    console.log('Component unmounted')
  }

  render() {
    return (
      <div>
        <p>Count: {this.state.count}</p>
        <button onClick={() => this.setState({ count: this.state.count + 1 })}>
          +1
        </button>
      </div>
    )
  }
}
```

Same component with Functions + Hooks:

```tsx
function Counter() {
  const [count, setCount] = useState(0)

  useEffect(() => {
    console.log('Component mounted/updated')
  })

  useEffect(() => {
    console.log('Component mounted')
    return () => console.log('Component unmounted')
  }, [])

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
    </div>
  )
}
```

## Problems That Hooks Solved

### 1. Logic Reuse — Wrapper Hell

Class components needed **Higher-Order Components** (HOCs) or **Render Props** for reusable logic. This created "wrapper hell" — deeply nested component trees:

```tsx
// Before — HOCs
export default withRouter(withTheme(withAuth(Counter)))

// After — Custom Hook
function Counter() {
  const router = useRouter()
  const theme = useTheme()
  const auth = useAuth()
  // Simple and clean
}
```

### 2. Scattered Lifecycle Methods

Related logic was scattered across lifecycle methods:

```tsx
componentDidMount() {
  this.fetchData()        // fetching
  this.startTimer()       // timer
  this.addListener()      // event listener
}

componentDidUpdate(prevProps) {
  if (prevProps.id !== this.props.id) {
    this.fetchData()      // fetching again
    this.stopTimer()      // timer again
    this.startTimer()     // timer new
  }
}

componentWillUnmount() {
  this.stopTimer()        // timer again
  this.removeListener()   // listener again
}
```

With Hooks, related logic stays together:

```tsx
useEffect(() => {
  fetchData()
}, [id])

useEffect(() => {
  startTimer()
  return () => stopTimer()
}, [])

useEffect(() => {
  addListener()
  return () => removeListener()
}, [])
```

### 3. No More `this` Confusion

Class components had `this` binding bugs:

```tsx
<button onClick={this.handleClick}>  // ❌ `this` was undefined
```

You either had to use an arrow function, or bind in the constructor:

```tsx
constructor(props) {
  super(props)
  this.handleClick = this.handleClick.bind(this)  // for every method
}
```

Hooks don't use `this` — just access variables directly:

```tsx
const handleClick = () => setCount(c => c + 1)
```

## When Will I See Class Components?

1. **Legacy codebases** — Projects built before 2019, or stuck on React 16.8
2. **Error Boundaries** — The `componentDidCatch` lifecycle. Hooks have no equivalent. ErrorBoundary is still built as a class component.
3. **Interview questions** — "Class components vs functional components" is a common interview question

## Error Boundary — The One Exception

```tsx
class ErrorBoundary extends React.Component<
  { children: React.ReactNode },
  { hasError: boolean; error: Error | null }
> {
  constructor(props: { children: React.ReactNode }) {
    super(props)
    this.state = { hasError: false, error: null }
  }

  static getDerivedStateFromError(error: Error) {
    return { hasError: true, error }
  }

  componentDidCatch(error: Error, info: React.ErrorInfo) {
    console.error('Error caught:', error, info)
  }

  render() {
    if (this.state.hasError) {
      return <h2>Something went wrong: {this.state.error?.message}</h2>
    }
    return this.props.children
  }
}
```

This is the one case where a class component is still needed. But it's just one — everything else is functional.

## Summary

✅ **Class components** — React's old way (before 2019)  
✅ **Problems solved by Hooks** — logic reuse, scattered lifecycle, `this` confusion, wrapper hell  
✅ **Hooks** — functional components + `useState`/`useEffect`/`useContext`, etc.  
✅ **Legacy codebases** may contain class components — you should be able to recognize them  
✅ **Error Boundary** — the one exception where a class component is still used  
✅ **Interview tip** — "What problems did Hooks solve?" is an important distinction to explain

This side note is recognition-level only — no code in this course will be written as class components. Next topic — **1.3 Import Export** — where we'll learn how to keep components in separate files and use one component inside another.
