## Before Hooks — Class Components

React mein Hooks (useState, useEffect, etc.) 2019 mein aaye — React 16.8 ke saath. Usse pehle components classes ke through banaye jaate the:

```tsx
class Counter extends React.Component<{}, { count: number }> {
  constructor(props: {}) {
    super(props)
    this.state = { count: 0 }
  }

  componentDidMount() {
    console.log('Component mount hua')
  }

  componentDidUpdate(prevProps: {}, prevState: { count: number }) {
    console.log('Component update hua:', prevState.count, '→', this.state.count)
  }

  componentWillUnmount() {
    console.log('Component unmount hua')
  }

  render() {
    return (
      <div>
        <p>Count: {this.state.count}</p>
        <button onClick={() => this.setState({ count: this.state.count + 1 })}>
          +1
        </button>
      </div>
    )
  }
}
```

Same component Functional + Hooks se:

```tsx
function Counter() {
  const [count, setCount] = useState(0)

  useEffect(() => {
    console.log('Component mount/update hua')
  })

  useEffect(() => {
    console.log('Component mount hua')
    return () => console.log('Component unmount hua')
  }, [])

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
    </div>
  )
}
```

## Problems That Hooks Solved

### 1. Logic Reuse — No Wrapper Hell

Class components mein reusable logic ke liye **Higher-Order Components** (HOCs) ya **Render Props** use karne padte the. Isse "wrapper hell" hoti thi — component tree deeply nested ho jata tha:

```tsx
// Before — HOCs
export default withRouter(withTheme(withAuth(Counter)))

// After — Custom Hook
function Counter() {
  const router = useRouter()
  const theme = useTheme()
  const auth = useAuth()
  // Simple, clean
}
```

### 2. Lifecycle Methods Scattered

Related logic lifecycle methods mein scattered ho jati thi:

```tsx
componentDidMount() {
  this.fetchData()        // fetch
  this.startTimer()       // timer
  this.addListener()      // event listener
}

componentDidUpdate(prevProps) {
  if (prevProps.id !== this.props.id) {
    this.fetchData()      // — wapas fetch logic
    this.stopTimer()      // — wapas timer logic
    this.startTimer()
  }
}

componentWillUnmount() {
  this.stopTimer()        // — wapas timer logic
  this.removeListener()   // — wapas listener logic
}
```

Hooks ke saath — related logic ek saath:

```tsx
useEffect(() => {
  fetchData()
}, [id])

useEffect(() => {
  startTimer()
  return () => stopTimer()
}, [])

useEffect(() => {
  addListener()
  return () => removeListener()
}, [])
```

### 3. No `this` Confusion

Class components mein `this` ka context loss ek common bug tha:

```tsx
<button onClick={this.handleClick}>  // ❌ this undefined hota tha
```

Ya toh arrow function banani padti thi, ya constructor mein bind karna padta tha:

```tsx
constructor(props) {
  super(props)
  this.handleClick = this.handleClick.bind(this)  // Har method ke liye
}
```

Hooks mein `this` nahi hai — directly variables access karo:

```tsx
const handleClick = () => setCount(c => c + 1)
```

## Kab Class Components Dekhenge?

1. **Legacy codebases** — Purane projects jo 2019 se pehle banaye gaye, ya React 16.8 pe upgrade nahi kiye
2. **Error Boundaries** — `componentDidCatch` lifecycle method. Hooks mein iska alternative nahi hai. ErrorBoundary abhi bhi class component se hi banaya jaata hai.
3. **Interview questions** — "Class components vs functional components" ek common interview question hai

## Error Boundary — The One Exception

```tsx
class ErrorBoundary extends React.Component<
  { children: React.ReactNode },
  { hasError: boolean; error: Error | null }
> {
  constructor(props: { children: React.ReactNode }) {
    super(props)
    this.state = { hasError: false, error: null }
  }

  static getDerivedStateFromError(error: Error) {
    return { hasError: true, error }
  }

  componentDidCatch(error: Error, info: React.ErrorInfo) {
    console.error('Error caught:', error, info)
  }

  render() {
    if (this.state.hasError) {
      return <h2>Kuch galat ho gaya: {this.state.error?.message}</h2>
    }
    return this.props.children
  }
}
```

Yeh ek case hai jahan class component abhi bhi zaroori hai. Lekin yeh ek hota hai, baaki sab functional.

## Summary

✅ **Class components** — React ka purana tarika (2019 se pehle)  
✅ **Problems solved by Hooks** — logic reuse, scattered lifecycle, `this` confusion, wrapper hell  
✅ **Hooks** — functional components + useState/useEffect/useContext etc.  
✅ **Legacy codebases** mein class components mil sakte hain — recognize karna aana chahiye  
✅ **Error Boundary** — ek exception jahan class component abhi bhi use hota hai  
✅ **Interview tip** — "Hooks ne kya problem solve ki" — yeh difference batana important hai

Ye side note sirf recognition-level hai — aage koi bhi code class components mein nahi likhenge. Agla topic — **1.3 Import Export** — jahan seekhenge ki components ko alag files mein kaise rakhte hain aur ek component doosre component mein kaise use karte hain.
