# 1.12.3 — Step 3: Create `ContactForm` Component

## Where We Left Off

Types and state are set up (1.12.2). Now build the form that adds a contact — one small piece at a time.

We'll build this in small pieces. Each sub-step does ONE thing. Read them in order — don't skip. The favorite checkbox is part of the form from the start (it's just another field).

### Step 3.1 — Controlled Form, Console.log Only (No Parent, No Callback)

**Think:** Before worrying about where data goes, just make a form that tracks what the user types and logs it on submit. One component, one job.

**Create `src/ContactForm.tsx` with only controlled inputs + a submit that console.logs:**

```tsx
import { useState } from "react";
import type { Category } from "./types";

export default function ContactForm() {
  const [name, setName] = useState("");
  const [phone, setPhone] = useState("");
  const [email, setEmail] = useState("");
  const [category, setCategory] = useState<Category>("friend");
  const [favorite, setFavorite] = useState(false);

  const handleSubmit = () => {
    if (name.trim() === "" || phone.trim() === "") {
      console.log("⚠️ Name and phone are required — ignoring");
      return;
    }
    console.log("📝 Form submitted:", { name, phone, email, category, favorite });
  };

  return (
    <div>
      <input value={name} onChange={(e) => setName(e.target.value)} placeholder="Name (required)" />
      <input value={phone} onChange={(e) => setPhone(e.target.value)} placeholder="Phone (required)" />
      <input value={email} onChange={(e) => setEmail(e.target.value)} placeholder="Email (optional)" />
      <select value={category} onChange={(e) => setCategory(e.target.value as Category)}>
        <option value="family">Family</option>
        <option value="work">Work</option>
        <option value="friend">Friend</option>
      </select>
      <label>
        <input type="checkbox" checked={favorite} onChange={(e) => setFavorite(e.target.checked)} />
        Favorite
      </label>
      <button onClick={handleSubmit}>Add Contact</button>
    </div>
  );
}
```

**Console check** – type in inputs, click Add. See `{ name, phone, email, category, favorite }` logged. Empty name/phone → ignored with a warning. The form works on its own; it knows nothing about contacts or App.

To actually see it run, render it from App.tsx:

```tsx
import ContactForm from "./ContactForm";

export default function App() {
  return (
    <div>
      <h1>Contact Book</h1>
      <ContactForm />
    </div>
  );
}
```

No `onAdd` prop yet (introduced in 3.3). The form renders and its console.log fires on submit.

### Step 3.2 — Why the Parent Must Own the Contacts

**Think:** The form now logs data. But where should the contacts array live? If `ContactForm` keeps `contacts` in its own state, App can't display them, filter them, or delete them — the data is trapped inside the form. The form's input state is *temporary* (only needed while typing); the contacts list is *shared* (needed by the whole app). So: App owns `contacts`, the form owns the typing.

**The rule (1.5.4):** state lives in the component that needs it. If multiple components need it (or the parent needs to pass it down), lift it up. Here, only App needs the contacts array, so App owns it. The form just collects input and hands it over.

### Step 3.3 — Callback Prop: Proof of Connection (Console.log Only, No Interface Yet)

**Think:** Before passing real data, prove the child can talk to the parent. Add an `onAdd` prop to ContactForm. For now, no data — just a signal. If the log fires when you submit, the connection works.

**First, what is a "prop"?** A prop is just an argument to a component function. `ContactForm({ onAdd })` receives `onAdd` like any function receives an argument. We can type it inline — no `interface` keyword yet:

```tsx
import { useState } from "react";
import type { Category } from "./types";

export default function ContactForm({ onAdd }: { onAdd: () => void }) {
  const [name, setName] = useState("");
  const [phone, setPhone] = useState("");
  const [favorite, setFavorite] = useState(false);

  const handleSubmit = () => {
    if (name.trim() === "" || phone.trim() === "") {
      console.log("⚠️ Name and phone are required — ignoring");
      return;
    }
    console.log("📝 Form collected:", name, phone, favorite);
    onAdd();   // tell the parent: "I submitted"
  };

  return (
    <div>
      <input value={name} onChange={(e) => setName(e.target.value)} placeholder="Name (required)" />
      <input value={phone} onChange={(e) => setPhone(e.target.value)} placeholder="Phone (required)" />
      <label>
        <input type="checkbox" checked={favorite} onChange={(e) => setFavorite(e.target.checked)} />
        Favorite
      </label>
      <button onClick={handleSubmit}>Add Contact</button>
    </div>
  );
}
```

Notice `{ onAdd }: { onAdd: () => void }` — the part after the colon is an inline type for the props object. `onAdd: () => void` means "a function that takes nothing and returns nothing." We wrote the type right there, inline. No `interface` keyword.

**In `src/App.tsx`, pass a handler that only logs:**

```tsx
import ContactForm from "./ContactForm";

export default function App() {
  const handleAdd = () => {
    console.log("✅ Parent received the submit signal");
  };

  return (
    <div>
      <h1>Contact Book</h1>
      <ContactForm onAdd={handleAdd} />
    </div>
  );
}
```

**Console check** – submit the form. You should see both logs: "📝 Form collected: ..." then "✅ Parent received the submit signal". The child talked to the parent. Connection proven.

### Step 3.4 — What is an `interface` for Props?

**Think:** Inline types like `{ onAdd: () => void }` work, but they get long and ugly when a component has many props. TypeScript lets us give that shape a **name** using the `interface` keyword. An interface is just a named object type.

**Tiny standalone example — a `Greeting` component:**

```tsx
// Imagine a component that shows a name
interface GreetingProps {
  name: string;          // a prop called "name", type string
  age?: number;          // optional prop (the ? means "may be absent")
}

function Greeting({ name, age }: GreetingProps) {
  return <p>Hello, {name}! {age && `You are ${age}.`}</p>;
}

// Usage:
<Greeting name="Vin" />            // ✅ age is optional
<Greeting name="Vin" age={25} />   // ✅
<Greeting age={25} />              // ❌ Error: "name" is required
```

Breaking down the syntax:
- `interface GreetingProps { ... }` — declares a new type named `GreetingProps` describing an object's shape.
- `name: string;` — the object has a `name` field of type `string`.
- `age?: number;` — the `?` makes it optional (from 1.5.3).
- `function Greeting({ name, age }: GreetingProps)` — the component receives a props object and we tell TypeScript "this props object has shape `GreetingProps`."

So an `interface` for props is just: "this component's props object has these fields with these types." Nothing more. We'll use this pattern for `ContactFormProps` next.

### Step 3.5 — Real Callback: Pass Data (Interface Now Has Params)

**Think:** Connection works (3.3). Interface syntax is clear (3.4). Now combine: the `onAdd` prop carries data. App receives it and creates the contact. The form's job ends at "hand over the data."

**Update `src/ContactForm.tsx` — full form, prop carries data:**

```tsx
import { useState } from "react";
import type { Category } from "./types";

interface ContactFormProps {
  onAdd: (name: string, phone: string, email: string, category: Category, favorite: boolean) => void;
}

export default function ContactForm({ onAdd }: ContactFormProps) {
  const [name, setName] = useState("");
  const [phone, setPhone] = useState("");
  const [email, setEmail] = useState("");
  const [category, setCategory] = useState<Category>("friend");
  const [favorite, setFavorite] = useState(false);

  const handleNameChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    setName(e.target.value);
  };

  const handlePhoneChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    setPhone(e.target.value);
  };

  const handleEmailChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    setEmail(e.target.value);
  };

  const handleCategoryChange = (e: React.ChangeEvent<HTMLSelectElement>) => {
    setCategory(e.target.value as Category);
  };

  const handleSubmit = () => {
    if (name.trim() === "" || phone.trim() === "") {
      console.log("⚠️ Name and phone are required — ignoring");
      return;
    }
    onAdd(name.trim(), phone.trim(), email, category, favorite);
    setName("");
    setPhone("");
    setEmail("");
    setCategory("friend");
    setFavorite(false);
  };

  return (
    <div>
      <input value={name} onChange={handleNameChange} placeholder="Name (required)" />
      <input value={phone} onChange={handlePhoneChange} placeholder="Phone (required)" />
      <input value={email} onChange={handleEmailChange} placeholder="Email (optional)" />
      <select value={category} onChange={handleCategoryChange}>
        <option value="family">Family</option>
        <option value="work">Work</option>
        <option value="friend">Friend</option>
      </select>
      <label>
        <input type="checkbox" checked={favorite} onChange={(e) => setFavorite(e.target.checked)} />
        Favorite
      </label>
      <button onClick={handleSubmit}>Add Contact</button>
    </div>
  );
}
```

**`as Category`** – the select's value is `string`, but state expects `Category`. We assert it's a `Category` (we know the options are valid). This is a type assertion.

**In `src/App.tsx`, `handleAdd` creates the contact:**

```tsx
import { useState } from "react";
import type { Contact, Category } from "./types";
import ContactForm from "./ContactForm";

export default function App() {
  const [contacts, setContacts] = useState<Contact[]>([]);

  const handleAdd = (name: string, phone: string, email: string, category: Category, favorite: boolean) => {
    const newContact: Contact = {
      id: Date.now(),
      name,
      phone,
      email: email.trim() === "" ? undefined : email.trim(),
      category,
      favorite,
    };
    setContacts([...contacts, newContact]);
    console.log("✅ Contact added:", newContact);
  };

  return (
    <div>
      <h1>Contact Book</h1>
      <ContactForm onAdd={handleAdd} />
      <p>{contacts.length} contact{contacts.length !== 1 ? "s" : ""}</p>
    </div>
  );
}
```

`Date.now()` – a simple way to generate a unique ID. Milliseconds since 1970 — almost guaranteed unique. `email` is set to `undefined` when empty (so the optional field stays absent, not an empty string).

**Console check** – add a contact, see it logged. Type in inputs, watch them update. Empty name/phone → ignored with a warning. Check "Favorite" before adding → new contact's `favorite` is `true`.
