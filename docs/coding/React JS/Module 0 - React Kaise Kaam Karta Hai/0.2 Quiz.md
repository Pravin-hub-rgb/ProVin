
## MCQ

Q: What is the full form of JSX?
A. JavaScript XML
B. JavaScript Syntax
C. Java Source Extension
D. JSON XML Entity
> A. JSX stands for JavaScript XML. It is a syntax extension for React that lets you write HTML-like syntax inside JavaScript. It's neither HTML nor plain JavaScript — it's a bridge between the two.

---

Q: Why can't browsers execute JSX directly?
A. `<` is an unexpected token to JavaScript engines
B. A different browser is needed for JSX
C. Browsers only support ES6 features
D. JSX is an encrypted format that can't be decoded
> A. `<` in `<h1>` is an unexpected token for the browser's JavaScript engine — in JavaScript syntax, `<` has no meaning. That's why JSX must be compiled into `React.createElement()` calls first, which the browser understands.

---

Q: What does Babel transform JSX into?
A. `React.createElement()` calls
B. Real DOM element objects
C. Webpack module bundles
D. Inline HTML template strings
> A. Babel compiles JSX into `React.createElement(type, props, ...children)` calls. For example, `<h1>Hello</h1>` becomes `React.createElement("h1", null, "Hello")`. It does NOT convert to Real DOM (B) — that's React's final output, not a compilation step.

---

Q: When returning two or more elements in JSX, what is required?
A. Wrap in a parent element or Fragment
B. Create a separate component for each element
C. Use commas between elements in the return
D. Write the `return` keyword for each element
> A. `React.createElement()` can only return one root element, so multiple siblings must be wrapped in a parent. You can use `<div>` or a Fragment `<>...</>`. Fragments are better because they don't create an extra DOM node.

---

Q: In `React.createElement(type, props, ...children)`, what does the `type` parameter represent?
A. An HTML tag string (like "div", "h1") or a React component
B. Only built-in HTML elements like div, span, h1, p
C. Only custom React components that you've created
D. A CSS selector string like ".container" or "#app"
> A. You can pass two things as `type`: (1) an HTML tag string — `"div"`, `"h1"`, `"p"`, or (2) a React component — `Button`, `Navbar`. B (only built-in HTML elements) is incorrect. C (only custom components) is incorrect. D (CSS selector) is incorrect — that's not what type is.

---

Q: What is the purpose of `{}` curly braces in JSX?
A. To render JavaScript expressions
B. To pass string values only
C. To hide HTML comments
D. To define CSS classes
> A. You can put any JavaScript expression inside curly braces: `{2 + 2}`, `{name.toUpperCase()}`, `{isLoggedIn ? "Hi" : "Login"}`, `{items.map(...)}`. B (only strings) is incorrect — numbers, booleans, expressions all work. C and D are irrelevant distractors.

---

Q: Which of these is the correct difference between HTML and JSX attributes?
A. HTML uses `class`, JSX uses `className` — because `class` is a reserved word in JS
B. HTML uses `onClick`, JSX uses `onclick` — because JSX uses lowercase
C. HTML uses `style` as a string, JSX uses `style` as an object
D. HTML and JSX have identical attributes
> A. This is correct. `class` is a reserved keyword in JavaScript (used for defining classes), so JSX uses `className`. B is incorrect — actually it's the opposite: HTML uses lowercase (`onclick`) and JSX uses camelCase (`onClick`). C is also incorrect — in HTML style is a string, in JSX it's a JavaScript object.

---

Q: What is the biggest advantage of using Fragment `<>...</>`?
A. It doesn't create an extra DOM node
B. It automatically re-renders the component
C. It auto-passes props to child components
D. It only works in development mode
> A. The biggest advantage of Fragments is that you can group elements without creating an extra DOM node. If you used `<div>`, an extra `<div>` would appear in the DOM. Fragments compile to `React.createElement(React.Fragment, null, ...)`. B, C, and D are all incorrect.

---

Q: If you skip JSX and use `React.createElement()` directly, what's the problem?
A. Code is harder to read and the UI structure is less clear
B. React components stop being functional, you must use class components
C. The browser can't execute createElement calls
D. Virtual DOM is disabled
> A. `createElement` technically works, but for deeply nested UI, the code becomes hard to read quickly. JSX looks like HTML, so the UI structure is visually clear. B, C, and D are all technically incorrect — `createElement` is normal React code.

---

Q: Why can't JSX be called a "template language"?
A. Because JSX has the full power of JavaScript — any expression can be used
B. Because template languages are only server-side, JSX is client-side
C. Because JSX uses XML-based syntax, template languages don't
D. Because template languages don't compile, JSX is compiled by Babel
> A. Template languages (like Handlebars, EJS) have their own limited syntax for loops and conditions. In JSX, you use direct JavaScript — `map()`, ternary operators, `filter()`, anything. C and D aren't entirely wrong, but they're not the primary reason JSX isn't a template language.

## TrueFalse

Q: JSX is a variant of HTML that browsers understand directly, so no compilation is needed.
- True
- False
> False. JSX is NOT HTML — it looks like HTML but is compiled into JavaScript. Browsers don't understand JSX directly. Babel (or another compiler) must transform JSX into `React.createElement()` calls before the browser can execute it.

---

Q: `React.createElement("div", null, "Hello World")` returns a plain JavaScript object containing `type`, `props`, and `children`.
- True
- False
> True. `createElement` returns an object — `{ type: "div", props: { children: "Hello World" } }`. This object is a node in the Virtual DOM. React builds a whole tree of these objects and manages them.

---

Q: JSX is only used in the React framework — no other library or framework supports JSX.
- True
- False
> False. JSX is not exclusive to React. Frameworks like Preact, Solid.js, and Vue (with JSX plugin) also support JSX. JSX is a syntax extension that any framework can use. (React 17+'s automatic JSX transform also makes this more accessible.)

---

Q: In JSX, the `style` attribute takes a CSS string just like HTML, e.g. `style="color: red"`.
- True
- False
> False. In JSX, `style` takes a JavaScript object — `style={{ color: "red" }}`. In HTML, it's a string (`"color: red"`). The double braces: the outer `{}` is a JSX expression, the inner `{}` is a JavaScript object. Properties use camelCase (`fontSize`, not `font-size`).

---

Q: `{items.map(item => <li key={item.id}>{item.name}</li>)}` is valid JSX — arrays can be rendered using `map()`.
- True
- False
> True. Rendering arrays of elements is a common pattern in React. `map()` returns a JSX element for each item, and React automatically renders the array. The `key` prop is required here (detailed in 0.3). Any JavaScript expression can be placed inside `{}`.

---

Q: Using Fragment `<>...</>` instead of `<div>` means the browser won't create an extra DOM node.
- True
- False
> True. This is a key advantage of Fragments — you can group elements without an extra wrapper in the DOM. If you used `<div>`, an extra `<div>` would be added to the DOM. Fragments only output the children — no extra parent node. Fragments internally become `React.createElement(React.Fragment, null, ...)`.

## ShortAnswer

Q: Explain the full JSX compilation flow — from writing JSX to the Virtual DOM node.

<details>
<summary>Sample Answer</summary>

**Step-by-step flow:**

1. **You write JSX:**
   ```jsx
   const element = (
     <div className="container">
       <h1>Hello</h1>
     </div>
   );
   ```

2. **Babel compiles** — JSX is transformed into `React.createElement()` calls:
   ```js
   const element = React.createElement(
     "div",
     { className: "container" },
     React.createElement("h1", null, "Hello")
   );
   ```

3. **createElement returns** — a plain JavaScript object:
   ```js
   {
     type: "div",
     props: {
       className: "container",
       children: {
         type: "h1",
         props: { children: "Hello" }
       }
     }
   }
   ```

4. **This object is a Virtual DOM node** — React builds a tree of these objects and renders them into the Real DOM.

**Analogy:** JSX is your native language. Babel is the translator. `createElement()` is the intermediate structured format. The Virtual DOM node is the final data structure that the computer can process.

**Connection to 0.1 (Virtual DOM):** We learned in 0.1 that the Virtual DOM is a tree of lightweight JavaScript objects. `createElement` returns exactly those objects. That's how JSX connects to the Virtual DOM — JSX → createElement → Virtual DOM node.

</details>

Q: What are the differences between JSX and regular HTML? Give 4 important ones.

<details>
<summary>Sample Answer</summary>

| Feature | HTML | JSX |
|---------|------|-----|
| `class` | `class="container"` | `className="container"` — because `class` is a reserved word in JS |
| `for` | `<label for="email">` | `<label htmlFor="email">` — same reason |
| Events | `onclick`, `onsubmit` | `onClick`, `onSubmit` — camelCase convention |
| Style | `style="color: red"` (string) | `style={{ color: "red" }}` (JavaScript object) |
| JS expressions | Can't embed | Any expression inside `{}` — math, ternary, map, function calls |
| Browser support | Browser understands directly | Must be compiled by Babel first |

**4 main differences:**

1. **Attributes:** HTML uses `class`, JSX uses `className` — because `class` is a reserved keyword in JavaScript. Same for `for` → `htmlFor`.
2. **Events:** HTML uses lowercase (`onclick`, `onsubmit`), JSX uses camelCase (`onClick`, `onSubmit`).
3. **Style:** HTML uses a CSS string (`"color: red"`), JSX uses a JavaScript object (`{{ color: "red" }}`). Double braces — outer `{}` for JSX expression, inner `{}` for JavaScript object.
4. **Dynamic content:** HTML is static — you can only write what HTML allows. In JSX, you can embed any JavaScript expression inside `{}` — math, ternary operators, `map()`, function calls — anything.

**Bonus — Common misconception:** JSX looks like HTML but is actually JavaScript that compiles into `createElement` calls. So "JSX is not HTML" is the most important rule to remember.

</details>

Q: What is the structure of `React.createElement()` and how does it connect to the Virtual DOM? Explain with a real-life analogy.

<details>
<summary>Sample Answer</summary>

**Structure:** `React.createElement(type, props, ...children)`

| Parameter | Meaning | Example |
|-----------|---------|---------|
| `type` | Which element to create | `"div"`, `"h1"`, `Button` |
| `props` | Attributes and properties | `{ className: "card" }` |
| `children` | Inner elements or text | `"Hello"` or `createElement(...)` |

**Example:**
```jsx
// JSX
<h1 className="title">Hello</h1>

// createElement
React.createElement("h1", { className: "title" }, "Hello")

// Returned object (Virtual DOM node)
{
  type: "h1",
  props: {
    className: "title",
    children: "Hello"
  }
}
```

**Virtual DOM connection:** We learned in 0.1 that the Virtual DOM is a tree of lightweight JavaScript objects. `React.createElement()` returns exactly those objects. Each call creates a node, and nesting builds a tree.

```
createElement("div", null,
  createElement("h1", null, "Title"),
  createElement("p", null, "Desc")
)
// Returns tree:
{
  type: "div",
  props: {
    children: [
      { type: "h1", props: { children: "Title" } },
      { type: "p", props: { children: "Desc" } }
    ]
  }
}
```

**Analogy:** Imagine you're ordering food at a restaurant.
- **JSX:** You tell the waiter — "I want a pizza with extra cheese and garlic bread" (high-level, readable language).
- **createElement:** The waiter translates it to the kitchen — "1 pizza, extra cheese, 1 garlic bread" (structured order).
- **Virtual DOM node:** The chef writes the order on a card — `{ item: "pizza", toppings: ["cheese"], side: "garlic bread" }` (processable data structure).

The waiter (`createElement`) converts your human-friendly language (JSX) into a kitchen-friendly format (Virtual DOM node), and the chef (React) uses that card to make the final dish (Real DOM).

</details>
