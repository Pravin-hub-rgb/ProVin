0.3 mein humne dekha ki React reconciliation ke through Virtual DOM trees ko compare karta hai. Lekin 0.3 ki transition mein ek problem hint ki thi — **jab React reconciliation kar raha hota hai, browser freeze ho jata hai.** React 15 tak, reconciliation synchronous tha — ek baar shuru hui toh poora kaam khatam hone tak browser freeze. 

React 16 mein ek naya internal engine aaya jisne ye problem solve ki — **Fiber Architecture.**

# Fiber Architecture (Halka Level)

## Problem — Synchronous Reconciliation

React 15 tak, reconciliation synchronous tha. Matlab — ek baar reconciliation start hui, toh browser tab tak freeze rahega jab tak poora kaam khatam na ho.

```
Browser Main Thread:

[🟦 User Click] [🟩 React Reconciliation — 50ms] [🟥 Browser Freeze ❌] [🟨 Animation Lag]
```

50ms lag raha hai? Itna time browser kisi aur kaam ke liye de sakta hai nahi. Iski wajah se:
- Animations ruk jaati hain (laggy feel)
- Typing delay ho jata hai (input slow)
- Scroll smooth nahi hota

## Kya Chahiye Tha?

Ek aisa system jo:
1. Kaam ko **chhote pieces** mein tod de
2. Beech mein **rok sake** agar kuch urgent aaye
3. Priority decide kare — "ye important hai pehle karo, ye baad mein"
4. Browser ko bhi **saans lene de** (frame skip nahi ho)

## Fiber Kya Hai?

Fiber ek **JavaScript object** hai — ek unit of work. Har component ke liye ek Fiber node hota hai. React 15 tree ko recursively process karta tha, Fiber ek linked-list based approach use karta hai.

Socho Fiber ko ek "work package" ki tarah — har package mein itna kaam hai jo ek frame ke andar complete ho sakta hai.

```
React 15:          [━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━] — ek saath, ruk nahi sakta

React 16 (Fiber):  [━━][━━][━━][━━][━━][━━][━━][━━][━━] — chhote pieces, beech mein ruk sakta hai
```

## Fiber Kaise Kaam Karta Hai?

### 1. Work as a Tree of Fibers

React har element ke liye ek Fiber node banata hai. Ye nodes ek linked-list se connected hote hain:

```jsx
<App>
  <header>
    <h1>Title</h1>
  </header>
  <main>
    <p>Content</p>
  </main>
</App>
```

React iska ek **Fiber Tree** banata hai jisme har node ko teen links se connect kiya jaata hai:
- **child** — pehla child node
- **sibling** — agla sibling node
- **return** — parent node (wapas jaane ke liye)

```
          App Fiber
         /          \
   header Fiber    main Fiber
      |               |
   h1 Fiber        p Fiber
```

Ye linked-list structure React ko allow karta hai ki woh **interrupt** kar sake — ek node process karo, check karo ki koi urgent kaam toh nahi, phir agla node process karo.

### 2. Two Phases — Render + Commit

Fiber architecture mein kaam do phases mein bata hota hai:

**Phase 1: Render (aka "Reconciliation Phase")**
- Virtual DOM tree traverse karo
- Changes calculate karo (diffing)
- **Interruptible hai** — beech mein rok sakte ho
- Side-effect free hai (DOM change nahi hota abhi)

**Phase 2: Commit**
- Calculate kiye gaye changes real DOM mein apply karo
- **Not interruptible** — ek baar shuru kiya toh poora karna padega
- Lifecycle methods call hote hain (`componentDidMount`, `useEffect`)

```
Render Phase (interruptible):      Commit Phase (not interruptible):
[Fiber1] [Fiber2] [Fiber3] [Fiber4]  →  [DOM Update 💥]
    ↺ can pause here                    ↺ cannot pause
```

### 3. Priority Levels

React Fiber different priorities assign karta hai:

| Priority | Example |
|----------|---------|
| 🔴 **Immediate** | User input, click events |
| 🟡 **High** | Animation, transitions |
| 🟢 **Normal** | Normal state updates |
| 🔵 **Low** | Data fetching, lazy loading |
| ⚫ **Idle** | Pre-rendering, offscreen content |

Socho — agar user kuch type kar raha hai (Immediate priority), aur saath mein koi animation chal rahi hai (High priority), toh React pehle user input process karega, phir animation, phir baki kaam.

### 4. Cooperative Scheduling

React browser ke saath "cooperate" karta hai. Jaise:

```
Frame 1:  [React work (5ms)] [Browser idle (11ms)] [Render next frame]
                                     ↺ React wait karega
Frame 2:  [React work (5ms)] [Browser work (8ms)]  [React again...]
```

React `requestIdleCallback` jaisa concept use karta hai (but internally apna implementation). Jab browser ko lagega ki "abhi kuch urgent nahi hai", tab React bache hue kaam karega.

> **Analogy — Office Work:** Socho tum ek project kar rahe ho jisme 10 tasks hain. Fiber se pehle — ek baar mein saare 10 tasks complete karo, beech mein koi call aaye toh ignore karo. Fiber ke saath — ek task karo, check karo ki urgent email toh nahi aayi, phir agla task karo. Urgent kaam (client call = user input) pehle, normal kaam (documentation = background rendering) baad mein.

## Fiber Tumhe Kya Karna Hai?

**Kuch nahi.** Fiber ek internal implementation detail hai. Tum React components waise likhoge jaise pehle likhte the. Fiber sirf framework ke andar hai — tumhe iska code likhna nahi hai.

Par Fiber ko samajhne ka fayda:
- Interview mein poochhte hain — "React 16 mein kya badla?"
- Performance issues debug karte waqt samajh aata hai ki "kyun ye render priority kam hai"
- React ka mental model strong hota hai — "acha, isliye ye async behave kar raha hai"


> ❌ Fiber **kuch naya syntax nahi hai** — internal implementation change hai, API same hai
> ❌ Fiber **asynchronous rendering nahi hai** — ye cooperative scheduling hai (concurrent mode ka foundation)
> ❌ Fiber **React 16+ ke baad aapko kuch alag likhna nahi padta** — same `useState`, same `useEffect`
> ❌ Fiber **sirf React ke liye hai** — koi general-purpose library nahi hai

3. Render phase aur Commit phase mein kya fark hai?

<details>
<summary>Sample Jawab</summary>

Is phase mein DOM change nahi hota. Commit phase mein calculated changes real DOM mein apply hote hain. Ye **not interruptible** hai — ek baar shuru kiya toh poora karna padega. useEffect aur lifecycle methods commit phase mein call hote hain.

<details>

Isse React decide kar sakta hai ki kaunsa kaam pehle karna hai. User input sabse high priority, background pre-rendering sabse low priority.

5. "Cooperative scheduling" ka kya matlab hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Matlab React browser ke saath cooperate karta hai. React apna kaam chhote pieces mein karta hai aur har piece ke baad browser ko control wapas deta hai — "ab tu apna kaam kar le (rendering, event handling), phir main agla piece lunga." Isse browser freeze nahi hota aur user experience smooth rehta hai.

</details>

---

Fiber ne rendering ko interruptible banaya. Lekin React aur bhi smart hai — jab ek event handler mein multiple state updates ho rahi hain, toh React unhe ek saath group karta hai. Ek aur optimization hai — **Batching.** Chalo 0.5 mein dekhte hain ki state updates kaise batch hote hain.
