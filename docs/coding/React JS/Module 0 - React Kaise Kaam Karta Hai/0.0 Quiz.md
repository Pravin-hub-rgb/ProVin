# 0.0 Quiz — React Kya Hai aur Ye Course Kaise Chalega

## MCQ

Q: React ka "Declarative approach" ka matlab kya hai?
A. Tum outcome declare karte ho, React decide karta hai kaise karna hai
B. Tum DOM manipulation step-by-step khud likhte ho
C. Tum server-side code likhte ho jo HTML generate karta hai
D. Tum template language use karte ho HTML ke andar
> A. Declarative ka matlab hai — tum batate ho "kya dikhna chahiye", React decide karta hai "kaise karna hai". Imperative approach (B) mein tum khud DOM update karte ho.

---

Q: Jab app chhoti hoti hai toh vanilla JS DOM manipulation theek kaam karta hai. Lekin jab app badi hoti hai toh problem kyun aati hai?
A. Kyunki vanilla JavaScript slow ho jata hai
B. Kyunki code messy aur bug-prone ho jata hai
C. Kyunki browser vanilla JS support karna band kar deta hai
D. Kyunki DOM manipulation sirf mobile apps mein kaam karta hai
> B. Vanilla JS mein DOM manipulation manual hai — `document.getElementById()`, `element.textContent`, etc. 50-100 components ki app mein ye approach maintain mushkil ho jata hai. React ne declarative approach di — tum UI declare karte ho, React DOM handle karta hai.

---

Q: React components ka sabse important feature kya hai?
A. Components HTML ko CSS se style karte hain
B. Components sirf server-side render hote hain
C. Components ek baar likhe jaate hain aur reuse ho sakte hain
D. Components database se directly data lete hain
> C. Components ka biggest advantage reusability hai — ek baar Button component likho, 100 jagah use karo. Jaise Lego blocks.

---

Q: React ek UI library hai. Library aur framework mein kya fark hai?
A. Library scope limited hota hai, framework sab kuch provide karta hai
B. Library sirf mobile apps mein use hoti hai, framework web mein
C. Library old technology hai, framework modern hai
D. Library aur framework mein koi fark nahi hai
> A. Library sirf specific kaam ke liye hoti hai (React sirf UI). Framework ek complete package hota hai (Angular, Next.js) jisme routing, data fetching, etc. built-in aata hai.

---

Q: React ke baare mein kaunsa statement GALAT hai?
A. React ek component-based architecture use karta hai
B. React ek full-stack framework hai jo backend provide karta hai
C. React ek declarative approach use karta hai
D. React ko Meta (Facebook) maintain karta hai
> B. React sirf frontend UI library hai, full-stack framework nahi. Backend features Next.js (React-based framework) provide karta hai.

---

Q: Ek software hai jo UI, routing, data fetching, authentication — sab kuch built-in provide karta hai. Ye kya kehlayega?
A. Library
B. Framework
C. Database
D. API
> B. Framework ek complete package hota hai — sab kuch built-in. Library sirf specific kaam ke liye hoti hai. (React = library, Next.js/Angular = framework)

## TrueFalse

Q: React mein tumhe har DOM operation khud likhna padta hai jaise vanilla JavaScript mein likhte ho.
- True
- False
> False. Vanilla JS mein tum DOM operations khud likhte ho. React mein tum sirf UI declare karte ho (declarative), React khud DOM operations handle karta hai.

---

Q: React ko ek "chhoti app" ke liye use karna overkill ho sakta hai.
- True
- False

## ShortAnswer

Q: "Declarative approach" ko apne words mein explain karo. Imperative approach se ye kyun better hai?

<details>
<summary>Sample Answer</summary>

**Declarative approach** — tum outcome declare karte ho, implementation React handle karta hai.

Simple example:

**Imperative (vanilla JS):**
```js
const btn = document.getElementById("btn");
const msg = document.getElementById("message");
btn.addEventListener("click", () => {
  msg.textContent = "Clicked!";
  msg.style.color = "blue";
});
```
Tum khud bata rahe ho — "ye element dhundo, ye change karo, ye color set karo."

**Declarative (React):**
```jsx
function App() {
  const [clicked, setClicked] = useState(false);
  return (
    <div>
      <button onClick={() => setClicked(true)}>Click</button>
      {clicked && <p style={{color: "blue"}}>Clicked!</p>}
    </div>
  );
}
```
Tum bas bata rahe ho — "clicked true hai toh ye dikhao." React khud decide karta hai DOM kaise update karna hai.

Declarative better kyun hai? Code predictable, maintainable aur debug-friendly. Ek jagah change karo, React automatically woh jagah DOM mein bhi change karta hai — tumhe koi `getElementById` call nahi likhni padti.

**Analogy:** Taxi mein driver ko "Mujhe CP le chalo" bolte ho (declarative). Bola nahi ki "Left lo, right lo, 200 meter jaao, phir U-turn lo" (imperative).

</details>

Q: React components kyun useful hain? Koi 2 reasons do.

<details>
<summary>Sample Answer</summary>

**1. Reusability (DRY Principle):** Ek baar component likho, kahi bhi use karo. Jaise ek `Button` component bana liya — login form mein, signup form mein, settings page mein — har jagah same button, lekin alag props ke saath. Code duplicate nahi karna padta.

**2. Isolation:** Har component apne scope mein kaam karta hai. Ek component mein bug doosre component ko affect nahi karta. Jaise agar `Navbar` mein problem hai toh `Footer` usse affected nahi hota. Isse debugging easy hoti hai.

**Analogy:** Kitchen ke alag-alag appliances — toaster, microwave, fridge. Ek kharab ho gaya toh baaki kaam karte rehte hain. Agar sab ek machine mein hote, toh ek part kharab = poora system band.

</details>
