# 0.6 Quiz — Synthetic Events

## MCQ

Q: Jab React mein tum `<button onClick={handleClick}>` likhte ho, toh actually event listener kaise laga hota hai?
A. React har button ke HTML attribute mein onclick directly inject kar deta hai
B. React root element par ek listener lagata hai aur bubbling se event catch karta hai
C. React har button ke liye alag addEventListener call karta hai build time pe
D. React server-side event listener lagata hai jo client ko nahi aata
> B. React har element pe alag addEventListener nahi lagata. Woh root element (<div id="root">) par ek listener lagata hai. Jab button click hota hai, event bubble hokar root tak pahunchta hai, aur React decide karta hai ki kis component ka onClick chalana hai.

---

Q: Native Event aur SyntheticEvent mein kya fark hai?
A. Native Event React ka banaya hota hai, SyntheticEvent browser ka — dono kaam same karte hain
B. Native Event browser ka original event hai, SyntheticEvent React ka wrapper hai jo cross-browser consistency deta hai
C. Native Event sirf server-side hota hai, SyntheticEvent sirf client-side hota hai
D. Native Event aur SyntheticEvent ek hi cheez hain — bas alag alag naam hain
> B. Native Event browser ka original event hai (addEventListener se milta hai). SyntheticEvent React ka wrapper object hai jo native event ke upar banta hai — event.target, event.preventDefault() sab browsers mein same kaam kare, ye ensure karta hai.

Q: React ne alag se SyntheticEvent system kyun banaya?
A. Kyunki browser ke native events bahut slow hote hain
B. Kyunki React ko apne khud ke events chahiye the jo backend pe bhi kaam karein
C. Kyunki different browsers mein same event ka behavior different hota tha — cross-browser consistency ke liye
D. Kyunki browser addEventListener support karta hi nahi, isliye React ne apna event system banaya
> C. Purane browsers mein same event ka alag behavior tha — kisi mein event.target, kisi mein event.srcElement. React ne SyntheticEvent banaya taaki developer ko har browser mein same properties milein. Jaise jQuery ne cross-browser consistency di thi, waise React ne SyntheticEvent ke through di.

Q: Event Delegation ka kya matlab hai?
A. React har element ke liye alag listener banata hai aur unhe prioritize karta hai
B. React root element par ek listener rakhta hai aur decide karta hai ki event kiske liye hai
C. React server-side events ko delegate karta hai client-side components ko
D. React event listeners ko child components se parent components mein copy karta hai
> B. Event Delegation means React har button/input pe alag addEventListener nahi lagata. Woh root element (<div id="root">) par ek listener lagata hai. Jab event bubble hokar root tak pahunchta hai, React identify karta hai ki kaunsa component handler chalana hai. Isse memory efficient hai.

---

Q: Event Bubbling ka matlab kya hai?
A. Event parent element se child element tak travel karta hai
B. Event child element se parent element tak travel karta hai
C. Event ek hi element par rukta hai, travel nahi karta
D. Event random order mein saare elements ko visit karta hai
> B. Event Bubbling browser ka mechanism hai jisme event sabse pehle target element par fire hota hai, phir uske parent, phir uske parent's parent — aise root tak jaata hai. React event delegation isi bubbling behavior ka fayda uthata hai.

Q: SyntheticEvent mein `event.nativeEvent` se kya milta hai?
A. React ka khud ka internal state object
B. Browser ka original native event object
C. Component ka props object
D. DOM element ka reference jo event trigger kiya
> B. SyntheticEvent ke andar `nativeEvent` property mein browser ka original native event object milta hai — jaise MouseEvent, KeyboardEvent, etc. SyntheticEvent wrapper hai, nativeEvent asli browser event hai. Normally SyntheticEvent ki properties enough hoti hain, nativeEvent rarely chahiye hota.

Q: Event Pooling kya thi?
A. Event objects ko database mein store karna baad mein use karne ke liye
B. Event handler ke baad SyntheticEvent object ko clear karke future events ke liye reuse karna
C. Multiple events ko ek saath group karna aur ek hi listener se handle karna
D. Events ko queue mein daalna aur ek thread se process karna
> B. Event Pooling React 17 ka optimization tha. Jaise hi event handler finish hota, React SyntheticEvent object ki saari properties null kar deta tha aur future events ke liye reuse kar leta tha. Isse memory allocation kam hoti thi, lekin asynchronous code mein event null ho jaata tha.

---

Q: React 17 mein `event.persist()` kya karta tha?
A. Event ko DOM mein permanently attach kar deta tha
B. SyntheticEvent object ko pooling se bahar nikalta tha taaki clear na ho
C. Event handler ko har browser ke liye alag version banata tha
D. Event ki properties ko localStorage mein save kar deta tha
> B. event.persist() React 17 mein SyntheticEvent ko pooling pool se bahar nikal deta tha. Iska matlab React us object ko clear nahi karta tha aur asynchronous code (setTimeout, Promise) mein safely access ho sakta tha. React 18 mein pooling nahi hai, isliye persist() ki zaroorat nahi.

## TrueFalse

Q: Event Bubbling aur Event Delegation dono React ke concepts hain — browser ka inmein koi role nahi hai.
- True
- False
> False. Event Bubbling browser ka mechanism hai — event child se parent tak travel karta hai. Event Delegation React ki technique hai jo is browser behavior ka fayda uthata hai. Bina browser ke bubbling mechanism ke, Event Delegation possible nahi hai.

---

Q: React 18 mein SyntheticEvent normal JavaScript object ki tarah behave karta hai — asynchronous code mein freely access kar sakte hain.
- True
- False
> True. React 18 mein Event Pooling hata di gayi hai. Ab har event ke liye naya SyntheticEvent object banta hai aur wahi memory mein rehta hai jab tak JavaScript usse garbage collect nahi kar leti. Isliye setTimeout, Promise, async/await sab mein bina persist() ke event access kar sakte hain.

---

Q: Agar tum React ke event system ke bajaye direct addEventListener use karte ho, toh bhi tumhe SyntheticEvent milta hai.
- True
- False
> False. SyntheticEvent sirf React ke event handlers (onClick, onChange, onSubmit, etc.) mein available hai. Direct addEventListener se tumhe browser ka native event milega — SyntheticEvent nahi. Isliye React ke event system ko prefer karna chahiye.

---

Q: React 17 mein agar event handler ke andar synchronous code likha ho toh bhi event pooling ki problem aati thi.
- True
- False
> False. Event pooling ki problem sirf asynchronous code mein aati thi — setTimeout, Promise, async/await. Synchronous code mein event handler khatam hone se pehle hi saari properties access ho jaati hain, isliye koi problem nahi thi. Problem tab thi jab handler khatam hone ke baad event access karna chaho.

## ShortAnswer

Q: Explain the flow of a click event in React — from user clicking a button to your onClick handler running. Include Event Delegation and Bubbling.

<details>
<summary>Sample Answer</summary>

**Step-by-step flow:**

1. User clicks a button inside a React app
2. Browser generates a native click event
3. Event bubbles up — button → div → body → document → root (`<div id="root">`)
4. React's single event listener on root catches this event
5. React identifies: "ye click kis component ka tha? Kaunsa onClick handler call karna hai?"
6. React wraps the native event into a SyntheticEvent object (cross-browser consistent)
7. SyntheticEvent is passed to your onClick handler
8. Your handler runs with event.target, event.preventDefault() etc. available

**Event Delegation:** React doesn't add a listener to every button. One listener on root handles all events. This is efficient — 1000 buttons = 1 listener, not 1000.

**Event Bubbling:** This is what makes delegation possible. Without bubbling, the root would never know about a button click.

</details>

Q: React 17 mein Event Pooling kyun thi, iski problem kya thi, aur React 18 mein kya badla?

<details>
<summary>Sample Answer</summary>

**Pooling kyun thi (React 17):**
Memory optimization ke liye. Har click par naya SyntheticEvent object banane ke bajaye, React ek object reuse karta tha. Handler khatam hote hi uski properties null karo, aur next event ke liye wahi object use karo.

**Problem kya thi:**
Agar tumne asynchronous code (setTimeout, Promise) mein event access kiya, toh object already clear ho chuka hota tha — properties null milti thin.

```jsx
function handleClick(event) {
  setTimeout(() => {
    console.log(event.type); // ❌ null — object clear
  }, 1000);
}
```

**Solution tha persist():**
```jsx
event.persist(); // Object ko pool se bahar nikalo
```

**React 18 mein kya badla:**
Modern JavaScript engines fast hain, isliye pooling ki zaroorat nahi. React 18 mein har event ke liye naya SyntheticEvent object banta hai aur wahi memory mein rehta hai. Ab asynchronous code bina persist() ke kaam karta hai.

</details>
