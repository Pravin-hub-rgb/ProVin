# TypeScript Warm-up + Vite Setup

## TypeScript vs JavaScript — Key Differences

Yeh dono code dekho — JS aur TS side by side:

```js
// JavaScript — koi type check nahi
function add(a, b) {
  return a + b;
}
add(5, "10"); // "510" — may be bug, but JS doesn't care
```

```ts
// TypeScript — types defined
function add(a: number, b: number): number {
  return a + b;
}
add(5, "10"); // ❌ Error: Argument of type 'string' not assignable to parameter of type 'number'
```

TypeScript error **development time** mein dikhata hai. Browser mein jaane se pehle hi pata chal jaata hai.

## Basic Types (Quick Revision)

```ts
// Basic types
let name: string = "Vin";
let age: number = 25;
let isLearning: boolean = true;
let data: null = null;
let notDefined: undefined = undefined;

// Arrays
let fruits: string[] = ["apple", "mango", "banana"];
let numbers: Array<number> = [1, 2, 3]; // same as number[]

// Objects
let user: { name: string; age: number } = {
  name: "Vin",
  age: 25,
};

// Union types — multiple types allow
let id: string | number = "abc123";
id = 456; // ✅ allowed (number bhi ho sakta hai)
// id = true; // ❌ Error

// Any — kuch bhi (avoid karo, type safety khatam)
let loose: any = "hello";
loose = 42; // no error
loose = true; // no error — but ab type checking ka fayda nahi

// Unknown — any jaisa but safe (use karo jab type nahi pata)
let input: unknown = "hello";
// input.toUpperCase(); // ❌ Error — pehle type check karo
if (typeof input === "string") {
  input.toUpperCase(); // ✅ Ab safe hai
}
```

## `type` vs `interface`

Dono se object shapes define kar sakte ho. Fark minor hai but important:

```ts
// type
type User = {
  name: string;
  age: number;
};

// interface
interface IUser {
  name: string;
  age: number;
}

// Dono ka use same:
function greet(user: User) {
  return `Hello, ${user.name}`;
}
```

| Feature | `type` | `interface` |
|---------|--------|-------------|
| Object shape | ✅ | ✅ |
| Extend | `&` (intersection) | `extends` |
| Add new props (declaration merging) | ❌ | ✅ |
| Union types | ✅ | ❌ |
| Primitives | ✅ | ❌ |
| Best for | Complex types, unions, primitives | Objects, class implementation |

**React mein mostly interface use karte hain** component props ke liye. Type use karte hain unions, utility types ke liye.

```ts
// Props ke liye interface prefer karo
interface ButtonProps {
  label: string;
  onClick: () => void;
  variant?: "primary" | "secondary";
}

// Union types ke liye type prefer karo
type Status = "loading" | "success" | "error";
```

## Function Typing

```ts
// Function with typed params and return
function add(a: number, b: number): number {
  return a + b;
}

// Arrow function
const multiply = (a: number, b: number): number => a * b;

// Void return (kuch return nahi karta)
function log(message: string): void {
  console.log(message);
}

// Optional parameter
function greet(name: string, greeting?: string): string {
  return `${greeting || "Hello"}, ${name}`;
}
```

## React-Specific Types (Important!)

Ye woh types hain jo React mein regularly use hote hain:

```tsx
// Component props
interface CardProps {
  title: string;
  children: React.ReactNode; // JSX, string, number — kuch bhi
  className?: string;        // Optional prop
}

// useState
const [count, setCount] = useState<number>(0);
const [user, setUser] = useState<User | null>(null); // Initially null, later User

// useRef
const inputRef = useRef<HTMLInputElement>(null);
// inputRef.current?.focus();

// Event handlers
const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  console.log(e.target.value);
};

const handleClick = (e: React.MouseEvent<HTMLButtonElement>) => {
  console.log("Clicked");
};

// Form event
const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => {
  e.preventDefault();
  // submit logic
};
```

## Pehla Component — TypeScript Ke Saath

`src/App.tsx` ko replace karo:

```tsx
import { useState } from "react";

// Props interface define kiya
interface GreetingProps {
  name: string;
  age?: number; // Optional prop
}

// Component — typed props ke saath
function Greeting({ name, age }: GreetingProps) {
  return (
    <div>
      <h1>Hello, {name}!</h1>
      {age && <p>Age: {age}</p>}
    </div>
  );
}

// Main App component
function App() {
  const [count, setCount] = useState<number>(0);

  return (
    <div>
      <Greeting name="Vin" age={25} />
      
      <p>Count: {count}</p>
      <button onClick={() => setCount((c) => c + 1)}>
        Increment
      </button>
    </div>
  );
}

export default App;
```

**In Your Own Words**

1. TypeScript React project mein kaise help karta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** TypeScript development time mein hi errors pakad leta hai — jaise galat type ka prop pass karna, undefined value access karna, function ka galat return type. Production mein jaane se pehle hi bugs catch ho jaate hain. Iske alawa, TypeScript ek "live documentation" ki tarah hai — koi bhi interface dekh ke samajh sakta hai ki component ko kya props chahiye.

</details>

2. `type` aur `interface` mein kya fark hai? React mein kab kaun sa use karein?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `interface` ko extend kiya ja sakta hai (`extends`) aur isme declaration merging hoti hai. `type` zyada flexible hai — union types, primitive types, mapped types bana sakte hain. React mein component props ke liye mostly `interface` use karte hain, aur complex types (unions, generics) ke liye `type`.

</details>

3. Vite ne Create React App ki jagah kyun li?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Vite fast hai — development server milliseconds mein start hota hai (ES modules ki wajah se), hot reload instant hota hai. CRA (Create React App) heavy tha — webpack-based, slow startup, slow reload. React official documentation bhi ab Vite recommend karta hai CRA ki jagah.

</details>

4. `useState<number | null>(null)` ka kya matlab hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** TypeScript generic hai. `useState<number | null>` batata hai ki ye state number bhi ho sakti hai aur null bhi. Initially `null` set hai, lekin baad mein `setState(42)` call kar sakte hain. TypeScript ensure karega ki tum state use karte waqt type check karo — agar null hai toh `.toFixed()` call karne se pehle guard clause daalna padega.

</details>

5. Module 0 se tumhe kya learn hua? Ek line mein batao.

<details>
<summary>Sample Jawab</summary>

**Jawab:** React ka internal working model clear ho gaya — Virtual DOM kaise kaam karta hai, JSX kaise compile hota hai, reconciliation aur diffing kaise hota hai, Fiber ne performance kya improve ki, batching aur synthetic events kya hain. Ab React ko "black box" nahi samajhta, internal mechanism pata hai.

</details>
