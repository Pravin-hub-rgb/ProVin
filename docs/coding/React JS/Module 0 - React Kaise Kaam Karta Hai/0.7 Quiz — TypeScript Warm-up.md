
## MCQ

Q: How is TypeScript different from JavaScript?
A. TypeScript runs in the browser, JavaScript runs on the server
B. TypeScript = JavaScript + Types; types are checked at compile time
C. TypeScript is only used with React; JavaScript is used everywhere
D. TypeScript and JavaScript are the same thing — just different names
> B. TypeScript is a superset of JavaScript that adds type checking. Types are checked at development/compile time, and the code compiles down to plain JavaScript.

---

Q: If you declare `let age: number = 25;` in TypeScript, what happens when you do `age = "twenty-five"`?
A. The code runs and age becomes the string "twenty-five"
B. TypeScript throws a compile-time error — number variable can't hold a string
C. JavaScript automatically converts the type
D. The browser throws a runtime error
> B. TypeScript enforces strict type checking. Once `age` is declared as `number`, assigning a `string` causes a compile-time error — the code won't compile. (At runtime, JavaScript would actually allow it, but TypeScript prevents this before it runs.)

---

Q: What does `let fruits: string[]` mean?
A. fruits is an array that can only hold strings
B. fruits is a string that contains an array
C. fruits is a variable that can be either a string or an array
D. fruits is a function that returns string arrays
> A. `string[]` means "an array of strings" — every element in the array must be a string. Calling `fruits.push(42)` would throw a TypeScript error.

---

Q: How do you define the return type of a function in TypeScript?
A. `function add(a: number, b: number) -> number`
B. `function add(a: number, b: number): number`
C. `function add(a: number, b: number) returns number`
D. `number function add(a: number, b: number)`
> B. The return type comes after the closing parenthesis with a colon — `): number`. TypeScript can also infer it, but writing it explicitly is safer.

---

Q: What is the syntax for an optional parameter?
A. `name: string?`
B. `name?: string`
C. `?name: string`
D. `name: ?string`
> B. The question mark goes after the name but before the colon. `greeting?: string` means the parameter is optional — if not passed, it's `undefined`.

---

Q: What does a union type `string | number` mean?
A. The variable holds both a string and a number at the same time
B. The variable can be either a string or a number
C. The variable can only be set once, with either type
D. The variable gets auto-converted between types
> B. Union means "or" at the type level. `string | number` means the value can be a string OR a number — but only one at a given time, not both simultaneously.

---

Q: What does an Interface define in TypeScript?
A. The implementation details of a function
B. The shape of an object — its properties and their types
C. The default values of a variable
D. The length of an array
> B. An interface defines the shape of an object — what properties it should have and what type each is. Like `interface User { name: string; age: number; }`.

---

Q: What does the pipe `|` symbol mean in `string | number`?
A. Bitwise OR — performs a binary operation on numbers
B. Union — either type is valid
C. Default value assignment — provides a fallback
D. Type assertion — forces the variable to a specific type
> B. In TypeScript, `|` creates a union type — meaning either the left type OR the right type is valid. It's "or" at the type level, not a bitwise operation.

## TrueFalse

Q: TypeScript checks types at runtime — the browser throws type errors.
- True
- False
> False. TypeScript only checks types at compile/development time. Once compiled, the code is plain JavaScript that runs in the browser. The browser never sees type errors.

---

Q: `string[]` and `Array<number>` both represent the same kind of type.
- True
- False
> True. `number[]` and `Array<number>` mean the same thing — an array of numbers. `Array<number>` uses generic syntax, which you'll learn later. `number[]` is the simpler syntax to start with.

---

Q: A union type `string | number` means the variable can hold a string and a number simultaneously.
- True
- False
> False. Union means "or" — the variable holds either a string OR a number at any given time, not both. If you assign a string, it's a string. If you assign a number, it's a number. It can't be both at the same time.

---

Q: Optional properties (`age?: number`) mean the value is always a number — it just defaults to undefined when not provided.
- True
- False
> False. Optional means the property might not exist at all, or might be undefined. When it does exist, it must be a `number`. It's not that the value is "always a number" — it might not be present.

---

Q: Function parameters always require explicit type annotations in TypeScript.
- True
- False
> True. Function parameters always need type annotations because TypeScript can't infer the type from a value — the value comes later when someone calls the function. TypeScript only infers types when a value is immediately assigned.

## ShortAnswer

Q: What is TypeScript's type inference? Give an example.

<details>
<summary>Sample Answer</summary>

**Answer:** Type Inference means TypeScript automatically figures out the type from the assigned value, without you explicitly writing it.

```ts
let name = "Vin";   // TypeScript infers: string
let age = 25;       // TypeScript infers: number
let isLearning = true; // TypeScript infers: boolean
```

When you write `let name = "Vin"`, TypeScript sees the string value and automatically determines that `name` is a `string`. So later, `name = 123` would throw a TypeScript error. You don't need to write `let name: string = "Vin"` — TypeScript infers it for you. Just don't skip annotations for function parameters (where there's no value to infer from).

</details>

---

Q: How do you define parameter types and return type in a TypeScript function? Give an example.

<details>
<summary>Sample Answer</summary>

**Answer:**

```ts
function add(a: number, b: number): number {
  return a + b;
}
```

- Parameter `a` has type `number` (written as `a: number`)
- Parameter `b` has type `number`
- The return type is `number` (written as `): number` — after the closing parenthesis, with a colon)
- TypeScript can also infer the return type, but writing it explicitly is safer

If the return type doesn't match:
```ts
function add(a: number, b: number): string {
  return a + b; // ❌ Error — returning a number, but string is expected
}
```

</details>

Q: What is an Interface? How will you use it in React? Give an example.

<details>
<summary>Sample Answer</summary>

**Answer:** An interface defines the shape of an object — what properties it has and what type each is.

```ts
interface User {
  name: string;
  age: number;
}

let user: User = {
  name: "Vin",
  age: 25,
};
```

In React, you'll use interfaces to **define component props**:

```tsx
interface ButtonProps {
  label: string;
  onClick: () => void;
}

function Button({ label, onClick }: ButtonProps) {
  return <button onClick={onClick}>{label}</button>;
}
```

The interface ensures the `Button` component only accepts `label` (a string) and `onClick` (a function) as props, with the correct types.

</details>
