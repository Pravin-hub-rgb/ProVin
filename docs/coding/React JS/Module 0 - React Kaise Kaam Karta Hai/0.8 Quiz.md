
## MCQ

Q: Node.js ka primary kaam kya hai?
A. Browser mein JavaScript execute karna
B. Terminal aur server par JavaScript chalana
C. React components ko render aur compile karna
D. CSS aur HTML files ko validate karna
> B. Node.js ek JavaScript runtime hai jo browser ke bahar terminal mein JavaScript execute karta hai. React project ki tooling (npm, dev server, build) Node.js par chalti hai.

---

Q: Bun, Node.js se kaise alag hai?
A. Bun browser mein chalta hai, Node.js sirf server pe
B. Bun sirf packages install karta hai, code execute nahi
C. Bun faster hai aur built-in tooling zyada provide karta hai
D. Bun React ke saath bundled aata hai, Node.js nahi
> C. Bun 2023 mein aaya, Node.js se ≈4x faster hai, aur built-in TypeScript support, bundler, test runner aur package manager sab ek hi runtime mein aate hain.

---

Q: npm ka matlab kya hai aur iska kaam kya hai?
A. Node Package Manager — packages ko permanently install karna
B. New Project Manager — naye projects aur scaffolding banana
C. Node Process Manager — Node.js processes ko monitor karna
D. Native Package Mapper — dependencies ki mapping banana
> A. npm = Node Package Manager. Iska kaam packages (React, Vite, Axios) ko internet se download karke project mein permanently install karna aur manage karna hai.

---

Q: npm aur npx mein main fark kya hai?
A. npx sirf Linux machines mein chalta hai, npm sab mein
B. npm permanently install karta hai, npx temporarily run
C. npx sirf packages delete karta hai, npm install karta hai
D. npm aur npx dono exact same kaam karte hain har jagah
> B. npm packages ko permanently install karta hai (`npm install react`). npx packages ko bina permanently install kiye sirf ek baar run karta hai (`npx create-vite`).

---

Q: Vite kis kaam ke liye use hota hai?
A. Ek JavaScript runtime hai jo Node.js ko replace karta hai
B. Ek package manager hai jo npm ka alternative provide hai
C. Ek build tool hai jo setup, dev server aur build karta hai
D. Ek testing framework jo React components ko test karta hai
> C. Vite ek build tool hai jo teen kaam karta hai: (1) React project ka starting structure generate karta hai, (2) development server chalata hai, (3) production build banata hai.

---

Q: HMR (Hot Module Replacement) ka kya matlab hai?
A. Code change hone par poora project rebuild hota hai
B. Sirf wahi module replace hota hai jo actually change hua
C. Browser ko manually refresh karna padta hai har baar
D. Code changes directly production mein deploy ho jaate hain
> B. HMR mein code change hone par Vite sirf wahi module replace karta hai jo change hua — poora page reload nahi hota, current state preserve rehti hai, aur update near-instant hota hai.

Q: `package.json` file mein kya information hoti hai?
A. Sirf React components ka actual source code hota hai
B. Project metadata, dependencies list aur scripts hoti hai
C. Browser configuration aur CSS stylesheets hoti hain
D. Node.js runtime ka version aur update history hota hai
> B. `package.json` mein project ka metadata (name, version), dependencies ki list, aur runnable scripts (`dev`, `build`) hote hain. `npm install` isi file ko padh kar packages download karta hai.

---

Q: `create-vite` aur `vite` package mein kya fark hai?
A. Dono ek hi cheez ka do alag naam hain
B. create-vite installer hai, vite build tool hai
C. create-vite React implementation hai, vite TypeScript hai
D. create-vite sirf Mac mein chalta hai, vite sab mein
> B. `create-vite` ek installer/scaffolding tool hai jo naya project banata hai. `vite` build tool hai jo project ke andar install hota hai aur dev server + production build handle karta hai.

## TrueFalse

Q: Node.js React ka part hai — React application run karne ke liye Node.js zaroori hai.
- True
- False
> False. Node.js React ka part nahi hai — ye ek independent tool hai. React khud Node.js par depend nahi karta, lekin React project ki tooling (npm, dev server, build) Node.js par chalti hai.

---

Q: `npm install react` aur `bun add react` dono ka same matlab hai — React ko project mein permanently add karna.
- True
- False
> True. `npm install react` Node.js ke saath, `bun add react` Bun ke saath — dono React package ko project mein permanently install karte hain. Sirf syntax alag hai, concept same hai.

---

Q: HMR browser ka built-in feature hai jo bina kisi extra tool ke kaam karta hai.
- True
- False
> False. HMR browser ka native feature nahi hai — ye Vite ka feature hai. Vite hi code changes detect karta hai aur browser ko selectively update karta hai bina full page reload ke.

---

Q: Create React App (CRA) Vite se pehle standard tool tha jo webpack-based tha aur slow tha.
- True
- False
> True. CRA webpack-based tha — har chhote code-change par poore project ko re-bundle karta tha jo slow tha. React ki official documentation ab CRA recommend nahi karti; Vite ab standard hai.

---

Q: `npx create-vite` chalne ke baad create-vite package project mein permanently install ho jaata hai.
- True
- False
> False. npx create-vite chalne par create-vite temporary download hota hai, project banata hai, aur kaam khatam hone ke baad permanently nahi rakha jaata. Project ke andar sirf React, ReactDOM, Vite, etc. install hote hain.

## ShortAnswer

Q: npm aur npx mein kya fark hai? Kab kaunsa use karoge?

<details>
<summary>Sample Answer</summary>

**Answer:** npm (Node Package Manager) packages ko permanently install karta hai. Jab kisi package ki har roz zaroorat ho — jaise React — toh `npm install react` use karte ho. npx packages ko bina permanently install kiye sirf ek baar run karta hai. Jab sirf ek baar koi tool chalana ho — jaise `create-vite` jo project banata hai aur phir zaroorat nahi hoti — toh `npx create-vite` use karte ho.

**Simple rule:** Har roz chahiye → npm install. Sirf ek baar chalana hai → npx.

</details>

---

Q: Vite kya hai aur yeh CRA se better kyun hai?

<details>
<summary>Sample Answer</summary>

**Answer:** Vite ek build tool hai jo teen kaam karta hai: (1) React project ka starting structure generate karta hai, (2) development server chalata hai, (3) production build banata hai.

CRA (Create React App) webpack-based tha — har chhote code-change par poore project ko re-bundle karta tha, jo slow tha. Vite native ES modules use karta hai — sirf wahi module reload hota hai jo change hua, poora project nahi. Isliye Vite near-instant HMR deta hai jabki CRA mein reload mein visible delay hota tha.

</details>

---

Q: HMR (Hot Module Replacement) kaise kaam karta hai? Code change par actually kya hota hai?

<details>
<summary>Sample Answer</summary>

**Answer:** HMR ka flow kuch aisa hai:

1. Tum code change karte ho (e.g., `App.tsx` mein kuch edit karte ho)
2. Vite change detect karta hai
3. Vite sirf wahi module replace karta jo change hua — poora project rebuild nahi karta
4. Browser update ho jaata hai bina page reload kiye
5. Current state (form inputs, scroll position, etc.) preserve rehti hai

HMR browser ka native feature nahi hai — ye Vite ka feature hai jo development experience fast banata hai.

</details>

---

Q: `npx create-vite my-app` command chalne par actually kya kya hota hai? Step-by-step sequence samjhao.

<details>
<summary>Sample Answer</summary>

**Answer:** Sequence kuch aisa hota hai:

1. `npx create-vite my-app` command chalti hai
2. npx internet se `create-vite` package download karta hai (temporarily)
3. create-vite run hota hai — tumse project name, template (React?), TypeScript, etc. poochta hai
4. create-vite folder structure banata hai — `src/`, `public/`, `package.json`, `vite.config.ts`, etc.
5. create-vite ka kaam khatam — yeh permanently install nahi hota, bas temporary tha
6. Tum `npm install` (ya `bun install`) chalate ho — ab `package.json` mein listed dependencies (React, ReactDOM, Vite, TypeScript) actually install hoti hain `node_modules` mein
7. Tum `npm run dev` (ya `bun run dev`) chalate ho — Vite dev server start hota hai

Yahan important distinction yeh hai ki **create-vite** sirf scaffolding hai (project banata hai), jabki **Vite**, **React**, **ReactDOM** actual dependencies hain jo project mein permanently install hoti hain.

</details>
