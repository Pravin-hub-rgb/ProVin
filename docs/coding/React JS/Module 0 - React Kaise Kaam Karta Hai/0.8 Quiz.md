
## MCQ

Q: What is Node.js's primary purpose?
A. Execute JavaScript inside the browser
B. Run JavaScript in the terminal and on the server
C. Render and compile React components
D. Validate CSS and HTML files
> B. Node.js is a JavaScript runtime that executes JavaScript outside the browser, in the terminal and on the server. React's tooling (npm, dev server, build) runs on Node.js.

---

Q: How is Bun different from Node.js?
A. Bun runs in the browser, Node.js runs only on the server
B. Bun only installs packages, it doesn't execute code
C. Bun is faster and provides more built-in tooling
D. Bun comes bundled with React, Node.js doesn't
> C. Bun was released in 2023 and is roughly 4x faster than Node.js. It also provides built-in TypeScript support, a bundler, test runner, and package manager — all in one runtime.

---

Q: What does "npm" stand for and what does it do?
A. Node Package Manager — permanently install packages
B. New Project Manager — create new projects and scaffolding
C. Node Process Manager — monitor Node.js processes
D. Native Package Mapper — map dependencies
> A. npm = Node Package Manager. It downloads packages (React, Vite, Axios) from the internet and installs them into your project permanently.

---

Q: What is the main difference between npm and npx?
A. npx only runs on Linux, npm runs on all platforms
B. npm installs permanently; npx runs temporarily without installing
C. npx only deletes packages; npm installs them
D. npm and npx do the exact same thing everywhere
> B. npm installs packages permanently (`npm install react`). npx runs a package once without permanently installing it (`npx create-vite`).

---

Q: What is Vite used for?
A. A JavaScript runtime that replaces Node.js
B. A package manager that replaces npm
C. A build tool that handles setup, dev server, and production builds
D. A testing framework for React components
> C. Vite is a build tool that does three things: (1) generates the initial project structure, (2) runs a development server, and (3) builds optimized code for production.

---

Q: What does HMR (Hot Module Replacement) mean?
A. The entire project is rebuilt on every code change
B. Only the module that actually changed gets replaced
C. You have to manually refresh the browser each time
D. Code changes are deployed directly to production
> B. With HMR, when code changes, Vite replaces only the module that changed — no full page reload, current state is preserved, and updates are near-instant.

---

Q: What information is stored in `package.json`?
A. The actual source code of React components
B. Project metadata, dependency list, and scripts
C. Browser configuration and CSS stylesheets
D. Node.js runtime version and update history
> B. `package.json` contains the project's metadata (name, version), the list of dependencies, and the runnable scripts (`dev`, `build`, etc.). `npm install` reads this file to download packages.

---

Q: What's the difference between `create-vite` and `vite`?
A. They're just two different names for the same thing
B. `create-vite` is an installer; `vite` is the build tool
C. `create-vite` is the React implementation; `vite` is the TypeScript tool
D. `create-vite` only runs on Mac; `vite` runs everywhere
> B. `create-vite` is the installer/scaffolding tool that creates a new project. `vite` is the build tool that gets installed inside the project and handles the dev server and production build.

## TrueFalse

Q: Node.js is part of React — it's required to run React applications.
- True
- False
> False. Node.js is NOT part of React — it's an independent tool. React doesn't depend on Node.js, but React's tooling (npm, dev server, build process) runs on Node.js.

---

Q: `npm install react` and `bun add react` mean the same thing — both add React to the project permanently.
- True
- False
> True. `npm install react` (with Node.js) and `bun add react` (with Bun) both permanently install the React package into the project. Only the syntax differs — the concept is identical.

---

Q: HMR is a browser-built-in feature that works without any extra tools.
- True
- False
> False. HMR is not a browser-native feature — it's a Vite feature. Vite detects changes and selectively updates the browser without a full page reload.

---

Q: Create React App (CRA) was the standard tool before Vite. It was webpack-based and slower.
- True
- False
> True. CRA was webpack-based — every small code change triggered a full re-bundle, which was slow. React's official documentation no longer recommends CRA; Vite is now the standard.

---

Q: After running `npx create-vite`, the `create-vite` package is permanently installed in the project.
- True
- False
> False. When you run `npx create-vite`, it is downloaded temporarily, generates the project, and is not permanently installed. Only the actual project dependencies (React, ReactDOM, Vite, TypeScript) are installed permanently via `npm install`.

## ShortAnswer

Q: What's the difference between npm and npx? When would you use each?

<details>
<summary>Sample Answer</summary>

**Answer:** npm (Node Package Manager) installs packages permanently. When you use a package every day — like React — you use `npm install react`. npx runs a package once, without permanently installing it. When you just need to run something once — like `create-vite` which generates a project and isn't needed after — you use `npx create-vite`.

**Simple rule:** If you use it every day → `npm install`. If you only need to run it once → `npx`.

</details>

---

Q: What is Vite and why is it better than Create React App (CRA)?

<details>
<summary>Sample Answer</summary>

**Answer:** Vite is a build tool that does three things: (1) generates the initial React project structure, (2) runs a development server, and (3) builds production-optimized code.

CRA was webpack-based — every small code change triggered a full project re-bundle, which was slow. Vite uses native ES modules — only the changed module is reloaded, not the entire project. This results in near-instant Hot Module Replacement (HMR), whereas CRA showed a noticeable delay even for minor changes.

</details>

---

Q: How does HMR (Hot Module Replacement) work when you change code?

<details>
<summary>Sample Answer</summary>

**Answer:** The HMR flow:

1. You make a code change (e.g., editing `App.tsx`)
2. Vite detects the change
3. Vite replaces **only** the module that changed — it does NOT rebuild the entire project
4. The browser updates instantly, without a full page reload
5. The current state (form inputs, scroll position, etc.) is preserved

HMR is not a browser feature — it's a Vite feature that makes the development experience much faster by avoiding full page reloads on every change.

</details>

---

Q: What happens when you run `npx create-vite my-app`? Explain step by step.

<details>
<summary>Sample Answer</summary>

**Answer:** The sequence is:

1. You run `npx create-vite my-app`
2. npx downloads the `create-vite` package from the internet (temporarily)
3. `create-vite` runs — it asks for the project name, template (React?), TypeScript, etc.
4. It creates the folder structure — `src/`, `public/`, `package.json`, `vite.config.ts`, etc.
5. `create-vite` finishes its job — it's temporary and not permanently installed
6. You run `npm install` — now the actual dependencies listed in `package.json` (React, ReactDOM, Vite, TypeScript) are installed into `node_modules`
7. You run `npm run dev` — the Vite dev server starts up

The key distinction: `create-vite` is just scaffolding (it creates the project), while `Vite`, `React`, and `ReactDOM` are the actual dependencies that get permanently installed and used.

</details>
