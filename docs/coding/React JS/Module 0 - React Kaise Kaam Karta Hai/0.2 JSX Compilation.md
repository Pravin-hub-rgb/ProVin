Socho tum ek restaurant mein khana order kar rahe ho. Tum waiter ko bolte ho — "Ek paneer butter masala, do roti, aur ek salad." Waiter ye order kitchen mein jaake chef ko batata hai. Chef is order ko samajh kar khana banata hai.

React mein bhi kuch aisa hi hota hai. Tum **JSX** likhte ho — jo HTML jaisa dikhta hai. Browser ye JSX samajhta nahi. Lekin React ka ek "waiter" hai — **Babel** — jo JSX ko samajh kar browser-friendly code mein convert karta hai.

# JSX Compilation

## JSX Kya Hai?

JSX ka full form hai **JavaScript XML**. Ye React ka syntax extension hai jo HTML-like syntax ko JavaScript ke andar likhne deta hai.

```jsx
const element = <h1>Hello, World!</h1>;
```

Ye na HTML hai na JavaScript. Ye **JSX** hai — ek special syntax jo Babel compile kar deta hai.

## Browser JSX Samajhta Nahi

Browser sirf JavaScript samajhta hai. JSX browser ko denge toh error dega. Isliye ek tool chahiye jo JSX ko JavaScript mein convert kare.

Ye tool hai **Babel**.

Babel ek JavaScript compiler hai. React projects mein Babel automatically configure hota hai (Vite ya Create React App ke saath). Tum JSX likhte ho, Babel usse `React.createElement()` calls mein convert karta hai.

## JSX → React.createElement()

Dekho asli magic:

```jsx
// Tum ye likhte ho (JSX)
const element = (
  <div className="container">
    <h1>Hello</h1>
    <p>World</p>
  </div>
);
```

Babel isse convert karta hai kuch aise:

```js
// Browser ye execute karta hai
const element = React.createElement(
  "div",
  { className: "container" },
  React.createElement("h1", null, "Hello"),
  React.createElement("p", null, "World")
);
```

`React.createElement()` ka structure hota hai:

```
React.createElement(type, props, ...children)
```

| Parameter | Matlab | Example |
|-----------|--------|---------|
| `type` | HTML tag ya component | `"div"`, `"h1"`, `Button` |
| `props` | Attributes/properties | `{ className: "container" }` |
| `children` | Andar ke elements | `"Hello"`, `React.createElement(...)` |

Ye `React.createElement()` call ek JavaScript object return karta hai — jo Virtual DOM ka ek node hota hai:

```js
// createElement return karta hai kuch aisa
{
  type: "div",
  props: {
    className: "container",
    children: [
      { type: "h1", props: { children: "Hello" } },
      { type: "p", props: { children: "World" } }
    ]
  }
}
```

Yeh object Virtual DOM ka part hai. React aise objects ka tree banata hai aur phir usse manipulate karta hai.

> **Analogy — Translate Karwane Wala:** Socho tum Hindi mein baat karte ho aur tumhara friend sirf English samajhta hai. Ek translator dono ke beech mein hota hai jo Hindi → English convert karta hai. JSX = Hindi (tumhari language). Browser = English (jo browser samajhta hai). Babel = Translator. Tum JSX (Hindi) likhte ho, Babel usse `createElement` calls (English) mein convert karta hai jo browser samajh leta hai.

## Why JSX Exists?

Tum soch rahe hoge — "Direct `createElement()` kyun nahi likhte? JSX kyun?" 

Dekho fark:

```jsx
// JSX
<div className="card">
  <h1>{title}</h1>
  <p>{description}</p>
  <Button onClick={handleClick}>Submit</Button>
</div>
```

```js
// createElement (without JSX)
React.createElement(
  "div",
  { className: "card" },
  React.createElement("h1", null, title),
  React.createElement("p", null, description),
  React.createElement(Button, { onClick: handleClick }, "Submit")
);
```

Kaunsa readable hai? Obviously JSX. JSX ka purpose hai — **developer experience**. Code padhne mein aasan lagta hai kyunki HTML jaisa dikhta hai. UI ka structure visually samajh aata hai.

## Multiple Elements Return

JSX mein multiple elements return karne ke liye unhe ek parent mein wrap karna padta hai:

```jsx
// ❌ Yeh nahi chalega
return (
  <h1>Title</h1>
  <p>Description</p>
); // Syntax error

// ✅ Yeh chalega
return (
  <div>
    <h1>Title</h1>
    <p>Description</p>
  </div>
);

// ✅ Ya phir <></> (Fragment) use karo
return (
  <>
    <h1>Title</h1>
    <p>Description</p>
  </>
);
```

Kyun? Kyunki `React.createElement` sirf **ek** root element return kar sakta hai. Fragment (`<>`) bhi internally `React.createElement(React.Fragment, null, ...)` ban jaata hai.

## Expressions in JSX

JSX mein JavaScript expressions `{}` ke andar likhe jaate hain:

```jsx
const name = "Vin";
const element = <h1>Hello, {name}</h1>;
// Output: <h1>Hello, Vin</h1>
```

Curly braces ke andar koi bhi JavaScript expression daal sakte ho:

```jsx
// Math
<p>{2 + 2}</p>

// Function call
<p>{fullName.toUpperCase()}</p>

// Ternary
<p>{isLoggedIn ? "Welcome" : "Login"}</p>

// Array map (lists)
<ul>
  {items.map(item => <li key={item.id}>{item.name}</li>)}
</ul>
```

## JSX Mein Attributes

HTML ke kuch attributes React mein thode different hote hain:

| HTML | JSX | Kyun? |
|------|-----|-------|
| `class` | `className` | `class` JavaScript reserved word hai |
| `for` | `htmlFor` | Same reason |
| `onclick` | `onClick` | camelCase convention |
| `tabindex` | `tabIndex` | camelCase |
| `style="..."` | `style={{ color: "red" }}` | JSX mein style ek object hai |


> ❌ JSX **HTML nahi hai** — HTML jaisa dikhta hai lekin JavaScript mein compile hota hai
> ❌ JSX **template language nahi hai** (jaise Handlebars, EJS) — JSX ki poori power JavaScript hai
> ❌ JSX **React ke bina nahi chal sakta** — React 17+ mein automatic JSX transform aaya hai (naya JSX transform import nahi maangta)
> ❌ JSX **sirf React ke liye nahi hai** — Preact, Solid, Vue bhi JSX support karte hain

**In Your Own Words**

1. Babel JSX ke saath kya karta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Babel JSX syntax ko `React.createElement()` calls mein compile karta hai. Jaise `const el = <h1>Hi</h1>` — Babel isse `React.createElement("h1", null, "Hi")` mein badal deta hai. Browser phir is createElement ko samajh leta hai.

</details>

2. `React.createElement()` ka structure kya hota hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `React.createElement(type, props, ...children)` — type batata hai ki kaunsa element banana hai (jaise "div", "h1", ya component), props mein attributes aate hain (className, id, etc.), aur children mein andar ke elements ya text.

</details>

3. JSX mein `className` kyun use karte hain, `class` kyun nahi?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Kyunki `class` JavaScript mein ek reserved keyword hai (classes define karne ke liye). JSX JavaScript mein compile hota hai, isliye `class` use nahi kar sakte. React ne alternative diya — `className`. Same reason — `for` ki jagah `htmlFor`.

</details>

4. JSX mein expressions `{}` ke andar kya-kya daal sakte ho?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Koi bhi JavaScript expression — math (`{2+2}`), variable (`{name}`), function call (`{getName()}`), ternary (`{a ? b : c}`), array methods (`{items.map()}`), template literals. Lekin statements nahi — jaise if-else, for loop direct nahi likh sakte.

</details>

5. JSX ko HTML se alag kya banata hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** JSX HTML jaisa dikhta hai but asal mein JavaScript ka syntactic sugar hai. HTML static hota hai, JSX dynamic hai (curly braces mein JS expressions). HTML browser directly samajhta hai, JSX pehle Babel se compile hona padta hai. Attributes bhi different hote hain (className, htmlFor, camelCase events).

</details>
