0.1 mein humne Virtual DOM ke baare mein padha — ye kya hai aur kyun fast hai. Ab sawaal ye hai ki React mein code likhte waqt hum kaun sa syntax use karte hain? HTML nahi, kyunki HTML static hota hai. Pure JavaScript nahi, kyunki woh UI structure dikhata nahi. React ne iske liye apna syntax banaya — **JSX**.

# JSX — React Ka Syntax

## JSX Kya Hai?

JSX ka full form hai **JavaScript XML**. Ye React ka syntax extension hai jo HTML-like syntax ko JavaScript ke andar likhne deta hai.

```jsx
const element = <h1>Hello, World!</h1>;
```

Dekho — `<h1>Hello, World!</h1>` HTML jaisa dikhta hai, lekin ye JavaScript file ke andar likha hua hai. Yahi JSX hai. HTML nahi, JavaScript nahi — ek special syntax jo React ke saath aata hai.

## Problem — Browser JSX Samajhta Nahi

Browser sirf JavaScript samajhta hai. Agar tum browser ko ye JSX denge:

```jsx
const element = <h1>Hello</h1>;
```

Browser error dega — kyunki `<h1>` uske liye ek unexpected token hai. JavaScript syntax mein `<` ka koi matlab nahi.

Isliye JSX ko pehle **compile** karna padta hai — asli JavaScript mein convert karna. Ye compilation kaun karta hai? **Babel.**

## Babel — JSX Ko JavaScript Mein Badalta Hai

Babel ek JavaScript compiler hai. React projects mein Babel automatically configured rehta hai. Tum JSX likhte ho, Babel usse `React.createElement()` calls mein convert karta hai jo browser samajh leta hai.

JSX likho:

```jsx
const element = (
  <div className="container">
    <h1>Hello</h1>
    <p>World</p>
  </div>
);
```

Babel ismein convert karega:

```js
const element = React.createElement(
  "div",
  { className: "container" },
  React.createElement("h1", null, "Hello"),
  React.createElement("p", null, "World")
);
```

`React.createElement()` ka structure:

```
React.createElement(type, props, ...children)
```

| Parameter | Matlab | Example |
|-----------|--------|---------|
| `type` | HTML tag ya component | `"div"`, `"h1"`, `Button` |
| `props` | Attributes/properties | `{ className: "container" }` |
| `children` | Andar ke elements | `"Hello"`, `React.createElement(...)` |

## Aur Ye Virtual DOM Se Kaise Julta Hai?

0.1 mein humne pada tha ki Virtual DOM lightweight JavaScript objects ka tree hota hai. `React.createElement()` wahi objects return karta hai:

```js
// createElement return karta hai kuch aisa
{
  type: "div",
  props: {
    className: "container",
    children: [
      { type: "h1", props: { children: "Hello" } },
      { type: "p", props: { children: "World" } }
    ]
  }
}
```

Yeh object Virtual DOM ka ek node hai. `type` batata hai kaunsa element hai, `props` batata hai uski properties, `children` batata hai andar kya hai. React aise objects ka poora tree banata hai — aur yahi Virtual DOM hai.

**Isliye flow aisa hai:**
`Tum JSX likhte ho → Babel React.createElement() mein compile karta hai → createElement Virtual DOM node object return karta hai → React in objects ka tree bana leta hai`

> **Babel ka kaam samajhne ke liye:** JSX = Hindi (tumhari language). Browser = English (jo browser samajhta hai). Babel = Translator jo Hindi → English convert karta hai. Tum JSX likhte ho, Babel usse createElement calls mein badalta hai jo browser samajh leta hai.

## Why JSX? Direct createElement Kyun Nahi?

Socho agar tumhe directly `createElement` likhna pade:

```js
React.createElement(
  "div",
  { className: "card" },
  React.createElement("h1", null, title),
  React.createElement("p", null, description),
  React.createElement(Button, { onClick: handleClick }, "Submit")
);
```

Vs JSX:

```jsx
<div className="card">
  <h1>{title}</h1>
  <p>{description}</p>
  <Button onClick={handleClick}>Submit</Button>
</div>
```

JSX ka purpose **developer experience** hai. Code padhne mein aasan lagta hai kyunki HTML jaisa dikhta hai. UI ka structure visually samajh aata hai. createElement se kaam chal sakta hai, lekin JSX likhna aur padhna dono easy hai.

## JSX Rules

### 1. Ek Root Element

JSX mein multiple elements return karne ke liye unhe ek parent mein wrap karna padta hai:

```jsx
// ❌ Yeh nahi chalega
return (
  <h1>Title</h1>
  <p>Description</p>
);

// ✅ Ek parent mein wrap karo
return (
  <div>
    <h1>Title</h1>
    <p>Description</p>
  </div>
);

// ✅ Ya Fragment <> use karo (extra DOM node nahi banata)
return (
  <>
    <h1>Title</h1>
    <p>Description</p>
  </>
);
```

Kyun? Kyunki `React.createElement` sirf **ek** root element return kar sakta hai. Fragment (`<>`) internally `React.createElement(React.Fragment, null, ...)` ban jaata hai.

### 2. JavaScript Expressions {}

JSX mein JavaScript expressions `{}` ke andar likhe jaate hain:

```jsx
const name = "Vin";
const element = <h1>Hello, {name}</h1>;
// Output: <h1>Hello, Vin</h1>
```

Curly braces ke andar koi bhi JavaScript expression daal sakte ho:

```jsx
<p>{2 + 2}</p>                          // Math
<p>{fullName.toUpperCase()}</p>         // Function call
<p>{isLoggedIn ? "Welcome" : "Login"}</p> // Ternary
<ul>
  {items.map(item => <li key={item.id}>{item.name}</li>)}  // Array map
</ul>
```

### 3. Attributes — HTML Se Thode Different

HTML ke kuch attributes React mein change ho jaate hain:

| HTML | JSX | Kyun? |
|------|-----|-------|
| `class` | `className` | `class` JavaScript reserved word hai |
| `for` | `htmlFor` | Same reason |
| `onclick` | `onClick` | camelCase convention |
| `tabindex` | `tabIndex` | camelCase |
| `style="..."` | `style={{ color: "red" }}` | JSX mein style ek object hai |


> ❌ JSX **HTML nahi hai** — HTML jaisa dikhta hai lekin JavaScript mein compile hota hai
> ❌ JSX **template language nahi hai** (jaise Handlebars, EJS) — JSX ki poori power JavaScript hai
> ❌ JSX **React ke bina nahi chal sakta** — React 17+ mein automatic JSX transform aaya hai (naya JSX transform import nahi maangta)
> ❌ JSX **sirf React ke liye nahi hai** — Preact, Solid, Vue bhi JSX support karte hain

**In Your Own Words**

1. Babel JSX ke saath kya karta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Babel JSX syntax ko `React.createElement()` calls mein compile karta hai. Jaise `const el = <h1>Hi</h1>` — Babel isse `React.createElement("h1", null, "Hi")` mein badal deta hai. Browser phir is createElement ko samajh leta hai.

</details>

2. `React.createElement()` ka structure kya hota hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `React.createElement(type, props, ...children)` — type batata hai ki kaunsa element banana hai (jaise "div", "h1", ya component), props mein attributes aate hain (className, id, etc.), aur children mein andar ke elements ya text.

</details>

3. JSX aur Virtual DOM mein kya connection hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** JSX Babel se `React.createElement()` calls mein compile hota hai. `React.createElement()` ek JavaScript object return karta hai — jisme `type`, `props`, `children` hote hain. Yeh object Virtual DOM ka ek node hai. React aise objects ka tree banata aur manage karta hai.

</details>

4. JSX mein `className` kyun use karte hain, `class` kyun nahi?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Kyunki `class` JavaScript mein ek reserved keyword hai (classes define karne ke liye). JSX JavaScript mein compile hota hai, isliye `class` use nahi kar sakte. React ne alternative diya — `className`. Same reason — `for` ki jagah `htmlFor`.

</details>

5. JSX ko HTML se alag kya banata hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** JSX HTML jaisa dikhta hai but asal mein JavaScript ka syntactic sugar hai. HTML static hota hai, JSX dynamic hai (curly braces mein JS expressions). HTML browser directly samajhta hai, JSX pehle Babel se compile hona padta hai. Attributes bhi different hote hain (className, htmlFor, camelCase events).

</details>
