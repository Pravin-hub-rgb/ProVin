In 0.1, we learned about the Virtual DOM — what it is and why it's fast. Now the question is — when we write React code, which syntax do we use? Not HTML, because that's static. Not plain JavaScript, because it doesn't show UI structure. React created its own syntax for this — **JSX**.

---

## What is JSX?

JSX stands for **JavaScript XML**. It's a syntax extension for React that lets you write HTML-like syntax inside JavaScript.

```jsx
const element = <h1>Hello, World!</h1>;
```

See — `<h1>Hello, World!</h1>` looks like HTML, but it's written inside a JavaScript file. That's JSX. It's not HTML, and it's not plain JavaScript — it's a special syntax that comes with React.

## Problem — Browsers Don't Understand JSX

Browsers only understand JavaScript. If you give the browser this JSX:

```jsx
const element = <h1>Hello</h1>;
```

The browser throws an error — `<h1>` is an unexpected token to it. In JavaScript syntax, `<` has no meaning.

That's why JSX must be **compiled** first — transformed into real JavaScript. And the compiler that does this is **Babel**.

## Babel — Converting JSX to JavaScript

Babel is a JavaScript compiler. In React projects, Babel is pre-configured. You write JSX, and Babel converts it into `React.createElement()` calls that the browser understands.

Write JSX:

```jsx
const element = (
  <div className="container">
    <h1>Hello</h1>
    <p>World</p>
  </div>
);
```

Babel transforms it into:

```js
const element = React.createElement(
  "div",
  { className: "container" },
  React.createElement("h1", null, "Hello"),
  React.createElement("p", null, "World")
);
```

The structure of `React.createElement()`:

```
React.createElement(type, props, ...children)
```

| Parameter | Meaning | Example |
|-----------|---------|---------|
| `type` | HTML tag or component | `"div"`, `"h1"`, `Button` |
| `props` | Attributes/properties | `{ className: "container" }` |
| `children` | Inner elements | `"Hello"`, `React.createElement(...)` |

## And How Does This Connect to Virtual DOM?

In 0.1, we learned that the Virtual DOM is a tree of lightweight JavaScript objects. `React.createElement()` is exactly what returns those objects:

```js
// createElement returns something like this
{
  type: "div",
  props: {
    className: "container",
    children: [
      { type: "h1", props: { children: "Hello" } },
      { type: "p", props: { children: "World" } }
    ]
  }
}
```

This object is a node in the Virtual DOM. `type` tells what element it is, `props` tells its properties, `children` tells what's inside. React builds a whole tree of these objects — and that tree is the Virtual DOM.

**So the flow is this:**
`You write JSX → Babel compiles it into React.createElement() → createElement returns a Virtual DOM node object → React builds a tree of these objects`

> **Understanding Babel's role:** JSX is like your native language. The browser speaks English (JavaScript). Babel is the translator that converts your language into what the browser can understand. You write JSX, Babel transforms it into `createElement()` calls that the browser can execute.

## Why JSX? Why Not Write createElement Directly?

Imagine if you had to write `createElement` directly for everything:

```js
React.createElement(
  "div",
  { className: "card" },
  React.createElement("h1", null, title),
  React.createElement("p", null, description),
  React.createElement(Button, { onClick: handleClick }, "Submit")
);
```

vs JSX:

```jsx
<div className="card">
  <h1>{title}</h1>
  <p>{description}</p>
  <Button onClick={handleClick}>Submit</Button>
</div>
```

The purpose of JSX is **developer experience**. Code is easier to read and the UI structure is visually clear. `createElement` technically works, but JSX is both easier to write and easier to read.

## JSX Rules

### 1. One Root Element

When returning multiple elements in JSX, you need to wrap them in a single parent:

```jsx
// ❌ This won't work
return (
  <h1>Title</h1>
  <p>Description</p>
);

// ✅ Wrap in a parent
return (
  <div>
    <h1>Title</h1>
    <p>Description</p>
  </div>
);

// ✅ Or use Fragment <> (no extra DOM node)
return (
  <>
    <h1>Title</h1>
    <p>Description</p>
  </>
);
```

Why? Because `React.createElement` can only return **one** root element. A Fragment (`<>...</>`) internally becomes `React.createElement(React.Fragment, null, ...)`.

### 2. JavaScript Expressions with {}

In JSX, JavaScript expressions are written inside `{}` curly braces:

```jsx
const name = "Vin";
const element = <h1>Hello, {name}</h1>;
// Output: <h1>Hello, Vin</h1>
```

You can put any JavaScript expression inside the curly braces:

```jsx
<p>{2 + 2}</p>                          // Math
<p>{fullName.toUpperCase()}</p>        // Function call
<p>{isLoggedIn ? "Welcome" : "Login"}</p> // Ternary
<ul>
  {items.map(item => <li key={item.id}>{item.name}</li>)}  // Array map
</ul>
```

### 3. Attributes — Slightly Different from HTML

Some attributes differ between HTML and React:

| HTML | JSX | Why? |
|------|-----|------|
| `class` | `className` | `class` is a reserved word in JavaScript |
| `for` | `htmlFor` | Same reason |
| `onclick` | `onClick` | camelCase convention |
| `tabindex` | `tabIndex` | camelCase |
| `style="..."` | `style={{ color: "red" }}` | In JSX, style is an object |

---

> ❌ JSX is **not HTML** — it looks like HTML but is compiled into JavaScript
> ❌ JSX is **not a template language** (like Handlebars, EJS) — JSX has the full power of JavaScript
> ❌ JSX **can't run without React** — React 17+ has the automatic JSX transform (new transform needs no import)
> ❌ JSX is **not exclusive to React** — Preact, Solid, Vue also support JSX

**In Your Own Words**

1. What does Babel do for JSX?

<details>
<summary>Sample Answer</summary>

**Answer:** Babel compiles JSX syntax into `React.createElement()` calls. For example, `const el = <h1>Hi</h1>` becomes `React.createElement("h1", null, "Hi")`. The browser then executes this `createElement` call, which it understands.

</details>

2. What is the structure of `React.createElement()`?

<details>
<summary>Sample Answer</summary>

**Answer:** `React.createElement(type, props, ...children)` — `type` tells what element to create (like `"div"`, `"h1"`, or a component), `props` holds attributes (`className`, `id`, etc.), and `children` holds the inner elements or text.

</details>

3. What's the connection between JSX and Virtual DOM?

<details>
<summary>Sample Answer</summary>

**Answer:** JSX is compiled by Babel into `React.createElement()` calls. `React.createElement()` returns a plain JavaScript object with `type`, `props`, and `children`. This object is a node in the Virtual DOM. React builds a tree of these objects and manages it.

</details>

4. Why do we use `className` instead of `class` in JSX?

<details>
<summary>Sample Answer</summary>

**Answer:** Because `class` is a reserved keyword in JavaScript (used for defining classes). Since JSX gets compiled into JavaScript, `class` can't be used. React uses the alternative — `className`. The same reason applies — `for` becomes `htmlFor`.

</details>

5. What makes JSX different from regular HTML?

<details>
<summary>Sample Answer</summary>

**Answer:** JSX looks like HTML but is really JavaScript's syntactic sugar. HTML is static; JSX is dynamic (JavaScript expressions inside `{}`). HTML is understood directly by browsers; JSX must be compiled by Babel first. Attributes also differ (`className`, `htmlFor`, camelCase events).

</details>
