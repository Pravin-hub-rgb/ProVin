
## MCQ

Q: React 15 mein reconciliation synchronous hone ki wajah se kaun si problem aati thi?
A. State updates batch nahi hote the, har setState alag render trigger karta tha
B. JSX ko compile karne ke liye alag se Babel configure karna padta tha
C. Browser freeze ho jata tha — animations lag, typing delay, scroll smooth nahi
D. key prop na dene par React poora list destroy karke naya bana deta tha
> C. Synchronous reconciliation means once started, it couldn't pause — browser frozen until done. Iski wajah se animations lag karti thi, typing delay hota tha, scrolling smooth nahi rehti thi.

Q: Fiber architecture ka sabse important feature kya hai jo React 15 mein nahi tha?
A. Code ko chhote pieces mein todna aur beech mein rok kar phir continue karna
B. JSX ko directly browser-friendly code mein compile karna bina Babel ke
C. key prop ke bina bhi lists ko correctly reorder karna
D. Multiple setState calls ko ek saath group karke ek hi render karna
> A. React 15 sab kaam ek saath karta tha (synchronous, non-interruptible). Fiber kaam ko chhote units (work packages) mein tod deta hai, har unit ke baad check kar sakta hai ki urgent kaam toh nahi, phir agla unit process karo.

Q: Fiber architecture kaun si data structure use karta hai jo interruptible rendering allow karta hai?
A. Binary tree — har node ke do children hote hain
B. Linked-list — har node connected hai child, sibling, aur return pointer se
C. Stack — nodes ek ke upar ek stack hote hain, LIFO order mein process hote hain
D. HashMap — har node ka unique key hota hai, O(1) lookup time
> B. Fiber linked-list based approach use karta hai. Har node ke teen connections hote hain — child (pehla child), sibling (agla sibling), return (parent ko wapas jaane ke liye). Ye structure allow karta hai ki ek node process karo, check karo, phir agla node process karo.

Q: Fiber architecture mein Render phase aur Commit phase mein kya fark hai?
A. Render phase sirf mobile devices ke liye hai, Commit phase desktop ke liye
B. Render phase mein DOM changes calculate hote hain (interruptible), Commit phase mein apply hote hain (not interruptible)
C. Render phase mein event handlers process hote hain, Commit phase mein state updates apply hote hain
D. Render phase asynchronous hai, Commit phase synchronous hai — dono interruptible hain
> B. Render phase (Reconciliation phase) mein Virtual DOM traverse hota hai, changes calculate hote hain — ye interruptible hai aur DOM change nahi hota. Commit phase mein calculated changes real DOM mein apply hote hain — ye not interruptible hai.

Q: Fiber architecture mein kaun si priority sabse high hoti hai?
A. Normal — regular state updates, data fetching, general rendering
B. High — animations, transitions, visual feedback
C. Immediate — user input, click events, typing
D. Low — pre-rendering, offscreen content, background tasks
> C. Immediate priority sabse high hai — user input, click events, typing. React ensure karta hai ki user interaction pehle process ho, phir animations, phir normal updates, aur sabse last mein background tasks.

Q: "Cooperative scheduling" ka matlab kya hai?
A. React saare kaam ek saath karta hai aur browser ko baad mein control deta hai
B. React browser ko control nahi deta — jab tak poora kaam khatam nahi ho jaata, browser freeze rehta hai
C. React apna kaam chhote pieces mein karta hai aur har piece ke baad browser ko control wapas deta hai
D. React aur browser dono ek saath parallel mein kaam karte hain — do cores use hote hain
> C. React browser ke saath cooperate karta hai — kaam ko chhote pieces mein divide karo, ek piece karo, browser ko control do (taaki wo apna rendering/event handling kar sake), phir agla piece lo. Isse browser freeze nahi hota.

A. Fiber ek naya React syntax hai jo developers ko alag tareeke se code likhne deta hai

A. Synchronous reconciliation ki problem — browser freeze kyun ho raha tha
B. Kaam ko chhote pieces mein todne ki problem — interruptible rendering

## TrueFalse

Q: Fiber architecture React 15 mein bhi tha, bas React 16 mein ise improve kiya gaya.
- True
- False
> False. React 15 mein reconciliation synchronous tha (no Fiber). Fiber React 16 mein naya aaya — ek complete rewrite of the reconciliation engine. React 15 tree ko recursively process karta tha, Fiber linked-list based approach use karta hai.

---

Q: Render phase mein Virtual DOM mein changes calculate hote hain aur ye interruptible hai — beech mein rok sakte hain.
- True
- False
> True. Render phase (aka Reconciliation phase) mein React sirf calculations karta hai — DOM change nahi hota. Is phase ko beech mein rok kar urgent kaam pehle kar sakte hain. Commit phase (jahan actual DOM update hota hai) interruptible nahi hai.

---

Q: Fiber architecture React ko complete asynchronous rendering deta hai — saara kaam background thread mein hota hai.
- True
- False
> False. Fiber asynchronous rendering nahi hai — ye cooperative scheduling hai (concurrent mode ka foundation). Saara kaam main thread mein hota hai, lekin chhote pieces mein, jisse browser freeze nahi hota. Background thread ki baat nahi hai.

---

Q: Commit phase mein lifecycle methods (jaise useEffect) call hote hain aur ye phase interruptible nahi hai.
- True
- False
> True. Commit phase tab shuru hota hai jab React sure hai ki kaun se changes apply karne hain. Ek baar commit shuru, beech mein rok nahi sakte — saare DOM updates aur lifecycle methods (`componentDidMount`, `useEffect`) ek saath execute hote hain.

## ShortAnswer

Q: Synchronous reconciliation ki problem kya thi aur Fiber ne ise kaise solve kiya?

<details>
<summary>Sample Answer</summary>

**Problem:** React 15 mein reconciliation synchronous tha — ek baar shuru hone ke baad beech mein nahi roka ja sakta tha. Jab tak poora Virtual DOM tree compare nahi ho jaata, browser freeze rehta tha. 50ms ka bhi reconciliation ho toh browser animations nahi chal paati, typing delay hota, scrolling smooth nahi rehti.

**Solution — Fiber Architecture:**

1. **Chhote pieces mein kaam:** Fiber kaam ko units (work packages) mein tod deta hai. Har unit itna chhota hai ki ek browser frame (16ms) ke andar complete ho sakta hai.

2. **Interruptible:** Har unit ke baad React check kar sakta hai — "koi urgent kaam toh nahi?" Agar haan (user click, typing), toh pehle woh karo, phir bacha hua Fiber kaam karo.

3. **Priority levels:** React decide kar sakta hai ki user input pehle, phir animations, phir normal updates, phir background tasks.

4. **Linked-list structure:** Fiber tree linked-list se connected hai (child, sibling, return pointers). Ye structure allow karta hai ki ek node process karo, check karo, phir agla node process karo.

</details>

Q: Render phase aur Commit phase mein kya antar hai? Dono phases ke characteristics explain karo.

<details>
<summary>Sample Answer</summary>

**Render Phase (Reconciliation Phase):**
- Virtual DOM tree traverse hota hai
- Changes calculate hote hain (diffing)
- **Interruptible** hai — beech mein rok sakte hain
- **Side-effect free** — actual DOM change nahi hota
- Multiple frames mein spread ho sakta hai

**Commit Phase:**
- Calculate kiye gaye changes real DOM mein apply hote hain
- **Not interruptible** — ek baar shuru kiya toh poora karna padega
- Lifecycle methods call hote hain (`componentDidMount`, `useEffect`)
- Ek hi frame mein complete hota hai
- DOM mutations, refs, aur effects sab yahan handle hote hain

**Analogy:** Jaise tum ek essay likh rahe ho. Render phase = draft prepare karna (changes decide karna, edit karna, pause karke phir continue karna). Commit phase = final copy print karna (ek baar print start kiya toh beech mein nahi rok sakte).

</details>
