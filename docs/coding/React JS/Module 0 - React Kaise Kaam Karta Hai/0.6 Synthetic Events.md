0.5 mein humne dekha ki React event handlers ke andar state updates ko batch karta hai. Lekin ek sawaal aata hai — **React ke event handlers (`onClick`, `onChange`) actually kaam kaise karte hain?**

```jsx
<button onClick={handleClick}>Click Me</button>
```

Jab user button par click karta hai, `handleClick` function chal jaata hai. Lekin React ko kaise pata chala ki button click hua? Iska answer samajhne ke liye pehle browser ke event system ko samajhna padega.

## Browser Events Kya Hote Hain?

Browser khud bahut saare events generate karta hai — `click`, `change`, `input`, `submit`, `keydown`, `mousemove`, etc.

```html
<button>Click</button>
```

JavaScript mein hum aise event listen karte hain:

```javascript
const btn = document.querySelector("button");
btn.addEventListener("click", () => {
  console.log("Clicked");
});
```

Yahan browser khud `"click"` event generate karta hai. Isliye ise **Native Event** bolte hain — browser ka original event.

## React Kya Karta Hai?

React mein hum normally aisa likhte hain:

```jsx
<button onClick={handleClick}>Click</button>
```

Yahan humne `addEventListener()` nahi likha. Phir bhi click detect ho gaya. **Kaise?**

React internally browser ke events ko listen karta hai. Lekin woh browser ka event directly tumhare handler ko nahi deta. Uske beech mein React apna ek **wrapper object** bana deta hai. Us wrapper ko kehte hain — **SyntheticEvent**.

```
Browser Click
     │
     ▼
Native Event
     │
     ▼
React
     │
     ▼
SyntheticEvent
     │
     ▼
Your onClick Handler
```

Matlab tumhare handler ko browser ka raw event nahi milta. React pehle usko wrap karta hai.

## SyntheticEvent Kya Hai?

Jab tum `onClick` mein event receive karte ho:

```jsx
function handleClick(event) {
  console.log(event);
}
```

Ye `event` browser ka event nahi hai. Ye React ka banaya hua object hai — **SyntheticEvent**.

Agar original browser event dekhna ho:

```jsx
function handleClick(event) {
  console.log(event);             // SyntheticEvent
  console.log(event.nativeEvent); // Browser ka original event
}
```

### Definition

> **SyntheticEvent React ka apna wrapper event object hai jo browser ke native event ke upar banta hai. Ye har browser mein consistent properties provide karta hai.**

## React Wrapper Kyun Banata Hai?

Purane browsers mein same event alag behave karte the. Example ke liye — kisi browser mein `event.target` support hota tha, kisi mein `event.srcElement` use hota tha. Mouse events ke `pageX` ka behavior bhi different tha. `preventDefault()` bhi sab browsers mein same nahi tha.

React ne decide kiya — "Browser chahe koi bhi ho, developer ko ek hi format mile." Isliye SyntheticEvent bana. Ab tum har browser mein same properties use karte ho — `event.target`, `event.currentTarget`, `event.preventDefault()`, `event.stopPropagation()`. React ensure karta hai ki ye consistently kaam kare.

```jsx
function handleClick(e) {
  e.preventDefault();    // Cross-browser — har browser mein kaam karega
  e.stopPropagation();   // Same
  e.target;              // Same
  e.currentTarget;       // Same
  e.clientX;             // Mouse events — cross-browser consistent
  e.key;                 // Keyboard events — same
}
```

## Event Delegation — Ek Listener Sab Ke Liye

Agar page mein 100 buttons hain, toh kya React 100 alag event listeners banata hai? Nahi.

Browser mein events **bubble** karte hain — child se parent tak jaate hain:

```
Button click → Div → Body → Document
```

React is bubbling behavior ka fayda uthata hai. React **ek hi event listener** lagata hai — apne root element pe (jo `<div id="root">` hota hai). Jab koi button click hota hai, event root tak bubble karta hai, aur React ka ek hi listener usse catch karta hai. React phir decide karta hai — "ye click kis button ka tha? Kaunsa onClick handler call karna hai?"

```
React: Ek listener root pe
─────────────────────────────────
     root (React listener here ☝️)
       └── div
            ├── button#1  ← click
            ├── button#2
            └── button#3
```

### Definition

> **Event Delegation ek technique hai jisme React har element par alag event listener lagane ke bajaye root element (`<div id="root">`) ke paas ek listener rakhta hai aur event bubbling ki madad se decide karta hai ki kis component ka event handler chalana hai.**

## Event Bubbling

Yeh Event Delegation tabhi possible hai kyunki browser mein events upar travel karte hain. Is process ko **Event Bubbling** kehte hain.

```html
<div>
  <button>Click</button>
</div>
```

Button click hua toh event ka path:

```
Button → Div → Body → Document
```

React isi behavior ka use karta hai. Bina bubbling ke, root listener event ko catch nahi kar paata.

---

> ### ⏳ Purana Concept — Event Pooling (React 17 aur usse pehle)
>
> Ye section **sirf tab padho** jab kabhi purane codebase mein `event.persist()` dikhe. Agar React 18 seekh rahe ho toh ye optional hai.
>
> **Pooling ka matlab:** Maan lo tumhare paas 100 plastic bottles hain. Har baar paani peene ke baad bottle ko phenkne ki jagah tum wahi bottle dho kar dobara use kar lete ho. Isi ko bolte hain Object Pooling — naya object banane ke bajaye purana object dobara use karna.
>
> React 17 mein bhi exactly yehi hota tha. Tumne button click kiya — React ne ek SyntheticEvent object banaya. Tumhara handler chal gaya. Jaise hi handler finish hua, React us object ko **empty** kar deta tha (sab properties null) aur future events ke liye reuse kar leta tha. Isliye ise Pooled Event kehte the.
>
> **Problem kahan aati thi?** Agar tumne setTimeout ke andar event access kiya:
>
> ```jsx
> function handleClick(event) {
>   setTimeout(() => {
>     console.log(event.type); // null — kyunki object already clear ho chuka
>   }, 1000);
> }
> ```
>
> Sequence:
> 1. Button click → event.type = "click"
> 2. setTimeout start hua (callback 1 second baad chalega)
> 3. handleClick function khatam → React ne event object clear kar diya (type = null)
> 4. 1 second baad callback chala → console.log(event.type) → **null**
>
> **Solution tha `event.persist()`:**
>
> ```jsx
> function handleClick(event) {
>   event.persist(); // React ko bolo — "is object ko reuse mat karo"
>   setTimeout(() => {
>     console.log(event.type); // ✅ "click" — object clear nahi hua
>   }, 1000);
> }
> ```
>
> `event.persist()` React 17 mein SyntheticEvent object ko pooling se bahar nikal deta tha. React 18 mein pooling hata di gayi — ab SyntheticEvent normal JavaScript object ki tarah behave karta hai. `persist()` ki zaroorat nahi.

## React Mein Events Kaise Likhte Hain

```jsx
function App() {
  return (
    <>
      {/* ✅ React way — onClick, onChange, etc. */}
      <button onClick={() => alert("Clicked!")}>Click</button>
      <input onChange={(e) => console.log(e.target.value)} />
      <form onSubmit={(e) => { e.preventDefault(); /* submit */ }}>
        <button type="submit">Submit</button>
      </form>
    </>
  );
}
```

React ke saath direct `addEventListener` use karne ki zaroorat nahi hai. React apne SyntheticEvent system ke through sab handle karta hai.


> ❌ SyntheticEvent **native event ko replace nahi karta** — native event ke upar ek wrapper hai
> ❌ SyntheticEvent **sirf React ke event handlers mein available hai** — `addEventListener` se SyntheticEvent nahi milega
> ❌ SyntheticEvent **React 18 mein pooled nahi hai** — freely use karo, `persist()` yaad rakhne ki zaroorat nahi
> ❌ SyntheticEvent **performance ke liye event delegation use karta hai** — but ye React internal hai, tumhe kuch alag nahi karna

### Quick Definitions (Revision Ke Liye)

> **Native Event:** Browser ka original event (`click`, `change`, etc.) jo `addEventListener` se listen kiya jaata hai.

> **SyntheticEvent:** React ka wrapper object jo native event ke upar banta hai. Har browser mein consistent properties provide karta hai.

> **Event Delegation:** React root element par ek listener rakhta hai aur event bubbling ki madad se decide karta hai ki kis component ka handler chalana hai.

> **Event Bubbling:** Browser ka mechanism jisme event child element se parent tak travel karta hai.

> **Event Pooling (React 17):** SyntheticEvent object ko handler ke baad clear karke reuse karna. React 18 mein ye nahi hai.

**In Your Own Words**

1. React event delegation kaise kaam karta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** React har element pe alag event listener nahi lagata. Uski jagah, React root element (jaise `<div id="root">`) pe ek single event listener lagata hai. Jab koi event hota hai, woh bubble hokar root tak jaata hai. React ka ek listener saare events catch karta hai aur decide karta hai ki kaunsa component handler call karna hai. Isse memory efficient hai — chahe 100 buttons ho ya 1000, sirf ek listener.

</details>

2. SyntheticEvent kya hai aur kyun exist karta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** SyntheticEvent React ka apna event wrapper object hai jo native browser event ke upar banta hai. Ye exist isliye karta hai taaki cross-browser consistency mile — `event.target`, `event.preventDefault()` sab browsers mein same kaam kare. React ensure karta hai ki developer ko har browser mein same properties milein, chahe browser specific differences kyun na ho.

</details>

3. Event Delegation aur Event Bubbling mein kya relation hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Bubbling ki wajah se event child se parent tak travel karta hai. Event Delegation isi behavior ka fayda uthata hai — React root element par ek listener rakhta hai, aur bubbling ki madad se saare events us root tak pahunchte hain. Bina bubbling ke event delegation possible nahi hai.

</details>

4. Event Pooling kya thi aur kyun React 18 mein nahi hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Event Pooling React 17 ka optimization tha jahan SyntheticEvent object ko handler khatam hote hi clear kar diya jaata tha aur future events ke liye reuse kar liya jaata tha. Isse memory allocation kam hoti thi, lekin asynchronous code (setTimeout, Promise) mein event ki properties null ho jaati thi. React 18 mein pooling hata di gayi kyunki modern JavaScript engines itne fast hain ki reuse ki zaroorat nahi. Ab SyntheticEvent normal object ki tarah behave karta hai.

</details>

5. React mein direct addEventListener use karna chahiye ya nahi?

<details>
<summary>Sample Jawab</summary>

**Jawab:** React mein direct addEventListener use karne ki zaroorat nahi hai — React ka built-in event system (onClick, onChange, onSubmit etc.) sab kuch handle karta hai. Direct addEventListener React ke event system se bahar hai — isse SyntheticEvent nahi milega, event delegation ka fayda nahi milega, aur bugs aa sakte hain. React ka event system hi prefer karo.

</details>
