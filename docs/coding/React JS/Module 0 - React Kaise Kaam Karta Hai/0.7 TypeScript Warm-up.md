# TypeScript Warm-up

## TypeScript Kya Hai?

TypeScript = JavaScript + Types. Bas itna fark hai.

```js
// JavaScript — koi type check nahi
function add(a, b) {
  return a + b;
}
add(5, "10"); // "510" — bug, but JS doesn't care
```

```ts
// TypeScript — types defined
function add(a: number, b: number): number {
  return a + b;
}
add(5, "10"); // ❌ Error — string is not assignable to number
```

TypeScript error **development time** mein hi dikha deta hai. Browser mein jaane se pehle hi pata chal jaata hai ki kuch galat hai.

## Basic Types

```ts
let name: string = "Vin";
let age: number = 25;
let isLearning: boolean = true;
```

`string` text ke liye, `number` numbers ke liye, `boolean` true/false ke liye. Colon (`:`) ke baad type likhi jaati hai.

## Arrays

```ts
let numbers: number[] = [1, 2, 3];
let fruits: string[] = ["apple", "mango", "banana"];
```

`number[]` ka matlab — **ye variable ek array hai aur iske har element ka type `number` hoga.**

Allowed:
```ts
numbers.push(4);
numbers.push(10);
```

Not allowed:
```ts
numbers.push("hello"); // ❌ Error — array sirf numbers ke liye hai
```

> **Note:** TypeScript mein isi type ko `Array<number>` bhi likha ja sakta hai. Dono exactly same hain. Lekin `<number>` wala syntax **Generic** hai — hum isse baad mein detail mein seekhenge. Abhi ke liye `number[]` hi use karo.

## Objects

```ts
let user: { name: string; age: number } = {
  name: "Vin",
  age: 25,
};
```

Object ke har property ka type define karte ho. Agar koi property galat type ki di, toh TypeScript error dega:

```ts
user.age = "twenty-five"; // ❌ Error — string nahi, number chahiye
```

## Functions

```ts
// Parameter types + return type
function add(a: number, b: number): number {
  return a + b;
}

// Return type TypeScript khud bhi infer kar sakta hai
function multiply(a: number, b: number) {
  return a * b; // TypeScript automatically samajh gaya ki return type number hai
}
```

Parameters ke baad `:` lagake type likho. Return type function ke parameters ke baad `): type` likho.

## Optional Properties

```ts
function greet(name: string, greeting?: string): string {
  return `${greeting || "Hello"}, ${name}`;
}
```

Question mark (`?`) ka matlab — ye parameter pass karna zaroori nahi hai. Agar pass nahi kiya, toh `undefined` hoga.

Objects mein bhi optional properties kaam karti hain:

```ts
let user: { name: string; age?: number } = {
  name: "Vin",
  // age optional hai, isliye ye valid hai
};
```

## Union Types

```ts
let id: string | number = "abc123";
id = 456; // ✅ allowed
id = true; // ❌ Error — boolean allowed nahi hai
```

Pipe (`|`) ka matlab "ya" — variable in dono types mein se koi bhi ho sakta hai.

## Interface

Interface ek **object ka shape** hota hai — batata hai ki object mein kaun si properties hongi aur unka type kya hoga:

```ts
interface User {
  name: string;
  age: number;
}

let user: User = {
  name: "Vin",
  age: 25,
};
```

Interface ko ek **blueprint** ki tarah socho. Jaise ek ghar banane se pehle blueprint hota hai ki kitchen yahan hoga, bedroom wahan — waise hi interface batata hai ki object mein kya kya hoga aur uska type kya hoga.

```
Interface (blueprint)
     │
     ▼
{
  name: string;
  age: number;
}
     │
     ▼
let user: User = {
  name: "Vin",    // ✅ string
  age: 25         // ✅ number
};
```

Agar galat type doge toh error:
```ts
let user: User = {
  name: "Vin",
  age: "twenty-five", // ❌ Error — string, number chahiye
};
```

Interface ka use React mein **component props** ke types define karne ke liye regularly hoga. Isliye abhi se familiar ho jao.

### Is Chapter Mein Humne Kya Seekha (aur kya nahi)

| Seekha | Abhi Nahi Seekha (baad mein) |
|--------|------------------------------|
| `string`, `number`, `boolean` | `unknown`, `any` |
| `number[]`, `string[]` | `Array<number>` (Generic syntax) |
| Objects with inline types | `type` keyword vs `interface` |
| Function parameter + return types | Generics (`<T>`) |
| Optional properties (`?`) | `React.ReactNode`, `React.ChangeEvent` |
| Union types (`string \| number`) | `useState<number>`, `useRef<HTMLInputElement>` |
| Interface (object shape) | Utility types, mapped types |

Jo "abhi nahi seekha" column mein hai — jab React mein naturally use honge tab detail mein seekhenge. Abhi confusion ki zaroorat nahi hai.

---

> ❌ TypeScript **React ko slow nahi karti** — types sirf development time check hote hain, runtime performance pe koi asar nahi
> ❌ TypeScript **extra syntax nahi hai** — basic types 15 minute mein aa jaate hain, baaki concepts React ke saath naturally seekho ge
> ❌ TypeScript **sirf React ke liye nahi hai** — lekin React ke saath use karna standard practice ban chuka hai, isliye yahan seekh rahe ho

**In Your Own Words**

1. TypeScript JavaScript se kaise alag hai? Ek example do.

<details>
<summary>Sample Jawab</summary>

**Jawab:** JavaScript mein function parameters ka type nahi batana padta — `function add(a, b)` likh sakte ho aur koi bhi value pass kar sakte ho. TypeScript mein tum types define karte ho — `function add(a: number, b: number): number`. Agar koi `add(5, "10")` call karega, TypeScript error dega. Ye bug development time mein hi catch ho jaata hai, production mein nahi aata.

</details>

2. `number[]` ka kya matlab hai? `Array<number>` se kyun confuse hone ki zaroorat nahi?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `number[]` ka matlab hai "ek array jiske andar sirf numbers hain." `Array<number>` exactly same hai — bas syntax alag hai. `Array<number>` wala syntax **Generic** hai, jo hum baad mein seekhenge. Abhi ke liye `number[]` use karo. Dono ka matlab same hai — array of numbers.

</details>

3. Interface kya hota hai? Real-world example do.

<details>
<summary>Sample Jawab</summary>

**Jawab:** Interface ek object ka shape define karta hai — batata hai ki object mein kaun si properties hongi aur unka type kya hoga. Jaise ghar banane se pehle blueprint hota hai (kitchen yahan, bedroom wahan), waise hi interface object ka blueprint hai. Example: `interface User { name: string; age: number; }` — ab koi bhi `User` type ka object sirf inhi properties ke saath valid hoga.

</details>

4. Union type kab use karte ho? Example do.

<details>
<summary>Sample Jawab</summary>

**Jawab:** Union type tab use karte ho jab koi value multiple types mein se koi bhi ho sakti hai. Example: `let id: string | number` — id kabhi string hogi ("abc123"), kabhi number (456). Pipe (`|`) ka matlab "ya" hota hai. Agar koi boolean assign karega, TypeScript error dega.

</details>
