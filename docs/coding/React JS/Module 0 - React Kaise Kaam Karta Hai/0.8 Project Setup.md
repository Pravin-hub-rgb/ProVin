## 1. Node.js — JavaScript Ko Browser Ke Bahar Chalana

Normally JavaScript sirf browser ke andar chalti hai — Chrome, Firefox apne engine se ise execute karte hain. Lekin React project set up karna, packages install karna, dev server chalana — ye sab terminal mein hota hai, browser ke bahar. Isliye ek separate runtime chahiye jo terminal mein JavaScript execute kar sake.

**Node.js** wahi runtime hai — ek JavaScript engine jo browser ke bahar, terminal/server par JavaScript chalata hai.

```
Browser  → JavaScript ko browser ke andar chalata hai
Node.js  → JavaScript ko terminal/server par chalata hai
```

React project banane ke liye Node.js zaroori hai kyunki:
- Iske saath **npm** (package manager) bundled aata hai — packages install karne ke liye
- Dev server chalane ke liye isi runtime ki zaroorat hoti hai
- Build process (production ke liye code compile karna) bhi isी par chalta hai

**Clarification:** Node.js React ka part nahi hai — ye ek independent, separate tool hai. React khud isse depend nahi karta, lekin React project ki tooling (npm, dev server, build) Node.js par chalti hai.

**Check karo already installed hai ya nahi:**
```
node --version
npm --version
```
Version number aaye to installed hai. Error aaye to nodejs.org se install karo.

Node.js samajh liya — ab isका ek modern alternative bhi dekhna zaroori hai, kyunki development community mein dono actively use hote hain, aur aage jab commands dekhoge to dono ke liye syntax pata hona chahiye.

## 2. Bun — Node.js Ka Modern Alternative

**Bun** bhi ek JavaScript runtime hai, bilkul Node.js ki tarah — matlab ye bhi terminal mein JavaScript chalata hai. Fark ye hai ki Bun zyada naya hai aur design-wise fast hone ke liye banaya gaya hai.

```
Node.js → 2009 mein aaya, sabse zyada widely used, "legacy standard"
Bun     → 2023 mein aaya, faster, built-in tooling zyada
```

Bun ke specific advantages:
- **Speed** — package installation Node.js ke comparison mein kaafi fast hai (roughly 4x tak)
- **Built-in TypeScript support** — TypeScript ke liye alag se configuration nahi karni padti
- **Built-in bundler, test runner, aur package manager** — teeno tools ek hi runtime ke andar aate hain, alag se install nahi karne padte

**Check karo installed hai ya nahi:**
```
bun --version
```
Nahi hai to bun.sh se install karo.

Node.js aur Bun dono runtimes hain — dono JavaScript ko terminal mein chalate hain, bas Bun newer aur faster hai. In dono ke apne-apne command tools bhi hain (`npm`/`npx` Node.js ke saath, aur inke equivalents Bun ke saath) — wahi ab dekhte hain.

## 3. npm, npx aur Bun

### Package Kya Hota Hai?

JavaScript ki duniya mein kisi bhi reusable library ya tool ko **package** kehte hain. React ek package hai, Vite ek package hai, Axios ek package hai — kisi aur developer ne code likha, internet par publish kar diya, aur hum apne project mein use kar sakte hain.

Sawaal ye hai — ye packages hamare computer mein aayenge kaise?

### npm — Packages Ko Permanently Install Karna

npm (Node Package Manager) Node.js ke saath bundled aata hai. Iska kaam hai packages ko internet se download karke project mein permanently add karna.

```bash
npm install react
```

Is command ka matlab: "React package ko mere project mein install kar do." React ko har din use karna hai — components banane hain, state manage karni hai — isliye ye permanently install hota hai.

> **npm ka kaam:** Packages ko permanently install aur manage karna.

Lekin kya har package ko permanently install karna zaroori hai?

### Vite Kya Hai? (Brief)

Agle section mein Vite ke baare mein detail mein dekhenge, lekin abhi itna samajh lo: Vite ek tool hai jo naya React project automatically set up karta hai — folder structure banata hai, configuration add karta hai, React install karta hai.

Vite ka installer **create-vite** kehlata hai. Jab tum `create-vite` chalate ho, toh yeh project bana deta hai. Ek baar project ban gaya, toh is installer ki phir kabhi zaroorat nahi padti.

Isliye `create-vite` ko permanently install karna bekar hai. Yahan aata hai npx.

### npx — Bina Install Kiye Ek Baar Run Karna

npx bhi npm ke saath aata hai. Iska kaam hai kisi package ko **bina permanently install kiye, sirf ek baar run karna.**

```bash
npx create-vite
```

Is command ka matlab:
1. npx internet se `create-vite` package download karta hai
2. Usko sirf ek baar run karta hai — jo project bana deta hai
3. Kaam khatam hone ke baad us installer ko permanently install nahi karta

> **npx ka kaam:** Package ko bina permanently install kiye temporarily run karna.

### npm vs npx — Kab Kaunsa Use Karna Hai

| Scenario | Command | Kyun? |
|---|---|---|
| React ko project mein permanently chahiye | `npm install react` | Har component mein import karna hai |
| Sirf ek baar project banana hai | `npx create-vite` | Installer ki baad mein zaroorat nahi |

**Simple rule:** Agar package har roz use karna hai → `npm install`. Agar sirf ek baar chalana hai → `npx`.

### Bun Mein Equivalents

Bun ke saath bhi same concept hai, sirf commands ke naam alag hain:

| Use Case | Node.js | Bun |
|---|---|---|
| Saari dependencies install karna | `npm install` | `bun install` |
| Naya package add karna | `npm install react` | `bun add react` |
| Package bina install kiye run karna | `npx create-vite` | `bunx create-vite` |
| Dev server chalana | `npm run dev` | `bun run dev` |

Concept identical hai — sirf syntax alag hai. Ab in tools ka actual use karte hain project banane ke liye. Lekin project banane se pehle ye samajhna zaroori hai ki kaunsa tool actually project create karega aur development ke time use chalayega — woh hai Vite.

## 4. Vite — Build Tool

**Vite** ek build tool hai jo teen kaam karta hai:
1. React project ka starting structure generate karta hai
2. Development ke dauraan ek local server chalata hai
3. Production ke liye final optimized code build karta hai

**Vite se pehle:** Create React App (CRA) standard tool tha. CRA webpack-based tha — har chhote code-change par poore project ko re-bundle karta tha, jo slow tha. React ki official documentation ab CRA recommend nahi karti; Vite standard hai.

**Clarification:** Vite, CRA ka simple "upgrade" nahi hai — architecture level par complete rewrite hai.

**Vite fast kyun hai:** Development ke dauraan Vite native ES modules use karta hai — matlab code change hone par sirf wahi module reload hota hai jo change hua, poora project rebuild nahi hota. (Iska practical effect — HMR — thodi der mein dev server start karne ke baad dekhenge, jab actually demonstrate ho sakega.)

Ab Node.js/Bun, npm/npx, aur Vite — teeno concept clear hain. Inhe combine karke ab ek actual project banate hain.

## 5. Project Create Karna (Step-by-Step)

Har step ke liye Node.js aur Bun dono commands diye hain — jo bhi runtime choose kiya ho, usी se consistently follow karo.

**Step 1 — Folder banao aur usme jao:**
```
cd Desktop
mkdir react-course
cd react-course
```

**Step 2 — Project generate karo:**

Node.js:
```
npx create-vite@latest . -- --template react-ts
```
Bun:
```
bunx create-vite@latest . -- --template react-ts
```

Ye command:
- Current folder (`.`) mein project generate karta hai
- `react-ts` template use karta hai — React + TypeScript pre-configured
- Vite ko build tool ke roop mein set karta hai

**Step 3 — Dependencies install karo:**

Node.js:
```
npm install
```
Bun:
```
bun install
```

Ye `package.json` mein listed saari libraries download karta hai, aur `node_modules` folder mein store karta hai. Node.js ke saath `package-lock.json` banta hai; Bun ke saath `bun.lock` banta hai — dono ka kaam same hai: exact installed versions ko lock/track karna.

**Step 4 — Dev server start karo:**

Node.js:
```
npm run dev
```
Bun:
```
bun run dev
```

Output kuch is tarah dikhega:
```
VITE v6.x.x  ready in 200ms
➜  Local:   http://localhost:5173/
```
Browser mein `http://localhost:5173` kholo — project chal raha hoga.

Dev server ab chal raha hai — isi state mein ek important behavior dekhne ko milega jab code change karoge. Wahi HMR hai, jo abhi practically dikhega.

## 6. HMR — Hot Module Replacement

Ab jab bhi code change karoge (dev server chalte hue), browser automatically update hoga bina full page reload ke. Isse HMR kehte hain.

**Flow:**
```
Code change hua
      ↓
Vite sirf wahi module replace karta hai jo change hua
      ↓
Browser update ho jata hai — current state preserve rehti hai
      ↓
Poore page ka reload nahi hota
```

**Clarification:** HMR browser ka native feature nahi hai — ye Vite ka feature hai. Vite hi change detect karta hai aur browser ko selectively update karta hai.

Ye feature CRA ke comparison mein practically kaafi noticeable hai — CRA mein chhota change karne ke baad bhi reload mein visible delay hota tha, Vite mein ye near-instant hota hai.

Ab project chal raha hai aur HMR bhi samajh liya — is point par project ke andar dekhna zaroori hai ki actually kaunsi files bani hain aur kya karti hain.

## 7. Project Folder Structure

```
react-course/
├── index.html
├── package.json
├── tsconfig.json
├── tsconfig.app.json
├── tsconfig.node.json
├── vite.config.ts
├── public/
└── src/
    ├── main.tsx
    ├── App.tsx
    ├── App.css
    ├── index.css
    └── vite-env.d.ts
```

**Har file ka role:**

- **`index.html`** — Browser sabse pehle ye file load karta hai. Isme `<div id="root">` hai jahan React app mount hota hai, aur ek `<script type="module" src="/src/main.tsx">` hai jo React app ko load karta hai.
- **`package.json`** — Project ki metadata (name, version), dependencies ki list, aur runnable scripts (`dev`, `build`, etc.). `npm install`/`bun install` isi file ko padh kar packages download karta hai.
- **`tsconfig.json`** — TypeScript ki configuration — strictness level, allowed features, etc. (`tsconfig.app.json` app-code ke liye, `tsconfig.node.json` Vite jaise Node-tooling ke liye — do separate configs isliye hain kyunki app code aur build-tooling code ki requirements alag hoti hain.)
- **`vite.config.ts`** — Vite ka apna configuration file (plugins, build options).
- **`src/main.tsx`** — Entry point. Yahan `ReactDOM.createRoot()` call hota hai jo React app ko `<div id="root">` ke andar render karta hai.
- **`src/App.tsx`** — Root component. Actual React code yahan se likhna shuru hota hai.

Folder structure samajh liya — ab isی `App.tsx` file ko edit karke pehla actual component likhte hain.

## 8. Pehla Component

`src/App.tsx` ko is code se replace karo:

```tsx
interface GreetingProps {
  name: string;
  age?: number;
}

function Greeting({ name, age }: GreetingProps) {
  return (
    <div>
      <h1>Hello, {name}!</h1>
      {age && <p>Age: {age}</p>}
    </div>
  );
}

function App() {
  return (
    <div>
      <Greeting name="Vin" age={25} />
    </div>
  );
}

export default App;
```

**Breakdown:**
- `GreetingProps` — ek `interface` jo define karta hai ki `Greeting` component ko `name` (string, required) aur `age` (number, optional — `?` se marked) props chahiye.
- `Greeting` — ek functional component jo `name` aur (agar present ho) `age` ko display karta hai.
- `App` — root component, jo `Greeting` ko render karta hai.

Notice karo — is code mein `useState`, `useRef`, ya generics kuch bhi nahi hai. Sirf basic TypeScript types + `interface`. Ye jaan-boojh kar hai — koi bhi naya concept tabhi introduce hoga jab uski actual zaroorat ho.

Save karo, browser check karo (agar dev server pehle se chal raha hai, HMR ki wajah se change turant reflect hoga) — "Hello, Vin!" aur "Age: 25" dikhna chahiye.

Component ban gaya, project chal raha hai — ab ek final setup step baaki hai jo har professional project mein hota hai: code quality tools.

## 9. ESLint + Prettier Setup

**ESLint** — code quality checker, potential bugs aur inconsistent patterns flag karta hai. Vite ka `react-ts` template ye already configured deta hai — matlab ye pehle se hi kaam kar raha hai bina extra setup ke.

**Prettier** — code formatter, formatting-style ke conflicts avoid karta hai. Ye alag se install karna padta hai:

Node.js:
```
npm install -D prettier eslint-config-prettier
```
Bun:
```
bun add -d prettier eslint-config-prettier
```

Project root mein `.prettierrc` file banao:

```json
{
  "semi": true,
  "singleQuote": false,
  "tabWidth": 2,
  "trailingComma": "all",
  "printWidth": 100
}
```

**Clarification:** Team-based ya professional projects mein ESLint/Prettier optional nahi hote — standard practice hai inhe project ke pehle din se set up karna.
