Socho tumhare paas do photos hain — ek purani, ek nayi. Tumhe dono ke beech mein fark nikalna hai. Tum kaise karoge? Dono ko side-by-side rakh kar compare karoge, na? Har element dekhenge — "ye same hai, ye badla hai, ye naya aaya hai."

React bhi kuch aisa hi karta hai. Jab state change hoti hai, React ek naya Virtual DOM tree banata hai. Phir woh naya tree purane tree se compare karta hai. Is process ka naam hai — **Reconciliation**.

# Reconciliation, Diffing aur `key` Prop

## Reconciliation Kya Hai?

Reconciliation ka matlab hai — **do trees ko compare karna aur pata lagana ki actually kya change hua hai.**

React ka reconciliation process do cheezein ensure karta hai:

1. **Speed** — Pure DOM ko baar-baar update nahi karna
2. **Accuracy** — Sirf woh elements update karna jo actually badle hain

## Naive Approach — O(n³) Problem

Agar React do trees ko brute-force compare kare (har node ko har node se), toh time complexity hoti **O(n³)** — jahan n hai nodes ki total count. 1000 nodes ke liye 1 billion comparisons. Ye bahut slow hai.

React ne is problem ko solve kiya do assumptions ke saath:

1. **Different type → alag tree** — Agar parent element ka type change ho gaya (div → span), toh poora subtree rebuild karo
2. **`key` prop → stable identity** — Same type ke elements mein `key` se pata chalega ki kaunsa element kya hai

In do assumptions ki wajah se React O(n³) se **O(n)** mein laa diya — matlab linear time. 1000 nodes ke liye sirf 1000 comparisons.

## Diffing Algorithm — Kaise Kaam Karta Hai

### 1. Root Elements Compare

React sabse pehle root elements ko compare karta hai. Agar type different hai, toh poora purana tree destroy hota hai aur naya build hota hai:

```jsx
// Before
<div>
  <Counter />
</div>

// After
<span>
  <Counter />
</span>
```

⚠️ Yahan `<Counter />` component destroy ho jayega aur uska state reset ho jayega — kyunki parent `<div>` → `<span>` change ho gaya. Poore subtree ka unmount aur remount hoga.

### 2. Same Type — Update Props

Agar type same hai, toh React sirf props compare karta hai:

```jsx
// Before
<div className="old" style={{ color: 'red' }} />

// After
<div className="new" style={{ color: 'blue' }} />
```

React kya karega:
- `className` → `"new"` update karega
- `style.color` → `"blue"` update karega
- DOM element destroy nahi karega, sirf properties update karega

### 3. Same Type — Recursive Children

Phir React children ke liye bhi same process recursively apply karta hai.

```jsx
// Before
<div>
  <h1>Title</h1>
  <p>Description</p>
</div>

// After
<div>
  <h1>New Title</h1>
  <p>New Description</p>
  <footer>Footer</footer>
</div>
```

React kya karega:
- `<h1>` ka text content update karega
- `<p>` ka text content update karega
- `<footer>` naya element hai — add karega

## `key` Prop — Kyun Critical Hai?

Ab sawaal aata hai — **lists ke case mein kaise kaam karega?**

```jsx
// Before
<ul>
  <li>Apple</li>
  <li>Mango</li>
  <li>Banana</li>
</ul>

// After (Banana pehle aa gaya)
<ul>
  <li>Banana</li>
  <li>Apple</li>
  <li>Mango</li>
</ul>
```

Bina `key` ke React kya karega? Position se compare karega:
- Position 1: `Apple` → `Banana` (text change — update)
- Position 2: `Mango` → `Apple` (text change — update)
- Position 3: `Banana` → `Mango` (text change — update)

**3 updates!** Jabki asal mein sirf order change hua hai, content nahi.

Ab `key` ke saath:

```jsx
// Before
<ul>
  <li key="a">Apple</li>
  <li key="m">Mango</li>
  <li key="b">Banana</li>
</ul>

// After
<ul>
  <li key="b">Banana</li>    // key="b" — pehle position 3 tha, ab position 1
  <li key="a">Apple</li>     // key="a" — pehle position 1 tha, ab position 2
  <li key="m">Mango</li>     // key="m" — pehle position 2 tha, ab position 3
</ul>
```

React `key` se pata laga lega ki **elements same hain, sirf order change hua hai.** Toh React DOM elements ko destroy nahi karega, sirf **reorder** karega. Text bhi nahi badlega — kyunki same elements hain.

**0 updates in DOM!** Sirf position swap hogi.

> **Analogy — Student Roll Numbers:** Socho ek class mein students hain. Unke naam change ho sakte hain (content change), lekin roll number fix hai (key). Agar teacher sirf naam se pukare, toh list rearrange karna mushkil hai. Lekin roll number se — "Roll 3, aage aa" — easy. `key` React ko woh roll number deta hai.

## `key` Kaise Choose Karein?

```jsx
// ✅ Sahi — unique ID
<li key={item.id}>{item.name}</li>

// ❌ Galat — index (list change hogi toh bugs aayenge)
<li key={index}>{item.name}</li>

// ❌ Galat — Math.random() (har render pe naya key = destroy + remount)
<li key={Math.random()}>{item.name}</li>
```

**Index kyun nahi use karna chahiye?**

Imagine karo — ek list hai jisme tum items add/remove/delete kar rahe ho:

```jsx
const [items, setItems] = useState(['A', 'B', 'C']);

// Ab tumne 'A' delete kar diya — items ab ['B', 'C']
// Index 0 pe pehle 'A' tha, ab 'B' hai — but React same index (=same key) dekhega
// Agar input field mein kuch type kiya tha 'A' ke saath, toh woh state 'B' ko transfer ho jayegi!
```

`key` ki **stability** React ko batati hai ki kaunsa element **actually same hai** across re-renders. Index stable nahi hota — list change par index change ho jata hai.

## Reconciliation Summary

```
State Change → Naya Virtual DOM → Purane se Compare
                                        |
                              ┌─────────┴──────────┐
                              │  Type Different?    │
                              │  → Destroy + Rebuild│
                              └─────────┬──────────┘
                                        │
                              ┌─────────┴──────────┐
                              │  Same Type?         │
                              │  → Update Props     │
                              └─────────┬──────────┘
                                        │
                              ┌─────────┴──────────┐
                              │  Lists?             │
                              │  → key se compare   │
                              └─────────────────────┘
```


> ❌ Reconciliation **Virtual DOM nahi hai** — Virtual DOM data structure hai, Reconciliation process hai
> ❌ `key` prop **performance ke liye sirf nahi hai** — correctness ke liye bhi hai (state preservation)
> ❌ Reconciliation **hamesha perfect nahi hota** — React's best-effort hai, manual optimization kabhi-kabhi needed hoti hai (`React.memo`, `useMemo`)
> ❌ `key` **index kabhi bhi mat do** — unless list absolutely static ho (kabhi change nahi hoti)

2. React ka diffing algorithm O(n) mein kaise kaam karta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** React do assumptions banata hai — (1) Different type ke elements poora tree change karte hain, (2) `key` prop stable identity deti hai. In assumptions ki wajah se React brute-force (O(n³)) nahi karta, balki linear comparison (O(n)) karta hai. Har node ko sirf ek baar compare karta hai.

</details>

3. `key` prop kyun important hai lists mein? Bina key ke kya problem hoti hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `key` React ko batata hai ki kaunsa element actually same hai across re-renders. Bina key ke React position se compare karta hai — agar list order change ho (item delete/insert/reorder), toh React galat elements ko update kar deta hai. Isse bugs aate hain — jaise input field ka state wrong element mein transfer ho jata hai. Key se React elements ko reorder karta hai, recreate nahi.

</details>

4. Jab parent element ka type change hota hai (div → span) toh kya hota hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** React poora subtree destroy kar deta hai aur naya build karta hai. Agar andar koi component tha (jaise `<Counter />`), uska bhi unmount ho jayega aur state reset ho jayegi. Isliye component wrappers change karte waqt careful rehna padta hai.

</details>

5. `key` prop ke liye index kyun galat hai? Example do.

<details>
<summary>Sample Jawab</summary>

**Jawab:** Index array position hota hai — jab list change hoti hai (delete/insert), index bhi change ho jata hai. Example — list ['A','B','C'] hai, index 0='A', 1='B', 2='C'. Agar 'A' delete karo, ab list ['B','C'] hai — index 0='B', 1='C'. Lekin React sochta hai ki index 0 wala element same hai, toh 'B' ke saath wo state attach ho jayegi jo pehle 'A' ki thi. Isliye unique aur stable key chahiye — jaise item.id.

</details>
