
## MCQ

Q: What is React's latest stable version?
A. React 17
B. React 18
C. React 19
D. React 16
> C. React 19 is the latest stable version (released December 2024). For new projects, always use the latest stable version.

---

Q: Which new feature did React 19 introduce?
A. Automatic Batching
B. Fiber Architecture
C. Actions (form submissions)
D. Concurrent Root
> C. Actions was a new feature in React 19 — sending form submissions directly to the server (`action` prop + `useFormState` + `"use server"`). Automatic Batching was React 18, Fiber was React 16, Concurrent Root was React 18.

---

Q: In which React version were Hooks introduced?
A. React 16.8
B. React 17
C. React 18
D. React 19
> A. Hooks were introduced in React 16.8. This was the moment that fundamentally changed React — `useState`, `useEffect`, etc. all came in 16.8.

---

Q: What problem did React 18 solve compared to React 17? (React 17 vs React 18 batching)
A. React 18 only batched inside event handlers
B. React 18 introduced "Automatic Batching" — batching now happens in setTimeout, Promises, etc.
C. React 18 removed batching
D. React 17 already batched everywhere
> B. React 18 introduced Automatic Batching — in React 17, batching only happened inside event handlers. setTimeout and Promises were not batched, so each `setState` triggered a separate render. React 18 batches everywhere.

---

Q: What was React 17?
A. The release with the most features
B. A bridge version — no new features, just easier upgrades
C. The start of Fiber architecture
D. The introduction of Hooks
> B. React 17 was a "bridge version" — no new features. Its purpose was to smooth the upgrade path (from React 16 to React 18). Changes included event delegation moving and the new JSX transform.

---

Q: What was React 16's biggest contribution?
A. The `useOptimistic` hook
B. React 19's features
C. Fiber architecture
D. Server Components
> C. React 16 introduced Fiber architecture — a new reconciliation algorithm. Hooks came in 16.8. Fiber is covered in detail in 0.4.

## TrueFalse

Q: When upgrading React versions, you can always jump to the latest — patch versions don't matter.
- True
- False
> False. Major version changes (18→19) can introduce breaking changes. Minor and patch releases are backward compatible, but major versions require reading the migration guide — some APIs may be deprecated.

---

Q: The `use()` hook was available in React 18.
- True
- False
> False. The `use()` hook is a new React 19 feature. It didn't exist in React 18. `use()` is used to read promises and context directly.

---

Q: React 19 introduced `useOptimistic` which provides optimistic UI updates.
- True
- False
> True. `useOptimistic` is a React 19 feature — it updates the UI immediately while the real data is being sent to the server. For example, showing a WhatsApp message as "sent" before the server finishes saving it.

---

Q: Refs as props (eliminating `forwardRef`) was a React 17 feature.
- True
- False
> False. Refs as props is a React 19 feature. It didn't exist in React 17. Until React 19, `forwardRef` was required to pass a `ref` to a component.

## ShortAnswer

Q: What are the two biggest differences between React 19 and React 18? Give one feature for each.

<details>
<summary>Sample Answer</summary>

**Answer:**

| Feature | React 18 | React 19 |
|---------|----------|----------|
| **Form handling** | Manual `event.preventDefault()` + `fetch()` + `useState` | **Actions** — `formAction` + `useFormState` + `"use server"` |
| **`use()` hook** | Didn't exist | New — read promises/context directly |
| **`useOptimistic`** | Didn't exist | New — optimistic UI updates |
| **Refs as props** | `forwardRef` was required | `forwardRef` no longer needed |
| **Server Components** | Experimental | Stable |

Common features between both: Automatic Batching (both have it), `createRoot` (both have it), `useId` (both have it). But React 19 adds Actions, `use()`, and `useOptimistic` — none of which existed in React 18.

</details>

Q: Why was React 17 a "bridge version"? What didn't it have?

<details>
<summary>Sample Answer</summary>

**Answer:** React 17 was called a "bridge version" because it had **no new features**. Its purpose was just to smooth the upgrade path (from React 16's legacy to React 18's concurrent mode). Specific changes:

- Event delegation moved from `document` to the root element
- New JSX transform (`react/jsx-runtime` — no React import required)
- No breaking changes — upgrading from React 16 was smooth

So it was a "bridge" — no new features, just making the path from 16 to 18 easier.

</details>

---

Q: Hooks (16.8) and Fiber (16.0) — both came in React 16. What impact did each have on React?

<details>
<summary>Sample Answer</summary>

**Answer:**

**Fiber (React 16.0):** A complete rewrite of React's engine. Replaced the old synchronous rendering (which froze the browser) with the interruptible Fiber system. Introduced priority levels, cooperative scheduling, and the render-commit phase split. (Covered in detail in 0.4.)

**Hooks (React 16.8):** Fundamentally changed React. Function components gained full power — `useState`, `useEffect`, `useContext` all available in function components. No more class components, no `this` binding struggles. Stateful logic became reusable through custom hooks.

Both came in React 16 but served different purposes — Fiber for the internal engine, Hooks for the developer API.

</details>
