
## MCQ

Q: TypeScript, JavaScript se kaise alag hai?
A. TypeScript browser mein chalti hai, JavaScript server pe
B. TypeScript = JavaScript + Types, types compile-time check hote hain
C. TypeScript sirf React ke saath use hoti hai, JavaScript sabke saath
D. TypeScript aur JavaScript ek hi cheez hain — bas naam alag hai
> B. TypeScript JavaScript ka superset hai jo types add karta hai. Development time type checking karta hai, runtime mein JavaScript ban jaata hai.

Q: TypeScript mein `let age: number = 25;` likha hai. `age = "twenty-five"` karne par kya hoga?
A. Code run hoga aur age "twenty-five" ban jayega
B. TypeScript compile-time error dega — number variable mein string assign nahi ho sakti
C. JavaScript automatically type convert kar dega
D. Browser error dega aur page reload ho jayega
> B. TypeScript strict type checking karta hai. Ek baar `number` type declare kar diya toh string assign karte hi compile-time error milega, code compile nahi hoga.

Q: `let fruits: string[]` ka kya matlab hai?
A. fruits ek array hai jisme sirf strings rakh sakte ho
B. fruits ek string hai jisme array store ho sakta hai
C. fruits ek variable hai jo string bhi ho aur array bhi
D. fruits ek function hai jo string array return karta hai
> A. `string[]` ka matlab "array of strings" — har element string hona chahiye. `fruits.push(42)` karne par TypeScript error dega.

Q: TypeScript mein function ka return type kaise define karte hain?
A. `function add(a: number, b: number) -> number`
B. `function add(a: number, b: number): number`
C. `function add(a: number, b: number) returns number`
D. `number function add(a: number, b: number)`
> B. Return type parameters ke baad `): type` likhkar define hota hai. TypeScript khud bhi infer kar sakta hai, lekin explicitly likhna safe hai.

Q: Optional property ka syntax kya hai?
A. `name: string?`
B. `name?: string`
C. `?name: string`
D. `name: ?string`
> B. Question mark property name ke baad, colon se pehle lagta hai. `greeting?: string` ka matlab optional hai — agar nahi di toh undefined.

Q: Union type `string | number` ka kya matlab hai?
A. Variable ek saath string bhi hai aur number bhi — dono ek value mein
B. Variable ya toh string hoga ya number — dono types allowed hain
C. Variable sirf ek baar set ho sakta hai, phir change nahi kar sakte
D. Variable string mein convert ho jayega agar number assign kiya
> B. Union ka matlab multiple types mein se koi ek. `string | number` — value string ho sakti hai ya number. Ek time pe sirf ek type, dono ek saath nahi.

Q: Interface TypeScript mein kya define karta hai?
A. Ek function ka implementation details
B. Ek object ka shape — properties aur unke types
C. Ek variable ki default value aur type
D. Ek array ka structure aur length
> B. Interface object ka shape define karta hai — kaun si properties hongi aur unka type kya hoga. Jaise `interface User { name: string; age: number; }`.

---

Q: Pipe symbol `|` TypeScript mein kya represent karta hai?
A. Bitwise OR operation — numbers ke saath
B. Union type — multiple types mein se koi ek
C. Default value assign karna — fallback ke liye
D. Type assertion — variable ka type force karna
> B. TypeScript mein `|` pipe union type banata hai. `string | number` ka matlab "string ya number" — dono types allowed hain.

## TrueFalse

Q: TypeScript runtime mein bhi type checking karta hai — browser console mein error dikhta hai.
- True
- False
> False. TypeScript sirf development / compile time type check karta hai. Code JavaScript mein compile ho jaata hai, aur browser pure JavaScript run karta hai. Runtime mein koi type checking nahi hoti.

Q: `Array<number>` aur `number[]` dono ka matlab same hai — dono array of numbers ko represent karte hain.
- True
- False
> True. `number[]` aur `Array<number>` exactly same type ko represent karte hain. `Array<number>` wala syntax Generic hai, jo TypeScript mein baad mein detail mein padhenge.

Q: Union type `string | number` ka matlab hai ki variable ek saath dono types ki values hold karega — jaise "abc" aur 456 ek saath.
- True
- False
> False. Union type ka matlab "ya" hai — variable kisi bhi time sirf ek type ki value hold karta hai, dono ek saath nahi. `string | number` ka matlab — abhi string hai, kal number ho sakta hai, lekin ek time pe ek hi.

- True
- False

## ShortAnswer

Q: TypeScript ka type inference kya hota hai? Ek example do.

<details>
<summary>Sample Answer</summary>

**Answer:** Type Inference ka matlab hai ki TypeScript khud automatically type deduce kar leta hai, bina explicitly type bataye.

```ts
let name = "Vin"; // TypeScript automatically infer karega ki name string hai
let age = 25;     // automatically infer karega ki age number hai
```

Jab tum likhte ho `let name = "Vin"`, TypeScript dekhta hai — "ye string hai" — aur automatically `name` ka type `string` set kar deta hai. Isliye baad mein `name = 123` nahi likh sakte, kyunki TypeScript already infer kar chuka hai ki `name` string type ka hai.

</details>

---

Q: Function mein parameter types aur return type define karne ka syntax kya hai? Example do.

<details>
<summary>Sample Answer</summary>

**Answer:**

```ts
function add(a: number, b: number): number {
  return a + b;
}
```

- Parameter `a` ka type `number` hai
- Parameter `b` ka type `number` hai
- Function ka return type `number` hai (colon aur parentheses ke baad)
- Agar return type nahi bhi likho, TypeScript infer kar lega ki `number` return ho raha hai

Agar return type galat ho:
```ts
function add(a: number, b: number): string {
  return a + b; // ❌ Error — number return ho raha hai, string chahiye
}
```

</details>

Q: Interface kya hota hai aur React mein kahan use hoga? Example do.

<details>
<summary>Sample Answer</summary>

**Answer:** Interface ek object ka shape define karta hai — batata hai ki object mein kaun si properties hongi aur unka type kya hoga.

```ts
interface User {
  name: string;
  age: number;
}

let user: User = {
  name: "Vin",
  age: 25
};
```

React mein Interface ka use **component props** ke types define karne ke liye hoga:

```tsx
interface ButtonProps {
  label: string;
  onClick: () => void;
}

function Button({ label, onClick }: ButtonProps) {
  return <button onClick={onClick}>{label}</button>;
}
```

Interface ensure karega ki Button component ko sirf wahi props pass ho jo expected hain, aur unke types bhi correct hain.

</details>

Q: Union types kab use karte hain? Syntax samjhao aur example do.

<details>
<summary>Sample Answer</summary>

**Answer:** Union types tab use karte hain jab koi value multiple types mein se koi bhi ho sakti hai. Syntax — types ke beech mein `|` (pipe) lagao.

```ts
let id: string | number;

id = "abc123"; // ✅ valid — string
id = 456;      // ✅ valid — number
id = true;     // ❌ Error — boolean allowed nahi
```

`|` pipe symbol ka matlab "ya" (OR) hai. `string | number` ka matlab — id ya toh string hogi ya number. Jo types union ka part nahi hain (jaise boolean), unki values assign karte hi TypeScript error dega.

Real use case: E-commerce app mein product ID kabhi string hoti hai ("PROD-001") kabhi number (456). Union type se tum TypeScript ko flexibility dete ho bina type safety sacrifice kiye.

</details>
