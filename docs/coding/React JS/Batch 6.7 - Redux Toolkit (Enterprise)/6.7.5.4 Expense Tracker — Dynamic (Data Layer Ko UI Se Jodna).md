## STAGE 1 — Connecting List + Filter + Stats to Store

### Imagine

In the hardcoded `ExpenseStaticApp.tsx`, `const [filter,setFilter]=useState("all")` was local, and so was `filtered = hardcoded.filter(...)`. Now in `expensesSlice`, `filter` is global — both `FilterBar` and `ExpenseList` need the same `filter`. We need to remove local `useState`, and read `s.expenses.items` + `s.expenses.filter` via `useAppSelector`, updating with `dispatch(setFilter(cat))`. Let's connect List + Stats first, Form in the next stage.

### CONCEPT

`useAppSelector` = the typed `useSelector` from `6.7.3` — to read any slice of the store. `dispatch` = sending an action. The List's derived `filtered` + `total` use the same `filter`/`reduce` logic as `6.7.5.2` — only the source changed from `hardcoded` to `store`.

### CODE

Create a new file `src/components/ExpenseList.tsx` — in this stage, we'll bring the `map` from the Hardcoded UI here:

```tsx
// src/components/ExpenseList.tsx — STAGE 1
import { useAppSelector, useAppDispatch } from "../rtk/hooks";
import { deleteExpense } from "../rtk/expensesSlice";

export function ExpenseList() {
  const { items, filter } = useAppSelector((s) => s.expenses);
  const dispatch = useAppDispatch();

  const filtered = items.filter((e) => filter === "all" || e.category === filter);

  if (filtered.length === 0) return <p>No expenses for {filter}.</p>;

  return (
    <div>
      {filtered.map((e) => (
        <div key={e.id} style={{ display: "flex", justifyContent: "space-between", padding: 8, border: "1px solid #ddd", marginBottom: 6 }}>
          <span>{e.title} — ₹{e.amount} ({e.category})</span>
          <button onClick={() => dispatch(deleteExpense(e.id))}>Delete</button>
        </div>
      ))}
    </div>
  );
}
```

`FilterBar.tsx`:

```tsx
// src/components/FilterBar.tsx
import { useAppSelector, useAppDispatch } from "../rtk/hooks";
import { setFilter } from "../rtk/expensesSlice";

export function FilterBar() {
  const filter = useAppSelector((s) => s.expenses.filter);
  const categories = useAppSelector((s) => s.categories.items);
  const dispatch = useAppDispatch();

  const cats = ["all", ...categories];

  return (
    <div style={{ display: "flex", gap: 8, marginBottom: 12 }}>
      {cats.map((cat) => (
        <button key={cat} onClick={() => dispatch(setFilter(cat))} style={{ fontWeight: filter === cat ? 700 : 400 }}>
          {cat}
        </button>
      ))}
    </div>
  );
}
```

`Stats.tsx`:

```tsx
// src/components/Stats.tsx
import { useAppSelector } from "../rtk/hooks";

export function Stats() {
  const { items, filter } = useAppSelector((s) => s.expenses);
  const filtered = items.filter((e) => filter === "all" || e.category === filter);
  const total = filtered.reduce((sum, e) => sum + e.amount, 0);
  return <p>Total: ₹{total} ({filtered.length} expenses) — Filter: {filter}</p>;
}
```

Why each line matters:

| Code | Why |
|------|------|
| `useAppSelector((s)=>s.expenses)` | `expenses` slice from `RootState` — typed `useSelector` from `6.7.3`, `s.expenses.items` has autocomplete |
| `items.filter(e=> filter==="all"...)` | Same derived logic as `6.7.5.2` — UI code **didn't change**, source changed from `hardcoded` to `store` |
| `dispatch(deleteExpense(e.id))` | `PayloadAction<string>` — `e.id` is a string, `deleteExpense(123)` with a number causes a TS error |
| `categories` via `useAppSelector` | `FilterBar`'s `All/Food/Travel` is dynamic — `fetchCategories` from `6.7.4` will bring `["Beef",...]`, not hardcoded |
| `key={e.id}` | The `key` rule from `6.7.5.2` — stable `id` |

## STAGE 2 — Connecting Form via Dispatch (console.log → real)

### Imagine

In `6.7.5.2 STAGE 3`, `handleAdd` had `console.log({title, amount})` — to verify click + value capture. Now we replace that `handleAdd` with `dispatch(addExpense(...))` — but convert `amount` string → `Number`, generate `id`, `date` as ISO, and validate `title.trim` + `amount>0`.

### CONCEPT

The `PayloadAction<Expense>` of `addExpense` takes a full `Expense` object — `title/amount/category/date/id` all at once. The form's `useState` stays local for `title/amount/category`, but on submit, `dispatch`.

### CODE

Create a new file `src/components/ExpenseForm.tsx` — in this stage:

```tsx
// src/components/ExpenseForm.tsx — STAGE 2
import { useState } from "react";
import { useAppDispatch, useAppSelector } from "../rtk/hooks";
import { addExpense } from "../rtk/expensesSlice";

export function ExpenseForm() {
  const [title, setTitle] = useState("");
  const [amount, setAmount] = useState("");
  const [category, setCategory] = useState("Food");
  const dispatch = useAppDispatch();
  const categories = useAppSelector((s) => s.categories.items);

  const handleAdd = () => {
    const numAmount = Number(amount);
    if (!title.trim() || !numAmount || numAmount <= 0) return;
    dispatch(
      addExpense({
        id: `exp-${Date.now()}-${Math.random().toString(36).slice(2, 6)}`,
        title: title.trim(),
        amount: numAmount,
        category,
        date: new Date().toISOString(),
      })
    );
    setTitle("");
    setAmount("");
  };

  return (
    <div style={{ display: "flex", gap: 8, marginBottom: 12 }}>
      <input placeholder="Title e.g. Chai" value={title} onChange={(e) => setTitle(e.target.value)} />
      <input placeholder="Amount e.g. 20" type="number" value={amount} onChange={(e) => setAmount(e.target.value)} />
      <select value={category} onChange={(e) => setCategory(e.target.value)}>
        {categories.map((cat) => (
          <option key={cat} value={cat}>{cat}</option>
        ))}
      </select>
      <button onClick={handleAdd}>Add</button>
    </div>
  );
}
```

| Code | Why |
|------|------|
| `useState` for `title/amount/category` | Local form state — not in global store, from `6.7.0 What It Is NOT` — `isModalOpen` is local |
| `Number(amount)` + `>0` | Convert input string → number, block `NaN` + negatives — the `amount: number` contract from `6.7.5.3` |
| `id: exp-${Date.now()}-...` | Unique for `key` + delete, `Date.now()` is simple, `crypto.randomUUID()` also works |
| `categories.map` for `<option>` | Dynamic categories — `["Food",...]` not hardcoded, `fetchCategories` will also bring `["Beef",...]` |
| `setTitle("")` after dispatch | UX — clear form after add, can also add `inputRef.current?.focus()` from `6.5:277` here |

## STAGE 3 — App.tsx + Categories Fetch Wireup (Dynamic Complete)

### Imagine

Categories are currently from `initialState` `["Food","Travel","Shopping"]`. To fetch `["Beef","Chicken",...]` from a real API, where to call `dispatch(fetchCategories())` from `6.7.4`? In `useEffect` on `App` mount — not the `useEffect` + `fetch` from `6.2`, but RTK thunk dispatch.

### CONCEPT

`useEffect(() => { dispatch(fetchCategories()) }, [dispatch])` — `dispatch` is stable from `useAppDispatch`, `fetchCategories` thunk auto transitions `pending → fulfilled`.

### CODE

Final `App.tsx` — replacing the Hardcoded UI's `ExpenseStaticApp` from `6.7.5.2`, now Dynamic with Data Layer:

```tsx
// src/App.tsx — STAGE 3 final Dynamic
import { useEffect } from "react";
import { useAppDispatch, useAppSelector } from "./rtk/hooks";
import { fetchCategories } from "./rtk/categoriesSlice";
import { ExpenseForm } from "./components/ExpenseForm";
import { FilterBar } from "./components/FilterBar";
import { ExpenseList } from "./components/ExpenseList";
import { Stats } from "./components/Stats";

export default function App() {
  const dispatch = useAppDispatch();
  const { status, error } = useAppSelector((s) => s.categories);

  useEffect(() => {
    dispatch(fetchCategories());
  }, [dispatch]);

  return (
    <main style={{ maxWidth: 640, margin: "0 auto", padding: 16 }}>
      <h1>💰 Expense Tracker — RTK</h1>
      <Stats />
      {status === "loading" && <p>⏳ Loading categories...</p>}
      {status === "failed" && <p style={{ color: "red" }}>❌ {error}</p>}
      <ExpenseForm />
      <FilterBar />
      <ExpenseList />
    </main>
  );
}
```

| Code | Why |
|------|------|
| `useEffect dispatch(fetchCategories())` | API call on mount — `createAsyncThunk` from `6.7.4`, `useAppDispatch` available inside `Provider` |
| `status === "loading"` | The `status` from `categoriesSlice` — `pending/fulfilled/rejected` from `6.7.4` |
| `categories` in `ExpenseForm`'s `select` | After `fetchCategories`, `["Beef",...]` will appear, showing `Beef` options instead of `Food` in Form — proof that `categories` is global |

## Common Mistakes (in Dynamic)

*   **`useAppSelector(s => s.expenses)` returns object:** `const {items, filter} = useAppSelector(s => s.expenses)` re-renders on every `categories` change — the trap from `6.7.3 STAGE 4`. Better to use separate `const items = useAppSelector(s => s.expenses.items)`, or since both `items` and `filter` are from `expenses`, it works but won't re-render on `categories` change.
*   **Removed `dispatch` from `useEffect` deps:** `useEffect(() => {dispatch(fetchCategories())}, [])` — ESLint `exhaustive-deps` warning, `dispatch` is stable from `useAppDispatch` but keep `dispatch` in deps — that's the Rules of Hooks discipline from `6.1`.
*   **Dispatched `amount` as string:** `dispatch(addExpense({amount}))` where `amount` is a string — TypeScript didn't show an error in `PayloadAction<Expense>` for `amount: number`? Forgot `Number(amount)` conversion — total `reduce` does string concat `\"2050\"`.
*   **Forgot `Provider` in `main.tsx`:** `useAppSelector` throws `could not find react-redux context` — check that `Provider` is wrapped in `main.tsx` from `6.7.3 STAGE 1`.

1. In `6.7.5.2`, `hardcoded.filter`, and in this doc, `items.filter` — the UI code is the same, only the source differs. What proof does this give for the `Data Layer`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** In `6.7.5.2`, `filtered = hardcoded.filter(e=> filter==="all" || e.category===filter)`, and in `6.7.5.4`, `filtered = items.filter(e=> filter==="all" || e.category===filter)` — the `filter` logic, `map` with `key={e.id}`, `reduce` total are the same. The difference is `useAppSelector(s=>s.expenses.items)` instead of the `hardcoded` const — the UI doesn't know whether data comes from a hard array or the RTK store. That's why when you add a new expense to `initialState.items` in `6.7.5.3`, `ExpenseList`/`Stats` auto-update, no change in `App.tsx` — the payoff of abstraction: data source changes, UI stays stable. That's what `how to write project in series prompt.md:130` means by 'UI code didn't change, only the source changed'.

</details>

2. In `ExpenseForm`, why are `title/amount/category` still local `useState`, and not in `expensesSlice`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The form's `title` changes on every keystroke — `onChange(e=>setTitle(e.target.value))` — this is local UI state, shared by only 2-3 components, not global. If put in the store, every keystroke would trigger `dispatch` + store update + `useAppSelector` re-render — that's the 'don't put everything in the store' principle from `6.7.0 What It Is NOT`. The `expensesSlice` only holds the final `Expense` object + `filter` — what `ExpenseList`/`FilterBar`/`Stats` share. Local form state = `useState`, global shared = RTK.

</details>

3. Why is `fetchCategories` in `App.tsx`'s `useEffect`, and not in `ExpenseForm`? Connect it with DRY from `6.1`.

<details>
<summary>Show Answer</summary>

**Sample Answer:** `categories` is needed by both `FilterBar` + `ExpenseForm` — `App` is their common parent. One `dispatch(fetchCategories())` in `App` fills `categories.items` in the store, and both children read via `useAppSelector`. If done in `ExpenseForm`, `FilterBar` would need prop drilling or a duplicate fetch. In `6.1`, `useFetch` was called by each component itself — here the RTK store does a single fetch, multiple consumers — DRY: one fetch, shared by all. The `dispatch` in `useEffect` is stable from `useAppDispatch`, with `dispatch` in deps.

</details>
