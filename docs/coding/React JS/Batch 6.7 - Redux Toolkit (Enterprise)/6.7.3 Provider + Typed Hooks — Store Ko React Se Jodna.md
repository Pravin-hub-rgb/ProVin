Pichle doc `6.7.2` me store ban gaya — `configureStore({reducer:{counter}})` + `counterSlice` ka `increment` mutate jaisa par Immer safe. Ab sawal — React component ko kaise pata chalega store ka `count` badla? `6.7.1` me humne manual `store.subscribe(() => setCount(store.getState().count))` kiya tha, har component me wahi boilerplate. RTK me React ke liye 2 hooks hain — `useSelector` (store se padhna) aur `useDispatch` (parchi bhejna) — par unhe `Provider` ke bina chalao toh error. # Doc 6.7.3 — Provider + Typed Hooks — Store Ko React Se Jodna

## Cheat Sheet (Quick Recall)

```ts
// Store ban gaya (6.7.2 se)
export const store = configureStore({ reducer: { counter: counterSlice.reducer } });
export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;

// Typed hooks (is doc me)
export const useAppSelector = useSelector.withTypes<RootState>();
export const useAppDispatch = useDispatch.withTypes<AppDispatch>();

// Usage
const count = useAppSelector((s) => s.counter.count);
const dispatch = useAppDispatch();
dispatch(increment());
```

## Abhi Tak Kya Hua

`6.7.1` manual reducer + store factory, `6.7.2` me `createSlice` + `configureStore` se wahi counter 15 lines me + Immer + `RootState`. Store ready hai, par React se abhi **kata hua** hai — component `store.getState()` seedha nahi padhega (subscribe kaise?), type bhi `any` banega. Ab jodna hai.

## Broader Goal

Is doc me 3 steps: **STAGE 1 Provider (kyun) -> STAGE 2 Minimal useSelector/useDispatch (bina types) -> STAGE 3 Typed Hooks (proper)**. Har stage `SOCH -> CONCEPT -> CODE -> TEST` — gradually, ek saath provider + typed hooks dump nahi. End me Zustand `6.4:92` selective subscription se compare, aur common mistakes (Provider bhoolna, `useSelector` me object return).

## STAGE 1 — Provider Kyun Chahiye (store ka “switchboard”)

### SOCH

Store toh `src/rtk/store.ts` me single export hai — `import {store} from "../rtk/store"` karke kahin bhi use kar sakte hain na? Toh `Provider` kyun? Socho — har component me `import {store}` + `store.subscribe` + `useEffect` + `useState` wahi `6.7.1 STAGE 3` wala boilerplate repeat hoga. 10 components = 10 subscribe, 10 useEffect. Koi central tareeka ho jo ek baar store de de, components bas `useSelector` se maang le — wahi `Provider`.

Maine pehli baar yahi socha tha — “Zustand me toh Provider nahi tha, RTK me kyun?” Phir samjha Zustand store khud `create` se singleton hai jo hooks ke andar subscribe handle karta hai, RTK ka store plain object hai jise React tree ko context se dena padta hai — `Provider` wahi context hai.

### CONCEPT

`Provider` `react-redux` ka component hai jo React Context se `store` poori tree me deta hai. Internally `store.subscribe` handle karta hai, `useSelector` usi context se store padhta hai. Ek baar `main.tsx` me wrap karo, har component `useSelector` se koi bhi slice padh sakta hai — bina `import {store}`.

**Nutshell:** `Provider` woh wrapper hai jo Redux `store` ko React Context se poori app me available karata hai, taaki `useSelector/useDispatch` kahi bhi store se baat kar sake bina direct import + manual subscribe ke.

### CODE

Pehle `react-redux` install (agar nahi kiya):

```bash
bun add @reduxjs/toolkit react-redux
# ya npm install @reduxjs/toolkit react-redux
```

Ab `Provider` lagao — `src/main.tsx` (Vite) me:

```tsx
// src/main.tsx
import React from "react";
import ReactDOM from "react-dom/client";
import { Provider } from "react-redux";
import { store } from "./rtk/store";
import App from "./App";

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <Provider store={store}>
      <App />
    </Provider>
  </React.StrictMode>
);
```

| Line | Kyun |
|------|------|
| `import {Provider} from "react-redux"` | Isi stage me import — pehle nahi, ab zaroorat padi tab |
| `import {store} from "./rtk/store"` | `6.7.2` wala `configureStore` wala store |
| `<Provider store={store}>` | Ek prop `store` — context me daal diya, ab `App` ke saare children access kar sakte hain |

### TEST

`bun run dev` — abhi koi `useSelector` nahi, sirf Provider wrap hai. App me koi error nahi hona chahiye. Agar `Provider` nahi lagao aur agle stage me `useSelector` use karoge toh error: `could not find react-redux context value; please ensure the component is wrapped in a <Provider>` — yahi proof hai Provider kyun chahiye.

## STAGE 2 — Minimal useSelector + useDispatch (bina types, sirf flow)

### SOCH

Provider lag gaya, ab component se store ka `count` padhna hai aur `increment` parchi bhejni hai — Zustand me `useStore(s=>s.count)` aur `useStore(s=>s.increment)` tha. RTK me 2 alag hooks — ek padhne ke liye, ek bhejne ke liye. Pehle bina types ke minimal dekho, types agle stage me.

### CONCEPT

*   `useSelector(selectorFn)` — `selectorFn` ko `RootState` deke jo return kare wahi value. Internally `store.subscribe` karke value memoize karta hai — value same rahi toh re-render skip (Zustand selective jaisa).
*   `useDispatch()` — `dispatch` function return, usse `dispatch(increment())` parchi bhejo.

### CODE

Naya component `src/rtk/CounterRTK.tsx` — minimal, sirf RTK:

```tsx
// src/rtk/CounterRTK.tsx — STAGE 2 minimal (bina typed hooks)
import { useSelector, useDispatch } from "react-redux";
import { increment, decrement, reset } from "./counterSlice";

export function CounterRTK() {
  const count = useSelector((state: any) => state.counter.count);
  const dispatch = useDispatch();

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => dispatch(increment())}>+1</button>
      <button onClick={() => dispatch(decrement())}>-1</button>
      <button onClick={() => dispatch(reset())}>Reset</button>
    </div>
  );
}
```

```tsx
// src/App.tsx — temporarily
import { CounterRTK } from "./rtk/CounterRTK";
export default function App() {
  return <main><h1>RTK Counter — Minimal</h1><CounterRTK /></main>;
}
```

Har line:

| Code | Kyun |
|------|------|
| `useSelector((state: any) => state.counter.count)` | `state` ka type `any` — kyunki abhi `RootState` type nahi bataya, TS help nahi. `state.counter.count` path `6.7.2` wale `reducer: {counter}` se aaya |
| `useDispatch()` | `dispatch` function — `increment()` action creator ko wrap karke bhejo |
| `dispatch(increment())` | `increment()` -> `{type:"counter/increment"}`, dispatch -> store -> reducer -> naya state -> `useSelector` wale re-render |

### TEST

Browser me `+1` click -> `Count: 0 -> 1` badhega. Redux DevTools extension khol ke dekho — har click pe `counter/increment` action dikhega, time-travel slider se undo bhi. Zustand me DevTools ke liye `devtools` middleware lagana padta tha `6.4:438`, RTK me `configureStore` me built-in.

**Problem yahan:** `state: any` — `state.counter.` likhoge toh autocomplete nahi, `state.countre` typo bhi error nahi dega. Isi problem ko agle stage me typed hooks solve karenge. Notice kiya? Problem pehle mehsoos karwaya, solution baad me — `Dost-to-Dost Style.md:30` ka cause-effect chain.

## STAGE 3 — Typed Hooks (Proper — ab TS madad karega)

### SOCH

`any` se `state.counter.count` ka path string se yaad rakhna padta hai, galat path pe runtime pe `undefined` milega. `6.7.2` me `RootState` type already banaya tha `ReturnType<typeof store.getState>` — use `useSelector` ko kaise batayein? Har component me `useSelector((state: RootState) => ...)` likhna repeat hoga. Ek baar typed wrapper bana lo, har jagah wahi use karo — wahi `useAppSelector`.

### CONCEPT

RTK ka `withTypes` helper — `useSelector.withTypes<RootState>()` ek naya hook return karta hai jiska `state` param auto `RootState` type ka hota hai. Same `useDispatch.withTypes<AppDispatch>()` se `dispatch` ko pata chalta hai kaunse action types allowed hain (thunk ke liye useful `6.7.4` me).

File alag `hooks.ts` me rakho — convention `src/rtk/hooks.ts`.

### CODE

```ts
// src/rtk/hooks.ts — STAGE 3 typed hooks (isko is stage me banate hain, pehle nahi)
import { useDispatch, useSelector } from "react-redux";
import type { RootState, AppDispatch } from "./store";

export const useAppSelector = useSelector.withTypes<RootState>();
export const useAppDispatch = useDispatch.withTypes<AppDispatch>();
```

Ab `CounterRTK` ko update karo — `any` hatao, typed hooks use karo:

```tsx
// src/rtk/CounterRTK.tsx — updated with typed hooks
import { useAppSelector, useAppDispatch } from "./hooks";
import { increment, decrement, reset, addBy } from "./counterSlice";

export function CounterRTK() {
  const count = useAppSelector((state) => state.counter.count);
  const dispatch = useAppDispatch();

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => dispatch(increment())}>+1</button>
      <button onClick={() => dispatch(decrement())}>-1</button>
      <button onClick={() => dispatch(reset())}>Reset</button>
      <button onClick={() => dispatch(addBy(5))}>+5</button>
    </div>
  );
}
```

| Line | Kyun |
|------|------|
| `useAppSelector((state) => state.counter.count)` | Ab `state` pe hover karo — TS `RootState` dikhayega, `state.counte` typo pe error, `state.counter.` ke baad autocomplete `count` |
| `useAppDispatch()` | `dispatch(addBy("five"))` karoge toh TS error `string not assignable to number` — `PayloadAction<number>` `6.7.2` se enforce |
| `import from "./hooks"` | `hooks.ts` ka path `./hooks` kyunki `CounterRTK.tsx` aur `hooks.ts` same `src/rtk/` folder me hain |

### TEST

*   `state.` type karo — `counter` suggest hoga, `counter.` ke baad `count`.
*   `dispatch(addBy("hi"))` likh ke hover — error aayega, sahi `addBy(5)` pe nahi.
*   Browser me `+5` click -> `count` 5 se badhega, DevTools me `counter/addBy` with payload `5`.

## STAGE 4 — Selective Subscription Ka Farak (Zustand se compare)

`6.4:92` Zustand selective tha — `useCounterStore(s=>s.count)` sirf `count` change pe re-render. RTK `useSelector` bhi same — `useAppSelector(s=>s.counter.count)` sirf `count` change pe. Par ek trap:

```tsx
// ❌ Galat — naya object har render pe, selector hamesha naya reference, har dispatch pe re-render
const { count, theme } = useAppSelector((s) => ({ count: s.counter.count, theme: s.counter.theme }));

// ✅ Sahi — alag selectors, ya `shallowEqual`
const count = useAppSelector((s) => s.counter.count);
const theme = useAppSelector((s) => s.counter.theme);
```

Zustand me `useStore()` bina selector ke poora store subscribe karta tha `6.4:286`, RTK me bhi object return karoge toh shallow compare fail — har bar re-render. Isliye **hamesha primitive/selective** selector.

## Common Mistakes

*   **Provider bhool gaye:** `useAppSelector` ko Provider ke bahar call kiya toh `could not find react-redux context value` — har test file me bhi `<Provider store={store}>` wrap chahiye ( `6.7.5.5` me testing me yahi wrap karenge).
*   **`useSelector` me object return:** `useSelector(s => ({count: s.counter.count}))` har render naya object -> unnecessary re-render. `Batch 5.1 React.memo` wala lesson yahan bhi lagta hai.
*   **Typed hooks nahi banaye, har jagah `state: RootState` repeat:** Kaam toh karega par DRY violation — `hooks.ts` ek baar banao, har component `useAppSelector` reuse kare — `6.1 Custom Hooks` ka hi pattern.
*   **`AppDispatch` ke bina thunk dispatch kiya:** `6.7.4` me `createAsyncThunk` dispatch karoge toh `useDispatch()` ka type `any` ban jayega, TS `dispatch(fetchCategories())` pe error nahi dega — `useAppDispatch` se sahi type.

3.  `main.tsx` se `<Provider>` hata ke `CounterRTK` render karo — error message kya aata hai? Us message ka matlab apne words me likh.

## What It Is NOT

*   **NOT Zustand jaisa provider-free:** RTK me Provider zaroori hai — Zustand `create` singleton hai, RTK store context se jaata hai.
*   **NOT `useSelector` = `useStore` same:** Zustand `useStore(s=>s.count)` me `set` bhi same hook se, RTK me `useSelector` read-only, `useDispatch` alag — separation.
*   **NOT har component ko store import karna:** `import {store}` + `store.getState()` manual `6.7.1` wala pattern — ab `Provider` ke baad kabhi store direct import mat karo component me.

## Summary

*   `Provider` = store ka switchboard — ek baar `main.tsx` me wrap, `useSelector/useDispatch` kahi bhi.
*   `useSelector` (read) + `useDispatch` (parchi bhejna) — minimal flow kaam karta hai par `any` se TS help nahi.
*   `useAppSelector/useAppDispatch` (`withTypes<RootState/AppDispatch>`) = typed wrappers — autocomplete + payload type safety.
*   Selective selector rakho — object return se re-render trap.

2. `useAppSelector` ne `useSelector((state: any) => ...)` ki kaunsi 2 problems solve ki? Ek typo wala example do.

<details>
<summary>Show Answer</summary>

**Sample Answer:** (1) Autocomplete — `state.` pe `counter` suggest, `state.counter.` pe `count`. (2) Type safety — `state.counetr.count` typo pe TS error, `any` me silent `undefined`. </details>

3. `useSelector(s => ({count: s.counter.count}))` object return kyun trap hai? `6.4:286` wala Zustand trap se kaise similar?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `useSelector` shallow `===` compare karta hai purana vs naya return value. `{count: ...}` har render pe naya object (reference alag) — value `0` se `0` hi hui, par reference naya, toh `useSelector` samjhega change hua, component har dispatch pe re-render.
