## STAGE 1 — Why Types? (Type Contract)

### THINK

In the Hardcoded `6.7.5.2`, there was an `Expense` interface for `hardcoded: Expense[]` — but `amount: 20` could also be written as `amount: "20"` string, `category` could typo as `"Foodd"`, and `e.amount` in `ExpenseStaticApp` doing `reduce` could cause the string concatenation bug `“2050”`. With a TS type, the compiler catches these. Let's see the pain without types first, then why types matter.

### CONCEPT

`interface Expense` = **contract** — every expense must have `id/title/amount/category/date`, and `amount` must be `number`. `type FilterStatus` = `"all" | string` — passing wrong type to `setFilter` gives a TS error. Remember the `CounterState` interface from `6.7.2` — same pattern.

### CODE

Without types (wrong):

```ts
// ❌ Wrong — no type, typo goes unnoticed
const hardcoded = [{ id:"1", title:"Chai", amt: 20, category:"Food" }];
// amt vs amount — no compile error, at runtime e.amount is undefined, total is NaN
```

With types (correct) — new file `src/rtk/expenseTypes.ts` (created at this stage, not before — import only when needed):

```ts
// src/rtk/expenseTypes.ts
export interface Expense {
  id: string;
  title: string;
  amount: number; // number because — total reduce needs numeric sum, string would give "20"+"50"="2050"
  category: string;
  date: string; // ISO string — for future "today's expenses" filter in 6.7.5.5
}

export type FilterStatus = "all" | string; // "all" explicit, rest dynamic category
```

| Field | Why (UI reason) |
|---|---|
| `id` | `key={e.id}` + `deleteExpense(id)` unique, generated with `Date.now().toString()` |
| `amount: number` | `total = items.reduce((s,e)=>s+e.amount,0)` numeric sum — avoid string bug |
| `date` | Not shown in list now, but in `6.7.5.5` we extend for "today's" filter — keep it |

### TEST

Write `hardcoded: Expense[] = [{id:"1", title:"Chai", amt:20, ...}]` and run `tsc` — you get error `Property 'amt' does not exist`, and it suggests `amount`. Remember `PayloadAction` from `6.7.2` — type safety starts from the payload itself.

**Nutshell:** A type contract is the TS interface that locks the shape of every object at compile time — typos or missing fields throw errors immediately, runtime bugs caught before they happen.

## STAGE 2 — expensesSlice (Sync Reducers — add/delete/setFilter)

### THINK

In Hardcoded `6.7.5.2`, `filter` came from `useState`, `handleAdd` had `console.log`, and `hardcoded` was a const array. Now, how do we move these three into a separate `expensesSlice` so any component can `dispatch(addExpense(...))`, read `items` via `useAppSelector` — without prop drilling? First, think about `initialState`.

### CONCEPT

In `createSlice`, `initialState` = `{items: Expense[], filter: FilterStatus}`. In `reducers`, 3 case reducers: `addExpense (PayloadAction<Expense>)`, `deleteExpense (PayloadAction<string>)`, `setFilter (PayloadAction<FilterStatus>)`. Each reducer writes as if mutating — Immer auto-creates a new object (`6.7.2`).

### CODE

New file `src/rtk/expensesSlice.ts` — created at this stage:

```ts
// src/rtk/expensesSlice.ts
import { createSlice, type PayloadAction } from "@reduxjs/toolkit";
import type { Expense, FilterStatus } from "./expenseTypes";

interface ExpensesState {
  items: Expense[];
  filter: FilterStatus;
}

const initialState: ExpensesState = {
  items: [
    { id: "1", title: "Chai", amount: 20, category: "Food", date: "2026-08-25" },
    { id: "2", title: "Bus", amount: 50, category: "Travel", date: "2026-08-25" },
    { id: "3", title: "Samosa", amount: 30, category: "Food", date: "2026-08-25" },
  ],
  filter: "all",
};

const expensesSlice = createSlice({
  name: "expenses",
  initialState,
  reducers: {
    addExpense: (state, action: PayloadAction<Expense>) => {
      state.items.push(action.payload);
    },
    deleteExpense: (state, action: PayloadAction<string>) => {
      state.items = state.items.filter((e) => e.id !== action.payload);
    },
    setFilter: (state, action: PayloadAction<FilterStatus>) => {
      state.filter = action.payload;
    },
  },
});

export const { addExpense, deleteExpense, setFilter } = expensesSlice.actions;
export default expensesSlice.reducer;
```

Why each line:

| Code | Why |
|------|------|
| `initialState.items` with 3 hardcoded expenses | The `hardcoded` array from `6.7.5.2` moves here — now single source of truth, fixes the duplication in `6.7.5.2` |
| `filter: "all"` | Replacement of `useState("all")` from `6.7.5.2` — now global, both FilterBar and List read it |
| `addExpense: (state, action: PayloadAction<Expense>)` | `Expense` type gives auto-complete on `action.payload`'s `title/amount/category`, if you pass a string for `amount` TS errors |
| `state.items.push(action.payload)` | Looks like mutation — Immer auto-creates a new array, no need for `return {items:[...state.items, payload]}` from `6.7.1` |
| `state.items = state.items.filter(...)` | `filter` assigns a new array — assigning to Immer draft is allowed |

### TEST

No component yet, test the slice with `console.log` (temporary):

```ts

```

## STAGE 3 — categoriesSlice (Async) + Store (Single Source)

### THINK

In `6.7.5.2`, categories were hardcoded `["Food","Travel","Shopping"]`, but in `6.7.4`, `fetchCategories` thunk fetched `["Beef","Chicken",...]` from the API — real apps need dynamic categories. Plus, where do we connect these two slices (`expenses`, `categories`) so `useAppSelector(s => s.expenses.items)` and `s.categories.items` both come from one `store`? In the store.

### CONCEPT

`categoriesSlice` is the same `6.7.4` version, `extraReducers` handles `fetchCategories.pending/fulfilled/rejected`. In `store.ts`, `configureStore({reducer: {expenses, categories}})` — `combineReducers` auto, `RootState` auto.

### CODE

Copy `src/rtk/categoriesSlice.ts` from `6.7.4`, adapted for this doc — here `items` is `string[]`, with `status/error`:

```ts
// src/rtk/categoriesSlice.ts — STAGE 3 (adapted from 6.7.4, file created at this stage if not created earlier)
import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";

interface CatState {
  items: string[];
  status: "idle" | "loading" | "succeeded" | "failed";
  error: string | null;
}

const initialState: CatState = { items: ["Food", "Travel", "Shopping"], status: "idle", error: null };

export const fetchCategories = createAsyncThunk("categories/fetch", async () => {
  const res = await fetch("https://www.themealdb.com/api/json/v1/1/categories.php");
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  const json = await res.json();
  return json.categories.map((c: any) => c.strCategory).slice(0, 5) as string[];
});

const categoriesSlice = createSlice({
  name: "categories",
  initialState,
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(fetchCategories.pending, (state) => { state.status = "loading"; state.error = null; })
      .addCase(fetchCategories.fulfilled, (state, action) => { state.status = "succeeded"; state.items = action.payload; })
      .addCase(fetchCategories.rejected, (state, action) => { state.status = "failed"; state.error = action.error.message ?? "Something went wrong"; });
  },
});

export default categoriesSlice.reducer;
```

Store — **update** `src/rtk/store.ts` (at this stage, previously had `counter`, now it has `expenses`):

```ts
// src/rtk/store.ts — updated (at this stage)
import { configureStore } from "@reduxjs/toolkit";

    expenses: expensesReducer,

export type AppDispatch = typeof store.dispatch;
```


| Code | Why |
|------|------|
| `reducer: {expenses, categories}` | Object form = `combineReducers` auto — `state.expenses.items` + `state.categories.items` |
| `RootState` | Auto-complete on `state.expenses.filter`, typos get caught |
| `fetchCategories` thunk | From `6.7.4` — `pending` sets `loading`, `fulfilled` sets `["Beef",...]` |

## Common Mistakes

*   **Kept `amount` as `string` in `Expense`:** Input gives a string, but store `number` — if you don't `Number(amount)` before dispatching, `reduce` does string concatenation `“2050”`. Since `PayloadAction<Expense>` has `amount` as number, passing a string gives a TS error.
*   **`initialState` with `filter: "All"` capitalized:** In `6.7.5.2`, `filter` was lowercase `"all"`, here if you write `"All"`, then `filtered = items.filter(e => filter==="all" || ...)` never matches `"All"`, and `"All"` filter returns empty. Case-sensitive string literal — TS `FilterStatus` catches `"all"` literal.
*   **Wrote `reducer: expensesReducer` (singular) in `store.ts`:** `configureStore({reducer: expensesReducer})` makes `RootState` shape `Expense[]`, so `state.items` not `state.expenses.items` — `useAppSelector(s => s.expenses.items)` errors with `Property 'expenses' does not exist`.
*   **Put `createAsyncThunk` in `reducers`:** `reducers: {fetchCategories: ...}` — `fetchCategories` is a thunk, `reducers` is for sync, use `extraReducers` with `builder.addCase` — wrong placement means no `pending` property.

## What It Is NOT

*   **NOT a component:** No `ExpenseForm.tsx` in this doc — `6.7.5.4` creates it, only data here.
*   **NOT persist:** Refreshes and `expenses` resets — `6.7.5.5` adds optional `redux-persist` or `localStorage` sync, intentionally not yet — comparison with `Zustand persist` from `6.4:478`.
*   **NOT plain Redux:** `createSlice` + `createAsyncThunk` is RTK — in plain Redux, there's a `switch` + `CounterAction` union in every slice like `6.7.1`.

## Summary

*   Types = contract — `Expense` 5 fields justified by UI, `amount` is number.
*   `expensesSlice` = sync `add/delete/setFilter` — Immer `push`/`filter`.
*   `categoriesSlice` = async `fetchCategories` with pending/fulfilled/rejected.
*   `store` = `expenses + categories` combined, `RootState` auto-generated.

## In Your Own Words

1. In `Expense`, why is `amount` a `number`, not a `string`? How is this related to the `reduce` bug?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The UI shows `Total: ₹580`, a numeric sum from `items.reduce((s,e)=>s+e.amount,0)`. If `amount` were string `"20"`, then `0 + "20" = "020"`, then `+ "50" = "02050"` — string concatenation, so total becomes `“2050”` incorrectly. Having `amount: number` as a contract means `addExpense({amount: "20"})` gives a TS error, and we must `Number(amount)` to convert before dispatching. The `completedCount` from `6.5:320` was also numeric.

</details>

2. Why keep 3 hardcoded expenses in `expensesSlice.initialState.items`, not `[]` empty?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The `hardcoded` array from `6.7.5.2` moves here — single source of truth, fixing the duplication in `6.7.5.2`. If kept empty `[]`, the `Chai/Bus/Samosa` rows from the Hardcoded UI disappear, the demo looks empty, and we can't test `filter`/`total` flow. In `6.7.5.4`, `addExpense` dispatches a new item, but for initial demo, keeping 3 items shows the `map`/`filter` flow immediately. When the DB connects, we'll set initial to `[]`.

</details>

3. In `store.ts`, with `reducer: {expenses, categories}` object form, what `RootState` shape is created? Where does the path `s.expenses.items` come from?

<details>
<summary>Show Answer</summary>

**Sample Answer:** In `configureStore({reducer: {expenses: expensesReducer, categories: categoriesReducer}})`, the keys `expenses`/`categories` themselves become the keys of `RootState` — `RootState = {expenses: {items, filter}, categories: {items, status, error}}`. The path in `useAppSelector(s => s.expenses.items)` comes from those same keys — `s.expenses` = the state of `expensesSlice`, `.items` is the array inside. If it were `reducer: expensesReducer` singular, then `RootState = ExpensesState`, and it would be `s.items` instead.

</details>
