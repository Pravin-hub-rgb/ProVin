Ab tak `increment`/`decrement` sync the — button click -> seedha `state.count++`. Real app me `6.5:310` `useFetch` se categories API se aati thi — `isLoading`, `error`, `data` teen states. # Doc 6.7.4 — Async — createAsyncThunk (Manual Try/Catch Ka Better)

## Cheat Sheet (Quick Recall)

```ts

export const fetchCategories = createAsyncThunk("categories/fetch", async () => {
  const res = await fetch("https://www.themealdb.com/api/json/v1/1/categories.php");

// slice me

         .addCase(fetchCategories.fulfilled, (s, a)=>{s.status="succeeded"; s.items=a.payload})
```

## Abhi Tak Kya Hua

`6.7.2` me `createSlice` + `configureStore`, `6.7.3` me `Provider` + `useAppSelector/useAppDispatch`. Sync counter chal raha hai. Ab async — API se data lane ka enterprise pattern.

## Broader Goal

Is doc me **async ka problem-first** samjhenge: pehle socho reducer async kyun nahi ho sakta, phir manual me 3 actions ka boilerplate mehsoos karo, phir `createAsyncThunk` se kaise 1 function me 3 actions auto. Har stage `SOCH -> CONCEPT -> CODE -> TEST`. Yeh async hi `6.7.5` project me `categories` slice ka base hai.

---

## STAGE 1 — Reducer Async Kyun Nahi? (Concept Pehle)

### SOCH

Tum sochoge — `reducers: { fetchCategories: async (state) => { const res = await fetch(...); state.items = await res.json() } }` — seedha reducer me fetch kar lo. Lekin `6.7.1` me bola tha reducer **pure** hota hai — same `state + action` pe hamesha same `newState`, koi `fetch`, `Date.now()`, `Math.random()` nahi. Async se `await` ke beech state ka time-travel kaise karoge? DevTools me “pending -> fulfilled” ka history kaise dikhoge? Isliye reducer sync hi rehta hai, async **bahar** thunk me hota hai, reducer sirf uske result pe state badalta hai.

### CONCEPT

Thunk ek **function jo function return karta hai** — `dispatch` ko `action object` ki jagah `async function` de sakte ho, middleware (RTK me built-in `redux-thunk`) us function ko `dispatch` aur `getState` deke chalata hai. Manual me thunk ke liye 3 actions chahiye: `fetch/pending` (loading true), `fetch/fulfilled` (data save), `fetch/rejected` (error). Har async ke liye 3 action types + 3 cases + try/catch — wahi boilerplate jo RTK 1 `createAsyncThunk` me deta hai.

**Nutshell:** Thunk woh middleware-pattern hai jo `dispatch` ko action object ki jagah async function bhejne deta hai, taaki reducer pure rahe aur async ka result 3 actions (pending/fulfilled/rejected) se reducer tak aaye.

## STAGE 2 — Manual Async Ka Dard (bina createAsyncThunk, samajhne ke liye)

### SOCH

Agar `createAsyncThunk` seedha de diya toh lagega “3 actions auto kyun?” — manual me 3 actions ka dard dekho tabhi auto ka value samjhega.

### CODE

Manual thunk jaisa — `counterSlice.ts` me nahi, alag `categoriesManual.ts` (RTK bina) — sirf samajhne ke liye, production me nahi likhna:

```ts
// src/manual-redux/categoriesManual.ts — ❌ Manual, tedious
interface CatState { items: string[]; status: "idle"|"loading"|"succeeded"|"failed"; error: string|null }

type CatAction =
  | {type:"categories/fetch/pending"}
  | {type:"categories/fetch/fulfilled", payload: string[]}
  | {type:"categories/fetch/rejected", payload: string};

const initial: CatState = { items: [], status:"idle", error: null };

export function catReducer(state=initial, action: CatAction): CatState {
  switch(action.type){
    case "categories/fetch/pending": return {...state, status:"loading", error:null}
    case "categories/fetch/fulfilled": return {...state, status:"succeeded", items: action.payload}
    case "categories/fetch/rejected": return {...state, status:"failed", error: action.payload}
    default: return state;
  }
}

// Thunk function (dispatch ko function dete hain)
export const fetchCategoriesManual = () => async (dispatch: any) => {
  dispatch({type:"categories/fetch/pending"});
  try {
    const res = await fetch("https://www.themealdb.com/api/json/v1/1/categories.php");
    const json = await res.json();
    const items = json.categories.map((c:any)=>c.strCategory).slice(0,5);
    dispatch({type:"categories/fetch/fulfilled", payload: items});
  } catch(e:any){
    dispatch({type:"categories/fetch/rejected", payload: e.message});
  }
};
```

| Line | Kyun |
|------|------|
| `CatAction` 3 types | Har stage ka action alag — pending/fulfilled/rejected |
| `switch` 3 cases | Har pending pe loading, fulfilled pe data, rejected pe error |
| `fetchCategoriesManual = () => async (dispatch)` | Thunk — `dispatch` ko function dete hain, middleware chalata hai |

Boilerplate: 1 async ke liye 1 type union (3), 1 reducer (3 cases), 1 thunk (try/catch + 3 dispatch). 5 async hote toh 50 lines.

```ts

// DevTools me 3 actions dikhenge: pending -> fulfilled
```

Kaam toh karta hai, par har async pe same 3-step repeat — wahi DRY violation `6.2` wala.

## STAGE 3 — createAsyncThunk Ka Better (1 function = 3 actions auto)

### SOCH

Manual ka 3-step pattern har async me same hai — `pending -> try fetch -> fulfilled/rejected`. Koi factory ho jo “URL aur return value do, baki mai 3 actions + dispatch + error handling sambhalta hun” — wahi `createAsyncThunk`.

### CONCEPT

`createAsyncThunk("categories/fetch", async () => { return data })` — pehla arg `typePrefix` (`categories/fetch`), doosra async `payloadCreator`. Yeh 1 thunk function return karta hai jiske 3 action creators auto hote hain: `fetchCategories.pending`, `fetchCategories.fulfilled`, `fetchCategories.rejected` — `slice` ke `extraReducers` me `builder.addCase` se handle karo.

### CODE

Naya slice `src/rtk/categoriesSlice.ts` — is stage me banate hain (pehle nahi, ab zaroorat padi):

```ts
// src/rtk/categoriesSlice.ts — STAGE 3 minimal
import { createSlice, createAsyncThunk } from "@reduxjs/toolkit";

interface CatState {
  items: string[];
  status: "idle" | "loading" | "succeeded" | "failed";
  error: string | null;
}

const initialState: CatState = { items: [], status: "idle", error: null };

export const fetchCategories = createAsyncThunk(
  "categories/fetch",
  async () => {
    const res = await fetch("https://www.themealdb.com/api/json/v1/1/categories.php");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const json = await res.json();
    return json.categories.map((c: any) => c.strCategory).slice(0, 5) as string[];
  }
);

const categoriesSlice = createSlice({
  name: "categories",
  initialState,
  reducers: {}, // is slice me sync reducer nahi, sirf async
  extraReducers: (builder) => {
    builder
      .addCase(fetchCategories.pending, (state) => {
        state.status = "loading";
        state.error = null;
      })
      .addCase(fetchCategories.fulfilled, (state, action) => {
        state.status = "succeeded";
        state.items = action.payload;
      })
      .addCase(fetchCategories.rejected, (state, action) => {
        state.status = "failed";
        state.error = action.error.message ?? "Kuch gadbad hui";
      });
  },
});

export default categoriesSlice.reducer;
```

Har line:

| Code | Kyun |
|------|------|
| `createAsyncThunk("categories/fetch", async () => ...)` | `typePrefix` se 3 types auto: `categories/fetch/pending` etc. |
| `async () => { fetch... return items }` | Jo `return` karoge wahi `fulfilled` ka `payload` — `action.payload` me ayega |
| `extraReducers: (builder) =>` | `reducers` sync ke liye, `extraReducers` external thunk ke 3 cases ke liye |
| `builder.addCase(fetchCategories.pending, ...)` | Pending pe `status="loading"` — Immer se mutate jaisa |
| `state.error = action.error.message` | Rejected pe `action.error` me error, `action.payload` nahi — `createAsyncThunk` `throw` ko `rejected` me daalta hai |

**Store me add karo:**

## Common Mistakes

*   **`extraReducers` ki jagah `reducers` me `fetchCategories` likh diya:** `reducers` sirf sync `state =>` wale, `createAsyncThunk` ke 3 cases `extraReducers` me `builder.addCase` se — `reducers` me daaloge toh TS error `Property 'pending' does not exist`.
*   **`dispatch(fetchCategories)` bina `()` ke:** `createAsyncThunk` ka return **thunk function** hai, `dispatch` ko `fetchCategories()` call ka result dena hai — `dispatch(fetchCategories)` se function object dispatch hoga, fetch nahi chalega.
*   **Reducer me async/await:** `reducers: { fetch: async (state)=>{await fetch...}}` — reducer pure nahi, DevTools time-travel tootega, RTK error dega `A non-serializable value was detected`.
*   **`action.payload` vs `action.error` confuse:** `fulfilled` me `payload` me data, `rejected` me `error.message` me error — `rejected` me `payload` nahi hota unless `rejectWithValue` use kiya.

## Khud Try Karo

1.  `categoriesSlice.ts` me `fetchCategories` ka URL galat `.../categories.php?wrong=1` karke `dispatch` karo — `status` `failed` hota? `error` me kya aata? `action.error.message` vs `action.payload` me kya farak?
2.  `builder.addCase(fetchCategories.pending, ...)` me `state.status = "loading"` ki jagah `return {items: [], status:"loading", error:null}` try karo — dono chalte hain? Immer ka mutate vs return ka fark kya?
3.  Manual `fetchCategoriesManual` aur RTK `fetchCategories` dono ko DevTools me compare karo — kaunse 3 actions dono me same dikhte hain?

## What It Is NOT

*   **NOT `useFetch` replacement:** `useFetch` (6.2) simple hook hai, RTK async global store me cache karta hai — `categories` 3 components me chahiye toh store me rakho, ek component me chahiye toh `useFetch` kaafi.
*   **NOT `RTK Query`:** RTK Query alag data-fetching layer hai (cache, dedup) — `createAsyncThunk` sirf thunk + 3 actions, caching khud karna padta hai. Interview me `TanStack Query` vs `RTK Query` compare puchte hain — yahan sirf `createAsyncThunk` seekha.
*   **NOT reducer me fetch:** Hamesha thunk me `fetch`, reducer me sirf `state.status/items/error` set.

## Summary

*   Reducer async nahi ho sakta — pure rakhna hai, async thunk me.
*   Manual async = 3 action types + switch + thunk (~25 lines).
*   `createAsyncThunk("prefix", async()=>return)` = 1 function, 3 actions auto, `extraReducers` me `builder.addCase(pending/fulfilled/rejected)`.
*   `store.dispatch(fetchCategories())` -> `pending` -> `fulfilled/rejected`, DevTools me traceable.

## In Your Own Words

1. Reducer me `await fetch` kyun nahi kar sakte? Pure function ka time-travel se kya connection hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Reducer `(state, action) => newState` pure hota hai — same input pe hamesha same output, koi `fetch` `Date.now()` nahi. Agar reducer me `await fetch` hota, toh same `fetchCategories` action pe kabhi `pending`, kabhi `fulfilled` — same input pe alag output, pure nahi. DevTools time-travel har action ko replay karke state banata hai — async reducer replay pe dobara fetch karega, network fail ho sakta hai, history corrupt. Isliye async thunk me (bahar), reducer sirf uske 3 results (pending/fulfilled/rejected) pe sync state update.

</details>

2. Manual 3 actions vs `createAsyncThunk` ke 3 actions — naam same, banane ka tareeka kya alag? Ek example `categories/fetch/pending` se samjhao.

<details>
<summary>Show Answer</summary>

**Sample Answer:** Manual me `type CatAction = {type:"categories/fetch/pending"} | {type:"categories/fetch/fulfilled", payload:string[]} | ...` union khud likhna, `catReducer` me `switch` me 3 case, `fetchCategoriesManual = () => async (dispatch)=>{dispatch({type:"categories/fetch/pending"}); try{...dispatch({type:"categories/fetch/fulfilled", payload})} catch...}` thunk khud. RTK me `createAsyncThunk("categories/fetch", async()=>return items)` ek call — `typePrefix` `"categories/fetch"` se 3 types auto `categories/fetch/pending` etc., `fetchCategories.pending/fulfilled/rejected` action creators auto, thunk function auto, `extraReducers` me sirf `builder.addCase` se handle. 25 lines 8 lines.

</details>

3. `dispatch(fetchCategories)` vs `dispatch(fetchCategories())` — bracket ka farak kya, galat kiya toh kya hoga?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `createAsyncThunk` se `fetchCategories` ek **thunk creator** hai — `fetchCategories()` call karne pe `async (dispatch)=>{...}` thunk function banta hai jo `redux-thunk` middleware chalata hai. `dispatch(fetchCategories)` me function creator khud dispatch hoga — middleware samjhega hi nahi, fetch nahi chalega, DevTools me `categories/fetch/pending` bhi nahi ayega. `dispatch(fetchCategories())` sahi — thunk function dispatch hota hai, middleware usse `dispatch(pending)` -> `fetch` -> `dispatch(fulfilled/rejected)` auto.

</details>
