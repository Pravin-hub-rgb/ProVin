## STAGE 2 — STATE + REDUCER (parchi-system ka dil)

### SOCH

Static me count hardcoded `0` hai. Ab count yaad rakhna hai, aur badalna bhi hai — par Zustand jaisa seedha `set` nahi, **parchi-system** se. Matlab ek jagah `state` rakho, aur har change ke liye ek `action` object bhejo, `reducer` function naya state banaye. Kyun yeh extra step? Taaki har change traceable ho — kaunsi parchi se kya badla. Manual me yeh kaise dikhega — chalo concept dekhte hain.

### CONCEPT

3 shabd yaad rakho:

*   **Store:** Ek object jo `state` hold karta hai — `{count: 0}`. Single source of truth, poori app ka hisaab yahin.
*   **Action:** Plain object `{type: "counter/increment"}` — parchi. `type` string hi sab kuch batata hai kya hua. Data bhejna ho toh `payload` add karo — `{type: "counter/add", payload: 5}`.
*   **Reducer:** Pure function `(state, action) => newState`. Sirf `state` aur `action` dekh ke naya state return karo — kabhi seedha `state.count++` mutate mat karo (manual me nahi chalta, RTK me Immer handle karta hai — wahi farak agle doc me dekhenge).

### CODE

Ab `CounterStatic` ko dynamic banate hain — par abhi bhi React ke bina, sirf TS me samajhne ke liye:

```ts
// src/manual-redux/counterManual.ts

// 1. State ka shape
interface CounterState {
  count: number;
}

// 2. Actions — parchi ke types
type CounterAction =
  | { type: "counter/increment" }
  | { type: "counter/decrement" }
  | { type: "counter/reset" };

// 3. Initial state
const initialState: CounterState = { count: 0 };

// 4. Reducer — register wala
export function counterReducer(
  state: CounterState = initialState,
  action: CounterAction
): CounterState {
  switch (action.type) {
    case "counter/increment":
      return { count: state.count + 1 };
    case "counter/decrement":
      return { count: state.count - 1 };
    case "counter/reset":
      return { count: 0 };
    default:
      return state;
  }
}
```

Dekho har line kyun hai:

| Line | Kyun |
|------|------|
| `interface CounterState` | TS ko pata chale state me kya hai — compile pe typo pakdega |
| `type CounterAction` | Union type — `type` sirf in 3 strings me se ek ho sakta hai, galat string `counter/incremnet` likhoge toh error |
| `switch(action.type)` | Har parchi ka alag case — kaunsi parchi pe kya karna |
| `return { count: state.count + 1 }` | **Naya object** return — `state.count++` nahi, kyunki manual reducer me mutate nahi kar sakte (warna React change detect nahi karega, reference same rahega) |
| `default: return state` | Unknown parchi aaye toh state waisa hi |

## STAGE 3 — STORE + DISPATCH + VIEW (sab jodna)

### SOCH

Reducer toh bas function hai — usse state kahaan rakhenge? Aur component ko kaise pata chalega state badla? Iske liye **store** chahiye — jo `state` hold kare, `dispatch` se parchi le, reducer call kare, aur subscribers ko bataye.

### CONCEPT

Manual store ka minimal shape:

*   `getState()` — current state do
*   `dispatch(action)` — parchi bhejo, reducer call karo, naya state set karo
*   `subscribe(listener)` — state badle toh listener ko call karo (React me `useSelector` yahi karta hai)

React me is store ko `Provider` se poori tree me dete hain, par is doc me abhi React ke bina minimal store banate hain taaki flow clear ho.

### CODE

```ts
// src/manual-redux/storeManual.ts
import { counterReducer } from "./counterManual";
import type { CounterState } from "./counterManual";

type CounterAction =
  | { type: "counter/increment" }
  | { type: "counter/decrement" }
  | { type: "counter/reset" };

function createStore(reducer: typeof counterReducer) {
  let state: CounterState = reducer(undefined as any, { type: "@@INIT" } as any);
  const listeners: (() => void)[] = [];

  return {
    getState: () => state,
    dispatch: (action: CounterAction) => {
      state = reducer(state, action);
      listeners.forEach((l) => l());
    },
    subscribe: (listener: () => void) => {
      listeners.push(listener);
      return () => {
        const idx = listeners.indexOf(listener);
        if (idx >= 0) listeners.splice(idx, 1);
      };
    },
  };
}

export const store = createStore(counterReducer);
```

Ab React component jisme store use ho — **stage-by-stage, dump nahi**:

```tsx
// src/manual-redux/CounterManual.tsx — STAGE 3 final
import { useEffect, useState } from "react";
import { store } from "./storeManual";

export function CounterManual() {
  const [count, setCount] = useState(store.getState().count);

  useEffect(() => {
    const unsub = store.subscribe(() => {
      setCount(store.getState().count);
    });
    return unsub;
  }, []);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => store.dispatch({ type: "counter/increment" })}>+1</button>
      <button onClick={() => store.dispatch({ type: "counter/decrement" })}>-1</button>
      <button onClick={() => store.dispatch({ type: "counter/reset" })}>Reset</button>
    </div>
  );
}
```

Har line ka “kyun”:

| Code | Kyun |
|------|------|
| `useState(store.getState().count)` | Initial UI state store se lo |
| `store.subscribe(() => setCount(...))` | Store badle toh component re-render — nahi toh UI stale rahega |
| `store.dispatch({type: ...})` | Parchi bhejo, reducer naya state banayega, subscriber trigger hoga |

### TEST

`App.tsx` me `CounterManual` render karo, `+1` click karo — count badhega. `console.log` me dekho — har click pe `counter/increment` parchi dispatch ho rahi hai.

## Kya Dard Mehsoos Hua? (Yahi Agle Doc Ka Reason)

Abhi tak sirf counter ke liye:

*   1 interface + 1 union type + 1 reducer switch + 1 store factory = **~40 lines**
*   Har naye feature (jaise `addAmount` `payload` ke saath) ke liye type me naya union, reducer me naya case, action creator alag function.
*   5 slices hote toh 5 reducer + `combineReducers` + har file me same boilerplate.

Yahi dard solve karne RTK bana — `createSlice` ek jagah `name + initialState + reducers` likho, action creators + action types auto generate. Agle doc `6.7.2` me isi counter ko **15 lines** me kar denge — tabhi lagega “haan RTK kyun chahiye tha”.

> **Nutshell:** Reducer woh pure function hai jo `(state, action) => nayaState` return karta hai — kabhi mutate nahi, hamesha naya object. Store woh container hai jo state hold karta hai, dispatch se action leta hai, reducer call karke state update karta hai aur subscribers ko batata hai.

---

## Common Mistakes

*   **Mutate kar diya reducer me:** `state.count++` return kiya toh UI nahi update hoga — manual me Immer nahi hai. Hamesha `{count: state.count + 1}` naya object.
*   **Action type me typo:** `"counter/increment"` ko `"counter/incremnet"` likh diya — `switch` default me chala jayega, state nahi badlega, error bhi nahi aayega. Isliye `type CounterAction` union zaroori hai — TS typo pakdega.
*   **Subscribe cleanup bhool gaye:** `useEffect` me `return unsub` nahi kiya toh component unmount pe listener leak — memory leak `Dost-to-Dost Style.md:34` wala chain: unmount -> listener array me reference alive -> GC collect nahi kar paya -> memory leak.

## What It Is NOT

*   **NOT RTK:** Yeh manual pattern sirf samajhne ke liye hai — production me kabhi aise `createStore` nahi likhte, `configureStore` use karte hain.
*   **NOT Zustand jaisa:** Zustand me `set` direct hai, yahan har change parchi se. Manual pattern verbose isliye hai kyunki har step explicit hai.

## Summary

*   Redux core = `store` (state holder) + `action` (parchi `{type,payload}`) + `reducer` (pure function).
*   Manual me har slice ke liye type + switch + store factory likhna padta hai — boilerplate ~40 lines sirf counter ke liye.
*   Common pitfalls: mutate, typo, subscribe leak.

## In Your Own Words

1. Manual reducer me `return {count: state.count+1}` kyun, `state.count++; return state` kyun nahi? Dono me object ka reference kahan alag hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `state.count++` same `state` object ko mutate karta hai — reference wahi rehta hai. React/redux `===` se check karta hai purana vs naya state — reference same toh samjhega “kuch badla hi nahi”, re-render nahi hoga. `return {count: state.count+1}` naya object banata hai — reference alag, change detect ho jaata hai. Manual me Immer nahi, isliye hamesha naya object. RTK me `state.count++` chal jaata hai kyunki Immer andar proxy se naya object bana deta hai.

</details>

2. Action type ko `string` union (`type CounterAction`) se kyun define kiya, seedha `string` kyun nahi? Typo ka kya scene hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Seedha `string` hota toh `"counter/incremnet"` typo bhi accept ho jaata — `switch` default me gir ke silent fail. Union `type CounterAction = {type:"counter/increment"} | ...` me TS compile pe error dega — `Type '"counter/incremnet"' is not assignable`. Isse parchi ka naam galat jaane se pehle hi pakda jaata hai. `createSlice` me yeh union auto generate hota hai, manually nahi likhna padta.

</details>

3. Store me `subscribe` ka kya kaam hai? `CounterManual.tsx` me `useEffect` me subscribe kyun kiya, seedha `store.getState()` render me call kar lete toh kya hota?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `store.getState()` sirf current snapshot deta hai — future updates ka pata nahi. `subscribe` listener register karta hai jo har `dispatch` ke baad chalta hai. `useEffect` me `subscribe(() => setCount(store.getState().count))` ka matlab — store badla toh `setCount` se React ko re-render bolo. Agar subscribe nahi karte, `+1` dispatch se store ka `count` toh badh jaata, par component ko pata hi nahi chalega, UI `0` pe atka rahega. `useSelector` (agle doc) yahi subscribe internally karta hai.

</details>
