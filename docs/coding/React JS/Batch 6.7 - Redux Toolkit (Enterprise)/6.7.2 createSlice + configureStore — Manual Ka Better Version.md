# Doc 6.7.2 — createSlice + configureStore — Manual Ka Better Version

## Cheat Sheet (Quick Recall)

```ts
// is doc me jo seekhna hai — ek baar me samjho
import { createSlice, configureStore } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",
  initialState: { count: 0 },
  reducers: { increment: (state) => { state.count += 1 } }, // Immer = mutate jaisa likho, naya state auto
});
export const { increment } = counterSlice.actions; // action creator auto

export const store = configureStore({ reducer: { counter: counterSlice.reducer } });
export type RootState = ReturnType<typeof store.getState>;
```

## Abhi Tak Kya Hua

`6.7.1` me manual Redux ka dard mehsoos kiya — reducer `switch` + `CounterAction` union + `createStore` factory. Kam kar raha tha par verbose tha, har slice me same pattern repeat, `state.count++` mutate karoge toh bug. Ab wahi counter ko RTK ke 2 APIs — `createSlice` aur `configureStore` — se 15 lines me karenge.

## Broader Goal

Is doc me **RTK ke 2 core APIs** seekhenge: `createSlice` (action + reducer ek saath) aur `configureStore` (store + DevTools + Immer built-in). Har step `SOCH -> CONCEPT -> CODE -> TEST` — koi dump nahi. End me manual vs RTK compare, aur `Immer` kyun `state.count++` ko safe banata hai. Yeh APIs hi agle `6.7.5` project ke `expenseSlice` ka base hain.

## STAGE 1 — createSlice Se Pehle: Manual Ka Kitna Bacha Tha

### SOCH

Manual me `counterReducer` me 3 cheeze alag thi — `initialState`, `CounterAction` type, aur `switch` ke cases. Tino ka naam bhi `counter/` prefix se manual jodna padta tha. Agar 1 typo toh silent fail. Koi tool aisa ho jo “name + initialState + reducers object do, baki mai sambhalta hun” — wahi `createSlice` hai. Pehle concept clear karte hain.

### CONCEPT

`createSlice` ek **factory function** hai. Tum bas object do:

*   `name: "counter"` — har action type ka prefix auto banega (`counter/increment`)
*   `initialState: {count: 0}` — starting state
*   `reducers: { increment: (state) => {state.count++} }` — har key ek **case reducer** hai, key hi action ka naam ban jaati hai

Return me 3 cheeze milti hain:

*   `slice.reducer` — poora reducer function (switch auto bana)
*   `slice.actions` — har reducer ke liye **action creator** function auto (`increment()` -> `{type:"counter/increment"}`)
*   `slice.name` — wahi name

**Nutshell:** `createSlice` woh factory hai jo `name + initialState + reducers` object leke `reducer + action creators + action types` ek saath generate kar deta hai — manual ke 3 alag pieces ki jagah ek object.

## STAGE 2 — Minimal createSlice (sirf increment, kuch aur nahi)

### SOCH

Seedha 3 reducers ek saath mat dikhate — sirf `increment` se start karte hain, minimal, taaki flow clear ho.

### CODE

Naya file `src/rtk/counterSlice.ts` banao — `manual-redux/` ke bagal me `rtk/` folder:

```ts
// src/rtk/counterSlice.ts — STAGE 2 minimal
import { createSlice } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",
  initialState: { count: 0 },
  reducers: {
    increment: (state) => {
      state.count += 1;
    },
  },
});

// Action creator export
export const { increment } = counterSlice.actions;

// Reducer export (store me use hoga)
export default counterSlice.reducer;
```

Har line ka “kyun”:

| Line | Kyun |
|------|------|
| `createSlice({` | Factory call — manual ke `interface + type + switch` ki jagah ek call |
| `name: "counter"` | Auto prefix — `increment` action ka type `counter/increment` banega |
| `initialState: {count: 0}` | Wahi `initialState` jo manual me `const initialState` tha |
| `increment: (state) => { state.count += 1 }` | **Mutate jaisa** likh rahe hain — `state.count++`! Manual me yeh bug tha, yahan **safe** hai — kyun? **Immer** |
| `export const { increment } = counterSlice.actions` | Action creator auto — `increment()` call karne pe `{type:"counter/increment"}` object banta hai |
| `export default counterSlice.reducer` | Store ko yeh reducer denge |

**Immer kya hai (1-line):** Immer ek library hai jo `state` ko **draft proxy** banata hai. Tum `state.count++` jaisa mutate likhte ho, Immer andar copy bana ke naya object return karta hai. Isliye manual me `return {count: state.count+1}` karna padta tha, RTK me `state.count++` chalta hai. `configureStore` me Immer built-in hai — alag install nahi.

### CODE — Aur 2 reducers add karo (build up, dump nahi)

Ab isi file ko **update** karo — `decrement` aur `reset` add karo, ek-ek karke:

```ts
// src/rtk/counterSlice.ts — updated
import { createSlice, type PayloadAction } from "@reduxjs/toolkit";

interface CounterState {
  count: number;
}

const initialState: CounterState = { count: 0 };

const counterSlice = createSlice({
  name: "counter",
  initialState,
  reducers: {
    increment: (state) => {
      state.count += 1;
    },
    decrement: (state) => {
      state.count -= 1;
    },
    reset: (state) => {
      state.count = 0;
    },
    // Payload wala example — stage 4 me kaam ayega
    addBy: (state, action: PayloadAction<number>) => {
      state.count += action.payload;
    },
  },
});

export const { increment, decrement, reset, addBy } = counterSlice.actions;
export default counterSlice.reducer;
```

*   `PayloadAction<number>` — TS type jo batata hai `action.payload` number hai. `addBy(5)` -> `{type:"counter/addBy", payload: 5}`. Manual me `type CounterAction` union me `payload` alag define karna padta tha, yahan generic se.
*   `addBy` ka use baad me `6.7.4` me bhi hoga — abhi bas syntax dekho.

### TEST

Abhi UI nahi, `console.log` se action creator check:

```ts
// temporary test — src/rtk/testSlice.ts
import { increment, addBy } from "./counterSlice";
console.log(increment()); // {type: "counter/increment", payload: undefined}
console.log(addBy(5));    // {type: "counter/addBy", payload: 5}
```

`increment()` function call karte hi action object ban gaya — string type manually likhna nahi pada, typo ka chance khatam.

## STAGE 3 — configureStore (manual createStore ka better version)

### SOCH

Manual me `createStore(counterReducer)` alag factory thi, `listeners` array khud manage kiya. RTK me `configureStore` ek line me store bana deta hai + DevTools + Immer + `combineReducers` auto. Concept dekho.

### CONCEPT

`configureStore` ko `reducer` object do — key = slice name, value = slice reducer. Yeh object hi `RootState` ka shape ban jaata hai: `{counter: {count: number}}`. DevTools, middleware, `getState/dispatch/subscribe` built-in.

### CODE

```ts
// src/rtk/store.ts
import { configureStore } from "@reduxjs/toolkit";
import counterReducer from "./counterSlice";

export const store = configureStore({
  reducer: {
    counter: counterReducer,
  },
});

// Types — agle doc 6.7.3 me Typed Hooks ke liye chahiye
export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
```

Har line:

| Code | Kyun |
|------|------|
| `configureStore({` | Manual `createStore` ki jagah — DevTools + middleware auto |
| `reducer: { counter: counterReducer }` | Object form = `combineReducers` auto — `state.counter.count` shape |
| `RootState = ReturnType<typeof store.getState>` | TS utility — store ke shape se type nikalta hai, manual interface nahi |
| `AppDispatch = typeof store.dispatch` | dispatch ka type — `6.7.3` me `useAppDispatch` banane ke liye |

### TEST

```ts
import { store } from "./store";
import { increment } from "./counterSlice";

console.log(store.getState()); // {counter: {count:0}}
store.dispatch(increment());
console.log(store.getState()); // {counter: {count:1}}
```

Manual wale `storeManual.ts` ka 25 lines ka factory ab 7 lines ka `configureStore` ho gaya. Aur `store.getState().counter.count` — nested shape dhyan do, agle doc me `useSelector((s) => s.counter.count)` yahi path use hoga.

## STAGE 4 — Manual vs RTK Compare (table LAST — AGENTS.md rule)

| Feature | Manual (`6.7.1`) | RTK (`createSlice`) |
|---------|----------------|---------------------|
| **Action type** | `type CounterAction` union manual, typo silent fail | `name + reducers` key se auto `counter/increment`, TS error agar galat |
| **Reducer** | `switch` + `return {count: ...}` naya object | `state.count++` mutate jaisa — Immer naya object auto |
| **Action creator** | Alag function `const increment = () => ({type: ...})` | `slice.actions.increment` auto |
| **Store** | `createStore` factory ~25 lines, listeners manual | `configureStore({reducer:{counter}})` 1 call, DevTools auto |
| **Boilerplate counter ke liye** | ~40 lines | ~15 lines |
| **5 slices pe** | ~200 lines | ~75 lines |

**Trade-off line:** Alternatives `plain Redux` vs `RTK` me RTK isliye chuna kyunki `docs/coding/WEB-DEV/00-MIND-MAP/webdev-tools-docs/01-frontend-state.md:186` kehta hai `Naya project? Redux Toolkit use karo, plain Redux nahi` — official recommendation, less boilerplate, same predictability.

## Common Mistakes

*   **`state = {count: 0}` assign kar diya reducer me:** `createSlice` ke andar `state = ...` assign karoge toh Immer draft replace nahi hota — bug. Ya `state.count = 0` mutate karo, ya `return {count: 0}` return karo — dono me se ek, mix nahi. `reset: (state) => {state.count = 0}` sahi, `reset: (state) => { state = {count:0} }` galat.
*   **`PayloadAction` type nahi diya:** `addBy: (state, action) => {state.count += action.payload}` me `action` ka type `any` ban jayega — `action.payload` pe TS help nahi. Hamesha `PayloadAction<number>` explicit.
*   **`configureStore` me `reducer` ko `reducers` (plural) likh diya:** API `reducer` singular hai — `configureStore({reducer: {...}})` — `s` extra lagega toh TS error `Object literal may only specify known properties`.

## Khud Try Karo

1.  `counterSlice.ts` me ek naya reducer `incrementBy5: (state) => {state.count += 5}` add karke `store.dispatch(incrementBy5())` call karo — `console.log(store.getState())` me `count` 5 se badha?
2.  `addBy` ko `PayloadAction<number>` ki jagah `PayloadAction<string>` karke `addBy(5)` call karo — TS error kya kehta hai? Kyun `number` vs `string` matter karta hai?
3.  Manual `6.7.1` wale `counterManual.ts` ka `return {count: state.count+1}` aur is doc ka `state.count++` — dono ka final `store.getState()` same kyun, andar mechanism kya alag?

## What It Is NOT

*   **NOT magic:** `createSlice` andar wahi `switch` + `action creator` bana raha hai — code generate ho raha hai, tumhare liye likh raha hai, concept wahi `6.7.1` wala.
*   **NOT Zustand jaisa direct:** Abhi bhi `dispatch(increment())` parchi bhejni padti hai — Zustand `set` direct se verbose hai, par traceable hai.
*   **NOT plain Redux:** Plain Redux me `createSlice` nahi hota — wahan sab manual `6.7.1` jaisa. RTK = Redux ka official shortcut.

## Summary

*   `createSlice` = `name + initialState + reducers` -> `reducer + actions` auto.
*   `configureStore` = store factory + DevTools + Immer + `RootState` type.
*   `state.count++` RTK me safe hai Immer ki wajah se, manual me bug tha.
*   Counter ka boilerplate 40 -> 15 lines, 5 slices pe 200 -> 75.

## Agla Step

Agla doc `6.7.3` me is store ko React se jodenge — `Provider` kaha lagta hai, `useSelector`/`useDispatch` kyun, aur `RootState`/`AppDispatch` se **typed hooks** `useAppSelector`/`useAppDispatch` kaise banate hain — taaki `action.payload` me TS auto-complete mile. Store toh ban gaya, ab React ko usse baat karwana hai.
