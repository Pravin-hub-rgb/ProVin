## STAGE 1 — States: Loading, Error, Empty (kyun, kahan, kab)

### SOCH

Dynamic `6.7.5.4` me `status` check tha par socho — API slow hai toh user ko blank `FilterBar` dikhega, samjhega hi nahi categories load ho rahi hain. API fail hui toh blank select, error ka pata nahi. Filter `Shopping` pe koi expense nahi toh blank list — “kuch hai hi nahi” vs “filter me kuch nahi”. Har state ka UI chahiye — Next.js me `loading.tsx`/`error.tsx`/`not-found.tsx` `1.4` me jaisa, yahan `status` se.

### CONCEPT

`categoriesSlice` ka `status` 4 values: `idle` (initial, fetch nahi hua), `loading` (fetch chal raha), `succeeded` (items aaye), `failed` (error). `expenses` ka `filtered.length===0` empty. Har state ka alag JSX.

### CODE

`App.tsx` me already `status` check tha `6.7.5.4 STAGE 3` me — yahan refine + `ExpenseList` me empty:

```tsx
// src/App.tsx — STAGE 1 states refined (existing App.tsx update, sirf naya highlight)
import { useEffect } from "react";
import { useAppSelector, useAppDispatch } from "./rtk/hooks";
import { fetchCategories } from "./rtk/categoriesSlice";
import { ExpenseForm } from "./components/ExpenseForm";
import { FilterBar } from "./components/FilterBar";
import { ExpenseList } from "./components/ExpenseList";
import { Stats } from "./components/Stats";

export default function App() {
  const dispatch = useAppDispatch();
  const { status, error } = useAppSelector((s) => s.categories);

  useEffect(() => {
    if (status === "idle") dispatch(fetchCategories());
  }, [status, dispatch]);

  return (
    <main style={{ maxWidth: 640, margin: "0 auto", padding: 16 }}>
      <h1>💰 Expense Tracker — RTK (States)</h1>
      <Stats />
      {status === "loading" && <p>⏳ Loading categories...</p>}
      {status === "failed" && <p style={{ color: "red" }}>❌ {error} — <button onClick={() => dispatch(fetchCategories())}>Retry</button></p>}
      {status === "succeeded" && <p style={{ color: "#666", fontSize: 13 }}>Categories loaded ✓</p>}
      <ExpenseForm />
      <FilterBar />
      <ExpenseList />
    </main>
  );
}
```

`ExpenseList.tsx` me empty already `6.7.5.4` me tha — yahan ensure:

```tsx
// src/components/ExpenseList.tsx — empty state (already 6.7.5.4 me, yahan verify)
```

## STAGE 3 — Persist (Optional — Zustand vs RTK Trade-off)

### SOCH

`6.7.5.4` me refresh pe new expenses reset — `6.5` Zustand `persist` middleware se auto `localStorage` sync tha `6.4:478` `persist({name:"todo-tasks"})` 1 line. RTK me `localStorage` manual? Koi `redux-persist` lib hai par extra setup + serializable check warning. Dono ka trade-off dekho — naya project kaunsa, legacy me kya milega.

### CONCEPT

*   **Zustand persist:** `create(persist((set)=>..., {name:"key"}))` — 1 wrapper, JSON stringify auto, `partialize` bhi.
*   **RTK persist:** `redux-persist` `persistReducer` + `persistStore` + `FLUSH/REHYDRATE` serializable ignore — `configureStore` me `middleware: getDefault => getDefault({serializableCheck:{ignoredActions:[...]}})`.

Nutshell: Persist woh middleware hai jo store ka state `localStorage` me auto save/restore karta hai — Zustand me built-in jaisa 1 line, RTK me extra lib + config.

### CODE

**Option A — Zustand jaisa simple (recommend nahi for RTK enterprise, par demo):**

```ts
// src/rtk/store.ts — with redux-persist (is stage me add, pehle nahi)
import { configureStore } from "@reduxjs/toolkit";
import { persistStore, persistReducer, FLUSH, REHYDRATE, PAUSE, PERSIST, PURGE, REGISTER } from "redux-persist";
import storage from "redux-persist/lib/storage"; // localStorage
import expensesReducer from "./expensesSlice";
import categoriesReducer from "./categoriesSlice";
import { combineReducers } from "@reduxjs/toolkit";

const rootReducer = combineReducers({ expenses: expensesReducer, categories: categoriesReducer });
const persistedReducer = persistReducer({ key: "expense-rtk", storage, whitelist: ["expenses"] }, rootReducer);

export const store = configureStore({
  reducer: persistedReducer,
  middleware: (getDefault) => getDefault({
    serializableCheck: { ignoredActions: [FLUSH, REHYDRATE, PAUSE, PERSIST, PURGE, REGISTER] },
  }),
});
export const persistor = persistStore(store);
export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
```

```tsx
// src/main.tsx — PersistGate wrap
import { PersistGate } from "redux-persist/integration/react";
import { persistor } from "./rtk/store";
<Provider store={store}>
  <PersistGate loading={null} persistor={persistor}>
    <App />
  </PersistGate>
</Provider>
```

**Trade-off line:** `redux-persist` + `PersistGate` + 6 ignored actions — Zustand `persist({name})` se 5x zyada config. Isliye `plan-03-architecture-cheatsheet.md:69` kehta hai `Zustand = sweet spot`, RTK persist enterprise me already setup milta hai toh rehne do, naya me Zustand.

**Option B — Simple manual (if no persist lib):** `6.7.1` wala `store.subscribe` + `localStorage.setItem` — `6.2` `useLocalStorage` jaisa, par RTK me bhi manual kar sakte ho — 10 lines.

## Common Mistakes (States + Persist)

*   **`status==="idle"` check bina `useEffect` me fetch loop:** `useEffect(()=>{dispatch(fetchCategories())},[status])` me `status` dep se `pending->fulfilled` pe dobara fetch — `idle` check nahi kiya toh infinite loop. `if(status==="idle")` guard zaroori.
*   **`PersistGate` bhool gaye:** `redux-persist` me `PersistGate` nahi wrap kiya toh `App` `REHYDRATE` se pehle render — `expenses.items` khali, phir `persist` se bhar gaya par `Stats` flicker. `PersistGate loading={null}` se rehydrate tak wait.
*   **Serializability warning ignore:** `configureStore` me `ignoredActions` nahi diya toh console `A non-serializable value was detected` warning — `redux-persist` ke `FLUSH` actions non-serializable hain, ignore karna padta hai.
*   **Test table skip kiya:** “Add kaam kar raha hai” bol diya bina `Food`/`Beef` filter + `Total` + DevTools verify ke — `6.7.5.2` wala `Reduce` bug `“2050”` miss ho jaata.

## Khud Try Karo

1.  `App.tsx` me `if(status==="idle")` guard hata ke `dispatch(fetchCategories())` har render pe karo — Network tab me kitni requests? Kyun infinite loop nahi (deps `[]` hai toh 1 baar, `[status]` hai toh loop)?
2.  `redux-persist` ke bina manual `store.subscribe(()=> localStorage.setItem("expenses", JSON.stringify(store.getState().expenses.items)))` try karo — `initialState.items` me `JSON.parse(localStorage.getItem("expenses"))` se restore — `6.2 useLocalStorage` jaisa, par RTK me kyun `PersistGate` better?

## What It Is NOT

*   **NOT RTK Query:** Categories `createAsyncThunk` se, `createApi`/`fetchBaseQuery` nahi — RTK Query data caching ka alag chapter, yahan `TanStack Query (Batch 2.3)` vs `createAsyncThunk` hi.
*   **NOT plain Redux persist:** Plain Redux me `switch` + manual `store.subscribe` persist — yahan RTK + `redux-persist`.
*   **NOT final persist required:** Refresh pe reset bhi acceptable demo ke liye — persist optional, concept `persist` ka tha, production me kaunsa use hoga team decide karegi.

## In Your Own Words

1. `status` ke 4 values (`idle/loading/succeeded/failed`) me `idle` ka kya kaam, `loading` se kaise alag? `if(status==="idle")` guard kyun?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `idle` = abhi tak fetch start hi nahi hua (initial), `loading` = `pending` dispatch ke baad fetch chal raha. `idle` guard se `useEffect` sirf pehli baar `fetchCategories` dispatch karta hai — `loading/succeeded/failed` pe dobara nahi. Guard nahi hota aur deps `[status]` hota toh `pending->succeeded` pe `status` change se `useEffect` dobara fetch, infinite loop. `6.7.4` me `createAsyncThunk` ke 3 actions `pending/fulfilled/rejected` wahi `status` ko drive karte hain.

</details>

2. `redux-persist` me `PersistGate` kyun, `Provider` ke andar bina uske kya flicker hota?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `redux-persist` `localStorage` se `REHYDRATE` action async bhejta hai — `persistStore` `localStorage.getItem("expense-rtk")` read karke store me `REHYDRATE` dispatch karta hai. `PersistGate` `REHYDRATE` tak `App` ko render rokta hai (`loading={null}`), taaki `initialState` khali `[]` se pehle render na ho. `PersistGate` nahi hota toh `App` pehle khali `items` se `No expenses` dikhata, phir `REHYDRATE` ke baad `Maggie` aata — flicker. Zustand `persist` me yeh gate built-in jaisa.

</details>

3. Test table ki row 3 (`Maggie ₹40 Food` Add) me UI + DevTools dono verify kyun? Sirf UI dekho toh kya miss ho sakta hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** UI me `Maggie — ₹40 (Food)` dikha toh `addExpense` payload sahi laga, par `amount` string `"40"` hota toh bhi `— ₹40` dikh jaata (string render). `Total: ₹90` me `reduce` string concat `“2040”` bug UI me `₹2040` dikhta — UI se pakda jaata, par `amount` type ka bug store me `string` save hua. DevTools me `expenses/addExpense` ka `payload` `{amount: "40"}` string dikhega — `PayloadAction<Expense>` me `amount: number` contract violation. UI + DevTools dono se `amount` number confirm — `Number(amount)` convert sahi.

</details>
