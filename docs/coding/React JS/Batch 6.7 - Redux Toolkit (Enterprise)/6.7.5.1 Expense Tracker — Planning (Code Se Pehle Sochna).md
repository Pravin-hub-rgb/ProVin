## 1. Kya Banana Hai? — Purpose

Expense Tracker — roz ke kharche note karo (chai, bus, lunch), category se filter karo (Food/Travel), total kitna kharcha hua dekho. Kyun yeh project? Kyunki yeh **RTK ke saare concepts ek saath** combine karta hai jo abhi seekhe:

| RTK Concept (batch ke) | Kahan Lagega |
|---|---|
| `createSlice` sync `reducers` | `addExpense` / `deleteExpense` / `setFilter` |
| `createAsyncThunk` | `fetchCategories` — API se categories (Beef, Chicken...) |
| `useAppSelector` selective | Total calculate, filtered list |
| `configureStore` + `Provider` | Central store, poori app me |
| `PayloadAction<T>` | `addExpense` ka payload `Expense` |

Zustand wala `To-Do v3 (6.5)` bhi same idea tha — par wahan `set` direct tha, yahan har change `dispatch` parchi se. Back-to-back compare ka maza Part 3 me ayega.

DukaanOS se connection? DukaanOS me bhi `stock` + `sale` + `udhaar` alag slices hote — wahi pattern yahan `expenses` + `categories` slices.

## 3. Data Ka Shape Kya Hai? — UI Se Decide (Ulta Nahi)

`how to write project in series prompt.md:64` kehta hai — **data UI se decide hota hai, ulta nahi.** Pehle socho list pe kya dikhega, phir field banao.

List pe kya dikhega? Har row: `“Chai — ₹20 (Food) [Delete]”`. Iska matlab har expense ko **title**, **amount**, **category** chahiye. Plus `id` (React `key` + delete ke liye), `date` (abhi nahi dikhayenge par future me `6.7.5.5` me “aaj ke expenses” filter extend ho sake).

| Field | Type | Kyun (UI se reason) | Example |
|---|---|---|---|
| `id` | `string` | `key` + `deleteExpense(id)` ke liye unique | `"exp-1703-abc"` |
| `title` | `string` | List me `title` text | `"Chai"` |
| `amount` | `number` | List me `₹amount` + Stats me total sum | `20` |
| `category` | `string` | `category` badge + FilterBar se filter | `"Food"` |
| `date` | `string` (ISO) | Abhi nahi dikhayenge, par future filter ke liye rakha | `"2026-08-25"` |

Type:

```ts
// yeh type 6.7.5.3 me actual file me banega, yahan sirf plan
interface Expense {
  id: string;
  title: string;
  amount: number;
  category: string;
  date: string; // ISO string, abhi display nahi par store me rakhenge
}
type FilterStatus = "all" | string; // "all" ya koi category name
```

**Har field ka reason hai — random nahi.** `amount` ko `string` nahi `number` rakha kyunki total `expenses.reduce((sum, e) => sum + e.amount, 0)` numeric sum chahiye — string hota toh `"20" + "50" = "2050"` bug.

Categories ka shape? `string[]` — `["Beef","Chicken","Dessert"]` API se `6.7.4` wale `fetchCategories` se — slice `categoriesSlice` me `items: string[]`.

## Common Mistakes (Planning Me Hi)

*   **Data shape UI se nahi, API se copy kiya:** API se `strCategory` aaya toh `strCategory` hi field rakh diya — UI me `category` chahiye, API ka naam nahi. `categoriesSlice` me `map(c => c.strCategory)` karke clean `string[]` banana — `6.7.4` me wahi kiya.
*   **`amount` ko `string` rakha:** Input se `e.target.value` string aata hai, par store me `number` rakho — `Number(value)` convert karke dispatch. Nahi toh total `reduce` bug.
*   **Ek hi slice me sab daal diya:** `expenses + categories + filter` ek slice me — slice ka `name` ka matlab hi alag section (register ka section). `expensesSlice` (items+filter) aur `categoriesSlice` (items+status) alag — `combineReducers` se `store` me jodna.
