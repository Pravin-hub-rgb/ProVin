## STAGE 2 — HARDCODED LIST + FILTER (local state, still no RTK)

### THINK

The skeleton had 2 rows as hardcoded `<p>`. Now turn them into an array with `map`, and filter with the `Food` button — but **without RTK**, using local `useState`, so the UI's `filter` logic is confirmed. In `6.7.5.3`, the same filter moves to the `slice` — but the UI logic is verified locally first.

### CONCEPT

`useState` for `filter` state, `hardcodedExpenses.filter(e => filter==="all" || e.category===filter)` for derived list, `total = filtered.reduce((s,e)=>s+e.amount,0)` — remember the `filteredTasks` pattern from `6.5:318`.

### CODE

**Update** `ExpenseStaticApp.tsx` — hardcoded array + local filter:

```tsx
// src/components/ExpenseStaticApp.tsx — STAGE 2 updated
import { useState } from "react";

interface Expense {
  id: string;
  title: string;
  amount: number;
  category: string;
  date: string;
}

const hardcoded: Expense[] = [
  { id: "1", title: "Chai", amount: 20, category: "Food", date: "2026-08-25" },
  { id: "2", title: "Bus", amount: 50, category: "Travel", date: "2026-08-25" },
  { id: "3", title: "Samosa", amount: 30, category: "Food", date: "2026-08-25" },
];

export function ExpenseStaticApp() {
  const [filter, setFilter] = useState<string>("all");

  const filtered = hardcoded.filter((e) => filter === "all" || e.category === filter);
  const total = filtered.reduce((sum, e) => sum + e.amount, 0);

  return (
    <main style={{ maxWidth: 640, margin: "0 auto", padding: 16 }}>
      <h1>💰 Expense Tracker — Hardcoded</h1>
      <p>Total: ₹{total} ({filtered.length} expenses) — Filter: {filter}</p>

      <div style={{ display: "flex", gap: 8, marginBottom: 12 }}>
        <input placeholder="Title e.g. Chai" />
        <input placeholder="Amount e.g. 20" type="number" />
        <select defaultValue="Food">
          <option>Food</option>
          <option>Travel</option>
          <option>Shopping</option>
        </select>
        <button>Add</button>
      </div>

      <div style={{ display: "flex", gap: 8, marginBottom: 12 }}>
        {["all", "Food", "Travel", "Shopping"].map((cat) => (
          <button
            key={cat}
            onClick={() => setFilter(cat)}
            style={{ fontWeight: filter === cat ? 700 : 400 }}
          >
            {cat}
          </button>
        ))}
      </div>

      <div>
        {filtered.map((e) => (
          <div key={e.id} style={{ display: "flex", justifyContent: "space-between", padding: 8, border: "1px solid #ddd", marginBottom: 6 }}>
            <span>{e.title} — ₹{e.amount} ({e.category})</span>
            <button>Delete</button>
          </div>
        ))}
        {filtered.length === 0 && <p>No expenses for {filter}.</p>}
      </div>
    </main>
  );
}
```

Why each new line of code:

| Code | Why |
|------|------|
| `hardcoded` array outside the component | Static data — if inside render, a new array on every render, `useMemo` trap |
| `useState<string>("all")` | Local version of `FilterStatus` — in RTK, this becomes `expensesSlice.filter` |
| `filtered = hardcoded.filter(...)` | Derived — the original `hardcoded` doesn't change, only the view changes |
| `total = filtered.reduce(...)` | For Stats — a derived value just like `completedCount` from `6.5:320` |
| `key={e.id}` | The `key` prop from `0.3 Reconciliation` — `id` is stable, not index |

### CONCEPT

The `STAGE 4` pattern — `onClick` first does `console.log({title, amount, category})` — confirmed click detection + value capture, real logic comes later.

### CODE

Bind the form inputs with `useState` — **gradually**, not 3 inputs + RTK at once:

```tsx
// src/components/ExpenseStaticApp.tsx — STAGE 3 form state added (existing file update, only new parts highlighted)
import { useState } from "react";
// ... hardcoded + filter as before

export function ExpenseStaticApp() {
  const [filter, setFilter] = useState<string>("all");
  const [title, setTitle] = useState("");
  const [amount, setAmount] = useState("");
  const [category, setCategory] = useState("Food");

  const filtered = hardcoded.filter((e) => filter === "all" || e.category === filter);
  const total = filtered.reduce((sum, e) => sum + e.amount, 0);

  const handleAdd = () => {
    console.log("Add clicked:", { title, amount: Number(amount), category });
  };

  return (
    <main style={{ maxWidth: 640, margin: "0 auto", padding: 16 }}>
      <h1>💰 Expense Tracker — Hardcoded + Form state</h1>
      <p>Total: ₹{total} ({filtered.length} expenses)</p>

      <div style={{ display: "flex", gap: 8, marginBottom: 12 }}>
        <input placeholder="Title e.g. Chai" value={title} onChange={(e) => setTitle(e.target.value)} />
        <input placeholder="Amount e.g. 20" type="number" value={amount} onChange={(e) => setAmount(e.target.value)} />
        <select value={category} onChange={(e) => setCategory(e.target.value)}>
          <option>Food</option>
          <option>Travel</option>
          <option>Shopping</option>
        </select>
        <button onClick={handleAdd}>Add</button>
      </div>

      {/* Filter + List same as STAGE 2 */}
      <div style={{ display: "flex", gap: 8, marginBottom: 12 }}>
        {["all", "Food", "Travel", "Shopping"].map((cat) => (
          <button key={cat} onClick={() => setFilter(cat)} style={{ fontWeight: filter === cat ? 700 : 400 }}>
            {cat}
          </button>
        ))}
      </div>
      <div>
        {filtered.map((e) => (
          <div key={e.id} style={{ display: "flex", justifyContent: "space-between", padding: 8, border: "1px solid #ddd", marginBottom: 6 }}>
            <span>{e.title} — ₹{e.amount} ({e.category})</span>
            <button>Delete</button>
          </div>
        ))}
      </div>
    </main>
  );
}
```

## What Pain Points Are Showing Up? (Reason for Next Doc)

The hardcoded array is now in **one place** — the `hardcoded` const. But imagine going forward without `6.7.5.3`:

*   `ExpenseStaticApp` has `hardcoded` + `filter` + `title/amount/category` + `handleAdd console.log` all in one file — the `App.tsx overloaded` problem from `6.5:66`.
*   Tomorrow, if we extract `ExpenseForm` as a separate component, we'd need prop drilling to pass `hardcoded` to 3 places.
*   The real logic of `Add` would be `hardcoded.push` mutation — the mutate bug from `6.7.1`, plus resets on refresh (no persistence).

This duplication + prop drilling + mutate + no persistence is what `6.7.5.3 Data Layer` solves — `expensesSlice` + `categoriesSlice` + `store` — a single source of truth, each component reads via `useAppSelector`, writes via `dispatch`.

## Common Mistakes (in Hardcoded UI)

*   **Using `key={index}`:** `hardcoded.map((e, idx) => <div key={idx}>)` — the `key` trap from `6.5:340` / `0.3 Reconciliation` — wrong row deleted, input state shuffled. Always use stable `key={e.id}`.
*   **Hardcoded array inside render:** `function ExpenseStaticApp(){ const hardcoded = [...] }` — new array reference on every render, infinite loop in `useEffect` deps, `React.memo` fails. Keep it outside.
*   **Jumped straight to dynamic `dispatch`:** Writing RTK dispatch without verifying `onChange` with `console.log` — if an error occurs, we won't know if the form is wrong or the slice is wrong. Always do the `STAGE 4 console.log` first.
*   **`amount` dispatched as string:** Input `value` is a string, no `NaN` check — total `reduce` does string concatenation `“20” + “50” = “2050”`. `Number(amount)` + `>0` check is essential.

## In Your Own Words

1. Why build Hardcoded UI first, why not `expensesSlice` straight away? What gets confusing in debugging if both are built at the same time?

<details>
<summary>Show Answer</summary>

**Sample Answer:** In Hardcoded, there's only UI — `map`, `key`, `filter`, `total`, with data from the `hardcoded` const. If we build `expensesSlice` + UI at the same time and the list doesn't show, we won't know if the `slice reducer` is wrong, or the `key` in `map` is wrong, or the `useAppSelector` path has a typo like `s.expenses.items`. Building Hardcoded first validates the UI's design + data shape — `title/amount/category` fields displayed correctly, `filter` logic correct, `total` sum correct. Then in `6.7.5.3`, we build the slice and in `6.7.5.4`, only the data source changes — UI code stays the same, the difference is clear, and the bug source is identifiable.

</details>

2. Why is the `hardcoded` array kept outside the component, what's the loss if `const hardcoded = [...]` is inside?

<details>
<summary>Show Answer</summary>

**Sample Answer:** If inside the component, every render creates a new array (new reference) — if used in `useEffect` deps, infinite loop; if passed as prop `expenses={hardcoded}` to a `React.memo` child, new prop on every render, memo fails. Outside, the reference is stable — one shared array. Like in `6.1:138`, the confusion of "different state every call" with `useToggle` doesn't apply here — this is static data, not state.

</details>

3. Why `console.log` first in `handleAdd`, why not `hardcoded.push` directly?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `Master Teaching Prompt.md:267` `STAGE 4` — first confirm that the click is detected + values are captured correctly. `console.log({title, amount: Number(amount)})` confirms `title` is a string, `amount` converts to number correctly, `category` from select is correct. If we pushed directly and the list didn't update, we won't know if the form's `onChange` is wrong, or the `push` mutate bug (like the `state.count++` from `6.7.1`), or the `hardcoded` const. `console.log` first verifies 1 layer, then the real logic goes in the next doc with `dispatch(addExpense(...))`.

</details>
