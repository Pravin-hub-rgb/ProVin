## Recipe Finder — Batch 2 Ka Code Recap

Yeh tha humara purana code (Batch 2.2 se). Poora component, loading/error/data states manually manage:

```tsx
// Reference: Batch 2 ka RecipeFinder.tsx — yeh code type MAT karo, bas padho (reuse hai)
import { useState, useEffect } from "react";

interface Recipe {
  idMeal: string;
  strMeal: string;
  strMealThumb: string;
  strCategory: string;
  strArea: string;
}

interface SearchResponse {
  meals: Recipe[] | null;
}

function RecipeFinder() {
  const [searchInput, setSearchInput] = useState("");
  const [recipes, setRecipes] = useState<Recipe[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    const fetchDefault = async () => {
      setIsLoading(true);
      const res = await fetch(
        "https://www.themealdb.com/api/json/v1/1/search.php?s=chicken"
      );
      const data: SearchResponse = await res.json();
      setRecipes(data.meals ?? []);
      setIsLoading(false);
    };
    fetchDefault();
  }, []);

  const handleSearch = async () => {
    if (!searchInput.trim()) return;
    setIsLoading(true);
    setError(null);
    try {
      const res = await fetch(
        `https://www.themealdb.com/api/json/v1/1/search.php?s=${searchInput.trim()}`
      );
      const data: SearchResponse = await res.json();
      setRecipes(data.meals ?? []);
    } catch (err) {
      setError(err instanceof Error ? err.message : "Kuch gadbad hui");
      setRecipes([]);
    } finally {
      setIsLoading(false);
    }
  };

  return (
    <div>
      <h1>🍳 Recipe Finder</h1>
      <input value={searchInput} onChange={e => setSearchInput(e.target.value)} />
      <button onClick={handleSearch} disabled={isLoading}>
        {isLoading ? "Searching..." : "Search"}
      </button>
      {isLoading && <p>⏳ Loading...</p>}
      {error && <p style={{ color: "red" }}>❌ {error}</p>}
      {!isLoading && recipes.length === 0 ? (
        <p>No recipes found.</p>
      ) : (
        <div className="grid">
          {recipes.map(recipe => (
            <RecipeCard key={recipe.idMeal} recipe={recipe} />
          ))}
        </div>
      )}
    </div>
  );
}
```

**Problems identify karo:**

| Problem | Lines Count |
|---------|------------|
| `useState` triplets | 3 lines |
| `handleSearch` + fetch | ~20 lines |
| `useEffect` + fetch | ~12 lines |
| Manual loading/error toggle | 6+ jagah |

Total: ~50 lines sirf state + fetch logic ke. Actual UI sirf ~25 lines.

## Refactor Step 1 — useFetch<Recipe[]> Se Replace

Sabse pehle, manual fetch logic hatao. `useFetch<Recipe[]>` use karo — woh hook humne 6.2 mein banaya tha. `src/components/` folder mein `RecipeFinder.tsx` nayi file banao aur hook import karo:

```tsx
// src/components/RecipeFinder.tsx
import { useFetch } from "../hooks/useFetch";

function RecipeFinder() {
  const [searchInput, setSearchInput] = useState("chicken");
  const { data: recipes, isLoading, error } = useFetch<Recipe[]>(
    `https://www.themealdb.com/api/json/v1/1/search.php?s=${searchInput}`
  );
  // ...
}
```

**Dekhte hain kya badla:**

| Purana | Naya |
|--------|------|
| 3 `useState` calls | 0 — sab hook mein chhup gaye |
| 1 `useEffect` with fetch function | 0 — hook handle karta hai |
| `handleSearch` with try/catch/finally | 0 — hook handle karta hai |
| Loading toggle manual | Auto — hook return karta hai `isLoading` |
| Error toggle manual | Auto — hook return karta hai `error` |
| `SearchResponse` interface | Zaroorat nahi — hook generic hai |
| `??` null check | Zaroorat nahi — T | null hook handle karta hai |

Lekin ek problem hai — `searchInput` abhi bhi useState se manage ho raha hai aur search button click pe change karna hai. Kya karein?

**Search trigger kaise kaam karega:** `useFetch` effect ke andar fetch karta hai, aur effect URL change hone pe re-run hota hai. Toh agar hum `searchInput` change karein toh URL change hoga, aur useEffect re-run hoga. Lekin button click pe change karna hai, har character pe nahi.

Solution — **query state** alag rakho jo sirf button click pe update ho (usi `src/components/RecipeFinder.tsx` mein):

```tsx
// src/components/RecipeFinder.tsx
function RecipeFinder() {
  const [searchInput, setSearchInput] = useState("chicken");
  const [query, setQuery] = useState("chicken");

  const { data: recipes, isLoading, error } = useFetch<Recipe[]>(
    `https://www.themealdb.com/api/json/v1/1/search.php?s=${query}`
  );

  const handleSearch = () => {
    if (!searchInput.trim()) return;
    setQuery(searchInput.trim());
  };

  return (
    <div>
      <input value={searchInput} onChange={e => setSearchInput(e.target.value)} />
      <button onClick={handleSearch}>Search</button>
      {/* ... */}
    </div>
  );
}
```

**Flow:** User type kare → `searchInput` update ho (but fetch nahi ho raha) → Button click kare → `query` update ho → URL change ho → `useFetch` ka effect re-run ho → fetch ho → UI update ho.

const [favorites, setFavorites] = useState<Recipe[]>(() => {

  return saved ? JSON.parse(saved) : [];

  localStorage.setItem("favorites", JSON.stringify(favorites));

## Poorna Code (Refactored Recipe Finder)

Yeh poori file hai — `src/components/RecipeFinder.tsx` mein yeh sab kuch likho (RecipeCard wali file alag se bana chuke ho):

```tsx
// src/components/RecipeFinder.tsx
import { useState } from "react";
import { useFetch } from "../hooks/useFetch";
import { useLocalStorage } from "../hooks/useLocalStorage";
import { RecipeCard } from "./RecipeCard";

interface Recipe {
  idMeal: string;
  strMeal: string;
  strMealThumb: string;
  strCategory: string;
  strArea: string;
}

function RecipeFinder() {
  const [searchInput, setSearchInput] = useState("chicken");
  const [query, setQuery] = useState("chicken");
  const [favorites, setFavorites] = useLocalStorage<Recipe[]>("favorites", []);

  const { data: recipes, isLoading, error } = useFetch<Recipe[]>(
    `https://www.themealdb.com/api/json/v1/1/search.php?s=${query}`
  );

  function toggleFavorite(recipe: Recipe) {
    const exists = favorites.some(fav => fav.idMeal === recipe.idMeal);
    if (exists) {
      setFavorites(favorites.filter(fav => fav.idMeal !== recipe.idMeal));
    } else {
      setFavorites([...favorites, recipe]);
    }
  }

  return (
    <div>
      <h1>🍳 Recipe Finder</h1>

      <input
        value={searchInput}
        onChange={e => setSearchInput(e.target.value)}
        placeholder="Search recipes..."
      />
      <button onClick={() => setQuery(searchInput.trim())} disabled={isLoading}>
        {isLoading ? "Searching..." : "Search"}
      </button>

      {isLoading && <p>⏳ Loading...</p>}
      {error && <p style={{ color: "red" }}>❌ {error}</p>}

      {!isLoading && (recipes?.length === 0 || !recipes) ? (
        <p>No recipes found.</p>
      ) : (
        <div className="grid">
          {recipes.map(recipe => (
            <RecipeCard
              key={recipe.idMeal}
              recipe={recipe}
              isFavorite={favorites.some(fav => fav.idMeal === recipe.idMeal)}
              onToggleFavorite={toggleFavorite}
            />
          ))}
        </div>
      )}
    </div>
  );
}
```

Compare karo purane code se. **Custom hooks ne ~35 lines of boilerplate hata di.** Naya feature (favorites) add kiya hai phir bhi code chhota hai. Yeh hai custom hooks ka power — less code, more features, cleaner structure.

## What Batch 6.3 Taught Us

1. **Custom hooks duplicate pattern ko eliminate karte hain** — ek baar likho, har jagah use karo
2. **`useFetch<T>` ne manual fetch logic ka ~25 lines hata diye**
3. **`useLocalStorage<T>` ne ~8 lines hata di + naya feature add karna easy bana diya**
4. **Component sirf "kyu" pe focus karta hai, "kaise" hook mein chhupa hai**
5. **TypeScript generics ensure karte hain ki types consistent rahein**

Agle topic mein ek aur powerful tool seekhenge — **Zustand**. Context API ki problems dekhenge, aur dekhenge ki Zustand kaise better hai global state management ke liye.

## In Your Own Words

1. Purane Recipe Finder mein `handleSearch` mein try/catch/finally tha. Refactored version mein kyun nahi hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Kyunki woh logic ab `useFetch` hook ke andar chhupa hua hai. Hook internally try/catch/finally handle karta hai, loading aur error states automatically manage karta hai, aur component ko clean data return karta hai. Component ab sirf `{ data, isLoading, error }` destructure karta hai — implementation detail hook mein chhupa hai. Yeh abstraction ka fayda hai — component ka code chhota aur readable.

</details>

2. Refactored version mein `searchInput` aur `query` do alag states kyun hain? Ek state se kaam kyun nahi chal sakta?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Ek state hoti toh har character type karne pe fetch trigger hota (kyunki `useFetch` URL change hone pe re-fetch karta hai). Yeh wasteful hai — user ko type karte waqt har character pe API call nahi chahiye. Isliye `searchInput` user ke typing ke liye hai (local state, koi side effect nahi), aur `query` sirf tab update hota hai jab user button click kare. Is pattern ko "controlled trigger" kehte hain — fetch tabhi trigger hota hai jab user explicitly chahe (button click, Enter key), har keystroke pe nahi.

</details>

3. `useLocalStorage<Recipe[]>("favorites", [])` kaun-si problem solve karta hai jo purane code mein nahi thi?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Purane Recipe Finder mein favorites ka feature tha hi nahi. Agar manually implement karte, toh `useState` + lazy initializer + `useEffect` + `localStorage.getItem` + `JSON.parse` + `JSON.stringify` — minimum 8-10 lines. `useLocalStorage` ne ek line mein sab kuch kar diya. State persist ho gayi browser refresh ke baad bhi, bina kisi boilerplate ke. Jab bhi `setFavorites` call karte ho, localStorage automatic update hota hai — extra effect ki zaroorat nahi.

</details>

4. Refactored code mein `SearchResponse` interface kyun nahi dikh raha? Purane code mein kyun tha?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `SearchResponse` interface API ke poore response shape ko define karta tha (`{ meals: Recipe[] | null }`). Purane code mein hume manually fetch karke response parse karna padta tha, isliye interface zaroori tha. `useFetch` generic hai — hum `useFetch<Recipe[]>` call karte hain, aur hook internally `json as T` karta hai (jahan `T = Recipe[]`). Hook JSON response ko directly T type mein cast kar deta hai. Isliye component ko `SearchResponse` ke baare mein jaanna nahi padta — hook ne woh abstraction handle kar liya.

</details>

5. Custom hooks use karne ke baad bhi component mein `loading` aur `error` states handle kar rahe hain — toh kya fark hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `isLoading` aur `error` ab hook se aa rahe hain, component khud manage nahi kar raha. Fark yeh hai — purane code mein component khud `setIsLoading(true/false)` har jagah kar raha tha, `try/catch/finally` mein. Ab component sirf *consume* kar raha hai, *manage* nahi. Agar implementation change karna ho (jaise loading time mein delay add karna ho, ya error format badalna ho), toh sirf `useFetch` hook change karo — sab components automatically updated ho jayenge. Yeh **separation of concerns** hai — component UI ke liye responsible, hook state management ke liye.

</details>
