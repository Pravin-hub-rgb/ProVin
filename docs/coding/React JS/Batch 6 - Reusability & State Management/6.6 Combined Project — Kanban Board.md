## Step 2 — Types (Normalized State Design)

First decision — **state structure**. Two options:

**Nested (denormalized):**
```ts
{
  columns: [
    { id: "todo", title: "To Do", cards: [{ id, title, ... }] }
  ]
}
```

Problem: to update a card, you need to find the entire column array. To move a card, you need to remove it from one column and add it to another. Complex operations become cumbersome.

**Normalized (recommended):**
```ts
{
  columns: {
    todo: { id: "todo", title: "To Do", cardIds: ["card1", "card2"] },
    progress: { id: "progress", title: "In Progress", cardIds: ["card3"] },
    done: { id: "done", title: "Done", cardIds: [] }
  },
  cards: {
    card1: { id: "card1", title: "...", description: "...", assignee: "...", priority: "high" }
  },
  columnOrder: ["todo", "progress", "done"]
}
```

Benefit: to update a card, just change `cards.card1` — no need to find or update a column. To move a card: just update the `cardIds` arrays of both columns. **O(1) lookup** for any card. This is the same approach used by industry-standard libraries (Redux docs, `react-beautiful-dnd`).

```ts
// types.ts
export interface Card {
  id: string;
  title: string;
  description: string;
  assignee: string;
  priority: "low" | "medium" | "high";
}

export interface Column {
  id: string;
  title: string;
  cardIds: string[];
}

export interface BoardState {
  columns: Record<string, Column>;
  cards: Record<string, Card>;
  columnOrder: string[];
}
```

`Record<string, Column>` is an object where keys are column IDs. Like a lookup table — `columns["todo"]` instantly returns the column. Fast and simple.

## Step 3 — Zustand Store with Undo/Redo

Now create the store with normalized state. We also need undo/redo.

**Undo/Redo concept:** Before every state change, save a snapshot of the current state. `undo` = go back to the previous snapshot. `redo` = go forward to the next snapshot.

Zustand does not have a built-in `history` middleware, but we can write a custom wrapper:

```ts
// stores/boardStore.ts
import { create } from "zustand";
import { persist } from "zustand/middleware";
import type { BoardState, Card, Column } from "../types";

interface BoardActions {
  addCard: (columnId: string, card: Card) => void;
  updateCard: (cardId: string, updates: Partial<Card>) => void;
  deleteCard: (cardId: string) => void;
  moveCard: (cardId: string, fromCol: string, toCol: string, toIndex?: number) => void;
  addColumn: (column: Column) => void;
  undo: () => void;
  redo: () => void;
}

type BoardStore = BoardState & BoardActions & {
  past: BoardState[];
  future: BoardState[];
};

const initialState: BoardState = {
  columns: {
    todo: { id: "todo", title: "To Do", cardIds: [] },
    progress: { id: "progress", title: "In Progress", cardIds: [] },
    done: { id: "done", title: "Done", cardIds: [] },
  },
  cards: {},
  columnOrder: ["todo", "progress", "done"],
};

function snapshot(state: BoardStore): BoardState {
  return {
    columns: state.columns,
    cards: state.cards,
    columnOrder: state.columnOrder,
  };
}

export const useBoardStore = create<BoardStore>()(
  persist(
    (set, get) => ({
      ...initialState,
      past: [],
      future: [],

      addCard: (columnId, card) => {
        set((state) => ({
          past: [...state.past, snapshot(state)],
          future: [],
          cards: { ...state.cards, [card.id]: card },
          columns: {
            ...state.columns,
            [columnId]: {
              ...state.columns[columnId],
              cardIds: [...state.columns[columnId].cardIds, card.id],
            },
          },
        }));
      },

      updateCard: (cardId, updates) => {
        set((state) => ({
          past: [...state.past, snapshot(state)],
          future: [],
          cards: {
            ...state.cards,
            [cardId]: { ...state.cards[cardId], ...updates },
          },
        }));
      },

      deleteCard: (cardId) => {
        set((state) => {
          const columnId = state.columnOrder.find((colId) =>
            state.columns[colId].cardIds.includes(cardId)
          );
          if (!columnId) return state;
          return {
            past: [...state.past, snapshot(state)],
            future: [],
            cards: Object.fromEntries(
              Object.entries(state.cards).filter(([id]) => id !== cardId)
            ),
            columns: {
              ...state.columns,
              [columnId]: {
                ...state.columns[columnId],
                cardIds: state.columns[columnId].cardIds.filter(
                  (id) => id !== cardId
                ),
              },
            },
          };
        });
      },

      moveCard: (cardId, fromCol, toCol, toIndex) => {
        set((state) => {
          const fromColumn = state.columns[fromCol];
          const toColumn = state.columns[toCol];
          const fromCardIds = fromColumn.cardIds.filter((id) => id !== cardId);
          const toCardIds = [...toColumn.cardIds];
          toIndex !== undefined
            ? toCardIds.splice(toIndex, 0, cardId)
            : toCardIds.push(cardId);

          return {
            past: [...state.past, snapshot(state)],
            future: [],
            columns: {
              ...state.columns,
              [fromCol]: { ...fromColumn, cardIds: fromCardIds },
              [toCol]: { ...toColumn, cardIds: toCardIds },
            },
          };
        });
      },

      addColumn: (column) => {
        set((state) => ({
          past: [...state.past, snapshot(state)],
          future: [],
          columns: { ...state.columns, [column.id]: column },
          columnOrder: [...state.columnOrder, column.id],
        }));
      },

      undo: () => {
        set((state) => {
          if (state.past.length === 0) return state;
          const previous = state.past[state.past.length - 1];
          return {
            past: state.past.slice(0, -1),
            future: [snapshot(state), ...state.future],
            columns: previous.columns,
            cards: previous.cards,
            columnOrder: previous.columnOrder,
          };
        });
      },

      redo: () => {
        set((state) => {
          if (state.future.length === 0) return state;
          const next = state.future[0];
          return {
            future: state.future.slice(1),
            past: [...state.past, snapshot(state)],
            columns: next.columns,
            cards: next.cards,
            columnOrder: next.columnOrder,
          };
        });
      },
    }),
    {
      name: "kanban-board",
      partialize: (state) => ({
        columns: state.columns,
        cards: state.cards,
        columnOrder: state.columnOrder,
        // past/future are not persisted — undo/redo is session-level
      }),
    }
  )
);
```

**Key decisions in the store:**

| Decision | Why |
|----------|------|
| `past` and `future` in the store | Save a snapshot before each mutation. Undo = pop from past, push to future. |
| `snapshot()` function | Pure copy of state — ensures mutations don't leak outside the store |
| `partialize` in persist | Only persist the board state, not undo history (session-level) |
| Card move with `filter` + `splice` | Immutable update pattern — don't mutate existing arrays |
| `Object.fromEntries` for delete | Filter out the deleted card from the cards object |

**State diagram — When a card is moved:**

```
User drags a card from "todo" to "progress"
    │
    ├── snapshot(state) → save to past
    ├── future = [] (clear redo stack)
    │
    ├── fromColumn.cardIds = [..., cardId] → filter out cardId
    ├── toColumn.cardIds = [...toColumn.cardIds, cardId] → add cardId
    │
    ├── columns updated → UI re-renders
    │
    └── undo available → one click back
```

## Step 4 — Generic UI Components

Now create components that are generic — `<Card<T>>` and `<Column<T>>` can work with any data type.

### Generic Card<T>

The Card component should not know the data type. Just render whatever content is given:

```tsx
// components/Card.tsx
import { memo, type ReactNode } from "react";

interface CardProps<T> {
  card: T;
  renderContent: (card: T) => ReactNode;
  onDragStart: (cardId: string) => void;
}

function GenericCard<T extends { id: string }>({
  card,
  renderContent,
  onDragStart,
}: CardProps<T>) {
  return (
    <div
      draggable
      onDragStart={() => onDragStart(card.id)}
      className="card"
    >
      {renderContent(card)}
    </div>
  );
}

export const Card = memo(GenericCard) as typeof GenericCard;
```

**What is happening:**

| Line | What It Is |
|------|---------|
| `<T extends { id: string }>` | Generic constraint — any type that has an `id: string` |
| `renderContent: (card: T) => ReactNode` | Render prop — the caller decides the card's UI |
| `draggable` + `onDragStart` | HTML5 drag and drop — native browser API |
| `memo(GenericCard)` | React.memo — same props = skip re-render (from Batch 5) |

**The caller decides the actual content of the card:**

```tsx
<Card<CardData>
  card={card}
  renderContent={(c) => (
    <div>
      <h3>{c.title}</h3>
      <p>{c.description}</p>
      <span className={`priority-${c.priority}`}>{c.priority}</span>
    </div>
  )}
  onDragStart={handleDragStart}
/>
```

### Generic Column<T>

Column is also generic — a container for any type of cards:

```tsx
// components/Column.tsx
import { memo, useCallback, type ReactNode, type DragEvent } from "react";
import { Card } from "./Card";

interface ColumnProps<T> {
  column: { id: string; title: string; cardIds: string[] };
  cards: T[];
  renderCardContent: (card: T) => ReactNode;
  onDragStart: (cardId: string) => void;
  onDrop: (columnId: string) => void;
  columnId: string;
}

function GenericColumn<T extends { id: string }>({
  column,
  cards,
  renderCardContent,
  onDragStart,
  onDrop,
  columnId,
}: ColumnProps<T>) {
  const handleDragOver = useCallback((e: DragEvent) => {
    e.preventDefault(); // necessary to allow drop
  }, []);

  const handleDrop = useCallback(() => {
    onDrop(columnId);
  }, [columnId, onDrop]);

  return (
    <div
      onDragOver={handleDragOver}
      onDrop={handleDrop}
      className="column"
    >
      <h2>{column.title} ({cards.length})</h2>
      {cards.map((card) => (
        <Card<T>
          key={card.id}
          card={card}
          renderContent={renderCardContent}
          onDragStart={onDragStart}
        />
      ))}
    </div>
  );
}

export const Column = memo(GenericColumn) as typeof GenericColumn;
```

**HTML5 Drag & Drop — three events:**

| Event | In Column | In Card |
|-------|-------------|-----------|
| `onDragStart` | — | Card stores its card ID |
| `onDragOver` | `preventDefault()` — allow drop | — |
| `onDrop` | Column knows a card was dropped | — |

### Board Component

Now assemble everything in the Board component:

```tsx
// components/Board.tsx
import { useCallback, useState } from "react";
import { useBoardStore } from "../stores/boardStore";
import { Column } from "./Column";
import { AddCardForm } from "./AddCardForm";
import type { Card as CardType } from "../types";

export function Board() {
  const { columns, cards, columnOrder, moveCard, addCard, undo, redo } =
    useBoardStore();
  const [draggedCardId, setDraggedCardId] = useState<string | null>(null);

  const handleDragStart = useCallback((cardId: string) => {
    setDraggedCardId(cardId);
  }, []);

  const handleDrop = useCallback(
    (targetColumnId: string) => {
      if (!draggedCardId) return;
      // Find source column
      const sourceColumnId = columnOrder.find((colId) =>
        columns[colId].cardIds.includes(draggedCardId)
      );
      if (!sourceColumnId || sourceColumnId === targetColumnId) return;
      moveCard(draggedCardId, sourceColumnId, targetColumnId);
      setDraggedCardId(null);
    },
    [draggedCardId, columnOrder, columns, moveCard]
  );

  const handleAddCard = useCallback(
    (columnId: string, card: CardType) => {
      addCard(columnId, card);
    },
    [addCard]
  );

  return (
    <div>
      <div className="toolbar">
        <button onClick={undo}>↩ Undo</button>
        <button onClick={redo}>↪ Redo</button>
      </div>
      <div className="board">
        {columnOrder.map((colId) => {
          const column = columns[colId];
          const columnCards = column.cardIds
            .map((cardId) => cards[cardId])
            .filter(Boolean);

          return (
            <div key={colId} className="column-wrapper">
              <Column<CardType>
                column={column}
                cards={columnCards}
                columnId={colId}
                renderCardContent={(card) => (
                  <div>
                    <h3>{card.title}</h3>
                    <p>{card.description}</p>
                    <span className={`priority-${card.priority}`}>
                      {card.priority}
                    </span>
                  </div>
                )}
                onDragStart={handleDragStart}
                onDrop={handleDrop}
              />
              <AddCardForm columnId={colId} onAdd={handleAddCard} />
            </div>
          );
        })}
      </div>
    </div>
  );
}
```

**Flow — When a user drags a card:**

```
User drags card from "todo" column
    │
    ├── Card's onDragStart → setDraggedCardId("card-1")
    │
    ▼
User drops on "progress" column
    │
    ├── Column's onDrop fires → handleDrop("progress")
    │
    ├── Find source column: "todo" (the one with card-1)
    ├── moveCard("card-1", "todo", "progress") called
    │
    ├── Zustand store updates:
    │   ├── past: [snapshot]
    │   ├── future: []
    │   ├── todo.cardIds: filter out card-1
    │   └── progress.cardIds: push card-1
    │
    ├── React re-renders only:
    │   ├── "todo" column (cardIds changed — count update)
    │   └── "progress" column (cardIds changed — new card added)
    │   (Other columns stay — Zustand selective subscription)
    │
    └── draggedCardId reset to null
```

## Step 5 — Custom Hook: useBoard

Wrap complex operations in custom hooks. Like — finding a card, or calculating board statistics:

```ts
// hooks/useBoard.ts
import { useBoardStore } from "../stores/boardStore";
import { useMemo } from "react";

export function useBoard() {
  const columns = useBoardStore((s) => s.columns);
  const cards = useBoardStore((s) => s.cards);
  const columnOrder = useBoardStore((s) => s.columnOrder);

  const stats = useMemo(() => {
    const totalCards = Object.keys(cards).length;
    const perColumn = columnOrder.map((colId) => ({
      column: columns[colId].title,
      count: columns[colId].cardIds.length,
    }));
    return { totalCards, perColumn };
  }, [cards, columns, columnOrder]);

  const getCard = (cardId: string) => cards[cardId];

  const getCardsInColumn = (columnId: string) =>
    columns[columnId]?.cardIds
      .map((id) => cards[id])
      .filter(Boolean) ?? [];

  return { stats, getCard, getCardsInColumn };
}
```

**What it returns:**
- `stats` — computed values (memoized — only changes when cards or columns change)
- `getCard` — O(1) lookup for any card
- `getCardsInColumn` — Get all cards for a column (converting from normalized to denormalized)

## Step 7 — Performance Optimizations (Batch 5 Carry-Forward)

### React.memo on Card (Already Done)

`GenericCard` is wrapped in `memo`. When the cards list in a column changes, only the cards whose actual data changed re-render. The rest stay the same.

### useCallback for Handlers

All handlers in the Board component are wrapped in `useCallback`. The Column and Card components receive stable function references — React.memo's shallow comparison works correctly.

### Selective Zustand Subscriptions

Each component subscribes to only as much state as it needs. This pattern is used inside components — like in `Column.tsx` subscribing to card count, or in Card wrapper subscribing to a specific card:

```tsx
// Inside a component (e.g. Column.tsx)
// Subscribe to count only — card content change won't trigger re-render
const cardCount = useBoardStore((s) => s.columns[colId].cardIds.length);

// Subscribe to a specific card only
const card = useBoardStore((s) => s.cards[cardId]);
```

## Step 8 — AddCardForm

A form for adding cards. Create a new file `AddCardForm.tsx` in `src/components/`:

```tsx
// components/AddCardForm.tsx
import { useState, useCallback, type FormEvent } from "react";
import type { Card } from "../types";

interface AddCardFormProps {
  columnId: string;
  onAdd: (columnId: string, card: Card) => void;
}

export function AddCardForm({ columnId, onAdd }: AddCardFormProps) {
  const [isOpen, setIsOpen] = useState(false);

  const handleSubmit = useCallback(
    (e: FormEvent<HTMLFormElement>) => {
      e.preventDefault();
      const form = e.currentTarget;
      const formData = new FormData(form);

      const card: Card = {
        id: `card-${Date.now()}`,
        title: formData.get("title") as string,
        description: formData.get("description") as string,
        assignee: formData.get("assignee") as string,
        priority: (formData.get("priority") as Card["priority"]) || "medium",
      };

      if (!card.title.trim()) return;
      onAdd(columnId, card);
      form.reset();
      setIsOpen(false);
    },
    [columnId, onAdd]
  );

  if (!isOpen) {
    return (
      <button onClick={() => setIsOpen(true)}>+ Add Card</button>
    );
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="title" placeholder="Title" required />
      <textarea name="description" placeholder="Description" />
      <input name="assignee" placeholder="Assignee" />
      <select name="priority" defaultValue="medium">
        <option value="low">Low</option>
        <option value="medium">Medium</option>
        <option value="high">High</option>
      </select>
      <button type="submit">Add</button>
      <button type="button" onClick={() => setIsOpen(false)}>Cancel</button>
    </form>
  );
}
```

## In Your Own Words

1. Why is normalized state (columns + cards separate) better than nested state for a Kanban-style app?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Normalized state keeps `columns` and `cards` as separate dictionaries. To update a card, just access `cards[cardId]` directly — O(1). To move a card, just update the `cardIds` arrays of both columns. With nested state, you need to traverse every column's array to find a card — O(n). Also, with normalized state, a card exists only once (in the `cards` object), while nested state might duplicate card data across arrays. This is the same approach recommended by Redux docs and libraries like `react-beautiful-dnd`.

</details>

2. For undo/redo, do you store the entire state or just the changed part in the past/future arrays?

<details>
<summary>Show Answer</summary>

**Sample Answer:** You store a complete state snapshot (columns, cards, columnOrder). Undo/redo only works reliably with a full snapshot — partial snapshots can corrupt state. But you don't store the entire store — only the parts affected by mutations. In this Kanban app, we snapshot `columns`, `cards`, and `columnOrder`. The `past` and `future` arrays are excluded from persistence via `partialize` — undo history is session-only, it resets on page refresh. The undo stack should not grow too large — 50-100 snapshots is sufficient.

</details>

3. What is the benefit of generic `<Card<T>>` and `<Column<T>>` components? Couldn't this work without generics?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Generic components enable reusability. If tomorrow you want to use Card for "Task Cards" or "Issue Cards" instead of Kanban cards, just call `<Card<Issue>>` with an `Issue`-specific `renderContent`. The component structure (draggable, memoized, dragStart) stays the same — only the data type changes. Without generics, you would either use `any` (losing type safety) or create a separate component for each type. Generics provide both type safety and reusability.

</details>

4. How does Zustand's selective subscription improve performance in the Kanban Board?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Selective subscription means each component only subscribes to the state it actually uses. For example, `Column` subscribes to `s.columns[colId].cardIds` — when a card's *content* changes (via `updateCard`), but `cardIds` doesn't change, the Column does not re-render. Only the specific `Card` whose data changed re-renders. Without this (like in Context API), the entire board would re-render on every change. With 100 cards on the board, selective subscription can be a 10x performance improvement.

</details>

5. The Kanban Board architecture has three layers — Store, Hooks, Components. What is each layer's responsibility, and how do they communicate?

<details>
<summary>Show Answer</summary>

**Sample Answer:** (1) **Store (Zustand)** — state management. Stores data, handles mutations (addCard, moveCard), handles persistence. It is the "source of truth." No UI logic. (2) **Hooks (Custom)** — business logic. Computed values (stats), data composition (getCardsInColumn), complex operations. Wraps the store, provides a component-friendly interface. (3) **Components (UI)** — rendering. Reads from store/hooks, calls actions on user interaction. No state mutation logic. Communication: Component → Store action → State changes → Components re-render (via selectors). The hook layer acts as a "middleman" that converts the store's raw data into a format that's easy for components to use.

</details>
