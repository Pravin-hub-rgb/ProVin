## Generics — Pehle Yeh Samjho

TypeScript generics ek din mein nahi aate, lekin basic concept simple hai.

**Problem:** Ek function jo kisi bhi type ka array leta ho aur uska first element return kare:

```ts
function first(arr: number[]): number {
  return arr[0];
}

const num = first([1, 2, 3]); // number — sahi hai
// const str = first(["a", "b"]); // ❌ Type error — string[] number[] nahi hai
```

Doosra function banana padega string ke liye:

```ts
function firstString(arr: string[]): string {
  return arr[0];
}
```

Aur har naye type ke liye naya function. Yeh to duplication ho gaya.

**Solution — Generics:**

```ts
function first<T>(arr: T[]): T {
  return arr[0];
}

const num = first<number>([1, 2, 3]); // number
const str = first<string>(["a", "b"]); // string
const bool = first<boolean>([true, false]); // boolean
```

`<T>` ek **type parameter** hai. Jaise function ka parameter (argument) value leta hai, waise hi generic type parameter **type leta hai**. Caller decide karta hai ki `T` kaunsa type hoga — number, string, boolean, ya koi custom interface.

TypeScript infer bhi kar sakta hai:

```ts
const str = first(["a", "b"]); // TypeScript automatically T = string infer karega
```

Visual mapping:

```
first<T>(arr: T[]): T
   │       │       │
   │       │       └── Return type same as T
   │       │
   │       └── Array of T
   │
   └── Type parameter — caller decide karega

Call: first<number>([1, 2, 3])
              │
              ▼
     first<number>(arr: number[]): number
```

Ab yeh concept custom hooks mein use karenge. Hooks jo kisi bhi data type ke saath kaam karein — aur TypeScript types automatically infer kare.

## useFetch<T> — Generic Data Fetching Hook

Yaad hai Batch 2 mein Recipe Finder mein kya likha tha? `useEffect` + `useState` triplets (data, loading, error) + try/catch/finally. Woh pattern har API call mein repeat hota hai. Ab ek generic hook banayenge jo **kisi bhi type** ka data fetch kare — aur loading/error states automatically handle kare.

### Step 1 — State Type Define Karein

Pehle sochte hain ki fetch operation ke kitne states hote hain:

1. **Idle** — abhi fetch shuru bhi nahi hua
2. **Loading** — fetch chal raha hai
3. **Success** — data aa gaya
4. **Error** — kuch gadbad hui

Ek type bana lo — `src/hooks/` folder mein `useFetch.ts` nayi file banao:

```ts
// src/hooks/useFetch.ts
type FetchState<T> = {
  data: T | null;
  isLoading: boolean;
  error: string | null;
};
```

`FetchState<T>` — generic hai. `T` ki jagah koi bhi type aa sakta hai — `Meal[]`, `string[]`, `Task[]`, kuch bhi.

### Step 2 — Hook Ka Skeleton

Isi file (`src/hooks/useFetch.ts`) mein ab hook add karte hain:

```ts
// src/hooks/useFetch.ts
import { useState, useEffect } from "react";

function useFetch<T>(url: string): FetchState<T> {
  const [data, setData] = useState<T | null>(null);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    // fetch logic yahan
  }, [url]);

  return { data, isLoading, error };
}
```

**Kya ho raha hai:**

| Line | Kya Hai |
|------|---------|
| `useFetch<T>` | Generic hook — caller batayega ki T kaunsa type hai |
| `url: string` | Fetch karne ka URL |
| `FetchState<T>` | Return type — same T type use karta hai |
| `useState<T \| null>` | Data ka type automatic T hoga |
| `useState<string \| null>` | Error string hamesha string type |

### Step 3 — Fetch Logic + Cleanup

Wahi file (`src/hooks/useFetch.ts`) continue karo — Step 2 ke skeleton mein fetch logic add karo:

```ts
// src/hooks/useFetch.ts
import { useState, useEffect } from "react";

function useFetch<T>(url: string): FetchState<T> {
  const [data, setData] = useState<T | null>(null);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    let ignore = false;

    async function fetchData() {
      setIsLoading(true);
      setError(null);

      try {
        const res = await fetch(url);
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const json = await res.json();
        if (!ignore) {
          setData(json as T);
        }
      } catch (err) {
        if (!ignore) {
          setError(err instanceof Error ? err.message : "Kuch gadbad hui");
        }
      } finally {
        if (!ignore) {
          setIsLoading(false);
        }
      }
    }

    fetchData();

    return () => {
      ignore = true;
    };
  }, [url]);

  return { data, isLoading, error };
}
```

**Important parts:**

| Cheez | Kyun |
|-------|------|
| `let ignore = false` | Race condition prevent — purane URL ka response reject karo |
| `res.ok` check | HTTP errors handle (404, 500) |
| `json as T` | TypeScript assertion — hume pata hai JSON ka type T hoga |
| `return () => { ignore = true }` | Cleanup — component unmount ya URL change pe |

**Flow — useFetch Call Ka Safer:**

```
Component render with url="https://api.example.com/meals"
    │
    ▼
useEffect trigger hota hai
    │
    ├── ignore = false
    ├── setIsLoading(true)      → isLoading = true
    ├── setError(null)           → error = null
    │
    ├── fetch(url) shuru
    │       │
    │       ├── Success → json as T → setData(json) → data = json
    │       └── Error → setError("message")         → error = "message"
    │
    └── finally → setIsLoading(false)               → isLoading = false
    │
    ▼
Component re-renders with { data, isLoading, error }
```

### Step 4 — useFetch Use Karte Hain

Ab is hook ko kisi component mein use karte hain. Naya component banao — `src/components/RecipeList.tsx` — aur `useFetch` ko `../hooks/useFetch` se import karo:

```tsx
// src/components/RecipeList.tsx
import { useState } from "react";
import { useFetch } from "../hooks/useFetch";

interface Meal {
  idMeal: string;
  strMeal: string;
  strMealThumb: string;
  strCategory: string;
}

function RecipeList() {
  const [query, setQuery] = useState("chicken");
  const { data: meals, isLoading, error } = useFetch<Meal[]>(
    `https://www.themealdb.com/api/json/v1/1/search.php?s=${query}`
  );

  if (isLoading) return <Spinner />;
  if (error) return <p className="text-red-500">{error}</p>;

  return (
    <div>
      {meals?.length === 0 ? (
        <p>Koi recipe nahi mili</p>
      ) : (
        meals?.map(meal => <RecipeCard key={meal.idMeal} meal={meal} />)
      )}
    </div>
  );
}
```

Notice kiya? Koi `useEffect` nahi, koi `try/catch` nahi, koi `useState` triplets nahi. Sirf ek line — `useFetch<Meal[]>(url)` — aur poora fetch logic handle ho gaya. Clean, readable, reusable.

**TypeScript ka magic:** `meals` ka type automatic `Meal[] | null` hai. `isLoading` ka type `boolean` hai. Sab kuch type-safe hai. Koi manual type annotation nahi chahiye.

## useLocalStorage<T> — Generic LocalStorage Hook

Wahi pattern localStorage ke saath. Batch 2 ke To-Do app mein dekha tha — `useState` + `JSON.parse` + `useEffect` + `JSON.stringify`. Har component mein repeat.

### Step 1 — Basic Version

Nayi file banao — `src/hooks/useLocalStorage.ts`:

```ts
// src/hooks/useLocalStorage.ts
import { useState, useEffect } from "react";

function useLocalStorage<T>(key: string, initialValue: T) {
  const [storedValue, setStoredValue] = useState<T>(() => {
    try {
      const item = localStorage.getItem(key);
      return item ? (JSON.parse(item) as T) : initialValue;
    } catch {
      return initialValue;
    }
  });

  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(storedValue));
    } catch (err) {
      console.error("localStorage set nahi kar paya:", err);
    }
  }, [key, storedValue]);

  return [storedValue, setStoredValue] as const;
}
```

**Kya ho raha hai:**

| Line | Kya Hai |
|------|---------|
| `useLocalStorage<T>(key, initialValue)` | Generic — T koi bhi type |
| `useState<T>(() => { ... })` | Lazy initializer — sirf ek baar chalega |
| `localStorage.getItem(key)` | Saved value read karo |
| `JSON.parse(item) as T` | String ko parse karo aur type cast karo |
| `try/catch` | Agar localStorage corrupt hai toh initialValue do |
| `useEffect(() => { localStorage.setItem(key, JSON.stringify(storedValue)) }, [key, storedValue])` | Jab bhi storedValue change ho, localStorage update karo |
| `return [storedValue, setStoredValue] as const` | Wahi interface jaise `useState` — familiar pattern |

**Agar custom hook nahi hota toh kya hota:**

```tsx
const [tasks, setTasks] = useState<Task[]>(() => {
  const saved = localStorage.getItem("tasks");
  return saved ? JSON.parse(saved) : [];
});

useEffect(() => {
  localStorage.setItem("tasks", JSON.stringify(tasks));
}, [tasks]);
```

Har localStorage feature ke liye yahi code repeat karna padta. `useLocalStorage<T>` se ek line kaam ho gaya.

### Step 2 — Ab To-Do App Mein Use Karte Hain

Naya component banao — `src/components/TodoApp.tsx` — aur `useLocalStorage` ko `../hooks/useLocalStorage` se import karo:

```tsx
// src/components/TodoApp.tsx
import { useLocalStorage } from "../hooks/useLocalStorage";

function TodoApp() {
  const [tasks, setTasks] = useLocalStorage<Task[]>("tasks", []);

  function addTask(text: string) {
    const newTask: Task = {
      id: Date.now(),
      text,
      completed: false,
    };
    setTasks([...tasks, newTask]);
    // localStorage automatically update ho gaya — koi useEffect nahi!
  }

  return (
    <div>
      <TaskInput onAdd={addTask} />
      <TaskList tasks={tasks} onToggle={...} onDelete={...} />
    </div>
  );
}
```

Notice kiya? Koi `localStorage.getItem`, koi `JSON.parse`, koi `useEffect` sync — sab kuch hook handle kar raha hai. Component sirf apne state ke saath kaam karta hai, jaise normal `useState` ho.

### Flow — useLocalStorage Ka Safer:

```
Component render
    │
    ├── Pehli baar: localStorage.getItem("tasks") → null
    │   └── useState lazy init → initialValue [] return
    │
    ├── Doosra render (state change): storedValue update
    │   └── useEffect → localStorage.setItem("tasks", JSON.stringify(newValue))
    │
    ├── Page refresh: localStorage.getItem("tasks") → "[...]"
    │   └── useState lazy init → JSON.parse → parsed value return
    │
    └── LocalStorage corrupt hai:
        └── try/catch → initialValue return
```

### useLocalStorage vs useState

| Feature | `useState` | `useLocalStorage` |
|---------|-----------|-------------------|
| Persistence | Re-render tak | Browser tab close ke baad bhi |
| Syntax | `const [v, setV] = useState(initial)` | `const [v, setV] = useLocalStorage(key, initial)` |
| Type-safe | Haan | Haan (generic hai) |
| JSON parse/sync | Manual karna padega | Automatic |
| Error handling | N/A | try/catch built-in |

## Combining Generics — useFetch + useLocalStorage Ek Saath

Yeh dono hooks ab har component mein use kar sakte ho. TypeScript automatically types infer karega. Example — ek component jo data fetch kare aur localStorage mein cache kare. Naya component banao — `src/components/Dashboard.tsx` — aur dono hooks import karo:

```tsx
// src/components/Dashboard.tsx
import { useFetch } from "../hooks/useFetch";
import { useLocalStorage } from "../hooks/useLocalStorage";

function Dashboard() {
  const { data, isLoading } = useFetch<DashboardData>("/api/dashboard");
  const [preferences, setPreferences] = useLocalStorage<Preferences>("dashboard-prefs", {
    theme: "dark",
    widgets: ["stats", "chart"],
  });

  if (isLoading) return <Spinner />;

  return (
    <div className={preferences.theme}>
      <WidgetSelector
        selected={preferences.widgets}
        onChange={setPreferences}
      />
      {/* Dashboard content */}
    </div>
  );
}
```

Dono hooks ek saath — ek URL se data fetch kar raha hai (generic type `DashboardData`), doosra user preferences localStorage mein save kar raha hai (generic type `Preferences`). Koi manual type annotation nahi, TypeScript automatically infer kar raha hai.

## Generic Hooks Mein Common Patterns

### 1. Return Type Always Include Loading/Error States

Fetch hook ka return type hamesha teen states include kare:

```ts
type FetchState<T> = {
  data: T | null;
  isLoading: boolean;
  error: string | null;
};
```

Is pattern ko "tri-state" pattern kehte hain. Har fetch operation ke yeh teen states hote hain. Hook inhe consistently handle karta hai.

### 2. useReducer Version for Complex State

Zyaada control chahiye toh `useReducer` use kar sakte ho andar:

```ts
type Action<T> =
  | { type: "loading" }
  | { type: "success"; payload: T }
  | { type: "error"; payload: string };

function fetchReducer<T>(state: FetchState<T>, action: Action<T>): FetchState<T> {
  switch (action.type) {
    case "loading": return { ...state, isLoading: true, error: null };
    case "success": return { data: action.payload, isLoading: false, error: null };
    case "error": return { ...state, isLoading: false, error: action.payload };
  }
}
```

Yeh pattern 5.5 (useReducer) mein seekha tha — discriminated union actions + reducer. Complex hooks mein useful hai.

### 3. AbortController for Advanced Cleanup

`ignore` flag kaafi hai simple cases ke liye. Advanced cleanup ke liye `AbortController` use kar sakte ho:

```ts
useEffect(() => {
  const controller = new AbortController();

  async function fetchData() {
    try {
      const res = await fetch(url, { signal: controller.signal });
      // ...
    } catch (err) {
      if (err instanceof DOMException && err.name === "AbortError") return;
      // handle error
    }
  }

  fetchData();
  return () => controller.abort();
}, [url]);
```

`AbortController` fetch request ko actually cancel kar deta hai (network level pe), jabki `ignore` flag sirf response ignore karta hai. Performance ke liye AbortController better hai.

## What useFetch Is NOT

- **Not a caching solution:** Har component mount / URL change pe fetch karega. Caching ke liye TanStack Query use karo (Batch 2.3 mein seekha tha).
- **Not an infinite retry solution:** Error pe retry nahi karta. TanStack Query mein built-in retry hai.
- **Not a mutation solution:** POST/PUT/DELETE ke liye nahi hai. Mutation ke liye alag approach chahiye.

`useFetch` simple hai — data fetch karo, loading/error handle karo. Complex features ke liye dedicated libraries use karo.

## So Here's the Takeaway

Generics ne custom hooks ko aur powerful bana diya. `useFetch<T>` kisi bhi type ka data fetch kar sakta hai, `useLocalStorage<T>` kisi bhi type ko localStorage mein persist kar sakta hai. TypeScript automatic type inference se developer experience bhout smooth ho jaati hai.

Ab agle topic mein ek mini-project karenge — Recipe Finder ko refactor karenge, wahan ke manual fetch logic ko `useFetch<Meal[]>` aur `useLocalStorage<Meal[]>` se replace karenge. Asli fark tab pata chalega jab tum purana aur naya code side-by-side dekhoge.

## In Your Own Words

1. TypeScript generics ka custom hook mein kya fayda hai? Bina generics ke hook kaise limited hota hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Generics ke bina custom hook sirf ek specific type ke saath kaam karega. Jaise `useFetch` sirf `Meal[]` ke liye kaam karega, `string[]` ke liye naya hook chahiye. Generics se hook caller decide karta hai ki kaunsa type use karna hai — `useFetch<Meal[]>` ya `useFetch<Task[]>` ya `useFetch<string>`. TypeScript automatic type inference karta hai, isliye caller ko bhi type specify karne ki zaroorat nahi hoti — bas hook call karo, types apne aap set ho jaate hain.

</details>

2. `useFetch` mein `ignore` flag kyun use kiya? Bina iske kya problem ho sakti hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `ignore` flag race condition prevent karta hai. Imagine — user fast-fast type kar raha hai search bar mein. Har character pe naya URL generate hota hai, naya fetch shuru hota hai. Agar purana fetch response doosre fetch ke baad aaye, toh woh galat data set kar dega (yaani pehle wale query ka result baad mein render ho jayega). `ignore` flag ensure karta hai ki jab naya URL aaye (effect re-run), toh purane effect ka response ignore ho jaaye. Agar `ignore` nahi hota, toh fast typing pe flickering aur galat data dikh sakta hai.

</details>

3. `useLocalStorage` mein `useState` lazy initializer kyun use kiya? Seedha `useState(localStorage.getItem(key))` kyun nahi likha?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Lazy initializer (`() => { ... }`) sirf ek baar chalega — pehli render pe. Isme `localStorage.getItem()` call efficient hai kyunki sirf ek baar local storage read hoga. Agar seedha `useState(localStorage.getItem(key))` likhte, toh har render pe `localStorage.getItem()` call hota (chahe React us value ko ignore kare), jo performance ke liye waste hai. Lazy initializer ensure karta hai ki expensive operation (localStorage read) sirf tab chale jab zaroorat ho — pehli render pe.

</details>

4. `useFetch` ko mutation (POST/PUT/DELETE) ke liye kyun use nahi karna chahiye?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `useFetch` effect ke andar fetch karta hai, jo component mount ya URL change pe trigger hota hai. Mutation (POST/PUT/DELETE) user interaction ke response mein chalta hai — button click pe, form submit pe. Mutation ke liye alag hook chahiye jo `mutate` function return kare, jise caller manually invoke kar sake. Simple `useFetch` sirf GET requests ke liye design kiya gaya hai jo automatic trigger hote hain. Mutation ke liye TanStack Query ka `useMutation` use karna chahiye.

</details>

5. `useLocalStorage<T>` aur `useState<T>` mein kya fark hai? Kaunsa kab use karna chahiye?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `useState` component ke lifecycle tak state rakhta hai — page refresh pe reset ho jaata hai. `useLocalStorage` state ko localStorage mein persist karta hai — page refresh ke baad bhi wahi value milti hai. `useLocalStorage` use karo jab data browser close/refresh ke baad bhi rehna chahiye — user preferences, saved items, draft data. `useState` use karo jab data sirf current session ke liye hai — form input values, temporary UI state, toggle states. Syntax almost same hai (isliye upgrade easy hai), lekin localStorage ka IO cost hai toh bhout frequent updates (har character pe) ke liye `useState` better hai, `useLocalStorage` sirf tab sync kare jab meaningful data ready ho.

</details>
