### 46. What are Custom Hooks?

**Answer:** Functions prefixed with `use` that compose built-in hooks into reusable stateful logic — `useFetch`, `useLocalStorage`. They share logic **without changing the component hierarchy**, replacing HOCs and render props as the default pattern.

**Likely follow-up:** *What rules apply?* — must start with `use`, can call other hooks, cannot be called conditionally (Rules of Hooks — Q47).

---

### 47. What are the Rules of Hooks?

**Answer:** (1) Only call Hooks at the top level — never inside loops, conditions or nested functions. (2) Only from React function components or custom Hooks. React tracks hooks by **call order**, so a changing order matches state to the wrong hook — subtle, hard-to-debug bugs.

**Likely follow-up:** *What if you need conditional logic?* — move the condition inside the hook: `useEffect(() => { if (shouldShow) {...} }, [shouldShow])`.

### 51. When should you use Context API vs Redux/Zustand?

**Answer:** Context for simple, rarely-changing global data (theme, auth user, locale). For frequent updates, complex state logic or a need for devtools/middleware/persistence, use a store — Context re-renders **all** consumers on any change; libraries give selective subscriptions.

**Likely follow-up:** *Concrete split?* — theme = Context; shopping cart with frequent updates + devtools = Zustand/Redux.

---

### 56. Props drilling vs Context vs global state library — when to use what?

**Answer:** 2–3 levels of plain prop passing is fine (and clearest). Deeper or cross-cutting concerns → Context. App-wide complex state needing devtools, middleware or persistence → a library like Redux/Zustand. Don't reach for a store before you've felt the pain.

**Likely follow-up:** *What signals you've crossed the line?* — the same prop passing through 4+ components nobody uses, or Context updates re-rendering the app on every keystroke.

---

### 58. What are the top three ways to achieve state management in React — and when to use what?

**Answer:** `useState` for small component-local state; Context API for sharing medium-complexity global data without drilling; Redux (or Zustand) for large-scale apps with complex, frequently-changing state. Rule of thumb: third-party tools only for complex scenarios — don't over-engineer.

**Likely follow-up:** *Where does server state fit?* — none of the three; that's TanStack Query's job (caching, refetch) — client vs server state are different problems.

---

### 57. How do lightweight state managers like Zustand or Jotai differ from Redux?

**Answer:** Less boilerplate, no mandatory Provider (Zustand), atomic state model (Jotai), simpler API and selective subscriptions. By 2026 they're popular even in large apps because they skip Redux's ceremony while keeping devtools support.

**Likely follow-up:** *When does full Redux still win?* — strict conventions across a big team, rich middleware ecosystem, RTK Query — that's why Batch 6.7 exists.

### 32. What is a Higher-Order Component (HOC)?

**Answer:** A function that takes a component and returns an enhanced component — the `withAuth(Component)` pattern. It was the standard way to reuse logic; **custom hooks have replaced it** in almost all cases (no wrapper-nesting, better TypeScript, no prop-name collisions).

**Likely follow-up:** *Any downside to HOCs?* — nested wrappers, unclear component trees (`displayName` issues), ref forwarding requirements, silently overwritten props.

---

### 33. What is the Render Props pattern?

**Answer:** A component exposes its logic through a function prop that returns JSX — `<DataProvider render={data => <UI data={data} />} />`. An alternative to HOCs; custom hooks are usually cleaner now, but children-as-function still has its place for render-time data.

**Likely follow-up:** *vs a custom hook?* — the hook reuses **logic** without touching the tree; render props control **what gets rendered** — often you use both (`const data = useData()` inside a render-prop component).

---

### 93. What is the Compound Components pattern?

**Answer:** Multiple components working together with shared implicit state — `<Select><Select.Option /></Select>`, `<Tabs><Tabs.List/><Tabs.Panel/></Tabs>` — usually communicating through Context, giving a flexible, composable API where the parent controls structure and children control behavior.

**Likely follow-up:** *vs passing callbacks for everything?* — compound components keep shared state (selected option, open tab) internal instead of forcing the user to wire every child manually.

---

### 94. What is the Container/Presentational pattern?

**Answer:** Container components own logic and data; presentational components render UI from props. Less strictly enforced since hooks (you can colocate state), but the underlying idea — separating data concerns from rendering — still keeps UIs predictable and reusable.

**Likely follow-up:** *Is it obsolete?* — the rigid split is; the practice lives on as "smart vs dumb" file organization and in storybook-driven presentational components.

---

### 71. What is `forwardRef` for?

**Answer:** Lets a parent reach a child's DOM node when the child is a custom component — `React.forwardRef((props, ref) => <input ref={ref} ... />)`. Without it, `ref` on a custom component doesn't pass through.

**Likely follow-up:** *React 19 change?* — `ref` is now passed as a regular prop; `forwardRef` still works but is no longer needed for function components.

---

### 72. What does `useImperativeHandle` do?

**Answer:** Used with `forwardRef` to expose only specific methods through the ref instead of the whole DOM node — a controlled "imperative API" (e.g. exposing `.focus()` but hiding everything else).

**Likely follow-up:** *Why limit the surface?* — encapsulation; the parent gets exactly the operations you allow, and internals can change freely.

---

### 116. Context vs Hooks vs Classes — what's the future?

**Answer:** **Hooks are the standard** — modern React is function components + hooks. Context is for *sharing values* and composes with hooks (not an old-vs-new axis). Classes remain only for legacy codebases and Error Boundaries, which have no hook equivalent yet.

**Likely follow-up:** *Will error boundaries ever get a hook?* — as of React 19, no; class boundaries stay, and that's the honest answer to give.
