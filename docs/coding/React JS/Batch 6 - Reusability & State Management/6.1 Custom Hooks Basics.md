## Problem — Duplicate Logic Across Components

React ke built-in hooks (`useState`, `useEffect`, `useRef`) bhout powerful hain. Lekin woh **generic** hain — kisi specific use-case ke liye nahi bane. Har component mein wohi logic baar-baar likhni padti hai.

Real example. Batao... Batch 2 mein Recipe Finder banaya tha:

```tsx
function RecipeFinder() {
  const [recipes, setRecipes] = useState<Meal[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState("");

  async function fetchRecipes(query: string) {
    setIsLoading(true);
    setError("");
    try {
      const res = await fetch(`https://www.themealdb.com/api/json/v1/1/search.php?s=${query}`);
      const data = await res.json();
      setRecipes(data.meals ?? []);
    } catch {
      setError("Kuch gadbad hui");
    } finally {
      setIsLoading(false);
    }
  }

  // ... UI
}
```

Aur Batch 2 ke To-Do App v2 mein **wahi pattern** — loading, error, data states, try/catch/finally:

```tsx
function ToDoApp() {
  const [categories, setCategories] = useState<string[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState("");

  useEffect(() => {
    setIsLoading(true);
    fetch("/api/categories")
      .then(res => res.json())
      .then(data => {
        setCategories(data.categories);
        setIsLoading(false);
      })
      .catch(() => {
        setError("Failed to load categories");
        setIsLoading(false);
      });
  }, []);
}
```

Notice kiya? **Teen states** — `data`, `isLoading`, `error` — plus ek `fetch` call. Yeh pattern har app mein repeat hota hai. Ek hi app mein bhi multiple jagah ho sakta hai. Code duplicate ho raha hai.

**Ek aur example** — localStorage. To-Do app mein tasks save karne ke liye localStorage use karte hain:

```tsx
const [tasks, setTasks] = useState<Task[]>(() => {
  const saved = localStorage.getItem("tasks");
  return saved ? JSON.parse(saved) : [];
});

useEffect(() => {
  localStorage.setItem("tasks", JSON.stringify(tasks));
}, [tasks]);
```

Yeh code bhi har project mein repeat hota hai. Sirf key name aur data type badalta hai.

**Yeh problem kyun hai?** React bhout flexible hai — koi bhi pattern follow kar sakte ho. Lekin yeh flexibility ek problem bhi create karti hai: "jaisa man karega waisa likho" approach se code inconsistent ho jaata hai, debugging mushkil hoti hai, aur naye developer ko samajhne mein time lagta hai.

### Ek Aur Example — Common Patterns

Kai baar components mein common patterns hote hain jo kisi specific hook se directly support nahi hote:

1. **Toggle** — ek boolean state jisko flip karna ho (dark mode, modal, accordion)
2. **Document Title** — component mount hone pe title change karna
3. **Previous Value** — kisi prop/state ki previous value track karna
4. **Boolean Operations** — true/set/false/toggle sab ek saath

Yeh sab cheezein baar-baar likhni padti hain. Har baar wahi `useState`, wahi function definitions. Code bhout repetitive ho jaata hai.

Agar tum ek recipe app bana rahe ho jisme 5 components alag-alag API calls kar rahe hain, toh har component mein wahi `useState` triplets (data, loading, error) plus try/catch/finally plus cleanup logic. Code 3x ho jaata hai unnecessarily.

Dekhte hain kaise solve karte hain...

## Custom Hook — Kya Hai

**Custom hook ek JavaScript function hai jo React hooks use karta hai.** Aur kuch nahi. Bas ek function jiska naam `use` se shuru hota hai aur jo andar se `useState`, `useEffect`, `useRef`, ya koi aur hook call karta hai.

Haan, itna simple hai.

React ki documentation kehti hai ki "custom hooks let you extract component logic into reusable functions." Matlab — component logic (jo hooks use karta hai) ko alag function mein nikaal kar doosre components mein reuse karna.

Toh woh duplicate logic jo upar dikhai — usse ek custom hook mein nikaal kar, har jagah woh hook call kar sakte ho. Ek baar likho, har jagah use karo.

Syntax:

```ts
function useHookName() {
  // React hooks yahan use kar sakte ho
  // kuch value ya array ya object return karo
  return something;
}
```

Bus itna. Koi magic nahi, koi special API nahi. Sirf ek function convention.

**Kyun `use` se start karna hai?** React ka rule hai — hooks ke naam `use` se shuru hone chahiye. Isse React ko pata chalta hai ki yeh function hooks use karta hai, aur React apne internal rules enforce kar sakta hai (jaise — hooks conditional nahi hone chahiye). Yeh sirf convention nahi hai — **lint rule enforce karta hai**. Agar kisi custom hook ka naam `use` se shuru nahi hua aur usme `useState` call kiya, toh ESLint error dega.

Visual mapping:

```
Component A            Component B
    │                      │
    ├── useToggle() ───────┤
    │                      │
    ▼                      ▼
[value, toggle]      [value, toggle]
      │                      │
   (A ka apna           (B ka apna
    state, alag)          state, alag)
```

Aur yeh ek bhout important cheez hai jo beginners galat samajhte hain:

**What It Is NOT:** Custom hook component ke beech **state share nahi karta**. Har component jo custom hook call karta hai, usko **apni alag state** milti hai. Custom hook logic share karta hai, state nahi. State share karni ho toh Context ya Zustand jaisi cheezein use karni padti hain (6.4 mein dekhenge). Custom hook sirf woh logic nikaalta hai jo baar-baar likhna padta hai — jaise toggle ka logic, fetch ka logic, localStorage ka logic.

## Pehla Custom Hook — useToggle (Mini Project)

Sabse simple possible custom hook. Ek boolean state jisko "flip" karna hai. Isse ek **Accordion** (expand/collapse) component banayenge. Poore project ko ek saath nahi dikha rahe — **step by step, har code block ke saath file path** kiye hue.

Pehle ek cheez samjhenge — **hooks array kyun return karte hain** (Step 2). Kyunki yehi woh chiz hai jo `as const` ki zaroorat banati hai — aur useToggle banate waqt wahi problem generate hogi (Step 3), wahi solution lagega.

### Step 1 — Project Setup

Pehle ek naya Vite + React + TypeScript project banao:

```
bun create vite@latest custom-hooks-demo --template react-ts
cd custom-hooks-demo
bun install
bun run dev
```

Humein 3 files chahiye hongi:

```
src/
├── hooks/              ← custom hooks yahan rakhenge
│   └── useToggle.ts
├── components/         ← components yahan rakhenge
│   ├── Accordion.tsx
│   └── ModalExample.tsx
└── App.tsx             ← sab yahan import karke render karenge
```

> **Note:** Vite ka default structure `src/App.tsx` aur `src/main.tsx` hota hai. `hooks/` aur `components/` folders ko apne aap **banana** padta hai. Convention yeh hai — custom hooks `hooks/` mein, reusable components `components/` mein.

### Step 2 — Hooks Array Kyun Return Karte Hain

Hook banane se pehle yeh samjho. **Familiar start karo** — tumne `useState` itni baar use kiya hai:

```tsx
const [count, setCount] = useState(0);
```

Dekh rahe ho? `useState` ek **array** return karta hai jisme pehli position pe value hai (`count`), doosri pe setter function (`setCount`). Destructuring se hum dono ko naam de dete hain. Yeh array jisme har position ka **fixed type** hota hai — `[number, function]` — TypeScript mein isko **tuple** kehte hain.

Batch 1 mein seekha tha — tuple matlab "fixed length, har position pe alag type". Normal array `string[]` jaisa hota hai (sab same type, koi bhi length). Tuple `[string, number]` jaisa — pehli position string, doosri number.

Yeh tuple pattern React mein convention hai — custom hooks bhi isi tarah kaam karte hain: pehli position state, doosri functions. Isliye `useToggle` bhi array return karega. Ab chalte hain Step 3 mein — wahi dekhenge ki aisa karne pe **problem kyun generate hoti hai aur `as const` kaise solve karta hai.**

### Step 3 — Hook Banao: src/hooks/useToggle.ts

Sabse pehle custom hook file banate hain — lekin **intentionally galat** (bina `as const`), taaki problem khud dikhe:

```ts
// src/hooks/useToggle.ts
// ❌ Galat — TypeScript ko tuple ka pata nahi
import { useState } from "react";

export function useToggle(initial = false) {
  const [value, setValue] = useState(initial);
  const toggle = () => setValue(v => !v);
  return [value, toggle];  // ❌ as const nahi lagaya
}
```

Ab component mein use karo — Step 4 mein yehi Accordion banayenge, lekin error pehle dikha deta hoon:

```tsx
// src/components/Accordion.tsx
// ❌ Error aayega
import { useToggle } from "../hooks/useToggle";

export function Accordion() {
  const [isOpen, toggleOpen] = useToggle(false);

  return (
    <div>
      <button onClick={toggleOpen}>  {/* ❌ Error yahan */}
        {isOpen ? "Close" : "Open"} Details
      </button>
      {isOpen && <p>Yeh hidden tha, ab dikh raha hai.</p>}
    </div>
  );
}
```

Error:

```
Type 'boolean | (() => void)' is not assignable to type 'MouseEventHandler<HTMLButtonElement> | undefined'.
  Type 'boolean' is not assignable to type 'MouseEventHandler<HTMLButtonElement>'.
```

**Error samjho — array vs tuple inference:**

Bina `as const` ke, TypeScript `[value, toggle]` ko ek **normal array** maanta hai. Normal array ka matlab: koi bhi length, har element `boolean` **ya** function. Iska type hai:

```
(boolean | (() => void))[]
```

Iska matlab ek **mixed box** — andar jo chahiye bharo, nikalte waqt pata nahi kya milega.

Ab jab component destructure karta hai:

```tsx
const [isOpen, toggleOpen] = useToggle(false);
```

TypeScript box se nikal ke **dono** variables ko union type de deta hai — `isOpen` bhi `boolean | (() => void)`, `toggleOpen` bhi `boolean | (() => void)`. Toh `toggleOpen` ke paas TypeScript ke hisaab se boolean hone ka bhi chance hai! Aur boolean ko `onClick` (jo sirf function leta hai) pe pass karoge toh — **error**.

**Analogies se samjho:**

- **Normal array** = ek mixed box. Andar sab kuch mila-jula hai. Nikalte waqt pata nahi — yeh number niklega ya string.
- **Tuple** = train ki reserved seats. Seat 0 pe hamesha boolean baithi hai, seat 1 pe hamesha function. Tumhe pata hai kaunsa seat se kya milega.

**Fix — `as const` lagao:**

```ts
// src/hooks/useToggle.ts
// ✅ Sahi — as const lagaya
import { useState } from "react";

export function useToggle(initial = false) {
  const [value, setValue] = useState(initial);
  const toggle = () => setValue(v => !v);
  return [value, toggle] as const;
}
```

`as const` TypeScript ko batata hai: "yeh mixed box nahi hai, yeh **fixed tuple** hai — position 0 always `boolean`, position 1 always `() => void`." Ab destructure pe:

- `isOpen: boolean` ✅
- `toggleOpen: () => void` ✅

Error gayab. `onClick` ko ab guaranteed function mil raha hai.

| Code | TypeScript Kya Samajhta Hai |
|------|----------------------------|
| `return [value, toggle]` | `(boolean \| (() => void))[]` — mixed box, har element kuch bhi |
| `return [value, toggle] as const` | `readonly [boolean, () => void]` — fixed tuple, position-wise exact types |

**Ek sawaal aa sakta hai — `useState` toh bina `as const` chal jaata hai, humein kyun lagana pad raha hai?**

Kyunki `useState` ka return type **React team ne khud declare kiya** hai. TypeScript ke types mein likha hai ki `useState` returns `[S, Dispatch<SetStateAction<S>>]` — ek tuple. React ke types dekh ke TypeScript ko sab pata hai.

Lekin `useToggle` **hamara** function hai. TypeScript ko tumhara intent nahi pata — usne `[value, toggle]` ko normal array maan liya. Isliye hume khud batana padta hai ki "yeh tuple hai" — `as const` laga ke. Jab tum koi custom hook likho jo array return kare, hamesha `as const` lagao.

**Dekhte hain final hook mein kya ho raha hai:**

| Line | Kya Hai |
|------|---------|
| `useState(initial)` | Default value `false` (ya jo tum do) |
| `toggle = () => setValue(v => !v)` | Purani value lo, ulta karo (true -> false, false -> true) |
| `return [value, toggle] as const` | Array return — value aur toggle function |
| `as const` | TypeScript ko batata hai ki yeh exact tuple hai, `(boolean \| (() => void))[]` nahi |

**Flow — Jab Koi Component useToggle Call Karega:**

```
Component render
    │
    ▼
useToggle(false) — pehli baar call
    │
    ├── useState(false) → value = false
    ├── toggle = () => setValue(v => !v)
    │
    ▼
return [false, toggle]
    │
    ▼
Component mein: const [isOpen, toggleOpen] = useToggle()
                    │              │
                    ▼              ▼
                  false          toggle()
                                    │
                            click → toggleOpen()
                                    │
                                    ▼
                            useToggle dubara call
                                    │
                            value becomes !false = true
                                    │
                                    ▼
                            [true, toggle] return
                                    │
                                    ▼
                            Component re-renders
```

## Doosra Custom Hook — useDocumentTitle

Browser tab ka title change karna. Koi complex baat nahi — bas `useEffect` ka wrapper.

Problem: har component mein `useEffect` + `document.title` likhna padta hai. Teen jagah same code. Ek custom hook bana lo.

Minimal code:

```ts
// src/hooks/useDocumentTitle.ts
import { useEffect } from "react";

export function useDocumentTitle(title: string) {
  useEffect(() => {
    document.title = title;
  }, [title]);
}
```

**Kya ho raha hai:**

| Line | Kya Hai |
|------|---------|
| `title: string` | Jo bhi title set karna hai |
| `useEffect(() => { document.title = title }, [title])` | Jab `title` change ho, tab title update karo |
| **Return?** | Kuch nahi — yeh hook koi value return nahi karta, sirf side effect karta hai |

Hook return kuch nahi kar raha — sirf kaam kar raha hai. Custom hooks mein return zaroori nahi.

Use:

```tsx
// src/components/ProfilePage.tsx
import { useDocumentTitle } from "../hooks/useDocumentTitle";

export function ProfilePage({ username }: { username: string }) {
  useDocumentTitle(`${username}'s Profile`);

  return <div>...</div>;
}
```

```tsx
// src/components/SettingsPage.tsx
import { useDocumentTitle } from "../hooks/useDocumentTitle";

export function SettingsPage() {
  useDocumentTitle("Settings");

  return <div>...</div>;
}
```

Har page apna title set kar raha hai, lekin implementation ek hi jagah — `useDocumentTitle`. Koi `useEffect` nahi dikh raha components mein. Clean.

**Agar custom hook nahi hota toh:**

```tsx
function ProfilePage() {
  useEffect(() => {
    document.title = `${username}'s Profile`;
  }, [username]);
  // ...
}

function SettingsPage() {
  useEffect(() => {
    document.title = "Settings";
  }, []);
  // ...
}
```

Same `useEffect` pattern baar-baar. Custom hook ne **intention ko clear kar diya** — "title set karo" sirf ek line mein. `useEffect` ka implementation detail ab component se hidden hai.

## Teesra Custom Hook — usePrevious

React mein kabhi kabhi zaroorat hoti hai kisi value ki **previous** value ki. Jaise — "count 5 se 6 hua, lekin pehle kya tha?" React built-in hook nahi hai iske liye.

Solution? Custom hook:

```ts
// src/hooks/usePrevious.ts
import { useRef, useEffect } from "react";

export function usePrevious<T>(value: T): T | undefined {
  const ref = useRef<T>();

  useEffect(() => {
    ref.current = value;
  }, [value]);

  return ref.current;
}
```

**Kya ho raha hai:**

| Line | Kya Hai |
|------|---------|
| `<T>` | Generic type — koi bhi type ho sakta hai (number, string, object) |
| `useRef<T>()` | Ek ref jisme previous value store karenge |
| `useEffect(() => { ref.current = value }, [value])` | Har render ke **baad** ref mein current value save karo |
| `return ref.current` | **Current render mein** ref mein abhi bhi **pichli** value hai (kyun effect render ke baad chalta hai) |

**Flow samjho:**

```
Pehla Render: value = 5
    │
    ├── ref.current = undefined (initial)
    ├── return undefined
    │
    ▼
    useEffect chalega → ref.current = 5
    │
    ▼
Doosra Render: value = 6
    │
    ├── ref.current = 5 (abhi tak update nahi hua)
    ├── return 5 ← yeh previous value hai!
    │
    ▼
    useEffect chalega → ref.current = 6
    │
    ▼
Teesra Render: value = 10
    │
    ├── ref.current = 6
    ├── return 6 ← previous value!
```

Notice kiya? `useEffect` render ke baad chalta hai, isliye jab hum `ref.current` return karte hain, us waqt ref mein **pichli render ki value** hoti hai. Current render ki value abhi ref mein nahi gayi — woh effect ke time jayegi.

Use:

```tsx
// src/components/Counter.tsx
import { useState } from "react";
import { usePrevious } from "../hooks/usePrevious";

export function Counter() {
  const [count, setCount] = useState(0);
  const prevCount = usePrevious(count);

  return (
    <div>
      <p>Abhi: {count}</p>
      <p>Pehle: {prevCount ?? "—"}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
    </div>
  );
}
```

Har click pe "Abhi" current count dikhayega, "Pehle" previous count dikhayega. Without `usePrevious`, yeh karna tha — `useEffect` + `useRef` ka wahi pattern. Ab ek line.

## Chautha Custom Hook — useBoolean

Kai baar simple toggle kaafi nahi hota. Kuch cheezein chahiye hoti hain — `setTrue`, `setFalse`, `toggle`, `reset`. Jaise modal, confirmation dialog, tooltip.

`useToggle` ne sirf flip karna sikhaaya. `useBoolean` aur operations dega:

```ts
// src/hooks/useBoolean.ts
import { useState, useCallback } from "react";

export function useBoolean(initial = false) {
  const [value, setValue] = useState(initial);

  const setTrue = useCallback(() => setValue(true), []);
  const setFalse = useCallback(() => setValue(false), []);
  const toggle = useCallback(() => setValue(v => !v), []);
  const reset = useCallback(() => setValue(initial), [initial]);

  return { value, setTrue, setFalse, toggle, reset };
}
```

Notice `useCallback` use kiya hai — har render pe naye function references na bane. Performance ke liye important hai (Batch 5 mein seekha tha).

Use:

```tsx
// src/components/ConfirmationDialog.tsx
import { useBoolean } from "../hooks/useBoolean";

export function ConfirmationDialog() {
  const { value: isOpen, setTrue: open, setFalse: close } = useBoolean(false);

  return (
    <div>
      <button onClick={open}>Delete Item</button>
      {isOpen && (
        <div className="dialog">
          <p>Sure?</p>
          <button onClick={close}>Cancel</button>
          <button onClick={() => { /* delete */ close(); }}>Delete</button>
        </div>
      )}
    </div>
  );
}
```

Naam dekh ke pata chal raha hai — `open` modal kholta hai, `close` band karta hai. Code readable hai. Aur agar reset karna ho (jaise form submit ke baad initial state pe jaana), `reset` bhi hai.

## Rules of Custom Hooks

Custom hooks bhi React hooks hain — toh **Rules of Hooks** yahan bhi apply hote hain:

| Rule | Matlab |
|------|--------|
| **Top-level call** | Hook loops, conditions, ya nested functions ke andar call nahi kar sakte |
| **Only in React functions** | Hook sirf React function components ya custom hooks mein call kar sakte ho |
| **`use` prefix** | Custom hook ka naam `use` se shuru hona chahiye — otherwise linter complain karega |

**Kyun yeh rules?** React internally hooks ki identity unke **call order** se track karta hai. Har render mein hooks same order mein call hone chahiye. Condition ke andar hook daaloge toh render-to-render order change ho sakta hai — React confuse ho jaayega.

## Jab Custom Hook Banayein?

Custom hook ka decision matrix:

| Scenario | Custom Hook? |
|----------|-------------|
| Ek component mein unique logic | Nahi rakho |
| Do components mein same pattern | **Haan** — extract karo |
| Pure UI abstraction (layout, styling) | Component banao, hook nahi |
| Stateful logic reuse karna hai | Hook banao |
| Koi built-in hook ka wrapper chahiye | Hook banao |
| Sirf ek baar use hoga, aur future mein bhi nahi chahiye | Faltu abstraction mat banao |

Senior devs ka rule: **"Rule of Three"** — agar same pattern teen ya zyada jagah dikhe, tabhi custom hook banao. Ek-do jagah ke liye over-engineering ho sakta hai. Lekin agar pattern bhout common hai (toggle, fetch, localStorage), toh do jagah bhi ho toh bana lo — kyunki aage aur jagah bhi lagega.

---

## So Here's the Takeaway

Custom hook ek function hai jo React hooks use karta hai. Logic extract karta hai, reuse enable karta hai, code clean banata hai. Component mein ab sirf **kya** dikhta hai, **kaise** nahi.

Abhi humne simple hooks banaye — `useToggle`, `useDocumentTitle`, `usePrevious`, `useBoolean`. Yeh sab specific types ke saath kaam karte hain (boolean, string, number). Lekin kya ho agar humein ek generic hook chahiye jo **kisi bhi type** ke saath kaam kare? Jaise `useFetch<T>` — koi bhi data type fetch kare? Ya `useLocalStorage<T>` — koi bhi type localStorage mein save kare?

Agle topic mein wahi dekhenge — **Generic Custom Hooks**.

## In Your Own Words

1. Custom hook aur regular function mein kya fark hai? React hook rules yahan kyun apply hote hain?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Regular function koi bhi JavaScript function hai jo kuch bhi kar sakta hai. Custom hook bhi ek function hai, lekin yeh React hooks (jaise `useState`, `useEffect`) call karta hai. Isliye iska naam `use` se shuru hona chahiye — taaki React ko pata chale ki yeh hooks use karta hai aur Rules of Hooks enforce kar sake (top-level call, no conditions, etc.). Agar regular function ke andar `useState` call kiya toh React error dega kyunki woh React function component ya custom hook nahi hai.

</details>

2. Custom hook component ke beech state share karta hai ya logic? Example ke saath samjhao.

<details>
<summary>Show Answer</summary>

**Sample Answer:** Custom hook **logic share karta hai, state nahi**. Agar do components `useToggle()` call karte hain, har component ko apna alag `value` aur `toggle` function milta hai. Ek component ka toggle doosre component ki value ko affect nahi karta. State share karni ho toh Context API ya Zustand jaise state management tools use karne padte hain. Custom hook sirf wahi code nikaalta hai jo baar-baar likhna padta hai — jaise toggle ka logic, fetch ka logic, localStorage ka logic.

</details>

3. `usePrevious` hook mein value render ke baad update hoti hai jabki return render ke dauran hota hai. Yeh kaise kaam karta hai? Yeh agar `useRef` ki jagah `useState` se karte toh kya problem aati?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `usePrevious` ka secret hai render cycle ka timing. `useRef` component ke poore lifetime mein ek mutable object rakhta hai, aur `useEffect` render ke **baad** chalta hai. Toh render ke dauran jab hum `ref.current` return karte hain, us waqt ref mein **pichli render ki value** hoti hai. Current render ki value abhi ref mein nahi gayi — woh effect chalne ke baad store hogi. Agar `useState` use karte, toh state change re-render trigger karta, jis se infinite loop ban jaata — setState → render → setState → render...

</details>

4. "Rule of Three" kya hai? Kab custom hook banana avoid karna chahiye?

<details>
<summary>Show Answer</summary>

**Sample Answer:** "Rule of Three" ka matlab hai ki agar same pattern teen ya zyada jagah dikhe, tabhi custom hook banao. Ek-do jagah ke liye custom hook banana over-engineering ho sakta hai — abstraction ka cost (extra file, extra indirection) benefit se zyada ho jaata hai. Lekin bhout common patterns (toggle, fetch, localStorage) ke liye do jagah bhi ho toh bana lo, kyunki aage aur jagah lagne wali hai. Custom hook banana avoid karo jab: (a) logic sirf ek component mein unique hai, (b) abstraction sirf "ho sakta hai future mein kaam aaye" ke liye ho, (c) woh logic UI/layout related ho (component better hai).

</details>

5. Custom hook ne component ke code ko kaise badal diya? Specific example do.

<details>
<summary>Show Answer</summary>

**Sample Answer:** Bina custom hook ke toggle logic: `const [isOpen, setIsOpen] = useState(false); const toggle = () => setIsOpen(v => !v);` — do lines. Custom hook se: `const [isOpen, toggle] = useToggle(false)` — ek line. Lekin fark sirf lines ka nahi hai. Custom hook ne **intention ko clear** kar diya hai. Component mein ab `useState` aur function definition nahi dikh raha — sirf `useToggle` dikh raha hai. Toggle ka "kaise" (implementation) hook mein chhupa hai, component mein sirf "kya" (intention) dikh raha hai. Is abstraction se code readable, maintainable, aur testable ban jaata hai.

</details>
