## Step 1 — Theme Store (Context → Zustand)

Purane ThemeContext ki jagah ek simple Zustand store:

```ts
// stores/themeStore.ts
import { create } from "zustand";
import { persist } from "zustand/middleware";

type Theme = "light" | "dark";

interface ThemeStore {
  theme: Theme;
  toggleTheme: () => void;
}

export const useThemeStore = create<ThemeStore>()(
  persist(
    (set) => ({
      theme: "light",
      toggleTheme: () =>
        set((state) => ({
          theme: state.theme === "light" ? "dark" : "light",
        })),
    }),
    { name: "todo-theme" }
  )
);
```

**Compare karo purane ThemeContext se:**

| Aspect | Context API (~45 lines) | Zustand (~15 lines) |
|--------|------------------------|--------------------|
| **createContext** | Required | Nahi |
| **Provider component** | Required | Nahi |
| **useMemo for value** | Required (re-renders) | Nahi (selective subscription) |
| **useCallback** | Optional (re-renders) | Nahi (built-in stable) |
| **Custom hook guard** | Required (!ctx throw) | Nahi (store exists hamesha) |
| **Persistence** | Manual (effect + localStorage) | Built-in (persist middleware) |

## Step 2 — Tasks Store (State + Actions)

Purane App.tsx mein tasks state, event handlers, aur computed values sab ek saath the. Ab ek alag tasks store banate hain:

```ts
// stores/tasksStore.ts
import { create } from "zustand";
import { persist } from "zustand/middleware";
import type { Task, FilterStatus } from "../types";

interface TasksStore {
  tasks: Task[];
  filter: FilterStatus;
  addTask: (text: string, category: string) => void;
  toggleTask: (id: number) => void;
  deleteTask: (id: number) => void;
  setFilter: (filter: FilterStatus) => void;
}

export const useTasksStore = create<TasksStore>()(
  persist(
    (set) => ({
      tasks: [],
      filter: "all",

      addTask: (text, category) =>
        set((state) => ({
          tasks: [
            ...state.tasks,
            { id: Date.now(), text, completed: false, category },
          ],
        })),

      toggleTask: (id) =>
        set((state) => ({
          tasks: state.tasks.map((t) =>
            t.id === id ? { ...t, completed: !t.completed } : t
          ),
        })),

      deleteTask: (id) =>
        set((state) => ({
          tasks: state.tasks.filter((t) => t.id !== id),
        })),

      setFilter: (filter) => set({ filter }),
    }),
    { name: "todo-tasks" }
  )
);
```

**Notice kiya?** `persist` middleware se tasks automatic localStorage mein save ho rahe hain. **Page refresh ke baad bhi tasks rehte hain** — bina kisi `useEffect` ke, bina kisi `JSON.parse` ke.

## Step 3 — Categories with useFetch

Purane categories fetch mein `useEffect` + ignore pattern + manual state tha. Ab `useFetch<string[]>` use karenge:

```ts
// hooks/useFetch.ts — wahi hook jo 6.2 mein banaya tha
import { useState, useEffect } from "react";

export function useFetch<T>(url: string) {
  const [data, setData] = useState<T | null>(null);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    let ignore = false;

    async function fetchData() {
      setIsLoading(true);
      setError(null);
      try {
        const res = await fetch(url);
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const json = await res.json();
        const categories = json.categories.map((c: any) => c.strCategory).slice(0, 5);
        if (!ignore) setData(categories as T);
      } catch (err) {
        if (!ignore) {
          setError(err instanceof Error ? err.message : "Kuch gadbad hui");
        }
      } finally {
        if (!ignore) setIsLoading(false);
      }
    }

    fetchData();
    return () => { ignore = true; };
  }, [url]);

  return { data, isLoading, error };
}
```

## Step 4 — Migrated Components

Ab components ko update karte hain — Context ki jagah seedha Zustand store use karein:

### ThemeToggle — Before vs After

```tsx
// Before (Context API):
import { useTheme } from "../context/ThemeContext";
function ThemeToggle() {
  const { theme, toggleTheme } = useTheme();
  return (
    <button onClick={toggleTheme}>
      {theme === "light" ? "🌙 Dark" : "☀️ Light"}
    </button>
  );
}

// After (Zustand):
import { useThemeStore } from "../stores/themeStore";
function ThemeToggle() {
  const theme = useThemeStore((s) => s.theme);
  const toggleTheme = useThemeStore((s) => s.toggleTheme);
  return (
    <button onClick={toggleTheme}>
      {theme === "light" ? "🌙 Dark" : "☀️ Light"}
    </button>
  );
}
```

Fark? Context version mein `useTheme()` poora object leta hai — agar context value mein koi aur property add hui, toh bhi component re-render hoga. Zustand version selective subscription karta hai.

### TaskInput — Simpler, Same Pattern

```tsx
import { useRef, useState, useEffect } from "react";
import { useTasksStore } from "../stores/tasksStore";

function TaskInput() {
  const [text, setText] = useState("");
  const inputRef = useRef<HTMLInputElement>(null);
  const addTask = useTasksStore((s) => s.addTask);

  useEffect(() => {
    inputRef.current?.focus();
  }, []);

  const handleAdd = () => {
    if (text.trim()) {
      addTask(text.trim(), "General");
      setText("");
      inputRef.current?.focus();
    }
  };

  return (
    <div>
      <input ref={inputRef} value={text} onChange={e => setText(e.target.value)} />
      <button onClick={handleAdd}>Add</button>
    </div>
  );
}
```

`addTask` ab store se aa raha hai, props se nahi. TaskInput ko ab `onAdd` prop pass nahi karna padta.

### App.tsx — Dramatically Cleaner

Purana App.tsx ~80 lines ka tha — state management, event handlers, computed values, fetch logic, JSX sab ek saath. Naya App.tsx:

```tsx
import { useTasksStore } from "./stores/tasksStore";
import { useThemeStore } from "./stores/themeStore";
import { useFetch } from "./hooks/useFetch";
import TaskInput from "./components/TaskInput";
import TaskItem from "./components/TaskItem";
import FilterBar from "./components/FilterBar";
import TaskStats from "./components/TaskStats";
import ThemeToggle from "./components/ThemeToggle";

function App() {
  const theme = useThemeStore((s) => s.theme);
  const { tasks, filter, toggleTask, deleteTask, setFilter } = useTasksStore();
  const { data: categories, isLoading, error } = useFetch<string[]>(
    "https://www.themealdb.com/api/json/v1/1/categories.php"
  );

  const filteredTasks = tasks.filter((t) => {
    if (filter === "active") return !t.completed;
    if (filter === "completed") return t.completed;
    return true;
  });

  const completedCount = tasks.filter((t) => t.completed).length;
  const remainingCount = tasks.length - completedCount;

  return (
    <div className={theme === "dark" ? "dark" : "light"}>
      <div>
        <h1>📋 To-Do App v3</h1>
        <ThemeToggle />
      </div>

      {isLoading && <p>⏳ Loading categories...</p>}
      {error && <p style={{ color: "red" }}>❌ {error}</p>}
      {categories && (
        <p style={{ fontSize: "13px", color: "#888" }}>
          Categories: {categories.join(", ")}
        </p>
      )}

      <TaskInput />
      <FilterBar currentFilter={filter} onFilterChange={setFilter} />

      <div>
        {filteredTasks.map((task) => (
          <TaskItem key={task.id} task={task} onToggle={toggleTask} onDelete={deleteTask} />
        ))}
        {filteredTasks.length === 0 && <p>No tasks to show.</p>}
      </div>

      <TaskStats total={tasks.length} completed={completedCount} remaining={remainingCount} />
    </div>
  );
}

export default App;
```

**Nahi dikh raha kya:**

| Missing From New App.tsx | Kahan Gaya |
|------------------------|------------|
| `useState` for tasks | Zustand store mein |
| `useState` for theme | Zustand store mein |
| `useState` for categories | `useFetch` hook mein |
| `useEffect` for categories fetch | `useFetch` hook mein |
| `handleAdd/toggle/delete` functions | Zustand store actions mein |
| `ThemeProvider` wrapper | Zaroorat nahi — Zustand needs no provider |
| `localStorage.getItem` for tasks | Zustand persist middleware |

## Step 5 — New Addition: Category Select

Ab jab categories API se aa rahi hain, toh TaskInput mein ek dropdown add karte hain taake user category select kar sake:

```tsx
function TaskInput() {
  const [text, setText] = useState("");
  const [selectedCategory, setSelectedCategory] = useState("General");
  const inputRef = useRef<HTMLInputElement>(null);
  const addTask = useTasksStore((s) => s.addTask);
  const { data: categories } = useFetch<string[]>(
    "https://www.themealdb.com/api/json/v1/1/categories.php"
  );

  useEffect(() => { inputRef.current?.focus(); }, []);

  const handleAdd = () => {
    if (text.trim()) {
      addTask(text.trim(), selectedCategory);
      setText("");
      inputRef.current?.focus();
    }
  };

  return (
    <div>
      <input ref={inputRef} value={text} onChange={e => setText(e.target.value)} />
      <select value={selectedCategory} onChange={e => setSelectedCategory(e.target.value)}>
        <option value="General">General</option>
        {categories?.map(cat => (
          <option key={cat} value={cat}>{cat}</option>
        ))}
      </select>
      <button onClick={handleAdd}>Add</button>
    </div>
  );
}
```

Notice kiya? TaskInput khud categories fetch kar raha hai — App se prop pass nahi ho raha. `useFetch` ek line mein categories laa raha hai. Yeh custom hooks ka power hai — **jo component jis data ki zaroorat hai, woh khud fetch karta hai.**

## Before vs After — Migration Summary

**Architecture change:**

```
Before (Batch 2):
App.tsx (state + handlers + fetch + JSX)
  ├── ThemeContext (provider wraps App)
  ├── TaskInput (onAdd prop)
  ├── TaskItem (onToggle prop, onDelete prop)
  ├── FilterBar (filter prop, onFilterChange prop)
  └── TaskStats (total/completed/remaining props)

After (Batch 6):
App.tsx (JSX only — lean)
  ├── themeStore (independent Zustand)
  ├── tasksStore (independent Zustand)
  ├── useFetch hook (categories)
  ├── TaskInput (no props — self-contained)
  ├── TaskItem (onToggle, onDelete — but from store)
  ├── FilterBar (filter, onFilterChange)
  └── TaskStats (total/completed/remaining)
```

**Key changes:**
- ThemeContext → `useThemeStore` (provider-free, auto-persist)
- App.tsx state → `useTasksStore` (actions + persist)
- useEffect fetch → `useFetch<string[]>` (loading + error built-in)
- Manual localStorage → `persist` middleware (zero boilerplate)

## So Here's the Takeaway

To-Do App v2 se v3 migration ne dikha diya:

1. **Zustand ne Context ka ~45 lines hata diya** — koi provider, koi useMemo, koi guard nahi
2. **useFetch ne useEffect ka ~15 lines hata diya** — loading + error + cleanup automatic
3. **persist middleware ne localStorage ka ~10 lines hata diya** — refresh pe bhi data safe
4. **Component self-contained ho gaye** — TaskInput khud apna data fetch karta hai
5. **App.tsx sirf JSX layout ka role hai** — state management store mein, fetch hooks mein

Ab tak ka journey dekho: Batch 2 mein humne Context API seekhi (manual approach). Batch 6 mein wahi problem Zustand se solve ki (better approach). Yeh industry ka pattern hai — "pehle manual seekho, phir better tool."

Ab agle aur final topic mein — **Combined Project #6**: Kanban Board. Zustand store with normalized state, generic UI components, drag-drop, undo/redo. Saare concepts ek saath.

## In Your Own Words

1. Batch 2 ke To-Do App v2 mein ThemeContext ka custom hook guard (`if (!ctx) throw`) kyun tha? Zustand mein uski zaroorat kyun nahi?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Context API mein guard pattern isliye chahiye tha kyunki component `ThemeProvider` ke bahar use ho sakta hai. Agar koi component `useTheme()` call kare bina `ThemeProvider` ke andar render hue, toh `useContext` undefined return karta — aur undefined access karne error aata. Guard yeh ensure karta hai ki clear error mile. Zustand mein store independent hai — koi provider nahi, koi context tree nahi. Component store seedha import karta hai, chahe kahan bhi render ho. Store hamesha exist karta hai, isliye guard ki zaroorat nahi.

</details>

2. `useTasksStore` mein `persist` middleware ne kaun-si problem solve kari jo Batch 2 ke To-Do App v2 mein thi?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Batch 2 ke To-Do App v2 mein tasks localStorage mein save nahi hote the — page refresh pe saare tasks reset ho jaate the. Agar manually karte, toh `useState` lazy initializer + `localStorage.getItem` + `JSON.parse` (load ke liye) aur `useEffect` + `localStorage.setItem` + `JSON.stringify` (save ke liye) — minimum 10 lines. `persist` middleware ne ek wrapper mein sab kuch kar diya — automatic serialization, deserialization, aur localStorage sync. Plus error handling bhi built-in hai (corrupt data pe fallback).

</details>

3. Naye App.tsx mein `categories` prop se nahi aa raha, balki TaskInput khud `useFetch` call kar raha hai. Yeh kaise possible hai aur iska kya fayda hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Har component jo `useFetch` call karta hai, woh apna fetch khud manage karta hai. TaskInput mein `useFetch` categories la raha hai — App.tsx ko categories prop pass karne ki zaroorat nahi. Fayda yeh hai: (a) **self-contained components** — component jis data ki zaroorat hai woh khud laata hai, parent ko nahi puchta; (b) **prop drilling reduce hoti hai** — categories ko 5 components mein pass nahi karna padta; (c) **reusability** — TaskInput kisi bhi app mein use kar sakte ho, woh apne data ka khayal rakhega. Lekin agar categories multiple components ko chahiye, toh store mein rakhna better hai.

</details>

4. Zustand version mein App.tsx ~40 lines ka hai, Batch 2 version ~80 lines ka tha. Kaun-si 40 lines bach gayi?

<details>
<summary>Show Answer</summary>

**Sample Answer:** (1) `useState` declaration for tasks + filter (3 lines), (2) event handlers — handleAdd, handleToggle, handleDelete (~15 lines), (3) useEffect for categories fetch + ignore pattern (~10 lines), (4) ThemeContext import + useTheme call (2 lines), (5) styles object (~8 lines), (6) Provider wrapper in export (~3 lines). Total ~41 lines. Yeh sab Zustand store actions, useFetch hook, aur themeStore mein shift ho gayi. App.tsx sirf JSX layout aur computed values handle karta hai.

</details>

5. Yeh approach kahan fail karega? Jab kab Zustand ki jagah Context better hoga?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Zustand fail ho sakta hai jab: (a) app bhout chhoti hai (2-3 components, 1 global value) — Zustand ki extra dependency worth nahi hai; (b) team React Context mein comfortable hai aur performance issues nahi hain; (c) library restriction hai (kisi company policy mein extra dependency allowed nahi). Context better hai jab: sirf 1-2 values hain jo infrequently change hoti hain (theme, locale), app chhoti hai, aur provider nesting se problem nahi hai. Decision criteria: agar `provider hell` + `unnecessary re-renders` + `boilerplate` se problem hai toh Zustand — nahi toh Context bhi chalega.

</details>
