## Step 7 — Cart Drawer

The cart has a brain (context) but no face. Items are invisible. The plan: a **drawer** — a panel sliding over the page from the right, with a dimmed backdrop. This is a *modal*, and modals are where accessibility stops being a checkbox and starts being a system.

### 7.1 "What is a drawer, structurally?"

Two layers over the page:

```
┌──────────────────────────────┐
│  store page (frozen)         │
│            ┌─────────────────┤
│            │ █ backdrop █    │
│            │ ┌─────────────┐ │
│            │ │ Cart (2)  ✕ │ │  ← panel, right edge
│            │ │ Headphones  │ │
│            │ │ [-] 2 [+]   │ │
│            │ │ Total ₹5498 │ │
│            │ │ [Checkout]  │ │
│            │ └─────────────┘ │
└────────────┴─────────────────┘
```

**Decision:** the drawer is *conditionally rendered* — `return null` when closed. No CSS `display: none` games: when it's not on screen, it's not in the DOM, so screen readers and Tab can't reach a ghost.

`The drawer's buttons will dispatch two kinds the cart does not know yet: `UPDATE_QTY` and `REMOVE`. And TypeScript refuses an unknown kind at the dispatch site - that is the union's whole job (4.5.0: the compiler knows exactly which shapes exist). So before any drawer code can compile, the two members join `CartAction` in `src/context/cartReducer.ts`:

```tsx
export type CartAction =
  | { kind: 'ADD'; product: { id: number; name: string; price: number; image: string } }
  | { kind: 'REMOVE'; productId: number }
  | { kind: 'UPDATE_QTY'; productId: number; quantity: number }
```

The `ADD` member is 4.5.6's, unchanged. The two new members carry exactly what their buttons will send: `REMOVE` just the row's key (`productId`, the same field `CartItem` stores), `UPDATE_QTY` the key plus the new quantity. The cases do not exist yet - that is fine for now; the union only declares shapes. Each case gets built together with its button, right after the drawer.

src/components/CartDrawer.tsx`:

```tsx
import { useEffect, useRef } from 'react'
import { useCart } from '../context/CartContext'
import { Link } from 'react-router-dom'

interface CartDrawerProps {
  isOpen: boolean
  onClose: () => void
}

export default function CartDrawer({ isOpen, onClose }: CartDrawerProps) {
  const { items, dispatch } = useCart()
  const drawerRef = useRef<HTMLDivElement>(null)
  const total = items.reduce((sum, i) => sum + i.price * i.quantity, 0)

  useEffect(() => {
    if (!isOpen) return
    const handleKeyDown = (e: KeyboardEvent) => {
      if (e.key === 'Escape') onClose()
      if (e.key === 'Tab') {
        const drawer = drawerRef.current
        if (!drawer) return
        const focusables = drawer.querySelectorAll<HTMLElement>(
          'button, [href], input, textarea, select, [tabindex]:not([tabindex="-1"])'
        )
        if (focusables.length === 0) return
        const first = focusables[0]
        const last = focusables[focusables.length - 1]
        if (e.shiftKey && document.activeElement === first) {
          e.preventDefault()
          last.focus()
        } else if (!e.shiftKey && document.activeElement === last) {
          e.preventDefault()
          first.focus()
        }
      }
    }
    document.addEventListener('keydown', handleKeyDown)
    drawerRef.current?.focus()
    return () => document.removeEventListener('keydown', handleKeyDown)
  }, [isOpen, onClose])

  if (!isOpen) return null

  return (
    <div className="fixed inset-0 z-50">
      <div className="absolute inset-0 bg-black/40" onClick={onClose} aria-hidden="true" />
      <div
        ref={drawerRef}
        role="dialog"
        aria-label="Shopping Cart"
        tabIndex={-1}
        className="absolute top-0 right-0 h-full w-full max-w-md bg-white shadow-xl p-6 overflow-y-auto focus:outline-none"
      >
        <div className="flex justify-between items-center mb-6">
          <h2 className="text-xl font-bold">Cart ({items.length})</h2>
          <button
            onClick={onClose}
            className="text-2xl leading-none hover:text-gray-500 focus:outline-none focus:ring-2 focus:ring-blue-400 rounded"
            aria-label="Close cart"
          >
            &times;
          </button>
        </div>

        {items.length === 0 ? (
          <p className="text-gray-500 text-center mt-12">Cart is empty</p>
        ) : (
          <>
            <ul className="space-y-4">
              {items.map(item => (
                <li key={item.productId} className="flex gap-4 border-b pb-4">
                  <img src={item.image} alt={item.name} className="w-16 h-16 object-cover rounded" />
                  <div className="flex-1">
                    <h3 className="font-semibold">{item.name}</h3>
                    <p className="text-sm text-green-600 font-bold">₹{item.price}</p>
                    <div className="flex items-center gap-2 mt-2">
                      <button
                        onClick={() => dispatch({ kind: 'UPDATE_QTY', productId: item.productId, quantity: Math.max(1, item.quantity - 1) })}
                        className="w-8 h-8 border rounded hover:bg-gray-100 focus:outline-none focus:ring-2 focus:ring-blue-400"
                        aria-label={`Decrease quantity of ${item.name}`}
                      >-</button>
                      <span className="w-8 text-center">{item.quantity}</span>
                      <button
                        onClick={() => dispatch({ kind: 'UPDATE_QTY', productId: item.productId, quantity: item.quantity + 1 })}
                        className="w-8 h-8 border rounded hover:bg-gray-100 focus:outline-none focus:ring-2 focus:ring-blue-400"
                        aria-label={`Increase quantity of ${item.name}`}
                      >+</button>
                      <button
                        onClick={() => dispatch({ kind: 'REMOVE', productId: item.productId })}
                        className="ml-auto text-red-500 hover:text-red-700 text-sm focus:outline-none focus:ring-2 focus:ring-red-400 rounded"
                        aria-label={`Remove ${item.name} from cart`}
                      >Remove</button>
                    </div>
                  </div>
                </li>
              ))}
            </ul>

            <div className="mt-6 border-t pt-4">
              <div className="flex justify-between text-xl font-bold">
                <span>Total</span>
                <span>₹{total}</span>
              </div>
              <Link
                to="/checkout"
                onClick={onClose}
                className="mt-4 block text-center bg-green-600 text-white py-3 rounded hover:bg-green-700 focus:outline-none focus:ring-2 focus:ring-green-400"
              >
                Checkout
              </Link>
            </div>
          </>
        )}
      </div>
    </div>
  )
}
```

The structure pieces:
- `fixed inset-0 z-50` — the wrapper covers the whole viewport, above everything (`z-50`).
- Backdrop: `absolute inset-0 bg-black/40` — click closes. `aria-hidden="true"` — it's decoration, not content; screen readers skip it.
- Panel: `role="dialog" aria-label="Shopping Cart"` — screen readers announce "Shopping Cart, dialog" when it opens. `tabIndex={-1}` — the panel itself isn't in Tab order (its buttons are), but *can* receive programmatic focus.
- `Math.max(1, item.quantity - 1)` — minus never goes to 0. Zero quantity means "remove," and removing has its own button with its own action. Two buttons, two meanings, no overlap.
- `total` via `reduce` — computed where displayed, not stored in the reducer. Store state minimal; derive the rest.

Now give each button its body - 4.5.6's promise, one button at a time.

**The [-] button** dispatches `{ kind: 'UPDATE_QTY', productId: item.productId, quantity: Math.max(1, item.quantity - 1) }`. Its case, in `cartReducer.ts`:

```tsx
case 'UPDATE_QTY':
  return state.map(i =>
    i.productId === action.productId
      ? { ...i, quantity: action.quantity }
      : i
  )
```

`map` walks the cart; the matching row becomes a NEW object (the spread copy from 4.5.6's ADD - here setting quantity instead of bumping it); every other row is returned as-is, same reference, untouched. New array reference, so React re-renders. And notice where the "never below 1" rule lives: not in this case - in the button's `Math.max(1, ...)`. The reducer sets what it is given; the button decides what is allowed to be given.

**The [+] button** dispatches the SAME kind - `{ kind: 'UPDATE_QTY', productId, quantity: item.quantity + 1 }`. One case, two buttons. The payload differs; the body does not care which button sent it - `action.quantity` is just the number that arrived. That is the discriminated union paying off: two UI controls, one transition, one case to maintain.

**The Remove button** dispatches `{ kind: 'REMOVE', productId: item.productId }` - no quantity, just "drop this row". Its case:

```tsx
case 'REMOVE':
  return state.filter(i => i.productId !== action.productId)
```

`filter` keeps every item EXCEPT the one whose `productId` matches - the dropped row simply never makes it into the new array. Again: new array reference, no mutation, React re-renders.

All three cases now exist - time for the same no-UI proof 4.5.6 used, covering everything at once:

```tsx
const actions = [
  { kind: 'ADD', product: products[0] },
  { kind: 'UPDATE_QTY', productId: products[0].id, quantity: 3 },
  { kind: 'REMOVE', productId: products[0].id },
]

actions.reduce(cartReducer, [])
// [] - added, set to 3, removed. All three kinds, one plain-function proof.
```

### 7.2 "How does keyboard focus behave?"

Three moves inside the `useEffect`, all conditional on `isOpen`:

1. **Focus moves in** — `drawerRef.current?.focus()` fires on open. Keyboard users land *inside* the drawer, not lost behind the backdrop.
2. **Escape closes** — one listener on `document` (the drawer has its own cleanup so listeners never pile up).
3. **Tab stays inside** — the trap: `querySelectorAll` grabs every focusable element inside the drawer. Tab on the last one wraps to the first, Shift+Tab on the first wraps to the last — `e.preventDefault()` stops the browser's default focus move so the wrap is ours. Keyboard users can no longer tab out into the hidden page behind.

Without the trap, a keyboard user Tabs "through" the backdrop and operates an invisible page. The trap is the whole difference between a modal and a popup-shaped bug.

**TEST:** click the cart button — the drawer opens and focus lands inside it. Press Escape or click the backdrop — it closes. Press Tab repeatedly — focus cycles through the drawer's buttons and stays inside. Screen readers announce the `dialog` role. Next step — the checkout page.

### 7.3 Wire it into the page

```tsx
import { useState } from 'react'

function HomePage() {
  const [cartOpen, setCartOpen] = useState(false)
  const { items } = useCart()

  return (
    <div className="max-w-6xl mx-auto p-8">
      <div className="flex justify-between items-center mb-8">
        <h1 className="text-3xl font-bold">E-Commerce Store</h1>
        <button
          onClick={() => setCartOpen(true)}
          className="relative bg-gray-100 px-4 py-2 rounded hover:bg-gray-200 focus:outline-none focus:ring-2 focus:ring-blue-400"
          aria-label={`Open cart, ${items.length} items`}
        >
          Cart ({items.length})
        </button>
      </div>
      <div className="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6">
        {products.map((product) => (
          <ProductCard key={product.id} product={product} />
        ))}
      </div>
      <CartDrawer isOpen={cartOpen} onClose={() => setCartOpen(false)} />
    </div>
  )
}
```

Note the split: `cartOpen` is *page* state (does the drawer show?) — it lives in `HomePage` via `useState`. *Cart contents* live in Context. Open/close is local; contents are global. Choosing which state goes where is half of state management.

The header button: visible text "Cart (2)" for sighted users, aria-label "Open cart, 2 items" for screen readers — the count is announced as a sentence, not a parenthesis.

## Common Mistakes (Senior Dev Blind Spots)

- **Listener leaks:** adding `keydown` in `useEffect` without the cleanup function stacks a new listener on every open. Five opens, five Escapes, five closes. Always return the remover.
- **Trap without `preventDefault`:** without it, the browser *also* moves focus — you get double-jumps. `preventDefault` + manual `.focus()` is the pair.
- **`display: none` modals:** hidden-but-mounted drawers stay in the Tab order and in screen readers. Conditional render (`return null`) removes them entirely.
- **Backdrop without `aria-hidden`:** a dimmed div is not content; announcing "group" for it is noise.
- **Quantity reaching 0:** minus clamped with `Math.max(1, ...)` — 0-quantity items are the reducer's and the UI's disagreeing about what "remove" means.

## Try It Yourself (Active Recall)

1. Open the drawer, Tab past the last button. Where does focus land? (First button — the wrap.)
2. Why is `cartOpen` in `HomePage` but cart items in Context? What breaks if you flip that? (Contents would be page-local — checkout couldn't see them.)
3. Set quantity to 0 by removing `Math.max`. What does a 0-row in a cart even mean? Design the ambiguity you just created.
