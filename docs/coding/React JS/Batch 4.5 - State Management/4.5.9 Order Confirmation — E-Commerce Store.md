## Step 9 - Order Confirmation & The Full Flow

In 4.5.8 a valid checkout dispatched `PLACE_ORDER` - the cart emptied and `navigate('/order-confirmed')` fired. That route doesn't exist yet, so the browser shows nothing: the last URL in the flow is a blank page.

Where the store stands: every page built so far renders - the store grid, the detail page, the drawer over the store, the checkout form - and the reducer holds all four cases. One page is missing, and without it the flow dead-ends: the customer pays, the cart empties, and the screen goes blank. This step builds the missing piece - the **order confirmation page** - and then wires the complete route table so the whole store runs end to end.

The feature: a static confirmation screen (its own URL - bookmarkable, back-button friendly) with a Continue Shopping link back to the store, and the finished `App.tsx` with every `<Route>`: `/`, `/product/:id`, `/checkout`, `/order-confirmed`. Two files: a new `src/pages/OrderConfirmed.tsx`, and the final `App.tsx`. When this step is done, the demo's full journey works: store, detail, add to cart, drawer, checkout, confirmation, back to the store with an empty cart.

The build order matters: the page first, then the routes that point at it.
### 9.1 "What does 'confirmed' actually need?"

Think about the real flow for a second: in production, `onSubmit` would POST the order to a backend, which returns an **order id** — and the confirmation page would show it ("Order #4821 confirmed"). This project has no backend, so the decision is: **simulate now, structure for later.** The page is static; when a backend arrives, only `onSubmit` changes — the confirmation page keeps its shape.

`src/pages/OrderConfirmed.tsx`:

```tsx
import { Link } from 'react-router-dom'

export default function OrderConfirmed() {
  return (
    <div className="max-w-md mx-auto p-8 text-center mt-20">
      <div className="text-6xl mb-4">&#10003;</div>
      <h1 className="text-3xl font-bold mb-4">Order Confirmed!</h1>
      <p className="text-gray-600 mb-8">Your order has been placed successfully.</p>
      <Link
        to="/"
        className="inline-block bg-blue-500 text-white px-6 py-3 rounded hover:bg-blue-600 focus:outline-none focus:ring-2 focus:ring-blue-400"
```

A simple page, but note the pattern: the success state is its own **route**, not a modal over the checkout. A URL means it's bookmarkable, shareable, and the back button behaves. That's why checkout `navigate`s instead of flipping local state.

### 9.2 Wire every route

```tsx
import { useState } from 'react'
import { Routes, Route } from 'react-router-dom'
import ProductCard from './components/ProductCard'
import CartDrawer from './components/CartDrawer'
import ProductDetail from './pages/ProductDetail'
import Checkout from './pages/Checkout'
import OrderConfirmed from './pages/OrderConfirmed'
import { useCart } from './context/CartContext'
import { products } from './data'

function HomePage() {
  const [cartOpen, setCartOpen] = useState(false)
  const { items } = useCart()

  return (
    <div className="max-w-6xl mx-auto p-8">
      <div className="flex justify-between items-center mb-8">
        <h1 className="text-3xl font-bold">E-Commerce Store</h1>
        <button
          onClick={() => setCartOpen(true)}
          className="relative bg-gray-100 px-4 py-2 rounded hover:bg-gray-200 focus:outline-none focus:ring-2 focus:ring-blue-400"
          aria-label={`Open cart, ${items.length} items`}
        >
          Cart ({items.length})
        </button>
      </div>
      <div className="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6">
        {products.map((product) => (
          <ProductCard key={product.id} product={product} />
        ))}
      </div>
      <CartDrawer isOpen={cartOpen} onClose={() => setCartOpen(false)} />
    </div>
  )
}

export default function App() {
  return (
    <Routes>
      <Route path="/" element={<HomePage />} />
      <Route path="/product/:id" element={<ProductDetail />} />
      <Route path="/checkout" element={<Checkout />} />
      <Route path="/order-confirmed" element={<OrderConfirmed />} />
    </Routes>
  )
}
```

Four routes, four views, one App component reduced to a route table — the folder structure from 4.5.1, delivered as promised.

## Common Mistakes (Senior Dev Blind Spots — Series Recap)

- **State in the wrong home:** page-local `useState` for open/close, Context for contents. Mixing them = drilling or re-fetching for nothing.
- **Mutating instead of returning:** every reducer case builds a new array. `push`/`++` = silent no-renders.
- **Nested interactive elements:** Link the content, never a card that contains buttons.
- **URL params are strings:** `Number(id)` before any comparison.
- **Duplicate truth:** data and types live in `data.ts`/`types.ts` — one copy each, imported everywhere.
- **A11y as an afterthought:** focus rings, aria-labels, `role="dialog"`, `role="alert"`, focus traps — all were *decisions made during*, not a patch-up pass.

## Try It Yourself (Active Recall)

1. **Persist the cart.** In `CartProvider`, initialize the reducer from `localStorage` (guard for `null`) and save on every change. Hint: `useReducer(cartReducer, [], () => JSON.parse(localStorage.getItem('cart') ?? '[]'))` — the third argument is an initializer function. Refresh — cart survives.
2. **Add an "Added ✓" flash.** After `ADD` dispatch in `ProductCard`, show a two-second "Added to cart" badge (a `useState` + `setTimeout`). How does it change the add-to-cart experience?
3. **Sold-out state.** Give one product `stock: 0` in `data.ts`; disable its button and announce it with aria. TypeScript: does `Product` need the new field to be optional or required?
