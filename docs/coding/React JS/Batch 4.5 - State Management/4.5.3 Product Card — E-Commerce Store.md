## Step 3 — Product Card

Three cards, three copies of the same JSX. Change the button color tomorrow and you edit three places — and miss one. That's the pain signal: extract the card into its own component.

### 3.1 "Why extract — what does a component buy here?"

**Decision:** one `ProductCard` component. What it buys:

- **One place to change.** Photo height, shadow, text sizes — edit once, all three cards update.
- **A name for a concept.** "ProductCard" says more than a block of JSX buried in `App.tsx`.
- **Reuse.** The cart drawer (4.5.7) and detail page will show product-ish info too — components are the currency of reuse.

The rule of thumb: the same JSX appearing twice is a component waiting to be born. Write it once, and let the changing parts arrive as props. (You have seen this move per-section — a `Features.tsx` holding three feature blocks; here the repetition is *inside* a list, so the extraction is per-card, not per-section.)

### 3.2 "What props does a card need?"

**Decision:** the card needs the product's fields — `id`, `name`, `price`, `image` — so the props are exactly those four. TypeScript checks them with an interface, declared inline for now (a shared types file waits for 4.5.5, when a second component needs the same shape):

`src/components/ProductCard.tsx`:

```tsx
interface ProductCardProps {
  id: number
  name: string
  price: number
  image: string
}

export default function ProductCard({ id, name, price, image }: ProductCardProps) {
  return (
    <div className="border rounded-lg overflow-hidden shadow-sm hover:shadow-md transition-shadow">
      <img
        src={image}
        alt={name}
        className="w-full h-64 object-cover"
      />
      <div className="p-4">
        <h2 className="text-lg font-semibold">{name}</h2>
        <p className="text-xl font-bold text-green-600 mt-2">₹{price}</p>
      </div>
    </div>
  )
}
```

The JSX is the card from 4.5.2 — only the values changed from `product.name` to `name`, because the props destructure brings them in as locals.

### 3.3 "What does a screen reader need here?"

Less than you would think — and that is the lesson. The card is pure content right now: photo with `alt={name}`, name, price. No controls, so nothing needs a focus ring or a label yet.

**Decision made once, applied forever:** every interactive element in this store gets a focus ring and a descriptive label — the habit arrives when the element does. The card becomes clickable in 4.5.4 (and carries it), the detail page gets the store's first button, the drawer follows in 4.5.7. Watch it repeat.

## Common Mistakes (Senior Dev Blind Spots)

- **Extracting too early:** one card means no component needed. Extraction pays when repetition (or reuse) is real.
- **Passing `key` into the component:** `key` never arrives as a prop — React consumes it. If you need the id inside, pass it as its own prop.
- **Spread without thought:** `{...product}` passes *everything*. Fine now; when `Product` grows fields (4.5.5), spread silently passes extras too — that's why 4.5.5 switches to an explicit `product` prop.
