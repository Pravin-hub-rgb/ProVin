## Step 4 — Product Detail

Clicking a product should open a detail page — bigger photo, category, price, its own Add to Cart button. A "page" means a URL per product: `/product/1`, `/product/2`. URLs in a React app = routing.

### 4.1 "How do multiple pages work in a React app?"

A Vite app is one HTML file — there's no server serving `/product/1`. Routing is done in JavaScript: a library reads the URL and decides which component renders. **Decision:** `react-router-dom` — the standard.

```bash
npm install react-router-dom
# bun: bun add react-router-dom
```

Wrap the whole app in `BrowserRouter` in `src/main.tsx`:

```tsx
import { BrowserRouter } from 'react-router-dom'
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import './index.css'
import App from './App'

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </StrictMode>
)
```

Why `main.tsx` and not `App.tsx`? Because `App.tsx` is about to become a route table — its job is rendering views, not providing routing. The provider goes *around* the thing that needs it. Same logic as `CartProvider` later (4.5.6) — you'll see the pattern twice, then own it.

**One ordering trap before you move on:** you can't use `Link` without `BrowserRouter`. `Link` is a react-router component — it reads the router's context to know the current URL and build navigation. Wrap first, link second. Skip the wrap and the moment `ProductCard` renders a `Link`, React throws `useHref() may be used only in the context of a <Router> component` — and not just the link breaks: the whole component tree crashes.

### 4.2 "How does one component serve three products?"

**Decision:** one dynamic route — `/product/:id`. The `:id` is a slot; `/product/1` fills it with `"1"`, `/product/3` with `"3"`.

`src/pages/ProductDetail.tsx` — read the id from the route, find the matching product:

```tsx
import { useParams, Link } from 'react-router-dom'

const products = [
  { id: 1, name: "Wireless Headphones", price: 2499, image: "https://images.unsplash.com/photo-1505740420928-5e560c06d30e?w=400&h=400&fit=crop&q=80", category: "electronics" },
  { id: 2, name: "Cotton T-Shirt", price: 799, image: "https://images.unsplash.com/photo-1521572163474-6864f9cf17ab?w=400&h=400&fit=crop&q=80", category: "clothing" },
  { id: 3, name: "Running Shoes", price: 3999, image: "https://images.unsplash.com/photo-1542291026-7eec264c27ff?w=400&h=400&fit=crop&q=80", category: "footwear" },
]

export default function ProductDetail() {
  const { id } = useParams()
  const product = products.find(p => p.id === Number(id))

  if (!product) {
    return (
      <div className="p-8 text-center" role="alert">
        <h2 className="text-2xl font-bold">Product not found</h2>
        <Link to="/" className="text-blue-500 underline mt-4 inline-block">Back to Store</Link>
      </div>
    )
  }

  return (
    <div className="max-w-4xl mx-auto p-8">
      <Link to="/" className="text-blue-500 underline mb-6 inline-block">&larr; Back to Store</Link>
      <div className="grid md:grid-cols-2 gap-8">
        <img src={product.image} alt={product.name} className="w-full rounded-lg" />
        <div>
          <p className="text-sm text-gray-500 uppercase">{product.category}</p>
          <h1 className="text-3xl font-bold mt-2">{product.name}</h1>
          <p className="text-2xl font-bold text-green-600 mt-4">₹{product.price}</p>
          <button className="mt-6 bg-blue-500 text-white px-6 py-3 rounded hover:bg-blue-600 focus:outline-none focus:ring-2 focus:ring-blue-400 w-full md:w-auto">
            Add to Cart
          </button>
        </div>
      </div>
    </div>
  )
}
```

Two lines carry the whole idea:
- `const { id } = useParams()` — the URL slot, as a **string**.
- `products.find(p => p.id === Number(id))` — `Number(id)` converts the string. Compare `"1" === 1` and you get `false` — the classic URL-param gotcha. Convert, then compare.
- `find` returns `undefined` when nothing matches (say, `/product/99`) — hence the `if (!product)` branch.

**The not-found branch gets `role="alert"`:** when a screen reader user lands on a broken URL, `role="alert"` makes the screen reader announce the message immediately instead of waiting for the user to Tab into it. Same habit as form errors in 4.4.

### 4.3 "How does the user reach the detail page?"

The card is display-only right now — the demo's store page is too. One move makes the whole card clickable: wrap it in a `<Link>`:

`src/components/ProductCard.tsx`:

```tsx
import { Link } from 'react-router-dom'

interface ProductCardProps {
  id: number
  name: string
  price: number
  image: string
}

export default function ProductCard({ id, name, price, image }: ProductCardProps) {
  return (
    <Link to={`/product/${id}`} className="block border rounded-lg overflow-hidden shadow-sm hover:shadow-md transition-shadow focus-visible:ring-2 focus-visible:ring-blue-400">
      <img src={image} alt={name} className="w-full h-64 object-cover" />
      <div className="p-4">
        <h2 className="text-lg font-semibold">{name}</h2>
        <p className="text-xl font-bold text-green-600">{price}</p>
      </div>
    </Link>
  )
}
```

The whole card is the link — photo, name, price, one tap target. `className="block"` turns the inline `<a>` into a block so the entire card area is clickable. The focus ring lives on the Link (`focus-visible:ring-2` — it appears only for keyboard Tab, not mouse clicks): the a11y habit from 3.3 gets its first real carrier. The accessible name comes free — screen readers announce the card's content (image alt text, name, price), so no labels are needed when the content already says it.

**One rule for your pocket:** a `<Link>` must never contain a button or any other interactive element — invalid HTML (nested interactive elements), and clicks bubble up into the link. The card has no button today, so the whole card links. The day a quick-add button appears on a card, the Link shrinks back to the image and the name, and the button lives outside it.

**TEST:** click a product — anywhere on the card. The URL changes to `/product/1` — and the page goes blank. That's not a bug, that's routing's contract: a URL alone renders nothing. A `<Route>` is the URL-to-component map, and the map does not exist yet. Next section builds it — and the blank page comes alive. Tab through the store: the whole card is one stop, ring around it.

### 4.4 Routes in App.tsx

```tsx
import { Routes, Route } from 'react-router-dom'
import ProductCard from './components/ProductCard'
import ProductDetail from './pages/ProductDetail'

const products = [
  { id: 1, name: "Wireless Headphones", price: 2499, image: "https://images.unsplash.com/photo-1505740420928-5e560c06d30e?w=400&h=400&fit=crop&q=80", category: "electronics" },
  { id: 2, name: "Cotton T-Shirt", price: 799, image: "https://images.unsplash.com/photo-1521572163474-6864f9cf17ab?w=400&h=400&fit=crop&q=80", category: "clothing" },
  { id: 3, name: "Running Shoes", price: 3999, image: "https://images.unsplash.com/photo-1542291026-7eec264c27ff?w=400&h=400&fit=crop&q=80", category: "footwear" },
]

function HomePage() {
  return (
    <div className="max-w-6xl mx-auto p-8">
      <h1 className="text-3xl font-bold mb-8">E-Commerce Store</h1>
      <div className="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6">
        {products.map((product) => (
          <ProductCard key={product.id} {...product} />
        ))}
      </div>
    </div>
  )
}

export default function App() {
  return (
    <Routes>
      <Route path="/" element={<HomePage />} />
      <Route path="/product/:id" element={<ProductDetail />} />
    </Routes>
  )
}
```

**TEST:** click a product — the image or the name — and the detail page opens with its own URL. Browser back button returns to the store. Visit `/product/99` by hand — "Product not found", announced by screen readers. Press Tab on the store — the whole card is one stop, ring around it.

Notice something ugly? The `products` array now exists in **two files** — `App.tsx` and `ProductDetail.tsx`. Next step fixes it.

## Common Mistakes (Senior Dev Blind Spots)

- **`"1" === 1` is false:** URL params arrive as strings. `Number(id)` before comparing — or `find` silently returns `undefined`.
- **Interactive elements inside a Link:** a button inside a link is invalid HTML — clicks bubble up and navigate away. The card has no controls today, so the whole card links; the day a quick-add appears, the Link wraps only image + name again.
- **Router provider in the wrong file:** `BrowserRouter` wraps the app in `main.tsx`; `Routes` lives where views are chosen. Confusing the two gives "useNavigate may be used only in the context of a Router" errors.
- **No not-found branch:** `find` gives `undefined` for bad ids; rendering `product.name` of `undefined` crashes the page. Handle the miss.

## Try It Yourself (Active Recall)

1. Visit `/product/2` — which product shows? How did the component know? (URL slot → `useParams` → `find`.)
2. Remove `Number(id)` from the find call. What happens for every product, even valid ones? (Nothing found — string vs number.)
3. Tab through the store. How many stops per card, and what does a screen reader announce for each? (One stop — the whole card; the link reads the photo's alt text, the name, the price.)

## Summary (The Developer's Mental Model)

| Concept | Developer's Thought |
|---|---|
| Routing = JS reading the URL | One HTML file, many views |
| `:id` slot | One component serves many products |
| Params are strings | `Number(id)` before any comparison |
| Interactive inside a link = invalid | Whole card links today; the day a button appears, the Link shrinks |
| `role="alert"` on dead-ends | Screen readers announce failures immediately |
