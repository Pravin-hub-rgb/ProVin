## Problem Pehle — Dev Server Sirf Tumhare Liye Hai

`bun run dev` wala server sirf **local development** ke liye hai. Ye kyu nahi deploy ho sakta:

| `bun run dev` | Production |
|---|---|
| Source code directly serve karta hai | Optimized bundle serve karta hai |
| Slow (har file on-the-fly) | Fast (minified + compressed) |
| HMR, error overlay — dev tools | No dev tools — performance pe focus |
| Sirf tumhare machine pe | Har device pe (mobile, desktop) |

**Production alag cheez hai.** Browser ko source code nahi chahiye — browser ko optimized files chahiye jo jaldi load ho. Isliye pehla step: **build**.

---

## Step 1 — Production Build

Vite apps mein build command hoti hai. `custom-hooks-demo` project mein run karo:

```bash
bun run build
```

**Kya hota hai:**

```
Source code (TSX, TS, CSS)
        │
        ▼
Vite: bundling → minification → optimization
        │
        ▼
dist/ folder — production-ready files
    ├── index.html
    ├── assets/
    │   ├── index-abc123.js   ← minified JS bundle
    │   ├── index-xyz456.css  ← minified CSS
    │   └── ...
```

**Har step kya karta hai:**

| Step | Kya |
|------|-----|
| **Bundling** | Saari JS/TSX files ko ek (ya kuch) chhote files mein jodo |
| **Minification** | Variables chhote naam (`a`, `b`), spaces hatao, comments hatao — file size kam |
| **Tree-shaking** | Jo code use nahi hota (unused imports, dead code) bundle se nikaal do |
| **Code splitting** | React.lazy wale parts alag chunks (7.5.1 se) — sirf zaroorat pe load |
| **Hash filenames** | `index-abc123.js` — cache busting, update pe browser nayi file leta hai |

**Result:** `dist/` folder mein optimized files — browser jaldi load karega.

## Step 2 — Production Build Check Karna

Build ke baad production build ko locally test karo — `preview` command:

```bash
bun run preview
```

Ye production build ko locally serve karta hai — asli production jaisa experience. Yahan test karo: routing sahi hai? lazy loading kaam karta hai? Build deploy ke liye ready hai?

**Build check — bhout important:** Production build mein source maps hatao (public code expose nahi karna), aur bundle size pe dhyaan do:

```bash
bun run build
```

Output mein Vite bundle size bhi batata hai:

```
dist/index.html                    0.52 kB │ gzip: 0.31 kB
dist/assets/index-DcP2b5sB.js  212.35 kB │ gzip: 68.21 kB
```

**Bundle size kyun matter karta hai:** 68KB gzip JS — India ke 4G pe ~1 second load time. 2MB gzip — 15+ seconds, users leave kar jaate hain. Performance = user retention.

## Step 3 — Env Vars in Production

7.2 mein `.env` + `VITE_` prefix seekha. Production build mein yeh kaise kaam karta hai:

**Build time injection:** Vite env vars ko **build ke waqt** bundle mein hardcode kar deta hai. Runtime pe nahi padta.

```
Build (bun run build) ke waqt:
  import.meta.env.VITE_QUOTE_API_URL → "https://api.quotable.io/random"
                                        ↑ bundle mein directly likh diya

Phir bundle browser mein chalega — woh URL wahi rahega
```

**Iska matlab:** Deploy se pehle production env vars set karne hote hain. Do tareeke:

**Tareeka 1 — `.env.production` file:**

```
# .env.production
VITE_QUOTE_API_URL=https://api.quotable.io/random
```

Vite `.env.production` ko build time automatically use karta hai (jab `bun run build` chalao).

**Tareeka 2 — Deploy platform ki env settings:** Vercel/Netlify pe dashboard mein env vars set karo (aage deploy step mein dikhayenge).

## Step 5 — Deploy (Vercel)

**Vercel** — React/Vite projects ke liye sabse popular deploy platform (free). Do tareeke: GitHub pe push karo aur Vercel connect karo (auto-deploy), ya CLI se.

### Tareeka 1 — GitHub + Vercel (Recommended)

**Pehle GitHub repo banao aur push karo:**

```bash
git init
git add .
git commit -m "init: custom hooks demo"
git remote add origin https://github.com/yourname/custom-hooks-demo.git
git push -u origin main
```

**Phir Vercel pe:**
1. [vercel.com](https://vercel.com) pe sign up (GitHub se)
2. "Add New Project" → apna repo choose karo
3. Framework: **Vite** (Vercel auto-detect karta hai)
4. Env vars add karo (`VITE_QUOTE_API_URL` agar hai)
5. Deploy karo — URL milega `https://custom-hooks-demo.vercel.app`

**Auto-deploy magic:** GitHub pe har push → Vercel auto-build + auto-deploy. Ye **Continuous Deployment** hai — code push kiya, app update ho gayi.

### Tareeka 2 — Vercel CLI

```bash
bunx vercel
```

CLI prompts ke baad direct deploy ho jata hai.

## Step 6 — Deploy (GitHub Pages)

**GitHub Pages** — GitHub ka free static hosting. Vercel se thoda alag setup chahiye kyunki Pages ko static files chahiye.

**Pehle** `vite.config.ts` mein base set karo — repo naam ke liye:

```ts
// vite.config.ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
  // GitHub Pages pe app repo-subfolder pe serve hoti hai
  base: "/custom-hooks-demo/",
});
```

**Phir build + deploy:**

```bash
bun run build
```

`dist/` folder GitHub Pages pe upload karo — ya toh manually, ya GitHub Actions (workflow file) se.

## Vercel vs GitHub Pages — Kab Kya

| | Vercel | GitHub Pages |
|---|---|---|
| **Setup** | Auto (framework detect) | Manual (base path) |
| **Env vars** | Dashboard pe easy | Build ke waqt set karna hota hai |
| **Continuous Deploy** | GitHub push pe auto | GitHub Actions se |
| **Best for** | Professional portfolio projects | Chhote static projects |

**Recommendation:** Portfolio/capstone ke liye **Vercel** — cleanest setup + auto-deploy. GitHub Pages bhi chalta hai lekin extra config chahiye (base path, Actions).

1. Production build (`bun run build`) mein kya hota hai jo `bun run dev` mein nahi hota?
