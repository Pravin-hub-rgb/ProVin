## The Problem

Most developers can write code. Fewer can:
- Explain their project in 30 seconds
- Describe why they chose Redux over Zustand
- Draw the data model on a whiteboard
- Answer "what would you do differently?"
- Turn a client's vague request into a structured plan

These skills are what separate **junior developers** from **senior developers**. And they're what interviewers actually test.

## The Gap Between Coding and Engineering

**Coding** is writing code that works. **Engineering** is making decisions that hold up under scrutiny.

| Coding | Engineering |
|--------|-------------|
| "I used Redux" | "I chose Redux because the data is relational with many derived views. The cost is more setup. For a simpler app, I'd use Zustand." |
| "I built a to-do app" | "I built a task management system with role-based access, normalized state, and accessible drag-and-drop. The admin can track progress per project and per person." |
| "It works" | "It works, and here are the 12 tests that prove it. Here's what I'd add with a backend." |

This batch teaches you to think like an engineer, not just a coder.

## In Your Own Words

1. What's the difference between coding and engineering?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Coding is writing code that works. Engineering is making decisions that hold up under scrutiny — choosing the right tool for the right reason, understanding tradeoffs, designing data models, and being able to explain why you did what you did. A coder can build a to-do app. An engineer can explain why they used Redux instead of Zustand, why they normalized the state, and what they'd change with a backend.

</details>

2. Why is "I built a to-do app" a weak interview answer?

<details>
<summary>Show Answer</summary>

**Sample Answer:** It doesn't tell the interviewer anything about your skills, decisions, or understanding. "I built a role-based task management system with Kanban board, normalized Redux state, protected routes, accessible drag-and-drop, and 12 tests" tells them: you understand state management, routing, accessibility, testing, and can scope a project. The first answer is a coder's answer; the second is an engineer's answer.

</details>
