```tsx
// Dynamic route — path mein :variable
<Route path="/movies/:id" element={<MovieDetail />} />

// useParams — URL se variable nikaalo
import { useParams } from "react-router-dom";
const { id } = useParams<{ id: string }>();

// Nested Routes — parent-child layout
<Route path="/movies" element={<MoviesLayout />}>
  <Route index element={<MovieList />} />
  <Route path=":id" element={<MovieDetail />} />
</Route>

// Outlet — parent component mein child render karne ki jagah
import { Outlet } from "react-router-dom";
function MoviesLayout() {
  return (
    <div>
      <h1>Movies</h1>
      <Outlet />  {/* child route yahan render hoga */}
    </div>
  );
}
```

## Abhi Tak Kya Hua

3.1 mein React Router ka setup seekha — BrowserRouter, Routes, Route, Link, NavLink, useNavigate. Static routes the — har path fixed tha (`/`, `/movies`, `/about`). Lekin real apps mein URLs dynamic hote hain — jaise `/movies/tt1375666` mein `tt1375666` har movie ke liye change hota hai.

Ab seekhenge: dynamic routes (URL se values capture karna), aur nested routes (layout components reusable banane ka pattern).

## Broader Goal

Dynamic routes ke bina tumhe har movie ke liye alag Route likhna padta — `/movies/inception`, `/movies/interstellar`, `/movies/matrix` — aur agar 1000 movies hain toh 1000 Routes? Yeh possible nahi hai. Dynamic route se ek hi pattern kaam karta hai.

Nested routes ka use case: Movie Browser mein layout component chahte ho — navbar, sidebar, footer — jo har page pe same rahe. Sirf content change ho. Nested routes ke saath layout component ek baar likho, child routes sirf content replace karte hain.

## Step 1 — Dynamic Routes aur `useParams`

### 1.1 Concept — URL Mein Variable

Socho — 3.1 mein tumne static routes banaye. `/movies` pe movie list dikhti thi. Lekin ab jab user kisi specific movie pe click karega, toh usse `/movies/tt1375666` pe jaana hai. Yeh `tt1375666` har movie ke liye change hoga — ek variable hai URL mein.

React Router mein variable capture karne ka tareeka hai — `useParams` hook. Aur URL mein variable define karne ka tareeka hai — `:` prefix.

### 1.2 Syntax — `:` Se Variable Define Karna

Route path mein jahan bhi variable chahiye, wahan colon laga do:

```tsx
<Route path="/movies/:id" element={<MovieDetail />} />
```

Yeh visual mapping samajh:

```
URL:           /movies/tt1375666
                      └────────── yeh segment variable hai

Route Path:    /movies/:id
                      └── :id capture karega "tt1375666"
```

`:id` sirf ek label hai. Tum `:movieId`, `:slug`, `:productId` kuch bhi rakh sakte ho. Jo bhi label doge, wahi `useParams` se return hoga — `{ movieId: "..." }` ya `{ slug: "..." }`.

### 1.3 Minimal Example — Sirf `useParams` Ka Use

Pehle ek simple component dekho — sirf URL se ID nikaal ke dikhata hai:

```tsx
// components/MovieDetail.tsx — minimal version
import { useParams } from "react-router-dom";

export default function MovieDetail() {
  const { id } = useParams();
  return <h2>Movie ID: {id}</h2>;
}
```

Bus itna. `useParams()` return karta hai ek object — `{ id: "tt1375666" }`. Destructuring se `id` variable mil gaya. Ab is `id` se kuch bhi kar sakte ho — API call, data lookup, etc.

### 1.4 Flow — Jab User `/movies/tt1375666` Pe Jata Hai

Step by step kya hota hai:

1. Browser URL change hota hai — `/movies/tt1375666`
2. React Router `Routes` mein se matching path dhunndhta hai — `"/movies/:id"` match ho gaya
3. `:id` ne URL ka variable segment capture kiya — `"tt1375666"`
4. React Router yeh parsed value store karta hai internally
5. `<MovieDetail />` component render hota hai
6. Component ke andar `useParams()` call hota hai — React Router stored value return karta hai: `{ id: "tt1375666" }`
7. Destructuring se `id = "tt1375666"` milta hai

Har dynamic route yahi pattern follow karta hai. URL segment capture → `useParams` → use karo.

### 1.5 Real Example — MovieDetail with Data Lookup

Ab asli component banate hain jo ID ke hisaab se movie dikhaye:

```tsx
// components/MovieDetail.tsx — full version
import { useParams } from "react-router-dom";

// Step 1 — movie data (normally API se aata hai)
const movieData: Record<string, { title: string; year: number; director: string; plot: string }> = {
  tt1375666: { title: "Inception", year: 2010, director: "Christopher Nolan", plot: "A thief who steals corporate secrets through dream-sharing technology." },
  tt0816692: { title: "Interstellar", year: 2014, director: "Christopher Nolan", plot: "A team of explorers travel through a wormhole in space." },
  tt0133093: { title: "The Matrix", year: 1999, director: "The Wachowskis", plot: "A computer hacker learns about the true nature of his reality." },
  tt0167260: { title: "The Lord of the Rings: The Return of the King", year: 2003, director: "Peter Jackson", plot: "Gandalf and Aragorn lead the World of Men against Sauron's army." },
  tt0111161: { title: "The Shawshank Redemption", year: 1994, director: "Frank Darabont", plot: "Over the course of several years, two convicts form a friendship." },
};

export default function MovieDetail() {
  // Step 2 — URL se ID nikaalo
  const { id } = useParams<{ id: string }>();

  // Step 3 — ID se movie dhunndho
  const movie = movieData[id ?? ""];

  // Step 4 — guard: movie mili ya nahi
  if (!movie) {
    return <h2>Movie not found</h2>;
  }

  // Step 5 — render
  return (
    <div className="movie-detail">
      <h1>{movie.title}</h1>
      <p><strong>Year:</strong> {movie.year}</p>
      <p><strong>Director:</strong> {movie.director}</p>
      <p>{movie.plot}</p>
    </div>
  );
}
```

Har step ka kaam clear hai:
- **Step 1:** Movie data — normally API se fetch hota hai, abhi hardcoded rakha hai samajhne ke liye
- **Step 2:** `useParams` se URL ka `:id` capture kiya
- **Step 3:** `movieData[id]` se matching movie dhunndhi
- **Step 4:** Agar movie nahi mili (invalid ID), toh "not found" dikhao
- **Step 5:** Movie mil gayi toh uski details render karo

### Agar ID invalid hai toh?

Hamesha guard dalna — `if (!movie)` case handle karo. User browser mein directly `/movies/abc123` type karega toh woh movie exist nahi karegi. `MovieDetail` component ko har state handle karna chahiye — found, not found, loading (agar API se fetch kar rahe ho).

> **What It Is NOT:** `useParams` URL parse nahi karta — React Router karta hai. `useParams` sirf parsed values return karta hai jo Route path mein `:variable` se match hui hain. Aur `useParams` TypeScript generic leta hai — `<{ id: string }>` — isse return type properly typed hota hai.

## Step 2 — Nested Routes with Outlet

### 2.1 Concept — Repeat Se Bachna

3.1 mein tumne dekha — har page component mein navbar alag se daalna padta hai:

```tsx
// 3.1 style — har component mein navbar repeat
function HomePage() {
  return (
    <div>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/movies">Movies</Link>
      </nav>
      <h2>Home</h2>
    </div>
  );
}

function MovieList() {
  return (
    <div>
      <nav>                     {/* same navbar dubara */}
        <Link to="/">Home</Link>
        <Link to="/movies">Movies</Link>
      </nav>
      <h2>Movies</h2>
    </div>
  );
}
```

Agar navbar mein kuch change karna hai, toh har component mein jaake change karo. Nested routes is problem ko solve karte hain — parent route ek layout component provide karta hai, child routes sirf content.

### 2.2 Visual — Route Tree

Nested routes ko ek tree ki tarah socho:

```
Path: "/"
└── Layout (navbar + Outlet)
    ├── index       → HomePage    (URL: /)
    ├── movies      → MovieList   (URL: /movies)
    ├── movies/:id  → MovieDetail (URL: /movies/tt1375666)
    └── *           → NotFound    (URL: /xyz)
```

Parent route (`/`) ka element `<Layout />` hai. Layout ke andar `<Outlet />` — yeh child route ka component render karne ki jagah hai. Jab URL `/movies` hai, toh Layout ke Outlet mein MovieList render hoga.

### 2.3 Minimal Example — Outlet in Action

Pehle sirf do child routes se samajhte hain:

```tsx
// App.tsx
import { BrowserRouter, Routes, Route, Link, Outlet } from "react-router-dom";

function Layout() {
  return (
    <div>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/movies">Movies</Link>
      </nav>
      <hr />
      <Outlet />  {/* child route yahan render hoga */}
    </div>
  );
}

export default function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Layout />}>
          <Route index element={<HomePage />} />
          <Route path="movies" element={<MovieList />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}
```

Notice pattern:
- **Parent:** `<Route path="/" element={<Layout />}>` — `/` pe Layout render hoga
- **Index child:** `<Route index element={<HomePage />} />` — jab URL exactly `/` hai, Outlet mein HomePage render hoga
- **Relative path:** `<Route path="movies" ... />` — `path` parent ke relative hai. Poorna path `/movies` hoga. Outlet mein MovieList render hoga

**Kya render hoga visually:**

```
URL: /
     ↓
Layout renders → <nav>Home | Movies</nav> <hr /> [Outlet → HomePage]

URL: /movies
     ↓
Layout renders → <nav>Home | Movies</nav> <hr /> [Outlet → MovieList]
```

Outlet ek switch ki tarah kaam karta hai — child route ke hisaab se content badalta hai, Layout (navbar + hr) wahi rehta hai.

### 2.4 Build Up — Adding Dynamic Route aur 404

Ab baaki routes add karte hain:

```tsx
<Route path="/" element={<Layout />}>
  <Route index element={<HomePage />} />
  <Route path="movies" element={<MovieList />} />
  <Route path="movies/:id" element={<MovieDetail />} />  {/* dynamic */}
  <Route path="*" element={<NotFound />} />               {/* 404 */}
</Route>
```

Har naya route sirf content badalta hai. Layout same rehta hai. `/movies/tt1375666` pe bhi Layout render hoga, bas Outlet mein MovieDetail dikhega.

**Important:** `useParams` nested routes mein bhi kaam karta hai. `MovieDetail` ab Layout ke child route mein hai, lekin `useParams()` abhi bhi `{ id: "tt1375666" }` return karega. React Router URL ko parent + child combine karke match karta hai — `"movies/:id"` actually `"/" + "movies/:id"` = `"/movies/:id"` hai.

### 2.5 Index Route — Kya Aur Kyun

`<Route index>` ka matlab hai "jab parent route ka path exactly match ho, toh yeh default child render karo." Iske bina tumhe alag `<Route path="/" element={<HomePage />} />` likhna padta jo Layout ke bahar hota.

Index route ka fark: parent route ke layout ke *andar* render hota hai. Alag route parent ke layout ko include nahi karta — navbar nahi dikhega.

### 2.6 Relative vs Absolute Paths

Nested routes mein `path` parent ke relative hoti hai. Agar parent ka path `"movies"` hai, toh child ka path `":id"` automatically `"movies/:id"` banega. Absolute path ke liye `/` prefix do: `<Route path="/about" element={<About />} />` — yeh parent se independent hai, seedha root `/about` pe render hoga.

### 2.7 What It Is NOT — Outlet aur Nested Routes

- **`<Outlet />` koi extra DOM element nahi render karta** — yeh sirf placeholder hai. DevTools mein child ka component dikhega, Outlet ka koi trace nahi.
- **Nested routes ≠ JSX nesting** — `<Route>` nesting URL nesting hai, DOM nesting nahi. Child component tab tak Layout ke andar nahi hai jab tak Layout mein `<Outlet />` na ho.
- **`useParams` sirf Route ke children mein kaam karta hai** — component `<Route element={...} />` mein diya hona chahiye. Layout ke andar kahin bhi ho toh kaam karta hai, lekin Route ke bahar ka component call karega toh undefined.

## Step 3 — Movie Browser Complete

Ab dono concepts (dynamic routes + nested routes) ko combine karte hain. 3.1 ke Movie Browser ko nested routes mein refactor karte hain.

### Before — 3.1 Style (Flat Routes)

```tsx
// App.tsx — 3.1 style
import { BrowserRouter, Routes, Route, Link } from "react-router-dom";

function HomePage() {
  return (
    <div>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/movies">Movies</Link>
      </nav>
      <hr />
      <h2>Welcome to Movie Browser</h2>
    </div>
  );
}

export default function App() {
  return (
    <BrowserRouter>
      <div className="app">
        <Routes>
          <Route path="/" element={<HomePage />} />
          <Route path="/movies" element={<MovieList />} />
          <Route path="*" element={<h2>404 — Page not found</h2>} />
        </Routes>
      </div>
    </BrowserRouter>
  );
}
```

Problems:
1. Navbar sirf `HomePage` mein hai — `/movies` pe nahi dikhega
2. `MovieList` mein bhi navbar daalna padega, repeat karke
3. Naya page add karna hai toh usme bhi navbar daalo — maintenance nightmare

### After — 3.2 Style (Nested Routes)

```tsx
// App.tsx
import { BrowserRouter, Routes, Route, Link, Outlet } from "react-router-dom";
import MovieList from "./components/MovieList";
import MovieDetail from "./components/MovieDetail";

function Layout() {
  return (
    <div className="app">
      <nav>
        <Link to="/">Home</Link>
        <Link to="/movies">Movies</Link>
      </nav>
      <Outlet />
    </div>
  );
}

function HomePage() {
  return <h2>Welcome to Movie Browser</h2>;
}

function NotFound() {
  return <h2>404 — Page not found</h2>;
}

export default function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Layout />}>
          <Route index element={<HomePage />} />
          <Route path="movies" element={<MovieList />} />
          <Route path="movies/:id" element={<MovieDetail />} />
          <Route path="*" element={<NotFound />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}
```

Kya badla:
- **Navbar ek baar:** `Layout` mein hai, har page pe dikhega
- **Naya page add karna:** Sirf ek `Route` line — layout automatically mil jayega
- **`useParams` works:** `MovieDetail` nested route mein hai, `useParams` kaam karega
- **404 consistent:** `*` Layout ke andar hai, 404 page mein bhi navbar dikhega

### Folder Structure

```
src/
├── components/
│   ├── MovieList.tsx
│   └── MovieDetail.tsx
├── App.tsx
└── main.tsx
```

`Layout` ko `App.tsx` mein hi rakha hai kyunki chhota hai. Bada hoga toh alag file mein nikaal lena.

### Feature Comparison

| Feature | Static Routes (3.1) | Nested Routes (3.2) |
|---|---|---|
| Layout | Har route ke component mein repeat | Ek baar parent mein, `<Outlet />` child render karta hai |
| Navbar | Har component mein alag se | Parent `Layout` mein ek baar |
| Path pattern | Fixed (`/movies`) | Dynamic (`/movies/:id`) |
| URL data capture | Nahi | `useParams` se |
| Add new page | + Component + Route + Layout repeat | Sirf + Route |

Nested routes ka real benefit tab dikhta hai jab layouts complex ho — sidebar, breadcrumbs, loading states sab parent route mein handle kar sakte ho. Child routes sirf content pe focus karte hain.

## What It Is NOT

- **Nested routes components ko physically nest nahi karte** — `<Outlet />` decide karta hai ki child component kahan render hoga. JSX nesting ka koi lena-dena nahi hai.
- **`useParams` har component mein kaam nahi karega** — sirf woh component jo `<Route element={...} />` mein diya gaya ho. Agar component Route ke andar kahin deep ho, toh bhi kaam karta hai — lekin Route ke bahar ka koi component useParams call karega toh undefined milega.
- **`Outlet` DOM mein koi extra wrapper nahi banata** — DevTools mein sirf child component dikhega. Outlet sirf ek concept hai — "child yahan render karo."

## In Your Own Words

<details>
<summary>Dynamic route kya hota hai? `useParams` kaise kaam karta hai?</summary>

Dynamic route ek aisa route hai jisme path ka kuch part variable hota hai — colon (`:`) se mark karte hain, jaise `/movies/:id`. `useParams` ek React Router hook hai jo current URL se in variables ki value nikaalta hai. Jaise URL `/movies/tt1375666` hai toh `useParams()` return karega `{ id: "tt1375666" }`.
</details>

<details>
<summary>Nested routes kya problem solve karte hain?</summary>

Bina nested routes ke har page ke component mein navbar, sidebar, footer repeat karna padta hai. Nested routes mein ek parent route layout component provide karta hai (navbar + `<Outlet />`), aur child routes sirf content change karte hain. Layout code ek hi jagah rehta hai, repeat nahi hota.
</details>

<details>
<summary>`<Outlet />` component ka kya kaam hai?</summary>

`Outlet` ek placeholder component hai jo parent route ke layout mein child route ka element render karne ke liye jagah banata hai. Parent component mein `<Outlet />` jahan rakhte ho, child route ka component wahan render hota hai. Iske bina nested routes ka koi fayda nahi — parent mein koi rendering point nahi hoga.
</details>

<details>
<summary>Index route kya hota hai? Kab use karna chahiye?</summary>

Index route parent route ka default child hota hai — tab render hota hai jab parent route ka path exactly match ho. Jaise `<Route path="/" element={<Layout />}>` mein `<Route index element={<Home />} />` ka matlab hai "jab `/` pe hoon, toh Layout ke andar Home dikhao." Index route ke bina tumhe alag Route component banana padta jo parent layout ko include nahi karta.
</details>
