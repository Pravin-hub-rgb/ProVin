## Abhi Tak Kya Hua

3.1 mein React Router ka setup seekha — BrowserRouter, Routes, Route, Link, NavLink, useNavigate. Static routes the — har path fixed tha (`/`, `/movies`, `/about`). Lekin real apps mein URLs dynamic hote hain — jaise `/movies/tt1375666` mein `tt1375666` har movie ke liye change hota hai.

Ab seekhenge: dynamic routes (URL se values capture karna), aur nested routes (layout components reusable banane ka pattern).

## Broader Goal

Dynamic routes ke bina tumhe har movie ke liye alag Route likhna padta — `/movies/inception`, `/movies/interstellar`, `/movies/matrix` — aur agar 1000 movies hain toh 1000 Routes? Yeh possible nahi hai. Dynamic route se ek hi pattern kaam karta hai.

Nested routes ka use case: Movie Browser mein layout component chahte ho — navbar, sidebar, footer — jo har page pe same rahe. Sirf content change ho. Nested routes ke saath layout component ek baar likho, child routes sirf content replace karte hain.

## Step 1 — Dynamic Routes aur `useParams`

### 1.1 Concept — URL Mein Variable

Socho — 3.1 mein tumne static routes banaye — `/`, `/movies`, `/about`. Ab hum ek product catalog banayenge. Har product ka apna URL hoga — `/products/p1`, `/products/p2`, `/products/p3`. Yeh `p1` part har product ke liye change hoga — ek variable hai URL mein.

React Router mein variable capture karne ka tareeka hai — `useParams` hook. Aur URL mein variable define karne ka tareeka hai — `:` prefix.

### 1.2 Syntax — `:` Se Variable Define Karna

Route path mein jahan bhi variable chahiye, wahan colon laga do:

```tsx
<Route path="/products/:id" element={<ProductDetail />} />
```

Yeh visual mapping samajh:

```
URL:           /products/p1
                      └── yeh segment variable hai

Route Path:    /products/:id
                      └── :id capture karega "p1"
```

`:id` sirf ek label hai. Tum `:productId`, `:slug`, `:itemId` kuch bhi rakh sakte ho. Jo bhi label doge, wahi `useParams` se return hoga — `{ productId: "..." }` ya `{ slug: "..." }`.

### 1.3 Minimal Example — Sirf `useParams` Ka Use

Pehle ek simple component dekho — sirf URL se ID nikaal ke dikhata hai:

```tsx
// components/ProductDetail.tsx — minimal version
import { useParams } from "react-router-dom";

export default function ProductDetail() {
  const { id } = useParams();
  return <h2>Product ID: {id}</h2>;
}
```

Bus itna. `useParams()` return karta hai ek object — `{ id: "p1" }`. Destructuring se `id` variable mil gaya. Ab is `id` se kuch bhi kar sakte ho — API call, data lookup, etc.

### 1.4 Flow — Jab User `/products/p1` Pe Jata Hai

Step by step kya hota hai:

1. Browser URL change hota hai — `/products/p1`
2. React Router `Routes` mein se matching path dhunndhta hai — `"/products/:id"` match ho gaya
3. `:id` ne URL ka variable segment capture kiya — `"p1"`
4. React Router yeh parsed value store karta hai internally
5. `<ProductDetail />` component render hota hai
6. Component ke andar `useParams()` call hota hai — React Router stored value return karta hai: `{ id: "p1" }`
7. Destructuring se `id = "p1"` milta hai

Har dynamic route yahi pattern follow karta hai. URL segment capture → `useParams` → use karo.

### 1.5 Real Example — ProductDetail with Data Lookup

Ab asli component banate hain jo ID ke hisaab se product dikhaye:

```tsx
// components/ProductDetail.tsx — full version
import { useParams } from "react-router-dom";

// Step 1 — product data (array of objects, har object ki apni id)
const products = [
  { id: "p1", name: "Wireless Headphones", price: 2499, desc: "Noise-cancelling Bluetooth 5.0 headphones with 30hr battery life." },
  { id: "p2", name: "Smart Watch", price: 3999, desc: "Fitness tracker with heart rate monitor, GPS, and 7 days battery." },
  { id: "p3", name: "USB-C Hub", price: 1299, desc: "7-in-1 USB-C hub with HDMI 4K, USB 3.0, and SD card reader." },
];

export default function ProductDetail() {
  // Step 2 — URL se ID nikaalo
  const { id } = useParams<{ id: string }>();

  // Step 3 — ID se product dhunndho (.find array method)
  const product = products.find(p => p.id === id);

  // Step 4 — guard: product mila ya nahi
  if (!product) {
    return <h2>Product not found</h2>;
  }

  // Step 5 — render
  return (
    <div className="product-detail">
      <h1>{product.name}</h1>
      <p><strong>Price:</strong> ₹{product.price}</p>
      <p>{product.desc}</p>
    </div>
  );
}
```

Har step ka kaam clear hai:
- **Step 1:** Product data — array of objects, har product ki apni `id` property hai. Normally API se fetch hota hai, abhi hardcoded rakha hai.
- **Step 2:** `useParams` se URL ka `:id` capture kiya
- **Step 3:** `products.find(p => p.id === id)` — array mein se pehla matching object dhunndhta hai. Mil gaya toh object return, nahi mila toh `undefined`.
- **Step 4:** Agar product nahi mila (invalid ID), toh "not found" dikhao
- **Step 5:** Product mil gaya toh uski details render karo

> **Array kyun?** Array pe `.map()` bhi chalta hai (list render karne ke liye) aur `.find()` bhi (lookup ke liye). Record (object) pe sirf bracket notation `[id]` chalta hai, `.map()` nahi. Isliye abhi se array use kar rahe hain — dono kaam ho jayenge.

### Agar ID invalid hai toh?

Hamesha guard dalna — `if (!product)` case handle karo. User browser mein directly `/products/xyz` type karega toh woh product exist nahi karega. `ProductDetail` component ko har state handle karna chahiye — found, not found, loading (agar API se fetch kar rahe ho).

> **What It Is NOT:** `useParams` URL parse nahi karta — React Router karta hai. `useParams` sirf parsed values return karta hai jo Route path mein `:variable` se match hui hain. Aur `useParams` TypeScript generic leta hai — `<{ id: string }>` — isse return type properly typed hota hai.

## Step 2 — Nested Routes with Outlet

### 2.1 Nested Routes Ka Syntax

#### Do Tarike — Ek Hi Kaam

3.1 mein humne ek line mein route banaya:

```tsx
<Route path="/products/:id" element={<ProductDetail />} />
```

Yeh **flat route** hai — sab kuch ek hi line mein, path bhi full, component bhi. Kaam karta hai, simple hai.

Lekin kya hoga agar `/products` ke under aur bhi routes chahiye? Jaise featured products, reviews, etc.:

```tsx
<Route path="/products/:id" element={<ProductDetail />} />
<Route path="/products/featured" element={<FeaturedProducts />} />
<Route path="/products/reviews" element={<Reviews />} />
```

Dekho — **`/products/` har baar repeat** ho raha hai. Agar 10 routes hain toh 10 baar. Aur agar parent path change karna hai (`/catalog`), toh har route mein jaake change karo.

Yahi problem solve karta hai **nested routes** — ek parent `Route` jiska path ek baar likho, aur child routes jinka sirf unique part likho:

```tsx
<Route path="products">
  <Route path=":id" element={<ProductDetail />} />
  <Route path="featured" element={<FeaturedProducts />} />
  <Route path="reviews" element={<Reviews />} />
</Route>
```

Parent path `"products"` automatically sab children ke aage lag jata hai. React Router khud combine karta hai.

#### Dono Approach — Same Result

| Flat Route (3.1 style) | Nested Route (3.2 style) |
|---|---|
| `<Route path="/products/:id" ... />` | `<Route path="products"><Route path=":id" ... /></Route>` |
| `<Route path="/products/featured" ... />` | `<Route path="products"><Route path="featured" ... /></Route>` |
| `<Route path="/products/reviews" ... />` | `<Route path="products"><Route path="reviews" ... /></Route>` |

**URL result same hai** — `/products/ps5`, `/products/featured`, `/products/reviews`. Fark sirf code organization ka hai.

#### Devs Nesting Kyun Use Karte Hain?

1. **Repeat nahi karna padta** — `/products/` ek baar parent mein likho, baar baar nahi
2. **URL structure clear** — sab `/products` ke under hain, hierarchy dikhti hai
3. **Parent path change karna ho toh ek jagah** — parent ka `path` `"products"` se `"catalog"` karo, sab children automatically update
4. **Future mein parent ko `element` + `<Outlet />` de sakte ho** — ek baar layout banao, sab children uske andar render hon (agli section mein detail)

#### Multiple Children

```tsx
<Route path="products">
  <Route path=":id" element={<ProductDetail />} />
  <Route path="featured" element={<FeaturedProducts />} />
  <Route path="reviews" element={<Reviews />} />
</Route>
```

Sab child apne parent ke path ke relative hain:

| Child Path | Full URL | Component |
|---|---|---|
| `:id` | `/products/ps5` | ProductDetail |
| `featured` | `/products/featured` | FeaturedProducts |
| `reviews` | `/products/reviews` | Reviews |

#### Parent Ke Paas `element` Optional Hai

Dhyan do — abhi parent `Route` ka koi `element` nahi hai:

```tsx
<Route path="products">           {/* no element prop — sirf grouping */}
  <Route path=":id" element={<ProductDetail />} />
</Route>
```

Yeh sirf **grouping** ke liye hai — child routes ke paths ko organize karne ke liye. Lekin parent ko `element` bhi de sakte ho — woh tab kaam aata hai jab tumhe sab children ke liye ek common layout chahiye (jaise navbar). Woh hum agle section mein dekhenge.

#### Key Points

- **Flat route = ek line mein sab** — simple, kam routes ke liye theek hai
- **Nested route = parent grouping children** — organized, maintainable, repeat bachata hai
- **Dono same URL generate karte hain** — fark sirf code structure ka hai
- **Parent ka `element` optional** — bina element ke sirf grouping, element ke saath layout+Outlet
- **Ek parent ke kai child ho sakte hain** — har child ka apna path, apna component

### 2.2 Problem — Repeat Se Bachna

3.1 mein tumne dekha — har page component mein navbar alag se daalna padta hai:

```tsx
// Old style — har component mein navbar repeat
function HomePage() {
  return (
    <div>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/products">Products</Link>
      </nav>
      <h2>Home</h2>
    </div>
  );
}

function ProductList() {
  return (
    <div>
      <nav>                     {/* same navbar dubara */}
        <Link to="/">Home</Link>
        <Link to="/products">Products</Link>
      </nav>
      <h2>Products</h2>
    </div>
  );
}
```

Agar navbar mein kuch change karna hai, toh har component mein jaake change karo. Nested routes is problem ko solve karte hain — parent route ek layout component provide karta hai, child routes sirf content.

### 2.3 Visual — Route Tree

Nested routes ko ek tree ki tarah socho:

```
Path: "/"
└── Layout
    ├── index       → HomePage     (URL: /)
    ├── products    → ProductList  (URL: /products)
    ├── products/:id → ProductDetail (URL: /products/p1)
    └── *           → NotFound     (URL: /xyz)
```

Parent route (`/`) ka element `<Layout />` hai. Layout ke andar child routes ka content render hoga. Jab URL `/products` hai, toh Layout ke andar ProductList render hoga. Jab URL `/products/p1` hai, toh ProductDetail render hoga.

> 2.1 mein dekha — parent Route bina element ke sirf grouping ke liye kaam karta hai. Yahan parent ko **element** de rahe hain — ek Layout component. Layout decide karega ki child content kahan dikhega (agli section mein dekhenge kaise).

### 2.4 Solution — Layout + Outlet

Ab problem clear hai — navbar repeat ho raha hai. Nested routes ka syntax bhi clear hai (2.1). Ab dekhte hain kaise parent route ka `element` + `Outlet` milkar is problem ko solve karte hain.

#### Outlet Kya Hai?

`<Outlet />` ek **placeholder component** hai jo React Router provide karta hai. Tum isse parent Layout mein rakhoge — aur jo bhi child route match karega, woh Outlet mein render ho jayega.

Socho ek **TV aur HDMI port** ki tarah:
- `Layout` = TV (navbar fixed hai, frame wahi rehta hai)
- `<Outlet />` = HDMI port (jahan bhi device lagao, wahan content aata hai)
- Child route = jo device tum lagao (PlayStation = Home, Fire Stick = Products)

TV ka frame nahi badalta. Sirf HDMI port pe content badalta hai.

#### Syntax

```tsx
import { Outlet } from "react-router-dom";

function Layout() {
  return (
    <div>
      <nav>Home | Products</nav>
      <Outlet />     {/* child route yahan render hoga */}
    </div>
  );
}
```

Parent route mein `element={<Layout />}` do, aur Layout ke andar `<Outlet />` rakh do:

```tsx
<Route path="/" element={<Layout />}>     {/* Layout render hoga */}
  <Route index element={<HomePage />} />    {/* → Layout ke Outlet mein */}
  <Route path="products" element={<ProductList />} />  {/* → Layout ke Outlet mein */}
</Route>
```

#### Kaam Kaise Karta Hai?

```
URL: /             → Layout render → Outlet → HomePage
URL: /products     → Layout render → Outlet → ProductList
```

Layout har baar render hota hai (navbar dikhta hai). Sirf Outlet ka content badalta hai — child route ke hisaab se.

#### Outlet Ke Bina Kya Hota?

Agar parent ke paas `<Outlet />` nahi hai, toh child routes render hi nahi honge:

```tsx
function Layout() {
  return (
    <div>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/products">Products</Link>
      </nav>
      {/* ❌ Outlet nahi hai — child routes kabhi render nahi honge */}
    </div>
  );
}
```

Tab `/products` pe jao ge toh sirf navbar dikhega, ProductList nahi. `Outlet` woh jagah hai jo React Router ko batati hai "child yahan daal do."

#### Minimal Code — Outlet in Action

Sirf do child routes se samajhte hain:

```tsx
// App.tsx
import { BrowserRouter, Routes, Route, Link, Outlet } from "react-router-dom";

function Layout() {
  return (
    <div>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/products">Products</Link>
      </nav>
      <hr />
      <Outlet />  {/* child route yahan render hoga */}
    </div>
  );
}

export default function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Layout />}>
          <Route index element={<HomePage />} />
          <Route path="products" element={<ProductList />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}
```

Notice pattern — yeh wahi nesting hai jo 2.1 mein seekha, bas ab **parent ke paas `element` bhi hai**:
- **Parent:** `<Route path="/" element={<Layout />}>` — `/` pe Layout render hoga. Layout ke andar `<Outlet />` hai — child yahan render hoga
- **Index child:** `<Route index element={<HomePage />} />` — jab URL exactly `/` hai, Outlet mein HomePage render hoga
- **Relative path:** `<Route path="products" ... />` — `path` parent ke relative hai (2.1 ka concept). Poorna path `/products` hoga. Outlet mein ProductList render hoga

**Kya render hoga visually:**

```
URL: /
     ↓
Layout renders → <nav>Home | Products</nav> <hr /> [Outlet → HomePage]

URL: /products
     ↓
Layout renders → <nav>Home | Products</nav> <hr /> [Outlet → ProductList]
```

Outlet ek switch ki tarah kaam karta hai — child route ke hisaab se content badalta hai, Layout (navbar + hr) wahi rehta hai.

### 2.5 Build Up — Adding Dynamic Route aur 404

Ab Layout + Outlet ka setup ready hai. Naye routes daalna simple hai — bas child `<Route>` add karo. Do aur routes daalte hain:

```tsx
<Route path="/" element={<Layout />}>
  <Route index element={<HomePage />} />
  <Route path="products" element={<ProductList />} />
  <Route path="products/:id" element={<ProductDetail />} />  {/* dynamic */}
  <Route path="*" element={<NotFound />} />                   {/* 404 */}
</Route>
```

Ab Layout ke 4 child routes hain:

| Route | URL | Component | Kahan se aaya |
|---|---|---|---|
| `index` | `/` | HomePage | 2.4 mein seekha |
| `products` | `/products` | ProductList | 2.4 mein seekha |
| `products/:id` | `/products/p1` | ProductDetail | **Step 1** ka dynamic route, ab Layout ke under |
| `*` | `/xyz` | NotFound | **3.1** ka catch-all, ab Layout ke under |

Har naya route sirf content badalta hai. Layout same rehta hai — `/products/p1` pe bhi Layout render hoga, bas Outlet mein ProductDetail dikhega. Aur `*` pe bhi Layout render hoga, bas Outlet mein NotFound — matlab **404 page pe bhi navbar dikhega** (jo 3.1 mein nahi tha).

> **Important — `useParams` Nested Routes Mein:** `useParams` ko nesting se koi fark nahi padta. Chahe `ProductDetail` flat ho (Step 1 style) ya nested (Layout ke child), URL wahi hai — `/products/p1`. `useParams` URL se value nikaalta hai, route tree se nahi. Toh `useParams()` hamesha `{ id: "p1" }` return karega.

### 2.6 Index Route — Kya Aur Kyun

Jab nested routes banate ho, toh ek problem aati hai: **"Jab URL sirf `/` (parent path) ho, tab child route mein kya dikhe?"**

Neeche dekho — teen child routes hain, lekin `/` ke liye koi nahi:

```tsx
<Route path="/" element={<Layout />}>
  <Route path="products" element={<ProductList />} />
  <Route path="products/:id" element={<ProductDetail />} />
  <Route path="*" element={<NotFound />} />
</Route>

// Jab URL "/" hai → Layout render hoga, lekin Outlet KHALI
// Koi child match nahi kiya — kuch nahi dikhega content area mein
```

Yeh problem solve karta hai **index route**.

#### Index Route Kya Hai?

`<Route index>` ka matlab hai — **"parent ka path exactly match ho, tab yeh default child render karo."**

Iska apna `path` nahi hota. Yeh parent ke path par hi render hota hai — lekin parent ke Layout ke ANDAR (Outlet mein).

```tsx
<Route path="/" element={<Layout />}>
  <Route index element={<HomePage />} />              {/* path nahi likhte */}
  <Route path="products" element={<ProductList />} />
  <Route path="products/:id" element={<ProductDetail />} />
  <Route path="*" element={<NotFound />} />
</Route>

// Jab URL "/" hai → Layout render → Outlet mein HomePage
```

#### Index Route Bina — Kya Hota?

Bina index route ke tum yeh karte:

```tsx
<Routes>
  <Route path="/" element={<HomePage />} />    {/* alag — Layout ke BAHAR */}
  <Route path="/" element={<Layout />}>         {/* alag route */}
    <Route path="products" element={<ProductList />} />
  </Route>
</Routes>
```

**Problem:** `/` pe Layout render hi nahi hoga! Sirf `<HomePage />` dikhega — **navbar nahi dikhega**, kyunki Layout ke bahar hai.

#### Visual Comparison

Samajhne ka sabse aasan tareeka — yeh do visuals dekho:

**Bina index route (galat approach):**
```
URL: /
     ↓
Layout call hi nahi hua
Sirf <HomePage /> dikha — app tooti hui lagti hai
```

**Index route ke saath (sahi approach):**
```
URL: /
     ↓
Layout → <nav>Home | Products</nav> → [Outlet → HomePage]
                                               ↑
                                   index route ne decide kiya
                                   "default child → HomePage"
```

#### Real-Life Analogy

Socho tum ek **shopping mall** mein ho (`Layout`). Mall ka har section ek child route hai:

| Section | URL | Content |
|---|---|---|
| Entrance (index) | `/` | Welcome desk, map |
| Electronics Store | `/products` | Product List |
| Specific Product | `/products/p1` | Product Detail |

Jab tum mall mein **sirf enter karte ho** (URL = `/`), toh kisi specific store mein nahi jaate. Tum entrance area mein ho — **index route** ne decide kiya "entrance pe welcome desk dikhao."

Agar index route nahi hota, toh mall mein ghuste hi **suna suna lobby** dikhta — koi content nahi.

#### Index Route Ke Rules

- **`path` property nahi hoti** — `<Route index>` likho, `<Route index path="..." />` nahi
- **Sirf parent ke nested children mein** — standalone `Route` nahi ho sakta
- **Har parent ka sirf EK index route** — do index routes nahi ho sakte
- **Parent path exactly match pe render** — `/products` match nahi karega, sirf `/`

#### Kab Use Karna Chahiye?

✅ **Use karo jab:**
- Parent route ka layout hai (navbar, sidebar, etc.)
- Tum chahte ho ki parent path pe kuch content dikhe
- Woh content layout ke ANDAR dikhna chahiye

❌ **Mat use karo jab:**
- Parent route ka koi layout nahi hai
- Tum chahte ho ki `/` pe ek completely different page dikhe (bina layout ke)
- Parent route pe koi default content nahi chahiye

#### Summary

```
Index route = default child for parent's path
              ├── No path property
              ├── Renders inside parent Layout
              ├── Only when URL = parent's exact path
              └── One per parent
```

### 2.7 Relative vs Absolute Paths

Nested routes mein `path` do tarah se likh sakte ho — **relative** (bina `/`) aur **absolute** (`/` se shuru).

#### Relative Path — Default Behavior

Jab child route ka path **bina `/`** likhte ho, toh woh parent ke path ke RELATIVE hota hai:

```tsx
<Route path="products" element={<Layout />}>        {/* parent = /products */}
  <Route path=":id" element={<ProductDetail />} />   {/* → /products/:id */}
  <Route path="reviews" element={<Reviews />} />      {/* → /products/reviews */}
</Route>
```

React Router parent ka path + child ka path **concat** karta hai:
```
Parent path:  "products"
Child path:   ":id"
Result:       "/products/:id"    ← automatically
```

#### Absolute Path — `/` Prefix

Jab child route ka path **`/` se shuru** karte ho, toh woh parent se INDEPENDENT hota hai — seedha root URL se match karega:

```tsx
<Route path="products" element={<Layout />}>         {/* parent = /products */}
  <Route path="/about" element={<About />} />         {/* → /about, NOT /products/about */}
</Route>
```

`/` prefix ne parent ko ignore kiya — About sirf `/about` pe render hoga, `/products/about` pe nahi.

#### Visual Comparison

```
Parent: "products" (URL = /products)
│
├── Child relative:  "featured"        → /products/featured     ✅
├── Child relative:  ":id"             → /products/ps5          ✅
├── Child absolute:  "/about"          → /about                 ✅ (parent ignore)
├── Child absolute:  "/products/top"   → /products/top          ✅ (explicit full path)
└── Child relative:  "/featured"       → /featured              ❌ WAIT — yeh absolute hai!
                                                   kyunki "/" se start hai
```

#### Rule of Thumb

```
Path start:  without "/"  →  relative (parent ke saath jude ga)
Path start:  with "/"     →  absolute (parent ignore, root se match)
```

#### Common Mistakes

**Mistake 1 — Relative path ko `/` se shuru karna:**
```tsx
<Route path="products" element={<Layout />}>
  <Route path="/:id" element={<ProductDetail />} />   {/* /:id → root pe match */}
</Route>
// Expected: /products/ps5
// Actual:   /ps5
```
Fix: Bina `/` likho — `path=":id"`

**Mistake 2 — Absolute path ko bina `/` ke likhna:**
```tsx
<Route path="products" element={<Layout />}>
  <Route path="about" element={<About />} />           {/* about → /products/about */}
</Route>
// Expected: /about
// Actual:   /products/about
```
Fix: `/` prefix do — `path="/about"`

#### Kab Kya Use Karein?

| Scenario | Path Type | Example |
|---|---|---|
| Child route parent ke under ka hai | Relative | `path="reviews"` → `/products/reviews` |
| Dynamic segment in child | Relative | `path=":id"` → `/products/ps5` |
| Child route ka parent se koi lena-dena nahi | Absolute | `path="/about"` → `/about` |
| Child route ko kisi aur section mein bhi reuse karna hai | Absolute | `path="/trending"` → `/trending` |

#### Real-Life Analogy

Socho tum **floor 2** (`/products`) pe ho. Tum kaho:

- **"bathroom jao"** → floor 2 ka bathroom → `/products/bathroom` (relative — isi floor pe)
- **"/ground-floor par jao"** → ground floor ka bathroom → `/bathroom` (absolute — neeche jao)

Relative = "isi floor ke andar." Absolute = "seedha ground floor pe."

#### Why This Matters

Agar tum relative vs absolute confuse karoge, toh:
- Tumhara `/about` page kabhi dikhega hi nahi (kyunki `/products/about` ho jayega)
- Ya tumhara `:id` route root URL se match karega (`/ps5`), jabki tum chahte the `/products/ps5`

Hamesha check karo: **"yeh route parent ke under hona chahiye ya alag?"** — relative ya absolute decide karo.

### 2.8 What It Is NOT — Outlet aur Nested Routes

- **`<Outlet />` koi extra DOM element nahi render karta** — yeh sirf placeholder hai. DevTools mein child ka component dikhega, Outlet ka koi trace nahi.
- **Nested routes ≠ JSX nesting** — `<Route>` nesting URL nesting hai, DOM nesting nahi. Child component tab tak Layout ke andar nahi hai jab tak Layout mein `<Outlet />` na ho.
- **`useParams` sirf Route ke children mein kaam karta hai** — component `<Route element={...} />` mein diya hona chahiye. Layout ke andar kahin bhi ho toh kaam karta hai, lekin Route ke bahar ka component call karega toh undefined.

  }

      <p><strong>Year:</strong> {movie.year}</p>
      <p><strong>Director:</strong> {movie.director}</p>

}

#### 4. `App.tsx` — Routes + Layout

```tsx
import { BrowserRouter, Routes, Route, Link, Outlet } from "react-router-dom";
import MovieList from "./components/MovieList";
import MovieDetail from "./components/MovieDetail";

function Layout() {
  return (
    <div className="app">
      <nav>
        <Link to="/">Home</Link>
        <Link to="/movies">Movies</Link>
      </nav>
      <Outlet />
    </div>
  );
}

function HomePage() {
  return <h2>Welcome to Movie Browser</h2>;
}

function NotFound() {
  return <h2>404 — Page not found</h2>;
}

export default function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Layout />}>
          <Route index element={<HomePage />} />
          <Route path="movies" element={<MovieList />} />
          <Route path="movies/:id" element={<MovieDetail />} />
          <Route path="*" element={<NotFound />} />
        </Route>
      </Routes>
    </BrowserRouter>
  );
}
```

#### Data Flow — Kahan Se Kahan Tak

```
data/movies.ts  ──import──▶  MovieList.tsx       MovieDetail.tsx
                   │           movies.map()          useParams → id
                   │           grid of cards          movies.find(m => m.id === id)
                   │           <Link> with ID         guard → render
                   │                │
                   └────────────────┘
                        same array, same structure
```

- **Ek hi data source:** `data/movies.ts` dono components import karte hain. Sync ki tension nahi — data ek jagah change karo, dono jagah reflect hoga.
- **MovieList:** Array ko `.map()` karta hai — har movie ke liye ek card, har card mein dynamic link.
- **MovieDetail:** Same array ko `.find()` karta hai — URL se ID nikaal ke matching movie dhunndhta hai.
- **Routing:** Nested routes Layout + Outlet ke saath — navbar ek baar, content change hota hai.

### Feature Comparison

| Feature | Static Routes (3.1) | Nested Routes (3.2) |
|---|---|---|
| Layout | Har route ke component mein repeat | Ek baar parent mein, `<Outlet />` child render karta hai |
| Navbar | Har component mein alag se | Parent `Layout` mein ek baar |
| Path pattern | Fixed (`/movies`) | Dynamic (`/movies/:id`) |
| URL data capture | Nahi | `useParams` se |
| Add new page | + Component + Route + Layout repeat | Sirf + Route |

Nested routes ka real benefit tab dikhta hai jab layouts complex ho — sidebar, breadcrumbs, loading states sab parent route mein handle kar sakte ho. Child routes sirf content pe focus karte hain.

## What It Is NOT

- **Nested routes components ko physically nest nahi karte** — `<Outlet />` decide karta hai ki child component kahan render hoga. JSX nesting ka koi lena-dena nahi hai.
- **`useParams` har component mein kaam nahi karega** — sirf woh component jo `<Route element={...} />` mein diya gaya ho. Agar component Route ke andar kahin deep ho, toh bhi kaam karta hai — lekin Route ke bahar ka koi component useParams call karega toh undefined milega.
- **`Outlet` DOM mein koi extra wrapper nahi banata** — DevTools mein sirf child component dikhega. Outlet sirf ek concept hai — "child yahan render karo."

## In Your Own Words

<details>
<summary>Dynamic route kya hota hai? `useParams` kaise kaam karta hai?</summary>

Dynamic route ek aisa route hai jisme path ka kuch part variable hota hai — colon (`:`) se mark karte hain, jaise `/movies/:id`. `useParams` ek React Router hook hai jo current URL se in variables ki value nikaalta hai. Jaise URL `/movies/tt1375666` hai toh `useParams()` return karega `{ id: "tt1375666" }`.
</details>

<details>
<summary>Nested routes kya problem solve karte hain?</summary>

Bina nested routes ke har page ke component mein navbar, sidebar, footer repeat karna padta hai. Nested routes mein ek parent route layout component provide karta hai (navbar + `<Outlet />`), aur child routes sirf content change karte hain. Layout code ek hi jagah rehta hai, repeat nahi hota.
</details>

<details>
<summary>`<Outlet />` component ka kya kaam hai?</summary>

`Outlet` ek placeholder component hai jo parent route ke layout mein child route ka element render karne ke liye jagah banata hai. Parent component mein `<Outlet />` jahan rakhte ho, child route ka component wahan render hota hai. Iske bina nested routes ka koi fayda nahi — parent mein koi rendering point nahi hoga.
</details>

<details>
<summary>Index route kya hota hai? Kab use karna chahiye?</summary>

Index route parent route ka default child hota hai — tab render hota hai jab parent route ka path exactly match ho. Jaise `<Route path="/" element={<Layout />}>` mein `<Route index element={<Home />} />` ka matlab hai "jab `/` pe hoon, toh Layout ke andar Home dikhao." Index route ke bina tumhe alag Route component banana padta jo parent layout ko include nahi karta.
</details>
