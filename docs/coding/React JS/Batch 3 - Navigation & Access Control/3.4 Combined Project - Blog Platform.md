## Step 2 — AuthContext (Protected Routes Ke Liye)

Pehle authentication setup karte hain — simple dummy auth, jaisa 3.3 mein seekha:

```tsx
// context/AuthContext.tsx
import { createContext, useContext, useState, type ReactNode } from "react";

interface AuthContextValue {
  user: string | null;
  login: (username: string) => void;
  logout: () => void;
}

const AuthContext = createContext<AuthContextValue | undefined>(undefined);

export function useAuth(): AuthContextValue {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("useAuth must be used within AuthProvider");
  return ctx;
}

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<string | null>(null);
  const login = (username: string) => setUser(username);
  const logout = () => setUser(null);

  return (
    <AuthContext value={{ user, login, logout }}>
      {children}
    </AuthContext>
  );
}
```

## Step 3 — ProtectedRoute Component

```tsx
// components/ProtectedRoute.tsx
import { Navigate, useLocation } from "react-router-dom";
import { useAuth } from "../context/AuthContext";
import type { ReactNode } from "react";

export default function ProtectedRoute({ children }: { children: ReactNode }) {
  const { user } = useAuth();
  const location = useLocation();

  if (!user) {
    return <Navigate to="/" state={{ from: location }} replace />;
  }

  return <>{children}</>;
}
```

`state={{ from: location }}` — login ke baad user ko wapas usi page pe bhej sakte hain jahan se redirect hua tha. Abhi implement nahi karenge, but pattern dikh raha hai.

```tsx
// components/Navbar.tsx
import { NavLink } from "react-router-dom";
import { useAuth } from "../context/AuthContext";
import ThemeToggle from "./ThemeToggle";

export default function Navbar() {
  const { user, logout } = useAuth();

  return (
    <nav>
      <NavLink to="/" end>Home</NavLink>
      <NavLink to="/create">Create Post</NavLink>
      <NavLink to="/dashboard">Dashboard</NavLink>
      <ThemeToggle />
      {user && (
        <span>
          {user} <button onClick={logout}>Logout</button>
        </span>
      )}
      {!user && <span>Guest</span>}
    </nav>
  );
}
```

Notice `end` prop in `<NavLink to="/" end>` — iska matlab hai "sirf tab active dikhao jab exactly `/` pe ho." Bina `end` ke, `/create` pe bhi Home active dikhega kyunki `/` se start hota hai. Small detail, big difference.

### PostDetail (Dynamic Route)

```tsx
// pages/PostDetail.tsx
import { useParams, useNavigate, Link } from "react-router-dom";
import { useState } from "react";
import type { Post } from "../types";

// Note: Posts data abhi local state mein hai (Home ke andar).
// Real app mein global store (Zustand/Context) ya API fetch se aayega.
// Abhi ke liye local posts array se simulate karte hain — isliye posts yahan bhi define hai.

export default function PostDetail() {
  const { id } = useParams<{ id: string }>();
  const navigate = useNavigate();

  const [posts] = useState<Post[]>([
    { id: 1, title: "Getting Started with React", content: "React is a library for building user interfaces...", author: "Vin", createdAt: "2026-01-15" },
    { id: 2, title: "Understanding useEffect", content: "useEffect lets you synchronize a component with an external system...", author: "Vin", createdAt: "2026-02-20" },
    { id: 3, title: "Why TypeScript?", content: "TypeScript adds static types to JavaScript...", author: "Vin", createdAt: "2026-03-10" },
  ]);

  const post = posts.find((p) => p.id === Number(id));

  if (!post) {
    return (
      <div>
        <h2>Post not found</h2>
        <Link to="/">← Back to Home</Link>
      </div>
    );
  }

  return (
    <div>
      <button onClick={() => navigate(-1)}>← Back</button>
      <article>
        <h1>{post.title}</h1>
        <p>By {post.author} — {post.createdAt}</p>
        <p>{post.content}</p>
      </article>
    </div>
  );
}
```

**Real implementation** mein posts state global hogi (useReducer + Context ya Zustand) — tab `PostDetail` directly state se post fetch kar sakta hai. Abhi ke liye yeh pattern dikhata hai ki dynamic route kaise kaam karega.

### PostForm Component

```tsx
// components/PostForm.tsx
import { useState } from "react";

interface PostFormProps {
  onSubmit: (title: string, content: string) => void;
}

export default function PostForm({ onSubmit }: PostFormProps) {
  const [title, setTitle] = useState("");
  const [content, setContent] = useState("");

  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    onSubmit(title, content);
  };

  return (
    <form onSubmit={handleSubmit}>
      <div>
        <label htmlFor="post-title">Title</label>
        <input
          id="post-title"
          type="text"
          value={title}
          onChange={(e) => setTitle(e.target.value)}
          placeholder="Post title"
        />
      </div>
      <div>
        <label htmlFor="post-content">Content</label>
        <textarea
          id="post-content"
          value={content}
          onChange={(e) => setContent(e.target.value)}
          placeholder="Write your post..."
          rows={6}
        />
      </div>
      <button type="submit">Publish Post</button>
    </form>
  );
}
```

## Step 7 — App.tsx: Sab Kuch Jodna

```tsx
// App.tsx
import { BrowserRouter, Routes, Route } from "react-router-dom";
import { AuthProvider } from "./context/AuthContext";
import Layout from "./components/Layout";
import ProtectedRoute from "./components/ProtectedRoute";
import Home from "./pages/Home";
import PostDetail from "./pages/PostDetail";
import CreatePost from "./pages/CreatePost";
import Dashboard from "./pages/Dashboard";
import NotFound from "./pages/NotFound";

export default function App() {
  return (
    <BrowserRouter>
      <AuthProvider>
        <Routes>
          <Route path="/" element={<Layout />}>
            <Route index element={<Home />} />
            <Route path="posts/:id" element={<PostDetail />} />
            <Route path="create" element={
              <ProtectedRoute>
                <CreatePost />
              </ProtectedRoute>
            } />
            <Route path="dashboard" element={
              <ProtectedRoute>
                <Dashboard />
              </ProtectedRoute>
            } />
            <Route path="*" element={<NotFound />} />
          </Route>
        </Routes>
      </AuthProvider>
    </BrowserRouter>
  );
}
```

Provider order — `BrowserRouter` sabse bahar, phir `AuthProvider`, phir `Routes`. Is order se Router context sabko milta hai, aur AuthProvider ke andar ke pages `useAuth()` access kar sakte hain.

## Feature Map

| Route | Page | Auth Required | Description |
|---|---|---|---|
| `/` | Home | No | Post list with preview cards |
| `/posts/:id` | PostDetail | No | Dynamic route — individual post |
| `/create` | CreatePost | **Yes** | Protected — new post form |
| `/dashboard` | Dashboard | **Yes** | Protected — manage your posts |
| `/*` | NotFound | No | 404 — invalid routes |

## What It Is NOT

- **PostDetail abhi real post data nahi dikha sakta** — kyunki posts state Home mein local hai. Cross-page state sharing ke liye global state chahiye (Batch 5-6 mein `useReducer` + Context aur Zustand seekhenge).
- **Protected Route sirf front-end guard hai** — koi bhi browser dev tools mein code dekh sakta hai. Real backend authorization alag se implement karni padti hai.
- **Is project mein koi form validation library nahi use ki** — manual validation hai. Batch 4 mein React Hook Form + Zod seekhenge.
- **Posts hardcoded hain** — koi database ya API nahi hai. Sirf front-end routing ka demo hai.

## In Your Own Words

<details>
<summary>Is project mein React Router ke kaun-se features use hue hain?</summary>

React Router ke teen main features use hue: (1) BrowserRouter + Routes + Route — multi-page navigation setup. (2) Dynamic routes (`/posts/:id`) with `useParams` — alag-alag posts ke liye ek hi component render hota hai. (3) Nested routes with Layout component + `<Outlet />` — navbar har page par same rahta hai, sirf content badalta hai. (4) `useNavigate` — programmatic navigation (Back button). (5) NavLink with `end` prop — active route styling.
</details>

<details>
<summary>ProtectedRoute component kaise kaam karta hai? redirect ke baad user ko wapas kahan bhejna chahiye?</summary>

ProtectedRoute `useAuth()` se user check karta hai. Agar user null hai, toh `<Navigate to="/" replace />` render karta hai — user Home page pe redirect ho jata hai. Agar user exist karta hai, toh `children` render hota hai (protected page). `useLocation()` se `state.from` store kar sakte hain — login ke baad user ko wapas usi page pe bhejne ke liye jahan se redirect hua tha.
</details>

<details>
<summary>Layout component aur nested routes ka kya fayda hai?</summary>

Layout component har page ke common structure ko ek jagah define karta hai — navbar, sidebar, footer. `<Outlet />` wahan hota hai jahan page-specific content render hoga. Nested routes is Layout ko parent route bana dete hain — har child route sirf apna specific content provide karta hai, Layout automatically apply hota hai. Isse code duplication nahi hoti aur structure consistent rehta hai.
</details>

<details>
<summary>NavLink ki `end` prop kyun important hai?</summary>

Bina `end` ke, NavLink "starts with" match karta hai — `/create` ya `/dashboard` pe bhi Home link active dikhega kyunki dono `/` se start hote hain. `end` prop ke saath, sirf exact match pe active hota hai. Isse navbar correctly current page highlight karta hai — sirf `/` pe Home active, `/create` pe Create Post active.
</details>

<details>
<summary>Is project mein posts data kahan store hai? Real app mein kahan store hoga?</summary>

Abhi posts hardcoded arrays hain jo Home.tsx aur PostDetail.tsx mein alag-alag defined hain — yeh duplicate data hai. Real app mein posts kisi global store mein honge — Context + useReducer (Batch 5) ya Zustand (Batch 6). Tab koi bhi page ya component ek hi source se posts access kar sakta hai, bina duplication ke.
</details>
