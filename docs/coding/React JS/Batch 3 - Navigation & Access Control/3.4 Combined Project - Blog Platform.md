## Step 2 — AuthContext (for Protected Routes)

First, set up authentication — simple dummy auth, as learned in 3.3:

```tsx
// context/AuthContext.tsx
import { createContext, useContext, useState, type ReactNode } from "react";

interface AuthContextValue {
  user: string | null;
  login: (username: string) => void;
  logout: () => void;
}

const AuthContext = createContext<AuthContextValue | undefined>(undefined);

export function useAuth(): AuthContextValue {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("useAuth must be used within AuthProvider");
  return ctx;
}

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<string | null>(null);
  const login = (username: string) => setUser(username);
  const logout = () => setUser(null);

  return (
    <AuthContext value={{ user, login, logout }}>
      {children}
    </AuthContext>
  );
}
```

## Step 3 — ProtectedRoute Component

```tsx
// components/ProtectedRoute.tsx
import { Navigate, useLocation } from "react-router-dom";
import { useAuth } from "../context/AuthContext";
import type { ReactNode } from "react";

export default function ProtectedRoute({ children }: { children: ReactNode }) {
  const { user } = useAuth();
  const location = useLocation();

  if (!user) {
    return <Navigate to="/" state={{ from: location }} replace />;
  }

  return <>{children}</>;
}
```

`state={{ from: location }}` — after login, you can send the user back to the page they were redirected from. Not implemented yet, but the pattern is visible.

## Step 4 — Layout and Navbar

The Layout component — the parent of nested routes — provides the same navbar and structure on every page:

```tsx
// components/Layout.tsx
import { Outlet } from "react-router-dom";
import Navbar from "./Navbar";

export default function Layout() {
  return (
    <div className="app">
      <Navbar />
      <main>
        <Outlet />
      </main>
    </div>
  );
}
```

```tsx
// components/Navbar.tsx
import { NavLink } from "react-router-dom";
import { useAuth } from "../context/AuthContext";
import ThemeToggle from "./ThemeToggle";

export default function Navbar() {
  const { user, logout } = useAuth();

  return (
    <nav>
      <NavLink to="/" end>Home</NavLink>
      <NavLink to="/create">Create Post</NavLink>
      <NavLink to="/dashboard">Dashboard</NavLink>
      <ThemeToggle />
      {user && (
        <span>
          {user} <button onClick={logout}>Logout</button>
        </span>
      )}
      {!user && <span>Guest</span>}
    </nav>
  );
}
```

Notice the `end` prop in `<NavLink to="/" end>` — it means "only show as active when the URL is exactly `/`." Without `end`, the Home link would also be active on `/create` and `/dashboard` because those start with `/`. Small detail, big difference.

### PostDetail (Dynamic Route)

```tsx
// pages/PostDetail.tsx
import { useParams, useNavigate, Link } from "react-router-dom";
import { useState } from "react";
import type { Post } from "../types";

// Note: Posts data is in local state (in Home).
// In a real app, this comes from a global store (Zustand/Context) or an API fetch.
// For now, simulating with a local posts array — that's why posts are defined here too.

export default function PostDetail() {
  const { id } = useParams<{ id: string }>();
  const navigate = useNavigate();

  const [posts] = useState<Post[]>([
    { id: 1, title: "Getting Started with React", content: "React is a library for building user interfaces...", author: "Vin", createdAt: "2026-01-15" },
    { id: 2, title: "Understanding useEffect", content: "useEffect lets you synchronize a component with an external system...", author: "Vin", createdAt: "2026-02-20" },
    { id: 3, title: "Why TypeScript?", content: "TypeScript adds static types to JavaScript...", author: "Vin", createdAt: "2026-03-10" },
  ]);

  const post = posts.find((p) => p.id === Number(id));

  if (!post) {
    return (
      <div>
        <h2>Post not found</h2>
        <Link to="/">← Back to Home</Link>
      </div>
    );
  }

  return (
    <div>
      <button onClick={() => navigate(-1)}>← Back</button>
      <article>
        <h1>{post.title}</h1>
        <p>By {post.author} — {post.createdAt}</p>
        <p>{post.content}</p>
      </article>
    </div>
  );
}
```

In a real implementation, the posts state would be global (useReducer + Context or Zustand) — then PostDetail can fetch the post directly from state. For now, this pattern shows how dynamic routes work.

### PostForm Component

```tsx
// components/PostForm.tsx
import { useState } from "react";

interface PostFormProps {
  onSubmit: (title: string, content: string) => void;
}

export default function PostForm({ onSubmit }: PostFormProps) {
  const [title, setTitle] = useState("");
  const [content, setContent] = useState("");

  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    onSubmit(title, content);
  };

  return (
    <form onSubmit={handleSubmit}>
      <div>
        <label htmlFor="post-title">Title</label>
        <input
          id="post-title"
          type="text"
          value={title}
          onChange={(e) => setTitle(e.target.value)}
          placeholder="Post title"
        />
      </div>
      <div>
        <label htmlFor="post-content">Content</label>
        <textarea
          id="post-content"
          value={content}
          onChange={(e) => setContent(e.target.value)}
          placeholder="Write your post..."
          rows={6}
        />
      </div>
      <button type="submit">Publish Post</button>
    </form>
  );
}
```

## Step 7 — App.tsx: Wiring Everything Together

```tsx
// App.tsx
import { BrowserRouter, Routes, Route } from "react-router-dom";
import { AuthProvider } from "./context/AuthContext";
import Layout from "./components/Layout";
import ProtectedRoute from "./components/ProtectedRoute";
import Home from "./pages/Home";
import PostDetail from "./pages/PostDetail";
import CreatePost from "./pages/CreatePost";
import Dashboard from "./pages/Dashboard";
import NotFound from "./pages/NotFound";

export default function App() {
  return (
    <BrowserRouter>
      <AuthProvider>
        <Routes>
          <Route path="/" element={<Layout />}>
            <Route index element={<Home />} />
            <Route path="posts/:id" element={<PostDetail />} />
            <Route path="create" element={
              <ProtectedRoute>
                <CreatePost />
              </ProtectedRoute>
            } />
            <Route path="dashboard" element={
              <ProtectedRoute>
                <Dashboard />
              </ProtectedRoute>
            } />
            <Route path="*" element={<NotFound />} />
          </Route>
        </Routes>
      </AuthProvider>
    </BrowserRouter>
  );
}
```

Provider order — `BrowserRouter` outermost, then `AuthProvider`, then `Routes`. In this order, the Router context reaches everyone, and the pages inside AuthProvider can access `useAuth()`.

## Feature Map

| Route | Page | Auth Required | Description |
|---|---|---|---|
| `/` | Home | No | Post list with preview cards |
| `/posts/:id` | PostDetail | No | Dynamic route — individual post |
| `/create` | CreatePost | **Yes** | Protected — new post form |
| `/dashboard` | Dashboard | **Yes** | Protected — manage your posts |
| `/*` | NotFound | No | 404 — invalid routes |

## What It Is NOT

- **PostDetail can't show real post data** — because the posts array is local to Home. Cross-page state sharing needs a global store (Batch 5-6 covers `useReducer` + Context and Zustand).
- **ProtectedRoute is only a front-end guard** — anyone can read the code in browser DevTools. Real backend authorization must be implemented on the server.
- **No form validation library** — validation is manual. Batch 4 covers React Hook Form + Zod.
- **Posts are hardcoded** — there's no database or API. This is just a front-end routing demo.

## In Your Own Words

<details>
<summary>Which React Router features are used in this project?</summary>

Three main React Router features appear: (1) BrowserRouter + Routes + Route — multi-page navigation setup. (2) Dynamic routes (`/posts/:id`) with `useParams` — a single component renders for each different post. (3) Nested routes with Layout + `<Outlet />` — navbar stays the same on every page, only content changes. (4) `useNavigate` — programmatic navigation (Back button). (5) NavLink with `end` prop — active route styling.

</details>

<details>
<summary>How does ProtectedRoute work? Where should the user be redirected after login?</summary>

ProtectedRoute calls `useAuth()` to check the user. If `user` is null, it renders `<Navigate to="/" replace />` — redirecting to the home page. If the user exists, it renders `{children}` (the protected page). With `useLocation()`, you can store `state.from` — the location where the user tried to go before being redirected. After login, send the user back to that original page instead of always redirecting to `/`.

</details>

<details>
<summary>What's the benefit of the Layout component and nested routes?</summary>

The Layout component defines the common structure for every page — navbar, sidebar, footer. `<Outlet />` is where page-specific content renders. Nested routes make Layout the parent route — each child route only provides its specific content, and Layout applies automatically. No code duplication, consistent structure across pages.

</details>

<details>
<summary>Why is NavLink's `end` prop important?</summary>

Without `end`, NavLink matches "starts with" — the Home link would be active on `/create` and `/dashboard` too, because they all start with `/`. With `end`, it's exact match only. So Home is highlighted only on `/`, Create Post only on `/create`. Without it, multiple nav links could be highlighted at once.

</details>

<details>
<summary>Where is the posts data stored in this project? Where should it be in a real app?</summary>

Posts are hardcoded arrays defined separately in Home.tsx and PostDetail.tsx — that's duplicate data. In a real app, posts live in a global store — Context + useReducer (Batch 5) or Zustand (Batch 6). Then any page or component can access posts from a single source of truth, without duplication.

</details>
