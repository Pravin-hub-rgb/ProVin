# 3.3 Quiz — Protected Routes

## MCQ

Q: Context consume karne wale custom hook mein guard pattern `if (!ctx) throw Error` kyun use karte hain?
A. Error boundary trigger karne ke liye
B. Provider bahar use pe error dene ke liye
C. TypeScript ki warning avoid karne ke liye
D. Component re-render force karne ke liye
> B. Provider ke bahar context undefined rehta hai — guard pattern clear error deta hai ki "hook context provider ke andar use karo." A galat kyunki error boundary alag React feature hai. C galat kyunki guard pattern runtime error deta hai, compile-time warning nahi. D galat kyunki guard pattern re-render trigger nahi karta.

Q: Auth state (jaise user info) ko Context mein rakhne ka main reason kya hai?

B. Koi bhi nested component bina props ke user access karega
C. User state page refresh pe automatically save rahegi
D. Context user state ko server ke saath sync rakhta hai
> B. Context API ka main purpose prop drilling avoid karna hai — koi bhi child component useAuth() call karke seedha user access kar sakta hai bina har level se props pass kiye. A galat kyunki har component apna state rakhna inconsistent data dega. C galat kyunki context state refresh pe reset hoti hai (local storage alag se chahiye). D galat kyunki context sync mechanism nahi hai.

Q: `<Navigate>` component kya karta hai?
A. User ko redirect karne ka function return karta hai
B. Render hote hi redirect turant trigger ho jaata hai
C. Browser ki poori history clear kar deta hai
D. URL change kiye bina component swap karta hai
> B. Navigate declarative component hai — render hote hi redirect trigger hota hai. A galat kyunki function useNavigate return karta hai. C galat kyunki sirf current entry replace hoti hai. D galat kyunki URL change hota hai aur naya component render hota hai.

Q: `useNavigate` hook kab use karte hain?
A. Jab JSX mein condition ke saath redirect karna ho
B. Jab event handler ke andar redirect karna ho
C. Jab sirf URL change karna ho bina render ke
D. Jab form validation ke baad redirect karna ho
> B. useNavigate programmatic redirect hai — event handlers, callbacks, timers, kahi bhi code se redirect kar sakte ho. A galat kyunki JSX condition ke saath `<Navigate>` use karte hain. C galat kyunki URL change hoga toh component render hoga. D galat kyunki sirf form validation ke baad nahi, kahi bhi use hota hai.

## TrueFalse

Q: `<Navigate>` component render hone par immediately redirect trigger karta hai bina kisi user interaction ke.
- True
- False
> True: Navigate declarative component hai — jese hi render hota hai, redirect execute ho jata hai. Isliye condition ke saath use karte hain — "agar user nahi hai toh yeh render karo."

---

Q: `useNavigate` hook sirf event handlers ke andar use kiya ja sakta hai.
- True
- False
> False: useNavigate kisi bhi code path mein call kar sakte ho — event handlers, useEffect, callbacks, timers. Har jagah kaam karta hai jahan Router context available ho. Sirf condition yeh hai ki component ke andar hook call karo.

---

Q: Bina `replace` prop ke `<Navigate>` use karne se back button press pe infinite redirect loop jaisa feel ho sakta hai.
- True
- False
> True: Bina replace ke nayi history entry push hoti hai. User back press karega toh protected route pe aayega — phir redirect — back — redirect. replace se history entry replace hoti hai, push nahi, isliye back pe redirect wali entry nahi dikhti.

---

Q: Context provider ko BrowserRouter ke andar rakhna zaroori hai kyunki guard component mein `<Navigate>` Router context access karta hai.
- True
- False
> True: Navigate component internally Router context use karta hai. Agar provider Router ke bahar hai toh guard component ke andar Navigate kaam nahi karega — error aayega "useNavigate may be used only in the context of a `<Router>` component."

## ShortAnswer

Q: `<Navigate>` component aur `useNavigate` hook mein kya difference hai? Example ke saath explain karo ki kaunsa kab use karna chahiye.

> Navigate declarative hai — JSX mein condition ke saath render hota hai. useNavigate programmatic hai — code ke andar (event handlers, timers) call hota hai. Example: ProtectedRoute mein agar user nahi hai toh `<Navigate to="/login" replace />` render karte hain. Login form submit ke baad `navigate("/dashboard")` call karte hain.

<details>
<summary>Sample Answer</summary>

Dono redirect karte hain, lekin context different hai:

**`<Navigate />` — Declarative (JSX mein):**
Jab redirect condition JSX ke andar check karni ho tab use karte hain. Component render hote hi redirect trigger hota hai.

```tsx
function ProtectedRoute({ children }) {
  const { user } = useAuth();
  if (!user) return <Navigate to="/login" replace />;
  return <>{children}</>;
}
```

**`useNavigate()` — Programmatic (code mein):**
Jab event handler, callback, ya kisi bhi code path mein redirect karna ho tab use karte hain.

```tsx
function LoginPage() {
  const { login } = useAuth();
  const navigate = useNavigate();
  function handleLogin() {
    login("user");
    navigate("/dashboard", { replace: true });
  }
  return <button onClick={handleLogin}>Login</button>;
}
```

**Simple rule:** JSX mein condition ke saath redirect → `<Navigate />`. Code ke andar redirect → `useNavigate()`.
</details>
