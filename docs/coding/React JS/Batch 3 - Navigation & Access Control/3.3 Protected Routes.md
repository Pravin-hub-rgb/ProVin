## Cheat Sheet (Quick Recall)

```tsx
// Auth context — authentication state globally available
const AuthContext = createContext<AuthContextValue | undefined>(undefined);

// ProtectedRoute wrapper — check karo, nahi toh redirect
function ProtectedRoute({ children }: { children: ReactNode }) {
  const { user } = useAuth();
  if (!user) return <Navigate to="/login" replace />;
  return <>{children}</>;
}

// Route mein wrap karo
<Route path="/watchlist" element={
  <ProtectedRoute>
    <Watchlist />
  </ProtectedRoute>
} />
```

## Abhi Tak Kya Hua

3.2 mein dynamic routes aur nested routes seekhe — URL se data capture karna, layout components ke saath nested routing. Movie Browser mein koi bhi user kisi bhi movie ki detail page dekh sakta hai — koi restriction nahi.

Lekin real apps mein aise pages hote hain jo sirf logged-in users ke liye accessible hone chahiye — "My Watchlist," "Settings," "Orders." Agar user login nahi hai toh unhe ya toh login page pe redirect karo, ya content hide karo. Is pattern ko kehte hain **Protected Routes**.

## Broader Goal

Protected routes React application me ek wrapper component hai jo check karta hai ki user authenticated hai ya nahi. Agar hai toh content dikhao, nahi toh redirect karo. Yeh React Router + Context API ka combination hai — auth state Context mein, redirect logic ProtectedRoute component mein.

Yeh seekhne ke baad tum kisi bhi route ko protected bana sakte ho — bus wrapper component mein wrap karo. Koi extra logic nahi.

## Step 1 — Auth Context

Pehle authentication state ke liye context banate hain — jaise 2.6 mein ThemeContext banaya tha, waise hi:

```tsx
// context/AuthContext.tsx
import { createContext, useContext, useState, type ReactNode } from "react";

interface AuthContextValue {
  user: string | null;
  login: (username: string) => void;
  logout: () => void;
}

const AuthContext = createContext<AuthContextValue | undefined>(undefined);

export function useAuth(): AuthContextValue {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("useAuth must be used within AuthProvider");
  return ctx;
}

interface AuthProviderProps {
  children: ReactNode;
}

export function AuthProvider({ children }: AuthProviderProps) {
  const [user, setUser] = useState<string | null>(null);

  const login = (username: string) => setUser(username);
  const logout = () => setUser(null);

  return (
    <AuthContext value={{ user, login, logout }}>
      {children}
    </AuthContext>
  );
}
```

Same pattern jo Context API mein seekha — `createContext`, custom hook with guard, `useState` for state. Yahan `user` ek string hai (username) ya null (logged out). Real apps mein yeh token, JWT, user object hota hai — lekin concept same hai.

## Step 2 — ProtectedRoute Component

ProtectedRoute ek wrapper component hai jo auth check karta hai:

```tsx
// components/ProtectedRoute.tsx
import { Navigate } from "react-router-dom";
import { useAuth } from "../context/AuthContext";
import type { ReactNode } from "react";

interface ProtectedRouteProps {
  children: ReactNode;
}

export default function ProtectedRoute({ children }: ProtectedRouteProps) {
  const { user } = useAuth();

  if (!user) {
    return <Navigate to="/login" replace />;
  }

  return <>{children}</>;
}
```

**Kaise kaam karta hai:**
1. `useAuth()` se check karo ki user hai ya nahi
2. Agar user nahi hai → `<Navigate to="/login" replace />` — login page pe bhej do
3. Agar user hai → `<>{children}</>` — original protected content render karo

`replace` prop ka matlab hai ki history mein current entry replace ho jayegi — user back press karega toh protected route pe nahi, balki usse pehle wali page pe jayega. Isse user ko "stuck" feel nahi hota.

## Step 3 — App Mein Use Karna

```tsx
// App.tsx
import { BrowserRouter, Routes, Route, Link, Outlet } from "react-router-dom";
import { AuthProvider } from "./context/AuthContext";
import { useAuth } from "./context/AuthContext";
import ProtectedRoute from "./components/ProtectedRoute";
import MovieList from "./components/MovieList";
import MovieDetail from "./components/MovieDetail";

function Layout() {
  return (
    <div className="app">
      <nav>
        <Link to="/">Home</Link>
        <Link to="/movies">Movies</Link>
        <Link to="/watchlist">My Watchlist</Link>
      </nav>
      <Outlet />
    </div>
  );
}

function HomePage() {
  const { user, login, logout } = useAuth();
  return (
    <div>
      <h2>Welcome to Movie Browser</h2>
      {user ? (
        <div>
          <p>Logged in as: <strong>{user}</strong></p>
          <button onClick={logout}>Logout</button>
        </div>
      ) : (
        <div>
          <p>You are not logged in.</p>
          <button onClick={() => login("DemoUser")}>Login as DemoUser</button>
        </div>
      )}
    </div>
  );
}

function LoginPage() {
  const { login } = useAuth();
  const navigate = useNavigate();

  function handleLogin() {
    login("DemoUser");
    navigate("/", { replace: true });
  }

  return (
    <div>
      <h2>Login</h2>
      <button onClick={handleLogin}>Login as DemoUser</button>
    </div>
  );
}

function Watchlist() {
  return (
    <div>
      <h2>My Watchlist</h2>
      <ul>
        <li>Inception</li>
        <li>Interstellar</li>
      </ul>
    </div>
  );
}

function NotFound() {
  return <h2>404 — Page not found</h2>;
}

export default function App() {
  return (
    <BrowserRouter>
      <AuthProvider>
        <Routes>
          <Route path="/" element={<Layout />}>
            <Route index element={<HomePage />} />
            <Route path="movies" element={<MovieList />} />
            <Route path="movies/:id" element={<MovieDetail />} />
            <Route path="login" element={<LoginPage />} />
            <Route path="watchlist" element={
              <ProtectedRoute>
                <Watchlist />
              </ProtectedRoute>
            } />
            <Route path="*" element={<NotFound />} />
          </Route>
        </Routes>
      </AuthProvider>
    </BrowserRouter>
  );
}
```

**Observe karo:** `AuthProvider` Router ke andar hai — kyunki ProtectedRoute mein `useAuth()` use karta hai aur `Navigate` component Router ke context mein hi kaam karta hai. Agar AuthProvider Router ke bahar hota, toh ProtectedRoute mein `useAuth()` to chal jaata, lekin ProtectedRoute ke andar `Navigate` nahi chal paata.

> **BEST PRACTICE:** Provider hierarchy important hai. Context providers Router ke *andar* hone chahiye agar unhe navigation ki zaroorat hai. Agar context sirf data provide karta hai (jaise ThemeContext), toh Router ke bahar bhi rakh sakte ho.

## Step 4 — Dummy Auth vs Real Auth

Is mini-project mein dummy auth hai — login button click karte hi user "DemoUser" ban jata hai. Real apps mein:
- Login form hota hai (username + password)
- API call hoti hai server ko
- Server token return karta hai
- Token localStorage ya cookie mein store hota hai
- Auth context token check karta hai

Dummy auth se pattern seekho — ProtectedRoute, AuthContext, redirect logic — yeh sab real auth mein bhi same rehte hain. Sirf login function change hoga jo abhi API call karega.

## What It Is NOT

- **ProtectedRoute security measure nahi hai** — yeh sirf UX pattern hai. Koi bhi browser tools khol ke code inspect kar sakta hai. Real security server-side hoti hai.
- **Auth context state page refresh pe reset ho jayega** — dummy auth mein state memory mein hai. Refresh karte hi user null ho jayega. Real apps mein localStorage ya cookies use karte hain persistence ke liye.
- **ProtectedRoute har component ke andar nahi lagana** — sirf route level pe lagao. Component ke andar check karne ke liye `useAuth()` direct use karo.
- **`<Navigate>` browser ki history replace karta hai** — push nahi. Isliye back button pe protected page nahi dikhega. Agar push chahiye toh `<Navigate to="/login" />` bina replace ke use karo.

## In Your Own Words

<details>
<summary>Protected route kya hota hai? Kya problem solve karta hai?</summary>

Protected route ek pattern hai jisme kuch pages sirf authenticated users ke liye accessible hote hain. Bina login ke un pages ko access karne ki koshish karoge toh user automatically login page pe redirect ho jayega. Yeh problem solve karta hai ki sensitive pages (watchlist, settings, orders) ka content unauthorized users ko na dikhe.
</details>

<details>
<summary>ProtectedRoute component kaise kaam karta hai? Step by step batao.</summary>

1. `useAuth()` hook se current auth state check karo (`user` null hai ya nahi). 2. Agar `user` null hai — `return <Navigate to="/login" replace />` — user ko login page pe bhej do, aur history replace karo. 3. Agar `user` exist karta hai — `return <>{children}</>` — protected content render karo. This is a wrapper pattern — jo bhi component iske andar hoga woh sirf authenticated users ko dikhega.
</details>

<details>
<summary>`AuthProvider` ko Router ke andar kyun rakhna chahiye?</summary>

Kyunki ProtectedRoute mein `useAuth()` bhi chahiye aur `<Navigate>` bhi. Navigate ko React Router ke context mein kaam karna hota hai. Agar AuthProvider Router ke bahar hai, toh `useAuth()` to chalega lekin `<Navigate>` ka error dega kyunki uske paas Router ka context nahi hoga.
</details>

<details>
<summary>Dummy auth aur real auth mein kya difference hai?</summary>

Dummy auth: login button click → state set (`setUser("DemoUser")`) → ho gaya. Real auth: form submit → API call → server validation → token return → token store (localStorage/cookie) → auth context update. Pattern same hai — sirf login function real API call karega aur token persist karega taaki page refresh pe bhi login na chhute.
</details>
