## Cheat Sheet (Quick Recall)

```tsx
// Auth context — global auth state
const AuthContext = createContext<...>(undefined);
function useAuth() { return useContext(AuthContext); }

// ProtectedRoute — guard component
function ProtectedRoute({ children }: { children: ReactNode }) {
  const { user } = useAuth();
  if (!user) return <Navigate to="/login" replace />;
  return <>{children}</>;
}

// Usage — wrap protected routes
<Route path="/watchlist" element={
  <ProtectedRoute><Watchlist /></ProtectedRoute>
} />
```

## Abhi Tak Kya Hua

3.2 mein nested routes + dynamic routes seekhe. Movie Browser ka layout tha — `/`, `/movies`, `/movies/:id`. Koi bhi user kisi bhi page pe ja sakta tha, koi restriction nahi thi.

Lekin yaar, real apps mein aise pages hote hain jo **sirf logged-in users** ko dikhne chahiye — "My Watchlist", "Settings", "Orders". Agar user login nahi hai, toh unhe login page pe bhej do ya content chhupa do.

Protected routes ka pattern yahi hai — ek wrapper component jo check karta hai: "user authenticated hai?" Agar haan toh content dikhao, nahi toh redirect.

## Broader Goal

Is doc mein hum Movie Browser mein ek `/watchlist` page add karenge jo sirf logged-in users access kar sakein. Iske liye:

1. Auth state globally available karni hogi (Context API se — 2.6 ka pattern yaad hai?)
2. React Router ke redirect tools seekhne honge — `<Navigate>` component aur `useNavigate` hook
3. Ek guard component chahiye jo check kare "user logged in hai?"
4. Guard ko route ke saath connect karna hoga

Yeh seekhne ke baad, kisi bhi route ko protected banana sirf ek `ProtectedRoute` wrap karne jitna simple ho jayega.

## Step 2 — Auth State: Context API se Global State

**SOCH:** Koi page sirf logged-in users ko dikhana hai. Matlab humein kahi na kahi yeh store karna hoga ki "abhi kaun logged in hai." Aur yeh state globally available honi chahiye — har component check kar sake. React ka Context API iske liye perfect hai — 2.6 mein ThemeContext banaya tha, wahi pattern.

**CONCEPT:** Auth context teen cheezein provide karega:
- `user` — currently logged in user ka naam (ya `null` agar logout hai)
- `login(name)` — user ko login karne ka function
- `logout()` — user ko logout karne ka function

Same trika jo Context API mein seekha: `createContext` → Provider component → custom hook with guard.

Chal banate hain. Pehle ek nayi folder `context/` banao — kyunki auth logic alag file mein rakhna cleaner hai.

Socho — file banane se pehle yeh clear karo ki kyun nayi folder:
- Components ka apna folder hai (`components/`)
- Data ka apna folder hai (`data/`)
- Context providers ka alag folder — `context/` — yeh convention hai, React projects mein common

**CODE:**

```tsx
// context/AuthContext.tsx
import { createContext, useContext, useState } from "react";
import type { ReactNode } from "react";
```

Import kiya — `createContext` aur `useContext` React se, `useState` state ke liye, aur `ReactNode` type ke liye (kyunki children ka type ReactNode hota hai — yaad hai 1.6 se?).

```tsx
interface AuthContextValue {
  user: string | null;
  login: (username: string) => void;
  logout: () => void;
}
```

Interface define kiya — context ki shape bata raha hai: `user` ek string hai ya null, `login` ek function hai jo string leta hai (username), `logout` function hai jo kuch nahi leta.

```tsx
const AuthContext = createContext<AuthContextValue | undefined>(undefined);
```

Context create kiya. Initial value `undefined` di — kyunki provider laga nahi hai toh context undefined hoga. TypeScript ko bataya "yeh `AuthContextValue` ho sakta hai ya `undefined`" — isliye baad mein guard lagayenge.

```tsx
export function useAuth(): AuthContextValue {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("useAuth must be used within AuthProvider");
  return ctx;
}
```

Custom hook — `useAuth()`. Guard pattern: agar context undefined hai (matlab provider ke bahar use kar rahe ho), toh error throw karo. Yeh same pattern hai jo 2.6 ke `ThemeContext` mein seekha tha.

```tsx
export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<string | null>(null);

  const login = (username: string) => setUser(username);
  const logout = () => setUser(null);

  return (
    <AuthContext.Provider value={{ user, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}
```

Provider component. `useState<string | null>(null)` se shuru karte hain — null matlab koi logged in nahi. `login` function `setUser(username)` call karta hai, `logout` `setUser(null)`.

**Test:** Is file mein `console.log("AuthContext ready")` daal ke check karo ki file import ho rahi hai ya nahi. Abhi actual use nahi karenge, lekin confirm karna ki export/import sahi hai.

> **Nutshell:** AuthContext ek global state container hai — `user`, `login`, `logout` ko poore app mein accessible banata hai bina props pass kiye.

## Step 3 — React Router Mein Redirect: `<Navigate>` aur `useNavigate`

**SOCH:** Auth state ready hai. Ab hume ek guard component banani hai — agar user logged in nahi hai toh redirect karna padega login page pe. Lekin React Router mein redirect kaise karte hain? Do tarike hain — ek declarative (JSX mein component) aur ek programmatic (event handler mein function). Pehle dono ko samajhte hain.

**CONCEPT — `<Navigate>` component:**

`<Navigate>` ek React Router component hai. Jab yeh render hota hai, turant redirect ho jaata hai. Iska use tab hota hai jab tumhare paas koi condition hai jo JSX ke andar decide karti hai "redirect karo ya nahi."

Syntax:

```tsx
<Navigate to="/login" replace />
```

- `to="/login"` — kahan redirect karna hai
- `replace` — browser history mein current URL ko replace karta hai (push nahi). Matlab back press karne pe protected page pe nahi aaoge

**CONCEPT — `useNavigate` hook:**

`useNavigate` ek hook hai jo `navigate` function return karta hai. Iska use tab hota hai jab tum event handler ke andar se redirect karna chahte ho — jaise button click karein, API response aaye, timer khatam ho.

Syntax:

```tsx
const navigate = useNavigate();
navigate("/", { replace: true });
```

Dono kaam ek hi karte hain — redirect. Fark sirf itna hai:
- `<Navigate />` — declarative, JSX mein condition ke saath (jaise "agar user nahi hai toh yeh render karo")
- `useNavigate()` — programmatic, code ke andar se call karo (jaise "form submit hone ke baad redirect karo")

**Minimal code — `<Navigate />`:**

```tsx
import { Navigate } from "react-router-dom";

function GuestGuard() {
  const isLoggedIn = false; // hardcoded abhi

  if (!isLoggedIn) {
    return <Navigate to="/login" replace />;
  }

  return <h2>Welcome, user!</h2>;
}
```

Yahan `isLoggedIn` false hai, toh `<Navigate to="/login" />` render hoga — user turant `/login` pe chala jayega. Console mein kuch error nahi aayega — `<Navigate>` silently redirect karta hai.

**Test:** Is component ko kisi route pe daal kar dekho — browser automatically `/login` pe chala jayega.

**Minimal code — `useNavigate`:**

```tsx
import { useNavigate } from "react-router-dom";

function LoginButton() {
  const navigate = useNavigate();

  function handleClick() {
    // login logic yahan aayegi
    navigate("/dashboard", { replace: true });
  }

  return <button onClick={handleClick}>Login</button>;
}
```

`handleClick` function mein `navigate("/dashboard")` call kiya. Button click pe user dashboard pe chala jayega.

**Test:** Button click karo — browser mein URL change hona chahiye aur dashboard page dikhna chahiye (agar route defined hai).

**`replace` prop kyun important hai?**

Bina `replace` ke agar user back button press kare, toh wapas usi page pe aa jayega jahan se redirect hua tha. Agar woh page phir se redirect kare, toh infinite loop jaisa feel hoga. `replace` se history entry replace ho jati hai, isliye back karne pe redirect wali entry nahi dikhegi.

Maine ek baar `replace` bhool gaya tha — user login page pe tha, login kiya, dashboard pe gaya, back press kiya — wapas login page. Phir wapas dashboard (redirect), back — login page. User confused. Tab samjha `replace` kyun chahiye.

**Ab project mein use karte hain — LoginPage banate hain:**

Dono tools seekh liye. Ab inhe Movie Browser project mein use karte hain. Pehla use case — **LoginPage** jahan user login kare aur uske baad home page pe redirect ho.

Chal banate hain `components/LoginPage.tsx`:

```tsx
// components/LoginPage.tsx
import { useNavigate } from "react-router-dom";
import { useAuth } from "../context/AuthContext";
```

Do imports — `useNavigate` redirect ke liye (abhi seekha), `useAuth` auth state access karne ke liye (Step 2 mein banaya).

```tsx
export default function LoginPage() {
  const { login } = useAuth();
  const navigate = useNavigate();

  function handleLogin() {
    login("DemoUser");
    navigate("/", { replace: true });
  }

  return (
    <div>
      <h2>Login</h2>
      <button onClick={handleLogin}>Login as DemoUser</button>
    </div>
  );
}
```

`handleLogin` function — pehle `login("DemoUser")` se auth context update kiya (abhi dummy auth hai, real API call nahi), phir `navigate("/", { replace: true })` se user ko home page pe bheja. `replace: true` ka matlab — history mein current entry replace ho jayegi, push nahi. Isliye back press karoge toh login page pe nahi aaoge (ware `replace` ki importance).

Ab App.tsx mein `/login` route add karte hain:

```tsx
// App.tsx mein — naya route
import LoginPage from "./components/LoginPage";

// Routes ke andar
<Route path="login" element={<LoginPage />} />
```

**Test:** Browser mein `/login` pe jao, button click karo — home page pe redirect ho jana chahiye. Console mein URL change dekho.

> **Nutshell:** `<Navigate>` declarative redirect hai (JSX mein), `useNavigate` programmatic redirect hai (code mein). `replace` prop/option history entry replace karta hai, push nahi. LoginPage mein `useNavigate` ka real use case dekha — event handler ke baad redirect.

## Step 4 — ProtectedRoute Component: Wrapper Pattern

**SOCH:** Auth state ready hai, redirect tools bhi seekh liye (Step 3). Ab ek guard component chahiye jo check kare: "user hai?" — nahi toh login page pe bhej do. Yeh component kisi bhi protected page ke upar wrap hoga.

**CONCEPT:** ProtectedRoute ek **wrapper component** hai — `children` prop leta hai (jo bhi protected page hai). Kaam karta hai:

1. `useAuth()` se current user check karo
2. Agar user `null` hai → `return <Navigate to="/login" replace />`
3. Agar user exist karta hai → `return <>{children}</>`

Bas itna. Wrapper pattern ka fayda — koi bhi component protected ho sakta hai sirf ek wrap karne se.

Chal banate hain:

```tsx
// components/ProtectedRoute.tsx
import { Navigate } from "react-router-dom";
import { useAuth } from "../context/AuthContext";
import type { ReactNode } from "react";
```

Teen imports. `Navigate` React Router se (redirect ke liye — Step 3 mein seekha), `useAuth` humare auth context se, `ReactNode` children ke type ke liye.

```tsx
interface ProtectedRouteProps {
  children: ReactNode;
}
```

Ek simple interface — sirf `children` leta hai.

```tsx
export default function ProtectedRoute({ children }: ProtectedRouteProps) {
  const { user } = useAuth();

  if (!user) {
    return <Navigate to="/login" replace />;
  }

  return <>{children}</>;
}
```

Samjha? `useAuth()` se user nikaala. Agar `!user` (null hai — logged out), toh `<Navigate>` component render karo jo user ko `/login` pe le jayega. `replace` prop se history replace — back press pe protected route nahi dikhega (Step 3 mein seekha). Agar user hai, toh `<>{children}</>` return karo.

**Test:** Is component ko kisi dummy page pe wrap karo — `console.log(user)` daal ke dekho ki jab user null hai toh `<Navigate />` render hota hai ya nahi.

> **Nutshell:** ProtectedRoute ek guard component hai jo auth check karta hai aur unauthorized users ko login page pe redirect karta hai — `children` prop ke through kisi bhi page ko protect kar sakte ho.

## Step 5 — App Mein Integrate Karna: AuthProvider + ProtectedRoute

**SOCH:** Ab teen cheezein ready hain — AuthContext, ProtectedRoute, Watchlist. Inhe App mein jodna hai. Lekin ek tricky part hai — **AuthProvider ko Router ke ANDAR rakhna hoga** kyunki ProtectedRoute mein `useAuth()` bhi chahiye aur `<Navigate>` bhi. `Navigate` React Router ke context mein kaam karta hai (Step 3 mein dekha tha).

**CONCEPT:** Hierarchy important hai. Context providers ko Router ke andar rakhna chahiye agar unhe navigation ki zaroorat hai. Agar context sirf data provide karta hai (jaise ThemeContext), toh Router ke bahar bhi rakh sakte ho.

Maine pehli baar yeh galti ki thi — AuthProvider ko Router ke bahar rakha, `useAuth()` chal gaya lekin `<Navigate>` ne error diya "useNavigate may be used only in the context of a `<Router>` component." Tab samajh mein aaya.

Chal App.tsx update karte hain. Pehle jo code tha — Layout, HomePage, MovieList, MovieDetail, NotFound — sab wahi hai. Sirf naye parts add karenge:

```tsx
// App.tsx mein naye imports
import { AuthProvider, useAuth } from "./context/AuthContext";
import ProtectedRoute from "./components/ProtectedRoute";
import Watchlist from "./components/Watchlist";
```

Ab HomePage mein login/logout buttons daalte hain — taaki user login kar sake:

```tsx
function HomePage() {
  const { user, login, logout } = useAuth();
  return (
    <div>
      <h2>Welcome to Movie Browser</h2>
      {user ? (
        <div>
          <p>Logged in as: <strong>{user}</strong></p>
          <button onClick={logout}>Logout</button>
        </div>
      ) : (
        <div>
          <p>You are not logged in.</p>
          <button onClick={() => login("DemoUser")}>Login as DemoUser</button>
        </div>
      )}
    </div>
  );
}
```

Dekho — `useAuth()` se `user`, `login`, `logout` nikaale. Agar `user` hai toh "Logged in as X" aur logout button. Agar nahi hai toh "not logged in" aur login button. `login("DemoUser")` ko directly onClick mein call kar diya — kyunki abhi dummy auth hai, real form nahi.

Ab `App()` component mein changes:

```tsx
export default function App() {
  return (
    <BrowserRouter>
      <AuthProvider>
        <Routes>
          <Route path="/" element={<Layout />}>
            <Route index element={<HomePage />} />
            <Route path="movies" element={<MovieList />} />
            <Route path="movies/:id" element={<MovieDetail />} />
            <Route path="login" element={<LoginPage />} />
            <Route path="watchlist" element={
              <ProtectedRoute>
                <Watchlist />
              </ProtectedRoute>
            } />
            <Route path="*" element={<NotFound />} />
          </Route>
        </Routes>
      </AuthProvider>
    </BrowserRouter>
  );
}
```

Notice kiya? `AuthProvider` **BrowserRouter ke andar** hai — kyunki ProtectedRoute mein `<Navigate>` use hota hai jo Router context mein kaam karta hai. Aur `watchlist` route mein element directly component nahi hai — `ProtectedRoute` mein wrap kiya hai. Jab user `/watchlist` pe jayega, pehle ProtectedRoute check karega "user hai?" — nahi toh `/login` redirect, haan toh `<Watchlist />` render.

**Test:** Browser mein `/watchlist` pe jao — redirect ho ke `/login` pe jaana chahiye (kyunki logged out ho). Phir home page pe jao, "Login" button click karo, phir wapas `/watchlist` pe jao — ab Watchlist dikhni chahiye.

## Dummy Auth vs Real Auth

Is mini-project mein dummy auth hai — login button click karte hi user "DemoUser" ban jata hai. Real apps mein:

1. Login form hota hai (username + password inputs)
2. API call hoti hai server ko
3. Server token return karta hai (JWT)
4. Token localStorage ya cookie mein store hota hai
5. Auth context token check karta hai page refresh pe bhi

Lekin pattern same hai — ProtectedRoute, AuthContext, redirect logic — yeh sab real auth mein bhi same rehte hain. Sirf login function change hoga jo abhi API call karega. Isliye dummy auth se pattern seekh lo, real mein migrate karna easy hoga.

## Common Mistakes

**ProtectedRoute ke andar `<Navigate />` bina `replace` ke:**

```tsx
❌ if (!user) return <Navigate to="/login" />;
✅ if (!user) return <Navigate to="/login" replace />;
```

Bina `replace` ke, user back button press karega toh protected route pe aa jayega — phir wapas redirect — infinite loop jaisa feel hoga.

**AuthProvider ko Router ke bahar rakhna:**

```tsx
❌ <AuthProvider><BrowserRouter>...</BrowserRouter></AuthProvider>
✅ <BrowserRouter><AuthProvider>...</AuthProvider></BrowserRouter>
```

ProtectedRoute mein `<Navigate>` Router context leta hai. Provider bahar hai toh Navigate kaam nahi karega. Maine khud yeh galti ki thi pehli baar — error aaya "useNavigate may be used only in the context of a `<Router>` component."

**ProtectedRoute ko component level pe use karna instead of route level:**

ProtectedRoute sirf route level pe lagao. Agar component ke andar check karna hai toh `useAuth()` directly use karo. Agar har component mein ProtectedRoute wrap karoge, toh nesting complex ho jayegi.

**`<Navigate>` aur `useNavigate` mein confuse hona:**

Dono redirect karte hain, lekin context different hai. `<Navigate />` JSX mein render hota hai (declarative). `useNavigate` event handlers mein call hota hai (programmatic). Agar event handler mein `<Navigate />` render karne ki koshish karo ge, toh kaam nahi karega.

4. `<Navigate>` aur `useNavigate` dono redirect karte hain. Kaunsa kab use karna chahiye? Ek scenario do jahan `<Navigate>` better hai aur ek jahan `useNavigate` better hai.

## Summary

- **AuthContext** — global auth state provide karta hai (`user`, `login`, `logout`)
- **`<Navigate to="/path" replace />`** — declarative redirect component (JSX mein)
- **`useNavigate()`** — programmatic redirect hook (event handlers mein)
- **`replace`** — history entry replace karta hai, push nahi — back button issues avoid karta hai
- **ProtectedRoute** — wrapper component jo auth check + redirect handle karta hai
- **Provider hierarchy important hai** — AuthProvider Router ke andar, kyunki ProtectedRoute ko both auth + router context chahiye
