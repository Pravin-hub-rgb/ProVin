### 80. How does client-side routing work in React Router?

**Answer:** It uses the Browser History API (`pushState`) to change the URL without requesting a new document, then renders the component matching the new route — so navigation feels instant and the SPA never reloads.

**Likely follow-up:** *What happens when someone hits refresh on `/blog/42`?* — the server must be configured to serve `index.html` for all paths (SPA fallback), and React Router reads the URL to restore the view.

---

### 81. Difference between `<Link>` and an `<a>` tag?

**Answer:** `<Link>` navigates client-side — it calls `history.pushState`, swaps the component, and keeps all app state alive. A plain `<a>` triggers a full page reload, which resets the SPA (state, stores, scroll) back to zero.

**Likely follow-up:** *When is `<a>` still right?* — external links, downloads, `target="_blank"`, or same-origin pages outside the SPA.

---

### 82. What are Nested Routes and `<Outlet>`?

**Answer:** Nested routes render child routes inside a parent layout route — the layout stays mounted while children swap. `<Outlet>` is the placeholder in the parent component where the matched child renders.

**Likely follow-up:** *Why does that matter for state?* — because the layout doesn't remount, its state (sidebar open, tabs) survives child navigation.

---

### 83. How do you implement dynamic and protected routes?

**Answer:** Dynamic: declare `path="/user/:id"` and read it with `useParams()`. Protected: wrap the route in a component that checks auth — if not logged in, render `<Navigate to="/login" replace />` instead of the children.

**Likely follow-up:** *How do you send the user back after login?* — save the intended location (state or `from` query param) and navigate there on success; use `replace` so Back doesn't return to a redirect loop.
