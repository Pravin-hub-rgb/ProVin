## Step 2 — AuthContext (Protected Routes Ke Liye)

Pehle authentication setup karte hain — simple dummy auth, jaisa 3.3 mein seekha:

```tsx
// context/AuthContext.tsx
import { createContext, useContext, useState, type ReactNode } from "react";

interface AuthContextValue {
  user: string | null;
  login: (username: string) => void;
  logout: () => void;
}

const AuthContext = createContext<AuthContextValue | undefined>(undefined);

export function useAuth(): AuthContextValue {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error("useAuth must be used within AuthProvider");
  return ctx;
}

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<string | null>(null);
  const login = (username: string) => setUser(username);
  const logout = () => setUser(null);

  return (
    <AuthContext value={{ user, login, logout }}>
      {children}
    </AuthContext>
  );
}
```

## Step 3 — ProtectedRoute Component

```tsx
// components/ProtectedRoute.tsx
import { Navigate } from "react-router-dom";
import { useAuth } from "../context/AuthContext";
import type { ReactNode } from "react";

export default function ProtectedRoute({ children }: { children: ReactNode }) {
  const { user } = useAuth();

  if (!user) {
    return <Navigate to="/" replace />;
  }

  return <>{children}</>;
}
```

```tsx
      </main>
    </div>
  );

```

```tsx
// components/Navbar.tsx
import { NavLink } from "react-router-dom";
import ThemeToggle from "./ThemeToggle";
import { useAuth } from "../context/AuthContext";

export default function Navbar() {
  const { user, logout } = useAuth();

  return (
    <nav>
      <NavLink to="/" end>Dashboard</NavLink>
      <NavLink to="/settings">Settings</NavLink>
      <ThemeToggle />
      {user && (
        <span>
          {user} <button onClick={logout}>Logout</button>
        </span>
      )}
    </nav>
  );
}
```

Notice `end` prop in `<NavLink to="/" end>` — iska matlab hai "sirf tab active dikhao jab exactly `/` pe ho." Bina `end` ke, `/settings` pe bhi Dashboard active dikhega kyunki `/` se start hota hai. Small detail, big difference.

## Step 6 — App.tsx: Sab Kuch Jodna

```tsx
// App.tsx
import { BrowserRouter, Routes, Route } from "react-router-dom";
import { AuthProvider } from "./context/AuthContext";
import { ThemeProvider } from "./context/ThemeContext";
import Layout from "./components/Layout";
import ProtectedRoute from "./components/ProtectedRoute";
import Dashboard from "./pages/Dashboard";
import TaskDetail from "./pages/TaskDetail";
import Settings from "./pages/Settings";
import NotFound from "./pages/NotFound";

export default function App() {
  return (
    <BrowserRouter>
      <ThemeProvider>
        <AuthProvider>
          <Routes>
            <Route path="/" element={<Layout />}>
              <Route index element={<Dashboard />} />
              <Route path="tasks/:id" element={<TaskDetail />} />
              <Route path="settings" element={
                <ProtectedRoute>
                  <Settings />
                </ProtectedRoute>
              } />
              <Route path="*" element={<NotFound />} />
            </Route>
          </Routes>
        </AuthProvider>
      </ThemeProvider>
    </BrowserRouter>
  );
}
```

Provider order important hai — `BrowserRouter` sabse bahar, phir `ThemeProvider`, phir `AuthProvider`. Routes sabse andar. Is order se Router ka context sabko milta hai, aur theme + auth providers dono Router ke andar hain.

## Feature Map

| Route | Page | Auth Required | Description |
|---|---|---|---|
| `/` | Dashboard | No | Main tasks page — add, filter, toggle |
| `/tasks/:id` | TaskDetail | No | Dynamic route — individual task detail |
| `/settings` | Settings | **Yes** | Protected — sirf logged-in users |
| `/*` | NotFound | No | 404 — invalid routes |

## What It Is NOT

- **TaskDetail abhi real task data nahi dikha sakta** — kyunki tasks state Dashboard mein local hai. Cross-page state sharing ke liye global state chahiye (Batch 5-6 mein `useReducer` + Context aur Zustand seekhenge).
- **Protected Route sirf front-end guard hai** — koi bhi browser dev tools mein code dekh sakta hai. Real backend authorization alag se implement karni padti hai.
- **Is project mein koi naya feature nahi add kiya** (tasks, theme, categories same hain) — sirf navigation layer add ki hai. Features next batches mein optimize honge.

## In Your Own Words

<details>
<summary>V2 se v3 mein sabse bada architectural change kya hai?</summary>

Single page se multi-page architecture shift. V2 mein sab ek hi page mein render hota tha, user ko "pages" ka feel nahi tha. V3 mein React Router add kar ke real website jaisa navigation experience diya — alag URL har section ke liye, dynamic routes, 404 page. Components ko `pages/` (route-specific) aur `components/` (reusable) mein separate kiya.
</details>

<details>
<summary>`TaskDetail` page mein task data kahan se aayega? Current dummy solution kyun temporary hai?</summary>

Abhi tasks state Dashboard component ke andar `useState` mein hai — parent component ka state hai jo children ko props mein milta hai. `TaskDetail` ek alag route hai, Dashboard ka child nahi, isliye woh state access nahi kar sakta. Isliye abhi dummy data use kar rahe hain. Real solution yahi hai ki tasks state kisi global store mein ho (Context + useReducer ya Zustand) — tab koi bhi page access kar sakta hai.
</details>

<details>
<summary>Provider hierarchy (BrowserRouter → ThemeProvider → AuthProvider → Routes) kyun is specific order mein hai?</summary>

BrowserRouter sabse bahar — kyunki React Router ke saare components (Link, Routes, Navigate, useParams) ko Router context chahiye. ThemeProvider aur AuthProvider Router ke andar — kyunki Settings page mein `useAuth()` bhi chahiye aur ProtectedRoute mein `<Navigate>` bhi (jiske liye Router context chahiye). Agar AuthProvider Router ke bahar hota toh ProtectedRoute ka Navigate fail ho jaata.
</details>

<details>
<summary>NavLink mein `end` prop kya karta hai, aur yahan Dashboard link mein kyun use kiya?</summary>

`end` prop NavLink ko sirf exact match pe active banata hai. Bina `end` ke, `/settings` ya `/tasks/123` pe bhi Dashboard link active dikhega kyunki yeh paths `/` se start hote hain. `end` ke saath sirf tab active hoga jab exactly `/` pe ho. Isse navbar correctly current page highlight karta hai.
</details>
