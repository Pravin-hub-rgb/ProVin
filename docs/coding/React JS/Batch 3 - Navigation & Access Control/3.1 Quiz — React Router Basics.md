
## MCQ

Q: What component must wrap the entire app to enable routing in React Router?
A. `<Routes>` — container for all route definitions
B. `<BrowserRouter>` — provides routing context to the entire app
C. `<Route>` — defines a single path-component mapping
D. `<Link>` — creates a clickable navigation element
> B. BrowserRouter (or HashRouter) must wrap the app so the routing context is available. A is wrong — Routes is a container for Route components, not a router provider. C is wrong — a single Route isn't a provider. D is wrong — Link is a navigation element, not a context provider.

Q: What does the `<Routes>` component do?
A. Changes the browser URL without a server request
B. Renders every Route in the tree
C. Renders only the first Route whose path matches the current URL
D. Provides routing context to child components
> C. Routes renders only the first matching Route. A is wrong — that's what Link or navigate does. B is wrong — Routes only renders matching routes, not all. D is wrong — context is provided by BrowserRouter.

Q: In React Router v6, how do you map a path to a component in a `<Route>`?
A. `<Route path="/about" component={About} />`
B. `<Route path="/about" element={<About />} />`
C. `<Route path="/about"><About /></Route>`
D. `<Route><About path="/about" /></Route>`
> B. React Router v6 uses the `element` prop with JSX. A is wrong — the `component` prop was removed in v6. C is wrong — child syntax of this kind isn't supported in v6 (it was in v5). D is wrong — path goes on Route, not on the component.

Q: What is the key difference between `<Link>` and `<NavLink>`?
A. Link makes server-side requests, NavLink doesn't

C. NavLink can apply active styling based on the current route
D. NavLink triggers a page refresh, Link doesn't
> C. NavLink provides an `isActive` flag that lets you style the link for the current active route. A is wrong — both are client-side. B is wrong — both open in the same tab. D is wrong — neither triggers a page refresh.

Q: How do you pass active styling to a `NavLink`?
A. `className={isActive => isActive ? "active" : ""}`

> B. NavLink's className receives a destructured `{ isActive }` object. A is wrong — `isActive` must be destructured from the param. C is wrong — template strings don't work in className. D is wrong — `activeClassName` was removed in v6.

Q: What does the `path="*"` route match?
A. Every URL — this route triggers for all paths
B. Any URL that didn't match any other route
C. Overrides the home route (path="/")
D. Only works when the literal string `*` is typed
> B. The `*` wildcard catches all unmatched URLs — used for 404 pages. A is wrong — specific routes match first. C is wrong — it doesn't override the home route. D is wrong — `*` means "anything", not a literal match.

Q: Why must the `path="*"` route always be last in `<Routes>`?
A. The `*` route is slow and should be cached for later

## TrueFalse

Q: `BrowserRouter` uses the HTML5 History API to manage URLs.
- True
- False
> True. BrowserRouter uses the History API (`pushState`, `popState`) to change URLs without server requests. This gives clean URLs like `/about`, `/contact`.

---

Q: `<Link>` triggers a page refresh when clicked.
- True
- False
> False. Link renders an `<a>` tag but prevents the default behavior — no page refresh. React Router's internal history mechanism changes the URL, only the component swaps.

---

Q: `navigate(-1)` takes the user back one step in browser history.
- True
- False
> True. Negative values navigate backward through history. `navigate(-1)` is equivalent to the back button.

---

Q: `<Routes>` renders all matching Route components simultaneously.
- True
- False
> False. Routes renders only the first matching Route — one component at a time. If multiple routes match, only the first one renders.

---

Q: React Router v6 supports the `<Route component={About} />` syntax.
- True
- False
> False. v6 removed the `component` prop. You must use `element={<About />}`.

---

Q: A `NavLink`'s `className` can receive a function to style the active state.
- True
- False
> True. NavLink's className can be a function that receives `{ isActive }` — allowing different styling for the active route.

---

Q: In React Router, relative paths in nested routes are automatically concatenated with the parent path.
- True
- False
> True. A child with `path=":id"` under a parent with `path="products"` becomes `/products/:id`. The parent path is prepended automatically.

## ShortAnswer

Q: Explain the difference between `BrowserRouter` and `HashRouter`. When would you use each?

<details>
<summary>Sample Answer</summary>

**BrowserRouter** uses the HTML5 History API (`pushState`, `popState`). URLs are clean paths like `/about`, `/contact`. But the server must be configured to serve `index.html` for all routes — otherwise refreshing gives a 404.

**HashRouter** uses the URL hash (`#`). URLs look like `/#/about`, `/#/contact`. The hash part never reaches the server, so no server configuration is needed. Works on static hosting like GitHub Pages.

When to use each:
- **BrowserRouter** — production apps where you control the server
- **HashRouter** — static hosting, Sandpack, development, or anywhere server config isn't possible

</details>

Q: What is the difference between `useNavigate` and `<Navigate>`? Give a scenario for each.

<details>
<summary>Sample Answer</summary>

**`<Navigate />`** is a component — it's JSX. Render it and it immediately redirects. Use it when you need conditional redirects in the render path:

```tsx
// Redirect to login if not authenticated (declarative)
function ProtectedRoute({ children }) {
  const { user } = useAuth();
  if (!user) return <Navigate to="/login" replace />;
  return children;
}
```

**`useNavigate()`** is a hook — it returns a function you call. Use it when you need to navigate from within an event handler, async callback, timer, or any Imperative code:

```tsx
// Navigate after form submit (programmatic)
function LoginForm() {
  const navigate = useNavigate();
  function handleSubmit() {
    login();
    navigate("/dashboard", { replace: true });
  }
  return <button onClick={handleSubmit}>Login</button>;
}
```

**Rule of thumb:** JSX condition → `<Navigate />`. Code/logic → `useNavigate()`.

</details>

Q: When a user navigates to `/products/xyz` — an ID that doesn't exist in your data — what should `useParams` + `.find()` return, and how do you handle it?

<details>
<summary>Sample Answer</summary>

`useParams()` returns `{ id: "xyz" }` — the parameter is always a string from the URL. Then `products.find(p => p.id === id)` returns `undefined` because no product has that ID.

The guard handles it:

```tsx
const { id } = useParams<{ id: string }>();
const product = products.find(p => p.id === id);

if (!product) {
  return <h2>Product not found</h2>;
}

return <h1>{product.name}</h1>;
```

The `if (!product)` check catches the `undefined` case. Users can type any ID directly into the URL — the guard ensures a graceful "not found" message instead of a crash.

</details>
