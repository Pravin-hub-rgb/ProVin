# 3.2 Quiz — Dynamic Routes & Nested Routes

## MCQ

Q: React Router mein dynamic route banane ke liye path mein variable segment kaise define karte hain?
A. `path="/products/{id}"` — curly braces variable capture karte hain
B. `path="/products/:id"` — colon variable segment mark karta hai
C. `path="/products/$id"` — dollar sign variable define karta hai
D. `path="/products/[id]"` — square brackets segment capture karte hain
> B. Colon (`:`) React Router ka tarika hai path mein variable segment define karne ka. A galat — curly braces JSX expressions ke liye hain, routing ke liye nahi. C galat — dollar sign template literals mein use hota hai, route path mein nahi. D galat — square brackets React Router ka syntax nahi hai.

Q: `useParams` hook kya return karta hai?
A. Ek string — current URL ka poora path return hota hai
B. Ek number — kitne dynamic segments hain route mein
C. Ek object — keys variable names, values URL se extract
D. Ek array — har dynamic segment ki value ek element mein
> C. useParams ek object return karta hai jaise `{ id: "p1" }`. Keys wo names hain jo route path mein colon ke baad likhe the. A galat — poora path ke liye `useLocation()` hota hai. B galat — useParams count nahi return karta. D galat — array nahi, object return hota hai.

Q: `<Outlet />` component ka kya kaam hai nested routes mein?

D. Har child route ke liye navigation link banata hai
> B. Outlet ek placeholder hai — parent Layout mein jahan likho ge, child route ka element wahan render hoga. A galat — ye kaam Link ya navigate ka hai. C galat — Outlet ka server-side se koi lena-dena nahi. D galat — Outlet links nahi banata, sirf content render karta hai.

Q: `<Route index>` ka kya matlab hai?

B. Parent ka default child — parent path pe render hota hai
C. Sab routes mein pehle render hota hai har URL pe
D. Special route sirf development mode mein kaam karta hai
> B. Index route parent ke exact path pe default content dikhata hai — iska apna path nahi hota. A galat — index route ka HTML se koi relation nahi. C galat — yeh sirf parent path match hone pe render hota hai. D galat — yeh production mein bhi kaam karta hai.

Q: Index route ke baare mein kaunsa statement sahi hai?
A. Index route ki apni `path` property hoti hai
B. Ek parent mein multiple index routes ho sakte hain
C. Index route ka koi `path` nahi — parent path pe render
D. Index route sirf nested routes ke bahar kaam karta hai
> C. Index route ki koi path property nahi hoti — yeh parent ke path exactly match hone pe automatically render hota hai. A galat — path property nahi hoti. B galat — har parent ka sirf ek index route allowed hai. D galat — index route sirf nested children mein kaam karta hai.

Q: Nested routes mein child ka path `"products"` aur parent ka path `"shop"` hai — child ka full URL kya hoga?
A. `/products` — parent path ignore hota hai, direct root URL
B. `/shop` — child path ignore hota hai, direct root URL
C. `/shop/products` — React Router dono combine karta hai
D. `/shop-products` — hyphen se combine karta hai
> C. Relative paths nested routes mein automatically parent + child concatenate hote hain. Parent `"shop"` + child `"products"` = `/shop/products`. A galat — parent ignore nahi hota. B galat — child ignore nahi hota. D galat — hyphen concatenation React Router ka syntax nahi hai.

C. Error aayega kyunki slash allowed nahi hai child mein

> B. `/` prefix ka matlab absolute path — parent ignore hota hai aur route root se match karta hai. A galat — concatenation tab hota hai jab bina `/` ke child path ho. C galat — slash allowed hai. D galat — concatenation nahi hota.

Q: Agar parent Layout mein `<Outlet />` nahi hai, toh child route render hone par kya dikhega?

- True
- False
> True. Colon React Router ka syntax hai dynamic segment mark karne ke liye. `:id` ka matlab hai — "yeh segment variable hai, iski value URL se capture karo."

- True
- False
> False. Index route ki koi `path` property nahi hoti. Yeh parent route ke exact path pe hi render hota hai — iska apna koi path nahi hai.

- True
- False
> False. Outlet koi DOM element nahi banata. Yeh sirf ek conceptual placeholder hai — developer tools mein sirf child component ka element dikhega.

Q: Nested routes mein relative path (bina `/` ke) parent ke path ke saath automatically concatenate hota hai.
- True
- False
> True. Relative path parent + child combine karta hai. Jaise parent `"products"` + child `":id"` = `/products/:id`. Absolute path (`/` se start) parent ignore karta hai.

---

Q: `useParams` kisi bhi component mein call kiya ja sakta hai, chahe woh Route ke element ke andar ho ya nahi — hamesha current URL ka data milega.
- True
- False
> False. useParams sirf un components mein kaam karta hai jo `<Route element={...} />` ke through render hue hain. Route ke bahar ka component call karega toh undefined milega — kyunki React Router ka data context sirf Route tree ke andar available hota hai.

## ShortAnswer

Q: `<Outlet />` component kya karta hai? Nested routes mein iska kya role hai — bina Outlet ke kya problem hoti?

<details>
<summary>Sample Answer</summary>

`<Outlet />` ek placeholder component hai jo React Router provide karta hai. Parent Layout component mein jahan Outlet rakhte ho, child route ka component wahan render hota hai.

**Role of Outlet:**
- Parent Layout ek common frame provide karta hai (navbar, sidebar, footer)
- Outlet us frame mein woh jagah hai jahan child route ka content aata hai
- Jab URL change hota hai, Layout wahi rehta hai, sirf Outlet ka content badalta hai

**Bina Outlet ke problem:**
Agar parent Layout mein Outlet nahi hai, toh child routes render hi nahi hote. React Router ko koi jagah nahi milti jahan child component daale. Example:

```tsx
function Layout() {
  return (
    <div>
      <nav>...</nav>
      {/* ❌ Outlet nahi — child route kabhi render nahi hoga */}
    </div>
  );
}
```

Agar URL `/products` pe bhi jao, sirf navbar dikhega — ProductList nahi. Outlet ke bina nested routes ka koi fayda nahi.

**Analogy:** TV + HDMI port. TV = Layout (frame fixed). HDMI port = Outlet (jahan bhi device lagao, content aata hai). Device (PlayStation, Fire Stick) = child route. TV ka frame nahi badalta, sirf HDMI port pe content badalta hai.
</details>

Q: Dynamic routes aur `useParams` hook kaise kaam karte hain? Ek example ke saath explain karo ki URL se value kaise capture hoti hai aur data lookup kaise kiya jata hai.

<details>
<summary>Sample Answer</summary>

**Dynamic routes** wo routes hain jinme path ka kuch part variable hota hai. Colon (`:`) se variable mark karte hain:

```tsx
<Route path="/items/:itemId" element={<ItemDetail />} />
```

Jab URL `/items/abc123` hai, to `:itemId` ne `"abc123"` capture kiya.

**useParams hook** React Router se yeh captured values nikaalta hai:

```tsx
import { useParams } from "react-router-dom";
const { itemId } = useParams();
// itemId = "abc123"
```

**Complete data lookup pattern:**

```tsx
const items = [
  { id: "a1", name: "Item 1" },
  { id: "a2", name: "Item 2" },
];

export default function ItemDetail() {
  const { itemId } = useParams();
  const item = items.find(i => i.id === itemId);

  if (!item) {
    return <h2>Item not found</h2>;  // guard
  }

  return <h1>{item.name}</h1>;
}
```

**Flow step by step:**
1. Browser URL `/items/a2`
2. React Router path `/items/:itemId` match karta hai
3. `:itemId` ne `"a2"` capture kiya
4. `<ItemDetail />` render hota hai
5. `useParams()` return karta hai `{ itemId: "a2" }`
6. `items.find(i => i.id === "a2")` se matching item milta hai
7. Guard check karta hai ki item undefined nahi hai
8. Render

**Guard kyun zaroori?** User directly URL mein kuch bhi type kar sakta hai (`/items/xyz`). Agar item exist nahi karta, guard "not found" message dikhata hai instead of crash.
</details>

Q: Relative aur absolute paths nested routes mein kya difference hai? Har ek ka example do aur batado kab kaunsa use karna chahiye.

<details>
<summary>Sample Answer</summary>

**Relative path** — bina `/` ke start hota hai. Parent path ke saath automatically concatenate hota hai:

```tsx
<Route path="dashboard" element={<Layout />}>
  <Route path="settings" element={<Settings />} />     {/* → /dashboard/settings */}
  <Route path=":id" element={<Profile />} />            {/* → /dashboard/123 */}
</Route>
```

**Absolute path** — `/` se start hota hai. Parent path ko ignore karta hai, root se match karta hai:

```tsx
<Route path="dashboard" element={<Layout />}>
  <Route path="/help" element={<Help />} />             {/* → /help, NOT /dashboard/help */}
</Route>
```

**Kab kaunsa use karein:**

| Scenario | Type | Example |
|---|---|---|
| Child parent ke under ka hai | Relative | `path="settings"` → `/dashboard/settings` |
| Dynamic segment | Relative | `path=":id"` → `/dashboard/123` |
| Child ka parent se koi lena-dena nahi | Absolute | `path="/about"` → `/about` |
| Cross-section reuse | Absolute | `path="/trending"` → `/trending` |

**Common mistakes:**
- Relative path ko `"/:id"` likhna → root URL se match hoga (`/123`), `/dashboard/123` nahi
- Absolute path ko bina `/` ke likhna → parent se concatenate ho jayega (`/help` nahi, `/dashboard/help`)

**Rule of thumb:** Agar route logically parent ke under aata hai to relative. Agar completely alag section hai to absolute.
</details>
