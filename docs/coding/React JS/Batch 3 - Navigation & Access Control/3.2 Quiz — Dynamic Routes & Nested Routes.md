
## MCQ

Q: How do you define a dynamic segment in a React Router path?
A. `path="/products/{id}"` — curly braces capture variables
B. `path="/products/:id"` — the colon marks a variable segment
C. `path="/products/$id"` — dollar sign defines a variable
D. `path="/products/[id]"` — square brackets capture segments
> B. The colon (`:`) is React Router's syntax for marking a variable path segment. A is wrong — curly braces are for JSX expressions. C is wrong — dollar signs are for template literals. D is wrong — square brackets are not React Router syntax.

Q: What does the `useParams` hook return?
A. A string — the full current URL path
B. A number — how many dynamic segments exist in the route
C. An object — keys are variable names, values are extracted from the URL
D. An array — each dynamic segment value as an element
> C. `useParams` returns an object like `{ id: "p1" }`. The keys match the names defined after the colon in the route path. A is wrong — use `useLocation()` for the full path. B is wrong — it doesn't return a count. D is wrong — it returns an object, not an array.

Q: What does the `<Outlet />` component do in nested routes?
A. Changes the browser URL on click
B. Provides a placeholder in the parent layout where child routes render
C. Enables server-side rendering for nested routes
D. Creates navigation links for each child route
> B. `Outlet` is a placeholder — wherever you place it in the parent Layout, the matched child route's component renders there. A is wrong — that's Link or navigate. C is wrong — no SSR-specific feature. D is wrong — it renders content, not links.

Q: What does `<Route index>` mean?
A. Refers to the browser's index.html file

> B. An index route renders as the parent's default child when the parent's path matches exactly. It has no `path` of its own. A is wrong — unrelated to index.html. C is wrong — only renders on the parent's exact path. D is wrong — works in production too.

Q: In nested routes, if a parent path is `"shop"` and a child path is `"products"`, what is the child's full URL?

> C. Relative paths in nested routes are automatically concatenated with the parent path. Parent `"shop"` + child `"products"` = `/shop/products`. A is wrong — parent isn't ignored. B is wrong — child isn't ignored. D is wrong — no hyphen concatenation.

A. The parent path is prepended — full path becomes `/shop/about`

C. An error occurs because `/` isn't allowed in child paths
D. Concatenation happens — full path becomes `/shop/about`
> B. A leading `/` makes the path absolute — it ignores the parent and matches from the root. A is wrong — concatenation only happens with relative (no slash) paths. C is wrong — `/` is allowed. D is wrong — no concatenation for absolute paths.

## TrueFalse

Q: Dynamic route paths use a colon to define variable segments, like `/movies/:id`.
- True
- False
> True. The colon is React Router's syntax for marking a variable path segment. `:id` captures that segment's value from the URL.

---

Q: Index routes have their own `path` property that's independent of the parent.
- True
- False
> False. Index routes don't have a `path` property. They render when the parent's exact path matches — they have no path of their own.

---

Q: `<Outlet />` renders an extra DOM wrapper element around child components.
- True
- False
> False. `Outlet` doesn't render any DOM element — it's a conceptual placeholder. Only the child component itself appears in DevTools.

---

Q: In nested routes, relative paths (without a leading `/`) are automatically concatenated with the parent path.
- True
- False
> True. Relative child paths combine with the parent: parent `"products"` + child `":id"` = `/products/:id`. Absolute paths (starting with `/`) ignore the parent.

---

Q: `useParams` can be called in any component regardless of whether it's inside a Route.
- True
- False
> False. `useParams` only works inside components rendered through `<Route element={...} />`. Outside the Route tree, it returns undefined.

## ShortAnswer

Q: How do `useParams` and dynamic routes work together? Show an example of capturing an ID from the URL and looking up data.

<details>
<summary>Sample Answer</summary>

Dynamic routes let you define variable segments in a path using a colon:

```tsx
<Route path="/items/:itemId" element={<ItemDetail />} />
```

When the URL is `/items/abc123`, the `:itemId` segment captures `"abc123"`.

The `useParams` hook retrieves those captured values:

```tsx
import { useParams } from "react-router-dom";

const { itemId } = useParams();
// itemId = "abc123"
```

Complete data lookup pattern:

```tsx
const items = [
  { id: "a1", name: "Item 1" },
  { id: "a2", name: "Item 2" },
];

export default function ItemDetail() {
  const { itemId } = useParams();
  const item = items.find(i => i.id === itemId);

  if (!item) {
    return <h2>Item not found</h2>; // guard for invalid IDs
  }

  return <h1>{item.name}</h1>;
}
```

**Step-by-step flow:**
1. User visits `/items/a2`
2. React Router matches path `/items/:itemId`
3. `:itemId` captures `"a2"`
4. `<ItemDetail />` renders
5. `useParams()` returns `{ itemId: "a2" }`
6. `items.find(i => i.id === "a2")` finds the matching item
7. Guard checks if item exists
8. Render the item

The guard is important because a user can type any URL — `/items/xyz` won't crash, it gracefully shows "Item not found."

</details>

Q: What's the difference between relative and absolute paths in nested routes? Give an example of each and when to use which.

<details>
<summary>Sample Answer</summary>

**Relative path** (no leading `/`): Concatenated with the parent path automatically:

```tsx
<Route path="dashboard" element={<Layout />}>
  <Route path="settings" element={<Settings />} />  {/* → /dashboard/settings */}
  <Route path=":id" element={<Profile />} />        {/* → /dashboard/123 */}
</Route>
```

**Absolute path** (leading `/`): Ignores parent, matches from root:

```tsx
<Route path="dashboard" element={<Layout />}>
  <Route path="/help" element={<Help />} />         {/* → /help, NOT /dashboard/help */}
</Route>
```

**When to use each:**

| Scenario | Type | Example |
|---|---|---|
| Child logically belongs under parent | Relative | `path="settings"` → `/dashboard/settings` |
| Dynamic segment | Relative | `path=":id"` → `/dashboard/123` |
| Child is independent of parent | Absolute | `path="/about"` → `/about` |
| Cross-section reuse | Absolute | `path="/trending"` → `/trending` |

**Common mistakes:**
- Forgetting: `path="/:id"` becomes `/123` (root match), not `/products/123`
- Forgetting: `path="about"` becomes `/products/about`, not `/about`

**Rule of thumb:** If the route logically belongs under the parent → relative. If it's completely separate → absolute.
</details>

Q: What happens when a parent Layout doesn't render `<Outlet />`? Explain with the visual analogy.

<details>
<summary>Sample Answer</summary>

Without `<Outlet />`, child routes have no place to render — they silently don't appear. It's like having a TV with no HDMI port. You plug in a PlayStation, but there's nowhere to connect it — you just see the TV's empty frame.

```tsx
function Layout() {
  return (
    <div>
      <nav>Navigation</nav>
      {/* ❌ No <Outlet /> — children have nowhere to render */}
    </div>
  );
}
```

Even if the URL is `/products`, only the `<nav>` renders. The ProductList component is never shown. `<Outlet />` is the port where child content plugs in.

Think of it as a picture frame:
- **Layout** = the frame (navigation, header, footer — stays the same)
- **`<Outlet />`** = the slot where the picture goes
- **Child route** = the picture (different content for each route)

No slot = no picture = empty frame.
</details>
