## Cheat Sheet (Quick Recall)

```tsx
import { BrowserRouter, Routes, Route, Link } from "react-router-dom";

// BrowserRouter wrap karta hai poori app
<BrowserRouter>
  <Routes>
    <Route path="/" element={<Home />} />
    <Route path="/about" element={<About />} />
  </Routes>
</BrowserRouter>

// <a> ki jagah Link use karo — reload nahi hoga
<Link to="/about">About</Link>

// Programmatic navigation
const navigate = useNavigate();
navigate("/about");       // push
navigate("/about", { replace: true });  // history replace karo
navigate(-1);             // back (history stack)

// NavLink — active route ke liye styling
<NavLink to="/" className={({ isActive }) => isActive ? "active" : ""}>
  Home
</NavLink>
```

## Abhi Tak Kya Hua

Batch 2 mein effects, refs, aur Context API seekha — data fetch karna, DOM refs handle karna, prop drilling se bachna. Lekin ab tak **sab kuch ek hi page** mein tha. User ek component se doosre component mein jaata tha? Nahin — sab ek hi screen par render hota tha.

Ab hum seekhenge **navigation** — React Router ke saath multiple pages banana, URL ke hisaab se components render karna, aur user ko ek "page" se doosre "page" le jaana bina browser reload kiye.

## Broader Goal

React Router react mein multi-page feel deta hai jabki asli app ek hi page hai (SPA — Single Page Application). Traditional websites mein har link click pe naya HTML page server se aata hai — isko kehte hain full page reload. SPA mein sirf component change hota hai, page reload nahi hota. Isse app fast feel hoti hai, aur user experience seamless rehta hai.

Batch 3 mein hum seekhenge: routes banana, dynamic URLs (jaise `movies/tt123456`), nested layouts, aur protected routes (bina login ke kuch pages access nahi kar sakte). Sabse pehle — React Router ka setup samajhte hain.

## Step 2 — BrowserRouter: Router Ka Provider

Koi bhi routing karne se pehle, app ko `<BrowserRouter>` mein wrap karna mandatory hai. BrowserRouter React ko batata hai ki "ab URL changes ko track karunga aur according render karunga." Yeh ek provider component hai — jaise Context ka provider tha, waise hi.

```tsx
// main.tsx ya App.tsx — jahan bhi entry point hai
import { BrowserRouter } from "react-router-dom";

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </React.StrictMode>
);
```

**Kyun BrowserRouter?** Kuch aur routers bhi hain — `HashRouter` (URL mein `#` use karta hai, older browsers ke liye), `MemoryRouter` (testing ke liye). Production apps mein `BrowserRouter` standard hai — yeh HTML5 history API use karta hai aur clean URLs deta hai (`/about`, `/contact`).

> **What It Is NOT:** BrowserRouter server ko kuch nahi batata. Jab tu `/about` pe jayega, toh browser server se koi request nahi karega — React khud decide karega ki kaunsa component dikhana hai. Isliye production deploy karte waqt server ko configure karna padta hai ki har route pe `index.html` serve kare. Abhi ke liye itna yaad rakh — development mein Vite sab sambhal leta hai.

## Step 3 — Routes aur Route: URL → Component Mapping

`<Routes>` ek container hai jisme `<Route>` components hote hain. Har Route ek path ko ek component se map karta hai:

```tsx
import { Routes, Route } from "react-router-dom";

function App() {
  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/about" element={<About />} />
      <Route path="/contact" element={<Contact />} />
    </Routes>
  );
}
```

**Kaise kaam karta hai:**
1. User browser mein `/about` type karta hai
2. React Router `/about` ko Routes mein har Route ke path se match karta hai
3. Jahan match milta hai (`path="/about"`), wahan ka `element` render hota hai
4. `<Home />` aur `<Contact />` render nahi hote — sirf matching wala component

**Important:** Sirf ek Route ka element ek time pe render hota hai. Routes ke andar ek hi Route match karega (pehla match). Agar koi bhi Route match nahi karta toh kuch bhi render nahi hota — isliye 404 page ke liye `path="*"` use karte hain.

```tsx
<Route path="*" element={<NotFound />} />
```

`*` ka matlab hai "jo bhi bache hue paths hain." Yeh sabse last mein rakhna — pehle specific routes, phir `*`.

## Step 4 — Link: &lt;a&gt; Ki Jagah

SPA mein agar `<a href="/about">` use karoge toh browser page reload kar dega — poora app dubara load hoga, state reset ho jayegi. Isliye React Router ka `<Link>` component use karte hain:

```tsx
import { Link } from "react-router-dom";

function Navbar() {
  return (
    <nav>
      <Link to="/">Home</Link>
      <Link to="/about">About</Link>
      <Link to="/contact">Contact</Link>
    </nav>
  );
}
```

`<Link>` browser mein `<a>` tag render karta hai, lekin click pe `event.preventDefault()` lagata hai aur React Router ke internal history mechanism se URL change karta hai. Reload nahi hota, sirf component swap hota hai.

**Socho:** Agar restaurant ka menu ho — `<a>` waiter ko bhejta hai "jao kitchen se naya lao" (reload). `<Link>` waiter ko bolega "jo abhi hai wahi le ao, bas plate badlo" (component swap). Yeh chhoti si cheez hai, lekin app ki speed aur user experience mein bohot fark padta hai.

## Step 5 — useNavigate: Code Se Navigation

Kabhi kabhi button click karne ke baad, form submit karne ke baad, ya koi async operation ke baad navigate karna hota hai. Link component ke saath yeh possible nahi kyunki Link sirf click event handle karta hai. Yahan `useNavigate` hook use karte hain:

```tsx
import { useNavigate } from "react-router-dom";

function LoginPage() {
  const navigate = useNavigate();

  function handleLogin() {
    // ...login logic...
    navigate("/dashboard"); // login ke baad dashboard pe bhejo
  }

  return (
    <div>
      <button onClick={handleLogin}>Login</button>
    </div>
  );
}
```

**useNavigate ke common patterns:**

```tsx
navigate("/about");                    // history mein naya entry add karo
navigate("/about", { replace: true }); // replace karo (wapas nahi aa sakta)
navigate(-1);                          // ek step piche jao (browser back)
navigate(2);                           // do step aage jao
```

`replace: true` tab use karo jab user ko wapas nahi aane dena chahte — jaise login ke baad dashboard pe bheja, toh user back press karega toh login page pe nahi jayega.

## Step 6 — NavLink: Active Route Styling

NavLink Link ka advanced version hai. Jab uska `to` current URL se match karta hai, toh usme ek active class lag jaati hai. Isse navigation menu mein "current page" highlight kar sakte ho:

```tsx
import { NavLink } from "react-router-dom";

function Navbar() {
  return (
    <nav>
      <NavLink to="/" className={({ isActive }) => isActive ? "nav-link active" : "nav-link"}>
        Home
      </NavLink>
      <NavLink to="/movies" className={({ isActive }) => isActive ? "nav-link active" : "nav-link"}>
        Movies
      </NavLink>
    </nav>
  );
}
```

Yahan `isActive` ek boolean hai jo NavLink automatically provide karta hai. Jab current URL `/movies` hai, toh doosre NavLink ko `"nav-link active"` class milega. CSS mein `.active` ko style karo:

```css
.nav-link { color: gray; text-decoration: none; }
.nav-link.active { color: blue; font-weight: bold; }
```

## Mini-Project: Movie Browser (Part 1 — Home Page)

Ye mini-project hum do parts mein banayenge. Part 1 (yahan) mein home page banayenge — movies ki list with links. Part 2 (3.2 mein) movie detail page banayenge dynamic route ke saath.

### Step 1 — Movie Data + Home Page Component

Pehle ek simple movie list component banao:

```tsx
// components/MovieList.tsx
import { Link } from "react-router-dom";

const movies = [
  { id: "tt1375666", title: "Inception", year: 2010 },
  { id: "tt0816692", title: "Interstellar", year: 2014 },
  { id: "tt0133093", title: "The Matrix", year: 1999 },
  { id: "tt0167260", title: "The Lord of the Rings: The Return of the King", year: 2003 },
  { id: "tt0111161", title: "The Shawshank Redemption", year: 1994 },
];

export default function MovieList() {
  return (
    <div>
      <h1>🍿 Movie Browser</h1>
      <div className="movie-grid">
        {movies.map((movie) => (
          <div key={movie.id} className="movie-card">
            <h3>{movie.title}</h3>
            <p>{movie.year}</p>
            <Link to={`/movies/${movie.id}`}>View Details →</Link>
          </div>
        ))}
      </div>
    </div>
  );
}
```

Notice kiya `Link to` mein dynamic path hai — `/movies/${movie.id}`. Har movie ki apni detail page hogi, aur yeh path 3.2 mein `useParams` se capture karenge.

### Step 2 — App.tsx with Router Setup

```tsx
// App.tsx
import { BrowserRouter, Routes, Route } from "react-router-dom";
import MovieList from "./components/MovieList";

function HomePage() {
  return (
    <div>
      <h2>Welcome to Movie Browser</h2>
      <p>Browse our collection of classic movies.</p>
    </div>
  );
}

export default function App() {
  return (
    <BrowserRouter>
      <div className="app">
        <nav>
          <Link to="/">Home</Link>
          <Link to="/movies">Movies</Link>
        </nav>
        <Routes>
          <Route path="/" element={<HomePage />} />
          <Route path="/movies" element={<MovieList />} />
          <Route path="*" element={<h2>404 — Page not found</h2>} />
        </Routes>
      </div>
    </BrowserRouter>
  );
}
```

Kyun `<BrowserRouter>` App ke andar? Kuch developers `main.tsx` mein wrap karte hain, kuch App ke andar. Dono kaam karte hain. Fark sirf scope ka hai — App ke andar rakhoge toh router-specific code ek hi jagah rehta hai. Project structure pe depend karta hai.

### Step 3 — Test Karo

1. `/` → "Welcome to Movie Browser" dikhe
2. `/movies` → 5 movies ki list dikhe, har movie ka "View Details" link ho
3. `/movies/tt1375666` → abhi sirf blank page dikhega (kyunki is path ka koi route nahi hai — 3.2 mein fix karenge)
4. `/xyz` → "404 — Page not found" dikhe

Is step tak humne React Router ka basic setup seekh liya: BrowserRouter, Routes, Route, Link. Agle topic mein dynamic routes aur `useParams` seekhenge.

## What It Is NOT

- **React Router server-side routing nahi hai** — yeh client-side hai. URL badalta hai par server pe koi request nahi jaati.
- **`<Link>` ek `<a>` tag render karta hai** — lekin default behavior override karta hai. CSS styling same `<a>` ki tarah kaam karti hai.
- **React Router app ko multi-page nahi banata** — yeh ek hi page (SPA) ko multi-page *feel* deta hai. Isliye "Single Page Application" kehte hain.
- **Router app ke top-level pe hona chahiye** — BrowserRouter ko component tree ke sabse upar rakho, nahi toh `useNavigate`, `Link`, `Routes` kaam nahi karenge.

## In Your Own Words

<details>
<summary>React Router kyu use karte hain? Simple &lt;a&gt; tag se kya problem hai?</summary>

&lt;a&gt; tag click karne poora page reload hota hai — browser server se naya HTML leta hai, React app ka sara state reset ho jata hai, aur ek flash (blank screen) aati hai. React Router ka Link component sirf component swap karta hai — state preserve hoti hai, reload nahi hota, aur transition smooth rehti hai.
</details>

<details>
<summary>`BrowserRouter` ka kaam kya hai? Use karna kyu mandatory hai?</summary>

BrowserRouter ek provider component hai jo React Router ko browser ke URL changes ke baare mein batata hai. Yeh window.location aur HTML5 history API ko listen karta hai, aur jab URL change hota hai toh Routes ko re-render trigger karta hai. Iske bina Routes, Link, useNavigate — kuch bhi kaam nahi karega kyunki Router ka context hi available nahi hoga.
</details>

<details>
<summary>`path="*"` wala Route kya karta hai, aur use kahan karna chahiye?</summary>

`*` match karta hai saare un paths ko jo upar kisi bhi Route se match nahi hue. Isse 404 page banane ke liye use karte hain. Yeh sabse last Route hona chahiye — pehle specific paths, phir `*`.
</details>

<details>
<summary>`useNavigate` aur `Link` mein kya difference hai? Kab kya use karna chahiye?</summary>

`Link` ek component hai jo sirf click event handle karta hai — user visible link ke liye. `useNavigate` ek hook hai jo code se navigation allow karta hai — form submit ke baad, API response ke baad, timeout ke baad, ya kisi bhi async operation ke baad navigate karne ke liye.
</details>

<details>
<summary>`NavLink` aur `Link` mein kya fark hai? `isActive` kya hota hai?</summary>

`NavLink` `Link` ka extended version hai jo automatically detect karta hai ki kya uska `to` current URL se match karta hai. `isActive` ek boolean parameter hai jo className ya style prop mein milta hai — true hai toh current route active hai. Isse navigation menu mein "current page" highlight karne ke liye use karte hain (jaise bold ya different color).
</details>
