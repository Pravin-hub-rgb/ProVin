## Step 3 — ThemeContext (Context API)

Remember in 2.6 we built the `useTheme()` custom hook? Same pattern here. Theme toggle logic lives in one place — `ThemeContext.tsx`:

**Step 3a — Types + createContext + useTheme hook:**

```ts
// context/ThemeContext.tsx
import { createContext, useContext, type ReactNode } from "react";

type Theme = "light" | "dark";

interface ThemeContextValue {
  theme: Theme;
  toggleTheme: () => void;
}

const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);

export function useTheme(): ThemeContextValue {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error("useTheme must be used within ThemeProvider");
  return ctx;
}
```

**Step 3b — ThemeProvider with useMemo for stable value:**

Now we create `ThemeProvider`. In 2.6, we saw that the context value creates a new object reference on every render, causing unnecessary re-renders. `useCallback` keeps `toggleTheme` stable (it never gets a new reference), and `useMemo` only creates a new `value` when `theme` actually changes. This pattern is critical for performance in larger apps.

```tsx
import { useState, useCallback, useMemo } from "react";

export function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<Theme>("light");
  const toggleTheme = useCallback(() => {
    setTheme((prev) => (prev === "light" ? "dark" : "light"));
  }, []);

  const value = useMemo(() => ({ theme, toggleTheme }), [theme]);

  return <ThemeContext value={value}>{children}</ThemeContext>;
}
```

## Step 4 — Components (One at a time)

Now we build the components — one component per file. This keeps the separation of concerns clean. In 2.5.0, we saw the pattern: data goes down, actions go up:

**Step 4a — ThemeToggle: Context's first consumer**

The simplest component. It uses `useTheme()` from context:

```tsx
// components/ThemeToggle.tsx
import { useTheme } from "../context/ThemeContext";

function ThemeToggle() {
  const { theme, toggleTheme } = useTheme();

  return (
    <button onClick={toggleTheme}>
      {theme === "light" ? "🌙 Dark" : "☀️ Light"}
    </button>
  );
}

export default ThemeToggle;
```

Why use `useTheme` directly? `ThemeToggle` is always rendered inside `ThemeProvider` — if someone uses it outside, the guard gives a clear error.

**Phase 3 — useRef for auto-focus:**

```tsx
function TaskInput({ onAdd }: { onAdd: (text: string) => void }) {
  const [text, setText] = useState("");
  const inputRef = useRef<HTMLInputElement>(null);

  useEffect(() => {
    inputRef.current?.focus();
  }, []);

  const handleClick = () => {
    console.log("Adding:", text);
  };

  return (
    <div>
      <input ref={inputRef} value={text} onChange={(e) => setText(e.target.value)} placeholder="Add a task..." />
      <button onClick={handleClick}>Add</button>
    </div>
  );
}
```

On page load — does the cursor automatically focus on the input? ✅

**Phase 4 — Replace logic (console.log → onAdd):**

```tsx
const handleClick = () => {
  if (text.trim() !== "") {
    onAdd(text.trim());
    setText("");
    inputRef.current?.focus();
  }
};

async function fetchCategories(): Promise<string[]> {
  const res = await fetch(
    "https://www.themealdb.com/api/json/v1/1/categories.php"
  );
  const data = await res.json();
  return data.categories.map((c: any) => c.strCategory).slice(0, 5);
}
```

Create the component. Just state and hardcoded data for now — no useEffect, no API. Think: first set up state and verify the UI renders, then add useEffect.

function ToDoApp() {

    { id: 2, text: "Build Recipe Finder", completed: true, category: "Projects" },

    { id: 4, text: "Deploy To-Do App v2", completed: false, category: "Projects" },

  const [filter, setFilter] = useState<FilterStatus>("all");
  const [categories, setCategories] = useState<string[]>([]);
  const { theme } = useTheme();

You should see the task list and filter working. But categories are empty — now let's add useEffect.

**Step 5d — useEffect for categories fetch (ignore pattern from 2.2):**

```tsx
  // useEffect: fetch categories on mount with ignore pattern (remember 2.2?)
  useEffect(() => {
    let ignore = false;
    fetchCategories().then((cats) => {
      if (!ignore) setCategories(cats);
    });
    return () => { ignore = true; };
  }, []);
```

Same ignore pattern we learned in 2.2 — prevents race conditions. Categories are fetched only on mount (`[]`). Check the console — does "Categories loaded: Beef, Chicken, Dessert..." appear?

**Step 5e — Event handlers (console.log first, always):**

We could write `onAdd` directly, but build the habit: log first, then hook up the real logic:

```tsx
  const handleAdd = (text: string) => {
    console.log("Adding:", text);
    const category = categories[Math.floor(Math.random() * categories.length)] || "General";
    setTasks([...tasks, { id: Date.now(), text, completed: false, category }]);
  };

  const handleToggle = (id: number) => {
    console.log("Toggling:", id);
    setTasks(tasks.map((t) =>
      t.id === id ? { ...t, completed: !t.completed } : t
    ));
  };

  const handleDelete = (id: number) => {
    console.log("Deleting:", id);
    setTasks(tasks.filter((t) => t.id !== id));
  };
```

State lives in App, children receive callbacks via props — **data down, actions up** pattern.

**Step 5f — Derived state + computed values:**

Calculate styles based on theme, and the filtered task list:

```tsx
  const filteredTasks = tasks.filter((t) => {
    if (filter === "active") return !t.completed;
    if (filter === "completed") return t.completed;
    return true;
  });

  const completedCount = tasks.filter((t) => t.completed).length;
  const remainingCount = tasks.length - completedCount;

  const styles: Record<string, React.CSSProperties> = {
    app: {
      padding: "20px",
      maxWidth: "600px",
      margin: "0 auto",
      background: theme === "dark" ? "#1a1a2e" : "#fff",
      color: theme === "dark" ? "#fff" : "#000",
      minHeight: "100vh",
      transition: "all 0.3s",

  };
```

    <div style={styles.app}>

        remaining={remainingCount}

## Common Mistakes

1. **Using `useTheme()` outside `ThemeProvider`** — throws error "must be used within ThemeProvider". That's why `ToDoApp` is rendered inside `ThemeProvider`.
2. **Forgetting error handling on categories fetch** — Only the success case is handled. If the API is down, `categories` stays empty. Production code needs `try/catch` (practice section at the end covers this).
3. **Not cleaning up `useRef`** — React DOM automatically cleans up refs on unmount, but if you've attached side effects to a ref, clean those up too.
4. **Not memoizing Context value** — ThemeContext uses `useMemo`. Without it, every render creates a new object reference → all consuming components re-render unnecessarily.
