# 2.4 — useRef

## Cheat Sheet (Quick Recall)

```ts
const inputRef = useRef<HTMLInputElement>(null);  // DOM ref — readonly .current
const intervalRef = useRef<number | null>(null);  // mutable value — writable .current

// DOM access
useEffect(() => { inputRef.current?.focus(); }, []);
// Mutable store
intervalRef.current = setInterval(() => {}, 1000);
```

- **DOM ref**: `useRef<HTMLInputElement>(null)` → `.current` = DOM node after mount (readonly)
- **Mutable ref**: `useRef<number>(0)` → `.current` change kar sakte ho, re-render nahi hota
- **Key insight**: null initial = DOM ref (readonly). Any value = mutable.

## Abhi Tak Kya Hua

2.3 mein TanStack React Query seekhi — data fetching automated. Lekin ek aur category hai jo useState ya useEffect se handle nahi hoti: **direct DOM access**. Input pe focus karna, video element control karna, ya interval ID store karna — iske liye useRef chahiye.

## Step 1 — Problem Feel Karo: useState Se DOM Access

Input pe focus karna hai page load pe. useState se kar sakte hain?

```tsx
const [inputEl, setInputEl] = useState(null);

return <input ref={(el) => setInputEl(el)} />;
```

Yeh kaam karega, lekin:
- Har render pe naya callback banega (ref function)
- useState change → re-render (unnecessary)
- State ka kaam UI update karna hai — DOM access alag concern hai

**useRef iska solution hai** — ek object jo re-render trigger kiye bina value store karta hai.

---

## Step 2 — useRef Basics

```ts
const ref = useRef(initialValue);
// ref = { current: initialValue }
```

- Returns ek **mutable object** jisme `.current` property hai
- Object **same reference** har render pe — kabhi change nahi hota
- `.current` change karo → **re-render nahi hota**
- Jab component unmount hota hai, React automatically DOM refs ko clean up karta hai

### TypeScript Typing

```ts
// DOM ref (initial value: null → RefObject with readonly .current)
const inputRef = useRef<HTMLInputElement>(null);
// typeof inputRef → RefObject<HTMLInputElement | null>

// Mutable value (initial value: number → MutableRefObject)
const intervalRef = useRef<number | null>(null);
// typeof intervalRef → MutableRefObject<number | null>
```

**Key insight:** `null` initial value → TypeScript infer karta hai "yeh DOM ref hai" → `.current` **readonly**. Koi bhi initial value → mutable.

**Nutshell:** `useRef(initialValue)` ek mutable object `{ current: initialValue }` return karta hai jo har render mein same reference rehta hai. Iski value change karne se re-render nahi hota — unlike useState.

## Step 3 — Mini-Project 1: Auto-Focus Input

Page load pe input automatically focus ho. `document.querySelector` se kar sakte hain, lekin React ka tarika `useRef` hai.

```tsx
import { useRef, useEffect } from "react";

function AutoFocusInput() {
  const inputRef = useRef<HTMLInputElement>(null);

  useEffect(() => {
    // Component mount hone ke baad DOM element ready hai
    inputRef.current?.focus();
    console.log("📍 Input focused:", inputRef.current?.placeholder);
  }, []);

  return (
    <div>
      <input ref={inputRef} type="text" placeholder="Auto-focused!" />
    </div>
  );
}
```

**`ref={inputRef}`** → React mount hone ke baad `inputRef.current` ko actual DOM element set kar deta hai. useEffect render ke baad chalta hai — tab `.current` set ho chuka hota hai.

> **What It Is NOT:** `useRef` ki value render ke andar mat padho ya likho. React purity tod jaayegi. Sirf event handlers ya useEffect mein use karo.

## Step 4 — Mini-Project 2: Stopwatch

Ek stopwatch chahiye — Start/Stop/Reset buttons ke saath. `setInterval` use karenge, aur interval ID state mein rakhoge to har update pe re-render hoga — unnecessary. Ref mein store karo — re-render nahi hoga, aur cleanup bhi kar sakte hain. Socho **notepad paper jaisa** — jo likho woh yaad rahega lekin kisi ko pata nahi chalega. Ref bhi waisa hi hai — value store hoti hai lekin React ko re-render trigger nahi karta.

```tsx
import { useState, useRef } from "react";

function Stopwatch() {
  const [seconds, setSeconds] = useState(0);
  const [isRunning, setIsRunning] = useState(false);
  const intervalRef = useRef<ReturnType<typeof setInterval> | null>(null);

  const start = () => {
    if (isRunning) return;

    setIsRunning(true);
    intervalRef.current = setInterval(() => {
      setSeconds((prev) => prev + 1);
    }, 1000);
  };

  const stop = () => {
    if (intervalRef.current) {
      clearInterval(intervalRef.current);
      intervalRef.current = null;
    }
    setIsRunning(false);
  };

  const reset = () => {
    stop();
    setSeconds(0);
  };

  return (
    <div style={{ padding: "20px" }}>
      <h1>⏱️ Stopwatch: {seconds}s</h1>
      <button onClick={start} disabled={isRunning}>Start</button>
      <button onClick={stop} disabled={!isRunning}>Stop</button>
      <button onClick={reset}>Reset</button>
    </div>
  );
}
```

**Why ref for interval ID?**
- `intervalRef.current` change → **no re-render**. State change → re-render hota hai (seconds update ke liye chahiye), lekin interval ID ka state se koi connection nahi.
- Cleanup: stop button ya component unmount pe `clearInterval(intervalRef.current)`

## Step 5 — TypeScript: `ReturnType<typeof setInterval>`

`ReturnType` TypeScript ka utility type hai jo function ke return type ko infer karta hai. Browser mein `setInterval` number return karta hai, lekin cross-platform compatibility ke liye `ReturnType` use karna safe hai.

```ts
const intervalRef = useRef<ReturnType<typeof setInterval> | null>(null);
```

- `typeof setInterval` → setInterval function ka type
- `ReturnType<ReturnType>` → woh function kya return karta hai (number in browser, Node.js mein object)
- Browser mein setInterval number return karta hai, lekin cross-platform compatibility ke liye `ReturnType` use karo

**Simple version (browser-specific):**
```ts
const intervalRef = useRef<number | null>(null);
```

## Step 6 — Bonus: Previous Value Pattern

Kabhi kabhi previous state value chahiye — jaise "count 3 se 4 hua" batana hai directly. `useState` se previous value directly nahi milti, lekin ref ka ek common pattern hai — previous value store karna.

Ref ka ek common pattern — previous value store karna:

```tsx
function CounterWithPrevious() {
  const [count, setCount] = useState(0);
  const prevCountRef = useRef(0);

  useEffect(() => {
    prevCountRef.current = count;
  }, [count]);

  const prevCount = prevCountRef.current;

  return (
    <div>
      <p>Abhi: {count}</p>
      <p>Pehle: {prevCount}</p>
      <button onClick={() => setCount(count + 1)}>+</button>
    </div>
  );
}
```

**Kaise kaam karta hai:**
1. Render ho raha hai — `prevCount` abhi bhi purani value dikha raha hai
2. useEffect render ke baad chalta hai — `prevCountRef.current = count` update ho raha hai
3. Next render — `prevCountRef.current` nayi value dikhayega

---

## Common Mistakes

1. **Ref ko render ke andar padhna/likhna** — `useRef` ki value render ke andar change karo toh React purity tod sakte ho. Sirf event handlers ya useEffect mein use karo.
2. **DOM ref ko initial value dena** — `useRef<HTMLInputElement>(null)` hi sahi hai. `useRef<HTMLInputElement>(document.createElement("input"))` mat karo.
3. **Ref aur state confuse karna** — Ref change → no re-render. State change → re-render. Agar UI ko value dikhani hai toh state chahiye, ref nahi.
4. **useRef vs createRef** — `useRef` hook hai (function component). `createRef` class component ke liye hai. Function component mein hamesha `useRef` use karo.

## Summary

| Concept | Samajh |
|---|---|
| `useRef(initialValue)` | `{ current: initialValue }` — mutable, persistent across renders |
| DOM ref | `useRef<HTMLInputElement>(null)` → `.current` = DOM node after mount |
| Mutable value | `useRef<number>(0)` → `.current` change karein, re-render nahi |
| `RefObject` vs `MutableRefObject` | null initial → readonly; anything else → mutable |
| Previous value pattern | Store value in ref inside useEffect, read before next render |
