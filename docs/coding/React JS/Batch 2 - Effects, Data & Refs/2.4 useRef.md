
## Abhi Tak Kya Hua

Ab tak 3 hooks seekhe — `useState` (client state), `useEffect` (side effects), `useQuery` (server state). Sab ka ek common pattern hai: **state change → re-render → UI update.** Lekin kuch values aisi hoti hain jo UI se related nahi — screen pe dikhni nahi chahiye, bas background mein "yaad" rehni chahiye. Iske liye kuch aur chahiye.

---

## Broader Goal

`useRef` hook — do kaam karta hai:

1. **Value store karna bina re-render trigger kiye** — timer ID, render count, previous value
2. **DOM element ko directly access karna** — input focus, video play, scroll position

Pehle samjhenge **kyun alag tool chahiye** (comparison demo), phir syntax, phir real use cases.

---

## Step 1 — useState vs useRef: Visual Comparison

**SOCH:** Jab hum `useState` use karte hain, React "subscribe" kar leta hai — "is state mein koi bhi change → component re-render karo, UI update karo." Lekin kabhi kabhi hum value sirf store karna chahte hain, UI update nahi karna. Ek real example: **previous value compare** — screen pe current count dikh raha hai (useState). Lekin "Previous: 5 → Current: 6" dikhane ke liye previous count bhi chahiye. Agar woh bhi `useState` mein ho, toh previous change hote hi re-render trigger karega — infinite loop ya unnecessary render.

Agar plain variable (`let prevCount = 0`) use karein, toh har render pe reset ho jayega. `useRef` dono problems solve karta hai — persist karega aur re-render trigger nahi karega.

**Pehle visual difference dekhte hain — do buttons, do counters:**

**Chal dekhte hain dono ke saath — ek hi component mein do buttons, do counters.**

```tsx
import { useState, useRef } from "react";

function CompareDemo() {
  const [stateCount, setStateCount] = useState(0);
  const refCount = useRef(0);

  const handleStateClick = () => {
    setStateCount(stateCount + 1);
    console.log("State count:", stateCount + 1);
  };

  const handleRefClick = () => {
    refCount.current = refCount.current + 1;
    console.log("Ref count:", refCount.current);
  };

  return (
    <div>
      <h2>useState vs useRef</h2>

      <button onClick={handleStateClick}>State Button</button>
      <p>State count: {stateCount}</p>

      <button onClick={handleRefClick}>Ref Button</button>
      <p>Ref count: (console dekho)</p>
    </div>
  );
}
```

⚠️ **React 19+ warning:** `refCount.current` ko JSX mein directly render nahi kar rahe (isliye `(console dekho)` likha hai). React 19 mein yeh warning aati hai — refs render ke andar access karne ke liye nahi hain. Kahani kahen? `ref.current` sirf event handlers, useEffect, callbacks ke andar use karo. JSX mein kabhi mat daalo — warning aayegi aur value stale ho sakti hai.

**TEST — do buttons hai, click karo aur dekho:**

| Click # | State Button → Console | State Button → UI | Ref Button → Console | Ref Button → UI |
|---|---|---|---|---|
| 1st click | `State count: 1` | Shows **1** | `Ref count: 1` | **(console dekho)** |
| 2nd click | `State count: 2` | Shows **2** | `Ref count: 2` | Still **(console)** |
| 3rd click | `State count: 3` | Shows **3** | `Ref count: 3` | Still **(console)** |
| 5 clicks | `State count: 5` | Shows **5** | `Ref count: 5` | Still **(console)** |

Kya dekh rahe ho?

- **State Button** dabao → `<p>State count: N</p>` **screen pe update hota hai** har click pe.
- **Ref Button** dabao → Console mein `1, 2, 3, 4, 5` print **ho raha hai** (matlab value andar se badal rahi hai), lekin screen pe kuch update nahi hota.** 

**Kyun?** `refCount.current = refCount.current + 1` se React ko koi signal nahi milta. React sirf `useState` ko "watch" karta hai. `useRef` ki value badal rahi hai, lekin React ko pata nahi chalta — isliye re-render nahi hota, screen update nahi hoti. Console seedha JS variable padh raha hai — isliye woh latest value dikhata hai.

> **Nutshell:** `useState` = React ko batata hai "kuch badla, re-render kar." `useRef` = silently store karta hai, React ko pata nahi chalta. Isliye `ref.current` ko JSX mein kabhi mat daalo — warning aayegi aur React guarantee nahi karta ki value update hogi.

## Step 2 — "Ref" Ka Sense Kya Hai?

**CONCEPT:** `useRef(0)` call karne par React ek object return karta hai — `{ current: 0 }`. Sirf ek plain JavaScript object jisme ek property hai `current`.

```ts
const refCount = useRef(0);
// refCount = { current: 0 }
```

Is object ki do khaas properties hain:

### 1. Persistence — Renders ke beech reset nahi hota

React component ek function hai jo har render pe dobara call hota hai. Agar tum component ke andar `let x = 0` likho, toh har render pe `x` phir se 0 ban jayega — kyunki function fresh run ho raha hai.

`useRef` se banaya object **reset nahi hota.** React use internally kahin store karke rakhta hai, aur agle render pe wahi same object wapas deta hai — same reference, same `current` value jo pichli baar chhodi thi.

```
Render 1: refCount = { current: 0 }
  → refCount.current = 5  (manually set)
Render 2: refCount = { current: 5 }  ← wahi object, value persist
  → refCount.current = 10
Render 3: refCount = { current: 10 }  ← still same object
```

### 2. No re-render trigger — React "subscribe" nahi karta

`setState(5)` call hota hai → React internal system ko signal jaata hai "kuch badla, re-render karo."

`refCount.current = 5` → yeh bas ek normal JavaScript object ki property change hai. Jaise `myObj.name = "Vin"`. React us object ko **watch nahi kar raha.** Isliye koi signal nahi jaata, koi re-render nahi hota.

**Socho aise:** React ka ek "watchlist" hai jahan saare `useState` variables registered hain. `useRef` us watchlist mein nahi hai. Ref underground mein hai — value change ho rahi hai, React ko pata nahi.

### "Ref" naam ka matlab

Ref = **Reference** (refer karna). Yeh khud value nahi hai — yeh ek "handle" hai jisse tum kisi cheez ko refer/access kar sakte ho. Jaise locker ki chaabi — chaabi khud locker nahi hai, wo sirf locker **ko point karti hai.** `useRef` bhi waisa hai — ek object jo kisi value ya DOM element **ko point karta hai** via `.current`.

> **Nutshell:** `useRef(initialValue)` ek `{ current: initialValue }` object return karta hai jo renders ke beech same reference rehta hai. `.current` change karne se re-render nahi hota — kyunki React useRef ko watch nahi karta. Isliye yeh un values ke liye hai jo UI se related nahi hain.

## Step 3 — TypeScript Typing: DOM Ref vs Mutable Ref

`useRef` ke saath TypeScript do alag types banata hai — yeh initial value pe decide hota hai.

### DOM Ref — `useRef<HTMLInputElement>(null)`

Jab initial value `null` hota hai, TypeScript samajhta hai "yeh DOM element ka reference hai":

```ts
const inputRef = useRef<HTMLInputElement>(null);
// typeof inputRef → RefObject<HTMLInputElement | null>
// .current → HTMLInputElement | null (READONLY)
```

Yahan `<HTMLInputElement>` **generic type** hai jo batata hai ki yeh ref kis type ke DOM element ko point karega — `<input>`, `<video>`, `<div>`, etc. React automatically `.current` ko actual DOM node se bhar deta hai — isliye `.current` **readonly** hai (tum khud assign nahi kar sakte, sirf React karega).

`null` initial value ka matlab: "abhi DOM element render nahi hua, isliye null hai. Render hone ke baad React khud ise DOM node se bhar dega."

### Mutable Ref — `useRef<number>(0)`

Jab initial value koi non-null value hota hai, TypeScript samajhta hai "yeh mutable value store kar raha hai":

```ts
const intervalRef = useRef<number | null>(null);
// typeof intervalRef → MutableRefObject<number | null>
// .current → number | null (WRITABLE — tum khud change kar sakte ho)

const renderCount = useRef(0);
// typeof renderCount → MutableRefObject<number>
```

Yahan type manually specify karte ho (`<number | null>`). `.current` **writable** hai — `intervalRef.current = 5` likh sakte ho kyunki React ise auto-assign nahi karta.

### Key Insight

| Initial value | Ref type | `.current` | Kaun assign karta hai |
|---|---|---|---|
| `null` | DOM ref (RefObject) | Readonly | React automatically (DOM node) |
| Anything non-null | Mutable ref (MutableRefObject) | Writable | Tum manually |

```ts
const domRef = useRef<HTMLInputElement>(null);   // DOM ref — readonly
const valRef = useRef(0);                         // mutable ref — writable
const valRef2 = useRef<string>("hello");          // mutable ref — writable
```

## Step 4 — First Use Case: DOM Access (Input Auto-Focus)

Ab jab `useRef` ka mechanism clear hai, dekhte hain kaise DOM element ko access karte hain.

**SOCH:** Page load pe ek input field pe automatically focus chahiye — cursor wahan blink kare. `useState` se possible hai lekin unnecessary re-render hota hai. `useRef` se karte hain.

**Phase 1 — Static UI:** Sirf input + button, koi ref nahi:

```tsx
function AutoFocusInput() {
  return (
    <div>
      <input type="text" placeholder="Auto-focused..." />
      <button>Focus</button>
    </div>
  );
}
```

**Phase 2 — useRef se ref object banao:** 

Pehle `useRef` ko import karo aur ek ref variable banayein. `useRef<HTMLInputElement>(null)` ka matlab: "ek box banao jisme `<input>` element ka reference aayega. Abhi kuch nahi hai, isliye `null` daal do."

`inputRef` ek object hai: `{ current: null }`. Sirf ek property `current` jisme abhi null hai. Baad mein React khud ise DOM element se bhar dega.

```tsx
import { useRef } from "react";

function AutoFocusInput() {
  const inputRef = useRef<HTMLInputElement>(null);
  console.log(inputRef); // { current: null } — abhi DOM bana nahi

  return (
    <div>
      <input type="text" placeholder="Auto-focused..." />
      <button>Focus</button>
    </div>
  );
}
```

`HTMLInputElement` generic type React ki built-in type hai jo HTML `<input>` element ko represent karti hai. Isliye TypeScript jaanta hai ki `.current` future mein `<input>` DOM node hoga ya `null`.

**Phase 3 — `ref={inputRef}` se connection banao:**

Ab baari hai React ko batane ki: "yeh jo `inputRef` object hai, isme `<input>` element ka reference daal do."

Iske liye `<input>` JSX mein `ref={inputRef}` attribute likhte ho. Yeh React ko batata hai:

> "Jab tu `<input>` element actual DOM mein create kare, toh uska reference `inputRef.current` mein assign kar de."

**React internally kya karta hai — simplified version:**

```
Tumhara JSX: <input ref={inputRef} />

React create karta hai:
  → const domElement = document.createElement('input')
  → inputRef.current = domElement   ← React khud kar deta hai
```

Bilkul — React khud `inputRef.current` ko actual DOM element se bhar deta hai. Tumhe kuch nahi karna.

```tsx
<input ref={inputRef} type="text" placeholder="Auto-focused..." />
```

Ab `inputRef.current` null nahi — actual `<input>` DOM node hoga (render ke baad).

> `ref` attribute sirf built-in HTML elements (`<input>`, `<div>`, `<video>`) pe kaam karta hai. Custom components pe nahi — unke liye `forwardRef` chahiye (baad mein).

**Phase 4 — console.log se verify karo ki ref kaam kar raha hai:**

Ab ek event handler add karte hain. Button click pe `inputRef.current` console mein print karenge — isse dekhenge ki kya sach mein `<input>` element ref mein store ho gaya hai.

Pehle handler function banate hain:

```tsx
const handleFocusClick = () => {
  console.log("Ref current value:", inputRef.current);
};
```

Phir button mein `onClick` lagate hain:

```tsx
return (
  <div>
    <input ref={inputRef} type="text" placeholder="Auto-focused..." />
    <button onClick={handleFocusClick}>Focus</button>
  </div>
);
```

Poore component ka code:

```tsx
function AutoFocusInput() {
  const inputRef = useRef<HTMLInputElement>(null);
  console.log("Before render:", inputRef.current); // null — DOM abhi bana nahi

  const handleFocusClick = () => {
    console.log("On click:", inputRef.current); // <input> element — DOM ready hai
  };

  return (
    <div>
      <input ref={inputRef} type="text" placeholder="Auto-focused..." />
      <button onClick={handleFocusClick}>Focus</button>
    </div>
  );
}
```

Notice kiya? Component ke top-level pe `inputRef.current` `null` hai kyunki DOM abhi create nahi hua. Lekin button click karne ke baad — jab DOM ready ho chuka hai — `inputRef.current` actual `<input>` DOM element dikhayega.

**TEST:** Button click karo → console mein `<input>` element print ho raha hai? ✅

**Phase 5 — Actual logic: `.focus()` call karo:**

**Phase 5 — Actual logic: `.focus()` call karo:**

Har DOM element ke paas built-in browser methods hote hain — `.focus()`, `.click()`, `.play()` (video). `.focus()` browser ka default method hai jo cursor ko input mein daal deta hai:

```tsx
const handleFocusClick = () => {
  inputRef.current?.focus();
};
```

`?.` (optional chaining) isliye — agar `inputRef.current` null ho (e.g., element unmount ho gaya), toh `.focus()` call nahi hoga, error nahi aayega.

**Final code:**

```tsx
import { useRef } from "react";

function AutoFocusInput() {
  const inputRef = useRef<HTMLInputElement>(null);

  const handleFocusClick = () => {
    inputRef.current?.focus();
  };

  return (
    <div>
      <input ref={inputRef} type="text" placeholder="Auto-focused..." />
      <button onClick={handleFocusClick}>Focus</button>
    </div>
  );
}
```

**TEST:** Button click karo → input pe cursor blink karne lagega? ✅

> **Nutshell:** DOM element access ke liye: (1) `const elRef = useRef<HTMLInputElement>(null)`, (2) `<input ref={elRef} />`, (3) `elRef.current?.focus()`. Ref ka `.current` render complete hone ke baad actual DOM node se bhar jaata hai.

## Step 5 — Second Use Case: Mutable Value (Stopwatch)

**SOCH:** Stopwatch — Start button dabao, `setInterval` har second seconds increment kare. Stop button dabao, interval band ho. Reset dabao, seconds zero.

Teen states chahiye: `seconds` (UI pe dikhega), `isRunning` (buttons enable/disable). Lekin **interval ID** — UI pe dikhni nahi chahiye, sirf `clearInterval` karne ke liye chahiye. Isliye state nahi, **ref** mein store karo.

**Phase 1 — Static UI:**

```tsx
function Stopwatch() {
  return (
    <div>
      <h1>⏱️ Stopwatch: 0s</h1>
      <button>Start</button>
      <button disabled>Stop</button>
      <button>Reset</button>
    </div>
  );
}
```

**Phase 2 — State add karo (seconds + isRunning):**

```tsx
const [seconds, setSeconds] = useState(0);
const [isRunning, setIsRunning] = useState(false);
```

Seconds UI pe dikhega — isliye state. IsRunning se buttons enable/disable honge — isliye state.

**Phase 3 — Ref for interval ID:**

```tsx
const intervalRef = useRef<ReturnType<typeof setInterval> | null>(null);
```

`ReturnType<typeof setInterval>` — TypeScript utility jo `setInterval` ke return type (number) ko nikaalta hai.

Interval ID sirf cleanup ke liye chahiye, display ke liye nahi. State mein rakhenge toh `setIntervalId(id)` → re-render trigger — unnecessary. Ref perfect hai.

**Phase 4 — Handlers:**

```tsx
const handleStart = () => {
  setIsRunning(true);
  intervalRef.current = setInterval(() => {
    setSeconds((prev) => prev + 1);
  }, 1000);
};

const handleStop = () => {
  setIsRunning(false);
  if (intervalRef.current) {
    clearInterval(intervalRef.current);
    intervalRef.current = null;
  }
};

const handleReset = () => {
  setSeconds(0);
  setIsRunning(false);
  if (intervalRef.current) {
    clearInterval(intervalRef.current);
    intervalRef.current = null;
  }
};
```

**Phase 5 — UI bind karo:**

```tsx
return (
  <div>
    <h1>⏱️ Stopwatch: {seconds}s</h1>
    <button onClick={handleStart} disabled={isRunning}>Start</button>
    <button onClick={handleStop} disabled={!isRunning}>Stop</button>
    <button onClick={handleReset}>Reset</button>
  </div>
);
```

**Full code:**

```tsx
import { useState, useRef } from "react";

function Stopwatch() {
  const [seconds, setSeconds] = useState(0);
  const [isRunning, setIsRunning] = useState(false);
  const intervalRef = useRef<ReturnType<typeof setInterval> | null>(null);

  const handleStart = () => {
    setIsRunning(true);
    intervalRef.current = setInterval(() => {
      setSeconds((prev) => prev + 1);
    }, 1000);
  };

  const handleStop = () => {
    setIsRunning(false);
    if (intervalRef.current) {
      clearInterval(intervalRef.current);
      intervalRef.current = null;
    }
  };

  const handleReset = () => {
    setSeconds(0);
    setIsRunning(false);
    if (intervalRef.current) {
      clearInterval(intervalRef.current);
      intervalRef.current = null;
    }
  };

  return (
    <div>
      <h1>⏱️ Stopwatch: {seconds}s</h1>
      <button onClick={handleStart} disabled={isRunning}>Start</button>
      <button onClick={handleStop} disabled={!isRunning}>Stop</button>
      <button onClick={handleReset}>Reset</button>
    </div>
  );
}
```

**TEST:** Start dabao → seconds badh rahe hain? Stop dabao → ruk gaya? Reset → 0? ✅

> **Nutshell:** `useRef` mutable value use karo jab value ko UI pe dikhana nahi hai, sirf "background bookkeeping" ke liye chahiye (timer ID, interval handle, previous value). State use karo jab value change pe UI update chahiye.

## Step 6 — Bonus: Previous Value Pattern

**SOCH:** Count screen pe dikh raha hai (`useState`). Ab "Previous: X → Current: Y" dikhana hai. Previous count bhi store karna hai — lekin woh `useState` mein rakhenge toh previous change hote hi re-render trigger hoga. Ref mein rakho — koi extra render nahi.

```tsx
import { useState, useRef } from "react";

function PrevValueDemo() {
  const [count, setCount] = useState(0);
  const prevCount = useRef(0);

  const handleClick = () => {
    prevCount.current = count;    // current value → previous ban gayi
    setCount(count + 1);          // naya count
  };

  return (
    <div>
      <p>Previous: {prevCount.current} → Current: {count}</p>
      <button onClick={handleClick}>Increment</button>
    </div>
  );
}
```

**TEST:** Button click karo. "Previous: 0 → Current: 1", fir "Previous: 1 → Current: 2"... ✅

**Yahan kya ho raha hai?**
- State change (`setCount`) → re-render
- Ref change (`prevCount.current = count`) → **koi re-render nahi**
- Previous value sirf "yaad" rakhni hai, UI usay tab dikhata hai jab state-triggered render ho

> **Nutshell:** Previous value pattern — current value ko ref mein daal do **phale** state update karne se. Ref persist karega, re-render trigger nahi karega. Screen pe tab dikhega jab state change se render ho. Yeh `useRef` ka real practical use case hai.

## What It Is NOT

- **useState ka replacement nahi hai** — UI-visible values ke liye `useState` chahiye. `useRef` se UI update nahi kar sakte kyunki re-render trigger nahi hota.
- **DOM manipulation tool nahi hai** — `useRef` sirf DOM element ka "reference" deta hai. Actual manipulation (focus, play, scroll) normal browser JS API hai.
- **Global variable nahi hai** — ref component instance-specific hai. Har component ka apna ref object hota hai, doosre component ka ref access nahi kar sakte bina prop drilling ya context ke.

---

## Common Mistakes

1. **`ref.current` ko render ke dauraan read karna** (JSX return se pehle top-level pe) — `null` milega kyunki DOM abhi bana nahi. Hamesha event handler ya `useEffect` ke andar read karo.

2. **UI update ke liye `useRef` use karna** — agar value screen pe dikhni chahiye, `useState` use karo. `useRef` se screen update nahi hogi.

3. **`inputRef.current?.focus()` bina optional chaining ke** — agar element conditionally render ho (e.g., `{show && <input ref={inputRef} />}`) aur `show` false ho, toh `inputRef.current` null hoga — `.focus()` call error dega. Hamesha `?.` use karo.

4. **useRef ka initial value `null` bhoolna** — `useRef<HTMLInputElement>()` (bina initial value) TypeScript error dega. Hamesha `useRef<Type>(null)` likho.

## Cheat Sheet (Quick Recall)

```ts
const inputRef = useRef<HTMLInputElement>(null);  // DOM ref — readonly .current
const intervalRef = useRef<number | null>(null);  // mutable value — writable .current

// DOM access
<input ref={inputRef} />
inputRef.current?.focus();

// Mutable store (bina re-render ke)
intervalRef.current = setInterval(() => {}, 1000);
clearInterval(intervalRef.current);

// Key difference:
// useState → change + RE-RENDER
// useRef → change + NO RE-RENDER
```

## Summary

| Concept | useRef | useState |
|---|---|---|
| Return type | `{ current: initialValue }` | `[value, setValue]` |
| Re-render on change | ❌ Nahi | ✅ Haan |
| Persists across renders | ✅ Haan | ✅ Haan |
| DOM access | ✅ `ref` attribute | ❌ Ref callback se possible but wasteful |
| Best for | Background values, DOM refs | UI-visible state |
