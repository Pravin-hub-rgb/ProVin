## Cheat Sheet (Quick Recall)

```ts
// Mount pe fetch: useEffect with []
useEffect(() => {
  async function fetchData() {
    const res = await fetch(url);
    const data = await res.json();
    setState(data);
  }
  fetchData();
}, []);

// Button click pe fetch: handleSearch mein seedha
async function handleSearch() {
  setIsLoading(true);
  const res = await fetch(url);
  const data = await res.json();
  setState(data);
  setIsLoading(false);
}
```

- **3 states**: `data`, `loading`, `error` — alag rakho
- **Loading** = fetch shuru pe `setIsLoading(true)`, khatam pe `false` (finally mein)
- **Error** = `try { fetch } catch { setError } finally { setIsLoading(false) }`
- **Empty state** = `recipes.length === 0 ? "No results" : recipes.map(...)`
- **Button disable** = `disabled={isLoading}` — user spam na kare
- **`??`** = `data.meals ?? []` — null aaya toh empty array

## Abhi Tak Kya Hua

2.1 mein `useEffect` seekha — side effect, dependency array, cleanup. Woh sab timer ke saath tha (`setInterval`). Ab wahi pattern **API Fetching** pe apply karenge. API se data lana React mein ek common kaam hai, aur iske saath kuch naye problems aati hain (race condition) jo timer mein nahi thi.

## Step 1 — Pehle Samjho: API Kya Hoti Hai?

React padhne se pehle, ek fundamental cheez samajh leni chahiye — **API**. Kyunki ab hum React ke andar se kisi external source se data lenge.

**API = Application Programming Interface.** Lamba naam hai, par kaam simple hai:

- React app ek URL ko request bhejti hai (`fetch`)
- Server us request ko process karta hai
- Server data (JSON format mein) response mein wapas bhejta hai
- React app us data ko UI mein dikhati hai

**URL kaise dikhta hai:**

```
https://www.themealdb.com/api/json/v1/1/search.php?s=chicken
```

Yeh URL ek **API endpoint** hai. Is URL ko browser mein kholo toh yeh JSON data return karta hai — recipe list. JSON ek format hai jisme data structured hota hai (jaise object/array). React mein API call ka matlab hai — kisi URL ko fetch karo, usse JSON data laao, aur UI mein dikhao.

Chal ab yeh app banana shuru karte hain.

## Step 5 — Fetch Function: Browser Se Data Maangna

Ab humare paas `query` hai. Jab user "chicken" search kare, toh hume API se data lena hai. Pehle manually test karte hain — browser mein URL khol ke dekhte hain ki response kaise dikhta hai.

**Try karo — browser mein yeh URL kholo:**

```
https://www.themealdb.com/api/json/v1/1/search.php?s=chicken
```

Kuch aisa response aayega:

```json
{
  "meals": [
    {
      "idMeal": "52795",
      "strMeal": "Chicken Handi",
      "strMealThumb": "https://www.themealdb.com/images/media/meals/wyxwsp1496972209.jpg",
      "strCategory": "Chicken",
      "strArea": "Indian"
    }
  ]
}
```

Dekha? Ek `meals` array hai, jisme har recipe ek object hai. Har object mein `idMeal`, `strMeal`, `strMealThumb` waghera hai.

Ab yehi kaam React mein karna hai — URL se data laao aur console mein dekho.

**Pehle teen naye concepts samajh lo:**

---

**1. `fetch` function — browser ka built-in API caller**

`fetch` ek JavaScript function hai jo browser built-in deta hai. Kaam: kisi URL ko call karo aur response laao. React ka feature nahi hai — seedha browser ka part hai.

```js
const response = fetch("https://api.example.com/data");
```

Lekin `fetch` ek **Promise** return karta hai.

**Promise kya hai?** Ek object jo future mein available value represent karta hai. Do states hain: `resolve` (success — value mil gayi) ya `reject` (failure — error aaya). Jab tak resolve/reject nahi hota, Promise "pending" state mein hota hai. `await` se uske resolve hone ka wait kiya ja sakta hai.

```
fetch(url) → ek Promise return karta hai
             |
             ├── resolve → response mil gaya ✅
             └── reject  → network error ❌
```

---

**2. `async` aur `await` — Promise ke saath wait kaise karein**

Jab tak Promise resolve nahi hota, hume wait karna padega. JavaScript mein wait karne ka tarika hai `await`:

```js
const response = await fetch("https://api.example.com/data");
// JavaScript yahan rukega — jab tak fetch complete na ho, aage nahi badhega
// Fetch complete hua → response variable mein actual value assign hogi
```

Lekin ek rule hai — **`await` sirf `async` function ke andar use kar sakte ho.** Isliye:

```js
async function getData() {
  const response = await fetch("https://api.example.com/data");
  // ✅ allowed — function async hai
}

function getData() {
  const response = await fetch("https://api.example.com/data");
  // ❌ error — function async nahi hai
}
```

`async` function ke aage lagao — matlab "yeh function time lene wala kaam karega, iske andar `await` use ho sakta hai."

---

**3. `res.json()` — response ko JavaScript object mein convert karo**

Network se jo data aata hai woh string format mein hota hai (JSON text). `res.json()` us string ko JavaScript object/array mein convert karta hai.

Aur guess karo — `res.json()` bhi ek **Promise return karta hai.** Kyun? Kyunki response body ko read karna bhi time le sakta hai (agar data bada ho). Toh iske aage bhi `await` lagega:

```js
const res = await fetch(url);       // 1. URL call karo, response aane do
const data = await res.json();      // 2. Response body ko parse karo, data aane do
console.log(data);                  // 3. Ab data use karo
```

**Teeno concepts ek saath — flow samjho:**

```
handleSearch click
  ↓
async → function time lega
  ↓
await fetch(url)  →  Promise → browser API call kar raha hai
  ↓                       ↓
  ruk                  response aaya
  ↓                       ↓
await res.json()  →  Promise → body parse ho rahi hai
  ↓                       ↓
  ruk                  data ready
  ↓
console.log(data)
```

## Step 6 — API Response Dekh Ke TypeScript Interface Banao

Console mein response dekha? Ab TypeScript ko batana hai ki response ka shape kya hai — taaki pura type safety mile.

**Pehle response ka structure dekho jo console mein aaya tha:**

```json
{
  "meals": [
    {
      "idMeal": "52795",
      "strMeal": "Chicken Handi",
      "strMealThumb": "https://...",
      "strCategory": "Chicken",
      "strArea": "Indian"
    }
  ]
}
```

Har recipe ke paas `idMeal`, `strMeal`, `strMealThumb`, `strCategory`, `strArea` hai. Poora response ek object hai jisme `meals` naam ka array hai.

**Ab interface define karo — ek recipe ka shape aur poore response ka shape:**

```ts
interface Recipe {
  idMeal: string;
  strMeal: string;
  strMealThumb: string;
  strCategory: string;
  strArea: string;
}

interface SearchResponse {
  meals: Recipe[] | null;
}
```

`meals: Recipe[] | null` — kyun `null`? Kyunki agar search ka koi result nahi milta (jaise `?s=xyzzzzz`), API `meals: null` return karti hai. TypeScript ko yeh batana zaroori hai.

**Ab `handleSearch` mein interface use karo — sirf type check ke liye, state nahi:**

```tsx
const handleSearch = async () => {
  if (!searchInput.trim()) return;

  const res = await fetch(
    "https://www.themealdb.com/api/json/v1/1/search.php?s=chicken"
  );
  const data: SearchResponse = await res.json();  // ← interface yahan use hua
  console.log("API Response:", data);
};
```

`const data: SearchResponse` — TypeScript ab jaanta hai ki `data.meals` ka type `Recipe[] | null` hai. Agar galat property access karo (jaise `data.recipes`), toh TypeScript error dega. Abhi state nahi daal rahe — sirf type safety check kar rahe hain ki interface sahi banaya hai. ✅

## Step 9 — Empty State: "Kuch Nahi Mila Toh?"

Dynamic search kaam kar raha hai. Lekin "xyzzzzz" search karke dekho — kuch nahi dikhta. Blank screen. API ne `meals: null` return kiya, `setRecipes([])` ne empty array set kiya, aur `recipes.map(...)` ne kuch render nahi kiya kyunki array empty hai.

Socho user ke perspective se — usne search kiya, button dabaaya, lekin screen pe kuch nahi aaya. Woh confuse ho jayega. Hume batana chahiye ki "kuch nahi mila, kuch aur try karo."

Yeh conditional rendering ka kaam hai — agar `recipes` empty hai toh ek message dikhao, nahi toh grid dikhao.

**Ternary operator se do states render karo:**

```tsx
{recipes.length === 0 ? (
  <p>No recipes found. Try a different search.</p>
) : (
  <div style={{ display: "grid", gridTemplateColumns: "1fr 1fr 1fr", gap: "16px" }}>
    {recipes.map((recipe) => (
      <div key={recipe.idMeal}>
        <img src={recipe.strMealThumb} alt={recipe.strMeal} style={{ width: "100%" }} />
        <h3>{recipe.strMeal}</h3>
        <p>{recipe.strCategory} — {recipe.strArea}</p>
      </div>
    ))}
  </div>
)}
```

**Nutshell:** Conditional rendering ka matlab hai — ek condition ke basis par decide karo ki kya render karna hai. Yahan condition hai `recipes.length === 0` — true hai toh "No recipes found" message, false hai toh recipe grid.

## Step 10 — Loading State: Button Disable + Spinner

Ab ek problem hai — search dabao, kuch hone mein 1-2 second lagte hain. Screen freeze si ho jaati hai. User nahi samajh paata ki app kaam kar rahi hai ya hang ho gayi.

Socho — button click ke turant baad, ek visual feedback chahiye ki "fetch chal raha hai, wait karo."

Iska solution hai ek **loading state** — `isLoading` naam ka boolean. Fetch shuru hone se pehle `true`, fetch complete hone ke baad `false`. Simple.

**Pehle state add karo:**

```tsx
const [isLoading, setIsLoading] = useState(false);
```

**Ab `handleSearch` mein loading on/off karo — fetch se pehle true, fetch ke baad false:**

```tsx
const handleSearch = async () => {
  if (!searchInput.trim()) return;

  setIsLoading(true);

  const res = await fetch(
    `https://www.themealdb.com/api/json/v1/1/search.php?s=${searchInput.trim()}`
  );
  const data: SearchResponse = await res.json();
  setRecipes(data.meals ?? []);

  setIsLoading(false);
};
```

**Nutshell:** Loading state ek boolean flag hai — `true` matlab fetch chal raha hai, `false` matlab fetch khatam ho gaya. Isse hum user ko feedback de sakte hain.

**Ab UI mein do kaam karo:**

1. **Button disable karo** — loading chal raha hai toh user dubara click na kar sake (spam prevent)
2. **Spinner dikhao** — "app kaam kar rahi hai" ka visual cue

```tsx
<button onClick={handleSearch} disabled={isLoading}>
  {isLoading ? "Searching..." : "Search"}
</button>

{isLoading && <p>⏳ Loading recipes...</p>}
```

`disabled={isLoading}` — jab `isLoading` true hai, button pe click nahi ho sakta. Text bhi badal gaya — "Search" se "Searching..." ho gaya taaki user ko feedback mile ki aakhri click register hua.

Aur empty state wala condition bhi update karo — loading ke dauran "No recipes found" nahi dikhna chahiye:

```tsx
{!isLoading && recipes.length === 0 ? (
  <p>No recipes found. Try a different search.</p>
) : (
  <div>...recipe grid...</div>
)}
```

Browser mein test karo — search dabao, button "Searching..." ho gaya + disabled, spinner dikh raha hai. Data aate hi sab normal. ✅

## Step 11 — Error State: Try/Catch

Loading handle kar liya. Lekin ek aur problem hai — network fail ho gaya toh? Server down hai toh? API rate limit hit hui toh?

Abhi agar network fail hua, fetch throw karega, aur code crash nahi karega lekin user ko kuch nahi dikhega — bas blank screen. Hume error handle karna chahiye.

**Pehle error state add karo — string store karega, null matlab koi error nahi:**

```tsx
const [error, setError] = useState<string | null>(null);
```

**Ab `handleSearch` ko `try/catch/finally` mein wrap karo:**

```tsx
const handleSearch = async () => {
  if (!searchInput.trim()) return;

  setIsLoading(true);
  setError(null);

  try {
    const res = await fetch(
      `https://www.themealdb.com/api/json/v1/1/search.php?s=${searchInput.trim()}`
    );
    const data: SearchResponse = await res.json();
    setRecipes(data.meals ?? []);
  } catch (err) {
    setError(err instanceof Error ? err.message : "Something went wrong");
    setRecipes([]);
  } finally {
    setIsLoading(false);
  }
};
```

Teen hisson mein samjho:

**`try` block mein woh code jo fail ho sakta hai** — `fetch` aur `res.json()`. Agar successful hai toh `setRecipes(data)` chalega.

**`catch` block tab chalega jab try ke andar koi error aaye** — network fail, server down, koi bhi unexpected cheez. Yahan do baatein samajhni hain:

**Pehla — `err` kya hai?** JavaScript mein kuch bhi "throw" kar sakte ho — ek Error object, ek string, ek number, kuch bhi. `fetch` fail hota hai toh wo ek `Error` object throw karta hai jisme `message` property hoti hai (jaise `"Failed to fetch"`). Lekin kabhi kabhi code mein koi aur kuch bhi throw kar sakta hai.

**Doosra — `instanceof` operator kya karta hai?** Yeh check karta hai ki koi value kisi specific class ka instance hai ya nahi. `err instanceof Error` ka matlab — "yeh `err` naam ki value `Error` class se bana hua object hai?"

```ts
// Example samajh lo:
const someError = new Error("Network fail");
console.log(someError instanceof Error); // true — kyunki Error class se bana hai

const someString = "kuch bhi error";
console.log(someString instanceof Error); // false — string hai, Error nahi
```

**Toh hum check kyun kar rahe hain?** Agar `err` sach mein `Error` ka instance hai, toh uske paas `.message` property hogi jo human-readable error text deti hai. Agar nahi hai (kisi aur ne string/number throw kiya), toh hum safe fallback message de dete hain: `"Something went wrong"`.

```
err instanceof Error ?
  → true:  err.message use karo  (jaise "Failed to fetch")
  → false: "Something went wrong" (fallback, kyunki pata nahi kya aaya)
```

**`finally` block har haal mein chalega** — chahe try success ho ya catch trigger ho. Isliye `setIsLoading(false)` yahan daalna safe hai — loading hamesha band hoga chahe kuch bhi ho jaye.

**UI mein error dikhana:**

```tsx
{error && <p style={{ color: "red" }}>❌ {error}</p>}
```

**Poora flow ab:**

```
Button click
  ↓
setIsLoading(true), setError(null)
  ↓
fetch url
  │
  ├── Success → setRecipes(data)
  │
  └── Error → setError(message), setRecipes([])
  │
  ↓
setIsLoading(false)  ← finally, har haal mein
```

Browser mein test karo — DevTools mein Network tab kholo, "Offline" toggle karo, search karo. ❌ error message dikh raha hai? Offline hatake wapas search karo — normal kaam kar raha hai? ✅

## Step 12 — useEffect Ki Asli Zaroorat: Mount Pe Pehla Data Dikhao

Step 11 tak sab theek hai — dynamic search, loading, error, sab handle ho gaya. Lekin ek cheez hai jo personally irritate karti hai...

App kholo, toh "No recipes found. Try a different search." dikhta hai. Obviously — kyunki `recipes` empty array hai, ternary ne condition match kar li. User ne abhi kuch kiya bhi nahi aur hum bol rahe hain "kuch nahi mila." Thoda rude lagta hai, na?

Aisa karein — **jaise hi app kholo, turant kuch interesting recipes dikh jaayein.** Chicken recipes, default. Phir user apne hisaab se search kare.

Lekin yahan problem hai — `handleSearch` to button click pe call hota hai. App mount hote waqt kaise fetch karein?

Yahan aata hai asli `useEffect` ka kaam.

### Soch: useEffect kya hai?

2.1 mein humne seekha tha — `useEffect` React ko batata hai ki "render ke baad yeh kaam karna." Timer ke saath dekha tha. Ab API fetch ke saath dekhte hain.

`useEffect` ka fundamental use-case yeh hai — **jab component mount ho (ya koi dependency change ho), toh koi side effect chalao.** Side effect matlab kuch bhi jo render cycle ke bahar ho — API call, timer, localStorage, etc.

### Pehle useEffect import karo

Ab tak useEffect import nahi kiya tha kyunki zaroorat nahi thi. Ab karte hain:

```tsx
import { useState, useEffect } from "react";
```

### Empty dependency array — sirf mount pe chalega

```tsx
useEffect(() => {
  // Yeh sirf tab chalega jab component mount ho
}, []);
```

`[]` ka matlab — "yeh effect kisi bhi cheez pe depend nahi karta." React ka rule hai: dependency array mein jo bhi hai, agar woh change ho toh effect dubara chalo. `[]` mein kuch nahi hai, toh koi change nahi hoga — isliye effect sirf **ek baar** chalega, component mount hone ke baad.

### Ab effect ke andar fetch karo — same pattern jo handleSearch mein use karte the

```tsx
useEffect(() => {
  const fetchDefault = async () => {
    const res = await fetch(
      "https://www.themealdb.com/api/json/v1/1/search.php?s=chicken"
    );
    const data: SearchResponse = await res.json();
    setRecipes(data.meals ?? []);
  };

  fetchDefault();
}, []);
```

Notice kiya? Yahan `fetchDefault` naam ka async function banaya aur turant call kiya. Seedha `useEffect(async () => ...)` nahi likha — kyun? Kyunki `useEffect` ka callback Promise return nahi karna chahiye, woh cleanup function (ya kuch nahi) return karta hai. Async function hamesha Promise return karta hai — isliye andar define karo aur call karo. Yeh wahi pattern hai jo official docs suggest karti hai.

**Nutshell:** `useEffect(() => { ... }, [])` ka matlab — "React bhai, yeh kaam sirf pehli baar karna, jab component UI pe aaye." Iske baad kabhi nahi chalega (jab tak component destroy aur mount na ho).

  const [recipes, setRecipes] = useState<Recipe[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);

  // Mount pe default chicken recipes fetch karo
  useEffect(() => {
    const fetchDefault = async () => {
      setIsLoading(true);
      const response = await fetch(
        "https://www.themealdb.com/api/json/v1/1/search.php?s=chicken"

      setIsLoading(false);
    };
    fetchDefault();

    setError(null);

      const response = await fetch(
        `https://www.themealdb.com/api/json/v1/1/search.php?s=${searchInput.trim()}`
      );
      const data: SearchResponse = await response.json();
      setRecipes(data.meals ?? []);
    } catch (err) {
      setError(err instanceof Error ? err.message : "Something went wrong");
      setRecipes([]);
    } finally {
      setIsLoading(false);
    }
  };

  return (
    <div style={{ padding: "20px", maxWidth: "800px", margin: "0 auto" }}>
      <h1>🍳 Recipe Finder</h1>

      <input
        type="text"
        value={searchInput}
        onChange={(e) => setSearchInput(e.target.value)}

        style={{ padding: "8px", width: "300px" }}
      />
      <button
        onClick={handleSearch}
        disabled={isLoading}
        style={{ padding: "8px 16px", marginLeft: "8px" }}
      >
        {isLoading ? "Searching..." : "Search"}
      </button>

      {isLoading && <p>⏳ Loading recipes...</p>}
      {error && <p style={{ color: "red" }}>❌ {error}</p>}

      {!isLoading && recipes.length === 0 ? (

              <p>{recipe.strCategory} — {recipe.strArea}</p>
            </div>
          ))}
        </div>
      )}
    </div>
  );
}

export default RecipeFinder;

## Khud Try Karo

1. Bina scroll kiye batao — `handleSearch` ko `async` kyun banana padta hai?

   <details>
   <summary>Sample Answer</summary>
   Kyunki `fetch` ek Promise return karta hai. Promise ke saath kaam karne ke liye `await` chahiye. Aur `await` sirf `async` function ke andar use ho sakta hai.
   </details>

2. Code likho — ek function jo `https://api.example.com/users` se data fetch kare, loading state handle kare, error handle kare, aur button disable kare.

   <details>
   <summary>Sample Answer</summary>

   ```tsx
   const [users, setUsers] = useState<User[]>([]);
   const [isLoading, setIsLoading] = useState(false);
   const [error, setError] = useState<string | null>(null);

   const fetchUsers = async () => {
     setIsLoading(true);
     setError(null);
     try {
       const res = await fetch("https://api.example.com/users");
       const data = await res.json();
       setUsers(data);
     } catch (err) {
       setError(err instanceof Error ? err.message : "Failed to fetch");
     } finally {
       setIsLoading(false);
     }
   };
   ```
   </details>

3. Predict karo — agar `setIsLoading(false)` finally nahi likha, sirf try ke end mein likha, toh kya hoga agar fetch fail ho?

   <details>
   <summary>Sample Answer</summary>
   Error catch block mein jayega, lekin `setIsLoading(false)` kabhi call nahi hoga. Spinner hamesha dikhta rahega — user atak jayega. Isliye `finally` mein loading off karna zaroori hai.
   </details>

## Summary

| Concept | Samajh |
|---|---|
| API | Interface jo React app ko server se data retrieve karne deta hai — request bhejo, response lao |
| fetch + async/await | `const res = await fetch(url)` → `const data = await res.json()` |
| useEffect with `[]` | Mount pe ek baar chalega — initial data load ke liye |
| Loading State | `isLoading` → fetch shuru pe `true`, khatam pe `false` (finally mein) |
| Error State | `error` → catch block mein set, fetch shuru pe `null` |
| Button Disable | `disabled={isLoading}` — loading ke dauran user spam na kare |
| Empty State | `recipes.length === 0` → "No results found" message |
| ?? (Nullish Coalescing) | `data.meals ?? []` — null aaya toh empty array, 0 ya "" ko affect nahi karta |
