# 2.2 — API Fetching with useEffect

## Cheat Sheet (Quick Recall)

```ts
useEffect(() => {
  let ignore = false;                       // race condition guard
  async function fetchData() {
    const res = await fetch(url);
    const data = await res.json();
    if (!ignore) setState(data);            // stale response ignore
  }
  fetchData();
  return () => { ignore = true; };
}, [query]);                                // query change = re-fetch
```

- **4 states**: data, loading, error, query — alag rakho
- **Race condition** = fast input changes pe multiple fetches — order unpredictable
- **Ignore pattern** = `let ignore = false`; cleanup mein `true`; async ke baad `if (!ignore)` check

## Abhi Tak Kya Hua

2.1 mein useEffect seekha — side effect kya hota hai, dependency array, cleanup function, aur timer mini-project banaya. Ab useEffect ke **real-world use case** — API Fetching — pe apply karenge. Lekin pehle manually karenge (taaki problem feel ho), phir agle doc mein better approach seekhenge.

Is doc mein ek **Recipe Finder** app banayenge jo:

## Step 2 — State Setup: Data, Loading, Error

API call karni hai — teen cheezein track karni hain: data aaya ki nahi, load ho raha hai ki nahi, error aaya ya nahi. Ek hi state mein sab rakhoge toh complex ho jayega. Alag-alag useState rakho — har state ka ek kaam.

```tsx
const [recipes, setRecipes] = useState<Recipe[]>([]);
const [isLoading, setIsLoading] = useState(false);
const [error, setError] = useState<string | null>(null);
const [query, setQuery] = useState("chicken");
```

| State | Type | Kaam |
|---|---|---|
| `recipes` | `Recipe[]` | Fetched recipes store karega |
| `isLoading` | `boolean` | Loading spinner dikhana/chhupana |
| `error` | `string \| null` | Error message (null = no error) |
| `query` | `string` | Search query — change hone pe re-fetch |

## Step 3 — useEffect Setup: Data Fetching

Jab query change ho tab API call karna hai. useEffect iske liye perfect hai.

```tsx
useEffect(() => {
  const fetchRecipes = async () => {
    setIsLoading(true);
    setError(null);

    try {
      const response = await fetch(
        `https://www.themealdb.com/api/json/v1/1/search.php?s=${query}`
      );
      const data: SearchResponse = await response.json();
      setRecipes(data.meals ?? []);
    } catch (err) {
      setError(err instanceof Error ? err.message : "Something went wrong");
      setRecipes([]);
    } finally {
      setIsLoading(false);
    }
  };

  fetchRecipes();
}, [query]);
```

**Har line decode karte hain:**

- `async function fetchRecipes()` — async function useEffect ke **andar** define kiya (seedha useEffect ko async nahi bana sakte — woh cleanup function expect karta hai, Promise nahi)
- `setIsLoading(true)` — fetch shuru, loading state on
- `setError(null)` — purana error clear
- `await fetch(...)` — API call
- `const data: SearchResponse = await response.json()` — response parse
- `setRecipes(data.meals ?? [])` — data set karo (nullish coalescing — agar `null` aaya toh empty array)
- `catch` block — network error handle
- `finally` — loading off

**Dependency `[query]`:** Query change hogi, effect re-run hoga, naya data fetch hoga.

**Nutshell:** `useEffect` ke andar `async` function alag se define karo (seedha useEffect ko async mat banao) — loading, error, aur data states ko manually set karo. Dependency array mein woh variable do jiske change pe re-fetch chahiye.

## Step 4 — Problem: Race Condition

User fast search kar raha hai — "c", "ch", "chi", "chic" — har character pe naya fetch. Slow network pe pehla fetch ka response baad mein aa sakta hai, baad wale ka pehle aa sakta hai. Effect re-run hota hai har query change pe lekin purana request cancel nahi hota. UI galat data dikha sakta hai. Is problem ko **race condition** kehte hain.

Socho **do runner ek race mein** — ek pehle start hua lekin baad mein finish hua, doosra baad mein start hua lekin pehle finish hua. UI ko pata nahi kaunsa 'winner' hai.

**Demo the problem:**

```tsx
useEffect(() => {
  const fetchRecipes = async () => {
    const response = await fetch(`...?s=${query}`);
    const data = await response.json();
    setRecipes(data.meals ?? []);
  };
  fetchRecipes();
}, [query]);
```

1. User types "c" → fetch starts (slow)
2. User types "ch" → fetch starts (fast)
3. "ch" ka response pehle aata hai → `setRecipes` → UI shows "ch" results ✅
4. "c" ka response baad mein aata hai → `setRecipes` → UI shows "c" results ❌ (galat!)

Yeh **race condition** hai — do requests race kar rahe hain, aur jo pehle start hua woh baad mein finish ho sakta hai.

## Step 5 — Solution: Ignore Pattern

Pehle wala response irrelevant ho gaya kyunki naya query hai. Kaise check karein ki yeh response abhi bhi relevant hai? **Ignore pattern** — ek boolean flag jo track karta hai ki component abhi bhi mounted hai ya effect re-run ho chuka hai:**

```tsx
useEffect(() => {
  let ignore = false;  // ← flag
  const fetchRecipes = async () => {
    setIsLoading(true);
    setError(null);

    try {
      const response = await fetch(
        `https://www.themealdb.com/api/json/v1/1/search.php?s=${query}`
      );
      const data: SearchResponse = await response.json();

      if (!ignore) {           // ← check
        setRecipes(data.meals ?? []);
      }
    } catch (err) {
      if (!ignore) {           // ← check
        setError(err instanceof Error ? err.message : "Something went wrong");
        setRecipes([]);
      }
    } finally {
      if (!ignore) {           // ← check
        setIsLoading(false);
      }
    }
  };

  fetchRecipes();

  return () => {
    ignore = true;             // ← cleanup: effect re-run/unmount pe flag true
  };
}, [query]);
```

**Kaise kaam karta hai:**

1. Effect setup chalata hai → `ignore = false`
2. Effect cleanup chalta hai (effect re-run se pehle) → `ignore = true`
3. Jab async operation complete ho, `if (!ignore)` check karta hai
4. Agar `true` hai (effect replace ho chuka hai), toh state update skip

**TypeScript note:** `let ignore = false` — closure variable. Cleanup function ise `true` set karta hai. Async function ka closure is variable ko check karta hai.

**Nutshell:** Ignore pattern ek closure-based technique hai — ek boolean flag effect setup mein `false` set hota hai, cleanup mein `true`. Async operation complete hone par flag check hota hai: agar `true` hai (effect re-run ho chuka hai), toh state update skip ho jaati hai.

## Step 6 — Complete Recipe Finder UI

Ab saara logic ready hai — loading, error, data, race condition handling. UI banate hain.

```tsx
import { useState, useEffect } from "react";

interface Recipe {
  idMeal: string;
  strMeal: string;
  strMealThumb: string;
  strCategory: string;
  strArea: string;
}

interface SearchResponse {
  meals: Recipe[] | null;
}

function RecipeFinder() {
  const [query, setQuery] = useState("chicken");
  const [searchInput, setSearchInput] = useState("chicken");
  const [recipes, setRecipes] = useState<Recipe[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    let ignore = false;
    const fetchRecipes = async () => {
      setIsLoading(true);
      setError(null);

      try {
        const response = await fetch(
          `https://www.themealdb.com/api/json/v1/1/search.php?s=${query}`
        );
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        
        const data: SearchResponse = await response.json();
        if (!ignore) {
          setRecipes(data.meals ?? []);
        }
      } catch (err) {
        if (!ignore) {
          setError(err instanceof Error ? err.message : "Failed to fetch");
          setRecipes([]);
        }
      } finally {
        if (!ignore) {
          setIsLoading(false);
        }
      }
    };

    if (query.trim()) {
      fetchRecipes();
    }
  }, [query]);

  const handleSearch = (e: React.FormEvent) => {
    e.preventDefault();
    setQuery(searchInput.trim());
  };

  return (
    <div style={{ padding: "20px", maxWidth: "800px", margin: "0 auto" }}>
      <h1>🍳 Recipe Finder</h1>
      
      <form onSubmit={handleSearch}>
        <input
          type="text"
          value={searchInput}
          onChange={(e) => setSearchInput(e.target.value)}
          placeholder="Search recipes..."
          style={{ padding: "8px", width: "300px" }}
        />
        <button type="submit" style={{ padding: "8px 16px", marginLeft: "8px" }}>
          Search
        </button>
      </form>

      {isLoading && <p>⏳ Loading...</p>}
      {error && <p style={{ color: "red" }}>❌ {error}</p>}
      {!isLoading && !error && recipes.length === 0 && (
        <p>No recipes found. Try a different search.</p>
      )}

      <div style={{ display: "grid", gridTemplateColumns: "1fr 1fr 1fr", gap: "16px", marginTop: "20px" }}>
        {recipes.map((recipe) => (
          <div key={recipe.idMeal} style={{ border: "1px solid #ddd", borderRadius: "8px", padding: "12px" }}>
            <img
              src={recipe.strMealThumb}
              alt={recipe.strMeal}
              style={{ width: "100%", borderRadius: "4px" }}
            />
            <h3>{recipe.strMeal}</h3>
            <p>{recipe.strCategory} — {recipe.strArea}</p>
          </div>
        ))}
      </div>
    </div>
  );
}

export default RecipeFinder;
```

## Step 7 — Abhi Ki State Management: Manual vs Automatic

Abhi humare paas **4 states** hain manually managed:

| State | Purpose | Set Kab Hota Hai |
|---|---|---|
| `recipes` | API data | Fetch success pe |
| `isLoading` | Loading indicator | Fetch start/end pe |
| `error` | Error message | Catch block mein |
| `query` | Trigger re-fetch | Form submit pe |

Har ek state ko manual set karna pad raha hai — loading on, loading off, error set, data set. Aur race condition bhi manually fix karni padi (ignore pattern).

**Yeh approach kaam karta hai, lekin:**
- Boilerplate zyada hai
- Race condition manually fix karni padti hai
- Caching nahi hai — har query change pe naya fetch (even if same query)
- Loading/error state galat ho sakti hai agar proper cleanup na ho

Agle doc mein **TanStack Query** dekhenge jo yeh sab automatically handle karta hai.

## Trade-off: Manual vs Library

Is doc mein humne manually useEffect + fetch + useStates se API calling ki. Yeh approach kaam karta hai, lekin trade-offs hain:
- **Alternatives:** TanStack Query, SWR, RTK Query — yeh libraries loading/error/caching automatically handle karte hain
- **Kyun manual seekha?** Taaki problem feel ho — libraries ka "pain point" clear ho. Agle doc mein TanStack Query seekhenge wahi benefits dikhenge
- **Kab manual appropriate hai?** Sirf 1-2 simple API calls, no caching needed, small project

---

## Common Mistakes

1. **useEffect ko seedha async banana** — `useEffect(async () => {}, [])` galat hai. Async function andar define karo aur call karo.
2. **Ignore pattern bhoolna** — Fast input changes pe race condition aayegi. `let ignore + if (!ignore)` pattern hamesha lagao.
3. **Loading/error states ko ek state mein rakhna** — Alag-alag useState rakho: `data`, `isLoading`, `error`. Ek state mein sab rakhoge toh type complex aur update logic messy ho jayega.
4. **finally block mein setIsLoading(false) bhoolna** — Agar try/catch dono mein alag kiya toh code duplicate. Finally mein ek baar karo.

## Summary

| Concept | Samajh |
|---|---|
| API Fetching in useEffect | async function andar define karo, useEffect ko async mat banao |
| Loading State | `useState(false)` — fetch shuru pe `true`, khatam pe `false` |
| Error State | `useState(null)` — catch block mein set, fetch shuru pe clear |
| Race Condition | Fast input changes pe multiple fetch — response order unpredictable |
| Ignore Pattern | `let ignore = false` → cleanup mein `true` → async check `if (!ignore)` |
| `??` (nullish coalescing) | `null` ya `undefined` ho toh default value do — `data.meals ?? []` |
