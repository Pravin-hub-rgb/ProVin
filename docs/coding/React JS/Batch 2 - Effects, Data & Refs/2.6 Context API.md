# 2.6 — Context API

## Cheat Sheet (Quick Recall)

```ts
// 1. Create
const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);
// 2. Provide
<ThemeContext value={{ theme, toggleTheme }}>{children}</ThemeContext>
// 3. Consume
const ctx = useContext(ThemeContext);
if (!ctx) throw new Error("Must be inside Provider");
```

- **createContext**: Context object banata hai with type + default value
- **Provider**: Value provide karta hai component tree ke andar
- **useContext(guard)**: Value consume karta hai + error agar Provider ke bahar use ho
- **Custom hook**: `useTheme()` — guard ke saath, reusable

## Abhi Tak Kya Hua

Yaar 2.5.0 mein Lifting State Up seekha — siblings share state through parent. Lekin jab component tree deep ho aur har level ko data chahiye (jaise theme, auth user), toh lifting se prop drilling hoti hai. Composition help karta hai, lekin kabhi kabhi data ko **kahi bhi** accessible hona chahiye bina props ke.

## Broader Goal

Is doc mein **Context API** seekhenge — React ka built-in mechanism for global data. Ek **Theme Switcher** app banayenge:
- Dark/light mode toggle
- Context se theme har component ko milega bina props ke
- Custom hook `useTheme()` banayenge (safe pattern)
- TypeScript typing with context

## Step 1 — Problem Feel Karo: Prop Drilling Without Escape

Dark/light mode toggle chahiye. Har component ko current theme pata hona chahiye — background color, text color sab change hoga. Lifting state up se karein toh kya hoga?

Maine bhi pehle prop drilling ko ignore karta tha — "2-3 level toh chalta hai." Lekin jab ek project mein 8 level deep props pass karni padi, tab realize hua ki kuch aur chahiye. Context API allow karta hai ki value ek jagah provide karo aur kisi bhi nested component mein bina props ke access karo.

```
App (theme state yahan)
  ├── Navbar
  │   ├── Logo (needs theme)
  │   └── ThemeToggle (needs theme + setter)
  ├── MainContent
  │   ├── Sidebar
  │   │   └── MenuItem[] (needs theme)
  │   └── Article (needs theme)
  └── Footer (needs theme)
```

Har component ko `theme` prop dena padega — 10+ components, including middle components jo sirf prop pass kar rahe hain. Prop drilling extreme ho gayi.

**Context API iska solution hai** — data directly component ko milta hai bina middle components ke through prop pass kiye.

## Step 2 — Context API: Teen Steps

Yaar Context ke liye teen cheezein chahihte hain — createContext, Provider, useContext. Teen steps mein poora kaam ho jata hai.

### Step 1: Create Context

Pehla kaam hai context object banana — `createContext` ek container banata hai jisme value store hogi. Type `ThemeContextValue` define karta hai ki container mein kya hoga (theme + toggleTheme), aur `undefined` default value hai taaki hum error throw kar sakein agar koi Provider ke bahar use kare.

```ts
import { createContext } from "react";

type Theme = "light" | "dark";

interface ThemeContextValue {
  theme: Theme;
  toggleTheme: () => void;
}

const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);
```

- `createContext<T>(defaultValue)` — ek context object banata hai
- Generic type `ThemeContextValue` — context ka shape define karta hai
- `undefined` as default — taaki hum check kar sakein ki Provider ke bahar use ho raha hai

### Step 2: Provide Value

Context container toh ban gaya, ab isme value dalni hai. `ThemeContext` component ke andar `<ThemeContext>` wrap karke `value` prop pass karo. Jo bhi component iske andar hoga, use yahan se theme aur toggleTheme milega bina props ke.

```tsx
function App() {
  const [theme, setTheme] = useState<Theme>("light");

  const toggleTheme = () => {
    setTheme((prev) => (prev === "light" ? "dark" : "light"));
  };

  return (
    <ThemeContext value={{ theme, toggleTheme }}>
      <Navbar />
      <MainContent />
      <Footer />
    </ThemeContext>
  );
}
```

**React 19:** Provider directly context component se render hota hai — `.Provider` ki zaroorat nahi.

### Step 3: Consume Value

Ab jo components Provider ke andar hain, unhe value chahiye. `useContext(ThemeContext)` container se value nikaalta hai. Guard `if (!ctx)` ensure karta hai ki yeh component Provider ke andar hi use ho raha hai — Provider ke bahar `undefined` milega, toh error throw karo.

```tsx
import { useContext } from "react";

function Navbar() {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error("useContext must be inside Provider");

  return (
    <nav style={{ background: ctx.theme === "dark" ? "#333" : "#eee" }}>
      <ThemeToggle />
    </nav>
  );
}
```

> **What It Is NOT:** Context API **global state management nahi hai** — yeh ek dependency injection mechanism hai. Redux/Zustand ki tarah iska apna koi store/cache nahi hai. Sirf React component tree ke andar value pass karta hai bina props ke. Agar complex state management chahiye, Context + useReducer ya Zustand use karo.

## Step 3 — Custom Hook: `useTheme()` (Safe Pattern)

Har component mein `useContext(ThemeContext)` + `if (!ctx) throw` likhna repetitive hai. Mujhe bhi repetitive lagta tha — ek jagah guard likho aur hamesha wahi use karo. Toh ek custom hook banao:

```ts
import { createContext, useContext } from "react";

type Theme = "light" | "dark";

interface ThemeContextValue {
  theme: Theme;
  toggleTheme: () => void;
}

const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);

export function useTheme(): ThemeContextValue {
  const ctx = useContext(ThemeContext);
  if (!ctx) {
    throw new Error("useTheme must be used within a ThemeProvider");
  }
  return ctx;
}
```

Notice kiya? `if (!ctx) throw` — yeh guard hai. Agar koi component `ThemeProvider` ke bahar `useTheme()` call karega, toh `undefined` milega (default value). Guard ensures clear error message instead of cryptic "cannot read properties of undefined" error. Debugging bohot easy ho jati hai isse.

**Nutshell:** Context API teen steps mein kaam karta hai — `createContext` se context object banao, `<Context value={...}>` se value provide karo, `useContext` se value consume karo. Custom hook guard pattern ensures Provider ke bahar use ho toh clear error mile.

## Step 4 — ThemeProvider Component

Yaar Step 3 mein custom hook `useTheme()` banaya. Lekin provider logic bhi alag component mein extract kar sakte hain. Socho — `App` component mein saara provider logic rakhne se woh bada ho jayega. Better hai ek `ThemeProvider` component banao jo sirf state + context provide kare. Isse `App` clean rahega:

```tsx
import { useState, type ReactNode } from "react";

interface ThemeProviderProps {
  children: ReactNode;
}

export function ThemeProvider({ children }: ThemeProviderProps) {
  const [theme, setTheme] = useState<Theme>("light");

  const toggleTheme = () => {
    setTheme((prev) => (prev === "light" ? "dark" : "light"));
  };

  return (
    <ThemeContext value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext>
  );
}
```

Notice kiya? `ThemeProvider` ka kaam sirf ek hai — state rakhna aur context provide karna. `App` mein ab sirf `<ThemeProvider> <App /> </ThemeProvider>` karna hai. Clean separation of concerns.

  const styles: Record<string, React.CSSProperties> = {

## Step 6 — Context API: Kab Use Karein, Kab Avoid Karein

Dekho, Context API powerful hai but har cheez isme daalna emotional decision hai — maine bhi yeh galti ki hai. Yeh rule follow karo:

### Use Context For:
- Theme (dark/light)
- Auth user
- Locale/language
- Any data almost har component ko chahiye

### Avoid Context For:
- High-frequency updates (animations, real-time data) — poora subtree re-render hota hai
- Data sirf 2-3 components ko chahiye — lifting state up kaafi hai
- Complex state logic — Context + useReducer milega, lekin Zustand better hai (Batch 6)

---

## Step 7 — Performance Note: useMemo se Context Value Stable Rakho

Yaar yeh woh cheez hai jo maine bahut baar bhooli hai — Context value change → saare consuming components re-render. Socho: ThemeProvider render hua → naya `{ theme, toggleTheme }` object bana (naya reference) → saare children re-render ho gaye, chahe theme change na hui ho. Yeh unnecessary hai.

**Fix:** `useMemo` se value memoize karo. Matlab — jab tak theme change na ho, wahi object reference do, naya mat banao:

```tsx
import { useMemo, useCallback } from "react";

function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<Theme>("light");
  const toggleTheme = useCallback(() => {
    setTheme((prev) => (prev === "light" ? "dark" : "light"));
  }, []);

  const value = useMemo(() => ({ theme, toggleTheme }), [theme]);

  return (
    <ThemeContext value={value}>{children}</ThemeContext>
  );
}
```

Ab `value` ka reference tabhi change hoga jab `theme` actual mein change hogi. Unnecessary re-renders se bach gaye.

## Trade-off: Context vs Alternatives

| Pattern | Use Case | Problem |
|---|---|---|
| **Lifting State Up** | 2-3 siblings share state | Prop drilling in deep trees |
| **Composition** | Deep tree, middle components don't need data | Can't solve every case |
| **Context API** | Global data (theme, auth, locale) | High-frequency updates → full subtree re-render |
| **Zustand/Redux** (Batch 6) | Complex state, high performance | Extra boilerplate, learning curve |

**Rule of thumb:** Lift first. Compose second. Context third. Zustand when Context's re-render becomes a problem.

---

## Common Mistakes

1. **Provider bhoolna** — Context value `undefined` rahega. Custom hook guard se clear error milega.
2. **Har cheez Context mein daalna** — Sirf woh data jo almost har component ko chahiye (theme, auth). 2-3 components ke liye lifting up kaafi hai.
3. **High-frequency updates Context mein** — Har update pe poora subtree re-render. Jaise real-time stock price — Context mat use karo, Zustand ya external store lo.
4. **useMemo bhoolna** — Context value object/function hai toh har render pe naya reference. `useMemo` se wrap karo taaki unnecessary re-renders na ho.

## Summary

| Concept | Samajh |
|---|---|
| `createContext<T>(default)` | Context object banata hai |
| `<Context value={val}>` | Provider — value provide karta hai (React 19 syntax) |
| `useContext(Context)` | Consumer — value consume karta hai |
| Custom hook guard | `if (!ctx) throw` — safe access |
| Prop drilling solution | Context bypasses middle components |
