# 2.6 — Context API

## Cheat Sheet (Quick Recall)

```ts
// 1. Create
const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);
// 2. Provide
<ThemeContext value={{ theme, toggleTheme }}>{children}</ThemeContext>
// 3. Consume
const ctx = useContext(ThemeContext);
if (!ctx) throw new Error("Must be inside Provider");
```

- **createContext**: Context object banata hai with type + default value
- **Provider**: Value provide karta hai component tree ke andar
- **useContext(guard)**: Value consume karta hai + error agar Provider ke bahar use ho
- **Custom hook**: `useTheme()` — guard ke saath, reusable

## Abhi Tak Kya Hua

2.5 mein Lifting State Up seekha — siblings share state through parent. Lekin jab component tree deep ho aur har level ko data chahiye (jaise theme, auth user), toh lifting se prop drilling hoti hai. Composition help karta hai, lekin kabhi kabhi data ko **kahi bhi** accessible hona chahiye bina props ke.

## Broader Goal

Is doc mein **Context API** seekhenge — React ka built-in mechanism for global data. Ek **Theme Switcher** app banayenge:
- Dark/light mode toggle
- Context se theme har component ko milega
- Custom hook `useTheme()` banayenge (safely)
- TypeScript typing with context

## Step 1 — Problem Feel Karo: Prop Drilling Without Escape

Dark/light mode toggle chahiye. Har component ko current theme pata hona chahiye — background color, text color sab change hoga. Lifting state up se karein toh kya hoga? Socho **electricity connection jaisa** — har room ko light chahiye, lekin har room ke liye alag wire kheechne ki jagah ek main switch se poora ghar connect hota hai. Context wahi hai — ek jagah value, har jagah accessible.

```
App (theme state yahan)
  ├── Navbar
  │   ├── Logo (needs theme)
  │   └── ThemeToggle (needs theme + setter)
  ├── MainContent
  │   ├── Sidebar
  │   │   └── MenuItem[] (needs theme)
  │   └── Article (needs theme)
  └── Footer (needs theme)
```

Har component ko `theme` prop dena padega — 10+ components, including middle components jo sirf prop pass kar rahe hain. Prop drilling extreme ho gayi.

**Context API iska solution hai** — data directly component ko milta hai bina middle components ke through prop pass kiye.

## Step 2 — Context API: Teen Steps

Context ke liye teen cheezein chahiye — createContext, Provider, useContext.

### Step 1: Create Context

```ts
import { createContext } from "react";

type Theme = "light" | "dark";

interface ThemeContextValue {
  theme: Theme;
  toggleTheme: () => void;
}

const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);
```

- `createContext<T>(defaultValue)` — ek context object banata hai
- Generic type `ThemeContextValue` — context ka shape define karta hai
- `undefined` as default — taaki hum check kar sakein ki Provider ke bahar use ho raha hai

### Step 2: Provide Value

```tsx
function App() {
  const [theme, setTheme] = useState<Theme>("light");

  const toggleTheme = () => {
    setTheme((prev) => (prev === "light" ? "dark" : "light"));
  };

  return (
    <ThemeContext value={{ theme, toggleTheme }}>
      <Navbar />
      <MainContent />
      <Footer />
    </ThemeContext>
  );
}
```

**React 19:** Provider directly context component se render hota hai — `.Provider` ki zaroorat nahi.

### Step 3: Consume Value

```tsx
import { useContext } from "react";

function Navbar() {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error("useContext must be inside Provider");

  return (
    <nav style={{ background: ctx.theme === "dark" ? "#333" : "#eee" }}>
      <ThemeToggle />
    </nav>
  );
}
```

## Step 3 — Custom Hook: `useTheme()` (Safe Pattern)

Har component mein `useContext(ThemeContext)` + `if (!ctx) throw` likhna repetitive hai. Ek custom hook banao.

```ts
import { createContext, useContext } from "react";

type Theme = "light" | "dark";

interface ThemeContextValue {
  theme: Theme;
  toggleTheme: () => void;
}

const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);

export function useTheme(): ThemeContextValue {
  const ctx = useContext(ThemeContext);
  if (!ctx) {
    throw new Error("useTheme must be used within a ThemeProvider");
  }
  return ctx;
}
```

**Why guard?** Agar koi component ThemeProvider ke bahar `useTheme()` call karega, toh `undefined` milega (default value). Guard ensures clear error message instead of cryptic runtime error.

**Nutshell:** Context API teen steps mein kaam karta hai — `createContext` se context object banao, `<Context value={...}>` se value provide karo, `useContext` se value consume karo. Custom hook guard pattern ensures Provider ke bahar use ho toh clear error mile.

## Step 4 — ThemeProvider Component

Provider logic bhi alag component mein extract karo — `ThemeProvider`. App clean rahega.

```tsx
import { useState, type ReactNode } from "react";

interface ThemeProviderProps {
  children: ReactNode;
}

export function ThemeProvider({ children }: ThemeProviderProps) {
  const [theme, setTheme] = useState<Theme>("light");

  const toggleTheme = () => {
    setTheme((prev) => (prev === "light" ? "dark" : "light"));
  };

  return (
    <ThemeContext value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext>
  );
}
```

## Step 5 — Complete Theme Switcher

```tsx
import { createContext, useContext, useState, type ReactNode } from "react";

// Types
type Theme = "light" | "dark";

interface ThemeContextValue {
  theme: Theme;
  toggleTheme: () => void;
}

const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);

// Custom hook
function useTheme(): ThemeContextValue {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error("useTheme must be used within ThemeProvider");
  return ctx;
}

// Provider
function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<Theme>("light");
  const toggleTheme = () => {
    setTheme((prev) => (prev === "light" ? "dark" : "light"));
  };
  return (
    <ThemeContext value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext>
  );
}

// Consumer components
function ThemedBox() {
  const { theme, toggleTheme } = useTheme();

  const styles: Record<string, React.CSSProperties> = {
    light: { background: "#fff", color: "#000", border: "1px solid #ddd" },
    dark: { background: "#1a1a2e", color: "#fff", border: "1px solid #333" },
  };

  return (
    <div style={{ padding: "40px", ...styles[theme] }}>
      <h2>Current Theme: {theme}</h2>
      <button onClick={toggleTheme}>
        Switch to {theme === "light" ? "Dark" : "Light"} Mode
      </button>
      <p style={{ marginTop: "20px" }}>
        This box uses Context for theming — no props drilling!
      </p>
    </div>
  );
}

// Root
function App() {
  return (
    <ThemeProvider>
      <ThemedBox />
    </ThemeProvider>
  );
}
```

## Step 6 — Context API: When to Use, When to Avoid

### Use Context For:
- Theme (dark/light)
- Auth user
- Locale/language
- Any data almost har component ko chahiye

### Avoid Context For:
- High-frequency updates (animations, real-time data) — poora subtree re-render hota hai
- Data sirf 2-3 components ko chahiye — lifting state up kaafi hai
- Complex state logic — Context + useReducer milega, lekin Zustand better hai (Batch 6)

---

## Step 7 — Performance Note: Context + useMemo

Context value change → saare consuming components re-render. Agar context mein object/functions hain toh har render pe naya reference — even if data same ho.

**Fix: `useMemo` se value memoize karo:**

```tsx
import { useMemo } from "react";

function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<Theme>("light");
  const toggleTheme = useCallback(() => {
    setTheme((prev) => (prev === "light" ? "dark" : "light"));
  }, []);

  const value = useMemo(() => ({ theme, toggleTheme }), [theme]);

  return (
    <ThemeContext value={value}>{children}</ThemeContext>
  );
}
```

## Trade-off: Context vs Alternatives

| Pattern | Use Case | Problem |
|---|---|---|
| **Lifting State Up** | 2-3 siblings share state | Prop drilling in deep trees |
| **Composition** | Deep tree, middle components don't need data | Can't solve every case |
| **Context API** | Global data (theme, auth, locale) | High-frequency updates → full subtree re-render |
| **Zustand/Redux** (Batch 6) | Complex state, high performance | Extra boilerplate, learning curve |

**Rule of thumb:** Lift first. Compose second. Context third. Zustand when Context's re-render becomes a problem.

---

## Common Mistakes

1. **Provider bhoolna** — Context value `undefined` rahega. Custom hook guard se clear error milega.
2. **Har cheez Context mein daalna** — Sirf woh data jo almost har component ko chahiye (theme, auth). 2-3 components ke liye lifting up kaafi hai.
3. **High-frequency updates Context mein** — Har update pe poora subtree re-render. Jaise real-time stock price — Context mat use karo, Zustand ya external store lo.
4. **useMemo bhoolna** — Context value object/function hai toh har render pe naya reference. `useMemo` se wrap karo taaki unnecessary re-renders na ho.

## Summary

| Concept | Samajh |
|---|---|
| `createContext<T>(default)` | Context object banata hai |
| `<Context value={val}>` | Provider — value provide karta hai (React 19 syntax) |
| `useContext(Context)` | Consumer — value consume karta hai |
| Custom hook guard | `if (!ctx) throw` — safe access |
| Prop drilling solution | Context bypasses middle components |
