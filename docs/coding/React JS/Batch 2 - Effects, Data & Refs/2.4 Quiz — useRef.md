# 2.4 Quiz — useRef

## MCQ

Q: `useRef(0)` call karne par kya return hota hai?
A. Ek object `{ current: 0 }` — current property ke saath, jisme initial value store hoti hai
B. Ek number `0` — seedha value return hoti hai, object mein wrap nahi hoti
C. Ek array `[0, setValue]` — useState ki tarah value aur setter function return hota hai
D. Ek function `() => 0` — call karne par initial value return karta hai
> A. `useRef` ek plain JavaScript object return karta hai — `{ current: initialValue }`. Is object ki do properties hain: (1) persistence — renders ke beech reset nahi hota, (2) no re-render — React useRef ko watch nahi karta.

---

Q: `useState` aur `useRef` mein sabse important fark kya hai?
A. `useState` sirf numbers store kar sakta hai, `useRef` kuch bhi store kar sakta hai
B. `useState` change → re-render hota hai, `useRef` change → koi re-render nahi hota
C. `useState` ki value persist nahi hoti renders ke beech, `useRef` ki hoti hai
D. `useRef` sirf DOM elements ke liye hai, `useState` sirf data ke liye
> B. `useState` React ki "watchlist" mein register hota hai — `setState` call → signal → re-render. `useRef` watchlist mein nahi hai — `ref.current = x` bas ek normal JS object ki property change hai, React ko pata nahi chalta.

---

Q: Jab `useRef` ki initial value `null` hoti hai (jaise `useRef<HTMLInputElement>(null)`), TypeScript `.current` ko kaise treat karta hai?
A. Writable — tum `.current` ko koi bhi value assign kar sakte ho
B. Readonly — `.current` ko tum manually assign nahi kar sakte, sirf React assign karta hai
C. Optional — `.current` hamesha undefined hota hai, kabhi value assign nahi hoti
D. Dynamic — type runtime par decide hota hai, TypeScript interfere nahi karta
> B. Initial value `null` → TypeScript DOM ref (RefObject) infer karta hai. `.current` readonly hai — React khud DOM node assign karta hai `ref` attribute ke through. Tum manually assign nahi kar sakte. Initial value non-null ho toh mutable ref (MutableRefObject) — `.current` writable hai.

---

Q: `useRef` se DOM element access karne ke liye JSX mein kaunsa attribute use karte hain?
A. `element={inputRef}` — custom element attribute, React ise DOM se connect karta hai
B. `ref={inputRef}` — ref attribute, React ko batata hai ki is DOM element ka reference store karo
C. `connect={inputRef}` — connect prop, React ise internally DOM node assign karta hai
D. `bind={inputRef}` — bind attribute, DOM element aur ref object ko link karta hai
> B. `<input ref={inputRef} />` — `ref` attribute React ko batata hai: "jab tu `<input>` DOM mein create kare, uska reference `inputRef.current` mein assign kar de." Render ke baad `.current` actual DOM node se bhar jaata hai. Custom components pe `ref` kaam nahi karta — `forwardRef` chahiye.

---

Q: Component ke top-level pe (JSX return se pehle) `inputRef.current` read karne par kya milega?
A. Actual `<input>` DOM element — kyunki ref turant populate ho jata hai
B. `null` — kyunki component function render ke dauraan chal raha hai, DOM abhi bana nahi
C. `undefined` — React ref ko initially undefined set karta hai
D. Error — render ke dauraan ref access nahi kar sakte
> B. Component function render ke dauraan execute hota hai — DOM abhi create nahi hua. `inputRef.current` tab populate hota hai jab React actual DOM elements bana leta hai (render complete). Isliye `.current` event handlers ya `useEffect` ke andar read karo.

---

Q: Agar timer ID (`setInterval` se milne wali ID) ko `useState` mein store karein, toh kya problem hogi?
A. Timer ID ek number hoti hai — `useState` numbers store nahi kar sakta, sirf objects aur arrays store karta hai
B. `setTimerId(id)` call → state change → unnecessary re-render — kyunki timer ID ka UI se koi lena dena nahi, sirf `clearInterval` ke liye chahiye
C. `useState` mein timer ID store karna syntax error dega — React ise allowed nahi karta
D. `useRef` hamesha `useState` se fast hota hai — isliye har cheez ref mein daalni chahiye
> B. Timer ID sirf `clearInterval` ke liye chahiye — UI pe dikhni nahi chahiye. `useState` mein rakhein toh har `setTimerId(id)` call par re-render — useless. `useRef` perfect hai: interval ID store hogi, jab `clearInterval` karna ho tab mil jayegi, extra re-render nahi hoga.

---

Q: `inputRef.current?.focus()` mein `?.` (optional chaining) kyun important hai?
A. `?.` se TypeScript type safety milti hai — warna compilation fail hota hai
B. Agar `inputRef.current` null ho (element unmount ya conditional render), toh `.focus()` call error dega — `?.` se safe hai
C. `?.` se focus asynchronous hota hai — render cycle ke saath sync rehta hai
D. `?.` zaroori nahi hai — `.current` kabhi null nahi hota, hamesha DOM element hota hai
> B. Agar element conditionally render ho (jaise `{show && <input ref={inputRef} />}`) aur `show` false ho, toh DOM element exist nahi karega — `inputRef.current` null hoga. Bina `?.` ke `null.focus()` call → error. `?.` check karta hai: "null hai toh aage mat ja, undefined return kar."

---

Q: Mutable ref (jaise `useRef(0)`) aur DOM ref mein `.current` property ka kya fark hai?
A. Mutable ref mein `.current` writable hai — tum manually assign kar sakte ho. DOM ref mein readonly hai — sirf React assign karta hai
B. Mutable ref mein `.current` sirf numbers store kar sakta hai, DOM ref sirf DOM elements
C. Mutable ref ka `.current` undefined hota hai, DOM ref ka null hota hai
D. Dono same hain — koi fark nahi, sirf naming convention ka fark hai
> A. Initial value non-null → MutableRefObject → `.current` tum manually assign/change kar sakte ho (jaise `intervalRef.current = setInterval(...)`). Initial value `null` → RefObject → `.current` readonly hai — React khud DOM node assign karta hai `ref` attribute ke through.

---

Q: Previous value pattern mein ref aur state ka sequence kya hota hai?
A. Pehle state update (`setCount`), phir ref mein purani value store karo
B. Pehle ref mein current value store karo, phir state update karo — `prevCount.current = count; setCount(count + 1)`
C. Sirf ref mein store karo, state ki zaroorat nahi — ref se UI update karo
D. Sirf state mein store karo, ref ki zaroorat nahi — state se previous value nikaalo
> B. Sequence: pehle `prevCount.current = count` (current value ref mein backup), phir `setCount(count + 1)` (naya value state mein). Ref change se re-render nahi hota — jab state change se render hoga tab UI mein "Previous: X → Current: Y" dikhega.

## TrueFalse

Q: `useRef` ki value change karne se component re-render hota hai — isliye UI update ke liye `useRef` use kar sakte hain.
- True
- False
> False. `useRef` change se koi re-render nahi hota. `ref.current = x` bas ek normal JavaScript object ki property change hai — React use watch nahi karta. UI update ke liye `useState` chahiye. `useRef` un values ke liye hai jo screen pe dikhni nahi chahiye.

---

Q: `useRef` ki value renders ke beech persist rehti hai — component function har render pe dobara call hone ke bawajood ref reset nahi hota.
- True
- False
> True. Plain variable (`let x = 0`) har render pe reset hota hai — kyunki function fresh run ho raha hai. `useRef` ka object React internally store karta hai aur agle render pe wahi same object wapas deta hai — same reference, same `current` value.

---

Q: DOM ref (`useRef<HTMLInputElement>(null)`) mein `.current` ko tum manually koi bhi value assign kar sakte ho — jaise `inputRef.current = document.createElement('div')`.
- True
- False
> False. DOM ref (initial value `null`) mein `.current` readonly hai — sirf React assign karta hai. Tum manually assign karne ki koshish karoge toh TypeScript error dega. Initial value non-null ho tab `.current` writable hota hai.

---

Q: `ref` attribute sirf built-in HTML elements (`<input>`, `<div>`, `<video>`) pe kaam karta hai — custom React components pe nahi.
- True
- False
> True. `ref` attribute React's built-in elements ke liye designed hai. Custom components pe `ref` use karne ke liye `forwardRef` wrapper chahiye — jo ref ko custom component ke andar kisi HTML element tak forward kare.

---

Q: `ref.current` ko component ke top-level pe (JSX return se pehle) read karna safe hai — woh hamesha actual DOM element return karega.
- True
- False
> False. Component function render ke dauraan chal raha hai — DOM abhi create nahi hua. `ref.current` sirf render complete hone ke baad populate hota hai. Isliye top-level pe read karoge toh `null` milega. Event handler ya `useEffect` ke andar read karo.

---

Q: Timer ID ko `useState` mein store karna wasteful hai kyunki `setIntervalId(id)` se re-render trigger hota hai jabki ID ka UI se koi lena dena nahi.
- True
- False
> True. Timer ID sirf `clearInterval` ke liye chahiye — UI pe dikhni nahi chahiye. `useState` mein rakhein toh har `setIntervalId` call par re-render — useless. `useRef` perfect hai: `intervalRef.current = id` se value store hogi, koi re-render nahi hoga.

## ShortAnswer

Q: `useState` aur `useRef` mein teen fundamental fark kya hain? Kab kaunsa use karna chahiye? Example ke saath explain karo.

<details>
<summary>Sample Answer</summary>

**Teen fundamental fark:**

| Feature | useState | useRef |
|---|---|---|
| Re-render on change | ✅ Haan — `setState` call → signal → re-render | ❌ Nahi — `ref.current = x` bas normal JS property change |
| Return type | `[value, setValue]` — value + setter function | `{ current: initialValue }` — object with current property |
| When to use | UI-visible state (count, input, toggle) | Background values (timer ID, DOM ref, previous value) |

**Kab kaunsa use karein:**

- **useState** — jab value change par screen update chahiye. Example: `<p>Count: {count}</p>` — user dekhe ki count change ho raha hai.
- **useRef** — jab value sirf "yaad" rakhni hai, UI pe dikhni nahi. Example: `intervalRef.current = setInterval(...)` — interval ID sirf `clearInterval` ke liye chahiye.

**Code example — dono ka saath use:**

```tsx
function Stopwatch() {
  const [seconds, setSeconds] = useState(0);        // UI dikhega — state
  const intervalRef = useRef<ReturnType<typeof setInterval> | null>(null);  // background — ref

  const handleStart = () => {
    intervalRef.current = setInterval(() => {
      setSeconds((prev) => prev + 1);
    }, 1000);
  };

  const handleStop = () => {
    if (intervalRef.current) {
      clearInterval(intervalRef.current);            // ref use hua cleanup ke liye
      intervalRef.current = null;
    }
  };

  return <h1>⏱️ {seconds}s</h1>;                     // state UI mein dikhta hai
}
```

**Rule of thumb:** Value screen pe dikhni chahiye → `useState`. Value sirf background bookkeeping ke liye chahiye → `useRef`.

</details>

Q: DOM element access ke liye `useRef` ka poora pattern kya hai? Input focus karne ka example do. `ref`, `?.` (optional chaining), aur `.current` ki timing sab kuch samjhao.

<details>
<summary>Sample Answer</summary>

**Teen steps:**

```tsx
// Step 1 — Ref object banao
const inputRef = useRef<HTMLInputElement>(null);

// Step 2 — JSX mein ref attribute laga do
<input ref={inputRef} type="text" placeholder="Auto focus..." />

// Step 3 — Event handler mein DOM method call karo
const handleFocusClick = () => {
  inputRef.current?.focus();
};
```

**Step by step kya ho raha hai:**

**Step 1:** `useRef<HTMLInputElement>(null)` — `{ current: null }`. Abhi DOM bana nahi. TypeScript `.current` ko readonly treat karta hai (initial value `null` hai).

**Step 2:** `<input ref={inputRef} />` — React internally kuch aisa karta hai:
```
React create karta hai: const domElement = document.createElement('input')
Phir: inputRef.current = domElement   ← React khud assign karta hai
```
Render complete hone ke baad `.current` actual `<input>` DOM node se bhar jaata hai.

**Step 3:** Button click par `inputRef.current?.focus()` — `.focus()` browser ka built-in method hai jo cursor input mein daal deta hai.

**?. kyun important hai?**

```tsx
// ❌ Galat — without optional chaining
inputRef.current.focus();  // Error if current is null

// ✅ Sahi — with optional chaining
inputRef.current?.focus(); // Safe — null hai toh kuch nahi hoga
```

Agar element conditionally render ho:
```tsx
{showInput && <input ref={inputRef} />}
```
Jab `showInput = false`, DOM element exist nahi karta — `inputRef.current` null hai. `?.` bina `null.focus()` call → runtime error. `?.` check karta hai: "null/undefined hai toh function call mat karo."

**Timing — kab kya hota hai:**
- **Render ke dauraan** (JSX return se pehle): `inputRef.current` = `null` (DOM abhi bana nahi)
- **Render complete hone ke baad**: `inputRef.current` = actual `<input>` DOM element
- **Event handler mein** (button click): `.current` already populated hai — safe to access

</details>
