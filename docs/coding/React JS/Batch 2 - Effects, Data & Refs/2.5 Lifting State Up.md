# 2.5 — Lifting State Up

## Cheat Sheet (Quick Recall)

```
Pattern: Data down, Actions up
State → prop (parent → child via props)
Child → callback → parent (via onXxx props)

Prop Drilling: State ko deep tree mein bhejne ke liye middle components se gussar
Solution: Composition (children) ya Context API (agle doc mein)
```

- **Lift state up** = state ko child se nikaal kar common parent mein daalna
- **Siblings share data** → state parent mein rakho, props mein do
- **Prop drilling** = 4+ level deep → middle components ko unnecessary props

## Abhi Tak Kya Hua

Batch 1 mein To-Do App banaya — state saari `App.tsx` mein thi, components ne props receive ki aur callbacks through events bheje. Lekin wahan state ek hi component (App) ke andar thi. Kya hoga jab do components ko ek same state share karni hai? Ya jab state ek child mein hai aur parent ko bhi chahiye?

## Broader Goal

Is doc mein **Lifting State Up** seekhenge — ek pattern jisme state ko common parent mein rakha jata hai taaki multiple components share kar sakein. Yeh React ka fundamental pattern hai — iske bina Context aur state management libraries ka "why" nahi samjhega.

To-Do App ka ek specific scenario refactor karenge — **Task counter** (kitne tasks complete hue) ab ek alag `TaskStats` component mein dikhega, aur state App mein lift hogi.

---

## Step 1 — Problem Feel Karo: Sibling Components share data kaise karein?

To-Do App mein do components hain — TaskList (tasks dikhata hai) aur Footer (count dikhata hai). TaskList ke andar toggle hone se Footer ka count bhi update hona chahiye. Lekin dono siblings hain — ek doosre ko directly data nahi bhej sakte. React mein data flow **top → bottom** hota hai (parent → child via props). Siblings directly communicate nahi kar sakte. Toh agar do siblings ko same data chahiye, woh data **parent** mein rehna chahiye.

Socho **do bhai apne papa ke through baat karte hain** — ek bhai doosre ko directly paisa nahi de sakta, papa ke through deta hai. Yahan parent = papa, siblings = do bhai.

**Galat approach — child mein state:**
```tsx
function TaskItem() {
  const [completed, setCompleted] = useState(false);
  // Lekin parent aur siblings ko yeh state pata nahi
}
```

**Sahi approach — parent mein state:**
```tsx
function App() {
  const [tasks, setTasks] = useState<Task[]>([]);
  // State yahan hai — dono children (TaskList, Footer) access kar sakte hain
}
```

**Nutshell:** Lifting State Up ka matlab hai — jab do ya zyada components ko same data chahiye, toh state unke common parent mein rakho aur props ke through do. Siblings directly communicate nahi kar sakte — parent ka rasta use karna padta hai. Yaad hai To-Do App v1? Woh already lift tha — state App mein thi.

---

## Step 2 — Lifting State Up: The Pattern

State child component mein thi, ab use parent mein rakhna hai. Child ko state aur updater function props mein dena hai.

**Pattern ke 3 steps:**

1. **State ko child se parent mein "lift" karo** (move karo)
2. **State ko prop ke roop mein child ko do** (data down)
3. **Child ko ek callback prop do jo parent mein state update kare** (actions up)

```
State: App (parent)
  ├── TaskList (receives tasks + onToggle via props)
  │   └── TaskItem (receives task + onToggle via props)
  └── Footer (receives counts via props)
```

## Step 3 — Refactor: To-Do App Ka Count Feature

Batch 1 ke To-Do App mein count logic App.tsx ke andar hi tha. Ab use alag `TaskStats` component mein daalte hain — state App mein lift karni padegi.

### Step 3a — State App mein hai (already)

```tsx
function App() {
  const [tasks, setTasks] = useState<Task[]>([]);

  const handleToggle = (id: number) => {
    setTasks(tasks.map(t =>
      t.id === id ? { ...t, completed: !t.completed } : t
    ));
  };

  // HTML mein count inline tha — ab TaskStats component banayenge
}
```

### Step 3b — TaskStats Component (receives data via props)

```tsx
interface TaskStatsProps {
  total: number;
  completed: number;
  remaining: number;
}

function TaskStats({ total, completed, remaining }: TaskStatsProps) {
  return (
    <div style={{ fontSize: "14px", color: "#666" }}>
      <span>✅ {completed} done</span>
      <span style={{ margin: "0 12px" }}>⏳ {remaining} left</span>
      <span>📋 {total} total</span>
    </div>
  );
}
```

### Step 3c — App mein use karo

```tsx
function App() {
  const [tasks, setTasks] = useState<Task[]>([]);

  const completedCount = tasks.filter(t => t.completed).length;
  const remainingCount = tasks.length - completedCount;

  return (
    <div>
      <TaskInput onAdd={handleAdd} />
      <TaskList
        tasks={filteredTasks}
        onToggle={handleToggle}
        onDelete={handleDelete}
      />
      <TaskStats
        total={tasks.length}
        completed={completedCount}
        remaining={remainingCount}
      />
    </div>
  );
}
```

**Yeh Lifting State Up ka simplest example hai** — state App mein hai, dono children (TaskList aur TaskStats) ise props mein receive kar rahe hain.

**Nutshell:** Lifting State Up ke 3 steps: (1) state child se parent mein move karo, (2) state prop ke roop mein child ko do, (3) child ko callback prop do jo parent mein state update kare.

## Step 4 — Prop Drilling: Jab Lift Zyada Ho Jaye

Kya hoga jab component tree deep ho? State App mein hai, lekin usse 5 level neeche ComponentZ mein chahiye? Socho **office mein memo pass karna** — CEO ne memo diya, har level ka manager use pass karta hai chahe unhe zaroorat na ho. Yeh prop drilling hai.

```
App (state yahan)
  └── Layout
      └── Sidebar
          └── UserPanel
              └── Avatar (yeh chahiye state)
```

State App se Avatar tak pahunchane ke liye, Layout, Sidebar, aur UserPanel — teeno components ko bhi woh prop receive karna padega, chahe unhe zaroorat na ho. Is problem ko **Prop Drilling** kehte hain.

```tsx
// Layout ko user prop nahi chahiye, lekin receive karna pad raha hai
function Layout({ user }: { user: User | null }) {
  return (
    <div>
      <Sidebar user={user} />
    </div>
  );
}
```

**Prop Drilling ki problems:**
- Code verbose ho jata hai
- Middle components unnecessary props receive karte hain
- Refactor mushkil — beech mein component add/remove karo toh saari props update karni padti hain

## Step 5 — Composition: Prop Drilling Ka Pehla Solution

Prop drilling se bachne ka sabse simple tarika — `children` prop se composition.

**Prop drilling wala code:**
```tsx
function App() {
  const [user] = useState({ name: "Vin" });
  return <Layout user={user} />;
}
function Layout({ user }: { user: User }) {
  return <Sidebar user={user} />;
}
function Sidebar({ user }: { user: User }) {
  return <Avatar user={user} />;
}
```

**Composition se fix:**
```tsx
function App() {
  const [user] = useState({ name: "Vin" });
  return (
    <Layout>
      <Sidebar>
        <Avatar user={user} />
      </Sidebar>
    </Layout>
  );
}
function Layout({ children }: { children: React.ReactNode }) {
  return <div>{children}</div>;
}
function Sidebar({ children }: { children: React.ReactNode }) {
  return <aside>{children}</aside>;
}
```

Ab Layout aur Sidebar ko `user` prop ki zaroorat nahi — woh sirf children pass kar rahe hain. Avatar ko directly user mil gaya.

## Step 6 — Kab Lift Karna Hai, Kab Composition Use Karna Hai

| Scenario | Solution |
|---|---|
| Siblings share state | Lift to parent |
| 2-3 level deep | Lift to common parent |
| 4+ level deep | Composition ya Context (agle doc) |
| Ek hi child ko data chahiye | Keep local, don't lift |

---

## Trade-off: Lifting vs Composition vs Context

| Pattern | Kab Use Karein | Problem |
|---|---|---|
| **Lifting State Up** | 2-3 siblings share state | Prop drilling deep tree mein |
| **Composition (children)** | Deep tree, middle components ko prop nahi chahiye | Har case mein kaam nahi karta |
| **Context API** (agle doc) | Almost har component ko data chahiye (theme, auth) | Re-render performance impact |

**Rule of thumb:** Lift karo jab tak prop drilling na ho. Phir composition try karo. Phir Context (agle doc).

---

## Common Mistakes

1. **State ko unnecessarily lift karna** — Agar sirf ek child ko data chahiye, toh state usi child mein rakho. Parent mein mat daalo.
2. **Prop drilling ko ignore karna** — 5 level deep props pass karte rehna. Isse better hai composition ya Context.
3. **Callback props ka type bhoolna** — `onToggle: (id: number) => void` — TypeScript type hamesha do. Parent ko pata hona chahiye ki callback kya expect karta hai.
4. **State mutation directly** — `tasks.push(newTask)` mat karo. Always `setTasks([...tasks, newTask])`

## Khud Try Karo

1. Bina scroll kiye batao — agar do siblings ko same data chahiye, toh state kahan rakhoge?
   
   <details>
   <summary>Sample Answer</summary>
   Common parent mein. Siblings directly communicate nahi kar sakte. Parent state rakhta hai aur props ke through dono ko data deta hai.
   </details>

2. Code likho — ek `Parent` component jisme `count` state ho, aur do children (`Display` aur `Button`) jo use karein.

   <details>
   <summary>Sample Answer</summary>
   
   ```tsx
   function Parent() {
     const [count, setCount] = useState(0);
     return (
       <div>
         <Display count={count} />
         <Button onIncrement={() => setCount(c => c + 1)} />
       </div>
     );
   }
   function Display({ count }: { count: number }) { return <p>{count}</p>; }
   function Button({ onIncrement }: { onIncrement: () => void }) { return <button onClick={onIncrement}>+</button>; }
   ```
   </details>

3. Predict karo — agar state `TaskItem` mein rakhi aur `App` ko bhi chahiye, toh kya problem hogi?

   <details>
   <summary>Sample Answer</summary>
   React mein data flow top → bottom hota hai. Child ka data parent tak nahi pahunch sakta bina callback ke. Lekin callback se state update karoge toh child ko prop update karna padega — cycle complex ho jayega. Isliye state parent mein rakhna better hai.
   </details>

## Summary

| Concept | Samajh |
|---|---|
| Lifting State Up | State ko child se parent mein move karo taaki siblings share kar sakein |
| Data down, actions up | State → prop (down), Child → callback → parent (up) |
| Prop Drilling | State ko deep tree mein bhejne ke liye middle components se gussar |

Lifting State Up samajh aa gaya — state parent mein, data props mein, actions callbacks mein.
