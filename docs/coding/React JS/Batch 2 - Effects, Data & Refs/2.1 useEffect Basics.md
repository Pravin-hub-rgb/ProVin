## Cheat Sheet (Quick Recall)

```ts
useEffect(() => { /* side effect */ }, [deps]);  // render ke baad chalta hai
useEffect(() => { return () => { /* cleanup */ }; }, []);  // mount + unmount
```
- **Side effect** = React ke render cycle ke bahar ka code (timer, API, storage)
- **Dependency array** = batata hai ki effect kab re-run karna hai
- **Cleanup** = unmount / re-run se pehle chalta hai — memory leak se bachata hai

## Abhi Tak Kya Hua

Yaar Batch 1 mein humne To-Do App banaya tha — components, props, useState, sab synchronous tha. React ka kaam hai: state change hoti hai → component re-render hota hai → naya JSX milta hai → DOM update hota hai. Is cycle ko kehte hain **render cycle**. Jab tak sab kuch is cycle ke andar hai, React apne aap sab sambhal leta hai.

Lekin asli apps mein timer chalana padta hai, API se data lana padta hai, localStorage mein save karna padta hai — yeh sab render cycle ke **bahar** ki cheezein hain. React inhe side effects kehta hai. Main bhi pehle confuse tha ki yeh kahan likhein. Is doc mein wahi dekhenge.

## Step 1 — Render Ke Baad Bhi Kaam Karna Hota Hai

Component render hota hai, UI dikh jaata hai. Lekin kabhi kabhi render ke **baad** bhi kuch kaam karna hota hai — browser tab ka title change karna, API se data laana, timer shuru karna. Yeh sab **side effects** hain.

Coder ki soch:
> "Pehle render ho jao, UI dikh jaye — phir yeh kaam karo."

**Yeh concept naya nahi hai.** Vanilla JS mein yaad hai — jab DOM element access karna hota tha, toh `DOMContentLoaded` event ka wait karte the? Kyonki DOM ready hone se pehle element access karoge toh error aayegi. Wahi baat React mein:

```
Vanilla JS:  DOMContentLoaded → DOM ready → phir element access
React:       Render complete → DOM ready → phir useEffect chale
```

`useEffect` React ka `DOMContentLoaded` hai — component render ke baad, DOM safe hone ke baad chalta hai. Chal dekhte hain kaam karte hue:

```tsx
'use client'
import { useEffect } from "react";

function PageTitle() {
  useEffect(() => {
    document.title = "Page Load Ho Gayi! 🎉";
  }, []);

  return <p>Browser tab dekh — title change ho gaya?</p>;
}
```

Browser mein dekh — component render hua, UI aaya, phir `useEffect` ne title change kiya. Pehle render, phir effect. Is order ko yaad rakhna — bahut kaam aayega.

**Nutshell:** `useEffect` ek hook hai jo **component render hone ke baad** chalta hai — jaise vanilla JS mein `DOMContentLoaded` event DOM ready hone ke baad chalta hai. Render ke baad wale sabhi kaam (title change, API call, timer) ke liye yeh jagah hai.

## Step 2 — Lekin Yeh Code Side Effect Hai (Problem Feel Karo)

Ab samajhte hain ki **kyun** yeh cheezein React ke render cycle ke andar nahi likhni chahiye. Side effect kya hota hai yeh samajhne ke liye, aisa try karte hain — ek timer chahiye jo har second tick kare. Main component mein seedha `setInterval` daal deta hoon. Chal karke dekhte hain kya hota hai:

```tsx
function Timer() {
  let count = 0;
  setInterval(() => {
    count++;
    console.log(count);
  }, 1000);
  return <p>Check console</p>;
}
```

Chala ke dekh — console mein tick aa raha hai. Lekin ek problem aa gayi: **React ko pata nahi ki kuch change ho raha hai.** Screen pe kuch update nahi hota.

Ruko, samajhte hain ki React ko pata kyun nahi chal raha. Yeh React ka core design hai:

React ka kaam hai: jab bhi koi **state** change hoti hai, tab component re-render hota hai. Lekin yahan humne `let count = 0` likha — yeh ek local variable hai, React state nahi. `count++` karke hum value toh badha rahe hain, lekin React ko is baat ka pata hi nahi ki kuch bhi change hua. Kyun? Kyunki React ke paas koi mechanism nahi hai jo "dekhte rahe" ki local variable change ho raha hai ya nahi.

**Yaise soch:** React ek restaurant ka manager hai. Waiter (state setter) use batata hai "order aaya" tabhi woh action leta hai. Local variable ek aisa customer hai jo seedha kitchen mein jaake khana bana raha hai — manager ko pata hi nahi ki kitchen mein kuch ho raha hai. Manager tabhi action lega jab waiter use bolega.

React ka render cycle sirf **state changes** se trigger hota hai. `useState` ka setter function call karte ho → React ko pata chalta hai → component re-render hota hai. Lekin `let count` ka koi setter nahi hai, koi "hey React, main change hua" signal nahi hai. Isliye React ko kuch pata nahi chalta.

**Kyun aisa design hai?** React intentionally alag rakhta hai "jo render trigger kare" (state) aur "jo sirf render ke andar use ho" (local variables). Agar har chhoti JS variable change pe React re-render karega, toh performance kharab ho jayegi. Isliye React kehta hai: "tujhe change batana hai toh setter call kar, nahi toh main nahi jaanunga."

Aur ek problem aur hai — soch agar yeh component kahi conditionally show ho raha ho, ya page change ho jaye, toh component UI se hat jayega (ise kehte hain **unmount**). Lekin `setInterval` abhi bhi background mein chal raha hai — kyunki React ko koi nahi bataya ki "yeh band kar do". Har second woh ek naya `count` increment kar raha hai aur variable ko reference hold kar raha hai. React ka garbage collector use nahi kar sakta kyunki interval abhi bhi active hai. Memory leak yahi hota hai — woh memory jo free honi chahiye thi, woh abhi bhi occupied hai kyunki interval ka reference khatam nahi hua. Maine bhi yahi galti ki thi pehli baar — component hat gaya but timer chalta raha, console tick karta raha, aur main sochta raha "kya chal raha hai?"

Timer, API call, localStorage — yeh sab render cycle ke bahar ki cheezein hain. React inhe side effects kehta hai. Render cycle pure hota hai — same props + same state = same JSX return karna chahiye. Timer ya API call is purity ko todti hai kyunki woh external cheezo par depend karti hai.

Yaad hai DukaanOS mein auto-save tha? Ya TradeStack mein stock price polling — woh sab side effects hi hain.

**Nutshell:** Side effects woh operations hote hain jo React ke render cycle ke bahar ja ke kaam karte hain — timer, API call, storage waghera. Inhe React ke render ke baad, alag se handle karna padta hai.

## Step 3 — useEffect Ka Syntax + Render-First Verification

Ab problem clear hai — side effect ko render ke baad handle karna hai. React iske liye ek hook deta hai — `useEffect`.

`useEffect` do arguments leta hai:

```ts
useEffect(() => {
  // side effect logic
}, [dependencies]);
```

- Pehla argument: **setup function** — side effect ka code
- Doosra argument: **dependency array** — batata hai ki effect kab re-run karna hai

Setup function **render ke baad** chalta hai — humesha. Jaise chai mein pehle cup taiyaar hota hai (render), phir patti daali jaati hai (useEffect). Agar cup hi nahi bana to patti daalne ka koi fayda nahi.

Chal visually verify karte hain ki render ke baad chal raha hai ya nahi:

```tsx
import { useState, useEffect } from "react";

function TimerApp() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    console.log("🔧 useEffect chala — count hai:", count);
  });

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
}
```

Browser mein dekh — har baar button dabao, console mein useEffect chala dikhega. **Notice order:** pehle screen change (render), phir console log (effect).

```
Initial render   → DOM update   → 🔧 useEffect chala — count hai: 0
Button click     → DOM update   → 🔧 useEffect chala — count hai: 1
Button click     → DOM update   → 🔧 useEffect chala — count hai: 2
```

**Kyun har baar?** Dependency array nahi diya — jab array nahi hota, useEffect **har render ke baad** chalta hai.

**Nutshell:** `useEffect(fn, [deps])` ek React hook hai jo component render hone ke baad fn ko call karta hai. Doosra argument (dependency array) control karta hai ki fn kab wapas call ho.

## Step 4 — Dependency Array: Teen Cases

Ab dependency array ke 3 cases samajhte hain. Mujhe bhi yeh samajhne mein time laga tha, lekin ek baar console mein dekh ke dekho toh fark clear ho jayega.

---

**Case 1 — Empty Array `[]`: Sirf Mount Pe Chale**

Kabhi sirf ek baar chalna chahiye — jab component pehli baar UI mein aata hai (ise kehte hain **mount**). Jaise API se data lana: component screen pe aate hi ek baar fetch karo, baar baar nahi.

```tsx
useEffect(() => {
  console.log("🟢 Component mount hua — sirf ek baar");
}, []);  // empty dependency array
```

Button dabao chahe 10 baar — console mein sirf ek baar log aayega. Sirf mount pe.

```
Initial render   → 🟢 Component mount hua — sirf ek baar
Button click     → (kuch nahi)
Button click     → (kuch nahi)
```

Empty array unique hai kyunki koi value change nahi ho sakti. React decide karta hai — "yeh effect sirf mount pe chalega, kabhi wapas nahi."

---

**Case 2 — With Value `[count]`: Sirf Count Change Pe Chale**

```tsx
useEffect(() => {
  console.log("🔄 Count change hua:", count);
}, [count]);  // sirf count change hone pe chale
```

```
Initial render   → 🔄 Count change hua: 0
Button click     → 🔄 Count change hua: 1
Button click     → 🔄 Count change hua: 2
```

Effect sirf count change pe chal raha hai — baaki kisi bhi state change pe nahi. Ek input daalo jo `text` set karta hai — text change karo, effect nahi chalega. Sirf count button dabane pe chalega. Dependency array ne effect ko count ki limit kar diya.

---

**Case 3 — No Array: Har Render Pe (Rare, Avoid)**

```tsx
useEffect(() => {
  console.log("Har render pe chalta hoon");
});  // no array = har baar
```

Yehi wala case tha Step 3 mein — dependency array diya hi nahi. Usually avoid karo, kyunki infinite loop ka khatra rahta hai (baad mein dekhenge).

---

**Important Rule:** Jo bhi reactive value (state, prop) effect ke andar use ho, woh dependency array mein aani chahiye. React lint rule enforce karta hai. Agar daali nahi toh purani value use hogi — ise **"stale closure"** kehte hain. Normal hai agar pehle confuse ho, mujhe bhi hua tha — agle step mein cleanup ke saath example dekhenge.

**Nutshell:** Dependency array `[dep1, dep2]` useEffect ko batata hai ki "yeh effect tabhi re-run karo jab in values mein se koi change ho." Empty array `[]` = sirf mount pe. Koi array nahi = har render pe (avoid).

## Step 5 — Cleanup Function: Gandaai Saaf Karna

Aur ek baat jo main bhool gaya tha pehle — cleanup. Soch: Step 2 wala timer setInterval chalaya. Ab component UI se hat gaya (unmount) — jaise page change kiya ya Hide button dabaya. Lekin `setInterval` abhi bhi background mein chal raha hai. Kyun? Kyunki kisi ne use nahi bataya "band kar do." React automatically timers nahi rokta — woh sirf JSX handle karta hai.

Har second woh interval function chal raha hai, variables ko reference hold kar raha hai, resources consume kar raha hai. Aur kyunki interval kabhi khatam nahi ho raha, React ka garbage collector us memory ko free nahi kar sakta. Isko **memory leak** kehte hain — woh memory jo free honi chahiye thi component unmount hone ke baad, woh abhi bhi occupied hai. Kam ho toh chalta hai, lekin 10-20 aise timers ho toh browser slow ho jayega aur kuch seconds mein pura page hang.

`useEffect` ka setup function ek cleanup function return kar sakta hai. React ise:
- Unmount hone pe chalata hai
- Effect re-run se pehle bhi chalata hai (purane effect ko clean karke naya chalata hai)

```tsx
useEffect(() => {
  console.log("⏱️ Timer setup");
  const id = setInterval(() => {
    console.log("⏰ Tick");
  }, 1000);

  return () => {
    console.log("🧹 Cleanup — timer hata rahe hain");
    clearInterval(id);
  };
}, []);
```

Pehle `[]` hai — sirf mount pe setInterval chalega. Unmount pe cleanup chalega.

Try kar browser mein:
1. Component mount hua → "⏱️ Timer setup" + har second "⏰ Tick"
2. Component unmount karo (conditional rendering se hide karo) → "🧹 Cleanup — timer hata rahe hain"
3. Timer ab background mein nahi chal raha

**Visibility Toggle example:**

```tsx
function TimerApp() {
  const [showTimer, setShowTimer] = useState(true);

  return (
    <div>
      <button onClick={() => setShowTimer(!showTimer)}>
        {showTimer ? "Hide" : "Show"} Timer
      </button>
      {showTimer && <Timer />}
    </div>
  );
}

function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    console.log("⏱️ Timer mounted");
    const id = setInterval(() => {
      setSeconds((prev) => prev + 1);
    }, 1000);

    return () => {
      console.log("🧹 Timer unmounted — cleanup");
      clearInterval(id);
    };
  }, []);

  return <p>Seconds: {seconds}</p>;
}
```

"Hide Timer" dabao — console mein "🧹 Timer unmounted — cleanup" aaya. 5 second ruko — koi tick nahi. "Show Timer" dabao — naya timer setup, seconds 0 se shuru.

> **What It Is NOT:** Cleanup function sirf unmount pe nahi chalata — re-run pe bhi chalata hai. Jab dependencies change hoti hain, pehle purane effect ka cleanup chalta hai, phir naya setup. Isko useEffect ka "reset" mechanism samjho.

**Nutshell:** Cleanup function ek regular function hai jo `useEffect` ke setup function se return hota hai. React ise component unmount hone par aur effect re-run se pehle call karta hai — resources (timers, subscriptions, listeners) ko saaf karne ke liye.

## Step 6 — Mini-Project: Countdown Timer (With All Concepts)

Ab saare concepts ek saath — dependency array, timers, cleanup. Chal ek countdown timer banate hain saath mein.

**Kya chahiye:**
- User initial time set kare (seconds mein)
- Start button dabaye toh countdown shuru ho
- Pause/Resume ho
- Time khatam ho toh alert dikhe
- Cleanup handle ho

### UI + State Setup

```tsx
function CountdownApp() {
  const [timeLeft, setTimeLeft] = useState(0);
  const [isRunning, setIsRunning] = useState(false);
  const [initial, setInitial] = useState(10);

  return (
    <div style={{ padding: "20px" }}>
      <h1>⏱️ Countdown: {timeLeft}s</h1>
      <div>
        <input
          type="number"
          value={initial}
          onChange={(e) => setInitial(Number(e.target.value))}
        />
        <button onClick={() => { setTimeLeft(initial); setIsRunning(false); }}>
          Set
        </button>
      </div>
      <div style={{ marginTop: "10px" }}>
        <button onClick={() => setIsRunning(true)} disabled={isRunning || timeLeft <= 0}>
          Start
        </button>
        <button onClick={() => setIsRunning(false)} disabled={!isRunning}>
          Pause
        </button>
        <button onClick={() => { setTimeLeft(0); setIsRunning(false); }}>
          Reset
        </button>
      </div>
    </div>
  );
}
```

### useEffect with Timer + Cleanup

Timer chahiye jo har second timeLeft decrement kare — lekin sirf jab isRunning true ho.

```tsx
useEffect(() => {
  if (!isRunning) return;

  const id = setInterval(() => {
    setTimeLeft((prev) => {
      if (prev <= 1) {
        setIsRunning(false);
        return 0;
      }
      return prev - 1;
    });
  }, 1000);

  return () => clearInterval(id);
}, [isRunning]);
```

`isRunning` dependency mein isliye hai kyunki andar use ho raha hai — agar effect re-run nahi kiya toh purani value use hogi. Lekin `timeLeft` dependency mein nahi kyunki `setTimeLeft(prev => ...)` functional update use kar rahe hain — stale closure problem prevent ho gayi.

### Handle Time Up

```tsx
useEffect(() => {
  if (timeLeft === 0 && isRunning) {
    setIsRunning(false);
    alert("Time's up! 🛎️");
  }
}, [timeLeft, isRunning]);
```

### Poora Code Ek Saath:

```tsx
import { useState, useEffect } from "react";

function CountdownApp() {
  const [timeLeft, setTimeLeft] = useState(0);
  const [isRunning, setIsRunning] = useState(false);
  const [initial, setInitial] = useState(10);

  useEffect(() => {
    if (!isRunning) return;
    const id = setInterval(() => {
      setTimeLeft((prev) => {
        if (prev <= 1) {
          setIsRunning(false);
          return 0;
        }
        return prev - 1;
      });
    }, 1000);
    return () => clearInterval(id);
  }, [isRunning]);

  useEffect(() => {
    if (timeLeft === 0 && isRunning) {
      setIsRunning(false);
      alert("Time's up! 🛎️");
    }
  }, [timeLeft, isRunning]);

  return (
    <div style={{ padding: "20px" }}>
      <h1>⏱️ Countdown: {timeLeft}s</h1>
      <div>
        <input
          type="number"
          value={initial}
          onChange={(e) => setInitial(Number(e.target.value))}
        />
        <button onClick={() => { setTimeLeft(initial); setIsRunning(false); }}>
          Set
        </button>
      </div>
      <div style={{ marginTop: "10px" }}>
        <button onClick={() => setIsRunning(true)} disabled={isRunning || timeLeft <= 0}>
          Start
        </button>
        <button onClick={() => setIsRunning(false)} disabled={!isRunning}>
          Pause
        </button>
        <button onClick={() => { setTimeLeft(0); setIsRunning(false); }}>
          Reset
        </button>
      </div>
    </div>
  );
}

export default CountdownApp;
```

## Step 7 — useEffect Recap: Kab Kaunsa Pattern Use Karein

| Dependency Array | Kab Chalega | Use Case |
|---|---|---|
| `[]` (empty) | Sirf mount pe | Initial API fetch, third-party setup |
| `[dep1, dep2]` | Mount pe + jab dep change ho | Sync with state/props |
| Kuch nahi | Har render pe (rare) | Debug/logging (avoid in production) |

### What It Is NOT

- `useEffect` **data fetching ka solution nahi hai** — yeh sirf ek tool hai. TanStack Query/SWR better hain (agle doc mein dekhenge).
- `useEffect` **synchronous nahi hai** — render ke baad chalta hai. Matlab pehle JSX DOM mein jayega (user screen pe dekhega), phir effect chalega. Isliye user ko koi "flash" (jaise loading spinner ke baad content achanak dikhe) nahi dikhta — kyunki jab tak effect chalta hai, DOM already ready hai.
- Dependency array ko "optimization" mat samjho — yeh **behavior definition** hai. Reactive value andar use ho toh array mein aani chahiye, chahe performance pe fark pade ya na.

---

## Common Mistakes

1. **Dependency array bhoolna** — `useEffect(() => { ... })` bina array ke har render pe chalega, infinite loop causes.
2. **Cleanup bhoolna** — `setInterval` / `addEventListener` ko cleanup na karein toh memory leak. Hamesha `return () => clearInterval(id)` karo.
3. **useEffect ko async banana** — `useEffect(async () => { ... })` galat hai. Kyun? `useEffect` ka pehla argument ek function expect karta hai jo ya toh kuch return na kare (void) ya ek cleanup function return kare. `async` function hamesha ek Promise return karta hai — cleanup function nahi. React Promise ko cleanup ki tarah treat karega toh kaam nahi karega. Toh solution: async function andar define karo aur call karo:
   ```tsx
   useEffect(() => {
     async function fetchData() {
       const data = await api.get(...);
     }
     fetchData();
   }, []);
   ```
4. **Stale closure** — Agar `count` andar use ho rahi hai lekin `[]` diya, toh effect sirf mount pe chalega. Mount ke time jo `count` ka value tha (0), woh closure mein capture ho gaya. Ab `count` change hone ke baad bhi, effect wapas nahi chalega kyunki `[]` hai — andar wala `count` hamesha 0 hi rahega. Isliye rule: **jo reactive value andar use ho, woh dependency array mein aani chahiye.**

## Summary

| Concept | Samajh |
|---|---|
| Side Effect | Render cycle ke bahar ka code — timer, API, browser API |
| `useEffect(fn, [deps])` | Render ke baad fn chalata hai; deps change pe re-run |
| Cleanup Function | Return karo `fn` se — component unmount/effect re-run pe chalta hai |
| Empty `[]` | Sirf mount pe effect chale |
| `[dep]` | Mount + dep change pe chale |
| No array | Har render ke baad (rare) |
