## Cheat Sheet (Quick Recall)

```ts
useEffect(() => { /* side effect */ }, [deps]);  // render ke baad chalta hai
useEffect(() => { return () => { /* cleanup */ }; }, []);  // mount + unmount
```
- **Side effect** = React ke render cycle ke bahar ka code (timer, API, storage)
- **Dependency array** = batata hai ki effect kab re-run karna hai
- **Cleanup** = unmount / re-run se pehle chalta hai — memory leak se bachata hai

## Abhi Tak Kya Hua

Yaar Batch 1 mein humne To-Do App banaya tha — components, props, useState, sab synchronous tha. React ka kaam hai: state change hoti hai → component re-render hota hai → naya JSX milta hai → DOM update hota hai. Is cycle ko kehte hain **render cycle**. Jab tak sab kuch is cycle ke andar hai, React apne aap sab sambhal leta hai.

Lekin asli apps mein timer chalana padta hai, API se data lana padta hai, localStorage mein save karna padta hai — yeh sab render cycle ke **bahar** ki cheezein hain. React inhe side effects kehta hai. Main bhi pehle confuse tha ki yeh kahan likhein. Is doc mein wahi dekhenge.

## Step 1 — Render Ke Baad Bhi Kaam Karna Hota Hai

Component render hota hai, UI dikh jaata hai. Lekin kabhi kabhi render ke **baad** bhi kuch kaam karna hota hai — browser tab ka title change karna, API se data laana, timer shuru karna. Yeh sab **side effects** hain.

Coder ki soch:
> "Pehle render ho jao, UI dikh jaye — phir yeh kaam karo."

**Yeh concept naya nahi hai.** Vanilla JS mein yaad hai — jab DOM element access karna hota tha, toh `DOMContentLoaded` event ka wait karte the? Kyonki DOM ready hone se pehle element access karoge toh error aayegi. Wahi baat React mein:

```
Vanilla JS:  DOMContentLoaded → DOM ready → phir element access
React:       Render complete → DOM ready → phir useEffect chale
```

`useEffect` React ka `DOMContentLoaded` hai — component render ke baad, DOM safe hone ke baad chalta hai. Chal dekhte hain kaam karte hue:

```tsx
'use client'
import { useEffect } from "react";

function PageTitle() {
  useEffect(() => {
    document.title = "Page Load Ho Gayi! 🎉";
  }, []);

  return <p>Browser tab dekh — title change ho gaya?</p>;
}
```

Browser mein dekh — component render hua, UI aaya, phir `useEffect` ne title change kiya. Pehle render, phir effect. Is order ko yaad rakhna — bahut kaam aayega.

**Nutshell:** `useEffect` ek hook hai jo **component render hone ke baad** chalta hai — jaise vanilla JS mein `DOMContentLoaded` event DOM ready hone ke baad chalta hai. Render ke baad wale sabhi kaam (title change, API call, timer) ke liye yeh jagah hai.

## Step 2 — Lekin Yeh Code Side Effect Hai (Problem Feel Karo)

Ab samajhte hain ki **kyun** yeh cheezein React ke render cycle ke andar nahi likhni chahiye. Side effect kya hota hai yeh samajhne ke liye, aisa try karte hain — ek timer chahiye jo har second tick kare. Main component mein seedha `setInterval` daal deta hoon. Chal karke dekhte hain kya hota hai:

```tsx
function Timer() {
  let count = 0;
  setInterval(() => {
    count++;
    console.log(count);
  }, 1000);
  return <p>Check console</p>;
}
```

<details>
<summary>⚡ setInterval / clearInterval kya hai? — Browser ki API hai</summary>

setInterval React ka feature nahi hai — yeh **browser ki API** hai. Seedha browser JavaScript engine ka part hai. Kaam: har X millisecond ke baad ek function chala do.

```js
setInterval(() => { console.log("Tick"); }, 1000);
// Har 1 second mein "Tick" print karega — infinite, jab tak band na karo
```

**setInterval ek ID return karta hai** — ek unique number (jaise 1, 2, 3...). Yeh ID us interval ka "identity card" hai. Jab band karna ho, toh yeh ID use karte hain:

```js
const id = setInterval(() => { console.log("Tick"); }, 1000);
// id = koi number, jaise 5

clearInterval(id);  // Band kar do! Ab "Tick" nahi print hoga
```

**Yaise samjho:** TV ka remote hai. `setInterval` = "har 1 second mein screen pe 'Tick' dikhao" ka button dabaya. Iska ek remote code hai (ID). `clearInterval(id)` = wahi remote code daal ke OFF karna. Agar OFF nahi kiya, TV infinite chalega.

Yeh concept React mein bahut aayega kaam — Step 5 mein cleanup function wahi `clearInterval` use karega timer band karne ke liye.
</details>

Chala ke dekh — console mein tick aa raha hai. Lekin ek problem aa gayi: **React ko pata nahi ki kuch change ho raha hai.** Screen pe kuch update nahi hota.

Ruko, samajhte hain ki React ko pata kyun nahi chal raha. Yeh React ka core design hai:

React ka kaam hai: jab bhi koi **state** change hoti hai, tab component re-render hota hai. Lekin yahan humne `let count = 0` likha — yeh ek local variable hai, React state nahi. `count++` karke hum value toh badha rahe hain, lekin React ko is baat ka pata hi nahi ki kuch bhi change hua. Kyun? Kyunki React ke paas koi mechanism nahi hai jo "dekhte rahe" ki local variable change ho raha hai ya nahi.

**Yaise soch:** React ek restaurant ka manager hai. Waiter (state setter) use batata hai "order aaya" tabhi woh action leta hai. Local variable ek aisa customer hai jo seedha kitchen mein jaake khana bana raha hai — manager ko pata hi nahi ki kitchen mein kuch ho raha hai. Manager tabhi action lega jab waiter use bolega.

React ka render cycle sirf **state changes** se trigger hota hai. `useState` ka setter function call karte ho → React ko pata chalta hai → component re-render hota hai. Lekin `let count` ka koi setter nahi hai, koi "hey React, main change hua" signal nahi hai. Isliye React ko kuch pata nahi chalta.

**Kyun aisa design hai?** React intentionally alag rakhta hai "jo render trigger kare" (state) aur "jo sirf render ke andar use ho" (local variables). Agar har chhoti JS variable change pe React re-render karega, toh performance kharab ho jayegi. Isliye React kehta hai: "tujhe change batana hai toh setter call kar, nahi toh main nahi jaanunga."

Aur ek problem aur hai — soch agar yeh component kahi conditionally show ho raha ho, ya page change ho jaye, toh component UI se hat jayega (ise kehte hain **unmount**). Lekin `setInterval` abhi bhi background mein chal raha hai — kyunki React ko koi nahi bataya ki "yeh band kar do". Har second woh ek naya `count` increment kar raha hai aur variable ko reference hold kar raha hai. React ka garbage collector use nahi kar sakta kyunki interval abhi bhi active hai. Memory leak yahi hota hai — woh memory jo free honi chahiye thi, woh abhi bhi occupied hai kyunki interval ka reference khatam nahi hua. Maine bhi yahi galti ki thi pehli baar — component hat gaya but timer chalta raha, console tick karta raha, aur main sochta raha "kya chal raha hai?"

Timer, API call, localStorage — yeh sab render cycle ke bahar ki cheezein hain. React inhe side effects kehta hai. Render cycle pure hota hai — same props + same state = same JSX return karna chahiye. Timer ya API call is purity ko todti hai kyunki woh external cheezo par depend karti hai.

Yaad hai DukaanOS mein auto-save tha? Ya TradeStack mein stock price polling — woh sab side effects hi hain.

**Nutshell:** Side effects woh operations hote hain jo React ke render cycle ke bahar ja ke kaam karte hain — timer, API call, storage waghera. Inhe React ke render ke baad, alag se handle karna padta hai.

## Step 3 — useEffect Ka Syntax + Render-First Verification

Ab problem clear hai — side effect ko render ke baad handle karna hai. React iske liye ek hook deta hai — `useEffect`.

`useEffect` do arguments leta hai:

```ts
useEffect(() => {
  // side effect logic
}, [dependencies]);
```

- Pehla argument: **setup function** — side effect ka code
- Doosra argument: **dependency array** — batata hai ki effect kab re-run karna hai

Setup function **render ke baad** chalta hai — humesha. Jaise chai mein pehle cup taiyaar hota hai (render), phir patti daali jaati hai (useEffect). Agar cup hi nahi bana to patti daalne ka koi fayda nahi.

Chal visually verify karte hain ki render ke baad chal raha hai ya nahi:

```tsx
import { useState, useEffect } from "react";

function TimerApp() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    console.log("🔧 useEffect chala — count hai:", count);
  });

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
}
```

Browser mein dekh — har baar button dabao, console mein useEffect chala dikhega. **Notice order:** pehle screen change (render), phir console log (effect).

```
Initial render   → DOM update   → 🔧 useEffect chala — count hai: 0
Button click     → DOM update   → 🔧 useEffect chala — count hai: 1
Button click     → DOM update   → 🔧 useEffect chala — count hai: 2
```

**Kyun har baar?** Dependency array nahi diya — jab array nahi hota, useEffect **har render ke baad** chalta hai.

**Nutshell:** `useEffect(fn, [deps])` ek React hook hai jo component render hone ke baad fn ko call karta hai. Doosra argument (dependency array) control karta hai ki fn kab wapas call ho.

## Step 4 — Dependency Array: Teen Cases

Ab dependency array ke 3 cases samajhte hain. Mujhe bhi yeh samajhne mein time laga tha, lekin ek baar console mein dekh ke dekho toh fark clear ho jayega.

---

**Case 1 — Empty Array `[]`: Sirf Mount Pe Chale**

Kabhi sirf ek baar chalna chahiye — jab component pehli baar UI mein aata hai (ise kehte hain **mount**). Jaise API se data lana: component screen pe aate hi ek baar fetch karo, baar baar nahi.

```tsx
useEffect(() => {
  console.log("🟢 Component mount hua — sirf ek baar");
}, []);  // empty dependency array
```

Button dabao chahe 10 baar — console mein sirf ek baar log aayega. Sirf mount pe.

```
Initial render   → 🟢 Component mount hua — sirf ek baar
Button click     → (kuch nahi)
Button click     → (kuch nahi)
```

Empty array unique hai kyunki koi value change nahi ho sakti. React decide karta hai — "yeh effect sirf mount pe chalega, kabhi wapas nahi."

---

**Case 2 — With Value `[count]`: Sirf Count Change Pe Chale**

```tsx
useEffect(() => {
  console.log("🔄 Count change hua:", count);
}, [count]);  // sirf count change hone pe chale
```

```
Initial render   → 🔄 Count change hua: 0
Button click     → 🔄 Count change hua: 1
Button click     → 🔄 Count change hua: 2
```

Effect sirf count change pe chal raha hai — baaki kisi bhi state change pe nahi. Ek input daalo jo `text` set karta hai — text change karo, effect nahi chalega. Sirf count button dabane pe chalega. Dependency array ne effect ko count ki limit kar diya.

---

**Case 3 — No Array: Har Render Pe (Rare, Avoid)**

```tsx
useEffect(() => {
  console.log("Har render pe chalta hoon");
});  // no array = har baar
```

Yehi wala case tha Step 3 mein — dependency array diya hi nahi. Usually avoid karo, kyunki infinite loop ka khatra rahta hai (baad mein dekhenge).

---

**Nutshell:** Dependency array `[dep1, dep2]` useEffect ko batata hai ki "yeh effect tabhi re-run karo jab in values mein se koi change ho." Empty array `[]` = sirf mount pe. Koi array nahi = har render pe (avoid).

## Step 5 — Cleanup Function: Gandaai Saaf Karna

Aur ek baat jo main bhool gaya tha pehle — cleanup. Soch: Step 2 wala timer setInterval chalaya. Ab component UI se hat gaya (unmount) — jaise page change kiya ya Hide button dabaya. Lekin `setInterval` abhi bhi background mein chal raha hai. Kyun? Kyunki kisi ne use nahi bataya "band kar do." React automatically timers nahi rokta — woh sirf JSX handle karta hai.

Har second woh interval function chal raha hai, variables ko reference hold kar raha hai, resources consume kar raha hai. Aur kyunki interval kabhi khatam nahi ho raha, React ka garbage collector us memory ko free nahi kar sakta. Isko **memory leak** kehte hain — woh memory jo free honi chahiye thi component unmount hone ke baad, woh abhi bhi occupied hai. Kam ho toh chalta hai, lekin 10-20 aise timers ho toh browser slow ho jayega aur kuch seconds mein pura page hang.

`useEffect` ka setup function ek cleanup function return kar sakta hai. React ise:
- Unmount hone pe chalata hai
- Effect re-run se pehle bhi chalata hai (purane effect ko clean karke naya chalata hai)

```tsx
useEffect(() => {
  console.log("⏱️ Timer setup");
  const id = setInterval(() => {
    console.log("⏰ Tick");
  }, 1000);

  return () => {
    console.log("🧹 Cleanup — timer hata rahe hain");
    clearInterval(id);
  };
}, []);
```

<details>
<summary>⚡ clearInterval(id) — yeh kya kar raha hai?</summary>

Step 2 mein dekha tha — `setInterval` ek unique number (ID) return karta hai. Woh ID us interval ka "remote code" hota hai.

```js
const id = setInterval(() => { ... }, 1000);
// id = koi number, jaise 7

clearInterval(id);  // Remote ka OFF button — band kar do
```

Yahan `clearInterval(id)` ka matlab: "jis interval ka ID `id` hai, use band kar do." Agar `clearInterval` nahi kiya, toh interval infinite chalega — chahe component screen pe ho ya nahi. Isi ko kehte hain **memory leak**.

React ka garbage collector automatically `setInterval` ko nahi rok sakta — kyunki browser JavaScript engine ko pata nahi hai ki "yeh interval ab nahi chahiye." Toh hume khud `clearInterval` call karna padta hai. Cleanup function ka yahi kaam hai.
</details>

Pehle `[]` hai — sirf mount pe setInterval chalega. Unmount pe cleanup chalega.

Try kar browser mein:
1. Component mount hua → "⏱️ Timer setup" + har second "⏰ Tick"
2. Component unmount karo (conditional rendering se hide karo) → "🧹 Cleanup — timer hata rahe hain"
3. Timer ab background mein nahi chal raha

**Visibility Toggle — visually verify cleanup kaam kar raha hai**

Ab cleanup samajh aa gaya. Lekin visually kaise dekhein ki unmount pe cleanup chal raha hai? Conditional rendering se component hide/show karte hain — jab component UI se hat ta hai, cleanup chalna chahiye.

Chal banate hain ek simple toggle — button dabao, Timer show/hide. Timer show hai toh button "Hide Timer" dikhayega, hide hai toh "Show Timer". Jab Timer hide ho, uska cleanup chalna chahiye.

**Step 1 — Sirf button banao, koi logic nahi:**

Pehle hum sabse simple version banayenge — sirf ek button. Koi state nahi, koi click handler nahi, bas UI ka skeleton. Kyun? Kyunki pehle confirm karna hai ki button screen pe aa raha hai, layout sahi hai. Phir uske upar ek-ek cheez add karenge. Maine bhi pehle seedha final code likhne lagta tha, phir kuch na kuch toot jaata tha — ab pehle static bana ke check karta hoon, phir aage badhta hoon.

```tsx
function TimerApp() {
  return (
    <div>
      <button>Show Timer</button>
    </div>
  );
}
```

Bas itna code. Browser mein dekh lo — button aa raha hai? Text "Show Timer" dikh raha hai? ✅

**Step 2 — Button ka text dynamic karo (ternary check):**

Ab button ka text change hona chahiye — kabhi "Show Timer" dikhe, kabhi "Hide Timer". Iske liye ternary operator use karenge. Pehle manually check karte hain ternary sahi chal raha hai ki nahi — abhi state nahi daal rahe, sirf hardcode karte hain `true`:

Soch: "Agar true hai toh 'Hide' dikhao, false hai toh 'Show' dikhao — chal syntax check karte hain."

```tsx
function TimerApp() {
  return (
    <div>
      <button>{true ? "Hide" : "Show"} Timer</button>
    </div>
  );
}
```

`{true ? "Hide" : "Show"}` — abhi `true` hardcode kiya hai toh hamesha "Hide Timer" dikhega. Browser mein dekh — button "Hide Timer" show kar raha hai. Ternary kaam kar raha hai, syntax samajh aa gaya. ✅

**Step 3 — State + click handler add karo toggle ke liye:**

Ab asli toggle karna hai — button click pe text change ho. Jab user click karega, "Show Timer" se "Hide Timer" ho jaaye aur wapas click kare toh ulta.

Iske liye state chahiye. Kyun? Dekho — button click hone ke baad React ko pata hona chahiye ki "UI change karna hai." React tabhi re-render karta hai jab koi state change hoti hai. Toh hum ek boolean state rakhenge — `showTimer` — jo batayega ki abhi Timer visible hai ya nahi.

```tsx
function TimerApp() {
  const [showTimer, setShowTimer] = useState(false);

  return (
    <div>
      <button onClick={() => setShowTimer(!showTimer)}>
        {showTimer ? "Hide" : "Show"} Timer
      </button>
    </div>
  );
}
```

`useState(false)` — `false` isliye kyunki shuru mein Timer hidden hai. `!showTimer` — click karne par current value ka opposite set kar do. Click → `false` se `true`, phir click → `true` se `false`.

Browser mein check karo — button dabao, text toggle ho raha hai? Haan. ✅

**Step 4 — Timer component banao + TimerApp mein render karo:**

Ab Timer component banate hain. Sirf UI abhi — seconds count dikhayega, static 0 rahega. Baad mein isme setInterval daalenge.

```tsx
function Timer() {
  return <p>Timer: 0s</p>;
}
```

Ab isse TimerApp mein render karte hain — call karo TimerApp ke andar:

```tsx
function TimerApp() {
  const [showTimer, setShowTimer] = useState(false);

  return (
    <div>
      <button onClick={() => setShowTimer(!showTimer)}>
        {showTimer ? "Hide" : "Show"} Timer
      </button>
      <Timer />
    </div>
  );
}
```

Browser mein dekh — "Timer: 0s" dikh raha hai neeche? Button toggle bhi kaam kar raha hai? ✅

**Step 5 — Conditional rendering: button se mount/unmount karo:**

Abhi `<Timer />` hamesha render ho raha hai — chahe button "Show" pe ho ya "Hide" pe. Lekin hum chahte hain ki sirf jab "Show Timer" dabaye tab dikhe. Toh conditional rendering daalte hain — jab `showTimer = true` ho tabhi render ho, warna nahi.

```tsx
function TimerApp() {
  const [showTimer, setShowTimer] = useState(false);

  return (
    <div>
      <button onClick={() => setShowTimer(!showTimer)}>
        {showTimer ? "Hide" : "Show"} Timer
      </button>
      {showTimer && <Timer />}
    </div>
  );
}
```

`{showTimer && <Timer />}` — JavaScript logical AND. Jab `showTimer` true hai, `<Timer />` render hoga. Jab false hai, React DOM se hata dega — yahi unmount hai.

Browser mein check karo: "Show Timer" dabao → Timer dikhe. "Hide Timer" dabao → Timer gayab. Mount + unmount kaam kar raha hai. ✅

**Step 6 — Timer component mein seconds state add karo:**

Ab Timer ko static "0s" dikhane ki jagah real seconds count karna hai jo har second increment ho. Iske liye state chahiye — `useState` se `seconds` rakhenge. Kyun? Kyunki value change hogi har second aur React ko re-render karna hoga.

```tsx
function Timer() {
  const [seconds, setSeconds] = useState(0);

  return <p>Timer: {seconds}s</p>;
}
```

Abhi `seconds` hamesha 0 hi rahega — kyunki koi increment karne wala code nahi hai. Screen pe "Timer: 0s" dikhega. ✅

**Step 7 — Bina useEffect ke try karo — problem feel karo:**

Ab `seconds` ko increment karna hai har second. Chal pehle bina useEffect ke seedha component mein setInterval daal ke dekhte hain:

```tsx
function Timer() {
  const [seconds, setSeconds] = useState(0);
  setInterval(() => {
    setSeconds(seconds + 1);
  }, 1000);
  return <p>Timer: {seconds}s</p>;
}
```

Browser mein dekh — seconds increment ho raha hai? Haan, 1, 2, 3... lagta hai kaam kar raha hai. ✅ Lekin ruko — yeh dhokha hai.

**Problem kya hai?** Har baar component render hota hai, ek **naya** setInterval banta hai. Purana interval kabhi clear nahi hota. Matlab:

```
Render 1 → interval #1 bana  (seconds = 0)
Render 2 → interval #2 bana  (seconds = 0, purana #1 abhi bhi chal raha)
Render 3 → interval #3 bana  (seconds = 0, #1, #2, #3 teeno chal rahe)
...
Render 30 → 30 intervals ek saath chal rahe hain
```

Console mein `console.log("interval bana")` daal ke dekh — har render pe print ho raha hai. Seconds bhi fast increment ho raha hai kyunki multiple intervals ek saath `setSeconds(0 + 1)` kar rahe hain — sab 0 daal rahe hain toh 1 hi rahega, lekin CPU waste ho raha hai.

Aur "Hide Timer" dabao — component unmount ho gaya. Lekin saare 30 intervals abhi bhi background mein chal rahe hain — memory leak. Browser slow ho jayega.

**Yeh wahi problem hai jo Step 2 mein dekhi thi** — side effect ko render cycle ke andar nahi likhna chahiye. React ke render cycle ke bahar handle karna padta hai.

**Step 8 — useEffect add karo — side effect ko render cycle se alag karo:**

Pehle do cheezein clear kar leta hoon — **mount** aur **render** mein kya fark hai:

- **Render** = component function chalna. Har baar jab state/prop change hoti hai, component function dobara chalta hai. Use kehte hain re-render.
- **Mount** = component **pehli baar** screen pe aata hai. Mount pe bhi render hota hai (first render), lekin har render mount nahi hota.

```
Mount → Render hota hai (first time)
State change → Render hota hai (re-render) → Mount nahi hai
```

**Ab Step 7 wala code yaad karo** — `setInterval` component ke andar seedha likha tha. Matlab har render pe woh line chalegi. Mount pe chali, state change hui → re-render hua → phir chali, phir state change → phir re-render → phir chali... Har render pe ek naya interval banta gaya.

`useEffect` is problem ko solve karta hai. `useEffect(fn, [])` ka matlab: fn ko **sirf mount pe** chalao (first render ke baad), state change ho toh wapas mat chalao. `[]` ki vajah se React ko lagta hai "kuch bhi track nahi karna, sirf ek baar chala do."

```tsx
function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setSeconds(seconds + 1);
    }, 1000);
  }, []);
  // [] → React: "sidha sidha ek baar chala do, condition nahi hai"

  return <p>Timer: {seconds}s</p>;
}
```

**Fark console mein dekho:**

| Scenario | Bina useEffect (Step 7) | useEffect + `[]` (Step 8) |
|---|---|---|
| Mount pe | "interval bana" ✅ | "interval bana" ✅ |
| State change → re-render | Phir "interval bana" ❌ ek aur interval | Kuch nahi ✅ sirf ek interval |
| 10 re-render ke baad | 11 intervals chal rahe | Sirf 1 interval ✅ |
| Unmount karo | Saare 11 background mein | Cleanup limiter ✅ |

Console mein `console.log("interval bana")` daal ke dekh — Step 7 mein har baar print ho raha tha, Step 8 mein sirf ek baar.

Lekin browser mein timer dekho — **1 pe atak gaya hai?** 1, 2, 3 nahi ja raha. Hamesha 1 hi dikh raha hai. Yeh problem hai. Is problem ka naam hai — **Stale Closure**.

**Closure kya hota hai pehle samjho (yeh React ka feature nahi, JavaScript ka concept hai):**

Jab bhi ek function kisi variable ko use karta hai jo uske **bahar** define hua, toh woh function us variable ko "yaad" rakh leta hai. Is phenomenon ko kehte hain **closure**. Example:

```js
let count = 0;
setInterval(() => {
  console.log(count);  // yeh function bahar ke `count` ko "yaad" rakhta hai
}, 1000);
```

Yahan `setInterval` ke andar wala function bahar ke `count` ko yaad rakhta hai. Agar `count` change ho, toh yeh naya value dekhta hai kyunki `let` variable hai.

**Lekin React mein kya hota hai?**

Har render ek naya local `seconds` variable banta hai. Mount pe render hua → `seconds = 0` wala variable bana. `useEffect` ne `setInterval` ko us waqt ke `seconds` wale variable ke saath bana diya. Ab React `seconds = 1` with naya variable bana deta hai kyunki state change hui. Lekin `setInterval` ke andar wala function abhi bhi **purane** `seconds = 0` wale variable ko refer kar raha hai.

```
Mount → seconds = 0 wala variable born
        ↓
useEffect chal → setInterval function bana → usne seconds = 0 "capture" kar liya
        ↓
State change hui (setSeconds)
        ↓
Naya render → seconds = 1 wala naya variable bana (purana seconds ab exist nahi karta)
        ↓
SetInterval abhi bhi purane 0 wale variable pe stuck hai
        ↓
setSeconds(0 + 1) → 1 hi set hota rahega
```

**Stale Closure = function ne purani value capture kar li.** Stale = purani/basi. Closure = capture karna. Matlab function ne value capture toh kar li lekin woh ab purani (stale) ho gayi.

**Fix — `seconds` ko direct use mat karo, React se latest value maango:**

Pehle yeh samjho ki `setSeconds` do tarah kaam kar sakta hai:

**Normal tareeka (Batch 1 wala):** `setSeconds(5)` → sidha value set

**Naya tareeka — function do:** `setSeconds(prev => prev + 1)`

`setSeconds` ko function dene par React andar kuch aisa karta hai:

```js
// React ke andar (imaginary code — actual implementation different hai, concept samjho)
let currentState = 0;  // seconds ka current value React ke internal storage mein

function setSeconds(valueOrFunction) {
  if (typeof valueOrFunction === 'function') {
    // Agar function diya → React use CALL karta hai, aur current state as argument deta hai
    const result = valueOrFunction(currentState);  // React khud currentState provide karta hai
    currentState = result;
  } else {
    // Sirf value diya → sidha set
    currentState = valueOrFunction;
  }
}
```

Dono tarah se call karke dekho:

```js
setSeconds(5); // else branch → currentState = 5 ✅

// ab function do:
setSeconds(function(prev) {   // React ne prev = 5 provide kiya (currentState ki value)
  return prev + 1;
}); // function branch → valueOrFunction(currentState) → currentState = 6 ✅
```

`prev` React ka internal variable hai — React khud latest `currentState` use provide karta hai. Naam kuch bhi de sakte ho: `prev`, `s`, `current` — sab kaam karega:

```js
setSeconds(s => s + 1);             // same thing
setSeconds(current => current + 1); // same thing
```

**Pair kya capture ho raha hai (stale closure kyun nahi):**

| Code | Kya ho raha | Problem? |
|---|---|---|
| `setSeconds(seconds + 1)` | `seconds` variable capture → 0 | Stale closure ❌ |
| `setSeconds(prev => prev + 1)` | Koi variable capture nahi. Sirf `setSeconds` capture ho raha jo stable hai. `prev` React deta hai runtime pe | ✅ |

Timer ka poora code ab:

```tsx
function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setSeconds((prev) => prev + 1);
    }, 1000);
  }, []);

  return <p>Timer: {seconds}s</p>;
}
```

Browser mein dekh — timer kaise chal raha hai?

Ruko... **0, 2, 4, 6** ja raha hai? Har second do-do increment ho raha hai? Yeh koi bug nahi hai — yeh **React StrictMode** ka effect hai.

**StrictMode kya hai?** Jab tumne Vite se project banaya tha (Batch 1, *1.0 React Project Structure.md*), `main.tsx` mein `<StrictMode>` wrapper hota hai. Development mein StrictMode component ko **do baar mount** karta hai: **mount → unmount → remount**. Iska purpose hai side-effect bugs ko early catch karna.

Ab dekho kya ho raha hai:

```
Pehla mount  → setInterval bana (id = 1)
StrictMode ne unmount kiya → ❌ par clearInterval nahi hua (cleanup nahi likha)
StrictMode ne remount kiya → doosra setInterval bana (id = 2)
Ab DO interval chal rahe hain → dono setSeconds(prev => prev + 1)
Result → counter 2-2 increment ho raha → 0, 2, 4, 6...
```

`useEffect(() => {...}, [])` sirf mount pe chalta hai — lekin cleanup nahi likha toh pehla interval zinda reh gaya. Jab StrictMode ne component ko unmount karke remount kiya, pehla interval abhi bhi background mein tick kar raha tha. Remount pe naya interval bana — ab do interval parallel mein daud rahe hain. Isliye counter do-guna speed se badh raha hai.

**Achhi baat:** StrictMode ne humein dikha diya ki cleanup nahi likha hai. Yeh iska kaam hai — bugs ko surface karna. Production mein StrictMode kuch nahi karta extra.

Is problem ka solution hai **cleanup function** — jo useEffect hamesha return kar sakta hai. React cleanup ko unmount hone par aur remount se pehle call karta hai. Toh agar hum `clearInterval(id)` cleanup mein daal denge, pehla interval remount se pehle band ho jayega — aur sirf ek interval chalega.

Chalo Step 9 mein implement karte hain.

**Toh useEffect ka asli kaam:** side effect ko render cycle se alag karna. Sirf mount pe chalao (dependency array se). Aur cleanup ka rasta deta hai — jo ab Step 9 mein detail mein dekhenge.

**Step 9 — Cleanup add karo — unmount pe interval band karo:**

Ab Step 8 wali problem dekhi — StrictMode ki wajah se 0, 2, 4, 6 ja raha tha. Aur ek aur problem hai — "Hide Timer" dabao, component unmount ho gaya. Lekin setInterval abhi bhi background mein chal raha hai. Memory leak. **Dono problems ka ek hi solution: cleanup function.** useEffect se cleanup function return karte hain:

```tsx
function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setSeconds((prev) => prev + 1);
    }, 1000);

    return () => clearInterval(id);
  }, []);

  return <p>Timer: {seconds}s</p>;
}
```

`return () => clearInterval(id)` — jab component unmount hoga, yeh chalega aur interval band kar dega.

**Observe karo browser mein:**
1. "Show Timer" dabao → Timer mount → setInterval shuru → seconds increment hota rahega
2. "Hide Timer" dabao → Timer unmount → `clearInterval(id)` chalega → interval band → koi increment nahi
3. "Show Timer" firse dabao → naya mount → naya setInterval shuru → timer 0 se shuru
4. **Ab StrictMode ke bawajood** sirf ek interval chal raha hai — kyunki cleanup ne pehle wale interval ko remount se pehle band kar diya. Counter ab 1, 2, 3... sahi se increment ho raha hai ✅

Notice kiya? Jab component unmount hua, `clearInterval(id)` chal gaya — timer band. Jab wapas mount hua, naya interval shuru. Is tarah memory leak nahi hoti.

> **What It Is NOT:** Cleanup function sirf unmount pe nahi chalata — re-run pe bhi chalata hai. Jab dependencies change hoti hain, pehle purane effect ka cleanup chalta hai, phir naya setup. Isko useEffect ka "reset" mechanism samjho.

**Nutshell:** Cleanup function ek regular function hai jo `useEffect` ke setup function se return hota hai. React ise component unmount hone par aur effect re-run se pehle call karta hai — resources (timers, subscriptions, listeners) ko saaf karne ke liye.

### useEffect with Timer + Cleanup

Timer chahiye jo har second timeLeft decrement kare — lekin sirf jab isRunning true ho.

useEffect(() => {

## Step 7 — useEffect Recap: Kab Kaunsa Pattern Use Karein

| Dependency Array | Kab Chalega | Use Case |
|---|---|---|
| `[]` (empty) | Sirf mount pe | Initial API fetch, third-party setup |
| `[dep1, dep2]` | Mount pe + jab dep change ho | Sync with state/props |
| Kuch nahi | Har render pe (rare) | Debug/logging (avoid in production) |

### What It Is NOT

- `useEffect` **data fetching ka solution nahi hai** — yeh sirf ek tool hai. TanStack Query/SWR better hain (agle doc mein dekhenge).
- `useEffect` **synchronous nahi hai** — render ke baad chalta hai. Matlab pehle JSX DOM mein jayega (user screen pe dekhega), phir effect chalega. Isliye user ko koi "flash" (jaise loading spinner ke baad content achanak dikhe) nahi dikhta — kyunki jab tak effect chalta hai, DOM already ready hai.
- Dependency array ko "optimization" mat samjho — yeh **behavior definition** hai. Reactive value andar use ho toh array mein aani chahiye, chahe performance pe fark pade ya na.

---

## Common Mistakes

1. **Dependency array bhoolna** — `useEffect(() => { ... })` bina array ke har render pe chalega, infinite loop causes.
2. **Cleanup bhoolna** — `setInterval` / `addEventListener` ko cleanup na karein toh memory leak. Hamesha `return () => clearInterval(id)` karo.
3. **useEffect ko async banana** — `useEffect(async () => { ... })` galat hai. Kyun? `useEffect` ka pehla argument ek function expect karta hai jo ya toh kuch return na kare (void) ya ek cleanup function return kare. `async` function hamesha ek Promise return karta hai — cleanup function nahi. React Promise ko cleanup ki tarah treat karega toh kaam nahi karega. Toh solution: async function andar define karo aur call karo:
   ```tsx
   useEffect(() => {
     async function fetchData() {
       const data = await api.get(...);
     }
     fetchData();
   }, []);
   ```
4. **Stale closure** — Agar `count` andar use ho rahi hai lekin `[]` diya, toh effect sirf mount pe chalega. Mount ke time jo `count` ka value tha (0), woh closure mein capture ho gaya. Ab `count` change hone ke baad bhi, effect wapas nahi chalega kyunki `[]` hai — andar wala `count` hamesha 0 hi rahega. Isliye rule: **jo reactive value andar use ho, woh dependency array mein aani chahiye.**

## Summary

| Concept | Samajh |
|---|---|
| Side Effect | Render cycle ke bahar ka code — timer, API, browser API |
| `useEffect(fn, [deps])` | Render ke baad fn chalata hai; deps change pe re-run |
| Cleanup Function | Return karo `fn` se — component unmount/effect re-run pe chalta hai |
| Empty `[]` | Sirf mount pe effect chale |
| `[dep]` | Mount + dep change pe chale |
| No array | Har render ke baad (rare) |
