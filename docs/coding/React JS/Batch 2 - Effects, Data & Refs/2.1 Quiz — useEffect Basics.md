
## MCQ

Q: `useEffect` hook ke do arguments kya hote hain?
A. Setup function aur dependency array — setup render ke baad chalta hai, deps control karte hain kab re-run
B. Callback function aur delay — setInterval ki tarah time interval set hota hai effect ke liye
C. Component name aur props — component ko React ke lifecycle mein register karne ke liye
D. State variable aur setter — effect ke andar state manage karne ka alternative syntax hai
> A. `useEffect(fn, [deps])` — pehla argument setup function hai jo side effect code contain karta hai. Doosra dependency array hai jo batata hai ki effect kab re-run karna hai. Setup function render ke baad execute hota hai.

---

Q: `useEffect` component ke lifecycle mein kab execute hota hai?
A. Component render hone se pehle — DOM update se pehle hi side effect chalta hai
B. Render ke turant baad — DOM update hone ke baad useEffect ka setup function chalta hai
C. Sirf component unmount hone par — jab component UI se hat raha hai tab chalta hai
D. Jab bhi koi state update hoti hai — render chale ya nahi, har setState pe chalta hai
> B. `useEffect` render ke baad chalta hai. Order: component function chal → JSX return → DOM update → useEffect setup execute. Is pattern ko kahte hain "render-first verification" — pehle screen ready, phir side effect.

Q: Side effects kya hote hain React ke context mein?
A. React component ke andar CSS styling aur animations jo visual effect dete hain
B. Woh operations jo render cycle ke bahar jaate hain — timer, API call, browser API, localStorage
C. React component ke props mein changes jo children components ko affect karte hain
D. Woh effects jo user interaction se trigger hote hain — button click, form submit, hover
> B. Side effects woh operations hain jo React ke render cycle ke bahar kaam karte hain — `setInterval`, `fetch`, `localStorage`, `document.title`. React ka render cycle same props + same state = same JSX guarantee karta hai, lekin side effects is purity ko todte hain kyunki external systems se interact karte hain.

Q: Empty dependency array `[]` wala useEffect kab chalega?
A. Har render ke baad — empty ka matlab koi restriction nahi, har baar chalega
B. Sirf mount pe — component jab pehli baar screen par aata hai, tab ek baar chalega
C. Jab bhi koi state change hoti hai — React automatically detect karta hai ki kis state ki zaroorat hai
D. Kabhi nahi chalega — empty array ka matlab React ko lagta hai ki effect disable hai
> B. `[]` ka matlab hai "sirf mount pe chalao." React track karta hai ki empty array mein koi value nahi hai jo change ho sakti hai — isliye effect sirf ek baar chalta hai. Button click ya state change se wapas nahi chalega.

Q: `useEffect(() => { setCount(count + 1) }, [count])` — yeh infinite loop karega ya nahi?
A. Nahi karega — useEffect sirf ek baar chalta hai chahe dependency kuch bhi ho
B. Karega — count change → effect re-run → count increment → effect re-run → count increment...
C. Sirf agar count ki initial value 0 hai tab loop karega, otherwise nahi
D. Nahi karega kyunki `setCount` React ka internal function hai — dependency array mein nahi aata
> B. Yeh infinite loop karega. `[count]` ka matlab hai "count change pe re-run." Effect ke andar `setCount(count + 1)` hai jo count increment karta hai. Count increment → effect re-run → count increment → effect re-run... Chain reaction. Is pattern se bachna chahiye.

Q: Cleanup function `useEffect` mein kab execute hota hai?
A. Sirf component unmount hone par — jab component UI se completely hat raha hai tab
B. Sirf jab component mount hota hai — pehli baar render ke baad cleanup chalta hai
C. Unmount hone par aur effect re-run se pehle — dono scenarios mein cleanup call hota hai
D. Cleanup function kabhi automatic nahi chalta — developer ko khud call karna padta hai
> C. React cleanup function ko do cases mein call karta hai: (1) Component unmount hone par — resources saaf karne ke liye. (2) Effect re-run se pehle — purane effect ka cleanup karke naya setup chalane ke liye. Cleanup ensure karta hai ki koi resource (timer, subscription) zinda na rahe.

Q: Stale closure kya hota hai useEffect ke saath?
A. Jab ek component unmount ho jata hai lekin usme state update karne ka attempt hota hai — React error deta hai
B. Jab useEffect ka function closure mein purani render ki variable value capture kar leta hai aur nayi value use nahi karta
C. Jab dependency array mein bahut zyada values daal di jaayein — React perform karne mein slow ho jata hai
D. Jab cleanup function likhna bhool jaayein — timer ya listener background mein chalte rehte hain
> B. Stale closure tab hota hai jab `useEffect` ke andar ka function purane render ke variable ko "capture" kar leta hai (JavaScript closure). Mount pe `seconds = 0` capture hua, phir state change ke baad naya render hua jisme `seconds = 1` hai lekin function abhi bhi `seconds = 0` refer kar raha hai. `setTimeout` / `setInterval` ke saath yeh common problem hai.

Q: Stale closure fix karne ka sahi tarika kya hai timer ke saath?
A. Timer ko component ke bahar global scope mein define karo — closure problem automatically solve ho jayegi
B. Variable ko `var` se declare karo — JavaScript hoisting latest value provide karegi
C. Functional update use karo — `setSeconds(prev => prev + 1)` — React khud latest value provide karta hai
D. `useEffect` ko `async` bana do — async functions closure problem fix kar dete hain
> C. Functional update `setSeconds(prev => prev + 1)` stale closure fix karta hai. Isme `prev` React ke internal storage se aata hai — jo bhi latest state hai, woh `prev` ke through milti hai. Koi external variable capture nahi ho raha. Sirf `setSeconds` function capture ho raha hai jo har render mein stable rehta hai.

Q: `setInterval(() => console.log("Tick"), 1000)` kya return karta hai?
A. Ek boolean — `true` agar interval successfully setup ho gaya, `false` agar component unmount ho gaya
B. Ek string — interval ka unique naam jo browser memory mein store hota hai
C. Ek numeric ID — interval ka unique identifier, `clearInterval(id)` band karne ke liye use hota hai
D. Ek function object — jisme interval cancel karne ka method attached hota hai directly
> C. `setInterval` ek numeric ID return karta hai (jaise 1, 2, 3...). Yeh ID us interval ka "identity card" hai. Jab interval band karna ho, `clearInterval(id)` mein yeh ID pass karte hain. Agar ID store nahi kiya toh interval kabhi band nahi ho sakta — isko kehte hain memory leak.

Q: `<StrictMode>` development mein `useEffect` ke saath kya special behaviour dikhata hai?
A. StrictMode `useEffect` ko production build mein bhi double mount karta hai — saari jagah side effects check karne ke liye
B. StrictMode component ko mount → unmount → remount karta hai development mein — cleanup bugs expose karne ke liye
C. StrictMode dependency array auto-fill kar deta hai — jo bhi state andar use ho rahi hai woh add ho jaati hai
D. StrictMode `useEffect` ko synchronously execute karta hai — render ke pehle chalata hai fast checking ke liye
> B. StrictMode development mein component ko intentionally double mount karta hai (mount → unmount → remount). Iska purpose: agar cleanup bhool gaye ho (jaise `clearInterval` nahi kiya), toh StrictMode expose kar deta hai. Example — timer 2x speed (0, 2, 4, 6) chal raha hai: yeh signal hai ki cleanup missing hai.

## TrueFalse

Q: `useEffect` render complete hone se pehle chalta hai — DOM update se pehle side effect execute hota hai.
- True
- False
> False. `useEffect` render ke baad chalta hai. Order hota hai: component function execute → JSX return → DOM update → `useEffect` setup call. Agar `useEffect` render se pehle chalta toh DOM access safe nahi hota — `DOMContentLoaded` event ki tarah yeh ensure karta hai ki DOM ready hai.

---

Q: Empty dependency array `[]` wala `useEffect` har render ke baad chalta hai kyunki array mein koi value nahi hai.
- True
- False
> False. Empty array `[]` ka matlab hai "sirf mount pe chalao." React dekhta hai ki array mein koi value nahi jo kabhi change ho sakti hai — isliye effect sirf ek baar chalega. Har render pe chalane ke liye dependency array dena hi nahi chahiye — `useEffect(() => {...})` bina array ke.

---

Q: Cleanup function sirf component unmount hone par call hota hai, re-run se pehle nahi.
- True
- False
> False. Cleanup function do cases mein call hota hai: (1) Component unmount hone par — resources release karne ke liye. (2) Effect re-run se pehle — purane effect ka cleanup karke naya setup chalane ke liye. Jab `[count]` diya hai aur count change hota hai, pehle cleanup chalta hai, phir naya effect.

---

Q: Dependency array sirf performance optimization ke liye hai — iska behavior par koi asar nahi hota.
- True
- False
> False. Dependency array behavior define karta hai — "yeh effect kab chalega." `[]` = sirf mount pe. `[count]` = mount + count change pe. No array = har render pe. Yeh optimization nahi, behavior definition hai. Jo reactive value andar use ho, woh dependency mein aani chahiye — chahe performance pe fark pade ya na.

---

Q: `useEffect(async () => { await fetchUsers() }, [])` — yeh async function sahi tarika hai useEffect likhne ka.
- True
- False
> False. `useEffect` ka pehla argument ek function expect karta hai jo ya toh `void` return kare ya cleanup function return kare. `async` function hamesha ek `Promise` return karta hai — cleanup function nahi. React `Promise` ko cleanup treat nahi kar sakta. Solution: async function andar define karo aur call karo.

---

Q: Bina cleanup ke `setInterval` component unmount hone ke baad bhi background mein chal sakta hai — memory leak cause karta hai.
- True
- False
> True. Agar `useEffect` mein `setInterval` chalaya aur cleanup mein `clearInterval` nahi kiya, toh component unmount hone ke baad bhi interval background mein chal raha hai. React automatically timers nahi rokta. Interval ka reference memory mein stuck ho jata hai — garbage collector use free nahi kar sakta. Isi ko memory leak kehte hain.

## ShortAnswer

Q: `useEffect` ke dependency array ke 3 cases explain karo. Har case kab chalega, use case kya hai, aur example do.

<details>
<summary>Sample Answer</summary>

**Case 1 — Empty Array `[]`: Sirf Mount Pe**
- **Kab chalega:** Sirf jab component pehli baar screen par aata hai (mount), uske baad kabhi nahi
- **Use case:** Initial API fetch, third-party library setup, timer start karna
- **Example:** `useEffect(() => { fetchUsers() }, [])`

**Case 2 — With Value `[count]`: Mount + Dep Change Pe**
- **Kab chalega:** Mount pe + jab bhi `count` ki value change hoti hai
- **Use case:** Kisi state ya prop ke saath sync karna, document.title update karna
- **Example:** `useEffect(() => { document.title = `${count} new messages` }, [count])`

**Case 3 — No Array: Har Render Ke Baad (Rare)**
- **Kab chalega:** Har render ke baad (mount + har state/prop change)
- **Use case:** Sirf debugging/logging. Production mein avoid karo
- **Example:** `useEffect(() => { console.log("Component rendered") })` — koi array nahi diya

**Rule of thumb:** Jo bhi reactive value (state/prop) `useEffect` ke andar use ho rahi hai, woh dependency array mein aani chahiye. Agar andar `count` use kiya lekin `[]` diya, toh stale closure hogi — effect hamesha mount waali `count` (0) hi dekhega.

</details>

Q: Stale closure kya hai? `useEffect` ke saath yeh problem kaise hoti hai aur functional update (`setX(prev => prev + 1)`) ise kaise fix karta hai? Code ke saath explain karo.

<details>
<summary>Sample Answer</summary>

**Stale Closure kya hai?**

Ek function jab apne bahar ke variable ko "capture" kar leta hai (closure), lekin baad mein variable change hone ke baad bhi function purani (stale) value refer karta rahe — ise stale closure kehte hain.

**useEffect mein problem:**

```tsx
function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setSeconds(seconds + 1);  // ❌ seconds = 0 capture ho gaya
    }, 1000);
  }, []);

  return <p>Timer: {seconds}s</p>;
}
```

**Kya ho raha hai:**
1. Mount → `seconds = 0` wala variable bana
2. `useEffect` chal → `setInterval` ne `seconds = 0` capture kar liya
3. `setSeconds(0 + 1)` → seconds 1 → re-render
4. Re-render mein naya `seconds = 1` wala variable bana
5. Par `setInterval` abhi bhi `seconds = 0` refer kar raha hai
6. `setSeconds(0 + 1)` → barabar 1 hi set hota rahega
7. Timer 1 pe atak gaya ❌

**Fix — Functional Update:**

```tsx
useEffect(() => {
  const id = setInterval(() => {
    setSeconds((prev) => prev + 1);  // ✅ Koi variable capture nahi
  }, 1000);
  return () => clearInterval(id);
}, []);
```

**Kyun fix karta hai?**
- `prev` React khud provide karta hai — jo bhi latest state hai, woh `prev` ke through aati hai
- Sirf `setSeconds` function capture ho raha hai — jo React ka stable function hai
- Koi external variable capture nahi ho raha, isliye stale closure ka issue nahi

**Comparison:**

| Code | Kya ho raha | Problem? |
|---|---|---|
| `setSeconds(seconds + 1)` | `seconds` variable capture → 0 | Stale closure ❌ |
| `setSeconds(prev => prev + 1)` | Koi variable capture nahi, `prev` React deta hai | ✅ |

</details>

Q: Countdown Timer app ka code likho jo `useEffect`, cleanup function, aur dependency array ko demonstrate kare. Set, Start, Pause, Reset buttons ke saath.

<details>
<summary>Sample Answer</summary>

```tsx
import { useState, useEffect } from "react";

function CountdownApp() {
  const [timeLeft, setTimeLeft] = useState(0);
  const [isRunning, setIsRunning] = useState(false);
  const [initial, setInitial] = useState(10);

  // Timer effect — sirf tab chale jab isRunning true ho
  useEffect(() => {
    if (!isRunning) return;
    const id = setInterval(() => {
      setTimeLeft((prev) => {
        if (prev <= 1) {
          setIsRunning(false);
          return 0;
        }
        return prev - 1;
      });
    }, 1000);
    return () => clearInterval(id);  // unmount ya re-run pe cleanup
  }, [isRunning]);

  // Time up detection
  useEffect(() => {
    if (timeLeft === 0 && isRunning) {
      setIsRunning(false);
      alert("Time's up! 🛎️");
    }
  }, [timeLeft, isRunning]);

  return (
    <div>
      <h1>Countdown: {timeLeft}s</h1>
      <input
        type="number"
        value={initial}
        onChange={(e) => setInitial(Number(e.target.value))}
      />
      <button onClick={() => { setTimeLeft(initial); setIsRunning(false); }}>
        Set
      </button>
      <button onClick={() => setIsRunning(true)} disabled={isRunning || timeLeft <= 0}>
        Start
      </button>
      <button onClick={() => setIsRunning(false)} disabled={!isRunning}>
        Pause
      </button>
      <button onClick={() => { setTimeLeft(0); setIsRunning(false); }}>
        Reset
      </button>
    </div>
  );
}
```

**Key concepts used:**
- `useEffect` with `[isRunning]` — timer sirf chale jab isRunning true ho, pause pe cleanup ho jaye
- Functional update `setTimeLeft(prev => ...)` — stale closure se bacha
- Cleanup `clearInterval(id)` — unmount / re-run pe timer band ho, memory leak na ho
- Second `useEffect` — time up detect karta hai aur alert dikhata hai

</details>
