# 2.3 — TanStack React Query

## Cheat Sheet (Quick Recall)

```ts
const { data, isLoading, isError, error } = useQuery({
  queryKey: ["recipes", query],   // unique identifier — cache isi se hota hai
  queryFn: () => fetchRecipes(query),  // actual fetch function
  staleTime: 60_000,               // data kitni der "fresh" rahega
  enabled: !!query,                // kab fetch trigger karna hai
});
```

- **`staleTime`** = freshness duration (default 0). Is time ke andar refetch nahi hoga.
- **`gcTime`** = inactive cache retention (default 5 min).
- **`isLoading`** = first fetch (no cache). **`isFetching`** = koi bhi fetch chal raha hai.
- **`queryKey`** = har query ki Aadhar card — same key = cache hit, different key = new fetch.

## Abhi Tak Kya Hua

2.2 mein Recipe Finder app manually banaya — useEffect, fetch, loading/error states, ignore pattern. Kaam karta hai, lekin boilerplate zyada hai. Har naye API feature ke liye wahi pattern repeat karna padega. Aur caching bhi nahi hai — har query change pe naya network request.

## Broader Goal

Is doc mein **TanStack React Query** (v5) seekhenge — ek library jo data fetching ko drastically simple karti hai. Recipe Finder app ko **v2** mein upgrade karenge:
- `useQuery` hook se loading/error/data — ek hi hook, zero boilerplate
- Auto-caching — same query dobara fetch nahi hogi
- Background refetching — data stale ho gaya toh auto refresh
- Race condition? Already handled

Pehle **"Manual → Better"** ka pattern follow karenge — 2.2 ka pain yaad karo, phir dekho Query kaise resolve karta hai.

## Step 2 — Provider Setup

`QueryClientProvider` component tree ke top pe hona chahiye — taaki saare components `useQuery` use kar sakein. TanStack Query apna internal state (cache, queries) manage karta hai aur `QueryClientProvider` React Context ki tarah poore app mein yeh state available karta hai.

```tsx
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 60 * 1000,    // 1 min — data "fresh" rahega
      gcTime: 5 * 60 * 1000,   // 5 min — inactive cache memory mein rahega
      retry: 1,                 // fail pe 1 baar retry
      refetchOnWindowFocus: false,
    },
  },
});

function App() {
  return (
    <QueryClientProvider client={queryClient}>
      <RecipeFinderV2 />
    </QueryClientProvider>
  );
}
```

| Option | Default | Matlab |
|---|---|---|
| `staleTime` | `0` | Data kitni der "fresh" rahega (refetch trigger nahi hoga) |
| `gcTime` | `5 * 60 * 1000` | Inactive cache kitni der rahega (pehle `cacheTime`) |
| `retry` | `3` | Fail pe kitni baar retry kare |
| `refetchOnWindowFocus` | `true` | Tab focus pe dobara fetch kare |

## Step 4 — useQuery: Data, Loading, Error — Ek Hi Hook

2.2 mein 4 useState the — recipes, isLoading, error, query. Query ke saath sirf ek hook. Socho **Zomato jaisa** — Zomato pe koi restaurant search karo to woh result dikhata hai, loading dikhata hai, error dikhata hai, aur cache bhi karta hai. TanStack Query wahi sab automatically karta hai React ke liye.

```tsx
import { useQuery } from "@tanstack/react-query";

function RecipeFinderV2() {
  const [query, setQuery] = useState("chicken");

  const {
    data: recipes,
    isLoading,
    isError,
    error,
    isFetching,
    refetch,
  } = useQuery({
    queryKey: ["recipes", query],
    queryFn: () => fetchRecipes(query),
    enabled: !!query,
  });
  // ...
}
```

**Comparison — 2.2 vs 2.3:**

| Concern | 2.2 (Manual) | 2.3 (TanStack Query) |
|---|---|---|---|
| Loading state | `useState` + manual set | `isLoading` auto |
| Error state | `useState` + try/catch | `isError` + `error` auto |
| Data | `useState` + manual set | `data` auto |
| Race condition | Ignore pattern | Auto-handled |
| Caching | No | Auto (by queryKey) |
| Refetch | Manual | Auto (staleTime) |
| Retry | No | Auto (3 tries) |

**Nutshell:** `useQuery` ek hook hai jo ek hi call mein loading, error, aur data states return karta hai. `queryKey` se caching aur deduplication handle hoti hai, `staleTime` se data freshness.

## Step 5 — Query Key: Identity Card

Query library ko kaise pata chalega ki yeh wahi query hai ya nayi? `queryKey` har query ki unique identity hai — isi key se cache hota hai, isi se refetch trigger hota hai. Jaise **Aadhar card number unique hota hai** — waisi hi identity hai `queryKey` har query ki.

```ts
// Jab query change hoti hai:
queryKey: ["recipes", "chicken"]  // 1st query
queryKey: ["recipes", "pasta"]    // 2nd query (different key, new fetch)
queryKey: ["recipes", "chicken"]  // 3rd query (same key, cached data!)
```

**Cache hit:** Agar `["recipes", "chicken"]` already fetch ho chuka hai aur stale nahi hua, toh `useQuery` cached data return karega — network call nahi.

**Nutshell:** `queryKey` ek unique array hai jo har query ki identity define karta hai. Same key = same cache. Key change = naya fetch. Cache automatically manage hoti hai — tumhe kuch nahi karna.

## Step 6 — Complete Recipe Finder v2

```tsx
import { useState } from "react";
import { useQuery } from "@tanstack/react-query";
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";

// --- Types ---
interface Recipe {
  idMeal: string;
  strMeal: string;
  strMealThumb: string;
  strCategory: string;
  strArea: string;
}

// --- Fetch function ---
async function fetchRecipes(query: string): Promise<Recipe[]> {
  const response = await fetch(
    `https://www.themealdb.com/api/json/v1/1/search.php?s=${query}`
  );
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const data = await response.json();
  return data.meals ?? [];
}

// --- QueryClient ---
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 60 * 1000,
      gcTime: 5 * 60 * 1000,
      retry: 1,
      refetchOnWindowFocus: false,
    },
  },
});

// --- Component ---
function RecipeFinderV2() {
  const [searchInput, setSearchInput] = useState("chicken");
  const [query, setQuery] = useState("chicken");

  const { data: recipes, isLoading, isError, error, isFetching } = useQuery({
    queryKey: ["recipes", query],
    queryFn: () => fetchRecipes(query),
    enabled: !!query,
  });

  const handleSearch = (e: React.FormEvent) => {
    e.preventDefault();
    setQuery(searchInput.trim());
  };

  return (
    <div style={{ padding: "20px", maxWidth: "800px", margin: "0 auto" }}>
      <h1>🍳 Recipe Finder v2</h1>
      <p style={{ fontSize: "14px", color: "#666" }}>
        Powered by TanStack Query {isFetching && "🔄 refreshing..."}
      </p>

      <form onSubmit={handleSearch}>
        <input
          type="text"
          value={searchInput}
          onChange={(e) => setSearchInput(e.target.value)}
          placeholder="Search recipes..."
          style={{ padding: "8px", width: "300px" }}
        />
        <button type="submit" style={{ padding: "8px 16px", marginLeft: "8px" }}>
          Search
        </button>
      </form>

      {isLoading && <p>⏳ Loading...</p>}
      {isError && <p style={{ color: "red" }}>❌ {error.message}</p>}
      {!isLoading && !isError && recipes?.length === 0 && (
        <p>No recipes found. Try a different search.</p>
      )}

      <div style={{ display: "grid", gridTemplateColumns: "1fr 1fr 1fr", gap: "16px", marginTop: "20px" }}>
        {recipes?.map((recipe) => (
          <div key={recipe.idMeal} style={{ border: "1px solid #ddd", borderRadius: "8px", padding: "12px" }}>
            <img src={recipe.strMealThumb} alt={recipe.strMeal} style={{ width: "100%", borderRadius: "4px" }} />
            <h3>{recipe.strMeal}</h3>
            <p>{recipe.strCategory} — {recipe.strArea}</p>
          </div>
        ))}
      </div>
    </div>
  );
}

// --- Root ---
function App() {
  return (
    <QueryClientProvider client={queryClient}>
      <RecipeFinderV2 />
    </QueryClientProvider>
  );
}
```

## Step 7 — isLoading vs isFetching

TanStack Query do alag states deta hai:

| State | Kab True Hai |
|---|---|
| `isLoading` | First time fetch — **koi cached data nahi** |
| `isFetching` | Koi bhi fetch chal raha hai (background refetch bhi) |
| `isLoading = isPending` | v5 mein `isPending` preferred hai |

**Example behavior:**
1. Pehli baar "chicken" search → `isLoading = true`, `isFetching = true`
2. Phir "pasta" search → `isLoading = true` (new key, no cache), `isFetching = true`
3. Wapas "chicken" → `isLoading = false` (cache hai), `isFetching = true` (background refetch)

## Trade-off: TanStack Query vs Alternatives

| Library | Caching | Bundle Size | Learning Curve |
|---|---|---|---|
| **TanStack Query** | ✅ Auto | ~13KB | Medium |
| **SWR** (Vercel) | ✅ Auto | ~7KB | Low |
| **RTK Query** | ✅ Auto | ~15KB (with Redux) | High |

**Kyun TanStack Query?** Caching model most flexible hai, DevTools built-in aata hai, aur React-agnostic bhi hai (Solid/Vue bhi support karta hai). SWR simpler hai lekin useMutation etc. ka ecosystem chhota hai.

## Common Mistakes

1. **`queryKey` bhoolna ya galat dena** — Key unique nahi hai toh cache collisions hongi. Hamesha `["entity", ...identifiers]` format use karo.
2. **`staleTime` ko hamesha 0 rakhna** — Default 0 hai (refetchOnMount pe hamesha fetch). Real apps mein kam se kam 30s-1min do.
3. **`isLoading` aur `isFetching` confuse karna** — `isLoading` (no cache) vs `isFetching` (any fetch including background). Dono ka use-case alag hai.
4. **Provider bhoolna** — `QueryClientProvider` wrap karna bhoologe toh `useQuery` error dega.
