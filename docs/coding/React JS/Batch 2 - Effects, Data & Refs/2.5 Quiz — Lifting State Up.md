
## MCQ

Q: Agar do sibling components ko same data chahiye, toh state kahan rakhna chahiye?
A. Kisi ek child component mein — siblings children ke through share kar sakte hain
B. Dono siblings ke common parent mein — phir props ke through dono ko data do
C. Global variable mein — kyunki siblings directly share nahi kar sakte
D. Alag file mein — import/export ke through dono components use karein
> B. React ka data flow top → bottom hota hai. Siblings directly communicate nahi kar sakte. Isliye state dono ke common parent mein rakho, phir props mein data do (data down), callbacks mein actions do (actions up).

Q: "Lifting State Up" ka matlab kya hai?
A. State ko parent component se nikaal kar child mein daalna — component ko khud-mukhtar banana
B. State ko child component se nikaal kar common parent mein daalna — taake siblings share kar sakein
C. State ko global store mein daalna — poore app mein accessible ho
D. State ko `useRef` se replace karna — re-render nahi hoga isliye fast hai
> B. Lifting State Up = state child se nikaal kar common parent mein daalna. Jab do siblings ko same data chahiye, toh parent mein rakho. Phir data props mein do (down), actions callbacks mein bhejo (up).

Q: React mein data kis direction mein flow hota hai?
A. Bidirectional — parent → child aur child → parent dono taraf ja sakta hai
B. Bottom → top — child se parent tak props ke through
C. Top → bottom — parent se child tak props ke through
D. Horizontal — siblings ke beech directly share ho sakta hai
> C. React ka data flow sirf top → bottom (parent → child) hota hai. Props ke through data ek hi direction mein jaata hai. Isliye siblings directly share nahi kar sakte — state common parent mein rakhna padta hai.

Q: Child component parent tak action ya signal kaise bhejta hai?
A. Seedha parent ke variable ko modify karke — React re-render trigger kar deta hai
B. Callback props ke through — parent ek function prop deta hai, child use call karta hai
C. Global event system ke through — `window.dispatchEvent` se signal bhejta hai
D. Direct function call — child parent ke function ko import kar ke call kar sakta hai
> B. Parent child ko ek function prop deta hai (jaise `onIncrement`). Child jab button click karta hai, woh function call karta hai — `onIncrement()`. Parent ka setter chal jata hai, state update hoti hai, re-render hota hai.

Q: "Data down, Actions up" pattern mein "down" aur "up" ka kya reference hai?
A. React component tree mein — data parent → child (down), actions child → parent (up)
B. File system mein — data code ke neeche likha hai (down), actions upar (up)
C. Screen position mein — data screen ke neeche dikhta hai, actions upar
D. Network request mein — data server se download (down), actions upload (up)
> A. "Down" = parent se child ki taraf data (props). "Up" = child se parent ki taraf action (callbacks). Yeh React component tree ke hierarchy ko reference karta hai — parent upar, child neeche.

Q: Lifting State Up ke 3 correct steps kya hain?
A. (1) Global store mein daalo (2) Import karo (3) Use karo
B. (1) State child → parent (2) Data prop mein do (3) Callback prop mein do
C. (1) useState remove karo (2) useRef add karo (3) Props adjust karo
D. (1) Children merge karo (2) Props rename karo (3) Components flatten karo
> B. Step 1: State ko child component se nikaal kar common parent mein daalo. Step 2: Data ko prop ke roop mein child component ko do (count={count}). Step 3: State change karne ka callback prop do (onIncrement={() => setCount(...)}).

Q: Prop drilling kya hai?
A. Ek prop ko multiple components mein alag-alag names se define karna
B. Deep component tree mein middle components ko unnecessary props receive karna — sirf aage pass through karne ke liye
C. Props ko optional banane ka pattern — `?` operator se har prop optional ho jaata hai
D. Ek component mein bohot saare props (10+) define kar dena — code bloat
> B. Prop drilling tab hota hai jab state 3+ level deep child tak bhejni ho. Middle components (Layout, Sidebar) ko woh prop receive karna padta hai chahe unhe zaroorat na ho — woh sirf aage pass through kar rahe hain. Isse code verbose hota hai aur refactor mushkil.

Q: Prop drilling ke solutions kya hain?
A. `useRef` use karo — props ki zaroorat nahi, data directly access ho jaata hai
B. Saare components ek file mein daal do — prop drilling ki problem nahi hogi
C. Composition (`children` prop) ya Context API — middle components ko prop nahi dena padta
D. Global variables use karo — har component directly access kar sakta hai
> C. Composition (children prop) mein component ko parent se seedha bhej do — middle components prop nahi dekhte. Context API (agle doc) mein provider wrapper ke through data directly kisi bhi level pe available ho jata hai — bina prop drilling ke.

Q: Global variable (`let globalCount = 0`) siblings ke beech share karne se kyun kaam nahi karta?
A. Global variables sirf strings store kar sakte hain — numbers nahi
B. React tabhi re-render karta hai jab `useState` ki setter call hoti hai — plain variable change se kuch nahi hota
C. JavaScript mein global variable sirf ek file tak limited hota hai — doosri file access nahi kar sakti
D. Global variables React mein allowed nahi hain — syntax error deta hai
> B. React ka render cycle state changes se trigger hota hai. `useState` ki setter call → React ko signal → re-render. `globalCount++` sirf ek plain JavaScript variable change hai — React ko pata nahi chalta. Isliye UI update nahi hota, chahe console mein value badal rahi ho.

Q: Lifting State Up ke liye `useRef` kyun use nahi kar sakte?
A. `useRef` sirf DOM elements store kar sakta hai — numbers nahi
B. `useRef` change → koi re-render nahi hota — display component ko pata nahi chalega ki data badla
C. `useRef` ka `current` property hamesha read-only hota hai — change nahi kar sakte
D. `useRef` sirf ek component mein kaam karta hai — doosre component access nahi kar sakte
> B. `useRef` ka `.current` change karne se component re-render nahi hota. Display component (jo data dikhata hai) ko pata nahi chalega ki value badli hai — UI update nahi hoga. Isliye `useState` chahiye — jo setter call pe re-render trigger kare.

Q: React mein data sirf parent → child direction mein flow hota hai — siblings directly communicate nahi kar sakte.
- True
- False

Q: Do sibling components directly ek doosre ke state variable ko access aur modify kar sakte hain.
- True
- False
> False. Sibling components alag functions hain — ek ka state dusre ke scope mein nahi hai. React components JavaScript functions hain — same scope rules apply hote hain. Ek component ka state variable doosre component mein exist nahi karta.

Q: Lifting State Up ka matlab hai — state ko child component se nikaal kar common parent mein daalna.
- True
- False
> True. Jab do siblings ko same data chahiye, toh kisi ek child mein state rakhne se doosra access nahi kar sakta. Solution: state dono ke common parent mein rakh do. Phir data props mein do, actions callbacks mein bhejo.

Q: Callback props (jaise `onIncrement`) child se parent tak "action up" bhejne ka tareeka hai — child function call karta hai, parent ka setter execute hota hai.
- True
- False
> True. Parent ek function prop pass karta hai. Child jab call karta hai (jaise button click pe), parent ka setter chal jata hai — state update → re-render. Children ko sirf function reference milta hai, setter nahi.

- True
- False

## ShortAnswer

Q: Lifting State Up pattern kya hai? Kab zaroorat padti hai? Steps ke saath example do.

<details>
<summary>Sample Answer</summary>

**Kya hai:** Lifting State Up = state ko child component se nikaal kar common parent mein daalna taake siblings share kar sakein.

**Kab zaroorat hai:** Jab do sibling components ko same data chahiye ya unhe ek doosre ke state ko affect karna hai. React ka data flow top → bottom hai — siblings directly communicate nahi kar sakte.

**3 Steps with example:**

```tsx
// Step 1: State child se nikaal kar parent mein daalo
function App() {
  const [count, setCount] = useState(0);
  // ...

// Step 2: Data prop mein do (data down)
<Display count={count} />

// Step 3: Callback prop mein do (actions up)
<Button onIncrement={() => setCount(c => c + 1)} />
```

**Full example:**

```tsx
function Display({ count }: { count: number }) {
  return <p>Count: {count}</p>;
}

function Button({ onIncrement }: { onIncrement: () => void }) {
  return <button onClick={onIncrement}>+1</button>;
}

function App() {
  const [count, setCount] = useState(0);
  return (
    <div>
      <Display count={count} />
      <Button onIncrement={() => setCount(c => c + 1)} />
    </div>
  );
}
```

**Data flow:**
```
App (state: count, setCount)
  ├── Display ← count prop (data down)
  └── Button ← onIncrement prop (actions up)
              → click → setCount → re-render → Display update
```

</details>

Q: Prop drilling kya hai? Kab problem banti hai? Solutions kya hain?

<details>
<summary>Sample Answer</summary>

**Prop drilling kya hai:** Jab state ko deep component tree (3+ level) mein bhejna ho, toh har middle component ko woh prop receive karna padta hai chahe unhe zaroorat na ho — woh sirf aage pass through kar rahe hain.

**Example:**
```
App (count state yahan)
  └──Layout ← count prop → pass through (use nahi karta)
      └──Sidebar ← count prop → pass through (use nahi karta)
          └──Avatar ← finally count use karta hai
```

```tsx
function Layout({ count }: { count: number }) {
  return <Sidebar count={count} />;  // Sirf pass through
}

function Sidebar({ count }: { count: number }) {
  return <Avatar count={count} />;  // Sirf pass through
}

function Avatar({ count }: { count: number }) {
  return <p>Count: {count}</p>;  // Asli use
}
```

**Kab problem banti hai:**
- Tree jitna deep hoga, prop drilling utni painful
- Middle component add/remove karo toh saari props update karni padti hain
- Code verbose ho jata hai — Layout aur Sidebar ko count se koi matlab nahi

**Solutions:**
1. **Composition (children prop):** Middle components ko prop mat do — Avatar ko seedha parent se bhejo:
   ```tsx
   function Layout({ children }: { children: React.ReactNode }) {
     return <Sidebar>{children}</Sidebar>;
   }
   function App() {
     return <Layout><Avatar count={count} /></Layout>;
   }
   ```

2. **Context API:** Provider wrapper ke through data directly kisi bhi level pe available — middle components prop nahi dekhte. (Agle doc mein seekhenge.)

</details>
