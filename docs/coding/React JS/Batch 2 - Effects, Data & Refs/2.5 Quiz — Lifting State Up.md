
## MCQ

Q: If two sibling components need the same data, where should the state be placed?
A. In one child component — siblings can share through each other
B. In the common parent of both siblings — then pass data via props
C. In a global variable — siblings can't share directly
D. In a separate file — import/export so both components can use it
> B. React's data flow is top → bottom. Siblings can't communicate directly. So the state goes in the common parent. Then data is passed as props (data down), actions as callbacks (actions up).

---

Q: What does "Lifting State Up" mean?
A. Remove state from parent component and put it in child — making the component autonomous
B. Take state out of a child component and put it in a common parent — so siblings can share
C. Put state into a global store — accessible by the entire app
D. Replace state with `useRef` — no re-render so it's faster
> B. Lifting State Up = take state out of a child component and put it in a common parent. When two siblings need the same data, put the state in the parent. Then pass data as props (down), actions as callbacks (up).

---

Q: In React, which direction does data flow?
A. Bidirectional — parent → child and child → parent both work
B. Bottom → top — child sends to parent through props
C. Top → bottom — parent sends to child through props
D. Horizontal — siblings can share directly
> C. React data flows only top → bottom (parent → child). Data travels one direction through props. That's why siblings can't share directly — state must be in the common parent.

---

Q: How does a child component send an action to its parent?
A. Directly modify the parent's variable — React detects the change and re-renders
B. Through callback props — parent passes a function, child calls it
C. Through a global event system — `window.dispatchEvent` sends the signal
D. Direct function call — child imports the parent's function and calls it
> B. The parent passes a function as a prop (like `onIncrement`). When the child clicks, it calls that function — `onIncrement()` — the parent's setter runs, state updates, re-renders.

Q: In the "Data down, Actions up" pattern, what do "down" and "up" refer to?
A. React component tree — data parent → child (down), actions child → parent (up)
B. File system — data written below, actions written above
C. Screen position — data shown below, actions above
D. Network — data downloaded (down), actions uploaded (up)
> A. "Down" = parent to child direction for data (props). "Up" = child to parent direction for actions (callbacks). This refers to the React component tree hierarchy — parent at top, children below.

Q: What are the three correct steps for Lifting State Up?
A. (1) Put in global store (2) Import (3) Use
B. (1) Move state child → parent (2) Pass data as prop (3) Pass callback as prop
C. (1) Remove useState (2) Add useRef (3) Adjust props
D. (1) Merge components (2) Rename props (3) Flatten components
> B. Step 1: Take state out of the child component and into the common parent. Step 2: Pass data as a prop (count={count}). Step 3: Pass a callback prop for state changes (onIncrement={() => setCount(...)}).

Q: What is prop drilling?
A. Defining the same prop with different names in multiple components
B. Passing props through middle components in a deep tree when only the deepest child needs them
C. Making props optional with the `?` operator — everything becomes optional
D. Defining too many props (10+) in one component — code bloat
> B. Prop drilling happens when state needs to go 3+ levels deep. Middle components receive the prop they don't need — just passing it through. This makes code verbose and refactoring harder.

---

Q: What are the solutions to prop drilling?
A. Use `useRef` — data stored directly, no props needed
B. Put all components in one file — prop drilling problem disappears
C. Composition (`children` prop) or Context API — middle components don't need props
D. Use global variables — any component can access directly
> C. Composition (children prop) means you pass a component directly from parent, middle components don't see the prop. Context API (next doc) wraps data in a Provider — any depth component accesses it directly without props.

Q: Why can't a global variable (`let globalCount = 0`) share data between siblings?
A. Global variables can only store strings — not numbers
B. React only re-renders when `useState`'s setter is called — a plain variable change does nothing
C. JavaScript global variables are limited to one file — another file can't access them
D. Global variables aren't allowed in React — syntax error
> B. React's render cycle is triggered by state changes. `useState`'s setter → React signals → re-render. `globalCount++` is just a plain JavaScript variable change — React doesn't know about it. So the UI doesn't update, even though the console might show the change.

---

Q: Why can't `useRef` be used for Lifting State Up?
A. `useRef` can only store DOM elements — not numbers
B. `useRef` change → no re-render — the display component won't know the data changed
C. `useRef`'s `current` property is always read-only — can't change it
D. `useRef` only works in one component — other components can't access it
> B. Changing `ref.current` doesn't trigger a re-render. The display component (which shows the data) won't know the state changed — no UI update. For UI display, `useState` is needed — which triggers re-renders when the setter is called.

## TrueFalse

Q: In React, data flows only top → bottom (parent → child). Siblings can't communicate directly.
- True
- False
> True. React's data flow is unidirectional (top → bottom). Parents pass data to children via props. Siblings have no direct communication channel. If two siblings need the same data, the state must be in their common parent.

---

Q: Two sibling components can directly access and modify each other's state variables.
- True
- False
> False. Sibling components are separate functions — one's state variable isn't in the other's scope. React components are JavaScript functions — the same scope rules apply. One component's state variable doesn't exist in another component.

---

Q: "Lifting State Up" means taking state out of a child component and putting it in a common parent.
- True
- False
> True. When two siblings need the same data, keeping state in one child means the other can't access it. Solution: put the state in both components' common parent. Then pass data as props, actions as callbacks.

---

Q: Callback props (like `onIncrement`) let a child send an action upward — the child calls the function, the parent's setter runs.
- True
- False
> True. The parent passes a function as a prop. When the child calls it (on button click), the parent's setter runs — state updates, re-renders. Children only receive a function reference, not the setter itself.

---

Q: Prop drilling happens when a component has too many props (10+) defined — causing code bloat.
- True
- False
> False. Prop drilling is when state is passed deep through a component tree (3+ levels), and middle components receive props they don't need — just passing them through. Having many props in one component is a different problem.

---

Q: You can use `useRef` for Lifting State Up — refs store data and persist across renders.
- True
- False
> False. `useRef` stores data and persists across renders, but changing it doesn't trigger a re-render. The display component won't know the data changed — no UI update. For UI display, `useState` is needed, which triggers re-renders when the setter is called.

## Short Answer

Q: What is the Lifting State Up pattern? When is it needed? Steps with example.

<details>
<summary>Sample Answer</summary>

**What it is:** Lifting State Up = taking state out of a child component and putting it in a common parent, so siblings can share data.

**When needed:** When two sibling components need the same data, or one needs to affect another's state. React's data flow is top → bottom — siblings can't communicate directly.

**Three steps with example:**

```tsx
// Step 1: Move state from child to common parent
function App() {
  const [count, setCount] = useState(0);
  // ...

// Step 2: Pass data as prop (data down)
<Display count={count} />

// Step 3: Pass callback as prop (actions up)
<Button onIncrement={() => setCount(c => c + 1)} />
```

**Full example:**

```tsx
function Display({ count }: { count: number }) {
  return <p>Count: {count}</p>;
}

function Button({ onIncrement }: { onIncrement: () => void }) {
  return <button onClick={onIncrement}>+1</button>;
}

function App() {
  const [count, setCount] = useState(0);
  return (
    <div>
      <Display count={count} />
      <Button onIncrement={() => setCount(c => c + 1)} />
    </div>
  );
}
```

**Data flow:**
```
App (state: count, setCount)
  ├── Display ← count prop (data down)
  └── Button ← onIncrement prop (actions up)
              → click → setCount → re-render → Display updates
```

</details>

Q: What is prop drilling? When does it become a problem? What are the solutions?

<details>
<summary>Sample Answer</summary>

**What is prop drilling:** When state needs to go 3+ levels deep in a component tree, every middle component must receive that prop, even if they don't need it — just passing it through.

**Example:**
```
App (theme state here)
  └──Layout ← theme prop → pass through (doesn't use)
      └──Sidebar ← theme prop → pass through (doesn't use)
          └──Avatar ← finally uses theme
```

```tsx
function Layout({ theme }: { theme: string }) {
  return <Sidebar theme={theme} />;  // Just passing through
}

function Sidebar({ theme }: { theme: string }) {
  return <Avatar theme={theme} />;   // Just passing through
}

function Avatar({ theme }: { theme: string }) {
  return <p>Theme: {theme}</p>;  // Actual use
}
```

**When it becomes a problem:**
- The deeper the tree, the more painful prop drilling
- Adding/removing a middle component requires updating all props
- Code gets verbose — Layout and Sidebar don't care about theme

**Solutions:**
1. **Composition (children prop):** Pass the component directly from parent so middle components don't see the prop:
   ```tsx
   function Layout({ children }: { children: React.ReactNode }) {
     return <Sidebar>{children}</Sidebar>;
   }
   function App() {
     return <Layout><Avatar theme={theme} /></Layout>;
   }
   ```

2. **Context API:** Wrap data in a Provider — any depth component accesses it directly. Middle components don't see the prop. (We'll learn this in the next doc.)

</details>
