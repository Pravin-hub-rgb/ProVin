# 2.5 — Lifting State Up

## Cheat Sheet (Quick Recall)

```
Pattern: Data down, Actions up
State → prop (parent → child)
Child → callback → parent (via onXxx props)

Lifting State Up = state child se nikaal kar common parent mein daalna
Siblings share data → state parent mein rakho, props mein do

Prop Drilling = deep tree mein middle components ko unnecessary props receive karna
Solution: Composition (children) ya Context API
```

## Abhi Tak Kya Hua

3 hooks seekh liye — `useState` (client state), `useRef` (DOM refs + mutable values), `useQuery` (server data). Lekin abhi tak ek cheez nahi dekhi — **jab do sibling components ko same data chahiye, toh kaise karein?** State ek child mein hai, doosre child ko bhi woh data chahiye. React ka data flow top → bottom hai — siblings directly ek doosre ko data bhej nahi sakte.

## Broader Goal

Ek simple counter banayenge. Do sibling components honge:

- `CountDisplay` — count dikhayega
- `CountButton` — count increment karega

Pehle galat approach banayenge (state child mein) — problem feel hogi. Phir **Lifting State Up** pattern se fix karenge — state common parent mein rakhna, data props mein bhejna, actions callbacks mein bhejna. Step by step, ek-ek line.

---

## Step 1 — Static UI: Sirf HTML skeleton, koi logic nahi

**SOCH:** Counter banana hai. Ek number dikhe, ek button ho. Pehle pure hardcoded values se shuru karte hain — koi state nahi, koi components nahi, sirf HTML.

```tsx
function App() {
  return (
    <div>
      <p>Count: 0</p>
      <button>+1</button>
    </div>
  );
}
```

**TEST:** Browser mein "Count: 0" aur "+1" button dikh raha hai. ✅ Bas HTML. Koi state nahi, koi click logic nahi.

---

## Step 2 — Do sibling components banao (still hardcoded)

**SOCH:** Ab is HTML ko do alag components mein split karte hain — `CountDisplay` aur `CountButton`. Yeh dono siblings honge — dono `App` ke direct children. Abhi bhi hardcoded, koi state nahi.

**CONCEPT:** Sibling components = do components jo ek hi parent ke andar render ho rahe hain, side by side. React tree mein woh parent ke do direct children hain.

```tsx
function CountDisplay() {
  return <p>Count: 0</p>;
}

function CountButton() {
  return <button>+1</button>;
}

function App() {
  return (
    <div>
      <CountDisplay />
      <CountButton />
    </div>
  );
}
```

**TEST:** Browser mein same UI dikh raha hai — "Count: 0" aur "+1" button. ✅

**Isme state kahan hai?** Kahin nahi. Sirf hardcoded HTML do components mein bant gaya.

---

## Step 3 — State CountButton mein daalo (galat approach)

**SOCH:** Ab button click pe count badlna chahiye. CountButton ke andar hi `useState` daal deta hoon — apna count khud manage karega.

```tsx
function CountButton() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>Count: {count}</button>;
}
```

Button click pe count +1 ho raha hai — button ke andar bhi `Count: {count}` dikh raha hai.

Ab CountDisplay mein bhi yahi count dikhana hai. Socho — dono components ek hi file mein hain (`App.tsx`), toh seedha `count` variable use kar leta hoon CountDisplay mein?

```tsx
function CountDisplay() {
  return <p>Count: {count}</p>;  // ❌ count yahan exist nahi karta!
}
```

**Yeh kaam nahi karega.** `count` CountButton ke function ke andar declare hua hai — uska **scope** sirf CountButton tak limited hai. CountDisplay ek alag function hai — CountButton ke andar ke variables access nahi kar sakta, chahe dono ek hi file mein kyun na ho.

```
CountButton() {
  const count = ...  ← count yahan rehta hai
  // Sirf CountButton ke andar accessible
}

CountDisplay() {
  // count❌ — CountButton ke scope ke bahar
}
```

React components bhi functions hain — same scope rules lagu hote hain. Isliye CountDisplay CountButton ke `count` ko access nahi kar sakta.

Toh ab CountDisplay mein hardcoded hi daalte hain:

```tsx
function CountDisplay() {
  return <p>Count: 0</p>;  // Hardcoded — abhi koi state nahi
}
```

**Poora code:**

```tsx
import { useState } from "react";

function CountDisplay() {
  return <p>Count: 0</p>;
}

function CountButton() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>Count: {count}</button>;
}

export default function App() {
  return (
    <div>
      <CountDisplay />
      <CountButton />
    </div>
  );
}
```

**TEST:** Button click karo — button ke andar count badal raha hai, lekin CountDisplay abhi bhi "Count: 0" dikha raha hai. ✅ (partially working)

Ab problem clear hai — `count` CountButton ke scope mein band hai, CountDisplay us tak nahi pahunch sakta. Scope ka issue hai, file ka nahi. Isse kaise solve karein? Koi "global" jaisa kuch chahiye jo dono components access kar sakein?

## Step 4 — Problem feel karo: CountDisplay ko pata nahi

**SOCH:** Scope ka issue tha — `count` CountButton ke andar band tha. Lekin kya koi "global" variable bana ke dono components use kar sakein? Jaise App component ke bahar ek variable rakh do? Try karte hain:

```tsx
let globalCount = 0;  // Global variable — dono components access kar sakte hain

function CountDisplay() {
  return <p>Count: {globalCount}</p>;
}

function CountButton() {
  return <button onClick={() => { globalCount++; console.log(globalCount); }}>+1</button>;
}
```

**TEST:** Button click karo — console mein `globalCount` badal raha hai, lekin CountDisplay update nahi ho raha! ❌

Kyun? Kyunki **React ko pata nahi chal raha ki globalCount change hua**. React tabhi re-render karta hai jab `useState` ki setter call hoti hai. Ek plain variable change karne se React kuch nahi karta.

**CONCEPT — React ka data flow:**

React ka data flow **top → bottom** hota hai — parent se child tak props ke through. Siblings ke beech koi direct sharing mechanism nahi hai.

```
React data sirf parent → child props ke through jaata hai.
Siblings directly communicate nahi kar sakte.

Agar do siblings ko same data chahiye:
  ❌ Ek child ka state — doosra access nahi kar sakta
  ❌ Global variable — React ko pata nahi chalta
  ✅ Common parent mein state — props mein dono ko do
```

Is problem ko dekho — `CountButton` ka state `CountDisplay` tak nahi pahunch raha. `globalCount` bhi kaam nahi aaya kyunki React usse track nahi karta. 

**Current code — problem visible:**

```tsx
function CountDisplay() {
  return <p>Count: 0</p>;  // ❌ Hardcoded — actual count nahi dikh raha
}

function CountButton() {
  const [count, setCount] = useState(0);  // Count yahan hai
  return <button onClick={() => setCount(count + 1)}>Count: {count}</button>;
}

function App() {
  return (
    <div>
      <CountDisplay />
      <CountButton />
    </div>
  );
}
```

**TEST:** Button click kar ke dekh — CountDisplay abhi bhi "Count: 0" dikha raha hai. ❌ Yeh broken state hai. Problem clear ho gayi: state ek child mein hai, doosra access nahi kar sakta.

## Step 5 — Lift state to App (Step 1 of pattern)

**SOCH:** Problem clear hai — state `CountButton` mein hai, `CountDisplay` use access nahi kar sakta. Solution: state dono ke **common parent** (`App`) mein rakh do. Phir dono children prop ke through access kar sakte hain.

**CONCEPT — Lifting State Up:** State ko child component se nikaal kar common parent mein daalne ko "lift state up" kehte hain. Isse siblings share kar sakte hain — parent ke through.

**Pehla step — state CountButton se nikaal kar App mein daalo:**

```tsx
import { useState } from "react";

function App() {
  const [count, setCount] = useState(0);  // State ab App mein

  return (
    <div>
      <CountDisplay />
      <CountButton />
    </div>
  );
}
```

`CountButton` ab stateless ho gaya — uske paas `count` ya `setCount` nahi hai. Uska button text sirf "+1" rahega (dynamic nahi).

```tsx
function CountButton() {
  return <button>+1</button>;  // Stateless — bas button
}
```

**TEST:** Ab button click pe kuch nahi hota — kyunki `setCount` App mein hai, CountButton ke paas nahi. Yeh half-done state hai — aage badhte hain. ✅ (intentionally incomplete)

## Step 6 — Data down: `count` prop do CountDisplay ko

**SOCH:** State ab App mein hai. CountDisplay ko count dikhana hai — toh prop mein do. Parent se child tak data bhejne ka React ka tareeka props hai.

**CONCEPT — Props:** Props React ka mechanism hai parent se child tak data bhejne ka. Child component function arguments ki tarah props receive karta hai. Jab parent ka state change hota hai, React naye props ke saath child ko re-render karta hai.

```tsx
function CountDisplay({ count }: { count: number }) {
  return <p>Count: {count}</p>;
}
```

`{ count }: { count: number }` — TypeScript type annotation. Pehla `{ count }` destructuring hai (object se count nikaal rahe hain). Doosra `{ count: number }` type hai — yeh prop number hoga.

Ab App mein prop do:

```tsx
<CountDisplay count={count} />
```

**TEST:** Browser mein "Count: 0" dikh raha hai. Lekin ab yeh 0 hardcoded nahi — App ke state se aa raha hai. CountDisplay ko ab actual count mil raha hai. ✅

---

## Step 7 — Actions up: callback prop do CountButton ko

**SOCH:** CountDisplay ko data mil gaya (count prop). Ab CountButton ko state update ka tareeka chahiye. `setCount` App mein hai — toh CountButton ko ek function prop do jo App ke `setCount` ko call kare. Child se parent tak action bhejne ka tareeka callbacks hain.

Pehle prop ka naam aisa rakhunga jo confuse na kare — `onIncrement`. Baad mein dekhenge ki convention kya hai.

```tsx
function CountButton({ onIncrement }: { onIncrement: () => void }) {
  return <button onClick={onIncrement}>+1</button>;
}
```

Dekho — `onIncrement` ek prop hai jo CountButton receive kar raha hai. Uske baad `<button onClick={onIncrement}>` mein yeh prop HTML button ke `onClick` event handler ko assign ho raha hai. Dono ka naam alag hai — confuse nahi hoge.

App mein jab use karo:

```tsx
<CountButton onIncrement={() => setCount(count + 1)} />
```

`() => setCount(count + 1)` — arrow function. Jab CountButton call karega `onIncrement()`, tab App ka `setCount` chalega → state update → re-render → CountDisplay ko naya count milega.

**Poora working code:**

```tsx
import { useState } from "react";

function CountDisplay({ count }: { count: number }) {
  return <p>Count: {count}</p>;
}

function CountButton({ onIncrement }: { onIncrement: () => void }) {
  return <button onClick={onIncrement}>+1</button>;
}

function App() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <CountDisplay count={count} />
      <CountButton onIncrement={() => setCount(count + 1)} />
    </div>
  );
}
```

**Data flow visually:**

```
App (state: count, setCount)
  │
  ├── CountDisplay
  │     └── receives "count" as prop (data down)
  │
  └── CountButton
        └── receives "onIncrement" as prop (actions up)
            → click → App ka setCount call
            → App re-render
            → CountDisplay ko naya count mila
```

**TEST:** Button click karo — CountDisplay ka count update ho raha hai? ✅ ✅ ✅

**Convention note:** Codebase mein aksar aise callback props ko `onXxx` naam diya jaata hai — jaise `onClick`, `onToggle`, `onDelete`. Mene `onIncrement` rakha taaki samajh aaye ki yeh custom prop hai. Convention follow karein toh naam `onClick` bhi rakh sakte ho — logic same hai, bas naam ka farak hai.

> **Nutshell:** Lifting State Up = state child se nikaal kar common parent mein daalo. Data down (props) aur actions up (callbacks) — siblings parent ke through share karte hain.

## Step 8 — Prop Drilling: Jab yeh lift deep tree mein karni ho

**SOCH:** Ab tak sirf 2 level deep tha (App → children). Kya hoga agar tree 4-5 level deep ho? Jaise App ke andar Layout, Layout ke andar Sidebar, Sidebar ke andar Avatar — aur Avatar ko state chahiye.

**CONCEPT — Prop Drilling:** Jab state ko 3+ level neeche bhejna ho, toh har middle component ko woh prop receive karna padta hai — chahe unhe zaroorat na ho. Is problem ko prop drilling kehte hain.

```
App (count state yahan)
  └── Layout ← count prop pass through (use nahi karta)
      └── Sidebar ← count prop pass through (use nahi karta)
          └── Avatar ← finally count use karta hai
```

```tsx
function Layout({ count }: { count: number }) {
  return <Sidebar count={count} />;  // Pass through — count use nahi kiya
}

function Sidebar({ count }: { count: number }) {
  return <Avatar count={count} />;  // Pass through — count use nahi kiya
}

function Avatar({ count }: { count: number }) {
  return <p>Count: {count}</p>;  // Finally use kiya
}
```

`Layout` aur `Sidebar` ko `count` ki zaroorat nahi — woh sirf prop aage bhej rahe hain. Isse code verbose ho jata hai, aur refactor mushkil — beech mein component add/remove karo toh saari props update karni padti hain.

**Solutions:**
- **Composition (`children`)** — Avatar ko directly parent se bhejo, middle components ko prop mat do
- **Context API** — agle doc (2.6) mein seekhenge

> **Nutshell:** Prop drilling = state ko deep tree mein bhejne ke liye middle components ko unnecessary props receive karna. Solutions: Composition ya Context API.

---

## What It Is NOT

- **Global state nahi hai** — state parent mein hai, children props se access karte hain. Yehi sahi React pattern hai.
- **useRef ka replacement nahi hai** — `useRef` re-render trigger nahi karta. Is pattern mein `useState` chahiye kyunki UI update karna hai.
- **Ek file mein sab kuch nahi** — alag files mein bhi same pattern: state parent mein, props children mein.

---

## Common Mistakes

1. **State ek child mein rakhna jab doosre child ko bhi chahiye** — state hamesha common parent mein rakho, kisi ek child mein nahi
2. **Callback directly child mein define karna** — `onClick={() => setCount(c+1)}` parent mein define karo, child ko sirf function reference do
3. **Prop drilling ko ignore karna** — 4+ level deep ja rahe ho toh Composition ya Context socho
4. **`useRef` use karna state sharing ke liye** — `useRef` re-render trigger nahi karta, display component update nahi hoga

## In Your Own Words

1. "Lifting State Up" ka matlab kya hai? Kab zaroorat padti hai?

   <details>
   <summary>Sample Answer</summary>
   State ko child component se nikaal kar common parent mein daalna. Zaroorat tab padti hai jab do siblings ko same data share karna ho — kyunki React mein data top → bottom jaata hai, siblings directly communicate nahi kar sakte.
   </details>

2. Lifting State Up ke 3 steps kya hain?

   <details>
   <summary>Sample Answer</summary>
   (1) State child se nikaal kar parent mein daalo. (2) State prop ke roop mein child ko do (data down). (3) State change karne ka callback prop do (actions up).
   </details>

3. Prop drilling kya hai? Kab problem banti hai?

   <details>
   <summary>Sample Answer</summary>
   Jab state 4+ level deep child tak bhejni ho, toh har middle component ko woh prop receive karna padta hai chahe unhe zaroorat na ho. Is problem ko prop drilling kehte hain. Solutions: Composition (children prop) ya Context API.
   </details>

4. `useRef` Lifting State Up ke liye kyun kaam nahi karta?

   <details>
   <summary>Sample Answer</summary>
   `useRef` change hone par re-render trigger nahi karta. Display component ko pata nahi chalega ki count badla hai. UI update ke liye `useState` chahiye — jo re-render trigger kare aur naya count display dikhaye.
   </details>

5. Is pattern doosre konse naam se jaana jaata hai?

   <details>
   <summary>Sample Answer</summary>
   "Data down, Actions up." State parent se child tak props mein jaata hai (down). Child actions callbacks ke through parent tak bhejta hai (up).
   </details>

## Summary

| Concept | Explanation |
|---|---|
| Lifting State Up | State child → common parent |
| Data down | Props mein parent → child |
| Actions up | Callbacks mein child → parent |
| Prop drilling | Deep tree mein middle components ko unnecessary props |
| Solution | Composition (children) ya Context API |
