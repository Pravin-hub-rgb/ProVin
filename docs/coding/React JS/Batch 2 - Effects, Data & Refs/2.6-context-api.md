## Cheat Sheet (Quick Recall)

```ts
// FILE: contexts/ThemeContext.tsx — export karna mat bhoolna

import { createContext } from "react";
export const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);

export function useTheme() {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error("Must be inside ThemeProvider");
  return ctx;
}

export function ThemeProvider({ children }) { ... }

// FILE: App.tsx — import ThemeProvider from contexts file
// FILE: components/Navbar.tsx — import useTheme from contexts file
```

- **createContext** (export karo) → Context object banata hai
- **Provider** — `<ThemeContext value={...}>` tree ke andar value provide karta hai
- **useContext(guard)** — value consume + error check
- **Custom hook** — `useTheme()` guard ke saath, reusable
- **File structure** — Context ek alag file mein rakhna best practice hai (Fast Refresh warning se bachne ke liye)

**Ek Line Mein:** 2.6 mein hum Context API seekh rahe hain — data ko directly component tree mein kahi bhi available karwana bina props pass kiye. `createContext` se container banao, `<Context>` se value do, `useContext` ya custom hook se value lo. Lab mein **Language Switcher** banayenge — App → MainContent (prop drilling victim) → Header/Greeting/LanguageToggle. Context se MainContent ko props se mukt karenge.

## Abhi Tak Kya Hua

Yaar 2.5.0 mein Lifting State Up seekha — siblings share state through parent. Lekin jab component tree deep ho aur har level ko data chahiye (jaise theme, auth user), toh lifting se prop drilling hoti hai. Composition help karta hai, lekin kabhi kabhi data ko **kahi bhi** accessible hona chahiye bina props ke.

## Broader Goal

Is doc mein **Context API** seekhenge — React ka built-in mechanism for global data. Ek **Theme Switcher** app banayenge:
- Dark/light mode toggle
- Context se theme har component ko milega bina props ke
- Custom hook `useTheme()` banayenge (safe pattern)
- TypeScript typing with context

**Roadmap (7 steps, ek dusre pe build karte hain):**
1. Problem feel karo — prop drilling without escape
2. Create Context
3. Provide value
4. Consume value
5. Custom hook `useTheme()` — safe pattern
6. `ThemeProvider` component — logic extract karo
7. Poora Theme Switcher build karo (gradual, phase by phase)

Uske baad performance note aur kab-use-karein guide.

## Step 1 — Problem Feel Karo: Prop Drilling Without Escape

Dark/light mode toggle chahiye. Har component ko current theme pata hona chahiye — background color, text color sab change hoga. Lifting state up se karein toh kya hoga?

Maine bhi pehle prop drilling ko ignore karta tha — "2-3 level toh chalta hai." Lekin jab ek project mein 8 level deep props pass karni padi, tab realize hua ki kuch aur chahiye. Context API allow karta hai ki value ek jagah provide karo aur kisi bhi nested component mein bina props ke access karo.

```text
App (theme state yahan)
  ├── Navbar
  │   ├── Logo (needs theme)
  │   └── ThemeToggle (needs theme + setter)
  ├── MainContent
  │   ├── Sidebar
  │   │   └── MenuItem[] (needs theme)
  │   └── Article (needs theme)
  └── Footer (needs theme)
```

Har component ko `theme` prop dena padega — 10+ components, including middle components jo sirf prop pass kar rahe hain. Prop drilling extreme ho gayi.

**Context API iska solution hai** — data directly component ko milta hai bina middle components ke through prop pass kiye. Isko teen steps mein karte hain: create → provide → consume.

**Aur isko "API" kyun kehte hain?** Jaise ek REST API hota hai — koi bhi client direct request bhej kar data le sakta hai bina har intermediate server se permission liye. Context API bhi waisa hi hai — koi bhi child component direct `useContext()` call karke data le sakta hai bina har parent component se props liye. `createContext` ne ek "endpoint" bana diya — Provider us endpoint pe data serve karta hai, aur koi bhi component directly us endpoint se fetch kar sakta hai. Isi similarity ki wajah se ise "Context API" kehte hain — React ka built-in data-fetching endpoint for component tree.

## Step 2 — Create Context (in a separate file)

**SOCH:** Pehle ek container chahiye jisme theme data store kar sakte hain. Ye container component tree ke through travel karega — iske liye `createContext` use karte hain.

**CONCEPT — `createContext`:** Ye React ka built-in function hai. Ek "container" object banata hai jisme koi bhi value store ho sakti hai.

**CONCEPT — Default value:** `createContext` ko hamesha ek default value chahiye. Ye tab use hota hai jab koi component context consume kare but uske paas Provider nahi hai. Hum `undefined` pass karte hain taaki baad mein guard pattern laga saken.

**FILE STRUCTURE:** Context ko ek **alag file** mein rakhna best practice hai. Isse do fayde hain:
1. Koi bhi component context import kar sakta hai bina circular dependency ke
2. **Fast Refresh warning nahi aati** — Vite/React dev mode mein agar ek file component ke saath non-component (jaise `ThemeContext`) export karegi, toh warning aati hai: *"Fast refresh only works when a file only exports components."* Context ki alag file rakhi toh yeh problem nahi aati.

Is file ko banate hain: `src/contexts/ThemeContext.tsx`

```ts
import { createContext } from "react";

export type Theme = "light" | "dark";

export interface ThemeContextValue {
  theme: Theme;
  toggleTheme: () => void;
}

export const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);
```

**Line by line:**
- `import { createContext } from "react"` — React se import kar rahe hain
- `export type Theme = "light" | "dark"` — union type. `export` kiya taaki App.tsx aur Navbar.tsx bhi is type ko use kar sakein
- `export interface ThemeContextValue` — context container ka blueprint. `export` zaroori hai kyunki doosre files ko pata hona chahiye ki context mein kya shape hai
  - `theme: Theme` — current theme value
  - `toggleTheme: () => void` — function to switch theme
- `export const ThemeContext = createContext<...>(undefined)` — actual container ban gaya. `export` karna mandatory hai — bina export ke doosri files import nahi kar payengi
  - Generic type `ThemeContextValue | undefined` — TypeScript ko pata hai ki ya to properly typed object aayega ya undefined
  - `undefined` default — agar Provider ke bahar use hoga toh undefined milega

>Agar aapne `export` nahi kiya, toh `ThemeContext`, `Theme`, aur `ThemeContextValue` sirf is file ke andar accessible honge. Baaki files (App.tsx, Navbar.tsx) context import nahi kar payengi.

**TEST:** Abhi console mein kuch nahi print hoga kyunki bas container banaya hai, use nahi kiya. ✅

## Step 3 — Provide Value (in App.tsx)

**SOCH:** Container ban gaya, ab usme actual value dalni hai. Theme state App mein hai — usko context ke through har child component tak pohunchana hai. Wrap karo `<ThemeContext>` ke around children, `value` prop mein daalo.

**CONCEPT — Provider component:** Jab hum `<ThemeContext value={...}>` likhte hain, React isko ek provider banata hai. Ye provider component tree ke andar saare children ko wo value directly deta hai.

**CONCEPT — React 19 syntax:** Pehle `<ThemeContext.Provider value={...}>` likhna padta tha. Ab React 19 mein context component khud hi provider ban jata hai — `.Provider` suffix ki zaroorat nahi.

**FILE:** Yeh code `src/App.tsx` mein likhenge. ThemeContext ko import karna hoga `contexts/ThemeContext` se.

```tsx
import { useState } from "react";
import { ThemeContext, type Theme } from "./contexts/ThemeContext";

function App() {
  const [theme, setTheme] = useState<Theme>("light");

  const toggleTheme = () => {
    setTheme((prev) => (prev === "light" ? "dark" : "light"));
  };

  return (
    <ThemeContext value={{ theme, toggleTheme }}>
      <Navbar />
      <MainContent />
      <Footer />
    </ThemeContext>
  );
}
```

**Line by line:**
- `import { ThemeContext, type Theme } from "./contexts/ThemeContext"` — Step 2 mein banayi gayi context container aur type ko import kar rahe hain. `ThemeContext` ki help se provide/consume karenge, `Theme` type se state type-safe rakhenge
- `const [theme, setTheme] = useState<Theme>("light")` — theme state banaya
- `toggleTheme` function — current theme ka opposite set karta hai
- `<ThemeContext value={{ theme, toggleTheme }}>` — provider wrap kiye, value object pass kiya
  - `{ theme, toggleTheme }` shorthand — dono cheezein ek saath

**TEST:** Console mein abhi bhi kuch nahi, lekin structure ready hai. ✅

## Step 4 — Consume Value (in components/Navbar.tsx)

**SOCH:** Ab children components ko theme chahiye. `useContext` hook se container se value nikaal sakte hain. Lekin agar koi component Provider ke bahar hai, toh `undefined` milega — usse handle karna padega.

**CONCEPT — `useContext` hook:** Ye hook context container ko as an argument leta hai, aur uske andar jo value hai woh return karta hai.

**CONCEPT — Guard pattern:** Agar koi component accidentally Provider ke bahar `useContext` call kare, default value `undefined` milega. Isse prevent karne ke liye check karte hain — agar `undefined` hai toh error throw karte hain.

**FILE:** Yeh code `src/components/Navbar.tsx` mein likhenge. Kyunki Navbar ek alag component hai, ise `export default` karna hoga taaki App.tsx import kar sake. ThemeContext ko `../contexts/ThemeContext` se import karna hoga (ek level up, phir contexts folder mein).

```tsx
import { useContext } from "react";
import { ThemeContext } from "../contexts/ThemeContext";

export default function Navbar() {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error("Navbar must be used within a ThemeProvider");

  return (
    <nav style={{ background: ctx.theme === "dark" ? "#333" : "#eee" }}>
      <ThemeToggle />
    </nav>
  );
}
```

**Line by line:**
- `import { useContext } from "react"` — React ka hook import kiya
- `import { ThemeContext } from "../contexts/ThemeContext"` — Step 2 mein banaya gaya context container import kiya. Path `../` isliye kyunki components folder contexts folder ke sibling hai
- `export default function Navbar()` — `export default` zaroori hai taaki App.tsx mein `import Navbar from "./components/Navbar"` kar sakein
- `const ctx = useContext(ThemeContext)` — context se value nikaal rahe hain
- `if (!ctx) throw new Error("Navbar must be used within a ThemeProvider")` — guard pattern. Error message mein component name do taaki debugging aasan ho
- `ctx.theme === "dark" ? "#333" : "#eee"` — theme ke according background color

> **What It Is NOT:** Context API **global state management nahi hai** — yeh ek dependency injection mechanism hai. Redux/Zustand ki tarah iska apna koi store/cache nahi hai. Sirf React component tree ke andar value pass karta hai bina props ke. Agar complex state management chahiye, Context + useReducer ya Zustand use karo.

**TEST:** Browser mein Navbar dekh — light mode mein "#eee" background. Theme toggle button dabao, theme change ho jata hai, Navbar ka background "#333" ho jata hai. ✅

## Step 5 — Custom Hook: `useTheme()` (Safe Pattern)

Har component mein `useContext(ThemeContext)` + `if (!ctx) throw` likhna repetitive hai. Isse ek custom hook mein wrap karte hain taaki har jagah reuse ho.

**SOCH:** Har component mein same `useContext` + guard code likhna repetitive hai. Isse ek custom hook mein wrap karo taaki har jagah reuse ho.

**CONCEPT — Custom hook:** Koi bhi function jo `use` se start hoti hai, usko React mein hook kehte hain. Custom hook ek wrapper function hai jisme existing hooks use kar sakte hain.

**FILE:** Yeh code `contexts/ThemeContext.tsx` mein hi likhenge — wahi pehle se `ThemeContext`, `Theme`, aur `ThemeContextValue` defined hain. Isliye `ThemeContext` ko import karne ki zaroorat nahi — woh already isi file mein hai. Sirf `useContext` React se import karna hoga.

```tsx
import { createContext, useContext } from "react";

export type Theme = "light" | "dark";

export interface ThemeContextValue {
  theme: Theme;
  toggleTheme: () => void;
}

export const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);

export function useTheme(): ThemeContextValue {
  const ctx = useContext(ThemeContext);
  if (!ctx) {
    throw new Error("useTheme must be used within a ThemeProvider");
  }
  return ctx;
}
```

**Line by line:**
- `import { createContext, useContext } from "react"` — ab `useContext` bhi import karna hoga
- `export function useTheme(): ThemeContextValue` — custom hook. `ThemeContextValue` return type specify kiya
  - `useTheme` naam — React convention: custom hooks `use` se shuru hote hain
- `const ctx = useContext(ThemeContext)` — context se value nikaal rahe hain. `ThemeContext` yahan defined hai, alag import ki zaroorat nahi
- `if (!ctx) throw new Error(...)` — guard pattern
- `return ctx` — safe value. TypeScript ab jaanta hai ki yeh `ThemeContextValue` hai, `undefined` nahi

**Ab Navbar mein use karo (import karna mat bhoolna) — full file:**
```tsx
// src/components/Navbar.tsx
import { useTheme } from "../contexts/ThemeContext";

export default function Navbar() {
  const { theme, toggleTheme } = useTheme();

  return (
    <nav style={{ background: theme === "dark" ? "#333" : "#eee", padding: "1rem" }}>
      <h1>My App</h1>
      <button onClick={toggleTheme}>
        Switch to {theme === "light" ? "Dark" : "Light"} Mode
      </button>
    </nav>
  );
}
```

Dekho — ab `useContext` aur guard pattern alag se likhne ki zaroorat nahi. `useTheme()` ke andar sab hai. Component sirf apna kaam karta hai. `toggleTheme` function bhi context se mil gaya — alag se prop pass nahi karna pada.

**TEST:** koi bhi component `useTheme()` call karega, automatically guard check ho jayega. ✅

## Step 6 — `ThemeProvider` Component (in contexts/ThemeContext.tsx)

Step 5 mein custom hook `useTheme()` banaya. Lekin provider logic bhi alag component mein extract kar sakte hain.

**SOCH:** Abhi App component mein saara provider logic hai — state, toggle function, context wrap. Better hai ek alag `ThemeProvider` component banao jo sirf provider ka kaam kare.

**CONCEPT — Separation of concerns:** Ek component ka ek kaam. ThemeProvider ka kaam hai sirf theme state rakhna aur context provide karna. App ka kaam hai layout banana.

**FILE:** `ThemeProvider` bhi `contexts/ThemeContext.tsx` mein hi banayenge — kyunki ise `ThemeContext`, `Theme`, aur `useTheme` (jo abhi add karenge) sab chahiye, aur yeh sab already isi file mein hain. Ek hi file mein sab context-related logic rakhna clean pattern hai.

```tsx
import { createContext, useContext, useState, type ReactNode } from "react";

export type Theme = "light" | "dark";

export interface ThemeContextValue {
  theme: Theme;
  toggleTheme: () => void;
}

export const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);

export function useTheme(): ThemeContextValue {
  const ctx = useContext(ThemeContext);
  if (!ctx) {
    throw new Error("useTheme must be used within a ThemeProvider");
  }
  return ctx;
}

interface ThemeProviderProps {
  children: ReactNode;
}

export function ThemeProvider({ children }: ThemeProviderProps) {
  const [theme, setTheme] = useState<Theme>("light");

  const toggleTheme = () => {
    setTheme((prev) => (prev === "light" ? "dark" : "light"));
  };

  return (
    <ThemeContext value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext>
  );
}
```

**Line by line:**
- `import { ..., useState, type ReactNode } from "react"` — ab `useState` aur `ReactNode` bhi import hue
- `interface ThemeProviderProps` — props ka blueprint
  - `children: ReactNode` — koi bhi React content accept karega
- `export function ThemeProvider` — component export kar rahe hain
- `const [theme, setTheme] = useState<Theme>("light")` — state yahan rahega
- `toggleTheme` function — same toggle logic
- `<ThemeContext value={{ theme, toggleTheme }}>` — children ko context wrap kiya
- `{children}` — aage ke saare components render honge

**Ab App.tsx ka use karna kaise hoga (import karna mat bhoolna):**
```tsx
import { ThemeProvider } from "./contexts/ThemeContext";
import Navbar from "./components/Navbar";

function App() {
  return (
    <ThemeProvider>
      <Navbar />
    </ThemeProvider>
  );
}
```

**TEST:** Sab components ab `useTheme()` se access kar sakte hain. App clean ho gaya. ✅

### Phase 3 — Dynamic Styles Based on Theme

**SOCH:** Ab styles hardcoded hain — `background: "#fff"` always white. Theme ke according background change hona chahiye. Ek styles object banao jisme light aur dark dono ke liye values hon.

**CONCEPT — Conditional styles:** `Record<string, React.CSSProperties>` ek type hai jo keys mein string leta hai aur values mein CSS properties ka object. Isme light aur dark dono keys ke under apne styles rakh sakte hain. Phir `styles[theme]` se current theme ke according style apply kar sakte hain.

**CONCEPT — Spread operator in styles:** `{...styles[theme]}` matlab — current theme ke saare CSS properties ko div ke style mein spread kar do. Ek saath background, color, border sab apply ho jayega.

**FILE:** `src/components/ThemedBox.tsx` — import same rahega, sirf JSX aur styles change hue.

```tsx
import { useTheme } from "../contexts/ThemeContext";

export default function ThemedBox() {
  const { theme, toggleTheme } = useTheme();

  const styles: Record<string, React.CSSProperties> = {
    light: { background: "#fff", color: "#000", border: "1px solid #ddd" },
    dark: { background: "#1a1a2e", color: "#fff", border: "1px solid #333" },
  };

  return (
    <div style={{ padding: "40px", ...styles[theme] }}>
      <h2>Current Theme: {theme}</h2>
      <button onClick={toggleTheme}>
        Switch to {theme === "light" ? "Dark" : "Light"} Mode
      </button>
      <p style={{ marginTop: "20px" }}>
        This box uses Context for theming — no props drilling!
      </p>
    </div>
  );
}
```

**Line by line:**
- `const styles: Record<string, React.CSSProperties>` — styles object banaya
  - `Record<string, ...>` matlab keys string hain ("light", "dark")
  - `React.CSSProperties` built-in TypeScript type for CSS inline styles
- `light: { background: "#fff", color: "#000", border: "1px solid #ddd" }` — light mode styles
- `dark: { background: "#1a1a2e", color: "#fff", border: "1px solid #333" }` — dark mode styles
- `{ padding: "40px", ...styles[theme] }` — padding fixed hai, baaki styles theme ke according spread
- `theme === "light" ? "Dark" : "Light"` — button text bhi dynamic

## Step 8 — Context API: Kab Use Karein, Kab Avoid Karein

Dekho, Context API powerful hai but har cheez isme daalna emotional decision hai — maine bhi yeh galti ki hai. Yeh rule follow karo:

### Use Context For:
- Theme (dark/light)
- Auth user
- Locale/language
- Any data almost har component ko chahiye

### Avoid Context For:
- High-frequency updates (animations, real-time data) — poora subtree re-render hota hai
- Data sirf 2-3 components ko chahiye — lifting state up kaafi hai
- Complex state logic — Context + useReducer milega, lekin Zustand better hai (Batch 6)

## Step 9 — Performance Note: useMemo se Context Value Stable Rakho

Yaar yeh woh cheez hai jo maine bahut baar bhooli hai.

**SOCH:** Context value change → saare consuming components re-render. Socho: ThemeProvider render hua → naya `{ theme, toggleTheme }` object bana (naya reference) → saare children re-render ho gaye, chahe theme change na hui ho. Yeh unnecessary hai.

**CONCEPT — Object references in React:** Jab bhi tum ek naya object banate ho `{ theme, toggleTheme }`, React usko naya samjhta hai kyunki memory location different hai. Agar pehle wale object se compare karo toh reference different hai → re-render trigger ho jata hai.

**CONCEPT — useMemo hook:** Ye hook memoization karta hai — matlab jab tak dependencies change nahi, wahi purana object reference aur stored value deta hai. Naya object nahi banata.

```tsx
import { useMemo, useCallback } from "react";

function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<Theme>("light");
  const toggleTheme = useCallback(() => {
    setTheme((prev) => (prev === "light" ? "dark" : "light"));
  }, []);

  const value = useMemo(() => ({ theme, toggleTheme }), [theme]);

  return (
    <ThemeContext value={value}>{children}</ThemeContext>
  );
}
```

**Line by line:**
- `const toggleTheme = useCallback(..., [])` — function reference stable rakho
  - `useCallback` function ko memoize karta hai
  - Empty dependency array `[]` matlab kabhi naya function nahi banega
- `const value = useMemo(() => ({ theme, toggleTheme }), [theme])` — object memoize kiya
  - `useMemo` mein callback function hai jo object return karta hai
  - `[theme]` dependency array — sirf jab theme change hoga tabhi naya object
- `value={value}` — ab stable reference pass ho raha hai

**TEST:** React DevTools mein Components tab kholo — ThemeProvider expand karo. Jab theme change karo, sirf ThemeProvider re-render hoga, baaki children nahi. ✅

## Trade-off: Context vs Alternatives

| Pattern | Use Case | Problem |
|---|---|---|
| **Lifting State Up** | 2-3 siblings share state | Prop drilling in deep trees |
| **Composition** | Deep tree, middle components don't need data | Can't solve every case |
| **Context API** | Global data (theme, auth, locale) | High-frequency updates → full subtree re-render |
| **Zustand/Redux** (Batch 6) | Complex state, high performance | Extra boilerplate, learning curve |

**Rule of thumb:** Lift first. Compose second. Context third. Zustand when Context's re-render becomes a problem.

---

## Common Mistakes

1. **Provider bhoolna** — Context value `undefined` rahega. Custom hook guard se clear error milega.
2. **Har cheez Context mein daalna** — Sirf woh data jo almost har component ko chahiye (theme, auth). 2-3 components ke liye lifting up kaafi hai.
3. **High-frequency updates Context mein** — Har update pe poora subtree re-render. Jaise real-time stock price — Context mat use karo, Zustand ya external store lo.
4. **useMemo bhoolna** — Context value object/function hai toh har render pe naya reference. `useMemo` se wrap karo taaki unnecessary re-renders na ho.

   Har render pe `{ theme, toggleTheme }` naya object banega (naya reference). Saare consuming components re-render honge chahe theme change na hui ho. `useMemo` se yeh problem solve hoti hai.
   </details>
