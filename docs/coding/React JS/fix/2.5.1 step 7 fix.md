## The roles of `isActive` and `onToggle`

Two different things are happening here.

### `onToggle`

Changes the state when the button is clicked.

### `isActive`

Looks at the state and decides whether the panel should show as open or not.

Both use `activeIndex`, but their **jobs are different**.

This does **not** change the state.

```tsx

This **changes** the state.

Logic:

```

Otherwise

## Most Important Point

Both `onToggle` and `isActive` use `activeIndex`, but their jobs are different.

* `onToggle` → **updates the state.**
* `isActive` → **renders the UI based on the updated state.**

So the flow is: first **button click → state update → React re-render → `isActive` evaluated → panel opens/closes.**

## Why was this expression written??

Look at the `Panel` component first.

```tsx
function Panel({
    isActive
}: {
    isActive: boolean
})
```

Notice.

**What does Panel need?**

```tsx
boolean
```

That's it.

It doesn't matter at all where the boolean came from.

It just needs to receive

```tsx
true
```

or

```tsx
false
```

---

So in Step 6 we were passing it directly

```tsx
isActive={isActive}
```

because

```tsx
isActive
```

was already a boolean.

---

But in Step 7

we now have

```tsx
activeIndex
```

This is not a boolean.

It is

```tsx
null

0

1
```

Now the problem.

Panel needs

```tsx
true

false
```

But we have

```tsx
0

1

null
```

So what do we do?

**Convert.**

---

We compare.

```tsx
activeIndex === 0
```

What does this return?

```tsx
true
```

or

```tsx
false
```

Exactly what Panel needs.

---

That's why

```tsx
isActive={activeIndex === 0}
```

was written.

**NOT because React wants it.**

**Because Panel wants a boolean.**

---

This line is actually this:

```tsx
const panel1IsOpen = activeIndex === 0;

<Panel
    isActive={panel1IsOpen}
/>
```

Both are the same.

We just didn't create a variable.

We wrote it inline.
