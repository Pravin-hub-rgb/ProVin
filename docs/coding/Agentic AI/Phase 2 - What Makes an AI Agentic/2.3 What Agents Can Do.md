You now know the loop. But the loop needs something to act *on*. That's where **tools** come in.

A tool is just a capability the agent can invoke. Think of it as a function the model can call. The model doesn't magically *become* a file system — it makes a request to a tool that knows how to read and write files. The model doesn't *become* a web browser — it calls a tool that goes and fetches a page.

Here's a list of common tools you'll see agents using today:

| Tool | What it does | Why an agent needs it |
|------|-------------|----------------------|
| Read/write files | Create, edit, delete files on your machine | This is how Cline writes your code |
| Run commands | Execute shell commands, scripts, install packages | This is how Cline runs `npm install` or `git commit` |
| Search the web | Look up current information | For research, finding docs, checking APIs |
| Call APIs | Make HTTP requests to external services | Send emails, update databases, post to Slack |
| Browse web pages | Click links, fill forms, read rendered pages | For testing your app or scraping data |
| Query databases | Run SQL queries against a database | Pull customer data, update records, generate reports |
| Call other AI models | Ask another model for help | Use a specialized model for images, audio, or translation |

Every tool has three parts:
- A **name** (like `read_file`)
- Some **parameters** (like `filepath: "src/index.js"`)
- A **return value** (like the contents of the file)

The agent's job is to pick the right tool with the right parameters at the right time.

You've seen most of these in Cline already. Cline can read your files, write new ones, run terminal commands, search for patterns in your code, and even use the web. Every one of those is a tool. When Cline asks for permission before running a command, it's showing you which tool it wants to call and what parameters it plans to use.

This is also why agents need good context windows (remember Phase 1?). Every tool result gets fed back into the model's context as the "Observe" step. A tool that returns a huge file or a long web page eats up tokens. Managing that is part of what makes agent design hard.

---

Having tools is one thing. Knowing what to do with them is another. That's where planning comes in.
