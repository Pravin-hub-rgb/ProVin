You now understand the pieces: the model predicts tokens, those tokens fit in a context window. But when you type a message and hit enter, what actually happens between your keyboard and the response appearing on screen?

Let's trace the full path, step by step.

**Step 1: You type a message**

Your AI tool (Cline, opencode, ChatGPT web — doesn't matter) takes whatever you wrote and collects the context. That means your current message plus the conversation history, system prompt, any attached files. Everything that needs to fit in the context window.

**Step 2: Tokenization**

That raw text gets converted into tokens. The tool runs it through a tokenizer — remember those sub-word chunks from earlier — and produces a sequence of numbers. Because models don't read text. They read numbers. Every token maps to a numeric ID.

**Step 3: The API call**

Here's where the magic of modern AI shows up. The model isn't running on your laptop. It's running on a server in a data center somewhere — owned by OpenAI, Anthropic, Google, or whoever provides the model. To talk to that server, your tool sends an **API request**.

API stands for Application Programming Interface. In plain English: it's a door. Your tool knocks on a specific URL (like `api.anthropic.com/v1/messages`) and hands over a structured package of data.

That package looks something like this (simplified):

```json
{
  "model": "claude-sonnet-4-20250514",
  "messages": [
    {"role": "system", "content": "You are a senior software engineer..."},
    {"role": "user", "content": "Write a function that sorts an array"}
  ],
  "max_tokens": 4096,
  "temperature": 0.3
}
```

This is the request body. It's JSON — a simple data format. It says which model to use, what the conversation is, how long the response can be, and how creative it should be (more on that last one soon).

**Step 4: Authentication and billing**

Your API key is in the header of that request. It's how the provider knows it's you, that you have credits, and that you haven't hit your rate limit. No API key? No response. That's also why you should never, ever commit an API key to a public repo — anyone who steals it can bill you.

**Step 5: The model processes**

The provider's server receives the tokens, feeds them through the model, and starts generating a response — one token at a time, the same "what comes next" prediction we talked about in file 1.1.

**Step 6: Streaming the response**

Most modern AI tools use something called **streaming**. Instead of waiting for the full response to be ready, the server sends tokens back as soon as they're generated — like watching someone type in real time. That's why you see the response appear word by word instead of all at once. Your tool receives each token, converts it back to text, and displays it.

**Step 7: Your tool shows it to you**

The tokens are decoded back into readable text, and the response appears in your chat window. One round trip complete.

The whole sequence usually takes a few seconds. From your keyboard, to a data center possibly across the world, through billions of calculations, and back to your screen.

One more thing: because this all happens over HTTP (the same protocol websites use), it can fail just like a website can. Network timeout, server overload, API rate limit exceeded — you've probably seen some of these errors in your tool. Now you know exactly where in the pipeline they happen.

The request body I showed you had a field called `temperature`. That's one of the most important knobs you can turn when working with AI. It controls how deterministic or creative the model's predictions are. That's its own topic, and a good one to end Phase 1 with.
