# 3.5 Handling Errors

Things will go wrong. Your API key will be invalid. You'll hit rate limits. The network will drop. The model will be overloaded. If you don't handle these gracefully, your app crashes and your users see a cryptic error message.

Let's look at what goes wrong and how to handle it.

## Wrong API Key

Run this:

```javascript
import Anthropic from "@anthropic-ai/sdk";
import dotenv from "dotenv";
dotenv.config();

const client = new Anthropic({ apiKey: "sk-ant-not-a-real-key" });

const message = await client.messages.create({
  model: "claude-sonnet-4-20250514",
  max_tokens: 1024,
  messages: [
    { role: "user", content: "Say hello." }
  ],
});
```

You'll get something like:

```
AnthropicError: 401 {"type":"error","error":{"type":"authentication_error","message":"Invalid API key"}}
```

A `401` status code means "unauthorized". The API got your request but doesn't recognize your key. This is an **authentication error** — your key is wrong, expired, or missing.

## Rate Limits

If you hammer the API with too many requests too quickly, you'll get a `429` status code:

```
AnthropicError: 429 {"type":"error","error":{"type":"rate_limit_error","message":"Rate limit exceeded. Please retry after 5 seconds."}}
```

Rate limits exist so one user can't overload the service. They vary by tier (free vs paid) and model. When you hit one, you need to wait and retry.

## Basic Error Handling with try/catch

The simplest way to handle errors is a `try/catch` block:

```javascript
import Anthropic from "@anthropic-ai/sdk";
import dotenv from "dotenv";
dotenv.config();

const client = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });

async function askModel(prompt) {
  try {
    const message = await client.messages.create({
      model: "claude-sonnet-4-20250514",
      max_tokens: 1024,
      messages: [
        { role: "user", content: prompt }
      ],
    });
    return message.content[0].text;
  } catch (error) {
    console.error("API call failed:", error.message);
    return "I'm sorry, I couldn't process that request.";
  }
}

const response = await askModel("What is the meaning of life?");
console.log(response);
```

The `try` block attempts the API call. If it succeeds, the function returns the response text. If it throws an error (network failure, invalid key, rate limit), execution jumps to the `catch` block, where we log the error and return a fallback message.

This is the absolute minimum. In a real app, you'd want to do different things for different error types.

## Handling Specific Errors

The Anthropic SDK throws `AnthropicError` objects with a `status` property. Let's handle each case differently:

```javascript
import Anthropic from "@anthropic-ai/sdk";
import dotenv from "dotenv";
dotenv.config();

const client = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });

async function askModel(prompt) {
  try {
    const message = await client.messages.create({
      model: "claude-sonnet-4-20250514",
      max_tokens: 1024,
      messages: [
        { role: "user", content: prompt }
      ],
    });
    return message.content[0].text;
  } catch (error) {
    if (error.status === 401) {
      return "Your API key is invalid. Check your .env file.";
    }
    if (error.status === 429) {
      console.warn("Rate limited. Waiting 5 seconds...");
      await new Promise(resolve => setTimeout(resolve, 5000));
      return askModel(prompt);
    }
    if (error.status === 400) {
      return "Bad request. Check your parameters.";
    }
    return `Unexpected error: ${error.message}`;
  }
}

const response = await askModel("What is the capital of Japan?");
console.log(response);
```

Here's what's going on:

- **401**: The API key is wrong. There's no point retrying — the user needs to fix the key.
- **429**: Rate limited. We wait 5 seconds (with a simple `setTimeout` wrapped in a Promise), then **retry the function recursively**. This is a basic retry strategy. In production you'd use exponential backoff and cap the number of retries.
- **400**: Bad request — your prompt may be too long, or your parameters invalid.
- **Everything else**: Network errors, server errors (5xx), etc. Log it and return a generic message.

## Why This Matters for Agents

When you build an agent (Phase 4 territory), it might make dozens or hundreds of API calls in sequence. If any one of those calls fails and you're not handling errors, the whole chain breaks. Rate limits are especially common when an agent is rapidly calling tools and feeding results back to the model.

Good error handling is what separates a demo from something you'd actually run in production.
