# 3.6 AI Parse Lab — Hinglish Order Parser (TypeScript)

> **Prerequisite:** Complete 3.1–3.5 (API setup, messages array, raw response, errors)
> **Bridge ahead:** `Career/TRADESTACK-DEFENSE-KIT.md` → M5 (operate DukaanOS) and `DUKAANOS-AI-DEFENSE-KIT.md`

That last call in 3.5 — it worked, it parsed, it returned something useful. But what happens when the model fails? Or returns nothing? Or the prompt is slightly off and you get garbage instead of structured data?

In DukaanOS, this isn't a theoretical problem — it's the core of the voice-order pipeline. The real code in `Dukaan_OS/src/actions/voice.ts` uses a **two-tier system**: Tier 1 tries the LLM; Tier 2 (regex fallback) catches the failure. No fallback = broken checkout = lost revenue.

This lab rebuilds that system in ~150 lines. You'll feel exactly why the fallback exists.

---

## What You Build

A CLI that parses Hinglish order text into structured items:

```bash
# LLM tier works
tsx index.ts "do kilo aloo, 10 rupee ki bhindi" --engine llm

# Fallback tier works (LLM disabled)
tsx index.ts "do kilo aloo, 10 rupee ki bhindi" --engine regex

# Auto degrades gracefully
tsx index.ts "do kilo aloo, 10 rupee ki bhindi" --engine auto
```

Output:
```
[{ name: "aloo", qty: 2, unit: "kilo" }, { name: "bhindi", qty: 10, unit: "rupee" }]
```

## File 1 — `prompt.ts` (the Tier 1 prompt)

A simplified version of DukaanOS's real pipe-format prompt. The LLM must return items in this exact format:

```
name|qty|unit
```

Lines are pipe-delimited. Empty response (no items) is valid — means "nothing parsed."

```typescript
// prompt.ts
export const SYSTEM_PROMPT = `Extract shopping items from the Hinglish text. Return ONLY pipe-delimited lines: name|qty|unit. One item per line. If nothing found, return nothing. No headings, no prose, no JSON.

Examples:
do kilo aloo, 10 rupee ki bhindi →
aloo|2|kilo
bhindi|10|rupee
`;
```

## File 2 — `llm.ts` (call the model)

Uses the same API pattern from 3.1–3.4. Temperature 0.1 (deterministic), stop sequence `\n\n` (ends response when items are done).

```typescript
// llm.ts
import 'dotenv/config';

export async function parseWithLLM(text: string): Promise<string | null> {
  const res = await fetch('https://api.groq.com/openai/v1/chat/completions', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.GROQ_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      model: 'openai/gpt-oss-20b',
      temperature: 0.1,
      stop: ['\n\n'],
      messages: [
        { role: 'developer', content: SYSTEM_PROMPT },
        { role: 'user', content: text },
      ],
    }),
  });

  if (!res.ok) return null;
  const data = await res.json();
  return data.choices?.[0]?.message?.content?.trim() ?? null;
}
```

## File 3 — `fallback.ts` (the Tier 2 regex parser)

This is your safety net. It handles Hindi number words, a few brand corrections, and basic `product|qty|unit` extraction.

```typescript
// fallback.ts
const HINDI_NUMBERS: Record<string, number> = {
  'ek': 1, 'do': 2, 'teen': 3, 'char': 4, 'paanch': 5,
  'saat': 7, 'aath': 8, 'nau': 9, 'das': 10,
};

export function parseWithRegex(text: string): Array<{ name: string; qty: number; unit: string }> {
  const items: Array<{ name: string; qty: number; unit: string }> = [];
  const pairs = text.split(/,|\s+aur\s+/);

  for (const pair of pairs) {
    const numMatch = pair.match(/(\w+)\s+(\w+)/);
    if (!numMatch) continue;

    const qtyWord = numMatch[1].toLowerCase();
    const itemName = numMatch[2];
    const qty = HINDI_NUMBERS[qtyWord] || parseInt(qtyWord) || 1;

    items.push({ name: itemName, qty, unit: 'pcs' });
  }

  return items;
}
```

## File 4 — `index.ts` (CLI + two-tier logic)

```typescript
// index.ts
import { parseWithLLM } from './llm';
import { parseWithRegex } from './fallback';

function parsePipeResponse(text: string) {
  return text
    .split('\n')
    .map(line => line.split('|'))
    .filter(parts => parts.length === 3)
    .map(([name, qty, unit]) => ({ name, qty: Number(qty), unit }));
}

async function main() {
  const args = process.argv.slice(2);
  const input = args[0] ?? 'do kilo aloo, 10 rupee ki bhindi';
  const engine = args[1]?.replace('--engine=', '') ?? 'auto';

  let result;

  if (engine === 'llm') {
    const raw = await parseWithLLM(input);
    result = raw ? parsePipeResponse(raw) : [];
  }

  if (engine === 'regex') {
    result = parseWithRegex(input);
  }

  if (engine === 'auto') {
    // Tier 1: try LLM
    const raw = await parseWithLLM(input);
    if (raw && raw.length > 0) {
      result = parsePipeResponse(raw);
      console.log('Parsed via LLM');
    } else {
      // Tier 2: fallback
      result = parseWithRegex(input);
      console.log('Parsed via regex fallback');
    }
  }

  console.log(JSON.stringify(result, null, 2));
}

main();
```

## Done When

- [ ] LLM path parses a two-item Hinglish order correctly
- [ ] Fallback path parses the same order with LLM disabled (rename `.env` key temporarily)
- [ ] `auto` degrades gracefully — no crash, fallback engaged
- [ ] 90-second explanation includes these three points:
  1. **Pipe format**: `name|qty|unit` is machine-friendly — delimiter is unambiguous, parses in one split
  2. **Temperature 0.1**: low randomness — deterministic for parsing (same input = same output)
  3. **Fallback exists because**: AI is an enhancement, not a dependency — it can fail or return nothing
