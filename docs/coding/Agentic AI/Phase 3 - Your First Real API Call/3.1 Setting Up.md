# 3.1 Setting Up

In Phase 2, you learned what agents are and what they can do. But so far it's all been theory. Let's get our hands dirty. We're going to make an actual API call to an AI model.

No abstractions. No "the model thinks" hand-waving. You, your terminal, and a raw HTTP response.

## What You Need

First, you need an API key. Since you use Claude, we'll use Anthropic. Go to https://console.anthropic.com/ and create an account if you haven't already. Once you're in, navigate to the API Keys section and create a new key. Copy it and keep it somewhere safe — you'll never see it again once you close the dialog.

**Never hardcode your API key in your source code.** If you commit it to GitHub, bots will find it within minutes and rack up a bill on your account. We'll use a `.env` file instead.

## Project Setup

Create a new directory and initialize a Node.js project:

```bash
mkdir my-first-api-call
cd my-first-api-call
npm init -y
```

The `-y` flag accepts all the defaults. You'll get a `package.json` file. Open it and add `"type": "module"` so we can use `import` syntax instead of `require`:

```json
{
  "name": "my-first-api-call",
  "type": "module",
  ...
}
```

Now install the two packages we need:

```bash
npm install @anthropic-ai/sdk dotenv
```

- `@anthropic-ai/sdk` is the Anthropic SDK — a JavaScript library that wraps their HTTP API so you don't have to manually construct requests and parse responses.
- `dotenv` lets you load environment variables from a `.env` file.

## What's an SDK?

You could call the Anthropic API directly with `fetch()` or `curl`. You'd construct a JSON payload, set headers manually, parse the response — it's doable but tedious. An SDK is just a convenience wrapper. It handles authentication, serialization, error formatting, and TypeScript types. Under the hood it's still making HTTP calls to the same API endpoints.

Think of it like ordering at a restaurant vs cooking in the back. The SDK is the waiter — you tell it what you want, it brings the food. You don't need to know what the chef is doing.

## The `.env` File

Create a file called `.env` in your project root:

```
ANTHROPIC_API_KEY=sk-ant-...
```

Make sure `.env` is in your `.gitignore`:

```bash
echo ".env" >> .gitignore
```

Now create `index.js` with this skeleton:

```javascript
import Anthropic from "@anthropic-ai/sdk";
import dotenv from "dotenv";
dotenv.config();

const client = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });

// We'll fill this in next
```

Run it (it won't do anything yet):

```bash
node index.js
```

If it doesn't crash, everything is wired up correctly.

Now let's actually call the model.

## What It Is NOT

An API key is NOT a user account password. A password lets you log into a website interactively. An API key lets a program authenticate itself to a service programmatically. They serve different purposes — you'd never put your email password in a `.env` file, but an API key is designed to be stored that way (just never commit it to Git).

The SDK is also NOT required to make API calls. You could use `fetch()` or `curl` with the same endpoint and get the same result. The SDK is a convenience layer, not a gate. If you understand the raw HTTP API, you understand everything the SDK does under the hood.

### In Your Own Words

<details>
<summary>1. What problem does the SDK solve? What would the alternative look like?</summary>

**Sample Answer:** The SDK saves you from manually constructing HTTP requests, setting authorization headers, and parsing JSON responses. Without it, you'd write a raw `fetch()` call with headers like `x-api-key` and `anthropic-version`, then parse the JSON body yourself. The SDK is like a food delivery app — you just say what you want, and it handles all the kitchen logistics.

</details>

<details>
<summary>2. Why should you never hardcode your API key in source code? What's a real scenario where this could go wrong?</summary>

**Sample Answer:** Hardcoding an API key means it's part of your codebase — committed to Git, pushed to GitHub, visible to anyone who clones the repo. Bots crawl public repos for exposed keys constantly. A real scenario: you push a project to GitHub as a learning portfolio piece, a bot finds your Anthropic key within hours, scripts it to generate spam, and you wake up to a surprise bill.

</details>

<details>
<summary>3. What's the difference between the `.env` file and a regular JavaScript config file?</summary>

**Sample Answer:** A `.env` file stays on your machine — it's listed in `.gitignore` so it never enters version control. A JavaScript config file gets committed and shared with everyone. This matters because you might have different keys for development, staging, and production. The `.env` file lets each environment provide its own values without changing code — it's separation of config from code.

</details>

<details>
<summary>4. If you were building an app that calls multiple AI providers (Anthropic, OpenAI, etc.), how would you structure your env variables?</summary>

**Sample Answer:** Use descriptive prefixes: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GOOGLE_API_KEY`. This keeps your `.env` file organized and makes the code self-documenting — you know exactly which provider a variable belongs to. Don't use generic names like `API_KEY` — they'll collide when you add a second provider and you won't know which one broke.

</details>

<details>
<summary>5. Why do we need `"type": "module"` in `package.json`? What's the alternative?</summary>

**Sample Answer:** Without `"type": "module"`, Node.js assumes CommonJS format, which uses `require()` instead of `import`. The alternative is to use CommonJS syntax (`const Anthropic = require("@anthropic-ai/sdk")`) or rename your file to `.mjs`. We use `"type": "module"` because `import` is the modern ES module standard and integrates better with the SDK's TypeScript types.

</details>
