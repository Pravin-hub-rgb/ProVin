# 3.2 Hello World — Your First API Call

You've got your project set up, your API key in a `.env` file, and the SDK installed. Now let's make the model talk.

Replace the contents of `index.js` with this:

```javascript
import Anthropic from "@anthropic-ai/sdk";
import dotenv from "dotenv";
dotenv.config();

const client = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });

const message = await client.messages.create({
  model: "claude-sonnet-4-20250514",
  max_tokens: 1024,
  messages: [
    { role: "user", content: "Say hello in 10 words." }
  ],
});

console.log(message.content[0].text);
```

Run it:

```bash
node index.js
```

You should see something like:

```
Hello! I'm Claude, nice to meet you today.
```

You just made your first AI API call. Let's break down every single line.

## Line by Line

```javascript
import Anthropic from "@anthropic-ai/sdk";
import dotenv from "dotenv";
```

These import the SDK and the dotenv package. The `from` paths match the package names you installed with npm. Node.js knows to look in `node_modules` for them.

```javascript
dotenv.config();
```

This reads your `.env` file and populates `process.env` with its contents. After this line runs, `process.env.ANTHROPIC_API_KEY` is available.

```javascript
const client = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });
```

This creates a **client** object — an authenticated handle to the Anthropic API. The `apiKey` option is your secret key pulled from the environment. The client will attach this key to every request it makes. You create the client once and reuse it for all your calls.

```javascript
const message = await client.messages.create({ ... });
```

This is the actual API call. `client.messages.create()` is an async function — it sends a POST request to Anthropic's servers and waits for the response. The `await` keyword pauses execution until the server responds. Inside the object we pass the parameters:

- **`model`**: The model identifier. `"claude-sonnet-4-20250514"` is the latest Claude Sonnet model. Different models have different capabilities, speeds, and costs. You can find the full list in the Anthropic docs.
- **`max_tokens`**: The maximum number of tokens the model is allowed to generate. Tokens are roughly 3/4 of a word. Setting this to 1024 means the model will stop generating after roughly 750 words, even if it's not done.
- **`messages`**: An array of conversation turns. Each turn has a `role` (who said it) and `content` (what they said). Right now there's just one message from the user.

```javascript
console.log(message.content[0].text);
```

The response comes back as an object. `message.content` is an array of content blocks. For text responses, there's a single block with a `text` property. We access it and print it.

## The Full Response Object

When you log `message` instead of just `message.content[0].text`, you'll see something like this:

```javascript
{
  id: "msg_01ABCDEF1234",
  type: "message",
  role: "assistant",
  content: [
    {
      type: "text",
      text: "Hello! I'm Claude, nice to meet you today."
    }
  ],
  model: "claude-sonnet-4-20250514",
  stop_reason: "end_turn",
  stop_sequence: null,
  usage: {
    input_tokens: 14,
    output_tokens: 12
  }
}
```

This is the raw response. Let's look at each field:

- **`id`**: A unique identifier for this message. Useful for debugging and tracking.
- **`type`**: Always `"message"` for message responses.
- **`role`**: The role of the responder — always `"assistant"`.
- **`content`**: An array of content blocks. Right now it's one text block, but models can also return tool calls (we'll get to that in Phase 4).
- **`model`**: Which model generated the response. Confirms your request used the right model.
- **`stop_reason`**: Why the model stopped generating. `"end_turn"` means it finished naturally. Other values are `"max_tokens"` (hit the limit), `"stop_sequence"` (found a custom stop sequence), or `"tool_use"` (wants to call a tool).
- **`usage`**: Token counts. `input_tokens` is how many tokens your prompt consumed. `output_tokens` is what the model generated. This is how you get billed — by the token.

## Why This Matters

Every AI coding tool — Cline, Kodu, opencode, cursor — makes calls like this under the hood. The difference is they do it over and over, in loops, with tool results fed back in. But the fundamental building block is always the same: you send messages, you get a response.

The magic is gone. You're just passing JSON back and forth.
