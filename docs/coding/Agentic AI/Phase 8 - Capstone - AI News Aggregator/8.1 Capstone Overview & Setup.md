## What We're Building

A system that **runs automatically once a day** and does:

1. **Scrape** — new content from some sources (YouTube channel RSS, Anthropic blog, OpenAI blog)
2. **Store** — in a Postgres database
3. **Aggregator Agent** — ranks the new items against your profile ("I care about agentic AI, tool calling, MCP")
4. **Digest Agent** — writes a small daily summary from the top-ranked items
5. **Deploy + schedule** — for free, running every day without you touching it

**AI News Aggregator** — this is a complete system, not a single script. And three features make it a "real system" that Phase 6's projects didn't have:
- **Persistence** (database — data is saved, not recreated every time)
- **Multiple cooperating agents** (aggregator → digest, two different agents working together)
- **Real deployment + schedule** (runs every day without a trigger)

In an interviewer's eyes, these three things are what separate a "toy script" from a "real system".

## Setup — Accounts and Keys (Day 1)

Let's get started. Three accounts to create:

### 1. Groq (LLM)
- Open [console.groq.com](https://console.groq.com) — free signup, no card
- Create an API key (API Keys → Create)
- Keep it as `GROQ_API_KEY`
- **Note:** Groq is OpenAI-compatible — if you used OpenAI SDK style in Phase 3-4, the code barely changes (just base URL + key swap)

### 2. Supabase (Database)
- [supabase.com](https://supabase.com) — create a free project
- From the project dashboard, **Project Settings → Database → Connection string**, get your `DATABASE_URL`
- Keep it safe

### 3. Node.js Project
In the terminal:

```bash
mkdir ai-news-aggregator
cd ai-news-aggregator
npm init -y
```

Now install packages:

```bash
npm install dotenv rss-parser pg groq-sdk
npm install -D nodemon
```

| Package | What it is |
|---|---|
| `dotenv` | Loads secrets from `.env` file |
| `rss-parser` | Parses RSS feeds (for scraping) |
| `pg` | Postgres client — raw SQL queries |
| `groq-sdk` | SDK to talk to Groq's LLM |

> **Drizzle ORM?** In the capstone we'll use `pg` + raw SQL (it's directly understandable). Drizzle/Prisma will be mentioned in 8.4 as a "better option" — first understand the raw way, then better.

### 4. `.env` File

Create `.env` in the project root:

```bash
# .env (never commit this!)
GROQ_API_KEY=your_groq_key_here
DATABASE_URL=postgresql://your_supabase_connection_string
```

And create `.gitignore`:

```gitignore
# .gitignore
node_modules
.env
```

**Critical rule:** `.env` is **never** pushed to Git. `node_modules` neither. Both are in `.gitignore` — so safe.

### 5. Scripts Setup

Add scripts to `package.json`:

```json
{
  "scripts": {
    "scrape": "node scrapers/index.js",
    "rank": "node agents/aggregator.js",
    "digest": "node agents/digest.js",
    "run": "node index.js"
  }
}
```

(These scripts will be created later — for now just the names are confirmed.)

## First Test — Is the Environment Running?

Create a small test file — check that keys are loading:

```javascript
// test-env.js
require('dotenv').config();

console.log("GROQ_API_KEY set:", Boolean(process.env.GROQ_API_KEY));
console.log("DATABASE_URL set:", Boolean(process.env.DATABASE_URL));
```

Run it:

```bash
node test-env.js
```

Both should show `true`. If `false` appeared — the keys in `.env` are written wrong, or dotenv isn't loading.

> **Tip:** Never `console.log` a full secret — only check "is it set or not" with `Boolean(...)`. Secrets must not leak into logs.

## Common Mistakes

- ❌ Committing `.env` to Git — secrets leak. It's in `.gitignore`, confirm it.
- ❌ Hardcoding keys in code — use `process.env.KEY` only.
- ❌ Putting `.env` somewhere other than project root — dotenv looks in root.
- ❌ Testing keys with `console.log` — check only with `Boolean()`.
- ❌ Installing both `pg` and `drizzle` (confusion) — first understand raw SQL with `pg`, you can upgrade later.

## What It Is NOT

⚠️ **This is not just "another LLM call" project.** The LLM is used only in 2 agents — the rest of the system is scraping, database, scheduling. **The LLM is a small part of it, not the whole system.**

⚠️ **This is not a web app.** No UI, no frontend — a background system that runs every day and produces output. (You can add a web UI later if you want.)

⚠️ **RSS = not just blogs.** YouTube channels also give RSS (free, no key). That's why scraping is easy.

⚠️ **Supabase = not just "database hosting".** It has a visual table editor, auth, storage — everything. Here we'll use only the database.
