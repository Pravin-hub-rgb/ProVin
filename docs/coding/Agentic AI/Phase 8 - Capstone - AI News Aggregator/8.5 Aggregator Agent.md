In 8.4 data started being stored in the database. Now the real AI work begins — out of the articles that were scraped, which ones are **relevant to you**? Out of 100 articles, 5-6 will match your interests (agentic AI, tool calling, MCP). Finding them — not manually, but **with an agent**.

## What the Aggregator Agent Does

It looks at every unranked article and gives a **score from 1-10** against your profile, plus a one-line reason.

```
Input:  unranked articles (WHERE ranked = false)
Agent:  "how much does this article match my profile?"
Output: score (1-10) + reason, and ranked = true
```

**Profile example:** "interested in agentic AI, tool calling, MCP, multi-agent systems"

## Phase 4's Pattern — Tool Calling

As mentioned in 8.1 — this capstone **directly reuses** Phase 4's tool-calling pattern. Recall Phase 4.2 (Defining Tools) and 4.5 (Tool Calling Loop):

- The agent is given a **tool** — `score_article`
- The agent doesn't write the score in free text — it **calls the tool**
- This makes the output structured → easy to store in the database

Tool concept:

```
Tool: score_article
Arguments: { score: number (1-10), reason: string }
```

Structured tool call instead of free-text output — meaning score and reason are guaranteed to come in structured format. That's the "tool-calling pattern".

## Score Single Article — The Agent Loop

Here's the actual Phase 4 loop:

```javascript
const tools = [
  {
    type: 'function',
    function: {
      name: 'score_article',
      description: 'Score an article by relevance to my profile',
      parameters: {
        type: 'object',
        properties: {
          score: { type: 'integer', description: '1-10 relevance score' },
          reason: { type: 'string', description: 'One line why' },
        },
        required: ['score', 'reason'],
      },
    },
  },
];

async function scoreArticle(article) {
  const response = await client.chat.completions.create({
    model: 'llama-3.3-70b-versatile',
    messages: [
      { role: 'system', content: SYSTEM_PROMPT },
      {
        role: 'user',
        content: `Article title: ${article.title}\nContent: ${article.raw_content}`,
      },
    ],
    tools,
    tool_choice: 'required',  // agent MUST call the tool
  });

  const toolCall = response.choices[0].message.tool_calls[0];
  const args = JSON.parse(toolCall.function.arguments);
  return args;  // { score: 8, reason: "MCP directly relevant" }
}
```

**Understand the tool loop:**
1. Article sent in user message (title + content)
2. `tools` — gave the agent the score_article tool
3. `tool_choice: 'required'` — **compelled** the agent to call the tool (not free text)
4. `tool_calls[0]` in the response — the agent's structured tool call
5. `JSON.parse(function.arguments)` — extracted `{ score, reason }`

Recall Phase 4's loop — Think (agent thinks) → Act (tool call) → Observe (we take the result). Here it's simplified — only one tool call (no multi-step loop) because each article is independent.

## DB Update — Make ranked True

```javascript
const pool = require('../db');

async function updateScore(articleId, score, reason) {
  await pool.query(
    `UPDATE articles
     SET score = $1, reason = $2, ranked = true
     WHERE id = $3`,
    [score, reason, articleId]
  );
}
```

Now wire it into `processArticles`:

```javascript
const { updateScore } = require('../db/updateScore');

async function processArticles() {
  const articles = await getUnranked();
  for (const article of articles) {
    try {
      const result = await scoreArticle(article);
      await updateScore(article.id, result.score, result.reason);
      console.log(`[${result.score}] ${article.title}`);
    } catch (err) {
      console.error(`Failed for ${article.title}:`, err.message);
    }
  }
}

if (require.main === module) {
  processArticles().then(() => process.exit(0)).catch((e) => {
    console.error(e);
    process.exit(1);
  });
}
```

## Common Mistakes

- ❌ Forgetting `tool_choice: 'required'` — the agent returns free text, you don't get structured output
- ❌ `JSON.parse(function.arguments)` without try/catch — crashes on malformed JSON. Error handling is essential.
- ❌ Sending all articles without thinking about rate limits — Groq free tier ~30 req/min. Fine in a loop (12 articles), but add a delay at larger scale.
- ❌ Forgetting to update `ranked = true` — the same articles get ranked again next time
- ❌ DB update and score in the same try/catch — if the update fails, the score worked but didn't reach the DB. Log it.

## What It Is NOT

⚠️ **Aggregator = not "summary of the whole internet".** It only ranks the items that were scraped (in 8.3). It doesn't search on its own.

⚠️ **Score = not "the model's ground truth".** The score is the agent's profile-matching judgment — an educated guess. You can change score behavior by customizing the profile.

⚠️ **Tool calling = not "the agent writing code".** The agent CALLS the tool, you wrote the tool's code. Here `score_article` has no backend function — just the mechanism for structured output. (In Phase 4 tools had real functions — here score validation is enough.)

⚠️ **One article = one LLM call = not expensive.** Groq's free tier is far more than enough for 1 run/day (~12 calls). No money.
