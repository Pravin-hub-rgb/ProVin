## Error Handling — The Mark of a Real System

A system is production-grade only when it **handles failures**. What can go wrong? Source down, Groq rate-limit, DB timeout.

### In Scrapers — Per-Source try/catch

If one source is down, the whole pipeline shouldn't stop — the other sources should keep working:

```javascript
// scrapers/index.js
async function scrapeAll() {
  const sources = [
    youtube.fetchNewItems,
    anthropic.fetchNewItems,
    openai.fetchNewItems,
  ];

  const results = [];
  for (const fetchFn of sources) {
    try {
      const items = await fetchFn();
      results.push(...items);
    } catch (err) {
      // source failed, log it, move on
      console.error(`Source failed: ${err.message}`);
    }
  }
  return results;
}
```

> **Key:** One source fails = log + continue. The whole pipeline shouldn't fail because of one source.

### LLM Rate-Limit Handling

Groq will rate-limit and throw an error. Add retry logic:

```javascript
// agents/aggregator.js
async function scoreArticle(article, retries = 3) {
  for (let attempt = 1; attempt <= retries; attempt++) {
    try {
      const response = await client.chat.completions.create({...});
      return JSON.parse(response.choices[0].message.tool_calls[0].function.arguments);
    } catch (err) {
      console.error(`Attempt ${attempt} failed: ${err.message}`);
      if (attempt === retries) throw err;   // last attempt — rethrow
      await new Promise((r) => setTimeout(r, 5000 * attempt));  // backoff
    }
  }
}
```

- `retries = 3` — try 3 times
- `setTimeout(r, 5000 * attempt)` — exponential backoff (5s, 10s, 15s)
- On the last attempt, rethrow — let the caller handle it

### Retry Wrapper (Reusable)

```javascript
// lib/retry.js
async function withRetry(fn, retries = 3, delayMs = 5000) {
  for (let attempt = 1; attempt <= retries; attempt++) {
    try {
      return await fn();
    } catch (err) {
      if (attempt === retries) throw err;
      console.error(`Retry ${attempt}/${retries}: ${err.message}`);
      await new Promise((r) => setTimeout(r, delayMs * attempt));
    }
  }
}

module.exports = { withRetry };
```

Use it everywhere if you want.

## Common Mistakes

- ❌ Not testing after refactor — structure changed, if some import broke everything fails. Run `node index.js` after every change.
- ❌ Creating a new Pool in every file — connection leak. One Pool in `db/index.js`, import everywhere.
- ❌ Error handling only in the main file — every layer (scrapers, agents) needs fail handling.
- ❌ Not writing a README — your code doesn't speak for itself. The README is the first impression.
- ❌ Putting `digests/` in `.gitignore` (if you want) — no need to commit local output files.

## What It Is NOT

⚠️ **Refactor = not "code rewrite".** Only structure/quality improves — functionality stays the same. Writing new code when requirements change is a feature, not a refactor.

⚠️ **Error handling = not "put try/catch everywhere".** It's intentional — where to log, where to retry, where to rethrow. Over-catching is also a problem (errors get hidden).

⚠️ **README = not "write anything".** A good README states: what, how, tech stack, setup, deployment. It's a document, not filler.

⚠️ **Ship = not "just pushed".** Ship = tested, documented, deployed, monitored. Confirm both manual run green + workflow green.
