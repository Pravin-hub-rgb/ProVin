In 8.3 the scraping pipeline was built — RSS feeds give normalized items. But now the problem — **scraped items are still in memory, nowhere saved.** Tomorrow when the system runs again, those items will come again — because the system doesn't remember it has already seen them. Database integration solves this problem: store items in the `articles` table, so the system remembers.

## What We Need to Do

1. Connect to Supabase (`DATABASE_URL`)
2. Insert scraped items into the `articles` table
3. Dedup — skip urls that already exist (8.2's `ON CONFLICT DO NOTHING`)
4. For the future — query "unranked" articles (for the Aggregator)

## Connect to Supabase

Create a `db.js` file — the database connection lives in one place:

```javascript
// db.js
require('dotenv').config();
const { Pool } = require('pg');

const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
});

module.exports = pool;
```

**What is `pg` Pool?** A group of Postgres connections. Instead of creating a new connection per query, we take one from the pool — fast and reliable. `connectionString` comes from `.env` — never hardcoded in code.

## Insert Scraped Items — With Dedup

Now connect scraping + DB. A function that inserts items:

```javascript
// db/insertArticles.js
const pool = require('../db');

async function insertArticles(items) {
  for (const item of items) {
    await pool.query(
      `INSERT INTO articles (source, title, url, published_at, raw_content)
       VALUES ($1, $2, $3, $4, $5)
       ON CONFLICT (url) DO NOTHING`,
      [item.source, item.title, item.url, item.published_at, item.raw_content]
    );
  }
  console.log(`Inserted/checked ${items.length} items`);
}

module.exports = { insertArticles };
```

**Understand:**
- `$1, $2...` — **parameterized queries** — we don't concatenate values directly into the string. This protects from SQL injection (security!)
- `ON CONFLICT (url) DO NOTHING` — if the url already exists, silently skip
- `pool.query()` — async, returns a Promise

> **Security note:** Never write something like `INSERT ... VALUES ('$' + item.title)` — always use parameterized queries (`$1`). This is the standard fix for SQL injection.

## Count Check — How Many New Came?

After insert, we should know how many actually got inserted (conflict ones skipped). A better version:

```javascript
// db/insertArticles.js
async function insertArticles(items) {
  let inserted = 0;
  for (const item of items) {
    const result = await pool.query(
      `INSERT INTO articles (source, title, url, published_at, raw_content)
       VALUES ($1, $2, $3, $4, $5)
       ON CONFLICT (url) DO NOTHING
       RETURNING id`,
      [item.source, item.title, item.url, item.published_at, item.raw_content]
    );
    if (result.rowCount > 0) inserted++;
  }
  console.log(`New: ${inserted}, duplicate/skipped: ${items.length - inserted}`);
  return inserted;
}
```

`RETURNING id` — returns the row's id on insert. `rowCount > 0` means it got inserted (no conflict). That's how we know how many were actually new.

## Main Pipeline — Wire Everything Together

Now connect scrape + insert in one `index.js`:

```javascript
// index.js
require('dotenv').config();
const { scrapeAll } = require('./scrapers');
const { insertArticles } = require('./db/insertArticles');

async function main() {
  console.log('Step 1: Scraping...');
  const items = await scrapeAll();

  console.log('Step 2: Inserting into database...');
  const inserted = await insertArticles(items);

  console.log(`Done. ${inserted} new articles saved.`);
  process.exit(0);
}

main().catch((err) => {
  console.error('Pipeline failed:', err);
  process.exit(1);
});
```

Run it:

```bash
node index.js
```

Output:

```
Step 1: Scraping...
Step 2: Inserting into database...
New: 17, duplicate/skipped: 10
Done. 17 new articles saved.
```

Now open the **Supabase dashboard** → Table Editor → `articles` — you'll see 17 new rows. You can literally watch data getting stored. **Run it again** — now 0 new will be inserted (all duplicates), because the urls already exist. Dedup is working live.

## Query Unranked Articles — For the Aggregator

For the Aggregator Agent (8.5), we only need the new, unranked articles:

```javascript
// db/getUnranked.js
const pool = require('../db');

async function getUnranked() {
  const result = await pool.query(
    `SELECT * FROM articles WHERE ranked = false`
  );
  return result.rows;
}

module.exports = { getUnranked };
```

These queries will be used in the agents ahead. For now just grasp the concept — `WHERE ranked = false` gives only the new ones.

## Common Mistakes

- ❌ Concatenating values instead of parameterizing with `$1` — **SQL injection risk**. Always parameterized.
- ❌ Creating a new `Pool` for every query — create one Pool, import everywhere. `pool.end()` on process exit.
- ❌ Forgetting `process.exit(0)` — the Node app can hang with the pool connection. Exit when the script ends.
- ❌ Forgetting `ON CONFLICT` — dedup will never work, duplicate rows will keep filling.
- ❌ Not checking `rowCount` — you won't know how many were actually new.

## What It Is NOT

⚠️ **Dedup = not "check the whole DB every time".** With the `UNIQUE` constraint + `ON CONFLICT`, the database handles it itself — you don't have to run a SELECT first.

⚠️ **`pg` = not "feels like a database but is only a client".** `pg` is a client library — the database itself lives on Supabase. You connect to it via `pg` in your code.

⚠️ **SQL injection = not "just a tutorial thing".** It's a real attack. Always use parameterized queries — build the habit from 8.4.

⚠️ **`process.exit(1)` on error = not a crash, it's correct.** The script signals failure with a non-zero exit code — that's how scheduling (8.7) knows something went wrong.
