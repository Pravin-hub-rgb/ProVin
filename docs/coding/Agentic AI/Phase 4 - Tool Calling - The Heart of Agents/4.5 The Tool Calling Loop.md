The examples so far handle one round of tool calls. But real agents keep going. The model calls a tool, gets the result, decides if it needs another tool, calls again, and only stops when it has enough information to answer in plain text.

That's the **agent loop** — the same loop from Phase 2, now in actual code. It's just a `while` loop.

### The Full Agent Loop

Here's the pattern that powers every AI agent:

```javascript
import Anthropic from "@anthropic-ai/sdk";

const anthropic = new Anthropic();

// --- Tool Definitions ---
const tools = [
  {
    name: "calculator",
    description: "Evaluate a mathematical expression.",
    input_schema: {
      type: "object",
      properties: {
        expression: { type: "string", description: "The math expression" }
      },
      required: ["expression"]
    }
  },
  {
    name: "get_current_date",
    description: "Get today's date.",
    input_schema: {
      type: "object",
      properties: {}
    }
  }
];

// --- Tool Implementations ---
function calculator(expression) {
  try {
    return String(eval(expression));
  } catch (err) {
    return `Error: ${err.message}`;
  }
}

function getCurrentDate() {
  return new Date().toISOString().split("T")[0];
}

async function executeToolCall(name, input) {
  switch (name) {
    case "calculator": return calculator(input.expression);
    case "get_current_date": return getCurrentDate();
    default: return `Unknown tool: ${name}`;
  }
}

// --- The Agent Loop ---
const messages = [
  { role: "user", content: "How many days until Christmas from today? First get today's date, then calculate." }
];

// Loop until the model decides to stop calling tools
while (true) {
  const response = await anthropic.messages.create({
    model: "claude-sonnet-4-20250514",
    max_tokens: 1024,
    system: "You are a helpful assistant with tools.",
    messages: messages,
    tools: tools
  });

  // Check if the model produced any tool_use blocks
  const toolCalls = response.content.filter(block => block.type === "tool_use");

  if (toolCalls.length === 0) {
    // No tool calls — the model is giving us the final answer
    console.log("Assistant:", response.content[0].text);
    break;
  }

  // Add the assistant's response (with tool_use blocks) to history
  messages.push({ role: "assistant", content: response.content });

  // Execute each tool and collect results
  for (const toolCall of toolCalls) {
    const result = await executeToolCall(toolCall.name, toolCall.input);
    console.log(`  → ${toolCall.name}: ${JSON.stringify(toolCall.input)} => ${result}`);

    // Send each tool result back
    messages.push({
      role: "user",
      content: [
        {
          type: "tool_result",
          tool_use_id: toolCall.id,
          content: result
        }
      ]
    });
  }

  // Loop continues — model gets tool results and decides what to do next
}
```

### What's Different Here

This is the real deal. Let's trace through what happens:

1. **First API call**: The model gets "How many days until Christmas?"
2. Model outputs: `tool_use { name: "get_current_date", input: {} }`
3. Your code executes `getCurrentDate()` → returns `"2026-06-14"`
4. Result is sent back. Loop continues.
5. **Second API call**: Model sees today's date, now needs to calculate the difference
6. Model outputs: `tool_use { name: "calculator", input: { expression: "...", ... } }`
7. Your code runs the calculator. Result sent back. Loop continues.
8. **Third API call**: Model has the number of days
9. Model outputs: `text { text: "There are 194 days until Christmas." }`
10. No tool_use blocks → `if (toolCalls.length === 0)` → `break`. Loop ends.

The loop handles any number of rounds automatically. The model leads, and your code follows until the model says "I'm done."

### Breaking Down the Key Parts

**The while(true) loop** — This keeps running until we explicitly break. Each iteration is one round of "model thinks → executes tools → gets results."

**Filtering for tool_use** — `response.content.filter(block => block.type === "tool_use")` gives us all the tools the model wants to call in this response. If there are none, we're done.

**Pushing assistant content before results** — We push the entire `response.content` (which includes the tool_use blocks) as the `assistant` role message. This tells the API: "The assistant already called these tools, here are the results." Without this, the model gets confused.

**Each tool_result gets its own message** — Even if the model called multiple tools at once, each result goes into the conversation history separately. The `tool_use_id` tells the API which tool call each result belongs to.

### Running It Yourself

Save this as `agent-loop.mjs` and run it with:

```bash
node agent-loop.mjs
```

You'll see output like:

```
  → get_current_date: {} => 2026-06-14
  → calculator: {"expression":"(new Date(2026, 11, 25) - new Date(2026, 5, 14)) / (1000 * 60 * 60 * 24)"} => 193.791... 
  → calculator: {"expression":"Math.floor(193.791...)"} => 193
Assistant: There are 193 days until Christmas.
```

Notice the model called `calculator` twice! It first got a decimal, realized it should round down, and called again. The loop handled both automatically because it doesn't stop until there are no more tool_use blocks.

### What We've Built

This loop is the engine of every agent. Cline runs this same pattern. opencode runs this same pattern. Every AI coding tool is a while loop checking for tool calls:

```
while model is not done:
  call model with tools
  if model outputs text → done, print it
  if model calls tools → execute, send results back, repeat
```

That's it. That's the secret sauce. Not magic. Not AGI. A while loop and a switch statement.

### Next Up: Memory

Your agent can act now. It can read files, run calculations, search the web. But once the conversation ends, it forgets everything. It has no memory of past conversations, no persistent state, no context beyond the current message history.
