A calculator is useful, but an agent with only one tool isn't much of an agent. The real power comes when the model can choose between multiple tools — and sometimes chain them together.

Let's build an agent with three tools: `calculator`, `get_current_date`, and `search_web`. The model will decide which tool fits the user's question.

### Step 1: Define Multiple Tools

```javascript
const tools = [
  {
    name: "calculator",
    description: "Evaluate a mathematical expression. Use this for any arithmetic or numeric computation.",
    input_schema: {
      type: "object",
      properties: {
        expression: {
          type: "string",
          description: "The math expression to evaluate"
        }
      },
      required: ["expression"]
    }
  },
  {
    name: "get_current_date",
    description: "Get today's date. Use this when the user asks for the current date, day of week, or what day it is.",
    input_schema: {
      type: "object",
      properties: {}
    }
  },
  {
    name: "search_web",
    description: "Search the web for information. Use this for questions about current events, facts, or things you don't know.",
    input_schema: {
      type: "object",
      properties: {
        query: {
          type: "string",
          description: "The search query"
        }
      },
      required: ["query"]
    }
  }
];
```

Each tool has a clear description that tells the model when to use it. Notice `get_current_date` has an empty `properties` object — it takes no parameters. The model will still call it, just with no input.

### Step 2: The Tool Functions

```javascript
function calculator(expression) {
  try {
    return String(eval(expression));
  } catch (err) {
    return `Error: ${err.message}`;
  }
}

function getCurrentDate() {
  return new Date().toISOString().split("T")[0];
}

async function searchWeb(query) {
  // In a real app, you'd call a search API here
  return `Simulated search result for "${query}": The sky is blue, water is wet.`;
}
```

Three functions, each matching one tool. When the model calls `get_current_date`, our code runs `getCurrentDate()` and returns the date string. The search is simulated here — in production you'd hit a real search API.

### Step 3: Route Tool Calls to the Right Function

We need a dispatcher — code that looks at the tool name and calls the right function:

```javascript
async function executeToolCall(toolName, input) {
  switch (toolName) {
    case "calculator":
      return calculator(input.expression);
    case "get_current_date":
      return getCurrentDate();
    case "search_web":
      return await searchWeb(input.query);
    default:
      return `Unknown tool: ${toolName}`;
  }
}
```

This switch statement is the bridge between the model's output and your real code. The model says `calculator`, we run `calculator()`. The model says `search_web`, we run `searchWeb()`. This pattern is how every agent system routes tool calls.

### Step 4: The Agent Loop (Manual Version)

```javascript
import Anthropic from "@anthropic-ai/sdk";

const anthropic = new Anthropic();

const messages = [
  { role: "user", content: "What is 15% of 200? And what day is it today?" }
];

const response = await anthropic.messages.create({
  model: "claude-sonnet-4-20250514",
  max_tokens: 1024,
  system: "You are a helpful assistant with tools.",
  messages: messages,
  tools: tools
});

// Check what the model wants to do
for (const block of response.content) {
  if (block.type === "text") {
    console.log("Assistant:", block.text);
  } else if (block.type === "tool_use") {
    console.log(`Tool called: ${block.name}`, block.input);

    // Execute the right tool
    const result = await executeToolCall(block.name, block.input);

    // Add to conversation history
    messages.push({ role: "assistant", content: response.content });
    messages.push({
      role: "user",
      content: [
        {
          type: "tool_result",
          tool_use_id: block.id,
          content: result
        }
      ]
    });

    // Call again with results
    const finalResponse = await anthropic.messages.create({
      model: "claude-sonnet-4-20250514",
      max_tokens: 1024,
      system: "You are a helpful assistant with tools.",
      messages: messages,
      tools: tools
    });

    console.log("Assistant:", finalResponse.content[0].text);
  }
}
```

### What You'll See

Run this with the question "What is 15% of 200? And what day is it today?" and the model might output **two tool_use blocks** in the same response:

```
Content block 1: { type: "tool_use", name: "calculator", input: { expression: "15/100 * 200" } }
Content block 2: { type: "tool_use", name: "get_current_date", input: {} }
```

The model figured out it needs both tools and called them both at once. Your code handles each one, sends both results back, and the model combines them into a single answer:

```
Assistant: 15% of 200 is 30. Today's date is 2026-06-14.
```

### Chaining Tool Calls

Sometimes the model needs to call tools in sequence — using the result of one as input to another. For example: "How many days until Christmas?"

The model might first call `get_current_date`, see today is June 14, then call `calculator` to compute the difference. But that requires multiple rounds. Our current code only handles one round of tool calls.

That brings us to the real agent loop — the while loop that keeps going until the model is done.

### How Tool Choice Works

Behind the scenes, the model estimates: "Which tool's description best matches what the user is asking?" It's not random. Each description acts like a signpost. If you say "search the web" vaguely, the model might use it for questions it could answer from its own training. If you say "use this for current events or things after your training cutoff", the model will reserve it for those cases.

The descriptions are your UI. Spend time on them.
