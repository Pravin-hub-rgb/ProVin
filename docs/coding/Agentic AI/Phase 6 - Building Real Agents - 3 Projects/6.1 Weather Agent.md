# 6.1 Project 1: Weather Agent

Phase 5 covered memory and context — how agents remember conversation history and manage long contexts. Now let's build something real.

Our first agent answers weather questions. The user types "What's the weather in Mumbai?" and the agent calls OpenWeatherMap's API, reads the JSON response, and returns a human-friendly answer.

This is the simplest possible agent: one tool, one API call, one answer. But it's the foundation for every agent you'll build after this.

---

## What you're building

A Next.js app with:
- A chat input on the page
- An API route that holds the agent logic
- One tool: `getWeather(city)`
- The agent decides when to call it, then formats the result

## Step 3: The tool — `getWeather(city)`

This is a plain async function. No agent logic yet. Just fetch weather data and return what matters.

```typescript
// app/api/agent/weather.ts — helper, not a route

const OPENWEATHERMAP_API_KEY = process.env.OPENWEATHERMAP_API_KEY!;

export async function getWeather(city: string): Promise<string> {
  const url = `https://api.openweathermap.org/data/2.5/weather?q=${encodeURIComponent(city)}&appid=${OPENWEATHERMAP_API_KEY}&units=metric`;

  const res = await fetch(url);
  if (!res.ok) {
    return `Couldn't find weather for "${city}". Check the city name.`;
  }

  const data = await res.json();
  const temp = data.main.temp;
  const description = data.weather[0].description;
  const humidity = data.main.humidity;
  const windSpeed = data.wind.speed;

  return `The weather in ${city} is ${temp}°C with ${description}. Humidity: ${humidity}%. Wind: ${windSpeed} m/s.`;
}
```

**Walkthrough line by line:**

- `encodeURIComponent(city)` — safely handles spaces and special chars in the city name
- `units=metric` — OpenWeatherMap returns Kelvin by default; `metric` gives Celsius
- We check `res.ok` — if the city doesn't exist, the API returns 404. We return a friendly message instead of crashing
- `data.main.temp`, `data.weather[0].description` — these are fields in the OpenWeatherMap JSON response. Weather is an array, so we take the first entry
- We return a formatted string. The agent will read this and rewrite it naturally

## Step 4: Define the tool for the agent

The Anthropic SDK expects tools in a specific format. Each tool has a name, description, and input schema.

```typescript
// app/api/agent/route.ts (partial — tool definition)

const weatherTool = {
  name: "get_weather",
  description: "Get the current weather for a city. Returns temperature, conditions, humidity, and wind speed.",
  input_schema: {
    type: "object",
    properties: {
      city: {
        type: "string",
        description: "The city name, e.g. 'Mumbai', 'New York', 'Tokyo'",
      },
    },
    required: ["city"],
  },
};
```

The `description` field is critical. Claude reads this to decide when to use the tool. A bad description means the agent won't know what the tool does. A good one makes it obvious.

The `input_schema` tells Claude what arguments the tool expects. We're saying: "You need to pass a `city` string, and it's required."

## Step 5: The agent loop — `route.ts`

This is the full API route. Every agent loop follows the same pattern:

1. Receive user message
2. Send it to Claude with the tool definition
3. Claude either responds directly OR says "I need to call a tool"
4. If tool call: run the actual function, send result back to Claude
5. Claude gives a final answer

```typescript
// app/api/agent/route.ts

import { NextRequest, NextResponse } from "next/server";
import Anthropic from "@anthropic-ai/sdk";
import { getWeather } from "./weather";

const anthropic = new Anthropic({
  apiKey: process.env.ANTHROPIC_API_KEY!,
});

const weatherTool = {
  name: "get_weather",
  description: "Get the current weather for a city. Returns temperature, conditions, humidity, and wind speed.",
  input_schema: {
    type: "object",
    properties: {
      city: {
        type: "string",
        description: "The city name, e.g. 'Mumbai', 'New York', 'Tokyo'",
      },
    },
    required: ["city"],
  },
};

export async function POST(req: NextRequest) {
  const { message } = await req.json();

  // Step 1: Send message + tool definition to Claude
  const response = await anthropic.messages.create({
    model: "claude-sonnet-4-20250514",
    max_tokens: 1024,
    system: "You are a helpful weather assistant. Answer questions about the weather using the get_weather tool. Be friendly and conversational.",
    messages: [
      { role: "user", content: message },
    ],
    tools: [weatherTool],
  });

  // Step 2: Check if Claude wants to call a tool
  // The response content is an array. Look for a block with type "tool_use"
  const toolUse = response.content.find((block) => block.type === "tool_use");

  if (!toolUse) {
    // Claude answered directly (no tool needed) — return it
    return NextResponse.json({ response: response.content[0].text });
  }

  // Step 3: Claude wants to call get_weather — run it
  const city = toolUse.input.city as string;
  const weatherResult = await getWeather(city);

  // Step 4: Send the tool result back to Claude for the final answer
  const finalResponse = await anthropic.messages.create({
    model: "claude-sonnet-4-20250514",
    max_tokens: 1024,
    system: "You are a helpful weather assistant.",
    messages: [
      { role: "user", content: message },
      { role: "assistant", content: response.content },
      {
        role: "user",
        content: [
          {
            type: "tool_result",
            tool_use_id: toolUse.id,
            content: weatherResult,
          },
        ],
      },
    ],
    tools: [weatherTool],
  });

  const answer = finalResponse.content[0].text;
  return NextResponse.json({ response: answer });
}
```

**Walkthrough of the loop:**

- We receive `{ message }` from the frontend via POST
- First `anthropic.messages.create` call sends the user message plus the tool definition
- Claude's response is an array of content blocks. One of them might be `type: "tool_use"` — that means Claude decided to call the tool
- If no tool call, Claude answered directly (e.g., "I don't know the weather, but I can help with..."). We return it
- If there IS a tool call, we extract `toolUse.input.city` and run `getWeather`
- Then we send a SECOND request to Claude with the full conversation history PLUS the tool result. This is crucial — Claude needs to see what the tool returned so it can craft a natural answer
- Claude's second response is the final answer

**Why two API calls?** Claude doesn't execute code. It says "I want to call get_weather with city=Mumbai" and stops. We run the function, then feed the result back. Claude then says "Oh, the weather in Mumbai is 32°C and partly cloudy."

## Step 6: The frontend — `page.tsx`

A minimal chat UI. Input box, send button, response display.

```tsx
// app/page.tsx

"use client";

import { useState } from "react";

export default function Home() {
  const [message, setMessage] = useState("");
  const [response, setResponse] = useState("");
  const [loading, setLoading] = useState(false);

  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault();
    if (!message.trim()) return;

    setLoading(true);
    setResponse("");

    const res = await fetch("/api/agent", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ message }),
    });

    const data = await res.json();
    setResponse(data.response);
    setLoading(false);
  }

  return (
    <main style={{ maxWidth: 600, margin: "50px auto", fontFamily: "sans-serif" }}>
      <h1>Weather Agent</h1>
      <form onSubmit={handleSubmit}>
        <input
          type="text"
          value={message}
          onChange={(e) => setMessage(e.target.value)}
          placeholder="What's the weather in Mumbai?"
          style={{ width: "100%", padding: 10, fontSize: 16 }}
        />
        <button type="submit" disabled={loading} style={{ marginTop: 10, padding: "10px 20px" }}>
          {loading ? "Thinking..." : "Ask"}
        </button>
      </form>
      {response && (
        <div style={{ marginTop: 20, padding: 15, background: "#f5f5f5", borderRadius: 8 }}>
          {response}
        </div>
      )}
    </main>
  );
}
```

**Key points:**

- `"use client"` — this is a client component because we need state and event handlers
- `handleSubmit` sends POST to `/api/agent` with the user's message
- When the response comes back, we show it in a simple div
- The loading state gives the user feedback while the agent thinks (which takes a couple seconds because of the two LLM calls)
