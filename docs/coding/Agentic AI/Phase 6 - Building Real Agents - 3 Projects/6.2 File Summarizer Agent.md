# 6.2 Project 2: File Summarizer Agent

In Project 1 your agent called an external API. This time the agent works with files on your own computer.

Here's what it does: point the agent at a folder of `.txt` files. It lists the folder, reads each file, then produces a single summary of everything.

This is how tools like Cline work under the hood. Cline has tools like `Read`, `Write`, `ListFiles` — each one is just a function the LLM can call. You're about to build the same thing.

---

## What you're building

A Next.js app where you press a button and the agent:
1. Lists all files in `/notes`
2. Reads each file
3. Produces a combined summary

No user input during the process — the agent plans the whole sequence itself.

---

## Step 3: The file system tools

We need two tools. Each is a plain async function.

```typescript
// app/api/agent/tools.ts

import { promises as fs } from "fs";
import path from "path";

export async function listFiles(folder: string): Promise<string> {
  try {
    const absolutePath = path.resolve(folder);
    const entries = await fs.readdir(absolutePath, { withFileTypes: true });
    const files = entries
      .filter((entry) => entry.isFile() && entry.name.endsWith(".txt"))
      .map((entry) => entry.name);

    if (files.length === 0) {
      return `No .txt files found in ${folder}.`;
    }

    return `Files in ${folder}:\n${files.join("\n")}`;
  } catch (error) {
    return `Error reading folder: ${error}`;
  }
}

export async function readFile(filePath: string): Promise<string> {
  try {
    const absolutePath = path.resolve(filePath);
    const content = await fs.readFile(absolutePath, "utf-8");
    return content;
  } catch (error) {
    return `Error reading file: ${error}`;
  }
}
```

**Walkthrough:**

- `promises as fs` — Node.js `fs` module has a promise-based API. `fs.readdir` and `fs.readFile` return promises instead of using callbacks
- `path.resolve(folder)` — converts relative paths (like `./notes`) to absolute paths. This avoids ambiguity about which directory we're reading
- `fs.readdir` with `{ withFileTypes: true }` — returns `Dirent` objects so we can check `isFile()` and filter out subdirectories
- We filter for `.txt` files only. If the folder has a `image.png`, the agent won't try (and fail) to read it
- `fs.readFile(filePath, "utf-8")` — reads the file as a string. Without `"utf-8"` it'd return a raw Buffer
- Both functions catch errors and return error messages as strings. This is important — if a tool throws an unhandled exception, the agent crashes. If it returns an error string, the agent reads it and can recover (e.g., "Oh, that file doesn't exist, let me try another")

## Step 4: The agent loop — `route.ts`

This is where it gets interesting. Unlike the weather agent which makes one tool call at most, this agent will chain multiple calls: list → read → read → read → summarize.

```typescript
// app/api/agent/route.ts

import { NextRequest, NextResponse } from "next/server";
import Anthropic from "@anthropic-ai/sdk";
import { listFiles, readFile } from "./tools";

const anthropic = new Anthropic({
  apiKey: process.env.ANTHROPIC_API_KEY!,
});

const tools = [
  {
    name: "list_files",
    description: "List all .txt files in a folder. Returns filenames only.",
    input_schema: {
      type: "object",
      properties: {
        folder: {
          type: "string",
          description: "Path to the folder, e.g. './notes'",
        },
      },
      required: ["folder"],
    },
  },
  {
    name: "read_file",
    description: "Read the contents of a text file and return it as a string.",
    input_schema: {
      type: "object",
      properties: {
        filePath: {
          type: "string",
          description: "Full path to the file, e.g. './notes/meeting-notes.txt'",
        },
      },
      required: ["filePath"],
    },
  },
];

const SYSTEM_PROMPT = `You are a file summarizer agent. Your goal is to summarize all files in a folder.

Follow this plan:
1. Call list_files to see what's in the folder
2. Call read_file for each file
3. Write a final summary that combines the key information from all files

Do NOT guess file paths — always list first, then read.`;

export async function POST(req: NextRequest) {
  const { folder } = await req.json();

  // Send the initial request with the goal
  let response = await anthropic.messages.create({
    model: "claude-sonnet-4-20250514",
    max_tokens: 2048,
    system: SYSTEM_PROMPT,
    messages: [
      {
        role: "user",
        content: `Summarize all files in this folder: ${folder}`,
      },
    ],
    tools,
  });

  // Multi-step loop: keep going until Claude responds with text (not a tool call)
  while (true) {
    const toolUse = response.content.find((block) => block.type === "tool_use");
    if (!toolUse) break; // No more tool calls — Claude is done

    // Execute the tool
    let result: string;
    if (toolUse.name === "list_files") {
      result = await listFiles(toolUse.input.folder as string);
    } else if (toolUse.name === "read_file") {
      result = await readFile(toolUse.input.filePath as string);
    } else {
      result = `Unknown tool: ${toolUse.name}`;
    }

    // Send the result back and let Claude decide what to do next
    response = await anthropic.messages.create({
      model: "claude-sonnet-4-20250514",
      max_tokens: 2048,
      system: SYSTEM_PROMPT,
      messages: [
        { role: "user", content: `Summarize all files in this folder: ${folder}` },
        { role: "assistant", content: response.content },
        {
          role: "user",
          content: [
            {
              type: "tool_result",
              tool_use_id: toolUse.id,
              content: result,
            },
          ],
        },
      ],
      tools,
    });
  }

  // When the loop breaks, response contains the final answer text
  const summary = response.content[0].text;
  return NextResponse.json({ summary });
}
```

**Walkthrough of the multi-step loop:**

- We send the initial request: "Summarize all files in this folder: ./notes"
- Claude comes back with `list_files(folder: "./notes")`
- We run `listFiles`, get back the list of filenames
- We append that result to the conversation and ask Claude again
- Claude sees the file list and says `read_file(filePath: "./notes/meeting-notes.txt")`
- We run `readFile`, return the content
- Claude says `read_file(filePath: "./notes/ideas.txt")`
- And again for the third file
- Now Claude has all the content. It responds with text: "Here's a combined summary..."
- The `while (true)` loop breaks because there are no more `tool_use` blocks
- We return the final text

**Why the while loop?** The weather agent did a single if-check because we knew there'd be at most one tool call. Here, the agent might call `list_files` once and `read_file` three times — we don't know the count upfront. The loop lets the agent decide how many steps it needs.

**The system prompt matters.** We explicitly tell Claude the plan: list first, then read, then summarize. Without this, Claude might try to read files without listing, or list twice. A good system prompt is like giving the agent a playbook.

## Step 5: The frontend — `page.tsx`

One button. One result area. Minimal.

```tsx
// app/page.tsx

"use client";

import { useState } from "react";

export default function Home() {
  const [summary, setSummary] = useState("");
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState("");

  async function handleSummarize() {
    setLoading(true);
    setSummary("");
    setError("");

    try {
      const res = await fetch("/api/agent", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ folder: "./notes" }),
      });

      if (!res.ok) {
        throw new Error(`HTTP ${res.status}`);
      }

      const data = await res.json();
      setSummary(data.summary);
    } catch (err) {
      setError(`Agent failed: ${err}`);
    } finally {
      setLoading(false);
    }
  }

  return (
    <main style={{ maxWidth: 600, margin: "50px auto", fontFamily: "sans-serif" }}>
      <h1>File Summarizer Agent</h1>
      <button
        onClick={handleSummarize}
        disabled={loading}
        style={{ padding: "10px 20px", fontSize: 16 }}
      >
        {loading ? "Summarizing..." : "Summarize /notes"}
      </button>

      {error && (
        <div style={{ marginTop: 20, padding: 15, background: "#ffe0e0", borderRadius: 8 }}>
          {error}
        </div>
      )}

      {summary && (
        <div style={{ marginTop: 20, padding: 15, background: "#f0fdf0", borderRadius: 8, whiteSpace: "pre-wrap" }}>
          <h3>Summary</h3>
          {summary}
        </div>
      )}
    </main>
  );
}
```

**Key points:**

- We hardcode `folder: "./notes"`. The user doesn't need to type it — the agent's job is fixed
- `whiteSpace: "pre-wrap"` preserves line breaks in Claude's response so the summary keeps its formatting
- Error handling with try/catch — if the API route crashes (e.g., env variable missing), the UI shows an error instead of freezing

## How this relates to Cline and similar tools

You've probably used Cline, opencode, or Copilot's agent mode. When you say "refactor this file" and it reads your code, edits it, then reads it again to verify — that's exactly what you just built.

Each tool is just a function:
- `listFiles` → Cline's `list_files`
- `readFile` → Cline's `read`
- Your `getWeather` from Project 1 → Cline's `web_search`

The agent loop — the while loop that keeps calling tools until the LLM decides it's done — is the same architecture used by every agentic coding tool.
