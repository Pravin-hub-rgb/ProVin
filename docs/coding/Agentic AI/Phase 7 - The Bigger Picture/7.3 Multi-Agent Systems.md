So far we've talked about single agents. One model, one loop, one goal. But what if you had multiple agents working together?

That's a multi-agent system. Instead of one model doing everything, you have multiple models, each with a specific role, collaborating on a task.

Here's a concrete example. Say you want to write a research report:

1. An **Orchestrator agent** receives the task and breaks it into pieces.
2. It assigns research to a **Researcher agent** — this agent searches the web, reads sources, and collects facts.
3. The results go to a **Writer agent** — this agent turns the facts into a well-structured report.
4. A **Reviewer agent** checks the report for errors, clarity, and completeness.
5. If the reviewer finds issues, the report goes back to the writer. Otherwise, it's returned to the user.

Each agent has its own system prompt, its own tools, and its own context window. The researcher doesn't need to know how to format a report. The writer doesn't need access to web search. They specialize.

Why would you do this instead of using one agent?

- **Parallelism**: the researcher and writer could work on different sections at the same time.
- **Specialization**: each agent can have a focused system prompt. A "strict reviewer" prompt works much better when it's not also trying to write.
- **Context management**: one agent can only fit so much in its context window. With multiple agents, each handles a smaller piece. The researcher stays focused on research, the writer on writing.
- **Error isolation**: if one agent messes up, the others can catch it. The reviewer catches what the writer missed.

The frameworks from 7.1 support this. **CrewAI** is designed for it — you literally define a Crew with roles. **AutoGen** lets agents converse to solve tasks. **LangGraph** can orchestrate multiple agents as nodes in a graph.

Multi-agent systems are where agentic AI gets really interesting. A single smart agent is powerful. A team of specialized agents working together is something else entirely.
