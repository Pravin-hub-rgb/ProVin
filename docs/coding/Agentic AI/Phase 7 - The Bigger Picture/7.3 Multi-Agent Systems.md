So far we've talked about single agents. One model, one loop, one goal. But what if you had multiple agents working together?

That's a multi-agent system. Instead of one model doing everything, you have multiple models, each with a specific role, collaborating on a task.

![Multi-Agent System — Orchestrator, Researcher, Writer, and Reviewer Working Together](/diagrams/agenticai/multi-agent.svg)

Here's a concrete example. Say you want to write a research report:

1. An **Orchestrator agent** receives the task and breaks it into pieces.
2. It assigns research to a **Researcher agent** — this agent searches the web, reads sources, and collects facts.
3. The results go to a **Writer agent** — this agent turns the facts into a well-structured report.
4. A **Reviewer agent** checks the report for errors, clarity, and completeness.
5. If the reviewer finds issues, the report goes back to the writer. Otherwise, it's returned to the user.

Each agent has its own system prompt, its own tools, and its own context window. The researcher doesn't need to know how to format a report. The writer doesn't need access to web search. They specialize.

Why would you do this instead of using one agent?

- **Parallelism**: the researcher and writer could work on different sections at the same time.
- **Specialization**: each agent can have a focused system prompt. A "strict reviewer" prompt works much better when it's not also trying to write.
- **Context management**: one agent can only fit so much in its context window. With multiple agents, each handles a smaller piece. The researcher stays focused on research, the writer on writing.
- **Error isolation**: if one agent messes up, the others can catch it. The reviewer catches what the writer missed.

The frameworks from 7.1 support this. **CrewAI** is designed for it — you literally define a Crew with roles. **AutoGen** lets agents converse to solve tasks. **LangGraph** can orchestrate multiple agents as nodes in a graph.

Multi-agent systems are where agentic AI gets really interesting. A single smart agent is powerful. A team of specialized agents working together is something else entirely.

## What It Is NOT

Multi-agent doesn't mean "smarter." A team of five average developers isn't automatically better than one brilliant developer — the same applies here. Multi-agent systems shine through specialization and parallel work, not through raw intelligence. In fact, a poorly designed multi-agent system (agents stepping on each other, conflicting prompts, unclear handoffs) can perform worse than a single well-prompted agent. More agents means more complexity, not more capability by default.

### In Your Own Words

<details>
<summary>1. What problem does a multi-agent system solve that a single agent can't?</summary>

**Sample Answer:** A single agent has one context window, one prompt, and one viewpoint. It can't critique its own work effectively — like proofreading your own email, you miss things. A multi-agent system solves this by splitting responsibilities: the researcher focuses on finding facts, the writer focuses on clarity, the reviewer focuses on catching errors. Each agent has its own narrow job and does it well, without the cognitive load of doing everything.

</details>

<details>
<summary>2. How does error isolation work differently in a multi-agent setup vs. a single agent?</summary>

**Sample Answer:** In a single agent, if it makes a mistake in research, it carries that mistake into writing, and there's no built-in check — the same agent that wrote the wrong thing is also supposed to catch it, which rarely works. In a multi-agent setup, separate agents act as independent reviewers. The researcher might miss a source, but the writer can flag it as incomplete. The writer might produce unclear text, but the reviewer catches it. The errors are isolated and caught by a fresh pair of eyes — or in this case, a fresh system prompt.

</details>

<details>
<summary>3. Think of a task you do regularly. How would you break it down into roles for a multi-agent system?</summary>

**Sample Answer:** Let's say you need to plan a team offsite. A Planner agent researches venues and dates, a Logistics agent handles transportation and accommodation bookings, a Budget agent tracks costs against the limit, and a Comms agent sends updates to the team. Each agent has its own tools — the Logistics agent interacts with booking APIs, the Budget agent accesses a spreadsheet — and they hand off results to each other as needed. If the Budget agent says it's over-budget, the Planner adjusts recommendations.

</details>
