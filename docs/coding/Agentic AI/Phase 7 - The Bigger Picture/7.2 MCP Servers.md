Frameworks handle the agent loop. But there's another piece of infrastructure you should know about — MCP, or the Model Context Protocol.

MCP is an open standard created by Anthropic. It lets AI models connect to external tools and data sources in a standardized way. Think of it as a universal plug for AI tools.

Before MCP, every tool integration was custom. You wanted your agent to read a file? You wrote code. Check GitHub? More custom code. Query a database? Even more code. Every integration was a one-off.

After MCP, tools expose themselves through an MCP server. Any compatible AI can connect to that server using the same protocol. The AI says "I need to read a file," the MCP server handles the file system, and the AI gets the result. The AI doesn't care *how* the server reads the file — it just speaks MCP.

![MCP Protocol — USB for AI Tools, One Standard Plug for All Integrations](/diagrams/agenticai/mcp-usb.svg)

Here's the analogy that makes it click: MCP is to AI tools what USB is to peripherals. Before USB, every device had its own connector. USB came along and said "one plug, works everywhere." That's what MCP does for AI tool integrations.

Real MCP servers already exist for:
- **GitHub** — create issues, read repos, manage PRs
- **Slack** — read and send messages
- **Notion** — search and create pages
- **File System** — read, write, search files
- **Databases** — run queries and get results
- **Web scraping** — fetch and parse web pages

You've already used MCP without knowing it. Cline and opencode support MCP servers — that's why they can connect to GitHub, search your file system, read documentation, and more. Every time Cline or opencode reads a file or runs a command, it's going through an MCP integration under the hood.

Here's the distinction to keep in your head: **Agentic AI is the concept**, MCP is the infrastructure that powers it. Agentic AI says "an AI should be able to take actions in the world." MCP says "here's a standard way to make that happen, so you don't need custom code for every tool."

## What It Is NOT

MCP is not an AI model. It doesn't generate text, make decisions, or reason about problems — it's purely a plumbing standard. Think of it like a power outlet: the outlet doesn't power your devices itself, it just provides a universal way to connect to the power grid. MCP doesn't think for your agent — it just gives your agent a standard plug to connect to tools.

<details>
<summary>1. How is MCP like USB for AI tools? What problem does it solve?</summary>

**Sample Answer:** Before USB, every peripheral had its own connector — printers, keyboards, mice all used different ports. MCP solves the same problem for AI tools: every tool (GitHub, Slack, databases) had its own custom integration code. MCP gives them all one standard plug. Your agent speaks one protocol, and any tool with an MCP server understands it.

</details>

<details>
<summary>2. Before MCP, how would you connect an AI agent to a tool like Slack or GitHub?</summary>

**Sample Answer:** You'd write custom code for each tool. You'd use the Slack SDK to read and send messages, the GitHub API to create issues, and the Notion API to search pages. Every integration meant learning a different API, different authentication, and different error handling. MCP replaces all of that with one standard interface — your agent just says "call this tool with these parameters" in a uniform way across all tools.

</details>

<details>
<summary>3. Can you think of a tool or data source that doesn't have an MCP server yet but would be useful if it did?</summary>

**Sample Answer:** An email client like Gmail or Outlook. Imagine an agent that could read your emails, draft replies, organize your inbox, and even unsubscribe from newsletters — all through one MCP server. This is especially powerful for agents that manage your schedule or handle customer inquiries, since so much business communication still happens over email.

</details>
