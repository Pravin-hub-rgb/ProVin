Speaking of marketable — let's talk about how to present what you've learned. You've built real things. Now let other people know about it.

Here are the terms you can now confidently use and explain:

- **Agentic AI / AI Agents** — AI systems that take actions, not just generate text
- **Tool Calling / Function Calling** — the mechanism by which an LLM requests external actions
- **Context Window Management** — keeping relevant information in the limited space the model can see
- **ReAct Pattern (Reasoning + Acting)** — the cycle of think, act, observe that powers agents
- **Multi-step AI Pipelines** — chaining multiple LLM calls to break down complex tasks
- **MCP (Model Context Protocol)** — the standard for connecting AI to tools
- **RAG (Retrieval Augmented Generation)** — retrieve relevant information, then generate the answer
- **Prompt Engineering for Agents** — writing system prompts that guide agent behavior, not just answer quality

When you write a LinkedIn post about your projects, use this structure:

1. **"I just built X"** — state what you built. Be specific.
2. **"Here's how it works"** — explain the architecture in 3-4 sentences. Mention the pattern (ReAct, tool calling, MCP).
3. **"Here's what I learned"** — share a specific challenge you overcame. This is the most valuable part.
4. **"What's next?"** — what you'd improve or try differently.

For example:

```
"Just built an AI agent that reads my Notion tasks, prioritizes them, and creates GitHub issues automatically. Here's how it works: it uses the ReAct pattern — the LLM reasons about the task, calls the Notion MCP server to fetch tasks, and creates issues through the GitHub API. The hardest part was managing the context window — task descriptions plus issue details filled up fast. I learned to chunk the data and feed it piece by piece."

"I just built X" — specific. "Here's how it works" — mentions ReAct, MCP, context window. "Here's what I learned" — real challenge with a real solution.
```

Project posts are always more credible than theory posts. Anyone can talk about RAG. You can say "I built an agent that uses RAG to search my past code before answering questions." One shows you read a blog post. The other shows you can build.

Same applies to your resume. Under each project:

- Use the terms above. "Built an AI agent using the ReAct pattern with MCP-based tool integration."
- Include the outcome. "Reduced time to create GitHub issues by 60%."
- Mention the techniques, not just the tools. Not just "used LangChain" but "implemented multi-step agent pipelines with context window management."
