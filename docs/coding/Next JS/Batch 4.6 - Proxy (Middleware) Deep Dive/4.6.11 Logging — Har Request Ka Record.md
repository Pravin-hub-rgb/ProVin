4.6.10 tak request padhna + response banana dono sides aate gaye. Ab **real scenarios** — production mein proxy ka sabse common kaam. Aur sabse simple se shuru: **logging.** Har request ka record — kya maanga, kab, kahan se. "Logs = evidence" wala mindset yahan milta hai — aur proxy iske liye perfect jagah hai kyunki har request wahan se guzarti hai.

---

## Logs Kyun — Production Ki Kahani

Ek user aata hai: "Kal raat 11 baje hamari site pe problem thi, dashboard galat data dikha raha tha!" Tumne kuch nahi dekha, koi error nahi — sab theek dikh raha hai.

**Bina logs:** tumhare paas koi proof nahi — kya hua, kab hua, kis request pe — pata hi nahi.

**Logs ke saath:** "11:04 PM — GET /dashboard — IP: 49.36.x.x" — request ka record — investigation wahan se shuru hoti hai. **Logs = evidence.** Isliye production systems har request log karte hain.

---

## Step 1 — Basic Logging: Method + Pathname

Proxy mein `request` se sab kuch milta hai — sabse basic combo:

```ts
import { NextRequest, NextResponse } from "next/server"

export function proxy(request: NextRequest) {
  const method = request.method
  const pathname = request.nextUrl.pathname

  console.log(`${method} ${pathname}`)
  return NextResponse.next()
}

export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"],
}
```

- `request.method` — HTTP method — `GET`, `POST`, `DELETE`... (Batch 3 mein API ke context mein dekha tha — yahan proxy ke andar)
- `request.nextUrl.pathname` — 4.6.4 wala
- Template literal (`` `${method} ${pathname}` ``) — 4.6.10 mein bhi use kiya

**Terminal:**

```
GET /dashboard
GET /about
POST /api/comments
```

---

## Step 2 — Timestamp Add Karna

"Kab hua?" — log mein time hona zaroori hai. `new Date().toISOString()`:

```ts
export function proxy(request: NextRequest) {
  const method = request.method
  const pathname = request.nextUrl.pathname
  const time = new Date().toISOString()

  console.log(`[${time}] ${method} ${pathname}`)
  return NextResponse.next()
}
```

- `new Date()` — abhi ka moment (JS Date object)
- `.toISOString()` — ISO format mein string — `2026-08-15T12:26:48.836Z` — **UTC** (Z = UTC), sortable, unambiguous — log formats mein standard. `Z` suffix matlab UTC time hai, local nahi.

---

## Step 3 — IP Add Karna

"Kahan se?" — 4.6.5 wala `x-forwarded-for`:

```ts
export function proxy(request: NextRequest) {
  const method = request.method
  const pathname = request.nextUrl.pathname
  const ip = request.headers.get("x-forwarded-for") ?? "unknown"
  const time = new Date().toISOString()

  console.log(`[${time}] ${method} ${pathname} — IP: ${ip}`)
  return NextResponse.next()
}
```

**Final log format:**

```
[2026-08-15T12:26:48.836Z] GET /dashboard — IP: 49.36.10.5
```

Test karte waqt `::ffff:127.0.0.1` jaisi IP dikhegi — IPv6-mapped IPv4 format mein localhost hai (::ffff = IPv6 wrapper, 127.0.0.1 = localhost) — galat nahi hai.

## Bonus — Local Timezone Mein Log

ISO UTC format machine-readable hai, par insaan ko local time zyada samajh aata hai:

```ts
const localTime = new Date().toLocaleString("en-IN", {
  timeZone: "Asia/Kolkata",
  hour12: false,
})
```

```
15/08/2026, 17:56:48   ← IST local time
```

Development/debugging mein helpful — production logs mostly UTC (comparison ke liye) — dono ka use case hai.

## What It Is NOT

- **Logging = security check nahi** — logs sirf record hain. 4.6.12 (protected routes) aur 4.6.13 (rate limit) me checks honge — logging unse alag cheez hai (record karna vs decide karna).
- **Sab logs terminal mein nahi rehte** — production mein logs log-management services (jaise Vercel Logs, Datadog, Loki) mein jaate hain. `console.log` hi interface hai — destination infra decide karta hai.
- **`console.log` = user data leak nahi, par sensitive info log mat karo** — passwords/tokens logs mein mat daalo — logs bhi file mein store hote hain, breaches mein expose ho jaate hain.
- **Matcher limit ke bina har request log hogi** — static files ko exclude karna yaad rahe (matcher) warna log spam.

## Common Mistakes

- **Template literal mein `${}` bhoolna** — `console.log(method + " " + pathname)` chalta hai, par template literal readable hai — consistent style rakho.
- **IP log bina fallback** — `?? "unknown"` mat bhoolo (4.6.5 wala rule) — header missing pe null print hoga.
- **Bina matcher ke logging** — static files ke saare requests log ho jaate hain — noise. Negative matcher se clean.
- **Log mein secret data** — request body/headers ke tokens log karna security hole.

## Nutshell

Logging: `[${new Date().toISOString()}] ${request.method} ${request.nextUrl.pathname} — IP: ${ip ?? "unknown"}` — evidence for debugging. Proxy sabse acchi jagah hai logging ke liye (har request wahan se). UTC ISO logs = standard; local timezone = readability. Logs = record, checks alag (4.6.12/4.6.13).

1. Logs ko "evidence" kyun kehte hain — production mein bina logs ke kya mushkil hai?

**Sample Answer:** Jab koi problem report hoti hai ("kal raat site kharab thi") — bina logs ke tumhare paas proof/sahi jawab nahi hota kya hua, kab, kis request pe. Logs request ka record hote hain (time, method, path, IP) — investigation wahin se shuru hoti hai — "11:04 PM GET /dashboard IP 49.36.x.x" — usi time frame ke logs dekh kar root cause dhundte ho. Logs = saboot jo production mein tumhara asli debug tool hai.

</details>

2. `new Date().toISOString()` kya deta hai — aur log ke liye kyun use karte hain?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Abhi ka moment ISO format mein — `2026-08-15T12:26:48.836Z` — UTC time (Z suffix = UTC), 1 second tak precision. Logs ke liye kyun: (a) unambiguous — UTC ek hi standard hai, local timezone confusion nahi, (b) sortable — string order = chronological order, (c) machine-readable — log tools parse kar lete hain. Kabhi-kabhi local timezone readability ke liye (toLocaleString), par default ISO hi standard hai.

</details>

3. Final log line `[${time}] ${method} ${pathname} — IP: ${ip}` — har hissa kahan se aa raha hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `time` = `new Date().toISOString()` (abhi ka moment, UTC). `method` = `request.method` (HTTP method — GET/POST). `pathname` = `request.nextUrl.pathname` (kaunsi route — 4.6.4). `ip` = `request.headers.get("x-forwarded-for") ?? "unknown"` (kis IP se — 4.6.5). Sab kuch proxy ke `request` object se — ek hi jagah, har request ke liye poora record.

</details>

4. Logging security check kyun nahi — kaunsa note abhi aayega?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Logging sirf record karta hai — kya request aayi, kab, kahan se. Woh kuch decide nahi karta — na rokta hai, na redirect karta hai. Checks (login hai kya, kitni requests aayi) decisions hain — woh 4.6.12 (protected routes) aur 4.6.13 (rate limiting) mein honge. Logs = journal, checks = guard. Dono proxy mein rehte hain par kaam alag.

</details>

5. Logs mein sensitive data kyun nahi daalna chahiye — "logs bhi file hain" ka kya matlab?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Logs likhe jaate hain — files/cloud log services mein store hote hain, aur records kabhi delete nahi hote. Agar log mein password/token/personal data chala gaya — woh permanent record mein reh gaya — log files breach hoti hain toh data leaked. Password kabhi log nahi karte, tokens nahi — sirf method/path/IP jaisi metadata ki cheezein jo benign hain.

</details>
