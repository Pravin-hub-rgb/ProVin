Ab woh poori kahani kholege: **Proxy** — Next.js ki request interception layer. ## Problem — Har Page Pe Check Baar-Baar

Socho 10 pages ki app hai, aur tumhe **har request** pe kuch common karna hai:

- User logged in hai ya nahi?
- Kaunsi country se request aa rahi hai?
- Kitni requests aayi is IP se (rate limit)?
- Request ka log likhna hai?

Bina proxy ke 10 pages pe 10 baar same code copy-paste karna padega:

```tsx
// app/dashboard/page.tsx
export default async function DashboardPage() {
  // check auth
  // check country
  // check rate limit
  // log request
  return <h1>Dashboard</h1>;
}

// app/profile/page.tsx — wahi 4 checks dobara
```

Ek page pe check bhool gaye? **Unprotected page.** Aur code ka duplication bhi (1.5.2 wala wahi pain). Yeh problem hai — ab iska solution.

## Proxy Kya Hai — Security Guard Wali Kahani

Ek building socho — bahar ek **security guard** hai. Koi bhi andar jane se pehle **usi ek jagah** check hota hai:

- ID hai? (auth check)
- Pass laga hai? (rate limit)
- Visitor book mein naam likho (logging)

Building ke andar har room ke andar alag-alag guard nahi — **ek hi guard, entrance pe.** Wohi proxy hai.

**Proxy (middleware ka Next 16 naam):** Next.js ki ek file jo **har incoming request pe, page render hone se PEHLE** chalti hai. Request → **Proxy** → Page — yeh lifecycle hai. Proxy kuch decide kar sakta hai:

- **Aage bhejo** ("theek hai, andar jao")
- **Redirect karo** ("sahi page yahan nahi, /login pe jao")
- **Rok do** ("bhau bhau — 429 Too Many Requests")

Ek jagah likho, **saari routes cover.** Koi aur file mein check likhne ki zaroorat nahi.

---

## Next.js Version Story — Middleware Se Proxy Tak

Next.js mein yeh feature pehle **`middleware.ts`** ke naam se tha. Next.js 16 mein **rename** hua — ab file ka naam `proxy.ts` (ya `proxy.js`) hai. Rename ke saath syntax bhi thoda badla (`export function middleware` → `export function proxy`). Isliye purani tutorials mein `middleware.ts` dikhega, nayi cheezein `proxy.ts` mein — dono ek hi cheez hain, bas version.

Purani codebase upgrade kar rahe ho toh Next.js khud deprecation warning dikhata hai:

```
⚠ The "middleware" file convention is deprecated. Please use "proxy" instead.
```

Aur ek official codemod hai jo khud rename + fix kar deta:

```bash
npx @next/codemod@canary middleware-to-proxy .
```

## Kyun Proxy — Alternatives Kyon Reject Hui

Proxy ka poora point samajhne ke liye, do alternatives dekho jo kaam nahi karte:

**Alternative 1 — Har page pe check karo.** 4.5.3 mein dekha — route group layout mein auth check ek jagah hua, par page-level logic (logging, geo) har page pe repeat karni padti. Ek miss = unprotected page.

**Alternative 2 — Ek `ProtectedRoute` component banao.** Sab pages mein woh component wrap karo — phir bhi har page ko import + wrap karna padta hai, aur sirf component-render level pe check hota hai (route pe nahi).

Proxy in dono ki jagah hai: **route-level, ek file, har request.** "Request kisi bhi page/API pe ja rahi ho — pehle proxy se guzro."

> **Note:** Express (Node.js) ka middleware alag cheez hai — woh Express ke andar ek function hai jo route ke saath manually chain hota hai. Next.js ka proxy framework-level hai — tumhare control ke bahar, har request pe khud chalta hai. Confuse mat karna.

## What It Is NOT

- **Proxy = security ka main layer nahi.** Batch 4 mein fix kiya tha (CVE-2025-29927) — proxy **bypass** ho sakta hai (header spoofing), isliye auth check layout/Server Component mein hota hai, proxy sirf routing/infra kaam karta hai. Is series ke 4.6.12 aur 4.6.17 mein yeh detail mein dekhenge — wahan tak yeh rule yaad rakho.
- **Proxy = Route Handler nahi.** Route handler (`route.ts`) API endpoint hai — client calls karta hai, data return hota hai. Proxy endpoint nahi hai — woh **bich wala layer** hai jo requests intercept karta hai, unhe route karta hai. Alag kaam, alag files.
- **Proxy = har page pe khud run nahi hota** — woh **pehle** chalta hai, ek baar, aur uski decision ke baad hi page render hota hai. Lifecycle: Request → Proxy → Page.

## Common Mistakes

- **Purani docs mein `middleware.ts` syntax copy karna** — Next 16 mein `export function proxy` chahiye, `export default function middleware` nahi.
- **Proxy ko Node.js cheezein use karwana** (fs, bcrypt, Prisma) — Edge runtime mein chalta hai, wahan yeh available nahi. 4.6.15/4.6.16 mein detail.
- **Proxy mein heavy work karna** — har request pe chalta hai; slow ho toh har page slow. Golden rule 4.6.16 mein.

## Nutshell

Proxy = building ka entrance guard. Har request pe, render se pehle, ek file mein saari routes ka common kaam (check/redirect/log/block). Pehle `middleware.ts` tha, Next 16 mein `proxy.ts`. Batch 4 mein auth routing ke liye chhota sa use kiya tha — ab poori power dekhenge.
