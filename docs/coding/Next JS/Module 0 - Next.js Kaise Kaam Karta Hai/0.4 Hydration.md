0.3 mein humne jaana ki Server Components ready HTML bhejte hain, aur Client Components `"use client"` se browser pe interactive kaam karte hain. Par yahan ek subtle problem hai — **server ne plain HTML bheja, par buttons pe kaun sa `onClick` attach hua?**

Socho 0.3 wali `Counter.tsx` — `"use client"` wala `<button onClick={...}>`. Server ne uska HTML bheja. Browser pe woh button dikha. Par ab tak uspe **koi "click" listener nahi** hai. Kaunsa JS chalega jab user click karega?

Yeh gap hi **hydration** bharata hai.

## Hydration Define Kar Lete Hain

Server-rendered HTML content sahi dikha raha hai — par uspe koi **event listener ya state attach** nahi. **Hydration** = existing server-created HTML ke upar React ka **event listeners + state attach** karna, taaki woh static se interactive ho jaye.

**Important:** Hydration ka matlab **HTML dobara banana nahi** — React server ka ready content adopt karta hai aur uspe interactivity (state, events, re-renders ka hook) jodta hai.

## What Happens Actually (3-step)

```
[1] Server bhejta hai ready HTML (server component render)  → user ko turant content dikhta hai
[2] Browser par wahi HTML paint hota hai (copy jaisa — content correct)
[3] JS bundle download + execute → React "hydrates" —
    existing DOM nodes pe event handlers + state attach karta hai
    → ab interaction tick hone lagte hain
```

### Timing — Isliye 0.1 Se Related

Yahan ek subtle baat samajhni hai. HTML (step 1-2) **fast** aata hai — content turant dikhta hai, yehi SSR ka fayda. Par interaction (step 3) ke liye bundle download, execute, aur hydration hona padta hai — tab tak buttons "dead" lagte hain. Yehi "CSR vs SSR" ka tension hai: SSR ke baad bhi **JS load hone** se pehle interactivity nahi milti.

## Hydration Mismatch — Server Tree vs Client Tree

Ruko, soch 0.3 wala `Counter` `"use client"` — uska HTML server ne bheja, aur phir browser pe woh **same tree** ke upar React listeners attach karta hai. Agar HTML aur client JS tree **mismatch** ho jaye (server render different from client) — React confuse ho jata hai aur hydration mismatch error aata hai.

Example mismatch: Client component mein `Math.random()` render, `Date.now()`, ya `window` pe depend karna. Server aur client pe alag value → mismatch.

```tsx
"use client";
export default function Bad() {
  // server pe time abhi, client pe time kuch min baad — alag → mismatch!
  return <p>{new Date().toString()}</p>;
}
```

Fix: yeh chizein `useEffect` mein dalo ya `useState` (client-only mount) — interactivity baad mein.

## What It Is NOT

⚠️ **Hydration = server HTML ko dobara render karna nahi.** Server ne ready HTML bhej diya — hydration bas usi pe listeners attach karta hai, content dobara nahi banata.

⚠️ **Hydration = SEO fix nahi (usi alone).** SEO ka fayda HTML content pehle se hona hai — hydration to sirf usko interactive banata hai. Timing alag.

⚠️ **Server Components par hydration ka overhead nahi.** Unka client JS bundle hota hi nahi — React ke paas attach karne ko kuch nahi hota. Pure static content optimized.

## Plain Summary

- SSR bhejta hai ready HTML — content turant
- Bundle aata hai — React us HTML pe interactivity attach karta hai = **hydration**
- Iske baad hi state, events, updates tick hoti hain
- Agar server HTML aur client JS tree mismatch ho → hydration error
- Server Components (no client JS) pe hydration ka overhead nahi — pure static optimized
