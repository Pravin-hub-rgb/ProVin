## create-next-app vs Building React From Scratch

To build a React app (with `create-react-app` or Vite), you had to choose and set up routing, ESLint, build configuration, and bundler separately. **`create-next-app` does all of this in one command** — TypeScript, ESLint, App Router, Tailwind, the dev server — everything is ready to code. That is the "zero config feel" — start building, not configuring.

| What you need to set up manually in React | What create-next-app gives you for free |
|---|---|
| React Router (separate install + config) | File-based routing built-in |
| ESLint (manual config) | ESLint pre-configured |
| Build config (vite/webpack, tsconfig) | Everything pre-configured |
| SSR / SSG setup (extra libraries) | SSR, SSG, ISR — all built-in |
| Image optimization (third-party) | `next/image` |
| TypeScript (separate setup) | TypeScript by default |

## The Command

In your terminal:

```bash
npx create-next-app@latest
```

You will be asked setup questions — choose the **recommended defaults**:

- **TypeScript**: Yes
- **ESLint**: Yes (best practice — catches errors before they happen)
- **Tailwind CSS**: Yes (or your preferred styling choice)
- **App Router**: Yes (the structure we learned in 0.7)
- **Import alias**: Yes (adds `@/` so you can import from the project root)
- **App router styles**: Use `app/` directory (default)

One command sets up the entire tooling chain that React required you to assemble piece by piece.

## What You Get — Project Structure

```
my-app/
├── app/
│   ├── layout.tsx        → root layout (wraps every page: html, body, header)
│   ├── page.tsx          → home page (route: /)
│   └── globals.css       → global styles
├── public/               → static assets (images, files)
├── package.json
├── next.config.ts        → Next.js configuration
├── tsconfig.json
├── next-env.d.ts         → auto-generated TypeScript declarations
└── .gitignore
```

The `app/` folder is the **App Router** route structure (covered in 0.7). The `public/` folder holds static files that are served directly — `/logo.png` maps to `public/logo.png`.

### Daily Commands (package.json scripts)

| Command | What it does |
|---|---|
| `npm run dev` | Starts the development server (localhost:3000) with hot reload |
| `npm run build` | Creates a production build (generates SSG / SSR / ISR pages) |
| `npm start` | Runs the production build locally |
| `npm run lint` | Runs ESLint to catch code errors and enforce style rules |

## The `@/` Import Alias

`create-next-app` sets up the `@/` alias by default. `@/components/Header` means "the `Header` component at the project root." This gives you **clean, root-based imports** instead of messy relative paths like `../../../components/Header`.

```tsx
import Header from "@/components/Header";  // root-based, clean
```

## Running — First Success

```bash
cd my-app
npm run dev
```

Open `http://localhost:3000` in your browser. The default Next.js starter page appears. Now edit `app/page.tsx`, save the file, and hot reload shows your change instantly. **This is your first Next.js page.**

## What It Is NOT

⚠️ **create-next-app is not bloated.** The files it scaffolds (`app/`, `public/`, `package.json`) are all essential — it is a bare-bones starter, not a heavy boilerplate.

⚠️ **It is not zero-config — it is prompt-based config.** You still choose TypeScript, ESLint, Tailwind. But you do it once, during setup, and the tooling is ready.

## In Your Own Words

1. What does `create-next-app` give you that you would have to set up manually in a React project?

<details>
<summary>Sample Answer</summary>

**Answer:** TypeScript, ESLint, App Router, a development server with hot reload, build configuration, and built-in SSR/SSG support. In a manual React setup, you would install and configure React Router, ESLint, a bundler (Vite/webpack), and an SSR library separately.

</details>

2. What is the difference between `npm run dev` and `npm run build` + `npm start`?

<details>
<summary>Sample Answer</summary>

**Answer:** `npm run dev` starts the development server with hot reload — fast iteration, debugging enabled. `npm run build` generates the production-ready files, and `npm start` runs that production build. You use `dev` while coding and `build` + `start` when deploying.

</details>

3. What goes in the `public/` folder?

<details>
<summary>Sample Answer</summary>

**Answer:** Static assets that should be served directly at a URL — images (`/logo.png`), favicons, PDFs, fonts. Anything in `public/` is accessible at `/{filename}` without going through your React app.

</details>

4. What does the `@/` alias do, and why is it useful?

<details>
<summary>Sample Answer</summary>

**Answer:** `@/` points to the project root. Instead of writing `import Header from "../../../components/Header"` (which breaks if you move files), you write `import Header from "@/components/Header"` — it always works because it starts from the root.

</details>

5. How does `app/page.tsx` relate to the App Router concepts from 0.7?

<details>
<summary>Sample Answer</summary>

**Answer:** `app/page.tsx` is the **home route** (`/`) in the App Router. The file-system routing rule from 0.7 says: a folder + `page.tsx` = a route. So `app/page.tsx` is the root route, and `app/about/page.tsx` would be the `/about` route.

</details>
