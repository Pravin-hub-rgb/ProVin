0.2 mein humne dekha ki SSR, SSG aur CSR ko **ek hi page pe mix** kiya ja sakta hai — aur bola ki *"component level pe decide karenge server pe render hoga ya client pe."* Usi promise ko ab detail mein pura karte hain. Yehi hai **React Server Components**.

Asli fark jahan decide hota hai woh hai **environment** — kaunsa code **server pe** render hoga (data fetch + ready HTML) aur kaunsa **browser mein** chale ga (interactivity). Yahi decision component level pe hota hai, page level pe nahi. Isko ek table mein dekhte hain:

| | Server environment | Client environment |
|---|---|---|
| **Kaha chalta hai** | Server pe (Node.js runtime) | Browser mein (user ki machine) |
| **Kab** | Request time pe, page serve hone se pehle | Browser mein, page load hone ke baad |
| **Kya kar sakta hai** | Data fetch (`await`), DB/API direct, secrets | State, events, hooks, browser APIs |
| **Kya nahi kar sakta** | Hooks, events, browser APIs | Direct DB / server secrets |

## Server Components — Naye React Concept (App Router)

**React Server Components (RSC)** ka simple definition: components jo **server pe render** hote hain (data fetch karke ready HTML bhejte hain) bina client-side JavaScript bundle mein chal ke. **App Router ke components default server components hote hain.**

```tsx
// app/page.tsx (Server Component — default!)
export default async function HomePage() {
  const posts = await getPosts();   // server pe data fetch
  return <div>{posts.map(p => <Post key={p.id} {...p} />)}</div>;
}
```

Is file mein `async` function hai jo `await` se data fetch karta hai — yeh **client bundle mein kaam nahi** karega. Server pe chalta hai, ready HTML bheja jata hai. Isliye **no client-side loading state zaroori nahi** — data server ke paas hai hi.

## Client Components — Jab Interactivity Chahiye

Jab component ko **browser-side interactive** hona hai (state, events, hooks, effects) — tab use `use client` directive:

```tsx
// components/Counter.tsx (Client Component)
"use client";
import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>Count: {count}</button>;
}
```

`"use client"` ka matlab hai — **yeh code client-side bundle mein jayega** aur browser pe chalega (interactions handle karega). Server se bhi alag.

## What Can't Be In Both (Simple Rule)

## Server Component Mein Kya Hota Hai, Kya Nahi

Server Component ka rule simple hai: jo kaam client ki interactivity se juda hai, woh server pe nahi ho sakta. Isliye server components mein **React hooks** (`useState`, `useEffect` — sab interactivity wale), **browser APIs** (`window`, `document` — jo sirf client pe exist karti hain), aur **event handlers** (`onClick` — server pe koi event hota hi nahi) use nahi kar sakte.

Uski jagah jo cheezein server component mein naturally strong hain woh yeh hain: `async`/`await` se **direct data fetch** (bina client-side loading state ke), **DB/API ko directly read** karna, aur **server libraries** — jahan secret keys hain (.env backend secrets) — kyunki yeh code client bundle mein jaata hi nahi. Aur ek important point — server component ek client component ko **children** ke roop mein render kar sakta hai, isi se dono ek hi page pe mix ho jaate hain.

> **Key: "use client" is boundary mark** — matlab is line ke **neeche** wala component subtree client-side bundle mein jayega. Upar wala server pe rahega. Isi se ek hi page pe dono mix hote hain (0.2 ka promise!).

## Rules — Mixing Ke Niyam

Rules bhi simple hain. Server component ek client component ko import + render kar sakta hai — wo uske children ke roop mein aata hai. Par ulta — ek client component ke andar server component ko directly import nahi kar sakte; safe path hai server component ko **children/prop** ke roop mein pass karna (nahi toh woh code client bundle mein aa jayega, jisse heavy computations ya secrets leak ho sakte hain). Aur dono files mein ek chhota technical rule — `"use client"` string hamesha file ke top par **pehla statement** hona chahiye.

## What It Is NOT

⚠️ **Next.js mein `use server` = `use client` ka ulta nahi.** `use server` functions (Server Actions) POST endpoints banate hain, `use client` ki tarah component boundary nahi. (Inhe aage modules mein detail se dekhenge — abhi sirf `use client` yaad rakho.)

⚠️ **Server component = slower ke liye nahi, faster hi.** Bade client bundles reduce karta hai (server code bundle me nahi jaata).

⚠️ **RSC sirf App Router mein use hote hain** (Pages Router alag model tha). `"use client"` bhi App Router ke saath hi apply hota hai.

## Summary

- App Router — components **default server** (RSC) — server pe render + data fetch ready HTML
- Interactive components — `"use client"` — client bundle, browser pe chalta hai
- RSC can: async/await, DB/API, server secrets/libraries
- RSC can't: hooks, browser APIs, events
- Mix allowed — a Client component ko RSC ke children ke roop mein pass karo
