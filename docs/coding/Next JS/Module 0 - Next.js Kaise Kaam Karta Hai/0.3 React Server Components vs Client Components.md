0.2 mein humne dekha ki SSR, SSG aur CSR ko **ek hi page pe mix** kiya ja sakta hai — aur bola ki *"component level pe decide karenge server pe render hoga ya client pe."* Usi promise ko ab detail mein pura karte hain. Yehi hai **React Server Components**.

Ek aisa kitchen socho jahan har dish ke liye alag rule hai — kuch dishes chef kitchen mein banata hai aur ready serve karta hai, kuch dishes tumhare table pe tumhare saamne banate hain.

## Kitchen Wala Example — Chef Kab Banata Hai, Customer Kab

Ek coffee shop pe do tarah ke orders:

1. **Barista pehle se banakar rakhta hai / kitchen mein banakar deta hai** → customer ko sirf ready cup milta hai. → *Ye hai **Server Component**.*
2. **Customer khud espresso machine operate karta hai event pe** (milk foam ko chhoota hai, switch toggles) → customer interaction ke saath live. → *Ye hai **Client Component**.*

User ko content wahi — coffee hi toh ban rahi hai. Fark yeh hai **kaun se environment mein kaam hua** (kitchen/server vs table/client) aur **kab** (pehle se vs live interaction pe).

## Server Components — Naye React Concept (App Router)

**React Server Components (RSC)** ka simple definition: components jo **server pe render** hote hain (data fetch karke ready HTML bhejte hain) bina client-side JavaScript bundle mein chal ke. **App Router ke components default server components hote hain.**

```tsx
// app/page.tsx (Server Component — default!)
export default async function HomePage() {
  const posts = await getPosts();   // server pe data fetch
  return <div>{posts.map(p => <Post key={p.id} {...p} />)}</div>;
}
```

Is file mein `async` function hai jo `await` se data fetch karta hai — yeh **client bundle mein kaam nahi** karega. Server pe chalta hai, ready HTML bheja jata hai. Isliye **no client-side loading state zaroori nahi** — data server ke paas hai hi.

## Client Components — Jab Interactivity Chahiye

Jab component ko **browser-side interactive** hona hai (state, events, hooks, effects) — tab use `use client` directive:

```tsx
// components/Counter.tsx (Client Component)
"use client";
import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>Count: {count}</button>;
}
```

`"use client"` ka matlab hai — **yeh code client-side bundle mein jayega** aur browser pe chalega (interactions handle karega). Server se bhi alag.

## What Can't Be In Both (Simple Rule)

### Server Components mein allowed ❌
- React hooks (`useState`, `useEffect`, etc.) — interactivity wale
- Browser APIs (window, document) — client pe hote hain
- Event handlers (`onClick` etc.) — server pe events nahi

### Server Components mein allowed ✅
- `async` / `await` data fetching (direct!)
- Reading DB / APIs directly
- Server libraries (jahan secret keys hain — .env backend secrets use kar sakte ho)
- Rendering Client Components as children

> **Key: "use client" is boundary mark** — matlab is line ke **neeche** wala component subtree client-side bundle mein jayega. Upar wala server pe rahega. Isi se ek hi page pe dono mix hote hain (0.2 ka promise!).

## Rules / Can't Do

- **Server component mein Client component import allowed hai**, lekin vice-versa mein woh chiz e.g. private heavy computations nahi kar sakte (bundle me jayegi). Safe path: Client component ko **children/prop** ke roop mein pass karo.
- Server component direct `console.log`/`fetch` module-level nahi — woh ek file mein hota hai, aur secret leak server bundle ke liye nahi hai.
- Client component file top mein `"use client"` string must be first statement.

## What It Is NOT

⚠️ **Next.js ke lie `use server` = function alag file bhejna.** Careful — `use server` functions (Server Actions) Next.js mein POST endpoints banate hain, `use client` koil nahi. (0.key mein rakhenge — abhi sirf `use client` yaad rakho.)

⚠️ **Server component = slower ke liye nahi, faster hi.** Bade client bundles reduce karta hai (server code bundle me nahi jaata).

⚠️ **RSC sirf App Router mein use hote hain** (Pages Router alag model tha). `"use client"` bhi App Router ke saath hi apply hota hai.

## Summary

- App Router — components **default server** (RSC) — server pe render + data fetch ready HTML
- Interactive components — `"use client"` — client bundle, browser pe chalta hai
- RSC can: async/await, DB/API, server secrets/libraries
- RSC can't: hooks, browser APIs, events
- Mix allowed — a Client component ko RSC ke children ke roop mein pass karo
