Ab tak humne rendering concepts samajh chuke — SSR, SSG, ISR, Server Components, caching, hydration. Par ek baat ab tak miss hai: **routing.** React course mein `React Router` ke `<Route path="/about">` configs yaad hain. Next.js mein routing **alag tareeke** se hota hai — file-based. Isko samjho toh React Router vs Next.js ka confusion gayab.

## File-based Routing — Folder = URL

Next.js ka rule bilkul direct hai: **folder ka naam = URL path, aur usme `page.tsx` = actual route content.**

**Next.js mein:** Folder banao (`app/about/`) aur usme ek file `page.tsx` banao — automatically `/about` URL ban jata hai. **Koi route config nahi, koi setup nahi** — folder structure hi routes.

## App Router — The Base Rules

```
app/
├── page.tsx          →  /          (home)
├── about/
│   └── page.tsx      →  /about
├── blog/
│   ├── page.tsx      →  /blog
│   └── [slug]/
│       └── page.tsx  →  /blog/:slug  (dynamic)
├── layout.tsx        →  shared layout (parent wrapper)
└── not-found.tsx     →  404 page
```

### Key Rules

| Concept | Syntax | Kya Hota Hai |
|---|---|---|
| **Home** | `app/page.tsx` | `/` pe route |
| **Static route** | `app/about/page.tsx` | `/about` |
| **Dynamic route** | `app/blog/[slug]/page.tsx` | `/blog/anything` → `params.slug` |
| **Shared layout** | `app/layout.tsx` | Har page ke around wrap hota hai (header/footer) |
| **404** | `app/not-found.tsx` | Not found page |

### Dynamic Route — `params`

```tsx
// app/blog/[slug]/page.tsx
export default async function BlogPost({ params }) {
  const { slug } = await params;   // URL se variable
  return <h1>Blog: {slug}</h1>;
}
```

Compare karo React Router: `useParams()` se `{ slug } = useParams()` lete the. **Concept same** — dynamic segment se value nikalna — bas implementation alag (file name `[slug]` + `params`).

## Layouts — Har Page Pe Repeat Hoti Cheez

`app/layout.tsx` ek **root layout** hai jo har page ke around render hota hai (header, footer, navigation) — React mein `Outlet`/wrapper component jaisa. Nested layouts bhi possible hain (`app/blog/layout.tsx` sirf blog pages pe wrap hota hai).

```tsx
// app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <Header />          {/* har page pe */}
        {children}           {/* current page */}
      </body>
    </html>
  );
}
```

## Client vs Server — Routing Mein Bhi

0.3 ke concepts routing mein bhi apply hote hain. `layout.tsx` aur `page.tsx` by default **Server Components** hote hain — server pe render hoke ready HTML aata hai. Interactivity chahiye toh `"use client"` components ke andar hi `useState`, `useEffect`, event handlers lagte hain. Aur page ke beech navigation ke liye `<Link>` use karo — yeh **client-side navigation** karta hai (page reload nahi, React Router jaisa smooth).

```tsx
import Link from "next/link";

<Link href="/blog">Blog</Link>   {/* reload nahi, SPA-style navigate */}
```

## What It Is NOT

⚠️ **App Router mein saare folders URL nahi bante.** `[slug]` ya `(group)` folders URL mein **nahi** dikhte — route groups `(dashboard)` sirf organizational hain. Sirf normal folders hi URL banate hain.

⚠️ **App Router ≠ React Router replacement syntax.** Tum `<Routes>`/`<Route>` configs nahi likhte — par `Link`, `useParams`-style (params), nested structure — concepts wahi. File-based hi Next.js ka model hai.

⚠️ **`page.tsx` bhi `page` name hi, koi bhi doosra nahi.** `about/page.tsx` hi correct — `about/index.tsx` chalti nahi App Router mein.

## Summary

- **File-based routing** — folder + `page.tsx` = URL
- **Dynamic** — `[slug]` folder + `params`
- **Layouts** — `layout.tsx` shared wrapper
- `"use client"` vs Server Components mixing (0.3) ab routing mein bhi
- `<Link>` se client-side navigation
