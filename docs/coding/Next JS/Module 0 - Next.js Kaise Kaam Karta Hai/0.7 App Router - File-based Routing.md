Ab tak humne rendering concepts samajh chuke — SSR, SSG, ISR, Server Components, caching, hydration. Par ek baat ab tak miss hai: **routing.** React course mein `React Router` ke `<Route path="/about">` configs yaad hain. Next.js mein routing **alag tareeke** se hota hai — file-based. Isko samjho toh React Router vs Next.js ka confusion gayab.

## File-based Routing — Folder = URL

Next.js ka rule bilkul direct hai: **folder ka naam = URL path, aur usme `page.tsx` = actual route content.**

**Next.js mein:** Folder banao (`app/about/`) aur usme ek file `page.tsx` banao — automatically `/about` URL ban jata hai. **Koi route config nahi, koi setup nahi** — folder structure hi routes.

## App Router — The Base Rules

```
app/
├── page.tsx          →  /          (home)
├── about/
│   └── page.tsx      →  /about
├── blog/
│   ├── page.tsx      →  /blog
│   └── [slug]/
│       └── page.tsx  →  /blog/:slug  (dynamic)
├── layout.tsx        →  shared layout (parent wrapper)
└── not-found.tsx     →  404 page
```

### Key Rules

| Concept | Syntax | Kya Hota Hai |
|---|---|---|
| **Home** | `app/page.tsx` | `/` pe route |
| **Static route** | `app/about/page.tsx` | `/about` |
| **Dynamic route** | `app/blog/[slug]/page.tsx` | `/blog/anything` → `params.slug` |
| **Shared layout** | `app/layout.tsx` | Har page ke around wrap hota hai (header/footer) |
| **404** | `app/not-found.tsx` | Not found page |

### Dynamic Route — `params`

```tsx
// app/blog/[slug]/page.tsx
export default async function BlogPost({ params }) {
  const { slug } = await params;   // URL se variable
  return <h1>Blog: {slug}</h1>;
}
```

Compare karo React Router: `useParams()` se `{ slug } = useParams()` lete the. **Concept same** — dynamic segment se value nikalna — bas implementation alag (file name `[slug]` + `params`).

## Layouts — Har Page Pe Repeat Hoti Cheez

`app/layout.tsx` ek **root layout** hai jo har page ke around render hota hai (header, footer, navigation) — React mein `Outlet`/wrapper component jaisa. Nested layouts bhi possible hain (`app/blog/layout.tsx` sirf blog pages pe wrap hota hai).

```tsx
// app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <Header />          {/* har page pe */}
        {children}           {/* current page */}
      </body>
    </html>
  );
}
```

## Layout Server Hai, Navbar Client Hai — Kaise Kaam Karta Hai?

Ek confusion hota hai — `layout.tsx` toh Server Component hai, par usme `<Navbar />` import karte ho jisme state, buttons, click handlers hain — toh `"use client"` lagta hai. Toh kya **Server Component ek Client Component ko import kar raha hai?** Kya dono mix ho jaate hain?

**Mix nahi hote. Clear boundary hai.** Dekho kya hota hai:

```tsx
// components/Navbar.tsx — Client Component
"use client";
export default function Navbar() {
  const [menuOpen, setMenuOpen] = useState(false);
  return <nav onClick={() => setMenuOpen(!menuOpen)}>...</nav>;
}
```

```tsx
// app/layout.tsx — Server Component (default)
import Navbar from '@/components/Navbar';

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <Navbar />       {/* ye Client Component hai */}
        {children}
      </body>
    </html>
  );
}
```

Yahan kya ho raha hai — step by step:

| Step | Location | Kya hota hai |
|---|---|---|
| 1 | Server | `layout.tsx` render hota hai — HTML banta hai |
| 2 | Server | `<Navbar />` ka sirf **placeholder** HTML mein aata hai (`<div id="Navbar">`) |
| 3 | Server | Baki sab (`<html>`, `<body>`, `{children}`) full HTML mein render |
| 4 | Browser | HTML aata hai — Navbar ki jagah pe placeholder dikh raha hai |
| 5 | Browser | Navbar ka JS bundle download hota hai |
| 6 | Browser | React hydrate — placeholder pe Navbar ka actual HTML + state attach |

**Server pe Navbar ka asli render nahi hota** — sirf placeholder aata hai. Asli Navbar ka code client bundle mein jaata hai. Isliye server aur client **mix nahi hote** — boundary `"use client"` line pe clear hai. Uske upar sab server pe, neeche sab client pe.

```
Server Component (layout.tsx)
│
├── HTML banta hai: <html><body>...
│   └── <Navbar placeholder>     ← sirf ek jagah reserve
│   └── {children}               ← page ka content
│
└── Client Bundle (Navbar)
    └── "use client" ke neeche ka pura code
        └── React client pe hydrate karta hai
            └── placeholder ko actual Navbar mein convert
```

**Rule yaad rakho:** Server Component Client Component ko **import + render** kar sakta hai — ye valid hai. Par **ulta nahi** — Client Component seedha Server Component ko import nahi kar sakta (unsafe hai, server code client bundle mein leak ho sakta hai). Safe path hai — server component ko `children` ya prop ke roop mein pass karna.

### Boundary Ka Direction — Kya Client Hai, Kya Nahi

Ek baat clear kar lete hain — `"use client"` ke neeche ka **pura subtree** client-side bundle mein jaata hai. Matlab agar `Navbar` mein `"use client"` hai, aur usme `<Logo />`, `<Menu />` render ho rahe hain — **woh sab Client Components hain.** Directly define kiya hai ya import kiya hai — farak nahi padta, boundary ke neeche hai toh client hai.

```tsx
"use client";
export default function Navbar() {
  return (
    <nav>
      <Logo />      {/* Client — "use client" ke neeche hai */}
      <Menu />      {/* Client — same reason */}
    </nav>
  );
}
```

Par boundary **per-file** hoti hai — sirf jis file mein `"use client"` hai, woh file Client Component hai. Baaki sab Server. Example:

```tsx
// layout.tsx — Server Component (default, koi "use client" nahi)
import Navbar from './Navbar';       // Client — "use client" hai isme
import ServerComp from './ServerComp'; // Server — koi "use client" nahi

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <Navbar />       {/* Client */}
        <ServerComp />   {/* Server — seedha import hai, layout bhi server hai */}
        {children}       {/* Server */}
      </body>
    </html>
  );
}
```

Yahan `ServerComp` Server Component hai kyunki `layout.tsx` mein koi `"use client"` nahi hai. `ServerComp` ka HTML server pe render hota hai — sirf `Navbar` ka placeholder aata hai.

Par **ek exception** hai — tum Server Component ko Client Component ke `children` ya prop ke roop mein pass kar sakte ho. Directly import nahi, par prop se:

```tsx
// layout.tsx (Server)
import Navbar from './Navbar';
import ServerFooter from './ServerFooter';  // Server Component

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <Navbar>
          <ServerFooter />   {/* Server Component — as children */}
        </Navbar>
        {children}
      </body>
    </html>
  );
}
```

```tsx
// Navbar.tsx (Client)
"use client";
export default function Navbar({ children }) {
  return (
    <nav>
      <Logo />        {/* Client */}
      {children}      {/* Server — prop se aaya, React handle karta hai */}
    </nav>
  );
}
```

Ye kaam karta hai kyunki `ServerFooter` ko directly import nahi kiya gaya — prop ke roop mein pass kiya gaya hai. React server pe `ServerFooter` ka HTML render karta hai aur wo HTML `Navbar` ko mil jaata hai. Directly import karte toh server code client bundle mein leak hota — isliye wo unsafe hai.

## Client vs Server — Routing Mein Bhi

Upar ka example samajh lo toh ye clear ho jaata hai — `layout.tsx` aur `page.tsx` by default **Server Components** hote hain. Par unme Client Components (`"use client"` wale) ko import karke render kar sakte hain. Aur page ke beech navigation ke liye `<Link>` use karo — yeh **client-side navigation** karta hai (page reload nahi, React Router jaisa smooth).

```tsx
import Link from "next/link";

<Link href="/blog">Blog</Link>   {/* reload nahi, SPA-style navigate */}
```

## What It Is NOT

⚠️ **App Router mein saare folders URL nahi bante.** `[slug]` ya `(group)` folders URL mein **nahi** dikhte — route groups `(dashboard)` sirf organizational hain. Sirf normal folders hi URL banate hain.

⚠️ **App Router ≠ React Router replacement syntax.** Tum `<Routes>`/`<Route>` configs nahi likhte — par `Link`, `useParams`-style (params), nested structure — concepts wahi. File-based hi Next.js ka model hai.

⚠️ **`page.tsx` bhi `page` name hi, koi bhi doosra nahi.** `about/page.tsx` hi correct — `about/index.tsx` chalti nahi App Router mein.

## Summary

- **File-based routing** — folder + `page.tsx` = URL
- **Dynamic** — `[slug]` folder + `params`
- **Layouts** — `layout.tsx` shared wrapper
- `"use client"` vs Server Components mixing (0.3) ab routing mein bhi
- `<Link>` se client-side navigation
