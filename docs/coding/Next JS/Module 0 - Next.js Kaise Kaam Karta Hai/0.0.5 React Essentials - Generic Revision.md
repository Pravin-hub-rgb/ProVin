## 1. JSX — HTML + JavaScript Ek Saath

JSX dikhne mein HTML jaisa hai, par asal mein JavaScript hai. Component `return` ke andar jo dikhta hai, wahi render hota hai.

```tsx
function Greeting() {
  return <h1>Hello, {name}!</h1>;  // {} ke andar JavaScript variable
}
```

> **Yaad rakh:** `{}` ke andar tum JavaScript ke expressions likh sakte ho (variables, function calls, conditions). `className` HTML ke `class` ki jagah hai (kyunki `class` JS keyword hai).

## 2. Components + Props

Component ek function hai jo UI ka ek piece bana kar return karta hai. Props = component ko pass kiye jaane wale data (inputs).

```tsx
interface CardProps {
  title: string;
  count: number;
}

function Card({ title, count }: CardProps) {
  return <div>The {title} has {count} items</div>;
}

<Card title="To-Do" count={3} />  // use karo jitni baar chaho
```

## 3. useState — Data Yaad Rakhna

React ko pata chalana hai ki "yeh value change hui" taaki UI update ho — plain variable se React nahi jaanta. Isliye `useState`.

```tsx
const [count, setCount] = useState(0);
// count = current value, setCount = update karne wala function

<button onClick={() => setCount(count + 1)}>+</button>
```

> **Yaad rakh:** Setter (setCount) se hi value badalni hai, seedha `count = ...` nahi. React tabhi re-render karega.

## 4. Lists + Keys

Array ko UI mein dikhane ke liye `.map()` use hota hai. Har item ko ek unique `key` ditte hain taaki React ko pata rahe kaunsa item hai (diffing ke liye — Module 0 React mein yaad tha):

```tsx
<ul>
  {items.map((item) => (
    <li key={item.id}>{item.name}</li>
  ))}
</ul>
```

## 5. Conditional Rendering

React mein `if` bolna allowed nahi, lekin ternary (`? :`) aur `&&` use hote hain:

```tsx
{isLoading ? <p>Loading...</p> : <p>{data}</p>}
{isAdmin && <button>Delete</button>}  // true hua toh dikhega
```

## 6. useEffect — Side Effects (API, Timer, Storage)

React ke render cycle ke bahar ke kaam (data fetch, timers, browser APIs) ko handle karta hai. Dependency array `[]` decide karta hai kab chalega.

```tsx
useEffect(() => {
  fetch("/api/users").then((r) => r.json()).then(setUsers);
}, []);  // [] = sirf mount pe ek baar
```

> **Yaad rakh:** Server Components (Next.js mein) mein `useEffect` ki zaroorat hi nahi padegi data fetch ke liye — yeh 0.3 mein dekhenge. Par client-side interactivity mein abhi bhi use hota hai.

## 7. React Router — Generic Yaad

React mein pages ke beech navigation React Router se hota tha. Concretes:

| Cheez | Kya karta hai |
|---|---|
| `<BrowserRouter>` / `<Routes>` / `<Route>` | Routing setup + route define karna |
| `<Route path="/about" element={<About/>} />` | URL `/about` pe `<About/>` render |
| `<Link to="/about">` | Page refresh ke bina navigate karna |
| `path="/movies/:id"` + `useParams()` | Dynamic route — URL se variable nikalna (`:id`) |
| `useNavigate()` | Code se programmatically navigate (`navigate("/login")`) |
| Nested routes `/parent/child` | Route structure nested banana |
| Protected routes | Sirf "logged in" users ko page dikhna — auth-check wrapper |

> **Yaad rakh:** yeh *generic* concept hai. Next.js mein routing **file-based** hai (folder banao, page banao) — React Router ke `<Route>` configs ki jagah. Concept (dynamic segment = variable, navigate karna) wahi hai, implementation alag. Issi ko 0.7 mein detail se dekhenge.

## 8. Forms — Controlled Inputs (Generic)

React mein form input ko "controlled" banane ka matlab — input ki value state se aati hai aur `onChange` se update hoti hai.

```tsx
const [email, setEmail] = useState("");
<input value={email} onChange={(e) => setEmail(e.target.value)} />
```

Skills: **React Hook Form (RHF)** se form kam re-renders mein manage hota hai, aur **Zod** se validation schema-based hoti hai (types bhi automatic aate hain). Inko Next.js mein bhi use karenge — seedha React ki tarah.

```tsx
// RHF + Zod ka generic shape
const schema = z.object({ email: z.string().email() });
const { register, handleSubmit } = useForm({ resolver: zodResolver(schema) });

<form onSubmit={handleSubmit(onSubmit)}>
  <input {...register("email")} />
  <button type="submit">Submit</button>
</form>
```

## 9. State Management — Context aur Zustand (Generic One-liners)

- **Context API:** Global state jo components ke beech prop-drilling ke bina share karta hai (`createContext` + `useContext`).
- **Zustand:** Lightweight alternative — ek store banao, kisi bhi component se state read/update karo, Context ke boilerplate ke bina.

Dono Next.js mein use hote hain — reactive/client pieces ke liye. Server-side state (data) alag tarah manage hota (0.3 mein clear hoga).

## Common Mistakes (Revision-specific)

- ❌ Yahan React **dobara seekhne** mat aana — yeh sirf refresh hai.
- ❌ React Router ka `<Route>` import Next.js mein mat karna — routing built-in hai, file-based.
- ❌ `useEffect` har jagah mat lagana — Server Components mein data fetch ki zaroorat ho toh woh server pe hota hai (0.3).
- ❌ Zustand/Context ko server-side data ke liye mat use karna — woh client-side reactive state ke liye hai.

## Summary

- JSX, components, props, state, lists+keys, conditional render, `useEffect` — React ka core, Next.js mein wahi
- Router/forms/state-mgmt ka **concept** yaad hai — Next.js unko apne tareeke se (file-based routing, built-in actions) implement karta hai

**In Your Own Words**

1. `useState` ki zaroorat kyun hai — simple variable kyun kaafi nahi hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Simple variable se React ko pata nahi chalta ki value badal gayi — isliye UI update nahi hota. `useState` React ko batata hai value change hui, taaki woh component re-render kare aur UI update ho.

</details>

2. React Router ka `:id` dynamic route kya karta hai aur URL se value kaise nikalte the?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `path="/movies/:id"` mein `:id` ek variable segment hai jo har URL pe alag value leta hai (jaise `/movies/tt123` mein `tt123`). `useParams()` hook se yeh value nikalte the — `const { id } = useParams()`. Next.js mein iska counterpart dynamic route folder `[id]` hai.

</details>

3. Controlled input ka matlab kya hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Input ki value state se aati hai (`value={email}`) aur `onChange` se state update hoti hai. Matlab HTML input React ke control mein hai, user type karta hai → state badalti hai → value dobara render hoti hai.

</details>

4. Context API aur Zustand ek line mein kya karte hain?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Dono global/client state ko components ke beech share karte hain bina prop-drilling ke. Context built-in hai (bas boilerplate zyada), Zustand lightweight library hai (minimal boilerplate).

</details>
