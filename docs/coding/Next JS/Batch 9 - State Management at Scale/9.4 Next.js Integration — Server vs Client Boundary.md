## The Project — Dashboard Todo App

The app has three independently-rendered components that all read from the same store:

1. **TodoInput** — adds a new todo (dispatches `addTodo`)
2. **TodoList** — lists todos (reads `state.todos`, dispatches `toggleTodo`/`deleteTodo`)
3. **TodoStats** — shows count of completed/total (reads `state.todos`, derives the count)

None of these pass props to each other. The store is the single source of truth.

## Step 1 — Extend the Slice with Filters

We already created `todosSlice` in 9.1. Let's add a `filter` field to the slice:

```ts
// store/todosSlice.ts
import { createSlice, type PayloadAction } from '@reduxjs/toolkit';

export interface Todo {
  id: number;
  text: string;
  completed: boolean;
}

type Filter = 'all' | 'active' | 'completed';

interface TodosState {
  todos: Todo[];
  filter: Filter;
}

const initialState: TodosState = {
  todos: [],
  filter: 'all',
};

const todosSlice = createSlice({
  name: 'todos',
  initialState,
  reducers: {
    addTodo: (state, action: PayloadAction<Todo>) => {
      state.todos.push(action.payload);
    },
    toggleTodo: (state, action: PayloadAction<number>) => {
      const todo = state.todos.find(t => t.id === action.payload);
      if (todo) todo.completed = !todo.completed;
    },
    deleteTodo: (state, action: PayloadAction<number>) => {
      state.todos = state.todos.filter(t => t.id !== action.payload);
    },
    setFilter: (state, action: PayloadAction<Filter>) => {
      state.filter = action.payload;
    },
  },
});

export const { addTodo, toggleTodo, deleteTodo, setFilter } = todosSlice.actions;
export default todosSlice.reducer;
```

**Key changes:**

- **`Todostate`** — the state is now an object with `todos` AND `filter`.
- **`setFilter`** — updates which todos to display.
- `state.todos = state.todos.filter(...)` — replacing the array (Immer handles the immutability).

## Step 3 — TodoInput Component (Client)

```tsx
// components/todo-input.tsx
'use client';  // Uses hooks → must be Client Component

import { useState } from 'react';
import { useAppDispatch } from '@/store/hooks';
import { addTodo } from '@/store/todosSlice';

export function TodoInput() {
  const [text, setText] = useState('');
  const dispatch = useAppDispatch();

  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    if (text.trim()) {
      dispatch(addTodo({
        id: Date.now(),
        text: text.trim(),
        completed: false,
      }));
      setText('');
    }
  };

  return (
    <form onSubmit={handleSubmit} className="flex gap-2">
      <input
        type="text"
        value={text}
        onChange={(e) => setText(e.target.value)}
        placeholder="What needs to be done?"
        className="flex-1"
      />
      <button type="submit">Add</button>
    </form>
  );
}
```

**Line-by-line:**

- `useAppDispatch()` — typed dispatch hook (created in 9.1).
- `dispatch(addTodo({...}))` — fires the action, which `createSlice` auto-generated.
- `'use client'` — this component uses `useState` + `useAppDispatch` (hooks), so it must be a Client Component.

## Step 4 — TodoList Component (Client)

```tsx
// components/todo-list.tsx
'use client';

import { useAppDispatch, useAppSelector } from '@/store/hooks';
import { toggleTodo, deleteTodo, setFilter } from '@/store/todosSlice';

export function TodoList() {
  const dispatch = useAppDispatch();
  const { todos, filter } = useAppSelector((state) => ({
    todos: state.todos,
    filter: state.filter,
  }));

  const visibleTodos = todos.filter(t => {
    if (filter === 'active') return !t.completed;
    if (filter === 'completed') return t.completed;
    return true;
  });

  return (
    <div className="space-y-2">
      <div className="flex gap-2">
        <button onClick={() => dispatch(setFilter('all'))}>All</button>
        <button onClick={() => dispatch(setFilter('active'))}>Active</button>
        <button onClick={() => dispatch(setFilter('completed'))}>Completed</button>
      </div>

      <ul className="space-y-1">
        {visibleTodos.map(todo => (
          <li key={todo.id} className="flex items-center justify-between">
            <label>
              <input
                type="checkbox"
                checked={todo.completed}
                onChange={() => dispatch(toggleTodo(todo.id))}
              />
              <span style={{ textDecoration: todo.completed ? 'line-through' : 'none' }}>
                {todo.text}
              </span>
            </label>
            <button onClick={() => dispatch(deleteTodo(todo.id))}>×</button>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

> **Advanced note on the selector:** We used `useAppSelector(state => ({ todos: state.todos, filter: state.filter }))`. This returns a new object every render — but in practice, this is fine for small state because the shallow comparison still works (Redux Toolkit changes only the affected field). For production, you'd split into two `useAppSelector` calls or use `createSelector`. See 9.2 for the gotcha.

## Step 5 — TodoStats Component (Client)

```tsx
// components/todo-stats.tsx
'use client';

import { useAppSelector } from '@/store/hooks';

export function TodoStats() {
  const total = useAppSelector((state) => state.todos.length);
  const completed = useAppSelector((state) =>
    state.todos.filter(t => t.completed).length
  );

  return (
    <div className="text-sm text-gray-500">
      {completed}/{total} completed
    </div>
  );
}
```

This component reads TWO separate slices (`state.todos.length` and a filtered count). When `filter` changes, this component does **not** re-render (it doesn't read `filter`). When a todo is toggled, it re-renders — because `state.todos` gets a new reference.

import { TodoStats } from '@/components/todo-stats';

## Common Mistakes

- ❌ **Forgetting `'use client'`** on components that use hooks — Server Components can't use `useSelector`
- ❌ **Placing `<Provider>` in `page.tsx`** instead of `layout.tsx` — other routes won't have Redux
- ❌ **Storing `Date.now()` as ID** — collisions if two todos added in the same millisecond. Use a UUID library in production.
- ❌ **Returning objects from selectors unnecessarily** — see 9.2 for the performance gotcha

## What It Is NOT

- **It is not server-side state.** Redux is for client-side UI state. The todos here are not persisted — refresh clears them. For persistence, use a database (Batch 6).
- **It is not a replacement for Server Actions.** If todos need to be saved to a database, use Server Actions for the mutation and update Redux for instant UI feedback.
- **It is not required by default.** Next.js does not need Redux. Add it when Context/Zustand's re-render cascade becomes a problem.

|---|---|---|

## The `'use client'` Boundary — Which Components Need It

Not every component needs `'use client'`. Here is the rule:

```tsx
// ❌ This does NOT need 'use client' — it uses no hooks
// app/dashboard/todos/page.tsx (Server Component)
import { TodoInput } from '@/components/todo-input';
import { TodoList } from '@/components/todo-list';

export default function TodosPage() {
  return (
    <div>
      <TodoInput />     // ← this IS 'use client'
      <TodoList />      // ← this IS 'use client'
    </div>
  );
}

// ✅ This NEEDS 'use client' — it uses hooks
// components/todo-input.tsx
'use client';  // ← because useState + useAppDispatch are hooks

import { useState } from 'react';
import { useAppDispatch } from '@/store/hooks';
...
```

**The rule:** If a component uses `useState`, `useEffect`, `useSelector`, `useDispatch`, or any other React hook — it must have `'use client'`. If it only renders static JSX or imports other components — it can stay a Server Component.

> **Why does this matter?** Server Components render on the server (faster, smaller JS bundle). Client Components ship JavaScript to the browser. Only mark what truly needs interactivity as `'use client'`.

## Provider Placement — `layout.tsx`, Not `page.tsx`

The `<Provider>` should live in `layout.tsx` so **every page** has access to the store:

```tsx
// app/layout.tsx — root layout, applies to ALL routes
import { StoreProvider } from '@/store/store-provider';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <StoreProvider>{children}</StoreProvider>
      </body>
    </html>
  );
}
```

```tsx
// ❌ Wrong — only this route has Redux
// app/dashboard/page.tsx
import { StoreProvider } from '@/store/store-provider';

export default function DashboardPage() {
  return (
    <StoreProvider>   // ← too local — /blog, /about won't have Redux
      <TodoList />
    </StoreProvider>
  );
}
```

**Why `layout.tsx`:** The root layout renders for every route. A `<Provider>` here wraps the entire app. If you put it in `page.tsx`, only `/dashboard` gets Redux — visiting `/blog` would crash because `useAppSelector` is called outside the Provider.

## Nested Layouts — Scoped Providers

You can also create **section-scoped** providers. If only `/dashboard` needs Redux:

```tsx
// app/dashboard/layout.tsx — only /dashboard gets Redux
import { StoreProvider } from '@/store/store-provider';

export default function DashboardLayout({ children }: { children: React.ReactNode }) {
  return <StoreProvider>{children}</StoreProvider>;
}
```

Now `app/dashboard/page.tsx` inside this folder can use Redux hooks — but `app/blog/page.tsx` cannot (and doesn't need to). This is useful for large apps where Redux is only needed in certain sections.

## The SSR Story — Server Components + Hydration

In Next.js, Server Components render HTML on the server. When a Client Component uses Redux, here is what happens:

1. **Server render:** The Server Component (`page.tsx`) renders HTML. It does NOT use Redux hooks (it doesn't need to). It just composes `<TodoInput />` and `<TodoList />`.
2. **Client hydrate:** The browser downloads the JS for `TodoInput` and `TodoList`. They connect to the Redux store (via Provider in `layout.tsx`).
3. **Interaction:** Clicking "Add" dispatches `addTodo` → store updates → `TodoList` re-renders.

The store is a **singleton** — created once at module level:

```ts
// store/store.ts
import { configureStore } from '@reduxjs/toolkit';
import todosReducer from './todosSlice';

export const store = configureStore({
  reducer: { todos: todosReducer },
});
```

This file runs on both server and client. But the store instance is fresh on each server request (stateless). On the client, the store persists across navigations (client-side hydration keeps the same store instance).

> **Important:** Do not create the store inside a React component. If you do, every render creates a new store — losing all state. Always create it at module level.

## Preloaded State — SSR Optimization

For advanced SSR (rehydrating server state on the client), you can pass preloaded state:

```ts
// store/store.ts — accepts initial state
export const createStore = (preloadedState?: Partial<RootState>) => {
  return configureStore({
    reducer: { todos: todosReducer },
    preloadedState,
  });
};
```

Then in your layout:

```tsx
// app/layout.tsx
import { createStore } from '@/store/store';
// (in a real app, you'd get initial state from a database or API)
```

This is an advanced pattern — for most apps, the singleton store is sufficient. The key is understanding **where** the boundaries are.

## Nutshell

| Rule | Why |
|---|---|
| Client Components need `'use client'` | They use hooks (useState, useSelector, etc.) |
| Server Components stay as-is | They just compose client components — no hooks needed |
| `<Provider>` in `layout.tsx` | Covers all routes, not just one page |
| Store at module level | Singleton — same store across all client navigations |

## Common Mistakes

- ❌ **Forgetting `'use client'`** on hook-using components — build error: "React hooks must be in Client Component"
- ❌ **Putting Provider in `page.tsx`** — routes outside `/dashboard` won't have Redux
- ❌ **Creating store inside a component** — `const store = createStore()` in a component creates a new store every render
- ❌ **Using hooks in Server Components** — `useSelector` can't run on the server

## What It Is NOT

- **It is not complex SSR setup.** For basic Redux in Next.js, you just mark hook-using components as `'use client'` and put `<Provider>` in `layout.tsx`. No extra config needed.
- **It is not required for all state.** Redux is for shared client-side UI state. Server data (database, API) should use Server Actions + caching, not Redux.
- **It is not a replacement for Server Components.** Pages should be Server Components. Only the interactive pieces (hooks) need `'use client'`.
