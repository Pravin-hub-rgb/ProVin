## Sawaal 3: Data Ka Shape Kya Hai?

**Rule yaad karo (1.5.1/3.4.1 wala): data ka shape UI se decide hota hai, ulta nahi.** Socho page pe kya dikhega.

**Dashboard pe kya dikhega?** User ka naam, email, avatar (GitHub ki photo), aur bio. Naam/email/avatar kahan se? **Session se** — GitHub ne Auth.js ko diya, `auth()` se milta hai. Koi app-side store nahi chahiye — yahi OAuth ka fayda hai (4.4 wala point).

**Profile pe kya dikhega?** Wahi details + ek **edit form** jisme bio change ho sakta hai. Aur yahan ek nayi cheez chahiye — **bio kahan store hogi?**

GitHub ke paas bio hai, par woh session mein nahi aati (Auth.js sirf name/email/image fetch karta hai). Aur agar user apna bio **humari app mein** change kare — toh woh GitHub pe reflect nahi ho sakta (OAuth access woh allow nahi karta). Toh **bio app-side store** chahiye — wahi Batch 3 wala file pattern:

```ts
// app/lib/profiles.json
[
  { "email": "pravin@example.com", "bio": "Next.js seekh raha hoon" }
]
```

```ts
// Profile type — UI se justified
export type Profile = {
  email: string;   // kyun? User ki pehchaan — session se aata hai, file mein lookup isi se
  bio: string;     // kyun? Profile page ka edit form isi ko update karta hai
};
```

**Har field ka reason:**
- `email` — session ka unique identifier. Naam/avatar GitHub se fresh aate hain; bio file mein email ke hisaab se milti hai.
- `bio` — sirf yahi app-side data hai jo user khud edit karta hai. (Aur kuch nahi chahiye — naam/email/avatar session se, warna data duplication hota.)

## Sawaal 4: Data Flow Kaise Hoga?

```
IDENTITY (kaun hai)                    APP DATA (bio)
GitHub → Auth.js → auth() session      profiles.json → profiles.ts
          ↓                            ↓
   dashboard/profile pages          profile page ka edit form
   (naam, email, avatar)            updateProfileAction (Server Action)
                                        ↓
                                     writeFileSync + revalidatePath
```

**Identity vs App data — alag alag sources:**
- **Identity** — GitHub se session ke through. Kabhi apni file mein copy mat karo (name/email/avatar) — GitHub hi source of truth hai, `auth()` se fresh milta hai har request pe.
- **App data** — bio. Yehi wahi cheez hai jo user humari app mein edit karta hai — isi ka mutation Batch 3 ka Server Action pattern use karega.

**Flow, step by step (profile update):**
1. User profile page pe bio form submit karta hai
2. `updateProfileAction` (Server Action) — `auth()` se email nikaalta hai (user khud email form mein nahi daalega — session se)
3. Action `profiles.json` mein email ke hisaab se bio save karta hai (upsert — pehli baar insert, baad mein update)
4. `revalidatePath("/profile")` — page dobara render, nayi bio dikhegi
5. `useActionState` se pending state + error/success message
