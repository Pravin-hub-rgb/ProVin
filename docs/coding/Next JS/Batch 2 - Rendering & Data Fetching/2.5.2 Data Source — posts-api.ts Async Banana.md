## Cheez 2 — Data + Async Functions

Ab main cheez — functions **async** banenge:

```ts
// lib/posts-api.ts
const posts: Post[] = [
  {
    slug: "pehla-post",
    title: "Mera Pehla Blog Post",
    date: "7 Aug 2026",
    excerpt: "Next.js routing seekhne ka pehla din.",
    content: "Yeh mera pehla blog post hai. Maine file-based routing se yeh page banaya hai.",
  },
  {
    slug: "dynamic-routes",
    title: "Dynamic Routes — [slug] Folder",
    date: "8 Aug 2026",
    excerpt: "Ek page, anek URLs.",
    content: "Is post mein maine seekha ki [slug] folder se ek hi page multiple URLs handle karta hai.",
  },
  {
    slug: "server-fetch",
    title: "Server Components — Direct Fetch",
    date: "9 Aug 2026",
    excerpt: "Bina useEffect ke data fetching.",
    content: "Server Component mein direct await fetch() — koi loading spinner nahi, koi useEffect nahi.",
  },
];

export async function fetchAllPosts(): Promise<Post[]> {
  // Real app mein yahan fetch("https://api.example.com/posts") hota
  await new Promise((resolve) => setTimeout(resolve, 500)); // network delay jaisa
  return posts;
}

export async function fetchPostBySlug(slug: string): Promise<Post | undefined> {
  await new Promise((resolve) => setTimeout(resolve, 300));
  return posts.find((post) => post.slug === slug);
}
```

**Dekho kya badla — line by line:**

1. **`export async function fetchAllPosts()`** — `async` keyword. Matlab function hamesha `Promise` return karega. Return type `Promise<Post[]>`.

2. **`await new Promise((resolve) => setTimeout(resolve, 500))`** — ye artificial delay hai. `setTimeout` 500ms ke baad `resolve` karta hai. `await` isko wait karta hai. **Real app mein yahan `fetch("https://api.example.com/posts")` hota** jo network ke wajah se naturally delay karta hai. Ye line sirf usko simulate karti hai.

3. **`return posts`** — abhi data static array se aata hai. Real mein `return (await res.json()).posts`.

**Function names bhi badle:** `getAllPosts` → `fetchAllPosts`, `getPostBySlug` → `fetchPostBySlug`. Kyun? Kyunki ab functions **fetch jaisa** behave karte hain — naming should reflect behaviour. `fetch` prefix se pata chalta hai ki ye async network-ish operation hai.

## Kya Same Raha, Kya Badla — Compare Karo

| | 1.5 `lib/posts.ts` | v2 `lib/posts-api.ts` |
|---|---|---|
| Type `Post` | Same | Same |
| Data fields | Same 5 | Same 5 |
| Function name | `getAllPosts()` | `fetchAllPosts()` |
| Return | `Post[]` (turant) | `Promise<Post[]>` (delay ke saath) |
| Function name | `getPostBySlug(slug)` | `fetchPostBySlug(slug)` |
| Return | `Post \| undefined` (turant) | `Promise<Post \| undefined>` |
| `undefined` case | `find` se | `find` se — same |
| Delay | Nahi | `setTimeout` 500ms / 300ms |

**Core fark ek hai:** synchronous vs async. Data same, shape same, `find` logic same — bas ab function **wait** karta hai (jaise network) aur `Promise` return karta hai.

**`Promise<Post | undefined>` ka matlab:** function kuch der baad ya toh `Post` dega ya `undefined` (galat slug pe) — aur ye dono ka possibility TypeScript ko pata hai, isliye page pe `if (!post)` check enforce hoga (1.5.3 wala hi pattern).

## What It Is NOT

⚠️ **Ye "real API" nahi — fake hai.** `setTimeout` sirf delay simulate karta hai. Data abhi bhi static array se aata hai. Real app mein yahan `fetch("https://...")` + `res.json()` hota. Pattern wahi, source alag.

⚠️ **`async` = "faster" nahi.** Ulta — ab functions **slow** hain (delay ke saath). `async` ka matlab asynchronous hai — kuch der baad result, bina browser block kiye.

⚠️ **Nayi file = "duplication theek hai" nahi.** `Post` type do jagah hai — ye learning demo ke liye. Production mein shared file se import karte (DRY). Aage batches mein ise consolidate karenge.
