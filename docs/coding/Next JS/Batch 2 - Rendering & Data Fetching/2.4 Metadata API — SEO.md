In the last three files (2.1–2.3), we fetched data in Server Components, added Client Component interactivity, and chose caching strategies (Static, Dynamic, ISR). Now one more critical piece: when someone lands on your page from Google or shares it on social media, how does the title and description get populated?

## Broader Goal

Search engines and social platforms display a **title** and **description** under each search result or shared link. These come from the page's **metadata** — the `<title>` and `<meta>` tags in the HTML `<head>`.

React managed these manually and fragilely — often with `document.title` in `useEffect`, which Google could not reliably crawl. Next.js has a **Metadata API** that sets metadata at the server level — guaranteed in the HTML, SEO-friendly.

This file covers:

**A — Static Metadata.** Setting fixed titles/descriptions per page via `export const metadata`.

**B — Dynamic Metadata.** Using `generateMetadata` to set titles based on fetched data (e.g., a blog post's title).

**C — Metadata Templates.** A root-level template so every page title follows `"Page Title | Site Name"` — defined once, applied everywhere.

**D — Open Graph.** Social preview metadata for when links are shared.

## Manual Approach — React's `document.title`

In React, you set the page title imperatively:

```tsx
// React — manual metadata
import { useEffect } from 'react';

export default function BlogPost({ post }) {
  useEffect(() => {
    document.title = `${post.title} | My Blog`;
  }, [post.title]);

  return <h1>{post.title}</h1>;
}
```

Problems:
- **Client-side only** — the title is set after JavaScript loads. Googlebot (which often crawls without JS) sees a blank or default title.
- **Fragile** — easy to forget, easy to have the title and content out of sync.
- **No description** — React gave you `document.title`, but meta descriptions required DOM manipulation (`document.querySelector`), which is worse.

---

## Better Approach — Next.js Metadata API

### Static Metadata — `export const metadata`

For pages with a fixed title (About, Contact, Projects), export a `metadata` object:

```tsx
// app/about/page.tsx
import type { Metadata } from 'next';

export const metadata: Metadata = {
  title: 'About | My Portfolio',
  description: 'Learn about Pravin — full-stack developer specializing in Next.js.',
};

export default function About() {
  return <h1>About Me</h1>;
}
```

Next.js reads this at build time and injects `<title>` and `<meta name="description">` into the HTML `<head>` — before the page even loads in the browser.

### How to Verify

1. Visit the page in your browser.
2. Right-click → Inspect → find the `<head>` section.
3. You will see `<title>About | My Portfolio</title>` and `<meta name="description" content="...">`.
4. **Bonus:** Even with JavaScript disabled, the title is there — because it was set server-side.

## B — Dynamic Metadata (`generateMetadata`)

### The Challenge

Static metadata works for fixed pages. But what about a blog post? Each post has a different title — `/blog/hello-world` shows "Hello World", `/blog/nextjs-tips` shows "Next.js Tips".

You need **dynamic** metadata — based on data fetched at request time.

### `generateMetadata` — The Reserved Function

Next.js reserves the name `generateMetadata` for this purpose. You cannot rename it — it is a contract:

```tsx
// ❌ Wrong name — Next.js will not call it
export async function getPageMetadata() { ... }

// ✅ Correct — reserved name
export async function generateMetadata({ params }): Promise<Metadata> {
  // ...
}
```

### How It Works

1. User visits `/blog/hello-world`.
2. Next.js reads `params = { slug: "hello-world" }`.
3. Next.js calls `generateMetadata({ params })` **before** rendering the page.
4. Inside, you fetch the post, use its title as the metadata.
5. Next.js injects `<title>Hello World | My Blog</title>` into the HTML.
6. Then the page component renders.

```tsx
// app/blog/[slug]/page.tsx
import type { Metadata } from 'next';
import { notFound } from 'next/navigation';
import { fetchPostBySlug } from '@/lib/posts-api';

interface BlogPostProps {
  params: Promise<{ slug: string }>;
}

export async function generateMetadata({ params }: BlogPostProps): Promise<Metadata> {
  const { slug } = await params;
  const post = await fetchPostBySlug(slug);

  if (!post) {
    return { title: 'Post Not Found' };
  }

  return {
    title: post.title,
    description: post.excerpt,
  };
}

export default async function BlogPost({ params }: BlogPostProps) {
  const { slug } = await params;
  const post = await fetchPostBySlug(slug);

  if (!post) {
    notFound();
  }

  return (
    <main>
      <h1>{post.title}</h1>
      <p>{post.date}</p>
      <p>{post.content}</p>
    </main>
  );
}
```

### Key Points

- `generateMetadata` is called **with `params`** — the same props the page component receives.
- It must be `async` if you are fetching data inside it (which you typically are).
- It returns a `Metadata` object — same structure as the static `export const metadata`.
- It runs **before** the page component — metadata is in the HTML, then the content renders.

## C — Metadata Templates

### The Problem — Inconsistent Titles

Without a template, every page sets its own full title:

```
Home → "Home | My Portfolio"
About → "About | My Portfolio"
Projects → "Projects | My Portfolio"
```

You repeat `" | My Portfolio"` on every page. It is repetitive, and if you want to change the suffix, you edit every file.

### The Solution — Template

Define a **template** in the root layout. The `%s` placeholder gets replaced with the page's own title:

```tsx
// app/layout.tsx — root layout
import type { Metadata } from 'next';

export const metadata: Metadata = {
  title: {
    default: 'My Portfolio',              // fallback if page sets no title
    template: '%s | My Portfolio',         // %s = page's title
  },
  description: 'Pravin — full-stack developer building with Next.js.',
};

export default function RootLayout({ children }: { readonly children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
```

### How the Template Resolves

| Page Title Set | Template | Final Browser Title |
|---|---|---|
| `"About"` | `%s \| My Portfolio` | `About \| My Portfolio` |
| `"Projects"` | `%s \| My Portfolio` | `Projects \| My Portfolio` |
| `"Hello World"` | `%s \| My Portfolio` | `Hello World \| My Portfolio` |
| *(not set)* | — | `My Portfolio` (from `default`) |

```tsx
// app/about/page.tsx — only sets the page-specific part
export const metadata: Metadata = {
  title: 'About',  // template adds " | My Portfolio"
};
```

The final title in the browser becomes **"About | My Portfolio"** — without you writing the suffix every time.

### Why This Matters

- **Consistency** — every page title follows the same pattern.
- **DRY** — change the template in one place (root layout), every page updates.
- **Professional** — a consistent title pattern looks polished and improves recognition.

## D — Open Graph (Social Sharing)

When someone shares your link on LinkedIn, Twitter, or WhatsApp, a **preview card** appears — with a title, description, and sometimes an image. These come from Open Graph meta tags.

Next.js supports this in the same `metadata` object:

```tsx
// app/about/page.tsx
export const metadata: Metadata = {
  title: 'About',
  description: 'Learn about Pravin.',
  openGraph: {
    title: 'About — My Portfolio',
    description: 'Learn about Pravin, a full-stack developer.',
    images: ['https://myportfolio.com/og-image.png'],
  },
};
```

This generates:

```html
<meta property="og:title" content="About — My Portfolio" />
<meta property="og:description" content="Learn about Pravin..." />
<meta property="og:image" content="https://myportfolio.com/og-image.png" />
```

Social platforms read these `og:` tags and render the preview card — no need for you to manually add `<meta>` tags to the HTML.

### Twitter Cards

Add the `twitter` property for Twitter/X-specific previews:

```tsx
export const metadata: Metadata = {
  // ...
  twitter: {
    card: 'summary_large_image',
    title: 'About — My Portfolio',
    description: 'Learn about Pravin.',
    images: ['https://myportfolio.com/og-image.png'],
  },
};
```

## Common Mistakes

- **Using `document.title` client-side** — it gets overwritten by Next.js's server-side metadata. Use `metadata` or `generateMetadata` instead.
- **Calling `generateMetadata` something else** — it is a reserved name. Next.js will not discover it if you rename it.
- **Not typing the return as `Metadata`** — import `type { Metadata } from 'next'` and annotate the return type. It gives you autocomplete on all valid fields.
- **Setting `title` as a plain string in the root layout when using a template** — the template needs the `{ default, template }` object form, not `title: "string"`.
- **Fetching data twice** — `generateMetadata` and the page component might both call the same fetch function. Use `cache()` (later batches) to avoid duplicate requests.

## In Your Own Words

1. How does `export const metadata` differ from setting `document.title` in `useEffect`?

<details>
<summary>Sample Answer</summary>

**Answer:** `export const metadata` is processed at **build time / server time** — Next.js injects the `<title>` tag into the HTML before it reaches the browser. Googlebot sees the title even without running JavaScript. `document.title` runs in `useEffect`, which is client-side only — Googlebot may not execute the JS, so the title is missing. Metadata API is server-side; `document.title` is client-side. The first is SEO-friendly, the second is not.

</details>

2. Why is `generateMetadata` a reserved function name? What happens if you rename it?

<details>
<summary>Sample Answer</summary>

**Answer:** `generateMetadata` is reserved because Next.js looks for that exact name to call for dynamic metadata. If I rename it to `getPageMetadata`, Next.js does not know to call it — the metadata stays as whatever the page's static `metadata` says (or the default). It is the same pattern as `page.tsx` — the filename is the convention Next.js looks for.

</details>

3. What does `%s` mean in a metadata template, and how does the page title combine with it?

<details>
<summary>Sample Answer</summary>

**Answer:** `%s` is a placeholder in the template string. When a page sets `title: "About"` and the root layout has `template: "%s | My Portfolio"`, Next.js replaces `%s` with "About", producing the final title "About | My Portfolio". The `default` property is used when a page does not set its own title.

</details>

4. How does Open Graph metadata affect social sharing, and is it required for SEO?

<details>
<summary>Sample Answer</summary>

**Answer:** Open Graph metadata (`og:title`, `og:description`, `og:image`) controls how links appear when shared on social platforms (LinkedIn, WhatsApp, Twitter). Without it, shared links show a bare URL with no preview. For pure SEO (Google search), `title` and `description` in the `metadata` object are sufficient — Google reads those directly. Open Graph is for **social sharing**, not search engine ranking.

</details>
