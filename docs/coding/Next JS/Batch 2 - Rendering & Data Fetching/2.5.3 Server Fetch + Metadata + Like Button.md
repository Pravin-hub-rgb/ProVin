## Step 1 — Like Button: `components/like-button.tsx`

Pehle interactive widget banate hain — **Like button** (plan se yaad, Upgrade 2). Ye Client Component hai (`useState` use karta hai — 2.2 se yaad). Alag file mein isliye kyunki poore page ko client nahi banana (2.2 ka hybrid model):

```tsx
// components/like-button.tsx
"use client";

import { useState } from "react";

export default function LikeButton() {
  const [likes, setLikes] = useState(0);

  return (
    <button
      onClick={() => setLikes(likes + 1)}
      style={{ marginTop: "1rem", cursor: "pointer" }}
    >
      ❤️ {likes} {likes === 1 ? "Like" : "Likes"}
    </button>
  );
}
```

**Logic:**
- `"use client"` — file ki pehli line, is component ko client pe render hone ke liye (2.2)
- `useState(0)` — likes ka count, shuru 0 se
- `onClick={() => setLikes(likes + 1)}` — click pe count +1
- `{likes === 1 ? "Like" : "Likes"}` — singular/plural — 1 Like, 2 Likes

**Ye state sirf is component mein hai** — click karne se poora page re-render nahi hota, sirf button ka count update hota hai. Isse page ka data (server se aaya) untouched rehta hai.

## Step 4 — Blog List: `app/blog/page.tsx`

Ab asli upgrade — `fetchAllPosts()` use karte hain (`await` + async Server Component — 2.1 se yaad):

```tsx
// app/blog/page.tsx
import type { Metadata } from "next";
import Link from "next/link";
import { fetchAllPosts } from "@/lib/posts-api";

export const metadata: Metadata = {
  title: "Blog",
  description: "Pravin ke blog posts — Next.js, React, development.",
};

export default async function BlogPage() {
  const posts = await fetchAllPosts();

  return (
    <main>
      <h1>Blog</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.slug}>
            <Link href={`/blog/${post.slug}`}>{post.title}</Link>
            <p>{post.excerpt}</p>
          </li>
        ))}
      </ul>
    </main>
  );
}
```

**Kya badla (1.5.4 se):**
1. `import { fetchAllPosts } from "@/lib/posts-api"` — nayi file se
2. `export default async function BlogPage()` — **`async`** function (Server Component — 2.1)
3. `const posts = await fetchAllPosts()` — **`await`** (2.5.2 se yaad — function Promise return karta hai)

**Render logic bilkul same** — `posts.map`, key, title, excerpt. UI ka code nahi badla, sirf data source + await. **Yehi 1.5.3 ki abstraction ka fayda hai.**

## Step 5 — Single Post: `app/blog/[slug]/page.tsx`

Sabse interesting file — yahan **4 concepts** milte hain: `generateMetadata` (2.4), `await fetchPostBySlug` (2.1), `notFound()` (1.4), aur `LikeButton` (2.2):

```tsx
// app/blog/[slug]/page.tsx
import type { Metadata } from "next";
import { notFound } from "next/navigation";
import { fetchPostBySlug } from "@/lib/posts-api";
import LikeButton from "@/components/like-button";

interface BlogPostProps {
  params: Promise<{ slug: string }>;
}

export async function generateMetadata({ params }: BlogPostProps): Promise<Metadata> {
  const { slug } = await params;
  const post = await fetchPostBySlug(slug);

  if (!post) {
    return { title: "Post Not Found" };
  }

  return {
    title: post.title,
    description: post.excerpt,
  };
}

export default async function BlogPost({ params }: BlogPostProps) {
  const { slug } = await params;
  const post = await fetchPostBySlug(slug);

  if (!post) {
    notFound();
  }

  return (
    <main>
      <h1>{post.title}</h1>
      <p>{post.date}</p>
      <p>{post.content}</p>
      <LikeButton />
    </main>
  );
}
```

**Har hissa samjho:**

**`generateMetadata`** — (2.4 se yaad) Next.js ise page se pehle chalata hai. `params` se slug (1.3 wala pattern — Next.js call karta hai), `fetchPostBySlug` se post, phir title/description return. Galat slug pe "Post Not Found" title.

**`export default async function BlogPost`** — page bhi async (Server Component). `await fetchPostBySlug(slug)` — same call jo metadata ne kiya.

**`if (!post) notFound()`** — (1.4 se yaad) `fetchPostBySlug` `Post | undefined` return karta hai (2.5.2 se yaad). `undefined` pe 404.

**`<LikeButton />`** — Server Component page ke andar Client Component import (2.2 se yaad — allowed hai). Page ka data server pe, button ki interactivity client pe.

> **Ek cheez notice karo:** `generateMetadata` aur page **dono** `fetchPostBySlug` call karte hain — data do baar fetch hota hai. Real app mein ise optimize karte hain (`cache()` — aage batches mein). Abhi learning ke liye simple rakha hai.

## Ab Kya Bana — Poore Flow Ka Picture

```
User /blog/server-fetch kholta hai
    ↓
Next.js generateMetadata call karta hai (params se slug)
    ↓  fetchPostBySlug → post → title/description metadata
Next.js page call karta hai
    ↓  fetchPostBySlug → post → notFound check → render
    ↓  <LikeButton /> → client pe interactivity
Browser: title "Server Components — Direct Fetch | Pravin" + post + like button
```

**Server vs client split clear:** fetch + render + metadata sab server pe. Like button ka click/state client pe. Hybrid model — 2.2 se yaad.

Metadata static (`export const metadata`) static pages pe, dynamic (`generateMetadata`) blog post pe. Ek file mein 4 concepts combine hue — generateMetadata, async fetch, notFound, client component.

## What It Is NOT

⚠️ **Like button = "persisted data" nahi.** `useState` se count sirf session mein hai — refresh pe 0. Ye DB/localStorage mein save nahi hota (persistence aage batches mein — mutations, database).

⚠️ **`generateMetadata` = "page render se alag request" nahi.** Dono same async source se data lete hain, bas alag-alag time pe chalta hai. Kaam optimize karna hai toh shared function/cache — aage seekhoge.

⚠️ **Ye "production-complete" nahi.** Metadata basic hai (Open Graph, canonical aage). Fetch unoptimized hai (dobaara call). Ye learning milestone hai, production polish aage batches.
