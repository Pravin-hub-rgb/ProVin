2.5.3 mein pages update kar diye — async data, Like button, metadata sab lag gaya. Ab project ke aakhri kaam: **states, rendering strategy (ISR), aur final test.**

**Ek important cheez notice karo:** 1.5 mein blog data synchronous tha (static array, instant) — isliye loading state kabhi dikhti hi nahi thi, aur error hona possible hi nahi tha. ## Step 1 — Loading State: `app/blog/[slug]/loading.tsx`

1.5.5 mein ye file banayi thi — wahi chalti hai, par ab **actually dikhegi** kyunki `fetchPostBySlug` 300ms delay karta hai:

```tsx
// app/blog/[slug]/loading.tsx
export default function Loading() {
  return <p>Post load ho raha hai...</p>;
}
```

**Ye ab kyun dikhega?** 1.5 mein `getPostBySlug` synchronous tha — turant data milta tha, page suspend hi nahi hota tha. Ab `fetchPostBySlug` async hai — 300ms wait hota hai, page suspend hota hai, aur Next.js us time pe `loading.tsx` dikhata hai (1.4 se yaad — automatic Suspense boundary).

`/blog/server-fetch` kholo — **pehle "Post load ho raha hai...", phir post.** Ab loading ka asli fayda dikha.

## Step 2 — Error State: `app/blog/[slug]/error.tsx`

Data async hone se error **actually ho sakta hai** — agar `fetchPostBySlug` fail ho (real app mein network down, API fail). Error state handle karta hai — 1.5.5 wali file wahi:

```tsx
// app/blog/[slug]/error.tsx
"use client";

export default function Error({
  error,
  reset,
}: {
  error: Error;
  reset: () => void;
}) {
  return (
    <div>
      <h2>Kuch galat ho gaya!</h2>
      <p>{error.message}</p>
      <button onClick={reset}>Dobara Try Karo</button>
    </div>
  );
}
```

**Test karne ke liye** — 2.5.2 ke `fetchPostBySlug` mein temporarily error throw karo:

```ts
// lib/posts-api.ts — test ke liye (baad mein hatao!)
export async function fetchPostBySlug(slug: string): Promise<Post | undefined> {
  throw new Error("API down — test error");
}
```

Ab `/blog/pehla-post` kholo — error page dikhega, "Dobara Try Karo" pe click karo → page dobara try karega. **Test ke baad throw hatao!**

## Step 4 — Rendering Strategy: ISR (`revalidate`)

Ab aata hai 4th upgrade (2.5.1 se yaad) — **ISR.** Blog data kam badalta hai — static serve + background refresh perfect (2.3 se yaad).

Abhi fake API mein asli `fetch()` nahi hai — `setTimeout` + array return. Isliye `revalidate` option **directly fetch pe** nahi lag sakta. Par real app mein asli `fetch()` pe aisa lagaoge:

```ts
// Real app mein — asli fetch pe ISR
export async function fetchAllPosts(): Promise<Post[]> {
  const res = await fetch("https://api.example.com/posts", {
    next: { revalidate: 300 },   // 5 minute mein background refresh
  });
  return (await res.json()).posts;
}
```

**`next: { revalidate: 300 }`** (2.3 se yaad) — page static serve hota hai, 300 second ke baad background mein fresh render. Fast + fresh.

**Abhi fake API ke saath ISR test karna** — page render time dikha ke:

```tsx
// app/blog/page.tsx — ISR check ke liye
export default async function BlogPage() {
  const posts = await fetchAllPosts();

  return (
    <main>
      <h1>Blog</h1>
      <p>Page render time: {new Date().toLocaleTimeString()}</p>
      {/* posts render */}
    </main>
  );
}
```

Reload karo — time same rahega (static render) ya badlega (dynamic) — isse pata chalta hai page ki nature. (2.3 ka practical test — dev mode mein thoda aggressive behave karta hai, production mein exact interval.)

**Iska matlab kya hua?** Aage jab real API/DB aayegi (Batch 5), `revalidate` lagana aata hoga — abhi pattern clear hai.

## Common Mistakes

- ❌ `await` bhoolna — `fetchAllPosts()` `Promise` return karta hai, `const posts = await fetchAllPosts()` hi sahi. `await` bhool gaye toh "Promise pending" render hoga.
- ❌ Blog page ko `async function` nahi banana — `await` use karne ke liye function `async` hona zaroori hai.
- ❌ Like button mein `"use client"` bhoolna — `useState` Server Component mein allowed nahi, build error.
- ❌ `generateMetadata` aur page mein alag-alag data fetch se redundancy — aage `cache()`/shared function se optimize karenge. Abhi simple rakhna thik.
- ❌ Test throw/delay production mein chhodna — testing ke liye the, hata do.
- ❌ `metadata.title` plain string likhna jab template use kar rahe ho — `{ default, template }` object use karo.

## What It Is NOT

⚠️ **V2 = "production app" nahi.** Fake API, unoptimized double-fetch, like button bina persistence — sab learning milestone. Real production concerns aage batches (DB, auth, security, deploy).

⚠️ **`revalidate` abhi lagaa nahi gaya** — fake API mein direct nahi lagta. Concept ready hai (2.3 + is file ka pattern), implementation real fetch ke saath aayegi.

⚠️ **"Actually dikhta hai" = "hamesha dikhta hai" nahi.** Loading 300ms ke liye dikhta hai — data aate hi hat jaata hai. Ye UX ka hissa hai — user ko wait ka pata chalta hai, blank screen nahi.

⚠️ **States sirf blog mein — baaki nahi.** Home/About/Projects/Contact static hain — loading/error ki zaroorat nahi. Har jagah states daalna over-engineering hai (1.5.5 se yaad).
