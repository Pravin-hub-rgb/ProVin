## Step 1 — Data Source: `lib/posts-api.ts`

Pehle data source banate hain. Asli app mein ye ek **API call** hota (`fetch("https://myapi.com/posts")`). Hum ek chhoti fake API banayenge jo promise return kare — taaki fetch ka flow same rahe, par koi server setup na chahiye:

```ts
// lib/posts-api.ts
export type Post = {
  slug: string;
  title: string;
  date: string;
  excerpt: string;
  content: string;
};

const posts: Post[] = [
  {
    slug: "pehla-post",
    title: "Mera Pehla Blog Post",
    date: "7 Aug 2026",
    excerpt: "Next.js routing seekhne ka pehla din.",
    content: "Yeh mera pehla blog post hai. Maine file-based routing se yeh page banaya hai.",
  },
  {
    slug: "dynamic-routes",
    title: "Dynamic Routes — [slug] Folder",
    date: "8 Aug 2026",
    excerpt: "Ek page, anek URLs.",
    content: "Is post mein maine seekha ki [slug] folder se ek hi page multiple URLs handle karta hai.",
  },
  {
    slug: "server-fetch",
    title: "Server Components — Direct Fetch",
    date: "9 Aug 2026",
    excerpt: "Bina useEffect ke data fetching.",
    content: "Server Component mein direct await fetch() — koi loading spinner nahi, koi useEffect nahi.",
  },
];

export async function fetchAllPosts(): Promise<Post[]> {
  // Fake API — real app mein yahan fetch("https://api.example.com/posts") hota
  await new Promise((resolve) => setTimeout(resolve, 500)); // network delay jaisa
  return posts;
}

export async function fetchPostBySlug(slug: string): Promise<Post | undefined> {
  await new Promise((resolve) => setTimeout(resolve, 300));
  return posts.find((post) => post.slug === slug);
}
```

**Dekho kya badla:** functions ab `async` hain aur `Promise` return karte hain — bilkul real API jaisa. `setTimeout` se network delay simulate kiya (asli API mein ye naturally hota hai). Page inhe `await` karke call karega — real `fetch()` ki tarah.

## Step 6 — Blog List: `app/blog/page.tsx`

Ab asli upgrade — `lib/posts.ts` (synchronous array) ki jagah `fetchAllPosts()` (async API) use karenge. Page Server Component hai, isliye directly `await`:

```tsx
// app/blog/page.tsx
import type { Metadata } from "next";
import Link from "next/link";
import { fetchAllPosts } from "@/lib/posts-api";

export const metadata: Metadata = {
  title: "Blog",
  description: "Pravin ke blog posts — Next.js, React, development.",
};

export default async function BlogPage() {
  const posts = await fetchAllPosts();

  return (
    <main>
      <h1>Blog</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.slug}>
            <Link href={`/blog/${post.slug}`}>{post.title}</Link>
            <p>{post.excerpt}</p>
          </li>
        ))}
      </ul>
    </main>
  );
}
```

**Notice:** `export default async function` + `await fetchAllPosts()` — 2.1 ka pattern. Data page render hone se pehle server pe aaya, HTML ke saath. Koi `useEffect`, koi loading state nahi.

## Step 7 — Single Post: `app/blog/[slug]/page.tsx`

Ab sabse interesting — `generateMetadata` (2.4) + data fetch (2.1) + `notFound()` (1.4) + `revalidate` (2.3), sab ek jagah:

```tsx
// app/blog/[slug]/page.tsx
import type { Metadata } from "next";
import { notFound } from "next/navigation";
import { fetchPostBySlug } from "@/lib/posts-api";
import LikeButton from "@/components/like-button";

interface BlogPostProps {
  params: Promise<{ slug: string }>;
}

export async function generateMetadata({ params }: BlogPostProps): Promise<Metadata> {
  const { slug } = await params;
  const post = await fetchPostBySlug(slug);

  if (!post) {
    return { title: "Post Not Found" };
  }

  return {
    title: post.title,
    description: post.excerpt,
  };
}

export default async function BlogPost({ params }: BlogPostProps) {
  const { slug } = await params;
  const post = await fetchPostBySlug(slug);

  if (!post) {
    notFound();
  }

  return (
    <main>
      <h1>{post.title}</h1>
      <p>{post.date}</p>
      <p>{post.content}</p>
      <LikeButton />
    </main>
  );
}
```

**Sab concepts ek jagah:**
1. `generateMetadata` — `params` se slug, post fetch, title/description return (2.4)
2. `notFound()` — post nahi mila toh 404 (1.4)
3. `LikeButton` — Client Component, interactive (2.2)
4. `await params` — Promise (1.3)

`/blog/server-fetch` kholo → tab title "Server Components — Direct Fetch | Pravin" dikhega. Aur post ke neeche Like button — click karo, count badhega.

## Step 9 — ISR: Rendering Strategy

Blog pages data kam badalte hain — ISR perfect hai (2.3 se). `fetchAllPosts()` wali fake API mein revalidate directly nahi lag sakta (wo function hai, fetch nahi), par real app mein asli `fetch()` pe lagate:

```ts
// Real app mein — asli fetch pe revalidate
const res = await fetch("https://api.example.com/posts", {
  next: { revalidate: 300 },
});
```

Fake API ke saath test karne ke liye page render time check kar sakte ho (2.3 wala trick) — blog list page mein `new Date().toLocaleTimeString()` dikhao aur reload karke dekho ki static render hua ya dynamic.

## Common Mistakes

- ❌ `fetchAllPosts()` ko `await` bhoolna — function Promise return karta hai, `await` lagao. Bhool gaye toh "Promise pending" render hoga.
- ❌ Blog list mein bhi loading state banana — Server Component mein koi loading spinner nahi (2.1). `loading.tsx` sirf async page ke suspend hone pe dikhta hai — single post page pe, list page pe nahi (kyunki list wahi await karta hai).
- ❌ `generateMetadata` aur page mein post data alag-alag fetch karna — fake API mein dono `fetchPostBySlug` call karte hain. Real app mein isse optimize karne ke liye shared function/cache use karte hain (aage batches mein).
- ❌ Like button ko server component banake bhoolna — `useState` hai, isliye `"use client"` zaroori (2.2). Bina directive ke build error aayega.
- ❌ Metadata `title` ko template ke saath string likhna — root layout mein `{ default, template }` object hi sahi hai.

## What It Is NOT

⚠️ **Yeh sirf "files upgrade" nahi — data architecture change hai.** Asli cheez ye hai: data ab sync array se async API source mein gaya. Aage real DB/API aayegi, pattern wahi rahega — `await fetch()`.

⚠️ **Fake API (`setTimeout`) production nahi hai.** Ye sirf training ke liye hai taaki fetch flow samjho. Real app mein actual `fetch("https://api...")` use hoga. Pattern same — source alag.

⚠️ **Like button localStorage/DB mein save nahi karta.** Ye sirf useState se count karta hai — refresh pe reset. Persistence aage batches mein (DB, server actions) aayegi. Abhi focus interactivity ka concept hai.

⚠️ **SEO complete nahi hua.** Basic metadata hai — Open Graph, sitemap, canonical aage batches mein aayenge. Foundation rakha hai, poori production SEO baad mein.
