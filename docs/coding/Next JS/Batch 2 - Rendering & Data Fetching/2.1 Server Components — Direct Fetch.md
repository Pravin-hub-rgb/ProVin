Kisi bhi e-commerce app mein ek product listing page dekha hoga — saare products ki grid. React course mein aisa page banate waqt kya karte the? `useEffect` ke andar `fetch()`, phir `loading` state, phir `data` state, phir error handling. Ek simple page ke liye kitna boilerplate. Ab socho — Next.js mein ye same page bina kisi `useEffect`, bina loading spinner ke bana sakte hain? Haan. **Server Components ka asli power yahi hai.**

Batch 1 mein `page.tsx` ko humne `async function` banaya tha (`BlogPost` — params await karte the). Wo asli reason tha: **async Server Component ke andar tum seedha `await fetch()` likh sakte ho.** Chalo yehi seekhte hain.

---

## Manual Approach — React Mein Data Fetching

React course mein data fetch karne ka tareeka yaad hai? `useEffect` + `fetch` + states:

```tsx
// React mein — data fetching ka manual tareeka
import { useState, useEffect } from 'react';

export default function Products() {
  const [products, setProducts] = useState([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch('/api/products')
      .then((res) => res.json())
      .then((data) => {
        setProducts(data);
        setLoading(false);
      })
      .catch((err) => {
        setError(err);
        setLoading(false);
      });
  }, []);  // empty dependency array — mount pe ek baar

  if (loading) return <p>Loading...</p>;
  if (error) return <p>Error: {error.message}</p>;

  return (
    <ul>
      {products.map((p) => (
        <li key={p.id}>{p.name}</li>
      ))}
    </ul>
  );
}
```

Dekho kitna boilerplate hai — tin states (`products`, `loading`, `error`), ek `useEffect`, `fetch` chain, loading/error checks. **Ye sab kyun?** Kyunki React ka component **client pe chalta hai** aur data browser se fetch karta hai. Client pe data turant nahi milta — wait karna padta hai, isliye states.

## Better Approach — Server Component Mein Direct `await fetch()`

Ab Next.js wala tareeka. 0.3 se yaad — **Server Components server pe render hote hain.** Server pe fetch karo, data mila, poora page server pe hi bana ke bhejo. Browser ke paas data **already ready** hota hai. Isliye:

- Koi `useEffect` nahi — data server pe fetch hua
- Koi `loading` state nahi — page load tak data ready hai
- Koi `error` state nahi — error aaya toh `throw` (1.4 ka `error.tsx` handle karega)

```tsx
// app/products/page.tsx — Next.js Server Component
export default async function ProductsPage() {
  const res = await fetch("https://dummyjson.com/products");
  const data = await res.json();

  return (
    <ul>
      {data.products.map((p: any) => (
        <li key={p.id}>{p.title}</li>
      ))}
    </ul>
  );
}
```

**Notice kya kya nahi hai:** koi `useState`, koi `useEffect`, koi `"use client"`, koi loading check. Function `async` hai, andar direct `await fetch()`. Bas. Yehi Server Component ka data fetching hai.

> **Roadmap note (0.5 se yaad):** `fetch()` by default Next.js **cache** karta hai — same request dobara server pe nahi jati. Ye 2.3 mein static rendering se judega.

---

## Typed Response — TypeScript Interface

Abhi code mein `p: any` tha — TypeScript ka anti-pattern. API ka response typed hona chahiye. Ek `interface` define karo jo response ki shape batae:

```tsx
// app/products/page.tsx
interface Product {
  id: number;
  title: string;
  price: number;
}

interface ProductsResponse {
  products: Product[];
}

export default async function ProductsPage() {
  const res = await fetch("https://dummyjson.com/products");
  const data: ProductsResponse = await res.json();  // typed!

  return (
    <ul>
      {data.products.map((product) => (
        <li key={product.id}>
          {product.title} — ${product.price}
        </li>
      ))}
    </ul>
  );
}
```

Ab `data.products` ko TypeScript samajhta hai — `product.title` string hai, `product.price` number hai. Galat property access kiya toh compile-time error milta hai, runtime nahi. Ye React course ka TypeScript pattern hai, yahan directly use ho raha hai.

## Minimal Example — Product Listing Page

Chal ek real mini-project banate hain. **DummyJSON API** use karenge (`https://dummyjson.com/products`) — free hai, koi API key nahi chahiye, bilkul dummy API jaisa hai. `create-next-app` ka project kholo, aur `app/products/page.tsx` mein ye code daalo:

```tsx
// app/products/page.tsx
interface Product {
  id: number;
  title: string;
  description: string;
  price: number;
  category: string;
}

interface ProductsResponse {
  products: Product[];
}

export default async function ProductsPage() {
  const res = await fetch("https://dummyjson.com/products");
  const data: ProductsResponse = await res.json();

  return (
    <main>
      <h1>Products</h1>
      <ul>
        {data.products.map((product) => (
          <li key={product.id}>
            <h2>{product.title}</h2>
            <p>{product.description}</p>
            <p>${product.price} — {product.category}</p>
          </li>
        ))}
      </ul>
    </main>
  );
}
```

`npm run dev` karo aur `/products` kholo. Pehle se hi saare products dikhenge — koi loading spinner nahi. **Page load hota hai, data ke saath.** Kyunki data server pe fetch hua aur HTML ke saath aa gaya.

## Error Kahan Handle Hoga?

React mein `if (error) return <p>Error...</p>` likhte the. Ab? Agar `fetch` fail hota hai (API down), toh function mein error **throw** hota hai — aur 1.4 se yaad hai, `error.tsx` usko catch karta hai. Toh tumhe page mein error handling nahi likhni — `app/products/error.tsx` daal do (1.4 mein banaya tha, wahi pattern):

```tsx
// app/products/error.tsx
"use client";

export default function Error({ error, reset }: { error: Error; reset: () => void }) {
  return (
    <div>
      <h2>Products load nahi ho paye!</h2>
      <p>{error.message}</p>
      <button onClick={reset}>Dobara Try Karo</button>
    </div>
  );
}
```

Separation of concerns — **page data fetch karta hai, error file error dikhati hai.** Har file apna kaam.

## Nutshell

Server Components mein data fetching React se bilkul alag hai: `async` function + `await fetch()` + typed response. Koi `useEffect`, koi loading/error state nahi. Server pe data mila, HTML banaya, browser ko ready bheja. Error agar aaye, `error.tsx` handle karta hai.

---

## Common Mistakes

- ❌ `useEffect` se fetch karna Server Component mein — galat. Server Component pe React hooks chalti hi nahi. Direct `await fetch()` likho.
- ❌ Response typed nahi karna (`any`) — `interface` banao, TypeScript ka fayda uthao.
- ❌ `"use client"` lagana — Server Component hai toh lagao mat, direct `await fetch()` chalega.
- ❌ Har request pe fresh data expect karna — `fetch()` by default cache hota hai (0.5 se yaad). 2.3 mein iska control seekhoge.
- ❌ `res.json()` se pehle `res.ok` check na karna — production mein check karna chahiye (`if (!res.ok) throw new Error(...)`).

## What It Is NOT

⚠️ **Server Component fetch = browser se fetch nahi.** Ye fetch server pe hota hai — browser pe visible nahi, terminal/logs mein server pe chalta hai. Client pe data fetch karna chahte ho toh wo alag case hai (2.2 mein dekhenge).

⚠️ **"Koi loading nahi" ka matlab data ko wait nahi karna nahi.** Server pe fetch ka time lagta hai (network). Fark ye hai ki wo wait **server pe** hota hai, browser pe nahi — user ko koi blank/loading nahi dikhta.

⚠️ **Ye sirf `page.tsx` ke liye nahi.** Koi bhi Server Component (`component.tsx`, `layout.tsx`) mein `await fetch()` likh sakte ho.
