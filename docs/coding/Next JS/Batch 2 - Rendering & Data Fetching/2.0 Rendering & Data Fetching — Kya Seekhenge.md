Batch 1 mein tumne routing seekhi — file-based routing, layouts, dynamic routes, loading/error/404 states. Aur combined project mein data `lib/posts.ts` jaisi static file se aaya. Par ab ek asli problem hai jo abhi tak avoid ki: **data kahan se aata hai?**

Real app mein data static file se nahi aata — **API se aata hai.** Database se, doosre server se, CMS se. Aur wo data fetch karna hota hai. React course mein tumne `useEffect` + `fetch()` se data laate the. Ab sawaal ye hai — Next.js mein data fetching kaise hoti hai?

Yeh Batch 2 ka focus hai: **Rendering & Data Fetching.** Aur yahan ek baat pakki — React mein jo karte the, usse kaafi alag (aur better) hai.

## Kya Seekhenge Is Batch Mein

Char concepts hain, har ek ka apna mini-project:

**E — Server Components mein Direct `await fetch()`.** React mein data `useEffect` + loading state se aata tha. Ab? Server Component ke andar seedha `await fetch()` likho — koi `useEffect` nahi, koi loading spinner nahi, page load tak data ready hai. Mini-project: **Product Listing Page** — server pe hi data fetch.

**F — Client Components — Kab Zaroorat Padti Hai.** Ab har component server pe render hota hai (0.3 se yaad). Par `useState`, `onClick`, browser APIs — ye sab client chahiye. `use client` directive se component ko client pe bhejo. Kab lagana hai, kab nahi — yahi tricky part hai. Mini-project: Product listing mein "Add to Favorites" button.

**G — Static vs Dynamic Rendering + `revalidate`.** 0.2/0.6 mein SSR, SSG, ISR ka theory samjha tha. Ab practically karenge — page ko static banao, phir `revalidate` interval set karo, dekho ISR kaise kaam karta hai. Mini-project: Product listing ko static + revalidate.

**H — Metadata API — SEO.** Jab tum Google pe "mern stack developer" search karte ho, toh result mein title aur description dikhte hain. Wo metadata hai. Ab? `generateMetadata` function se dynamic SEO — har page ka apna title/description. Mini-project: Blog + product dono mein proper meta tags.

## Manual → Better Pattern

React mein data fetching ka manual tareeka tha — `useEffect` + `fetch` + loading state + error state. Next.js ka better tareeka hai — Server Components mein direct `await fetch()`. Pehle manual wala dekhenge (taaki dard mehsoos ho), phir Next.js wala. Isi tarah tumhe "why" bhi samajh aayega, sirf "how" nahi.

Chalo shuru karte hain — pehla concept: **Server Components mein Direct Fetch.**
