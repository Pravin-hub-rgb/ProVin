## Broader Goal

In the real world, data does not come from a hardcoded array — it comes from an **API** (server-to-server, database, CMS). This introduces new challenges:

1. **How do you fetch data in Next.js?** (Not `useEffect` — Server Components can `await fetch()` directly.)
2. **When do you need Client vs Server Components?** (State, events, browser APIs demand Client.)
3. **How often do you fetch?** (Static at build, dynamic on every request, or somewhere in between with ISR.)
4. **How does Google find your pages?** (Metadata — titles, descriptions, Open Graph.)

This batch covers all four — each as a mini-project on the Blog site you already built.

## The Four Concepts

### E — Server Components: Direct `await fetch()`

React needed `useEffect` + loading state + error state just to fetch data. Next.js Server Components can `await fetch()` directly inside the component — no hooks, no loading spinner, no error handling. Data is ready by the time HTML reaches the browser.

**Mini-project:** Product Listing Page — fetch from DummyJSON right inside the Server Component.

### F — Client Components: When Interactivity Is Needed

Server Components render on the server. But `useState`, `onClick`, `localStorage` — those are browser-only. That is what `"use client"` is for: it tells Next.js "this component needs to run in the browser."

**Mini-project:** Add a "Like this post" button to the blog — `useState` + click handler.

### G — Static vs Dynamic Rendering + `revalidate`

Should the page re-fetch on every request, or can it be cached? Server-side caching (Next.js on the server, not browser cache) with `revalidate` for ISR — the best of both worlds: static speed with background refresh.

**Mini-project:** Product page with render time display — see static caching in action.

### H — Metadata API: SEO

When someone searches for your page on Google, what shows up? A title, a description, maybe an image. That is **metadata** — and React managed it with fragile `document.title` in `useEffect`. Next.js has a proper Metadata API that sets it server-side.

**Mini-project:** Dynamic metadata for blog posts — each post's title becomes the page title.
