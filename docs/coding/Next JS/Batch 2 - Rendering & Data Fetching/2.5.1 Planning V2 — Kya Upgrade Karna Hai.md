1.5 mein tumne Portfolio/Blog Site banaya — aur us process mein asli coding mindset seekha: **planning se shuru, hardcoded UI, phir data layer, phir dynamic, phir states.** Ab Batch 2 ke concepts (2.1–2.4) ready hain — server fetch, client components, rendering + revalidate, metadata. 

Ab time hai wahi project **v2 mein upgrade** karne ka. Aur jaise 1.5.1 mein planning se shuru kiya tha, waise hi yahan bhi — **pehle sochna hai kya upgrade karna hai, kaise, kyun.**

**Ek important baat:** 1.5 mein `lib/posts.ts` banai thi — type + static array + functions. Usme ek **genius decision** liya tha jo ab phal dega: pages data layer ke functions ko call karte hain, data file nahi jaante. Yehi abstraction 1.5.3 mein explain kiya tha — **"aage jab data API se aayega, pages ka code nahi badlega, sirf function ka andar."** Ab wo waqt aa gaya hai. Isko dhyaan mein rakho — ye v2 ki planning ki root hai.

## Planning V2 — Kya Upgrade Karna Hai

1.5.1 ke 4 sawaal dobara karo, par is baar context v2 ka:

**Sawaal 1 — Kya banana hai?** Portfolio/Blog Site ka upgrade — same spine, behtar capability.

**Sawaal 2 — Kaunse pages?** Same pages (Home, About, Projects, Contact, Blog, Blog/[slug]). Routes nahi badlenge — **kuch naya add hoga** (interactive widget) aur **kuch behtar hoga** (SEO).

**Sawaal 3 — Data kya hai?** Post ka shape same (slug/title/date/excerpt/content). **Source badlega** — static array se async API-jaisa source.

**Sawaal 4 — Data flow?** Pages wahi functions call karenge, par functions ka andar badlega.

Ab specific upgrades list karte hain — **teen upgrades + ek naya feature:**

### Upgrade 1 — Data Source: Static → Async API

**Problem:** Abhi `lib/posts.ts` mein data static array hai — page pe instant milta hai. Real app mein data **server/API se** aata hai. 

**Solution:** `lib/posts-api.ts` banayenge — functions `async` ho jayenge aur `Promise` return karenge, bilkul real `fetch()` ki tarah. **Pages ka call pattern badlega** — `await` lagana padega — par **data shape same rehta hai** (Post type). 

Kyun zaroori? Kyunki ye **real-world flow** hai. Batch 5 mein asli database aayegi, pattern wahi hoga. Abhi `setTimeout` se network delay simulate karenge — asli fetch jaisa.

### Upgrade 2 — Interactivity: Like Button (Client Component)

**Problem:** Abhi site bilkul static hai — user kuch click karke interact nahi kar sakta.

**Solution:** Ek **"Like this post" button** — `useState` use karega, click pe count badhega. Ye **Client Component** hoga (`"use client"`, 2.2 se yaad). Post page mein add hoga.

**Important decision (2.2 se):** Poore page ko client nahi banayenge — **sirf button** client. Page Server Component rahega (fast, SEO), button apni interactivity client pe laayega. **Yehi hybrid model hai.**

### Upgrade 3 — SEO: Metadata API

**Problem:** Abhi page ka tab title default hai ("portfolio" jaisa) — Google aur users ko pata nahi chalta page kya hai.

**Solution:** 
- Root layout mein **metadata template** — "… | Pravin" pattern
- Har page pe **static metadata** (About, Projects, Contact, Blog)
- Blog post pe **`generateMetadata`** — dynamic, post ke title se (2.4 se yaad)

### Upgrade 4 — Rendering Strategy: ISR

**Problem:** Blog data kam badalta hai — har request pe dynamic overkill hai.

**Solution:** Real fetch pe `revalidate` lagayenge (ISR, 2.3 se yaad) — static serve + background refresh.

## Data Flow — Kaise Badlega

1.5 mein:

```
lib/posts.ts (static array)
    ↓ getAllPosts()           ← synchronous, instant
app/blog/page.tsx
```

v2 mein:

```
lib/posts-api.ts (async data)
    ↓ await fetchAllPosts()   ← async, Promise, delay
app/blog/page.tsx  (Server Component)
```

**Notice:** Page ab `await` karega — isliye page `async function` hona chahiye (Server Component, 2.1 se yaad). **Yehi Next.js ka data fetching model hai.**

## What It Is NOT

⚠️ **v2 = "naya project" nahi.** Same Portfolio/Blog spine ka upgrade hai — routes, data shape, structure wahi. Capability badhi: async data, interactivity, SEO, rendering strategy.

⚠️ **Planning = "code likhna" nahi.** Ye sirf decide karna hai kya/kaise/kyun. Execution 2.5.2 se start hoga. Pehle sochna, phir banana — 1.5.1 wala hi mindset.

⚠️ **"Async data source" = "real backend" nahi.** Abhi fake API hai (setTimeout se delay). Real API/DB Batch 5+ mein. Pattern wahi rahega, isliye abhi hi async flow sikhna zaroori hai.
