2.1 mein humne product listing page banaya — Server Component mein direct `await fetch()`, koi loading state nahi. Bas ek problem — **page ab static hai.** User click kare toh kya hoga? Kuch nahi. Koi button interact nahi karta. Ab socho ek e-commerce site mein "Add to Cart" button — wo click karte hi count badhna chahiye, localStorage mein save hona chahiye. Wo Server Component mein kaisa chalega?

**Nahi chalega.** Kyunki 0.3 se yaad — Server Components browser pe run nahi hote, wo sirf server pe HTML banate hain. `useState`, `onClick`, `localStorage` — ye sab browser features hain. Inhe chahiye **Client Component**. Chalo isi confusion ko solve karte hain — Client Components kab chahiye, kab nahi.

---

## Manual Approach — React Mein Sab Kuch Client Tha

React course mein ye problem thi hi nahi — **React mein har component client-side tha.** `useState`, `useEffect`, `onClick` — sab kahin bhi chalta tha:

```tsx
// React — sab kuch client side
export default function ProductCard() {
  const [favorited, setFavorited] = useState(false);

  return (
    <button onClick={() => setFavorited(!favorited)}>
      {favorited ? "♥ Favorited" : "♡ Add to Favorites"}
    </button>
  );
}
```

Koi confusion nahi — sab browser pe chalta tha. Par iska nuksaan bhi tha (0.1 se yaad) — **poore app ka JavaScript browser pe bhejna padta tha, SEO ko dikkat, pehla load slow.**

---

## Better Approach — Server Default, Client Sirf Jab Chahiye

Next.js (App Router) ka model ulta hai: **by default sab Server Component hai, aur `"use client"` lagao toh Client Component banta hai.** 0.3 se yaad — aur wo cheez jo client chahiye usi ko client banao, baaki server pe rahe. Ye balance deta hai.

Server Component (default) → server pe render, browser pe kabhi JS load nahi hota → fast, SEO-friendly
Client Component (`"use client"`) → browser pe bhi JS load hota hai → interactivity

---

## Kab Chahiye Client Component?

Yeh decision points yaad rakho — agar inme se **koi ek** bhi true ho, toh Client Component chahiye:

1. **`useState`, `useEffect`, `useReducer`** — React state/hooks use kar rahe ho
2. **`onClick`, `onChange`** — event handlers (kuch clickable interactive)
3. **Browser APIs** — `localStorage`, `window`, `document`, `navigator`
4. **`usePathname`, `useSearchParams`** (client navigation hooks — aage use honge)

Agar sirf data dikhana hai (2.1 jaisa) — **Server Component.** Agar button interact kare — **Client Component.**

---

## Syntax — `"use client"` Directive

Server Component ko Client Component banana hai toh file ke **sabse upar** ek line:

```tsx
"use client";   // file ki sabse pehli line

import { useState } from "react";

export default function FavoriteButton() {
  const [favorited, setFavorited] = useState(false);

  return (
    <button onClick={() => setFavorited(!favorited)}>
      {favorited ? "♥ Added" : "♡ Add to Favorites"}
    </button>
  );
}
```

Bas. `"use client"` file ke top pe — isse Next.js samajhta hai ki is file ke saare components client pe render hone hain. **Important:** directive file-level hai — poori file ke components client bante hain.

---

## Minimal Example — Product Listing + Favorites Button

Ab 2.1 ke product listing mein interactivity jodte hain. Do files banengi — server page (data fetch) + client button (interactivity):

**File 1: `app/products/favorite-button.tsx`** (Client Component)

```tsx
"use client";

import { useState } from "react";

export default function FavoriteButton() {
  const [favorited, setFavorited] = useState(false);

  return (
    <button
      onClick={() => setFavorited(!favorited)}
      style={{ color: favorited ? "red" : "black" }}
    >
      {favorited ? "♥ Added to Favorites" : "♡ Add to Favorites"}
    </button>
  );
}
```

**File 2: `app/products/page.tsx`** (Server Component — data fetch)

```tsx
// app/products/page.tsx
import FavoriteButton from "./favorite-button";

interface Product {
  id: number;
  title: string;
  price: number;
}

interface ProductsResponse {
  products: Product[];
}

export default async function ProductsPage() {
  const res = await fetch("https://dummyjson.com/products");
  const data: ProductsResponse = await res.json();

  return (
    <main>
      <h1>Products</h1>
      <ul>
        {data.products.map((product) => (
          <li key={product.id}>
            <h2>{product.title}</h2>
            <p>${product.price}</p>
            <FavoriteButton />   {/* Client Component yahan */}
          </li>
        ))}
      </ul>
    </main>
  );
}
```

**Magic yahan kya hai:** Server Component (page) mein Client Component (button) **import aur render** ho raha hai. Page ka data fetch server pe hota hai, aur button apna JS browser pe load hota hai. Dono ek saath kaam kar rahe hain — **server data de raha hai, client interact kar raha hai.** Yehi hybrid model Next.js ki taakat hai.

Har product ke liye button alag click karega — kyunki har button apna `useState` chala raha hai. Click karo → "Add to Favorites" se "Added" ho jayega.

---

## Rule of Thumb — Server Component Ki File Pehle

Ab ek practical confusion — "ye component client lagana hai ya server?" Ek simple mental model:

**Pehle page/component ko Server Component socho. Phir poocho — kya isme interactivity chahiye?**
- Nahi → Server Component raho (fast, SEO-friendly)
- Haan → `"use client"` lagao

Aur ek acha pattern: **interactive parts ko alag chhote client components mein rakho** — poora page client nahi banate. Upar wale example mein page Server Component hai, sirf button Client hai. Isse baaki page ka fast/SEO fayda bacha raha hai, sirf button ko interactivity mili.

---

## Nutshell

Next.js mein default Server Component hai. `useState`, `onClick`, browser APIs chahiye toh `"use client"` file ke top pe lagao. Interactive parts ko alag chhote Client Components mein rakho, aur data-fetching page ko Server Component hi rehne do. Server Component ke andar Client Component import karna bilkul allowed hai.

---

## Common Mistakes

- ❌ `"use client"` ko file ke beech/neeche likhna — directive **sabse pehli line** pe hona chahiye.
- ❌ `"use client"` likhne par browser APIs (`localStorage`) directly render mein use karna — hydration mismatch ho sakta hai. `useEffect` ke andar ya event handler mein use karo.
- ❌ Server Component ko bina zaroorat client banana — poora page `"use client"` = React jaisa hi slow. Interactive parts ko hi alag karo.
- ❌ Client Component mein `await fetch()` karna — Client Components async nahi hote (Server Component feature hai). Wahan React style (`useEffect`) ya 2.1 wale server fetch se data bhejo.
- ❌ Doosri file ka `"use client"` bhoolna — har client file pe apna directive chahiye, parent se inherit nahi hota.

## What It Is NOT

⚠️ **`"use client"` = "client-side rendering" nahi.** Ye CSR (0.1 wala) nahi hai. `"use client"` wala component bhi pehle server pe pre-render hota hai (SSR), phir browser pe interactive banta hai. Directive sirf boundary define karta hai — konse components browser pe JS bundle mein jayenge.

⚠️ **`"use client"` = "yaani browser mein fetch" nahi.** Client Component mein bhi server-se-passed props mil sakte hain, aur 2.3/2.4 mein dekhenge ki data flow kaise manage hota hai.

⚠️ **Default server = "sirf Next.js ka tareeka" nahi.** Modern React (RSC) ka hi model hai, Next.js ise default banata hai. Concept aage aur frameworks mein bhi milega.
