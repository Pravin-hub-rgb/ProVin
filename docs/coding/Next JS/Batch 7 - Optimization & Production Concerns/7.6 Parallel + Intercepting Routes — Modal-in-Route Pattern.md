# Parallel + Intercepting Routes — The Modal-in-Route Pattern

## THINK — The Modal URL Puzzle

The familiar pattern: click an image → a **modal** opens (background blurred, photo detail). But Instagram's trick: the modal has a **URL** — `/photo/123`. And:

1. Click → modal opens, **URL becomes `/photo/123`** — shareable
2. **Navigate inside the modal** — **no full page reload**
3. **Back button** → modal closes, back on the same page
4. **Open URL directly** (someone else shared it) → **full page**, not a modal

This "modal-with-URL" pattern is built from two concepts — **Parallel Routes** (two independent screens on one URL) and **Intercepting Routes** (intercept a URL navigation to show a modal instead).

## CONCEPT — Two Concepts, One Pattern

### Parallel Routes — Two Screens on One URL

You're looking at a page layout. What if, on a single URL, **two independent screens** render simultaneously — one for the main content, one for a modal (if it's open)? This is **Parallel Routes** — two (or more) `page.tsx` files in the same route, in separate **slots.**

Syntax — folders prefixed with `@`:

```
app/
├── layout.tsx              ← renders both slots
├── page.tsx                ← children (root page)
├── @main/
│   ├── page.tsx            ← main content (gallery grid)
│   └── default.tsx         ← fallback (mandatory!)
└── @modal/
    ├── page.tsx            ← root: nothing (null)
    ├── default.tsx         ← fallback (mandatory!)
    └── (.)gallery/
        └── [id]/
            └── page.tsx    ← photo modal (intercepted)
```

**`@main`** and **`@modal`** are **slots.** Next.js automatically passes them as **props** to the root `layout.tsx` — no imports needed. The folder name `@main` becomes the prop `main`, `@modal` becomes `modal`.

```tsx
// app/layout.tsx
export default function RootLayout({ children, main, modal }) {
  return (
    <html lang="en">
      <body>
        {children}     {/* implicit slot — app/page.tsx */}
        {main}         {/* @main slot — gallery grid */}
        {modal}        {/* @modal slot — photo modal */}
      </body>
    </html>
  );
}
```

**Important:** Don't remove `{children}`! It's the **implicit slot** — the content of `app/page.tsx`. Add `{main}` and `{modal}` alongside it.

Two screens, one URL, side by side. Main content + an overlay modal.

### Intercepting Routes — Breaking the URL Flow

Now the Instagram trick — the URL becomes `/gallery/1` when you click, but the **modal** appears (no page reload). But open that URL **directly** and you get the **full page.** This is done with **Intercepting Routes.**

Syntax — folder name starts with `(.)`:

```
app/
├── @modal/
│   └── (.)gallery/         ← "intercept the gallery route"
│       └── [id]/
│           └── page.tsx    ← modal shown on click
└── gallery/
    └── [id]/
        └── page.tsx        ← full page on direct visit
```

**`(.)gallery`** — "intercept the `gallery` route." When the user navigates to `gallery/1` **from inside the app** (a Link click), the browser shows URL `/gallery/1`, but Next.js knows the user **clicked from a page** — so it renders `@modal/(.)gallery/[id]` (the modal). When someone opens the URL **directly** (or refreshes) — Next.js renders `gallery/[id]` as the full page.

Other match prefixes:
- `(.)` — same level
- `(..)` — one level up
- `(..)(..)` — two levels up
- `(...)` — from the root

### Each Slot Needs 3 Files

Parallel routes require **three files per slot:**

| File | What it does | Required? |
|---|---|---|
| `page.tsx` | What shows at the root of this slot | Yes (at the slot's parent route) |
| `default.tsx` | Fallback when no route matches | **Required** — build fails without it |
| `(.)route/page.tsx` | Intercepted content (the modal) | Yes (for the modal pattern) |

**`@modal/page.tsx`** — at root, shows nothing (`null`). Without this, interception doesn't work — it redirects instead.

## CODE — Step-by-Step Build (What We Built)

### Step 1 — Add `modal` Slot to Layout

**THINK:** Parallel routes need the layout to render the slot — `{children}` (main) + `{modal}`. Update the root layout (from 7.7.2 / 7.7.4).

**File:** `app/layout.tsx`

**Concept:** The layout's signature changes — `children` plus `modal`. `RootLayout({ children, modal })` — Next.js passes the parallel slot as the `modal` prop (folder `@modal` → prop `modal`). Render: main content + modal overlay.

**File:** `app/layout.tsx` — step by step.

First, the signature — **`RootLayout({ children, modal })`** — two props now: `children` (main page) + `modal` (`@modal` slot — the parallel route). Add both to the types:

```tsx
// app/layout.tsx
import { Inter } from "next/font/google";
import Link from "next/link";

const inter = Inter({ subsets: ["latin"], variable: "--font-inter" });

export default function RootLayout({
  children,
  modal,
}: Readonly<{
  children: React.ReactNode;
  modal: React.ReactNode;
}>) {
```

**`children` + `modal`** — two props — the parallel slot `@modal` comes through as `modal`.

Now render — **`{modal}`** — render after main, so the modal overlay appears **on top** of the content (via absolute/fixed positioning):

```tsx
// app/layout.tsx
import { Inter } from "next/font/google";
import Link from "next/link";

const inter = Inter({ subsets: ["latin"], variable: "--font-inter" });

export default function RootLayout({
  children,
  modal,
}: Readonly<{
  children: React.ReactNode;
  modal: React.ReactNode;
}>) {
  return (
    <html lang="en" className={inter.variable}>
      <body>
        <header className="border-b p-4">
          <Link href="/" className="text-lg font-semibold">
            Photo Gallery
          </Link>
        </header>
        <main className="mx-auto max-w-4xl p-4">{children}</main>
        {modal}
      </body>
    </html>
  );
}
```

**`{modal}`** — rendered after `</main>` — the modal overlay on top. No `@modal` folder yet — no error, just nothing renders.

### Step 2 — `@modal/default.tsx`: No Modal State

**THINK (7.6):** Each slot needs a `default.tsx` — the fallback when no route matches. During normal navigation (no modal open) — `@modal` should render nothing.

**File:** `app/@modal/default.tsx`

**Concept:** `default.tsx` is the fallback for a parallel slot — when no matching route exists, this renders. No modal = `null` — nothing shows. (7.6 explains why this is needed.)

```tsx
// app/@modal/default.tsx
export default function ModalDefault() {
  return null;
}
```

**`return null`** — the slot is empty during normal navigation. This file is mandatory — without it, the parallel route throws a build error.

### Step 3 — `@modal/(.)photo/[id]/page.tsx`: The Modal

**THINK (7.6):** This is the real interception — `(.)photo/[id]` — when the user **navigates from within** `/photo/1` (click from the grid), Next.js renders this file as a **modal.** A direct visit or refresh hits `photo/[id]` (the full page from 7.7.4).

**File:** `app/@modal/(.)photo/[id]/page.tsx` (create folders `@modal/(.)photo/[id]`)

**Concept:** The modal content is the photo detail (image + title + description) shown **as an overlay** — `fixed inset-0` (full screen), `bg-black/70` (dark backdrop), content centered. Photo data comes from `getPhoto(id)` — same query as the full page. The close button → Link to `/` — the modal slot empties and the grid returns.

**File:** `app/@modal/(.)photo/[id]/page.tsx` — step by step.

First, imports + data — **`Image`** (optimized, same as 7.7.4), **`Link`** (to close), **`prisma`** (to fetch). **`getPhoto`** — the same helper (7.7.3) fetching a photo by id:

```tsx
// app/@modal/(.)photo/[id]/page.tsx
import Image from "next/image";
import Link from "next/link";
import prisma from "@/lib/prisma";

async function getPhoto(id: number) {
  return prisma.photo.findUnique({ where: { id } });
}

export default async function PhotoModal({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const photo = await getPhoto(Number(id));

  if (!photo) {
    return null;
  }

  return (
    <div className="fixed inset-0 z-50 flex items-center justify-center bg-black/70">
      <div className="relative w-full max-w-lg rounded-lg bg-white p-4 shadow-xl">
        <Link
          href="/"
          className="absolute right-3 top-3 rounded-full bg-zinc-200 px-2 text-zinc-600"
        >
          X
        </Link>

        <Image
          src={photo.src}
          alt={photo.alt}
          width={800}
          height={600}
          className="rounded object-cover"
        />
        <h2 className="mt-3 text-lg font-semibold">{photo.title}</h2>
        <p className="text-zinc-600">{photo.description}</p>
      </div>
    </div>
  );
}
```

**`if (!photo) return null`** — if the photo doesn't exist, don't show a modal (no 404 page in a modal). **`fixed inset-0 z-50 bg-black/70`** — the overlay — full screen, dark backdrop, on top (same pattern as 7.6's demo). **`Link href="/"`** — the **close button** — navigating to `/` empties the `@modal` slot, the grid returns. **`<Image width={800} height={600}>`** — inside the modal we know the size (fixed modal) so `width`/`height` work — no `fill` needed.

> **DRY note — `getPhoto` now exists in two files** (the full page + the modal). For now, small project — duplication is acceptable. In production, move it to a shared file (`lib/photos.ts`) — that's the data-layer pattern from the series. A hint for 7.7.6.

### Step 4 — TEST: Modal Behavior

**TEST (7.6's expected behaviors):**

1. **Click from grid:** Click a photo on `/` → a **modal opens** (overlay, dark backdrop) — URL becomes `/photo/1` — **no page reload** (the grid stays visible underneath the modal).
2. **Back button:** Browser back → **modal closes**, back to the grid (URL `/`).
3. **Direct visit:** Open `/photo/1` in a **new tab** → you get the **full page** (header + large image + title) — not a modal.
4. **Close button:** Click X in the modal → back to grid.
5. **Refresh modal URL:** Modal is open (`/photo/1`) and you refresh → you get the **full page** (refresh = direct visit, interception doesn't apply).

This test is the proof of 7.6's pattern — **click = modal, direct/refresh = full page.**

### Step 5 — Modal SEO/Title (Bonus)

**THINK:** When the modal is open, what's the browser tab title? Interception means Next.js doesn't look up that route's metadata (the full page's metadata). A small tweak — static metadata on the modal page:

```tsx
// app/@modal/(.)photo/[id]/page.tsx
import type { Metadata } from "next";
import Image from "next/image";
import Link from "next/link";
import prisma from "@/lib/prisma";

export const metadata: Metadata = {
  title: "Photo Detail",
};

async function getPhoto(id: number) {
  return prisma.photo.findUnique({ where: { id } });
}
```

**`export const metadata`** — a static title for the modal route. Dynamic `generateMetadata` is skipped here — the modal is a transient state. The full page's dynamic metadata (from 7.7.3) still applies on direct visits. Note: real SEO benefits come from the full page — the modal is just a transition.

## Nutshell

Photo Modal: add a **`modal` slot** to the root layout (`{children}` + `{modal}`). Create `app/@modal/default.tsx` → `return null` (no modal state — mandatory). Create `app/@modal/(.)photo/[id]/page.tsx` → the intercepted modal — renders on click from the grid (fixed overlay, dark backdrop, photo + close Link); direct visit/refresh hits `photo/[id]` (the full page, unchanged). Close = Link to `/`. If the photo is missing → `return null` (no 404 in a modal). Back button closes. **Click = modal, direct visit = full page.**

## What It Is NOT

- **`@modal` folder is not a "URL path."** The `@` prefix marks a **slot** — it doesn't appear in the URL. The slot is just where in the layout the modal renders. The real URL is still `/photo/1` — the slot is a rendering position, not a route.
- **The modal page is not "duplicating the full page."** Both are variants of rendering `/photo/[id]` — the full page on direct visit, the modal on click. Same data, image, title — different presentation.
- **`(.)` prefix is not "hiding a folder."** `(.)` is an **intercept marker** — "intercept this segment when navigation comes from within the app." The `(.)` is stripped from the URL (it's not part of the folder's public name). The click vs. direct distinction comes entirely from this marker.
- **`if (!photo) return null` is not the same as `notFound()`.** On a full page, no photo = a proper 404 (`notFound()`). In a modal, a 404 page would be awkward — so we just render nothing (the slot stays empty, the user is still on the grid). Different context, different handling.
- **The close button is not the same as browser back.** The close button navigates to `/` (empties the modal slot). Browser back also closes the modal (the history stack had `/` before `/photo/1`) — both achieve the same result through different mechanisms.

1. How does the `modal` slot get into the root layout — what connects `@modal` to the layout?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Next.js passes the parallel slot as a prop to the layout — the folder `@modal` becomes the prop `modal`, and the `RootLayout({ children, modal })` receives it. The layout renders `{modal}` after the main content. The `@` prefix means it's a slot (not in the URL), and Next.js wires it to the layout automatically — no imports needed.

</details>

2. How do `@modal/(.)photo/[id]/page.tsx` and `photo/[id]/page.tsx` render differently for the same `/photo/1` URL?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `(.)photo` is an interception — when the user navigates to `/photo/1` **from within the app** (clicking from the grid), Next.js renders `@modal/(.)photo/[id]` as a modal. When someone opens the URL **directly** or refreshes, interception doesn't apply — the `photo/[id]` full page renders. Same URL, different render based on how navigation happened.

</details>

3. Why is `@modal/default.tsx` needed — what happens without it?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `default.tsx` is the fallback for a parallel slot — rendered when no matching route exists for that slot. During normal navigation (no modal open), `@modal` has no matching route, so `default.tsx` renders (returning `null` = empty). Without `default.tsx`, Next.js throws a build error — the slot has no fallback. Every parallel slot requires one.

</details>

4. Why does the modal use `return null` when the photo is missing, while the full page uses `notFound()`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Different contexts. The full page is the photo's own page — if it doesn't exist, a proper 404 is appropriate (the URL points to nothing). The modal is a transient overlay on top of the grid — a 404 page appearing as an overlay is jarring. Instead, we render nothing (the slot stays empty and the user is still on the grid).

</details>

5. The close button uses `Link href="/"` and so does browser back — how do they differ?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The close button navigates to `/` programmatically via a `Link` — the URL changes to `/`, the `@modal` slot loses its matching route, and `default.tsx` (null) renders, hiding the modal. Browser back works because `/` was on the history stack before `/photo/1` — going back returns to `/`, which also empties the modal. Same result, different mechanism — one is a `Link` click, the other is browser history.

</details>
