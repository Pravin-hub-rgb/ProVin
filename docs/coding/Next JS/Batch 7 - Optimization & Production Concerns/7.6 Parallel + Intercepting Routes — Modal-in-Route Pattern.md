# Parallel + Intercepting Routes — The Modal-in-Route Pattern

## THINK — The Modal URL Puzzle

A familiar pattern — click an image → a **modal** opens (background blurred, photo detail). But Instagram's trick: the modal has a **URL** — `/photo/123`. And:

1. Click → modal opens, **URL becomes `/photo/123`** — shareable
2. **Navigate inside the modal** — **no full page reload**
3. **Back button** → modal closes, back on the same page
4. **Open URL directly** (someone else shared it) → **full page**, not a modal

This "modal with a URL" pattern is built from two concepts — **Parallel Routes** (two independent screens on one URL) and **Intercepting Routes** (intercept a URL navigation to show a modal instead).

## CONCEPT — Two Concepts, One Pattern

### Parallel Routes — Two Screens on One URL

You're looking at a page layout. What if, on a single URL, **two independent screens** could render simultaneously — one for main content, one for a modal (if it's open)? This is **Parallel Routes** — two (or more) `page.tsx` files in the same route, in separate **slots.**

Syntax — folders prefixed with `@`:

```
app/
├── layout.tsx              ← renders both slots
├── page.tsx                ← children (root page)
├── @main/
│   ├── page.tsx            ← main content (gallery grid)
│   └── default.tsx         ← fallback (mandatory!)
└── @modal/
    ├── page.tsx            ← root: nothing (null)
    ├── default.tsx         ← fallback (mandatory!)
    └── (.)gallery/
        └── [id]/
            └── page.tsx    ← photo modal (intercepted)
```

**`@main`** and **`@modal`** are **slots.** Next.js **automatically** passes them to the root `layout.tsx` as **props** — no imports needed. The folder name `@main` becomes the prop `main`, `@modal` becomes `modal`.

```tsx
// app/layout.tsx
export default function RootLayout({ children, main, modal }) {
  return (
    <html lang="en">
      <body>
        {children}     {/* implicit slot — app/page.tsx */}
        {main}         {/* @main slot — gallery grid */}
        {modal}        {/* @modal slot — photo modal */}
      </body>
    </html>
  );
}
```

**Important:** Don't remove `{children}`! It's the **implicit slot** — the content of `app/page.tsx`. Add `{main}` and `{modal}` alongside it.

Two screens, one URL, side by side. Main content + a floating modal on top.

### Intercepting Routes — Breaking the URL Flow

Now the Instagram trick — the URL becomes `/gallery/1` when you click, but the **modal** appears (no page reload). But open that URL **directly** and you get the **full page.** This is **Intercepting Routes.**

Syntax — folder name starts with `(.)`:

```
app/
├── @modal/
│   └── (.)gallery/         ← "intercept the gallery route"
│       └── [id]/
│           └── page.tsx    ← modal shown on click
└── gallery/
    └── [id]/
        └── page.tsx        ← full page on direct visit
```

**`(.)gallery`** — "intercept the `gallery` route." When the user navigates to `gallery/1` **from inside the app** (a Link click), the browser shows the URL `/gallery/1`, but Next.js knows the user **clicked from a page** — so it renders `@modal/(.)gallery/[id]` (the modal). When someone opens the URL **directly** (or refreshes) — Next.js renders `gallery/[id]` as the full page.

Other match prefixes:
- `(.)` — same level
- `(..)` — one level up
- `(..)(..)` — two levels up
- `(...)` — from the root

### Each Slot Needs 3 Files

Parallel routes require **three files per slot:**

| File | What it does | Required? |
|---|---|---|
| `page.tsx` | What shows at the root of this slot | Yes (at the slot's parent route) |
| `default.tsx` | Fallback when no route matches | **Required** — build fails without it |
| `(.)route/page.tsx` | Intercepted content (the modal) | Yes (for the modal pattern) |

**`@modal/page.tsx`** — at root, shows nothing (`null`). Without this, interception doesn't work — it redirects instead.

## CODE — Step-by-Step Build (What We Built)

### Step 1 — Add Slots to Layout

```tsx
// app/layout.tsx
export default function RootLayout({ children, main, modal }: LayoutProps<"/">) {
  return (
    <html lang="en">
      <body>
        {children}     {/* implicit slot */}
        {main}         {/* @main slot */}
        {modal}        {/* @modal slot */}
      </body>
    </html>
  );
}
```

**Before:** just `{children}`. **After:** `{children}` + `{main}` + `{modal}`. The function signature also gets the new props.

### Step 2 — Root Page Empty

```tsx
// app/page.tsx
export default function Home() {
  return null;
}
```

`@main` renders the grid — `children` should be empty to avoid duplicates.

### Step 3 — `default.tsx` for Each Slot

```tsx
// app/@main/default.tsx
export default function Default() {
  return null;
}

// app/@modal/default.tsx
export default function Default() {
  return null;
}
```

**Don't skip this step.** Without `default.tsx`, you get: *"Missing required default.js file for parallel route."*

### Step 4 — Root `@modal/page.tsx`

```tsx
// app/@modal/page.tsx
export default function ModalPage() {
  return null;
}
```

**This is the trickiest step.** Without it, clicking an image doesn't open a modal — it just redirects to `/gallery/1` and shows a 404. The `@modal` slot needs a root-level page for interception to work.

### Step 5 — Build the Grid (`@main/page.tsx`)

```tsx
// app/@main/page.tsx
import Image from "next/image";
import { fetchPhotos } from "@/app/lib/photos";
import Link from "next/link";

export default async function GalleryGrid() {
  const photos = await fetchPhotos();
  return (
    <div className="flex flex-wrap gap-4">
      {photos.map((photo) => (
        <Link key={photo.id} href={`/gallery/${photo.id}`}>
          <Image src={photo.src} alt={photo.alt} width={250} height={250} />
        </Link>
      ))}
    </div>
  );
}
```

**Wrap in `Link`** — so the click does a soft navigation (interception works). A plain `<Image>` click would need an `<a>` wrapper.

### Step 6 — Build the Modal (`@modal/(.)gallery/[id]/page.tsx`)

```tsx
// app/@modal/(.)gallery/[id]/page.tsx
import Image from "next/image";
import { fetchPhotos } from "@/app/lib/photos";
import { CloseButton } from "@/app/components/CloseButton";
import { ModalOverlay } from "@/app/components/ModalOverlay";

export default async function PhotoModal({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const photos = await fetchPhotos();
  const photo = photos.find((p) => p.id === parseInt(id));
  if (!photo) return null;
  return (
    <ModalOverlay>
      <CloseButton />
      <Image src={photo.src} alt={photo.alt} width={800} height={600} />
      <p className="mt-2 text-center">{photo.title}</p>
    </ModalOverlay>
  );
}
```

In Next.js 16, `params` is a **Promise** — `params: Promise<{ id: string }>`. `await params` first. (Older versions had `params` as a plain object.)

### Step 7 — Standalone Full Page

```tsx
// app/gallery/[id]/page.tsx
import Image from "next/image";
import { fetchPhotos } from "@/app/lib/photos";

export default async function PhotoPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const photos = await fetchPhotos();
  const photo = photos.find((p) => p.id === Number(id));
  if (!photo) return <p>Photo not found</p>;
  return (
    <main className="p-8">
      <Image src={photo.src} alt={photo.alt} width={800} height={800} />
      <h1>{photo.title}</h1>
    </main>
  );
}
```

When someone opens the URL **directly** (or refreshes), this full page renders. No modal.

### Step 8 — Client Components (Close + Backdrop)

The modal needs interactive elements — a close button, backdrop click. But the modal page is a **Server Component** (async `params`). So create separate client components:

```tsx
// app/components/CloseButton.tsx
"use client";
import { useRouter } from "next/navigation";

export function CloseButton() {
  const router = useRouter();
  return (
    <button
      onClick={() => router.back()}
      className="absolute top-2 right-2 bg-black/50 text-white rounded-full w-8 h-8 flex items-center justify-center hover:bg-black/70 cursor-pointer"
    >
      ✕
    </button>
  );
}
```

```tsx
// app/components/ModalOverlay.tsx
"use client";
import { useRouter } from "next/navigation";
import { ReactNode } from "react";

export function ModalOverlay({ children }: { children: ReactNode }) {
  const router = useRouter();
  return (
    <div
      className="fixed inset-0 bg-black/30 flex items-center justify-center z-50"
      onClick={() => router.back()}
    >
      <div onClick={(e) => e.stopPropagation()} className="bg-white p-4 rounded-lg relative max-w-lg">
        {children}
      </div>
    </div>
  );
}
```

**`stopPropagation()`** — if you click the modal content, the event doesn't bubble to the backdrop (modal doesn't close). Clicking the backdrop = close. Clicking the modal content = nothing.

### Final Folder Structure

```
app/
├── layout.tsx                          ← slots: children, main, modal
├── page.tsx                            ← null (empty)
├── @main/
│   ├── page.tsx                        ← gallery grid + Link
│   └── default.tsx                     ← null
├── @modal/
│   ├── page.tsx                        ← null (root level — REQUIRED for interception!)
│   ├── default.tsx                     ← null
│   └── (.)gallery/
│       └── [id]/
│           └── page.tsx                ← modal (intercepted)
├── gallery/
│   └── [id]/
│       └── page.tsx                    ← full photo page (standalone)
├── components/
│   ├── CloseButton.tsx                 ← "use client" — router.back()
│   └── ModalOverlay.tsx                ← "use client" — backdrop click + stopPropagation
└── lib/
    └── photos.ts                       ← data layer
```

## COMMON PITFALLS — Errors We Faced

### 1. `main is not defined`

```
ReferenceError: main is not defined
at RootLayout (app\layout.tsx:26:61)
```

**What happened:** Used `{main}` and `{modal}` in JSX but didn't add them to the function signature.

**Fix:**

```tsx
// Wrong — only children
export default function RootLayout({ children }: LayoutProps<"/">) {

// Correct — children + main + modal
export default function RootLayout({ children, main, modal }: LayoutProps<"/">) {
```

### 2. `Missing required default.js file for parallel route`

```
Error: Missing required default.js file for parallel route at //@main
```

**What happened:** `@main/default.tsx` was an empty file (0 lines, no export).

**Fix:** Every slot needs a `default.tsx` with an export:

```tsx
export default function Default() {
  return null;
}
```

### 3. Redirect Instead of Modal

```
Click on image → /gallery/1 → 404 Not Found
```

**What happened:** Missing `@modal/page.tsx`. Without a root-level page, the slot doesn't support interception.

**Fix:** Add `@modal/page.tsx`:

```tsx
export default function ModalPage() {
  return null;
}
```

### 4. `Property 'params' does not exist on type 'Promise'`

```
Property 'params' does not exist on type 'Promise<{ params: { id: string; }; }>'
```

**What happened:** Params type was wrong — `Promise<{ params: { id: string } }>` (double-wrapped).

**Fix:** In Next.js 16, params is a separate Promise:

```tsx
// Wrong
{ params }: Promise<{ params: { id: string } }>

// Correct
{ params }: { params: Promise<{ id: string }> }
```

### 5. Turbopack Crash — HMR Error

```
FATAL: An unexpected Turbopack error occurred
```

**What happened:** The `.next` cache got corrupted after file changes.

**Fix:** Stop the server, delete the `.next` folder, restart:

```
Ctrl+C
Remove-Item -Recurse -Force .next
npm run dev
```

## TEST — Verify the Pattern

1. Click a photo in the gallery → **URL `/gallery/1`** changes, modal opens (no page reload).
2. **Click the backdrop** → modal closes, gallery returns.
3. **Close button (✕)** → modal closes, gallery returns.
4. Open `/gallery/1` in a **new tab** → full photo page (not modal).
5. Press browser **Back** → modal closes (or goes back).

This behavior — click = modal, direct = full page — is the **signature of Intercepting Routes.**

## Nutshell

Parallel Routes + Intercepting Routes create the **modal-in-route pattern** (Instagram-style photo modal). **Parallel Routes** render two independent screens on one URL via slots (`@modal`, `@main`) — the layout renders both slots, and slot names become automatic props (no imports needed). **Intercepting Routes** use the `(.)` folder prefix to intercept a URL: click from a page → modal renders; direct visit → full page. Each slot needs a **mandatory** `default.tsx`, and `@modal/page.tsx` must exist at root level. In Next.js 16, `params` is a **Promise** — `await params` first. Interactive elements (close button, backdrop click) must be **Client Components** (`"use client"`).

## What It Is NOT

- **Parallel Routes are not "nested routes."** Nested routes render inside each other (parent-child). Parallel routes are **independent** sibling screens on the same URL — side by side in different slots.
- **Intercepting Routes are not "redirects."** A redirect changes the URL and reloads the page. Intercepting keeps the URL **the same** but renders a different component (modal vs. full page) — no reload.
- **The `(.)` prefix is not "hiding a folder."** `(.)` is an **intercept marker** — "intercept this segment when navigation originates from within the app." The `(.)` is stripped from the URL. Its purpose is navigation interception, not folder hiding.
- **A modal is not "just a CSS overlay."** The overlay styling is part of it, but the modal's core is **URL handling** — back button support, shareable URL, and click vs. direct-visit distinction. That's what makes it production-grade.
- **`default.tsx` is not "optional."** Every slot requires it as a fallback. Without it, the build fails. Each slot needs a `default.tsx` that says what to render when no route matches.
- **`@modal/page.tsx` is not "skippable."** The root-level `page.tsx` for the slot is required — without it, linking doesn't open the modal, it just redirects to a 404.

**In Your Own Words**

1. Parallel Routes render two screens on one URL — what role do slots play?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Each slot (`@modal`, `@main`) is an independent rendering area on the same URL. Next.js passes each slot as a prop to the root layout — `@main` → `main`, `@modal` → `modal` — and the layout renders them (`{children} + {main} + {modal}`). One URL, two screens: main content + an overlay modal side by side. No imports needed — the `@` prefix is the signal.

</details>

2. What does `(.)` prefix on `(.)gallery` actually do — how does it "intercept"?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The `(.)gallery/[id]/page.tsx` inside `@modal` is an **intercept** — when the user navigates to `/gallery/1` **from within the app** (a Link click from the grid), Next.js intercepts the navigation and renders the modal instead of the full page. The URL still shows `/gallery/1`, but the rendered component is the modal. If the URL is opened **directly** (or refreshed), no interception happens — the full page renders.

</details>

3. Why does each slot need `default.tsx` — and `@modal/page.tsx` at root?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `default.tsx` is the **fallback** — what renders when no route in that slot matches (e.g. normal navigation with no modal open → `null`). Without it, Next.js fails: *"Missing required default.js file for parallel route."* `@modal/page.tsx` at root is required for interception to work — without it, clicking a link redirects to the bare route (404) instead of rendering the intercepted modal. Both are mandatory.

</details>

4. Why do the close button and overlay need `"use client"`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The modal page is a Server Component (it's async — fetching data). But the close button needs `onClick` → `router.back()`, and the overlay needs click-to-close — **interactivity only works in Client Components.** So they're split into separate `"use client"` files. Server Component for data, Client Component for interaction — the standard pattern.

</details>

5. What's the difference between `router.back()` and `router.push("/")`? Which is better for closing a modal?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `router.back()` uses the **browser history** — goes back to whatever was before (could be the gallery, or somewhere else). `router.push("/")` always goes to `/`, regardless of where you came from. For a modal-on-gallery pattern, `router.back()` is natural (back = close = back to grid), but if you want to guarantee landing on the gallery, `router.push("/")`. Both empty the `@modal` slot → modal closes.

</details>
