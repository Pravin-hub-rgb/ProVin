# Parallel + Intercepting Routes — Modal-in-Route Pattern

## SOCH — Modal Ka URL Wala Puzzle

Ek aam pattern — kisi image pe click karte ho, **modal** khulta hai (background blur, photo detail). Par Instagram wala trick yeh hai ki modal ka ek **URL hota hai** — `/photo/123`. Aur:

1. Click pe modal khulta hai, **URL `/photo/123` ho jaata hai** — share kar sakte ho
2. Modal mein hi navigate karte ho — **poore page ka reload nahi**
3. **Back button** dabao toh modal close, same page wapas
4. URL direct kholo toh (kisi aur ne share kiya) — **full photo page** khulta hai, modal nahi

Yeh "modal-with-URL" pattern do cheezon se banta hai — **Parallel Routes** (ek hi URL pe do screens) aur **Intercepting Routes** (browser URL ko intercept karke modal dikhana).

## CONCEPT — Do Concepts, Ek Pattern

### Parallel Routes — Ek URL Pe Do Screens

Ek page ka layout aap dekh rahe ho. Kya ho agar ek hi URL pe **do independent screens** simultaneously render hon — ek main content, ek modal (agar khola ho)? Isi ko kehte hain **Parallel Routes** — do ya zyada `page.tsx` ek hi route mein, sirf unki **slots** alag.

Syntax — folder ke andar do folders with `@` prefix:

```
app/
└── layout.tsx
└── @main/
    └── page.tsx        ← main content (gallery grid)
└── @modal/
    └── default.tsx     ← koi modal na ho toh (empty)
    └── photo/[id]/
        └── page.tsx    ← photo modal
```

**`@main`** aur **`@modal`** — yeh **slots** hain. Root `layout.tsx` dono ko render karta hai — `{children}` (main) aur `{modal}`:

```tsx
// app/layout.tsx
export default function RootLayout({ children, modal }) {
  return (
    <html lang="en">
      <body>
        {children}     {/* @main — gallery grid */}
        {modal}        {/* @modal — photo modal, agar khola ho */}
      </body>
    </html>
  );
}
```

Do screens, ek URL pe, side-by-side render. Main content + overlay modal.

### Intercepting Routes — URL Ko Pattern Se Todna

Ab Instagram trick — click pe URL `/photo/123` dikhta hai, par modal khulta hai (page reload nahi). Par direct `/photo/123` kholo toh **full page**. Isi URL-change-but-layout-hack ko karte hain **Intercepting Routes**.

Syntax — folder ka naam `(.)` prefix se shuru:

```
app/
└── @modal/
    └── (.)photo/
        └── [id]/
            └── page.tsx    ← click pe yeh modal dikhega
└── photo/
    └── [id]/
        └── page.tsx        ← direct visit pe yeh full page
```

**`(.)photo`** — "intercept `photo` route." Jab user gallery se `photo/123` pe navigate karta hai, browser URL `/photo/123` dikhata hai, par Next.js ko pata hai ki **user ne page se click kiya** — toh `@modal/(.)photo/[id]` render karta hai (modal). Jab koi URL **directly** kholta hai (ya refresh) — Next.js `photo/[id]` full page render karta hai.

### Kya chahiye — `default.tsx`

Har slot ko `default.tsx` chahiye — tab jab slot ki koi matching route na ho. `@modal` mein jab koi modal nahi (normal page) — `@modal/default.tsx` render ho — `null` return karo. Baaki navigation par `default.tsx` use hota hai (jaise unknown route). Bina `default.tsx` — error.

## CODE — Chhota Demo (Photo Gallery ka Preview)

Poora Photo Gallery 7.7.5 mein banayenge — yahan sirf structure dikhta hai. Ek photo card pe click → modal. Do files:

**File:** `app/@modal/(.)photo/[id]/page.tsx` — intercepted modal

```tsx
// app/@modal/(.)photo/[id]/page.tsx
import Image from "next/image";
import Link from "next/link";

export default async function PhotoModal({
  params,
}: {
  params: { id: string };
}) {
```

## TEST — Pattern Ka Farak Dekho

Photo Gallery (7.7.5) pe:

1. Gallery se photo pe click → **URL `/photo/123`** hota hai, modal khulta hai (page reload nahi).
2. **Back** button → modal close, gallery wapas.
3. URL `/photo/123` ko **naye tab mein kholo** → full photo page, modal nahi.

Yeh behaviour — click = modal, direct = full page — **Intercepting Routes** ka signature hai.

## Nutshell

Parallel Routes + Intercepting Routes milke **modal-in-route pattern** banate hain (Instagram-style photo modal). **Parallel Routes** — ek URL pe do independent screens render karte hain slots (`@modal`, `@main`) ke through; layout mein dono slot render hote hain. **Intercepting Routes** — `(.)photo` folder syntax se URL ko intercept karte hain: page se click = modal, direct visit = full page. Har slot ko `default.tsx` chahiye. 7.7.5 mein Photo Gallery mein full implementation.

## What It Is NOT

- **Parallel Routes = "nested routes" nahi.** Nested routes ek-dusre ke andar render hote hain (parent-child). Parallel routes ek hi URL pe **independent** screens hain — side-by-side, do slots.
- **Intercepting Routes = "redirect" nahi.** Redirect URL change karta hai. Intercepting browser ke URL ko **wahi rakhta hai** par render alag component karta hai (click = modal, direct = full page).
- **`(.)` prefix = "folder ko hide karna" nahi.** URL se `(.)` hata diya jaata hai (jaise route groups `(auth)` mein) — par iska actual purpose navigation ke time intercept karna hai. Kaam alag hai.
- **Modal = "sirf CSS overlay" nahi.** Overlay styling ka hissa hai, par pattern ka core URL handling hai — back button, share-able URL, direct vs click distinction. Yehi to modal ko pro banata hai.
