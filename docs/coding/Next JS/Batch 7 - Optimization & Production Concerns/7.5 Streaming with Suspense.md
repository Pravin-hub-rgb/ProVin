# Streaming with Suspense

## SOCH — Pura Page Kyun Rukta Hai

Server Component mein `await db.select()` likha — page tab tak render nahi hota jab tak query complete na ho. Agar query 3 second leti hai, user 3 second **blank screen** dekhta hai. Poori page render — server pe — ek hi block mein.

Kyun? Kyunki page ka **render data pe depend hai** — server ko poora data chahiye, poora HTML bhejne se pehle. Par isme koi zaroorat nahi ki **header** bhi 3 second ruke — header ka data 50ms ka hai.

Ise solve karta hai **Streaming** — server HTML ko **chunks** mein bhejta hai. Jo section ready, uska chunk pehle. Slow section baad mein. User ko page **turant** dikhna shuru ho jaata hai.

## CONCEPT — Suspense Kya Hai

**Suspense** React ka built-in feature hai — "is jagah ke ready hone tak fallback dikhao." Jaisi hi andar ka data ready, fallback replace ho jaata hai.

```tsx
<Suspense fallback={<GallerySkeleton />}>
  <SlowGallery />
</Suspense>
```

**`<Suspense fallback={...}>`** — boundary. **`<SlowGallery />`** — andar wala component (slow async). Jab tak `SlowGallery` ready nahi, `fallback` (skeleton) dikhega. Ready hote hi real content.

Ab Next.js ke Server Components mein — `SlowGallery` ek **async component** hai jo `await` karta hai. Uske await ke time, Suspense boundary ko fallback dikhata hai. Baaki page (Suspense ke bahar) turant render + stream hota hai.

### `loading.tsx` vs `<Suspense>`

1.4 mein `loading.tsx` dekh chuke ho — wo **route-level Suspense boundary** hai (poora page). Agar poora page slow hai toh `loading.tsx` — skeleton. Par jab page ka **sirf ek section** slow hai — granular `<Suspense>` use karo, section ke around.

## CODE — Ek Section Ko Stream Karna

Ek page lo jisme gallery slow hai:

**File:** `app/gallery/page.tsx` — bina Suspense (poore page ka wait)

```tsx
// app/gallery/page.tsx
import { fetchPhotos } from "@/lib/photos";

export default async function GalleryPage() {
  const photos = await fetchPhotos();          // 3 second slow

  return (
    <main>
      <h1>Photo Gallery</h1>
      <div className="grid grid-cols-3 gap-4">
        {photos.map((photo) => (
          <div key={photo.id}>{photo.title}</div>
        ))}
      </div>
    </main>
  );
}
```

Yahan `await fetchPhotos()` — 3 second — poora page rukta hai, `h1` tak nahi dikhta. Ab same page, Suspense se:

**File:** `app/gallery/page.tsx` — Suspense boundary (h1 turant, grid stream)

```tsx
// app/gallery/page.tsx
import { Suspense } from "react";
import { fetchPhotos } from "@/lib/photos";

async function PhotoGrid() {
  const photos = await fetchPhotos();          // 3 second slow

  return (
    <div className="grid grid-cols-3 gap-4">
      {photos.map((photo) => (
        <div key={photo.id}>{photo.title}</div>
      ))}
    </div>
  );
}

export default function GalleryPage() {
  return (
    <main>
      <h1>Photo Gallery</h1>
      <Suspense fallback={<PhotoGridSkeleton />}>
        <PhotoGrid />
      </Suspense>
    </main>
  );
}

function PhotoGridSkeleton() {
  return (
    <div className="grid grid-cols-3 gap-4">
      {Array.from({ length: 9 }).map((_, i) => (
        <div key={i} className="h-40 animate-pulse bg-zinc-200" />
      ))}
    </div>
  );
}
```

**Kya badla:**

1. **`async function PhotoGrid()`** — slow wala logic alag async component mein nikala.
2. **`export default function GalleryPage()`** — page ab `async` nahi — synchronous. Koi `await` top level pe nahi — isliye poora page **turant** render ho sakta hai.
3. **`<Suspense fallback={<PhotoGridSkeleton />}>`** — `PhotoGrid` ke around boundary. Jab tak `await fetchPhotos()` complete na ho, `PhotoGridSkeleton` (gray boxes with `animate-pulse`) dikhta hai. Query complete → skeleton replace → real grid.

**Result:** `h1` + page structure turant dikhte hain. Gallery grid ka skeleton dikhta hai, phir 3 second baad real photos. User ko blank screen nahi — **progressive loading.**

## TEST — Streaming Khud Dekho

1. `fetchPhotos` mein `await new Promise((r) => setTimeout(r, 3000))` daal do (slow simulate).
2. Browser mein page reload karo — **`h1` "Photo Gallery" turant dikhega**, grid mein skeleton (gray pulsing boxes).
3. 3 second baad skeleton → real photos. **Page kabhi blank nahi** — turant kuch na kuch.

DevTools → Network pe dekhoge — HTML alag chunks mein aata hai (streaming). Yeh wahi cheez hai jo 7.7.6 mein Photo Gallery pe use hogi.

## Nutshell

Streaming with Suspense: page ke sections ko **alag-alag stream** karte hain — jo ready, pehle. `<Suspense fallback={...}>` ek boundary hai — andar ke async component ke await time fallback (skeleton) dikhata hai, ready hote hi real content. Slow section (3s query) ko Suspense mein wrap karo, baaki page turant render — **koi blank screen nahi.** `loading.tsx` = route-level (poora page), `<Suspense>` = section-level (granular).

## What It Is NOT

- **Suspense = "loader spinner" nahi.** Suspense is *mechanism* hai jo fallback dikhata hai jab tak data ready nahi. Fallback tum kuch bhi bana sakte ho — skeleton, spinner, ya kuch nahi.
- **Streaming = "server pe fast ho gaya" nahi.** Query abhi bhi 3 second leti hai. Streaming ka fayda UX hai — user ko blank screen ki jagah turant page + skeleton dikhta hai.
- **`loading.tsx` = "<Suspense> se same" nahi.** `loading.tsx` poore route ke liye automatic boundary hai. `<Suspense>` granular — page ke kisi ek section ke around. Slow section ho toh `<Suspense>` use karo.
- **"Suspense = async component hi chahiye" nahi.** Suspense tab useful jab andar slow async operation ho (DB query, slow API). Fast cheezon ko wrap karna bekaar — boundary overhead.
