Soch — Batch 6 ke end mein Task Board ban gaya tha: Prisma + Neon, real database, production-grade pattern. App kaam kar raha hai, data database mein hai, states sahi handle ho rahi hain. Par ab ek naya sawaal uthta hai — **kya app *fast* aur *smooth* hai?** Database sahi hai, par agar images load hone mein 5 second lagein, font aate waqt text hile, aur poora page data ke intezar mein blank rahe — toh user ko lagega "yeh app slow hai". Batch 6 ne data ka ghar theek kiya; Batch 7 mein **user ko dikhne wala experience** theek karenge — performance aur production concerns.

Roadmap ise "Optimization & Production Concerns" kehta hai. Aur ek baat clear kar doon shuru mein — **yeh SEO optimization nahi hai.** SEO (metadata, `generateMetadata`) humne Batch 2 mein cover kar liya tha. Batch 7 ki optimization **assets aur rendering ki** hai — images, fonts, loading experience, aur ek advanced routing pattern. Yehi production app ki asli feeling deta hai.

## Batch Ka Spine — "Manual → Better"

Roadmap ka core principle — **pehle purana tareeka feel karo, phir Next.js ka better solution.** Batch 7 mein yeh chaar baar chalta hai:

| Topic | Manual (pehle problem feel) | Better (Next.js solution) |
|---|---|---|
| Images | `<img>` — LCP slow, text shift hota hai, har size ke liye alag file | `next/image` — automatic optimization, srcset/sizes, responsive |
| Fonts | Google Fonts link / `@font-face` — text FOUC + shift | `next/font` — self-hosted, preload, koi layout shift nahi |
| Loading | Poora page data ke intezar mein blank | Streaming with Suspense — section-wise progressive load |
| Modal | Client state modal — URL pe nahi hota, refresh/back pe khatam | Parallel + Intercepting Routes — modal URL pe (Instagram pattern) |

Har topic mein pehle **problem feel karoge** (manual), phir **solution** (Next.js ka built-in). Yahi "why" clear karta hai, sirf "how" nahi.
