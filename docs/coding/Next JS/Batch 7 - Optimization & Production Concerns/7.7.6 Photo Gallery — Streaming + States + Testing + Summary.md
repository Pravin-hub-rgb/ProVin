## Step 1 — Streaming: Gallery Grid Progressive Load

**SOCH (7.5):** Home page grid ab `await prisma.photo.findMany()` karta hai — poore page (hero tak) query ke time rukta hai. Network delay (Neon + 6 remote images) pe user ko blank screen. **Streaming with Suspense** se fix — hero + page turant, grid skeleton + progressive.

**File:** `app/page.tsx`

**Concept (7.5 recap):** Slow logic alag async component mein nikalo, `<Suspense>` boundary se wrap karo, fallback = skeleton. Page synchronous ho jaata hai — turant render.

Ab step-by-step.

Pehla kaam — grid alag component — **`async function PhotoGrid()`** — slow logic (query) alag — page se nikal kar. `skeleton` ko test karne ke liye ek **simulated delay** add karo (`await new Promise(...)`) — asli network me bhi delay hota hai, par isse streaming ka fayda clearly dikhta hai:

**`async function PhotoGrid()`** — grid logic alag component mein (7.5 pattern) — query yahan. JSX wahi (7.7.4 wala grid).

Ab page component — **`export default function Home()`** — ab **async nahi** — synchronous. Koi `await` top level pe nahi — isliye poora page turant render ho sakta hai. **`<Suspense fallback={<PhotoGridSkeleton />}>`** — grid ke around boundary — query ke time skeleton dikhta hai:

```tsx
// app/page.tsx
import Image from "next/image";
import Link from "next/link";
import { Suspense } from "react";
import prisma from "@/lib/prisma";

async function PhotoGrid() {
  const photos = await prisma.photo.findMany();

  return (
    <div className="mt-6 grid grid-cols-3 gap-4">

        >
          <Image
            src={photo.src}
            alt={photo.alt}
            fill
            sizes="(max-width: 768px) 100vw, 33vw"
            className="rounded object-cover"
          />
          <p className="mt-1 text-sm font-medium">{photo.title}</p>
        </Link>
      ))}
    </div>
  );
}

function PhotoGridSkeleton() {
  return (
    <div className="mt-6 grid grid-cols-3 gap-4">
      {Array.from({ length: 6 }).map((_, i) => (
        <div key={i} className="h-40 animate-pulse rounded bg-zinc-200" />

  );
}

export default function Home() {
  return (
    <section>
      <h1 className="text-2xl font-bold">Photo Gallery</h1>
      <p className="text-zinc-600">A showcase of curated photography.</p>

      <Suspense fallback={<PhotoGridSkeleton />}>
        <PhotoGrid />
      </Suspense>
    </section>
  );
}
```

**`function PhotoGridSkeleton()`** — skeleton — 6 gray pulsing boxes (`animate-pulse`) — real grid ka same layout (`grid-cols-3 gap-4 h-40`). **`<Suspense fallback={<PhotoGridSkeleton />}>`** — boundary — query ke time skeleton, ready pe real photos. **`Home` ab sync** — hero `h1` + `<p>` turant render — streaming.

**States ka order (Next.js pipeline — 6.13.5 wala):**


## Nutshell

Streaming: grid ko alag async component + `<Suspense>` boundary + skeleton — hero turant, grid progressive. States: `not-found.tsx` (galat id), `error.tsx` (system error, reset), `loading.tsx` (query ke dauran). Pipeline: loading → page, error pe error.tsx, notFound pe not-found.tsx. Test table se sab verify. Batch output: har "manual" cheez (images, fonts, loading, routing) ka "better" Next.js solution — aur Photo Gallery project wo sab combine karta hai.

## What It Is NOT

- **Suspense + skeleton = "lazy loading ka naam change" nahi.** Lazy loading images defer karta hai (7.2). Streaming **poore page ke sections** ko alag-alag render/stream karta hai — slow query ka impact sirf us section pe. Skeleton iska visual feedback hai.
- **`not-found.tsx` = `error.tsx` ka copy nahi.** not-found = resource nahi (user galti, predictable — galat id). error = unexpected failure (recoverable — retry). Predictable cases notFound, unpredictable error.tsx.
- **`error.tsx` = "client component isliye kyunki lazy" nahi.** Reset button interactivity chahiye — isliye client. Boundary mechanism Next.js ka hai — file name + placement hi kaafi.
- **Test table = "sirf checklist" nahi.** Har row = ek behavior verify — expected vs actual. Especially modal tests (click vs direct) — yehi 7.6 pattern ka proof hai.
- **Batch 7 = "chaar packages seekh liya, bas" nahi.** next/image, next/font, Suspense, parallel/intercepting — sab ek pattern follow karte hain: **"manual cheez ko production-grade better cheez se badlo"**. Har Next.js app mein yehi optimization-first soch chahiye.
