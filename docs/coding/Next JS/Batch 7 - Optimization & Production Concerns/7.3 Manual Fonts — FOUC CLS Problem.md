Now another element on every website — **fonts.** And few think about it, but when you use a custom font (Google Fonts, or any nice typeface), that font is **downloaded over the network.** And that download creates two production problems: **FOUC** and **layout shift (CLS).** We saw CLS from images in 7.1; now we see it from fonts.

# Manual Fonts — The FOUC/CLS Problem

## THINK — What Happens When a Font Loads

A common setup — adding the Inter font from Google Fonts:

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600&display=swap" rel="stylesheet">
```

You drop those `<link>` tags in the HTML `<head>` — the CSS file comes from Google, which then points to the font files. Now think — the browser renders the page, but the font hasn't arrived yet (network delay). What font does the text display in?

**This is where the problem begins.** The browser has two choices:

1. **Block the text** (keep it invisible) until the font arrives — nothing shows for now
2. **Use a fallback font** (system font like Arial) — then swap to the custom font when it arrives

`display=swap` (in the link above) means **option 2** — show the fallback, then swap. But that "swap" is exactly what causes **layout shift** — Arial and Inter have different widths, so the text jumps.

## CONCEPT — Two Problems: FOUC and CLS

### Problem 1 — FOUC (Flash of Unstyled Text)

When the custom font is delayed downloading, the browser shows text in a fallback font — then when the custom font arrives, the text style changes abruptly. That "flash" is **FOUC — Flash of Unstyled Text.**

Scenario: the user is on a slow network, the font takes 2 seconds to load. The text shows in Arial for 2 seconds, then suddenly switches to Inter. Very noticeable — like a flicker.

`display=swap` mostly fixes this (fallback first, then swap). But with `display=block` (some sites use it) the text stays **invisible for the full 2 seconds** — worse. Swap is better than block, but swapping comes with its own problem.

### Problem 2 — Layout Shift (CLS) — From Font Swapping

When text swaps from fallback (Arial) to custom (Inter), the **widths differ** — "Breadcrumb" in Arial is narrow, in Inter it's wider (or vice versa). The text changes size → content below shifts → **CLS.**

And remember — CLS is a metric Google uses for ranking (that's the SEO angle, but for now we focus on UX). Text jumping mid-sentence is jarring.

### Problem 3 — Network Dependency

A Google Fonts `<link>` means — **you depend on Google's servers.** The font CSS + files come from Google's CDN. Even deployed to Vercel, the font request goes to Google. This is an external request — outside your control. If Google Fonts is down or slow (regional issues), your site's text depends on it. (Self-hosting fixes this — 7.4.)

### Problem 4 — Extra Requests (Performance)

Each font family + weight is a separate file. `wght@400;600` — that's 2 weights. Each weight is a file to download. Multiple fonts × multiple weights = many font files. In production, every file is a request — every request costs time.

## CODE — The Manual Approach in Practice

A simple example — adding a Google Font project-wide (in 7.4 we replace this with `next/font`):

**File:** `app/layout.tsx` — manual font setup

```tsx
// app/layout.tsx
export default function RootLayout({
  children,
}: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <head>
        <link rel="preconnect" href="https://fonts.googleapis.com" />
        <link rel="preconnect" href="https://fonts.gstatic.com" crossOrigin />
        <link
          href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600&display=swap"
          rel="stylesheet"
        />
      </head>
      <body>{children}</body>
    </html>
  );
}
```

**`<head>` with `<link>` tags** — Google Fonts CSS + font files. `crossOrigin` is needed because fonts are cross-origin requests. This is the approach you've used so far — and it has the four problems above.

## TEST — See FOUC/CLS Yourself

DevTools → **Network** tab → **Font** filter → refresh the page. You'll see `Inter` font files downloading (`Inter-Regular.woff2`, etc.) — **from Google's servers.** Now DevTools → **Performance** tab → Record → reload → look at the **Layout Shift** section — you'll see the shift as text swaps fonts.

One more test — **simulate "Slow 4G"** in the Network tab (throttling dropdown → Slow 4G) → refresh. Text shows in the fallback first, then suddenly switches to Inter. That flicker = FOUC, that shift = CLS.

## Nutshell

Manual font loading (Google Fonts `<link>`) has four problems: **FOUC** (text flashes from fallback to custom font), **layout shift** (fallback and custom font have different widths — CLS), **network dependency** (depends on Google's servers), and **extra requests** (each weight is a separate font file). ## What It Is NOT

- **`display=swap` is not a "complete fix."** It does prevent invisible text (shows fallback first), but the swap still causes layout shift — the width difference between fallback and custom font. You need swap + width-matching together (7.4).
- **Custom font is not "just for looks."** Font loading has direct performance and UX impact — flickering, shifting. In production, fonts must be optimized too.
- **Google Fonts link is not "free CDN, no risk."** It's an external dependency — network latency, regional issues, downtime risk. Self-hosting (7.4) puts it under your control.
