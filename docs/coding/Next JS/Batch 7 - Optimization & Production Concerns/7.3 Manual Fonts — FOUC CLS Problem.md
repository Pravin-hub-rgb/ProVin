# Manual Fonts — FOUC/CLS Problem

## SOCH — Font Aate Hue Kya Hota Hai

Ek aam kaam — Google Fonts se Inter font add karte hain:

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600&display=swap" rel="stylesheet">
```

Ye `<link>` tag HTML ke `<head>` mein daalte ho — CSS file Google se download hogi, jo font files ka URL deti hai. Ab socho — browser page render karta hai, par font abhi download nahi hua (network delay). Text kya font mein dikhega?

**Yahan problem shuru hoti hai.** Browser ke paas do options hain:
1. Font aane tak text ko **roko** (invisible) — abhi tak bhi kuch nahi dikhta
2. **Fallback font** se text dikhao (system font, jaise Arial) — phir custom font aate hi **swap** karo

`display=swap` (upar ke link mein) ka matlab hai **option 2** — fallback dikhao, phir swap karo. Aur yahi "swap" **layout shift** paida karta hai — kyunki Arial aur Inter ki widths alag hain, text hilta hai.

## CONCEPT — Do Problems: FOUC aur CLS

### Problem 1 — FOUC (Flash of Unstyled Text)

Jab custom font download mein delay hota hai, browser fallback font se text dikhata hai — phir custom font aate hi text ka style achanak badal jaata hai. Is "flash" ko kahte hain **FOUC — Flash of Unstyled Text.** 

Ek scenario: user ka network slow hai, font 2 second mein aata hai. Text pehle 2 second Arial mein dikhta hai, phir achanak Inter mein. Bahut noticeable — ek flicker jaisa.

`display=swap` ise kaafi solve karta hai (fallback pehle, phir swap). Par `display=block` ho toh (koi website aise use karti hai) text **2 second tak invisible** rehta hai — worse. Swap better hai, par swap ke saath shift problem aati hai.

### Problem 2 — Layout Shift (CLS) — Font Swap Se

Jab fallback (Arial) se custom (Inter) pe text swap hota hai, dono fonts ki **width alag hoti hai** — "Breadcrumb" Arial mein chhota, Inter mein bada (ya ulta). Text ka size badalta hai → neeche wala content shift ho jaata hai → **CLS.**

Aur CLS yaad rakho — Google ise user experience metric maanta hai. Zyada CLS = slow/annoying site feel. (7.1 mein bhi yeh aaya tha — same problem, alag source.)

### Problem 3 — Network Dependency

Google Fonts `<link>` ka matlab hai — **Google ke server pe depend karte ho.** Font CSS + files unke CDN se aati hain. Deploy Vercel pe ho toh bhi font request Google ko jaati hai. Ye ek extra external request hai — aapke control mein nahi. Agar Google Fonts down ya slow ho (region issue), toh aapki site ka text depend karta hai. (Production concern — self-hosting ise solve karta hai.)

### Problem 4 — Extra Requests (Performance)

Har font family + weight ek file hai. `wght@400;600` — 2 weights. Har weight ki file download. Multiple fonts × multiple weights = kai font files. Production mein har file ek request hai — har request time hai.

## CODE — Abhi Kya Kar Rahe Ho (Manual)

Ek simple example — project-wide Google Fonts add karna (7.4 mein isi ko `next/font` se badlenge):

**File:** `app/layout.tsx` — manual font setup

```tsx
// app/layout.tsx
import "./globals.css";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <head>
        <link rel="preconnect" href="https://fonts.googleapis.com" />
        <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
        <link
          href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600&display=swap"
          rel="stylesheet"
        />
      </head>
      <body>{children}</body>
    </html>
  );
}
```

**`<head>` mein `<link>` tags** — Google Fonts ki CSS + font files. **`crossorigin`** — fonts cross-origin request hain, iski zaroorat hai. Yahi approach hai jo abhi tak use ki hai — aur isme upar ki char problems hain.

## TEST — FOUC/CLS Khud Dekho

DevTools → **Network** tab → **Font** filter → page refresh karo. Dekhoge — `Inter` ki alag files download ho rahi hain (`Inter-Regular.woff2`, etc.) — **Google ke server se.** Ab DevTools → **Performance** tab → Record karke page reload karo → **Layout Shift** section mein score dekho — koi shift hai kya.

Ek aur test — **Network tab mein "Slow 4G" simulate** karo (No throttling dropdown → Slow 4G) → refresh. Text pehle fallback font mein dikhega, phir achanak Inter mein swap hoga. Wo flicker = FOUC, wo shift = CLS.

## Nutshell

Manual font loading (Google Fonts `<link>`) char problems deta hai: **FOUC** (text fallback se custom font pe flash karta hai), **layout shift** (fallback aur custom font ki widths alag — CLS), **network dependency** (Google ke server pe depend), aur **extra requests** (har weight ki alag font file). Next.js ka `next/font` inhe solve karta hai — agle file mein.

## What It Is NOT

- **`display=swap` = "complete solution" nahi.** Swap FOUC solve karta hai (fallback pehle dikhao), par shift paida karta hai — fallback vs custom font ki width difference se CLS aata hai. Dono ka combo — swap + width-match — chahiye (7.4 mein).
- **Custom font = "sirf looks ki cheez" nahi.** Font loading ka performance aur UX par seedha effect hai — shift aur flicker. Production mein fonts ko bhi optimize karte hain.
- **Google Fonts link = "free CDN, koi takleef nahi" nahi.** External dependency hai — network latency, region issues, down hone ka risk. Self-hosting (7.4) ise control mein laata hai.
