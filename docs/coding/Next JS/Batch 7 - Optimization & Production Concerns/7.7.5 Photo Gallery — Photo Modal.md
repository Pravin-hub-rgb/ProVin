# Photo Gallery — Part 5: Photo Modal (Parallel + Intercepting)

## SOCH — Kya Bana Rahe Hain

7.6 ka concept yaad karo — **Modal-in-Route pattern**. Do cheezein mil kar:

1. **Parallel Routes** — ek URL pe do independent screens — `@main` (grid) + `@modal` (modal slot)
2. **Intercepting Routes** — URL `/photo/1` pe navigate → modal dikhao, direct visit → full page

Ab Photo Gallery mein implement karte hain. Asli files:

```
app/
├── layout.tsx                    ← `modal` slot add (7.7.2 wala layout update)
├── page.tsx                      ← main grid (wahi)
├── photo/[id]/page.tsx           ← full detail page (7.7.4 ka — wahi rahega)
└── @modal/
    ├── default.tsx               ← koi modal nahi → null
    └── (.)photo/
        └── [id]/
            └── page.tsx          ← intercepted modal (naya — main kaam)
```

**Key insight:** `/photo/[id]/page.tsx` **badalne ki zaroorat nahi** — direct visit pe wahi full page. Naya `@modal` slot hi modal render karega jab user **grid se click** karega. Yahi interception hai.

## Step 1 — Layout: `modal` Slot Add Karo

**SOCH:** Parallel routes ke liye layout ko slot render karna hota hai — `{children}` (main) + `{modal}`. Root layout (7.7.2/7.7.4 wala) mein `modal` prop add karo.

**File:** `app/layout.tsx`

**Concept:** Layout ka signature badalega — `children` ke saath `modal` bhi. `RootLayout({ children, modal })` — Next.js parallel slot ko layout ke prop mein pass karta hai (folder `@modal` → prop `modal`). Render: main content + modal overlay.

**File:** `app/layout.tsx` — ab step-by-step.

Pehla kaam — signature — **`RootLayout({ children, modal })`** — do props — `children` (main page) + `modal` (`@modal` slot — parallel route). Types mein dono add:

```tsx
// app/layout.tsx
import Link from "next/link";
import { Inter } from "next/font/google";

const inter = Inter({ subsets: ["latin"], variable: "--font-inter" });

export default function RootLayout({
  children,
  modal,
}: Readonly<{
  children: React.ReactNode;
  modal: React.ReactNode;
}>) {
```

**`children` + `modal`** — do props — parallel slot `@modal` ko Next.js `modal` prop mein pass karta hai.

Ab render — **`{modal}`** — main ke baad render — modal overlay ko content ke **upar** dikhne deta hai (absolute/fixed positioning se):

```tsx
// app/layout.tsx
import Link from "next/link";
import { Inter } from "next/font/google";

const inter = Inter({ subsets: ["latin"], variable: "--font-inter" });

export default function RootLayout({
  children,
  modal,
}: Readonly<{
  children: React.ReactNode;
  modal: React.ReactNode;
}>) {
  return (
    <html lang="en" className={inter.variable}>
      <body>
        <header className="border-b p-4">
          <Link href="/" className="text-lg font-semibold">
            Photo Gallery
          </Link>
        </header>
        <main className="mx-auto max-w-4xl p-4">{children}</main>
        {modal}
      </body>
    </html>
  );
}
```

**`{modal}`** — `</main>` ke baad render — modal content overlay. Abhi `@modal` folder nahi hai — error nahi aayega, bas render nahi hoga.

## Step 2 — `@modal/default.tsx`: No Modal State

**SOCH (7.6):** Har slot ko `default.tsx` chahiye — tab jab slot ki matching route na ho. Normal navigation pe (koi modal nahi) — `@modal` mein kuch render nahi hona chahiye.

**File:** `app/@modal/default.tsx`

**Concept:** `default.tsx` — parallel route ka fallback — matching route nahi hai tab render. Modal na ho toh `null` — kuch nahi dikhta. (7.6 mein explain hua tha — bina `default.tsx` error.)

```tsx
// app/@modal/default.tsx
export default function ModalDefault() {
  return null;
}
```

**`return null`** — slot khali — normal navigation pe koi modal nahi. Yeh file mandatory hai — bina iske parallel route error dega.

## Step 3 — `@modal/(.)photo/[id]/page.tsx`: The Modal

**SOCH (7.6):** Yeh asli interception hai — `(.)photo/[id]` — jab user **page ke andar** `/photo/1` pe navigate karta hai (grid pe click), Next.js is file ko render karta hai — **modal**. Direct visit / refresh → `/photo/[id]` full page (7.7.4 wala).

**File:** `app/@modal/(.)photo/[id]/page.tsx` (folders `@modal/(.)photo/[id]` banao)

**Concept:** Modal content = photo detail (image + title + description) **overlay mein** — `fixed inset-0` (poore screen pe), `bg-black/70` (dark backdrop), content center mein. Photo data `getPhoto(id)` se — same query as full page (DRY? — abhi duplicate, niche note). Close button → Link to `/` (modal slot khali ho jaata hai).

**File:** `app/@modal/(.)photo/[id]/page.tsx` — ab step-by-step.

Pehla kaam — imports + data — **`Image`** (optimized, 7.7.4 wala), **`Link`** (close), **`prisma`** (photo fetch). **`getPhoto`** — wahi helper (7.7.3) — photo by id:

```tsx
// app/@modal/(.)photo/[id]/page.tsx
import Image from "next/image";
import Link from "next/link";
import prisma from "@/lib/prisma";

async function getPhoto(id: number) {
  return prisma.photo.findUnique({ where: { id } });
}

export default async function PhotoModal({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const photo = await getPhoto(Number(id));

  if (!photo) {
    return null;
  }

  return (
    <div className="fixed inset-0 z-50 flex items-center justify-center bg-black/70">
      <div className="relative w-full max-w-lg rounded-lg bg-white p-4 shadow-xl">
        <Link
          href="/"
          className="absolute right-3 top-3 rounded-full bg-zinc-200 px-2 text-zinc-600"
        >
          X
        </Link>

        <Image
          src={photo.src}
          alt={photo.alt}
          width={800}
          height={600}
          className="rounded object-cover"
        />
        <h2 className="mt-3 text-lg font-semibold">{photo.title}</h2>
        <p className="text-zinc-600">{photo.description}</p>
      </div>
    </div>
  );
}
```

**`if (!photo) return null`** — photo nahi mili toh modal hi mat dikhao (full page wala `notFound()` yahan nahi — modal mein 404 page chahiye nahi). **`fixed inset-0 z-50 bg-black/70`** — overlay — poore screen, dark backdrop, sabse upar (7.6 demo jaisa). **`Link href="/"`** — **close button** — `/` pe navigate → `@modal` slot khali → modal gayab (main grid wahi rehta hai). **`<Image width={800} height={600}>`** — modal ke andar dimensions pata hain (fixed modal size) — `fill` ki zaroorat nahi — `width`/`height` + CSS `object-cover`.

> **DRY note — `getPhoto` ab do files mein hai** (photo/[id] + modal). Abhi small project hai — duplicate acceptable. Production mein ise ek shared file (`lib/photos.ts`) mein nikalte — series prompt ka "data layer alag file" pattern. Iska hint 7.7.6 mein.

## Step 4 — TEST: Modal Behaviour

**TEST — 7.6 ke expected behaviours:**

1. **Grid se click:** `/` pe photo pe click → **modal khulta hai** (overlay, dark backdrop) — URL `/photo/1` ho jaata hai — **page reload nahi** (main grid wahi dikhta hai, uske upar modal).
2. **Back button:** Browser back → **modal close**, grid wapas (URL `/`).
3. **Direct visit:** `/photo/1` **naye tab mein** kholo → **full page** (7.7.4 wala — header + bada image + title) — modal nahi.
4. **Close button:** Modal mein X → grid wapas.
5. **Refresh modal URL:** Modal khula ho (`/photo/1`) aur refresh karo → **full page** (interception navigation pe hai, refresh = direct).

Yeh test hi 7.6 ke concept ka proof hai — **click = modal, direct/refresh = full page.**

## Step 5 — Modal SEO/Title (Bonus)

**SOCH:** Modal kholne pe browser tab ka title kya hota hai? Interception pe Next.js is route ka metadata nahi dhoondta (full page ka). Chhota tweak — modal page mein static metadata:

```tsx
// app/@modal/(.)photo/[id]/page.tsx
import type { Metadata } from "next";
import Image from "next/image";
import Link from "next/link";
import prisma from "@/lib/prisma";

export const metadata: Metadata = {
  title: "Photo Detail",
};

async function getPhoto(id: number) {
  return prisma.photo.findUnique({ where: { id } });
}
```

**`export const metadata`** — modal route ka static title (dynamic generateMetadata yahan skip — modal transitory hai). Full page ka dynamic title (7.7.3) wahi kaam karta hai direct visit pe. Note: tamam-asli SEO full page se hai — modal ek transition state hai.

## Nutshell

Photo Modal: root layout mein **`modal` slot prop** add (`{children}` + `{modal}`). `app/@modal/default.tsx` → `return null` (no modal state — mandatory). `app/@modal/(.)photo/[id]/page.tsx` → intercepted modal — grid se click pe render (fixed overlay, dark backdrop, photo + close Link), direct visit/refresh pe `photo/[id]` full page (wahi raha). Close = Link to `/`. `photo` missing → `return null` (modal mein 404 nahi). Back button → close. **Click = modal, direct = full page.**

## What It Is NOT

- **`@modal` folder = "URL path" nahi.** `@` prefix slot hai — URL mein nahi aata. Slot sirf layout ka render position hai (`{modal}`). Asli URL `/photo/1` hi hai — slot usse alag cheez hai.
- **Modal page = "naya route duplicating full page" nahi.** Dono `/photo/[id]` ke render variants hain — full page (direct) vs modal (intercepted). Data (getPhoto), image, title — same content, alag presentation.
- **`(.)photo` = "folder chhupana" nahi.** `(.)` = **intercept marker** — "is segment ko intercept karo jab navigation page ke andar se ho". URL se `(.)` hata diya jaata hai (folder name ka hissa nahi). Click vs direct ka distinction isi se aata hai.
- **`if (!photo) return null` = `notFound()` jaisa nahi.** Full page pe 404 dikhata hai (photo ka apna page hai). Modal mein 404 page awkward hota — isliye bas kuch render mat karo (slot khali). Alag context, alag handling.
- **Close button = "browser back" nahi.** Link to `/` pe navigate karta hai (modal slot khali). Browser back (step 4 test 2) bhi kaam karta hai — dono close karne ke tareeke, alag mechanism (Link vs history).
