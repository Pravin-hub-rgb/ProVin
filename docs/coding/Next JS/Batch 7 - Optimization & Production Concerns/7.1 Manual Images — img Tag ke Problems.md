# Manual Images — `<img>` ke Problems

## SOCH — Ek Photo Dikhana Kitna Mehnga Hai

Tumne app mein images aise use ki hain — ek `<img>` tag:

```html
<img src="/cat.jpg" alt="A cat" />
```

Bhai, yeh ek line hai. Browser isse kya karta hai? **Poori image file download hoti hai** — jitne MB ki hai, utne MB. Ek 2MB ki image agar mobile pe 3G pe load ho toh kya hoga? User page kholta hai, image aane mein 5 second lagte hain, beech mein kuch nahi dikhta. Phir wahi image tablet pe, laptop pe, 4K monitor pe — **har jagah wahi poori 2MB file.** Koi smartness nahi.

Issi file mein char asli problems dekhenge jo `<img>` ke saath production mein aati hain. Har ek ko samjho, kyunki agle file mein `next/image` inhe ek-ek karke solve karta hai.

## CONCEPT — `<img>` ki Char Problems

### Problem 1 — Koi Automatic Optimization Nahi

Jab tum `<img src="/cat.jpg">` likhte ho, browser **jo file hai wahi** download karta hai. Agar photographer ne 4000×3000 ki full-res image di hai (8MB), toh mobile pe jo screen 400px ki hai, wahan bhi **8MB download hogi.** Browser ki koi dimaag nahi — "mere screen pe 400px chahiye, toh 400px wali le lo." Nahi, poori le leta hai.

Is problem ka naam hai **file size / bandwidth.** Aise hi har image pe 8MB download karo, toh page 50MB ka ho jaata hai. Aur web pe file size ka seedha matlab **speed** hai.

### Problem 2 — Layout Shift (CLS)

Yeh sabse annoying problem hai jo aapne zaroor dekhi hogi. Kholo koi news website, scroll karo — **text halke se hilta hai** jab image load hoti hai. Kya ho raha hai?

HTML mein `<img src="/cat.jpg">` — browser ko **pata hi nahi image kitni badi hai** (width × height). Jab tak file download na ho, usse ek jagah nahi milti. Toh browser page render karta hai bina image ke, phir image aate hi **poora layout neeche push** ho jaata hai. Iska naam hai **CLS — Cumulative Layout Shift.** Google ise ek ranking factor maanta hai (poora SEO angle, par abhi hum sirf UX pe focus karein). User ko text ke beech achanak shift bahut annoying lagta hai.

Ise solve karna hota hai `width` + `height` attributes (ya CSS aspect-ratio) — par manually har image pe likhna, aur jisse pata chale proper dimensions. Phir bhi responsive images ke saath tricky.

### Problem 3 — Koi srcset/sizes Nahi

Ek hi image, alag-alag screens — phone (small), tablet (medium), desktop (large). Proper solution: browser ko **alag-alag sizes ki images do** (800px, 1600px, 3200px) aur wo apni screen ke hisaab se sahi wali chune. Iska naam hai **srcset** — HTML ka built-in feature.

```html
<img
  src="/cat.jpg"
  srcset="/cat-800.jpg 800w, /cat-1600.jpg 1600w, /cat-3200.jpg 3200w"
  sizes="(max-width: 600px) 400px, 1600px"
  alt="A cat"
/>
```

Par yahan problem yeh hai — **images alag-alag sizes ki banani padti hain.** `/cat-800.jpg`, `/cat-1600.jpg`, `/cat-3200.jpg` — tum khud generate karo, khud naye file names do, khud URL banao. Photo 10 hai toh 30 files. Yeh manually maintain karna bahut tedious hai.

### Problem 4 — `loading="lazy"` ki Limits

Performance ke liye ek simple cheez karte hain — **lazy loading.** Image tab load karo jab user uske paas scroll kare, pehle nahi:

```html
<img src="/cat.jpg" loading="lazy" alt="A cat" />
```

Yeh built-in HTML hai aur kaam bhi karta hai. Par ek problem — browser lazy load karne ke liye image ki jagah jaan na chahiye, aur jis problem se humein bataye ho... shuru se hi `<img>` mein dimensions ki problem hai. Lazy loading tabhi acha hota hai jab dimensions known ho. Aur zyada important — **agar width/height nahi diye toh lazy-loaded images layout shift aur bhi badhate hain.**

Aur kuch edge cases bhi hain — `loading="lazy"` sirf browser ke viewport ke paas wali cheez focus karta hai, par complex layouts mein browser ko pata hi nahi hota. Manual approach ki limits hain.

## CODE — Abhi Jo Approach Hai, Usme Kya Hota Hai

Chhota sa example — ek photo grid jo abhi `<img>` se ban raha hai (7.7.2 mein yahi banayenge, par simple version):

> **Images files:** `public/photos/` mein `cat.jpg`, `dog.jpg`, `bird.jpg` chahiye (setup ke liye 7.2 ka **Step 0** dekho — wahan download + dimensions ka tarika hai).

```tsx
// app/gallery/page.tsx
const photos = [
  { id: 1, src: "/photos/cat.jpg", alt: "Cat sleeping" },
  { id: 2, src: "/photos/dog.jpg", alt: "Dog running" },
  { id: 3, src: "/photos/bird.jpg", alt: "Bird flying" },
];

export default function GalleryPage() {
  return (
    <div className="grid grid-cols-3 gap-4">
      {photos.map((photo) => (
        <img
          key={photo.id}
          src={photo.src}
          alt={photo.alt}
          className="h-40 w-full object-cover"
        />
      ))}
    </div>
  );
}
```

Dekho — `className="h-40 w-full object-cover"` se **CSS ke through** size fixed hai, par `<img>` ko `width`/`height` attributes nahi diye. Iska matlab browser ko dimensions nahi pata jab tak file na aaye — **layout shift.** Aur har photo poori file download — optimization nahi.

## Nutshell

`<img>` tag production mein char problems deta hai: **koi automatic optimization nahi** (har screen pe poori file download), **layout shift (CLS)** (dimensions pata na hone se text hilti hai), **srcset/sizes manually maintain karna padta hai** (har size ki alag file), aur **`loading="lazy"` ki limits** (dimensions ke bina lazy bhi shift badhata hai). Next.js ka `next/image` inhe solve karta hai — agle file mein.

## What It Is NOT

- **`<img>` = "galat tag" nahi.** HTML ka valid tag hai, aur chhoti/static images ke liye chal jaata hai. Par production apps mein images scale hoti hain — wahan manual approach maintain karna mushkil ho jaata hai. Next.js better solution deta hai isliye use karte hain.
- **`loading="lazy"` = "complete solution" nahi.** Ye basic lazy loading hai, par dimensions ke bina yeh layout shift solve nahi karta aur complex cases mein browser ko pata nahi hota. Next.js ka `next/image` lazy + dimensions dono handle karta hai.
- **Image optimization = "CSS se chhoti kar dena" nahi.** CSS se image *dikhe* chhoti hoti hai, par download poori file hoti hai. Asli optimization **server pe alag size ki file generate** karta hai — jo browser download kare wo chhoti ho.
- **srcset = "manual solution ka option" nahi jo abhi use karo.** Haan, HTML mein built-in hai, par har size ki alag file banani padti hai. `next/image` yeh automatically generate karta hai.
