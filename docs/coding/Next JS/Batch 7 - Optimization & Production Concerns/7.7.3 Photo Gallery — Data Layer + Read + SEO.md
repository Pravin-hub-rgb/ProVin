  params: Promise<{ id: string }>;

### SEO — `generateMetadata`

**Concept (planning, Question 4):** The Photo Gallery reinforces **SEO** — 2.4's Metadata API applied here. The photo detail page's title + description should be dynamic for search engines + social sharing — each photo gets its own title.

**File:** `app/photo/[id]/page.tsx` — add `generateMetadata`

**Concept:** `generateMetadata` — Next.js's function that builds **dynamic metadata** from `params`. Search engines read this before rendering the page — title/description become page-specific. (In 2.4 it was static metadata — `export const metadata`; here it's dynamic — `generateMetadata` — dependent on params.) If the photo isn't found → `notFound()`; but metadata needs a fallback too:

```tsx
// app/photo/[id]/page.tsx
import type { Metadata } from "next";
import Link from "next/link";
import { notFound } from "next/navigation";
import prisma from "@/lib/prisma";

async function getPhoto(id: number) {
  return prisma.photo.findUnique({ where: { id } });
}

export async function generateMetadata({
  params,
}: {
  params: Promise<{ id: string }>;
}): Promise<Metadata> {
  const { id } = await params;
  const photo = await getPhoto(Number(id));

  if (!photo) {
    return { title: "Photo Not Found" };
  }

  return {
    title: photo.title,
    description: photo.description ?? photo.alt,
  };
}

export default async function PhotoPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const photo = await getPhoto(Number(id));

  if (!photo) {
    notFound();
  }

  return (
    <section>
      <Link href="/" className="text-sm text-zinc-500">
        &larr; Back to gallery
      </Link>

      <img
        src={photo.src}
        alt={photo.alt}
        className="mt-4 w-full rounded-lg"
      />
      <h1 className="mt-4 text-2xl font-bold">{photo.title}</h1>
      <p className="mt-1 text-zinc-600">{photo.description}</p>
    </section>
  );
}
```

**`async function getPhoto(id)`** — a shared helper — both `generateMetadata` and the page need the photo, so one function avoids duplicating the query (DRY). **`generateMetadata`** — dynamic metadata — `title: photo.title` (each photo's own title), `description: photo.description ?? photo.alt` (fall back to `alt` if no description). **If the photo doesn't exist** — `return { title: "Photo Not Found" }` — a safe fallback (you can't call `notFound()` inside `generateMetadata`).

## What It Is NOT

- **A single `Photo` model is not "missing relations."** Relations exist when things are connected. A photo stands on its own here — no user or album. The focus is optimization + routing, not relations (6.12/6.13 covered that). Simple model = focused project.
- **`findUnique` is not the same as `findMany`.** `findMany` returns a list (the whole grid); `findUnique` returns a single record by primary key (one photo's detail). Different query, different use.
- **`findUnique` returning `null` is not an error.** When no photo matches the id, `findUnique` returns `null` (not an exception) — that's why `if (!photo) notFound()` checks for it.
- **Seed scripts are not "production data."** Seeds create development/test data. In production, data comes from an admin panel or import — not a seed script that runs once.
- **`generateMetadata` is not "static metadata."** Static `export const metadata` is the same for every page. `generateMetadata` is **dynamic** — it reads `params`, fetches the photo, and returns photo-specific title/description. Each photo gets its own SEO metadata.
