# next/font — No Layout Shift

## THINK — What "Better" Means for Fonts

Recall the problems from 7.3:

1. **FOUC** — text flashes from fallback to custom font
2. **Layout shift** — fallback and custom font widths differ → CLS
3. **Network dependency** — depends on Google's servers
4. **Extra requests** — each weight is a separate font file

What if there were a tool that: **self-hosts** the font (no external request), **preloads** it, and **adjusts the fallback** so swapping causes no layout shift? That's `next/font` — Next.js's built-in font system.

## CONCEPT — What `next/font` Does

`next/font` does things the manual approach can't:

- **Self-hosted fonts** — downloads the font from Google and **bundles it with your app.** No external request, no Google CDN dependency. Fonts travel with your deployment.
- **Automatic font optimization** — Next.js downloads font files at build time, optimizes them, and **preloads** them. The font request comes from your own server — fast.
- **`adjustFontFallback`** — this is the real magic. It **adjusts the fallback font's size** to match the custom font's aspect ratio — swapping causes **no layout shift.** CLS = 0.
- **CSS variables** — exposes the font as a CSS variable (`--font-inter`) so you can use it anywhere in your components.

One line: **`next/font` downloads + self-hosts + preloads the font at build time, and adjusts the fallback so there's zero layout shift.**

## CODE — Using `next/font/google` for Inter

Replacing the 7.3 layout with `next/font`:

**File:** `app/layout.tsx`

**Concept:** 7.4's pattern — import `Inter` from `next/font/google`, use `subsets: ["latin"]` (only English characters — smaller file), `variable: "--font-inter"` (expose as CSS variable), then apply on `<html>`. Then use `font-family: var(--font-inter)` in CSS.

**File:** `app/layout.tsx` — step by step.

First, import + configure Inter — **`import { Inter } from "next/font/google"`** — Inter from Next.js's Google Fonts collection (7.4). **`const inter = Inter({ subsets: ["latin"], variable: "--font-inter" })`** — latin subset (smaller file) + expose as CSS variable:

```tsx
// app/layout.tsx
import { Inter } from "next/font/google";
import "./globals.css";

const inter = Inter({ subsets: ["latin"], variable: "--font-inter" });
```

**`import { Inter } from "next/font/google"`** — Inter (same pattern as 7.4). **`const inter = Inter({ subsets: ["latin"], variable: "--font-inter" })`** — latin subset (smaller file) + expose as CSS variable.

Now apply on `<html>` — **`<html lang="en" className={inter.variable}>`** — the CSS variable is available app-wide (same pattern as 7.4):

```tsx
// app/layout.tsx
import { Inter } from "next/font/google";
import "./globals.css";

const inter = Inter({ subsets: ["latin"], variable: "--font-inter" });

export default function RootLayout({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return (
    <html lang="en" className={inter.variable}>
      <body>{children}</body>
    </html>
  );
}
```

**`<html className={inter.variable}>`** — the variable is available across all pages. Then apply it in CSS:

**File:** `app/globals.css`

```css
/* app/globals.css */
body {
  font-family: var(--font-inter), Arial, sans-serif;
}
```

**`font-family: var(--font-inter)`** — the self-hosted Inter. **`, Arial, sans-serif`** — fallback (already adjusted by `next/font` — no shift, 7.4).

### Why CSS Variables?

`variable: "--font-inter"` means the font class goes on the `<html>` element, and the CSS variable can be used anywhere. This is a good pattern because:

- Font family as a CSS variable — change in one place, everywhere updates
- Works with Tailwind too (`font-family: var(--font-inter)`)
- Easy to manage multiple fonts — `--font-heading`, `--font-body`

### `next/font/local` — Your Own Font Files

If you're not using Google Fonts but have your own `.woff2` files:

```ts
// app/layout.tsx
import localFont from "next/font/local";

const myFont = localFont({ src: "./fonts/MyFont.woff2" });
```

**`next/font/local`** — for your own font files. For the Photo Gallery project, Google Fonts (Inter) is enough — this is just to know it exists.

## Nutshell

`next/font` solves all four manual font problems from 7.3: **self-hosted** (downloads from Google, bundles with your app — no CDN dependency), **preloaded** (served from your own server, fast), and **`adjustFontFallback`** (adjusts fallback to match — zero layout shift). `next/font/google` for Google Fonts like Inter, `next/font/local` for your own files. Use `variable: "--font-inter"` on `<html>` and `font-family: var(--font-inter)` in CSS.

## What It Is NOT

- **`next/font` is not a "Google Fonts shortcut."** It **self-hosts** the font — downloaded and bundled at build time. It's not just swapping one `<link>` for another.
- **`adjustFontFallback` is not "just setting Arial."** It dynamically adjusts the fallback font's metrics to match the custom font — so swapping causes no shift. Manual `font-family: Inter, Arial` doesn't do this automatically.
- **`subsets: ["latin"]` is not optional.** It bundles only the characters you need — smaller font file, faster load. A wrong subset = missing characters.
- **Self-hosted is not "slower than CDN."** Your server serves the font — controlled, no external latency. External CDNs can actually be slower (region/latency issues) and are outside your control.

1. What does it mean for `next/font` to "self-host" a font — and how does that remove the network dependency?

<details>
<summary>Show Answer</summary>

**Sample Answer:** At build time, Next.js downloads the font from Google and bundles it into your app. At production, the font is served from **your own server** — there's no request to Google's CDN. Even if Google Fonts is down or slow, your font still loads. The external dependency is eliminated.

</details>

2. How does `adjustFontFallback` prevent layout shift?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Layout shift on font swap happens because the fallback font (Arial) and the custom font (Inter) have different character widths. `adjustFontFallback` dynamically adjusts the fallback font's metrics to match the custom font — so when swapping occurs, the text size stays consistent and there's **no CLS.**

</details>

3. What is the role of `variable: "--font-inter"`, and why set it on `<html>`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `variable` exposes the font as a CSS variable (`--font-inter`). Setting the class on `<html>` makes the variable available across the entire app — use `font-family: var(--font-inter)` anywhere in CSS. Change it once, it applies everywhere.

</details>

4. Why is `subsets: ["latin"]` important?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Font files are large because they include glyphs for many languages. `subsets: ["latin"]` bundles only the Latin (English) characters — a much smaller file. If you need Devanagari or other scripts, specify the appropriate subset.

</details>
