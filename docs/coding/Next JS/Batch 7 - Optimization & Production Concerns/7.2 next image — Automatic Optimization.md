# next/image — Automatic Image Optimization

## SOCH — "Better" Ka Matlab Kya Hota Hai

7.1 ki problem list yaad karo:

1. **Koi optimization nahi** — har screen pe poori file download
2. **Layout shift (CLS)** — dimensions pata na hone se text hilti hai
3. **srcset manually** — har size ki alag file banani padti hai
4. **Lazy ki limits** — dimensions ke bina lazy bhi shift badhata hai

Ab kya hota agar ek **component** aisa ho jo: image ko automatic optimize kare, dimensions khud manage kare, responsive versions khud generate kare, aur lazy loading bhi khud handle kare? That's exactly `next/image` — ek `Image` component jo `next/image` se import hota hai. Tum `<img>` ki jagah `<Image>` likho, baaki Next.js sab karega.

## CONCEPT — `next/image` Kaise Kaam Karta Hai

`next/image` sirf ek "bada `<img>`" nahi hai. Isme kuch asli machinery chalti hai — yeh jo kar raha hai wo **Image Optimization API** hai:

- **Request-time optimization** — jab browser kisi image ke liye request karta hai, Next.js server pe us image ka optimized version banata hai (screen ke hisaab se width, modern format jaise WebP/AVIF). Client ko jo milta hai wo **chhoti, optimized file** hai — koi bhari original file nahi.
- **srcset automatic** — Next.js khud multiple sizes generate karta hai aur `srcset` attribute mein daal deta hai. Tumhe alag-alag files banani nahi padti.
- **Layout shift control** — `width`/`height` ya `fill` se browser ko dimensions pehle se pata rehti hain. No CLS.
- **Lazy loading default** — `Image` default `loading="lazy"` hai (viewport ke paas aane pe load), aur dimensions known hone ki wajah se shift bhi nahi hota.
- **Priority** — jo image page pe sabse upar hai (LCP image), usme `priority` prop se preload.

Ek line mein — **`next/image` server pe optimized image banata hai, sahi sizes ka srcset deta hai, aur client pe shift-free + lazy load karta hai.**

## Step 0 — Images Kahan Se (Download + Dimensions)

Upar wale examples `/photos/cat.jpg`, `/photos/dog.jpg`, `/photos/bird.jpg` use karte hain — yeh files tumhe **khud add karni hain.** `public/photos/` folder banao (public folder pehle se hai) aur 3 **landscape** images wahan daalo. Sabse easy source — **picsum.photos** (placeholder image service) — URL ke andar size daal sakte ho:

```
https://picsum.photos/seed/cat/800/600   → save as public/photos/cat.jpg
https://picsum.photos/seed/dog/800/600   → save as public/photos/dog.jpg
https://picsum.photos/seed/bird/800/600  → save as public/photos/bird.jpg
```

`seed/cat` — wahi seed word dobara daalo toh **wahi image** milti hai (har baar change nahi hoti). Browser mein URL kholo → image aayegi → right-click → "Save image as..." → `public/photos/` mein cat/dog/bird.jpg naam se save karo.

**Dimensions kahan se?** URL ka `800/600` = image ka **asli size**. Isliye neeche array mein `width: 800, height: 600` **guess nahi, exact value hai.** (Khud ki koi aur image ho toh Windows mein right-click → Properties → Details se asli width/height dekh ke array update karna.) `width`/`height` image ke **actual aspect ratio** se match hone chahiye — galat value pe `next/image` warning deta hai aur browser galat jagah reserve karta hai (CLS).

## CODE — Pehla Step: `<img>` → `<Image>`

7.1 wali gallery lo, aur `<img>` ko `<Image>` se badlo:

**File:** `app/gallery/page.tsx` — naya import + component

```tsx
// app/gallery/page.tsx
import Image from "next/image";

const photos = [
  { id: 1, src: "/photos/cat.jpg", alt: "Cat sleeping", width: 800, height: 600 },
  { id: 2, src: "/photos/dog.jpg", alt: "Dog running", width: 800, height: 600 },
  { id: 3, src: "/photos/bird.jpg", alt: "Bird flying", width: 800, height: 600 },
];

export default function GalleryPage() {
  return (
    <div className="grid grid-cols-3 gap-4">
      {photos.map((photo) => (
        <Image
          key={photo.id}
          src={photo.src}
          alt={photo.alt}
          width={photo.width}
          height={photo.height}
          className="h-40 w-full object-cover"
        />
      ))}
    </div>
  );
}
```

**`import Image from "next/image"`** — Next.js ka built-in component. **`width` + `height`** — ab **zaroori** hain (ya `fill` — neeche). Kyun? Browser ko dimensions pehle se chahiye taaki layout shift na ho — 7.1 ki Problem 2 ka solution. `className` wahi raha — styling CSS se.

> **Important — pehla run pe error aayega:** "Image with src /photos/cat.jpg has either width or height modified, but not the other..." ya "width/height not specified". Yeh by design hai — Next.js **tumhe shift-free banane pe force karta hai.** Fix: ya `width`/`height` do, ya `fill` use karo.

### Local vs Remote Images — `fill` aur remotePatterns

Ab upar wale example mein images `/public` folder mein hain (local). Dono case ke liye alag approach:

**1. Local images (public folder):**

```tsx
<Image
  src="/photos/cat.jpg"
  alt="Cat sleeping"
  width={800}
  height={600}
/>
```

**2. Remote images (URL se, jaise Unsplash):** Yahan Next.js ko batana padta hai ki kaunse domains se images allow karni hain — **security feature.** `next.config.ts` mein:

```ts
// next.config.ts
const nextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: "https",
        hostname: "images.unsplash.com",
      },
    ],
  },
};

export default nextConfig;
```

**`remotePatterns`** — ek allowlist — Next.js sirf isi domain se image fetch + optimize karega. Koi bhi random domain nahi. (7.7.4 mein Photo Gallery ke liye yahi use karenge.)

**3. `fill` — jab width/height nahi pata:**

```tsx
<div className="relative h-40 w-full">
  <Image
    src="/photos/cat.jpg"
    alt="Cat sleeping"
    fill
    className="object-cover"
  />
</div>
```

**`fill`** — image ko parent container ko bharne ke liye stretch karta hai. Parent pe `relative` chahiye. Dimensions tumhare paas nahi, par container ka size pata hai — isse bhi CLS nahi aata (container fixed hai). `object-cover` se crop hota hai.

## TEST — Before/After Compare (Asli Size Difference)

Yeh wahi test hai jo 7.7.4 mein Photo Gallery pe hoga, par abhi concept pehle — DevTools se:

1. **Pehle (7.1 wala `<img>`):** Network tab → Img filter → kisi image pe click → **Size** column → full file (say 800KB).
2. **Ab (`<Image>`):** Naya `<Image>` wala page — wahi image → Next.js ka optimized version (say 40KB WebP). **~95% chhoti file.**

Aur Dimensions check karo — `<img>` ke saath `width`/`height` attributes browser ke rendered DOM mein honge (Next.js khud add karta hai) — koi layout shift nahi. Performance tab → CLS score → 0 ke kareeb.

## Compare Table (LAST — pehle concept clear, phir compare)

| Cheez | `<img>` (manual) | `next/image` |
|---|---|---|
| Optimization | Koi nahi — original file | Automatic — server pe optimized (WebP/AVIF, size ke hisaab se) |
| srcset | Khud banani padti hai (alag files) | Automatic — khud generate |
| Layout shift | Dimensions na ho toh shift | `width`/`height` ya `fill` se koi shift nahi |
| Lazy loading | Manual `loading="lazy"` (limits) | Default lazy + shift-safe |
| LCP image | Khud `preload` nahi | `priority` prop se preload |
| Remote images | Direct URL | `remotePatterns` allowlist — security |

## Nutshell

`next/image` (`Image` component) 7.1 ki saari `<img>` problems solve karta hai: **server pe automatic optimization** (screen ke hisaab se chhoti WebP/AVIF file), **automatic srcset** (khud multiple sizes), **`width`/`height` ya `fill` se koi layout shift nahi**, aur **default lazy loading** shift-safe. Remote images ke liye `remotePatterns` allowlist chahiye. `<img>` manual, `next/image` better — roadmap ka pattern.

## What It Is NOT

- **`next/image` = "sirf ek wrapper component" nahi.** Isme real machinery hai — server pe optimization, image pipeline. Sirf `<img>` ko rename karne jaisa nahi hai.
- **`next/image` = "CSS se chhoti image" nahi.** CSS sirf dikhane ka size badalta hai. `next/image` actual download ki file ko optimize karta hai.
- **`width`/`height` = "hardcoded size" nahi.** Yeh layout ke liye hai (aspect ratio browser ko batane ke liye) — CSS se ise override kar sakte ho (`w-full`, `h-40`). Ye style nahi, reservation hai.
- **`fill` = "bina dimensions ke default" nahi.** `fill` ka matlab hai parent ko bharo — parent pe `relative` zaroori hai. Dimensions ki jagah container size dete ho.
- **`remotePatterns` = "kisi bhi URL ko allow karna" nahi.** Ye security allowlist hai — sirf listed domains optimize honge. Random external images pe error aayega jab tak config mein na ho.
