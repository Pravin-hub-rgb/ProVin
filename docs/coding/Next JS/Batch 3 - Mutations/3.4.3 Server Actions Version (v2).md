## Step 1: Server Actions

Ab sabse important part — **form submit kaise hoga?** Version 1 mein `axios` se call karte the. Ab sirf function call hoga.

**File:** `app/actions.ts`

Pehle `addReview` action banate hain:

```tsx
"use server";

import { addReview, updateReview, deleteReview } from "@/lib/reviews";
import { revalidatePath } from "next/cache";

export type FormState = {
  success: boolean;
  message: string;
};

export async function addReviewAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const text = formData.get("text") as string;
  const rating = Number(formData.get("rating"));
  const productId = Number(formData.get("productId"));

  // Validation
  if (!text) {
    return { success: false, message: "Review text zaroori hai!" };
  }

  if (!rating || rating < 1 || rating > 5) {
    return { success: false, message: "Rating 1 se 5 honi chahiye!" };
  }

  addReview({ productId, text, rating });
  revalidatePath("/reviews");

  return { success: true, message: "Review add ho gaya!" };
}
```

Dekho kya hai — ye **3.1 ke Route Handler jaisa hai**, par fark hai:
- **Route Handler mein:** `request.json()` se data aata hai, `NextResponse.json()` se response jaata hai
- **Server Action mein:** `formData.get("text")` se data aata hai, return value se response jaata hai

**Notice kiya?** Koi `axios`/`fetch()` nahi, koi `NextResponse` nahi — sirf function hai jo data leta hai aur return karta hai. Bilkul normal function jaisa.

Ab `deleteReview` action bhi add karte hain — same file mein:

```tsx
export async function deleteReviewAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const id = Number(formData.get("id"));

  const deleted = deleteReview(id);

  if (!deleted) {
    return { success: false, message: "Review nahi mila!" };
  }

  revalidatePath("/reviews");
  return { success: true, message: "Review delete ho gaya!" };
}

export async function updateReviewAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const id = Number(formData.get("id"));
  const text = (formData.get("text") as string) || "";
  const rating = Number(formData.get("rating"));

  if (!text) {
    return { success: false, message: "Review text zaroori hai!" };
  }

  const updated = updateReview(id, { text, rating });

  if (!updated) {
    return { success: false, message: "Review nahi mila!" };
  }

  revalidatePath(`/reviews/${id}`);
  revalidatePath("/reviews");
  return { success: true, message: "Review update ho gaya!" };
}
```

**Dekho — ye bhi same pattern hai.** FormData se `id` nikalo, function call karo, result return karo. Koi `route.ts` file nahi, koi HTTP method nahi — sirf functions.

**`revalidatePath("/reviews")` kya kar raha hai?** 3.3.2 mein seekha tha — ye Next.js ko bolta hai ki "/reviews" page ka data purana ho gaya hai, dobara render karo. Isliye naya review dikh jaata hai bina page reload ke.

**Return type `FormState` kyun hai?** `useActionState` ko pata hona chahiye ki response kaisa hoga — `success` boolean hai ya nahi, `message` kya hai. Isliye type define kiya hai.

> **⚠️ `useFormState` deprecated hai.** Purani React versions mein `useFormState` (`react-dom` se) use hota tha. React 19 se uska naam badal kar **`useActionState`** (`react` se) ho gaya, aur isme `isPending` bhi extra mila. Is batch mein hum hamesha **`useActionState`** hi use karenge — aage koi code `useFormState` se mat likhna, warna deprecation error milega.

## Step 3: Client Components - Form + Delete Button

Ab form banate hain — par **Version 1 se comparison karte jao.**

### Pehle Samjho: Hidden Input Kya Hai?

Form mein data bhejne ke liye `input` fields hote hain — user unmein type karta hai. Par kabhi kabhi **user ko dikhaye bina** data bhejna hota hai — jaise `productId` ya `reviewId`. Iske liye **hidden input** use hota hai:

```tsx
<input type="hidden" name="productId" value={productId} />
```

**`type="hidden"` kya karta hai?** User ko ye input **dikhta nahi** — par form submit hone pe ye **data mein include hota hai.** Jaise ek invisible field jo form ke saath jaata hai.

**`name="productId"` kyun zaroori hai?** Server Action mein `formData.get("productId")` se ye value milti hai. **`name` attribute aur `formData.get()` ka naam same hona chahiye:**

```tsx
// Client side — form mein
<input type="hidden" name="productId" value={1} />

// Server side — Server Action mein
const productId = formData.get("productId");  // 1 mila
```

Chal ab form banate hain — pehle sirf text input, phir rating add karo, phir hidden input.

**File:** `app/components/ReviewForm.tsx`

#### Pehle Sirf Text + Submit

```tsx
"use client";

import { useEffect, useActionState } from "react";
import { toast } from "sonner";
import { addReviewAction, FormState } from "../actions";

const initialState: FormState = {
  success: false,
  message: "",
};

export function ReviewForm({ productId }: { productId: number }) {
  const [state, formAction, isPending] = useActionState(
    addReviewAction,
    initialState
  );

  useEffect(() => {
    if (state.message) {
      if (state.success) toast.success(state.message);
      else toast.error(state.message);
    }
  }, [state]);

  return (
    <form action={formAction} className="space-y-2 border p-4 rounded">
      <h3 className="font-bold">Naya Review Likho</h3>

      <input type="hidden" name="productId" value={productId} />

      <textarea
        name="text"
        placeholder="Apna review likho..."
        className="w-full border p-2 rounded"
        rows={3}
      />

      <button
        type="submit"
        disabled={isPending}
        className="bg-blue-500 text-white px-4 py-2 rounded disabled:bg-gray-400"
      >
        {isPending ? "Adding..." : "Submit Review"}
      </button>
    </form>
  );
}
```

Dekho kya hai — Version 1 ke comparison mein:

| Version 1 | Version 2 | Kya badla |
|---|---|---|
| `onSubmit={handleSubmit}` | `action={formAction}` | `useActionState` se action milta hai |
| `useState` for pending | `isPending` from `useActionState` | Built-in — manually nahi banana padta |
| `useState` for message | `toast.success/error` | Server Action return se message, sonner toast se display (3.3.1 wala pattern) |
| `axios.post()` — auto JSON | Sirf `action` attribute | Boilerplate khatam |

**Notice kiya?** Version 1 mein **3 useState** the (text, pending, message). Version 2 mein **zero** — `useActionState` hi state (`state`), action (`formAction`) aur loading (`isPending`) — teeno deta hai. Toast ke liye bas ek cheez check karo: layout mein `<Toaster />` laga ho (3.3.1 mein kiya tha). Nahi to `bun add sonner` + layout mein `<Toaster />` add karo.

#### Ab Rating Add Karo

Ab rating select add karte hain — `defaultValue` use karo (controlled nahi):

```tsx
// ReviewForm mein add karo — textarea ke pehle:

<div>
  <label>Rating:</label>
  <select name="rating" defaultValue={5} className="border p-1 rounded ml-2">
    {[1, 2, 3, 4, 5].map((n) => (
      <option key={n} value={n}>
        {"⭐".repeat(n)}
      </option>

```

**`defaultValue={5}` kyun, `value` kyun nahi?** Version 1 mein `value={rating}` + `onChange` use kiya tha — ye **controlled component** hai. Version 2 mein `defaultValue` use karte hain — ye **uncontrolled** hai, form data mein sirf name aur value chahiye. React ko manage nahi karna.

**Notice kiya?** Version 2 mein `useState("rating")` ki zaroorat nahi — form khud manage karta hai.

#### Delete Button Bhi Same Pattern Hai

Delete ke liye alag component hai — par pattern same hai:

**File:** `app/components/DeleteButton.tsx`

```tsx
"use client";

import { useEffect, useActionState } from "react";
import { toast } from "sonner";
import { deleteReviewAction, FormState } from "../actions";

const initialState: FormState = {
  success: false,
  message: "",
};

export function DeleteButton({ reviewId }: { reviewId: number }) {
  const [state, formAction, isPending] = useActionState(
    deleteReviewAction,
    initialState
  );

  useEffect(() => {
    if (state.message) {
      if (state.success) toast.success(state.message);
      else toast.error(state.message);
    }
  }, [state]);

  return (
    <form action={formAction}>
      <input type="hidden" name="id" value={reviewId} />
      <button
        type="submit"
        disabled={isPending}
        className="text-red-500 text-sm disabled:text-gray-400"
      >
        {isPending ? "Deleting..." : "Delete"}
      </button>
    </form>
  );
}
```

Notice kiya? **ReviewForm aur DeleteButton same pattern hai** — dono mein `action={formAction}` hai, dono mein `useActionState` se state + isPending aata hai, dono mein hidden input hai. Version 1 mein delete ke liye `axios.delete(url)` likhna padta tha — ab sirf function call hai.

**Do cheezein yahan fix hui jo 3.3.1 mein tumhe error deti thi:**
1. **`action={deleteReviewAction}` direct nahi lagaya** — kyunki action object return karta hai aur direct `action={...}` pe wo TypeScript error deta hai. `useActionState` se wrapped `formAction` lagaya.
2. **`isPending` abhi button pe direct hai** — isliye alag child component (`SubmitButton` jaisa) ya `useFormStatus` ki zaroorat nahi. `useFormStatus` sirf tab chahiye jab button form ke andar kahin deep ho aur props thread karna mushkil ho — humare case mein button form ke immediate child hai, isliye `useActionState` ka `isPending` hi kaafi hai.

## Step 5: Detail Page — View + Edit (Dynamic Route)

Version 1 mein edit ke liye detail page banate waqt `useEffect` + `params.then` + `axios.get()` likhna padta tha — wahi 3.2 wala boilerplate. **Server Components se wo sab khatam ho jaata hai.** `/reviews/[id]/page.tsx` seedha data layer se `getReviewById()` call karta hai — koi `axios`, koi loading state nahi:

```tsx
// app/reviews/[id]/page.tsx
import { getReviewById } from "@/lib/reviews";
import { notFound } from "next/navigation";
import { EditReviewForm } from "../../components/EditReviewForm";

export default async function ReviewPage({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  const review = getReviewById(Number(id));

  if (!review) {
    notFound();
  }

  return (
    <div className="max-w-md mx-auto p-4 border rounded">
      <p>{"⭐".repeat(review.rating)}</p>
      <p className="text-lg">{review.text}</p>
      <p className="text-sm text-gray-500">{review.createdAt}</p>
      <EditReviewForm review={review} />
    </div>
  );
}
```

Ye **Server Component** hai — isliye `await params` seedha, `getReviewById()` direct call. Version 1 mein wahi kaam `useEffect` + `axios.get()` se karna padta tha. **Boilerplate ka fark hi Server Actions + Server Components ka point hai.**

Ab `EditReviewForm` — client component jisme **Edit button → form khulta hai** (3.2 wala toggle), par Save pe **server action** (`updateReviewAction`) call hota hai:

```tsx
// app/components/EditReviewForm.tsx
"use client";

import { useState, useEffect, useActionState } from "react";
import { toast } from "sonner";
import { updateReviewAction, FormState } from "../actions";

const initialState: FormState = {
  success: false,
  message: "",
};

export function EditReviewForm({ review }: { review: { id: number; text: string; rating: number } }) {
  const [editing, setEditing] = useState(false);   // ← view/edit toggle (3.2 pattern)
  const [state, formAction, isPending] = useActionState(updateReviewAction, initialState);

  useEffect(() => {
    if (state.message) {
      if (state.success) toast.success(state.message);
      else toast.error(state.message);
    }
  }, [state]);

  return (
    <div className="mt-3">
      {editing ? (
        // EDIT MODE — form khula
        <form action={formAction} className="space-y-2">
          <input type="hidden" name="id" value={review.id} />

          <div>
            <label>Rating:</label>
            <select name="rating" defaultValue={review.rating} className="border p-1 rounded ml-2">
              {[1, 2, 3, 4, 5].map((n) => (
                <option key={n} value={n}>{"⭐".repeat(n)}</option>
              ))}
            </select>
          </div>

          <textarea name="text" defaultValue={review.text} className="w-full border p-2 rounded" rows={3} />

          <div className="flex gap-2">
            <button
              type="submit"
              disabled={isPending}
              className="bg-green-500 text-white px-4 py-2 rounded disabled:bg-gray-400"
            >
              {isPending ? "Saving..." : "Save"}
            </button>
            <button type="button" onClick={() => setEditing(false)} className="text-gray-500 text-sm">
              Cancel
            </button>
          </div>
        </form>
      ) : (
        // VIEW MODE — Edit button
        <button onClick={() => setEditing(true)} className="bg-blue-500 text-white px-4 py-2 rounded">
          Edit
        </button>
      )}
    </div>
  );
}
```

Dekho — `editing` boolean wahi 3.2 wala toggle hai. Par **Save pe `axios` nahi, `action={formAction}`** hai — `useActionState` se wrapped version, isliye `updateReviewAction` ab `prevState` param leta hai (same pattern jo add/delete mein hai). FormData se `id` hidden input mein jaata hai (`name="id"`), `select` ka `name="rating"`, `textarea` ka `name="text"` — wahi `formData.get()` mapping jo add/delete mein tha. Submit pe `updateReviewAction` chalta hai, `revalidatePath` se page auto-refresh hota hai — **koi manual refresh nahi.** Save pe `isPending` se "Saving...", aur result toast mein dikhta hai — wahi `useActionState` + toast pattern.

Pura flow:

```
User list mein "Edit →" dabata hai (Link → /reviews/2)
    ↓
app/reviews/[id]/page.tsx (Server Component) → getReviewById(2) → review dikha
    ↓
"Edit" button click → setEditing(true) → form khula (text + rating prefilled)
    ↓
Save click → action={updateReviewAction} → updateReview → revalidatePath
    ↓
Page auto-refresh → naya data dikha
```

**Notice kiya?** Version 1 ka detail page `useEffect` + `axios.get()` + manual state wala tha. Version 2 ka detail page **Server Component hai** (data direct) + chhota client form (sirf toggle). Boilerplate ka fark hi yahan clearly dikhta hai.

## Comparison: Version 1 vs Version 2

| | Version 1 (Route Handler) | Version 2 (Server Actions) |
|---|---|---|
| **Route files** | 2 files (`/api/reviews/route.ts`, `/api/reviews/[id]/route.ts`) | 0 files |
| **Server code** | Route Handler functions | Server Actions (actions.ts) |
| **Client fetch code** | `axios.post("/api/reviews", { productId, text, rating })` | `action={addReviewAction}` |
| **Pending state** | `useState` manually | `useActionState` ka `isPending` |
| **Error state** | `useState` + `try/catch` | `useActionState` return + `sonner` toast |
| **Page refresh** | `router.refresh()` | `revalidatePath("/reviews")` |
| **Total client code** | ~50 lines | ~20 lines |
| **Boilerplate** | Zyada | Almost zero |

## Server Action Version Ka Summary

| Step | Kya Kiya |
|------|----------|
| 1 | Server Actions banaye (add, update, delete) - koi route file nahi |
| 2 | Server Component - review list + delete button + "Edit →" Link |
| 3 | Client Components - useActionState + sonner toast |
| 4 | Main page - sab jod diya |
| 5 | Detail page - `/reviews/[id]` pe Edit button → form → `updateReviewAction` |

**Magic:**
- Koi API route nahi - sirf functions
- Koi `axios` nahi - form seedha function call karta hai
- Koi manual pending state nahi - `useActionState` ka `isPending` built-in hai
- Koi manual refresh nahi - `revalidatePath` se auto refresh
