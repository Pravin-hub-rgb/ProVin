## Step 1: Server Actions

Ab sabse important part — **form submit kaise hoga?** Version 1 mein `fetch()` se call karte the. Ab sirf function call hoga.

**File:** `app/actions.ts`

Pehle `addReview` action banate hain:

```tsx
"use server";

import { addReview, deleteReview } from "@/lib/reviews";
import { revalidatePath } from "next/cache";

export type FormState = {
  success: boolean;
  message: string;
};

export async function addReviewAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const text = formData.get("text") as string;
  const rating = Number(formData.get("rating"));
  const productId = Number(formData.get("productId"));

  // Validation
  if (!text) {
    return { success: false, message: "Review text zaroori hai!" };
  }

  if (!rating || rating < 1 || rating > 5) {
    return { success: false, message: "Rating 1 se 5 honi chahiye!" };
  }

  addReview({ productId, text, rating });
  revalidatePath("/reviews");

  return { success: true, message: "Review add ho gaya!" };
}
```

Dekho kya hai — ye **3.1 ke Route Handler jaisa hai**, par fark hai:
- **Route Handler mein:** `request.json()` se data aata hai, `NextResponse.json()` se response jaata hai
- **Server Action mein:** `formData.get("text")` se data aata hai, return value se response jaata hai

**Notice kiya?** Koi `fetch()` nahi, koi `NextResponse` nahi — sirf function hai jo data leta hai aur return karta hai. Bilkul normal function jaisa.

Ab `deleteReview` action bhi add karte hain — same file mein:

```tsx
export async function deleteReviewAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const id = Number(formData.get("id"));

  const deleted = deleteReview(id);

  if (!deleted) {
    return { success: false, message: "Review nahi mila!" };
  }

  revalidatePath("/reviews");
  return { success: true, message: "Review delete ho gaya!" };
}
```

**Dekho — ye bhi same pattern hai.** FormData se `id` nikalo, function call karo, result return karo. Koi `route.ts` file nahi, koi HTTP method nahi — sirf functions.

**`revalidatePath("/reviews")` kya kar raha hai?** 3.6 mein seekha tha — ye Next.js ko bolta hai ki "/reviews" page ka data purana ho gaya hai, dobara render karo. Isliye naya review dikh jaata hai bina page reload ke.

**Return type `FormState` kyun hai?** `useFormState` ko pata hona chahiye ki response kaisa hoga — `success` boolean hai ya nahi, `message` kya hai. Isliye type define kiya hai.

## Step 2: Server Component - Review List

```tsx
// app/components/ReviewList.tsx
import { getReviewsByProduct } from "@/lib/reviews";
import { DeleteButton } from "./DeleteButton";  // Step 3 mein banega

export function ReviewList({ productId }: { productId: number }) {
  const reviews = getReviewsByProduct(productId);

  if (reviews.length === 0) {
    return <p className="text-gray-500">Abhi koi review nahi hai.</p>;

  return (

            <span>{"⭐".repeat(review.rating)}</span>
            <span className="text-sm text-gray-500">{review.createdAt}</span>
          </div>
          <p>{review.text}</p>
          <DeleteButton reviewId={review.id} />
        </div>
      ))}
    </div>
  );
}
```

**Note:** `DeleteButton` Step 3 mein banega - abhi sirf import hai. React mein ye normal hai - ek component doosre ko import karta hai.

## Step 3: Client Components - Form + Delete Button

Ab form banate hain — par **Version 1 se comparison karte jao.**

### Pehle Samjho: Hidden Input Kya Hai?

Form mein data bhejne ke liye `input` fields hote hain — user unmein type karta hai. Par kabhi kabhi **user ko dikhaye bina** data bhejna hota hai — jaise `productId` ya `reviewId`. Iske liye **hidden input** use hota hai:

```tsx
<input type="hidden" name="productId" value={productId} />
```

**`type="hidden"` kya karta hai?** User ko ye input **dikhta nahi** — par form submit hone pe ye **data mein include hota hai.** Jaise ek invisible field jo form ke saath jaata hai.

**`name="productId"` kyun zaroori hai?** Server Action mein `formData.get("productId")` se ye value milti hai. **`name` attribute aur `formData.get()` ka naam same hona chahiye:**

```tsx
// Client side — form mein
<input type="hidden" name="productId" value={1} />

// Server side — Server Action mein
const productId = formData.get("productId");  // 1 mila
```

Chal ab form banate hain — pehle sirf text input, phir rating add karo, phir hidden input.

**File:** `app/components/ReviewForm.tsx`

#### Pehle Sirf Text + Submit

```tsx
"use client";

import { useFormState, useFormStatus } from "react-dom";
import { addReviewAction, FormState } from "../actions";

const initialState: FormState = {
  success: false,
  message: "",
};

function SubmitButton() {
  const { pending } = useFormStatus();

  return (
    <button
      type="submit"
      disabled={pending}
      className="bg-blue-500 text-white px-4 py-2 rounded disabled:bg-gray-400"
    >
      {pending ? "Loading..." : "Submit Review"}
    </button>
  );
}

export function ReviewForm({ productId }: { productId: number }) {
  const [state, formAction] = useFormState(addReviewAction, initialState);

  return (
    <form action={formAction} className="space-y-2 border p-4 rounded">
      <h3 className="font-bold">Naya Review Likho</h3>

      <input type="hidden" name="productId" value={productId} />

      <textarea
        name="text"
        placeholder="Apna review likho..."
        className="w-full border p-2 rounded"
        rows={3}
      />

      <SubmitButton />

      {state.message && (
        <p className={state.success ? "text-green-500" : "text-red-500"}>
          {state.message}
        </p>
      )}
    </form>
  );
}
```

Dekho kya hai — Version 1 ke comparison mein:

| Version 1 | Version 2 | Kya badla |
|---|---|---|
| `onSubmit={handleSubmit}` | `action={formAction}` | `useFormState` se action milta hai |
| `useState` for pending | `useFormStatus()` se pending | Built-in — manually nahi banana padta |
| `useState` for message | `state.message` | Server Action se aata hai |
| `fetch()` + `JSON.stringify` | Sirf `action` attribute | Boilerplate khatam |

**Notice kiya?** Version 1 mein **3 useState** the (text, pending, message). Version 2 mein **sirf 1 useState** hai (formAction). Baki sab built-in hai.

#### Ab Rating Add Karo

Ab rating select add karte hain — `defaultValue` use karo (controlled nahi):

```tsx
// ReviewForm mein add karo — textarea ke pehle:

<div>
  <label>Rating:</label>
  <select name="rating" defaultValue={5} className="border p-1 rounded ml-2">
    {[1, 2, 3, 4, 5].map((n) => (
      <option key={n} value={n}>
        {"⭐".repeat(n)}
      </option>
    ))}
  </select>
</div>
```

**`defaultValue={5}` kyun, `value` kyun nahi?** Version 1 mein `value={rating}` + `onChange` use kiya tha — ye **controlled component** hai. Version 2 mein `defaultValue` use karte hain — ye **uncontrolled** hai, form data mein sirf name aur value chahiye. React ko manage nahi karna.

**Notice kiya?** Version 2 mein `useState("rating")` ki zaroorat nahi — form khud manage karta hai.

#### Delete Button Bhi Same Pattern Hai

Delete ke liye alag component hai — par pattern same hai:

**File:** `app/components/DeleteButton.tsx`

```tsx
"use client";

import { useFormStatus } from "react-dom";
import { deleteReviewAction } from "../actions";

function DeleteForm({ reviewId }: { reviewId: number }) {
  const { pending } = useFormStatus();

  return (
    <form action={deleteReviewAction}>
      <input type="hidden" name="id" value={reviewId} />
      <button
        type="submit"
        disabled={pending}
        className="text-red-500 text-sm disabled:text-gray-400"
      >
        {pending ? "Deleting..." : "Delete"}
      </button>
    </form>
  );
}

export function DeleteButton({ reviewId }: { reviewId: number }) {
  return <DeleteForm reviewId={reviewId} />;
}
```

Notice kiya? **ReviewForm aur DeleteButton same pattern hai** — dono mein `action={function}` hai, dono mein `useFormStatus()` se pending state hai, dono mein hidden input hai. Version 1 mein delete ke liye `fetch()` + `method: "DELETE"` likhna padta tha — ab sirf function call hai.

**Why two components (`DeleteForm` + `DeleteButton`)?** Ye `useFormStatus` ki wajah se hai — `useFormStatus` sirf **immediate parent** form ka status dhoondhta hai. Agar `DeleteButton` directly form return karta toh `useFormStatus` kaam nahi karta. Isliye alag `DeleteForm` component hai jo form return karta hai.

## Comparison: Version 1 vs Version 2

| | Version 1 (Route Handler) | Version 2 (Server Actions) |
|---|---|---|
| **Route files** | 2 files (`/api/reviews/route.ts`, `/api/reviews/[id]/route.ts`) | 0 files |
| **Server code** | Route Handler functions | Server Actions (actions.ts) |
| **Client fetch code** | `fetch("/api/reviews", { method: "POST", headers: {...}, body: JSON.stringify({...}) })` | `action={addReviewAction}` |
| **Pending state** | `useState` manually | `useFormStatus` built-in |
| **Error state** | `useState` + `try/catch` | `useFormState` built-in |
| **Page refresh** | `window.location.reload()` | `revalidatePath("/reviews")` |
| **Total client code** | ~50 lines | ~20 lines |
| **Boilerplate** | Zyada | Almost zero |

## Server Action Version Ka Summary

| Step | Kya Kiya |
|------|----------|
| 1 | Server Actions banaye (add, delete) - koi route file nahi |
| 2 | Server Component - review list + delete button |
| 3 | Client Components - useFormStatus + useFormState |
| 4 | Main page - sab jod diya |

**Magic:**
- Koi API route nahi - sirf functions
- Koi `fetch()` nahi - form seedha function call karta hai
- Koi manual pending state nahi - `useFormStatus` built-in hai
- Koi manual refresh nahi - `revalidatePath` se auto refresh

## Kab Version 1 (Route Handler) Use Karein?

1. External client hai (mobile app, third-party website)
2. API share karni hai
3. Complex operations hain
4. Debugging chahiye (network tab mein sab dikhe)

## Kab Version 2 (Server Actions) Use Karein?

1. Sirf Next.js app hai
2. Simple form submissions hain
3. Kam code chahiye
4. Quick iteration chahiye

**Dono seekho, samjho kab kya use karna hai.** Ye Batch 3 ka main goal tha.
