# Static UI — Review Cards + Layout (3.4.2)

## Where We Left Off

In 3.4.1, we planned the Reviews & Ratings App. We defined the data shape (id, productId, text, rating, createdAt) and the page structure (list page + detail page). Now we build the **static UI** first — hardcoded data to confirm the layout looks right before wiring up data.

## Why Static First?

Think about building a house. You don't start with the plumbing and electrical — you start with the frame and structure. You need to see the layout, the proportions, the flow before worrying about how data moves through it.

Same here — let's see how it looks with static data first, then wire up the data layer underneath.

```tsx
  },
  {
    id: 4,
    productId: 2,
    text: "Mujhe pasand nahi aaya. Waste of money.",
    rating: 2,
    createdAt: "2025-01-18",
  },
];

export default function ReviewsPage() {
  const product1Reviews = reviews.filter((r) => r.productId === 1);
  const product2Reviews = reviews.filter((r) => r.productId === 2);

  return (
    <div>
      <h1 className="text-2xl font-bold mb-6">Reviews & Ratings</h1>
      <ProductSection name="Product 1" reviews={product1Reviews} />
      <ProductSection name="Product 2" reviews={product2Reviews} />
    </div>
  );
}
```

**Notice:** `filter()` splits reviews by product. Same data, two different views — that's the query pattern from 3.4.1.

## Step 3: ProductSection Component

Each product gets a section — name + reviews:

```tsx
// app/components/ProductSection.tsx
import { ReviewCard } from "./ReviewCard";

export function ProductSection({
  name,
  reviews,
}: {
  name: string;
  reviews: { id: number; text: string; rating: number; createdAt: string }[];
}) {
  return (
    <div className="border p-4 rounded mb-6">
      <h2 className="text-xl font-bold mb-3">{name}</h2>

      {reviews.length === 0 ? (
        <p className="text-gray-500">Abhi koi review nahi hai.</p>
      ) : (
        <div className="space-y-2">
          {reviews.map((review) => (
            <ReviewCard
              key={review.id}
              text={review.text}
              rating={review.rating}
              createdAt={review.createdAt}
            />
          ))}
        </div>
      )}
    </div>
  );
}
```

The empty check (`reviews.length === 0`) handles products with no reviews yet. The `key` ensures React can track items properly.

## Step 4: ReviewCard Component

The building block — displays one review:

```tsx
// app/components/ReviewCard.tsx
export function ReviewCard({
  text,
  rating,
  createdAt,
}: {
  text: string;
  rating: number;
  createdAt: string;
}) {
  return (
    <div className="border p-3 rounded bg-white shadow-sm">
      <div className="flex justify-between items-center mb-2">
        <span className="text-lg">{"⭐".repeat(rating)}</span>
        <span className="text-sm text-gray-500">{createdAt}</span>
      </div>
      <p className="text-gray-700">{text}</p>
    </div>
  );
}
```

**Note on props:** Currently `ReviewCard` only receives `text`, `rating`, `createdAt` — no `id` or `productId`. That's intentional — this component only displays, it doesn't need identifiers. When we add edit/delete buttons later, we'll add `id` to the props.

## What's Wrong

1. **Data is hardcoded** — to add a review, you'd need to edit the code
2. **No forms** — can't add, edit, or delete reviews
3. **No detail page** — clicking a review doesn't go anywhere
4. **No server** — the data isn't persisted or fetched from a real source

These are the problems the next steps will solve — starting with the data layer.

## In Your Own Words

<details>
<summary>Question 1: Why build static UI before dynamic data?</summary>
<p><strong>Answer:</strong> Static UI separates layout from data. If you build both at once and something's wrong, you don't know if it's the UI design or the data flow. With static first, you confirm the UI looks right — then the data layer slots underneath without changing the layout.</p>
</details>

<details>
<summary>Question 2: What does `filter()` do, and how does it work here?</summary>
<p><strong>Answer:</strong> `filter()` creates a new array with only the elements that match a condition. Here, `reviews.filter((r) => r.productId === 1)` returns only reviews for Product 1. Same data array, different views — that's how we show Product 1's reviews separately from Product 2's.</p>
</details>

<details>
<summary>Question 3: Why does `ReviewCard` not receive `id` or `productId`?</summary>
<p><strong>Answer:</strong> It only needs what to display — text, rating, date. The `id` is only needed when you want to edit or delete (identifying which review to change). Prematurely passing data a component doesn't need is unnecessary complexity.</p>
</details>

<details>
<summary>Question 4: Why is `key={review.id}` necessary in the map?</summary>
<p><strong>Answer:</strong> React uses `key` to track which items in a list are which. When the list changes (add, remove, reorder), React uses the key to know which DOM elements to update, add, or remove. Without `key`, React warns and list updates become buggy.</p>
</details>
