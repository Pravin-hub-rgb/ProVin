3.3 mein Server Actions seekhe — form submit hota hai, server function call hota hai. Par ek problem thi: **user ko pata nahi chalta ki kya ho raha hai.**

Form submit kiya → kuch pata nahi → loading hai? success hua? error aaya?

Server Actions ke saath Next.js do hooks deta hai — `useFormStatus` aur `useFormState` — jo ye problem solve karte hain.

---

## SOCH: Form Submit Pe Kya Chahiye?

User ne comment form submit kiya. Usse ye sab chahiye:
1. **Pending state** — "Loading..." dikhe jab tak server kaam kar raha hai
2. **Success message** — "Comment add ho gaya!" dikhe
3. **Error message** — "Kuch gadbad hui" dikhe agar fail ho

React mein ye `useState` se karte the. Next.js mein ye **built-in hooks** se hota hai — zyada clean aur reliable.

---

## CONCEPT: useFormStatus — Pending State

`useFormStatus` batata hai ki form **abhi submit ho raha hai** ya nahi. Ye hook sirf Client Components mein kaam karta hai.

```tsx
"use client";

import { useFormStatus } from "react-dom";

function SubmitButton() {
  const { pending } = useFormStatus();

  return (
    <button type="submit" disabled={pending}>
      {pending ? "Loading..." : "Submit"}
    </button>
  );
}
```

**Note:** `useFormStatus` sirf **submit button ke child component** mein kaam karta hai. Direct form mein nahi — alag component banana padta hai.

---

## CODE: Pending State with Server Action

```tsx
// app/actions.ts
"use server";

export async function addComment(formData: FormData) {
  const text = formData.get("comment") as string;

  // Simulate delay (database call jaisa)
  await new Promise((resolve) => setTimeout(resolve, 2000));

  console.log("Comment added:", text);
  return { success: true, message: "Comment add ho gaya!" };
}
```

### `new Promise((resolve) => setTimeout(resolve, 2000))` Kya Hai?

Ye line simulate karti hai ki database call ho raha hai (2 second ka delay).

**Promise Kya Hai?**

Promise ek JavaScript concept hai — ye batata hai ki kuch kaam **abhi ho raha hai** aur **baad mein result aayega**.

```tsx
// Promise: "Ye kaam ho raha hai, result baad mein aayega"
const promise = new Promise((resolve) => {
  // Kuch kaam karo...
  setTimeout(() => {
    resolve("Kaam ho gaya!");  // Result mil gaya
  }, 2000);
});
```

**`resolve` kya hai?** Ye function hai jo Promise ko batata hai ki "kaam ho gaya, ye lo result". Jab `resolve("Kaam ho gaya!")` call hota hai, toh Promise complete hota hai.

**`setTimeout` kya hai?** Ye browser/Node.js ka function hai — kuch der baad kuch karne ke liye:

```tsx
// 2 second baad kuch karo
setTimeout(() => {
  console.log("2 seconds ho gaye!");
}, 2000);
```

**`await` kyun laga hai?** Kyunki Promise complete hone tak wait karna hai. `await` se execution rukta hai jab tak Promise resolve na ho jaaye.

**Matlab:** Ye poori line bolti hai — "2 second wait karo, phir aage badho." Real projects mein database call hota hai jo thoda time leta hai — isliye ye simulation.

```tsx
// app/components/SubmitButton.tsx
"use client";

import { useFormStatus } from "react-dom";

export function SubmitButton() {
  const { pending } = useFormStatus();

  return (
    <button
      type="submit"
      disabled={pending}
      className="bg-blue-500 text-white px-4 py-2 rounded disabled:bg-gray-400"
    >
      {pending ? "Loading..." : "Submit"}
    </button>
  );
}
```

```tsx
// app/page.tsx
import { addComment } from "./actions";
import { SubmitButton } from "./components/SubmitButton";

export default function Home() {
  return (
    <form action={addComment}>
      <input
        name="comment"
        placeholder="Apna comment likho..."
        className="border p-2 rounded"
      />
      <SubmitButton />
    </form>
  );
}
```

**Flow:**
1. User "Submit" click karta hai
2. `pending = true` ho jaata hai → button "Loading..." dikhata hai
3. Server pe 2 second kaam hota hai
4. `pending = false` ho jaata hai → button wapas "Submit" ho jaata hai

## CONCEPT: useFormState — Success/Error States

`useFormStatus` sirf pending state deta hai. Agar **success ya error message** chahiye, toh `useFormState` use karo.

### Pehle Samjho: TypeScript `type` Kya Hai?

Code mein aap dekhoge `type FormState = { ... }`. Ye **TypeScript** hai — JavaScript ka upgraded version jo data types define karta hai.

```tsx
// TypeScript type — data ka shape define karta hai
export type FormState = {
  success: boolean;    // true ya false hoga
  message: string;     // text hoga
};
```

**`type` kyun use karte hain?** Taaki pata ho ki function kya return karega. Bina type ke pata nahi chalega ki `state.success` hai ya `state.error` hai.

**`boolean` kya hai?** Sirf do values ho sakti hain — `true` ya `false`. Jaise: success hua ya nahi.

**`string` kya hai?** Text data — "Hello", "Error aaya", etc.

**`initialState` kyun chahiye?** Kyunki `useFormState` ko pata hona chahiye ki shuru mein state kaisi hogi. Jab form pehli baar load ho, tab `state` mein ye values hongi:

```tsx
const initialState = {
  success: false,     // Abhi kuch hua nahi
  message: "",        // Abhi message nahi hai
};
```

### useFormState Kaise Kaam Karta Hai?

```tsx
"use client";

import { useFormState } from "react-dom";
import { addComment } from "../actions";

const initialState = {
  success: false,
  message: "",
};

export function CommentForm() {
  const [state, formAction] = useFormState(addComment, initialState);

  return (
    <form action={formAction}>
      <input name="comment" placeholder="Comment..." />
      <button type="submit">Submit</button>

      {state.message && (
        <p className={state.success ? "text-green-500" : "text-red-500"}>
          {state.message}
        </p>
      )}
    </form>
  );
}
```

**`useFormState` kya return karta hai?**

Ye **array** return karta hai (jaise `useState`):
- `state` — Server Action ka return value (`{ success: true, message: "..." }`)
- `formAction` — Ye `addComment` ki wrapped version hai jo `useFormState` ke saath kaam karti hai

**Kyun `formAction` alag hai?** Kyunki `useFormState` ko server action ka return value capture karna hota hai. `formAction` use karte ho toh hook automatically state update kar deta hai.

**Server Action ka return type aur `initialState` ka shape same hona chahiye:**

```tsx
// Server Action
export async function addComment(...) {
  return { success: true, message: "Comment add ho gaya!" };
  //     ^ boolean         ^ string
}

// initialState
const initialState = {
  success: false,    // boolean
  message: "",       // string
};
// Dono ka shape same hai!
```

## CODE: Dono Hooks Ek Sath

```tsx
// app/actions.ts
"use server";

export type FormState = {
  success: boolean;
  message: string;
};

export async function addComment(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const text = formData.get("comment") as string;

  if (!text) {
    return { success: false, message: "Comment text zaroori hai!" };
  }

  // Simulate delay
  await new Promise((resolve) => setTimeout(resolve, 1000));

  // 50% chance of error (demo ke liye)
  if (Math.random() > 0.5) {
    return { success: false, message: "Server error — dobara try karo!" };
  }

  console.log("Comment added:", text);
  return { success: true, message: "Comment add ho gaya!" };
}
```

**Server Action ke parameters samjho:**

`prevState: FormState` — Ye **purana state** hai. `useFormState` hook automatically previous state pass karta hai. Jab form pehli baar load ho, tab `initialState` milta hai.

`: Promise<FormState>` — Ye TypeScript return type hai. Ye batata hai ki function ek Promise return karega jo `FormState` shape ka hoga.

**`Math.random() > 0.5` kya hai?** Randomly check kar raha hai ki error aaye ya nahi. 50% chance hai error ka — demo ke liye taaki error handling dekh sako.

```tsx
// app/components/SubmitButton.tsx
"use client";

import { useFormStatus } from "react-dom";

export function SubmitButton() {
  const { pending } = useFormStatus();

  return (
    <button
      type="submit"
      disabled={pending}
      className="bg-blue-500 text-white px-4 py-2 rounded disabled:bg-gray-400"
    >
      {pending ? "Loading..." : "Submit"}
    </button>
  );
}
```

```tsx
// app/page.tsx
"use client";

import { useFormState } from "react-dom";
import { addComment, FormState } from "./actions";
import { SubmitButton } from "./components/SubmitButton";

const initialState: FormState = {
  success: false,
  message: "",
};

export default function Home() {
  const [state, formAction] = useFormState(addComment, initialState);

  return (
    <div className="p-4">
      <h1>Comment Form</h1>
      <form action={formAction} className="flex flex-col gap-2">
        <input
          name="comment"
          placeholder="Apna comment likho..."
          className="border p-2 rounded"
        />
        <SubmitButton />
      </form>

      {state.message && (
        <p className={`mt-2 ${state.success ? "text-green-500" : "text-red-500"}`}>
          {state.message}
        </p>
      )}
    </div>
  );
}
```

## Flow Samjho

```
1. User "Submit" click karta hai
         ↓
2. useFormStatus → pending = true → Button "Loading..." dikha raha hai
         ↓
3. Server pe addComment call hota hai
         ↓
4. Server response bhejta hai → { success: true, message: "Comment add ho gaya!" }
         ↓
5. useFormState → state update hota hai → Message dikhta hai
         ↓
6. useFormStatus → pending = false → Button wapas "Submit" ho gaya
```

## useFormStatus vs useFormState — Kab Kya?

| Hook | Kya karta hai | Kab use karein |
|------|---------------|----------------|
| `useFormStatus` | Sirf `pending` state deta hai | Button ko disable karna ho, loading dikhana ho |
| `useFormState` | Server Action ka return state deta hai | Success/error message dikhana ho |

Dono ek saath use karte hain — `useFormStatus` button ke liye, `useFormState` form ke liye.

---

## Nutshell

`useFormStatus` pending state deta hai — button disable karo, loading dikhao. `useFormState` server action ka return state deta hai — success/error message dikhao. Dono hooks Client Components mein chalte hain. `useFormStatus` sirf submit button ke child component mein kaam karta hai.

---

## Common Mistakes

- ❌ `useFormStatus` ko directly form mein lagana — ye alag child component mein hona chahiye
- ❌ Server Action ka return type aur initialState ka shape match na karna — dono same hone chahiye
- ❌ `useFormState` mein `prevState` parameter na lena — ye zaroori hai, Next.js isse pass karta hai
- ❌ Dono hooks ko Server Component mein use karna — ye sirf Client Components mein chalte hain

## In Your Own Words

<details>
<summary>Sample Jawab</summary>

**Jawab:** `useFormStatus` sirf `pending` state deta hai — form submit ho raha hai ya nahi. `useFormState` server action ka return value deta hai — success message, error message, ya koi bhi data.

</details>

2. `useFormStatus` ko directly form mein kyun nahi lagate?

<details>
<summary>Sample Jawab</summary>

</details>

3. Server Action ka return type kyun match karna padta hai `initialState` se?

<details>
<summary>Sample Jawab</summary>

**Jawab:** `useFormState` hook ko pata hona chahiye ki state ka shape kya hai. Agar return type alag ho toh TypeScript error aayega aur runtime pe gadbad ho sakti hai. Dono same shape hona chahiye — `{ success: boolean, message: string }` jaisa.

</details>

## What It Is NOT

⚠️ **`useFormStatus` = "loading state" nahi.** Ye sirf pending state batata hai. Actual loading logic tumhe khud likhni padegi (jaise database call).

⚠️ **`useFormState` = "automatic error handling" nahi.** Ye sirf return value deta hai. Error handle tumhe khud karna hai — `if (!state.success)` check karo.

⚠️ **Dono hooks = "Server Actions ke liye hi hain" nahi.** Ye `react-dom` ke hooks hain, sirf forms ke liye design kiye gaye hain. Server Actions ke saath use karte hain par ye sirf unke liye nahi hain.
