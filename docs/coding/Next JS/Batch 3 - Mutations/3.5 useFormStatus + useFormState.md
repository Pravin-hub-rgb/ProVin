3.3 mein Server Actions seekhe — form submit hota hai, server function call hota hai. Par ek problem thi: **user ko pata nahi chalta ki kya ho raha hai.**

Form submit kiya → kuch pata nahi → loading hai? success hua? error aaya?

Server Actions ke saath Next.js do hooks deta hai — `useFormStatus` aur `useFormState` — jo ye problem solve karte hain.

---

## SOCH: Form Submit Pe Kya Chahiye?

User ne comment form submit kiya. Usse ye sab chahiye:
1. **Pending state** — "Loading..." dikhe jab tak server kaam kar raha hai
2. **Success message** — "Comment add ho gaya!" dikhe
3. **Error message** — "Kuch gadbad hui" dikhe agar fail ho

React mein ye `useState` se karte the. Next.js mein ye **built-in hooks** se hota hai — zyada clean aur reliable.

---

## useFormStatus — Pending State

`useFormStatus` batata hai ki form **abhi submit ho raha hai** ya nahi. Ye hook sirf Client Components mein kaam karta hai.

```tsx
"use client";

import { useFormStatus } from "react-dom";

function SubmitButton() {
  const { pending } = useFormStatus();

  return (
    <button type="submit" disabled={pending}>
      {pending ? "Loading..." : "Submit"}
    </button>
  );
}
```

**Note:** `useFormStatus` sirf **submit button ke child component** mein kaam karta hai. Direct form mein nahi — alag component banana padta hai.

---

## Pending State with Server Action

```tsx
// app/actions.ts
"use server";

export async function addComment(formData: FormData) {
  const text = formData.get("comment") as string;

  // Simulate delay (database call jaisa)
  await new Promise((resolve) => setTimeout(resolve, 2000));

  console.log("Comment added:", text);
  return { success: true, message: "Comment add ho gaya!" };
}
```

### `new Promise((resolve) => setTimeout(resolve, 2000))` Kya Hai?

Ye line simulate karti hai ki database call ho raha hai — 2 second ka delay.

**Promise** ek JavaScript concept hai — batata hai ki kuch kaam **abhi ho raha hai** aur **baad mein result aayega**. `resolve` function hai jo Promise ko batata hai ki "kaam ho gaya". `setTimeout` browser/Node.js ka function hai — kuch der baad kuch karne ke liye.

**`await` kyun laga hai?** Kyunki Promise complete hone tak wait karna hai. Ye poori line bolti hai — "2 second wait karo, phir aage badho."

Maine bhi pehli baar `Promise` dekh ke socha tha "ye kya hai?" — par yaad rakh, ye async operations ke liye hai. Real projects mein database call hota hai jo thoda time leta hai — isliye ye simulation.

### Component aur Page

```tsx
// app/components/SubmitButton.tsx
"use client";

import { useFormStatus } from "react-dom";

export function SubmitButton() {
  const { pending } = useFormStatus();

  return (
    <button
      type="submit"
      disabled={pending}
      className="bg-blue-500 text-white px-4 py-2 rounded disabled:bg-gray-400"
    >
      {pending ? "Loading..." : "Submit"}
    </button>
  );
}
```

```tsx
// app/page.tsx
import { addComment } from "./actions";
import { SubmitButton } from "./components/SubmitButton";

export default function Home() {
  return (
    <form action={addComment}>
      <input
        name="comment"
        placeholder="Apna comment likho..."
        className="border p-2 rounded"
      />
      <SubmitButton />
    </form>
  );
}
```

**Flow:** User "Submit" click → `pending = true` → button "Loading..." → Server pe 2 second kaam → `pending = false` → button wapas "Submit".

Notice kiya? Button alag component mein hai (`SubmitButton`) — kyunki `useFormStatus` sirf child component mein kaam karta hai.

## useFormState — Success/Error States

`useFormStatus` sirf pending state deta hai. Agar **success ya error message** chahiye, toh `useFormState` use karo.

### Pehle Samjho: TypeScript `type` Kya Hai?

Code mein dekhoge `type FormState = { ... }`. Ye **TypeScript** hai — JavaScript ka upgraded version jo data types define karta hai.

```tsx
export type FormState = {
  success: boolean;    // true ya false hoga
  message: string;     // text hoga
};
```

`type` kyun use karte hain? Taaki pata ho ki function kya return karega. Bina type ke pata nahi chalega ki `state.success` hai ya `state.error` hai.

**`initialState` kyun chahiye?** Kyunki `useFormState` ko pata hona chahiye ki shuru mein state kaisi hogi:

```tsx
const initialState = {
  success: false,     // Abhi kuch hua nahi
  message: "",        // Abhi message nahi hai
};
```

### useFormState Kaise Kaam Karta Hai?

```tsx
"use client";

import { useFormState } from "react-dom";
import { addComment } from "../actions";

const initialState = {
  success: false,
  message: "",
};

export function CommentForm() {
  const [state, formAction] = useFormState(addComment, initialState);

  return (
    <form action={formAction}>
      <input name="comment" placeholder="Comment..." />
      <button type="submit">Submit</button>

      {state.message && (
        <p className={state.success ? "text-green-500" : "text-red-500"}>
          {state.message}
        </p>
      )}
    </form>
  );
}
```

`useFormState` kya return karta hai? Ye **array** return karta hai (jaise `useState`):
- `state` — Server Action ka return value
- `formAction` — `addComment` ki wrapped version jo `useFormState` ke saath kaam karti hai

**Server Action ka return type aur `initialState` ka shape same hona chahiye:**

```tsx
// Server Action
return { success: true, message: "Comment add ho gaya!" };
//     ^ boolean         ^ string

// initialState
const initialState = {
  success: false,    // boolean
  message: "",       // string
};
// Dono ka shape same hai!
```

## Dono Hooks Ek Sath

```tsx
// app/actions.ts
"use server";

export type FormState = {
  success: boolean;
  message: string;
};

export async function addComment(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const text = formData.get("comment") as string;

  if (!text) {
    return { success: false, message: "Comment text zaroori hai!" };
  }

  // Simulate delay
  await new Promise((resolve) => setTimeout(resolve, 1000));

  // 50% chance of error (demo ke liye)
  if (Math.random() > 0.5) {
    return { success: false, message: "Server error - dobara try karo!" };
  }

  console.log("Comment added:", text);
  return { success: true, message: "Comment add ho gaya!" };
}
```

**Server Action ke parameters samjho:**

`prevState: FormState` — Ye **purana state** hai. `useFormState` hook automatically previous state pass karta hai. Jab form pehli baar load ho, tab `initialState` milta hai.

`: Promise<FormState>` — TypeScript return type. Batata hai ki function ek Promise return karega jo `FormState` shape ka hoga.

`Math.random() > 0.5` — Randomly check kar raha hai ki error aaye ya nahi. 50% chance hai error ka — demo ke liye.

```tsx
// app/components/SubmitButton.tsx
"use client";

export function SubmitButton() {

```

```tsx
// app/page.tsx

    </div>
  );

```

## Flow Samjho

```
1. User "Submit" click karta hai
         ↓
2. useFormStatus → pending = true → Button "Loading..." dikha raha hai
         ↓
3. Server pe addComment call hota hai
         ↓
4. Server response bhejta hai → { success: true, message: "Comment add ho gaya!" }
         ↓
5. useFormState → state update hota hai → Message dikhta hai
         ↓
6. useFormStatus → pending = false → Button wapas "Submit" ho gaya
```

## useFormStatus vs useFormState — Kab Kya?

| Hook | Kya karta hai | Kab use karein |
|------|---------------|----------------|
| `useFormStatus` | Sirf `pending` state deta hai | Button ko disable karna ho, loading dikhana ho |
| `useFormState` | Server Action ka return state deta hai | Success/error message dikhana ho |

Dono ek saath use karte hain — `useFormStatus` button ke liye, `useFormState` form ke liye.

---

## Nutshell

`useFormStatus` pending state deta hai — button disable karo, loading dikhao. `useFormState` server action ka return state deta hai — success/error message dikhao. Dono hooks Client Components mein chalte hain. `useFormStatus` sirf submit button ke child component mein kaam karta hai.

---

## Common Mistakes

- **`useFormStatus` ko directly form mein lagana** — ye alag child component mein hona chahiye
- **Server Action ka return type aur initialState ka shape match na karna** — dono same hone chahiye
- **`useFormState` mein `prevState` parameter na lena** — ye zaroori hai
- **Dono hooks ko Server Component mein use karna** — ye sirf Client Components mein chalte hain

## In Your Own Words

1. `useFormStatus` aur `useFormState` mein kya fark hai?

<details>
<summary>Sample Jawab</summary>

<details>
<summary>Sample Jawab</summary>

</details>

3. Server Action ka return type kyun match karna padta hai `initialState` se?

<details>
<summary>Sample Jawab</summary>

</details>

---

## What It Is NOT

**`useFormStatus` = "loading state" nahi.** Ye sirf pending state batata hai. Actual loading logic tumhe khud likhni padegi.

**`useFormState` = "automatic error handling" nahi.** Ye sirf return value deta hai. Error handle tumhe khud karna hai.

**Dono hooks = "Server Actions ke liye hi hain" nahi.** Ye `react-dom` ke hooks hain, sirf forms ke liye design kiye gaye hain.
