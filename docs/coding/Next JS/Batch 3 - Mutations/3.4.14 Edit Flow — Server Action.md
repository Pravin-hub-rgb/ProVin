# Edit Flow — Server Action Version (3.4.14)

## Where We Left Off

In 3.4.13, we converted delete to a Server Action using a form with a hidden input. Now we'll convert the **edit flow** — the most complex mutation, which involves toggling between view mode and edit mode.

## The Plan

The Route Handler version (3.4.8) had:
1. A Client Component detail page with `useState` for `review`, `editing`, `editText`, `editRating`
2. `useEffect` + `axios.get()` to load the review
3. `axios.put()` for saving edits
4. `window.location.reload()` for refresh

We'll replace this with:
1. A **Server Component** detail page that reads data directly (`getReviewById`)
2. A **Client Component** `EditReviewForm` that handles the edit toggle and submission
3. A Server Action (`updateReviewAction`) that handles the update
4. `useActionState` for pending state and feedback
5. `revalidatePath` for auto-refresh (both detail and list pages)

## Step 1: updateReviewAction

Add the action to `app/actions.ts`:

```tsx
// app/actions.ts — add alongside the others
export async function updateReviewAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const id = Number(formData.get("id"));
  const text = formData.get("text") as string;
  const rating = Number(formData.get("rating"));

  // Validation
  if (!text || !text.trim()) {
    return { success: false, message: "Review text is required" };
  }
  if (!rating || rating < 1 || rating > 5) {
    return { success: false, message: "Rating must be between 1 and 5" };
  }

  // Call the data layer
  const updated = updateReview(id, { text, rating });

  if (!updated) {
    return { success: false, message: "Review not found" };
  }

  // Refresh both the detail page and the list page
  revalidatePath(`/reviews/${id}`);
  revalidatePath("/reviews");

  return { success: true, message: "Review updated" };
}
```

**Key insight:** `revalidatePath` is called for **both** `/reviews/${id}` (the detail page where the edit happened) and `/reviews` (the list page that also shows this review's text). Edit affects data visible on two pages.

## Step 2: Convert Detail Page to Server Component

The detail page becomes simpler — it reads data directly and renders the `EditReviewForm`:

```tsx
// app/reviews/[id]/page.tsx
import { getReviewById } from "@/lib/reviews";
import { notFound } from "next/navigation";
import Link from "next/link";
import { EditReviewForm } from "../../components/EditReviewForm";

export default async function ReviewPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const review = getReviewById(Number(id));

  if (!review) {
    notFound();
  }

  return (
    <div className="max-w-md mx-auto p-4 border rounded bg-white">
      <Link href="/reviews" className="text-blue-500 hover:underline text-sm mb-4 block">
        ← Back to Reviews
      </Link>

      <div className="flex justify-between items-center mb-3">
        <span className="text-2xl">{"⭐".repeat(review.rating)}</span>
        <span className="text-sm text-gray-500">{review.createdAt}</span>
      </div>

      <p className="text-lg mb-4">{review.text}</p>

      <EditReviewForm review={review} />
    </div>
  );
}
```

### What Disappeared

| State | Gone? | Why |
|---|---|---|
| `useState` for `review` | ✅ | Server Component reads data directly |
| `useState` for `editing` | ✅ | Moved to EditReviewForm component |
| `useState` for `editText` | ✅ | Uncontrolled input — `defaultValue` instead |
| `useState` for `editRating` | ✅ | Uncontrolled input — `defaultValue` instead |
| `useEffect` + `axios.get()` | ✅ | No fetch needed — direct function call |
| `"use client"` | ✅ | No hooks needed — Server Component |
| Loading state | ✅ | Not needed — data ready at render |

### What Stayed?

- **View mode shows review details** — stars, text, date
- **Edit button** — triggers edit form
- **Edit form** — textarea + rating select + save/cancel

The difference: the data loading and display is in the Server Component; the interactive editing logic is in the Client Component.

## Step 3: EditReviewForm — The Interactive Part

```tsx
// app/components/EditReviewForm.tsx
"use client";

import { useState, useEffect, useActionState } from "react";
import { updateReviewAction, FormState } from "../actions";
import { toast } from "sonner";

const initialState: FormState = { success: false, message: "" };

export function EditReviewForm({
  review,
}: {
  review: { id: number; text: string; rating: number };
}) {
  const [editing, setEditing] = useState(false);
  const [state, formAction, isPending] = useActionState(
    updateReviewAction,
    initialState
  );

  // Close the form automatically when update succeeds
  useEffect(() => {
    if (state.success) {
      setEditing(false);
    }
  }, [state]);

  // Show toast feedback
  useEffect(() => {
    if (state.message) {
      if (state.success) toast.success(state.message);
      else toast.error(state.message);
    }
  }, [state]);

  return (
    <div className="mt-4">
      {editing ? (
        <form action={formAction} className="space-y-3">
          {/* Hidden input passes the review ID */}
          <input type="hidden" name="id" value={review.id} />

          <div>
            <label className="block text-sm font-medium mb-1">Rating:</label>
            <select
              name="rating"
              defaultValue={review.rating}
              className="border p-2 rounded w-full"
              disabled={isPending}
            >
              {[1, 2, 3, 4, 5].map((n) => (
                <option key={n} value={n}>{"⭐".repeat(n)}</option>
              ))}
            </select>
          </div>

          <div>
            <label className="block text-sm font-medium mb-1">Review:</label>
            <textarea
              name="text"
              defaultValue={review.text}
              className="w-full border p-2 rounded"
              rows={3}
              disabled={isPending}
            />
          </div>

          <div className="flex gap-2">
            <button
              type="submit"
              disabled={isPending}
              className="bg-green-500 text-white px-4 py-2 rounded disabled:bg-gray-400"
            >
              {isPending ? "Saving..." : "Save"}
            </button>
            <button
              type="button"
              onClick={() => setEditing(false)}
              className="text-gray-500 px-4 py-2"
            >
              Cancel
            </button>
          </div>
        </form>
      ) : (
        <button
          onClick={() => setEditing(true)}
          className="bg-blue-500 text-white px-4 py-2 rounded hover:bg-blue-600"
        >
          Edit
        </button>
      )}
    </div>
  );
}
```

### Uncontrolled Inputs — `defaultValue`

Notice: `defaultValue={review.text}` and `defaultValue={review.rating}` — not `value={editText}`.

**Why?** Server Actions read from `FormData`, not from React state. The form holds the value natively, and when submitted, `formData.get("text")` retrieves it. No need for `useState` to track the input.

This is the key simplification from the Route Handler version, which needed `value={editText}` + `onChange` because it had to pass the value to `axios.put()` manually.

### Auto-Closing on Success

```tsx
useEffect(() => {
  if (state.success) {
    setEditing(false);
  }
}, [state]);
```

When the action returns `{ success: true }`, `state` updates, this `useEffect` fires, and the form automatically closes. The user doesn't need to click "Cancel" after saving.

## Full Flow

```
User sees review + "Edit" button (Server Component page)
  ↓
User clicks "Edit"
  → setEditing(true) in EditReviewForm (Client Component)
  → Form appears with defaultValue prefilled from review prop
  ↓
User edits text/rating, clicks "Save"
  → Form submits via action={formAction}
  → updateReviewAction(formData) runs on server
     → formData.get("id"), formData.get("text"), formData.get("rating")
     → updateReview(id, { text, rating }) in data layer
     → revalidatePath("/reviews/{id}") and revalidatePath("/reviews")
     → returns { success: true, message: "Review updated" }
  → state updates, isPending returns to false
  → useEffect sees state.success → setEditing(false) → form closes
  → toast.success("Review updated")
  → Page re-renders with fresh data
```

## Server Actions CRUD — Complete

All four operations now use Server Actions:

| Operation | Action | Component |
|---|---|---|
| Create | `addReviewAction` | `ReviewFormServer` |
| Read | (Server Component direct call) | `ReviewListServer` |
| Update | `updateReviewAction` | `EditReviewForm` |
| Delete | `deleteReviewAction` | `DeleteButtonServer` |

## What It Is NOT

- **The detail page is not a Client Component** — it only reads data, so Server Component is correct.
- **`EditReviewForm` doesn't need `useState` for text/rating** — that's the whole point of uncontrolled inputs.
- **`revalidatePath` is called twice on purpose** — edit changes data on both the detail and list pages.

## In Your Own Words

<details>
<summary>Question 1: What's the split between the Server Component page and the Client Component EditReviewForm?</summary>
<p><strong>Answer:</strong> The page (Server Component) reads data directly from the data layer — `getReviewById()` with no fetch needed. It renders the view. The `EditReviewForm` (Client Component) handles interactivity only — the edit toggle, form submission, loading states. The page passes `review` as a prop to the form.</p>
</details>

<details>
<summary>Question 2: How does `useEffect` auto-close the edit form on success?</summary>
<p><strong>Answer:</strong> When `updateReviewAction` returns `{ success: true }`, `useActionState` updates `state`. The `useEffect` watching `[state]` fires, checks `state.success`, and calls `setEditing(false)`. The form disappears, returning to view mode.</p>
</details>

<details>
<summary>Question 3: Why use `defaultValue` instead of `value` for the edit inputs?</summary>
<p><strong>Answer:</strong> `defaultValue` makes the input uncontrolled — the browser manages the value after initial render. The Server Action reads from `FormData` directly, so React doesn't need to track every keystroke. This eliminates `editText` and `editRating` state, plus `onChange` handlers.</p>
</details>

<details>
<summary>Question 4: Why does `updateReviewAction` call `revalidatePath` twice?</summary>
<p><strong>Answer:</strong> Editing a review changes data visible on two pages: the detail page (`/reviews/{id}`) shows the review, and the list page (`/reviews`) also displays it. Both paths need revalidation to show the updated text.</p>
</details>
