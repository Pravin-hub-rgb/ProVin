## Kya Banana Hai?

Ek **Reviews & Ratings App** — jisme users products pe reviews de sakein.

Zomato socho. Tum ek restaurant dekhte ho — usmein reviews hain. Kisi ne 5 star diya, kisi ne 3. Kisi ne likha "Bahut achha tha", kisi ne likha "Average tha." Tum bhi review de sakte ho — text likho, rating do, submit karo.

Wahi banana hai — par simplified version. Koi real restaurant nahi, koi real users nahi — bas **2 products** hain aur unpe reviews hain.

**Kyun ye project?** Kyunki ismein Batch 3 ke saare concepts ek saath aayenge:
- **Route Handlers** — API endpoints banenge (GET, POST, PUT, DELETE)
- **Server Actions** — Form seedha server function call karega
- **HTTP Methods** — har operation ka apna method
- **useActionState** — pending state + messages
- **Revalidation** — data change ho toh page refresh ho

## Kaunse Pages Chahiye?

| Route | Kya dikhega | Concept |
|-------|------------|---------|
| `/reviews` | Saare products ki list + unke reviews + form | GET (list), POST (add review) |
| `/reviews/[id]` | Ek review ka detail + Edit button + form | GET (single), PUT (edit), DELETE (delete) |

Bas 2 pages. Par inmein saare CRUD operations hain.

## Data Ka Shape Kya Hai?

Pehle socho — **UI pe kya dikhega?**

**List page pe:**
- Product ka naam (Product 1, Product 2)
- Uske reviews ki list
- Har review mein: text, rating (1-5 stars), date
- Naya review add karne ka form (textarea + rating select + submit button)

**Detail page pe:**
- Ek review ka poora text
- Rating stars
- Date
- Edit button → click pe form khule
- Delete button

Ab socho — **in sab ke liye data mein kya chahiye?**

Har review ke liye:
- **`id`** — unique number (1, 2, 3...) — taaki delete/edit mein pata chale kaunsa review hai
- **`productId`** — kaunsa product hai (1 ya 2) — list page pe filtering ke liye
- **`text`** — review ka text — user likhta hai
- **`rating`** — 1 se 5 — user select karta hai
- **`createdAt`** — date — jab review add hua

**Har field ka reason hai:**
- `id` bina delete/edit nahi ho payega — "kaunsa review?" ka answer
- `productId` bina list page pe "Product 1 ke reviews" filter nahi ho payenge
- `text` aur `rating` — review ka asli content
- `createdAt` — user ko pata chale "kab likha tha"

## Data Flow Kaise Hoga?

Ab tak jo bhi banaya — 3.1 mein route handler, 3.3 mein server action — sab mein data kisi na kisi jagah se aata tha. Yahan bhi wahi hoga.

**Data rahega ek JSON file mein** — `reviews.json`. Kyunki abhi database nahi seekha, toh file hi kaam karegi. `fs` module se file padhenge aur likhenge (3.1 mein seekha tha).

**Functions banenge** — `lib/reviews.ts` mein:
- `getAllReviews()` — saare reviews lao
- `getReviewsByProduct(id)` — ek product ke reviews
- `addReview(data)` — naya review add karo
- `updateReview(id, data)` — review edit karo
- `deleteReview(id)` — review delete karo

**Do versions banenge:**
1. **Route Handler version** — API endpoints, client se axios se call
2. **Server Actions version** — Direct function calls, bina API ke

Dono mein data layer same rahega — sirf **tareeka** alag hoga. Pehle Route Handler version banayenge (kyunki ye fundamental hai), phir Server Actions se compare karenge.
