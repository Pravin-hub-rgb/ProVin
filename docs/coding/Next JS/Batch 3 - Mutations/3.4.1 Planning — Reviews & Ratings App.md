Batch 3 ke saare concepts seekh liye - Route Handlers, Server Actions, HTTP Methods, useActionState, Revalidation. Ab sab kuch **ek jagah practice** karenge - **Reviews & Ratings App.**

## Kya Banega?

Ek app jisme:
- Products ki list ho (GET)
- Har product pe reviews ho (GET)
- Users review add kar sakein (POST)
- Users review edit kar sakein (PUT) — detail page pe, 3.2 wala pattern
- Users review delete kar sakein (DELETE)
- Pending state dikhe jab review submit ho raha ho
- Success/error messages aayein
- Review add hone ke baad page automatically refresh ho

## Do Versions Banenge

### Version 1: Route Handlers (REST)

Ye **fundamental** approach hai - API endpoints banenge, client se call hoga.

> **Ek naya cheez:** 3.1–3.3 mein humne `fetch()` se HTTP calls kiye. Ab is project se **axios** use karenge — ek popular HTTP client library jo `fetch()` se zyada concise hai. Basic theory 3.4.2 ke shuruaat mein milegi, aur phir project ke saath-saath seekhenge.

```
/app
  /api
    /reviews
      route.ts          ← GET, POST handle karega
      [id]/route.ts     ← PUT, DELETE handle karega
  /components
    ReviewForm.tsx      ← Client Component (form)
    ReviewList.tsx      ← Server Component (data display)
  /lib
    reviews.ts          ← Data layer (fs module)
    reviews.json        ← Data storage (JSON file)
  /reviews
    page.tsx            ← Main page
    [id]/page.tsx       ← Detail page (view + edit)
```

**Features:**
- `/api/reviews` - GET saare reviews, POST naya review
- `/api/reviews/[id]` - PUT review edit, DELETE review
- `/reviews/[id]` - detail page pe Edit button → form khulta hai (3.2 pattern)
- Client mein `axios` se call hota hai (fetch ki jagah)
- JSON.stringify, headers, method — sab automatically

### Version 2: Server Actions (Next.js Shortcut)

Ye **Next.js specific** approach hai - API route ki zaroorat nahi, form seedha server function call karta hai.

```
/app
  /actions.ts           ← Server Actions (add, edit, delete)
  /components
    ReviewForm.tsx      ← Client Component (form + useActionState + toast)
    ReviewList.tsx      ← Server Component (data display)
  /lib
    reviews.ts          ← Data layer (fs module)
    reviews.json        ← Data storage (JSON file)
  /reviews
    page.tsx            ← Main page
    [id]/page.tsx       ← Detail page (view + edit)
```

**Features:**
- Koi `/api/reviews` nahi - direct `addReview` / `updateReview` actions
- Form `action={...}` se call hota hai
- `/reviews/[id]` - detail page pe Edit button → form khulta hai
- `useActionState` se pending state + return value (`isPending` + `state`)
- `sonner` toast se success/error messages (3.3.1 wala pattern)
- `revalidatePath` se auto refresh

## Data Layer - Dono Versions Ke Liye

Dono versions mein same data use hoga - sirf tareeka alag hoga (Route Handler vs Server Action). Isliye pehle data layer banate hain.

### Data Ka Structure (`Review` Type)

```tsx
export type Review = {
  id: number;
  productId: number;
  text: string;
  rating: number;
  createdAt: string;
};
```

**TypeScript `type` kya hai?** Ye define karta hai ki data ka **shape** kaisa hoga. Jaise form mein hota hai ki "naam text hoga, age number hoga" - waise hi `type` se data ka structure fix hota hai.

- `id: number` - number hoga (1, 2, 3...)
- `productId: number` - kaunsa product hai
- `text: string` - review ka text
- `rating: number` - 1 se 5 tak
- `createdAt: string` - date (text format mein)

### Storage — JSON File (Real Storage)

3.1 mein seekha — `fs` module se JSON file padh sakte hain. Yahan bhi wahi pattern hai:

```tsx
// lib/reviews.ts
import { readFileSync, writeFileSync } from "fs";
import path from "path";

const filePath = path.join(process.cwd(), "app", "lib", "reviews.json");
```

Production mein database hota hai (PostgreSQL, MongoDB). Abhi ke liye **JSON file** use karenge — `fs` module se file padhte aur likhte hain. Data save rahega — server restart hone pe bhi nahi udEGA.

### Functions Ka Breakdown

```tsx
export function getAllReviews(): Review[] {
  const data = readFileSync(filePath, "utf-8");
  return JSON.parse(data);
}

export function getReviewsByProduct(productId: number): Review[] {
  return getAllReviews().filter((r) => r.productId === productId);
}
```

**Notice kiya?** `getAllReviews()` mein ab `readFileSync` hai — har baar file se fresh data padhta hai. `getReviewsByProduct()` bhi `getAllReviews()` call karta hai — same function, sirf `filter()` lagaya.

**`filter()` kya hai?** 3.2 mein `findIndex()` seekha tha - ye uska cousin hai. `filter()` array mein se **saare matching elements** dhoondhta hai:

```tsx
const reviews = [
  { id: 1, productId: 1, text: "Achha" },
  { id: 2, productId: 1, text: "Average" },
  { id: 3, productId: 2, text: "Excellent" },
];

const product1Reviews = reviews.filter((r) => r.productId === 1);
// [{ id: 1, ... }, { id: 2, ... }] - dono product 1 ke hain
```

**`find()` vs `filter()`:**
- `find()` - pehla match dhoondhta hai (ek object)
- `filter()` - saare matches dhoondhta hai (array)

### `addReview` Function - Advanced Concepts

```tsx
export function addReview(data: Omit<Review, "id" | "createdAt">): Review | null {
  if (!data.text || !data.text.trim()) return null;  // ← Empty check
  if (!data.rating || data.rating < 1 || data.rating > 5) return null;  // ← Rating check

  const reviews = getAllReviews();
  const newReview: Review = {
    ...data,
    text: data.text.trim(),
    id: reviews.length + 1,
    createdAt: new Date().toISOString().split("T")[0],
  };
  reviews.push(newReview);
  writeFileSync(filePath, JSON.stringify(reviews, null, 2));
  return newReview;
}
```

**Notice kiya?** `addReview` mein ab 3 steps hain: (1) validation — empty text ya galat rating ho toh `null` return, (2) file se padho + naya review add karo, (3) file mein likho. **Validation hamesha pehle karo** — invalid data ko pakdo, save mat karo.

**`Omit<Review, "id" | "createdAt">` kya hai?**

Ye TypeScript utility type hai. Ye bolti hai - "Review type jaisa ho, par `id` aur `createdAt` chhod do". Kyunki ye dono function khud generate karega:

```tsx
// Full Review type
{ id: number, productId: number, text: string, rating: number, createdAt: string }

// Omit<Review, "id" | "createdAt">
{ productId: number, text: string, rating: number }
// id aur createdAt hat gaye!
```

**Kyun?** Kyunki `id` aur `createdAt` function ke andar banenge - user ko ye nahi dena padega.

**`|` (pipe) kya hai?** TypeScript mein ye "ya" hota hai - `"id" | "createdAt"` matlab "id ya createdAt".

### `new Date().toISOString().split("T")[0]` Kya Hai?

Ye **aaj ki date** nikalta hai:

```tsx
new Date()                    // Mon Jan 15 2025 10:30:00 GMT+0000
.toISOString()                // "2025-01-15T10:30:00.000Z"
.split("T")                   // ["2025-01-15", "10:30:00.000Z"]
[0]                           // "2025-01-15"
```

**Breakdown:**
1. `new Date()` - current date/time object banata hai
2. `.toISOString()` - usko string format mein convert karta hai (ISO standard)
3. `.split("T")` - "T" se todta hai (date aur time alag)
4. `[0]` - pehla hissa lo (sirf date)

**Result:** `"2025-01-15"` - sirf date, time ke bina.

### `deleteReview` Function

```tsx
export function deleteReview(id: number): boolean {
  const reviews = getAllReviews();
  const index = reviews.findIndex((r) => r.id === id);
  if (index === -1) return false;
  reviews.splice(index, 1);
  writeFileSync(filePath, JSON.stringify(reviews, null, 2));
  return true;
}
```

Wahi `findIndex()` + `splice()` pattern — par ab file mein bhi save ho raha hai. **Same 3 steps:** (1) file se padho, (2) change karo, (3) file mein likho.

### `getReviewById` Function

Edit ke liye pehle wo ek review chahiye jiska data form mein prefill karna hai. Sirf wo review dhoondo:

```tsx
export function getReviewById(id: number): Review | null {
  return getAllReviews().find((r) => r.id === id) ?? null;
}
```

`.find()` pehle match hota element return karta hai, warna `undefined`. `?? null` se `undefined` ko `null` bana dete hain — taaki caller ko pata chale ki \"review nahi mila\".

### `updateReview` Function

Ab existing review ko badlo — same `findIndex()` waala pattern, par `splice()` ke bajaye **spread** se overwrite karo:

```tsx
export function updateReview(
  id: number,
  data: { text: string; rating: number }
): Review | null {
  const reviews = getAllReviews();
  const index = reviews.findIndex((r) => r.id === id);

  if (index === -1) return null;

  const updated: Review = { ...reviews[index], ...data, text: data.text.trim() };
  reviews[index] = updated;
  writeFileSync(filePath, JSON.stringify(reviews, null, 2));

  return updated;
}
```

`{ ...reviews[index], ...data }` — purane review ki saari properties copy hui (`id`, `productId`, `createdAt`), phir `data` ki nayi (`text`, `rating`) overwrite hui. **`id` aur `createdAt` safe rehte hain** kyunki `data` mein woh nahi hain. Wahi 3.2 mein seekha `findIndex()` + spread pattern — bas ab file mein save bhi ho raha hai.

## Comparison: Dono Versions

| | Version 1 (Route Handler) | Version 2 (Server Actions) |
|---|---|---|
| **Boilerplate** | Zyada - route file, axios call | Kam - sirf function |
| **Client code** | `axios.post()` — auto JSON, headers | `action={function}` |
| **Pending state** | Khud `useState` se banana padega | `useActionState` ka `isPending` |
| **Error handling** | Khud try/catch | `useActionState` return + `sonner` toast |
| **Revalidation** | Route Handler mein `revalidatePath` | Server Action mein `revalidatePath` |
| **External clients** | Support karta hai | Nahi |

---

## Kya Seekhoge?

1. **Version 1 se:** REST API banana, GET/POST/PUT/DELETE, **axios** (naya HTTP client — fetch ki jagah), manual pending state
2. **Version 2 se:** Server Actions, useActionState, toast, revalidation, auto refresh
3. **Edit flow se:** `getReviewById` + `updateReview`, aur detail page (`/reviews/[id]`) pe Edit button → form khulne wala pattern (3.2 se repeat)
4. **Comparison se:** Kab kya use karna hai, boilerplate ka fark, control vs convenience
