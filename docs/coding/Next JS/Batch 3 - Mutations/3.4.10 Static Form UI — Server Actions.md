# Static Form UI — Server Actions Version (3.4.10)

## Where We Left Off

In 3.4.9, we planned the Server Actions version of the Reviews app. Now we'll build the **static form UI** first — same incremental approach as the Route Handler version (3.4.7 Step 1).

## Why Static First?

Same reason as 3.4.2 and 3.4.7 — confirm the UI looks right before wiring up functionality. The form structure itself is similar to the Route Handler version, but there's a key difference in how inputs work.

## Key Difference: Uncontrolled vs Controlled

**Route Handler version (3.4.7):**
```tsx
// Controlled — React tracks the state
<input value={text} onChange={(e) => setText(e.target.value)} />
```

**Server Actions version:**
```tsx
// Uncontrolled — form tracks the value
<input name="text" defaultValue="initial" />
```

With controlled inputs, React's `useState` tracks every keystroke. With uncontrolled inputs, the browser manages the value, and the `name` attribute is used by `FormData` to extract it on submit.

This matters because Server Actions read from `FormData` — they don't need React state. The form itself holds the data until submission.

## Step 1: Create the Form Component

```tsx
// app/components/ReviewFormServer.tsx
"use client";

export function ReviewFormServer({ productId }: { productId: number }) {
  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    console.log("Form submitted — no action yet");
  };

  return (
    <form onSubmit={handleSubmit} className="space-y-3 border p-4 rounded bg-white mt-4">
      <h3 className="font-bold">New Review</h3>

      {/* Hidden input — passes productId to the server action */}
      <input type="hidden" name="productId" value={productId} />

      <div>
        <label className="block text-sm font-medium mb-1">Rating:</label>
        <select
          name="rating"
          defaultValue={5}
          className="border p-2 rounded w-full"
        >
          {[1, 2, 3, 4, 5].map((n) => (
            <option key={n} value={n}>{"⭐".repeat(n)}</option>
          ))}
        </select>
      </div>

      <div>
        <label className="block text-sm font-medium mb-1">Review:</label>
        <textarea
          name="text"
          placeholder="Write your review..."
          className="w-full border p-2 rounded"
          rows={3}
        />
      </div>

      <button
        type="submit"
        className="bg-blue-500 text-white px-4 py-2 rounded hover:bg-blue-600"
      >
        Submit Review
      </button>
    </form>
  );
}
```

### What's Different From the Route Handler Version?

| Route Handler | Server Actions |
|---|---|
| `useState` for text and rating | No `useState` — form holds the data |
| `value={text}` — controlled | `name="text"` — uncontrolled |
| `onChange={(e) => setText()}` | Not needed |
| `onSubmit={handleSubmit}` | Will become `action={formAction}` |

### Key Observations

1. **No `useState` imports** — the form manages its own values via native HTML behavior
2. **`name` attribute instead of `value`** — this is how the Server Action will find the data (`formData.get("text")`)
3. **`defaultValue` instead of `value`** — sets the initial value but doesn't track changes
4. **`<input type="hidden">`** — passes `productId` to the form (same pattern as hidden `id` in delete)

## What It Is NOT

- **This form doesn't do anything yet** — submit just logs to console. The Server Action connection comes in 3.4.11.
- **Uncontrolled doesn't mean "no JavaScript"** — the form still has `"use client"` because it will use `useActionState` later.
- **The `onSubmit` handler is temporary** — we'll replace it with `action={formAction}` in the next step.

## In Your Own Words

<details>
<summary>Question 1: What's the difference between `value` and `defaultValue` on form inputs?</summary>
<p><strong>Answer:</strong> `value` makes the input controlled — React manages the value, and every change updates state via `onChange`. `defaultValue` sets the initial value but lets the browser manage subsequent changes. After initial render, React doesn't track the input.</p>
</details>

<details>
<summary>Question 2: Why does a Server Action form use `name` attributes instead of `value`/`onChange`?</summary>
<p><strong>Answer:</strong> Server Actions receive data as `FormData` — they extract values by name using `formData.get("fieldName")`. The `name` attribute is how `FormData` identifies which value belongs to which field. No React state management is needed.</p>
</details>

<details>
<summary>Question 3: What's the purpose of `<input type="hidden" name="productId" />`?</summary>
<p><strong>Answer:</strong> Hidden inputs pass data to the Server Action that the user doesn't manually enter. The form is rendered for a specific product, so `productId` must reach the action — but there's no visible input for it. The hidden field carries this value in the `FormData` submission.</p>
</details>

<details>
<summary>Question 4: Is there less code without `useState`?</summary>
<p><strong>answer:</strong> Yes. Without `useState`, we eliminate the state declaration, the `onChange` handlers, and the controlled `value` props. The form is simpler. But we still need `"use client"` because the final version uses `useActionState` for pending states and messages.</p>
</details>
