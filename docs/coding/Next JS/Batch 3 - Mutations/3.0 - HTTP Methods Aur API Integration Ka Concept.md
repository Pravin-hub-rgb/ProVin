# HTTP Methods & API Integration Concepts (3.0)

## Where We Left Off

In the previous files, we learned how to make our pages look good and load data. Our Next.js app could fetch data from the server and render it in the browser, but there was no way to send data back — no way to create, update, or delete records on the server.

Remember how we used `getServerSideProps` and `getStaticProps` to fetch data and show it on our pages? That's great for displaying things, but what about when we need to save data? What about when we need to update something or delete it?

That's what this batch is all about - making our app interactive, not just a display board.

## Broader Goal

Think about every app you use daily - Instagram, Gmail, Todoist, or even the comment section on a blog:

- You post a comment (create new data)
- You like a photo (update existing data)
- You delete a message (remove data)
- You edit your profile (update data)

All of these actions involve sending data to a server, not just receiving it.

In technical terms, we're moving beyond `GET` requests (where we just read data) to using other HTTP methods that let us write, update, and delete data.

## What Are HTTP Methods?

Before we dive into coding, let's understand the four most common HTTP methods:

Here's how the four most common HTTP methods move data between the browser (client) and the server:

| HTTP Method | Data Flow (Browser ↔ Server) | What It Does |
|-------------|------------------------------|--------------|
| `GET` | Browser requests data → Server reads store → sends data back | Read/view existing data (safe, doesn't change anything) |
| `POST` | Browser sends new data → Server validates and saves it | Create new data |
| `PUT` | Browser sends full updated record → Server replaces existing record | Update/replace existing data completely |
| `DELETE` | Browser sends an id → Server removes that record | Remove data |

### GET - Reading Data

You've already seen this - when we use `getServerSideProps` to fetch data, Next.js sends a GET request to our API. The browser asks for data, the server reads from its store and sends it back. Nothing changes on the server.

### POST - Creating New Data

When you sign up for a new account, post a new tweet, or create a new todo item - that's a POST. You're adding something new. The browser sends the new record in the request body; the server validates it, writes it to the store, and responds with the created record.

### PUT/PATCH - Updating Existing Data

When you edit your profile picture or change the title of a blog post, you're updating data. PUT typically replaces the entire thing, while PATCH makes partial changes. The browser sends the full updated record; the server finds the existing one, replaces it, and responds with the updated record.

### DELETE - Removing Data

When you delete an email or remove an item from your cart - that's DELETE. The browser sends the id of the record to remove; the server deletes it from the store and responds with a success status.

## API Integration: The Big Picture

When your Next.js frontend needs to talk to a backend server (which could be your own API or a third-party service), here's what happens:

1. **Your browser sends a request** using one of the HTTP methods above
2. **The server processes the request** - it validates data, checks permissions, writes to database, etc.
3. **The server sends a response** back with a status code and optionally data

### Using `fetch()` in the Browser

The most common way to make HTTP requests in the browser is using the `fetch()` function. Here's the basic pattern:

```javascript
fetch('https://api.example.com/data')
  .then(response => response.json())
  .then(data => {
    console.log(data);
  })
  .catch(error => {
    console.error('Error:', error);
  });
```

The `fetch()` function takes two arguments:
- The URL to call
- An options object (optional) where you specify the method, headers, and body

### POST Example:

```javascript
fetch('https://api.example.com/posts', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    title: 'My New Post',
    content: 'Hello world!',
  }),
})
  .then(response => response.json())
  .then(data => console.log('Success:', data))
  .catch(error => console.error('Error:', error));
```

### Handling Response Status Codes

The server always sends back a status code with every response:

- `200 OK` - Everything worked fine
- `201 Created` - A new resource was successfully created (common after POST)
- `400 Bad Request` - The client sent something invalid (missing fields, bad format)
- `401 Unauthorized` - You need to log in first
- `403 Forbidden` - You don't have permission
- `404 Not Found` - The resource doesn't exist
- `500 Internal Server Error` - Something went wrong on the server

## What It Is NOT

- **HTTP methods are not the same as HTTP status codes** - methods are instructions (GET, POST), status codes are responses (200, 404).
- **POST is not the only way to send data** - PUT, PATCH, and DELETE also send data, just with different meanings.
- **You don't need a backend to understand this** - the concepts apply whether you're building a frontend that talks to an existing API or building both ends yourself.

<summary>Question 1: What's the difference between POST and PUT? Give an example from daily life.</summary>
<p><strong>Answer:</strong> POST creates something brand new (the browser sends a new record that the server adds to its store), while PUT modifies something that already exists (the browser sends the full updated record that the server uses to replace the existing one). Both send data to the server, but POST adds to the collection while PUT replaces or updates an existing item.</p>
</details>

<details>
<summary>Question 2: What HTTP status code should the server return after a successful POST request?</summary>
<p><strong>Answer:</strong> The server should typically return <code>201 Created</code> (not just 200 OK), because a new resource was successfully created.</p>
</details>

<details>
<summary>Question 4: What's the difference between headers and body in a fetch() request?</summary>
<p><strong>Answer:</strong> Headers are metadata about the request (like saying "I'm sending JSON"), while the body is the actual data payload (like the JSON string with our data). You need to set the Content-Type header to application/json when sending a JSON body.</p>
