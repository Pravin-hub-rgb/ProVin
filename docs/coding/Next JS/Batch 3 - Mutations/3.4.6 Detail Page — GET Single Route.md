## Step 1: Create GET Route for Reviews

The client component calls `axios.get("/api/reviews?productId=1")`. We need a route that handles this:

```tsx
// app/api/reviews/route.ts
import { NextResponse } from "next/server";
import { getAllReviews, getReviewsByProduct } from "@/lib/reviews";

export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const productId = searchParams.get("productId");

  if (productId) {
    const reviews = getReviewsByProduct(Number(productId));
    return NextResponse.json(reviews);
  }

  const reviews = getAllReviews();
  return NextResponse.json(reviews);
}
```

### How It Works

1. **`new URL(request.url)`** — Parse the URL to extract query parameters.
2. **`searchParams.get("productId")`** — Get the `productId` query param (or `null` if not present).
3. **If productId exists** — return reviews for just that product using `getReviewsByProduct()`.
4. **Otherwise** — return all reviews using `getAllReviews()`.

This single endpoint handles both cases — all reviews or filtered by product.

## Server Component — The Alternative Approach

Now let's see the **Server Component** version. Instead of the client fetching data, the Server Component reads the data layer directly:

```tsx
// app/components/ReviewListServer.tsx
import { getReviewsByProduct } from "@/lib/reviews";
import Link from "next/link";

export function ReviewListServer({ productId }: { productId: number }) {
  const reviews = getReviewsByProduct(productId);

  if (reviews.length === 0) {
    return <p className="text-gray-500">No reviews yet.</p>;
  }

  return (
    <div className="space-y-2">
      <h3 className="font-bold">Reviews ({reviews.length})</h3>
      {reviews.map((review) => (
        <div key={review.id} className="border p-2 rounded bg-white">
          <div className="flex justify-between items-center mb-1">
            <span>{"⭐".repeat(review.rating)}</span>
            <span className="text-sm text-gray-500">{review.createdAt}</span>
          </div>
          <p className="text-gray-700">{review.text}</p>
        </div>
      ))}
    </div>
  );
}
```

### Client vs Server — Side by Side

| Aspect | Client Component | Server Component |
|---|---|---|
| Where data is fetched | `axios.get()` in `useEffect` | Direct function call |
| Network request | Yes — HTTP call to API route | No — direct data layer call |
| Loading state | Yes — required | No — data ready at render |
| `"use client"` | Required | Not needed |
| `useState` / `useEffect` | Required | Not needed |

**The key insight:** Server Components call data layer functions directly because they run on the server. Client Components must go through an API route because they run in the browser (where `fs` doesn't exist).

## Which Should You Use?

**Use Server Component** when:
- You only need to display data (read-only)
- No user interaction needed (no forms, no click handlers)
- You want simpler code and better performance
- This is a Next.js-only app

**Use Client Component** when:
- You need forms, click handlers, or interactive state
- You need to manage pending/loading states
- You need to show real-time feedback (toasts, inline messages)
- You need browser-only APIs (`window`, `localStorage`)

## Common Mistakes

- **Client Component calling `fs`** — This will fail. Use an API route or Server Component instead.
- **Missing `"use client"`** on interactive components — React hooks only work in Client Components.
- **Forgetting loading states in Client Components** — data fetches asynchronously; handle the loading phase.
- **Not handling `null` from `searchParams`** — `productId` might not exist in the URL.

<details>
<summary>Question 2: What advantage does a Server Component have for displaying data?</summary>
<p><strong>Answer:</strong> Server Components run at request time on the server. They have data ready before sending HTML to the client — no loading spinners, no flash of empty content. They also skip an unnecessary network round-trip (no fetch → API → response cycle) since they call the data layer directly.</p>
</details>

<summary>Question 3: When would you choose a Client Component over a Server Component for reading data?</summary>
<p><strong>Answer:</strong> When you also need client-side interactivity — form submission, click handlers, state management, or real-time updates. If the component only displays data with no interaction, Server Component is better.</p>

## Why a Detail Page?

On the list page, each review is a compact card — stars, date, short text. But what if the review text is long and gets cut off? What if users want to see the full review and have edit/delete options?

This is like clicking on an email in your inbox — the list gives you a preview, but the detail view shows the full content with actions.

## Step 1: GET Single Route

First, create a route that returns one review by ID:

```tsx
// app/api/reviews/[id]/route.ts
import { NextResponse } from "next/server";
import { getReviewById } from "@/lib/reviews";

export async function GET(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const review = getReviewById(Number(id));

  if (!review) {
    return NextResponse.json(
      { error: "Review not found" },
      { status: 404 }
    );
  }

  return NextResponse.json(review);
}
```

### How It Works

1. **`[id]/route.ts`** — The `[id]` folder makes this a dynamic route. Any URL like `/api/reviews/1` or `/api/reviews/5` will match.
2. **`{ params }`** — Next.js passes the URL parameters. `params.id` contains the `"1"` from the URL.
3. **`Number(id)`** — Convert the string `"1"` to a number `1` for the data layer function.
4. **`getReviewById`** — Fetch the specific review.
5. **404 handling** — If the review doesn't exist, return a 404 error.

## Step 2: Detail Page — Server Component

The detail page will be a Server Component — it reads data directly from the data layer (no axios needed):

```tsx
// app/reviews/[id]/page.tsx
import { getReviewById } from "@/lib/reviews";
import { notFound } from "next/navigation";
import Link from "next/link";

export default async function ReviewPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const review = getReviewById(Number(id));

  if (!review) {
    notFound();
  }

  return (
    <div className="max-w-md mx-auto p-4 border rounded bg-white">
      <Link href="/reviews" className="text-blue-500 hover:underline text-sm mb-4 block">
        ← Back to Reviews
      </Link>

      <div className="flex justify-between items-center mb-3">
        <span className="text-2xl">{"⭐".repeat(review.rating)}</span>
        <span className="text-sm text-gray-500">{review.createdAt}</span>
      </div>

      <p className="text-lg mb-4">{review.text}</p>

      <div className="border-t pt-3 text-sm text-gray-500">
        Review ID: {review.id} | Product: {review.productId}
      </div>
    </div>
  );
}
```

### Key Points

1. **`async function`** — Server Components can be async, so we can `await params` directly.
2. **`getReviewById(Number(id))`** — Direct data layer call. No `fetch()`, no `axios`.
3. **`notFound()`** — If the review doesn't exist, Next.js shows a 404 page automatically.
4. **`Link`** — Back to the list page.
