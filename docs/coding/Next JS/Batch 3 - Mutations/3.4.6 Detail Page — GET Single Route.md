# Detail Page — GET Single + Review Display (3.4.6)

## Where We Left Off

In 3.4.5, we built the GET API route that serves reviews to the client. The list page now shows all reviews with proper data from the data layer. But clicking a review does nothing — there's no detail page yet.

Today we'll build the **detail page** — `/reviews/[id]` — that shows a single review with all its details and an "Edit" button.

## Why a Detail Page?

On the list page, each review is a compact card — stars, date, short text. But what if the review text is long and gets cut off? What if users want to see the full review and have edit/delete options?

This is like clicking on an email in your inbox — the list gives you a preview, but the detail view shows the full content with actions.

## Step 1: GET Single Route

First, create a route that returns one review by ID:

```tsx
// app/api/reviews/[id]/route.ts
import { NextResponse } from "next/server";
import { getReviewById } from "@/lib/reviews";

export async function GET(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const review = getReviewById(Number(id));

  if (!review) {
    return NextResponse.json(
      { error: "Review not found" },
      { status: 404 }
    );
  }

  return NextResponse.json(review);
}
```

### How It Works

1. **`[id]/route.ts`** — The `[id]` folder makes this a dynamic route. Any URL like `/api/reviews/1` or `/api/reviews/5` will match.
2. **`{ params }`** — Next.js passes the URL parameters. `params.id` contains the `"1"` from the URL.
3. **`Number(id)`** — Convert the string `"1"` to a number `1` for the data layer function.
4. **`getReviewById`** — Fetch the specific review.
5. **404 handling** — If the review doesn't exist, return a 404 error.

## Step 2: Detail Page — Server Component

The detail page will be a Server Component — it reads data directly from the data layer (no axios needed):

```tsx
// app/reviews/[id]/page.tsx
import { getReviewById } from "@/lib/reviews";
import { notFound } from "next/navigation";
import Link from "next/link";

export default async function ReviewPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const review = getReviewById(Number(id));

  if (!review) {
    notFound();
  }

  return (
    <div className="max-w-md mx-auto p-4 border rounded bg-white">
      <Link href="/reviews" className="text-blue-500 hover:underline text-sm mb-4 block">
        ← Back to Reviews
      </Link>

      <div className="flex justify-between items-center mb-3">
        <span className="text-2xl">{"⭐".repeat(review.rating)}</span>
        <span className="text-sm text-gray-500">{review.createdAt}</span>
      </div>

      <p className="text-lg mb-4">{review.text}</p>

      <div className="border-t pt-3 text-sm text-gray-500">
        Review ID: {review.id} | Product: {review.productId}
      </div>
    </div>
  );
}
```

### Key Points

1. **`async function`** — Server Components can be async, so we can `await params` directly.
2. **`getReviewById(Number(id))`** — Direct data layer call. No `fetch()`, no `axios`.
3. **`notFound()`** — If the review doesn't exist, Next.js shows a 404 page automatically.
4. **`Link`** — Back to the list page.

## Step 3: Add Detail Links to List

Make each review in the list clickable to go to the detail page:

```tsx
// app/components/ReviewListServer.tsx
import Link from "next/link";
import { getReviewsByProduct } from "@/lib/reviews";

export function ReviewListServer({ productId }: { productId: number }) {
  const reviews = getReviewsByProduct(productId);

  if (reviews.length === 0) {
    return <p className="text-gray-500">No reviews yet.</p>;
  }

  return (
    <div className="space-y-2">
      <h3 className="font-bold">Reviews ({reviews.length})</h3>
      {reviews.map((review) => (
        <div key={review.id} className="border p-2 rounded bg-white">
          <Link href={`/reviews/${review.id}`} className="block">
            <div className="flex justify-between items-center mb-1">
              <span>{"⭐".repeat(review.rating)}</span>
              <span className="text-sm text-gray-500">{review.createdAt}</span>
            </div>
            <p className="text-gray-700">{review.text}</p>
          </Link>
        </div>
      ))}
    </div>
  );
}
```

## Test It

```bash
npm run dev
```

1. Visit `http://localhost:3000/reviews` — reviews appear
2. Click any review — navigate to `/reviews/1` (detail page)
3. See the full review with stars, date, and text
4. Click "← Back to Reviews" — return to list
5. Try `/reviews/999` — 404 page (review doesn't exist)

## What It Is NOT

- **The detail page is not a Client Component** — it only reads data, no interactivity yet. It will stay a Server Component for the Server Actions version, but needs to become a Client Component when we add the edit form.
- **`notFound()` is not a custom error page** — it's Next.js's built-in 404. You can customize it later with `app/not-found.tsx`.

## In Your Own Words

<details>
<summary>Question 1: How does the dynamic route `[id]` work?</summary>
<p><strong>Answer:</strong> The `[id]` folder creates a dynamic route. Next.js matches any URL like `/reviews/1`, `/reviews/2`, etc. The ID from the URL is available in `params.id` as a string. The same component handles all review detail pages — the `id` determines which review to display.</p>
</details>

<details>
<summary>Question 2: Why is the detail page a Server Component?</summary>
<p><strong>Answer:</strong> It only reads data — `getReviewById()` is called directly on the server. No need for `useState`, `useEffect`, or axios. Server Components get data at render time, so there's no loading state.</p>
</details>

<details>
<summary>Question 3: What happens if someone visits `/reviews/999`?</summary>
<p><strong>Answer:</strong> `getReviewById(999)` returns `null` (no review with that ID). The `notFound()` call tells Next.js to show a 404 page. The user sees a "Not Found" message instead of an error.</p>
</details>

<details>
<summary>Question 4: Why use `Link` instead of a plain `<a>` tag for navigation?</summary>
<p><strong>Answer:</strong> Next.js's `Link` component gives you client-side navigation — clicking it navigates instantly without a full page reload. It prefetches the target page in the background. A plain `<a>` tag would cause a full page reload, which is slower.</p>
</details>
