# Client Fetch — Axios + useEffect (3.4.4)

## Where We Left Off

In 3.4.3, we built the data layer — `lib/reviews.ts` with all CRUD functions and `reviews.json` as seed data. The functions work, but they're disconnected from the UI. The page is still using hardcoded data from 3.4.2.

Now we connect them. But there's a constraint: the Client Component can't call the data layer directly (because it uses `fs`, which only runs on the server). We need an API route as a middleman. First, let's build the client side that fetches through that API.

## Axios — The HTTP Client

Throughout Batch 3 (3.1-3.3), we used `fetch()` — the browser's built-in HTTP client. It works, but it's verbose:

```tsx
// fetch — verbose
const res = await fetch("/api/reviews", {
  method: "POST",
  body: JSON.stringify({ text, rating }),
  headers: { "Content-Type": "application/json" },
});
const data = await res.json();
```

**Axios** is a third-party library that simplifies this:

```tsx
// axios — concise
const res = await axios.post("/api/reviews", { text, rating });
const data = res.data;
```

No `method`, no `headers`, no `JSON.stringify()`, no `.json()`. Axios handles JSON automatically.

### Fetch vs Axios — Quick Reference

| Operation | `fetch()` | Axios |
|-----------|-----------|-------|
| GET | `fetch(url)` → `await res.json()` | `axios.get(url)` → `res.data` |
| POST | `fetch(url, { method:"POST", headers, body:JSON.stringify(data) })` | `axios.post(url, data)` |
| Response data | Must call `.json()` | Already parsed — `res.data` |
| Error handling | Manual `if (!res.ok)` | Throws automatically for non-2xx |

## Step 1: Create ReviewList — Client Component with Data Fetching

The key insight: **client-side components can't call `fs` directly**. They need an API route. We'll fetch via `axios.get("/api/reviews")`.

```tsx
// app/components/ReviewList.tsx
"use client";

import { useEffect, useState } from "react";
import axios from "axios";
import Link from "next/link";

export function ReviewList({ productId }: { productId: number }) {
  const [reviews, setReviews] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const loadReviews = async () => {
      try {
        const res = await axios.get(`/api/reviews?productId=${productId}`);
        setReviews(res.data);
      } catch (err) {
        console.error("Failed to load reviews:", err);
      } finally {
        setLoading(false);
      }
    };

    loadReviews();
  }, [productId]);

  if (loading) return <p>Loading reviews...</p>;

  if (reviews.length === 0) {
    return <p>No reviews yet.</p>;
  }

  return (
    <div className="space-y-2">
      <h3>Reviews ({reviews.length})</h3>
      {reviews.map((review) => (
        <div key={review.id} className="border p-2 rounded bg-white">
          <Link href={`/reviews/${review.id}`}>
            <div className="flex justify-between">
              <span>{"⭐".repeat(review.rating)}</span>
              <span className="text-sm text-gray-500">{review.createdAt}</span>
            </div>
            <p>{review.text}</p>
          </Link>
        </div>
      ))}
    </div>
  );
}
```

### What's Happening Here

1. **"use client"** at the top — this is a Client Component because it uses `useState` and `useEffect`.
2. **`useState`** — `reviews` starts empty, `loading` starts `true`.
3. **`useEffect`** — on mount (or when `productId` changes), fetch data via axios.
4. **`axios.get`** — calls the API route (which we haven't built yet — that's 3.4.5).
5. **`res.data`** — axios auto-parses JSON, so no `.json()` needed.
6. **Conditional rendering** — loading state, empty state, then the actual list.

**Important:** The link `<Link href={`/reviews/${review.id}`}>` goes to the detail page. That route doesn't exist yet — we'll add it in 3.4.6.

### Why Loading State?

Because data fetching is asynchronous — the component renders before the data arrives. Without a loading state, the user would briefly see an empty list, then suddenly see reviews. The loading text tells them "data is coming."

## Step 2: Update the Page to Use ReviewList

Replace the hardcoded data with the new `ReviewList` component:

```tsx
// app/reviews/page.tsx
import { ReviewList } from "../components/ReviewList";

export default function ReviewsPage() {
  return (
    <div>
      <h1 className="text-2xl font-bold mb-6">Reviews & Ratings</h1>

      <div className="border p-4 rounded mb-6">
        <h2 className="text-xl font-bold mb-3">Product 1</h2>
        <ReviewList productId={1} />
      </div>

      <div className="border p-4 rounded mb-6">
        <h2 className="text-xl font-bold mb-3">Product 2</h2>
        <ReviewList productId={2} />
      </div>
    </div>
  );
}
```

**What changed:**
- The hardcoded `reviews` array is **gone**
- No more `.filter()` — `ReviewList` handles fetching internally
- The page is simpler — it just says "show Product 1 reviews, show Product 2 reviews"

**Note:** The page is still a Server Component (no `"use client"`). It passes `productId` as a prop to the Client Component `ReviewList`, which does the fetching.

## What It Is NOT

- **Axios is not "required"** — `fetch()` works fine. We use axios for the cleaner syntax that becomes especially valuable when making many API calls.
- **Client-side fetching is not "always best"** — it requires loading states, error handling, and an API round-trip. Next topic (3.4.5) shows a simpler approach for Next.js apps.
- **`loading` state is not "optional"** — without it, the user sees a flash of empty content while data loads.

## In Your Own Words

<details>
<summary>Question 1: Why can't the Client Component call `getAllReviews()` directly?</summary>
<p><strong>Answer:</strong> Client Components run in the browser, where Node.js modules like `fs` don't exist. `getAllReviews()` uses `readFileSync` to read a JSON file — that only works on the server. The client must go through an API endpoint that runs on the server.</p>
</details>

<details>
<summary>Question 2: What does `res.data` mean with axios?</summary>
<p><strong>answer:</p>
<p>Axios automatically parses JSON responses. While `fetch()` requires you to call `await res.json()`, axios puts the parsed data in `res.data`. It's a convenience that removes boilerplate.</p>
</details>

<details>
<summary>Question 3: Why is there a loading state in the client component?</summary>
<p><strong>Answer:</strong> Data fetching is asynchronous. The component renders immediately with empty state, then updates when data arrives. Without a loading state, users would see an empty list briefly. The loading text tells them "we're getting the data."</p>
</details>

<details>
<summary>Question 4: Why is `productId` a prop instead of being hardcoded in ReviewList?</summary>
<p><strong>answer:</p>
<p>Making it a prop makes the component reusable. The same component can fetch Product 1's reviews or Product 2's reviews just by changing the prop. Hardcoding would require duplicating the component for each product.</p>
</details>
