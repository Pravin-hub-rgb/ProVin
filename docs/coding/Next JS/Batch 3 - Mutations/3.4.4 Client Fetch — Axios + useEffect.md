## Axios Kya Hai?

3.1-3.3 mein `fetch()` use kiya tha — browser ka built-in HTTP client. Kaam karta hai, par har baar POST ke liye 3 cheezein likhni padti hain:

```tsx
// fetch — har baar ye likho
const res = await fetch("/api/reviews", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text, rating }),
});
const data = await res.json();
```

**Axios** ek library hai jo ye sab khud karti hai:

```tsx
// axios — bas itna
const res = await axios.post("/api/reviews", { text, rating });
const data = res.data;
```

Dekha? No `method`, no `headers`, no `JSON.stringify`, no `.json()`. Axios khud handle karta hai.

### Fetch vs Axios — Quick Comparison

| Kaam | `fetch()` | Axios |
|------|-----------|-------|
| GET | `fetch(url)` → `res.json()` | `axios.get(url)` → `res.data` |
| POST | `fetch(url, { method, headers, body })` | `axios.post(url, data)` |
| JSON | Khud `.json()` bulana padta hai | Already parsed — `res.data` |
| Error | `res.ok` khud check karo | 2xx ke alawa khud throw |

```bash
bun add axios
```

## Step 1: Client Component — ReviewList

Ab `ReviewList` banayenge — client component jo `useEffect` se data fetch kare aur dikhaye.

**SOCH:** Page pe reviews dikhne chahiye. Par data kahan se aayega? Abhi hardcoded array hai. Agar data layer se laana hai toh kuch na kuch toh **fetch** karna padega — server se data maangna padega.

Par **kaise?** Direct data layer call nahi ho sakta client side pe — `fs` module client pe kaam nahi karta. Isliye **API route** chahiye — jo server pe data layer call kare aur client ko data de. Par API route abhi nahi banaya — pehle client component banate hain jo fetch kare.

**Abhi kya karenge?** Pehle GET route banaenge (agla step), tab tak hardcoded data rakhenge — par structure dynamic banayenge taaki baad mein sirf data source change karna ho.

```tsx
// app/components/ReviewList.tsx
"use client";

import { useEffect, useState } from "react";
import axios from "axios";

export function ReviewList({ productId }: { productId: number }) {
  const [reviews, setReviews] = useState<
    { id: number; text: string; rating: number; createdAt: string }[]
  >([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const loadReviews = async () => {
      try {
        const res = await axios.get(`/api/reviews?productId=${productId}`);
        setReviews(res.data);
      } catch (error) {
        console.error("Reviews load nahi ho paye:", error);
      } finally {
        setLoading(false);
      }
    };

    loadReviews();
  }, [productId]);

  if (loading) return <p className="text-gray-500">Loading reviews...</p>;

  if (reviews.length === 0) {
    return <p className="text-gray-500">Abhi koi review nahi hai.</p>;
  }

  return (
    <div className="space-y-2">
      <h3 className="font-bold">Reviews ({reviews.length})</h3>
      {reviews.map((review) => (
        <div key={review.id} className="border p-2 rounded bg-white">
          <div className="flex justify-between items-center mb-1">
            <span>{"⭐".repeat(review.rating)}</span>
            <span className="text-sm text-gray-500">{review.createdAt}</span>
          </div>
          <p className="text-gray-700">{review.text}</p>
        </div>
      ))}
    </div>
  );
}
```

**Line by line:**

1. **`"use client"`** — ye client component hai. `useEffect` aur `useState` sirf client pe kaam karte hain.

2. **`useState<...>([])`** — reviews ka state — initially empty array. Type diya hai taaki TypeScript ko pata chale kaunsa data aayega.

3. **`useState(true)`** — `loading` state — shuru mein `true` (data aa raha hai), baad mein `false`.

4. **`useEffect(() => { ... }, [productId])`** — component mount hone pe data fetch ho. `[productId]` — agar product badle toh dobara fetch ho.

5. **`axios.get(`/api/reviews?productId=${productId}`)** — GET request. `?productId=1` se sirf Product 1 ke reviews aayenge. **Abhi ye route exist nahi karta** — 3.4.5 mein banayenge. Abhi error aayega — par structure sahi hai.

6. **`setReviews(res.data)`** — axios ka response already parsed hai — `res.data` mein JSON hai.

7. **`finally { setLoading(false) }** — chahe success ho ya error, loading khatam.

8. **`loading` check** — agar loading hai toh "Loading..." dikhe. `return` se function ruk jaata hai — baaki JSX render nahi hota.

9. **`reviews.length === 0` check** — agar koi review nahi hai toh message dikhe.

10. **`reviews.map()`** — har review ko div mein convert karo.

## Kya Badla?

| Pehle (3.4.2) | Ab (3.4.4) |
|---------------|------------|
| `const reviews = [ ... ]` hardcoded | `ReviewList` component — data `axios.get()` se |
| Data page ke andar tha | Data API se aayega (route baad mein banega) |
| Naya review add = code badlo | Naya review add = API call (form baad mein banega) |

**Notice kiya?** Page ka code chhota ho gaya — sirf `ReviewList` components hain. Data ka logic `ReviewList` ke andar hai. Agar data source badalna ho (axios → fetch, ya API → database) toh sirf `ReviewList` ka `useEffect` badlega — page ka code nahi.

---

## Common Mistakes

1. **`"use client"` mat bhoolo** — `useEffect` aur `useState` sirf client pe kaam karte hain. Bina `"use client"` ke error aayega.
2. **`loading` state mat bhoolo** — Agar `loading` nahi hai toh pehle empty array dikhega (0 reviews), phir suddenly reviews aa jaayenge — flicker hoga.
3. **`finally` mat bhoolo** — `try/catch` ke saath `finally` lagao — loading hamesha khatam ho chahe success ho ya error.
4. **API route exist nahi karta** — Abhi expected hai. 3.4.5 mein banayenge. Abhi error aaye toh darr mat jao.

---

## Problem Jo Abhi Hai

1. **API route exist nahi karta** — `axios.get("/api/reviews")` call ho raha hai par route nahi hai. Error aayega.
2. **Loading sirf initial hai** — jab naya review add hoga toh list automatically refresh nahi hogi.
3. **Edit/Delete nahi hai** — abhi sirf reviews dikha raha hai, kuch kar nahi sakta.

## Agle Step Mein Kya Hoga?

Ab **GET route banayenge** — `/api/reviews/route.ts`. Jab client `axios.get("/api/reviews")` karega toh ye route data layer se data lega aur client ko bhejega. Tab se reviews screen pe dikhenge.

Aur ek aur cheez — **Server Component** version bhi banayenge ReviewList ka. Compare karenge ki client fetch aur server rendering mein kya fark hai. Wahi 3.3.2 waala concept — par ab real project mein.
