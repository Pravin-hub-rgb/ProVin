Ab tak sirf **data padha** - Server Components se fetch kiya, Client Components mein display kiya. Par ek cheez missing hai - **data change karna.**

Socho - tumne product listing banayi (2.1), usme favorites button add kiya (2.2). Par jab user "Add to Favorites" click kare, toh **wo data server pe save hona chahiye** - taki kal user wapas aaye toh dikhe ki favorites mein tha. Abhi tak ye nahi kiya - sirf client-side state thi jo refresh pe gayab ho jaati hai.

Batch 3 mein ye seekhenge - **data kaise change karte hain server pe.**

## Do Approaches Hain - Ek Nahi

**Confusion mat karo:** Ye "ye sahi hai, ye galat" wali baat nahi hai. **Dono approaches alag alag jagah kaam aati hain.**

### Approach 1: Route Handlers (REST API)

Ye **fundamental** hai - har web developer ko aana chahiye. React mein bhi `fetch()` se API call karte the, wahi pattern hai. Route Handler mein tum API endpoint banate ho (`/api/comments`) aur client se `fetch()` se call karte ho.

**Kab use karein:**
- Third-party apps ko API deni ho (mobile app, another website)
- Complex operations ho (file upload, payment processing)
- External services se baat karni ho
- Microservices architecture ho

### Approach 2: Server Actions

Ye **Next.js specific** hai - sirf Next.js App Router mein kaam karta hai. Form seedha server function ko call kare, koi API endpoint nahi, koi `fetch()` nahi. Boilerplate kam hota hai.

**Kab use karein:**
- Simple form submissions ho (comment add karna, profile update karna)
- Sirf Next.js app hai (koi external client nahi)
- Quick CRUD operations ho
- API layer ki zaroorat nahi

### Comparison

| | Route Handlers (REST) | Server Actions |
|---|---|---|
| **Universal?** | Haan - har jagah kaam aata hai | Nahi - sirf Next.js |
| **Boilerplate** | Zyada - route file, fetch call, types | Kam - function likho, done |
| **External clients** | Support karta hai | Nahi (sirf Next.js app) |
| **Industry standard** | Haan - REST universal hai | Nahi - Next.js specific |
| **Complex operations** | Better control | Limited |

---

## "Manual → Better" Nahi - "Fundamental → Shortcut" Hai

Roadmap mein pehle likha tha ki Route Handlers "manual" hai aur Server Actions "better" hai. **Ye galat framing thi.**

**Sahi framing:**
- Route Handlers = **Fundamental** - ye seekho pehle, ye har jagah kaam aayega
- Server Actions = **Next.js shortcut** - ye baad mein seekho, ye sirf forms ke liye hai

Jaise React mein `useEffect` fundamental hai, aur React Query (TanStack Query) shortcut hai. `useEffect` galat nahi hai - React Query sirf easier hai specific use cases ke liye.
