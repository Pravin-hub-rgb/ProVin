# Delete Button — Server Action Version (3.4.13)

## Where We Left Off

In 3.4.12, we converted the add review form to use Server Actions with `useActionState` and toast notifications. The form is clean — no `useState`, just `action={formAction}` and `isPending` for feedback.

Now we'll convert the **delete button** to a Server Action. Delete is simpler than add — it only needs a review ID, not text or rating. The challenge: how do we send that ID to the server?

## The Hidden Input Pattern

Server Actions work through forms — `<form action={action}>`. But the delete button needs to tell the server **which** review to delete. We can't have a visible input for this — the user just clicks "Delete" on a review.

The solution: a **hidden input** inside a form. The user sees just a button, but the form secretly carries the review ID:

```tsx
<form action={formAction}>
  <input type="hidden" name="id" value={review.id} />
  <button type="submit">Delete</button>
</form>
```

The `type="hidden"` input is invisible to the user but gets included in the form's `FormData`. The server action reads it with `formData.get("id")`.

## Step 1: Add deleteReviewAction

Add the action to `app/actions.ts`:

```tsx
// app/actions.ts
"use server";

import { addReview, deleteReview, updateReview } from "@/lib/reviews";
import { revalidatePath } from "next/cache";

export type FormState = {
  success: boolean;
  message: string;
};

// ... existing addReviewAction ...

export async function deleteReviewAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const id = Number(formData.get("id"));

  const deleted = deleteReview(id);

  if (!deleted) {
    return { success: false, message: "Review not found" };
  }

  revalidatePath("/reviews");
  return { success: true, message: "Review deleted" };
}
```

Same pattern as `addReviewAction` — extract data from `formData`, call the data layer function, `revalidatePath`, return `{ success, message }`.

## Step 2: Delete Button Component

```tsx
// app/components/DeleteButtonServer.tsx
"use client";

import { useActionState } from "react";
import { deleteReviewAction, FormState } from "../actions";
import { toast } from "sonner";
import { useEffect } from "react";

const initialState: FormState = { success: false, message: "" };

export function DeleteButtonServer({ reviewId }: { reviewId: number }) {
  const [state, formAction, isPending] = useActionState(
    deleteReviewAction,
    initialState
  );

  useEffect(() => {
    if (state.message) {
      state.success ? toast.success(state.message) : toast.error(state.message);
    }
  }, [state]);

  return (
    <form action={formAction}>
      <input type="hidden" name="id" value={reviewId} />
      <button
        type="submit"
        disabled={isPending}
        className="text-red-500 hover:text-red-700 text-sm disabled:text-gray-400"
      >
        {isPending ? "Deleting..." : "Delete"}
      </button>
    </form>
  );
}
```

### Why a Form Around the Button?

Server Actions work through **forms**. A standalone `<button onClick={handler}>` can't trigger a Server Action — it needs to be inside `<form action={formAction}>`. The button's `type="submit"` submits the form, which triggers the action.

### Why Not `onClick` with Direct Call?

You technically can call a Server Action directly from an async event handler, but you lose `useActionState` benefits (pending state, return value tracking). Using a form with `useActionState` gives you consistent handling across all mutations.

## Step 3: Confirm Dialog

Add a confirmation dialog before deleting — destructive actions need a second thought:

```tsx
const handleConfirm = (e: React.FormEvent) => {
  const confirmed = window.confirm("Are you sure you want to delete this review?");
  if (!confirmed) {
    e.preventDefault();
  }
};

// In the form:
<form action={formAction} onSubmit={handleConfirm}>
```

## Step 4: Use in Review List

Add the delete button to each review in the list:

```tsx
// app/components/ReviewListServer.tsx
import { DeleteButtonServer } from "./DeleteButtonServer";

export function ReviewListServer({ productId }: { productId: number }) {
  const reviews = getReviewsByProduct(productId);

  if (reviews.length === 0) {
    return <p className="text-gray-500">No reviews yet.</p>;
  }

  return (
    <div className="space-y-2">
      <h3 className="font-bold">Reviews ({reviews.length})</h3>
      {reviews.map((review) => (
        <div key={review.id} className="border p-2 rounded bg-white">
          <div className="flex justify-between items-center mb-1">
            <span>{"⭐".repeat(review.rating)}</span>
            <span className="text-sm text-gray-500">{review.createdAt}</span>
          </div>
          <p className="text-gray-700">{review.text}</p>
          <div className="flex gap-4 mt-2">
            <Link href={`/reviews/${review.id}`} className="text-blue-500 text-sm">
              View Detail
            </Link>
            <DeleteButtonServer reviewId={review.id} />
          </div>
        </div>
      ))}
    </div>
  );
}
```

## Route Handler vs Server Action Delete

| Route Handler | Server Actions |
|---|---|
| `onClick={handleDelete}` with `axios.delete()` | `<form action={formAction}>` |
| `window.location.reload()` | `revalidatePath("/reviews")` |
| `useState` for pending | `isPending` from `useActionState` |
| `confirm()` in handler | `onSubmit` handler on form |
| 15 lines including error handling | 12 lines with toast support |

**Key insight:** Each delete button is its own tiny form. The hidden `reviewId` input ensures the correct review is targeted.

## What It Is NOT

- **Hidden inputs are not secure** — anyone can inspect and modify them via DevTools. Server-side validation is still required.
- **A form around each button is not wasteful** — these are lightweight form elements, not full-page reloads. The form just packages the data for the action.
- **Delete via form doesn't cause page reload** — Next.js intercepts the form submission. The `revalidatePath` handles refreshing the data.

## In Your Own Words

<details>
<summary>Question 1: Why is a form necessary around the delete button?</summary>
<p><strong>Answer:</strong> Server Actions can only be triggered by form submissions using `action={formAction}`. A standalone `onClick` handler can call the action directly, but it bypasses `useActionState` — meaning no `isPending`, no `state` tracking, and no toast feedback. The form wrapper enables all the benefits of `useActionState`.</p>
</details>

<details>
<summary>Question 2: How does the hidden input carry the review ID?</summary>
<p><strong>Answer:</strong> `<input type="hidden" name="id" value={reviewId} />` is invisible but included in form submission. When the form submits, the browser creates `FormData` with `id` → `reviewId`. The server action reads it with `formData.get("id")`.</p>
</details>

<details>
<summary>Question 3: Why use `onSubmit` for confirm instead of `onClick` on the button?</summary>
<p><strong>Answer:</strong> `onSubmit` on the form fires before the submission happens. If the user cancels, we call `e.preventDefault()` to stop the submission entirely. With `onClick` on the button, the form would already be submitting by the time we check the confirmation — preventing it from within `onClick` is more complex.</p>
</details>

<details>
<summary>Question 4: Can multiple delete buttons on the same page share one `useActionState`?</summary>
<p><strong>Answer:</strong> Yes! All delete buttons can use the same `deleteReviewAction` — the `id` comes from each form's hidden input, so each deletion targets the correct review. Sharing one `useActionState` instance is fine because the action processes one submission at a time.</p>
</details>
