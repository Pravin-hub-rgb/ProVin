# useOptimistic — Instant UI Updates (3.3.7)

## Where We Left Off

In 3.3.6 you learned `useFormStatus` for form pending state and `next/form` `<Form>` for progressive enhancement. Both solve the "button feels stuck" problem — they show loading state during submission.

But there is a deeper UX issue: even with a loading spinner, the user **waits**. They click "Delete" and stare at a spinner until the server confirms. For fast actions (delete, toggle, like), the user should see the result **immediately** — and the server syncs in the background.

## The Problem: Waiting Is Painful

Think of a social media feed: you click "Like" and nothing happens until the server responds. That feels slow. Or you delete a todo and it just sits there with a spinner for 3 seconds. Users hate it.

The solution is **optimistic UI** — update the screen first, then confirm with the server. If the server fails, undo the change.

## `useOptimistic` — Update Now, Reconcile Later

React's `useOptimistic` hook works like `useState` but with an extra update function for **immediate, optimistic updates**:

```tsx
'use client';

import { useOptimistic } from 'react';
import { deleteTodoAction } from '@/actions/todo';

interface Todo {
  id: number;
  text: string;
}

interface OptimisticTodo {
  id: number;
  text: string;
  isDeleting: boolean;
}

export default function TodoList({ todos }: { todos: Todo[] }) {
  // The "real" state — comes from the server
  const [optimisticTodos, addOptimisticTodo] = useOptimistic(
    todos,                          // current state (from DB fetch)
    (current, newTodo: Todo) =>     // updater: (currentState, payload) => newState
      current.filter(todo => todo.id !== newTodo.id)
  );

  async function handleDelete(todo: Todo) {
    // 1. Optimistically remove from UI — INSTANT
    addOptimisticTodo(todo);

    // 2. Call the server in the background
    await deleteTodoAction(todo.id);

    // 3. If it fails — Next.js auto-revalidates the route, UI snaps back
  }

  return (
    <ul>
      {optimisticTodos.map(todo => (
        <li key={todo.id}>
          {todo.text}
          <button onClick={() => handleDelete(todo)}>Delete</button>
        </li>
      ))}
    </ul>
  );
}
```

Here is the flow:

1. **Click "Delete"** → `handleDelete(todo)` fires.
2. **Instant UI update** → `addOptimisticTodo(todo)` immediately removes the todo from the list. The user sees it disappear. **Zero wait.**
3. **Background server call** → `deleteTodoAction(todo.id)` runs on the server.
4. **Reconciliation** → If the server succeeds, great. If it fails, Next.js revalidates the route → the original server data flows back → the todo **snaps back** into the list.

## The Updater Function — Your "What If"

The second argument to `useOptimistic` is the **updater function** — it receives:

1. The current state
2. The payload you passed to the dispatch function
3. Returns what the UI should show **right now**

```tsx
// More complex example: optimistic status update
const [users, addOptimisticUser] = useOptimistic(
  users,
  (currentUsers, optimisticUser: User) =>
    currentUsers.map(u =>
      u.id === optimisticUser.id ? { ...u, ...optimisticUser } : u
    )
);

// Usage: update UI before server confirms
async function updateUser(user: User) {
  // Instantly show "Saving..." status
  addOptimisticUser({ id: user.id, status: "saving" });

  // Server action runs in background
  await updateUserAction(user);

  // On success/failure, Next.js revalidates — real state flows back
}
```

## Optimistic UI + Server Actions = The Full Stack

Combine everything from this batch:

```tsx
// app/todos/TodoItem.tsx
'use client';

import { useOptimistic } from 'react';
import { toggleTodoAction, deleteTodoAction } from '@/actions/todo';

export default function TodoItem({ todo }: { todo: Todo }) {
  const [optimisticTodo, addOptimisticTodo] = useOptimistic(
    todo,
    (current, newFields: Partial<Todo>) => ({ ...current, ...newFields })
  );

  async function handleToggle() {
    addOptimisticTodo({ completed: !optimisticTodo.completed });  // instant visual toggle
    await toggleTodoAction(todo.id, !optimisticTodo.completed);     // server syncs
  }

  async function handleDelete() {
    addOptimisticTodo({ id: todo.id, text: "[deleting...]" });     // instant placeholder
    await deleteTodoAction(todo.id);                                // server deletes
  }

  return (
    <li>
      <input
        type="checkbox"
        checked={optimisticTodo.completed}
        onChange={handleToggle}
      />
      <span>{optimisticTodo.text}</span>
      <button onClick={handleDelete}>Delete</button>
    </li>
  );
}
```

## Nutshell

| Without `useOptimistic` | With `useOptimistic` |
|---|---|
| User clicks → spinner shows → server responds → UI updates | User clicks → UI updates instantly → server syncs in background |
| Feels slow on poor connections | Feels instant, even if server is slow |
| No reconciliation needed | If server fails, Next.js revalidation snaps back to real state |

## Common Mistakes

- ❌ **Using optimistic updates for critical data** — optimistic UI is for **UX polish**, not for operations where seeing stale data is dangerous (financial transactions). For those, wait for server confirmation.
- ❌ **Forgetting that the server is the source of truth** — the optimistic update is temporary. If the server returns different data (e.g. "this todo was already deleted by someone else"), the revalidated state overrides your optimistic update.
- ❌ **Returning the wrong shape from the updater** — your updater function's return type must match your state type. If `todo` is `{ id: number; text: string; completed: boolean }`, your updater must return the same shape.
- ❌ **Calling `useOptimistic` inside a loop** — it must be called unconditionally at the top of the component, like all hooks.

## What It Is NOT

- **It is not `useState` with extra steps.** `useOptimistic` adds a dispatch function specifically for temporary, optimistic updates — and pairs with React 19's `useActionState` to reconcile when the server responds.
- **It is not a caching mechanism.** The optimistic state is lost on page refresh. The real state always comes from the server.
- **It is not a substitute for `useFormStatus`.** `useFormStatus` reads form submission state. `useOptimistic` manages the data state. They solve different problems and can be used together.

## In Your Own Words

1. When does the optimistic UI state get replaced by the "real" state?

<details>
<summary>Sample Answer</summary>

**Answer:** When the server action completes and Next.js revalidates the route. The revalidated server data flows back and replaces the optimistic state. If the server action fails, the revalidation still happens — so the UI snaps back to the last known good server state.

</details>

2. What two arguments does the `useOptimistic` updater function receive?

<details>
<summary>Sample Answer</summary>

**Answer:** (1) The current state — same as `useState`. (2) The payload — the value you passed to the dispatch function returned by `useOptimistic`.

</details>

3. Can you use `useOptimistic` and `useActionState` on the same form? How do they interact?

<details>
<summary>Sample Answer</summary>

**Answer:** Yes — and they work on different axes. `useActionState` gives you the action's return value (errors, messages, isPending). `useOptimistic` gives you a dispatch function for optimistic data updates. You call the optimistic dispatch before calling the server action; `useActionState` handles the form feedback (success/error messages).

</details>
