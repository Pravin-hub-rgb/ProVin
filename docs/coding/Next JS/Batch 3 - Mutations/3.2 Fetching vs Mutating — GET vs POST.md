3.1 mein Route Handler banaya — GET aur POST dono likhe. Par ek sawaal utha hoga: **GET aur POST mein fark kya hai? Kab GET use karein, kab POST?**

Ye sirf Next.js ki baat nahi — ye **HTTP protocol** hai. Har web server, har API, har website ye use karti hai. Ye concept har jagah kaam aayega.

---

## SOCH: Tum Phone Se Kya Karte Ho?

Phone 2 kaam karta hai:
1. **Calls/Message padhte ho** — kuch nahi badalte, sirf lete ho
2. **Calls/Message karte ho** — kuch bhejte ho, kuch badalte ho

Web bhi same kaam karta hai:
1. **GET** — data padho (kuch nahi badalte)
2. **POST** — data bhejo (kuch badalte ho)

---

## CONCEPT: HTTP Methods

HTTP mein 4 main methods hain — har kaam ka apna method:

| Method | Kaam | Example |
|--------|------|---------|
| `GET` | Data padho (kuch mat chhuo) | Product listing, blog post padhna |
| `POST` | Naya data banao | Comment add karna, form submit karna |
| `PUT` | Existing data update karo | Profile update karna, comment edit karna |
| `DELETE` | Data hatao | Comment delete karna, account delete karna |

**Analogy:** Restaurant ka menu
- **GET** = Menu padho (kuch nahi badalte)
- **POST** = Order karo (naya item add)
- **PUT** = Order change karo (pehle soup tha, ab salad)
- **DELETE** = Order cancel karo

## CODE: GET Aur POST (Pehle Se Seekha)

3.1 mein ye dono banaye the. Ek baar revision:

```tsx
// app/api/comments/route.ts
import { NextResponse } from "next/server";

let comments = [
  { id: 1, text: "Pehla comment" },
  { id: 2, text: "Doosra comment" },
];

// GET — Saare comments padho
export async function GET() {
  return NextResponse.json(comments);
}

// POST — Naya comment banao
export async function POST(request: Request) {
  const body = await request.json();
  const newComment = {
    id: comments.length + 1,
    text: body.text,
  };
  comments.push(newComment);
  return NextResponse.json(newComment, { status: 201 });
}
```

**GET** sirf data bhejta hai. **POST** naya data leta hai aur save karta hai. Dono 3.1 mein detail mein seekhe the.

## Ab PUT Aur DELETE Bhi Seekhte Hain

GET aur POST toh samajh aa gaya. Ab baaki dono methods - PUT (update) aur DELETE (hatao).

**Pehle samjho array methods jo use honge:**

### `findIndex()` Kya Hai?

`findIndex()` array mein se element ka **index** dhoondta hai. Index matlab - element kis position pe hai.

```tsx
const comments = [
  { id: 1, text: "Pehla" },
  { id: 2, text: "Doosra" },
  { id: 3, text: "Teesra" },
];

const index = comments.findIndex((c) => c.id === 2);
console.log(index);  // 1 (doosre position pe hai)

const notFound = comments.findIndex((c) => c.id === 99);
console.log(notFound);  // -1 (nahi mila toh -1 return hota hai)
```

**`.find()` vs `.findIndex()`:**
- `.find()` — element khud return karta hai (`{ id: 2, text: "Doosra" }`)
- `.findIndex()` — element ki position return karta hai (`1`)

**Kyun index chahiye?** Kyunki array mein se element update ya delete karne ke liye position pata honi chahiye.

### Spread Operator (`...`) Kya Hai?

Object update karte waqt spread operator use hota hai — purane properties copy karo, nayi overwrite karo:

```tsx
const comment = { id: 1, text: "Pehla", createdAt: "2025-01-15" };

// Purana copy + naya text
const updated = { ...comment, text: "Updated!" };
console.log(updated);
// { id: 1, text: "Updated!", createdAt: "2025-01-15" }
```

**Kya hua?**
1. `...comment` — purane comment ki saari properties copy ki (id, text, createdAt)
2. `text: "Updated!"` — text ko overwrite kiya
3. Baaki properties (id, createdAt) wahi rahe

**Bina spread ke kya karna padta?**
```tsx
// Manually sab likhna padega
const updated = { id: comment.id, text: "Updated!", createdAt: comment.createdAt };
```

Dekha? Spread operator ne 3 line ki jagah 1 line mein kaam kiya.

### `splice()` Kya Hai?

Array mein se element **hataane** ke liye `splice()` use hota hai:

```tsx
const fruits = ["apple", "banana", "cherry"];

fruits.splice(1, 1);  // index 1 se 1 element hatao
console.log(fruits);  // ["apple", "cherry"]
```

**`splice(index, count)`:**
- `index` — kahan se hatana hai
- `count` — kitne elements hatane hain

```tsx
fruits.splice(0, 2);  // index 0 se 2 elements hatao
console.log(fruits);  // ["cherry"]
```

## PUT: Comment Update Karna

```tsx
// app/api/comments/[id]/route.ts
import { NextResponse } from "next/server";

// PUT — Comment update karo
export async function PUT(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;                    // 1
  const body = await request.json();               // 2
  const index = comments.findIndex((c) => c.id === Number(id));  // 3

  if (index === -1) {                              // 4
    return NextResponse.json({ error: "Nahi mila" }, { status: 404 });
  }

  comments[index] = { ...comments[index], text: body.text };  // 5
  return NextResponse.json(comments[index]);       // 6
}
```

**Line by line:**
1. `await params` se URL mein se `id` nikalo
2. `request.json()` se client ne jo naya text bheja wo lo
3. `findIndex()` se comment ki position dhoondo (-1 matlab nahi mila)
4. Agar index -1 hai toh 404 error bhejo
5. Spread operator se purana comment copy karo + text update karo
6. Updated comment client ko bhejo

---

## DELETE: Comment Hatana

```tsx
// DELETE — Comment hatao
export async function DELETE(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const index = comments.findIndex((c) => c.id === Number(id));

  if (index === -1) {
    return NextResponse.json({ error: "Nahi mila" }, { status: 404 });
  }

  comments.splice(index, 1);
  return NextResponse.json({ message: "Delete ho gaya" });
}
```

**Line by line:**
1. URL se `id` nikalo
2. `findIndex()` se comment ki position dhoondo
3. Agar nahi mila toh 404 error
4. `splice(index, 1)` se us position se 1 element hata do
5. Success message bhejo

## Client Se Kaise Call Karein?

Ab saare 4 methods ban gaye. Client se kaise call karenge?

**GET — Sabse simple:**

```tsx
const res = await fetch("/api/comments");
const comments = await res.json();
```

GET mein kuch bhejne ki zaroorat nahi — sirf URL do, data aa jaayega.

**POST — Naya data bhejo:**

```tsx
const res = await fetch("/api/comments", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "Naya comment!" }),
});
```

POST mein 3 cheezein extra hoti hain: `method`, `headers`, `body`.

**PUT — Data update karo:**

```tsx
const res = await fetch("/api/comments/1", {
  method: "PUT",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "Updated comment!" }),
});
```

PUT bhi POST jaisa hai — data bhejte hain. Fark ye hai ki URL mein `id` hota hai (kaunsa comment update karna hai).

**DELETE — Data hatao:**

```tsx
const res = await fetch("/api/comments/1", {
  method: "DELETE",
});
```

DELETE mein sirf `method: "DELETE"` hota hai — kuch bhejne ki zaroorat nahi.

```tsx
// GET — Data padho
const res = await fetch("/api/comments");
const comments = await res.json();

const res = await fetch("/api/comments", {

  method: "PUT",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "Updated comment!" }),
});

// DELETE — Comment hatao
const res = await fetch("/api/comments/1", {
  method: "DELETE",
});
```

## GET vs POST — Kab Kya Use Karein?

| Scenario | Method | Kyun? |
|----------|--------|-------|
| Product listing dekhna | GET | Sirf padh rahe ho, kuch nahi badalte |
| Blog post padhna | GET | Sirf padh rahe ho |
| Comment add karna | POST | Naya data create kar rahe ho |
| Form submit karna | POST | Server pe data bhej rahe ho |
| Profile update karna | PUT | Existing data badal rahe ho |
| Account delete karna | DELETE | Data hata rahe ho |

**Simple rule:** 
- Sirf padhna hai → **GET**
- Kuch badalna hai → **POST/PUT/DELETE**

## Status Codes — Response Mein Kya Bhejte Hain?

Jab server client ko response bhejta hai, uske saath ek **status code** jaata hai. Ye three-digit number hota hai jo batata hai ki kya hua.

| Status Code | Matlab | Kab Bhejte Hain |
|-------------|--------|-----------------|
| 200 | OK | GET successful — data sahi aa gaya |
| 201 | Created | POST successful — naya resource ban gaya |
| 400 | Bad Request | Client ne galat data bheja (validation error) |
| 404 | Not Found | Resource nahi mila (wrong URL ya ID) |
| 500 | Server Error | Server pe kuch gadbad hui (database crash, etc.) |

**Kaise bhejte hain?**

`NextResponse.json()` mein doosra argument `{ status: code }` hota hai:

```tsx
// Success — GET ke liye
return NextResponse.json(data, { status: 200 });

// Naya resource bana — POST ke liye
return NextResponse.json(newItem, { status: 201 });

// Error — resource nahi mila
return NextResponse.json({ error: "Nahi mila" }, { status: 404 });

// Error — galat data aaya
return NextResponse.json({ error: "Text zaroori hai" }, { status: 400 });

// Error — server pe problem
return NextResponse.json({ error: "Server down hai" }, { status: 500 });
```

**Agar status code na do?**

```tsx
return NextResponse.json(data);  // Default 200 ho jaayega
```

Default 200 (OK) hai. Par POST ke liye 201 dena chahiye — taaki client ko pata chale ki naya resource ban gaya.

## Nutshell

HTTP methods batate hain ki client kya karna chahta hai — padhna (GET), banana (POST), update karna (DELETE), ya hatana (DELETE). Route Handler mein har method ka apna function hota hai. GET safe hai (kuch nahi badalta), POST/PUT/DELETE data change karte hain. Status codes se client ko pata chalta hai ki kya hua.

---

## Common Mistakes

- ❌ GET mein data change karna — GET safe hona chahiye, sirf read
- ❌ POST ke baad 200 dena — 201 dena chahiye (Created)
- ❌ Status code na dena — client ko pata nahi chalega ki kya hua
- ❌ Galat method use karna — profile update ke liye POST nahi, PUT use karo

## What It Is NOT

⚠️ **HTTP methods = "Next.js ka feature" nahi.** Ye universal hai — har web framework, har API ye use karti hai. Next.js sirf implementation deta hai.

⚠️ **GET = "hamesha safe" nahi.** Technically GET mein bhi data badal sakte ho (server pe), par ye practice galat hai. GET ko hamesha safe rakho — kuch mat chhuo.
