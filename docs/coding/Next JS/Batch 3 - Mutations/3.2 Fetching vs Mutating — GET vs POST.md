3.1 mein Route Handler banaya — GET aur POST dono likhe. Par ek sawaal utha hoga: **GET aur POST mein fark kya hai? Kab GET use karein, kab POST?**

Ye sirf Next.js ki baat nahi — ye **HTTP protocol** hai. Har web server, har API, har website ye use karti hai.

---

## SOCH: Phone Se Kya Karte Ho?

Phone 2 kaam karta hai:
1. **Calls/Message padhte ho** — kuch nahi badalte, sirf lete ho
2. **Calls/Message karte ho** — kuch bhejte ho, kuch badalte ho

Web bhi same kaam karta hai:
1. **GET** — data padho (kuch nahi badalte)
2. **POST** — data bhejo (kuch badalte ho)

---

## HTTP Methods — 4 Main Hain

| Method | Kaam | Example |
|--------|------|---------|
| `GET` | Data padho (kuch mat chhuo) | Product listing, blog post padhna |
| `POST` | Naya data banao | Comment add karna, form submit karna |
| `PUT` | Existing data update karo | Profile update karna, comment edit karna |
| `DELETE` | Data hatao | Comment delete karna, account delete karna |

Restaurant ka menu soch — **GET** = menu padho, **POST** = order karo, **PUT** = order change karo, **DELETE** = order cancel karo.

## GET Aur POST — Revision

3.1 mein ye dono banaye the. Ek baar yaad karo — data ab JSON file se aa raha hai:

```tsx
// app/api/comments/route.ts
import { NextResponse } from "next/server";
import { getAllComments, addComment } from "@/lib/comments";

// GET - Saare comments padho
export async function GET() {
  return NextResponse.json(getAllComments());
}

// POST - Naya comment banao
export async function POST(request: Request) {
  const body = await request.json();
  const newComment = addComment(body.text);
  return NextResponse.json(newComment, { status: 201 });
}
```

**GET** sirf data bhejta hai. **POST** naya data leta hai aur save karta hai. Data `lib/comments.ts` se aa raha hai — wahan `fs` module se JSON file padhti hai.

## Ab PUT Aur DELETE Bhi Seekhte Hain

GET aur POST toh samajh aa gaya. Ab baaki dono — PUT (update) aur DELETE (hatao).

Pehle samjho **array methods** jo use honge:

### `findIndex()` — Position Dhoondo

`findIndex()` array mein se element ka **index** dhoondta hai — element kis position pe hai:

```tsx
const comments = [
  { id: 1, text: "Pehla" },
  { id: 2, text: "Doosra" },
  { id: 3, text: "Teesra" },
];

const index = comments.findIndex((c) => c.id === 2);
console.log(index);  // 1 (doosre position pe hai)

const notFound = comments.findIndex((c) => c.id === 99);
console.log(notFound);  // -1 (nahi mila toh -1)
```

`.find()` vs `.findIndex()` — `.find()` element khud return karta hai, `.findIndex()` position return karta hai. Kyun chahiye? Kyunki update ya delete karne ke liye position pata honi chahiye.

### Spread Operator (`...`) — Copy Karo, Overwrite Karo

Object update karte waqt purane properties copy karo, nayi overwrite karo:

```tsx
const comment = { id: 1, text: "Pehla", createdAt: "2025-01-15" };

const updated = { ...comment, text: "Updated!" };
// { id: 1, text: "Updated!", createdAt: "2025-01-15" }
```

Dekha? `...comment` se saari properties copy hui, phir `text: "Updated!"` ne overwrite kiya. Bina spread ke 3 line likhni padti.

### `splice()` — Hatao

Array mein se element **hataane** ke liye:

```tsx
const fruits = ["apple", "banana", "cherry"];

fruits.splice(1, 1);  // index 1 se 1 element hatao
console.log(fruits);  // ["apple", "cherry"]
```

`splice(index, count)` — index = kahan se, count = kitne.

Comments pe try karte hain:

```tsx
const comments = [
  { id: 1, text: "Pehla" },
  { id: 2, text: "Doosra" },
  { id: 3, text: "Teesra" },
];

// Doosra comment hatana hai (id: 2)
const index = comments.findIndex((c) => c.id === 2);
comments.splice(index, 1);

console.log(comments);
// [{ id: 1, text: "Pehla" }, { id: 3, text: "Teesra" }]
```

`findIndex()` se pehle position nikali (index 1), phir `splice(1, 1)` se us position se 1 element hata diya. **"Doosra" gaya — baaki safe.**

## PUT — Comment Update Karna (Route Handler)

Abhi tak `lib/comments.ts` mein sirf GET/POST wale functions the (`getAllComments`, `addComment`, `getCommentById`). Put ke liye ek naya function chahiye — `updateComment`. **Wahi 3.1 ka read-file → change → write-file pattern:**

```ts
// lib/comments.ts — updateComment add karo (addComment ke pattern pe)
export function updateComment(id: number, text: string) {
  const comments = getAllComments();                          // 1. file se padho
  const index = comments.findIndex((c) => c.id === id);       // 2. dhoondo

  if (index === -1) return null;                              // 3. nahi mila → null

  comments[index].text = text.trim();                         // 4. update
  writeFileSync(filePath, JSON.stringify(comments, null, 2)); // 5. file mein likho
  return comments[index];                                     // 6. updated return
}
```

**Notice kiya?** `findIndex()` + update + file likhna — sab kuch `lib` ke andar hai. Route handler sirf is function ko **call** karega:

```tsx
// app/api/comments/[id]/route.ts
import { NextResponse } from "next/server";
import { updateComment } from "@/lib/comments";

export async function PUT(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const body = await request.json();

  // Validation — empty text allow mat karo
  if (!body.text || !body.text.trim()) {
    return NextResponse.json(
      { error: "Text khali nahi ho sakta" },
      { status: 400 }
    );
  }

  const updated = updateComment(Number(id), body.text);

  if (!updated) {
    return NextResponse.json({ error: "Nahi mila" }, { status: 404 });
  }

  return NextResponse.json(updated);
}
```

Chal samajhte hain — `await params` se URL mein se `id` nikali. `request.json()` se client ne jo naya text bheja wo liya. Validation check kiya ki text khali na ho. Phir `updateComment()` ko call kiya — wo `lib` mein file se padhta hai, `findIndex()` se position dhoondhta hai, text update karta hai, aur **file mein wapas likh deta hai** (`comments.json`). Agar `null` aaya toh 404, warna updated comment client ko bheja.

**Notice kiya?** Route handler mein ab koi `comments.findIndex` ya `comments[index] = ...` **nahi hai** — wo sab `lib/comments.ts` ke andar chala gaya. Route sirf patla layer hai: request aayi → function call kiya → response bheja. **Data kahan hai? `comments.json` mein — `lib` ke functions usko padhte/likhte hain.**

### Client-Se-Server Mapping — PUT Ka Flow

3.1 mein POST ka mapping dekha tha. Ab PUT ka bhi dekh le — aur **`params` kaise kaam karta hai** ye samajh:

**Client (`app/comments/[id]/page.tsx`):**
```tsx
const handleUpdate = async (id: number) => {
  const res = await fetch(`/api/comments/${id}`, {
    method: "PUT",
    body: JSON.stringify({ text: editText }),
    headers: { "Content-Type": "application/json" },
  });
};
```

**Server (`route.ts`):**
```tsx
export async function PUT(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const body = await request.json();
}
```

**Mapping:**

```
Client                                          Server
───────────────────────────────────────────────────────────
fetch(`/api/comments/${id}`)     →    URL milta hai → /api/comments/1
        ↓                                        ↓
params: { id: "1" }              →    { params } parameter mein aata hai
                                              ↓
                                     const { id } = await params
                                              ↓
                                     id = "1" (string, isliye Number() lagaya)

method: "PUT"                    →    export async function PUT()

body: JSON.stringify({...})      →    request.json() se nikalta hai
```

**Notice kiya?** URL mein jo `id` hota hai — wo `params` ke andar aata hai. `fetch(\`/api/comments/${id}\`)` mein jo `id` hai, wohi `params.id` mein dikhta hai. Ye Next.js ka **dynamic routing** hai — `[id]` bracket mein jo likha hota hai, wo `params` ka key ban jaata hai.

## PUT — Comment Edit Karna (UI)

Route handler ban gaya — ab UI se call karna hai. Par ek sawaal utha: **edit ki UI kahaan banayein?**

Soch — jab tum already bheja hua message edit karte ho (WhatsApp mein), toh tum chaat ka pura screen khol ke "edit" nahi dhoondte. Tum **us message pe jate ho** aur wahan edit karte ho, kyunki edit sirf usi message se juda hai. Web mein bhi update wahi dikhana chahiye — **us item se judi jagah pe**, pura list screen nahi.

Aur woh jagah humare paas pehle se hai — 3.1 mein bana **dynamic detail page** `/comments/[id]`. User comment click karta hai → `/comments/2` khulta hai → wahan 2 kaam karke dikhane hain: **view** (comment dekhna) aur **edit** (comment badalna). Isliye edit ki UI isi detail page pe banate hain, list ke andar nahi.

Chal step by step — pehle `/comments/2` page pe comment ke saath **Edit button** lagao, aur click pe **form khula de**:

```tsx
// app/comments/[id]/page.tsx
"use client";

import { useEffect, useState } from "react";

export default function CommentPage({ params }: { params: Promise<{ id: string }> }) {
  const [comment, setComment] = useState<{ id: number; text: string } | null>(null);
  const [editing, setEditing] = useState(false);   // ← edit mode ON/OFF
  const [editText, setEditText] = useState("");    // ← form ka value

  useEffect(() => {
    params.then(({ id }) => {
      const load = async () => {
        const res = await fetch(`/api/comments/${id}`);
        const data = await res.json();
        setComment(data);
        setEditText(data.text);  // form pehle se old text dikhaye
      };
      load();
    });
  }, [params]);

  if (!comment) return <p>Loading...</p>;

  return (
    <div className="p-4 border rounded max-w-md mx-auto">
      {editing ? (
        // EDIT MODE — form khula
        <form
          onSubmit={(e) => e.preventDefault()}
          className="flex flex-col gap-2"
        >
          <input
            value={editText}
            onChange={(e) => setEditText(e.target.value)}
            className="border p-2 rounded"
          />
          <div className="flex gap-2">
            <button type="submit" className="bg-green-500 text-white px-4 py-2 rounded">
              Save
            </button>
            <button type="button" onClick={() => setEditing(false)} className="text-gray-500 text-sm">
              Cancel
            </button>
          </div>
        </form>
      ) : (
        // VIEW MODE — comment dikhao + Edit button
        <>
          <p className="text-lg">{comment.text}</p>
          <button
            onClick={() => setEditing(true)}
            className="mt-3 bg-blue-500 text-white px-4 py-2 rounded"
          >
            Edit
          </button>
        </>
      )}
    </div>
  );
}
```

Dekho kya naya hai:
1. **`editing`** — `false` hai toh view mode (comment + Edit button), `true` hai toh edit mode (form). Bas ek boolean se toggle.
2. **Edit button** — `setEditing(true)` karta hai. **Click karte hi form khul jaata hai** — yehi woh flow hai: dynamic route pe Edit button, phir form khula.
3. **`editText` prefill** — form ka input pehle se us comment ka asli text dikhata hai (`setEditText(data.text)`). Koi user bina purana text dekhe edit nahi karna chahta.
4. **`params.then` aur Loading** — 3.1 ka wahi pattern. Page load pe `/api/comments/${id}` se wo ek comment fetch hota hai.

**Notice kiya?** Ye **React ka state-toggle pattern** hi hai — bas toggle ab ek boolean (`editing`) se ho raha hai. List mein multiple items hote hain, isliye wahan yaad rakhna padta hai ki *kaun si* row edit ho rahi hai. Par detail page pe sirf EK comment hai — isliye ek boolean (`false`/`true`) kaafi hai. Aisa hi fark reuse karte waqt dikhta hai: complexity wahi rehti hai jahan multiple items hote hain.

**Ab test karo:** `/comments/2` kholo → Edit dabao → form khula (old text dikh raha hai) → Cancel dabao wapas. **Par abhi PUT request nahi ja rahi** — form ke Submit pe bas `e.preventDefault()` hai. Isliye agla step — Save pe PUT bhejna.

#### Step 2: Ab PUT Request Add Karo

`handleUpdate` add karo — jab form submit ho toh PUT request jaaye:

```tsx
// app/comments/[id]/page.tsx — handleUpdate add karo

const handleUpdate = async (e: React.FormEvent) => {
  e.preventDefault();

  const res = await fetch(`/api/comments/${comment.id}`, {
    method: "PUT",
    body: JSON.stringify({ text: editText }),
    headers: { "Content-Type": "application/json" },
  });

  const updated = await res.json();
  console.log("Updated:", updated);

  // Page pe naya comment dikhao + edit mode band karo
  setComment(updated);
  setEditing(false);
};
```

Aur form ke `onSubmit` mein `handleUpdate` laga do:

```tsx
<form onSubmit={handleUpdate} className="flex flex-col gap-2">
```

Chal samajhte hain — `e.preventDefault()` se page reload rukta hai. URL mein `id` **dynamic route page se direct pata hai** — is page pe sirf ek comment hai, isliye `comment.id` hi use karte hain. `method: "PUT"` se upar wala PUT route handler chalta hai (find → check → spread → return, wahi validation samet). Response se `updated` comment milta hai — `setComment(updated)` se wahi text dikh jaata hai aur `setEditing(false)` se form band ho jaata hai.

**Ordering gotcha — `if (!comment) return` hamesha `handleUpdate` se PEHLE hona chahiye.** `comment` ka type `{ id, text } | null` hai — `null` isliye kyunki useState ka default `null` hai. TypeScript ka **control-flow narrowing** aise kaam karta hai: wo check karta hai ki closure banne ke **waqt** variable ka type kya tha. Agar `handleUpdate` pehle define karo aur null-check baad mein, toh closure ke andar `comment` abhi bhi `null | Comment` hi hai → `comment.id` pe error aata hai: *"Parameter 'comment' is possibly 'null'"* (ya hover pe type `{ id: number; text: string } | null` dikhega). Par `comment` ek `const` hai — agar null-check pehle likh diya, toh narrowing baad ke function mein bhi preserve rehti hai aur `comment.id` safely typed ho jaata hai. Isliye order: `useState` → `useEffect` → `if (!comment) return <p>Loading...</p>` → `handleUpdate` → `return`. Isi liye Step 1 mein null-check pehle rakha tha.

**Notice kiya?** Ye **DELETE se same pattern hai** — `fetch()` + `method` + server function + phir client update. Fark bas itna: DELETE `filter()` se **hataata** hai (list se), PUT `setComment(updated)` se **badalta** hai is ek comment ko. Aur DELETE sirf URL se id leta hai (koi body nahi), jabki PUT mein `body` ke andar naya text jaata hai.

**Ab test karo:** `/comments/2` kholo → Edit dabao → form khula (old text dikh raha hai) → text badlo → Save dabao → PUT request jaayega → jo text likha wo page pe dikh jaayega. **PUT kaam kar raha hai!**

Pura flow ek saath:

```
User clicks comment (Link → /comments/2)
    ↓
app/comments/[id]/page.tsx loads → fetch("/api/comments/2") → comment dikha
    ↓
"Edit" button click → setEditing(true) → form khula (text prefilled)
    ↓
Save click → handleUpdate → PUT /api/comments/2 → updated comment
    ↓
setComment(updated) + setEditing(false) → naya text dikha, form band
```

**Polish baad mein aayega** — na loading state ka design, na error handling, na pending button. Ye sab **3.3 (Server Actions)** mein aayega — useActionState + toast hum 3.3.1 mein laga lenge. Abhi REST pattern ka flow samajh lo — ye har jagah kaam aata hai.

## DELETE — Comment Hatana (Route Handler)

PUT toh ban gaya. Ab DELETE — ye PUT se zyada simple hai. Pehle `lib/comments.ts` mein `deleteComment` bhi add karo (wahi pattern, bas `splice()` se hataate hain):

```ts
// lib/comments.ts — deleteComment add karo
export function deleteComment(id: number) {
  const comments = getAllComments();                          // 1. file se padho
  const index = comments.findIndex((c) => c.id === id);       // 2. dhoondo

  if (index === -1) return false;                             // 3. nahi mila → false

  comments.splice(index, 1);                                  // 4. hatao
  writeFileSync(filePath, JSON.stringify(comments, null, 2)); // 5. file mein likho
  return true;
}
```

Aur route handler mein call karo:

```tsx
// app/api/comments/[id]/route.ts
import { NextResponse } from "next/server";
import { deleteComment } from "@/lib/comments";

export async function DELETE(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const deleted = deleteComment(Number(id));

  if (!deleted) {
    return NextResponse.json({ error: "Nahi mila" }, { status: 404 });
  }

  return NextResponse.json({ message: "Delete ho gaya" });
}
```

PUT se zyada simple hai — `deleteComment()` hi sab kuch karta hai: file se padhta hai, `findIndex()` se position dhoondhta hai, `splice(index, 1)` se us position se 1 element hataata hai, aur **file mein wapas likh deta hai** (`comments.json`). Route sirf `deleted` check karke success message bhejta hai.

Maine bhi pehli baar `splice()` dekh ke socha tha "ye kya hai?" — par yaad rakh, array se element hatana hai toh `splice()`.

**DELETE mein kya fark hai?** DELETE mein koi body nahi hota — sirf URL se `id` chahiye. Isliye `request.json()` ki zaroorat nahi — sirf `params` se kaam chal jaata hai.

## DELETE — Comment Hatana (UI)

Handler ban gaya — par ab UI se call karna hai. 3.1 ka `ShowComments.tsx` lete hain aur usme **Delete button add** karte hain.

#### Step 1: Sirf Route Hit Karo

Pehle bas itna karo — har comment ke saath **Delete button** laga do, aur click pe DELETE request bhejo. List se hatana **abhi nahi** — pehle confirm karo ki route hit ho raha hai:

```tsx
// app/components/ShowComments.tsx
"use client";

import Link from "next/link";
import { useEffect, useState } from "react";

export default function ShowComments() {
  const [allComments, setAllComments] = useState<{ id: number; text: string }[]>([]);

  // GET — Page load pe saare comments fetch karo (3.1 se)
  useEffect(() => {
    const fetchComments = async () => {
      const res = await fetch("/api/comments");
      const comments = await res.json();
      setAllComments(comments);
    };
    fetchComments();
  }, []);

  // DELETE — Button click pe comment server se hatao
  const handleDelete = async (id: number) => {
    const res = await fetch(`/api/comments/${id}`, { method: "DELETE" });
    const data = await res.json();
    console.log("Deleted:", data);  // { message: "Delete ho gaya" }
    // List se hatana abhi NAHI — pehle route hit confirm karo
  };

  return (
    <div className="p-4 border rounded">
      <h2 className="text-xl font-bold mb-4">Comments</h2>
      <ul className="space-y-2">
        {allComments.map((comment) => (
          <li key={comment.id} className="border-b pb-2 flex items-center justify-between">
            <Link href={`/comments/${comment.id}`} className="hover:underline">
              {comment.text}
            </Link>
            <button
              onClick={() => handleDelete(comment.id)}
              className="text-red-500 hover:underline text-sm"
            >
              Delete
            </button>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

Kya badla? Sirf 2 cheezein — har `<li>` mein Delete button, aur `handleDelete` function. Click karo → `fetch()` DELETE request → route ka `DELETE` function chala.

**Notice kiya?** Delete button list component (`ShowComments.tsx`) ke andar hi hai — kyunki `allComments` state yahin hai. CommentForm (3.1 ka form) ko delete se koi lena-dena nahi — wo sirf naya comment add karta hai.

**Ab test karo:** Delete dabao → comment **abhi bhi list mein dikhega** — kyunki humne UI se hataya nahi. Par console mein `Deleted: {message: "Delete ho gaya"}` dikh raha hai. **Ye confirm karta hai ki route kaam kar raha hai.** Route hit ho raha hai — ab logic add karte hain.

#### Step 2: Ab List Se Hatana

Ab `handleDelete` mein ek line add karo — UI se comment remove karo:

```tsx
// app/components/ShowComments.tsx — handleDelete update karo

const handleDelete = async (id: number) => {
  const res = await fetch(`/api/comments/${id}`, { method: "DELETE" });
  const data = await res.json();
  console.log("Deleted:", data);

  // List se comment hatao
  setAllComments((prev) => prev.filter((c) => c.id !== id));
};
```

`filter()` — naya array banata hai jisme deleted comment **nahi hai**. `prev.filter((c) => c.id !== id)` — "jo comment ka id DELETE wale id se match nahi karta, wo rakho."

**Ab test karo:** Delete dabao → comment **list se gayab** ho jayega. Route bhi hit hua (console mein message), UI bhi update hua. **Delete kaam kar raha hai.**

**Polish baad mein aayega** — na loading state, na confirm popup, na error handling. Pehle kaam karwao, phir polish.

## DELETE vs PUT — Same Pattern, Alag Purpose:

| | DELETE | PUT |
|---|---|---|
| `fetch()` method | `DELETE` | `PUT` |
| Server function | `splice()` se hatata hai | Spread se update karta hai |
| Client update | `filter()` se hatao | `map()` se replace karo |

## Kab Kya Use Karein?

| Scenario | Method | Kyun? |
|----------|--------|-------|
| Product listing dekhna | GET | Sirf padh rahe ho |
| Blog post padhna | GET | Sirf padh rahe ho |
| Comment add karna | POST | Naya data create kar rahe ho |
| Form submit karna | POST | Server pe data bhej rahe ho |
| Profile update karna | PUT | Existing data badal rahe ho |
| Account delete karna | DELETE | Data hata rahe ho |

**Simple rule:** Sirf padhna hai → **GET**. Kuch badalna hai → **POST/PUT/DELETE**.

## Status Codes — Server Kya Message Bhejta Hai

Jab server response bhejta hai, uske saath ek **status code** jaata hai — three-digit number jo batata hai ki kya hua.

| Status Code | Matlab | Kab |
|-------------|--------|-----|
| 200 | OK | GET successful |
| 201 | Created | POST successful |
| 400 | Bad Request | Galat data aaya |
| 404 | Not Found | Resource nahi mila |
| 500 | Server Error | Server pe gadbad |

Kaise bhejte hain? `NextResponse.json()` mein doosra argument `{ status: code }`:

```tsx
return NextResponse.json(data);                    // Default 200
return NextResponse.json(newItem, { status: 201 }); // POST ke liye
return NextResponse.json({ error: "Nahi mila" }, { status: 404 }); // Error
```

Default 200 hai. Par POST ke liye 201 dena chahiye — taaki client ko pata chale ki naya resource ban gaya.

---

## Nutshell

HTTP methods batate hain ki client kya karna chahta hai — padhna (GET), banana (POST), update karna (PUT), ya hatana (DELETE). Route Handler mein har method ka apna function hota hai. GET safe hai, POST/PUT/DELETE data change karte hain. Status codes se client ko pata chalta hai ki kya hua.

---

## Common Mistakes

- **GET mein data change karna** — GET safe hona chahiye, sirf read
- **POST ke baad 200 dena** — 201 dena chahiye (Created)
- **Status code na dena** — client ko pata nahi chalega
- **Galat method use karna** — profile update ke liye POST nahi, PUT

4. Comment edit karte waqt UI dynamic detail page pe kyun banate hain?

## What It Is NOT

**HTTP methods = "Next.js ka feature" nahi.** Ye universal hai — har framework mein kaam aata hai. Next.js sirf implementation deta hai.

**GET = "hamesha safe" nahi.** Technically GET mein bhi data badal sakte ho, par practice galat hai. GET ko hamesha safe rakho.
