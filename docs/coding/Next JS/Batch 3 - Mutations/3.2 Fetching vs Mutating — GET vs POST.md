3.1 mein Route Handler banaya — GET aur POST dono likhe. Par ek sawaal utha hoga: **GET aur POST mein fark kya hai? Kab GET use karein, kab POST?**

Ye sirf Next.js ki baat nahi — ye **HTTP protocol** hai. Har web server, har API, har website ye use karti hai.

---

## SOCH: Phone Se Kya Karte Ho?

Phone 2 kaam karta hai:
1. **Calls/Message padhte ho** — kuch nahi badalte, sirf lete ho
2. **Calls/Message karte ho** — kuch bhejte ho, kuch badalte ho

Web bhi same kaam karta hai:
1. **GET** — data padho (kuch nahi badalte)
2. **POST** — data bhejo (kuch badalte ho)

---

## HTTP Methods — 4 Main Hain

| Method | Kaam | Example |
|--------|------|---------|
| `GET` | Data padho (kuch mat chhuo) | Product listing, blog post padhna |
| `POST` | Naya data banao | Comment add karna, form submit karna |
| `PUT` | Existing data update karo | Profile update karna, comment edit karna |
| `DELETE` | Data hatao | Comment delete karna, account delete karna |

Restaurant ka menu soch — **GET** = menu padho, **POST** = order karo, **PUT** = order change karo, **DELETE** = order cancel karo.

## GET Aur POST — Revision

3.1 mein ye dono banaye the. Ek baar yaad karo:

```tsx
// app/api/comments/route.ts
import { NextResponse } from "next/server";

let comments = [
  { id: 1, text: "Pehla comment" },
  { id: 2, text: "Doosra comment" },
];

// GET - Saare comments padho
export async function GET() {
  return NextResponse.json(comments);
}

// POST - Naya comment banao
export async function POST(request: Request) {
  const body = await request.json();
  const newComment = {
    id: comments.length + 1,
    text: body.text,
  };
  comments.push(newComment);
  return NextResponse.json(newComment, { status: 201 });
}
```

**GET** sirf data bhejta hai. **POST** naya data leta hai aur save karta hai.

## Ab PUT Aur DELETE Bhi Seekhte Hain

GET aur POST toh samajh aa gaya. Ab baaki dono — PUT (update) aur DELETE (hatao).

Pehle samjho **array methods** jo use honge:

### `findIndex()` — Position Dhoondo

`findIndex()` array mein se element ka **index** dhoondta hai — element kis position pe hai:

```tsx
const comments = [
  { id: 1, text: "Pehla" },
  { id: 2, text: "Doosra" },
  { id: 3, text: "Teesra" },
];

const index = comments.findIndex((c) => c.id === 2);
console.log(index);  // 1 (doosre position pe hai)

const notFound = comments.findIndex((c) => c.id === 99);
console.log(notFound);  // -1 (nahi mila toh -1)
```

`.find()` vs `.findIndex()` — `.find()` element khud return karta hai, `.findIndex()` position return karta hai. Kyun chahiye? Kyunki update ya delete karne ke liye position pata honi chahiye.

### Spread Operator (`...`) — Copy Karo, Overwrite Karo

Object update karte waqt purane properties copy karo, nayi overwrite karo:

```tsx
const comment = { id: 1, text: "Pehla", createdAt: "2025-01-15" };

const updated = { ...comment, text: "Updated!" };
// { id: 1, text: "Updated!", createdAt: "2025-01-15" }
```

Dekha? `...comment` se saari properties copy hui, phir `text: "Updated!"` ne overwrite kiya. Bina spread ke 3 line likhni padti.

### `splice()` — Hatao

Array mein se element **hataane** ke liye:

```tsx
const fruits = ["apple", "banana", "cherry"];

fruits.splice(1, 1);  // index 1 se 1 element hatao
console.log(fruits);  // ["apple", "cherry"]
```

`splice(index, count)` — index = kahan se, count = kitne.

Comments pe try karte hain:

```tsx
const comments = [
  { id: 1, text: "Pehla" },
  { id: 2, text: "Doosra" },
  { id: 3, text: "Teesra" },
];

// Doosra comment hatana hai (id: 2)
const index = comments.findIndex((c) => c.id === 2);
comments.splice(index, 1);

console.log(comments);
// [{ id: 1, text: "Pehla" }, { id: 3, text: "Teesra" }]
```

`findIndex()` se pehle position nikali (index 1), phir `splice(1, 1)` se us position se 1 element hata diya. **"Doosra" gaya — baaki safe.**

## PUT — Comment Update Karna

```tsx
// app/api/comments/[id]/route.ts
import { NextResponse } from "next/server";

export async function PUT(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const body = await request.json();
  const index = comments.findIndex((c) => c.id === Number(id));

  if (index === -1) {
    return NextResponse.json({ error: "Nahi mila" }, { status: 404 });
  }

  comments[index] = { ...comments[index], text: body.text };
  return NextResponse.json(comments[index]);
}
```

Chal samajhte hain — `await params` se URL mein se `id` nikali. `request.json()` se client ne jo naya text bheja wo liya. `findIndex()` se comment ki position dhoondhi. Agar index -1 hai toh 404 error. Spread operator se purana comment copy kiya + text update kiya. Updated comment client ko bheja.

Notice kiya? **4 steps hain** — find, check, update, return. Ye pattern har jagah milega — GET mein finding nahi hoti, par baaki sab same.

## DELETE — Comment Hatana

```tsx
// DELETE - Comment hatao
export async function DELETE(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const index = comments.findIndex((c) => c.id === Number(id));

  if (index === -1) {
    return NextResponse.json({ error: "Nahi mila" }, { status: 404 });
  }

  comments.splice(index, 1);
  return NextResponse.json({ message: "Delete ho gaya" });
}
```

PUT se zyada simple hai — sirf find, check, splice, return. `splice(index, 1)` se us position se 1 element hat gaya.

Maine bhi pehli baar `splice()` dekh ke socha tha "ye kya hai?" — par yaad rakh, array se element hatana hai toh `splice()`.

## Kab Kya Use Karein?

| Scenario | Method | Kyun? |
|----------|--------|-------|
| Product listing dekhna | GET | Sirf padh rahe ho |
| Blog post padhna | GET | Sirf padh rahe ho |
| Comment add karna | POST | Naya data create kar rahe ho |
| Form submit karna | POST | Server pe data bhej rahe ho |
| Profile update karna | PUT | Existing data badal rahe ho |
| Account delete karna | DELETE | Data hata rahe ho |

**Simple rule:** Sirf padhna hai → **GET**. Kuch badalna hai → **POST/PUT/DELETE**.

## Status Codes — Server Kya Message Bhejta Hai

Jab server response bhejta hai, uske saath ek **status code** jaata hai — three-digit number jo batata hai ki kya hua.

| Status Code | Matlab | Kab |
|-------------|--------|-----|
| 200 | OK | GET successful |
| 201 | Created | POST successful |
| 400 | Bad Request | Galat data aaya |
| 404 | Not Found | Resource nahi mila |
| 500 | Server Error | Server pe gadbad |

Kaise bhejte hain? `NextResponse.json()` mein doosra argument `{ status: code }`:

```tsx
return NextResponse.json(data);                    // Default 200
return NextResponse.json(newItem, { status: 201 }); // POST ke liye
return NextResponse.json({ error: "Nahi mila" }, { status: 404 }); // Error
```

Default 200 hai. Par POST ke liye 201 dena chahiye — taaki client ko pata chale ki naya resource ban gaya.

---

## Nutshell

HTTP methods batate hain ki client kya karna chahta hai — padhna (GET), banana (POST), update karna (PUT), ya hatana (DELETE). Route Handler mein har method ka apna function hota hai. GET safe hai, POST/PUT/DELETE data change karte hain. Status codes se client ko pata chalta hai ki kya hua.

---

## Common Mistakes

- **GET mein data change karna** — GET safe hona chahiye, sirf read
- **POST ke baad 200 dena** — 201 dena chahiye (Created)
- **Status code na dena** — client ko pata nahi chalega
- **Galat method use karna** — profile update ke liye POST nahi, PUT

## What It Is NOT

**HTTP methods = "Next.js ka feature" nahi.** Ye universal hai — har framework mein kaam aata hai. Next.js sirf implementation deta hai.

**GET = "hamesha safe" nahi.** Technically GET mein bhi data badal sakte ho, par practice galat hai. GET ko hamesha safe rakho.
