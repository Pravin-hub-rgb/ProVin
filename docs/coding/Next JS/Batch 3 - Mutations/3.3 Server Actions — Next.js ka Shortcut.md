3.1 aur 3.2 mein Route Handlers seekhe — REST API banaya, GET/POST/PUT/DELETE likhe. Par ek problem thi:

```tsx
// Route Handler - bahut boilerplate
// 1. Route file banao (app/api/comments/route.ts)
// 2. Function likho (POST)
// 3. Request parse karo (await request.json())
// 4. Client mein fetch call karo
```

**4 steps** — har form ke liye. Agar 10 forms hain toh 10 baar ye sab likho.

3.1 mein detail page (`comments/[id]/page.tsx`) yaad karo — **Client Component** banaya tha: `useState`, `useEffect`, `params.then()`, `fetch()`, loading state. Aur 3.2 mein isi detail page pe **Edit button → form** wala PUT flow banaya tha — wahan bhi `params.then`, `fetch`, manual `editing` state. Itna sab boilerplate sirf ek comment dikhane/edite karne ke liye. **Yehi problem hai jiska solution Server Actions hai.**

Server Actions se ye **1 step** mein ho jaata hai.

---

## SOCH: Form Submit Karna Kitna Easy Hona Chahiye?

React mein form submit karna simple tha:

```tsx
<form onSubmit={handleSubmit}>
  <input name="comment" />
  <button type="submit">Submit</button>
</form>
```

Par `handleSubmit` mein kya hota tha? `fetch()` call, JSON stringify, headers set karna — boilerplate.

**Kya hota agar form seedha server function ko call karta — bina API layer ke?**

```tsx
<form action={addComment}>
  <input name="comment" />
  <button type="submit">Submit</button>
</form>
```

Koi `fetch()`, koi API route, koi boilerplate. Form seedha server function call karta hai. **Ye Server Action hai.**

---

## Server Actions — Kaise Kaam Karta Hai?

Server Actions Next.js ka **built-in feature** hai — form seedha server function ko call kare.

Kaise kaam karta hai? Tum `"use server"` likhte ho function ke upar → Next.js automatically ek API endpoint bana deta hai (tumhe dikhata nahi) → Form submit hone pe server pe function call hota hai → Response client ko mil jaata hai.

Matlab — tumhe API route ki zaroorat nahi, Next.js khud handle karta hai.

---

## Server Action Kaisa Dikhta Hai?

Abhi hum **sirf concept** samjh rahe hain — 3.3.1 se lekar 3.3.4 tak ise **asli comments project** pe lagayenge. Pehle ye samjho ki ek Server Action ka shape kya hota hai:

```tsx
// app/actions.ts
"use server";

export async function addComment(formData: FormData) {
  const text = formData.get("comment") as string;
  return { success: true, message: "Comment add ho gaya!" };
}
```

```tsx
// koi bhi form (page ya component mein)
<form action={addComment}>
  <input name="comment" placeholder="Apna comment likho..." />
  <button type="submit">Submit</button>
</form>
```

Dekho kitna simple hai — `"use server"` lagaya, function likha jo `FormData` leta hai, form mein `action={addComment}` daala. **Bas.** Koi `fetch()`, koi API route, koi boilerplate.

Maine bhi pehli baar ye dekh ke socha tha "itna simple ho sakta hai?" — par haan, ho sakta hai. Yahan `addComment` kuch **save nahi karta** (sirf shape dikh raha hai) — **3.3.1 mein isko asli `addComment` function se jodenge** jo 3.1 mein `lib/comments.ts` mein banaya tha.

### Client-Se-Server Mapping — FormData Ka Flow

Confusion ho sakta hai — **`formData.get("comment")` mein "comment" kahan se aaya?**

**Client (form):**
```tsx
<form action={addComment}>
  <input name="comment" placeholder="Apna comment likho..." />
  <button type="submit">Submit</button>
</form>
```

**Server (actions.ts):**
```tsx
export async function addComment(formData: FormData) {
  const text = formData.get("comment") as string;
}
```

**Mapping:**

```
Client                              Server
─────────────────────────────────────────────────────
<input name="comment" />    →    formData.get("comment")
      ↑                                  ↑
      |                                  |
  name attribute               same naam se get karo
```

**Rule:** `<input>` ka `name` attribute aur `formData.get()` ka naam **same hona chahiye.**

```tsx
// Client
<input name="comment" />       →    formData.get("comment")     ✅
<input name="review" />        →    formData.get("review")      ✅
<input name="text" />          →    formData.get("text")        ✅

<input name="comment" />       →    formData.get("text")        ❌ (naam alag hai!)
```

**Route Handler se fark:** Route Handler mein `request.json()` se poora object aata tha. Server Action mein `formData.get("name")` se ek ek field nikalte ho — **field by field.**

```tsx
// Route Handler — ek saath poora body
const body = await request.json();
body.text    // "Naya comment!"

// Server Action — ek ek field
const text = formData.get("comment") as string;
```

## Route Handler vs Server Actions — Same Kaam, Alag Tareeka

**Route Handler (3.1 wala):**
```
Client → fetch("/api/comments", { method: "POST" }) → Route Handler → Response
```
Client ko pata hai ki API call ho rahi hai. Client mein `fetch()` likhna padta hai — headers, JSON.stringify, method.

**Server Action:**
```
Client → Form action={addComment} → Next.js (automatically) → Server Function → Response
```
Client ko pata nahi ki API call ho rahi hai. Sirf `action` attribute lagana hai — boilerplate almost zero.

## Do Tarke Se Server Action Call Kar Sakte Ho

### Tarika 1: Form action attribute (simple, par page reload)

```tsx
// Server Component
<form action={addComment}>
  <input name="comment" />
  <button type="submit">Submit</button>
</form>
```

Simple hai, par page reload hota hai — kyunki ye HTML default behaviour hai.

### Tarika 2: JavaScript se call (no reload, control zyada)

```tsx
// Client Component
"use client";

import { useState } from "react";
import { addComment } from "./actions";

export default function CommentForm() {
  const [message, setMessage] = useState("");

  const handleSubmit = async (formData: FormData) => {
    const result = await addComment(formData);  // Direct function call
    setMessage(result.message);
  };

  return (
    <form action={handleSubmit}>
      <input name="comment" placeholder="Comment..." />
      <button type="submit">Submit</button>
      {message && <p>{message}</p>}
    </form>
  );
}
```

Dekho fark — pehle `action={addComment}` tha (seedha server action), ab `action={handleSubmit}` hai (pehle client function, uske andar server action).

`handleSubmit` kya hai? Normal JavaScript function jo `FormData` leta hai aur `addComment` (Server Action) call karta hai. `addComment` server pe run hota hai, par `handleSubmit` client pe hai — isliye loading state aur messages control kar sakte ho.

**Kyun chahiye?** Kyunki page reload hone se form ka data ud jaata hai, loading state nahi dikha sakte, success/error message dikhana mushkil hai.

## Server Action Kahan Define Karein?

**Option 1: Alag file (recommended)**
```tsx
// app/actions.ts
"use server";

export async function addComment(formData: FormData) { ... }
```

**Option 2: Wahi page mein**
```tsx
// app/page.tsx
async function addComment(formData: FormData) {
  "use server";
  // ...
}

export default function Home() {
  return <form action={addComment}>...</form>;
}
```

Dono sahi hain — par alag file better hai (separation of concerns).

## Server Action Ka Andar Kya Kar Sakte Ho?

Server Action **server pe** run hota hai. Toh tum:
- Database se baat kar sakte ho (Prisma, Supabase)
- Files padh/sakte ho
- Environment variables access kar sakte ho
- Third-party APIs call kar sakte ho

Par **browser APIs** (localStorage, window) nahi chalenge — ye client pe hain.

### Prisma — Database Se Baat Karna

Abhi tak hum **in-memory storage** use kar rahe the — `let comments = [...]`. Ye temporary hai — server restart karo toh sab data ud jaayega.

Production mein **database** use hota hai. Database se baat karne ke liye **ORM** use hota hai — **Prisma** ek popular ORM hai.

```tsx
// Bina ORM ke (SQL likhna padega)
INSERT INTO comments (text) VALUES ('Naya comment');

// Prisma ORM se (JavaScript)
await prisma.comment.create({
  data: { text: "Naya comment" },
});
```

SQL ki jagah JavaScript — Dekha? Abhi sirf example samjho — Prisma setup Batch 5 mein aayega.

### `@/lib/prisma` Kya Hai?

`@/` ek **path alias** hai — project root ko refer karta hai:

```tsx
// Ye dono same hain
import { prisma } from "@/lib/prisma";    // @/ alias se
import { prisma } from "../../lib/prisma"; // relative path se
```

`@/lib/prisma` padhne mein simple hai, chahe kitne bhi folders andar ho.

### Server Action Mein Database Example

```tsx
// app/actions.ts
"use server";

import { prisma } from "@/lib/prisma";

export async function addComment(formData: FormData) {
  const text = formData.get("comment") as string;

  const comment = await prisma.comment.create({
    data: { text },
  });

  return { success: true, comment };
}
```

`prisma.comment.create()` — database mein naya comment banata hai. **Ye abhi samajhna zaroori nahi** — bas itna yaad rakho ki Server Action mein database se baat kar sakte ho.

## Error Handling

Server Action mein error aaye toh kya hoga?

```tsx
// app/actions.ts
"use server";

export async function addComment(formData: FormData) {
  const text = formData.get("comment") as string;

  if (!text) {
    throw new Error("Comment text zaroori hai");
    // Ya return { success: false, error: "Text zaroori hai" }
  }

  // ... save karo
}
```

Client mein error handle karna ho toh `try/catch`:

```tsx
"use client";

import { addComment } from "./actions";

export default function CommentForm() {
  const handleSubmit = async (formData: FormData) => {
    try {
      const result = await addComment(formData);
      console.log("Success:", result);
    } catch (error) {
      console.error("Error:", error);
    }
  };

  return (
    <form action={handleSubmit}>
      <input name="comment" />
      <button type="submit">Submit</button>
    </form>
  );
}
```

## Nutshell

Server Actions Next.js ka shortcut hai — form seedha server function ko call karta hai, bina API route ke. `"use server"` directive lagao, function likho, form mein `action` attribute daalo. Boilerplate almost zero. Par yaad rakho — ye **Next.js specific** hai, universal nahi. REST API (Route Handlers) abhi bhi zaroori hai jab external clients ho.

---

## Common Mistakes

- **`"use server"` na likhna** — bina directive ke function client pe run hoga, server pe nahi
- **Server Action mein browser APIs use karna** — `localStorage`, `window` server pe nahi chalenge
- **`"use server"` har function pe lagana** — sirf server-side functions pe lagao
- **Server Action ko directly export na karna** — `export async function` hona chahiye

## Ab Asli Project Pe Lagate Hain

Concept samajh aa gaya — Server Actions kya hain, `action` attribute kaise kaam karta hai, `FormData` kaise flow hota hai. Par abhi tak wo sab **theory** hai — ek chhota `addComment` shape example tha jo kuch save nahi kar raha tha.

**Asli seekh abhi shuru hogi** — jab hum ise 3.1 aur 3.2 ke **comments project** pe lagate hain. Woh project abhi Route Handlers pe hai (`app/api/comments/route.ts`, `[id]/route.ts`). Ab usko ek-ek karke Server Actions mein convert karenge — **har file mein route handler ko Server Action se replace karenge**.

Aage ke 4 files — 3.3.x series:

| File | Kya Convert Karenge |
|---|---|
| 3.3.1 | POST (comment add) → Server Action |
| 3.3.2 | GET (list) → Server Component direct read |
| 3.3.3 | DELETE → Server Action + hidden input |
| 3.3.4 | Detail page + PUT (edit) → Server Component + action |

<summary>Sample Jawab</summary>

</details>

2. `"use server"` directive kya karta hai?

<details>
<summary>Sample Jawab</summary>

Ye batata hai ki ye function server pe run hona chahiye. Next.js automatically ek API endpoint bana deta hai aur form submit hone pe server pe function call karta hai.

</details>

<details>

</details>

4. Server Action kab use karein aur kab Route Handler?

<details>
<summary>Sample Jawab</summary>

</details>

---

## What It Is NOT

**Server Action = "REST API ka replacement" nahi.** Dono alag jagah kaam aate hain. Server Action Next.js specific hai, REST universal hai.

**Server Action = "hamesha better" nahi.** Boilerplate kam karta hai, par control bhi kam hota hai. Complex operations ke liye Route Handler better hai.

**Server Action = "client pe run hota hai" nahi.** Server pe run hota hai — isliye database, env vars, third-party APIs access kar sakte ho.
