3.1 aur 3.2 mein Route Handlers seekhe — REST API banaya, GET/POST/PUT/DELETE likhe. Par ek problem thi:

```tsx
// Route Handler — bahut boilerplate
// 1. Route file banao (app/api/comments/route.ts)
// 2. Function likho (POST)
// 3. Request parse karo (await request.json())
// 4. Client mein fetch call karo (fetch("/api/comments", { method: "POST", ... }))
```

**4 steps** — har form ke liye. Agar 10 forms hain toh 10 baar ye sab likho.

Server Actions se ye **1 step** mein ho jaata hai.

---

## SOCH: Form Submit Karna Kitna Easy Hona Chahiye?

React mein form submit karna simple tha:

```tsx
// React — form submit
<form onSubmit={handleSubmit}>
  <input name="comment" />
  <button type="submit">Submit</button>
</form>
```

Par `handleSubmit` mein kya hota tha? `fetch()` call, JSON stringify, headers set karna — boilerplate.

**Kya hota agar form seedha server function ko call karta — bina API layer ke?**

```tsx
// Server Action — ye possible hai Next.js mein
<form action={addComment}>
  <input name="comment" />
  <button type="submit">Submit</button>
</form>
```

Koi `fetch()`, koi API route, koi boilerplate. Form seedha server function call karta hai. **Ye Server Action hai.**

---

## CONCEPT: Server Actions

Server Actions Next.js ka **built-in feature** hai — form seedha server function ko call kare. `"use server"` directive lagao, function likho, done.

**Kaise kaam karta hai:**
1. Tum `"use server"` likhte ho function ke upar
2. Next.js automatically ek API endpoint bana deta hai (tumhe dikhata nahi)
3. Form submit hone pe, Next.js server pe function call karta hai
4. Response client ko mil jaata hai

**Matlab:** Tumhe API route ki zaroorat nahi — Next.js khud handle karta hai.

---

## CODE: Pehla Server Action

```tsx
// app/actions.ts
"use server";

export async function addComment(formData: FormData) {
  const text = formData.get("comment") as string;

  // Server pe data save karo (abhi in-memory)
  console.log("Comment received:", text);

  // Kuch return karo
  return { success: true, message: "Comment add ho gaya!" };
}
```

```tsx
// app/page.tsx
import { addComment } from "./actions";

export default function Home() {
  return (
    <form action={addComment}>
      <input name="comment" placeholder="Apna comment likho..." />
      <button type="submit">Submit</button>
    </form>
  );
}
```

**Dekho kitna simple hai:**
1. `"use server"` lagaya
2. Function likha jo `FormData` leta hai
3. Form mein `action={addComment}` daala
4. **Bas.** Koi `fetch()`, koi API route, koi boilerplate.

---

## Route Handler vs Server Actions — Same Kaam, Alag Tareeka

**Route Handler (3.1 wala):**
```
Client → fetch("/api/comments", { method: "POST" }) → Route Handler → Response
```
- Client ko pata hai ki API call ho rahi hai
- Client mein `fetch()` likhna padta hai
- Boilerplate: headers, JSON.stringify, method

**Server Action:**
```
Client → Form action={addComment} → Next.js (automatically) → Server Function → Response
```
- Client ko pata nahi ki API call ho rahi hai
- Client mein sirf `action` attribute lagana hai
- Boilerplate:几乎 zero

---

## CODE: Server Action with async/await

Upar wala example mein form submit hone pe **page reload** hota hai — kyunki ye HTML default behaviour hai. Par agar tum chaho toh **JavaScript se bhi call kar sakte ho** — `use client` component mein.

**Kyun chahiye?** Kyunki page reload hone se:
- Form ka data ud jaata hai
- Loading state nahi dikha sakte
- Success/error message dikhana mushkil hai

### Do Tarke Se Server Action Call Kar Sakte Ho

**Tarika 1: Form action attribute (simple, par page reload)**
```tsx
// Server Component
<form action={addComment}>
  <input name="comment" />
  <button type="submit">Submit</button>
</form>
```

**Tarika 2: JavaScript se call (no reload, control zyada)**
```tsx
// Client Component
"use client";

import { useState } from "react";
import { addComment } from "./actions";

export default function CommentForm() {
  const [message, setMessage] = useState("");

  const handleSubmit = async (formData: FormData) => {
    const result = await addComment(formData);  // Direct function call
    setMessage(result.message);
  };

  return (
    <form action={handleSubmit}>
      <input name="comment" placeholder="Comment..." />
      <button type="submit">Submit</button>
      {message && <p>{message}</p>}
    </form>
  );
}
```

**Dekho fark:**
- Pehle: `action={addComment}` — seedha server action call
- Ab: `action={handleSubmit}` — pehle client function, uske andar server action

**`handleSubmit` kya hai?** Ye ek normal JavaScript function hai jo `FormData` leta hai aur `addComment` (Server Action) call karta hai. `addComment` server pe run hota hai, par `handleSubmit` client pe hai — isliye loading state aur messages control kar sakte ho.

---

## Server Action Kahan Define Karein?

**Option 1: Alag file (recommended)**
```tsx
// app/actions.ts
"use server";

export async function addComment(formData: FormData) { ... }
```

**Option 2: Wahi page mein**
```tsx
// app/page.tsx
async function addComment(formData: FormData) {
  "use server";
  // ...
}

export default function Home() {
  return <form action={addComment}>...</form>;
}
```

**Dono sahi hain** — par alag file better hai (separation of concerns).

## Server Action Ka Andar Kya Kar Sakte Ho?

Server Action **server pe** run hota hai. Toh tum:
- Database se baat kar sakte ho (Prisma, Supabase)
- Files padh/sakte ho
- Environment variables access kar sakte ho
- Third-party APIs call kar sakte ho
- Browser APIs (localStorage, window) nahi chalenge — ye client pe hain

### Prisma Kya Hai?

Abhi tak hum **in-memory storage** use kar rahe the — `let comments = [...]`. Ye temporary hai — server restart karo toh sab data ud jaayega.

Production mein **database** use hota hai (PostgreSQL, MySQL, MongoDB). Database se baat karne ke liye **ORM** use hota hai.

**ORM (Object-Relational Mapping)** ek library hai jo JavaScript objects ko database tables mein convert karti hai. Tumhe SQL likhne ki zaroorat nahi — sirf JavaScript likho.

```tsx
// Bina ORM ke (SQL likhna padega)
INSERT INTO comments (text) VALUES ('Naya comment');

// Prisma ORM se (JavaScript)
await prisma.comment.create({
  data: { text: "Naya comment" },
});
```

Dekha? SQL ki jagah JavaScript. Prisma ek popular ORM hai Next.js projects mein.

### Prisma Kab Seekhoge?

Abhi ke liye sirf example samjho — Prisma setup aur usage Batch 5 mein detail mein seekhoge. Abhi ke liye ye yaad rakho ki Server Action mein database access kar sakte ho.

### `@/lib/prisma` Kya Hai?

`@/` ek **path alias** hai — ye project root ko refer karta hai. `tsconfig.json` mein configure hota hai.

```tsx
// Ye dono same hain
import { prisma } from "@/lib/prisma";    // @/ alias se
import { prisma } from "../../lib/prisma"; // relative path se
```

**Kyun use karte hain?** Kyunki `@/lib/prisma` padhne mein simple hai, chahe kitne bhi folders andar ho. Relative paths mein `../../` count karna padta hai.

### Server Action Mein Database Example

```tsx
// app/actions.ts
"use server";

import { prisma } from "@/lib/prisma";  // Prisma client import karo

export async function addComment(formData: FormData) {
  const text = formData.get("comment") as string;

  // Database mein save karo
  const comment = await prisma.comment.create({
    data: { text },  // { text: "Naya comment" } jaisa hoga
  });

  return { success: true, comment };
}
```

**Kya ho raha hai?**
1. `prisma.comment.create()` — database mein naya comment banata hai
2. `data: { text }` — comment ka data (text field)
3. Database se response aata hai — `comment` variable mein save hota hai

**Ye abhi samajhna zaroori nahi** — Prisma setup Batch 5 mein aayega. Abhi ke liye bas itna yaad rakho ki Server Action mein database se baat kar sakte ho.

## Error Handling

Server Action mein error aaye toh kya hoga?

```tsx
// app/actions.ts
"use server";

export async function addComment(formData: FormData) {
  const text = formData.get("comment") as string;

  if (!text) {
    throw new Error("Comment text zaroori hai");
    // Ya return { success: false, error: "Text zaroori hai" }
  }

  // ... save karo
}
```

Client mein error handle karna ho toh `try/catch` use karo:

```tsx
"use client";

import { addComment } from "./actions";

export default function CommentForm() {
  const handleSubmit = async (formData: FormData) => {
    try {
      const result = await addComment(formData);
      console.log("Success:", result);
    } catch (error) {
      console.error("Error:", error);
    }
  };

  return (
    <form action={handleSubmit}>
      <input name="comment" />
      <button type="submit">Submit</button>
    </form>
  );
}
```

## Nutshell

Server Actions Next.js ka shortcut hai — form seedha server function ko call karta hai, bina API route ke. `"use server"` directive lagao, function likho, form mein `action` attribute daalo. Boilerplate almost zero. Par yaad rakho — ye **Next.js specific** hai, universal nahi. REST API (Route Handlers) abhi bhi zaroori hai jab external clients ho.

---

## Common Mistakes

- ❌ `"use server"` na likhna — bina directive ke function client pe run hoga, server pe nahi
- ❌ Server Action mein browser APIs use karna — `localStorage`, `window` server pe nahi chalenge
- ❌ `"use server"` har function pe lagana — sirf server-side functions pe lagao, client-side functions pe nahi
- ❌ Server Action ko directly export na karna — `export async function` hona chahiye

## In Your Own Words

1. Server Action aur Route Handler mein kya fark hai? Same kaam dono karte hain, par tareeka alag hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Route Handler mein tum API endpoint banate ho (`/api/comments`) aur client `fetch()` se call karta hai. Server Action mein tum sirf function likhte ho (`"use server"`) aur form seedha usse call karta hai — koi API route nahi, koi `fetch()` nahi. Boilerplate kam hota hai.

</details>

2. `"use server"` directive kya karta hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Ye batata hai ki ye function server pe run hona chahiye. Next.js automatically ek API endpoint bana deta hai (hidden) aur form submit hone pe server pe function call karta hai. Bina directive ke function client pe run hoga.

</details>

3. Server Action mein database se baat kar sakte ho?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Haan, bilkul. Server Action server pe run hota hai, toh tum Prisma, Supabase, ya koi bhi database use kar sakte ho. Environment variables bhi access kar sakte ho. Sirf browser APIs (localStorage, window) nahi chalenge.

</details>

4. Server Action kab use karein aur kab Route Handler?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Server Action tab jab sirf Next.js app hai aur simple form submission ho. Route Handler tab jab external client ho (mobile app, third-party website), ya complex API chahiye, ya REST standard follow karna ho.

</details>

---

## What It Is NOT

⚠️ **Server Action = "REST API ka replacement" nahi.** Dono alag alag jagah kaam aate hain. Server Action Next.js specific hai, REST universal hai.

⚠️ **Server Action = "hamesha better" nahi.** Server Action boilerplate kam karta hai, par control bhi kam hota hai. Complex operations ke liye Route Handler better hai.

⚠️ **Server Action = "client pe run hota hai" nahi.** Server Action server pe run hota hai — isliye database, env vars, third-party APIs access kar sakte ho. Client sirf function call karta hai.
