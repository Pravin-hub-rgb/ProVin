# Create — Form UI + POST Route + Axios (3.4.7)

## Where We Left Off

In 3.4.6, we built the detail page that shows a single review. The list page links to it. Now we need to close the loop — let users **create** new reviews by filling out a form.

We'll follow the incremental approach we've used throughout: **UI first, then route, then connect**. This way, if something breaks, we know whether the problem is in the layout, the server logic, or the connection.

## Why UI First?

Before wiring up real functionality, we confirm the form looks right. This is like reviewing a restaurant menu before ordering — you want to see all the options and how they're presented before committing. If we built everything at once (form + route + axios) and something looked wrong, we'd have to debug the UI, the server logic, and the networking separately.

With static UI first:
- You confirm the form fields, layout, and styling
- When you click submit and nothing happens, you know that's expected (it's just UI)
- Then you add the route — if that works, you see real data
- Then you connect with axios — if that works, the full flow is complete

## Step 1: Form UI — Just the Structure

Create the form with a textarea for the review text, a dropdown for the rating, and a submit button:

```tsx
// app/components/ReviewForm.tsx
"use client";

import { useState } from "react";

export function ReviewForm({ productId }: { productId: number }) {
  const [text, setText] = useState("");
  const [rating, setRating] = useState(5);

  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    console.log("Submitted:", { text, rating, productId });
  };

  return (
    <form onSubmit={handleSubmit} className="space-y-3 border p-4 rounded bg-white mt-4">
      <h3 className="font-bold">New Review</h3>

      <div>
        <label className="block text-sm font-medium mb-1">Rating:</label>
        <select
          value={rating}
          onChange={(e) => setRating(Number(e.target.value))}
          className="border p-2 rounded w-full"
        >
          {[1, 2, 3, 4, 5].map((n) => (
            <option key={n} value={n}>{"⭐".repeat(n)}</option>
          ))}
        </select>
      </div>

      <div>
        <label className="block text-sm font-medium mb-1">Review:</label>
        <textarea
          value={text}
          onChange={(e) => setText(e.target.value)}
          placeholder="Write your review..."
          className="w-full border p-2 rounded"
          rows={3}
        />
      </div>

      <button type="submit" className="bg-blue-500 text-white px-4 py-2 rounded hover:bg-blue-600">
        Submit Review
      </button>
    </form>
  );
}
```

This is a **controlled form** — `value` is tied to React state via `useState`, and `onChange` updates that state. We'll see an **uncontrolled** alternative in the Server Actions version (3.4.10).

## Step 3: Create POST Route

The form needs somewhere to send data. Create the POST route in the existing API file:

```tsx
// app/api/reviews/route.ts — add POST alongside GET
import { NextResponse } from "next/server";
import { getAllReviews, getReviewsByProduct, addReview } from "@/lib/reviews";

export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const productId = searchParams.get("productId");

  if (productId) {
    return NextResponse.json(getReviewsByProduct(Number(productId)));
  }
  return NextResponse.json(getAllReviews());
}

export async function POST(request: Request) {
  const body = await request.json();

  // Validation
  if (!body.text || !body.productId || !body.rating) {
    return NextResponse.json(
      { error: "text, productId, and rating are required" },
      { status: 400 }
    );
  }

  const review = addReview({
    productId: Number(body.productId),
    text: body.text,
    rating: Number(body.rating),
  });

  if (!review) {
    return NextResponse.json(
      { error: "Failed to add review — check text and rating" },
      { status: 400 }
    );
  }

  return NextResponse.json(review, { status: 201 });
}
```

### How POST Works

1. **`await request.json()`** — Parse the incoming JSON body.
2. **Validation** — Ensure all required fields are present.
3. **`addReview()`** — Call the data layer to actually save the review.
4. **Return** — Send back the new review with status `201` (Created, per HTTP convention).

## Step 4: Connect — Form to API

Now update the form's `handleSubmit` to use axios instead of console.log:

```tsx
// app/components/ReviewForm.tsx — updated handleSubmit
import axios from "axios";

const handleSubmit = async (e: React.FormEvent) => {
  e.preventDefault();

  try {
    const res = await axios.post("/api/reviews", {
      productId,
      text,
      rating,
    });

    console.log("Added:", res.data);
    setText("");
    setRating(5);
  } catch (error) {
    if (axios.isAxiosError(error)) {
      console.error("Error:", error.response?.data?.error);
    }
  }
};
```

## Step 5: Add Pending State

When the user clicks submit, there's a network request in flight. We need to tell the user "we're working on it":

```tsx
const [pending, setPending] = useState(false);

const handleSubmit = async (e: React.FormEvent) => {
  e.preventDefault();
  setPending(true);

  try {
    await axios.post("/api/reviews", { productId, text, rating });
    setText("");
    setRating(5);
    window.location.reload();
  } catch (error) {
    console.error("Error:", error);
  } finally {
    setPending(false);
  }
};
```

And in the JSX:

```tsx
<button
  type="submit"
  disabled={pending}
  className="bg-blue-500 text-white px-4 py-2 rounded hover:bg-blue-600 disabled:bg-gray-400"
>
  {pending ? "Adding..." : "Submit Review"}
</button>
```

## Full Component

```tsx
// app/components/ReviewForm.tsx
"use client";

import { useState } from "react";
import axios from "axios";

export function ReviewForm({ productId }: { productId: number }) {
  const [text, setText] = useState("");
  const [rating, setRating] = useState(5);
  const [pending, setPending] = useState(false);
  const [message, setMessage] = useState("");

  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    setPending(true);
    setMessage("");

    try {
      await axios.post("/api/reviews", { productId, text, rating });
      setMessage("Review added successfully!");
      setText("");
      setRating(5);
      window.location.reload();
    } catch (error) {
      if (axios.isAxiosError(error)) {
        setMessage(error.response?.data?.error || "Failed to add review");
      }
    } finally {
      setPending(false);
    }
  };

  return (
    <form onSubmit={handleSubmit} className="space-y-3 border p-4 rounded bg-white mt-4">
      <h3 className="font-bold">New Review</h3>

      <div>
        <label className="block text-sm font-medium mb-1">Rating:</label>
        <select
          value={rating}
          onChange={(e) => setRating(Number(e.target.value))}
          className="border p-2 rounded w-full"
          disabled={pending}
        >
          {[1, 2, 3, 4, 5].map((n) => (
            <option key={n} value={n}>{"⭐".repeat(n)}</option>
          ))}
        </select>
      </div>

      <div>
        <label className="block text-sm font-medium mb-1">Review:</label>
        <textarea
          value={text}
          onChange={(e) => setText(e.target.value)}
          placeholder="Write your review..."
          className="w-full border p-2 rounded"
          rows={3}
          disabled={pending}
        />
      </div>

      <button
        type="submit"
        disabled={pending}
        className="bg-blue-500 text-white px-4 py-2 rounded hover:bg-blue-600 disabled:bg-gray-400"
      >
        {pending ? "Adding..." : "Submit Review"}
      </button>

      {message && (
        <p className={message.includes("Failed") ? "text-red-500" : "text-green-500"}>
          {message}
        </p>
      )}
    </form>
  );
}
```

## What It Is NOT

- **`window.location.reload()` is not "best practice"** — it's a simple solution for now. We'll use `revalidatePath` later in the Server Actions version, and `router.refresh()` as an intermediate step.
- **Validation on the client is not "secure"** — always validate on the server too. Client-side validation improves UX; server-side validation ensures data integrity.
- **Controlled inputs are not "always required"** — they're necessary here because React state tracks the form values. Server Actions will use uncontrolled inputs (`defaultValue`) to simplify.

## In Your Own Words

<details>
<summary>Question 1: Why use controlled form inputs (`value` + `onChange`) with Route Handlers?</summary>
<p><strong>Answer:</strong> Controlled inputs let React track form state in real-time. When you submit, React has the current text and rating values in state. You need this to pass the data to `axios.post()`. With uncontrolled inputs, you'd need to read the DOM manually.</p>
</details>

<details>
<summary>Question 2: Why do we need both client and server validation?</summary>
<p><strong>Answer:</strong> Client validation gives instant feedback (no network round-trip) and improves UX. But it can be bypassed — a user can disable JavaScript or send raw requests. Server validation is the last line of defense — it guarantees data integrity regardless of how the request arrives.</p>
</details>

<details>
<summary>Question 3: What does `axios.isAxiosError(error)` do?</summary>
<p><strong>Answer:</strong> It's a type guard that tells you whether the error was an axios error (as opposed to another kind of error). It lets you safely access `error.response?.data?.error` — axios error responses have a `data` property with the server's error message.</p>
</details>

<details>
<summary>Question 4: Why is `disabled={pending}` important?</summary>
<p><strong>Answer:</strong> It prevents double submits. Without it, a user might click submit multiple times while waiting, creating duplicate reviews. The `finally` block resets `pending` to false regardless of success or failure.</p>
</details>
