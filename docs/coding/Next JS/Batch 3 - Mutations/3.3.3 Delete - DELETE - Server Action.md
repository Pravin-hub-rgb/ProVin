3.3.2 mein list ko Server Component bana diya — ab comments direct `getAllComments()` se dikhte hain, bina kisi `useEffect`/`fetch` ke. Form add bhi kaam karta hai.

Ab ek cheez bachi hai jo abhi tak REST se chalti hai — **delete**. 3.2 mein delete button `ShowComments.tsx` ke andar banaya tha, aur 3.3.2 mein list ko props wala presentational component bana diya (delete button wahi reh gaya). Ab is delete ko bhi **Server Action** banaenge — aur is baar ek **naya pattern** dikhega: **Delete button ka form + hidden input.**

3.2 / 3.3.2 mein delete kaise kiya tha yaad karo — `handleDelete` mein `fetch("/api/comments/${id}", { method: "DELETE" })`. Ab wo `fetch` bhi hat jaata hai.

## Step 1: deleteCommentAction Banao — app/actions.ts

Pehle server function banayenge, phir Step 2 mein UI mein use karenge. **Order kyun?** Kyunki form `useActionState` ke through `deleteCommentAction` ko call karta hai — agar action pehle nahi bana toh form mein import kuch nahi milega. 3.3.1 wale pattern ki tarah: **function pehle, form baad mein.**

Ab `app/actions.ts` mein delete aur add dono likhenge:

**File:** `app/actions.ts`

```tsx
// app/actions.ts — UPDATED (addCommentAction + deleteCommentAction)
"use server";

import { revalidatePath } from "next/cache";
import { addComment, deleteComment } from "@/lib/comments";

export type FormState = {
  success: boolean;    // true ya false hoga
  message: string;     // text hoga
};

// 3.3.1 Step 4 (useActionState) + 3.3.2 Step 2 (revalidatePath) se — wahi pattern
export async function addCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const text = formData.get("comment") as string;

  if (!text || !text.trim()) {
    return { success: false, message: "Comment khali nahi ho sakta!" };
  }

  addComment(text);

  revalidatePath("/");

  return { success: true, message: "Comment add ho gaya!" };
}

// NAYA: delete action — wahi pattern, bas deleteComment function call
export async function deleteCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const id = Number(formData.get("id"));

  const deleted = deleteComment(id);

  if (!deleted) {
    return { success: false, message: "Comment nahi mila!" };
  }

  // Delete bhi mutation hai — page fresh render taaki list se gayab dikhe
  revalidatePath("/");

  return { success: true, message: "Comment delete ho gaya!" };
}
```

**Dekho — ye bilkul addCommentAction jaisa pattern hai** — `prevState` pehla argument, `Promise<FormState>` return type, aur form mein `formAction` se call hoga (Step 2 mein). Fark sirf kaam ka: `formData.get("id")` se id nikali, `deleteComment()` function call kiya (3.2 mein tha, `splice` se hatata hai), `deleted` check kiya (agar false → comment nahi mila). Aur **donon action mein `revalidatePath("/")`** — kyunki add ho ya delete, dono mutation hain aur mutation ke baad page fresh render karna standard practice hai (3.3.2 Step 2 mein seekha).

**`Number()` kyun?** Hidden input ki value **string** hoti hai (`"3"`). `deleteComment()` ko number chahiye (`3`). Isliye `Number(formData.get("id"))`.

**Kya `deleteComment` hata bhi raha hai file se?** Haan — wo 3.2 mein banaya function hai jo `comments.json` se comment nikal ke file mein wapas likh deta hai. Server Action sirf usko call karta hai.

**Abhi ye function kahin use nahi hua** — bas bana ke rakha hai. Step 2 mein form banate hi isko import karke use karenge.

## Step 2: ShowComments Mein Delete Button Ko Form Banao

Ab `deleteCommentAction` ready hai — isko UI mein use karte hain.

3.3 mein padha tha — Server Action koi bhi form se chal sakta hai. Delete button ab **form** hi hai — kyunki usme submit karte waqt `id` bhejna hai. Naya component nahi banayenge — **form seedha `ShowComments.tsx` ke andar** hi laga denge (kyunki list aur delete button dono yahin hain).

**Pehla sawaal — form ka `action` kya hoga?**

`addCommentAction` jaise function nahi — kyunki wo `FormData` leta hai usme se `comment` nikalta tha. Delete mein bhi `FormData` aayega, par usme **`id`** hogi (hidden input ke through) — `text` nahi.

**File:** `app/components/ShowComments.tsx`

```tsx
// app/components/ShowComments.tsx — UPDATED (delete ab form + useActionState + toast)
"use client";

import Link from "next/link";
import { useEffect, useActionState } from "react";
import { toast } from "sonner";
import { deleteCommentAction, FormState } from "../actions";

const initialState: FormState = {
  success: false,     // Abhi kuch hua nahi
  message: "",        // Abhi message nahi hai
};

export default function ShowComments({
  comments,
}: {
  comments: { id: number; text: string }[];
}) {
  const [state, formAction, isPending] = useActionState(
    deleteCommentAction,
    initialState
  );

  // Toast — 3.3.1 Step 4 wala hi pattern
  useEffect(() => {
    if (state.message) {
      if (state.success) toast.success(state.message);
      else toast.error(state.message);
    }
  }, [state]);

  return (
    <div className="p-4 border rounded">
      <h2 className="text-xl font-bold mb-4">Comments</h2>
      <ul className="space-y-2">
        {comments.map((comment) => (
          <li key={comment.id} className="border-b pb-2 flex items-center justify-between">
            <Link href={`/comments/${comment.id}`} className="hover:underline">
              {comment.text}
            </Link>

            <form action={formAction}>
              <input type="hidden" name="id" value={comment.id} />
              <button
                type="submit"
                disabled={isPending}
                className="text-red-500 hover:underline text-sm disabled:opacity-50"
              >
                Delete
              </button>
            </form>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

Dekho:
1. **`action={formAction}`** — Wahi `useActionState` ka adapter jo 3.3.1 Step 4 mein add form mein lagaya tha. `formAction` delete submit pe `deleteCommentAction(prevState, formData)` call karta hai aur result `state` mein store hota hai.
2. **`<input type="hidden" name="id" value={comment.id} />`** — Ye naya concept hai. `type="hidden"` input user ko **dikhta nahi**, par form submit pe **data mein jaata hai**. Jab user "Delete" click karega, form submit hoga aur `id` server action tak pahunchegi.
3. **`name="id"`** — Matlab server action mein `formData.get("id")` se ye value milegi. Wahi name↔get matching rule.
4. **`disabled={isPending}`** — delete chal raha hai toh button kaam nahi karega (double submit nahi hoga). Wahi 3.3.1 ka `isPending` use.

**Toast aur `useActionState` kyun chahiye?** Delete bhi mutation hai — user ko pata hona chahiye ki "Comment delete ho gaya!" ya galat id pe "Comment nahi mila!". Isliye `deleteCommentAction` ko wahi `prevState` + return-type pattern diya (Step 1 mein) jo 3.3.1 mein add ko diya tha. `ShowComments` already Client Component hai (`"use client"`), isliye hook yahan chal jaata hai.

## Step 3: DELETE Route Handler Delete Karo

Ab `app/api/comments/[id]/route.ts` mein DELETE use nahi ho raha — wo bhi gayab ho jaata hai. Is file mein 3.2 se **teen handlers** the — **GET** (detail), **PUT** (edit), **DELETE**. Ab sirf **DELETE** hatana hai; GET aur PUT abhi rehne do (edit abhi bhi REST se chalta hai — wo 3.3.4 mein Server Action banega).

**File:** `app/api/comments/[id]/route.ts`

```tsx
// app/api/comments/[id]/route.ts — UPDATED (sirf DELETE hata diya)
import { NextResponse } from "next/server";
import { getCommentById, updateComment } from "@/lib/comments";

export async function GET(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const comment = getCommentById(Number(id));

  if (!comment) {
    return NextResponse.json({ error: "Comment nahi mila" }, { status: 404 });
  }

  return NextResponse.json(comment);
}

export async function PUT(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const body = await request.json();

  // Validation — empty text allow mat karo
  if (!body.text || !body.text.trim()) {
    return NextResponse.json(
      { error: "Text khali nahi ho sakta" },
      { status: 400 }
    );
  }

  const updated = updateComment(Number(id), body.text);

  if (!updated) {
    return NextResponse.json({ error: "Nahi mila" }, { status: 404 });
  }

  return NextResponse.json(updated);
}
```

**NOTE:** Is file ka `GET` aur `PUT` abhi bhi hain! Kyunki detail page (`GET`) abhi client side `fetch("/api/comments/${id}")` kar raha hai, aur edit (`PUT`) abhi bhi `fetch` + `method: "PUT"` se chalta hai. Dono 3.3.4 mein hatenge — `GET` Server Component banega, `PUT` Server Action. **Abhi sirf DELETE hataya hai.**

## Kya Badla? — Ab Tak Ka Summary

| | 3.1 / 3.2 | Ab |
|---|---|---|
| **GET (list)** | Route Handler + Client `useEffect`/`fetch` | Server Component `getAllComments()` direct |
| **POST** | Route Handler + Client `fetch` | Server Action `action={formAction}` + toast (3.3.1) |
| **DELETE** | Route Handler + Client `fetch` + URL id | Server Action + form + hidden input `id` + `useActionState` + toast |

**Hidden input ka concept yahin seekha** — jab mutation mein value bhejni ho jo user se nahi aa rahi (jabki `text` form field se aati hai, `id` hum kaise bhejen?), toh hidden input.

## What It Is NOT

**Hidden input = "user data hide karna" nahi.** User browser ke DevTools se isko pehle bhi dekh sakta hai. Ye sirf "user ko UI mein na dikhao, par form ke saath bhejo" ke liye hai. Security ke liye server pe fir bhi validate karna padta hai.

**`.map()` ke andar form/button = "har render pe naya component" nahi.** React ko `<li key>` se track karta hai — isliye form+delete button dene pe bhi `key` zaroori hai taki list sync rahe.

**Server Action = "page refresh hota hai — isliye kharab" nahi.** `useActionState` se `isPending` aur toast feedback milta hai — user ko pata hai ki kya ho raha hai. Refresh ka jhol `revalidatePath` handle karta hai.
