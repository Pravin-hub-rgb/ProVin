3.3.2 mein list ko Server Component bana diya — ab comments direct `getAllComments()` se dikhte hain, bina kisi `useEffect`/`fetch` ke. Form add bhi kaam karta hai.

Ab ek cheez bachi hai jo abhi tak REST se chalti hai — **delete**. 3.2 mein delete button `ShowComments.tsx` ke andar banaya tha, aur 3.3.2 mein list ko props wala presentational component bana diya (delete button wahi reh gaya). Ab is delete ko bhi **Server Action** banaenge — aur is baar ek **naya pattern** dikhega: **Delete button ka form + hidden input.**

3.2 / 3.3.2 mein delete kaise kiya tha yaad karo — `handleDelete` mein `fetch("/api/comments/${id}", { method: "DELETE" })`. Ab wo `fetch` bhi hat jaata hai.

## Step 1: ShowComments Mein Delete Button Ko Form Banao

3.3 mein padha tha — Server Action koi bhi form se chal sakta hai. Delete button ab **form** hi hai — kyunki usme submit karte waqt `id` bhejna hai. Naya component nahi banayenge — **form seedha `ShowComments.tsx` ke andar** hi laga denge (kyunki list aur delete button dono yahin hain).

**Pehla sawaal — form ka `action` kya hoga?**

`addCommentAction` jaise function nahi — kyunki wo `FormData` leta hai usme se `comment` nikalta tha. Delete mein bhi `FormData` aayega, par usme **`id`** hogi (hidden input ke through) — `text` nahi.

**File:** `app/components/ShowComments.tsx`

```tsx
// app/components/ShowComments.tsx — UPDATED (delete ab form + server action)
"use client";

import Link from "next/link";
import { deleteCommentAction } from "../actions";

export default function ShowComments({
  comments,
}: {
  comments: { id: number; text: string }[];
}) {
  return (
    <div className="p-4 border rounded">
      <h2 className="text-xl font-bold mb-4">Comments</h2>
      <ul className="space-y-2">
        {comments.map((comment) => (
          <li key={comment.id} className="border-b pb-2 flex items-center justify-between">
            <Link href={`/comments/${comment.id}`} className="hover:underline">
              {comment.text}
            </Link>

            <form action={deleteCommentAction}>
              <input type="hidden" name="id" value={comment.id} />
              <button type="submit" className="text-red-500 hover:underline text-sm">
                Delete
              </button>
            </form>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

Dekho:
1. **`<form action={deleteCommentAction}>`** — Wahi pattern jo add mein tha. Bas `deleteCommentAction` ab `app/actions.ts` mein likhna baaki hai.
2. **`<input type="hidden" name="id" value={comment.id} />`** — Ye naya concept hai. `type="hidden"` input user ko **dikhta nahi**, par form submit pe **data mein jaata hai**. Jab user "Delete" click karega, form submit hoga aur `id` server action tak pahunchegi.
3. **`name="id"`** — Matlab server action mein `formData.get("id")` se ye value milegi. Wahi name↔get matching rule.

**`"use client"` rehne do** — `ShowComments` ko delete button ke interaction ke liye client hona zaroori hai. Par **Server Action ka form Client Component mein bhi chalta hai** — `action={deleteCommentAction}` seedha import karke form pe laga sakte ho. Ye allowed hai; Client Component sirf action ko *call* karta hai, action khud server pe run hota hai.

## Step 2: deleteCommentAction Banao — app/actions.ts

Ab `app/actions.ts` mein delete aur add dono likhenge:

**File:** `app/actions.ts`

```tsx
// app/actions.ts — UPDATED (addCommentAction + deleteCommentAction)
"use server";

import { revalidatePath } from "next/cache";
import { addComment, deleteComment } from "@/lib/comments";

export async function addCommentAction(formData: FormData) {
  const text = formData.get("comment") as string;

  if (!text || !text.trim()) {
    return { success: false, message: "Comment khali nahi ho sakta!" };
  }

  const newComment = addComment(text);

  // Mutation ke baad page fresh render (3.3.1 Step 5 se yahi pattern)
  revalidatePath("/");

  return {
    success: true,
    message: "Comment add ho gaya!",
  };
}

// NAYA: delete action — wahi pattern, bas deleteComment function call
export async function deleteCommentAction(formData: FormData) {
  const id = Number(formData.get("id"));

  const deleted = deleteComment(id);

  if (!deleted) {
    return { success: false, message: "Comment nahi mila!" };
  }

  // Delete bhi mutation hai — page fresh render taaki list se gayab dikhe
  revalidatePath("/");

  return { success: true, message: "Comment delete ho gaya!" };
}
```

Dekho — **ye bilkul addCommentAction jaisa pattern hai.** `formData.get("id")` se id nikali, `deleteComment()` function call kiya (3.2 mein tha, `splice` se hatata hai), `deleted` check kiya (agar false → comment nahi mila). Aur **donon action mein `revalidatePath("/")`** — kyunki add ho ya delete, dono mutation hain aur mutation ke baad page fresh render karna standard practice hai (3.3.1 Step 5 mein seekha).

**`Number()` kyun?** Hidden input ki value **string** hote hai (`"3"`). `deleteComment()` ko number chahiye (`3`). Isliye `Number(formData.get("id"))`.

**Kya `deleteComment` hata bhi raha hai file se?** Haan — wo 3.2 mein banaya function hai jo `comments.json` se comment nikal ke file mein wapas likh deta hai. Server Action sirf usko call karta hai.

## Kya Badla? — Ab Tak Ka Summary

| | 3.1 / 3.2 | Ab |
|---|---|---|
| **GET (list)** | Route Handler + Client `useEffect`/`fetch` | Server Component `getAllComments()` direct |
| **POST** | Route Handler + Client `fetch` | Server Action `action={addCommentAction}` |
| **DELETE** | Route Handler + Client `fetch` + URL id | Server Action + form + hidden input `id` |

**Hidden input ka concept yahin seekha** — jab mutation mein value bhejni ho jo user se nahi aa rahi (jabki `text` form field se aati hai, `id` hum kaise bhejen?), toh hidden input.

## What It Is NOT

**Hidden input = "user data hide karna" nahi.** User browser ke DevTools se isko pehle bhi dekh sakta hai. Ye sirf "user ko UI mein na dikhao, par form ke saath bhejo" ke liye hai. Security ke liye server pe fir bhi validate karna padta hai.

**`.map()` ke andar form/button = "har render pe naya component" nahi.** React ko `<li key>` se track karta hai — isliye form+delete button dene pe bhi `key` zaroori hai taki list sync rahe.

**Server Action = "page refresh hota hai — isliye kharab" nahi.** 3.3.1 mein `useActionState` se refresh bina dikhaye optimistic UX milega. Abhi simple version hai.
