# Delete with Server Action + Hidden Input (3.3.3)

## Where We Left Off

In 3.3.2, we moved list data to a Server Component and added `revalidatePath`. Now adding a comment shows up immediately without a page refresh. The add flow is complete with toast feedback.

But one operation is still using the old Route Handler approach — **delete**. The delete button in `ShowComments.tsx` still calls `fetch("/api/comments/${id}", { method: "DELETE" })` followed by `router.refresh()`. Today we'll convert DELETE to a Server Action using a **form with a hidden input** — the pattern for when you need to send data the user doesn't type in.

## Current Code — How DELETE Works Now

Here's how delete works right now:

```tsx
// app/components/ShowComments.tsx — delete
const handleDelete = async (id: number) => {
  await fetch(`/api/comments/${id}`, { method: "DELETE" });
  router.refresh();
};
```

```tsx
// app/api/comments/[id]/route.ts — DELETE handler
export async function DELETE(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const deleted = deleteComment(Number(id));

  if (!deleted) {
    return NextResponse.json({ error: "Not found" }, { status: 404 });
  }

  return NextResponse.json({ message: "Deleted successfully" });
}
```

DELETE from a REST API — clean, but still uses `fetch()` on the client and needs a route handler file. Server Actions eliminate both.

## Step 1: Create deleteCommentAction — app/actions.ts

Let's create the new Server Action. It follows the exact same pattern as `addCommentAction`:

**File:** `app/actions.ts`

```tsx
// app/actions.ts — UPDATED (addCommentAction + deleteCommentAction)
"use server";

import { revalidatePath } from "next/cache";
import { addComment, deleteComment } from "@/lib/comments";

export type FormState = {
  success: boolean;
  message: string;
};

export async function addCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const text = formData.get("comment") as string;

  if (!text || !text.trim()) {
    return { success: false, message: "Comment cannot be empty!" };
  }

  addComment(text);
  revalidatePath("/");
  return { success: true, message: "Comment added!" };
}

// NEW: delete action — same pattern, just calls deleteComment()
export async function deleteCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const id = Number(formData.get("id"));

  const deleted = deleteComment(id);

  if (!deleted) {
    return { success: false, message: "Comment not found!" };
  }

  // Delete is a mutation too — revalidate for fresh list
  revalidatePath("/");

  return { success: true, message: "Comment deleted!" };
}
```

**Why this pattern?** It's the same structure as `addCommentAction`:
1. Extract data from `formData` (`formData.get("id")` for delete, `formData.get("comment")` for add)
2. Call the data layer function (`deleteComment` from `lib/comments.ts`)
3. `revalidatePath("/")` after mutation
4. Return `{ success, message }`

**Why `Number()`?** Hidden input values are always strings. `deleteComment()` expects a number. Convert with `Number()`.

**`deleteComment` — where did it come from?** Same function from 3.2 in `lib/comments.ts` — uses `splice()` to remove from the array and writes back to the file.

## Step 2: Wrap Delete Button in a Form

Now connect the delete button to the Server Action. The delete button becomes a **form** with a **hidden input** containing the comment ID.

**The key challenge:** Server Actions work through forms, not click handlers. A form needs to know which comment to delete — that information goes in a hidden input.

**File:** `app/components/ShowComments.tsx`

```tsx
// app/components/ShowComments.tsx — UPDATED (delete via Server Action)
"use client";

import Link from "next/link";
import { useEffect, useActionState } from "react";
import { toast } from "sonner";
import { deleteCommentAction, FormState } from "../actions";

const initialState: FormState = {
  success: false,
  message: "",
};

export default function ShowComments({
  comments,
}: {
  comments: { id: number; text: string }[];
}) {
  const [state, formAction, isPending] = useActionState(
    deleteCommentAction,
    initialState
  );

  // Toast feedback for delete
  useEffect(() => {
    if (state.message) {
      if (state.success) toast.success(state.message);
      else toast.error(state.message);
    }
  }, [state]);

  return (
    <div className="p-4 border rounded">
      <h2 className="text-xl font-bold mb-4">Comments</h2>
      <ul className="space-y-2">
        {comments.map((comment) => (
          <li key={comment.id} className="border-b pb-2 flex items-center justify-between">
            <Link href={`/comments/${comment.id}`} className="hover:underline">
              {comment.text}
            </Link>

            <form action={formAction}>
              <input type="hidden" name="id" value={comment.id} />
              <button
                type="submit"
                disabled={isPending}
                className="text-red-500 hover:text-red-700 text-sm disabled:opacity-50"
              >
                {isPending ? "Deleting..." : "Delete"}
              </button>
            </form>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

**Three things to notice:**

1. **`<form action={formAction}>`** — Same adapter from `useActionState` (3.3.1). Submit calls `deleteCommentAction(prevState, formData)`, result goes to `state`.

2. **`<input type="hidden" name="id" value={comment.id} />`** — The crucial part. `type="hidden"` means invisible to the user but included in form submission. `name="id"` matches `formData.get("id")` on the server. `value={comment.id}` passes which comment to delete.

3. **`disabled={isPending}` + toast** — Same pattern from 3.3.1. User gets feedback: "Deleting..." → "Comment deleted!" toast.

### Why Hidden Input?

Think of it like an order slip — the visible fields are what the user orders (the comment text), but hidden fields are like writing "Table 5" on the slip — the user doesn't choose it, but the kitchen (server) needs to know where to deliver.

The hidden input bridges "user clicked delete on comment #3" and "the server action needs to know it's comment #3."

## How It Works — Step by Step

```
1. User clicks "Delete" on comment #3
   ↓
2. Form submits → browser collects FormData
   - hidden input: name="id", value="3"
   ↓
3. useActionState's formAction calls deleteCommentAction(prevState, formData)
   ↓
4. Server action:
   - formData.get("id") → "3"
   - Number("3") → 3
   - deleteComment(3) → removes from JSON file
   - revalidatePath("/") → marks page as stale
   - returns { success: true, message: "Comment deleted!" }
   ↓
5. useActionState updates state → useEffect → toast.success("Comment deleted!")
   ↓
6. Page re-renders → getAllComments() → deleted comment is gone
```

No `fetch()`, no route handler, no `router.refresh()`. The form directly invokes the server function, and `revalidatePath` handles the refresh automatically.

## What It Is NOT

- **Hidden input is not "secret"** — anyone can see it in DevTools. It's hidden from the UI, not from technical inspection. Security validation still happens on the server.
- **Delete is not "instant"** — there's network latency. The `isPending` state manages user expectations.
- **Server Actions don't work without `use server`** — the directive is mandatory for the function to be callable as a form action.

## In Your Own Words

<details>
<summary>Question 1: Why do you need a hidden input for the delete Server Action?</summary>
<p><strong>Answer:</strong> Server Actions only work through forms, and forms send all their fields via FormData. The delete button needs to tell the server *which* comment to delete — but that ID isn't something the user types. A hidden input (`type="hidden"`) carries the ID in the FormData without showing it to the user, and `formData.get("id")` retrieves it on the server.</p>
</details>

<details>
<summary>Question 2: Why must you call `Number()` on `formData.get("id")`?</summary>
<p><strong>Answer:</strong> Form fields' values are always strings — `"3"` not `3`. `deleteComment()` expects a number to find the right comment. `Number("3")` converts the string to a number.</p>
</details>

<details>
<summary>Question 3: How does delete become more efficient with Server Actions?</summary>
<p><strong>Answer:</strong> Previously: route handler + `fetch()` + URL + `router.refresh()`. Now: `deleteCommentAction` + form + hidden input + `revalidatePath`. The route handler file is removed, `fetch()` is eliminated, and `revalidatePath` works automatically inside the action.</p>
</details>

<details>
<summary>Question 4: What role does `useActionState` play in the delete form?</summary>
<p><strong>Answer:</strong> It provides the `formAction` adapter (which handles the `prevState` + `formData` arguments) and `isPending` (for the loading state on the button). It also captures the action's return value into `state`, which the `useEffect` watches to trigger toast notifications.</p>
</details>
