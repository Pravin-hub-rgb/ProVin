Batch 2 mein humne data **padha** — Server Components se `fetch()` kiya, products dikhaye. Par sirf padha — data **likha** nahi.

Socho ek blog hai — post padh sakte ho, par comment nahi kar sakte. Review dekh sakte ho, par review likh nahi sakte. **Ye adhura hai.**

Ab seekhenge data **kaise change karte hain** — pehle Route Handlers se (REST API), phir Server Actions se (Next.js shortcut).

---

## SOCH: Ab Tak Kya Karte The?

Ab tak hum sirf **GET** karte the — data padhte the. Server se data aata tha, hum dekhte the. **One-way communication** tha.

```
Client  ——GET——>  Server
Client  <——data——  Server
```

Browser mein URL type kiya → server ne page bheja → humne dekha. Bas. Humne server ko kuch **bheja** nahi.

**Ab kya badlega?**

Ab hum server ko data **bhejenge** bhi:
- Comment add karenge → server ko bhejenge
- Review likhenge → server ko bhejenge
- Kuch update karenge → server ko bhejenge
- Kuch delete karenge → server ko bhejenge

```
Client  ——GET——>     Server   (data mangna)
Client  <——data——    Server   (data aaya)
Client  ——POST——>    Server   (data bhejna)
Client  <——confirm—— Server   (confirm mila)
```

Ye **two-way communication** ho gayi. Client aur server dono ek doosre se baat kar rahe hain.

## Pehle Samjho: HTTP Methods Kya Hote Hain?

Har request ke saath ek **method** hota hai — ye batata hai ki client kya karna chahta hai.

| Method | Matlab | Example |
|--------|--------|---------|
| **GET** | Data padho | Blog post dekho, products list karo |
| **POST** | Naya data banao | Comment add karo, review likho |
| **PUT** | Data update karo | Review edit karo, profile update karo |
| **DELETE** | Data hatao | Comment delete karo, post hatao |

**Ab tak hum sirf GET use kar rahe the.** Browser mein URL type karo → GET request jaati hai → server data bhejta hai.

Ab POST, PUT, DELETE bhi seekhenge.

## Fetch Kya Hai?

`fetch()` ek **built-in JavaScript function** hai — browser mein pehle se hota hai. Ye client se server ko request bhejne ke liye use hota hai.

```tsx
// GET request — data mangna
const res = await fetch("https://api.example.com/products");
const products = await res.json();
```

**Kya ho raha hai?**
1. `fetch("https://api.example.com/products")` — server ko GET request bheji
2. Server ne data bheja (JSON format mein)
3. `.json()` se JSON → JavaScript object convert kiya
4. `products` mein data aa gaya

**Ye tum ab tak kar rahe the** — Server Components mein `fetch()` se data late the.

## Fetch Se POST Kaise Karte Hain?

Ab tak sirf GET kar rahe the. Ab POST kaise karenge — `fetch()` mein options dena padega:

```tsx
// POST request — data bhejna
const res = await fetch("/api/comments", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "Naya comment!" }),
});

const newComment = await res.json();
```

**Breakdown — Har Line Kya Karti Hai:**

**Line 1: `method: "POST"`**

Ab tak ye nahi tha — kyunki default GET hota hai. Ab explicitly bol rahe hain ki "mujhe POST karna hai".

**Line 2: `headers: { "Content-Type": "application/json" }`**

Ye batata hai ki hum **JSON** bhej rahe hain. Jaise letter pe address hota hai, waise request pe hota hai ki data kis format mein hai.

**Line 3: `body: JSON.stringify({ text: "Naya comment!" })`**

Ye hai actual data. `JSON.stringify()` se JavaScript object → JSON string convert hota hai.

## Kyun Fetch? Axios Kyun Nahi?

Dono ka kaam same hai — server se request bhejna. Par fark hai:

### Fetch (Built-in)

```tsx
// Fetch — browser mein pehle se hai
const res = await fetch("/api/comments", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "Hello" }),
});
const data = await res.json();  // Manual conversion
```

**Fayda:**
- Kuch install nahi karna — browser mein pehle se hai
- Zero dependencies — koi extra package nahi
- Standard hai — har jagah kaam karta hai

**Nuksaan:**
- `.json()` manual karna padta hai
- Error handling thoda verbose hai
- Headers har baar dena padta hai

### Axios (Third-party Library)

```tsx
// Axios — install karna padega
import axios from "axios";

const { data } = await axios.post("/api/comments", {
  text: "Hello",
});
// data mein directly object aa gaya — .json() ki zaroorat nahi
```

**Fayda:**
- Automatic JSON conversion — `.json()` nahi chahiye
- Error handling better hai
- Headers centrally set kar sakte ho

**Nuksaan:**
- Install karna padega (`npm install axios`)
- Extra dependency hai — bundle size badhta hai
- Ab axios ke bina kaam nahi chalega

### Kab Kya Use Karein?

| Situation | Use Karo |
|-----------|----------|
| Simple project, kam dependencies | **Fetch** |
| Complex project, bahut saari API calls | **Axios** |
| Third-party APIs call karne hain | **Axios** (interceptors useful hain) |
| Production app, optimize karna hai | **Fetch** (zero dependency) |

**Abhi ke liye:** Fetch se seekho — fundamental hai, har jagah kaam aayega. Baad mein axios bhi use kar lenge.

## Ab Route Handlers Banate Hain

Ab tak samjha ki fetch kya hai, method kya hai. Ab Next.js mein kaise implement karenge?

Next.js mein API endpoints banane ka tareeka hai - `route.ts` file. Jaise `page.tsx` se page banta hai, waise `route.ts` se API route banta hai.

**Pattern:**
```
app/
  api/
    comments/
      route.ts    <- Ye file API endpoint banati hai
```

`app/api/comments/route.ts` ka matlab hai - `/api/comments` ek API endpoint hai.

## Pehle Samjho: NextResponse Kya Hai?

Jab bhi server client ko kuch bhejta hai - page, JSON data, error - usko **response** kehte hain. Next.js mein ye response bhejne ke liye `NextResponse` use hota hai.

### NextResponse Kyun Chahiye?

JavaScript mein already ek `Response` class hai (Web API). Par Next.js ne usko **extend** kiya hai - kuch extra features diye hain jo Next.js ke kaam aate hain.

```tsx
// Plain JavaScript Response
return Response.json({ message: "Hello" });

// Next.js extended Response
return NextResponse.json({ message: "Hello" });
```

Dono kaam karte hain. Par `NextResponse` mein kuch extras hain:
- **`.json()` method** � JSON data bhejne ke liye (sabse commonly used)
- **`.redirect()` method** � user ko doosre page pe bhejne ke liye
- **`.cookies()` method** � cookies set karne ke liye

### NextResponse Kaise Import Karte Hain?

```tsx
import { NextResponse } from "next/server";
```

Ye `next/server` module se aata hai. **Har Route Handler mein ye import zaroori hai** � bina iske response bhej nahi paoge.

### `.json()` Method Kya Hai?

Jab server JSON data bhejta hai, usko properly format karna padta hai. `.json()` method ye kaam karta hai:

```tsx
// Ye automatically:
// 1. JavaScript object ko JSON string mein convert karta hai
// 2. Content-Type header "application/json" set karta hai
// 3. Proper HTTP response bhejta hai

return NextResponse.json({ name: "Vin", age: 25 });
// Client ko milega: {"name":"Vin","age":25}
```

**Bina `.json()` ke kya hota?**

```tsx
// Manually karna padega:
return new Response(JSON.stringify({ name: "Vin" }), {
  headers: { "Content-Type": "application/json" },
});
```

Dekha? `.json()` ne 3 kaam kiye ek line mein. Isliye `NextResponse.json()` use karte hain.

## CODE: Pehla Route Handler

Ab theory samjhi - ab code samajhna aasaan hoga:

```tsx
// app/api/comments/route.ts
import { NextResponse } from "next/server";

// GET request handle karo
export async function GET() {
  const comments = [
    { id: 1, text: "Bahut achha hai!" },
    { id: 2, text: "Mujhe pasand aaya." },
  ];

  return NextResponse.json(comments);
}
```

**Line by line:**

1. `import { NextResponse } from "next/server"` � Response bhejne ke liye chahiye

2. `export async function GET()` � Ye **named export** hai. Naam **GET** hona chahiye � kyunki Next.js HTTP method ke hisaab se function call karta hai. Client ne GET request bheji ? ye GET function chalega.

3. `return NextResponse.json(comments)` � Comments array ko JSON format mein client ko bhej do

**Kyun named exports?** Kyunki Next.js ko pata hona chahiye ki GET request ke liye kaun sa function call karna hai. Agar naam galat likha (jaise `Get` ya `GetData`), toh Next.js samajh nahi payega.

Ab browser mein `/api/comments` kholo - JSON dikhega!

**Test karo:**
```
Browser mein: http://localhost:3000/api/comments
Response: [{"id":1,"text":"Bahut achha hai!"}, {"id":2,"text":"Mujhe pasand aaya."}]
```

## Ab POST Bhi Banate Hain

Comments padhna ho (GET) aur likhna ho (POST) - dono same file mein:

```tsx
// app/api/comments/route.ts
import { NextResponse } from "next/server";

// In-memory storage (abhi database nahi hai)
let comments = [
  { id: 1, text: "Bahut achha hai!" },
  { id: 2, text: "Mujhe pasand aaya." },
];

// GET - saare comments lao
export async function GET() {
  return NextResponse.json(comments);
}

// POST - naya comment add karo
export async function POST(request: Request) {
  const body = await request.json();
  const newComment = {
    id: comments.length + 1,
    text: body.text,
  };
  comments.push(newComment);
  return NextResponse.json(newComment, { status: 201 });
}
```
### Request Object Kya Hai?

**Pehle sawaal:** `request: Request` likha hai - par `Request` import kahan hai? File mein kahin nahi hai!

**Jawab:** `Request` ek **global Web API** hai - import ki zaroorat nahi hai. Jaise `console`, `setTimeout`, `fetch` - ye sab pehle se available hain. Waise hi `Request` bhi browser aur Node.js dono mein pehle se hota hai.

```tsx
// Import mat karo - global hai
import { NextResponse } from "next/server";  // Import zaroori hai

export async function POST(request: Request) {  // Request import nahi hota
  // request.json() seedha kaam karega
}
```

**Kaise pata chalta hai ki global hai?**

Browser DevTools mein console mein try karo - `typeof Request` dega `"function"` - already available hai.

**Ye Next.js ka nahi hai** - ye JavaScript standard (Web API) hai. Next.js sirf tumhe `request` parameter pass karta hai Route Handler mein.

### Request Mein Kya Hota Hai?

Jab client kuch bhejta hai server ko (POST, PUT, DELETE), toh wo data **Request object** mein aata hai. Ye Web API standard hai - Next.js se pehle bhi exist karta tha.
```tsx
export async function POST(request: Request) {
  // request mein ye sab hota hai:
  // request.method  ? "POST"
  // request.url     ? "http://localhost:3000/api/comments"
  // request.headers ? { "content-type": "application/json", ... }
  // request.json()  ? body parse karo
}
```

**Request ke important methods:**

| Method | Kya karta hai |
|--------|---------------|
| `request.json()` | Body ko JavaScript object mein convert karta hai |
| `request.text()` | Body ko plain string mein convert karta hai |
| `request.headers` | Request ke headers dekho |
| `request.url` | Request ka URL dekho |

**Sabse zyada use hota hai `request.json()`** � kyunki client usually JSON data bhejta hai.

### POST Ka Breakdown

```tsx
export async function POST(request: Request) {
  const body = await request.json();     // 1
  const newComment = {
    id: comments.length + 1,             // 2
    text: body.text,                     // 3
  };
  comments.push(newComment);             // 4
  return NextResponse.json(newComment, { status: 201 });  // 5
}
```

1. **`await request.json()`** � Client ne jo JSON bheja, usko JavaScript object mein convert karo. `await` isliye kyunki body padhne mein time lagta hai (stream hai).

2. **`id: comments.length + 1`** � Simple ID generation. Abhi database nahi hai, isliye array ki length se ID bana rahe hain. (Production mein database auto-increment ya UUID use karega.)

3. **`body.text`** � Client ne jo text bheja wo. `body` mein wo sab hota hai jo client ne JSON mein likha.

4. **`comments.push(newComment)`** � Naye comment ko array mein add karo.

5. **`{ status: 201 }`** � HTTP status code. 201 matlab "Created" � naya resource ban gaya. Default 200 hota hai, par POST ke liye 201 standard hai.

### Status Codes Kya Hote Hain?

Har response ke saath ek **status code** jaata hai � ye batata hai ki request safal hui ya nahi.

| Code | Matlab | Kab use hota hai |
|------|--------|------------------|
| **200** | OK | Request safal hui (GET ke liye) |
| **201** | Created | Naya resource ban gaya (POST ke liye) |
| **400** | Bad Request | Client ne galat data bheja |
| **404** | Not Found | Resource nahi mila |
| **500** | Server Error | Server pe kuch gadbad hui |

**Client ko status code kaise pata chalta hai?**

```tsx
// Client side
const res = await fetch("/api/comments", { method: "POST", ... });
console.log(res.status);  // 201 (ya 400, 500 etc.)
```

## Client Se Kaise Call Karein?

Ab ye API ban gayi. Client se kaise call karenge? **`fetch()` se - exactly wahi jo upar seekha:**

```tsx
// Client Component
"use client";

import { useState } from "react";

export default function CommentForm() {
  const [text, setText] = useState("");

  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();

    const res = await fetch("/api/comments", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ text }),
    });

    const newComment = await res.json();
    console.log("Comment added:", newComment);
    setText("");
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={text}
        onChange={(e) => setText(e.target.value)}
        placeholder="Apna comment likho..."
      />
      <button type="submit">Submit</button>
    </form>
  );
}
```

**Kya ho raha hai?**
1. User form mein text likhta hai
2. Form submit hota hai ? `handleSubmit` call hota hai
3. `fetch()` se POST request jaati hai `/api/comments` pe
4. Server pe Route Handler handle karta hai ? naya comment banta hai
5. Response aata hai ? `newComment` mein data aa jaata hai

**Dekho pattern:** Form submit hota hai -> `fetch()` se POST call jaati hai -> server pe Route Handler handle karta hai -> naya comment ban jaata hai.

## Dynamic Routes Bhi Ban Sakte Hain

Ek specific comment padhna ho (`/api/comments/1`):

```tsx
// app/api/comments/[id]/route.ts
import { NextResponse } from "next/server";

let comments = [
  { id: 1, text: "Bahut achha hai!" },
  { id: 2, text: "Mujhe pasand aaya." },
];

// GET /api/comments/1
export async function GET(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const comment = comments.find((c) => c.id === Number(id));

  if (!comment) {
    return NextResponse.json({ error: "Comment nahi mila" }, { status: 404 });
  }

  return NextResponse.json(comment);
}
```

### Params Pattern Samjho

**Pehle samjho `{ params }` kya hai:**

Route Handler ko **do arguments** milte hain:
1. `request` � client se aaya request object
2. `{ params }` � dynamic route ki values

```tsx
// app/api/comments/[id]/route.ts
export async function GET(request, { params }) {
  // Agar URL: /api/comments/1
  // params = { id: "1" }

  // Agar URL: /api/comments/42
  // params = { id: "42" }
}
```

**`[id]`** ek **dynamic segment** hai � ye URL ka wo hissa hai jo badal sakta hai. Jaise `/api/comments/1` mein `1` hai, `/api/comments/42` mein `42`.

### Next.js 15: Params Ab Promise Hai

**Important change:** Next.js 15 mein `params` ek **Promise** ban gaya hai. Isliye `await` karna padega:

```tsx
// Next.js 14 (purana pattern � sync)
export async function GET(request, { params }) {
  const comment = comments.find((c) => c.id === Number(params.id));  // Direct use
}

// Next.js 15 (naya pattern � async)
export async function GET(request, { params }) {
  const { id } = await params;  // Pehle await karo
  const comment = comments.find((c) => c.id === Number(id));
}
```

**Kyun Promise?** Kyunki Next.js ab params ko server se laane ke liye async operations kar sakta hai (jaise database se data lana). Isliye ab wait karna padta hai.

### `comments.find()` Kya Hai?

Ye JavaScript ka array method hai � array mein se pehla matching element dhoondta hai:

```tsx
const comments = [
  { id: 1, text: "Bahut achha hai!" },
  { id: 2, text: "Mujhe pasand aaya." },
];

const comment = comments.find((c) => c.id === 1);
// result: { id: 1, text: "Bahut achha hai!" }

const notFound = comments.find((c) => c.id === 99);
// result: undefined (nahi mila)
```

**`.find()` vs `.filter()`:**
- `.find()` � pehla match dhoondta hai (ek object milta hai)
- `.filter()` � saare matches dhoondta hai (array milta hai)

## Nutshell

Route Handlers se Next.js mein API endpoints bante hain - `app/api/[something]/route.ts` file se. Har HTTP method ka apna function hota hai (`GET`, `POST`, `PUT`, `DELETE`). Server se `NextResponse.json()` se response bhejte hain - ye automatic JSON formatting aur status codes set karta hai. Client se `fetch()` se call hota hai - built-in JavaScript function, kuch install nahi karna. Ye **fundamental** hai - REST API har jagah kaam aata hai, sirf Next.js mein nahi.

---

## Common Mistakes

- **Function ka naam galat likhna** - `GET` likhna hai toh `export async function GET()` hona chahiye, `Get` ya `GetData` nahi chalega

- **`NextResponse` import na karna** - Bina import ke `NextResponse.json()` use karoge toh error aayega

- **`request.json()` ke baad dobara use karna** - Body ek baar hi padh sakte ho (stream consume hota hai)

- **Status code na dena** - POST ke baad `201` dena chahiye, error pe `404` ya `500`

- **Server-side code client mein daal dena** - `route.ts` sirf server pe run hota hai, ismein `localStorage` ya browser APIs nahi chalengi

- **`method` na likhna** - `fetch()` mein agar `method` nahi likhoge toh GET ho jaayega, POST nahi hoga

## What It Is NOT

**Route Handler = "sirf Next.js" nahi.** Route Handler Next.js ka implementation hai, par REST API concept universal hai. Ye seekhna isliye zaroori hai kyunki third-party apps, mobile apps, microservices - sab REST use karte hain.

**Route Handler = "Server Action se better" nahi.** Dono alag alag jagah kaam aate hain. Route Handler fundamental hai, Server Actions shortcut hai. Kab kya use karna hai - 3.4 mein cover hoga.
