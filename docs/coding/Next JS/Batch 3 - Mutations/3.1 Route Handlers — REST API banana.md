Batch 2 mein humne data **padha** — Server Components se `fetch()` kiya, products dikhaye. Par sirf padha — data **likha** nahi.

Socho ek blog hai — post padh sakte ho, par comment nahi kar sakte. Review dekh sakte ho, par review likh nahi sakte. **Ye adhura hai.**

Ab seekhenge data **kaise change karte hain** — pehle Route Handlers se (REST API), phir Server Actions se (Next.js shortcut).

---

## SOCH: Ab Tak Kya Karte The?

Ab tak hum sirf **GET** karte the — data padhte the. Server se data aata tha, hum dekhte the. **One-way communication** tha.

```
Client  --GET-->  Server
Client  <--data--  Server
```

Browser mein URL type kiya → server ne page bheja → humne dekha. Bas. Humne server ko kuch **bheja** nahi.

**Ab kya badlega?**

Ab hum server ko data **bhejenge** bhi — comment add karenge, review likhenge.

```
Client  --GET-->     Server   (data mangna)
Client  <--data--    Server   (data aaya)
Client  --POST-->    Server   (data bhejna)
Client  <--confirm-- Server   (confirm mila)
```

Ye **two-way communication** ho gayi. Client aur server dono ek doosre se baat kar rahe hain.

---

## HTTP Methods Kya Hote Hain?

Har request ke saath ek **method** hota hai — ye batata hai ki client kya karna chahta hai.

| Method | Matlab | Example |
|--------|--------|---------|
| **GET** | Data padho | Blog post dekho, products list karo |
| **POST** | Naya data banao | Comment add karo, review likho |

Ab tak hum sirf GET use kar rahe the. Ab POST bhi seekhenge. PUT aur DELETE baad mein 3.2 mein.

---

## Fetch Kya Hai?

`fetch()` ek **built-in JavaScript function** hai — browser mein pehle se hota hai. Ye client se server ko request bhejne ke liye use hota hai.

```tsx
const res = await fetch("https://api.example.com/products");
const products = await res.json();
```

Kya ho raha hai? Pehle `fetch()` se server ko GET request jaati hai, phir `.json()` se JSON → JavaScript object convert hota hai. **Ye tum ab tak kar rahe the** — Server Components mein `fetch()` se data late the.

---

## Kyun Fetch? Axios Kyun Nahi?

Dono ka kaam same hai — server se request bhejna. Par fark hai:

**Fetch (Built-in):** Kuch install nahi karna, browser mein pehle se hai. Par `.json()` manual karna padta hai, headers har baar dena padta hai.

**Axios (Third-party):** Automatic JSON conversion hai, par install karna padega. Extra dependency hai.

Simple project hai toh **Fetch** — zero dependency, standard hai. Complex project hai toh **Axios**. Abhi ke liye Fetch se seekho.

## Pehle Data Centralize Karo

Ek problem hai — agar data (comments) alag-alag route files mein hardcode karo, toh ek jagah change karne se doosri jagah nahi badlega. Jaise abhi `api/comments/route.ts` aur `api/comments/[id]/route.ts` dono mein alag-alag `let comments` hoga — POST se naya comment add ho toh `[id]` route ko nahi milega.

Isliye pehle ek **centralized data file** banao.

### Data Kahan Se Aayega?

Ab tak humne data memory mein rakha — `let comments = [...]`. Par ye temporary hai — **server restart = data gaya.**

Real projects mein data **file** ya **database** mein hota hai. Abhi ke liye **JSON file** use karenge — same concept, sirf storage alag hai.

Iske liye 2 Node.js modules chahiye:
- **`fs`** — File System — files padhna aur likhna
- **`path`** — File paths banana (safe tareeke se)

```tsx
// lib/comments.ts
import { readFileSync } from "fs";  // writeFileSync POST mein addComment ke saath aayega
import path from "path";

// JSON file ka path — process.cwd() = project root
const filePath = path.join(process.cwd(), "lib", "comments.json");

export function getAllComments() {
  const data = readFileSync(filePath, "utf-8");  // File padho
  return JSON.parse(data);                        // String → Object convert
}
```

### `filePath` — Path Kaise Banta Hai?

`path.join(process.cwd(), "lib", "comments.json")` — 3 arguments, 3 kaam. Tod ke dekho:

```tsx
path.join(
  process.cwd(),   // 1. Root — project jahan hai
  "lib",           // 2. Folder — root ke andar lib/
  "comments.json"  // 3. File — lib/ ke andar ye file
);
```

**Argument by argument:**

1. **`process.cwd()`** — project root ka full path. `cwd` = **Current Working Directory** — jis folder se `npm run dev` chala. Maan lo tumhara project `C:\Users\dev\comments-app` mein hai, toh ye wahi path degi.
2. **`"lib"`** — root ke andar `lib` folder.
3. **`"comments.json"`** — `lib` folder ke andar ye file.

**Result — `path.join` teeno ko jod ke ek full path banata hai:**

```
C:\Users\dev\comments-app\lib\comments.json
```

**`path.join` kyun — seedha `+` se kyun nahi?**

```tsx
const filePath = process.cwd() + "/lib/comments.json";  // galat ho sakta hai
```

Problem — **OS ke hisaab se path ka symbol alag hota hai:**
- **Windows:** `C:\Users\dev\comments-app\lib\comments.json` — backslash `\`
- **Mac / Linux:** `/home/dev/comments-app/lib/comments.json` — forward slash `/`

Agar tum `+` se seedha `/` likhoge, toh Windows pe kaam nahi karega. `path.join()` khud decide karta hai ki kaunsa symbol chahiye — **tumhe sirf cheezein deni hain (root, folder, file), jodna `path.join` ka kaam hai.**

**Socho aise:** raste batate waqt hum kehte hain "gali se seedha, phir left, phir school ke saamne rukna" — `path.join` usi tarah har step follow karta hai aur poora pata banata hai. Tum sirf destinations batate ho (`process.cwd()`, `"lib"`, `"comments.json"`), baaki wo manage karta hai.

Abhi sirf `getAllComments()` banaya — GET route ko chahiye. `addComment()` abhi nahi banate — POST route banayenge tab banayenge. **Jo chahiye tab banate hain.**

**Naye Concepts:**
- `readFileSync(filePath, "utf-8")` — File se data padho (synchronous = wait karo jab tak padh na jaaye)
- `process.cwd()` — Current working directory (jahan se `npm run dev` chala)
- `path.join()` — OS ke hisaab se safe path banata hai (Windows: `\`, Mac: `/`)

`writeFileSync` file mein likhne wala function hai — wo abhi nahi, POST section mein `addComment()` ke saath seekhenge.

Aur ek JSON file bhi banao — `lib/comments.json`:

```json
[
  { "id": 1, "text": "Bahut achha hai!" },
  { "id": 2, "text": "Mujhe pasand aaya." }
]
```

**Kyun `lib/` folder?** Next.js mein `lib/` ek convention hai — reusable logic, data, utilities rakhne ke liye. `app/` mein pages aur routes hain, `lib/` mein baaki sab.

**`@/` prefix se import hota hai** — `@/lib/comments` ka matlab hai project root se `lib/comments.ts`. Ye Next.js ka auto-alias hai — `tsconfig.json` mein configured hota hai.

## Pehla Route Handler — GET

`export async function GET()` — Naam **GET** hona chahiye, kyunki Next.js HTTP method ke hisaab se function call karta hai. Client ne GET request bheji → ye GET function chalega.

### "GET mein toh `await` hai nahi — phir `async` kyun?"

Tune notice kiya hoga — GET function mein koi `await` nahi hai. `getAllComments()` seedha call kiya, kuch wait nahi kiya. Phir bhi `async` kyun likha?

**Kyun:** Next.js ke Route Handlers **hamesha** async hone chahiye. Ye Next.js ka rule hai — chahe tum `await` use karo ya nahi.

**Kyun hai ye rule?** Kyunki Next.js ko pata nahi ki tum baad mein `await` add karoge ya nahi. Abhi GET simple hai — par baad mein database se data lana ho, `await` chahiye hoga. Agar function pehle se async nahi hoga, toh Next.js ko error aayega jab tum `await` add karoge. Isliye safe side pe — hamesha `async` likho.

**Simple:** Route Handler = hamesha `async function`. Chahe `await` ho ya na ho.

**Notice kiya?** GET mein koi data nahi bhejna — sirf `getAllComments()` call kiya aur JSON bhej diya. Simple hai — sirf padhna hai.

### "Ye `fetchComments` kyun alag se banaya?"

Tune socha hoga — **"Seedha `useEffect` ko async kyun nahi kar sakte?"**

```tsx
// YE KAAM NAHI KAREGA ❌
useEffect(async () => {
  const res = await fetch("/api/comments");
  const comments = await res.json();
  setAllComments(comments);
}, []);
```

**Kyun nahi chalega?** Kyunki `useEffect` ka callback **return kuch nahi karta** — wo **void** hota hai. Par `async` function hamesha ek **Promise** return karta hai. React ko lagta hai — "tune kuch return kiya, shayad cleanup function hai!" — par Promise milta hai toh error aata hai.

**Simple language mein:** React bolta hai — "Main callback chalata hoon, par tu kuch return mat kar." `async` function automatically Promise return karta hai — React confuse ho jaata hai.

### "Toh `export default async function` kyun nahi?"

```tsx
// YE BHI KAAM NAHI KAREGA ❌
"use client";
export default async function ShowComments() {
  const res = await fetch("/api/comments");
  // ...
}
```

**Kyun nahi?** Kyunki React components ka signature **fixed hai** — wo ek function hona chahiye jo JSX return kare. `async` function Promise return karta hai, JSX nahi. React bolega — "Maine JSX expect kiya, par mujhe Promise mila."

**Server Components mein kyun chalta hai?** Kyunki wahan React khud `await` karta hai — component ko render karne se pehle Promise resolve karta hai. Client Components mein ye React nahi karta — browser ko hot reload milta hai.

### Solution: Inner Async Function

Isliye pattern ye hai — `useEffect` ke andar ek **alag async function** banao aur usse call karo:

```tsx
useEffect(() => {
  const fetchComments = async () => {    // ← Alag function
    const res = await fetch("/api/comments");
    const comments = await res.json();
    setAllComments(comments);
  };
  fetchComments();                        // ← Call karo
}, []);
```

**Kyun kaam karta hai?** Kyunki `useEffect` ka callback kuch **return nahi** kar raha — bas `fetchComments()` call kar raha hai. `fetchComments` async hai, par `useEffect` ka callback nahi hai. React khush — "kuch return nahi hua, theek hai!"

**Notice kiya?** Ye wahi concept hai jo 3.3 mein Server Actions ke saath bhi milega — React ke saath kaam karte waqt **function signature matters** karta hai.

## Ab POST Bhi Seekhte Hain

GET toh samajh aa gaya — comments dikh rahe hain. Par abhi sirf dekh sakte ho — **likh nahi sakte.** Comment add kaise karenge?

Pehle samjho **POST kaise kaam karta hai** — `fetch()` mein options dena padega:

```tsx
const res = await fetch("/api/comments", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "Naya comment!" }),
});

const newComment = await res.json();
```

Chal samajhte hain har line:

**`method: "POST"`** — Ab tak ye nahi tha, kyunki default GET hota hai. Ab explicitly bol rahe hain ki "mujhe POST karna hai".

**`headers: { "Content-Type": "application/json" }`** — Ye batata hai ki hum JSON bhej rahe hain. Jaise letter pe address hota hai, waise request pe hota hai ki data kis format mein hai.

**`body: JSON.stringify({ text: "Naya comment!" })`** — Ye hai actual data. `JSON.stringify()` se JavaScript object → JSON string convert hota hai.

Notice kiya? GET mein sirf URL tha. POST mein **teen cheezein extra** hain — method, headers, body. Kyunki ab hum sirf data nahi padh rahe, bhej bhi rahe hain.

### `addComment()` — Ab Ye Function Banao

POST route banane se pehle `addComment()` banao — `lib/comments.ts` mein `getAllComments()` ke saath. Ye `comments.json` se padhta hai, naya comment add karta hai, aur **wapas file mein likhta hai**:

```tsx
// lib/comments.ts — getAllComments() ke neeche add karo
import { readFileSync, writeFileSync } from "fs";  // ← writeFileSync ab import karo

export function addComment(text: string) {
  if (!text || !text.trim()) return null;         // ← Empty check
  const comments = getAllComments();              // 1. file se padho
  const newComment = { id: comments.length + 1, text: text.trim() };
  comments.push(newComment);                      // 2. add
  writeFileSync(filePath, JSON.stringify(comments, null, 2));  // 3. file mein likho
  return newComment;
}
```

**Naye concepts (data-centralize mein inhe POST ke saath batane ko bola tha):**
- `writeFileSync(filePath, data)` — File mein data likho (getAllComments sirf padhta tha, ye likhta hai)
- `JSON.stringify(comments, null, 2)` — Object → JSON string, `2` se pretty print (indentation)

**Line by line** — `addComment("Bahut badhiya!")`:
1. `getAllComments()` — file se pura array padho
2. `comments.push(...)` — naya comment array mein daalo (`id: comments.length + 1` se auto ID)
3. `writeFileSync(...)` — pura array wapas file mein likho — warna server restart pe data khoya jaata

**Notice kiya?** `getAllComments()` sirf padhta tha. `addComment()` padhta hai + badalta hai + wapas likhta hai — isi liye ise `writeFileSync` chahiye. POST route bas isko call karegi.

### Route Handler — POST

Ab route handler mein POST function add karo:

```tsx
// app/api/comments/route.ts
import { NextResponse } from "next/server";
import { getAllComments, addComment } from "@/lib/comments";

// GET - saare comments lao
export async function GET() {
  return NextResponse.json(getAllComments());
}

// POST - naya comment add karo
export async function POST(request: Request) {
  const body = await request.json();

  // Validation — empty text allow mat karo
  if (!body.text || !body.text.trim()) {
    return NextResponse.json(
      { error: "Comment khali nahi ho sakta" },
      { status: 400 }
    );
  }

  const newComment = addComment(body.text);
  return NextResponse.json(newComment, { status: 201 });
}
```

Notice kiya? GET mein sirf `return` tha. POST mein `request`, `body`, `addComment`, `status: 201` — kyunki data aa raha hai aur naya resource ban raha hai.

### "Request" import kahan hai?

Tune notice kiya hoga — `request: Request` likha hai par import kahan hai? File mein kahin nahi!

`Request` ek **global Web API** hai — import ki zaroorat nahi. Jaise `console`, `setTimeout`, `fetch` — ye sab pehle se available hain. Waise hi `Request` bhi browser aur Node.js dono mein pehle se hota hai.

Maine bhi pehli baar ye dekh ke socha tha "import kahan hai?" — par yaad rakh, ye global hai.

### POST ke andar kya ho raha hai?

```tsx
export async function POST(request: Request) {
  const body = await request.json();     // 1
  const newComment = addComment(body.text);  // 2
  return NextResponse.json(newComment, { status: 201 });  // 3
}
```

`await request.json()` — client ne jo JSON bheja, usko object mein convert kar raha hai. `await` isliye kyunki body stream hai — thoda time lagta hai.

`addComment(body.text)` — `lib/comments.ts` ka function. Ye naya comment banata hai aur `comments` array mein add karta hai. ID automatically generate hoti hai.

`{ status: 201 }` — HTTP status code. 201 matlab "Created" — naya resource ban gaya.

### Client-Se-Server Mapping — Kahan Se Kahan Jaata Hai?

Ab confusion ho sakta hai — **client pe hum 3 cheezein bhej rahe hain (method, headers, body), par server pe sirf `request` parameter milta hai. Ye kaise connected hain?**

Pehle client ka code dekho:

```tsx
// CLIENT — CommentForm.tsx
const res = await fetch("/api/comments", {
  method: "POST",                          // ← 1. Kaunsa function chalega
  headers: { "Content-Type": "..." },      // ← 2. Data kis format mein hai
  body: JSON.stringify({ text: "..." }),   // ← 3. Actual data
});
```

Ab server ka code dekho:

```tsx
// SERVER — route.ts
export async function POST(request: Request) {
  const body = await request.json();
  // ...
}
```

**Mapping:**

```
Client                              Server
─────────────────────────────────────────────────────
method: "POST"          →    export async function POST()
                                    (Next.js method dekhta hai,
                                     usi naam ka function chalata hai)

headers: { "Content-Type": "application/json" }
                          →    Request object mein set hota hai
                                    (Next.js khud handle karta hai)

body: JSON.stringify({ text: "..." })
                          →    request.json() se nikalta hai
                                    (JSON string → JavaScript object)
```

**Step-by-Step Flow:**

```
1. fetch("/api/comments", { method: "POST", ... })
        ↓
   Next.js URL dekhta hai → "/api/comments"
        ↓
   method dekhta hai → "POST"
        ↓
   route.ts mein jaata hai → export async function POST() chalega

2. body: JSON.stringify({ text: "..." })
        ↓
   Ye data request ke andar pack hota hai
        ↓
   request object mein jaata hai

3. request.json()
        ↓
   JSON string → JavaScript object convert hota hai
        ↓
   body = { text: "Naya comment!" }
        ↓
   body.text = "Naya comment!"
```

### "request.body" kyun nahi?

`request.body` bhi hota hai — par wo ek **ReadableStream** hai (raw data). Usse directly padh nahi sakte — pehle parse karna padta hai.

`request.json()` ek **shortcut** hai — ye `request.body` ko automatically read karta hai, JSON parse karta hai, aur object return karta hai.

```tsx
// Ye dono same hain:
const body = await request.json();                    // ← Shortcut

const rawStream = request.body;                       // ← Raw stream
const text = await new Response(rawStream).text();    // ← Manual read
const body = JSON.parse(text);                        // ← Manual parse
```

Isliye `request.json()` use karte hain — simple hai. **3.2 mein `request.text()` bhi milega — same pattern, JSON ki jagah plain text.**

### Server data wapas kyun bhejta hai?

Comment save ho gaya — par server kyun wapas bhej raha hai? Main bhi pehle sochta tha "bas save ho gaya, khatam". Par 3 reasons hain:

**Server-generated fields** — Client sirf `text` bhejta hai. Par `id` server generate karta hai. Agar server wapas na bheje, toh client ko pata kaise chalega ki kaunsa ID mila?

**Confirmation** — Server wapas bhej ke confirm karta hai — "haan, data save ho gaya."

**Client state update** — Client ko list mein naya comment add karna hai. Server wapas bhej de toh seedha list mein add kar sakte ho — dobara GET request nahi padegi.

```tsx
      >

      </button>

  );
}
```

Notice kiya? Ye **sirf POST** hai — user type karta hai, submit karta hai, `fetch()` se POST request jaati hai. Bilkul wahi jo upar seekha — `method: "POST"`, `headers`, `body`, `JSON.stringify`.

Ab isko `page.tsx` mein `ShowComments` ke saath render karo (`<CommentForm />` + `<ShowComments />` dono). Try karo — form mein kuch likho, submit karo. Console mein naya comment dikhega. **Par problem hai** — naya comment page pe list mein **nahi dikh raha** — kyunki POST ke baad list refresh nahi hui. Iska asli fix aage (3.3.2 mein) aayega — abhi ke liye bas problem ko clearly dekh lo. Step 2 mein dono components jodenge, phir samjhenge ki ye problem kyun hai.

### `router.refresh()` — Kyun Abhi Kaam Nahi Karega

Tumne socha hoga — "chalo `router.refresh()` se list update kar lete hain." Sochna galat nahi hai, par isko samjhe bina use karna ek **classic bug** hai. Pehle dekho ye kya karta hai:

**`router.refresh()` kya karta hai?** Ye Next.js se kehta hai — "current route ke **Server Components** ko dobara render karo aur naya payload merge karo." Client Components ka `useState` **preserve** hota hai — matlab component **remount nahi hota**.

**Ab problem dekho:** `ShowComments` ek Client Component hai jo `useEffect([])` mein khud `fetch` karta hai. `useEffect([])` **sirf mount pe chalta hai**. `router.refresh()` se component remount nahi hota — isliye `useEffect` dobara nahi chalta, `fetch` nahi hota, aur **list purani hi rehti hai**. Comment `comments.json` mein add ho gaya hoga, par page pe dikhega nahi.

(Ye theory nahi hai — real project mein exactly yehi hota hai. `router.refresh()` call karne pe bhi list purani dikhti hai, kyunki data dikhane wala component khud fetch karta hai.)

**Abhi ke liye kya karein?** Simple — **manual reload (`F5`)**. Page dobara load hota hai, `ShowComments` mount hota hai, `useEffect` chalta hai, naya comment dikhta hai.

**Asli fix 3.3.2 mein aayegi** — jab list ka data `ShowComments` ke andar fetch na hokar `page.tsx` (Server Component) se **props mein** aayega. Tab `router.refresh()` (ya `revalidatePath`) sahi kaam karega — kyunki `router.refresh()` tab hi kaam karta hai jab list ka data **Server Component** se aaye. Abhi wait karo — REST phase mein list ka fresh-data dikhna baad tak defer hai.

**Ek note:** `setAllComments()` wala pattern tab chalega jab list ka state aur form/delete **ek hi component** mein ho — isliye 3.2 ka delete (dono `ShowComments` ke andar) wahi pattern use karega. Par yahan form alag component hai — isliye ye pattern bhi nahi chalega.

### Test Karo — POST Bhi Kaam Kar Raha Hai

1. Browser kholo — `http://localhost:3000`
2. Pehle 2 comments dikhenge — "Bahut achha hai!" aur "Mujhe pasand aaya."
3. Naya comment likho — "Submit" pe click karo
4. **Comment `comments.json` mein add ho gaya** — par page pe list mein **nahi dikha** (kyunki list abhi update nahi hui — upar wala `router.refresh()` wala point)
5. **`F5` / manual refresh** karo — naya comment ab list mein dikhega (`ShowComments` mount pe dobara fetch karega)
6. Server restart karo (`Ctrl+C` phir `npm run dev`) — **changes wapas dikhega!**

**Kyun?** Kyunki data JSON file mein save ho raha hai — memory mein nahi. Server restart hone pe bhi data safe rahega. Par naya comment **khud se list mein nahi aata** — list client side khud fetch karti hai aur usko pata nahi chalta ki data badla hai. Isliye manual refresh karna padta hai. **Asli fix 3.3.2 mein** — jab list ka data Server Component se aayega.

Kya ho raha hai background mein? User "Submit" click → `CommentForm` ka `handleSubmit` → `fetch("/api/comments", { method: "POST" })` → `route.ts` ka POST function → naya comment JSON mein save → **list abhi purani** (`ShowComments` ko pata nahi chala). Manual refresh pe `ShowComments` mount hota hai → `useEffect` chalta hai → fresh data → naya comment list mein dikhta hai.

## Dynamic Routes — Comments Ko Click Karo

Ab tumhare paas comments ki list hai. Par kya hota agar har comment pe click karke uska detail page dekh sako? Chal ab woh banate hain.

### Step 1: Dynamic Route Handler

Pehle `lib/comments.ts` mein `getCommentById()` function add karo:

```tsx
// lib/comments.ts — getCommentById() add kiya
export function getCommentById(id: number) {
  return getAllComments().find((c) => c.id === id);
}
```

Abhi tak `getAllComments()` aur `addComment()` tha. Ab specific comment chahiye toh `getCommentById()` banaya. **Har naya requirement pe naya function.**

Ab **API route** banao — `app/api/comments/[id]/route.ts`:

```tsx
// app/api/comments/[id]/route.ts
import { NextResponse } from "next/server";
import { getCommentById } from "@/lib/comments";

export async function GET(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const comment = getCommentById(Number(id));

  if (!comment) {
    return NextResponse.json({ error: "Comment nahi mila" }, { status: 404 });
  }

  return NextResponse.json(comment);
}
```

`[id]` ek **dynamic segment** hai — URL ka wo hissa jo badal sakta hai. Route Handler ko **do arguments** milte hain — `request` aur `{ params }`. Agar URL: `/api/comments/1` toh `params = { id: "1" }`.

**Important:** Next.js 15 mein `params` ek **Promise** hai — `await` karna padega.

`comments.find()` — JavaScript ka array method, pehla matching element dhoondta hai. `.find()` se ek milta hai, `.filter()` se saare.

### Step 2: Page Banao

Nayi file banao: `app/comments/[id]/page.tsx`

```tsx
// app/comments/[id]/page.tsx
"use client";

import Link from "next/link";
import { useEffect, useState } from "react";

type Comment = {
  id: number;
  text: string;
};

export default function CommentPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const [comment, setComment] = useState<Comment | null>(null);

  useEffect(() => {
    params.then(({ id }) => {
      fetch(`/api/comments/${id}`)
        .then((res) => res.json())
        .then(setComment);
    });
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, []);  // ← Empty — params change hota nahi, sirf mount pe fetch

  if (!comment) {
    return (
      <div className="p-4">
        <h1 className="text-xl font-bold">Loading...</h1>
      </div>
    );
  }

  return (
    <div className="p-4">
      <h1 className="text-xl font-bold mb-2">Comment #{comment.id}</h1>
      <p className="text-lg">{comment.text}</p>
      <Link href="/" className="text-blue-600 hover:underline mt-4 block">
        Wapas jao
      </Link>
    </div>
  );
}
```

Ab `/comments/1` pe jaao — **"Bahut achha hai!"** dikhega! `/comments/2` pe — **"Mujhe pasand aaya!"**!

**Notice kiya?** Ye bhi Client Component hai — `useEffect` + `fetch` wahi pattern hai jo `ShowComments.tsx` mein tha. **Dono pages, same pattern — REST endpoint se data.**

### Promise Kya Hai? — 2 Tareeke Se Data Nikalo

`params` ek **Promise** hai. Promise ka matlab hai — "data abhi nahi hai, **baad mein** aayega."

Promise se data nikalne ke **2 tareeke** hain:

#### Tareeka 1: `await` (Server Component)

```tsx
// Server Component — async function banake await karo
export default async function Page({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;  // ← wait karo jab tak resolve na ho
  // ab id mil gaya — aage badho
}
```

**Kyun chalta hai?** Kyunki Next.js server pe pehle async functions run karta hai, phir HTML render karta hai. Server ko wait kar sakte ho — user ko pata bhi nahi chalta.

#### Tareeka 2: `.then()` (Client Component)

```tsx
// Client Component — async nahi bana sakte, isliye .then()
"use client";

export default function Page({ params }: { params: Promise<{ id: string }> }) {
  useEffect(() => {
    params.then(({ id }) => {    // ← register karo, turant return
      fetch(`/api/comments/${id}`)
        .then((res) => res.json())
        .then(setComment);
    });
  }, []);
}
```

**Kyun `.then()`?** Kyunki Client Component mein `async` nahi bana sakte. Par `.then()` use kar sakte ho — ye **callback pattern** hai.

### `await` vs `.then()` — Fark Kya Hai?

```tsx
// AWAIT — BLOCKING hai
async function Component() {
  const { id } = await params;   // ← poora function RUK jayega
  const data = await fetch(...); // ← phir ye chalega
  return <div>{data}</div>;      // ← phir ye render hoga
}

// .then() — NON-BLOCKING hai
function Component() {
  useEffect(() => {
    params.then(({ id }) => {    // ← register karo, turant return
      fetch(...).then(setData);  // ← baad mein chalega
    });
  }, []);
  return <div>Loading...</div>;  // ← turant render ho jaata hai
}
```

**Notice kiya?**
- `await` = **ruk jao** jab tak data na aaye
- `.then()` = **register karo** aur aage badho, data baad mein aayega

**Server Component mein `await` kyun chalta hai?** Kyunki server pe user wait kar sakta hai — HTML render hone tak. Client Component mein browser ko wait nahi kar sakte — page frozen ho jaayega. Isliye `.then()` pattern use karte hain — **non-blocking** hai.

### useEffect Dependency — `[params]` vs `[]`

```tsx
// GALAT — infinite loop ho sakta hai ❌
useEffect(() => { ... }, [params]);

// SAHI — sirf mount pe ek baar ✅
useEffect(() => { ... }, []);
```

**Kyun `[]`?** Kyunki React mein **har render pe props naye reference hote hain**. `[params]` har baar change dikhta hai → useEffect har render pe chalta hai → infinite fetch loop!

**`[]` (empty dependency)** = sirf component mount hone pe ek baar chale. Params change hota nahi hai — page load pe ek baar fetch enough hai.

### Lint Warning — "missing dependency: params"

Jab `[]` rakhoge, React ka lint rule bolega:

> ⚠️ React Hook useEffect has a missing dependency: 'params'. Either include it or remove the dependency array.

**Par hum `params` nahi likh sakte** — kyunki har render pe naya reference hota hai → infinite loop.

**Solution:** Comment se disable karo:

```tsx
useEffect(() => {
  params.then(({ id }) => {
    fetch(`/api/comments/${id}`)
      .then((res) => res.json())
      .then(setComment);
  });
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, []);
```

Ye **intentional** hai — hum jaante hain ki kya kar rahe ho. Lint rule conservative hai — wo sochta hai "shayad tum bhool gaye." Par humne jaan bujh ke `[]` rakha hai.

**Rule:** Jab bhi `[]` rakho aur lint warning aaye, `eslint-disable` lagao — **par SIRF tab jab tum confirm ho** ki effect ko sirf mount pe chalna hai.

**Kya hota hai agar dependency array hata do (bina `[]` ke)?**

```tsx
// GALAT — har render pe chalega ❌
useEffect(() => {
  params.then(({ id }) => {
    fetch(`/api/comments/${id}`).then(...);
  });
});  // ← koi array nahi!
```

Ye **infinite loop** hai — har render pe fetch hota hai, comment set hota hai, re-render hota hai, phir fetch hota hai... Tumhein data dikh raha hai par performance kharab hai aur unnecessary network calls ho rahi hain.

### Kya Ho Raha Hai?

```
User clicks "Bahut achha hai!" (Link → /comments/1)
    ↓
app/comments/[id]/page.tsx loads ("use client")
    ↓
useEffect → params.then → id = "1"
    ↓
fetch("/api/comments/1") → REST call
    ↓
api/comments/[id]/route.ts → GET → getCommentById(1)
    ↓
JSON: { id: 1, text: "Bahut achha hai!" }
    ↓
Page renders: Comment #1 + "Bahut achha hai!"
```

**Pura flow REST API ke through hai** — page ka `fetch` → API route → lib ka data. `ShowComments.tsx` bhi isi pattern se kaam karta hai (`fetch("/api/comments")`). **Dono pages, same pattern — REST endpoint se data.**

### Par Ye Client Component Kyun? Loading State Kyun?

Tumne notice kiya hoga — isme `useState`, `useEffect`, loading state sab hai. **Boilerplate** lag rahi hai? Haan, bilkul hai. Aur yehi reason hai ki aage **3.3 mein Server Actions aayenge** — jo is boilerplate ko khatam karenge. Abhi REST pattern seekhna zaroori hai, kyunki ye har jagah kaam aata hai.

**Rule of thumb:**
- **Data REST API se aata hai** → Client Component + `fetch` + loading state
- **Form submit karna hai** → abhi REST, baad mein Server Actions (3.3)

## Nutshell

Route Handlers se Next.js mein API endpoints bante hain — `app/api/[something]/route.ts` file se. Har HTTP method ka apna function hota hai (`GET`, `POST`). Server se `NextResponse.json()` se response bhejte hain. Client se `fetch()` se call hota hai. Ye **fundamental** hai — REST API har jagah kaam aata hai.

---

## Common Mistakes

- **Function ka naam galat** — `GET` likhna hai toh `export async function GET()` hona chahiye
- **`NextResponse` import na karna** — bina import ke error aayega
- **`request.json()` ke baad dobara use karna** — body ek baar hi padh sakte ho
- **Status code na dena** — POST ke baad `201`, error pe `404` ya `500`
- **Server-side code client mein daal dena** — `route.ts` sirf server pe run hota hai
- **`method` na likhna** — `fetch()` mein method nahi likhoge toh GET ho jaayega
