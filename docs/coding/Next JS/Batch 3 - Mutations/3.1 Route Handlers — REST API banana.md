Batch 2 mein humne data **padha** — Server Components se `fetch()` kiya, products dikhaye. Par sirf padha — data **likha** nahi.

Socho ek blog hai — post padh sakte ho, par comment nahi kar sakte. Review dekh sakte ho, par review likh nahi sakte. **Ye adhura hai.**

Ab seekhenge data **kaise change karte hain** — pehle Route Handlers se (REST API), phir Server Actions se (Next.js shortcut).

---

## SOCH: Ab Tak Kya Karte The?

Ab tak hum sirf **GET** karte the — data padhte the. Server se data aata tha, hum dekhte the. **One-way communication** tha.

```
Client  --GET-->  Server
Client  <--data--  Server
```

Browser mein URL type kiya → server ne page bheja → humne dekha. Bas. Humne server ko kuch **bheja** nahi.

**Ab kya badlega?**

Ab hum server ko data **bhejenge** bhi — comment add karenge, review likhenge.

```
Client  --GET-->     Server   (data mangna)
Client  <--data--    Server   (data aaya)
Client  --POST-->    Server   (data bhejna)
Client  <--confirm-- Server   (confirm mila)
```

Ye **two-way communication** ho gayi. Client aur server dono ek doosre se baat kar rahe hain.

---

## HTTP Methods Kya Hote Hain?

Har request ke saath ek **method** hota hai — ye batata hai ki client kya karna chahta hai.

| Method | Matlab | Example |
|--------|--------|---------|
| **GET** | Data padho | Blog post dekho, products list karo |
| **POST** | Naya data banao | Comment add karo, review likho |

Ab tak hum sirf GET use kar rahe the. Ab POST bhi seekhenge. PUT aur DELETE baad mein 3.2 mein.

---

## Fetch Kya Hai?

`fetch()` ek **built-in JavaScript function** hai — browser mein pehle se hota hai. Ye client se server ko request bhejne ke liye use hota hai.

```tsx
const res = await fetch("https://api.example.com/products");
const products = await res.json();
```

Kya ho raha hai? Pehle `fetch()` se server ko GET request jaati hai, phir `.json()` se JSON → JavaScript object convert hota hai. **Ye tum ab tak kar rahe the** — Server Components mein `fetch()` se data late the.

---

## Fetch Se POST Kaise Karte Hain?

Ab tak sirf GET kar rahe the. Ab POST kaise karenge — `fetch()` mein options dena padega:

```tsx
const res = await fetch("/api/comments", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ text: "Naya comment!" }),
});

const newComment = await res.json();
```

Chal samajhte hain har line:

**`method: "POST"`** — Ab tak ye nahi tha, kyunki default GET hota hai. Ab explicitly bol rahe hain ki "mujhe POST karna hai".

**`headers: { "Content-Type": "application/json" }`** — Ye batata hai ki hum JSON bhej rahe hain. Jaise letter pe address hota hai, waise request pe hota hai ki data kis format mein hai.

**`body: JSON.stringify({ text: "Naya comment!" })`** — Ye hai actual data. `JSON.stringify()` se JavaScript object → JSON string convert hota hai.

Notice kiya? GET mein sirf URL tha. POST mein **teen cheezein extra** hain — method, headers, body. Kyunki ab hum sirf data nahi padh rahe, bhej bhi rahe hain.

---

## Kyun Fetch? Axios Kyun Nahi?

Dono ka kaam same hai — server se request bhejna. Par fark hai:

**Fetch (Built-in):** Kuch install nahi karna, browser mein pehle se hai. Par `.json()` manual karna padta hai, headers har baar dena padta hai.

**Axios (Third-party):** Automatic JSON conversion hai, par install karna padega. Extra dependency hai.

Simple project hai toh **Fetch** — zero dependency, standard hai. Complex project hai toh **Axios**. Abhi ke liye Fetch se seekho.

## Pehle NextResponse Samajh Lo

Server client ko data bhejta hai — usko **response** kehte hain. Next.js mein ye `NextResponse` se hota hai. Sabse commonly used hai `.json()` method:

```tsx
return NextResponse.json({ name: "Vin", age: 25 });
// Client ko milega: {"name":"Vin","age":25}
```

Ye automatically **teen kaam** karta hai — object → JSON string, Content-Type header set, proper response. Import kaise karte hain?

```tsx
import { NextResponse } from "next/server";
```

`next/server` se aata hai. **Har Route Handler mein ye import zaroori hai.**

---

## Pehla Route Handler — GET

```tsx
// app/api/comments/route.ts
import { NextResponse } from "next/server";

export async function GET() {
  const comments = [
    { id: 1, text: "Bahut achha hai!" },
    { id: 2, text: "Mujhe pasand aaya." },
  ];

  return NextResponse.json(comments);
}
```

`export async function GET()` — Naam **GET** hona chahiye, kyunki Next.js HTTP method ke hisaab se function call karta hai. Client ne GET request bheji → ye GET function chalega.

Browser mein `/api/comments` kholo — JSON dikhega!

## Ab POST Bhi Karte Hain

GET toh samajh aa gaya. Ab sawaal — naya comment add kaise karenge? Chal same file mein dono likhte hain:

```tsx
// app/api/comments/route.ts
import { NextResponse } from "next/server";

let comments = [
  { id: 1, text: "Bahut achha hai!" },
  { id: 2, text: "Mujhe pasand aaya." },
];

// GET - saare comments lao
export async function GET() {
  return NextResponse.json(comments);
}

// POST - naya comment add karo
export async function POST(request: Request) {
  const body = await request.json();
  const newComment = {
    id: comments.length + 1,
    text: body.text,
  };
  comments.push(newComment);
  return NextResponse.json(newComment, { status: 201 });
}
```

Notice kiya? GET mein sirf `return` tha. POST mein `request`, `body`, `push`, `status: 201` — kyunki data aa raha hai aur naya resource ban raha hai.

### "Request" import kahan hai?

Tune notice kiya hoga — `request: Request` likha hai par import kahan hai? File mein kahin nahi!

`Request` ek **global Web API** hai — import ki zaroorat nahi. Jaise `console`, `setTimeout`, `fetch` — ye sab pehle se available hain. Waise hi `Request` bhi browser aur Node.js dono mein pehle se hota hai.

Maine bhi pehli baar ye dekh ke socha tha "import kahan hai?" — par yaad rakh, ye global hai.

### POST ke andar kya ho raha hai?

```tsx
export async function POST(request: Request) {
  const body = await request.json();     // 1
  const newComment = {
    id: comments.length + 1,             // 2
    text: body.text,                     // 3
  };
  comments.push(newComment);             // 4
  return NextResponse.json(newComment, { status: 201 });  // 5
}
```

`await request.json()` — client ne jo JSON bheja, usko object mein convert kar raha hai. `await` isliye kyunki body stream hai — thoda time lagta hai.

`id: comments.length + 1` — simple ID bana rahe hain, database nahi hai abhi.

`{ status: 201 }` — HTTP status code. 201 matlab "Created" — naya resource ban gaya.

### Server data wapas kyun bhejta hai?

Comment save ho gaya — par server kyun wapas bhej raha hai? Main bhi pehle sochta tha "bas save ho gaya, khatam". Par 3 reasons hain:

**Server-generated fields** — Client sirf `text` bhejta hai. Par `id` server generate karta hai. Agar server wapas na bheje, toh client ko pata kaise chalega ki kaunsa ID mila?

**Confirmation** — Server wapas bhej ke confirm karta hai — "haan, data save ho gaya."

**Client state update** — Client ko list mein naya comment add karna hai. Server wapas bhej de toh seedha list mein add kar sakte ho — dobara GET request nahi padegi.

### Status Codes

| Code | Matlab | Kab |
|------|--------|-----|
| **200** | OK | GET successful |
| **201** | Created | POST successful |
| **400** | Bad Request | Galat data aaya |
| **404** | Not Found | Resource nahi mila |
| **500** | Server Error | Server pe gadbad |

#### Step 1: Sirf Form + POST

Pehle sirf wo banate hain jo comment submit kare — bina list ke, bina GET ke:

```tsx
"use client";

import { useState } from "react";

export default function CommentForm() {
  const [text, setText] = useState("");

  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();

    const res = await fetch("/api/comments", {
      method: "POST",
      body: JSON.stringify({ text }),
      headers: {
        "Content-Type": "application/json",
      },
    });

    const newComment = await res.json();
    console.log("Added:", newComment);
    setText("");
  };

  return (
    <form onSubmit={handleSubmit} className="mb-4">
      <input
        value={text}
        onChange={(e) => setText(e.target.value)}
        placeholder="Apna comment likho..."
        className="border p-2 rounded mr-2"

        type="submit"
        className="bg-blue-500 text-white px-4 py-2 rounded"
```

Notice kiya? Ye **sirf POST** hai — user type karta hai, submit karta hai, `fetch()` se POST request jaati hai. Bilkul wahi jo upar seekha — `method: "POST"`, `headers`, `body`, `JSON.stringify`.

Ab isko try karo — `npm run dev` chalao, form mein kuch likho, submit karo. Console mein naya comment dikhega. **Par problem hai** — page reload ho raha hai (HTML default behaviour).

#### Step 2: Ab GET Add Karo — Comments Load Karo

Ab problem ye hai ki purane comments nahi dikh rahe. Chal `useEffect` se page load pe GET add karte hain:

```tsx
"use client";

import { useEffect, useState } from "react";

export default function CommentForm() {
  const [text, setText] = useState("");
  const [allComments, setAllComments] = useState<{ id: number; text: string }[]>([]);

  // Page load pe saare comments fetch karo
  useEffect(() => {
    const fetchComments = async () => {
      const res = await fetch("/api/comments");
      const comments = await res.json();
      setAllComments(comments);
    };
    fetchComments();
  }, []);

  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();

    const res = await fetch("/api/comments", {
      method: "POST",
      body: JSON.stringify({ text }),
      headers: {
        "Content-Type": "application/json",
      },
    });

    const newComment = await res.json();
    setAllComments([...allComments, newComment]);
    setText("");
  };

  return (
    <div className="p-4 border rounded">
      <h2 className="text-xl font-bold mb-4">Comments</h2>

      <form onSubmit={handleSubmit} className="mb-4">
        <input
          value={text}
          onChange={(e) => setText(e.target.value)}
          placeholder="Apna comment likho..."
          className="border p-2 rounded mr-2"
        />
        <button
          type="submit"
          className="bg-blue-500 text-white px-4 py-2 rounded"
        >
          Submit
        </button>
      </form>

      <ul className="space-y-2">
        {allComments.map((comment) => (
          <li key={comment.id} className="border-b pb-2">
            <span>{comment.text}</span>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

Dekho kya badla — sirf 2 cheezein add hui:

1. **`useEffect`** — page load pe GET request karke saare comments laata hai
2. **`allComments` state** — comments ko store karta hai
3. **List in JSX** — comments ko render karta hai

**Notice kiya?** `useEffect` mein sirf URL hai — GET mein kuch bhejne ki zaroorat nahi. `handleSubmit` mein method + headers + body hai — POST mein teeno chahiye. **Wahi fetch, alag alag purpose ke liye.**

## Dynamic Routes Bhi Ban Sakte Hain

Ek specific comment padhna ho (`/api/comments/1`):

```tsx
// app/api/comments/[id]/route.ts
import { NextResponse } from "next/server";

let comments = [
  { id: 1, text: "Bahut achha hai!" },
  { id: 2, text: "Mujhe pasand aaya." },
];

export async function GET(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const comment = comments.find((c) => c.id === Number(id));

  if (!comment) {
    return NextResponse.json({ error: "Comment nahi mila" }, { status: 404 });
  }

  return NextResponse.json(comment);
}
```

`[id]` ek **dynamic segment** hai — URL ka wo hissa jo badal sakta hai. Route Handler ko **do arguments** milte hain — `request` aur `{ params }`. Agar URL: `/api/comments/1` toh `params = { id: "1" }`.

**Important:** Next.js 15 mein `params` ek **Promise** hai — `await` karna padega.

`comments.find()` — JavaScript ka array method, pehla matching element dhoondta hai. `.find()` se ek milta hai, `.filter()` se saare.

## Nutshell

Route Handlers se Next.js mein API endpoints bante hain — `app/api/[something]/route.ts` file se. Har HTTP method ka apna function hota hai (`GET`, `POST`). Server se `NextResponse.json()` se response bhejte hain. Client se `fetch()` se call hota hai. Ye **fundamental** hai — REST API har jagah kaam aata hai.

---

## Common Mistakes

- **Function ka naam galat** — `GET` likhna hai toh `export async function GET()` hona chahiye
- **`NextResponse` import na karna** — bina import ke error aayega
- **`request.json()` ke baad dobara use karna** — body ek baar hi padh sakte ho
- **Status code na dena** — POST ke baad `201`, error pe `404` ya `500`
- **Server-side code client mein daal dena** — `route.ts` sirf server pe run hota hai
- **`method` na likhna** — `fetch()` mein method nahi likhoge toh GET ho jaayega
