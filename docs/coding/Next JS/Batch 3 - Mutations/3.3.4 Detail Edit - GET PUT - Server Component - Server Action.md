3.3.3 mein delete ko Server Action bana diya — hidden input ke through `id` bheji, `deleteComment` call hua. Ab sirf ek operation baaki hai — **edit (PUT)**.

3.2 mein edit ka flow yaad karo — detail page `/comments/[id]` pe **Edit button** tha, click pe form khulata tha, Save pe **PUT request** jaati thi. Wo page **Client Component** tha — `params.then`, `useEffect`, `fetch`, manual `editing` state... bahut boilerplate.

Ab isko refactor karte hain — **sabse bada boilerplate hatane wala step.**

export default function CommentPage({ params }: { params: Promise<{ id: string }> }) {
  const [comment, setComment] = useState<{ id: number; text: string } | null>(null);
  const [editing, setEditing] = useState(false);   // edit mode ON/OFF

        setEditText(data.text);  // form pehle se old text dikhaye

      load();
    });

  if (!comment) return <p>Loading...</p>;

  return (
    <div className="p-4 border rounded max-w-md mx-auto">
      {editing ? (
        <form onSubmit={handleUpdate} className="flex flex-col gap-2">
          <input value={editText} onChange={(e) => setEditText(e.target.value)} className="border p-2 rounded" />
          <div className="flex gap-2">
            <button type="submit" className="bg-green-500 text-white px-4 py-2 rounded">Save</button>
            <button type="button" onClick={() => setEditing(false)} className="text-gray-500 text-sm">Cancel</button>
          </div>
        </form>

        <>
          <p className="text-lg">{comment.text}</p>

        </>
      )}
    </div>
  );

## Step 2: EditCommentForm Banao

Form kya use karega — 2 mutate operations combine karte hain:
- **PUT** → `updateCommentAction`
- Form data: `text` (input se) + `id` (hidden input se, delete waise hi jaise delete mein tha)

**File:** `app/components/EditCommentForm.tsx` — NAYI FILE

```tsx
// app/components/EditCommentForm.tsx — NAYI FILE (Client Component — button click chahiye)
"use client";

import { useEffect, useActionState, useState } from "react";
import { toast } from "sonner";
import { updateCommentAction, FormState } from "../actions";

const initialState: FormState = {
  success: false,     // Abhi kuch hua nahi
  message: "",        // Abhi message nahi hai
};

export default function EditCommentForm({
  comment,
}: {
  comment: { id: number; text: string };
}) {
  const [editing, setEditing] = useState(false);
  const [state, formAction, isPending] = useActionState(
    updateCommentAction,
    initialState
  );

  // Toast — wahi 3.3.1 / 3.3.3 pattern
  useEffect(() => {
    if (state.message) {
      if (state.success) toast.success(state.message);
      else toast.error(state.message);
    }
  }, [state]);

  return (
    <div className="mt-3">
      {editing ? (
        <form action={formAction} className="flex flex-col gap-2">
          {/* Delete ki tarah — id hidden input se */}
          <input type="hidden" name="id" value={comment.id} />

          <input
            name="text"
            defaultValue={comment.text}   // ← Uncontrolled — prefill old text
            className="border p-2 rounded"
          />

          <div className="flex gap-2">
            <button
              type="submit"
              disabled={isPending}
              className="bg-green-500 text-white px-4 py-2 rounded disabled:opacity-50"
            >
              {isPending ? "Saving..." : "Save"}
            </button>
            <button
              type="button"
              onClick={() => setEditing(false)}
              className="text-gray-500 text-sm"
            >
              Cancel
            </button>
          </div>
        </form>
      ) : (
        <button
          onClick={() => setEditing(true)}
          className="mt-3 bg-blue-500 text-white px-4 py-2 rounded"
        >
          Edit
        </button>
      )}
    </div>
  );
}
```

Dekho kya hai:

1. **`"use client"` isko chahiye** — kyunki `useState(editing)` aur `useActionState` dono hooks hain. Button click pe view/edit toggle karna hai — wo **client interaction** hai.

2. **`defaultValue={comment.text}`** vs 3.2 ka `value={editText}` — 3.2 mein controlled the (`value` + `onChange`). Ab **uncontrolled** hai — `defaultValue` bas initial value set karta hai, phir browser khud track karta hai. **Kyun?** Kyunki `updateCommentAction` form data se direct padh lega — `setEditText` ki zaroorat nahi. (Wahi pattern 3.3.1 mein add form mein dikha tha.)

3. **`name="text"`** + **`name="id"` hidden** — delete waale pattern ka combo. `editText` abhi kahan? `defaultValue` mein.

4. **`action={formAction}`** — wahi `useActionState` adapter. Save pe `updateCommentAction(prevState, formData)` chalta hai, result `state` mein — `useEffect` se toast dikhta hai. `isPending` se Save pe "Saving..." dikhta hai.

5. **Cancel button sirf client ka kaam** — `setEditing(false)` se form band. Server kuch nahi kar raha — isliye `type="button"` (form submit nahi karega).

## Step 3: updateCommentAction Banao

**File:** `app/actions.ts`

```tsx
// app/actions.ts — UPDATED (updateCommentAction add kiya)
"use server";

import { revalidatePath } from "next/cache";
import { addComment, deleteComment, updateComment } from "@/lib/comments";

export type FormState = {
  success: boolean;
  message: string;
};

export async function addCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> { ... }  // 3.3.1 se (wahi)

export async function deleteCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> { ... } // 3.3.3 se (wahi)

// NAYA: update — text + id dono formData se
export async function updateCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const id = Number(formData.get("id"));
  const text = formData.get("text") as string;

  if (!text || !text.trim()) {
    return { success: false, message: "Comment khali nahi ho sakta!" };
  }

  const updated = updateComment(id, text);

  if (!updated) {
    return { success: false, message: "Comment nahi mila!" };
  }

  // List aur detail dono ka data badla — dono paths revalidate
  revalidatePath("/");
  revalidatePath(`/comments/${id}`);

  return { success: true, message: "Comment update ho gaya!" };
}
```

**Wahi pattern** — `prevState` pehla argument, `Promise<FormState>` return type (kyunki `EditCommentForm` mein `useActionState` se call hota hai). Andar: `formData.get("id")` + `formData.get("text")`, validation, `updateComment()` call (3.2 ka function — file se padhta, findIndex karta, text badalta, wapas likhta). Asli kaam `lib` mein hai — Server Action sirf data nikal ke call karta hai. Result `{ success, message }` `state` mein jaata hai aur toast dikhta hai.

**`revalidatePath` do baar kyun?** Edit se **do pages** ka data badalta hai — list (`/` pe text naya dikhe) aur detail page (`/comments/{id}`). Ek `revalidatePath` ek path handle karta hai, isliye dono ko call kiya. (3.3.1 Step 5 mein seekha — path-based revalidation.)

## In Your Own Words

1. Detail page Server Component banane se kaunsi boilerplate hat gayi?

<details>
<summary>Sample Jawab</summary>

`useState` (comment, editing, editText), `useEffect` + `params.then`, inner async function, `fetch("/api/comments/id")`, loading state — sab hat gaya. Server Component `await params` se id nikalta hai aur `getCommentById()` direct call karta hai (data layer layout). Client ka data-fetching boilerplate zero ho gaya.

</details>

2. `defaultValue={comment.text}` aur 3.2 ke `value={editText}` mein kya fark hai?

<details>
<summary>Sample Jawab</summary>

Server Action ke liye uncontrolled better hai kyunki `formData.get("text")` se direct value milti hai — state ki zaroorat nahi.

</details>

3. EditCommentForm ko `"use client"` kyun chahiye, jabki page.tsx Server hai?

<details>
<summary>Sample Jawab</summary>

Kyunki usme `useState(editing)` aur onClick handlers hain — "Edit" button ke click pe form ko open/close karna client-side interaction hai. Page.tsx ka data-read server pe hota hai, par edit ka visibility toggle browser mein chalta hai. Isliye exactly "page server, form client" split karte hain.

</details>

## What It Is NOT

**`notFound()` = "custom 404 page banana" nahi.** Ye sirf "ye resource exist nahi karta" signal karta hai — Next.js default 404 dikhata hai. Custom page aage layout chapter mein banega.

**EditCommentForm = "2 input ka complicated form" nahi.** Pattern same hai — form + action + hidden id. `defaultValue` ke wajah se controlled state ki complexity nahi.

**`app/api` delete karna = "REST bad practice hai" nahi.** Sirf is project ke liye sahi decision hai — kyunki data sare ek hi Next.js app mein hai. External client = route handlers zaroori (3.3.5 ke end aur 3.4.2 mein).
