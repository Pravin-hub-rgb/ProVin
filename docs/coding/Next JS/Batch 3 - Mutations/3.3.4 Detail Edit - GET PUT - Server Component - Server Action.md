3.3.3 mein delete ko Server Action bana diya — hidden input ke through `id` bheji, `deleteComment` call hua. Ab sirf ek operation baaki hai — **edit (PUT)**.

3.2 mein edit ka flow yaad karo — detail page `/comments/[id]` pe **Edit button** tha, click pe form khulata tha, Save pe **PUT request** jaati thi. Wo page **Client Component** tha — `params.then`, `useEffect`, `fetch`, manual `editing` state... bahut boilerplate.

Ab isko refactor karte hain — **sabse bada boilerplate hatane wala step.**

**Flow aise chalega:** pehle **action** (`updateCommentAction`, Step 1), phir **form** (`EditCommentForm`, Step 2), phir **page** (Server Component, Step 3). Har step mein pehle building block banega, phir usse use karne wala — is order se chaloge toh har step compile karega. (3.3.1 / 3.3.3 wala hi rule.)

```tsx
// app/comments/[id]/page.tsx — 3.2 ka pura code
"use client";

import { useEffect, useState } from "react";

export default function CommentPage({ params }: { params: Promise<{ id: string }> }) {
  const [comment, setComment] = useState<{ id: number; text: string } | null>(null);
  const [editing, setEditing] = useState(false);   // edit mode ON/OFF

  useEffect(() => {

        setEditText(data.text);  // form pehle se old text dikhaye
      };
      load();
    });
  }, [params]);

  if (!comment) return <p>Loading...</p>;

  return (
    <div className="p-4 border rounded max-w-md mx-auto">
      {editing ? (
        <form onSubmit={handleUpdate} className="flex flex-col gap-2">
          <input value={editText} onChange={(e) => setEditText(e.target.value)} className="border p-2 rounded" />
          <div className="flex gap-2">
            <button type="submit" className="bg-green-500 text-white px-4 py-2 rounded">Save</button>
            <button type="button" onClick={() => setEditing(false)} className="text-gray-500 text-sm">Cancel</button>
          </div>
        </form>

        <>
          <p className="text-lg">{comment.text}</p>

        </>
      )}
    </div>
  );
}
```

(Save pe `handleUpdate` `fetch` + PUT request bhejta tha — 3.2 mein dekha tha.)

- `useState` × 3 (comment, editing, editText)
- `useEffect` + `params.then` + inner async + `fetch`
- Loading state
- Manual `setComment(updated)` + `setEditing(false)` update logic
- `preventDefault`, `JSON.stringify`, headers...

**Sab kuch iski kyun zaroori tha?** Kyunki client browser mein data load kar raha tha. Par **Server Component seedha `lib` se data padh sakta hai** — toh `useState`/`useEffect`/`fetch` sab gayab!

## Step 1: updateCommentAction Banao — app/actions.ts

Edit ke liye do cheezein chahiye — **`id`** (kis comment ko edit karna hai) aur **`text`** (naya text). Dono form se aayenge (`id` hidden input se, `text` input field se).

**Order kyun?** Pehle server function banayenge, phir Step 2 ke form mein `useActionState` se isi ko call karenge — 3.3.1 / 3.3.3 wale pattern ki tarah: **function pehle, form baad mein.** Agar form pehle banate toh usme import karne ko kuch hota hi nahi.

**File:** `app/actions.ts`

```tsx
// app/actions.ts — UPDATED (updateCommentAction add kiya)
"use server";

import { revalidatePath } from "next/cache";
import { addComment, deleteComment, updateComment } from "@/lib/comments";

export type FormState = {
  success: boolean;
  message: string;
};

// 3.3.1 Step 4 (useActionState) se — wahi pattern
export async function addCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const text = formData.get("comment") as string;

  if (!text || !text.trim()) {
    return { success: false, message: "Comment khali nahi ho sakta!" };
  }

  addComment(text);

  revalidatePath("/");

  return { success: true, message: "Comment add ho gaya!" };
}

// 3.3.3 Step 1 se — wahi pattern
export async function deleteCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const id = Number(formData.get("id"));

  const deleted = deleteComment(id);

  if (!deleted) {
    return { success: false, message: "Comment nahi mila!" };
  }

  revalidatePath("/");

  return { success: true, message: "Comment delete ho gaya!" };
}

// NAYA: update — text + id dono formData se
export async function updateCommentAction(
  prevState: FormState,
  formData: FormData
): Promise<FormState> {
  const id = Number(formData.get("id"));
  const text = formData.get("text") as string;

  if (!text || !text.trim()) {
    return { success: false, message: "Comment khali nahi ho sakta!" };
  }

  const updated = updateComment(id, text);

  if (!updated) {
    return { success: false, message: "Comment nahi mila!" };
  }

  // List aur detail dono ka data badla — dono paths revalidate
  revalidatePath("/");
  revalidatePath(`/comments/${id}`);

  return { success: true, message: "Comment update ho gaya!" };
}
```

**Wahi pattern** — `prevState` pehla argument, `Promise<FormState>` return type (kyunki Step 2 ke `EditCommentForm` mein `useActionState` se call hoga). Andar: `formData.get("id")` + `formData.get("text")`, validation, `updateComment()` call (3.2 ka function — file se padhta, findIndex karta, text badalta, wapas likhta). Asli kaam `lib` mein hai — Server Action sirf data nikal ke call karta hai. Result `{ success, message }` `state` mein jaata hai aur toast dikhta hai.

**`revalidatePath` do baar kyun?** Edit se **do pages** ka data badalta hai — list (`/` pe text naya dikhe) aur detail page (`/comments/{id}`). Ek `revalidatePath` ek path handle karta hai, isliye dono ko call kiya. (3.3.2 Step 2 mein seekha — path-based revalidation.)

**Abhi ye function kahin use nahi hua** — bas bana ke rakha hai. Step 2 mein form banate hi isko import karke use karenge.

## Step 2: EditCommentForm Banao

Ab `updateCommentAction` ready hai — isko form mein use karte hain.

**Naya component kyun?** Page ko Server Component banayenge (Step 3) — par "Edit" button ka click, form ka open/close, Save — sab **client interaction** hai. Isliye form apna alag **Client Component** hoga, page usko render karega.

Form kya use karega — 2 mutate operations combine karte hain:
- **PUT** → `updateCommentAction`
- Form data: `text` (input se) + `id` (hidden input se — wahi delete waala pattern)

**File:** `app/components/EditCommentForm.tsx` — NAYI FILE

```tsx
// app/components/EditCommentForm.tsx — NAYI FILE (Client Component — button click chahiye)
"use client";

import { useEffect, useActionState, useState } from "react";
import { toast } from "sonner";
import { updateCommentAction, FormState } from "../actions";

const initialState: FormState = {
  success: false,     // Abhi kuch hua nahi
  message: "",        // Abhi message nahi hai
};

export default function EditCommentForm({
  comment,
}: {
  comment: { id: number; text: string };
}) {
  const [editing, setEditing] = useState(false);
  const [state, formAction, isPending] = useActionState(
    updateCommentAction,
    initialState
  );

  // Toast — wahi 3.3.1 / 3.3.3 pattern
  useEffect(() => {
    if (state.message) {
      if (state.success) toast.success(state.message);
      else toast.error(state.message);
    }
  }, [state]);

  return (
    <div className="mt-3">
      {editing ? (
        <form action={formAction} className="flex flex-col gap-2">
          {/* Delete ki tarah — id hidden input se */}
          <input type="hidden" name="id" value={comment.id} />

          <input
            name="text"
            defaultValue={comment.text}   // ← Uncontrolled — prefill old text
            className="border p-2 rounded"
          />

          <div className="flex gap-2">
            <button
              type="submit"
              disabled={isPending}
              className="bg-green-500 text-white px-4 py-2 rounded disabled:opacity-50"
            >
              {isPending ? "Saving..." : "Save"}
            </button>
            <button
              type="button"
              onClick={() => setEditing(false)}
              className="text-gray-500 text-sm"
            >
              Cancel
            </button>
          </div>
        </form>
      ) : (
        <button
          onClick={() => setEditing(true)}
          className="mt-3 bg-blue-500 text-white px-4 py-2 rounded"
        >
          Edit
        </button>
      )}
    </div>
  );
}
```

Dekho kya hai:

1. **`"use client"` isko chahiye** — kyunki `useState(editing)` aur `useActionState` dono hooks hain. Button click pe view/edit toggle karna hai — wo **client interaction** hai.

2. **`defaultValue={comment.text}`** vs 3.2 ka `value={editText}` — 3.2 mein controlled the (`value` + `onChange`). Ab **uncontrolled** hai — `defaultValue` bas initial value set karta hai, phir browser khud track karta hai. **Kyun?** Kyunki `updateCommentAction` form data se direct padh lega — `setEditText` ki zaroorat nahi. (Wahi pattern 3.3.1 mein add form mein dikha tha.)

3. **`name="text"`** + **`name="id"` hidden** — delete waale pattern ka combo. `editText` abhi kahan? `defaultValue` mein.

4. **`action={formAction}`** — wahi `useActionState` adapter. Save pe `updateCommentAction(prevState, formData)` chalta hai, result `state` mein — `useEffect` se toast dikhta hai. `isPending` se Save pe "Saving..." dikhta hai.

5. **Cancel button sirf client ka kaam** — `setEditing(false)` se form band. Server kuch nahi kar raha — isliye `type="button"` (form submit nahi karega).

## Step 3: Detail Page Ko Server Component Banao

Ab `EditCommentForm` ready hai (Step 2) — page isko import karke render kar sakta hai. **Order yahan ka reason:** bina form ke page mein `EditCommentForm` import karne ko kuch nahi tha — pehle building block (action → form), phir usse use karne wala page. Isi liye har step compile karta hai.

**File:** `app/comments/[id]/page.tsx` — pura rewrite

```tsx
// app/comments/[id]/page.tsx — UPDATED (ab SERVER Component hai)
import { getCommentById } from "@/lib/comments";
import { notFound } from "next/navigation";
import Link from "next/link";
import EditCommentForm from "../../components/EditCommentForm";

export default async function CommentPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;               // Promise → value (Server Component hai, isliye await allowed)
  const comment = getCommentById(Number(id));

  if (!comment) {
    notFound();                              // comment nahi mila → 404 page
  }

  return (
    <div className="p-4 border rounded max-w-md mx-auto">
      <p className="text-lg">{comment.text}</p>
      <EditCommentForm comment={comment} />
      <Link href="/" className="text-blue-600 hover:underline mt-4 block">
        Wapas jao
      </Link>
    </div>
  );
}
```

**Pura page kya kar raha hai?** Sab server pe hi — `params` se `id` nikali, `getCommentById(Number(id))` se comment seedha `lib` se padha (koi `fetch` nahi), aur comment ke saath `EditCommentForm` render kiya. Edit ki saari interaction (button click, form toggle) us Client Component mein hai — page sirf data + component dikhata hai.

Dekho kya gayab hua (Current Code Dekho wale count se compare karo):
1. **`"use client"`** — hat gaya
2. **`useState` × 3** — hat gaya
3. **`useEffect` + `params.then`** — hat gaya. Ab `await params` seedha (wahi 3.1 mein dekha tha: Server Component mein await chalta hai, Client mein `.then()`)
4. **`fetch` + Loading state** — hat gaya. `getCommentById(Number(id))` direct call

**`notFound()` kya kar raha hai?** Agar `getCommentById` null return kare (id galat), toh Next.js automatic **404 page** dikha deta hai. 3.1 mein API route mein `{ status: 404 }` return karte the — yahan direct built-in.

**Abhi page pe "Edit" button dikhta hai** — kyunki `EditCommentForm` (Step 2) render ho raha hai. Dono parts mil ke poora flow banate hain: data server se, edit interaction client se.

**Poori file delete** (VS Code right-click → Delete) — kyunki ab usme koi bhi handler use nahi ho raha:

**Ab `app/api/` folder khaali ho gaya hai — poora folder bhi delete kar do** (VS Code mein `api` folder right-click → Delete):

**Ye hi refactor ka poora point hai** — Route Handlers (3.1, 3.2 ke 2 files) **poori tarah hat gaye.** (`comments/route.ts` wala GET + POST toh 3.3.1 / 3.3.2 mein hi gaya tha — `[id]/route.ts` aakhri REST file thi.) Ab structure:

```
  comments.ts                       ← Data layer (unchanged)

```

## What It Is NOT

**`notFound()` = "custom 404 page banana" nahi.** Ye sirf "ye resource exist nahi karta" signal karta hai — Next.js default 404 dikhata hai. Custom page aage layout chapter mein banega.

**EditCommentForm = "2 input ka complicated form" nahi.** Pattern same hai — form + action + hidden id. `defaultValue` ke wajah se controlled state ki complexity nahi.

**`app/api` delete karna = "REST bad practice hai" nahi.** Sirf is project ke liye sahi decision hai — kyunki data sare ek hi Next.js app mein hai. External client = route handlers zaroori (3.3.5 ke end aur 3.4.2 mein).
