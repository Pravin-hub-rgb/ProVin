## TEST + Problem Highlight

**TEST:** `/` pe boards list, `/board/1` pe columns + tasks dikhne chahiye. Design confirm — columns ek line mein, har column mein add form + sorted tasks.

**Problem — data do jagah hai (DRY violation):**

Abhi tasks hardcoded hain **page ke andar**. Kya problem? 6.13.1 mein plan tha — Task Board ka data **database** mein hoga (Prisma). Is UI ko dynamic banane ke liye:

- Hardcoded array hatao
- Database se data lao
- Forms ko server actions se jodo

Ye tino cheezein 6.13.3 (data layer) + 6.13.4 (dynamic) mein hongi. **UI ka code mostly wahi rahega** — sirf data source badlega. Yahi planning + hardcoded-first ka fayda — UI confirm ho gayi, ab data layer bas plug-in karni hai.

## Nutshell

Hardcoded UI: `/` pe boards list (`{ id, name }` map + form), `/board/[id]` pe columns (filter by status + sort by order) + har column mein add form + tasks. Dynamic route `[id]` ka dhacha taiyr hai (params async — 6.7.3 pattern). Data page ke andar hardcoded hai — ek jagah, par database se replace karni hai — 6.13.4 ka kaam.

## What It Is NOT

- **Hardcoded UI = "final data"** is not true. Yeh static demo hai — UI + data shape validate ke liye. Asli data database se aayega (6.13.4). Ye file UI pattern hai, data nahi.
- **Buttons with `type="button"` = "kaam kar rahe"** is not true. Abhi koi action attached nahi — Move/Delete 6.13.4 mein server actions se judegi. `type="button"` isliye — form submit na karein (default button form submit karta hai).
- **`params as any` hack = "sahi pattern"** is not true. Yeh temporary placeholder hai. Sahi tarika `await params` (6.7.3 mein seekha) — 6.13.4 mein file saaf hogi. Isse future concept ka hint bhi mile — hardcoded phase mein hi dynamic route ka dhacha.
- **Layout = "har page pe copy karo"** is not true. Layout ek baar define hota hai — dono pages uske andar. Header board app ka shared brand hai. (Batch 1 layout concept.)
- **Filter/sort page = "final logic"** is not true. Abhi JS filter/sort chal raha hai. Database mein query-side sorting/filtering hogi (6.13.4). Par logic ka idea yahi hai — column ke tasks + order.
