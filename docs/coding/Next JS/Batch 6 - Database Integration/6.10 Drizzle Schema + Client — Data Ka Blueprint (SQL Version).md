# Drizzle Schema + Client — Data Ka Blueprint (SQL Version)

## Pehle Schema Kyun?

Database use karne ke liye ek **connection file** banani hai (`db/index.ts`) — jo Neon se connect karegi aur `db` variable export karegi. Par woh connection file **schema import** karegi — taaki Drizzle ko pata ho table ka structure kya hai:

```
db/index.ts → schema import karega → db/schema.ts
```

Toh pehle schema (table structure), phir connection file — ek baar mein complete.

## `db/` Folder Kyun, `lib/` Kyun Nahin?

Mongo mein `lib/mongodb.ts` banayi thi (`lib/` = general helpers). **`db/` specifically database ke liye** — schema + connection, dono yahan. Drizzle community mein yahi convention hai. Project root mein banao (jahan `app/` hai):

```
sql-todo/
├── app/
├── db/              ← naya folder
├── .env.local
└── package.json
```

## `db/schema.ts` — Table Define Karna

6.9 mein test connection mein raw SQL likhi thi. Ek table ka SQL structure aisa hota hai:

```sql
CREATE TABLE drizzle_todos (
  id    SERIAL   PRIMARY KEY,
  title TEXT     NOT NULL,
  done  BOOLEAN  DEFAULT false
);
```

Ab yahi cheez TypeScript mein — **Drizzle ke syntax mein**. Column types `drizzle-orm/pg-core` se aate hain (`pg` = PostgreSQL — Drizzle ka PostgreSQL wala part):

```ts
import { pgTable, serial, text, boolean } from 'drizzle-orm/pg-core'
```

```
pgTable   ← "ek PostgreSQL table define karo"
serial    ← SERIAL — auto 1, 2, 3... — id ke liye
text      ← TEXT — string data
boolean   ← BOOLEAN — true ya false
```

**File:** `db/schema.ts`

```ts
// db/schema.ts
import { pgTable, serial, text, boolean } from 'drizzle-orm/pg-core'
import { InferSelectModel } from 'drizzle-orm'

export const todos = pgTable('drizzle_todos', {
  id: serial('id').primaryKey(),
  title: text('title').notNull(),
  done: boolean('done').default(false).notNull(),
})

export type Todo = InferSelectModel<typeof todos>
```

Line by line:

- **`pgTable('drizzle_todos', {...})`** — database mein table ka naam `drizzle_todos`. (Naam conflict se bachne ke liye `todos` nahi — yaad hai 6.9 mein Neon mein manually tables banayi the? Agar Drizzle wali bhi `todos` rakhen toh `push` pe confusion — kaunsi table kisne banayi. `drizzle_todos` clear hai.)
- **`serial('id').primaryKey()`** — SQL `id SERIAL PRIMARY KEY` — auto 1, 2, 3... + unique identifier.
- **`text('title').notNull()`** — SQL `title TEXT NOT NULL` — string, khaali nahi ho sakti.
- **`boolean('done').default(false).notNull()`** — SQL `done BOOLEAN DEFAULT false` — value na do toh false.
- **`export type Todo = InferSelectModel<typeof todos>`** — 6.5 mein `ITodo` interface **manually** likha tha. Problem: schema badla toh type alag se update karna padega — bhool gaye toh bug. `InferSelectModel` schema dekh ke **khud type nikaal deta hai** — schema badla, type auto-update.

Internally `Todo` banta hai:

```ts
type Todo = {
  id: number      // serial → number
  title: string   // text → string
  done: boolean   // boolean → boolean
}
```

Compare karo 6.5 ke saath — manually interface vs schema-derived:

```ts
// 6.5 MongoDB — manually interface
interface ITodo {
  _id: string
  title: string
  done: boolean
}

// 6.10 Drizzle — schema se automatic
export type Todo = InferSelectModel<typeof todos>
```

## `db/index.ts` — Connection + Db Client

**Kyun chahiye?** Next.js mein kai jagah database use karni hai (page, actions). Har jagah seedha Neon se connect karein toh har file mein same connection code — repetition. **Ek jagah connection banao — sab jagah se import karo.** Yahi `db/index.ts` ka kaam hai.

**File:** `db/index.ts`

```ts
// db/index.ts
import { neon } from '@neondatabase/serverless'
import { drizzle } from 'drizzle-orm/neon-http'
import * as schema from './schema'

const sql = neon(process.env.DATABASE_URL!)

export const db = drizzle(sql, { schema })
```

Line by line:

- **`neon(process.env.DATABASE_URL!)`** — raw Neon connection (6.9 wala test wahi tha). `!` — TypeScript ko guarantee: "`.env.local` mein definitely hai, undefined nahi".
- **`import * as schema from './schema'`** — schema.ts ki saari exports ek saath `schema` object mein (`schema.todos`, `schema.Todo`). Drizzle ko isi se types pata chalti hain.
- **`drizzle(sql, { schema })`** — Drizzle instance banata hai — `db.select()`, `db.insert()` jaisi type-safe queries. **`{ schema }` dena zaroori hai** — bina iske queries mein types check nahi hongi.
- **`export const db`** — har jagah import karenge: `db.select()`, `db.insert()`, etc.

**`drizzle-orm/neon-http` kyun — seedha `drizzle-orm` kyun nahi?** Drizzle ke andar alag databases ke liye alag connectors hain:

```
drizzle-orm/neon-http    ← Neon ke liye
drizzle-orm/postgres-js  ← local PostgreSQL ke liye
drizzle-orm/mysql2       ← MySQL ke liye
```

Hum Neon use kar rahe hain — toh `neon-http` wala.

**MongoDB se compare** (6.4 wala `lib/mongodb.ts`):

```ts
// 6.4 MongoDB — lib/mongodb.ts
// async/await + readyState check karna padta tha
async function connectDB() {
  if (mongoose.connection.readyState === 1) return
  await mongoose.connect(MONGODB_URI)
}

// 6.10 Drizzle — db/index.ts
// Neon serverless hai — har query pe auto connect — 3 lines
const sql = neon(process.env.DATABASE_URL!)
export const db = drizzle(sql, { schema })
```

Mongo connection persistent hota tha (ek baar connect, reused). Neon serverless hai — queries apne aap connect/disconnect karta hai — isliye `db` direct export hota hai, `connectDB()` await ki zaroorat nahi.

## `drizzle.config.ts` — Drizzle-kit Ko Sab Batana

`drizzle-kit` ko abhi kuch pata nahi: "schema file kahan hai? kaunsa database? connect kaise?" — sab config file mein batate hain.

**File:** `drizzle.config.ts` (project root — `drizzle-kit` command chalaate waqt automatically root mein dhundhta hai)

```ts
// drizzle.config.ts
import { defineConfig } from 'drizzle-kit'

export default defineConfig({
  schema: './db/schema.ts',
  out: './drizzle',
  dialect: 'postgresql',
  dbCredentials: {
    url: process.env.DATABASE_URL!,
  },
})
```

- **`schema`** — schema file kahan hai (table structure).
- **`out`** — migrations kahan save karein (`drizzle/` folder — `drizzle-kit` khud banayega).
- **`dialect: 'postgresql'`** — kaunsa database (Drizzle MySQL/SQLite/PostgreSQL sab support karta hai).
- **`dbCredentials.url`** — Neon se connect ke liye connection string (table banane ke liye).

> **Migration kya hota hai?** Aaj table banayi. Kal naya column chahiye (`createdAt`). Database mein table pehle se hai — seedha nahi badal sakte. Pehle ek "change record" banate hain (migration file), phir apply karte hain. `drizzle-kit` yeh files `drizzle/` folder mein save karta hai. Production mein yehi system hai — schema changes track hote hain. (Detail 6.13.3 mein — abhi bas idea.)

## Neon Mein Table Banao — `npx drizzle-kit push`

Ab terminal mein:

```bash
npx drizzle-kit push
```

- **`npx`** — installed packages ko terminal se run karta hai (yaad hai `npx create-next-app`? wahi).
- Kya hoga: `drizzle.config.ts` padha → schema file padhi → Neon se connect kiya → check kiya "drizzle_todos table pehle se hai?" → nahi thi toh `CREATE TABLE` SQL khud chala di.

Terminal mein: `[✓] Changes applied`. Neon dashboard mein "Tables" → `drizzle_todos` dikhegi.

## Nutshell

Drizzle mein: `db/schema.ts` mein `pgTable` + column types (serial/text/boolean) se table define hoti hai, `InferSelectModel` type nikaalta hai. `db/index.ts` mein `neon()` connection + `drizzle(sql, { schema })` se `db` client milta hai (Mongo ke `connectDB` se simpler). `drizzle.config.ts` kit ko batata hai kaunsi file/kaunsa DB. `npx drizzle-kit push` Neon mein actual table banata hai.

## What It Is NOT

- **`pgTable` = database mein table banana nahi.** `pgTable` sirf TypeScript definition hai. Asli table Neon mein `drizzle-kit push` se banti hai. Bina push ke app chalao toh error — "relation does not exist".
- **`InferSelectModel` = "magic type" nahi.** Yeh schema ke columns dekh ke ek type generate karta hai — convenience hai, magic nahi. `number`/`string`/`boolean` — yahi toh banega.
- **`db` = connection nahi.** `db` Drizzle ka client/interface hai jo queries likhne ke liye hai (`db.select()`). Connection neeche `sql` hai. User `db` hi use karega — `sql` seedha nahi.
- **`drizzle.config.ts` = runtime code nahi.** Yeh sirf `drizzle-kit` (dev tool) ke liye hai — app ke andar import nahi hota. Isliye `drizzle-kit` production dependency nahi, dev dependency hai.
- **`npx drizzle-kit push` = production migration tool nahi.** `push` dev mein quick sync ke liye hai. Production-grade changes migrations se hote hain (`out` folder). 6.13.3 mein Prisma migrate wala system milega.
