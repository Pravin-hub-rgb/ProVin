# Drizzle Schema + Client — Data Ka Blueprint (SQL Version)

## Pehle Schema Kyun?

Database use karne ke liye ek **connection file** banani hai (`db/index.ts`) — jo Neon se connect karegi aur `db` variable export karegi. Par woh connection file **schema import** karegi — taaki Drizzle ko pata ho table ka structure kya hai:

```
db/index.ts → schema import karega → db/schema.ts
```

Toh pehle schema (table structure), phir connection file — ek baar mein complete.

## `db/` Folder Kyun, `lib/` Kyun Nahin?

Mongo mein `lib/mongodb.ts` banayi thi (`lib/` = general helpers). **`db/` specifically database ke liye** — schema + connection, dono yahan. Drizzle community mein yahi convention hai. Project root mein banao (jahan `app/` hai):

```
sql-todo/
├── app/
├── db/              ← naya folder
├── .env
└── package.json
```

## `db/schema.ts` — Table Define Karna

6.9 mein test connection mein raw SQL likhi thi. Ek table ka SQL structure aisa hota hai:

```sql
CREATE TABLE drizzle_todos (
  id    SERIAL   PRIMARY KEY,
  title TEXT     NOT NULL,
  done  BOOLEAN  DEFAULT false
);
```

Ab yahi cheez TypeScript mein — **Drizzle ke syntax mein**. Column types `drizzle-orm/pg-core` se aate hain (`pg` = PostgreSQL — Drizzle ka PostgreSQL wala part). Code se pehle concepts samjho:

**`pgTable`** — SQL ke `CREATE TABLE` ka Drizzle version — "ek PostgreSQL table define karo." Pehla argument table ka naam, doosra columns ka object.

**Column types:** `serial` — SQL ka `SERIAL` — auto 1, 2, 3... — id ke liye. `text` — SQL ka `TEXT` — string data. `boolean` — SQL ka `BOOLEAN` — true ya false.

**Table ka naam `drizzle_todos` kyun, `todos` kyun nahi?** Naam conflict se bachne ke liye — yaad hai 6.9 mein Neon mein manually tables banayi the? Agar Drizzle wali bhi `todos` rakhen toh `push` pe confusion — kaunsi table kisne banayi. `drizzle_todos` clear hai.

**Har field ka option:** `id` pe `.primaryKey()` — SQL `PRIMARY KEY` — auto-increment + unique identifier. `title` pe `.notNull()` — SQL `NOT NULL` — khaali nahi ho sakti. `done` pe `.default(false)` — SQL `DEFAULT false` — value na do toh `false`.

**`InferSelectModel` kya hai?** 6.5 mein `ITodo` interface **manually** likha tha. Problem: schema badla toh type alag se update karna padega — bhool gaye toh bug. `InferSelectModel` schema dekh ke **khud type nikaal deta hai** — schema badla, type auto-update.

Ab file banate hain — ek-ek line, taaki har line ka reason clear rahe. **File:** `db/schema.ts`

Pehle imports — charon column types (`pgTable`, `serial`, `text`, `boolean`) `drizzle-orm/pg-core` se aate hain (PostgreSQL wala part — upar wala concept), aur `InferSelectModel` type nikaalne wala helper core package se:

```ts
// db/schema.ts
import { pgTable, serial, text, boolean } from 'drizzle-orm/pg-core'
import { InferSelectModel } from 'drizzle-orm'
```

**Import column types** — charon types `drizzle-orm/pg-core` se (PostgreSQL wala part — upar wala concept). **`InferSelectModel` import** — type nikaalne wala helper core package se (6.5 ke manual interface ki jagah).

Ab table define karo — `pgTable('drizzle_todos', {...})` — database mein naam `drizzle_todos` (naam conflict wala reason). Andar har column ek-ek:

```ts
// db/schema.ts
import { pgTable, serial, text, boolean } from 'drizzle-orm/pg-core'
import { InferSelectModel } from 'drizzle-orm'

export const todos = pgTable('drizzle_todos', {    // NEW
```

**`pgTable('drizzle_todos', {...})`** — table define — database mein naam `drizzle_todos` (naam conflict wala reason). Andar har column ek-ek:

```ts
// db/schema.ts
import { pgTable, serial, text, boolean } from 'drizzle-orm/pg-core'
import { InferSelectModel } from 'drizzle-orm'

export const todos = pgTable('drizzle_todos', {
  id: serial('id').primaryKey(),                   // NEW
```

**`serial('id').primaryKey()`** — SQL `id SERIAL PRIMARY KEY` — auto 1, 2, 3... + unique identifier. `'id'` column ka naam.

```ts
// db/schema.ts
import { pgTable, serial, text, boolean } from 'drizzle-orm/pg-core'
import { InferSelectModel } from 'drizzle-orm'

export const todos = pgTable('drizzle_todos', {
  id: serial('id').primaryKey(),
  title: text('title').notNull(),                  // NEW
```

**`text('title').notNull()`** — SQL `title TEXT NOT NULL` — string, khaali nahi ho sakti.

```ts
// db/schema.ts
import { pgTable, serial, text, boolean } from 'drizzle-orm/pg-core'
import { InferSelectModel } from 'drizzle-orm'

export const todos = pgTable('drizzle_todos', {
  id: serial('id').primaryKey(),
  title: text('title').notNull(),
  done: boolean('done').default(false).notNull(),  // NEW
})
```

**`boolean('done').default(false).notNull()`** — SQL `done BOOLEAN DEFAULT false` — value na do toh `false`.

Ab type nikaalo — `InferSelectModel` schema dekh ke khud type bana deta hai — 6.5 mein manually interface likhna padta tha, yahan schema khud nikaal deta hai:

```ts
// db/schema.ts
import { pgTable, serial, text, boolean } from 'drizzle-orm/pg-core'
import { InferSelectModel } from 'drizzle-orm'

export const todos = pgTable('drizzle_todos', {
  id: serial('id').primaryKey(),
  title: text('title').notNull(),
  done: boolean('done').default(false).notNull(),
})

export type Todo = InferSelectModel<typeof todos>  // NEW
```

**`export type Todo = InferSelectModel<typeof todos>`** — schema se automatic type — 6.5 mein manually interface likhna padta tha, yahan schema khud nikaal deta hai.

Internally `Todo` banta hai:

```ts
type Todo = {
  id: number      // serial → number
  title: string   // text → string
  done: boolean   // boolean → boolean
}
```

Compare karo 6.5 ke saath — manually interface vs schema-derived:

```ts
// 6.5 MongoDB — manually interface
interface ITodo {
  _id: string
  title: string
  done: boolean
}

// 6.10 Drizzle — schema se automatic
export type Todo = InferSelectModel<typeof todos>
```

## `db/index.ts` — Connection + Db Client

**Kyun chahiye?** Next.js mein kai jagah database use karni hai (page, actions). Har jagah seedha Neon se connect karein toh har file mein same connection code — repetition. **Ek jagah connection banao — sab jagah se import karo.** Yahi `db/index.ts` ka kaam hai.

Teen cheezein samjho pehle:

**Raw connection (`neon`)** — 6.9 wala wahi function — `neon(process.env.DATABASE_URL!)` connection string se raw Neon connection banata hai. `!` — TypeScript ko guarantee: "`.env` mein definitely hai, undefined nahi".

**`import * as schema`** — schema.ts ki saari exports ek saath `schema` object mein (`schema.todos`, `schema.Todo`). Drizzle ko isi se types pata chalti hain.

**`drizzle()` ek function hai jiske do arguments hain:**
- **Pehla argument = connection** (`sql`) — *database se kaise baat karni hai* — kaunsa driver, kahan connect. Yeh 6.9 wala raw Neon connection.
- **Doosra argument = ek config object** (`{ schema }`) — *database mein kya-kya hai* — kaunsi tables, kaunse types. Drizzle isi se queries type-safe banata hai.

Result ek **`db` client object** hai — jiske andar query methods hain (`db.select()`, `db.insert()`). Aur isi ko **`export const db`** se export karenge — har jagah import.

Aur ek import ka sawaal — **`drizzle-orm/neon-http` kyun, seedha `drizzle-orm` kyun nahi?** Drizzle ke andar alag databases ke liye alag connectors hain:

```
drizzle-orm/neon-http    ← Neon ke liye
drizzle-orm/postgres-js  ← local PostgreSQL ke liye
drizzle-orm/mysql2       ← MySQL ke liye
```

Hum Neon use kar rahe hain — toh `neon-http` wala.

Ab file banate hain — ek-ek line, taaki har line ka reason clear rahe. **File:** `db/index.ts`

Pehle imports — `neon` raw connection ke liye (6.9 mein dekha tha), `drizzle` Neon connector se (`neon-http` upar wala reason), aur `* as schema` schema.ts ki saari exports ek saath import karta hai (sirf `todos` nahi — bhaavi nayi tables bhi isi se aayengi):

```ts
// db/index.ts
import { neon } from '@neondatabase/serverless'
import { drizzle } from 'drizzle-orm/neon-http'
import * as schema from './schema'
```

**`neon` import** — raw connection ke liye (6.9 mein dekha tha). **`drizzle` import** — Neon connector se — upar wala reason (`neon-http`). **`* as schema`** — schema.ts ki saari exports ek saath import karo (sirf `todos` nahi — bhaavi nayi tables bhi isi se aayengi).

Ab raw connection banao — `neon(process.env.DATABASE_URL!)` connection string se (`.env` se):

```ts
// db/index.ts
import { neon } from '@neondatabase/serverless'
import { drizzle } from 'drizzle-orm/neon-http'
import * as schema from './schema'

const sql = neon(process.env.DATABASE_URL!)    // NEW
```

**`const sql`** — raw connection banaya (connection string `.env` se).

Ab usse Drizzle client banao — `drizzle()` function ke do arguments: pehla `sql` (connection — database se kaise baat karni hai), doosra `{ schema }` (config object — database mein kya-kya hai). Result `db` client — `export const db` se har jagah import karenge: `db.select()`, `db.insert()`, etc.:

```ts
// db/index.ts
import { neon } from '@neondatabase/serverless'
import { drizzle } from 'drizzle-orm/neon-http'
import * as schema from './schema'

const sql = neon(process.env.DATABASE_URL!)

export const db = drizzle(sql, { schema })    // NEW
```

**`export const db`** — `drizzle()` function ka result. Pehla argument `sql` = connection (database se kaise baat karni hai). Doosra `{ schema }` = config object — **poora schema kyun?** Kyunki `* as schema` ne saari exports ek object mein daal di hain (table definitions + types) — Drizzle ko poora model do taaki:
- **Types check hongi** — `db.select().from(todos)` pe TypeScript ko pata hai `todos` ki columns kya hain, kya value sahi hai (6.11.1 mein dikhega).
- **Nayi tables future mein auto-available** — aage `users` table banayi toh `schema` object mein khud aa jaayegi — is file mein kuch nahi badlega.
- **Relational queries (`db.query`)** — Drizzle ka relational API isi schema se chalta hai (6.13.4 mein Prisma `include` jaisa — Drizzle mein `db.query.todos.findMany()`).

Sirf `todos` pass karte toh Drizzle ko ek table hi pata hota — poora schema pass karo toh pura model registered hai.

**MongoDB se compare** (6.4 wala `lib/mongodb.ts`):

```ts
// 6.4 MongoDB — lib/mongodb.ts
// async/await + readyState check karna padta tha
async function connectDB() {
  if (mongoose.connection.readyState === 1) return
  await mongoose.connect(MONGODB_URI)
}

// 6.10 Drizzle — db/index.ts
// Neon serverless hai — har query pe auto connect — 3 lines
const sql = neon(process.env.DATABASE_URL!)
export const db = drizzle(sql, { schema })
```

Mongo connection persistent hota tha (ek baar connect, reused). Neon serverless hai — queries apne aap connect/disconnect karta hai — isliye `db` direct export hota hai, `connectDB()` await ki zaroorat nahi.

## `drizzle.config.ts` — Drizzle-kit Ko Sab Batana

`drizzle-kit` ko abhi kuch pata nahi: "schema file kahan hai? kaunsa database? connect kaise?" — sab config file mein batate hain. Char options:

**`schema`** — schema file kahan hai (table structure — `./db/schema.ts`).
**`out`** — migrations kahan save karein (`drizzle/` folder — `drizzle-kit` khud banayega).
**`dialect: 'postgresql'`** — kaunsa database (Drizzle MySQL/SQLite/PostgreSQL sab support karta hai — hum `postgresql`).
**`dbCredentials.url`** — Neon se connect ke liye connection string (table banane ke liye).

Ab file banate hain — ek-ek line, taaki har line ka reason clear rahe. **File:** `drizzle.config.ts` (project root — `drizzle-kit` command chalaate waqt automatically root mein dhundhta hai)

Pehle `defineConfig` import — **`defineConfig` ek function hai** — config object leta hai (argument), aur usi ko typed config return karta hai (drizzle-kit ke liye). Iske baare mein sirf itna jaan lo ki config ko drizzle-kit samajh paaye:

```ts
// drizzle.config.ts
import { defineConfig } from 'drizzle-kit'
```

**`defineConfig` import** — function hai: ek config object argument leta hai, typed config return karta hai — `drizzle-kit` ise padhta hai. Ab config object banao — `defineConfig({...})` — andar char options ek-ek:

```ts
// drizzle.config.ts
import { defineConfig } from 'drizzle-kit'

export default defineConfig({                   // NEW
```

**`export default defineConfig({...})`** — config object — andar char options.

Pehla — `schema` — table structure kahan hai:

```ts
// drizzle.config.ts
import { defineConfig } from 'drizzle-kit'

export default defineConfig({
  schema: './db/schema.ts',                     // NEW
```

**`schema`** — schema file kahan hai (table structure).

Doosra — `out` — migrations kahan save karein (`drizzle/` folder — `drizzle-kit` khud banayega):

```ts
// drizzle.config.ts
import { defineConfig } from 'drizzle-kit'

export default defineConfig({
  schema: './db/schema.ts',
  out: './drizzle',                             // NEW
```

**`out`** — migrations kahan save karein (`drizzle/` folder — `drizzle-kit` khud banayega).

Teen — `dialect` — kaunsa database — `postgresql` (Drizzle MySQL/SQLite/PostgreSQL sab support karta hai):

```ts
// drizzle.config.ts
import { defineConfig } from 'drizzle-kit'

export default defineConfig({
  schema: './db/schema.ts',
  out: './drizzle',
  dialect: 'postgresql',                        // NEW
```

**`dialect`** — kaunsa database — `postgresql` (Drizzle MySQL/SQLite/PostgreSQL sab support karta hai).

Aur last — `dbCredentials.url` — Neon se connect ke liye connection string (table banane ke liye). `!` — TypeScript ko guarantee — `.env` mein definitely hai:

```ts
// drizzle.config.ts
import { defineConfig } from 'drizzle-kit'

export default defineConfig({
  schema: './db/schema.ts',
  out: './drizzle',
  dialect: 'postgresql',
  dbCredentials: {                              // NEW
    url: process.env.DATABASE_URL!,
  },
})
```

**`dbCredentials.url`** — Neon se connect ke liye connection string (table banane ke liye). `!` — TypeScript ko guarantee — `.env` mein definitely hai.

> **Migration kya hota hai?** Aaj table banayi. Kal naya column chahiye (`createdAt`). Database mein table pehle se hai — seedha nahi badal sakte. Pehle ek "change record" banate hain (migration file), phir apply karte hain. `drizzle-kit` yeh files `drizzle/` folder mein save karta hai. Production mein yehi system hai — schema changes track hote hain. (Detail 6.13.3 mein — abhi bas idea.)

## Neon Mein Table Banao — `npx drizzle-kit push`

Ab Neon mein actual table banani hai. Pehle samjho — **`npx` kya hai?** Installed packages ko terminal se run karta hai (yaad hai `npx create-next-app`? wahi). Yehi se `drizzle-kit` chalega.

Aur command ke peeche kya hoga? `drizzle.config.ts` padha → schema file padhi → Neon se connect kiya → check kiya "drizzle_todos table pehle se hai?" → nahi thi toh `CREATE TABLE` SQL khud chala di. Ab terminal mein:

```bash
npx drizzle-kit push
# bun users ke liye (6.4 me dekha tha) — same command, bun se:
bunx drizzle-kit push
```

Terminal mein: `[✓] Changes applied`. Neon dashboard mein "Tables" → `drizzle_todos` dikhegi.

> **Ek asaan galti (aage se bachna):** `DATABASE_URL` ko `.env` mein rakhna (Next.js aur drizzle-kit dono `.env` padhte hain), `.env.local` mein nahi. Kyun? Next.js (app) `.env.local` padhta hai, par **drizzle-kit ka apna dotenv sirf `.env` padhta hai**. `.env` mein rakho toh dono ko milti hai — ek jagah, dono kaam. Agar error aaye — "Either connection url or host, database are required" — toh iska matlab drizzle-kit ko `DATABASE_URL` nahi mili (sirf `.env.local` mein thi). Fix: `.env` file mein wahi connection string daalo.

## Nutshell

Drizzle mein: `db/schema.ts` mein `pgTable` + column types (serial/text/boolean) se table define hoti hai, `InferSelectModel` type nikaalta hai. `db/index.ts` mein `neon()` connection + `drizzle(sql, { schema })` se `db` client milta hai (Mongo ke `connectDB` se simpler). `drizzle.config.ts` kit ko batata hai kaunsi file/kaunsa DB. `npx drizzle-kit push` Neon mein actual table banata hai.

## What It Is NOT

- **`pgTable` = database mein table banana nahi.** `pgTable` sirf TypeScript definition hai. Asli table Neon mein `drizzle-kit push` se banti hai. Bina push ke app chalao toh error — "relation does not exist".
- **`InferSelectModel` = "magic type" nahi.** Yeh schema ke columns dekh ke ek type generate karta hai — convenience hai, magic nahi. `number`/`string`/`boolean` — yahi toh banega.
- **`db` = connection nahi.** `db` Drizzle ka client object hai jiske andar query methods hain (`db.select()`, `db.insert()`) — inhi se tum queries likhte ho. Connection neeche `sql` hai. User `db` hi use karega — `sql` seedha nahi.
- **`drizzle.config.ts` = runtime code nahi.** Yeh sirf `drizzle-kit` (dev tool) ke liye hai — app ke andar import nahi hota. Isliye `drizzle-kit` production dependency nahi, dev dependency hai.
- **`npx drizzle-kit push` = production migration tool nahi.** `push` dev mein quick sync ke liye hai. Production-grade changes migrations se hote hain (`out` folder). 6.13.3 mein Prisma migrate wala system milega.
