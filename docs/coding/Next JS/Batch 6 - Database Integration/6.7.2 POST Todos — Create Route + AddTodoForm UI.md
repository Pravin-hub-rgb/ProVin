# POST /api/todos — Create Route + AddTodoForm UI

## Step 1 — Route: Naya Todo Banana

**SOCH:** Ab data **bhejna** hai — frontend se naya todo aata hai (`{ title: "..." }`), use database mein save karna hai. Yahan request body read karni padti hai — POST mein data `request` ke andar hota hai.

**CONCEPT:** POST mein data **aata** hai — frontend bhejta hai `{ title: "..." }`. Yahan ek naya concept aata hai: **request body**. Problem-first:

**Sawaal 1 — data kaise aayega?** GET mein kuch bhejna nahi tha — isliye function ka koi parameter nahi tha. POST mein data **request ke andar** hota hai. Network pe woh ek text hota hai (JSON string). `request.json()` us text ko **JavaScript object** mein convert karta hai. Isliye POST function ko `request: NextRequest` parameter chahiye, aur `NextRequest` import add karna padega (6.7.1 mein sirf `NextResponse` tha).

**Sawaal 2 — bina title wala todo?** Data mil gaya, par quality check: agar `title` hi nahi hai, ya khali hai, ya sirf spaces hain (`"   "`) — toh bekaar todo banega. Aisa todo mat banao. Validation — `!title || title.trim() === ""` pe reject, **400** ke saath. 400 = client ki galti (6.6 design — galat body = 400).

**Sawaal 3 — save kaise karenge?** `Todo.create({...})` — naya document banata aur save karta hai ek saath. `create` pe schema ki validation apply hoti hai (6.5 — required/default checks). **`title.trim()`** — aage-peeche spaces hata ke (schema mein bhi `trim: true` hai — double layer). **`done: false`** explicit — naya todo hamesha pending se shuru (schema default bhi hai, par explicit likhne se intention clear).

**Sawaal 4 — status code?** Naya resource **bana** — **201 Created** (6.6 design). GET success 200 tha, create success 201 — dono alag kyunki 201 clearly batata hai "naya cheez create hui".

```ts
// app/api/todos/route.ts
import { NextRequest, NextResponse } from "next/server";
import { connectDB } from "@/app/lib/db";
import Todo from "@/app/models/Todo";

export async function GET() {
  try {
    await connectDB();
    const todos = await Todo.find().sort({ createdAt: -1 });
    return NextResponse.json(todos, { status: 200 });
  } catch (error) {
    console.error("Todos fetch error:", error);
    return NextResponse.json({ error: "Todos fetch nahi ho sake" }, { status: 500 });
  }
}

export async function POST(request: NextRequest) {
  try {
    await connectDB();

    const body = await request.json();
    const { title } = body;

    if (!title || title.trim() === "") {
      return NextResponse.json({ error: "Title dena zaroori hai" }, { status: 400 });
    }

    const newTodo = await Todo.create({
      title: title.trim(),
      done: false,
    });

    return NextResponse.json(newTodo, { status: 201 });
  } catch (error) {
    console.error("Todo create error:", error);
    return NextResponse.json({ error: "Todo create nahi ho saka" }, { status: 500 });
  }
}
```

Upar wala code wahi hai — upar import line mein `NextRequest` juda, aur neeche `POST` function. POST line-by-line:

- **`import { NextRequest, NextResponse }`** — `NextRequest` Sawaal 1 ka jawab. POST mein request read karni hai, isliye `NextRequest` type chahiye. `NextResponse` wahi raha. (Baaki imports — `connectDB` (6.4) aur `Todo` (6.5) — wahi, naya kuch nahi.)
- **`export async function POST(request: NextRequest)`** — naya function, naam = HTTP method. `request` parameter — data iske andar aayega (Sawaal 1).
- **`try` + `await connectDB()`** — wahi pattern — pehle connection ready, phir kaam.
- **`await request.json()`** — request body read karo (Sawaal 1). Network pe data text hai — `json()` usse JS object banata hai. `await` — data aane mein time lagta hai.
- **`const { title } = body`** — destructuring — `body.title` ko `title` naam de rahe hain (Batch 3 ka pattern).
- **Validation — 400** — missing title, khali title, ya spaces-only title — sab reject (Sawaal 2). `{ error }` JSON + 400 — client ki galti.
- **`Todo.create({...})`** — banao + save (Sawaal 3). `title.trim()` — spaces hata ke; `done: false` — naya todo pending se shuru.
- **`{ status: 201 }`** — Created (Sawaal 4). Response mein saved document — `_id`, timestamps ke saath (6.5 se yaad hai).
- **`catch` + 500** — wahi pattern — error pe server-side log + 500.

## Step 2 — UI: AddTodoForm Component

**SOCH:** User ko ek form chahiye — text input + submit button. Jab wo submit kare, `fetch` POST `/api/todos` pe jaaye, naya todo bane. **Aur sabse important:** naya todo list mein dikhe bhi — isliye form ko `TodoApp` ko bataana padega ki "naya todo ban gaya, list refresh karo."

**CONCEPT:** Batch 3.1 mein `CommentForm` aur `ShowComments` alag components the, aur wahan POST ke baad list refresh hone mein problem thi — `useEffect([])` sirf mount pe chalta hai, naya data khud nahi dikhta tha. Wahi problem yahan bhi aayegi. Iska saaf solution: **form khud data na rakhe — submit karne ke baad `TodoApp` ko call kare, aur `TodoApp` list refresh kare.** Kyonki data ka asli owner `TodoApp` hai (6.7.1 mein decide kiya tha — "brain"). Problem-first:

**Sawaal 1 — form ka data kaun rakhega?** Form mein text input hai — uska value chahiye. `useState` se `title` state rakhenge (React ka standard controlled input pattern). Par yeh state **sirf form ki apni** hai — list ka data nahi. Form ka kaam: user jo likhe woh dikhna + submit pe bhejna.

**Sawaal 2 — submit pe kya hoga?** `onSubmit` handler: `fetch("/api/todos", { method: "POST", headers, body })`. POST mein body bhejni hoti hai — `JSON.stringify({ title })` se object → JSON string, aur `Content-Type: application/json` header batata hai ki body JSON hai.

**Sawaal 3 — form ka data `TodoApp` tak kaise pahuncha?** Form `TodoApp` se ek function **props mein** leta hai — `onAdd(title)`. Form submit kare → `onAdd(title)` call kare → `TodoApp` ka `addTodo` function chale. Yeh wahi pattern hai jo kisi bhi React app mein parent-child communication ka hota hai — **child apna kaam karta hai, par data change parent ke through**.

**Sawaal 4 — POST ke baad list refresh kaise? (asli sawaal)** `TodoApp` ka `addTodo`: pehle POST bhejo, phir **`loadTodos()` wapas call karo** — wahi function jo 6.7.1 mein mount pe chalta tha. Kyunki `loadTodos` `fetch("/api/todos")` karta hai, dobara call karne se **server se fresh list aati hai** — naya todo bhi shamil. Yeh "server se re-fetch" pattern hai: **mutation ke baad server hi source of truth hai, fresh data usi se laao.** (Local state mein khud se item jodne ke bajaye — kyunki server ne `_id`/timestamps add kiye, aur future mein order/sort bhi server decide karta hai.)

**Sawaal 5 — `res.ok` check aur `AddTodoForm` ka `"use client"`?** `AddTodoForm` mein hooks hain (`useState`, event handlers) — isliye `"use client"` chahiye. Aur `fetch` errors pe `res.ok` check karenge — wahi pattern jo `loadTodos` mein tha (6.7.1).

```tsx
"use client";

import { useState } from "react";

export default function AddTodoForm({
  onAdd,
}: {
  onAdd: (title: string) => void;
}) {
  const [title, setTitle] = useState("");

  const handleSubmit = async (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    if (!title.trim()) return;
    onAdd(title);
    setTitle("");
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={title}
        onChange={(e) => setTitle(e.target.value)}
        placeholder="Naya todo..."
      />
      <button type="submit">Add</button>
    </form>
  );
}
```

Upar wala code wahi hai — neeche ab `handleSubmit` aur form juda. Line-by-line:

- **`handleSubmit`** — line-by-line:
  - `e.preventDefault()` — **form ka default behavior roko.** Bina iske submit pe page reload ho jaata hai (browser ka default) — hum chahte hain JavaScript handle kare, page reload na ho
  - `if (!title.trim()) return` — khali/space-only title = submit mat karo (client-side bhi wahi validation — pehle hi roko, server pe 400 jaane se pehle)
  - `onAdd(title)` — asli kaam: `TodoApp` ka `addTodo` function call (Sawaal 3)
  - `setTitle("")` — input saaf karo (user agla todo likh sake)
- **Form JSX** — `onSubmit={handleSubmit}` se form ke submit pe handler chalta hai. **`input`** — `value` state se, `onChange` pe state update (controlled). **`button type="submit"`** — click karne pe form submit hota hai, jo `handleSubmit` ko trigger karta hai.

> **Notice:** `AddTodoForm` mein **koi `fetch` nahi** hai! Form sirf `onAdd(title)` call karta hai. Fetch ka kaam `TodoApp` ka `addTodo` karega. Yeh intentional hai — form presentational hai, data logic parent mein (Sawaal 3).

## Nutshell

POST route: `request.json()` se body read, `!title || title.trim() === ""` pe 400, `Todo.create({ title: title.trim(), done: false })` se save, **201 Created**. UI: `AddTodoForm` (client) controlled input se title leta hai, submit pe `onAdd(title)` call karta hai. `TodoApp` ka `addTodo` POST bhejta hai, phir **`loadTodos()` re-fetch** — mutation ke baad server se fresh list. Data flow ek loop: form → onAdd → POST → re-fetch → render.

## What It Is NOT

- **`AddTodoForm` mein `fetch` mat rakho** — form ka kaam input + submit call hai, data logic `TodoApp` mein. Yeh split hi hai jo code clean rakhta hai.
- **`e.preventDefault()` optional nahi** — bina iske page reload ho jaata hai, React state sab reset, aur form ka data khud query param ban jaata hai. Form handle karne pe hamesha pehli line.
- **`res.ok` check POST mein bhi zaroori** — 400 (khali title) aur 500 dono `fetch` mein resolve hoti hain. Check na ho toh galat flow.
- **"POST ke baad local state mein add karna" = sahi shortcut nahi** — server `_id`/timestamps deta hai aur order decide karta hai; local add se mismatch ho sakta hai. Server se re-fetch hi source of truth hai.
- **`JSON.stringify` = body "JSON jaisa dikhna" nahi** — object ko string banana hi hai, kyunki fetch ki body string maangti hai. Object seedha pass karoge toh `[object Object]` jaayega.

5. Agar user sirf spaces wala title submit kare — kya hoga, aur kahan roka jaayega?

<summary>Show Answer</summary>

**Sample Answer:** Do jagah rok hai. Client-side: `handleSubmit` mein `if (!title.trim()) return` — submit ho hi nahi (button click pe kuch nahi hota). Agar phir bhi request pahunch jaaye, server-side: route mein `!title || title.trim() === ""` → 400 `{ error }`. Client check UX ke liye (turant feedback), server check safety ke liye — client check bypass ho sakta hai, server check nahi.
