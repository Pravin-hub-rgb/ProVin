# MongoDB Atlas + Connection

## Step 1 — Project Aur Packages

Fresh practice project banao (jaise tumne 0.8 mein seekha):

```bash
npx create-next-app@latest mongo-todo
```

Options wahi jo 0.8 mein the — TypeScript, App Router, Tailwind, `src/` no.

Ab MongoDB ke liye package install karo:

```bash
npm install mongoose
```

**`mongoose`** — MongoDB ka ODM (6.3 mein discuss kiya) — connection banata hai, schema define karne deta hai, aur simple methods deta hai (`Todo.find()`, `Todo.create()`). Bina mongoose ke MongoDB se seedha baat karna low-level code hota hai (`MongoClient` + `collection.find()` manually) — mongoose woh boilerplate hata deta hai.

## Step 2 — MongoDB Atlas Setup

Ab ek free cloud MongoDB banao. Steps:

1. **https://www.mongodb.com/cloud/atlas** pe jao → "Try Free" → account banao (Google se bhi ho sakta hai)
2. **Cluster banana:** Login ke baad **"Create a Cluster"** → **Free** plan chuno (M0 — bilkul free, "For learning and exploring MongoDB") → cluster ka naam do (`todouser` ya jo chahte ho) → Provider/Region (Mumbai/Hyderabad agar option hai) → **"Create Deployment"** click karo. **Is waqt password field nahi aata** — username/password cluster banne ke baad milte hain.
3. **Credentials screen:** Cluster ban jaane ke baad **"Copy and save database user credentials"** screen aayegi — yahan teen cheezein milti hain:

```
MONGODB_USERNAME=""                     ← apna username
MONGODB_PASSWORD=""                     ← autogenerate hota hai, copy karke rakho (phir kabhi nahi dikhega)
MONGODB_URI="mongodb+srv://db_user:<password>@todouser.xxxxx.mongodb.net"
```

   `<password>` abhi placeholder hai — actual password Step 3 mein `.env.local` mein daalenge.
4. **Connect modal:** "Choose a connection method" → **"Connect to your application"** → **Drivers** chuno. Wahan **Node.js (4.0 or later)** select karke connection string copy karo:

```
mongodb+srv://<db_username>:<db_password>@todouser.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=todouser
```

   `<db_username>`/`<db_password>` ki jagah step 3 wale actual credentials daalne hain — Atlas ka copy button password placeholder hi chhodta hai.
5. **Network Access:** Connect modal ke Step 1 "Set up connection security" mein "Add My Current IP Address" — development ke liye "Allow Access from Anywhere" bhi okay hai.

> **Cluster kya hai?** MongoDB ka terminology — ek cluster ek server hai jahan tumhara database rehta hai. M0 Free ek shared server hai — free, chhote apps ke liye kaafi.

## Step 3 — `.env.local` — Secret Rakho, Code Mein Nahin

Connection string mein **password** hai. Ise code mein seedha nahi likh sakte — GitHub pe push karo toh duniya dekh legi, aur browser-side code mein ho toh koi bhi DevTools se dekh lega. Isliye **`.env.local`** — ek special file jo:

- `.gitignore` mein already listed hai — GitHub pe kabhi nahi jaati
- Sirf server-side code padh sakta hai
- Next.js automatically load karta hai

**File:** `.env.local` (project root, `package.json` ke paas)

```env
MONGODB_URI=mongodb+srv://todouser:TUMHARA_PASSWORD@todouser.xxxxx.mongodb.net/?retryWrites=true&w=majority
```

Atlas credentials screen mein `MONGODB_USERNAME`/`MONGODB_PASSWORD`/`MONGODB_URI` alag-alag milte hain — par hamara code sirf `MONGODB_URI` padhta hai, isliye username aur password dono ko URI ke andar `username:password` format mein daalo. Dhyan rakhna: username aur password actual credentials se badlo (URI mein `<password>` placeholder mat chhodo), `=` ke aage-peeche koi spaces nahi, quotes nahi.

Code mein access aise hota hai — **`process.env`** ek object hai Node.js mein jo saari environment variables rakhta hai:

```ts
process.env.MONGODB_URI
```

## Step 4 — Connection File — `lib/db.ts`

Ab connection ka code. **File:** `lib/db.ts` (nayi file — `lib/` wahi convention jo Batch 3 mein `lib/comments.ts` tha: baar-baar use hone wala code ek jagah).

Pehle samjho kya chahiye. MongoDB se connect karna hai — `mongoose.connect(uri)` se. Simple version:

```ts
// app/lib/db.ts
import mongoose from "mongoose";

await mongoose.connect(process.env.MONGODB_URI!);
```

**Problem isme — Next.js development mode.** Har code change pe dev server files ko reload karta hai (hot reload). Agar `connect()` har reload pe chale, toh baar-baar naye connections bante hain — **connection leak.** Asli duniya mein ek app ko ek hi baar connect hona chahiye, phir usi connection ko reuse karna chahiye.

**Solution — cached connection (singleton pattern).** Global scope mein ek variable rakho jo connect hone pe set ho jaaye, aur har call check kare ki pehle se connected toh nahi:

```ts
// app/lib/db.ts
import mongoose from "mongoose";

const cached = (global as any).mongoose || { conn: null, promise: null };

export async function connectDB() {
  if (cached.conn) return cached.conn;

  cached.promise = cached.promise || mongoose.connect(process.env.MONGODB_URI!);
  cached.conn = await cached.promise;
  return cached.conn;
}
```

Line by line:

- **`const cached = (global as any).mongoose || { conn: null, promise: null }`** — global scope mein ek cached object. `conn` = bana hua connection, `promise` = chal rahi connect process. Pehli baar `{}` milega.
- **`if (cached.conn) return cached.conn`** — agar connection pehle se hai, seedha return — dobara connect mat karo. **Yahi reuse hai.**
- **`cached.promise = cached.promise || mongoose.connect(...)`** — agar connect process pehle se shuru hai toh use karo, warna shuru karo. `||` isliye kyunki do calls ek saath aaye toh dono alag connect na banayen.
- **`cached.conn = await cached.promise`** — connect complete hone ke baad conn set karo.
- **`(global as any)`** — `global` Node.js ka built-in global object hai. `as any` isliye kyunki hum custom property (`mongoose`) daal rahe hain jo TypeScript ke type mein nahi hai. (Aage 6.13 mein proper typed version dekhenge.)

> **Nutshell:** Singleton pattern — connection pehli baar banate hain, global scope mein cache karte hain, aur har aage wali call wahi cached connection reuse karti hai. Next.js ke hot reload mein baar-baar connect hone se bachata hai.

## Step 5 — Test — Connection Verify

Ab connection ko test karo. `npm run dev` chalao, aur `app/page.tsx` mein pehle temporary test:

```tsx
// app/page.tsx
import { connectDB } from "../lib/db";

export default async function Home() {
  await connectDB();
  return <h1>Connected to MongoDB</h1>;
}
```

Browser mein `http://localhost:3000` kholo — agar "Connected to MongoDB" dikha, connection kaam kar raha hai. Agar error aaya (jaise `MongoParseError` ya network error) — check karo:

- Connection string mein `<password>` aur username actual credentials se badle hain? (Atlas ka copy button `<db_password>` placeholder hi chhodta hai)
- `.env.local` mein `MONGODB_URI` single line hai — koi spaces/quotes nahi, username:password dono URI ke andar?
- Atlas mein Network Access mein IP allowed hai?

**Important:** Yeh test page abhi sirf verification ke liye hai. Connection code `connectDB()` hi hai jo baar-baar use hoga — page ke andar ka test code agle steps mein hat jayega (sirf samajhne ke liye tha).

## Nutshell

MongoDB Atlas cloud pe MongoDB host karta hai (free M0 cluster). Connection string — jisme password hota hai — `.env.local` mein rakhi jaati hai. `lib/db.ts` mein singleton pattern se `connectDB()` ek baar connect karta hai aur global cache se reuse karta hai — Next.js ke hot reload mein connection leak se bachata hai.

## What It Is NOT

- **`.env.local` ≠ app ke code ka hissa.** Yeh secret config file hai jo `.gitignore` mein hai — GitHub pe nahi jaati, sirf server-side padhti hai. Code seedha connection string paste karna galat hai.
- **`connectDB()` har request pe call hona = har baar connect hona nahi.** Singleton cache ki wajah se connection ek hi baar banta hai, baaki calls reuse karte hain. Function baar-baar call hota hai, connection nahi.
- **M0 Free cluster = production database nahi.** Shared server hai, free — practice ke liye perfect, production scale ke liye nahi.
- **`(global as any)` = sloppy code nahi.** Global cache ka pattern hai — TypeScript ke type system mein custom global property nahi hoti, isliye `as any` temporary hai. 6.13 mein typed version milega.
