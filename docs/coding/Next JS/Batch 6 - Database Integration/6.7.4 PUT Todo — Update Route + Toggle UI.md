## Step 1 — Route: Todo Update Karna

**SOCH:** Ab update — todo ka `done` toggle karna ho ya `title` badalna ho. 6.6 mein decide kiya tha PUT use karenge. Same dynamic route pe PUT function add karna hai.

**CONCEPT:** Update ka sawaal — todo ka `done` toggle karna ho ya `title` badalna ho. 6.6 mein decide kiya tha **PUT** use karenge. Update mein do cheezein chahiye: **kaunsa todo** (id — Step 3 wala dynamic route) aur **kya update** (data — body mein). Problem-first:

**Sawaal 1 — data kahan se?** PUT mein bhi body aati hai (naya title, naya done) — isliye `NextRequest` wapas chahiye, bilkul POST jaisa (6.7.2). `request.json()` se `{ title, done }` nikalte hain.

**Sawaal 2 — update kaise karein?** `Todo.findByIdAndUpdate(id, updateData)` — id se dhoondho, data update karo. Do arguments: pehla **kiski** (id), dusra **kya** (`{ title: ..., done }`).

**Sawaal 3 — `{ new: true }` kyun? (gotcha!)** Yeh sabse tricky part hai. Bina iske `findByIdAndUpdate` **purana (pre-update) document return karta hai** — update se pehle wala data. User ko lagta hai update fail ho gaya, jabki database mein update ho chuka tha. **`{ new: true }`** bataata hai: "updated document return karo." Isliye teen arguments: id, updateData, options. `{ new: true }` hi is method ka sabse common bug hai.

**Sawaal 4 — galat id?** Step 3 jaisa — `null` → **404**. Aur success pe **200 + updated document**.

## Step 2 — UI: Checkbox Toggle

**SOCH:** User ko ek checkbox chahiye — tick = todo done, untick = pending. Click karne pe `PUT /api/todos/[id]` bhejna hai `{ done: !todo.done }` ke saath — jo bhi abhi hai usse **ulta** karo (toggle). Checkbox kahan hoga? `TodoItem` mein — kyunki wo har todo ko jaanta hai (6.7.3 mein wahi bana).

**CONCEPT:** Socho ek light switch — click karne pe on/off hota hai, jo bhi state thi usse invert karta hai. Checkbox bhi wahi hai — har click pe `done` ka **opposite** chahiye. Problem-first:

**Sawaal 1 — checkbox ki value kaise bind karein?** `<input type="checkbox" checked={todo.done}>` — `checked` prop todo ki `done` field se. Jab bhi list refresh hoti hai (`loadTodos`), server ka naya `done` dikhega — checkbox **server state ka mirror** hai.

**Sawaal 2 — click pe kya bhejna?** `PUT` body mein `{ done: !todo.done }` — **toggle**. Abhi `false` hai toh `true` bhejo, `true` hai toh `false`. Aur title? PUT full update hai (6.6) — title bhi bhejna hoga (rename change ho sakta hai aage). Body: `{ title: todo.title, done: !todo.done }` — pura todo ka data, sirf `done` flipped.

**Sawaal 3 — onChange kyun (onClick nahi)?** Checkbox pe change event hota hai jab value toggle hoti hai. `onChange={() => onToggle(todo)}` — har tick/untick pe chalta hai. (OnClick checkbox pe tricky hota hai — onChange hi standard tarika hai.)

**Sawaal 4 — PUT route `id` kaise use karega?** Wahi dynamic route pattern — `[id]` folder (6.7.3) — `context.params` se id. `TodoApp` ka `toggleDone(id, todo)` fetch ke URL mein id daalega — `` `/api/todos/${id}` ``.

**Sawaal 5 — toggle ke baad list refresh?** Wahi pattern — fetch ke baad `loadTodos()` — 6.7.2 (add) aur 6.7.3 (delete) mein same. Ab ek pattern ban chuka hai: **har mutation ke baad server se re-fetch.** Isi liye 6.7.1 mein `loadTodos` ko alag function banaya tha — ab teen jagah use ho raha hai.

```ts
import { NextRequest, NextResponse } from "next/server";
import { connectDB } from "@/app/lib/db";
import Todo from "@/app/models/Todo";

export async function GET() {
  try {
    await connectDB();
    const todos = await Todo.find().sort({ createdAt: -1 });
    return NextResponse.json(todos, { status: 200 });
  } catch (error) {
    console.error("Todos fetch error:", error);
    return NextResponse.json({ error: "Todos fetch nahi ho sake" }, { status: 500 });
  }
}

export async function POST(request: NextRequest) {
  try {
    await connectDB();

    const body = await request.json();
    const { title } = body;

    if (!title || title.trim() === "") {
      return NextResponse.json({ error: "Title dena zaroori hai" }, { status: 400 });
    }

    const newTodo = await Todo.create({
      title: title.trim(),
      done: false,
    });

    return NextResponse.json(newTodo, { status: 201 });
  } catch (error) {
    console.error("Todo create error:", error);
    return NextResponse.json({ error: "Todo create nahi ho saka" }, { status: 500 });
  }
}
```

```tsx
      const res = await fetch("/api/todos", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ title }),
      });
      if (!res.ok) throw new Error("Create failed");
      await loadTodos();
    } catch {
      setError("Todo create nahi ho saka");
    }
  };

  const deleteTodo = async (id: string) => {
    try {
      const res = await fetch(`/api/todos/${id}`, {
        method: "DELETE",
      });
      if (!res.ok) throw new Error("Delete failed");
      await loadTodos();
    } catch {
      setError("Todo delete nahi ho saka");
    }
  };

  const toggleDone = async (todo: Todo) => {
    try {
      const res = await fetch(`/api/todos/${todo._id}`, {
        method: "PUT",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ title: todo.title, done: !todo.done }),
      });
      if (!res.ok) throw new Error("Update failed");
      await loadTodos();
    } catch {
      setError("Todo update nahi ho saka");
    }
  };

  useEffect(() => {
    loadTodos();
  }, []);

  return (
    <div>
      <h1>Todo List</h1>
      <AddTodoForm onAdd={addTodo} />
      <TodoList
        todos={todos}
        loading={loading}
        error={error}
        onToggle={toggleDone}
        onDelete={deleteTodo}
      />
    </div>
  );
}
```

Data flow (ek loop):

```
UI action (add/delete/toggle) → TodoApp handler → fetch (POST/DELETE/PUT)
  → server (route → Mongoose → MongoDB) → response
  → loadTodos() re-fetch → fresh list → render → user naya state dekhta hai
```

---

## Nutshell

PUT route: same `[id]` dynamic route pe `PUT(request, context)` — `request.json()` se `{ title, done }`, `Todo.findByIdAndUpdate(id, { title, done }, { new: true })` — **`{ new: true }` updated document return karta hai** (bina iske purana milta — sabse common Mongoose bug), galat id → 404, success 200 + updated. UI: checkbox `checked={todo.done}` + `onChange={() => onToggle(todo)}` → `TodoApp.toggleDone` → PUT (done flipped) → `loadTodos()`. Pura CRUD UI se chal raha hai — database persist karta hai.

## What It Is NOT

- **`{ new: true }` = optional nahi.** Bina iske `findByIdAndUpdate` **purana** document return karta hai — updated nahi. Yehi sabse common bug hai. Naya document chahiye toh `{ new: true }` zaroori hai.
- **PUT ka body "sirf jo badla" nahi** — PUT **full update** hai (6.6). Toggle ke liye title bhi body mein bhejna pada (`{ title, done }`) kyunki PUT poori resource replace karta hai. Partial update ke liye PATCH hota — humne 6.6 mein decide kiya PUT kaafi hai.
- **Checkbox = "component ka apna state" nahi** — `checked={todo.done}` — server data ka mirror hai, component ki apni state nahi. Koi local `useState` nahi. Change → server → re-fetch → naya data render. Refresh pe bhi wahi rehta hai kyunki database store karta hai.
- **`onClick` checkbox pe standard nahi** — `onChange` use karo (value toggle hone pe chalta hai). `onClick` pe bhi chalta par edge cases (keyboard, label click) mein unpredictable.
- **Toggle = "sirf UI fancy" nahi** — yeh asli PUT request hai database pe. Isliye 6.8 mein Postman se bhi same route test hoga — wahi API jo UI use karta hai.

**In Your Own Words**

1. `Todo.findByIdAndUpdate(id, data, { new: true })` — `{ new: true }` kya kar raha hai, aur bina iske kya hoga?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `{ new: true }` updated document return karta hai. Bina iske Mongoose update ke **baad** nahi, **pehle** wala (purana) document return karta hai — matlab response mein purana data dikhega aur confusion hogi. Updated data chahiye toh `{ new: true }` option zaroori hai. Yehi method ka sabse common bug hai.

</details>

2. Checkbox ke `checked` mein `todo.done` use kiya — yeh "component ka apna state" kyun nahi hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Kyunki `checked` server data ka mirror hai — jo `loadTodos()` se aaya (`todos` state mein). Checkbox ka koi apna `useState` nahi. Jab tick karte ho → PUT → re-fetch → naya `todo.done` aata hai → `checked` update. Isliye refresh (`F5`) pe bhi checkbox wahi rehta hai — data database mein save hua, sirf UI state nahi jo reset ho jaati.

</details>

3. `onToggle` ko pura `todo` kyun diya (sirf `id` kyun nahi, jaise `onDelete` mein)?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Kyunki toggle ke liye `todo.done` ka **current value** chahiye — body mein `done: !todo.done` bhejna hai (flip). Sirf id se current done ka value nahi pata. Delete ko sirf id chahiye tha (kya delete karna = kaafi). Isliye `onDelete: (id) => void` aur `onToggle: (todo) => void` — har callback ko wahi do jo usko chahiye.

</details>

4. PUT mein body mein `title` bhi kyun bheja jab sirf `done` toggle karna tha?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Kyunki PUT **full update** hai (6.6 mein decide kiya) — poori resource ki value bhejte ho. Agar sirf `{ done: true }` bhejte toh server `title` ko undefined se overwrite kar deta (ya schema ki required validation fail hoti). Toggle `done` flip karta hai, par title wahi rehta hai — isliye dono body mein: `{ title: todo.title, done: !todo.done }`.

</details>

5. Tumne notice kiya ki add/delete/toggle — teeno ke baad `loadTodos()` call hota hai. Yeh pattern kya sikhaata hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Mutation ke baad **server se re-fetch** — server hi source of truth hai. Local state mein khud se update karne ki jagah, har change ke baad fresh data laao. Isliye hi `loadTodos` ko alag function banaya tha (6.7.1) — teen jagah reuse ho raha hai. Isse UI hamesha server ki real state dikhati hai, mismatch nahi hota.

</details>
