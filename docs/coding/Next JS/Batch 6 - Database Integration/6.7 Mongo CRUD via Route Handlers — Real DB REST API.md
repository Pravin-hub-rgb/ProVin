6.6 mein humne API design socha — resources, methods, status codes, error shape. Ab asli kaam: **Mongo Todo API** banayenge. Design ke hisaab se chaar endpoints chahiye:

- `GET /api/todos` — saare todos
- `POST /api/todos` — naya todo
- `PUT /api/todos/[id]` — update
- `DELETE /api/todos/[id]` — delete

Batch 3 mein tumne REST pattern (3.1) seekha tha — `route.ts` files, `NextResponse.json`, status codes. 6.7 mein wahi pattern ab **real database (Mongoose)** ke saath wapas aa raha hai — JSON file ki jagah MongoDB. Har step gradual, har step ke baad test.

# Mongo CRUD via Route Handlers

## Step 1 — GET: Saare Todos Fetch Karna

**SOCH:** Sabse basic — list dikhana. `/api/todos` pe GET aaye toh database se saare todos nikalo aur JSON mein bhejo. Model ready hai (6.5), connection ready hai (6.4) — bas jodna hai.

**CONCEPT:** `Todo.find()` — Mongoose method jo collection ke saare documents return karta hai. `.sort({ createdAt: -1 })` — newest pehle. `await connectDB()` pehle — connection ke bina query nahi chalegi.

**File:** `app/api/todos/route.ts` (nayi file)

```ts
// app/api/todos/route.ts
import { NextResponse } from "next/server";
import { connectDB } from "@/lib/db";
import Todo from "@/models/Todo";

export async function GET() {
  try {
    await connectDB();
    const todos = await Todo.find().sort({ createdAt: -1 });
    return NextResponse.json(todos, { status: 200 });
  } catch (error) {
    console.error("Todos fetch error:", error);
    return NextResponse.json({ error: "Todos fetch nahi ho sake" }, { status: 500 });
  }
}
```

Line by line:

- **`await connectDB()`** — 6.4 wala singleton connection. Har route pe call karte hain — connection ek hi banta hai, baaki reuse.
- **`await Todo.find()`** — saare todos. `.sort({ createdAt: -1 })` — `-1` matlab descending — naye pehle.
- **`NextResponse.json(todos, { status: 200 })`** — array JSON mein. GET successful = 200 (6.6 wala design).
- **`try/catch`** — database error aaye toh 500. `console.error` log karo debugging ke liye (server-side log — user ko nahi dikhta).

**TEST:** `npm run dev` chalao, browser mein `http://localhost:3000/api/todos` kholo. Agar database mein 6.5 ka "First real todo" hai, woh dikhna chahiye. Agar khali hai toh `[]`.

## Step 2 — POST: Naya Todo Banana

**SOCH:** Ab data **bhejna** hai — frontend se naya todo aata hai (`{ title: "..." }`), use database mein save karna hai. Yahan request body read karni padti hai — POST mein data `request` ke andar hota hai.

**CONCEPT:** `request.json()` — network pe data text travel karta hai, ise JavaScript object mein convert karta hai. `Todo.create({...})` — naya document banata aur save karta hai (6.5 mein dekha tha). Validation — bina title ke todo mat banao (400).

**File:** `app/api/todos/route.ts` (same file — GET ke neeche POST add karo)

```ts
// app/api/todos/route.ts
import { NextRequest, NextResponse } from "next/server";   // NEW: NextRequest
import { connectDB } from "@/lib/db";
import Todo from "@/models/Todo";

export async function GET() {
  // ... wahi jo Step 1 mein likha
}

export async function POST(request: NextRequest) {
  try {
    await connectDB();

    const body = await request.json();
    const { title } = body;

    if (!title || title.trim() === "") {
      return NextResponse.json({ error: "Title dena zaroori hai" }, { status: 400 });
    }

    const newTodo = await Todo.create({
      title: title.trim(),
      done: false,
    });

    return NextResponse.json(newTodo, { status: 201 });
  } catch (error) {
    console.error("Todo create error:", error);
    return NextResponse.json({ error: "Todo create nahi ho saka" }, { status: 500 });
  }
}
```

Line by line:

- **`request: NextRequest`** — `NextRequest` import add kiya (abhi sirf `NextResponse` tha). POST mein request chahiye kyunki data usme hota hai. GET mein nahi chahiye tha — sirf fetch karna tha.
- **`const { title } = body`** — destructuring — `body.title` ko `title` naam de rahe hain (Batch 3 ka pattern).
- **`if (!title || title.trim() === "")`** — validation. `""` ya `"   "` ya missing title — sab reject. **400** — client ki galti (6.6 design).
- **`Todo.create({ title: title.trim(), done: false })`** — save. `title.trim()` — aage-peeche spaces hatake (schema mein bhi `trim: true` hai, double layer). `done: false` explicit — naya todo hamesha pending se shuru (schema default bhi hai, par explicit clear hai).
- **`{ status: 201 }`** — Created — naya resource bana (6.6 design).

**TEST:** Abhi seedha browser se POST nahi kar sakte (browser GET karta hai). Postman 6.8 mein full testing milega — abhi ke liye chhota check. Terminal mein:

```bash
curl -X POST http://localhost:3000/api/todos -H "Content-Type: application/json" -d '{"title":"Test from curl"}'
```

Agar naya todo JSON mein wapas aaya — POST kaam kar raha hai. (curl terminal mein built-in hai.)

## Step 3 — DELETE: Ek Todo Hatana

**SOCH:** Ab delete — lekin kaunsa todo? **ID chahiye.** URL mein ID bhejte hain: `DELETE /api/todos/abc2` = "abc2 wala hatao." Isliye ek **dynamic route** chahiye — `[id]` folder.

**CONCEPT:** Dynamic route — folder ke naam mein square brackets = variable URL part. `app/api/todos/[id]/route.ts` sab `/api/todos/anything` handle karta hai. URL ka variable `context.params` se milta hai — aur **Next.js 15+ mein params async hai**, isliye `await context.params` karna padta hai (Batch 1 ka `params` pattern yaad hai — wahi).

**File:** `app/api/todos/[id]/route.ts` (nayi file — folder `[id]` banao)

```ts
// app/api/todos/[id]/route.ts
import { NextResponse } from "next/server";
import { connectDB } from "@/lib/db";
import Todo from "@/models/Todo";

export async function DELETE(
  _request: Request,
  context: { params: Promise<{ id: string }> }
) {
  try {
    await connectDB();
    const { id } = await context.params;

    const deleted = await Todo.findByIdAndDelete(id);

    if (!deleted) {
      return NextResponse.json({ error: "Todo nahi mila" }, { status: 404 });
    }

    return NextResponse.json({ message: "Todo delete ho gaya" }, { status: 200 });
  } catch (error) {
    console.error("Todo delete error:", error);
    return NextResponse.json({ error: "Todo delete nahi ho saka" }, { status: 500 });
  }
}
```

Line by line:

- **`context: { params: Promise<{ id: string }> }`** — URL ke variable parts. `/api/todos/abc2` → `params = { id: "abc2" }`. `Promise` isliye kyunki Next.js params async hai — `await` karna padta hai.
- **`Todo.findByIdAndDelete(id)`** — Mongoose method — id se dhoondh ke delete karta hai. Delete hone wala document return karta hai.
- **`if (!deleted)`** — id galat ho (todo exist nahi karta) toh `null` return hoga. **404** — resource nahi mila (6.6 design: galat id = 404, galat body = 400).
- **Success pe 200** — delete ke baad message. (Kuch APIs 204 No Content bhi dete hain — par message ke saath 200 humare design mein clear hai.)

**TEST:** 6.5 ka "First real todo" wala ID chahiye. Browser mein `/api/todos` kholo, kisi todo ka `_id` copy karo. Terminal mein:

```bash
curl -X DELETE http://localhost:3000/api/todos/<YOUR_ID>
```

`{ "message": "Todo delete ho gaya" }` dikhe — delete ho gaya. Browser mein `/api/todos` dobara kholo — woh todo gaya.

## Step 4 — PUT: Todo Update Karna

**SOCH:** Ab update — todo ka `done` toggle karna ho ya `title` badalna ho. 6.6 mein decide kiya tha PUT use karenge. Same dynamic route pe PUT function add karna hai.

**CONCEPT:** `Todo.findByIdAndUpdate(id, updateData, { new: true })` — id se dhoondho, data update karo, updated document return karo. `{ new: true }` zaroori hai — bina iske purana document return hota hai. Body se naya title + done.

**File:** `app/api/todos/[id]/route.ts` (same file — DELETE ke neeche PUT add karo)

```ts
// app/api/todos/[id]/route.ts
import { NextRequest, NextResponse } from "next/server";   // NEW: NextRequest
import { connectDB } from "@/lib/db";
import Todo from "@/models/Todo";

export async function DELETE(
  _request: Request,
  context: { params: Promise<{ id: string }> }
) {
  // ... wahi jo Step 3 mein likha
}

export async function PUT(
  request: NextRequest,
  context: { params: Promise<{ id: string }> }
) {
  try {
    await connectDB();
    const { id } = await context.params;
    const body = await request.json();
    const { title, done } = body;

    const updated = await Todo.findByIdAndUpdate(
      id,
      { title: title.trim(), done },
      { new: true }
    );

    if (!updated) {
      return NextResponse.json({ error: "Todo nahi mila" }, { status: 404 });
    }

    return NextResponse.json(updated, { status: 200 });
  } catch (error) {
    console.error("Todo update error:", error);
    return NextResponse.json({ error: "Todo update nahi ho saka" }, { status: 500 });
  }
}
```

Line by line:

- **`request: NextRequest`** — PUT mein bhi body aati hai (naya title/done), isliye request import.
- **`{ title: title.trim(), done }`** — update data. Body se aaya title/done.
- **`{ new: true }`** — updated document return karo. **Bina iske purana (pre-update) document return hota** — confusing bug.
- **`if (!updated)`** — galat id → `null` → 404.
- **200 + updated document** — update successful.

**TEST:**

```bash
curl -X PUT http://localhost:3000/api/todos/<YOUR_ID> -H "Content-Type: application/json" -d '{"title":"Updated title","done":true}'
```

Updated todo JSON mein wapas aaye — `done: true` ke saath. Browser mein `/api/todos` kholo — wahi todo updated dikhe.

## Nutshell

MongoDB + Route Handlers mein CRUD: `Todo.find()` (list), `Todo.create()` (banao), `Todo.findByIdAndUpdate(id, data, { new: true })` (badlo), `Todo.findByIdAndDelete(id)` (hatao) — sab `await connectDB()` ke baad, try/catch + sahi status code ke saath. Dynamic route `[id]` mein params `await context.params` se milta hai (Next.js 15+ async params).

## What It Is NOT

- **`{ new: true }` = optional.** Bina iske `findByIdAndUpdate` **purana** document return karta hai — updated nahi. Yehi sabse common bug hai. Naya document chahiye toh `{ new: true }` zaroori hai.
- **`await context.params` = kabhi skip nahi.** Next.js 15+ mein params Promise hai — bina `await` ke id nahi milegi. Batch 1 wala `params` bhi yaad karo — wahan page components mein bhi async params ka pattern tha.
- **`Todo.find()` bina `await` = galat.** Mongoose methods async hain — hamesha `await` (ya `.then`). Bina await ke Promise object milega, data nahi.
- **400 vs 404 — exchange nahi.** Galat body (bina title) = 400 (client ki galti). Galat id (todo exist nahi) = 404 (resource nahi). Dono alag problems — 6.6 design.
- **Route Handler sirf Next.js ka nahi.** REST API pattern universal hai — yeh wahi 3.1 wala concept hai, bas data source file ki jagah MongoDB hai.

1. `Todo.findByIdAndUpdate(id, data, { new: true })` — `{ new: true }` kya kar raha hai, aur bina iske kya hoga?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `{ new: true }` updated document return karta hai. Bina iske Mongoose update ke **baad** nahi, **pehle** wala (purana) document return karta hai — matlab response mein purana data dikhega aur confusion hogi. Updated data chahiye toh `{ new: true }` option zaroori hai.

</details>

2. `DELETE /api/todos/xyz` (galat id) — kaunsa status code, kyun?

<details>
<summary>Show Answer</summary>

**Sample Answer:** 404 Not Found. `findByIdAndDelete` galat id pe `null` return karta hai — `if (!deleted)` check pakad leta hai. Resource exist nahi karta isliye 404. 400 tab hota jab body galat ho (bina title) — client ki request shape mein problem. Yahan problem resource ki existence mein hai.

</details>

3. Dynamic route `[id]` mein ID kaise milti hai, aur `await` kyun?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Folder ka naam `[id]` = URL ka variable part. `context.params` se milta hai — `/api/todos/abc2` → `{ id: "abc2" }`. Next.js 15+ mein params Promise hai — isliye `await context.params` karna padta hai, bina await ke id nahi milegi.

</details>

4. GET aur POST mein function signature alag kyun hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** GET mein data sirf **nikalna** hai — request ki body ki zaroorat nahi, isliye `request` parameter bhi nahi. POST mein frontend **data bhejta hai** (`{ title }`) — woh data `request` ke andar hota hai, `request.json()` se read hota hai. Isliye POST ka function `request: NextRequest` leta hai, GET ka nahi.

</details>

5. Naya todo create karte waqt `done: false` explicit kyun likha, jabki schema mein `default: false` hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Technically schema default se hi false aa jaata, explicit likhna zaroori nahi. Par explicit `done: false` likhne se code padhne wale ko clearly pata chalta hai ki naya todo hamesha pending se shuru hota hai — intention clear hai, sirf default pe bharosa nahi. Yeh "explicit > implicit" pattern hai.

</details>
