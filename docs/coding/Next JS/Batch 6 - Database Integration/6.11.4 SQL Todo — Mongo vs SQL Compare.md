# SQL Todo — Part 4: Mongo vs SQL Full Comparison

## Full Comparison — Mongo REST vs SQL Server Actions

Now both mini-projects are in front of us — full comparison. Earlier each concept was clear one-by-one — now they come together in a table:

| | **Mongo (6.7.x-6.8)** | **SQL (6.11.1-6.11.3)** |
|---|---|---|
| **Data model** | NoSQL — document | SQL — table/row |
| **Read** | REST GET route → client fetch | Server Component `db.select()` |
| **Write** | POST/PUT/DELETE route → client fetch | Server Action `db.insert/update/delete` |
| **ID** | `_id` string (generated by Mongo) | `id` number (auto-incremented SERIAL) |
| **Fetch result** | `Todo.create()` returns the row | `.returning()` would be needed |
| **Data flow** | Client state + refetch | Server render + `revalidatePath` |
| **Testing** | Postman (REST URLs) | Direct browser/form (Server Actions) |
| **Connection** | `connectDB()` async singleton | `db` ready export (serverless) |
| **When to use** | External clients, mobile, 3rd party | Same-app internal, form-driven, simpler |

**When to use what** — REST when external clients consume the data (mobile app, third party, public API). Server Actions when the data only comes from this same app's UI — no public API surface needed. The Task Board (6.13) will use SC+SA — the production pattern.

One thing to note — this table is **not** "Mongo vs SQL", it's a **data-flow pattern comparison**. In 6.2 we compared SQL vs NoSQL (data structure), here we're comparing how data flows through the app. Two different questions — so different tables.

## Nutshell

Full comparison of both mini-projects: Mongo REST (6.7.x-6.8) — URL + fetch + client state + Postman testing, for external clients. SQL Server Actions (6.11.1-6.11.3) — server functions + forms + `revalidatePath`, for same-app UI. The difference here is in the data-flow pattern, not the database — when to use which situation decides.

## What It Is NOT

- **"SQL Server Actions = Mongo REST upgrade"** is not accurate. Both are right in their own context — REST for external access, Server Actions for same-app forms. Different tools, different use-cases — neither is "better".
