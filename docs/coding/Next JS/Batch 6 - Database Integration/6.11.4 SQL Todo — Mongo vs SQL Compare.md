# SQL Todo — Part 4: Mongo vs SQL Full Compare

## Poora Compare — Mongo REST vs SQL Server Actions

Ab dono mini-projects saamne hain — full compare. Pehle har concept ek-ek clear tha, ab table:

| | **Mongo (6.7.x-6.8)** | **SQL (6.11.1-6.11.3)** |
|---|---|---|
| **Data pattern** | NoSQL — document | SQL — table/row |
| **Read** | REST GET route → client fetch | Server Component `db.select()` |
| **Write** | POST/PUT/DELETE route → client fetch | Server Action `db.insert/update/delete` |
| **ID** | `_id` string (Mongo banaata) | `id` number (SERIAL auto) |
| **Fetch result** | `Todo.create()` row wapas deta hai | `.returning()` lagana padta hai |
| **Data flow** | Client state + re-fetch | Server render + `revalidatePath` |
| **Testing** | Postman (REST URLs) | Direct browser/form (SA) |
| **Connection** | `connectDB()` async singleton | `db` ready export (serverless) |
| **Kyun use karein** | External clients, mobile, 3rd party | Same-app internal, form-driven, simpler |

**Kab kya use karein** — REST jab API ko external clients consume karein (mobile app, third party, public API). Server Actions jab data sirf apni hi app ke UI se aana hai — koi public API surface nahi chahiye. Task Board (6.13) mein SC+SA hi hoga — production pattern.

Ek cheez note karo — yeh table **Mongo vs SQL** nahi, **data-flow pattern** ka compare hai. 6.2 mein SQL vs NoSQL ka compare tha (data structure), yahan baat hai kaise data app tak aata hai. Dono alag saawaal — isliye alag tables.

## Nutshell

Dono mini-projects ka compare: Mongo REST (6.7.x-6.8) — URL + fetch + client state + Postman testing, external clients ke liye. SQL Server Actions (6.11.1-6.11.3) — server functions + forms + `revalidatePath`, same-app UI ke liye. Idhar fark data structure (6.2) ka nahi, data-flow pattern ka hai — kab kya, situation decide karti hai.

## What It Is NOT

- **"SQL Server Actions = Mongo REST ka upgrade" nahi.** Dono apne apne context mein sahi hain — REST external access ke liye, Server Actions same-app forms ke liye. Alag tools, alag use-case — koi "better" nahi.
