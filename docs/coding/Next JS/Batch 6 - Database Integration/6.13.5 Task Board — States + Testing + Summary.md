# Task Board — Part 5: States + Testing + Summary

## Step 1 — 404: Galat Board Id

6.13.4 mein `if (!board) notFound()` likha tha. `notFound()` abhi default Next.js 404 page dikhayega. Custom `not-found.tsx` banao — board-specific message (Batch 3/4 mein `not-found.tsx` padha tha):

**File:** `app/board/[id]/not-found.tsx`

```tsx
// app/board/[id]/not-found.tsx
export default function NotFound() {
  return (
    <section>
      <h2>Board nahi mila</h2>
      <p>Yeh board exist nahi karta — galat link, ya delete ho chuka.</p>
      <a href="/">Boards pe wapas jao</a>
    </section>
  );
}
```

- `app/board/[id]/not-found.tsx` — **is route folder ka** 404 page. `/board/999` pe `notFound()` chalta hai → yeh dikhega.
- Global `app/not-found.tsx` alag bana sakte ho (poori app ka 404) — folder-specific wala route ke hisaab se override karta hai.

## Step 2 — Error: Something Went Wrong

Runtime error — database down, unexpected — `error.tsx` handle karta hai (Batch 3 mein tha):

**File:** `app/board/[id]/error.tsx`

```tsx
// app/board/[id]/error.tsx
"use client";

export default function Error({
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  return (
    <section>
      <h2>Kuch galat ho gaya</h2>
      <p>Board load karte waqt error aaya. Dobara try karo.</p>
      <button onClick={reset}>Try Again</button>
    </section>
  );
}
```

- **`"use client"`** — error boundary client component hona chahiye (interactive reset button).
- **`reset`** — Next.js function — dobara render try karta hai. Server action nahi, client-side.

**Try karo:** koi bhi aisa change karo jo error de (jaise temporarily `prisma` import galat karke) — error.tsx dikhega. Fix karke hatao.

## Step 3 — Loading: Data Aate Hue

Server Components async hain — database query time lagati hai — **pehli baar data aate hue loading state** dikhani chahiye:

**File:** `app/board/[id]/loading.tsx`

```tsx
// app/board/[id]/loading.tsx
export default function Loading() {
  return (
    <section>
      <h2>Board load ho raha hai...</h2>
    </section>
  );
}
```

- `loading.tsx` — route segment ke liye automatic loading UI (Batch 1 mein tha). Board page async hai — render shuru hote hi loading dikhega, query complete pe page.

**States ka order (Next.js pipeline):**

```
Request → loading.tsx (abhi) → page render
           ↓ error aaya
           error.tsx (recover/retry)
galat id → not-found.tsx
```

- **404 vs error alag:** galat id = **user ki galti** (URL galat) → `notFound()` → not-found.tsx (yaadanadhyay 404). Unexpected error = **system ki galti** → error.tsx (recoverable). 6.6 wala 404 vs 500 soch — 404 = resource nahi, 500 = server problem. Yahi UI version.

## Nutshell

States: `not-found.tsx` (galat id — user galti), `error.tsx` (system error — recoverable), `loading.tsx` (query ke dauran). Pipeline: loading → page, error pe error.tsx, notFound pe not-found.tsx. Test table se sab verify. Journey: JSON file → MongoDB (document, REST) → Neon/Drizzle (table, SC+SA) → Prisma (production pattern) — do DB, teen ORM tools, ek soch (relations, migrations, states).

## What It Is NOT

- **`not-found.tsx` = `error.tsx` ka copy nahi.** Dono alag problems — not-found = resource nahi (user galti, predictable), error = unexpected failure (recoverable). URL se predictable cases notFound, unpredictable error.tsx. 6.6 ke 404 vs 500 ka UI version.
- **`error.tsx` = "client component isliye kyunki lazy" nahi.** Reset button interactivity chahiye — isliye client. Boundary mechanism Next.js ka hai — file name + placement hi kaafi.
- **`loading.tsx` = "sirf slow apps ke liye" nahi.** Server components async hain — DB query hamesha time leti hai. Loading UI default experience hai — bina uske blank/old screen. Production mein har dynamic segment ka loading.
- **Test table = "sirf checklist" nahi.** Har row = ek behavior verify — expected vs actual. Test table project ko "feature complete" se "verified complete" banata hai.
- **Batch 6 = "teen ORM seekh liya, bas" nahi.** Teen tools examples hain — asli output: **database ka sochna** (6.1-6.3 concepts), **data flow patterns** (REST vs SC+SA — 6.8/6.11.4/6.13), **production readiness** (relations, migrations, states). Koi bhi DB/ORM naya aaye — pattern yaad hai.
