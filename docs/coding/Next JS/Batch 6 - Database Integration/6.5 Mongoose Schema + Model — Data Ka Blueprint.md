6.4 mein connection ready hua — `connectDB()` se app ab real MongoDB se baat kar sakti hai. Ab agla sawaal: **data ki shape kya hai?** MongoDB flexible hai — koi bhi document save ho sakta hai. Par humein fir bhi batana padega ki "Todo document mein kya-kya hoga" — taaki code mein type safety ho aur data consistent rahe. 6.5 mein **Mongoose schema + interface + model** banayenge — data ka blueprint.

**File:** `models/Todo.ts` (nayi file — `models/` folder wahi convention jo 6.4 mein `lib/` tha: specific type ka code apni jagah).

# Mongoose Schema + Model

## Step 1 — Schema — Data Ka Blueprint

Pehle socho kya chahiye. Ek Todo mein:

- `title` — string (kya karna hai)
- `done` — boolean (ho gaya ya nahi)
- `createdAt` / `updatedAt` — jab bana / jab badla

**Schema kya hai?** Data ka blueprint/template — "MongoDB mein jo bhi todo document save hoga, usme in fields ka type yeh hoga." Mongoose ka `Schema` function yeh blueprint banata hai.

**File:** `models/Todo.ts`

```ts
// models/Todo.ts
import mongoose, { Schema } from "mongoose";

const TodoSchema = new Schema({
  title: {
    type: String,
    required: true,
    trim: true,
  },
  done: {
    type: Boolean,
    default: false,
  },
}, {
  timestamps: true,
});
```

Line by line:

- **`import mongoose, { Schema } from "mongoose"`** — `mongoose` poora library object, `Schema` uske andar se blueprint banane wala function (destructuring — 6.4 mein import pattern).
- **`new Schema({...})`** — blueprint object banta hai. `{ title: {...}, done: {...} }` mein batate hain data kaisa hoga.
- **`title: { type: String, required: true, trim: true }`** — title string hai, **required** (bina title ke save nahi hoga), **trim** (aage-peeche spaces hata do). `required` se "bina title ka todo" wali problem solve hoti hai.
- **`done: { type: Boolean, default: false }`** — done true/false, default false (naya todo default me pending).
- **`timestamps: true`** — `createdAt` aur `updatedAt` **automatically** add honge — manually daalne ki zaroorat nahi.

Abhi yeh schema **sirf definition** hai — database mein kuch nahi hua. Schemas seedha database se baat nahi karte; model (Step 3) unhe database se jodta hai.

## Step 2 — TypeScript Interface — Type Safety

Ab TypeScript ko bhi batana padega ki todo data kaisa dikhega. Schema runtime pe enforce karta hai, interface compile-time pe — **dono alag kaam.**

**File:** `models/Todo.ts` (same file, upar add karo)

```ts
// models/Todo.ts
import mongoose, { Schema, Document } from "mongoose";

interface ITodo extends Document {
  title: string;
  done: boolean;
  createdAt: Date;
}

const TodoSchema = new Schema({
  // ... wahi schema jo upar likha
});
```

- **`interface ITodo`** — TypeScript ka contract — "ek todo object mein exactly yeh fields hain." `I` prefix convention hai (interface batane ke liye).
- **`extends Document`** — Mongoose ka type. Har MongoDB document mein automatically `_id`, `__v`, aur methods (`.save()`, `.deleteOne()`) hote hain. `extends` matlab "Document wali cheezein bhi lo, aur apne fields bhi" — isliye `createdAt` define kiya (timestamps se aata hai), `_id` Document se aata hai, manually likhna nahi.

> **Nutshell:** Schema runtime data ko validate karta hai (required, type). Interface compile-time TypeScript ko type safety deta hai. `ITodo extends Document` se interface ko Mongoose ke built-in fields (`_id`, methods) milte hain.

## Step 3 — Model — Schema + Database Ka Connection

Ab schema ko database se jodna hai. **Model** kya hota hai — schema ka use karke database mein collection ke saath baat karne ka interface. `Todo.find()` yeh model hi provide karta hai.

**File:** `models/Todo.ts` (same file, end mein)

```ts
// models/Todo.ts
import mongoose, { Schema, Document, Model } from "mongoose";

interface ITodo extends Document {
  title: string;
  done: boolean;
  createdAt: Date;
}

const TodoSchema = new Schema({
  title: {
    type: String,
    required: true,
    trim: true,
  },
  done: {
    type: Boolean,
    default: false,
  },
}, {
  timestamps: true,
});

const Todo = mongoose.model<ITodo>("Todo", TodoSchema);

export default Todo;
```

- **`mongoose.model<ITodo>("Todo", TodoSchema)`** — `"Todo"` collection ka naam hai (MongoDB mein lowercase plural banta hai: `todos`), schema usse jodta hai. `<ITodo>` generic hai — TypeScript ko batata hai ki is model se aane wala data `ITodo` jaisa dikhega.
- **`export default Todo`** — baaki files isse import karenge (`import Todo from "@/models/Todo"`).

**Ek Next.js special problem — hot reload model redefinition.** 6.4 mein connection ka singleton pattern dekha (cache). Model ke saath bhi same problem: Next.js hot reload mein `mongoose.model("Todo", ...)` baar-baar call hoga toh **OverwriteModelError** aayegi ("Cannot overwrite model"). Solution — pehle check karo model exists karta hai kya, warna banao:

```ts
// models/Todo.ts
const Todo = mongoose.models.Todo || mongoose.model<ITodo>("Todo", TodoSchema);
```

`mongoose.models.Todo` — ek registry hai pehle se bane models ki. Agar `Todo` pehle se hai toh wahi use karo, warna banao. **Hot reload mein model bhi ek hi baar banna chahiye** — yahi check guarantee karta hai.

## Test — Database Mein Kuch Save Karke Dekho

Ab pehla real database write karte hain — verifiy karne ke liye. **File:** `app/page.tsx` (temporary test)

```tsx
// app/page.tsx
import { connectDB } from "../lib/db";
import Todo from "../models/Todo";

export default async function Home() {
  await connectDB();
  const test = await Todo.create({ title: "First real todo" });
  return (
    <main>
      <h1>Saved todo:</h1>
      <pre>{JSON.stringify(test, null, 2)}</pre>
    </main>
  );
}
```

- **`await connectDB()`** — pehle connection (6.4 wala singleton).
- **`await Todo.create({ title: "First real todo" })`** — naya todo save karta hai. `create()` MongoDB mein document insert karta hai.
- **`JSON.stringify(test, null, 2)`** — saved document ko pretty print karta hai browser mein.

Browser kholo — aisa kuch dikhna chahiye:

```json
{
  "_id": "65a1b2c3d4e5f6a7b8c9d0e1",
  "title": "First real todo",
  "done": false,
  "createdAt": "2026-08-15T10:30:00.000Z",
  "updatedAt": "2026-08-15T10:30:00.000Z",
  "__v": 0
}
```

- **`_id`** — MongoDB ne automatically banaya (unique identifier — 6.2 mein discuss kiya)
- **`done: false`** — humne nahi diya, `default: false` se automatic aaya
- **`createdAt`/`updatedAt`** — `timestamps: true` se
- **`__v`** — Mongoose ka internal version field — ignore karo

**Bada moment:** yeh data **MongoDB Atlas mein save hai** — ab app restart karo, server band karo, dobara chalao — data wahi milega. 6.1 mein "permanent storage" ka point tha, yeh ab practically confirm hua.

**Important:** yeh test page abhi sirf verify ke liye hai. `Todo.create()` seedha page se kar raha hai — aage REST API mein proper tarike se hoga (6.7). Abhi isse dekhna tha ki model kaam kar raha hai.

## Nutshell

Mongoose mein teen cheezein mil ke data ko define karti hain — **Schema** (runtime validation: types, required, default, timestamps), **Interface** (compile-time TypeScript contract, `extends Document` se Mongoose ke fields milte hain), aur **Model** (`mongoose.model<TodoType>("Todo", Schema)` — schema ko collection se jodta hai aur methods deta hai: `create()`, `find()`). Hot reload mein `mongoose.models.Todo || mongoose.model(...)` pattern model ko ek hi baar banata hai.

## What It Is NOT

- **Schema ≠ database table.** Schema sirf definition hai. Jab tak model ise use karke data save nahi karta, database mein kuch nahi hota. MongoDB mein "collection" model ke through banta hai.
- **Interface ≠ runtime check.** Interface sirf compile-time hai — TypeScript ki type safety. Runtime pe MongoDB ko interface ka pata nahi — wahan schema validate karta hai. Isliye dono chahiye.
- **`Todo.create()` ≠ `INSERT INTO todos` ki MongoDB version nahi.** `create()` ek Mongoose method hai jo insert + validation dono karta hai — schema ki required/default checks pehle apply hoti hain, phir document save hota hai.
- **`_id` tumhe manually nahi banana.** MongoDB automatically har document ko unique `_id` deta hai — 24-character hex string. Interface mein bhi define nahi karna (Document se aata hai).
