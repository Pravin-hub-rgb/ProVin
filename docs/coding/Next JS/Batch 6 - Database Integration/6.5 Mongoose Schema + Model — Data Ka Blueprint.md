6.4 mein connection ready hua — `connectDB()` se app ab real MongoDB se baat kar sakti hai. Ab agla sawaal: **data ki shape kya hai?** MongoDB flexible hai — koi bhi document save ho sakta hai. Par humein fir bhi batana padega ki "Todo document mein kya-kya hoga" — taaki code mein type safety ho aur data consistent rahe. 6.5 mein **Mongoose schema + interface + model** banayenge — data ka blueprint.

**File:** `models/Todo.ts` (nayi file — `models/` folder wahi convention jo 6.4 mein `lib/` tha: specific type ka code apni jagah).

# Mongoose Schema + Model

## Step 1 — Schema — Data Ka Blueprint

Pehle socho kya chahiye. Ek Todo mein:

- `title` — string (kya karna hai)
- `done` — boolean (ho gaya ya nahi)
- `createdAt` / `updatedAt` — jab bana / jab badla

**Schema kya hai?** Data ka blueprint/template — "MongoDB mein jo bhi todo document save hoga, usme in fields ka type yeh hoga." Mongoose ka `Schema` function yeh blueprint banata hai.

Par fields ke **type** ke alawa kuch aur sawaal hain jinhe sochna padega. Aur yehi options hain jo schema mein batane hote hain. Ek-ek karke samjho — pehle problem, phir option:

**Sawaal 1 — "bina title wala todo" save kyun nahi hona chahiye?** Socho `Todo.create({ done: true })` — koi title hi nahi diya. Kya yeh document database mein jana chahiye? Nahi — ek todo jiska koi kaam hi nahi, woh bekaar hai. Isliye `title` ko **required** banana hai — "yeh field ke bina save hi mat karna." Error aayega aur document reject ho jayega.

**Sawaal 2 — "  milk  " wala title kaisa dikhega?** User kabhi-kabhi aage-peeche spaces daal deta hai (`"  milk  "`). Save hote waqt agar spaces ke saath hi chala gaya, toh baad mein `"milk"` search karo toh milega nahi — kyunki data mein spaces hain. Isliye **trim** — save hote waqt aage-peeche ke spaces **hata do.** Input "  milk  " hota hai, database mein "milk" jaata hai.

**Sawaal 3 — naya todo ka `done` kya hoga?** Jab koi naya todo banata hai, woh to-do **pending** hota hai — `done: false`. Par user ko har baar `done: false` bhejna padna chahiye? Nahi — **default** bata do: "agar `done` diya hi nahi, toh `false` maan lo." Bina bataaye naya todo apne aap pending banega.

**Sawaal 4 — `createdAt` / `updatedAt` khud likhna padega kya?** Yeh exact sawaal hai jo tumne pucha — aur jawab yeh hai ki **schema mein yeh fields likhte hi nahi.** Mongoose ka **timestamps** option hai: `timestamps: true` karo, toh Mongoose khud har document mein `createdAt` (kab bana) aur `updatedAt` (kab badla) **automatically add kar deta hai.** Tumhe manually likhne ki zaroorat nahi — isliye upar fields list mein bola, par schema mein dikhega nahi. `timestamps: true` hi woh kaam karta hai.

Ab in charon options ko schema mein rakho — ek-ek line:

```ts
// models/Todo.ts
import mongoose, { Schema } from "mongoose";
```

**Import — `mongoose`** poora library object, **`Schema`** uske andar se blueprint banane wala function (destructuring — 6.4 mein import pattern).

```ts
const TodoSchema = new Schema({
```

**`new Schema({...})`** — blueprint object banta hai. Par ek important baat — `Schema` ko **do arguments** dene hain: pehla woh object jisme **fields + unke options** (required, trim, default), doosra woh object jisme **model-level options** (timestamps jaise). Abhi pehla argument khula hai — andar fields daalte hain:

```ts
  title: {
    type: String,
    required: true,
    trim: true,
  },
```

**`title`** — teen cheezein: `type: String` (string hogi), `required: true` (bina title ke save nahi), `trim: true` (aage-peeche spaces hata do). Sawaal 1 aur 2 ke solutions.

```ts
  done: {
    type: Boolean,
    default: false,
  },
```

**`done`** — `type: Boolean` (true/false), `default: false` (naya todo default pending — Sawaal 3).

```ts
}, {
  timestamps: true,
});
```

**`}, {` — yahan doosra argument shuru ho raha hai.** Pehla object (fields wala) `}` se band hua, phir `,` aur `{` — doosra object khula: **options**. `timestamps: true` — Sawaal 4 ka jawab. `createdAt` aur `updatedAt` automatically add honge, manual nahi. Yeh options ke andar isliye hai kyunki yeh koi field nahi — poore document pe apply hone wala setting hai. Agar bhool ke isko fields object ke andar daal do toh schema toot jayega — do arguments ka structure yaad rakho: `new Schema(fieldsObject, optionsObject)`.

Abhi yeh schema **sirf definition** hai — database mein kuch nahi hua. Schemas seedha database se baat nahi karte; model (Step 3) unhe database se jodta hai.

**Step 1 ke end mein poori file ka state** — `models/Todo.ts` abhi bilkul yeh dikhegi:


Bas itna hi — abhi interface aur model nahi hai, kyunki woh Step 2 aur Step 3 mein add honge. **Har step ke end mein file ka poora current state dikhaunga** — taaki hamesha pata rahe ki is step ke baad file mein exactly kya likhna hai.

## Step 2 — TypeScript Interface — Type Safety

Ab TypeScript ko bhi batana padega ki todo data kaisa dikhega. Schema runtime pe enforce karta hai, interface compile-time pe — **dono alag kaam.**

Pehle ek sawaal: **jab MongoDB ek document return karta hai, toh usme aur kya-kya hota hai?** Sirf tumhare fields nahi. Har document mein automatically `_id` (unique identifier — 6.2 mein discuss kiya), `__v` (Mongoose ka internal version), aur methods (`.save()`, `.deleteOne()`) bhi hote hain. Toh jab tum TypeScript mein "todo kaisa dikhta hai" bataoge, kya tumhe `_id` bhi likhna padega? Nahi — kyunki yeh cheezein **har document mein hamesha** hoti hain. Isliye Mongoose ke paas ek built-in type hai — **`Document`** — jisme yeh sab already defined hai.

**`extends Document` ka matlab:** "Document wali built-in cheezein bhi lo (`_id`, methods), **aur** mere apne fields bhi (`title`, `done`, `createdAt`, `updatedAt`)." `extends` inheritance hai — "jo Document mein hai, woh bhi mere paas hai."

Isliye interface mein `_id` manually nahi likhte (Document se aata hai). Par **`createdAt` aur `updatedAt` DONO likhte hain** — aur yahi tumhare sawaal ka jawab hai: timestamps `createdAt` ke saath-saath `updatedAt` bhi add karta hai, toh dono interface mein define hone chahiye. Ek ko chhod ke doosra nahi — kyunki document mein dono aayenge. `createdAt` Document ka hissa nahi, `updatedAt` bhi nahi — dono timestamps se aate hain (Step 1), isliye dono khud likhne padte hain. Ab code ek-ek line:

```ts
// models/Todo.ts
import mongoose, { Schema, Document } from "mongoose";
```

**`Document` import** — Step 1 mein sirf `Schema` tha, ab `Document` type bhi chahiye (interface mein use hoga).

```ts
interface ITodo extends Document {
  title: string;
  done: boolean;
  createdAt: Date;
  updatedAt: Date;
}
```

**`interface ITodo`** — TypeScript ka contract — "ek todo object mein exactly yeh fields hain." `I` prefix convention hai (interface batane ke liye). `extends Document` — upar wala logic. `createdAt: Date` aur `updatedAt: Date` — dono timestamp fields (dono timestamps se aate hain, isliye dono likhe).

```ts
const TodoSchema = new Schema({
  // ... wahi schema jo upar likha
});
```

**Schema wahi** — Step 1 wala. Interface abhi sirf TypeScript ke liye hai, schema runtime ke liye — dono ka kaam alag.

> **Nutshell:** Schema runtime data ko validate karta hai (required, type). Interface compile-time TypeScript ko type safety deta hai. `ITodo extends Document` se interface ko Mongoose ke built-in fields (`_id`, methods) milte hain — isliye `_id` manual nahi likhte, par `createdAt` aur `updatedAt` dono likhte hain (dono timestamps se aate hain, Document se nahi).

**Step 2 ke end mein poori file ka state** — ab interface bhi jud gaya:

```ts
// models/Todo.ts

  title: string;
  done: boolean;
  createdAt: Date;
  updatedAt: Date;
}

  title: {
    type: String,
    required: true,
    trim: true,
  },
  done: {
    type: Boolean,
    default: false,
  },
}, {
  timestamps: true,
});
```

Interface + schema ready. Ab Step 3 — inhe database se jodna hai.

## Step 3 — Model — Schema + Database Ka Connection

Ab schema ko database se jodna hai. Aur yehi woh jagah hai jahan confusion hota hai — **schema vs model. Ek form aur usse kaam karne wale clerk ka socho.**

**Schema (form)** sirf bataata hai ki data **kaisa dikhega** — kaunse fields, kaunse types, kya required. Par form apne aap kuch nahi kar sakta — na naya record bana sakta hai, na koi record dhundh sakta hai. Bas definition hai.

**Model (clerk)** woh cheez hai jo us form ke rules use karke **database ke saath asli kaam** karta hai:

- `Todo.create(...)` — naya record database mein daalo
- `Todo.find()` — records database se nikalo
- `Todo.findById(id)` — ek specific record dhundho

Isliye bolte hain "model schema ko **collection** se jodta hai" — schema form hai, collection (database ki table) filing cabinet hai, model clerk hai jo dono ke beech kaam karta hai. **Schema ke paas methods nahi hote** (`create`/`find` schema pe nahi milte) — methods model ke paas hain. Abhi Schema + Interface ban chuke hain — ab inhe `mongoose.model()` se clerk (model) bana ke database se jodna hai.

Pehle ek sawaal: **database mein collection ka naam kya hoga?** `mongoose.model("Todo", ...)` — pehla argument `"Todo"` model ka naam hai. MongoDB automatically isse **lowercase plural** banata hai — `todos`. Toh collection ka naam `todos` hoga. Model ka naam tum decide karte ho, collection uska plural version. Ab code ek-ek line:

```ts
// models/Todo.ts
import mongoose, { Schema, Document, Model } from "mongoose";
```

**`Model` import** — Step 2 mein `Document` tha, ab `Model` bhi chahiye. (Asal code mein hum `Model` ko generic type ke roop mein use nahi kar rahe — `mongoose.model<ITodo>` se return type automatically infer hota hai. Isliye final file mein `Model` import nahi bhi kar sakte; par Step 2-3 ko jodte waqt interface `extends Document` ke saath model type samajhne ke liye rakha gaya hai. Clean version final file mein dekhoge.)

```ts
interface ITodo extends Document {
  title: string;
  done: boolean;
  createdAt: Date;
  updatedAt: Date;
}
```

**Interface wahi** — Step 2 wala. Schema aur interface pehle se ready hain.

```ts
const TodoSchema = new Schema({
  title: {
    type: String,
    required: true,
    trim: true,
  },
  done: {
    type: Boolean,
    default: false,
  },
}, {
  timestamps: true,
});
```

**Schema wahi** — Step 1 wala. Ab dono ready cheezein model mein jodni hain.

```ts
const Todo = mongoose.model<ITodo>("Todo", TodoSchema);
```

**`mongoose.model<ITodo>("Todo", TodoSchema)`** — model banata hai (clerk ko kaam pe lagata hai): `"Todo"` naam (collection `todos`), `TodoSchema` form (blueprint). Ab `Todo.create()` / `Todo.find()` available hain.

**Ab `<ITodo>` — generic, yahan samjho.** `<ITodo>` angle brackets wali cheez TypeScript ko batati hai: **"is model se aane wala data `ITodo` jaisa dikhega."** Matlan jab `const todos = await Todo.find()` karo, toh TypeScript ko pata hai `todos[0].title` string hai, `todos[0].done` boolean hai — galat field/type use karo toh error likhte waqt hi dikh jata hai (type safety). **Agar `<ITodo>` na likho** toh `Todo.find()` ka result TypeScript ko kaisa dikhega — koi shape ka pata nahi, `todos[0].title` pe type safety nahi milegi. Yahi generic ka kaam hai — "jo bhi is model se aayega, uska shape `ITodo` hai."

```ts
export default Todo;
```

**`export default Todo`** — baaki files isse import karenge (`import Todo from "@/models/Todo"`).

**Ek Next.js special problem — hot reload model redefinition.** 6.4 mein connection ka singleton pattern dekha (cache). Model ke saath bhi same problem: Next.js hot reload mein `mongoose.model("Todo", ...)` baar-baar call hoga toh **OverwriteModelError** aayegi ("Cannot overwrite model"). Pehle socho — kya kar sakte hain? Check karo ki model pehle se bana hai kya. `mongoose.models` — ek registry hai pehle se bane models ki. Agar `Todo` wahan hai toh wahi use karo, warna banao:

```ts
// models/Todo.ts
const Todo = mongoose.models.Todo || mongoose.model<ITodo>("Todo", TodoSchema);
```

**`mongoose.models.Todo || mongoose.model(...)`** — `||` wahi pattern jo 6.4 mein dekha: "pehle se set hai toh use karo, warna banao." Hot reload mein model ek hi baar banna chahiye — yahi check guarantee karta hai.

## Test — Database Mein Kuch Save Karke Dekho

Ab pehla real database write karte hain — verify karne ke liye. Pehle socho — **`Todo.create({ title: "First real todo" })` kya karega?**

- `connectDB()` se connection ready (6.4 wala singleton)
- `Todo.create(...)` — model ka method — naya document **insert** karta hai, aur save se pehle **schema ki validation apply** hoti hai (required/default checks — Step 1). Humne sirf `title` diya hai — `done` humne nahi diya, par `default: false` se automatic aayega. `createdAt`/`updatedAt` `timestamps` se automatic aayenge. **Yahi toh schema ka kaam hai** — humne 2 cheezein nahi bheji, par document mein 4-5 fields aayenge.
- Browser mein dikhane ke liye object ko **string** banana padta hai. `test` ek object hai (Mongoose document) — aur React/JSX mein object seedha render nahi hota. `{test}` likho toh browser `[object Object]` dikhayega — kyunki object ko display karne se pehle string mein convert karna padta hai. `JSON.stringify()` yahi karta hai — object ko JSON string mein badal deta hai. Aur iske **teen arguments** hain — ek-ek samjho:

```tsx
JSON.stringify(test)             // 1. test — object → JSON string
JSON.stringify(test, null)       // 2. null — replacer: koi filtering nahi
JSON.stringify(test, null, 2)    // 3. 2 — indentation: 2 spaces → pretty print
```

- **Argument 1 — `test`** — convert hone wala object. `Todo.create()` ka return — saved document.
- **Argument 2 — `null`** — replacer: yeh function ya array ho sakta hai jo batata hai "kaunse fields include karo, kaise change karo". Hum saara data chahiye — isliye `null` = "kuch filter mat karo". (Agar sirf `title` dikhana hota toh `["title"]` likhte.)
- **Argument 3 — `2`** — indentation: har nested level pe kitne spaces. `2` se output readable tree-form mein aata hai (upar wala output). `0` ya undefined hota toh sab ek line mein aata.

Code:

```tsx
// app/page.tsx
import { connectDB } from "../lib/db";
import Todo from "../models/Todo";

export default async function Home() {
  await connectDB();
  const test = await Todo.create({ title: "First real todo" });
  return (
    <main>
      <h1>Saved todo:</h1>
      <pre>{JSON.stringify(test, null, 2)}</pre>
    </main>
  );
}
```

Browser kholo — aisa kuch dikhna chahiye:

```json
{
  "_id": "65a1b2c3d4e5f6a7b8c9d0e1",
  "title": "First real todo",
  "done": false,
  "createdAt": "2026-08-15T10:30:00.000Z",
  "updatedAt": "2026-08-15T10:30:00.000Z",
  "__v": 0
}
```

Ab output ke har field ka hisaab milega — kahan se aaya:

- **`_id`** — MongoDB ne automatically banaya (unique identifier — 6.2 mein discuss kiya)
- **`done: false`** — humne nahi diya, `default: false` se automatic aaya (Step 1 Sawaal 3)
- **`createdAt`/`updatedAt`** — `timestamps: true` se (Step 1 Sawaal 4 — ab dikha)
- **`__v`** — Mongoose ka internal version field — ignore karo

**Bada moment:** yeh data **MongoDB Atlas mein save hai** — ab app restart karo, server band karo, dobara chalao — data wahi milega. 6.1 mein "permanent storage" ka point tha, yeh ab practically confirm hua.

**Important:** yeh test page abhi sirf verify ke liye hai. `Todo.create()` seedha page se kar raha hai — aage REST API mein proper tarike se hoga (6.7.2 mein, UI form se). Abhi isse dekhna tha ki model kaam kar raha hai.

## Nutshell

Mongoose mein teen cheezein mil ke data ko define karti hain — **Schema** (runtime validation: types, required, default, timestamps), **Interface** (compile-time TypeScript contract, `extends Document` se Mongoose ke fields milte hain), aur **Model** (`mongoose.model<TodoType>("Todo", Schema)` — schema ko collection se jodta hai aur methods deta hai: `create()`, `find()`). Hot reload mein `mongoose.models.Todo || mongoose.model(...)` pattern model ko ek hi baar banata hai.

## What It Is NOT

- **Schema ≠ database table.** Schema sirf definition hai. Jab tak model ise use karke data save nahi karta, database mein kuch nahi hota. MongoDB mein "collection" model ke through banta hai.
- **Interface ≠ runtime check.** Interface sirf compile-time hai — TypeScript ki type safety. Runtime pe MongoDB ko interface ka pata nahi — wahan schema validate karta hai. Isliye dono chahiye.
- **`Todo.create()` ≠ `INSERT INTO todos` ki MongoDB version nahi.** `create()` ek Mongoose method hai jo insert + validation dono karta hai — schema ki required/default checks pehle apply hoti hain, phir document save hota hai.
- **`_id` tumhe manually nahi banana.** MongoDB automatically har document ko unique `_id` deta hai — 24-character hex string. Interface mein bhi define nahi karna (Document se aata hai).
