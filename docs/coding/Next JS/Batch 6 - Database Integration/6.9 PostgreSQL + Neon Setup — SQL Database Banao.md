# PostgreSQL + Neon Setup — Creating an SQL Database

## First — Recall SQL Database Structure

In 6.2 we saw the details — quick recap. SQL database stores data in **tables** — rows and columns:

```
| id | title          | done  |
|----|----------------|-------|
| 1  | Homework        | false |
| 2  | Exercise        | true  |
```

- **Row** = one record (one todo)
- **Column** = one field (title, done)
- **Structure is defined first** — columns + types — then data is inserted

And an important SQL point — **id auto-increments** (`SERIAL`): add a new todo and the id automatically becomes 1, 2, 3... In MongoDB the `_id` was an object id (24-char hex string), in SQL it's an integer number.

## PostgreSQL Kya Hai, Neon Kyun

**PostgreSQL** is an SQL database (discussed in 6.2). Installing it on your computer is a headache for beginners (port conflicts, config). **Solution — Neon:** cloud-hosted free PostgreSQL — just like Atlas was for MongoDB.

```
For MongoDB   → Atlas  (cloud MongoDB)
For PostgreSQL → Neon   (cloud PostgreSQL)
```

With Atlas we didn't install anything — account banaya, database mila, connect kiya. Same with Neon — open in browser, database is ready.

**Neon's hierarchy** (simpler than Atlas):

```
Account → Project → Database → Tables
```

- **Project** — a container for an app ("Todo App Project")
- **Database** — the actual database inside the project (`neondb`)
- **Tables** — the data inside (`todos`, `users`)

## Step 1 — Neon Account + Project

1. Go to **neon.tech** → "Sign Up" → with GitHub (easiest)
2. After login, "Create your first project":
   - **Project name:** `sql-todo`
   - **Region:** AWS ap-south-1 (Mumbai) — closest to India, fast
   - **Create project**
3. As soon as the project is created, Neon automatically creates a database — **`neondb`** — that's what we'll use. (A popup shows the connection string — ignore for now, we'll get it in the next step.)

## Step 2 — Connection String

In the Neon Dashboard, find **"Connection Details"** or the **"Connect"** button — copy the **connection string**. It looks something like:

```
postgresql://username:password@ep-something-xxx.region.neon.tech/neondb?sslmode=require
```

Put this in your `.env` file (new file at project root). But note — in **`.env`**, not `.env.local` (the 6.4 secret pattern — it contains a password, must not reach GitHub). Why `.env`? Two things read it — **the Next.js app and drizzle-kit** (tables created in 6.10). Next.js reads `.env.local`, but **drizzle-kit's own dotenv only reads `.env`** — so use `.env` so both can read it (more in 6.10):

**File:** `.env` (project root)

```env
DATABASE_URL=postgresql://username:password@ep-something-xxx.region.neon.tech/neondb?sslmode=require
```

> **Remember — connection strings can have query params** (`?sslmode=require`) — that's the connection's encryption setting, commonly appears in Neon strings. Keep the full string intact when copying, don't cut it.

## Step 3 — Install Packages

Drizzle needs two packages (concept from 6.3):

```bash
npm install drizzle-orm @neondatabase/serverless
npm install -D drizzle-kit
```

- **`.drizzle-orm`** — runtime ORM — for writing queries (`db.select()`, `db.insert()`)
- **`.@neondatabase/serverless`** — Neon's serverless driver — creates connections and sends raw queries (like the driver MongoDB had for Mongoose)
- **`drizzle-kit`** — development tool — creates tables from schema (`drizzle-kit push`) — generates types, migrations

> **Nutshell:** Neon is free cloud PostgreSQL (the SQL version of Atlas). The connection string goes in `.env`. For Drizzle, three packages: `drizzle-orm` (queries), `@neondatabase/serverless` (driver), `drizzle-kit` (tool to create tables from schema).

## Step 4 — Test Connection

Before writing code, understand **how the test works and what's in it.**

**`neon` function** — the entry point of Neon's driver. Give it the connection string (`.env`'s one), and it returns a **`sql` function**. That `sql` function takes a template literal of SQL — `sql`SELECT 1`` — and sends it to the server. The backtick syntax is the driver's way to say "this is raw SQL".

**`SELECT 1` test** — ask the database: "are you reachable?" No actual data is queried — just return `1`. The simplest SQL query, which developers use to test a connection. If Neon returns `value: 1`, the connection is working.

Now create the file — but one line at a time, so the reason for each is clear. **File:** `app/page.tsx` (temporary test)

First — import the driver's entry point (installed in Step 3). `neon` must be imported before you can use it:

```tsx
// app/page.tsx
import { neon } from "@neondatabase/serverless";
```

**`import { neon }`** — import the driver's entry point (installed in Step 3).

Now make the page component — but the database call needs `await`, so the page must be `async` (same pattern as 6.4-6.5):

```tsx
// app/page.tsx
import { neon } from "@neondatabase/serverless";

export default async function Home() {        // NEW
```

**`async function Home`** — the page can be async because it renders on the server, and `await db` requires this. Compare with 6.4-6.5's `connectDB` await — there we awaited the connection, here `db` is already ready, we only await the query.

Now create the connection — `neon(process.env.DATABASE_URL!)` creates a raw connection from the connection string. `!` is TypeScript's non-null assertion — "this is definitely defined" (6.4 env access pattern):

```tsx
// app/page.tsx
import { neon } from "@neondatabase/serverless";

export default async function Home() {
  const sql = neon(process.env.DATABASE_URL!);     // NEW
```

**`const sql`** — raw connection created (from the `.env` connection string).

Now send the `sql` query — `SELECT 1` is just a test, ask for nothing real, just return `1`. SQL is written in backtick template syntax — the driver sends it to the server:

```tsx
// app/page.tsx
import { neon } from "@neondatabase/serverless";

export default async function Home() {
  const sql = neon(process.env.DATABASE_URL!);
  const result = await sql`SELECT 1 as value`;      // NEW
```

**`await sql`SELECT 1 as value``** — raw SQL query sent to the server. `SELECT 1` is just a test — asks for nothing real, returns `1`. SQL is in backtick template syntax — driver sends it to the server.

Now display the result in the browser — `<pre>` makes a code/text block, `JSON.stringify` turns the result into a readable string:

```tsx
// app/page.tsx
import { neon } from "@neondatabase/serverless";

export default async function Home() {
  const sql = neon(process.env.DATABASE_URL!);
  const result = await sql`SELECT 1 as value`;
  return <pre>{JSON.stringify(result)}</pre>;       // NEW
}
```

**`<pre>{JSON.stringify(result)}</pre>`** — pretty-prints the result in the browser. If "value: 1" shows, **the connection works** — we talked to Neon.

**TEST:** `npm run dev`, open the page — "value: 1" should show.

**This raw SQL test is just to verify** — going forward we won't write raw SQL, we'll use the Drizzle ORM. But it was important to confirm the connection works.

## Nutshell

PostgreSQL is an SQL database (tables/rows/columns, auto-increment ids). Neon hosts this on the cloud for free — connection string in `.env`. For Drizzle, install `drizzle-orm` + `@neondatabase/serverless` + `drizzle-kit`. `SELECT 1` tests the connection.

## What It Is NOT

- **Neon = exact copy of MongoDB Atlas** is wrong. Both are cloud database services, but the hierarchy is different (Atlas: Account→Cluster→Database→Collection, Neon: Account→Project→Database→Tables). Same concept though — no installs, open in browser, connect.
- **`@neondatabase/serverless` = ORM** is wrong. It's a **driver** — creates a raw connection to Neon and sends SQL. The ORM (Drizzle) is built on top. We won't use the driver directly in production — through Drizzle.
- **Connection string = secret**, `?sslmode=require` = not optional. The connection string with credentials goes in `.env` (outside git). Query params (encryption settings) must be kept intact — the full string is needed.
- **`SELECT 1` = a real query** is wrong. It's just a connection check — "is the database reachable". Real queries come later from Drizzle (`db.select()`).
- **Installing PostgreSQL locally = necessary** is wrong. The cloud version (Neon) is there — no local install needed. That's the beginner-friendly part.
