## Step 2 — Actions: `createBoard`

**SOCH:** Ab Server Actions file banani hai — forms se data lena, Prisma se insert, UI refresh. 6.11 wala pattern.

**CONCEPT:** `"use server"` file — `prisma.board.create({ data })` — Prisma insert (`.returning()` nahi chahiye — **Prisma `create()` automatically naya record return karta hai**, Drizzle mein `.returning()` lagana padta tha — 6.11 yaad hai). `revalidatePath("/")`.

**File:** `app/actions.ts` (nayi file)

```ts
// app/actions.ts
"use server";

import prisma from "@/lib/prisma";
import { revalidatePath } from "next/cache";

export async function createBoard(formData: FormData) {
  const name = formData.get("name") as string;

  if (!name || name.trim() === "") {
    return;
  }

  await prisma.board.create({
    data: {
      name: name.trim(),
      user_id: 1,
    },
  });

  revalidatePath("/");
}
```

Line by line:

- **`"use server"`** — saare exports server actions (6.11 wala).
- **`formData.get("name")`** — form input se naam.
- **Validation** — empty/sirf spaces reject.
- **`prisma.board.create({ data: { name, user_id: 1 } })`** — INSERT. `user_id: 1` — abhi ek hi user hai (6.13.3 relation design — har board ka user). Auth aaye toh yahan real user id aayegi.
- **`revalidatePath("/")`** — home page dobara render — naya board list mein.

**TEST:** Home page pe naya board banao — bina page reload ke list mein dikhe (server action + revalidate). Prisma Studio mein verify.

## Step 3 — Board Page: Relation Data (include)

**SOCH:** `/board/[id]` — board + columns + tasks. 6.13.2 mein hardcoded `tasks` array tha + `(params as any)` hack. Ab **real data** + **`await params`** (6.7 wala pattern). Board fetch karte waqt uske tasks bhi chahiye — **relation data** — 6.12 ka include/JOIN pattern.

**CONCEPT:** `prisma.board.findUnique({ where: { id }, include: { tasks: true } })` — ek query mein board + uske saare tasks (internal JOIN — N+1 se bacha, 6.12). `findUnique` — ek record id se (findMany = saare, findUnique = ek).

**File:** `app/board/[id]/page.tsx`

```tsx
// app/board/[id]/page.tsx
import prisma from "@/lib/prisma";
import { notFound } from "next/navigation";
import { createTask, moveTask, deleteTask } from "@/app/actions";    // NEW

const columns = ["BACKLOG", "IN_PROGRESS", "DONE"];

export default async function BoardPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;                        // NEW — 6.7 pattern

  const board = await prisma.board.findUnique({        // NEW
    where: { id: Number(id) },
    include: { tasks: true },
  });

  if (!board) {
    notFound();
  }

  return (
    <section>
      <h2>{board.name}</h2>

      <div style={{ display: "flex", gap: 16 }}>
        {columns.map((column) => {
          const columnTasks = board.tasks
            .filter((t) => t.status === column)
            .sort((a, b) => a.order - b.order);

          return (
            <div key={column} style={{ flex: 1, border: "1px solid #ccc", padding: 12 }}>
              <h3>{column.replace("_", " ")}</h3>

              <form action={createTask}>              {/* NEW */}
                <input type="hidden" name="board_id" value={board.id} />
                <input name="title" placeholder="Naya task..." />
                <button type="submit">Add</button>
              </form>

              <ul>
                {columnTasks.map((task) => (
                  <li key={task.id}>
                    <p>{task.title}</p>
                    {task.description && <small>{task.description}</small>}
                    <form action={moveTask}>           {/* NEW */}
                      <input type="hidden" name="id" value={task.id} />
                      <select name="status">
                        <option value="BACKLOG">Backlog</option>
                        <option value="IN_PROGRESS">In Progress</option>
                        <option value="DONE">Done</option>
                      </select>
                      <button type="submit">Move</button>
                    </form>
                    <form action={deleteTask}>         {/* NEW */}
                      <input type="hidden" name="id" value={task.id} />
                      <button type="submit">Delete</button>
                    </form>
                  </li>
                ))}
              </ul>
            </div>
          );
        })}
      </div>
    </section>
  );
}
```

Line by line:

- **`const { id } = await params`** — dynamic route id (Next.js 15+ async params — 6.7 wala pattern, ab actual use).
- **`findUnique({ where: { id: Number(id) }, include: { tasks: true } })`** — `where` Prisma ka filter (SQL WHERE), `include` relation data (JOIN). **`Number(id)`** — params string hota hai, id Int column — convert (6.11 wala `Number()` point).
- **`if (!board) notFound()`** — galat id → board null → 404 page. (6.13.5 mein `not-found.tsx`.)
- **`board.tasks.filter(...).sort(...)`** — 6.13.2 wala logic — par ab `board.tasks` database se aaya (include), hardcoded nahi. **`column.replace("_", " ")`** — enum `IN_PROGRESS` → UI "In Progress".
- **Forms** — `action={createTask}` / `moveTask` / `deleteTask` — hidden inputs id bhejte hain (6.11 wala pattern).

**Abhi `createTask`, `moveTask`, `deleteTask` actions exist nahi karte** — aage add karenge.

## Step 4 — Actions: Task Mutations

**File:** `app/actions.ts` (createBoard ke neeche add)

```ts
// app/actions.ts
"use server";

import prisma from "@/lib/prisma";
import { revalidatePath } from "next/cache";

export async function createBoard(formData: FormData) {
  // ... wahi jo Step 2 mein likha
}

export async function createTask(formData: FormData) {    // NEW
  const title = formData.get("title") as string;
  const board_id = Number(formData.get("board_id"));

  if (!title || title.trim() === "") {
    return;
  }

  await prisma.task.create({
    data: {
      title: title.trim(),
      board_id,
      order: 0,
    },
  });

  revalidatePath(`/board/${board_id}`);
}

export async function moveTask(formData: FormData) {      // NEW
  const id = Number(formData.get("id"));
  const status = formData.get("status") as "BACKLOG" | "IN_PROGRESS" | "DONE";

  await prisma.task.update({
    where: { id },
    data: { status },
  });

  revalidatePath(`/board`);
}

export async function deleteTask(formData: FormData) {    // NEW
  const id = Number(formData.get("id"));

  await prisma.task.delete({
    where: { id },
  });

  revalidatePath(`/board`);
}
```

Line by line:

- **`createTask`** — `prisma.task.create({ data: { title, board_id, order: 0 } })` — INSERT. `order: 0` — naya task column ke start mein (simple; aage production mein user position hoga). `revalidatePath(`/board/${board_id}`)` — board page refresh.
- **`moveTask`** — `prisma.task.update({ where: { id }, data: { status } })` — UPDATE WHERE id (6.11 `db.update().set().where(eq())` — Prisma mein `where` + `data` object). `status` type — enum string union.
- **`deleteTask`** — `prisma.task.delete({ where: { id } })` — DELETE WHERE id (6.11 `db.delete().where(eq())`).
- **`revalidatePath(`/board`)`** — move/delete ke baad sab boards ke pages refresh (board id dynamic hai — `/board` prefix revalidate karta hai). Prisma mein bhi SQL ka rule — **update/delete `where` ke saath** (bina where saari rows).

**Prisma vs Drizzle — query compare (6.11 vs ab):**

```ts
// Drizzle (6.11)
await db.update(todos).set({ done: true }).where(eq(todos.id, id))
await db.delete(todos).where(eq(todos.id, id))

// Prisma
await prisma.task.update({ where: { id }, data: { status } })
await prisma.task.delete({ where: { id } })
```

Prisma object-style, readable. Drizzle SQL-close. Same SQL, alag tarika.

## Nutshell

Dynamic: Home pe `prisma.board.findMany()`, Board page pe `prisma.board.findUnique({ where, include: { tasks: true } })` (relation data — N+1 se bacha, 6.12). `await params` se id (6.7 pattern), `Number(id)` convert. Actions: `prisma.board.create/task.create/update/delete` + `revalidatePath`. Prisma query style object-based — Drizzle chain-based. UI code 6.13.2 wala — sirf data source badla.

## What It Is NOT

- **`findUnique` vs `findMany` = same nahi.** `findMany()` saare records (SELECT *). `findUnique` ek record id/unique field se (SELECT ... WHERE id). Board page ek board chahiye — isliye `findUnique`.
- **`include: { tasks: true }` = "dusri query" nahi.** Yeh ek hi Prisma query hai jo relations internal JOIN karke laata hai — N+1 se bachta hai (6.12). Bina include ke `board.tasks` empty/error — tasks board ke saath nahi aate.
- **`where` update/delete mein = optional nahi.** `prisma.task.update({ where: { id }, data })` — bina where saari rows update. Prisma enforce karta hai (`where` required) — SQL ka rule, ORM style.
- **`.returning()` abhi chahiye = nahi.** Drizzle mein insert ke baad row wapas lene ke liye `.returning()` lagana padta tha. Prisma `create()` hamesha naya record return karta hai — internally handle — tumhe sochna nahi padta.
- **`user_id: 1` = "auth ka replacement" nahi.** Abhi single user hai isliye hardcoded. 6.13.3 ka design aisa ki auth aane pe yahan real user id aayegi. Forward-thinking — yahi 6.12 ki relation design ki value.

**In Your Own Words**

1. `findUnique({ where: { id }, include: { tasks: true } })` — `where` aur `include` alag kya karte hain?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `where` filter karta hai — kaunsa board (`WHERE id = ...`), ek record. `include` relation data laata hai — board ke saath uske tasks bhi (internal JOIN). `where` = kaunsa, `include` = aur kya saath mein. Board page pe ek board + uske tasks — dono ek query mein.

</details>

2. `await params` aur `Number(id)` — dono kyun zaroori hain?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `await params` — Next.js 15+ mein params async hai (Promise) — bina await ke id nahi milegi (6.7 wala pattern). `Number(id)` — params se id string aati hai (`"3"`), Prisma ka `id` Int column hai — `where: { id: Number(id) }` type-safe. String bhejo toh type error/query fail.

</details>

3. Prisma `task.create()` ko `.returning()` kyun nahi chahiye — Drizzle mein kyun lagana padta tha?

<details>
<summary>Show Answer</summary>

**Sample Answer:** PostgreSQL INSERT ke baad row automatically wapas nahi deta — isliye Drizzle mein `.returning()` force karna padta tha. Prisma ne yeh complexity internally handle ki hai — `create()` hamesha naya created record return karta hai automatically. ORM layer ne SQL detail chhupayi.

</details>

4. "UI ka code nahi badla, sirf data source badla" — 6.13.2 vs 6.13.4 mein iska kya matlab hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** 6.13.2 mein UI `const boards = [...]` (hardcoded) se render hota tha. 6.13.4 mein wahi JSX, wahi map/filter/sort — par data `await prisma.board.findMany()` se aata hai. UI ka structure wahi — bas data ki source badli. Yahi data layer abstraction ka fayda — pages ko pata nahi data kahan se aata hai, isliye source change pe UI nahi badla.

</details>

5. Task Board mein N+1 problem se kaise bache — `include` kya guarantee karta hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Bina include ke board page pe har column ke liye alag query chalti (ya `board.tasks` ki N queries) — N+1, slow. `include: { tasks: true }` Prisma ko ek hi query mein board + saare tasks laane ko bolta hai (internal JOIN) — ek round-trip, N+1 nahi. 6.12 ka JOIN pattern — ORM `include` wahi karta hai.

</details>
