6.11.2 mein Create ready hai — form se todo add ho raha hai, `revalidatePath` se UI refresh. Ab do aur operations baaki hain — **done toggle karna aur todo delete karna.** 6.7.3/6.7.4 (Mongo) mein PUT/DELETE routes the, TodoItem mein buttons. Yahan wahi kaam do aur **Server Actions** se — `toggleTodo` aur `deleteTodo`, aur is phase ka ek important SQL rule seekhenge jo 6.7.x se bilkul alag hai.

# SQL Todo — Part 3: Toggle + Delete (Server Actions)

## Step 5 — Toggle + Delete

**SOCH:** Todo app ke baaki operations — done toggle karna, todo delete karna. **Mongo mein** `PUT`/`DELETE` route + fetch. **Yahan** — do aur server actions. Aise toggles ke liye form submit hota hai (checkbox/button), action ko `formData` se id milti hai.

Ek sawaal: **form ka data string hota hai, SQL column number hai — id kaise pass hogi?** Mongo mein `_id` string tha (URL se aata tha) — koi conversion nahi. SQL mein `id` number column hai (SERIAL — 6.11.1 Step 1). Form se jo bhi aata hai woh string hota hai — isliye `Number(formData.get("id"))` convert karna zaroori hai. **Yeh 6.7.x se alag hai!** Ab ek aur sawaal: **kaunsi row update/delete karni hai, Drizzle ko kaise batayenge?** `where(eq(todos.id, id))` — `eq` Drizzle ka equality operator, `drizzle-orm` se import. Bina where ke update/delete **saari rows** pe lag jaata — SQL ka rule (Mongo mein `findByIdAndUpdate(id, ...)` id function parameter mein tha, isliye SQL mein where explicit dena padta hai).

**File:** `app/actions.ts` (createTodo ke neeche add) — line-by-line:

```ts
// app/actions.ts
"use server";

import { db } from "@/db";
import { todos } from "@/db/schema";
import { eq } from "drizzle-orm";           // NEW
import { revalidatePath } from "next/cache";
```

**`eq` import** — nayi line, `drizzle-orm` se (abhi tak `desc` use kiya tha, ab `eq`). Baaki imports wahi. Ab toggle action:

```ts
export async function toggleTodo(formData: FormData) {    // NEW
  const id = Number(formData.get("id"));
```

**`toggleTodo`** — naya action. **`Number(formData.get("id"))`** — form data string, `id` number column — convert zaroori (upar wala sawaal). Ab update:

```ts
  await db
    .update(todos)
    .set({ done: true })
    .where(eq(todos.id, id));
```

**`db.update(todos).set({ done: true }).where(eq(todos.id, id))`** — SQL `UPDATE drizzle_todos SET done = true WHERE id = ...`. `eq(todos.id, id)` — "jis row ki id equals hai". Ab refresh:

```ts
  revalidatePath("/");
}
```

**`revalidatePath("/")`** — wahi 6.11.2 wala pattern. Ab delete action:

```ts
export async function deleteTodo(formData: FormData) {    // NEW
  const id = Number(formData.get("id"));

  await db.delete(todos).where(eq(todos.id, id));

  revalidatePath("/");
}
```

**`db.delete(todos).where(eq(todos.id, id))`** — SQL `DELETE FROM drizzle_todos WHERE id = ...`. `where()` yahan bhi zaroori — bina where ke **saari rows** delete ho jaati. Same shape: id convert → query → revalidate.

**File:** `app/page.tsx` — har todo ke saath action buttons (form mein id hidden field ke saath):

## Nutshell

Toggle + Delete SQL phase mein: `app/actions.ts` mein `toggleTodo` aur `deleteTodo` — `Number(formData.get("id"))` se id convert (form string, SQL column number), `db.update().set({ done: true }).where(eq(todos.id, id))` / `db.delete(todos).where(eq(todos.id, id))` — `where` bina saari rows pe lag jaata hai, `revalidatePath("/")` se refresh. Page mein har todo ke `<li>` ke andar apna form + `<input type="hidden" name="id">` se action ko id milti hai.

## What It Is NOT

- **`db.update().set()` bina `where()` = "pura table update" nahi.** Bilkul — SQL mein bina where ke update/delete saari rows pe apply hota hai. `eq(todos.id, id)` zaroori hai. Mongo ka `findByIdAndUpdate(id, ...)` yeh automatically handle karta tha — SQL mein explicit.
- **`Number(formData.get("id"))` = optional nahi.** Form data hamesha string hota hai — SQL column number. Bina Number() ke `eq(todos.id, "3")` type error/query fail — convert zaroori.
- **Hidden input = "user ke liye koi cheez" nahi.** `<input type="hidden">` user ko dikhta nahi — bas form submit pe uski value `formData` mein jaati hai, action use padhta hai. `name="id"` us field ki key hai.

</details>

2. `Number(formData.get("id"))` — `Number()` kyun lagana padta hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Form ka data hamesha string hota hai — `formData.get("id")` string deta hai. SQL ka `id` column number hai (SERIAL). `Number()` string ko number mein convert karta hai — bina iske `eq(todos.id, "3")` type mismatch — query fail.
