# SQL Todo — Part 2: Create (Server Action + Form)

## Step 3 — Write: Create a Server Action

**THINK:** Now we need to add a new todo. **In the Mongo phase** there was a POST route + fetch + JSON body. **Here?** A Server Action — a server function that a form calls. The form directly calls the action — no API URL, no fetch, no JSON parsing.

**CONCEPT:** Server Action (seen in Batch 2, used in 5.x). Functions in a file with `"use server"` — called from a form `<form action={...}>`. Form data comes in as `formData`.

## Nutshell

Creating in the SQL phase: in `app/actions.ts`, a file with `"use server"` + `createTodo(formData)` — `formData.get("title")` gets the value, empty check rejects, `db.insert(todos).values(...)` inserts, then `revalidatePath("/")` refreshes the UI. On the page, `<form action={createTodo}>` + `name="title"` input — the form itself carries data to the action, no fetch/JSON needed.

## What It Is NOT

- **Server Action = "REST endpoint replacement"** is not accurate. Server Actions are for form/data mutations — direct server function calls. REST is for when external clients consume data (mobile, public API). Different use-cases — that's why the phases were separated (intro of 6.11.1).
- **`revalidatePath` = "page refresh magic button"** is not accurate. The data changed, the old render is stale. `revalidatePath` tells Next.js to re-render that route on the server. Without it, the new data is in the database but the page stays old.

**In Your Own Words**

1. Why is `revalidatePath("/")` needed after `db.insert(todos).values(...)`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The data changed in the database, but the page's rendered output is cached/stale. `revalidatePath("/")` tells Next.js to re-render that route on the server — that's when the new todo shows up in the UI. Without it, the new data is in the database but the page still shows the old render.

</details>

2. The form's input has `name="title"` and the action reads `formData.get("title")` — what's their relationship?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The input's `name` attribute becomes the key — when the form submits, all inputs' key-value pairs go into `formData`, and `formData.get("title")` retrieves that same value by key. If the names don't match, `title` comes back undefined — so both must use the same name.

</details>

3. In the Mongo phase, POSTing required sending a JSON body. Why not with Server Actions?

<details>
<summary>Show Answer</summary>

**Sample Answer:** In the Mongo phase, the client was on a different machine from the server — data needed to reach the server via network + a JSON body. Server Actions run on the server — the form's data goes into `formData` directly to the action, no network call, no JSON conversion.

</details>

4. Why doesn't `db.insert(todos)` pass `done`, yet a todo still gets created?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Because the schema (6.10) has `done` defaulting to `false` — Drizzle inserts the default value when no value is provided. Only the fields that need changing are sent, the rest is handled by the schema.

</details>
