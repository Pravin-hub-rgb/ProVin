6.11.1 mein Read ready hai — `db.select()` se todos server pe render ho rahe hain. Par abhi ek problem hai: **user naya todo kaise banayega?** 6.7.2 (Mongo) mein POST route + AddTodoForm + fetch tha. Yahan pattern alag hai — **Server Action** se Create. 6.11.1 ka Read server pe tha, mutations (Write) bhi server pe hi hongi — bas forms se action call hoga.

# SQL Todo — Part 2: Create (Server Action + Form)

## Step 3 — Write: Server Action Banao

**SOCH:** Ab naya todo add karna hai. **Mongo phase mein** POST route + fetch + JSON body bhejta tha. **Yahan?** Server Action — ek server function jo form submit pe chalata hai. Form seedha action ko call karta hai — koi API URL nahi, koi fetch nahi, koi JSON parse nahi.

**CONCEPT:** Server Action (Batch 2 mein the, 5.x mein bhi use kiye the). `"use server"` file mein functions — form `<form action={...}>` se call. Form ke data `formData` se milte hain.

Ek sawaal: **form ka data action tak kaise pahunchta hai?** `formData` — form ke saare inputs ki key-value pairs. Input ka `name` attribute key hota hai — `name="title"` wala input `formData.get("title")` se milta hai. Isliye form (Step 4) mein input ka naam `title` rakhna hi padta hai, warna data nahi milega.

**File:** `app/actions.ts` (nayi file) — ab file banate hain ek-ek line.

Pehle `"use server"` directive — file ke saare exports server actions ban jaate hain (Batch 2 pattern). Saath mein imports — `db` aur `todos` wahi jo 6.11.1 mein use kiye, aur naya `revalidatePath` (`next/cache` se — mutation ke baad UI refresh ke liye):

```ts
// app/actions.ts
"use server";

import { db } from "@/db";
import { todos } from "@/db/schema";
import { revalidatePath } from "next/cache";
```

**`"use server"`** — file ke saare exports server actions ban jaate hain (Batch 2 pattern). **Imports** — `db` aur `todos` wahi jo 6.11.1 mein use kiye. Naya import **`revalidatePath`** — `next/cache` se, mutation ke baad UI refresh ke liye (neeche milega).

Ab action function banao — `createTodo(formData)` form submit pe Next.js isse call karta hai, form data `formData` mein aata hai. `formData.get("title")` input se value leta hai (input ka `name="title"` hona chahiye), `as string` — TS ko batao string hai:

```ts
// app/actions.ts
"use server";

import { db } from "@/db";
import { todos } from "@/db/schema";
import { revalidatePath } from "next/cache";

export async function createTodo(formData: FormData) {    // NEW
  const title = formData.get("title") as string;
```

**`createTodo(formData)`** — form submit pe Next.js isse call karta hai, form data `formData` mein aata hai. **`formData.get("title")`** — input se value (input ka `name="title"` hona chahiye). `as string` — TS ko batao string hai.

Ab validation — `!title || title.trim() === ""` — empty ya sirf spaces reject (6.7.2 wala pattern, wahi check):

```ts

    return;
  }
```

**Validation** — `!title || title.trim() === ""` — empty ya sirf spaces reject (6.7.2 wala pattern, wahi check).

Ab asli insert — **`db.insert(todos)`** — insert query shuru karta hai (argument = kis table mein, yahan `todos`). **`.values({ title: title.trim() })`** — argument = kaunsa column kaunsa value (data object). Poora chain SQL `INSERT INTO drizzle_todos (title) VALUES (...)`. `done` nahi diya — schema default `false` (6.10):

```ts
// app/actions.ts
"use server";

import { todos } from "@/db/schema";
import { revalidatePath } from "next/cache";

export async function createTodo(formData: FormData) {
  const title = formData.get("title") as string;

  if (!title || title.trim() === "") {
    return;
  }

  await db.insert(todos).values({ title: title.trim() });    // NEW
```

**`db.insert(todos).values(...)`** — `db.insert(todos)` = insert query shuru (kis table mein), `.values({ title })` = data object (column → value). Poora chain SQL `INSERT INTO drizzle_todos (title) VALUES (...)`. `done` nahi diya — schema default `false` (6.10). **Mongo `Todo.create()` vs yahan `db.insert()`** — same kaam.

Aur last — `revalidatePath("/")` — data change hua, page ka cached render purana hai — Next.js ko bolo "/" ko dobara render karo. Bina iske naya todo database mein ho par page purana dikhata rahega:

```ts

Step 3 ka action ab use karna hai — koi fetch nahi, koi JSON body nahi, form hi data lekar action tak jaata hai.

**File:** `app/page.tsx` — 6.11.1 wali file mein form ka hissa add karna hai. Ab step-by-step.

## Nutshell

Create SQL phase mein: `app/actions.ts` mein `"use server"` file + `createTodo(formData)` — `formData.get("title")` se value, empty check, `db.insert(todos).values(...)`, phir `revalidatePath("/")` se UI refresh. Page mein `<form action={createTodo}>` + `name="title"` input — form hi data action tak le jaata hai, koi fetch/JSON nahi.

## What It Is NOT

- **Server Action = "REST endpoint ka replacement" nahi.** SA form/data mutations ke liye hai — direct server function call. REST unke liye hai jo URL se API consume karte hain (Postman, mobile). Alag use-cases — isliye phase alag banaye the (6.11.1 intro).
- **`revalidatePath` = "page refresh ka magic button" nahi.** Data change hua toh purana render galat hai — `revalidatePath` Next.js ko bolta hai is route ko dobara server pe render karo. Bina iske naya data UI mein nahi dikhega.

1. `db.insert().values({ title })` ke baad `revalidatePath("/")` kyun zaroori hai?

**Sample Answer:** Data database mein change ho gaya, par page ka render pehle se cached/rendered hai. `revalidatePath("/")` Next.js ko bolta hai route ko dobara server pe render karo — tab naya todo UI mein aayega. Bina iske naya data database mein ho par page purana dikhata rahega.

</details>

2. Form ke input ka `name="title"` aur action ka `formData.get("title")` — inka kya sambandh hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Input ka `name` attribute key hota hai — form submit hote hi saare inputs ki key-value pairs `formData` mein banti hain, aur `formData.get("title")` usi key se value nikalta hai. Naam mismatch hua toh `title` undefined milega — isliye dono ka naam match karna zaroori hai.

</details>

3. Mongo POST mein JSON body bhejna padta tha, Server Action mein kyun nahi?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Mongo mein client alag machine pe tha — data server tak pahunchane ke liye network + JSON body chahiye thi. Server Action server pe hi chalta hai — form ka data `formData` mein action ko seedha mil jaata hai, koi network call, koi JSON conversion nahi.

</details>

<details>
<summary>Show Answer</summary>

**Sample Answer:** Kyunki schema (6.10) mein `done` ka default `false` hai — Drizzle insert ke waqt us column mein default value daal deta hai. Sirf jo badalna hai wahi dete hain, baaki schema sambhal leta hai.

</details>
