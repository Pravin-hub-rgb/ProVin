4.7 mein ek jhalak dikhi thi: `response.headers.set()` — response ko modify karna. Ab usko practically karenge — aur saath mein ek power move: **`headers()` API se Server Component mein wahi values read karna.** Yahan ek problem solve hoti hai jo pehle impossible thi: **layout ko current pathname ka pata chalta hai.**

---

## Response Headers Kya Hote Hain

Request headers browser→server (4.5 wale). **Response headers server→browser** — reverse direction. Jaise request mein label hota hai, waise hi response mein bhi — status, content-type, cache... aur **custom bhi add kar sakte ho.**

Custom headers ka convention: `x-` prefix (jaise `x-hello`, `x-pathname`) — "yeh standard HTTP header nahi, hamara custom hai" ka signal.

---

## Step 1 — Proxy Mein Custom Headers Add Karna

4.7 wala pattern yaad karo — **pehle response save, phir modify, phir return:**

```ts
import { NextRequest, NextResponse } from "next/server"

export function proxy(request: NextRequest) {
  const response = NextResponse.next()
  response.headers.set("x-hello", "world")
  response.headers.set("x-pathname", request.nextUrl.pathname)
  return response
}

export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"],
}
```

- `NextResponse.next()` ko variable mein save — kyunki modify karna hai (4.7 wala point).
- `response.headers.set("x-hello", "world")` — static value.
- `response.headers.set("x-pathname", request.nextUrl.pathname)` — **dynamic value** — har request ka pathname.

**Verify (curl se):**

```bash
curl -D - http://localhost:3000/about | grep "x-"
```

```
x-hello: world
x-pathname: /about
```

Response headers mein dono dikhe — browser/client inhe dekh sakta hai.

---

## Step 2 — Server Component Mein Read Karna: `headers()` API

Ab jawaab do: **yeh custom headers components mein kaise padhenge?** — `headers()` from `next/headers`:

```tsx
// app/layout.tsx
import { headers } from "next/headers"

export default async function RootLayout({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  const headersList = await headers()
  const pathname = headersList.get("x-pathname")

  return (
    <html lang="en">
      <body>
        <div>Current pathname: {pathname ?? "unknown"}</div>
        {children}
      </body>
    </html>
  )
}
```

**Naye pieces:**

- `import { headers } from "next/headers"` — Server Components/Route Handlers ke andar request data access karne ka API (Batch 3 mein `cookies()` ka pattern tha — same family).
- `await headers()` — **async call** (Next 15+ API — purani tutorials mein bina await ke dikhega). Layout bhi `async` ho gaya.
- `headersList.get("x-pathname")` — 4.5 wala `.get()` pattern — value ya null.

**Test:** `/about` kholo → layout mein "Current pathname: /about" dikhega. `/dashboard` → `/dashboard`.

---

## Yeh Kyun Power Move Hai — Layout Ko Pathname Ka Pata

Socho: layout har page pe render hota hai — layout ke andar `usePathname()` **nahi chalta** (client hook), `window.location` bhi nahi (server). Toh layout ko kaise pata chale ki **kaunsa page render ho raha hai?**

Ek tarika: har page khud pathname pass kare — 10 pages, 10 baar. Ugh.

**Proxy wala tarika:** proxy ko request ka pathname pata hai (4.4) → response header mein daal do → layout `headers()` se read karta hai. **Ek jagah, sab pages.** Yahi pattern hai: proxy jo jaanta hai, usko components tak pahunchao — bina har component ko khud puchna pade.

---

## `response.cookies.set()` — Bonus

Same pattern cookies ke saath bhi: response pe cookie **set** kar sakte ho (request cookies sirf padhna aata tha, 4.6):

```ts
const response = NextResponse.next()
response.cookies.set("theme", "dark", {
  httpOnly: true,
  maxAge: 60 * 60 * 24 * 30,   // 30 din
  sameSite: "lax",
})
return response
```

`cookies.set` — response mein `Set-Cookie` header add karta hai. Options (httpOnly, maxAge, sameSite) — cookie ke attributes jo 4.6 mein request cookies se pehle sahi tarike se samjhe. Kab kaunsa — context alag: Server Action/Route Handler ke response mein `cookies().set` (aage Batch 5 mein login system wahan hoga), proxy = har request ke response mein.

## What It Is NOT

- **`headers()` response headers hi nahi padhti** — technically yeh request headers padhti hai; proxy ke response headers bhi isi flow mein accessible hote hain (Next.js inhe render context mein pass karta hai). Practical baat: **proxy mein set → layout mein get — works.** (Ultra edge-cases: kuch headers server framework filter kar sakta hai — `x-` custom ones safe hain.)
- **`headers()` client component mein nahi chalta** — server-only API. Client ko value chahiye toh server se prop/provide karo.
- **Custom headers browser-visible hain** — `x-` headers public hain (browser DevTools mein dikhte). Secret data unme mat daalo.
- **Har request pe `headers()` call = dynamic rendering** — layout static nahi rahega (har request pe render hoga) — iska tradeoff soch kar use karo.

## Common Mistakes

- **`await headers()` bhoolna** — Next 15+ mein promise hai — bina await ke object nahi milega.
- **Layout async banana bhoolna** — `await` kar rahe ho toh layout bhi `async` function hona chahiye.
- **`headers.set` ko `NextResponse.next()` pe turant chain karna** — `return NextResponse.next().headers.set(...)` galat pattern — pehle save, phir modify, phir return.
- **Secret values custom headers mein** — headers client ko dikhte hain — API keys wagera server-side hi rehne chahiye.
- **`headers()` ka import galat** — `next/headers` se hai, `next/server` se nahi.

## Nutshell

Proxy: `response.headers.set("x-name", value)` — response headers add (static ya dynamic). Layout/Server Component: `await headers()` → `.get("x-pathname")`. Pattern: proxy jaanta hai (pathname) → header mein daalo → component read karta hai. Bonus: `response.cookies.set(...)` — wahi Set-Cookie pattern, proxy level pe.

**In Your Own Words**

1. Request headers aur response headers ka direction kya hai — custom headers ka `x-` prefix kya signal deta hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Request headers browser→server jaate hain (User-Agent, Cookie — 4.5/4.6 wale), response headers server→browser (status, content-type, Set-Cookie). `x-` prefix custom headers ka convention hai — "yeh standard HTTP header nahi, hamari app ka apna hai" — taaki standard headers se confuse na ho. `x-pathname` dekhte hi pata chalta hai: yeh Next.js ka default nahi, proxy ne daala hai.

</details>

2. `response.headers.set("x-pathname", request.nextUrl.pathname)` — yahan dynamic value kahan se aa rahi hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Proxy ko `request` milta hai — aur `request.nextUrl.pathname` (4.4 wala) har request ka apna path deta hai. `/about` pe `/about`, `/dashboard` pe `/dashboard`. Static value (`"world"`) har request pe same, dynamic value (`pathname`) har request pe alag — isliye ek hi proxy har page ke liye sahi pathname header bana deti hai.

</details>

3. Layout ko pathname kaise milta hai proxy se — bina proxy ke kya karna padta?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Proxy pathname ko response header (`x-pathname`) mein daal deta hai. Layout `await headers()` karke `.get("x-pathname")` se usko read karta hai. Bina proxy ke layout ko pathname nahi milta: `usePathname()` client hook hai (layout server hai), `window.location` browser cheez hai (server pe nahi) — isliye har page ko khud pathname pass karna padta (10 pages, 10 baar). Proxy ek jagah se sab components ko batata hai.

</details>

4. `await headers()` — yeh async kyun hai, aur layout ko bhi async kyun banana padta?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Next 15+ mein `headers()` promise return karta hai — isliye `await` karna padta hai (purani tutorials bina await ke thi, ab nahi). Aur `await` kisi bhi function ke andar kar rahe ho toh woh function bhi `async` hona chahiye — isliye RootLayout `async` function hai. Yaad rakho: await headers() + async layout = naya pattern, purani docs ke against mat compare karna.

</details>

5. Custom headers mein secret values kyun nahi daalni chahiye — aur `headers()` pe dynamic rendering ka kya fark padta hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Response headers browser ko dikhte hain — DevTools mein sab visible. Secret (API key, token) daala toh user use dekh + exploit kar sakta hai — secrets server-side rehne chahiye (env vars). Aur `headers()` read karne se page dynamic ho jaata hai — har request pe render hota hai, static caching nahi — performance tradeoff. Isliye headers pattern tab use karo jab dynamic value genuinely har request pe chahiye (jaise pathname).

</details>
