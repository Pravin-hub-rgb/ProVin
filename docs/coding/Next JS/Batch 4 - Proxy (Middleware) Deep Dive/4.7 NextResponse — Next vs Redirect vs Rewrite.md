Ab woh gate kholte hain: **`NextResponse`** — response banana wali class. Isme teen main methods hain — `next()`, `redirect()`, `rewrite()` — aur inka fark hi proxy ka fark hai. Shopping-mall wali kahani se samjhte hain.

## NextResponse Kya Hai

`NextResponse` = Next.js ki class jo proxy ke andar **response banane** ke liye hai. Har proxy function ek response return karta hai — aur woh response inhi methods se banta hai.

`next/server` se import hota hai (4.2 mein pehle hi use kiya):

```ts
import { NextResponse } from "next/server"
```

Teen methods — teen alag kaam:

| Method | Matlab | URL ka kya hota hai |
|---|---|---|
| `NextResponse.next()` | "Check ho gaya — aage bhejo" | Wahi URL, wahi page |
| `NextResponse.redirect(url)` | "Yahan nahi — is URL pe jao" | **Badal jaata hai** (browser naya URL load karta hai) |
| `NextResponse.rewrite(url)` | "Yahan ka content doosre route se lao" | **Wahi rehta hai** (browser ko pata hi nahi chalta) |

---

## Shopping-Mall Security Guard Ki Kahani

Ek mall mein guard teen tarah ke instructions de sakta hai:

**`next()` — "Theek hai, andar jaao."**
Visitor ko koi fark nahi padta — woh seedha apni jagah jaata hai. Proxy ka default response — kuch nahi badla.

**`redirect()` — "Nahi, woh gate se jaao."**
Guard visitor ko **doosre gate** pe bhejta hai — visitor **URL mein** woh naya gate dekh ke wahan jata hai, aur phir wahan naya flow hota hai. Example: user ne `/dashboard` khola, par login nahi hai → guard bolta hai `/login` pe jao → browser ka URL `/login` ho jata hai, `/dashboard` khatam.

**`rewrite()` — "Yahan ruko, main content laata hoon."**
Guard visitor ko rokta hai, lekin khud **andar se alag samaan** laakar deta hai — visitor ko pata hi nahi chalta ki original jagah se alag cheez mili. URL wahi rehta hai, content alag. Example: `/home` kholo → rewrite se `/home-v2` ka content milega — lekin browser URL mein hamesha `/home` hi dikhega.

**Ek sentence mein:** redirect = "URL badal ke dusri jagah", rewrite = "URL wahi, content doosri jagah se".

## Code Mein Teenon — Side By Side

```ts
import { NextRequest, NextResponse } from "next/server"

export function proxy(request: NextRequest) {
  const pathname = request.nextUrl.pathname

  // 1. next() — aage bhejo
  if (pathname === "/about") {
    return NextResponse.next()
  }

  // 2. redirect() — dusri jagah bhejo (URL badlega)
  if (pathname === "/dashboard") {
    return NextResponse.redirect(new URL("/login", request.url))
  }

  // 3. rewrite() — content doosri jagah se lao (URL wahi)
  if (pathname === "/home") {
    return NextResponse.rewrite(new URL("/home-v2", request.url))
  }

  return NextResponse.next()
}
```

**(Abhi `new URL(path, base)` ka syntax mat pucho — 4.8 mein detail. Bas pattern dikh raha hai.)**

## NextResponse Ke Saath Aur Do Cheezein

`next()`/`redirect()`/`rewrite()` ke alawa response pe do aur kaam hote hain:

```ts
const response = NextResponse.next()          // pehle response banao
response.headers.set("x-hello", "world")      // response ke headers mein add karo (4.10)
response.cookies.set("theme", "dark")         // response ke cookies mein add karo
return response
```

**Pattern notice karo:** pehle response **variable mein save**, phir `headers.set`/`cookies.set` se modify, phir return. (Seedha `return NextResponse.next()` pe set nahi kar sakte.) 4.10 mein `headers.set` ka full use case milega.

## What It Is NOT

- **`NextResponse` proxy-only nahi** — Route Handlers mein bhi use hota hai (Batch 3 mein `route.ts` ke responses wahi the — `NextResponse.json()` wagera). Class common hai, proxy ka context alag.
- **redirect vs rewrite "dono browser pe kuch na kuch karte hain" — confusion mat karo** — difference **URL**: redirect browser ko naya URL load karne bolta hai (URL badalta hai, purana page khatam), rewrite server-side hi content swap karta hai (URL wahi, browser ko pata nahi).
- **`next()` ka matlab "page render karo" nahi** — kaam "aage badho" hai — jo bhi original destination tha usi ko continue karna.

## Common Mistakes

- **Rewrite ko redirect samajhna** — 4.9 mein A/B testing aur maintenance page wale use-cases milenge — wahan farak pakka ho jayega.
- **Response variable save karna bhoolna** — `NextResponse.next()` ko modify karna hai toh pehle variable mein lo, phir `.headers.set()` — ek line mein nahi.
- **`NextResponse.next()` ko optional samajhna** — proxy ka har path kuch na kuch return kare (next/redirect/rewrite) — kuch bhi return na kiya toh request hang (4.2 wala point).

## Nutshell

`NextResponse` — proxy ka response builder. `next()` = aage, `redirect()` = URL badal ke bhej, `rewrite()` = URL wahi content alag. Response pe `headers.set`/`cookies.set` bhi hota hai. Ab teeno ka actual implementation — agle teen notes mein ek ek karke.

**In Your Own Words**

1. `next()`, `redirect()`, `rewrite()` — ek line mein fark batao.

<details>
<summary>Show Answer</summary>

**Sample Answer:** `next()` = "check ho gaya, aage bhejo" (kuch nahi badla). `redirect()` = "dusri jagah jao" — browser URL badal ke naya URL load karta hai (purana page khatam). `rewrite()` = "content doosri jagah se lao" — server-side content swap, URL wahi rehta hai aur browser ko pata nahi chalta. Redirect URL-level decision hai, rewrite content-level.

</details>

2. Redirect mein URL kyun badalta hai — browser ke perspective se kya hota hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Redirect response browser ko `Location` header ke saath naya URL batata hai (307 status). Browser woh naya URL **load karta hai** — jaise user ne khud address bar mein naya URL type kiya ho. Isliye purana page (e.g. `/dashboard`) browser mein khatam ho jaata hai aur `/login` render hota hai — user ko URL change bhi dikhta hai.

</details>

3. Rewrite ka real scenario batao jahan URL change na ho par content alag chahiye.

<details>
<summary>Show Answer</summary>

**Sample Answer:** A/B testing: `/home` pe do versions (`/home-v2`) test ho rahe hain — kuch users ko v2 dikhana hai, par URL hamesha `/home` hi rehna chahiye (warna user ko dikhega ki "main v2 pe hoon" aur results biased honge). Maintenance page bhi: site under maintenance hai toh kisi bhi URL pe rewrite se maintenance page — par URL waise hi dikhega. 4.9 mein dono milenge.

</details>

4. `response.headers.set()` ke liye pehle response variable mein save kyun karna padta hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Kyunki `NextResponse.next()` ek expression hai — uska result modify karna hai toh pehle use variable mein rakho (`const response = NextResponse.next()`), phir `response.headers.set(...)` call karo, phir `return response`. `return NextResponse.next()` pe turant return ho jaata hai — beech mein set karne ka mauka nahi. Save → modify → return, yehi pattern hai.

</details>

5. `NextResponse` Route Handlers mein bhi use hota hai — proxy wale use se kya farak hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Class same hai, kaam ka context alag. Route Handler (`route.ts`) mein `NextResponse` se API ka response banta hai — data return karna (JSON, status codes) — wahan request pehle se route tak aa chuki hoti hai. Proxy mein `NextResponse` har incoming request pe page render hone se pehle decide karta hai — aage jana hai, redirect karna hai, rewrite karna hai. Ek API ka response builder, doosra interception layer ka decision tool.

</details>
