# `NextResponse` — Next vs Redirect vs Rewrite (4.7)

## Where We Left Off

From 4.2 through 4.6 we have been a **reader** of the request — URL (`pathname`, `searchParams`), headers (`user-agent`, IP), and cookies (`has`, `get`). But reading without acting changes nothing. The real power is the proxy **answering** the request. That happens through `NextResponse` — the class for building the proxy's decision. There are three core tools: `next()`, `redirect()`, and `rewrite()`. Understanding the difference between them is the essence of what the proxy can do. Let's use the shopping-mall security analogy.

---

## What Is `NextResponse`

`NextResponse` is Next.js's class for constructing **the response** the proxy sends back. Every proxy function must return a response, and that response is built with `NextResponse`. It is imported from `next/server` (used already in 4.2):

```ts
import { NextResponse } from "next/server"
```

Three core methods — three different decisions:

| Method | Meaning | What the browser sees |
|---|---|---|
| `NextResponse.next()` | "Check complete — forward to destination" | The same URL, the same page |
| `NextResponse.redirect(url)` | "Go to this URL instead" | **The URL changes** — browser loads the new URL |
| `NextResponse.rewrite(url)` | "Serve content from this URL, keep the current one" | The **same URL** — content swapped silently |

---

## The Shopping-Mall Security Analogy

A mall guard can give three kinds of instructions:

**`next()` — "Looks good, proceed."**
The visitor enters normally — nothing changes. This is the proxy's default, "pass-through" response.

**`redirect()` — "Go to this entrance instead."**
The guard sends the visitor to a different entrance. The visitor **sees the new entrance** — the address bar changes — and walks that way. If a user opens `/dashboard` without being logged in, the guard sends them to `/login`; the browser's URL becomes `/login`, and `/dashboard` is left behind.

**`rewrite()` — "Step aside, I'll get your item."**
The guard stops the visitor at the same entrance but fetches the item from a different location. The visitor **never sees the switch** — they stay at the original entrance, but receive different content. If you open `/home` and the guard swaps in the `/home-v2` layout, the URL bar stays `/home` while the page content is actually from `home-v2`.

**One-line distinction:** redirect = "change the URL"; rewrite = "same URL, different content."

---

## All Three Side by Side in Code

```ts
import { NextRequest, NextResponse } from "next/server"

export function proxy(request: NextRequest) {
  const pathname = request.nextUrl.pathname

  // 1. next() — forward as-is
  if (pathname === "/about") {
    return NextResponse.next()
  }

  // 2. redirect() — send to a new URL (URL changes)
  if (pathname === "/dashboard") {
    return NextResponse.redirect(new URL("/login", request.url))
  }

  // 3. rewrite() — same URL, different content
  if (pathname === "/home") {
    return NextResponse.rewrite(new URL("/home-v2", request.url))
  }

  return NextResponse.next()
}
```

**(Don't ask about `new URL(path, base)` yet — 4.8 covers it. For now, note the shape: pass a URL object.)**

## `NextResponse` Also Carries Headers and Cookies

Beyond the three factories, `NextResponse` lets you attach data to the outgoing response:

```ts
const response = NextResponse.next()          // build the response first
response.headers.set("x-hello", "world")      // attach a custom header (4.10)
response.cookies.set("theme", "dark")         // attach a cookie
return response
```

**Notice the pattern:** build the response into a variable first, then attach things, then return it. You can not chain `.headers.set()` directly onto `return NextResponse.next()`. 4.10 covers the full use case of `headers.set`.

---

## What It Is NOT

- **`NextResponse` is not proxy-only.** Route Handlers use the same class to build API responses (`NextResponse.json()`, as seen in Batch 3's `route.ts`). Same tool, different context.
- **Redirect and rewrite are not "both visibly change something."** The differentiator is the URL: redirect makes the URL change; rewrite keeps it the same and silently swaps content.
- **`next()` does not mean "render the page."** It means "continue to whatever the destination was." Whether that destination is a page, an API route, or nothing at all — it is "no decision made," not "make a page."

## Common Mistakes

- **Using `rewrite` where the URL should change.** Login flows must redirect so the browser shows `/login` — rewriting there hides the navigation and confuses the user.
- **Returning without a response.** Every code path must return `next`, `redirect`, or `rewrite`. Falling off the end returns `undefined`, and the request hangs.
- **Trying to chain on `NextResponse.next()` directly.** `return NextResponse.next().headers.set(...)` does not work — assign to a variable first.
- **Confusing the three with each other at a glance.** Keep the shopping-mall analogy in mind: redirect = send to another door; rewrite = swap the contents behind the same door.

## Nutshell

`NextResponse` builds the proxy's answer. `next()` forwards unchanged; `redirect()` makes the browser go to a new URL; `rewrite()` keeps the URL but swaps the content. Headers and cookies can be attached by building the response into a variable first. Every code path returns one of these.

**In Your Own Words**

1. In one line, how do `next()`, `redirect()`, and `rewrite()` differ?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `next()` forwards with no change; `redirect()` sends the browser to a new URL (the URL bar updates); `rewrite()` keeps the URL but serves content from elsewhere (silent swap).

</details>

2. Why does `redirect()` change the URL in the browser?

<details>
<summary>Show Answer</summary>

**Sample Answer:** The redirect response returns a `307` (or `302`) status with a `Location` header pointing to the new URL. The browser treats that as navigation instructions — it loads the new URL, so the address bar and history reflect the destination, and the page that triggered the redirect is left behind.

</details>

3. When would you choose `rewrite()` over `redirect()`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** When you want to keep the address private. Examples: A/B testing (show `/home-v2` content under the `/home` URL so visitors can't tell which variant they got), or a maintenance page (serve it under any URL so the URL stays consistent).

</details>

4. Why assign `NextResponse.next()` to a variable before calling `.headers.set()`?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `return NextResponse.next()` returns immediately, so there is no object to modify. By assigning first (`const response = NextResponse.next()`), you get a mutable response object, call `response.headers.set(...)` on it, and then `return response`. It is the build-then-decorate pattern.

</details>

5. Is `NextResponse` only for the proxy?

<details>
<summary>Show Answer</summary>

**Sample Answer:** No. Route Handlers use it too — `NextResponse.json(...)` builds API responses. The class is shared; the proxy uses it to decide routing, the route handler uses it to return data. Same tool, different jobs.

</details>
