4.3 mein matcher samjha — proxy kahan chalega ka control. Ab **proxy ke andar kya milta hai** — request ka data hi decisions ka input hai. Pehle sabse obvious: URL. `request.nextUrl` mein poora URL hai — aaj `pathname` aur `searchParams` padhenge, aur `.startsWith()` se checks karne ka pattern.

---

## `request.nextUrl` Kya Hai?

Proxy mein `request` milta hai — `NextRequest` type ka — aur iske andar ek property hai: **`nextUrl`** — poora URL object. Pehle console.log karke dekho asli data:

```ts
import { NextRequest, NextResponse } from "next/server"

export function proxy(request: NextRequest) {
  console.log(request.nextUrl)
  return NextResponse.next()
}

export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"],
}
```

Browser mein visit karo:

```
http://localhost:3000/dashboard?tab=settings&user=123
```

Terminal mein kuch aisa dikhega:

```js
URL {
  href: 'http://localhost:3000/dashboard?tab=settings&user=123',
  pathname: '/dashboard',
  search: '?tab=settings&user=123',
  searchParams: URLSearchParams { 'tab' => 'settings', 'user' => '123' },
  ...
}
```

Bahut saari properties hain (href, host, origin, protocol...) — series mein `pathname` aur `searchParams` kaam aayenge.

---

## `pathname` — URL Ka Path

URL ka structure:

```
http://localhost:3000/dashboard?tab=settings
                      ↑              ↑
                  pathname        search
```

`pathname` = domain ke baad, `?` se pehle wala part:

```ts
const pathname = request.nextUrl.pathname
console.log(pathname) // → "/dashboard"
```

**Practical use** — user kaunse page pe ja raha hai, yahi to check karna hai:

```ts
export function proxy(request: NextRequest) {
  const pathname = request.nextUrl.pathname
  console.log("User ja raha hai:", pathname)
  return NextResponse.next()
}
```

```
/          → "User ja raha hai: /"
/dashboard → "User ja raha hai: /dashboard"
/profile   → "User ja raha hai: /profile"
```

---

## `searchParams` — Query Parameters

`?` ke baad wala part — `searchParams`:

```
http://localhost:3000/products?category=shoes&color=red
                                 ↑
                         yeh sab searchParams mein
```

`.get()` method se koi bhi parameter nikal lo:

```ts
export function proxy(request: NextRequest) {
  const pathname = request.nextUrl.pathname
  const category = request.nextUrl.searchParams.get("category")
  console.log("pathname:", pathname)
  console.log("category:", category)
  return NextResponse.next()
}
```

`searchParams.get("category")` — `get` string mein parameter ka naam le leta hai, value deta hai. Agar woh parameter URL mein **hai hi nahi** — `null` milta hai:

```
/products?category=shoes → category: "shoes"
/products               → category: null
```

---

## Combined — Condition URL Se

Ab combine karo — path se decision:

```ts
export function proxy(request: NextRequest) {
  const pathname = request.nextUrl.pathname

  if (pathname.startsWith("/dashboard")) {
    console.log("Dashboard route pe hai user")
  }

  return NextResponse.next()
}
```

`.startsWith("/dashboard")` — string method — "kya yeh string `/dashboard` se shuru hoti hai?" — `true`/`false`.

```
/dashboard          → "Dashboard route pe hai user" ✅
/dashboard/settings → "Dashboard route pe hai user" ✅  (prefix match)
/about              → kuch nahi ✅
```

`startsWith` isliye kaam ka hai kyunki `/dashboard/settings` jaisi children paths bhi cover ho jaati hain — exact compare ke bajaye prefix check. (4.3 ka matcher `:path*` URL level pe karta tha; `startsWith` logic level pe.)

---

## What It Is NOT

- **`searchParams` object normal object nahi** — woh `URLSearchParams` instance hai. `.get()` use karo, `searchParams.category` nahi.
- **`pathname` mein query nahi hoti** — `/dashboard?tab=settings` ka `pathname` sirf `/dashboard` hai. Domain bhi nahi hota — sirf path.
- **`request.url` aur `request.nextUrl` same nahi** — `request.url` raw URL string hai; `nextUrl` Next.js ka parsed object (pathname/searchParams ready-made). Proxy kaam `nextUrl` se hota hai.

## Common Mistakes

- **`pathname` ko exact compare karna** — `pathname === "/dashboard"` se `/dashboard/settings` miss ho jaati hai. Prefix chahiye toh `startsWith`.
- **`searchParams.get` ka result `null` check karna bhoolna** — parameter missing pe `null` aata hai; `"shoes" ?? "default"` jaisa fallback pattern 4.5 mein headers ke saath dekhenge.
- **Matcher pehle filter karta hai, phir proxy ka logic** — matcher mein `/dashboard` limit hai aur code mein `/about` ka check — code never chalta. Matcher aur logic ko ek saath socho.

## Nutshell

`request.nextUrl` = parsed URL object. `pathname` = path (`/dashboard`), `searchParams.get("key")` = query value (missing → `null`), `startsWith()` = prefix checks ke liye. Yahi hai proxy ka "user kahan ja raha hai" ka input.

**In Your Own Words**

1. `request.nextUrl.pathname` kis URL ka kaunsa hissa deta hai — ek example ke saath?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Domain ke baad, `?` se pehle wala part — sirf path. Example: `http://localhost:3000/dashboard?tab=settings` ka `pathname` sirf `/dashboard` hai — query (`?tab=settings`) aur domain dono isme nahi. Har request pe proxy ko bataata hai ki user kaunse page pe ja raha hai.

</details>

2. `searchParams.get("category")` ka return value kya hota hai — aur jab parameter URL mein nahi hota?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Parameter ki value string mein — `?category=shoes` pe `"shoes"`. Agar parameter URL mein hai hi nahi (`/products` bina query), toh `null` milta hai. Isliye result ko hamesha null-check karna chahiye ya fallback dena chahiye (`?? "default"`) — null ko seedha use karoge toh logic mein silent bugs aayenge.

</details>

3. `startsWith("/dashboard")` `=== "/dashboard"` se kyun behtar hai proxy checks ke liye?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Kyunki `===` exact string match karta hai — `/dashboard/settings` ko miss kar dega (woh alag string hai). `startsWith` prefix check hai — `/dashboard`, `/dashboard/settings`, `/dashboard/users/123` sab true. Proxy mein protected routes ke checks aise hi chahiye: ek root path, saare children bhi covered. Exact compare sirf tab jab ek exact page hi matter kare.

</details>

4. `request.url` aur `request.nextUrl` mein kya farak hai?

<details>
<summary>Show Answer</summary>

**Sample Answer:** `request.url` raw URL string hai — poora `http://localhost:3000/dashboard?tab=settings` ek string. `request.nextUrl` Next.js ka parsed URL object hai — pathname, searchParams, href sab ready-made properties. Proxy mein hume parsed chahiye hota hai (path/query alag nikalne ke liye) — isliye `nextUrl` preferred hai, `url` sirf base ke liye (4.8 mein `new URL(path, request.url)` mein base ke roop mein milega).

</details>

5. Matcher aur code mein `startsWith` — dono mein path checks ka kya relation hona chahiye?

<details>
<summary>Show Answer</summary>

**Sample Answer:** Matcher pehle decide karta hai ki request proxy tak pahunchegi ya nahi (routing-level filter), phir code ka `startsWith` decide karta hai ki us request pe kya karna hai (logic-level). Agar matcher `/dashboard` tak limit hai toh `/about` pe code ka check kabhi nahi chalega — dono consistent rakhne chahiye: matcher "kahan", code "kya". Code woh checks likho jo matcher ke scope mein already hain.

</details>
