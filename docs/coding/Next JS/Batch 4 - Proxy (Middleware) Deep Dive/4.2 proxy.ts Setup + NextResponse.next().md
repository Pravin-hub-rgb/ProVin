4.1 mein samjha — proxy kya hai, darwaze pe guard wali kahani, request lifecycle. Ab **asli file banate hain** — `proxy.ts` kahan banana hai, `NextRequest`/`NextResponse` kaam mein kaise aate hain, aur ek basic proxy chala ke verify karenge ki woh **sach mein har request pe chalta hai**.

---

## File Kahan Banate Hain?

Yeh zaroori hai pehle clear kar lo. Project structure kuch aisa hai:

```
my-app/
  app/
    page.tsx
    layout.tsx
  public/
  package.json
  next.config.ts
```

`proxy.ts` banana hai **project root** mein — matlab `app` folder ke **bahar** — `next.config.ts` ke saath wali jagah:

```
my-app/
  app/
    page.tsx
    layout.tsx
  proxy.ts        ← yahan
  public/
  package.json
  next.config.ts
```

**Kyun root mein?** — Next.js yahan specifically dhundhta hai — andar kisi aur jagah rakhoge toh ignore kar dega. Yeh framework ka convention hai.

---

## Step 1 — Sabse Basic Proxy

Pehle bas ek line:

```ts
console.log("proxy chala!")
```

Ab test karo — dev server chalao, koi bhi URL kholo.

**Error aayega** — "proxy function not found" ya kuch aisa.

**Kyun?** Next.js ko pata nahi chala kaun sa function run karna hai. `export default` karna padta hai — file ka main function:

```ts
export function proxy() {
  console.log("proxy chala!")
}
```

Ab test karo — **chal gaya!** Terminal mein "proxy chala!" print ho raha hai. (Baaki ke logs jaise `GET / 200 in 43ms` Next.js ke apne internal logs hain — proxy ke nahi.)

---

## Step 2 — Request Ki Information Padhna

Ab thoda aur detail — request ka **path** bhi print karna hai. Iske liye Next.js request ke andar ek special object deta hai — `nextUrl` — jiski property `pathname` URL ka path deti hai:

```ts
import { NextRequest, NextResponse } from "next/server"

export function proxy(request: NextRequest) {
  console.log("proxy chala!", request.nextUrl.pathname)
  return NextResponse.next()
}

export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico|.*\\.svg).*)"],
}
```

**Line by line:**

- `import { NextRequest, NextResponse } from "next/server"` — dono `next/server` se aate hain. `NextRequest` — request ka object type (URL, headers, cookies — sab isi ke andar). `NextResponse` — response banana wala class (agle phase mein detail).
- `export function proxy(request: NextRequest)` — Next.js is function ko **har request ke saath call** karta hai. `request` parameter mein poora request ka data milta hai. (`export default` ke bajaye named export bhi chalega — dono Next.js samajhta hai, default zyada common.)
- `request.nextUrl.pathname` — URL ka path part — `/`, `/about`, `/dashboard` wagera.
- `return NextResponse.next()` — yeh line zaroori hai. Abhi tak proxy sirf log kar raha tha — lekin request ko aage nahi bheja tha. `NextResponse.next()` ka matlab: "Maine check kar liya, ab **aage bhejo**". Bina is line ke request hang ho jayegi — page load nahi hoga.
- `config.matcher` — Next.js ko batata hai **kaunse routes pe proxy chale**. Yehi regex hai jo usually tutorials mein copy-paste milta hai, bina samjhe — 4.3 mein ise detail mein todenge. Abhi itna samjho: `_next/static|_next/image|favicon.ico|.*\\.svg` = "in cheezon ko CHHOD ke baaki sab pe proxy chalao" (Next.js ki JS/CSS files, optimized images, browser icon, SVG files).

---

## Step 3 — Verify: Proxy Sach Mein Har Request Pe?

Ab test karte hain — dev server chalao (`npm run dev`), phir browser mein `/` kholo:

```
http://localhost:3000
```

Terminal mein kuch aisa print hoga:

```
proxy chala! /
```

Bas `/` visit kiya — par static files ki entries **nahi** dikhengi — matcher ne unhe rok diya. Ab naye pages banao aur verify karo ki unpe bhi chalta hai:

`app/about/page.tsx`:

```tsx
export default function About() {
  return <h1>About Page</h1>
}
```

Ab visit karo:

```
http://localhost:3000/about
http://localhost:3000/dashboard   (banao app/dashboard/page.tsx, kuch bhi return karo)
```

Terminal mein:

```
proxy chala! /about
proxy chala! /dashboard
```

**Dekha?** — Dono pe chala. Tumne **ek hi jagah** likha — saari routes cover. Yahi proxy ka power hai: request pe common kaam ek baar likho, har route pe apply.

## Security Guard Wali Kahani (Reinforcement)

- Guard tumhe dekhta hai (proxy chala — request kahan ja rahi hai)
- Guard check karta hai (hamara abhi case: log — agle notes mein: checks)
- Guard kehta hai "proceed" (`NextResponse.next()`)
- Tum andar jaate ho (page render hota hai)

`NextResponse.next()` = guard ki "jaao" wali haath ki ishara.

---

## What It Is NOT

- **`NextResponse.next()` optional nahi** — bina uske request aage nahi jaati (browser hang/fail). Jab tak proxy kuch return nahi karti, Next.js nahi jaanta kya karna hai.
- **Proxy har request pe nahi chalta jab matcher ho** — matcher batata hai kab chale. `_next/static` etc. exclude ho jaate hain — isliye sirf pages wale log dikhte hain.
- **`request` ka type optional nahi** — TypeScript project mein `NextRequest` annotation daalna clean hai; bina annotation bhi chalega par type-safety kho jaati hai.

## Common Mistakes

- **File ko `app/` ke andar banana** — proxy root mein hai, `next.config.ts` ke saath. Galat jagah = Next.js ignore.
- **`return NextResponse.next()` bhoolna** — ya toh `next()` return karo, ya `redirect()`/`rewrite()` (agle notes), kuch na return = request stuck.
- **Har URL pe logs dekhke confuse hona** — dev mein Next.js khud ke requests bhi karta hai (reload, HMR). Matcher ki wajah se sirf relevant paths aate hain.
- **Server restart** — `config` (matcher) change karne ke baad dev server restart karna padta hai (4.3 mein bhi aayega) — `npm run dev` dobara.

## Nutshell

`proxy.ts` project root mein. `export function proxy(request: NextRequest)` — har request pe chalta hai, `request.nextUrl.pathname` se path padh sakte ho. `return NextResponse.next()` = aage bhejo (zaroori). `config.matcher` = kaunse routes pe chale (static files exclude). Ek file — saari routes.
