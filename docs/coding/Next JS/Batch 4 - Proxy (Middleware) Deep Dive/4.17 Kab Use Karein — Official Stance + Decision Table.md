## Official Stance — Next.js Kya Kehta Hai

Next.js ki official docs (middleware-to-proxy migration message) mein seedha likha hai:

> **"We recommend users avoid relying on Middleware unless no other options exist. Our goal is to give them APIs with better ergonomics so they can achieve their goals without Middleware."**

Yeh conservative stance kyun? Humne is series mein khud dekha:

- **Proxy bypass ho sakti hai** (CVE-2025-29927 — 4.12)
- **Har request pe chalti hai** — heavy = har page slow (4.16)
- **Reinventing** — redirects/headers ke liye framework ke dedicated configs hain (niche table) jo better ergonomics dete hain
- **Confusion** — Express middleware wala misuse (isliye rename bhi hua — 4.1)

Matlab: **proxy default choice nahi — last resort/tool-specific choice.** Jaise wrench har problem ke liye nahi — screwdriver wali jagah screwdriver.

## Decision Table — Kaunsa Kaam Kahan?

| Kaam | Best jagah | Kyun |
|---|---|---|
| **Auth check / redirect (logged-out → login)** | Server Components: `auth()` + `redirect()` (Batch 5 ka layout pattern) | Verified session — proxy spoofable + CVE bypass (4.12) |
| **Redirects based on conditions** | Server Components `redirect()` ya `next.config` `redirects()` | Dedicated configs, no proxy runtime |
| **Headers set karna** | `next.config` `headers()` ya Server Components | Config-level, proxy ki zaroorat nahi |
| **Rate limiting** | Proxy ✅ | Request-level check — proxy hi sahi jagah (4.13) |
| **Geo blocking** | Proxy ✅ | Har request pe country check — proxy (4.14) |
| **Logging (request-level)** | Proxy ✅ | Har request ka record — ek jagah (4.11) |
| **A/B routing / maintenance page** | Proxy ✅ (rewrite) | Request-time decisions — proxy (4.9) |
| **Verified auth (data protection)** | Layout/Server Components `auth()` | Security layer proxy mein nahi (CVE) |

**Read karo pattern:** auth/data-security wale kaam → **components/actions** (verified, bypass-proof). Infra/request-level wale kaam → **proxy** (jaise 4.13/4.14/4.11 mein kiya). "Auth proxy mein" wala column galat hai (4.12 ka why-not).

## Best Practices — Final Checklist

1. **Proxy ko thin rakho** — cookie/header + condition + redirect/rewrite. Heavy → components/actions (4.16).
2. **Matcher ko tight rakho** — sirf un routes pe jahan kaam hai; static files always excluded (4.3).
3. **Redirect/rewrite target ko matcher se exclude** — loop prevention (4.8/4.9).
4. **Verified auth proxy mein nahi** — layout `auth()` (4.12).
5. **Rate-limit state shared store mein (production)** — Redis (4.13).
6. **Geo header local mein simulate karo** — `x-vercel-ip-country` production-only (4.14).
7. **Secrets log/header mein nahi** — logs bhi records hain (4.11).
8. **Version-aware raho** — Next 16: proxy = Node.js default, `runtime` export removed (4.15/4.16).
