# SQL CRUD via Server Components + Server Actions

## Step 1 — Pehli Problem: Table Empty Hai

`drizzle_todos` bilkul khali hai — koi data nahi. Pehle ek dummy todo daalte hain (neon ke SQL Editor se), taaki fetch test karne par pata chale ki data aa raha hai:

```sql
INSERT INTO drizzle_todos (title, done) VALUES ('Pehla Drizzle Todo', false);
```

Verify:

```sql
SELECT * FROM drizzle_todos;
```

```
id | title               | done
---+---------------------+------
1  | Pehla Drizzle Todo  | false
```

Data aa gaya — `id` automatically 1 (SERIAL). Ab aage.

## Step 2 — Read: Server Component Mein Fetch Karo

**SOCH:** Todo app ka home page = list dikhana. **Mongo phase mein** `/api/todos` route bana tha, frontend `fetch()` karta tha, client component state mein data rakhta tha. **Yahan kya alag?** Server Component hi server pe data fetch kar sakta hai — **seedha database se** — koi API layer nahi chahiye. `app/page.tsx` ko `async` bana do, andar `db.select()`, aur data directly render.

**CONCEPT:** Server Component (Batch 1 mein padha tha) = server pe render hota hai. Database bhi server pe hai. Toh page hi database se seedha query chalata hai — ek request, koi client round-trip nahi.

**File:** `app/page.tsx`

```tsx
// app/page.tsx
import { db } from "@/db";
import { todos } from "@/db/schema";
import { desc } from "drizzle-orm";

export default async function Home() {
  const allTodos = await db.select().from(todos).orderBy(desc(todos.id));

  return (
    <main>
      <h1>SQL Todo App</h1>
      <ul>
        {allTodos.map((todo) => (
          <li key={todo.id}>
            {todo.title} {todo.done ? "(done)" : ""}
          </li>
        ))}
      </ul>
    </main>
  );
}
```

Line by line:

- **`async function Home()`** — Server Component async ho sakta hai — `await db` ke liye (Mongo phase ke `connectDB` wale await se compare — wahan await karna padta tha connection ke liye, yahan `db` seedha ready hai).
- **`db.select().from(todos)`** — SQL `SELECT * FROM drizzle_todos`. `.orderBy(desc(todos.id))` — naya todo upar (descending). Yeh Drizzle khud SQL banata hai — tum raw SQL nahi likhte (5.10 mein compare tha).
- **`{allTodos.map((todo) => ...)}`** — server pe array render — `<li key={todo.id}>` — `id` number hai (Mongo mein `_id` string tha).

**Important — name check:** 5.10 mein table export `todos` tha (import `todos` from `@/db/schema`). `drizzle_todos` database table ka naam hai, TypeScript mein variable `todos` se access karte hain. Confuse mat hona — ek hi table, do names (DB name + TS variable).

**TEST:** `npm run dev`, browser mein page kholo — "Pehla Drizzle Todo" dikhega. **Koi `/api/todos` URL nahi, koi fetch nahi, koi client state nahi** — direct server query. Yahi SC pattern ka fayda.

## Step 3 — Write: Server Action Banao

**SOCH:** Ab naya todo add karna hai. **Mongo phase mein** POST route + fetch + JSON body bhejta tha. **Yahan?** Server Action — ek server function jo form submit pe chalata hai. Form seedha action ko call karta hai — koi API URL nahi, koi fetch nahi, koi JSON parse nahi.

**CONCEPT:** Server Action (Batch 2 mein the, 4.x mein bhi use kiye the). `"use server"` file mein functions — form `<form action={...}>` se call. Form ke data `formData` se milte hain.

**File:** `app/actions.ts` (nayi file)

```ts
// app/actions.ts
"use server";

import { db } from "@/db";
import { todos } from "@/db/schema";
import { revalidatePath } from "next/cache";

export async function createTodo(formData: FormData) {
  const title = formData.get("title") as string;

  if (!title || title.trim() === "") {
    return;
  }

  await db.insert(todos).values({ title: title.trim() });

  revalidatePath("/");
}
```

Line by line:

- **`"use server"`** — file ke saare exports server actions ban jaate hain (Batch 2 pattern).
- **`formData.get("title")`** — form ke input se value (input ka `name="title"` hona chahiye — aage form mein). `as string` — TS ko batao string hai.
- **Validation** — `!title || title.trim() === ""` — empty ya sirf spaces reject (5.7 wala pattern, wahi check).
- **`await db.insert(todos).values({ title: title.trim() })`** — SQL `INSERT INTO drizzle_todos (title) VALUES (...)`. `done` nahi diya — schema default `false` (5.10). **Mongo `Todo.create()` vs yahan `db.insert()`** — same kaam.
- **`revalidatePath("/")`** — data change hua, page ka cached render purana hai — Next.js ko bolo "/" ko dobara render karo (Server Action mutation ke baad zaroori — Batch 2 mein padha tha).

## Step 4 — Form Se Action Call Karo

**SOCH:** Ab user ko naya todo type karke add karna hai — input + button. **Server Actions ke saath forms:** `<form action={createTodo}>` — submit pe Next.js action ko call karta hai — form data usme jaata hai.

**File:** `app/page.tsx` (form add karo)


- **`<form action={createTodo}>`** — submit pe `createTodo` chalega. **`name="title"`** — input ka naam wahi jo action mein `formData.get("title")` padhta hai. Form bheja — action ne insert kiya — `revalidatePath` ne page dobara render kiya — naya todo list mein.
- **Full page reload nahi** — Server Action form submit progressive enhancement se handle hota hai (Batch 2).

## Step 5 — Toggle + Delete

**SOCH:** Todo app ke baaki operations — done toggle karna, todo delete karna. **Mongo mein** `PUT`/`DELETE` route + fetch. **Yahan** — do aur server actions. Aise toggles ke liye form submit hota hai (checkbox/button), action ko `formData` se id milti hai.

**File:** `app/actions.ts` (createTodo ke neeche add)

```ts
// app/actions.ts
"use server";

import { db } from "@/db";
import { todos } from "@/db/schema";
import { eq } from "drizzle-orm";           // NEW
import { revalidatePath } from "next/cache";

export async function createTodo(formData: FormData) {
  // ... wahi jo Step 3 mein likha
}

export async function toggleTodo(formData: FormData) {    // NEW
  const id = Number(formData.get("id"));

  await db
    .update(todos)
    .set({ done: true })
    .where(eq(todos.id, id));

  revalidatePath("/");
}

export async function deleteTodo(formData: FormData) {    // NEW
  const id = Number(formData.get("id"));

  await db.delete(todos).where(eq(todos.id, id));

  revalidatePath("/");
}
```

Line by line:

- **`Number(formData.get("id"))`** — form data string hota hai, `id` number column hai — convert zaroori. **Yeh 5.7 se alag hai!** Mongo mein `_id` string tha (URL se aata tha). SQL mein `id` number hai — form se string aata hai, `Number()` se number.
- **`db.update(todos).set({ done: true }).where(eq(todos.id, id))`** — SQL `UPDATE drizzle_todos SET done = true WHERE id = ...`. **`eq`** Drizzle ka equality operator — `drizzle-orm` se import.
- **`db.delete(todos).where(eq(todos.id, id))`** — SQL `DELETE FROM drizzle_todos WHERE id = ...`.
- **`where()` kyun zaroori?** Bina where ke update/delete **saari rows** pe lag jaata — SQL ka rule. Mongo mein `findByIdAndUpdate(id, ...)` tha — id function parameter mein. SQL mein where clause explicit.

**File:** `app/page.tsx` — har todo ke saath action buttons (form mein id hidden field ke saath)

```tsx
// app/page.tsx
import { db } from "@/db";
import { todos } from "@/db/schema";
import { desc } from "drizzle-orm";
import { createTodo, toggleTodo, deleteTodo } from "./actions";   // NEW

export default async function Home() {
  const allTodos = await db.select().from(todos).orderBy(desc(todos.id));

  return (
    <main>
      <h1>SQL Todo App</h1>
      <form action={createTodo}>
        <input name="title" placeholder="Naya todo..." />
        <button type="submit">Add</button>
      </form>
      <ul>
        {allTodos.map((todo) => (
          <li key={todo.id}>
            {todo.title} {todo.done ? "(done)" : ""}
            <form action={toggleTodo}>              {/* NEW */}
              <input type="hidden" name="id" value={todo.id} />
              <button type="submit">Done</button>
            </form>
            <form action={deleteTodo}>              {/* NEW */}
              <input type="hidden" name="id" value={todo.id} />
              <button type="submit">Delete</button>
            </form>
          </li>
        ))}
      </ul>
    </main>
  );
}
```

- **`<input type="hidden" name="id" value={todo.id} />`** — har todo ka form apni id bhejta hai (hidden input — user nahi dekhta, par action ke `formData` mein jaata hai).
- **Har todo ka apna form** — submit pe sirf usi todo ka action call hota hai.

**TEST:** Todo ke paas "Done" dabao — `done: true` ho jaata hai, page refresh ho jaata hai (revalidate). "Delete" dabao — todo list se chala jaata hai. Neon mein verify.

## Poora Compare — Mongo REST vs SQL Server Actions

Ab dono mini-projects saamne hain — full compare. Pehle har concept ek-ek clear tha, ab table:

| | **Mongo (5.7-5.8)** | **SQL (5.11)** |
|---|---|---|
| **Data pattern** | NoSQL — document | SQL — table/row |
| **Read** | REST GET route → client fetch | Server Component `db.select()` |
| **Write** | POST/PUT/DELETE route → client fetch | Server Action `db.insert/update/delete` |
| **ID** | `_id` string (Mongo banaata) | `id` number (SERIAL auto) |
| **Fetch result** | `Todo.create()` row wapas deta hai | `.returning()` lagana padta hai |
| **Data flow** | Client state + re-fetch | Server render + `revalidatePath` |
| **Testing** | Postman (REST URLs) | Direct browser/form (SA) |
| **Connection** | `connectDB()` async singleton | `db` ready export (serverless) |
| **Kyun use karein** | External clients, mobile, 3rd party | Same-app internal, form-driven, simpler |

**Kab kya use karein** — REST jab API ko external clients consume karein (mobile app, third party, public API). Server Actions jab data sirf apni hi app ke UI se aana hai — koi public API surface nahi chahiye. Task Board (5.13) mein SC+SA hi hoga — production pattern.

## Nutshell

SQL Todo Server Components + Server Actions se: reads `app/page.tsx` mein `async` + `db.select()` (SC — koi API layer nahi), mutations `app/actions.ts` mein `"use server"` functions (`db.insert/update/delete` + `eq` + `revalidatePath`), forms `action={...}` se call. SQL ke rules: `where()` bina update/delete saari rows pe lagta hai, id number hai (`Number()` convert).

## What It Is NOT

- **Server Component = "async render" nahi.** Server Component data fetch kar sakta hai kyunki woh server pe hi hai — database bhi server pe hai — isliye seedha query ho paati hai, koi network round-trip nahi. Yeh architectural choice hai, sirf syntax nahi.
- **Server Action = "REST endpoint ka replacement" nahi.** SA form/data mutations ke liye hai — direct server function call. REST unke liye hai jo URL se API consume karte hain (Postman, mobile). Alag use-cases — isliye phase alag banaye the.
- **`db.update().set()` bina `where()` = "pura table update" nahi.** Bilkul — SQL mein bina where ke update/delete saari rows pe apply hota hai. `eq(todos.id, id)` zaroori hai. Mongo ka `findByIdAndUpdate(id, ...)` yeh automatically handle karta tha — SQL mein explicit.
- **`revalidatePath` = "page refresh ka magic button" nahi.** Data change hua toh purana render galat hai — `revalidatePath` Next.js ko bolta hai is route ko dobara server pe render karo. Bina iske naya data UI mein nahi dikhega.
- **`Number(formData.get("id"))` = optional nahi.** Form data hamesha string hota hai — SQL column number. Bina Number() ke `eq(todos.id, "3")` type error/query fail — convert zaroori.
