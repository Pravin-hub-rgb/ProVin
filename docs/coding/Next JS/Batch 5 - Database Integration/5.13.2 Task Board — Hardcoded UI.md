## Board Page — Columns + Tasks (Hardcoded)

**SOCH:** `/board/[id]` — ek board, columns (Backlog/In Progress/Done), har column mein tasks. Plan ka data: board + tasks with `status` + `order`.

**File:** `app/board/[id]/page.tsx` (folder `board/[id]` banao)

```tsx
// app/board/[id]/page.tsx
const tasks = [
  { id: 1, title: "Setup landing page", description: "Hero + sections", status: "Backlog", order: 1 },
  { id: 2, title: "Write blog post", status: "Backlog", order: 2 },
  { id: 3, title: "Design logo", status: "In Progress", order: 1 },
  { id: 4, title: "Launch", description: "Go live", status: "Done", order: 1 },
];

const columns = ["Backlog", "In Progress", "Done"];

export default function BoardPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  return (
    <section>
      <h2>Board #{(params as any).then ? "" : (params as any).id}</h2>

      <div style={{ display: "flex", gap: 16 }}>
        {columns.map((column) => {
          const columnTasks = tasks
            .filter((t) => t.status === column)
            .sort((a, b) => a.order - b.order);

          return (
            <div key={column} style={{ flex: 1, border: "1px solid #ccc", padding: 12 }}>
              <h3>{column}</h3>

              <form>
                <input name="title" placeholder="Naya task..." />
                <button type="submit">Add</button>
              </form>

              <ul>
                {columnTasks.map((task) => (
                  <li key={task.id}>
                    <p>{task.title}</p>
                    {task.description && <small>{task.description}</small>}
                    <button type="button">Move</button>
                    <button type="button">Delete</button>
                  </li>
                ))}
              </ul>
            </div>
          );
        })}
      </div>
    </section>
  );
}
```

Line by line:

- **`columns`** — teen fixed columns (plan: enum Backlog/InProgress/Done — yahan UI strings).
- **`tasks`** — hardcoded — plan ka shape: `id, title, description?, status, order`. **Har column mein tasks filtered + sorted** — `.filter(t => t.status === column)` (column ke tasks) + `.sort((a,b) => a.order - b.order)` (kram) — `order` field ka use yahi hai (5.13.1 Sawaal 3).
- **`columnTasks`** — variable mein filtered list — map se pehle compute karta hai — code readable (map ke andar filter/sort chhupa na de).
- **`{task.description && <small>...`}** — description optional hai — agar hai toh dikhao, nahi toh skip (plan ka `String?`).
- **Move/Delete buttons** — abhi `type="button"` (koi action nahi — 5.13.4 mein server actions se judege). Add form bhi abhi static.

**`params` handling:** Dynamic route `[id]` — Next.js 15+ mein `params` async hai. **5.7 wala wahi pattern** — `Promise<{ id: string }>`. Abhi data hardcoded hai isliye id use nahi ho raha — maine upar placeholder likha hai. **5.13.4 mein seedha `const { id } = await params` karenge** — wahan actual use hoga. Abhi ke liye dynamic route ka dhacha tayar hai.

> **Note:** Upar `(params as any).then ? "" : (params as any).id` wala hack sirf temporary placeholder hai — 5.13.4 mein poora `await params` pattern aayega. Wahan file saaf ho jayegi.

## TEST + Problem Highlight

**TEST:** `/` pe boards list, `/board/1` pe columns + tasks dikhe. Design confirm — columns ek line mein, har column mein add form + sorted tasks.

**Problem — data do jagah hai (DRY violation):**

Abhi tasks hardcoded hain **page ke andar**. Kya problem? 5.13.1 mein plan tha — Task Board ka data **database** mein hoga (Prisma). Is UI ko dynamic banane ke liye:

- Hardcoded array hatao
- Database se data lao
- Forms ko server actions se jodo

Yeh tino cheezein 5.13.3 (data layer) + 5.13.4 (dynamic) mein hongi. **UI ka code mostly wahi rahega** — sirf data source badlega. Yahi planning + hardcoded-first ka fayda — UI confirm ho gayi, ab data layer bas plug-in karni hai.

## Nutshell

Hardcoded UI: `/` pe boards list (`{ id, name }` map + form), `/board/[id]` pe columns (filter by status + sort by order) + har column mein add form + tasks. Dynamic route `[id]` ka dhacha ready (params async — 5.7 pattern). Data page ke andar hardcoded hai — duplic... matlab ek jagah, par database se replace karni hai — 5.13.4 ka kaam.

## What It Is NOT

- **Hardcoded UI = "final data" nahi.** Yeh static demo hai — UI + data shape validate karne ke liye. Asli data database se aayega (5.13.4). Is file ka code UI pattern hai, data nahi.
- **`type="button"` wale buttons = "kaam kar rahe" nahi.** Abhi koi action attached nahi — Move/Delete 5.13.4 mein server actions se judege. `type="button"` isliye ki form submit na karein (default button form submit karta hai).
- **`params as any` wala hack = "sahi pattern" nahi.** Yeh temporary placeholder hai. Sahi tarika `await params` (5.7 mein seekha) — 5.13.4 mein file saaf hogi. Isse future concept ka hint bhi mile — hardcoded phase mein hi dynamic route ka dhacha.
- **Layout = "har page pe copy karo" nahi.** Layout ek baar define hota hai — dono pages uske andar. Header board app ka shared brand hai. (Batch 1 ka layout concept.)
- **Filter/sort page mein = "final logic" nahi.** Abhi JS filter/sort chal raha hai. Database mein query-side sorting/filtering hogi (5.13.4). Par logic ka idea yahi hai — column ke tasks + order.
