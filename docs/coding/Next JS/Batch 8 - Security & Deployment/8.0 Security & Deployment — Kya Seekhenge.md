## Batch Spine — "Manual → Better"

The core principle of the roadmap continues here too — **first feel the problem with manual approaches, then see Next.js' better solution:**

| Topic | Manual (first, feel the problem) | Better (Next.js/Production solution) |
|---|---|---|
| Secrets | Hardcoded secret / `NEXT_PUBLIC_` misuse → exposed in client bundle | `.env` server-only vars, `NEXT_PUBLIC_` prefix rules, `.gitignore` |
| Input/CSRF | Trust client input / XSS / CSRF attacks | Server Actions built-in CSRF (Origin check) + server-side validation |
| Errors | Raw errors, no boundary, layout crash = white screen | `error.tsx` at scale + `global-error.tsx` hierarchy |
| Deploy | Self-host (build/start, env management pain) | Vercel — git push, zero-config, env per environment |

Every topic first makes you feel the **problem** (manual), then shows the **solution** (production-grade). That's what makes the "why" clear, not just the "how".
