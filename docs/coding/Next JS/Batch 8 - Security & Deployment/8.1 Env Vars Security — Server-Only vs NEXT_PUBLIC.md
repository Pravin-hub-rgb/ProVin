Soch — Photo Gallery ban gaya hai, Prisma + Neon, database connected hai. Par ek sawaal: `DATABASE_URL` kahan hai? `.env` file mein. Aur `.env` file kahan hai? Project ke root pe. Aur agar koi developer naya join ho aur `.env` khol ke dekhe — usme `DATABASE_URL="postgresql://user:password@neon.tech/mydb"` dikhega. Chal raha hai, koi dikkat nahi. Par ab soch — jab app deploy hoga, toh kya hoga? Client browser ko `DATABASE_URL` dikh raha hai? Agar haan toh koi bhi user database dekh sakta hai — **password, data, sab.** Yehi woh problem hai jo 8.1 mein solve karenge.

Is file mein samjhenge ki **secrets (DATABASE_URL, API keys) server pe kaise safe rakhte hain** — aur galti se client bundle mein kaise nahi jaate. Manual approach (hardcoded secret) ki problem, phir Next.js ka better solution (`.env` + server-only vs `NEXT_PUBLIC_`).

---

## Manual Approach — Hardcoded Secret (Problem)

Sabse pehle dekhte hain ki galti se kya hota hai. Agar tum `DATABASE_URL` seedha code mein likh do:

**File:** `lib/prisma.ts` — ❌ galat approach

```ts
import { PrismaClient } from "@prisma/client";

export const prisma = new PrismaClient({
  datasources: {
    db: {
      url: "postgresql://user:password@neon.tech/mydb",  // ❌ hardcoded
    },
  },
});
```

Yeh kaam toh karega — database connect hoga, sab chalega. Par **do problems hain:**

1. **Secret code mein dikh raha hai** — agar yeh code GitHub pe push ho jaaye (`.gitignore` miss), toh duniya ko pata chal jaayega. Hacker directly database access le sakta hai.

2. **Har jagah same value** — dev aur production mein same password hona chahiye? Nahi. Local `localhost:5432` aur production `neon.tech` alag databases hain. Hardcoded mein dono ek hi jagah se manage karna padega.

Yeh "manual approach" hai — aur yeh **production mein kaam nahi karta.** Iska solution hai environment variables.

---

## CONCEPT — Environment Variables Kya Hoti Hain

Environment variable ek **key-value pair** hai jo code ke bahar hota hai. Tum code mein sirf key ka naam likhte ho (`process.env.DATABASE_URL`), aur actual value deployment platform pe set hoti hai.

```
DATABASE_URL = "postgresql://user:password@neon.tech/mydb"
AUTH_SECRET = "cX8v7K9mN2pR..."
```

Code mein sirf access karte ho:
```ts
const url = process.env.DATABASE_URL;  // "postgresql://user:password@neon.tech/mydb"
```

**Kyun better hai?**
- Secret code mein nahi hai — `.env` file mein hai
- `.gitignore` mein `.env` listed hai — GitHub pe push nahi hota
- Har environment (dev, production) ki alag value ho sakti hai

Par ab sawaal — `.env` file `.gitignore` mein hai, toh **local development mein kaise kaam karta hai?** Next.js automatically `.env.local` file load karta hai jab `npm run dev` chalta hai. Server pe values mil jaati hain `process.env` se. Client bundle mein? **Woh 8.1.1 ka next section hai.**

---

## CODE — `.env` File Banana

Project ke root pe `.env.local` file banao:

```
# .env.local
DATABASE_URL="postgresql://user:password@neon.tech/mydb"
AUTH_SECRET="cX8v7K9mN2pR4sT6vY1zA3bC5dE7fG9hJ2kL4mN6pQ8rS0tU2vW4xZ6aB8cD0eF2"
```

**`.env.local` kyun `.env` se alag hai?**
- `.env` — general environment file, sab jagah load hota hai (development + production)
- `.env.local` — sirf local machine pe load hota hai, Vercel/production pe nahi. **Isliye secrets `.env.local` mein rakhte hain.**

Ab code mein access karo:

**File:** `lib/prisma.ts` — ✅ sahi approach

```ts
import { PrismaClient } from "@prisma/client";

export const prisma = new PrismaClient({
  datasources: {
    db: {
      url: process.env.DATABASE_URL,  // ✅ .env.local se aayega
    },
  },
});
```

`.gitignore` mein confirm karo:

```
# .gitignore
.env
.env.local
.env*.local
```

Yeh lines honi chahiye. Agar nahi hain — abhi add karo. Agar `.env.local` already GitHub pe push ho chuki hai:

```bash
git rm --cached .env.local
git commit -m "remove .env.local from tracking"
git push
```

`git rm --cached` file ko git tracking se hatata hai — file local machine pe rahegi par git ignore karega.

## CONCEPT — Server-Only vs `NEXT_PUBLIC_` (The Two Worlds)

Ab aata hai sabse important concept — **client aur server ki duniya alag hai.**

Next.js mein do tarah ke components hain:
- **Server Components** — sirf server pe chalte hain (`page.tsx`, `layout.tsx` default)
- **Client Components** — browser mein bhi chalte hain (`'use client'` lagao)

Har request pe:
1. **Server** pehle HTML render karta hai (Server Components)
2. Phir **client** (browser) us HTML ko interactive banata hai (Client Components hydrate)

Ab soch — agar `DATABASE_URL` kisi **Server Component** mein use ho raha hai, toh woh sirf server pe hai. Browser tak nahi pahunchta. **Safe hai.**

Par agar `DATABASE_URL` kisi **Client Component** mein use ho jaye (`'use client'`), toh Next.js us value ko **browser bundle mein daal deta hai** — kyunki client ko chahiye. Aur browser bundle mein sab kuch dikhta hai — DevTools → Sources tab → search karo, mil jaayega. **Secret leak ho gaya.**

Yehi `NEXT_PUBLIC_` prefix se judta hai.

---

## `NEXT_PUBLIC_` Prefix — Client Bundle Mein Expose

Next.js ka rule:

| Variable Name | Server (Server Component/Route Handler) | Client (Client Component) |
|---|---|---|
| `DATABASE_URL` | ✅ Available | ❌ undefined |
| `NEXT_PUBLIC_MAPS_KEY` | ✅ Available | ✅ Available (bundle mein) |

**`NEXT_PUBLIC_` prefix lagao = value browser bundle mein dikh jaayegi.** Isliye:

- **`DATABASE_URL`** — `NEXT_PUBLIC_` nahi lagana. Sirf server pe chahiye. Agar lagao toh browser mein dikh jaayega.
- **`NEXT_PUBLIC_MAPS_KEY`** — Google Maps API key jo client pe chahiye maps render karne ke liye. Yeh **safe hai** kyunki Maps key sirf frontend use hai, database nahi hai.

**Golden Rule:** Jo bhi **secret** hai (password, API key, database URL, auth secret) — usmein `NEXT_PUBLIC_` **mat lagao.** Sirf woh cheezein `NEXT_PUBLIC_` banao jo **client ko genuinely chahiye** (public API keys, analytics IDs, public URLs).

---

## TEST — Client Bundle Mein Secret Nahi Dikhna Chahiye

1. `npm run dev` chalao
2. Browser mein `localhost:3000` kholo
3. DevTools → Sources tab (Chrome) ya Debugger tab (Firefox)
4. Search karo apni `DATABASE_URL` ki value ya `AUTH_SECRET`

**Expected:** Kuch nahi milna chahiye. Agar mil jaaye — secret client bundle mein hai. Check karo ki kahin Client Component mein toh nahi use ho raha.

5. Ab `NEXT_PUBLIC_` prefix wali value dekho (agar koi hai):
   - Search karo — dikhni chahiye (yehi expected hai)

**Result:** Server-only secrets client mein nahi dikhni chahiye. `NEXT_PUBLIC_` wali dikhegi. Yehi security hai.

## Compare Table (LAST)

| Cheez | Hardcoded (manual) | `.env` + Server-Only | `NEXT_PUBLIC_` |
|---|---|---|---|
| Secret location | Code mein | `.env.local` (gitignore mein) | `.env.local` (gitignore mein) |
| Client bundle | ❌ Dikh jaayega | ❌ undefined | ✅ Available (public cheezein) |
| Multiple envs | Same value everywhere | Dev/production alag | Dev/production alag |
| Security | ❌ Leak | ✅ Safe (server pe sirf) | ⚠️ Public cheezein ke liye safe |

---

## Nutshell

Environment variables `.env` file mein hoti hain — code ke bahar. Next.js `.env.local` ko automatically load karta hai. **Server-only variables** (bina prefix) sirf server pe accessible hain — `process.env.DATABASE_URL` Client Component mein `undefined` hai. **`NEXT_PUBLIC_` prefix** lagao toh value browser bundle mein bhi dikh jaati hai — isliye sirf public cheezein (analytics, public URLs) pe use karo. Secrets (password, API key, database URL) pe `NEXT_PUBLIC_` kabhi mat lagao.

---

## What It Is NOT

- **`.env.local` = "production mein bhi load hoti hai" nahi.** `.env.local` sirf local pe load hota hai. Production mein `.env.production` ya platform ke env vars (Vercel dashboard) use hota hain.
- **`NEXT_PUBLIC_` = "har public cheez ke liye use karo" nahi.** Sirf woh cheezein jo client ko genuinely chahiye (maps key, analytics ID). "Public" ka matlab "secret nahi" — par "public" bhi nahi hai.
- **`process.env.X` = "hamesha available hai" nahi.** Sirf tab available hai jab `.env` file mein ya platform env vars mein set ho. Undefined aa sakta hai — TypeScript ke liye optional handle karo.
- **`git rm --cached` = "file delete kar deta hai" nahi.** File sirf git tracking se hat'ti hai — local machine pe rahegi.
