8.5.1 mein audit ka naksha banaya — ab Photo Gallery ke asli files check karte hain. Sabse pehle **env vars + config security** — kyunki yeh sabse critical hai. Agar `DATABASE_URL` leak ho jaaye toh baaki sab meaningless hai.

---

## Step 1 — `.gitignore` Verify

Sabse pehle check karo ki `.env.local` file git mein track toh nahi ho rahi:

**File:** `.gitignore` — existing file verify

```
# dependencies
/node_modules

# testing
/coverage

# next.js
/.next/
/out/

# production
/build

# misc
.DS_Store
*.pem

# debug
npm-debug.log*
yarn-debug.log*
yarn-error.log*

# env files
.env
.env.local
.env*.local

# vercel
.vercel
```

**Check:** `.env` aur `.env.local` listed hai? ✅ toh theek. Nahi hai? Abhi add karo.

**Agar `.env.local` already GitHub pe push ho chuki hai:**

```bash
git rm --cached .env.local
git commit -m "remove .env.local from tracking"
git push
```

`git rm --cached` — file local pe rahegi, git tracking se hat'ti hai.

---

## Step 2 — `.env.local` Verify

`.env.local` kholo — kya hai usme?

```
DATABASE_URL="postgresql://user:password@neon.tech/mydb"
```

**Check:**
- [x] `DATABASE_URL` hai — Prisma use karta hai ✅
- [ ] Koi `NEXT_PUBLIC_DATABASE_URL` toh nahi? (❌ agar hai — remove karo, secret hai)
- [ ] `AUTH_SECRET` hai? (Photo Gallery read-only hai toh shayad nahi — agar hai toh strong hona chahiye)

**Result:** Photo Gallery read-only hai — sirf `DATABASE_URL` hai. `NEXT_PUBLIC_` koi nahi. **Safe.**

---

## Step 3 — Code Mein `NEXT_PUBLIC_` Search

Pura project grep karo — kahin `NEXT_PUBLIC_` toh nahi use ho raha:

```bash
grep -r "NEXT_PUBLIC_" --include="*.ts" --include="*.tsx" .
```

**Expected:** Kuch nahi milna chahiye. Photo Gallery mein koi client-side API key ya public URL nahi hai.

**Agar mil jaaye:**
- Soch — kya yeh genuinely client ko chahiye?
- Agar haan (jaise analytics ID) — theek hai
- Agar nahi (jaise database URL) — **security leak hai**, fix karo

---

## Step 4 — `next.config.ts` Verify

**File:** `next.config.ts` — existing file

```ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: "https",
        hostname: "images.unsplash.com",
      },
    ],
  },
};

export default nextConfig;
```

**Check:**
- [x] `remotePatterns` mein sirf **trusted domains** hain? (Unsplash = trusted ✅)
- [ ] Koi wildcard `hostname: "*"` toh nahi? (❌ — any domain allowed = security risk)
- [ ] Koi unnecessary `rewrites`/`redirects` toh nahi?

**Result:** Sirf Unsplash allowed hai. **Safe.** Agar `*` hota toh koi bhi external image optimize hoti — bandwidth abuse + security risk.

---

## Step 5 — Server Components Check

Photo Gallery ke pages check karo — kya sab Server Components hain?

```bash
grep -r "use client" --include="*.tsx" .
```

**Expected:** Sirf modal component (`@modal`) mein `use client` hona chahiye — baaki sab Server Components.

**Kyun important hai?** Server Components mein `process.env.DATABASE_URL` sirf server pe accessible hai. Client Component mein `process.env.DATABASE_URL` = `undefined` (safe) ya agar `NEXT_PUBLIC_` hai toh bundle mein dikh jaayega.

**Result:** Photo Gallery mein sirf modal + maybe koi interactive element pe `use client` — baaki sab Server Components. **Safe.**
