In 8.5.1, we made the audit blueprint — now we check the Photo Gallery's real files. First up: **env vars + config security** — because this is the most critical. If `DATABASE_URL` leaks, everything else is meaningless.

---

## Step 1 — Verify `.gitignore`

First, confirm that `.env.local` is not tracked by git:

**File:** `.gitignore` — verify existing file

```

/.next/
/out/

# production
/build

# misc

# debug
npm-debug.log*
yarn-debug.log*

# env files
.env
.env.local
.env*.local

# vercel
.vercel
```

**Check:** Are `.env` and `.env.local` listed? ✅ if yes, all good. If not, add them now.

**If `.env.local` has already been pushed to GitHub:**

```bash
git rm --cached .env.local
git commit -m "remove .env.local from tracking"
git push
```

`git rm --cached` — the file stays on your local machine, removed from git tracking.

## Step 2 — Verify `.env.local`

Open `.env.local` — what's in it?

```
DATABASE_URL="postgresql://user:password@neon.tech/mydb"
```

**Check:**
- [x] `DATABASE_URL` is there — Prisma uses it ✅
- [ ] Is there no `NEXT_PUBLIC_DATABASE_URL`? (❌ if yes — remove it, it's a secret)
- [ ] Is there an `AUTH_SECRET`? (Photo Gallery is read-only, probably not — if yes, it should be strong)

**Result:** Photo Gallery is read-only — it only has `DATABASE_URL`. No `NEXT_PUBLIC_`. **Safe.**

---

## Step 3 — Search for `NEXT_PUBLIC_` in Code

Grep the entire project — make sure `NEXT_PUBLIC_` isn't being used anywhere:

```bash
grep -r "NEXT_PUBLIC_" --include="*.ts" --include="*.tsx" .
```

**Expected:** Nothing should be found. The Photo Gallery has no client-side API keys or public URLs.

**If something is found:**
- Think — does it genuinely need the client?
- If yes (like an analytics ID) — that's fine
- If no (like a database URL) — **that's a security leak**, fix it

---

## Step 4 — Verify `next.config.ts`

**File:** `next.config.ts` — existing file

```ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: "https",
        hostname: "images.unsplash.com",
      },
    ],
  },
};

export default nextConfig;
```

**Check:**
- [x] Are only **trusted domains** in `remotePatterns`? (Unsplash = trusted ✅)
- [ ] Is there a wildcard `hostname: "*"`? (❌ if yes — any domain allowed = security risk)
- [ ] Are there any unnecessary `rewrites`/`redirects`?

**Result:** Only Unsplash is allowed. **Safe.** If there was `*`, any external image could be optimized — bandwidth abuse + security risk.

---

## Step 5 — Server Components Check

Check the Photo Gallery's pages — are they all Server Components?

```bash
grep -r "use client" --include="*.tsx" .
```

**Expected:** Only the modal component (`@modal`) should have `use client` — everything else should be Server Components.

**Why is this important?** `process.env.DATABASE_URL` in a Server Component is only accessible on the server. In a Client Component, `process.env.DATABASE_URL` = `undefined` (safe) or if it has `NEXT_PUBLIC_` prefix, it shows up in the bundle.

**Result:** In the Photo Gallery, only the modal + maybe some interactive element has `use client` — everything else is a Server Component. **Safe.**
