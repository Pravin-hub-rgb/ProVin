1.4 mein samjha tha ki `error.tsx` kya hota hai — basic error handling: `error` object + `reset` function. Woh concepts the — ab production app mein **at scale** dekhte hain. Photo Gallery mein kai routes hain — `/`, `/photo/[id]`, modal. Agar `/photo/[id]` mein kuch crash ho jaaye toh kya poora app band ho jaayega? Nahi — error boundaries alag-alag level pe kaam karti hain. Par **kaunsi boundary kaunse error ko catch karti hai?** Yeh hierarchy samajhni padti hai — tabhi production app mein errors gracefully handle hote hain.

---

## Manual Problem — Single Error Boundary Kaafi Nahi

1.4 mein ek `error.tsx` banaya tha route level pe. Par production app mein errors alag-alag jagah se aa sakte hain:

- **Route-level error** — `/photo/[id]` mein data fetch fail
- **Layout error** — shared layout (jaise navbar) mein crash
- **Root layout crash** — poora app ka root layout fail
- **Client Component error** — `'use client'` wale component mein runtime error

Agar sirf ek `error.tsx` ho toh — layout ka error bhi wohi catch karega? Nahi — layout uske upar wale boundary mein hai. **Multiple error boundaries chahiye** — har level pe alag. Yehi "at scale" hai.

---

## CONCEPT — Error Hierarchy (Kaunsi Boundary Kab Catch Karti Hai)

Next.js mein error boundaries **nested** hain — jaise Russian dolls (chhota doll andar, bada bahar). Har folder ka apna `error.tsx` hota hai jo **us folder aur uske children** ke errors catch karta hai.

**Error Hierarchy Diagram:**

```
app/
├── global-error.tsx        ← Root layout crash (last resort — sabse bahar)
├── not-found.tsx           ← Global 404
├── layout.tsx              ← Root layout (yahan error = global-error catch)
├── page.tsx                ← / (home)
├── photo/
│   ├── error.tsx           ← /photo/* sab routes ke errors
│   ├── loading.tsx         ← /photo/* loading
│   └── [id]/
│       ├── error.tsx       ← /photo/[id] specific errors
│       └── page.tsx        ← /photo/:id
├── error.tsx               ← App-level errors (root ke baad)
└── not-found.tsx
```

**Flow samjho:**

1. `/photo/5` pe data fetch ho raha hai → error aata hai
2. Next.js sabse pehle **sabse chhoti boundary** (nearest) dhundhta hai — `photo/[id]/error.tsx`
3. Agar woh nahi hai → upar jaata hai — `photo/error.tsx`
4. Agar woh bhi nahi → `app/error.tsx`
5. Agar root layout crash ho — `app/global-error.tsx` (last resort)

**Yehi hierarchy hai — chhoti boundary se start, badi tak jaao.**

---

## CODE — `global-error.tsx` (Last Resort)

`global-error.tsx` tab catch karta hai jab **root layout** hi crash jaaye. Yeh special hai kyunki:
- Root layout ke andar nahi hota — **root `app/` folder mein**
- Root layout ki jagah render hota hai — isliye `<html>` aur `<body>` khud dena padta hai
- `'use client'` zaroori hai (same reason jaise `error.tsx`)

**File:** `app/global-error.tsx` — naya file (root `app/` folder mein)

```tsx
'use client'

export default function GlobalError({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  return (
    <html lang="en">
      <body>
        <div style={{ padding: "2rem", textAlign: "center" }}>
          <h2>Kuch bahut bura ho gaya</h2>
          <p>{error.message}</p>
          <button onClick={() => reset()}>Try Again</button>
        </div>
      </body>
    </html>
  )
}
```

**Kuch important cheezein:**

1. **`'use client'`** — zaroori hai — error handling client-side hoti hai
2. **`<html>` aur `<body>`** — zaroor likho — kyunki yeh root layout ki jagah render hota hai. Layout available nahi hota — toh khud provide karna padta hai
3. **`error.digest`** — production mein Next.js error ko hash karta hai (string identifier). Optional property hai, digest dikha sakte ho debugging ke liye

## CODE — Route-Level `error.tsx` (Basic)

Yeh 1.4 wala concept hai — ab at scale mein ek route ke liye:

**File:** `app/photo/[id]/error.tsx` — naya file

```tsx
'use client'

export default function PhotoError({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  return (
    <div style={{ padding: "2rem", textAlign: "center" }}>
      <h2>Photo load nahi ho paayi</h2>
      <p>{error.message}</p>
      <button onClick={() => reset()}>Dobara try karo</button>
    </div>
  )
}
```

**`app/photo/error.tsx`** bhi bana sakte ho — dono `/photo/*` routes cover karenge. Agar dono hain toh `photo/[id]/error.tsx` pehle catch karega (sabse chhoti boundary).

## CONCEPT — Error Recovery UX (Production vs Dev)

Development mein aur production mein errors differently dikhte hain:

**Development:**
- Next.js ka **red error overlay** dikhta hai (detailed error, stack trace)
- `error.tsx` bhi render hota hai — par overlay upar se aata hai
- Useful hai debugging ke liye

**Production:**
- Overlay nahi dikhta — sirf `error.tsx` ka UI dikhta hai
- User ko friendly message dikhna chahiye — "Something went wrong" + retry button
- `error.digest` string dikha sakte ho (hash identifier — support team ke liye useful)

**Isliye production app mein error.tsx ko clean rakho:**
- Friendly message (technical details mat dikhao user ko)
- Retry button (`reset()`)
- Error logging (server pe `console.error(error)` — user ko mat dikhao)

## Nutshell

Error hierarchy mein **chhoti boundary se start, badi tak jaao.** Har folder ka `error.tsx` us folder + children ke errors catch karta hai. `global-error.tsx` root `app/` mein hota hai — last resort jab root layout crash ho. Development mein Next.js overlay dikhata hai, production mein sirf `error.tsx` ka UI. Har error boundary mein friendly message + retry button (`reset()`) — technical details user ko mat dikhao.

---

## What It Is NOT

- **`global-error.tsx` = "har error ke liye" nahi.** Yeh sirf **root layout crash** ke liye hai. Route-level errors ke liye route ka `error.tsx` catch hota hai.
- **`error.tsx` = "error fix karta hai" nahi.** Yeh error ko **gracefully handle** karta hai — user ko friendly dikhata hai. Asli fix code mein karni padti hai.
- **`reset()` = "error fix ho gaya" nahi.** Yeh sirf page ko **dobara render** karta hai. Agar error transient tha (network), toh shayad solve ho. Permanent error aa jaayega fir se.
- **Error boundaries = "try-catch" nahi.** React error boundaries class component hain jo render errors catch karti hain. Next.js `error.tsx` iska wrapper hai — tumhe class banana nahi padta.
