## What Is MCP?

**MCP** = **Model Context Protocol**. It is a standard way for AI tools to **"plug into" your application** and read its structure — routes, logic, file layout.

Think of it like this: without MCP, asking an AI "how many routes do I have" requires you to manually copy your `app/` folder structure into the chat. The AI counts what you pasted — but it never sees your actual route logic, your server actions, your data layer.

With MCP, the AI connects directly to your codebase and reads everything — routes, files, logic — then answers from the real thing.

## Why MCP Matters for Next.js

Next.js apps grow complex fast:

- 40+ routes in the `app/` router
- Dynamic routes, catch-all segments, parallel routes
- API route handlers and Server Actions mixed together
- Shared layouts, middleware, edge configs

When you ask an AI to help, it needs to **see this reality**, not a summary you typed. MCP gives your AI agent:

- `get routes` — auto-discovers all your routes from the running dev server
- Code inspection — read any file in your project
- Debugging — understand your actual error, not a description of it
- Editing — make changes with full context of your patterns

## What MCP Is NOT

- **It is not a debugging tool per se.** It helps your AI **find** routes and **understand** code. You still test and verify behavior yourself.
- **It is not production code.** MCP is a development-time tool — it does not run in your deployed app.
- **It is not only for Cursor.** Works with Gemini CLI, VS Code, Codex, and other AI agents.

## Nutshell

| Without MCP | With Next.js MCP |
|---|---|
| AI needs you to paste code manually | AI reads your real codebase automatically |
| Generic answers based on pasted text | Precise answers based on actual routes + logic |
| You hunt through folders for routes | `get routes` lists everything instantly |
| No code editing based on real structure | AI can safely edit based on real patterns |
