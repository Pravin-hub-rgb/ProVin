Until now, the Photo Gallery runs on your local machine — started with `npm run dev` at `localhost:3000`. Everything works locally, but **to show it to the world, you need a live URL.** Only you can see it right now — no one else.

The manual approach: rent a VPS/Virtual server, install Node.js, run `npm run build`, start with `npm start`, set up an nginx reverse proxy, get an SSL certificate, maintain the server (RAM, updates, backups). Do all of this — only then does the app go live. **It's a lot of work.**

Now let's look at Vercel — which is so simple that **deploying is just a git push.**

---

## Manual Approach — Self-Hosting (Problem)

When self-hosting, here's what you need to do:

1. **Get a server** — AWS/DigitalOcean/VPS, install Node.js
2. **Deploy code** — git clone, `npm install`, `npm run build`, `npm start`
3. **Reverse proxy** — port forwarding with nginx or Apache
4. **SSL certificate** — via Let's Encrypt or manual setup
5. **Environment variables** — set `.env` on the server
6. **Maintain** — server updates, RAM monitoring, backups
7. **Domain setup** — configure DNS records

Do all of this — only then does the app go live. And when an update comes (new code pushed) — rebuild + restart again. **Every deploy is manual.**

---

## CONCEPT — Vercel (Zero-Config Deploy)

Vercel is the platform built by Next.js creators. It does everything **automatically:**

- **Git push = deploy** — push to git, Vercel automatically builds + deploys
- **Environment variables** — set them in the Vercel dashboard, no `.env` file needed
- **SSL/TLS** — automatic (via Let's Encrypt)
- **Preview deployments** — each PR gets a different preview URL
- **Server-side features** — ISR, Image Optimization, Edge Middleware all work
- **Zero-config** — mostly, you don't need to add anything extra in `next.config.ts`

---

## CODE — Before Deploy: `npm run build`

Before deploying, **check the local build** — make sure there are no errors in the production build:

```bash
npm run build
```

This command creates a **production build** — exactly what Vercel will build. If an error appears in the local build — fix it first. There's a difference between production build and `npm run dev`:

- `npm run dev` — development mode, hot reload, error overlay
- `npm run build` — production build, optimized, static generation, strict checks

Once the build succeeds, you can locally test production mode with `npm run start`.

## CODE — Deploy to Vercel (Step by Step)

### Step 1: Push to GitHub

```bash
git add .
git commit -m "Photo Gallery ready for deploy"
git push origin main
```

The code needs to be on GitHub — that's where Vercel pulls from.

### Step 2: Import into Vercel

1. Go to [vercel.com](https://vercel.com) → Sign in with GitHub
2. **"Add New..."** → **"Project"**
3. Select your GitHub repo
4. Vercel automatically detects that it's a **Next.js project**
5. Click **"Deploy"**

That's it. The build starts. It'll be deployed in 1-2 minutes.

### Step 3: Set Environment Variables

Vercel dashboard → **Settings** → **Environment Variables**:

| Key | Value | Environment |
|---|---|---|
| `DATABASE_URL` | `postgresql://...` | Production, Preview |
| `AUTH_SECRET` | `cX8v7K9m...` | Production, Preview |

These variables exist only on Vercel's servers — not in the client bundle (because `NEXT_PUBLIC_` was not added).

### Step 4: Domain (Optional)

Vercel automatically gives you a `.vercel.app` URL. If you want a custom domain:
- Vercel dashboard → **Settings** → **Domains**
- Add your domain
- Set DNS records (Vercel tells you what to set)

## CONCEPT — Preview vs Production Deployments

Vercel creates two types of deployments:

| Type | When it's created | URL |
|---|---|---|
| **Preview** | Every PR (pull request) | `preview-abc123.vercel.app` |
| **Production** | Push to `main` branch | `your-app.vercel.app` |

**Preview deployment** — a separate URL for each PR. Team members can review changes without affecting production. Once merged, production deploys.

**Production deployment** — pushing to the `main` branch = live deploy. This is your production URL.

## What It Is NOT

- **Vercel = "everything free" is NOT true.** The free tier has limited builds per month. The paid plan has unlimited. But the free tier is enough for personal projects.
- **`npm run dev` = "production build" is NOT true.** Development mode gives hot reload + error overlay. Production build is via `npm run build` — optimized, static generation, strict checks.
- **Deploy = "done" is NOT true.** After deploying, verify — routes, images, errors, security. Deploying is easy, verifying is necessary.
- **Preview deployment = "staging environment" is NOT true.** Preview is temporary — it disappears after the PR is merged. You need a separate environment for staging.
