In 8.5.2 we audited env + config. Now add **error boundaries.** The Photo Gallery currently has only a basic `error.tsx` (1.4 level). A production app needs:

1. **`global-error.tsx`** — the last resort when the root layout crashes
2. **Route-level error boundaries** — proper error handling on each route
3. **Verify the hierarchy** — the error boundary hierarchy works correctly

---

## Step 1 — Add `global-error.tsx`

First, create **global-error.tsx** in the root `app/` folder:

**File:** `app/global-error.tsx` — new file

```tsx
'use client'

export default function GlobalError({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  return (
    <html lang="en">
      <body>
        <div style={{
          display: "flex",
          flexDirection: "column",
          alignItems: "center",
          justifyContent: "center",
          minHeight: "100vh",
          fontFamily: "system-ui, sans-serif",
        }}>
          <h2 style={{ fontSize: "1.5rem", marginBottom: "1rem" }}>
            Something went very wrong
          </h2>
          <p style={{ color: "#666", marginBottom: "1.5rem" }}>
            {error.message || "Unexpected error occurred"}
          </p>
          <button
            onClick={() => reset()}
            style={{
              padding: "0.75rem 1.5rem",
              backgroundColor: "#0070f3",
              color: "white",
              border: "none",
              borderRadius: "8px",
              cursor: "pointer",
              fontSize: "1rem",
            }}
          >
            Try Again
          </button>
        </div>
      </body>
    </html>
  )
}
```

**Important:**
- `'use client'` is required
- Include `<html>` and `<body>` — the root layout is replaced entirely
- A clean, friendly UI — the user should understand something went wrong

## Step 2 — Photo Detail Route Error Boundary

The Photo Gallery has a `/photo/[id]` route — add an error boundary there too:

**File:** `app/photo/[id]/error.tsx` — new file

```tsx
'use client'

export default function PhotoError({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  return (
    <div style={{
      display: "flex",
      flexDirection: "column",
      alignItems: "center",
      justifyContent: "center",
      padding: "4rem 2rem",
    }}>
      <h2 style={{ fontSize: "1.25rem", marginBottom: "1rem" }}>
        Could not load this photo
      </h2>
      <p style={{ color: "#666", marginBottom: "1.5rem" }}>
        {error.message || "Something went wrong loading this photo."}
      </p>
      <button
        onClick={() => reset()}
        style={{
          padding: "0.5rem 1rem",
          backgroundColor: "#0070f3",
          color: "white",
          border: "none",
          borderRadius: "6px",
          cursor: "pointer",
        }}
      >
        Try Again
      </button>
    </div>
  )
}
```

## Step 3 — Verify Error Hierarchy

Now check the Photo Gallery's error hierarchy:

```
app/
├── global-error.tsx         ← ✅ Added (root layout crash)
├── layout.tsx               ← Root layout
├── page.tsx                 ← / (home)
├── photo/
│   ├── [id]/
│   │   ├── error.tsx        ← ✅ Added (/photo/[id] errors)
│   │   └── page.tsx         ← /photo/:id
│   └── page.tsx             ← /photo (gallery list)
├── @modal/
│   └── (.)photo/[id]/
│       └── page.tsx         ← Modal (client component)
```

**Hierarchy flow:**
1. Error on `/photo/5` → caught by `photo/[id]/error.tsx` ✅
2. Error in root layout → caught by `global-error.tsx` ✅
3. Error in gallery list (`/photo`) → caught by `app/error.tsx` (if present) or falls back to `global-error.tsx` ✅
