## The MCP Tools Available

When MCP is configured, your AI agent gets access to tools like:

| Tool | What it does |
|---|---|
| `get routes` | Lists all routes discovered from your app's file system |
| `get route` | Shows the code for a specific route (page.tsx, layout.tsx, etc.) |
| `get component` | Reads a component file by name |
| `get middleware` | Inspects your middleware/route handlers |

## Using `get routes`

Ask your AI assistant: **"What routes does my app have?"** or **"List all routes."**

The AI calls `get routes` — MCP reads your `app/` directory and returns something like:

```
Route (app)
┌ ○ /                                  → app/page.tsx
├ ○ /_not-found                        → app/not-found.tsx
├ ƒ /api/notes                         → app/api/notes/route.ts
├ ƒ /api/progress                      → app/api/progress/route.ts
├ ○ /blog                              → app/blog/page.tsx
├ ○ /blog/[slug]                       → app/blog/[slug]/page.tsx
├ ○ /dashboard                         → app/dashboard/page.tsx
└ ƒ /dashboard/api/stats               → app/dashboard/api/stats/route.ts

○  (Static)   prerendered as static content
ƒ  (Dynamic)  server-rendered on demand
```

**This is live data from your running app** — not your memory of the file structure. The AI sees the actual routes, whether they are static (`○`) or dynamic (`ƒ`), and where they map in the filesystem.

## Inspecting a Route

Once you know a route exists, ask: **"Show me the code for /blog/[slug]."**

The AI calls `get route app/blog/[slug]/page.tsx` and returns the **actual file contents** — not your recollection of it:

```tsx
// app/blog/[slug]/page.tsx
import { notFound } from 'next/navigation';
import { getPostBySlug } from '@/lib/posts';

export default async function BlogPost({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  const post = getPostBySlug(slug);

  if (!post) notFound();

  return (
    <>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </>
  );
}
```

Now you can ask: **"Why is this route throwing a 500?"** The AI sees the actual code, spots the bug, and suggests a fix.

|---|---|

| `get middleware` | "What does my middleware do?" — reads route handlers |

## Common Mistakes

- ❌ **Not starting the dev server first** — MCP reads from the live app. No dev server = no data.
- ❌ **Asking generic questions** — "build a todo app" doesn't need MCP. "how do my routes work?" does.
- ❌ **Expecting MCP to find non-route files** — it discovers routes from Next.js's routing. For other files, use `get component` or ask the AI to read a specific path.

## What It Is NOT

- **It is not a file explorer.** MCP discovers routes from Next.js's routing system — it's optimized for the routing data layer, not arbitrary file browsing.
- **It is not a debugger.** It helps your AI **find** and **understand** code. The AI still reads the logic and suggests fixes.
