1.1 mein humne banaye teen pages — Home, About, Contact. Par ek problem dekhi: **footer har page pe repeat** ho raha tha. Agar 10 pages ho toh 10 baar footer likhna padega. Ye toh galat hai — code duplicate ho raha hai.

React mein iska fix manually karna padta tha — ek `<Layout>` component banao, usme `<Routes>` wrap karo. Ab Next.js mein ye built-in hai: **`layout.tsx`.**

---

## Manual Approach — React Router Mein Kya Karte The

React Router mein shared layout chahiye toh ye karna padta tha:

```tsx
// App.tsx — React Router
import { Routes, Route } from 'react-router-dom';
import Home from './pages/Home';
import About from './pages/About';
import Layout from './components/Layout';

export default function App() {
  return (
    <Layout>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </Layout>
  );
}
```

```tsx
// components/Layout.tsx
export default function Layout({ children }) {
  return (
    <div>
      <Navbar />
      {children}
      <Footer />
    </div>
  );
}
```

Layout alag file mein banana padta tha, phir usme `<Routes>` wrap karna padta tha. **Har naye route ke liye `<Route>` tag bhi likhna, layout bhi apply karna.**

---

## Better Approach — Next.js Ka `layout.tsx`

Next.js mein ye automatically hota hai. `app/layout.tsx` banao — **har page pe automatically apply ho jayega.** Route change pe layout reset nahi hota — wohi navbar, wohi footer, sirf content change hota hai.

```
app/
├── layout.tsx        →  shared layout (har page pe)
├── page.tsx          →  /          (home)
├── about/
│   └── page.tsx      →  /about
└── contact/
    └── page.tsx      →  /contact
```

---

## `layout.tsx` Kaise Kaam Karta Hai

**`app/layout.tsx`** ek special file hai. Ye har page ke around wrap hoti hai — jaise React mein `<Layout>{children}</Layout>`. Par yahan manually wrap nahi karna — Next.js khud karta hai.

```tsx
// app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <nav>My Site</nav>
        {children}
        <footer>© 2026 My Site</footer>
      </body>
    </html>
  );
}
```

Ab har page pe automatically `<nav>` aur `<footer>` hoga. Koi page mein footer repeat nahi karna. `page.tsx` mein sirf content likho:

```tsx
// app/page.tsx — sirf content
export default function Home() {
  return <h1>Home Page</h1>;
}
```

```tsx
// app/about/page.tsx — sirf content
export default function About() {
  return <h1>About Page</h1>;
}
```

Notice kiya? **Layout alag hai, content alag hai.** Layout sirf ek baar likha — har page pe apply ho raha hai. Footer 10 baar nahi likha — ek baar `layout.tsx` mein likha, 10 pages pe kaam kar raha hai.

---

## Route Change Pe Layout Reset Nahi Hota

Ye sabse important behavior hai. Browser mein `/about` se `/contact` pe jao — **navbar aur footer wohi rehte hain.** Sirf `{children}` wala content change hota hai.

React Router mein kya hota tha? Agar layout component re-mount hota tha toh navbar bhi re-render hota tha — animation ya scroll position reset ho jaati thi. Next.js mein **layout mount ek hi baar hota hai**, sirf content swap hota hai.

---

## Nested Layouts — Har Section Ka Apna Layout

Ek aur powerful cheez — **nested layouts.** Agar tumhara `/blog` section apna alag layout chahta hai (jaise blog sidebar), toh `app/blog/layout.tsx` banao:

```
app/
├── layout.tsx              →  root layout (sab pe apply)
├── page.tsx                →  /
├── about/
│   └── page.tsx            →  /about
└── blog/
    ├── layout.tsx          →  sirf blog pages pe apply
    ├── page.tsx            →  /blog
    └── [slug]/
        └── page.tsx        →  /blog/:slug
```

`app/blog/layout.tsx` sirf `/blog` aur `/blog/[slug]` pages pe apply hoga. Root layout toh sab pe hai hi — **dono layouts ek doosre ke upar stack hote hain.**

---

## Server vs Client — Layout Mein Bhi

0.7 mein humne samjha ki `layout.tsx` default **Server Component** hai. Agar usme `<Navbar />` dalna hai jisme `useState`, click handlers hain — toh `Navbar` ko `"use client"` banana padega. Layout server pe render hoga, Navbar client pe hydrate hoga. Boundary clear hai — "use client" line ke upar server, neeche client.

```tsx
// components/Navbar.tsx
"use client";
import { useState } from 'react';

export default function Navbar() {
  const [menuOpen, setMenuOpen] = useState(false);
  return (
    <nav>
      <button onClick={() => setMenuOpen(!menuOpen)}>Menu</button>
      {menuOpen && <div>Links...</div>}
    </nav>
  );
}
```

```tsx
// app/layout.tsx — Server Component
import Navbar from '@/components/Navbar';

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <Navbar />        {/* Client Component — hydrate hoga */}
        {children}        {/* Server Component — ready HTML */}
      </body>
    </html>
  );
}
```

Server pe `Navbar` ka sirf placeholder aata hai, client pe JS bundle aake hydrate karta hai — ye 0.4 ka hydration concept hai.

## In Your Own Words

1. React Router mein shared layout kaise banate the, aur Next.js mein kya fark hai?

<details>
<summary>Sample Jawab</summary>

**Jawab:** React Router mein manually `<Layout>` component banana padta tha aur usme `<Routes>` wrap karna padta tha. Next.js mein `app/layout.tsx` banao — har page pe automatically apply hota hai. Koi wrapping nahi, koi manual setup nahi.

</details>

2. Route change pe layout reset kyun nahi hota?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Next.js mein layout mount ek hi baar hota hai. Sirf `{children}` wala content swap hota hai. Isliye navbar, footer, scroll position — sab preserved rehta hai.

</details>

3. Nested layout kya hai aur kab use karenge?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Agar kisi section (jaise `/blog`) ka apna alag layout chahiye (sidebar, alag styling), toh us folder mein `layout.tsx` banao. Root layout sab pe apply hota hai, nested layout sirf us section pe. Dono stack hote hain.

</details>

4. Layout Server Component hai toh usme Client Component (jaise Navbar) kaise dalenge?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Layout mein Client Component ko import karke render karo — ye valid hai. Client Component mein `"use client"` lagao. Server pe layout ka HTML banta hai, Client Component ka placeholder aata hai, client pe JS bundle aake hydrate karta hai.

</details>

## What It Is NOT

⚠️ **Layout = sirf header/footer nahi.** Kuch bhi repeat karna ho — sidebar, navigation, branding — sab layout mein ja sakta hai.

⚠️ **Har folder mein `layout.tsx` zaroori nahi.** Sirf root `app/layout.tsx` zaroori hai. Baaki folders mein sirf tab jab section-specific layout chahiye.

⚠️ **Layout aur page ek doosre ko override nahi karte.** Layout wrapper hai, page content hai. Dono milke final output banate hain.

---

Footer repeat ki problem solve ho gayi. Ab ek aur problem hai — abhi sab pages static hain. Agar blog posts dynamic ho — `/blog/my-first-post`, `/blog/second-post` — toh kya karenge? Agla concept: **Dynamic Routes + Params.**
