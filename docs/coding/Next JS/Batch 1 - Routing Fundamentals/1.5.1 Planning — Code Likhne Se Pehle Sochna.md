Batch 1 mein tumne routing ke saare concepts seekhe — file-based routing (1.1), layouts (1.2), dynamic routes (1.3), states (1.4). Ab time hai inko ek jagah jodne ka — ek asli project. Par ruko. **Pehle ek baat saaf karein.**

Tum ab tak jo code dekh rahe ho, usme har file ka code already likha hua milta hai. Bas copy-paste karte chale ja rahe ho. Isme kuch galt nahi — learning ke liye jaroori hai. Par **asli coding skill copy-paste nahi hai, planning hai.** Jis din tumko khud project banana hoga, tumhare paas koi file nahi hogi jisse copy karo. Toh ab, combined project se, hum ek nayi cheez seekhenge — **code likhne se PEHLE kya sochna chahiye.**

Yeh series (1.5.1 se 1.5.5) tumhe project banane ka asli process sikhayegi:
- Pehle **plan karo** (kaise sochna hai, kya banana hai)
- Phir **hardcoded UI dekho** (pehle static data se UI samjho)
- Phir **data layer banao** (post.ts kyun, type kyun)
- Phir **dynamic banate** (data aur UI ko jodo)
- Last mein **states + test** (sab kaam karta hai confirm karo)

Chalo, step 1 — planning.

## Planning Kya Hai — Code Likhne Se Pehle Ka Sochna

Ek ghar banane se pehle architect ek **naksha** (blueprint) banata hai — kamre kitne, kahan hoga kitchen, kahan bathroom. Bina naksha ke seedha eent rakhni shuru karo toh ghar kaisa banega? **Designer soch, execution baad mein.**

Coding bhi exactly yahi hai. Project start karne se pehle, chand sawaalon ka jawab sochna hota hai:

1. **Kya banana hai?** — Project ka purpose
2. **Kya-kya pages chahiye?** — Routes ka structure
3. **Data kya hai?** — Kaunsa data render karna hai, uska shape kya hoga
4. **Pages ko data kaise milega?** — Data flow

Ye sab soch liya toh code likhna sirf execution ban jaata hai — form bharne jaisa. Planning hi asli kaam hai.

## Sawaal 1 — Kya Banana Hai?

Hum ek **Portfolio site** banayenge — ek developer ki personal website. Jaise real developers ki hoti hai: Home, About, Projects, Contact. Aur saath mein ek **Blog section** jahan developer apni baatein likhta hai.

Kyun portfolio? Kyunki:
- Routing ke saare concepts naturally use honge (static pages + dynamic blog)
- Ye ek **real project** hai jo tum apne naam pe deploy kar sakte ho
- Agla batch (2) isi ko upgrade karega — "v2" — toh iska foundation solid hona chahiye

## Sawaal 2 — Kya-Kya Pages Chahiye?

Ab sochte hain routes ka structure. Static pages + ek dynamic blog:

| Route | Page | Kaunsa concept |
|---|---|---|
| `/` | Home — hero section | File-based routing (1.1) |
| `/about` | About Me | File-based routing |
| `/projects` | Projects list | File-based routing |
| `/contact` | Contact info | File-based routing |
| `/blog` | Blog posts list | File-based routing + data |
| `/blog/[slug]` | Single blog post | Dynamic route (1.3) |

Ye structure dekh ke turant pata chalta hai ki file system kaise banega:

```
app/
├── layout.tsx           →  root layout (Navbar + Footer)
├── page.tsx             →  /
├── about/page.tsx       →  /about
├── projects/page.tsx    →  /projects
├── contact/page.tsx     →  /contact
├── blog/
│   ├── page.tsx         →  /blog
│   └── [slug]/page.tsx  →  /blog/[slug]
└── not-found.tsx        →  404
```

**Dhyan do:** Ye folder structure maine pehle hi soch liya — code likhne se pehle. Kyunki 1.1 se pata hai ki Next.js mein folder = route. So structure sochna = routes sochna. Planning ka poora fayda yahi hai.

## Sawaal 3 — Data Kya Hai?

Ab sabse important sawaal — **data ka shape.** Blog posts dikhane hain. Ek post mein kya-kya cheezein hongi?

Socho — `/blog` list mein kya dikhega? Aur `/blog/[slug]` single page pe kya? Aisa socho ki pehle UI socho, phir data:

**List page (`/blog`) pe:**
- Post ka title (link banane ke liye)
- Ek chhoti si line (excerpt) — taaki user ko pata chale post kya hai

**Single post page (`/blog/[slug]`) pe:**
- Title
- Date
- Poora content

Aur ek cheez jo dono jagah chahiye — **slug.** Kya hai ye? 1.3 se yaad — URL mein jo dynamic value aati hai (`/blog/pehla-post` mein "pehla-post"). Link banane ke liye slug hi chahiye.

Isliye post ka shape aisa banta hai:

```
Post {
  slug: string      ← URL ke liye (pehla-post)
  title: string     ← Heading ke liye
  date: string      ← Single post pe dikhega
  excerpt: string   ← List pe dikhega
  content: string   ← Single post pe dikhega
}
```

**Har field ka ek kaam hai** — koi bhi field aise hi nahi rakha. Data structure kaise sochta hai, yahi asli skill hai: **UI dekh ke data ke fields decide karna.**

> **Analogy:** Ek form socho. User ko kaunse fields dikhane hain, pehle wo socho. Phir data structure wahi fields banega. UI hi data ki shape decide karta hai — ulta nahi.

## Sawaal 4 — Data Flow Kaise Hoga?

Ab tak: pages ka structure hai, data ka shape hai. Ab — data kahan rakhenge aur pages ko milega kaise?

Sabse simple tareeka: data ko **ek alag file** mein rakho. React course mein bhi shared data alag file mein rakhte the — kyun? Kyunki `/blog` list aur `/blog/[slug]` dono ko post data chahiye. Agar har page apna data rakhe, toh duplication hogi — post badli toh do jagah badalni padegi. **DRY principle** (Don't Repeat Yourself) — React Batch se yaad hai.

Isliye:

```
lib/
└── posts.ts         →  post data + functions (shared)
```

Aur functions bhi sochna hai — pages kya karenge:
- `/blog` page ko **saare posts** chahiye → `getAllPosts()`
- `/blog/[slug]` page ko **ek specific post** chahiye → `getPostBySlug(slug)`

Do functions, do zarooratein. Plan mein hi ye soch liya.

## Ab Tak Ka Plan — Summary

```
1. Kya: Portfolio + Blog site
2. Pages: Home, About, Projects, Contact, Blog, Blog/[slug]
3. Data: Post = { slug, title, date, excerpt, content }
4. Data flow: lib/posts.ts → getAllPosts() / getPostBySlug() → pages
```

**Is plan ke bina code likhne se kya hoga?** Tumhe folder banana shuru karega, beech mein pata chalega "are post mein date bhi chahiye", phir usko add karega, phir structure badlega... **Planning ki kami code mein chaos ban jaati hai.** Plan hone ke baad code execution hai — bas ek form bharna hai.

## Nutshell

Planning = code likhne se pehle 4 sawaal ka jawab: kya banana hai, kaunse pages, data ka shape, data ka flow. Data structure UI se decide hota hai — pehle socho kya dikhana hai, phir fields banao. Yehi coder mindset hai — **execution se pehle design.**

## What It Is NOT

⚠️ **Planning = "documentation likhna" nahi.** Ye formal document nahi hai — bas dimaag mein ya chhote notes mein 4 sawaal ka jawab. Over-engineering mat karo, bas direction clear ho.

⚠️ **Planning = "final structure" nahi.** Plan change ho sakta hai. Kaam karte waqt nayi cheez pata chali toh update karo. Plan guide hai, jail nahi.

⚠️ **Yeh "hardcoded data" nahi hai — abhi sirf plan hai.** Data abhi kisi file mein hai hi nahi. Agla step ye dekhna hai ki UI kaise dikhega.

---

Ab plan taiyar hai — pages, data shape, flow sab soch liya. Agla step: **hardcoded data se UI dekhna.** Kyunki pehle ye dikhna chahiye ki page kaise dikhta hai, phir data structure pakka karna. Chalo 1.5.2 mein milte hain.
