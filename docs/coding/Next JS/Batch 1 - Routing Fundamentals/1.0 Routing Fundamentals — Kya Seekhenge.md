Module 0 mein humne Next.js ka mental model samjha — SSR, SSG, ISR, Server Components, Hydration, Caching, App Router, create-next-app. Sab foundation taiyar hai. Ab waqt hai us foundation pe **haath gandhe ka** — pehla hands-on batch: **Routing Fundamentals.**

React course mein jab tumne pehli baar multi-page feel banaya tha, toh `React Router` use kiya tha — `<Routes>`, `<Route>`, `<Link>`, `useParams`. Yaad hai? Config likhte the — "ye path hai, ye component render karo." Ab Next.js mein wohi kaam **alag tareeke** se hota hai — aur honestly, better hai.

## Kya Seekhenge Is Batch Mein

Char concepts hain, har ek ka apna mini-project:

**A — File-based Routing Basics.** React Router mein tum `<Route path="/about" element={<About />} />` likhte the. Ab? Folder banao, `page.tsx` daal do — route ban gaya. Koi config nahi, koi setup nahi. Folder structure hi route hai. Mini-project: **Simple Multi-page Site** — Home, About, Contact, teen static pages.

**B — Nested Layouts.** React mein jab shared layout chahiye tha (Navbar, Footer), toh manually wrap karna padta tha — `<Layout><Routes>...</Routes></Layout>`. Ab? `layout.tsx` likho — har page pe automatically apply hota hai. Route change pe layout reset nahi hota. Mini-project: Same multi-page site mein ek shared Navbar/Footer add karo.

**C — Dynamic Routes + Params.** React Router mein `:id` use karte the aur `useParams()` se value nikalte the. Ab? `[id]` folder banao — URL se variable automatically extract hota hai. Mini-project: **Blog Post Pages** — `/blog/[slug]` dynamic route, dummy data se.

**D — Loading, Error, Not-Found States.** React mein manually Suspense, ErrorBoundary, 404 route banana padta tha. Ab? `loading.tsx`, `error.tsx`, `not-found.tsx` teen files daal do — Next.js khud handle karta hai. Mini-project: Blog project mein in teeno states ko add karo.
