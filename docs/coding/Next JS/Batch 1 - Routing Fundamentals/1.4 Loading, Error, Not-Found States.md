Ab tak humne banaye pages, layouts, dynamic routes. Par ek cheez missing hai — **user experience jab kuch slow ho ya galat ho.** Data load ho raha hai toh user ko pata hona chahiye. Error aaya toh gracefully handle hona chahiye. Page nahi mila toh 404 dikhna chahiye.

React mein manually Suspense, ErrorBoundary, 404 route banana padta tha. Next.js mein teen files hain — `loading.tsx`, `error.tsx`, `not-found.tsx` — **bas daal do, Next.js khud handle karta hai.**

---

## Manual Approach — React Mein Kya Karte The

React mein ye sab manually karna padta tha:

```tsx
// React — manually Suspense banana padta tha
import { Suspense } from 'react';

export default function App() {
  return (
    <Routes>
      <Route
        path="/blog/:slug"
        element={
          <Suspense fallback={<div>Loading...</div>}>
            <BlogPost />
          </Suspense>
        }
      />
    </Routes>
  );
}
```

```tsx
// React — ErrorBoundary alag class component
class ErrorBoundary extends React.Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false };
  }
  static getDerivedStateFromError(error) {
    return { hasError: true };
  }
  render() {
    if (this.state.hasError) {
      return <h1>Something went wrong</h1>;
    }
    return this.props.children;
  }
}
```

```tsx
// React — 404 route manually
<Route path="*" element={<NotFound />} />
```

Har cheez ka alag setup — Suspense wrapper, ErrorBoundary class, catch-all route. **Boilerplate bahut tha.**

## Better Approach — Next.js Ki Teen Special Files

Next.js mein teen conventions hain — inhe apne folder mein daal do, automatically kaam karte hain:

| File | Kya karta hai |
|---|---|
| `loading.tsx` | Jab page data load ho raha ho — turant "Loading..." dikhata hai |
| `error.tsx` | Jab error aaye — gracefully error message dikhata hai |
| `not-found.tsx` | Jab page na mile — custom 404 page dikhata hai |

---

## `loading.tsx` — Data Load Hote Waqt

Jab koi page server pe data fetch kar raha hai (async function), user ko wait nahi karna chahiye. `loading.tsx` daal do — **Next.js automatically loading state dikhata hai jab tak page ready nahi hota.**

```tsx
// app/blog/[slug]/loading.tsx
export default function Loading() {
  return <p>Loading blog post...</p>;
}
```

```tsx
// app/blog/[slug]/page.tsx
export default async function BlogPost({ params }) {
  const { slug } = await params;
  // Imagine — yahan slow fetch ho raha hai
  const post = await fetchPost(slug);
  return <h1>{post.title}</h1>;
}
```

Jab `/blog/my-first-post` pe jaoge — pehle "Loading blog post..." dikhega, phir page load hone pe actual content. **Manually Suspense wrap nahi karna — Next.js khud karta hai.**

---

## `error.tsx` — Error Gracefully Handle Karna

Jab data fetch mein error aaye — network fail, API down, kuch bhi — `error.tsx` automatically catch karta hai:

```tsx
// app/blog/[slug]/error.tsx
"use client";

export default function Error({ error, reset }) {
  return (
    <div>
      <h2>Something went wrong!</h2>
      <p>{error.message}</p>
      <button onClick={() => reset()}>Try again</button>
    </div>
  );
}
```

**Note:** `error.tsx` mein `"use client"` zaroori hai — kyunki error handling client-side hoti hai (error object interact karna, reset function). Ye 0.3/0.7 ka server/client concept hai.

---

## `not-found.tsx` — Custom 404 Page

Jab koi page na mile — URL galat hai, post exist nahi karta — `not-found.tsx` dikhata hai:

```tsx
// app/not-found.tsx
export default function NotFound() {
  return (
    <div>
      <h2>404 — Page Not Found</h2>
      <p>Ye page exist nahi karta.</p>
    </div>
  );
}
```

Aur manually trigger bhi kar sakte ho — `notFound()` function call karo:

```tsx
// app/blog/[slug]/page.tsx
import { notFound } from 'next/navigation';

export default async function BlogPost({ params }) {
  const { slug } = await params;
  const post = await fetchPost(slug);

  if (!post) {
    notFound();  // automatically not-found.tsx render karega
  }

  return <h1>{post.title}</h1>;
}
```

## Build-up — Blog Project Mein Teeno States

Ab teeno files ko blog project mein dekhte hain:

```
app/
├── layout.tsx
├── not-found.tsx              →  global 404
├── page.tsx                   →  / (home)
└── blog/
    ├── layout.tsx             →  blog section layout
    ├── page.tsx               →  /blog
    └── [slug]/
        ├── loading.tsx        →  blog post loading
        ├── error.tsx          →  blog post error
        └── page.tsx           →  /blog/:slug
```

Har level pe alag error handling — global `not-found.tsx` sab pe apply hota hai, `[slug]` folder ka `loading.tsx` sirf blog post pe apply hota hai. **Hierarchical error handling.**

---

## `loading.tsx` Ka Behavior — Automatic Suspense

Ek baat clear kar lete hain — `loading.tsx` automatically ek `<Suspense>` boundary create karta hai. Tumhe manually `<Suspense>` wrap nahi karna. Next.js jaanta hai ki `page.tsx` mein `async` function hai, data load ho raha hai — isliye `loading.tsx` ko turant render karta hai jab tak page ready nahi hota.

Ye **streaming** ka concept hai — content progressively load hota hai. Pehle loading state, phir actual content. User ko pata hai ki kuch ho raha hai — blank screen nahi dikhta.

## What It Is NOT

⚠️ **`error.tsx` = global error nahi.** Ye sirf us folder aur uske children pe apply hota hai. Global error ke liye `app/error.tsx` banao.

⚠️ **`loading.tsx` = sirf async pages ke liye nahi.** Agar page mein slow computation hai, woh bhi loading state trigger kar sakta hai.

⚠️ **`not-found.tsx` = sirf URL galat hone pe nahi.** `notFound()` function se manually bhi trigger kar sakte ho — jaise data na mila ho.
