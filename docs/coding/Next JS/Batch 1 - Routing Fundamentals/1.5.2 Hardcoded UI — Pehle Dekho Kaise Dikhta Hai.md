1.5.1 mein plan banaya — pages, data shape, flow sab soch liya. Ab aata hai sabse interesting step: **pehle data layer banane se pehle, UI ko hardcoded data se dekhna.**

Tum soche rahe hoge — "seedha `lib/posts.ts` bana ke dynamic kyun nahi kar dete?" Kyunki ek problem hai. **Agar pehle dynamic data + UI dono ek saath banate, toh error aane par pata nahi chalta ki UI mein galti hai ya data mein.** Do cheezein ek saath test karna mushkil hai.

Isliye senior developers ka tareeka: **pehle hardcoded data se UI banao — dekh lo UI kaise dikhta hai, kya data chahiye confirm karo — phir data layer banao.** Ek time pe ek cheez. Yehi "hardcoded first" approach hai.

---

## Ab Kya Bana Rahe Hain

Plan se (1.5.1) yaad karo — folder structure:

```
app/
├── layout.tsx           →  root layout (Navbar + Footer)
├── page.tsx             →  /          (home)
├── about/page.tsx       →  /about
├── projects/page.tsx    →  /projects
├── contact/page.tsx     →  /contact
├── blog/
│   ├── page.tsx         →  /blog      (posts list)
│   └── [slug]/page.tsx  →  /blog/[slug]
└── not-found.tsx        →  404
```

Is part mein hum **sirf hardcoded UI** banayenge — data page ke andar hi hardcoded string hai. `lib/posts.ts` nahi banayenge. Phir dekh lenge UI kaise dikhta hai.

## Step 5 — Blog List: `app/blog/page.tsx`

Ab yahan pehla **important decision.** Plan (1.5.1) mein data shape soch liya tha — post mein `slug`, `title`, `date`, `excerpt`, `content`. Par abhi data layer nahi hai — `lib/posts.ts` abhi banegi nahi. Toh list page pe kya karein?

**Hardcoded array se UI dekho.** Ek post ki shape jo final hogi, usi se 3-4 hardcoded posts banao aur UI render karo:

```tsx
// app/blog/page.tsx
import Link from "next/link";

// ⚠️ ABHI hardcoded — bas UI dekhne ke liye. Agle part mein ise lib/posts.ts se replace karenge.
const posts = [
  {
    slug: "pehla-post",
    title: "Mera Pehla Blog Post",
    excerpt: "Next.js routing seekhne ka pehla din.",
  },
  {
    slug: "dynamic-routes",
    title: "Dynamic Routes — [slug] Folder",
    excerpt: "Ek page, anek URLs.",
  },
  {
    slug: "loading-error-404",
    title: "Loading, Error aur 404",
    excerpt: "Teen files jo UX ko smooth banati hain.",
  },
];

export default function Blog() {
  return (
    <main>
      <h1>Blog</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.slug}>
            <Link href={`/blog/${post.slug}`}>{post.title}</Link>
            <p>{post.excerpt}</p>
          </li>
        ))}
      </ul>
    </main>
  );
}
```

**Notice kya kiya:** 
- `title` + `excerpt` list mein dikha rahe hain — plan se exactly wahi fields
- `slug` se link bana rahe hain — `/blog/pehla-post`
- `date` aur `content` is list mein **nahi** hai — kyun? Kyunki plan mein decide kiya tha ki ye single post page pe chahiye. List pe nahi.

**Yehi planning ka fayda hai** — hardcoded UI se confirm ho raha hai ki data shape sahi hai. Pehle UI dekh kar pata chalta hai, phir data structure pakka karna.

## Step 6 — Single Post: `app/blog/[slug]/page.tsx`

Ab dynamic route (1.3 se yaad) — folder `[slug]`, params se value. Par abhi `getPostBySlug()` function nahi hai (agla part). Toh hardcoded how? 

Ek **hardcoded posts array** page ke andar, aur `params.slug` se match karo:

```tsx
// app/blog/[slug]/page.tsx
import { notFound } from "next/navigation";

// ⚠️ ABHI hardcoded — bas UI dekhne ke liye
const posts = [
  {
    slug: "pehla-post",
    title: "Mera Pehla Blog Post",
    date: "7 Aug 2026",
    excerpt: "Next.js routing seekhne ka pehla din.",
    content: "Yeh mera pehla blog post hai. Maine file-based routing se yeh page banaya hai.",
  },
  {
    slug: "dynamic-routes",
    title: "Dynamic Routes — [slug] Folder",
    date: "8 Aug 2026",
    excerpt: "Ek page, anek URLs.",
    content: "Is post mein maine seekha ki [slug] folder se ek hi page multiple URLs handle karta hai.",
  },
  {
    slug: "loading-error-404",
    title: "Loading, Error aur 404",
    date: "9 Aug 2026",
    excerpt: "Teen files jo UX ko smooth banati hain.",
    content: "loading.tsx, error.tsx aur not-found.tsx — in teeno files ka experience is post mein hai.",
  },
];

interface BlogPostProps {
  params: Promise<{ slug: string }>;
}

export default async function BlogPost({ params }: BlogPostProps) {
  const { slug } = await params;          // URL se value (1.3 se yaad)
  const post = posts.find((p) => p.slug === slug);

  if (!post) {
    notFound();                           // slug nahi mila → 404 (1.4 se yaad)
  }

  return (
    <main>
      <h1>{post.title}</h1>
      <p>{post.date}</p>
      <p>{post.content}</p>
    </main>
  );
}
```

**Teen important cheezein:**
1. `params` ek Promise hai (Next.js 15+) — `await` lagaya
2. `posts.find(p => p.slug === slug)` — array se match kiya. `undefined` aaya toh `notFound()`
3. `date` + `content` **yahi** dikh rahe hain — list mein nahi the. Plan ke hisaab se perfect.

Ab browser mein check karo — `/blog` list dikhta hai, `/blog/pehla-post` single post dikhta hai. **UI ready hai, sirf hardcoded data se.**

## Ab Humne Kya Seekha — Hardcoded First Ka Fayda

Ab ek baat socho. Agar tumne seedha `lib/posts.ts` bana ke dynamic kar dete, toh kya hota? Kuch bhi galat hua — UI ka styling issue, data shape ka issue, ya function ka issue — sab ek saath. Debug mushkil.

Hardcoded first se:
1. **UI ka design confirm** — ab pata hai page kaise dikhega, kya data chahiye
2. **Data shape validate** — `slug/title/date/excerpt/content` — sab jagah kaam kar raha hai
3. **Ek problem ek time pe** — ab agar agle part mein data layer banega, aur kuch galti hui, toh pata hoga ki wo **data layer ki galti hai** (UI already tested hai)

**Par ek problem ab dikh rahi hai** — hardcoded posts array **do jagah** hai — list page mein aur single post page mein. Do jagah same data. Agar post change karna ho toh do jagah karna padega. Ye duplication hai — DRY violation. Aur yahi se agle part ki shuruaat hogi.

---

## Nutshell

Hardcoded first = pehle UI ko static data se dekhna, phir data layer banana. Fayda: ek time pe ek problem, UI design confirm, data shape validate. Problem jo dikhi: hardcoded posts do jagah duplicate hai — ye data layer ki zaroorat dikhata hai.

## What It Is NOT

⚠️ **Hardcoded UI = "final code" nahi.** Ye temporary hai — sirf UI dekhne ke liye. Agle part mein `lib/posts.ts` banake ise replace karenge. Hardcoded ko project mein chhodna nahi hai.

⚠️ **Hardcoded = "duplication theek hai" nahi.** Humne jabardasti do jagah data rakha hai — aur ye hume **dikhane ke liye** kiya hai ki duplication kyu bura hai. Agla part ise theek karega.

⚠️ **`posts.find` = "real data lookup" nahi.** Ye hardcoded array lookup hai. Real app mein ye database/API se aayega. Pattern (slug se post dhundhna) wahi rahega, source badlega.

---

Ab UI dekh liya, data shape confirm hua. Ab wo problem solve karni hai jo abhi dikhi — **duplicate posts data.** Agla step: **Data Layer — `lib/posts.ts`** mein post type, array, aur functions banayenge. Chalo 1.5.3 mein milte hain.
