Ab tak jo pages banaye — Home, About, Contact — sab **static** the. URL fixed tha: `/about`, `/contact`. Par socho agar tumhe blog posts dikhane ho — `/blog/my-first-post`, `/blog/second-post`, `/blog/hello-world` — toh har post ke liye alag folder nahi bana sakte. **Ek hi pattern chahiye jo different URLs handle kare.**

React Router mein tum `:id` use karte the. Next.js mein `[id]` folder syntax hai — concept same, implementation better.

---

## Manual Approach — React Router Mein `:id` + `useParams`

React Router mein dynamic route aisa dikhta tha:

```tsx
// React Router
<Route path="/blog/:slug" element={<BlogPost />} />
```

```tsx
// BlogPost.tsx
import { useParams } from 'react-router-dom';

export default function BlogPost() {
  const { slug } = useParams();
  return <h1>Blog Post: {slug}</h1>;
}
```

Route path mein `:slug` likhte the — React Router URL se value nikalke `useParams()` mein deta tha. **Config alag thi, component alag.**

---

## Better Approach — Next.js Ka `[slug]` Folder

Next.js mein **folder ka naam hi dynamic segment hai.** `[slug]` folder banao — URL se value automatically extract hoti hai aur `params` prop mein milti hai.

```
app/
├── layout.tsx
├── page.tsx
└── blog/
    ├── page.tsx              →  /blog
    └── [slug]/
        └── page.tsx          →  /blog/:slug
```

**Visual mapping:**

```
Folder:        blog/[slug]/page.tsx
URL:           /blog/my-first-post
                                    →  params.slug = "my-first-post"

URL:           /blog/hello-world
                                    →  params.slug = "hello-world"
```

---

## Syntax — `[variable]` Se Dynamic Route

### Pehle Ye Samjho — "Call" Ka Matlab Kya Hai?

JavaScript mein function likhna alag hai, **chalaana** alag hai:

```js
// Function likha — abhi kuch nahi ho raha
function greet(name) {
  return "Hello " + name;
}

// Function chalaya (CALL kiya) — ab kaam ho raha hai
greet("Pravin");   // "Hello Pravin"
```

**"Call" = function chalaana with value.** `greet("Pravin")` call kiya, `"Pravin"` value pass kiya.

### Ab Params Samjho — Next.js Chalata Hai, Values Bhar Dete Hai

Ab `BlogPost` ka code dekho:

```tsx
export default async function BlogPost({ params }) {
  const { slug } = await params;
  return <h1>Blog Post: {slug}</h1>;
}
```

Tumne ye function **likha** hai. Par tumne isse **kabhi call nahi kiya** — kahin `BlogPost({ params: { slug: "..." } })` nahi likha. Toh ye function chalega kab? **Next.js chalata hai.**

Jab user `/blog/my-first-post` pe jaata hai, Next.js khud ye karta hai:

```
BlogPost({ params: { slug: "my-first-post" } })
```

Tumne likha → **Next.js chalaya** → `params` ki value bhi **Next.js ne bhara.** Tumne bas function ki shape bata di ("mujhe `params` chahiye"), baaki Next.js ne kiya.

### BlogPage Ka Case — Call Hoti Hai, Params Nahi Milta

`blog/page.tsx` (posts ki list wala page) bhi aise hi chalta hai — Next.js usse bhi call karta hai:

```tsx
// app/blog/page.tsx
export default async function BlogPage() {   // Next.js ise bhi call karta hai
  // params nahi milta — kyunki folder mein [slug] nahi hai
  ...
}
```

`BlogPage` ko bhi Next.js call karta hai, bas `params` nahi deta. Rule simple: **folder mein `[variable]` hai toh params milta hai, nahi hai toh nahi.**

### Rule Simple Hai

1. Folder naam mein `[]` brackets lagao — `[slug]`, `[id]`, `[productId]`
2. `page.tsx` mein `params` prop lo
3. `params` se value nikalo

```tsx
// app/blog/[slug]/page.tsx
export default async function BlogPost({ params }) {
  const { slug } = await params;
  return <h1>Blog Post: {slug}</h1>;
}
```

**Note:** `params` ek Promise hai (Next.js 15+ mein) — isliye `await` lagana padta hai. React Router mein `useParams()` synchronous tha, yahan async hai.

> **Error mil raha hai — "Binding element 'params' implicitly has an 'any' type"?** Yeh tab aata hai jab tum TypeScript file (`.tsx`) mein `{ params }` use karte ho bina type bataye. TypeScript ko nahi pata ki `params` kya hai, isliye wo complain karta hai — **"tumne bataya hi nahi, main assume kar raha hoon `any`."** Fix simple hai — `params` ka type batado:
>
> ```tsx
> interface PageProps {
>   params: Promise<{ slug: string }>;
> }
>
> export default async function BlogPost({ params }: PageProps) {
>   const { slug } = await params;
>   return <h1>Blog Post: {slug}</h1>;
> }
> ```
>
> `Promise<{ slug: string }>` ka matlab: params ek Promise hai jo ek object resolve karega jisme `slug` string hai. Multiple segments hain toh object mein saare keys daalo — `params: Promise<{ slug: string; commentId: string }>`. TypeScript ka detailed section neeche padhoge.

### Piche Kya Ho Raha Hai — Step By Step

Browser mein `/blog/my-first-post` khulte hi:

1. Request Next.js server pe aayi: `GET /blog/my-first-post`
2. Next.js apne file-system routing se match karta hai — `app/blog/[slug]/page.tsx` mila
3. URL parse kiya: `my-first-post` → `slug`
4. Ab Next.js tumhara function chalata hai (call karta hai):

```
BlogPost({ params: { slug: "my-first-post" } })
```

5. Tumhari function ke andar `const { slug } = await params` → `slug = "my-first-post"` milta hai

`params` ko aise socho — ek plate jo **server khud tumhare haath mein de raha hai.** Tumne maanga nahi, lekin Next.js jaanta hai ki is route ke liye tumhe `params` chahiye, isliye woh khud de deta hai. Tumne bas plate pakadni hai.

### React Router Se Comparison — Confusion Kahan Thi

React Router mein tum **khud** value nikalte the:

```tsx
const { slug } = useParams();   // tumne khud hook se maanga
```

Wahan `<Route path="/blog/:slug">` mein config alag thi — React Router tumhe `useParams()` hook deta tha, aur tum maang ke lete the. **Config alag thi, component alag.**

Next.js mein config hat gaya — `[slug]` folder ka naam hi route bana deta hai. Isliye value **directly function argument ke roop mein** aati hai, kyunki ab Next.js hi tumhare page ko call karta hai. `useParams` naam ka koi hook hai hi nahi — params props mein hi mil jaate hain.

> **Bonus insight:** Yeh sirf `params` ka khaas pattern nahi — poora React ka **props concept** yahi hai. Tum jis function ko component banate ho, React/Next.js use **uske props ke saath call** karta hai. `params` usi ka ek special case hai jo URL se aata hai. Baaki props tum khud pass karte ho, `params` Next.js khud pass karta hai.

## Minimal Example — Sirf Dynamic Route

Chal banate hain — blog post page jo URL se title dikhaye:

```tsx
// app/blog/[slug]/page.tsx
export default async function BlogPost({ params }) {
  const { slug } = await params;
  return (
    <div>
      <h1>{slug}</h1>
      <p>This is blog post: {slug}</p>
    </div>
  );
}
```

Ab browser mein `/blog/my-first-post` jao — "my-first-post" dikhega. `/blog/hello-world` jao — "hello-world" dikhega. **Ek page, alag-alag URLs handle kar raha hai.**

## Build-up — Blog Post with Dummy Data

Ab thoda real banaate hain. Dummy data hai, aur slug se post dhundhte hain:

```tsx
// app/blog/[slug]/page.tsx
const posts = [
  { slug: "my-first-post", title: "My First Post", content: "This is my first blog post." },
  { slug: "second-post", title: "Second Post", content: "Here is the second one." },
  { slug: "hello-world", title: "Hello World", content: "Classic first post." },
];

export default async function BlogPost({ params }) {
  const { slug } = await params;
  const post = posts.find(p => p.slug === slug);

  if (!post) {
    return <h1>Post not found</h1>;
  }

  return (
    <div>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </div>
  );
}
```

Notice kiya? **Ek hi page hai jo teeno URLs handle kar raha hai.** `/blog/my-first-post` ho, `/blog/second-post` ho — same component, alag data. React Router mein bhi yahi karte the, par config alag thi.

## `params` Ka Type — TypeScript Mein

TypeScript use kar rahe ho toh `params` ka type define karo:

```tsx
// app/blog/[slug]/page.tsx
interface PageProps {
  params: Promise<{ slug: string }>;
}

export default async function BlogPost({ params }: PageProps) {
  const { slug } = await params;
  return <h1>{slug}</h1>;
}
```

React Router mein `useParams<{ slug: string }>()` generic use karte the. Yahan `params` ka type direct props mein hota hai.

## Multiple Dynamic Segments

Ek se zyada dynamic segments ho sakte hain:

```
app/
└── blog/
    └── [slug]/
        └── comments/
            └── [commentId]/
                └── page.tsx    →  /blog/:slug/comments/:commentId
```

```tsx
// app/blog/[slug]/comments/[commentId]/page.tsx
export default async function Comment({ params }) {
  const { slug, commentId } = await params;
  return <p>Comment {commentId} on post {slug}</p>;
}
```

## What It Is NOT

⚠️ **Dynamic route = sirf `params` se data fetch nahi.** Server Components mein direct `await fetch()` bhi kar sakte ho — abhi dummy data hai, aage real API se fetch karenge.

⚠️ **`[slug]` sirf text nahi — number bhi ho sakta hai.** `[id]` folder banao, `params.id` string aayegi, `Number(id)` se convert karo.

⚠️ **Static aur dynamic routes ek saath kaam karte hain.** `/blog` static hai, `/blog/[slug]` dynamic hai — dono alag pages hain, conflict nahi.

---

Dynamic routes samajh aa gaye. Ab ek aur problem hai — agar data load ho raha hai toh user ko kuch dikhna chahiye, error aaye toh handle hona chahiye. Agla concept: **Loading, Error, Not-Found States.**
