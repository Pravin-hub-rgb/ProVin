## Step 1 — Blog Data: `lib/posts.ts`

Pehle data file banate hain — blog posts ka dummy data. Ye dono jagah use hoga: `/blog` list mein aur `/blog/[slug]` single post mein. Isliye isse ek shared file mein rakhte hain (React course mein bhi shared data alag file mein rakhte the — yaad hai?).

```ts

export type Post = {
  slug: string;
  title: string;
  date: string;
  excerpt: string;
  content: string;
};

const posts: Post[] = [
  {
    slug: "pehla-post",
    title: "Mera Pehla Blog Post",
    date: "7 Aug 2026",
    excerpt: "Next.js routing seekhne ka pehla din.",
    content: "Yeh mera pehla blog post hai. Maine file-based routing se yeh page banaya hai.",
  },
  {
    slug: "dynamic-routes",
    title: "Dynamic Routes — [slug] Folder",
    date: "8 Aug 2026",
    excerpt: "Ek page, anek URLs.",
    content: "Is post mein maine seekha ki [slug] folder se ek hi page multiple URLs handle karta hai.",
  },
  {
    slug: "loading-error-404",
    title: "Loading, Error aur 404",
    date: "9 Aug 2026",
    excerpt: "Teen files jo UX ko smooth banati hain.",
    content: "loading.tsx, error.tsx aur not-found.tsx — in teeno files ka experience is post mein hai.",
  },
];

export function getAllPosts(): Post[] {
  return posts;
}
```

## Step 8 — Single Post Page: `app/blog/[slug]/page.tsx`

Ab asli magic — dynamic route. Folder `[slug]` banao, URL se value automatically `params` mein aayegi (1.3 se yaad):

```tsx
// app/blog/[slug]/page.tsx
import { notFound } from "next/navigation";
import { getPostBySlug } from "@/lib/posts";

interface BlogPostProps {
  params: Promise<{ slug: string }>;
}

export default async function BlogPost({ params }: BlogPostProps) {
  const { slug } = await params;          // URL se value
  const post = getPostBySlug(slug);

  if (!post) {
    notFound();                           // slug nahi mila → 404
  }

  return (
    <main>
      <h1>{post.title}</h1>
      <p>{post.date}</p>
      <p>{post.content}</p>
    </main>
  );
}
```

**Teen important cheezein:**
1. `params` ek Promise hai (Next.js 15+) — isliye `await` lagaya.
2. `getPostBySlug(slug)` se post dhundha. Agar `undefined` aaya (`!post`), toh `notFound()` call kiya — ye automatically `not-found.tsx` render karega (1.4 se yaad).
3. `params` ka type `Promise<{ slug: string }>` define kiya — TypeScript clean.

## Step 9 — Loading State: `app/blog/[slug]/loading.tsx`

Ab jab post page load ho, pehle loading dikhna chahiye. `loading.tsx` daal do — Next.js automatically use karega (1.4 se yaad):

```tsx
// app/blog/[slug]/loading.tsx
export default function Loading() {
  return <p>Post load ho raha hai...</p>;
}
```

Isse dekhne ke liye, page mein thodi artificial delay daal do (real app mein DB/API se data aata hai — wahan naturally thoda time lagta hai). Test ke liye `page.tsx` mein ek line:

```tsx
export default async function BlogPost({ params }: BlogPostProps) {
  await new Promise((resolve) => setTimeout(resolve, 1000)); // demo delay
  const { slug } = await params;
  // ... baaki wahi
}
```

Ab `/blog/pehla-post` kholo — pehle "Post load ho raha hai..." dikhega, phir actual post. User ko blank screen nahi dikhti — loading state turant aati hai.

## Step 10 — Error State: `app/blog/[slug]/error.tsx`

Agar post ke data mein error aaye (network fail, server down), toh gracefully handle hona chahiye. `error.tsx` — **important: isme `"use client"` zaroori hai** (error handling client-side hoti hai, 1.4 se yaad):

```tsx
// app/blog/[slug]/error.tsx
"use client";

export default function Error({
  error,
  reset,
}: {
  error: Error;
  reset: () => void;
}) {
  return (
    <div>
      <h2>Kuch galat ho gaya!</h2>
      <p>{error.message}</p>
      <button onClick={reset}>Dobara Try Karo</button>
    </div>
  );
}
```

`reset()` function Next.js deta hai — click pe page dobara try karta hai. Test ke liye page mein `throw new Error("Test error")` daal ke dekh sakte ho (baad mein hata dena!).

## Step 11 — Custom 404: `app/not-found.tsx`

Global 404 page — koi bhi galat URL kholo, yeh dikhega:

```tsx
// app/not-found.tsx
export default function NotFound() {
  return (
    <main>
      <h1>404 — Page nahi mila</h1>
      <p>Kuch toh galat hua — yeh page exist nahi karta.</p>
    </main>
  );
}
```

Aur yaad rakho — sirf galat URL se nahi, `notFound()` function se bhi trigger hota hai (step 8 mein `if (!post) notFound()`). Jab `/blog/galat-slug` khologe, `getPostBySlug` `undefined` dega, `notFound()` chalega, aur yeh 404 dikhega.

## Common Mistakes

- ❌ `app/about/index.tsx` banana — galat. **`page.tsx` hi naam chalega** (1.1 se yaad).
- ❌ `params` mein `await` bhoolna — Next.js 15+ mein `params` Promise hai. `const { slug } = await params` hi sahi hai.
- ❌ Layout ke bahar Navbar alag-alag page mein daalna — **layout.tsx mein ek baar** likho, sab pe apply ho jata hai.
- ❌ `error.tsx` mein `"use client"` bhoolna — error handling client-side hoti hai, bina iske kaam nahi karega.
- ❌ `notFound()` ko return karna — `notFound()` khud route ko render karta hai, uske aage `return` ki zaroorat nahi (bas call karo).
- ❌ Sab data ek hi page mein daalna — shared data (`lib/posts.ts`) alag file mein rakhna, taaki list aur single post dono use kar sakein.

⚠️ **Yeh sirf "code copy-paste" exercise nahi.** Har file ke peeche ek concept hai (1.1–1.4). Agar koi file bina samjhe copy ki, toh aage kaam nahi chalega. Har file ka naam `page.tsx` kyun, `[slug]` kya karta hai — yeh samajhna zaroori hai.

⚠️ **Data abhi dummy hai — real DB nahi.** Batch 2 se real data fetching aayegi (Server Components mein `await fetch()`). Abhi `lib/posts.ts` ka static array hi kaafi hai.

⚠️ **Blog section "already build kar chuke" ka matlab skip nahi.** 1.3/1.4 mein blog ka hissa alag-alag seekha tha — yahan usi ko portfolio ke saath jod rahe ho. Integration hi asli skill hai.
