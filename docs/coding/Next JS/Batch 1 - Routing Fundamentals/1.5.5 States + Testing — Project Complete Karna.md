## Teen States — Kya, Kab, Kahan

1.4 se yaad karo — teen files:

| File | Kab dikhta hai | Kahan |
|---|---|---|
| `loading.tsx` | Jab page data load ho raha ho | `app/blog/[slug]/loading.tsx` |
| `error.tsx` | Jab page mein error throw ho | `app/blog/[slug]/error.tsx` |

**Kyun blog section mein, sab jagah nahi?** Home/About/Projects/Contact static pages hain — koi async data load nahi, koi error nahi. Sirf blog posts mein data flow hai (fetch/lookup). Isliye states blog ke liye. **Har cheez ko zaroorat ke hisaab se lagao — over-engineer mat karo.**

## Step 1 — Loading State: `app/blog/[slug]/loading.tsx`

Single post page mein `getPostBySlug()` ko call karte hain. Abhi static array hai toh turant milta hai — loading dikhega hi nahi. Par real app mein data API/DB se aayega — time lagega. Tab loading chahiye:

```tsx
// app/blog/[slug]/loading.tsx
export default function Loading() {
  return <p>Post load ho raha hai...</p>;
}
```

**Ye loading kab dikhega?** Jab `page.tsx` (async function) suspend hota hai — data aane tak. 1.4 se yaad — Next.js automatically Suspense boundary banata hai. Tumne bas file daali, Next.js use karta hai.

**Test karne ke liye** — page mein artificial delay daalo (real app mein naturally delay hota hai). 1.5.3 ke `getPostBySlug` function mein:

```ts
// lib/posts.ts — test ke liye temporary delay
export async function getPostBySlug(slug: string): Promise<Post | undefined> {
  await new Promise((resolve) => setTimeout(resolve, 1000)); // 1 sec delay
  return posts.find((post) => post.slug === slug);
}
```

**⚠️ Dhyan —** yahan maine function ko `async` bana diya (Promise return). Iska matlab page mein bhi `await` lagana padega. Test karne ke baad delay hatao ya real app mein ye naturally hota hai. Abhi project mein ye test ke liye hai.

## Step 2 — Error State: `app/blog/[slug]/error.tsx`

Agar data fetch mein error aaye — API down, network fail — `error.tsx` handle karta hai. **Important: `"use client"` zaroori hai** (error handling client-side — 1.4 se yaad):

```tsx
// app/blog/[slug]/error.tsx
"use client";

export default function Error({
  error,
  reset,
}: {
  error: Error;
  reset: () => void;
}) {
  return (
    <div>
      <h2>Kuch galat ho gaya!</h2>
      <p>{error.message}</p>
      <button onClick={reset}>Dobara Try Karo</button>
    </div>
  );
}
```

**Test karne ke liye** — page mein temporarily throw daalo:

```tsx
// app/blog/[slug]/page.tsx — test ke liye (baad mein hatao!)
throw new Error("Test error");
```

`error` = kya fail hua, `reset` = dobara try karo (Next.js deta hai — 1.4 se yaad).

## Step 3 — Custom 404: `app/not-found.tsx`

`app/not-found.tsx` **global** hai — koi bhi galat URL pe dikhta hai:

```tsx
// app/not-found.tsx
export default function NotFound() {
  return (
    <main>
      <h1>404 — Page nahi mila</h1>
      <p>Kuch toh galat hua — yeh page exist nahi karta.</p>
    </main>
  );
}
```

**Ye do tarah se trigger hota hai:**
1. **URL hi galat** — `/kuch-bhi` kholo, Next.js khud match na ho toh yeh dikhata hai
2. **`notFound()` call** — 1.5.4 ke page mein `if (!post) notFound()` — jab slug se post nahi mili

`/blog/galat-slug` kholo → `getPostBySlug` `undefined` → `notFound()` → yeh 404 dikhega.

## Common Mistakes

- ❌ Nayi post add karke list aur single page dono mein add karna — data layer mein ek jagah (`lib/posts.ts`) add karo, dono auto ho jayenge (1.5.3 se yaad).
- ❌ `getPostBySlug` se `if (!post)` check bhoolna — `Post | undefined` return type compiler ko enforce karwata hai, warna compile error.
- ❌ `error.tsx` mein `"use client"` bhoolna — error handling client-side, bina directive ke build error.
- ❌ Artificial delay / test throw production mein chhodna — testing ke liye the, project mein nahi rehna chahiye.
- ❌ Har page pe loading/error daalna — sirf async data wale sections mein chahiye. Static pages ko zaroorat nahi.
- ❌ `notFound()` ko return karna — `notFound()` khud route render karta hai, `return` ki zaroorat nahi.
