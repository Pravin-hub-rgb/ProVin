1.5.3 mein data layer banai — `lib/posts.ts` mein `Post` type, `posts` array, aur `getAllPosts()` + `getPostBySlug()` functions. Ab ye data layer UI se jodni hai — **hardcoded arrays hata ke functions use karna.**

Ye step bahut important hai kyunki yahi "dynamic" ka matlab hai — page ka code data-specific nahi raha, wo bas "data do" bolta hai. Ab asli data source (ye static array, aage API) se aata hai. Ab jab nayi post add karni hai, sirf `lib/posts.ts` badla — pages ka code chhuta nahi.

---

## Step 1 — Blog List Dynamic: `app/blog/page.tsx`

1.5.2 mein list page mein hardcoded array tha. Ab hatao aur `getAllPosts()` import karo:

```tsx
// app/blog/page.tsx
import Link from "next/link";
import { getAllPosts } from "@/lib/posts";

export default function Blog() {
  const posts = getAllPosts();

  return (
    <main>
      <h1>Blog</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.slug}>
            <Link href={`/blog/${post.slug}`}>{post.title}</Link>
            <p>{post.excerpt}</p>
          </li>
        ))}
      </ul>
    </main>
  );
}
```

**Kya badla:**
1. `import { getAllPosts } from "@/lib/posts"` — `@/` project root hai (0.8 se yaad, import alias). `getAllPosts` named import hai.
2. Hardcoded `posts` array **hata diya** — ab `const posts = getAllPosts()` function se milta hai.
3. Render logic **bilkul same** — `posts.map(...)`, `key={post.slug}`, title, excerpt.

**Notice kya hua:** UI ka code ek line bhi nahi badla. Sirf data ka source badla (array → function). **Yehi to chahiye tha** — 1.5.3 mein abstraction ka fayda. UI aur data source alag — ek change karo, doosra nahi toota.

## Step 2 — Single Post Dynamic: `app/blog/[slug]/page.tsx`

1.5.2 mein single page mein bhi hardcoded array tha. Ab `getPostBySlug()` use karte hain:

```tsx
// app/blog/[slug]/page.tsx
import { notFound } from "next/navigation";
import { getPostBySlug } from "@/lib/posts";

interface BlogPostProps {
  params: Promise<{ slug: string }>;
}

export default async function BlogPost({ params }: BlogPostProps) {
  const { slug } = await params;          // URL se value (1.3 se yaad)
  const post = getPostBySlug(slug);       // data layer se post

  if (!post) {
    notFound();                           // post nahi mili → 404 (1.4 se yaad)
  }

  return (
    <main>
      <h1>{post.title}</h1>
      <p>{post.date}</p>
      <p>{post.content}</p>
    </main>
  );
}
```

**Kya badla:**
1. Hardcoded `posts` array **hata diya** — ab `getPostBySlug(slug)` se post aati hai.
2. `const post = getPostBySlug(slug)` — return type `Post | undefined` hai (1.5.3 se yaad), isliye `if (!post)` check karna **compiler enforce karta hai**.
3. Baaki logic same — `await params`, `notFound()`, render.

**Notice `params` ka type:** `interface BlogPostProps` banaya, `params: Promise<{ slug: string }>` — 1.3 se yaad, Next.js 15+ mein params Promise hai. TypeScript clean.

## Ab Kya Hone Laga — Data Flow Samjho

Ab poora data flow dekh lo — **data kahan se aaya aur page tak kaise pahuncha:**

```
lib/posts.ts (data) 
    ↓ getAllPosts()
app/blog/page.tsx (list)      →  UI: posts.map() render

lib/posts.ts (data)
    ↓ getPostBySlug("pehla-post")
app/blog/[slug]/page.tsx       →  UI: title, date, content render
```

- `getAllPosts()` ko koi argument nahi — saare posts de deta hai (list ke liye)
- `getPostBySlug(slug)` ko slug chahiye — ek specific post (single page ke liye)
- `slug` kahan se aaya? URL se — `params` se (1.3)

**Yehi data flow hai** — data layer → function → page → UI. Har layer apna kaam karti hai. Isi ko "separation of concerns" kehte hain.

## Ek Aur Fark — TypeScript Ki Madad

Ab data layer se ek aur fayda milta hai. `getAllPosts()` `Post[]` return karta hai — page ko `post.title`, `post.excerpt` typed milte hain. Galat property (jaise `post.contnet`) likha toh **compile-time error** — turant pata chalta hai, runtime pe nahi. `getPostBySlug` ke `Post | undefined` se `if (!post)` check compulsory hai.

**TypeScript isi ke liye hai** — jitna code typed, utna aasaan bug-free. Data layer pe type define kiya, baaki sab auto.

## Nutshell

Dynamic banana = hardcoded array hata ke data layer ke functions use karna. `getAllPosts()` list ke liye, `getPostBySlug()` single ke liye. UI ka code nahi badla — sirf data source. Data flow: data layer → function → page → UI. Nayi post add karni hai toh sirf `lib/posts.ts` badlo.

## What It Is NOT

⚠️ **Dynamic = "data real-time badalta hai" nahi.** Abhi data static array hai — `lib/posts.ts`. "Dynamic" ka matlab yahan ye hai ki **page ka code data-independent hai** — data source se alag. Real dynamic (API/DB) Batch 2+ mein aayega, pattern wahi.

⚠️ **`getAllPosts()` import = "state management" nahi.** Ye sirf data access function hai. Koi state, koi reactivity nahi — static data return. React state concepts yahan nahi hai.

⚠️ **Sirf blog dynamic hai, baaki nahi.** About/Projects/Contact mein koi shared data nahi tha — unhe data layer ki zaroorat nahi. Har page ko wahi layer chahiye jo uski zaroorat ho — over-engineer mat karo.

---

Ab pages data se dynamic ho gaye — list aur single post dono `lib/posts.ts` se. Ab bacha hua ek kaam: **user experience — loading, error, 404.** Jab data slow ho ya fail ho, kya dikhega? 1.5.5 mein in states ko add karke project test karenge. Chalo.
