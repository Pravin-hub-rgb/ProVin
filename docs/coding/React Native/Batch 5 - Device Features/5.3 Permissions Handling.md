# Doc 5.3 — Permissions Handling

## Cheat Sheet (Quick Recall)

- Permission flow: check status → request if undetermined → handle granted/denied.
- Statuses: `granted`, `denied`, `undetermined`.
- `requestXPermissionsAsync()` returns `{ status }`.
- Always provide fallback UI when denied.
- Some permissions require `app.json` config (camera, location, notifications).

## Main Content

### SOCH

Camera, location, notifications — sab permissions mangte hain. Har jagah alag pattern → messy. Ek unified permission flow chahiye: check → request → handle granted/denied → fallback UI. Pehle flow, phir fallback, phir settings redirect, phir app.json config.

### CONCEPT

**Permission flow:**

```tsx
import * as Location from "expo-location";

// 1. Check
const { status: existing } = await Location.getForegroundPermissionsAsync();

// 2. Request if undetermined
let finalStatus = existing;
if (existing === "undetermined") {
  const { status } = await Location.requestForegroundPermissionsAsync();
  finalStatus = status;
}

// 3. Handle
if (finalStatus !== "granted") {
  // denied → fallback UI
}
```

**Statuses:**

- `granted` — allowed.
- `denied` — user denied (can't request again on iOS; redirect to settings).
- `undetermined` — not asked yet.

**Fallback UI:**

```tsx
if (status !== "granted") {
  return (
    <View className="flex-1 items-center justify-center p-4">
      <Text className="text-center mb-4">Location permission needed for this feature.</Text>
      <Pressable onPress={openSettings} className="bg-blue-500 px-4 py-2 rounded">
        <Text className="text-white">Open Settings</Text>
      </Pressable>
    </View>
  );
}
```

**Redirect to settings:**

```tsx
import { Linking } from "react-native";
Linking.openSettings();
```

**app.json config (required for some permissions):**

```json
{
  "expo": {
    "plugins": [
      ["expo-camera", { "cameraPermission": "Allow app to use camera" }],
      ["expo-location", { "locationAlwaysAndWhenInUsePermission": "Allow location access" }]
    ]
  }
}
```

**Reusable hook pattern:**

```tsx
function usePermission(requestFn) {
  const [status, setStatus] = useState("undetermined");
  const request = async () => {
    const { status } = await requestFn();
    setStatus(status);
    return status;
  };
  return { status, request };
}
```

### CODE (gradual)

Stage 1 — Check status:

```tsx
const { status } = await Location.getForegroundPermissionsAsync();
console.log(status);
```

Stage 2 — Request if undetermined:

```tsx
if (status === "undetermined") {
  const { status: newStatus } = await Location.requestForegroundPermissionsAsync();
}
```

Stage 3 — Handle denied with fallback UI:

```tsx
if (status !== "granted") return <PermissionDeniedUI />;
```

Stage 4 — Redirect to settings:

```tsx
<Pressable onPress={() => Linking.openSettings()}>Open Settings</Pressable>
```

Stage 5 — app.json plugin config.

## Common Mistakes

- Permission request without check (re-prompt on iOS after deny — won't show again).
- Fallback UI missing → blank screen.
- `app.json` config missing → permission prompt nahi aayega (production build).
- Background permission ko foreground samajhna.

## What It Is NOT

- ❌ `denied` is **not** recoverable by re-requesting on iOS.
- ❌ Permissions are **not** automatic.
- ❌ `app.json` config is **not** optional for production builds.
