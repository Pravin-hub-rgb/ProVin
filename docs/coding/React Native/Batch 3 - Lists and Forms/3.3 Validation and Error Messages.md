# Doc 3.3 — Validation and Error Messages

## Cheat Sheet (Quick Recall)

- Validate on submit (RHF `handleSubmit`) + optionally on blur.
- Show errors inline below the field: `errors.field.message`.
- Disable the submit button while invalid (`formState.isValid`).
- Errors auto-clear when the value changes (depending on mode).
- UX: red border + message; focus the first error field.

## Main Content

### THINK

The form + keyboard are ready. But the validation UX is still basic. When to validate (on submit vs on blur vs on change)? How to show errors (inline, red border, focus)? Disable submit when invalid? These UX decisions make a form "good". First the strategy, then display, then disable submit, then focus the first error.

### CONCEPT

**Validation timing:**

- `mode: "onSubmit"` (default) — validate on submit. Less noisy.
- `mode: "onBlur"` — validate when the field loses focus. Good for long forms.
- `mode: "onChange"` — validate on every keystroke. Noisy, but instant feedback.
- `mode: "onTouched"` — first blur, then change. Balanced (recommended).

```tsx
useForm({ resolver: zodResolver(schema), mode: "onTouched" });
```

**Error display pattern:**

```tsx
<Controller ... />
{errors.amount && (
  <Text className="text-red-500 text-sm mt-1">{errors.amount.message}</Text>
)}
```

Red border on the input:

```tsx
<TextInput
  className={errors.amount ? "border-red-500" : "border-gray-300"}
  ...
/>
```

**Disable submit while invalid:**

```tsx
const { formState: { isValid, isSubmitting } } = useForm(...);

<Pressable
  onPress={handleSubmit(onSubmit)}
  disabled={!isValid || isSubmitting}
  className={!isValid ? "opacity-50" : "opacity-100"}
>
  <Text>{isSubmitting ? "Saving..." : "Add"}</Text>
</Pressable>
```

**Focus the first error:**

```tsx
const { setFocus } = useForm(...);

const onSubmit = async (data) => { ... };
// On error, RHF does not auto-focus; use setFocus in onError
handleSubmit(onSubmit, (errors) => {
  const firstError = Object.keys(errors)[0];
  setFocus(firstError as any);
})();
```

**Clear errors on fix:** RHF auto-clears when the value changes (in `onTouched`/`onChange` mode). In `onSubmit` mode, errors clear on the next submit.

### CODE (gradual)

Stage 1 — Basic error display (onSubmit):

```tsx
{errors.amount && <Text className="text-red-500">{errors.amount.message}</Text>}
```

Stage 2 — Red border:

```tsx
<TextInput className={errors.amount ? "border-red-500 border" : "border-gray-300 border"} />
```

Stage 3 — Mode onTouched:

```tsx
useForm({ resolver: zodResolver(schema), mode: "onTouched" });
```

Stage 4 — Disable submit:

```tsx
<Pressable disabled={!isValid} className={!isValid ? "opacity-50" : ""}>
```

Stage 5 — Focus first error:

```tsx
handleSubmit(onSubmit, (errs) => setFocus(Object.keys(errs)[0]));
```

## Common Mistakes

- Default `mode` (`onSubmit`) is not noisy — but the user may be confused.
- Rendering `errors.amount` (object) instead of `errors.amount.message` (string).
- Not disabling submit → invalid submit attempts.
- Not focusing the first error → the user scrolls around looking for it.

## Summary

- Validation timing: `mode` (onSubmit/onBlur/onChange/onTouched).
- Inline errors: red border + message below the field.
- Disable submit while `!isValid`.
- Focus the first error via `setFocus`.

## What It Is NOT

- ❌ `onSubmit` mode is **not** always best — `onTouched` is better UX.
- ❌ Errors are **not** auto-cleared in `onSubmit` mode until the next submit.
- ❌ Disabling submit is **not** enough — show why.
