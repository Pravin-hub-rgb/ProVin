# Doc 3.2 — Keyboard-friendly Screens

## Cheat Sheet (Quick Recall)

- `KeyboardAvoidingView` pushes content up when the keyboard opens.
- `behavior`: iOS `"padding"`, Android `"height"`.
- Dismiss on outside tap: `TouchableWithoutFeedback` + `Keyboard.dismiss()`.
- `keyboardShouldPersistTaps` on ScrollView/FlatList.
- `inputAccessoryView` for a toolbar above the keyboard (iOS).

## Main Content

### THINK

The form is built (3.1). But on a phone the keyboard opens and covers inputs — the user cannot see what they type. On the web there is `position: fixed`/scroll; in RN there is `KeyboardAvoidingView` + a dismiss pattern. First the problem (covered input), then the solution (avoiding view), then dismiss (outside tap), then ScrollView integration.

### CONCEPT

**The problem:**

The keyboard covers the bottom ~40% of the screen. If an input is at the bottom, it gets hidden behind the keyboard. The user cannot see what they type.

**Solution: KeyboardAvoidingView:**

```tsx
import { KeyboardAvoidingView, Platform, ScrollView } from "react-native";

<KeyboardAvoidingView
  behavior={Platform.OS === "ios" ? "padding" : "height"}
  style={{ flex: 1 }}
>
  <ScrollView keyboardShouldPersistTaps="handled">
    {/* inputs */}
  </ScrollView>
</KeyboardAvoidingView>
```

- `behavior="padding"` (iOS): adds padding, pushing content up.
- `behavior="height"` (Android): adjusts height.
- `keyboardShouldPersistTaps="handled"`: taps on the ScrollView do not dismiss the keyboard unless handled.

**Dismiss on outside tap:**

```tsx
import { TouchableWithoutFeedback, Keyboard } from "react-native";

<TouchableWithoutFeedback onPress={Keyboard.dismiss}>
  <View style={{ flex: 1 }}>
    {/* inputs */}
  </View>
</TouchableWithoutFeedback>
```

**inputAccessoryView (iOS toolbar):**

```tsx
import { InputAccessoryView, Button } from "react-native";

<InputAccessoryView nativeID="toolbar">
  <Button title="Done" onPress={Keyboard.dismiss} />
</InputAccessoryView>

<TextInput inputAccessoryViewID="toolbar" />
```

A "Done" button above the keyboard.

### CODE (gradual)

Stage 1 — Problem (no handling):

```tsx
<View style={{ flex: 1, justifyContent: "flex-end", padding: 16 }}>
  <TextInput placeholder="Amount" />
</View>
```

Keyboard opens → input is covered.

Stage 2 — KeyboardAvoidingView:

```tsx
<KeyboardAvoidingView behavior={Platform.OS === "ios" ? "padding" : "height"} style={{ flex: 1 }}>
  <View style={{ flex: 1, justifyContent: "flex-end", padding: 16 }}>
    <TextInput placeholder="Amount" />
  </View>
</KeyboardAvoidingView>
```

Stage 3 — Dismiss on outside tap:

```tsx
<TouchableWithoutFeedback onPress={Keyboard.dismiss}>
  <KeyboardAvoidingView ...>
    <View>...</View>
  </KeyboardAvoidingView>
</TouchableWithoutFeedback>
```

Stage 4 — ScrollView integration:

```tsx
<KeyboardAvoidingView ...>
  <ScrollView keyboardShouldPersistTaps="handled">
    {inputs}
  </ScrollView>
</KeyboardAvoidingView>
```

## Common Mistakes

- Wrong `behavior` (e.g., `"height"` on iOS) → layout breaks.
- Not giving `KeyboardAvoidingView` `flex: 1` → it will not work.
- Missing `keyboardShouldPersistTaps` → tap dismisses the keyboard (annoying).
- Input inside a ScrollView without an avoiding view → gets covered.

## What It Is NOT

- ❌ `KeyboardAvoidingView` is **not** automatic — the behavior must be set.
- ❌ It does **not** work without `flex: 1`.
- ❌ `keyboardShouldPersistTaps` is **not** the default — set it explicitly.
