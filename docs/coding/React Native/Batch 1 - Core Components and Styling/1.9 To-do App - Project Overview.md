### CONCEPT

**Goal:** A working to-do app on the phone:

- Add a task via `TextInput`.
- Show tasks in a `ScrollView`.
- Tap a task to toggle complete.
- Delete a task.
- Completed styling.

**Suggested structure:**

```
app/
└── index.tsx        # single screen to-do app
components/
├── TaskInput.tsx    # TextInput + Add button
├── TaskItem.tsx     # single row with toggle + delete
└── TaskList.tsx     # ScrollView of TaskItems
```

**Data model:**

```ts
type Task = {
  id: string;
  title: string;
  done: boolean;
};
```

Field reasons:

- `id` — unique handle for toggle/delete (also the list key).
- `title` — task text displayed in the row.
- `done` — checkbox state (completed styling).

**State:**

```tsx
const [tasks, setTasks] = useState<Task[]>([]);
const [input, setInput] = useState("");
```

- `addTask`: append a new task with `done: false`.
- `toggleTask`: flip `done` for the matching id.
- `deleteTask`: filter out the matching id.

**Operations (Batch 1 scope):**

1. Add: `TextInput` + `Pressable` (Add) → append task.
2. Toggle: tap task → flip `done` → completed styling.
3. Delete: delete button → remove task.

**Build steps (gradual):**

1. Create the project (`npx create-expo-app todo-app`).
2. Static skeleton: `View` + `TextInput` + `Pressable` (Add) + `ScrollView` (empty) — no state.
   - **Checkpoint:** the layout should show on the phone (input + button + empty area). Save → verify.
3. Add state: `tasks`, `input` with `useState`.
   - **Checkpoint:** console.log tasks/input — values should be correct.
4. Wire `TaskInput`: controlled `TextInput` + Add button `onPress` → `addTask`.
   - **Checkpoint:** type + Add → the new task should print in the console.
5. Wire `TaskList`: `ScrollView` + `tasks.map` → `TaskItem`.
   - **Checkpoint:** the added task should appear on the phone.
6. Wire `TaskItem`: toggle on tap (completed styling) + delete button.
   - **Checkpoint:** tap toggles styling; delete removes it.
7. Styling: `StyleSheet`, spacing, colors, safe area, completed styling (strikethrough/opacity).
   - **Checkpoint:** verify the final look on the phone.

### CODE (sample pieces)

Data model + state:

```tsx
type Task = { id: string; title: string; done: boolean };

const [tasks, setTasks] = useState<Task[]>([]);
const [input, setInput] = useState("");

const addTask = () => {
  if (!input.trim()) return;
  setTasks((prev) => [...prev, { id: Date.now().toString(), title: input.trim(), done: false }]);
  setInput("");
};

const toggleTask = (id: string) => {
  setTasks((prev) => prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t)));
};

const deleteTask = (id: string) => {
  setTasks((prev) => prev.filter((t) => t.id !== id));
};
```

Line by line:

- `type Task` — the data shape; reasons for each field above.
- `useState<Task[]>([])` — an empty task list.
- `addTask` — validation (trim), immutable append, clear input.
- `toggleTask` — immutable map, flip `done`.
- `deleteTask` — immutable filter.

## Common Mistakes

- Direct state mutation (`tasks.push(...)`) — React will not re-render. Use immutable updates.
- Missing `key` prop in `.map` — warning + bugs.
- Deleting by title instead of id — multiple tasks with the same title would all be deleted.
- Expecting persistence — that comes in Batch 4 (AsyncStorage); for now data is lost when the app closes.
