### CONCEPT

**Goal:** Working to-do app on phone:

- Add task via `TextInput`.
- Show tasks in `ScrollView`.
- Tap task to toggle complete.
- Delete task.
- Completed styling.

**Suggested structure:**

```
app/
└── index.tsx        # single screen to-do app
components/
├── TaskInput.tsx    # TextInput + Add button
├── TaskItem.tsx     # single row with toggle + delete
└── TaskList.tsx     # ScrollView of TaskItems
```

**Data model:**

```ts
type Task = {
  id: string;
  title: string;
  done: boolean;
};
```

Field reasons:

- `id` — unique handle for toggle/delete (list key bhi).
- `title` — task text displayed in row.
- `done` — checkbox state (completed styling).

**State:**

```tsx
const [tasks, setTasks] = useState<Task[]>([]);
const [input, setInput] = useState("");
```

- `addTask`: append new task `{ id, title: input, done: false }`.
- `toggleTask`: flip `done` for matching id (immutable update).
- `deleteTask`: filter out matching id.

**Operations (Batch 1 scope):**

1. Add: `TextInput` + `Pressable` (Add) → append task.
2. Toggle: tap task → flip `done` → completed styling.
3. Delete: delete button → remove task.

**Build steps (gradual):**

1. Create project (`npx create-expo-app todo-app`).
2. Static skeleton: `View` + `TextInput` + `Pressable` (Add) + `ScrollView` (empty) — no state.
   - **Checkpoint:** phone pe layout dikhna chahiye (input + button + empty area). Save → verify.
3. Add state: `tasks`, `input` with `useState`.
   - **Checkpoint:** console.log tasks/input — values sahi.
4. Wire `TaskInput`: controlled `TextInput` + Add button `onPress` → `addTask`.
   - **Checkpoint:** type + Add → console mein new task print.
5. Wire `TaskList`: `ScrollView` + `tasks.map` → `TaskItem`.
   - **Checkpoint:** added task phone pe dikhna chahiye.
6. Wire `TaskItem`: toggle on tap (completed styling) + delete button.
   - **Checkpoint:** tap toggle → styling change; delete → removed.
7. Styling: `StyleSheet`, spacing, colors, safe area, completed styling (strikethrough/opacity).
   - **Checkpoint:** final look verify on phone.

### CODE (sample pieces)

Data model + state:

```tsx
type Task = { id: string; title: string; done: boolean };

const [tasks, setTasks] = useState<Task[]>([]);
const [input, setInput] = useState("");

const addTask = () => {
  if (!input.trim()) return;
  setTasks((prev) => [...prev, { id: Date.now().toString(), title: input.trim(), done: false }]);
  setInput("");
};

const toggleTask = (id: string) => {
  setTasks((prev) => prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t)));
};

const deleteTask = (id: string) => {
  setTasks((prev) => prev.filter((t) => t.id !== id));
};
```

Line-by-line:

- `type Task` — data shape; har field ka reason above.
- `useState<Task[]>([])` — empty task list.
- `addTask` — validation (trim), immutable append, input clear.
- `toggleTask` — immutable map, flip `done`.
- `deleteTask` — immutable filter.

## Common Mistakes

- Direct state mutation (`tasks.push(...)`) — React re-render nahi hoga. Immutable updates use karo.
- `key` prop missing in `.map` — warning + bugs.
- Delete by title instead of id — same title ke multiple tasks delete ho jayenge.
- Persistence expect karna — Batch 4 (AsyncStorage) mein aayega; abhi app close pe data lost.
