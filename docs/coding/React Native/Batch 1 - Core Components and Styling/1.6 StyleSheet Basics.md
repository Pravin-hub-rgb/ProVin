# Doc 1.6 — StyleSheet Basics

## Cheat Sheet (Quick Recall)

- `StyleSheet.create({...})` defines styles as JS objects with camelCase keys.
- Use `style={styles.x}` or an array `style={[styles.a, styles.b, { color: "red" }]}`.
- `StyleSheet.create` validates keys, registers once (performance), keeps JSX clean.
- Platform-specific: `Platform.select({ ios: {...}, android: {...} })`.
- No CSS selectors/cascading/global stylesheet.

## Main Content

### THINK

Flexbox is understood — layout can be arranged. But styling (colors, fonts, padding) is still done with inline objects, which is messy. On the web there are CSS files; in RN there is `StyleSheet`. First basic usage, then the benefit of `StyleSheet.create`, then combining styles, then platform-specific.

### CONCEPT

**Basic usage:**

```tsx
import { StyleSheet, Text, View } from "react-native";

export default function App() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Hello</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: "#fff",
    alignItems: "center",
    justifyContent: "center",
  },
  title: {
    fontSize: 24,
    fontWeight: "bold",
    color: "#333",
  },
});
```

**Why `StyleSheet.create`?**

- **Validation:** invalid style keys are caught at dev time.
- **Performance:** styles are registered once and referenced by ID.
- **Readability:** JSX stays clean.

Inline objects (`style={{ color: "red" }}`) are also possible, but `StyleSheet.create` is preferred for reusable styles.

**Combining styles:**

```tsx
<Text style={[styles.base, styles.bold, { color: "red" }]}>
  Combined
</Text>
```

Later styles override earlier ones for the same property.

**Platform-specific styles:**

```tsx
import { Platform } from "react-native";

const styles = StyleSheet.create({
  shadow: {
    ...Platform.select({
      ios: { shadowColor: "#000", shadowOpacity: 0.2, shadowRadius: 4 },
      android: { elevation: 4 },
    }),
  },
});
```

### CODE (gradual)

Stage 1 — Inline style (messy):

```tsx
<View style={{ flex: 1, backgroundColor: "#fff", padding: 16 }}>
  <Text style={{ fontSize: 24, color: "#333" }}>Hello</Text>
</View>
```

Save and check — it works but is messy.

Stage 2 — `StyleSheet.create`:

```tsx
const styles = StyleSheet.create({
  container: { flex: 1, backgroundColor: "#fff", padding: 16 },
  title: { fontSize: 24, color: "#333" },
});

<View style={styles.container}>
  <Text style={styles.title}>Hello</Text>
</View>
```

Stage 3 — Combining:

```tsx
<Text style={[styles.title, styles.bold, { color: "red" }]}>Hello</Text>
```

Stage 4 — Platform-specific shadow:

```tsx
const styles = StyleSheet.create({
  card: {
    padding: 16,
    ...Platform.select({
      ios: { shadowColor: "#000", shadowOpacity: 0.2, shadowRadius: 4 },
      android: { elevation: 4 },
    }),
  },
});
```

## Common Mistakes

- Inline objects everywhere — messy, no validation.
- Writing style keys in kebab-case — RN needs camelCase (`backgroundColor`).
- Expecting CSS selectors — not in RN.
- Expecting a global stylesheet — styles are per-component.

## Try It Yourself

## Summary

- `StyleSheet.create` = styles as JS objects, camelCase keys.
- Combine via array; later overrides earlier.
- `Platform.select` for platform-specific styles.
- No selectors, cascading, or global styles.

## What It Is NOT

- ❌ `StyleSheet` is **not** CSS — no selectors/cascading.
- ❌ Styles are **not** strings — JS objects, camelCase.
- ❌ No global stylesheet — per-component (or shared via imports).
