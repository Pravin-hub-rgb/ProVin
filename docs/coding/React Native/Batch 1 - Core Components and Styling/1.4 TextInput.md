# Doc 1.4 — TextInput

## Cheat Sheet (Quick Recall)

- `TextInput` = text entry; controlled via `value` + `onChangeText` (gives a string).
- Props: `placeholder`, `secureTextEntry`, `keyboardType`, `autoCapitalize`, `autoCorrect`, `multiline`, `maxLength`, `editable`.
- Keyboard handling: `KeyboardAvoidingView` + `Keyboard.dismiss()` on outside tap.
- `onChangeText` gives a string, not an event (unlike web `onChange`).

## Main Content

### THINK

The to-do app needs to add tasks — the user types, presses "Add", and the task appears in the list. Text entry uses `TextInput`. It is like the web's `<input>`, but native. First a basic controlled input, then props (keyboard type, secure entry), then keyboard handling (avoid covering).

### CONCEPT

**Basic usage (controlled):**

```tsx
import { TextInput, View, Text } from "react-native";
import { useState } from "react";

export default function App() {
  const [text, setText] = useState("");

  return (
    <View style={{ padding: 16 }}>
      <TextInput
        value={text}
        onChangeText={setText}
        placeholder="Type here"
        style={{ borderWidth: 1, borderColor: "#ccc", padding: 12, borderRadius: 8 }}
      />
      <Text>{text}</Text>
    </View>
  );
}
```

- `value` + `onChangeText` = controlled (recommended). You own the state.
- Uncontrolled: use `defaultValue` and read via a ref (less common).

**Common props:**

- `placeholder` / `placeholderTextColor`
- `secureTextEntry` — for passwords.
- `keyboardType` — `"default"`, `"numeric"`, `"email-address"`, `"phone-pad"`.
- `autoCapitalize` — `"none"`, `"sentences"`, `"words"`, `"characters"`.
- `autoCorrect` — boolean.
- `multiline` — textarea-like.
- `maxLength` — limit characters.
- `editable` — disable input.

```tsx
<TextInput
  placeholder="Email"
  keyboardType="email-address"
  autoCapitalize="none"
  autoCorrect={false}
/>
```

**Keyboard handling:**

The keyboard covers the bottom of the screen. `KeyboardAvoidingView` pushes content up. Dismiss the keyboard on tap outside: wrap in `TouchableWithoutFeedback` + `Keyboard.dismiss()`.

```tsx
import { KeyboardAvoidingView, Platform, TouchableWithoutFeedback, Keyboard } from "react-native";

<KeyboardAvoidingView behavior={Platform.OS === "ios" ? "padding" : "height"} style={{ flex: 1 }}>
  <TouchableWithoutFeedback onPress={Keyboard.dismiss}>
    <View>{/* inputs */}</View>
  </TouchableWithoutFeedback>
</KeyboardAvoidingView>
```

## Common Mistakes

- Expecting `onChangeText` to receive an event — it gives the string.
- Using `onChange` (web) — RN uses `onChangeText`.
- Ignoring keyboard handling — inputs get covered.
- Expecting `multiline` to auto-grow — handle height manually.

## What It Is NOT

- ❌ `TextInput` is **not** an HTML input — many CSS props do not apply.
- ❌ `onChangeText` is **not** `onChange` — it gives a string.
- ❌ `multiline` does **not** auto-grow without height handling.
