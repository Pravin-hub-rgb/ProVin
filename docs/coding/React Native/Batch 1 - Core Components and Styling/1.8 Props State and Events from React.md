# Doc 1.8 — Props, State, and Events from React

## Cheat Sheet (Quick Recall)

- Props/state/hooks carry over unchanged: `useState`, `useReducer`, `useRef`, Context, Redux, TanStack Query.
- Events differ: `onPress` (not `onClick`), `onChangeText` gives a string (not an event).
- `onChangeText` receives the typed string directly; no `e.target.value`.
- Keyboard: `KeyboardAvoidingView` (no `position: fixed`).

## Main Content

### THINK

Styling is clear. The to-do app now needs data flow: props (pass data to a component), state (store tasks), events (add/toggle/delete). The good news: all of this is the same as React. But event naming and shape differ (RN is native). First confirm the carry-over (props/state), then the RN differences (events).

### CONCEPT

**Props (same as React):**

```tsx
type GreetingProps = { name: string; color?: string };

function Greeting({ name, color = "#333" }: GreetingProps) {
  return <Text style={{ color }}>{`Hello, ${name}`}</Text>;
}

<Greeting name="Vin" />
```

- TypeScript interfaces are the same.
- Destructuring, defaults, children are the same.

**State (same as React):**

```tsx
const [count, setCount] = useState(0);
```

- `useState`, `useReducer`, `useRef` work unchanged.
- State updates trigger re-render, same as on the web.

**Events (RN differences):**

| Web | React Native |
|-----|--------------|
| `onClick` | `onPress` (Pressable) |
| `onChange` (input) | `onChangeText` (TextInput) — gives a string |
| `onSubmit` | `onSubmitEditing` (TextInput) |

```tsx
<Pressable onPress={() => setCount((c) => c + 1)}>
  <Text>Count: {count}</Text>
</Pressable>

<TextInput
  value={text}
  onChangeText={setText}
  onSubmitEditing={() => console.log("submitted", text)}
/>
```

**What is different:**

- No DOM events (no `onClick`, `onMouseEnter`).
- Touch events: `onPress`, `onLongPress`, `onPressIn/Out`.
- `onChangeText` gives the string, not an event.
- `KeyboardAvoidingView` for keyboard handling (no `position: fixed`).

### CODE (gradual)

Stage 1 — Props (static):

```tsx
function Greeting({ name }: { name: string }) {
  return <Text>Hello, {name}</Text>;
}
<Greeting name="Vin" />
```

Stage 2 — State (counter):

```tsx
const [count, setCount] = useState(0);
<Pressable onPress={() => setCount((c) => c + 1)}>
  <Text>Count: {count}</Text>
</Pressable>
```

Stage 3 — Event difference (onChangeText):

```tsx
const [text, setText] = useState("");
<TextInput value={text} onChangeText={setText} />
<Text>{text}</Text>
```

Stage 4 — Combined (props + state + event):

```tsx
type TaskProps = { title: string; onToggle: () => void };
function TaskItem({ title, onToggle }: TaskProps) {
  return (
    <Pressable onPress={onToggle}>
      <Text>{title}</Text>
    </Pressable>
  );
}
```

## Common Mistakes

- Writing `onClick` — RN uses `onPress`.
- Expecting an event from `onChangeText` — it gives a string.
- Using `e.target.value` — not available in RN.
- Expecting DOM events — they do not exist.
