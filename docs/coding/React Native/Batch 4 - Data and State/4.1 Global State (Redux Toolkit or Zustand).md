# Doc 4.1 — Global State (Redux Toolkit or Zustand)

## Cheat Sheet (Quick Recall)

- Zustand: `create((set) => ({ ... }))` — minimal, no boilerplate, hooks-based.
- Redux Toolkit: `createSlice` + `configureStore` + `Provider` — enterprise standard.
- Use Zustand for simple/global client state; RTK for complex/enterprise.
- Both work in RN the same as on the web.
- TanStack Query for server state; Zustand/RTK for client state.

## Main Content

### THINK

TanStack Query handles server state (movies). But client state (favorites, theme, user prefs) needs to be global — multiple screens access it. React Context (2.3) works but re-renders the entire tree on high-frequency updates. Zustand/Redux Toolkit are better. First compare (Zustand minimal vs RTK enterprise), then choose, then implement.

### CONCEPT

**Zustand (minimal):**

```tsx
import { create } from "zustand";

type FavState = { favorites: string[]; add: (id: string) => void; remove: (id: string) => void };

export const useFavStore = create<FavState>((set) => ({
  favorites: [],
  add: (id) => set((s) => ({ favorites: [...s.favorites, id] })),
  remove: (id) => set((s) => ({ favorites: s.favorites.filter((f) => f !== id) })),
}));
```

- No Provider needed.
- Hook-based: `const { favorites, add } = useFavStore();`.
- Minimal boilerplate.

**Redux Toolkit (enterprise):**

```tsx
import { createSlice, configureStore } from "@reduxjs/toolkit";
import { Provider, useSelector, useDispatch } from "react-redux";

const favSlice = createSlice({
  name: "favorites",
  initialState: { ids: [] as string[] },
  reducers: {
    add: (state, action) => { state.ids.push(action.payload); },
    remove: (state, action) => { state.ids = state.ids.filter((id) => id !== action.payload); },
  },
});

export const store = configureStore({ reducer: { favorites: favSlice.reducer } });

// In a component:
const ids = useSelector((s) => s.favorites.ids);
const dispatch = useDispatch();
dispatch(favSlice.actions.add(movieId));
```

- `Provider` wraps the app.
- More boilerplate but devtools, middleware, enterprise patterns.

**When to use which:**

| Need | Pick |
|------|------|
| Simple global state, few slices | Zustand |
| Complex state, middleware, devtools, enterprise | RTK |
| Server state | TanStack Query (not these) |

### CODE (gradual)

Stage 1 — Context (problem: high-frequency re-render):

```tsx
const FavContext = createContext(...);
// every update re-renders all consumers
```

Stage 2 — Zustand (solution, minimal):

```tsx
export const useFavStore = create((set) => ({
  favorites: [],
  add: (id) => set((s) => ({ favorites: [...s.favorites, id] })),
}));
```

Stage 3 — Use in a component:

```tsx
const { favorites, add } = useFavStore();
const isFav = favorites.includes(movieId);
```

Stage 4 — RTK (enterprise alternative):

```tsx
const favSlice = createSlice({ name: "favorites", initialState: { ids: [] }, reducers: { add: (s, a) => { s.ids.push(a.payload); } } });
export const store = configureStore({ reducer: { favorites: favSlice.reducer } });
```

Stage 5 — Provider + hooks:

```tsx
<Provider store={store}><Stack /></Provider>
const ids = useSelector((s) => s.favorites.ids);
```

## Common Mistakes

- Storing server state in Zustand/RTK (use TanStack Query).
- Adding a Provider with Zustand (not needed).
- Mutating state directly in RTK outside a slice (use dispatch).
- Using Context for high-frequency updates (use Zustand/RTK).

- Zustand: minimal, no Provider, hook-based.
- RTK: enterprise, slices, Provider, devtools.
- Server state → TanStack Query; client state → Zustand/RTK.
