## Main Content

### THINK

The app is shipped. But bugs? Manual testing can miss them. Automated tests are needed. Jest (test runner) + RNTL (component testing). First setup, then unit tests (pure functions), then component tests, then mocking.

### CONCEPT

**Setup:**

```bash
npx expo install jest-expo @testing-library/react-native
```

`package.json`:

```json
"scripts": {
  "test": "jest"
}
```

`jest.config.js`:

```js
module.exports = {
  preset: "jest-expo",
  transformIgnorePatterns: [
    "node_modules/(?!((jest-)?react-native|@react-native(-community)?)|expo(nent)?|@expo(nent)?/.*|@expo-google-fonts/.*|react-navigation|@react-navigation/.*|@unimodules/.*|unimodules|sentry-expo|native-base|react-native-svg)",
  ],
};
```

**Unit test (pure function):**

```tsx
// utils/streak.ts
export function calculateStreak(completedDates: string[]): number {
  // ... logic
  return streak;
}

// __tests__/streak.test.ts
import { calculateStreak } from "../utils/streak";

test("calculates streak for consecutive days", () => {
  const dates = ["2026-11-20", "2026-11-21", "2026-11-22"];
  expect(calculateStreak(dates)).toBe(3);
});
```

**Component test (RNTL):**

```tsx
import { render, screen, fireEvent } from "@testing-library/react-native";
import HabitItem from "../components/HabitItem";

test("renders habit name", () => {
  render(<HabitItem habit={{ id: "1", name: "Read", streak: 5, completedDates: [] }} onToggle={() => {}} />);
  expect(screen.getByText("Read")).toBeTruthy();
});

test("calls onToggle on press", () => {
  const onToggle = jest.fn();
  render(<HabitItem habit={{ id: "1", name: "Read", streak: 5, completedDates: [] }} onToggle={onToggle} />);
  fireEvent.press(screen.getByText("Read"));
  expect(onToggle).toHaveBeenCalledWith("1");
});
```

**Mock native modules:**

```tsx
jest.mock("@react-native-async-storage/async-storage", () =>
  require("@react-native-async-storage/async-storage/jest/async-storage-mock")
);
```

## Common Mistakes

- Not mocking native modules → test crashes.
- Wrong `transformIgnorePatterns` → module parse error.
- Testing implementation instead of behavior.
- Async tests without `await`/`findBy`.

4. Why mock AsyncStorage in tests?

<details>
<summary>Sample Answer</summary>

**Answer:** Native modules do not run in Jest (Node); the mock provides an in-memory implementation.

</details>

5. What does `transformIgnorePatterns` do?

<details>
<summary>Sample Answer</summary>

**Answer:** Tells Jest which node_modules to transform (RN/Expo packages need Babel).

</details>

## What It Is NOT

- ❌ Jest is **not** an E2E tool (use Detox/Maestro).
- ❌ RNTL is **not** testing implementation details.
- ❌ Mocks are **not** optional for native modules.
