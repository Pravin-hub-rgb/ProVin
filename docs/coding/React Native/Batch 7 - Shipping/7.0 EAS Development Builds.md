# Doc 7.0 — EAS Development Builds

## Cheat Sheet (Quick Recall)

- EAS = Expo Application Services (cloud builds).
- Dev build: `eas build --profile development` → install on phone → run `npx expo start`.
- Profiles in `eas.json`: development, preview, production.
- Dev build contains your native code; works with any module.
- Replaces Expo Go when custom native modules needed.

### CONCEPT

**EAS setup:**

```bash
npm install -g eas-cli
eas login
eas build:configure
```

Creates `eas.json`.

**eas.json profiles:**

```json
{
  "cli": { "version": ">= 5.0.0" },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal"
    },
    "production": {}
  }
}
```

- `development`: dev client (reload JS), internal distribution.
- `preview`: internal testing (no dev client).
- `production`: store submission.

**Build dev client:**

```bash
eas build --profile development --platform android
# or ios
```

Cloud build → download `.apk`/`.ipa` → install on phone.

**Run with dev build:**

```bash
npx expo start --dev-client
```

Scan QR with dev build (not Expo Go) → app loads.

**Install on phone:**

- Android: download APK, install (enable unknown sources).
- iOS: TestFlight or direct install (needs Apple dev account).

### TEST

1. Dev build kya hai? (your own binary with dev client)
2. `eas build --profile development` ka purpose? (build dev client)

**Checkpoint:** Dev build install kar, `--dev-client` start kar, QR scan → app loads in dev build.

## Common Mistakes

- Expo Go se QR scan karna (dev build chahiye).
- `eas build:configure` skip karna → no `eas.json`.
- Platform specify na karna → both build (slow).
- iOS dev account missing → build fail.

## What It Is NOT

- ❌ Dev build is **not** production build.
- ❌ Expo Go is **not** a substitute for dev build testing.
- ❌ EAS is **not** local build — cloud.
