# Doc 7.0 — EAS Development Builds

## Cheat Sheet (Quick Recall)

- EAS = Expo Application Services (cloud builds).
- Dev build: `eas build --profile development` → install on phone → run `npx expo start`.
- Profiles in `eas.json`: development, preview, production.
- Dev build contains your native code; works with any module.
- Replaces Expo Go when custom native modules are needed.

## Main Content

### THINK

The app is polished. Now a real app is needed on the phone (not Expo Go) — a dev build. Expo Go's limits are exceeded (custom native modules). EAS builds in the cloud. First EAS setup, then dev build profile, then build + install, then run.

### CONCEPT

**EAS setup:**

```bash
npm install -g eas-cli
eas login
eas build:configure
```

Creates `eas.json`.

**`eas.json` profiles:**

```json
{
  "cli": { "version": ">= 5.0.0" },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal"
    },
    "production": {}
  }
}
```

- `development`: dev client (reload JS), internal distribution.
- `preview`: internal testing (no dev client).
- `production`: store submission.

**Build dev client:**

```bash
eas build --profile development --platform android
# or ios
```

Cloud build → download `.apk`/`.ipa` → install on phone.

**Run with dev build:**

```bash
npx expo start --dev-client
```

Scan the QR with the dev build (not Expo Go) → app loads.

**Install on phone:**

- Android: download APK, install (enable unknown sources).
- iOS: TestFlight or direct install (needs Apple dev account).

## Common Mistakes

- Scanning the QR with Expo Go (the dev build is needed).
- Skipping `eas build:configure` → no `eas.json`.
- Not specifying platform → builds both (slow).
- Missing iOS dev account → build fails.

## What It Is NOT

- ❌ A dev build is **not** a production build.
- ❌ Expo Go is **not** a substitute for dev build testing.
- ❌ EAS is **not** a local build — it is cloud.
