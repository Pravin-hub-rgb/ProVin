# Doc 7.3 — Environment Configuration

## Cheat Sheet (Quick Recall)

- `.env` files with `EXPO_PUBLIC_` prefix for client-exposed vars.
- Access: `process.env.EXPO_PUBLIC_API_KEY`.
- EAS: env vars in `eas.json` or EAS secrets (`eas secret:create`).
- Never commit secrets; use `.env.local` + `.gitignore`.
- Different envs: development, preview, production profiles.

## Main Content

### SOCH

App mein API keys (TMDB), endpoints (dev/prod) hain. Hardcode karna bad practice (security, env switching). Env vars use karo. Expo mein `EXPO_PUBLIC_` prefix client-exposed. EAS secrets for sensitive. Pehle `.env` (dev), phir EAS secrets (prod), phir profiles.

### CONCEPT

**Local .env:**

```bash
# .env
EXPO_PUBLIC_API_URL=https://api.example.com
EXPO_PUBLIC_API_KEY=dev-key-123
```

Access in code:

```tsx
const apiUrl = process.env.EXPO_PUBLIC_API_URL;
```

- `EXPO_PUBLIC_` prefix = bundled into client (visible). Use for non-secrets.
- Without prefix = server-side only (not in RN client).

**.gitignore:**

```
.env
.env.local
.env.*.local
```

**EAS secrets (production):**

```bash
eas secret:create --name API_KEY --value "prod-secret" --type string
```

Access in `eas.json`:

```json
{
  "build": {
    "production": {
      "env": {
        "EXPO_PUBLIC_API_URL": "https://api.prod.com"
      }
    }
  }
}
```

For secrets (not EXPO_PUBLIC), use EAS secrets + app config.

**Multiple envs:**

```bash
# .env.development
EXPO_PUBLIC_API_URL=http://localhost:3000

# .env.production
EXPO_PUBLIC_API_URL=https://api.prod.com
```

Expo loads `.env` by default; use `--env-file` for others.

**app.config.js (dynamic):**

```js
export default ({ config }) => ({
  ...config,
  extra: {
    apiUrl: process.env.EXPO_PUBLIC_API_URL,
  },
});
```

Access: `Constants.expoConfig.extra.apiUrl`.

### CODE (gradual)

Stage 1 — Hardcoded (problem):

```tsx
const API_KEY = "abc123"; // in code — bad
```

Stage 2 — .env + EXPO_PUBLIC:

```bash
EXPO_PUBLIC_API_KEY=dev-key
```

```tsx
const key = process.env.EXPO_PUBLIC_API_KEY;
```

Stage 3 — .gitignore .env.

Stage 4 — EAS secret for prod:

```bash
eas secret:create --name API_KEY --value "prod-secret"
```

Stage 5 — Profile-based env in eas.json.

### TEST

Teen sawaal:

1. Client-exposed env var prefix? (`EXPO_PUBLIC_`)
2. Secret store kaise EAS pe? (`eas secret:create`)
3. `.env` git mein commit karna chahiye? (Nahi — `.gitignore`)

**Checkpoint:** `.env` bana with `EXPO_PUBLIC_API_URL`, code se access, verify value. EAS secret create kar, build mein verify.

## Common Mistakes

- Secrets ko `EXPO_PUBLIC_` mein daalna (client-visible).
- `.env` commit karna (security).
- Env var bina prefix (undefined in client).
- Different envs ke liye same value use karna.

## Khud Try Karo

1. `.env` setup kar, `process.env` access.
2. EAS secret create + build verify.
3. Dev/prod profiles with different URLs.

## Summary

- `.env` + `EXPO_PUBLIC_` prefix for client vars.
- EAS secrets + `eas.json` env for production.
- Never commit `.env`; `.gitignore`.
- Profiles for dev/preview/production.

## What It Is NOT

- ❌ `EXPO_PUBLIC_` vars are **not** secret — visible in bundle.
- ❌ `.env` is **not** for production secrets.
- ❌ Env vars are **not** automatically per-profile.
