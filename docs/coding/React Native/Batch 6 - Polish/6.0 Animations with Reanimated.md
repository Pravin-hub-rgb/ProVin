## Main Content

### THINK

The app is functional but feels static. Animations make the app feel "alive". RN's built-in `Animated` API works but runs on the bridge (jank). Reanimated runs on the UI thread (smooth). First Reanimated basics (shared value, animated style, withTiming/withSpring), then practical (fade, scale, slide).

### CONCEPT

**Core concepts:**

- `useSharedValue(initial)` — a UI-thread value (like state but on the UI thread).
- `useAnimatedStyle(() => ({ ... }))` — derives style from a shared value (worklet).
- `withTiming(toValue, config)` — animate to a value over a duration.
- `withSpring(toValue, config)` — spring animation.
- `Animated.View` — animated component.

**Fade in example:**

```tsx
import Animated, { useSharedValue, useAnimatedStyle, withTiming } from "react-native-reanimated";
import { useEffect } from "react";

export default function FadeIn() {
  const opacity = useSharedValue(0);

  useEffect(() => {
    opacity.value = withTiming(1, { duration: 500 });
  }, []);

  const animatedStyle = useAnimatedStyle(() => ({
    opacity: opacity.value,
  }));

  return <Animated.View style={animatedStyle}><Text>Fade in</Text></Animated.View>;
}
```

**Scale on press:**

```tsx
const scale = useSharedValue(1);

const animatedStyle = useAnimatedStyle(() => ({
  transform: [{ scale: scale.value }],
}));

<Pressable onPressIn={() => (scale.value = withSpring(0.9))} onPressOut={() => (scale.value = withSpring(1))}>
  <Animated.View style={animatedStyle}>...</Animated.View>
</Pressable>
```

**Reanimated vs Animated:**

| | Animated (built-in) | Reanimated |
|---|---|---|
| Thread | JS thread (bridge) | UI thread |
| Performance | Jank on heavy | Smooth |
| API | `Animated.Value` | `useSharedValue` |
| Worklets | No | Yes |

```tsx
const opacity = useSharedValue(0);

return <Animated.View style={style}>...</Animated.View>;
```

Stage 3 — Scale on press:

```tsx
const scale = useSharedValue(1);
const style = useAnimatedStyle(() => ({ transform: [{ scale: scale.value }] }));
<Pressable onPressIn={() => scale.value = withSpring(0.9)} onPressOut={() => scale.value = withSpring(1)}>
  <Animated.View style={style}>...</Animated.View>

```

Stage 4 — Slide in:

```tsx
const translateX = useSharedValue(-200);
useEffect(() => { translateX.value = withSpring(0); }, []);
const style = useAnimatedStyle(() => ({ transform: [{ translateX: translateX.value }] }));
```

## Common Mistakes

- Treating `useSharedValue` like `useState` — use `.value` access.
- Non-worklet code inside `useAnimatedStyle` → error.
- Importing `Animated` from RN instead of reanimated.
- Heavy animations on the JS thread (use Reanimated).

**In Your Own Words**

1. What is a shared value?

<details>
<summary>Sample Answer</summary>

**Answer:** A value that lives on the UI thread, updated via `.value`.

</details>

2. What does `useAnimatedStyle` do?

<details>
<summary>Sample Answer</summary>

**Answer:** Returns an animated style object derived from shared values (runs as a worklet on the UI thread).

</details>

3. `withTiming` vs `withSpring`?

<details>
<summary>Sample Answer</summary>

**Answer:** `withTiming` animates over a duration; `withSpring` uses physics (spring).

</details>

4. Why Reanimated over the built-in `Animated`?

<details>
<summary>Sample Answer</summary>

**Answer:** Reanimated runs on the UI thread (smooth); built-in runs on the JS thread (can jank).

</details>

5. What is a worklet?

<details>
<summary>Sample Answer</summary>

**Answer:** A function that runs on the UI thread (marked with `'worklet'`).

</details>

## What It Is NOT

- ❌ Reanimated is **not** the built-in `Animated` — different API.
- ❌ Shared values are **not** React state — use `.value`.
- ❌ Worklets are **not** normal JS — UI thread only.
