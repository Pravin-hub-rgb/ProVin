# Doc 6.2 — Theming and Dark Mode

## Cheat Sheet (Quick Recall)

- `useColorScheme()` from RN detects light/dark.
- NativeWind: `dark:` prefix classes (`dark:bg-black`).
- Theme context: store theme preference (system/light/dark) in Zustand/AsyncStorage.
- Colors: define semantic tokens (background, text, primary) per theme.
- Persist user preference; respect system default.

## Main Content

### THINK

The app is functional but single-themed. Dark mode is needed (user preference + system). NativeWind `dark:` classes are easy. But full theming (semantic tokens, persist preference, system default) is needed. First NativeWind dark (simple), then theme context (persist), then semantic tokens.

### CONCEPT

**NativeWind dark mode (simple):**

```tsx
<View className="bg-white dark:bg-black">
  <Text className="text-black dark:text-white">Hello</Text>
</View>
```

Tailwind's `dark:` variant is based on the system color scheme by default.

**Theme preference (system/light/dark):**

```tsx
type Theme = "system" | "light" | "dark";

const useThemeStore = create((set) => ({
  theme: "system" as Theme,
  setTheme: (t: Theme) => set({ theme: t }),
}));
```

Persist in AsyncStorage.

**Resolve the actual scheme:**

```tsx
const systemScheme = useColorScheme(); // "light" | "dark" | null
const theme = useThemeStore((s) => s.theme);

const isDark =
  theme === "dark" || (theme === "system" && systemScheme === "dark");
```

**Apply to NativeWind:**

NativeWind supports a `colorScheme` override via `setColorScheme` from `nativewind`:

```tsx
import { setColorScheme } from "nativewind";
setColorScheme(isDark ? "dark" : "light");
```

**Semantic tokens (advanced):**

Define colors in `tailwind.config.js`:

```js
theme: {
  extend: {
    colors: {
      background: "var(--color-background)",
      text: "var(--color-text)",
    },
  },
}
```

Or simpler: use Tailwind's built-in dark variants.

### CODE (gradual)

Stage 1 — NativeWind dark classes:

```tsx
<View className="bg-white dark:bg-gray-900 p-4">
  <Text className="text-black dark:text-white">Hello</Text>
</View>
```

Stage 2 — System detect:

```tsx
const scheme = useColorScheme();
<Text>{scheme === "dark" ? "Dark mode" : "Light mode"}</Text>
```

Stage 3 — Theme store (persist):

```tsx
const useThemeStore = create((set) => ({
  theme: "system",
  setTheme: (t) => set({ theme: t }),
}));
```

Stage 4 — Apply via setColorScheme:

```tsx
const isDark = theme === "dark" || (theme === "system" && systemScheme === "dark");
useEffect(() => { setColorScheme(isDark ? "dark" : "light"); }, [isDark]);
```

Stage 5 — Persist + load on mount:

```tsx
useEffect(() => {
  AsyncStorage.getItem("theme").then((t) => t && setTheme(t as Theme));
}, []);
```

## Common Mistakes

- NativeWind dark mode not configured (tailwind config `darkMode: "class"` or media).
- Ignoring the system scheme when theme is "system".
- Not persisting the theme preference.
- Hardcoding colors instead of semantic tokens.

## What It Is NOT

- ❌ NativeWind dark mode is **not** automatic without config.
- ❌ `useColorScheme` is **not** user preference — system only.
- ❌ Hardcoded colors are **not** themable.
