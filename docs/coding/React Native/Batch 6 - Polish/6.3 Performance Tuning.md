# Doc 6.3 — Performance Tuning

## Cheat Sheet (Quick Recall)

- `React.memo` to avoid re-renders of unchanged components.
- `useMemo` for expensive calculations; `useCallback` for stable function refs.
- `FlatList` performance props (`getItemLayout`, `windowSize`, etc.).
- Avoid inline functions/objects in render.
- Profile with React DevTools / Flipper.

### CONCEPT

**React.memo:**

```tsx
const HabitItem = React.memo(({ habit, onToggle }) => {
  return <Pressable onPress={() => onToggle(habit.id)}>...</Pressable>;
});
```

Re-rend only if props change (shallow compare).

**useMemo:**

```tsx
const sortedHabits = useMemo(() => habits.sort((a, b) => a.streak - b.streak), [habits]);
```

Expensive calculation cache.

**useCallback:**

```tsx
const handleToggle = useCallback((id: string) => {
  setHabits((prev) => prev.map((h) => (h.id === id ? { ...h, done: !h.done } : h)));
}, []);
```

Stable function reference for child props.

**Avoid inline:**

```tsx
// ❌ Bad — new object/function every render
<HabitItem style={{ padding: 8 }} onPress={() => toggle(id)} />

// ✅ Good — stable
const style = { padding: 8 }; // or StyleSheet
const onPress = useCallback(() => toggle(id), [id]);
<HabitItem style={style} onPress={onPress} />
```

**FlatList perf:**

- `getItemLayout` for fixed height.
- `keyExtractor` stable.
- `renderItem` as separate component or `useCallback`.
- `windowSize`, `maxToRenderPerBatch`, `initialNumToRender`.

**Images:**

- Use `expo-image` (better caching than RN `Image`).
- Resize images appropriately.

**Profiling:**

- React DevTools Profiler (component render counts).
- Flipper (network, layout).
- `console.log` count (dev only).

### CODE (gradual)

Stage 1 — Problem (inline re-render):

```tsx
{habits.map((h) => (
  <HabitItem key={h.id} habit={h} onPress={() => toggle(h.id)} style={{ padding: 8 }} />
))}
```

Every render new function/object.

Stage 2 — React.memo on child:

```tsx
const HabitItem = React.memo(({ habit, onPress }) => { ... });
```

Stage 3 — useCallback for handler:

```tsx
const handleToggle = useCallback((id) => toggle(id), []);
```

Stage 4 — useMemo for derived data:

```tsx
const sorted = useMemo(() => [...habits].sort(...), [habits]);
```

Stage 5 — FlatList with getItemLayout:

```tsx
<FlatList data={sorted} getItemLayout={(_, i) => ({ length: 60, offset: 60 * i, index: i })} ... />
```

## Common Mistakes

- `React.memo` with object props (always re-render) — use primitive or stable refs.
- `useMemo`/`useCallback` overuse (premature optimization).
- Inline styles/functions in FlatList renderItem.
- `getItemLayout` galat offset → wrong scroll.

## Khud Try Karo

1. Profiler se render count check kar.
2. `React.memo` + `useCallback` add kar, before/after compare.
3. `expo-image` use kar (caching).

## Summary

- `React.memo`, `useMemo`, `useCallback` for re-render control.
- Avoid inline functions/objects in render.
- FlatList perf props + `expo-image`.

**In Your Own Words**

1. What does `React.memo` do?

<details>
<summary>Sample Answer</summary>

**Answer:** Skips re-render if props are shallowly equal.

</details>

2. `useMemo` vs `useCallback`?

<details>
<summary>Sample Answer</summary>

**Answer:** `useMemo` caches a computed value; `useCallback` caches a function reference.

</details>

3. Why avoid inline functions in render?

<details>
<summary>Sample Answer</summary>

**Answer:** They create new references each render, causing child re-renders.

</details>

<details>
<summary>Sample Answer</summary>

**Answer:** `getItemLayout`.

</details>

<details>
<summary>Sample Answer</summary>

**Answer:** React DevTools Profiler.

</details>

## What It Is NOT

- ❌ `React.memo` is **not** deep compare — shallow only.
- ❌ `useMemo` is **not** always needed — premature optimization.
- ❌ Profiling is **not** for production builds.
