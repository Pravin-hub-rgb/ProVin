# Doc 2.5 — Safe Areas and Tab Layout

## Cheat Sheet (Quick Recall)

- `SafeAreaView` from `react-native-safe-area-context` keeps content clear of the notch/home indicator.
- Tab layout in `app/(tabs)/_layout.tsx` with `Tabs` + `Tabs.Screen`.
- Tab icons via `options={{ tabBarIcon }}` (Ionicons/Expo vector icons).
- Safe area + tab bar = content not hidden behind the tab bar or notch.

## Main Content

### THINK

NativeWind is ready. But on a phone the notch and the tab bar can hide content. Safe areas (notch/home indicator) + tab bar (bottom) need proper layout. First safe area (single screen), then tab layout (bottom tabs), then combined (safe area + tabs).

### CONCEPT

**SafeAreaView:**

```tsx
import { SafeAreaView } from "react-native-safe-area-context";

<SafeAreaView style={{ flex: 1 }}>
  {/* content stays clear of notch/home indicator */}
</SafeAreaView>
```

Expo sets up `react-native-safe-area-context` by default.

**Tab layout:**

```tsx
// app/(tabs)/_layout.tsx
import { Tabs } from "expo-router";
import { Ionicons } from "@expo/vector-icons";

export default function TabLayout() {
  return (
    <Tabs screenOptions={{ tabBarActiveTintColor: "#007AFF" }}>
      <Tabs.Screen
        name="index"
        options={{
          title: "Notes",
          tabBarIcon: ({ color }) => <Ionicons name="list" size={24} color={color} />,
        }}
      />
      <Tabs.Screen
        name="settings"
        options={{
          title: "Settings",
          tabBarIcon: ({ color }) => <Ionicons name="settings" size={24} color={color} />,
        }}
      />
    </Tabs>
  );
}
```

**Safe area + tabs (combined):**

Tabs automatically handle the bottom safe area for the tab bar. In the content area, use `SafeAreaView` or `useSafeAreaInsets` for the top notch.

```tsx
import { useSafeAreaInsets } from "react-native-safe-area-context";

const insets = useSafeAreaInsets();
<View style={{ paddingTop: insets.top, flex: 1 }}>...</View>
```

### CODE (gradual)

Stage 1 — SafeAreaView on a single screen:

```tsx
<SafeAreaView className="flex-1 bg-white">
  <Text className="p-4">Content clear of notch</Text>
</SafeAreaView>
```

Stage 2 — Tab layout (no icons):

```tsx
<Tabs>
  <Tabs.Screen name="index" options={{ title: "Notes" }} />
  <Tabs.Screen name="settings" options={{ title: "Settings" }} />
</Tabs>
```

Stage 3 — Add icons:

```tsx
<Tabs.Screen name="index" options={{ title: "Notes", tabBarIcon: ({ color }) => <Ionicons name="list" size={24} color={color} /> }} />
```

Stage 4 — Safe area insets in content:

```tsx
const insets = useSafeAreaInsets();
<View style={{ paddingTop: insets.top, flex: 1 }}>...</View>
```

## Common Mistakes

- Using the core `SafeAreaView` (deprecated).
- Content hidden behind the tab bar — use `useSafeAreaInsets` or `SafeAreaView`.
- Missing tab icon → default placeholder.
- Including the route group `(tabs)` in the URL.

## What It Is NOT

- ❌ The core `SafeAreaView` is **not** recommended (deprecated).
- ❌ The tab bar does **not** auto-handle content padding (use insets).
- ❌ Route groups are **not** URL segments.
