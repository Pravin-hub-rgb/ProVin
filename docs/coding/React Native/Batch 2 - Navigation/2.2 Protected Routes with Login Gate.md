# Doc 2.2 — Protected Routes with Login Gate

## Cheat Sheet (Quick Recall)

- Auth state via Context (or Redux/Zustand) — `isAuthenticated`.
- Protect routes in `_layout.tsx` using `Redirect` or conditional rendering.
- Login gate: if not auth, redirect to `/login`.
- Store token securely: `expo-secure-store` (not AsyncStorage for tokens).
- Logout clears state + token.

## Main Content

### THINK

The notes app can have private screens (my notes, settings). They should not be accessible without login. On the web there are protected routes (React Router guards). In Expo Router, manage auth state with Context, check it in `_layout.tsx`, and redirect to login if not auth. Store the token securely (SecureStore, not AsyncStorage).

### CONCEPT

**Auth state (Context):**

```tsx
// contexts/AuthContext.tsx
import { createContext, useContext, useState } from "react";

type AuthContextType = { isAuthenticated: boolean; login: () => void; logout: () => void };
const AuthContext = createContext<AuthContextType | null>(null);

export function AuthProvider({ children }) {
  const [isAuthenticated, setIsAuthenticated] = useState(false);
  const login = () => setIsAuthenticated(true);
  const logout = () => setIsAuthenticated(false);
  return <AuthContext.Provider value={{ isAuthenticated, login, logout }}>{children}</AuthContext.Provider>;
}

export const useAuth = () => useContext(AuthContext)!;
```

**Protect in a layout:**

```tsx
// app/(protected)/_layout.tsx
import { Redirect } from "expo-router";
import { useAuth } from "@/contexts/AuthContext";

export default function ProtectedLayout() {
  const { isAuthenticated } = useAuth();
  if (!isAuthenticated) return <Redirect href="/login" />;
  return <Stack />;
}
```

**Secure token storage:**

```tsx
import * as SecureStore from "expo-secure-store";
await SecureStore.setItemAsync("token", token);
const token = await SecureStore.getItemAsync("token");
await SecureStore.deleteItemAsync("token");
```

- Tokens go in SecureStore (encrypted, OS keychain/keystore).
- AsyncStorage is plain text — avoid it for tokens.

**Logout:**

```tsx
const logout = async () => {
  await SecureStore.deleteItemAsync("token");
  setIsAuthenticated(false);
};
```

### CODE (gradual)

Stage 1 — Auth Context (state only, no persistence):

```tsx
const [isAuthenticated, setIsAuthenticated] = useState(false);
```

Stage 2 — Wrap the app with the provider:

```tsx
// app/_layout.tsx
<AuthProvider>
  <Stack />
</AuthProvider>
```

Stage 3 — Protected group + redirect:

```tsx
// app/(protected)/_layout.tsx
if (!isAuthenticated) return <Redirect href="/login" />;
return <Stack />;
```

Stage 4 — Login screen sets auth:

```tsx
// app/login.tsx
const { login } = useAuth();
<Pressable onPress={login}><Text>Login</Text></Pressable>
```

Stage 5 — SecureStore token (real auth):

```tsx
await SecureStore.setItemAsync("token", response.token);
```

**Checkpoint:** Navigate to `/protected` without login → redirect to `/login`. Login → protected screen opens. Logout → redirect.

## Common Mistakes

- Storing tokens in AsyncStorage (plain text, insecure).
- Checking auth at the component level instead of the layout level.
- Forgetting the early return after `Redirect` → children still render.
- Not clearing the token on logout.

## What It Is NOT

- ❌ Protected routes are **not** just component-level checks.
- ❌ AsyncStorage is **not** secure for tokens.
- ❌ Auth state is **not** automatically persisted — you persist the token manually.
