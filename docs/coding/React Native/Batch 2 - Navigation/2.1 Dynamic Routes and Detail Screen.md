# Doc 2.1 — Dynamic Routes and Detail Screen

## Cheat Sheet (Quick Recall)

- Dynamic route file: `app/notes/[id].tsx` → `/notes/:id`.
- Read param: `useLocalSearchParams()` from `expo-router` → `{ id }`.
- Pass data via param or fetch by id.
- `useLocalSearchParams()` for query params.
- Always handle missing/invalid id (guard).

## Main Content

### THINK

The notes app has a notes list, and each note has a detail screen. The URL contains the note id (`/notes/123`). A dynamic route is needed. On the web there is React Router's `:id`; in Expo Router it is the `[id].tsx` file. First the dynamic route file, then reading the param, then data fetch/show, then the guard (invalid id).

### CONCEPT

**Dynamic route file:**

A file named with brackets: `app/notes/[id].tsx` → route `/notes/:id`.

**Read the param:**

```tsx
import { useLocalSearchParams } from "expo-router";

export default function NoteDetail() {
  const { id } = useLocalSearchParams<{ id: string }>();
  return <Text>Note: {id}</Text>;
}
```

- `useLocalSearchParams` returns an object with the route params.
- Type with a generic for safety.

**Data handling:**

- Option A: pass data via param (limited by URL length).
- Option B: fetch by id (TanStack Query, Batch 4).
- For now: local array lookup by id.

**Guard (invalid id):**

```tsx
const note = notes.find((n) => n.id === id);
if (!note) return <Text>Not found</Text>;
```

### CODE (gradual)

Stage 1 — Static detail (hardcoded):

```tsx
// app/notes/detail.tsx
export default function Detail() {
  return <Text>Note title here</Text>;
}
```

Stage 2 — Dynamic route file + param read:

```tsx
// app/notes/[id].tsx
import { useLocalSearchParams } from "expo-router";
import { Text, View } from "react-native";

export default function NoteDetail() {
  const { id } = useLocalSearchParams<{ id: string }>();
  return (
    <View style={{ flex: 1, padding: 16 }}>
      <Text>Note ID: {id}</Text>
    </View>
  );
}
```

Save and navigate to `/notes/123` → "Note ID: 123".

Stage 3 — Data lookup:

```tsx
const { id } = useLocalSearchParams<{ id: string }>();
const note = notes.find((n) => n.id === id);
```

Stage 4 — Guard + render:

```tsx
if (!note) return <Text>Not found</Text>;
return (
  <View style={{ flex: 1, padding: 16 }}>
    <Text style={{ fontSize: 20, fontWeight: "bold" }}>{note.title}</Text>
    <Text>{note.body}</Text>
  </View>
);
```

Stage 5 — Navigate from the list:

```tsx
// app/index.tsx (list)
import { router } from "expo-router";
<Pressable onPress={() => router.push(`/notes/${note.id}`)}>
  <Text>{note.title}</Text>
</Pressable>
```

### TEST

Three questions:

2. How to read a param? (`useLocalSearchParams`)

**Checkpoint:** Build a notes list, tap to open the detail screen with the correct id. On an invalid id, "Not found" should show.

## Common Mistakes

- Using `useParams` (React Router) — Expo Router uses `useLocalSearchParams`.
- Ignoring the param type — string vs number confusion.
- Missing the guard → crash on invalid id.
- Overusing data passed via param — URL length limits.

## Summary

- Dynamic route: `[id].tsx` → `/notes/:id`.
- Read with `useLocalSearchParams<{ id: string }>()`.
- Guard invalid ids; navigate via `router.push`.

## What It Is NOT

- ❌ A dynamic route is **not** a normal file — brackets matter.
- ❌ `useLocalSearchParams` is **not** `useParams` (React Router).
- ❌ A param is **not** auto-fetched data — you fetch/lookup it yourself.
