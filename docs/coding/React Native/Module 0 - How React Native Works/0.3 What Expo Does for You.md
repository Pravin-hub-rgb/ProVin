# Doc 0.3 — What Expo Does for You

## Cheat Sheet (Quick Recall)

- Expo provides: project setup, dev server + QR code, SDK native modules, EAS cloud builds, OTA updates.
- Expo hides: Android Studio/Xcode, Gradle/CocoaPods, native project files, manual module linking.
- Expo Go = generic viewer app; dev builds = your own binary.
- Managed workflow enough for learning; bare workflow for deep native needs.

## Main Content

### SOCH

Native side samajh aaya — Android Studio, Xcode, Gradle, CocoaPods, module linking sab complex hai. Agar har beginner ko yeh setup karna pade, toh course shuru hone se pehle hi log drop kar denge. Expo yahi problem solve karta hai: tooling layer jo native complexity hide karta hai, taaki reader JS/TS pe focus kare. Lekin Expo kya exactly karta hai aur kya nahi — yeh clear hona chahiye.

### CONCEPT

**Expo provides:**

- **Project setup.** `npx create-expo-app` → working app with sane defaults.
- **Dev server + QR code.** `npx expo start` → scan with Expo Go → app phone pe open.
- **SDK.** Pre-built native modules (camera, location, notifications, file system, etc.) as JS APIs.
- **Builds.** EAS (Expo Application Services) → real Android/iOS binaries in cloud.
- **Updates.** Over-the-air updates (within limits) without app store resubmission.

**Expo hides:**

- Android Studio / Xcode setup.
- Gradle / CocoaPods configuration.
- Native project files (mostly).
- Manual linking of native modules.

Reader JS/TS pe focus kare; Expo native glue handle kare.

**Expo Go vs real app:**

- **Expo Go** = generic app jo tumhara JS run karta hai. Learning/prototyping ke liye great.
- **Development build** = tumhara own app binary with tumhara native code. Needed when custom native module add karo ya Expo Go limits exceed.

Course: Expo Go se start (no setup), dev builds Batch 7 mein.

**When Expo is not enough:**

- Native SDK Expo doesn't wrap → config plugin ya native code.
- Full control chahiye native project files pe → bare workflow.
- App store submission with strict native requirements → EAS builds.

Learning ke liye managed workflow kaafi hai until Batch 7.

### CODE

Project create + run:

```bash
npx create-expo-app my-app
cd my-app
npx expo start
```

Line-by-line:

- `npx create-expo-app my-app` — naya Expo project create karta hai with defaults.
- `cd my-app` — project folder mein ja.
- `npx expo start` — dev server start karta hai, QR code dikhata hai. Scan karo Expo Go se.

## Common Mistakes

- Expo ko React Native ka replacement samajhna — Expo tooling hai, RN concepts same.
- Expo Go ke limits exceed karne pe confuse hona — custom native module need hota hai dev build.
- Bare workflow pe jump karna bina managed workflow try kiye.

## Khud Try Karo

## Summary

- Expo = tooling layer (setup, dev server, QR, SDK, builds, updates).
- Expo hides native complexity so reader JS/TS pe focus kare.
- Expo Go for learning; dev builds later when needed.

## What It Is NOT

- ❌ Expo is **not** a framework — it's tooling on top of React Native.
- ❌ Expo does **not** replace learning React Native concepts.
- ❌ Expo Go is **not** your final app — it's a viewer for development.
