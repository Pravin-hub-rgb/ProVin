# Doc 0.3 — What Expo Does for You

## Cheat Sheet (Quick Recall)

- Expo provides: project setup, dev server + QR code, SDK native modules, EAS cloud builds, OTA updates.
- Expo hides: Android Studio/Xcode, Gradle/CocoaPods, native project files, manual module linking.
- Expo Go = generic viewer app; dev builds = your own binary.
- Managed workflow is enough for learning; bare workflow is for deep native needs.

## Main Content

### THINK

The native side is clear — Android Studio, Xcode, Gradle, CocoaPods, module linking are all complex. If every beginner had to set that up, people would drop out before the course even started. Expo solves exactly this problem: a tooling layer that hides native complexity so the reader can focus on JS/TS. But what Expo does and does not do must be clear.

### CONCEPT

**Expo provides:**

- **Project setup.** `npx create-expo-app` → a working app with sensible defaults.
- **Dev server + QR code.** `npx expo start` → scan with Expo Go → app opens on the phone.
- **SDK.** Pre-built native modules (camera, location, notifications, file system, etc.) exposed as JS APIs.
- **Builds.** EAS (Expo Application Services) → real Android/iOS binaries in the cloud.
- **Updates.** Over-the-air updates (within limits) without app store resubmission.

**Expo hides:**

- Android Studio / Xcode setup.
- Gradle / CocoaPods configuration.
- Native project files (mostly).
- Manual linking of native modules.

The reader focuses on JS/TS; Expo handles the native glue.

**Expo Go vs real app:**

- **Expo Go** = a generic app that runs your JS. Great for learning and prototyping.
- **Development build** = your own app binary with your native code. Needed when you add a custom native module or exceed Expo Go's limits.

The course starts with Expo Go (no setup) and moves to dev builds in Batch 7.

**When Expo is not enough:**

- You need a native SDK Expo does not wrap → use a config plugin or write native code.
- You need full control over native project files → "bare" workflow.
- You ship to app stores with strict native requirements → EAS builds.

For this course, Expo's managed workflow is enough until Batch 7.

### CODE (gradual)

Create and run a project:

```bash
npx create-expo-app my-app
cd my-app
npx expo start
```

Line by line:

- `npx create-expo-app my-app` — creates a new Expo project with defaults.
- `cd my-app` — enter the project folder.
- `npx expo start` — starts the dev server and shows a QR code. Scan it with Expo Go.

## Common Mistakes

- Thinking Expo replaces React Native — Expo is tooling; RN concepts are the same.
- Getting confused when exceeding Expo Go's limits — that is when a dev build is needed.
- Jumping to the bare workflow without trying the managed workflow first.

## What It Is NOT

- ❌ Expo is **not** a framework — it is tooling on top of React Native.
