# Doc 0.2 — Old Bridge vs New Architecture

## Cheat Sheet (Quick Recall)

- Old Bridge: async JSON messages between JS and native threads; serialization bottleneck.
- New Architecture: JSI (direct native access), Fabric (renderer), TurboModules (lazy native modules).
- You don't choose in code; Expo/RN migrating to new architecture.
- Know terms for docs/errors: Bridge, JSI, Fabric, TurboModules.

## Main Content

### SOCH

0.1 mein bola ki instructions JS se native tak cross hoti hain. Lekin yeh communication kabhi bhi "free" nahi tha. Old architecture mein sab kuch async JSON messages se hota tha — aur yahi bottleneck bana. Jab app complex hua, bridge par traffic badha, jank aaya. React Native team ne isliye new architecture banaya. Ab dekhna hai kya badla.

### CONCEPT

**Old Bridge:**

- JS aur native alag threads pe run karte hain.
- Communication via async JSON messages across a bridge.
- JS: "View banao in props ke saath" → JSON serialize → bridge → native deserialize → draw.
- Native: "user tapped" → JSON → bridge → JS handle.

Limitations:

- **Async only.** Har call async; synchronous native read impossible.
- **Serialization cost.** Large data (big lists) serialize/deserialize → lag.
- **Bottleneck.** Sab traffic ek bridge se; heavy traffic → jank.

**New Architecture (teen parts):**

1. **JSI (JavaScript Interface)** — JS native objects ko directly reference kar sakta hai, bina serialization ke, synchronous-ish calls.
2. **Fabric** — new renderer. Faster view rendering, concurrent rendering support.
3. **TurboModules** — native modules lazily loaded via JSI, startup pe sab load nahi hote.

Result: less overhead, synchronous access when needed, better performance, path to concurrent React features.

Do you need to choose? Nahi. Expo/RN migrating to new architecture. Learner: normal code likho; architecture mostly invisible. Terms jaano (Bridge, JSI, Fabric, TurboModules) taaki docs/errors samajh aaye. `app.json`/Expo mein "new architecture" toggle dekho toh samajh aaye kya hai.

### CODE

Koi app code nahi — yeh architecture theory hai. Lekin ek chhota mental-model snippet:

```tsx
// Old (conceptual): JS ko native value chahiye toh async message bhejna padta tha
// nativeModule.getValue((result) => { ... })  // callback-based, async

// New (conceptual): JSI se direct reference
// const value = nativeModule.getValue()  // synchronous-ish, no serialization
```

Line-by-line:

- Old: callback-based async; result baad mein aata hai.
- New: direct call; result turant milta hai (synchronous-ish).

## Common Mistakes

- Bridge aur JSI ko same samajhna.
- Sochna ki new architecture mein code badalna padega — nahi, normal RN code same hai.
- `app.json` mein new architecture toggle dekh ke panic karna — yeh migration setting hai.

## Khud Try Karo

1. Expo docs mein "New Architecture" search karo — Fabric/TurboModules ka official explanation padho.
2. Apne project ka `app.json` open karo — `newArchEnabled` ya similar setting dekho.

## What It Is NOT

- ❌ New architecture is **not** a different framework — same React Native, better internals.
- ❌ You do **not** need to rewrite code for new architecture.
- ❌ Bridge is **not** gone overnight — migration gradual hai.
