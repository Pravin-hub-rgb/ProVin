## Main Content

### THINK

In 0.1 we said instructions cross from JS to native. But this communication was never "free". In the old architecture everything went through async JSON messages — and that became the bottleneck. As apps grew more complex, bridge traffic increased and jank appeared. That is why the React Native team built the new architecture. Now see what changed.

### CONCEPT

**Old Bridge:**

- JS and native run on separate threads.
- Communication via async JSON messages across a bridge.
- JS: "create a View with these props" → serialize to JSON → bridge → native deserializes → draws.
- Native: "user tapped" → serialize → bridge → JS handles it.

Limitations:

- **Async only.** Every call is async; you cannot synchronously read a native value.
- **Serialization cost.** Large data (like big lists) gets serialized/deserialized, causing lag.
- **Bottleneck.** All traffic goes through one bridge; heavy traffic causes jank.

**New Architecture (three parts):**

1. **JSI (JavaScript Interface)** — JS can hold references to native objects and call them directly, without serialization, synchronously.
2. **Fabric** — the new renderer. Renders views faster and supports concurrent rendering.
3. **TurboModules** — native modules loaded lazily via JSI, instead of all at startup.

Result: less overhead, synchronous access when needed, better performance, and a path to concurrent React features.

Do you need to choose? No. Expo and React Native are migrating to the new architecture. As a learner: write normal React Native code; the architecture is mostly invisible. Know the terms (Bridge, JSI, Fabric, TurboModules) so docs and errors make sense. When you see "new architecture" toggles in `app.json`/Expo, you know what they mean.

### CODE (gradual)

There is no app code here — this is architecture theory. But a small mental-model snippet:

```tsx
// Old (conceptual): to get a native value, JS had to send an async message
// nativeModule.getValue((result) => { ... })  // callback-based, async

// New (conceptual): JSI allows direct reference
// const value = nativeModule.getValue()  // synchronous-ish, no serialization
```

Line by line:

- Old: callback-based async; the result arrives later.
- New: direct call; the result is available immediately (synchronous-ish).

## Common Mistakes

- Treating Bridge and JSI as the same thing.
- Thinking the new architecture requires different code — normal RN code stays the same.
- Panicking at "new architecture" toggles in `app.json` — it is a migration setting.

## What It Is NOT

- ❌ The new architecture is **not** a different framework — same React Native, better internals.
- ❌ You do **not** need to rewrite code for the new architecture.
- ❌ The Bridge is **not** gone overnight — migration is gradual.
