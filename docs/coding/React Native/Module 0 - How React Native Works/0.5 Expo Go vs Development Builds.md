## Main Content

### THINK

Expo is chosen. But inside Expo there are two ways to preview your app on a phone: Expo Go (a generic viewer) and development builds (your own binary). Both reload code, but their capabilities differ. If this difference is not understood, the "this module does not work in Expo Go" confusion will come later. So clear it now.

### CONCEPT

**Expo Go:**

- A pre-built app (from the app stores).
- Scan the QR code from `npx expo start`; your JS bundle runs inside Expo Go.
- Pros: zero setup, instant start.
- Limits: only modules bundled into Expo Go are available. If you add a native module not in Expo Go, it will not work.

**Development builds:**

- Your own app binary, built with EAS, containing your native code.
- Install it on the phone once; then it reloads JS like Expo Go.
- Pros: any native module works; behaves like a real app.
- Cons: requires a build step (cloud or local).

**When to switch:**

- Stay on Expo Go while learning Batches 1–6.
- Switch to dev builds when:
  - You add a native module not in Expo Go.
  - You need to test real app behavior (icon, splash, deep links).
  - You prepare for store submission (Batch 7).

### CODE (gradual)

Expo Go workflow (current):

```bash
npx expo start
# scan QR with Expo Go
```

Dev build workflow (later, Batch 7):

```bash
npx eas build --profile development
# install the binary on the phone, then run npx expo start
```

Line by line:

- Expo Go: just start + scan.
- Dev build: EAS build (cloud) → install binary → then start.

## Common Mistakes

- Adding a custom native module in Expo Go and getting confused.
- Treating a dev build as a production build — a dev build is for debugging.
- Treating Expo Go's limits as React Native's limits.

## Try It Yourself

1. Install Expo Go on your phone (from the app store).
2. Run `npx create-expo-app go-demo` + `npx expo start` + scan — the app will open.
3. Skim the EAS docs — the dev build process will make sense.
