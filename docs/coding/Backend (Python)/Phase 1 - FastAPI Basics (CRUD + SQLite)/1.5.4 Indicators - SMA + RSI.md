## Think (Something to Think About)

In DukaanOS you added an item — Parle-G kept. Now tell me — *"Is this item expensive or cheap? Is the trend going up or down?"*

You can't tell from just one price (`last_price = 1420`). You need a **time series** — previous 20-30 days of prices. From that you'll know:

- **SMA (Simple Moving Average)** — average price of last 20 days. If current price is above it, trend is up (bullish). Below it, downtrend.
- **RSI (Relative Strength Index)** — a number from 0 to 100. RSI < 30 = **oversold** (price dropped a lot, might bounce). RSI > 70 = **overbought**.

That's what TradeStack does — computes indicators for 2000 stocks, then the scanner filters them.

**Right now you have a problem** — `stocks` table has only **one** price (`last_price`), no history. Indicators need **multiple days of prices**. So we'll create a **new table** — `prices` — and put time-series data in it.

## Manual Method (painful way)

Think about calculating RSI in Python **without pandas**. You'd do:

```python
def calculate_rsi(prices, period=14):
    # Get price changes
    changes = [prices[i] - prices[i-1] for i in range(1, len(prices))]

    # Separate gains and losses
    gains = [c if c > 0 else 0 for c in changes]
    losses = [-c if c < 0 else 0 for c in changes]

    # Average of last 'period'
    avg_gain = sum(gains[:period]) / period
    avg_loss = sum(losses[:period]) / period

    # RSI formula
    rs = avg_gain / avg_loss if avg_loss > 0 else 0
    rsi = 100 - (100 / (1 + rs))
    return rsi
```

This is **fine for one symbol.** But think — you have **2000 stocks**, and you need to run this for each. And each stock has **60 days of prices**.

This will **run loops** — 2000 stocks × inner loops per stock. Python loops are **slow** — process one value at a time, one after another.

With just 5 stocks, no problem. But TradeStack has 2000 stocks, and the real scanner needs to compute **13 different indicators** per stock. Manual loops would take **minutes**. **That's what pandas solves.**

---

## Concept: What Is Pandas (Simple Language)

Pandas is a **library** for working with tables (dataframes). But it has one **special thing** that makes it perfect for trading/analytics:

**Pandas works on rows, and it runs at C-level.**

Understand — when you write a Python loop:

```python
total = 0
for price in prices:
    total += price     # one by one, slow
```

Every iteration has Python overhead — very slow for 2000 stocks.

In pandas, the same thing happens in **one line**:

```python
total = prices.sum()   # all prices at once, fast
```

It uses C code internally — very fast.

**Analogy:** Think of calculating average height of 2000 students.
- **Python loop** — measure each student one by one, write it down, move to next. Slow.
- **Pandas** — line all students up, measure in one experiment. Fast.

Pandas gives two things this project needs:
1. **DataFrame** — a table (like Excel) where fast operations can happen
2. **Vectorized operations** — math on whole columns at once

## Step 1: Create `prices` Table

Update `init_db()` in `app/db.py` — add `prices` table:

```python
def init_db():
    DB_PATH.parent.mkdir(parents=True, exist_ok=True)

    conn = get_conn()

    # stocks table (already there)
    conn.execute("""
        CREATE TABLE IF NOT EXISTS stocks (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            symbol TEXT NOT NULL UNIQUE,
            name TEXT NOT NULL,
            sector TEXT,
            last_price REAL,
            active INTEGER DEFAULT 1
        )
    """)

    # NEW: prices table — time-series data
    conn.execute("""
        CREATE TABLE IF NOT EXISTS prices (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            symbol TEXT NOT NULL,
            date TEXT NOT NULL,
            open REAL,
            high REAL,
            low REAL,
            close REAL,
            UNIQUE(symbol, date)          # one symbol, one date — no duplicates
        )
    """)

    conn.commit()
    conn.close()
```

**This table was planned in 1.5.1.** Now see its shape:
- `symbol` + `date` → **UNIQUE** — one symbol's one date has only one price (no duplicates)
- `open/high/low/close` — 4 prices for the day. Indicator runs on **`close`** (last price)

**`UNIQUE(symbol, date)` composite key** — same symbol, same date can't be inserted twice. Important in real data (if bhavcopy downloaded again, no duplicates).

```python
"""
Import data from CSV into prices table.
Run: python -m app.seed
"""
import csv
import sqlite3
from pathlib import Path
from .db import get_conn

CSV_PATH = Path(__file__).parent.parent / "data" / "prices.csv"


def seed_prices():
    conn = get_conn()

    # Create table if it doesn't exist yet
    conn.execute("""
        CREATE TABLE IF NOT EXISTS prices (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            symbol TEXT NOT NULL,
            date TEXT NOT NULL,
            open REAL, high REAL, low REAL, close REAL,
            UNIQUE(symbol, date)
        )
    """)

    count = 0
    with open(CSV_PATH) as f:
        reader = csv.DictReader(f)
        for row in reader:
            try:
                conn.execute(
                    """INSERT INTO prices (symbol, date, open, high, low, close)
                       VALUES (?, ?, ?, ?, ?, ?)""",
                    (
                        row["symbol"],
                        row["date"],
                        float(row["open"]),
                        float(row["high"]),
                        float(row["low"]),
                        float(row["close"]),
                    )
                )
                count += 1
            except sqlite3.IntegrityError:
                pass    # duplicate (symbol, date) — skip (idempotent seed)

    conn.commit()
    conn.close()
    print(f"Seeded {count} price rows")


if __name__ == "__main__":
    seed_prices()
```

**`idempotent` means** — if you run it twice, no duplicates appear (UNIQUE constraint + catching `IntegrityError`). This is standard for real seed scripts.

**Run:** `python -m app.seed` — terminal shows "Seeded 240 price rows" (4 stocks × 60 days).

**Verify:** Open `prices` table in SQLite Viewer — 240 rows will show.

## Step 4: `app/indicators.py` — The Real Work (SMA + RSI)

Now the file that's the heart of the whole project. Create new file `app/indicators.py`:

```python
"""
Technical indicators — using pandas.
Real TradeStack has 13 indicators; here we learn with 2 (SMA, RSI).
"""
import pandas as pd


def calculate_sma(prices: pd.Series, period: int = 20) -> float:
    """Simple Moving Average — average of last 'period' closing prices."""
    return float(prices.rolling(window=period).mean().iloc[-1])


def calculate_rsi(prices: pd.Series, period: int = 14) -> float:
    """
    Relative Strength Index (0-100).
    RSI < 30 = oversold, RSI > 70 = overbought.
    """
    delta = prices.diff()          # difference between consecutive prices
    gain = (delta.where(delta > 0, 0)).rolling(window=period).mean()
    loss = (-delta.where(delta < 0, 0)).rolling(window=period).mean()

    rs = gain / loss                # relative strength
    rsi = 100 - (100 / (1 + rs))     # RSI formula
    return float(rsi.iloc[-1])


def get_price_series(conn, symbol: str, limit: int = 60) -> pd.Series:
    """Get closing prices for one symbol from database — as pandas Series."""
    rows = conn.execute(
        "SELECT date, close FROM prices WHERE symbol = ? ORDER BY date LIMIT ?",
        (symbol, limit)
    ).fetchall()

    if not rows:
        raise ValueError(f"No price data for {symbol}")

    # list of tuples -> DataFrame -> Series (only close column)
    df = pd.DataFrame(rows, columns=["date", "close"])
    return df["close"]
```

**See what happened — pure Python loops are gone!**

- `prices.rolling(window=20).mean()` — average of last 20, **one line**. No loop.
- `prices.diff()` — consecutive difference, vectorized.
- `.where(delta > 0, 0)` — where there's no gain, put 0.
- `.rolling(window=14).mean()` — average gain/loss.
- `100 - (100 / (1 + rs))` — RSI formula.

**Compare:**
- Manual: ~10 lines, loop per stock, slow.
- Pandas: ~6 lines, **whole column at once**, fast.

**This is vectorization.** TradeStack also writes each indicator this way in pandas (`src/indicators.py`). You're doing the same — just 2 indicators (SMA, RSI), they have 13.

**`get_price_series`'s job** — get `close` prices from database as a pandas Series. It's the **bridge** between database and calculation. Give data to pandas, pandas calculates.

## Step 5: Endpoint — Add Indicators to `app/main.py`

Now add an endpoint to `main.py` that shows indicators:

```python
import pandas as pd
from .db import get_conn, init_db
from .indicators import get_price_series, calculate_sma, calculate_rsi

# ... (previous code)


@app.get("/api/indicators/{symbol}")
def get_indicators(symbol: str, period: int = 20):
    """
    Get SMA and RSI for one symbol.
    Path param: symbol (like /api/indicators/RELIANCE)
    Query param: period (SMA window)
    """
    conn = get_conn()
    try:
        prices = get_price_series(conn, symbol, limit=60)
    except ValueError as e:
        raise HTTPException(status_code=404, detail=str(e))
    finally:
        conn.close()

    if len(prices) < 20:
        raise HTTPException(status_code=400, detail="Need at least 20 days of data")

    sma = calculate_sma(prices, period)
    rsi = calculate_rsi(prices, period=14)

    current = float(prices.iloc[-1])
    trend = "bullish" if current > sma else "bearish"

    return {
        "symbol": symbol,
        "last_close": current,
        "sma": round(sma, 2),
        "rsi": round(rsi, 2),
        "trend": trend,
        "data_points": len(prices),
    }
```

**This endpoint combines 1.1 (path param `{symbol}` + query `?period`) + pandas.** Data from database → pandas Series → indicators → JSON.

## Extra: Why DataFrame Works (Understand Vectorization)

This is a small thing but very important — because interviews ask *"why is pandas vectorized?"*

**How to think about it:**
- When you write `prices.rolling(20).mean()`, pandas processes **all 60 prices at once** — in one C loop.
- It calculates last 20's average for everything — **in one pass**, for the whole column.
- With manual loops you'd run **60 separate loops** — first 20's average, then next 20, etc.

**Interview answer (remember this):** *"Pandas vectorized operations run at C-level. Manual Python loops have interpreter overhead for every element — pandas applies one bulk operation to all elements at once. So when data is large (thousands of stocks, minute-level candles), pandas is dramatically faster. My scanner computing 2000 stocks × 13 indicators takes seconds with pandas, while manual loops would take minutes."*

---

## Common Mistakes

1. **Not enough data for `period`.** `rolling(window=20)` needs at least 20 values. Less data → `NaN`. Guard added (`if len(prices) < 20`).

2. **Forgetting `.iloc[-1]`.** `rolling().mean()` returns a whole Series. Need `.iloc[-1]` for the last value, otherwise error.

3. **Not casting to `float()`.** `.iloc[-1]` sometimes gives `numpy.float64`, sometimes `NaN`. Cast with `float()` for JSON-safe return.

4. **Not handling `NaN`.** First `period` rows have RSI as `NaN` (no previous prices). `round(NaN)` can crash or return `null`. Add guards.

5. **Not running seed.** `prices` table will be empty → endpoint gives `ValueError`. Run `python -m app.seed` first.

6. **Wrong data types from CSV.** `close` might come as string from CSV — `float(row["close"])` cast is needed, otherwise text goes into SQLite.

7. **Changing the seed.** `seed_prices.py` has `random.seed(42)` fixed. If you change it, data will be different every time — testing gets confusing.

<details>
<summary>1. What's the benefit of pandas vectorized operations? Why better than manual loop?</summary>

Pandas operations run on C-level code, which is much faster than Python interpreter loops. In manual loops, every element has Python overhead (checking happens every iteration), while pandas applies **one bulk operation to the entire column at once** — in a single pass. With 2000 stocks of data, the difference is **minutes vs seconds**. For projects like TradeStack where you compute 13 indicators on 2000 stocks × minute-level candles, without vectorization the scanner would be realistically slow.

</details>

<details>
<summary>2. What do SMA and RSI do? How are they used in real trading?</summary>

**SMA** (Simple Moving Average) = average closing price of last N days. It shows a trend — if current price is above SMA, uptrend (bullish); below, downtrend (bearish). It's a baseline. **RSI** (Relative Strength Index) = a number from 0 to 100 showing momentum. RSI < 30 = **oversold** (price dropped a lot, might bounce). RSI > 70 = **overbought** (price rose a lot, might drop). In real trading, scanners filter stocks based on these indicators — like "list stocks with RSI < 30" = finding oversold stocks.

</details>

<details>
<summary>3. Why is `prices` table's `UNIQUE(symbol, date)` constraint necessary?</summary>

It prevents **duplicate entries**. Think — you imported CSV twice by accident. Without UNIQUE, instead of 240 rows you'd get 480 — every symbol, every date appearing twice. Then SMA/RSI would be wrong (duplicate prices counted, rolling window breaks). `UNIQUE(symbol, date)` tells the database "one symbol's one date can have only one price" — if you try to insert again, `IntegrityError` occurs which the seed script catches and skips. This keeps data **consistent**.

</details>

<details>
<summary>4. Why is `get_price_series` a bridge between database and pandas?</summary>

Database returns raw data (list of `(date, close)` tuples) — pandas can't directly consume that. `get_price_series` converts those tuples into a pandas DataFrame, then returns just the `close` column as a Series. It's a **bridge** function — database's job is separate (data storage), pandas' job is separate (calculation). This keeps both layers **decoupled** — changing data doesn't change calculation logic, and changing indicators doesn't change the data layer.

</details>

<details>
<summary>5. Why is `if len(prices) < 20` guard needed in the endpoint?</summary>

`rolling(window=20)` needs at least 20 values to calculate SMA. If you only have 10 days of data, the rolling window never fills and result is `NaN` (Not a Number). `NaN` doesn't go into JSON cleanly, and the calculation would be wrong. So we added a guard — if data is too little, return a proper **400 error** ("Need at least 20 days of data") instead of crashing or returning `null`. That's defensive programming — validate input before using.

</details>

No. Understanding **2 indicators in depth** is enough for interviews. If they ask *"how do you compute indicators?"* — explaining SMA's formula and vectorization is sufficient.
