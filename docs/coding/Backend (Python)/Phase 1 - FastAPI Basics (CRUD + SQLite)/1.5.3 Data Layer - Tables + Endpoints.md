## Step 1: `app/db.py` Banao — Database Ka Ghar

Pehle `main.py` me sab kuch na likho. **Database wala kaam alag file me.** Ye separation (planning me socha tha) abhi apply kar rahe ho.

Naya file `app/db.py`:

```python
"""
Database layer — SQLite connection, table setup, aur helper functions.
Ye file sirf database se baat karti hai. Endpoints nahi hain yahan.
"""
import sqlite3
from pathlib import Path

# Database file kahan hogi
DB_PATH = Path(__file__).parent.parent / "data" / "stocks.db"


def get_conn():
    """Naya connection banao database se."""
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row   # rows ko dict jaisa banayega
    return conn


def init_db():
    """Table banayi agar pehle se nahi hai. Server start pe ek baar call karoge."""
    DB_PATH.parent.mkdir(parents=True, exist_ok=True)   # data/ folder banao agar nahi

    conn = get_conn()
    conn.execute("""
        CREATE TABLE IF NOT EXISTS stocks (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            symbol TEXT NOT NULL UNIQUE,
            name TEXT NOT NULL,
            sector TEXT,
            last_price REAL,
            active INTEGER DEFAULT 1
        )
    """)
    conn.commit()
    conn.close()
```

**Line by line:**

- `DB_PATH` — file ka location. `Path(__file__).parent.parent` = `app/` folder ka **parent** = project root. Phir `data/stocks.db`. Ye **absolute path** hai — kahin se bhi run karo, milega.
- `get_conn()` — naya connection. `row_factory = sqlite3.Row` (1.4 me seekha) — rows dict jaise milenge.
- `init_db()` — `IF NOT EXISTS` (1.4 me seekha) — har restart pe safe. `mkdir` pehle data folder banata hai. `CREATE TABLE` schema banata hai. `commit()` pakka karta hai.

**`IF NOT EXISTS` kyun?** Kyunki `init_db()` har server restart pe call hoga. Agar `IF NOT EXISTS` na ho, har baar error aayega *"table already exists"*. Ye guard wahi kaam karta hai jo `CREATE TABLE IF NOT EXISTS` karta hai.

## Step 2: `app/models.py` Banao — Data Ka Shape

Doosri file — Pydantic models (1.2 me seekha). `app/models.py`:

```python
"""
Pydantic models — data ka shape aur validation.
"""
from pydantic import BaseModel


class StockCreate(BaseModel):
    """Naya stock add karne ke liye — ye client bhejta hai."""
    symbol: str
    name: str
    sector: str | None = None
    last_price: float


class Stock(StockCreate):
    """Stock jo database se aata hai — id aur active bhi hai."""
    id: int
    active: bool = True
```

**Note kya hua:** `class Stock(StockCreate)` — `Stock` ne `StockCreate` ko **inherit** kiya. Matlab `Stock` me `symbol`, `name`, `sector`, `last_price` sab inherited hain, plus `id` aur `active` extra. Ye **inheritance** hai — baar baar same fields likhne se bachata hai. (Yehi pattern Pydantic docs me standard hai, aur real TradeStack me bhi hai.)

## Step 4: Pehla Endpoint — POST (Naya Stock Add)

Ab pehla **asli** endpoint — naya stock add karna (Create). `main.py` me add karo:

```python
@app.post("/api/stocks", response_model=Stock, status_code=201)
def create_stock(data: StockCreate):
    """Naya stock add karo database me."""
    conn = get_conn()
    try:
        cursor = conn.execute(
            "INSERT INTO stocks (symbol, name, sector, last_price) VALUES (?, ?, ?, ?)",
            (data.symbol, data.name, data.sector, data.last_price)
        )
        conn.commit()
        new_id = cursor.lastrowid          # naya ID jo autoincrement ne diya

        # wahi row wapas padho (1.4 me seekha tha row->dict)
        row = conn.execute("SELECT * FROM stocks WHERE id = ?", (new_id,)).fetchone()
        return dict(row)                   # JSON ban jayega

    except sqlite3.IntegrityError:
        # symbol UNIQUE hai — duplicate aaya to 409 (1.4 me test kiya tha)
        raise HTTPException(status_code=409, detail="Symbol already exists")
    finally:
        conn.close()   # connection band karo (1.4 me seekha)
```

**Ye 1.2, 1.3, 1.4 teeno tools ek saath use kar raha hai:**
- **1.2 (Pydantic)** — `data: StockCreate` me automatically validate hua. `symbol` string hai, `last_price` float hai, `sector` optional. Galat data to 422.
- **1.3 (CRUD/Create)** — `POST` + `status_code=201` (naya bana to 201).
- **1.4 (SQLite)** — `INSERT` query, `?` placeholders, `commit()`, `row` dict me convert, `close()`.

**`sqlite3` import bhoola?** Haan — `import sqlite3` bhi add karna padega `main.py` me (upar `from .db import` ke saath). `except sqlite3.IntegrityError` ke liye chahiye.

**`cursor.lastrowid` kya hai?** Jab `INSERT` karte ho, SQLite naye row ka ID apne aap badhata hai. `lastrowid` se pata chalta hai wo ID kya tha. Yehi woh `id` hai jo hum `SELECT` me use karte hain wapas padhne ke liye.

## Step 5: Test Karo — POST `/api/stocks`

Server chalao (`uvicorn app.main:app --reload`), `/docs` kholo.

**`POST /api/stocks` pe "Try it out" → Execute. Body me likho:**
```json
{
  "symbol": "RELIANCE",
  "name": "Reliance Industries",
  "sector": "Oil",
  "last_price": 1420.50
}
```

**Expect:**
- Response code **201** (Create)
- Response: `{"id": 1, "symbol": "RELIANCE", ..., "active": true}`

**Extra tests (ye zaroori hain):**

1. **Optional field:** Body me `sector` **hata do**. Response me `"sector": null` aayega — kyunki `sector: str | None = None`. Default lag gaya.

2. **Validation (422):** `"last_price": "abc"` bhejo (string, number nahi). FastAPI/Pydantic **422** dega — kyunki `last_price: float` hai, `"abc"` float nahi. Ye Pydantic ka kaam, tumhare code me koi `if` nahi.

3. **UNIQUE (409):** **Same body dobara** bhejo (same `symbol: RELIANCE`). Ab **409 Conflict** aayega — *"Symbol already exists"* — kyunki `symbol` UNIQUE tha aur duplicate reject hua.

**Teeno alag codes (201, 422, 409) — yehi 1.3 ka status codes concept real me dikh raha hai.**

## Step 6: Doosra Endpoint — GET (List Dekho)

Ab **Read** endpoint — stocks ki list. `main.py` me add karo:

```python
@app.get("/api/stocks", response_model=list[Stock])
def list_stocks(limit: int = 20, sector: str | None = None, active_only: bool = False):
    """Stocks ki list — filter aur limit ke saath."""
    conn = get_conn()

    query = "SELECT * FROM stocks WHERE 1=1"      # 1.4 me seekha — dummy condition
    params = []

    if sector:
        query += " AND sector = ?"
        params.append(sector)

    if active_only:
        query += " AND active = 1"                 # boolean -> SQLite me 1/0 (1.4 me seekha)

    query += " LIMIT ?"
    params.append(limit)

    rows = conn.execute(query, params).fetchall()
    conn.close()

    return [dict(r) for r in rows]     # har row ko dict banao
```

**Ye 1.1 (query params) + 1.3 (Read) + 1.4 (SQLite SELECT) combine karta hai:**
- **1.1** — `limit`, `sector`, `active_only` query params hain. `limit` default 20, `sector` optional.
- **1.3** — `GET` = Read, `200` default.
- **1.4** — dynamic SQL (`WHERE 1=1` + filters), `?` placeholders.

**`list[Stock]` ka matlab?** Response model ek **list of Stock**. FastAPI check karega ki har dict me `symbol`, `name` etc fields hain, warna error dega.

## Common Mistakes

1. **`commit()` bhoolna.** Data dikhega par save nahi hoga — restart pe gayab. Har `INSERT`/`UPDATE`/`DELETE` ke baad `conn.commit()` zaroori.

2. **`close()` na karna.** Har endpoint me `finally: conn.close()` ya end me `conn.close()`. Warna connection leak — file handle khule.

3. **`from .db import` bhoolna.** Endpoint likha par `get_conn` import nahi kiya — NameError aayega. Top pe sab imports.

4. **`sqlite3` import na karna** jab `except sqlite3.IntegrityError` likha. `import sqlite3` bhi chahiye upar.

5. **`list[Stock]` ki jagah `Stock` likhna.** List return kar rahe ho to `response_model=list[Stock]` likhna padega, warna FastAPI sochega ek dict chahiye aur error dega.

6. **`WHERE 1=1` me `params` empty list na bhejo.** `conn.execute(query, params)` me `params` list hoti hai. Filters add hone pe `params.append()` karna mat bhoolna, warna `?` aur value match nahi honge.

7. **Data add kiye bina GET test karna.** Pehle 3-4 alag sectors ke stocks POST karo, phir `?sector=` filter test karo. Warna test me kuch dikhega hi nahi.

## Nutshell

- **`db.py`** = database connection + `init_db()` (table setup). `models.py` = Pydantic shapes. `main.py` = sirf endpoints. Separation.
- **`POST /api/stocks`** — 1.2 (validate), 1.3 (create, 201), 1.4 (INSERT, `?`, commit). UNIQUE → 409.
- **`GET /api/stocks`** — 1.1 (`?limit`, `?sector`), 1.3 (read, 200), 1.4 (SELECT, `WHERE 1=1`).
- **`GET /api/stocks/{id}`** — 1.1 (path param), 404 jab na mile.
- **Har write ke baad `commit()`, har endpoint ke baad `close()`.**

## In Your Own Words

<details>
<summary>1. `init_db()` kyun alag function banaya, har baar endpoint me kyun nahi?</summary>

`init_db()` sirf **ek baar** chahiye — jab server start ho, table banani hai. Agar har endpoint me `CREATE TABLE` daal dete to har request pe unnecessary table-check hota. Isse alag function me rakha aur `main.py` me sirf ek baar call kiya (module load pe). `CREATE TABLE IF NOT EXISTS` se safe bhi hai (agar pehle se hai to skip). Ye separation (`db.py` alag) code organized rakhta hai — jab project bada hoga, database ka pura kaam ek jagah rahega.

</details>

<details>
<summary>2. `cursor.lastrowid` ka kya kaam hai aur ye kahan se aata hai?</summary>

Jab `INSERT` karte ho aur `id INTEGER PRIMARY KEY AUTOINCREMENT` hai, to SQLite naye row ka ID **apne aap** 1, 2, 3... badha deta hai. `cursor.lastrowid` se pata chalta hai ki is particular insert ka ID kya banaya. Ye zaroori hai kyunki humein naye stock ka ID chahiye taaki usse wapas `SELECT` kar ke poora row return kar sakein (user ko poora object chahiye, sirf ID nahi).

</details>

<details>
<summary>3. `sector` filter query me kaise add hota hai? `?` ka role kya hai?</summary>

Query shuru me `SELECT * FROM stocks WHERE 1=1` hai (dummy). Fir agar user `?sector=Oil` bheje, to `if sector:` true hota aur `query += " AND sector = ?"` ho jaata hai, aur `params.append(sector)` se value add hoti hai. Final query: `SELECT * FROM stocks WHERE 1=1 AND sector = ?`. Ye **dynamic SQL building** hai — filters user ke input ke hisaab se add hote hain. `?` placeholder hai (1.4 me seekha) — user ka sector value sirf value ki tarah jaata hai, SQL command nahi ban sakta (SQL injection safe).

</details>

<details>
<summary>4. `active_only=true` ko SQL me kaise handle kiya aur kyun?</summary>

SQLite me boolean type nahi hota. `active` column INTEGER hai (1 ya 0). User `?active_only=true` bhejta hai to FastAPI usse Python boolean `True` me convert karta hai (1.1 me seekha). Fir code me `if active_only:` check hota hai aur SQL me `AND active = 1` add hota hai. Kyunki SQLite `True` ko `1` ki tarah store karta hai aur padhta hai `1` return karta hai. Ye boole-integer conversion Python me automatic hai — `if active_only:` `True` ko truthy samajhta hai.

</details>

<details>
<summary>5. Response code 201, 409, 422, 404 — kaunse kab aaya is part me?</summary>

**201** — jab naya stock successfully bana (`POST`). **422** — jab validation fail hui, jaise `"last_price": "abc"` (FastAPI/Pydantic ne reject kiya). **409** — jab `symbol` UNIQUE constraint violate hua (duplicate symbol). **404** — jab `GET /api/stocks/999` kiya aur wo ID exist nahi karta. **200** — normal successful GET. Ye sab 1.3 me padhe the status codes — ab real me dikh rahe hain har ek practically.

</details>

<details>
<summary>6. Data server restart ke baad bhi kyun milta hai jabki pehle ke dict me nahi milta?</summary>

Pehle data ek Python dict me tha — jo sirf RAM me rehti hai, restart pe gayab. Ab data SQLite **file** me likha jaata hai (`data/stocks.db`) — jo disk pe permanent rehti hai. Restart karne se file safe rehti hai, aur `get_conn()` fir us file ko kholke wahi data deta hai. Ye SQLite ka core fayda hai — **disk-based persistence, zero config**.

</details>

## What It Is NOT

- ❌ **Complete CRUD nahi** — sirf Create (POST) aur Read (GET) banaye. Update (PUT) aur Delete abhi nahi — agle step me.
- ❌ **Settings table nahi** — sirf `stocks`. `settings` aur `prices` agle steps me.
- ❌ **Single detail view nahi** — `/api/stocks/{id}` to hai par "detail page" jaisa rich view nahi (chart, history wagairah nahi).
- ❌ **Auth nahi** — koi bhi POST/GET kar sakta hai. Real me token chahiye.
- ❌ **Seed data nahi** — manually POST karke stocks add kiye. Real me ek `seed.py` script hota (agle steps me `prices` ke liye banayenge).
