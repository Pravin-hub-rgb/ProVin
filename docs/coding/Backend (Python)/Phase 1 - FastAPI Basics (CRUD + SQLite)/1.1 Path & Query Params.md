Shuru karte hain. Sabse pehla core tool — **Path aur Query parameters**. Ye FastAPI ka sabse simple aur sabse zyada use hone wala feature hai.

Socho tumhe apni **DukaanOS** chalani hai — wo kirana store ka POS system hai. Customer aata hai aur bill ke liye line maarta hai. Ab kuch scenarios sochо:

---

## Sochо (Sochne Wala Scene)

DukaanOS ke counter pe kuch requests aati hain roz:

1. *"Bhai RELIANCE ka price dikha."* — **ek specific stock** chahiye.
2. *"IT sector ke top 20 stocks dikha."* — **ek group, aur limit** chahiye.
3. *"Sirf wo stocks dikha jinka RSI 30 se kam hai."* — **ek filter** chahiye.

Ab in teeno me kya farak hai? Pehle me **ek cheez ka naam** hai (RELIANCE). Doosre me **filter + limit** hai (sector=IT, 20 tak). Teesre me **ek condition** hai (RSI < 30).

Server ko ye baat kahin se bhejni hi padegi — **URL ke through**. Aur yahi FastAPI ka kaam hai — URL se data nikal ke tumhare function me dena.

## Manual Tareeka (dard wala)

Agar FastAPI na hota, to kya karte? Server ko ek URL string milti — jaise `http://localhost:8000/api/stocks/RELIANCE?sector=IT&limit=20`. Ab usse manually parse karna padta.

Python me ye karna padta (ye `cgi` module ka purana tareeka tha, ya khud string todna):

```python
# Manual (ye kabhi mat karna)
from urllib.parse import urlparse, parse_qs
parsed = urlparse(request.url)
path_parts = parsed.path.split("/")   # ['', 'api', 'stocks', 'RELIANCE']
query = parse_qs(parsed.query)          # {'sector': ['IT'], 'limit': ['20']}

symbol = path_parts[3]                  # RELIANCE
sector = query.get("sector")            # ['IT']  (list me hai!)
limit = int(query.get("limit")[0])      # 20
```

Socho ye karte hi kya dard hota:

- `path_parts[3]` — **magic number**. Kal route structure badla, aur tera index 3 galat ho gaya. Pata bhi nahi chalega, bas galat data aa jayega.
- `query.get("sector")` — **list me hai** (`['IT']`), string me nahi. Har baar `[0]` likhna padta.
- `limit` — string `"20"` hai, convert karna padta. Aur agar user ne `?limit=abc` bheja to **crash** — kyunki `int("abc")` error dega, aur user ko proper message nahi jayega.
- Type checking kahin nahi.

Yeh sab problems FastAPI ke **path aur query parameters** se khatam ho jaati hain.

## Concept: Path Parameter

**Path parameter** woh value hai jo URL ke **path** me directly likhi hoti hai aur jo tumhari resource ki identity batati hai.

FastAPI me isse `{ }` se mark karte hain:

```python
@app.get("/api/stocks/{symbol}")
def get_stock(symbol: str):
    return {"symbol": symbol}
```

Ab jab koi bhejega `GET /api/stocks/RELIANCE`, to FastAPI:
1. URL dekhta hai — path me `{symbol}` placeholder hai
2. `RELIANCE` ko nikalta hai
3. **Automatically** function ko `symbol="RELIANCE"` ke saath call karta hai
4. Aur `symbol` ko **automatic string type** maanta hai (kyunki `symbol: str` likha hai)

Tumhe `split("/")` karne ki zaroorat nahi, `[0]` likhne ki zaroorat nahi, magic number koi nahi. Bas function ka signature dekho aur samajh a gaya ki kya milega.

---

## Concept: Query Parameter

**Query parameter** woh extra filter hai jo URL ke **path ke baad `?` lagake** aata hai. Ye resource ki identity nahi hai — wo **dekhna hai** ki kya chahiye.

```python
@app.get("/api/stocks")
def list_stocks(limit: int = 20, sector: str | None = None):
    # limit aur sector browser se aayenge
    return {"limit": limit, "sector": sector}
```

Ab `GET /api/stocks?limit=10&sector=IT` bhejoge to FastAPI function ko `limit=10, sector="IT"` dega.

**Do baatein dhyan rakh:**

1. **Default value** — `limit: int = 20`. Agar user `?limit=` na bheje, to 20 use hoga. Agar default na hota, to FastAPI error dega ("field required") — aur simple list page toot jata. Default rakhna **robust** hota hai.

2. **Optional query** — `sector: str | None = None`. `|` ka matlab "ya". Agar user sector nahi de, to `None` aayega, aur tumhare code ko handle karna padega. Ye `|` Python ka "union" operator hai (Python 3.10+). Purane `Optional[str]` bhi sahi hai — dono same cheez.

**Types FastAPI khud badalta hai.** Agar user `?limit=abc` bheje, to FastAPI `int("abc")` crash hone se pehle **apne aap** 422 error de deta hai — *"limit must be an integer"*. Ye manual tareeke me nahi hota tha.

## Concept: Path + Query Saath

Real mein dono ek saath chahiye. DukaanOS ka soch — *"RELIANCE ka data dikha, aur uska last 30 din ka history bhi."*

```python
@app.get("/api/stocks/{symbol}")
def get_stock(symbol: str, days: int = 30):
    return {"symbol": symbol, "days": days}
```

- `GET /api/stocks/RELIANCE` → `symbol="RELIANCE", days=30`
- `GET /api/stocks/RELIANCE?days=90` → `symbol="RELIANCE", days=90`

Path se **kaunsa stock** (identity), query se **kya chahiye** (options). Ye do ka alag-alag hona hi path vs query ka core rule hai.

## Code: Ek Complete Example

Ek chhota endpoint likhte hain jo real TradeStack jaisa feel de:

```python
from fastapi import FastAPI

app = FastAPI(title="Trading Backend Basic")


# Sirf path parameter — ek stock
@app.get("/api/stocks/{symbol}")
def get_stock(symbol: str):
    # symbol ka type already string hai, convert karne ki zaroorat nahi
    return {
        "symbol": symbol,
        "name": "Reliance Industries",
        "last_price": 1420.50,
    }


# Sirf query parameters — list + filter
@app.get("/api/stocks")
def list_stocks(limit: int = 20, sector: str | None = None):
    stocks = [
        {"symbol": "RELIANCE", "sector": "Oil"},
        {"symbol": "TCS", "sector": "IT"},
        {"symbol": "INFY", "sector": "IT"},
        {"symbol": "HDFCBANK", "sector": "Banking"},
    ]

    # Filter apply karo agar sector diya
    if sector:
        stocks = [s for s in stocks if s["sector"].lower() == sector.lower()]

    # Limit lagao
    return {"count": len(stocks[:limit]), "stocks": stocks[:limit]}


# Path + Query dono — specific stock, specific days
@app.get("/api/stocks/{symbol}/history")
def get_history(symbol: str, days: int = 30, interval: str = "1d"):
    return {
        "symbol": symbol,
        "days": days,
        "interval": interval,
        "candles": days,  # abhi fake data
    }
```

**Ab kya naya mila vs manual tareeka?**

- Koi `split("/")` nahi
- Koi `parse_qs` nahi
- Koi magic number nahi
- Koi `int()` convert nahi — FastAPI ne kiya
- Koi `if` validation nahi — FastAPI ne kiya

Sirf **business logic** bacha — filter, limit, data. Wahi tumhara kaam hai. Baaki framework ka.

## Test: Kaise Verify Karein (Browser Se)

FastAPI ka sabse khoobsurat part — **automatic docs**. Server chalao:

```bash
uvicorn app.main:app --reload
```

Ab browser me jao `http://localhost:8000/docs`. Yahan har endpoint dikhega with "Try it out" button.

**Test sequence (1.1 ke liye):**

1. `GET /api/stocks/RELIANCE` — Try it out → Execute. Dekho response me `"symbol": "RELIANCE"` — path param kaam kar raha hai.
2. `GET /api/stocks?limit=2&sector=IT` — Response me sirf TCS aur INFY, sirf 2 — query params kaam kar rahe hain.
3. `GET /api/stocks/RELIANCE/history?days=90&interval=1h` — Path + query dono.
4. **Galat input test:** `GET /api/stocks?limit=abc` — dekho FastAPI ne 422 de diya (*"field required"/"not a valid integer"*) apne aap, bina tumhare code me kisi `if` ke. **Ye 422 hi Pydantic/validation ka proof hai.**

Har endpoint ke neeche "Try it out" pe click karo, parameters bharo, Execute dabao — response aur status code dono dikhenge. Yehi tumhara testing tool hai is poori phase ka.

## Nutshell

- **Path param** `{symbol}` — kaunsi resource (RELIANCE). Resource ki identity.
- **Query param** `?limit=10` — kya chahiye (filter, limit). Options.
- FastAPI dono **khud parse, convert aur validate** karta hai — tumhe string todne, `int()` karne, ya `if` likhne ki zaroorat nahi.
- Type hint (`symbol: str`, `limit: int = 20`) hi FastAPI ko batata hai kya convert karna hai — aur default value se robust banata hai.

## Common Mistakes

1. **Path aur query mix kar dena.** Path me `{symbol}` hai to wo **path** param hoga. Agar `sector` chahiye to `?sector=IT` bhejo, path me nahi daalna. `/api/stocks/{symbol}/{sector}` galat hai — sector ek filter hai, identity nahi.

2. **Default value na dena.** `def list_stocks(limit: int)` — ab `GET /api/stocks` bina `?limit=` pe error dega. Hamesha default do jab field optional ho.

3. **`Optional` vs `|` bhoolna.** `sector: str` mat likhna agar sector optional hai — warna `"IT"` bhejne wala bhi error milega kyunki `str` required hai. `sector: str | None = None` sahi hai.

4. **Type convert karna FastAPI pe.** `limit: int = 20` — ab function ke andar `int(limit)` mat karo. Already int hai. Double convert = redundant.

5. **`days` jaisa number query me bhejna vs path me.** `/stocks/RELIANCE?days=90` sahi. `/stocks/RELIANCE/90` galat — wo ek **alag resource** ban jayega jaise "RELIANCE ka 90-din wala version". Numbers bhi options hain, identity nahi (unless wo resource identity ka hissa ho).

## In Your Own Words

<details>
<summary>1. Path parameter aur query parameter me kya farak hai? Ek-ek example do.</summary>

Path parameter wo value hai jo URL ke path me `{ }` ke andar aati hai aur resource ki **identity** batata hai — jaise `/api/stocks/RELIANCE` me `RELIANCE` ek specific stock hai. Query parameter wo extra **option/filter** hai jo `?` ke baad aata hai — jaise `/api/stocks?limit=10&sector=IT` me hum 10 stocks maang rahe hain, sirf IT sector se. Simple rule: agar main resource ka **naam** bata raha hoon, wo path param hai; agar main **filter/sort/limit** bata raha hoon, wo query param hai.

</details>

<details>
<summary>2. FastAPI kaise jaanta hai ki `symbol` string hai aur `limit` integer hai? Kya tune koi convert kiya?</summary>

FastAPI function ke **type hints** (`symbol: str`, `limit: int`) padhta hai. Inhi type hints se wo khud decide karta hai ki URL se aayi value ko kya maana jaye — `symbol` ko string maane ka, `limit` ko integer maane ka. Aur agar user `?limit=abc` bhejega to FastAPI **apne aap** 422 error de dega kyunki `"abc"` valid integer nahi hai. Maine manually kuch bhi convert nahi kiya — `int(limit)` jaisa kuch likhna bhi zaroorat nahi thi kyunki value pehle se int ban chuki hoti hai.

</details>

<details>
<summary>3. `limit: int = 20` me `= 20` kyun rakha? Agar na rakhta to?</summary>

`= 20` default value hai. Iska matlab — agar user `?limit=` nahi bhejega, to server 20 maan lega. Agar default na hota, to FastAPI kehta "limit field required" aur error de deta. Phir ek simple list page, jisme user bas `/api/stocks` kholta hai, wo 422 error dikha deta — bahut galat behavior. Default value isliye rakhte hain taaki optional fields optional hi rahein aur server gracefully handle kare.

</details>

<details>
<summary>4. Ek endpoint likho jo stock symbol (path) aur sector (query) dono le, aur sector optional ho.</summary>

```python
@app.get("/api/stocks/{symbol}")

    return {"symbol": symbol, "sector": sector}
```

`{symbol}` path me hai to wo path param. `sector` `?sector=IT` se aayega aur optional hai to `str | None = None`. Result: `GET /api/stocks/RELIANCE` → `sector=None` milega, aur `GET /api/stocks/RELIANCE?sector=IT` → `sector="IT"`.

</details>

<details>
<summary>5. Manual tareeke me kya problems thi jo FastAPI parameters ne khatam ki?</summary>

Manual tareeke me: URL khud `split("/")` karke parse karna padta tha (aur magic numbers jaise `[3]` use karne padte the — route badalne pe bug). Query values list me aati thi (`['IT']`) har baar `[0]` likhna padta tha. Strings ko manually `int()` me convert karna padta tha (aur galat input pe crash hota tha — proper error message ke bajaye). Type checking kahin nahi thi. FastAPI parameters ne ye sab khatam kiya — automatic parsing, automatic type conversion, aur automatic 422 validation.

## What It Is NOT

- ❌ **Ye data validate nahi kar raha** — ye sirf URL se value nikal raha hai. Body se aane wale data ke liye Pydantic chahiye (1.2).
- ❌ **Ye data save nahi kar raha** — har request pe naya response, koi storage nahi. Iske liye SQLite (1.4).
- ❌ **Ye list nahi filter kar raha database se** — abhi to memory me hardcoded list hai. Real filtering DB query hogi.
- ❌ **Ye nested/optional complex structures nahi** — nested models ke liye Pydantic ke nested models padhenge (1.2).

## Agle Step Mein Kya Hoga?

Ab tum jaante ho URL se **single values** kaise aati hain. Par DukaanOS ka asli use case ye hai — jab koi naya **stock add** karna chahta hai, ya **settings update** karna chahta hai, to wo data **path me nahi, body me** aata hai. URL sirf bolta hai *"kahan"* — data kya hai, wo body se aata hai, aur usko validate karna Pydantic ka kaam hai.

**Agla: 1.2 Pydantic + Request Body** — data bhejne aur validate karne ka sahi tareeka.
