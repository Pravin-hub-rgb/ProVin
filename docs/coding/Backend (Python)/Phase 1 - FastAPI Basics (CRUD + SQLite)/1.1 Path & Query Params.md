Let's start. First core tool — **Path and Query parameters**. This is FastAPI's simplest and most used feature.

Think you have to run your **DukaanOS** — it's a grocery store POS system. A customer comes to the counter and stands in line for a bill. Now think of some scenarios:

---

## Think (Something to Think About)

At DukaanOS's counter, these kinds of requests come every day:

1. *"Bhai show me RELIANCE's price."* — **one specific stock** needed.
2. *"Show me top 20 stocks from IT sector."* — **a group, and a limit** needed.
3. *"Show only stocks whose RSI is less than 30."* — **a filter** needed.

What's the difference between these three? The first has **one thing's name** (RELIANCE). The second has **filter + limit** (sector=IT, up to 20). The third has **one condition** (RSI < 30).

The server needs to get this information somehow — **through the URL**. And that's exactly FastAPI's job — extracting data from the URL and passing it to your function.

---

## Manual Method (painful way)

If FastAPI didn't exist, what would you do? The server gets a URL string — like `http://localhost:8000/api/stocks/RELIANCE?sector=IT&limit=20`. Now you'd have to parse it manually.

In Python you'd do this (old `cgi` module approach, or splitting strings yourself):

```python
# Manual (never do this)
from urllib.parse import urlparse, parse_qs
parsed = urlparse(request.url)
path_parts = parsed.path.split("/")   # ['', 'api', 'stocks', 'RELIANCE']
query = parse_qs(parsed.query)          # {'sector': ['IT'], 'limit': ['20']}

symbol = path_parts[3]                  # RELIANCE
sector = query.get("sector")            # ['IT']  (it's a list!)
limit = int(query.get("limit")[0])      # 20
```

Think about the pain here:

- `path_parts[3]` — **magic number**. If the route structure changes tomorrow, your index 3 becomes wrong. You won't even know — you'll just get wrong data.
- `query.get("sector")` — **it's a list** (`['IT']`), not a string. You'd have to write `[0]` every time.
- `limit` — it's a string `"20"`, you'd have to convert it. And if the user sends `?limit=abc` it will **crash** — because `int("abc")` gives an error, and the user won't get a proper message.
- No type checking anywhere.

FastAPI's **path and query parameters** eliminate all these problems.

---

## Concept: Path Parameter

A **path parameter** is a value written directly in the URL's **path** that identifies your resource.

In FastAPI, mark it with `{ }`:

```python
@app.get("/api/stocks/{symbol}")
def get_stock(symbol: str):
    return {"symbol": symbol}
```

Now when someone sends `GET /api/stocks/RELIANCE`, FastAPI:
1. Sees the URL — there's a `{symbol}` placeholder in the path
2. Extracts `RELIANCE`
3. **Automatically** calls the function with `symbol="RELIANCE"`
4. Treats `symbol` as **automatic string type** (because `symbol: str` was written)

You don't need to `split("/")`, you don't need `[0]`, no magic number. Just look at the function signature and you know what you'll get.

---

## Concept: Query Parameter

A **query parameter** is an extra filter that comes **after `?`** in the URL's path. It's not the resource's identity — it's **what you want to see**.

```python
@app.get("/api/stocks")
def list_stocks(limit: int = 20, sector: str | None = None):
    # limit and sector come from the browser
    return {"limit": limit, "sector": sector}
```

Now if you send `GET /api/stocks?limit=10&sector=IT`, FastAPI passes `limit=10, sector="IT"` to the function.

**Two things to keep in mind:**

1. **Default value** — `limit: int = 20`. If the user doesn't send `?limit=`, 20 will be used. If there's no default, FastAPI will error ("field required") — and a simple list page breaks. Keeping a default is **robust**.

2. **Optional query** — `sector: str | None = None`. `|` means "or". If the user doesn't provide sector, `None` comes, and your code needs to handle it. `|` is Python's "union" operator (Python 3.10+). Older `Optional[str]` is also correct — both mean the same thing.

**FastAPI changes types automatically.** If the user sends `?limit=abc`, FastAPI gives a **422 error** automatically — *"limit must be an integer"* — before `int("abc")` crashes. This doesn't happen in the manual method.

---

## Concept: Path + Query Together

In reality you need both. Think of DukaanOS — *"Show me RELIANCE's data, and also its last 30 days of history."*

```python
@app.get("/api/stocks/{symbol}")
def get_stock(symbol: str, days: int = 30):
    return {"symbol": symbol, "days": days}
```

- `GET /api/stocks/RELIANCE` → `symbol="RELIANCE", days=30`
- `GET /api/stocks/RELIANCE?days=90` → `symbol="RELIANCE", days=90`

Path for **which stock** (identity), query for **what you want** (options). These two being separate is the core rule of path vs query.

## Code: A Complete Example

Let's write a small endpoint that feels like real TradeStack:

```python
from fastapi import FastAPI

app = FastAPI(title="Trading Backend Basic")


# Only path parameter — one stock
@app.get("/api/stocks/{symbol}")
def get_stock(symbol: str):
    # symbol type is already string, no conversion needed
    return {
        "symbol": symbol,
        "name": "Reliance Industries",
        "last_price": 1420.50,
    }


# Only query parameters — list + filter
@app.get("/api/stocks")
def list_stocks(limit: int = 20, sector: str | None = None):
    stocks = [
        {"symbol": "RELIANCE", "sector": "Oil"},
        {"symbol": "TCS", "sector": "IT"},
        {"symbol": "INFY", "sector": "IT"},
        {"symbol": "HDFCBANK", "sector": "Banking"},
    ]

    # Apply filter if sector given
    if sector:
        stocks = [s for s in stocks if s["sector"].lower() == sector.lower()]

    # Apply limit
    return {"count": len(stocks[:limit]), "stocks": stocks[:limit]}


# Path + Query both — specific stock, specific days
@app.get("/api/stocks/{symbol}/history")
def get_history(symbol: str, days: int = 30, interval: str = "1d"):
    return {
        "symbol": symbol,
        "days": days,
        "interval": interval,
        "candles": days,  # fake data for now
    }
```

**What's new vs the manual method?**

- No `split("/")`
- No `parse_qs`
- No magic number
- No `int()` conversion — FastAPI did it
- No `if` validation — FastAPI did it

Only **business logic** remains — filter, limit, data. That's your work. The rest is the framework's.

## Nutshell

- **Path param** `{symbol}` — which resource (RELIANCE). Resource identity.
- **Query param** `?limit=10` — what you want (filter, limit). Options.
- FastAPI **parses, converts, and validates both** automatically — you don't need to split strings, do `int()`, or write `if` statements.
- Type hint (`symbol: str`, `limit: int = 20`) tells FastAPI what to convert — and a default value makes it robust.

---

## Common Mistakes

1. **Mixing up path and query.** If `{symbol}` is in the path, it's a **path** param. If you need `sector`, send `?sector=IT`, not in the path. `/api/stocks/{symbol}/{sector}` is wrong — sector is a filter, not identity.

2. **Not giving a default value.** `def list_stocks(limit: int)` — now `GET /api/stocks` without `?limit=` will error. Always give a default when the field is optional.

3. **Forgetting `Optional` vs `|`.** Don't write `sector: str` if sector is optional — otherwise even someone sending `"IT"` will get an error because `str` is required. `sector: str | None = None` is correct.

4. **Converting types yourself.** `limit: int = 20` — don't do `int(limit)` inside the function. It's already int. Double conversion = redundant.

5. **Sending `days` as a query vs path.** `/stocks/RELIANCE?days=90` is correct. `/stocks/RELIANCE/90` is wrong — it becomes a **different resource** like "RELIANCE's 90-day version". Numbers are options, not identity (unless they're part of resource identity).

## What It Is NOT

- ❌ **Not validating data** — it's just extracting values from the URL. For body data you need Pydantic (1.2).
- ❌ **Not saving data** — new response every request, no storage. For that you need SQLite (1.4).
- ❌ **Not filtering from database** — right now it's just a hardcoded list in memory. Real filtering will be a DB query.
- ❌ **Not handling nested/optional complex structures** — for nested models you'll learn Pydantic nested models (1.2).
