Ye phase ka sabse important lecture. Ab tak humne CRUD banaya — par data **memory me** tha. Aaj wo **permanent** ban jayega.

Par pehle ek zaroori baat samajh lo. Ye lecture sirf "database kaise lagana hai" nahi hai. Ye lecture tumhare **interview** ka ek core topic hai — "data kahan store karte ho, kyun, aur kya problem solve karta hai."

## Sochо (Sochne Wala Scene)

Tu 3 din se DukaanOS ka data dikha raha hai. Roz 10 items add kiye, sab kaam kar raha hai. Par raat ko server **restart** ho gaya — Next.js me jo bhi crash ho gaya.

Ab subah uthke `/api/stocks` kholta hai — **empty**. 30 items gayab. Kyun? Kyunki `stocks: dict[int, Stock] = {}` — ye **RAM** me ek temporary variable hai. Jaise notepad ka unsaved document — band karo, gaya.

**Iske do option hain:**

**Option 1 — Notepad se bachana.** Har add ko ek `.txt` file me likh de. Par 10,000 items ho gaye to? Har read pe file padhna slow. Har write pe file kholna, likhna, band karna — dard. Aur ek hi time pe do jagah likhna ho to corruption.

**Option 2 — Database use karo.** SQLite ek aisi **library** hai jo Python ke andar hai, aur ye kaam karti hai: data ek **file** me safe rehta hai, queries **fast** hain, aur do programs ek hi file pe safely kaam kar sakte hain.

**SQLite Option 2 hai — aur wahi TradeStack aur DukaanOS dono use karte hain.** Kyun? Kyunki sqlite3 **Python ke saath aata hai** (koi install nahi karna), aur ek simple `.db` **file** hai jo disk pe rehti hai. No server, no setup. Chhote se medium project ke liye perfect.

## Manual Tareeka (dard wala)

SQLite ke bina "database" banane ki koshish karte hain — matlab **JSON file**. Ye actually ek real tareeka hai (Next.js me bhi hoti hai), aur dekhna zaroori hai ki ye kahan tak ja sakta hai aur kahan **tod-ta** hai.

```python
# Manual JSON file "database"
import json
from pathlib import Path

DB_FILE = Path("data/stocks.json")

def load_all():
    if not DB_FILE.exists():
        return []
    return json.loads(DB_FILE.read_text())

def save_all(stocks):
    DB_FILE.parent.mkdir(exparents=True, exist_ok=True)
    DB_FILE.write_text(json.dumps(stocks, indent=2))

# Create
stocks = load_all()
stocks.append({"id": 1, "symbol": "RELIANCE"})
save_all(stocks)          # har baar poori file rewrite!

# Read — filter Python me
stocks = load_all()
it_sector = [s for s in stocks if s["sector"] == "IT"]

# Update — dhoondho, badlo, poora file likho
for s in stocks:
    if s["id"] == 1:
        s["last_price"] = 1450
save_all(stocks)          # phir se poori file!
```

Ye **chhote project me chalta hai.** Par jaise hi data bada hota hai, ye **toot-na** shuru hota hai:

**Dard 1 — Har write pe poori file rewrite.** Ek item add = 2000 items ka file dobara likhna. 2000 items = slow ho jayega.

**Dard 2 — Filter database me nahi, Python me.** `sector == "IT"` ke liye database ko chhod ke **saare 2000 items Python me load** karo, phir filter karo. Real me tu na chahe to DB me hi filter kar — ye bahut slow ho jaata hai.

**Dard 3 — Concurrency (2 programs ek saath).** Agar **do** request ek saath aayein (browser me double-click, ya do tabs), to dono `load_all()` → `save_all()` karein → ek dusre ka data **overwrite** kar de. File corrupt. Database isko **transactions** se handle karta hai.

**Dard 4 — Structure adhoora.** Koi enforce nahi ki `sector` string hai. Koi guarantee nahi ki `id` unique hai. Database me **schema** hota hai — types define, unique enforce, relations validate.

**Isiliye database.** Ab samajhte hain **kaise**.

## Concept: SQLite Kya Hai (Simple Bhasha Me)

SQLite ek **library** hai — Python ka built-in module `sqlite3`. Iska kaam hai: **structured data ko ek file me rakhna**, aur usse **safely, fast, reliably** padhna-likhna.

**File-based** — ek hi `.db` file. Server nahi, install nahi, config nahi. Jaise ek Excel file, bas smart.

**Ye PostgreSQL/MySQL se chhota hai.** Wo dono me ek **server** chalta hai aur database alag service hoti hai. SQLite me sab kuch ek file me. Isliye:
- Chhote projects, personal tools, offline apps, mobile → **SQLite**
- Bade production systems, multiple servers → **PostgreSQL/MySQL**

**TradeStack kyun SQLite?** Kyunki wo ek **personal trading tool** hai, ek user, local machine. Server chala kar koi faayda nahi jab data ek file me aa jaata hai aur fast bhi hai.

---

## Concept: Table Kya Hai

Database me data **tables** me rehta hai — jaise Excel sheet. Table ke rows = records, columns = fields.

```sql
CREATE TABLE stocks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    symbol TEXT NOT NULL,
    name TEXT NOT NULL,
    sector TEXT,
    last_price REAL,
    active INTEGER DEFAULT 1
);
```

**Har column ka type hai.** Ye important hai — Excel me koi bhi cell me kuch bhi daal sakte ho, database me **nahi**. `symbol TEXT NOT NULL` ka matlab — ye text hai, aur ye kabhi khaali nahi hoga.

**`PRIMARY KEY AUTOINCREMENT`** — `id` har naye row ke liye **automatically** 1, 2, 3, 4... badhega. Tumhe khud ID sochne ki zaroorat nahi.

Ye sab SQL hai. **SQL** = Structured Query Language — database se baat karne ki language. SQLite me SQL chalti hai. Har database (Postgres, MySQL) me bhi SQL hoti hai — bas thodi alag dialect.

---

## Concept: Python se SQLite (sqlite3 Module)

Tum SQL directly `sqlite3` se likhoge. 3 cheezein har query ke liye hoti hain:

1. **Connect** — file se jodo
2. **Cursor** — ek helper jo query chalata hai
3. **Execute + commit** — query chalao, changes pakke

```python
import sqlite3
from pathlib import Path

DB_PATH = Path(__file__).parent / "data" / "stocks.db"

def get_conn():
    conn = sqlite3.connect(DB_PATH)
    return conn

# CREATE
conn = get_conn()
cursor = conn.cursor()
cursor.execute("""
    CREATE TABLE IF NOT EXISTS stocks (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        symbol TEXT NOT NULL,
        name TEXT NOT NULL,
        sector TEXT,
        last_price REAL,
        active INTEGER DEFAULT 1
    )
""")
conn.commit()      # ZAROORI — bina commit ke changes save nahi honge
conn.close()
```

**`conn.commit()` ka matlab — "jo kiya, usse pakka kar de."** Bina commit ke changes memory me hi rehte hain, file me nahi likhte. Ye ek baar bhool gaye to data gayab — ye concept baad me 1.5.3 ke project me clearly aayega.

## Concept: CRUD in SQL (har method ka SQL)

CRUD ke har method ka ek SQL query hota hai. Ye table yaad karlo — interview me bhi kaam aata hai:

| Operation | SQL | Matlab |
|---|---|---|
| **Create** | `INSERT` | Naya row daal |
| **Read** | `SELECT` | Data lao |
| **Update** | `UPDATE` | Row badal |
| **Delete** | `DELETE` | Row hata |

**Yehi 4 kaafi hain** database ke liye. Baaki sab — filter, join, count — ye 4 ka extension hai.

```python
# CREATE
cursor.execute(
    "INSERT INTO stocks (symbol, name, sector, last_price) VALUES (?, ?, ?, ?)",
    ("RELIANCE", "Reliance Industries", "Oil", 1420.50)
)
conn.commit()

# READ (sabhi)
cursor.execute("SELECT * FROM stocks")
rows = cursor.fetchall()      # sab rows lao

# READ (ek)
cursor.execute("SELECT * FROM stocks WHERE symbol = ?", ("RELIANCE",))
row = cursor.fetchone()       # ek hi row

# READ (filter + limit)
cursor.execute("SELECT * FROM stocks WHERE sector = ? LIMIT ?", ("IT", 20))
rows = cursor.fetchall()

# UPDATE
cursor.execute(
    "UPDATE stocks SET last_price = ? WHERE id = ?",
    (1450.0, 1)
)
conn.commit()

# DELETE
cursor.execute("DELETE FROM stocks WHERE id = ?", (1,))
conn.commit()
```

## Concept: `?` Placeholders (Ye Bahut Important Hai)

Dekh upar har query me **`?`** hai. Ye **placeholder** hai. Values ke liye `?` likho, aur actual value **tuple** me `execute()` ko do.

**Ye kyu zaroori hai?** SQL injection se protection. Ye samajhna **bahut zaroori** hai interview me bhi.

**Galat tareeka (dangerous):**
```python
symbol = "RELIANCE'; DROP TABLE stocks; --"   # malicious input
cursor.execute(f"SELECT * FROM stocks WHERE symbol = '{symbol}'")
# KYA HUA? Ye SQL ban gaya: SELECT * FROM stocks WHERE symbol = 'RELIANCE'; DROP TABLE stocks; --'
# POORI TABLE KHATAM! 😱
```

**Sahi tareeka (safe):**
```python
cursor.execute("SELECT * FROM stocks WHERE symbol = ?", (symbol,))
# `?` ko value bhar di — aur wo value SQL ki tarah interpret NAHI hoti.
# Malicious string bas ek string hi rahegi, command nahi banegi.
```

Ye Python me `sqlite3` ka security feature hai. Interview me koi poochhe *"SQL injection kaise rokte ho?"* — jawab: **parameterized queries, `?` placeholders, kabhi f-string se SQL mat likho.**

## Concept: Rows Ko Dict Mein Lena

Ek cheez dhyan dena. `cursor.fetchall()` se jo milta hai wo **tuples** hote hain — `(1, "RELIANCE", "Reliance Industries", "Oil", 1420.50)`. Ye FastAPI ke JSON response me nahi ja sakta directly — kyunki tuples JSON nahi hote.

Isliye hum **dict** me convert karte hain — taaki FastAPI use Pydantic model me convert kar sake:

```python
import sqlite3

def row_to_dict(cursor, row):
    """Row ko dict banao — column names ke saath."""
    return dict(zip([col[0] for col in cursor.description], row))

# Use
cursor.execute("SELECT * FROM stocks WHERE id = ?", (1,))
row = cursor.fetchone()
if row:
    stock = row_to_dict(cursor, row)
    # stock = {"id": 1, "symbol": "RELIANCE", "name": "...", ...}
```

`cursor.description` batata hai ki columns kaunse hain. `dict(zip(names, values))` unhe jod ke ek clean dict bana deta hai. **Yehi pattern real TradeStack me bhi hai** — wahan bhi SQLite se rows aati hain aur dict me convert hoti hain.

## Code: Complete Example (CRUD + SQLite)

Ab 1.3 ka wahi stocks API — par ab **database** ke saath. Same endpoints, sirf storage badla:

```python
import sqlite3
from pathlib import Path
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI(title="Trading Backend Basic")

DB_PATH = Path(__file__).parent / "data" / "stocks.db"
DB_PATH.parent.mkdir(parents=True, exist_ok=True)


def get_conn():
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row     # <-- rows dict-like milenge
    return conn


def init_db():
    conn = get_conn()
    conn.execute("""
        CREATE TABLE IF NOT EXISTS stocks (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            symbol TEXT NOT NULL UNIQUE,
            name TEXT NOT NULL,
            sector TEXT,
            last_price REAL,
            active INTEGER DEFAULT 1
        )
    """)
    conn.commit()
    conn.close()


init_db()


# --- Models (1.2 se) ---

class StockCreate(BaseModel):
    symbol: str
    name: str
    sector: str | None = None
    last_price: float

class StockUpdate(BaseModel):
    name: str | None = None
    sector: str | None = None
    last_price: float | None = None

class Stock(StockCreate):
    id: int
    active: bool = True


# --- CREATE ---

@app.post("/api/stocks", response_model=Stock, status_code=201)
def create_stock(data: StockCreate):
    conn = get_conn()
    try:
        cursor = conn.execute(
            "INSERT INTO stocks (symbol, name, sector, last_price) VALUES (?, ?, ?, ?)",
            (data.symbol, data.name, data.sector, data.last_price)
        )
        conn.commit()
        new_id = cursor.lastrowid
        row = conn.execute("SELECT * FROM stocks WHERE id = ?", (new_id,)).fetchone()
        return dict(row)
    except sqlite3.IntegrityError:
        raise HTTPException(status_code=409, detail="Symbol already exists")
    finally:
        conn.close()


# --- READ single ---

@app.get("/api/stocks/{stock_id}", response_model=Stock)
def get_stock(stock_id: int):
    conn = get_conn()
    row = conn.execute("SELECT * FROM stocks WHERE id = ?", (stock_id,)).fetchone()
    conn.close()
    if not row:
        raise HTTPException(status_code=404, detail="Stock not found")
    return dict(row)


# --- READ list (filter + limit) ---

@app.get("/api/stocks", response_model=list[Stock])
def list_stocks(limit: int = 20, sector: str | None = None, active_only: bool = False):
    conn = get_conn()
    query = "SELECT * FROM stocks WHERE 1=1"
    params = []
    if sector:
        query += " AND sector = ?"
        params.append(sector)
    if active_only:
        query += " AND active = 1"
    query += " LIMIT ?"
    params.append(limit)
    rows = conn.execute(query, params).fetchall()
    conn.close()
    return [dict(r) for r in rows]


# --- UPDATE ---

@app.put("/api/stocks/{stock_id}", response_model=Stock)
def update_stock(stock_id: int, data: StockUpdate):
    conn = get_conn()
    existing = conn.execute("SELECT * FROM stocks WHERE id = ?", (stock_id,)).fetchone()
    if not existing:
        conn.close()
        raise HTTPException(status_code=404, detail="Stock not found")

    fields = data.model_dump(exclude_none=True)
    if fields:
        set_clause = ", ".join(f"{k} = ?" for k in fields)
        values = list(fields.values()) + [stock_id]
        conn.execute(f"UPDATE stocks SET {set_clause} WHERE id = ?", values)
        conn.commit()

    row = conn.execute("SELECT * FROM stocks WHERE id = ?", (stock_id,)).fetchone()
    conn.close()
    return dict(row)


# --- DELETE ---

@app.delete("/api/stocks/{stock_id}", status_code=204)
def delete_stock(stock_id: int):
    conn = get_conn()
    cursor = conn.execute("DELETE FROM stocks WHERE id = ?", (stock_id,))
    conn.commit()
    deleted = cursor.rowcount
    conn.close()
    if deleted == 0:
        raise HTTPException(status_code=404, detail="Stock not found")
```

**Teen naye concepts isme:**

1. **`sqlite3.Row`** — `conn.row_factory = sqlite3.Row` set karne se rows aise milte hain jisme `row["symbol"]` likh sakte ho (dict jaisa). Isse `dict(row)` se clean JSON ban jaata hai.

2. **`WHERE 1=1`** — ye thoda weird lagta hai, par smart hai. Filter conditions dheere dheere `AND sector = ?` jodte ho. `WHERE 1=1 AND sector = ? AND ...` — starting point ban gaya. Bina iske har filter me `AND` ya `OR` ka logic sochna padta.

3. **`conn.close()` har baar** — connection band karna zaroori hai. Har request pe naya connection, use ke baad band.

## Test: Kaise Verify Karein (Browser Se + Restart Test)

Server chalao `/docs`. Wahi sequence — Create, Read, Update, Delete.

**Par is baar ek EXTRA test hai jo pehle possible nahi tha — yehi SQLite ka sabse bada faayda hai:**

1. **Data add karo:** 2-3 items `POST` karo (`/api/stocks`).
2. **VERIFY restart:** Server **band** karo (`Ctrl+C`), phir `uvicorn` se dobara chalao. `GET /api/stocks` kholo — **data abhi bhi hai!** 🎉

Pehle (memory dict me) ye data **gayab** hota. Ab database me hai — restart safe.

3. **UNIQUE test:** Ek hi symbol dobara add karo (`RELIANCE` phir se). Ab **409 Conflict** aayega — kyunki `symbol TEXT NOT NULL UNIQUE` set tha. (Pehle dobara add ho jaata tha, duplicate ban jaata.) Ye real constraint ka proof hai — database ne khud reject kiya.

4. **DELETE + 404:** Koi item delete karo, phir `GET` karo — **404** aayega.

5. **Browser me dekhna:** Chrome me `sqlitebrowser.org` download karke ya VS Code ke "SQLite Viewer" extension se `data/stocks.db` kholo — table dekh lena. Data wahi dikhega jo API se aaya. **Yehi hota hai database me data — memory me nahi.**

## Nutshell

- **SQLite** = Python ka built-in module `sqlite3`, ek file me data. No server, no install. TradeStack aur DukaanOS dono ye use karte hain.
- **Table** = structure (columns + types), **row** = ek record. `PRIMARY KEY AUTOINCREMENT` = ID khud badhega.
- **CRUD = 4 SQL commands**: `INSERT` (create), `SELECT` (read), `UPDATE`, `DELETE`.
- **`?` placeholders** = SQL injection se protection. Kabhi f-string se SQL mat likho.
- **`conn.commit()`** = changes pakke karo. **`conn.close()`** = connection band karo.

---

## Common Mistakes

1. **`conn.commit()` bhoolna.** Data query to chalega, par **save nahi hoga**. Server restart = sab gayab. Ye sabse common galti hai.

2. **f-string se SQL banana.** `f"...WHERE symbol = '{symbol}'"` — **SQL injection ka khaali**. Hamesha `?` placeholder aur tuple use karo.

3. **`conn.close()` na karna.** Har endpoint me finally block me connection close karo, warna **connection leak** hoga — file handle khule rahenge, performance giregi.

4. **`PRIMARY KEY` na lagana.** Bina iske duplicate IDs ban sakte hain, aur update/delete galat row pe lag sakta hai. Ye foundation hai.

5. **`row_factory` set na karna.** Default tuples milte hain. JSON response banana mushkil. `sqlite3.Row` set karo, `dict(row)` use karo.

6. **`active` INTEGER vs boolean confuse karna.** SQLite me booleans nahi hote — `True`/`False` ki jagah `1`/`0` store hota hai. Pydantic wapas boolean bana dega.

7. **Table banane se pehle `CREATE TABLE` na dekhna.** `CREATE TABLE IF NOT EXISTS` use karo — warna har server restart pe "table already exists" error aayega.

## In Your Own Words

<details>
<summary>1. SQLite kyun use karte hain? PostgreSQL se kya alag hai?</summary>

SQLite **file-based** database hai — ek hi `.db` file me data, koi server nahi, Python ke saath built-in aata hai (koi install nahi karna). Ye chhote projects aur personal tools ke liye perfect hai — TradeStack aur DukaanOS dono aise hi single-user/local tools hain. PostgreSQL MySQL me ek alag **server** chalta hai jo database host karta hai — zaroori jab multiple servers/apps ek hi database ko access karein (production scale). Simple rule: **chhota/local project = SQLite, bada/multi-user production = PostgreSQL.**

</details>

<details>
<summary>2. `?` placeholder kyun zaroori hai? F-string se SQL likhna kyu galat hai?</summary>

`?` placeholder SQL injection se **bachata hai**. Kyunki SQL aur values ko alag rakh deta hai — value ko kabhi SQL code ki tarah interpret nahi karta. F-string se likhne me agar user ne `'; DROP TABLE stocks; --` bheja, to wo poora SQL statement ban jata hai aur table delete ho jata hai. `?` use karne se wo dangerous string bas ek **normal text value** rehti hai, command nahi banti. Simple rule: **SQL me kabhi bhi user data f-string/string-concatenation se mat daalo, hamesha `?` aur parameterized query use karo.**

</details>

<details>
<summary>3. `conn.commit()` kyun zaroori hai? Iske bina kya hoga?</summary>

SQLite me jab bhi tum data **badalte** ho (INSERT/UPDATE/DELETE), wo change pehle memory me pending rehta hai. `conn.commit()` se wo pakka hoke disk pe file me likh diya jaata hai. **Bina commit ke** data sirf us connection ke dauran dikhega, par **server restart ya program band karne pe gayab** ho jayega (kuch versions me connection close karne pe bhi rollback ho jaata hai). Isliye har write operation ke baad `conn.commit()` likhna zaroori hai.

</details>

<details>
<summary>4. `WHERE 1=1` ka kya faayda hai? Ye weird kyun lagta hai?</summary>

`WHERE 1=1` shuru me ek **dummy condition** hai jo hamesha true hoti hai. Iska faayda ye hai ki jab tum filters add karte ho (jaise sector, active_only), tum har baar `AND ...` jod sakte ho bina soche ki pehle condition ka kya hoga. `WHERE 1=1 AND sector = ? AND active = 1` — ye hamesha sahi structure banata hai, chahe ek filter ho ya das. Ye pattern optional conditions wale dynamic queries me bahut common hai.

</details>

<details>
<summary>5. Tuples nahi aate dict kaise? `sqlite3.Row` ka kya kaam hai?</summary>

Default me `sqlite3` rows ko **tuples** me deta hai — `(1, "RELIANCE", ...)`. Ye JSON me convert nahi hote, isliye FastAPI response nahi bana sakta. `conn.row_factory = sqlite3.Row` set karne se rows **dict-like** ho jaate hain jahan `row["symbol"]` likh sakte ho. Phir `dict(row)` call karke clean JSON ready milta hai, jo Pydantic `response_model` me jaata hai.

</details>

<details>
<summary>6. 409 Conflict kab aata hai? Ye real me kaise test hota hai?</summary>

Tab jab koi constraint violate ho — jaise `symbol TEXT NOT NULL UNIQUE` ho aur user same symbol dobara add kare. Database duplicate ko reject kar deta hai aur FastAPI me `sqlite3.IntegrityError` aata hai, jise tum `except` block me catch karke `HTTPException(409, "Symbol already exists")` bhejte ho. Test karne ke liye ek item add karo, phir **same symbol** ke saath dobara add karo — 409 Conflict aayega. Ye dikhata hai database ne khud data integrity enforce ki, application code nahi karna pada.

</details>

## What It Is NOT

- ❌ **Ye PostgreSQL nahi hai** — SQLite single-user hai. Multi-server production ke liye PostgreSQL chahiye. Abhi single-user/local ke liye perfect.
- ❌ **Ye ORM nahi hai** — raw SQL likh rahe ho. Real me SQLAlchemy use hota hai, par **raw SQL seekhna zaroori** hai — interview me poochte hain aur complex queries me ORM se zyada clear hoti hai.
- ❌ **Ye relationships nahi sikha raha** — foreign keys, joins, one-to-many. Ye Phase 3 me ya real project me. Abhi single table.
- ❌ **Ye migrations nahi hai** — schema change karna abhi manual hai. Real me Alembic jaisa tool chahiye.
- ❌ **Ye async nahi hai** — `sqlite3` sync hai. FastAPI async hai par SQLite ke liye sync theek hai chhote project me. (Async DB ke liye `aiosqlite` hota hai.)
