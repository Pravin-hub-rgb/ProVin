## Step 1: Verify all endpoints work in container

```bash
# 1. Start container (clean start)
docker compose up --build -d
# -d = detached mode (background)

# 2. Health check
curl -s http://localhost:8000/health | python -m json.tool
# Expected: {"status": "ok", "db": "connected"} (or similar)

# 3. Create a stock (seed)
curl -s -X POST http://localhost:8000/api/stocks \
  -H "Content-Type: application/json" \
  -d '{"symbol": "DOCKER", "name": "Docker Test", "sector": "IT"}' | python -m json.tool
# Expected: 201 Created with ID

# 4. Read it back (verify DB works in container)
curl -s http://localhost:8000/api/stocks | python -m json.tool
# Expected: list including DOCKER stock

# 5. Run indicator
curl -s http://localhost:8000/api/indicators/DOCKER | python -m json.tool
# Expected: SMA, RSI values

# 6. Run scan
curl -s "http://localhost:8000/api/scan?min_rsi=0&max_rsi=50" | python -m json.tool
# Expected: scan results matching RSI criteria
```

If everything responds as above → **containerization successful**.

## Step 2: Verify data persistence (the important test)

```bash
# 1. Take container down (data should be on host)
docker compose down

# 2. Check host machine: is DB file in data/ folder?
ls -la data/
# Expected: settings.db (or equivalent SQLite file)

# 3. Start container again
docker compose up -d
# Note: no --build — same image is used

# 4. Is DB back?
curl -s http://localhost:8000/api/stocks | python -m json.tool
# Expected: DOCKER stock still present (data persisted across down/up)
```

If the DOCKER stock comes back → **volume mount is working**. Data is saved outside the container.

## Step 3: What Breaks Inside Container?

Common issues + fixes:

| Problem | Cause | Fix |
|---------|-------|-----|
| `500 Internal Server Error` on POST | DB path `./data/` relative path issue | Verify volume mount path `./data:/app/data` |
| Port `8000` already in use | Host machine has 8000 conflict | `docker compose down` or use `8001:8000` |
| Permission denied on `data/` | Linux file permissions | `chmod -R 777 data/` on host, or fix Docker user |
| `/health` works but `/api/scan` fails | Python package missing in container | Add to `requirements.txt`, rebuild (`--build`) |
| DB file not visible inside container | Volume mount wrong | Double-check `./data:/app/data` |

## Step 4: Bridge to TradeStack

How do we connect Phase 1 mini-project to TradeStack?

### TradeStack folder structure (real):

```
tradestack/
├── backend/               # TradeStack's actual backend
│   ├── server.py           # 930 lines, FastAPI app
│   ├── src/
│   │   ├── db.py
│   │   ├── scanner.py
│   │   ├── indicators/
│   │   └── ...
│   ├── requirements.txt
│   └── Dockerfile          # <-- we'll build this
├── docker-compose.yml      # root level
└── data/
    └── trades.db           # SQLite (WAL mode)
```

### TradeStack Dockerfile (copy from Appendix A + adjust):

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["uvicorn", "server:app", "--host", "0.0.0.0", "--port", "8000"]
```

**Changes from Appendix A:**
- `COPY . .` → `COPY backend .` (context from `backend/` folder)
- `app.main:app` → `server:app` (TradeStack's entry point)

### TradeStack docker-compose.yml:

```yaml
version: "3.8"
services:
  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    container_name: tradestack-backend
    ports:
      - "5000:8000"          # TradeStack port 5000
    volumes:
      - ./data:/app/data      # TradeStack's data/ folder
    restart: unless-stopped
```

### TradeStack's 16 labs comparison:

| Phase 1 mini-project | TradeStack |
|---------------------|------------|
| `app/main.py` | `server.py` |
| `app/db.py` | `backend/src/db.py` |
| `app/scanner.py` | `backend/src/scanner.py` |
| `data/settings.db` | `data/trades.db` |
| Port 8000 | Port 5000 |

**Same pattern.** Learn Docker on the Phase 1 project, then apply directly to TradeStack.
