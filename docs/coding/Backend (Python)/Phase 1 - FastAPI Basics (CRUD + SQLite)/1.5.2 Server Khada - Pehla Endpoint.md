## Step 2: Create Virtual Environment (venv)

This confuses people at first — *"what is venv, why?"* — but learn it, every Python project has it.

Think of your **phone's charger** — libraries one project needs (FastAPI, pandas), another project might not need. Every project needs its own separate charger.

**venv = Python project's personal "charger bag."** Only the libraries this project needs will be installed in it. Other projects won't have those libraries — clean, isolated.

```bash
python -m venv venv
```

This creates a `venv/` folder with Python's **private copy**. Now activate it:

```bash
# Windows:
venv\Scripts\activate

# Mac/Linux:
source venv/bin/activate
```

Now terminal shows `(venv)` at the start — meaning **you're inside that venv.** Now every `pip install` goes only to this project.

**You need to do this every time** you open a new terminal. Forgot? No problem — just activate again.

---

## Step 3: Install Libraries

Now install the libraries you need:

```bash
pip install fastapi uvicorn
```

- **`fastapi`** — this is the framework (routing, validation, docs)
- **`uvicorn`** — this is the **server** that runs the FastAPI app. FastAPI is just a blueprint, uvicorn actually **runs** it. (Like blueprint vs building — uvicorn is the building that makes the blueprint real.)

We don't need pandas or SQLite yet — they come later (1.5.4). For now just these two are enough.

## Step 4: Create First File — `app/main.py`

Now write your first FastAPI app. It has 3 things — creating the app, one route, and one health check:

```python
from fastapi import FastAPI

# Create app — this is your "server blueprint"
app = FastAPI(title="Trading Backend Basic", version="0.1.0")


# First endpoint — health check
@app.get("/health")
def health():
    """
    Is server alive or not.
    This doesn't put any data — just confirms app is running.
    """
    return {"status": "ok", "service": "Trading Backend Basic", "version": "0.1.0"}
```

**Understand line by line:**

- `from fastapi import FastAPI` — import FastAPI class
- `app = FastAPI(...)` — create an app instance. `title` shows name in Swagger, `version` shows version
- `@app.get("/health")` — **decorator**. Say *"when GET request comes to `/health` URL, run the function below."* This is the same decorator you learned in 1.1-1.3
- `def health():` — this function runs on request. Name can be anything
- `return {...}` — whatever dict you return is **automatically JSON** and sent to client

**This is FastAPI's magic** — you wrote `return {"status": "ok"}`, and FastAPI automatically converted it to JSON and sent it. You didn't convert anything.

---

## Step 5: Run the Server

This is the **most important moment**. In terminal (venv activated) run:

```bash
uvicorn app.main:app --reload
```

**What this command means:**
- `uvicorn` — server will run
- `app.main:app` — `app` folder → `main.py` file → `app` variable. **These three are linked by colons**
- `--reload` — **if you change code, server restarts automatically.** This is for development. Production doesn't have `--reload` (security + performance)

**Terminal will show something like:**
```
INFO:     Started reloader process
INFO:     Uvicorn running on http://127.0.0.1:8000
INFO:     Application startup complete.
```

`http://127.0.0.1:8000` — your server is running. `127.0.0.1` means **"this computer itself"** (localhost). Open this URL in browser.

## Step 6: Test — `/docs` (The Most Fun Part)

Go to browser: **`http://127.0.0.1:8000/docs`**

**Wait. Look at what appears.** This is **Swagger UI** — FastAPI's own automatic documentation. You didn't write anything manually, just wrote one function, and FastAPI:

- Made a **list** of all endpoints
- Wrote **what each endpoint does** (from docstring)
- Gave a **"Try it out"** button on each
- Showed **example response** for each

**This is FastAPI's biggest killer feature** — free, automatic documentation.

Now test:
1. Expand `GET /health` → click **"Try it out"** → click **"Execute"**
2. Below you'll see **Response**: `200` and `{"status":"ok","service":"Trading Backend Basic","version":"0.1.0"}`
3. Status code **200** = everything fine (learned in 1.3)

**Celebrate this moment.** You've set up an **API server**. This is the base where tables and endpoints will come in 1.5.3.

## Extra: Sometimes Useful — `/health`'s Role

Right now `/health` is just proof. But **in real life** it's very useful. Interview asks *"why create health endpoint?"*

**Answer:** *"It's used to check after deployment — load balancer or hosting platform (Vercel, Railway, AWS) checks server status every few seconds. If `/health` returns 200, server is fine; otherwise it stops sending traffic or assumes crash. DukaanOS and TradeStack both have this endpoint."*

This one line makes a very good impression because it shows **deployment awareness** — not just code, real-world understanding.

## Common Mistakes

1. **Writing `uvicorn app.main:app` wrong.** Format is exact: `module.path:variable`. `app.main:app` is correct. `app/app.py:app` is wrong. Or `main:app` is also wrong (because file is in `app/` folder, so module path is `app.main`).

2. **Not activating venv.** `pip install` goes global and you get `uvicorn: command not found`. Terminal should show `(venv)` at the start.

3. **Forgetting `--reload`.** You'll change code and server stays old — you'll be confused why "my change isn't showing?" Always keep `--reload` in development.

4. **Port busy.** If something else is running on port `8000`, you'll get an error. Solution: `uvicorn app.main:app --reload --port 8001`.

5. **Browser `localhost:8000/docs` not opening.** Server is off or `/docs` path is wrong. Check if terminal shows errors. And remember `/docs` — root `/` won't show anything now (we didn't create root route).

6. **`return` with string vs dict.** `return "ok"` also works (becomes JSON string), but `return {"status": "ok"}` is better because it's structured data. Dict is standard for health check.

## Nutshell

- **venv** = project's isolated environment. Create with `python -m venv venv`, activate, then remember to activate every new terminal.
- **`pip install fastapi uvicorn`** — FastAPI (framework) + uvicorn (server that runs it).
- **`app = FastAPI()`** — create app. `@app.get("/health")` — define route. `return {}` — FastAPI makes JSON automatically.
- **`uvicorn app.main:app --reload`** — run server. `--reload` = auto-restart on code change.
- **`/docs`** = free, automatic Swagger documentation. Test with "Try it out" without frontend.

## In Your Own Words

<details>
<summary>1. Why is venv necessary? What problem happens without it?</summary>

Every Python project needs different libraries. One project needs pandas, another needs a different version. venv gives each project an **isolated Python environment** — whatever you `pip install` goes only to that project, not system-wide or other projects. Without it, libraries mix together, version conflicts happen, and one project can break another. venv = each project's own separate "toolbox".

</details>

<details>
<summary>2. What does each part of `uvicorn app.main:app --reload` mean?</summary>

`uvicorn` = the server that actually **runs** the FastAPI app (FastAPI is just the blueprint). `app.main:app` = module path (`app` folder → `main.py`) and the variable in that file (`app`) — linked by colons. `--reload` = development mode, server auto-restarts when code changes. Production doesn't have `--reload` because it hits performance and is a security risk.

</details>

<details>
<summary>3. What is `/docs` and how does it appear without writing it?</summary>

`/docs` = **Swagger UI** — FastAPI's automatic interactive documentation. It's built into FastAPI. When you define a route `@app.get("/health")`, FastAPI automatically documents it — function name, docstring (in `"""..."""`), and example response. You don't need to write docs manually. Each endpoint gets a "Try it out" button so you can test from browser without any frontend.

</details>

<details>
<summary>4. How does `return {"status": "ok"}` become JSON?</summary>

FastAPI automatically converts every route function's **return value to JSON** and sends it with `Content-Type: application/json` header. You don't need to call `json.dumps()` or anything manually. Just return a normal Python dict/list — FastAPI handles the rest. This is the biggest difference between FastAPI and Flask (Flask requires manual `jsonify()`).

</details>

<details>
<summary>5. Who uses the health endpoint in real life? How to explain in interview?</summary>

In real life, health endpoint is used to **check server after deployment**. Hosting platforms (Vercel, Railway, AWS, Docker) and load balancers hit `/health` every few seconds — if it returns 200, server is considered healthy; otherwise they stop sending traffic or restart the server. In interview say: *"I've added a `/health` endpoint to every service I build which checks if the server is alive — this helps the deployment platform know if the server is ready, and monitoring tools also use it."*

</details>
