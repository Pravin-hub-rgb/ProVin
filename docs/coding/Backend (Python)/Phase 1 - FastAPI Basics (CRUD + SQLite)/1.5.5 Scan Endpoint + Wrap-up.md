## Step 1: Pydantic Models — `app/models.py` Update

Pehle scan ka response shape define karo. `app/models.py` me add karo:

```python
class ScanResult(BaseModel):
    """Ek stock ka scan result."""
    symbol: str
    name: str
    last_close: float
    sma: float
    rsi: float
    trend: str


class ScanResponse(BaseModel):
    """Poore scan ka wrapper — metadata ke saath."""
    generated_at: str
    scanned: int          # kitne stocks scan hue
    matched: int          # kitne match hue (filter ke baad)
    criteria: str         # kya filter lagaya
    results: list[ScanResult]
```

**`ScanResult` har stock ka shape hai. `ScanResponse` poore scan ka.**

**Ye Pydantic kyun?** Kyunki bina iske FastAPI sirf raw JSON return karta — koi guarantee nahi ki har result me `rsi` field hai. `response_model=ScanResponse` lagao to:
- FastAPI **check** karta hai har result sahi shape ka hai (agar bug ho to error milega, chup-chap galat data nahi jayega)
- `/docs` me **exact schema** dikhta hai
- `results` ki jagah galat field likhoge to **422** milega development me hi

Yehi 1.2 ka asli fayda hai — **data ka contract.**

## Step 2: Scanner Logic — `app/indicators.py` Me Ya Naya `app/scanner.py`

Real TradeStack me ye alag file hai (`src/scanner.py`). Same rakhte hain — naya file `app/scanner.py`:

```python
"""
Scanner — saari stocks scan karke filter karta hai.
Ye TradeStack ke src/scanner.py ka simple version hai.
"""
from .db import get_conn
from .indicators import get_price_series, calculate_sma, calculate_rsi


def scan_market(
    min_rsi: float = 30.0,
    max_rsi: float = 70.0,
    sma_period: int = 20,
    price_limit: int = 20,
) -> list[dict]:
    """
    Saari stocks scan karo, RSI range ke andar wala return karo.

    min_rsi=30, max_rsi=70 -> oversold + overbought dono.
    Sirf oversold chahiye? max_rsi=100 kar do.
    """
    conn = get_conn()
    results = []
    errors = 0

    try:
        # Saare active symbols lao
        symbols = conn.execute(
            "SELECT symbol, name FROM stocks WHERE active = 1"
        ).fetchall()

        for row in symbols:
            symbol, name = row["symbol"], row["name"]
            try:
                prices = get_price_series(conn, symbol, limit=60)

                # Kam data hai to skip (error count badhao)
                if len(prices) < sma_period:
                    errors += 1
                    continue

                sma = calculate_sma(prices, sma_period)
                rsi = calculate_rsi(prices, period=14)
                last_close = float(prices.iloc[-1])

                # Filter: RSI range me aana chahiye
                if min_rsi <= rsi <= max_rsi:
                    results.append({
                        "symbol": symbol,
                        "name": name,
                        "last_close": round(last_close, 2),
                        "sma": round(sma, 2),
                        "rsi": round(rsi, 2),
                        "trend": "bullish" if last_close > sma else "bearish",
                    })

            except Exception as e:
                # EK stock fail hua to baki scan kare
                errors += 1
                continue

    finally:
        conn.close()

    # Sorting — sabse zyada oversold pehle
    results.sort(key=lambda r: r["rsi"])

    return results[:price_limit]
```

**Do important cheezein isme:**

**1. `try/except` per stock.** Dekho — bahar `try/finally` hai (connection close), aur **har stock ka apna `try/except`** hai. Matlab agar ek stock ke prices missing hain ya koi error aaya, **sirf wo skip** hota hai — baaki 1999 stocks **phir bhi scan hote hain**. Ye production-ready soch hai. Bina iske ek bad stock poori scan rok degi.

**2. `results.sort(key=lambda r: r["rsi"])`** — phir se sort kiya, taaki sabse zyada oversold pehle aaye. Scanner me ye zaroori hai — top opportunities pehle dikhein.

**`lambda r: r["rsi"]`** — lambda ek chhoti anonymous function hai jo har result ka `rsi` nikaalti hai. `sort` usko comparison ke liye use karta hai. Ye Python ka ek common pattern hai.

## Step 3: Endpoint — `app/main.py` Me

Ab endpoint add karo — `/api/scan`:

```python
from datetime import datetime
from .models import ScanResponse
from .scanner import scan_market

# ... (pehle wala code)

@app.get("/api/scan", response_model=ScanResponse)
def scan(
    min_rsi: float = 30.0,
    max_rsi: float = 70.0,
    sma_period: int = 20,
    price_limit: int = 20
):
    """
    Market scan — RSI criteria ke hisaab se stocks filter karo.

    Query params (1.1 se):
    - min_rsi: kam se kam RSI (default 30)
    - max_rsi: zyada se zyada RSI (default 70)
    - sma_period: SMA window (default 20)
    - price_limit: kitne results chahiye (default 20)
    """
    # Validation — parameters sensible hain ya nahi
    if min_rsi >= max_rsi:
        raise HTTPException(status_code=400, detail="min_rsi must be less than max_rsi")
    if not (0 <= min_rsi <= 100 and 0 <= max_rsi <= 100):
        raise HTTPException(status_code=400, detail="RSI must be between 0 and 100")
    if sma_period < 5 or price_limit < 1:
        raise HTTPException(status_code=400, detail="Invalid period or limit")

    results = scan_market(
        min_rsi=min_rsi,
        max_rsi=max_rsi,
        sma_period=sma_period,
        price_limit=price_limit,
    )

    return {
        "generated_at": datetime.now().isoformat(),
        "scanned": len(results),
        "matched": len(results),
        "criteria": f"RSI {min_rsi}-{max_rsi}",
        "results": results,
    }
```

**`response_model=ScanResponse`** (1.2 se) — FastAPI check karega ki response sahi shape ka hai.

**Validation ab bhi hai** — `min_rsi >= max_rsi` check. Ye **application-level validation** hai (1.2 ke Pydantic se alag). Pydantic **types** check karta hai (number hai ya nahi), par **business logic** (RSI 0-100 me hona chahiye) application ko khud check karna padta.

## Common Mistakes

1. **`response_model=ScanResponse` na lagana.** Bina iske FastAPI raw dict return karta hai, koi guarantee nahi shape ki. Typed model lagao.

2. **Scan me `try/except` bahar na rakhna.** Agar poora scan ek `try` me hai aur beech me ek stock fail ho to **poora scan marr jayega**. Per-stock `try/except` zaroori hai.

3. **Validation skip karna.** `min_rsi=80&max_rsi=20` pe code crash ho sakta hai bina check ke. Basic validation (jaise `min_rsi >= max_rsi`) application-level hai — Pydantic se alag.

4. **Sorting bhoolna.** Bina sort ke results random order me aayenge. Scanner me **priority order** (sabse oversold pehle) important hai.

5. **`limit` pe slice na karna.** 2000 stocks scan ho sakte hain, response me sab bhejna heavy hai. `price_limit` se slice karo.

6. **README mat likhna.** Chhota sa likh do — interview me dikhta hai aur tujhe yaad rahega.
