## Step 1: Pydantic Models — Update `app/models.py`

First define scan's response shape. Add to `app/models.py`:

```python
class ScanResult(BaseModel):
    """One stock's scan result."""
    symbol: str
    name: str
    last_close: float
    sma: float
    rsi: float
    trend: str


class ScanResponse(BaseModel):
    """Whole scan wrapper — with metadata."""
    generated_at: str
    scanned: int          # how many stocks were scanned
    matched: int          # how many matched (after filter)
    criteria: str         # what filter was applied
    results: list[ScanResult]
```

**`ScanResult` is each stock's shape. `ScanResponse` is the whole scan.**

**Why Pydantic?** Because without it FastAPI returns raw JSON — no guarantee every result has `rsi` field. Add `response_model=ScanResponse`:
- FastAPI **checks** every result has the right shape (if there's a bug, you get an error instead of silently sending wrong data)
- `/docs` shows **exact schema**
- If you put a wrong field in place of `results`, you get **422** during development itself

That's the real benefit of 1.2 — **data's contract.**

## Step 2: Scanner Logic — Add to `app/indicators.py` or New `app/scanner.py`

Real TradeStack has this as a separate file (`src/scanner.py`). Let's keep the same — create new file `app/scanner.py`:

```python
"""
Scanner — scans all stocks and filters them.
This is a simple version of TradeStack's src/scanner.py.
"""
from .db import get_conn
from .indicators import get_price_series, calculate_sma, calculate_rsi


def scan_market(
    min_rsi: float = 30.0,
    max_rsi: float = 70.0,
    sma_period: int = 20,
    price_limit: int = 20,
) -> list[dict]:
    """
    Scan all stocks, return those within RSI range.

    min_rsi=30, max_rsi=70 -> both oversold and overbought.
    Only oversold needed? Set max_rsi=100.
    """
    conn = get_conn()
    results = []
    errors = 0

    try:
        # Get all active symbols
        symbols = conn.execute(
            "SELECT symbol, name FROM stocks WHERE active = 1"
        ).fetchall()

        for row in symbols:
            symbol, name = row["symbol"], row["name"]
            try:
                prices = get_price_series(conn, symbol, limit=60)

                # Not enough data? Skip and count error
                if len(prices) < sma_period:
                    errors += 1
                    continue

                sma = calculate_sma(prices, sma_period)
                rsi = calculate_rsi(prices, period=14)
                last_close = float(prices.iloc[-1])

                # Filter: RSI must be in range
                if min_rsi <= rsi <= max_rsi:
                    results.append({
                        "symbol": symbol,
                        "name": name,
                        "last_close": round(last_close, 2),
                        "sma": round(sma, 2),
                        "rsi": round(rsi, 2),
                        "trend": "bullish" if last_close > sma else "bearish",
                    })

            except Exception as e:
                # ONE stock failed — others still scan
                errors += 1
                continue

    finally:
        conn.close()

    # Sorting — most oversold first
    results.sort(key=lambda r: r["rsi"])

    return results[:price_limit]
```

**Two important things here:**

**1. `try/except` per stock.** Notice — outer `try/finally` (for connection close), and **each stock has its own `try/except`**. That means if one stock has missing prices or an error, **only that stock is skipped** — the other 1999 stocks **still get scanned**. That's production-ready thinking. Without it, one bad stock would stop the whole scan.

**2. `results.sort(key=lambda r: r["rsi"])`** — sorted so the most oversold stocks come first. Important in scanners — top opportunities show first.

**`lambda r: r["rsi"]`** — lambda is a small anonymous function that extracts each result's `rsi`. `sort` uses it for comparison. This is a common Python pattern.

## Step 3: Endpoint — Add to `app/main.py`

Now add the endpoint — `/api/scan`:

```python
from datetime import datetime
from .models import ScanResponse
from .scanner import scan_market

# ... (previous code)


@app.get("/api/scan", response_model=ScanResponse)
def scan(
    min_rsi: float = 30.0,
    max_rsi: float = 70.0,
    sma_period: int = 20,
    price_limit: int = 20
):
    """
    Market scan — filter stocks based on RSI criteria.

    Query params (from 1.1):
    - min_rsi: minimum RSI (default 30)
    - max_rsi: maximum RSI (default 70)
    - sma_period: SMA window (default 20)
    - price_limit: how many results (default 20)
    """
    # Validate parameters are sensible
    if min_rsi >= max_rsi:
        raise HTTPException(status_code=400, detail="min_rsi must be less than max_rsi")
    if not (0 <= min_rsi <= 100 and 0 <= max_rsi <= 100):
        raise HTTPException(status_code=400, detail="RSI must be between 0 and 100")
    if sma_period < 5 or price_limit < 1:
        raise HTTPException(status_code=400, detail="Invalid period or limit")

    results = scan_market(
        min_rsi=min_rsi,
        max_rsi=max_rsi,
        sma_period=sma_period,
        price_limit=price_limit,
    )

    return {
        "generated_at": datetime.now().isoformat(),
        "scanned": len(results),
        "matched": len(results),
        "criteria": f"RSI {min_rsi}-{max_rsi}",
        "results": results,
    }
```

**`response_model=ScanResponse`** (from 1.2) — FastAPI checks that the response has the right shape.

**Validation is still there** — `min_rsi >= max_rsi` check. This is **application-level validation** (different from 1.2's Pydantic). Pydantic checks **types** (is it a number or not), but **business rules** (RSI must be 0-100) must be checked by the application itself.

## Common Mistakes

1. **Not adding `response_model=ScanResponse`.** Without it FastAPI returns raw dict — no shape guarantee. Add typed model.

2. **Not wrapping scan in `try/except` per stock.** If the whole scan is in one `try` and one stock fails midway, **the whole scan dies**. Per-stock `try/except` is essential.

3. **Skipping validation.** Without checks, `min_rsi=80&max_rsi=20` could crash the code. Basic validation (like `min_rsi >= max_rsi`) is application-level — different from Pydantic.

4. **Forgetting sorting.** Without sorting, results come in random order. **Priority order** (most oversold first) is important in scanners.

5. **Not slicing with `limit`.** 2000 stocks could be scanned, but sending all in response is heavy. Slice with `price_limit`.

6. **Not writing README.** Write even a small one — it shows in interviews and helps you remember.
