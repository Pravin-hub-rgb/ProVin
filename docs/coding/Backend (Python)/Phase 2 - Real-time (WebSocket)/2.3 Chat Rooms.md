In 2.2, you built a ConnectionManager that tracks every connected WebSocket in one flat dictionary and broadcasts to everyone. That works for a single global chat. But a real chat app has **rooms** — #general, #trading, #random. A message in #trading should not leak into #general.

That's what this file adds: **rooms**. Each room is its own group of connections with its own message history.

# 2.3 Chat Rooms — Multiple Rooms, Join/Leave, Message History

## Think — A Hotel with Many Rooms

Imagine a hotel. The lobby has a front desk (the server). Guests (clients) arrive and ask for a room. The front desk gives them a key (room_id) and points them to that room. Inside the room, only the guests in that room hear each other. If someone leaves, the others notice. And if a new guest arrives late, the front desk can hand them a **notebook of recent messages** so they catch up.

That's a chat room system: room management (who's in which room), join/leave announcements, message history (last N messages), and broadcasting only to people in the same room.

## Concept — Room Management

The core idea: instead of one flat `dict[connection_id -> WebSocket]`, you have a **two-level structure**:

```
rooms: dict[room_id -> list[WebSocket]]
history: dict[room_id -> deque of last N messages]
```

- `rooms` answers "who is in room X?"
- `history` answers "what was said recently in room X?"

When a client connects, it picks a room (via the URL path `/ws/{room_id}`). You add its WebSocket to that room's list. When it disconnects, you remove it. When a message arrives, you broadcast to only that room's list.

## Code — RoomManager

```python
# room_manager.py
from fastapi import WebSocket
from collections import deque
from typing import Dict, List

class RoomManager:
    def __init__(self, history_size: int = 20):
        # room_id -> list of connected WebSockets
        self.rooms: Dict[str, List[WebSocket]] = {}
        # room_id -> last N messages (deque auto-drops oldest)
        self.history: Dict[str, deque] = {}
        self.history_size = history_size

    async def connect(self, websocket: WebSocket, room_id: str):
        # Complete the handshake
        await websocket.accept()

        # Create room if it doesn't exist yet
        if room_id not in self.rooms:
            self.rooms[room_id] = []
            self.history[room_id] = deque(maxlen=self.history_size)

        # Add this connection to the room
        self.rooms[room_id].append(websocket)

        # Catch-up: send last N messages to the new arrival
        for old_msg in self.history[room_id]:
            await websocket.send_text(old_msg)

        # Announce join to everyone in the room
        await self.broadcast(room_id, f"[system] a user joined {room_id}")

    def disconnect(self, websocket: WebSocket, room_id: str):
        # Remove from room list; keep room + history even if empty
        if room_id in self.rooms and websocket in self.rooms[room_id]:
            self.rooms[room_id].remove(websocket)

    async def broadcast(self, room_id: str, message: str):
        # Store message in history first (so late joiners see it)
        if room_id in self.history:
            self.history[room_id].append(message)

        # Send only to connections in THIS room
        dead: List[WebSocket] = []
        for ws in list(self.rooms.get(room_id, [])):
            try:
                await ws.send_text(message)
            except Exception:
                dead.append(ws)

        # Clean up dead connections
        for ws in dead:
            if ws in self.rooms.get(room_id, []):
                self.rooms[room_id].remove(ws)
```

Each part:
- `__init__` — two dictionaries: `rooms` (who's connected) and `history` (what was said). `deque(maxlen=N)` automatically drops the oldest message when it exceeds N.
- `connect()` — accepts handshake, creates room on first join, appends connection, replays history, announces join.
- `disconnect()` — removes the WebSocket from the room list. We keep the room and its history so a later joiner can still see past messages.
- `broadcast()` — stores the message in history, then sends only to that room's connections. Dead connections are collected and removed (handles dropped clients).

## Concept — Join/Leave Messages

A chat feels alive when you see "X joined" and "X left". The RoomManager already announces joins in `connect()`. For leaves, the endpoint's `except` block announces it:

```python
# In the endpoint:
except WebSocketDisconnect:
    manager.disconnect(websocket, room_id)
    await manager.broadcast(room_id, f"[system] a user left {room_id}")
```

These system messages also go into history, so a late joiner sees the join/leave trail too. If you don't want system messages in history, move the `history.append` call to only store user messages — but for a simple chat, storing everything is fine.

## Concept — Message History (Last N per Room)

Why history? Two reasons:
1. A user who joins late shouldn't see an empty screen — they should see the last few messages.
2. On reconnect (network blip), the client can re-request or just rejoin and get history again.

We use `collections.deque(maxlen=history_size)`. When you append beyond `maxlen`, the oldest item is automatically removed. No manual slicing, no memory leak. Each room has its own deque, so #general and #trading keep separate histories.

Tuning `history_size`: 20 is fine for a chat. For a trading feed you might want more (or persist to DB). For a notification bell, 5–10 is plenty.

## Concept — Broadcasting to a Specific Room Only

The key difference from 2.2: `broadcast(room_id, message)` only iterates `self.rooms[room_id]`. A message sent to #trading never touches #general's connections. This is what makes rooms useful.

If you accidentally broadcast to `self.rooms` (the whole dict) instead of `self.rooms[room_id]`, you've recreated 2.2's global chat. Always scope the loop to one room.

## The FastAPI Endpoint

```python
# main.py
import json
from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from room_manager import RoomManager

app = FastAPI()
manager = RoomManager(history_size=20)

@app.websocket("/ws/{room_id}")
async def room_endpoint(websocket: WebSocket, room_id: str):
    # room_id comes from the URL path: /ws/general, /ws/trading, etc.
    await manager.connect(websocket, room_id)
    try:
        while True:
            raw = await websocket.receive_text()

            # Accept either plain text or JSON {"user": "Vin", "text": "hi"}
            try:
                payload = json.loads(raw)
                user = payload.get("user", "anon")
                text = payload.get("text", raw)
            except json.JSONDecodeError:
                user = "anon"
                text = raw

            message = f"{user}: {text}"
            await manager.broadcast(room_id, message)
    except WebSocketDisconnect:
        manager.disconnect(websocket, room_id)
        await manager.broadcast(room_id, f"[system] a user left {room_id}")
```

Each line:
- `@app.websocket("/ws/{room_id}")` — the `{room_id}` path param becomes the room name. `/ws/general` and `/ws/trading` are different rooms.
- `manager.connect(...)` — handshake + join + history replay + join announcement.
- `while True` — keep listening.
- `json.loads(raw)` — try to parse as JSON for structured messages; fall back to plain text.
- `manager.broadcast(room_id, message)` — sends only to that room.
- `except WebSocketDisconnect` — client closed; clean up and announce leave.

## A Tiny Browser Client (for testing)

Save as `client.html` and open in two tabs with different room URLs:

```html
<!DOCTYPE html>
<html>
<body>
  <h3 id="title"></h3>
  <div id="log" style="height:300px;overflow:auto;border:1px solid #ccc;padding:8px;"></div>
  <input id="user" placeholder="your name" />
  <input id="msg" placeholder="message" />
  <button onclick="send()">Send</button>
  <script>
    const room = new URLSearchParams(location.search).get("room") || "general";
    document.getElementById("title").textContent = "Room: " + room;
    const ws = new WebSocket(`ws://localhost:8000/ws/${room}`);
    ws.onmessage = (e) => {
      const div = document.createElement("div");
      div.textContent = e.data;
      document.getElementById("log").appendChild(div);
    };
    function send() {
      const u = document.getElementById("user").value || "anon";
      const t = document.getElementById("msg").value;
      ws.send(JSON.stringify({ user: u, text: t }));
      document.getElementById("msg").value = "";
    }
  </script>
</body>
</html>
```

Test: open `client.html?room=general` in tab A and tab B, and `client.html?room=trading` in tab C. A message from A appears in B but not C. That's room isolation working.

## What It Is NOT

- ❌ **Not persistent** — history lives in memory (deque). Server restart = all history gone. For real persistence, write messages to SQLite/Postgres and load on join.
- ❌ **Not authenticated** — anyone can join any room by URL. No identity check, no permission. Add auth (JWT in query param or first message) for real apps.
- ❌ **Not scaled** — all rooms in one process. With multiple server instances, you need Redis pub/sub to broadcast across machines.
- ❌ **Not ordered across reconnects** — if a client reconnects, it re-joins and gets history, but messages sent while disconnected are lost (unless persisted).

## Nutshell

**Chat rooms = two dicts: room_id -> list[WebSocket] (who's in) and room_id -> deque (last N messages). connect() joins + replays history + announces. broadcast(room_id) sends only to that room. disconnect() cleans up.**

## Common Mistakes

- ❌ **"Broadcast to all rooms"** — looping over `self.rooms` instead of `self.rooms[room_id]` sends every message to everyone. Scope the loop to one room.
- ❌ **"History stored globally"** — one shared deque for all rooms mixes messages. Each room needs its own deque.
- ❌ **"Forgetting to replay history on join"** — new joiner sees empty screen. Replay `self.history[room_id]` in `connect()`.
- ❌ **"Not handling dead connections in broadcast"** — a dropped client stays in the list and `send_text` throws every broadcast. Collect dead sockets and remove them.
- ❌ **"Removing the room when empty"** — if you `del self.rooms[room_id]`, you also lose history. Keep the room (and its deque) even when empty, unless you explicitly want to reset history.

## In Your Own Words

1. How does RoomManager differ from the ConnectionManager in 2.2?

<details>
<summary>Sample Answer</summary>

**Answer:** ConnectionManager had one flat dict (connection_id -> WebSocket) and broadcast to everyone. RoomManager has two dicts keyed by room_id: room_id -> list[WebSocket] (members) and room_id -> deque (history). broadcast() is scoped to one room, and connect() replays that room's history to the new joiner.

</details>

2. Why use `deque(maxlen=N)` for message history instead of a plain list?

<details>
<summary>Sample Answer</summary>

**Answer:** `deque(maxlen=N)` automatically drops the oldest message when it exceeds N, so memory stays bounded without manual slicing. A plain list would grow forever (memory leak) unless you manually trim with `del history[:len-N]`.

</details>

3. A user joins #trading 5 minutes late. How do they see earlier messages?

<details>
<summary>Sample Answer</summary>

**Answer:** In `connect()`, after adding the WebSocket to the room, we loop over `self.history[room_id]` and `send_text` each stored message to just that WebSocket. The deque holds the last N messages, so the late joiner catches up.

</details>

4. What happens if you broadcast to `self.rooms` instead of `self.rooms[room_id]`?

<details>
<summary>Sample Answer</summary>

**Answer:** Every message goes to every connection in every room — you've recreated the global chat from 2.2 and room isolation is broken. Always scope the send loop to the single target room.

</details>

5. Why keep an empty room (and its history) instead of deleting it when the last user leaves?

<details>
<summary>Sample Answer</summary>

**Answer:** So a future joiner can still see the room's message history. If you delete the room and its deque, history is lost. Only delete if you want a fresh start (e.g., daily reset). Otherwise keep it.

</details>
