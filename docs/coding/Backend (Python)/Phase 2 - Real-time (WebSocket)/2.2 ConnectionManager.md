In 2.1, you learned what WebSocket is — a persistent two-way connection. Now the question is: how do you track who's connected? If 5 people open the chat, you need to know who they are and be able to send messages to all of them.

That's what **ConnectionManager** does. It's the simplest pattern in the world — a dictionary that maps connection IDs to WebSocket objects.

# 2.2 ConnectionManager — Tracking Who's Connected

## Think — Coat Check at a Restaurant

Imagine a restaurant with a coat check. When you walk in, you hand over your coat and get a ticket (your ID). The coat check person writes down: "Ticket #42 → Vin's coat." When you leave, you give your ticket, they find your coat, and remove the entry.

ConnectionManager is the same thing. When a client connects, you store their WebSocket object with an ID. When they disconnect, you remove it. When you want to broadcast a message, you go through all stored connections and send to each one.

## Concept — ConnectionManager Pattern

```python
from fastapi import WebSocket
from typing import List

class ConnectionManager:
    def __init__(self):
        # Dictionary: connection_id -> WebSocket object
        self.active_connections: dict[str, WebSocket] = {}

    async def connect(self, websocket: WebSocket, connection_id: str):
        await websocket.accept()
        self.active_connections[connection_id] = websocket

    def disconnect(self, connection_id: str):
        if connection_id in self.active_connections:
            del self.active_connections[connection_id]

    async def send_personal(self, message: str, connection_id: str):
        if connection_id in self.active_connections:
            await self.active_connections[connection_id].send_text(message)

    async def broadcast(self, message: str):
        for connection_id, websocket in self.active_connections.items():
            await websocket.send_text(message)
```

Each method:
- `connect()` — accept the WebSocket handshake and store the connection
- `disconnect()` — remove the connection from the dictionary
- `send_personal()` — send a message to one specific connection
- `broadcast()` — send a message to ALL connections

## The FastAPI Endpoint

```python
from fastapi import FastAPI, WebSocket
from uuid import uuid4

app = FastAPI()
manager = ConnectionManager()

@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    # Generate a unique ID for this connection
    connection_id = str(uuid4())
    
    # Connect and store
    await manager.connect(websocket, connection_id)
    
    try:
        while True:
            # Wait for a message from this client
            data = await websocket.receive_text()
            # Broadcast to everyone (including sender)
            await manager.broadcast(f"User {connection_id[:8]}: {data}")
    except Exception:
        # Client disconnected (closed browser, network drop, etc.)
        manager.disconnect(connection_id)
```

Each line:
- `uuid4()` — generates a unique ID for each connection (so we can track who's who)
- `manager.connect()` — accepts handshake and stores in dictionary
- `while True` — keeps listening for messages
- `manager.broadcast()` — sends to all connected clients
- `except Exception` — handles disconnection (browser closed, network dropped)

## What ConnectionManager Is NOT

- ❌ **Not a database** — connections are in memory, lost on restart
- ❌ **Not authentication** — anyone can connect, no identity verification
- ❌ **Not scalable** — all connections in one process, one machine

## Nutshell

**ConnectionManager = dictionary of connection_id → WebSocket. connect() stores, disconnect() removes, broadcast() sends to all. The foundation of any real-time multi-user app.**

## Common Mistakes

- ❌ **"broadcast() is automatic"** — no, you must loop through connections and send manually
- ❌ **"disconnect() is called automatically"** — no, you must call it in the except block
- ❌ **"uuid4() is the only way to identify"** — no, you can use usernames, tokens, or any unique identifier

## In Your Own Words

1. What does ConnectionManager store and why?

<details>
<summary>Sample Answer</summary>

**Answer:** It stores a dictionary mapping connection_id → WebSocket object. This lets you track who's connected, send messages to specific users (send_personal), or broadcast to everyone. Without it, you can't distinguish between connections.

</details>

2. Why do we need a `try/except` block around the WebSocket loop?

<details>
<summary>Sample Answer</summary>

**Answer:** Because the client can disconnect at any time (close browser, network drop). When that happens, `receive_text()` throws an exception. The except block catches it and calls `disconnect()` to clean up the dictionary. Without this, disconnected clients stay in the dictionary forever (memory leak).

</details>

3. What's the difference between `send_personal` and `broadcast`?

<details>
<summary>Sample Answer</summary>

**Answer:** `send_personal` sends to one specific connection (by ID). `broadcast` sends to ALL connections. In a chat app, you might use `send_personal` for private messages and `broadcast` for room messages.

</details>
