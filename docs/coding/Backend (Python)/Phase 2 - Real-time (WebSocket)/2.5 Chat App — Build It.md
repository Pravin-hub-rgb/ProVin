## Step 2 — room_manager.py (from 2.3)

```python
# room_manager.py
from fastapi import WebSocket
from collections import deque
from typing import Dict, List

class RoomManager:
    def __init__(self, history_size: int = 30):
        self.rooms: Dict[str, List[WebSocket]] = {}
        self.history: Dict[str, deque] = {}
        self.users: Dict[WebSocket, str] = {}   # websocket -> username
        self.history_size = history_size

    async def connect(self, websocket: WebSocket, room_id: str, username: str):
        await websocket.accept()

        if room_id not in self.rooms:
            self.rooms[room_id] = []
            self.history[room_id] = deque(maxlen=self.history_size)

        self.rooms[room_id].append(websocket)
        self.users[websocket] = username

        # Catch-up history
        for old in self.history[room_id]:
            await websocket.send_text(old)

        await self.broadcast(room_id, f"[system] {username} joined {room_id}")

    def disconnect(self, websocket: WebSocket, room_id: str):
        if room_id in self.rooms and websocket in self.rooms[room_id]:
            self.rooms[room_id].remove(websocket)
        name = self.users.pop(websocket, "anon")
        return name

    async def broadcast(self, room_id: str, message: str):
        if room_id in self.history:
            self.history[room_id].append(message)

        dead: List[WebSocket] = []
        for ws in list(self.rooms.get(room_id, [])):
            try:
                await ws.send_text(message)
            except Exception:
                dead.append(ws)
        for ws in dead:
            if ws in self.rooms.get(room_id, []):
                self.rooms[room_id].remove(ws)
            self.users.pop(ws, None)

    def room_users(self, room_id: str) -> List[str]:
        return [self.users[ws] for ws in self.rooms.get(room_id, [])]

    def room_list(self) -> List[str]:
        return list(self.rooms.keys())
```

New vs 2.3: a `users` dict (websocket -> username) so we can show "who's online" and announce names. `room_users()` and `room_list()` feed REST endpoints.

## Step 3 — main.py

```python
# main.py
import json
from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from fastapi.responses import FileResponse
from room_manager import RoomManager

app = FastAPI(title="Chat App")
manager = RoomManager(history_size=30)

@app.get("/")
async def index():
    return FileResponse("static/index.html")

@app.get("/api/rooms")
async def list_rooms():
    return {"rooms": manager.room_list()}

@app.websocket("/ws/{room_id}")
async def room_endpoint(websocket: WebSocket, room_id: str):
    # Username comes as query param: /ws/general?user=Vin
    username = websocket.query_params.get("user", "anon")
    await manager.connect(websocket, room_id, username)
    try:
        while True:
            raw = await websocket.receive_text()
            try:
                payload = json.loads(raw)
                text = payload.get("text", raw)
            except json.JSONDecodeError:
                text = raw

            message = f"{username}: {text}"
            await manager.broadcast(room_id, message)
    except WebSocketDisconnect:
        name = manager.disconnect(websocket, room_id)
        await manager.broadcast(room_id, f"[system] {name} left {room_id}")

if __name__ == "__main__":
    import uvicorn
    uvicorn.run("main:app", host="0.0.0.0", port=8000, reload=True)
```

Each part:
- `GET /` serves the HTML client.
- `GET /api/rooms` lists active rooms (useful for a room picker).
- `/ws/{room_id}?user=Vin` — room from path, username from query param. Clean separation.
- On disconnect, announce with the real username (returned by `disconnect`).

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8" />
  <title>Chat App</title>
  <style>
    body { font-family: sans-serif; max-width: 720px; margin: 20px auto; }

    input { padding: 6px; }
    button { padding: 6px 12px; }
  </style>
</head>
<body>
  <h2>Chat App</h2>
  <div>
    <input id="user" placeholder="your name" value="anon" />
    <input id="room" placeholder="room" value="general" />
    <button onclick="connect()">Connect</button>
    <button onclick="disconnect()">Disconnect</button>
  </div>
  <div id="log"></div>
  <div style="margin-top:8px;">
    <input id="msg" placeholder="message" style="width:80%;" />
    <button onclick="send()">Send</button>
  </div>

  <script>
    let ws = null;
    const log = document.getElementById("log");

    function append(text, sys=false) {
      const div = document.createElement("div");
      div.textContent = text;
      if (sys || text.startsWith("[system]")) div.className = "sys";
      log.appendChild(div);
      log.scrollTop = log.scrollHeight;
    }

    function connect() {
      const user = document.getElementById("user").value || "anon";
      const room = document.getElementById("room").value || "general";
      ws = new WebSocket(`ws://localhost:8000/ws/${room}?user=${encodeURIComponent(user)}`);
      ws.onopen = () => append(`[system] connected to ${room}`, true);
      ws.onmessage = (e) => append(e.data);
      ws.onclose = () => append("[system] disconnected", true);
      ws.onerror = () => append("[system] error", true);
    }

    function disconnect() { if (ws) ws.close(); }

    function send() {
      const input = document.getElementById("msg");
      if (!ws || ws.readyState !== 1) { append("[system] not connected", true); return; }
      ws.send(JSON.stringify({ text: input.value }));
      input.value = "";
    }

    document.getElementById("msg").addEventListener("keydown", (e) => {
      if (e.key === "Enter") send();
    });
  </script>
</body>
</html>
```

## What You Just Built (Recap)

| Feature | Where it lives |
|---------|----------------|
| WebSocket handshake + loop | `main.py` endpoint |
| Connection tracking | `RoomManager.rooms` |
| Room isolation | `broadcast(room_id)` scopes to one room |
| Message history (last 30) | `deque(maxlen=30)` per room |
| Join/leave announcements | `connect()` / `disconnect()` |
| Usernames | query param `?user=` + `users` dict |
| Browser UI | `static/index.html` |
| Room listing | `GET /api/rooms` |

## What It Is NOT

- ❌ **Not production-ready** — no auth, no persistence, no rate limiting, no reconnect logic on the client.
- ❌ **Not scalable** — one process, in-memory state. For multi-instance, add Redis pub/sub.
- ❌ **Not secure** — usernames are self-declared (anyone can claim "admin"). Real apps verify identity (JWT) before `connect()`.
- ❌ **Not persistent** — restart wipes all history. Add SQLite/Postgres writes in `broadcast()` for real persistence.
- ❌ **Not a replacement for REST** — `/api/rooms` is still HTTP. Use WebSocket only for the live stream.

## Nutshell

**Full chat app = RoomManager (rooms + history + users) + FastAPI WebSocket endpoint + browser client. Assembly of 2.1–2.3, no new concepts. The same pattern powers trading streams (2.4) with symbol instead of room_id.**

## Common Mistakes

- ❌ **"Username from client is trusted"** — self-declared names are fine for demos, dangerous for real apps. Verify server-side.
- ❌ **"No reconnect on client"** — a dropped connection stays dropped. Add `onclose` reconnect with backoff for real UX.
- ❌ **"Blocking the event loop"** — don't do heavy work (DB queries, ML) inside the WebSocket loop without `await` or background tasks.
- ❌ **"One global manager vs per-room"** — one manager with room dicts is simpler than many managers. Keep it centralized.
- ❌ **"Forgetting CORS for browser clients"** — if your frontend is on a different origin, add `CORSMiddleware`. Same-origin (served by FastAPI) avoids this.

## In Your Own Words

1. Walk through what happens when Tab A sends "hi" in room "general" while Tab B is in "trading".

<details>
<summary>Sample Answer</summary>

**Answer:** Tab A's message hits `/ws/general`, `broadcast("general", "Vin: hi")` stores it in `history["general"]` and sends to every WebSocket in `rooms["general"]` (Tab A and any other general members). Tab B is in `rooms["trading"]`, so it never receives it. Room isolation holds.

</details>

2. How would you add persistence so history survives a server restart?

<details>
<summary>Sample Answer</summary>

**Answer:** In `broadcast()`, also `INSERT` the message into a SQLite/Postgres table keyed by room_id. In `connect()`, load the last N rows for that room_id instead of (or in addition to) the in-memory deque. Keep the deque as a hot cache.

</details>

3. Why is the username taken from a query param rather than the first WebSocket message?

<details>
<summary>Sample Answer</summary>

**Answer:** Query param is available at connection time, before the loop starts, so `connect()` can announce the name immediately. A first-message approach requires an extra round-trip and a "waiting for identity" state. Either works; query param is simpler for demos.

</details>

4. What breaks if two users pick the same username in the same room?

<details>
<summary>Sample Answer</summary>

**Answer:** Nothing breaks mechanically — messages just show the same name twice. But it's confusing. Real apps enforce unique names (or show a user ID alongside). For this demo, it's acceptable.

</details>

5. How would you adapt this chat app into a live price ticker (like TradeStack)?

<details>
<summary>Sample Answer</summary>

**Answer:** Replace room_id with symbol. Remove client-to-client messaging. Add an upstream task connecting to Upstox that calls `broadcast(symbol, tick)` on each tick. Keep `latest[symbol]` cache so new subscribers get current price. Subscribe/unsubscribe commands replace join/leave.

</details>
