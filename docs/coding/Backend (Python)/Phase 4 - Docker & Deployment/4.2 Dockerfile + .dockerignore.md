## Step 1 â€” Write `.dockerignore`

Create `.dockerignore` in the project root. It works exactly like `.gitignore` â€” Docker skips matching files when copying into the image.

```text
# Python bytecode
__pycache__/
*.py[cod]
*$py.class
*.so

# Virtual environment
venv/
.env
.venv/

# Git
.git/
.gitignore

# Data (SQLite DB is generated at runtime via volume mount)
data/

# Docs (no need to ship docs inside the image)
*.md
!README.md

# IDE / editor
.vscode/
.idea/
*.swp
.DS_Store

# OS
Thumbs.db
```

Why each group matters:
- **`venv/`** â€” without this, your 500MB virtual environment gets copied. Image would be huge and slow.
- **`__pycache__/`** â€” bytecode from your machine's Python; useless (and possibly wrong version) inside the container.
- **`.env`** â€” secrets must never bake into an image. Pass them at runtime.
- **`data/`** â€” SQLite DB is created at runtime and persisted via volume mount (4.3). Don't bake a stale DB into the image.
- **`*.md`** â€” docs don't need to ship. `!README.md` keeps the README as an exception.

## Step 2 â€” Write the `Dockerfile`

Create a file named `Dockerfile` (no extension) in the project root:

```dockerfile
# Base image: Python 3.12 slim (small, security-patched Debian)
FROM python:3.12-slim

# Set working directory inside the image
WORKDIR /app

# Copy requirements.txt FIRST (cache optimization â€” see below)
COPY requirements.txt .

# Install dependencies
RUN pip install --no-cache-dir -r requirements.txt

# Now copy the rest of the app
COPY . .

# Environment variables
ENV PYTHONUNBUFFERED=1
ENV PYTHONDONTWRITEBYTECODE=1

# Document the port the app listens on
EXPOSE 8000

# Command run when the container starts
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## Step 3 â€” Understand Every Line

### `FROM python:3.12-slim`

- Picks the **base image** â€” the starting layer. `python:3.12-slim` is Python 3.12 on a minimal Debian. ~150 MB instead of ~900 MB for the full image.
- **Version match matters:** your Phase 1 code was written for Python 3.12. Use the same here or dependency surprises await.
- `slim` drops docs, tests, and optional packages. Smaller image = faster pulls, smaller attack surface.

### `WORKDIR /app`

- Creates `/app` inside the image and makes it the working directory for all subsequent instructions.
- Without it, `COPY` would land in `/` (root) and your paths would be messy.
- `CMD` and `RUN` execute relative to this directory.

### `COPY requirements.txt .`

- Copies **only** `requirements.txt` into `/app`.
- This single line is the **cache-optimization trick** (see layer caching below). The dot `.` means "current WORKDIR" = `/app`.

### `RUN pip install --no-cache-dir -r requirements.txt`

- `RUN` executes a command at **build time** (not runtime). Here it installs FastAPI, uvicorn, pandas.
- `--no-cache-dir` stops pip from saving downloaded wheels inside the image. Saves ~100MB+.
- This layer is cached as long as `requirements.txt` doesn't change.

### `COPY . .`

- Copies everything else (app/, README, etc.) into `/app`. `.dockerignore` filters out `venv/`, `__pycache__/`, `data/`, etc.
- Comes **after** pip install so code changes don't trigger a reinstall.

### `ENV PYTHONUNBUFFERED=1`

- Makes Python flush stdout/stderr immediately. Without it, `print()` and logs appear late or not at all inside `docker logs`.
- `PYTHONDONTWRITEBYTECODE=1` stops Python from writing `.pyc` files (already ignored, but belt-and-braces).

### `EXPOSE 8000`

- **Documentation only.** Tells readers (and tooling) that this app listens on port 8000.
- It does **not** publish the port. Actual publishing happens via `-p` flag or `ports:` in compose (4.3).

### `CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]`

- The command that runs when a container **starts**. JSON array form (exec form) â€” runs directly without a shell.
- `app.main:app` = the `app` object in `app/main.py` (your FastAPI instance).
- `--host 0.0.0.0` = listen on **all interfaces**. Critical: `127.0.0.1` would bind to container-local only and be unreachable from outside.
- `--port 8000` = port inside the container.

## Layer Caching â€” Why Order Matters

Docker caches each instruction's result as a **layer**. On rebuild, if an instruction and all inputs are unchanged, Docker reuses the cached layer instead of re-running it.

```
Layer 1: FROM python:3.12-slim      (cached forever unless base changes)
Layer 2: WORKDIR /app               (cached)
Layer 3: COPY requirements.txt .    (cached IF requirements.txt unchanged)
Layer 4: RUN pip install ...        (cached IF layer 3 cached)
Layer 5: COPY . .                   (re-runs if ANY file changed)
Layer 6: ENV ...                    (cached)
Layer 7: EXPOSE 8000                (cached)
Layer 8: CMD ...                    (cached)
```

**The bad order** (copy everything first):

```dockerfile
COPY . .                  # any code change invalidates this layer
RUN pip install -r requirements.txt   # re-runs EVERY time code changes â€” slow!
```

**The good order** (ours): copy requirements first, install, then copy code. Now editing `scanner.py` only re-runs `COPY . .` (fast) â€” pip install stays cached. A code change rebuild takes seconds instead of minutes.

Cache invalidation is **cascading**: if layer N changes, layers N+1, N+2... all rebuild. So put slow, stable steps (pip install) early and fast, volatile steps (copy code) late.

## Step 4 â€” Build the Image

From the project root (where `Dockerfile` lives):

```bash
docker build -t trading-backend-basic .
```

- `build` = build an image from a Dockerfile.
- `-t trading-backend-basic` = tag (name) the image. You'll use this name to run it.
- `.` = build context (current directory). Docker sends this folder's files (respecting `.dockerignore`) to the daemon.


- `run` = create + start a container from an image.
- `-p 8000:8000` = publish port: host 8000 â†’ container 8000 (host:container).

## Common Mistakes

1. **`CMD` as a string instead of JSON array** â€” `CMD uvicorn app.main:app ...` runs via shell and breaks signal handling / graceful shutdown. Use `CMD ["uvicorn", ...]`.
2. **`--host 127.0.0.1`** â€” binds to container-local only; external requests fail. Must be `0.0.0.0`.
3. **Copying `venv/`** â€” forgot `.dockerignore`; image bloats to GBs. Always ignore `venv/`.
4. **Baking `data/` into image** â€” stale DB ships with image; volume mount gets shadowed. Ignore `data/`.
5. **Wrong app path in CMD** â€” `app.main:app` assumes `app/main.py` with `app = FastAPI()`. If your module differs, fix the path.
6. **No `--no-cache-dir`** â€” pip cache adds ~100MB of dead weight.
7. **Editing Dockerfile but not rebuilding** â€” `docker run` uses the old image. Rebuild with `docker build` or `docker compose up --build`.

## What It Is NOT

- âŒ **Multi-stage build** â€” single `FROM`. Production images use build stage + slim runtime stage for tiny images.
- âŒ **Non-root user** â€” container runs as root. Production adds `USER appuser`.
- âŒ **Healthcheck** â€” no `HEALTHCHECK` instruction; orchestrators can't auto-detect unhealthy containers.
- âŒ **Secrets in image** â€” never `ENV API_KEY=...` with real values in the Dockerfile.

## Nutshell

- `.dockerignore` skips `venv/`, `data/`, `__pycache__/`, docs, secrets.
- `Dockerfile`: `FROM python:3.12-slim` â†’ `WORKDIR /app` â†’ copy requirements â†’ `RUN pip install` â†’ copy code â†’ `ENV` â†’ `EXPOSE` â†’ `CMD uvicorn ... 0.0.0.0:8000`.
- **Copy requirements before code** for layer-cache speed.
- Build: `docker build -t name .` ; Run: `docker run -p 8000:8000 name`.

## In Your Own Words

1. Why do we copy `requirements.txt` before copying the rest of the code?

<details>
<summary>Sample Answer</summary>

**Answer:** For layer caching. Docker caches each instruction's result. If requirements.txt hasn't changed, the pip install layer is reused and code changes don't trigger a reinstall. Copying code first would invalidate the cache and force pip install on every edit, making builds slow.

</details>

2. What's the difference between `RUN` and `CMD`?

<details>
<summary>Sample Answer</summary>

**Answer:** `RUN` executes at build time (creates a layer in the image, e.g., installing packages). `CMD` specifies the command that runs when a container starts from the image. RUN = build-time; CMD = runtime.

</details>

3. Why must `--host` be `0.0.0.0` and not `127.0.0.1`?

<details>
<summary>Sample Answer</summary>

**Answer:** `127.0.0.1` binds only to the container's own loopback, so requests from outside the container (your browser, host machine) can't reach it. `0.0.0.0` binds to all interfaces, making the app reachable through the published port.

</details>

4. What does `.dockerignore` do and why is it important?

<details>
<summary>Sample Answer</summary>

**Answer:** It tells Docker which files to skip when sending the build context. Without it, `venv/` (500MB+), `__pycache__/`, secrets in `.env`, and stale DB files get copied into the image, bloating it and leaking secrets. It works like `.gitignore`.

</details>

5. What happens if you change one line in `scanner.py` and rebuild?

<details>
<summary>Sample Answer</summary>

**Answer:** Docker reuses cached layers up to `COPY requirements.txt .` and `RUN pip install` (since requirements.txt is unchanged), then re-runs `COPY . .` and everything after. The build is fast because pip install is skipped. Only the final layers rebuild.

</details>
