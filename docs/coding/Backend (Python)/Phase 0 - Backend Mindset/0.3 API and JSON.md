# 0.3 API + JSON — How Data Travels Between Client and Server

## Think — Restaurant Menu Order Form

When you order a dish at a restaurant, the waiter writes it on a **pad** (checklist/slip) in a fixed way:

```
Dish: "Paneer Butter Masala"
Quantity: 2
Extra: "Less spicy"
```

If every restaurant wrote it differently — *"2 paneer medium spicy"* or *"do paneer, less spicy"* — there would be confusion. That's why orders are written in a fixed format. **Server-client also needs a format** — that's called **JSON**.

## Concept — What Is JSON

**JSON (JavaScript Object Notation)** is a format where data is written as **key-value pairs**. All modern APIs (and FastAPI) send data in this format.

JSON example:

```json
{
  "name": "Rahul",
  "age": 27,
  "city": "Mumbai",
  "isActive": true,
  "skills": ["Python", "FastAPI"]
}
```

Notice — `"name": "Rahul"` means key `name` has value `"Rahul"`. Strings in `"..."`, numbers plain, booleans `true/false`, arrays `[...]`. That's the "universal order slip."

## What Is an API

**API (Application Programming Interface)** is a set of rules/URLs by which the client talks to the server (or another program). Remember the restaurant — the menu is what you order from. **API = the menu/door of the server**, through which the client asks for data.

| Thing | Restaurant analogy |
|-------|--------------------|
| **API** | Menu — so you know what you can ask for |
| **Endpoint** | A specific dish (a resource on some URL) |
| **JSON response** | Cooked dish — what the server sends back |

Real example:

```
GET https://api.twitter.com/2/tweets → (JSON) { "tweets": [ ... ] }
```

## Serializing Data to Transmit

The thing to understand here — you can't directly send a Python dict/object as a bitstream. **Python objects are converted to text/string (serialized)** — that conversion is JSON. And when the client opens it (React/Next.js), JSON is **parsed** (deserialized) back into an object.

Graph:

```
Python dict { "name": "Rahul" }
   ↓ (serialize)
JSON string: {"name": "Rahul" }
   ↓ (sent over network)
Client parse → JavaScript object
```

## Nutshell

**JSON = universal text format for data. API = the door (URLs + rules) to ask the server for data.**

## What API Is NOT

- ❌ **API = UI** — API gives data/logic, UI displays it.
- ❌ **JSON = JavaScript-only** — every language can parse it, the name just came from JavaScript.
- ❌ **API is only for backend** — your frontend can also call an API.

## Common Mistakes

- ❌ **"JSON = JavaScript object"** — no. JSON is just a text format. JavaScript object exists in memory; JSON is just a string. They're different things.
- ❌ **"API is just a set of URLs"** — partially true. API is the complete set of URLs + rules (methods, params, auth). Just a URL isn't enough.
- ❌ **"Serialize means compress"** — no. Serialize means converting an object into a text format. Compression is a different thing.

## In Your Own Words

1. Why is JSON used? Tell me 3 basic rules?

<details>
<summary>Sample Answer</summary>

**Answer:** JSON writes data in a text format that every language can parse:
- Key-value pairs `{ "key": "value" }`
- Strings `"..."`, numbers, booleans, arrays
- Nested allowed (object inside object) — creates a flexible tree

</details>

2. What's the difference between API and Endpoint?

<details>
<summary>Sample Answer</summary>

**Answer:** API is the whole system — the complete set of URLs/rules that the client uses. Endpoint is a specific URL/resource inside it (like `/orders`) that gives specific data.

</details>

3. Is JSON only used by JavaScript?

<details>
<summary>Sample Answer</summary>

**Answer:** No. The name came from JavaScript, but JSON is a standard — Python, Java, Node, everyone parses it. FastAPI also returns JSON.

</details>
