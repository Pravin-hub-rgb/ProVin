# 0.5 Setup + First FastAPI App (Hello World)

## Think — First Meal in a New Kitchen

You're opening a new restaurant. First, you need to set up the kitchen workstation, arrange the tools, then practice cooking a simple dish. Similarly, before writing backend code on your machine, you need to set up an **environment**.

## Step 1 — Python Check

First confirm that Python is installed. In terminal/command prompt:

```bash
python --version
# or
python3 --version
```

You'll see something like: `Python 3.12.x`. (FastAPI needs 3.8+)

## Step 2 — Virtual Environment (venv)

**Problem:** All projects shouldn't mix in the same Python (one project needs Flask, another needs FastAPI — packages shouldn't collide). That's why every project gets its own isolated environment.

```bash
# create a folder (make your project folder)
mkdir fastapi-course
cd fastapi-course

# create venv
python -m venv venv
```

This creates a `venv` folder — a project-specific Python copy.

## Step 3 — Activate venv

Linux/Mac:

```bash
source venv/bin/activate
```

Windows:

```powershell
.\venv\Scripts\activate
```

The terminal will now show `(venv)` — meaning you're inside that isolated environment.

## Step 4 — Install FastAPI and "Uvicorn"

FastAPI is a Python framework — and to run it, you also need a **server** (like a database thing). That server is called **uvicorn**:

```bash
pip install fastapi
pip install "uvicorn[standard]"
```

> **FastAPI vs uvicorn:** FastAPI = framework (routes, validation, docs), uvicorn = ASGI server that handles incoming requests and brings them to FastAPI. TradeStack also uses both (`backend/server.py`).

## Step 5 — First App (main.py)

Create a `main.py` file with this code:

```python
from fastapi import FastAPI

# FastAPI app object (this is the whole "server program")
app = FastAPI()

# When a GET request comes to '/', this function runs
@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI!"}
```

Each line:
- `from fastapi import FastAPI` — import FastAPI
- `app = FastAPI()` — create the app
- `@app.get("/")` — decorator: when a GET request comes to `/`
- `def read_root()` — the function that runs
- `return {"message": ...}` — this dict goes as JSON in the response

## Step 6 — Run It

```bash
uvicorn main:app --reload
```

- `main` = filename (`main.py`)
- `app` = variable name (app object)
- `--reload` = auto-restart on code change (for dev)

Open your browser:
- **http://localhost:8000** → `{"message": "Hello, FastAPI!"}`
- **http://localhost:8000/docs** → 🎉 Swagger auto documentation (FastAPI's superpower)

## Nutshell

**FastAPI install + uvicorn server + main.py = first app. `/docs` gives interactive documentation for free — and this is also TradeStack's core.**

## What This Is NOT

- ❌ **venv = Python's second version** — just a package isolation wrapper.
- ❌ **uvicorn = part of FastAPI** — separate server that FastAPI uses.
- ❌ **`--reload` is for production** — only for dev.

## Common Mistakes

- ❌ **"venv isn't needed, just install directly"** — wrong. Without venv, one project's packages can clash with another project's. Always use venv.
- ❌ **"FastAPI is a server"** — no. FastAPI is a framework. Uvicorn is the server. They're different but work together.
- ❌ **`/docs` is just for viewing** — no. It's interactive — you can send requests and test from there without Postman or a frontend.

1. Why do we create a virtual environment (venv)?

<summary>Sample Answer</summary>

**Answer:** So each project keeps its own isolated Python packages and they don't mix with other projects. One project uses Flask, another uses FastAPI — venv keeps them separate.

2. What's the difference between FastAPI and uvicorn?

<details>
<summary>Sample Answer</summary>

**Answer:** FastAPI is the framework (creates routes, validation, docs). Uvicorn is an ASGI server that handles incoming requests and brings them to FastAPI. They run together.

<details>
<summary>Sample Answer</summary>

**Answer:** `/docs` is FastAPI's auto-generated interactive documentation (Swagger UI). You can make GET/POST requests and test from there — without a frontend. This is FastAPI's biggest convenience (Flask requires adding it manually).

</details>
