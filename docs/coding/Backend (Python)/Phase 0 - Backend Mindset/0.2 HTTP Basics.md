In the previous file, we saw that the client sends a request to the server, and the server sends back a response. Now the question is — how are "request" and "response" actually written? That's why we'll learn HTTP basics in this file, which is the "language" of the internet.

# 0.2 HTTP Basics — Request, Response, Methods, Status Codes

## Think — Post Office Example

Suppose you want to send a letter to a friend. What's inside the letter?
1. **Who to send to** — address/destination
2. **What to send** — content (message)
3. **What to do** — "this is an order" or "this is a question"

When a browser talks to a server, the same thing happens — in HTML form, and this "language" is called **HTTP**.

## Concept — HTTP

**HTTP (HyperText Transfer Protocol)** is the language of the internet — the rules by which client and server talk to each other. When you open a URL, you send an **HTTP request**, and you receive an **HTTP response**.

A request looks like:

```
METHOD /path  HTTP/version
```

- **METHOD** — tells what action to perform (the request's "verb")
- **/path** — which resource to access (part of the URL)
- **HTTP version** — which version is being used (like HTTP/1.1)

## Request Methods (Most Important)

Methods tell what the request wants to do. The 4 main ones:

| Method | What it does | Real-world example |
|--------|--------------|-------------------|
| **GET** | **Get** data (read) | Opening a website, searching |
| **POST** | **Create/send** new data | Submitting a login form, creating a new post |
| **PUT** | **Update** entire data | Replacing an entire file |
| **DELETE** | **Delete** data | Removing a post |

Real-world example: GET = "give me this page/page list", POST = "create this new record here".

## Status Codes — The Server's Answer

When the server sends a response, it also sends a code — an **HTTP status code** — that tells what the result of the request was.

| Code | Meaning | Real place |
|------|---------|------------|
| **200** | OK — everything fine | Page loaded |
| **201** | Created — new thing made | New record after POST |
| **404** | Not Found — that page/data not found | Wrong URL |
| **500** | Server error — server's fault | A bug on the server |
| **401/403** | Unauthorized / Forbidden — no permission | Login needed |

**Remember:** 4xx means client's fault (wrong URL/request), 5xx means server's fault (bug on server side). 2xx means everything is fine.

## Nutshell

**HTTP = the client-server language. GET/POST/PUT/DELETE are actions, status codes (200/404/500) are results.**

## What HTTP Is NOT

- ❌ **HTTP = HTTPS** — HTTPS = HTTP + encryption (SSL). Almost everything is HTTPS today.
- ❌ **HTTP is only for browsers** — mobile apps, API calls, everyone uses it.
- ❌ **Status code is a random number** — every code has a specific meaning, and clients understand them.

## Common Mistakes

- ❌ **"The only difference between GET and POST is the name"** — no. GET only reads data, POST sends data. GET doesn't change anything on the server, POST does.
- ❌ **"The server chooses the status code itself"** — partially true. The server assigns the code, but it depends on the request result. If data was found, 200; if not found, 404; if the server crashed, 500.
- ❌ **"Only web browsers use HTTP"** — no. Mobile apps, IoT devices, everyone uses HTTP for data exchange.

## In Your Own Words

1. What's the difference between GET and POST?

<details>
<summary>Sample Answer</summary>

**Answer:** GET is for **reading/getting** data (opening a page, searching). POST is for **creating/sending** data (login, creating a new item). GET doesn't create data on the server, POST does.

</details>

2. What do 200, 404, 500 mean?

<details>
<summary>Sample Answer</summary>

**Answer:** 200 = everything is fine (OK), 404 = that page/resource wasn't found (client's fault — wrong URL), 500 = a problem/error occurred on the server (server's fault).

</details>

3. What are the 4 core things in an HTTP request?

<details>
<summary>Sample Answer</summary>

**Answer:** Method (GET/POST), URL/path (which resource we're going to), version, and headers (extra info like language). In short — a request has action + resource.

</details>
