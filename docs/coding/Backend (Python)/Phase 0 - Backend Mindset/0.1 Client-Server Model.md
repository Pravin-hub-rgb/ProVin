# 0.1 Client–Server Model — When You Open a URL

## Think — Restaurant Example

A restaurant has two separate parts:
- **Menu + Waiter or you (customer)** — what's visible in front
- **Kitchen** — behind, where the order is prepared

You (customer) tell the waiter — "I want to order food." The waiter takes the order to the kitchen. The kitchen prepares the food, then the waiter brings it back and places it on your table.

In this whole scene, **you never go into the kitchen**. You just send the order (request), and receive the cooked dish (response). The logic inside the kitchen — what ingredients are there, how to cook — none of that is shown to you.

This is exactly 1:1 what happens with a browser.

## Concept — Client and Server

| Name | Who | What they do |
|------|-----|--------------|
| **Client** | Browser (and mobile app, desktop app) | Asks for request — "give me this data" |
| **Server** | The computer that stores the website's files/data | Processes the request, sends back data or response |

The relationship is simple:

```
Client (browser) --request--> Server (computer)
Client (browser) <--response-- Server
```

This is the **Client–Server model** — the most basic internet architecture in the world. The client sends a request to the server, the server sends back a response. This same pair is behind every website, every app.

## Example — How a Request Happens

When you open `google.com`:
1. Your browser (client) sends a request to Google's server — "give me the home page"
2. Google's server processes the request
3. The server sends back a response — home page HTML/CSS/JS
4. The browser displays it

This whole round trip happens even when you scroll Instagram — every photo loaded involves request/response with the server.

## Analogy — Restaurant Again

- Client = customer (who's looking, who's asking)
- Server = kitchen + restaurant management (who's preparing, who's deciding)
- Browser (request) = order slip
- Response = cooked food

There's one special thing about restaurants — you can never tell the kitchen "make it like this." You can only place an order. Same on the web — the client can't go inside the server and change data, it can only make requests. The server decides.

## What Client–Server Is NOT

- ❌ **Client means only a browser** — mobile apps, smartwatches, any device that sends a request is a client.
- ❌ **Server = the website's entire code** — the server is a *computer/process* that stores data and handles requests. It hosts the files on web hosting.
- ❌ **Server = WordPress/Dashboard** — WordPress runs *on* a server; it isn't the server itself.

## Nutshell

**Client sends a request, server sends a response — that's the Client–Server model. The most basic internet architecture.**

## Common Mistakes

- ❌ **"Client and server are on the same machine"** — they can be on different machines. Your browser (client) is on your laptop, the server is somewhere else (in a data center). But they can also be on the same machine (during development).
- ❌ **"Server only gives data"** — server gives data, validates it, decides rules, and sometimes rejects too.
- ❌ **"Client can directly access the server"** — no. The client can only send requests. It can't directly touch the server's internal files or database.
