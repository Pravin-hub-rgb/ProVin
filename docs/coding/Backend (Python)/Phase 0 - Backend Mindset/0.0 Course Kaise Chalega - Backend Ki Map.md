When you type google.com and press Enter, results appear instantly on your screen. But none of that work happens on your laptop — behind your screen, somewhere there is another computer that stores data, processes requests, and sends back results. Your browser just displays what it receives. That "computer behind the screen" is the backend.

Now think — you already have React and Next.js experience. You've built the frontend (what the user sees). In this course, you'll learn the "behind the scenes" part — the part that stores data, does calculations, and decides what rules apply to who can see what.

## Common Mistakes

- ❌ **"Backend is just a database"** — database is just one part. Backend has routing, validation, authentication, business logic — everything.
- ❌ **"If you learn frontend, backend will come automatically"** — they're two different worlds. Frontend just displays, backend thinks and decides.
- ❌ **"If you know Python, FastAPI will come automatically"** — Python is a language, not a framework. Learning a framework is a separate step.

1. What is backend, in your own words? (Think about this: when you log into a website, where does the data go?)

4. Why does a website need a backend? Why can't frontend alone do the job?

<details>
<summary>Sample Answer</summary>

**Answer:** Because data shouldn't stay in the user's browser. If everything were in the frontend, any user would have access to all the website's data. The backend keeps data in a protected place (server/database) and decides who can see what. The frontend just displays what the backend allows.

</details>
