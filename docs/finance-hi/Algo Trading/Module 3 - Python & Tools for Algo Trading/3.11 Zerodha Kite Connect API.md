# 3.11 Zerodha Kite Connect API

## Teen-Token Ka Dance — Pehle Kahani Samjho

Doosre brokers: *"password do, token lo."* Done.

Zerodha: *"Ruko... pehle BROWSER mein login karo, phir ek code lo, usse dusra token banao..."*

Teen steps hain:

```text
TOKEN 1: REQUEST TOKEN   ← browser login ke baad milta hai (ek baar)
TOKEN 2: CHECKSUM        ← api_secret + request_token se banta hai
TOKEN 3: ACCESS TOKEN    ← asli badge! Isse data milta hai
```

Analogy:

```text
Club jaana hai:
1. Gate pe ID dikhayi      → entry slip mili (request token)
2. Slip + secret haath-mudai → VIP band ban gaya (checksum)
3. Band dikhao              → andar! Poore din ka access (access token)
```

Confusing lag raha? Chalo CODE mein karo — samajh aa jayega.

## Login — Step-by-Step Code

Best practice: login ka code **alag file** mein rakho — `login.py`.

Kyunki yeh dance roz repeat hoga, toh ek jagah pack kar lo (3.3 wala concept!).

```python
# login.py

from kiteconnect import KiteConnect
from tokens import api_key, api_secret

# STEP 1: Kite object banao
kite = KiteConnect(api_key=api_key)

# STEP 2: Login URL generate karo
print(kite.login_url())
```

Line-by-line:

```python
from kiteconnect import KiteConnect   ← library se main class
kite = KiteConnect(api_key=...)       ← waiter ready — ab requests jayengi
kite.login_url()                      → ek URL print hogi
```

Chalao. Terminal mein ek URL aayegi.

**Us URL ko browser mein kholo** → Zerodha login karo (normally, jaise app mein karte ho).

Login ke baad browser redirect hoga... aur address bar mein dekho:

```text
https://127.0.0.1/....?request_token=ABC123XYZ&status=success
                              ↑↑↑↑↑↑↑↑↑
                          YEH DEKHO! TOKEN 1 mil gaya!
```

`request_token=` ke baad jo bhi hai — copy kar lo.

Yehi hai **Token 1: Request Token.** Slip mili! 🎫

## Token 2 + 3 — Ab Asli Magic

Request token copy karke, `login.py` mein aage badho:

```python
# login.py (aage ka hissa)

request_token = "ABC123XYZ"     ← abhi jo browser se copy kiya

data = kite.generate_session(request_token, api_secret=api_secret)

access_token = data["access_token"]
kite.set_access_token(access_token)

print("LOGIN DONE! ✅")
print(f"Token: {access_token}")
```

Line-by-line:

```python
kite.generate_session(request_token, api_secret=...)
```

Yeh wohi **checksum wala step** hai — request token + api secret milake Zerodha ko bheja.

Zerodha verify karega: *"haan, yeh sach mein tumhara hi login tha"* — aur dega:

```python
data["access_token"]    ← TOKEN 3! Asli badge 🎫
```

```python
kite.set_access_token(access_token)
```

Badge Kite object pe chipka diya — ab har request mein apne-aap jayega.

**DONE!** Login complete. Teen tokens ka dance khatam.

## ⚠️ Access Token Ki Expiry — Roz Ka Sach

Ek zaroori baat jo sabko surprise karti hai:

> **Zerodha ka access token sirf ~24 ghante chalta hai.**

Kal ka token aaj KAAM NAHI karega.

Matlab roz (ya jab bhi expire ho) yeh dance phir karna hoga:

```text
Browser login → request_token copy → generate_session → naya token
```

Isliye `login.py` alag file mein rakha tha!

Roz: sirf `login.py` chalao → naya token → baaki code normal chalega.

(Chota tip: request_token bhi single-use hai — ek baar use kiya toh dobara nahi chalega.)

## Ruk — Dance Ka Saar

```text
1. login_url() print karo        → URL browser mein kholo
2. Browser login                  → request_token mili (copy)
3. generate_session(rt, secret)   → access_token mila
4. set_access_token(at)           → badge laga — KAAM SHURU!
```

Char steps. Roz repeat. Bas.

## Nutshell

Zerodha = popular but dramatic login. **Teen tokens:** browser login se request_token → request_token + api_secret se generate_session → access_token → set_access_token(). Token ~24 ghante mein expire — isliye login.py alag file, roz chalao. Fetch: `historical_data(instrument_token, from_date, to_date, interval)` — token NUMBER lagta hai (`kite.instruments("NSE")` se list). Convert → DataFrame. Dance annoying hai par pattern wahi golden wala hai.

## What It Is NOT

- ❌ **Kite app ≠ Kite Connect API.** Kite app = normal trading app (phone pe). Kite Connect = ALAG developer platform jiska alag account/app setup hota hai. API access ke liye developers.kite.trade pe app banana zaroori hai.
- ❌ **request_token reuse nahi hoti.** Ek baar `generate_session` mein use hui? Dead. Dobara login karke fresh leni padegi. Isliye flow ek hi run mein complete karo.
- ❌ **Access token expire = kuch toda nahi hai.** Yeh DESIGN hai — security ke liye (3.9 samjha tha: short-life = small blast radius). Roz login.py chalana routine ban jaati hai — 2 minute ka kaam.

2. Access token roz kyun naya lena padta hai — aur iska achha solution?
