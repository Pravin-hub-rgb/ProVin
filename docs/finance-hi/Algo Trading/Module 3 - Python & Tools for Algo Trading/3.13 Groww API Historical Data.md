# 3.13 Groww API Historical Data

```text
1. Groww account → Trading APIs section mein jao
2. Generate new API karo → naam do
3. API Key + Secret copy karo (secret DOBARA nahi dikhegi!)
4. tokens.py mein save karo
5. Library install:
```

```bash
pip install grow_api
```

Platform ka naam: **Groww Cloud** — keys yahin manage hoti hain.

## Login — Do Line Ka Kaam

```python
from grow_api import GrowApi
from tokens import grow_key, grow_secret     # tokens.py se (habit!)

grow = GrowApi(api_key=grow_key, api_secret=grow_secret)

access_token = grow.get_access_token()
```

Line-by-line:

```python
GrowApi(api_key=..., api_secret=...)   ← ID + password de diye
grow.get_access_token()                ← badge mil gaya — done!
```

Bas?! Haan bas.

Na Zerodha jaisa dance. Na Angel One jaisi OTP.

Key + secret → token. Khatam.

(Yehi toh 3.9 wala standard flow hai — Groww ne extra kuch nahi add kiya.)

## Historical Data Fetch

```python
response = grow.get_historical_candle_data(
    symbol="RELIANCE",         ← naam hi chalega (number nahi!)
    interval="5minute",
    from_date="2024-01-01",
    to_date="2024-02-01"
)

print(response["status"])      # "success" aana chahiye
```

Parameters familiar lag rahe hain? Symbol, interval, dates —

wahi teen cheezein jo har broker maangta hai. Sirf naam alag.

Bonus: Groww mein **chunking ki tension nahi** — bada date-range ek hi request mein mil jaata hai (Angel One mein chunks karna padta tha — 6.x mein dikhega).

## Convert → DataFrame (Hamesha Ki Tarah)


## Nutshell

Groww = simplest broker: key+secret → get_access_token() → get_historical_candle_data(symbol, interval, dates) → DataFrame. No dance, no TOTP, no chunking. Asli lesson chaar brokers ke baad: **pattern constant hai (connect→auth→fetch→convert), vocabulary badalti hai.** Naya broker = docs mein 5 cheezein dhundhna: login style, function naam, parameters, response shape — phir pattern apply.

## What It Is NOT

- ❌ **Simple = kam powerful nahi.** Groww ka API utna capable hai jitna doosron ka. Easy ≠ basic — bas friction kam hai setup mein.
- ❌ **Key+secret har request pe nahi jaate.** Sirf token GENERATE karne ke liye ek baar use hote hain; phir badge (token) hi saare kaam karta hai — 3.9 wala model hi hai.
- ❌ **Groww Cloud sirf dashboard nahi.** Wahi tera API-control-center hai — keys generate/manage, usage dekhna. Alag tab se alag cheez samajh mat lena.

4. Chunking-free hona (bade range ek request mein) kyu matter karta hai?

<details>
<summary>Sample Jawab</summary>

Groww jaisa single-request range = simpler script, kam failure points, faster development. Jab multi-broker systems banega (Module 8 projects), har broker ki limits kaam aayengi design mein — chunking support wale ko wrapper function banana padta hai, simple wale ko nahi.
