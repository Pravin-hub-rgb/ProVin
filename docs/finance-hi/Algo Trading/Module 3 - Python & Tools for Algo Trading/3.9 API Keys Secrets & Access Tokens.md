# 3.9 API Keys, Secrets & Access Tokens

## Ghar Ki Chabi Wali Kahani

Soch tere ghar ke do darwaze:

```text
MAIN DOOR    → ghar mein entry (sab kuch access)
GODAM KA LOCK→ sirf godam khulega
```

Brokers bhi same system use karte hain — digital chabiyan dete hain:

| Chabi | Kya Kholti Hai |
|---|---|
| **API Key** | Teri identity batati hai — "yeh banda KAUN hai" |
| **API Secret** | Password jaisi — "yeh SACH MEIN wahi hai" proof |
| **Access Token** | Temporary pass — "aaj ke liye entry allowed" |

Teen cheezein, teen roles. Ab ek-ek karke detail.

## API Key + Secret — Permanent Identity

Broker dashboard pe account banane ke baad milte hain:

```text
API_KEY    = "abc123xyz..."     ← dikh sakti hai (ID card jaisi)
API_SECRET = "xyz789secret..."  ← KABHI kisi ko na do! (password)
```

```text
API Key    → username jaisi — "main Rahul hun"
API Secret → password jaisa — proof ki sach mein Rahul hi hun
```

⚠️ Sabse zaroori rule:

> **Secret = PASSWORD hai.** Usse code mein openly likhna, screenshot mein dikhana, dost ko WhatsApp karna — SAB GALAT.

Secret leak ho gayi? Koi bhi TERE account se trade kar sakta hai.

## Access Token — Roz Ka Pass

Ab problem: secret har request pe bhejna risky hai.

Jaise tu office roz apna original passport nahi dikhata —

ek baar dikhata hai, phir **visitor badge** mil jaata hai din ke liye.

Wahi hai **access token:**

```text
STEP 1: Key + Secret de ke LOGIN karo        (passport dikhaaya)
STEP 2: Broker ne ACCESS TOKEN diya           (badge mil gaya)
STEP 3: Ab har request pe sirf TOKEN jayega   (badge dikhao, kaam hoga)
```

Fayda: asli secret network pe baar-baar travel NAHI karti.

Sirf token jaata hai — aur token expire hota hai (roz naya).

## Ruk — Teen Cheezein Ek Line Mein

```text
API Key     → ID card (kaun hun main)
API Secret  → password (proof)
Access Token→ roz ka visitor badge
```

Flow: **key+secret se token banao → token se kaam karao.**

Ab asli sawaal: in keys ko CODE mein kahan likhein?

## ❌ Sabse Badi Beginner Galti

```python
# GALAT TARIKA:
api_key = "abc123xyz..."
secret = "xyz789secret..."

# ...baaki code...
```

Yeh chal jayega. Kaam bhi karega.

**Par ek din tune yeh code GitHub pe daala... ya screenshot share kiya...**

Keys public ho gayi. Koi stranger teri trading karne laga.

Isliye yeh tareeka BAN hai.

## ✅ Sahi Tarike — Do Options

### Option 1: Alag File Mein Rakho

```python
# tokens.py   ← sirf ismein keys hain
API_KEY = "abc123xyz..."
SECRET = "xyz789secret..."
```

```python
# main.py    ← asli code
from tokens import API_KEY, SECRET     # wahan se import
```

Code share karna ho toh `tokens.py` ko CHHOD ke baaki do.

### Option 2: Environment Variables

```python
import os

api_key = os.getenv("MY_API_KEY")
```

```text
os.getenv("NAME")  → "computer ki memory mein NAME naam ki
                      value rakhi hai? Woh de do."
```

Values computer ke settings mein rakhi jaati hain — code mein kahin nahi dikhti.

Cloud pe deploy karte waqt (Module 8) yeh hi system use hoga — abhi concept pakdo.

### Aur Ek Habit — .gitignore

Jab bhi code GitHub pe jayega, ek `.gitignore` file banegi jo batati hai: *"yeh files upload MAT karo."*

Usme `tokens.py` aur `.env` hamesha daalna:

```text
# .gitignore
tokens.py
.env
```

Git unhe ignore kar dega — kabhi upload nahi hongi. (Detail Module 7 mein.)

## Ruk — Security Checklist

```text
✅ Secret = password, kisi ko na do
✅ Keys alag file (.py) ya env-vars mein — main code mein NAHI
✅ .gitignore setup — upload se pehle
✅ Token = temporary badge; secret permanent identity
```

Yeh 4 lines har broker file mein practically use hongi. Zinda raho toh yaad rahe!

## Nutshell

Teen security layers: **API Key** (ID — kaun hai), **API Secret** (password — proof), **Access Token** (roz ka badge — key+secret se ek baar banta hai, phir requests usse jaati hain). Secret kabhi openly share/likhо mat. Keys store karo: alag file (`tokens.py`) ya environment variables (`os.getenv`) mein — main code mein kabhi nahi. GitHub jaoge toh `.gitignore` mandatory. Leak = account takeover.

## What It Is NOT

- ❌ **Key aur token same cheez nahi hain.** Key+secret = PERMANENT credentials (login material). Token = TEMPORARY pass jo unse BANTA hai aur expire hota hai. Token leak ho gaya? Kal expire ho jayega. Secret leak ho gayi? Poora account compromised.
- ❌ **"Mera chota account hai, kaun hack karega" — galat soch.** Hackers bots chalate hain jo internet pe HAR leaked key scan karte hain, seconds mein. Size nahi dekhte. Automation unki taraf se bhi hai!
- ❌ **os.getenv() khud values create nahi karta.** Woh sirf READ karta hai — value tu/computer/cloud settings mein pehle rakhni padti hai. Agar set nahi, toh None milega (aur baad mein confusing error).

**In Your Own Words**

1. API Key, Secret, Token — teeno ka role apne shabdon mein?

<details>
<summary>Sample Jawab</summary>

**Jawab:** API Key = ID card — batata hai request KISKI hai. Secret = password — proof karta hai sach mein wahi banda hai (sirf key copy karke koi ghus na jaye). Access Token = temporary visitor badge — login ke waqt key+secret se milta hai, phir roz ki requests usi badge se hoti hain. Badge expire hota hai (safe), secret permanent hai (super-sensitive). Flow: key+secret → token → token se saare kaam.

</details>

2. Keys ko code mein directly likhna kyun galat hai? Do sahi tarike?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Kyunki code SHARE hota hai — GitHub, screenshots, dost ko bhejna... jahan bhi gaya, keys gayi. Bots seconds mein leaked keys scan kar lete hain. Fixes: (1) alag file — tokens.py mein keys, main code mein from tokens import; share waqt woh file skip. (2) Environment variables — os.getenv("KEY") computer/cloud ki settings se value leta hai, code mein value kahin nahi dikhti. Plus .gitignore taaki files accidentally push na hon.

</details>

3. Access token expire hone ka fayda kya hai (drawback lagta hai na)?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Fayda SECURITY ka hai. Agar token leak ho jaye toh nuksaan limited window ka hai — kal tak, phir dead. Permanent credential hota toh hacker hamesha ke liye andar tha. Trade-off: tujhe roz/frequently re-login karna padta hai (thoda annoying), par hacker ko bhi roz fresh access chahiye hota hai jo uske paas nahi hota. Short-life = small blast radius. Yeh design feature hai, bug nahi.

</details>

4. `os.getenv("MY_KEY")` ne None diya — matlab kya hua?

<details>
<summary>Sample Jawab</summary>

**Jawab:** Matlab computer/memory mein "MY_KEY" naam ki koi environment variable SET hi nahi hai — getenv kuch na milne pe None deta hai. Fix: value pehle set karni padegi (local machine pe env var / .env file; cloud pe dashboard setting). Common beginner confusion: samajhte hain getenv khud value banata hai — nahi, woh sirf READER hai. Pehle rakhna, phir mangwana.

</details>
